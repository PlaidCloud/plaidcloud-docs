結合条件を指定します。**自動判定**は、2つのテーブルの列が当てはまる次の項目のうち、最初のものを使って**テーブル関係の結合フィールドマップ**を入力します。

- 同じ2つのテーブルを結合する、このプロジェクト内の別の結合ステップのキー
- それらを結合する承認済みメトリックのキー
- 一方のテーブルに設定されたキー列と、もう一方のテーブルで名前が一致する列、または同じ[プロジェクト要素](/ja/guides/projects/data-model/)に関連付けられた1つの列
- 後述の、両方のテーブルが列を持つ要素
- 両方のテーブルで同じ名前の列
- 大文字・小文字やアンダースコアだけが異なる名前の列、または `id` 列と、テーブル名に由来する名前の列（たとえば、*Customers* テーブルに対する `customer_id`）

マップを変更するまで、マップの下の1行にどれを使用したかが表示されます。自動判定はテーブルの行ではなく列を読み取るため、保存する前にキーを確認してください。**ソースを検査**でも、空の**テーブル関係の結合フィールドマップ**が同じ方法で入力されます。

**共有要素からのキー。** 列は、その名前が要素の名前またはエイリアスのいずれかである場合に、その要素に属します。両方のテーブルが列を持つ各要素について、自動判定は、名前が異なっていても、それぞれの側の1つの列を対応付けます。テーブルにその要素の列が複数ある場合、自動判定は両方のテーブルにある名前の列を対応付け、そうでなければその要素を除外します。テキストと日付など、型の種類が異なる2つの列は対応付けられません。一方のテーブルだけが共有要素にちなんだ名前である場合、結合はその要素だけで行われます。テーブルが要素にちなんだ名前であるとは、その名前が（大文字・小文字を区別せず）要素の名前、その名前に `s` を付けたもの、またはそのいずれかの前に単語1つとアンダースコアが付いたものである場合です。たとえば `customer`、`customers`、`dim_customer` です。`sales_by_customer` のような長い名前や、`customer_product` のように最初の単語自体が要素である名前は該当しません。マップの下の行には、*These keys are the elements both tables share: customer, period.* のように要素の名前が示されます。どの要素からも対応付けが得られない場合、自動判定は同じ名前の列に進みます。

要素による判定には2つの制限があります。

- 要素に属する列のみを対応付け、それらと並べて同じ名前の列を追加することはありません。テーブルのキーが複数の列で、会計カレンダーの列のように一部が要素ではない場合、自動判定は要素の列のみを提案します。ほかの列はご自身で追加してください。
- 名前が単語1つとアンダースコアに続けて要素名が付いたテーブルは、`ar_customer` や `bank_account` のように実際にはそうでなくても、その要素自身のテーブルと見なされるため、共有される要素に対して名前が付いているテーブルがそれだけである場合、結合はその要素だけで提案されます。

**マップ内の要素。** 結合マップ内の要素に属する各列には、その横に要素の名前がピルとして表示されます。ピルにカーソルを合わせると、要素、その説明、提供するディメンションが表示されます。マップの下の注記は助言であり、ステップの保存を妨げることはありません。

- 2つの異なる要素の列を対応付ける行には、*行 2 は異なる要素を組み合わせています: customer と vendor。* のような注記が表示されます。
- **自動判定**がキーを見つけられない場合、注記 *有力なキーが見つかりませんでした。* に、プロジェクトの[データモデル](/ja/guides/projects/data-model/)ページを、ステップを閉じて開く**データモデル**リンクが表示されます。そこで、テーブルが共有する列を要素として記述できます。ステップに未保存の変更がある場合は、先に変更を破棄するかどうかを確認するメッセージが表示されます。

列を手動で追加するには、セクション内の任意の場所を右クリックし、**行を挿入**または**行を追加**を選択します。それぞれ、現在選択している行の前、または末尾に行が追加されます。続いて、**table1のフィールド**と**table2のフィールド**で照合する列を選択します。**テーブル関係の結合フィールドマップ**からフィールドを削除するには、右クリックして**削除**を選択します。
