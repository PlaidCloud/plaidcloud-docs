### Configuration du Data Mapper

![Table Data Mapper](/images/table_data_mapper.png)

Le Data Mapper sert à mapper les colonnes des données source vers la table de données cible.

#### Inspection et remplissage du mappeur

Le bouton de menu **Inspecter la source** offre d'autres façons de mapper les colonnes de la source vers la cible :

* Renseigner les deux tables de mappage : propage toutes les valeurs de la table de données source vers la table de données cible. C'est le comportement par défaut.
* Renseigner uniquement la table de mappage source : mappe uniquement toutes les valeurs de la table de données source. C'est utile pour modifier un workflow existant lorsque la structure des colonnes source a changé.
* Renseigner uniquement la table de mappage cible : propage toutes les valeurs vers la table de données cible uniquement.

Si les options de colonnes source et cible ne suffisent pas, vous pouvez ajouter d'autres colonnes à la table de données cible de plusieurs façons :

* **Tout propager** insère toutes les colonnes source dans la table de données cible, qu'elles existent déjà ou non.
* **Propager la sélection** insère uniquement la ou les colonnes source sélectionnées.
* Faites un clic droit côté cible et sélectionnez **Insérer une ligne** pour insérer une ligne juste au-dessus de la ligne actuellement sélectionnée.
* Faites un clic droit côté cible et sélectionnez **Ajouter une ligne** pour insérer une ligne en bas (à l'extrême droite) de la table de données cible.

<Aside type="danger">Sélectionner *Tout propager* duplique les colonnes si elles existent déjà dans la liste cible</Aside>

#### Suppression de colonnes

Pour supprimer des colonnes de la table de données cible, sélectionnez la ou les colonnes voulues, puis faites un clic droit et sélectionnez **Supprimer**.

#### Colonnes source qui ne sont plus listées

Une ligne cible peut nommer une **Colonne source** que la table de données source ne liste plus, par exemple après une nouvelle inspection de la source. L'étape ne supprime jamais une telle ligne à votre place. À la place, le nom de la colonne s'affiche en rouge derrière un signe d'avertissement ⚠, et le survol indique que la colonne ne figure pas dans les colonnes source. Dans une étape à plusieurs tables, comme une union, chaque table est vérifiée par rapport à ses propres colonnes source.

Une ligne avec une **Constante**, une **Expression** ou un résumé **Nombre (valeurs nulles incluses)** n'est jamais signalée, car l'étape ne lit pas sa colonne source. Rien n'est signalé tant que la table de données source ne liste aucune colonne, par exemple avant la première inspection de la source.

Lorsque vous enregistrez une étape qui contient encore des lignes signalées, une boîte de dialogue **Colonnes obsolètes détectées** les liste sous l'onglet ou la table concernés, et propose trois choix :

- **Tout supprimer et enregistrer** : supprime les lignes signalées, puis enregistre.
- **Enregistrer quand même** : enregistre l'étape telle quelle.
- **Annuler** : retourne à l'étape sans enregistrer.

Pour conserver une ligne et faire disparaître son avertissement, rajoutez la colonne à la table de données source, ou choisissez une colonne que la table de données source liste.

#### Type de données d'une colonne

Chaque colonne cible possède un **Type**. Une colonne propagée depuis la source conserve le type de la colonne source ; une ligne que vous ajoutez à la main est de type **Texte** au départ, et vous définissez le **Type** pour indiquer ce qu'elle doit réellement être : une colonne que vous comptez additionner ou trier a besoin de son type numérique ou date, car le texte se trie et s'additionne comme du texte.

Une étape enregistrée avec une colonne sans aucun type s'exécute malgré tout. Le type est déterminé au démarrage de l'étape, à partir de la colonne source que cette colonne lit. Lorsqu'il n'y a rien à partir duquel le déduire, il est traité comme du texte : les colonnes d'une étape **Extraire SQL** proviennent de la requête que vous avez écrite et non d'une source mappée, et lorsque plusieurs sources portent le même nom de colonne avec des types qui divergent, le texte est utilisé plutôt que d'en deviner un : une mauvaise supposition produit une conversion que l'entrepôt peut rejeter, alors que tout se convertit en texte.

<Aside type="caution">
**Jointure multi-tables** est l'exception, volontairement. Elle refuse de s'exécuter et nomme la colonne, ce qui est plus utile qu'une supposition dans une étape qui joint plusieurs tables. Définissez le **Type** de cette colonne et enregistrez à nouveau.
</Aside>

Définir vous-même le **Type** reste la façon d'indiquer ce qu'une colonne doit être. Le laisser vide revient à accepter ce que la colonne source se trouve être.

#### Modification de l'ordre des colonnes

Pour réorganiser les colonnes de la table de données cible, sélectionnez la ou les colonnes voulues. Vous pouvez utiliser l'une ou l'autre des méthodes suivantes :
* **Flèches de déplacement groupé** : sélectionnez l'option de déplacement voulue avec les flèches en haut à droite.
* **Menu contextuel** : faites un clic droit et sélectionnez **Déplacer en haut**, **Monter**, **Descendre** ou **Déplacer en bas**.

#### Réduire le résultat aux seuls enregistrements distincts

Pour ne renvoyer que des valeurs distinctes, sélectionnez l'option de menu **Distinct**. Un ensemble de cases à cocher s'affiche pour chaque colonne de la source. Il suffit de cocher la case en regard d'une colonne pour ne renvoyer que des résultats distincts.

Selon la situation, vous pouvez envisager d'utiliser plutôt la synthèse.

Le processus de distinction conserve le premier enregistrement unique trouvé et écarte les autres. Vous pouvez appliquer un tri aux données s'il est important d'obtenir des résultats cohérents d'une exécution à l'autre.

<Aside type="danger">Sélectionner toutes les colonnes pour déterminer le caractère distinct peut donner l'impression que l'option n'est pas appliquée. Sélectionnez uniquement les colonnes qui, selon vous, définissent le caractère distinct des données.</Aside>

#### Agrégation et regroupement

Pour agréger les résultats, sélectionnez l'option de menu **Résumer**. Un ensemble de listes de sélection s'affiche pour chaque colonne de la table de données cible. Choisissez une méthode de synthèse adaptée à chaque colonne.

Lorsque **Inspecter la source** remplit les colonnes, une colonne numérique commence à **Regrouper par** plutôt qu'à **Somme** si son nom ressemble à un identifiant, comme `id`, `customer_id`, `Order No` ou `CustomerKey`, si sa table la définit comme une clé, ou si la jointure l'utilise comme clé.

- Regrouper par
- Somme
- Min
- Max
- Premier
- Dernier
- Nombre
- Nombre (valeurs nulles incluses)
- Moyenne
- Écart type
- Écart type d'échantillon
- Écart type de population
- Variance
- Variance d'échantillon
- Variance de population
- Avancé hors regroupement


<Aside>Lorsque vous utilisez l'agrégation, toutes les colonnes **doivent** avoir un type de synthèse spécifié</Aside>
