**Check Keys**, next to **Guess**, counts the key values in the **Join Map** that appear on more than one row of a table. When a key value repeats in the table you join to, each row that matches it appears in the result once for each matching row, so the result can have more rows than the table you started from.

Which table is checked depends on the step:

- **Inner Join** and **Table Lookup**: Table 2.
- **Outer Join**: Table 2 for a left join, Table 1 for a right join, and both tables for a full join.

The answer appears under the **Join Map**. It gives the number of repeated key values and the rows that share them, and lists up to five of the most repeated. It counts:

- the table as it is now, after this step's filter on that table;
- only the rows you can see, when row-level security limits what you see of the table. The answer says so;
- no rows with a blank key, because a blank key never matches another row. The exception is an Inner or Outer Join set to match blank keys to each other, as a join converted from Alteryx can be: there, blank keys count as a key value and can be listed as **(blank)**.

**Table Lookup** never repeats a row. For a repeated key it keeps one row of Table 2, taking each column's lowest value (the smallest number, the earliest date, the first text in sort order), so that row can mix values from different rows of Table 2. Check Keys tells you when that happens; to choose which values are used, make each key appear once in Table 2.

The check reads the table in your warehouse, so it runs only when you choose it, and it stops after 30 seconds. Changing either table, its filter, the **Join Map** or, on Outer Join, the **Join Type** clears the answer.
