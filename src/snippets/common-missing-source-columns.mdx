#### Columns Missing From the Source Table

When you save, the source data table itself is checked as it is now. A column the step lists in its source columns but the table doesn't have, for example one an earlier step renamed or dropped, means the step's columns are out of date, and a step that reads such a column fails when it runs. Saving then opens a **Missing Source Columns** dialog that names each table and the columns it lacks, with two choices:

- **Save Anyway** — save the step as it is.
- **Cancel** — go back to the step without saving.

Nothing is removed for you, because the table may be what is wrong, and it can change again before the step runs. When rows are also flagged as no longer listed, both appear together in the **Stale Columns Found** dialog, and **Remove All and Save** removes only the flagged rows. While the source columns list is empty, the columns the step maps are checked instead, except rows with a **Constant**, an **Expression** or a **Count (including nulls)** summary, which read no column.

A source named with a variable, such as `{year}/Sales`, is checked as the variable stands when you save, and the dialog names the table it checked, such as `2026/Sales (from {year}/Sales)`. A variable that a loop sets holds the value from its last iteration, so a loop over tables of different shapes can warn about a table that the next run won't read. A table that doesn't exist yet, for example one an earlier step in the workflow creates, isn't checked, and neither is a source whose variable has no value, a table the step finds by searching when it runs, or a table that can't be read at the moment.
