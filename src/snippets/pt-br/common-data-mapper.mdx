### Configuração do Data Mapper

![Data Mapper de tabela](/images/table_data_mapper.png)

O Data Mapper é usado para mapear as colunas dos dados de origem para a tabela de dados de destino.

#### Inspeção e Preenchimento do Mapeador

O botão de menu **Inspecionar origem** oferece formas adicionais de mapear colunas da origem para o destino:

* Preencher ambas as tabelas de mapeamento: propaga todos os valores da tabela de dados de origem para a tabela de dados de destino. Este é o comportamento padrão.
* Preencher somente a tabela de mapeamento de origem: mapeia apenas todos os valores da tabela de dados de origem. Isso é útil ao modificar um fluxo de trabalho existente quando a estrutura de colunas da origem mudou.
* Preencher somente a tabela de mapeamento de destino: propaga todos os valores apenas para a tabela de dados de destino.

Se as opções de coluna de origem e de destino não forem suficientes, é possível adicionar outras colunas à tabela de dados de destino de várias maneiras:

* **Propagar tudo** insere todas as colunas de origem na tabela de dados de destino, quer elas já existam ou não.
* **Propagar selecionadas** insere apenas as colunas de origem selecionadas.
* Clique com o botão direito no lado do destino e selecione **Inserir linha** para inserir uma linha imediatamente acima da linha selecionada.
* Clique com o botão direito no lado do destino e selecione **Anexar linha** para inserir uma linha no final (extrema direita) da tabela de dados de destino.

<Aside type="danger">Selecionar *Propagar tudo* duplica as colunas que já existem na lista de destino</Aside>

#### Exclusão de Colunas

Para excluir colunas da tabela de dados de destino, selecione as colunas desejadas, clique com o botão direito e selecione **Excluir**.

#### Colunas de Origem que Não Estão Mais Listadas

Uma linha de destino pode indicar uma **Coluna de origem** que a tabela de dados de origem não lista mais, por exemplo depois que a origem foi inspecionada novamente. A etapa nunca remove essa linha por você. Em vez disso, o nome da coluna aparece em vermelho, após um sinal de aviso ⚠, e ao passar o mouse sobre ele é exibida a informação de que a coluna não está nas colunas de origem. Em uma etapa com várias tabelas, como uma união, cada tabela é verificada em relação às suas próprias colunas de origem.

Uma linha com resumo **Constante**, **Expressão** ou **Contagem (incluindo nulos)** nunca é sinalizada, porque a etapa não lê a coluna de origem dela. Nada é sinalizado enquanto a tabela de dados de origem não listar nenhuma coluna, por exemplo antes de a origem ser inspecionada pela primeira vez.

Ao salvar uma etapa que ainda tem linhas sinalizadas, uma caixa de diálogo **Colunas obsoletas encontradas** as lista sob a guia ou a tabela em que estão e oferece três opções:

- **Remover todas e salvar** — remove as linhas sinalizadas e, em seguida, salva.
- **Salvar mesmo assim** — salva a etapa como está.
- **Cancelar** — volta para a etapa sem salvar.

Para manter uma linha e eliminar o aviso dela, adicione a coluna de volta à tabela de dados de origem ou escolha uma coluna que a tabela de dados de origem liste.

#### Tipo de Dados da Coluna

Toda coluna de destino tem um **Tipo**. Uma coluna propagada da origem mantém o tipo da coluna de origem; uma linha que você adiciona manualmente começa como **Texto**, e você define o **Tipo** para indicar o que ela deve realmente ser — uma coluna que você pretende somar ou ordenar precisa do tipo numérico ou de data, porque texto é ordenado e somado como texto.

Uma etapa salva com uma coluna sem nenhum tipo ainda é executada. O tipo é determinado quando a etapa é iniciada, a partir da coluna de origem que essa coluna lê. Onde não há de onde lê-lo, ele é tratado como texto: as colunas de uma etapa **Extrair SQL** vêm da consulta que você escreveu, e não de uma origem mapeada, e onde várias origens têm o mesmo nome de coluna com tipos divergentes, usa-se texto em vez de adivinhar um deles — um palpite errado gera uma conversão que o data warehouse pode rejeitar, e qualquer coisa pode ser convertida em texto.

<Aside type="caution">
**Junção de várias tabelas** é a exceção, deliberadamente. Ela se recusa a executar e indica a coluna, o que é mais útil do que um palpite em uma etapa que une várias tabelas. Defina o **Tipo** dessa coluna e salve novamente.
</Aside>

Definir o **Tipo** você mesmo continua sendo a forma de dizer o que uma coluna deve ser. Deixá-lo sem definição significa aceitar o tipo que a coluna de origem tiver.

#### Alteração da Ordem das Colunas

Para reorganizar as colunas na tabela de dados de destino, selecione as colunas desejadas. Você pode usar:
* **Setas de movimentação em massa**: selecione a opção de movimentação desejada nas setas no canto superior direito
* **Menu de contexto**: clique com o botão direito e selecione **Mover para o início**, **Mover para cima**, **Mover para baixo** ou **Mover para o final**.

#### Reduzir o Resultado a Registros Distintos

Para retornar apenas opções distintas, selecione a opção de menu **Distintos**. Isso exibe um conjunto de caixas de seleção para cada coluna da origem. Basta marcar a caixa ao lado da coluna correspondente para retornar apenas resultados distintos.

Dependendo da situação, talvez seja melhor considerar o uso de resumo.

O processo de distinção mantém o primeiro registro exclusivo encontrado e descarta os demais. Talvez você queira aplicar uma ordenação aos dados se a consistência entre execuções for importante.

<Aside type="danger">Selecionar todas as colunas para determinar a distinção pode dar a impressão de que ela não está sendo aplicada. Selecione apenas as colunas que, na sua avaliação, definem a distinção dos dados.</Aside>

#### Agregação e Agrupamento

Para agregar resultados, selecione a opção de menu **Resumir**. Isso exibe um conjunto de caixas de seleção para cada coluna da tabela de dados de destino. Escolha um método de resumo adequado para cada coluna.

Quando **Inspecionar origem** preenche as colunas, uma coluna numérica começa como **Agrupar por** em vez de **Soma** se o nome dela se parecer com um identificador, como `id`, `customer_id`, `Order No` ou `CustomerKey`, se a tabela dela a definir como chave ou se a junção a usar como chave.
