#### Quando a etapa é executada

As etapas Table Extract, Table Lookup, Table Inner Join, Table Cross Join, Table Outer Join, Table Anti Join, Junção de várias tabelas, Table Union Distinct, Table Union All, Table Pivot, Table Melt, Table In-Place Delete, Table Upsert e Table Append verificam suas tabelas de origem quando são executadas, antes de gravar qualquer coisa. A verificação compara a consulta que a etapa montou com cada tabela de origem como ela está naquele momento:

- Uma coluna que a etapa lê e que a tabela não tem, uma chave de junção que a tabela não tem ou que não está nas colunas de origem da etapa, ou uma tabela de origem que a etapa lê e que não foi construída interrompe a etapa. Um único erro nomeia todos os problemas, cada um com a sua própria correção. Uma tabela de destino que já existia permanece como estava, e uma que a etapa precisou criar fica vazia.
- Uma coluna que a etapa lista, mas não lê, e que a tabela não tem mais, gera um aviso. A etapa é executada sem ela.
- Table Union Distinct e Table Union All são a exceção para uma tabela de origem que não foi construída: elas a deixam de fora, sem aviso, e combinam as demais, como antes. Se nenhuma das tabelas de origem tiver sido construída, elas terminam com um aviso em vez de falhar.

Uma etapa cujo destino é uma visão apenas cria a visão, portanto as colunas e as chaves de junção que ela lista são verificadas em relação às suas tabelas somente quando o warehouse se recusaria a criar essa visão de qualquer forma. Nos demais casos, apenas uma tabela de origem que não foi construída ou uma chave de junção que a etapa não lista a interrompe, e nenhum aviso é adicionado.

Sempre que possível, o erro nomeia a etapa que constrói uma tabela e, quando a tabela tem uma coluna cujo nome é parecido com o de uma coluna ausente, por exemplo uma que difere apenas na caixa das letras, ele nomeia essa coluna também.
