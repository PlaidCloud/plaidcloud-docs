Specify join conditions. **Guess** fills the **Join Map** from the first of these that the two tables' columns can take:

- the keys of another join step in this project that joins the same two tables
- the keys of an approved metric that joins them
- the key columns set on one of the tables, matched in the other by name, or else by the one column bound to the same [project element](/guides/projects/data-model/)
- the elements both tables have a column for, as described below
- the columns with the same name in **Table 1** and **Table 2**
- columns whose names differ only in capitals or underscores, or an `id` column matched to a column named for its table, such as `customer_id` for a table named *Customers*

A line under the map says which it used, until you change the map. Guess reads the tables' columns, not their rows, so check the keys before you save. **Inspect Source** fills an empty **Join Map** the same way.

**Keys from shared elements.** A column belongs to an element when its name is the element's name or one of its aliases. For each element both tables have a column for, Guess pairs the one column on each side, even when their names differ. When a table has several columns for the element, Guess pairs the one name both tables have, and otherwise leaves that element out. Two columns whose types are of different kinds, such as text and a date, are not paired. When exactly one of the tables is named for a shared element, the join is on that element alone. A table is named for an element when its name, ignoring capitals, is the element's name, that name with an `s`, or either one after a single word and an underscore, such as `customer`, `customers` or `dim_customer`. A longer name, such as `sales_by_customer`, doesn't count, and neither does one whose first word is itself an element, such as `customer_product`. The line under the map names the elements, such as *These keys are the elements both tables share: customer, period.* When no element gives a pair, Guess goes on to the columns with the same name.

The element guess has two limits:

- It pairs only columns that belong to an element, and adds no same-named columns beside them. When a table's key is several columns and some aren't elements, such as a fiscal calendar's, Guess proposes only the element columns; add the others yourself.
- A table whose name is one word and an underscore before an element's name is taken to be that element's own table even when it isn't, such as `ar_customer` or `bank_account`, so when it is the only table named for a shared element, the join is proposed on that element alone.

**Elements in the map.** Each column in the join map that belongs to an element shows the element's name as a pill beside it. Hover over the pill to see the element, its description and the dimension it supplies. Notes under the map advise you but never stop you saving the step:

- A row that pairs columns of two different elements gets a note, such as *Row 2 pairs different elements: customer and vendor.*
- When **Guess** finds no keys, the note *No likely keys found.* has a **Data model** link that opens the project's [Data model](/guides/projects/data-model/) page, where you can describe the columns your tables share as elements.

To add additional columns manually, right click anywhere in the section and select either **Insert Row** or **Append Row**, to add a row prior to the currently selected row or to add a row at the end, respectively. Then, type the column names to match from **Table 1** to **Table 2**. To remove a field from the **Join Map**, simply right-click and select **Delete**.
