#### When the Step Runs

Table Extract, Table Lookup, Table Inner Join, Table Cross Join, Table Outer Join, Table Anti Join, Multi-Table Join, Table Union Distinct, Table Union All, Table Pivot, Table Melt, Table In-Place Delete, Table Upsert and Table Append check their source tables when they run, before they write anything. The check compares the query the step built with each source table as it is at that moment:

- A column the step reads that the table doesn't have, a join key the table doesn't have or that isn't in the step's source columns, or a source table the step reads that hasn't been built stops the step. One error names every problem, each with its own fix. A target table that already existed is left as it was, and one the step had to create stays empty.
- A column the step lists but doesn't read, and the table no longer has, adds a warning. The step runs without it.
- Table Union Distinct and Table Union All are the exception for a source table that hasn't been built: they leave it out, without a warning, and combine the rest, as they did before. If none of their source tables has been built, they finish with a warning instead of failing.

A step whose target is a view only creates the view, so the columns and join keys it lists are checked against its tables only where the warehouse would refuse to create that view anyway. Elsewhere, only a source table that hasn't been built or a join key the step doesn't list stops it, and no warning is added.

Where it can, the error names the step that builds a table, and when the table has a column whose name is close to a missing one, such as one that differs only in case, it names that column too.
