### Option „Erneuten Import überspringen, wenn Quelldateien unverändert sind“

Wenn diese Option aktiviert ist, überspringt eine Workflow-Ausführung dieses Schritts den gesamten Import — Download, Konvertierung und Neuaufbau der Tabelle —, sofern die Quelldateien und die Einstellungen des Schritts seit der letzten erfolgreichen Ausführung unverändert sind. So vermeiden Sie wiederholte Arbeit, wenn ein geplanter Workflow erneut auf Quelldateien läuft, die sich nicht geändert haben.

Der Schritt vergleicht jede Quelldatei anhand von Pfad, Größe und Zeitpunkt der letzten Änderung (zusätzlich anhand eines Inhalts-Hashes, sofern die Quelle einen liefert). Wird eine Datei hinzugefügt, entfernt oder geändert oder ändert sich die Konfiguration des Schritts, läuft der Import normal. Die Option ist **standardmäßig aktiviert** — deaktivieren Sie sie, um immer erneut zu importieren —, und manuelle, einmalige Importe laufen immer.

Das Überspringen setzt außerdem voraus, dass die Zieltabelle noch die Zeilen enthält, die der letzte Import geladen hat. Wurde die Tabelle seitdem geleert oder lässt sich ihre Zeilenanzahl nicht lesen, läuft der Import erneut, statt zu überspringen und nachgelagerte Schritte ohne Daten zu lassen.

Einige Quellen (zum Beispiel SFTP) liefern keinen Inhalts-Hash, sodass bei ihnen allein Größe und Zeitpunkt der letzten Änderung der Datei das Änderungssignal bilden. Eine Datei, die an Ort und Stelle mit gleicher Größe und gleichem Änderungszeitpunkt ersetzt wird, würde dann als unverändert behandelt und übersprungen — deaktivieren Sie diese Option bei einem Schritt, dessen Quelle auf diese Weise aktualisiert werden kann.
