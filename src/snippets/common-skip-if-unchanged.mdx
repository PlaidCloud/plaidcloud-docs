### Skip Re-Import If Source Files Unchanged Option

When this option is on, a workflow run of this step skips the whole import — download, conversion, and table rebuild — if the source files and the step's settings are unchanged since the last successful run. This avoids repeating the work when a scheduled workflow re-runs against source files that have not changed.

The step compares each source file by its path, size, and last-modified time (plus a content hash where the source provides one). If any file is added, removed, or changed, or the step's configuration changes, the import runs normally. The option is **on by default** — untick it to always re-import — and manual, one-off imports always run.

The skip also requires the target table to still hold the rows the last import loaded. If the table has since been emptied or its row count can't be read, the import runs again instead of skipping and leaving downstream steps without data.

Some sources (for example SFTP) do not provide a content hash, so on those the change signal is the file's size and last-modified time alone. A file replaced in place with the same size and modified time would then be treated as unchanged and skipped — untick this option on a step whose source can be updated that way.
