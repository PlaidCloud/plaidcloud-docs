指定联接条件。**推测**会按下列顺序，使用两个表的列能满足的第一种方式填充 **Join Map**：

- 此项目中联接相同两个表的另一个联接步骤所用的键
- 联接这两个表的已批准指标所用的键
- 其中一个表上设置的键列，按名称匹配到另一个表中的列，否则匹配到绑定到同一[项目元素](/zh-cn/guides/projects/data-model/)的那一列
- 两个表都有对应列的元素，如下所述
- **Table 1**和**Table 2**中名称相同的列
- 名称仅在大小写或下划线上有差异的列，或将 `id` 列匹配到以其表命名的列，例如表 *Customers* 对应的 `customer_id`

映射下方会有一行文字说明所用的方式，直到您更改映射为止。推测读取的是表的列而非行，因此保存前请检查这些键。**检查源**会以同样的方式填充空的 **Join Map**。

**来自共享元素的键。** 当列名是元素的名称或其某个别名时，该列属于该元素。对于两个表都有对应列的每个元素，推测会将每一侧的那一列配对，即使它们的名称不同。当某个表有多个对应该元素的列时，推测会将两个表都有的同名那一列配对，否则忽略该元素。类型属于不同种类的两列（如文本和日期）不会配对。当恰好只有一个表以某个共享元素命名时，联接仅基于该元素。表的名称在忽略大小写后，如果是该元素的名称、该名称加 `s`，或二者之一前面加一个单词和下划线，就算以该元素命名，例如 `customer`、`customers` 或 `dim_customer`。更长的名称（如 `sales_by_customer`）不算，首个单词本身就是元素的名称（如 `customer_product`）也不算。映射下方的那一行文字会说明这些元素，例如 *These keys are the elements both tables share: customer, period.* 当没有任何元素能给出配对时，推测会继续使用名称相同的列。

元素推测有两个限制：

- 它只配对属于元素的列，不会在它们旁边添加同名的列。当表的键由多个列组成而其中有些不是元素（如财政日历的键）时，推测只会提议元素列；请自行添加其他列。
- 名称为一个单词加下划线再加元素名称的表，即使并非如此，也会被视为该元素自己的表（如 `ar_customer` 或 `bank_account`），因此当它是唯一以某个共享元素命名的表时，联接仅基于该元素提议。

**映射中的元素。** 联接映射中属于某个元素的每一列，其旁边都会以标签显示该元素的名称。将鼠标悬停在标签上可查看元素、其说明及其提供的维度。映射下方的备注仅供参考，绝不会阻止您保存步骤：

- 将两个不同元素的列配对的行会收到一条备注，例如 *第 2 行配对了不同的元素：customer 和 vendor。*
- 当**推测**找不到任何键时，备注 *未找到可能的键。* 带有一个**数据模型**链接，会打开项目的[数据模型](/zh-cn/guides/projects/data-model/)页面，您可以在其中将表共享的列描述为元素。

如需手动添加更多列，请在该区域任意位置右键单击，选择**插入行**或**追加行**，分别在当前所选行之前或末尾添加一行。然后输入要从**Table 1**匹配到**Table 2**的列名。要从 **Join Map** 中移除某个字段，只需右键单击并选择**删除**。
