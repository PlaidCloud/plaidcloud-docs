### 데이터 매퍼 구성

![Table Data Mapper](/images/table_data_mapper.png)

데이터 매퍼는 소스 데이터의 열을 대상 데이터 테이블에 매핑하는 데 사용합니다.

#### 매퍼 검사 및 채우기

**소스 검사** 메뉴 버튼을 사용하면 소스에서 대상으로 열을 매핑하는 다양한 방법을 이용할 수 있습니다.

* 두 매핑 테이블 모두 채우기: 소스 데이터 테이블의 모든 값을 대상 데이터 테이블로 전파합니다. 기본적으로 이 방식이 적용됩니다.
* 소스 매핑 테이블만 채우기: 소스 데이터 테이블의 모든 값만 매핑합니다. 소스 열 구조가 변경된 상태에서 기존 워크플로를 수정할 때 유용합니다.
* 대상 매핑 테이블만 채우기: 모든 값을 대상 데이터 테이블에만 전파합니다.

소스 및 대상 열 옵션만으로 충분하지 않다면 다음과 같은 여러 방법으로 대상 데이터 테이블에 다른 열을 추가할 수 있습니다.

* **모두 전파**는 이미 존재하는지 여부와 관계없이 모든 소스 열을 대상 데이터 테이블에 삽입합니다.
* **선택 항목 전파**는 선택한 소스 열만 삽입합니다.
* 대상 쪽에서 마우스 오른쪽 버튼을 클릭하고 **행 삽입**을 선택하면 현재 선택한 행 바로 위에 행이 삽입됩니다.
* 대상 쪽에서 마우스 오른쪽 버튼을 클릭하고 **행 추가**를 선택하면 대상 데이터 테이블의 맨 아래(맨 오른쪽)에 행이 삽입됩니다.

<Aside type="danger">*모두 전파*를 선택하면 대상 목록에 이미 존재하는 열이 중복됩니다</Aside>

#### 열 삭제

대상 데이터 테이블에서 열을 삭제하려면 원하는 열을 선택한 다음 마우스 오른쪽 버튼을 클릭하고 **삭제**를 선택합니다.

#### 더 이상 목록에 없는 소스 열

대상 행이 소스 데이터 테이블에 더 이상 나열되지 않는 **소스 열**을 지정하는 경우가 있습니다. 예를 들어 소스를 다시 검사한 후에 이런 일이 생길 수 있습니다. 단계는 이러한 행을 자동으로 제거하지 않습니다. 대신 열 이름이 ⚠ 경고 표시 뒤에 빨간색으로 표시되며, 마우스를 올리면 해당 열이 소스 열에 없다는 메시지가 나타납니다. 유니온처럼 여러 테이블을 사용하는 단계에서는 각 테이블을 해당 테이블의 소스 열과 비교하여 검사합니다.

**상수**, **식** 또는 **개수(null 포함)** 요약이 지정된 행은 단계가 해당 소스 열을 읽지 않으므로 표시되지 않습니다. 소스 데이터 테이블에 열이 하나도 나열되지 않은 경우(예: 소스를 처음 검사하기 전)에도 아무것도 표시되지 않습니다.

표시된 행이 남아 있는 단계를 저장하면 **오래된 열 발견** 대화 상자가 해당 행을 각 행이 속한 탭 또는 테이블별로 나열하고 세 가지 선택지를 제공합니다.

- **모두 제거 후 저장** — 표시된 행을 제거한 다음 저장합니다.
- **그대로 저장** — 단계를 현재 상태 그대로 저장합니다.
- **취소** — 저장하지 않고 단계로 돌아갑니다.

행을 유지하면서 경고를 없애려면 해당 열을 소스 데이터 테이블에 다시 추가하거나 소스 데이터 테이블에 나열된 열을 선택하십시오.

#### 열 데이터 유형

모든 대상 열에는 **유형**이 있습니다. 소스에서 전파된 열은 소스 열의 유형을 그대로 유지하고, 직접 추가한 행은 **텍스트**로 시작하므로 **유형**을 설정하여 실제로 필요한 유형을 지정해야 합니다. 합산하거나 정렬하려는 열에는 숫자 또는 날짜 유형이 필요합니다. 텍스트는 텍스트로 정렬되고 합산되기 때문입니다.

유형이 전혀 없는 열이 포함된 상태로 저장된 단계도 실행됩니다. 유형은 단계가 시작될 때 해당 열이 읽는 소스 열로부터 결정됩니다. 유형을 읽어 올 곳이 없으면 텍스트로 처리됩니다. **SQL 추출** 단계의 열은 매핑된 소스가 아니라 사용자가 작성한 쿼리에서 가져오며, 같은 열 이름이 서로 다른 유형으로 여러 소스에 있는 경우에는 그중 하나를 추측하지 않고 텍스트를 사용합니다. 잘못 추측하면 웨어하우스가 거부할 수 있는 변환이 발생하지만, 모든 값은 텍스트로 변환할 수 있기 때문입니다.

<Aside type="caution">
**다중 테이블 조인**은 의도적으로 예외입니다. 이 단계는 실행을 거부하고 해당 열의 이름을 알려 주며, 여러 테이블을 조인하는 단계에서는 추측보다 이 방식이 더 유용합니다. 해당 열의 **유형**을 설정하고 다시 저장하십시오.
</Aside>

열이 어떤 유형이어야 하는지 지정하는 올바른 방법은 여전히 **유형**을 직접 설정하는 것입니다. 설정하지 않은 채 두면 소스 열이 어떤 유형이든 그대로 받아들이게 됩니다.

#### 열 순서 변경

대상 데이터 테이블에서 열을 재정렬하려면 원하는 열을 선택합니다. 다음 두 가지 방법 중 하나를 사용할 수 있습니다.
* **일괄 이동 화살표**: 오른쪽 위의 화살표에서 원하는 이동 옵션을 선택합니다.
* **컨텍스트 메뉴**: 마우스 오른쪽 버튼을 클릭하고 **맨 위로 이동**, **위로 이동**, **아래로 이동** 또는 **맨 아래로 이동**을 선택합니다.

#### 결과를 고유 레코드로만 줄이기

고유한 항목만 반환하려면 **고유** 메뉴 옵션을 선택합니다. 그러면 소스의 각 열마다 체크박스 집합이 표시됩니다. 고유한 결과만 반환하려면 해당 열 옆의 상자를 선택하기만 하면 됩니다.

상황에 따라서는 요약을 대신 사용하는 것이 좋을 수 있습니다.

고유 처리는 처음 발견된 고유 레코드를 유지하고 나머지는 버립니다. 실행 간 일관성이 중요하다면 데이터에 정렬을 적용하는 것이 좋습니다.

<Aside type="danger">고유성을 판단하는 데 모든 열을 선택하면 고유 처리가 적용되지 않은 것처럼 보일 수 있습니다. 데이터의 고유성을 정의한다고 판단되는 열만 선택하십시오.</Aside>

#### 집계 및 그룹화

결과를 집계하려면 **요약** 메뉴 옵션을 선택합니다. 그러면 대상 데이터 테이블의 각 열마다 선택 상자가 표시됩니다. 각 열에 적절한 요약 방법을 선택합니다.

**소스 검사**로 열을 채울 때, 숫자 열은 이름이 `id`, `customer_id`, `Order No`, `CustomerKey`처럼 식별자로 읽히거나, 테이블에서 키로 설정되어 있거나, 조인에서 키로 사용되는 경우 **합계** 대신 **그룹화 기준**으로 시작합니다.

- 그룹화 기준
- 합계
- 최소
- 최대
- 처음
- 마지막
- 개수
- 개수(null 포함)
- 평균
- 표준 편차
- 표본 표준 편차
- 모집단 표준 편차
- 분산
- 표본 분산
- 모집단 분산
- 고급 Non-Group_By


<Aside>집계를 사용할 때는 모든 열에 요약 유형을 **반드시** 지정해야 합니다</Aside>

식, 정리, 상수 등 데이터 매퍼의 고급 사용법은 [고급 데이터 매퍼 사용법](/ko/reference/workflow-steps/common/advanced-data-mapper-usage/)을 참조하십시오.
