*约 25 分钟 · 一份版本历史、一次比较、一个共享链接*

多人在同一个项目中工作时，第一天最重要的问题总是相同的：*改了什么？能否恢复到更早的状态？如何把一处更改从一个项目移到另一个项目？如何让队友直接找到我正在看的内容？* PlaidCloud 开箱即用地回答了这四个问题：工作是**有版本的、可比较的、可共享的**，本教程将逐一带您体验。

要记住的信息是：什么都不会丢失。每项更改都有记录，任意两个项目都可以比较，每个屏幕都有链接。

## 您将完成的内容

1. 查看项目的自动更改历史并阅读其日志。
2. 比较两个项目，并了解合并的作用。
3. 使用标签整理工作，以便日后查找。
4. 复制一个深层链接，将队友带到确切的位置。

## 先决条件

- 一个 PlaidCloud 工作区和一个您可以打开的项目。
- 如果想在真实内容上尝试比较，还需要第二个项目，例如一个副本，或对应的 QA/生产项目。[复制的项目](/zh-cn/guides/projects/managing-projects/#复制项目)效果很好。

## 第 1 部分：工作有版本记录

您在项目中构建的一切都会被自动跟踪，无需手动开启。

> **什么都不会丢失。** 项目的所有更改（工作流、数据编辑器、层次结构、表结构和用户定义函数）都会被跟踪，并支持**时间点恢复**。这意味着可以恢复意外的更改，也可以将任何更早的时间点复制出来进行比较。

在这种自动跟踪之外，项目及其元素还支持**版本控制**：创建版本很容易，并且可以**将更改从一个版本合并到另一个版本**。这是保留快照的简单方法，也可以在一个版本中开发，准备就绪后再将这些更改合并到非开发版本。

### 阅读项目日志

项目日志将每个单独的工作流日志整合到一个全面的项目活动视图中，包括成员分配、工作流运行等。

1. 打开**分析**。
2. 选择**项目**。
3. 打开**日志**选项卡（项目日志）。

要缩小繁忙日志的范围，请使用日志消息旁边的筛选控件并选择筛选条件。要完整阅读某一条目，请右键单击它并查看**日志消息**框。

> **清除日志也会删除子日志。** **清除日志**按钮会删除项目日志*以及*其下每个工作流的子日志。只有在确实希望删除这些历史记录时才这样做。

## 第 2 部分：比较两个项目

比较可让您准确看到两个项目之间的差异，对于可以安全复制的部分，还可将所选更改从一个项目合并到另一个项目。它适用于两种日常情形：**在环境之间推广更改**（将 QA 项目推广到对应的生产项目），以及**对照较早的副本进行审阅**（按月克隆的项目，用于查看有何变化）。

整个过程都由您掌控：只有在您选择具体项目并应用之后才会写入，并且可以先通过试运行进行验证。

### 打开比较

1. 打开**分析**并选择**项目**。
2. 右键单击要作为起点的项目（或使用其操作菜单），然后选择**比较对象…**。
3. 您作为起点的项目会自动填入**源**。从下拉列表中选择**目标**。
4. 单击**比较**。

两个项目必须位于同一个工作区。比较之前，可使用**交换**对调源和目标；方向很重要，因为合并是*从*源复制*到*目标。

### 阅读比较结果

左侧将每个差异归入其类别：**工作流**（嵌套**步骤**）、**变量**、**维度**、**编辑器**、**UDF**、**视图**和**表**。每个项目都带有其状态徽章：

| 徽章 | 含义 |
|---|---|
| **已添加** | 存在于源但不在目标中，将在目标中创建 |
| **已修改** | 两者都有，但配置不同 |
| **已删除** | 存在于目标但不在源中 |
| **未更改** | 两侧完全相同（默认隐藏） |

选择一个已更改的项目，右侧会显示**字段 / 源 / 目标**表，其下方是完整的**配置差异**。可以按名称或路径筛选，或切换状态复选框，以便聚焦较长的列表。

### 了解合并的作用

并非所有差异都能安全复制，因此比较会为每个项目添加标注：

- **工作流、步骤和变量**可以合并。
- **维度、编辑器、UDF、视图和表**为**仅查看**：可在此处审阅，但需要使用各自专用的工具复制过去。

要合并，请选择可合并的项目，单击**试运行**以在不写入的情况下进行验证，然后单击**应用**并确认。已合并的项目在目标中保留其标识，因此日后可以再次比较并合并后续更改，而不会产生重复项。

> **合并会更改目标。** 应用之前，请查看差异、执行试运行，并确认源和目标的方向正确。如果在您加载比较之后有其他人编辑了目标，合并会停止而不是覆盖他们的工作，此时请刷新并重新应用。

关于在互相复制的项目之间推广 Dev → QA → 生产，参见[从您复制的项目重新同步](/zh-cn/guides/projects/compare-and-merge-projects/#从您复制的项目重新同步)，它按复制谱系而不是按名称来配对项目。

## 第 3 部分：使用标签整理

**标签**是您附加到对象上的自由格式标记，对象包括项目本身及其工作流、步骤、表、维度、数据编辑器和 UDF。可以用它们按任何对您重要的维度（工作阶段、源系统、所有者、发布版本）对相关项目分组，并快速再次找到它们。

每个可打标签的对象在其详细信息面板中都有一个**标签**框：

1. 在**标签**框的任意位置单击，放置光标。
2. 输入标签文本。
3. 按 **Enter**（或输入逗号）添加。

使用标签上的 **×** 可删除标签，或在输入框为空时按 **Backspace** 删除最后一个标签。

> **标签以小写形式存储。** PlaidCloud 会自动将每个标签转换为小写，并拒绝同一对象上的重复标签。保持标签集一致，它就会成为切分大型项目的轻量方式。

要查找已打标签的项目，请在项目列表的筛选框中输入标签，搜索会同时匹配标签文本和项目名称。

## 第 4 部分：共享深层链接

PlaidCloud 会使地址栏与您打开的内容保持同步。打开一个工作流、表或维度，URL 就会成为指向它的**深层链接**。没有单独的共享按钮，地址栏*就是*链接。

1. 打开要共享的对象。
2. 从浏览器的地址栏复制完整的 URL。
3. 发送出去，打开它的人会进入同一个屏幕。

链接以项目优先：先是项目，然后是其中的对象，两者之间以 `~` 分隔。

| 屏幕 | 链接结尾 |
|---|---|
| 项目 | `#p~<project>` |
| 工作流（步骤网格） | `#p~<project>~w~<workflow>` |
| 工作流（可视化工作流设计器画布） | `#p~<project>~c~<workflow>` |
| 工作流中的某个步骤 | `…~w~<workflow>~s~<step>` |
| 表资源管理器 | `#p~<project>~t~<table>` |
| 维度层次结构 | `#p~<project>~d~<dimension>` |
| 数据编辑器 | `#p~<project>~e~<editor>` |

打开链接会恢复**父级上下文**，而不只是那一个窗口：指向工作流的链接也会重新打开它所属的项目，因此接收者到达时，标签栏中会有周围的项目。步骤链接甚至会为他们选中该步骤。

> **链接携带的是*位置*，而不是权限。** 打开链接的人仍然需要有项目的访问权限。没有权限的人看不到该对象，因此共享链接是安全的。可在[控制数据访问](/zh-cn/get-started/tutorials/control-data-access/)中控制谁能看到什么。

旧的 `#te?p=…&t=…` 样式链接仍然可用，并会在首次导航时自动改写为当前更易读的形式。

**什么都不会丢失，现在您可以证明这一点。** 您已经阅读了项目的历史，比较了两个项目并以单一方向安全合并，使用标签整理工作以便再次查找，并给队友发送了一个深层链接，让他们直接来到您所在的位置。
