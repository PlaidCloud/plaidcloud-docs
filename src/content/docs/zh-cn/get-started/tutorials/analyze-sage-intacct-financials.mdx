*约 40 分钟 · 一个可用的 Sage Intacct 连接、一张已加载的试算平衡表、一份部门损益表、一个仪表板，以及一个计划刷新*

这是使用 Sage Intacct 的财务总监或 FP&A 分析师上手的第一条路径：完成后，您将直接从 Intacct 提取**按维度划分的科目余额**，把它们整理成可以像财务报表一样阅读的**部门试算平衡表和损益表**，放到仪表板上，并让整个流程自动刷新。无需导出预置报表，无需手动重新录入，数字直接来自 Intacct 并保持最新。

只需连接一次、提取一次，然后进入真正重要的部分：把原始余额整理成业务人员周一早晨阅读的汇总。

## 前提条件

- 一个 PlaidCloud 工作区和一个用于工作的项目（如需要，可以[开始试用](https://app.plaidcloud.com)）。
- **一个可用的 Sage Intacct 连接。** 请先按照[连接到 Sage Intacct](/zh-cn/guides/connections/sage-intacct/) 操作：您需要启用 Web Services，需要一个对所读取对象具有权限的 Web 服务用户，以及连接的四个凭据字段：**客户端 ID**、**客户端密钥**、**Web 服务用户名**和**公司 ID**。开始本教程之前，请确认连接可用。
- 了解您的**运营实体**（您要报告的实体 ID），以及包含损益表科目（收入和费用）的大致**科目编号范围**。下面的示例使用 `201` 和 `301` 作为实体，使用 `4010`–`9999` 作为损益表范围，请替换为您自己的值。

<Aside type="note">
提取之后的所有操作都是点选式的，无需 SQL，也无需代码。唯一与 Intacct 相关的部分是**导入 Sage** 步骤，它按日期和科目范围读取 Intacct 的*按维度划分的科目余额*。它为每个科目与维度的组合返回一行，每行包含期初余额、本期余额和期末余额。
</Aside>

## 步骤 1：创建工作流

工作流是提取并整理数据的管道。

<Steps>

1. 打开项目，切换到**工作流**选项卡。
2. 单击**新建工作流**，命名为 `Intacct Financials` 之类的名称，然后打开它。

</Steps>

## 步骤 2：提取试算平衡表

[导入 Sage 步骤](/zh-cn/reference/workflow-steps/sage-intacct/import-sage/)按日期范围和科目范围提取科目余额，并把您选择的维度带到每一行上，这就是您的试算平衡表。

<Steps>

1. 添加一个**导入 Sage**步骤。

2. 在其配置中设置：

   | 字段 | 值 |
   |---|---|
   | **连接** | 您的 Sage Intacct 连接 |
   | **公司** | 要读取的 Intacct 公司 |
   | **开始日期** / **结束日期** | 您正在结账的期间，例如当月的第一天和最后一天 |
   | **Start account** / **End account** | 您的损益表范围，例如 `4010` 到 `9999` |
   | **实体** | 您的运营实体，例如 `201`、`301` |
   | **维度** | 开启您用于报告的维度，通常是**位置**、**部门**、**员工**和**类别** |

3. 将**目标**设置为名为 `intacct_trial_balance` 的新表。

4. 运行该步骤。现在每个科目与维度的组合有一行，包含 `startbalance`、`periodbalance` 和 `endbalance` 列，以及您启用的每个维度的 ID/名称对（例如 `departmentid` / `departmentname`、`locationname`）。

</Steps>

<Aside type="caution">
Intacct 将所有列都作为**文本**返回，并且 Sage 提取是**单次请求**（不分页）。科目余额结果较小，所以这里没有问题，但不要将此步骤用于大批量的行项目明细。您将在下一步设置真正的列类型，到那时类型才起作用。
</Aside>

<Aside type="note">
**开始日期**和**结束日期**必须同时设置，只设置其中之一会被忽略。如果您启用了某个维度，但不需要它的 ID 和名称，可以在下一步中删除多余的列。（**Warehouse** 维度复选框没有任何效果；如果需要在输出中包含仓库，请使用**自定义维度**。）
</Aside>

## 步骤 3：将余额整理为损益表

接下来是分析，只需一个点选式转换，无需 SQL。您的损益表范围会按部门汇总为几个报表项目，并翻转符号，使收入显示为正数。[Table Extract 步骤](/zh-cn/reference/workflow-steps/tables/table-extract/)在其**表数据选择**和**筛选器**选项卡上即可完成全部工作。

<Steps>

1. 添加一个 **Table Extract** 步骤。将其**源**设置为 `intacct_trial_balance`，将**目标**设置为新表 `intacct_pnl`。

2. 在**列**选项卡上，单击**汇总**以启用聚合，然后设置三个目标列：

   - **`departmentname`**：直接从源映射。类型为**文本**，汇总方式为**分组依据**。
   - **`pnl_line`**：一个**表达式**（见下文），将科目编号转换为报表项目。类型为**文本**，汇总方式为**分组依据**。
   - **`amount`**：表达式 `func.to_float64(intacct_trial_balance.endbalance) * -1`，将文本余额转换为数字并翻转符号。类型为**货币**，汇总方式为**求和**。

   将 `amount` 目标列的**类型**设置为**货币**，文本余额才能求和。对于 `pnl_line`，双击其**表达式**单元格并输入以下内容（通过点选选取列，以及选取**条件**组中的 `case` 函数）：

   ```python
   case(
       (func.to_float64(intacct_trial_balance.glaccountno) < 5000, '1 - Revenue'),
       (func.to_float64(intacct_trial_balance.glaccountno) < 6000, '2 - Cost of Goods Sold'),
       else_='3 - Operating Expenses',
   )
   ```

3. 运行该步骤。

</Steps>

`* -1` 是唯一的会计处理：Intacct 将收入记为贷方（负数），将费用记为借方（正数），因此对期末余额取反会使**收入显示为正、成本显示为负**，每个部门的各项目*相加即为净利润*。请根据您的会计科目表调整 `case()` 中的科目编号分界值。表达式使用 PlaidCloud 的点选式编辑器，请参阅[高级数据映射器用法](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/)和[表达式参考](/zh-cn/reference/expressions/)。

<Aside type="tip">
想要全公司的损益表而不是按部门？从目标列中删除 `departmentname`，只保留 `pnl_line`（分组依据）和 `amount`（求和）。
</Aside>

## 步骤 4：像财务人员一样阅读

打开 `intacct_pnl` 表。每个部门有三个数字：

| departmentname | pnl_line | amount |
|---|---|---|
| Operations | 1 - Revenue | 486,200.00 |
| Operations | 2 - Cost of Goods Sold | -190,540.00 |
| Operations | 3 - Operating Expenses | -212,880.00 |

可以直接读出：

- **毛利** = 收入 + 销货成本（销货成本已经为负）→ `486,200 − 190,540 = 295,660`。
- **净利润** = 三个项目之和 → `82,780`。
- **毛利率** = 毛利 ÷ 收入 → 约 61%。

首先要做的是**核对**：对同一期间和同一实体运行 Intacct 自己的损益表（财务报表），确认收入和净利润一致。如果不一致，几乎总是范围不同造成的：遗漏了某个实体、科目范围截断了损益表的一部分，或者期间未对齐。只有核对一致后，才可信任该管道。

<Aside type="tip">
想要经典的期间横排布局？添加一个读取 `intacct_pnl` 的 [Table Pivot 步骤](/zh-cn/reference/workflow-steps/tables/table-pivot/)：将期间透视为列，保留 `pnl_line` 作为行，并对 `amount` 求和。要首先得到期间列，请在步骤 3 中将 `end_date` 添加为**分组依据**列。这样月度对比一目了然，无需 SQL。
</Aside>

## 步骤 5：放到仪表板上

表中的数字尚可，但发给 CFO 的应该是图表。先[发布](/zh-cn/get-started/tutorials/load-and-transform-data/#步骤-7发布结果) `intacct_pnl`，然后按照[构建仪表板](/zh-cn/get-started/tutorials/build-a-dashboard/)添加：

- 按 `departmentname` 显示净利润（或收入）的**条形图**，以及
- 显示各 `pnl_line` 的**条形图**，使收入、销货成本和运营费用的构成一目了然。

这就是一个实时的 Sage Intacct 财务仪表板：无需导出，每次工作流运行时都会刷新。

## 步骤 6：计划刷新

<Steps>

1. 从头到尾完整运行一次工作流，确认每个步骤都是绿色。
2. [为工作流设置计划](/zh-cn/get-started/tutorials/schedule-a-workflow/)：按结账周期每月一次，或者如果希望整个月内数字都保持最新，则每周一次。

</Steps>

由于提取是整表替换，每次运行都会重新读取您所设置的日期和科目范围内的余额，因此请将范围限制在所需的窗口内（当前期间、您的损益表科目），而不是全部历史数据。

## 步骤 7：使用统计账户添加人均指标

Intacct 还会在财务科目表之外跟踪非货币型的**统计账户**，例如人数、面积、单位数。使用设为统计模式的第二个**导入 Sage**步骤提取它们，然后联接到损益表上，即可读取诸如各部门人均运营费用之类的指标。再增加三个标准步骤，仍然无需 SQL。

<Steps>

1. 添加第二个**导入 Sage**步骤。在其配置中设置：

   | 字段 | 值 |
   |---|---|
   | **连接** | 您的 Sage Intacct 连接 |
   | **公司** | 要读取的 Intacct 公司 |
   | **开始日期** / **结束日期** | 与步骤 2 相同的期间 |
   | **统计** | **仅统计** |
   | **Start account** / **End account** | `0000` 到 `9999`：统计账户的编号不一定落在财务科目表的编号范围内，因此请提取完整范围，而不是步骤 2 中的损益表范围 |
   | **实体** | 您的运营实体，例如 `201`、`301` |
   | **维度** | **部门**：用于按人均报告的维度 |

2. 将**目标**设置为名为 `intacct_statistics` 的新表。

3. 运行该步骤。每个统计账户与部门的组合有一行，`endbalance` 中是统计值本身，例如该部门期末的人数。

</Steps>

现在把人数带到损益表上并相除，但不要直接使用 `intacct_statistics`。该表中每个统计账户与部门的组合有一行（人数、面积、单位数，凡是您跟踪的都有），因此仅按 `departmentname` 联接会使每个损益表行按该部门的统计账户数量成倍扩散，`amount_per_head` 也会被恰好落在该行上的某个统计账户相除。请先筛选出人数，使联接后每个部门只有一行，这样比值才有意义。

<Steps>

1. 添加一个 **Table Extract** 步骤。将其**源**设置为 `intacct_statistics`，将**目标**设置为新表 `intacct_headcount`。在**列**中，原样传播所有列，此处无需聚合。在**筛选器**选项卡上，对源数据添加一个**选择数据子集**筛选器：`intacct_statistics.glaccountno == '9000'`，请将 `9000` 替换为您自己的人数统计账户编号（如果您的提取结果返回的是科目名称列，则改为按该列筛选；`glaccountno` 仍是文本，因此请与带引号的字符串比较）。运行该步骤，`intacct_headcount` 现在每个部门恰好有一行。

2. 添加一个 [Table Outer Join 步骤](/zh-cn/reference/workflow-steps/tables/table-outer-join/)。将 **Table 1** 设置为 `intacct_pnl`，将 **Table 2** 设置为 `intacct_headcount`，并按 `departmentname` 联接，现在每个部门都是干净的一对一匹配。将**联接类型**保留为默认的**左联接**，这样每个损益表行都会保留，部门匹配时填入人数。目标为新表 `intacct_pnl_with_headcount`，并传播两个表的所有列。

3. 运行该步骤，然后添加一个 **Table Extract** 步骤，读取 `intacct_pnl_with_headcount`，目标为新表 `intacct_pnl_per_head`。在**列**中传播现有列，然后再添加一个目标列：`amount_per_head`，表达式为 `intacct_pnl_with_headcount.amount / func.to_float64(intacct_pnl_with_headcount.endbalance)`，类型为**货币**。

4. 运行该步骤。

</Steps>

查看 **`3 - Operating Expenses`** 行的 `amount_per_head`，即可得到各部门的人均运营费用，读法与步骤 4 相同，只是多了一列。可以将其与损益表一起添加到仪表板上，也可以将其纳入步骤 6 的计划，使其与其他内容一起刷新。

## 您构建了什么

从一个空工作流开始，您提取了实时的 Sage Intacct 科目余额，用一个标准转换步骤将其整理为**部门损益表**，联接了统计账户以得到人均指标（整个管道中没有任何 SQL），放到了仪表板上，并设置了自动刷新。这就是财务团队的核心报告循环，现在已实现自动化。
