*约 30 分钟 · 一张已发布的表、一个图表、一个共享的仪表板*

您已经有一张从工作流发布的干净的表。本教程将它变成人们一眼就能读懂的内容：先是一个图表，然后是围绕它构建的仪表板，最后将仪表板共享给合适的人。要在屏幕上得到第一个图表无需 SQL，只需点选并查询即可。

如果您已完成[加载、转换和发布数据](/zh-cn/get-started/tutorials/load-and-transform-data/)，那里发布的 `sales_final` 表正是本教程假定的起点。任何已发布的表同样适用。

## 您将构建的内容

一个仪表板，包含基于同一张已发布表的两个图表：一个显示总收入的 Big Number，以及一个按分组列细分收入的条形图。完成格式设置并保存后，工作区即可看到。

## 先决条件

- 一个 PlaidCloud 工作区，以及一个您可以打开的项目。
- 该项目中有一张**已发布**的表。如果没有，请先按照[加载、转换和发布数据](/zh-cn/get-started/tutorials/load-and-transform-data/)操作，或发布任何现有的表：在**表**选项卡中右键单击它，然后选择 **Set Published Table Reporting Name**。参见[发布表](/zh-cn/guides/data/publish/)。
- 无需在仪表板区域安装任何内容，首次从 PlaidCloud 打开仪表板时会自动为您创建仪表板账户。

> **只有已发布的表才能进入仪表板。** 仪表板通过表的已发布报表名称读取表，而不是内部表名。如果之后您的表没有作为数据集显示，通常是因为它从未发布，或以您不认识的名称发布，请在**表**选项卡中检查**发布为**列。

## 步骤 1：打开仪表板区域

1. 在 PlaidCloud 的项目中，打开**仪表板**区域。
2. 首次执行此操作时，您的仪表板账户会自动设置，无需手动创建。您能看到的内容取决于您的工作区成员身份和安全组。
3. 因为该表属于您可以访问的项目，所以您的已发布表现在可作为**数据集**使用。

关于仪表板可见性如何对应工作区成员身份，参见[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。

## 步骤 2：准备数据集

在绘制图表之前，先告诉仪表板每一列应如何使用。每张表只需设置一次，这样点选式资源管理器才能很好地工作。

1. 单击数据集上的编辑图标。
2. 打开 **List Columns** 选项卡。
3. 为每一列设置适用的角色，然后单击**保存**：

| 设置 | 在以下情况启用 |
|---|---|
| **Groupable** | 需要按此字段细分指标（区域、产品、月份） |
| **Filterable** | 需要按此字段筛选 |
| **求和** / **最小值** / **最大值** | 这是需要合计或汇总的数值度量 |
| **Count Distinct** | 需要统计此字段的唯一值数量 |
| **Is temporal** | 这是日期或时间字段 |

> **将日期列标记为时间列。** 资源管理器中基于时间的筛选器和“Since / Until”控件仅对标记为 **Is temporal** 的列有效。这是最容易遗漏的设置。

## 步骤 3：构建您的第一个图表

从资源管理器开始，它以普通的 Table View 打开，将其调整为显示总收入的 Big Number。

> **使用您自己的度量列。** 本教程对 `revenue` 列绘制图表，但先决条件只要求“任何已发布的表”。凡是出现 `revenue` 之处，请替换为您实际想要合计的数值列（`amount`、`sales`、`quantity` 等）。

1. 单击数据集以打开它。默认显示的是 **Table View**。
2. 在指标部分添加所需的度量：若要得到累计总数，输入并选择要求和的列（例如对 `revenue` 做 `SUM`），或使用 **COUNT(\*)** 统计行数。
3. 添加想要用来细分数值的任意**分组依据**字段。若只要一个醒目的总数，则将分组依据留空。
4. 单击**查询**运行并查看结果。
5. 滚动到 **Chart Options**（或可视化类型选择器），将图表类型切换为 **Big Number**。图表可以是表格、Big Number、条形图等，每种方式以不同形式显示同一个查询结果。
6. 再次单击**查询**以重新绘制。

现在制作第二个图表，将同一度量细分：

1. 在同一数据集上开始新的探索。
2. 保留 `revenue` 的 `SUM` 作为指标，并按可分组的列（例如 `region` 或 `product`）添加**分组依据**。
3. 将图表类型设为 **Bar Chart** 并**查询**。
4. 如果只想看排名靠前的行，请打开**选项**并设置**行数限制**，例如 `10` 可得到前十名的条形图。

> **优先使用显示格式，而不是修改数据。** 有两种方式对值进行舍入或重新设置格式：在表中转换它们，或在显示时设置格式。通常的选择是在显示时设置格式：底层的值保留完整精度，每位查看者看到的都是整洁的数字。这就是下一步。

## 步骤 4：设置数字格式

原始度量返回时没有格式。请在图表上而不是在数据中解决这个问题。

- **Big Number：** 编辑图表，打开 **Customize** 选项卡，设置 **Number Format**。
- **表：** 编辑图表，打开 **Customize** 选项卡，在 **Customize Column** 下选择一个数值列（以 `#` 显示），并设置其 **D3 Format**。

默认值为 **Adaptive formatting**，它会根据数值自动调整。要固定格式，请从下拉列表中选择一种，或输入 D3 格式字符串：

| 格式 | 输入 | 显示 |
|---|---|---|
| `,d` | `12345.67` | `12,346` |
| `$,d` | `12345.67` | `$12,346` |
| `$,.2f` | `12345.67` | `$12,345.67` |
| `,.2%` | `13.215` | `1,321.50%` |

完整的格式语法（货币符号、填充、精度、SI 前缀）见[设置数字和其他数据类型的格式](/zh-cn/guides/dashboards/formatting-numbers/)。

> **要舍入到整数美元？请使用 `,d` 或 `$,d`，而不是 `,.0f`。** `,.0f` 形式是数字格式出错的已知原因；`,d`（十进制，舍入为整数）是去掉小数的可靠方法。

## 步骤 5：添加计算度量（可选）

如果您想要的数字不是普通的列，而是比率、利润率百分比或条件求和，请将其写成指标。指标和计算列在数据集上以 PostgreSQL 风格的 SQL 编写。

```sql
SUM("revenue") / (COUNT(*) + 0.00001)
```

`+ 0.00001` 用于避免某个分组没有行时出现除以零。更多模式（`CASE` 逻辑、用于处理空值的 `COALESCE`、条件求和）参见[指标示例](/zh-cn/guides/dashboards/example-metrics/)和[计算列示例](/zh-cn/guides/dashboards/example-calculated-columns/)。

## 步骤 6：组装仪表板

仪表板是已保存图表的布局。请将您构建的每个图表关联到同一个仪表板，让它们汇集在一起。

1. 对您的 Big Number 打开 **Edit Chart**。
2. 在**仪表板**部分，输入它应显示在其上的仪表板名称。如果该仪表板尚不存在，在这里为其命名。
3. 保存，然后对条形图重复此操作，并指向同一个仪表板。
4. 打开仪表板即可看到两个图表。在仪表板自己的编辑模式下，可以排列图块、调整大小并添加筛选器。

关于布局、筛选器和交互选项的完整说明，参见[了解仪表板](/zh-cn/guides/dashboards/learning-dashboard/)。

## 步骤 7：共享

谁能看到仪表板，首先取决于 PlaidCloud 访问权限，然后才是叠加在其上的仪表板服务角色。

- **默认情况下，项目成员可以看到它。** PlaidCloud 中的仪表板列表会显示某人有权访问的项目所属的已发布仪表板，因此任何能打开该项目的人都可以找到您的仪表板，无需额外步骤。
- **随时添加图表所有者。** 保存图表时，请将所有需要它的人添加到图表的**所有者**中，否则同事在访问不到的图表上可能会遇到“requires the datasource… permission”错误。在保存时添加所有者，比事后补充访问权限更容易。
- **仅在需要时才限制到特定角色。** 仪表板可以限制为仪表板服务中的特定角色，这在仪表板自己的属性中设置。受限的仪表板对没有匹配角色的任何人隐藏，因此如果您限制了某个仪表板，请告知应有权访问它的人。PlaidCloud 中的项目访问权限仍然叠加生效：角色授权绝不会把仪表板授予无法访问相应项目的人。

完整的可见性规则参见[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。

## 保持仪表板最新

无需手动刷新仪表板。当工作流重新发布图表背后的表时，读取该表的每个图表都会丢弃其缓存结果，下一位打开仪表板的人会看到新的数字。

> **看起来过时的仪表板几乎从来不是缓存的问题。** 如果工作流运行后数字看起来仍是旧的，请检查工作流，确认运行已完成且重新发布了您期望的表，而不是检查缓存。还要以**相同**的已发布名称重新发布：图表与名称绑定，因此以新名称重建的表会使旧图表仍指向旧数据。

如果确实需要强制刷新，请打开 **Edit dashboard** 旁边的菜单，选择 **Force refresh dashboard**。完整详细信息（包括结果保留多长时间）参见[仪表板缓存](/zh-cn/guides/dashboards/dashboard-caching/)。
