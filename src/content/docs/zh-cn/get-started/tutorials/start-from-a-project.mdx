*约 15 分钟 · 复制或导入项目，然后据为己有*

在 PlaidCloud 中，第一天最快的收获不是从零开始构建，而是从已经可用的内容起步。选择一个已经能导入数据、转换数据并产生结果的项目，获得自己的副本，然后修改属于您的那部分。

这里没有可供浏览的模板库。取而代之的是，有两种可靠的方式可以从可用的项目开始：

- **复制项目**：将工作区中已有的项目复制为您自己的全新项目，请参阅[复制项目](/zh-cn/guides/projects/managing-projects/#复制项目)。
- **运行可移植项目包**：他人以自包含的[可移植格式](/zh-cn/guides/projects/export-to-portable-format/)包导出的项目，可在 PlaidCloud 之外独立运行。

选择哪一种取决于您的目标。

| 您想要… | 使用 | 结果 |
|---|---|---|
| 在 PlaidCloud 内基于某个项目继续迭代 | **复制项目** | 一个您拥有的新项目，可随时编辑和运行 |
| 离线运行项目的逻辑，或交给没有 PlaidCloud 登录权限的人 | **导出为可移植格式** | 独立的 Python + DuckDB 包 |

## 前提条件

- 一个 PlaidCloud 工作区（如果还没有，请[开始免费试用](https://app.plaidcloud.com)）。
- **路径 A**：您能在**项目**选项卡中看到的现有项目，可以是自己的项目、共享的示例，或同事授予您访问权限的任何项目。
- **路径 B**：他人导出的可移植格式 `.zip`，或您自己要导出的项目。

> **不确定什么是项目？** 项目是 PlaidCloud 中的工作单元，它拥有自己的数据、工作流、维度和历史记录，与任何其他项目不共享状态。如果这对您来说还很陌生，请先阅读[项目](/zh-cn/guides/projects/)。

## 路径 A：复制现有项目

复制会生成完整且可编辑的副本（全部内容，或只含您选择的部分），放入完全属于您的全新项目中。

1. 打开 **Analyze**，选择**项目**选项卡。
2. 选择要作为起点的项目。
3. 点击**操作**按钮，选择**复制项目**。
4. 选择 **a new project** 作为目标。为其指定名称和 **ID**。
5. 保持选择树完全勾选以带过整个项目，然后点击**复制项目**。

> **ID 是永久的。** 为新项目指定的 ID 会成为其架构名称，之后无法更改。请选择一个您乐于长期使用的 ID：名称可以随时更改，ID 则不行。

复制在后台运行，完成时会通知您。完整的对话框说明请参阅[复制项目](/zh-cn/guides/projects/managing-projects/#复制项目)。

### 只带入需要的部分

您不必复制全部内容。选择树按类型列出项目包含的内容：工作流、步骤、表、维度、数据编辑器、用户定义函数，您可以只勾选需要的部分。勾选的任何内容都会自动带上其依赖项：步骤读取和写入的表、加载所依据的维度、调用的函数以及调用的任何子工作流。您无需自己梳理这些依赖关系。

> **让引用指向您的副本。** 请保持**更新引用**处于开启状态（默认值）。它会重写复制的步骤，使其指向新项目中的表和对象，而不是原始项目，这几乎总是您想要的。只有在您特意希望副本继续读取源项目的对象时才将其关闭。

## 路径 B：从可移植包开始

可移植包是打包为自包含 Python 程序的项目，运行在 [DuckDB](https://duckdb.org) 上，无需连接 PlaidCloud。当您希望项目在*平台之外*运行（在笔记本电脑上、CI 作业中，或交给没有 PlaidCloud 登录权限的人）时，这是从可用项目起步的方式。

如果同事已经给了您一个包，请跳到[运行](#运行)。要自己创建：

1. 打开 **Analyze**，选择**项目**选项卡。
2. 选择单个项目。
3. 打开**操作**菜单，选择**导出为可移植格式**。
4. 设置包写入的**文档账户**和**文件夹路径**，保持勾选 **Include data** 以便无需任何外部源即可运行，然后点击**导出**。

结果是一个 `.zip`，其中包含每个工作流各一个 Python 脚本、Parquet 数据快照、列出脚本所需 Python 包的 `requirements.txt`，以及 `README.md`、`COVERAGE.md` 和 `RUN_ORDER.md`。每个文件的含义请参阅[导出为可移植格式](/zh-cn/guides/projects/export-to-portable-format/)。

> **可移植包是单向快照，而不是重新导入。** 它在 PlaidCloud *之外*运行，不会同步回来：对包所做的更改不会返回到项目，编辑后重新导出会生成全新的包。若要继续在 PlaidCloud 内工作，请改用**路径 A**。若要在 PlaidCloud 中继续迭代，*并且*分发可运行的副本，则两者都做。

> **保真度为尽力而为。** SQL 转换步骤会被精确复现。专有步骤和有副作用的步骤（分摊、维度加载、通知、文档和报表步骤、脚本）会导出为不会重新运行的存根，转而打包其最近一次物化的输出作为快照。每个步骤的保真度记录在 `COVERAGE.md` 中。如需完全重新计算的结果，请在 PlaidCloud 中运行项目。

### 运行

解压包，创建 Python 环境，并按 `RUN_ORDER.md` 列出的顺序运行每个工作流脚本：

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python pipeline_<workflow>.py
```

每个脚本都会在本地 DuckDB 数据库中构建其表。SQL 步骤实时重新计算；存根步骤则保留其快照输出。

## 据为己有

无论如何开始，副本现在都可以由您修改，这就是第一天收获回报的地方。几个起步操作：

| 要做的事 | 位置 |
|---|---|
| 将导入指向*您自己的*数据，而不是示例数据 | 每个工作流中的导入步骤，请参阅[加载、转换和发布数据](/zh-cn/get-started/tutorials/load-and-transform-data/) |
| 重命名项目或调整谁可以打开它 | [管理项目](/zh-cn/guides/projects/managing-projects/) → 访问控制 |
| 为在多个工作流中重复出现的值设置项目变量 | [管理项目变量](/zh-cn/guides/projects/managing-projects/#管理项目变量) |
| 确认整个流程仍能端到端运行 | 在每个工作流上点击**运行**并观察日志 |

由于每项更改都会被跟踪，您可以放心试验，如果编辑出了问题，[自动变更跟踪](/zh-cn/guides/projects/managing-projects/#版本历史)可让您恢复到任何较早的时间点状态。
