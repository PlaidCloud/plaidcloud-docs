*约 20 分钟 · 一个失败的步骤、一次 AI 诊断、一次已应用的修复*

运行工作流时，某个步骤变红，仅凭错误文本看不出该改什么。本教程演示的正是这一刻：打开 PlaidCloud 内置的 **AI Assistant**，让它对照实时数据诊断失败的步骤，批准它提出的修复方案，然后重新运行以确认。接着，用同一个助手根据一段自然语言描述编写提取 SQL 步骤。

这是产品内置的 AI 助手，帮助您构建和修复工作流。它**不同于**将外部 AI 编码代理（Claude Code、Cursor、MCP）连接到租户，后者属于互补的另一条路径，详见[连接 AI 编码代理](/zh-cn/get-started/tutorials/mcp-with-ai-agent/)。

## 您将完成的操作

| 阶段 | 使用的功能 |
|---|---|
| 查看步骤失败并阅读错误 | 项目的**日志**选项卡 |
| 诊断并修复失败的步骤 | 日志条目 **AI Assistant** 选项卡上的修复助手 |
| 确认修复 | 助手提出重新运行步骤时回答“是” |
| 无需编写 SQL 即可添加新查询 | 提取 SQL 步骤中的 **Generate SQL with AI** |

## 前提条件

- 一个 PlaidCloud 工作区（如果没有，请[开始免费试用](https://app.plaidcloud.com)）和一个可编辑的项目。
- 一个至少包含一个步骤的工作流，最好是会失败的，或者可以让它失败的（在转换中打错一个列名就足以重现此场景）。

> **助手以您的权限进行修复。** 它只能修改您本来就可以编辑的步骤，并且它所做的每项更改都可以通过重新运行或直接编辑步骤来撤销。请参阅[使用 AI 修复工作流错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/)。

## 步骤 1：运行工作流并找到错误

步骤失败时，工作流和失败的步骤上都会出现错误标记，失败信息会写入工作流日志。

1. 打开项目，运行工作流（或正在测试的单个步骤）。
2. 切换到项目的**日志**选项卡。日志按步骤运行的先后列出事件，包括警告和错误。
3. 在日志列表中，选择失败步骤的条目。其完整信息（包括任何回溯）会在右侧面板的**日志消息**选项卡下打开。

> **手边没有出错的工作流？30 秒就能造一个。** 在任意转换步骤中，编辑某一列的表达式，使其引用一个不存在的列，例如把 `net_amount` 改成 `net_amnt`，然后保存。运行该步骤，它会失败，日志中的错误提示列 `net_amnt` 不存在。这是修复助手专门用来发现的真实配置错误，因此用它可以顺畅地完整走完本教程。

有关错误如何呈现及处理方式，请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)和[查看工作流日志](/zh-cn/guides/workflows/viewing-workflow-log/)。

## 步骤 2：打开修复助手

修复助手就在原始错误旁边，并且已经指向失败的步骤。

1. 选中失败的日志条目后，找到右侧显示**日志消息**的面板。
2. 将该面板切换到 **AI Assistant** 选项卡。

**AI Assistant** 聊天打开时，已指向所选日志条目所属的工作流和步骤，因此无需告诉它是哪个步骤失败。可以并排在**日志消息**下阅读原始错误，并在 **AI Assistant** 下与助手聊天。

对于大多数错误，它会立即开始诊断。对于少数常见错误（例如表达式中引用了不存在的列），第一条回复则是 PlaidCloud 针对此类错误已有的简短说明：通常的成因、应关注错误信息中的哪些词，以及如何修复。该说明不会查看您的步骤。请回复，例如*“请检查此步骤并修复”*，助手就会接手处理。请参阅[常见错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/#常见错误)。

## 步骤 3：让它诊断并提出修复方案

助手按固定顺序工作，在您同意之前不会保存任何内容：

1. **诊断**：读取失败步骤的配置及其涉及的表和列，用您的数据核对自己的判断，而不是仅凭错误文本猜测。
2. **提出方案**：如果发现确实存在配置错误，它会显示修正后的步骤配置，并明确说明改了什么以及原因。此时不会写入任何内容。
3. **您批准**：它会等待您明确的许可，含糊的回复不会被视为批准。
4. **应用**：您批准后，它通过步骤编辑器使用的同一路径，将修正后的配置写入步骤。
5. **提议重新运行**：它会询问是否立即重新运行该步骤。回答“是”，它就会运行该步骤并告诉您修复是否生效。

批准前请先阅读提出的更改。助手修复的是错误所在那一个步骤的配置，例如拼错的列名或函数名、无效的表达式、错误的数据类型或转换、格式错误的 SQL，并且只做能解决错误的最小改动。

> **对于无法修复的情况，它会如实说明。** 它唯一能动的只有那一个步骤的配置。它不会创建、删除或重新排列步骤，不会编辑其他步骤，也不会更改您的数据。许多失败根本不是配置问题：源数据缺失或格式错误、上游步骤先失败、瞬时或基础设施错误、权限问题，或转换或 UDF 内部的逻辑错误。对于这些情况，它会说明发现了什么，并指出真正的修复位置，而不是把某个修改硬凑成解决方案。

## 步骤 4：批准并重新运行

1. 当建议的配置看起来正确时，明确确认该更改。助手会将其应用到步骤。
2. 当助手询问是否重新运行步骤时，回答“是”。它会运行该步骤，并告诉您是成功还是再次失败。您也可以自己重新运行步骤或工作流。

如果助手告诉您原因在步骤配置之外，例如数据有问题、上游失败或权限问题，那就是答案。请在问题真正所在之处修复，不要再要求助手去编辑该步骤。

> **警告通常无害。** 如果日志条目是警告而不是严重失败，助手往往会告诉您无需更改，而不会凭空编造修改。这是有效的结果，并非死胡同。

## 步骤 5：用 AI 生成提取 SQL 步骤

现在用同一个助手来添加新工作，而不仅仅是修复。**提取 SQL** 步骤运行只读的 `SELECT`，并将结果写入新表，步骤编辑器可以为您编写这个查询。

1. 在工作流的**步骤**视图中，点击**创建步骤**，选择 **表 → 提取 SQL** 或 **AI → SQL Extract (AI Assisted)**。两者打开的是同一个编辑器，其中 **SQL 提取参数**页面顶部带有 **Generate SQL with AI** 面板。
2. **（可选）选择源表。** 在**源表**列表中，选择查询应读取的一个或多个表。留空则让助手检查项目并自行选择相关的表。
3. **描述您的需求。** 在**描述**框中，用自然语言写出期望的结果，例如*“根据科目编号范围，将每个总账科目归入一个作业池”*。
4. **点击 Generate SQL。** 助手会编写一条只读的 `SELECT`，通过运行来验证它，并填充 **SQL 选择查询**编辑器，以及带有检测到的列的**表数据选择**映射页面。如果源列表留空，它所选的表会在列表中被重新选中，方便您了解它用了哪些表。

> **无需任何设置。** 这里使用的是 AI 助手所用的同一个内置模型，无需为此配置工作区级的 AI 代理或 LLM 连接。

## 步骤 6：检查并保存步骤

生成的 SQL 只是起点，而不是黑箱。

1. **随意编辑。** SQL 编辑器完全可编辑：保存前可以优化查询、添加联接或更改列列表。
2. **选择目标表。** 选择或命名步骤写入结果的**目标表**。
3. **保存步骤。** 它会作为普通的提取 SQL 步骤保存，并像其他步骤一样作为工作流的一部分运行。

助手只会编写只读的 `SELECT` 语句，绝不会写 `INSERT`、`UPDATE`、`DELETE` 或其他更改数据的 SQL。生成仅起草和预览；步骤在您保存时创建，在工作流运行时执行。如果生成的查询无法运行，编辑器会连同错误一起显示该 SQL，供您更正，也可以调整描述后重新生成。详细内容请参阅[使用 AI 生成提取 SQL 步骤](/zh-cn/guides/ai-assistant/generate-sql-extract/)。

**这就是 AI 辅助。** 您对照实时数据诊断了失败的步骤，批准并应用了 AI 的修复，通过重新运行确认了结果，并根据一句自然语言生成了可用的提取 SQL 步骤：同一个助手既修复出错之处，又构建新的内容。
