## 新增

- **新工作区的引导式首次运行**。空白屏幕现在会说明其用途，并提供合适的下一步操作。您可以从多个引导式示例项目中选择，包括零售销售分析、营销活动绩效、供应链库存状况以及财务预算与实际对比报表，并一步完成加载和运行，实时查看数据导入、清理和汇总的进度。运行结束后，PlaidCloud 会自动将结果发布到报表，并据此构建仪表板，其中包含 KPI 摘要、随时间变化的趋势、类别明细，以及（零售和库存示例）按美国州划分的明细，因此您看到的是一个完整的仪表板，而不只是一张表。屏幕会事先说明预期：首次运行需要预热仓库，大约需要一分钟，之后的运行几乎是即时的。遇到困难时，随时可以点击**需要帮助？** 链接，不再需要引导时可以将其关闭，之后还可以从用户菜单重新启动。请参阅[从示例项目开始](/zh-cn/get-started/quickstart/#从示例项目开始)。

- **一键设置密码，账户邮件更简洁**。新成员的欢迎邮件现在包含一个**Set your password** 链接，无需先申请一次性验证码。该链接安全、仅可使用一次，并在 24 小时后过期。欢迎邮件的送达也更可靠：未送达的邮件会自动重试，因此新成员不会因无法登录而被卡住。账户和通知邮件还去掉了营销退订页脚，与其事务性用途保持一致。请参阅[新成员欢迎邮件](/zh-cn/administration/access/member-management/#新成员欢迎电子邮件)。

- **邀请团队成员成为免费且不限数量的查看者**。添加成员现在是发出邀请：选择角色（查看者或构建者），并输入一个或多个电子邮件地址即可一次邀请所有人。在所有套餐中，查看者均可享受免费、不限数量的只读访问，因此完全可以让整个团队都来看看；构建者可以创建和编辑内容，并计入套餐的构建席位上限。切换角色时，席位使用提示会随之更新，让您随时了解一次邀请的成本。请参阅[邀请新成员](/zh-cn/administration/access/member-management/#邀请新成员)。

- **适用于 Snowflake 和 Databricks 的外部数据湖仓**。项目现在可以将您的 Snowflake 或 Databricks 数据湖仓用作数据后端，数据保留在您自己的治理和计费之下，而由 PlaidCloud 运行工作流和仪表板。文件导入使用各仓库原生的批量加载路径，仪表板支持这两种引擎。请参阅[使用外部数据湖仓](/zh-cn/guides/connections/external-lakehouse/)。

- **面向主流 ERP 的原生连接和步骤目录**。PlaidCloud 现在可原生连接 NetSuite、Acumatica、Business Central、Dynamics 365 Finance & Operations、Oracle Fusion、Workday Financials、Sage Intacct 和 SAP S/4HANA Cloud。现成的导入步骤可提取财务和运营数据，包括余额、总账明细、主数据和交易记录，无需编写 SuiteQL、OData 或自定义 REST 调用，并提供丰富的服务器端筛选（包括日期、科目和维度范围），因此无需下载全部数据即可限定提取范围。配套的过账步骤可将日记账分录、发票、账单和付款写回，并提供预览/验证模式，在任何内容过账之前检查每一份单据；还提供幂等写入路径，防止重试或重新运行的批次重复过账；对于更正，则采用过账冲销分录，而不是就地编辑或删除。在启用多账簿会计的 NetSuite 账户上，提取现在默认汇总主账簿，而不是悄悄地把所有账簿加在一起；按日期限定的大范围提取会自动分块，以保持在 NetSuite 单次查询的行数上限之内，如果无限定范围的提取会被截断，则会给出明确的错误并要求提供日期范围。Sage Intacct 导入可以包含统计科目，现已涵盖总账明细、余额、分录和维度主数据，并支持自动分页；其 Post Journal Entry 步骤支持预览并过账来自工作流表的日记账分录；配套步骤则可将表中的支持文档附加到 Intacct 记录上。SAP S/4HANA Cloud 公有云版通过 OAuth2 和 OData/SOAP 直接连接，无需 PlaidLink 代理，与现有的用于本地系统的基于代理的 SAP ECC / S/4HANA 连接器不同。ERP 过账历史提供了对所有这些 ERP 以及 SAP 的过账尝试及其当前状态的只读记录。请参阅[导入 NetSuite 财务数据](/zh-cn/guides/connections/import-netsuite-financials/)、[连接到 Acumatica](/zh-cn/guides/connections/acumatica/)、[连接到 Business Central](/zh-cn/guides/connections/business-central/)、[连接到 Dynamics 365 Finance & Operations](/zh-cn/guides/connections/dynamics-365-fo/)、[连接到 Oracle Fusion](/zh-cn/guides/connections/oracle-fusion/)、[连接到 Workday Financials](/zh-cn/guides/connections/workday-financials/)、[连接到 Sage Intacct](/zh-cn/guides/connections/sage-intacct/)、[连接到 SAP S/4HANA Cloud](/zh-cn/guides/connections/s4hana-cloud/) 和[查看 ERP 过账历史](/zh-cn/guides/connections/erp-post-history/)。

- **使用前先测试数据库连接**。数据库连接编辑器可以对照实时服务器检查连接设置并报告结果，因此错误的主机、端口或凭据会在编辑器中暴露，而不是在工作流运行到一半时才出现。请参阅[创建和管理连接](/zh-cn/guides/connections/create-connection/)。

- **托管 Plotly Dash 应用**。从 PlaidCloud Git 部署 Dash 应用，其构建、自动扩缩容、单点登录、按用户数据访问、日志和重新构建的工作流程均与服务器端 Panel 应用相同。请参阅[从 PlaidCloud Git 部署 Dash 应用](/zh-cn/guides/dash-apps/deploy-from-git/)。

- **高级工作流控制**。执行容器将一组相关步骤作为一个单元运行，并提供容器级条件、迭代、状态和有针对性的重新运行。画布现在可以显示并编辑条件步骤，支持复制和粘贴步骤（包括其连线和分组），还允许失败的工作流从出错的步骤继续运行，而无需重新运行已完成的工作。请参阅[执行容器](/zh-cn/guides/workflows/advanced-workflows/#执行容器)、[在可视化画布上查看条件](/zh-cn/guides/workflows/step-conditions/#在可视化画布上查看条件)、[复制和粘贴步骤](/zh-cn/guides/workflows/copy-paste-steps/)和[运行工作流](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)。

- **更灵活的项目、代理和访问控制**。将选定的项目内容复制到现有项目，并可在之后重新同步；将 PlaidLink 代理分配给环境，使项目环境选择匹配的代理；并将安全组行访问应用于仪表板。请参阅[复制项目](/zh-cn/guides/projects/managing-projects/#复制项目)、[代理环境](/zh-cn/reference/cli/plaidlink/agents/#代理环境)和[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。

- **已发布表性能建议**。表优化器现在可以针对已发布表的布局改进显示被动的、基于证据的建议。这是第一阶段，绝不会自动更改任何表，每一项更改都由您的团队掌控。请参阅[查看已发布表性能](/zh-cn/guides/data/publish/#查看已发布表的性能)。

- **更清晰的工作区预配**。工作区列表和详细信息现在会报告预配状态，并且仅在相应服务就绪时才显示服务链接。请参阅[预配状态](/zh-cn/administration/control-plane/workspace-configuration/#预配状态)。

- **地理空间服务和工作流工具**。使用 PlaidCloud 的地理编码 API 进行地址查询、反向地理编码、自动补全和地点查询；可选择使用行车时间路线规划；并可使用地理哈希或 Plus Code 丰富工作流结果。生成网格和 Poly-Split 现在有了设计器表单。请参阅[地理编码 API](/zh-cn/guides/data/geocoding-api/)、[行车时间路线规划 API](/zh-cn/guides/data/drive-time-routing-api/)和[地理空间分析](/zh-cn/guides/workflows/geospatial-analytics/)。

- **引导式分摊维度构建器**。在维度视图中创建基于规则的分摊维度，无需手动搭建底层层次结构。请参阅[创建分摊维度](/zh-cn/guides/dimensions/dimensions/#创建分配维度)。

- **时点主数据**。两个新的工作流步骤让您可以保留并使用主数据的历史，而不只是其当前状态。SCD-2 主数据构建器步骤将源表转换为历史表，记录每个键曾经持有的每个值，并标注其生效的日期范围；SCD-2 截至日期联接步骤随后为每一行事实数据附加在该行自身日期生效的版本，因此交易会归属于其发生时适用的区域、成本中心或价格，而不是当前生效的那一个。请参阅 [SCD-2 主数据构建器](/zh-cn/reference/workflow-steps/dimensions/scd2-master-builder/)和 [SCD-2 截至日期联接](/zh-cn/reference/workflow-steps/dimensions/scd2-asof-join/)。

- **对 Oracle Essbase 多维数据集的实时查询**。使用服务账户连接 Oracle Essbase 21c 或 Oracle Analytics Cloud，然后从工作流对多维数据集运行 MDX 查询，并将结果直接写入表中。这是真正的实时查询，每次运行都反映多维数据集的当前数字，无需等待提取作业。可以通过浏览多维数据集的维度并选择成员来构建查询，也可以直接编写 MDX，结果的列由返回的网格推导而来，因此无需预先声明。行访问与其他表一样适用于写入的表。请参阅 [Essbase 查询](/zh-cn/reference/workflow-steps/essbase/essbase-query/)和 [Oracle Essbase 连接器](/zh-cn/reference/connectors/erp/oracle-essbase/)。

- **丰富的 HTML 数据报表邮件**。Notify Via Email 步骤现在会基于模板，针对工作流中的一个或多个表，将邮件内容编排为丰富的 HTML 报表，包含标题、摘要和渲染后的表格。将每个表添加为一个命名框架（带有各自的列选择、筛选器和聚合），并在带有实时预览的单一模板编辑器中进行布局，编辑器还提供**向我发送测试**按钮、**美化**按钮，以及用于插入表格、工作区名称、循环、数字和日期格式的插入面板。无需再维护单独的纯文本正文，现有步骤会自动沿用，其旧正文也会为您转换。请参阅[发送模板化的 HTML 邮件通知](/zh-cn/guides/workflows/notify-email-templates/)。

## 变更

- **浅色、深色和自动外观**。顶部工具栏中账户菜单旁边的**外观**按钮，可在浅色和深色外观之间切换整个界面，包括启动器、每个应用，以及其中的每个窗口和对话框。默认的**自动（跟随系统）** 会跟随计算机的外观设置并实时切换，无需重新加载；**浅色**和**深色**则固定所选外观。界面还迁移到了 PlaidCloud 通用的 Fluent 设计，因此按钮、输入框、表格、选项卡、菜单和对话框采用统一的外观，并且深色模式在此前难以阅读之处也变得清晰可读：工作流检查器的步骤卡片和面板、可搜索网格的焦点行，以及您并非所有者的连接上的只读横幅。您的选择按浏览器而不是按账户记住，因此请在您使用的每个浏览器中各设置一次。请参阅[外观（浅色、深色、自动）](/zh-cn/guides/launcher/#外观浅色深色自动)。

- **更简洁的 REST 和工作区 API**。项目、代理和仓库列表中未使用的 `all workspaces` 选项已被移除。REST 调用方在更新期间可以继续发送该选项；JSON-RPC 调用方应将其移除。工作区数字 ID 请求现在返回工作区 ID，而不是调用者的用户 ID。

- **更快、更清晰的报表和导出**。PDF 项目报表渲染时布局开销更小，并发收集数据，且可能占用更少页面。Excel 导出以流式方式处理大文件，内存占用更低，保留日期格式，并在导出开始前指出 Excel 的大小限制。报表文本现在可以解析列引用，报表/表读取会显示其实际错误，而不是悄悄地生成空内容。请参阅[导出到 Excel](/zh-cn/reference/workflow-steps/export/export-to-excel/#大小限制)和[报表文本](/zh-cn/reference/workflow-steps/reports/report-text/#在文本中引用列)。

- **更好用的工作流设计器**。可视化工作流设计器新增了带文件夹且支持无障碍访问的步骤面板；可折叠、可调整大小的面板和检查器窗格；以及跟随应用程序主题的深色画布。只读用户现在看到的步骤是只读的，而不是在保存时才发现权限问题。请参阅[高级工作流](/zh-cn/guides/workflows/advanced-workflows/)和[步骤面板](/zh-cn/guides/workflows/advanced-workflows/#步骤面板)。

- **更新鲜、治理更完善的仪表板**。重新发布表会立即使其仪表板缓存失效，同时默认缓存有效期现为一小时。仪表板的可见性遵循仪表板服务中设置的限制，仪表板账户也能更可靠地跟随 PlaidCloud 成员变更。请参阅[仪表板缓存](/zh-cn/guides/dashboards/dashboard-caching/)和[您能看到哪些仪表板](/zh-cn/guides/dashboards/using-dashboards/#您能看到哪些仪表板)。

- **更高效的已连接 AI 代理**。MCP 结果现在支持更小的分页、选定字段、按列组织的结果、明确的截断标记、有上限的查询和批处理大小，以及更精简且已更正的工具目录。这些变化减少了代理的上下文占用，并避免单个请求独占共享容量。请参阅[保持结果精简](/zh-cn/integrations/ai-coding-agents/getting-started/#保持结果精简)和[批量请求](/zh-cn/integrations/ai-coding-agents/getting-started/#批量请求)。

- **更清晰的分摊和成本追溯解答**。分摊分析现在会说明其发现背后的金额、期间、范围和度量方式；区分完整结果与变动最大的项目；用通俗语言解释置信度和局限；排序保持稳定；并给出与其能够和不能确定的内容相符的后续建议。假设分析的解答也能更好地指出过时数据、舍入限制以及估算的范围。计算本身没有变化，变化的是解释更加透明、一致。请参阅[使用 AI 分析分摊](/zh-cn/guides/allocations/results/analyzing-allocations-with-ai/)、[诚实的解答](/zh-cn/integrations/ai-coding-agents/honest-answers/)和[追溯分摊](/zh-cn/integrations/ai-coding-agents/tracing-allocations/)。

- **负载下的性能更好**。工作流运行请求的重复信息更少，大型表和维度操作会分批解析依赖关系，闲置的 Lakehouse 仓库会随需求下调并在需求回升时恢复查询容量，长时间运行的外部身份验证或导入工作也不再无谓地占用共享容量。请参阅 [Lakehouse 管理](/zh-cn/reference/expressions/lakehouse-v2/lakehouse-management/#仓库)。

- **更精致的集成与组织**。Microsoft 365 Copilot 代理现在命名为 PlaidCloud，并在登录时使用 PlaidCloud 品牌。Sage Intacct 工作流步骤现归入外部系统。请参阅 [Microsoft 365 Copilot](/zh-cn/integrations/microsoft-365-copilot/)和 [Sage Intacct 步骤](/zh-cn/reference/workflow-steps/sage-intacct/)。

## 已修复

- **成员生命周期和工作区管理**。删除成员现在会将该成员（而不是管理员）从分发列表中移除，并撤销该成员的连接和文档账户访问权限。已禁用的成员可以重新启用，维度成员选择器也能可靠地打开，并将更改应用到预期的行。请检查在此版本之前已删除成员所涉及的分发列表、连接和文档账户。请参阅[成员管理](/zh-cn/administration/access/member-management/)和[维度类型属性与成员选择器](/zh-cn/guides/dimensions/dimensions/#维度类型属性和成员选取器)。

- **工作流、连接和项目的可靠性**。REST 请求以及 Slack 或 Teams 通知步骤又可以获取其连接凭据了。删除工作流时也会同时删除其计划事件；连接的使用位置包含 REST v2 步骤；Macro Concurrent 会检测已停止的子实例，而不是无限期等待；可以保存大型 ML 模型；步骤配置和中断状态的报告也更准确。如果分摊或基于规则的标记步骤的分配维度没有活动规则（例如，所有规则都被 include 属性关闭），现在会以明确的消息停止，并指向该分配维度，而不是因内部错误而失败。请参阅 [REST 请求](/zh-cn/reference/workflow-steps/general/rest-request/)、[Notify via Slack](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)和[子调用停止响应时](/zh-cn/reference/workflow-steps/workflow-control/macro-concurrent/#子调用停止响应时)。

- **Postman 请求步骤不再截断结果**。在分页响应中途失败的请求，现在会使目标表保持不变，而不是只加载了一部分；超大分页响应也会完整导入，而不是只导入最后一部分。这个旧版步骤已被 REST 请求步骤取代。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。

- **数据导入、导出和项目传输更可靠**。Excel 和 Lakehouse 时间戳导入会保留原值；当无法读取源表时，Access 导入会明确失败；表反联接会保留文本列；归档导入和导出会准确报告结果，保留可区分的重复副本，并保持界面响应。Alteryx 导入现在会在成功时关闭，并且普通注释不再显示警告样式。请参阅[导入 Access](/zh-cn/reference/workflow-steps/import/import-access/#文件无法读取时)和[导入工作流](/zh-cn/guides/workflows/migrate-alteryx-workflows/#导入工作流)。

- **已连接和内置的 AI 代理能完成更多预期工作**。代理可以创建有文档说明的文本、文档、空间和报表步骤；保存运行条件和相关的工作流设置；将所需的图表渲染为图像而不编造数值；发送电子邮件和短信；上传文档；并准确检测已更改的记录和仓库搜索结果。Text Sentiment 的句子级评分现已有文档说明。请参阅 [Weave AI 聊天](/zh-cn/guides/ai-assistant/weave-tab/#weave-ai-聊天)和 [Text Sentiment](/zh-cn/reference/workflow-steps/text-documents/nlp-sentiment/#句子级打分)。

- **一些虽小但重要的界面修正**。下载现在会指明失败原因，文档文件夹的启动器固定项在 S3 和 Wasabi 账户上可以正常工作，导入和导出表包对话框不再显示占位文本，停滞的请求正文也不再拖累工作区中的其他用户。

## 安全

- **安全组权限得到正确保留**。编辑安全组不再移除编辑者本身不具备的权限，非管理员仍然无法授予自己没有的权限。权限和成员变更现在会记录在安全日志中。请检查此版本之前由非管理员编辑过的安全组，以确认其权限集。请参阅[管理安全组和分配](/zh-cn/administration/access/managing-security-groups-and-assignments/)。

- **更严格的归档和项目访问检查**。将归档导入现有项目会保留该项目的访问限制，归档会对无权读取的用户排除表数据，项目内容、项目锁定和工作流步骤复制请求现在会验证对所指定源项目的访问权限。请检查在此版本之前接收过归档的受限项目。

- **更强的查询、助手和自动化凭据边界**。提交的查询组件不能携带任意 SQL；助手对工作流的编辑会拒绝格式错误的已保存结构；项目的自动化凭据被限制在该项目内，不能再管理工作区级别的文件夹或项目。现有的从工作流管理项目的自动化可能需要联系支持团队以重新启用该行为。
