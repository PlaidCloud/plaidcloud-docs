## 新增

- **PlaidXL 可在 Excel 中生成、下钻、解释和规划。** **PlaidCloud** 功能区选项卡分为 **连接**、**插入**、**刷新**、**Drill**、**写入** 和 **共享**，常用命令也出现在 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡中，主要命令都有可以更改的键盘快捷键，在字段中输入时不会触发。命令失败时会说明是哪个命令以及原因。登录之前运行的命令会打开登录界面，并在您登录后运行一次；一次登录对应一个工作区，因此切换工作区时会要求您登录新的工作区（切换回来则无需再次登录）；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次单击即可生成报表。** **报表** 选项卡会根据表生成实时报表，一个维度向下钻取到行，另一个维度横跨列，每个交叉点都有一个 `CELL` 值。**Build my first report** 会用您自己的数据生成示例。在下钻时，报表会插入和删除整行整列，您输入的值、备注和格式会随所在行一起保留。请参阅[生成报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格下钻。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 可将节点转换为实时的 `DRILL` 公式并为您编辑，适用于节点、维度标题或报表值。**Custom drill** 会在插入之前预览行，成员选择器可以插入成员，或向单元格添加某个节点的子节点下拉列表。`DRILL` 可接受要排除或展开的节点，也可以横跨一行运行。请参阅[下钻、选择成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释一个数字。** **Explain this number** 会显示某个值的计算方式、它现在是否与 PlaidCloud 一致，以及它所来自的表和工作流步骤。**Show detail rows** 会将某个值背后的行放到单独的工作表上，并检查它们加总是否一致。
  - **Excel 中的受治理指标。** `PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 会按仪表板中的显示方式返回业务指标；没有可聚合内容的 `CELL` 或 `CELLS`，求和时显示 `0`，其他情况显示 `#VALUE!` 并附带原因（在 `CELLS` 溢出区域中为空白）；**Metric...** 会列出项目的指标及其当前值。一个指标可以基于多个备用层次结构进行筛选，并可将备用层次结构的成员与其他维度的成员混合使用。请参阅[指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中直接输入即可规划。** 在 `CELL` 值上输入数字，它就会写入 PlaidCloud：可按比例分摊、均分，或按另一个成员的形态分摊，也可按金额或百分比调整，已锁定的单元格保持不变。平均值、中位数、最小值、最大值、标准差和方差单元格同样可以输入值；插入或删除行列时，输入的值会跟随其单元格（被删除单元格中的值会被报告）。**Undo last write** 会按从新到旧的顺序撤消输入的值和保存，只有执行写入的人员和工作区才能撤消该写入。撤消求和，或撤消在空单元格中输入的平均值，会保留此后写入同一批单元格的内容；在完成之前被中断的写入无法撤消。请参阅[向 PlaidCloud 输入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新需要的内容。** 可刷新一个工作表、一个选区或所有表，每个表的进度和 **取消** 都显示在任务窗格中，也可以只重新计算 PlaidXL 公式。检索到的表会以 Excel 表的形式到达，并按数据类型设置格式，刷新时保留您自己的列和数字格式，且在原位置刷新。检索或刷新绝不会覆盖其他单元格，也不会与其他 Excel 表重叠；超出 Excel 范围的整数 ID 和 1900 年之前的日期会以文本形式到达。再次检索同一个表不会将其重复加入刷新列表，**Stop refreshing** 可将某个表从中移除，维度会随您的表一起刷新。请参阅[刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#refresh-all-tables)。
  - **保存立即写入，并且可以撤消。** **Save to PlaidCloud** 无需确认即可写入，会说明所做的操作，并提供 **撤消**，对于 Lakehouse 表，在每次保存后的 7 天内都可撤消。带有筛选器检索的工作表、明细行工作表，或访问权限只涵盖部分行的人员所保存的内容，只会替换对应的行，因此其他人的行会保留。自检索以来成员已发生变化的下钻工作表不会被保存；保存失败时会指出还原点的名称，以便将表恢复原状。请参阅[将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在 **Weave** 选项卡上，可用日常语言询问要生成的报表、公式、下钻或表，也可以选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只会更改工作簿，替换您已输入的内容前会先询问，绝不会写入引用工作簿之外内容的公式，并且每项更改在您重新加载窗格之前都可以还原。请参阅[在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享整个工作簿或某个工作表的纯值副本。** **Convert to values** 可转换整个工作簿、单个工作表，或转换为无法恢复的值（会先询问），只更改 PlaidXL 公式及其溢出区域，仍在计算的公式会留待再次尝试，并且在您重命名工作表后，**Restore PlaidXL formulas** 仍然有效。
- **过账登记簿会打开到需要您处理的内容。** 有内容需要查看时打开到 **异常**，有请求在等待您处理时打开到 **审批**，否则打开到 **所有过账**。导航栏将其屏幕分为 **需要我处理**、**登记簿**、**洞察** 和 **设置**，在 **异常** 和 **审批** 上带有计数，每个屏幕共用同一个页眉和范围栏：选择期间（**本月**、**上个月**、**最近 7 天**、**最近 30 天** 或 **自定义**）、连接、项目、环境或实体，以及 **实时**、**模拟** 或 **全部**，然后 **重置**，或保留一个 **Saved scope**。系统会记住您上次的范围。
  - **异常会整理出需要查看的内容。** **需要查看**、**未确认**、**待处理**、**失败** 和 **待冲销** 等筛选标签会显示其计数，连接健康状况一行显示“All N connections posting normally”，每笔过账都有一个通俗易懂的状态，并附带关于下一步该做什么的提示。没有未处理项时会显示 **All clear**。将总账 ID 粘贴到 **Find a posting by ledger id** 或命令面板中，即可直接打开该过账。
  - **审批、委托和关注是收件箱式的屏幕。** 可在 **Waiting on me** 和 **Submitted by me** 之间切换，**批准** 或 **拒绝** 时需填写原因，可一次批准多项，并可从提示消息中 **撤消** 批准。**Delegate approvals** 是一个简短的对话框，**我的关注** 列出您所关注的内容。**冲销过账** 以及批量重试和清除对话框使用同一布局。
  - **过账的抽屉会说明发生了什么。** 它显示状态及其含义、按名称列出的关键信息，以及 **明细行**、**历史记录** 和 **签核** 选项卡，并提供 **标记为已审核**、**重试**、**冲销…**、**关注连接**、**关注运行** 和 **复制链接**，其中 **复制链接** 会直接打开该过账。
  - **辅助、导出和保留采用相同的设计。** **辅助** 有一个提问框和洞察卡片、标有 **Draft — nothing applied** 的建议，以及 **所有过账** 上的异常卡片（带 **显示这些**）。**导出和警报** 有 **New schedule**，**保留** 是一张卡片。
  - **登记簿保持最新。** 导航栏徽章会随着过账变化而更新，打开的列表会在过账发生变化时提供 **刷新**，打开的抽屉会原地更新。**主页** 在 **需要关注** 下显示一张 **过账登记簿** 卡片。请参阅[查看过账登记簿](/zh-cn/guides/connections/posting-register/)。
- **步骤表单上的预览。** 导入：SQL、执行：SQL、提取：SQL、导出：SQL 和 Salesforce：查询对象 无需运行步骤即可显示最多 100 行，Anaplan 视图和列表的读取会显示其将生成的列和类型。请单击 **源** 选项卡上的 **预览**。变量会按运行时的方式填入，但不支持 `{x:>9}` 这样的变量格式。预览只运行标准 SQL 函数；否则它会提示您运行该步骤。在已锁定的项目中，或对于基于代理的“执行 SQL”步骤，预览不可用。请参阅[导入 SQL 步骤](/zh-cn/reference/workflow-steps/import/import-sql/)和[提取 SQL 步骤](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告会显示变化、可缩小到某个分组，并可接入工作流。** **概览** 新增了与上一期间对比的趋势箭头，以及一个 **Highlights** 列表，指出不活跃的成员，以及无人打开的仪表板和应用。已停用的成员不会被计入，也不会被列为不活跃。**分组** 会将 **概览**、**内容** 和不活跃列表限制为某个安全组的成员，日期范围新增了 **上月** 和 **本月**，由每个选项卡共用，并随您的账户记住。现在每个数字都有说明，表格使用 **成员** 和 **区域** 等通俗名称，按 Enter 键即可打开行，加载和错误提示更清晰，**漏斗** 的最后一步会显示有多少成员完成了它。新的 **Get Workspace Usage** 步骤会按计划将每日或每月的使用情况合计写入表中，不含成员姓名，并且每次运行都与 **Get Workspace Members** 一样记录在 **安全日志** 中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage 步骤](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表，并设置项目的默认仪表板受众。** `publish_manage` 会取消发布表及其已发布的视图和任何没有图表使用的仪表板数据集；仍有图表使用的数据集会保留，当报表视图构建在已发布的视图之上时，该视图和数据集也会保留，但表仍会被取消发布。`project_upsert` 会设置 `dashboard_default_audience`，即项目中新仪表板所共享给的分组，`[]` 表示清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Git 应用会列出您的存储库，并告诉您可以做什么。** 应用列表中的 **Git** 会显示您的角色（**管理员**、**贡献者** 或 **查看者**）以及工作区的存储库，每个存储库都带有说明、最近更新日期、带复制按钮的克隆地址和 **打开**。**Set up Git on your computer** 卡片会引导您完成安装 Git、创建令牌和克隆，**How to clone** 会重新打开它。**View all in Git** 会打开完整的 Git 界面，**Manage who can push** 会打开分组管理。访问权限分为 **查看者**、**贡献者**（将应用代码推送到 `apps`）或 **管理员**（可推送到所有位置，包括 `udfs`），查看者最多可看到三位工作区管理员以便向其申请。新的 **Git Contributors** 组授予贡献者权限，并且可以设为默认组，使新成员自动获得；**Git Administration** 授予管理员权限。成员的 **Git** 选项卡会显示其 Git 用户名、级别和授予该级别的组。成员的 Git 账户跟随其成员身份：停用或移除成员会在大约一小时内封锁其 Git 账户（包括令牌和 SSH 密钥），重新激活则会解除封锁，其存储库和历史记录会保留。使用单点登录登录 Git 时会打开该成员自己的账户。贡献者不能直接在工作区的 Git 组织中创建存储库；存储库通过 PlaidCloud 创建。应用窗口会显示 **存储库** 部分，UDF 带有 **打开**，Git 中有指向您工作区的 **← Back to** 链接。平台创建的每个存储库（包括应用存储库以及内置的 `apps` 和 `udfs` 存储库）都可供工作区中每个已登录的成员读取，因此成员无需逐个存储库设置即可打开并重新发布应用。Git 管理员仍然可以将存储库设为私有，这会将其从存储库选择器中隐藏，并阻止成员从中发布，或运行存储在其中的基于 Git 的 UDF 代码。请参阅 [PlaidCloud Git](/zh-cn/guides/git/#打开-git) 和[谁可以看到存储库](/zh-cn/guides/connections/plaidcloud-git/#谁可以查看存储库)。
- **Cost to Serve 和 Operational Transfer Pricing 模板基于 Common Finance Model 构建。** 从 **Cost to Serve** 启动项目，可按您为每个部门设置的作业和动因，将运营费用分摊到客户，并查看每位客户在扣除服务成本后的利润，且与总账相互核对。从 **Operational Transfer Pricing** 启动，可根据您的政策区间，测试每个实体的利润水平（销售回报率、净成本加成或转售价格减除），并提供将超出区间的实体拉回目标的补足调整。销售回报率为 EBIT 除以受测方销售额。请参阅 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/) 和 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)。
- **OneStream 和 Anaplan 为 Data Foundation 提供数据，OneStream 还有读取步骤。** Data Foundation 通过由您的 OneStream 管理员构建的数据适配器读取 OneStream 合并结果，并通过导出操作读取 Anaplan 计划，然后将集团损益表与它们进行核对。新的 **OneStream: Read Adapter** 步骤会读取适配器（每个合并成员调用一次），并将其写入任意工作流中的表。请参阅 [OneStream 用于 Data Foundation](/zh-cn/guides/connections/onestream-for-data-foundation/)、[Anaplan 作为 Data Foundation 数据源](/zh-cn/guides/connections/anaplan/#将-anaplan-作为-data-foundation-源)和 [OneStream: Read Adapter 步骤](/zh-cn/reference/workflow-steps/onestream/onestream-read-adapter/)。
- **自行选择 Data Foundation 如何分摊共享成本。** **操作 > Allocations...** 会引导您逐步确定要分摊哪些成本、按什么分摊、分摊到哪里，以及对负的动因如何处理，适用于将间接费用分摊到部门，以及将部门成本分摊到产品和客户，并提供一个月的预览，显示汇集、已分摊和未分摊的内容。您手动编辑的规则会保留。请参阅[分摊规则](/zh-cn/guides/projects/data-foundation/#分摊规则)。
- **在 Data Foundation 中解释数字，并用您自己的方式命名。** **Explain this number** 会在您自己的行访问权限下，将损益表数字拆分为总账所持有的金额、分摊转入和转出的金额以及在集团中被抵销的金额，并列出最大的源文档。**Business names** 为类别、损益表行项目、指标和列提供您的业务所使用的名称，并应用于报表、指标和助手。请参阅[解释数字](/zh-cn/guides/projects/data-foundation/#解释数字)和[业务名称](/zh-cn/guides/projects/data-foundation/#业务名称)。
- **Data Foundation 在每次加载时生成董事会材料包，并让您可以回退。** 每次 **加载** 都会将损益表仪表板的 Excel 工作簿和 PDF 写入文档账户的某个文件夹；关闭报表时材料包只有工作簿，对话框会说明这一点。每次加载开始时，以及每次更改映射或数据源之前，都会创建一个还原点，**操作 > Restore...** 会显示每个还原点将还原多少个表，并将项目（包括维度）恢复原状。**基础数据** 选项卡会更清楚地说明正在发生什么：它会显示仍在运行或中途停止的更新，说明为什么一个表文件夹不是数据源，在有内容核对一致之前让 **检查合计是否一致** 保持待处理，并在状态读取失败时自行恢复。应用更新时会保留您对生成步骤和备注的自行编辑，并注明任何冲突。请参阅[董事会材料包](/zh-cn/guides/projects/data-foundation/#董事会资料包)和[还原点](/zh-cn/guides/projects/data-foundation/#还原点)。
- **克隆 Data Foundation 项目，或将其另存为模板。** **操作 > Clone...** 会复制项目，包括您对模型的编辑、指标和分析路径。**Save as my template...** 会将设置保存到文档账户，**From a template file...** 会据此启动一个新的私有项目，其数据源等待连接。请参阅[克隆项目](/zh-cn/guides/projects/data-foundation/#克隆项目)和[另存为我的模板](/zh-cn/guides/projects/data-foundation/#另存为我的模板)。
- **Data Foundation 的设置清单一直延伸到交接，助手可以解决遗留问题。** 清单新增了夜间刷新、证据包以及将项目移交给其所有者，并说明是谁设置了项目。可以让助手为没有类型的科目、多个数据源使用的代码以及未匹配到任何内容的文件列提出答案；它不会写入任何内容，由您来应用这些答案。请参阅 [Data Foundation 入门](/zh-cn/guides/projects/data-foundation-getting-started/)和[使用 Ask 解决未决问题](/zh-cn/guides/projects/data-foundation/#用-ask-解决未决问题)。

- **移动端的 Weave 语音只需轻点一下。** 轻点麦克风，说出您的问题，停止说话后 Weave 会将其发送一次。再次轻点麦克风可提前停止，如果没有听到任何声音，它会自动关闭。如果您在说话中途离开 **Weave** 选项卡或将应用切到后台，您说的话会留在问题框中而不发送，以便您查看。运行、暂停、停止和恢复会忽略对其确认的意外双击。需要应用版本 1.3.0 或更高版本。请参阅[使用语音](/zh-cn/guides/mobile-app/weave-on-mobile/#使用语音)。

## 变更

- **PlaidCloud 的 Web 应用和 Python 客户端库使用 REST API，JSON-RPC 已弃用。** Web 应用将其请求发送到 REST API。使用 `plaidcloud-rpc` 1.25.0 或更高版本时，`SimpleRPC` 调用会转到 REST API，您的代码无需更改；REST API 尚未涵盖的调用，或仍在旧版本上的工作区，会照旧使用 JSON-RPC。JSON-RPC 将在后续版本中移除，因此请将脚本和笔记本升级到 `plaidcloud-rpc` 1.25.0 或更高版本，并针对 REST API 编写新的集成。请参阅[命令行](/zh-cn/reference/cli/jupyter/command-line/)。
- **步骤表单遵循统一的布局。** 选项卡具有标准名称和标准顺序：常规、设置、源、列、筛选器、输出和高级，ERP 过账表单上还有表头列和行列。必填字段用 * 标记，表单只会因步骤所需的内容而阻止保存。
- **复制项目时可分别选择表数据和维度成员，复制数据更快，并保留私有副本的 ERP 写入授权。** 在 **要复制的数据** 下，选择 **表数据**（**无表数据**（默认）、**完整** 或 **样本**），并单独选择 **复制维度成员**（默认开启），因此不含表行的副本仍会带有已填充的维度，且创建很快。**完整** 和 **样本** 副本会同时复制多个表，因此包含许多表的项目完成得更快。**复制结果** 会将每个维度的结果与表一起列出，**重试失败项** 会同时重试失败的表和维度。带数据创建的新副本仅您自己可见，并保留源项目中您自己可以授予的 ERP 写入授权；如果源项目以 **实时** 过账，副本会以 **模拟** 到达，因此在您将其切换为 **实时** 之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **表的详细信息面板会更快地显示使用它的步骤。** 选择另一个表时，会立即清除上一个表的步骤，并且共享本项目数据的其他项目中的步骤会在其余内容之后片刻再添加，而不是拖慢整个面板。请参阅[查看表的使用位置](/zh-cn/guides/projects/managing-tables-and-views/#查看表的使用位置)。
- **行操作在每个列表中的工作方式都相同。** 可以通过行开头的 **⋯** 按钮、右键单击该行，或工具栏的 **操作** 菜单打开行的菜单。它始终先列出 **打开**、**详细信息** 和 **编辑**，然后是该列表自身的操作，最后是 **删除** 或 **移除**，不适用于某行的操作会在原位置显示为灰色。**Enter** 和 **Del** 显示在其所执行的菜单项上。如果列表中的行只有一个操作，则显示该操作的图标而不是 **⋯**，并且 **我的仪表板**、**我的 Panel 应用** 和 JupyterLite 再次显示 **打开** 图标。请参阅[行操作菜单](/zh-cn/guides/dashboards/using-dashboards/#行操作菜单)。
- **应用选项卡图标统一为一套**，浅色和深色模式下均如此。
- **没有验证设置的已保存 ERP 写入步骤以仅验证方式打开。** 涵盖 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post，以及 Xero 导出。明确设置为实时运行的步骤仍保持实时。
- **长时间运行的作业在各处以相同方式显示进度。**
- **工作流如实停止、失败和报告。** 停止工作流会停止其启动的所有内容，无法完成的运行或步骤会带着原因失败而不是挂起，运行状态与实际运行的内容一致。
  - **停止工作流会停止其启动的所有内容，无法完成的运行或步骤会失败而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中后续的导入和维度加载可以正常启动，它还会停止该工作流中排队或正在运行的连接器（Singer）同步。如果步骤的作业无法启动，该步骤会带着原因失败，而不是无限等待：约 40 分钟内没有工作进程启动它、工作进程启动后消失、其 pod 卡在 Pending 状态约 20 分钟、其映像约 5 分钟内无法拉取，或约 20 分钟内没有创建 pod。约 30 分钟内没有运行器接手的连接器同步会失败，并显示指明该同步的消息。当步骤在等待工作进程时，其状态消息会显示“Waiting for a worker…”及已等待的分钟数，工作开始后即清除。停止宏会停止它的每个正在运行的副本，而停止某一个副本，或 **Macro Concurrent** 步骤放弃一个已停止响应的副本，不会影响调用它的工作流继续运行。仅在其他工作流内部运行的宏会在工作流列表中显示为 **正在运行**，其 **停止** 可用，并显示每个步骤来自其最近一次运行的状态、开始和结束时间。服务器丢失的运行会以失败结束，仍运行超过 12 小时的运行会失败，并显示“Run failed: still running at the 12-hour limit. Re-run the workflow.”。请参阅[从未启动的步骤](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
  - **恢复、运行历史和运行状态与实际运行的内容一致。** 恢复父工作流会运行子工作流剩下的所有内容，即使您之前单独重新运行了子工作流的某个步骤；同一次运行中对子工作流的每次调用都有自己的运行历史条目。因服务器停止而重新启动的步骤会在其日志中说明，并且 `workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续的步骤，而不是将该次运行报告为正常。请参阅[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)和[出错时继续](/zh-cn/guides/workflows/continue-on-error/)。
  - **步骤错误显示其自身的消息。** PlaidCloud 未预料到的错误会显示为“The step stopped on an unexpected error (*type*): *message*”。启动台上的 **需要关注** 卡片会用一行显示错误，并省略已被删除的工作流的运行。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。
  - **未完成的 ERP 提取会使其步骤失败，恢复会继续它。** 当 **SAP：临时提取** 在其行数或时间限制处暂停或其代理未及时回复，或者 Salesforce、Oracle Fusion 批量或 HFM/FCCS 导出作业在步骤停止等待时仍在运行时，该步骤会失败，使其后的步骤不会在不完整的表上运行。恢复工作流或重新运行该步骤，提取会在同一作业上从停止处继续。请参阅[运行限制](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制)和 [Salesforce：查询对象 步骤](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
  - **取消导出会在数据仓库中停止其查询。** 当导出或下载被取消（包括因停止其工作流而取消）时，在 Lakehouse v2、Snowflake、Databricks、PostgreSQL 和 Greenplum 上，读取其数据的查询也会停止，导出到远程数据库时也会停止读取其源，而不是一直运行到结束。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求 步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **会话过期后打开的仪表板链接，会在您登录后带您到该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝它们无法识别的字段**，并在错误中指明该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为它的另一个名称。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据会使用该账户自己的凭据直接写入账户的存储桶，而不是先让每一行都经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式与之前相同。请参阅 [Export to Parquet 步骤](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息为何未发送。** 步骤的错误会指明它尝试连接的服务器，对于 Slack 和 Teams 还会指明连接，并说明出了什么问题：例如 Slack 不再识别该 webhook、无法向该频道发布、找不到服务器或服务器在 60 秒内没有应答，或者连接已被删除。Slack 或 Teams 的 webhook URL 绝不会显示，因为任何持有它的人都可以冒充您的集成发布消息。请参阅 [Notify via Slack 步骤](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。
- **项目服务账户的访问令牌至少有效 24 小时。** 以项目身份运行的工作流作业（例如 UDF 步骤）会获得有效期为 24 小时的令牌。工作区升级时，较短的有效期会被提高到该值，您设置的更长有效期则会保留。
- **工作区的组织、所有者、发行版和版本由 PlaidCloud 设置，您可以选择其数据中心。** 在控制平面中，您创建的工作区归您所有，并被放置在 PlaidCloud 设置的发行渠道上，您可以从注册时提供的区域中选择其 **Data Center**。编辑工作区时，组织、所有者、发行版和版本为只读。请使用 **Set Version** 更改版本，并联系 PlaidCloud 支持团队来迁移工作区、更改其所有者或渠道，或将其固定。请参阅[工作区配置](/zh-cn/administration/control-plane/workspace-configuration/#主要设置)。

## 已修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的标识、无效的存储类型或过账模式，现在会返回指明问题的消息，而不是通用的服务器错误。通过 REST API 时返回 400 而不是 500，通过 AI 助手或 MCP 时为无效参数错误。
- **REST API 的维度值请求已可正常工作。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 曾被当作网格请求应答并被拒绝为无效。它现在会为 `value_columns` 中的每一列返回一个聚合值，而网格（每对行筛选器和列筛选器对应一个值）有自己的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再拖延其他请求。** 从数据仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，每一项都可能使同一服务器正在处理的所有其他请求暂停，直到其完成。现在它们与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口还高，因此 **创建** 和 **更新** 按钮可能够不到。现在表单可滚动，按钮保持在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 过去对这种大小的文件，这些操作都会失败，移动或重命名包含此类文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚写入的内容。** 写入表的步骤或导入可能记录的是写入之前的行数，因此刚加载的表显示为 0 行，导入可能报告导入了 0 行。现在会在新行在各处都可见之后再读取行数，因此其后的步骤也能读取到它们。将表切换到另一个分支，或将分支合并到表中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的内容进行比较。** 步骤的空值经常是在步骤清空其表以重新填充之后才被统计，因此其之前的运行看起来没有空值，而一个始终有部分空值的列会被报告为刚刚变成这样。现在每次运行都按步骤留在其表中的状态统计。之前记录的计数无法与正确的计数区分，因此不会使用它们：每个步骤的空值检查会重新开始其历史，并在统计满五次运行之前报告为未检查。行数和值分布检查也不再把另一个步骤在其完成两秒之后对同一个表所做的写入记在该步骤名下。请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **Data Foundation 保留反转汇率和小数阈值的精度。** PlaidCloud 反转的汇率（因为您的汇率是以报告货币兑换另一种货币的方式报价）可能被舍入到六位小数，导致币值较小的货币（例如印度尼西亚盾）的金额偏差约 1%。现在反转后的汇率保留 12 位小数。带小数的 `group_amber` 或 `group_red` 阈值（例如 `0.5`）曾被舍入为整数。您的下一次 **加载** 将使用精确的值。请参阅[汇率](/zh-cn/guides/projects/data-foundation/#汇率)。
- **已停用成员的警报和摘要会停止。** 其所有者已被停用的 Panel 应用警报或摘要仍会继续检查和发送。现在它会在其所有者被停用期间暂停，并在重新激活后恢复。请参阅[警报和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
- **向 REST API 请求已删除的连接会返回 404。** 请求已被删除的连接或不存在的 ID，过去会应答通用的服务器错误 (500)。现在返回 404，并附带指明连接 ID 的消息。

## 安全

- **密码登录需要验证器应用，并且密码更强。** 使用 PlaidCloud 密码登录的成员，在下次登录时会被要求设置验证器应用，此后每次都要输入其验证码。单点登录、Google、Microsoft 和 GitHub 登录、API 令牌和服务账户保持不变。新密码至少需要 12 个字符，不能是您的用户名或您最近六个密码之一，多次登录失败后账户会被短暂锁定。您的工作区已有的更严格规则会保留。请参阅[成员身份验证](/zh-cn/administration/access/member-authentication/)。
- **连接可指向公共和专用网络地址。** 连接不能指向环回地址、链路本地地址或云元数据地址，错误会指明主机及其解析到的地址。您专用网络上的地址不受影响。请参阅[连接无法到达的地址](/zh-cn/guides/connections/create-connection/#连接无法访问的地址)。
- **已保存的连接凭据只向可编辑连接或工作流的成员显示。** 通过 REST API 和 MCP，已保存连接的密码、令牌和密钥对其他成员会被遮蔽，他们仍可打开并浏览该连接。请参阅[谁可以看到连接的凭据](/zh-cn/guides/connections/create-connection/#谁能看到连接的凭据)。
- **应用构建在运行时无法访问您工作区的 Git 凭据。**
- **代理的私钥只向可编辑代理的成员显示。** 通过 REST API 和 MCP，该密钥不再出现在代理列表或详细信息中，代理表单也只向可编辑代理的成员显示 **私钥** 和 **查看 RPC 配置**。服务账户、项目和代理令牌以及 AI 委托的令牌无法检索该密钥或 RPC 配置。运行中的代理不受影响，公钥仍会显示。请参阅[获取代理凭据](/zh-cn/reference/cli/plaidlink/agents/#获取代理凭据)。
- **代理下载链接的有效期为一小时。** 开启 **Use PlaidCloud Proxy Download** 后，链接过期时请重新打开下载以获取新链接。请参阅[服务](/zh-cn/administration/control-plane/workspace-configuration/#服务)。
- **将人员添加到安全组遵循您所持有的权限。** 当您持有安全组所授予的全部权限时，才可以将成员添加到该安全组、选择成员所属的分组或邀请架构师。工作区管理员不受限制。请参阅[管理安全组](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理安全组)。
- **连接的所有者或工作区管理员可以更改其设置并将其启用或停用。** 通过 REST API、JSON-RPC 以及 AI 助手或 MCP 更改连接的设置，需要其所有者之一，或者对于没有所有者的连接，需要工作区管理员。启用、停用、锁定和解锁连接需要所有者或工作区管理员，并且指明多个连接的请求只有在您能更改所有这些连接时才会应用。只有工作区管理员可以选择工作区的默认 AI 连接，并且只有在没有任何由管理员拥有或没有所有者的连接可作为默认连接时，成员所拥有的连接才会成为默认连接。请参阅[编辑连接](/zh-cn/guides/connections/create-connection/#编辑连接)和[LLM 提供商](/zh-cn/integrations/ai-architecture/llm-providers/#连接包含的内容)。
- **行访问适用于成员对受限表所做的一切操作。** 成员在仪表板中、在自己的 SQL 中以及在加载中，只能看到和更改其授权所允许的行。
  - **项目架构师在仪表板中可以看到行受限表的所有行**，与他们在 Analyze 中看到的一致。取消架构师访问权限会立即在仪表板中生效，无论是更改某人的角色、将他们或其分组从项目中移除、更改项目的访问类型、还原项目的早期版本，还是删除安全组。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
  - **受行访问限制的成员可以运行自己的 SQL 查询并导出结果。** 在设有行访问的项目中，非架构师成员通过查询屏幕上自己的查询，恰好得到其授权所允许的行，并且可以将其导出为 CSV、Excel 或 JSON，并显示 **行数受您的访问权限限制** 提示；此前这些操作会被拒绝。包含百分号 (`%`) 的授权值现在可在查询屏幕上返回其行，并且将此类查询下载为 CSV 也可正常工作。他们在 Snowflake 或 Databricks 上自己的自由格式 SQL、从 Postgres 系列数据仓库导出其自己的 SQL，以及按快照时间读取受治理的表，仍会被拒绝，并且视图必须以原始名称保留受治理的列才能被筛选。请参阅[行访问与您自己编写的查询](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问与您自己编写的查询)。
  - **保存行访问时会保留其来源中不存在的已授权值。** 当表中没有包含该值的行、维度中没有该成员，或列表中没有该值时，安全组被授予的值会保留在网格中并带有标记。**保存** 会询问是保留还是移除每个这样的值。请参阅[行访问网格](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
  - **向行受限表写入 DataFrame、保存记录和清除，只会更改您能看到的行。** 当行访问限制您的行时，使用 Python 客户端将 DataFrame 写入受限表或清除它，或通过 REST API 向其保存记录或清除，只会更改您自己的行，并且携带超出您访问范围的行的加载会在任何更改之前被拒绝，并指明所发现的值。项目架构师、能看到所有行的成员以及工作流运行会写入整个表。任何人对任何表所做的此类写入，都会记录在 **安全日志** 中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
  - **对行受限表进行导入、复制、还原和删除，需要您能看到每一行。** 当行访问限制您的行时，将文件导入受限表、从另一个项目将表复制到其中、切换或合并其分支、还原它、删除它、在其被删除后将其恢复，或任何其他替换整个表的操作，只有在您能看到表的每一行时才会运行；否则会被拒绝，且不会有任何更改。通过 REST API 保存表的行只会更改您自己的行，与其他加载相同。项目架构师、能看到所有行的成员以及工作流运行不受影响，这些操作同样会记录在 **安全日志** 中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
- **只有账户的所有者才能还原其早期版本。** 将文档账户还原到早期版本、保留或释放某个版本以及执行备份，都需要账户的所有者之一，并且这些操作在系统管理的账户上都不可用。查看账户的版本历史需要有该账户的访问权限。
- **`query_run` 运行只读语句。** AI 助手和 MCP 客户端使用的 `query_run` 工具接受一条 SELECT 或 WITH 语句、对其的 EXPLAIN，或一条 SHOW；任何其他语句都不会运行。要更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 遵循同样的规则。通过 REST 和 JSON-RPC API，对于无法更改项目数据的成员，该规则也适用于运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库，以及使用自己的查询导出表数据；被拒绝的查询返回 403。Explain Analyze 会运行查询以测量它，因此在查询日志和 Lakehouse 中它只接受读取数据的查询，并且在设有行访问的项目中，只有项目架构师才能从查询日志运行它。
