## 新增

- **PlaidXL 可在 Excel 中构建、钻取、解释和规划。** **PlaidCloud** 功能区选项卡分为 **Connect**、**Insert**、**Refresh**、**Drill**、**Write** 和 **Share** 几组，常用命令也出现在 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡中，主要命令都有可更改的键盘快捷键，在字段中输入时不会触发。命令失败时会说明是哪条命令以及原因。登录前运行的命令会先打开登录，登录后自动运行一次；一次登录只对一个工作区有效，因此切换工作区时会要求登录新工作区（切换回来则不需要）；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次点击即可构建报表。** **Report** 选项卡可根据一张表生成实时报表，一个维度逐级钻取在行上，另一个维度横跨各列，每个交叉点都有一个 `CELL` 值。**Build my first report** 会用您自己的数据生成示例。钻取时，报表会插入和删除整行整列，您输入的值、备注和格式会跟随所在的行。请参阅[构建报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 可将节点转为实时的 `DRILL` 公式并为您编辑，适用于节点、维度标题或报表值。**Custom drill** 会在插入前预览行，成员选择器可插入成员，或为单元格添加某个节点的子节点下拉列表。`DRILL` 可指定要排除或展开的节点，也可横跨一行运行。请参阅[钻取、选择成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释一个数字。** **Explain this number** 会显示某个值的计算方式、它现在是否与 PlaidCloud 一致，以及它来自哪张表和哪个工作流步骤。**Show detail rows** 会将某个值背后的行放到单独的工作表中，并检查这些行是否加总一致。
  - **Excel 中的受治理指标。** `PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 按仪表板的显示方式返回业务指标；没有可聚合内容的 `CELL` 或 `CELLS`，求和时显示 `0`，其他情况显示 `#VALUE!` 并附原因（在 `CELLS` 溢出区域中则为空白）；**Metric...** 会列出项目的指标及其当前值。请参阅[指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中直接输入即可规划。** 在 `CELL` 值上输入数字，即可写入 PlaidCloud：可按比例分摊、平均分摊或按另一个成员的形态分摊，也可按金额或百分比调整，已锁定的单元格不受影响。平均值、中位数、最小值、最大值、标准差和方差单元格同样接受输入值，插入或删除行列时，输入的值会跟随其单元格（已删除单元格中的值会被报告）。**Undo last write** 会按从新到旧的顺序撤消输入的值和保存，且只有执行写入的人和工作区才能撤消该写入。请参阅[向 PlaidCloud 输入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新您需要的部分。** 可刷新一张工作表、一个选区或所有表，任务窗格会显示每张表的进度和**取消**，也可以只重新计算 PlaidXL 公式。检索到的表以按数据类型设置格式的 Excel 表形式到达，刷新时保留您自己的列和数字格式，并在原位置刷新。检索或刷新绝不会覆盖其他单元格，也不会与另一个 Excel 表重叠；超出 Excel 范围的整数 ID 和 1900 年以前的日期会以文本形式到达。重复检索同一张表不会将其两次加入刷新列表，**Stop refreshing** 可将其移除，维度会随您的表一起刷新。请参阅[刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#refresh-all-tables)。
  - **保存立即写入，并且可以撤消。** **Save to PlaidCloud** 无需确认即可写入，会说明所做的操作，并提供**撤消**。带筛选器检索的工作表、明细行工作表，或访问范围仅覆盖部分行的用户，只会替换相应的行，因此其他人的行会保留。成员自检索后发生变化的钻透工作表不会被保存；保存失败时会指出还原点的名称，以便将表恢复原状。请参阅[将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在 **Weave** 选项卡上，可用日常语言要求生成报表、公式、钻取或表，也可选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只更改工作簿，替换您已输入的内容前会先询问，绝不会写入指向工作簿之外的公式，每项更改在您重新加载窗格之前都可以还原。请参阅[在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享一张工作表或整个工作簿的纯值副本。** **Convert to values** 可转换整个工作簿、一张工作表，或转换为无法恢复的纯值（会先询问），只更改 PlaidXL 公式及其溢出区域，仍在计算的公式会留待再次尝试，**Restore PlaidXL formulas** 在您重命名工作表后依然可用。
- **步骤表单上的预览。** 导入：SQL、Execute: SQL、提取 SQL、导出：SQL 和 Salesforce：查询对象 这几个步骤无需运行步骤即可显示最多 100 行，Anaplan 视图和列表读取会显示它们将生成的列和类型。点击**源**选项卡上的**预览**。变量会按运行时的方式填充，但不支持 `{x:>9}` 这类变量格式。预览只运行标准 SQL 函数，否则会提示您运行步骤。已锁定的项目以及基于代理的 Execute SQL 步骤不可用。请参阅[导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/)和[提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告会显示变化、可缩小到某个分组，并可接入工作流。** **概览**新增与上一期间相比的趋势箭头，以及一个**亮点**列表（**Highlights**），指出不活跃的成员以及无人打开的仪表板和应用。**分组**可将**概览**、**内容**和不活跃列表限定为某个安全组的成员，日期范围新增 **Previous month** 和 **This month**，由所有选项卡共用，并随您的账户记住。现在每个数字都有说明，表使用**成员**和 **Area** 等通俗名称，按 Enter 键可打开行，加载和错误提示更清晰，最后一个**漏斗**步骤会显示有多少成员完成了它。新的 Get Workspace Usage 步骤会按计划将每日或每月使用总量写入一张表，不含成员姓名，其每次运行与 Get Workspace Members 步骤一样，都会记录在**安全日志**中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表，并设置项目的默认仪表板受众。** `publish_manage` 会取消发布一张表，同时取消其已发布的视图以及没有图表使用的仪表板数据集；仍有图表使用的数据集会保留，当报表视图建立在已发布视图之上时，该视图和数据集也会保留，但这张表仍会被取消发布。`project_upsert` 可设置 `dashboard_default_audience`，即项目中新仪表板的共享分组，设为 `[]` 则清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Git 应用会列出您的存储库，并告诉您可以执行哪些操作。**应用列表中的 **Git** 会显示您的角色（**Administrator**、**Contributor** 或 **Viewer**）以及工作区的存储库，每个存储库都有说明、最后更新日期、带复制按钮的克隆地址和**打开**。**Set up Git on your computer** 卡片会指导您安装 Git、创建令牌并克隆，**How to clone** 可重新打开该卡片。**View all in Git** 会打开完整的 Git 界面，**Manage who can push** 会打开分组管理。访问级别为 **Viewer**、**Contributor**（将应用代码推送到 `apps`）或 **Administrator**（可推送到所有位置，包括 `udfs`），Viewer 最多会看到三位可联系的工作区管理员。新的 **Git Contributors** 分组授予 Contributor 级别，可设为默认分组，使新成员自动获得；**Git Administration** 授予 Admin 级别。成员的 **Git** 选项卡会显示其 Git 用户名、级别以及授予该级别的分组。应用窗口会显示**存储库**部分，UDF 提供**打开**，Git 中有返回工作区的 **← Back to** 链接。平台创建的每个存储库（包括应用存储库以及内置的 `apps` 和 `udfs` 存储库）都可由工作区中每位已登录的成员读取，未登录的人员则无法读取，因此成员无需逐个存储库设置即可打开并重新发布应用。Git 管理员仍可将存储库设为私有，这会使其从存储库选择器中隐藏，并使成员无法从中发布，也无法运行其中存储的基于 Git 的 UDF 代码。请参阅 [PlaidCloud Git](/zh-cn/guides/git/#打开-git) 和[谁可以查看存储库](/zh-cn/guides/connections/plaidcloud-git/#谁可以查看存储库)。
- **移动端 Weave 的语音输入只需轻点一下。** 点击麦克风，说出您的问题，停止说话后 Weave 会发送一次。再次点击麦克风可提前停止；如果一直没有听到声音，它会自动关闭。如果您在说话中途离开 **Weave** 选项卡或将应用切到后台，您的话会保留在问题框中而不会发送，以便您检查。运行、暂停、停止和继续会忽略对其确认框的误触双击。需要应用版本 1.3.0 或更高版本。请参阅[使用语音](/zh-cn/guides/mobile-app/weave-on-mobile/#使用语音)。

## 变更

- **步骤表单采用统一布局。** 选项卡有标准名称和标准顺序：常规、设置、源、列、筛选器、输出和高级，ERP 过账表单另有表头列和行列。必填字段标有 *，表单只会因步骤所需的内容而阻止保存。
- **复制项目可分别选择表数据和维度成员，复制数据更快，并保留私有副本的 ERP 写入授权。** 在 **Data to copy** 下，可选择**表数据**——**No table data**（默认）、**完整**或**样本**——并另行选择 **Copy dimension members**（默认开启），因此不含表行的副本仍会带有已填充的维度，创建速度也很快。**完整**和**样本**复制会同时复制多张表，因此表较多的项目完成得更快。**复制结果**会在表旁边列出每个维度的结果，**Retry failed items** 会将失败的表和维度一起重试。带数据的新副本仅您自己可见，并保留源项目中您自己有权授予的 ERP 写入授权；如果源项目以 Live 方式过账，副本会以 Simulate 方式创建，因此在您将其切换为 Live 之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **表的详细信息面板更快显示使用它的步骤。** 选择另一张表时，会立即清除上一张表的步骤，与本项目共享数据的其他项目中的步骤会稍后补充，而不再拖慢整个面板。请参阅[查看表的使用位置](/zh-cn/guides/projects/managing-tables-and-views/#查看表的使用位置)。
- **行操作菜单（⋯）位于每个网格行的最左侧。**
- **应用选项卡图标统一为一套**，浅色和深色模式均适用。
- **没有验证设置的已保存 ERP 写入步骤以仅验证方式打开。** 涵盖 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post 以及 Xero 导出。明确设为实际运行的步骤仍保持实际运行。
- **长时间运行的作业在各处以相同方式显示进度。**
- **停止工作流会停止它启动的一切内容，无法完成的运行或步骤会失败，而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中后续的导入和维度加载可正常开始，同时也会停止该工作流排队或正在运行的连接器（Singer）同步。如果步骤的作业无法启动，该步骤会连同原因一起失败，而不是无限等待：约 40 分钟内没有工作进程启动它、工作进程启动后消失、其 pod 卡在 Pending 状态约 20 分钟、镜像约 5 分钟内无法拉取，或约 20 分钟内没有创建 pod。约 30 分钟内没有运行器接手的连接器同步会失败，并给出指明该同步的消息。步骤等待工作进程期间，其状态消息显示“Waiting for a worker…”及已等待的分钟数，工作开始后即清除。停止宏会停止它的每个运行副本，仅在其他工作流内部运行的宏会在工作流列表中显示为**正在运行**，可使用**停止**，并显示每个步骤最近一次运行的状态、开始时间和结束时间。服务器丢失的运行会以失败结束，运行超过 12 小时仍未结束的会失败，并提示“Run failed: still running at the 12-hour limit. Re-run the workflow.”。请参阅[无法启动的步骤](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
- **继续、运行历史和运行状态与实际运行的内容一致。** 继续父工作流时，会运行子工作流剩余的全部内容，即使您已单独重新运行过子工作流的某个步骤也是如此；同一次运行中对子工作流的每次调用都有各自的运行历史条目。因服务器停止而重启的步骤会在日志中说明，`workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续运行的步骤，而不是将该运行报告为正常。请参阅[暂停、停止和继续](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)和[出错后继续](/zh-cn/guides/workflows/continue-on-error/)。
- **步骤错误显示其自身的消息。** PlaidCloud 未预料到的错误会显示为“The step stopped on an unexpected error (*type*): *message*”。启动台上的**需要关注**卡片以一行显示错误，并省略已被删除的工作流的运行。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。
- **未完成的 ERP 提取会使其步骤失败，继续则会接着提取。** 当**SAP：临时提取**在行数或时间限制处暂停、其代理未及时回复，或 Salesforce、Oracle Fusion 批量或 HFM/FCCS 导出作业在步骤停止等待时仍在运行，该步骤会失败，这样其后的步骤就不会基于不完整的表运行。继续工作流或重新运行该步骤，提取会在同一作业上从停止的位置继续。请参阅[运行限制](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制)和 [Salesforce：查询对象](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **项目架构师可在仪表板中看到受行限制的表的所有行**，与他们在 Analyze 中看到的一致。撤销架构师访问权限会立即在仪表板中生效，无论是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、还原项目的早期版本，还是删除安全组。前任架构师不再能看到受行限制数据的每一行。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
- **会话过期后打开的仪表板链接，会在您登录后直接带您进入该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝它们不识别的字段**，并在错误中指明该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为它的另一个名称。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据会使用该账户自己的凭据直接写入账户的存储桶，而不再让每一行都先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式不变。请参阅 [Export to Parquet 步骤](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会指明它尝试连接的服务器，对于 Slack 和 Teams 还会指明连接，并说明出了什么问题：例如 Slack 不再识别该 webhook、无法向该频道发帖、找不到服务器或服务器在 60 秒内没有响应，或者连接已被删除。Slack 或 Teams 的 webhook URL 绝不会显示，因为任何拥有它的人都可以冒充您的集成发帖。请参阅 [Notify via Slack 步骤](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。

## 修复

- **无效的项目设置会给出清晰的消息。** 未知的环境或文档账户、已被占用或保留的 slug，或无效的存储类型或过账模式，现在会返回指明问题的消息，而不是笼统的服务器错误。通过 REST API 时返回 400 而非 500，通过 AI 助手或 MCP 时则是无效参数错误。
- **REST API 的维度值请求现在可用。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 过去被当作网格请求处理并被拒绝为无效。现在它为 `value_columns` 中的每一列返回一个聚合值，而网格（每对行筛选器和列筛选器返回一个值）有了专属的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再拖慢其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，以前都可能让同一服务器正在处理的所有其他请求暂停，直到它完成。现在它们与这些请求并行运行。
- **项目变量和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口还高，因此**创建**和**更新**按钮可能够不到。现在表单可以滚动，按钮固定在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 这些操作以前对这种大小的文件都会失败，移动或重命名包含这类文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚写入的内容。** 写入表的步骤或导入可能记录写入之前的行数，因此刚加载的表显示 0 行，导入也可能报告导入了 0 行。现在行数会在新行在各处都可见之后再读取，因此其后的步骤也能读到它们。将表切换到另一个分支，或将分支合并到表中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的内容进行比较。** 步骤的空值数量常常是在步骤清空其表以重新填充之后才统计的，因此它之前的运行看起来没有空值，而一个一直有部分空值的列会被报告成刚刚变成这样。现在每次运行都按步骤留下表的状态来统计。此前记录的计数无法与正确的计数区分，因此不予使用：每个步骤的空值检查都会重新开始记录历史，并在统计满五次运行之前报告为未检查。行数和值分布检查也不再把另一个步骤在本步骤完成两秒以上之后对同一张表的写入算作本步骤的写入。请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **向 REST API 请求已删除的连接会返回 404。** 请求已被删除的连接或不存在的 ID，以前会返回笼统的服务器错误（500）。现在返回 404，并附带指明该连接 ID 的消息。

## 安全

- **保存行访问时，会保留其来源中已不存在的已授予值。** 一个安全组被授予的值，过去在表中不再有包含它的行、维度已失去该成员或列表不再包含它时，会在下次保存时从授权中消失。这样，没有任何勾选项的分组会回退为 **Everyone else**，这可能意味着所有行。现在该值会保留在网格中并带有标记，**保存**时会询问是保留还是移除。请参阅[行访问网格](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
- **只有账户的所有者才能还原其早期版本。** 将文档账户还原到早期版本、保留或释放某个版本以及进行备份，现在都要求您是该账户的所有者之一，且这些操作在系统管理的账户上均不可用。查看账户的版本历史需要有该账户的访问权限。
- **只应读取数据的查询不能再更改数据。** AI 助手和 MCP 客户端使用的 `query_run` 工具只运行读取数据的语句——一条 SELECT 或 WITH 语句、对其的 EXPLAIN，或 SHOW——并拒绝其他任何语句而不运行。要更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 遵循同样的规则。对于不能更改项目数据的成员，通过 REST 和 JSON-RPC API 运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库以及用自己的查询导出表数据时，也适用该规则；被拒绝的查询返回 403。Explain Analyze 会运行查询以进行测量，因此在查询日志和 Lakehouse 中，它现在只接受读取数据的查询，并且在设有行访问的项目中，只有项目架构师才能从查询日志中运行它。
- **向受行限制的表写入 DataFrame、保存记录和清除，只会更改您能看到的行。** 当行访问限制了您的行时，使用 Python 客户端将 DataFrame 写入受限表或清除该表，或通过 REST API 向其保存记录或清除它，只会更改您自己的行；包含超出您访问范围的行的加载会在任何更改发生前被拒绝，并指出发现的值。项目架构师、能看到所有行的成员和工作流运行仍像以前一样写入整张表。个人对任何表进行的每一次此类写入，现在都会记录在**安全日志**中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
- **导入、复制、还原和删除不再替换您看不到的行。** 当行访问限制了您的行时，只要表中有您看不到的行，向受限表导入文件、从另一个项目将表复制到其中、切换或合并其分支、还原它、删除它，或任何其他会替换整张表的操作都会被拒绝，且不会有任何更改。通过 REST API 保存表的行现在也只会更改您自己的行，与其他加载方式一致。项目架构师、能看到所有行的成员和工作流运行不受影响，这些操作同样会记录在**安全日志**中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
