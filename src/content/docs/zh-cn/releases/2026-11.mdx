## 新增

- **PlaidXL 可在 Excel 中构建、钻取、解释和计划。** **PlaidCloud** 功能区选项卡分为**连接**、**插入**、**刷新**、**钻取**、**写入**和**共享**几组，常用命令也位于 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡上，主要命令都有可更改的键盘快捷键，在字段中输入时这些快捷键不会触发。命令失败时会说明是哪个命令以及失败原因。在登录之前运行的命令会打开登录界面，并在您登录后运行；一次登录仅对一个工作区有效，因此切换工作区时会要求您登录新工作区（切换回来时则不需要）；如果在 Office 中使用 Microsoft Entra 工作账户，PlaidXL 会自动为您找到工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **只需几次点击即可构建报表。** **报表**选项卡基于表布局一份实时报表，一个维度沿行向下钻取，另一个维度沿列展开，每个交叉点都有一个 `CELL` 值。**Build my first report** 会根据您自己的数据生成一个示例。钻取时，报表会插入和删除整行和整列，您输入的值、备注和格式会跟随其所在的行。请参阅[构建报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 可从节点、维度标题或报表值出发，将节点转换为实时 `DRILL` 公式并自动为您编辑。**Custom drill** 会在插入之前预览行，成员选择器可以插入成员，或者向单元格添加包含节点子项的下拉列表。`DRILL` 接受要排除或展开的节点，并且可以跨行运行。请参阅[钻取、选取成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释数字。** **Explain this number** 显示一个值的计算方式、它当前是否与 PlaidCloud 一致，以及它来自哪个表和工作流步骤。**Show detail rows** 会将某个值背后的行放到单独的工作表中，并检查它们的合计是否一致。
  - **在 Excel 中使用受管控的指标。**`PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 按照仪表板中的显示方式返回业务指标；没有可聚合内容的 `CELL` 或 `CELLS` 在求和时显示 `0`，否则显示 `#VALUE!` 及原因（在 `CELLS` 溢出区域中为空白）；**Metric...** 会列出项目的指标及其当前值。指标可以按多个备用层次结构筛选，并将备用层次结构的成员与其他维度的成员组合使用。请参阅[指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中直接输入进行计划。** 在 `CELL` 值上输入一个数字，它就会被写入 PlaidCloud：按比例、平均或按另一个成员的分布形态进行分配，按金额或百分比进行调整，锁定的单元格保持不变。平均值、中位数、最小值、最大值、标准差和方差单元格也接受输入的值；插入或删除行或列时，输入的值会跟随其单元格（被删除单元格中的值会被报告）。**Undo last write** 会从最新的开始撤消输入的值和保存，并且只有执行写入的人员和工作区才能撤消。撤消求和或在空单元格中输入的平均值时，会保留此后写入相同单元格的内容；在完成之前被中断的写入无法撤消。请参阅[向 PlaidCloud 输入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新所需内容。** 可以刷新一个工作表、一个选择区域或所有表，任务窗格中会显示每个表的进度和**取消**；也可以只重新计算 PlaidXL 公式。检索到的表以按数据类型设置格式的 Excel 表形式提供，刷新时会保留您自己的列和数字格式，并在原位置刷新。检索或刷新绝不会覆盖其他单元格或与其他 Excel 表重叠，对于 Excel 而言过大的整数 ID 以及 1900 年之前的日期会以文本形式提供。再次检索同一个表不会将其重复添加到刷新列表中，**Stop refreshing** 可将其移出列表，维度会与您的表一起刷新。请参阅[刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#refresh-all-tables)。
  - **保存会立即写入并且可以撤消。** **Save to PlaidCloud** 无需确认即可写入，会说明执行了什么操作，并提供**撤消**，对 Lakehouse 表而言，每次保存后的 7 天内都可以撤消。使用筛选器检索的工作表、明细行工作表，或者访问权限仅涵盖部分行的用户，只会替换这些行，因此其他人的行会被保留。自检索以来成员发生变化的钻取工作表不会被保存；保存失败时会注明还原点，以便将表恢复原状。请参阅[将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在 **Weave** 选项卡上，用通俗语言请求报表、公式、钻取或表，或者选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，并且只更改工作簿；在替换您输入的任何内容之前会先询问，绝不会编写引用工作簿之外内容的公式，并且在您重新加载窗格之前，每项更改都可以还原。请参阅[在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享单个工作表或整个工作簿的仅值副本。** **Convert to values** 可以转换整个工作簿、单个工作表，或者转换为无法恢复的值（会先询问），只更改 PlaidXL 公式及其溢出区域，仍在计算的公式会留待再次尝试；重命名工作表后，**Restore PlaidXL formulas** 仍然有效。
- **过账登记簿打开时首先显示需要您处理的内容。** 当有内容需要查看时打开**异常**，当有请求等待您处理时打开**审批**，否则打开**所有过账**。导航栏将屏幕分为**需要我处理**、**登记簿**、**洞察**和**设置**几组，**异常**和**审批**上显示计数，每个屏幕共享同一个标题区和范围栏：选择期间（**本月**、**上个月**、**最近 7 天**、**最近 30 天**或**自定义**）、连接、项目、环境或实体，以及**实时**、**模拟**或**全部**，然后选择**重置**或保留一个 **Saved scope**。系统会记住您上次使用的范围。
  - **异常屏幕整理出需要查看的内容。** **需要查看**、**未确认**、**待处理**、**失败**和**冲销未完成**标签显示各自的计数，连接健康状况行显示“All N connections posting normally”，每笔过账都有一个以通俗语言表示的状态，并带有说明下一步操作的工具提示。没有未结项时显示 **All clear**。将分类账 ID 粘贴到 **Find a posting by ledger id** 或命令面板中，即可直接打开该过账。
  - **审批、委派和关注都是收件箱式屏幕。** 可在 **Waiting on me** 和 **Submitted by me** 之间切换，填写原因后选择**批准**或**拒绝**，一次批准多项，并可从提示消息中**撤消**批准。**Delegate approvals** 是一个简短的对话框，**我的关注**列出您关注的内容。**冲销过账**以及批量重试和清除对话框使用相同的布局。
  - **过账的抽屉会说明发生了什么。** 它显示状态及其含义、按名称列出的关键信息，以及**行**、**历史记录**和**签核**选项卡，并提供**标记为已审核**、**重试**、**冲销…**、**关注连接**、**关注运行**和 **Copy link**，后者可直接打开该过账。
  - **辅助、导出和保留采用相同的设计。** **辅助**包含提问框和洞察卡片、标记为 **Draft — nothing applied** 的建议，以及**所有过账**上带有**显示这些**的异常情况卡片。**导出和警报**包含 **New schedule**，**保留**则是一张卡片。
  - **登记簿保持最新。** 导航栏徽章随过账的变化而更新，过账发生变化时已打开的列表会提供**刷新**，已打开的抽屉会原位更新。**主页**会在**需要关注**下显示一张**过账登记簿**卡片。请参阅[查看过账登记簿](/zh-cn/guides/connections/posting-register/)。
- **步骤表单中的预览。** 导入：SQL、Execute: SQL、提取：SQL、导出：SQL 和 Salesforce Query 无需运行步骤即可显示最多 100 行，Anaplan 视图和列表读取会显示它们将生成的列和类型。在**源**选项卡上单击**预览**。变量会按照运行时的方式填充，但不支持 `{x:>9}` 之类的变量格式。预览仅运行标准 SQL 函数；否则会提示您运行该步骤。锁定的项目不提供预览，基于代理的 Execute SQL 步骤也不提供预览。请参阅[导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/) 和[提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告可显示变化、缩小到某个分组，并可流入工作流。** **概览**新增与上一期间相比的趋势箭头，以及一个 **Highlights** 列表，指出不活跃的成员以及无人打开的仪表板和应用。已停用的成员不会被计为不活跃，也不会列为不活跃。**分组**可将**概览**、**内容**和不活跃列表限定为某个安全组的成员；日期范围新增**上一个月**和**本月**，并由所有选项卡共享，与您的账户一起保存。现在每个数字都有说明，表格使用**成员**和**区域**等通俗名称，按 Enter 即可打开行，加载和错误信息更加清晰，**漏斗**的最后一步会显示有多少成员完成了该步。新的 **Get Workspace Usage** 步骤会按计划将每日或每月的使用情况总计写入表中，不含成员姓名；与 **Get Workspace Members** 一样，每次运行都会记录在安全日志中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表并设置项目的默认仪表板受众。**`publish_manage` 会取消发布表，同时取消发布其已发布视图以及任何未被图表使用的仪表板数据集；仍被图表使用的数据集会保留，如果有报表视图基于已发布视图构建，该视图和数据集也会保留，而表仍会被取消发布。`project_upsert` 用于设置 `dashboard_default_audience`，即项目中新仪表板共享给的分组，`[]` 则将其清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Git 应用会列出您的存储库，并告诉您可以执行哪些操作。** 应用列表中的 **Git** 会显示您的角色（**管理员**、**贡献者**或**查看者**）以及工作区的存储库，每个存储库都带有说明、上次更新日期、带有复制按钮的克隆地址以及**打开**。**Set up Git on your computer** 卡片会逐步引导您安装 Git、创建令牌和克隆，**How to clone** 可重新打开该卡片。**View all in Git** 会打开完整的 Git 界面，**Manage who can push** 会打开分组管理。访问级别分为**查看者**、**贡献者**（将应用代码推送到 `apps`）或**管理员**（可推送到任何位置，包括 `udfs`），查看者最多可以看到三位可联系的工作区管理员。新的 **Git Contributors** 分组授予贡献者权限，并且可以设为默认分组，以便新成员自动获得该权限；**Git Administration** 授予管理员权限。成员的 **Git** 选项卡会显示其 Git 用户名、级别以及授予该级别的分组。成员的 Git 账户与其成员身份保持一致：停用或移除成员后，大约一小时内会封锁其 Git 账户（包括令牌和 SSH 密钥），重新激活后会解除封锁，其存储库和历史记录均会保留。使用单点登录登录 Git 会打开成员本人的账户。贡献者不会直接在工作区的 Git 组织中创建存储库；存储库通过 PlaidCloud 创建。应用窗口会显示**存储库**部分，UDF 提供**打开**，Git 中有一个返回工作区的 **← Back to** 链接。平台创建的每个存储库（包括应用存储库以及内置的 `apps` 和 `udfs` 存储库）都可供工作区中每个已登录成员读取，因此成员无需针对每个存储库进行设置即可打开和重新发布应用。Git 管理员仍可将存储库设为私有，这样会在存储库选择器中隐藏该存储库，并阻止成员从中发布或运行其中存储的基于 Git 的 UDF 代码。请参阅 [PlaidCloud Git](/zh-cn/guides/git/#打开-git) 和[谁可以看到存储库](/zh-cn/guides/connections/plaidcloud-git/#谁可以查看存储库)。
- **Cost to Serve 和 Operational Transfer Pricing 模板基于 Common Finance Model 构建。** 从 **Cost to Serve** 启动项目，可按照您为每个部门设置的作业和动因将运营费用分摊到客户，并查看扣除服务成本后每个客户的利润率，且与总账相勾稽。从 **Operational Transfer Pricing** 启动项目，可根据您的政策区间测试每个实体的利润水平（销售回报率、净成本加成或转售减价），并通过调整使超出区间的实体回到目标水平。销售回报率等于息税前利润除以受测方销售额。请参阅 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/) 和 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)。
- **OneStream 和 Anaplan 为 Data Foundation 提供数据，并且 OneStream 有了读取步骤。** Data Foundation 通过由 OneStream 管理员构建的数据适配器读取 OneStream 合并结果，通过导出操作读取 Anaplan 计划，并将集团损益表与它们进行核对。新的 **OneStream: Read Adapter** 步骤会读取适配器（每个合并成员调用一次），并在任何工作流中将其写入表。请参阅[用于 Data Foundation 的 OneStream](/zh-cn/guides/connections/onestream-for-data-foundation/)、[作为 Data Foundation 源的 Anaplan](/zh-cn/guides/connections/anaplan/#将-anaplan-作为-data-foundation-源) 和 [OneStream: Read Adapter](/zh-cn/reference/workflow-steps/onestream/onestream-read-adapter/)。
- **选择 Data Foundation 分摊共享成本的方式。** **操作 > Allocations...** 会逐步引导您确定要分摊哪些成本、按什么分摊、分摊到何处以及如何处理负数动因，适用于将间接费用分摊到部门，以及将部门费用分摊到产品和客户，并提供一个月的预览，显示哪些金额被归集、分摊以及未分摊。您手动编辑的规则会被保留。请参阅[分摊规则](/zh-cn/guides/projects/data-foundation/#分摊规则)。
- **在 Data Foundation 中解释数字并按您的方式命名。** **Explain this number** 会在您自己的行访问权限下，将损益表中的数字拆分为总账中的金额、分摊转入和转出的金额以及在集团中抵销的金额，并列出最大的源单据。**业务名称**让类别、损益表行、指标和列在报表、指标和助手中使用您企业的叫法。请参阅[解释数字](/zh-cn/guides/projects/data-foundation/#解释数字)和[业务名称](/zh-cn/guides/projects/data-foundation/#业务名称)。
- **Data Foundation 每次加载都会生成董事会报告包，并允许您回退。** 每次**加载**都会将一个 Excel 工作簿和损益表仪表板的 PDF 写入文档账户的某个文件夹；如果关闭了报告功能，报告包只包含工作簿，对话框会加以说明。每次加载开始时以及每次更改映射或源之前都会创建一个还原点，**操作 > Restore...** 会显示每个还原点会恢复多少个表，并将项目（包括维度）恢复原状。**基础数据**选项卡能够更清楚地显示正在发生的事情：它会显示仍在运行或中途停止的更新，说明某个表文件夹为何不是源，在有内容核对一致之前使**检查合计是否一致**保持待处理状态，并在状态读取失败时恢复。应用更新时会保留您对生成的步骤所做的编辑，并注明任何冲突。请参阅[董事会报告包](/zh-cn/guides/projects/data-foundation/#董事会资料包)和[还原点](/zh-cn/guides/projects/data-foundation/#还原点)。
- **克隆 Data Foundation 项目，或将其另存为模板。** **操作 > Clone...** 会复制一个项目，包括您的模型编辑、指标和分析路径。**Save as my template...** 会将设置保存到文档账户，**From a template file...** 则根据该模板启动一个新的私有项目，其源等待连接。请参阅[克隆项目](/zh-cn/guides/projects/data-foundation/#克隆项目)和[另存为我的模板](/zh-cn/guides/projects/data-foundation/#另存为我的模板)。
- **Data Foundation 的设置检查清单涵盖到交接为止的全过程，助手可以处理剩余问题。** 检查清单新增了每晚刷新、证据包以及将项目移交给其所有者，并说明项目由谁设置。可以请助手为没有类型的科目、多个源共用的代码以及没有匹配任何内容的文件列提出答案建议；助手不会写入任何内容，由您来应用这些答案。请参阅[Data Foundation 入门](/zh-cn/guides/projects/data-foundation-getting-started/)和[使用提问解决未决问题](/zh-cn/guides/projects/data-foundation/#用-ask-解决未决问题)。

- **在移动端的 Weave 中使用语音只需轻点一下。** 轻点麦克风，提出问题，停止说话后 Weave 就会发送。再次轻点麦克风可提前停止；如果没有听到任何声音，麦克风会自动关闭。如果在说话中途离开 **Weave** 选项卡或将应用切换到后台，您说的话会保留在问题框中且不会发送，以便您检查。运行、暂停、停止和恢复会忽略在其确认上的意外双击。需要应用版本 1.3.0 或更高版本。请参阅[使用语音](/zh-cn/guides/mobile-app/weave-on-mobile/#使用语音)。

## 变更

- **PlaidCloud 的 Web 应用和 Python 客户端库使用 REST API，JSON-RPC 已弃用。** Web 应用将其请求发送到 REST API。使用 `plaidcloud-rpc` 1.25.0 或更高版本时，`SimpleRPC` 调用会发送到 REST API，无需更改代码；REST API 尚未涵盖的调用，或仍在使用旧版本的工作区，会像以前一样使用 JSON-RPC。JSON-RPC 将在以后的版本中删除，因此请将脚本和笔记本升级到 `plaidcloud-rpc` 1.25.0 或更高版本，并基于 REST API 编写新的集成。请参阅[命令行](/zh-cn/reference/cli/jupyter/command-line/)。
- **步骤表单采用统一的布局。** 选项卡使用标准名称并按标准顺序排列：常规、设置、源、列、筛选器、输出和高级，ERP 过账表单上还有标题列和行列。必填字段以 * 标记，表单只会因步骤所需的内容而阻止保存。
- **复制项目可分别选择表数据和维度成员，复制数据更快，并保留私有副本的 ERP 写入授权。** 在 **Data to copy** 下，选择**表数据**（**无表数据**（默认）、**完整**或**样本**），并另外选择 **Copy dimension members**（默认开启），因此即使副本不含表行，其维度仍有数据，并且可以快速生成。**完整**和**样本**副本会同时复制多个表，因此包含许多表的项目完成得更快。**复制结果**会在表旁边列出每个维度的结果，**Retry failed items** 会同时重试失败的表和维度。使用数据创建的新副本仅对您私有，并保留源项目中您本人能够授予的 ERP 写入授权；如果源项目以实时模式过账，副本会以模拟模式提供，因此在您将其切换为实时模式之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择要复制的数据量](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **表的详细信息面板能更快地显示使用该表的步骤。** 选择另一个表时会立即清除上一个表的步骤，共享此项目数据的其他项目中的步骤会稍后于其余步骤添加，而不会拖慢整个面板。请参阅[查看表的使用位置](/zh-cn/guides/projects/managing-tables-and-views/#查看表的使用位置)。
- **行操作菜单（⋯）位于每个网格行的左边缘。**
- **应用选项卡图标采用统一的一套图标**，适用于浅色和深色模式。
- **没有验证设置的已保存 ERP 写入步骤会以仅验证模式打开。** 这包括 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post 以及 Xero 导出。明确设置为实时运行的步骤保持实时运行。
- **长时间运行的作业在所有地方都以相同的方式显示进度。**
- **工作流会停止、失败，并如实报告。** 停止工作流会停止它启动的一切；无法完成的运行或步骤会带着原因失败，而不是一直挂起；运行状态与实际运行的内容一致。
  - **停止工作流会停止它启动的所有内容，无法完成的运行或步骤会失败而不是挂起。** 停止操作会取消仍在排队的导入和维度步骤，以便工作区中后续的导入和维度加载能够正常启动，同时还会停止该工作流排队中或正在运行的连接器（Singer）同步。如果步骤的作业无法启动，该步骤会失败并给出原因，而不是无限期等待：大约 40 分钟内没有工作器启动它、某个工作器启动它后又消失、其 pod 停留在 Pending 状态约 20 分钟、其镜像约 5 分钟无法拉取，或者约 20 分钟内没有创建 pod。在大约 30 分钟内没有被任何运行器拾取的连接器同步会失败，并显示一条注明该同步的消息。步骤等待工作器期间，其状态消息显示“Waiting for a worker…”以及已等待的分钟数，工作开始后该消息会清除。停止宏会停止其所有正在运行的副本，而停止其中一个副本，或者 **Macro Concurrent** 步骤放弃一个已停止响应的副本时，调用它的工作流会继续运行。仅在其他工作流内部运行的宏会在工作流列表中显示为**正在运行**，提供**停止**，并显示其最近一次运行中每个步骤的状态、开始时间和结束时间。服务器丢失的运行会以失败告终，运行超过 12 小时仍未结束的运行会失败，并显示“Run failed: still running at the 12-hour limit. Re-run the workflow.”。请参阅[运行工作流](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
  - **恢复、运行历史记录和运行状态与实际运行的内容一致。** 恢复父工作流时会运行子工作流剩余的所有内容，即使您单独重新运行了子工作流中的某个步骤也是如此；在一次运行中，子工作流的每次调用都有各自的运行历史记录条目。由于服务器停止而重新启动的步骤会在其日志中加以说明，`workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续执行的步骤，而不是将运行报告为无问题。请参阅[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)和[出错时继续](/zh-cn/guides/workflows/continue-on-error/)。
  - **步骤错误会显示其自身的消息。** PlaidCloud 未预料到的错误会显示为“The step stopped on an unexpected error (*type*): *message*”。启动器上的**需要关注**卡片会用一行显示错误，并且不包含此后已被删除的工作流的运行。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。
  - **未完成的 ERP 提取会使其步骤失败，恢复后会继续进行。** 当 **SAP：临时提取**因达到行数或时间限制而暂停，或者其代理未及时答复，或者在步骤停止等待时 Salesforce、Oracle Fusion 批量或 HFM/FCCS 导出作业仍在运行，该步骤会失败，以免其后的步骤基于不完整的表运行。恢复工作流或重新运行该步骤后，提取会在同一个作业上从停止处继续。请参阅[运行限制](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制)和 [Salesforce：查询对象](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
  - **取消导出会停止其在仓库中的查询。** 当导出或下载被取消（包括通过停止其工作流取消）时，在 Lakehouse v2、Snowflake、Databricks、PostgreSQL 和 Greenplum 上读取其数据的查询也会停止，导出到远程数据库的操作也会停止读取其源，而不会继续运行到结束。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会转换为 REST 请求步骤。** 无法干净转换的步骤会保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **会话过期后打开的仪表板链接会在您登录后转到该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝无法识别的字段**，并在错误中注明该字段，而不是将其忽略。`workflow_upsert` 接受 `memo`，并接受 `description` 作为其别名。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 会自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，会使用该账户自身的凭据直接写入账户的存储桶，而不是让每一行先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式保持不变。请参阅 [Export to Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会注明其尝试连接的服务器（对于 Slack 和 Teams，还会注明连接），并说明出了什么问题，例如 Slack 不再识别该 webhook、无法向该频道发帖、找不到服务器或服务器在 60 秒内没有响应，或者连接已被删除。Slack 或 Teams 的 webhook URL 永远不会显示，因为任何拥有该 URL 的人都可以以您的集成身份发帖。请参阅 [Notify via Slack](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。
- **项目服务账户的访问令牌有效期至少为 24 小时。** 以项目身份运行的工作流作业（例如 UDF 步骤）会获得有效期为 24 小时的令牌。工作区升级时，较短的有效期会被延长，您设置的较长有效期则会保留。
- **工作区的组织、所有者、发布渠道和版本由 PlaidCloud 设置，数据中心由您选择。** 在控制平面中，您创建的工作区归您所有，并被放置在 PlaidCloud 设置的发布渠道上；**数据中心**从注册时提供的区域中选择。编辑工作区时，组织、所有者、发布渠道和版本为只读。使用 **Set Version** 更改版本；如需迁移工作区、更改其所有者或渠道，或固定其版本，请联系 PlaidCloud 支持。请参阅[工作区配置](/zh-cn/administration/control-plane/workspace-configuration/#主要设置)。

## 修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的 slug，或者无效的存储类型或过账模式，现在会返回一条注明问题的消息，而不是一般性的服务器错误。通过 REST API 时返回 400 而不是 500，通过 AI 助手或 MCP 时则返回无效参数错误。
- **REST API 的维度值请求可以正常工作。**`POST /rest/v1/analyze/query/retrieve-dimension-values` 曾被当作网格请求处理并因无效而被拒绝。现在它会为 `value_columns` 中的每一列返回一个聚合值，而网格（为每对行筛选器和列筛选器各返回一个值）有了专门的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再阻塞其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，以前都可能使同一服务器正在处理的所有其他请求暂停，直到其完成。现在它们会与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框的高度曾超过窗口，导致**创建**和**更新**按钮可能无法触及。现在表单可以滚动，按钮保持在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 以前这些操作在处理这种大小的文件时都会失败，移动或重命名包含此类文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚刚写入的内容。** 写入表的步骤或导入可能会记录写入之前的行数，因此刚加载的表显示为 0 行，导入可能报告导入了 0 行。现在会在新行在所有位置均可见后读取计数，因此其后的步骤也能读取到这些行。将表切换到另一个分支或将某个分支合并到该表中时，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的结果进行比较。** 步骤的空值经常是在步骤清空其表以重新填充之后立即统计的，因此其之前的运行看起来似乎没有空值，而一个一直部分为空的列会被报告为刚刚变空。现在每次运行都按步骤留下的表进行统计。之前记录的计数无法与正确的计数区分开，因此不再使用：每个步骤的空值检查会重新开始其历史记录，并在统计满五次运行之前报告为未检查。行数和值分布检查也不再将另一个步骤在该步骤完成两秒以上之后对同一个表的写入算作该步骤的写入。请参阅[Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **Data Foundation 会保留反转汇率和小数阈值的精度。** 由于您的汇率是从报告货币报价到另一种货币，PlaidCloud 需要将其反转，而反转后的汇率可能被舍入到六位小数，导致汇率较小的货币（例如印尼盾）中的金额偏差约 1%。现在反转后的汇率保留 12 位小数。带有小数的 `group_amber` 或 `group_red` 阈值（例如 `0.5`）曾被舍入为整数。下一次加载将使用精确的值。请参阅[汇率](/zh-cn/guides/projects/data-foundation/#汇率)。
- **已停用成员的警报和摘要会停止。** 所有者已被停用的 Panel 应用警报或摘要以前仍会继续检查和发送。现在在所有者被停用期间会暂停，并在其重新激活后恢复。请参阅[警报和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
- **通过 REST API 请求已删除的连接会返回 404。** 请求已被删除的连接或不存在的 ID 时，以前会返回一般性的服务器错误（500）。现在会返回 404，并显示一条注明连接 ID 的消息。

## 安全

- **密码登录需要身份验证器应用，并且密码强度更高。** 使用 PlaidCloud 密码登录的成员会在下次登录时被要求设置身份验证器应用，之后每次登录都需要输入其代码。单点登录、Google、Microsoft 和 GitHub 登录、API 令牌以及服务账户不受影响。新密码至少需要 12 个字符，不能与您的用户名或最近六个密码之一相同，并且在多次登录尝试失败后，账户会被短时锁定。工作区已有的更严格规则会被保留。请参阅[成员身份验证](/zh-cn/administration/access/member-authentication/)。
- **连接只能指向公共地址和专用网络地址。** 连接不能指向环回地址、链路本地地址或云元数据地址，错误会注明主机及其解析到的地址。专用网络上的地址不受影响。请参阅[连接无法访问的地址](/zh-cn/guides/connections/create-connection/#连接无法访问的地址)。
- **已保存的连接凭据仅向可以编辑连接或工作流的成员显示。** 通过 REST API 和 MCP，已保存连接的密码、令牌和密钥会对其他成员进行掩码处理，但他们仍可打开和浏览该连接。请参阅[谁可以看到连接的凭据](/zh-cn/guides/connections/create-connection/#谁能看到连接的凭据)。
- **应用构建在无法访问工作区 Git 凭据的情况下运行。**
- **代理的私钥仅向可以编辑代理的成员显示。** 通过 REST API 和 MCP 获取的代理列表或详细信息中不再显示该密钥，代理表单仅向可以编辑代理的成员显示**私钥**和**查看 RPC 配置**。服务账户、项目和代理令牌以及 AI 委派令牌无法检索该密钥或 RPC 配置。正在运行的代理不受影响，公钥仍会显示。请参阅[获取代理凭据](/zh-cn/reference/cli/plaidlink/agents/#获取代理凭据)。
- **代理下载链接的有效期为一小时。** 启用 **Use PlaidCloud Proxy Download** 后，如果链接已过期，请重新打开下载以获取新链接。请参阅[服务](/zh-cn/administration/control-plane/workspace-configuration/#服务)。
- **将人员添加到安全组时遵循您所持有的权限。** 只有当您持有某个分组授予的所有权限时，才能将成员添加到该安全组、为成员选择分组或邀请架构师。工作区管理员不受此限制。请参阅[管理安全组](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理安全组)。
- **由连接的所有者或工作区管理员更改其设置以及启用或禁用连接。** 通过 REST API、JSON-RPC 以及 AI 助手或 MCP 更改连接的设置，需要由其所有者之一执行；对于没有所有者的连接，则需要由工作区管理员执行。启用、禁用、锁定和解锁连接需要由所有者或工作区管理员执行，并且指定多个连接的请求只有在您可以更改所有这些连接时才会生效。只有工作区管理员才能选择工作区的默认 AI 连接，并且只有当没有任何由管理员拥有或没有所有者的连接可以作为默认连接时，成员拥有的连接才会成为默认连接。请参阅[编辑连接](/zh-cn/guides/connections/create-connection/#编辑连接)和 [LLM 提供商](/zh-cn/integrations/ai-architecture/llm-providers/#连接包含的内容)。
- **行访问适用于成员对受限表执行的所有操作。** 无论是在仪表板、自己编写的 SQL 中，还是在加载数据时，成员都只能查看和更改其授权允许的行。
  - **项目架构师在仪表板中可以看到行受限表的所有行**，与他们在 Analyze 中看到的一致。撤销架构师访问权限会立即在仪表板中生效，无论是更改某人的角色、将其本人或其分组从项目中移除、更改项目的访问类型、还原项目的早期版本，还是删除安全组。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
  - **受行访问限制的成员可以运行自己的 SQL 查询并导出结果。** 在启用了行访问的项目中，非架构师成员在查询屏幕上运行自己的查询时，会准确获得其授权所允许的行，并可将其导出为 CSV、Excel 或 JSON，同时显示**行数受您的访问权限限制**提示；以前这些操作会被拒绝。包含百分号（`%`）的授权值现在可以在查询屏幕上返回其行，将此类查询下载为 CSV 也可以正常工作。他们在 Snowflake 或 Databricks 上自己编写的自由格式 SQL、从 Postgres 系列仓库导出他们自己的 SQL，以及按快照读取受管控的表，仍会被拒绝；并且视图必须保留受管控列的原始名称才能被筛选。请参阅[行访问与您自己编写的查询](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问与您自己编写的查询)。
  - **保存行访问时会保留其来源中不存在的已授权值。** 当表中没有包含某个安全组已授权值的行、维度中没有该成员或列表中没有该值时，该值仍会保留在网格中并带有标记。**保存**时会询问对每个此类值是保留还是移除。请参阅[行访问网格](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
  - **对行受限表的 DataFrame 写入、记录保存和清除只会更改您可以看到的行。** 当行访问限制了您可见的行时，使用 Python 客户端将 DataFrame 写入受限表或清除该表，或者通过 REST API 向该表保存记录或清除该表，只会更改您自己的行；包含您访问权限之外的行的加载会在任何内容更改之前被拒绝，并注明发现的值。项目架构师、可以看到所有行的成员以及工作流运行会写入整个表。个人对任何表执行的每次此类写入都会记录在安全日志中。请参阅[将数据加载到受限表](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
  - **对行受限表执行导入、复制、还原和删除操作，需要您能够看到所有行。** 当行访问限制了您可见的行时，将文件导入受限表、从另一个项目将表复制到该表、切换或合并其分支、还原该表、删除该表、在删除后将其恢复，或者任何其他替换整个表的操作，只有在您可以看到该表的所有行时才会运行；否则会被拒绝，并且不会更改任何内容。通过 REST API 保存表的行只会更改您自己的行，与其他加载操作相同。项目架构师、可以看到所有行的成员以及工作流运行不受影响，这些操作也会记录在安全日志中。请参阅[将数据加载到受限表](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
- **只有账户的所有者才能还原其早期版本。** 将文档账户还原到早期版本、保留或释放某个版本以及创建备份，需要由账户的所有者之一执行，并且这些操作在系统管理的账户上均不可用。查看账户的版本历史记录需要具有该账户的访问权限。
- **`query_run` 运行只读语句。** AI 助手和 MCP 客户端使用的 `query_run` 工具接受一条 SELECT 或 WITH 语句、对其中一条语句的 EXPLAIN，或者一条 SHOW 语句；其他任何语句都不会运行。如需更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 也遵循相同的规则。通过 REST 和 JSON-RPC API，对于无法更改项目数据的成员，该规则还适用于运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库，以及使用您自己的查询导出表数据；被拒绝的查询会返回 403。Explain Analyze 会运行查询以进行度量，因此在查询日志和 Lakehouse 中，它只接受读取数据的查询；在启用了行访问的项目中，只有项目架构师才能从查询日志中运行它。
