## 新增

- **PlaidXL 在 Excel 中生成报表、钻取、解释数字并编制计划。** **PlaidCloud** 功能区选项卡分为 **连接**、**插入**、**刷新**、**Drill**、**写入** 和 **共享**，常用命令也出现在 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡中，主要命令带有可自行更改的键盘快捷键，在字段中输入时不会触发。命令失败时会说明是哪条命令以及原因。登录之前运行的命令会先打开登录窗口，登录后自动运行一次；一次登录只对一个工作区有效，因此切换工作区时会要求登录新工作区（切换回来则无需再次登录）；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次点击即可生成报表。** **报表** 选项卡根据一个表生成实时报表，一个维度向下钻取到行，另一个维度横跨列，每个交叉点是一个 `CELL` 值。**Build my first report** 会用您自己的数据生成示例。钻取时，报表会插入和删除整行整列，您输入的值、备注和格式会跟随所在的行。请参阅 [生成报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 可将节点、维度标题或报表值变成实时的 `DRILL` 公式，并为您编辑该公式。**Custom drill** 在插入前预览行，成员选择器可插入成员，或为单元格添加某个节点的子节点下拉列表。`DRILL` 可接受要排除或展开的节点，也可以横跨一行运行。请参阅 [钻取、选择成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释一个数字。** **Explain this number** 显示某个值的计算方式、它现在是否与 PlaidCloud 一致，以及它来自哪个表和工作流步骤。**Show detail rows** 将值背后的行放在单独的工作表中，并检查这些行是否加总一致。
  - **Excel 中的受治理指标。** `PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 按仪表板显示的方式返回业务指标；没有可聚合内容的 `CELL` 或 `CELLS`，求和显示 `0`，其他情况显示 `#VALUE!` 并附带原因（在 `CELLS` 溢出区域中为空白）；**Metric...** 会列出项目的指标及其当前值。请参阅 [指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中直接输入即可规划。** 在 `CELL` 值上输入数字，即可写入 PlaidCloud：可按比例分摊、平均分摊或按另一个成员的形态分摊，也可按金额或百分比调整，已锁定的单元格不受影响。平均值、中位数、最小值、最大值、标准差和方差单元格同样接受输入值，插入或删除行列时，输入的值会跟随其单元格（已删除单元格中的值会被报告）。**Undo last write** 会按从新到旧的顺序撤消输入的值和保存，且只有执行写入的人和工作区才能撤消该写入。撤消求和，或撤消输入到空单元格中的平均值时，会保留之后写入同一单元格的内容；在完成前被中断的写入无法撤消。请参阅[向 PlaidCloud 输入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新您需要的内容。** 可以刷新一个工作表、一个选区或所有表，每个表的进度和 **取消** 显示在任务窗格中，也可以只重新计算 PlaidXL 公式。检索到的表以 Excel 表格形式到达并按数据类型设置格式，刷新时保留您自己的列和数字格式，并在原位置刷新。检索或刷新不会覆盖其他单元格，也不会与另一个 Excel 表格重叠；超出 Excel 范围的整数 ID 和 1900 年之前的日期以文本形式到达。再次检索同一个表不会将它重复加入刷新列表，**Stop refreshing** 可将某个表移出列表，维度会随表一起刷新。请参阅 [刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#refresh-all-tables)。
  - **保存立即写入，并且可以撤消。** **Save to PlaidCloud** 无需确认即可写入，会说明所做的操作，并提供 **撤消**。带筛选器检索的工作表、明细行工作表，或访问权限仅覆盖部分行的人员，只会替换那些行，因此其他人的行会保留。自检索以来成员已发生变化的钻透工作表不会被保存；保存失败时会给出还原点的名称，以便将表恢复原状。请参阅 [将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在 **Weave** 选项卡上，可以用日常语言要求生成报表、公式、钻取或表，也可以选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只更改工作簿，在替换您已输入的内容之前会先询问，绝不会写出引用工作簿之外内容的公式，并且每项更改在您重新加载窗格之前都可以还原。请参阅 [在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享一个工作表或整个工作簿的纯值副本。** **Convert to values** 可转换整个工作簿、一个工作表，或转换为无法恢复的纯值（会先询问），只更改 PlaidXL 公式及其溢出区域，仍在计算的公式会保留以便再次尝试，并且在您重命名工作表之后，**Restore PlaidXL formulas** 仍然有效。
- **步骤表单上的预览。** 导入：SQL、Execute: SQL、提取 SQL、导出：SQL 和 Salesforce 查询最多显示 100 行，而无需运行步骤；Anaplan 视图和列表读取会显示它们将生成的列和类型。点击 **源** 选项卡上的 **预览**。变量会按运行时的填充方式填入，但不支持 `{x:>9}` 这类变量格式。预览只运行标准 SQL 函数，否则会提示您运行该步骤。锁定的项目以及基于代理的 Execute SQL 步骤不支持预览。请参阅 [导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/) 和 [提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告会显示变化、可缩小到某个分组，并可接入工作流。** **概览**新增与上一期间相比的趋势箭头，以及一个**亮点**列表（**Highlights**），指出不活跃的成员以及无人打开的仪表板和应用。已停用的成员不会被计入，也不会被列为不活跃。**分组**可将**概览**、**内容**和不活跃列表限定为某个安全组的成员，日期范围新增 **Previous month** 和 **This month**，由所有选项卡共用，并随您的账户记住。现在每个数字都有说明，表使用**成员**和 **Area** 等通俗名称，按 Enter 键可打开行，加载和错误提示更清晰，最后一个**漏斗**步骤会显示有多少成员完成了它。新的 Get Workspace Usage 步骤会按计划将每日或每月使用总量写入一张表，不含成员姓名，其每次运行与 Get Workspace Members 步骤一样，都会记录在**安全日志**中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表，并设置项目的默认仪表板受众。** `publish_manage` 取消发布一个表，同时取消发布其已发布的视图和没有图表使用的仪表板数据集；仍被图表使用的数据集会保留，当报表视图建立在已发布的视图之上时，该视图和数据集也会保留，而表仍会被取消发布。`project_upsert` 设置 `dashboard_default_audience`，即该项目中新仪表板所共享的分组，`[]` 表示清除。请参阅 [取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布) 和 [通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Git 应用会列出您的存储库，并说明您可以执行的操作。** 应用列表中的 **Git** 显示您的角色（**管理员**、**贡献者**或**查看者**）和工作区的存储库，每个存储库带有说明、最后更新日期、带复制按钮的克隆地址以及**打开**。**Set up Git on your computer** 卡片引导完成安装 Git、创建令牌和克隆，**How to clone** 可重新打开它。**View all in Git** 打开完整的 Git 界面，**Manage who can push** 打开分组管理。访问级别为**查看者**、**贡献者**（向 `apps` 推送应用代码）或**管理员**（可推送到所有位置，包括 `udfs`），查看者会看到最多三位可以联系的工作区管理员。新的 **Git Contributors** 分组授予贡献者权限，并可设为默认分组，因此新成员会自动获得；**Git Administration** 授予管理员权限。成员的 **Git** 选项卡显示其 Git 用户名、级别以及授予该级别的分组。成员的 Git 账户跟随其成员身份：停用或移除成员后，约一小时内其 Git 账户（包括令牌和 SSH 密钥）将被阻止，重新激活后即解除阻止，其存储库和历史记录予以保留。通过单点登录登录 Git 会打开成员本人的账户。贡献者不能直接在工作区的 Git 组织中创建存储库；存储库通过 PlaidCloud 创建。应用窗口显示**存储库**部分，UDF 有**打开**，Git 提供返回工作区的 **← Back to** 链接。平台创建的每个存储库（包括应用存储库以及内置的 `apps` 和 `udfs` 存储库）均可由工作区中每位已登录的成员读取，因此成员无需逐个存储库进行设置即可打开并重新发布应用。Git 管理员仍可将存储库设为私有，这会使其在存储库选取器中隐藏，并使成员无法从中发布，也无法运行其中存储的基于 Git 的 UDF 代码。请参阅 [PlaidCloud Git](/zh-cn/guides/git/#打开-git) 和[谁可以查看存储库](/zh-cn/guides/connections/plaidcloud-git/#谁可以查看存储库)。
- **Cost to Serve 和 Operational Transfer Pricing 模板基于 Common Finance Model 构建。** 从 **Cost to Serve** 启动项目，可按您为每个部门设置的活动和动因，将运营费用分摊到客户，并查看每个客户扣除服务成本后的利润，且与总账相互勾稽。从 **Operational Transfer Pricing** 启动，可对照您的政策区间测试每个实体的利润水平（销售回报率、成本加成或再销售价格减让），并通过调整补足使超出区间的实体回到目标值。销售回报率为息税前利润（EBIT）除以受测方销售额。请参阅 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/) 和 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)。
- **OneStream 和 Anaplan 为 Data Foundation 提供数据，OneStream 还有读取步骤。** Data Foundation 通过您的 OneStream 管理员构建的数据适配器读取 OneStream 合并结果，通过导出操作读取 Anaplan 计划，并将集团损益表与它们进行核对。新的 **OneStream: Read Adapter** 步骤可在任意工作流中读取适配器，每个合并成员调用一次，并将结果写入表中。请参阅 [OneStream 用于 Data Foundation](/zh-cn/guides/connections/onestream-for-data-foundation/)、[Anaplan 作为 Data Foundation 数据源](/zh-cn/guides/connections/anaplan/#将-anaplan-作为-data-foundation-源) 和 [OneStream: Read Adapter](/zh-cn/reference/workflow-steps/onestream/onestream-read-adapter/)。
- **选择 Data Foundation 如何分摊共同成本。** **Actions > Allocations...** 会逐步引导您确定要分摊哪些成本、按什么分摊、落在哪里，以及负的动因如何处理，适用于将间接费用分摊到部门，以及将部门成本分摊到产品和客户，并提供一个月的预览，显示归集、已分摊和未分摊的金额。您手动编辑的规则会保留。请参阅 [分摊规则](/zh-cn/guides/projects/data-foundation/#分摊规则)。
- **在 Data Foundation 中解释数字，并按您的习惯命名。** **Explain this number** 在您自己的行访问权限下，将损益表数字拆分为总账中的金额、分摊转入和转出的金额以及集团内抵销的金额，并列出最大的来源单据。**Business names** 为类别、损益表行、指标和列提供贵公司使用的名称，应用于报表、指标和助手。请参阅 [解释数字](/zh-cn/guides/projects/data-foundation/#解释数字) 和 [业务名称](/zh-cn/guides/projects/data-foundation/#业务名称)。
- **Data Foundation 每次加载都会生成董事会材料包，并允许您回退。** 每次 **加载** 都会将一个 Excel 工作簿和损益表仪表板的 PDF 写入文档账户的某个文件夹；关闭报告时，材料包只有工作簿，对话框会说明这一点。每次加载开始时，以及每次更改映射或数据源之前，都会创建一个还原点，**Actions > Restore...** 显示每个还原点会恢复多少个表，并将项目（包括维度）恢复原状。**基础数据** 选项卡对当前状态的说明更清晰：它会显示仍在运行或中途停止的更新，说明为什么一个表文件夹不是数据源，在有内容勾稽一致之前让 **检查合计是否一致** 保持待定状态，并在状态读取失败后自动恢复。应用更新时会保留您对生成步骤的手动编辑，并注明任何冲突。请参阅 [董事会材料包](/zh-cn/guides/projects/data-foundation/#董事会资料包) 和 [还原点](/zh-cn/guides/projects/data-foundation/#还原点)。
- **克隆 Data Foundation 项目，或将其另存为模板。** **Actions > Clone...** 会复制项目，包括您对模型的编辑、指标和分析路径。**Save as my template...** 将设置保存到文档账户，**From a template file...** 据此启动新的私有项目，其数据源等待连接。请参阅 [克隆项目](/zh-cn/guides/projects/data-foundation/#克隆项目) 和 [另存为我的模板](/zh-cn/guides/projects/data-foundation/#另存为我的模板)。
- **Data Foundation 的设置清单一直延伸到移交，助手可以解决剩余问题。** 清单新增了夜间刷新、证据包以及将项目移交给其负责人，并说明是谁设置了该项目。可以让助手为没有类型的科目、多个数据源使用的代码以及没有匹配到任何内容的文件列提出答案；它不会写入任何内容，由您来应用这些答案。请参阅 [Data Foundation 入门](/zh-cn/guides/projects/data-foundation-getting-started/) 和 [用 Ask 解决未决问题](/zh-cn/guides/projects/data-foundation/#用-ask-解决未决问题)。

- **移动端 Weave 的语音输入只需点一下。** 点击麦克风，提出问题，您停止说话后 Weave 会发送一次。再次点击麦克风可提前停止，如果一直没有声音，它会自动关闭。如果您在说话中途离开 **Weave** 选项卡或将应用切到后台，您说的话会保留在问题框中而不发送，以便您检查。运行、暂停、停止和恢复会忽略对其确认的误触双击。需要应用版本 1.3.0 或更高版本。请参阅 [使用语音](/zh-cn/guides/mobile-app/weave-on-mobile/#使用语音)。

## 变更

- **PlaidCloud 的 Web 应用和 Python 客户端库使用 REST API，JSON-RPC 已弃用。** Web 应用将请求发送到 REST API。使用 `plaidcloud-rpc` 1.25.0 或更高版本时，`SimpleRPC` 调用无需修改代码即可发送到 REST API；REST API 尚未覆盖的调用，或仍在旧版本上运行的工作区，会像以前一样使用 JSON-RPC。JSON-RPC 将在以后的版本中移除，因此请将脚本和笔记本升级到 `plaidcloud-rpc` 1.25.0 或更高版本，并基于 REST API 编写新的集成。请参阅[命令行](/zh-cn/reference/cli/jupyter/command-line/)。
- **步骤表单遵循统一的布局。** 选项卡采用标准名称和标准顺序：常规、设置、源、列、筛选器、输出和高级，ERP 过账表单上另有表头列和行项目列。必填字段以 * 标记，表单只对步骤所需的内容阻止保存。
- **复制项目分别选择表数据和维度成员，复制数据更快，并保留私有副本的 ERP 写入授权。** 在 **Data to copy** 下，选择 **表数据**（**No table data**（默认）、**完整** 或 **样本**），并另外选择 **Copy dimension members**（默认开启），因此不含表行的副本到达时仍有已填充的维度，制作也很快。**完整** 和 **样本** 复制会同时复制多个表，因此包含许多表的项目完成得更快。**复制结果** 在表旁边列出每个维度的结果，**Retry failed items** 会同时重试失败的表和维度。带数据创建的新副本归您私有，并保留来源中您自己有权授予的 ERP 写入授权；如果来源以 Live 方式过账，副本会以 Simulate 方式到达，因此在您将其切换为 Live 之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅 [选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据) 和 [副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **表的详细信息面板更快显示使用该表的步骤。** 选择另一个表时，会立即清除上一个表的步骤；与本项目共享数据的其他项目中的步骤会稍后补充，而不再拖慢整个面板。请参阅 [查看表在哪里使用](/zh-cn/guides/projects/managing-tables-and-views/#查看表的使用位置)。
- **行操作菜单（⋯）位于每个网格行的最左侧。**
- **应用选项卡图标统一为一套**，浅色和深色模式下都一致。
- **没有验证设置的已保存 ERP 写入步骤以仅验证方式打开。** 涵盖 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post 以及 Xero 导出。明确设置为实际运行的步骤仍保持实际运行。
- **长时间运行的作业在所有位置以相同方式显示进度。**
- **停止工作流会停止它启动的一切内容，无法完成的运行或步骤会失败，而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中后续的导入和维度加载可正常开始，同时也会停止该工作流排队或正在运行的连接器（Singer）同步。如果步骤的作业无法启动，该步骤会连同原因一起失败，而不是无限等待：约 40 分钟内没有工作进程启动它、工作进程启动后消失、其 pod 卡在 Pending 状态约 20 分钟、镜像约 5 分钟内无法拉取，或约 20 分钟内没有创建 pod。约 30 分钟内没有运行器接手的连接器同步会失败，并给出指明该同步的消息。步骤等待工作进程期间，其状态消息显示“Waiting for a worker…”及已等待的分钟数，工作开始后即清除。停止宏会停止它的每个运行副本，而停止其中一个副本，或 **Macro Concurrent** 步骤放弃一个已停止响应的副本时，调用它的工作流会继续运行。仅在其他工作流内部运行的宏会在工作流列表中显示为**正在运行**，可使用**停止**，并显示每个步骤最近一次运行的状态、开始时间和结束时间。服务器丢失的运行会以失败结束，运行超过 12 小时仍未结束的会失败，并提示“Run failed: still running at the 12-hour limit. Re-run the workflow.”。请参阅[无法启动的步骤](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
- **恢复、运行历史和运行状态与实际运行情况一致。** 恢复父工作流会运行子工作流剩余的所有内容，即使您之前单独重新运行过子工作流的某个步骤也是如此，同一次运行中对子工作流的每次调用都有自己的运行历史条目。因服务器停止而重启的步骤会在日志中说明，`workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续运行的步骤，而不是将该运行报告为正常。请参阅 [暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复) 和 [出错时继续](/zh-cn/guides/workflows/continue-on-error/)。
- **步骤错误显示其自身的消息。** PlaidCloud 未预料到的错误显示为“The step stopped on an unexpected error (*type*): *message*”。启动台上的 **需要关注** 卡片以一行显示错误，并省略已被删除的工作流的运行。请参阅 [管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。
- **未完成的 ERP 提取会使其步骤失败，恢复后可继续。** 当 **SAP：临时提取** 在行数或时间限制处暂停，或其代理未及时回复，或者 Salesforce、Oracle Fusion 批量导出或 HFM/FCCS 导出作业在步骤停止等待时仍在运行，该步骤会失败，使后续步骤不会基于部分表运行。恢复工作流或重新运行该步骤，提取会在同一作业上从停止处继续。请参阅 [运行限制](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制) 和 [Salesforce：查询对象](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
- **取消导出会停止其在仓库中的查询。** 导出或下载被取消时（包括因停止其工作流而取消），在 Lakehouse v2、Snowflake、Databricks、PostgreSQL 和 Greenplum 上，读取其数据的查询也会停止；导出到远程数据库时也会停止读取其源，而不会一直运行到结束。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **项目架构师在仪表板中可以看到行受限表的所有行**，与他们在 Analyze 中看到的一致。取消架构师访问权限会在仪表板中立即生效，无论是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、还原较早的项目版本，还是删除安全组。前架构师不再能看到行受限数据的所有行。请参阅 [管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
- **受行访问限制的成员可以运行自己的 SQL 查询并导出结果。** 在设置了行访问的项目中，非架构师成员在查询屏幕上自己的查询中，恰好得到其授权允许的行，并可将其导出为 CSV、Excel 或 JSON，同时显示 **行数受您的访问权限限制** 提示；此前这些操作会被拒绝。包含百分号（`%`）的授权值现在可以在查询屏幕上返回其行，将此类查询下载为 CSV 也可以正常工作。他们在 Snowflake 或 Databricks 上自己编写的自由格式 SQL、从 Postgres 系列仓库导出自己的 SQL，以及读取某个快照时点的受治理表，仍然会被拒绝；视图必须以原始名称保留受治理的列，才能被筛选。请参阅 [行访问与您自己编写的查询](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问与您自己编写的查询)。
- **会话过期后打开的仪表板链接，在您登录后会带您进入该仪表板。** 请参阅 [使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝无法识别的字段**并在错误中指出该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为它的另一个名称。请参阅 [未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据直接进入该账户的存储桶，使用该账户自己的凭据写入，而不是每一行都先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式与之前相同。请参阅 [导出为 Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会指出它尝试访问的服务器，对 Slack 和 Teams 还会指出连接，并说明出了什么问题，例如：Slack 不再识别该 webhook、无法向该频道发布消息、找不到服务器或服务器在 60 秒内没有响应，或者连接已被删除。Slack 或 Teams 的 webhook URL 绝不会显示，因为任何持有它的人都可以冒充您的集成发布消息。请参阅 [通过 Slack 通知](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。
- **项目服务账户的访问令牌有效期至少为 24 小时。** 以项目身份运行的工作流作业（例如 UDF 步骤）获得的令牌有效期为 24 小时。较短的有效期会在工作区升级时提高，您设置的较长有效期保持不变。
- **工作区的组织、所有者、数据中心、发布渠道和版本由 PlaidCloud 设置。** 在控制平面中编辑工作区时，这些字段为只读；您创建的工作区归您所有，并放在默认的数据中心和发布渠道上。使用 **设置版本** 更改版本；如需移动工作区、更改其所有者或渠道，或将其固定，请联系 PlaidCloud 支持。请参阅[工作区配置](/zh-cn/administration/control-plane/workspace-configuration/#主要设置)。

## 修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的 slug，或无效的存储类型或过账模式，现在会返回指明问题的消息，而不是通用的服务器错误。通过 REST API 时返回 400 而不是 500，通过 AI 助手或 MCP 时是无效参数错误。
- **REST API 的维度值请求可以正常工作。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 曾被当作网格请求处理并因无效而被拒绝。现在它为 `value_columns` 中的每一列返回一个聚合值，而网格请求（每对行筛选器和列筛选器返回一个值）有了自己的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再拖慢其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，以前都可能使同一服务器正在处理的所有其他请求暂停，直到它完成。现在它们与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口高，因此 **创建** 和 **更新** 按钮可能够不到。现在表单可以滚动，按钮保持在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 这些操作以前对这种大小的文件都会失败，移动或重命名包含此类文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚刚写入的内容。** 写入表的步骤或导入可能记录写入之前的行数，因此刚加载的表显示 0 行，导入也可能报告导入了 0 行。现在会在新行对所有位置可见之后再读取行数，因此其后的步骤也能读取到这些行。将表切换到另一个分支，或将分支合并到表中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的内容比较。** 步骤的空值数量经常在该步骤清空其表以重新填充之后才被统计，因此其较早的运行看起来没有空值，而一直部分为空的列则被报告为刚刚变空。现在每次运行都按步骤留下的表来统计。之前记录的计数无法与正确的计数区分，因此不予使用：每个步骤的空值检查会重新开始其历史记录，在统计满五次运行之前报告为未检查。行数和值分布检查也不再把另一个步骤在其完成两秒之后对同一个表所做的写入算作该步骤的写入。请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **Data Foundation 保留取倒数汇率和小数阈值的精度。** 当您的汇率是从报告货币折算为其他货币报价时，PlaidCloud 会将汇率取倒数，而这类汇率可能被舍入到 6 位小数，导致印尼盾等汇率很小的货币的金额偏差约 1%。现在取倒数后的汇率保留 12 位小数。带小数的 `group_amber` 或 `group_red` 阈值（例如 `0.5`）曾被舍入为整数。下一次加载会使用精确的值。请参阅[汇率](/zh-cn/guides/projects/data-foundation/#汇率)。
- **已停用成员的警报和摘要会停止。** 所有者已被停用的 Panel 应用警报或摘要曾经会继续检查和发送。现在，在所有者被停用期间它会暂停，并在所有者被重新启用后恢复。请参阅[警报和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
- **向 REST API 请求已删除的连接时返回 404。** 请求已被删除的连接或不存在的 ID，以前会返回通用服务器错误（500）。现在返回 404，并附带指明该连接 ID 的消息。

## 安全

- **使用密码登录需要身份验证器应用，密码要求也更严格。** 使用 PlaidCloud 密码登录的成员会在下次登录时被要求设置身份验证器应用，此后每次登录都需输入其代码。单点登录、Google、Microsoft 和 GitHub 登录、API 令牌和服务账户不受影响。新密码至少需要 12 个字符，且不能与用户名或最近六个密码中的任何一个相同；多次登录失败后，账户会被短暂锁定。工作区原有的更严格规则保持不变。请参阅[成员身份验证](/zh-cn/administration/access/member-authentication/)。
- **连接可指向公共网络和私有网络地址。** 连接不能指向环回地址、链路本地地址或云元数据地址，错误信息会列出主机及其解析到的地址。私有网络中的地址不受影响。请参阅[连接无法访问的地址](/zh-cn/guides/connections/create-connection/#连接无法访问的地址)。
- **已保存的连接凭据只显示给可以编辑连接或工作流的成员。** 通过 REST API 和 MCP，其他成员获得的已保存连接的密码、令牌和密钥均为掩码形式，但仍可以打开和浏览该连接。请参阅[谁能看到连接的凭据](/zh-cn/guides/connections/create-connection/#谁能看到连接的凭据)。
- **应用构建在运行时无法访问工作区的 Git 凭据。**
- **代理下载链接的有效期为一小时。** 开启 **使用 PlaidCloud 代理下载** 后，链接过期时请重新打开下载以获取新链接。请参阅[服务](/zh-cn/administration/control-plane/workspace-configuration/#服务)。
- **将人员添加到安全组时遵循您所拥有的权限。** 当您拥有组授予的全部权限时，可以将成员添加到安全组、选择成员所属的组或邀请 Architect。工作区管理员不受此限制。请参阅[管理安全组](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理安全组)。
- **连接的所有者或工作区管理员可更改其设置并将其开启或关闭。** 通过 REST API、JSON-RPC 以及 AI 助手或 MCP 更改连接的设置时，需要您是其所有者之一；对于没有所有者的连接，则需要您是工作区管理员，与在 PlaidCloud 中一样。启用、禁用、锁定和解锁连接需要所有者或工作区管理员；如果请求中指定了多个连接，只有当您可以更改全部连接时，该请求才会生效。只有工作区管理员才能选择工作区的默认 AI 连接；只有当没有任何由管理员拥有或没有所有者的连接可以作为默认连接时，成员拥有的连接才会成为默认连接。请参阅[编辑连接](/zh-cn/guides/connections/create-connection/#编辑连接)和 [LLM 提供商](/zh-cn/integrations/ai-architecture/llm-providers/#连接包含的内容)。
- **保存行访问时会保留其来源已不再包含的授权值。** 一旦表中没有包含该值的行、维度已失去该成员，或列表不再包含它，安全组被授予的该值在下次保存时会从授权中消失。这样，未选中任何值的分组会退回到 **Everyone else**，这可能意味着所有行。现在该值会保留在网格中并带有标记，**保存** 会询问是保留还是移除。请参阅 [行访问网格](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
- **只有账户的所有者才能还原其较早的版本。** 将文档账户还原到较早的版本、保留或释放某个版本以及进行备份，现在都要求您是该账户的所有者，并且系统托管的账户不提供其中任何一项。查看账户的版本历史需要有该账户的访问权限。
- **只应读取数据的查询不能再更改数据。** AI 助手和 MCP 客户端使用的 `query_run` 工具只运行读取数据的语句，即一条 SELECT 或 WITH 语句、对它的 EXPLAIN，或 SHOW，并且会拒绝其他任何语句而不运行。要更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 遵循同样的规则。通过 REST 和 JSON-RPC API，对于无权更改项目数据的成员，该规则同样适用于运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库，以及用自己的查询导出表数据；被拒绝的查询返回 403。Explain Analyze 会运行查询以进行度量，因此在查询日志和 Lakehouse 中，它现在只接受读取数据的查询，并且在设置了行访问的项目中，只有项目架构师才能从查询日志中运行它。
- **将 DataFrame 写入、保存记录和清空行受限表只会更改您能看到的行。** 当行访问限制您的行时，用 Python 客户端将 DataFrame 写入受限表或清空它，或通过 REST API 向其保存记录或清空它，只会更改您自己的行，而包含您无权访问的行的加载会在任何更改之前被拒绝，并指出发现的值。项目架构师、能看到所有行的成员和工作流运行像以前一样写入整个表。现在，人员对任何表所做的这些写入每一次都会记录在 **安全日志** 中。请参阅 [向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
- **导入、复制、还原和删除不再替换您看不到的行。** 当行访问限制了您的行时，只要表中有您看不到的行，向受限表导入文件、从另一个项目将表复制到其中、切换或合并其分支、还原它、删除它、在删除后恢复它，或任何其他会替换整张表的操作都会被拒绝，且不会有任何更改。通过 REST API 保存表的行现在也只会更改您自己的行，与其他加载方式一致。项目架构师、能看到所有行的成员和工作流运行不受影响，这些操作同样会记录在**安全日志**中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
