## 新增

- **PlaidXL 在 Excel 中构建、钻取、解释和规划。**“PlaidCloud”功能区选项卡分为**连接**、**插入**、**刷新**、**钻取**、**写入**和**共享**，常用命令也出现在 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡中，主要命令带有可更改的键盘快捷键。登录前运行的命令会打开登录界面，并在登录后运行一次；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次点击即可构建报表。**“Report”选项卡根据表生成实时报表，一个维度沿行向下钻取，另一个沿列横向展开，每个交叉点是一个 `CELL` 值。**Build my first report** 会用您自己的数据生成示例。钻取时，报表会插入和删除整行整列，您键入的值、备注和格式会跟随其所在的行。请参阅[构建报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 可将节点转换为实时的 `DRILL` 公式并为您编辑，适用于节点、维度标题或报表值。**Custom drill** 会在插入前预览行，成员选取器可插入成员，或为单元格添加某个节点子级的下拉列表。`DRILL` 支持排除或展开节点，并可横跨一行运行。请参阅[钻取、选取成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释一个数字。** **Explain this number** 会显示值的计算方式、它现在是否与 PlaidCloud 一致，以及它来自的表和工作流步骤。**Show detail rows** 会将值背后的行放到单独的工作表中，并附带检查这些行是否加总一致。
  - **Excel 中的受治理指标。**`PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 返回与仪表板所示一致的业务指标，**Metric...** 会列出项目的指标及其当前值。请参阅[指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中键入即可规划。** 在 `CELL` 值上键入数字，它就会写入 PlaidCloud：可按比例、平均或按另一成员的形态分摊，也可按金额或百分比调整，已锁定的单元格保持不变。均值、中位数、最小值、最大值、标准差和方差单元格同样接受键入值。**Undo last write** 按从新到旧的顺序撤销键入的值和保存。请参阅[向 PlaidCloud 键入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新您需要的内容。** 可刷新一个工作表、一个选区或所有表，每张表的进度和**取消**显示在任务窗格中，也可只重新计算 PlaidXL 公式。检索到的表以按数据类型设置格式的 Excel 表格形式到达，刷新时保留您自己的列和数字格式，并在原位刷新。再次检索表不会将其重复添加到刷新列表，**Stop refreshing** 可将其移出，维度会随您的表一起刷新。请参阅[刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#刷新所有表)。
  - **保存立即写入，并且可以撤消。** **Save to PlaidCloud** 无需确认即可写入，会说明所做的操作，并提供**撤消**。通过筛选器检索的工作表、明细行工作表，或访问权限仅覆盖部分行的人员，只会替换那些行，因此其他人的行得以保留。请参阅[将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在“Weave”选项卡上，可用日常语言要求生成报表、公式、钻取或表，也可选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只更改工作簿，在替换您已输入的内容之前会先询问，并且每项更改在您重新加载窗格之前都可以还原。请参阅[在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享一个工作表或整个工作簿的仅值副本。** **Convert to values** 可转换整个工作簿、单个工作表，或无法恢复的值，**Restore PlaidXL formulas** 在您重命名工作表后仍然有效。
- **步骤表单上的预览。** 导入：SQL、Execute: SQL、提取：SQL、导出：SQL 和 Salesforce 查询最多可在不运行步骤的情况下显示 100 行，Anaplan 视图和列表读取则显示它们将生成的列和类型。请在**源**选项卡上单击**预览**。变量会按运行时的方式填充，但不支持 `{x:>9}` 这类变量格式。预览只运行标准 SQL 函数；否则会提示您运行该步骤。在已锁定的项目上，或对基于代理的 Execute SQL 步骤，预览不可用。请参阅[导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/)和[提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告显示变化、可限定到分组，并可接入工作流。** **概览**新增相对上一期间的趋势箭头，以及指向不活跃成员和无人打开的仪表板与应用的**亮点**列表。**分组**将**概览**、**内容**和不活跃列表限定为某个安全组的成员，日期范围新增**上月**和**本月**，由所有选项卡共享，并会随您的账户记住。每个数字现在都有说明，表格使用**成员**和**区域**等通俗名称，按 Enter 可打开行，加载和错误提示更清晰，最后一个**漏斗**步骤显示有多少成员完成了它。新的 **Get Workspace Usage** 步骤按计划将每日或每月使用总量写入表中，不含成员姓名，每次运行都与 **Get Workspace Members** 一样记录在安全日志中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表并设置项目的默认仪表板受众。**`publish_manage` 会取消发布表及其已发布视图和任何没有图表使用的仪表板数据集；仍有图表使用的数据集会保留，当报表视图建立在已发布视图之上时，该视图和数据集也会保留，而表仍会被取消发布。`project_upsert` 设置 `dashboard_default_audience`，即项目中新仪表板所共享的分组，设为 `[]` 则清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Git 应用列出您的存储库，并告诉您可以做什么。** 应用列表中的 **Git** 显示您的角色（**Administrator**、**Contributor** 或 **Viewer**）和工作区的存储库，每个存储库带有说明、最后更新日期、带复制按钮的克隆地址以及**打开**。**Set up Git on your computer** 卡片会引导您完成安装 Git、创建令牌和克隆，**How to clone** 可重新打开它。**View all in Git** 打开完整的 Git 界面，**Manage who can push** 打开分组管理。访问级别为 **Viewer**、**Contributor**（将应用代码推送到 `apps`）或 **Administrator**（可推送到所有位置，包括 `udfs`），查看者最多可看到三位可联系的工作区管理员。新的 **Git Contributors** 分组授予 Contributor 权限，可设为默认分组，使新成员自动获得；**Git Administration** 授予 Admin 权限。成员的 **Git** 选项卡显示其 Git 用户名、级别以及授予该级别的分组。应用窗口显示**存储库**部分，UDF 带有**打开**，Git 中有返回您工作区的 **← Back to** 链接。请参阅 [PlaidCloud Git](/zh-cn/guides/git/#打开-git)。
- **移动端 Weave 的语音只需轻点一下。** 轻点麦克风，提出问题，停止说话后 Weave 会发送一次。再次轻点麦克风可提前结束，如果没有听到声音，它会自动关闭。如果在说话中途离开 **Weave** 选项卡或将应用切换到后台，您说的话会保留在问题框中而不发送，以便您查看。运行、暂停、停止和恢复会忽略对其确认按钮的意外双击。需要应用版本 1.3.0 或更高。请参阅[使用语音](/zh-cn/guides/mobile-app/weave-on-mobile/#使用语音)。

## 变更

- **步骤表单采用统一布局。** 选项卡按统一顺序使用标准名称：General、Settings、Source、Columns、Filters、Output 和 Advanced，ERP 过账表单另有 Header columns 和 Line columns。必填字段以 * 标记，表单只会因步骤所需内容而阻止保存。
- **复制项目可分别选择表数据和维度成员，复制数据更快，并保留私有副本的 ERP 写入授权。** 在 **Data to copy** 下，选择**表数据**——**无表数据**（默认）、**完整**或**样本**——并另外选择**复制维度成员**（默认开启），因此不含表行的副本仍带有已填充的维度，创建速度也很快。**完整**和**样本**复制会同时复制多张表，因此包含大量表的项目完成得更快。**复制结果**会将每个维度的结果与表一起列出，**Retry failed items** 会同时重试失败的表和维度。带数据创建的新副本对您是私有的，并保留源项目中您自己可以授予的 ERP 写入授权；如果源项目以 Live 过账，副本会以 Simulate 到达，因此在您将其切换为 Live 之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **行操作菜单（⋯）位于每个网格行的最左侧。**
- **应用选项卡图标统一为一套**，浅色和深色模式均适用。
- **未设置验证选项的已保存 ERP 写入步骤以仅验证方式打开。** 涵盖 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post 以及 Xero 导出。明确设置为实时运行的步骤保持实时。
- **长时间运行的作业在各处以相同方式显示进度。**
- **停止工作流会停止它启动的一切，无法完成的运行或步骤会失败而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中之后的导入和维度加载可正常开始，同时也会停止该工作流排队或正在运行的连接器（Singer）同步。如果步骤的作业无法启动，该步骤会连同原因一起失败，而不是永远等待：约 40 分钟内没有工作进程启动它、工作进程启动后又消失、其 pod 停滞在 Pending 约 20 分钟、其镜像约 5 分钟无法拉取，或约 20 分钟内没有创建 pod。约 30 分钟内没有运行器接手的连接器同步会失败，并给出指明该同步的消息。步骤在等待工作进程时，其状态消息显示“Waiting for a worker…”及已等待的分钟数，工作开始后消失。停止宏会停止其所有正在运行的副本，仅在其他工作流内部运行的宏在工作流列表中显示为**正在运行**，并提供**停止**，同时显示每个步骤最近一次运行的状态、开始时间和结束时间。服务器丢失的运行会以失败结束，运行超过 12 小时仍未结束的会失败，并显示“Run failed: still running at the 12-hour limit. Re-run the workflow.”请参阅[运行工作流](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
- **恢复、运行历史和运行状态与实际运行的内容一致。** 恢复父工作流时，会运行子工作流剩余的所有内容，即使您之前单独重新运行过该子工作流的某个步骤也是如此；一次运行中对子工作流的每次调用都有各自的运行历史条目。因服务器停止而重新启动的步骤会在其日志中说明，`workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续运行的步骤，而不是将该运行报告为正常。请参阅[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)和[出错时继续](/zh-cn/guides/workflows/continue-on-error/)。
- **步骤错误显示其自身的消息。** PlaidCloud 未预料到的错误显示为“The step stopped on an unexpected error (*type*): *message*”。启动台上的**需要关注**卡片用一行显示错误，并省略已被删除的工作流的运行。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。
- **未完成的 ERP 提取会使其步骤失败，恢复后可继续。** 当 **SAP：临时提取**在其行数或时间限制处暂停，或其代理未及时回复，或者 Salesforce、Oracle Fusion 批量或 HFM/FCCS 导出作业在步骤停止等待时仍在运行，该步骤会失败，使其后的步骤不会在不完整的表上运行。恢复工作流或重新运行该步骤，提取会从停止处继续，沿用同一个作业。请参阅[运行限制](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制)和 [Salesforce：查询对象](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **项目架构师可在仪表板中看到行受限表的所有行**，与他们在 Analyze 中看到的一致。收回架构师访问权限会在仪表板中立即生效——无论您是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、还原较早的项目版本，还是删除安全组。前架构师不再看到行受限数据的每一行。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
- **会话过期后打开的仪表板链接，会在您登录后带您进入该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝其不认识的字段**并在错误中指出该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为其另一个名称。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据使用该账户自身的凭据直接写入账户的存储桶，而不是让每一行先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式不变。请参阅[导出到 Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会指出它尝试连接的服务器，对 Slack 和 Teams 还会指出连接，并说明出了什么问题：例如 Slack 不再识别该 webhook、无法向该频道发帖、找不到服务器或服务器在 60 秒内没有响应，或者连接已被删除。Slack 或 Teams 的 webhook URL 绝不会显示，因为任何持有它的人都可以冒充您的集成发帖。请参阅 [Notify via Slack](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。

## 修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的 slug，或无效的存储类型或过账模式，现在会返回指明问题的消息，而不是通用的服务器错误。通过 REST API 时为 400 而不是 500，通过 AI 助手或 MCP 时为无效参数错误。
- **REST API 的维度值请求现已可用。**`POST /rest/v1/analyze/query/retrieve-dimension-values` 过去被当作网格请求处理并被拒绝为无效。现在它会为 `value_columns` 中的每一列返回一个聚合值，而网格（即每对行筛选器和列筛选器对应一个值）有了自己的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再阻塞其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，过去都可能使同一服务器正在处理的所有其他请求暂停，直到其完成。现在它们与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口更高，因此**创建**和**更新**按钮可能够不到。现在表单可以滚动，按钮保持在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 这些操作过去对该大小的文件都会失败，移动或重命名包含此类文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚写入的内容。** 写入表的步骤或导入可能记录的是写入之前的行数，因此刚加载的表显示 0 行，导入可能报告导入了 0 行。现在行数会在新行在各处都可见之后才读取，因此其后的步骤也能读取到它们。将表切换到另一个分支，或将分支合并到表中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的内容比较。** 步骤的空值经常是在步骤清空其表以重新填充之后才被统计的，因此其之前的运行看起来没有空值，而一直部分为空的列被报告得好像刚刚变成这样。现在每次运行都按步骤留下的表来统计。之前记录的计数无法与正确的计数区分，因此不予使用：每个步骤的空值检查会重新开始其历史，并在统计满五次运行之前报告为未检查。行数和值分布检查也不再把另一个步骤在其完成后两秒以上对同一张表所做的写入记在某个步骤名下。请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **向 REST API 请求已删除的连接时返回 404。** 请求已被删除的连接或不存在的 ID 时，过去返回通用的服务器错误（500）。现在返回 404，并附带指明连接 ID 的消息。

## 安全

- **保存行访问时会保留其来源中已不存在的已授予值。** 分组被授予的值，过去在表中已没有带该值的行、维度失去该成员或列表不再包含该值之后，会在下次保存时从授权中丢失。没有任何勾选的分组随后会回退到 **Everyone else**，这可能意味着看到所有行。现在该值会保留在网格中并带有标记，**保存**会询问是保留还是移除。请参阅[行访问网格](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
- **只有账户的所有者可以还原其较早的版本。** 将文档账户还原到较早版本、保留或释放某个版本以及进行备份，现在都要求您是该账户的所有者，且系统管理的账户上这些操作均不可用。查看账户的版本历史需要拥有该账户的访问权限。
- **只应读取数据的查询不能再更改数据。** AI 助手和 MCP 客户端使用的 `query_run` 工具只运行读取数据的语句——一条 SELECT 或 WITH 语句、对其执行的 EXPLAIN，或 SHOW——并会拒绝其他任何语句而不运行。要更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 遵循同样的规则。通过 REST 和 JSON-RPC API 时，对于无权更改项目数据的成员，该规则同样适用于运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库，以及使用您自己的查询导出表数据；被拒绝的查询返回 403。Explain Analyze 会运行查询以进行度量，因此在查询日志和 Lakehouse 中，它现在只接受读取数据的查询，并且在有行访问的项目上，只有项目架构师可以从查询日志中运行它。
- **向行受限表写入 DataFrame、保存记录和清除，只更改您能看到的行。** 当行访问限制了您的行时，使用 Python 客户端将 DataFrame 写入受限表或清除它，或通过 REST API 向其保存记录或清除它，只会更改您自己的行；包含超出您访问范围的行的加载会在任何更改发生之前被拒绝，并列出所发现的值。项目架构师、能看到每一行的成员以及工作流运行照常写入整张表。个人对任何表所做的这类写入，现在都会记录在安全日志中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
