## 新增

- **控制平面中的信任中心为安全团队提供 PlaidCloud 的安全文档。** 管理员和安全用户可打开所在组织的**Trust Center**，立即下载子处理方列表和 DPA 等公开文档，并为组织一次性签署安全文档 NDA，以解锁 SOC 2 Type II 报告等受限文档。其他管理员和安全用户可以看到签署人和签署时间。合同中已包含 NDA 的组织可以将其标记为已备案，这样无需签署即可解锁文档。受限文档的下载带有水印并会被记录，NDA 发布新版本后需要重新接受。管理员和安全用户还可以按组织选择订阅每日电子邮件，汇总新增或更新的文档以及新版本的 NDA；邮件中绝不包含文档本身。请参阅[信任中心](/zh-cn/administration/control-plane/trust-center/)。
- **PlaidXL 可在 Excel 中构建、钻取、解释和规划。** **PlaidCloud**功能区选项卡分为**连接**、**插入**、**刷新**、**Drill**、**写入**和**共享**，常用命令还位于**PlaidXL**右键菜单和**PlaidXL Cell**选项卡中，主要命令带有可更改的键盘快捷键，在字段中输入时不会触发。命令失败时会说明是哪个命令以及原因。在登录前运行的命令会先打开登录窗口，登录后自动运行；一次登录对应一个工作区，因此切换工作区时会要求登录新工作区（切换回来则不需要）；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次点击即可构建报表。** **报表**选项卡根据表生成实时报表，一个维度逐级下钻显示在行上，另一个显示在列上，每个交叉点都有一个 `CELL` 值。**Build my first report**会用您自己的数据生成示例。钻取时，报表会插入和删除整行整列，您输入的值、备注和格式会随所在行保留。请参阅[构建报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only**和**Remove only**可将节点变为实时的 `DRILL` 公式并为您编辑，适用于节点、维度标题或报表值。**Custom drill**会在插入前预览行，成员选择器可插入成员，或为单元格添加节点子级的下拉列表。`DRILL` 可指定要排除或展开的节点，并能跨行运行。请参阅[钻取、选择成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释数字。** **Explain this number**显示值的计算方式、是否与 PlaidCloud 当前一致，以及它来自的表和工作流步骤。**Show detail rows**会将值背后的行放在单独的工作表中，并检查它们是否相加一致。
  - **在 Excel 中使用受管指标。** `PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 返回与仪表板中显示一致的业务指标；没有可聚合内容的 `CELL` 或 `CELLS`，对于求和显示 `0`，其他情况显示 `#VALUE!` 并附原因（`CELLS` 溢出区域中为空白）；**Metric...** 会列出项目的指标及其当前值。一个指标可以按多个备用层次结构筛选，也可以将备用层次结构的成员与其他维度的成员混合使用。请参阅[指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中直接输入进行规划。** 在 `CELL` 值上输入数字，即可将其写入 PlaidCloud：可按比例分摊、平均分摊或按另一个成员的分布形状分摊，可按金额或百分比调整，已冻结的单元格保持不变。平均值、中位数、最小值、最大值、标准差和方差单元格同样接受输入值，输入值会在插入或删除行列时跟随其单元格（已删除单元格中的值会被报告）。**Undo last write**按从新到旧的顺序撤消输入的值和保存，只有执行写入的人员和工作区才能撤消。撤消求和，或撤消在空单元格中输入的平均值时，会保留此后写入同一批单元格的内容；写入未完成即被中断时无法撤消。请参阅[向 PlaidCloud 输入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新所需内容。** 可刷新一个工作表、一个选区或所有表，任务窗格中会显示每个表的进度和**取消**，也可以只重新计算 PlaidXL 公式。检索到的表以 Excel 表的形式到达并按数据类型设置格式，刷新时保留您自己的列和数字格式，并在原位置刷新。检索或刷新绝不会覆盖其他单元格，也不会与其他 Excel 表重叠；超出 Excel 范围的整数 ID 和 1900 年之前的日期会以文本形式到达。再次检索同一个表不会将其重复加入刷新列表，**Stop refreshing**可将其移除，维度会随表一起刷新。请参阅[刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#refresh-all-tables)。
  - **保存立即写入，并且可以撤消。** **Save to PlaidCloud**无需确认即写入，会说明执行了什么，并提供**撤消**，对 Lakehouse 表而言，每次保存后最长 7 天内可用。使用筛选器检索的工作表、明细行工作表，或访问权限仅覆盖部分行的人员，只会替换那些行，因此其他人的行会保留。自检索后成员已更改的下钻工作表不会保存，保存失败时会指明还原点，以便将表恢复原状。请参阅[将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在**Weave**选项卡上，可以用日常语言要求生成报表、公式、钻取或表，也可以选择**Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只更改工作簿，替换您已输入的内容前会先询问，绝不会写入指向工作簿之外的公式，并且每项更改在您重新加载窗格之前都可以还原。请参阅[在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享整个工作簿或某个工作表的纯值副本。** **Convert to values**可转换整个工作簿、一个工作表，或转换为无法恢复的值（会先询问），只更改 PlaidXL 公式及其溢出区域，仍在计算的公式会保留以便再次尝试，并且在您重命名工作表后，**Restore PlaidXL formulas**仍然有效。
- **过账登记簿会在打开时显示需要您处理的内容。** 有事项需要查看时打开**异常**，有请求等待您处理时打开**审批**，否则打开**所有过账**。侧栏将各屏幕分为**需要我处理**、**登记簿**、**洞察**和**设置**，并在**异常**和**审批**上显示数量，每个屏幕共用同一个标题和范围栏：选择期间（**This month**、**上个月**、**最近 7 天**、**最近 30 天**或**自定义**）、连接、项目、环境或实体，以及**实时**、**模拟**或**全部**，然后**重置**或保留**Saved scope**。系统会记住您上次的范围。
  - **异常会整理出需要查看的内容。** **Needs a look**、**未确认**、**待处理**、**失败**和**Reversal outstanding**标签会显示各自的数量，连接健康状况行显示“所有 N 个连接过账正常”，每笔过账都有通俗易懂的状态，并通过提示说明下一步该做什么。没有未处理事项时显示**All clear**。将分类账 ID 粘贴到**Find a posting by ledger id**或命令面板中，可直接打开该过账。
  - **审批、委托和关注是收件箱式屏幕。** 可在**Waiting on me**和**Submitted by me**之间切换，填写理由后**批准**或**拒绝**，可一次批准多项，并可通过提示条**撤消**批准。**Delegate approvals**是一个简短的对话框，**我的关注**列出您关注的内容。**冲销过账**以及批量重试和清除对话框共用同一布局。
  - **过账抽屉会说明发生了什么。** 它显示状态及其含义、按名称列出的关键事实，以及**Lines**、**历史记录**和**签核**选项卡，并提供**标记为已审核**、**重试**、**冲销…**、**关注连接**、**关注运行**和**Copy link**（直接打开该过账）。
  - **辅助、导出和保留遵循相同的设计。** **辅助**包含提问框和洞察卡片、标记为**Draft — nothing applied**的建议，以及**所有过账**上带有**显示这些**的异常卡片。**导出和警报**包含**New schedule**，**保留**是一张卡片。
  - **登记簿保持最新。** 侧栏徽章随过账变化而更新，过账发生变化时已打开的列表会提供**刷新**，已打开的抽屉会原地更新。**主页**在**需要关注**下显示**过账登记簿**卡片。请参阅[查看过账登记簿](/zh-cn/guides/connections/posting-register/)。
- **项目主页有六个页面。** 纯文本侧栏列出**概览**、**变量**、**计划与传感器**、**访问与共享**、**数据与连接**和**应用与品牌设置**，并以徽章显示变量数量以及活动计划和传感器的数量。**概览**显示项目的描述和标签、锁定状态，表、工作流、步骤、变量、已发布表和**数据大小**（打开**存储**；与**项目**屏幕显示的合计相同，包含为还原而保留的早期版本，工具提示会将当前数据与早期版本分开显示）的磁贴，接下来三次计划运行以及项目默认设置，并提供 PDF 或交互式 HTML 格式的**项目报表**和**导出归档**。其他页面管理变量、计划和传感器（带有**Calendar view**以及**Activate**或**Deactivate**）、谁可以打开项目及其仪表板以及哪些项目可以读取其表、连接和表存储默认设置（含 ERP 过账模式），以及 Panel 应用、品牌和项目的磁贴图像。已锁定的项目会显示横幅并禁用其控件。请参阅[项目主页](/zh-cn/guides/projects/project-home/)。
- **文档以概览页打开，并带有页面侧栏。** 侧栏中包含**概览**、**浏览**、**您的账户**和**管理**，页面有标题（通常带有副标题），其操作位于页眉中。**概览**显示您的账户、会打开**浏览**并定位到其所在文件夹且选中该文件的**Pinned**文件、按服务分组的账户以及谁可以使用它们的磁贴。**您的账户**是一个列表，列出您可以使用的所有账户，每行带有**已共享**或**私有**标签。**管理**列出您拥有的账户，工作区管理员在此可以看到所有文档账户，并可以管理其他情况下有权管理的任何账户（系统管理的账户会被拒绝，托管存储桶账户无法克隆）。行的 **⋯** 菜单包含**打开**、**编辑**、**克隆…**、**Who can use it**、**使用位置…**、**Version history**、**启用**或**Disable**以及**删除**。账户以页面形式打开，包含**常规**、**访问**、**Credentials**卡片，SFTP 账户还有**SSH**卡片，存在未保存的更改时离开前会先询问。**浏览**会打开您收藏的账户或工作区的默认账户，带有带标签的工具栏、行菜单、拖放上传（拖放到文件列表或文件夹上即可上传到该处，拖放到树的空白处则上传到账户根目录）以及**Uploads and imports**面板，该面板显示每次上传和导入到表的进度和操作。**弹出**会在新的浏览器选项卡中打开文件夹。请参阅[文档](/zh-cn/guides/documents/)和[使用文档账户](/zh-cn/guides/documents/using-document/)。
- **仪表板以概览页打开，并带有页面侧栏。** 侧栏中包含**概览**、**仪表板**、**应用**、**Notebooks**，工作区管理员还有**访问审核**，底部是**打开导航器 ↗**，带箭头标记是因为它会在自己的窗口中打开。页面有标题（通常带有副标题），其操作位于页眉中。**概览**显示仪表板和应用的磁贴（打开时已筛选出相应列表）、您最近打开或加星标的内容、失败的应用和等待您处理的访问请求，并为有使用情况访问权限的成员显示打开次数最多的仪表板。**仪表板**可按**全部**、**You manage**和**收藏**筛选，**应用**显示每个应用的**类型**和实时状态。请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **身份以概览页打开，并带有页面侧栏。** 侧栏依次列出**概览**、**成员**、**目录**、**安全组**和**分发列表**，然后是**会话**、**安全日志**、**API 客户端**、**Group audit**和**All scopes**。页面有标题（通常带有副标题），其操作位于页眉中。**概览**显示成员、活动成员和从未登录的成员、构建者席位以及当前在线人员的磁贴，**活动成员**图表，带有**重新发送欢迎电子邮件**和**审核**的**需要关注**，以及最近 7 天的安全事件。成员以页面形式打开，包含**配置文件**、**访问**和**Groups and data**卡片，**Invite member**可从概览和主页的首次运行卡片中使用。请参阅[成员管理](/zh-cn/administration/access/member-management/)。
- **列表可以显示为标准行、宽松行或卡片。** **仪表板**、**应用**、ERP 登记簿和身份**成员**等列表工具栏中的**视图**菜单可让您在它们之间选择。卡片保留列表的全部功能：选择、排序、列、右键单击**复制**，以及在列表带有收藏时的收藏星标。**仪表板**卡片显示缩略图。请参阅[标准、宽松和卡片视图](/zh-cn/guides/dashboards/using-dashboards/#标准宽松和卡片视图)。
- **Lakehouse 窗口新增侧栏、表详细信息和时间旅行。** **查询**、**性能分析**、**加载**和**目录**位于侧栏中，**管理**下有**Lakehouse 目录**、**数据库用户**和**计算**。**数据库用户**和**计算**仅向拥有 Lakehouse 管理员或 Lakehouse 集群角色的成员显示。**查询**可按 SQL 文本、用户、类型和持续时间筛选历史记录，使用**Copy SQL**复制语句，并使用**Profile this query**在**性能分析**中打开查询。**目录**可打开表的列、当前快照、分区、位置、属性和快照历史记录，**Copy query as of this snapshot**会复制一条 `FOR VERSION AS OF` 查询，按表在该快照时的状态读取它。请参阅[Lakehouse 窗口](/zh-cn/guides/data/lakehouse-window/)。
- **步骤表单上的预览。** 导入：SQL、Execute: SQL、Extract: SQL、导出：SQL 和 Salesforce Query 无需运行步骤即可显示最多 100 行，Anaplan 视图和列表读取会显示它们将生成的列和类型。点击**源**选项卡上的**预览**。变量会按运行时的方式填充，但不支持 `{x:>9}` 之类的变量格式。预览只运行标准 SQL 函数，否则会提示您运行步骤。在已锁定的项目中，或对于基于代理的 Execute SQL 步骤，预览不可用。请参阅[导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/)和[提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告在身份内打开、显示变化、可缩小到某个分组，并可接入工作流。** 身份导航栏中**洞察**下的**使用情况报告**会作为导航栏旁的页面打开，而不是单独的窗口，包含**概览**、**活动**、**路径**、**成员**、**内容**、**导出**和**漏斗**选项卡。**概览**新增相对上一期间的趋势箭头和**Highlights**列表，指出不活跃的成员以及无人打开的仪表板和应用。已停用的成员不计入，也不会列为不活跃。**分组**将**概览**、**内容**和不活跃列表限定为某个安全组的成员，日期范围新增**Previous month**和**This month**，由所有选项卡共用并记在您的账户中。现在每个数字都有说明，表使用**成员**和**Area**之类通俗易懂的名称，按 Enter 键可打开行，加载和错误提示更清晰，**漏斗**的最后一步显示有多少成员完成了该步骤。**Get Workspace Usage**步骤会按计划将使用情况写入表，可以是不含成员姓名的每日或每月合计，也可以是可直接用于报告的数据集：**成员**、**Daily per member**、**内容**和**Content per member**。成员数据集包含姓名、电子邮件、分组和活动，因此可以按电子邮件将其与您自己的组织表联接，并按部门报告活跃分钟数或仪表板打开次数。与**Get Workspace Members**步骤一样，每次运行都会记录在安全日志中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以分析表。** 通过 MCP，`table_profile` 会返回表资源管理器显示的列统计信息和数据质量雷达检查，以及每一列最常见的值，一次最多 50 列，且仅限您可以查看的行。请参阅[从 AI 助手读取分析结果](/zh-cn/guides/data/table-explorer/#从-ai-助手读取分析结果)。
- **AI 助手可以取消发布表，并设置项目的默认仪表板受众。** `publish_manage` 会取消发布表及其已发布视图和没有图表使用的仪表板数据集；仍有图表使用的数据集会保留，当报表视图构建在已发布视图之上时，该视图和数据集也会保留，但表仍会被取消发布。`project_upsert` 设置 `dashboard_default_audience`，即项目中新仪表板共享给的分组，`[]` 表示清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

## 变更

- **如果您的工作区使用 Grok，Weave 移动端会再次要求您同意其 AI 声明。** 该声明不再说 xAI 不会使用您的数据训练其模型，而是说明 PlaidCloud 与 xAI 之间没有零数据留存协议，因此 xAI 可能会保留这些数据，并在其标准条款允许的范围内使用。请参阅 [Weave 如何使用您的数据](/zh-cn/guides/ai-assistant/weave-data-use/)。
- **“假设分析”窗口一次读取一个期间。** 当 Allocation Split 步骤的输出具有期间列时，窗口会打开到最新期间，您可以通过**期间：** 选择其他期间或**所有期间**。如果某个步骤的驱动因素为每个期间都有一行，以致无法跨所有期间读取，现在也能打开，并针对单个期间给出结果。已保存的方案会保留其保存时所用的期间（如果有），打开它时，只要该期间仍在列表中，窗口就会切换到该期间。请参阅[选择期间](/zh-cn/guides/allocations/results/driver-what-if/#选择期间)。
- **PlaidCloud 的 Web 应用和 Python 客户端库使用 REST API，JSON-RPC 已弃用。** Web 应用将其请求发送到 REST API。使用 `plaidcloud-rpc` 1.25.0 或更高版本时，`SimpleRPC` 调用会转到 REST API，您的代码无需更改；REST API 尚未涵盖的调用，或仍在较旧版本上的工作区，会照常使用 JSON-RPC。JSON-RPC 将在以后的版本中移除，因此请将脚本和笔记本升级到 `plaidcloud-rpc` 1.25.0 或更高版本，并针对 REST API 编写新的集成。请参阅[命令行](/zh-cn/reference/cli/jupyter/command-line/)。
- **步骤遵循其项目的连接环境，除非您将其固定到其他环境。** 在 QA 和 Production 等环境之间切换项目时，所有步骤都会随之切换。必须保持在某个环境的步骤可以改为设置**Fixed environment**：表单会以警告标记它，其日志会注明每次在项目环境之外的环境上运行，切换项目时会指出不会跟随的步骤。ERP 过账步骤始终使用项目的环境。只要有项目、固定步骤或代理在使用某个环境，就无法删除它，代理表单中的字段现在是**Environment this agent serves**。请参阅[将步骤固定到某个环境](/zh-cn/guides/projects/managing-projects/#将步骤固定到单一环境)。
- **步骤表单遵循统一的布局。** 选项卡采用标准名称和标准顺序：常规、设置、源、列、筛选器、输出和高级，ERP 过账表单还有表头列和行项目列。必填字段以 * 标记，表单只会因步骤所需的内容而阻止保存。
- **复制项目会分别选择表数据和维度成员，复制数据更快，并为私有副本保留 ERP 写入授权。** 在**Data to copy**下，选择**表数据**——**No table data**（默认）、**完整**或**样本**——并单独选择**Copy dimension members**（默认开启），这样不含表行的副本仍会带有已填充的维度，并且创建很快。**完整**和**样本**复制会同时复制多张表，因此包含大量表的项目完成得更快。**复制结果**会将每个维度的结果与表一起列出，**Retry failed items**会同时重试失败的表和维度。带数据创建的新副本仅您自己可见，并保留源项目中您自己有权授予的 ERP 写入授权；如果源项目以 Live 方式过账，副本会以 Simulate 方式到达，因此在您将其切换为 Live 之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **表的详细信息面板更快显示使用该表的步骤。** 选择另一张表时，会立即清除上一张表的步骤，与本项目共享数据的其他项目中的步骤会在其余内容之后稍候添加，而不是让整个面板等待。请参阅[查看表的使用位置](/zh-cn/guides/projects/managing-tables-and-views/#查看表的使用位置)。

- **长时间运行的作业在各处以相同的方式显示进度。**
- **工作流如实地停止、失败和报告。** 停止工作流会停止它启动的所有内容，无法完成的运行或步骤会带着原因失败而不是挂起，运行状态与实际运行的内容一致。
  - **停止工作流会停止它启动的所有内容，无法完成的运行或步骤会失败而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中后续的导入和维度加载可以正常启动，同时也会停止该工作流排队或正在运行的连接器（Singer）同步。如果步骤的作业无法启动，该步骤会带着原因失败而不是永远等待：约 40 分钟内没有工作进程启动它、工作进程启动后消失、其 Pod 卡在 Pending 约 20 分钟、无法拉取其镜像约 5 分钟，或约 20 分钟内没有创建 Pod。约 30 分钟内没有运行器接手的连接器同步会失败，并显示指明该同步的消息。步骤等待工作进程期间，其状态消息显示“正在等待工作进程…”及已等待的分钟数，工作开始后即清除。停止宏会停止它所有正在运行的副本，而停止其中一个副本，或**Macro Concurrent**步骤放弃一个停止响应的副本，会让调用它的工作流继续运行。仅在其他工作流内运行的宏在工作流列表中显示为**正在运行**，可使用**停止**，并显示每个步骤最近一次运行的状态、开始和结束时间。服务器丢失的运行会以失败结束，运行超过 12 小时的运行会失败，并显示“运行失败：仍在运行，已达到 12 小时限制。请重新运行工作流。”请参阅[运行工作流](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
  - **恢复、运行历史和运行状态与实际运行的内容一致。** 恢复父工作流会运行子工作流剩下的所有内容，即使您之前单独重新运行了子工作流的某个步骤也是如此，同一次运行中对子工作流的每次调用都有各自的运行历史记录。因服务器停止而重新启动的步骤会在其日志中说明，`workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续运行的步骤，而不是报告该运行没有问题。请参阅[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)和[出错时继续](/zh-cn/guides/workflows/continue-on-error/)。
  - **步骤错误会显示其自身的消息。** PlaidCloud 未预料到的错误显示为“步骤因意外错误（*类型*）而停止：*消息*”。启动器上的**需要关注**卡片以一行显示错误，并忽略此后已被删除的工作流的运行。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。
  - **未完成的 ERP 提取会使其步骤失败，恢复后可继续。** 当**SAP：临时提取**在其行数或时间限制处暂停，或其代理未及时回复，或者在步骤停止等待时 Salesforce、Oracle Fusion 批量或 HFM/FCCS 导出作业仍在运行，该步骤会失败，这样其后的步骤就不会基于不完整的表运行。恢复工作流或重新运行该步骤，提取会在同一作业上从停止处继续。请参阅[运行限制](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制)和 [Salesforce：查询对象](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
  - **取消导出会停止其在仓库中的查询。** 取消导出或下载（包括通过停止其工作流取消）时，在 Lakehouse v2、Snowflake、Databricks、PostgreSQL 和 Greenplum 上，读取其数据的查询也会停止，而导出到远程数据库会停止读取其源，而不是一直运行到结束。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **会话过期后打开的仪表板链接，在您登录后会带您到该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝无法识别的字段**并在错误中指明该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为其另一个名称。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据会使用该账户自己的凭据直接写入账户的存储桶，而不是让每一行都先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式与以前相同。请参阅[导出到 Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会指明它试图访问的服务器，对于 Slack 和 Teams 还会指明连接，并说明出了什么问题：例如 Slack 不再识别该 webhook、无法向该频道发帖、找不到服务器或服务器在 60 秒内没有响应，或者连接已被删除。Slack 或 Teams 的 webhook URL 绝不会显示，因为任何拥有它的人都可以冒充您的集成发帖。请参阅 [Notify via Slack](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。
- **项目服务账户的访问令牌至少有效 24 小时。** 以项目身份运行的工作流作业（例如 UDF 步骤）获得的令牌有效期为 24 小时。较短的有效期会在工作区升级时提高，您设置的更长有效期会保留。
- **工作区的组织、所有者、发布渠道和版本由 PlaidCloud 设置，您可以选择其数据中心。** 在控制平面中，您创建的工作区归您所有，并放置在 PlaidCloud 设置的发布渠道上，您可以从注册时提供的区域中选择其**Data Center**。编辑工作区时，组织、所有者、发布渠道和版本为只读。使用**Set Version**更改版本，如需迁移工作区、更改其所有者或渠道，或将其固定，请联系 PlaidCloud 支持。请参阅[工作区配置](/zh-cn/administration/control-plane/workspace-configuration/#主要设置)。
- **编码转换步骤可以保留文件夹的子文件夹。** **文档：将文件转换为 ASCII 编码**、**文档：将文件转换为 Unicode (UTF-8) 编码**和**文档：将文件转换为 Unicode (UTF-16) 编码**都有一个**保留子文件夹**复选框。勾选后，输入文件夹子文件夹中的每个文件会写入目标位置中对应的子文件夹；压缩文件的内容会进入该压缩文件所在的子文件夹。不勾选时，每个文件都像以前一样直接写入目标位置本身。请参阅 [Convert Document Encoding to UTF-16 步骤](/zh-cn/reference/workflow-steps/document/convert-document-encoding-to-utf-16/)。

## 已修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的 slug，或无效的存储类型或过账模式，现在会返回指明问题的消息，而不是通用的服务器错误。通过 REST API 返回 400 而不是 500，通过 AI 助手或 MCP 返回无效参数错误。
- **REST API 的维度值请求现在可用。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 曾被当作网格请求处理并被拒绝为无效。现在它为 `value_columns` 中的每一列返回一个聚合值，而网格（每对行筛选器和列筛选器对应一个值）有自己的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再阻塞其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，过去都可能让同一服务器正在处理的所有其他请求暂停，直到其完成。现在它们与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框高于窗口，因此**创建**和**更新**按钮可能无法点到。现在表单会滚动，按钮保持在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 这些操作过去对该大小的文件都会失败，移动或重命名包含此类文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚写入的内容。** 写入表的步骤或导入可能记录的是写入之前的行数，因此刚加载的表显示 0 行，导入可能报告导入了 0 行。现在会在新行在所有位置都可见之后再读取行数，因此其后的步骤也能读取到它们。将表切换到另一个分支，或将分支合并到表中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的内容进行比较。** 步骤的空值经常是在步骤清空其表以重新填充之后才被统计，因此其之前的运行看起来没有空值，而一直部分为空的列会被报告为刚刚变成这样。现在每次运行都按步骤留下表时的状态统计。之前记录的计数无法与正确的计数区分，因此不予使用：每个步骤的空值检查会重新开始其历史，在统计满五次运行之前报告为未检查。行数和值分布检查也不再把另一个步骤在其完成两秒之后对同一张表所做的写入记在该步骤名下。请参阅 [Weave 检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **Data Foundation 保留反转汇率和小数阈值的精度。** PlaidCloud 因您的汇率是从报告货币报价到另一种货币而反转的汇率，过去可能被四舍五入到六位小数，这会使汇率很小的货币（例如印度尼西亚盾）的金额偏差约 1%。现在反转汇率保留 12 位小数。带小数的 `group_amber` 或 `group_red` 阈值（例如 `0.5`）过去被四舍五入为整数。您的下一次加载将使用精确值。请参阅[汇率](/zh-cn/guides/projects/data-foundation/#汇率)。
- **已停用成员的警报和摘要会停止。** 所有者已被停用的 Panel 应用警报或摘要过去仍会继续检查和发送。现在在其被停用期间会暂停，重新激活后恢复。请参阅[警报和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
- **向 REST API 请求已删除的连接会返回 404。** 请求已被删除的连接或不存在的 ID，过去会返回通用服务器错误（500）。现在返回 404，并附带指明连接 ID 的消息。
- **通过 AI 助手和 MCP 的模板化表导出可用。** `table_data_export` 的 `templated` 格式在传入表时总是失败。现在它会通过您的模板导出表，并限于您可读取的行。在模板中，表的行以其表 ID 命名，其中每个 `-` 写作 `_`。
- **Amazon S3 和 S3 兼容的文档账户会保留其区域。** 保存这类账户时会丢弃您输入的**区域**，因此下次打开账户时该字段为空。现在区域会被保存。对于在此修复之前保存的账户，请重新输入区域并保存。请参阅[添加 AWS S3 账户](/zh-cn/guides/documents/adding-accounts/add-aws-s3-account/)。
- **转换文件夹的编码时，不再让一个文件覆盖另一个同名文件。** 两个文件的目标位置相同——例如来自不同子文件夹的两个同名文件——过去只会留下最后写入的那个。现在步骤会在写入第二个文件之前停止，指明这两个文件及其将要写入的位置，并在勾选**保留子文件夹**可将它们分开时予以说明。
- **在“文档：将文件转换为 ASCII 编码”中清除“将目标编码无法表示的字符替换为 ?”现在会生效。** 保存时勾选了**将目标编码无法表示的字符替换为 ?** 的步骤，在取消勾选并再次保存后仍保持勾选。现在取消勾选会关闭替换。
- **AI 助手和 JSON-RPC 不再指明使用您的角色所隐藏表的步骤。** 询问此类表的使用位置时，它们曾指明您的角色可以看到的、读取或写入该表的每个步骤，及其设置和工作流。现在它们只会说明有步骤使用该表而不指明是哪些步骤，与项目的表引用一致。请参阅[您的角色隐藏的内容](/zh-cn/guides/ai-assistant/weave-tab/#您的角色隐藏的内容)。
- **您选择的默认 AI 连接会一直保持为默认。** 将某个 AI 连接标记为工作区默认连接时，看起来操作成功了，但从未真正保存，因此依赖默认连接的代理和步骤仍然使用最近更新的那个连接。现在您的选择会被保存。请参阅 [LLM 提供商](/zh-cn/integrations/ai-architecture/llm-providers/#连接包含的内容)。
- **在 Weave 历史记录中右键单击对话时，不再会在“删除对话线程”上方打开“重命名”。** **重命名** 现在位于聊天的选项卡上：请右键单击该选项卡，此前右键单击它不会显示任何选项。请参阅 [Weave 选项卡中的选项卡](/zh-cn/guides/ai-assistant/weave-tab/#weave-选项卡中的选项卡)。
- **备注留空不再导致保存失败。** 在 **备注** 框留空的情况下创建或保存项目、维度、表、仓库、编辑器、计划的工作流事件或分发列表时，会因“Memo: Input should be a valid string”而失败。现在可以接受空备注。

## 安全

- **Weave 不再在每次对话开始时将您的姓名和电子邮件地址发送给其 AI 提供商。** 它从来没有用过这些信息。
- **密码登录需要验证器应用，并且密码更强。** 使用 PlaidCloud 密码登录的成员会在下次登录时被要求设置验证器应用，此后每次都需输入其验证码。单点登录、Google、Microsoft 和 GitHub 登录、API 令牌和服务账户不变。新密码至少需要 12 个字符，不能是您的用户名或最近六个密码之一，多次登录失败后账户会被短暂锁定。您的工作区已有的更严格规则会保留。请参阅[成员身份验证](/zh-cn/administration/access/member-authentication/)。
- **连接指向公共和专用网络地址。** 连接不能指向环回地址、链路本地地址或云元数据地址，错误会指明主机及其解析到的地址。您专用网络上的地址不受影响。请参阅[连接无法访问的地址](/zh-cn/guides/connections/create-connection/#连接无法访问的地址)。
- **已保存的连接凭据仅向可以编辑连接或工作流的成员显示。** 通过 REST API 和 MCP，已保存连接的密码、令牌和密钥会对其他成员进行掩码，他们仍可以打开和浏览该连接。请参阅[谁能看到连接的凭据](/zh-cn/guides/connections/create-connection/#谁能看到连接的凭据)。
- **应用构建在运行时无法访问您工作区的 Git 凭据。**
- **代理的私钥仅向可以编辑代理的成员显示。** 通过 REST API 和 MCP，该密钥不再出现在代理列表或详细信息中，代理表单仅向可以编辑代理的成员显示**私钥**和**查看 RPC 配置**。服务账户、项目和代理令牌以及 AI 委托的令牌无法检索密钥或 RPC 配置。正在运行的代理不受影响，公钥仍会显示。请参阅[获取代理凭据](/zh-cn/reference/cli/plaidlink/agents/#获取代理凭据)。
- **代理下载链接有效期为一小时。** 启用**Use PlaidCloud Proxy Download**后，链接过期时请重新打开下载以获取新链接。请参阅[服务](/zh-cn/administration/control-plane/workspace-configuration/#服务)。
- **将人员添加到安全组遵循您所拥有的权限。** 当您拥有某个安全组授予的所有权限时，才能将成员添加到该安全组、选择成员的分组或邀请架构师。工作区管理员不受限制。请参阅[管理安全组](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理安全组)。
- **连接的所有者或工作区管理员可以更改其设置并将其开启或关闭。** 通过 REST API、JSON-RPC 和 AI 助手或 MCP 更改连接设置，需要其所有者之一，或对于没有所有者的连接需要工作区管理员。启用、停用、锁定和解锁连接需要所有者或工作区管理员，指定多个连接的请求只有在您可以更改所有这些连接时才会生效。只有工作区管理员可以选择工作区的默认 AI 连接，并且仅当不存在由管理员拥有或没有所有者的连接可作为默认连接时，成员拥有的连接才会成为默认连接。请参阅[编辑连接](/zh-cn/guides/connections/create-connection/#编辑连接)和 [LLM 提供商](/zh-cn/integrations/ai-architecture/llm-providers/#连接包含的内容)。
- **行访问适用于成员对受限表所做的一切操作。** 成员在仪表板、自己的 SQL 和加载中只能看到和更改其授权允许的行。
  - **项目架构师在仪表板中可以看到行受限表的所有行**，与他们在 Analyze 中看到的一致。取消架构师访问权限会在仪表板中立即生效——无论是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、还原项目的较早版本，还是删除安全组。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
  - **受行访问限制的成员可以运行自己的 SQL 查询并导出结果。** 在设有行访问的项目中，非架构师成员在查询屏幕上通过自己的查询恰好得到其授权允许的行，并且可以将它们导出为 CSV、Excel 或 JSON，同时显示**行数受您的访问权限限制**通知；以前这些操作会被拒绝。包含百分号（`%`）的授权值现在可在查询屏幕上返回其行，并且将这类查询下载为 CSV 也能正常工作。在 Snowflake 或 Databricks 上他们自己的自由格式 SQL、从 Postgres 系列仓库导出他们自己的 SQL，以及按快照时间点读取受管表，仍会被拒绝，并且视图必须以原始名称保留受管列才能被筛选。请参阅[行访问和您自己编写的查询](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问与您自己编写的查询)。
  - **保存行访问会保留其来源中不存在的已授权值。** 当表中没有包含该值的行、维度中没有该成员，或列表中没有该值时，安全组被授予的值会保留在网格中并带有标记。**保存**会询问是保留还是移除每个这样的值。请参阅[行访问网格](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
  - **向行受限表写入 DataFrame、保存记录和清除，只会更改您能看到的行。** 当行访问限制了您的行时，使用 Python 客户端向受限表写入 DataFrame 或将其清除，或通过 REST API 向其保存记录或将其清除，只会更改您自己的行，包含您访问权限之外的行的加载会在任何更改发生之前被拒绝，并指明发现的值。项目架构师、可以看到所有行的成员以及工作流运行会写入整张表。人员对任何表进行的这些写入都会记录在安全日志中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
  - **对行受限表的导入、复制、还原和删除需要您能看到每一行。** 当行访问限制了您的行时，将文件导入受限表、将另一个项目中的表复制到其中、切换或合并其分支、还原它、删除它、在其被删除后恢复它，或任何其他替换整张表的操作，只有在您能看到该表的每一行时才会运行；否则会被拒绝，且不会有任何更改。通过 REST API 保存表的行只会更改您自己的行，与其他加载相同。项目架构师、可以看到所有行的成员以及工作流运行不受影响，这些操作同样会记录在安全日志中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
- **只有账户的所有者可以还原其较早版本。** 将文档账户还原到较早版本、保留或释放某个版本以及进行备份，都需要账户的所有者之一，并且这些操作在系统管理的账户上均不可用。查看账户的版本历史需要拥有对该账户的访问权限。
- **`query_run` 运行只读语句。** AI 助手和 MCP 客户端使用的 `query_run` 工具接受一条 SELECT 或 WITH 语句、对其的 EXPLAIN，或一条 SHOW；任何其他语句都不会运行。如需更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 遵循同样的规则。通过 REST 和 JSON-RPC API，对于无法更改项目数据的成员，该规则同样适用于运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库以及使用自己的查询导出表数据；被拒绝的查询返回 403。Explain Analyze 会运行查询来进行度量，因此在查询日志和 lakehouse 中它只接受读取数据的查询，在设有行访问的项目中，只有项目架构师才能从查询日志运行它。
- **表资源管理器的筛选器、发送到 PlaidCloud 的查询，以及 Table Extract 步骤用来查找其动态列的查询，不能调用会执行 SQL 或读取服务器文件的函数。** 调用此类函数（例如 `query_to_xml`、`dblink` 或 `pg_read_file`）会被拒绝，错误信息会指出函数名。在这些位置，`.op()` 只接受运算符，`literal_column` 也不能使用 Unicode 转义的引号。动态列查询包含该步骤的筛选器以及从源中读取列名的表达式，因此违反规则的表达式会使该步骤在运行时失败。请参阅[会被拒绝的函数和运算符](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#会被拒绝的函数和运算符)。
- **Data Foundation 分摊规则会拒绝包含单引号、反斜杠或换行符的部门名称或统计名称。** 名称会写入分摊步骤的筛选器，因此**保存**和阶段 1 的预览会拒绝该名称并指出其值。请参阅[分摊规则](/zh-cn/guides/projects/data-foundation/#分摊规则)。
