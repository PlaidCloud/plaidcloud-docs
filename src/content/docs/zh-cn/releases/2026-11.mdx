## 新增

- **控制平面中的 Trust Center 为安全团队提供 PlaidCloud 的安全文档。** 管理员和安全用户可为其组织打开 **Trust Center**，立即下载子处理方列表和 DPA 等公开文档，并为组织一次性签署安全文档保密协议（NDA），以解锁 SOC 2 Type II 报告等受限文档。其他管理员和安全用户可以看到谁在何时签署。合同中已包含 NDA 的组织可将其标记为已存档，这样无需签署即可解锁文档。受限文档的下载带有水印并会被记录，NDA 出现新版本时需要重新接受。请参阅 [Trust Center](/zh-cn/administration/control-plane/trust-center/)。
- **PlaidXL 可在 Excel 中构建、钻取、解释和规划。** **PlaidCloud** 功能区选项卡分为 **连接**、**插入**、**刷新**、**Drill**、**写入** 和 **共享**，常用命令也可在 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡中找到，主要命令带有可更改的键盘快捷键，在字段中输入时不会触发。命令失败时会说明是哪个命令以及原因。登录前运行的命令会打开登录窗口，登录后自动运行一次；一次登录仅对一个工作区有效，因此切换工作区时会要求登录新的工作区（切换回来则无需再登录）；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次点击即可构建报表。** **报表**选项卡根据表生成实时报表，一个维度逐级向下展开在行上，另一个维度横跨列，每个交叉点上是一个 `CELL` 值。**Build my first report** 会用您自己的数据生成示例。钻取时，报表会插入和删除整行整列，您输入的值、备注和格式会跟随所在行。请参阅[构建报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 会把一个节点变成实时的 `DRILL` 公式并为您编辑，可从节点、维度标题或报表值发起。**Custom drill** 会在插入前预览行，成员选择器可插入成员，或为单元格添加某个节点的子级下拉列表。`DRILL` 可接受要排除或展开的节点，也可横跨一行运行。请参阅[钻取、选取成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释一个数字。** **Explain this number** 会显示一个值如何计算、是否与 PlaidCloud 当前一致，以及它来自哪个表和工作流步骤。**Show detail rows** 会把支撑某个值的行放到单独的工作表中，并附带核对其合计是否一致的检查。
  - **Excel 中的受治理指标。** `PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 按仪表板显示的方式返回业务指标；没有可聚合内容的 `CELL` 或 `CELLS` 在求和时显示 `0`，其他情况下显示 `#VALUE!` 并给出原因（在 `CELLS` 溢出区域中则为空白）；**Metric...** 会列出项目的指标及其当前值。一个指标可以按多个备用层次结构筛选，也可以把备用层次结构的成员与其他维度的成员混合使用。请参阅[指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中直接输入来规划。** 在 `CELL` 值上输入数字，即可写入 PlaidCloud：按比例分摊、平均分摊或按另一成员的形态分摊，按金额或百分比调整，已锁定的单元格保持不变。平均值、中位数、最小值、最大值、标准差和方差单元格也接受输入值；插入或删除行列时，输入的值会跟随其单元格（已删除单元格中的值会被报告）。**Undo last write** 会按从新到旧的顺序撤消输入的值和保存，只有执行写入的人员和工作区才能撤消该次写入。撤消求和，或撤消在空单元格中输入的平均值时，会保留此后写入同一单元格的内容；写入完成前被中断的操作无法撤消。请参阅[向 PlaidCloud 输入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新您需要的内容。** 可刷新一个工作表、一个选区或所有表，任务窗格中会显示每个表的进度和**取消**按钮，也可以只重新计算 PlaidXL 公式。检索到的表以按数据类型设置格式的 Excel 表格形式到达，刷新时保留您自己的列和数字格式，并在原位置刷新。检索或刷新绝不会覆盖其他单元格，也不会与另一个 Excel 表格重叠；超出 Excel 范围的整数 ID 和 1900 年之前的日期会以文本形式到达。再次检索某个表不会把它两次加入刷新列表，**Stop refreshing** 可将其移除，维度会随您的表一同刷新。请参阅[刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#refresh-all-tables)。
  - **保存立即写入，并且可以撤消。** **Save to PlaidCloud** 无需确认即可写入，会说明所做的操作，并提供**撤消**，对 Lakehouse 表而言，每次保存后 7 天内都可撤消。带筛选器检索的工作表、明细行工作表，或访问权限仅涵盖部分行的用户，只会替换相应的行，因此其他人的行会保留。成员自检索后已更改的钻取工作表不会被保存，保存失败时会指出还原点，以便将表恢复。请参阅[将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在 **Weave** 选项卡上，可用日常语言要求生成报表、公式、钻取或表，或选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只会更改工作簿，替换您已输入的内容前会先询问，绝不会写入指向工作簿之外的公式，且每项更改在重新加载窗格前都可以还原。请参阅[在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享单个工作表或整个工作簿的纯值副本。** **Convert to values** 可转换整个工作簿、单个工作表，或转换为无法恢复的值（会先询问），只更改 PlaidXL 公式及其溢出区域，仍在计算的公式会留待再次尝试，重命名工作表后 **Restore PlaidXL formulas** 仍然有效。
- **过账登记簿打开时直接显示需要您处理的内容。** 有需要查看的内容时打开 **异常**，有请求等待您处理时打开 **审批**，否则打开 **所有过账**。侧栏把各屏幕分为 **需要我处理**、**登记簿**、**洞察** 和 **设置**，**异常** 和 **审批** 带有计数，每个屏幕共用同一个页眉和范围栏：选择期间（**本月**、**上个月**、**最近 7 天**、**最近 30 天** 或 **自定义**）、连接、项目、环境或实体，以及 **实时**、**模拟** 或 **全部**，然后 **重置**，或保留 **已保存的范围**。系统会记住您上次使用的范围。
  - **异常会整理出需要查看的内容。** **需要查看**、**未确认**、**待处理**、**失败** 和 **冲销未完成** 等标签显示各自的计数，连接健康状况行显示“所有 N 个连接均正常过账”，每笔过账都有通俗易懂的状态，并附带提示说明下一步该做什么。没有未处理事项时显示 **一切正常**。把账簿 ID 粘贴到 **Find a posting by ledger id** 或命令面板中，即可直接打开该笔过账。
  - **审批、委派和关注都是收件箱屏幕。** 可在 **Waiting on me** 和 **Submitted by me** 之间切换，**批准**或**拒绝**时需填写理由，可一次批准多项，也可通过提示条**撤消**批准。**Delegate approvals** 是一个简短的对话框，**我的关注**会列出您关注的内容。**冲销过账**以及批量重试和清除对话框共用同一布局。
  - **过账抽屉会说明发生了什么。** 它显示状态及其含义、按名称列出的关键事实，以及 **明细行**、**历史记录** 和 **签核** 选项卡，还有 **标记为已审核**、**重试**、**冲销…**、**关注连接**、**关注运行** 和 **Copy link**，其中 **Copy link** 会直接打开该笔过账。
  - **辅助、导出和保留采用相同的设计。** **辅助** 有提问框和洞察卡片、标有 **Draft — nothing applied** 的建议，以及 **所有过账** 上带有 **显示这些** 的异常卡片。**导出和警报** 有 **New schedule**，**保留** 是一张卡片。
  - **登记簿保持最新。** 侧栏徽章随过账变化而更新，过账发生变化时打开的列表会提供 **刷新**，打开的抽屉会就地更新。**主页** 在 **需要关注** 下显示 **过账登记簿** 卡片。请参阅[审阅过账登记簿](/zh-cn/guides/connections/posting-register/)。
- **项目主页有六个页面。** 纯文字侧栏列出 **概览**、**变量**、**计划和传感器**、**访问和共享**、**数据和连接** 以及 **应用和品牌**，并以徽章显示变量数量以及活动的计划和传感器数量。**概览** 显示项目的说明和标签、锁定状态，表、工作流、步骤、变量、已发布表和 **数据大小**（会打开 **存储**）的图块，其中数据大小与 **项目** 屏幕显示的总数相同，包含为还原而保留的早期版本，并通过工具提示区分当前数据和早期版本；还显示接下来三次计划的运行和项目的默认值，以及作为 PDF 或交互式 HTML 的 **项目报表** 和 **导出归档**。其他页面管理变量、计划和传感器（带有 **Calendar view** 以及 **Activate** 或 **Deactivate**）、谁可以打开项目及其仪表板、哪些项目可以读取其表、连接和表存储的默认值以及 ERP 过账模式，还有 Panel 应用、品牌和项目的图块图像。锁定的项目会显示横幅并禁用其控件。请参阅[项目主页](/zh-cn/guides/projects/project-home/)。
- **文档打开时显示概览，并带有页面侧栏。** **概览**、**浏览**、**已共享**、**我的私有** 和 **管理** 位于侧栏中。**概览** 显示您的账户图块、会在所选文件夹处打开 **浏览** 并选中该文件的 **已固定** 文件、按服务分类的账户以及谁可以使用它们。**管理** 列出您拥有的账户，工作区管理员可在此看到每个文档账户，并可管理其本来就有权管理的任何账户（系统管理的账户会被拒绝，托管存储桶账户无法克隆）。行的 **⋯** 菜单包含 **打开**、**编辑**、**克隆…**、**谁可以使用**、**使用位置…**、**版本历史记录**、**启用** 或 **禁用** 以及 **删除**。账户以页面形式打开，带有 **常规**、**访问**、**凭据** 卡片，SFTP 账户还有 **SSH** 卡片，有未保存的更改时离开前会先询问。**浏览** 有带标签的工具栏、行菜单、拖放区，以及 **上传和导入** 面板，该面板显示每个上传和导入到表的进度和操作。**弹出** 会在窗口中打开文件夹，**停靠** 会将其放回。请参阅[文档](/zh-cn/guides/documents/)和[使用文档账户](/zh-cn/guides/documents/using-document/)。
- **仪表板打开时显示概览，并带有页面侧栏。** **概览**、**仪表板**、**应用**、**笔记本**以及面向工作区管理员的 **访问审核** 位于侧栏中，底部有 **打开导航器**。**概览** 显示仪表板和应用的图块，点击会打开已筛选的对应列表，还显示您最近打开或加星标的内容、失败的应用和等待您处理的访问请求，并为有使用情况访问权限的成员显示打开次数最多的仪表板。**仪表板** 可按 **全部**、**由您管理** 和 **收藏** 筛选，**应用** 显示每个应用的 **类型** 和实时状态。请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **身份打开时显示概览，并带有页面侧栏。** 侧栏列出 **概览**、**成员**、**目录**、**安全组** 和 **分发列表**，然后是 **会话**、**安全日志**、**API 客户端**、**分组审核** 和 **所有范围**，**使用情况报告** 会在页面上方打开。**概览** 显示成员、活动成员和从未登录成员、构建者席位以及当前已登录人员的图块，一个 **活动成员** 图表，带有 **重新发送欢迎电子邮件** 和 **审核** 的 **需要关注**，以及最近 7 天的安全事件。成员以页面形式打开，带有 **配置文件**、**访问** 和 **分组和数据** 卡片，**邀请成员** 可在概览以及主页的首次运行卡片中使用。请参阅[成员管理](/zh-cn/administration/access/member-management/)。
- **Lakehouse 窗口有侧栏、表详细信息和时间旅行。** **查询**、**配置文件**、**加载** 和 **目录** 位于侧栏中，**管理** 下有 **Lakehouse 目录**、**数据库用户** 和 **计算**。**数据库用户** 和 **计算** 仅向具有 Lakehouse 管理员或 Lakehouse 集群角色的成员显示。**查询** 可按 SQL 文本、用户、类型和持续时间筛选历史记录，用 **复制 SQL** 复制语句，并用 **为此查询生成配置文件** 在 **配置文件** 中打开查询。**目录** 会打开表的列、当前快照、分区、位置、属性和快照历史记录，**复制此快照时间点的查询** 会复制一条 `FOR VERSION AS OF` 查询，读取表在当时的状态。请参阅 [Lakehouse 窗口](/zh-cn/guides/data/lakehouse-window/)。
- **步骤表单上的预览。** 导入：SQL、Execute: SQL、提取 SQL、导出：SQL 和 Salesforce：查询对象 无需运行步骤即可显示最多 100 行，Anaplan 的视图和列表读取会显示其将生成的列和类型。在 **源** 选项卡上点击 **预览**。变量会按运行时的方式填入，但不支持 `{x:>9}` 之类的变量格式。预览只运行标准 SQL 函数，否则会提示您运行该步骤。锁定的项目以及基于代理的 Execute SQL 步骤不可用。请参阅[导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/)和[提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告会显示变化、可缩小到某个分组，并可流入工作流。** **概览** 新增了与上一期间对比的趋势箭头和 **要点** 列表，其中指出不活跃的成员以及无人打开的仪表板和应用。已停用的成员不会被计入或列为不活跃。**分组** 可将 **概览**、**内容** 和不活跃列表限定为某个安全组的成员；日期范围新增 **上一个月** 和 **本月**，由所有选项卡共用，并随您的账户记住。每个数字现在都有说明，表格使用 **成员** 和 **领域** 等通俗名称，按 Enter 可打开行，加载和错误更清晰，最后一个 **漏斗** 步骤显示有多少成员完成了它。**Get Workspace Usage** 步骤按计划把使用情况写入表，形式为不含成员姓名的每日或每月合计，或可直接用于报告的数据集：**成员**、**每位成员每日**、**内容** 和 **每位成员的内容**。成员数据集包含姓名、电子邮件、分组和活动，因此可按电子邮件与您自己的组织表联接，按部门报告活动分钟数或仪表板打开次数。与 **Get Workspace Members** 一样，每次运行都会记录在 **安全日志** 中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以分析表。** 通过 MCP，`table_profile` 返回 **表资源管理器** 显示的列统计信息和 **数据质量雷达** 检查，以及每列最常见的值，一次最多 50 列，且仅限您可见的行。请参阅[通过 AI 助手读取配置文件](/zh-cn/guides/data/table-explorer/#从-ai-助手读取分析结果)。
- **AI 助手可以取消发布表并设置项目的默认仪表板受众。** `publish_manage` 会取消发布表及其已发布的视图，以及没有图表使用的任何仪表板数据集；仍有图表使用的数据集会保留，当报表视图构建在已发布视图之上时，该视图和数据集也会保留，而表仍会被取消发布。`project_upsert` 设置 `dashboard_default_audience`，即项目中新仪表板所共享的分组，`[]` 表示清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Git 应用会列出您的存储库并告知您可以做什么。** 应用列表中的 **Git** 显示您的角色（**管理员**、**贡献者** 或 **查看者**）以及工作区的存储库，每个存储库都有说明、最后更新日期、带复制按钮的克隆地址和 **打开**。**在计算机上设置 Git** 卡片会逐步说明如何安装 Git、创建令牌和克隆，**如何克隆** 可重新打开它。**在 Git 中查看全部** 会打开完整的 Git 界面，**管理谁可以推送** 会打开分组管理。访问级别为 **查看者**、**贡献者**（将应用代码推送到 `apps`）或 **管理员**（可推送到所有位置，包括 `udfs`），查看者最多可看到三位可联系的工作区管理员。新的 **Git Contributors** 分组授予贡献者权限，并可设为默认分组，这样新成员会自动获得；**Git Administration** 授予管理员权限。成员的 **Git** 选项卡显示其 Git 用户名、级别以及授予该级别的分组。成员的 Git 账户随其成员身份而变化：停用或移除成员后，其 Git 账户（包括令牌和 SSH 密钥）会在约一小时内被阻止，重新激活后解除阻止，其存储库和历史记录会保留。使用单点登录登录 Git 会打开该成员自己的账户。贡献者不能直接在工作区的 Git 组织中创建存储库；存储库通过 PlaidCloud 创建。应用窗口显示 **存储库** 部分，UDF 有 **打开**，Git 有指向您工作区的 **← 返回到** 链接。平台创建的每个存储库，包括应用存储库以及内置的 `apps` 和 `udfs` 存储库，工作区中每位已登录的成员都可读取，因此成员无需逐个存储库设置即可打开和重新发布应用。Git 管理员仍可将存储库设为私有，这会使其不出现在存储库选择器中，并阻止成员从中发布或运行其中存储的基于 Git 的 UDF 代码。请参阅 [PlaidCloud Git](/zh-cn/guides/git/#打开-git) 和[谁可以看到存储库](/zh-cn/guides/connections/plaidcloud-git/#谁可以查看存储库)。

- **Data Foundation 将多个 ERP 和系统合并为一个模型，您可选择每个系统加载哪些公司。** **Sources** 页面上的 **Connect a system** 为每种系统提供一个图块，**Connect another system** 可添加另一个 ERP 或另一个实例，而不会替换已有的。在 **Load order** 中，源上的 **编辑** 有其子公司的 **Companies** 列表：勾选要加载的公司，全不勾选则加载全部。排除某家公司前会先要求您确认，因为保存时会清除其已加载的行，下一次 **加载** 会再次拉取已勾选的公司。如果源的连接现在读取的是另一个账户，保存会被拒绝并给出提示，而不会更改另一个源。请参阅[源](/zh-cn/guides/projects/data-foundation/#源)。

## 变更

- **PlaidCloud 的 Web 应用和 Python 客户端库使用 REST API，JSON-RPC 已弃用。** Web 应用把请求发送到 REST API。使用 `plaidcloud-rpc` 1.25.0 或更高版本时，`SimpleRPC` 调用会转到 REST API，您的代码无需更改；REST API 尚未覆盖的调用，或仍在旧版本上的工作区，会像以前一样使用 JSON-RPC。JSON-RPC 将在以后的版本中移除，因此请将脚本和笔记本升级到 `plaidcloud-rpc` 1.25.0 或更高版本，并针对 REST API 编写新的集成。请参阅[命令行](/zh-cn/reference/cli/jupyter/command-line/)。
- **步骤遵循其项目的连接环境，除非您将其固定到另一个环境。** 在 QA 和 Production 等环境之间切换项目时，每个步骤都会随之移动。必须保持在某个环境上的步骤可以改为设置 **Fixed environment**：表单用警告标记它，其日志会注明每次在项目环境之外的环境上的运行，切换项目时会指出不会跟随的步骤。ERP 过账步骤始终使用项目的环境。当项目、固定的步骤或代理正在使用某个环境时，该环境无法删除，代理表单中的字段现在是 **Environment this agent serves**。请参阅[将步骤固定到一个环境](/zh-cn/guides/projects/managing-projects/#将步骤固定到单一环境)。
- **步骤表单遵循同一种布局。** 选项卡采用标准名称和标准顺序：常规、设置、源、列、筛选器、输出和高级，ERP 过账表单上另有标题列和明细行列。必填字段标有 *，表单只会因步骤所需的内容而阻止保存。
- **复制项目将表数据和维度成员分开选择，复制速度更快，并保留私有副本的 ERP 写入授权。** 在 **Data to copy** 下，选择 **表数据**——**无表数据**（默认）、**完整** 或 **样本**——并单独选择 **Copy dimension members**（默认开启），这样不含表行的副本仍会带有已填充的维度，且创建很快。**完整** 和 **样本** 复制会同时复制多张表，因此包含许多表的项目完成得更快。**复制结果** 在表旁边列出每个维度的结果，**Retry failed items** 会把失败的表和维度一起重试。带数据创建的新副本仅您自己可见，并保留您自己有权授予的源的 ERP 写入授权；如果源以 实时 方式过账，副本会以 模拟 方式创建，因此在您将其切换为 实时 之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **表的详细信息面板更快地显示使用它的步骤。** 选择另一个表会立即清除上一个表的步骤，共享本项目数据的其他项目中的步骤会稍后再补充进来，而不会拖慢整个面板。请参阅[查看表的使用位置](/zh-cn/guides/projects/managing-tables-and-views/#查看表的使用位置)。
- **行操作在每个列表中的工作方式相同。** 可从行首的 **⋯** 按钮、右键单击行，或工具栏的 **操作** 菜单打开行的菜单。它始终先列出 **打开**、**详细信息** 和 **编辑**，然后是该列表自己的操作，最后是 **删除** 或 **移除**，不适用于某行的操作会置灰并保留在原位。**Enter** 和 **Del** 会显示在它们所运行的项目上。行只有单个操作的列表会显示该操作的图标而不是 **⋯**，仪表板、应用和笔记本再次显示 **打开** 图标。请参阅[行操作菜单](/zh-cn/guides/dashboards/using-dashboards/#行操作菜单)。
- **PlaidCloud 采用焕新的蓝色外观，支持浅色和深色。** 按钮、复选框、选中的行、选项卡、链接以及列出工作区页面的侧栏使用同一种 PlaidCloud 蓝，并具有在两种主题下阅读所需的对比度。应用选项卡图标是统一的一套。
- **全新的加载屏幕。** PlaidCloud 以更简洁的加载屏幕打开，并跟随您的浅色或深色主题。从空闲状态唤醒的 Panel 或 Dash 应用会显示其经过 **正在启动**、**正在准备** 和 **正在加载应用** 的进度，如果未能启动，会说明停在了哪一步，并提供 **重试**。请参阅[使用 Panel 应用](/zh-cn/guides/panel-apps/using/)。
- **没有验证设置的已保存 ERP 写入步骤会以仅验证模式打开。** 这涵盖 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post，以及 Xero 导出。明确设置为实时运行的步骤保持实时。
- **长时间运行的作业在各处以相同方式显示进度。**
- **工作流如实地停止、失败和报告。** 停止工作流会停止它启动的所有内容，无法完成的运行或步骤会带着原因失败而不是挂起，运行状态与实际运行的内容一致。
  - **停止工作流会停止它启动的所有内容，无法完成的运行或步骤会失败而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中后面的导入和维度加载会正常启动，它还会停止该工作流排队或正在运行的连接器（Singer）同步。如果步骤的作业无法启动，该步骤会带着原因失败而不是永远等待：约 40 分钟内没有工作进程启动它、工作进程启动后消失、其 pod 卡在 Pending 约 20 分钟、其映像约 5 分钟无法拉取，或约 20 分钟没有创建 pod。约 30 分钟内没有运行器接手的连接器同步会失败，并给出指明该同步的消息。步骤等待工作进程时，其状态消息显示“正在等待工作进程…”以及已等待的分钟数，工作开始后消息清除。停止宏会停止它所有正在运行的副本，而停止单个副本，或 **Macro Concurrent** 步骤放弃一个不再响应而停止的副本，会让调用它的工作流继续运行。仅在其他工作流内运行的宏在工作流列表中显示为 **正在运行**，可使用 **停止**，并显示每个步骤来自其最新一次运行的状态、开始时间和结束时间。服务器丢失的运行会以失败结束，仍在运行超过 12 小时的运行会失败，并显示“运行失败：已达到 12 小时限制时仍在运行。请重新运行工作流。”请参阅[运行工作流](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
  - **继续、运行历史记录和运行状态与实际运行的内容一致。** 继续父工作流会运行子工作流剩下的所有内容，即使您之前单独重新运行过子工作流的某个步骤也是如此，同一次运行中对子工作流的每次调用都有自己的运行历史记录条目。因服务器停止而重新启动的步骤会在其日志中说明，`workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续的步骤，而不是把运行报告为干净。请参阅[暂停、停止和继续](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)和[出错时继续](/zh-cn/guides/workflows/continue-on-error/)。
  - **步骤错误会显示各自的消息。** PlaidCloud 未预料到的错误会显示为“步骤因意外错误（*type*）而停止：*message*”。启动板上的 **需要关注** 卡片用一行显示错误，并不再列出此后已被删除的工作流的运行。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。
  - **未完成的 ERP 提取会使其步骤失败，继续会接着执行。** 当 **SAP：临时提取** 因行数或时间限制而暂停，或其代理未及时回复，或者 Salesforce、Oracle Fusion 批量或 HFM/FCCS 导出作业在步骤停止等待时仍在运行，该步骤会失败，这样后面的步骤就不会在不完整的表上运行。继续工作流或重新运行该步骤，提取会在同一个作业上从停止处继续。请参阅[运行限制](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制)和 [Salesforce：查询对象](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
  - **取消导出会停止其在仓库中的查询。** 当导出或下载被取消（包括因停止其工作流而取消）时，读取其数据的查询在 Lakehouse v2、Snowflake、Databricks、PostgreSQL 和 Greenplum 上也会停止，导出到远程数据库时会停止读取其源，而不是一直运行到结束。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会被转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **会话过期后打开的仪表板链接，在您登录后会带您到该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝无法识别的字段**，并在错误中指出该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为它的另一个名称。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据会直接进入该账户的存储桶，使用账户自己的凭据写入，而不是每一行都先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式不变。请参阅[导出到 Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会指明它试图访问的服务器，对 Slack 和 Teams 还会指明连接，并说明出了什么问题：例如 Slack 不再识别该 webhook、无法向该频道发帖、找不到服务器或服务器在 60 秒内未应答，或者连接已被删除。Slack 或 Teams 的 webhook URL 绝不会显示，因为任何持有它的人都可以冒充您的集成发帖。请参阅[通过 Slack 通知](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。
- **项目服务账户的访问令牌有效期至少为 24 小时。** 以项目身份运行的工作流作业（如 UDF 步骤）获得的令牌有效期为 24 小时。工作区升级时会提高较短的有效期，您设置的较长有效期则保留。
- **工作区的组织、所有者、发布和版本由 PlaidCloud 设置，您可选择其数据中心。** 在控制平面中，您创建的工作区归您所有，并放在 PlaidCloud 设置的发布渠道上，您可从注册时提供的区域中选择其 **Data Center**。编辑工作区时，组织、所有者、发布和版本为只读。使用 **Set Version** 更改版本，并请 PlaidCloud 支持团队迁移工作区、更改其所有者或渠道，或将其固定。请参阅[工作区配置](/zh-cn/administration/control-plane/workspace-configuration/#主要设置)。

## 已修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的 slug，或无效的存储类型或过账模式，现在会返回指明问题的消息，而不是通用的服务器错误。通过 REST API 返回的是 400 而不是 500，通过 AI 助手或 MCP 则是无效参数错误。
- **REST API 的维度值请求现在可用。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 过去被当作网格请求应答并被判定为无效。现在它为 `value_columns` 中的每一列返回一个聚合值，而网格（行筛选器与列筛选器的每一对返回一个值）有了自己的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再拖住其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，过去都可能让同一服务器正在处理的所有其他请求暂停，直到它完成。现在它们与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口还高，因此 **创建** 和 **更新** 按钮可能无法触及。现在表单可以滚动，按钮保持在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 这些操作过去对这种大小的文件都会失败，移动或重命名包含这种文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚写入的内容。** 写入表的步骤或导入过去可能记录写入之前的行数，因此刚加载的表显示 0 行，导入可能报告导入了 0 行。现在会在新行对所有位置都可见之后再读取行数，因此后面的步骤也能读到它们。将表切换到另一个分支，或把分支合并到其中，也会更新其行数和列数。
- **Weave 的空值检查会把每次运行与此前运行实际留下的内容进行比较。** 步骤的空值过去常在该步骤清空其表以便重新填充之后才被统计，因此它此前的运行看起来没有空值，而一直部分为空的列会被报告为刚刚变成这样。现在每次运行都按步骤留下的表来统计。此前记录的计数无法与正确的计数区分，因此不予使用：每个步骤的空值检查会重新开始其历史记录，并在统计满五次运行之前报告为未检查。行数和值分布检查也不再把另一个步骤在其完成两秒之后对同一张表所做的写入记在该步骤名下。请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **Data Foundation 保留反向汇率和小数阈值的精度。** PlaidCloud 反转的汇率（因为您的汇率是从报告货币报价到另一种货币）过去可能被舍入到六位小数，导致汇率很小的货币（如印度尼西亚盾）的金额偏差约 1%。反向汇率现在保留 12 位小数。带小数的 `group_amber` 或 `group_red` 阈值（如 `0.5`）过去被舍入为整数。您的下一次加载将使用精确的值。请参阅[汇率](/zh-cn/guides/projects/data-foundation/#汇率)。
- **已停用成员的警报和摘要会停止。** 所有者已被停用的 Panel 应用警报或摘要过去仍会继续检查和发送。现在它在所有者被停用期间暂停，重新激活后恢复。请参阅[警报和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
- **向 REST API 请求已删除的连接会返回 404。** 请求已被删除的连接或不存在的 ID，过去会返回通用的服务器错误（500）。现在它返回 404，并附带指明连接 ID 的消息。
- **模板化的表导出可通过 AI 助手和 MCP 使用。** `table_data_export` 的 `templated` 格式过去在传入表时总是失败。现在它通过您的模板导出该表，并限于您可读取的行。在模板中，表的行以其表 ID 命名，其中每个 `-` 写作 `_`。
- **Amazon S3 和兼容 S3 的文档账户会保留其区域。** 保存这类账户过去会丢弃您输入的 **区域**，因此下次打开账户时该字段为空白。现在区域会被保存。对于在此修复之前保存的账户，请重新输入区域并保存。请参阅[添加 AWS S3 账户](/zh-cn/guides/documents/adding-accounts/add-aws-s3-account/)。
- **两次命名同一输出列的步骤会在清空目标之前停止。** 在 Table Lookup、Table Extract 或联接中，两个同名的 **目标输出列** 过去会让步骤先清空其目标表，然后以不清楚的错误失败。现在步骤会先停止，并给出指明重复列的消息，这样您可以为每个输出列指定各自的名称。按查询返回顺序写入列的 提取 SQL 不受影响。请参阅 [Table Lookup](/zh-cn/reference/workflow-steps/tables/table-lookup/)。

## 安全

- **密码登录需要身份验证器应用，并且密码更强。** 使用 PlaidCloud 密码登录的成员，在下次登录时会被要求设置身份验证器应用，此后每次都要输入其验证码。单点登录、Google、Microsoft 和 GitHub 登录、API 令牌和服务账户不变。新密码至少需要 12 个字符，不能是您的用户名或最近六个密码之一，多次登录失败后账户会被短暂锁定。工作区已有的更严格规则会保留。请参阅[成员身份验证](/zh-cn/administration/access/member-authentication/)。
- **连接指向公共和专用网络地址。** 连接不能指向环回地址、链路本地地址或云元数据地址，错误会指明主机及其解析到的地址。您专用网络上的地址不受影响。请参阅[连接无法访问的地址](/zh-cn/guides/connections/create-connection/#连接无法访问的地址)。
- **已保存的连接凭据仅向可以编辑连接或工作流的成员显示。** 通过 REST API 和 MCP，已保存连接的密码、令牌和密钥会对其他成员屏蔽，他们仍可打开和浏览该连接。请参阅[谁能看到连接的凭据](/zh-cn/guides/connections/create-connection/#谁能看到连接的凭据)。
- **应用构建在运行时无法访问工作区的 Git 凭据。**
- **代理的私钥仅向可以编辑代理的成员显示。** 通过 REST API 和 MCP，该密钥不再出现在代理列表或详细信息中，代理表单也只向可以编辑代理的成员显示 **私钥** 和 **查看 RPC 配置**。服务账户、项目和代理令牌以及 AI 委派的令牌无法检索该密钥或 RPC 配置。正在运行的代理不受影响，公钥仍会显示。请参阅[获取代理凭据](/zh-cn/reference/cli/plaidlink/agents/#获取代理凭据)。
- **代理下载链接的有效期为一小时。** 开启 **Use PlaidCloud Proxy Download** 时，如果链接已过期，请再次打开下载以获取新链接。请参阅[服务](/zh-cn/administration/control-plane/workspace-configuration/#服务)。
- **向安全组添加人员遵循您所持有的权限。** 当您拥有某个安全组授予的全部权限时，才可以将成员添加到该安全组、选择成员的分组或邀请架构师。工作区管理员不受限制。请参阅[管理安全组](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理安全组)。
- **连接的所有者或工作区管理员可更改其设置并将其开启或关闭。** 通过 REST API、JSON-RPC 以及 AI 助手或 MCP 更改连接的设置，需要其所有者之一，或对于没有所有者的连接需要工作区管理员。启用、禁用、锁定和解锁连接需要所有者或工作区管理员，指明多个连接的请求仅在您能更改全部连接时才会生效。只有工作区管理员可以选择工作区的默认 AI 连接，成员拥有的连接只有在管理员拥有的连接或没有所有者的连接都不可能成为默认时才会成为默认。请参阅[编辑连接](/zh-cn/guides/connections/create-connection/#编辑连接)和 [LLM 提供商](/zh-cn/integrations/ai-architecture/llm-providers/#连接包含的内容)。
- **行访问适用于成员对受限表所做的一切。** 成员在仪表板、自己的 SQL 和加载中，只能看到和更改其授权所允许的行。
  - **项目架构师在仪表板中可以看到行受限表的所有行**，与他们在 Analyze 中看到的一致。取消架构师访问权限会立即在仪表板中生效——无论是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、还原项目的早期版本，还是删除安全组。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
  - **受行访问限制的成员可以运行自己的 SQL 查询并导出结果。** 在有行访问的项目上，不是架构师的成员从查询屏幕上自己的查询中得到的恰好是其授权所允许的行，并且可以将其导出为 CSV、Excel 或 JSON，同时显示 **行数受您的访问权限限制** 通知；此前这些操作会被拒绝。包含百分号（`%`）的授权值现在可在查询屏幕上返回其行，将此类查询下载为 CSV 也可以正常工作。他们在 Snowflake 或 Databricks 上自己的自由格式 SQL、从 Postgres 系列仓库导出自己的 SQL，以及按快照读取受治理的表，仍然会被拒绝，并且视图必须以原名称保留受治理的列才能被筛选。请参阅[行访问与您自己编写的查询](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问与您自己编写的查询)。
  - **保存行访问时会保留其源中不存在的已授权值。** 当表中没有包含某个值的行、维度没有该成员或列表中没有它时，安全组被授予的值会保留在网格中并带有标记。**保存** 会询问是保留还是移除每个这样的值。请参阅[行访问网格](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
  - **DataFrame 写入、记录保存以及对行受限表的清除，只会更改您能看到的行。** 当行访问限制了您的行时，使用 Python 客户端将 DataFrame 写入受限表或清除它，或通过 REST API 向其保存记录或清除它，只会更改您自己的行；携带您访问权限之外的行的加载会在任何更改之前被拒绝，并指明所发现的值。项目架构师、能看到所有行的成员以及工作流运行会写入整张表。个人对任何表所做的这些写入每一次都会记录在 **安全日志** 中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
  - **对行受限表的导入、复制、还原和删除要求您能看到每一行。** 当行访问限制了您的行时，将文件导入受限表、从另一个项目将表复制到其中、切换或合并其分支、还原它、删除它、在删除后将其恢复，或任何其他替换整张表的操作，只有在您能看到该表的每一行时才会运行；否则会被拒绝，且不会有任何更改。通过 REST API 保存表的行只会更改您自己的行，与其他加载相同。项目架构师、能看到所有行的成员以及工作流运行不受影响，这些操作同样会记录在 **安全日志** 中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
- **只有账户的所有者才能还原其早期版本。** 将文档账户还原到早期版本、保留或释放某个版本以及进行备份，都需要账户的所有者之一，并且在系统管理的账户上都不可用。查看账户的版本历史记录需要有该账户的访问权限。
- **`query_run` 运行只读语句。** AI 助手和 MCP 客户端使用的 `query_run` 工具接受一条 SELECT 或 WITH 语句、对其执行的 EXPLAIN，或 SHOW；任何其他语句都不会运行。要更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 遵循同样的规则。通过 REST 和 JSON-RPC API，对于无法更改项目数据的成员，该规则也适用于运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库，以及使用自己的查询导出表数据；被拒绝的查询返回 403。Explain Analyze 会运行查询以进行度量，因此在查询日志和 lakehouse 中它只接受读取数据的查询，并且在有行访问的项目上，只有项目架构师可以从查询日志中运行它。
- **表资源管理器筛选器、发送到 PlaidCloud 的查询，以及查找 Table Extract 步骤的动态列的查询，不能调用运行 SQL 或读取服务器文件的函数。** 对其中任何一个的调用（如 `query_to_xml`、`dblink` 或 `pg_read_file`）都会被拒绝，错误会指明该函数。在相同的位置，`.op()` 只接受运算符，`literal_column` 不能使用 Unicode 转义引号。动态列查询带有步骤的筛选器以及从源读取列名的表达式，因此违反规则的查询会在步骤运行时使其失败。请参阅[被拒绝的函数和运算符](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#会被拒绝的函数和运算符)。
- **Data Foundation 分摊规则会拒绝包含单引号、反斜杠或换行符的部门或统计名称。** 该名称会被写入分摊步骤的筛选器中，因此 **保存** 和第 1 阶段的预览会拒绝它并指明该值。请参阅[分摊规则](/zh-cn/guides/projects/data-foundation/#分摊规则)。
