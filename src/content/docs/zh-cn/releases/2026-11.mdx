## 新增

- **PlaidXL 可在 Excel 中构建、钻取、解释和规划。** **PlaidCloud** 功能区选项卡分为**连接**、**插入**、**刷新**、**Drill**、**写入**和**共享**，常用命令也出现在 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡中，主要命令都有可更改的键盘快捷方式。在登录前运行的命令会先打开登录，登录后再运行一次；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次单击即可构建报表。** **报表**选项卡根据表布置出实时报表，一个维度向下钻取到行，另一个维度横跨各列，每个交叉点都有一个 `CELL` 值。**Build my first report** 会用您自己的数据生成示例。钻取时，报表会插入和删除整行整列，您输入的值、备注和格式会跟随其所在的行。请参阅[构建报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 可将节点变成实时的 `DRILL` 公式并为您编辑，可从节点、维度标题或报表值发起。**Custom drill** 会在插入前预览行，成员选择器可插入成员，或向单元格添加某个节点子级的下拉列表。`DRILL` 可接受要排除或展开的节点，并可跨行运行。请参阅[钻取、选择成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释数字。** **Explain this number** 会显示某个值的计算方式、它现在是否与 PlaidCloud 一致，以及它来自哪个表和工作流步骤。**Show detail rows** 会将值背后的行放到单独的工作表中，并附有核对其合计是否相符的检查。
  - **Excel 中的受管指标。** `PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 会按仪表板显示的方式返回业务指标，**Metric...** 会列出项目的指标及其当前值。请参阅[指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中直接输入即可规划。** 在 `CELL` 值上输入数字，即可写入 PlaidCloud：按比例分摊、平均分摊或按另一成员的形态分摊，按金额或百分比调整，已锁定的单元格保持不变。平均值、中位数、最小值、最大值、标准差和方差单元格也可以输入值。**Undo last write** 会按从新到旧的顺序撤销输入的值和保存。请参阅[向 PlaidCloud 输入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新所需内容。** 可以刷新一个工作表、一个选区或所有表，任务窗格中会显示每个表的进度和**取消**，也可以只重新计算 PlaidXL 公式。检索到的表以 Excel 表的形式到达，按数据类型设置格式，刷新时保留您自己的列和数字格式，并在各自的位置刷新。再次检索表不会将其重复加入刷新列表，**Stop refreshing** 可将某个表移出，维度会随表一起刷新。请参阅[刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#刷新所有表)。
  - **保存立即写入，并且可以撤消。** **Save to PlaidCloud** 无需确认即可写入，会说明所做的操作，并提供**撤消**。带筛选器检索的工作表、明细行工作表，或访问权限仅覆盖部分行的人员，只会替换这些行，因此其他人的行会保留。请参阅[将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在 **Weave** 选项卡上，可用日常语言要求生成报表、公式、钻取或表，也可以选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只更改工作簿，在替换您已输入的内容前会先询问，在您重新加载窗格之前，每项更改都可以还原。请参阅[在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享单个工作表或整个工作簿的纯值副本。** **Convert to values** 可转换整个工作簿、单个工作表，或转换后无法恢复的值；即使重命名工作表后，**Restore PlaidXL formulas** 仍然有效。
- **步骤表单中的预览。** Import: SQL、Execute: SQL、Extract: SQL、Export: SQL 和 Salesforce Query 无需运行步骤即可显示最多 100 行，Anaplan 视图和列表读取会显示它们将生成的列和类型。在**源**选项卡上单击**预览**。变量会按运行时的方式填充，但不支持 `{x:>9}` 之类的变量格式。预览只运行标准 SQL 函数，否则会提示您运行该步骤。锁定的项目以及基于代理的 Execute SQL 步骤不可用。请参阅[导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/) 和[提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告会显示变化、可限定到某个分组，并可接入工作流。** **概览**新增与上一期间对比的趋势箭头，以及一个 **Highlights** 列表，指出不活跃的成员以及无人打开的仪表板和应用。**分组**会将**概览**、**内容**和不活跃列表限定为某个安全组的成员；日期范围新增 **Previous month** 和 **This month**，由所有选项卡共用并随您的账户记住。每个数字现在都有说明，表使用 **成员** 和 **Area** 等通俗名称，按 Enter 即可打开行，加载和错误提示更清晰，最后一个**漏斗**步骤会显示有多少成员完成了它。新的 **Get Workspace Usage** 步骤会按计划将每日或每月的使用情况合计写入表，不含成员姓名，并且与 **Get Workspace Members** 一样，每次运行都记录在**安全日志**中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表并设置项目的默认仪表板受众。** `publish_manage` 会取消发布表及其已发布的视图，以及没有图表使用的仪表板数据集；仍被图表使用的数据集会保留，当报表视图构建在已发布视图之上时，该视图和数据集也会保留，而表仍会被取消发布。`project_upsert` 会设置 `dashboard_default_audience`，即项目中新仪表板所共享的分组，`[]` 会将其清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Git 应用会列出您的存储库，并告知您可以执行的操作。** 应用列表中的 **Git** 会显示您的角色（**Administrator**、**Contributor** 或**查看者**）和工作区的存储库，每个存储库带有说明、最后更新日期、带复制按钮的克隆地址以及**打开**。**Set up Git on your computer** 卡片会引导您完成安装 Git、创建令牌和克隆，**How to clone** 可重新打开它。**View all in Git** 会打开完整的 Git 界面，**Manage who can push** 会打开分组管理。访问级别为**查看者**、**Contributor**（向 `apps` 推送应用代码）或 **Administrator**（可推送到所有存储库，包括 `udfs`），查看者最多会看到三位可以求助的工作区管理员。新的 **Git Contributors** 分组授予 Contributor 级别，并且可以作为默认分组，因此新成员会自动获得；**Git Administration** 授予管理员级别。成员的 **Git** 选项卡会显示其 Git 用户名、级别以及授予该级别的分组。应用窗口会显示**存储库**部分，UDF 有**打开**，Git 中有指向工作区的 **← Back to** 链接。请参阅 [PlaidCloud Git](/zh-cn/guides/git/#打开-git)。
- **移动端 Weave 的语音输入只需点一下。** 点击麦克风，说出问题，停止说话后 Weave 会发送一次。再次点击麦克风可提前停止，如果没有听到任何声音，它会自动关闭。如果在说话途中离开 **Weave** 选项卡或将应用切到后台，您的话会保留在问题框中而不发送，以便您检查。运行、暂停、停止和恢复会忽略对其确认操作的意外双击。需要应用版本 1.3.0 或更高版本。请参阅[使用语音](/zh-cn/guides/mobile-app/weave-on-mobile/#使用语音)。

## 变更

- **步骤表单采用统一布局。** 选项卡采用标准名称和标准顺序：General、Settings、Source、Columns、Filters、Output 和 Advanced，ERP 过账表单另有 Header columns 和 Line columns。必填字段以 * 标记，表单只会因步骤所需的内容而阻止保存。
- **复制项目可分别选择表数据和维度成员，复制数据更快，并为私有副本保留 ERP 写入授权。** 在 **Data to copy** 下，选择**表数据**（**无表数据**（默认）、**完整**或**样本**），并另外选择 **Copy dimension members**（默认开启），因此不含表行的副本到达时维度也已填充，制作很快。**完整**和**样本**副本会同时复制多个表，因此包含大量表的项目完成得更快。**复制结果**会在表旁列出每个维度的结果，**Retry failed items** 会同时重试失败的表和维度。带数据的新副本归您私有，并保留源中您自己可以授予的 ERP 写入授权；如果源以 Live 过账，副本会进入 Simulate，因此在您将其切换为 Live 之前不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **行操作菜单（⋯）位于每个网格行的最左侧。**
- **应用选项卡图标统一为一套**，浅色和深色模式均适用。
- **未设置验证选项的已保存 ERP 写入步骤以仅验证方式打开。** 这涵盖 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post 以及 Xero export。明确设置为实时运行的步骤保持实时。
- **长时间运行的作业在各处以相同方式显示进度。**
- **停止工作流会停止它启动的所有内容，无法完成的运行或步骤会失败而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中后续的导入和维度加载可正常开始；它也会停止该工作流排队中或正在运行的连接器（Singer）同步。如果步骤的作业无法启动，该步骤会失败并给出原因，而不是无限等待：约 40 分钟内没有工作进程启动它、工作进程启动后消失、其 pod 卡在 Pending 状态约 20 分钟、约 5 分钟内无法拉取其镜像，或约 20 分钟内未创建 pod。约 30 分钟内没有运行器接手的连接器同步会失败，并显示指明该同步的消息。步骤等待工作进程时，其状态消息显示“正在等待工作进程…”及已等待的分钟数，工作开始后消息会清除。停止宏会停止它所有正在运行的副本，仅在其他工作流内部运行的宏会在工作流列表中显示为**正在运行**，可使用**停止**，并显示每个步骤最近一次运行的状态、开始时间和结束时间。服务器丢失的运行会以失败结束，运行超过 12 小时仍未结束的运行会失败，并显示“运行失败：已达到 12 小时上限，仍在运行。请重新运行工作流。”请参阅[运行工作流](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
- **恢复、运行历史和运行状态与实际运行内容一致。** 恢复父工作流时，会运行子工作流剩余的全部内容，即使您已单独重新运行过子工作流的某个步骤；同一次运行中对子工作流的每次调用都有自己的运行历史条目。因服务器停止而重新启动的步骤会在其日志中说明，`workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续运行的步骤，而不是将运行报告为正常。请参阅[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)和[出错后继续](/zh-cn/guides/workflows/continue-on-error/)。
- **步骤错误显示其自身的消息。** PlaidCloud 未预料到的错误会显示为“步骤因意外错误而停止（*type*）：*message*”。启动板上的**需要关注**卡片以一行显示错误，并且不再包含已被删除的工作流的运行。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。
- **未完成的 ERP 提取会使其步骤失败，恢复后会继续。** 当**SAP：临时提取**在行数或时间限制处暂停，或其代理未及时回复，或者 Salesforce、Oracle Fusion 批量或 HFM/FCCS 导出作业在步骤停止等待时仍在运行时，该步骤会失败，因此其后的步骤不会基于不完整的表运行。恢复工作流或重新运行该步骤，提取会在同一作业上从停止处继续。请参阅[运行限制](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制)和 [Salesforce：查询对象](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **项目架构师在仪表板中可看到行受限表的所有行**，与他们在 Analyze 中看到的一致。撤销架构师访问权限会立即在仪表板中生效：无论是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、还原项目的早期版本，还是删除安全组。前架构师不再能看到行受限数据的每一行。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
- **会话过期后打开的仪表板链接，会在您登录后带您进入该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝它们无法识别的字段**，并在错误中指明该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为它的另一个名称。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据会使用账户自己的凭据直接写入账户的存储桶，而不是让每一行都先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式不变。请参阅[导出到 Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会指明它尝试访问的服务器，对于 Slack 和 Teams 还会指明连接，并说明出了什么问题：例如 Slack 不再识别该 webhook、无法向该频道发帖、找不到服务器或服务器在 60 秒内没有响应，或连接已被删除。Slack 或 Teams 的 webhook URL 从不显示，因为任何拥有它的人都可以冒充您的集成发帖。请参阅[通过 Slack 通知](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。

## 修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的标识、无效的存储类型或过账模式，现在会返回指明问题的消息，而不是通用的服务器错误。通过 REST API 返回 400 而不是 500，通过 AI 助手或 MCP 则返回无效参数错误。
- **REST API 的维度值请求现在可用。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 曾被当作网格请求处理并被拒绝为无效。它现在会为 `value_columns` 中的每一列返回一个聚合值；而网格（每对行筛选器和列筛选器对应一个值）有了自己的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再拖延其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，这些操作原先都可能让同一服务器正在处理的所有其他请求暂停，直到其完成。现在它们与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口还高，因此**创建**和**更新**按钮可能无法点到。现在表单可以滚动，按钮保留在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 以前对这种大小的文件执行这些操作都会失败，移动或重命名包含此类文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚写入的内容。** 写入表的步骤或导入可能记录的是写入前的行数，因此刚加载的表显示 0 行，导入也可能报告导入了 0 行。现在会在新行处处可见之后再读取行数，因此后续步骤也能读取到它们。将表切换到另一个分支，或将分支合并到表中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的内容进行比较。** 步骤的空值经常是在该步骤清空表以重新填充之后才统计的，因此它之前的运行看起来没有空值，而一直有部分为空的列会被报告为刚刚才变为如此。现在每次运行都按步骤留下的表来统计。之前记录的计数无法与正确的计数区分，因此不予使用：每个步骤的空值检查会重新开始其历史，并在统计满五次运行之前报告为未检查。行数和值分布检查也不再将另一个步骤在本步骤完成两秒以上之后对同一个表所做的写入记在本步骤名下。请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **请求已删除的连接时，REST API 会返回 404。** 请求已删除的连接或不存在的 ID 时，曾返回通用的服务器错误（500）。现在会返回 404，并附有指明连接 ID 的消息。

## 安全

- **保存行访问时会保留其来源已不再包含的已授予值。** 以前，一旦表中没有包含该值的行、维度失去了该成员或列表不再包含该值，安全组已被授予的值会在下次保存时从授权中消失。这样一来，没有任何勾选项的分组会回退到 **Everyone else**，这可能意味着所有行。现在该值会保留在网格中并带有标记，**保存**时会询问您是保留还是移除。请参阅[行访问网格](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
- **只有账户所有者才能还原其早期版本。** 将文档账户还原到早期版本、保留或释放某个版本以及进行备份，现在都要求您是该账户的所有者之一，并且系统管理的账户上均不可用。查看账户的版本历史需要有该账户的访问权限。
- **只读数据的查询不再能更改数据。** AI 助手和 MCP 客户端使用的 `query_run` 工具只运行读取数据的语句（一条 SELECT 或 WITH 语句、对其执行的 EXPLAIN，或 SHOW），并会拒绝其他任何语句而不运行。若要更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 遵循同样的规则。通过 REST 和 JSON-RPC API，对于无法更改项目数据的成员，该规则也适用于运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库以及使用自己的查询导出表数据；被拒绝的查询会返回 403。Explain Analyze 会运行查询以进行测量，因此在查询日志和 Lakehouse 中，它现在只接受读取数据的查询，并且在有行访问的项目中，只有项目架构师才能从查询日志运行它。
