## 新增

- **PlaidXL 可在 Excel 中构建、钻取、解释和规划。** **PlaidCloud** 功能区选项卡分为**连接**、**插入**、**刷新**、**钻取**、**写入**和**共享**，常用命令也位于 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡上，主要命令带有可更改的键盘快捷键，在字段中输入时这些快捷键不会触发。命令失败时会说明是哪个命令以及原因。在登录之前运行的命令会打开登录界面，并在登录后运行；一次登录对一个工作区有效，因此切换工作区时会要求登录新的工作区（切换回来则不需要）；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次点击即可构建报表。** **报表**选项卡根据表生成实时报表，一个维度沿行向下钻取，另一个维度横跨各列，每个交叉点都有一个 `CELL` 值。**Build my first report** 会基于您自己的数据生成示例。钻取时，报表会插入和删除整行整列，您输入的值、备注和格式会随所在行保留。请参阅[构建报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 可将节点变为实时的 `DRILL` 公式并为您编辑，适用于节点、维度标题或报表值。**Custom drill** 会在插入之前预览行，成员选择器可插入成员，或向单元格添加节点子级的下拉列表。`DRILL` 支持指定要排除或展开的节点，并可跨行运行。请参阅[钻取、选择成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释数字。** **Explain this number** 显示值的计算方式、是否与 PlaidCloud 当前一致，以及它来自哪个表和工作流步骤。**Show detail rows** 将值背后的行放在单独的工作表上，并检查它们的合计是否一致。
  - **Excel 中的受治理指标。** `PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 按仪表板显示的方式返回业务指标；没有可聚合内容的 `CELL` 或 `CELLS`，求和时显示 `0`，否则显示 `#VALUE!` 并附原因（在 `CELLS` 溢出区域中为空白），**Metric...** 会列出项目的指标及其当前值。指标可以按多个备用层次结构筛选，并可将备用层次结构成员与其他维度的成员混合使用。请参阅[指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中直接输入进行规划。** 在 `CELL` 值上输入数字，即可将其写入 PlaidCloud：按比例分摊、平均分摊或按另一个成员的形态分摊，按金额或百分比调整，已保留的单元格不受影响。平均值、中位数、最小值、最大值、标准差和方差单元格也接受输入值，在插入或删除行或列时，输入值会跟随其单元格（已删除单元格中的值会被报告）。**Undo last write** 会按从新到旧的顺序撤消输入的值和保存，并且只有执行写入的人员和工作区才能撤消该写入。撤消求和，或撤消在空单元格中输入的平均值时，会保留此后写入同一单元格的内容，在完成之前被中断的写入无法撤消。请参阅[向 PlaidCloud 输入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新所需内容。** 可刷新一个工作表、一个选区或所有表，任务窗格中显示每个表的进度和**取消**，也可以只重新计算 PlaidXL 公式。检索到的表以按数据类型设置格式的 Excel 表形式到达，刷新时保留您自己的列和数字格式，并在原位刷新。检索或刷新绝不会覆盖其他单元格或与其他 Excel 表重叠，对 Excel 来说过大的整数 ID 以及 1900 年之前的日期将以文本形式到达。再次检索表不会将其两次加入刷新列表，**Stop refreshing** 会将其中一个移出列表，维度会随您的表一起刷新。请参阅[刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#refresh-all-tables)。
  - **保存立即写入，并且可以撤消。** **Save to PlaidCloud** 无需确认即可写入，会说明所做的操作，并提供**撤消**，对于 Lakehouse 表，每次保存后最长 7 天内均可使用。带筛选器检索的工作表、明细行工作表，或访问权限仅涵盖部分行的人员，仅替换这些行，因此其他人的行会保留。自检索以来成员已发生变化的钻取工作表不会被保存，保存失败时会指出还原点，以便将表恢复原状。请参阅[将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在 **Weave** 选项卡上，用自然语言请求报表、公式、钻取或表，或选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只更改工作簿，在替换您已输入的内容之前会先询问，绝不会写入指向工作簿之外的公式，并且在您重新加载窗格之前，每项更改都可以还原。请参阅[在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享单个工作表或整个工作簿的仅值副本。** **Convert to values** 可转换整个工作簿、单个工作表，或转换为无法恢复的值（会先询问），只更改 PlaidXL 公式及其溢出区域，仍在计算的公式会留待再次尝试，并且在您重命名工作表后，**Restore PlaidXL formulas** 仍然有效。
- **过账登记簿会直接打开到需要您处理的内容。** 有内容需要查看时，它会打开到**异常**；有请求等待您处理时，打开到**审批**；否则打开到**所有过账**。导航栏将其屏幕分组为**需要我处理**、**登记簿**、**洞察**和**设置**，并在**异常**和**审批**上显示计数，所有屏幕共用同一个页眉和范围栏：选择期间（**本月**、**上个月**、**最近 7 天**、**最近 30 天**或**自定义**）、连接、项目、环境或实体，以及**实时**、**模拟**或**全部**，然后**重置**或保留 **Saved scope**。系统会记住您上次的范围。
  - **异常会整理出需要查看的内容。** **需要查看**、**未确认**、**待处理**、**失败**和**冲销未完成**的标签显示各自的计数，连接健康状况行显示“所有 N 个连接过账正常”，每笔过账都有通俗易懂的状态，并附带提示说明下一步该怎么做。没有未处理项时会显示 **All clear**。将分类账 ID 粘贴到 **Find a posting by ledger id** 或命令面板中，即可直接打开该过账。
  - **审批、委托和关注是收件箱式屏幕。** 可在 **Waiting on me** 和 **Submitted by me** 之间切换，附理由**批准**或**拒绝**，一次批准多项，并可通过提示条**撤消**审批。**Delegate approvals** 是一个简短的对话框，**我的关注**列出您关注的内容。**冲销过账**以及批量重试和清除对话框共用同一布局。
  - **过账抽屉会说明发生了什么。** 它显示状态及其含义、按名称列出的关键事实，以及**明细行**、**历史记录**和**签核**选项卡，并提供**标记为已审核**、**重试**、**冲销…**、**关注连接**、**关注运行**和**复制链接**，其中**复制链接**会直接打开该过账。
  - **辅助、导出和保留遵循相同的设计。** **辅助**有提问框和洞察卡片、标注为 **Draft — nothing applied** 的建议，以及**所有过账**上带有**显示这些**的异常卡片。**导出和警报**有 **New schedule**，**保留**是一张卡片。
  - **登记簿保持最新。** 导航栏徽章会随过账变化而更新，过账发生变化时，打开的列表会提供**刷新**，打开的抽屉会就地更新。**主页**在**需要关注**下显示**过账登记簿**卡片。请参阅[查看过账登记簿](/zh-cn/guides/connections/posting-register/)。
- **项目主页有六个页面。** 导航栏列出**概览**、**变量**、**计划和传感器**、**访问和共享**、**数据和连接**以及**应用和品牌**，并带有变量数量以及活动计划和传感器数量的徽章。**概览**显示项目的说明和标签、锁定状态、表、工作流、步骤、变量、已发布的表和**数据大小**（打开**存储**）的磁贴、接下来的三次计划运行以及项目的默认值，并提供 PDF 或交互式 HTML 形式的**项目报表**和**导出归档**。其他页面管理变量、计划和传感器（带有 **Calendar view** 以及 **Activate** 或 **Deactivate**）、谁可以打开项目及其仪表板、哪些项目可以读取其表、连接和表存储默认值以及 ERP 过账模式，还有 Panel 应用、品牌和项目的磁贴图片。已锁定的项目会显示横幅并禁用其控件。请参阅[项目主页](/zh-cn/guides/projects/project-home/)。
- **文档以概览页打开，并提供页面导航栏。** **概览**、**浏览**、**已共享**、**我的私有**和**管理**位于导航栏中。**概览**显示您的文档账户磁贴、**Pinned** 文件（打开时会在**浏览**中定位到其文件夹并选中该文件）、按服务划分的文档账户以及谁可以使用它们。**管理**列出您拥有的文档账户，工作区管理员可在此看到所有文档账户并可管理其可管理的任何账户（系统托管的账户会被拒绝，托管存储桶账户无法克隆）。行的 **⋯** 菜单包含**打开**、**编辑**、**克隆…**、**谁可以使用**、**使用位置…**、**版本历史记录**、**启用**或**禁用**以及**删除**。文档账户以页面形式打开，包含**常规**、**访问**、**凭据**卡片，对于 SFTP 还有 **SSH** 卡片，并在您带着未保存的更改离开前进行询问。**浏览**提供带标签的工具栏、行菜单、拖放区域，以及 **Uploads and imports** 面板，显示每次上传和导入到表的操作及其进度和可执行的操作。**Pop out** 在窗口中打开该文件夹，**Dock** 将其恢复原位。请参阅[文档](/zh-cn/guides/documents/)和[使用文档账户](/zh-cn/guides/documents/using-document/)。
- **仪表板以概览页打开，并提供页面导航栏。** **概览**、**仪表板**、**应用**、**笔记本**以及（对工作区管理员而言）**访问审核**位于导航栏中，底部是 **Open navigator**。**概览**显示仪表板和应用的磁贴（点击后会打开已筛选的对应列表）、您最近打开或加星标的内容、失败的应用和等待您处理的访问请求，以及（对具有使用情况访问权限的成员而言）打开次数最多的仪表板。**仪表板**可按**全部**、**由您管理**和**收藏**筛选，**应用**显示每个应用的**类型**和实时状态。请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **身份以概览页打开，并提供页面导航栏。** 导航栏列出**概览**、**成员**、**目录**、**安全组**和**分发列表**，然后是**会话**、**安全日志**、**API 客户端**、**分组审计**和**所有范围**，**使用情况报告**会在页面上方打开。**概览**显示成员、活动成员和从未登录的成员、构建者席位以及当前登录者的磁贴，一个**活动成员**图表，带有**重新发送欢迎电子邮件**和**审核**的**需要关注**，以及最近 7 天的安全事件。成员以页面形式打开，包含**配置文件**、**访问**和**分组和数据**卡片，**Invite member** 可在概览和主页的首次运行卡片中使用。请参阅[成员管理](/zh-cn/administration/access/member-management/)。
- **步骤表单上的预览。** 导入：SQL、执行：SQL、提取：SQL、导出：SQL 和 Salesforce 查询无需运行步骤即可显示最多 100 行，Anaplan 视图和列表读取会显示它们将生成的列和类型。点击**源**选项卡上的**预览**。变量会按运行时的填充方式填入，但不支持 `{x:>9}` 这样的变量格式。预览仅运行标准 SQL 函数，否则会提示您运行该步骤。它在已锁定的项目上不可用，对于基于代理的 Execute SQL 步骤也不可用。请参阅[导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/) 和[提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告会显示变化、可缩小到某个分组，并可流入工作流。** **概览**新增与上一期间对比的趋势箭头，以及指向不活跃成员和无人打开的仪表板和应用的 **Highlights** 列表。已停用的成员不会被计入或列为不活跃成员。**分组**会将**概览**、**内容**和不活跃列表限定为某个安全组的成员，日期范围新增**上个月**和**本月**，由每个选项卡共用，并随您的账户记住。现在每个数字都有说明，表使用**成员**和**区域**等通俗名称，按 Enter 可打开行，加载和错误提示更清晰，最后一个**漏斗**步骤会显示有多少成员完成了该步骤。**Get Workspace Usage** 步骤会按计划将使用情况写入表，形式为不含成员姓名的每日或每月合计，或可直接用于报告的数据集：**成员**、**每位成员每日**、**内容**和**每位成员内容**。成员数据集包含姓名、电子邮件、分组和活动，因此可以按电子邮件将其与您自己的组织表联接，并按部门报告活动分钟数或仪表板打开次数。与 **Get Workspace Members** 一样，每次运行都会记录在安全日志中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表并设置项目的默认仪表板受众。** `publish_manage` 会取消发布表及其已发布的视图，以及没有图表使用的仪表板数据集；图表仍在使用的数据集会保留，当报表视图基于已发布的视图构建时，该视图和数据集也会保留，而表仍会取消发布。`project_upsert` 设置 `dashboard_default_audience`，即项目中新仪表板共享给的分组，`[]` 表示清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Git 应用会列出您的存储库，并告诉您可以做什么。** 应用列表中的 **Git** 显示您的角色（**管理员**、**贡献者**或**查看者**）以及工作区的存储库，每个存储库都有说明、最后更新日期、带复制按钮的克隆地址以及**打开**。**Set up Git on your computer** 卡片会逐步介绍安装 Git、创建令牌和克隆，**How to clone** 可重新打开它。**View all in Git** 会打开完整的 Git 界面，**Manage who can push** 会打开分组管理。访问级别为**查看者**、**贡献者**（将应用代码推送到 `apps`）或**管理员**（推送到所有位置，包括 `udfs`），查看者最多可看到三位工作区管理员以便询问。新的 **Git Contributors** 分组授予贡献者级别，并且可以作为默认分组，因此新成员会自动获得；**Git Administration** 授予管理员级别。成员的 **Git** 选项卡显示其 Git 用户名、级别以及授予该级别的分组。成员的 Git 账户随其成员资格变化：停用或移除成员会在大约一小时内阻止其 Git 账户（包括令牌和 SSH 密钥），重新激活后会解除阻止，其存储库和历史记录得以保留。使用单点登录登录 Git 会打开该成员自己的账户。贡献者不会直接在工作区的 Git 组织中创建存储库；存储库通过 PlaidCloud 创建。应用窗口显示**存储库**部分，UDF 有**打开**，Git 有指向您的工作区的 **← Back to** 链接。平台创建的每个存储库（包括应用存储库以及内置的 `apps` 和 `udfs` 存储库）都可由工作区的每位已登录成员读取，因此成员无需逐个存储库设置即可打开和重新发布应用。Git 管理员仍然可以将存储库设为私有，这会使其不出现在存储库选择器中，并阻止成员从中发布，也阻止运行其中存储的基于 Git 的 UDF 代码。请参阅 [PlaidCloud Git](/zh-cn/guides/git/#打开-git) 和[谁可以看到存储库](/zh-cn/guides/connections/plaidcloud-git/#谁可以查看存储库)。
- **Cost to Serve 和 Operational Transfer Pricing 模板基于 Common Finance Model 构建。** 从 **Cost to Serve** 启动项目，可按您为每个部门设置的作业和动因将运营费用分摊给客户，并查看每位客户扣除服务成本后的利润，且可追溯到总账。从 **Operational Transfer Pricing** 启动，可对照政策区间检验各实体的利润水平（销售回报率、成本加成净额或转售减价），并通过补差使区间外的实体回到目标。销售回报率为 EBIT 除以被测方销售额。请参阅 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/) 和 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)。
- **OneStream 和 Anaplan 为 Data Foundation 提供数据，OneStream 还有读取步骤。** Data Foundation 通过 OneStream 管理员构建的数据适配器读取 OneStream 合并结果，通过导出操作读取 Anaplan 计划，并将集团损益表与它们核对。新的 **OneStream: Read Adapter** 步骤会读取适配器（每个合并成员调用一次），并将结果写入任意工作流中的表。请参阅[面向 Data Foundation 的 OneStream](/zh-cn/guides/connections/onestream-for-data-foundation/)、[Anaplan 作为 Data Foundation 数据源](/zh-cn/guides/connections/anaplan/#将-anaplan-作为-data-foundation-源)和 [OneStream: Read Adapter](/zh-cn/reference/workflow-steps/onestream/onestream-read-adapter/)。

## 变更

- **PlaidCloud 的 Web 应用和 Python 客户端库使用 REST API，JSON-RPC 已弃用。** Web 应用将其请求发送到 REST API。使用 `plaidcloud-rpc` 1.25.0 或更高版本时，`SimpleRPC` 调用会转到 REST API，您的代码无需更改；REST API 尚未涵盖的调用，或仍使用较旧版本的工作区，仍像以前一样使用 JSON-RPC。JSON-RPC 将在后续版本中移除，因此请将脚本和笔记本升级到 `plaidcloud-rpc` 1.25.0 或更高版本，并针对 REST API 编写新的集成。请参阅[命令行](/zh-cn/reference/cli/jupyter/command-line/)。
- **步骤遵循其项目的连接环境，除非您将其固定到另一个环境。** 在环境之间切换项目（例如 QA 和生产）会使每个步骤随之切换。必须停留在同一环境的步骤可以改用**固定环境**：表单会用警告标记它，其日志会记录每次在项目环境之外的环境上的运行，切换项目时会列出不会随之变化的步骤。ERP 过账步骤始终使用项目的环境。当项目、固定了环境的步骤或代理正在使用某个环境时，该环境不能被删除，代理表单中的字段现在是**此代理服务的环境**。请参阅[将步骤固定到单一环境](/zh-cn/guides/projects/managing-projects/#将步骤固定到单一环境)。
- **步骤表单遵循统一的布局。** 选项卡采用标准名称和标准顺序：常规、设置、源、列、筛选器、输出和高级，ERP 过账表单上还有抬头列和行项目列。必填字段以 * 标记，表单仅会因步骤所需的内容而阻止保存。
- **复制项目会分别选择表数据和维度成员，复制数据更快，并保留私有副本的 ERP 写入授权。** 在 **Data to copy** 下，选择**表数据**（**无表数据**（默认）、**完整**或**样本**），并另外选择 **Copy dimension members**，它默认开启，因此不含表行的副本仍带有已填充的维度，并且制作很快。**完整**和**样本**复制会同时复制多个表，因此表很多的项目完成得更快。**复制结果**会将每个维度的结果与表一起列出，**Retry failed items** 会一并重试失败的表和维度。带数据创建的新副本仅对您私有，并保留您自己能够授予的源项目 ERP 写入授权；如果源项目为实时过账，副本将以模拟模式创建，因此在您将其切换为实时之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **表的详细信息面板会更快地显示使用它的步骤。** 选择另一个表会立即清除上一个表的步骤，共享此项目数据的其他项目中的步骤会在其余步骤之后稍等片刻再添加，而不是拖慢整个面板。请参阅[查看表的使用位置](/zh-cn/guides/projects/managing-tables-and-views/#查看表的使用位置)。
- **每个列表中的行操作工作方式相同。** 可从行首的 **⋯** 按钮、右键单击行或工具栏的**操作**菜单打开行菜单。它始终先列出**打开**、**详细信息**和**编辑**，然后是该列表自己的操作，最后是**删除**或**移除**，不适用于某行的操作会以灰色显示在原位。**Enter** 和 **Del** 会显示在它们所执行的项目上。行只有单一操作的列表会显示该操作的图标，而不是 **⋯**，仪表板、应用和笔记本再次显示**打开**图标。请参阅[行操作菜单](/zh-cn/guides/dashboards/using-dashboards/#行操作菜单)。
- **应用选项卡图标统一为一套**，同时适用于浅色和深色模式。
- **新的加载屏幕。** PlaidCloud 打开时会显示更简洁的加载屏幕，并跟随您的浅色或深色主题。从空闲状态唤醒的 Panel 或 Dash 应用会显示其依次经历**正在启动**、**正在准备**和**正在加载应用**的进度；如果未能启动，会说明停在了哪一步，并提供**重试**。请参阅[使用 Panel 应用](/zh-cn/guides/panel-apps/using/)。
- **未设置验证选项的已保存 ERP 写入步骤将以仅验证方式打开。** 这涵盖 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post 以及 Xero 导出。明确设置为实时运行的步骤仍保持实时。
- **长时间运行的作业在各处以相同方式显示进度。**
- **工作流如实地停止、失败和报告。** 停止工作流会停止它启动的所有内容，无法完成的运行或步骤会带着原因失败而不是挂起，运行状态与实际运行的内容一致。
  - **停止工作流会停止它启动的所有内容，无法完成的运行或步骤会失败而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中后续的导入和维度加载可以正常启动，它还会停止该工作流排队或正在运行的连接器（Singer）同步。如果步骤的作业无法启动，该步骤会带着原因失败，而不是永远等待：约 40 分钟内没有工作进程启动它、工作进程启动后又消失、其 Pod 在大约 20 分钟内一直处于 Pending、其镜像在大约 5 分钟内无法拉取，或者在大约 20 分钟内没有创建 Pod。约 30 分钟内没有任何运行器接手的连接器同步会失败，并给出指明该同步的消息。步骤等待工作进程期间，其状态消息显示“正在等待工作进程…”及已等待的分钟数，工作开始后即清除。停止宏会停止它所有正在运行的副本，而停止其中一个副本，或 **Macro Concurrent** 步骤放弃一个停止响应的副本，会使调用它的工作流继续运行。仅在其他工作流内部运行的宏，在工作流列表中显示为**正在运行**，可使用**停止**，并显示每个步骤最近一次运行的状态、开始时间和结束时间。服务器丢失的运行会以失败结束，运行 12 小时后仍在运行的运行会失败并显示“运行失败：在 12 小时上限时仍在运行。请重新运行该工作流。”请参阅[运行工作流](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
  - **恢复、运行历史和运行状态与实际运行的内容一致。** 恢复父工作流会运行子工作流剩余的所有内容，即使您单独重新运行过子工作流的某个步骤也是如此，并且一次运行中对子工作流的每次调用都有各自的运行历史条目。因服务器停止而重新启动的步骤会在其日志中说明，`workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续运行的步骤，而不是将运行报告为正常。请参阅[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)和[出错后继续](/zh-cn/guides/workflows/continue-on-error/)。
  - **步骤错误会显示其自身的消息。** PlaidCloud 未预料到的错误显示为“该步骤因意外错误（*类型*）而停止：*消息*”。启动器上的**需要关注**卡片会以一行显示错误，并省略此后已被删除的工作流的运行。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。
  - **未完成的 ERP 提取会使其步骤失败，并可通过恢复继续。** 当 **SAP：临时提取**在其行数或时间限制处暂停，或其代理未及时回复，或者在步骤停止等待时 Salesforce、Oracle Fusion 批量或 HFM/FCCS 导出作业仍在运行，该步骤会失败，这样其后的步骤就不会在不完整的表上运行。恢复工作流或重新运行该步骤，提取会在同一作业上从停止处继续。请参阅[运行限制](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制)和 [Salesforce：查询对象](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
  - **取消导出会停止其在仓库中的查询。** 取消导出或下载（包括通过停止其工作流取消）时，在 Lakehouse v2、Snowflake、Databricks、PostgreSQL 和 Greenplum 上，读取其数据的查询也会停止，导出到远程数据库会停止读取其源，而不是一直运行到结束。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **会话过期后打开的仪表板链接，会在您登录后带您进入该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝无法识别的字段**并在错误中指明它，而不是忽略。`workflow_upsert` 接受 `memo`，并接受 `description` 作为其另一个名称。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据会直接进入该账户的存储桶，使用该账户自己的凭据写入，而不是每一行都先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式与以前相同。请参阅 [Export to Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息为何未发送。** 步骤的错误会指明它尝试访问的服务器，对于 Slack 和 Teams 还会指明连接，并说明出了什么问题：例如，Slack 不再识别该 webhook、无法向该频道发布、找不到服务器或服务器在 60 秒内没有响应，或者连接已被删除。Slack 或 Teams 的 webhook URL 绝不会显示，因为任何持有它的人都可以冒充您的集成发布消息。请参阅 [Notify via Slack](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。
- **项目服务账户的访问令牌至少有效 24 小时。** 以项目身份运行的工作流作业（例如 UDF 步骤）获得的令牌有效期为 24 小时。较短的有效期会在工作区升级时提高，您设置的较长有效期会保留。
- **工作区的组织、所有者、版本通道和版本由 PlaidCloud 设置，您可以选择其数据中心。** 在控制平面中，您创建的工作区归您所有，并放置在 PlaidCloud 设置的版本通道上，您可以从注册时提供的区域中选择其 **Data Center**。编辑工作区时，组织、所有者、版本通道和版本为只读。使用 **Set Version** 更改版本，如需迁移工作区、更改其所有者或通道，或将其固定，请联系 PlaidCloud 支持。请参阅[工作区配置](/zh-cn/administration/control-plane/workspace-configuration/#主要设置)。

## 已修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的 slug，或者无效的存储类型或过账模式，现在会返回指明问题的消息，而不是通用的服务器错误。通过 REST API 时为 400 而不是 500，通过 AI 助手或 MCP 时为无效参数错误。
- **REST API 的维度值请求现在可以正常工作。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 曾被当作网格请求来应答并被拒绝为无效。它现在会为 `value_columns` 中的每一列返回一个聚合值，而网格（行筛选器和列筛选器的每一对组合对应一个值）有了自己的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再拖慢其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，每一项都可能使同一服务器正在处理的所有其他请求暂停，直到其完成。它们现在与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口还高，因此**创建**和**更新**按钮可能够不到。现在表单可以滚动，按钮保持在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 以前对这种大小的文件，这些操作都会失败，移动或重命名包含这种文件的文件夹同样会失败。
- **在 Lakehouse v2 上，表的行数反映刚刚写入的内容。** 写入表的步骤或导入可能记录的是写入之前的行数，因此刚加载的表显示 0 行，导入可能报告已导入 0 行。现在会在新行在各处可见之后再读取行数，因此其后的步骤也能读取它们。将表切换到另一个分支，或将分支合并到其中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前的运行实际留下的内容进行比较。** 步骤的空值通常是在步骤清空其表以便重新填充之后才被统计，因此其之前的运行看起来没有空值，而一直部分为空的列被报告得好像刚刚才变空。现在每次运行都按步骤留下的表状态来统计。此前记录的计数无法与正确的计数区分，因此不会使用：每个步骤的空值检查都会重新开始其历史，并在统计满五次运行之前报告为未检查。行数和值分布检查也不再将另一个步骤在其完成两秒之后对同一个表所做的写入记在该步骤名下。请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **Data Foundation 保留倒数汇率和小数阈值的精度。** 由于您的汇率是从报告货币报价到另一种货币，PlaidCloud 取倒数后的汇率可能被舍入到六位小数，导致汇率很小的货币（例如印尼盾）的金额偏差约 1%。倒数汇率现在保留 12 位小数。带小数的 `group_amber` 或 `group_red` 阈值（例如 `0.5`）曾被舍入为整数。您的下一次加载会使用精确值。请参阅[汇率](/zh-cn/guides/projects/data-foundation/#汇率)。
- **已停用成员的警报和摘要会停止。** 所有者已被停用的 Panel 应用警报或摘要曾继续检查和发送。现在它在所有者被停用期间暂停，在重新激活后恢复。请参阅[警报和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
- **向 REST API 请求已删除的连接会返回 404。** 请求已被删除的连接或不存在的 ID 时，曾返回通用服务器错误（500）。现在返回 404，并附带指明连接 ID 的消息。
- **通过 AI 助手和 MCP 按模板导出表现已可用。** `table_data_export` 的 `templated` 格式在指定表时会失败。现在它会使用您的模板导出该表，且仅限您有权读取的行。在模板中，表的行以其表 ID 命名，并将每个 `-` 写作 `_`。
- **Amazon S3 及 S3 兼容的文档账户现在会保留区域。** 以前保存这类账户时，您输入的**区域**会被丢弃，因此下次打开该账户时该字段为空。现在区域会被保存。对于在此修复之前保存的账户，请重新输入区域并保存。请参阅[添加 AWS S3 账户](/zh-cn/guides/documents/adding-accounts/add-aws-s3-account/)。

## 安全

- **密码登录需要验证器应用，并且密码更强。** 使用 PlaidCloud 密码登录的成员，会在下次登录时被要求设置验证器应用，此后每次都要输入其验证码。单点登录、Google、Microsoft 和 GitHub 登录、API 令牌以及服务账户保持不变。新密码至少需要 12 个字符，不能是您的用户名或最近六个密码之一，并且在多次登录失败后，账户会被锁定一小段时间。您的工作区已有的更严格规则会保留。请参阅[成员身份验证](/zh-cn/administration/access/member-authentication/)。
- **连接可指向公共和专用网络地址。** 连接不能指向环回地址、链路本地地址或云元数据地址，错误会指明主机及其解析到的地址。您专用网络上的地址不受影响。请参阅[连接无法访问的地址](/zh-cn/guides/connections/create-connection/#连接无法访问的地址)。
- **已保存的连接凭据仅向能够编辑连接或工作流的成员显示。** 通过 REST API 和 MCP，已保存连接的密码、令牌和密钥会对其他成员进行掩码处理，他们仍然可以打开和浏览该连接。请参阅[谁可以看到连接的凭据](/zh-cn/guides/connections/create-connection/#谁能看到连接的凭据)。
- **应用构建在运行时无法访问您工作区的 Git 凭据。**
- **代理的私钥仅向能够编辑代理的成员显示。** 通过 REST API 和 MCP，该密钥不再出现在代理列表或详细信息中，代理表单仅向能够编辑代理的成员显示**私钥**和**查看 RPC 配置**。服务账户、项目和代理令牌以及 AI 委托令牌无法检索该密钥或 RPC 配置。正在运行的代理不受影响，公钥仍会显示。请参阅[获取代理凭据](/zh-cn/reference/cli/plaidlink/agents/#获取代理凭据)。
- **代理下载链接有效期为一小时。** 开启 **Use PlaidCloud Proxy Download** 时，链接过期后请重新打开下载以获取新链接。请参阅[服务](/zh-cn/administration/control-plane/workspace-configuration/#服务)。
- **将人员添加到安全组须遵循您所拥有的权限。** 当您拥有安全组授予的所有权限时，才可以将成员添加到安全组、选择成员的分组或邀请架构师。工作区管理员不受限制。请参阅[管理安全组](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理安全组)。
- **连接的所有者或工作区管理员可以更改其设置并将其开启或关闭。** 通过 REST API、JSON-RPC 以及 AI 助手或 MCP 更改连接的设置，需要其所有者之一，对于没有所有者的连接则需要工作区管理员。启用、禁用、锁定和解锁连接需要所有者或工作区管理员，指定多个连接的请求仅在您能够更改所有这些连接时才会生效。只有工作区管理员可以选择工作区的默认 AI 连接，并且只有在管理员拥有的连接或没有所有者的连接都不可能成为默认连接时，成员拥有的连接才会成为默认连接。请参阅[编辑连接](/zh-cn/guides/connections/create-connection/#编辑连接)和 [LLM 提供商](/zh-cn/integrations/ai-architecture/llm-providers/#连接包含的内容)。
- **行访问适用于成员对受限表所做的一切操作。** 在仪表板、他们自己的 SQL 以及加载中，成员只能看到和更改其授权所允许的行。
  - **项目架构师在仪表板中可以看到行受限表的所有行**，与他们在 Analyze 中看到的一致。撤销架构师访问权限会在仪表板中立即生效，无论您是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、还原较早的项目版本，还是删除安全组。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
  - **受行访问限制的成员可以运行自己的 SQL 查询并导出结果。** 在具有行访问的项目上，非架构师成员通过查询屏幕上的自有查询，恰好得到其授权所允许的行，并可将其导出为 CSV、Excel 或 JSON，同时显示**行数受您的访问权限限制**提示；此前这些操作会被拒绝。包含百分号（`%`）的授权值现在可在查询屏幕上返回其行，并且将此类查询下载为 CSV 也可以正常工作。他们在 Snowflake 或 Databricks 上自己编写的自由格式 SQL、从 Postgres 系列仓库导出自己的 SQL，以及读取某个快照时点的受治理表仍会被拒绝，并且视图必须以原名保留受治理的列才能被筛选。请参阅[行访问与您自己编写的查询](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问与您自己编写的查询)。
  - **保存行访问会保留其来源中不存在的已授权值。** 当表中没有包含该值的行、维度中没有该成员或列表中没有该值时，安全组被授予的值会保留在网格中并带有标记。**保存**会询问是保留还是移除每个这样的值。请参阅[行访问网格](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
  - **向行受限表写入 DataFrame、保存记录和清除，只会更改您能看到的行。** 当行访问限制了您的行时，使用 Python 客户端向受限表写入 DataFrame 或将其清除，或通过 REST API 向其保存记录或将其清除，只会更改您自己的行，包含您访问权限之外的行的加载会在任何更改之前被拒绝，并指明其发现的值。项目架构师、能看到所有行的成员和工作流运行会写入整个表。个人对任何表所做的每一次此类写入都会记录在安全日志中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
  - **对行受限表进行导入、复制、还原和删除，需要您能看到每一行。** 当行访问限制了您的行时，将文件导入受限表、从另一个项目将表复制到其中、切换或合并其分支、还原它、删除它、在删除后将其恢复，或任何其他替换整个表的操作，只有在您能看到该表的每一行时才会运行；否则会被拒绝，并且不会有任何更改。与其他加载一样，通过 REST API 保存表的行只会更改您自己的行。项目架构师、能看到所有行的成员和工作流运行不受影响，这些操作同样会记录在安全日志中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
- **只有账户的所有者才能还原其较早的版本。** 将文档账户还原到较早的版本、保留或释放版本以及进行备份，都需要该账户的所有者之一，并且在系统托管的账户上均不可用。查看账户的版本历史需要具有该账户的访问权限。
- **`query_run` 运行只读语句。** AI 助手和 MCP 客户端使用的 `query_run` 工具接受一条 SELECT 或 WITH 语句、对其中一条的 EXPLAIN，或 SHOW；任何其他语句都不会运行。如需更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 遵循相同的规则。通过 REST 和 JSON-RPC API，对于无法更改项目数据的成员，它也适用于运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库，以及使用您自己的查询导出表数据；被拒绝的查询会返回 403。Explain Analyze 会运行查询以进行测量，因此在查询日志和 Lakehouse 中，它只接受读取数据的查询，并且在具有行访问的项目上，只有项目架构师可以从查询日志中运行它。
