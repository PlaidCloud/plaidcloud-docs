## 新增

- **PlaidXL 可在 Excel 中生成报表、钻取、解释并做计划。** **PlaidCloud** 功能区选项卡分为 **连接**、**插入**、**刷新**、**Drill**、**写入** 和 **共享**，常用命令也出现在 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡中，主要命令还有可自行修改的键盘快捷键。登录前运行的命令会先打开登录界面，登录后自动运行一次；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次点击即可生成报表。** **报表** 选项卡根据一张表生成实时报表，一个维度逐级钻取到行，另一个维度横跨各列，每个交叉点是一个 `CELL` 值。**Build my first report** 会用您自己的数据生成示例。钻取时，报表会整行整列地插入和删除，您输入的值、备注和格式会跟随所在的行。请参阅 [Build a Report](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 可将节点、维度标题或报表值变成实时的 `DRILL` 公式，并为您编辑该公式。**Custom drill** 会在插入前预览行，成员选取器可插入成员，或为单元格添加节点子级的下拉列表。`DRILL` 可指定要排除或展开的节点，也可以横跨一行运行。请参阅 [Drill, Pick Members and Explain Numbers](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释一个数字。** **Explain this number** 会显示一个值的计算方式、是否与 PlaidCloud 当前数据一致，以及它来自哪张表和哪个工作流步骤。**Show detail rows** 会把值背后的行放到单独的工作表中，并检查这些行的合计是否一致。
  - **Excel 中的受管指标。** `PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 会按仪表板中的显示方式返回业务指标，**Metric...** 会列出项目的指标及其当前值。请参阅 [Metrics](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中直接输入即可做计划。** 在 `CELL` 值上输入数字，该数字就会写入 PlaidCloud：可按比例分摊、平均分摊或按另一成员的形态分摊，可按金额或百分比调整，已锁定的单元格不受影响。平均值、中位数、最小值、最大值、标准差和方差单元格也接受输入值。**Undo last write** 会按从新到旧的顺序撤销输入的值和保存。请参阅 [Type Values Into PlaidCloud](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新需要的部分。** 可刷新一个工作表、一个选区或所有表，每张表的进度和 **取消** 都显示在任务窗格中，也可以只重新计算 PlaidXL 公式。检索到的表会成为按数据类型设置格式的 Excel 表格，刷新时保留您自己的列和数字格式，并在原位置刷新。再次检索同一张表不会把它两次加入刷新列表，**Stop refreshing** 可将其移出，维度会随表一起刷新。请参阅 [Refresh All Tables](/zh-cn/reference/cli/plaidxl/retrieve/#刷新所有表)。
  - **保存立即写入，且可撤消。** **Save to PlaidCloud** 无需确认即可写入，说明执行了什么，并提供 **撤消**。带筛选器检索的工作表、明细行工作表，或访问权限只覆盖部分行的用户，只会替换对应的行，其他人的行会保留。请参阅 [Save a Table to PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在 **Weave** 选项卡上，可用日常语言要求生成报表、公式、钻取或表，也可以选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只修改工作簿，替换您已输入的内容前会先询问，每项更改在重新加载窗格前都可以还原。请参阅 [Ask Weave in Excel](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享单个工作表或整个工作簿的纯值副本。** **Convert to values** 可转换整个工作簿、单个工作表，或转换后无法恢复的值；重命名工作表后，**Restore PlaidXL formulas** 仍然有效。
- **步骤表单上的预览。** 导入：SQL、Execute: SQL、提取 SQL、导出：SQL 和 Salesforce Query 无需运行步骤即可显示最多 100 行，Anaplan 的视图和列表读取会显示它们将生成的列和类型。在 **源** 选项卡上点击 **预览**。变量会按运行时的方式填入，但不支持 `{x:>9}` 这样的变量格式。预览只运行标准 SQL 函数，否则会提示您运行该步骤。锁定的项目以及基于代理的 Execute SQL 步骤不可用。请参阅 [Import SQL](/zh-cn/reference/workflow-steps/import/import-sql/) 和 [Extract SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告会显示变化、可缩小到某个分组，并可接入工作流。** **概览** 新增与上一期间对比的趋势箭头，以及 **Highlights** 列表，指出不活跃的成员，以及无人打开的仪表板和应用。**分组** 可将 **概览**、**内容** 和不活跃列表限定在某个安全组的成员内；日期范围新增 **Previous month** 和 **This month**，由所有选项卡共用，并随您的账户记住。现在每个数字都有说明，表格使用 **成员** 和 **Area** 这样的通俗名称，按 Enter 即可展开行，加载和错误提示更清晰，最后一个 **漏斗** 步骤会显示有多少成员完成了它。新的 **Get Workspace Usage** 步骤按计划将每日或每月的使用量合计写入一张表，不含成员姓名；与 **Get Workspace Members** 一样，每次运行都会记录在 **安全日志** 中。请参阅 [使用情况报告](/zh-cn/administration/access/usage-reports/) 和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表，并设置项目的默认仪表板受众。** `publish_manage` 会取消发布一张表，同时取消其已发布的视图和没有图表使用的仪表板数据集；仍有图表使用的数据集会保留，当报表视图建立在已发布的视图之上时，该视图和数据集也会保留，但表仍会被取消发布。`project_upsert` 可设置 `dashboard_default_audience`，即项目中新仪表板所共享的分组，设为 `[]` 则清除。请参阅 [Unpublish](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布) 和 [Set the Default Audience Through the AI Assistant or MCP](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Git 应用会列出您的存储库，并告诉您可以做什么。** 应用列表中的 **Git** 会显示工作区的存储库及其描述、默认分支和最近更新时间，**Copy clone URL** 附有使用访问令牌克隆的简短提示，还有 **View all in Git**。访问级别为 **读取**、**Contributor**（将应用代码推送到 `apps`）或 **管理员**（可推送到所有位置，包括 `udfs`），读取级别的成员会看到最多三位可以联系的工作区管理员。新的 **Git Contributors** 分组授予 Contributor，并可设为默认分组，这样新成员会自动获得；**Git Administration** 授予管理员。成员的 **Git** 选项卡会显示其 Git 用户名、级别以及授予该级别的分组。应用窗口会显示 **存储库** 部分，UDF 有 **Open**，Git 中还有返回工作区的 **← Back to** 链接。请参阅 [PlaidCloud Git](/zh-cn/guides/git/#打开-git)。
- **移动端 Weave 的语音输入只需轻点一下。** 点击麦克风，说出问题，停止说话后 Weave 会发送一次。再次点击麦克风可提前停止，如果没有听到声音，它会自动关闭。如果您在说话中途离开 **Weave** 选项卡或将应用切到后台，您说的话会保留在问题框中而不发送，方便您检查。运行、暂停、停止和恢复的确认按钮会忽略误触的连点。需要应用版本 1.3.0 或更高版本。请参阅 [Use Your Voice](/zh-cn/guides/mobile-app/weave-on-mobile/#使用语音)。

## 变更

- **步骤表单采用统一布局。** 选项卡采用标准名称和标准顺序：常规、设置、源、列、筛选器、输出和高级，ERP 过账表单另有表头列和行项目列。必填字段以 * 标记，表单只会因步骤所需的内容而阻止保存。
- **复制项目可分别选择表数据和维度成员，复制数据更快，并保留私有副本的 ERP 写入授权。** 在 **Data to copy** 下，选择 **表数据**（**No table data**（默认）、**完整** 或 **Sample**），另外还可选择 **Copy dimension members**（默认开启），因此不复制表行的副本仍会带有已填充的维度，创建起来也很快。**完整** 和 **Sample** 复制会同时复制多张表，所以包含很多表的项目完成得更快。**复制结果** 会在表旁边列出每个维度的结果，**Retry failed items** 会同时重试失败的表和维度。带数据创建的新副本仅您本人可见，并保留源项目中您自己有权授予的 ERP 写入授权；如果源项目以 Live 过账，副本会以 Simulate 模式创建，因此在您将其切换为 Live 之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅 [Choosing How Much Data to Copy](/zh-cn/guides/projects/managing-projects/#选择复制多少数据) 和 [ERP Write Authorizations in the Copy](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **行操作菜单（⋯）位于每个网格行的最左侧。**
- **应用选项卡图标统一为一套**，浅色和深色模式均适用。
- **未设置校验选项的已保存 ERP 写入步骤将以仅校验方式打开。** 涵盖 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post，以及 Xero 导出。明确设为实时运行的步骤仍保持实时。
- **长时间运行的作业在各处以相同方式显示进度。**
- **停止工作流会停止它启动的所有内容，无法完成的运行或步骤会失败而不是卡住。** 停止会取消仍在排队的导入和维度步骤，因此工作区中后续的导入和维度加载可正常启动，同时也会停止该工作流中排队或正在运行的连接器（Singer）同步。如果步骤的作业无法启动，该步骤会失败并给出原因，而不是无限等待：约 40 分钟内没有工作器启动它、工作器启动后消失了、其 Pod 卡在 Pending 状态约 20 分钟、镜像约 5 分钟无法拉取，或约 20 分钟内没有创建 Pod。约 30 分钟内没有运行器接手的连接器同步会失败，并给出指明该同步的消息。步骤等待工作器时，其状态消息显示“Waiting for a worker…”及已等待的分钟数，工作开始后消息会清除。停止宏会停止它的每个运行中的副本，仅在其他工作流内运行的宏会在工作流列表中显示为 **正在运行**，可使用 **停止**，并显示各步骤最近一次运行的状态、开始时间和结束时间。服务器丢失的运行会以失败结束，运行超过 12 小时仍未结束的运行会失败，并显示“Run failed: still running at the 12-hour limit. Re-run the workflow.”。请参阅 [Run a Workflow](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
- **恢复、运行历史和运行状态与实际运行的内容一致。** 恢复父工作流时，会运行子工作流剩余的全部内容，即使您已单独重新运行过子工作流的某个步骤；同一次运行中对子工作流的每次调用都有各自的运行历史记录。因服务器停止而重新启动的步骤会在日志中说明，`workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续运行的步骤，而不是将运行报告为正常。请参阅 [Pause, Stop, and Resume](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复) 和 [Continue on Error](/zh-cn/guides/workflows/continue-on-error/)。
- **步骤错误会显示其自身的消息。** PlaidCloud 未预料到的错误显示为“The step stopped on an unexpected error (*type*): *message*”。启动器上的 **需要关注** 卡片会以一行显示错误，并省略已被删除的工作流的运行。请参阅 [Managing Step Errors](/zh-cn/guides/workflows/managing-step-errors/)。
- **未完成的 ERP 提取会使其步骤失败，恢复后可继续。** 当 **SAP：临时提取** 在行数或时间限制处暂停，或其代理未及时答复，或 Salesforce、Oracle Fusion 批量或 HFM/FCCS 导出作业在步骤停止等待时仍在运行，该步骤会失败，这样后续步骤不会基于部分数据的表运行。恢复工作流或重新运行该步骤后，提取会在同一作业上从停止处继续。请参阅 [Run Limits](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制) 和 [Salesforce: Query Object](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST Request Step](/zh-cn/guides/workflows/rest-request-step/)。
- **项目架构师在仪表板中可以看到行受限表的所有行**，与他们在 Analyze 中看到的一致。撤销架构师访问权限会立即在仪表板中生效，无论是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、恢复项目的早期版本，还是删除安全组。前架构师不再能看到行受限数据的所有行。请参阅 [Managing Row Access](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
- **会话过期后打开的仪表板链接，在您登录后会带您进入该仪表板。** 请参阅 [Using Dashboards](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝无法识别的字段**，并在错误中指出该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为其另一个名称。请参阅 [Unknown Fields Are Refused](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据会使用该账户自己的凭据直接写入账户的存储桶，而不是让每一行先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式不变。请参阅 [Export to Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会指出它尝试连接的服务器，对于 Slack 和 Teams 还会指出连接，并说明出了什么问题：例如 Slack 不再识别该 Webhook、无法向该频道发帖、找不到服务器或服务器在 60 秒内没有响应，或连接已被删除。Slack 或 Teams 的 Webhook URL 永远不会显示，因为任何拥有它的人都可以冒充您的集成发帖。请参阅 [Notify via Slack](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。

## 修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的 slug，或无效的存储类型或过账模式，现在会返回指明问题的消息，而不是通用的服务器错误。通过 REST API 返回 400 而不是 500，通过 AI 助手或 MCP 则是无效参数错误。
- **REST API 的维度值请求现在可用。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 曾被当作网格请求处理并被拒绝为无效。现在它会为 `value_columns` 中的每一列返回一个聚合值，而网格，即每对行筛选器和列筛选器对应一个值，有了自己的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再阻碍其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，每一项都可能让同一服务器正在处理的所有其他请求暂停，直到它完成。现在它们与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口还高，因此 **创建** 和 **更新** 按钮可能够不到。现在表单可滚动，按钮固定在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 过去这些操作对这种大小的文件都会失败，移动或重命名包含这种文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚写入的内容。** 写入表的步骤或导入可能记录的是写入之前的行数，因此刚加载的表显示 0 行，导入可能报告导入了 0 行。现在会在新行在各处都可见之后再读取行数，因此后续步骤也能读到这些行。将表切换到另一个分支，或将分支合并到表中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的结果进行比较。** 过去步骤的空值往往是在该步骤清空表以重新填充之后才被统计，因此它之前的运行看起来没有空值，而一直部分为空的列会被报告为刚刚变空。现在每次运行都按步骤留下的表来统计。之前记录的计数无法与正确的计数区分，因此不予使用：每个步骤的空值检查会重新开始记录历史，并在统计满五次运行之前报告为未检查。行数和值分布检查也不再把另一个步骤在该步骤完成两秒之后对同一张表的写入算到该步骤名下。请参阅 [What Weave Checks](/zh-cn/guides/ai-assistant/weave-findings/)。
- **通过 REST API 请求已删除的连接会返回 404。** 请求已被删除的连接或不存在的 ID 时，过去会返回通用服务器错误（500）。现在返回 404，并附带指明连接 ID 的消息。

## 安全

- **保存行访问时会保留其来源已不再包含的已授予值。** 过去，一旦表中没有包含某个值的行、维度已不再有该成员或列表已不再包含它，安全组已被授予的该值就会在下一次保存时从授权中消失。这样，没有勾选任何值的分组会退回到 **Everyone else**，这可能意味着所有行。现在该值会保留在网格中并带有标记，**保存** 时会询问是保留还是移除。请参阅 [The Row Access Grid](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
- **只有账户的所有者才能恢复其早期版本。** 将文档账户恢复到早期版本、保留或释放某个版本，以及进行备份，现在都要求您是该账户的所有者之一，系统管理的账户上则这些操作都不可用。查看账户的版本历史需要有该账户的访问权限。
- **只应读取数据的查询无法再更改数据。** AI 助手和 MCP 客户端使用的 `query_run` 工具只运行读取数据的语句，即一条 SELECT 或 WITH 语句、对其执行的 EXPLAIN，或 SHOW，并拒绝其他任何语句，不会运行它们。要更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 遵循同样的规则。通过 REST 和 JSON-RPC API，对于无法更改项目数据的成员，该规则同样适用于运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库，以及用自己的查询导出表数据；被拒绝的查询会返回 403。**Explain Analyze** 会运行查询来测量它，因此在查询日志和 Lakehouse 中，它现在只接受读取数据的查询；在设有行访问的项目上，只有项目架构师可以从查询日志中运行它。
