## 新增

- **步骤表单上的预览。** Import: SQL、Execute: SQL、Extract: SQL、Export: SQL 和 Salesforce Query 无需运行步骤即可显示最多 100 行，Anaplan 的视图和列表读取会显示它们将生成的列和类型。在**源**选项卡上单击**预览**。变量会按运行时的方式填充，但不支持 `{x:>9}` 这类变量格式。预览只运行标准 SQL 函数；否则会提示您运行该步骤。在已锁定的项目上，以及基于代理的 Execute SQL 步骤中不可用。请参阅[导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/)和[提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告显示变化、可缩小到某个分组，并可接入工作流。** **Overview** 新增与上一期间对比的趋势箭头，以及一个 **Highlights** 列表，指出不活跃的成员，以及无人打开的仪表板和应用。**分组**会将 **Overview**、**内容**和不活跃列表限制为某一个安全组的成员，日期范围新增 **Previous month** 和 **This month**，并由所有选项卡共用，且会随您的账户记住。现在每个数字都有说明，表格使用 **成员** 和 **Area** 这样的通俗名称，按 Enter 键即可打开行，加载和错误提示更清晰，最后一个**漏斗**步骤会显示有多少成员完成了它。新的 Get Workspace Usage 步骤会按计划将每日或每月的使用量合计写入表中，不含成员姓名，并且与 Get Workspace Members 步骤一样，每次运行都会记录在安全日志中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表，并设置项目的默认仪表板受众。** `publish_manage` 会取消发布表，连同其已发布的视图和任何没有图表使用的仪表板数据集一起取消；仍被图表使用的数据集会保留，当报表视图建立在已发布的视图之上时，该视图和数据集也会保留，而表仍会被取消发布。`project_upsert` 会设置 `dashboard_default_audience`，即项目中新仪表板所共享的分组，设置为 `[]` 则清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **移动端 Weave 中的语音只需轻点一下。** 点按麦克风，说出您的问题，停止说话后 Weave 会发送一次。再次点按麦克风可提前停止；如果一直没有检测到声音，它会自动关闭。如果您在说话中途离开 **Weave** 选项卡或将应用切到后台，您说的内容会保留在问题框中而不发送，以便您查看。运行、暂停、停止和恢复会忽略对其确认操作的意外双击。需要应用版本 1.3.0 或更高版本。请参阅[使用语音](/zh-cn/guides/mobile-app/weave-on-mobile/#使用语音)。

## 变更

- **步骤表单遵循同一布局。** 选项卡使用标准名称并按标准顺序排列：常规、设置、源、列、筛选器、输出和高级，ERP 过账表单上还有表头列和行列。必填字段以 * 标记，表单只会因步骤所需的内容而阻止保存。
- **复制项目可分别选择表数据和维度成员，复制数据更快，并会保留私有副本的 ERP 写入授权。** 在 **Data to copy** 下，选择**表数据** — **无表数据**（默认）、**完整**或**样本** — 并另外选择 **Copy dimension members**（默认开启），因此不含表行的副本仍会带有已填充的维度，并且创建速度很快。**完整**和**样本**副本会同时复制多个表，因此包含大量表的项目完成得更快。**复制结果**会将每个维度的结果与表一同列出，**Retry failed items** 会同时重试失败的表和维度。带数据创建的新副本仅对您私有，并保留源中您自己可以授予的 ERP 写入授权；如果源以 Live 方式过账，副本会以 Simulate 方式创建，因此在您将其切换为 Live 之前，任何内容都不会到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **行操作菜单（⋯）位于每个网格行的最左侧。**
- **没有验证设置的已保存 ERP 写入步骤以仅验证方式打开。** 这涵盖 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post，以及 Xero 导出。明确设置为实时运行的步骤仍保持实时。
- **长时间运行的作业在各处以相同方式显示进度。**
- **停止工作流会停止它启动的所有内容，无法启动的步骤会失败而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中之后的导入和维度加载会正常启动，同时也会停止该工作流排队或正在运行的连接器（Singer）同步。如果某个步骤的作业无法启动，该步骤会连同原因一起失败，而不是一直等待：约 40 分钟内没有工作进程启动它、工作进程启动后又消失、其 pod 约 20 分钟一直处于 Pending、其镜像约 5 分钟无法拉取，或约 20 分钟没有创建 pod。约 30 分钟内没有运行器接手的连接器同步会失败，并给出指明该同步的消息。步骤在等待工作进程期间，其状态消息显示“Waiting for a worker…”及已等待的分钟数，工作开始后即清除。请参阅[运行工作流](/zh-cn/guides/workflows/run-a-workflow/#永远不会开始的步骤)。
- **REST、Import REST 和 Import Postman 步骤会在您的工作区升级时转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **项目架构师可以在仪表板中看到行受限制的表的所有行**，与他们在 Analyze 中看到的一致。撤销架构师访问权限会在仪表板中立即生效 — 无论是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、还原项目的早期版本，还是删除安全组。前架构师不再看到行受限制数据的每一行。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
- **会话过期后打开的仪表板链接，会在您登录后带您进入该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝无法识别的字段**并在错误中指出该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为它的另一个名称。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据会直接进入该账户的存储桶，使用该账户自己的凭据写入，而不是每一行都先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式不变。请参阅[导出到 Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会指出它尝试访问的服务器，对于 Slack 和 Teams 还会指出连接，并说明出了什么问题：例如，Slack 不再识别该 webhook、无法向该频道发帖、找不到服务器或服务器在 60 秒内没有应答，或者连接已被删除。Slack 或 Teams 的 webhook URL 永远不会显示，因为任何拥有它的人都可以冒充您的集成发帖。请参阅[通过 Slack 通知](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。

## 修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的 slug，或无效的存储类型或过账模式，现在会返回指明问题的消息，而不是通用的服务器错误。通过 REST API 时返回 400 而不是 500，通过 AI 助手或 MCP 时则是无效参数错误。
- **REST API 的维度值请求可以正常工作。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 过去被当作网格请求处理并被判为无效。现在它会为 `value_columns` 中的每一列返回一个聚合值，而网格（行筛选器与列筛选器的每一对组合对应一个值）有自己专用的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再阻碍其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，都可能使同一服务器正在处理的所有其他请求暂停直到其完成。现在它们与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口还高，因此**创建**和**更新**按钮可能够不到。现在表单会滚动，按钮保持在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 这些操作过去对这种大小的文件都会失败，移动或重命名包含此类文件的文件夹也一样。
- **在 Lakehouse v2 上，表的行数会反映刚刚写入的内容。** 写入表的步骤或导入可能记录的是写入之前的行数，因此刚加载的表显示 0 行，导入也可能报告导入了 0 行。现在会在新行在各处都可见之后才读取行数，因此其后的步骤也能读到它们。将表切换到另一个分支，或将分支合并到其中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的结果进行比较。** 步骤的空值常常恰好在步骤清空其表以重新填充之后被统计，导致它之前的运行看起来没有空值，而一个一直部分为空的列会被报告为刚刚变成这样。现在每次运行都按步骤留下表时的状态统计。此前记录的计数无法与正确的计数区分，因此不再使用：每个步骤的空值检查会重新开始记录历史，并在统计满五次运行之前报告为未检查。行数和值分布检查也不再把另一个步骤在其完成两秒之后对同一个表所做的写入算到该步骤头上。请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **请求 REST API 获取已删除的连接会返回 404。** 请求已被删除的连接或不存在的 ID 时，过去会返回通用的服务器错误（500）。现在它返回 404，并附带指明连接 ID 的消息。

## 安全

- **只有账户的所有者才能还原其早期版本。** 将文档账户还原到早期版本、保留或释放某个版本，以及创建备份，现在都要求您是该账户的所有者之一，并且这些操作都不适用于系统管理的账户。查看账户的版本历史需要拥有该账户的访问权限。
- **向行受限制的表写入 DataFrame、保存记录和清除，只会更改您可以看到的行。** 当行访问限制了您的行时，使用 Python 客户端向受限制的表写入 DataFrame 或将其清除，或通过 REST API 向其保存记录或将其清除，只会更改您自己的行，并且包含您访问范围之外的行的加载会在任何更改发生之前被拒绝，并指出所发现的值。项目架构师、可以看到所有行的成员以及工作流运行，仍像以前一样写入整个表。现在，人所做的每一次这类写入，无论针对哪个表，都会记录在安全日志中。请参阅[向受限制的表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限制的表加载数据)。
