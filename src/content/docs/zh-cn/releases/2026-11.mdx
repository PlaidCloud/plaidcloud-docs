## 新增

- **PlaidXL 可在 Excel 中构建、钻取、解释和规划。** **PlaidCloud** 功能区选项卡分为**连接**、**插入**、**刷新**、**钻取**、**写入**和**共享**，常用命令还位于 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡上，主要命令都有可更改的键盘快捷键。登录之前运行的命令会打开登录界面，并在您登录后运行一次；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次点击即可构建报表。** **报表**选项卡根据表生成实时报表，一个维度向下钻取显示在行上，另一个横向显示在列上，每个交叉点是一个 `CELL` 值。**Build my first report** 会用您自己的数据生成示例。随着钻取，报表会插入和删除整行整列，您键入的值、备注和格式会跟随其所在的行。请参阅[构建报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 会将节点转为实时的 `DRILL` 公式并为您编辑，可从节点、维度标题或报表值发起。**Custom drill** 会在插入之前预览行，成员选择器可以插入成员，或为单元格添加某个节点的子级下拉列表。`DRILL` 可接受要排除或展开的节点，并且可以横跨一行运行。请参阅[钻取、选择成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释数字。** **Explain this number** 显示某个值的计算方式、它现在是否与 PlaidCloud 一致，以及它所来自的表和工作流步骤。**Show detail rows** 会将某个值背后的行放到单独的工作表中，并检查它们是否合计一致。
  - **在 Excel 中使用受治理的指标。** `PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 按仪表板所示返回业务指标，**Metric...** 会列出项目的指标及其当前值。请参阅[指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中键入即可规划。** 在 `CELL` 值上键入数字，它就会写入 PlaidCloud：按比例分摊、均分或按另一个成员的形态分摊，按金额或百分比调整，被锁定的单元格保持不变。平均值、中位数、最小值、最大值、标准差和方差单元格也接受键入的值。**Undo last write** 会按从新到旧的顺序撤销键入的值和保存。请参阅[向 PlaidCloud 键入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新您需要的内容。** 可以刷新一个工作表、一个选区或所有表，任务窗格中会显示每张表的进度和**取消**，也可以只重新计算 PlaidXL 公式。检索到的表会作为按数据类型设置格式的 Excel 表到达，刷新时保留您自己的列和数字格式，并在原位刷新。重新检索表不会将其重复加入刷新列表，**Stop refreshing** 可将某张表移出，维度会随您的表一起刷新。请参阅[刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#刷新所有表)。
  - **保存立即写入，并且可以撤消。** **Save to PlaidCloud** 无需确认即写入，说明所做的操作，并提供**撤消**。带筛选器检索的工作表、明细行工作表，或访问权限仅覆盖部分行的用户，只会替换那些行，因此其他人的行会被保留。请参阅[将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在 **Weave** 选项卡上，用日常语言请求报表、公式、钻取或表，或选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只更改工作簿，在替换您已输入的任何内容之前会先询问，并且每项更改都可以还原，直到您重新加载窗格。请参阅[在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **分享某个工作表或整个工作簿的纯值副本。** **Convert to values** 可转换整个工作簿、一个工作表，或转换为无法恢复的纯值，重命名工作表后 **Restore PlaidXL formulas** 仍然有效。
- **步骤表单上的预览。** 导入：SQL、执行：SQL、提取 SQL、导出：SQL 和 Salesforce：查询对象 无需运行步骤即可显示最多 100 行，Anaplan 视图和列表读取会显示它们将生成的列和类型。点击**源**选项卡上的**预览**。变量会按运行时的方式填入，但不支持 `{x:>9}` 这样的变量格式。预览只运行标准 SQL 函数；否则会提示您运行该步骤。它在锁定的项目上不可用，也不适用于基于代理的 Execute SQL 步骤。请参阅[导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/)和[提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告显示变化、可按分组缩小范围，并可接入工作流。** **概览**增加了相对上一期间的趋势箭头，以及指向不活跃成员以及无人打开的仪表板和应用的 **Highlights** 列表。**分组**将**概览**、**内容**和不活跃列表限制为某个安全组的成员，日期范围新增**上月**和**本月**，由所有选项卡共用并与您的账户一起记住。现在每个数字都有说明，表使用**成员**和**区域**这样的通俗名称，按 Enter 可打开行，加载和错误提示更清晰，最后一个**漏斗**步骤会显示有多少成员完成了它。新的 **Get Workspace Usage** 步骤会按计划将每日或每月使用量合计写入表中，不含成员姓名，并且与 **Get Workspace Members** 一样，每次运行都会记录在安全日志中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage 步骤](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表，并设置项目的默认仪表板受众。** `publish_manage` 会取消发布表及其已发布的视图，以及没有图表使用的任何仪表板数据集；仍被图表使用的数据集会保留，当报表视图构建在已发布的视图之上时，该视图和数据集也会保留，而表仍会被取消发布。`project_upsert` 会设置 `dashboard_default_audience`，即项目中新仪表板所共享给的分组，`[]` 会将其清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Cost to Serve 和 Operational Transfer Pricing 模板构建在 Common Finance Model 之上。** 从 **Cost to Serve** 启动项目，可按您为每个部门设置的活动和驱动因素将运营费用分摊到客户，并查看每个客户在扣除服务成本后的利润，且与总账核对一致。从 **Operational Transfer Pricing** 启动，可根据您的政策区间检验各实体的利润水平（销售回报率、成本加成净利率或转售价格减价法），并得到使超出区间的实体回到目标的补差。销售回报率是 EBIT 除以受测方销售额。请参阅 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/) 和 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)。
- **OneStream 和 Anaplan 为 Data Foundation 提供数据，OneStream 另有一个读取步骤。** Data Foundation 通过 OneStream 管理员构建的数据适配器读取 OneStream 合并结果，通过导出操作读取 Anaplan 计划，并将集团损益表与之对账。新的 **OneStream: Read Adapter** 步骤可在任意工作流中将适配器读入表，每个合并成员调用一次。请参阅[适用于 Data Foundation 的 OneStream](/zh-cn/guides/connections/onestream-for-data-foundation/)、[将 Anaplan 作为 Data Foundation 的数据源](/zh-cn/guides/connections/anaplan/#将-anaplan-作为-data-foundation-的数据源)和 [OneStream: Read Adapter 步骤](/zh-cn/reference/workflow-steps/onestream/onestream-read-adapter/)。
- **自行选择 Data Foundation 如何分摊共享成本。** **操作 > 分摊...** 会逐步引导您确定分摊哪些成本、按什么分摊、分摊到哪里，以及动因为负数时怎么办，涵盖间接费用到部门，以及部门到产品和客户，并提供单月预览，显示汇集、已分摊和未分摊的金额。您手动编辑的规则会被保留。请参阅[分摊规则](/zh-cn/guides/projects/data-foundation/#分摊规则)。
- **在 Data Foundation 中解释数字，并按您的方式命名。** **Explain this number** 在您自己的行访问权限下，将损益表数字拆分为总账中的金额、分摊转入和转出的金额，以及在集团中被抵销的金额，并列出最大的来源单据。**业务名称**为类别、损益表行、指标和列赋予您的业务所使用的名称，应用于报表、指标和助手。请参阅[解释数字](/zh-cn/guides/projects/data-foundation/#解释数字)和[业务名称](/zh-cn/guides/projects/data-foundation/#业务名称)。
- **Data Foundation 可以生成董事会报告包，也允许您回退。** **董事会报告包**会按需或随每晚刷新，将损益表仪表板的 Excel 工作簿和 PDF 写入文档账户的文件夹。每次加载以及每次更改映射或源之前，都会创建还原点，**操作 > 还原...** 可将项目恢复。请参阅[董事会报告包](/zh-cn/guides/projects/data-foundation/#董事会报告包)和[还原点](/zh-cn/guides/projects/data-foundation/#还原点)。
- **克隆 Data Foundation 项目，或将其另存为模板。** **操作 > 克隆...** 会复制项目，包含您对模型的编辑、指标和分析路径。**Save as my template...** 将设置保存到文档账户，**From a template file...** 据此启动一个新的私有项目，其源等待连接。请参阅[克隆项目](/zh-cn/guides/projects/data-foundation/#克隆项目)和[另存为我的模板](/zh-cn/guides/projects/data-foundation/#另存为我的模板)。
- **Data Foundation 的设置清单一直延伸到移交，助手可以解决遗留问题。** 清单新增了每晚刷新、证据包以及将项目移交给其所有者，并说明是谁设置了项目。可以让助手为未指定类型的科目、多个源使用的代码以及未匹配任何内容的文件列提出答案；它不会写入任何内容，由您来应用这些答案。请参阅 [Data Foundation 入门](/zh-cn/guides/projects/data-foundation-getting-started/)和[使用 Ask 解决未决问题](/zh-cn/guides/projects/data-foundation/#使用-ask-解决未决问题)。

- **移动端 Weave 的语音输入只需轻点一次。** 点击麦克风，提出问题，您停止说话后 Weave 会发送。再次点击麦克风可提前停止，如果听不到任何声音，它会自动关闭。如果您在说话中途离开 **Weave** 选项卡或将应用切到后台，您的话会保留在问题框中而不发送，以便您查看。运行、暂停、停止和恢复会忽略对其确认的误触双击。需要应用版本 1.3.0 或更高。请参阅[使用语音](/zh-cn/guides/mobile-app/weave-on-mobile/#使用语音)。

## 变更

- **步骤表单遵循同一布局。** 选项卡具有标准名称和标准顺序：常规、设置、源、列、筛选器、输出和高级，ERP 过账表单上还有表头列和明细列。必填字段以 * 标记，表单只会因步骤所需的内容而阻止保存。
- **复制项目可分别选择表数据和维度成员，复制数据更快，并保留私有副本的 ERP 写入授权。** 在 **Data to copy** 下，选择**表数据**——**无表数据**（默认）、**完整**或**样本**——并另外选择 **Copy dimension members**（默认开启），因此不含表行的副本仍会带有已填充的维度，并且创建很快。**完整**和**样本**复制会同时复制多张表，因此包含大量表的项目完成得更快。**复制结果**会将每个维度的结果与表一并列出，**Retry failed items** 会将失败的表和维度一起重试。带数据创建的新副本仅对您私有，并保留来源中您自己可以授予的 ERP 写入授权；如果来源以 Live 方式过账，则副本以 Simulate 方式到达，因此在您将其切换为 Live 之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **行操作菜单 (⋯) 位于每个网格行的最左侧。**
- **未设置验证选项的已保存 ERP 写入步骤以仅验证方式打开。** 这包括 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL and AP Post 以及 Xero export。明确设置为实时运行的步骤保持实时。
- **长时间运行的作业在各处以相同方式显示进度。**
- **停止工作流会停止它启动的所有内容，无法启动的步骤会失败而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中之后的导入和维度加载可正常启动，同时也会停止该工作流排队或运行中的连接器（Singer）同步。如果某个步骤的作业无法启动，该步骤会连同原因一起失败，而不是永远等待：约 40 分钟内没有工作进程启动它、工作进程启动后又消失、其 Pod 约 20 分钟一直处于 Pending、其镜像约 5 分钟无法拉取，或约 20 分钟内没有创建 Pod。约 30 分钟内没有运行器接手的连接器同步，会以指出该同步的消息失败。在步骤等待工作进程期间，其状态消息显示“Waiting for a worker…”及已等待的分钟数，并在工作开始后清除。请参阅[运行工作流](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
- **REST、Import REST 和 Import Postman 步骤会在您的工作区升级时转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **项目架构师在仪表板中可看到行受限表的所有行**，与他们在 Analyze 中看到的一致。取消架构师访问权限会在仪表板中立即生效——无论您是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、还原较早的项目版本，还是删除安全组。前任架构师不再能看到行受限数据的每一行。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
- **会话过期后打开的仪表板链接，会在您登录后带您到该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝无法识别的字段**并在错误中指出该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为它的另一个名称。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，会直接进入该账户的存储桶，使用该账户自己的凭据写入，而不是让每一行先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式不变。请参阅 [Export to Parquet 步骤](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会指出它尝试访问的服务器，对于 Slack 和 Teams 还会指出连接，并说明出了什么问题：例如 Slack 不再识别该 Webhook、无法向该频道发帖、找不到服务器或服务器在 60 秒内没有响应，或连接已被删除。Slack 或 Teams 的 Webhook URL 绝不会显示，因为任何持有它的人都可以冒充您的集成发帖。请参阅 [Notify via Slack 步骤](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。

## 已修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的 slug，或无效的存储类型或过账模式，现在会返回指出问题的消息，而不是通用的服务器错误。通过 REST API 时为 400 而不是 500，通过 AI 助手或 MCP 时为无效参数错误。
- **REST API 的维度值请求现在可用。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 曾被当作网格请求应答并被拒绝为无效。现在它会为 `value_columns` 中的每一列返回一个聚合值，而网格（每对行筛选器和列筛选器对应一个值）有其自己的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再阻碍其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，都可能在完成之前暂停同一台服务器正在处理的所有其他请求。现在它们与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口更高，因此**创建**和**更新**按钮可能够不到。现在表单可以滚动，按钮保持在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 过去对这种大小的文件进行这些操作都会失败，移动或重命名包含这种文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚写入的内容。** 写入表的步骤或导入可能会记录写入之前的行数，因此刚加载的表显示 0 行，导入可能报告导入了 0 行。现在行数会在新行处处可见之后才读取，因此之后的步骤也能读取到它们。将表切换到另一个分支，或将分支合并到其中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的内容进行比较。** 步骤的空值经常是在该步骤清空其表以重新填充之后才被统计，因此它之前的运行看起来没有空值，而一直部分为空的列会被报告为刚刚变空。现在每次运行都按步骤留下表的状态统计。之前记录的计数无法与正常计数区分，因此不会被使用：每个步骤的空值检查会重新开始其历史，并在统计五次运行之前报告为未检查。行数和值分布检查也不再将另一个步骤在其完成后超过两秒对同一张表所做的写入计入某个步骤。请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **向 REST API 请求已删除的连接会返回 404。** 请求已被删除的连接或不存在的 ID 时，过去会应答通用服务器错误 (500)。现在它返回 404，并附带指出连接 ID 的消息。

## 安全

- **只有账户的所有者才能还原其较早的版本。** 将文档账户还原到较早版本、保留或释放版本以及进行备份，现在都需要您是该账户的所有者之一，并且这些操作在系统管理的账户上均不可用。查看账户的版本历史需要有该账户的访问权限。
