## 新增

- **PlaidXL 可在 Excel 中构建、钻取、解释和规划。** **PlaidCloud** 功能区选项卡分为 **连接**、**插入**、**刷新**、**Drill**、**写入** 和 **共享**，常用命令也位于 **PlaidXL** 右键菜单和 **PlaidXL Cell** 选项卡上，主要命令均有可更改的键盘快捷键，在字段中输入时快捷键不会触发。命令失败时会说明是哪个命令以及原因。登录前运行的命令会打开登录界面，并在登录后运行一次；一次登录对应一个工作区，因此切换工作区会要求登录新的工作区（切换回来则不需要）；在 Office 中使用 Microsoft Entra 工作账户时，PlaidXL 会自动找到您的工作区。请参阅 [PlaidXL 参考](/zh-cn/reference/cli/plaidxl/)。
  - **几次单击即可构建报表。** **报表** 选项卡根据表生成实时报表，一个维度向下钻取到行，另一个维度横跨列，每个交叉点都有一个 `CELL` 值。**Build my first report** 会根据您自己的数据生成示例。钻取时，报表会插入和删除整行整列，您输入的值、备注和格式会跟随其所在的行。请参阅[构建报表](/zh-cn/reference/cli/plaidxl/build-a-report/)。
  - **从任意单元格钻取。** **Drill down**、**Drill up**、**Keep only** 和 **Remove only** 可将节点转换为实时 `DRILL` 公式并替您编辑，可从节点、维度标题或报表值发起。**Custom drill** 会在插入之前预览行，成员选择器可插入成员，或向单元格添加某个节点子级的下拉列表。`DRILL` 可指定要排除或展开的节点，并可横跨一行运行。请参阅[钻取、选择成员和解释数字](/zh-cn/reference/cli/plaidxl/drill/)。
  - **解释数字。** **Explain this number** 显示某个值的计算方式、是否与 PlaidCloud 当前数据一致，以及其来源的表和工作流步骤。**Show detail rows** 将值背后的行放在单独的工作表中，并检查它们是否加总一致。
  - **Excel 中的受管指标。** `PLAIDXL.METRIC` 和 `PLAIDXL.METRIC_BREAKDOWN` 返回与仪表板显示一致的业务指标；没有可聚合内容的 `CELL` 或 `CELLS`，求和时显示 `0`，否则显示 `#VALUE!` 及原因（在 `CELLS` 溢出区域中为空白）；**Metric...** 列出项目的指标及其当前值。请参阅[指标](/zh-cn/reference/cli/plaidxl/functions/#指标)。
  - **在报表中直接输入即可规划。** 在 `CELL` 值上输入数字，即会写入 PlaidCloud：可按比例分摊、平均分摊或按另一个成员的形态分摊，也可按金额或百分比调整，已锁定的单元格保持不变。平均值、中位数、最小值、最大值、标准差和方差单元格同样接受输入的值；插入或删除行列时，输入的值会跟随其单元格（已删除单元格中的值会被报告）。**Undo last write** 会按从新到旧的顺序撤销输入的值和保存，且只有执行写入的人员和工作区才能撤销该写入。撤销求和，或撤销在空单元格中输入的平均值时，会保留此后写入同一单元格的内容；写入未完成即中断的操作无法撤销。请参阅[向 PlaidCloud 输入值](/zh-cn/reference/cli/plaidxl/write-values/)。
  - **只刷新所需内容。** 可刷新一个工作表、一个选区或所有表，每个表的进度和 **取消** 显示在任务窗格中，也可以只重新计算 PlaidXL 公式。检索到的表以 Excel 表的形式到达，并按数据类型设置格式；刷新时保留您自己的列和数字格式，并在原位置刷新。检索或刷新绝不会覆盖其他单元格或与另一个 Excel 表重叠；对 Excel 而言过大的整数 ID 和 1900 年之前的日期以文本形式到达。再次检索某个表不会将其两次加入刷新列表，**Stop refreshing** 会将其移除，维度会随表一起刷新。请参阅[刷新所有表](/zh-cn/reference/cli/plaidxl/retrieve/#refresh-all-tables)。
  - **保存立即写入，并可撤销。** **Save to PlaidCloud** 无需确认即写入，说明所做的操作，并提供 **Undo**。带筛选器检索的工作表、明细行工作表，或访问权限仅涵盖部分行的人员，只会替换那些行，因此其他人的行会保留。自检索以来成员已发生变化的钻取工作表不会被保存；保存失败时会指明还原点，以便恢复该表。请参阅[将表保存到 PlaidCloud](/zh-cn/reference/cli/plaidxl/retrieve/#将表保存到-plaidcloud)。
  - **在 Excel 中询问 Weave。** 在 **Weave** 选项卡上，用日常语言请求报表、公式、钻取或表，或选择 **Ask Weave about this cell**。Weave 以您的身份读取 PlaidCloud，只更改工作簿，在替换您已输入的内容之前会先询问，绝不会写入引用工作簿之外的公式，且每项更改在您重新加载窗格之前都可以还原。请参阅[在 Excel 中询问 Weave](/zh-cn/reference/cli/plaidxl/weave/)。
  - **共享单个工作表或整个工作簿的纯值副本。** **Convert to values** 可转换整个工作簿、单个工作表，或转换为无法恢复的值（会先询问），只更改 PlaidXL 公式及其溢出区域，仍在计算的公式会留待再次尝试，重命名工作表后 **Restore PlaidXL formulas** 仍然可用。
- **步骤表单上的预览。** 导入：SQL、Execute: SQL、提取：SQL、导出：SQL 和 Salesforce 查询最多可在不运行步骤的情况下显示 100 行，Anaplan 视图和列表读取会显示其将生成的列和类型。在 **源** 选项卡上单击 **预览**。变量按运行时的方式填充，但不支持 `{x:>9}` 等变量格式。预览只运行标准 SQL 函数；否则会提示您运行步骤。在已锁定的项目中，或对于基于代理的 Execute SQL 步骤，预览不可用。请参阅[导入 SQL](/zh-cn/reference/workflow-steps/import/import-sql/)和[提取 SQL](/zh-cn/reference/workflow-steps/tables/table-extract-sql/)。
- **使用情况报告显示变化、可缩小到某个分组，并可汇入工作流。** **概览** 新增了与上一期间对比的趋势箭头，以及 **Highlights** 列表，指出不活跃的成员以及无人打开的仪表板和应用。已停用的成员不计入，也不会列为不活跃。**分组** 将 **概览**、**内容** 和不活跃列表限定为某个安全组的成员；日期范围新增 **Previous month** 和 **This month**，由所有选项卡共用，并记在您的账户中。现在每个数字都有说明，表格使用 **成员** 和 **Area** 等通俗名称，按 Enter 键即可打开行，加载和错误提示更清晰，**漏斗** 的最后一步显示完成该步骤的成员数。新的 **Get Workspace Usage** 步骤按计划将每日或每月使用量合计写入表中，不含成员姓名；与 **Get Workspace Members** 一样，每次运行都会记录在安全日志中。请参阅[使用情况报告](/zh-cn/administration/access/usage-reports/)和 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。
- **AI 助手可以取消发布表，并设置项目的默认仪表板受众。** `publish_manage` 取消发布表，同时取消发布其已发布的视图和任何没有图表使用的仪表板数据集；图表仍在使用的数据集会保留，当报表视图建立在已发布视图之上时，该视图和数据集也会保留，而该表仍会被取消发布。`project_upsert` 设置 `dashboard_default_audience`，即项目中新仪表板所共享的分组，`[]` 表示清除。请参阅[取消发布](/zh-cn/guides/data/publish/#通过-ai-助手或-mcp-取消发布)和[通过 AI 助手或 MCP 设置默认受众](/zh-cn/guides/dashboards/control-who-can-see-a-dashboard/#通过-ai-助手或-mcp-设置默认受众)。

- **Git 应用列出您的存储库，并告诉您可以执行哪些操作。** 应用列表中的 **Git** 显示您的角色（**Administrator**、**Contributor** 或 **查看者**）以及工作区的存储库，每个存储库带有说明、最后更新日期、带复制按钮的克隆地址和 **打开**。**Set up Git on your computer** 卡片会引导您完成安装 Git、创建令牌和克隆，**How to clone** 可重新打开它。**View all in Git** 打开完整的 Git 界面，**Manage who can push** 打开分组管理。访问级别为 **查看者**、**Contributor**（将应用代码推送到 `apps`）或 **Administrator**（可推送到任何位置，包括 `udfs`），查看者最多可看到三位可联系的工作区管理员。新的 **Git Contributors** 分组授予 Contributor 权限，且可设为默认分组，使新成员自动获得；**Git Administration** 授予管理员权限。成员的 **Git** 选项卡显示其 Git 用户名、级别以及授予该级别的分组。成员的 Git 账户随其成员资格变化：停用或移除成员后，其 Git 账户（包括令牌和 SSH 密钥）会在大约一小时内被阻止，重新激活后则解除阻止，其存储库和历史记录均予保留。使用单点登录登录 Git 会打开该成员自己的账户。Contributor 不能直接在工作区的 Git 组织中创建存储库；存储库通过 PlaidCloud 创建。应用窗口显示 **存储库** 部分，UDF 带有 **打开**，Git 中有返回您的工作区的 **← Back to** 链接。平台创建的每个存储库（包括应用存储库以及内置的 `apps` 和 `udfs` 存储库）都可供工作区中每位已登录的成员读取，因此成员无需针对每个存储库进行设置即可打开和重新发布应用。Git 管理员仍可将存储库设为私有，这会使其在存储库选择器中隐藏，并阻止成员从中发布，或运行存储在其中的基于 Git 的 UDF 代码。请参阅 [PlaidCloud Git](/zh-cn/guides/git/#打开-git)和[谁可以查看存储库](/zh-cn/guides/connections/plaidcloud-git/#谁可以查看存储库)。
- **Cost to Serve 和 Operational Transfer Pricing 模板基于 Common Finance Model 构建。** 从 **Cost to Serve** 启动项目，可按您为每个部门设置的活动和动因将运营费用分摊到客户，并查看每个客户在扣除服务成本后的利润率，且可追溯至总账。从 **Operational Transfer Pricing** 启动，可对照您的政策区间测试每个实体的利润水平（销售回报率、净成本加成或转售价格减项），并通过补差调整使超出区间的实体回到目标值。销售回报率为 EBIT 除以被测试方销售额。请参阅 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/)和 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)。
- **OneStream 和 Anaplan 为 Data Foundation 提供数据，OneStream 还提供读取步骤。** Data Foundation 通过您的 OneStream 管理员构建的数据适配器读取 OneStream 合并结果，通过导出操作读取 Anaplan 计划，并将集团损益表与它们进行对账。新的 **OneStream: Read Adapter** 步骤可在任何工作流中读取适配器（每个合并成员调用一次）并写入表中。请参阅[用于 Data Foundation 的 OneStream](/zh-cn/guides/connections/onestream-for-data-foundation/)、[Anaplan 作为 Data Foundation 源](/zh-cn/guides/connections/anaplan/#将-anaplan-作为-data-foundation-源)和 [OneStream: Read Adapter](/zh-cn/reference/workflow-steps/onestream/onestream-read-adapter/)。
- **选择 Data Foundation 如何分摊共享成本。** **Actions > Allocations...** 会逐步引导您选择要分摊哪些成本、按什么分摊、分摊到何处，以及如何处理负的动因，适用于将间接费用分摊到部门，以及将部门成本分摊到产品和客户，并提供一个月的预览，显示汇集、已分摊和未分摊的内容。手动编辑的规则会保留。请参阅[分摊规则](/zh-cn/guides/projects/data-foundation/#分摊规则)。
- **在 Data Foundation 中解释数字，并按您的方式命名。** **Explain this number** 将损益表数字拆分为总账中的金额、分摊转入和转出的金额，以及在集团内被抵销的金额，并列出最大的源文档，且遵循您自己的行访问权限。**Business names** 为类别、损益表行、指标和列提供您的业务所用的名称，用于报表、指标和助手。请参阅[解释数字](/zh-cn/guides/projects/data-foundation/#解释数字)和[业务名称](/zh-cn/guides/projects/data-foundation/#业务名称)。
- **Data Foundation 每次加载都会编写董事会报告包，并允许您回退。** 每次 **加载** 都会将损益表仪表板的 Excel 工作簿和 PDF 写入某个文档账户的文件夹；关闭报告时，报告包仅含工作簿，对话框会对此作出说明。每次加载开始时，以及每次更改映射或源之前，都会创建一个还原点；**Actions > Restore...** 显示每个还原点会恢复多少个表，并将项目（包括维度）恢复原状。**基础数据** 选项卡更清楚地说明正在发生的事情：显示仍在运行或中途停止的更新，说明为什么表的文件夹不是源，在有内容核对一致之前将 **检查合计是否一致** 保持为待处理，并在状态读取失败时恢复。应用更新会保留您对生成的步骤和备注所做的编辑，并注明任何冲突。请参阅[董事会报告包](/zh-cn/guides/projects/data-foundation/#董事会资料包)和[还原点](/zh-cn/guides/projects/data-foundation/#还原点)。
- **克隆 Data Foundation 项目，或将其另存为模板。** **Actions > Clone...** 复制项目，并带有您的模型编辑、指标和分析路径。**Save as my template...** 将设置保存到文档账户，**From a template file...** 据此启动新的私有项目，其源等待连接。请参阅[克隆项目](/zh-cn/guides/projects/data-foundation/#克隆项目)和[另存为我的模板](/zh-cn/guides/projects/data-foundation/#另存为我的模板)。
- **Data Foundation 的设置清单贯穿交接，助手可以解决遗留问题。** 清单新增了夜间刷新、证据包和将项目移交给其所有者，并说明是谁设置了项目。可以请助手为没有类型的科目、多个源使用的代码以及没有匹配项的文件列提出答案；它不会写入任何内容，由您应用这些答案。请参阅 [Data Foundation 入门](/zh-cn/guides/projects/data-foundation-getting-started/)和[使用 Ask 解决未决问题](/zh-cn/guides/projects/data-foundation/#用-ask-解决未决问题)。

- **移动端 Weave 中的语音只需轻点一下。** 点击麦克风，说出您的问题，停止说话后 Weave 会发送一次。再次点击麦克风可提前停止，若未检测到声音则会自动关闭。如果在说话中途离开 **Weave** 选项卡或将应用切换到后台，您的话语会保留在问题框中而不发送，以便您查看。运行、暂停、停止和恢复会忽略对其确认的意外双击。需要应用版本 1.3.0 或更高版本。请参阅[使用语音](/zh-cn/guides/mobile-app/weave-on-mobile/#使用语音)。

## 变更

- **PlaidCloud 的 Web 应用和 Python 客户端库使用 REST API，JSON-RPC 已弃用。** Web 应用将其请求发送到 REST API。使用 `plaidcloud-rpc` 1.25.0 或更高版本时，`SimpleRPC` 调用会转到 REST API，您的代码无需更改；REST API 尚未涵盖的调用，或仍使用旧版本的工作区，则照常使用 JSON-RPC。JSON-RPC 将在后续版本中移除，因此请将脚本和笔记本升级到 `plaidcloud-rpc` 1.25.0 或更高版本，并针对 REST API 编写新的集成。请参阅[命令行](/zh-cn/reference/cli/jupyter/command-line/)。
- **步骤表单遵循统一的布局。** 选项卡具有标准名称和标准顺序：General、Settings、Source、Columns、Filters、Output 和 Advanced，ERP 过账表单上另有 Header columns 和 Line columns。必填字段以 * 标记，表单仅对步骤所需的内容阻止保存。
- **复制项目分别选择表数据和维度成员，复制数据更快，并保留私有副本的 ERP 写入授权。** 在 **Data to copy** 下，选择 **表数据**——**No table data**（默认）、**完整** 或 **样本**——并单独选择 **Copy dimension members**（默认开启），因此不含表行的副本仍会带有已填充的维度，且创建速度很快。**完整** 和 **样本** 副本会同时复制多个表，因此包含许多表的项目完成得更快。**复制结果** 将每个维度的结果与表一并列出，**Retry failed items** 会同时重试失败的表和维度。带数据的新副本仅对您私有，并保留源中您自己有权授予的 ERP 写入授权；如果源以 Live 方式过账，副本将以 Simulate 方式创建，因此在您将其切换为 Live 之前，不会有任何内容到达 ERP。REST API 和 `project_copy` MCP 工具也接受 `dimension_members`。请参阅[选择复制多少数据](/zh-cn/guides/projects/managing-projects/#选择复制多少数据)和[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。
- **表的详细信息面板更快显示使用它的步骤。** 选择另一个表时，上一个表的步骤会立即清除；共享本项目数据的其他项目中的步骤会在其余内容之后稍候添加，而不会拖延整个面板。请参阅[查看表的使用位置](/zh-cn/guides/projects/managing-tables-and-views/#查看表的使用位置)。
- **行操作菜单（⋯）位于每个网格行的左边缘。**
- **应用选项卡图标统一为一套**，浅色和深色模式下均适用。
- **没有验证设置的已保存 ERP 写入步骤将以仅验证方式打开。** 这涵盖 SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL 和 AP Post，以及 Xero 导出。明确设置为实时运行的步骤保持实时。
- **长时间运行的作业在各处以相同方式显示进度。**
- **停止工作流会停止其启动的所有内容，无法完成的运行或步骤会失败而不是挂起。** 停止会取消仍在排队的导入和维度步骤，因此工作区中后续的导入和维度加载可正常启动，同时也会停止该工作流排队或正在运行的连接器（Singer）同步。如果某个步骤的作业无法启动，该步骤会连同原因一起失败，而不是永远等待：约 40 分钟内没有工作进程启动它、工作进程启动后消失、其 Pod 约 20 分钟一直处于 Pending 状态、其镜像约 5 分钟无法拉取，或约 20 分钟内未创建 Pod。约 30 分钟内没有运行器接手的连接器同步会失败，并给出指明该同步的消息。步骤等待工作进程时，其状态消息显示“Waiting for a worker…”及已等待的分钟数，工作开始后清除。停止宏会停止其所有正在运行的副本，而停止一个副本，或 **Macro Concurrent** 步骤放弃已停止响应的副本，则不会影响调用它的工作流，该工作流继续运行。仅在其他工作流内部运行的宏，在工作流列表中显示为 **正在运行**，可使用 **停止**，并显示每个步骤最近一次运行的状态、开始和结束时间。服务器丢失的运行以失败结束，仍在运行超过 12 小时的运行则以“Run failed: still running at the 12-hour limit. Re-run the workflow.”失败。请参阅[运行工作流](/zh-cn/guides/workflows/run-a-workflow/#永远无法启动的步骤)。
- **恢复、运行历史和运行状态与实际运行内容一致。** 恢复父工作流会运行子工作流剩余的所有内容，即使您已单独重新运行了子工作流的某个步骤；一次运行中子工作流的每次调用都有自己的运行历史条目。因服务器停止而重新启动的步骤会在其日志中说明，`workflow_run_status` 和 REST API 的运行结果会在 `continued_step_ids` 和 `continued_step_count` 中列出失败但继续运行的步骤，而不是将运行报告为正常。请参阅[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)和[出错时继续](/zh-cn/guides/workflows/continue-on-error/)。
- **步骤错误显示其自身的消息。** PlaidCloud 未预料到的错误显示为“The step stopped on an unexpected error (*type*): *message*”。Launcher 上的 **需要关注** 卡片以一行显示错误，并省略此后已删除的工作流的运行。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。
- **未完成的 ERP 提取会使其步骤失败，恢复后可继续。** 当 **SAP：临时提取** 在达到行数或时间限制时暂停，或其代理未及时回复，或者 Salesforce、Oracle Fusion 批量或 HFM/FCCS 导出作业在步骤停止等待时仍在运行时，该步骤会失败，使其后的步骤不会基于不完整的表运行。恢复工作流或重新运行该步骤，提取将在同一作业上从停止处继续。请参阅[运行限制](/zh-cn/guides/connections/sap-adhoc-extract/#运行限制)和 [Salesforce：查询对象](/zh-cn/reference/workflow-steps/salesforce/query-salesforce-object/#运行未完成时)。
- **取消导出会停止其在仓库中的查询。** 取消导出或下载（包括通过停止其工作流）时，在 Lakehouse v2、Snowflake、Databricks、PostgreSQL 和 Greenplum 上，读取其数据的查询也会停止；导出到远程数据库的操作会停止读取其源，而不是一直运行到结束。
- **工作区升级时，REST、Import REST 和 Import Postman 步骤会转换为 REST 请求。** 无法干净转换的步骤保持原样。请参阅 [REST 请求步骤](/zh-cn/guides/workflows/rest-request-step/)。
- **项目架构师在仪表板中可看到行受限表的所有行**，与他们在 Analyze 中看到的一致。撤销架构师访问权限会在仪表板中立即生效——无论是更改某人的角色、将其或其分组从项目中移除、更改项目的访问类型、还原项目的早期版本，还是删除安全组。请参阅[管理行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)。
- **受行访问限制的成员可以运行自己的 SQL 查询并导出结果。** 在设有行访问的项目中，不是架构师的成员，可在查询屏幕上通过自己的查询准确获得其授权所允许的行，并可将其导出为 CSV、Excel 或 JSON，同时显示 **行数受您的访问权限限制** 通知；此前这些操作会被拒绝。包含百分号（`%`）的授权值现在可在查询屏幕上返回其行，将此类查询下载为 CSV 也可正常工作。Snowflake 或 Databricks 上他们自己的自由格式 SQL、从 Postgres 系列仓库导出他们自己的 SQL，以及按快照读取受管表，仍会被拒绝，且视图必须以原名保留受管列才能被筛选。请参阅[行访问与您自己编写的查询](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问与您自己编写的查询)。
- **会话过期后打开的仪表板链接，会在您登录后带您进入该仪表板。** 请参阅[使用仪表板](/zh-cn/guides/dashboards/using-dashboards/)。
- **MCP 工具会拒绝其无法识别的字段**，并在错误中指明该字段，而不是忽略它。`workflow_upsert` 接受 `memo`，并接受 `description` 作为其另一名称。请参阅[未知字段会被拒绝](/zh-cn/integrations/ai-coding-agents/getting-started/#无法识别的字段会被拒绝)。
- **在 Lakehouse v2 上，Lakehouse 自行将 Parquet 导出写入 Google Cloud Storage。** 导出到 Google Cloud Storage 文档账户时，数据直接进入该账户的存储桶，使用该账户自己的凭据写入，而不是每一行都先经过 PlaidCloud。导出到 Amazon S3 和 Azure Blob Storage 账户的方式不变。请参阅[导出到 Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)。
- **Slack、Microsoft Teams 和 Web Hook 步骤会说明消息未发送的原因。** 步骤的错误会指明其尝试访问的服务器，对于 Slack 和 Teams 还会指明连接，并说明出了什么问题：例如 Slack 不再识别该 webhook、无法向该频道发布、找不到服务器或服务器在 60 秒内未响应，或连接已被删除。Slack 或 Teams 的 webhook URL 绝不会显示，因为任何持有它的人都可以冒充您的集成发布内容。请参阅[通过 Slack 通知](/zh-cn/reference/workflow-steps/notifications/notify-via-slack/)。
- **项目服务账户的访问令牌有效期至少为 24 小时。** 以项目身份运行的工作流作业（如 UDF 步骤）获得的令牌有效期为 24 小时。较短的有效期会在工作区升级时调高，您设置的较长有效期则予以保留。
- **工作区的组织、所有者、数据中心、发行版和版本由 PlaidCloud 设置。** 在控制平面中，编辑工作区时这些字段为只读，您创建的工作区归您所有，并置于默认数据中心和发行渠道。使用 **Set Version** 更改版本，并请联系 PlaidCloud 支持团队来迁移工作区、更改其所有者或渠道，或将其固定。请参阅[工作区配置](/zh-cn/administration/control-plane/workspace-configuration/#主要设置)。

## 修复

- **无效的项目设置会以清晰的消息报告。** 未知的环境或文档账户、已被占用或保留的 slug，或无效的存储类型或过账模式，现在会返回指明问题的消息，而不是通用的服务器错误。通过 REST API 时返回 400 而非 500，通过 AI 助手或 MCP 时返回无效参数错误。
- **REST API 的维度值请求现已可用。** `POST /rest/v1/analyze/query/retrieve-dimension-values` 过去被当作网格请求来应答并被判为无效。现在它会为 `value_columns` 中的每一列返回一个聚合值，而网格（行筛选器与列筛选器的每一对组合各有一个值）则有自己的 `POST /rest/v1/analyze/query/retrieve-dimension-cells`。
- **缓慢的表读取和文件处理不再拖延其他请求。** 从仓库读取表的列、注册 Data Foundation 文件、导出到 Excel、读取 REST 或 SOAP 导入的响应、查找文档账户的使用位置，以及检查 Panel 应用的代码或徽标，过去都可能使同一服务器正在处理的所有其他请求暂停，直到其完成。现在它们与这些请求并行运行。
- **项目和工作流变量对话框可以滚动。** 在小屏幕或低分辨率下，添加和编辑对话框比窗口更高，因此 **创建** 和 **更新** 按钮可能无法触及。现在表单可以滚动，按钮保持在底部。
- **Azure Blob Storage 文档账户中超过 256 MiB 的文件可以复制、移动和重命名。** 过去这些操作对该大小的文件都会失败，移动或重命名包含此类文件的文件夹也会失败。
- **在 Lakehouse v2 上，表的行数反映刚写入的内容。** 写入表的步骤或导入过去可能记录写入之前的行数，因此刚加载的表显示 0 行，导入可能报告导入了 0 行。现在会在新行处处可见之后再读取行数，因此其后的步骤也能读取到这些行。将表切换到另一个分支，或将分支合并到其中，也会更新其行数和列数。
- **Weave 的空值检查会将每次运行与之前运行实际留下的内容进行比较。** 步骤的空值过去常常是在步骤清空其表以重新填充之后才被统计，因此其之前的运行看起来没有空值，而一直部分为空的列会被报告为刚刚才变为如此。现在每次运行都按步骤留下其表时的状态统计。之前记录的计数无法与正确的计数区分，因此不予使用：每个步骤的空值检查会重新开始其历史记录，并在统计满五次运行之前报告为未检查。行数和值分布检查也不再把另一个步骤在本步骤完成两秒之后对同一表所做的写入记在本步骤名下。请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。
- **Data Foundation 保留反转汇率和小数阈值的精度。** 当您的汇率是从报告货币折算为另一种货币来报价时，PlaidCloud 会将其反转，该汇率可能被舍入到六位小数，导致汇率较小的货币（例如印尼盾）的金额偏差约 1%。现在反转的汇率保留 12 位小数。带小数的 `group_amber` 或 `group_red` 阈值（例如 `0.5`）曾被舍入为整数。您的下一次加载将使用精确值。请参阅[汇率](/zh-cn/guides/projects/data-foundation/#汇率)。
- **已停用成员的警报和摘要会停止。** 其所有者已被停用的 Panel 应用警报或摘要过去会继续检查和发送。现在在其被停用期间会暂停，重新激活后恢复。请参阅[警报和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
- **向 REST API 请求已删除的连接会返回 404。** 请求已被删除的连接或不存在的 ID，过去会返回通用的服务器错误（500）。现在返回 404，并附带指明该连接 ID 的消息。

## 安全

- **密码登录需要身份验证器应用，并且密码更强。** 使用 PlaidCloud 密码登录的成员，在下次登录时会被要求设置身份验证器应用，此后每次都需输入其验证码。单点登录、Google、Microsoft 和 GitHub 登录、API 令牌和服务账户保持不变。新密码至少需要 12 个字符，不能是您的用户名或您最近六个密码之一，多次登录失败后，账户会被锁定一小段时间。您的工作区已有的更严格规则会予以保留。请参阅[成员身份验证](/zh-cn/administration/access/member-authentication/)。
- **连接可指向公共和私有网络地址。** 连接不能指向环回地址、链路本地地址或云元数据地址，错误会指明主机及其解析到的地址。您的私有网络上的地址不受影响。请参阅[连接无法访问的地址](/zh-cn/guides/connections/create-connection/#连接无法访问的地址)。
- **已保存的连接凭据仅向可编辑连接或工作流的成员显示。** 通过 REST API 和 MCP，已保存连接的密码、令牌和密钥会对其他成员进行掩码处理，他们仍可打开并浏览该连接。请参阅[谁能看到连接的凭据](/zh-cn/guides/connections/create-connection/#谁能看到连接的凭据)。
- **应用构建在运行时无法访问您工作区的 Git 凭据。**
- **代理的私钥仅向可编辑代理的成员显示。** 通过 REST API 和 MCP，该密钥不再出现在代理列表或详细信息中，代理表单仅向可编辑代理的成员显示 **私钥** 和 **查看 RPC 配置**。服务账户、项目和代理令牌以及 AI 委托的令牌无法获取密钥或 RPC 配置。运行中的代理不受影响，公钥仍会显示。请参阅[获取代理凭据](/zh-cn/reference/cli/plaidlink/agents/#获取代理凭据)。
- **代理下载链接的有效期为一小时。** 开启 **Use PlaidCloud Proxy Download** 后，链接过期时请再次打开下载以获取新链接。请参阅[服务](/zh-cn/administration/control-plane/workspace-configuration/#服务)。
- **将人员添加到安全组遵循您所持有的权限。** 当您持有安全组授予的每一项权限时，才可以将成员添加到该安全组、为成员选择分组或邀请架构师。工作区管理员不受限制。请参阅[管理安全组](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理安全组)。
- **连接的所有者或工作区管理员可更改其设置并将其开启或关闭。** 通过 REST API、JSON-RPC 和 AI 助手或 MCP 更改连接设置，需要其所有者之一，或对于没有所有者的连接需要工作区管理员。启用、停用、锁定和解锁连接需要所有者或工作区管理员，指明多个连接的请求仅在您能更改所有这些连接时才会生效。只有工作区管理员才能选择工作区的默认 AI 连接，且仅当没有任何由管理员拥有或没有所有者的连接可以成为默认连接时，成员拥有的连接才会成为默认连接。请参阅[编辑连接](/zh-cn/guides/connections/create-connection/#编辑连接)和[LLM 提供商](/zh-cn/integrations/ai-architecture/llm-providers/#连接包含的内容)。
- **保存行访问会保留其源中不存在的已授权值。** 当表中没有包含该值的行、维度中没有该成员，或列表中没有该值时，安全组被授予的值会保留在网格中并带有标记。**保存** 会询问是保留还是移除每个此类值。请参阅[行访问网格](/zh-cn/administration/access/managing-security-groups-and-assignments/#行访问网格)。
- **只有账户的所有者才能还原其早期版本。** 将文档账户还原到早期版本、保留或释放版本以及进行备份，都需要该账户的所有者之一，且系统托管的账户上这些操作均不可用。查看账户的版本历史需要有该账户的访问权限。
- **`query_run` 运行只读语句。** AI 助手和 MCP 客户端使用的 `query_run` 工具接受一条 SELECT 或 WITH 语句、对其中之一的 EXPLAIN，或 SHOW；任何其他语句均不会运行。要更改数据，请使用 `query_transform`。MCP 表导出中的 SQL 遵循相同规则。对于无法更改项目数据的成员，通过 REST 和 JSON-RPC API 时，该规则同样适用于运行查询、构建列分面、将查询下载为 CSV、将查询导出到远程数据库，以及使用自己的查询导出表数据；被拒绝的查询返回 403。Explain Analyze 会运行查询以进行测量，因此在查询日志和 Lakehouse 中它只接受读取数据的查询，并且在设有行访问的项目中，只有项目架构师才能从查询日志中运行它。
- **向行受限表写入 DataFrame、保存记录和清除，仅更改您能看到的行。** 当行访问限制了您的行时，使用 Python 客户端将 DataFrame 写入受限表或清除该表，或通过 REST API 向其保存记录或清除它，仅更改您自己的行；包含您访问权限之外的行的加载会在任何更改发生之前被拒绝，并指明发现的值。项目架构师、能看到每一行的成员以及工作流运行会写入整个表。人员对任何表进行的每一次此类写入都会记录在安全日志中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
- **对行受限表的导入、复制、还原和删除，要求您能看到每一行。** 当行访问限制了您的行时，将文件导入受限表、将另一个项目的表复制到其中、切换或合并其分支、还原它、删除它、在删除后将其找回，或任何其他替换整个表的操作，仅在您能看到该表的每一行时才会运行；否则会被拒绝，且不会有任何更改。与其他加载一样，通过 REST API 保存表的行只更改您自己的行。项目架构师、能看到每一行的成员以及工作流运行不受影响，这些操作同样会记录在安全日志中。请参阅[向受限表加载数据](/zh-cn/administration/access/managing-security-groups-and-assignments/#向受限表加载数据)。
