## 新增

- **Data Foundation 将您的 ERP 数据整合到一个 Common Finance Model 中。** Common Finance Model 将来自多个 ERP 系统和实例的 ERP 数据整合为单一模型：一套会计科目表、一组实体和一种报告货币。基于它构建的报表、指标和 AI 助手读取的都是同一组数字，无论数据来自哪个 ERP。

  - **直接来自您的 ERP。** 总账、试算平衡表、主数据和预算通过 PlaidCloud 的 ERP 直连获取。**实体对照表**将各来源的公司代码映射到相同的实体，文件则用来补充系统中没有的内容，例如汇率或分摊动因。
  - **一个模型，一种货币。** **加载**会将每个来源统一到 Common Finance Model 中，并换算为您的报告货币：损益表按期间平均汇率，资产负债表按期末汇率，权益按历史汇率。层次结构由您的主数据构建。
  - **检查就绪状态。** 按每个实体和期间运行检查：试算平衡表和销售额与总账一致，每个产品、客户和科目都是已知的，货币可以换算，每个实体都已映射。
  - **保持最新。** **每晚刷新**会每晚重新加载模型，缺失或为空的文件会以警告而不是错误结束。

  从模板（例如 **Enterprise Profitability**）创建项目后，项目的**基础数据**选项卡会带您完成从连接 ERP 到加载并检查模型的全过程。请参阅 [Data Foundation：Common Finance Model](/zh-cn/guides/projects/data-foundation/)。

- **在您自己的 Snowflake 或 Databricks 数据仓库上运行 PlaidCloud。** 工作区管理员在用户菜单中打开**使用您自己的数据仓库**，并在自己的账户中运行生成的设置脚本。该脚本会创建一个设有上限的数据仓库和一个供 PlaidCloud 使用的服务身份，且不会触碰您现有的数据仓库。**检查连接**会用通俗的语言说明任何问题及其解决办法。之后新项目会在您的数据仓库中存储表并运行工作流，移除该数据仓库即可撤销 PlaidCloud 在那里的访问权限。请参阅[使用您自己的数据仓库](/zh-cn/guides/connections/external-lakehouse/)。

  - **使用 Snowflake 或 Databricks 登录。** 管理员无需粘贴凭据，可以通过登录来关联数据仓库。仪表板随后以每个人自己的数据仓库权限运行，工作流则以仅持有您指定数据角色的服务身份运行。请参阅[使用 Snowflake 或 Databricks 登录](/zh-cn/guides/connections/external-lakehouse/#使用-snowflake-或-databricks-登录)。
  - **连接多个数据仓库。** 在**管理数据仓库**中选择**设为默认**，可将新项目发送到另一个数据仓库，现有项目则保持不变。请参阅[管理数据仓库](/zh-cn/guides/connections/external-lakehouse/#管理数据仓库)。
  - **查看一次运行的成本。** 运行历史记录为每次运行显示**仓库成本**列，单位为 credit 或 DBU。请参阅[每次运行的数据仓库成本](/zh-cn/guides/connections/external-lakehouse/#每次运行的仓库成本)。
  - **您的治理策略保持不变。** 描述会写入数据仓库自己的目录，当 PlaidCloud 替换、重新创建或克隆表时，Snowflake 的行访问策略和掩码策略，以及 Databricks 的行筛选器和列掩码都会保持关联。请参阅[您的策略和描述会被保留](/zh-cn/guides/connections/external-lakehouse/#您的策略和说明会延续)。

- **在 PlaidCloud 中构建、发布 Panel 应用并设置其品牌样式。**

  - **Panel Studio。** **新建 Studio 应用**是**我的 Panel 应用**中的第一个按钮，可从空白应用、表、视图、另一个 Studio 应用或应用库开始，而**表**选项卡上的**创建 Panel 应用**则从您选中的表开始。**在 Studio 中打开**会在编辑器中打开应用的文件。可保存草稿、**预览**私有构建，以及**发布**正式应用。构建错误会指向对应的文件和行，**历史记录**可恢复任何已发布的版本，**洞察**显示浏览量、加载时间和错误。**询问 Weave**了解应用的文件和构建状态，并在保存任何代码之前向您展示完整的差异供您批准。请参阅 [Panel Studio](/zh-cn/guides/panel-apps/studio/) 和[使用 Weave 构建 Panel 应用](/zh-cn/guides/panel-apps/build-with-weave/)。
  - **外观与 PlaidCloud 一致的应用套件。** 使用该套件构建的应用在浅色和深色模式下都采用 PlaidCloud 的颜色、字体和间距。套件包含导航、筛选器、关键数字卡片、图表、表单、命令面板、运行工作流的按钮、打印功能，以及一个在服务器端排序和汇总、按列设置数字格式、每次只加载一屏行的数据网格，因此可处理任意大小的表。应用以已登录查看者的身份读取表，并应用行级安全。请参阅 [Panel 应用套件](/zh-cn/guides/panel-apps/app-kit/)、[DataGrid](/zh-cn/guides/panel-apps/app-kit/#datagrid) 和 [Panel 应用的数据 API](/zh-cn/guides/panel-apps/data-api/)。
  - **提醒和摘要。** 当项目表中的某个数字越过限值时，通过推送通知、电子邮件、Slack 或 Microsoft Teams 获得通知，也可以获得最多包含 10 个数字的每日或每周摘要，且始终遵循您自己的行访问权限。请参阅[提醒和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
  - **项目、品牌和共享。** 将应用分配给项目，分配前会先审核哪些不在项目中的人可以打开它。项目**主页**选项卡上的**编辑品牌设置**可为项目中的每个应用设置八种品牌颜色和一个徽标。**应用库…** 会将属于某个项目的 Studio 应用列为模板，供所有能查看其项目的人使用，**从应用库中移除**则将其移除。请参阅[项目品牌设置和应用项目](/zh-cn/guides/panel-apps/branding/)以及[应用库](/zh-cn/guides/panel-apps/gallery/)。

- **一次约定业务数字的计算方式，之后每个 AI 回答都使用该计算方式。** 项目架构师定义一个**指标**，例如 *净收入* 或 *人员数量*：它的源表、各行如何汇总、始终计入的行、联接的查找表，以及可用于细分的列。定义保存后立即生效，如果保存时指定了不存在的表或列，或者查找表中每个键对应多行，保存会被拒绝。按名称或同义词向 AI 助手询问该指标，数字就会按定义计算，并遵循您自己的行访问权限，而不是由助手自行推算。定义通过 AI 助手或 REST API 管理。请参阅[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。

  - **派生指标。** 定义两个指标的比率、和或差，例如人均净收入，或者某个指标乘以固定系数。请参阅[从其他指标派生指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#由其他指标派生指标)。
  - **比较、排名和占比。** 询问与预算的差异、保留并列项的前 N 名或后 N 名，或每一行占总计的份额。请参阅[比较、排名和占比](/zh-cn/integrations/ai-coding-agents/metric-definitions/#比较排名和占比)。
  - **您的措辞，约定的取值。** 将细分列绑定到某个维度，像 *EMEA* 这样的词就会变成其下的每个区域。如果某个词没有匹配项或匹配多个成员，会作为候选项返回并向您确认，而不会猜测。请参阅[询问指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#询问指标)。
  - **财政时间。** 告诉指标其各行在您的财政日历中的位置，即可询问某个财政期间、年初至今、同比或环比。请参阅[随时间比较](/zh-cn/integrations/ai-coding-agents/metric-definitions/#随时间比较)。

  PlaidCloud 自己的 AI 助手回答业务数字时优先使用指标，并在带有 ✓ 标记的专用卡片中显示数字，这个标记绝不会附加在助手自己的文字上。请参阅[业务数字](/zh-cn/guides/ai-assistant/weave-tab/#业务数字)和[来自指标的数字](/zh-cn/guides/ai-assistant/weave-tab/#来自指标的数字)。

- **询问 Weave 是否已准备好结账，并检查两张表是否一致。** 两者都不涉及 AI。

  - **结账就绪检查。** 在项目**Weave** 选项卡的**就绪状态**中，将结账、预测或任何截止日期所依赖的工作流命名为一个**就绪集**。一份清单即可回答全部情况：“13 个中有 11 个就绪；1 个未就绪；1 个无法检查。”只有 Weave 能运行的每项检查都通过，工作流才算就绪；任何 Weave 无法判断的内容都会显示为**无法检查**并附上原因，绝不会显示为就绪。如果最近一次运行没有足够的早期历史可供比较，例如新工作流，则按正常情况计算。不写入表的步骤，例如发送电子邮件或导出文件的步骤，没有行或空值可检查，因此不会使工作流停留在**无法检查**。请参阅[结账前检查就绪状态](/zh-cn/guides/ai-assistant/weave-readiness/)。
  - **对账。** 按您配对的关键列，逐行比较两张表，或同一张表的两个期间。Weave 会说明它们是否一致、相差多少以及哪些行不同，对于无法完整读取的数据，绝不会说“一致”。每个对账在使用前都需要另一位架构师批准。请参阅[检查两张表是否一致](/zh-cn/guides/ai-assistant/weave-reconciliation/)。

- **Weave 监控更多可能出错的地方，并在两次运行之间通知您。** Weave 的检查不使用 AI。每个发现项以及 AI 助手的每个回答都有一个 **Weave 如何得知**面板：对于发现项，显示检查及其依据的值；对于回答，显示助手运行的每个查询，并将每个句子标记为**已匹配**、**未匹配**或**未检查**。请参阅 [Weave 目前检查的内容](/zh-cn/guides/ai-assistant/weave-findings/#weave-目前检查的内容)、[Weave 如何得知](/zh-cn/guides/ai-assistant/weave-findings/#weave-如何得知)以及 [AI 助手中的 Weave 如何得知](/zh-cn/guides/ai-assistant/weave-tab/#weave-如何得知)。

  - **表按时写入。** Weave 会报告自计划到期以来一直没有写入的表，或者超过您在表详细信息的**时效性**中设置的时效阈值（1 小时到 180 天）的表。
  - **过时或损坏的输入。** Weave 会报告读取了另一工作流此后写入过的表的工作流，以及依赖于失败运行的每个工作流和仪表板，包括图表建立在 SQL 数据集上的仪表板。**同步依赖项**会在步骤与其读取的表之间补上缺失的连接器。请参阅[同步依赖项](/zh-cn/guides/workflows/sync-dependencies/)。
  - **数据形态发生变化。** Weave 会报告运行后取值分布发生很大变化的小数列、开始多次写入同一行的联接、提取步骤因无法转换为列类型而留空的值，以及未找到任何文件的导入。它还会报告最新期间与常态相差很大的指标，并指明导致该情况的项目。Weave 会考虑月末和工作日规律，因此始终在月末较为繁重的加载不会被报告。请参阅[异常的指标合计](/zh-cn/guides/ai-assistant/weave-metric-insights/)。
  - **运行变慢。** Weave 会指出使运行变慢的步骤，并报告较新运行耗时比较早运行至少多四分之一的工作流，同时指出耗时增长最多的步骤。
  - **两次运行之间的通知。** 每小时一次的检查会通过应用内消息将每个问题通知其负责人一次，页眉中的 **Weave** 按钮会统计您在所有项目中尚未阅读的问题数。请参阅[在两次运行之间收到通知](/zh-cn/guides/ai-assistant/weave-findings/#两次运行之间收到通知)和[页眉中的 Weave 按钮](/zh-cn/guides/ai-assistant/weave-tab/#标题栏中的-weave-按钮)。
  - **负责人、评论和预期的警告。** 每个发现项都有一位负责人，默认是最后运行其工作流的人。**分配**可将其转交他人，评论用于记录进展，**团队**视图显示谁负责什么。架构师可以将警告标记为**此为预期**，并附上原因和截止日期。请参阅[为发现项指定负责人](/zh-cn/guides/ai-assistant/weave-tab/#为发现项指定所有者)和[将发现项标记为预期](/zh-cn/guides/ai-assistant/weave-tab/#将发现项标记为预期)。

- **修复助手会解释错误，提出需要您在卡片上批准的更改，重新运行步骤，并且可以撤消修复。** 对于最常见的失败，例如表中不存在的列、为空的必填设置、数据库无法读取的 SQL 或类型错误的值，第一条回复会解释常见原因和修复方法。提出的更改以卡片形式呈现，说明步骤失败的原因，并显示每个更改的设置，当前值为红色，新值为绿色。**批准**会应用更改，随后助手会提示重新运行该步骤，并诊断新的失败。**Weave** 选项卡中发现项上的**修复**会针对该问题打开助手。**撤消**会恢复步骤之前的设置，**撤消并运行**则会重建其输出。请参阅[使用 AI 修复工作流错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/)、[使用 AI 助手修复发现项](/zh-cn/guides/ai-assistant/weave-tab/#使用-ai-助手修复发现项)和[撤消修复](/zh-cn/guides/ai-assistant/fixing-workflow-errors/#撤消修复)。

- **查看 Weave 在项目中所做的一切，并导出供审计人员使用。** 项目 **Weave** 选项卡上的**活动**列出 Weave 发现并随后不再发现的问题、AI 助手提出的每项更改、谁请求以及谁批准或拒绝、它具体替换和写入了什么，以及最终结果。Weave 会先记录您的批准再进行更改，并且不会进行无法记录的更改。**导出 CSV**或**导出 PDF**可将一个时间段保存为审计证据，条目无法被编辑或删除。**摘要**一览显示一个月的情况：发现并解决的问题、已批准的更改以及其中被撤消的数量。工作区管理员可通过**工作区摘要…** 获得每个项目的同类信息。请参阅 [Weave 活动历史记录](/zh-cn/guides/ai-assistant/weave-activity/)和 [Weave 月度摘要](/zh-cn/guides/ai-assistant/weave-monthly-summary/)。

- **在保存之前了解步骤的作用以及更改会影响什么。** 以下内容均由项目已保存的设置构建，不涉及 AI，您的角色所隐藏的内容只会被计数，不会被指名。

  - **每个表、步骤和工作流的文档。** 详细信息面板中的**文档**部分描述步骤的作用和工作流中按顺序排列的步骤，哪些内容读取和写入某张表则可供 Weave 和 AI 助手使用。表的详细信息面板列出其**列**及其类型和描述。**下载交接包**会将整个项目保存为一份文档，包括指标定义和分摊模型。请参阅[表、步骤和工作流的文档](/zh-cn/guides/ai-assistant/weave-documentation/)。
  - **更改会影响什么。** 在**保存**上方，Weave 会说明有多少个下游步骤读取该步骤写入的内容，例如“对此步骤的更改会影响 2 个工作流中的 8 个下游步骤”，**显示步骤**会列出它们。请参阅[更改会影响什么](/zh-cn/guides/ai-assistant/impact-preview/)。
  - **保存会拒绝什么。** **保存**上方的条带会在您编辑时运行该步骤的检查，每个问题旁都有**转到**，表达式编辑器会在您输入时检查表达式。请参阅[保存会拒绝什么](/zh-cn/guides/ai-assistant/check-while-you-edit/)。
  - **审核一个工作流。** 工作流画布或**步骤**网格上的**检查**会对其运行 Weave 的检查，另外还包括分摊和行级安全检查。请参阅[审核一个工作流](/zh-cn/guides/ai-assistant/weave-findings/#审核单个工作流)。

- **为您的工作区关闭 Weave 的任何 AI 功能。** 工作区管理员在页眉 **Weave** 按钮上选择 **AI 功能…**，即可分别开启或关闭 Weave 聊天、修复助手、导入和导出助手、表达式助手、根据描述生成 SQL、工作流审核摘要或初始图表。在管理员关闭之前，所有功能均为开启状态，Weave 的检查和发现项始终保持开启，每项更改都会记录在**安全日志**中。请参阅 [AI 功能](/zh-cn/guides/ai-assistant/weave-ai-features/)。

- **在 Allocation Split 步骤上尝试驱动因素假设分析。** 右键点击该步骤并选择**假设分析…**，即可查看使用不同的驱动因素取值、驱动因素表的不同列，或另一张具有相同键的表的数值列时，它会如何分摊成本。最多可比较 10 个方案，每个方案都根据该步骤最近一次运行精确计算到分，并显示谁受益、谁受损，以及哪些行将得不到任何分摊。**细分依据**显示每个成员的变化落在哪些科目或其他值上，**后续步骤**则会将方案延续到由分摊输出构建的表中。不会重新运行任何内容，也不会更改任何数据。请参阅[尝试驱动因素假设分析](/zh-cn/guides/allocations/results/driver-what-if/)。

- **将项目迁移到 Lakehouse v2 的过程从就绪检查到撤消全程有引导。** **检查迁移就绪状态**会将表、视图、步骤、仪表板、数据共享和容量报告为通过、需要审核或已阻止，并对每个发现项给出通俗的说明。**在 v2 上试用…** 会创建一个私有的试用副本，计划处于关闭状态，ERP 过账处于模拟模式。可以立即开始迁移，也可以在您选择的时间开始。迁移运行期间项目的计划会暂停，并在之后恢复，迁移完成时会通过消息和电子邮件通知您。**变更内容…** 会报告每张表的结果，**撤消迁移…** 可在撤消窗口期内将项目恢复到 Lakehouse v1。请参阅[将项目迁移到 Lakehouse v2](/zh-cn/guides/data/migrate-project-lakehouse/)。

## 变更

- **Ctrl/Cmd-K 可在任何屏幕上打开命令面板。** 在您输入之前，它会列出您最近打开的内容和可以执行的操作：转到主页、项目、仪表板或文档，在浅色和深色之间切换，连接您的 AI，或获取帮助。输入内容会同时缩小两个列表，输入两个字符后还会搜索项目、工作流、表、仪表板和 Panel 应用。请参阅[搜索和命令](/zh-cn/guides/launcher/#搜索和命令)。

- **步骤在保存时而不是运行时发现问题。** 保存设置会导致运行失败或给出错误结果的步骤时会被拒绝，并附上需要更改什么的消息。每个步骤的参考页面都列出了它检查的内容。步骤或其源表中已不存在的已映射源列会以红色标出，保存时会打开一个对话框，其中有**全部移除并保存**、**仍然保存**或**取消**。联接、查找和空间步骤会保留这些行，而不是自行删除。使用未定义变量的表达式会指出该变量，运行时被拒绝的步骤会用通俗的语言解释原因。请参阅[不再列出的源列](/zh-cn/reference/workflow-steps/tables/table-extract/#不再列出的源列)、[源表中缺失的列](/zh-cn/reference/workflow-steps/tables/table-extract/#源表中缺少的列)和[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。

- **缺失或为空的源绝不是错误。** 文件缺失或为空的文件导入会以警告结束并指出路径，目标表保持为空但保留其声明的列，因此后续步骤读取到零行。针对缺失或为空文件夹的文档步骤会报告“无需处理”，工作流继续运行。远程文件步骤对缺失的路径给出警告，并拒绝不安全的路径。检查文件缺失的功能适用于 OneDrive、SharePoint 和 SFTP。批处理表为空的**报表：批量生成**会以警告结束，且不生成任何报表。请参阅[导入步骤](/zh-cn/reference/workflow-steps/import/)、[文档工作流步骤](/zh-cn/reference/workflow-steps/document/)和[文档路径条件](/zh-cn/guides/workflows/step-conditions/#文档路径条件)。

- **大型工作流运行可靠，并且停止可取消导入和导出。** 当 PlaidCloud 繁忙时，步骤会等待容量而不是失败，并且随着步骤排队会增加容量。导入外部数据库表最多同时运行 10 张表。如果运行步骤的服务器丢失，替换其输出的步骤会自动再次运行，无法安全重复的步骤则会失败一次并显示 *已中断* 消息。**停止**会取消正在运行的导入和导出作业，已停止的运行会报告“已停止”。请参阅[中断的步骤](/zh-cn/guides/workflows/run-a-workflow/#已中断的步骤)以及[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)。

- **每个 Lakehouse 的存储和计算方式相同。** 来自导入 CSV、导入 XML 或 Import Table Archive 步骤的空字段会作为 null 加载，因此之后测试 `= ''` 或 `= 0` 的步骤需要改为测试 null。`cast(x, Float)` 在所有地方都是 64 位，因此大额数值会保留全部位数，PlaidCloud 创建的 Float 列为双精度。JSON 列、**Table: Delete Rows** 和聚合条件在所有 Lakehouse 上都可使用。自行构建结果的步骤，例如求解器、预测，以及在 pandas 中运行的 Pivot 和 Allocation Split，会将结果作为带类型的数据加载，速度快得多。表资源管理器显示数值列的最小值、最大值、平均值、总和、标准差和方差。请参阅[转换为 Float](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#转换为-float)和[列数据和唯一计数](/zh-cn/guides/data/table-explorer/#列数据和唯一值计数)。

- **文件导出保留其类型。** Parquet 文件将整数列保留为整数，以微秒存储时间戳，并将时区标注为 UTC。Avro 文件保留带类型的日期、时间戳和布尔值，单表 Avro 导出以该导出命名。为 Parquet 导出选择多个文件会停止并提示 Parquet 只写入单个文件。超大的 Parquet、ORC 和 JSON 导出会在读取行的同时写入，因此不再耗尽内存，Parquet 使用您选择的压缩方式。版本 1.2.33 或更高版本的 PlaidLink 代理会以 Parquet 文件接收导出的表。请参阅 [Export to Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/) 步骤、[Export to Avro](/zh-cn/reference/workflow-steps/export/export-to-avro/) 步骤和[数据如何到达代理](/zh-cn/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#数据如何到达代理)。

- **ERP 过账遵循每个计划的模式，不确定的答复会被挂起等待您检查。** 计划事件保留自己的过账模式（**实时**、**模拟**或**关闭**），并受项目设置的上限约束，**运行所选事件**会使用每个事件的模式。PlaidCloud 无法确认的 ERP 答复（例如超时或服务器错误）会作为存疑挂起，而不是记录为已拒绝，并且同一笔过账不能被冲销两次。过账登记簿会列出 **reversal outstanding** 的过账，架构师可在项目主页的 **ERP 写入授权**中授权项目过账。请参阅 [ERP 过账模式](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)、[冲销](/zh-cn/guides/connections/posting-register/#冲销)和[授权项目过账](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)。

- **行访问会跟上组的变化，并说明哪里出了问题。** 用户登录时由单点登录设置的组成员身份会在大约 15 分钟内到达仪表板行访问，默认组的新成员会在大约一分钟内获得其行。当某个限制没有筛选掉任何内容时，**行访问**窗口会发出警告，可处理包含 `&`、`/` 或 `%` 的列名，并在同步失败时显示带原因的**错误**，或带有**重试**按钮的**正在重试**。请参阅[保持仪表板同步](/zh-cn/administration/access/managing-security-groups-and-assignments/#保持仪表板同步)。

- **用户定义函数在 Python 3.14 上运行，并使用更新的库。** 大多数函数无需更改即可运行。导入 numba 的函数，或导入 Python 已移除的标准库模块（例如 `cgi` 或 `telnetlib`）的函数，现在会失败，需要重写。预测的 AutoTheta 边界可能与之前的运行略有不同。请参阅[用户定义转换](/zh-cn/reference/workflow-steps/general/user-defined-transform/)。

- **“完整”代理访问已弃用，并将于 2027 年 1 月 15 日移除。** 使用**完整**访问的 LLM 步骤会记录警告。请改用**读取和写入**，在该模式下代理通过 PlaidCloud 的写入工具更改数据，LLM 步骤只写入勾选了**写入**的绑定。请参阅[代理访问](/zh-cn/integrations/ai-architecture/llm-providers/#代理访问)。

- **Project 应用对发票、行程和补报工时的处理更加完整。** 新发票从提供客户和 PO 编号的主项目开始。删除草稿发票会使其工时和行程重新变为可计费，**AR 收件人**设置提交发票时向谁发送电子邮件。行程抽屉显示每一行的供应商、类别和审计状态，**添加补报工时**会为已批准的一周启动工时表。请参阅[使用 Project 应用跟踪工时和费用](/zh-cn/guides/time-expense/track-time-and-expenses/)。

- **已移除删除所有没有步骤引用的表的 API 调用。** 请改为按 ID 删除表。

- **应用各处的小改动。** 双击账户、仪表板、成员、组或设置列表中的行即可打开它。空的**维度**、**数据编辑器**、**UDF** 和**步骤**选项卡会说明下一步该做什么，没有应用的成员会进入启动板。步骤的表选择器会显示该表上次更新的时间（[查看源表上次更改的时间](/zh-cn/guides/workflows/create-workflow/#查看源表最后一次更改的时间)）。Export External Database Tables 在其自己的选项卡上映射列，**报表：批量生成**不再显示未使用的 **Report Constants** 部分。Convert Encoding 步骤可识别中欧、土耳其和阿拉伯语编码。指向已移除屏幕的链接会说明这一点。

- **工作流画布和屏幕表现正常。** **钻取到工作流**会在其画布上打开高级工作流，画布可打开每个工作流，并在布局的一部分无法读取时告知您。放不下的工具栏按钮会移入**更多**菜单，保存后列表会立即更新。通知会显示其完整消息，警告在**日志**选项卡中显示警告图标，表资源管理器会在列的概要分析失败时说明，数据编辑器会让空的日期单元格保持为空。在开启列筛选器的情况下保存数据编辑器时，会保留筛选器所隐藏的行，包括在您添加、删除或移动行之后。用户定义函数编辑器对任何有权更改它的人都以可编辑状态打开。请参阅[当画布无法打开工作流时](/zh-cn/guides/workflows/advanced-workflows/#画布无法打开工作流时)。从**表**列表中删除表时，会列出仅通过变量路径（例如 `/Periods/{period}/Sales`）访问某张表的所有步骤，只有在您强制执行时才会删除该表。请参阅[删除](/zh-cn/guides/projects/managing-tables-and-views/#删除)。

- **成员和连接按应有方式工作。** **添加工作区成员**对已有账户的人（包括由单点登录创建的账户）有效，并且绝不会降低他们已持有的项目角色。ODBC 连接通过 PlaidLink 代理所在机器上的 DSN 或驱动程序进行连接。拒绝您的 OAuth 凭据的提供商会提示您重新输入或重新授权，Databricks 示例和导出会刷新即将过期的令牌，较旧数据库类型的连接可以删除。**使用位置**包含通知步骤，免费工作区保留每日、每周和每月备份。请参阅[成员管理](/zh-cn/administration/access/member-management/)和 [ODBC](/zh-cn/reference/connectors/databases/odbc/)。

- **REST API 和 AI 助手工具完全按您的要求执行。** 对成员、组或计划事件的部分更新只更改您指定的字段，因此已暂停的事件保持暂停。从指定步骤开始运行会从该步骤开始，恢复表快照会保留一个安全快照和一条审计记录。来自 AI 工具的驱动因素假设分析，只在与您的模型实际进行的分摊一致时才会给出答案。过去会以服务器错误失败的请求现在要么可以工作，要么会说明问题所在。请参阅[追踪分摊](/zh-cn/integrations/ai-coding-agents/tracing-allocations/)和[回退或还原快照](/zh-cn/guides/data/table-snapshots/#回退或还原快照)。

## 安全

- **AI 助手始终在您的权限范围内。** 助手的数据查询在运行前会按其结构进行检查，并且只运行单个读取查询。只读的 AI 连接（包括 Microsoft 365 Copilot）无法导出文件、保存仪表板 PDF、将行复制到另一个项目，或通过 REST 连接发送更改。通过 AI 助手进行的导入以您的身份在您指定的项目中运行，对话只能由发起者本人继续。助手和表引用会省略您的角色所隐藏的表、步骤、工作流和维度，Weave 会对您无法打开的失败步骤计数，而不是指名。请参阅[访问级别](/zh-cn/integrations/microsoft-365-copilot/#访问级别)、[您的角色隐藏的内容](/zh-cn/guides/ai-assistant/weave-tab/#您的角色所隐藏的内容)和[管理过去的对话](/zh-cn/guides/ai-assistant/weave-tab/#管理过去的对话)。

- **ERP 过账无法绕过其控制。** 开启职责分离后，冲销需通过过账登记簿，并在那里适用审批。复制或导入的项目不再继承过账权限，SAP 和 EBS 过账无法直接发送给代理，处于仅测试模式的 SAP Post 步骤需要与实际过账相同的权限。一个未公开的、可在没有这些检查的情况下向 Sage Intacct 过账的端点已被移除。来自 ERP 和 REST 连接的错误消息不再包含凭据。请参阅[职责分离](/zh-cn/guides/connections/posting-register/#职责分离)。

- **机密信息为只写，且只有所有者决定谁可以使用连接。** 文档账户的密钥、密码和令牌一旦保存便不再显示，更改账户的连接位置需要再次提供机密信息。步骤中的密码和密钥只存放在变量中；已输入到步骤中的机密信息已移入仅架构师可见的项目变量。多行凭据在您输入时会被屏蔽。只有连接的所有者或工作区管理员才能更改谁有权访问它。请参阅[已保存的机密为只写](/zh-cn/guides/documents/adding-accounts/#已保存的机密为只写)、[密钥存放在变量中](/zh-cn/reference/workflow-steps/document/encrypt-decrypt-file/#密钥存放在变量中)以及[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

- **您无法使用的文档账户对您保持关闭。** 检查文件是否存在、读取 Parquet、Avro、ORC 或 Delta 文件的列、使用**填充**填充导入步骤的列，以及 AI 助手的文件检查，现在都会拒绝您无权访问的账户，就像浏览该账户时已有的做法一样。

- **只有工作区管理员才能更改工作区管理员。** 编辑、停用或删除管理员、更改其组，以及将某人设为管理员，都需要工作区管理员。请参阅[更改工作区管理员](/zh-cn/administration/access/member-management/#更改工作区管理员)。

- **数据共享只代表被授予该共享的项目的成员。** 通过共享读取需要在接收项目中拥有角色，写入则需要**写入**共享以及在那里拥有管理者或架构师角色。请参阅[在项目之间共享数据](/zh-cn/guides/projects/managing-projects/#在项目之间共享数据)。

- **还原只适用于所指定的项目。** 还原早期版本会还原该项目本身，权限检查针对该项目。内容不属于其自身标头中所列维度的维度备份文件会被拒绝。请参阅[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。

- **模板、导入和归档会拒绝不安全的内容。** 导出模板和报表模板在沙盒中渲染，只读取提供给它们的数据。导入根据其自身设置构建加载查询，包含 PlaidCloud 归档从不包含的内容的项目归档会被拒绝，与其他项目共享报表架构的项目短名称会被拒绝。请参阅[模板可以使用什么](/zh-cn/reference/workflow-steps/export/export-templated/#模板可以使用的内容)和[还原归档](/zh-cn/guides/projects/archive-a-project/#还原归档)。

- **仪表板遵循 PlaidCloud 登录和您的行访问权限。** 仪表板的缩略图以您的身份渲染，账户仅来自 PlaidCloud 登录，仪表板只能从导出所生成的 ZIP 文件导入。请参阅[导入现有仪表板](/zh-cn/guides/dashboards/learning-dashboard/#导入现有仪表板)。

- **启动工作流运行不再返回该运行的凭据。**

- **运行用户定义函数的环境不再包含 PySpark 的 Java 库，** 这些库存在已知漏洞。PySpark 的 DataFrame 和 SQL API 仍可访问您的 Spark 计算集群，但导入 `SparkContext` 或 `RDD` 的函数现在会失败。请参阅 [PySpark 入门](/zh-cn/integrations/pyspark/getting-started/)。

- **附件、还原和转换只读取您可以使用的账户。** 通过电子邮件发送文件、从文件还原维度或表归档、检查或导入表包、从模板填充 Excel 导出，以及转换 Alteryx 工作流，现在都会拒绝您无权访问的文档账户。将维度备份到文档账户需要对其拥有写入权限。工作流步骤不受影响，但通过电子邮件发送文件、还原表或填充 Excel 模板的步骤不能再从个人临时驱动器读取。
