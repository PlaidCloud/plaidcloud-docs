## 新增

- **Data Foundation 将 ERP 数据汇集到一个 Common Finance Model 中。** Common Finance Model 将来自多个 ERP 系统和实例的 ERP 数据汇集到单一模型中：一套会计科目表、一组实体和一种报告货币。基于它构建的报表、指标和 AI 助手读取的都是同一套数字，无论数据来自哪个 ERP。

  - **直接来自 ERP。** 总账、试算平衡表、主数据和预算通过 PlaidCloud 的 ERP 直接连接传入。**实体对照表**将各来源的公司代码映射到相同的实体，文件则用于补充系统中没有的内容，例如汇率或分摊动因。
  - **一个模型，一种货币。** **加载**会将每个来源统一到 Common Finance Model 中，并换算为报告货币：损益表按期间平均汇率，资产负债表按期末汇率，权益按历史汇率。层次结构由主数据构建。
  - **检查就绪状态。** 针对每个实体和期间运行检查：试算平衡表和销售额与总账一致，每个产品、客户和科目都已知，货币可以换算，每个实体都已映射。
  - **保持最新。** **每晚刷新**会在每晚重新加载模型，文件缺失或为空时以警告而非错误结束。

  从模板（例如 **Enterprise Profitability**）启动项目，项目的**基础数据**选项卡会带您从已连接的 ERP 一路走到已加载并经过检查的模型。请参阅 [Data Foundation：Common Finance Model](/zh-cn/guides/projects/data-foundation/)。

- **在您自己的 Snowflake 或 Databricks 数据仓库上运行 PlaidCloud。** 工作区管理员在用户菜单中打开**使用您自己的数据仓库**，并在自己的账户中运行生成的设置脚本。该脚本会为 PlaidCloud 创建一个有用量上限的数据仓库和一个服务身份，不会触及您现有的任何数据仓库。之后新项目会将表存储在您的数据仓库中，并在其中运行工作流；移除该数据仓库即可撤销 PlaidCloud 在其中的访问权限。**检查连接**会用通俗的语言说明任何问题及其修复方法。请参阅[使用您自己的数据仓库](/zh-cn/guides/connections/external-lakehouse/)。

  - **使用 Snowflake 或 Databricks 登录。** 管理员无需粘贴凭据，可以通过登录来关联数据仓库。之后仪表板以每个人自己的数据仓库权限运行，工作流则以仅持有您指定数据角色的服务身份运行。请参阅[使用 Snowflake 或 Databricks 登录](/zh-cn/guides/connections/external-lakehouse/#使用-snowflake-或-databricks-登录)。
  - **连接多个数据仓库。** 在**管理数据仓库**中选择**设为默认**，可将新项目发送到另一个数据仓库，现有项目保持不变。请参阅[管理数据仓库](/zh-cn/guides/connections/external-lakehouse/#管理数据仓库)。
  - **查看每次运行的成本。** 运行历史记录为每次运行显示一列**仓库成本**，单位为积分或 DBU。请参阅[每次运行的数据仓库成本](/zh-cn/guides/connections/external-lakehouse/#每次运行的仓库成本)。
  - **您的治理策略保持不变。** 描述会写入数据仓库自己的目录；当 PlaidCloud 替换、重建或克隆表时，Snowflake 的行访问策略和掩码策略以及 Databricks 的行筛选器和列掩码仍会保留。请参阅[您的策略和描述会一并保留](/zh-cn/guides/connections/external-lakehouse/#您的策略和说明会延续)。

- **在 PlaidCloud 内构建、发布 Panel 应用并设置品牌。**

  - **Panel Studio。** **Create app** 可从空白应用、表、视图、模板或应用库开始，**Open in Studio** 会在编辑器中打开应用的文件。保存草稿，**预览**私有构建，并**发布**正式应用。构建错误会指向其所在的文件和行，**历史记录**可还原任何已发布的版本，**Insights** 显示浏览量、加载时间和错误。**Ask Weave** 了解应用的文件和构建状态，并在保存任何代码之前向您展示完整差异以供批准。请参阅 [Panel Studio](/zh-cn/guides/panel-apps/studio/) 和[使用 Weave 构建 Panel 应用](/zh-cn/guides/panel-apps/build-with-weave/)。
  - **外观与 PlaidCloud 一致的应用套件。** 使用该套件构建的应用在浅色和深色模式下都采用 PlaidCloud 的颜色、字体和间距。套件包括导航、筛选器、关键数字卡片、图表、表单、命令面板、可运行工作流的按钮、打印功能，以及在服务器上排序和汇总、按列设置数字格式、每次加载一屏行的数据网格，因此可以处理任意大小的表。应用以登录查看者的身份读取表，并应用行安全。请参阅 [Panel 应用套件](/zh-cn/guides/panel-apps/app-kit/)、[DataGrid](/zh-cn/guides/panel-apps/app-kit/#datagrid) 和 [Panel 应用的数据 API](/zh-cn/guides/panel-apps/data-api/)。
  - **提醒和摘要。** 当项目表中的某个数字越过限值时，通过推送通知、电子邮件、Slack 或 Microsoft Teams 收到通知，或接收最多包含 10 个数字的每日或每周摘要，始终遵循您自己的行访问。请参阅[提醒和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
  - **项目、品牌和共享。** 将应用分配给项目，分配前会先审核哪些人可以打开该应用但不在项目中。项目**主页**选项卡上的 **Edit Branding** 可为项目中的每个应用设置八种品牌颜色和一个徽标。**Gallery…** 会将应用作为模板列出，供所有可以查看其项目的人使用。请参阅[项目品牌和应用项目](/zh-cn/guides/panel-apps/branding/)和[应用库](/zh-cn/guides/panel-apps/gallery/)。

- **一次约定业务数字的计算方式，每个 AI 回答都使用该计算。** 项目架构师定义一个**指标**，例如*净收入*或*人数*：它的源表、各行如何相加、始终计入的行、它所联接的查找表，以及可用于细分的列。定义保存后立即生效；如果保存时指定了不存在的表或列，或者查找表中同一个键对应多行，保存会被拒绝。按名称或同义词向 AI 助手询问该指标，数字会按定义计算并遵循您自己的行访问，而不是由助手自行推算。定义通过 AI 助手或 REST API 管理。请参阅[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。

  - **派生指标。** 定义两个指标的比率、和或差，例如人均净收入，或指标乘以固定系数。请参阅[从其他指标派生指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#由其他指标派生指标)。
  - **比较、排名和占比。** 可以询问与预算的差异、保留并列项的前 N 名或后 N 名，或每一行占合计的比例。请参阅[比较、排名和占比](/zh-cn/integrations/ai-coding-agents/metric-definitions/#比较排名和占比)。
  - **您的用词，约定的取值。** 将细分列绑定到维度后，*EMEA* 这样的词会变成其下的每个区域。如果某个词没有匹配项或匹配多个成员，系统会将候选项返回并向您确认，而不会猜测。请参阅[询问指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#询问指标)。
  - **财政时间。** 告知指标其各行位于财政日历的哪个位置，即可询问某个财政期间、年初至今、同比或环比。请参阅[随时间比较](/zh-cn/integrations/ai-coding-agents/metric-definitions/#随时间比较)。

  PlaidCloud 自己的 AI 助手会优先根据指标回答业务数字，并将数字显示在带 ✓ 标记的独立卡片中，该标记绝不会附在助手自己的文字上。请参阅[业务数字](/zh-cn/guides/ai-assistant/weave-tab/#业务数字)和[来自指标的数字](/zh-cn/guides/ai-assistant/weave-tab/#来自指标的数字)。

- **向 Weave 询问是否已准备好结账，并检查两张表是否一致。** 两者都不涉及 AI。

  - **结账就绪状态。** 在项目的 **Weave** 选项卡中通过**就绪状态**，将结账、预测或任何截止日期所依赖的工作流命名为一个**就绪集**。一份清单即可回答所有这些工作流的情况：“13 个中有 11 个已就绪；1 个未就绪；1 个无法检查。”只有 Weave 能对工作流运行的每项检查都通过，工作流才算就绪；Weave 无法判断的内容会显示为**无法检查**并附上原因，绝不会显示为就绪。如果最近一次运行的更早历史记录太少而无法比较，例如新工作流的运行，则视为正常。不写入表的步骤（例如发送电子邮件或导出文件的步骤）没有行或空值可检查，因此不会使工作流停留在**无法检查**状态。请参阅[结账前检查就绪状态](/zh-cn/guides/ai-assistant/weave-readiness/)。
  - **对账。** 按您配对的键列，逐行比较两张表，或同一张表的两个期间。Weave 会说明两者是否一致、相差多少以及哪些行不同，对于无法完整读取的数据，绝不会说“一致”。每个对账在使用前由另一位架构师批准。请参阅[检查两张表是否一致](/zh-cn/guides/ai-assistant/weave-reconciliation/)。

- **Weave 监视更多可能出错的地方，并在两次运行之间通知您。** Weave 的检查不使用 AI。每个发现项以及 AI 助手的每个回答都有一个 **Weave 如何得知**面板：对发现项，显示检查及其依据的值；对回答，显示助手运行的每个查询，每句话都标记为**已匹配**、**未匹配**或**未检查**。请参阅 [Weave 现在检查的内容](/zh-cn/guides/ai-assistant/weave-findings/#weave-目前检查的内容)、[Weave 如何得知](/zh-cn/guides/ai-assistant/weave-findings/#weave-如何得知)和 [AI 助手中的 Weave 如何得知](/zh-cn/guides/ai-assistant/weave-tab/#weave-如何得知)。

  - **表按时写入。** Weave 会报告自计划到期以来一直没有写入的表，或超过您在表详细信息的**时效性**下设置的时效阈值（1 小时到 180 天）仍未写入的表。
  - **过时或损坏的输入。** Weave 会报告读取了另一个工作流此后写入的表的工作流，以及所有依赖于失败运行的工作流和仪表板，包括图表基于 SQL 数据集构建的仪表板。**同步依赖项**会补上步骤与其读取的表之间缺失的连接器。请参阅[同步依赖项](/zh-cn/guides/workflows/sync-dependencies/)。
  - **数据形态发生变化。** Weave 会报告运行后数值分布发生很大变化的小数列、开始多次写入行的联接、Extract 步骤因无法转换为列类型而留空的值，以及找不到任何文件的导入。它还会报告最近一个期间远离常态的指标，并指出导致这一情况的项目。Weave 会考虑月末和工作日规律，因此总在月末较为繁重的加载不会被报告。请参阅[异常的指标合计](/zh-cn/guides/ai-assistant/weave-metric-insights/)。
  - **变慢的运行。** Weave 会指出使运行变慢的步骤，并报告较新运行比较早运行至少多花四分之一时间的工作流，同时指出耗时增长最多的步骤。
  - **在两次运行之间通知。** 每小时一次的检查会通过应用内消息向每个问题的负责人通知一次，页眉中的 **Weave** 按钮会统计您所有项目中尚未阅读的问题数。请参阅[在两次运行之间收到通知](/zh-cn/guides/ai-assistant/weave-findings/#两次运行之间收到通知)和[页眉中的 Weave 按钮](/zh-cn/guides/ai-assistant/weave-tab/#标题栏中的-weave-按钮)。
  - **负责人、评论和预期警告。** 每个发现项都有负责人，默认是最后运行其工作流的人。**分配**可将其移交他人，评论记录进展，**团队**视图显示谁负责什么。架构师可以将警告标记为**此为预期**，并填写原因和结束日期。请参阅[为发现项指定负责人](/zh-cn/guides/ai-assistant/weave-tab/#为发现项指定所有者)和[将发现项标记为预期](/zh-cn/guides/ai-assistant/weave-tab/#将发现项标记为预期)。

- **修复助手会解释错误、在卡片上提出供您批准的更改、重新运行步骤，并可撤销修复。** 对于最常见的失败，例如表中没有的列、必填设置为空、数据库无法读取的 SQL 或类型错误的值，第一条回复会解释常见原因及修复方法。提议的更改显示为一张卡片，说明步骤失败的原因，并逐项显示每个更改的设置，当前值为红色，新值为绿色。**批准**会应用更改，随后助手会提议重新运行步骤，并诊断新出现的失败。在 **Weave** 选项卡中的发现项上点击**修复**，会针对该问题打开助手。**撤消**会恢复步骤之前的设置，**撤消并运行**则会重建其输出。请参阅[使用 AI 修复工作流错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/)、[使用 AI 助手修复发现项](/zh-cn/guides/ai-assistant/weave-tab/#使用-ai-助手修复发现项)和[撤消修复](/zh-cn/guides/ai-assistant/fixing-workflow-errors/#撤消修复)。

- **查看 Weave 在项目中做过的一切，并导出供审计人员使用。** 项目 **Weave** 选项卡上的**活动**列出 Weave 发现并随后不再发现的问题、AI 助手提议的每项更改、谁提出请求、谁批准或拒绝、它具体替换和写入了什么，以及最终结果。Weave 会先记录您的批准再进行更改，对于无法记录的更改一律不做。**导出 CSV** 或**导出 PDF** 可将某个时间段保存为审计证据，条目不能编辑或删除。**摘要**显示一个月的概览：发现并解决的问题、已批准的更改以及其中被撤消的数量。工作区管理员可以通过**工作区摘要…** 查看每个项目的同类信息。请参阅 [Weave 活动历史记录](/zh-cn/guides/ai-assistant/weave-activity/)和 [Weave 月度摘要](/zh-cn/guides/ai-assistant/weave-monthly-summary/)。

- **保存之前，了解步骤的作用以及更改会影响什么。** 所有这些内容均基于项目已保存的设置生成，不涉及 AI；您的角色所隐藏的内容只计数，不会列出名称。

  - **每个表、步骤和工作流的文档。** 详细信息面板中的**文档**部分描述哪些内容读取和写入某个表、某个步骤的作用，以及工作流中各步骤的顺序。**下载交接包**会将整个项目（包括指标定义和分摊模型）保存为一份文档。请参阅[表、步骤和工作流的文档](/zh-cn/guides/ai-assistant/weave-documentation/)。
  - **更改会影响什么。** 在**保存**上方，Weave 会说明有多少下游步骤读取该步骤写入的内容，例如“对此步骤的更改会影响 2 个工作流中的 8 个下游步骤”，**显示步骤**会列出这些步骤。请参阅[更改会影响什么](/zh-cn/guides/ai-assistant/impact-preview/)。
  - **保存会拒绝什么。** **保存**上方的状态条会在您编辑时运行步骤的检查，每个问题都有**转到**，表达式编辑器会在您输入时检查表达式。请参阅[保存会拒绝什么](/zh-cn/guides/ai-assistant/check-while-you-edit/)。
  - **审核单个工作流。** 工作流画布或**步骤**网格上的**检查**会对其运行 Weave 的检查，以及分摊和行级安全检查。请参阅[审核单个工作流](/zh-cn/guides/ai-assistant/weave-findings/#审核单个工作流)。

- **为您的工作区关闭 Weave 的任何 AI 功能。** 工作区管理员在页眉 **Weave** 按钮上选择 **AI 功能…**，即可分别开启或关闭 Weave 聊天、修复助手、导入和导出助手、表达式助手、根据描述生成 SQL、工作流审核摘要或初始图表。在管理员关闭之前，所有功能都处于开启状态；Weave 的检查和发现项始终保持开启，每次更改都会记录在安全日志中。请参阅 [AI 功能](/zh-cn/guides/ai-assistant/weave-ai-features/)。

- **在 Allocation Split 步骤上试用驱动因素假设分析。** 右键点击该步骤并选择**假设分析…**，可以查看使用不同的驱动因素值、其驱动因素表的另一列，或另一个具有相同键的表中的数值列时，它会如何分摊其成本。最多可比较 10 个方案，每个方案都根据步骤最近一次运行精确计算到分，并显示谁受益、谁受损，以及哪些行将得不到任何分摊。**细分依据**显示每个成员的变化落在哪些科目或其他值上，**后续步骤**会将方案带入由该分摊输出构建的表中。不会重新运行任何内容，也不会更改任何数据。请参阅[试用驱动因素假设分析](/zh-cn/guides/allocations/results/driver-what-if/)。

- **将项目迁移到 Lakehouse v2 时，从就绪状态到撤消全程有引导。** **检查迁移就绪状态**会将表、视图、步骤、仪表板、数据共享和容量报告为畅通、需要审核或已阻止，并对每个发现项附上通俗的说明。**在 v2 上试用…** 会创建一份私有的试用副本，其中计划关闭，ERP 过账处于模拟模式。可以立即开始迁移，也可以在您选择的时间开始。迁移期间项目的计划会暂停，之后恢复，完成时会通过消息和电子邮件通知您。**变更内容…** 会报告每个表的结果，**撤消迁移…** 可在撤消期限内让项目回到 Lakehouse v1。请参阅[将项目迁移到 Lakehouse v2](/zh-cn/guides/data/migrate-project-lakehouse/)。

- **复制项目时会复制其数据，并可选择复制多少。** **复制项目**提供**仅结构**、**完整数据**或**样本**，可在同一个 Lakehouse 内复制，也可从一个 Lakehouse 复制到另一个，复制前会先审核其大小和任何警告。带数据的副本仅对创建者本人私有。**复制结果**会列出每个表的结果，**重试失败的表**只复制失败的表，**查看导入或复制结果**可在稍后重新打开该窗口。传感器和计划事件在副本中是关闭的，因此在您于副本中打开它们之前不会触发任何内容。请参阅[复制项目](/zh-cn/guides/projects/managing-projects/#复制项目)。

- **步骤在保存时而不是运行时发现问题。** 如果保存的步骤设置会导致其运行失败或给出错误结果，保存会被拒绝，并显示说明需要更改什么的消息。每个步骤的参考页面都列出了它所做的检查。步骤或其源表已不再具有的已映射源列会以红色标记，保存时会打开一个对话框，提供**全部移除并保存**、**仍然保存**或**取消**。联接、查找和空间步骤会保留这类行，而不是自行删除。使用未定义变量的表达式会指出该变量的名称，运行时被拒绝的步骤会用通俗的语言解释原因。请参阅[不再列出的源列](/zh-cn/reference/workflow-steps/tables/table-extract/#不再列出的源列)、[源表中缺失的列](/zh-cn/reference/workflow-steps/tables/table-extract/#源表中缺少的列)和[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。

- **每个 Lakehouse 的存储和计算方式都相同。** 来自导入 CSV、导入 XML 或 Import Table Archive 的空字段会加载为 null，因此之后测试 `= ''` 或 `= 0` 的步骤需要改为测试 null。`cast(x, Float)` 在任何地方都是 64 位，因此大额数字会保留所有位数，PlaidCloud 创建的 Float 列为双精度。JSON 列、**Table: Delete Rows** 以及聚合的条件适用于每个 Lakehouse。自行构建结果的步骤，例如求解器、预测，以及在 pandas 中运行时的 Pivot 和 Allocation Split，会将结果作为带类型的数据加载，速度快得多。表资源管理器会显示数值列的最小值、最大值、平均值、总和、标准差和方差。请参阅[转换为 Float](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#转换为-float)和[列数据和唯一计数](/zh-cn/guides/data/table-explorer/#列数据和唯一值计数)。

- **文件导出保留其类型。** Parquet 文件将整数列保留为整数，以微秒存储时间戳，并将时区标记为 UTC。Avro 文件保留日期、时间戳和布尔值的类型，单表 Avro 导出以导出名称命名。为 Parquet 导出选择多个文件时会停止并提示 Parquet 只写入单个文件。非常大的 Parquet、ORC 和 JSON 导出会边读取行边写入，因此不再出现内存不足，Parquet 使用您选择的压缩方式。版本 1.2.33 或更高版本的 PlaidLink 代理会以 Parquet 文件接收导出的表。请参阅 [Export to Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro](/zh-cn/reference/workflow-steps/export/export-to-avro/) 和[数据如何到达代理](/zh-cn/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#数据如何到达代理)。

- **ERP 过账遵循每个计划的模式，不确定的答复会被保留以供您检查。** 计划事件保留自己的过账模式（**实时**、**模拟**或**关闭**），但受项目设置的限制，**运行所选事件**使用每个事件的模式。PlaidCloud 无法确认的 ERP 答复（例如超时或服务器错误）会作为存疑保留，而不是记录为被拒绝，并且一笔过账不能被冲销两次。过账登记簿会列出 **reversal outstanding** 的过账，架构师可在项目主页的 **ERP 写入授权**中授权项目过账。请参阅 [ERP过账模式](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)、[冲销](/zh-cn/guides/connections/posting-register/#冲销)和[授权项目过账](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)。

- **行访问跟得上分组变化，并说明问题所在。** 用户登录时由单点登录设置的分组成员资格，会在约 15 分钟内同步到仪表板行访问，默认分组的新成员约在一分钟内获得其行。行访问窗口会在限制条件没有筛掉任何内容时发出警告，能够处理包含 `&`、`/` 或 `%` 的列名，并在同步失败时显示带原因的**错误**，或显示**正在重试**以及**重试**按钮。请参阅[保持仪表板同步](/zh-cn/administration/access/managing-security-groups-and-assignments/#保持仪表板同步)。

- **用户定义函数在 Python 3.14 上运行，并使用较新的库。** 大多数函数无需更改即可运行。导入 numba 的函数，或导入 Python 已移除的标准库模块（例如 `cgi` 或 `telnetlib`）的函数，现在会失败，需要重写。Forecast 的 AutoTheta 边界可能与之前的运行略有不同。请参阅[用户定义转换](/zh-cn/reference/workflow-steps/general/user-defined-transform/)。

- **完整代理访问已弃用，将于 2027 年 1 月 15 日移除。** 使用**完整**访问的 LLM 步骤会记录警告。请改用**读取和写入**，此时代理通过 PlaidCloud 的写入工具更改数据，LLM 步骤仅写入勾选了**写入**的绑定。请参阅[代理访问](/zh-cn/integrations/ai-architecture/llm-providers/#代理访问)。

- **Project 应用更完整地处理发票、行程和补报工时。** 新发票从主项目开始，由主项目提供客户和采购订单号。删除发票草稿会使其工时和行程重新可计费，**AR 收件人**设置发票提交时通过电子邮件通知谁。行程抽屉会显示每一行的供应商、类别和审核状态，**添加补报工时**会为已批准的一周启动工时表。请参阅[使用 Project 应用跟踪工时和费用](/zh-cn/guides/time-expense/track-time-and-expenses/)。

- **删除所有未被任何步骤引用的表的 API 调用已移除。** 请改为按 ID 删除表。

- **应用中的其他小改动。** 双击账户、仪表板、成员、分组或设置列表中的行即可打开它。空的**维度**、**数据编辑器**、**UDF** 和**步骤**选项卡会说明下一步该做什么，没有应用的成员会进入 Launcher。步骤的表选择器会显示表最后一次更新的时间（[查看源表最后一次更改的时间](/zh-cn/guides/workflows/create-workflow/#查看源表最后一次更改的时间)）。Export External Database Tables 在自己的选项卡上映射列，**报表：批量生成**不再显示未使用的 **Report Constants** 部分。Convert Encoding 可识别中欧、土耳其和阿拉伯语编码。指向已移除屏幕的链接会注明这一点。

## 修复

- **AI 助手在您批准之前不会更改任何内容，并按原样显示名称。** 以前将步骤构建到新表中时，表会在您批准之前就被创建；现在表和步骤会在您批准之后一起创建，创建项目、工作流或维度、复制表以及更改表属性或标签也都会先询问。批准只在您的下一条回复中有效。助手提议的导入或导出会按名称显示其表、文档账户和工作流，并且绝不会与不存在或您无法打开的对象一起提供。包含下划线的名称会原样显示而不会变成斜体，表和代码在深色主题中可读，图表会绘制出来而不是显示为文本，表达式编辑器的 Weave 面板会读取您正在编辑的表达式。即使有表没有名称，助手也会列出项目的表；即使步骤读取或写入多个表，助手也能回答哪些步骤读取或写入某个表，而不是因错误而停止。请参阅[构建工作流步骤](/zh-cn/guides/ai-assistant/weave-tab/#构建工作流步骤)。

- **文件导入读取您指向的内容。** 导入 Excel 可读取整列范围和 XLSB 工作簿，能在压缩的工作簿中找到工作表，并且不再因带填充或换行的标题而失败。导入 CSV 遵循**跳过行数**，因此标题上方有若干行的文件（例如 SAP 列表导出）可按列名导入，并且使用默认的分隔符、引号和转义字符运行。一个源列可以为多个目标列提供数据，列均为固定值的导入会加载每一行，使用大写压缩扩展名命名的文件会被解压缩，未变化时跳过的导入会重新加载已被清空的表。要求 AI 助手从 **Project Default** 导入文件时，会读取项目的默认文档账户，并在项目未设置时明确告知您。包含较新列类型的 Parquet 文件可在文档中打开。请参阅[导入 Excel](/zh-cn/reference/workflow-steps/import/import-excel/#读取内容)和[导入 CSV](/zh-cn/reference/workflow-steps/import/import-csv/#行选择)。

- **工作流步骤按配置保存和运行。** 表：Upsert 步骤可以再次保存，其**更新键**列也已恢复。表：项目间复制会指明其目标项目，并通过数据共享读取。文档：将仪表板保存为 PDF 会保留其列类型，表：去重合并和表：全部合并按名称匹配列。多表联接可以使用多个输入保存，并接受带空格的列名。Table Lookup 会忽略其查找列上的聚合设置，SCD-2 截至日期联接可将变量作为日期。LLM 步骤可在早于 4.6 的 Claude 模型上运行，并在 AI 助手编辑它们时保持其模型。REST 请求发送的行值只编码一次，导出到远程数据库的步骤会提交其行。请参阅[更新键](/zh-cn/reference/workflow-steps/tables/table-upsert/#更新键)、[数据共享管理](/zh-cn/reference/workflow-steps/tables/frame-project-copy/#数据共享管理)和[多表联接](/zh-cn/reference/workflow-steps/tables/table-multi-table-join/)。选择工作流的步骤（例如删除工作流、复制工作流、重命名工作流和停止工作流）会保留已不存在的工作流，显示为 *id (missing)*，而不是切换到列表中的第一个工作流。

- **工作流运行按应有方式完成。** Workflow Loop 会在每次迭代中运行循环的工作流，迭代容器以及在一次运行中多次运行的工作流也是如此。从某个步骤开始或在并行组内开始的运行会运行正确的步骤并完成。长时间运行的导入或导出绝不会启动两次，也不会在 PlaidCloud 更新期间停滞，以服务器错误结束的操作不会再次发送。数据库驱动程序崩溃只会使其自身的步骤失败，并给出数据库的原因。运行历史记录会统计每个步骤的行数，在工作开始前失败的步骤会将原因写入工作流日志。请参阅 [Workflow Loop](/zh-cn/reference/workflow-steps/workflow-control/workflow-loop/) 和[运行历史记录](/zh-cn/guides/workflows/advanced-workflows/#运行历史)。

- **项目的复制、导入和打开不再出现意外。** 项目导入会保留所有能够恢复的内容，并在**导入结果**窗口中列出遗漏的内容，显示进度，说明失败的原因，并且可以重试。当项目含有变量时，复制所选对象也能正常工作。打开项目不再更改其设置，**导入您自己的数据**会导入您的 CSV，在 PostgreSQL 数据仓库上创建表也能正常工作。App Runner 应用会在 PlaidCloud 更新时自动刷新，并对限制行的项目上的查看者正常工作。请参阅[归档中的部分内容未导入时](/zh-cn/guides/projects/archive-a-project/#归档的部分内容未能导入时)和[保持应用为最新](/zh-cn/guides/workflows/use-converted-alteryx-apps/#保持应用为最新)。

- **维度和分摊的加载与读取正确无误。** 父子加载会将父级为空的行保留为顶级成员，对于第二个备用层次结构，在每种加载方式中都会拒绝主层次结构之外的成员。将成员移到其层次结构中不存在的父级之下会被拒绝，维度步骤会指出找不到的维度名称，粘贴含有空白的列时每个值仍保留在其所在行。读取大型维度不再拖慢工作区中的其他所有人。维度属性的**层次结构**保持为**未指定**的分摊规则可以运行。请参阅[加载到备用层次结构](/zh-cn/reference/workflow-steps/dimensions/dimension-load/#加载到备用层次结构)和[维度类型属性和成员选择器](/zh-cn/guides/dimensions/dimensions/#维度类型属性和成员选取器)。

- **工作流画布和屏幕表现正常。** **钻取到工作流**会在画布上打开高级工作流，画布可以打开每个工作流，并在布局的某部分无法读取时告知您。放不下的工具栏按钮会移入**更多**菜单，列表在您保存后立即更新。通知会显示完整的消息，警告会在**日志**选项卡中显示警告图标，表资源管理器会在某列的概要分析失败时给出说明，数据编辑器会让空日期单元格保持为空。在打开列筛选器的情况下保存数据编辑器，会保留被筛选器隐藏的行，包括在您添加、删除或移动行之后。任何有权更改用户定义函数的人，其编辑器都可编辑。请参阅[画布无法打开工作流时](/zh-cn/guides/workflows/advanced-workflows/#画布无法打开工作流时)。从**表**列表中删除表时，会列出仅通过变量路径（例如 `/Periods/{period}/Sales`）访问某个表的任何步骤，并且只有在您强制删除时才会删除该表。请参阅[删除](/zh-cn/guides/projects/managing-tables-and-views/#删除)。

- **成员和连接按预期工作。** **添加工作区成员**适用于已有账户的人（包括通过单点登录创建的账户），并且绝不会降低其已有的项目角色。ODBC 连接通过 PlaidLink 代理所在计算机上的 DSN 或驱动程序进行连接。拒绝您的 OAuth 凭据的提供商会提示您重新输入或重新授权，Databricks 示例和导出会刷新即将过期的令牌，较旧数据库类型的连接可以删除。**使用位置**包括通知步骤，免费工作区保留每日、每周和每月备份。请参阅[成员管理](/zh-cn/administration/access/member-management/)和 [ODBC](/zh-cn/reference/connectors/databases/odbc/)。

- **REST API 和 AI 助手工具严格按您的要求执行。** 对成员、分组或计划事件的部分更新只更改您指定的字段，因此暂停的事件会保持暂停。从指定步骤开始运行就会从该步骤开始，还原表快照会保留一个安全快照和一条审计记录。AI 工具的驱动因素假设分析仅在与您的模型实际进行的拆分一致时才作答。以前因服务器错误而失败的请求现在可以正常工作，或说明哪里出了问题。请参阅[追踪分摊](/zh-cn/integrations/ai-coding-agents/tracing-allocations/)和[回退或还原快照](/zh-cn/guides/data/table-snapshots/#回退或还原快照)。

## 安全

- **AI 助手始终在您的权限范围内。** 助手的数据查询在运行前会按其结构检查，并且只运行单个读取查询。只读的 AI 连接（包括 Microsoft 365 Copilot）无法导出文件、保存仪表板 PDF、将行复制到另一个项目，或通过 REST 连接发送更改。通过 AI 助手进行的导入以您的身份在您指定的项目中运行，对话只能由发起者继续。助手和表引用不包含您的角色所隐藏的表、步骤、工作流和维度，对于您无法打开的失败步骤，Weave 只统计数量而不列出名称。请参阅[访问级别](/zh-cn/integrations/microsoft-365-copilot/#访问级别)、[您的角色隐藏了什么](/zh-cn/guides/ai-assistant/weave-tab/#您的角色所隐藏的内容)和[管理过去的对话](/zh-cn/guides/ai-assistant/weave-tab/#管理过去的对话)。

- **ERP 过账无法绕过其控制措施。** 启用职责分离后，冲销需通过过账登记簿，并适用其中的批准。复制或导入的项目不再继承过账权限，SAP 和 EBS 过账无法直接发送给代理，仅测试模式下的 SAP Post 步骤需要与实际过账相同的权限。一个未公开的、不经过这些检查就向 Sage Intacct 过账的端点已被移除。ERP 和 REST 连接的错误消息不再包含凭据。请参阅[职责分离](/zh-cn/guides/connections/posting-register/#职责分离)。

- **机密信息只写不读，只有所有者决定谁可以使用连接。** 文档账户的密钥、密码和令牌在保存后不再显示，更改账户的连接位置需要再次提供机密信息。步骤中的密码和密钥只保存在变量中；已输入到步骤中的机密信息已移入仅架构师可见的项目变量。多行凭据在您输入时会被屏蔽。只有连接的所有者或工作区管理员才能更改谁有权访问它。请参阅[已保存的机密信息只写不读](/zh-cn/guides/documents/adding-accounts/#已保存的机密为只写)、[密钥保存在变量中](/zh-cn/reference/workflow-steps/document/encrypt-decrypt-file/#密钥存放在变量中)和[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

- **您无法使用的文档账户对您保持关闭。** 检查文件是否存在、读取 Parquet、Avro、ORC 或 Delta 文件的列、使用**填充**填充导入步骤的列，以及 AI 助手的文件检查，现在都会拒绝您没有访问权限的账户，浏览该账户时本来就是如此。

- **只有工作区管理员才能更改工作区管理员。** 编辑、停用或删除管理员、更改其分组以及将某人设为管理员，都需要工作区管理员。请参阅[更改工作区管理员](/zh-cn/administration/access/member-management/#更改工作区管理员)。

- **数据共享只代表获得授权的项目的成员。** 通过共享读取需要在接收项目中拥有角色，写入需要**写入**共享以及在该项目中拥有管理者或架构师角色。请参阅[在项目之间共享数据](/zh-cn/guides/projects/managing-projects/#在项目之间共享数据)。

- **还原只适用于所指定的项目。** 还原早期版本会还原项目本身，权限检查针对该项目。内容不属于其自身标头中所列维度的维度备份文件会被拒绝。请参阅[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。

- **模板、导入和归档会拒绝不安全的内容。** 导出模板和报表模板在沙盒中渲染，只读取提供给它们的数据。导入根据自身的设置构建加载查询，包含 PlaidCloud 归档绝不会包含的内容的项目归档会被拒绝，会与其他项目共享报表架构的项目标识符也会被拒绝。请参阅[模板可以使用什么](/zh-cn/reference/workflow-steps/export/export-templated/#模板可以使用的内容)和[还原归档](/zh-cn/guides/projects/archive-a-project/#还原归档)。

- **仪表板遵循 PlaidCloud 登录和您的行访问。** 仪表板的缩略图以您的身份渲染，账户仅来自 PlaidCloud 登录，仪表板只能从导出所生成的 ZIP 文件导入。请参阅[导入现有仪表板](/zh-cn/guides/dashboards/learning-dashboard/#导入现有仪表板)。

- **启动工作流运行不再返回该运行的凭据。**

- **运行用户定义函数的环境不再包含 PySpark 的 Java 库，** 这些库存在已知漏洞。PySpark 的 DataFrame 和 SQL API 仍可访问您的 Spark 计算集群，但导入 `SparkContext` 或 `RDD` 的函数现在会失败。请参阅 [PySpark 入门](/zh-cn/integrations/pyspark/getting-started/)。

- **附件、还原和转换只读取您可以使用的账户。** 通过电子邮件发送文件、从文件还原维度或表归档、检查或导入表包、从模板填充 Excel 导出，以及转换 Alteryx 工作流，现在都会拒绝您没有访问权限的文档账户。将维度备份到文档账户需要对其具有写入权限。工作流步骤不受影响，只是通过电子邮件发送文件、还原表或填充 Excel 模板的步骤不再能从 Personal Temp Drive 读取。
