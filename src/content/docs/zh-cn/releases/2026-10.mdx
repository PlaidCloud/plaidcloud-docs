## 新增

- **Data Foundation 将您的 ERP 数据汇集到一个 Common Finance Model 中。** Common Finance Model 将来自多个 ERP 系统和实例的 ERP 数据汇入单一模型：一个会计科目表、一组实体和一种报告货币。基于它构建的报表、指标和 AI 代理读取的都是同一组数字，无论数据来自哪个 ERP。

  - **直接来自 ERP。** 总账、试算平衡表、主数据和预算通过 PlaidCloud 的 ERP 直连到达。**实体对照表** 将每个源的公司代码映射到同一批实体，文件则补充系统中没有的内容，例如汇率或分摊动因。
  - **一个模型，一种货币。** **加载** 将每个源整合进 Common Finance Model，并折算为您的报告货币：损益表按期间平均汇率，资产负债表按期末汇率，权益按历史汇率。层次结构由您的主数据构建。
  - **检查就绪状态。** 针对每个实体和期间运行检查：试算平衡表和销售与总账一致，每个产品、客户和科目都已知，货币可以折算，每个实体都已映射。
  - **多个源，一个模型。** 添加、排序、编辑和移除源，每个源可以是一个 ERP 系统、实例或文件。**加载** 会整合所有源，在重叠处保留一份副本，并记录被暂扣的行及原因；**应用更改** 无需再次从 ERP 拉取即可重新运行整合。
  - **跨源映射代码。** 当多个源共用一个代码时，系统会按名称匹配给出建议，询问它们是否含义相同；可以回答单个代码，也可以用 **全部接受**、**全部相同** 或 **全部不同** 回答整个分组。映射按源和维度保存。最多十个额外类别使用您指定的名称，覆盖范围视图则可让您选择从哪个月起由哪个源计数。
  - **文件选项。** 文件可以只适用于一个源、询问其需要回答的问题、将一列拆分为多个字段、设置报告货币，或被移除。
  - **管理合并。** 每次加载都会构建集团损益表（包括年初至今），公司间交易在 **抵销** 实体上抵销，另有 **未映射** 项，并可与合并系统的结果对账。这是一种管理视图，仅限项目的架构师查看，除非其向团队开放，并且不是法定合并。
  - **保持最新。** **每晚刷新** 每晚重新加载模型，缺失或为空的文件会以警告而不是错误结束。

  从 **Enterprise Profitability** 等模板开始项目，项目的 **基础数据** 选项卡会带您从已连接的 ERP 一路走到已加载并检查过的模型。请参阅 [Data Foundation：Common Finance Model](/zh-cn/guides/projects/data-foundation/)。

- **在您自己的 Snowflake 或 Databricks 数据仓库上运行 PlaidCloud。** 工作区管理员在用户菜单中打开 **使用您自己的数据仓库**，并在自己的账户中运行生成的设置脚本。该脚本会为 PlaidCloud 创建一个设有用量上限的数据仓库和一个服务身份，绝不会触及您现有的数据仓库。**检查连接** 会用通俗的语言说明任何问题及其修复方法。此后新项目会将其表存储在您的数据仓库中并在其中运行工作流，移除该数据仓库即可撤销 PlaidCloud 在其中的访问权限。请参阅[使用您自己的数据仓库](/zh-cn/guides/connections/external-lakehouse/)。

  - **使用 Snowflake 或 Databricks 登录。** 管理员无需粘贴凭据，可以通过登录来附加数据仓库。仪表板随后以每个人自己的数据仓库权限运行，工作流则以仅持有您指定数据角色的服务身份运行。请参阅[使用 Snowflake 或 Databricks 登录](/zh-cn/guides/connections/external-lakehouse/#使用-snowflake-或-databricks-登录)。
  - **连接多个。** 在 **管理数据仓库** 中点击 **设为默认** 会将新项目发送到另一个数据仓库，现有项目保持原样。请参阅[管理数据仓库](/zh-cn/guides/connections/external-lakehouse/#管理数据仓库)。
  - **查看每次运行的成本。** 运行历史记录会为每次运行显示一列以点数或 DBU 计的 **仓库成本**。请参阅[每次运行的仓库成本](/zh-cn/guides/connections/external-lakehouse/#每次运行的仓库成本)。
  - **您的治理策略保持不变。** 描述会写入数据仓库自己的目录，且当 PlaidCloud 替换、重建或克隆表时，Snowflake 的行访问策略和掩码策略以及 Databricks 的行筛选器和列掩码仍保持附加。请参阅[您的策略和描述会被保留](/zh-cn/guides/connections/external-lakehouse/#您的策略和说明会延续)。

- **在 PlaidCloud 内构建、发布 Panel 应用并设置品牌。**

  - **Panel Studio。** **创建应用** 可从空白应用、表、视图、模板或应用图库开始，**在 Studio 中打开** 会在编辑器中打开应用的文件。可以保存草稿、**预览** 私有构建，并 **发布** 正式应用。构建错误会指向其所在的文件和行，**历史记录** 可恢复任何已发布的版本，**洞察** 显示浏览量、加载时间和错误。**询问 Weave** 了解应用的文件和构建状态，并在保存任何代码之前向您展示完整差异以供批准。请参阅 [Panel Studio](/zh-cn/guides/panel-apps/studio/) 和[借助 Weave 构建 Panel 应用](/zh-cn/guides/panel-apps/build-with-weave/)。
  - **外观与 PlaidCloud 一致的应用工具包。** 使用该工具包构建的应用在浅色和深色模式下都采用 PlaidCloud 的颜色、字体和间距。工具包包括导航、筛选器、关键数字卡片、图表、表单、命令面板、运行工作流的按钮、打印，以及一个在服务器端排序和合计、按列设置数字格式、每次只加载一屏行的数据网格，因此可处理任意大小的表。应用以已登录查看者的身份读取表，并应用行级安全。请参阅 [Panel 应用工具包](/zh-cn/guides/panel-apps/app-kit/)、[DataGrid](/zh-cn/guides/panel-apps/app-kit/#datagrid) 和 [Panel 应用的数据 API](/zh-cn/guides/panel-apps/data-api/)。
  - **提醒和摘要。** 当项目表中的某个数字越过限值时，通过推送通知、电子邮件、Slack 或 Microsoft Teams 获得通知，或获取最多 10 个数字的每日或每周摘要，始终遵循您自己的行访问权限。请参阅[提醒和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
  - **项目、品牌和共享。** 将应用分配给项目，分配前会审核哪些不在项目中的人可以打开它。项目 **主页** 选项卡上的 **编辑品牌** 为项目中的每个应用设置八种品牌颜色和一个徽标。**图库…** 将应用列为可供所有能查看其项目的人使用的模板。请参阅[项目品牌和应用项目](/zh-cn/guides/panel-apps/branding/)和[应用图库](/zh-cn/guides/panel-apps/gallery/)。

- **一次约定业务数字的计算方式，每个 AI 答案都采用该计算。** 项目架构师定义一个 **指标**，例如 *净收入* 或 *员工人数*：其源表、各行如何汇总、始终计入的行、它联接的查找表，以及可用于细分的列。定义一经保存即生效；如果保存时指明了缺失的表或列，或某个查找表的每个键对应多行，则保存会被拒绝。按名称或同义词向 AI 助手询问该指标，数字将按定义在您自己的行访问权限下计算，而不是由助手自行推算。定义通过 AI 助手或 REST API 管理。请参阅[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。

  - **派生指标。** 定义两个指标的比率、和或差，例如每名全职员工的净收入，或某个指标乘以固定系数。请参阅[由其他指标派生指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#由其他指标派生指标)。
  - **比较、排名和占比。** 询问相对预算的差异、保留并列的前 N 或后 N，或每行占合计的比例。请参阅[比较、排名和占比](/zh-cn/integrations/ai-coding-agents/metric-definitions/#比较排名和占比)。
  - **用您的话，取约定的值。** 将细分列绑定到某个维度，则像 *EMEA* 这样的词会变成其下的每个区域。不匹配任何成员或匹配多个成员的词，会以候选项的形式返回并询问您，绝不猜测。请参阅[询问指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#询问指标)。
  - **财政时间。** 告诉指标其各行在财务日历中的位置，即可询问财政期间、年初至今、同比或环比。请参阅[随时间比较](/zh-cn/integrations/ai-coding-agents/metric-definitions/#随时间比较)。

  PlaidCloud 自己的 AI 助手会优先根据指标回答业务数字，并在带有 ✓ 标记的单独卡片中显示这些数字，该标记绝不会附加在助手自己的文字上。请参阅[业务数字](/zh-cn/guides/ai-assistant/weave-tab/#业务数字)和[来自指标的数字](/zh-cn/guides/ai-assistant/weave-tab/#来自指标的数字)。

- **询问 Weave 是否已准备好结账，并检查两张表是否一致。** 两者都不涉及 AI。

  - **结账就绪状态。** 在项目 **Weave** 选项卡的 **就绪状态** 中，将结账、预测或任何截止期限所依赖的工作流指定为一个 **就绪集**。一份清单即可回答所有这些工作流的状态：“13 个中 11 个已就绪；1 个未就绪；1 个无法检查。”只有当 Weave 能对某个工作流运行的每项检查都通过时，该工作流才算就绪；Weave 无法判断的任何内容都会显示为 **无法检查** 并附上原因，绝不显示为已就绪。若最近一次运行缺少足够的较早历史可供比较（例如新工作流的运行），则视为正常。不写入表的步骤（例如发送电子邮件或导出文件的步骤）没有可检查的行或空值，因此不会使工作流停留在 **无法检查**。请参阅[结账前检查就绪状态](/zh-cn/guides/ai-assistant/weave-readiness/)。
  - **对账。** 按您配对的键列，逐行比较两张表，或同一张表的两个期间。Weave 会说明它们是否一致、相差多少以及哪些行不同，对于无法完整读取的数据，绝不会说“一致”。每个对账在使用前都需由另一位架构师批准。请参阅[检查两张表是否一致](/zh-cn/guides/ai-assistant/weave-reconciliation/)。

- **Weave 监视更多可能出错的地方，并在两次运行之间通知您。** Weave 的检查不使用 AI。每个发现项以及 AI 助手的每个答案都有一个 **Weave 如何得知** 面板：对于发现项，显示检查及其背后的值；对于答案，显示助手运行的每条查询，并将每个句子标记为 **已匹配**、**未匹配** 或 **未检查**。请参阅 [Weave 目前检查的内容](/zh-cn/guides/ai-assistant/weave-findings/#weave-目前检查的内容)、[Weave 如何得知](/zh-cn/guides/ai-assistant/weave-findings/#weave-如何得知)和 [AI 助手中的 Weave 如何得知](/zh-cn/guides/ai-assistant/weave-tab/#weave-如何得知)。

  - **表按时写入。** Weave 会报告自其计划到期以来未被写入的表，或超过您在表详细信息的 **时效性** 下所设阈值（1 小时至 180 天）未被写入的表。
  - **过期或损坏的输入。** Weave 会报告读取了其他工作流此后写入的表的工作流，以及所有依赖失败运行的工作流和仪表板，包括图表基于 SQL 数据集构建的仪表板。**同步依赖项** 会添加步骤与其所读取的表之间缺失的连接器。请参阅[同步依赖项](/zh-cn/guides/workflows/sync-dependencies/)。
  - **数据形态发生变化。** Weave 会报告运行后值的分布差异很大的小数列、开始多次写入行的联接、提取步骤因无法转换为列类型而留空的值，以及未找到任何文件的导入。它还会报告最新期间与常态相差很大的指标，并指出造成这一情况的项目。Weave 会考虑月末和工作日规律，因此在月末总是偏重的加载不会被报告。请参阅[异常的指标合计](/zh-cn/guides/ai-assistant/weave-metric-insights/)。
  - **变慢的运行。** Weave 会指出使运行变慢的步骤，并报告较新运行比较早运行至少多花四分之一时间的工作流，同时指出耗时增长最多的步骤。
  - **在两次运行之间通知。** 每小时一次的检查会在应用内消息中通知每个问题的所有者一次，页眉中的 **Weave** 按钮会统计您所有项目中尚未读取的问题数。请参阅[在两次运行之间获得通知](/zh-cn/guides/ai-assistant/weave-findings/#两次运行之间收到通知)和[页眉中的 Weave 按钮](/zh-cn/guides/ai-assistant/weave-tab/#标题栏中的-weave-按钮)。
  - **所有者、评论和预期警告。** 每个发现项都有一位所有者，默认是最后运行其工作流的人。**分配** 可将其移交，评论记录进展，**团队** 视图显示谁负责什么。架构师可以将警告标记为 **此为预期**，并附上原因和结束日期。请参阅[为发现项指定所有者](/zh-cn/guides/ai-assistant/weave-tab/#为发现项指定所有者)和[将发现项标记为预期](/zh-cn/guides/ai-assistant/weave-tab/#将发现项标记为预期)。

- **修复助手会解释错误，提出供您在卡片上批准的更改，重新运行步骤，并可撤消修复。** 对于最常见的故障，例如表中不存在的列、必填设置为空、数据库无法读取的 SQL 或类型错误的值，首次回复会解释常见原因及修复方法。提议的更改以卡片形式出现，卡片说明步骤失败的原因，并显示每个更改的设置，其当前值为红色，新值为绿色。**批准** 会应用更改，随后助手会提议重新运行该步骤，并诊断新出现的失败。在 **Weave** 选项卡中的发现项上点击 **修复** 会针对该问题打开助手。**撤消** 会恢复步骤之前的设置，**撤消并运行** 用于重建其输出。请参阅[借助 AI 修复工作流错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/)、[借助 AI 助手修复发现项](/zh-cn/guides/ai-assistant/weave-tab/#使用-ai-助手修复发现项)和[撤消修复](/zh-cn/guides/ai-assistant/fixing-workflow-errors/#撤消修复)。

- **查看 Weave 在项目中所做的一切，并导出供审计人员使用。** 项目 **Weave** 选项卡上的 **活动** 会列出 Weave 发现并后来不再发现的问题、AI 助手提议的每项更改、由谁请求以及由谁批准或拒绝、它具体替换和写入了什么，以及最终结果。Weave 会在做出更改之前记录您的批准，并且不会做出无法记录的更改。**导出 CSV** 或 **导出 PDF** 可将某个期间保存为审计证据，条目无法编辑或删除。**摘要** 显示一个月的概览：发现并解决的问题、已批准的更改以及其中被撤消的数量。工作区管理员可通过 **工作区摘要…** 获得所有项目的同类信息。请参阅 [Weave 活动历史记录](/zh-cn/guides/ai-assistant/weave-activity/)和 [Weave 月度摘要](/zh-cn/guides/ai-assistant/weave-monthly-summary/)。

- **在保存之前了解步骤的作用以及更改它会影响什么。** 所有这些都基于项目已保存的设置构建，不涉及 AI，且您的角色所隐藏的内容只会被计数，绝不会点名。

  - **每张表、每个步骤和每个工作流的文档。** 详细信息面板中的 **文档** 部分说明了哪些内容读取和写入某张表、某个步骤的作用，以及工作流各步骤的先后顺序。**下载交接包** 会将整个项目保存为一份文档，其中包含指标定义和分摊模型。请参阅[表、步骤和工作流的文档](/zh-cn/guides/ai-assistant/weave-documentation/)。
  - **更改会影响什么。** 在 **保存** 上方，Weave 会说明下游有多少个步骤读取该步骤所写入的内容，例如“对此步骤的更改会影响 2 个工作流中的 8 个下游步骤”，**显示步骤** 会列出它们。请参阅[更改会影响什么](/zh-cn/guides/ai-assistant/impact-preview/)。
  - **保存会拒绝什么。** **保存** 上方的状态条会在您编辑时运行该步骤的检查，并为每个问题提供 **转到**，表达式编辑器会在您输入时检查表达式。请参阅[保存会拒绝什么](/zh-cn/guides/ai-assistant/check-while-you-edit/)。
  - **对单个工作流的审查。** 在工作流画布或 **步骤** 网格上点击 **检查**，会对其运行 Weave 的检查，以及分摊和行级安全检查。请参阅[审查单个工作流](/zh-cn/guides/ai-assistant/weave-findings/#审核单个工作流)。

- **为您的工作区关闭任何 Weave AI 功能。** 工作区管理员在页眉的 **Weave** 按钮上选择 **AI 功能…**，可以分别打开或关闭 Weave 聊天、修复助手、导入和导出助手、表达式助手、根据描述生成 SQL、工作流审查摘要或入门图表。在管理员关闭之前，所有功能均为开启状态，Weave 的检查和发现项始终保持开启，且每项更改都会记录在安全日志中。请参阅 [AI 功能](/zh-cn/guides/ai-assistant/weave-ai-features/)。

- **在分摊拆分步骤上尝试驱动因素假设分析。** 右键点击该步骤并选择 **假设分析…**，可查看使用不同的驱动因素值、其驱动因素表的不同列，或来自另一张具有相同键的表的数值列时，它将如何分摊其成本。最多可比较 10 个方案，每个方案都基于该步骤上次运行的结果精确计算到分，并可看到谁受益、谁受损，以及哪些行将分不到任何金额。**细分依据** 显示每个成员的变化落在哪些科目或其他值上，**后续步骤** 则将该方案延续到由分摊输出构建的表中。不会重新运行任何内容，也不会更改任何数据。请参阅[尝试驱动因素假设分析](/zh-cn/guides/allocations/results/driver-what-if/)。

- **在运行之前把联接的键设置正确。** **联接映射** 上的 **推测** 会依次使用联接同样两张表的另一个步骤的键、指标、表的键列、匹配的名称，并说明用了哪一种。**检查键** 会统计被联接表中重复的键值，这些重复值可能使您的行数成倍增加。当 **检查源** 填充步骤的列时，`customer_id` 之类的标识符列起初为 **分组依据** 而不是 **求和**。请参阅[内联接](/zh-cn/reference/workflow-steps/tables/table-inner-join/#检查键)。

  - **Copilot 能做更多。** Microsoft 365 Copilot 中的 PlaidCloud 代理可以创建 CSV、Excel、PowerPoint 和 Word 文件，根据您的指标回答业务数字，对整张表的细分结果求和，并解释分摊的工作原理。管理员下载更新后的软件包，并在 Teams 管理中心更新。请参阅 [Microsoft 365 Copilot](/zh-cn/integrations/microsoft-365-copilot/)。
  - **一次调用完成更多。** 助手可以在服务器上对表分组并求和（先应用行访问权限）、搜索和阅读 PlaidCloud 的文档、创建完整配置的文档账户（包括 OneDrive 和 SharePoint，凭据为只写）、移除和添加标签，并使用您在 PlaidCloud 中看到的视图。请参阅[分析路径](/zh-cn/integrations/ai-coding-agents/analysis-paths/#通过-mcp-使用)和 [AI 代理入门](/zh-cn/integrations/ai-coding-agents/getting-started/)。

## 变更

- **一个 Weave 选项卡同时包含您的发现项和 Weave AI 聊天。** 聊天是 **Weave** 选项卡内位于 **发现项** 之后的选项卡。每个发现项都是一张卡片，带有各自的 **修复**、**转到** 和 **标记为已读** 按钮，虚线卡片标示 Weave 无法检查的内容，筛选标签按需要关注的程度筛选列表。关于表达式的发现项会指出错误所在位置，表达式本身位于 **Weave 如何得知** 之下。Weave 在运行结束时对每个问题只提及一次，关于同一项目的消息会合并为一条，而不是不断堆叠。该选项卡在大型项目中打开很快，因为 Weave 只重新检查发生变化的内容。工作流列表中的 Weave 列已移除。请参阅 [Weave 选项卡](/zh-cn/guides/ai-assistant/weave-tab/)和[运行结束时获得通知](/zh-cn/guides/ai-assistant/weave-findings/#运行结束时收到通知)。

- **Ctrl/Cmd-K 可在任意屏幕打开命令面板。** 在输入之前，它会列出您最近打开的内容和可执行的操作：前往主页、项目、仪表板或文档，在浅色和深色之间切换，连接您的 AI，或获取帮助。输入内容会同时缩小两个列表，输入两个字符后还会搜索项目、工作流、表、仪表板和 Panel 应用。请参阅[搜索和命令](/zh-cn/guides/launcher/#搜索和命令)。

- **步骤在保存时发现问题，而不是在运行时。** 如果保存的步骤其设置会导致运行失败或产生错误结果，保存会被拒绝，并附带说明需要更改什么的消息。每个步骤的参考页面都列出了它所做的检查。映射的源列如果步骤或其源表中已不存在，会以红色标记，保存时会打开带有 **全部移除并保存**、**仍然保存** 或 **取消** 的对话框。联接、查找和空间步骤会保留此类行，而不是自行删除。使用未定义变量的表达式会指出该变量，运行时被拒绝的步骤会用通俗的语言解释原因。请参阅[不再列出的源列](/zh-cn/reference/workflow-steps/tables/table-extract/#不再列出的源列)、[源表中缺失的列](/zh-cn/reference/workflow-steps/tables/table-extract/#源表中缺少的列)和[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。

- **缺失或为空的源绝不是错误。** 文件缺失或为空的文件导入会以指明路径的警告结束，并让其目标表保持为空但保留已声明的列，因此后续步骤读取到零行。针对缺失或为空文件夹的文档步骤会报告“无需处理”，工作流继续运行。远程文件步骤对缺失的路径给出警告，并拒绝不安全的路径。对缺失文件的检查适用于 OneDrive、SharePoint 和 SFTP。批处理表为空的 **报表：批量生成** 会以警告结束，且不生成任何报表。请参阅[导入步骤](/zh-cn/reference/workflow-steps/import/)、[文档工作流步骤](/zh-cn/reference/workflow-steps/document/)和[文档路径条件](/zh-cn/guides/workflows/step-conditions/#文档路径条件)。

- **大型工作流运行可靠，并且停止会取消导入和导出。** 当 PlaidCloud 繁忙时，步骤会等待容量而不是失败，并且随着步骤排队会增加容量。导入外部数据库表最多同时运行 10 张表。如果运行步骤的服务器丢失，替换其输出的步骤会自动再次运行，无法安全重复的步骤则会以 *已中断* 消息失败一次。**停止** 会取消正在运行的导入和导出作业，已停止的运行报告为“已停止”。请参阅[已中断的步骤](/zh-cn/guides/workflows/run-a-workflow/#已中断的步骤)和[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)。

- **每个 Lakehouse 的存储和计算方式一致。** 来自导入 CSV、导入 XML 或 Import Table Archive 步骤的空字段会加载为空值，因此后面测试 `= ''` 或 `= 0` 的步骤需要改为测试空值。`cast(x, Float)` 在各处都是 64 位，因此大额金额保留所有位数，PlaidCloud 创建的 Float 列为双精度。JSON 列、Table: Delete Rows 步骤以及使用聚合的条件在每个 Lakehouse 上都可使用。自行构建结果的步骤，例如求解器、预测，以及在 pandas 中运行的 Pivot 和 Allocation Split，会将结果作为类型化数据加载，速度快得多。表资源管理器会显示数值列的最小值、最大值、平均值、总和、标准差和方差。请参阅[转换为 Float](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#转换为-float)和[列数据和唯一计数](/zh-cn/guides/data/table-explorer/#列数据和唯一值计数)。

- **文件导出保留其类型。** Parquet 文件将整数列保留为整数，以微秒存储时间戳，并将时区标记为 UTC。Avro 文件保留日期、时间戳和布尔值的类型，单表 Avro 导出以该导出命名。为 Parquet 导出选择多个文件时会停止，并提示 Parquet 只写入单个文件。非常大的 Parquet、ORC 和 JSON 导出会边读取行边写入，因此不再耗尽内存，Parquet 使用您选择的压缩方式。版本为 1.2.33 或更高的 PlaidLink 代理会以 Parquet 文件接收导出的表。请参阅 [Export to Parquet 步骤](/zh-cn/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro 步骤](/zh-cn/reference/workflow-steps/export/export-to-avro/)和[数据如何到达代理](/zh-cn/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#数据如何到达代理)。

- **ERP 过账遵循每个计划的模式，不确定的答复会被暂扣以供您检查。** 计划事件保留自己的过账模式——**实时**、**模拟** 或 **关闭**——并受项目设置限制，**运行所选事件** 使用每个事件各自的模式。PlaidCloud 无法确认的 ERP 答复（例如超时或服务器错误）会被作为存疑暂扣，而不是记录为已拒绝，并且过账不能被冲销两次。过账登记簿会列出 **待冲销** 的过账，架构师可在项目主页的 **ERP 写入授权** 中授权项目过账。请参阅 [ERP 过账模式](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)、[冲销](/zh-cn/guides/connections/posting-register/#冲销)和[授权项目过账](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)。

- **行访问跟上分组变化，并说明问题所在。** 用户登录时由单点登录设置的分组成员资格，大约 15 分钟内即可到达仪表板行访问，默认分组的新成员大约一分钟内即可获得其行。当某个限制没有筛选掉任何内容时，行访问窗口会发出警告，可处理包含 `&`、`/` 或 `%` 的列名，并在同步失败时显示带原因的 **错误**，或显示 **正在重试** 以及 **重试** 按钮。请参阅[保持仪表板同步](/zh-cn/administration/access/managing-security-groups-and-assignments/#保持仪表板同步)。

- **用户定义函数在 Python 3.14 上运行，并使用更新的库。** 大多数函数无需更改即可运行。导入 numba 或 Python 已移除的标准库模块（例如 `cgi` 或 `telnetlib`）的函数现在会失败，需要重写。预测的 AutoTheta 边界可能与之前的运行略有不同。请参阅[用户定义转换](/zh-cn/reference/workflow-steps/general/user-defined-transform/)。

- **完整代理访问已弃用，并将于 2027 年 1 月 15 日移除。** 使用 **完整** 访问的 LLM 步骤会记录警告。请改用 **读取和写入**，此时代理通过 PlaidCloud 的写入工具更改数据，LLM 步骤只写入勾选了 **写入** 的绑定。请参阅[代理访问](/zh-cn/integrations/ai-architecture/llm-providers/#代理访问)。

- **文档账户更易于设置和浏览。** OneDrive 或 SharePoint 账户的文件浏览器会打开其起始路径下的文件夹。Google Cloud Storage 账户需要有效的服务账户密钥，没有密钥的现有账户在您添加密钥之前将停止工作。被拒绝的设置会自行说明原因，**管理账户** 中未使用的备份图标已移除。请参阅[添加 Google Cloud Storage 账户](/zh-cn/guides/documents/adding-accounts/add-google-cloud-storage-account/)和[备份文档账户](/zh-cn/guides/documents/account-management/managing-document-account-backups/)。

- **Project 应用对发票、行程和补报工时的处理更完整。** 新发票从主项目开始，由其提供客户和采购订单号。删除草稿发票会使其工时和行程重新变为可计费，**AR 收件人** 设置发票提交时向谁发送电子邮件。行程抽屉显示每行的供应商、类别和审计状态，**添加补报工时** 会为已批准的一周开始一张工时表。请参阅[使用 Project 应用跟踪工时和费用](/zh-cn/guides/time-expense/track-time-and-expenses/)。

- **已移除会删除所有未被任何步骤引用的表的 API 调用。** 请改为按 ID 删除表。

- **应用各处的小改动。** 双击账户、仪表板、成员、分组或设置列表中的某一行即可打开。空的 **维度**、**数据编辑器**、**UDF** 和 **步骤** 选项卡会说明下一步该怎么做，没有应用的成员会进入启动器。步骤的表选择器会显示表上次更新的时间（[查看源表上次更改的时间](/zh-cn/guides/workflows/create-workflow/#查看源表最后一次更改的时间)）。Export External Database Tables 步骤在其自己的选项卡上映射列，**报表：批量生成** 不再显示未使用的 **报表常量** 部分。Convert Encoding 步骤可识别中欧、土耳其和阿拉伯语编码。指向已移除屏幕的链接会注明这一点。

## 已修复

- **AI 助手在您批准之前不会做任何更改，并按原样显示名称。** 以前将步骤构建到新表时，表会在您批准之前就创建了；现在表和步骤会在您批准后一起创建，并且创建项目、工作流或维度、复制表以及更改表属性或标签也会先询问。批准仅对您的下一条回复有效。助手提出的导入或导出会按名称显示其表、文档账户和工作流，并且绝不会与不存在或您无法打开的内容一起提供。带下划线的名称会如实显示，而不会变成斜体；表和代码在深色主题下可读；图表会正常绘制，而不是显示为文本；表达式编辑器的 Weave 面板读取您正在编辑的表达式。助手会列出项目的表，即使某张表没有名称；回答哪些步骤读取或写入某张表时，即使某个步骤读取或写入多张表，也不会因错误而停止。请参阅[构建工作流步骤](/zh-cn/guides/ai-assistant/weave-tab/#构建工作流步骤)。

- **文件导入读取您指定的内容。** 导入 Excel 可读取整列范围和 XLSB 工作簿，能在压缩的工作簿中找到工作表，并且不再因带有填充或换行的标题而失败。导入 CSV 遵循 **跳过行数**，因此标题上方有若干行的文件（例如 SAP 列表导出）可按列名导入，并使用默认的分隔符、引号和转义字符运行。一个源列可以为多个目标列提供数据，列全部为固定值的导入会加载每一行，以大写压缩扩展名命名的文件会被解压，设置为未更改时跳过的导入会重新加载已被清空的表。让 AI 助手从 **项目默认** 导入文件时，会读取项目的默认文档账户，如果项目未设置，则会明确告知。带有较新列类型的 Parquet 文件可在文档中打开。请参阅[导入 Excel](/zh-cn/reference/workflow-steps/import/import-excel/#读取内容)和[导入 CSV](/zh-cn/reference/workflow-steps/import/import-csv/#行选择)。

- **工作流步骤按配置保存和运行。** 表：Upsert 步骤可再次保存，其 **更新键** 列也已恢复。表：项目间复制会指明其目标项目，并通过数据共享读取。文档：将仪表板保存为 PDF 保留其列类型，表：去重合并和表：全部合并按名称匹配列。多表联接可保存多个输入，并接受带空格的列名。Table Lookup 步骤会忽略其查找列上的聚合设置，SCD-2 截至日期联接可将变量用作日期。LLM 步骤可在早于 4.6 的 Claude 模型上运行，并在 AI 助手编辑时保留其模型。REST 请求发送的行值只编码一次，导出到远程数据库会提交其行。请参阅[更新键](/zh-cn/reference/workflow-steps/tables/table-upsert/#更新键)、[数据共享管理](/zh-cn/reference/workflow-steps/tables/frame-project-copy/#数据共享管理)和[多表联接](/zh-cn/reference/workflow-steps/tables/table-multi-table-join/)。选择工作流的步骤（例如删除工作流、复制工作流、重命名工作流和停止工作流）会保留已不存在的工作流，显示为 *id（缺失）*，而不是切换到列表中的第一个工作流。

- **工作流运行按预期完成。** Workflow Loop 步骤在每次迭代时都会运行被循环的工作流，迭代容器和在一次运行中多次运行的工作流也是如此。从某个步骤或并行组内部开始的运行会运行正确的步骤并完成。长时间运行的导入或导出绝不会被启动两次，在 PlaidCloud 更新期间不会停滞，以服务器错误结束的操作不会被再次发送。数据库驱动程序崩溃只会使其自身的步骤失败，并给出数据库的原因。运行历史记录会统计每个步骤的行数，在工作开始之前就失败的步骤会将原因写入工作流日志。请参阅 [Workflow Loop 步骤](/zh-cn/reference/workflow-steps/workflow-control/workflow-loop/)和[运行历史记录](/zh-cn/guides/workflows/advanced-workflows/#运行历史)。

- **项目的复制、导入和打开不再出现意外。** 项目导入会保留其能恢复的所有内容，并在 **导入结果** 窗口中列出遗漏的内容、显示进度、说明失败原因，并可重试。当项目有变量时，复制所选对象也能正常工作。打开项目不再更改其设置，**导入您自己的数据** 会导入您的 CSV，在 PostgreSQL 数据仓库上创建表也能正常工作。App Runner 应用会在 PlaidCloud 更新时自行刷新，并对限制了行的项目上的查看者正常工作。请参阅[归档的部分内容未导入时](/zh-cn/guides/projects/archive-a-project/#归档的部分内容未能导入时)和[保持应用为最新](/zh-cn/guides/workflows/use-converted-alteryx-apps/#保持应用为最新)。

- **维度和分摊的加载与读取正确。** 父子加载会将父级为空的行保留为顶级成员，对于第二个备用层次结构，每种加载都会拒绝主层次结构之外的成员。将成员移到其层次结构不包含的父级之下会被拒绝，维度步骤会指出找不到的维度，粘贴含有空白的列会让每个值保留在其所在行。读取大型维度不再拖慢工作区中的其他所有人。维度属性将 **层次结构** 保留为 **未指定** 的分摊规则可以运行。请参阅[加载到备用层次结构](/zh-cn/reference/workflow-steps/dimensions/dimension-load/#加载到备用层次结构)和[维度类型属性和成员选择器](/zh-cn/guides/dimensions/dimensions/#维度类型属性和成员选取器)。

- **工作流画布和各个屏幕表现正常。** **钻取到工作流** 会在画布上打开高级工作流，画布可打开每个工作流，并在部分布局无法读取时告知您。放不下的工具栏按钮会移入 **更多** 菜单，列表在您保存后立即更新。通知会显示完整消息，警告会在 **日志** 选项卡中显示警告图标，表资源管理器会在某列的概要分析失败时说明，数据编辑器会让空日期单元格保持为空。在启用列筛选器时保存数据编辑器，会保留被筛选器隐藏的行，包括在您添加、删除或移动行之后。用户定义函数编辑器对任何有权更改它的人都以可编辑状态打开。请参阅[画布无法打开工作流时](/zh-cn/guides/workflows/advanced-workflows/#画布无法打开工作流时)。从 **表** 列表中删除表时，会列出仅通过变量路径（例如 `/Periods/{period}/Sales`）访问某张表的所有步骤，只有在您强制时才会删除该表。请参阅[删除](/zh-cn/guides/projects/managing-tables-and-views/#删除)。

- **成员和连接正常工作。** **添加工作区成员** 对已有账户的人（包括通过单点登录创建的账户）有效，并且绝不会降低他们已有的项目角色。ODBC 连接通过 PlaidLink 代理所在机器上的 DSN 或驱动程序连接。拒绝您的 OAuth 凭据的提供商会提示您重新输入或重新授权，Databricks 样本和导出会刷新即将过期的令牌，较旧数据库类型的连接可以删除。**使用位置** 包括通知步骤，免费工作区保留每日、每周和每月备份。请参阅[成员管理](/zh-cn/administration/access/member-management/)和 [ODBC](/zh-cn/reference/connectors/databases/odbc/)。

- **REST API 和 AI 助手工具严格按您的要求执行。** 对成员、分组或计划事件的部分更新只会更改您指定的字段，因此已暂停的事件保持暂停。从指定步骤开始运行就会从该步骤开始，恢复表快照会保留一份安全快照和一条审计记录。AI 工具的驱动因素假设分析只在与您的模型实际所做拆分一致的情况下作答。过去因服务器错误而失败的请求现在要么成功，要么说明哪里有问题。请参阅[追踪分摊](/zh-cn/integrations/ai-coding-agents/tracing-allocations/)和[还原或恢复快照](/zh-cn/guides/data/table-snapshots/#回退或还原快照)。

## 安全

- **AI 助手始终在您的权限范围内。** 助手的数据查询在运行之前会按结构进行检查，并且只运行单条读取查询。只读 AI 连接（包括 Microsoft 365 Copilot）不能导出文件、保存仪表板 PDF、将行复制到另一个项目，或通过 REST 连接发送更改。通过 AI 助手进行的导入以您的身份在您指定的项目中运行，对话只能由发起者继续。助手和表引用会省略您的角色所隐藏的表、步骤、工作流和维度，Weave 会统计您无法打开的失败步骤，而不是指名道姓。请参阅[访问级别](/zh-cn/integrations/microsoft-365-copilot/#访问级别)、[您的角色隐藏的内容](/zh-cn/guides/ai-assistant/weave-tab/#您的角色所隐藏的内容)和[管理过往对话](/zh-cn/guides/ai-assistant/weave-tab/#管理过去的对话)。

- **ERP 过账无法绕过其控制措施。** 开启职责分离后，冲销通过过账登记簿进行，并适用审批。复制或导入的项目不再继承过账权限，SAP 和 EBS 过账不能直接发送到代理，处于仅测试模式的 SAP Post 步骤需要与实际过账相同的权限。一个未公开的、无需这些检查即可向 Sage Intacct 过账的端点已被移除。来自 ERP 和 REST 连接的错误消息不再包含凭据。请参阅[职责分离](/zh-cn/guides/connections/posting-register/#职责分离)。

- **机密为只写，只有所有者决定谁可以使用连接。** 文档账户的密钥、密码和令牌一经保存就不会再次显示，更改账户的连接位置需要再次提供机密。步骤中的密码和密钥只存放在变量中；已输入到步骤中的机密已移入仅架构师可见的项目变量。多行凭据在您输入时会被掩码。只有连接的所有者或工作区管理员才能更改谁有权访问它。请参阅[已保存的机密为只写](/zh-cn/guides/documents/adding-accounts/#已保存的机密为只写)、[密钥存放在变量中](/zh-cn/reference/workflow-steps/document/encrypt-decrypt-file/#密钥存放在变量中)和[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

- **您无法使用的文档账户对您保持关闭。** 检查文件是否存在、读取 Parquet、Avro、ORC 或 Delta 文件的列、使用 **填充** 填充导入步骤的列，以及 AI 助手的文件检查，现在都会拒绝您无权访问的账户，就像浏览该账户已经做到的那样。

- **只有工作区管理员才能更改工作区管理员。** 编辑、停用或删除管理员、更改其分组，以及将某人设为管理员，都需要工作区管理员。请参阅[更改工作区管理员](/zh-cn/administration/access/member-management/#更改工作区管理员)。

- **数据共享只代表获得授权的项目的成员。** 通过共享读取需要在接收项目中拥有角色，写入则需要 **写入** 共享以及在该项目中的管理者或架构师角色。请参阅[在项目之间共享数据](/zh-cn/guides/projects/managing-projects/#在项目之间共享数据)。

- **恢复仅应用于指定的项目。** 恢复较早版本会恢复该项目本身，权限检查针对该项目。内容不属于其自身标头中所列维度的维度备份文件会被拒绝。请参阅[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。

- **模板、导入和归档会拒绝不安全的内容。** 导出模板和报表模板在沙盒中渲染，只读取提供给它们的数据。导入根据其自身设置构建加载查询，包含 PlaidCloud 归档绝不会包含的内容的项目归档会被拒绝，会与另一个项目共用报表架构的项目标识符会被拒绝。请参阅[模板可以使用什么](/zh-cn/reference/workflow-steps/export/export-templated/#模板可以使用的内容)和[恢复归档](/zh-cn/guides/projects/archive-a-project/#还原归档)。

- **仪表板遵循 PlaidCloud 登录和您的行访问权限。** 仪表板的缩略图以您的身份渲染，账户仅来自 PlaidCloud 登录，仪表板仅从“导出”生成的 ZIP 文件导入。请参阅[导入现有仪表板](/zh-cn/guides/dashboards/learning-dashboard/#导入现有仪表板)。

- **启动工作流运行不再返回该运行的凭据。**

- **运行用户定义函数的环境不再包含 PySpark 的 Java 库，** 这些库带有已知漏洞。PySpark 的 DataFrame 和 SQL API 仍可访问您的 Spark 计算集群，但导入 `SparkContext` 或 `RDD` 的函数现在会失败。请参阅 [PySpark 入门](/zh-cn/integrations/pyspark/getting-started/)。

- **附件、恢复和转换只读取您可以使用的账户。** 以电子邮件发送文件、从文件恢复维度或表归档、检查或导入表包、使用模板填充 Excel 导出，以及转换 Alteryx 工作流，现在都会拒绝您无权访问的文档账户。将维度备份到文档账户需要对其有写入权限。工作流步骤不受影响，只是发送文件、恢复表或填充 Excel 模板的步骤不再能从个人临时驱动器读取。
