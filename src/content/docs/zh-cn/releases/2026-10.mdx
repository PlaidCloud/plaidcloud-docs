## 新增

- **Data Foundation 将您的 ERP 数据整合到一个 Common Finance Model 中。** Common Finance Model 将来自多个 ERP 系统和实例的 ERP 数据整合为单一模型：一套会计科目表、一组实体和一种报告货币。基于它构建的报表、指标和 AI 助手读取的都是同一组数字，无论数据来自哪个 ERP。

  - **直接来自您的 ERP。** 总账、试算平衡表、主数据和预算通过 PlaidCloud 的 ERP 直连获取。**实体对照表** 将各数据源的公司代码映射到同一组实体上，文件则用于补充系统中没有的内容，例如汇率或分摊动因。
  - **一个模型，一种货币。** **加载** 会将每个数据源统一到 Common Finance Model 中，并换算为您的报告货币：损益表按期间平均汇率，资产负债表按期末汇率，权益按历史汇率。层次结构由您的主数据构建。
  - **检查就绪状态。** 针对每个实体和期间运行检查：试算平衡表和销售额与总账核对一致，每个产品、客户和科目都是已知的，货币可以换算，每个实体都已映射。
  - **多个源，一个模型。** 添加、排序、编辑和移除源，每个源可以是一个 ERP 系统、实例或文件。**加载** 会整合所有源，在重叠处保留一份副本，并记录被暂扣的行及原因；**应用更改** 无需再次从 ERP 拉取即可重新运行整合。
  - **跨源映射代码。** 当多个源共用一个代码时，系统会按名称匹配给出建议，询问它们是否含义相同；可以回答单个代码，也可以用 **全部接受**、**全部相同** 或 **全部不同** 回答整个分组。映射按源和维度保存。最多十个额外类别使用您指定的名称，覆盖范围视图则可让您选择从哪个月起由哪个源计数。
  - **文件选项。** 文件可以只适用于一个源、询问其需要回答的问题、将一列拆分为多个字段、设置报告货币，或被移除。
  - **管理合并。** 每次加载都会构建集团损益表（包括年初至今），公司间交易在 **抵销** 实体上抵销，另有 **未映射** 项，并可与合并系统的结果对账。这是一种管理视图，遵循项目的行访问权限，并且不是法定合并。
  - **保持最新。** **每晚刷新** 每晚重新加载模型，文件缺失或为空时，以警告而不是错误结束。

  基于模板（例如 **Enterprise Profitability**）启动项目后，项目的 **基础数据** 选项卡会带您从已连接的 ERP 一路走到已加载并检查过的模型。请参阅 [Data Foundation：Common Finance Model](/zh-cn/guides/projects/data-foundation/)。

- **在您自己的 Snowflake 或 Databricks 数据仓库上运行 PlaidCloud。** 工作区管理员在用户菜单中打开 **使用您自己的数据仓库**，在自己的账户中运行生成的设置脚本。该脚本会为 PlaidCloud 创建一个有用量上限的数据仓库和一个服务身份，绝不会触及您现有的数据仓库。**检查连接** 会用通俗的话解释任何问题及其解决办法。此后新项目会在您的数据仓库中存储表并运行工作流，移除该数据仓库即可撤销 PlaidCloud 在其中的访问权限。请参阅[使用您自己的数据仓库](/zh-cn/guides/connections/external-lakehouse/)。

  - **使用 Snowflake 或 Databricks 登录。** 管理员可以通过登录来关联数据仓库，而不必粘贴凭据。仪表板随后以每个人自己的数据仓库权限运行，工作流则以仅持有您指定数据角色的服务身份运行。请参阅[使用 Snowflake 或 Databricks 登录](/zh-cn/guides/connections/external-lakehouse/#使用-snowflake-或-databricks-登录)。
  - **可连接多个。** 在 **管理数据仓库** 中使用 **设为默认**，可让新项目使用另一个数据仓库，现有项目则保持不变。请参阅[管理数据仓库](/zh-cn/guides/connections/external-lakehouse/#管理数据仓库)。
  - **查看一次运行的成本。** 运行历史记录为每次运行显示 **仓库成本** 列，以积分或 DBU 计。请参阅[每次运行的数据仓库成本](/zh-cn/guides/connections/external-lakehouse/#每次运行的仓库成本)。
  - **您的治理策略保持有效。** 说明会写入数据仓库自身的目录，PlaidCloud 替换、重建或克隆表时，Snowflake 的行访问策略和掩码策略，以及 Databricks 的行筛选器和列掩码都会保持关联。请参阅[您的策略和说明会随之保留](/zh-cn/guides/connections/external-lakehouse/#您的策略和说明会延续)。

- **在 PlaidCloud 内构建、发布和定制 Panel 应用的品牌。**

  - **Panel Studio。** **新建 Studio 应用** 是 **我的 Panel 应用** 中的第一个按钮，可从空白应用、表、视图、另一个 Studio 应用或应用库开始；**表** 选项卡上的 **创建 Panel 应用** 则从您选中的表开始。**在 Studio 中打开** 会在编辑器中打开应用的文件。可以保存草稿、**预览** 私有构建，以及 **发布** 线上应用。构建错误会指向对应的文件和行，**历史记录** 可还原任何已发布的版本，**洞察** 显示浏览量、加载时间和错误。**询问 Weave** 了解应用的文件和构建状态，并在保存任何代码之前向您展示完整的差异供您批准。请参阅 [Panel Studio](/zh-cn/guides/panel-apps/studio/) 和[使用 Weave 构建 Panel 应用](/zh-cn/guides/panel-apps/build-with-weave/)。
  - **看起来像 PlaidCloud 的应用套件。** 使用该套件构建的应用在浅色和深色下都采用 PlaidCloud 的颜色、字体和间距。套件包括导航、筛选器、关键数字卡片、图表、表单、命令面板、运行工作流的按钮、打印，以及一个在服务器端排序和汇总、按列设置数字格式、每次只加载一屏行的数据网格，因此可以处理任意大小的表。应用以已登录查看者的身份读取表，并应用行级安全。请参阅 [Panel 应用套件](/zh-cn/guides/panel-apps/app-kit/)、[DataGrid](/zh-cn/guides/panel-apps/app-kit/#datagrid) 和 [Panel 应用的数据 API](/zh-cn/guides/panel-apps/data-api/)。
  - **提醒与摘要。** 当项目表中的某个数字越过限值时，通过推送通知、电子邮件、Slack 或 Microsoft Teams 收到通知，或收到最多包含 10 个数字的每日或每周摘要，始终遵循您自己的行访问权限。请参阅[提醒与摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
  - **项目、品牌和共享。** 将应用分配到项目，之前会先审查哪些人可以打开该应用却不在项目中。项目 **主页** 选项卡上的 **编辑品牌设置** 可为项目中的每个应用设置八种品牌颜色和一个徽标。**应用库…** 会将属于某个项目的 Studio 应用列为模板，供所有能查看其项目的人使用，**从应用库中移除** 则将其移除。请参阅[项目品牌和应用项目](/zh-cn/guides/panel-apps/branding/)和[应用库](/zh-cn/guides/panel-apps/gallery/)。

- **一次约定业务数字的计算方式，之后每个 AI 回答都采用该计算。** 项目架构师定义一个 **指标**，例如 *净收入* 或 *员工人数*：其源表、各行如何汇总、始终计入的行、联接的查找表，以及可以按哪些列细分。定义一经保存即生效，如果保存时指定了不存在的表或列，或者查找表的每个键对应多行，则保存会被拒绝。按名称或同义词向 AI 助手询问该指标，得到的数字由该定义计算，遵循您自己的行访问权限，而不是由助手自行推算。定义通过 AI 助手或 REST API 管理。请参阅[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。

  - **派生指标。** 定义两个指标的比率、和或差，例如每名全职员工的净收入，或某个指标乘以固定系数。请参阅[从其他指标派生指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#由其他指标派生指标)。
  - **比较、排名和占比。** 可以询问相对预算的差异、保留并列项的前 N 名或后 N 名，或每行占总额的比例。请参阅[比较、排名和占比](/zh-cn/integrations/ai-coding-agents/metric-definitions/#比较排名和占比)。
  - **您的用词，约定的值。** 将细分列绑定到维度后，像 *EMEA* 这样的词会变成其下的所有区域。无法匹配任何成员，或匹配多个成员的词，会作为候选项返回并向您确认，绝不猜测。请参阅[询问指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#询问指标)。
  - **财年时间。** 告知指标其各行在您的财年日历中的位置，即可询问某个财年期间、年初至今、同比或环比。请参阅[随时间比较](/zh-cn/integrations/ai-coding-agents/metric-definitions/#随时间比较)。

  PlaidCloud 自己的 AI 助手会先从指标中得出业务数字，并将数字显示在带 ✓ 标记的独立卡片中，该标记绝不会附在助手自己的文字上。请参阅[业务数字](/zh-cn/guides/ai-assistant/weave-tab/#业务数字)和[来自指标的数字](/zh-cn/guides/ai-assistant/weave-tab/#来自指标的数字)。

- **向 Weave 询问是否已准备好结账，并核对两个表是否对平。** 两者都不涉及 AI。

  - **结账就绪状态。** 在项目 **Weave** 选项卡的 **就绪状态** 中，将结账、预测或任何截止日期所依赖的工作流命名为一个 **就绪集**。一张清单即可回答所有这些工作流的情况：“13 个中 11 个就绪；1 个未就绪；1 个无法检查。”只有 Weave 能对工作流运行的所有检查都通过时，该工作流才算就绪；Weave 无法判断的任何内容都会显示为 **无法检查** 并附上原因，绝不会显示为就绪。最近一次运行的历史数据太少、无法与之比较的情况（例如新工作流）按正常处理。不写入表的步骤（例如发送电子邮件或导出文件的步骤）没有可检查的行或空值，因此不会让工作流停留在 **无法检查**。请参阅[结账前检查就绪状态](/zh-cn/guides/ai-assistant/weave-readiness/)。
  - **对账。** 按您配对的关键列，逐行比较两个表，或同一个表的两个期间。Weave 会说明它们是否对平、相差多少以及哪些行不同，对于未能完整读取的数据，绝不会说“对平”。每项对账在使用前需要第二位架构师批准。请参阅[核对两个表是否对平](/zh-cn/guides/ai-assistant/weave-reconciliation/)。

- **Weave 关注更多可能出错的地方，并在两次运行之间通知您。** Weave 的检查不使用 AI。每个发现项以及 AI 助手的每个回答，都有一个 **Weave 如何得知** 面板：对于发现项，显示检查及其背后的值；对于回答，显示助手运行的每个查询，并将每句话标记为 **已匹配**、**未匹配** 或 **未检查**。请参阅 [Weave 目前检查的内容](/zh-cn/guides/ai-assistant/weave-findings/#weave-目前检查的内容)、[Weave 如何得知](/zh-cn/guides/ai-assistant/weave-findings/#weave-如何得知)和 [AI 助手中的 Weave 如何得知](/zh-cn/guides/ai-assistant/weave-tab/#weave-如何得知)。

  - **表按时写入。** Weave 会报告自计划到期以来一直没有被写入的表，或超过您在表详情中 **时效性** 下设置的时效阈值（1 小时到 180 天）的表。
  - **过时或损坏的输入。** Weave 会报告读取了另一个工作流此后写入的表的工作流，以及所有依赖失败运行的工作流和仪表板，包括图表基于 SQL 数据集的仪表板。**同步依赖项** 会补上步骤与其所读取的表之间缺失的连接器。请参阅[同步依赖项](/zh-cn/guides/workflows/sync-dependencies/)。
  - **数据形态发生变化。** Weave 会报告运行后取值分布大幅变化的小数列、开始重复写入行的联接、提取步骤因无法转换为列类型而留空的值，以及未找到任何文件的导入。它还会报告最新期间与常态相差很大的指标，并指出推动这一变化的项目。Weave 会考虑月末和工作日规律，因此月末总是很重的加载不会被报告。请参阅[异常的指标合计](/zh-cn/guides/ai-assistant/weave-metric-insights/)。
  - **变慢的运行。** Weave 会指出让一次运行变慢的步骤，并报告较新运行比较旧运行至少多花四分之一时间的工作流，同时指出耗时增长最多的步骤。
  - **两次运行之间的通知。** 每小时一次的检查会在应用内消息中向每个问题的负责人通知一次，页眉中的 **Weave** 按钮会统计您所有项目中尚未阅读的问题数量。请参阅[在两次运行之间收到通知](/zh-cn/guides/ai-assistant/weave-findings/#两次运行之间收到通知)和[页眉中的 Weave 按钮](/zh-cn/guides/ai-assistant/weave-tab/#标题栏中的-weave-按钮)。
  - **负责人、评论和预期内的警告。** 每个发现项都有一位负责人，默认是最后运行其工作流的人。**分配** 可将其转交他人，评论用于记录进展，**团队** 视图显示谁负责什么。架构师可以将警告标记为 **此为预期**，并填写原因和结束日期。请参阅[为发现项指定负责人](/zh-cn/guides/ai-assistant/weave-tab/#为发现项指定所有者)和[将发现项标记为预期内](/zh-cn/guides/ai-assistant/weave-tab/#将发现项标记为预期)。

- **修复助手会解释错误，在卡片上提出由您批准的更改，重新运行步骤，还能撤消修复。** 对于最常见的故障，例如表中没有的列、空的必填设置、数据库无法读取的 SQL 或类型错误的值，第一条回复会解释常见原因及修复方法。提出的更改以卡片形式出现，说明步骤失败的原因，并逐项显示更改的设置，当前值为红色，新值为绿色。**批准** 会应用更改，之后助手会提出重新运行该步骤，并诊断新出现的失败。**Weave** 选项卡中发现项上的 **修复** 会针对该问题打开助手。**撤消** 会恢复步骤的先前设置，**撤消并运行** 则重新生成其输出。请参阅[使用 AI 修复工作流错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/)、[使用 AI 助手修复发现项](/zh-cn/guides/ai-assistant/weave-tab/#使用-ai-助手修复发现项)和[撤消修复](/zh-cn/guides/ai-assistant/fixing-workflow-errors/#撤消修复)。

- **查看 Weave 在项目中所做的一切，并导出给审计人员。** 项目 **Weave** 选项卡上的 **活动** 会列出 Weave 发现后来又不再发现的问题、AI 助手提出的每项更改、谁提出请求、谁批准或拒绝、它具体替换并写入了什么，以及最终结果。Weave 会在做出更改之前记录您的批准，并且不会做出无法记录的更改。**导出 CSV** 或 **导出 PDF** 可将某个时间段保存为审计证据，条目不能被编辑或删除。**摘要** 以月度概览显示：发现和解决的问题、批准的更改以及其中撤消的数量。工作区管理员可通过 **工作区摘要…** 查看所有项目的同样信息。请参阅 [Weave 活动历史记录](/zh-cn/guides/ai-assistant/weave-activity/)和 [Weave 月度摘要](/zh-cn/guides/ai-assistant/weave-monthly-summary/)。

- **保存之前，了解步骤的作用以及更改它会影响什么。** 以下内容均根据项目已保存的设置生成，不涉及 AI，且您的角色所隐藏的任何内容只会计数，绝不点名。

  - **每个步骤和工作流的文档，以及每个表的列。** 详情面板中的 **文档** 部分描述步骤的作用和工作流中按顺序排列的步骤，Weave 和 AI 助手还可以获取读取和写入某个表的内容。表的详情面板列出其 **列** 及其类型和说明。**下载交接包** 会将整个项目保存为一份文档，其中包含指标定义和分摊模型。请参阅[表、步骤和工作流的文档](/zh-cn/guides/ai-assistant/weave-documentation/)。
  - **更改会影响什么。** 在 **保存** 上方，Weave 会说明下游有多少个步骤读取该步骤所写入的内容，例如“对此步骤的更改会影响 2 个工作流中的 8 个下游步骤”，**显示步骤** 会列出它们。请参阅[更改会影响什么](/zh-cn/guides/ai-assistant/impact-preview/)。
  - **保存会拒绝什么。** **保存** 上方的提示条会在您编辑时运行步骤的检查，每个问题都带有 **转到**，表达式编辑器则在您输入时检查表达式。请参阅[保存会拒绝什么](/zh-cn/guides/ai-assistant/check-while-you-edit/)。
  - **审查单个工作流。** 工作流画布或 **步骤** 网格上的 **检查** 会对其运行 Weave 的检查，外加分摊和行级安全检查。请参阅[审查单个工作流](/zh-cn/guides/ai-assistant/weave-findings/#审核单个工作流)。

- **为您的工作区关闭 Weave 的任何 AI 功能。** 工作区管理员在页眉 **Weave** 按钮上选择 **AI 功能…**，即可分别开启或关闭 Weave 聊天、修复助手、导入和导出助手、表达式助手、根据描述生成 SQL、工作流审核摘要或初始图表。在管理员关闭之前，所有功能都处于开启状态；Weave 的检查和发现项始终保持开启，每次更改都会记录在安全日志中。请参阅 [AI 功能](/zh-cn/guides/ai-assistant/weave-ai-features/)。

- **在运行之前把联接的键设置正确。** **Join Map** 上的**推测**会依次使用联接相同两张表的另一个步骤的键、指标、表的键列、匹配的名称，并说明使用了哪一种。**检查键**会统计被联接表中重复的键值，这些值可能使您的行数成倍增加。当**检查源**填充步骤的列时，像 `customer_id` 这样的标识符列会从**分组依据**而不是**求和**开始。请参阅[内联接](/zh-cn/reference/workflow-steps/tables/table-inner-join/#检查键)。

- **AI 助手和 Microsoft 365 Copilot 更了解您的数据，也能用它做更多事。**

  - **每个分析路径和列的指引。** 每个分析路径都有 **提示指引**，最多 1,000 个字符，用于说明始终适用的筛选器、财年日历和您的业务术语。列备注会随表的列一起提供给助手和 LLM 步骤，因此代码或标志会按您的本意解读。请参阅[让路径对 AI 助手有用](/zh-cn/integrations/ai-coding-agents/analysis-paths/#让路径对-ai-助手更有用)。
  - **Copilot 能做得更多。** Microsoft 365 Copilot 中的 PlaidCloud 代理可以创建 CSV、Excel、PowerPoint 和 Word 文件，根据您的指标回答业务数字，对整个表汇总细分，并解释分摊的工作原理。管理员下载更新后的包，并在 Teams 管理中心中更新。请参阅 [Microsoft 365 Copilot](/zh-cn/integrations/microsoft-365-copilot/)。
  - **一次调用完成更多事。** 助手可以在服务器端对表分组和汇总（先应用行访问权限）、搜索和读取 PlaidCloud 的文档、使用只写凭据创建完整配置的文档账户（包括 OneDrive 和 SharePoint）、移除以及添加标签，并使用您在 PlaidCloud 中看到的视图。请参阅[分析路径](/zh-cn/integrations/ai-coding-agents/analysis-paths/#通过-mcp-使用)和 [AI 代理入门](/zh-cn/integrations/ai-coding-agents/getting-started/)。

## 变更

- **一个 Weave 选项卡同时容纳您的发现项和 Weave AI 聊天。** 聊天是 **Weave** 选项卡内的选项卡，位于 **发现项** 之后。每个发现项是一张卡片，带有各自的 **修复**、**转到** 和 **标记为已读** 按钮，虚线卡片表示 Weave 无法检查的内容，筛选标签按需要关注的程度筛选列表。关于表达式的发现项会指出错误所在位置，表达式本身位于 **Weave 如何得知** 之下。运行结束时，Weave 对每个问题只提及一次，关于同一项目的消息会合并为一条，而不是不断堆叠。由于 Weave 只重新检查已更改的内容，该选项卡在大型项目中也能快速打开。工作流列表中的 Weave 列已移除。请参阅 [Weave 选项卡](/zh-cn/guides/ai-assistant/weave-tab/)和[运行结束时收到通知](/zh-cn/guides/ai-assistant/weave-findings/#运行结束时收到通知)。

- **在任何屏幕上按 Ctrl/Cmd-K 即可打开命令面板。** 在您输入之前，它会列出您最近打开的内容和可以执行的操作：前往主页、项目、仪表板或文档，在浅色和深色之间切换，连接您的 AI，或获取帮助。输入内容会缩小两个列表的范围，输入两个字符后还会搜索项目、工作流、表、仪表板和 Panel 应用。请参阅[搜索和命令](/zh-cn/guides/launcher/#搜索和命令)。

- **步骤在保存时而非运行时发现问题。** 保存其设置会导致运行失败或给出错误结果的步骤时，系统会拒绝并给出需要更改什么的消息。每个步骤的参考页面都列出了它检查的内容。步骤或其源表中已不存在的已映射源列会以红色标出，保存时会打开一个对话框，提供 **全部移除并保存**、**仍然保存** 或 **取消**。联接、查找和空间步骤会原地保留此类行，而不是自行删除。使用未定义变量的表达式会指出该变量，运行时被拒绝的步骤会用通俗的话解释原因。请参阅[不再列出的源列](/zh-cn/reference/workflow-steps/tables/table-extract/#不再列出的源列)、[源表中缺失的列](/zh-cn/reference/workflow-steps/tables/table-extract/#源表中缺少的列)和[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。

- **缺失或为空的源绝不是错误。** 文件缺失或为空的文件导入会以警告结束并指出路径，目标表保持为空并保留其声明的列，因此后续步骤读取的是零行。针对缺失或为空文件夹的文档步骤会报告“Nothing to process”，工作流继续运行。远程文件步骤在路径缺失时发出警告，并拒绝不安全的路径。对缺失文件的检查适用于 OneDrive、SharePoint 和 SFTP。批处理表为空的 **报表：批量生成** 会以警告结束，并且不生成任何报表。请参阅[导入步骤](/zh-cn/reference/workflow-steps/import/)、[文档工作流步骤](/zh-cn/reference/workflow-steps/document/)和[文档路径条件](/zh-cn/guides/workflows/step-conditions/#文档路径条件)。

- **大型工作流可靠运行，停止可取消导入和导出。** 当 PlaidCloud 繁忙时，步骤会等待容量而不是失败，并且随着步骤排队会增加容量。导入外部数据库表最多同时运行 10 个表。如果运行步骤的服务器丢失，替换其输出的步骤会自动重新运行，无法安全重复的步骤则以 *interrupted* 消息失败一次。**停止** 会取消正在运行的导入和导出作业，已停止的运行会报告 Stopped。请参阅[中断的步骤](/zh-cn/guides/workflows/run-a-workflow/#已中断的步骤)和[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)。

- **每个 Lakehouse 的存储和计算方式相同。** 导入 CSV、导入 XML 或 Import Table Archive 中的空字段会加载为 null，因此之后测试 `= ''` 或 `= 0` 的步骤需要改为测试 null。`cast(x, Float)` 在所有位置都是 64 位，因此大额数值保留所有数字位，PlaidCloud 创建的 Float 列也是双精度。JSON 列、**Table: Delete Rows** 和带聚合的条件在每个 Lakehouse 上都可使用。自行构建结果的步骤，例如求解器、预测，以及在 pandas 中运行的 Pivot 和 Allocation Split，会将结果作为有类型的数据加载，速度快得多。表资源管理器会显示数值列的最小值、最大值、平均值、总和、标准差和方差。请参阅[转换为 Float](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#转换为-float)和[列数据和唯一计数](/zh-cn/guides/data/table-explorer/#列数据和唯一值计数)。

- **文件导出保留其类型。** Parquet 文件将整数列保留为整数，以微秒存储时间戳，并将时区标记为 UTC。Avro 文件保留日期、时间戳和布尔值的类型，单表 Avro 导出以该导出命名。为 Parquet 导出选择多个文件时会停止并提示 Parquet 只写入单个文件。非常大的 Parquet、ORC 和 JSON 导出会在读取行的同时写出，因此不再耗尽内存，Parquet 也会使用您选择的压缩方式。版本 1.2.33 或更高的 PlaidLink 代理会以 Parquet 文件形式接收导出的表。请参阅 [Export to Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro](/zh-cn/reference/workflow-steps/export/export-to-avro/) 和[数据如何到达代理](/zh-cn/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#数据如何到达代理)。

- **ERP 过账遵循每个计划的模式，不确定的答复会被暂存等您检查。** 计划事件保留其自己的过账模式，**实时**、**模拟** 或 **关闭**，并受项目设置限制，**运行所选事件** 使用每个事件各自的模式。PlaidCloud 无法确认的 ERP 答复（例如超时或服务器错误）会被保留为存疑，而不是记录为已拒绝，并且一笔过账不能被冲销两次。过账登记簿会列出 **reversal outstanding** 的过账，架构师可在项目主页的 **ERP 写入授权** 中授权项目过账。请参阅 [ERP 过账模式](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)、[冲销](/zh-cn/guides/connections/posting-register/#冲销)和[授权项目过账](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)。

- **行访问跟得上分组变化，并说明问题所在。** 用户登录时由单点登录设置的分组成员资格，会在约 15 分钟内同步到仪表板行访问，默认分组的新成员约在一分钟内获得其行。行访问窗口会在限制条件没有筛掉任何内容时发出警告，能够处理包含 `&`、`/` 或 `%` 的列名，并在同步失败时显示带原因的**错误**，或显示**正在重试**以及**重试**按钮。请参阅[保持仪表板同步](/zh-cn/administration/access/managing-security-groups-and-assignments/#保持仪表板同步)。

- **用户定义函数在 Python 3.14 和更新的库上运行。** 大多数函数无需更改即可运行。导入 numba 或 Python 已移除的标准库模块（例如 `cgi` 或 `telnetlib`）的函数现在会失败，需要重写。预测的 AutoTheta 边界可能与之前的运行略有差异。请参阅 [User Defined Transform](/zh-cn/reference/workflow-steps/general/user-defined-transform/)。

- **完整代理访问已弃用，并将于 2027 年 1 月 15 日移除。** 使用 **完整** 访问的 LLM 步骤会记录一条警告。请改用 **读取和写入**，此时代理通过 PlaidCloud 的写入工具更改数据，LLM 步骤只写入勾选了 **写入** 的绑定。请参阅[代理访问](/zh-cn/integrations/ai-architecture/llm-providers/#代理访问)。

- **Project 应用更完整地处理发票、行程和补报工时。** 新发票从主项目开始，由主项目提供客户和采购订单号。删除发票草稿会使其工时和行程重新变为可计费，**AR 收件人** 设置发票提交时向谁发送电子邮件。行程抽屉显示每一行的供应商、类别和审计状态，**添加补报工时** 会为已批准的一周开始一张工时表。请参阅[使用 Project 应用跟踪时间和费用](/zh-cn/guides/time-expense/track-time-and-expenses/)。

- **删除所有未被任何步骤引用的表的 API 调用已移除。** 请改为按 ID 删除表。

- **应用中的其他小变化。** 双击账户、仪表板、成员、分组或设置列表中的一行即可将其打开。空的 **维度**、**数据编辑器**、**UDF** 和 **步骤** 选项卡会说明下一步该做什么，没有应用的成员会进入启动器。步骤的表选择器会显示表上次更新的时间（[查看源表上次更改的时间](/zh-cn/guides/workflows/create-workflow/#查看源表最后一次更改的时间)）。Export External Database Tables 在其自己的选项卡上映射列，**报表：批量生成** 不再显示未使用的 **Report Constants** 部分。Convert Encoding 可识别中欧、土耳其和阿拉伯语编码。指向已移除屏幕的链接会说明这一点。

## 已修复

- **AI 助手在您批准之前不会更改任何内容，并按原样显示名称。** 以前，将步骤构建到新表中时，表在您批准之前就已创建；现在表和步骤会在您批准后一起创建，创建项目、工作流或维度、复制表，以及更改表属性或标签也会先询问。批准只在您的下一条回复中有效。助手提出的导入或导出会按名称显示其表、文档账户和工作流，并且绝不会与不存在或您无法打开的对象一起提供。带下划线的名称会原样显示，而不会变成斜体，表和代码在深色主题中清晰可读，图表会绘制出来而不是显示为文本，表达式编辑器的 Weave 面板会读取您正在编辑的表达式。助手会列出项目的表，即使其中有一个没有名称，也会回答哪些步骤读取或写入某个表，即使一个步骤读取或写入多个表，而不是以错误停止。请参阅[构建工作流步骤](/zh-cn/guides/ai-assistant/weave-tab/#构建工作流步骤)。

- **文件导入读取您指向的内容。** 导入 Excel 可读取整列范围和 XLSB 工作簿，能在压缩的工作簿中找到工作表，也不再因带填充或换行的标题而失败。导入 CSV 遵循 **跳过行数**，因此标题上方有若干行的文件（例如 SAP 列表导出）可按列名导入，并使用默认的分隔符、引号和转义字符运行。一个源列可以供给多个目标列，所有列都是固定值的导入会加载每一行，使用大写压缩扩展名命名的文件会被解压，数据未变化时跳过的导入会重新加载已被清空的表。要求 AI 助手从 **项目默认值** 导入文件时，会读取项目的默认文档账户，并在项目未设置时明确告知您。具有较新列类型的 Parquet 文件可在文档中打开。请参阅[导入 Excel](/zh-cn/reference/workflow-steps/import/import-excel/#读取内容)和[导入 CSV](/zh-cn/reference/workflow-steps/import/import-csv/#行选择)。

- **工作流步骤按配置保存和运行。** 表：Upsert 步骤可以再次保存，其 **更新键** 列也已恢复。表：项目间复制会指明其目标项目，并通过数据共享读取。文档：将仪表板保存为 PDF 会保留其列类型，表：去重合并和表：全部合并按名称匹配列。多表联接可保存多个输入，并接受带空格的列名。Table Lookup 会忽略其查找列上的聚合设置，截至日期联接可接受变量作为其日期。LLM 步骤可在早于 4.6 的 Claude 模型上运行，并在 AI 助手编辑它们时保留其模型。REST 请求发送的行值只编码一次，导出到远程数据库会提交其行。请参阅[更新键](/zh-cn/reference/workflow-steps/tables/table-upsert/#更新键)、[数据共享管理](/zh-cn/reference/workflow-steps/tables/frame-project-copy/#数据共享管理)和[多表联接](/zh-cn/reference/workflow-steps/tables/table-multi-table-join/)。选择工作流的步骤（例如删除工作流、复制工作流、重命名工作流和停止工作流）会保留已不存在的工作流，显示为 *id (missing)*，而不是切换到列表中的第一个工作流。

- **工作流运行按应有方式完成。** Workflow Loop 会在每次迭代时运行循环的工作流，迭代容器以及在一次运行中被多次运行的工作流也是如此。从某个步骤或并行组内部开始的运行，会运行正确的步骤并完成。长时间运行的导入或导出绝不会被启动两次，在 PlaidCloud 更新期间也不会停滞，以服务器错误结束的操作不会被重新发送。数据库驱动程序崩溃只会使其自己的步骤失败，并给出数据库给出的原因。运行历史记录会统计每个步骤的行数，在工作开始之前就失败的步骤会将原因写入工作流日志。请参阅 [Workflow Loop](/zh-cn/reference/workflow-steps/workflow-control/workflow-loop/) 和[运行历史记录](/zh-cn/guides/workflows/advanced-workflows/#运行历史)。

- **项目的复制、导入和打开不再出现意外。** 项目导入会保留其能够还原的所有内容，并在 **导入结果** 窗口中列出遗漏的内容，显示进度，说明失败原因，并且可以重试。当项目有变量时，复制所选对象也能正常工作。打开项目不再更改其设置，**导入您自己的数据** 会导入您的 CSV，在 PostgreSQL 数据仓库上创建表也能正常工作。App Runner 应用会在 PlaidCloud 更新时自动刷新，并且对限制行的项目的查看者也能正常使用。请参阅[归档的一部分未导入时](/zh-cn/guides/projects/archive-a-project/#归档的部分内容未能导入时)和[保持应用为最新](/zh-cn/guides/workflows/use-converted-alteryx-apps/#保持应用为最新)。

- **维度和分摊的加载与读取正确无误。** 父子加载会将父级为空的行保留为顶层成员，对于第二个备用层次结构，主层次结构之外的成员在每种加载方式中都会被拒绝。将成员移到其层次结构中不存在的父级之下会被拒绝，维度步骤会指出它找不到的维度，粘贴带空白的列会让每个值保持在原行。读取大型维度不再拖累工作区中的其他所有人。其维度属性将 **层次结构** 保留为 **未指定** 的分摊规则可以运行。请参阅[加载到备用层次结构](/zh-cn/reference/workflow-steps/dimensions/dimension-load/#加载到备用层次结构)和[维度类型属性和成员选取器](/zh-cn/guides/dimensions/dimensions/#维度类型属性和成员选取器)。

- **工作流画布和各屏幕行为正常。** **钻取到工作流** 会在画布上打开高级工作流，画布可打开每个工作流，并在部分布局无法读取时告知您。放不下的工具栏按钮会移到 **更多** 菜单中，列表在您保存后立即更新。通知显示完整消息，警告在 **日志** 选项卡中显示警告图标，表资源管理器会在某列的概要分析失败时说明，数据编辑器会让空的日期单元格保持为空。在启用列筛选的情况下保存数据编辑器，会保留被筛选隐藏的行，包括在您添加、删除或移动行之后。任何有权更改用户定义函数的人，其编辑器都以可编辑状态打开。请参阅[画布无法打开工作流时](/zh-cn/guides/workflows/advanced-workflows/#画布无法打开工作流时)。从 **表** 列表中删除表时，会列出仅通过变量路径（例如 `/Periods/{period}/Sales`）访问某个表的任何步骤，并且仅在您强制时才删除该表。请参阅[删除](/zh-cn/guides/projects/managing-tables-and-views/#删除)。

- **成员和连接按预期工作。** **添加工作区成员** 适用于已有账户的人（包括由单点登录创建的账户），并且绝不会降低其已有的项目角色。ODBC 连接通过 PlaidLink 代理所在计算机上的 DSN 或驱动程序连接。拒绝您的 OAuth 凭据的提供方会提示您重新输入或重新授权，Databricks 样本和导出会刷新即将过期的令牌，旧数据库类型的连接可以删除。**使用位置** 包含通知步骤，免费工作区保留每日、每周和每月备份。请参阅[成员管理](/zh-cn/administration/access/member-management/)和 [ODBC](/zh-cn/reference/connectors/databases/odbc/)。

- **REST API 和 AI 助手工具严格按您的要求执行。** 对成员、分组或计划事件的部分更新只会更改您指定的字段，因此暂停的事件会保持暂停。在指定步骤开始运行时，确实从该步骤开始，还原表快照会保留一份安全快照和一条审计记录。AI 工具的动因假设分析只在与您的模型实际所做的拆分一致时才作答。以前因服务器错误而失败的请求，现在要么成功，要么说明哪里出了问题。请参阅[追踪分摊](/zh-cn/integrations/ai-coding-agents/tracing-allocations/)和[回退或还原快照](/zh-cn/guides/data/table-snapshots/#回退或还原快照)。

## 安全

- **AI 助手始终在您的权限范围内。** 助手的数据查询在运行前会按其结构进行检查，并且只运行单个读取查询。只读 AI 连接（包括 Microsoft 365 Copilot）无法导出文件、保存仪表板 PDF、将行复制到另一个项目，或通过 REST 连接发送更改。通过 AI 助手进行的导入以您的身份在您指定的项目中运行，对话只能由发起者继续。助手和表引用会省略您的角色所隐藏的表、步骤、工作流和维度，Weave 会统计您无法打开的失败步骤，而不是点名。请参阅[访问级别](/zh-cn/integrations/microsoft-365-copilot/#访问级别)、[您的角色隐藏的内容](/zh-cn/guides/ai-assistant/weave-tab/#您的角色所隐藏的内容)和[管理过往对话](/zh-cn/guides/ai-assistant/weave-tab/#管理过去的对话)。

- **ERP 过账无法绕过其控制。** 启用职责分离后，冲销通过过账登记簿进行，并适用审批。复制或导入的项目不再继承过账权限，SAP 和 EBS 过账不能直接发送给代理，处于仅测试模式的 SAP 过账步骤需要与实时过账相同的权限。一个无需这些检查即可向 Sage Intacct 过账的未公开端点已被移除。来自 ERP 和 REST 连接的错误消息不再包含凭据。请参阅[职责分离](/zh-cn/guides/connections/posting-register/#职责分离)。

- **密钥为只写，只有所有者决定谁可以使用连接。** 文档账户的密钥、密码和令牌一经保存就不再显示，更改账户的连接位置需要再次提供密钥。步骤中的密码和密钥只存放在变量中；已输入到步骤中的密钥已移入仅架构师可见的项目变量。多行凭据在输入时会被屏蔽。只有连接的所有者或工作区管理员才能更改谁有权访问它。请参阅[已保存的密钥为只写](/zh-cn/guides/documents/adding-accounts/#已保存的机密为只写)、[密钥存放在变量中](/zh-cn/reference/workflow-steps/document/encrypt-decrypt-file/#密钥存放在变量中)和[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

- **您无法使用的文档账户对您保持关闭。** 检查文件是否存在、读取 Parquet、Avro、ORC 或 Delta 文件的列、使用 **填充** 填充导入步骤的列，以及 AI 助手的文件检查，现在都会拒绝您无权访问的账户，就像浏览该账户一样。

- **只有工作区管理员才能更改工作区管理员。** 编辑、停用或删除管理员、更改其分组，以及将某人设为管理员，都需要工作区管理员。请参阅[更改工作区管理员](/zh-cn/administration/access/member-management/#更改工作区管理员)。

- **数据共享只代表获授权项目的成员。** 通过共享读取需要在接收项目中拥有角色，写入则需要 **写入** 共享，以及在该项目中的管理者或架构师角色。请参阅[在项目之间共享数据](/zh-cn/guides/projects/managing-projects/#在项目之间共享数据)。

- **还原仅适用于所指定的项目。** 还原早期版本会还原项目本身，权限检查针对该项目。其内容不属于自身标头中所指维度的维度备份文件会被拒绝。请参阅[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。

- **模板、导入和归档会拒绝不安全的内容。** 导出模板和报表模板在沙盒中渲染，只读取提供给它们的数据。导入根据自己的设置构建其加载查询，包含 PlaidCloud 归档从不含有的内容的项目归档会被拒绝，会与另一个项目共用报告架构的项目标识符会被拒绝。请参阅[模板可以使用什么](/zh-cn/reference/workflow-steps/export/export-templated/#模板可以使用的内容)和[还原归档](/zh-cn/guides/projects/archive-a-project/#还原归档)。

- **仪表板遵循 PlaidCloud 登录和您的行访问权限。** 仪表板的缩略图以您的身份渲染，账户仅来自 PlaidCloud 登录，仪表板只能从导出所生成的 ZIP 文件导入。请参阅[导入现有仪表板](/zh-cn/guides/dashboards/learning-dashboard/#导入现有仪表板)。

- **启动工作流运行不再返回该运行的凭据。**

- **运行用户定义函数的环境不再包含 PySpark 的 Java 库，** 这些库存在已知漏洞。PySpark 的 DataFrame 和 SQL API 仍可访问您的 Spark 计算集群，但导入 `SparkContext` 或 `RDD` 的函数现在会失败。请参阅 [PySpark 入门](/zh-cn/integrations/pyspark/getting-started/)。

- **附件、还原和转换仅读取您可以使用的账户。** 通过电子邮件发送文件、从文件还原维度或表归档、检查或导入表包、从模板填充 Excel 导出，以及转换 Alteryx 工作流，现在都会拒绝您无权访问的文档账户。将维度备份到文档账户需要对其有写入权限。工作流步骤不受影响，但通过电子邮件发送文件、还原表或填充 Excel 模板的步骤不能再从个人临时驱动器读取。
