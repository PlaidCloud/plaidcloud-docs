## 新增

- **Data Foundation 将您的 ERP 数据整合到一个 Common Finance Model 中。** Common Finance Model 将多个 ERP 系统和实例的 ERP 数据整合到单一模型中：统一的会计科目表、统一的实体集和统一的报告货币。基于它构建的报表、指标和 AI 助手读取的都是同一组数字，无论数据来自哪个 ERP。

  - **直接来自您的 ERP。** 总账、试算平衡表、主数据和预算通过 PlaidCloud 的 ERP 直接连接传入。**实体对照表**将各个源系统的公司代码映射到相同的实体，文件则用于补充系统中没有的内容，例如汇率或分摊动因。
  - **一个模型，一种货币。** **加载**会将每个源系统规整到 Common Finance Model 中，并换算为您的报告货币：损益表按期间平均汇率，资产负债表按期末汇率，权益按历史汇率。层次结构由您的主数据构建。
  - **检查就绪状态。** 针对每个实体和期间运行检查：试算平衡表和销售额与总账核对一致，每个产品、客户和科目都是已知的，货币可以换算，每个实体都已映射。
  - **保持最新。** **每晚刷新**会在每晚重新加载模型，缺失或为空的文件以警告而非错误结束。

  从模板（例如 **Enterprise Profitability**）创建项目，项目的 **基础数据**选项卡会引导您从已连接的 ERP 一路得到一个已加载并经过检查的模型。请参阅 [Data Foundation：Common Finance Model](/zh-cn/guides/projects/data-foundation/)。

- **在您自己的 Snowflake 或 Databricks 数据仓库上运行 PlaidCloud。** 工作区管理员在用户菜单中打开 **使用您自己的数据仓库**，并在自己的账户中运行生成的设置脚本。该脚本会为 PlaidCloud 创建一个有上限的数据仓库和一个服务身份，且从不触及您现有的数据仓库。**检查连接**会用通俗的语言解释任何问题及其解决方法。此后，新项目会将其表存储在您的数据仓库中，并在其中运行工作流；移除该数据仓库会撤销 PlaidCloud 在其中的访问权限。请参阅[使用您自己的数据仓库](/zh-cn/guides/connections/external-lakehouse/)。

  - **使用 Snowflake 或 Databricks 登录。** 管理员无需粘贴凭据，而是可以通过登录来关联数据仓库。之后，仪表板以每个人自己的数据仓库权限运行，工作流则以只持有您指定数据角色的服务身份运行。请参阅[使用 Snowflake 或 Databricks 登录](/zh-cn/guides/connections/external-lakehouse/#使用-snowflake-或-databricks-登录)。
  - **连接多个数据仓库。** **管理数据仓库**中的 **设为默认**会将新项目发送到另一个数据仓库，而现有项目保持不变。请参阅[管理数据仓库](/zh-cn/guides/connections/external-lakehouse/#管理数据仓库)。
  - **查看运行成本。** 运行历史记录会显示 **仓库成本**列，以积分或 DBU 显示每次运行的成本。请参阅[每次运行的仓库成本](/zh-cn/guides/connections/external-lakehouse/#每次运行的仓库成本)。
  - **您的治理规则保持不变。** 描述会写入数据仓库自己的目录；当 PlaidCloud 替换、重新创建或克隆表时，Snowflake 行访问和掩码策略以及 Databricks 行筛选器和列掩码会保持附加状态。请参阅[您的策略和描述会被保留](/zh-cn/guides/connections/external-lakehouse/#您的策略和说明会延续)。

- **在 PlaidCloud 中构建、发布 Panel 应用并为其设置品牌。**

  - **Panel Studio。** **Create app** 可从空白应用、表、视图、模板或应用库开始创建应用，**Open in Studio** 会在编辑器中打开应用的文件。保存草稿，**预览**私有构建，然后 **发布**正式应用。构建错误会指向对应的文件和行，**历史记录**可恢复任何已发布的版本，**Insights** 显示浏览量、加载时间和错误。**Ask Weave** 了解应用的文件和构建状态，并在保存任何代码之前向您显示完整差异供您批准。请参阅 [Panel Studio](/zh-cn/guides/panel-apps/studio/) 和[使用 Weave 构建 Panel 应用](/zh-cn/guides/panel-apps/build-with-weave/)。
  - **外观与 PlaidCloud 一致的应用套件。** 使用该套件构建的应用在浅色和深色模式下都采用 PlaidCloud 的颜色、字体和间距。套件包括导航、筛选器、关键数字卡片、图表、表单、命令面板、运行工作流的按钮、打印功能，以及一个在服务器上排序和汇总、按列设置数字格式、每次加载一屏行的数据网格，因此可以处理任意大小的表。应用以已登录查看者的身份读取表，并应用行安全。请参阅 [Panel 应用套件](/zh-cn/guides/panel-apps/app-kit/)、[DataGrid](/zh-cn/guides/panel-apps/app-kit/#datagrid) 和[面向 Panel 应用的数据 API](/zh-cn/guides/panel-apps/data-api/)。
  - **提醒和简报。** 当项目表中的某个数字超过限值时，通过推送通知、电子邮件、Slack 或 Microsoft Teams 获得通知，或者获取包含最多 10 个数字的每日或每周简报，且始终在您自己的行访问权限范围内。请参阅[提醒和简报](/zh-cn/guides/panel-apps/alerts-and-digests/)。
  - **项目、品牌和共享。** 将应用分配给项目，此前会先审核哪些人能打开该应用但不在该项目中。项目 **主页**选项卡上的 **Edit Branding** 可为项目中的所有应用设置八种品牌颜色和一个徽标。**Gallery…** 会将应用作为模板列出，供所有能查看其项目的人使用。请参阅[项目品牌和应用项目](/zh-cn/guides/panel-apps/branding/)和[应用库](/zh-cn/guides/panel-apps/gallery/)。

- **就业务数字的计算方式统一约定一次，每个 AI 答案都会使用该计算方式。** 项目架构师定义一个 **指标**，例如 *净收入*或 *员工人数*：包括其源表、行的汇总方式、始终计入的行、要联接的查找表，以及可用于细分的列。定义一经保存即生效；如果保存时引用了不存在的表或列，或者查找表的每个键对应多行，则会被拒绝。按名称或同义词向 AI 助手询问该指标，数字会按照定义、在您自己的行访问权限范围内计算得出，而不是由助手自行推算。定义通过 AI 助手或 REST API 进行管理。请参阅[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。

  - **派生指标。** 定义两个指标的比率、和或差（例如每个 FTE 的净收入），或者某个指标乘以固定系数。请参阅[从其他指标派生指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#由其他指标派生指标)。
  - **比较、排名和占比。** 询问与预算的差异、保留并列项的前 N 名或后 N 名，或者每一行占总计的比例。请参阅[比较、排名和占比](/zh-cn/integrations/ai-coding-agents/metric-definitions/#比较排名和占比)。
  - **您的用语，约定的值。** 将细分列绑定到维度后，诸如 *EMEA* 之类的词就代表其下的所有区域。不匹配任何成员或匹配多个成员的词，会作为候选项返回并询问您，而绝不会被猜测。请参阅[询问指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#询问指标)。
  - **财务时间。** 告知指标其行在您的财务日历中的位置，即可询问某个财务期间、年初至今、同比或环比。请参阅[随时间比较](/zh-cn/integrations/ai-coding-agents/metric-definitions/#随时间比较)。

  PlaidCloud 自己的 AI 助手会优先根据指标回答业务数字，并在单独的卡片中显示这些数字，卡片带有 ✓ 标记，该标记绝不会附加到助手自己的文字上。请参阅[业务数字](/zh-cn/guides/ai-assistant/weave-tab/#业务数字)和[来自指标的数字](/zh-cn/guides/ai-assistant/weave-tab/#来自指标的数字)。

- **询问 Weave 是否已准备好结账，并检查两个表是否核对一致。** 两者都不涉及 AI。

  - **结账就绪状态。** 在项目 **Weave** 选项卡的 **就绪状态**中，将结账、预测或任何截止日期所依赖的工作流指定为一个 **就绪集**。一份清单即可回答所有这些工作流的情况：“13 个中 11 个已就绪；1 个未就绪；1 个无法检查。”只有当 Weave 能对某个工作流运行的每项检查都通过时，该工作流才算就绪；Weave 无法判断的任何内容都显示为 **无法检查**并附上原因，绝不会显示为已就绪。如果上次运行之前可供比较的历史记录太少（例如新工作流），该运行视为正常。不写入表的步骤（例如发送电子邮件或导出文件的步骤）没有要检查的行数或空值，因此不会让工作流停留在 **无法检查**状态。请参阅[结账前检查就绪状态](/zh-cn/guides/ai-assistant/weave-readiness/)。
  - **对账。** 按您配对的键列逐行比较两个表，或同一个表的两个期间。Weave 会说明它们是否核对一致、相差多少以及哪些行不同，并且对于无法完整读取的数据，绝不会说“核对一致”。每个对账在使用前都需由另一位架构师批准。请参阅[检查两个表是否核对一致](/zh-cn/guides/ai-assistant/weave-reconciliation/)。

- **Weave 会关注更多可能出错的地方，并在两次运行之间通知您。** Weave 的检查不使用 AI。每个发现项以及 AI 助手的每个答案都有一个 **Weave 如何得知**面板：对于发现项，显示检查及其依据的值；对于答案，显示助手运行的每个查询，并将每句话标记为 **已匹配**、**未匹配**或 **未检查**。请参阅 [Weave 目前检查的内容](/zh-cn/guides/ai-assistant/weave-findings/#weave-目前检查的内容)、[Weave 如何得知](/zh-cn/guides/ai-assistant/weave-findings/#weave-如何得知)和 [AI 助手中的 Weave 如何得知](/zh-cn/guides/ai-assistant/weave-tab/#weave-如何得知)。

  - **按时写入的表。** Weave 会报告自计划到期以来未被写入的表，或未写入时间超过您在表详细信息的 **时效性**下设置的时效性阈值的表，阈值范围为 1 小时到 180 天。
  - **过时或损坏的输入。** Weave 会报告读取了此后又被另一个工作流写入的表的工作流，以及依赖失败运行的每个工作流和仪表板，包括图表基于 SQL 数据集构建的仪表板。**同步依赖项**会添加步骤与其读取的表之间缺失的连接线。请参阅[同步依赖项](/zh-cn/guides/workflows/sync-dependencies/)。
  - **形态发生变化的数据。** Weave 会报告运行后值的分布差异很大的小数列、开始将行写入多次的联接、Extract 步骤因无法转换为列类型而留空的值，以及未找到文件的导入。它还会报告最近一个期间与平常相差很大的指标，并指出导致该变化的项。Weave 会考虑月末和工作日模式，因此月末总是很重的加载不会被报告。请参阅[异常的指标总计](/zh-cn/guides/ai-assistant/weave-metric-insights/)。
  - **变慢的运行。** Weave 会指出导致运行变慢的步骤，并报告较新运行比较早运行至少慢四分之一的工作流，同时指出耗时增长最多的步骤。
  - **在两次运行之间收到通知。** 每小时检查会以应用内消息的形式通知每个问题的负责人一次，页眉中的 **Weave** 按钮会统计您所有项目中尚未阅读的问题。请参阅[两次运行之间收到通知](/zh-cn/guides/ai-assistant/weave-findings/#两次运行之间收到通知)和[页眉中的 Weave 按钮](/zh-cn/guides/ai-assistant/weave-tab/#标题栏中的-weave-按钮)。
  - **负责人、评论和预期警告。** 每个发现项都有一个负责人，默认为上次运行其工作流的人。**分配**可将其转交他人，评论可记录进展，**团队**视图显示谁负责什么。架构师可以将警告标记为 **此为预期**，并注明原因和结束日期。请参阅[为发现项指定负责人](/zh-cn/guides/ai-assistant/weave-tab/#为发现项指定负责人)和[将发现项标记为预期](/zh-cn/guides/ai-assistant/weave-tab/#将发现项标记为预期)。

- **修复助手会解释错误，提出一项需您在卡片上批准的更改，重新运行步骤，并可撤消修复。** 对于最常见的失败，例如表中不存在的列、为空的必填设置、数据库无法读取的 SQL 或类型错误的值，第一条回复就会解释通常的原因及修复方法。提议的更改以卡片形式显示，卡片说明步骤失败的原因，并显示每个更改的设置，当前值为红色，新值为绿色。**批准**会应用该更改，随后助手会提议重新运行该步骤，并诊断新的失败。**Weave** 选项卡中发现项上的 **修复**会针对该问题打开助手。**撤消**会恢复步骤之前的设置，**撤消并运行**会重新构建其输出。请参阅[使用 AI 修复工作流错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/)、[使用 AI 助手修复发现项](/zh-cn/guides/ai-assistant/weave-tab/#使用-ai-助手修复发现项)和[撤消修复](/zh-cn/guides/ai-assistant/fixing-workflow-errors/#撤消修复)。

- **查看 Weave 在项目中所做的一切，并导出给审计人员。** 项目 **Weave** 选项卡上的 **活动**会列出 Weave 发现后又不再出现的问题、AI 助手提议的每项更改、由谁请求以及由谁批准或拒绝、它具体替换和写入了什么，以及最终结果。Weave 会在进行更改之前记录您的批准，并且不会进行任何无法记录的更改。**导出 CSV** 或 **导出 PDF** 可将某个期间保存为审计证据，且条目无法编辑或删除。**摘要**以概览形式显示一个月的情况：发现和解决的问题、已批准的更改以及其中有多少被撤消。工作区管理员可从 **工作区摘要…** 获取所有项目的相同信息。请参阅 [Weave 活动历史记录](/zh-cn/guides/ai-assistant/weave-activity/)和 [Weave 月度摘要](/zh-cn/guides/ai-assistant/weave-monthly-summary/)。

- **在保存之前了解步骤的作用，以及更改它会影响什么。** 所有这些内容都基于项目的已保存设置构建，不涉及 AI，您的角色所隐藏的任何内容都只计数，绝不列出名称。

  - **每个表、步骤和工作流的文档。** 详细信息面板中的 **文档**部分会说明哪些内容读取和写入某个表、某个步骤的作用，以及工作流按顺序排列的步骤。**下载交接包**会将整个项目保存为一个文档，其中包括指标定义和分摊模型。请参阅[表、步骤和工作流的文档](/zh-cn/guides/ai-assistant/weave-documentation/)。
  - **更改会影响什么。** 在 **保存**上方，Weave 会说明有多少下游步骤读取该步骤写入的内容，例如“对此步骤的更改会影响 2 个工作流中的 8 个下游步骤”，**显示步骤**会列出这些步骤。请参阅[更改会影响什么](/zh-cn/guides/ai-assistant/impact-preview/)。
  - **保存会拒绝什么。** **保存**上方的提示条会在您编辑时运行步骤的检查，并为每个问题提供 **转到**，表达式编辑器会在您输入时检查表达式。请参阅[保存会拒绝什么](/zh-cn/guides/ai-assistant/check-while-you-edit/)。
  - **审核单个工作流。** 在工作流的画布或 **步骤**网格中选择 **检查**，即可对其运行 Weave 的检查，外加分摊和行级安全检查。请参阅[审核单个工作流](/zh-cn/guides/ai-assistant/weave-findings/#审核单个工作流)。

- **为您的工作区关闭 Weave 的任意 AI 功能。** 工作区管理员在页眉 **Weave** 按钮上选择 **AI 功能…**，即可分别打开或关闭 Weave 聊天、修复助手、导入和导出助手、表达式助手、根据描述生成 SQL、工作流审核摘要或入门图表。在管理员关闭之前，所有功能都处于打开状态；Weave 的检查和发现项始终保持打开，每项更改都会记录在安全日志中。请参阅 [AI 功能](/zh-cn/guides/ai-assistant/weave-ai-features/)。

- **在 Allocation Split 步骤上尝试动因假设分析。** 右键单击该步骤并选择 **假设分析…**，即可查看在使用不同的动因值、其驱动因素表的另一列，或另一个具有相同键的表中的数值列时，它会如何分摊成本。最多可比较 10 个方案，每个方案都根据步骤的上次运行精确计算到分，并可查看谁得益、谁受损，以及哪些行将分不到任何金额。**细分依据**会显示每个成员的变化落在哪些科目或其他值上，**后续步骤**会将方案延续到基于分摊输出构建的表中。不会重新运行任何内容，也不会更改任何数据。请参阅[尝试动因假设分析](/zh-cn/guides/allocations/results/driver-what-if/)。

- **将项目迁移到 Lakehouse v2 的过程从就绪检查到撤消都有引导。** **检查迁移就绪状态**会将表、视图、步骤、仪表板、数据共享和容量报告为无问题、需要审核或受阻，并对每个发现项给出通俗的解释。**在 v2 上试用…** 会创建一个私有试用副本，其中计划处于关闭状态，ERP 过账处于模拟模式。可以立即开始迁移，也可以在您选择的时间开始。迁移运行期间，项目的计划会暂停，之后会恢复；迁移完成时，您会通过消息和电子邮件收到通知。**变更内容…** 会报告每个表的结果，**撤消迁移…** 可在撤消时限内将项目恢复到 Lakehouse v1。请参阅[将项目迁移到 Lakehouse v2](/zh-cn/guides/data/migrate-project-lakehouse/)。

  - **Copilot 能做更多事情。** Microsoft 365 Copilot 中的 PlaidCloud 代理可创建 CSV、Excel、PowerPoint 和 Word 文件，根据您的指标回答业务数字，对整个表进行细分汇总，并解释分摊的工作方式。管理员下载更新后的包，并在 Teams 管理中心中进行更新。请参阅 [Microsoft 365 Copilot](/zh-cn/integrations/microsoft-365-copilot/)。
  - **一次调用完成更多工作。** 助手可以在服务器上对表进行分组和汇总（先应用行访问），搜索和阅读 PlaidCloud 的文档，使用只写凭据创建完全配置好的文档账户（包括 OneDrive 和 SharePoint），既可添加标签也可移除标签，并可处理您在 PlaidCloud 中看到的视图。请参阅[分析路径](/zh-cn/integrations/ai-coding-agents/analysis-paths/#通过-mcp-使用)和[AI 代理入门](/zh-cn/integrations/ai-coding-agents/getting-started/)。

## 变更

- **转到指标会打开 Weave 发现项所涉及的指标。** 它显示指标的数字，在您点击时计算并按您自己的行访问权限显示，并用 ✓ 标明数字所来自的版本。对于异常总计，是 Weave 指明的项在其判断期间的数据。对于任何其他指标发现项（包括由其他指标计算得出的指标），则是该指标的总计。数字下方的**转到行**仍会在表资源管理器中打开变化背后的行。请参阅[转到指标](/zh-cn/guides/ai-assistant/weave-metric-insights/#转到指标)。

- **一个 Weave 选项卡同时容纳您的发现项和 Weave AI 聊天。** 聊天以选项卡形式位于 **Weave** 选项卡内，排在 **发现项**之后。每个发现项都是一张卡片，带有各自的 **修复**、**转到**和 **标记为已读**按钮；虚线卡片表示 Weave 无法检查的内容，筛选标签可按需要关注的内容筛选列表。关于表达式的发现项会指出错误所在位置，表达式本身位于 **Weave 如何得知**中。运行结束时，Weave 对每个问题只提及一次，关于同一项目的消息会合并为一条，而不是层层堆叠。由于 Weave 只重新检查已更改的内容，该选项卡在大型项目中也能快速打开。工作流列表中的 Weave 列已移除。请参阅 [Weave 选项卡](/zh-cn/guides/ai-assistant/weave-tab/)和[运行结束时收到通知](/zh-cn/guides/ai-assistant/weave-findings/#运行结束时收到通知)。

- **Ctrl/Cmd-K 可从任意屏幕打开命令面板。** 在您输入之前，它会列出您最近打开的内容以及可以执行的操作：转到主页、项目、仪表板或文档，在浅色和深色之间切换，连接您的 AI，或获取帮助。输入内容会缩小两个列表的范围，输入两个字符后，它还会搜索项目、工作流、表、仪表板和 Panel 应用。请参阅[搜索和命令](/zh-cn/guides/launcher/#搜索和命令)。

- **步骤在保存时而不是运行时发现问题。** 如果步骤的设置会导致运行失败或给出错误结果，保存该步骤时会被拒绝，并显示一条说明需要更改什么的消息。每个步骤的参考页面都列出了它检查的内容。步骤或其源表已不再包含的已映射源列会以红色标出，保存时会打开一个对话框，提供 **全部移除并保存**、**仍然保存**或 **取消**。联接、查找和空间步骤会保留这些行，而不是自行删除它们。使用未定义变量的表达式会指出该变量，运行时被拒绝的步骤会用通俗的语言解释原因。请参阅[不再列出的源列](/zh-cn/reference/workflow-steps/tables/table-extract/#不再列出的源列)、[源表中缺失的列](/zh-cn/reference/workflow-steps/tables/table-extract/#源表中缺少的列)和[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。

- **缺失或为空的源绝不会被视为错误。** 文件缺失或为空的文件导入会以警告完成，警告中会注明路径，并将其目标表保留为空表，但包含其声明的列，因此后续步骤读取到的行数为零。处理缺失或空文件夹的文档步骤会报告“没有要处理的内容”，工作流继续运行。远程文件步骤会对缺失的路径发出警告，并拒绝不安全的路径。缺失文件检查适用于 OneDrive、SharePoint 和 SFTP。批处理表为空的 **报表：批量生成**会以警告完成，且不生成任何报表。请参阅[导入步骤](/zh-cn/reference/workflow-steps/import/)、[文档工作流步骤](/zh-cn/reference/workflow-steps/document/)和[文档路径条件](/zh-cn/guides/workflows/step-conditions/#文档路径条件)。

- **大型工作流可靠运行，停止操作会取消导入和导出。** 当 PlaidCloud 繁忙时，步骤会等待可用容量而不是失败，并且会随着步骤排队而增加容量。导入外部数据库表一次最多运行 10 个表。如果运行步骤的服务器丢失，替换其输出的步骤会自动重新运行，而无法安全重复的步骤会失败一次，并显示 *已中断* 消息。**停止**会取消正在运行的导入和导出作业，已停止的运行会报告为 Stopped。请参阅[已中断的步骤](/zh-cn/guides/workflows/run-a-workflow/#已中断的步骤)和[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)。

- **每个 Lakehouse 的存储和计算方式都相同。** 来自导入 CSV、导入 XML 或 Import Table Archive 的空字段会加载为 null，因此测试 `= ''` 或 `= 0` 的后续步骤需要改为测试 null。`cast(x, Float)` 在所有地方都是 64 位，因此大金额会保留其位数，PlaidCloud 创建的 Float 列均为双精度。JSON 列、**Table: Delete Rows** 和进行聚合的条件在每个 Lakehouse 上都可用。自行构建结果的步骤，例如求解器、预测，以及在 pandas 中运行时的 Pivot 和 Allocation Split，会以带类型的数据加载结果，速度快得多。表资源管理器会显示数值列的最小值、最大值、平均值、总和、标准差和方差。请参阅[转换为 Float](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#转换为-float)和[列数据和唯一值计数](/zh-cn/guides/data/table-explorer/#列数据和唯一值计数)。

- **文件导出会保留其类型。** Parquet 文件将整数列保留为整数，以微秒存储时间戳，并将时区标记为 UTC。Avro 文件会保留日期、时间戳和布尔值的类型，单表 Avro 导出会以导出名称命名。为 Parquet 导出选择多个文件时会停止，并显示消息说明 Parquet 只写入单个文件。非常大的 Parquet、ORC 和 JSON 导出会在读取行的同时写入，因此不会再耗尽内存，并且 Parquet 会使用您选择的压缩方式。版本为 1.2.33 或更高版本的 PlaidLink 代理会以 Parquet 文件的形式接收导出的表。请参阅 [Export to Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro](/zh-cn/reference/workflow-steps/export/export-to-avro/) 和[数据如何到达代理](/zh-cn/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#数据如何到达代理)。

- **ERP 过账遵循每个计划的模式，不确定的答复会保留供您检查。** 计划事件保留其自身的过账模式：**实时**、**模拟**或 **关闭**，上限为项目的设置，**运行所选事件**会使用每个事件的模式。PlaidCloud 无法确认的 ERP 答复（例如超时或服务器错误）会作为存疑保留，而不是记录为已拒绝，并且同一笔过账不能被冲销两次。过账登记簿会列出 **reversal outstanding** 的过账，架构师可在项目主页的 **ERP 写入授权**中授权项目过账。请参阅 [ERP过账模式](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)、[冲销](/zh-cn/guides/connections/posting-register/#冲销)和[授权项目过账](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)。

- **行访问会跟上组的变化，并说明出错的原因。** 单点登录在用户登录时设置的组成员身份会在大约 15 分钟内同步到仪表板行访问，默认组的新成员会在大约一分钟内获得其行。行访问窗口会在限制没有筛选任何内容时发出警告，可处理包含 `&`、`/` 或 `%` 的列名，并在同步失败时显示 **错误**及原因，或显示 **正在重试**及 **重试**按钮。请参阅[保持仪表板同步](/zh-cn/administration/access/managing-security-groups-and-assignments/#保持仪表板同步)。

- **用户定义函数在 Python 3.14 上运行，并使用更新的库。** 大多数函数无需更改即可运行。导入 numba 或 Python 已移除的标准库模块（例如 `cgi` 或 `telnetlib`）的函数现在会失败，需要重写。预测的 AutoTheta 边界可能与之前的运行略有不同。请参阅 [User Defined Transform](/zh-cn/reference/workflow-steps/general/user-defined-transform/)。

- **完整代理访问已弃用，并将于 2027 年 1 月 15 日移除。** 使用 **完整**访问的 LLM 步骤会记录一条警告。请改用 **读取和写入**，在此模式下，代理通过 PlaidCloud 的写入工具更改数据，LLM 步骤只写入勾选了 **写入**的绑定。请参阅[代理访问](/zh-cn/integrations/ai-architecture/llm-providers/#代理访问)。

- **文档账户更易于设置和浏览。** OneDrive 或 SharePoint 账户的文件浏览器会打开其起始路径下的文件夹。Google Cloud Storage 账户需要有效的服务账户密钥，没有密钥的现有账户将停止工作，直到您添加密钥。被拒绝的设置会说明原因，**管理账户**中未使用的备份图标已移除。请参阅[添加 Google Cloud Storage 账户](/zh-cn/guides/documents/adding-accounts/add-google-cloud-storage-account/)和[备份文档账户](/zh-cn/guides/documents/account-management/managing-document-account-backups/)。

- **Project 应用对发票、差旅和补报工时的处理更加完善。** 新发票从主项目开始创建，主项目提供客户和采购订单号。删除草稿发票会使其工时和差旅重新变为可计费，**AR 收件人**设置提交发票时向谁发送电子邮件。差旅抽屉会显示每一行的供应商、类别和审计状态，**添加补报工时**会为已批准的一周创建工时表。请参阅[使用 Project 应用跟踪工时和费用](/zh-cn/guides/time-expense/track-time-and-expenses/)。

- **删除所有未被任何步骤引用的表的 API 调用已移除。** 请改为按 ID 删除表。

- **应用中的一些较小更改。** 在账户、仪表板、成员、组或设置列表中双击某一行即可打开它。空的 **维度**、**数据编辑器**、**UDF** 和 **步骤**选项卡会说明下一步该做什么，没有任何应用的成员会进入启动器。步骤的表选择器会显示表的上次更新时间（[查看源表上次更改的时间](/zh-cn/guides/workflows/create-workflow/#查看源表最后一次更改的时间)）。Export External Database Tables 在单独的选项卡上映射列，**报表：批量生成**不再显示未使用的 **Report Constants** 部分。Convert Encoding 可识别中欧、土耳其和阿拉伯编码。指向已移除屏幕的链接会说明该屏幕已移除。

## 修复

- **AI 助手在您批准之前不会更改任何内容，并按原样显示名称。** 以前将步骤构建到新表中时，会在您批准之前就创建该表；现在，表和步骤会在您批准后一起创建，创建项目、工作流或维度、复制表以及更改表属性或标签也都会先征求您的同意。批准只在您的下一条回复中有效。助手提议的导入或导出会按名称显示其表、文档账户和工作流，并且绝不会提供不存在或您无法打开的对象。带下划线的名称会按原样显示，而不会变成斜体，表格和代码在深色主题中清晰可读，图表会正常绘制而不是显示为文本，表达式编辑器的 Weave 面板会读取您正在编辑的表达式。即使某个表没有名称，助手也会列出项目的表；即使某个步骤读取或写入多个表，助手也会回答哪些步骤读取或写入某个表，而不是因错误而停止。请参阅[构建工作流步骤](/zh-cn/guides/ai-assistant/weave-tab/#构建工作流步骤)。

- **文件导入会读取您指定的内容。** 导入 Excel 可读取整列范围和 XLSB 工作簿，能在压缩的工作簿中找到工作表，并且不再因标题带有填充或换行而失败。导入 CSV 会遵循 **跳过行数**设置，因此标题上方有其他行的文件（例如 SAP 列表导出）会按列名导入，并且它使用默认的分隔符、引号和转义字符运行。一个源列可以为多个目标列提供数据，所有列都是固定值的导入会加载每一行，以大写压缩扩展名命名的文件会被解压，未更改时跳过的导入会重新加载已被清空的表。让 AI 助手从 **Project Default** 导入文件时，会读取项目的默认文档账户，并在项目未设置默认账户时明确告知您。具有较新列类型的 Parquet 文件可在文档中打开。请参阅[导入 Excel](/zh-cn/reference/workflow-steps/import/import-excel/#读取内容)和[导入 CSV](/zh-cn/reference/workflow-steps/import/import-csv/#行选择)。

- **工作流步骤会按配置保存和运行。** 表：Upsert 步骤可以再次保存，其 **更新键**列也已恢复。表：项目间复制会指出其目标项目，并可通过数据共享读取数据。文档：将仪表板保存为 PDF 会保留其列类型，表：去重合并和全部合并会按名称匹配列。多表联接可以使用多个输入进行保存，并接受包含空格的列名。Table Lookup 会忽略其查找列上的聚合设置，SCD-2 截至日期联接可接受变量作为日期。LLM 步骤可在早于 4.6 的 Claude 模型上运行，并且在 AI 助手编辑它们时会保留其模型。REST 请求发送的行值只编码一次，导出到远程数据库时会提交其行。请参阅[更新键](/zh-cn/reference/workflow-steps/tables/table-upsert/#更新键)、[数据共享管理](/zh-cn/reference/workflow-steps/tables/frame-project-copy/#数据共享管理)和[多表联接](/zh-cn/reference/workflow-steps/tables/table-multi-table-join/)。选择工作流的步骤（例如 Workflow Delete、Copy、Rename 和 Stop）会保留已不存在的工作流，并显示为 *id（缺失）*，而不是切换到列表中的第一个工作流。

- **工作流运行会正常完成。** Workflow Loop 会在每次迭代中运行被循环的工作流，迭代容器以及在一次运行中多次运行的工作流也是如此。从某个步骤开始或在并行组内开始的运行会运行正确的步骤并完成。长时间运行的导入或导出绝不会被启动两次，不会在 PlaidCloud 更新期间停滞，以服务器错误结束的操作也不会再次发送。数据库驱动程序崩溃只会使其自身的步骤失败，并给出数据库提供的原因。运行历史记录会统计每个步骤的行数，在工作开始之前就失败的步骤会将原因写入工作流日志。请参阅 [Workflow Loop](/zh-cn/reference/workflow-steps/workflow-control/workflow-loop/) 和[运行历史记录](/zh-cn/guides/workflows/advanced-workflows/#运行历史)。

- **项目的复制、导入和打开不再出现意外。** 项目导入会保留它能够恢复的所有内容，并在 **导入结果**窗口中列出未导入的内容，同时显示进度，说明失败的原因，并且可以重试。当项目包含变量时，复制所选对象也能正常工作。打开项目不再更改其设置，**导入您自己的数据**会导入您的 CSV，在 PostgreSQL 数据仓库上创建表也能正常工作。App Runner 应用会在 PlaidCloud 更新时自行刷新，并且在限制行的项目中也能供查看者使用。请参阅[归档的部分内容未导入时](/zh-cn/guides/projects/archive-a-project/#归档的部分内容未能导入时)和[让应用保持最新](/zh-cn/guides/workflows/use-converted-alteryx-apps/#保持应用为最新)。

- **维度和分摊可以正确加载和读取。** 父子加载会将父项为空的行保留为顶级成员，在每种加载中，主层次结构之外的成员都会被拒绝加入第二个备用层次结构。将成员移到其层次结构中不包含的父项下会被拒绝，维度步骤会指出它找不到的维度，粘贴含空白的列时每个值都会保留在其所在行。读取大型维度不再阻塞工作区中的其他所有人。维度属性将 **层次结构**保留为 **未指定**的分摊规则可以运行。请参阅[加载到备用层次结构](/zh-cn/reference/workflow-steps/dimensions/dimension-load/#加载到备用层次结构)和[维度类型属性和成员选择器](/zh-cn/guides/dimensions/dimensions/#维度类型属性和成员选取器)。

- **工作流画布和各个屏幕运行正常。** **钻取到工作流**会在画布上打开高级工作流，画布可以打开每个工作流，并在布局的某部分无法读取时告知您。放不下的工具栏按钮会移到 **更多**菜单中，列表在您保存后立即更新。通知会显示完整消息，警告会在 **日志**选项卡中显示警告图标，表资源管理器会在列的概况分析失败时说明，数据编辑器会保持空的日期单元格为空。在启用列筛选器的情况下保存数据编辑器时，会保留被筛选器隐藏的行，包括在您添加、删除或移动行之后。用户定义函数编辑器会以可编辑状态为任何有权更改它的人打开。请参阅[画布无法打开工作流时](/zh-cn/guides/workflows/advanced-workflows/#画布无法打开工作流时)。从 **表**列表中删除表时，会列出仅通过变量路径（例如 `/Periods/{period}/Sales`）访问某个表的任何步骤，并且只有在您强制执行时才会删除该表。请参阅[删除](/zh-cn/guides/projects/managing-tables-and-views/#删除)。

- **成员和连接正常工作。** **添加工作区成员**适用于已有账户的人，包括通过单点登录创建的账户，并且绝不会降低他们所持有的项目角色。ODBC 连接通过 PlaidLink 代理所在计算机上的 DSN 或驱动程序进行连接。拒绝您 OAuth 凭据的提供程序会提示您重新输入或重新授权，Databricks 示例和导出会刷新即将过期的令牌，较旧数据库类型的连接可以删除。**使用位置**包括通知步骤，免费工作区会保留每日、每周和每月备份。请参阅[成员管理](/zh-cn/administration/access/member-management/)和 [ODBC](/zh-cn/reference/connectors/databases/odbc/)。

- **REST API 和 AI 助手工具会严格按您的要求执行。** 对成员、组或计划事件的部分更新只会更改您指定的字段，因此已暂停的事件会保持暂停状态。在指定步骤开始运行会从该步骤开始，还原表快照时会保留一个安全快照和一条审计记录。来自 AI 工具的动因假设分析只会在与模型实际执行的拆分一致时给出答案。以前因服务器错误而失败的请求现在可以正常工作，或会说明出错的原因。请参阅[跟踪分摊](/zh-cn/integrations/ai-coding-agents/tracing-allocations/)和[还原或恢复快照](/zh-cn/guides/data/table-snapshots/#回退或还原快照)。

## 安全

- **AI 助手始终在您的权限范围内工作。** 助手的数据查询会在运行之前按其结构进行检查，并且只运行单个读取查询。只读 AI 连接（包括 Microsoft 365 Copilot）无法导出文件、保存仪表板 PDF、将行复制到另一个项目，或通过 REST 连接发送更改。通过 AI 助手进行的导入以您的身份、在您指定的项目中运行，并且对话只能由发起者继续。助手和表引用会排除您的角色所隐藏的表、步骤、工作流和维度，Weave 会对您无法打开的失败步骤只计数而不列出名称。请参阅[访问级别](/zh-cn/integrations/microsoft-365-copilot/#访问级别)、[您的角色所隐藏的内容](/zh-cn/guides/ai-assistant/weave-tab/#您的角色隐藏的内容)和[管理过去的对话](/zh-cn/guides/ai-assistant/weave-tab/#管理过往对话)。

- **ERP 过账无法绕过其控制。** 启用职责分离后，冲销会通过过账登记簿进行，并在其中应用审批。复制或导入的项目不再继承过账权限，SAP 和 EBS 过账无法直接发送给代理，处于 Test Only Mode 的 SAP Post 步骤需要与正式过账相同的权限。一个未经这些检查即可向 Sage Intacct 过账的未记录端点已被移除。来自 ERP 和 REST 连接的错误消息不会包含凭据。请参阅[职责分离](/zh-cn/guides/connections/posting-register/#职责分离)。

- **密钥为只写，且只有所有者才能决定谁可以使用连接。** 文档账户的密钥、密码和令牌在保存后绝不会再次显示，更改账户的连接目标需要再次提供密钥。步骤中的密码和密钥只存在于变量中；之前直接输入到步骤中的密钥已移至仅对架构师可见的项目变量中。多行凭据在您输入时会被遮盖。只有连接的所有者或工作区管理员才能更改谁有权访问该连接。请参阅[已保存的密钥为只写](/zh-cn/guides/documents/adding-accounts/#已保存的机密为只写)、[密钥存放在变量中](/zh-cn/reference/workflow-steps/document/encrypt-decrypt-file/#密钥存放在变量中)和[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

- **您无法使用的文档账户对您保持关闭。** 检查文件是否存在、读取 Parquet、Avro、ORC 或 Delta 文件的列、使用 **填充**来填写导入步骤的列，以及 AI 助手的文件检查，现在都会拒绝您无权访问的账户，就像浏览该账户时一样。

- **只有工作区管理员才能更改工作区管理员。** 编辑、停用或删除管理员、更改其组以及将某人设为管理员，都需要由工作区管理员执行。请参阅[更改工作区管理员](/zh-cn/administration/access/member-management/#更改工作区管理员)。

- **数据共享只为被授予共享的项目中的成员提供数据。** 通过共享读取需要在接收项目中拥有角色，写入则需要 **写入**共享以及在该项目中拥有管理者或架构师角色。请参阅[在项目之间共享数据](/zh-cn/guides/projects/managing-projects/#在项目之间共享数据)。

- **还原只应用于指定的项。** 还原较早的版本会还原该项本身，权限检查也针对该项进行。内容不属于其自身标头中所列维度的维度备份文件会被拒绝。请参阅[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。

- **模板、导入和归档会拒绝不安全的内容。** 导出模板和报表模板在沙盒中呈现，只能读取提供给它们的数据。导入会根据其自身的设置构建加载查询，包含 PlaidCloud 归档中绝不会出现的内容的项目归档会被拒绝，会与另一个项目共享报表架构的项目标识（slug）也会被拒绝。请参阅[模板可以使用的内容](/zh-cn/reference/workflow-steps/export/export-templated/#模板可以使用的内容)和[还原归档](/zh-cn/guides/projects/archive-a-project/#还原归档)。

- **仪表板遵循 PlaidCloud 登录和您的行访问权限。** 仪表板的缩略图以您的身份呈现，账户只来自 PlaidCloud 登录，仪表板只能从导出功能生成的 ZIP 文件导入。请参阅[导入现有仪表板](/zh-cn/guides/dashboards/learning-dashboard/#导入现有仪表板)。

- **启动工作流运行时不再返回该运行的凭据。**

- **运行用户定义函数的环境不再包含 PySpark 的 Java 库，** 这些库带有已知漏洞。PySpark 的 DataFrame 和 SQL API 仍可访问您的 Spark 计算集群，但导入 `SparkContext` 或 `RDD` 的函数现在会失败。请参阅[PySpark 入门](/zh-cn/integrations/pyspark/getting-started/)。

- **附件、还原和转换只读取您可以使用的账户。** 通过电子邮件发送文件、从文件还原维度或表归档、检查或导入表包、使用模板填充 Excel 导出，以及转换 Alteryx 工作流，现在都会拒绝您无权访问的文档账户。将维度备份到文档账户需要对该账户具有写入权限。工作流步骤不受影响，但通过电子邮件发送文件、还原表或填充 Excel 模板的步骤将无法再从个人临时驱动器读取。
