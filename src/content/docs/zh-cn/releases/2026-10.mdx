## 新增

- **Data Foundation 将您的 ERP 数据汇集到一个 Common Finance Model 中。** Common Finance Model 将来自多个 ERP 系统和实例的 ERP 数据汇集到单一模型中：一套会计科目表、一组实体和一种报告货币。基于它构建的报表、指标和 AI 助手读取的都是同样的数字，无论数据来自哪个 ERP。

  - **直接来自您的 ERP。** 总账、试算平衡表、主数据和预算通过 PlaidCloud 的 ERP 直连获取。**实体对照表**将各来源的公司代码映射到相同的实体，文件则补充系统未包含的内容，例如汇率或分摊动因。
  - **一个模型，一种货币。** **加载**会将每个来源统一到 Common Finance Model 中，并折算为您的报告货币：损益表按期间平均汇率，资产负债表按期末汇率，权益按历史汇率。层次结构根据您的主数据构建。
  - **检查就绪状态。** 针对每个实体和期间运行检查：试算平衡表和销售额与总账一致、每个产品、客户和科目均已知、货币可折算，并且每个实体都已映射。
  - **保持最新。** **每晚刷新**会在每晚重新加载模型，缺失或为空的文件会以警告而非错误结束。

  从模板（如 **Enterprise Profitability**）启动项目，项目的**基础数据**选项卡会带您从已连接的 ERP 一直到已加载、已检查的模型。请参阅 [Data Foundation：Common Finance Model](/zh-cn/guides/projects/data-foundation/)。

- **在您自己的 Snowflake 或 Databricks 数据仓库上运行 PlaidCloud。** 工作区管理员在用户菜单中打开**使用您自己的数据仓库**，并在自己的账户中运行生成的设置脚本。该脚本会为 PlaidCloud 创建一个有上限的数据仓库和一个服务身份，且绝不会触碰您现有的数据仓库。**检查连接**会用通俗的语言解释任何问题及其修复方法。此后新项目会在您的数据仓库中存储表并运行工作流，移除该数据仓库会撤销 PlaidCloud 在那里的访问权限。请参阅[使用您自己的数据仓库](/zh-cn/guides/connections/external-lakehouse/)。

  - **使用 Snowflake 或 Databricks 登录。** 管理员无需粘贴凭据，可以通过登录来关联数据仓库。仪表板随后以每个人自己的数据仓库权限运行，工作流则以仅持有您指定的数据角色的服务身份运行。请参阅[使用 Snowflake 或 Databricks 登录](/zh-cn/guides/connections/external-lakehouse/#使用-snowflake-或-databricks-登录)。
  - **连接多个。** **管理数据仓库**中的**设为默认**会将新项目发送到另一个数据仓库，而现有项目保持原位。请参阅[管理数据仓库](/zh-cn/guides/connections/external-lakehouse/#管理数据仓库)。
  - **查看一次运行的成本。** 运行历史记录为每次运行显示一个以积分或 DBU 计的**仓库成本**列。请参阅[每次运行的数据仓库成本](/zh-cn/guides/connections/external-lakehouse/#每次运行的仓库成本)。
  - **您的治理保持不变。** 说明会写入数据仓库自己的目录，Snowflake 的行访问和掩码策略以及 Databricks 的行筛选器和列掩码，在 PlaidCloud 替换、重新创建或克隆表时仍保持附加。请参阅[您的策略和说明会延续](/zh-cn/guides/connections/external-lakehouse/#您的策略和说明会延续)。

- **在 PlaidCloud 内构建、发布 Panel 应用并设置品牌。**

  - **Panel Studio。** **Create app** 可从空白应用、表、视图、模板或应用库开始，**Open in Studio** 在编辑器中打开应用的文件。保存草稿、**预览**私有构建，并**发布**正式应用。构建错误会指向其文件和行，**历史记录**可恢复任何已发布的版本，**洞察**显示浏览量、加载时间和错误。**询问 Weave** 了解应用的文件和构建状态，并在保存任何代码之前向您显示完整差异供批准。请参阅 [Panel Studio](/zh-cn/guides/panel-apps/studio/) 和[使用 Weave 构建 Panel 应用](/zh-cn/guides/panel-apps/build-with-weave/)。
  - **外观与 PlaidCloud 一致的应用套件。** 使用该套件构建的应用在浅色和深色下都采用 PlaidCloud 的颜色、字体和间距。套件包括导航、筛选器、标题数字卡片、图表、表单、命令面板、运行工作流的按钮、打印，以及在服务器上排序和汇总、按列设置数字格式、每次加载一屏行的数据网格，因此可处理任意大小的表。应用以已登录查看者的身份读取表，并应用行级安全。请参阅 [Panel 应用套件](/zh-cn/guides/panel-apps/app-kit/)、[DataGrid](/zh-cn/guides/panel-apps/app-kit/#datagrid) 和 [Panel 应用的数据 API](/zh-cn/guides/panel-apps/data-api/)。
  - **提醒与摘要。** 当项目表中的某个数字越过限值时，通过推送通知、电子邮件、Slack 或 Microsoft Teams 获得通知，或获得最多 10 个数字的每日或每周摘要，始终遵循您自己的行访问权限。请参阅[提醒与摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
  - **项目、品牌与共享。** 将应用分配给项目，分配前会审查谁可以打开它但不在该项目中。项目**主页**选项卡上的 **Edit Branding** 为项目中的每个应用设置八种品牌颜色和一个徽标。**Gallery…** 将应用作为模板列给所有能查看其项目的人。请参阅[项目品牌与应用项目](/zh-cn/guides/panel-apps/branding/)和[应用库](/zh-cn/guides/panel-apps/gallery/)。

- **一次约定业务数字的计算方式，所有 AI 回答都使用该计算。** 项目架构师定义一个**指标**，例如 *Net Revenue* 或 *Headcount*：其源表、各行如何汇总、始终计入的行、它联接的查找表，以及可用于细分的列。定义一经保存即生效，而指明了不存在的表或列、或查找表中每个键有多行的保存会被拒绝。按名称或同义词向 AI 助手询问该指标，数字就由该定义按您自己的行访问权限计算，而不是由助手推算。定义通过 AI 助手或 REST API 管理。请参阅[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。

  - **派生指标。** 定义两个指标的比率、和或差，例如人均净收入，或指标乘以固定系数。请参阅[从其他指标派生指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#由其他指标派生指标)。
  - **比较、排名和占比。** 询问相对预算的差异、保留并列项的前 N 名或后 N 名，或每行占总计的份额。请参阅[比较、排名和占比](/zh-cn/integrations/ai-coding-agents/metric-definitions/#比较排名和占比)。
  - **您的用语，约定的取值。** 将细分列绑定到维度，*EMEA* 之类的词就会变成其下的每个地区。不匹配任何成员、或匹配多个成员的词，会作为候选项返回并询问您，绝不会猜测。请参阅[询问指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#询问指标)。
  - **财政时间。** 告知指标其各行位于您财政日历中的什么位置，然后询问财政期间、年初至今、同比或环比。请参阅[随时间比较](/zh-cn/integrations/ai-coding-agents/metric-definitions/#随时间比较)。

  PlaidCloud 自己的 AI 助手会优先根据指标回答业务数字，并将数字显示在带有 ✓ 标记的独立卡片中，该标记绝不会附在助手自己的文字上。请参阅[业务数字](/zh-cn/guides/ai-assistant/weave-tab/#业务数字)和[来自指标的数字](/zh-cn/guides/ai-assistant/weave-tab/#来自指标的数字)。

- **询问 Weave 是否已准备好结账，并检查两个表是否一致。** 两者都不涉及 AI。

  - **结账就绪状态。** 在项目 **Weave** 选项卡的**就绪状态**中，将结账、预测或任何截止期限所依赖的工作流命名为一个**就绪集**。一份清单即可回答所有这些工作流：“13 个中 11 个就绪；1 个未就绪；1 个无法检查。”只有当 Weave 能对工作流运行的每项检查都通过时，该工作流才算就绪，Weave 无法判断的任何内容都会连同原因显示为**无法检查**，绝不会显示为就绪。上次运行的更早历史记录太少而无法比较（例如新工作流）时，按正常情况计算。不写入表的步骤（例如发送电子邮件或导出文件）没有行或空值可检查，因此不会使工作流停留在**无法检查**。请参阅[结账前检查就绪状态](/zh-cn/guides/ai-assistant/weave-readiness/)。
  - **对账。** 在您配对的键列上，逐行比较两个表，或同一个表的两个期间。Weave 会说明它们是否一致、相差多少以及哪些行不同，并且对于它无法完整读取的数据，绝不会说“一致”。每项对账在使用前需由另一位架构师批准。请参阅[检查两个表是否一致](/zh-cn/guides/ai-assistant/weave-reconciliation/)。

- **Weave 监视更多可能出错的地方，并在两次运行之间通知您。** Weave 的检查不使用 AI。每个发现项以及 AI 助手的每个回答都有一个 **Weave 如何得知**面板：对于发现项，是检查及其背后的取值；对于回答，是助手运行的每个查询，每个语句都标有**已匹配**、**未匹配**或**未检查**。请参阅 [Weave 现在检查什么](/zh-cn/guides/ai-assistant/weave-findings/#weave-目前检查哪些内容)、[Weave 如何得知](/zh-cn/guides/ai-assistant/weave-findings/#weave-如何得知)和 [AI 助手中的 Weave 如何得知](/zh-cn/guides/ai-assistant/weave-tab/#weave-如何得知)。

  - **按时写入的表。** Weave 会报告自计划到期以来一直未写入的表，或超过您在表详细信息的**时效性**下设置的时效性阈值（1 小时至 180 天）未写入的表。
  - **过时或损坏的输入。** Weave 会报告读取了另一个工作流此后写入的表的工作流，以及所有依赖于失败运行的工作流和仪表板。**同步依赖项**会补上步骤与其读取的表之间缺失的连接器。请参阅[同步依赖项](/zh-cn/guides/workflows/sync-dependencies/)。
  - **形态发生变化的数据。** Weave 会报告运行后取值分布大幅不同的小数列、开始多次写入行的联接、Extract 步骤因无法转换为列类型而留空的值，以及未找到文件的导入。它还会报告最近一个期间远离常态的指标，并指明造成变化的项。Weave 会考虑月末和工作日的规律，因此总在月末偏重的加载不会被报告。请参阅[异常指标总计](/zh-cn/guides/ai-assistant/weave-metric-insights/)。
  - **变慢的运行。** Weave 会指明使运行变慢的步骤，并报告较新运行比较早运行至少多花四分之一时间的工作流，指明耗时增长最多的步骤。
  - **在两次运行之间通知。** 每小时检查一次，通过应用内消息将每个问题通知其负责人一次，标题栏中的 **Weave** 按钮统计您在所有项目中尚未阅读的问题。请参阅[在两次运行之间收到通知](/zh-cn/guides/ai-assistant/weave-findings/#在两次运行之间收到通知)和[标题栏中的 Weave 按钮](/zh-cn/guides/ai-assistant/weave-tab/#标题栏中的-weave-按钮)。
  - **负责人、注释和预期的警告。** 每个发现项都有负责人，默认是最后运行其工作流的人。**分配**可将其移交，注释记录进展，**团队**视图显示谁负责什么。架构师可以将警告标记为**此为预期**，并附上原因和结束日期。请参阅[为发现项指定负责人](/zh-cn/guides/ai-assistant/weave-tab/#为发现项指定负责人)和[将发现项标记为预期](/zh-cn/guides/ai-assistant/weave-tab/#将发现项标记为预期)。

- **修复助手会解释错误，在卡片上提出您可批准的更改，重新运行步骤，并可撤消修复。** 对于最常见的故障，例如表中不存在的列、必填设置为空、数据库无法读取的 SQL，或类型错误的值，第一条回复会解释通常的原因及修复方法。提出的更改以卡片形式出现，说明步骤失败的原因，并显示每个更改的设置，当前值为红色，新值为绿色。**批准**会应用更改，助手随后会提出重新运行该步骤，并诊断新的故障。**Weave** 选项卡中发现项上的**修复**会针对该问题打开助手。**撤消**会恢复步骤之前的设置，**撤消并运行**则重建其输出。请参阅[使用 AI 修复工作流错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/)、[使用 AI 助手修复发现项](/zh-cn/guides/ai-assistant/weave-tab/#使用-ai-助手修复发现项)和[撤消修复](/zh-cn/guides/ai-assistant/fixing-workflow-errors/#撤消修复)。

- **查看 Weave 在项目中所做的一切，并导出供审计人员使用。** 项目 **Weave** 选项卡上的**活动**列出 Weave 发现并随后不再发现的问题、AI 助手提出的每项更改、谁请求以及谁批准或拒绝、它具体替换和写入了什么，以及结果如何。Weave 会在做出更改之前记录您的批准，并且不会做出无法记录的更改。**导出 CSV**或**导出 PDF**可将某个时间段保存为审计证据，条目无法编辑或删除。**摘要**一览一个月的情况：发现并已解决的问题、已批准的更改以及其中被撤消的数量。工作区管理员可通过**工作区摘要…** 获得每个项目的同样内容。请参阅 [Weave 活动历史记录](/zh-cn/guides/ai-assistant/weave-activity/)和 [Weave 月度摘要](/zh-cn/guides/ai-assistant/weave-monthly-summary/)。

- **在保存之前了解步骤的作用，以及更改它会影响什么。** 所有这些都根据项目已保存的设置构建，不涉及 AI，且您的角色所隐藏的任何内容都只计数，绝不指名。

  - **每个表、步骤和工作流的文档。** 详细信息面板中的**文档**部分描述哪些内容读取和写入表、步骤的作用，以及工作流中各步骤的顺序。**下载交接包**会将整个项目（包括指标定义和分摊模型）保存为一份文档。请参阅[表、步骤和工作流的文档](/zh-cn/guides/ai-assistant/weave-documentation/)。
  - **更改会影响什么。** 在**保存**上方，Weave 会说明有多少个下游步骤读取该步骤所写入的内容，例如“对此步骤的更改会影响 2 个工作流中的 8 个下游步骤”，**显示步骤**会列出它们。请参阅[更改会影响什么](/zh-cn/guides/ai-assistant/impact-preview/)。
  - **保存会拒绝什么。** **保存**上方的一个条带会在您编辑时运行步骤的检查，每个问题旁有**转到**，表达式编辑器会在您输入时检查表达式。请参阅[保存会拒绝什么](/zh-cn/guides/ai-assistant/check-while-you-edit/)。
  - **对单个工作流的审查。** 工作流画布或**步骤**网格上的**检查**会对其运行 Weave 的检查，以及分摊和行级安全检查。请参阅[审查单个工作流](/zh-cn/guides/ai-assistant/weave-findings/#审核一个工作流)。

- **为您的工作区关闭 Weave 的任何 AI 功能。** 工作区管理员在标题栏 **Weave** 按钮上选择 **AI 功能…**，即可分别开启或关闭 Weave 聊天、修复助手、导入和导出助手、表达式助手、根据描述生成 SQL、工作流审查摘要或初始图表。在管理员关闭之前，所有功能都是开启的，Weave 的检查和发现项始终保持开启，每项更改都会记录在安全日志中。请参阅 [AI 功能](/zh-cn/guides/ai-assistant/weave-ai-features/)。

- **在 Allocation Split 步骤上尝试驱动因素假设分析。** 右键点击该步骤并选择**假设分析…**，可查看它在不同的驱动因素值、其驱动因素表的另一列，或另一个具有相同键的表的数值列下会如何分摊其成本。最多可比较 10 个方案，每个方案都根据步骤的上次运行精确计算到分，并可查看谁受益、谁受损，以及哪些行将得不到任何分摊。**细分依据：** 显示每个成员的变化落在哪些科目或其他值上，**后续步骤**会将该方案延续到由分摊输出构建的表中。不会重新运行任何内容，也不会更改任何数据。请参阅[尝试驱动因素假设分析](/zh-cn/guides/allocations/results/driver-what-if/)。

- **将项目迁移到 Lakehouse v2 的过程从就绪状态到撤消都有指引。** **检查迁移就绪状态**会将表、视图、步骤、仪表板、数据共享和容量报告为畅通、需要审查或受阻，并对每个发现项附有通俗的说明。**在 v2 上试用…** 会创建一份私有的试用副本，其中计划关闭，ERP 过账处于模拟模式。可立即开始迁移，或在您选择的时间开始。迁移运行期间项目的计划会暂停，并在之后恢复，完成时会通过消息和电子邮件通知您。**变更内容…** 会报告每个表的结果，**撤消迁移…** 会在撤消期限内将项目恢复到 Lakehouse v1。请参阅[将项目迁移到 Lakehouse v2](/zh-cn/guides/data/migrate-project-lakehouse/)。

- **复制项目会复制其数据，并可选择复制多少。** **复制项目**提供**仅结构**、**完整数据**或**样本**，可在一个 Lakehouse 内，或从一个 Lakehouse 复制到另一个，并会先审查其大小和任何警告。带数据的副本仅对创建者私有。**复制结果**列出每个表的结果，**重试失败的表**只复制那些表，**查看导入或复制结果**可稍后重新打开该窗口。传感器和计划事件在副本上以关闭状态到达，因此在您于副本中开启之前不会触发任何内容。请参阅[复制项目](/zh-cn/guides/projects/managing-projects/#复制项目)。

## 变更

- **转到指标会打开 Weave 发现项所涉及的指标。** 它显示指标的数字，在您点击时计算并按您自己的行访问权限显示，并用 ✓ 标明数字所来自的版本。对于异常总计，是 Weave 指明的项在其判断期间的数据。对于任何其他指标发现项（包括由其他指标计算得出的指标），则是该指标的总计。数字下方的**转到行**仍会在表资源管理器中打开变化背后的行。请参阅[转到指标](/zh-cn/guides/ai-assistant/weave-metric-insights/#转到指标)。

- **一个 Weave 选项卡同时容纳您的发现项和 Weave AI 聊天。** 聊天是 **Weave** 选项卡内、**发现项**之后的选项卡。每个发现项是一张卡片，带有各自的**修复**、**转到**和**标记为已读**按钮，虚线卡片标记 Weave 无法检查的事项，筛选标签按需要关注的内容过滤列表。关于表达式的发现项会指明错误所在，表达式本身位于 **Weave 如何得知**下。运行结束时 Weave 对每个问题只提及一次，关于同一个项目的消息会合并为一条而不是堆叠。由于 Weave 只重新检查已更改的内容，该选项卡在大型项目中打开很快。工作流列表中的 Weave 列已移除。请参阅 [Weave 选项卡](/zh-cn/guides/ai-assistant/weave-tab/)和[运行结束时收到通知](/zh-cn/guides/ai-assistant/weave-findings/#在运行结束时收到通知)。

- **Ctrl/Cmd-K 可在任何屏幕打开命令面板。** 在您输入之前，它会列出您最近打开的内容和可执行的操作：转到主页、项目、仪表板或文档，在浅色和深色之间切换，连接您的 AI，或获取帮助。输入内容会缩小两个列表的范围，输入两个字符后还会搜索项目、工作流、表、仪表板和 Panel 应用。请参阅[搜索与命令](/zh-cn/guides/launcher/#搜索和命令)。

- **步骤在保存时发现问题，而不是在运行时。** 保存其设置会导致运行失败或给出错误结果的步骤时会被拒绝，并附有说明要更改什么的消息。每个步骤的参考页面会列出它检查的内容。已映射的源列如果步骤或其源表不再包含，会以红色标记，保存时会打开一个包含**全部移除并保存**、**仍然保存**或**取消**的对话框。联接、查找和空间步骤会原地保留此类行，而不是自行删除它们。使用未定义变量的表达式会指明该变量，运行时被拒绝的步骤会用通俗的语言解释原因。请参阅[不再列出的源列](/zh-cn/reference/workflow-steps/tables/table-extract/#不再列出的源列)、[源表中缺失的列](/zh-cn/reference/workflow-steps/tables/table-extract/#源表中缺少的列)和[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。

- **缺失或为空的源绝不是错误。** 文件缺失或为空的文件导入会以警告结束并指明路径，并使其目标表保持为空且保留其声明的列，因此后续步骤读取到零行。针对缺失或为空文件夹的 Document 步骤会报告“无需处理”，工作流继续运行。远程文件步骤在路径缺失时发出警告，并拒绝不安全的路径。检查文件缺失的功能适用于 OneDrive、SharePoint 和 SFTP。批处理表为空的**报表：批量生成**会以警告结束，且不生成任何报表。请参阅[导入步骤](/zh-cn/reference/workflow-steps/import/)、[Document 工作流步骤](/zh-cn/reference/workflow-steps/document/)和 [Document 路径条件](/zh-cn/guides/workflows/step-conditions/#文档路径条件)。

- **大型工作流可靠运行，且“停止”会取消导入和导出。** 当 PlaidCloud 繁忙时，步骤会等待容量而不是失败，并且随着步骤排队会增加容量。导入外部数据库表最多同时运行 10 个表。如果运行步骤的服务器丢失，替换其输出的步骤会自动再次运行，而无法安全重复的步骤会失败一次，并显示*已中断*消息。**停止**会取消正在运行的导入和导出作业，已停止的运行报告为已停止。请参阅[中断的步骤](/zh-cn/guides/workflows/run-a-workflow/#已中断的步骤)和[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)。

- **每个 Lakehouse 的存储和计算方式相同。** 来自导入 CSV、导入 XML 或 Import Table Archive 的空字段会作为空值加载，因此后续测试 `= ''` 或 `= 0` 的步骤需要改为测试空值。`cast(x, Float)` 在任何地方都是 64 位，因此大额金额会保留其位数，PlaidCloud 创建的 Float 列为双精度。JSON 列、**Table: Delete Rows** 和聚合条件在每个 Lakehouse 上都可使用。自行构建结果的步骤（如 Solver、Forecast，以及在 pandas 中运行的 Pivot 和 Allocation Split）会将结果作为带类型的数据加载，速度快得多。表资源管理器会显示数值列的最小值、最大值、平均值、总和、标准差和方差。请参阅[转换为 Float](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#转换为-float)和[列数据与非重复计数](/zh-cn/guides/data/table-explorer/#列数据和唯一值计数)。

- **文件导出保留其类型。** Parquet 文件将整数列保留为整数，以微秒存储时间戳，并将时区标记为 UTC。Avro 文件保留日期、时间戳和布尔值的类型，单表 Avro 导出以该导出命名。为 Parquet 导出选择多个文件时会停止并提示 Parquet 只写入单个文件。非常大的 Parquet、ORC 和 JSON 导出会在读取行的同时写入，因此不再耗尽内存，Parquet 使用您选择的压缩方式。版本 1.2.33 或更高版本的 PlaidLink 代理会以 Parquet 文件形式接收导出的表。请参阅 [Export to Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro](/zh-cn/reference/workflow-steps/export/export-to-avro/) 和[数据如何到达代理](/zh-cn/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#数据如何到达代理)。

- **ERP 过账遵循每个计划的模式，不确定的答复会被保留以待您检查。** 计划事件保留自己的过账模式（**实时**、**模拟**或**关闭**），受项目设置限制，**运行所选事件**使用每个事件的模式。PlaidCloud 无法确认的 ERP 答复（例如超时或服务器错误）会被保留为存疑而不是记录为被拒绝，并且一笔过账不能被冲销两次。过账登记簿会列出**待冲销**的过账，架构师可在项目主页的 **ERP 写入授权**中授权项目过账。请参阅 [ERP过账模式](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)、[冲销](/zh-cn/guides/connections/posting-register/#冲销)和[授权项目过账](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)。

- **行访问跟上分组变化，并说明问题所在。** 某人登录时由单点登录设置的分组成员资格，会在大约 15 分钟内到达仪表板的行访问，您默认分组的新成员会在大约一分钟内获得其行。当某个限制没有筛选掉任何内容时，**行访问**窗口会发出警告，可处理包含 `&`、`/` 或 `%` 的列名，并在同步失败时显示带原因的**错误**，或显示带**重试**按钮的**正在重试**。请参阅[使仪表板保持同步](/zh-cn/administration/access/managing-security-groups-and-assignments/#保持仪表板同步)。

- **用户定义函数在 Python 3.14 上运行，库也更新了。** 大多数函数无需更改即可运行。导入 numba 或 Python 已移除的标准库模块（如 `cgi` 或 `telnetlib`）的函数现在会失败，需要重写。Forecast 的 AutoTheta 界限可能与之前的运行略有不同。请参阅 [User Defined Transform](/zh-cn/reference/workflow-steps/general/user-defined-transform/)。

- **完全代理访问已弃用，并将于 2027年1月15日移除。** 使用**完整**访问的 LLM 步骤会记录警告。请改用**读取和写入**，此时代理通过 PlaidCloud 的写入工具更改数据，LLM 步骤只写入勾选了**写入**的绑定。请参阅[代理访问](/zh-cn/integrations/ai-architecture/llm-providers/#代理访问)。

- **文档账户更易设置和浏览。** OneDrive 或 SharePoint 账户的文件浏览器会打开其起始路径下的文件夹。Google Cloud Storage 账户需要有效的服务账户密钥，没有密钥的现有账户在您添加之前将停止工作。被拒绝的设置会自行说明原因，**管理账户**中未使用的备份图标已移除。请参阅[添加 Google Cloud Storage 账户](/zh-cn/guides/documents/adding-accounts/add-google-cloud-storage-account/)和[备份文档账户](/zh-cn/guides/documents/account-management/managing-document-account-backups/)。

- **Project 应用更完整地处理发票、行程和补报工时。** 新发票从主项目开始，主项目提供客户和采购订单号。删除发票草稿会使其工时和行程再次可计费，**AR 收件人**设置提交发票时向谁发送电子邮件。行程抽屉显示每一行的供应商、类别和审核状态，**添加补报工时**会为已批准的一周开启一张工时表。请参阅[使用 Project 应用跟踪时间和费用](/zh-cn/guides/time-expense/track-time-and-expenses/)。

- **已移除删除所有无步骤引用的表的 API 调用。** 请改为按 ID 删除表。

- **应用各处的小改动。** 双击账户、仪表板、成员、分组或设置列表中的某一行可将其打开。空的**维度**、**数据编辑器**、**UDF** 和**步骤**选项卡会说明下一步该做什么，没有应用的成员会进入 Launcher。步骤的表选择器会显示表上次更新的时间（[查看源表上次更改的时间](/zh-cn/guides/workflows/create-workflow/#查看源表最后一次更改的时间)）。导出外部数据库表在其自己的选项卡上映射列，**报表：批量生成**不再显示未使用的 **Report Constants** 部分。转换编码可识别中欧、土耳其和阿拉伯编码。指向已移除屏幕的链接会说明这一点。

## 已修复

- **AI 助手在您批准之前不会更改任何内容，并按原样显示名称。** 将步骤构建到新表中时，以前会在您批准之前就创建表；现在表和步骤会在您批准后一起创建，创建项目、工作流或维度、复制表，以及更改表的属性或标签也会先询问。批准只对您的下一条回复有效。助手提出的导入或导出会按名称显示其表、文档账户和工作流，并且绝不会与不存在或您无法打开的对象一起提供。带下划线的名称会如实显示而不再变成斜体，表和代码在深色主题下可读，图表会绘制而不是显示为文本，表达式编辑器的 Weave 面板会读取您正在编辑的表达式。即使某个表没有名称，助手也会列出项目的表；即使步骤读取或写入多个表，也能回答哪些步骤读取或写入某个表，而不是以错误停止。请参阅[构建工作流步骤](/zh-cn/guides/ai-assistant/weave-tab/#构建工作流步骤)。

- **文件导入读取您指向的内容。** 导入 Excel 可读取整列范围和 XLSB 工作簿，能在压缩的工作簿中找到工作表，并且不再因带有填充或换行的标头而失败。导入 CSV 遵循**跳过行数：**，因此标头上方有若干行的文件（例如 SAP 列表导出）可按列名导入，并使用默认的分隔符、引号和转义字符运行。一个源列可以为多个目标列提供数据，列全为固定值的导入会加载每一行，带有大写压缩扩展名的文件会被解压，未更改则跳过的导入会重新加载被清空的表。让 AI 助手从**项目默认**导入文件时，会读取项目的默认文档账户，并在项目没有设置时明确告知您。带有较新列类型的 Parquet 文件可在文档中打开。请参阅[导入 Excel](/zh-cn/reference/workflow-steps/import/import-excel/#读取内容)和[导入 CSV](/zh-cn/reference/workflow-steps/import/import-csv/#行选择)。

- **工作流步骤按配置保存和运行。** 表：Upsert 步骤可再次保存，其**更新键**列也恢复了。表：项目间复制会指明其目标项目，并通过数据共享读取。文档：将仪表板保存为 PDF 会保留其列类型，表：去重合并和表：全部合并按名称匹配列。多表联接可以保存多个输入，并接受带空格的列名。Table Lookup 会忽略其查找列上的聚合设置，SCD-2 截至日期联接可将变量作为其日期。LLM 步骤可在早于 4.6 的 Claude 模型上运行，并在 AI 助手编辑它们时保留其模型。REST 请求发送的行值只编码一次，导出到远程数据库会提交其行。请参阅[更新键](/zh-cn/reference/workflow-steps/tables/table-upsert/#更新键)、[数据共享管理](/zh-cn/reference/workflow-steps/tables/frame-project-copy/#数据共享管理)和[多表联接](/zh-cn/reference/workflow-steps/tables/table-multi-table-join/)。选择工作流的步骤（如 Workflow Delete、Copy、Rename 和 Stop）会保留已不存在的工作流，显示为 *id (missing)*，而不是切换到列表中的第一个工作流。

- **工作流运行按应有方式完成。** Worklow Loop 在每次迭代中运行循环的工作流，迭代容器以及在一次运行中多次运行的工作流也是如此。从某个步骤开始或在并行组内开始的运行会运行正确的步骤并完成。长时间运行的导入或导出绝不会被启动两次，不会在 PlaidCloud 更新期间停滞，以服务器错误结束的操作也不会被再次发送。数据库驱动程序崩溃只会使其自己的步骤失败，并附上数据库给出的原因。运行历史记录会统计每个步骤的行数，在工作开始前就失败的步骤会将原因写入工作流日志。请参阅 [Worklow Loop](/zh-cn/reference/workflow-steps/workflow-control/workflow-loop/) 和[运行历史记录](/zh-cn/guides/workflows/advanced-workflows/#运行历史)。

- **项目的复制、导入和打开不再出现意外。** 项目导入会保留其能够恢复的所有内容，并在**导入结果**窗口中列出遗漏的内容，显示进度，说明失败原因，并可重试。当项目有变量时，复制所选对象可正常工作。打开项目不再更改其设置，**导入您自己的数据**会导入您的 CSV，在 PostgreSQL 数据仓库上创建表也可正常工作。App Runner 应用会在 PlaidCloud 更新时自行刷新，并对限制行的项目上的查看者正常工作。请参阅[归档的部分内容未导入时](/zh-cn/guides/projects/archive-a-project/#归档的部分内容未能导入时)和[保持应用为最新](/zh-cn/guides/workflows/use-converted-alteryx-apps/#保持应用为最新)。

- **维度和分摊的加载与读取正确。** 父子加载会将父级为空的行保留为顶层成员，对于第二个备用层次结构，每种加载方式都会拒绝主层次结构之外的成员。将成员移到其层次结构不包含的父级之下会被拒绝，维度步骤会指明它找不到的维度，粘贴带空白的列会使每个值保留在其所在的行。读取大型维度不再拖慢工作区中的其他所有人。维度属性将**层次结构**保留为**未指定**的分摊规则可以运行。请参阅[加载到备用层次结构](/zh-cn/reference/workflow-steps/dimensions/dimension-load/#加载到备用层次结构)和[维度类型属性与成员选择器](/zh-cn/guides/dimensions/dimensions/#维度类型属性和成员选取器)。

- **工作流画布和屏幕表现正常。** **钻取到工作流**会在其画布上打开高级工作流，画布会打开每个工作流，并在布局的某一部分无法读取时告知您。放不下的工具栏按钮会移入**更多**菜单，列表会在保存后立即更新。通知显示其完整消息，警告在**日志**选项卡中显示警告图标，表资源管理器会说明列的概要分析何时失败，数据编辑器会让空的日期单元格保持为空。在开启列筛选器的情况下保存数据编辑器，会保留筛选器隐藏的行，包括在您添加、删除或移动行之后。允许更改用户定义函数的人可以在可编辑状态下打开其编辑器。请参阅[画布无法打开工作流时](/zh-cn/guides/workflows/advanced-workflows/#画布无法打开工作流时)。从**表**列表中删除表时，会列出仅通过变量路径（如 `/Periods/{period}/Sales`）访问某个表的任何步骤，并且只有在您强制时才会删除该表。请参阅[删除](/zh-cn/guides/projects/managing-tables-and-views/#删除)。

- **成员和连接按应有方式工作。** **添加工作区成员**对已有账户的人（包括通过单点登录创建的账户）有效，并且绝不会降低其已有的项目角色。ODBC 连接通过 PlaidLink 代理所在机器上的 DSN 或驱动程序连接。拒绝您的 OAuth 凭据的提供商会提示您重新输入或重新授权，Databricks 示例和导出会刷新即将过期的令牌，较旧数据库类型的连接可以删除。**使用位置**包括通知步骤，免费工作区保留每日、每周和每月备份。请参阅[成员管理](/zh-cn/administration/access/member-management/)和 [ODBC](/zh-cn/reference/connectors/databases/odbc/)。

- **REST API 和 AI 助手工具严格按您的要求执行。** 对成员、分组或计划事件的部分更新只更改您指定的字段，因此已暂停的事件保持暂停。在指定步骤开始运行就会从该步骤开始，恢复表快照会保留一份安全快照和一条审计记录。来自 AI 工具的驱动因素假设分析仅在与您的模型实际所做的拆分一致时才作答。以前因服务器错误而失败的请求现在要么可以运行，要么会说明问题所在。请参阅[追踪分摊](/zh-cn/integrations/ai-coding-agents/tracing-allocations/)和[还原或恢复快照](/zh-cn/guides/data/table-snapshots/#回退或还原快照)。

## 安全

- **AI 助手不会超出您的权限。** 助手的数据查询在运行前会按其结构检查，并且只运行单个读取查询。只读的 AI 连接（包括 Microsoft 365 Copilot）无法导出文件、保存仪表板 PDF、将行复制到另一个项目，或通过 REST 连接发送更改。通过 AI 助手进行的导入以您的身份在您指定的项目中运行，并且对话只能由发起它的人继续。助手和表引用会省略您的角色所隐藏的表、步骤、工作流和维度，Weave 会对您无法打开的失败步骤计数而不是指名。请参阅[访问级别](/zh-cn/integrations/microsoft-365-copilot/#访问级别)、[您的角色隐藏的内容](/zh-cn/guides/ai-assistant/weave-tab/#您的角色隐藏的内容)和[管理过往对话](/zh-cn/guides/ai-assistant/weave-tab/#管理过往对话)。

- **ERP 过账无法绕过其控制。** 开启职责分离后，冲销通过过账登记簿进行，其中适用批准。复制或导入的项目不再继承过账权限，SAP 和 EBS 过账无法直接发送到代理，处于仅测试模式的 SAP Post 步骤需要与实际过账相同的权限。一个不经这些检查就向 Sage Intacct 过账的未公开端点已被移除。ERP 和 REST 连接的错误消息会省略凭据。请参阅[职责分离](/zh-cn/guides/connections/posting-register/#职责分离)。

- **机密信息只写不读，且只有所有者决定谁可以使用连接。** 文档账户的密钥、密码和令牌一经保存便不再显示，更改账户的连接位置需要再次提供机密信息。步骤中的密码和密钥只存在于变量中；已输入到步骤中的机密信息已移入仅架构师可见的项目变量。多行凭据在您输入时会被掩码。只有连接的所有者或工作区管理员可以更改谁有权访问它。请参阅[已保存的机密信息只写不读](/zh-cn/guides/documents/adding-accounts/#已保存的机密为只写)、[密钥存放在变量中](/zh-cn/reference/workflow-steps/document/encrypt-decrypt-file/#密钥存放在变量中)和[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

- **您无法使用的文档账户对您保持关闭。** 检查文件是否存在、读取 Parquet、Avro、ORC 或 Delta 文件的列、使用**填充**填充导入步骤的列，以及 AI 助手的文件检查，现在都会拒绝您无权访问的账户，就像浏览该账户时一样。

- **只有工作区管理员才能更改工作区管理员。** 编辑、停用或删除管理员、更改其分组以及将某人设为管理员，都需要工作区管理员。请参阅[更改工作区管理员](/zh-cn/administration/access/member-management/#更改工作区管理员)。

- **数据共享只代表获授权的项目的成员。** 通过共享读取需要在接收项目中拥有角色，写入需要**写入**共享以及在那里拥有管理者或架构师角色。请参阅[在项目之间共享数据](/zh-cn/guides/projects/managing-projects/#在项目之间共享数据)。

- **恢复只应用于指定的项。** 恢复较早的版本会恢复项本身，权限检查针对的就是该项。内容不属于其自身标头中所指维度的维度备份文件会被拒绝。请参阅[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。

- **模板、导入和归档会拒绝不安全的内容。** 导出模板和报表模板在沙盒中渲染，只读取提供给它们的数据。导入根据自己的设置构建其加载查询，包含 PlaidCloud 归档从不含有的内容的项目归档会被拒绝，会与另一个项目共享报表架构的项目别名会被拒绝。请参阅[模板可以使用什么](/zh-cn/reference/workflow-steps/export/export-templated/#模板可以使用的内容)和[还原归档](/zh-cn/guides/projects/archive-a-project/#还原归档)。

- **仪表板遵循 PlaidCloud 登录和您的行访问。** 仪表板的缩略图以您的身份渲染，账户仅来自 PlaidCloud 登录，仪表板只能从导出所生成的 ZIP 文件导入。请参阅[导入现有仪表板](/zh-cn/guides/dashboards/learning-dashboard/#导入现有仪表板)。

- **启动工作流运行不再返回该运行的凭据。**

- **运行用户定义函数的环境不再包含 PySpark 的 Java 库，** 这些库存在已知漏洞。PySpark 的 DataFrame 和 SQL API 仍可访问您的 Spark 计算集群，但导入 `SparkContext` 或 `RDD` 的函数现在会失败。请参阅 [PySpark 入门](/zh-cn/integrations/pyspark/getting-started/)。

- **附件、恢复和转换只读取您可以使用的账户。** 通过电子邮件发送文件、从文件恢复维度或表归档、检查或导入表包、根据模板填充 Excel 导出，以及转换 Alteryx 工作流，现在都会拒绝您无权访问的文档账户。将维度备份到文档账户需要对其有写入权限。工作流步骤不受影响，只是通过电子邮件发送文件、恢复表或填充 Excel 模板的步骤不能再从个人临时驱动器读取。
