## 新增

- **Data Foundation 将您的 ERP 数据汇集到一个 Common Finance Model 中**。Common Finance Model 将来自多个 ERP 系统和实例的 ERP 数据汇集到单一模型中：一个会计科目表、一套实体和一种报告货币。基于它构建的报表、指标和 AI 助手读取的都是同一套数字，无论这些数字来自哪个 ERP。

  - **直接来自您的 ERP。** 总账、试算平衡表、主数据和预算通过 PlaidCloud 的 ERP 直接连接传入。**实体对照表**会将每个源的公司代码映射到相同的实体，文件则用于补充系统中没有的内容，例如汇率或分摊动因。
  - **一个模型，一种货币。** **加载**会将每个源整合到 Common Finance Model 中，并换算为您的报告货币：损益表按期间平均汇率，资产负债表按期末汇率，权益按历史汇率。层次结构由您的主数据构建。
  - **检查就绪状态。** 针对每个实体和期间运行检查：试算平衡表和销售额与总账核对一致，每个产品、客户和科目都已知，货币可以换算，每个实体都已映射。
  - **多个源，一个模型。** 添加、排序、编辑和移除源，每个源可以是 ERP 系统、实例或文件。**加载**会整合所有源，在重叠处保留一份副本，并记录被保留不加载的行及其原因，而 **Apply changes** 则无需再次从 ERP 拉取数据，即可重新运行整合。
  - **跨源映射代码。** 当多个源使用相同的代码时，系统会按名称匹配给出建议，询问它们是否表示同一事物；可以逐个代码回答，也可以使用 **Accept all**、**All the same** 或 **All different** 一次回答整组。映射按源和维度分别保存。最多十个额外类别会采用您为其指定的名称，覆盖范围视图则让您选择从哪个月起由哪个源计入。
  - **文件选项。** 文件可以只应用于一个源、提出它需要回答的问题、将一列拆分为多个字段、设置报告货币，或被移除。
  - **管理合并。** 每次加载都会构建集团损益表，也包括年初至今，集团内部交易在 **Eliminations** 实体上抵销，并设有 **Unmapped** 桶，以及与您的合并系统结果的对账。这是遵循项目行访问权限的管理视图，而不是法定合并。
  - **保持最新。** **每晚刷新**会在每天夜间重新加载模型，缺少或为空的文件会以警告而不是错误结束。

  从模板（例如 **Enterprise Profitability**）启动项目后，项目的**基础数据**选项卡会带您从已连接的 ERP 一路走到已加载并经过检查的模型。参见 [Data Foundation：Common Finance Model](/zh-cn/guides/projects/data-foundation/)。

- **在您自己的 Snowflake 或 Databricks 数据仓库上运行 PlaidCloud**。工作区管理员在用户菜单中打开**使用您自己的数据仓库**，并在自己的账户中运行生成的设置脚本。该脚本会创建一个有上限的仓库和一个供 PlaidCloud 使用的服务身份，绝不会触及您现有的仓库。**检查连接**会用通俗的语言解释任何问题及其解决方法。之后新项目会在您的仓库中存储表并运行工作流，移除该仓库会撤销 PlaidCloud 在其中的访问权限。参见[使用您自己的数据仓库](/zh-cn/guides/connections/external-lakehouse/)。

  - **使用 Snowflake 或 Databricks 登录。** 管理员无需粘贴凭据，可以通过登录来关联仓库。之后仪表板会以每个人自己的仓库权限运行，工作流则以仅持有您指定的数据角色的服务身份运行。参见[使用 Snowflake 或 Databricks 登录](/zh-cn/guides/connections/external-lakehouse/#使用-snowflake-或-databricks-登录)。
  - **连接多个仓库。** 在**管理数据仓库**中点击**设为默认**，可将新项目发送到另一个仓库，而现有项目保持不变。参见[管理仓库](/zh-cn/guides/connections/external-lakehouse/#管理数据仓库)。
  - **查看每次运行的成本。** 运行历史记录会为每次运行显示一个**仓库成本**列，以积分或 DBU 计。参见[每次运行的仓库成本](/zh-cn/guides/connections/external-lakehouse/#每次运行的仓库成本)。
  - **您的治理策略保持有效。** 说明会写入仓库自己的目录，并且当 PlaidCloud 替换、重新创建或克隆表时，Snowflake 的行访问策略和掩码策略，以及 Databricks 的行筛选器和列掩码都会保持关联。参见[您的策略和说明会延续](/zh-cn/guides/connections/external-lakehouse/#您的策略和说明会延续)。

- **在 PlaidCloud 内构建、发布和定制 Panel 应用的品牌。**

  - **Panel Studio。** **新建 Studio 应用**是**我的 Panel 应用**中的第一个按钮，可从空白应用、表、视图、另一个 Studio 应用或应用库开始；**表**选项卡上的**创建 Panel 应用**则从您选中的表开始。**在 Studio 中打开**会在编辑器中打开应用的文件。保存草稿，**预览**私有构建，并**发布**正式应用。构建错误会指向其所在的文件和行，**历史记录**可恢复任何已发布的版本，**洞察**则显示浏览量、加载时间和错误。**询问 Weave** 了解应用的文件和构建状态，并在保存任何代码之前向您显示完整的差异供您批准。参见 [Panel Studio](/zh-cn/guides/panel-apps/studio/) 和[使用 Weave 构建 Panel 应用](/zh-cn/guides/panel-apps/build-with-weave/)。
  - **外观与 PlaidCloud 一致的应用套件。** 使用该套件构建的应用在浅色和深色模式下都采用 PlaidCloud 的颜色、字体和间距。套件包含导航、筛选器、关键数字卡片、图表、表单、命令面板、运行工作流的按钮、打印功能，以及在服务器端排序和汇总、按列设置数字格式、每次加载一屏行数据的数据网格，因此可处理任意大小的表。应用以已登录查看者的身份读取表，并应用行级安全。参见 [Panel 应用套件](/zh-cn/guides/panel-apps/app-kit/)、[DataGrid](/zh-cn/guides/panel-apps/app-kit/#datagrid) 和 [Panel 应用的数据 API](/zh-cn/guides/panel-apps/data-api/)。
  - **提醒和摘要。** 当项目表中的某个数字越过限值时，通过推送通知、电子邮件、Slack 或 Microsoft Teams 获得通知，或获取最多包含 10 个数字的每日或每周摘要，始终遵循您自己的行访问权限。参见[提醒和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
  - **项目、品牌和共享。** 将应用分配给项目，分配前会检查哪些不在项目中的人可以打开它。项目**主页**选项卡上的**编辑品牌设置**可为项目中的每个应用设置八种品牌颜色和一个徽标。**应用库…** 会将属于某个项目的 Studio 应用作为模板，列给所有可以查看其项目的人，**从应用库中移除**则将其移除。参见[项目品牌设置和应用项目](/zh-cn/guides/panel-apps/branding/)和[应用库](/zh-cn/guides/panel-apps/gallery/)。

- **一次约定业务数字的计算方式，之后每个 AI 回答都使用该计算**。项目架构师定义一个**指标**，例如*净收入*或*人员数量*：它的源表、各行如何累加、始终计入的行、所联接的查找表，以及可用于细分的列。定义一经保存即生效，而指定了不存在的表或列，或者查找表中每个键对应多行的保存会被拒绝。按名称或同义词向 AI 助手询问该指标，数字将按定义在您自己的行访问权限下计算，而不是由助手自行推算。定义通过 AI 助手或 REST API 管理。参见[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。

  - **派生指标。** 定义两个指标的比率、总和或差，例如每 FTE 净收入，或某个指标乘以固定系数。参见[从其他指标派生指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#由其他指标派生指标)。
  - **比较、排名和占比。** 可询问相对预算的差异、保留并列项的前 N 名或后 N 名，或每行占总计的份额。参见[比较、排名和占比](/zh-cn/integrations/ai-coding-agents/metric-definitions/#比较排名和占比)。
  - **您的措辞，约定的值。** 将细分列绑定到维度后，像 *EMEA* 这样的词会变成其下的每个区域。未匹配到任何成员或匹配到多个成员的词，会作为候选项返回并向您确认，绝不猜测。参见[询问指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#询问指标)。
  - **财年时间。** 告诉指标其各行在您的财务日历中的位置，然后询问财务期间、年初至今、同比或环比。参见[随时间比较](/zh-cn/integrations/ai-coding-agents/metric-definitions/#随时间比较)。

  PlaidCloud 自己的 AI 助手会优先根据指标回答业务数字，并在带有 ✓ 标记的专属卡片中显示这些数字，该标记绝不会附在助手自己的文字上。参见[业务数字](/zh-cn/guides/ai-assistant/weave-tab/#业务数字)和[来自指标的数字](/zh-cn/guides/ai-assistant/weave-tab/#来自指标的数字)。

- **询问 Weave 是否已准备好结账，并检查两个表是否核对一致**。两者都不涉及 AI。

  - **结账就绪检查。** 在项目 **Weave** 选项卡的**就绪状态**中，将结账、预测或任何截止日期所依赖的工作流命名为一个**就绪集**。一份清单即可回答所有这些工作流的情况：“13 个中有 11 个已就绪；1 个未就绪；1 个无法检查。”只有当 Weave 能对某个工作流运行的每项检查都通过时，该工作流才算就绪，而 Weave 无法判断的任何内容都会显示为**无法检查**并附上原因，绝不会显示为已就绪。最后一次运行因之前的历史记录太少而无法与之比较（例如新工作流的情况），按正常情况计算。不写入任何表的步骤（例如发送电子邮件或导出文件的步骤）没有行或空值可检查，因此不会使工作流停在**无法检查**。参见[结账前检查就绪状态](/zh-cn/guides/ai-assistant/weave-readiness/)。
  - **对账。** 在您配对的键列上，逐行比较两个表，或同一个表的两个期间。Weave 会说明它们是否核对一致、相差多少以及哪些行不同，并且对于无法完整读取的数据，绝不会说“核对一致”。每项对账在使用前须由另一位架构师批准。参见[检查两个表是否核对一致](/zh-cn/guides/ai-assistant/weave-reconciliation/)。

- **Weave 监视更多可能出错的地方，并在两次运行之间通知您**。Weave 的检查不使用 AI。每个发现项以及 AI 助手的每个回答都有一个 **Weave 如何得知**面板：对于发现项，显示检查及其背后的值；对于回答，显示助手运行的每条查询，每个句子都标有**已匹配**、**未匹配**或**未检查**。参见 [Weave 目前检查的内容](/zh-cn/guides/ai-assistant/weave-findings/#weave-目前检查的内容)、[Weave 如何得知](/zh-cn/guides/ai-assistant/weave-findings/#weave-如何得知)和 [AI 助手中的 Weave 如何得知](/zh-cn/guides/ai-assistant/weave-tab/#weave-如何得知)。

  - **按时写入的表。** 当某个表自其计划到期以来一直未写入，或超过您在表详细信息的**时效性**下设置的时效阈值（1 小时到 180 天）未写入时，Weave 会报告。
  - **过时或损坏的输入。** Weave 会报告读取了另一个工作流此后写入的表的工作流，以及依赖失败运行的每个工作流和仪表板，包括图表基于 SQL 数据集构建的仪表板。**同步依赖项**会补上步骤与其所读取表之间缺失的连接器。参见[同步依赖项](/zh-cn/guides/workflows/sync-dependencies/)。
  - **数据形态发生变化。** Weave 会报告运行后取值分布大幅变化的小数列、开始多次写入行的联接、Extract 步骤因无法转换为列类型而留空的值，以及未找到任何文件的导入。它还会报告最新期间与常态相差很大的指标，并指出推动该变化的项目。Weave 会考虑月末和工作日的规律，因此总是在月末负载很重的加载不会被报告。参见[异常的指标总计](/zh-cn/guides/ai-assistant/weave-metric-insights/)。
  - **变慢的运行。** Weave 会指出使某次运行变慢的步骤，并报告较新运行耗时比较旧运行至少多四分之一的工作流，指出耗时增长最多的步骤。
  - **在两次运行之间通知。** 每小时一次的检查会通过应用内消息，将每个问题通知其负责人一次，页眉中的 **Weave** 按钮会统计您所有项目中尚未读取的问题数。参见[在两次运行之间获得通知](/zh-cn/guides/ai-assistant/weave-findings/#两次运行之间收到通知)和[页眉中的 Weave 按钮](/zh-cn/guides/ai-assistant/weave-tab/#标题栏中的-weave-按钮)。
  - **负责人、评论和预期警告。** 每个发现项都有一位负责人，默认是最后运行其工作流的人。**分配**可将其转交给他人，评论记录进展，**团队**视图显示谁负责什么。架构师可将警告标记为**此为预期**，并附上原因和结束日期。参见[为发现项指定负责人](/zh-cn/guides/ai-assistant/weave-tab/#为发现项指定负责人)和[将发现项标记为预期](/zh-cn/guides/ai-assistant/weave-tab/#将发现项标记为预期)。

- **修复助手会解释错误，提出一项您可在卡片上批准的更改，重新运行步骤，并可撤消修复**。对于最常见的失败，例如列不在表中、必填设置为空、数据库无法读取的 SQL 或类型错误的值，第一条回复会解释常见原因及修复方法。提出的更改以卡片形式出现，卡片说明步骤失败的原因，并显示每个更改的设置，当前值为红色，新值为绿色。**批准**会应用更改，之后助手会提议重新运行该步骤，并诊断新出现的失败。**Weave** 选项卡中发现项上的**修复**会针对该问题打开助手。**撤消**会恢复步骤之前的设置，**撤消并运行**可重新构建其输出。参见[使用 AI 修复工作流错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/)、[使用 AI 助手修复发现项](/zh-cn/guides/ai-assistant/weave-tab/#使用-ai-助手修复发现项)和[撤消修复](/zh-cn/guides/ai-assistant/fixing-workflow-errors/#撤消修复)。

- **查看 Weave 在项目中所做的一切，并导出供审计人员使用**。项目 **Weave** 选项卡上的**活动**会列出 Weave 发现并后来不再发现的问题、AI 助手提出的每项更改、谁请求以及谁批准或拒绝了它、它替换和写入的确切内容，以及最终的结果。Weave 会在进行更改之前记录您的批准，并且不会进行无法记录的更改。**导出 CSV** 或**导出 PDF** 可将一个时间段保存为审计证据，条目不能被编辑或删除。**摘要**一目了然地显示一个月的情况：发现和解决的问题、已批准的更改以及其中有多少被撤消。工作区管理员可从**工作区摘要…** 获得每个项目的同样内容。参见 [Weave 活动历史记录](/zh-cn/guides/ai-assistant/weave-activity/)和 [Weave 月度摘要](/zh-cn/guides/ai-assistant/weave-monthly-summary/)。

- **在保存之前，了解步骤的作用以及更改它会影响什么**。所有这些都基于您项目已保存的设置构建，不涉及 AI，并且您的角色所隐藏的内容只会被计数，绝不会被指名。

  - **每个步骤和工作流的文档，以及每个表的列。** 详细信息面板中的**文档**部分描述步骤的作用以及工作流中各步骤的顺序，而哪些内容读取和写入某个表，则可供 Weave 和 AI 助手使用。表的详细信息面板会列出其**列**及其类型和说明。**下载交接包**会将整个项目（包括指标定义和分摊模型）保存为一个文档。参见[表、步骤和工作流的文档](/zh-cn/guides/ai-assistant/weave-documentation/)。
  - **更改会影响什么。** 在**保存**上方，Weave 会说明有多少下游步骤读取该步骤写入的内容，例如“对此步骤的更改会影响 2 个工作流中的 8 个下游步骤”，**显示步骤**会列出这些步骤。参见[更改会影响什么](/zh-cn/guides/ai-assistant/impact-preview/)。
  - **保存会拒绝什么。** **保存**上方的一个条带会在您编辑时运行该步骤的检查，每个问题都有**转到**，并且表达式编辑器会在您输入时检查表达式。参见[保存会拒绝什么](/zh-cn/guides/ai-assistant/check-while-you-edit/)。
  - **对单个工作流的审查。** 工作流画布或**步骤**网格上的**检查**会对其运行 Weave 的检查，外加分摊和行级安全检查。参见[审查单个工作流](/zh-cn/guides/ai-assistant/weave-findings/#审核单个工作流)。

- **为您的工作区关闭 Weave 的任何 AI 功能**。工作区管理员可在页眉 **Weave** 按钮上选择 **AI 功能…**，分别开启或关闭 Weave 聊天、修复助手、导入和导出助手、表达式助手、根据描述生成 SQL、工作流审查摘要或入门图表。在管理员关闭之前，所有功能均为开启状态，Weave 的检查和发现项始终保持开启，每项更改都会记录在**安全日志**中。参见 [AI 功能](/zh-cn/guides/ai-assistant/weave-ai-features/)。

- **更直接地排列和编辑高级工作流画布**。按住 **Cmd** 或 **Ctrl** 并拖动步骤，可将其移入或移出容器，并可从执行容器的**出口端口**连接其输出。**排列**菜单可整理、对齐、分布并吸附步骤，同时保持您的顺序并让注释随其步骤移动，每种操作都可作为一次**撤消**。右键单击空白处，可在您单击的位置复制和粘贴步骤。所选步骤上的**创建步骤**会从其写入的表开始创建联接或提取，包含未保存更改的窗口在丢弃前会询问。步骤输入或输出上的眼睛图标会打开恰好该表的预览。参见[容器](/zh-cn/guides/workflows/advanced-workflows/#容器)、[排列画布](/zh-cn/guides/workflows/advanced-workflows/#排列画布)、[在高级画布上复制和粘贴](/zh-cn/guides/workflows/copy-paste-steps/#在高级画布上复制和粘贴)和[创建步骤](/zh-cn/guides/workflows/workflow-explorer/#创建步骤)。

- **优化高级工作流以更快运行**。右键单击工作流并选择**优化…**，可在任何更改发生之前进行审查。**Rebuild dependencies from data lineage** 只将每个步骤与其所用表对应的步骤连接，因此相互独立的步骤可并行运行，**Merge** 会将一连串 Extract Data 步骤合并为一个，并且仅在两个版本对您当前数据给出相同结果后才会应用。窗口会显示节省的时间，并列出无法优化的每个步骤及其原因，**撤消优化…** 可恢复该工作流。参见[优化工作流](/zh-cn/guides/workflows/optimize-a-workflow/)。

- **在运行之前确认联接的键正确无误**。**Join Map** 上的**推测**会先使用联接相同两个表的另一个步骤的键，然后是指标，再是表的键列，最后是匹配的名称，并说明所用的是哪一种。**检查键**会统计被联接的表中重复出现的键值，这些重复值可能使您的行数成倍增加。当**检查源**填充步骤的列时，诸如 `customer_id` 之类的标识符列起初为**分组依据**而不是**求和**。参见[内联接](/zh-cn/reference/workflow-steps/tables/table-inner-join/#检查键)。

- **AI 助手和 Microsoft 365 Copilot 更了解您的数据，也能用它做更多事情**。

  - **每个分析路径和列的指导说明。** 每个分析路径都有**提示指引**（最多 1,000 个字符），用于始终适用的筛选器、财务日历和您的业务术语。列备注会与表的列一起提供给助手和 LLM 步骤，使代码或标志按您的本意被理解。参见[让路径对 AI 助手有用](/zh-cn/integrations/ai-coding-agents/analysis-paths/#让路径对-ai-助手更有用)。
  - **Copilot 能做更多。** Microsoft 365 Copilot 中的 PlaidCloud 代理可以创建 CSV、Excel、PowerPoint 和 Word 文件，根据您的指标回答业务数字，对整个表的细分进行汇总，并解释分摊的工作原理。管理员下载更新后的包，并在 Teams 管理中心更新它。参见 [Microsoft 365 Copilot](/zh-cn/integrations/microsoft-365-copilot/)。
  - **一次调用完成更多。** 助手可以在服务器端对表进行分组和汇总（先应用行访问权限），搜索和阅读 PlaidCloud 的文档，创建配置完整的文档账户（包括 OneDrive 和 SharePoint）并使用只写凭据，除添加标签外还可移除标签，并可处理您在 PlaidCloud 中看到的视图。参见[分析路径](/zh-cn/integrations/ai-coding-agents/analysis-paths/#通过-mcp-使用)和 [AI 代理入门](/zh-cn/integrations/ai-coding-agents/getting-started/)。

## 变更

- **Go To Metric 会打开 Weave 发现项所涉及的指标**。它会显示该指标的数字，这些数字在您单击时计算并遵循您自己的行访问权限，并带有一个 ✓，标明它们来自哪个版本。对于异常的总计，显示的是 Weave 在其判断的期间内指出的那个项目。对于任何其他指标发现项（包括针对由其他指标计算得出的指标的发现项），显示的是该指标的总计。数字下方的**转到行**仍会在表资源管理器中打开发生变化背后的行。参见 [Go To Metric](/zh-cn/guides/ai-assistant/weave-metric-insights/#转到指标)。

- **一个 Weave 选项卡同时容纳您的发现项和 Weave AI 聊天**。聊天是 **Weave** 选项卡内位于**发现项**之后的选项卡。每个发现项都是一张卡片，带有自己的**修复**、**转到**和**标记为已读**按钮，虚线卡片标记 Weave 无法检查的内容，并且可用标签筛选需要关注的内容。关于表达式的发现项会指出错误所在的位置，表达式本身位于 **Weave 如何得知**之下。运行结束时 Weave 对每个问题只提及一次，并且关于同一项目的消息会合并为一条，而不是堆叠。该选项卡在大型项目中打开很快，因为 Weave 只重新检查已更改的内容。工作流列表中的 Weave 列已移除。参见 [Weave 选项卡](/zh-cn/guides/ai-assistant/weave-tab/)和[在运行结束时获得通知](/zh-cn/guides/ai-assistant/weave-findings/#运行结束时收到通知)。

- **Ctrl/Cmd-K 可在任何屏幕上打开命令面板**。在您输入之前，它会列出您最近打开的内容和您可以执行的操作：前往主页、项目、仪表板或文档，在浅色和深色之间切换，连接您的 AI，或获取帮助。输入内容会缩小两个列表的范围，输入两个字符后还会搜索项目、工作流、表、仪表板和 Panel 应用。参见[搜索和命令](/zh-cn/guides/launcher/#搜索和命令)。

- **步骤在您保存时而不是运行时发现问题**。保存其设置会导致运行失败或给出错误结果的步骤会被拒绝，并附带说明需要更改什么的消息。每个步骤的参考页面都列出了它所检查的内容。步骤或其源表已不再具有的已映射源列会以红色标出，保存时会打开一个包含**全部移除并保存**、**仍然保存**或**取消**的对话框。联接、查找和空间步骤会将这些行保留在原位，而不是自行删除。使用未定义变量的表达式会指出该变量的名称，运行时被拒绝的步骤会用通俗的语言解释原因。参见[不再列出的源列](/zh-cn/reference/workflow-steps/tables/table-extract/#不再列出的源列)、[源表中缺少的列](/zh-cn/reference/workflow-steps/tables/table-extract/#源表中缺少的列)和[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。

- **缺少或为空的源绝不是错误**。文件缺少或为空的文件导入会以警告结束并指出路径，同时使其目标表保持为空并带有其声明的列，因此后续步骤读取零行。针对缺少或为空的文件夹的文档步骤会报告“Nothing to process”，工作流继续运行。远程文件步骤在路径缺失时发出警告，并拒绝不安全的路径。对缺少文件的检查适用于 OneDrive、SharePoint 和 SFTP。批次表为空的**报表：批量生成**会以警告结束，且不生成任何报表。参见[导入步骤](/zh-cn/reference/workflow-steps/import/)、[文档工作流步骤](/zh-cn/reference/workflow-steps/document/)和[文档路径条件](/zh-cn/guides/workflows/step-conditions/#文档路径条件)。

- **大型工作流可靠运行，并且“停止”会取消导入和导出**。当 PlaidCloud 繁忙时，步骤会等待容量而不是失败，并且随着步骤排队会增加容量。导入外部数据库表最多同时运行 10 个表。如果运行某个步骤的服务器丢失，替换其输出的步骤会自动重新运行，而无法安全重复的步骤会失败一次并给出 *interrupted* 消息。**停止**会取消正在运行的导入和导出作业，已停止的运行会报告 Stopped。参见[中断的步骤](/zh-cn/guides/workflows/run-a-workflow/#已中断的步骤)和[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)。

- **每个 Lakehouse 的存储和计算方式都相同**。来自导入 CSV、导入 XML 或 Import Table Archive 步骤的空字段会作为 null 加载，因此之后测试 `= ''` 或 `= 0` 的步骤需要改为测试 null。`cast(x, Float)` 在所有位置都是 64 位，因此大额金额会保留其位数，PlaidCloud 创建的 Float 列为双精度。JSON 列、**Table: Delete Rows** 以及进行聚合的条件在每个 Lakehouse 上都可使用。自行构建结果的步骤（例如求解器、预测，以及在 pandas 中运行的 Pivot 和 Allocation Split）会将结果作为带类型的数据加载，速度快得多。表资源管理器会显示数值列的最小值、最大值、平均值、总和、标准差和方差。参见[转换为 Float](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#转换为-float)和[列数据和唯一值计数](/zh-cn/guides/data/table-explorer/#列数据和唯一值计数)。

- **文件导出保持其类型**。Parquet 文件会将整数列保持为整数，以微秒存储时间戳，并将时区标记为 UTC。Avro 文件会保持日期、时间戳和布尔值的类型，单表 Avro 导出以该导出命名。为 Parquet 导出选择多个文件时会停止并提示 Parquet 只写入单个文件。非常大的 Parquet、ORC 和 JSON 导出会在读取行的同时写入，因此不再耗尽内存，并且 Parquet 使用您选择的压缩方式。版本 1.2.33 或更高版本的 PlaidLink 代理会以 Parquet 文件接收导出的表。参见 [Export to Parquet 步骤](/zh-cn/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro 步骤](/zh-cn/reference/workflow-steps/export/export-to-avro/)和[数据如何到达代理](/zh-cn/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#数据如何到达代理)。

- **ERP 过账遵循每个计划的模式，不确定的回复会被保留供您检查**。计划事件保留其自己的过账模式（**实时**、**模拟**或**关闭**），受项目设置的限制，而**运行所选事件**使用每个事件的模式。PlaidCloud 无法确认的 ERP 回复（例如超时或服务器错误）会被保留为存疑，而不是记录为被拒绝，并且一项过账不能被冲销两次。过账登记簿会列出 **reversal outstanding** 过账，架构师可在项目主页的 **ERP 写入授权**中授权项目过账。参见 [ERP过账模式](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)、[冲销](/zh-cn/guides/connections/posting-register/#冲销)和[授权项目过账](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)。

- **行访问跟上分组变化，并说明哪里有问题**。单点登录在某人登录时设置的分组成员资格，大约在 15 分钟内即可应用到仪表板行访问，而默认分组的新成员大约在一分钟内即可获得其行。行访问窗口会在某项限制没有筛选任何内容时发出警告，可处理包含 `&`、`/` 或 `%` 的列名，并在同步失败时显示带原因的**错误**，或显示带**重试**按钮的**正在重试**。参见[保持仪表板同步](/zh-cn/administration/access/managing-security-groups-and-assignments/#保持仪表板同步)。

- **用户定义函数在 Python 3.14 上运行，并使用更新的库**。大多数函数无需更改即可运行。导入 numba 的函数，或导入 Python 已移除的标准库模块（例如 `cgi` 或 `telnetlib`）的函数，现在会失败，需要重写。预测的 AutoTheta 边界可能与之前的运行略有不同。参见 [User Defined Transform 步骤](/zh-cn/reference/workflow-steps/general/user-defined-transform/)。

- **完整代理访问已弃用，将于 2027 年 1 月 15 日移除**。使用**完整**访问权限的 LLM 步骤会记录一条警告。请改用**读取和写入**，在该模式下代理通过 PlaidCloud 的写入工具更改数据，而 LLM 步骤只会写入勾选了**写入**的绑定。参见[代理访问](/zh-cn/integrations/ai-architecture/llm-providers/#代理访问)。

- **文档账户更易于设置和浏览**。OneDrive 或 SharePoint 账户的文件浏览器会打开其起始路径下的文件夹。Google Cloud Storage 账户需要有效的服务账户密钥，没有密钥的现有账户在您添加之前将停止工作。被拒绝的设置会自行说明原因，**管理账户**中未使用的备份图标已移除。参见[添加 Google Cloud Storage 账户](/zh-cn/guides/documents/adding-accounts/add-google-cloud-storage-account/)和[备份文档账户](/zh-cn/guides/documents/account-management/managing-document-account-backups/)。

- **Project 应用更完整地处理发票、行程和补报工时**。新发票从主项目开始，主项目提供客户和采购订单号。删除草稿发票会使其工时和行程重新可计费，**AR 收件人**设置提交发票时向谁发送电子邮件。行程抽屉会显示每一行的供应商、类别和审计状态，**添加补报工时**会为已批准的周开始一张工时表。参见[使用 Project 应用跟踪工时和费用](/zh-cn/guides/time-expense/track-time-and-expenses/)。

- **删除所有未被任何步骤引用的表的 API 调用已移除**。请改为按 ID 删除表。

- **应用中的其他小更改**。双击账户、仪表板、成员、分组或设置列表中的某一行即可打开它。空的**维度**、**数据编辑器**、**UDF** 和**步骤**选项卡会说明下一步该做什么，没有应用的成员会进入启动台。步骤的表选择器会显示表的最后更新时间（[查看源表的最后更改时间](/zh-cn/guides/workflows/create-workflow/#查看源表最后一次更改的时间)）。导出外部数据库表在其自己的选项卡上映射列，**报表：批量生成**不再显示未使用的 **Report Constants** 部分。Convert Encoding 步骤可识别中欧、土耳其和阿拉伯编码。指向已移除屏幕的链接会说明这一点。

## 已修复

- **AI 助手在您批准之前不会更改任何内容，并按原样显示名称**。将步骤构建到新表中时，表在您批准之前就已创建；现在表和步骤会在您批准之后一起创建，并且创建项目、工作流或维度、复制表，以及更改表属性或标签也会先征求您的意见。批准仅对您的下一条回复有效。助手提出的导入或导出会按名称显示其表、文档账户和工作流，并且绝不会与不存在或您无法打开的对象一起提供。包含下划线的名称会如实显示，而不是变成斜体；表和代码在深色主题下可读；图表会被绘制出来，而不是显示为文本；表达式编辑器的 Weave 面板会读取您正在编辑的表达式。即使某个表没有名称，助手也会列出项目的表；即使某个步骤读取或写入多个表，助手也能回答哪些步骤读取或写入某个表，而不是因错误而停止。参见[构建工作流步骤](/zh-cn/guides/ai-assistant/weave-tab/#构建工作流步骤)。

- **文件导入会读取您指向的内容**。导入 Excel 可读取整列范围和 XLSB 工作簿，可在压缩的工作簿中找到工作表，并且不再因带有填充或换行的标题而失败。导入 CSV 遵循**跳过行数**，因此标题上方有若干行的文件（例如 SAP 列表导出）可按列名导入，并使用默认的分隔符、引号和转义字符运行。一个源列可以向多个目标列提供数据，所有列均为固定值的导入会加载每一行，以大写压缩扩展名命名的文件会被解压，而在未更改时跳过的导入会重新加载已被清空的表。要求 AI 助手从**项目默认值**导入文件时，会读取项目的默认文档账户，并在项目没有设置默认账户时明确告知您。具有较新列类型的 Parquet 文件可在文档中打开。参见[导入 Excel](/zh-cn/reference/workflow-steps/import/import-excel/#读取内容)和[导入 CSV](/zh-cn/reference/workflow-steps/import/import-csv/#行选择)。

- **工作流步骤按配置保存和运行**。表：Upsert 步骤可以再次保存，其**更新键**列也已恢复。表：项目间复制步骤会指定其目标项目，并可通过数据共享读取。文档：将仪表板保存为 PDF 会保持其列类型，表：去重合并和表：全部合并按名称匹配列。多表联接可保存多个输入，并接受包含空格的列名。Table Lookup 步骤会忽略其查找列上的聚合设置，SCD-2 截至日期联接可将变量作为日期。LLM 步骤可在早于 4.6 的 Claude 模型上运行，并在 AI 助手编辑它们时保留其模型。REST 请求发送的行值只编码一次，导出到远程数据库的行会被提交。参见[更新键](/zh-cn/reference/workflow-steps/tables/table-upsert/#更新键)、[数据共享管理](/zh-cn/reference/workflow-steps/tables/frame-project-copy/#数据共享管理)和[多表联接](/zh-cn/reference/workflow-steps/tables/table-multi-table-join/)。选择工作流的步骤（例如删除工作流、复制工作流、重命名工作流和停止工作流）会保留已不存在的工作流并显示为 *id (missing)*，而不是切换到列表中的第一个工作流。

- **工作流运行按应有方式完成**。Workflow Loop 会在每次迭代时运行循环的工作流，迭代容器以及在一次运行中多次运行的工作流也是如此。从某个步骤或并行组内部开始的运行会运行正确的步骤并完成。长时间运行的导入或导出绝不会启动两次，也不会在 PlaidCloud 更新期间停滞，并且以服务器错误结束的操作不会被重复发送。数据库驱动程序崩溃只会使其自己的步骤失败，并附带数据库给出的原因。运行历史记录会统计每个步骤的行数，在工作开始之前就失败的步骤会将原因写入工作流日志。参见 [Workflow Loop 步骤](/zh-cn/reference/workflow-steps/workflow-control/workflow-loop/)和[运行历史记录](/zh-cn/guides/workflows/advanced-workflows/#运行历史)。

- **项目的复制、导入和打开不再出现意外**。项目导入会保留其能够恢复的所有内容，并在**导入结果**窗口中列出所遗漏的内容，显示其进度，说明失败的原因，并且可以重试。当项目有变量时，复制所选对象可以正常工作。打开项目不再更改其设置，**导入您自己的数据**会导入您的 CSV，并且在 PostgreSQL 仓库上创建表可以正常工作。App Runner 应用会在 PlaidCloud 更新时自动刷新，并对限制行的项目上的查看者正常工作。参见[归档的一部分未导入时](/zh-cn/guides/projects/archive-a-project/#归档的部分内容未能导入时)和[保持应用为最新](/zh-cn/guides/workflows/use-converted-alteryx-apps/#保持应用为最新)。

- **维度和分摊可以正确加载和读取**。父子加载会将父级为空的行保留为顶级成员，并且在每种加载中，对第二个备用层次结构，主层次结构之外的成员都会被拒绝。将成员移到其层次结构不包含的父级之下会被拒绝，维度步骤会指出它找不到的维度，并且粘贴包含空白的列会使每个值保持在其所在行。读取大型维度不再拖累工作区中的其他所有人。其维度属性将**层次结构**保留为**未指定**的分摊规则可以运行。参见[加载到备用层次结构](/zh-cn/reference/workflow-steps/dimensions/dimension-load/#加载到备用层次结构)和[维度类型属性和成员选择器](/zh-cn/guides/dimensions/dimensions/#维度类型属性和成员选取器)。

- **工作流画布和屏幕表现正常**。**钻取到工作流**会在其画布上打开高级工作流，并且画布可打开每个工作流，在无法读取部分布局时告知您。放不下的工具栏按钮会移到**更多**菜单中，列表会在您保存后立即更新。通知会显示其完整消息，警告在**日志**选项卡中显示警告图标，表资源管理器会在某列的概要分析失败时说明，数据编辑器会让空的日期单元格保持为空。在启用列筛选器的情况下保存数据编辑器，会保留筛选器隐藏的行，包括在您添加、删除或移动行之后。允许更改用户定义函数的任何人都可以在可编辑状态下打开其编辑器。参见[当画布无法打开工作流时](/zh-cn/guides/workflows/advanced-workflows/#画布无法打开工作流时)。从**表**列表中删除表时，会列出仅通过变量路径（例如 `/Periods/{period}/Sales`）到达某个表的任何步骤，并且只有在您强制删除时才会删除该表。参见[删除](/zh-cn/guides/projects/managing-tables-and-views/#删除)。

- **成员和连接按应有方式工作**。**添加工作区成员**对已有账户的人（包括通过单点登录创建的账户）有效，并且绝不会降低其已持有的项目角色。ODBC 连接通过 PlaidLink 代理所在计算机上的 DSN 或驱动程序进行连接。拒绝您的 OAuth 凭据的提供商会提示您重新输入或重新授权，Databricks 样本和导出会刷新即将过期的令牌，并且较旧数据库类型的连接可以删除。**使用位置**包含通知步骤，免费工作区保留每日、每周和每月备份。参见[成员管理](/zh-cn/administration/access/member-management/)和 [ODBC](/zh-cn/reference/connectors/databases/odbc/)。

- **REST API 和 AI 助手工具会完全按您的要求执行**。对成员、分组或计划事件的部分更新只更改您指定的字段，因此已暂停的事件保持暂停。从指定步骤开始运行会从该步骤启动，恢复表快照会保留一个安全快照和一条审计记录。AI 工具中的驱动因素假设分析仅在与您的模型实际做出的拆分一致时才作答。过去会因服务器错误而失败的请求，现在要么可以正常工作，要么会说明出了什么问题。参见[追踪分摊](/zh-cn/integrations/ai-coding-agents/tracing-allocations/)和[还原或恢复快照](/zh-cn/guides/data/table-snapshots/#回退或还原快照)。

## 安全

- **AI 助手保持在您的权限范围内**。助手的数据查询在运行前会按其结构进行检查，并且只运行单条读取查询。只读的 AI 连接（包括 Microsoft 365 Copilot）无法导出文件、保存仪表板 PDF、将行复制到另一个项目，或通过 REST 连接发送更改。通过 AI 助手进行的导入会以您的身份在您指定的项目中运行，并且对话只能由发起者继续。助手和表引用会省略您的角色所隐藏的表、步骤、工作流和维度，而 Weave 会统计您无法打开的失败步骤，而不是指出其名称。参见[访问级别](/zh-cn/integrations/microsoft-365-copilot/#访问级别)、[您的角色隐藏了什么](/zh-cn/guides/ai-assistant/weave-tab/#您的角色隐藏的内容)和[管理过去的对话](/zh-cn/guides/ai-assistant/weave-tab/#管理过往对话)。

- **ERP 过账无法绕过其控制**。启用职责分离后，冲销会通过过账登记簿进行，并适用审批。复制或导入的项目不再继承过账权限，SAP 和 EBS 过账无法直接发送给代理，并且处于 Test Only Mode 的 SAP Post 步骤需要与实时过账相同的权限。一个未记录在案、不经这些检查就向 Sage Intacct 过账的端点已被移除。来自 ERP 和 REST 连接的错误消息会省略凭据。参见[职责分离](/zh-cn/guides/connections/posting-register/#职责分离)。

- **密钥为只写，只有所有者决定谁可使用连接**。文档账户的密钥、密码和令牌在保存后不再显示，更改账户的连接位置需要重新提供密钥。步骤中的密码和密钥只保存在变量中；已键入步骤中的密钥已移入仅架构师可见的项目变量。多行凭据在您输入时会被屏蔽。只有连接的所有者或工作区管理员才能更改谁有权访问它。参见[已保存的密钥为只写](/zh-cn/guides/documents/adding-accounts/#已保存的机密为只写)、[密钥保存在变量中](/zh-cn/reference/workflow-steps/document/encrypt-decrypt-file/#密钥存放在变量中)和[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

- **您无法使用的文档账户对您保持关闭**。检查文件是否存在、读取 Parquet、Avro、ORC 或 Delta 文件的列、使用**填充**填充导入步骤的列，以及 AI 助手的文件检查，现在都会拒绝您无权访问的账户，就像浏览该账户时一样。

- **只有工作区管理员才能更改工作区管理员**。编辑、停用或删除管理员、更改其分组，以及将某人设为管理员，都需要工作区管理员。参见[更改工作区管理员](/zh-cn/administration/access/member-management/#更改工作区管理员)。

- **数据共享只代表被授予该共享的项目的成员**。通过共享读取需要在接收项目中拥有角色，写入则需要**写入**共享以及在该项目中的管理者或架构师角色。参见[在项目之间共享数据](/zh-cn/guides/projects/managing-projects/#在项目之间共享数据)。

- **恢复只应用于所指定的项目**。恢复早期版本会恢复项目本身，权限检查针对该项目。其内容不属于其自身标头中所列维度的维度备份文件会被拒绝。参见[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。

- **模板、导入和归档会拒绝不安全的内容**。导出模板和报表模板在沙盒中渲染，只读取提供给它们的数据。导入会根据其自身的设置构建其加载查询，包含 PlaidCloud 归档从不包含的内容的项目归档会被拒绝，并且会与另一个项目共享其报告架构的项目标识会被拒绝。参见[模板可以使用什么](/zh-cn/reference/workflow-steps/export/export-templated/#模板可以使用的内容)和[还原归档](/zh-cn/guides/projects/archive-a-project/#还原归档)。

- **仪表板遵循 PlaidCloud 登录和您的行访问权限**。仪表板的缩略图以您的身份渲染，账户仅来自 PlaidCloud 登录，并且仪表板只能从导出所生成的 ZIP 文件导入。参见[导入现有仪表板](/zh-cn/guides/dashboards/learning-dashboard/#导入现有仪表板)。

- **启动工作流运行不再返回该运行的凭据**。

- **运行用户定义函数的环境不再包含 PySpark 的 Java 库**，这些库带有已知漏洞。PySpark 的 DataFrame 和 SQL API 仍可连接到您的 Spark 计算集群，但导入 `SparkContext` 或 `RDD` 的函数现在会失败。参见 [PySpark 入门](/zh-cn/integrations/pyspark/getting-started/)。

- **附件、恢复和转换只读取您可以使用的账户**。通过电子邮件发送文件、从文件恢复维度或表归档、检查或导入表捆绑包、使用模板填充 Excel 导出，以及转换 Alteryx 工作流，现在都会拒绝您无权访问的文档账户。将维度备份到文档账户需要对其具有写入权限。工作流步骤不受影响，只是通过电子邮件发送文件、恢复表或填充 Excel 模板的步骤不能再从 Personal Temp Drive 读取。

- **导出只保存到您可以写入的账户**。将表或查询导出为任何格式的文件、导出表归档、项目归档或表捆绑包、根据项目创建本地 Python 工作流、将 REST 响应保存为文件，以及转换 Alteryx 或 Prophecy 工作流，现在都需要对其所保存到的文档账户具有写入权限。导出查询现在还会检查您是否可以使用其项目。表捆绑包导入不再把其导入日志写入您只能读取的账户。工作流中的导出步骤不受影响，只是它们不能再保存到 Personal Temp Drive。
