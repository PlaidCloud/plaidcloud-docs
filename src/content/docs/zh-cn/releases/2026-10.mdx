## 新增

- **Data Foundation 将您的 ERP 数据整合到一个 Common Finance Model 中。** Common Finance Model 将多个 ERP 系统和实例的 ERP 数据整合到单一模型中：统一的会计科目表、统一的实体集和统一的报告货币。基于它构建的报表、指标和 AI 助手读取的都是同一组数字，无论数据来自哪个 ERP。

  - **直接来自您的 ERP。** 总账、试算平衡表、主数据和预算通过 PlaidCloud 的 ERP 直接连接传入。**实体对照表**将各个源系统的公司代码映射到相同的实体，文件则用于补充系统中没有的内容，例如汇率或分摊动因。
  - **一个模型，一种货币。** **加载**会将每个源系统整合为 Common Finance Model，并换算为您的报告货币：损益表按期间平均汇率，资产负债表按期末汇率，权益按历史汇率。层次结构由您的主数据构建。
  - **检查就绪状态。** 针对每个实体和期间运行检查：试算平衡表和销售额与总账一致，每个产品、客户和科目都已知，货币可以换算，每个实体都已映射。
  - **保持最新。** **每晚刷新**会在每晚重新加载模型，缺失或为空的文件将以警告而非错误结束。

  从模板（例如 **Enterprise Profitability**）启动项目后，项目的**基础数据**选项卡将带您完成从已连接的 ERP 到已加载、已检查模型的全过程。请参阅 [Data Foundation：Common Finance Model](/zh-cn/guides/projects/data-foundation/)。

- **在您自己的 Snowflake 或 Databricks 数据仓库上运行 PlaidCloud。** 工作区管理员在用户菜单中打开**使用您自己的数据仓库**，并在自己的账户中运行生成的设置脚本。该脚本会为 PlaidCloud 创建一个有用量上限的数据仓库和一个服务身份，不会触及您现有的数据仓库。**检查连接**会用通俗的语言说明任何问题及其修复方法。此后新项目会在您的数据仓库中存储表并运行工作流，移除该数据仓库即可撤销 PlaidCloud 在其中的访问权限。请参阅[使用您自己的数据仓库](/zh-cn/guides/connections/external-lakehouse/)。

  - **使用 Snowflake 或 Databricks 登录。** 管理员无需粘贴凭据，可以通过登录来关联数据仓库。仪表板随后以每个人自己的数据仓库权限运行，工作流则以仅持有您指定数据角色的服务身份运行。请参阅[使用 Snowflake 或 Databricks 登录](/zh-cn/guides/connections/external-lakehouse/#使用-snowflake-或-databricks-登录)。
  - **可连接多个。** 在**管理数据仓库**中选择**设为默认**，新项目将使用另一个数据仓库，现有项目保持不变。请参阅[管理数据仓库](/zh-cn/guides/connections/external-lakehouse/#管理数据仓库)。
  - **查看每次运行的成本。** 运行历史记录中的**仓库成本**列以积分或 DBU 显示每次运行的成本。请参阅[每次运行的仓库成本](/zh-cn/guides/connections/external-lakehouse/#每次运行的仓库成本)。
  - **您的治理策略保持有效。** 说明会写入数据仓库自己的目录；当 PlaidCloud 替换、重建或克隆表时，Snowflake 行访问策略和掩码策略以及 Databricks 行筛选器和列掩码仍会保留。请参阅[您的策略和说明会延续](/zh-cn/guides/connections/external-lakehouse/#您的策略和说明会延续)。

- **在 PlaidCloud 内构建、发布 Panel 应用并设置品牌。**

  - **Panel Studio。** **Create app** 可从空白应用、表、视图、模板或应用库开始，**Open in Studio** 会在编辑器中打开应用的文件。保存草稿，**预览**私有构建，并**发布**正式应用。构建错误会指向对应的文件和行，**历史记录**可还原任何已发布的版本，**Insights** 显示浏览量、加载时间和错误。**Ask Weave** 了解应用的文件和构建状态，并在保存任何代码之前向您展示完整差异以供批准。请参阅 [Panel Studio](/zh-cn/guides/panel-apps/studio/) 和[使用 Weave 构建 Panel 应用](/zh-cn/guides/panel-apps/build-with-weave/)。
  - **外观与 PlaidCloud 一致的应用套件。** 使用该套件构建的应用在浅色和深色模式下都采用 PlaidCloud 的颜色、字体和间距。套件包含导航、筛选器、关键数字卡片、图表、表单、命令面板、运行工作流的按钮、打印功能，以及一个数据网格：它在服务器端排序和汇总，按列设置数字格式，每次只加载一屏行，因此可处理任意大小的表。应用以已登录查看者的身份读取表，并应用行级安全。请参阅 [Panel 应用套件](/zh-cn/guides/panel-apps/app-kit/)、[DataGrid](/zh-cn/guides/panel-apps/app-kit/#datagrid) 和 [Panel 应用的数据 API](/zh-cn/guides/panel-apps/data-api/)。
  - **提醒和摘要。** 当项目表中的某个数字越过限值时，通过推送通知、电子邮件、Slack 或 Microsoft Teams 获得通知，或获取最多包含 10 个数字的每日或每周摘要，始终遵循您自己的行访问权限。请参阅[提醒和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
  - **项目、品牌和共享。** 将应用分配给项目，分配前会审核哪些人可以打开该应用但不在该项目中。项目**主页**选项卡上的 **Edit Branding** 可为项目中的每个应用设置八种品牌颜色和一个徽标。**Gallery…** 会将应用作为模板列出，供所有可以查看其项目的人使用。请参阅[项目品牌和应用项目](/zh-cn/guides/panel-apps/branding/) 和[应用库](/zh-cn/guides/panel-apps/gallery/)。

- **只需统一约定一次业务数字的计算方式，所有 AI 回答都使用该计算。** 项目架构师定义一个**指标**，例如 *Net Revenue* 或 *Headcount*：它的源表、各行如何汇总、始终计入的行、联接的查找表，以及可用于细分的列。定义一经保存即生效；如果保存时引用了不存在的表或列，或者查找表的每个键对应多行，则会被拒绝。按名称或同义词向 AI 助手询问该指标，数字将按定义计算并遵循您自己的行访问权限，而不是由助手自行推算。定义通过 AI 助手或 REST API 管理。请参阅[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。

  - **派生指标。** 定义两个指标的比率、和或差，例如人均净收入，或者某个指标乘以固定系数。请参阅[由其他指标派生指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#由其他指标派生指标)。
  - **比较、排名和占比。** 可以询问与预算的差异、保留并列项的前 N 名或后 N 名，或者每行占总计的比例。请参阅[比较、排名和占比](/zh-cn/integrations/ai-coding-agents/metric-definitions/#比较排名和占比)。
  - **您的用语，约定的取值。** 将细分列绑定到维度后，*EMEA* 之类的词会变成其下的所有区域。如果某个词没有匹配项或匹配多个成员，则会以候选项的形式返回并向您确认，绝不猜测。请参阅[询问指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#询问指标)。
  - **财年时间。** 告诉指标其各行在您的财年日历中的位置，即可询问财年期间、年初至今、同比或环比。请参阅[随时间比较](/zh-cn/integrations/ai-coding-agents/metric-definitions/#随时间比较)。

  PlaidCloud 自己的 AI 助手会优先根据指标回答业务数字，并在带有 ✓ 标记的独立卡片中显示这些数字，该标记绝不会出现在助手自己的文字上。请参阅[业务数字](/zh-cn/guides/ai-assistant/weave-tab/#业务数字) 和[来自指标的数字](/zh-cn/guides/ai-assistant/weave-tab/#来自指标的数字)。

- **询问 Weave 是否已准备好结账，并检查两张表是否一致。** 两者都不涉及 AI。

  - **结账就绪状态。** 在项目的 **Weave** 选项卡中通过**就绪状态**，将结账、预测或任何截止日期所依赖的工作流指定为一个**就绪集**。一份清单即可回答所有工作流的情况：“13 个中 11 个已就绪；1 个未就绪；1 个无法检查。”只有当 Weave 能对某个工作流运行的所有检查都通过时，该工作流才算就绪；Weave 无法判断的内容会显示为**无法检查**并附上原因，绝不会显示为已就绪。如果最近一次运行的更早历史记录太少而无法比较，例如新工作流，则视为正常。不写入表的步骤（例如发送电子邮件或导出文件的步骤）没有可检查的行或空值，因此不会让工作流停留在**无法检查**状态。请参阅[结账前检查就绪状态](/zh-cn/guides/ai-assistant/weave-readiness/)。
  - **对账。** 在您配对的键列上，逐行比较两张表，或同一张表的两个期间。Weave 会说明它们是否一致、相差多少以及哪些行不同，对于无法完整读取的数据，绝不会说“一致”。每个对账在使用前都需另一位架构师批准。请参阅[检查两张表是否一致](/zh-cn/guides/ai-assistant/weave-reconciliation/)。

- **Weave 监视更多可能出错的地方，并在两次运行之间通知您。** Weave 的检查不使用 AI。每个发现项以及 AI 助手的每个回答都有一个 **Weave 如何得知**面板：对发现项，显示检查及其依据的值；对回答，显示助手运行的每个查询，每句话都标记为**已匹配**、**未匹配**或**未检查**。请参阅 [Weave 目前检查哪些内容](/zh-cn/guides/ai-assistant/weave-findings/#weave-目前检查哪些内容)、[Weave 如何得知](/zh-cn/guides/ai-assistant/weave-findings/#weave-如何得知) 和 [AI 助手中的“Weave 如何得知”](/zh-cn/guides/ai-assistant/weave-tab/#weave-如何得知)。

  - **表按时写入。** 如果表自其计划到期以来一直未被写入，或者超过了您在表详细信息的**时效性**下设置的时效阈值（1 小时到 180 天），Weave 会报告。
  - **陈旧或损坏的输入。** Weave 会报告读取了某张表的工作流，而该表此后已被另一个工作流写入；也会报告依赖于失败运行的每个工作流和仪表板。**同步依赖项**会补上步骤与其所读表之间缺失的连接器。请参阅[同步依赖项](/zh-cn/guides/workflows/sync-dependencies/)。
  - **数据形态发生变化。** Weave 会报告运行后值分布发生很大变化的小数列、开始多次写入行的联接、Extract 步骤因无法转换为列的类型而留空的值，以及未找到任何文件的导入。它还会报告最新期间与常态相差很大的指标，并指出导致此情况的项。Weave 会考虑月末和工作日的规律，因此始终在月末偏重的加载不会被报告。请参阅[异常的指标合计](/zh-cn/guides/ai-assistant/weave-metric-insights/)。
  - **变慢的运行。** Weave 会指出导致运行变慢的步骤，并报告较新运行比较早运行耗时至少多四分之一的工作流，同时指出耗时增长最多的步骤。
  - **运行之间的通知。** 每小时一次的检查会通过应用内消息向每个问题的负责人通知一次，页眉中的 **Weave** 按钮会统计您在所有项目中尚未阅读的问题数。请参阅[在两次运行之间收到通知](/zh-cn/guides/ai-assistant/weave-findings/#在两次运行之间收到通知) 和[页眉中的 Weave 按钮](/zh-cn/guides/ai-assistant/weave-tab/#标题栏中的-weave-按钮)。
  - **负责人、评论和预期警告。** 每个发现项都有一个负责人，默认是最后运行其工作流的人。**分配**可将其转交他人，评论用于记录进展，**团队**视图显示谁负责什么。架构师可以将警告标记为**此为预期**，并附上原因和结束日期。请参阅[为发现项指定负责人](/zh-cn/guides/ai-assistant/weave-tab/#为发现项指定所有者) 和[将发现项标记为预期](/zh-cn/guides/ai-assistant/weave-tab/#将发现项标记为预期)。

- **修复助手会解释错误，提出需要您在卡片上批准的更改，重新运行步骤，并可撤消修复。** 对于最常见的失败，例如列不在表中、必填设置为空、数据库无法读取的 SQL 或类型错误的值，第一条回复会解释常见原因和修复方法。提出的更改以卡片形式显示，说明步骤失败的原因，并逐项显示更改的设置，当前值为红色，新值为绿色。**批准**会应用更改，随后助手会提议重新运行该步骤，并诊断新出现的失败。**Weave** 选项卡中发现项上的**修复**会针对该问题打开助手。**撤消**会还原步骤之前的设置，**撤消并运行**可重建其输出。请参阅[使用 AI 修复工作流错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/)、[使用 AI 助手修复发现项](/zh-cn/guides/ai-assistant/weave-tab/#使用-ai-助手修复发现项) 和[撤消修复](/zh-cn/guides/ai-assistant/fixing-workflow-errors/#撤消修复)。

- **查看 Weave 在项目中做过的所有事情，并导出供审计人员使用。** 项目 **Weave** 选项卡上的**活动**列出 Weave 发现并后来不再发现的问题、AI 助手提出的每项更改、谁提出请求、谁批准或拒绝、它替换和写入的确切内容，以及最终结果。Weave 会在进行更改之前记录您的批准，并且不会进行无法记录的更改。**导出 CSV** 或**导出 PDF** 可将某个时间段保存为审计证据，条目无法编辑或删除。**摘要**一目了然地显示一个月的情况：发现并解决的问题、已批准的更改以及其中被撤消的数量。工作区管理员可通过**工作区摘要…** 获得每个项目的同类信息。请参阅 [Weave 活动历史记录](/zh-cn/guides/ai-assistant/weave-activity/) 和 [Weave 月度摘要](/zh-cn/guides/ai-assistant/weave-monthly-summary/)。

- **保存之前就了解步骤的作用以及更改会影响什么。** 所有这些都基于项目已保存的设置生成，不涉及 AI，而且您的角色看不到的内容只计数，不会列出名称。

  - **每个表、步骤和工作流的文档。** 详细信息面板中的**文档**部分说明哪些内容读取和写入某张表、某个步骤的作用，以及工作流中各步骤的先后顺序。**下载交接包**会将整个项目保存为一份文档，其中包括指标定义和分摊模型。请参阅[表、步骤和工作流的文档](/zh-cn/guides/ai-assistant/weave-documentation/)。
  - **更改会影响什么。** 在**保存**上方，Weave 会说明有多少下游步骤读取该步骤写入的内容，例如“对此步骤的更改会影响 2 个工作流中的 8 个下游步骤”，**显示步骤**会列出这些步骤。请参阅[更改会影响什么](/zh-cn/guides/ai-assistant/impact-preview/)。
  - **保存会拒绝什么。** **保存**上方的状态栏会在您编辑时运行该步骤的检查，每个问题都有**转到**，表达式编辑器会在您输入时检查表达式。请参阅[保存会拒绝什么](/zh-cn/guides/ai-assistant/check-while-you-edit/)。
  - **对单个工作流的审核。** 工作流画布或**步骤**网格上的**检查**会对其运行 Weave 的检查，以及分摊和行级安全检查。请参阅[审核单个工作流](/zh-cn/guides/ai-assistant/weave-findings/#审核一个工作流)。

- **为您的工作区关闭 Weave 的任何 AI 功能。** 工作区管理员在页眉 **Weave** 按钮上选择 **AI 功能…**，可以分别开启或关闭 Weave 聊天、修复助手、导入和导出助手、表达式助手、根据描述生成 SQL、工作流审核摘要或入门图表。在管理员关闭之前，所有功能均为开启状态，Weave 的检查和发现项始终保持开启，每次更改都会记录在安全日志中。请参阅 [AI 功能](/zh-cn/guides/ai-assistant/weave-ai-features/)。

- **在 Allocation Split 步骤上尝试驱动因素假设分析。** 右键单击该步骤并选择**假设分析…**，即可查看在不同驱动因素取值、其驱动因素表的另一列，或另一张具有相同键的表中的数值列的情况下，它将如何分摊成本。最多可比较 10 个方案，每个方案都根据该步骤的上次运行精确计算到分，并可查看谁受益、谁受损，以及哪些行将分不到任何金额。**细分依据**显示每个成员的变化落在哪些科目或其他值上，**后续步骤**则将方案延续到根据分摊输出构建的表中。不会重新运行，也不会更改任何数据。请参阅[尝试驱动因素假设分析](/zh-cn/guides/allocations/results/driver-what-if/)。

- **将项目迁移到 Lakehouse v2 的过程从就绪检查到撤消全程有引导。** **检查迁移就绪状态**会将表、视图、步骤、仪表板、数据共享和容量报告为畅通、需要审核或受阻，并对每个发现项给出通俗易懂的说明。**在 v2 上试用…** 会创建一个私有试用副本，其中计划已关闭，ERP 过账处于模拟模式。可以立即开始迁移，也可以在您选择的时间开始。迁移运行期间项目的计划会暂停，结束后恢复，完成时会通过消息和电子邮件通知您。**变更内容…** 会报告每张表的结果，**撤消迁移…** 可在撤消期限内将项目恢复到 Lakehouse v1。请参阅[将项目迁移到 Lakehouse v2](/zh-cn/guides/data/migrate-project-lakehouse/)。

- **复制项目时会复制其数据，并可选择复制多少。** **复制项目**提供**仅结构**、**完整数据**或**样本**，可在同一个 Lakehouse 内或从一个 Lakehouse 到另一个 Lakehouse，复制前会审核其大小和任何警告。包含数据的副本仅对创建者本人可见。**复制结果**列出每张表的结果，**重试失败的表**仅复制这些表，**查看导入或复制结果**可稍后重新打开该窗口。传感器和计划事件在副本上处于关闭状态，因此在您于副本中将其开启之前不会触发任何内容。请参阅[复制项目](/zh-cn/guides/projects/managing-projects/#复制项目)。

- **步骤在保存时而不是运行时发现问题。** 如果保存的步骤其设置会导致运行失败或给出错误结果，保存会被拒绝，并附有说明需要更改什么的消息。每个步骤的参考页面都会列出它检查的内容。步骤或其源表中已不存在的已映射源列会以红色标记，保存时会打开一个对话框，其中有**全部移除并保存**、**仍然保存**或**取消**。联接、查找和空间步骤会原地保留此类行，而不会自行删除。使用未定义变量的表达式会指出该变量的名称，运行时被拒绝的步骤会用通俗的语言解释原因。请参阅[不再列出的源列](/zh-cn/reference/workflow-steps/tables/table-extract/#不再列出的源列)、[源表中缺少的列](/zh-cn/reference/workflow-steps/tables/table-extract/#源表中缺少的列) 和[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。

- **每个 Lakehouse 的存储和计算方式相同。** 来自导入 CSV、导入 XML 或 Import Table Archive 的空字段会作为 null 加载，因此之后测试 `= ''` 或 `= 0` 的步骤需要改为测试 null。`cast(x, Float)` 在任何地方都是 64 位，因此大额金额可保留全部位数，PlaidCloud 创建的 Float 列为双精度。JSON 列、**Table: Delete Rows** 以及聚合条件可在每个 Lakehouse 上使用。自行构建结果的步骤（例如求解器、预测，以及在 pandas 中运行的 Pivot 和 Allocation Split）会将结果加载为带类型的数据，速度快得多。表资源管理器会显示数值列的最小值、最大值、平均值、总和、标准差和方差。请参阅[转换为 Float](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#转换为-float) 和[列数据和唯一值计数](/zh-cn/guides/data/table-explorer/#列数据和唯一值计数)。

- **文件导出保留其类型。** Parquet 文件将整数列保留为整数，以微秒存储时间戳，并将时区标记为 UTC。Avro 文件保留带类型的日期、时间戳和布尔值，单表 Avro 导出以导出名称命名。为 Parquet 导出选择多个文件时会停止并提示 Parquet 只写入单个文件。非常大的 Parquet、ORC 和 JSON 导出会在读取行的同时写入，因此不再耗尽内存，Parquet 使用您选择的压缩方式。版本 1.2.33 或更高版本的 PlaidLink 代理会以 Parquet 文件接收导出的表。请参阅 [Export to Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro](/zh-cn/reference/workflow-steps/export/export-to-avro/) 和[数据如何到达代理](/zh-cn/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#数据如何到达代理)。

- **ERP 过账遵循每个计划的模式，不确定的答复会被保留供您检查。** 计划事件保留自己的过账模式（**实时**、**模拟**或**关闭**），并受项目设置的上限约束，**运行所选事件**会使用每个事件的模式。PlaidCloud 无法确认的 ERP 答复（例如超时或服务器错误）会被视为存疑而保留，而不是记录为已拒绝，并且一笔过账不能被冲销两次。过账登记簿会列出**待冲销**的过账，架构师在项目主页的 **ERP 写入授权**中授权项目进行过账。请参阅 [ERP过账模式](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)、[冲销](/zh-cn/guides/connections/posting-register/#冲销) 和[授权项目过账](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)。

- **行访问跟得上分组变化，并说明问题所在。** 用户登录时由单点登录设置的分组成员关系会在约 15 分钟内反映到仪表板行访问中，默认分组的新成员会在约一分钟内获得其行。当某个限制没有筛选掉任何内容时，行访问窗口会发出警告，可处理包含 `&`、`/` 或 `%` 的列名，并在同步失败时显示带原因的**错误**或带有**重试**按钮的**正在重试**。请参阅[保持仪表板同步](/zh-cn/administration/access/managing-security-groups-and-assignments/#保持仪表板同步)。

- **用户定义函数在 Python 3.14 上运行，并使用较新的库。** 大多数函数无需更改即可运行。导入 numba 的函数，或导入 Python 已移除的标准库模块（例如 `cgi` 或 `telnetlib`）的函数，现在会失败，需要重写。预测的 AutoTheta 边界可能与以前的运行略有不同。请参阅 [User Defined Transform](/zh-cn/reference/workflow-steps/general/user-defined-transform/)。

- **完整代理访问已弃用，并将于 2027 年 1 月 15 日移除。** 使用**完整**访问的 LLM 步骤会记录警告。请改用**读取和写入**，在该模式下代理通过 PlaidCloud 的写入工具更改数据，LLM 步骤仅写入选中**写入**的绑定。请参阅[代理访问](/zh-cn/integrations/ai-architecture/llm-providers/#代理访问)。

- **Project 应用更完整地处理发票、行程和补报工时。** 新发票从主项目开始，由主项目提供客户和采购订单号。删除发票草稿会使其工时和行程重新变为可计费，**AR 收件人**设置提交发票时向谁发送电子邮件。行程抽屉会显示每行的供应商、类别和审核状态，**添加补报工时**会为已批准的一周创建工时表。请参阅[使用 Project 应用跟踪工时和费用](/zh-cn/guides/time-expense/track-time-and-expenses/)。

- **删除所有未被任何步骤引用的表的 API 调用已移除。** 请改为按 ID 删除表。

- **应用各处的较小变更。** 双击账户、仪表板、成员、分组或设置列表中的某一行即可将其打开。空的**维度**、**数据编辑器**、**UDF** 和**步骤**选项卡会说明下一步该做什么，没有应用的成员会进入 Launcher。步骤的表选择器会显示表的上次更新时间（[查看源表最后一次更改的时间](/zh-cn/guides/workflows/create-workflow/#查看源表最后一次更改的时间)）。Export External Database Tables 在自己的选项卡上映射列，**报表：批量生成**不再显示未使用的 **Report Constants** 部分。Convert Encoding 可识别中欧、土耳其和阿拉伯语编码。指向已移除屏幕的链接会说明这一点。

## 修复

- **AI 助手在您批准之前不会更改任何内容，并按原样显示名称。** 以前，将步骤构建到新表中时会在您批准之前就创建该表；现在表和步骤会在您批准后一起创建，创建项目、工作流或维度、复制表以及更改表属性或标签时也会先询问。批准仅在您的下一条回复中有效。助手提出的导入或导出会按名称显示其表、文档账户和工作流，并且不会与不存在或您无法打开的对象一起提供。带下划线的名称会按原样显示而不再变成斜体，表和代码在深色主题下可读，图表会绘制而不是显示为文本，表达式编辑器的 Weave 面板会读取您正在编辑的表达式。助手会列出项目的表，即使有的表没有名称；当某个步骤读取或写入多张表时，也能回答哪些步骤读取或写入某张表，而不是因错误而中止。请参阅[构建工作流步骤](/zh-cn/guides/ai-assistant/weave-tab/#构建工作流步骤)。

- **文件导入读取您指向的内容。** 导入 Excel 可读取整列范围和 XLSB 工作簿，可在压缩的工作簿中找到工作表，并且不再因带有填充或换行的标题而失败。导入 CSV 遵循**跳过行数**，因此标题上方有若干行的文件（例如 SAP 列表导出）可按列名导入，并使用默认的分隔符、引号和转义字符运行。一个源列可以馈入多个目标列，所有列均为固定值的导入会加载每一行，使用大写压缩扩展名的文件会被解压缩，跳过未更改内容的导入会重新加载已清空的表。要求 AI 助手从**项目默认**导入文件时，会读取项目的默认文档账户，如果项目未设置则会明确告知您。带有较新列类型的 Parquet 文件可在 Documents 中打开。请参阅[导入 Excel](/zh-cn/reference/workflow-steps/import/import-excel/#读取内容) 和[导入 CSV](/zh-cn/reference/workflow-steps/import/import-csv/#行选择)。

- **工作流步骤按配置保存和运行。** 表：Upsert 步骤可以再次保存，其**更新键**列也已恢复。表：项目间复制会指明其目标项目，并通过数据共享读取。文档：将仪表板保存为 PDF 会保留其列类型，表：去重合并和表：全部合并按名称匹配列。多表联接可保存多个输入，并接受包含空格的列名。Table Lookup 会忽略其查找列上的聚合设置，SCD-2 截至日期联接可将变量作为其日期。LLM 步骤可在 4.6 之前的 Claude 模型上运行，并在 AI 助手编辑它们时保留其模型。REST 请求发送的行值只编码一次，导出到远程数据库的操作会提交其行。请参阅[更新键](/zh-cn/reference/workflow-steps/tables/table-upsert/#更新键)、[数据共享管理](/zh-cn/reference/workflow-steps/tables/frame-project-copy/#数据共享管理) 和[多表联接](/zh-cn/reference/workflow-steps/tables/table-multi-table-join/)。选择工作流的步骤（例如 Workflow Delete、Copy、Rename 和 Stop）会保留已不存在的工作流并显示为 *id (missing)*，而不是切换到列表中的第一个工作流。

- **工作流运行按应有方式结束。** Workflow Loop 会在每次迭代中运行循环的工作流，迭代容器以及在一次运行中多次运行的工作流也是如此。从某个步骤或并行组内部开始的运行会运行正确的步骤并结束。长时间运行的导入或导出绝不会启动两次，在 PlaidCloud 更新期间不会停滞，以服务器错误结束的操作不会被重新发送。数据库驱动程序崩溃只会使其自己的步骤失败，并给出数据库的原因。运行历史记录会统计每个步骤的行数，在工作开始之前就失败的步骤会将原因写入工作流日志。请参阅 [Workflow Loop](/zh-cn/reference/workflow-steps/workflow-control/workflow-loop/) 和[运行历史记录](/zh-cn/guides/workflows/advanced-workflows/#运行历史)。

- **项目复制、导入和打开不再出现意外。** 项目导入会保留其能够恢复的所有内容，并在**导入结果**窗口中列出遗漏的内容，显示进度，说明失败的原因，并且可以重试。当项目有变量时，复制所选对象可以正常工作。打开项目不再更改其设置，**导入您自己的数据**会导入您的 CSV，在 PostgreSQL 数据仓库上创建表可以正常工作。App Runner 应用会在 PlaidCloud 更新时自行刷新，并且对限制行的项目上的查看者可用。请参阅[归档的部分内容未能导入时](/zh-cn/guides/projects/archive-a-project/#归档的部分内容未能导入时) 和[保持应用为最新](/zh-cn/guides/workflows/use-converted-alteryx-apps/#保持应用为最新)。

- **维度和分摊可正确加载和读取。** 父子加载会将父级为空的行保留为顶层成员，并且在各类加载中，主层次结构之外的成员对第二个备用层次结构都会被拒绝。将成员移到其层次结构不包含的父级之下会被拒绝，维度步骤会指出它找不到的维度，粘贴包含空白的列时每个值都保留在其所在行上。读取大型维度不再拖累工作区中的其他所有人。其维度属性将**层次结构**保留为**未指定**的分摊规则可以运行。请参阅[加载到备用层次结构](/zh-cn/reference/workflow-steps/dimensions/dimension-load/#加载到备用层次结构) 和[维度类型属性和成员选取器](/zh-cn/guides/dimensions/dimensions/#维度类型属性和成员选取器)。

- **工作流画布和各屏幕表现正常。** **钻取到工作流**会在其画布上打开高级工作流，画布可打开每个工作流，并在布局的某一部分无法读取时告知您。放不下的工具栏按钮移入**更多**菜单，列表在您保存后立即更新。通知会显示完整消息，警告会在**日志**选项卡中显示警告图标，表资源管理器会说明某列的概要分析失败，数据编辑器会让空的日期单元格保持为空。在启用列筛选器的情况下保存数据编辑器时，会保留被筛选器隐藏的行，添加、删除或移动行之后也是如此。对于有权更改用户定义函数的任何人，其编辑器会以可编辑状态打开。请参阅[画布无法打开工作流时](/zh-cn/guides/workflows/advanced-workflows/#画布无法打开工作流时)。从**表**列表中删除表时，会列出仅通过变量路径（例如 `/Periods/{period}/Sales`）引用某张表的所有步骤，并且只有在您强制删除时才会删除该表。请参阅[删除](/zh-cn/guides/projects/managing-tables-and-views/#删除)。

- **成员和连接按应有方式工作。** **添加工作区成员**适用于已有账户的人（包括通过单点登录创建的账户），并且绝不会降低他们已持有的项目角色。ODBC 连接通过 PlaidLink 代理所在机器上的 DSN 或驱动程序连接。拒绝您的 OAuth 凭据的提供商会告诉您重新输入或重新授权，Databricks 示例和导出会刷新即将过期的令牌，旧数据库类型的连接可以删除。**使用位置**包含通知步骤，免费工作区保留每日、每周和每月备份。请参阅[成员管理](/zh-cn/administration/access/member-management/) 和 [ODBC](/zh-cn/reference/connectors/databases/odbc/)。

- **REST API 和 AI 助手工具严格按您的要求执行。** 对成员、分组或计划事件的部分更新只会更改您指定的字段，因此暂停的事件保持暂停。在指定步骤开始的运行会从该处开始，还原表快照会保留一个安全快照和一条审计记录。AI 工具的驱动因素假设分析只会在与您的模型实际所做的拆分一致时作答。以前因服务器错误而失败的请求现在要么能正常工作，要么会说明问题所在。请参阅[追踪分摊](/zh-cn/integrations/ai-coding-agents/tracing-allocations/) 和[回退或还原快照](/zh-cn/guides/data/table-snapshots/#回退或还原快照)。

## 安全

- **AI 助手不会超出您的权限。** 助手的数据查询在运行之前会按其结构检查，并且只运行单个读取查询。只读的 AI 连接（包括 Microsoft 365 Copilot）无法导出文件、保存仪表板 PDF、将行复制到另一个项目，或通过 REST 连接发送更改。通过 AI 助手进行的导入以您的身份在您指定的项目中运行，对话只能由发起者继续。助手和表引用会省略您的角色隐藏的表、步骤、工作流和维度，Weave 会统计您无法打开的失败步骤，而不是列出其名称。请参阅[访问级别](/zh-cn/integrations/microsoft-365-copilot/#访问级别)、[您的角色所隐藏的内容](/zh-cn/guides/ai-assistant/weave-tab/#您的角色所隐藏的内容) 和[管理过去的对话](/zh-cn/guides/ai-assistant/weave-tab/#管理过去的对话)。

- **ERP 过账无法绕过其控制。** 启用职责分离后，冲销需通过过账登记簿进行，并适用审批。复制或导入的项目不再继承过账权限，SAP 和 EBS 过账不能直接发送给代理，处于仅测试模式的 SAP Post 步骤需要与实际过账相同的权限。一个未公开的、无需这些检查即可向 Sage Intacct 过账的端点已被移除。来自 ERP 和 REST 连接的错误消息不再包含凭据。请参阅[职责分离](/zh-cn/guides/connections/posting-register/#职责分离)。

- **机密为只写，只有所有者决定谁可以使用连接。** 文档账户的密钥、密码和令牌一经保存就不会再显示，更改账户的连接位置需要再次提供机密。步骤中的密码和密钥仅存在于变量中；已输入到步骤中的机密已移入仅架构师可见的项目变量。多行凭据在您输入时会被屏蔽。只有连接的所有者或工作区管理员才能更改谁有权访问它。请参阅[已保存的机密为只写](/zh-cn/guides/documents/adding-accounts/#已保存的机密为只写)、[密钥存放在变量中](/zh-cn/reference/workflow-steps/document/encrypt-decrypt-file/#密钥存放在变量中) 和[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

- **您无权使用的文档账户始终对您关闭。** 检查文件是否存在、读取 Parquet、Avro、ORC 或 Delta 文件的列、使用**填充**为导入步骤填充列，以及 AI 助手的文件检查，现在都会拒绝您无权访问的账户，与浏览该账户时的行为一致。

- **只有工作区管理员才能更改工作区管理员。** 编辑、停用或删除管理员、更改其分组以及将某人设为管理员，都需要工作区管理员。请参阅[更改工作区管理员](/zh-cn/administration/access/member-management/#更改工作区管理员)。

- **数据共享只代表被授予该共享的项目的成员。** 通过共享读取需要在接收项目中拥有角色，写入需要**写入**共享以及在该项目中拥有管理者或架构师角色。请参阅[在项目之间共享数据](/zh-cn/guides/projects/managing-projects/#在项目之间共享数据)。

- **还原仅适用于指定的项。** 还原较早的版本会还原项本身，权限检查针对该项。内容不属于其自身标头中所指维度的维度备份文件会被拒绝。请参阅[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。

- **模板、导入和归档会拒绝不安全的内容。** 导出模板和报表模板在沙盒中渲染，只读取提供给它们的数据。导入会根据自己的设置构建加载查询，包含 PlaidCloud 归档从不包含的内容的项目归档会被拒绝，会与另一个项目共享报告架构的项目标识也会被拒绝。请参阅[模板可以使用的内容](/zh-cn/reference/workflow-steps/export/export-templated/#模板可以使用的内容) 和[还原归档](/zh-cn/guides/projects/archive-a-project/#还原归档)。

- **仪表板遵循 PlaidCloud 登录和您的行访问权限。** 仪表板的缩略图以您的身份渲染，账户仅来自 PlaidCloud 登录，仪表板仅能从导出所生成的 ZIP 文件导入。请参阅[导入现有仪表板](/zh-cn/guides/dashboards/learning-dashboard/#导入现有仪表板)。

- **启动工作流运行不再返回该运行的凭据。**

- **运行用户定义函数的环境不再包含 PySpark 的 Java 库，** 这些库存在已知漏洞。PySpark 的 DataFrame 和 SQL API 仍可连接到您的 Spark Compute Cluster，但导入 `SparkContext` 或 `RDD` 的函数现在会失败。请参阅 [PySpark 入门](/zh-cn/integrations/pyspark/getting-started/)。
