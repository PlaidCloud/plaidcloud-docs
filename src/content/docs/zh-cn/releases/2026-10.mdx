## 新增

- **Data Foundation 将 ERP 数据整合到一个 Common Finance Model 中。** Common Finance Model 将来自多个 ERP 系统和实例的 ERP 数据整合为一个模型：一套会计科目表、一组实体和一种报告货币。基于它构建的报表、指标和 AI 助手读取的都是同一组数字，无论数据来自哪个 ERP。

  - **直接来自 ERP。** 总账、试算平衡表、主数据和预算通过 PlaidCloud 的 ERP 直连导入。**实体对照表**将各数据源的公司代码映射到同一组实体，系统中没有的数据（如汇率或分摊动因）可以用文件补充。
  - **一个模型，一种货币。** **加载**会将所有数据源统一为 Common Finance Model，并换算为报告货币：损益表按期间平均汇率，资产负债表按期末汇率，权益按历史汇率。层次结构根据主数据构建。
  - **检查就绪状态。** 按实体和期间运行检查：试算平衡表和销售额与总账一致，每个产品、客户和科目均为已知，货币可以换算，每个实体均已映射。
  - **保持最新。** **每晚刷新**会在每晚重新加载模型；文件缺失或为空时，将以警告而非错误结束。

  使用 **Enterprise Profitability** 等模板创建项目后，项目的**基础数据**选项卡会带您从已连接的 ERP 一直到已加载并通过检查的模型。请参阅 [Data Foundation：Common Finance Model](/zh-cn/guides/projects/data-foundation/)。

- **在您自己的 Snowflake 或 Databricks 数据仓库上运行 PlaidCloud。** 工作区管理员在用户菜单中打开**使用您自己的数据仓库**，并在自己的账户中运行生成的设置脚本。该脚本会创建一个有用量上限的数据仓库和一个供 PlaidCloud 使用的服务身份，并且不会触及您现有的任何数据仓库。**检查连接**会用通俗的语言说明任何问题及其解决方法。此后，新项目会将其表存储在您的数据仓库中，并在其中运行工作流；移除该数据仓库会同时撤销 PlaidCloud 在其中的访问权限。请参阅[使用您自己的数据仓库](/zh-cn/guides/connections/external-lakehouse/)。

  - **使用 Snowflake 或 Databricks 登录。** 管理员无需粘贴凭据，而是可以通过登录来关联数据仓库。这样，仪表板将以每位用户自己的数据仓库权限运行，工作流则以仅持有您指定的数据角色的服务身份运行。请参阅[使用 Snowflake 或 Databricks 登录](/zh-cn/guides/connections/external-lakehouse/#使用-snowflake-或-databricks-登录)。
  - **连接多个。** 在**管理数据仓库**中使用**设为默认**，可将新项目指向另一个数据仓库，现有项目保持不变。请参阅[管理数据仓库](/zh-cn/guides/connections/external-lakehouse/#管理数据仓库)。
  - **查看每次运行的成本。** 运行历史记录中的**仓库成本**列显示每次运行消耗的积分或 DBU。请参阅[每次运行的仓库成本](/zh-cn/guides/connections/external-lakehouse/#每次运行的仓库成本)。
  - **您的治理策略保持不变。** 说明会写入数据仓库自己的目录；PlaidCloud 替换、重建或克隆表时，Snowflake 的行访问策略和掩码策略，以及 Databricks 的行筛选器和列掩码仍会保持关联。请参阅[您的策略和说明会保留](/zh-cn/guides/connections/external-lakehouse/#您的策略和说明会延续)。

- **在 PlaidCloud 内构建、发布 Panel 应用并设置品牌样式。**

  - **Panel Studio。** **我的 Panel 应用**中的第一个按钮**新建 Studio 应用**可从空白应用、表、视图、另一个 Studio 应用或应用库开始；**表**选项卡上的**创建 Panel 应用**则从您选中的表开始。**在 Studio 中打开**会在编辑器中打开应用的文件。您可以保存草稿、**预览**私有构建，并**发布**正式应用。构建错误会指向对应的文件和行，**历史记录**可恢复任何已发布的版本，**洞察**显示浏览量、加载时间和错误。**询问 Weave**了解应用的文件和构建状态，并在保存任何代码之前向您展示完整的差异以供批准。请参阅 [Panel Studio](/zh-cn/guides/panel-apps/studio/) 和[使用 Weave 构建 Panel 应用](/zh-cn/guides/panel-apps/build-with-weave/)。
  - **外观与 PlaidCloud 一致的应用套件。** 使用该套件构建的应用在浅色和深色模式下都采用 PlaidCloud 的颜色、字体和间距。套件包含导航、筛选器、关键数字卡片、图表、表单、命令面板、运行工作流的按钮、打印，以及一个在服务器端排序和汇总、按列设置数字格式、每次只加载一屏行数据的数据网格，因此可以处理任意大小的表。应用以登录查看者的身份读取表，并应用行级安全。请参阅 [Panel 应用套件](/zh-cn/guides/panel-apps/app-kit/)、[DataGrid](/zh-cn/guides/panel-apps/app-kit/#datagrid) 和 [Panel 应用的数据 API](/zh-cn/guides/panel-apps/data-api/)。
  - **提醒和摘要。** 当项目表中的某个数字超过限值时，通过推送通知、电子邮件、Slack 或 Microsoft Teams 收到通知，也可以收到最多包含 10 个数字的每日或每周摘要，且始终遵循您自己的行访问权限。请参阅[提醒和摘要](/zh-cn/guides/panel-apps/alerts-and-digests/)。
  - **项目、品牌设置和共享。** 将应用分配给项目，分配前会先审核哪些人可以打开应用但不属于该项目。项目**主页**选项卡上的**编辑品牌设置**可为项目中的每个应用设置八种品牌颜色和一个徽标。**应用库…** 按钮会将属于某个项目的 Studio 应用列为模板，供所有能查看该项目的人使用，**从应用库中移除**则将其撤下。请参阅[项目品牌设置和应用项目](/zh-cn/guides/panel-apps/branding/)和[应用库](/zh-cn/guides/panel-apps/gallery/)。

- **一次约定业务数字的计算方式，所有 AI 回答都使用该计算。** 项目架构师定义一个**指标**，例如*净收入*或*员工人数*：其源表、各行的汇总方式、始终计入的行、联接的查找表，以及可用于细分的列。定义保存后立即生效；如果保存时指定了不存在的表或列，或者查找表中同一个键对应多行，保存将被拒绝。向 AI 助手按名称或同义词询问该指标时，数字由定义计算得出，并遵循您自己的行访问权限，而不是由助手自己推算。定义通过 AI 助手或 REST API 管理。请参阅[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。

  - **派生指标。** 定义两个指标的比率、和或差，例如人均净收入，或将指标乘以固定系数。请参阅[从其他指标派生指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#由其他指标派生指标)。
  - **比较、排名和占比。** 可以询问与预算的差异、保留并列名次的前 N 名或后 N 名，以及每行占总数的比例。请参阅[比较、排名和占比](/zh-cn/integrations/ai-coding-agents/metric-definitions/#比较排名和占比)。
  - **您的说法，约定的值。** 将细分列绑定到某个维度后，*EMEA* 之类的词就会对应其下的所有地区。无法匹配任何成员或匹配多个成员的词，会作为候选项返回并向您确认，绝不猜测。请参阅[询问指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/#询问指标)。
  - **财年时间。** 告知指标的行在您的财年日历中所处的位置，即可询问某个财务期间、年初至今、同比或环比。请参阅[按时间比较](/zh-cn/integrations/ai-coding-agents/metric-definitions/#随时间比较)。

  PlaidCloud 自己的 AI 助手会优先从指标中回答业务数字，并把数字显示在带 ✓ 标记的独立卡片中，该标记绝不会出现在助手自己的文字上。请参阅[业务数字](/zh-cn/guides/ai-assistant/weave-tab/#业务数字)和[来自指标的数字](/zh-cn/guides/ai-assistant/weave-tab/#来自指标的数字)。

- **询问 Weave 是否已为结账做好准备，并检查两张表是否一致。** 两者都不使用 AI。

  - **结账就绪状态。** 在项目 **Weave** 选项卡的**就绪状态**中，将结账、预测或任何截止日期所依赖的工作流命名为**就绪集**。一份清单即可回答所有这些工作流的情况：“13 个中 11 个已就绪；1 个未就绪；1 个无法检查。”只有当 Weave 能运行的每项检查都通过时，工作流才算已就绪；Weave 无法判断的内容会连同原因显示为**无法检查**，绝不会显示为已就绪。最近一次运行因更早的历史记录太少而无法与之比较（例如新建的工作流）时，按正常情况计算。不写入表的步骤（例如发送电子邮件或导出文件）没有可检查的行或空值，因此不会让工作流停留在**无法检查**状态。请参阅[结账前检查就绪状态](/zh-cn/guides/ai-assistant/weave-readiness/)。
  - **对账。** 按您配对的键列，逐行比较两张表，或同一张表的两个期间。Weave 会说明二者是否一致、相差多少以及哪些行不同，对于无法完整读取的数据，绝不会说“一致”。每个对账在使用前都需由另一位架构师批准。请参阅[检查两张表是否一致](/zh-cn/guides/ai-assistant/weave-reconciliation/)。

- **Weave 监控更多可能出错的地方，并在两次运行之间通知您。** Weave 的检查不使用 AI。每个发现项和 AI 助手的每个回答都有一个 **Weave 如何得知**面板：对于发现项，显示检查及其依据的值；对于回答，显示助手运行的每个查询，并将每句话标记为**已匹配**、**未匹配**或**未检查**。请参阅 [Weave 目前检查的内容](/zh-cn/guides/ai-assistant/weave-findings/#weave-目前检查的内容)、[Weave 如何得知](/zh-cn/guides/ai-assistant/weave-findings/#weave-如何得知)和 [AI 助手中的 Weave 如何得知](/zh-cn/guides/ai-assistant/weave-tab/#weave-如何得知)。

  - **表是否按时写入。** Weave 会报告自计划到期以来一直未写入的表，或超过您在表详细信息的**时效性**中设置的时效阈值（1 小时至 180 天）未写入的表。
  - **过期或损坏的输入。** Weave 会报告读取了另一个工作流之后写入的表的工作流，以及所有依赖失败运行的工作流和仪表板，包括图表建立在 SQL 数据集上的仪表板。**同步依赖项**会补上步骤与其读取的表之间缺失的连接器。请参阅[同步依赖项](/zh-cn/guides/workflows/sync-dependencies/)。
  - **形态发生变化的数据。** Weave 会报告运行后取值分布发生明显变化的小数列、开始重复写入行的联接、Extract 步骤因无法转换为列类型而留空的值，以及未找到文件的导入。它还会报告最新期间明显偏离常态的指标，并指出造成偏离的项目。Weave 会考虑月末和工作日规律，因此总是在月末负载较高的加载不会被报告。请参阅[异常的指标合计](/zh-cn/guides/ai-assistant/weave-metric-insights/)。
  - **变慢的运行。** Weave 会指出导致运行变慢的步骤，并报告较新运行比较旧运行耗时至少多四分之一的工作流，同时指出耗时增长最多的步骤。
  - **两次运行之间的通知。** 每小时一次的检查会通过应用内消息将每个问题仅通知其所有者一次，页眉中的 **Weave** 按钮会统计您在所有项目中尚未阅读的问题。请参阅[在两次运行之间收到通知](/zh-cn/guides/ai-assistant/weave-findings/#两次运行之间收到通知)和[页眉中的 Weave 按钮](/zh-cn/guides/ai-assistant/weave-tab/#标题栏中的-weave-按钮)。
  - **所有者、评论和预期警告。** 每个发现项都有所有者，默认是最后运行其工作流的人。**分配**可将其转交他人，评论用于记录进展，**团队**视图显示谁负责什么。架构师可以将警告标记为**此为预期**，并注明原因和结束日期。请参阅[为发现项指定所有者](/zh-cn/guides/ai-assistant/weave-tab/#为发现项指定所有者)和[将发现项标记为预期](/zh-cn/guides/ai-assistant/weave-tab/#将发现项标记为预期)。

- **修复助手会解释错误，在卡片上提出由您批准的更改，重新运行步骤，并可撤消修复。** 对于最常见的故障，例如表中没有的列、必填设置为空、数据库无法读取的 SQL 或类型错误的值，第一条回复会说明常见原因和修复方法。提出的更改以卡片形式显示，说明步骤失败的原因，并显示每项更改的设置，当前值为红色，新值为绿色。**批准**即可应用，随后助手会提议重新运行该步骤，并诊断新出现的故障。**Weave** 选项卡中发现项上的**修复**会针对该问题打开助手。**撤消**会恢复步骤之前的设置，**撤消并运行**会重新生成其输出。请参阅[使用 AI 修复工作流错误](/zh-cn/guides/ai-assistant/fixing-workflow-errors/)、[使用 AI 助手修复发现项](/zh-cn/guides/ai-assistant/weave-tab/#使用-ai-助手修复发现项)和[撤消修复](/zh-cn/guides/ai-assistant/fixing-workflow-errors/#撤消修复)。

- **查看 Weave 在项目中所做的一切，并导出给审计人员。** 项目 **Weave** 选项卡上的**活动**会列出 Weave 发现后来不再出现的问题、AI 助手提出的每项更改、请求者以及批准或拒绝者、被替换和写入的具体内容，以及最终结果。Weave 会在做出更改之前记录您的批准，无法记录的更改一律不做。**导出 CSV**或**导出 PDF**可将某个时间段保存为审计证据，条目无法编辑或删除。**摘要**一览一个月的情况：发现和解决的问题、已批准的更改以及其中被撤消的数量。工作区管理员可通过**工作区摘要…** 按钮查看所有项目的同类信息。请参阅 [Weave 活动历史记录](/zh-cn/guides/ai-assistant/weave-activity/)和 [Weave 月度摘要](/zh-cn/guides/ai-assistant/weave-monthly-summary/)。

- **保存之前了解步骤的作用以及更改的影响。** 这些内容均根据项目已保存的设置生成，不使用 AI，您的角色所隐藏的内容只计数，不会列出名称。

  - **每个表、步骤和工作流的文档。** 详细信息面板中的**文档**部分说明步骤的作用以及工作流中各步骤的顺序，哪些内容读取和写入某个表则可供 Weave 和 AI 助手使用。表的详细信息面板列出其**列**及其类型和说明。**下载交接包**将整个项目（包括指标定义和分摊模型）保存为一份文档。请参阅[表、步骤和工作流的文档](/zh-cn/guides/ai-assistant/weave-documentation/)。
  - **更改的影响。** 在**保存**上方，Weave 会说明有多少个下游步骤读取该步骤写入的内容，例如“对此步骤的更改会影响 2 个工作流中的 8 个下游步骤”，**显示步骤**会列出这些步骤。请参阅[更改的影响](/zh-cn/guides/ai-assistant/impact-preview/)。
  - **保存会拒绝的内容。** **保存**上方的提示条会在您编辑时运行步骤的检查，每个问题旁有**转到**，表达式编辑器会在您输入时检查表达式。请参阅[保存会拒绝的内容](/zh-cn/guides/ai-assistant/check-while-you-edit/)。
  - **审查单个工作流。** 工作流画布或**步骤**网格上的**检查**会运行 Weave 的检查，以及分摊和行级安全检查。请参阅[审查单个工作流](/zh-cn/guides/ai-assistant/weave-findings/#审核单个工作流)。

- **为您的工作区关闭任何 Weave AI 功能。** 工作区管理员在页眉 **Weave** 按钮上选择 **AI 功能…**，即可分别开启或关闭 Weave 聊天、修复助手、导入和导出助手、表达式助手、根据描述生成 SQL、工作流审查摘要或入门图表。在管理员关闭之前，所有功能均为开启状态，Weave 的检查和发现项始终保持开启，每次更改都会记录在安全日志中。请参阅 [AI 功能](/zh-cn/guides/ai-assistant/weave-ai-features/)。

- **在 Allocation Split 步骤上试用驱动因素假设分析。** 右键单击该步骤并选择**假设分析…**，即可查看在使用不同驱动因素取值、驱动因素表的另一列，或另一张具有相同键的表中的数值列时，该步骤会如何分摊其成本。最多可比较 10 个方案，每个方案都根据步骤上次运行的结果精确计算到分，并可查看谁受益、谁受损，以及哪些行将得不到任何分摊。**细分依据**显示每个成员的变化落在哪些科目或其他值上，**后续步骤**会把方案延续到由分摊输出生成的表中。不会重新运行任何内容，也不会更改任何数据。请参阅[试用驱动因素假设分析](/zh-cn/guides/allocations/results/driver-what-if/)。

- **将项目迁移到 Lakehouse v2 时，从就绪检查到撤消都有引导。** **检查迁移就绪状态**会将表、视图、步骤、仪表板、数据共享和容量报告为畅通、需要审查或受阻，并对每个发现提供通俗的说明。**在 v2 上试用…** 按钮会创建一个关闭计划并将 ERP 过账设为模拟模式的私有试用副本。可立即开始迁移，也可在您选择的时间开始。迁移期间项目的计划会暂停，完成后恢复，并在迁移结束时通过消息和电子邮件通知您。**变更内容…** 按钮报告每张表的结果，**撤消迁移…** 按钮可在可撤消的时间窗口内将项目恢复到 Lakehouse v1。请参阅[将项目迁移到 Lakehouse v2](/zh-cn/guides/data/migrate-project-lakehouse/)。

  - **针对每个分析路径和列的指导。** 每个分析路径都有**提示指引**（最多 1,000 个字符），用于说明始终适用的筛选条件、财年日历和您的业务术语。列备注会随表的列一起传递给助手和 LLM 步骤，使代码或标志按您的本意被理解。请参阅[让路径对 AI 助手更有用](/zh-cn/integrations/ai-coding-agents/analysis-paths/#让路径对-ai-助手更有用)。
  - **Copilot 能做更多。** Microsoft 365 Copilot 中的 PlaidCloud 代理可创建 CSV、Excel、PowerPoint 和 Word 文件，根据您的指标回答业务数字，对整张表的细分结果求和，并解释分摊的工作原理。管理员下载更新后的软件包，并在 Teams 管理中心中更新。请参阅 [Microsoft 365 Copilot](/zh-cn/integrations/microsoft-365-copilot/)。
  - **一次调用完成更多。** 助手可以在服务器端对表分组并汇总（先应用行访问权限），搜索并阅读 PlaidCloud 的文档，使用只写凭据创建完全配置好的文档账户（包括 OneDrive 和 SharePoint），移除标签（而不仅是添加），并处理您在 PlaidCloud 中看到的视图。请参阅[分析路径](/zh-cn/integrations/ai-coding-agents/analysis-paths/#通过-mcp-使用)和 [AI 代理入门](/zh-cn/integrations/ai-coding-agents/getting-started/)。

## 变更

- **一个 Weave 选项卡同时包含您的发现项和 Weave AI 聊天。** 聊天是 **Weave** 选项卡内位于**发现项**之后的选项卡。每个发现项是一张卡片，带有各自的**修复**、**转到**和**标记为已读**按钮，虚线卡片表示 Weave 无法检查的内容，筛选标签按需要关注的内容过滤列表。关于表达式的发现项会指出错误所在位置，表达式本身位于 **Weave 如何得知**下方。运行结束时，Weave 对每个问题只提及一次，同一项目的消息会合并为一条而不是堆叠出现。由于 Weave 只重新检查发生变化的内容，该选项卡在大型项目中也能快速打开。工作流列表中的 Weave 列已移除。请参阅 [Weave 选项卡](/zh-cn/guides/ai-assistant/weave-tab/)和[在运行结束时收到通知](/zh-cn/guides/ai-assistant/weave-findings/#运行结束时收到通知)。

- **Ctrl/Cmd-K 可在任何屏幕上打开命令面板。** 在您输入之前，它会列出您最近打开的内容和可执行的操作：转到主页、项目、仪表板或文档，在浅色和深色之间切换，连接您的 AI，或获取帮助。输入内容会同时缩小两个列表的范围，输入两个字符之后，还会搜索项目、工作流、表、仪表板和 Panel 应用。请参阅[搜索和命令](/zh-cn/guides/launcher/#搜索和命令)。

- **步骤在保存时而不是运行时发现问题。** 保存的步骤如果其设置会导致运行失败或得到错误结果，将被拒绝，并附带说明需要更改什么的消息。每个步骤的参考页面都列出了它所做的检查。已映射的源列如果步骤或其源表中已不存在，会以红色标出，保存时会打开一个包含**全部移除并保存**、**仍然保存**或**取消**的对话框。联接、查找和空间步骤会保留这类行，不再自行删除。使用了未定义变量的表达式会指明该变量，运行时被拒绝的步骤会用通俗的语言说明原因。请参阅[不再列出的源列](/zh-cn/reference/workflow-steps/tables/table-extract/#不再列出的源列)、[源表中缺失的列](/zh-cn/reference/workflow-steps/tables/table-extract/#源表中缺少的列)和[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。

- **缺失或为空的数据源永远不会是错误。** 文件缺失或为空的文件导入会带着指明路径的警告完成，并使其目标表保持为仅含声明列的空表，因此后续步骤读取到零行。针对缺失或为空文件夹的文档步骤会报告“Nothing to process”，工作流继续运行。远程文件步骤在路径缺失时发出警告，并拒绝不安全的路径。文件缺失检查适用于 OneDrive、SharePoint 和 SFTP。批处理表为空的**报表：批量生成**会带着警告完成，并且不生成任何报表。请参阅[导入步骤](/zh-cn/reference/workflow-steps/import/)、[文档工作流步骤](/zh-cn/reference/workflow-steps/document/)和[文档路径条件](/zh-cn/guides/workflows/step-conditions/#文档路径条件)。

- **大型工作流运行可靠，停止会取消导入和导出。** PlaidCloud 繁忙时，步骤会等待资源而不是失败，并且随着步骤排队会增加资源。Import External Database Tables 一次最多并行运行 10 张表。如果运行步骤的服务器丢失，替换其输出的步骤会自动重新运行，无法安全重复的步骤则会失败一次并提示 *interrupted* 消息。**停止**会取消正在运行的导入和导出作业，已停止的运行会报告为已停止。请参阅[中断的步骤](/zh-cn/guides/workflows/run-a-workflow/#已中断的步骤)和[暂停、停止和恢复](/zh-cn/guides/workflows/run-a-workflow/#暂停停止和恢复)。

- **每个 Lakehouse 的存储和计算方式都相同。** 来自导入 CSV、导入 XML 或导入表归档的空字段会作为 null 加载，因此后续测试 `= ''` 或 `= 0` 的步骤需要改为测试 null。`cast(x, Float)` 在所有位置都是 64 位，因此大额数字不会丢失位数，PlaidCloud 创建的 Float 列为双精度。JSON 列、**表：删除行**以及聚合的条件在每个 Lakehouse 上都可使用。自行生成结果的步骤（例如 Solver、Forecast，以及在 pandas 中运行的 Pivot 和 Allocation Split）会将结果作为带类型的数据加载，速度快得多。表资源管理器显示数值列的最小值、最大值、平均值、总和、标准差和方差。请参阅[转换为 Float](/zh-cn/reference/workflow-steps/common/advanced-data-mapper-usage/#转换为-float)和[列数据和唯一值计数](/zh-cn/guides/data/table-explorer/#列数据和唯一值计数)。

- **文件导出会保留类型。** Parquet 文件将整数列保留为整数，以微秒存储时间戳，并将时区标记为 UTC。Avro 文件保留日期、时间戳和布尔值的类型，单表 Avro 导出以导出名称命名。为 Parquet 导出选择多个文件时，会停止并提示 Parquet 只写入单个文件。非常大的 Parquet、ORC 和 JSON 导出会边读取行边写入，因此不再出现内存不足，Parquet 使用您选择的压缩方式。版本 1.2.33 或更高的 PlaidLink 代理会以 Parquet 文件的形式接收导出的表。请参阅 [Export to Parquet](/zh-cn/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro](/zh-cn/reference/workflow-steps/export/export-to-avro/) 和[数据如何到达代理](/zh-cn/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#数据如何到达代理)。

- **ERP 过账遵循每个计划的模式，不确定的应答会被保留以便您检查。** 计划事件保留自己的过账模式（**实时**、**模拟**或**关闭**），并以项目的设置为上限，**运行所选事件**会使用每个事件自己的模式。PlaidCloud 无法确认的 ERP 应答（例如超时或服务器错误）会作为存疑保留，而不是记录为已拒绝，同一笔过账也不能被冲销两次。过账登记簿会列出 **reversal outstanding** 的过账，架构师在项目主页的 **ERP 写入授权**中授权项目进行过账。请参阅 [ERP 过账模式](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)、[冲销](/zh-cn/guides/connections/posting-register/#冲销)和[授权项目过账](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)。

- **行访问权限跟得上分组变化，并说明问题所在。** 单点登录在用户登录时设置的组成员身份，会在约 15 分钟内同步到仪表板行访问权限，默认组的新成员会在约一分钟内获得其对应的行。当某项限制没有过滤任何内容时，行访问窗口会发出警告，可处理包含 `&`、`/` 或 `%` 的列名，并在同步失败时显示带原因的**错误**，或显示带**重试**按钮的**正在重试**。请参阅[保持仪表板同步](/zh-cn/administration/access/managing-security-groups-and-assignments/#保持仪表板同步)。

- **用户定义函数在 Python 3.14 上运行，并使用更新的库。** 大多数函数无需更改即可运行。导入 numba 的函数，或导入 Python 已移除的标准库模块（如 `cgi` 或 `telnetlib`）的函数，现在会失败，需要重写。Forecast 的 AutoTheta 边界可能与之前的运行略有不同。请参阅 [User Defined Transform](/zh-cn/reference/workflow-steps/general/user-defined-transform/)。

- **完整代理访问已弃用，并将于 2027 年 1 月 15 日移除。** 使用**完整**访问权限的 LLM 步骤会记录一条警告。请改用**读取和写入**，此时代理通过 PlaidCloud 的写入工具更改数据，而 LLM 步骤只写入勾选了**写入**的绑定。请参阅[代理访问](/zh-cn/integrations/ai-architecture/llm-providers/#代理访问)。

- **文档账户更易于设置和浏览。** OneDrive 或 SharePoint 账户的文件浏览器会打开起始路径下的文件夹。Google Cloud Storage 账户需要有效的服务账户密钥，没有密钥的现有账户在您添加密钥之前将无法工作。被拒绝的设置会自行说明原因，**管理账户**中未使用的备份图标已移除。请参阅[添加 Google Cloud Storage 账户](/zh-cn/guides/documents/adding-accounts/add-google-cloud-storage-account/)和[备份文档账户](/zh-cn/guides/documents/account-management/managing-document-account-backups/)。

- **Project 应用对发票、行程和补报工时的处理更加完整。** 新发票从主项目开始，由主项目提供客户和采购订单号。删除草稿发票会使其工时和行程重新变为可计费，**AR 收件人**设置发票提交时通知哪些人。行程抽屉显示每一行的供应商、类别和审核状态，**添加补报工时**会为已批准的周开启一张工时表。请参阅[使用 Project 应用跟踪工时和费用](/zh-cn/guides/time-expense/track-time-and-expenses/)。

- **删除所有未被任何步骤引用的表的 API 调用已移除。** 请改为按 ID 删除表。

- **应用中的其他小改动。** 双击账户、仪表板、成员、组或设置列表中的某一行即可将其打开。空的**维度**、**数据编辑器**、**UDF** 和**步骤**选项卡会说明下一步该做什么，没有应用的成员会进入启动器。步骤的表选择器会显示表最后更新的时间（[查看源表最后更改的时间](/zh-cn/guides/workflows/create-workflow/#查看源表最后一次更改的时间)）。Export External Database Tables 在自己的选项卡上映射列，**报表：批量生成**不再显示未使用的 **Report Constants** 部分。Convert Encoding 可识别中欧、土耳其和阿拉伯语编码。指向已移除屏幕的链接会说明这一点。

## 修复

- **AI 助手在您批准之前不会更改任何内容，并按原样显示名称。** 以前，把步骤构建到新表时，表会在您批准之前就被创建；现在表和步骤会在您批准后一起创建，创建项目、工作流或维度，复制表，以及更改表属性或标签时也会先询问。批准只在您的下一条回复中有效。助手提议的导入或导出会按名称显示其表、文档账户和工作流，不会与不存在或您无法打开的对象一起提供。带下划线的名称会原样显示，不再变成斜体，表和代码在深色主题下清晰可读，图表会正常绘制而不是显示为文本，表达式编辑器的 Weave 面板会读取您正在编辑的表达式。即使某张表没有名称，助手也能列出项目的表；即使某个步骤读取或写入多张表，助手也能回答哪些步骤读取或写入某张表，而不是因错误而中断。请参阅[构建工作流步骤](/zh-cn/guides/ai-assistant/weave-tab/#构建工作流步骤)。

- **文件导入会读取您指向的内容。** 导入 Excel 可读取整列范围和 XLSB 工作簿，可在压缩的工作簿中找到工作表，并且不再因带有填充或换行的表头而失败。导入 CSV 遵循**跳过行数**，因此表头之上还有若干行的文件（例如 SAP 列表导出）可按列名导入，并使用默认的分隔符、引号和转义字符运行。一个源列可以为多个目标列提供数据，所有列均为固定值的导入会加载每一行，使用大写压缩扩展名命名的文件会被解压，未更改则跳过的导入会重新加载被清空的表。要求 AI 助手从**项目默认值**导入文件时，会读取项目的默认文档账户，并在项目未设置时明确告知。带有较新列类型的 Parquet 文件可在 Documents 中打开。请参阅[导入 Excel](/zh-cn/reference/workflow-steps/import/import-excel/#读取内容)和[导入 CSV](/zh-cn/reference/workflow-steps/import/import-csv/#行选择)。

- **工作流步骤按配置保存和运行。** Table: Upsert 步骤可再次保存，其**更新键**列也已恢复。表：项目间复制会指明其目标项目，并通过数据共享读取。文档：将仪表板保存为 PDF 会保留列类型，Table: Union Distinct 和表：全部合并按名称匹配列。Multi-Table Join 可保存多个输入，并接受带空格的列名。Table Lookup 会忽略其查找列上的聚合设置，SCD-2 截至日期联接可将变量用作日期。LLM 步骤可在早于 4.6 的 Claude 模型上运行，并且在 AI 助手编辑它们时保留其模型。REST 请求发送的行值只编码一次，导出到远程数据库会提交其行。请参阅[更新键](/zh-cn/reference/workflow-steps/tables/table-upsert/#更新键)、[数据共享管理](/zh-cn/reference/workflow-steps/tables/frame-project-copy/#数据共享管理)和 [Multi-Table Join](/zh-cn/reference/workflow-steps/tables/table-multi-table-join/)。选择工作流的步骤（例如 Workflow Delete、Copy、Rename 和 Stop）会保留已不存在的工作流，并显示为 *id (missing)*，而不是切换为列表中的第一个工作流。

- **工作流运行会正常完成。** Workflow Loop 会在每次迭代时运行循环的工作流，迭代容器和在一次运行中被多次运行的工作流也是如此。从某个步骤开始或在并行组内部开始的运行，会运行正确的步骤并完成。长时间运行的导入或导出绝不会被启动两次，在 PlaidCloud 更新期间不会停滞，以服务器错误结束的操作也不会被重新发送。数据库驱动程序崩溃只会使其自身步骤失败，并附上数据库给出的原因。运行历史记录会统计每个步骤的行数，在工作开始前就失败的步骤会将原因写入工作流日志。请参阅 [Workflow Loop](/zh-cn/reference/workflow-steps/workflow-control/workflow-loop/) 和[运行历史记录](/zh-cn/guides/workflows/advanced-workflows/#运行历史)。

- **项目的复制、导入和打开不再出现意外。** 项目导入会保留其能够恢复的一切，并在**导入结果**窗口中列出遗漏的内容，同时显示进度、说明失败原因，并可重试。当项目含有变量时，复制所选对象也能正常工作。打开项目不再更改其设置，**导入您自己的数据**会导入您的 CSV，在 PostgreSQL 数据仓库上创建表也能正常工作。App Runner 应用会在 PlaidCloud 更新时自动刷新，并且对限制行的项目的查看者同样有效。请参阅[归档的部分内容未导入时](/zh-cn/guides/projects/archive-a-project/#归档的部分内容未能导入时)和[保持应用为最新](/zh-cn/guides/workflows/use-converted-alteryx-apps/#保持应用为最新)。

- **维度和分摊的加载与读取正确无误。** 父子加载会将父级为空的行保留为顶层成员，对于任何类型的加载，位于主层次结构之外的成员都会被第二个备用层次结构拒绝。将成员移到其层次结构中不包含的父级之下会被拒绝，维度步骤会指出它找不到的维度，粘贴含空白的列时每个值都保持在原来的行上。读取大型维度不再拖慢工作区中的其他所有人。维度属性的**层次结构**保持为**未指定**的分摊规则可以运行。请参阅[加载到备用层次结构](/zh-cn/reference/workflow-steps/dimensions/dimension-load/#加载到备用层次结构)和[维度类型属性与成员选择器](/zh-cn/guides/dimensions/dimensions/#维度类型属性和成员选取器)。

- **工作流画布和屏幕表现正常。** **钻取到工作流**会在其画布上打开高级工作流，画布可以打开每个工作流，并在无法读取布局的一部分时告知您。放不下的工具栏按钮会移到**更多**菜单中，列表在您保存后立即更新。通知显示完整的消息，警告在**日志**选项卡中显示警告图标，表资源管理器会在某列的概要分析失败时说明，数据编辑器会保持空日期单元格为空。在开启列筛选的情况下保存数据编辑器，会保留被筛选隐藏的行，包括在您添加、删除或移动行之后。允许更改的用户可在可编辑状态下打开用户定义函数编辑器。请参阅[画布无法打开工作流时](/zh-cn/guides/workflows/advanced-workflows/#画布无法打开工作流时)。从**表**列表中删除表时，会列出仅通过变量路径（例如 `/Periods/{period}/Sales`）引用某张表的步骤，且只有在您强制删除时才会删除该表。请参阅[删除](/zh-cn/guides/projects/managing-tables-and-views/#删除)。

- **成员和连接按预期工作。** **添加工作区成员**适用于已有账户的用户（包括通过单点登录创建的账户），并且绝不会降低其已持有的项目角色。ODBC 连接通过 PlaidLink 代理所在计算机上的 DSN 或驱动程序进行连接。拒绝您的 OAuth 凭据的提供商会提示您重新输入或重新授权，Databricks 示例和导出会刷新即将过期的令牌，旧数据库类型的连接可以删除。**使用位置**包含通知步骤，免费工作区会保留每日、每周和每月备份。请参阅[成员管理](/zh-cn/administration/access/member-management/)和 [ODBC](/zh-cn/reference/connectors/databases/odbc/)。

- **REST API 和 AI 助手工具完全按您的要求执行。** 对成员、组或计划事件的部分更新只会更改您指定的字段，因此已暂停的事件会保持暂停。从指定步骤开始运行时会从该步骤开始，恢复表快照时会保留一个安全快照和审计记录。AI 工具的驱动因素假设分析只在与您的模型实际所做的拆分一致时才作答。过去因服务器错误而失败的请求，现在要么成功，要么说明问题所在。请参阅[追踪分摊](/zh-cn/integrations/ai-coding-agents/tracing-allocations/)和[回退或恢复快照](/zh-cn/guides/data/table-snapshots/#回退或还原快照)。

## 安全

- **AI 助手始终在您的权限范围内。** 助手的数据查询在运行前会按结构进行检查，并且只运行单个读取查询。只读 AI 连接（包括 Microsoft 365 Copilot）无法导出文件、保存仪表板 PDF、将行复制到另一个项目，或通过 REST 连接发送更改。通过 AI 助手进行的导入会以您的身份在您指定的项目中运行，对话只能由发起者本人继续。助手和表引用会省略您的角色所隐藏的表、步骤、工作流和维度，Weave 对您无法打开的失败步骤只计数，不会列出名称。请参阅[访问级别](/zh-cn/integrations/microsoft-365-copilot/#访问级别)、[您的角色隐藏的内容](/zh-cn/guides/ai-assistant/weave-tab/#您的角色所隐藏的内容)和[管理过往对话](/zh-cn/guides/ai-assistant/weave-tab/#管理过去的对话)。

- **ERP 过账无法绕过其控制。** 启用职责分离后，冲销需经过过账登记簿，并在其中适用审批。复制或导入的项目不再继承过账权限，SAP 和 EBS 过账不能直接发送给代理，处于仅测试模式的 SAP Post 步骤需要与实际过账相同的权限。一个未公开、可绕过这些检查向 Sage Intacct 过账的端点已被移除。ERP 和 REST 连接的错误消息中不再包含凭据。请参阅[职责分离](/zh-cn/guides/connections/posting-register/#职责分离)。

- **机密信息为只写，只有所有者才能决定谁可使用连接。** 文档账户的密钥、密码和令牌在保存后不会再次显示，更改账户的连接位置时需要再次提供机密信息。步骤中的密码和密钥只保存在变量中；已经输入到步骤中的机密信息已移入仅架构师可见的项目变量。多行凭据在输入时会被掩码。只有连接的所有者或工作区管理员才能更改谁有权访问该连接。请参阅[已保存的机密信息为只写](/zh-cn/guides/documents/adding-accounts/#已保存的机密为只写)、[密钥保存在变量中](/zh-cn/reference/workflow-steps/document/encrypt-decrypt-file/#密钥存放在变量中)和[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

- **您无法使用的文档账户对您保持关闭。** 检查文件是否存在、读取 Parquet、Avro、ORC 或 Delta 文件的列、使用**填充**填充导入步骤的列，以及 AI 助手的文件检查，现在都会像浏览一样拒绝您无权访问的账户。

- **只有工作区管理员才能更改工作区管理员。** 编辑、停用或删除管理员，更改其所属组，以及将某人设为管理员，都需要工作区管理员权限。请参阅[更改工作区管理员](/zh-cn/administration/access/member-management/#更改工作区管理员)。

- **数据共享只对获得共享的项目的成员有效。** 通过共享读取需要在接收项目中拥有角色，写入则需要**写入**共享以及在该项目中拥有管理者或架构师角色。请参阅[在项目之间共享数据](/zh-cn/guides/projects/managing-projects/#在项目之间共享数据)。

- **恢复只适用于所指定的项。** 恢复较早的版本时恢复的是该项本身，权限检查也针对该项。如果维度备份文件的内容不属于其自身标头所指的维度，将被拒绝。请参阅[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。

- **模板、导入和归档会拒绝不安全的内容。** 导出模板和报表模板在沙盒中渲染，沙盒只能读取提供给它们的数据。导入根据自身设置构建加载查询，包含 PlaidCloud 归档中绝不会出现的内容的项目归档会被拒绝，会与另一个项目共享报告架构的项目标识符也会被拒绝。请参阅[模板可以使用什么](/zh-cn/reference/workflow-steps/export/export-templated/#模板可以使用的内容)和[恢复归档](/zh-cn/guides/projects/archive-a-project/#还原归档)。

- **仪表板遵循 PlaidCloud 登录和您的行访问权限。** 仪表板缩略图以您的身份渲染，账户只来自 PlaidCloud 登录，仪表板只能从导出所生成的 ZIP 文件导入。请参阅[导入现有仪表板](/zh-cn/guides/dashboards/learning-dashboard/#导入现有仪表板)。

- **启动工作流运行不再返回该运行的凭据。**

- **运行用户定义函数的环境不再包含 PySpark 的 Java 库，** 这些库存在已知漏洞。PySpark 的 DataFrame 和 SQL API 仍可连接到您的 Spark Compute Cluster，但导入 `SparkContext` 或 `RDD` 的函数现在会失败。请参阅 [PySpark 入门](/zh-cn/integrations/pyspark/getting-started/)。

- **附件、恢复和转换只读取您可使用的账户。** 通过电子邮件发送文件、从文件恢复维度或表归档、检查或导入表包、通过模板填充 Excel 导出，以及转换 Alteryx 工作流，现在都会拒绝您无权访问的文档账户。将维度备份到文档账户需要对该账户具有写入权限。工作流步骤不受影响，但通过电子邮件发送文件、恢复表或填充 Excel 模板的步骤不再能从个人临时驱动器读取。
