**工作区**页面列出您可以管理的 PlaidCloud 工作区。可用它创建工作区、编辑工作区设置、打开工作区、打开仪表板、打开 SQL 控制台、查看日志和指标，或对所选工作区应用批量操作。

<Aside type="caution">
	删除会移除工作区及其关联的数据。删除工作区之前，请确认备份和保留要求。
</Aside>

## 工作区列表

工作区表包括名称、唯一 ID、版本、发布渠道、状态、暂停状态、创建时间、预配状态、集群、维护日和维护时间。该表支持搜索、刷新、行操作和批量操作。

可用的行操作包括：

| 操作 | 说明 |
| --- | --- |
| 查看 | 打开只读的工作区详细信息。 |
| 编辑 | 更改工作区配置。 |
| 删除 | 删除工作区。 |
| 主页 | 打开工作区应用程序。 |
| 仪表板 | 打开工作区仪表板服务。 |
| SQL | 打开工作区 SQL 控制台。 |
| 日志和指标 | 打开工作区的运维日志和指标。 |

四个服务操作（主页、仪表板、SQL 以及日志和指标）仅在正在运行的工作区上显示，且仅针对该工作区已启用的服务。正在创建的工作区完全不显示服务图标，因此不会出现点击后无处可去的链接。

## 预配状态

创建工作区需要几分钟时间，在完成之前，工作区虽已存在但无法打开。**创建时间**、**状态**和 **Provisioning** 列会告诉您进度，工作区详细信息对话框中的 **Provisioning** 选项卡会显示同一工作区的相同信息，以及当前为其发布的服务 URL。

| 列 | 说明 |
| --- | --- |
| 创建时间 | 工作区记录的创建时间，也是其首次预配尝试的开始时间。 |
| 状态 | 预配所处的阶段，例如 `activating`。已完成的工作区显示为 `running`。 |
| Provisioning | 将阶段归纳为一个词：`provisioning`、`running`、`failed`、`paused`、`trashed` 或 `deleting`。 |

如果工作区在同一阶段停留超过约半小时，即表示已停滞；显示 `failed` 的工作区则已停止。无论哪种情况，请联系 PlaidCloud 支持团队，并提供工作区 ID 和所显示的阶段。失败详情涉及 PlaidCloud 的内部组件，因此保存在 PlaidAdmin 区域，而不在此处显示。

<Aside type="note">
	工作区在部署工具中看起来可能一切正常，但仍无法使用，因为部署完成并不等同于工作区完成了自身的设置。**Provisioning** 列报告的是工作区自身的设置情况，它决定了您能否登录。
</Aside>

## 单点登录

让用户通过公司的身份提供商登录工作区，而不是使用单独的 PlaidCloud 密码。在**工作区**页面上，对相应工作区选择 **Single sign-on**。对话框列出当前的 **Sign-in options**，每项都带有其状态（**开启**或**关闭**）、**Test sign-in** 和**移除**，并可在 **Add an identity provider** 下添加新的选项。

### 计划与登录方式

每个计划（包括 Free (Sandbox)）都包含带多重身份验证（MFA）的密码登录，以及使用 Google、Microsoft（个人或组织的“common”登录）和 GitHub 的社交登录。更高级的计划会增加使用您自己的身份提供商的企业级单点登录：

| 计划 | 新增内容 |
| --- | --- |
| Free (Sandbox) | 除每个计划都包含的登录方式外，无其他内容 |
| Starter | 除每个计划都包含的登录方式外，无其他内容 |
| Team | SAML |
| Business | Microsoft Entra ID 和 Okta |
| Enterprise | 其他 OpenID Connect 提供商和 SCIM |

每个计划都包含其下各级计划的全部内容。在 Free (Sandbox) 和 Starter 上，**Single sign-on** 对话框显示升级提示，而不是身份提供商选项。

如果降级，已添加的提供商仍会列出，您仍可将其移除，但无法添加计划中不包含的新提供商。

### 添加身份提供商

1. 选择 **Identity provider**：**Microsoft Entra ID**、**Okta** 或 **Other (OpenID Connect)**，具体取决于您的计划允许的选项。
2. 使用**复制**复制 **Redirect URI**，并按下文所述在身份提供商中注册。
3. 填写所用提供商对应的字段，然后选择 **Add provider**。
4. 选择 **Test sign-in**，它会打开您的工作区，以便您在隐私窗口中通过新的提供商登录。请在通知团队之前先进行测试。

| 提供商 | 在身份提供商中注册 | 在 PlaidCloud 中输入 |
|---|---|---|
| Microsoft Entra ID | 在 Microsoft Entra 管理中心，使用重定向 URI 注册应用（Web 平台），在 **Certificates & secrets** 下添加客户端密钥，并在 **Token configuration** 下将可选的 `email` 声明添加到 ID 令牌。 | **Directory (tenant) ID**、**客户端 ID**、**Client secret** |
| Okta | 在 Okta 管理控制台中，创建 OIDC Web 应用程序，将重定向 URI 作为其登录重定向 URI，并分配应有访问权限的人员。 | **Okta domain**（例如 `acme.okta.com`）、**客户端 ID**、**Client secret** |
| Other (OpenID Connect) | 使用重定向 URI 注册机密 Web 客户端。 | **Button label**、**Discovery URL**、**客户端 ID**、**Client secret** |

对于 **Other (OpenID Connect)**，PlaidCloud 从发现 URL 读取端点。如果无法从该处读取配置，或颁发者与发现 URL 位于不同的站点，请选择 **Enter endpoints manually**，并填写 **Issuer**、**Authorization URL**、**Token URL**、**JWKS URL**，以及可选的 **Userinfo URL (optional)**。提供商地址必须是 PlaidCloud 可以访问的公共主机。

**Button label** 是用户在登录页面上看到的名称，例如 *Acme SSO*。

### 现有账户与电子邮件验证

- 已拥有相同电子邮件的 PlaidCloud 账户的人员，只需登录该账户一次即可完成关联。PlaidCloud 绝不会仅凭电子邮件匹配就关联账户。
- **Trust email addresses from this provider (new people skip email verification)** 默认关闭。新用户在首次登录时需验证其电子邮件地址。仅当身份提供商能保证其发送的地址可信时，才启用此项。

### 移除身份提供商

选择提供商旁边的**移除**。用户将无法再使用它登录。他们已有的账户会保留，并且可以重置密码后登录。

## 批量操作

选择一个或多个工作区即可使用批量操作。

| 批量操作 | 说明 |
| --- | --- |
| 设置版本 | 将所选工作区固定到指定版本。所有所选工作区必须使用相同的发布渠道。 |
| 暂停 | 暂停所选工作区。 |
| 取消暂停 | 恢复所选的已暂停工作区。 |

## 主要设置

主要设置用于标识工作区、指定所有者并控制发布行为。

| 设置 | 说明 |
| --- | --- |
| 名称 | 工作区的显示名称。 |
| ID | 唯一的工作区标识符，成为工作区标识的一部分，并在创建时设置。 |
| 备注 | 可选的说明或管理备注。 |
| 组织 | 拥有该工作区的组织。 |
| 所有者 | 工作区所有者的电子邮件。 |
| 数据中心（集群） | 工作区运行所在的数据中心或集群。 |
| 发布 | 发布渠道：Rapid、Regular、Stable 或 No Release (pinned)。 |
| 版本 | 具体的已部署版本。 |
| 活动 | 将工作区标记为活动。 |
| 已暂停 | 暂停工作区运行而不删除工作区。 |
| 邀请链接有效期 | 新用户邀请链接保持有效的时长。选项为 12 小时、1 天、2 天、3 天、5 天、7 天、10 天和 14 天。 |

## 发布选项

| 发布 | 典型用途 |
| --- | --- |
| Rapid | 最早收到更新。适用于能够接受较快产品变化的工作区。 |
| Regular | 大多数工作区的默认更新节奏。 |
| Stable | 更新节奏较慢，适用于优先考虑更新稳定性的工作区。 |
| No Release (pinned) | 使工作区保持在所选版本，直到管理员更改。 |

维护时段决定何时应用自动发布更新。

## 自动发布更新

PlaidCloud 持续发布新版本，并自动将其交付到您的工作区。您无需请求或安装更新：当某个版本到达工作区的发布渠道时，PlaidCloud 会在该工作区的维护时段内升级工作区。发布渠道决定版本到达的快慢，维护时段决定升级在一天中的哪个时间进行。

### 版本如何到达工作区

1. PlaidCloud 向某个渠道发布版本。Rapid 最先收到，其次是 Regular，然后是 Stable。
2. 组织中的每个人都会在升级前至少七天收到预先通知电子邮件，其中注明版本和应用日期。
3. 在该通知之后的第一个维护时段，PlaidCloud 会将工作区升级到该版本。默认维护时段为 UTC 时间周日 02:00，可在[维护](#维护)下设置日期和时间。
4. 工作区的**版本**更新为新版本。您或工作区用户无需进行任何操作。

由于工作区只会在自己的维护时段内升级，更新会在可预测的低流量时间到来，而七天的通知让每个组织都有时间针对变更做好规划。

### 通过固定工作区选择退出

要让工作区保持在当前版本，请将其**发布**渠道设置为 **No Release (pinned)**。自动升级会跳过已固定的工作区，该工作区将保持在所选版本，直到管理员选择新版本或将其移回某个渠道。当工作区必须保持不变时（例如在验证周期或受监管的结账期间），请将其固定。

固定只会停止后续的升级，不会撤销已应用的升级。要让已固定的工作区重新向前升级，请选择具体的**版本**，或选择 Rapid、Regular 或 Stable 渠道，该工作区即重新加入自动计划。

## 主题

主题设置用于在工作区的各个入口自定义品牌。

| 设置 | 说明 |
| --- | --- |
| 应用徽标 | 工作区应用程序中显示的徽标。 |
| 启动画面徽标 | 工作区启动画面或登录屏幕上显示的徽标。 |

## 服务

服务设置用于在工作区内启用可选的应用程序和支持服务。

| 设置 | 说明 |
| --- | --- |
| JupyterHub | 为工作区用户启用托管笔记本访问。 |
| Web SQL 控制台（CloudBeaver） | 启用基于浏览器的 SQL 访问。 |
| 仪表板（Apache Superset） | 启用仪表板服务。 |
| 用户表单和工作流（Forms Flow） | 启用表单和工作流应用支持。 |
| 变更数据捕获（Apache Flink） | 启用变更数据捕获处理。 |
| SFTP 访问和 Web UI | 启用 SFTP 访问和 SFTP Web 界面。 |
| 使用 PlaidCloud 代理下载 | 通过 PlaidCloud 代理路径路由下载。 |
| 激活向量数据库（Weaviate） | 启用向量数据库支持。 |
| 激活自定义应用沙盒 | 启用自定义应用沙盒支持。 |
| 激活项目管理应用 | 启用项目管理应用程序。 |

某些服务可能需要在控制平面表单之外进行额外的预配，用户才能使用。

## Lakehouse

Lakehouse 设置控制外部数据库连接和额外的数据库用户。

| 设置 | 说明 |
| --- | --- |
| 启用外部数据库访问 | 允许外部客户端连接到工作区 Lakehouse。 |
| 允许的 CIDR | 以逗号分隔的、允许连接的 CIDR 范围。如果不需要允许列表，请留空。 |
| 拒绝的 CIDR | 以逗号分隔的、被拒绝的 CIDR 范围。 |
| 其他 Lakehouse 用户 | 用于数据库访问的额外 Lakehouse 用户名和密码。 |

请使用能满足用户和集成需求的最窄 CIDR 范围。不再需要访问权限时，请移除未使用的 Lakehouse 用户。

## 维护

维护设置定义工作区的首选更新时段。

| 设置 | 说明 |
| --- | --- |
| 日 | 维护的星期几：周日至周六。 |
| 时间 | 一天中的时间，以 15 分钟为增量。 |

发布渠道升级使用工作区的维护时段。在管理员选择新版本或渠道之前，自动发布渠道升级会跳过已固定的工作区。
