## 说明


为特定工作流制定计划是一种实用的组织工具，PlaidCloud 为此提供了相应的功能。使用事件调度器，可以按月、每月的日期、每周的日期、小时和分钟计划工作流运行，并可指定以哪个时区来解读该计划。



一个计划事件指定某个项目中的一个工作流，以及它运行所依据的计划。如需让多个工作流按相同的节奏运行，请为每个工作流各添加一个事件。



“事件表”列出工作区中的所有事件，包括其运行的项目和工作流、UTC 偏移量、上次运行的状态以及开始和结束时间，还有下次到期运行的时间。



**查看事件的步骤：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“事件调度器”

这将打开**事件表**，其中显示为工作区配置的所有当前事件。

<Aside>如果事件处于活动状态，则会显示“活动”图标。</Aside>

## 创建事件


**创建事件的步骤：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“事件调度器”
4. 单击“Add Scheduled Event”
5. 填写下文所述的详细信息、时区和计划字段
6. 单击“Create”

### 详细信息


**名称**：事件在事件表中的显示名称。必填。



**备注**：关于事件用途的可选说明。



**激活作业并按定义的计划运行**：默认勾选。取消勾选可保存事件但不让其运行；参见[暂停事件](#暂停事件)。



**项目**和**工作流**：此事件运行的工作流。请先选择项目：工作流列表会根据所选项目填充。两者均为必填，且事件创建后即固定不变；如需将事件改到其他工作流，请删除该事件并添加新事件。



### 时区


该计划按此时区解读，时区以 **UTC -12** 到 **UTC +14** 的偏移量选择。默认为 **UTC +0**，按伦敦时间解读，包含英国夏令时。



大多数偏移量对应该偏移量所在地的当地时间，并遵循当地的夏令时：设置为 **UTC -5** 且时间为 09:00 的事件，无论夏季还是冬季，都在纽约时间 09:00 运行，即夏季为 UTC 13:00，冬季为 UTC 14:00。**下次运行**列和[即将进行的运行日历](/zh-cn/administration/scheduled-events/upcoming-runs-calendar/)会显示事件实际的运行时间。

### 计划


计划由五个字段组成：**个月**、**小时**、**分钟**、**每月的日期**和**每周的日期**，每个字段都是一组复选框，顶部有一个**全部**复选框。只要当前时间同时匹配每个字段中已勾选的值，事件就会运行。



每个字段都必须有内容：勾选**全部**以匹配所有值，或勾选所需的单个值。字段完全留空将无法保存事件，提示消息会指出该字段名称，便于您找到。



一些示例：


- **每天 06:30**：在个月、每月的日期和每周的日期下勾选**全部**；在小时下勾选 **06**；在分钟下勾选 **30**。
- **每月 1 日午夜**：在个月和每周的日期下勾选**全部**；在每月的日期下勾选 **01**；在小时和分钟下勾选 **00**。
- **每个工作日 18:00**：在个月和每月的日期下勾选**全部**；在每周的日期下勾选周一至周五；在小时下勾选 **18**；在分钟下勾选 **00**。
- **每 15 分钟**：在个月、每月的日期、每周的日期和小时下勾选**全部**；在分钟下勾选 **00**、**15**、**30** 和 **45**。

<Aside>新事件初始时没有勾选任何内容，因此在选择计划之前不会运行。</Aside>


### ERP过账模式

每个事件都有自己的 [ERP过账模式](/zh-cn/guides/workflows/run-a-workflow/#选择过账模式)：**实时**、**模拟**或**关闭**，其启动的每次运行都使用该模式。未设置模式的事件以实时模式运行，同时项目自身的过账模式上限仍然适用，因此事件的过账自由度永远不会超过其项目所允许的范围。

请通过 API 或 AI 助手设置该模式：在 `PUT /rest/v1/analyze/workflow/scheduled-event` 上设置 `erp_write_mode` 字段（`live`、`simulate` 或 `off`），或在 `workflow_schedule` MCP 工具的 upsert 上设置。此后事件会一直保留该模式。在事件调度器中编辑事件、暂停或重新启用事件都不会改变该模式，因此设为模拟的计划在每次触发时都保持模拟，直到您更改模式本身。

## 编辑事件


**编辑事件的步骤：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“事件调度器”
4. 单击编辑图标
5. 调整所需字段
6. 单击“更新”

编辑时，项目和工作流以只读方式显示：事件始终附属于创建时所针对的工作流。

AI 助手可以通过 `workflow_schedule` MCP 工具编辑事件，只需发送要更改的字段，例如新的名称或计划。未发送的所有字段保持当前值。

## 删除事件


**删除事件的步骤：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“事件调度器”
4. 单击删除图标
5. 再次单击 delete

<Aside type="note">
删除工作流也会删除针对它计划的所有事件。无需先移除其事件，也不会留下任何事件去运行已不存在的工作流。针对其他工作流计划的事件不受影响。
</Aside>

## 暂停事件


**暂停一个或多个事件的步骤：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“事件调度器”
4. 选择一个或多个事件
5. 单击“Disable Selected”

单击**启用所选项**可使它们重新开始运行。暂停的事件会保留其计划和运行历史，只是在重新启用之前不再触发，且其**活动**图标会在事件表中清除。



也可以在编辑单个事件时将其暂停：取消勾选**激活作业并按定义的计划运行**，然后单击**更新**。



## 按需运行事件


**立即运行事件的步骤：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“事件调度器”
4. 选择所需的一个或多个事件
5. 单击“Run Selected Events”

每个事件都以自己的 [ERP过账模式](#erp过账模式)运行，因此设为模拟的事件会以模拟方式运行。如果某个事件的工作流已在运行，则会跳过该事件，运行后的消息只统计已启动的事件。
