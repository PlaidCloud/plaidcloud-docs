**使用情况报告**显示工作区中谁在使用什么：成员打开了哪些屏幕、仪表板、应用和笔记本，有多少成员会再次访问，以及他们接下来去了哪里。借助它可以了解成员采用了哪些功能，哪些仪表板和应用物有所值，以及人们在流程的哪个环节流失。

在**身份**选项卡侧栏的**洞察**下，选择**使用情况报告**即可打开。它会作为“身份”内的页面在侧栏旁边打开，而不是在单独的窗口中打开。

## 谁可以查看

使用情况报告所需的权限与安全日志相同：`identity.security_log.read`。没有该权限时不会提供此按钮，而直接打开报告的成员会看到无权访问的提示。

报告会在以下位置按成员显示使用情况：**成员**选项卡、从**内容**和**概览**打开的成员列表，以及包含成员 ID 的**按成员划分的每日活动**和**首次使用**导出。其他所有内容都是在全体成员范围内统计的。请仅向应当查看个人活动的人员授予该权限。

## 统计内容

使用情况报告整合了五个区域。可从**区域**中选择其一，也可保持为**全部区域**。

| 区域 | 记录的内容 |
|---|---|
| PlaidCloud 应用 | 成员打开的屏幕以及在应用中执行的操作。 |
| 仪表板 | 仪表板和图表的查看次数。 |
| 应用 | 应用访问次数以及成员在每个应用中花费的时间。 |
| 笔记本服务器 | 成员在笔记本服务器会话中花费的时间。 |
| 笔记本 | 成员打开和保存的笔记本。 |

笔记本服务器和笔记本是两个独立的区域，因此可以任选其一。应用则是单一区域。笔记本事件仅针对运行在默认笔记本镜像上的笔记本记录，自定义镜像不会报告这些事件。

<Aside type="note">
报告中的每一天都是一个 UTC 日。在美洲工作到深夜的成员可能会出现在次日。
</Aside>

## 阅读报告

页面顶部的栏中包含筛选器。每个选项卡在首次打开时加载，更改筛选器时会再次加载。

| 筛选器 | 作用 |
|---|---|
| **区域** | 将报告限定到某一个区域。在**漏斗**（为每个步骤选择区域）和**导出**（有自己的选项）上会隐藏。 |
| **分组** | 将报告限定到某个安全组的成员。请参阅[限定到某个分组](#限定到某个分组)。 |
| **日期范围** | **最近 7 天**、**最近 30 天**、**最近 90 天**、**最近 180 天**、**本月**、**上月**，或**自定义…**（可设置最长 180 天的开始和结束日期）。 |
| **刷新** | 重新加载数据（F5）。**已更新**显示数据上次加载的时间。 |

日期范围由所有选项卡共用，您所在的选项卡和所选范围会保存到您的账户设置中，因此在任何计算机上，页面都会在您上次离开的位置重新打开。更改范围会重新加载当前选项卡，其他选项卡则在打开时重新加载。每个选项卡都有各自的说明：将鼠标指向标题或数字即可查看其含义。

选项卡加载时会显示占位符，而不是空白页面。如果报告无法加载，选项卡会显示原因，并提供**重试**和 **Copy details**。当某个范围内没有活动时，选项卡会建议尝试更长的范围。若要打开某一行，请双击该行，或选中后按 Enter。**返回**可从打开的项目返回列表。

### 概览

所选范围内的关键数字，每个数字都带有一个箭头和百分比，表示相对于上一个等长周期的变化：

| 数字 | 含义 |
|---|---|
| **活动成员** | 有任何活动的成员。 |
| **新成员** | 在该范围内首次出现的成员。如果范围的起点早于开始采集的时间，则显示为破折号，因为无法确定更早的首次使用。 |
| **回访成员** | 在该范围之前就已首次出现的活动成员。 |
| **活动分钟数** | 估算值：每个存在任何操作或查看行为的五分钟时段计为五分钟。 |
| **应用打开分钟数** | 应用和笔记本服务器处于打开状态的时间，包括空闲时间。与活动分钟数分开统计。 |
| **事件** | 记录的所有内容。 |

无法关联到成员的事件会在数字下方的一行中单独统计。它们计入事件，而不计入成员。

**Highlights** 最多列出四项值得关注的内容，每一项都链接到可查看更多信息的位置：

- 与上一个周期相比，活动成员增加或减少 10% 或更多。
- 在该范围内不活跃的成员数量。选择它可打开未激活成员的列表。
- 无人打开的仪表板和应用的数量。选择它可打开**内容**，并将未使用的项目排在最前面。
- 使用最多的项目（至少有五位成员使用过）。

要点仅在有内容可说时才会出现。当 PlaidCloud 无法计算某个数量时，该要点会被隐藏，而不是显示 0；如果没有任何突出之处，则会显示 **No notable changes in this range.**

**Most used** 列出每个屏幕、仪表板、图表或项目及其区域、事件、成员数和**覆盖率**，即在该范围内使用过它的活动成员所占的比例。列选择器可添加**事件**和 **Events not linked to a member**。**按月（全部历史）**显示每个月的活动成员、日均成员数和**用户粘性**，当月份仍在进行或仅部分覆盖时会附带说明。用户粘性是日均活动成员数除以当月的活动成员数，因此值越高，表示人们在更多天数回访。

### 活动

按**每天**、**每周**或**每月**周期划分的活动成员，以及**按首周划分的留存**：对于成员首次出现的每一周，显示 **Cohort size**，以及其中在之后每一周仍然活跃的成员所占比例。带星号的周期并未完全落在该范围内。

### 路径

屏幕之间最常见的跳转，以**移动自**、**移动至**和**经过次数**显示，跨区域统计。路径最多涵盖最近 30 天。

### 成员

**显示**可在两个列表之间切换：

- **活动**为该范围内出现的每位成员提供一行：姓名、用户名、活动天数、事件、活动分钟数、应用打开分钟数，以及首次和最后一次出现的时间。打开某一行可查看该成员每天的事件及其使用的内容。
- **未激活**列出在该范围内没有活动的当前成员，以及其成为成员的时间和最后一次出现的时间。**None recorded** 表示在保留的历史记录中没有活动，历史记录最长保留 25 个月，且仅从开始采集时算起。可使用**下载 CSV**下载该列表。未激活是指在所有区域均无活动，因此会忽略**区域**。已从工作区移除或已停用的成员不会被列出或统计。

### 内容

每个仪表板、应用和笔记本，附带其**类型**、**成员**、**覆盖率**、**打开次数**、**应用打开分钟数**（仅限应用）、每周**趋势**以及**上次使用**时间。选择**类型**可缩小列表范围，或选择 **Hide unused** 以排除无人打开的项目。打开某一行可查看使用过该项目的成员，并可使用**下载 CSV**下载任一列表。列表下方的说明会指出哪些类型尚未采集，或仅从较晚的日期开始采集。

### 限定到某个分组

**分组**将**概览**、**内容**和**未激活**列表限定到某个安全组的成员。选择**所有人**可取消限定。在框中键入内容可搜索工作区的分组。报告使用的是分组当前的成员关系，而不是活动发生时的成员关系，并在筛选器旁边说明了这一点。

- **活动**成员、**活动**、**路径**和**导出**不受限定。这些选项卡上的筛选器处于禁用状态，并会说明原因。
- 对分组不显示**按月**，因为月度历史是针对所有人保留的。
- 没有成员的分组或已不存在的分组会返回空结果，并给出相应的警告，而不是错误。
- 如果无法读取工作区的安全组，则不提供该筛选器。

### 导出

将摘要下载为 CSV。选择**摘要**和**日期范围**，然后选择**下载 CSV**。范围最长为 25 个月。

| 摘要 | 内容 |
|---|---|
| **每日活动** | 每天、每个区域、每个事件和每个主题的成员和事件。 |
| **按成员划分的每日活动** | 与上面相同，但按成员划分，并包含成员 ID。 |
| **每月采用情况** | 每个月、每个区域、每个事件和每个主题的成员和事件。 |
| **每月活动成员** | 每个月和每个区域的活动成员。 |
| **首次使用** | 每位成员首次使用各区域的时间，并包含成员 ID。 |

导出使用的是您在选项卡上方选择的区域。较大的摘要会以每批最多 50,000 行的方式下载，页面会将它们合并为一个文件。如果文件超出页面可构建的大小，则会保存已有内容并告知文件不完整：请选择更短的范围以获取其余部分。

每次导出都会向安全日志写入一条记录，说明谁导出了哪个摘要、范围以及行数。跨多个批次的摘要会为每个批次各写入一条记录。

若要按计划将这些数据放入表中，请改用 [Get Workspace Usage 步骤](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。

<Aside type="caution">
每月摘要中，每个事件都包含一个合计行，其主题为 `*`。该行是该事件所有主题的去重成员数和事件数。请不要将其与各主题行相加，否则所有内容都会被重复计算。
</Aside>

### 漏斗

查看有多少成员完成了一系列步骤。步骤是来自某个区域、针对特定主题或**任意主题**的事件。漏斗使用您选择的日期范围，最长为最近 90 天；如果缩短了较长的范围，会给出说明。

1. 选择**添加步骤**，并为每个步骤选择区域、事件和主题。漏斗包含 2 到 6 个步骤。
2. 选择**步骤之间允许的时间**：1、6、24、72 或 168 小时。
3. 选择**运行漏斗**。

结果会显示每个步骤有多少成员到达、占起始成员的比例，以及距上一步骤的中位时间。除最后一步外，每个步骤都会显示有多少成员在此停止。最后一步显示有多少成员完成了漏斗。各步骤可以混用区域，因此可以跟踪某位成员从 PlaidCloud 屏幕到仪表板的过程。**最近的漏斗**可重新打开您之前运行过的漏斗。步骤列表只提供该范围内已记录的事件。

## 未归属的使用情况

有些事件无法关联到 PlaidCloud 成员。它们会计入**事件**和**未归属事件**，但绝不计入成员数。主要情况包括：

- 在 Superset 内而不是通过 PlaidCloud 创建的 Superset 账户。
- 嵌入式仪表板的查看，它没有 Superset 用户。
- 平台日志无法关联到成员的应用和笔记本服务器活动。它们的归属来自这些日志，因此应视为尽力而为。

某个区域的未归属占比较大，意味着其成员数被低估。

## 历史记录的起点

历史记录从为您的工作区开启使用情况采集时开始，在此之前的某天或某月不显示任何活动。第一个有数据的月份会标记为部分数据。

Panel 和 JupyterHub 的数据读取自平台日志，这些日志保留约 90 天。采集开始时，这两个区域最多回填这么长的早期历史。Superset 从其自身日志回填，最长 180 天。只有 PlaidCloud 应用在采集开始时从零开始。

使用情况报告保留原始事件 180 天，这也是最长范围为 180 天的原因，并保留月度摘要 25 个月。当成员在 PlaidCloud 之外被移除时（例如通过 SCIM 或 Keycloak），其原始使用数据在 180 天后过期，首次使用记录在 25 个月后过期。

## 清除成员的使用数据

具有 `identity.security_log.read` 权限的工作区管理员（或超级用户）可以清除某位成员的使用数据并停止采集，之后还可以解除清除。清除和恢复都要求具备该权限和该角色。这两项操作仅可通过 REST API 使用。

| 操作 | 请求 |
|---|---|
| 清除 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 恢复 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

清除会删除该成员的事件和首次使用记录，从那一刻起，报告和导出会排除该成员。其使用数据不会再被采集，之后从 Panel 和 JupyterHub 日志读入的历史记录也会被丢弃。如果无法一次性完成删除，响应中会说明，并由下一次每小时维护运行来完成。

恢复会解除清除，使新的活动重新被采集。它不会恢复已被清除的内容。

这两项操作都会向安全日志写入一条记录。
