**使用情况报告**显示工作区中谁使用了什么：成员打开了哪些屏幕、仪表板、应用和笔记本，有多少人会再次回访，以及他们接下来去了哪里。借助它可以了解成员采用了哪些功能，哪些仪表板、应用和笔记本物有所值、哪些无人问津，谁久未出现，以及人们在流程中的哪一步流失。

从**身份**选项卡打开，位置在安全日志旁边。

## 谁可以查看

使用情况报告所需的权限与安全日志相同：`identity.security_log.read`。没有该权限时不会提供此按钮，而成员若仍然打开报告，会看到一条无权访问的提示。

报告在以下几个位置按成员显示使用情况：**用户**选项卡及其成员资料、**内容**选项卡中每个项目的成员列表，以及包含成员 ID 的**按成员划分的每日活动**和**首次使用**导出。其余内容均按全部成员汇总统计。请仅向需要查看个人活动的人员授予该权限。

打开指定成员的资料、列出 **Not seen** 的成员、打开某个项目的成员列表，以及每次 CSV 下载，都会在安全日志中写入一条记录。参见[隐私与审计](#隐私与审计)。

## 统计内容

使用情况报告汇总以下来源。在**源**中选择其一，或保持为**所有来源**。

| 源 | 记录内容 |
|---|---|
| PlaidCloud 应用 | 成员打开的屏幕以及在应用中执行的操作。 |
| Superset | 仪表板和图表的查看。 |
| Panel 应用 | 应用访问次数以及成员在每个应用中花费的时间。 |
| App visits | 对 Dash 应用和 WASM 应用的访问。 |
| JupyterHub | 成员在 JupyterHub 会话中花费的时间。 |
| Jupyter 笔记本 | 成员打开和保存的笔记本。 |

JupyterHub 会话和 Jupyter 笔记本是两个独立的来源，因此可以任选其一。Panel 应用是单一来源，而 **App visits** 涵盖 Dash 应用和 WASM 应用。只有在默认笔记本镜像上运行的笔记本才会记录笔记本事件，自定义镜像不会报告这些事件。

事件、来源和屏幕以易读的名称显示，例如 **Opened Dash app**、**Opened WASM app**、**Opened notebook** 和 **App visits**，而不是内部代码。已被删除的仪表板或应用显示为 **Deleted dashboard** 或 **Deleted app**。

<Aside type="note">
报告中的每一天都是一个 UTC 日。在美洲工作到深夜的成员可能会出现在次日。
</Aside>

## 阅读报告

在窗口顶部选择一个源和一个**日期范围**，然后选择**刷新**。可选范围为最近 7、30、90 或 180 天。每个选项卡在首次打开时加载，更改源或范围后会再次加载。

### 概览

所选范围内的核心数字：

| 数字 | 含义 |
|---|---|
| **活跃用户** | 有任何活动的成员。 |
| **新用户** | 在该范围内首次出现的成员。 |
| **回访用户** | 在该范围之前就已首次出现的活跃成员。 |
| **Activity minutes** | 估算值：每个存在任何操作或查看的五分钟时段计五分钟。 |
| **事件** | 所有已记录的内容。 |
| **未归属事件** | 无法确定对应成员的事件。它们计入事件，但不计入用户。 |
| **App open minutes** | Panel 应用和 JupyterHub 服务器处于打开状态的时长，包含空闲时间。与 activity minutes 分开统计。 |

每个数字都会显示与相同时长的上一个周期相比的**更改**，因此 30 天的范围会与之前的 30 天比较。**新增**表示该数字从零增长而来。破折号（**—**）表示上一个周期未被所保留的历史记录完整覆盖，因此没有可公平比较的对象。

当工作区的历史记录始于该范围之内时，会显示 **History starts** 横幅并给出日期。在此之前的日期没有活动，是因为当时尚未收集数据，而不是因为没有人使用产品。

**采用情况**列出每个屏幕、仪表板、图表或项目，以及其来源、事件、用户数、占活跃用户的比例、事件和未归属事件。**按月**显示每个月的活跃用户、日均用户和黏性，并在该月仍在进行、仅部分覆盖或为冻结快照时附带说明。

### 活动

按**每天**、**每周**或**每月**周期显示活跃用户，以及**按首周划分的留存**：对于成员首次出现的每一周，之后每一周有多少人回访。带星号的周期并非完全位于该范围内。

### 路径

屏幕之间被走得最多的跳转，以**移动自**、**移动至**和**经过次数**显示，涵盖各个应用和来源。路径最多涵盖最近 30 天。

### 用户

选择 **Seen** 或 **Not seen**。

**Seen** 每位成员一行：姓名、用户名、活跃天数、事件、**Activity minutes**、**App open minutes**，以及首次和最后一次出现的时间。选择某位成员即可打开其资料。

成员资料显示其**活跃天数**、**事件**、**Activity minutes** 和 **App open minutes**，首次和最后一次出现的时间，按天显示事件的图表，以及其使用过的项目，并附有每个项目的来源、事件、事件数和最后使用时间。项目以易读的名称显示，例如仪表板或应用的标题。使用**返回**回到列表。

**Not seen** 列出该范围内没有任何活动的成员，并显示其**成员起始时间**和**最后出现**日期。**None recorded** 表示在所保留的历史记录中没有活动：最长 25 个月，且仅限于开始收集之后。选择**下载 CSV** 可保存该列表。

### 内容

查看每个仪表板、Panel 应用、Dash 应用、WASM 应用和笔记本的使用量。按**类型**筛选，或保持为 **All types**。

| 列 | 含义 |
|---|---|
| **名称** | 项目的名称。已删除的项目显示为 **Deleted dashboard** 或 **Deleted app**。无论有多少人的服务器中包含某个笔记本，该笔记本都按其路径只计一次。 |
| **类型** | 仪表板、Panel 应用、Dash 应用、WASM 应用或笔记本。 |
| **用户** | 在该范围内使用过它的不同成员。 |
| **采用情况** | 用户数占该范围内活跃用户的比例。 |
| **打开次数** | 仪表板：页面加载次数。Panel 应用：启动的会话数。笔记本：打开次数，每位成员每个笔记本每 30 分钟计一次。Dash 应用和 WASM 应用：访问次数。 |
| **App open minutes** | 仅限 Panel 应用。应用处于打开状态的时间，包含空闲时间。 |
| **趋势** | 该范围内每周的打开次数，从最早的一周开始。 |
| **Last used (UTC)** | 成员最后一次使用它的时间。 |

范围内无人使用的项目也会列出，便于您判断哪些可以淘汰。选择 **Hide unused** 可将它们隐藏。选择某个项目可查看使用过它的成员，以及他们的**打开次数**和各自最后一次使用的时间。**下载 CSV** 可保存项目列表或某个项目的成员。

笔记本在有人打开后才会出现。Dash 应用和 WASM 应用的访问仅从此版本到达您的工作区之后开始统计，列表上方的说明会注明每种类型开始收集的时间。

如果无法查询仪表板和应用的名称，会出现警告 **Names are unavailable right now, so items nobody used are not listed**。已被使用的项目仍会显示。

### 导出

将摘要下载为 CSV。选择**摘要**和最长 25 个月的**日期范围**，然后选择**下载 CSV**。

| 摘要 | 内容 |
|---|---|
| **每日活动** | 每天、每个来源、事件和主题的用户与事件。 |
| **按成员划分的每日活动** | 同上，但按每位成员统计，并包含成员 ID。 |
| **每月采用情况** | 每月、每个来源、事件和主题的用户与事件。 |
| **月活跃用户** | 每月、每个来源的活跃用户。 |
| **首次使用** | 每位成员首次使用各个来源的时间，并包含成员 ID。 |

导出使用您在选项卡上方选择的源。较大的摘要会分批下载，每批最多 50,000 行，由窗口合并为一个文件。如果文件超出窗口能够构建的大小，则会保存已有内容并提示文件不完整：请选择更短的范围以获取其余部分。

每次导出都会在安全日志中写入一条记录，记录谁导出了哪份摘要、范围以及行数。跨多个批次的摘要会为每个批次各写入一条记录。

<Aside type="caution">
每月摘要为每个事件包含一个合计行，其主题为 `*`。该行是该事件所有主题的不同用户和事件的合计。请勿将其与各主题行相加，否则所有内容都会被重复计算。
</Aside>

### 漏斗

查看有多少成员完成了一系列步骤。一个步骤是来自某个来源、针对特定主题的事件，或针对**任意主题**。

1. 选择**添加步骤**，并为每个步骤选择来源、事件和主题。一个漏斗有 2 到 6 个步骤。
2. 选择**步骤之间允许的时间**：1、6、24、72 或 168 小时。
3. 选择 7、30 或 90 天的**日期范围**。
4. 选择**运行漏斗**。

结果会针对每个步骤显示：有多少成员到达该步骤、占起始人数的比例、有多少人在此停止，以及距上一步骤的中位时间。步骤可以混合不同来源，因此可以追踪成员从 PlaidCloud 屏幕到 Superset 仪表板的路径。**最近的漏斗**可重新打开之前运行过的漏斗。步骤列表只提供该范围内已记录的事件。

## 未归属的使用情况

有些事件无法关联到某位 PlaidCloud 成员。它们计入**事件**和**未归属事件**，但绝不计入用户数。主要情形如下：

- 在 Superset 内部而非通过 PlaidCloud 创建的 Superset 账户。
- 对嵌入式仪表板的查看，它没有 Superset 用户。
- 平台日志无法关联到某位成员的 Panel 和 JupyterHub 活动。其归属信息来自这些日志，因此应视为尽力而为。

某个来源的未归属占比较大，意味着其用户数被低估。

## 历史记录何时开始

历史记录从为工作区开启使用情况收集时开始，在此之前的某一天或某个月显示没有活动。第一个有数据的月份会标记为部分。

Panel 和 JupyterHub 从平台日志中读取，这些日志保留约 90 天。开始收集时，这两个来源最多回填这么长的历史记录。Superset 从其自身的日志回填，最长 180 天。只有 PlaidCloud 应用在开始收集时从零开始。

使用情况报告将详细活动保留 180 天，因此最长的范围是 180 天；同时将每位成员和每个项目的首次与最后使用时间连同月度摘要一起保留 25 个月。如果范围的起点早于 180 天前，则会显示警告，而不是 **Not seen** 列表和无人使用的项目，因为用于判断谁缺席的明细已不存在。当成员在 PlaidCloud 之外被移除（例如通过 SCIM 或 Keycloak）时，其原始使用数据在 180 天后过期，其首次使用记录在 25 个月后过期。

## 隐私与审计

查看具名成员的使用情况本身会被审计。以下操作会在安全日志中写入一条记录，记录执行者：

- 打开具名成员的资料。
- 列出 **Not seen** 的成员。
- 打开使用过某个项目的成员列表。
- 每次 CSV 下载，无论来自**导出**选项卡、**Not seen** 列表还是**内容**选项卡。

只有拥有 `identity.security_log.read` 权限的成员才能打开该报告。

## 擦除成员的使用情况

拥有 `identity.security_log.read` 权限的工作区管理员（或超级用户）可以擦除某位成员的使用情况并停止对其收集，之后也可以解除擦除。擦除和恢复都需要该权限和该角色。这两项操作仅可通过 REST API 使用。

| 操作 | 请求 |
|---|---|
| 擦除 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 恢复 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

擦除会删除该成员的事件和首次使用记录，从此刻起，报告和导出将不再包含该成员。其使用情况不会再被收集，之后从 Panel 和 JupyterHub 日志回填的历史记录也会被丢弃。如果无法立即完成删除，响应会予以说明，并由下一次每小时维护运行完成。

恢复会解除擦除，使新的活动重新被收集。它不会找回已擦除的内容。

两项操作都会在安全日志中写入一条记录。
