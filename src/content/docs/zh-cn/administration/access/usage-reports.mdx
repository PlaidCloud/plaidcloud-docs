**使用情况报告**显示工作区中谁在使用什么：成员打开了哪些屏幕、仪表板、应用和笔记本，有多少成员会再次回来，以及他们接下来去了哪里。借助它可以了解成员采用了哪些功能，哪些仪表板和应用物有所值，以及人们在流程的哪一环节流失。

从 **身份** 选项卡中打开，位于安全日志旁边。

## 谁可以查看

使用情况报告需要与安全日志相同的权限：`identity.security_log.read`。没有该权限时不会提供该按钮；如果成员仍然设法打开报告，会看到一条无权访问的提示。

报告按成员显示使用情况的位置包括：**成员** 选项卡、从 **内容** 和 **概览** 打开的成员列表，以及包含成员 ID 的 **按成员划分的每日活动** 和 **首次使用** 导出。其余内容均为跨成员汇总统计。仅向应当查看个人活动的人员授予该权限。

## 统计范围

使用情况报告整合了五个领域。可从 **Area** 中选择其一，或保持为 **All areas**。

| 领域 | 记录内容 |
|---|---|
| PlaidCloud 应用 | 成员打开的屏幕以及在应用中执行的操作。 |
| 仪表板 | 仪表板和图表的查看。 |
| 应用 | 应用访问次数以及成员在每个应用中花费的时间。 |
| 笔记本服务器 | 成员在笔记本服务器会话中花费的时间。 |
| 笔记本 | 成员打开和保存的笔记本。 |

笔记本服务器和笔记本是不同的领域，因此可以分别选择。应用则是单一领域。仅会记录在默认笔记本镜像上运行的笔记本的事件，自定义镜像不会上报这些事件。

<Aside type="note">
报告中的每一天都是 UTC 日。在美洲晚间工作较晚的成员可能会显示在第二天。
</Aside>

## 阅读报告

窗口顶部的栏中包含各个筛选器。每个选项卡会在首次打开时加载，并在更改筛选器后重新加载。

| 筛选器 | 作用 |
|---|---|
| **Area** | 将报告限定为一个领域。在 **漏斗** 上会隐藏（漏斗为每个步骤单独选择领域），在 **导出** 上也会隐藏（导出有自己的选择）。 |
| **分组** | 将报告限定为某个安全组的成员。参见[缩小到某个分组](#缩小到某个分组)。 |
| **日期范围** | **最近 7 天**、**最近 30 天**、**最近 90 天**、**最近 180 天**、**本月**、**上月**，或 **自定义…**（可指定开始和结束日期，最长 180 天）。 |
| **刷新** | 重新加载数据（F5）。**已更新** 显示上次加载的时间。 |

日期范围由所有选项卡共用；您所在的选项卡和所选的范围会保存在账户设置中，因此在任何计算机上，窗口都会回到您离开时的状态。更改范围会重新加载当前所在的选项卡，其他选项卡则在打开时重新加载。每个选项卡都有各自的说明：将鼠标指向标题或数字即可查看其含义。

选项卡加载期间会显示占位内容，而不是空白页面。如果报告无法加载，选项卡会显示原因，并提供 **重试** 和 **Copy details**。当某个范围内没有活动时，选项卡会建议尝试更长的范围。要打开某一行，可双击该行，或选中后按 Enter。**返回** 可从所打开的项目回到列表。

### 概览

所选范围的核心数据，每项都带有箭头和百分比，表示与上一个相同长度时段相比的变化：

| 数据 | 含义 |
|---|---|
| **活动成员** | 有任何活动的成员。 |
| **New members** | 在该范围内首次出现的成员。如果范围的起点早于开始收集的时间，则显示为短横线，因为无法确定更早的首次使用。 |
| **Returning members** | 在该范围之前就已首次出现的活动成员。 |
| **Activity minutes** | 估算值：每个有任何操作或查看的五分钟时段计为五分钟。 |
| **App open minutes** | 应用和笔记本服务器处于打开状态的时间，包括空闲时间。与活动分钟数分开统计。 |
| **事件** | 记录的所有内容。 |

无法关联到成员的事件会单独统计，显示在数据下方的一行中。它们计入事件，而不计入成员。

**Highlights** 最多列出四项值得关注的内容，每项都是指向详情的链接：

- 与上一时段相比，活动成员上升或下降 10% 或以上。
- 在该范围内不活动的成员数量。选择它可打开未激活成员的列表。
- 无人打开的仪表板和应用的数量。选择它可打开 **内容**，未使用的项目排在最前。
- 使用最多的项目，前提是至少有五名成员使用过它。

高亮项只在有内容可说时才会出现。当 PlaidCloud 无法计算出某个数量时，该高亮项会被隐藏，而不是显示 0；如果没有突出的内容，则会显示 **No notable changes in this range.**

**Most used** 列出每个屏幕、仪表板、图表或项目及其领域、事件、成员数和 **Reach**（在该范围内使用过它的活动成员所占的比例）。通过列选择器可添加 **事件** 和 **Events not linked to a member**。**按月（全部历史）** 显示每个月的活动成员数、日均成员数和 **用户粘性**，当该月仍在进行中或仅部分覆盖时会附带说明。用户粘性是日均活动成员数除以当月的活动成员数，因此数值越高，表示人们回来的天数越多。

### 活动

按 **每天**、**每周** 或 **每月** 时段显示活动成员，并附带 **按首周划分的留存**：对于成员首次出现的每一周，显示 **Cohort size** 以及其中此后每周仍保持活动的成员比例。带星号的时段并非完全位于该范围内。

### 路径

跨领域的屏幕间最常见的跳转，以 **移动自**、**移动至** 和 **经过次数** 显示。路径最多涵盖最近 30 天。

### 成员

**显示** 可在两种列表之间切换：

- **活动** 中每个在该范围内出现的成员占一行：姓名、用户名、活动天数、事件、活动分钟数、应用打开分钟数，以及首次和最后一次出现的时间。打开某一行可查看该成员每天的事件及其使用的内容。
- **未激活** 列出在该范围内没有活动的当前成员，以及其成为成员的时间和最后一次出现的时间。**None recorded** 表示在保留的历史记录中没有活动，历史记录最长为 25 个月，且仅从开始收集时起算。使用 **下载 CSV** 可下载该列表。未激活指在任何领域都没有活动，因此会忽略 **Area**。已从工作区中移除的成员不会列出。

### 内容

每个仪表板、应用和笔记本，包含其 **类型**、**成员**、**Reach**、**打开次数**、**App open minutes**（仅限应用）、每周 **Trend** 以及 **上次使用** 的时间。选择 **类型** 可缩小列表范围，或选择 **Hide unused** 以排除无人打开的项目。打开某一行可查看使用该项目的成员，两种列表都可通过 **下载 CSV** 下载。列表下方的说明会指出哪些类型尚未收集，或仅从较晚的日期开始收集。

### 缩小到某个分组

**分组** 将 **概览**、**内容** 和 **未激活** 列表限定为某个安全组的成员。选择 **所有人** 可取消限定。在框中输入内容可搜索工作区的分组。报告使用的是该分组当前的成员关系，而不是活动发生时的成员关系，并在筛选器旁边注明这一点。

- **活动** 成员、**活动**、**路径** 和 **导出** 不会被缩小范围。这些选项卡上的筛选器处于禁用状态，并会说明原因。
- 选择分组时不显示 **按月**，因为按月历史是针对所有人保存的。
- 没有成员的分组或已不存在的分组会返回空结果并给出相应警告，而不是错误。
- 如果无法读取工作区的安全组，则不提供该筛选器。

### 导出

将摘要下载为 CSV。选择 **摘要** 和 **日期范围**，然后选择 **下载 CSV**。范围最长为 25 个月。

| 摘要 | 内容 |
|---|---|
| **每日活动** | 按每天、领域、事件和主题统计的成员和事件。 |
| **按成员划分的每日活动** | 同上，但按每个成员统计，并包含成员 ID。 |
| **每月采用情况** | 按每月、领域、事件和主题统计的成员和事件。 |
| **Monthly active members** | 按每月和领域统计的活动成员。 |
| **首次使用** | 每个成员首次使用每个领域的时间，并包含成员 ID。 |

导出使用的是您在选项卡上方所选的领域。较大的摘要会以每批最多 50,000 行的方式下载，窗口会将它们合并为一个文件。如果文件超出窗口能够构建的大小，则会保存已有内容，并告知文件不完整：选择更短的范围即可获取其余部分。

每次导出都会向安全日志写入一条记录，记录谁导出了哪个摘要、范围以及行数。跨多个批次的摘要会为每个批次各写入一条记录。

如需按计划将这些数据放入表中，请使用 [Get Workspace Usage](/zh-cn/reference/workflow-steps/general/get-workspace-usage/) 步骤。

<Aside type="caution">
每月摘要中，每个事件都包含一个合计行，其主题为 `*`。该行是该事件所有主题的去重成员数和事件数。不要将它与主题行相加，否则所有内容都会被重复计算。
</Aside>

### 漏斗

查看有多少成员完成了一系列步骤。步骤是来自某个领域、针对特定主题的事件，或 **任意主题**。漏斗使用您所选的日期范围，最长为最近 90 天；当较长的范围被缩短时，会给出提示。

1. 选择 **添加步骤**，并为每个步骤选择领域、事件和主题。一个漏斗有 2 到 6 个步骤。
2. 选择 **步骤之间允许的时间**：1、6、24、72 或 168 小时。
3. 选择 **运行漏斗**。

结果会针对每个步骤显示有多少成员到达该步骤、占起始成员的比例，以及距上一步骤的中位时间。除最后一步外，每一步都会显示有多少成员在此停止。最后一步显示有多少成员完成了漏斗。步骤可以混合不同领域，因此可以跟踪某个成员从 PlaidCloud 屏幕到仪表板的过程。**最近的漏斗** 可重新打开您之前运行过的漏斗。步骤列表只提供在该范围内记录过的事件。

## 未归属的使用

有些事件无法关联到 PlaidCloud 成员。它们计入 **事件** 和 **未归属事件**，但绝不计入成员数。主要情况如下：

- 在 Superset 内部而不是通过 PlaidCloud 创建的 Superset 账户。
- 嵌入式仪表板的查看，它没有 Superset 用户。
- 平台日志无法关联到成员的应用和笔记本服务器活动。其归属来自这些日志，因此应视为尽力而为。

某个领域的未归属占比较大，意味着其成员数被低估。

## 历史从何时开始

历史记录从为您的工作区开启使用情况收集时开始，在此之前的某一天或某个月不显示任何活动。有数据的第一个月会标记为部分。

Panel 和 JupyterHub 从平台日志读取，日志保留约 90 天。收集开始时，这两个领域最多回填这么长时间的更早历史。Superset 从其自身日志回填，最长 180 天。只有 PlaidCloud 应用在收集开始时是从零起算。

使用情况报告将原始事件保留 180 天，这就是最长范围为 180 天的原因，并将月度摘要保留 25 个月。当成员在 PlaidCloud 之外被移除时（例如通过 SCIM 或 Keycloak），其原始使用数据会在 180 天后过期，首次使用记录会在 25 个月后过期。

## 清除某个成员的使用数据

具有 `identity.security_log.read` 权限的工作区管理员（或超级用户）可以清除某个成员的使用数据并停止收集，之后还可以解除清除。清除和恢复都需要该权限和该角色。这两项操作仅可通过 REST API 使用。

| 操作 | 请求 |
|---|---|
| 清除 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 恢复 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

清除会移除该成员的事件和首次使用记录，从那一刻起，报告和导出将不再包含该成员。其使用数据不会再被收集，之后从 Panel 和 JupyterHub 日志中回填的历史也会被丢弃。如果无法立即完成移除，响应会予以说明，并由下一次每小时维护运行完成。

恢复会解除清除，使新的活动重新被收集。它不会找回已被清除的内容。

这两项操作都会向安全日志写入一条记录。
