**使用情况报告**显示工作区中谁在使用什么：成员打开了哪些屏幕、仪表板、应用和笔记本，有多少成员再次回来，以及他们接下来去了哪里。可用它了解成员采用了哪些功能，哪些仪表板和应用物有所值，以及人们在流程的哪个环节流失。

从**身份**选项卡打开，位于安全日志旁边。

## 谁可以查看

使用情况报告需要与安全日志相同的权限：`identity.security_log.read`。没有该权限时不会提供此按钮，仍然打开报告的成员会看到无权访问的提示。

报告会在以下位置按成员显示使用情况：**成员**选项卡、从**内容**和**概览**打开的成员列表，以及包含成员 ID 的**按成员划分的每日活动**和**首次使用**导出。其他所有内容都是跨成员汇总的。请仅向应当查看个人活动的人员授予该权限。

## 统计内容

使用情况报告合并了五个区域。可从**区域**中选择一个，或保持为**所有区域**。

| 区域 | 记录内容 |
|---|---|
| PlaidCloud 应用 | 成员打开的屏幕以及在应用中执行的操作。 |
| 仪表板 | 仪表板和图表的查看。 |
| 应用 | 应用访问，以及成员在每个应用中花费的时间。 |
| 笔记本服务器 | 成员在笔记本服务器会话中花费的时间。 |
| 笔记本 | 成员打开和保存的笔记本。 |

笔记本服务器和笔记本是不同的区域，因此可以选择其中任意一个。应用是单一区域。只有在默认笔记本镜像上运行的笔记本才会记录笔记本事件，自定义镜像不会报告这些事件。

<Aside type="note">
报告中的每一天都是 UTC 日。在美洲晚间工作到很晚的成员可能会出现在第二天。
</Aside>

## 阅读报告

窗口顶部的栏包含筛选器。每个选项卡在您首次打开时加载，更改筛选器时会再次加载。

| 筛选器 | 作用 |
|---|---|
| **区域** | 将报告限制为一个区域。在**漏斗**（每一步各自选择区域）和**导出**（有自己的选择）上隐藏。 |
| **分组** | 将报告限制为某个安全组的成员。请参阅[缩小到某个分组](#缩小到某个分组)。 |
| **日期范围** | **最近 7 天**、**最近 30 天**、**最近 90 天**、**最近 180 天**、**本月**、**上个月**，或**自定义…**（起止日期，最长 180 天）。 |
| **刷新** | 重新加载数据 (F5)。**已更新**显示上次加载的时间。 |

日期范围由所有选项卡共享，您所在的选项卡和所选范围会随账户设置保存，因此在任何计算机上窗口都会回到您离开时的位置。更改范围会重新加载当前所在的选项卡，其他选项卡在打开时重新加载。每个选项卡都有各自的说明：指向标题或数字即可查看其含义。

选项卡加载时会显示占位内容，而不是空白页面。如果报告无法加载，选项卡会显示原因，并提供**重试**和**复制详细信息**。当某个范围内没有活动时，选项卡会建议尝试更长的范围。要打开某一行，可双击它，或选中后按 Enter。**返回**可从打开的项目回到列表。

### 概览

所选范围的核心数字，每个数字都带有箭头和百分比，表示与上一个等长时间段相比的变化：

| 数字 | 含义 |
|---|---|
| **活动成员** | 有任何活动的成员。 |
| **新成员** | 在该范围内首次出现的成员。如果范围的起点早于开始收集的时间，则显示为短横线，因为无法判断更早的首次使用。 |
| **回访成员** | 在该范围之前就已出现过的活动成员。 |
| **活动分钟数** | 估算值：每个存在任何操作或查看的五分钟时段计为五分钟。 |
| **应用打开分钟数** | 应用和笔记本服务器处于打开状态的时间，包括空闲时间。与活动分钟数分开统计。 |
| **事件** | 记录的所有内容。 |

无法关联到成员的事件会单独统计，显示在数字下方的一行中。它们计入事件，而不计入成员。

**重点提示**最多列出四项值得一看的内容，每项都是指向详细信息的链接：

- 与上一个时间段相比，活动成员上升或下降 10% 或更多。
- 在该范围内不活动的成员数。选择它可打开未激活成员的列表。
- 无人打开的仪表板和应用数。选择它可打开**内容**，未使用的排在最前面。
- 使用最多的项目，前提是至少有五名成员使用过它。

重点提示只在有内容可说时才会出现。当 PlaidCloud 无法得出某个计数时，该重点提示会被隐藏而不是显示 0，如果没有任何突出之处，您会看到 **此范围内没有值得关注的变化。**

**最常用**列出每个屏幕、仪表板、图表或项目，以及其区域、事件、成员数和**覆盖率**（在该范围内使用过它的活动成员所占的比例）。通过列选择器可添加**事件**和**未关联到成员的事件**。**按月（全部历史记录）**显示每个月的活动成员、日均成员数和**用户粘性**，并在该月仍在进行或仅部分覆盖时附带说明。用户粘性是日均活动成员数除以该月的活动成员数，因此值越高，表示人们在更多天里回来使用。

### 活动

按**每天**、**每周**或**每月**周期显示活动成员，另有**按首周划分的留存**：对于成员首次出现的每一周，显示**群组规模**，以及这些成员在之后每周仍然活动的比例。带星号的周期并未完全落在该范围内。

### 路径

最常见的屏幕间移动，显示为**移动自**、**移动至**和**经过次数**，跨区域统计。路径最多涵盖最近 30 天。

### 成员

**显示**可在两个列表之间切换：

- **活动**中，在该范围内出现的每位成员占一行：姓名、用户名、活动天数、事件、活动分钟数、应用打开分钟数，以及首次和最近一次出现的时间。打开某一行可查看该成员每天的事件及其使用的内容。
- **未激活**列出在该范围内没有活动的当前成员，以及其成为成员的时间和最近一次出现的时间。**无记录**表示在保留的历史记录中没有任何活动，历史记录最长 25 个月，并且只从开始收集时算起。可通过**下载 CSV**下载该列表。未激活是指在任何区域都没有活动，因此会忽略**区域**。已从工作区中移除的成员不会列出。

### 内容

每个仪表板、应用和笔记本，显示其**类型**、**成员**、**覆盖率**、**打开次数**、**应用打开分钟数**（仅限应用）、每周的**趋势**以及**上次使用**时间。选择一个**类型**可缩小列表，或选择**隐藏未使用项**以排除无人打开的项目。打开某一行可查看使用过该项目的成员，两个列表均可通过**下载 CSV**下载。列表下方的说明会指出哪些类型尚未收集，或仅从较晚的日期开始收集。

### 缩小到某个分组

**分组**将**概览**、**内容**和**未激活**列表限制为某个安全组的成员。选择**所有人**可取消限制。在框中输入可搜索工作区的分组。报告使用的是分组当前的成员关系，而不是活动发生时的成员关系，并在筛选器旁边说明了这一点。

- **活动**成员、**活动**、**路径**和**导出**不会被缩小。这些选项卡上的筛选器被禁用，并说明了原因。
- 对于分组不显示**按月**，因为月度历史记录是针对所有人保留的。
- 没有成员的分组，或已不存在的分组，会返回空结果和说明这一点的警告，而不是错误。
- 如果您无法读取工作区的安全组，则不提供该筛选器。

### 导出

将摘要下载为 CSV。选择**摘要**和**日期范围**，然后选择**下载 CSV**。范围最长 25 个月。

| 摘要 | 内容 |
|---|---|
| **每日活动** | 每天、每个区域、事件和主题的成员数与事件数。 |
| **按成员划分的每日活动** | 同上，但按每位成员划分，包含成员 ID。 |
| **每月采用情况** | 每月、每个区域、事件和主题的成员数与事件数。 |
| **每月活动成员** | 每月、每个区域的活动成员。 |
| **首次使用** | 每位成员首次使用每个区域的时间，包含成员 ID。 |

导出使用您在选项卡上方选择的区域。较大的摘要会按最多 50,000 行分批下载，窗口会将它们合并为一个文件。如果文件超过窗口可构建的大小，则会保存已有内容并告知您文件不完整：请选择更短的范围以获取其余部分。

每次导出都会向安全日志写入一条记录，记录谁导出了哪份摘要、范围以及行数。跨多个批次的摘要会为每个批次各写一条记录。

如果想按计划将这些数据放入表中，请使用 [Get Workspace Usage 步骤](/zh-cn/reference/workflow-steps/general/get-workspace-usage/)。

<Aside type="caution">
每月摘要中，每个事件都有一个合计行，其主题为 `*`。该行是该事件所有主题的去重成员数和事件数。请勿将它与各主题行相加，否则所有内容都会被统计两次。
</Aside>

### 漏斗

查看有多少成员经历了一系列步骤。一个步骤是来自某个区域的、针对特定主题或**任意主题**的事件。漏斗使用您选择的日期范围，最长为最近 90 天，并在缩短较长范围时说明这一点。

1. 选择**添加步骤**，并为每一步选择区域、事件和主题。一个漏斗有 2 到 6 个步骤。
2. 选择**步骤之间允许的时间**：1、6、24、72 或 168 小时。
3. 选择**运行漏斗**。

结果会为每一步显示有多少成员到达、占起始成员的比例，以及距上一步的中位时间。除最后一步外，每一步都会显示有多少成员停在这里。最后一步显示有多少成员完成了漏斗。各步骤可以混合不同区域，因此可以追踪成员从 PlaidCloud 屏幕到仪表板的过程。**最近的漏斗**可重新打开您以前运行过的漏斗。步骤列表只提供该范围内记录过的事件。

## 未归属的使用情况

有些事件无法关联到某位 PlaidCloud 成员。它们计入**事件**和**未归属事件**，但绝不计入成员数。主要情形如下：

- 在 Superset 内部而不是通过 PlaidCloud 创建的 Superset 账户。
- 嵌入式仪表板的查看，它没有 Superset 用户。
- 平台日志无法关联到成员的应用和笔记本服务器活动。它们的归属来自这些日志，因此请视为尽力而为。

某个区域的未归属占比较大，意味着其成员数被低估。

## 历史记录的起点

历史记录从为工作区开启使用情况收集时开始，在此之前的某一天或某个月显示没有活动。第一个有数据的月份会标记为部分。

Panel 和 JupyterHub 从平台日志中读取，日志大约保留 90 天。收集开始时，这两个区域最多会回填这么长的早期历史记录。Superset 从其自身的日志回填，最长 180 天。只有 PlaidCloud 应用在收集开始时从零开始。

使用情况报告将原始事件保留 180 天，这就是最长范围为 180 天的原因，并将月度摘要保留 25 个月。当成员在 PlaidCloud 之外被移除时，例如通过 SCIM 或 Keycloak，其原始使用情况在 180 天后过期，其首次使用记录在 25 个月后过期。

## 清除成员的使用情况

拥有 `identity.security_log.read` 权限的工作区管理员（或超级用户）可以清除某位成员的使用情况并停止收集，之后还可以撤销清除。清除和恢复都需要该权限和该角色。这两项操作仅可通过 REST API 使用。

| 操作 | 请求 |
|---|---|
| 清除 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 恢复 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

清除会删除该成员的事件和首次使用记录，从那一刻起，报告和导出会排除该成员。其使用情况不会再被收集，之后从 Panel 和 JupyterHub 日志读入的历史记录也会被丢弃。如果无法立即完成删除，响应会说明这一点，下一次每小时的维护运行会完成删除。

恢复会撤销清除，使新的活动再次被收集。它不会找回已清除的内容。

这两项操作都会向安全日志写入一条记录。
