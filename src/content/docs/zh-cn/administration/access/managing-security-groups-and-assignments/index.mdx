PlaidCloud 的安全与访问管理简单直接。成员能否获得访问权限，取决于其所属的分组。添加或更改成员的安全关联非常灵活。

<Aside>每个工作区可拥有的安全组数量不限，但建议尽量减少数量，以便简化安全管理。</Aside>



## 管理安全组


安全组可以添加、更新或删除。



**管理安全组：**


1. 打开 Identity
2. 选择“Security”选项卡
3. 在下拉菜单中单击“安全组”（将显示包含现有分组的表单）
4. 要添加分组，请单击“Create Security Group”
5. 要编辑分组的权限，请单击最左侧的图标

**管理分组成员：**


1. 打开 Identity
2. 选择“Security”选项卡
3. 在下拉菜单中单击“安全组”
4. 单击“成员”图标
5. 将所需成员从“Unassigned Members”列拖到“Assigned Members”列，反向拖动则移除成员

<Aside>“Assigned Members”列为空时保存不会产生任何更改，并会提示这一点。要让所有人都不再属于某个分组，请移除该分组的权限或删除该分组，而不要清空其成员。</Aside>

<Aside>如果某个分组通过[行访问](#管理行访问)获得了行授权，成员变更会在大约一分钟内反映到仪表板：新添加的成员会在仪表板中看到该分组的行，被移除的成员则不再看到。禁用或删除成员以及删除分组，也以同样方式生效。</Aside>

<Aside type="caution">保存分组的权限矩阵时，您无法自行授予的权限会保持原样，也不会显示在矩阵中。如需更改其中某项，请联系拥有该权限的人员——矩阵只能编辑您有权控制的内容。</Aside>

## 管理行访问

行访问根据某一列的值，限制安全组可以查看表中的哪些行。例如，可以用 `region` 列来限制访问：被授予 `East` 和 `Central` 的分组，只能查看带有这些值的行。针对某个项目和列的所有设置——选择列、选择值的来源、决定哪个分组可以看到什么——都在同一个屏幕中完成，保存后立即生效。

设置和更改行访问需要项目架构师或租户管理员。其他人打开项目的 Security 选项卡时，会被告知行访问仅限架构师使用，下列入口也不会向他们显示。

### 打开行访问

所有入口打开的都是同一个行访问屏幕：

- **表资源管理器的工具栏**有一个**行访问**按钮，当表已限制行时按钮上带有徽章。它会在表的第一个受限列上打开（如果有的话），您也可以切换到表的任何其他列。
- **列的分面菜单**中有**按此列限制行…**，用于在该列上打开行访问。对于已限制行的列，该菜单项显示为**按此列限制的行 — 编辑…**。
- **项目的 Security 选项卡**列出项目中每个受限列，以及它所适用的表、持有授权的分组及其**同步**状态。选择某一列即可编辑，或单击**限制某一列…** 开始新建：先选择表，再选择列。已限制行的列带有锁形标记。
- **Identity → Member** 中成员的**行访问**选项卡，以及 **Identity → Security → 安全组** 中分组的行访问摘要。**打开行访问**（或**编辑**）会打开所选的列；**添加**会在该行所属的项目中限制另一列。

从某一列打开时，屏幕停留在该列。通过**限制某一列…** 或**添加**打开时，则可自行选择列。

### 行访问网格

按某一列限制表的步骤如下：

1. 从上述任一入口打开行访问；如果打开时未指定列，请选择列——选择器提供的是表中真实存在的列，而不是自由文本。
2. 选择**值来源**——**列**（表中某一列的不同值）、**维度**（维度的节点）或**列表**（手动输入的值）。值的类型取决于该列的数据类型。
3. 为每个安全组勾选该分组可以查看的值。网格列出有权访问该项目的分组，以及已在该列上持有授权的所有分组。
4. 将 **Everyone else** 设为 **sees all rows** 或 **sees no rows**——这适用于网格中没有任何勾选的所有分组。
5. 单击**保存**。

保存即时生效。PlaidCloud 自身的查询会立即遵循更改，Superset 仪表板则在大约一分钟内跟进——无需另行应用，只有当某个授权持有的值在其来源中已不存在时（见下文），**保存**才会停下来询问。屏幕的同步状态显示更改传播到了哪一步；请参阅[保持仪表板同步](#保持仪表板同步)。

网格还会为您处理这些细节：

- **值很多时。** 值按顺序排列。当某一列的值多到无法全部显示时，网格会提示“More values than fit here — type to search.”，筛选框会搜索整列，并保留分组已持有的所有值。
- **来源中已不存在的值。** 分组已被授予的某个值，在其来源失去该值后仍会保留在网格中——表中已没有任何行带有该值、维度中已没有该成员，或列表中已没有该值。其列标题带有警告图标，悬停时会说明原因。**全选**、**反选**和**粘贴**会让这类值保持各分组原有的持有状态。除非您取消勾选，否则不会从授权中移除任何内容：当您单击**保存**而某个分组仍持有此类值时，行访问会在 **Values No Longer in the Source** 中列出相关的分组和值并询问。**Keep and Save** 按原样保存，**Remove and Save** 会先将它们从所有分组的授权中移除，关闭该询问则不保存任何内容。如果移除后会使某个分组没有任何勾选，询问中会按照 **Everyone else** 的设置说明该分组此时将看到所有行还是不看到任何行。尚未保存的勾选会随其值一同消失。当某一列的值多到无法全部显示，或其表尚未构建时，行访问无法判断表缺少哪些值，因此会保留所有已授予的值，且不做任何标记。
- **空值。** 一个 **空值 — 对每个拥有授权的组可见** 复选框决定该列没有值的行如何处理。勾选后，在该列上持有任何授权的每个分组都能看到这些行。
- **尚未构建的表**会显示**请先构建此表（运行创建它的工作流）**，而不是空列表。
- **保存会等待屏幕上的值加载完成。** 在加载值期间——切换值来源、维度或表之后，或应用模板之后——**保存**处于禁用状态，工具提示为“Save is available once this source's values load.”。如果加载失败，网格会提示并要求重新选择来源；在加载成功之前不会保存任何内容。

### 一个列名，所有表

限制属于项目中的列*名称*，而不是某一张表。一旦 `region` 限制了行，项目中每张带有名为 `region` 的列的表都会受其过滤，无论是在 PlaidCloud 自身的查询中还是在仪表板中。网格的 **Applies to** 列表显示这些表。该列表为只读，因为由列名决定，之后新增的同名列的表，一经发布即受覆盖。

当项目中没有任何表含有该名称的列时，窗口除显示 **Applies to 0 tables** 外，还会警告说在有表含该列之前，此限制不会过滤任何仪表板。为某张表添加该列，或更正列名，警告即会消失。

<Aside type="caution">
**列名必须完全匹配**——包括大小写和空白。`Region` 和 `region` 是不同的名称，`region` 和带尾随空格的 `region ` 也是。选择器只提供真实的列名，因此这主要涉及列在别处被重命名的情况——此时行访问会发出警告并指出它找到的最接近的列，而不是悄悄地什么都不限制。
</Aside>

<Aside type="caution">
**发布限制行的表时，会在同一步骤中设置其仪表板筛选器。** 仪表板通过已发布的报表视图读取表，因此当您发布或重新发布带有受限列的表时，PlaidCloud 会在发布完成之前注册该表的仪表板筛选器。如果无法注册，发布会被拒绝，该次尝试创建的内容将被回滚，因此受限的表绝不会在仪表板中处于未过滤状态。在限制行的项目上，*视图*不能发布，因为视图的查询可能重命名或派生出受限列。请参阅[发布表](/zh-cn/guides/data/publish/)。
</Aside>

### 停止限制

网格上的**停止限制**会在内联确认后移除限制——“Stop restricting rows by ‘region’? Every group's grant on it is removed and everyone sees its rows.”随后行访问会确认“Rows in ‘region’ are no longer restricted.”。该列的 Superset 数据集会随之移除，除非仍有图表在使用它；在这种情况下，行访问会说明数据集保留以及有多少图表在使用。

列在限制行期间不能被重命名或删除。如果是架构师，会被告知先在行访问中停止限制；其他人则会被告知联系项目架构师。

### 谁可以更改限制行的项目

项目的工作流、步骤和用户定义函数以项目自己的服务身份运行，该身份可以读取每一行。能够更改它们的人，可能让某个步骤把自己未被授权的行复制到自己可读的表中，因此在项目上限制行，也就限制了谁可以更改项目的行为。一旦项目限制了至少一列：

- **自动化仅限架构师。** 只有项目架构师和租户管理员可以更改工作流、步骤、用户定义函数、计划、工作流变量和项目变量以及通知邮件模板——出于同样的原因，也只有他们可以导入工作流包、转换 Alteryx 工作流，或向项目中导入、复制或还原，或更改其连接环境、默认文档账户或 ERP 过账模式。其他人仍然可以运行项目的工作流：**开始**、**停止**、**恢复**和**运行所选步骤**仍然可用。对他们来说，步骤编辑器、工作流的创作控件、UDF 编辑器和计划表单以只读方式打开，并带有说明应联系哪些架构师的横幅：“This project restricts rows, so only its Architects can change workflows, steps, UDFs, schedules, variables and notify templates. You can still run them.”
- **受限列读取的维度仅限架构师。** 决定谁能看到哪些行的维度——即受限列的值来源——只能由项目架构师或租户管理员以及项目自己的工作流更改。这包括添加、移动、重命名、复制、清除、加载和还原其节点，以及维度本身。其他人会看到“This dimension decides who sees which rows of ‘region’, so only a project Architect can change it.”没有任何限制读取的维度不受影响。
- **授权来源表仅限架构师。** 绑定为某列[授权来源](#将授权绑定到源表)的表，其行只能由项目架构师、租户管理员或项目的工作流更改或删除——无论是通过数据编辑器、导入、连接器加载还是 API。
- **复制项目仅限架构师**，且副本会显示“This copy is not row-restricted.”——在您设置限制之前，新项目不带任何限制。
- **还原较早的版本与其他更改一样。** 还原项目自身的设置或上述维度需要项目架构师。还原始终应用于该版本所属的项目项，因此无法指向其他项目来规避这一点——请参阅[版本历史](/zh-cn/guides/projects/managing-projects/#版本历史)。
- **编辑受限表中的数据**需要架构师，详见[行访问与数据编辑器](#行访问与数据编辑器)。
- **向受限表写入 DataFrame、保存记录和清除，只会更改您自己的行**，除非您能看到每一行，详见[向受限表加载数据](#向受限表加载数据)。

在项目上限制第一列之前，行访问会告知这会影响哪些人：“Restricting rows here means only Architects can change this project's workflows, steps, UDFs, schedules and notify templates. N members can change them today; they will still be able to run them.”

运行与之前完全一样，包括计划运行，因为它们以项目的服务身份运行。运行产生的内容取决于架构师为其设计的方案：不含受限列的输出表、导出文件、通知邮件或日志行，不会对读取者进行过滤。

**运行开始时给定的值。** 任何可以运行工作流的人，都可以用自己的变量值来启动它——[应用运行器](/zh-cn/guides/workflows/use-converted-alteryx-apps/#app-runner-前端)使用其表单的答案来完成此操作，API 和 AI 工具也可以。这些值仅对该次运行有效：它们不会保存在工作流上，其他运行、导出或读取者也看不到。由于运行以服务身份执行，这些值可以改变该次运行读取和写入的内容，因此请仅将运行工作流的权限授予您信任的人。

**不限制行的项目。** 这些规则只有在项目限制了某一列之后才生效。在没有任何限制的项目上，任何可以更改项目自动化的人，都可以编写一个以项目服务身份运行的步骤或用户定义函数，来更改项目的访问权限，使自己成为项目的架构师之一。这是有意为之：此类项目并不承诺行隔离。请将创作权限限定在您信任其担任架构师的人员，或限制一列。

### 保持仪表板同步

行访问会在网格上以及项目 Security 选项卡的**同步**列中，显示更改在通往仪表板途中所处的位置：

| 状态 | 含义 |
|---|---|
| **等待中** | 更改已保存，正在发往仪表板。通常在大约一分钟内完成。 |
| **正在重试** | 发送失败，正在再次尝试。失败原因显示在状态旁边，并提供**重试**以立即重新发送。 |
| **尚未应用** | 项目的限制尚未发送到仪表板。 |
| **已应用** | 最近一次将限制发送到仪表板的尝试已成功。 |
| **与仪表板同步** | 行访问将仪表板实际执行的内容与它将要写入的内容进行了比较，两者一致。 |
| **仪表板不一致** | 仪表板执行的内容与行访问将要写入的不一致——某条规则在 Superset 中被更改或删除，或者无法检查某张表的已发布视图。 |
| **错误** | 发送限制失败。原因显示在状态旁边。 |

更改达到**已应用**后，网格会将其与仪表板进行核对，并转为**与仪表板同步**或**仪表板不一致**。**仪表板不一致**和**错误**都提供**重试**，用于再次发送项目的限制。如果根本无法读取状态，网格会提示“Couldn't check sync status.”

由某一张表引起的**错误**会指出该表并说明处理方法——例如，表发布时没有包含其受限列（“Republish or unpublish it.”），或者带有受限列的表尚未发布，在发布之前仪表板无法对其进行过滤。状态会一直停留在**错误**并指出未发布的表，直到您发布它，或改为在已发布的表上限制该列。这样的表不会拖住项目的其余部分：其他所有表都保持同步。

仪表板遵循与 PlaidCloud 自身查询相同的授权：

- **每张带有该列的已发布表都会被过滤**，而不仅仅是设置限制时您正在查看的那张表。
- **即使其他所有人都能看到所有行，仅被授予部分值的分组也会被过滤**，适用于每张仪表板数据集已存在的表。
- **项目架构师可以看到每一行**，在仪表板中与在表资源管理器及 PlaidCloud 其他部分中一样。这适用于项目的架构师分组，以及与个别成员共享的项目的架构师。收回架构师访问权限会在仪表板中立即生效，无论您是更改成员的角色、将成员或其分组从项目中移除、更改项目的访问类型、还原较早的项目版本，还是删除该分组。
- **安全组成员变更会自动传递到仪表板。** 在 PlaidCloud 中将某人添加到分组或从分组中移除、禁用或删除成员、删除分组，或添加加入您默认安全组的新成员，都会在大约一分钟内更新他们在仪表板中看到的内容，涉及所有向该分组授予值的项目，无需任何人重新打开行访问。在 PlaidCloud 之外所做的成员变更——直接在 Keycloak 中，或由单点登录在登录时将某人放入分组——会在大约 15 分钟内传递到仪表板，无需保存或重试。

### 维度授权

当**维度**作为值来源时，勾选一个节点即可授予其下的全部内容。授权会跟随维度变化：在已勾选节点下添加的成员，会在维度保存后的下一次同步时授予该分组；从其下移出或被移除的成员则不再被授予——无需任何人重新打开网格。重新打开时，您勾选过的节点仍显示为已勾选。

单独勾选（而非通过节点勾选）的成员，在从维度中移除后仍保持已授予状态，网格会将其标记为来源中已不存在的值。

取消勾选已勾选节点之下的任何内容，会同时取消勾选该节点，分组只保留仍被勾选的成员。再次勾选该成员不会重新勾选节点——请单击节点自己的复选框。**粘贴**、**全选**和**反选**只勾选成员，不勾选节点。

名称无法用作行访问值的维度成员，在保存时会被拒绝，并指出该成员。如果这样的成员后来出现，其行不会授予任何人，同步状态会指出它：“Dimension ‘…’ member ‘…’ cannot be used as a row access value, so its rows are not granted. Rename it in the dimension.”

### 将授权绑定到源表

除了手动勾选值，您还可以让受限列指向一张已包含答案的源表——每行对应一个分组及其可以查看的值。先在网格中限制该列，然后添加一个[**设置行访问权限**](/zh-cn/reference/workflow-steps/tables/table-set-row-access/)工作流步骤，指定该列、源表以及源表的分组列和值列。该步骤首次运行时会将该列绑定到该表：该列手动设置的授权会被清除，其授权改为根据该表的行来设置。

绑定之后，该列即为**来源所有**：行访问网格将其显示为锁定状态，并带有指明源表的徽章，在您单击**移除绑定**之前，手动编辑其授权会被拒绝。

该步骤之后的每次运行都会重新读取源表并重新应用授权——请将它安排在加载或刷新该表的工作流之后，这样源数据中新增、移除或重新分配的分组会在下一次运行时反映到行访问，无需任何人手动编辑网格。

由于源表决定了谁能看到什么，只有项目架构师、租户管理员或项目自己的工作流可以更改其行或删除它。其他人会看到“This table supplies the row access grants for ‘region’, so only a project Architect can change its rows or delete it.”

### 限制模板

如果您构建了想要重复使用的限制形态——相同的值来源、值类型和空值设置——可以保存一次，并在需要的地方应用，而无需逐列重建。

- 在已打开的行访问屏幕中，**另存为模板…** 会将当前列的形态保存为一个具名的租户级模板。它只保存形态，不附带任何授权。
- 在另一个项目的列上，**应用模板**会以模板的形态开始设置该列，每个分组的授权均为空，等待您填写。

任何项目架构师都可以保存和应用模板。重命名（**重命名…**）和删除（**删除**）模板需要租户管理员，因为模板在整个租户内共享。删除模板后，已应用它的列仍保持原有的限制。

<Aside type="note">
模板是副本，而不是链接。之后编辑模板不会更改任何已应用过它的列——请重新应用模板，使列与模板的后续修订保持一致。
</Aside>

### 来自 SSO 组属性的授权

列也可以从您的身份提供商而不是 PlaidCloud 获取授权。项目架构师在行访问中启用 **Accept row-access grants from SSO group attributes**，即可让某一列采用此方式。

启用后，安全组的 Keycloak 属性 `row_access.<column>` 会设置该分组通过该列可以看到的值——在 Keycloak 中为分组设置该属性，PlaidCloud 就会为任何已有项目访问权限的分组自动采用。行访问本身无需再做任何配置，授权会在 PlaidCloud 自身的查询和 Superset 仪表板中保持同步。

<Aside type="caution">
这只会向已经可以访问项目的分组授予值。将 `row_access.region` 添加到没有项目访问权限的分组，在该分组也获得项目访问权限之前，不会授予它任何内容。
</Aside>

### 保存前预览

行访问会在您提交之前，向您展示更改的含义：

- **预览身份**页脚会显示某个分组可以看到表的总行数中的多少行，以及这些行本身的样本——在网格中选择任意分组即可预览。保存后预览会刷新。
- 保存之前，行访问会就任何值得再看一眼的情况发出警告：某个分组没有任何勾选，并按照您的 **Everyone else** 设置说明这意味着它看到所有行还是不看到任何行；拥有项目访问权限但不在任何分组授权覆盖范围内的成员；或者该列值为空（`NULL`）且没有任何分组被授权的行。

### 受限成员能看到什么

无论受限成员按名称在何处读取表，他们都只会得到自己的行——表资源管理器的网格、列分面和下载、表下载对话框、以查看者身份读取的应用和工具，以及仪表板。当您查看的网格已按您的授权过滤时，表资源管理器会在工具栏中显示**行数受您的访问权限限制**，开始将被过滤的下载时会提示“Rows limited by your access.”读取每一行的架构师则两者都不会看到。

### 行访问与您自己编写的查询

行访问通过过滤其所针对的表来限制分组可以看到哪些行。自己编写的查询没有单一的表可以附加该过滤——查询可以联接、合并或嵌套任意多张表——因此在限制行的项目上，PlaidCloud 会拒绝运行调用方提供的查询，而不是返回未经审查的行。

这适用于通过您自己的 SQL 读取、将您自己的 SQL 的结果导出到文件或另一个数据库，以及在扇出步骤的“Test row 1”预览中输入行条件。它**不**适用于按名称读取表，这是应用和工具读取数据的常规方式——这些方式会应用授权，并返回查看者有权看到的行。写成单张表的普通查询的列分面也是按名称读取，因此会返回成员自己的值，而不是被拒绝。

被拒绝的人会被告知是哪个项目，并被指向按名称读取的方式。项目架构师可以按原样运行该查询，并以任何格式导出其结果，因为架构师本来就可以为自己授予每个受限列的每个值。

导入电子表格本身并不是您自己编写的查询——普通的文件导入完全不读取受限数据，它只是根据您上传的文件创建项目自己的新表，因此不受行访问影响。例外是数据投影由调用方提供的导入：逐列表达式或动态 Excel 映射。在交互式导入屏幕上，这些会像上述自由格式 SQL 的入口一样被拒绝，并需要项目架构师，因为调用方提供的投影可能读取另一张表。无论哪种情况，由工作流运行的导入都不受影响，因为它以项目自己的服务身份运行。

<Aside type="caution">
在项目上限制第一列会改变所有使用该项目的人的情况。如果该项目上的 Panel 应用、笔记本或集成通过自行编写 SQL 来读取数据，请在限制之前将其改为按名称读取表——否则它将对所有非架构师停止工作。
</Aside>

### 行访问与数据编辑器

数据编辑器直接读取和写入表，因此行访问对两个方向都适用。

在数据编辑器中打开受限表时，只显示您的安全组被授权的行——这与您在仪表板中遇到的过滤相同，即使受限列不在网格显示的列中也同样适用。

保存您的编辑需要项目的**架构师**权限。保存会整体替换表的行，而不是读取它们，并且不会逐行过滤，因此在受限表上编辑数据被视为创作操作而不是读取：没有架构师权限的人会被告知需要该权限。不含受限列的表照常编辑，不限制行的项目也一样。

### 向受限表加载数据

当行访问限制了您可以看到的行时，使用 Python 客户端（`PlaidConnection`）将 DataFrame 写入受限表或清除它，或通过 REST API 向其保存记录或清除它，都只作用于您自己的行。替换表的数据只替换您能看到的行，清除只清除这些行，追加则添加行；其他所有行保持不变。

包含超出您访问范围的行的加载会在任何更改发生之前被拒绝，错误会列出每个超出您访问范围的值及带有该值的行数。省略了受限列的行会被当作该列为空来检查，因此除非您的访问范围包含空行，否则会被拒绝。以会改变列类型的方式替换数据也会被拒绝；请联系项目架构师进行该更改。

项目架构师、授权覆盖每一行的成员，以及以项目服务身份运行的工作流运行，照常写入整张表。不含受限列的表不受影响。

个人对任何表所做的这类写入，都会记录在安全日志中。工作流运行不会记录在那里。

### 行数与表大小

表的行数和存储大小描述的是整张表，而不是您可能看到的行，因此它们会告诉受限读取者在其授权之外还存在多少行。在限制行的项目上，凡读取受到过滤的人，都看不到项目中任何表的行数或大小——在表列表、搜索、表详情和快照中，以及通过 AI 助手和经 MCP 连接的 AI 工具也是如此。这涵盖项目中的每张表，包括没有受限列的表。项目自身的总数也会对他们隐藏——主页、项目列表和搜索以及项目详情中的总行数和大小。

工作流运行历史同样如此。每次运行和每个步骤记录的读取和写入的行数同样描述整张表，因此对于同样的读取者，这些数字会留空——在工作流和步骤的运行历史中，以及通过 AI 助手和经 MCP 连接的 AI 工具也是如此。对他们而言，[Weave](/zh-cn/guides/ai-assistant/weave-findings/) 不会检查步骤的行数或空值是否与以往运行不同，因为这样的发现项本身就会告诉他们整张表的行数发生了变化。

项目架构师照常看到这些数字，不限制行的项目上的所有人也一样。

### 查看成员能看到什么

要检查某个具体的人能看到什么，而不是某个分组被授予什么：打开 **Identity → Member**，选择该成员，然后打开其**行访问**选项卡。其**有效访问权限**列会针对每个受限项目和列，列出该成员通过其所有分组合并后看到的值——包括来自 SSO 组属性的授权，以及分组授权包含的空（`NULL`）行。项目架构师显示为**可查看所有行（架构师）**，因为架构师读取每一行。这与 PlaidCloud 自身查询所采用的答案相同，因此对支持工作很有用，也可以在有人报告问题之前确认更改达到了您的预期。

### 更清晰的错误

当行访问阻止某项操作时——在限制行的项目上自己编写的查询、没有架构师权限的编辑、对自动化、维度或授权来源表的更改，以及上述其他情形——消息会指明受到了什么限制以及下一步该怎么做，例如应联系哪些架构师，而不是给出笼统的失败提示。

### 行访问会被审计

限制或取消限制某一列，以及编辑分组的授权，都会在该项目的[项目日志](/zh-cn/get-started/tutorials/collaborate-versions-and-sharing/#阅读项目日志)中写入一条记录——谁在何时做了更改。在项目上打开 **Analyze → Projects → Log** 即可查看。无需为行访问开启任何设置即可获得此记录；它与项目的其他所有受跟踪更改的记录方式相同。

## 设置默认安全组


为减少添加新成员所需的时间，可以确定一组默认安全组。这为新成员提供一组基准安全组，无需手动逐个分配。添加新安全组时，如果勾选安全组窗口底部写有“Assign to New Users by Default”的复选框，即可使用该设置。



## 执行安全审核


安全审核功能可让您查看所有成员和分组的分组成员关系。



**执行安全审核：**


1. 打开 Identity
2. 选择“Security”选项卡
3. 在下拉菜单中单击“Security Group Audit”

由于 PlaidCloud 中的所有表都可以导出为 CSV 文件格式，分组与成员的关联可以在 PlaidCloud 之外查看，既可用于历史留存，也可以只是离线看看消遣。



**从“Security Group Audit”表单导出：**


1. 打开 Identity
2. 选择“Security”选项卡
3. 在下拉菜单中单击“Security Group Audit”
4. 单击表中“Username”最右侧的小图标
5. 根据您的偏好，单击“Export CSV”或“Export XLXS”

## 查看可用的权限设置


工作区中使用的每个应用程序都有各自可用的权限。安全组权限基于这些应用程序权限。


每个应用程序的完整可用权限列表可在 Security Bin 中查看。



**访问 Security Bin：**


1. 打开 Identity
2. 选择“Security”
3. 在下拉菜单中单击“Security Bins”

要查看每个应用程序的详细安全设置，请选择最左侧的标签图标。



这些可用的安全设置信息仅供参考。有关管理权限的详细信息，请参阅上文的“管理安全组”一节。
