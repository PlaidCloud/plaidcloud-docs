PlaidCloud 的安全和访问管理简单直观。成员是否获得访问权限，取决于其所属的分组。添加或更改成员的安全关联可以灵活自定义。

<Aside>每个工作区可以拥有不限数量的安全组，但我们建议尽量减少安全组数量，以便于安全管理。</Aside>



## 管理安全组


安全组可以添加、更新或删除。



**管理安全组：**


1. 打开 Identity
2. 在导航栏中选择 **安全组**（将显示现有分组的列表）
3. 要添加分组，请单击**新建组**
4. 要编辑分组的权限，请单击最左侧的图标

**管理分组成员：**


1. 打开 Identity
2. 在导航栏中选择 **安全组**
3. 单击成员图标
4. 将所需成员从“Unassigned Members”列拖到“Assigned Members”列，或反向拖动以移除成员

<Aside>在“Assigned Members”列为空时保存不会产生任何更改，并会给出相应提示。要让所有人都失去某个分组，请移除该分组的权限或删除该分组，而不是清空其成员。</Aside>

<Aside>如果某个分组通过[行访问](#管理行访问)获得了行授权，成员变更会在大约一分钟内同步到仪表板：新添加的成员会在仪表板中看到该分组的行，被移除的成员则不再看到这些行。停用或删除成员以及删除分组，也以同样方式生效。</Aside>

<Aside type="caution">保存分组的权限矩阵时，您自己无法授予的权限会保持不变，并且不会显示在矩阵中。如需更改此类权限，请联系拥有该权限的人员——权限矩阵只会编辑您能控制的内容。</Aside>

<Aside type="caution">只有当您拥有某个分组授予的全部权限时，才能将成员添加到该分组，或为成员选择分组。邀请他人担任架构师时同样适用此规则。工作区管理员不受此限制。</Aside>

## 管理行访问

行访问根据某一列的值，限制安全组可以查看表中的哪些行。例如，可以用 `region` 列限制访问：被授予 `East` 和 `Central` 的分组只能看到带有这些值的行。针对某个项目和列的所有设置——选择列、选择其值的来源、决定哪个分组能看到什么——都在同一个屏幕中完成，保存后立即生效。

设置和更改行访问需要项目架构师或租户管理员。其他人打开项目的“安全”选项卡时，会看到行访问仅限架构师使用的提示，下面列出的入口也不会对他们显示。

### 打开行访问

每个入口都会打开同一个行访问屏幕：

- **表资源管理器的工具栏**中有 **行访问** 按钮，当表已限制行时会显示徽标。如果表有受限列，屏幕会打开其第一个受限列，您也可以切换到该表的任意其他列。
- **列的分面菜单**中有 **按此列限制行…**，可在该列上打开行访问。对于已限制行的列，该菜单项显示为 **按此列限制的行 — 编辑…**。
- **项目的“安全”选项卡**列出项目上的所有受限列，以及其适用的表、拥有授权的分组和 **同步** 状态。选择某一列即可编辑，或单击 **限制某一列…** 新建限制：先选择表，再选择列。已限制行的列会带有锁形标记。
- **Identity → Member** 中成员的 **行访问** 选项卡，以及 **Identity → 安全 → 安全组** 中分组的行访问摘要。**打开行访问**（或 **编辑**）会打开所选列；**添加** 会在该行所属的项目中限制另一列。

从某一列打开时，屏幕会固定在该列上。通过 **限制某一列…** 或 **添加** 打开时，可以自行选择列。

### 行访问网格

按列限制表：

1. 从上述任一入口打开行访问；如果进入时尚未指定列，请选择列——选择器提供的是表中真实存在的列，而不是自由文本。
2. 选择 **值来源**——**列**（某个表中某一列的不重复值）、**维度**（某个维度的节点）或 **列表**（您手动输入的值）。值类型跟随该列的数据类型。
3. 为每个安全组勾选该分组可以查看的值。网格会列出有权访问该项目的分组，以及已在该列上拥有授权的任何分组。
4. 将 **Everyone else** 设置为 **sees all rows** 或 **sees no rows**——此设置适用于在网格中没有任何勾选的分组。
5. 单击 **保存**。

保存即时生效。PlaidCloud 自身的查询会立即遵循更改，Superset 仪表板会在大约一分钟内跟进——无需单独执行应用步骤，只有当某个授权包含其来源已不存在的值时，**保存** 才会停下来询问（见下文）。屏幕上的同步状态会显示更改的进度；请参阅[保持仪表板同步](#保持仪表板同步)。

网格还会为您处理以下细节：

- **值很多时。** 值会排序显示。当某列的值多到无法全部显示时，网格会提示“值太多，无法在此全部显示——请输入以搜索。”，筛选框会搜索整列，并保留分组已拥有的每个值。
- **来源中已不存在的值。** 当来源失去某个已授予分组的值时——表中已没有任何行包含该值、维度中已没有该成员，或列表中已没有该值——该值仍会保留在网格中。其列标题会带有警告图标，将鼠标悬停在图标上可查看原因。**全选**、**反选** 和 **粘贴** 不会改变各分组对此类值的持有状态。除非您取消勾选，否则不会从授权中移除任何内容：当某个分组仍持有此类值时单击 **保存**，行访问会在 **Values No Longer in the Source** 中列出相关分组和值并询问您。**Keep and Save** 按原样保存这些值，**Remove and Save** 会先将它们从所有分组的授权中移除，而关闭该询问则不保存任何内容。如果移除后某个分组将没有任何勾选，询问中会根据 **Everyone else** 的设置说明该分组届时将看到所有行还是一行都看不到。尚未保存的勾选会随其值一起处理。当某列的值多到无法全部显示，或其表尚未构建时，行访问无法判断表中缺少哪些值，因此会保留所有已授予的值，且不标记任何值。
- **空值。** 一个 **空值 — 对每个拥有授权的组可见** 复选框决定该列中没有值的行。勾选后，在该列上拥有任何授权的每个分组都能看到这些行。
- **尚未构建的表**会显示 **请先构建此表（运行创建它的工作流）**，而不是空列表。
- **保存会等待屏幕上的值加载完成。** 值加载期间——切换值来源、维度或表，或应用模板之后——**保存** 处于禁用状态，工具提示为“此来源的值加载完成后即可保存。”如果加载失败，网格会给出提示并要求您重新选择来源；在加载成功之前不会保存任何内容。

### 一个列名，适用于所有表

限制属于项目上的某个列*名称*，而不是单个表。一旦 `region` 限制了行，项目中每个包含名为 `region` 的列的表都会按此筛选，无论是在 PlaidCloud 自身的查询中还是在仪表板中。网格的 **Applies to** 列表会显示这些表。该列表为只读，因为它由列名决定；之后添加的、具有相同列的表一经发布即会被覆盖。

当项目中没有任何表包含该名称的列时，窗口除了显示 **Applies to 0 tables** 之外，还会警告该限制在有表包含此列之前不会筛选任何仪表板。为某个表添加该列，或更正列名，警告即会消除。

<Aside type="caution">
**列名必须完全匹配**——包括大小写和空白字符。`Region` 和 `region` 是不同的名称，`region` 与带尾随空格的 `region ` 也不同。选择器只提供真实的列名，因此这主要影响在其他地方被重命名的列——此时行访问会发出警告，并给出它找到的最接近的列，而不是悄无声息地什么都不限制。
</Aside>

<Aside type="caution">
**发布一个限制行的表时，会在同一步骤中设置其仪表板筛选器。** 仪表板通过表的已发布报表视图读取表，因此当您发布或重新发布带有受限列的表时，PlaidCloud 会在发布完成之前注册该表的仪表板筛选器。如果无法注册，发布会被拒绝，并回滚该次尝试创建的所有内容，因此受限表绝不会在仪表板中处于未筛选状态。在限制行的项目上无法发布*视图*，因为视图的查询可以重命名或派生受限列。请参阅[发布表](/zh-cn/guides/data/publish/)。
</Aside>

### 停止限制

网格上的 **停止限制** 会在内联确认后移除限制——“停止按‘region’限制行？该列上所有分组的授权都将被移除，所有人都能看到其行。”随后行访问会确认“‘region’中的行不再受限。”该列的 Superset 数据集也会随之删除，除非仍有图表在使用它；在这种情况下，行访问会说明数据集将保留，以及有多少个图表在使用它。

当某列限制行时，无法重命名或删除该列。架构师会被告知先在行访问中停止对该列的限制；其他人会被告知联系项目架构师。

### 谁可以更改限制行的项目

项目的工作流、步骤和用户定义函数以项目自身的服务身份运行，该身份可以读取所有行。能够更改它们的人可以让某个步骤把自己未获授权的行复制到自己可读的表中，因此在项目上限制行，也会限制谁可以更改项目的行为。一旦项目限制了至少一列：

- **自动化仅限架构师。** 只有项目架构师和租户管理员可以更改工作流、步骤、用户定义函数、计划、工作流变量和项目变量，以及通知电子邮件模板——出于同样的原因，也只有他们可以导入工作流包、转换 Alteryx 工作流、向项目中导入、复制或还原内容，或更改其连接环境、默认文档账户或 ERP 过账模式。其他人仍可以运行项目的工作流：**开始**、**停止**、**恢复** 和 **运行所选步骤** 仍然可用。对他们而言，步骤编辑器、工作流的创作控件、UDF 编辑器和计划表单都以只读方式打开，并显示一个列出可联系的架构师的横幅：“此项目限制行，因此只有其架构师可以更改工作流、步骤、UDF、计划、变量和通知模板。您仍然可以运行它们。”
- **受限列读取的维度仅限架构师。** 决定谁能看到哪些行的维度——即受限列的值来源——只能由项目架构师、租户管理员以及项目自身的工作流更改。这包括添加、移动、重命名、复制、清除、加载和还原其节点，以及维度本身。其他人会被告知“此维度决定谁能看到‘region’的哪些行，因此只有项目架构师可以更改它。”未被任何限制读取的维度不受影响。
- **授权来源表仅限架构师。** 绑定为某列[授权来源](#将授权绑定到源表)的表，其行只能由项目架构师、租户管理员或项目的工作流更改或删除——无论是通过数据编辑器、导入、连接器加载还是 API。
- **复制项目仅限架构师**，并且副本会显示“此副本不受行限制。”——在您设置限制之前，新项目不带任何限制。
- **还原早期版本与其他更改一样。** 还原项目自身的设置或上面列出的维度需要项目架构师。还原始终作用于该版本所属的对象，因此无法将其指向另一个项目来绕过此限制——请参阅[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。
- **编辑受限表中的数据**需要架构师，详见[行访问与数据编辑器](#行访问与数据编辑器)。
- **向受限表写入 DataFrame、保存记录和清除操作只会更改您自己的行**，除非您能看到所有行，详见[向受限表加载数据](#向受限表加载数据)。
- **当受限表包含您看不到的行时，对其进行的导入、复制、分支切换、还原和删除都会被拒绝**，详见[向受限表加载数据](#向受限表加载数据)。

在项目上限制第一列之前，行访问会告诉您此操作会影响哪些人：“在此处限制行意味着只有架构师才能更改此项目的工作流、步骤、UDF、计划和通知模板。目前有 N 名成员可以更改它们；他们仍然可以运行它们。”

运行（包括计划运行）会完全照常进行，因为它们以项目的服务身份运行。运行生成的结果遵循架构师为其设计的方式：不含受限列的输出表、导出文件、通知电子邮件或日志行，不会针对读取者进行筛选。

**运行开始时提供的值。** 任何能够运行工作流的人都可以使用自己的变量值启动工作流——[App Runner](/zh-cn/guides/workflows/use-converted-alteryx-apps/#app-runner-前端) 会用其表单中的答案这样做，API 和 AI 工具也可以。这些值仅对该次运行有效：它们永远不会保存在工作流上，其他运行、导出或读取者也看不到它们。由于运行以服务身份执行，这些值可以改变该次运行读取和写入的内容，因此请只将运行工作流的权限授予您信任的人。

**不限制任何行的项目。** 这些规则只有在项目限制了某一列之后才会生效。在不限制任何列的项目上，任何能够更改项目自动化的人都可以编写一个步骤或用户定义函数，使其以项目的服务身份运行时更改项目的访问权限，让自己成为项目的架构师之一。这是设计使然：此类项目不承诺任何行隔离。请只将此类项目的创作权限授予您愿意信任为架构师的人，或者限制某一列。

### 保持仪表板同步

行访问会在网格上以及项目“安全”选项卡的 **同步** 列中，显示更改在同步到仪表板途中所处的状态：

| 状态 | 含义 |
|---|---|
| **等待中** | 更改已保存，正在同步到仪表板。通常会在大约一分钟内完成。 |
| **正在重试** | 某次发送失败，正在重新尝试。失败原因显示在状态旁边，并提供 **重试** 以立即重新发送。 |
| **尚未应用** | 项目的限制尚未发送到仪表板。 |
| **已应用** | 最近一次向仪表板发送限制的尝试已成功。 |
| **与仪表板同步** | 行访问已将仪表板实际执行的内容与其要写入的内容进行比较，两者一致。 |
| **仪表板不一致** | 仪表板执行的内容与行访问要写入的内容不一致——某条规则在 Superset 中被更改或删除，或者无法检查某个表的已发布视图。 |
| **错误** | 发送限制失败。原因显示在状态旁边。 |

更改达到 **已应用** 后，网格会将其与仪表板进行核对，然后进入 **与仪表板同步** 或 **仪表板不一致**。**仪表板不一致** 和 **错误** 都提供 **重试**，可重新发送项目的限制。如果完全无法读取状态，网格会显示“无法检查同步状态。”

由单个表引起的 **错误** 会指出该表并说明处理方法——例如，某个表发布时未包含其受限列（“请重新发布或取消发布该表。”），或者某个带有受限列的表尚未发布，仪表板在其发布之前无法对其进行筛选。在您发布该表，或改为在已发布的表上限制该列之前，状态会一直保持为 **错误** 并指出未发布的表。这样的表不会阻碍项目的其余部分：其他所有表都会保持同步。

仪表板遵循与 PlaidCloud 自身查询相同的授权：

- **所有包含该列的已发布表都会被筛选**，而不仅是您设置限制时正在查看的那个表。
- **仅被授予部分值的分组会被筛选，即使其他人都能看到所有行**，这适用于每个已存在仪表板数据集的表。
- **项目架构师可以看到所有行**，在仪表板中与在表资源管理器及 PlaidCloud 其他位置一样。这适用于项目的架构师分组，以及与个别成员共享的项目的架构师。撤销架构师访问权限会立即在仪表板中生效，无论您是更改成员的角色、将成员或其分组从项目中移除、更改项目的访问类型、还原早期项目版本，还是删除分组。
- **安全组成员变更会自动同步到仪表板。** 在 PlaidCloud 中将某人添加到分组或从分组中移除、停用或删除成员、删除分组，或添加一位加入默认安全组的新成员，都会在大约一分钟内更新他们在仪表板中看到的内容，适用于向该分组授予值的每个项目，无需任何人重新打开行访问。在 PlaidCloud 之外进行的成员变更——直接在 Keycloak 中修改，或在登录时由单点登录将某人放入分组——会在大约 15 分钟内同步到仪表板，无需保存或重试。

### 维度授权

以 **维度** 作为值来源时，勾选某个节点即可授予其下的所有内容。授权会跟随维度变化：在维度保存后的下一次同步中，添加到已勾选节点下的成员会被授予该分组，而移出该节点或被删除的成员则不再被授予——无需任何人重新打开网格。重新打开网格时，您勾选过的节点仍会显示为已勾选。

单独勾选（而不是通过节点勾选）的成员在从维度中删除后仍保持授权，网格会将其标记为来源中已不存在的值。

取消勾选已勾选节点下的任何内容都会取消勾选该节点，分组只保留仍被勾选的成员。重新勾选该成员不会重新勾选节点——要勾选节点，请单击节点自己的复选框。**粘贴**、**全选** 和 **反选** 只勾选成员，从不勾选节点。

如果某个维度成员的名称无法用作行访问值，保存时会被拒绝并指出该成员。如果之后出现此类成员，其行不会授予任何人，同步状态会指出它：“维度‘…’的成员‘…’无法用作行访问值，因此其行未被授予。请在维度中重命名该成员。”

### 将授权绑定到源表

除了手动勾选值，您还可以将受限列指向一个已包含答案的源表——每行一个分组及其可查看的值。先在
网格中限制该列，然后添加一个 [**设置行访问权限**](/zh-cn/reference/workflow-steps/tables/table-set-row-access/)
工作流步骤，指定该列、源表以及源表的分组列和值
列。该步骤首次运行时会将该列绑定到该表：清除该列手动设置的授权，
并根据表中的行设置其授权。

绑定后，该列即为 **来源所有**：行访问网格会将其显示为锁定状态，并带有一个显示
源表名称的徽标；在您单击 **移除绑定** 之前，手动编辑其授权会被拒绝。

此后该步骤每次运行都会重新读取源表并重新应用授权——将其计划在
加载或刷新该表的工作流之后运行，源数据中添加、移除或重新分配的分组
就会在下一次运行时同步到行访问，无需任何人手动编辑网格。

由于源表决定了谁能看到什么，只有项目架构师、租户管理员或
项目自身的工作流可以更改其行或删除它。其他人会被告知“此表
提供‘region’的行访问授权，因此只有项目架构师可以更改其行或
删除它。”

### 限制模板

如果您构建了一个想要复用的限制结构——相同的值来源、值类型和
空值设置——只需保存一次，然后在需要的地方应用，而不必
逐列重新构建。

- 在打开的行访问屏幕中使用 **另存为模板…**，可将当前列的结构保存为
  一个已命名的租户级模板。它只保存结构——不会带上任何授权。
- 在另一个项目的列上使用 **应用模板**，会以模板的结构作为该列的起点，
  所有分组的授权均为空，供您填写。

任何项目架构师都可以保存和应用模板。重命名（**重命名…**）和删除
（**删除**）模板需要租户管理员，因为模板在整个租户中共享。
删除模板后，已应用该模板的列仍保持原有的限制。

<Aside type="note">
模板是副本，而不是链接。之后编辑模板不会改变任何已
应用该模板的列——要让某列与模板的后续修订保持一致，请重新应用该模板。
</Aside>

### 来自 SSO 分组属性的授权

列也可以从您的身份提供程序获取授权，而不是从 PlaidCloud 获取。
项目架构师可以在行访问中启用 **Accept row-access grants from
SSO group attributes**，为某列开启此功能。

启用后，安全组的 Keycloak 属性 `row_access.<column>` 会设置该
分组通过该列可以查看的值——在 Keycloak 中为分组设置该属性，PlaidCloud
会自动为任何已有项目访问权限的分组获取它。无需在行访问中
进行其他配置，授权在 PlaidCloud 自身的
查询和 Superset 仪表板中都会保持同步。

<Aside type="caution">
此功能只会向已能访问项目的分组授予值。向没有项目访问权限的分组添加 `row_access.region`
不会授予任何内容，直到该分组也被授予该
项目的访问权限。
</Aside>

### 保存前预览

行访问会在您提交更改之前向您展示其影响：

- **预览身份** 页脚会显示某个分组在表的总行数中可以看到多少行，并附有部分行的示例——在网格中选择任意分组即可预览。预览会在保存后刷新。
- 保存之前，行访问会提醒您任何值得再次确认的情况：没有任何勾选的分组，以及在您的 **Everyone else** 设置下这意味着它将看到所有行还是一行都看不到；拥有项目访问权限但未被任何分组授权覆盖的成员；或该列值为空（`NULL`）且未授予任何分组的行。

### 受限成员看到的内容

无论受限成员在何处按名称读取表，都只能获得自己的行——表资源管理器的网格、列分面和下载、表下载对话框、以查看者身份读取的应用和工具，以及仪表板。当您查看的网格已按您的授权筛选时，表资源管理器会在工具栏中显示 **行数受您的访问权限限制**，开始一个将被筛选的下载时会提示“行数受您的访问权限限制。”架构师可以读取所有行，因此不会看到这两条提示。

### 行访问与您自己编写的查询

当行访问限制了您的行时，您可以在项目的查询屏幕上运行自己的 SQL 查询，并准确获得授权允许的行。您可以将结果导出为 CSV、Excel 或 JSON，导出内容只包含这些行，并带有 **行数受您的访问权限限制** 提示。项目架构师可以读取所有行，因为架构师本来就可以为自己授予每个受限列的所有值，因此不会看到该提示。

包含百分号（`%`）的授权值在查询屏幕上会返回其授权的行，将此类查询下载为 CSV 也可正常工作。

对于非项目架构师的成员，以下操作仍会被拒绝：

- 在 Snowflake 或 Databricks 项目仓库上运行自己编写的自由格式 SQL。
- 从 Postgres 系列仓库导出自己编写的 SQL 的结果。
- 将自己编写的 SQL 的结果导出到另一个数据库。
- 在扇出步骤的“Test row 1”预览中输入行条件。
- 按早期快照读取受治理的表（时间旅行）。

被拒绝的人会被告知是哪个项目，并被引导使用按名称读取的方式：按名称读取表是应用和工具读取数据的常规方式，它会应用授权并返回查看者有权查看的行。写成单个表简单查询的列分面同样按名称读取，因此会返回该成员自己的值，而不会被拒绝。项目架构师可以按原样运行上述任何操作。

行访问会对视图按受治理的列进行筛选，因此视图必须以原始名称保留该列。删除或重命名了受治理列的视图不会被筛选。

导入电子表格本身并不属于您自己编写的查询——普通的文件导入完全不读取任何受限数据，它只会根据您上传的文件创建项目自己的新表，因此不受行访问影响。例外情况是数据投影由调用方提供的导入：按列表达式或动态 Excel 映射。在交互式导入屏幕上，这些导入会像上述自由格式 SQL 界面一样被拒绝，并需要项目架构师，因为调用方提供的投影可能会读取另一个表。从工作流运行的导入在任何情况下都不受影响，因为它以项目自身的服务身份运行。

<Aside type="caution">
在项目上限制第一列会改变所有使用该项目的人的这一行为。如果该项目上的 Panel 应用、笔记本或集成会在 Snowflake 或 Databricks 仓库上自行编写 SQL，或从 Postgres 系列仓库导出自己的查询结果，请在限制之前将其改为按名称读取表——否则，对所有非架构师用户而言，它将无法正常工作。
</Aside>

### 行访问与数据编辑器

数据编辑器直接读取和写入表，因此行访问会同时作用于读写两端。

在数据编辑器中打开受限表时，只会显示您的安全组获得授权的行——与在仪表板中跟随您的筛选相同，即使受限列不在网格显示的列中也同样适用。

保存编辑需要拥有项目的 **架构师** 权限。保存会整体替换表中的行，而不是读取它们，并且不会逐行筛选，因此在受限表上编辑数据被视为创作操作而不是读取操作：没有架构师权限的人会被告知需要该权限。不带受限列的表照常编辑，不限制任何行的项目也是如此。

### 向受限表加载数据

当行访问限制了您能看到的行时，使用 Python 客户端（`PlaidConnection`）向受限表写入 DataFrame 或清除该表，或通过 REST API 向其保存记录或清除该表，都只作用于您自己的行。替换表的数据只会替换您能看到的行，清除表只会清除这些行，追加则会添加行；其他所有行保持不变。

如果加载的数据包含超出您访问权限的行，会在发生任何更改之前被拒绝，错误信息会列出每个超出您访问权限的值以及包含该值的行数。省略受限列的行会被视为该列为空，因此除非您的访问权限包含空值行，否则会被拒绝。以会改变列类型的方式替换数据也会被拒绝；请联系项目架构师进行该更改。

项目架构师、授权覆盖所有行的成员，以及以项目服务身份运行的工作流运行，会写入整个表。不带受限列的表不受影响。

当受限表包含您看不到的行时，其他任何替换或移除整个受限表的操作都会被拒绝，且不会进行任何更改：向其导入文件、从另一个项目将表复制到其中、切换或合并其分支、从归档中还原它或在还原项目保留的快照时一并还原它、删除它、在删除后恢复它，以及任何先清空表再重新填充的其他操作。受限列为空的行会被视为您看不到的行，除非您的访问权限包含空值行。您能看到其所有行的表（例如您创建的只包含您自己行的表）可以被替换或删除。

个人对任何表进行的上述每次写入都会记录在安全日志中，包括被拒绝的写入。工作流运行不会记录在其中。

### 行数和表大小

表的行数和存储大小描述的是整个表，而不是您可以看到的行，因此它们会让受限读取者知道其授权之外还有多少行。在限制行的项目上，读取受筛选的人看不到该项目任何表的行数或大小——无论是在表列表、搜索、表详细信息和快照中，还是通过 AI 助手和通过 MCP 连接的 AI 工具。这适用于项目中的每个表，包括不带受限列的表。项目自身的总计也会对他们隐藏——包括 Home、项目列表和搜索以及项目详细信息中的总行数和大小。

工作流运行历史记录同样如此。每次运行和每个步骤记录的读取和写入行数也描述的是整个表，因此对于同样的读取者，这些数字会留空——无论是在工作流和步骤的运行历史记录中，还是通过 AI 助手和通过 MCP 连接的 AI 工具。对于他们，[Weave](/zh-cn/guides/ai-assistant/weave-findings/) 不会检查步骤的行数或空值是否与以往运行不同，因为发现项本身就会告诉他们整个表的行数发生了变化。

项目架构师照常看到这些数字，不限制任何行的项目上的所有人也是如此。

### 查看成员可以看到的内容

要检查特定人员可以看到什么（而不是某个分组被授予了什么）：打开 **Identity → Member**，选择该成员，然后打开其 **行访问** 选项卡。其 **有效访问权限** 列针对每个受限项目和列，列出该成员通过其所有分组合计可以看到的值——包括来自 SSO 分组属性的授权，以及分组授权中包含的空值（`NULL`）行。项目架构师显示为 **可查看所有行（架构师）**，因为架构师可以读取所有行。这与 PlaidCloud 自身查询所应用的结果相同，因此可用于支持工作，也可在有人报告问题之前确认某项更改是否达到了预期效果。

### 更清晰的错误信息

当行访问阻止某项操作时——在受限项目上运行自己编写的查询、没有架构师权限的编辑、对自动化、维度或授权来源表的更改，以及上文所述的其他情况——消息会指出受限的内容以及下一步该怎么做（例如可联系的架构师），而不是显示笼统的失败信息。

### 行访问会被审计

限制或取消限制某列，以及编辑分组的授权，都会在该项目的[项目日志](/zh-cn/get-started/tutorials/collaborate-versions-and-sharing/#阅读项目日志)中写入一条记录——记录谁在何时进行了更改。在项目上打开 **Analyze → Projects → Log** 即可查看。无需为行访问开启任何设置即可获得此记录；它的记录方式与项目的其他所有受跟踪更改相同。

## 设置默认安全组


为了减少添加新成员所需的时间，可以指定一组默认安全组。这样无需手动为每个人分配，即可为新成员提供一组基准安全组。添加新安全组时，勾选“安全组”窗口底部的“Assign to New Users by Default”复选框即可启用此设置。



## 执行安全审计


安全审计功能可以查看所有成员和分组的分组成员关系。



**执行安全审计：**


1. 打开 Identity
2. 在导航栏的 **安全** 下选择 **Group audit**

由于 PlaidCloud 中的所有表都可以导出为 CSV 文件格式，因此可以在 PlaidCloud 之外查看分组成员关联，无论是用于历史记录，还是只是离线浏览。



**从“Security Group Audit”表单导出：**


1. 打开 Identity
2. 在导航栏的 **安全** 下选择 **Group audit**
3. 单击表中“Username”最右侧的小图标
4. 根据您的偏好单击“Export CSV”或“Export XLXS”

## 查看可用的权限设置


工作区中使用的每个应用程序都有特定的可用权限。安全组权限基于这些应用程序权限。


每个应用程序的完整可用权限列表可以在 Security Bin 中查看。



**访问 Security Bin：**


1. 打开 Identity
2. 选择“安全”
3. 在下拉菜单中单击“Security Bins”

要查看每个应用程序的详细安全设置，请选择最左侧的标签图标。



这些可用安全设置信息仅供参考。有关管理权限的详细信息，请参阅上文的“管理安全组”一节。
