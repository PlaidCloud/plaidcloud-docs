PlaidCloud 的安全与访问管理简单直接。成员能否获得访问权限，取决于该成员所属的组。添加或更改成员的安全关联非常灵活。

<Aside>每个工作区可以拥有数量不限的安全组，但建议尽量减少安全组的数量，以便简化安全管理。</Aside>



## 管理安全组


可以添加、更新或删除安全组。



**管理安全组：**


1. 打开 Identity
2. 在导航栏中选择**安全组**（将显示现有组的列表）
3. 要添加组，请点击 **New group**
4. 要编辑组的权限，请点击最左侧的图标

**管理组成员：**


1. 打开 Identity
2. 在导航栏中选择**安全组**
3. 点击“成员”图标
4. 勾选应属于该组的成员，并取消勾选不应属于该组的成员。可使用筛选框查找人员。请参阅[使用选择器进行分配](#使用选择器进行分配)
5. 点击**更新分配**

<Aside>未分配任何人就保存不会产生任何更改，并会提示您。要让所有人都脱离某个组，请移除该组的权限或删除该组，而不是清空其成员。</Aside>

<Aside>如果某个组通过[行访问](#管理行访问)获得了行，成员变更会在大约一分钟内同步到仪表板：您添加的人员可在其中看到该组的行，您移除的人员则不再看到这些行。禁用或删除成员以及删除组，也以同样的方式生效。</Aside>

<Aside type="caution">保存组的权限矩阵时，您自己无法授予的权限会保持不变，也不会显示在矩阵中。如需更改其中某项，请联系拥有该权限的人员，矩阵只能编辑您可控制的权限。</Aside>

<Aside type="caution">只有当您拥有某个组所授予的全部权限时，才能将成员添加到该组，或为成员选择所属的组。邀请他人成为架构师时同样适用。工作区管理员不受此限制。</Aside>

## 使用选择器进行分配

无论是为人员、组还是其他项目分配某项内容的访问权限，都使用同一个复选清单，取代了以往的两个列表。每一行都有一个复选框，勾选的行即已分配。每一行将名称和电子邮件分列显示。可用它来设置组的成员、成员所属的安全组、科目的成员、组、代理和所有者、连接的访问权限、分发列表的工作区成员，以及 Weave 就绪状态集中的工作流。

- **筛选器**。在筛选框中输入内容可缩小列表范围。匹配为部分匹配且不区分大小写，因此 `smith` 会找到名称或电子邮件中包含它的所有人，`@example.com` 会找到该域名下的所有人。输入多个词时，仅保留同时匹配所有词的行。
- **粘贴电子邮件列表**。粘贴多个电子邮件地址（以空格、逗号、分号或换行分隔），列表就只显示这些人员。也可以混入整个域名，例如 `@example.com`。筛选框下方的一行会说明粘贴的条目中有多少匹配，并列出未找到的条目。点击**分配**后跟匹配数量，即可一键勾选所有匹配的人员。
- **All、Assigned 和 Not assigned**。列表上方的三个按钮可在全部、仅已分配和仅未分配之间切换，每个按钮都带有计数。它们可与筛选框组合使用。
- **Assign all shown 和 Unassign all shown**。这两个按钮会勾选或取消勾选当前筛选和视图所显示的每一行，隐藏的行不受影响。列表上方的一行会说明共显示多少行，总计多少行。
- **Will add 和 Will remove**。在点击保存按钮之前不会保存任何内容。您勾选的行会着色并显示 **Will add** 标记，您取消勾选的行则显示 **Will remove**。列表上方的摘要显示已分配的数量和待处理的更改，并带有**撤消**。摘要的显示形式例如 `12 assigned · +3 to add · −1 to remove`**。Undo changes** 会将所有内容恢复为打开窗口时的状态。
- **仅在有更改时才能保存**。保存按钮（例如**更新分配**、**更新成员**或**更新组**）仅在您做出更改后才可用。
- **键盘**。按**空格**可勾选或取消勾选所选行。在筛选框中按 **Enter** 不会保存，因此搜索时按下它绝不会更改访问权限。

如果您能看到谁拥有访问权限但无法更改，例如在您并非所有者的连接上，则选择器为只读：会有备注说明这一点，并且只列出已分配的人员，以首字母缩写代替复选框，也没有可更改分配的按钮。

## 管理行访问

行访问根据某一列的值，限制安全组可以看到表中的哪些行。例如，可以用 `region` 列来限制访问，被授予 `East` 和 `Central` 的组只能看到带有这些值的行。针对某个项目和列的所有操作（选择列、选择其值的来源、决定哪个组可以看到什么）都在同一个屏幕中完成，保存后立即生效。

设置和更改行访问需要项目架构师或租户管理员。其他人打开项目的“安全”选项卡时，会被告知行访问仅限架构师使用，下文所述的入口也不会向他们显示。

### 打开行访问

所有入口打开的都是同一个行访问屏幕：

- **表资源管理器的工具栏**有一个**行访问**按钮，当表已限制行时按钮上带有徽章。它会在表的第一个受限列上打开（如果有的话），您也可以切换到该表的任何其他列。
- **列的分面菜单**中有**按此列限制行…**，它会在该列上打开行访问。在已经限制行的列上，该菜单项显示为**按此列限制的行 — 编辑…**。
- **项目的“安全”选项卡**列出项目上所有受限的列，以及其适用的表、持有授权的组及其**同步**状态。选择某一列即可编辑，或点击**限制某一列…** 开始新的限制：先选择表，再选择列。已限制行的列带有锁形标记。
- **Identity → Member** 中成员的**行访问**选项卡，以及 **Identity → Security → Security Groups** 中组的行访问摘要。**打开行访问**（或**编辑**）会打开所选的列；**添加**会在该行所属的项目中限制另一列。

在某一列上打开时，屏幕会停留在该列。通过**限制某一列…** 或**添加**打开时，可以自行选择列。

### 行访问网格

按某一列限制表的步骤：

1. 从上述任一入口打开行访问，如果打开时没有指定列，请选择列，选择器提供的是表的真实列，而不是自由文本。
2. 选择**值来源**：**列**（表某一列的不同值）、**维度**（维度的节点）或**列表**（您输入的值）。值类型取决于该列的数据类型。
3. 对每个安全组，勾选该组可以看到的值。网格列出有权访问该项目的组，以及已在该列上持有授权的所有组。
4. 将 **Everyone else** 设置为 **sees all rows** 或 **sees no rows**，这适用于网格中没有任何勾选的所有组。
5. 点击**保存**。

保存即生效。PlaidCloud 自身的查询会立即遵循更改，您的 Superset 仪表板会在大约一分钟内遵循更改，无需单独的应用步骤；只有当某项授权持有其来源已不再具有的值时，**保存**才会停下来询问（见下文）。屏幕的同步状态显示更改进行到了哪一步；请参阅[保持仪表板同步](#保持仪表板同步)。

网格还会为您处理以下细节：

- **大量值**。值已排序。当某一列的值多到无法全部显示时，网格会显示“More values than fit here — type to search.”，筛选框会搜索整列，并保留各组已持有的所有值。
- **来源已不再具有的值**。当某个值的来源不再具有它时（表中已没有任何行含有该值、维度中不再有该成员，或列表中不再有该值），授予某个组的这个值仍会保留在网格中。其列标题带有警告图标，悬停时会说明原因。**全选**、**反选**和**粘贴**会让这样的值保持各组当前持有的状态。除非您取消勾选，否则不会从授权中移除任何内容：当您点击**保存**而某个组仍持有这样的值时，行访问会在 **Values No Longer in the Source** 中列出相关的组和值并询问您。**Keep and Save** 按原样保存它们，**Remove and Save** 会先将它们从每个组的授权中移除，关闭该提问则不保存任何内容。如果移除它们会使某个组没有任何勾选，提问中会根据 **Everyone else** 说明该组随后将看到所有行还是不看到任何行。尚未保存的勾选会随其值一起移除。当某一列的值多到无法全部显示，或其表尚未构建时，行访问无法判断表中缺少哪些值，因此会保留所有已授予的值而不作任何标记。
- **空值**。一个 **Blank values — visible to every group with a grant** 复选框决定该列中没有值的行如何处理。勾选后，在该列上拥有任何授权的每个组都能看到这些行。
- **尚未构建的表**会显示**请先构建此表（运行创建它的工作流）**，而不是空列表。
- **保存会等待屏幕上的值**。在值加载期间（切换值来源、维度或表之后，或应用模板之后），**保存**处于禁用状态，并带有提示“Save is available once this source's values load.”。如果加载失败，网格会说明并要求您重新选择来源；在加载成功之前不会保存任何内容。

### 一个列名，所有表

限制属于项目上的列*名称*，而不是单个表。一旦 `region` 限制了行，项目中所有带有名为 `region` 的列的表都会被它筛选，PlaidCloud 自身的查询和仪表板均如此。网格的 **Applies to** 列表会显示这些表。它是只读的，因为由列名决定，之后添加的带有同名列的表，一经发布即受覆盖。

如果项目中没有任何表含有该名称的列，除显示 **Applies to 0 tables** 外，窗口还会警告在有表含有该列之前，该限制不会筛选任何仪表板。向某个表添加该列或更正列名后，警告即会消失。

<Aside type="caution">
**列名必须完全匹配**，包括大小写和空白。`Region` 和 `region` 是不同的名称，`region` 和带尾随空格的 `region ` 也是不同的名称。选择器只提供真实的列名，因此这主要在某一列在别处被重命名时才有影响：此时行访问会发出警告，并指出它找到的最接近的列，而不是悄悄地什么也不限制。
</Aside>

<Aside type="caution">
**发布限制行的表时，会同时设置其仪表板筛选器**。仪表板通过表已发布的报表视图读取表，因此当您发布或重新发布带有受限列的表时，PlaidCloud 会在发布完成前注册该表的仪表板筛选器。如果无法注册，发布会被拒绝，该次尝试创建的内容会被回滚，因此受限的表不会在仪表板中处于未筛选状态。在限制行的项目上无法发布*视图*，因为视图的查询可能会重命名或派生受限列。请参阅[发布表](/zh-cn/guides/data/publish/)。
</Aside>

### 停止限制

网格上的 **Stop restricting** 会在内联确认后移除限制，确认内容为“Stop restricting rows by ‘region’? Every group's grant on it is removed and everyone sees its rows.”。随后行访问会确认“Rows in ‘region’ are no longer restricted.”。该列的 Superset 数据集会随之移除，除非仍有图表在使用它；在这种情况下，行访问会说明数据集保留，以及有多少个图表在使用它。

当某一列限制行时，无法重命名或删除该列。架构师会被告知先在行访问中停止对它的限制；其他人则会被告知请联系项目架构师。

### 谁可以更改限制行的项目

项目的工作流、步骤和用户定义函数以项目自身的服务身份运行，该身份可以读取每一行。能够更改它们的人可能让某个步骤把他们未被授权的行复制到他们可读的表中，因此限制项目的行也会限制谁可以更改项目的行为。一旦项目至少限制了一列：

- **自动化仅限架构师**。只有项目架构师和租户管理员才能更改工作流、步骤、用户定义函数、计划、工作流和项目变量以及通知电子邮件模板，并且出于同样的原因，也只有他们才能导入工作流包、转换 Alteryx 工作流，或向项目导入、复制或还原内容，或更改其连接环境、默认文档账户或 ERP 过账模式。其他人仍然可以运行项目的工作流：**开始**、**停止**、**恢复**和**运行所选步骤**仍然可用。步骤编辑器、工作流的创作控件、UDF 编辑器和计划表单对他们以只读方式打开，并带有一条横幅，指出应联系的架构师：“This project restricts rows, so only its Architects can change workflows, steps, UDFs, schedules, variables and notify templates. You can still run them.”
- **受限列所读取的维度仅限架构师**。决定谁能看到哪些行的维度（即受限列的值来源）只能由项目架构师或租户管理员以及项目自身的工作流更改。这涵盖添加、移动、重命名、复制、清除、加载和还原其节点，以及维度本身。其他人会被告知“This dimension decides who sees which rows of ‘region’, so only a project Architect can change it.”。没有任何限制读取的维度不受影响。
- **授权源表仅限架构师**。绑定为某列的[授权来源](#将授权绑定到源表)的表，只有项目架构师、租户管理员或项目的工作流才能更改其行或删除它，通过数据编辑器、导入、连接器加载或 API 均如此。
- **复制项目仅限架构师**，并且副本会显示“This copy is not row-restricted.”，在您设置之前，新项目不带任何限制。
- **还原较早的版本与其他更改一样**。还原项目自身的设置或上述某个维度，需要项目架构师。还原始终作用于该版本所属的项目，因此无法将其指向另一个项目以规避此限制，请参阅[版本历史](/zh-cn/guides/projects/managing-projects/#版本历史)。
- **在受限表中编辑数据**需要架构师，详见[行访问和数据编辑器](#行访问和数据编辑器)。
- **向受限表写入 DataFrame、保存记录和清除，只会更改您自己的行**，除非您能看到每一行，详见[向受限表加载数据](#向受限表加载数据)。
- **只要受限表中有您看不到的行，对其进行的导入、复制、分支切换、还原和删除都会被拒绝**，详见[向受限表加载数据](#向受限表加载数据)。

在项目上的第一列被限制之前，行访问会告诉您这会影响到谁：“Restricting rows here means only Architects can change this project's workflows, steps, UDFs, schedules and notify templates. N members can change them today; they will still be able to run them.”

运行会与以前完全一样地继续工作（包括计划运行），因为它们以项目的服务身份运行。运行产生的内容遵循其架构师所做的设计：不含受限列的输出表、导出文件、通知电子邮件或日志行，不会针对读取者进行筛选。

**在运行开始时给定的值**。任何能够运行工作流的人都可以使用自己的变量值来启动它，[应用运行器](/zh-cn/guides/workflows/use-converted-alteryx-apps/#app-runner-前端)就是用其表单的答案来这样做的，API 和 AI 工具也可以。这些值仅对该次运行有效：它们不会保存在工作流上，其他运行、导出或读取者也看不到它们。由于运行以服务身份执行，这些值可以改变该次运行所读取和写入的内容，因此请只将运行工作流的权限授予您信任的人。

**不限制行的项目**。这些规则仅在项目限制了某一列后才生效。在没有任何限制的项目上，任何能够更改项目自动化的人都可以编写一个步骤或用户定义函数，使其以项目的服务身份运行，更改项目的访问权限，让自己成为其架构师之一。这是设计使然：这样的项目并不承诺行隔离。请将那里的创作权限仅授予您信任为架构师的人，或者限制某一列。

### 保持仪表板同步

行访问会在网格上以及项目“安全”选项卡的**同步**列中，显示更改在到达仪表板途中的状态：

| 状态 | 含义 |
|---|---|
| **等待中** | 更改已保存，正在发送到仪表板。通常会在大约一分钟内清除。 |
| **正在重试** | 发送失败，正在再次尝试。失败的原因会显示在状态旁边，并带有**重试**，可立即再次发送。 |
| **尚未应用** | 项目的限制尚未发送到仪表板。 |
| **已应用** | 上一次向仪表板发送限制的尝试成功。 |
| **与仪表板同步** | 行访问将仪表板所执行的内容与它将写入的内容进行了比较，两者相符。 |
| **仪表板不一致** | 仪表板所执行的内容与行访问将写入的内容不一致，原因是某条规则在 Superset 中被更改或删除，或者无法检查某个表的已发布视图。 |
| **错误** | 发送限制失败。原因显示在状态旁边。 |

更改达到**已应用**后，网格会对照仪表板进行检查，并转为**与仪表板同步**或**仪表板不一致**。**仪表板不一致**和**错误**都提供**重试**，它会再次发送项目的限制。如果完全无法读取状态，网格会显示“无法检查”同步状态：“Couldn't check sync status.”

由某一个表引起的**错误**会指明该表并说明如何处理，例如某个表在发布时没有其受限列（“Republish or unpublish it.”），或者某个表带有未发布的受限列，在其发布之前仪表板无法对其进行筛选。状态会一直停留在**错误**并指明未发布的表，直到您发布它，或改为限制已发布表上的列。这样的表不会拖累项目的其余部分：其他每个表都会保持同步。

仪表板遵循与 PlaidCloud 自身查询相同的授权：

- **每个带有该列的已发布表都会被筛选**，而不仅仅是您设置限制时所查看的表。
- **即使其他所有人都能看到所有行，仅被授予部分值的组也会被筛选**，适用于每个其仪表板数据集存在的表。
- **项目架构师可以看到每一行**，在仪表板中的情形与在表资源管理器和 PlaidCloud 其余部分中相同。这适用于项目的架构师组，以及与个别成员共享的项目的架构师。无论您更改成员的角色、将成员或其组从项目中移除、更改项目的访问类型、还原较早的项目版本还是删除该组，取消架构师访问权限都会立即在仪表板中生效。
- **安全组成员变更会自动同步到仪表板**。在 PlaidCloud 中将某人添加到组或移除、禁用或删除成员、删除组，或添加加入您的默认安全组的新成员，都会在大约一分钟内更新他们在仪表板中看到的内容，涵盖每个向该组授予值的项目，无需任何人重新打开行访问。在 PlaidCloud 之外所做的成员变更（直接在 Keycloak 中进行，或由单点登录在登录时将某人放入某个组）会在大约 15 分钟内同步到仪表板，无需保存或重试。

### 维度授权

当值来源为**维度**时，勾选一个节点即可授予其下的所有内容。授权会跟随维度：在已勾选节点下添加的成员，会在维度保存后的下一次同步时授予该组；从该节点下移出或被移除的成员则不再被授予，无需任何人重新打开网格。重新打开时，您勾选过的节点会再次显示为已勾选。

单独勾选（而不是通过节点勾选）的成员在从维度中移除后仍保持已授予状态，网格会将其标记为来源已不再具有的值。

取消勾选已勾选节点之下的任何项会取消勾选该节点，该组仅保留仍被勾选的成员。再次勾选该成员并不会重新勾选该节点，要重新勾选节点，请点击节点自己的复选框。**粘贴**、**全选**和**反选**勾选的是成员，而不是节点。

名称无法用作行访问值的维度成员会在保存时被拒绝，并指明该成员。如果这样的成员稍后出现，其行不会授予任何人，同步状态会指明它：“Dimension ‘…’ member ‘…’ cannot be used as a row access value, so its rows are not granted. Rename it in the dimension.”

### 将授权绑定到源表

您可以不手动勾选值，而是将受限列指向一个已包含答案的源表，每行对应一个组及其可以看到的值。先在网格中限制该列，然后添加一个 [**设置行访问权限**](/zh-cn/reference/workflow-steps/tables/table-set-row-access/)工作流步骤，指定列、源表以及源表的组列和值列。该步骤的首次运行会将列绑定到该表：列中手动设置的授权会被清除，其授权改为根据该表的行设置。

绑定后，该列即为**源自拥有**：行访问网格会将其显示为锁定，并带有标明源表的徽章，在您点击**移除绑定**之前，手动编辑其授权会被拒绝。

该步骤之后的每次运行都会重新读取源表并重新应用授权。请将其安排在加载或刷新该表的工作流之后，源数据中添加、移除或重新分配的组会在下一次运行时进入行访问，无需任何人手动编辑网格。

由于源表决定谁能看到什么，只有项目架构师、租户管理员或项目自身的工作流才能更改其行或删除它。其他人会被告知“This table supplies the row access grants for ‘region’, so only a project Architect can change its rows or delete it.”

### 限制模板

如果您构建了一个想要复用的限制形态（相同的值来源、值类型和空值设置），可以保存一次，然后在需要的地方应用，而不必逐列重新构建。

- 在打开的行访问屏幕中使用**另存为模板…**，会将当前列的形态保存为一个已命名的租户级模板。它只保存形态，不会附带任何授权。
- 在另一个项目的列上使用**应用模板**，会以模板的形态启动该列，每个组的授权均为空，等待您填写。

任何项目架构师都可以保存和应用模板。重命名（**重命名…**）和删除（**删除**）模板需要租户管理员，因为模板在整个租户内共享。删除模板后，已应用它的列仍保持其限制不变。

<Aside type="note">
模板是副本，而不是链接。之后编辑模板不会更改任何已应用它的列，要使某一列与模板的后续修订保持一致，请重新应用该模板。
</Aside>

### 来自 SSO 组属性的授权

列也可以从您的身份提供商而不是从 PlaidCloud 获取其授权。项目架构师通过在行访问中启用 **Accept row-access grants from SSO group attributes**，让某一列选择采用此方式。

启用后，安全组的 Keycloak 属性 `row_access.<column>` 会设置该组可通过该列看到的值：在 Keycloak 中为组设置该属性，PlaidCloud 会自动为任何已有该项目访问权限的组获取它。在行访问本身中无需再配置其他任何内容，授权会在 PlaidCloud 自身的查询和 Superset 仪表板中保持同步。

<Aside type="caution">
这只会向已经能够访问项目的组授予值。向没有项目访问权限的组添加 `row_access.region` 不会授予它任何内容，直到该组也获得该项目的访问权限。
</Aside>

### 保存前预览

行访问会在您提交之前，向您展示更改的含义：

- **预览身份**页脚会显示一个组将能看到表总行数中的多少行，以及这些行的示例，在网格中选择任意组即可预览。保存后预览会刷新。
- 保存之前，行访问会就值得再看一眼的情况向您发出警告：某个组没有任何勾选，并根据您的 **Everyone else** 设置说明这意味着它看到所有行还是不看到任何行；拥有项目访问权限的成员未被任何组的授权覆盖；或者该列的值为空（`NULL`）的行没有被授予任何组。

### 受限成员能看到什么

无论受限成员按名称在何处读取表，他们都只会得到自己的行，包括表资源管理器的网格、列分面和下载、表下载对话框、以查看者身份读取的应用和工具，以及仪表板。当您正在查看的网格已按您的授权进行筛选时，表资源管理器会在其工具栏中显示**行数受您的访问权限限制**，开始将被筛选的下载时会提示“行数受您的访问权限限制。”读取每一行的架构师不会看到这两种提示。

### 行访问和您自己编写的查询

当行访问限制了您的行时，您可以在项目的查询屏幕上运行自己的 SQL 查询，并准确得到您的授权所允许的行。您可以将结果导出为 CSV、Excel 或 JSON，导出内容仅包含这些行，并带有**行数受您的访问权限限制**的提示。项目架构师可以读取每一行，因为架构师本来就可以为自己授予每个受限列的每个值，因此不会看到提示。

包含百分号（`%`）的授权值会在查询屏幕上返回其授予的行，并且将这样的查询下载为 CSV 也可正常工作。

对于不是项目架构师的成员，以下操作仍会被拒绝：

- 在 Snowflake 或 Databricks 项目仓库上运行自己编写的自由格式 SQL。
- 从 Postgres 系列仓库导出自己编写的 SQL 的结果。
- 将自己编写的 SQL 的结果导出到另一个数据库。
- 在扇出步骤的“Test row 1”预览中输入行条件。
- 读取较早快照时的受管控表（时间旅行）。

被拒绝的人会被告知是哪个项目，并被指向按名称读取的方式：按名称读取表是应用和工具读取数据的常规方式，它会应用授权并返回查看者有权获得的行。以单个表的普通查询形式编写的列分面同样是按名称读取的，因此它返回的是成员自己的值，而不会被拒绝。项目架构师可以按原样运行上述任何操作。

行访问会在受管控的列上筛选视图，因此视图必须以原名称保留该列。删除或重命名受管控列的视图不会被筛选。

导入电子表格本身并不是您自己编写的查询，普通的文件导入根本不读取任何受限数据，它只是根据您上传的文件创建项目自己的新表，因此不受行访问影响。例外是数据投影由调用方提供的导入：逐列表达式或动态 Excel 映射。在交互式导入屏幕上，这些操作会与上述自由格式 SQL 的场景一样被拒绝，需要项目架构师，因为调用方提供的投影可能读取另一个表。由工作流运行的导入不受任何影响，因为它以项目自身的服务身份运行。

<Aside type="caution">
在项目上限制第一列会改变所有使用该项目的人的情况。如果该项目上的 Panel 应用、笔记本或集成在 Snowflake 或 Databricks 仓库上自行编写 SQL，或从 Postgres 系列仓库导出自己的查询结果，请在限制之前将其改为按名称读取表，否则它对所有非架构师都将停止工作。
</Aside>

### 行访问和数据编辑器

数据编辑器直接读取和写入表，因此行访问在两个方面都适用。

在数据编辑器中打开受限表时，仅显示您的安全组被授予的行，这与在仪表板中跟随您的筛选相同，即使受限列不是网格中显示的列之一，也同样适用。

保存您的编辑需要项目上的**架构师**权限。保存会整体替换表的行而不是读取它们，并且不会逐行筛选，因此在受限表上编辑数据被视为创作操作而不是读取，没有架构师权限的人会被告知需要它。不带受限列的表照常编辑，不限制行的任何项目同样如此。

### 向受限表加载数据

当行访问限制了您所见的行时，使用 Python 客户端（`PlaidConnection`）将 DataFrame 写入受限表或清除它，或通过 REST API 向其保存记录或清除它，只会作用于您自己的行。替换表的数据只会替换您能看到的行，清除只会清除这些行，追加则会添加行，其他所有行保持不变。

如果加载包含您访问范围之外的行，会在任何内容更改之前被拒绝，错误会指出您访问范围之外的每个值以及有多少行带有该值。省略受限列的行在该列中按空值检查，因此除非您的访问包含空行，否则会被拒绝。以会更改列类型的方式替换数据同样会被拒绝，请让项目架构师进行该更改。

项目架构师、授权覆盖每一行的成员以及工作流运行（以项目的服务身份运行）可写入整个表。不带受限列的表不受影响。

只要受限表中有您看不到的行，其他任何会替换或移除整个受限表的操作都会被拒绝，且不会更改任何内容：向其中导入文件、从另一个项目将表复制到其中、切换或合并其分支、从归档还原它或在还原项目保留的快照时还原它、删除它、在删除后恢复它，以及在重新填充之前先将表清空的其他任何操作。除非您的访问包含空行，否则受限列为空的行视为您看不到的行。您能看到每一行的表（例如您创建的、只包含您自己的行的表）可以被替换或删除。

个人对任何表所做的每一次此类写入都会记录在安全日志中，包括被拒绝的写入。工作流运行不会记录在那里。

### 行数和表大小

表的行数和存储大小描述的是整个表，而不是您可能看到的行，因此它们会告诉受限读取者，其授权之外还存在多少行。在限制行的项目上，读取被筛选的任何人都不会看到该项目任何表的行数或大小，在表列表、搜索、表详细信息和快照中，以及通过 AI 助手和经由 MCP 连接的 AI 工具，均如此。这涵盖项目中的每个表，包括没有受限列的表。项目自身的总计对他们也会隐藏：首页、项目列表和搜索以及项目详细信息中的总行数和大小。

工作流运行历史同样适用。每次运行和每个步骤所记录的读取和写入的行数同样描述整个表，因此对于相同的读取者，这些数字会留空：在工作流和步骤的运行历史中，以及通过 AI 助手和经由 MCP 连接的 AI 工具。对于他们，[Weave](/zh-cn/guides/ai-assistant/weave-findings/) 不会检查步骤的行数或与以往运行相比的空值情况，因为这样的发现项本身就会告诉他们整个表的行数已经变化。

项目架构师照常看到这些数字，不限制行的项目上的所有人也是如此。

### 查看成员能看到什么

要检查某个具体的人能看到什么，而不是某个组被授予什么：打开 **Identity → Member**，选择成员，然后打开其**行访问**选项卡。其**有效访问权限**列会为每个受限的项目和列，列出该成员通过其所有组合并后能看到的值，包括来自 SSO 组属性的授权，以及在某个组的授权包含空（`NULL`）行时的这些行。项目架构师显示为**可查看所有行（架构师）**，因为架构师读取每一行。这与 PlaidCloud 自身查询所应用的答案相同，因此对于支持工作，以及在有人报告问题之前确认更改达到了您的预期非常有用。

### 更清晰的错误

当行访问阻止某项操作时（在受限项目上自行编写的查询、没有架构师权限的编辑、对自动化、维度或授权源表的更改，以及上述其他情形），消息会指出受到限制的内容以及下一步该怎么做（例如应联系哪些架构师），而不是笼统的失败提示。

### 行访问会被审计

限制或取消限制某一列以及编辑组的授权，都会在该项目的[项目日志](/zh-cn/get-started/tutorials/collaborate-versions-and-sharing/#阅读项目日志)中写入一条记录，说明谁在何时做了更改。在项目上打开 **Analyze → Projects → Log** 即可查看。无需启用行访问的任何功能即可获得此记录，其记录方式与项目的其他所有被跟踪的更改相同。

## 设置默认安全组

 
为减少添加新成员所需的时间，请确定一组默认安全组。这样无需手动为每个人分配，就能为新成员提供一组基准安全组。添加新安全组时，如果勾选“安全组”窗口底部写着“Assign to New Users by Default”的复选框，即可使用该设置。



## 执行安全审计


安全审计功能可让您查看所有成员和组的组成员关系。



**执行安全审计：**


1. 打开 Identity
2. 在导航栏的 Security 下选择 **Group audit**

由于 PlaidCloud 中的所有表都可以导出为 CSV 文件格式，因此无论是出于历史记录目的，还是只是为了在离线时有趣地查看，组成员关联都可以在 PlaidCloud 之外进行审阅。



**从“Security Group Audit”表单导出：**


1. 打开 Identity
2. 在导航栏的 Security 下选择 **Group audit**
3. 点击表中“Username”最右侧的小图标
4. 根据您的偏好，点击“Export CSV”或“Export XLXS”
