PlaidCloud 的安全和访问管理简单明了。成员能否获得访问权限，取决于该成员所属的分组。添加或更改成员的安全关联非常容易自定义。

<Aside>每个工作区允许创建不限数量的安全组，但建议尽量减少数量，以便简化安全管理。</Aside>



## 管理安全组


可以添加、更新或删除安全组。



**管理安全组：**


1. 打开身份
2. 在导航栏中选择 **安全组**（将显示现有分组的列表）
3. 要添加分组，请点击 **New group**
4. 要编辑分组的权限，请点击最左侧的图标

**管理分组成员：**


1. 打开身份
2. 在导航栏中选择 **安全组**
3. 点击“成员”图标
4. 勾选应属于该分组的成员，并取消勾选不应属于该分组的成员。可使用筛选框查找人员。请参阅[使用选择器进行分配](#使用选择器进行分配)
5. 点击 **更新分配**

<Aside>在没有分配任何人的情况下保存不会产生任何更改，并且会告知您这一点。要取消所有人从分组获得的权限，请移除其权限或删除该分组，而不是清空其成员列表。</Aside>

<Aside>如果通过[行访问](#管理行访问)向某个分组授予了行，成员变动会在大约一分钟内传递到仪表板：新添加的人员会在那里看到该分组的行，被移除的人员则不再看到。停用或删除成员以及删除分组，也以同样的方式生效。</Aside>

<Aside type="caution">保存分组的权限矩阵时，您自己无法授予的权限会保持不变，并且不会在矩阵中显示。如果需要更改其中某一项，请向拥有该权限的人求助，权限矩阵只会编辑您能控制的内容。</Aside>

<Aside type="caution">只有在您拥有分组授予的每一项权限时，才能将成员添加到该分组，或选择成员所属的分组。邀请某人成为架构师时同样适用。工作区管理员不受此限制。</Aside>

## 使用选择器进行分配

在为人员、分组或其他项目授予某项内容的访问权限时，同一个复选列表取代了原先的两个列表。每一行都有一个复选框，被勾选的行即为已分配。可用它来设置分组的成员、成员所属的安全组、账户的成员、分组、代理和所有者、连接的访问权限、分发列表的工作区成员，以及 Weave 就绪集中的工作流。

- **筛选器。** 在筛选框中输入内容以缩小列表范围。匹配是部分匹配且不区分大小写，因此 `smith` 会找到包含它的每个姓名或电子邮件，`@example.com` 会找到该域名下的所有人。输入多个词时，仅保留与所有这些词都匹配的行。
- **粘贴电子邮件列表。** 粘贴多个以空格、逗号、分号或换行分隔的电子邮件地址，列表就会准确显示这些人员。您还可以混入整个域名，例如 `@example.com`。筛选框下方的一行会说明有多少粘贴的条目匹配，并列出未找到的条目。**Assign** 后跟匹配数量，可一键勾选所有匹配的人员。
- **All、Assigned 和 Not assigned。** 列表上方的三个按钮可在全部、仅已分配和仅未分配之间切换，每个按钮都带有计数。它们可与筛选器结合使用。
- **Assign all shown 和 Unassign all shown。** 它们会勾选或清除筛选器和视图当前显示的每一行，隐藏的行保持不变。列表上方的一行会说明总数中显示了多少行。
- **Will add 和 Will remove。** 在点击保存按钮之前，不会保存任何内容。已勾选的行显示 **Will add** 标签，已清除的行显示 **Will remove**。摘要的内容例如 `12 assigned · +3 to add · −1 to remove`。**Undo changes** 会将所有内容恢复为打开窗口时的状态。
- **仅在有更改时才可保存。** 保存按钮（例如 **更新分配**、**更新成员** 或 **更新组**）仅在您进行了更改时才可用。
- **键盘。** **空格** 键勾选或清除所选行。在筛选框中按 **Enter** 不会保存，因此在搜索时按它绝不会更改访问权限。

当您能看到谁拥有访问权限但无法更改时，例如对于不归您所有的连接，选择器为只读：它仅列出已分配的人员，没有可更改他们的复选框或按钮。

## 管理行访问

行访问根据某一列的值，限制安全组可以看到表的哪些行。例如，`region` 列可以限制访问，授予 `East` 和 `Central` 的分组仅限于带有这些值的行。针对某个项目和列的所有操作（选取列、选择其值的来源，以及决定哪个分组看到什么）都在单个屏幕中完成，保存后立即生效。

设置和更改行访问需要项目架构师或租户管理员。其他任何人打开项目的 **安全** 选项卡时，会被告知行访问仅限架构师使用，并且下列入口不会对其显示。

### 打开行访问

每个入口都会打开同一个行访问屏幕：

- **表资源管理器的工具栏** 上有一个 **行访问** 按钮，当表已限制行时会带有徽章。它会在表的第一个受限列上打开（如果有的话），您可以切换到该表的任何其他列。
- **列的分面菜单** 中有 **按此列限制行…**，它会在该列上打开行访问。在已限制行的列上，该项显示为 **按此列限制的行 — 编辑…**。
- **项目的“安全”选项卡** 列出项目上的每个受限列，以及其适用的表、持有授权的分组及其 **同步** 状态。选择某一列进行编辑，或点击 **限制某一列…** 开始新的限制：选择一个表，然后选择一列。已限制行的列以锁形标记。
- **身份 → 成员**（在成员的 **行访问** 选项卡上）和 **身份 → 安全 → 安全组**（在分组的行访问摘要上）。**打开行访问**（或 **编辑**）会打开所选的列；**添加** 会限制该行所属项目中的另一列。

在某一列上打开时，屏幕会停留在该列。通过 **限制某一列…** 或 **添加** 打开时，则可让您选择一列。

### 行访问网格

要按某一列限制表：

1. 从上述任一入口打开行访问，如果打开时没有指定列，请选择该列：选择器提供表的真实列，而不是自由文本。
2. 选择 **值来源**：**列**（表某一列的不同值）、**维度**（维度的节点）或 **列表**（您输入的值）。值类型取决于该列的数据类型。
3. 对每个安全组，勾选该分组可以看到的值。网格列出有权访问该项目的分组，以及已在该列上持有授权的任何分组。
4. 将 **Everyone else** 设置为 **sees all rows** 或 **sees no rows**，这涵盖在网格中没有任何勾选的所有分组。
5. 点击 **保存**。

保存即生效。PlaidCloud 自身的查询会立即遵循更改，您的 Superset 仪表板则在约一分钟内遵循，无需单独的应用步骤，**保存** 仅在授权持有其来源已不再拥有的值时才会停下来询问（见下文）。屏幕的同步状态显示更改进行到了哪一步，请参阅[保持仪表板同步](#保持仪表板同步)。

网格还会为您处理以下细节：

- **大量的值。** 值已排序。当某一列的值多到无法全部显示时，网格会显示“More values than fit here — type to search.”，并且筛选框会搜索整个列，同时保留分组已持有的每个值。
- **来源已不再拥有的值。** 当来源丢失某个已授予分组的值时，该值仍保留在网格中，即表中现在没有行具有该值、维度中不再有该成员，或列表中不再有该值。其列标题带有警告图标，悬停时会说明原因。**全选**、**反选** 和 **粘贴** 对此类值保持每个分组持有的状态。除非您取消勾选，否则不会从授权中删除任何内容：当您点击 **保存** 而某个分组仍持有此类值时，行访问会在 **Values No Longer in the Source** 中指明这些分组和值并询问。**Keep and Save** 会按原样保存它们，**Remove and Save** 会先将它们从每个分组的授权中删除，关闭该询问则不保存任何内容。如果删除它们会导致某个分组没有任何勾选，则询问会根据 **Everyone else** 说明该分组随后将看到所有行还是不看到任何行。尚未保存的勾选会随其值一起移除。当某一列的值多到无法全部显示，或其表尚未构建时，行访问无法判断表缺少哪些值，因此会保留每个已授予的值而不做任何标记。
- **空值。** 一个 **空值 — 对每个拥有授权的组可见** 复选框决定该列中没有值的行。勾选它后，对该列拥有任何授权的每个分组都会看到这些行。
- **尚未构建的表** 显示 **请先构建此表（运行创建它的工作流）**，而不是空列表。
- **保存会等待屏幕上的值。** 在加载值期间（切换值来源、维度或表之后，或应用模板之后），**保存** 会被禁用，并显示工具提示“Save is available once this source's values load.”。如果加载失败，网格会说明情况并要求您重新选择来源；在加载成功之前不会保存任何内容。

### 一个列名，适用于每个表

限制属于项目上的列*名称*，而不是单个表。一旦 `region` 限制了行，项目中每个具有名为 `region` 的列的表都会受其筛选，无论是在 PlaidCloud 自身的查询中还是在仪表板中。网格的 **Applies to** 列表会显示这些表。该列表为只读，因为由列名决定，之后添加的具有同名列的表一经发布即受覆盖。

当项目中没有任何表具有该名称的列时，除了显示 **Applies to 0 tables** 之外，窗口还会警告在有表具备该列之前，该限制不会筛选任何仪表板。向某个表添加该列，或更正列名，警告就会消失。

<Aside type="caution">
**列名必须完全匹配**，包括大小写和空白字符。`Region` 和 `region` 是不同的名称，`region` 和带尾随空格的 `region ` 也是不同的名称。选择器只提供真实的列名，因此这主要在列在别处被重命名时才有影响，此时行访问会警告您并指出它找到的最接近的列，而不是悄悄地什么都不限制。
</Aside>

<Aside type="caution">
**发布限制行的表时，会在同一步骤中设置其仪表板筛选器。** 仪表板通过表的已发布报告视图读取表，因此当您发布或重新发布带有受限列的表时，PlaidCloud 会在发布完成之前注册该表的仪表板筛选器。如果无法注册，则发布会被拒绝，该次尝试所创建的内容会被回滚，因此受限的表绝不会在仪表板中处于未筛选状态。在限制行的项目上无法发布*视图*，因为视图的查询可以重命名或派生受限列。请参阅[发布表](/zh-cn/guides/data/publish/)。
</Aside>

### 停止限制

网格上的 **停止限制** 在内联确认后移除限制，确认内容为“Stop restricting rows by ‘region’? Every group's grant on it is removed and everyone sees its rows.”随后行访问会确认“Rows in ‘region’ are no longer restricted.”该列的 Superset 数据集会随之删除，除非仍有图表在使用它；在这种情况下，行访问会说明数据集保留以及有多少图表在使用它。

当某一列限制着行时，不能重命名或删除该列。系统会告知架构师先在行访问中停止对其限制；其他任何人则会被告知询问项目架构师。

### 谁可以更改限制行的项目

项目的工作流、步骤和用户定义函数以项目自身的服务身份运行，该身份会读取每一行。任何能够更改它们的人都可能让某个步骤将其未被授予的行复制到其可读取的表中，因此在项目上限制行也会限制谁可以更改项目的行为。一旦项目至少限制了一列：

- **自动化仅限架构师。** 只有项目架构师和租户管理员才能更改工作流、步骤、用户定义函数、计划、工作流和项目变量以及通知电子邮件模板，并且出于同样的原因，还可以导入工作流包、转换 Alteryx 工作流，或向项目中导入、复制或还原内容，或更改其连接环境、默认文档账户或 ERP 过账模式。其他所有人仍然可以运行项目的工作流：**开始**、**停止**、**恢复** 和 **运行所选步骤** 仍然可用。步骤编辑器、工作流的创作控件、UDF 编辑器和计划表单对他们以只读方式打开，并带有一个说明可向哪些架构师求助的横幅：“This project restricts rows, so only its Architects can change workflows, steps, UDFs, schedules, variables and notify templates. You can still run them.”
- **受限列所读取的维度仅限架构师。** 决定谁能看到哪些行的维度（即受限列的值来源）只能由项目架构师或租户管理员以及项目自身的工作流更改。这涵盖添加、移动、重命名、复制、清除、加载和还原其节点，以及维度本身。其他任何人会被告知“This dimension decides who sees which rows of ‘region’, so only a project Architect can change it.”没有任何限制读取的维度不受影响。
- **授权来源表仅限架构师。** 绑定为列的[授权来源](#将授权绑定到源表)的表，其行只能由项目架构师、租户管理员或项目的工作流更改或删除，无论是通过数据编辑器、导入、连接器加载还是 API。
- **复制项目仅限架构师**，并且副本会显示“This copy is not row-restricted.”，在您进行设置之前，新项目不带有任何限制。
- **还原较早的版本与其他任何更改一样。** 还原项目自身的设置或上述某个维度需要项目架构师。还原始终应用于该版本所属的项，因此不能将其指向另一个项目来规避这一点，请参阅[版本历史记录](/zh-cn/guides/projects/managing-projects/#版本历史)。
- **编辑受限表中的数据** 需要架构师，详见[行访问和数据编辑器](#行访问与数据编辑器)。
- **除非您能看到每一行，否则向受限表进行的 DataFrame 写入、记录保存和清除只会更改您自己的行**，详见[向受限表加载数据](#向受限表加载数据)。
- **当受限表中含有您看不到的行时，对其进行的导入、复制、分支切换、还原和删除会被拒绝**，详见[向受限表加载数据](#向受限表加载数据)。

在项目上限制第一列之前，行访问会告知您这会影响谁：“Restricting rows here means only Architects can change this project's workflows, steps, UDFs, schedules and notify templates. N members can change them today; they will still be able to run them.”

运行与以前完全一样地继续工作，包括计划运行，因为它们以项目的服务身份运行。运行产生的内容遵循架构师赋予它的设计：不含受限列的输出表、导出文件、通知电子邮件或日志行，不会针对读取者进行筛选。

**运行开始时提供的值。** 任何可以运行工作流的人都可以使用自己为其变量提供的值来启动它，[应用运行器](/zh-cn/guides/workflows/use-converted-alteryx-apps/#app-runner-前端)就是用其表单的答案来实现这一点的，API 和 AI 工具也可以。这些值仅对该次运行有效：它们绝不会保存在工作流中，其他任何运行、导出或读取者都看不到它们。由于运行以服务身份执行，这些值可以改变该次运行读取和写入的内容，因此请仅将运行工作流的权限授予您信任的人。

**不限制行的项目。** 这些规则仅在项目限制了某一列之后才生效。在没有任何限制的项目上，任何可以更改项目自动化的人都可以编写一个步骤或用户定义函数，该步骤或函数以项目的服务身份运行，从而更改项目的访问权限，使自己成为其架构师之一。这是有意为之：此类项目不承诺行隔离。请将那里的创作权限仅授予您信任其担任架构师的人，或者限制某一列。

### 保持仪表板同步
行访问会在网格上以及项目“安全”选项卡的 **同步** 列中，显示更改在发往仪表板途中的进展：

| 状态 | 含义 |
|---|---|
| **等待中** | 更改已保存，正在发往仪表板。通常会在约一分钟内完成。 |
| **正在重试** | 发送失败，正在重试。失败原因会显示在状态旁边，并带有 **重试**，可立即再次发送。 |
| **尚未应用** | 项目的限制尚未发送到仪表板。 |
| **已应用** | 上一次将限制发送到仪表板的尝试已成功。 |
| **与仪表板同步** | 行访问将仪表板所强制执行的内容与其将要写入的内容进行了比较，二者一致。 |
| **仪表板不一致** | 仪表板强制执行的内容与行访问将要写入的内容不一致，原因是某条规则在 Superset 中被更改或删除，或者无法检查某个表的已发布视图。 |
| **错误** | 发送限制失败。原因会显示在状态旁边。 |

更改一旦达到 **已应用**，网格就会对照仪表板进行检查，并转到 **与仪表板同步** 或 **仪表板不一致**。**仪表板不一致** 和 **错误** 都提供 **重试**，它会再次发送项目的限制。如果完全无法读取状态，网格会显示“Couldn't check sync status.”

由某个表引起的 **错误** 会指明该表并说明该怎么做，例如，某个表发布时没有其受限列（“Republish or unpublish it.”），或者某个表带有未发布的受限列，在其发布之前仪表板无法对其进行筛选。状态会一直保持为 **错误** 并指明未发布的表，直到您将其发布，或者改为限制已发布表上的列。这样的表不会阻碍项目的其余部分：其他每个表都会保持同步。

仪表板遵循与 PlaidCloud 自身查询相同的授权：

- **每个带有该列的已发布表都会被筛选**，而不仅仅是您设置限制时所查看的表。
- **即使其他所有人都看到所有行，仅被授予部分值的分组也会被筛选**，适用于存在其仪表板数据集的每个表。
- **项目架构师可以看到每一行**，在仪表板中与在表资源管理器和 PlaidCloud 其他部分中一样。这适用于项目的架构师分组，以及与个别成员共享的项目的架构师。取消架构师访问权限会在仪表板中立即生效，无论您是更改成员的角色、从项目中移除成员或其分组、更改项目的访问类型、还原较早的项目版本，还是删除该分组。
- **安全组成员变动会自动传递到仪表板。** 在 PlaidCloud 中将某人添加到分组或从分组中移除、停用或删除成员、删除分组，或添加加入您默认安全组的新成员，都会在约一分钟内更新其在仪表板中看到的内容，适用于向该分组授予值的每个项目，无需任何人重新打开行访问。在 PlaidCloud 之外进行的成员变动（直接在 Keycloak 中进行，或由单点登录在登录时将某人放入某个分组）会在约 15 分钟内传递到仪表板，无需保存或重试任何内容。

### 维度授权

当值来源为 **维度** 时，勾选某个节点即可授予其下的所有内容。授权会跟随维度：在已勾选节点下添加的成员，会在维度保存后的下一次同步时被授予该分组；从其下移出或被移除的成员则不再被授予，无需任何人重新打开网格。当您重新打开时，您勾选过的节点仍显示为已勾选。

单独勾选（而不是通过节点勾选）的成员在从维度中移除后仍保持已授予状态，并且网格会将其标记为来源已不再拥有的值。

取消勾选已勾选节点下的任何内容都会取消勾选该节点，并且该分组仅保留仍被勾选的成员。再次勾选该成员不会重新勾选节点，请点击节点自己的复选框。**粘贴**、**全选** 和 **反选** 勾选的是成员，绝不是节点。

如果某个维度成员的名称无法用作行访问值，保存时会被拒绝并指明该成员。如果此类成员稍后出现，其行不会授予任何人，并且同步状态会指明它：“Dimension ‘…’ member ‘…’ cannot be used as a row access value, so its rows are not granted. Rename it in the dimension.”

### 将授权绑定到源表

除了手动勾选值之外，您还可以将受限列指向一个已包含答案的源表，即每个分组及其可以看到的值各占一行。先在网格中限制该列，然后添加一个 [**设置行访问权限**](/zh-cn/reference/workflow-steps/tables/table-set-row-access/)工作流步骤，指定列、源表以及源表的分组列和值列。该步骤的第一次运行会将列绑定到该表：列的手动设置的授权被清除，其授权改为根据该表的行来设置。

一旦绑定，该列即变为**源所有**：行访问网格会将其显示为锁定，并带有指明源表的徽章，在您点击 **移除绑定** 之前，不允许手动编辑其授权。

该步骤之后的每次运行都会重新读取源表并重新应用授权，请将其计划在加载或刷新该表的工作流之后运行，这样在源数据中添加、移除或重新分配的分组会在下一次运行时传递到行访问，无需任何人手动编辑网格。

由于源表决定谁看到什么，只有项目架构师、租户管理员或项目自身的工作流才能更改其行或将其删除。其他任何人会被告知“This table supplies the row access grants for ‘region’, so only a project Architect can change its rows or delete it.”

### 限制模板

如果您已构建了想要重复使用的限制形态（相同的值来源、值类型和空值设置），可以保存一次，并在需要的地方应用，而无需逐列重新构建。

- 在打开的行访问屏幕中，**另存为模板…** 会将当前列的形态保存为具名的租户级模板。它只保存形态，不会附带任何授权。
- 在另一个项目的列上，**应用模板** 会从模板的形态开始该列，每个分组的授权为空，供您填写。

任何项目架构师都可以保存和应用模板。重命名（**重命名…**）和删除（**删除**）模板需要租户管理员，因为模板在整个租户中共享。删除模板不会改变已应用该模板的列的限制状态。

<Aside type="note">
模板是副本，而不是链接。之后编辑模板不会更改已应用它的任何列，请再次应用该模板，使列更新到后来的修订版。
</Aside>

### 来自 SSO 分组属性的授权

列也可以从您的身份提供商而不是从 PlaidCloud 获取授权。项目架构师可在行访问中通过启用 **Accept row-access grants from SSO group attributes** 来为某一列选择加入。

启用后，安全组的 Keycloak 属性 `row_access.<column>` 会设置该分组可通过该列看到的值，在 Keycloak 中为分组设置该属性，PlaidCloud 会自动为已有项目访问权限的任何分组获取它。行访问本身无需进一步配置，并且授权在 PlaidCloud 自身的查询和 Superset 仪表板中都保持同步。

<Aside type="caution">
这只会向已经可以访问项目的分组授予值。将 `row_access.region` 添加到没有项目访问权限的分组，在该分组也被授予项目访问权限之前，不会授予它任何内容。
</Aside>

### 保存前预览

行访问会在您提交更改之前向您展示其含义：

- **预览身份** 页脚显示某个分组将在总行数中看到表的多少行，并附带行的示例，在网格中选择任意分组即可预览。预览会在保存后刷新。
- 保存之前，行访问会就任何值得再次查看的内容向您发出警告：没有任何勾选的分组，以及根据您的 **Everyone else** 设置，这意味着它看到所有行还是不看到任何行；拥有项目访问权限但未被任何分组的授权覆盖的成员；或者该列中值为空（`NULL`）且未授予任何分组的行。

### 受限成员看到的内容

受限成员无论在何处按名称读取表，都只会得到其自己的行，包括表资源管理器的网格、列分面和下载、表下载对话框、以查看者身份读取的应用和工具，以及仪表板。当您正在查看的网格已按您的授权进行筛选时，表资源管理器的工具栏会显示 **行数受您的访问权限限制**，并且开始下载将被筛选的内容时会显示“Rows limited by your access.”读取每一行的架构师不会看到这两种提示。

### 行访问与您自己编写的查询

当行访问限制您的行时，您可以在项目的查询屏幕上运行自己的 SQL 查询，并准确得到您的授权所允许的行。您可以将结果导出为 CSV、Excel 或 JSON，导出内容仅包含这些行，并带有 **行数受您的访问权限限制** 提示。项目架构师会读取每一行，因为架构师本来就可以为自己授予每个受限列的每个值，并且看不到任何提示。

包含百分号（`%`）的授权值会在查询屏幕上返回其被授予的行，并且将此类查询下载为 CSV 也可以正常工作。

对于不是项目架构师的成员，以下操作仍会被拒绝：

- 在 Snowflake 或 Databricks 项目仓库上运行自己的自由格式 SQL。
- 从 Postgres 系列仓库导出自己 SQL 的结果。
- 将自己 SQL 的结果导出到另一个数据库。
- 在扇出步骤的“Test row 1”预览中输入行条件。
- 读取某个较早快照时间点的受管表（时间旅行）。

被拒绝的任何人都会被告知是哪个项目，并被指引到按名称读取的方式：按名称读取表是应用和工具读取数据的常规方式，它会应用授权并返回查看者有权看到的行。写成单个表的普通查询的列分面也是按名称读取的，因此它返回的是成员自己的值，而不会被拒绝。项目架构师可以按原样运行其中任何一项。

行访问会在受管列上筛选视图，因此视图必须以原名称保留该列。删除或重命名受管列的视图不会被筛选。

导入电子表格本身并不是您自己编写的查询，普通的文件导入根本不读取受限数据，它只是根据您上传的文件创建项目自己的新表，因此不受行访问影响。例外情况是数据投影由调用方提供的导入：每列表达式或动态 Excel 映射。在交互式导入屏幕上，这些操作会与上述自由格式 SQL 界面一样被拒绝，并需要项目架构师，因为调用方提供的投影可能读取另一个表。从工作流运行的导入则不受任何影响，因为它以项目自己的服务身份运行。

<Aside type="caution">
在项目上限制第一列会改变所有使用该项目的人的情况。如果该项目上的某个 Panel 应用、笔记本或集成在 Snowflake 或 Databricks 仓库上自行组合 SQL，或从 Postgres 系列仓库导出自己的查询结果，请在限制之前将其切换为按名称读取表，否则它将对所有不是架构师的人停止工作。
</Aside>

### 行访问与数据编辑器

数据编辑器直接读取和写入表，因此行访问对其两侧都适用。

在数据编辑器中打开受限表时，只显示您的安全组被授予的行，这与跟随您进入仪表板的筛选器相同，即使受限列不是网格中显示的列之一，它也适用。

保存编辑需要项目上的 **架构师**。保存会整体替换表的行而不是读取它们，并且不会逐行筛选，因此编辑受限表中的数据被视为创作操作而不是读取：没有架构师权限的任何人都会被告知需要该权限。不带受限列的表像以前一样编辑，不限制行的任何项目也是如此。

### 向受限表加载数据

当行访问限制您看到的行时，使用 Python 客户端（`PlaidConnection`）将 DataFrame 写入受限表或将其清除，或通过 REST API 向其保存记录或将其清除，仅针对您自己的行。替换表的数据只替换您能看到的行，清除只清除这些行，追加则添加行；其他每一行保持原样。

包含您访问范围之外的行的加载会在发生任何更改之前被拒绝，并且错误会指明您访问范围之外的每个值及带有该值的行数。省略了受限列的行会按该列为空来检查，因此除非您的访问包含空行，否则会被拒绝。以会更改列类型的方式替换数据也会被拒绝；请让项目架构师进行该更改。

项目架构师、授权覆盖每一行的成员，以及以项目服务身份运行的工作流运行，会写入整个表。没有受限列的表不受影响。

当表中含有您看不到的行时，任何其他会替换或删除整个受限表的操作都会被拒绝，并且不会更改任何内容：向其中导入文件、从另一个项目将表复制到其中、切换或合并其分支、从归档中还原它或作为还原项目保留的快照的一部分还原它、删除它、在删除后将其恢复，以及在重新填充之前清空表的任何其他操作。受限列为空的行会被视为您看不到的行，除非您的访问包含空行。您能看到每一行的表（例如您创建的、仅包含您自己行的表）可以被替换或删除。

人员对任何表所做的这些写入，包括被拒绝的写入，都会记录在安全日志中。工作流运行不会记录在那里。

### 行数和表大小

表的行数和存储大小描述的是整个表，而不是您可能看到的行，因此它们会告诉受限读取者其授权之外存在多少行。在限制行的项目上，读取被筛选的任何人都看不到该项目任何表的行数或大小，在表列表、搜索、表详细信息和快照中，以及通过 AI 助手和通过 MCP 连接的 AI 工具时均是如此。这涵盖项目中的每个表，包括没有受限列的表。项目自身的合计也会对他们隐藏，包括主页上、项目列表和搜索中以及项目详细信息中的总行数和大小。

同样适用于工作流运行历史记录。每次运行和每个步骤所记录的读取和写入的行数同样描述整个表，因此对于相同的读取者，这些数字会留空，在工作流和步骤的运行历史记录中，以及通过 AI 助手和通过 MCP 连接的 AI 工具时均是如此。对他们而言，[Weave](/zh-cn/guides/ai-assistant/weave-findings/) 不会检查步骤的行数或空值与以前运行是否不同，因为这样的发现项本身就会告诉他们整个表的计数发生了变化。

项目架构师像以前一样看到这些数字，不限制行的项目上的所有人也是如此。

### 查看成员能看到什么

要检查特定人员能看到什么，而不是分组被授予什么：打开 **身份 → 成员**，选择该成员，然后打开其 **行访问** 选项卡。其 **有效访问权限** 列针对每个受限项目和列，列出该成员通过其所有分组合并后看到的值，包括来自 SSO 分组属性的授权，以及分组授权包含的空（`NULL`）行。项目架构师显示为 **可查看所有行（架构师）**，因为架构师会读取每一行。这与 PlaidCloud 自身查询所应用的答案相同，因此对支持工作以及在有人报告问题之前确认更改达到了预期效果很有用。

### 更清晰的错误

当行访问阻止某项操作时，例如您在受限项目上自己编写的查询、没有架构师权限的编辑、对自动化、维度或授权来源表的更改，以及上述其他情形，消息会指明什么受到限制以及下一步该怎么做（例如可向哪些架构师求助），而不是给出通用的失败信息。

### 行访问会被审计

限制或取消限制某一列，以及编辑分组的授权，都会在该项目的[项目日志](/zh-cn/get-started/tutorials/collaborate-versions-and-sharing/#阅读项目日志)中写入一条记录，说明谁在何时做出了更改。在项目上打开 **Analyze → Projects → Log** 即可查看。无需启用行访问的任何内容即可获得此跟踪记录，它的记录方式与项目的其他所有受跟踪更改相同。

## 设置默认安全组


为了减少添加新成员所需的时间，请指定一组默认安全组。这为新成员提供了一组基线安全组，无需手动逐个分配人员。添加新安全组时，如果勾选安全组窗口底部写有“默认分配给新用户”的复选框，即可使用该设置。



## 执行安全审计


安全审计功能可用于查看所有成员和分组的分组成员关系。



**执行安全审计：**


1. 打开身份
2. 在导航栏的 **安全** 下选择 **Group audit**

由于 PlaidCloud 中的所有表都可以导出为 CSV 文件格式，因此分组成员关联可以在 PlaidCloud 之外查看，既可用于历史记录目的，也可纯粹用于离线浏览。



**从“Security Group Audit”表单导出：**


1. 打开身份
2. 在导航栏的 **安全** 下选择 **Group audit**
3. 点击表中“用户名”最右侧的小图标
4. 根据您的偏好点击“导出 CSV”或“Export XLXS”
