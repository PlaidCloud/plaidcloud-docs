PlaidCloud 的安全与访问管理简单明了。成员能否获得访问权限，取决于该成员所属的分组。添加或更改成员的安全关联都可以灵活定制。

<Aside>每个工作区可拥有的安全组数量不限，但建议尽量减少数量，以便简化安全管理。</Aside>



## 管理安全组


可以添加、更新或删除安全组。



**管理安全组：**


1. 打开 Identity
2. 选择“Security”选项卡
3. 在下拉菜单中点击“Security Groups”（将显示包含现有分组的表单）
4. 要添加分组，点击“Create Security Group”
5. 要编辑分组的权限，点击最左侧的图标

**管理分组成员：**


1. 打开 Identity
2. 选择“Security”选项卡
3. 在下拉菜单中点击“Security Groups”
4. 点击成员图标
5. 将所需成员从“Unassigned Members”列拖到“Assigned Members”列，反向拖动则移除成员

<Aside>在“Assigned Members”列为空时保存不会产生任何更改，并会提示您这一点。要让所有人都脱离某个分组，请移除该分组的权限或删除该分组，而不要清空其成员。</Aside>

<Aside>如果某个分组通过[行访问](#管理行访问)被授予了行，成员变更会在约一分钟内同步到仪表板：新添加的人可在仪表板中看到该分组的行，被移除的人则不再看到。禁用或删除成员以及删除分组，也以同样方式生效。</Aside>

<Aside type="caution">保存分组的权限矩阵时，您自己无法授予的权限会保持原样，也不会显示在矩阵中。如果需要更改其中某项权限，请联系拥有该权限的人——矩阵只会编辑您能控制的内容。</Aside>

## 管理行访问

行访问根据某一列的值，限制安全组可以看到表中的哪些行。例如，可以用 `region` 列来限制访问，被授予 `East` 和 `Central` 的分组只能看到带有这些值的行。针对某个项目和列的所有操作——选择列、选择值的来源，以及决定哪个分组可以看到什么——都在同一个屏幕中完成，保存后立即生效。

设置和更改行访问需要项目架构师或租户管理员。其他人打开项目的 Security 选项卡时，会被告知行访问仅限架构师使用，下面的入口也不会向他们显示。

### 打开行访问

所有入口打开的都是同一个行访问屏幕：

- **表资源管理器的工具栏**有一个**行访问**按钮，当表已限制行时会带有徽章。它会在表的第一个受限列上打开（如果有的话），您可以切换到该表的任何其他列。
- **列的分面菜单**中有**按此列限制行…**，会在该列上打开行访问。对于已经限制行的列，该项显示为**按此列限制的行 — 编辑…**。
- **项目的 Security 选项卡**列出项目中所有受限的列，以及其适用的表、持有授权的分组和**同步**状态。选择某一列即可编辑，或点击**限制某一列…** 开始新的限制：先选择表，再选择列。已限制行的列以锁形图标标记。
- **Identity → Member**，在成员的**行访问**选项卡上，以及 **Identity → Security → Security Groups**，在分组的行访问摘要上。**打开行访问**（或**编辑**）会打开所选的列；**添加**会在该行所属的项目中限制另一列。

在某一列上打开时，屏幕会停留在该列。通过**限制某一列…** 或**添加**打开时，则可以自行选择列。

### 行访问网格

按某一列限制表：

1. 从上述任一入口打开行访问；如果打开时没有带上列，请选择列——选择器提供的是表中真实存在的列，而非自由输入的文本。
2. 选择**值来源**——**列**（某个表的列的不重复值）、**维度**（维度的节点）或**列表**（您输入的值）。值的类型取决于列的数据类型。
3. 对每个安全组，勾选该分组可以看到的值。网格列出有权访问该项目的分组，以及已在该列上持有授权的任何分组。
4. 将**其他所有人**设置为**可查看所有行**或**不可查看任何行**——这适用于网格中没有任何勾选的所有分组。
5. 点击**保存**。

保存即时生效。PlaidCloud 自身的查询会立即遵循该更改，Superset 仪表板则在约一分钟内遵循——没有单独的应用步骤，且仅当授权中包含其来源已不再拥有的值时，**保存**才会停下来询问（见下文）。屏幕上的同步状态会显示更改传播到了哪一步；请参阅[保持仪表板同步](#保持仪表板同步)。

网格还会为您处理这些细节：

- **大量取值。** 值按顺序排列。当某列的取值多到无法全部显示时，网格会提示“More values than fit here — type to search.”，筛选框会搜索整列，并保留分组已持有的每个值。
- **来源已不再拥有的值。** 分组被授予的值，在其来源失去它之后仍会保留在网格中：表中已没有任何行含有该值、维度中已没有该成员，或列表中已没有该值。其列标题带有警告图标，悬停即可看到原因。**全选**、**反选**和**粘贴**会让这类值保持各分组现有的状态。除非您取消勾选，否则不会从授权中移除任何内容：当某个分组仍持有这类值时点击**保存**，行访问会在**已不在源中的值**中列出相关分组和值并询问。**保留并保存**会按原样保存，**移除并保存**会先将它们从每个分组的授权中移除，关闭该询问则不保存任何内容。如果移除后会使某个分组没有任何勾选，询问会根据**其他所有人**的设置说明该分组随后将看到所有行还是不看到任何行。尚未保存的勾选会随其值一并消失。当某列的取值多到无法全部显示，或其表尚未构建时，行访问无法判断表中缺少哪些值，因此会保留每个已授予的值，且不加任何标记。
- **空值。** 一个**空值 — 对每个拥有授权的组可见**复选框决定该列中没有值的行如何处理。勾选后，在该列上拥有任何授权的每个分组都能看到这些行。
- **尚未构建的表**会显示**请先构建此表（运行创建它的工作流）**，而不是空列表。
- **保存会等待屏幕上的值加载完毕。** 在加载值期间——切换值来源、维度或表之后，或应用模板之后——**保存**处于禁用状态，并显示提示“Save is available once this source's values load.” 如果加载失败，网格会说明情况并请您重新选择来源；在加载成功之前不会保存任何内容。

### 一个列名，对应每个表

限制属于项目上的某个列*名称*，而不是单个表。一旦 `region` 限制了行，项目中每个带有名为 `region` 的列的表都会按它筛选，PlaidCloud 自身的查询和仪表板均是如此。网格中的 **Applies to** 列表显示这些表。该列表是只读的，因为由列名决定，之后新增的同名列表在发布后即受覆盖。

如果项目中没有任何表带有该名称的列，窗口除了显示 **Applies to 0 tables** 之外，还会警告该限制在有表带有此列之前不会筛选任何仪表板。将该列添加到某个表中，或更正列名，警告即会消失。

<Aside type="caution">
**列名必须完全匹配**——包括大小写和空白。`Region` 与 `region` 是不同的名称，`region` 与末尾带空格的 `region ` 也是不同的名称。选择器只提供真实存在的列名，因此这主要在其他地方重命名了列时才会遇到——此时行访问会发出警告并指出它找到的最接近的列，而不是悄悄地什么都不限制。
</Aside>

<Aside type="caution">
**发布限制行的表时，会在同一步骤中设置其仪表板筛选器。** 仪表板通过表已发布的报表视图读取表，因此当您发布或重新发布带有受限列的表时，PlaidCloud 会在发布完成前注册该表的仪表板筛选器。如果无法注册，发布会被拒绝，并回滚该次尝试创建的内容，因此受限的表绝不会在仪表板中未经筛选。在限制行的项目上无法发布*视图*，因为视图的查询可能会重命名或派生出受限的列。请参阅[发布表](/zh-cn/guides/data/publish/)。
</Aside>

### 停止限制

网格上的**停止限制**会在内联确认后移除该限制——“Stop restricting rows by ‘region’? Every group's grant on it is removed and everyone sees its rows.” 随后行访问会确认“Rows in ‘region’ are no longer restricted.” 该列的 Superset 数据集也会一并移除，除非仍有图表在使用它；在这种情况下，行访问会说明数据集保留以及有多少图表在使用。

列在限制行期间无法重命名或删除。架构师会被告知先在行访问中停止对它的限制；其他人则被告知请向项目架构师求助。

### 谁可以更改限制行的项目

项目的工作流、步骤和用户定义函数以项目自己的服务身份运行，该身份可读取每一行。能够更改它们的人，可能让某个步骤把自己未被授权的行复制到自己可读的表中，因此在项目上限制行，同时也限制了谁可以更改项目的行为。一旦项目限制了至少一列：

- **自动化仅限架构师。** 只有项目架构师和租户管理员可以更改工作流、步骤、用户定义函数、计划、工作流和项目变量以及通知邮件模板——出于同样的原因，也只有他们可以导入工作流包、转换 Alteryx 工作流，或向项目中导入、复制或还原内容，或更改其连接环境、默认文档账户或 ERP 过账模式。其他所有人仍可运行项目的工作流：**开始**、**停止**、**恢复**和**运行所选步骤**依然可用。对他们来说，步骤编辑器、工作流的编写控件、UDF 编辑器和计划表单以只读方式打开，并带有一条指明可求助的架构师的横幅：“This project restricts rows, so only its Architects can change workflows, steps, UDFs, schedules, variables and notify templates. You can still run them.”
- **受限列所读取的维度仅限架构师。** 决定谁能看到哪些行的维度——即受限列的值来源——只能由项目架构师或租户管理员以及项目自己的工作流更改。这包括对其节点以及维度本身的添加、移动、重命名、复制、清除、加载和还原。其他人会被告知“This dimension decides who sees which rows of ‘region’, so only a project Architect can change it.” 没有任何限制读取的维度不受影响。
- **授权源表仅限架构师。** 绑定为某列[授权来源](#将授权绑定到源表)的表，其行只能由项目架构师、租户管理员或项目的工作流更改或删除——数据编辑器、导入、连接器加载或 API 均同样如此。
- **复制项目仅限架构师**，且副本会提示“This copy is not row-restricted.”——新项目在您设置限制之前不带任何限制。
- **还原早期版本与其他更改一样。** 还原项目自身的设置或上面列出的维度，需要项目架构师。还原始终作用于该版本所属的对象，因此无法将其指向另一个项目来绕过这一点——请参阅[版本历史](/zh-cn/guides/projects/managing-projects/#版本历史)。
- **在受限表中编辑数据**需要架构师，详见[行访问与数据编辑器](#行访问与数据编辑器)。

在项目上限制第一列之前，行访问会告诉您这会影响哪些人：“Restricting rows here means only Architects can change this project's workflows, steps, UDFs, schedules and notify templates. N members can change them today; they will still be able to run them.”

运行与之前完全一样地继续工作，包括计划运行，因为它们以项目的服务身份运行。运行产生的结果取决于项目架构师为其设计的方式：不含受限列的输出表、导出文件、通知邮件或日志行，不会对读取它们的人进行筛选。

**运行开始时给定的值。** 任何可以运行工作流的人，都可以用自己的变量值来启动它——[应用运行器](/zh-cn/guides/workflows/use-converted-alteryx-apps/#app-runner-前端)使用其表单中的答案来实现这一点，API 和 AI 工具也可以。这些值仅对该次运行有效：它们不会保存在工作流上，其他任何运行、导出或读取者都看不到它们。由于运行以服务身份执行，这些值可以改变该次运行读取和写入的内容，因此请只将运行工作流的权限授予您信任的人。

**不限制行的项目。** 这些规则仅在项目限制了某一列之后才生效。在没有任何限制的项目上，任何可以更改项目自动化的人，都可以编写一个以项目服务身份运行的步骤或用户定义函数，修改项目的访问权限，让自己成为项目的架构师之一。这是设计使然：这样的项目并不承诺行隔离。请把那里的编写权限仅授予您会信任为架构师的人，或者限制某一列。

### 保持仪表板同步

行访问会在网格上以及项目 Security 选项卡的**同步**列中显示更改到达仪表板的进度：

| 状态 | 含义 |
|---|---|
| **等待中** | 更改已保存，正在发往仪表板。通常会在约一分钟内清除。 |
| **正在重试** | 一次发送失败，正在重新尝试。失败原因显示在状态旁边，并带有**重试**可立即再次发送。 |
| **尚未应用** | 项目的限制尚未发送到仪表板。 |
| **已应用** | 上一次将限制发送到仪表板的尝试已成功。 |
| **与仪表板同步** | 行访问将仪表板所强制执行的内容与其将写入的内容进行了比较，二者一致。 |
| **仪表板不一致** | 仪表板强制执行的内容与行访问将写入的内容不一致——某条规则在 Superset 中被更改或删除，或者无法检查某个表已发布的视图。 |
| **错误** | 发送限制失败。原因显示在状态旁边。 |

更改一旦达到**已应用**，网格会将其与仪表板核对，并转为**与仪表板同步**或**仪表板不一致**。**仪表板不一致**和**错误**都提供**重试**，它会再次发送项目的限制。如果完全无法读取状态，网格会提示“Couldn't check sync status.”

由某个表引起的**错误**会指明该表并说明该怎么做——例如，表在发布时没有带上其受限列（“Republish or unpublish it.”），或者带有受限列的表尚未发布，在发布之前仪表板无法对其筛选。状态会一直停留在**错误**并指明未发布的表，直到您发布它，或改为在已发布的表上限制该列。这样的表不会拖累项目的其余部分：其他每个表都会保持同步。

仪表板遵循与 PlaidCloud 自身查询相同的授权：

- **每个带有该列的已发布表都会被筛选**，而不只是您设置限制时所查看的那个表。
- **即使其他所有人都能看到所有行，仅被授予部分值的分组也会被筛选**，在每个存在仪表板数据集的表上均是如此。
- **项目架构师可以看到所有行**，在仪表板中与在表资源管理器及 PlaidCloud 其他位置一样。这适用于项目的架构师分组，以及与个别成员共享的项目的架构师。撤销架构师访问权限会立即在仪表板中生效，无论您是更改成员的角色、将该成员或其分组从项目中移除、更改项目的访问类型、还原项目的早期版本，还是删除该分组。
- **安全组成员变更会自动同步到仪表板。** 在 PlaidCloud 中将某人添加到分组或从分组中移除、禁用或删除成员、删除分组，或添加加入您默认安全组的新成员，都会在约一分钟内更新他们在仪表板中看到的内容，涵盖所有向该分组授予值的项目，无需任何人重新打开行访问。在 PlaidCloud 之外所做的成员变更——直接在 Keycloak 中进行，或由单点登录在登录时将某人放入某个分组——会在约 15 分钟内同步到仪表板，无需保存或重试。

### 维度授权

以**维度**作为值来源时，勾选某个节点即可授予其下的所有内容。授权会随维度变化：在已勾选节点下新增的成员，在维度保存后的下一次同步时授予该分组；从其下移出或被移除的成员则不再被授予——无需任何人重新打开网格。重新打开时，您勾选过的节点仍显示为已勾选。

不是通过节点、而是单独勾选的成员，在从维度中移除后仍保持被授予状态，网格会将其标记为来源已不再拥有的值。

取消勾选已勾选节点下的任何内容，会取消勾选该节点，分组仅保留仍被勾选的成员。再次勾选该成员不会重新勾选该节点——请点击节点自己的复选框。**粘贴**、**全选**和**反选**只勾选成员，不勾选节点。

名称无法用作行访问值的维度成员，在保存时会被拒绝，并指明该成员。如果这样的成员后来才出现，其行不会授予任何人，同步状态会指明该成员：“Dimension ‘…’ member ‘…’ cannot be used as a row access value, so its rows are not granted. Rename it in the dimension.”

### 将授权绑定到源表

您不必手动勾选值，可以让受限列指向一个已经包含答案的源表——每个分组及其可见的值各占一行。先在网格中限制该列，
然后添加一个 [**设置行访问权限**](/zh-cn/reference/workflow-steps/tables/table-set-row-access/)
工作流步骤，指定列、源表以及源表的分组列和值列。该步骤首次运行时会将该列绑定到该表：该列手动设置的授权会被清除，
授权改由该表的行设定。

绑定之后，该列即为**源所有**：行访问网格会将其显示为锁定，并带有指明源表的徽章，在您点击**移除绑定**之前，手动编辑其授权会被拒绝。

该步骤之后的每次运行都会重新读取源表并重新应用授权——请将其安排在加载或刷新该表的工作流之后，源数据中新增、移除或重新分配的分组会在下一次运行时同步到行访问，无需任何人手动编辑网格。

由于源表决定谁能看到什么，只有项目架构师、租户管理员或项目自己的工作流可以更改其行或删除它。其他人会被告知“This table
supplies the row access grants for ‘region’, so only a project Architect can change its rows or
delete it.”

### 限制模板

如果您构建了想要复用的限制形态——同样的值来源、值类型和空值设置——请保存一次，然后在需要的地方应用，而不必逐列重新构建。

- 在打开的行访问屏幕中，**另存为模板…** 会将当前列的形态保存为具名的租户级模板。它只保存形态——不带任何授权。
- 在另一个项目的列上**应用模板**，会以模板的形态作为该列的起点，每个分组的授权均为空，等待您填写。

任何项目架构师都可以保存和应用模板。重命名（**重命名…**）和删除（**删除**）模板需要租户管理员，因为模板由整个租户共享。删除模板不会影响已应用该模板的列，它们仍保持原有的限制。

<Aside type="note">
模板是副本，而不是链接。之后编辑模板，不会改变任何已应用过它的列——如需让某列跟上模板的后续修订，请重新应用该模板。
</Aside>

### 来自 SSO 分组属性的授权

列也可以从您的身份提供商而不是 PlaidCloud 获取授权。项目架构师在行访问中启用**接受来自 SSO 分组属性的行访问授权**，即可让某一列选择采用这种方式。

启用后，安全组的 Keycloak 属性 `row_access.<column>` 会设置该分组通过该列可以看到的值——在 Keycloak 中为分组设置该属性，PlaidCloud 会自动为任何已有该项目访问权限的分组采用。行访问本身无需进一步配置，授权在 PlaidCloud 自身的查询和 Superset 仪表板中都保持同步。

<Aside type="caution">
这只会向已经可以访问项目的分组授予值。向没有项目访问权限的分组添加 `row_access.region`，在该分组同时获得项目访问权限之前不会授予它任何内容。
</Aside>

### 保存前预览

行访问会在您提交之前显示更改的含义：

- **预览身份**页脚会显示某个分组可以看到表总行数中的多少行，并附带行的样本——在网格中选择任何分组即可预览。预览会在您保存后刷新。
- 保存之前，行访问会就值得再看一眼的情况发出警告：没有勾选任何内容的分组，以及按您的**其他所有人**设置这意味着它可以看到所有行还是不能看到任何行；有项目访问权限但未被任何分组的授权覆盖的成员；或者该列中值为空（`NULL`）而没有任何分组被授予的行。

### 受限成员能看到什么

受限成员只要按名称读取表，得到的就只有自己的行——表资源管理器的网格、列分面和下载、表下载对话框、以查看者身份读取的应用和工具，以及仪表板。当您查看的网格已按您的授权筛选时，表资源管理器会在工具栏中显示**行数受您的访问权限限制**；开始一次将被筛选的下载时，会提示“Rows limited by your access.”读取所有行的架构师则两种提示都不会看到。

### 行访问与您自己编写的查询

行访问通过筛选其所定义的表，来限制分组可以看到哪些行。由某人自己编写的查询没有可以附加该筛选的单一表——查询可以联接、合并或嵌套任意多个表——因此在限制行的项目上，PlaidCloud 会拒绝运行由调用方提供的查询，而不是返回未经审查的行。

这适用于通过您自己的 SQL 读取、将您自己的 SQL 的结果导出到文件或其他数据库，以及在扇出步骤的“Test row 1”预览中输入行条件。这**不**适用于按名称读取表，那是应用和工具读取数据的常规方式——它们会应用授权并返回查看者有权看到的行。只对单个表进行普通查询的列分面也是按名称读取的，因此它返回的是成员自己的值，而不会被拒绝。

被拒绝的人会被告知是哪个项目，并被指向按名称读取的方式。项目架构师可以按原样运行该查询，并以任何格式导出其结果，因为架构师本来就可以授予自己每个受限列的每个值。

导入电子表格本身并不算是您自己编写的查询——普通的文件导入不会读取任何受限数据，它只是用您上传的文件创建项目自己的新表，因此不受行访问影响。例外是数据投影由调用方提供的导入：逐列表达式或动态 Excel 映射。在交互式导入屏幕上，这些情况与上述自由格式 SQL 的情形一样会被拒绝，并需要项目架构师，因为由调用方提供的投影可能读取另一个表。从工作流运行的导入在两种情况下都不受影响，因为它以项目自己的服务身份运行。

<Aside type="caution">
在项目上限制第一列会改变所有使用该项目的人的情况。如果该项目上的 Panel 应用、笔记本或集成通过自行组合 SQL 来读取数据，请在限制之前将其改为按名称读取表——否则对每个非架构师的人来说，它都将停止工作。
</Aside>

### 行访问与数据编辑器

数据编辑器直接读取和写入表，因此行访问在两个方向上都适用。

在数据编辑器中打开受限表时，只显示您的安全组被授予的行——与仪表板中使用的筛选相同，即使受限列不是网格中显示的列之一，该筛选也同样适用。

保存编辑需要项目上的**架构师**权限。保存会整体替换表的行，而不是读取这些行，也不会逐行筛选，因此在受限表上编辑数据被视为编写操作而非读取：没有架构师权限的人会被告知需要该权限。不带受限列的表照常编辑，不限制行的项目也一样。

### 行数和表大小

表的行数和存储大小描述的是整个表，而不是您可以看到的行，因此会向受限读取者透露授权之外还存在多少行。在限制行的项目上，读取被筛选的任何人都看不到该项目任何表的行数或大小——无论是在表列表、搜索、表详情和快照中，还是通过 AI 助手和通过 MCP 连接的 AI 工具。这涵盖项目中的每个表，包括没有受限列的表。项目自身的总计也会对他们隐藏——首页、项目列表和搜索以及项目详情中的总行数和大小。

工作流运行历史同样如此。每次运行和每个步骤所记录的读取和写入行数也描述的是整个表，因此对于相同的读取者，这些数字会留空——在工作流和步骤的运行历史中，以及通过 AI 助手和通过 MCP 连接的 AI 工具。对于他们，[Weave](/zh-cn/guides/ai-assistant/weave-findings/) 不会检查步骤的行数或空值是否与以往运行不同，因为这样的发现项本身就会告诉他们整个表的行数发生了变化。

项目架构师照常看到这些数字，不限制行的项目上的所有人也是如此。

### 查看成员能看到什么

要检查某个具体的人能看到什么，而不是某个分组被授予了什么：打开 **Identity → Member**，选择该成员，然后打开其**行访问**选项卡。其**有效访问权限**列针对每个受限的项目和列，列出该成员通过其所有分组合计能看到的值——包括来自 SSO 分组属性的授权，以及分组授权包含的空（`NULL`）行。项目架构师显示为**可查看所有行（架构师）**，因为架构师可读取每一行。这与 PlaidCloud 自身查询所采用的答案相同，因此对支持工作很有用，也可用于在有人报告问题之前确认更改是否达到了您的预期。

### 更清晰的错误

当行访问阻止某项操作时——在受限项目上由您自己编写的查询、没有架构师权限的编辑、对自动化、维度或授权源表的更改，以及上文所述的其他情形——消息会指明哪些内容受限以及下一步该怎么做，例如应向哪些架构师求助，而不是笼统的失败提示。

### 行访问会被审计

限制或取消限制某一列，以及编辑分组的授权，都会在该项目的[项目日志](/zh-cn/get-started/tutorials/collaborate-versions-and-sharing/#阅读项目日志)中写入一条记录——谁做了更改以及何时。在项目上打开 **Analyze → Projects → Log** 即可查看。无需启用行访问的任何选项即可获得这一记录；它的记录方式与项目的其他所有受追踪更改相同。

## 设置默认安全组


为减少添加新成员所需的时间，请指定一组默认安全组。这样无需手动为每个人分配，即可为新成员提供一组基准安全组。添加新安全组时，如果勾选了 Security Group 窗口底部写着“Assign to New Users by Default”的复选框，即可使用此设置。



## 执行安全审计


安全审计功能可以查看所有成员和分组的分组成员关系。



**执行安全审计：**


1. 打开 Identity
2. 选择“Security”选项卡
3. 在下拉菜单中点击“Security Group Audit”

由于 PlaidCloud 中的所有表都可以导出为 CSV 文件格式，因此分组与成员的关联可以在 PlaidCloud 之外查阅，既可用于历史存档，也可以只是离线随意查看。



**从“Security Group Audit”表单导出：**


1. 打开 Identity
2. 选择“Security”选项卡
3. 在下拉菜单中点击“Security Group Audit”
4. 点击表中“Username”最右侧的小图标
5. 根据您的偏好点击“Export CSV”或“Export XLXS”

## 查看可用的权限设置


工作区中使用的每个应用程序都有各自可用的权限。安全组的权限基于这些应用程序权限。


每个应用程序的完整可用权限列表可在 Security Bin 中查看。



**访问 Security Bin：**


1. 打开 Identity
2. 选择“Security”
3. 在下拉菜单中点击“Security Bins”

要查看每个应用程序的详细安全设置，请选择最左侧的标签图标。



这些可用的安全设置信息仅供参考。有关管理权限的详细信息，请参阅上文的“管理安全组”部分。
