**Cost to Serve** 模板展示服务每个客户的成本，以及扣除成本后剩余的利润。它构建在 [Common Finance Model](/zh-cn/guides/projects/data-foundation/) 之上，因此适用于为项目提供数据的任何 ERP，并包含 **Enterprise Profitability** 构建的全部内容。

## 工作原理

1. 运营费用按实体、期间及其所属的部门汇集成池。
2. 每个池采用您的**活动映射**为其部门指定的活动和驱动因素。
3. 每个客户的驱动因素来自项目的已开票销售明细行。
4. 每个池在实体和期间范围内，按其驱动因素分摊给客户。

如果某个池的驱动因素在该实体和期间内没有正值，该池将不归属任何客户直接转入，因此分摊结果始终与池的总额相等。

## 活动映射

活动映射是表 `cts_activity_map`。它由您自行编辑，模型从不向其写入。每一行为一个部门指定一个**活动**和一个**驱动因素**。

| 列 | 内容 |
|---|---|
| `department` | 部门代码，或用 `*` 表示所有未列出的部门。 |
| `activity` | 活动名称，例如仓储。 |
| `driver` | 按什么来分摊该部门的成本（见下文）。 |

| 驱动因素 | 分摊成本的依据 |
|---|---|
| `orders` | 每个客户的订单数（不同的发票）。 |
| `lines` | 发票行。 |
| `quantity` | 处理的数量。退货也需要处理，因此按其数量计入。 |
| `revenue` | 净收入，已抵减贷项凭证。 |

示例数据附带 `SALES`、`SERVICE` 和 `OPS` 部门，以及一个涵盖其余部门的 `*` 行。请将它们改为您自己的部门和活动，然后点击**基础数据**选项卡上的 **Apply changes**。

## 您将获得什么

| 输出 | 内容 |
|---|---|
| `cts_by_customer` | 按实体、期间、客户和活动：服务成本，以及客户的收入、销货成本、毛利、扣除服务成本后的净利润和订单数。 |
| `cts_per_order` | 每个订单的服务成本。 |
| `cts_tie_out` | 按实体和期间，对比总账的运营费用与分摊到客户的成本。若没有遗漏或重复计算，差异为 0。 |

供助手和仪表板使用的指标：**Cost to Serve**、**Net margin after CTS**、**Orders** 和 **CTS per order**，可按实体、客户或活动查看。活动为 `Unmapped` 或没有客户的成本，是没有任何活动或驱动因素能够归属的运营费用。

## 启动项目

<Steps>

1. 在 Analyze 中，打开**项目**并点击**新建项目**。

2. 在**起始来源**下，选择 **Cost to Serve (template)**。勾选**从示例数据开始**，可先查看一个完整的示例。

3. 连接您的 ERP 并运行**加载**。请参阅[Data Foundation 入门](/zh-cn/guides/projects/data-foundation-getting-started/)。

4. 针对您的部门编辑活动映射，然后点击 **Apply changes**。

</Steps>

使用 **操作 > Save as my template...** 可将活动映射与项目一起保存。请参阅[另存为我的模板](/zh-cn/guides/projects/data-foundation/#另存为我的模板)。
