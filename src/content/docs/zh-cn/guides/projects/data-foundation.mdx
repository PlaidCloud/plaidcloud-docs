**Data Foundation** 是 PlaidCloud 项目的财务数据基础。它的 **Common Finance Model** 将来自多个 ERP 系统（以及每个系统的多个实例）的 ERP 数据汇集到一个模型中：一套会计科目表、一组实体和一种报告货币。基于该模型构建的报表、指标和 AI 助手读取的都是同一组数字，无论这些数字来自哪个 ERP。

ERP 通过其 PlaidCloud 连接接入，因此总账、试算平衡表、主数据和预算直接来自源头，无需导出。文件用于补充系统中没有的数据，例如汇率、分摊动因或保存在 ERP 之外的预算，并且可以替换其所覆盖的 ERP 行。**加载**会将每个源整合到模型中，折算为报告货币，并检查合计是否一致，这一切都在项目的**基础数据**选项卡中完成。当多个源对不同事物使用相同代码时，由您说明它们是否表示同一含义；管理合并则会生成已抵销集团内部往来的集团损益表。模板（例如 **Enterprise Profitability**）在此基础上构建各自的报表和模型。

## 连接 ERP

ERP 通过其 PlaidCloud 连接接入 Data Foundation。Data Foundation 直接从中读取总账、试算平衡表、主数据、汇率和预算，并且只读取。您可以在选项卡上选择现有连接或创建一个连接。每个系统都有一个面向授予访问权限的管理员的页面，列在[哪些系统可以为模型提供数据](/zh-cn/guides/projects/data-foundation-getting-started/#哪些系统可以为模型提供数据)中；[Data Foundation 覆盖矩阵](/zh-cn/reference/data-foundation-coverage-matrix/)列出了各系统直接提供的数据集。

<Steps>

1. 在 Analyze 中打开**项目**，然后点击**新建项目**。输入名称，在**起始来源**下选择一个模板（例如**企业盈利能力(模板)**），而不是**空白项目**。点击**创建**。

   项目会在其**基础数据**选项卡中打开。在您共享之前，项目仅您可见，且您是唯一的架构师。

2. 在**基础数据**选项卡中，打开**源**，然后在 **Connect a system** 中，从磁贴中选择您的系统类型。接着为其选择现有连接，或选择**创建新连接**。每个现有连接都会列出已使用它的工作流，或显示**暂无工作流使用**；已作为源的连接会标为 **already a source**，不能再次选择。

3. 对于新连接，输入**连接名称**，选择**环境**，并填写 ERP 连接所需的凭据。

   还没有凭据？表单会显示一份现成的访问请求，供您发给 ERP 管理员。点击**复制请求**或**通过电子邮件发送请求**，发送后输入对方返回的值。

4. 点击**测试连接**。PlaidCloud 会登录并尝试读取每个数据集，然后将每个数据集列为**可读取**、**缺少权限**或**错误**。如有缺失，它会列出需要请 ERP 管理员添加的权限。

5. 设置**历史月数**：向前加载多少个月，范围为 1 到 120。默认为 24。

6. 对于现有连接，勾选要加载的实体，或全部不勾选以加载所有实体。非活动实体和抵销实体在您选择显示之前保持隐藏。然后点击**连接**。

7. 对于新连接，点击**连接**以创建它。然后勾选要加载的实体，再次点击**连接**以保存。在此之前，将加载所有实体。

8. 若要接入另一个 ERP 系统或另一个实例，请打开 **Connect another system** 并重复上述步骤。连接操作始终会新增一个源，并保持现有源不变，因此多个 ERP 系统和实例可以共同为同一个合并模型提供数据。

</Steps>

连接后，卡片会显示项目加载所用的连接、环境、实体和历史月数。

每次加载只读取发生变化的内容：未结账期间和最近一个已结账期间会被重新读取，已加载的已结账期间则保持不变。提高**历史月数**只会读取新增的月份。汇率、实体对照表或报告货币发生变化时，会重新读取受其影响的月份。

## 源

项目加载所用的每个 ERP 系统和实例都是一个源。**基础数据**选项卡**源**页面上的 **Load order** 列表按顺序为每个源显示一行，包含其名称和系统、**公司**、**Last loaded**、**行**和**状态**。**公司**显示**全部**或已选择的数量。尚未加载的源显示 **Not loaded yet**。您确认的文件也是源。

点击源上的**编辑**，可更改其使用方式：

| 设置 | 作用 |
|---|---|
| **名称** | 报表、映射问题和消息中用于该源的标签。 |
| **Place in the order** | 源的排序位置。当两个源覆盖同一公司的同一个月时，排序靠前的源优先。 |
| **Reporting books, separated by commas** | 要读取的会计账簿，适用于保存多个账簿的系统。**All reporting books** 会读取所有账簿。 |
| **公司** | 对于系统源，指该源加载其哪些公司（子公司）。该列表在您首次打开面板时从系统读取，并显示该源当前加载的公司。勾选要加载的公司，或不勾选任何公司以加载全部公司。如果系统不列出其公司，请输入公司名称，以逗号分隔。 |
| **公司**、**From (2026-01)** 和 **To (2026-12)** | 该源为每家公司提供的月份。留空表示不设限制。月份写作“年-月”，例如 `2026-03`。 |

点击**保存**以保留更改。添加公司或不勾选任何公司时会立即保存。去掉某个公司时，会先要求您确认 **Load fewer companies?**，因为保存会立即清除从该源加载的所有内容，下一次**加载**会重新拉取已勾选的公司。如果该源的连接现在读取的账户与设置该源时的账户不同，保存会被拒绝并显示相应消息，因此更改绝不会替换另一个源。请改为将该账户作为独立的源重新连接。若要移除某个源，请点击 **Remove this source** 并确认**移除**。从该源加载的所有内容都会被删除，您以后可以重新连接它。

更改源不会再次读取 ERP。在您点击 **Apply changes** 之前，**上次加载**卡片会显示 **Changes not applied yet**；该操作会基于已拉取的数据运行一次加载：按新的排序、映射、名称和文件重新整合各源，并重新构建模型。如果还想从 ERP 获取最新数据，请点击**加载**。

## 添加文件以补充 ERP 之外的数据

文件用于补充 ERP 连接中没有的数据，例如汇率、分摊动因、[实体对照表](#实体对照表)或保存在 ERP 之外的预算。每个文件属于[Common Finance Model 表](#common-finance-model-表)下列出的某个数据集。

<Steps>

1. 在**文件**下，选择用于存放该文件的**文档账户**。

2. 将 CSV 或 Excel 文件拖放到**将 CSV 或 Excel 文件拖放到此处**，或点击**选择文件**。文件会上传到文档账户的 `/foundation/` 文件夹。

   对于文档账户中已有的文件，请输入其**文件路径**，例如 `/foundation/budget.csv`，然后点击**添加文件**。

   若要每月读取一个新文件，请添加名称匹配的文件夹中的所有文件：输入文件夹，并指定**文件名**包含、开头为、结尾为、完全匹配或按模式匹配的内容，然后点击 **Add files**。其中子文件夹内的文件不会被读取。

3. PlaidCloud 会读取该文件并提出映射建议：

   - **Detected delimiter, decimal separator and dates.** 分隔符（逗号、分号、制表符或竖线）、小数分隔符和日期格式会被自动检测。
   - **数据集**：文件所属的 Common Finance Model 表，根据文件名和列标题匹配。匹配不明确时，请从列表中选择。
   - **小数分隔符**：**句点(1,234.56)** 或**逗号(1.234,56)**。
   - **日期格式**：文件包含日期时显示。如果检测到的格式有误，请更改：`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY` 或 `MM/DD/YYYY`。
   - 一个包含**文件中的列**、**类型**、**示例**和**去向**的网格。更改**去向**可将某列发送到其他字段，或设为**不加载**。

4. 回答文件引发的问题，例如 **Which company is this file for?**、**Which currency are the amounts in?**、**Are these amounts year-to-date or for the month?**、**Are the amounts shown in thousands or millions?** 或 **Are revenues shown as negative numbers?** 只有文件本身没有说明时，才会询问相应问题。

5. 检查每一列的去向，然后点击**确认映射**。处理期间，按钮下方的说明会解释为何在等待。在仍含示例数据的项目中，您确认的第一个文件也会移除示例数据，这可能需要几分钟。

</Steps>

文件适用时会出现以下选项：

| 选项 | 用途 |
|---|---|
| **Which source do these rows apply to?** | 将代码映射文件限定到某一个源。**Every source** 会将其应用于所有源。 |
| **Where does this file come from?** | 说明文件包含的是 **This project's own codes**，还是来自 **Another system**（需要您命名，例如 `SAP Germany export`）。来自其他系统的文件会像 ERP 源一样检查共用代码。 |
| **Split … into … parts at each …**（在**高级**下） | 拆分包含多个值的单列（例如 `100-200-300`），并将每一部分发送到各自的字段。 |
| **Which currency do you report in?** | 在项目尚未设置报告货币时设置报告货币。写作三个字母，例如 `USD`。 |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 加载合并系统的结果，以便[对账](#与合并系统对账)集团损益表。 |

若要将文件从项目中移除，请点击**文件**下该文件旁的**移除**，或其映射上的 **Remove this file**，然后确认。下次点击 **Apply changes** 时，其数字将从报表中消失。

当 PlaidCloud 无法自行确定数据集、小数分隔符或日期顺序时（例如文件中的日期既可能是日/月，也可能是月/日），它会在您确认之前请您选择。为同一数据集添加第二个文件会替换第一个文件。如果后续文件的列与数据集不匹配，加载会指出该文件和这些列，并提示您更正文件或其列名，或将步骤的 **Schema Mismatch** 设为 `union`。

接受的文件有 CSV、TSV 和 TXT 文本文件、Excel `.xlsx` 文件（读取第一个工作表）以及 Parquet 文件。

<Aside type="note">
缺失或为空的文件永远不会中止加载。添加这样的文件时会提示暂无可映射的内容，加载会在完成时给出指明路径的警告，并使该数据集保持为空。文件存在后再重新添加即可。
</Aside>

## 加载您的数据

点击**加载**卡片或**上次加载**卡片上的**加载**。加载会读取已连接的 ERP 和您已确认的文件，将它们整合到 Common Finance Model 中，折算为报告货币，运行就绪状态检查，并重新构建模板的模型。

- 一个项目同一时间只能运行一次加载。第二次**加载**或 **Apply changes** 会提示已有加载正在运行，并且加载运行期间无法更改源。
- 如果其他工作流使用同一个 ERP 连接，首次加载会列出这些工作流并请您确认，因为加载会读取 ERP，可能拖慢这些工作流。点击**仍然加载**即可继续。
- PlaidCloud 升级后，架构师的**加载**还会更新项目生成的工作流，并创建它们所需的工作表。在此之前，状态页会列出一个琥珀色事项“The workflows were generated by an earlier release. An Architect's Load updates them.”，而管理者的**加载**会警告只有架构师才能更新它们。
- 应用更新时会保留您对生成步骤所做的修改。如果您更改了某个步骤而更新也更改了它，将保留您的修改，状态页会按步骤名称注明冲突。您编辑过、而更新不再生成的步骤会被保留但处于关闭状态；若仍需要它，请删除或重新开启。被更新替换的步骤会被点名，原有步骤仍保留在其步骤版本中。
- 如果更新中途停止或仍在运行，状态页会指出，且在它完成之前，其步骤可能会乱序运行。请以架构师身份再次点击**加载**以完成更新。如果再次停止，请联系支持人员。
- 失败的加载显示为红色，绝不会被先前的结果掩盖。如果合并失败，状态会指出它停在哪个步骤，而不是显示旧的集团结果。来自较早加载的行会显示**来自较早的加载。请重新加载。**，直到加载成功。
- 如果某个实体和期间读取失败，其余部分仍会加载。再次运行**加载**即可只获取失败的部分。

### 被暂扣的行

当源重叠时，加载只保留每个数字的一份副本，并暂扣其余副本，以免重复计算。被暂扣的行会连同其源、实体和原因一起记录，加载完成时会给出写明数量的警告，例如 `120 rows of NetSuite EU also provided by a source ranked ahead`。原因如下：

| 原因 | 含义 |
|---|---|
| 在另一个会计账簿中 | 该行属于源未设置读取的某个报告账簿。 |
| 超出源提供的期间 | 该行落在为公司设置的 **From** 和 **To** 月份之外。 |
| 排序靠前的源也提供了该行 | 排序更靠前的源覆盖了同一公司和月份。 |
| 该源的较早文件中也有 | 同一源的较早文件已覆盖该月份。 |
| 已被文件替换 | 文件替换了该实体和月份的 ERP 行。 |
| 带有另一个源也使用的代码 | 该代码需要您回答。请参阅[跨源映射代码](#跨源映射代码)。 |
| 带有映射到两个代码的代码 | 代码映射为该代码给出了两个答案。 |

统计账户会转入分摊动因而不是总账，并显示为已转移，而不是问题。

### ERP 数据与文件共用

文件只替换它所覆盖的内容，ERP 的其他行保持不变。

- **主数据文件**（科目、部门、客户、产品和分部值）会替换代码相同的 ERP 行。
- **交易文件**会替换同一实体和月份的 ERP 行。总账和试算平衡表文件还按账簿匹配，预算文件按方案匹配，统计动因文件按方案和动因匹配。

如果某个文件之后不再覆盖某个月份，ERP 在该月份的数据会在下次加载时恢复。

## 实体对照表

每个源都用自己的代码命名实体。**实体对照表**将这些代码映射到实体主数据中的实体，使各源的明细行落在同一个实体上。

若要使用，请添加 CSV 或 Excel 文件并选择**实体对照表**数据集：

| 列 | 内容 |
|---|---|
| `source_entity` | 源所带的代码，例如公司代码。 |
| `entity` | 它所属的实体，按实体主数据中的名称。 |

- 不在对照表中的代码按原样使用。
- 多个代码可以映射到同一个实体。它们的明细行会被合并，只有当它们全部已结账时，该月才算已结账。
- 对照表中的代码适用于所有源，因此各源的实体代码在源之间必须唯一。
- **实体**文件中的一行会替换 ERP 中实体代码相同的实体。

**未映射的实体**检查会标记所有实体既不在实体主数据中、也未通过对照表映射到某个实体的明细行。在加载实体主数据之前，它显示为 **– 不适用**。

## 跨源映射代码

两个源可能用相同的代码表示不同的事物，也可能用不同的代码表示同一事物。当某个代码出现在多个源中时，Data Foundation 会暂扣其行，直到您说明它在各处是否表示同一含义，从而使每笔金额只计算一次。**Codes waiting for your answer** 检查会列出这些代码，先列前 10 个，然后是“以及另外 K 项”，而**基础数据**选项卡上的 **What to do next** 卡片有一个**审核**按钮。

**审核**会打开 **Codes waiting for your answer**。它按代码的类型对其分组：**账户类型**、**公司**、**账户**、**部门**、**利润中心**、**客户**、**产品**以及每个额外类别。对每个代码，它会显示各源对它的称呼和一条建议：

- 当各源对该代码给出相同名称时，显示 **Looks like the same thing**。
- 当名称不同时，显示 **Looks like different things**。
- 当没有任何依据时，显示 **We can't tell. Please answer.**

可以逐个回答代码，选择 **Yes, the same** 或 **No, different**；也可以用 **Accept all**（采纳所有建议）、**All the same** 或 **All different** 一次回答整个分组。对于科目，还可以一次回答科目表中的整个父级分组。当某个源不带科目类型时，可为一组科目选择 **Use this type**：**收入**、**Cost of goods sold**、**Operating expenses**、**Non-operating income and expenses**、**Assets**、**Liabilities** 或 **Equity**。

映射按源和维度保存，因此对某个源的部门所做的回答绝不会改变另一个源的科目。回答会随时保存，并显示“**Saved. Press Apply changes to use your answers.**”点击 **Apply changes** 即可使用。

您也可以通过文件提供映射。添加一个 **Code map** 数据集的文件，并选择 **Which source do these rows apply to?** 将其限定到某一个源。

## 选择从何时起以哪个源为准

当两个源提供相同的月份时，**Which source covers which months** 检查会请您做出选择。点击 **What to do next** 卡片中的 **Choose which source counts from when** 以打开 **Which source counts from when**，它按公司列出每处重叠。选择要采用的源，在 **That month is** 中输入从哪个月起采用（例如 `2026-04`），然后点击 **Apply changes**。另一个源保留较早的月份。

当两个源为同一种货币给出不同汇率时，同一个对话框也会发出警告；此时使用排序靠前的源的汇率。

## 货币折算

每次加载都会将总账、试算平衡表、销售、库存和预算金额从本位币折算为一种报告货币。报表和模型读取折算后的金额，因此来自任何系统、使用不同货币的实体都能正确合计。

### 报告货币

若要选择报告货币，请将项目变量 `reporting_currency` 设置为货币代码，例如 `USD`。请参阅[管理项目变量](/zh-cn/guides/projects/managing-projects/#管理项目变量)。模板创建时它为空。在它为空时，每次加载会采用下列第一个恰好指向一种货币的来源：

1. 实体的集团货币。
2. 顶层实体（没有父级的实体）的本位币。
3. 文件的本位币。

如果没有任何一项恰好指向一种货币，**货币折算**会显示问题，直到您设置 `reporting_currency`。

已经是报告货币的金额保持不变，因此数据全部为同一种货币的项目不需要汇率。

销售、库存和预算文件也可以带货币。映射名为 `Currency` 或 `Local Currency` 的列，系统会自动识别，并将文件中的本位币金额折算为报告货币。文件中已有的集团或报告金额按原样保留。产品标准成本不做折算。

### 汇率

汇率将一个单位的某种货币折算为某个月的报告货币：折算后的金额等于本位币金额乘以汇率。

- **来自 ERP**：每次加载都会读取 ERP 中保存的汇率。
- **来自文件**：添加 CSV 或 Excel 文件并选择**汇率**数据集。文件中的汇率会替换 ERP 中同一货币对和月份的汇率。如果要使用 ERP 未发布汇率的货币作为报告货币，或为预算月份添加计划汇率，请使用文件。

| 列 | 内容 |
|---|---|
| `from_currency` | 折算的来源货币，例如 `EUR`。 |
| `to_currency` | 报告货币，例如 `USD`。 |
| `period` | 月份，格式为 `YYYY-MM`。 |
| `average_rate` | 当月平均汇率。 |
| `closing_rate` | 月末汇率。 |
| `historical_rate` | 历史汇率，用于权益以及设置为按历史汇率折算的科目。 |

当某种货币没有折算为报告货币的汇率时，会将其反方向的汇率（即从报告货币折算为该货币的汇率）取倒数，并保留 12 位小数。如果也没有这样的汇率，则将该货币折算为另一种货币的汇率，乘以那种货币折算为报告货币的汇率。

### 适用哪种汇率

每一行都按其自身的货币折算，因此与其实体货币不同的明细行会按它所用的货币折算。适用第一条符合该行的规则：

| 行 | 汇率 |
|---|---|
| 统计账户和非过账账户 | 不折算。 |
| 已经是报告货币 | 不折算。 |
| 带汇率类型的科目 | 该汇率：平均、期末或历史。没有历史汇率时，历史汇率回退为期末汇率。来自 ERP 时，汇率类型即科目自身的汇率类型。在会计科目表文件中，将汇率类型列映射到 `fx_rate_type`，取值为 `average`、`closing` 或 `historical`。 |
| 销售明细行 | 该期间的平均汇率。 |
| 库存余额 | 该期间的期末汇率。 |
| 预算行 | 与总账一样按科目：损益科目用平均汇率，资产负债表科目用期末汇率。 |
| 损益科目 | 该期间的平均汇率。 |
| 权益科目 | 历史汇率；没有历史汇率时用期末汇率。 |
| 其他任何资产负债表科目 | 该期间的期末汇率。 |

折算后的金额不做四舍五入，因此合计不会产生偏差。

<Aside type="note">
试算平衡表保存的是各期间的发生额，因此资产负债表金额是每个月的发生额按该月期末汇率折算的结果。它们并不是按期末汇率重新折算的资产负债表，也没有累计折算调整或集团内部往来抵销。请将折算后的金额用于损益表。
</Aside>

## 层次结构

每次加载都会根据每个源的主数据重新构建维度。起初有七个维度，另外最多可有十个额外类别：

| 维度 | 构建依据 |
|---|---|
| **实体** | 实体及其父级 |
| **科目** | 会计科目表和父级科目 |
| **部门** | 部门及其父级 |
| **客户** | 客户及其父级客户 |
| **产品** | 产品及其父级产品 |
| **Segment 1** | `segment_1` 的分部值 |
| **Segment 2** | `segment_2` 的分部值 |
| **Segment 3** 至 **Segment 10** | `segment_3` 至 `segment_10` 的分部值（当您的源带有这些值时） |

- 没有父级的记录，或将自己指定为父级的记录，会作为顶层成员加载。
- 由于每次加载都会重新构建层次结构，请在 ERP 或您的文件中更改父级，而不要在维度中更改。
- 一个层次结构中的问题只影响该维度。加载和模板的模型仍会完成。
- 您可以将每个额外类别重命名为其所含内容，例如**类别**或**区域**。在 **Rename extra categories** 下，输入报表使用的名称并点击 **Save names**。名称可使用字母、数字、空格、点、短横线和下划线，最长 60 个字符。
- 每个源会说明其自身的每个额外类别归入您的哪个类别名称之下。点击源上的**编辑**，为每个类别选择名称，或选择 **Leave out**，然后点击**保存**。这样，用不同名称称呼同一类别的源（例如 `Class` 和 `Business area`）会共用同一个位置。

若要通过文件提供分部层次结构，请选择**分部值**数据集：

| 列 | 内容 |
|---|---|
| `segment` | 该值所属的分部：`segment_1` 至 `segment_10`。 |
| `segment_value` | 该值，与总账、销售和预算明细行所带的值一致。 |
| `segment_value_name` | 其名称。 |
| `parent_segment_value` | 同一分部内的父级值。 |

## 就绪状态检查

每次加载之后，**就绪状态**网格会列出每个实体和期间的每项检查，状态为下列之一：

| 状态 | 含义 |
|---|---|
| **● 就绪** | 检查已通过。 |
| **▲ 需要关注** | 值得查看，但数字可以使用。 |
| **■ 问题** | 在依赖结果之前请先修复。 |
| **– 不适用** | 此项检查暂无数据。 |

检查项如下：

| 检查 | 确认内容 |
|---|---|
| **数据已加载** | 每个会计期间都有总账明细行，且每次 ERP 读取都已成功。没有明细行的已结账期间是问题；没有明细行的未结账期间需要关注。 |
| **试算平衡表与总账一致** | 每个实体、期间和科目的试算平衡表都等于总账。当试算平衡表和总账都为某个科目带有部门时，还会逐个部门核对。 |
| **销售与总账一致** | 每个期间的销售明细行都等于总账的收入和 COGS 科目。 |
| **未知产品/客户** | 每条销售明细行所指的产品和客户都存在于产品主数据和客户主数据中。 |
| **科目表中缺失的科目** | 每条总账明细行所指的科目都在会计科目表中。带有未知科目的明细行不会计入损益表。有过账但没有科目类型的科目也是问题；如果某个源的科目表为收入科目设置了类型，却没有销售成本科目，则需要关注。 |
| **货币折算** | 每个总账、试算平衡表、销售、库存和预算行都有报告货币金额。没有汇率的损益行或销售行是问题，因为损益表读取的是折算后的金额。没有汇率的资产负债表、库存或预算行需要关注。尚无汇率的预算月份显示为琥珀色，因此请为预算月份加载计划汇率。请参阅[货币折算](#货币折算)。 |
| **未映射的实体** | 每条总账、试算平衡表和销售明细行所指的实体，都在实体主数据中，或通过实体对照表映射到其中。在加载实体主数据之前不适用。请参阅[实体对照表](#实体对照表)。 |

包含多个源的加载会增加以下检查：

| 检查 | 确认内容 |
|---|---|
| **Reporting book** | 对于为某个实体带有多个会计账簿的源，已选定报告账簿。在您选择之前，只计入第一个账簿。 |
| **Codes waiting for your answer** | 多个源使用的每个代码都已回答。请参阅[跨源映射代码](#跨源映射代码)。 |
| **Extra categories from your sources** | 源带有的每个额外类别都已命名或已排除。 |
| **Which source covers which months** | 除非您已选择以哪个为准，否则没有两个源提供同一公司的相同月份。 |
| **Account types and hierarchy** | 维度所指的每个父级都存在，且没有成员是其自身的父级或祖先。缺失的父级会使其子级位于层次结构顶部，循环则会使该层次结构无法加载。合计不受影响。 |
| **Fiscal calendar** | 每个实体的会计期间都是日历月，且每个月的行都能归入一个会计期间。当实体的期间不是日历月（4-4-5、13 个期间），或某个月的行可能属于多个会计期间，或财务日历缺少该月时，需要关注。 |

每个未就绪的行都会在**操作**列中说明该怎么做，例如加载会计科目表、加载汇率，或针对某个期间再次运行**加载**。

网格还会显示两项设置检查，仅在需要关注时出现：

| 检查 | 出现时机 |
|---|---|
| **间接费用分摊** | 项目变量 `overhead_department` 和 `overhead_driver` 只设置了其中一个，或没有任何分摊动因与 `overhead_driver` 匹配，导致分摊不起作用。请同时设置两者，或同时清除两者以关闭间接费用分摊。 |
| **预算对比** | 已加载预算行，但没有任何一行属于项目变量 `budget_version` 所指的版本，导致预算对比为空。 |

## 管理合并

每次加载都会构建一个管理合并：集团中所有实体的集团损益表，以报告货币列示，并已抵销集团内部往来。它用于管理报告。合并系统仍是法定集团的记录依据；请按下文与其对账。

<Aside type="note">
管理合并仅涵盖损益表。它不是法定合并或法律合并，也没有合并资产负债表、折算调整、商誉或少数股东权益。
</Aside>

### 选择集团

在**源**下打开**分组**，可查看集团中的公司。您取消勾选的公司仍会单独出现在报表中，但不计入集团合计。点击 **Save group**。更改会在下次**加载**或 **Apply changes** 时生效。新公司在您取消勾选之前都属于集团。

集团会计年度从项目变量 `group_fy_start_month` 设置的月份开始，除非您更改，否则为 `1`。

### 您将得到什么

| 表 | 内容 |
|---|---|
| **Group P&L** | 每个实体、期间和明细项（收入、销售成本、运营费用、营业外项目、集团内部差异）各一行，以报告货币列示。收入和成本保留其自然符号。 |
| **Group P&L year to date** | 同上，为年初至今，截至集团最近一个完全加载的期间。 |
| **Intercompany pairs** | 每对实体、每个集团和期间各一行，列出双方的金额和余额。 |
| **Intercompany lines** | 集团数字或某一对背后的总账明细行，附带交易伙伴。 |
| **Reconciliation** | 集团年初至今损益表与合并系统的对比。 |

这些表中会出现三个实体名称：

| 实体 | 含义 |
|---|---|
| **Eliminations** | 集团内部往来抵销。它们合计为零，因此集团数字应保留它们，而要得到抵销前各实体之和时则应将它们筛选掉。 |
| **Group total** | 对账中合并系统的合计。 |
| **Unmapped** | 没有期间的明细行，以及合并系统中有而本项目没有的科目或实体。 |

指标 **Consolidated income**、**Consolidated result** 和 **IC difference**，以及每个表对应的分析路径，可用于回答有关集团的问题。

### 集团内部往来抵销

集团内部往来明细行按交易伙伴匹配。使用明细行上的伙伴；如果明细行没有伙伴，则使用其客户的伙伴。一对交易的双方都会被抵销，双方不一致的金额会计入集团内部差异行。每一对都会得到一个原因：

| 原因 | 含义 |
|---|---|
| **Matched** | 双方记录的金额相同。 |
| **Only one side booked** | 一个实体记录了该交易，而其伙伴没有。 |
| **Not eliminated** | 这一对中的某条明细行没有汇率，因此双方都未被抵销。 |

一对交易按其年初至今来判断。当某一对的差异超过项目变量 `group_amber`（默认 `1`）时，**Intercompany balances** 行变为琥珀色；超过 `group_red`（默认 `1000`）时变为红色。没有伙伴的明细行，或伙伴不是实体的明细行，不会被抵销，并会在该行中计数。如果一个源带有伙伴而另一个不带，则显示为琥珀色。

源自身的抵销实体不计入集团损益表，**合并**行会注明这一点。

### 与合并系统对账

将合并系统报告的结果作为文件添加，并在确认其映射时勾选 **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)**。用系统名称回答 **Which version of the numbers is this?** 之后，**Reconciliation** 表会按每个实体和明细项显示年初至今的 **ours**、**reported** 和**差异**。差异通常可以由 **Eliminations**、**Group total** 和 **Unmapped** 行或系统所用的汇率来解释。**Reconciliation to the source** 行会列出所有超过 `group_amber` 的明细项。

### 谁能看到

集团结果遵循项目的行访问权限。当行访问权限阻止集团结果时，状态显示为琥珀色。只能看到部分实体的人会看到这些实体抵销前的合计。**Eliminations** 行和集团内部往来表需要有权访问所有实体。

如果项目按集团表不带的列（例如部门）限制谁能看到哪些行，集团结果会对所有人关闭，**合并**会显示 **Group views are off**。此时只有架构师才能在**分组**下勾选 **Everyone on the project may see the group results**。更改会在下次**加载**或 **Apply changes** 时生效。

## 保持数据最新

通过 ERP 连接的加载顺利成功、没有问题后，**上次加载**卡片上会出现**每晚刷新**。点击它即可在您所在时区每晚 2:00 运行**加载**。卡片随后会显示 **Nightly refresh: Every night at 2:00** 以及设置者。

每晚加载以设置者的身份运行。如果该用户不能再使用 ERP 连接，网格会提示跳过每晚加载；请重新设置。只有示例数据的项目无法设置计划。

每晚加载时缺失或为空的文件，会在完成时给出指明路径的警告，而不是报错，模型的其余部分仍会加载。

## 业务名称

**Business names**（位于**基础数据**选项卡**源**页面的**名称**下）为模型中的代码赋予贵公司使用的名称。报表、指标和助手都会显示这些名称，保存的名称立即生效，之后的加载会保留它。

1. 点击 **Add a name** 并选择**类型**：**类别**、**P&L line**、**指标**或**列**。
2. 输入**代码**：类别为 `segment_1` 至 `segment_10`，损益表行为该行的键，指标为指标名称，列为 `table.column`。
3. 输入**名称**，最多 60 个字符，单行。
4. 点击 **Save names**。

保存会替换整个列表。名称为空的行会移除该名称，**移除所选项**会移除您勾选的行。同一个代码命名两次会被拒绝。业务名称还会写入分析路径的说明，使助手使用您的措辞，而该说明有长度限制：如果某个名称会使其过长，则不会保存任何内容，并会通知您。

## 解释数字

**Explain this number** 显示一个损益数字由哪些部分构成。在**就绪状态**网格中，某个实体和月份的行带有 **Explain this number**，它会打开该实体当月的营业利润率。窗口将数字拆分为若干层，各层相加等于顶部的合计：

| 层 | 内容 |
|---|---|
| **From the general ledger** | 总账过账到该明细项的金额。 |
| **Allocated in** | 按[分摊规则](#分摊规则)分摊给该实体的成本。 |
| **Allocated out** | 该实体分摊给其他实体的成本。 |
| **Eliminated in the group** | 在集团结果中被抵销的集团内部往来。 |

每一层都有一句话说明它是什么，并列出其最大的来源单据，包括来源系统、单据和科目。只显示有行的层。窗口遵循您的行访问权限：只能解释您看得到的数字。没有任何依据的数字显示 **Nothing to explain**。

## 分摊规则

分摊把共享成本（例如间接费用）分配到部门、产品和客户。模型分为两个阶段：**Stage 1: overhead to departments** 和 **Stage 2: departments to products and customers**。打开**操作** > **分摊...** 可查看或更改每个阶段的做法。不做更改时，它们的运行方式与向导出现之前相同。读者可以打开规则，但不能保存。

对每个阶段，向导会问四个问题：

| 步骤 | 问题 | 选项 |
|---|---|---|
| **Pool** | 您想分摊哪些成本？ | 科目的类型；阶段 1 还有承担该成本的部门，或 **All departments**。 |
| **Driver** | 您想按什么来分摊？ | 您作为分摊动因加载的 **Statistic**（例如人数或平方英尺）、**Net sales amount**、**Sales quantity** 或 **Spread evenly**。使用 **Same period** 或 **Same period last year** 的动因。 |
| **Target** | 分摊到哪里？ | 阶段 1：部门。阶段 2：产品、客户或两者。 |
| **Method** | 动因为负数时怎么办？ | **Ignore negative values** 或 **Stop and tell me**。 |

在这些步骤下方，**Preview for** 某个月份（写作年和月，例如 `2026-09`）会显示规则（包括尚未保存的规则）将产生的结果：`Pool 120,000 · Allocated 120,000 · Unallocated 0`。任何未分摊的部分都是没有动因可承接的成本。预览遵循您的行访问权限。

点击**保存**。规则会在下次**加载**时生效，或在您点击 **Apply changes** 时生效。如果您手动编辑过某个分摊步骤，您的编辑会被保留而不会被覆盖，保存时会指出该步骤。加载运行期间无法保存。

## 董事会资料包

董事会资料包会把您的结果写入文档账户中的某个文件夹，随时可以发送。打开**操作** > **Board pack...**，选择**文档账户**和**文件夹**（例如 `/board-packs`），然后点击**保存**。此后每次**加载**都会生成资料包，因此文件夹中的文件与最近一次加载保持同步。每次运行会写入：

- 一个 Excel 工作簿 `Board pack.xlsx`，包含按实体划分的损益表、利润桥以及排名靠前和靠后的客户。
- 一份损益表仪表板的 PDF。

点击 **Run now** 可立即生成资料包；完成后其文件会出现在文件夹中。对话框会显示上次运行及其结果，以及下次运行。**Apply changes** 不会生成资料包。若要每晚生成，请设置每晚刷新（请参阅[保持数据最新](#保持数据最新)）；在此之前，对话框会显示 **Not scheduled yet**。只有能更改项目的人才能设置。

无法完整生成的资料包绝不会导致加载失败：

- 如果您的工作区已关闭报告功能，资料包就只有 Excel 工作簿，运行结果会显示 **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- 如果他人创建的某个仪表板已占用了 Data Foundation 为损益表仪表板所需的地址，该仪表板会保持原样，不会生成 PDF。消息会指出该地址；请为另一个仪表板改用其他地址，然后再次运行**加载**。
- 如果资料包的任何步骤失败，**状态**列表会显示一个琥珀色的 **Board pack** 行，指出该步骤及原因。加载本身仍然成功。

## 还原点

每次**加载**或 **Apply changes** 开始时都会创建一个还原点，无论由谁启动，包括计划加载，并且在每次更改映射或源之前也会创建。它保存模型的表、维度，以及下次加载据以构建的设置：您的源、文件和分摊规则。系统保留为加载创建的最近七个还原点，以及在更改前创建的最近五个，因此更改不会挤掉为加载创建的还原点。更早的还原点会被淘汰。

若要回退，请打开**操作** > **还原...**。每个还原点都会显示创建时间，其下方显示还原它会带回多少张表，例如 **Puts back 12 tables.**，以及所有警告。选择一个还原点并点击**还原**。存在还原点后才提供**还原**。还原时，会先把项目当前的状态记录为一个独立的还原点，因此您可以再次回退。然后它会把表、维度和这些设置恢复到原来的样子，下次加载会基于它们构建。还原到您已有的源时，不会将其标记为已更改。视图、无法保存的维度或没有已保存副本的表会在警告中点名，其余部分照常还原。已被淘汰的还原点会被拒绝，加载运行期间也无法还原。

## 克隆项目

**操作** > **克隆...** 会以您给定的名称复制项目。副本保留模板、您对模型所做的修改以及您的指标和分析路径，并加载示例数据。其源未连接，因此请在副本中先连接它们再加载。副本生成期间您可以继续工作，准备就绪后，**打开项目**会带您前往。

## 另存为我的模板

保存项目的设置，以便用于下一个客户或实体。打开**操作** > **Save as my template...**，选择文档账户并为文件命名。如果您省略了扩展名，会自动添加以 `.zip` 结尾的名称。覆盖已有文件会被拒绝，因此请选择另一个名称。

该文件包含项目的结构、您对模型所做的修改、指标和分析路径、实体和科目的业务名称，以及模板配置表的行，例如 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/) 的活动映射或 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/) 的政策区间。它不包含连接、文件、每晚计划、运行记录、还原点、董事会资料包以及谁拥有访问权限。

使用时，请创建项目，在**起始来源**下选择 **From a template file...**，然后选择文档账户和路径。新项目仅您可见，所有源都等待连接。之后模板发布新版本时，会围绕您编辑过的步骤合并其更改。如果该路径下没有文件，则不会创建任何内容，并会通知您。任何能读取该文档账户的人都可以从该文件安装。若要在另一个工作区中使用，请下载该文件并上传到那里。

## 用 Ask 解决未决问题

加载之后，项目可能仍在等待您告知三件事：会计科目表中未设置类型的科目、多个源使用的代码，以及文件中未匹配到任何内容的列。请让助手来解决：通过 MCP 从 AI 助手使用 **Resolve Data Foundation residue** 提示。它会读取待处理的内容，并为每一项提出一个答案及理由。

助手不会写入任何内容。您需要在本该由自己回答的位置应用它的答案：科目和代码在 **Codes waiting for your answer** 下，文件列则在文件的映射中。它绝不会提议实体。

## 移交项目

在**查看您的层级结构**之后，**设置**清单还有四个收尾事项：

- **Set up the nightly refresh**：开启**每晚刷新**后即完成。
- **与团队共享**：除设置项目的人之外还有其他成员后即完成。
- **Download the evidence pack**：在最近一次成功加载之后下载资料包即完成。
- **Hand the project over to its owner**：存在设置者之外的另一位架构师且合计一致后即完成。未完成时，清单会说明该怎么做：将客户的所有者设为此项目的架构师，然后将自己从成员中移除。

清单会注明项目由谁设置（**Set up by**）。

## 使用模板在模型基础上构建

模板在 Common Finance Model 之上构建其报表和模型，因此无论由哪些 ERP 提供数据，它们的运作方式都相同。当您从模板（例如 **Enterprise Profitability**）启动项目时，它会创建：

- [Common Finance Model 表](#common-finance-model-表)，为空或填充了示例数据。
- 由这些表构建的**实体**、**科目**、**部门**、**客户**、**产品**、**Segment 1** 和 **Segment 2** 维度。请参阅[层次结构](#层次结构)。
- **加载**工作流，以及它为读取 ERP 和文件、整合数据、检查就绪状态和构建模板模型而运行的工作流。
- 模板自己的报表和模型。**Enterprise Profitability** 会添加一个损益表，包含收入、COGS、毛利、直接和间接运营费用、边际贡献和营业利润率，以及同比和对预算的利润桥。
- 用于就结果提问的指标和一条分析路径。

**起始来源**下提供三个模板，都构建在同一个模型之上：

| 模板 | 新增内容 |
|---|---|
| **Enterprise Profitability** | 损益表和利润桥。 |
| **Cost to Serve** | 服务每位客户的成本，以及扣除后的利润率。请参阅 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/)。 |
| **Operational Transfer Pricing** | 每个实体的利润水平与您的政策区间的对比，以及补差调整。请参阅 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)。 |

**From a template file...** 从您保存的项目开始。请参阅[另存为我的模板](#另存为我的模板)。

若要在连接自己的 ERP 之前先做探索，请在创建项目时勾选**从示例数据开始**。项目会立即运行第一次加载，因此**基础数据**选项卡会显示一个完整的示例，其中包括折算为美元的欧元实体。当您连接自己的 ERP 或添加自己的文件时，示例数据会被移除，由您的数据取而代之。如果移除被中断，下次**加载**会完成它。您自己命名为 `sample` 的文件夹绝不会被移除：状态页会注明示例数据占用了该文件夹，因此其中的其他表不会被读取，并请您将它们移到名称不同的文件夹中。

## 基础数据选项卡

**基础数据**选项卡是您连接、加载和检查数据的地方。左侧的导航栏列出四个页面：

| 页面 | 显示内容 |
|---|---|
| **状态** | 项目的状态：带有**加载**、**Apply changes**、**刷新**和**每晚刷新**按钮的**上次加载**、**What to do next**、**设置**清单、**数据已加载**、**期间**、**就绪状态**以及**操作**菜单。 |
| **需要回答** | 等待您回答的问题，例如多个源共用的代码，由您说明它们是否表示同一事物。 |
| **源覆盖范围** | 各源在某个公司和月份上的重叠或缺口，以及每个源从何时起计入。 |
| **源** | 按 **Load order** 列出每个源，带有**编辑**和 **Remove this source**、**分组**和**名称**卡片，以及 **Connect a system**（或 **Connect another system**）：可在此选择系统类型、选取其连接、选择公司和要加载的历史月数，或添加文件。您添加的文件位于**文件**卡片中。 |

导航栏上的徽标统计需要关注的事项：**需要回答**上的待回答问题、**源覆盖范围**上的覆盖问题，以及**源**上的源。**状态**不显示徽标。**加载**或 **Apply changes** 的结果以及状态横幅显示在当前打开的页面上方，因此每个页面都能看到。**状态**上指向某个问题或覆盖问题的按钮（例如**审核**）会将您带到相应页面。关闭**需要回答**或**源覆盖范围**会返回**状态**。

更改源后，每个页面上方会出现一条提示栏：**You have changed your sources. Press Apply changes to use them.** 该提示栏带有 **Show what changed** 和 **Apply changes**，是应用更改的唯一位置。没有待应用的更改时，**加载**是**状态**上的主按钮。在**状态**上，**What to do next** 先列出问题，再列出需要关注的事项，两组连续编号。在**需要回答**上，**Answer all** 提供 **Accept suggestions**、**All the same** 和 **All different**。在**源覆盖范围**上，**Save choice** 会保存每个源从何时起计入。

**设置**清单包括：**连接您的数据**、**加载您的数据**、**检查合计是否一致**、**查看您的层级结构**、**Set up the nightly refresh**、**与团队共享**、**Download the evidence pack** 和 **Hand the project over to its owner**。当前事项以粗体显示。业务名称、您添加的文件及其映射状态（**✓ 已确认**或 **○ 等待确认**），以及就绪状态网格（每个实体、期间和检查各一行，带有**操作**）也位于这些页面上。请参阅[业务名称](#业务名称)。

加载运行期间，选项卡会自动刷新，即使某次读取失败也会继续读取。如果无法读取状态，会出现**无法读取基础数据状态。** 及**重试**，后者会重新读取；选项卡在显示该消息之前也会自行重试一次，服务器响应后该消息会消失。

**状态**页还会注明：

- `/sources/` 下的文件夹，如果其中的表缺少所需的列，则不会被添加为源。注释会指出每个被排除的表及其缺少的列。请添加该列，然后点击**加载**或 **Apply changes**。
- 如果某次加载成功，但没有带来可供比较的总账明细行，会有一个琥珀色的 **Model P&L ties to GL** 行提示没有任何内容核对一致。在有内容核对一致之前，**检查合计是否一致**会在设置清单中保持待办状态，而不是完成。请添加带有总账明细行的源，然后点击**加载**。

设置清单会跟踪您的进度：

- 附加了源并且加载成功后，**连接您的数据**和**加载您的数据**会自动打勾。
- 合计核对检查通过后，**检查合计是否一致**会自动打勾。
- **查看您的层级结构**：点击**打开维度**以查看实体、科目和部门层次结构，然后勾选**我已查看**。这一项由您自行确认。
- **Set up the nightly refresh**、**与团队共享**、**Download the evidence pack** 和 **Hand the project over to its owner** 位于清单末尾。请参阅[移交项目](#移交项目)和[管理项目访问权限](/zh-cn/guides/projects/managing-projects/#管理项目访问权限)。

**操作**菜单包含**分摊...**、**Board pack...**、**克隆...**、**还原...** 和 **Save as my template...**。请参阅[分摊规则](#分摊规则)、[董事会资料包](#董事会资料包)、[克隆项目](#克隆项目)、[还原点](#还原点)和[另存为我的模板](#另存为我的模板)。

## Common Finance Model 表

Data Foundation 将每个源（无论是 ERP 还是文件）整合到同样的十五张表中，因此基于它们构建的报表、指标和模型无论数据来自何处，运作方式都相同。每一行还会记录其来源系统和读取时间。**数据集**列是您添加文件时选择的名称。

| 数据集 | 表 | 内容 |
|---|---|---|
| 实体 | `cfm_entity` | 法人实体，含父级、本位币和集团货币以及国家。 |
| 实体对照表 | `cfm_entity_map` | 源实体代码及其所属的实体。请参阅[实体对照表](#实体对照表)。 |
| 汇率 | `cfm_fx_rate` | 按货币对列示的月度平均、期末和历史汇率。请参阅[汇率](#汇率)。 |
| 财务日历 | `cfm_fiscal_calendar` | 每个实体会计期间一行，含起止日期以及是否已结账。 |
| 会计科目表 | `cfm_account` | 科目，含父级、类型（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、报表、正常余额和汇率类型。 |
| 部门 | `cfm_department` | 部门和成本中心，含父级和利润中心。 |
| 产品 | `cfm_product` | 产品主数据，含父级、系列、分组、计量单位和标准成本。 |
| 客户 | `cfm_customer` | 客户主数据，含父级、分组、区域和国家。客户名称不会被屏蔽。 |
| 分部值 | `cfm_segment` | 分部值，含名称和父级。请参阅[层次结构](#层次结构)。 |
| 总账 | `cfm_gl_journal` | 以交易货币、本位币和报告货币列示的日记账明细行。 |
| 试算平衡表 | `cfm_trial_balance` | 按实体、科目和部门列示的期间借方、贷方和净额，以本位币和报告货币列示。 |
| 销售明细行 | `cfm_sales_line` | 已开票的销售明细行，含数量、毛额、折扣、净额和 COGS 金额。 |
| 库存余额 | `cfm_inventory_balance` | 按产品和仓库列示的期末库存。 |
| 预算 | `cfm_budget` | 按方案、版本、科目和部门列示的预算和预测。 |
| 分摊动因 | `cfm_stat_driver` | 统计动因，例如人数、平方英尺或单位数。 |

期间写作 `YYYY-MM`，交易按过账期间归属。预算是可选的：没有预算的 ERP 仍会加载其他所有内容。

试算平衡表文件可以带借方和贷方列、净额列，或两者都带。只有借方和贷方时，净额为借方减贷方，空白的一侧按零计算。只有净额时，正的净额记为借方，负的净额记为贷方，以正数表示。部门列是可选的。

## 故障排除

| 现象 | 处理办法 |
|---|---|
| **测试连接**提示 ERP 拒绝了凭据 | 检查连接的凭据，并确认集成用户可以登录 ERP。 |
| **测试连接**对某个数据集显示**缺少权限** | 请 ERP 管理员添加其列出的权限。您 ERP 的[连接指南](/zh-cn/guides/connections/)列出了连接所需的内容。 |
| ERP 的错误消息比 ERP 自身的更短 | PlaidCloud 在显示提供方的错误之前会移除其中的凭据、令牌和密钥，因此部分细节会被省略。运行**测试连接**可查看受影响的数据集。 |
| 某个期间的**数据已加载**为问题 | 该期间的 ERP 读取失败。再次运行**加载**；已加载的期间会被跳过。 |
| **科目表中缺失的科目**为问题 | 将缺失的科目添加到 ERP 或您文件中的会计科目表，然后再次运行**加载**。 |
| **货币折算**为问题 | 某个实体的货币在该期间没有折算为报告货币的汇率，或未找到唯一的报告货币。请将汇率添加到**汇率**文件中，检查连接能否读取 ERP 的汇率，或设置项目变量 `reporting_currency`。然后再次运行**加载**。 |
| **货币折算**需要关注 | 资产负债表、库存或预算行在该期间没有期末、历史或计划汇率。损益表不受影响。请添加汇率（包括预算月份的计划汇率），然后再次运行**加载**。 |
| **Codes waiting for your answer** 需要关注 | 点击**审核**，回答每个代码，然后点击 **Apply changes**。 |
| **Which source covers which months** 需要关注 | 点击 **Choose which source counts from when**，选择源，然后点击 **Apply changes**。 |
| **Intercompany balances** 为红色或琥珀色 | 检查 **Intercompany pairs** 中的各对交易。记录缺失的一方，为明细行添加交易伙伴，或补充缺失的汇率。 |
| **Group views are off** | 请架构师在**分组**下勾选 **Everyone on the project may see the group results**。 |
| **未映射的实体**为问题 | 将该实体添加到实体主数据，或在**实体对照表**文件中将其代码映射到现有实体，然后再次运行**加载**。 |
