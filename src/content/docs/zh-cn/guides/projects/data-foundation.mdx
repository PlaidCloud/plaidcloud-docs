**Data Foundation** 是您的 PlaidCloud 项目的财务数据基础。其 **Common Finance Model** 将来自多个 ERP 系统（以及每个系统的多个实例）的 ERP 数据整合到单一模型中：一套会计科目表、一组实体和一种报告货币。基于该模型构建的报表、指标和 AI 助手读取的都是相同的数字，无论它们来自哪个 ERP。

您的 ERP 通过其 PlaidCloud 连接接入，因此总账、试算平衡表、主数据和预算直接从源头到达，无需导出任何内容。文件用于补充系统未保存的数据，例如货币汇率、分摊动因或保存在 ERP 之外的预算，并且可以替换其所覆盖的 ERP 行。**加载**会将每个源整合到模型中，折算为报告货币，并检查其是否核对一致，这一切都在项目的**基础数据**选项卡中完成。当多个源对不同含义使用相同的代码时，由您说明它们是否含义相同，随后管理合并会构建已抵销公司间交易的集团损益表。模板（例如 Enterprise Profitability）在此基础上构建各自的报表和模型。

## 连接您的 ERP

您的 ERP 通过其 PlaidCloud 连接接入 Data Foundation。Data Foundation 直接从中读取总账、试算平衡表、主数据、汇率和预算，并且只执行读取。您可以在该选项卡上选择现有连接或创建一个；[连接指南](/zh-cn/guides/connections/)涵盖了各个 ERP 的访问设置。

<Steps>

1. 在 Analyze 中，打开**项目**并点击**新建项目**。输入名称，并在**起始来源**下选择一个模板（例如**企业盈利能力(模板)**），而不是**空白项目**。点击**创建**。

   项目会在其**基础数据**选项卡上打开。在您共享之前，它仅对您私有，并且您是它唯一的架构师。

2. 在**基础数据**选项卡上，为您的 ERP 选择现有连接，或选择**创建新连接**。每个现有连接都会列出已使用它的工作流，或显示**暂无工作流使用**。

3. 对于新连接，输入**连接名称**，选择**环境**，并填写 ERP 连接所要求的凭据。

   还没有凭据？表单会显示一份为 ERP 管理员准备好的访问请求。点击**复制请求**或**通过电子邮件发送请求**，将其发送出去，然后输入他们回复的值。

4. 点击**测试连接**。PlaidCloud 会登录并尝试读取每个数据集，然后将每个数据集列为**可读取**、**缺少权限**或**错误**。当有内容缺失时，它会指出需要请 ERP 管理员添加的权限。

5. 设置**历史月数**：要向前加载多少个月，范围为 1 到 120。默认为 24。

6. 对于现有连接，勾选要加载的实体，或全部不勾选以加载每个实体。已停用的实体和抵销实体在您选择显示之前保持隐藏。然后点击**连接**。

7. 对于新连接，点击**连接**以创建它。然后勾选要加载的实体，再次点击**连接**以保存。在此之前，将加载每个实体。

8. 若要引入另一个 ERP 系统或另一个实例，请重复这些步骤，并在点击**连接**之前勾选 **Add this as another source instead of replacing the current one**。否则，新连接会替换当前的源。

</Steps>

连接之后，卡片会说明项目加载的是哪个连接、环境、实体以及多少个月的历史。

每次加载只读取发生变化的内容：未结账期间和最近一个已结账期间会被重新读取，已加载的已结账期间则保持不变。提高**历史月数**只会读取新增的月份。汇率、实体对照表或报告货币发生变化时，会重新读取受影响的月份。

## 源

项目加载所用的每个 ERP 系统和实例都是一个源。**基础数据**选项卡上的**源**列表为每个源按顺序显示一行，包含其名称、上次加载时间、提供的行数，以及所读取的报告账簿，例如 `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`。尚未加载的源显示 **not loaded yet**。您确认的文件也是源。

打开某个源的**高级**可更改其使用方式：

| 设置 | 作用 |
|---|---|
| **名称** | 报表、映射问题和消息中对该源使用的标签。 |
| **在顺序中的位置** | 该源的排名。当两个源覆盖同一公司的同一个月时，顺序靠前的源优先。 |
| **报告账簿，以逗号分隔** | 要读取的会计账簿，适用于保存多个账簿的系统。**All reporting books** 读取每个账簿。 |
| **公司**、**从 (2026-01)** 和 **至 (2026-12)** | 该源为每个公司提供的月份。将月份留空表示不设限制。月份写作年和月，例如 `2026-03`。 |

点击**保存**以保留您的更改。若要删除某个源，请点击 **Remove this source** 并确认**移除**。从该源加载的所有内容都会被删除，您之后可以重新连接它。

更改源不会再次读取您的 ERP。在您点击 **Apply changes** 之前，**上次加载**卡片会显示 **Changes not applied yet**，点击后将基于已拉取的数据运行加载：它会使用您新的顺序、映射、名称和文件重新整合各个源，并重建模型。如果还想从 ERP 获取最新数据，请点击**加载**。

## 为 ERP 之外的数据添加文件

文件用于补充您的 ERP 连接，提供系统未保存的数据，例如货币汇率、分摊动因、[实体对照表](#实体对照表)或保存在 ERP 之外的预算。每个文件属于[Common Finance Model 表](#common-finance-model-表)下列出的某个数据集。

<Steps>

1. 在**文件**下，选择用于存放该文件的**文档账户**。

2. 将 CSV 或 Excel 文件拖放到**将 CSV 或 Excel 文件拖放到此处**，或点击**选择文件**。文件会上传到文档账户的 `/foundation/` 文件夹。

   对于已在文档账户中的文件，请输入其**文件路径**，例如 `/foundation/budget.csv`，然后点击**添加文件**。

   若要每月读取新文件，可添加名称匹配的文件夹中的所有文件：输入文件夹以及 **File names that** 包含、开头为、结尾为、完全匹配或按模式匹配的内容，然后点击 **Add files**。不会读取其内部子文件夹中的文件。

3. PlaidCloud 读取文件并提出映射建议：

   - **检测到的分隔符、小数分隔符和日期。** 系统会自动检测分隔符（逗号、分号、制表符或竖线）、小数分隔符和日期格式。
   - **数据集**：文件所属的 Common Finance Model 表，根据文件名和列标题匹配。当匹配结果不明确时，请从列表中选择。
   - **小数分隔符**：**句点(1,234.56)** 或**逗号(1.234,56)**。
   - **日期格式**：文件包含日期时显示。如果检测到的格式有误，请更改：`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY` 或 `MM/DD/YYYY`。
   - 一个包含**文件中的列**、**类型**、**示例**和**去向**的网格。更改**去向**可将某一列发送到其他字段，或设为**不加载**。

4. 回答文件引发的问题，例如 **Which company is this file for?**、**Which currency are the amounts in?**、**Are these amounts year-to-date or for the month?**、**Are the amounts shown in thousands or millions?** 或 **Are revenues shown as negative numbers?** 只有在文件本身未说明时才会询问每个问题。

5. 检查每一列的去向，然后点击**确认映射**。

</Steps>

适用时，文件上会出现这些选项：

| 选项 | 用途 |
|---|---|
| **Which source do these rows apply to?** | 将代码映射文件限制到某一个源。**Every source** 将其应用于所有源。 |
| **Where does this file come from?** | 说明文件包含的是 **This project's own codes**，还是来自您命名的 **Another system**，例如 `SAP Germany export`。来自其他系统的文件会像 ERP 源一样检查共享代码。 |
| **Split … into … parts at each …**（在**高级**下） | 拆分包含多个值的某一列（例如 `100-200-300`），并将每个部分发送到各自的字段。 |
| **Which currency do you report in?** | 在项目尚无报告货币时设置报告货币。写作三个字母，例如 `USD`。 |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 加载您的合并系统的结果，以便[对账](#与合并系统对账)集团损益表。 |

若要将文件从项目中移除，请点击**文件**下该文件旁的**移除**，或其映射上的 **Remove this file**，并确认。下次点击 **Apply changes** 时，其数字会从您的报表中消失。

当 PlaidCloud 无法自行确定数据集、小数分隔符或日期顺序时（例如文件中的日期既可读作日/月也可读作月/日），它会要求您在确认之前进行选择。为同一数据集添加第二个文件会替换第一个文件。如果后续文件的列与数据集不匹配，加载会指出该文件和这些列，并告诉您更正文件或其列名，或将步骤的 **Schema Mismatch** 设为 `union`。

接受的文件有 CSV、TSV 和 TXT 文本文件、Excel `.xlsx` 文件（读取第一个工作表）以及 Parquet 文件。

<Aside type="note">
缺失或为空的文件永远不会阻止加载。添加此类文件时会提示暂无可映射的内容，加载会以指出路径的警告结束，并使该数据集保持为空。文件存在后请再次添加。
</Aside>

## 加载您的数据

点击**加载**卡片或**上次加载**卡片上的**加载**。加载会读取您已连接的 ERP 和已确认的文件，将它们整合到 Common Finance Model 中，折算为报告货币，运行就绪状态检查，并重建模板的模型。

- 一个项目同一时间只运行一次加载。第二次**加载**或 **Apply changes** 会提示已有加载正在运行，并且在加载运行期间无法更改源。
- 如果其他工作流使用同一个 ERP 连接，首次加载会列出它们并请您确认，因为加载会从 ERP 读取数据，可能会拖慢这些工作流。点击**仍然加载**即可继续。
- PlaidCloud 升级后，架构师的**加载**还会更新项目生成的工作流，并创建它们所需的任何工作表。在此之前，状态页面会列出一个琥珀色项目：“The workflows were generated by an earlier release. An Architect's Load updates them.”，而管理者的**加载**会警告只有架构师才能更新它们。
- 失败的加载显示为红色，绝不会隐藏在之前的结果之后。如果合并失败，状态会指出它停止于哪个步骤，而不是显示旧的集团结果。来自较早加载的行会显示**来自较早的加载。请重新加载。**，直到加载成功。
- 如果某个实体和期间读取失败，其余部分仍会加载。再次运行**加载**，仅获取失败的部分。

### 被扣留的行

当多个源重叠时，加载会保留每个数字的一份副本，并扣留其他副本，而不是重复计算。被扣留的行会连同其源、实体和原因一并记录，加载会以指出数量的警告结束，例如 `120 rows of NetSuite EU also provided by a source ranked ahead`。原因如下：

| 原因 | 含义 |
|---|---|
| 位于另一个会计账簿中 | 该行属于该源未设置读取的报告账簿。 |
| 超出该源提供的期间 | 该行落在为公司设置的**从**和**至**月份之外。 |
| 排名靠前的源也提供了该行 | 顺序靠前的源覆盖了同一公司和月份。 |
| 该源的较早文件中也有 | 同一源的较早文件已经覆盖了该月。 |
| 已被文件替换 | 文件替换了该实体和月份的 ERP 行。 |
| 带有另一个源也使用的代码 | 该代码需要您回答。请参阅[跨源映射代码](#跨源映射代码)。 |
| 带有映射到两个代码的代码 | 代码映射为该代码给出了两个答案。 |

统计科目会转入分摊动因而不是总账，并显示为已转移，而不是问题。

### ERP 数据与文件并用

文件只替换其所覆盖的内容，ERP 的其他行保持不变。

- **主文件**（科目、部门、客户、产品和分部值）会替换代码相同的 ERP 行。
- **交易文件**会替换同一实体和月份的 ERP 行。总账和试算平衡表文件还按账簿匹配，预算文件按方案匹配，统计动因文件按方案和动因匹配。

如果某个文件之后不再覆盖某个月，该月的 ERP 数据会在下次加载时恢复。

## 实体对照表

每个源使用自己的代码来命名其实体。**实体对照表**将这些代码映射到实体主数据中的实体，使来自每个源的行落在同一个实体上。

要使用它，请添加 CSV 或 Excel 文件并选择**实体对照表**数据集：

| 列 | 内容 |
|---|---|
| `source_entity` | 源所带的代码，例如公司代码。 |
| `entity` | 其所属的实体，与实体主数据中的命名一致。 |

- 不在对照表中的代码将按原样使用。
- 多个代码可以映射到同一个实体。它们的行会被合并，当某个月对所有这些代码都已结账时，该月才算已结账。
- 对照表中的代码适用于每个源，因此各源的实体代码在所有源中必须唯一。
- **实体**文件中的一行会替换实体代码相同的 ERP 实体。

**未映射的实体**检查会标记任何其实体既不在实体主数据中、也未通过对照表映射到实体主数据的行。在加载实体主数据之前，它显示 **– 不适用**。

## 跨源映射代码

两个源可能对不同的事物使用相同的代码，或对同一事物使用不同的代码。当某个代码出现在多个源中时，Data Foundation 会扣留其行，直到您说明它在各处是否含义相同，从而使每个金额只计算一次。**等待您回答的代码**检查会列出这些代码，先列出前 10 个，然后是“以及另外 K 个”，**基础数据**选项卡上的 **后续操作** 卡片带有一个**审核**按钮。

**审核**会打开**等待您回答的代码**。它按代码的类型分组：**账户类型**、**公司**、**账户**、**部门**、**利润中心**、**客户**、**产品**以及每个额外类别。对于每个代码，它会显示各个源对它的称呼以及一条建议：

- 当各源给该代码起了相同的名称时，显示 **Looks like the same thing**。
- 当名称不同时，显示 **Looks like different things**。
- 当没有任何依据时，显示 **We can't tell. Please answer.**

可以用 **Yes, the same** 或 **No, different** 逐个回答代码，也可以用 **Accept all**（采纳每条建议）、**All the same** 或 **All different** 一次回答整个分组。对于账户，还可以一次回答科目表中的整个父级分组。如果某个源没有账户类型，请为一组账户选择 **Use this type**：**收入**、**销货成本**、**运营费用**、**营业外收支**、**资产**、**负债**或**权益**。

映射按源和维度分别保存，因此对某个源的部门所作的回答绝不会改变另一个源的账户。回答会随时保存，并提示 **Saved. Press Apply changes to use your answers.** 点击 **Apply changes** 即可使用它们。

您也可以通过文件提供映射。添加一个使用**代码映射**数据集的文件，并选择 **Which source do these rows apply to?** 将其限制到某一个源。

## 选择哪个源从何时起计入

当两个源提供相同的月份时，**哪个源覆盖哪些月份**检查会请您做出选择。在 **后续操作** 卡片中点击 **Choose which source counts from when**，打开 **Which source counts from when**，其中按公司列出每处重叠。选择计入的源，在 **That month is** 中输入其开始计入的月份（例如 `2026-04`），然后点击 **Apply changes**。另一个源保留较早的月份。

当两个源给出同一种货币的不同汇率时，同一个对话框也会发出警告；系统使用顺序靠前的源的汇率。

## 货币折算

每次加载都会将总账、试算平衡表、销售、库存和预算金额从本位币折算为一种报告货币。报表和模型读取折算后的金额，因此来自任何系统、使用不同货币的实体都能正确合计。

### 报告货币

要选择报告货币，请将项目变量 `reporting_currency` 设置为货币代码，例如 `USD`。请参阅[管理项目变量](/zh-cn/guides/projects/managing-projects/#管理项目变量)。模板创建时它为空。在它为空期间，每次加载使用以下各项中第一个恰好指向一种货币的：

1. 实体的集团货币。
2. 顶层实体（没有父级的实体）的本位币。
3. 文件的本位币。

如果其中没有任何一项恰好指向一种货币，**货币折算**会显示问题，直到您设置 `reporting_currency`。

已经是报告货币的金额保持不变，因此数据全部使用同一种货币的项目不需要汇率。

销售、库存和预算文件也可以带有货币。将名为 `Currency` 或 `Local Currency` 的列映射后，系统会自动识别，文件中的本位币金额会折算为报告货币。文件中已有的集团或报告金额将保持原样。产品标准成本不进行折算。

### 汇率

汇率将一个单位的某种货币换算为某个月的报告货币：折算后的金额等于本位币金额乘以汇率。

- **来自 ERP**：每次加载都会读取 ERP 中保存的汇率。
- **来自文件**：添加 CSV 或 Excel 文件并选择**汇率**数据集。文件中的汇率会替换 ERP 中相同货币和月份的汇率。如果要使用您的 ERP 未发布汇率的货币作报告货币，或为预算月份添加计划汇率，请使用文件。

| 列 | 内容 |
|---|---|
| `from_currency` | 要折算的源货币，例如 `EUR`。 |
| `to_currency` | 报告货币，例如 `USD`。 |
| `period` | 月份，格式为 `YYYY-MM`。 |
| `average_rate` | 该月的平均汇率。 |
| `closing_rate` | 月末汇率。 |
| `historical_rate` | 历史汇率，用于权益以及设置为使用历史汇率的科目。 |

仅使用折算为报告货币的汇率。反向报价的汇率（从报告货币折算为其他货币）不会取倒数。

### 适用哪种汇率

每一行都从其自身的货币折算，因此与其实体货币不同的行会从它所用的货币折算。第一个符合该行的规则适用：

| 行 | 汇率 |
|---|---|
| 统计科目和非过账科目 | 不折算。 |
| 已经是报告货币 | 不折算。 |
| 带有汇率类型的科目 | 该汇率：平均、期末或历史。没有历史汇率时，历史汇率回退为期末汇率。对于来自 ERP 的数据，汇率类型就是科目自身的汇率类型。在会计科目表文件中，将汇率类型列映射到 `fx_rate_type`，取值为 `average`、`closing` 或 `historical`。 |
| 销售行 | 该期间的平均汇率。 |
| 库存余额 | 该期间的期末汇率。 |
| 预算行 | 按科目，与总账相同：损益科目使用平均汇率，资产负债表科目使用期末汇率。 |
| 损益科目 | 该期间的平均汇率。 |
| 权益科目 | 历史汇率；没有历史汇率时使用期末汇率。 |
| 任何其他资产负债表科目 | 该期间的期末汇率。 |

折算后的金额不进行舍入，因此合计不会产生偏差。

<Aside type="note">
试算平衡表保存的是每个期间的发生额，因此资产负债表金额是每个月的发生额按当月期末汇率折算的结果。它们不是按期末汇率重新折算的资产负债表，也没有累计折算调整或公司间抵销。请将折算后的金额用于损益表。
</Aside>

## 层次结构

每次加载都会根据每个源的主数据重建维度。初始有七个维度，另外最多可有十个额外类别：

| 维度 | 构建依据 |
|---|---|
| **实体** | 实体及其父级 |
| **科目** | 会计科目表和父级科目 |
| **部门** | 部门及其父级 |
| **客户** | 客户及其父级客户 |
| **产品** | 产品及其父级产品 |
| **分部 1** | `segment_1` 的分部值 |
| **分部 2** | `segment_2` 的分部值 |
| **分部 3** 至 **分部 10** | `segment_3` 至 `segment_10` 的分部值（如果您的源带有这些值） |

- 没有父级的记录，或将自身指定为父级的记录，会作为顶层成员加载。
- 由于每次加载都会重建层次结构，请在 ERP 或您的文件中更改父级，而不要在维度中更改。
- 某个层次结构中的问题只影响该维度。加载和模板的模型仍会完成。
- 您可以将每个额外类别重命名为其所含内容，例如**类别**或**区域**。在 **Rename extra categories** 下，输入报表使用的名称并点击 **Save names**。名称可使用字母、数字、空格、点、短横线和下划线，最长 60 个字符。
- 每个源会说明它自己的每个额外类别归入您的哪个类别名称之下。打开该源的**高级**，为每个类别选择名称，或选择 **Leave out**，然后点击**保存**。用不同名称称呼同一类别的源（例如 `Class` 和 `Business area`）随后会共用同一个位置。

要通过文件提供分部层次结构，请选择**分部值**数据集：

| 列 | 内容 |
|---|---|
| `segment` | 该值所属的分部：`segment_1` 至 `segment_10`。 |
| `segment_value` | 该值，与总账、销售和预算行中所带的一致。 |
| `segment_value_name` | 其名称。 |
| `parent_segment_value` | 其在同一分部内的父级。 |

## 就绪状态检查

每次加载后，**就绪状态**网格会按每个实体和期间列出每项检查，状态为以下之一：

| 状态 | 含义 |
|---|---|
| **● 就绪** | 检查通过。 |
| **▲ 需要关注** | 值得查看，但数字可以使用。 |
| **■ 问题** | 在依赖结果之前请先修复。 |
| **– 不适用** | 此项检查暂无数据。 |

检查项如下：

| 检查 | 确认内容 |
|---|---|
| **数据已加载** | 每个会计期间都有总账行，并且每次 ERP 读取都成功。没有行的已结账期间属于问题；没有行的未结账期间需要关注。 |
| **试算平衡表与总账一致** | 每个实体、期间和科目的试算平衡表都与总账相等。当试算平衡表和总账对某个科目都带有部门时，还会逐部门核对。 |
| **销售与总账一致** | 每个期间的销售行都与总账收入和销货成本科目相等。 |
| **未知产品/客户** | 每个销售行所指的产品和客户都存在于产品主数据和客户主数据中。 |
| **科目表中缺失的科目** | 每个总账行所指的科目都在会计科目表中。带有未知科目的行不计入损益表。有过账但没有科目类型的科目也属于问题；某个源的科目表为收入科目指定了类型、却没有销货成本科目，则需要关注。 |
| **货币折算** | 每个总账、试算平衡表、销售、库存和预算行都有以报告货币表示的金额。没有汇率的损益表或销售行属于问题，因为损益表读取的是折算后的金额。没有汇率的资产负债表、库存或预算行需要关注。尚无汇率的预算月份显示为琥珀色，因此请为预算月份加载计划汇率。请参阅[货币折算](#货币折算)。 |
| **未映射的实体** | 每个总账、试算平衡表和销售行所指的实体，都直接或通过实体对照表存在于实体主数据中。在加载实体主数据之前显示为不适用。请参阅[实体对照表](#实体对照表)。 |

有多个源的加载会增加以下检查：

| 检查 | 确认内容 |
|---|---|
| **报告账簿** | 为某个实体带有多个会计账簿的源，已选择其报告账簿。在您选择之前，只有第一个账簿计入。 |
| **等待您回答的代码** | 被多个源使用的每个代码都已得到回答。请参阅[跨源映射代码](#跨源映射代码)。 |
| **来自您的源的额外类别** | 源带有的每个额外类别都已命名或已被排除。 |
| **哪个源覆盖哪些月份** | 除非您选择了哪个源计入，否则不会有两个源提供同一公司的相同月份。 |
| **科目类型与层次结构** | 维度所指定的每个父级都存在，且没有成员是其自身的父级或祖先。缺失的父级会使其子级位于层次结构顶部，循环会使该层次结构无法加载。合计不受影响。 |
| **财务日历** | 每个实体的会计期间都是日历月，并且每个月的行都可以归入某一个会计期间。当某个实体的期间不是日历月（4-4-5、13 个期间），或某个月的行可能属于多个会计期间、或财务日历缺少该月时，需要关注。 |

每个未就绪的行都会在**操作**列中说明该怎么做，例如加载会计科目表、加载汇率，或针对某个期间再次运行**加载**。

网格还会显示两项设置检查，它们仅在需要关注时出现：

| 检查 | 出现时机 |
|---|---|
| **间接费用分摊** | 项目变量 `overhead_department` 和 `overhead_driver` 只设置了其中一个，或没有任何分摊动因与 `overhead_driver` 匹配，导致分摊不会产生任何效果。请同时设置两者，或同时清除两者以关闭间接费用分摊。 |
| **预算对比** | 已加载预算行，但没有任何一行属于项目变量 `budget_version` 所指定的版本，导致预算对比为空。 |

## 管理合并

每次加载都会构建管理合并：集团中每个实体的集团损益表，以报告货币表示，并已抵销公司间交易。它用于管理报告。您的合并系统仍是法定集团的记录；请按下文与其对账。

<Aside type="note">
管理合并仅涵盖损益表。它不是法定或法律意义上的合并，没有合并资产负债表、折算调整、商誉或少数股东权益。
</Aside>

### 选择集团

在**源**下，打开**分组**可查看集团中的公司。您清除勾选的公司仍会单独出现在报表中，但不计入集团合计。点击 **Save group**。更改将在下次**加载**或 **Apply changes** 时生效。新增的公司默认属于集团，直到您清除勾选。

集团的财年从项目变量 `group_fy_start_month` 设置的月份开始，除非您更改，否则为 `1`。

### 您将获得什么

| 表 | 内容 |
|---|---|
| **集团损益表** | 每个实体、期间和行项目（收入、销货成本、运营费用、营业外、公司间差异）一行，以报告货币表示。收入和成本保持其自然符号。 |
| **集团损益表（年初至今）** | 相同内容，为年初至今，截至集团最后一个完整加载的期间。 |
| **公司间配对** | 每对实体、集团和期间一行，包含每一方的金额和残差。 |
| **公司间明细行** | 集团数字或某个配对背后的总账行，及交易伙伴。 |
| **对账** | 集团损益表年初至今与您的合并系统的对比。 |

这些表中会出现三个实体名称：

| 实体 | 含义 |
|---|---|
| **抵销** | 公司间抵销。它们合计为零，因此在集团数字中保留它们，而在计算抵销前的实体之和时将其筛选掉。 |
| **集团总计** | 对账中合并系统的总计。 |
| **未映射** | 没有期间的行，以及您的合并系统中存在、而本项目没有的科目或实体。 |

指标 **Consolidated income**、**Consolidated result** 和 **IC difference**，以及每个表对应的分析路径，可用于回答有关集团的问题。

### 公司间抵销

公司间行按交易伙伴匹配。使用行上的伙伴；当行上没有伙伴时，使用其客户的伙伴。配对的双方都会被抵销，双方不一致的金额会计入公司间差异行。每个配对都有一个原因：

| 原因 | 含义 |
|---|---|
| **已匹配** | 双方入账的金额相同。 |
| **仅一方入账** | 一个实体记录了该交易，而其伙伴没有。 |
| **未抵销** | 配对中的某一行没有汇率，因此双方都不抵销。 |

配对按其年初至今的数据判断。当某个配对的差异超过项目变量 `group_amber`（默认 `1`）时，**Intercompany balances** 行变为琥珀色，超过 `group_red`（默认 `1000`）时变为红色。没有伙伴或伙伴不是实体的行不会被抵销，并计入该行。若某个源带有伙伴而另一个源没有，则显示琥珀色。

源自身的抵销实体不计入集团损益表，**合并**行会对此作出说明。

### 与合并系统对账

将合并系统报告的结果作为文件添加，并在确认其映射时勾选 **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)**。用系统的名称回答 **Which version of the numbers is this?**。**对账**表随后会按每个实体和行项目显示年初至今的**我方**、**已报告**和**差异**。差异通常可以在**抵销**、**集团总计**和**未映射**行上，或由该系统使用的汇率来解释。**Reconciliation to the source** 行会列出所有超过 `group_amber` 的行项目。

### 谁能看到

集团结果遵循项目的行访问权限。当行访问权限使集团结果无法生成时，状态显示为琥珀色。只能看到部分实体的人，会看到这些实体在抵销前的合计。**抵销**行和公司间的表需要有权访问每个实体。

如果项目按集团表中没有的列（例如部门）限制谁能看到哪些行，则对所有人都关闭集团结果，并且**合并**会显示 **Group views are off**。此时只有架构师才能在**分组**下勾选 **Everyone on the project may see the group results**。更改将在下次**加载**或 **Apply changes** 时生效。

## 保持最新

当来自 ERP 连接的加载顺利成功且没有问题后，**上次加载**卡片上会出现**每晚刷新**。点击它，即可在您所在时区每晚 2:00 运行**加载**。卡片随后会显示 **Nightly refresh: Every night at 2:00** 以及设置者。

每晚的加载以设置者的身份运行。如果该用户无法再使用 ERP 连接，网格会提示已跳过每晚加载；请重新设置。仅包含示例数据的项目无法设置计划。

每晚加载时缺失或为空的文件会以指出路径的警告结束，而不是错误，其余模型仍会加载。

## 业务名称

**基础数据**选项卡上的**业务名称**为模型中的代码赋予您的业务所使用的名称。报表、指标和助手会显示这些名称，保存的名称立即生效。之后的加载会保留它。

1. 点击 **Add a name** 并选择**类型**：**类别**、**损益表行**、**指标**或**列**。
2. 输入**代码**：类别为 `segment_1` 至 `segment_10`，损益表行为该行的键，指标为指标的名称，列为 `table.column`。
3. 输入**名称**，单行最多 60 个字符。
4. 点击 **Save names**。

保存会替换整个列表。名称为空的行会移除该名称，**移除所选项**会移除您勾选的行。对同一个代码重复命名会被拒绝。业务名称还会写入分析路径的描述，使助手使用您的用词，而该描述有长度限制：如果某个名称会使其过长，则不会保存任何内容，并会通知您。

## 解释数字

**Explain this number** 显示构成某个损益表数字的内容。在**就绪状态**网格上，某个实体和月份对应的行带有 **Explain this number**，它会打开该实体当月的营业利润率。该窗口将数字拆分为各个层，合计为顶部的总数：

| 层 | 内容 |
|---|---|
| **From the general ledger** | 总账过账到该行的金额。 |
| **Allocated in** | 按您的[分摊规则](#分摊规则)分摊到此实体的成本。 |
| **Allocated out** | 此实体分摊给其他实体的成本。 |
| **Eliminated in the group** | 在集团结果中被抵销的公司间交易。 |

每一层都有一句说明其含义的话，以及其最大的来源单据，包括其来源系统、单据和科目。只显示有行的层。该窗口遵循您的行访问权限：您只能解释自己能看到的数字。背后没有任何内容的数字会显示 **Nothing to explain**。

## 分摊规则

分摊用于将共享成本（例如间接费用）分摊到部门、产品和客户。模型有两个阶段：**Stage 1: overhead to departments** 和 **Stage 2: departments to products and customers**。打开 **操作 > 分摊...** 可查看或更改每个阶段的处理方式。不做更改时，它们的工作方式与向导出现之前相同。只读用户可以打开规则，但无法保存。

对于每个阶段，向导会提出四个问题：

| 步骤 | 问题 | 选项 |
|---|---|---|
| **池** | 您想分摊哪些成本？ | 科目的种类；对于阶段 1，还有保存该成本的部门，或 **All departments**。 |
| **驱动** | 您想按什么来分摊？ | 作为分摊动因加载的 **Statistic**（例如人数或平方英尺）、**Net sales amount**、**Sales quantity** 或 **Spread evenly**。使用 **Same period** 或 **Same period last year** 的动因。 |
| **目标** | 分摊到哪里？ | 阶段 1：部门。阶段 2：产品、客户或两者。 |
| **方法** | 动因为负数时怎么办？ | **Ignore negative values** 或 **Stop and tell me**。 |

在这些步骤下方，针对某个月（写作年和月，例如 `2026-09`）的 **Preview for** 会显示规则（包括您尚未保存的规则）将产生的效果：`Pool 120,000 · Allocated 120,000 · Unallocated 0`。任何未分摊的部分，都是没有动因可承接的成本。预览遵循您的行访问权限。

点击**保存**。规则将在下次**加载**时生效，或在您点击 **Apply changes** 时生效。如果您手动编辑过某个分摊步骤，您的编辑会被保留而不会被覆盖，并且保存时会指出该步骤。加载运行期间无法保存。

## 董事会报告包

董事会报告包会按计划将您的结果写入文档账户中的文件夹，可随时发送。打开 **操作 > Board pack...**，选择**文档账户**和**文件夹**（例如 `/board-packs`），然后点击**保存**。每次运行会写入：

- 一个 Excel 工作簿 `Board pack.xlsx`，包含按实体划分的损益表、利润率桥，以及排名靠前和靠后的客户。
- 损益表仪表板的 PDF。

如果项目还没有仪表板，则仅写入工作簿，并且运行会告诉您原因。点击 **Run now** 可立即生成一份；完成后其文件会出现在该文件夹中。卡片会显示上次运行及其结果，以及下次运行。设置每晚刷新后，该包会随每晚刷新一起运行。只有能够更改项目的人才能设置它。

## 还原点

在每次加载之前，以及每次更改映射或源之前，都会创建一个还原点。它保存模型的表、维度，以及下次加载所基于的设置：您的源、文件和分摊规则。系统会保留近期的还原点；较早的会滚动淘汰，且编辑绝不会挤掉加载前创建的还原点。

要回退，请打开 **操作 > 还原...**，选择一个还原点，然后点击**还原**。一旦存在还原点，就会提供**还原**。还原会将表、维度和这些设置恢复到原来的状态，下次加载将基于它们构建。没有已保存副本的表，或无法保存历史的引擎，会在警告中指出，其余部分仍会还原。已滚动淘汰的还原点会被拒绝，并且加载运行期间无法还原。

## 克隆项目

**操作 > 克隆...** 会以您指定的名称复制项目。副本保留模板、您对模型的编辑、您的指标和分析路径，并加载示例数据。其源未连接，因此请在加载之前在副本中连接它们。复制期间您可以继续工作，复制完成后，**打开项目**会带您前往。

## 另存为我的模板

保存项目的设置，以便为下一个客户或实体重用。打开 **操作 > Save as my template...**，选择文档账户，并为文件命名。如果您省略了扩展名，系统会添加以 `.zip` 结尾的名称。覆盖已有文件会被拒绝，因此请选择其他名称。

该文件包含项目的结构、您对模型的编辑、指标和分析路径、实体和科目的业务名称，以及模板配置表的行，例如 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/) 的活动映射或 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/) 的政策区间。它不包括连接、文件、每晚计划、运行记录、还原点、董事会报告包以及谁有访问权限。

要使用它，请创建项目，在**起始来源**下选择 **From a template file...**，并指定文档账户和路径。新项目仅对您私有，所有源都等待连接。模板之后的版本发布会围绕您编辑过的步骤合并其更改。如果该路径下没有文件，则不会创建任何内容，并会通知您。任何可以读取该文档账户的人都可以从该文件安装。若要在另一个工作区中使用，请下载该文件并在那里上传。

## 使用 Ask 解决未决问题

加载之后，项目可能仍在等待您告知三件事：科目表中未指定类型的科目、被多个源使用的代码，以及您的文件中未匹配任何内容的列。请让助手来解决它们：在通过 MCP 使用的 AI 助手中，使用 **Resolve Data Foundation residue** 提示词。它会读取待处理内容，并为每个项目提出一个答案及理由。

助手不会写入任何内容。您可以在您本来会自行回答的地方应用其答案：科目和代码在**等待您回答的代码**下，文件列则在文件的映射中。它从不提出实体建议。

## 移交项目

在**查看您的层级结构**之后，**设置**清单还有四个收尾事项：

- 一旦开启**每晚刷新**，**设置每晚刷新**即完成。
- 一旦除设置项目的人之外还有其他人成为成员，**与团队共享**即完成。
- 在最近一次成功加载之后下载证据包，**下载证据包**即完成。
- 一旦存在除设置者之外的架构师，并且合计一致，**将项目移交给其所有者**即完成。在未完成时，清单会说明该做什么：将客户的所有者设为此项目的架构师，然后将自己从其成员中移除。

清单会说明是谁设置了该项目（**Set up by**）。

## 使用模板在模型之上构建

模板在 Common Finance Model 之上构建其报表和模型，因此无论为其提供数据的是哪些 ERP，它们的工作方式都相同。当您从模板（例如 Enterprise Profitability）启动项目时，它会创建：

- [Common Finance Model 表](#common-finance-model-表)，为空或填充示例数据。
- 根据这些表构建的**实体**、**科目**、**部门**、**客户**、**产品**、**分部 1** 和**分部 2**维度。请参阅[层次结构](#层次结构)。
- **加载**工作流，以及它运行的用于读取您的 ERP 和文件、整合它们、检查就绪状态并构建模板模型的工作流。
- 模板自己的报表和模型。**Enterprise Profitability** 增加了一张损益表，包含收入、销货成本、毛利、直接和间接运营费用、贡献和营业利润率，以及同比和对比预算的利润率桥。
- 用于就结果提问的指标和分析路径。

**起始来源**下有三个可用模板，每个都构建在同一个模型之上：

| 模板 | 增加的内容 |
|---|---|
| **Enterprise Profitability** | 损益表和利润率桥。 |
| **Cost to Serve** | 服务每个客户的成本，以及扣除成本后的利润。请参阅 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/)。 |
| **Operational Transfer Pricing** | 每个实体的利润水平与您的政策区间的对比，以及补差。请参阅 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)。 |

**From a template file...** 从您保存的项目启动。请参阅[另存为我的模板](#另存为我的模板)。

若要在连接自己的 ERP 之前先行探索，请在创建项目时勾选**从示例数据开始**。项目会立即运行首次加载，因此**基础数据**选项卡会显示一个完整的示例，其中包括一个折算为美元的欧元实体。当您连接自己的 ERP 或添加自己的文件时，示例行会被清除，由您的数据取而代之。

## 基础数据选项卡

**基础数据**选项卡是您连接、加载和检查数据的地方。它自上而下包含以下部分：

| 部分 | 显示内容 |
|---|---|
| **上次加载** | 上次加载是成功、失败还是仍在运行，以及**加载**、**Apply changes**、**刷新**和**每晚刷新**按钮。 |
| **后续操作** | 需要您关注的内容，按重要性从高到低排列，每项带有**审核**或 **Choose which source counts from when** 按钮。 |
| **源** | 按顺序列出的每个源，带有**高级**、**Remove this source**、**分组**和 **Rename extra categories**。 |
| **设置** | 设置清单：**连接您的数据**、**加载您的数据**、**检查合计是否一致**、**查看您的层级结构**、**设置每晚刷新**、**与团队共享**、**下载证据包**和**将项目移交给其所有者**。当前事项以粗体显示。 |
| **业务名称** | 您的业务为类别、损益表行、指标和列使用的名称。请参阅[业务名称](#业务名称)。 |
| **文件** | 您添加的每个文件、其数据集（例如**总账**或**汇率**），以及其映射是 **✓ 已确认** 还是 **○ 等待确认**。 |
| **数据已加载** | 对于每个实体，已加载的第一个和最后一个期间，以及有多少个期间已就绪。 |
| **期间** | 每个实体的会计期间，以及每个期间是 **✓ 已关闭** 还是 **○ 未结账**。 |
| **就绪状态** | 就绪状态网格：每个实体、期间和检查一行，带有其状态和**操作**。 |
| 连接 | 连接您的 ERP，选择实体以及要加载多少个月的历史，或添加另一个源。 |
| **文件**（添加） | 添加 CSV、TSV、TXT、Excel 或 Parquet 文件，并确认其列如何映射。 |
| **加载** | 开始加载。**Apply changes** 运行一次但不从 ERP 拉取数据。 |

加载运行期间，选项卡会自动刷新。

设置清单会跟踪您的进度：

- 一旦附加了源且加载成功，**连接您的数据**和**加载您的数据**会自动勾选。
- 当核对检查通过时，**检查合计是否一致**会自动勾选。
- **查看您的层级结构**：点击**打开维度**以查看实体、科目和部门的层次结构，然后勾选**我已查看**。这一项由您自行确认。
- **设置每晚刷新**、**与团队共享**、**下载证据包**和**将项目移交给其所有者**为清单收尾。请参阅[移交项目](#移交项目)和[管理项目访问](/zh-cn/guides/projects/managing-projects/#管理项目访问)。

**操作**菜单包含**分摊...**、**Board pack...**、**克隆...**、**还原...** 和 **Save as my template...**。请参阅[分摊规则](#分摊规则)、[董事会报告包](#董事会报告包)、[克隆项目](#克隆项目)、[还原点](#还原点)和[另存为我的模板](#另存为我的模板)。

## Common Finance Model 表

Data Foundation 将每个源（ERP 或文件）整合到相同的十五张表中，因此基于这些表构建的报表、指标和模型无论数据来源如何，工作方式都相同。每一行还会记录其来源系统以及读取时间。**数据集**列是您添加文件时选择的名称。

| 数据集 | 表 | 内容 |
|---|---|---|
| 实体 | `cfm_entity` | 法人实体，含父级、本位币和集团货币以及国家。 |
| 实体对照表 | `cfm_entity_map` | 源实体代码及其所属的实体。请参阅[实体对照表](#实体对照表)。 |
| 汇率 | `cfm_fx_rate` | 按货币对的月度平均、期末和历史汇率。请参阅[汇率](#汇率)。 |
| 财务日历 | `cfm_fiscal_calendar` | 每个实体的会计期间一行，含起止日期以及是否已结账。 |
| 会计科目表 | `cfm_account` | 科目，含父级、类型（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、报表、正常余额方向和汇率类型。 |
| 部门 | `cfm_department` | 部门和成本中心，含父级和利润中心。 |
| 产品 | `cfm_product` | 产品主数据，含父级、产品系列、产品组、计量单位和标准成本。 |
| 客户 | `cfm_customer` | 客户主数据，含父级、客户组、区域和国家。客户名称不会被遮盖。 |
| 分部值 | `cfm_segment` | 分部值，含名称和父级。请参阅[层次结构](#层次结构)。 |
| 总账 | `cfm_gl_journal` | 以交易货币、本位币和报告货币表示的日记账行。 |
| 试算平衡表 | `cfm_trial_balance` | 按实体、科目和部门划分的期间借方、贷方和净额，以本位币和报告货币表示。 |
| 销售明细行 | `cfm_sales_line` | 已开票的销售明细行，含数量、毛额、折扣、净额和销货成本金额。 |
| 库存余额 | `cfm_inventory_balance` | 按产品和仓库划分的期末库存。 |
| 预算 | `cfm_budget` | 按方案、版本、科目和部门划分的预算和预测。 |
| 分摊动因 | `cfm_stat_driver` | 统计动因，例如人数、平方英尺或件数。 |

期间写作 `YYYY-MM`，交易按过账期间归属。预算是可选的：没有预算的 ERP 仍会加载其他所有内容。

试算平衡表文件可以带有借方和贷方列、净额列，或两者都有。仅有借方和贷方时，净额为借方减贷方，空白的一侧按零计。仅有净额时，正的净额成为借方，负的净额成为贷方，并以正数表示。部门列是可选的。

## 故障排除

| 症状 | 处理方法 |
|---|---|
| **测试连接**提示 ERP 拒绝了凭据 | 检查连接的凭据，以及集成用户是否可以登录 ERP。 |
| **测试连接**对某个数据集显示**缺少权限** | 请 ERP 管理员添加其指出的权限。您的 ERP 的[连接指南](/zh-cn/guides/connections/)列出了连接所需的内容。 |
| ERP 错误消息比 ERP 自身的更短 | PlaidCloud 在显示提供商错误之前会移除其中的凭据、令牌和密钥，因此会省略一些细节。运行**测试连接**以查看哪个数据集受到影响。 |
| 某个期间的**数据已加载**为问题 | 该期间的 ERP 读取失败。再次运行**加载**；已加载的期间会被跳过。 |
| **科目表中缺失的科目**为问题 | 将缺失的科目添加到 ERP 或您的文件中的会计科目表，然后再次运行**加载**。 |
| **货币折算**为问题 | 某个实体的货币在该期间没有折算为报告货币的汇率，或未找到唯一的报告货币。请将汇率添加到**汇率**文件中，检查连接能否读取 ERP 的汇率，或设置项目变量 `reporting_currency`。然后再次运行**加载**。 |
| **货币折算**需要关注 | 资产负债表、库存或预算行在该期间没有期末、历史或计划汇率。损益表不受影响。请添加汇率（包括预算月份的计划汇率），然后再次运行**加载**。 |
| **等待您回答的代码**需要关注 | 点击**审核**，回答每个代码，然后点击 **Apply changes**。 |
| **哪个源覆盖哪些月份**需要关注 | 点击 **Choose which source counts from when**，选择源，然后点击 **Apply changes**。 |
| **Intercompany balances** 为红色或琥珀色 | 检查**公司间配对**中的配对。记录缺失的一方，为行添加交易伙伴，或添加缺失的汇率。 |
| **Group views are off** | 请架构师在**分组**下勾选 **Everyone on the project may see the group results**。 |
| **未映射的实体**为问题 | 将该实体添加到实体主数据，或在**实体对照表**文件中将其代码映射到现有实体，然后再次运行**加载**。 |
