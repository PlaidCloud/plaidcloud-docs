**Data Foundation** 是 PlaidCloud 项目的财务数据基础。其 **Common Finance Model** 将来自多个 ERP 系统（以及每个系统的多个实例）的 ERP 数据汇集到同一个模型中：一套会计科目表、一套实体和一种报告货币。基于该模型构建的报表、指标和 AI 助手读取的都是同样的数字，无论数据来自哪个 ERP。

ERP 通过其 PlaidCloud 连接接入，因此总账、试算平衡表、主数据和预算直接从源系统到达，无需导出。文件用于补充系统中没有的数据，例如汇率、分摊动因或保存在 ERP 之外的预算，并且可以替换其所覆盖的 ERP 行。**加载** 会将每个数据源整合到模型中，折算为报告货币，并检查数据是否一致，这一切都在项目的 **基础数据** 选项卡中完成。当多个数据源对不同事物使用相同的编码时，由您确认它们是否含义相同，随后管理合并会生成已抵销公司间交易的集团损益表。模板（例如 **Enterprise Profitability**）在此基础上构建各自的报表和模型。

## 连接 ERP

ERP 通过其 PlaidCloud 连接接入 Data Foundation。Data Foundation 直接从中读取总账、试算平衡表、主数据、汇率和预算，并且只读取。可以选择现有连接，也可以在选项卡中创建连接；各 ERP 的访问设置请参阅[连接指南](/zh-cn/guides/connections/)。

<Steps>

1. 在 Analyze 中，打开 **项目** 并点击 **新建项目**。输入名称，然后在 **起始来源** 下选择一个模板（例如 **企业盈利能力(模板)**），而不是 **空白项目**。点击 **创建**。

   项目会在其 **基础数据** 选项卡中打开。在您共享之前，该项目为您私有，并且您是它唯一的架构师。

2. 在 **基础数据** 选项卡上，为 ERP 选择现有连接，或选择 **创建新连接**。每个现有连接都会列出已在使用它的工作流，或显示 **暂无工作流使用**。

3. 对于新连接，输入 **连接名称**，选择 **环境**，并填写 ERP 连接要求的凭据。

   还没有凭据？表单会为您的 ERP 管理员显示一份现成的访问请求。点击 **复制请求** 或 **通过电子邮件发送请求**，将其发送出去，然后输入对方返回的值。

4. 点击 **测试连接**。PlaidCloud 会登录并尝试读取每个数据集，然后将每个数据集列为 **可读取**、**缺少权限** 或 **错误**。如有缺失，会列出需要请 ERP 管理员添加的权限。

5. 设置 **历史月数**：向前加载多少个月，范围为 1 到 120。默认为 24。

6. 对于现有连接，勾选要加载的实体，或全部不勾选以加载所有实体。未启用的实体和抵销实体默认隐藏，直到您选择显示。然后点击 **连接**。

7. 对于新连接，点击 **连接** 创建它。然后勾选要加载的实体，再次点击 **连接** 保存。在此之前，将加载所有实体。

8. 要接入另一个 ERP 系统或另一个实例，请重复上述步骤，并在点击 **连接** 之前勾选 **Add this as another source instead of replacing the current one**。否则，新连接会替换当前数据源。

</Steps>

连接完成后，卡片会显示项目加载所使用的连接、环境、实体和历史月数。

每次加载只读取发生变化的内容：未结账期间和最近一个已结账期间会重新读取，已加载的已结账期间则保持不变。增加 **历史月数** 只会读取新增的月份。汇率、实体对照表或报告货币发生变化时，会重新读取受其影响的月份。

## 数据源

项目所加载的每个 ERP 系统和实例都是一个数据源。**基础数据** 选项卡上的 **源** 列表按顺序为每个数据源显示一行，包含其名称、上次加载时间、提供的行数以及所读取的报告账簿，例如 `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`。尚未加载的数据源显示 **not loaded yet**。您确认的文件也是数据源。

在数据源上打开 **高级** 可更改其使用方式：

| 设置 | 作用 |
|---|---|
| **名称** | 报表、映射问题和消息中用来称呼该数据源的标签。 |
| **Place in the order** | 数据源的排名。当两个数据源覆盖同一公司的同一个月份时，排序靠前的数据源优先。 |
| **Reporting books, separated by commas** | 要读取的会计账簿，适用于保存多个账簿的系统。**All reporting books** 会读取所有账簿。 |
| **公司**、**从 (2026-01)** 和 **至 (2026-12)** | 该数据源为每家公司提供的月份。月份留空表示不限制。月份写作年和月，例如 `2026-03`。 |

点击 **保存** 保留更改。要移除数据源，点击 **Remove this source** 并确认 **移除**。从该数据源加载的所有内容都会被删除，之后可以再次连接。

更改数据源不会重新读取 ERP。**上次加载** 卡片会显示 **Changes not applied yet**，直到点击 **Apply changes**。它会基于已拉取的数据运行一次加载：按新的顺序、映射、名称和文件重新整合各数据源，并重建模型。如果还需要从 ERP 获取最新数据，请点击 **加载**。

## 添加 ERP 之外数据的文件

文件用于补充 ERP 连接中没有的数据，例如汇率、分摊动因、[实体对照表](#实体对照表)或保存在 ERP 之外的预算。每个文件属于[Common Finance Model 表](#common-finance-model-表)下列出的某个数据集。

<Steps>

1. 在 **文件** 下，选择用于存放文件的 **文档账户**。

2. 将 CSV 或 Excel 文件拖放到 **将 CSV 或 Excel 文件拖放到此处**，或点击 **选择文件**。文件会上传到文档账户的 `/foundation/` 文件夹。

   对于已在文档账户中的文件，输入其 **文件路径**（例如 `/foundation/budget.csv`），然后点击 **添加文件**。

   若要每月读取新文件，可添加名称匹配的文件夹中的所有文件：输入文件夹，以及 **File names that** 包含、以其开头、以其结尾、完全匹配或按模式匹配的条件，然后点击 **Add files**。其中子文件夹内的文件不会被读取。

3. PlaidCloud 读取文件并提出映射建议：

   - **自动检测分隔符、小数分隔符和日期。** 分隔符（逗号、分号、制表符或竖线）、小数分隔符和日期格式都会自动检测。
   - **数据集**：文件所属的 Common Finance Model 表，根据文件名和列标题匹配。匹配不明确时，从列表中选择。
   - **小数分隔符**：**句点(1,234.56)** 或 **逗号(1.234,56)**。
   - **日期格式**：文件包含日期时显示。如果检测到的格式有误，请更改：`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY` 或 `MM/DD/YYYY`。
   - 由 **文件中的列**、**类型**、**示例** 和 **去向** 组成的网格。更改 **去向** 可将某一列发送到其他字段，或设为 **不加载**。

4. 回答文件引出的问题，例如 **Which company is this file for?**、**Which currency are the amounts in?**、**Are these amounts year-to-date or for the month?**、**Are the amounts shown in thousands or millions?** 或 **Are revenues shown as negative numbers?**。每个问题仅在文件本身未给出答案时才会询问。

5. 检查每一列的去向，然后点击 **确认映射**。

</Steps>

文件适用时会显示以下选项：

| 选项 | 用途 |
|---|---|
| **Which source do these rows apply to?** | 将编码映射文件限定于某一个数据源。**Every source** 会将其应用于所有数据源。 |
| **Where does this file come from?** | 说明文件包含的是 **This project's own codes**，还是来自 **Another system**（需填写其名称，例如 `SAP Germany export`）。来自其他系统的文件会像 ERP 数据源一样检查共享编码。 |
| **Split … into … parts at each …**（位于 **高级** 下） | 拆分包含多个值的单列（例如 `100-200-300`），并将每个部分发送到各自的字段。 |
| **Which currency do you report in?** | 在项目尚无报告货币时设置报告货币。写作三个字母，例如 `USD`。 |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 加载合并系统的结果，以便[对账](#与合并系统对账)集团损益表。 |

要将文件从项目中移除，请点击 **文件** 下该文件旁的 **移除**，或点击其映射中的 **Remove this file**，然后确认。下次点击 **Apply changes** 时，其数据会从报表中消失。

当 PlaidCloud 无法自行确定数据集、小数分隔符或日期顺序时（例如文件中的日期既可能是日/月，也可能是月/日），会在您确认之前请您选择。为同一数据集再添加第二个文件会替换第一个。

支持的文件包括 CSV、TSV 和 TXT 文本文件、Excel `.xlsx` 文件（读取第一个工作表）以及 Parquet 文件。

<Aside type="note">
缺失或为空的文件绝不会中止加载。添加此类文件时会提示暂无可映射的内容，加载则会以一条指明路径的警告结束，并使该数据集保持为空。文件存在后，再次添加即可。
</Aside>

## 加载数据

点击 **加载** 卡片或 **上次加载** 卡片上的 **加载**。加载会读取已连接的 ERP 和已确认的文件，将它们整合到 Common Finance Model 中，折算为报告货币，运行就绪状态检查，并重建模板的模型。

- 一个项目同一时间只能运行一次加载。第二次 **加载** 或 **Apply changes** 会提示已有加载正在运行，并且加载运行期间无法更改数据源。
- 如果其他工作流使用同一个 ERP 连接，首次加载会列出这些工作流并请您确认，因为加载会从 ERP 读取数据，可能会使这些工作流变慢。点击 **仍然加载** 继续。
- 失败的加载显示为红色，绝不会被之前的结果掩盖。在加载成功之前，来自较早加载的行会显示 **来自较早的加载。请重新加载。**
- 如果某个实体和期间读取失败，其余部分仍会加载。再次运行 **加载** 即可只获取失败的部分。

### 被保留的行

当数据源重叠时，加载只保留每个数字的一份副本，其余的则被保留不计，以免重复计算。被保留的行会连同其数据源、实体和原因一并记录，加载结束时会给出一条列出数量的警告，例如 `120 rows of NetSuite EU also provided by a source ranked ahead`。原因如下：

| 原因 | 含义 |
|---|---|
| In another accounting book | 该行属于数据源未设置读取的报告账簿。 |
| Outside the periods the source provides | 该行超出为该公司设置的 **从** 和 **至** 月份范围。 |
| Also provided by a source ranked ahead | 排序更靠前的数据源覆盖了同一公司和月份。 |
| Also in an earlier file of the source | 同一数据源的较早文件已覆盖该月份。 |
| Replaced by a file | 文件替换了该实体和月份的 ERP 行。 |
| Carrying a code another source also uses | 该编码需要您作出回答。请参阅[跨数据源映射编码](#跨数据源映射编码)。 |
| Carrying a code mapped to two codes | 编码映射给该编码提供了两个答案。 |

统计科目会转入分摊动因而不是总账，并显示为已转移，而不是问题。

### ERP 数据与文件并用

文件只替换其所覆盖的内容，ERP 的其他行保持不变。

- **主数据文件**（科目、部门、客户、产品和分部值）会替换编码相同的 ERP 行。
- **交易文件** 会替换同一实体和月份的 ERP 行。总账和试算平衡表文件还按账簿匹配，预算文件按方案匹配，统计动因文件按方案和动因匹配。

如果某个文件之后不再覆盖某个月份，该月份的 ERP 数据会在下次加载时恢复。

## 实体对照表

每个数据源都使用各自的编码来命名实体。**实体对照表** 将这些编码映射到实体主数据中的实体，使所有数据源的行落在同一个实体上。

要使用它，请添加 CSV 或 Excel 文件并选择 **实体对照表** 数据集：

| 列 | 内容 |
|---|---|
| `source_entity` | 数据源中携带的编码，例如公司代码。 |
| `entity` | 它所属的实体，以实体主数据中的名称为准。 |

- 对照表中没有的编码按原样使用。
- 多个编码可以映射到同一个实体。它们的行会合并，并且只有当所有这些编码对应的月份都已结账时，该月份才算已结账。
- 对照表中的编码适用于所有数据源，因此每个数据源的实体编码在各数据源之间必须唯一。
- **实体** 文件中的一行会替换实体编码相同的 ERP 实体。

**未映射的实体** 检查会标出实体既不在实体主数据中、也未通过对照表映射到实体主数据的任何行。在加载实体主数据之前，它显示 **– 不适用**。

## 跨数据源映射编码

两个数据源可能对不同事物使用相同的编码，也可能对同一事物使用不同的编码。当某个编码出现在多个数据源中时，Data Foundation 会保留其行，直到您说明它在各处是否含义相同，从而使每个金额只计算一次。**Codes waiting for your answer** 检查会列出这些编码，并且 **基础数据** 选项卡上的 **What to do next** 卡片带有 **审核** 按钮。

**审核** 会打开 **Codes waiting for your answer**。它按编码类别分组：**账户类型**、**公司**、**账户**、**部门**、**利润中心**、**客户**、**产品** 以及每个额外类别。对于每个编码，它会显示各数据源对它的称呼以及一条建议：

- 当各数据源为该编码给出相同名称时，显示 **Looks like the same thing**。
- 当名称不同时，显示 **Looks like different things**。
- 当没有任何依据时，显示 **We can't tell. Please answer.**。

可以逐个编码回答 **Yes, the same** 或 **No, different**，也可以通过 **Accept all**（采纳所有建议）、**All the same** 或 **All different** 一次回答整个分组。对于科目，还可以一次回答会计科目表中的整个父级分组。如果某个数据源没有科目类型，可为一组科目选择 **Use this type**：**Revenue**、**Cost of goods sold**、**Operating expenses**、**Non-operating income and expenses**、**Assets**、**Liabilities** 或 **Equity**。

映射按数据源和维度分别保存，因此对某个数据源部门的回答绝不会改变另一个数据源的科目。回答会随时保存，并提示 **Saved. Press Apply changes to use your answers.** 点击 **Apply changes** 即可使用。

也可以通过文件提供映射。添加数据集为 **Code map** 的文件，并通过 **Which source do these rows apply to?** 将其限定于某一个数据源。

## 选择从何时起采用哪个数据源

当两个数据源提供相同的月份时，**Which source covers which months** 检查会请您作出选择。点击 **What to do next** 卡片中的 **Choose which source counts from when**，打开 **Which source counts from when**，其中按公司列出每处重叠。选择采用的数据源，在 **That month is** 中输入从哪个月起采用（例如 `2026-04`），然后点击 **Apply changes**。另一个数据源保留更早的月份。

当两个数据源为某种货币给出不同汇率时，同一对话框也会发出警告；此时使用排序更靠前的数据源的汇率。

## 货币折算

每次加载都会将总账、试算平衡表、销售、库存和预算金额从本位币折算为一种报告货币。报表和模型读取折算后的金额，因此来自任何系统、使用不同货币的实体都能正确汇总。

### 报告货币

要选择报告货币，请将项目变量 `reporting_currency` 设置为货币代码，例如 `USD`。请参阅[管理项目变量](/zh-cn/guides/projects/managing-projects/#管理项目变量)。模板会将其创建为空。在其为空时，每次加载会使用以下第一个恰好指向一种货币的来源：

1. 实体的集团货币。
2. 顶级实体（没有父级的实体）的本位币。
3. 文件的本位币。

如果以上都不能恰好指向一种货币，**货币折算** 会显示问题，直到您设置 `reporting_currency`。

已经是报告货币的金额保持不变，因此数据全部使用一种货币的项目不需要汇率。

销售、库存和预算文件也可以携带货币。映射名为 `Currency` 或 `Local Currency` 的列后会自动识别，文件中的本位币金额会折算为报告货币。文件中已有的集团或报告金额保持原样。产品标准成本不折算。

### 汇率

汇率将一个单位的某种货币按月份折算为报告货币：折算后的金额等于本位币金额乘以汇率。

- **来自 ERP**：每次加载都会读取 ERP 所持有的汇率。
- **来自文件**：添加 CSV 或 Excel 文件并选择 **汇率** 数据集。文件中的汇率会替换 ERP 中相同货币和月份的汇率。如果要以 ERP 未发布汇率的货币进行报告，或为预算月份添加计划汇率，请使用文件。

| 列 | 内容 |
|---|---|
| `from_currency` | 要折算的源货币，例如 `EUR`。 |
| `to_currency` | 报告货币，例如 `USD`。 |
| `period` | 月份，格式为 `YYYY-MM`。 |
| `average_rate` | 当月平均汇率。 |
| `closing_rate` | 月末汇率。 |
| `historical_rate` | 历史汇率，用于权益以及设为历史汇率的科目。 |

只使用折算为报告货币的汇率。反向报价的汇率（即从报告货币折算为其他货币）不会取倒数使用。

### 适用哪种汇率

每一行都按其自身的货币折算，因此与所属实体货币不同的行会按其所用的货币折算。符合该行的第一条规则适用：

| 行 | 汇率 |
|---|---|
| 统计科目和非过账科目 | 不折算。 |
| 已是报告货币 | 不折算。 |
| 设有汇率类型的科目 | 该汇率：平均、期末或历史。没有历史汇率时，历史汇率回退为期末汇率。来自 ERP 时，汇率类型即科目自身的汇率类型。在会计科目表文件中，将汇率类型列映射到 `fx_rate_type`，取值为 `average`、`closing` 或 `historical`。 |
| 销售行 | 该期间的平均汇率。 |
| 库存余额 | 该期间的期末汇率。 |
| 预算行 | 与总账一样按科目：损益科目使用平均汇率，资产负债表科目使用期末汇率。 |
| 损益科目 | 该期间的平均汇率。 |
| 权益科目 | 历史汇率；没有历史汇率时使用期末汇率。 |
| 其他任何资产负债表科目 | 该期间的期末汇率。 |

折算后的金额不做四舍五入，因此合计不会产生偏差。

<Aside type="note">
试算平衡表记录每个期间的发生额，因此资产负债表金额是每个月的发生额按当月期末汇率折算的结果。它们并不是按期末汇率重新折算的资产负债表，也没有累计折算调整或公司间抵销。请将折算后的金额用于损益表。
</Aside>

## 层次结构

每次加载都会根据所有数据源的主数据重建各维度。起初有七个维度，另外最多可有十个额外类别：

| 维度 | 构建来源 |
|---|---|
| **实体** | 实体及其父级 |
| **科目** | 会计科目表和父级科目 |
| **部门** | 部门及其父级 |
| **客户** | 客户及其父级客户 |
| **产品** | 产品及其父级产品 |
| **分部 1** | `segment_1` 的分部值 |
| **分部 2** | `segment_2` 的分部值 |
| **分部 3** 至 **分部 10** | 当数据源携带时，`segment_3` 至 `segment_10` 的分部值 |

- 没有父级或将自身指定为父级的记录，作为顶级成员加载。
- 由于每次加载都会重建层次结构，请在 ERP 或文件中更改父级，而不要在维度中更改。
- 某个层次结构中的问题只影响该维度。加载和模板的模型仍会完成。
- 可以将每个额外类别重命名为其所含内容，例如 **类别** 或 **区域**。在 **Rename extra categories** 下，输入报表所用的名称并点击 **Save names**。名称可使用字母、数字、空格、点、短横线和下划线，最长 60 个字符。
- 每个数据源会说明自己的每个额外类别归入您的哪个类别名称之下。在数据源上打开 **高级**，为每个类别选择名称，或选择 **Leave out**，然后点击 **保存**。这样，对同一类别使用不同称呼的数据源（例如 `Class` 和 `Business area`）就会共用一个位置。

要通过文件提供分部层次结构，请选择 **分部值** 数据集：

| 列 | 内容 |
|---|---|
| `segment` | 该值所属的分部：`segment_1` 至 `segment_10`。 |
| `segment_value` | 值本身，与总账、销售和预算行中携带的值一致。 |
| `segment_value_name` | 其名称。 |
| `parent_segment_value` | 其在同一分部内的父级。 |

## 就绪状态检查

每次加载之后，**就绪状态** 网格会列出每个实体和期间的每项检查，并带有以下状态之一：

| 状态 | 含义 |
|---|---|
| **● 就绪** | 检查已通过。 |
| **▲ 需要关注** | 值得查看，但数字可以使用。 |
| **■ 问题** | 在依赖结果之前请先解决。 |
| **– 不适用** | 此项检查暂无数据。 |

检查项如下：

| 检查 | 确认内容 |
|---|---|
| **数据已加载** | 每个财务期间都有总账行，并且每次 ERP 读取都已成功。没有行的已结账期间是问题；没有行的未结账期间需要关注。 |
| **试算平衡表与总账一致** | 每个实体、期间和科目的试算平衡表都与总账相等。如果某个科目的试算平衡表和总账都带有部门，还会逐个部门核对一致。 |
| **销售与总账一致** | 每个期间的销售行与总账的收入和 COGS 科目相等。 |
| **未知产品/客户** | 每条销售行所指的产品和客户都存在于产品主数据和客户主数据中。 |
| **科目表中缺失的科目** | 每条总账行所指的科目都在会计科目表中。科目未知的行不计入损益表。有记账但没有科目类型的科目同样是问题；科目表为收入科目指定了类型、却没有为销货成本科目指定类型的数据源需要关注。 |
| **货币折算** | 每条总账、试算平衡表、销售、库存和预算行都有以报告货币表示的金额。没有汇率的损益行或销售行是问题，因为损益表读取的是折算后的金额。没有汇率的资产负债表、库存或预算行需要关注。尚无汇率的预算月份显示为琥珀色，因此请为预算月份加载计划汇率。请参阅[货币折算](#货币折算)。 |
| **未映射的实体** | 每条总账、试算平衡表和销售行所指的实体，都直接或通过实体对照表存在于实体主数据中。在加载实体主数据之前不适用。请参阅[实体对照表](#实体对照表)。 |

包含多个数据源的加载会增加以下检查：

| 检查 | 确认内容 |
|---|---|
| **Reporting book** | 为某个实体保存多个会计账簿的数据源，已选定其报告账簿。在您选择之前，只有第一个账簿计入。 |
| **Codes waiting for your answer** | 被多个数据源使用的每个编码都已得到回答。请参阅[跨数据源映射编码](#跨数据源映射编码)。 |
| **Extra categories from your sources** | 数据源携带的每个额外类别都有名称，或已被舍弃。 |
| **Which source covers which months** | 除非您选择了采用哪个，否则没有两个数据源提供同一公司的相同月份。 |
| **Account types and hierarchy** | 维度所指定的每个上级都存在，并且没有成员是其自身的上级或祖先。上级缺失时，其下级显示在层次结构顶层；出现循环则该层次结构无法加载。合计不受影响。 |
| **Fiscal calendar** | 每个实体的财务期间都是日历月，并且某个月的所有行都能归入唯一的财务期间。当实体的期间不是日历月（4-4-5、13 个期间），或某个月的行可能属于多个财务期间，或财务日历缺少该月时，需要关注。 |

每个未就绪的行都会在 **操作** 列中说明该怎么做，例如加载会计科目表、加载汇率，或针对某个期间再次运行 **加载**。

网格还显示两项设置检查，仅在需要关注时出现：

| 检查 | 出现时机 |
|---|---|
| **间接费用分摊** | 项目变量 `overhead_department` 和 `overhead_driver` 只设置了其中一个，或没有任何分摊动因与 `overhead_driver` 匹配，导致分摊不起作用。请同时设置两者，或同时清除两者以关闭间接费用分摊。 |
| **预算对比** | 已加载预算行，但没有任何一行属于项目变量 `budget_version` 所指定的版本，因此预算对比将为空。 |

## 管理合并

每次加载都会构建管理合并：以报告货币表示的、集团内所有实体的集团损益表，并已抵销公司间交易。它用于管理报告。法定集团的记录仍以您的合并系统为准；请按下文与其对账。

<Aside type="note">
管理合并仅涵盖损益表。它不是法定或法律意义上的合并，没有合并资产负债表、折算调整、商誉或少数股东权益。
</Aside>

### 选择集团

在 **源** 下，打开 **分组** 可查看集团内的公司。取消勾选的公司仍会单独出现在报表中，但不计入集团合计。点击 **Save group**。更改在下次 **加载** 或 **Apply changes** 时生效。新公司在您取消勾选之前属于集团。

集团的财务年度从项目变量 `group_fy_start_month` 设置的月份开始，除非更改，否则为 `1`。

### 得到的内容

| 表 | 内容 |
|---|---|
| **Group P&L** | 每个实体、期间和行项目（收入、销货成本、营业费用、非经营性项目、公司间差异）各一行，以报告货币表示。收入和成本保留其自然符号。 |
| **Group P&L year to date** | 同上，为年初至今，截至集团最后一个已完整加载的期间。 |
| **Intercompany pairs** | 每对实体、集团和期间各一行，包含双方的金额和差额。 |
| **Intercompany lines** | 集团数字或某对实体背后的账目行，带有交易伙伴。 |
| **对账** | 年初至今的集团损益表与您的合并系统的对比。 |

这些表中会出现三个实体名称：

| 实体 | 含义 |
|---|---|
| **Eliminations** | 公司间抵销。它们合计为零，因此集团数字中保留它们，而在计算抵销前各实体之和时将其筛选掉。 |
| **Group total** | 对账中合并系统的合计。 |
| **Unmapped** | 没有期间的行，以及合并系统中本项目没有的科目或实体。 |

指标 **Consolidated income**、**Consolidated result** 和 **IC difference**，以及针对每个表的分析路径，可用于回答有关集团的问题。

### 公司间抵销

公司间的行按交易伙伴匹配。使用行上的伙伴；行上没有时，使用其客户的伙伴。一对交易的双方都会被抵销，双方不一致的金额计入一条公司间差异行。每对交易都会得到一个原因：

| 原因 | 含义 |
|---|---|
| **已匹配** | 双方记账金额相同。 |
| **Only one side booked** | 一个实体记录了该交易，而其伙伴没有。 |
| **Not eliminated** | 这对交易中的某一行没有汇率，因此双方都不会被抵销。 |

一对交易按其年初至今来判断。当某对交易的差异超过项目变量 `group_amber`（默认为 `1`）时，**Intercompany balances** 行变为琥珀色；超过 `group_red`（默认为 `1000`）时变为红色。没有伙伴的行，或伙伴不是实体的行，不会被抵销，并计入该行。一个携带伙伴的数据源与一个不携带伙伴的数据源并存时，显示为琥珀色。

数据源自身的抵销实体不计入集团损益表，**合并** 行会说明这一点。

### 与合并系统对账

将合并系统报告的结果作为文件添加，并在确认其映射时勾选 **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)**。用该系统的名称回答 **Which version of the numbers is this?**。**对账** 表随后会按实体和行项目显示年初至今的 **ours**、**reported** 和 **差异**。差异通常可由 **Eliminations**、**Group total** 和 **Unmapped** 行或该系统所用的汇率来解释。**Reconciliation to the source** 行会列出所有超过 `group_amber` 的行。

### 谁能查看

集团结果遵循项目的行访问权限。只能查看部分实体的人员，看到的是这些实体抵销前的合计。**Eliminations** 行和公司间表需要有权访问所有实体。

如果项目按集团表不携带的列（例如部门）限制谁能看到哪些行，集团结果将对所有人保持关闭，**合并** 会显示 **Group views are off**。此时只有架构师可以在 **分组** 下勾选 **Everyone on the project may see the group results**。更改在下次 **加载** 或 **Apply changes** 时生效。

## 保持最新

从 ERP 连接加载成功且没有问题之后，**上次加载** 卡片上会出现 **每晚刷新**。点击它可在每晚您所在时区的 2:00 运行 **加载**。卡片随后会显示 **Nightly refresh: Every night at 2:00** 以及设置者。

每晚加载以设置它的人员身份运行。如果该人员无法再使用 ERP 连接，网格会提示每晚加载被跳过；请重新设置。只有示例数据的项目无法设置计划。

每晚加载时缺失或为空的文件，会以一条指明路径的警告结束，而不是报错，并且模型的其余部分仍会加载。

## 使用模板在模型之上构建

模板在 Common Finance Model 之上构建其报表和模型，因此无论由哪些 ERP 提供数据，它们的工作方式都相同。当基于模板（例如 **Enterprise Profitability**）启动项目时，它会创建：

- [Common Finance Model 表](#common-finance-model-表)，为空或已填充示例数据。
- 基于这些表构建的 **实体**、**科目**、**部门**、**客户**、**产品**、**分部 1** 和 **分部 2** 维度。请参阅[层次结构](#层次结构)。
- **加载** 工作流，以及它所运行的、用于读取 ERP 和文件、整合数据、检查就绪状态并构建模板模型的工作流。
- 模板自身的报表和模型。**Enterprise Profitability** 增加了一个损益表，包含收入、COGS、毛利率、直接和间接营业费用、边际贡献和营业利润率，以及同比和与预算对比的利润桥。
- 用于询问结果相关问题的指标和分析路径。

要在连接自己的 ERP 之前先行探索，请在创建项目时勾选 **从示例数据开始**。项目会立即运行首次加载，因此 **基础数据** 选项卡会显示一个完整的示例，其中包括折算为美元的欧元实体。连接自己的 ERP 或添加自己的文件后，示例行会被清除，由您的数据取而代之。

- **与团队共享**：项目就绪后进行共享。请参阅[管理项目访问](/zh-cn/guides/projects/managing-projects/#管理项目访问)。

## Common Finance Model 表

Data Foundation 将每个数据源（无论是 ERP 还是文件）整合到同样的十五个表中，因此基于这些表构建的报表、指标和模型，无论数据源是什么，工作方式都相同。每一行还会记录其来源系统和读取时间。**数据集** 列是添加文件时要选择的名称。

| 数据集 | 表 | 内容 |
|---|---|---|
| 实体 | `cfm_entity` | 法人实体，包含父级、本位币和集团货币以及国家。 |
| 实体对照表 | `cfm_entity_map` | 数据源的实体编码及其所属的实体。请参阅[实体对照表](#实体对照表)。 |
| 汇率 | `cfm_fx_rate` | 按货币对划分的月度平均、期末和历史汇率。请参阅[汇率](#汇率)。 |
| 财务日历 | `cfm_fiscal_calendar` | 每个实体的每个财务期间一行，包含起止日期以及是否已结账。 |
| 会计科目表 | `cfm_account` | 科目，包含父级、类型（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、报表、正常余额方向和汇率类型。 |
| 部门 | `cfm_department` | 部门和成本中心，包含父级和利润中心。 |
| 产品 | `cfm_product` | 产品主数据，包含父级、系列、分组、计量单位和标准成本。 |
| 客户 | `cfm_customer` | 客户主数据，包含父级、分组、区域和国家。客户名称不做掩码处理。 |
| 分部值 | `cfm_segment` | 分部值，包含名称和父级。请参阅[层次结构](#层次结构)。 |
| 总账 | `cfm_gl_journal` | 以交易货币、本位币和报告货币表示的日记账行。 |
| 试算平衡表 | `cfm_trial_balance` | 按实体、科目和部门划分的期间借方、贷方和净额，以本位币和报告货币表示。 |
| 销售明细行 | `cfm_sales_line` | 已开票的销售行，包含数量、毛额、折扣、净额和 COGS 金额。 |
| 库存余额 | `cfm_inventory_balance` | 按产品和仓库划分的期末库存。 |
| 预算 | `cfm_budget` | 按方案、版本、科目和部门划分的预算和预测。 |
| 分摊动因 | `cfm_stat_driver` | 统计动因，例如人数、平方英尺或件数。 |

期间写作 `YYYY-MM`，交易按过账期间归属。预算是可选的：没有预算的 ERP 仍会加载其他所有内容。

试算平衡表文件可以带有借方和贷方列、净额列，或两者都有。只有借方和贷方时，净额为借方减去贷方，空白的一方按零计。只有净额时，正的净额成为借方，负的净额成为贷方，并以正数表示。部门列是可选的。

## 故障排除

| 现象 | 处理方法 |
|---|---|
| **测试连接** 提示 ERP 拒绝了凭据 | 检查连接的凭据，并确认集成用户可以登录 ERP。 |
| **测试连接** 对某个数据集显示 **缺少权限** | 请 ERP 管理员添加其列出的权限。您所用 ERP 的[连接指南](/zh-cn/guides/connections/)列出了连接所需的权限。 |
| ERP 错误消息比 ERP 自身的消息短 | PlaidCloud 在显示提供商错误之前会移除其中的凭据、令牌和密钥，因此会省略部分细节。运行 **测试连接** 以查看受影响的是哪个数据集。 |
| 某个期间的 **数据已加载** 出现问题 | 该期间的 ERP 读取失败。再次运行 **加载**；已加载的期间会被跳过。 |
| **科目表中缺失的科目** 出现问题 | 在 ERP 或文件中将缺失的科目添加到会计科目表，然后再次运行 **加载**。 |
| **货币折算** 出现问题 | 某个实体的货币在该期间没有折算为报告货币的汇率，或未找到唯一的报告货币。将汇率添加到 **汇率** 文件，检查连接能否读取 ERP 的汇率，或设置项目变量 `reporting_currency`。然后再次运行 **加载**。 |
| **货币折算** 需要关注 | 资产负债表、库存或预算行在该期间没有期末、历史或计划汇率。损益表不受影响。添加汇率（包括预算月份的计划汇率），然后再次运行 **加载**。 |
| **Codes waiting for your answer** 需要关注 | 点击 **审核**，回答每个编码，然后点击 **Apply changes**。 |
| **Which source covers which months** 需要关注 | 点击 **Choose which source counts from when**，选择数据源，然后点击 **Apply changes**。 |
| **Intercompany balances** 为红色或琥珀色 | 检查 **Intercompany pairs** 中的各对交易。补记缺失的一方，在行上添加交易伙伴，或添加缺失的汇率。 |
| **Group views are off** | 请架构师在 **分组** 下勾选 **Everyone on the project may see the group results**。 |
| **未映射的实体** 出现问题 | 将该实体添加到实体主数据，或在 **实体对照表** 文件中将其编码映射到现有实体，然后再次运行 **加载**。 |
