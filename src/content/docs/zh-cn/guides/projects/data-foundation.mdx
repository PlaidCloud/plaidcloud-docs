**Data Foundation** 是 PlaidCloud 项目的财务数据基础。它的 **Common Finance Model** 将来自多个 ERP 系统（以及每个系统的多个实例）的 ERP 数据汇集到一个模型中：一套会计科目表、一组实体和一种报告货币。基于该模型构建的报表、指标和 AI 助手读取的都是同一组数字，无论这些数字来自哪个 ERP。

ERP 通过其 PlaidCloud 连接接入，因此总账、试算平衡表、主数据和预算直接来自源头，无需导出。文件用于补充系统中没有的数据，例如汇率、分摊动因或保存在 ERP 之外的预算，并且可以替换其所覆盖的 ERP 行。**加载**会将每个源整合到模型中，折算为报告货币，并检查合计是否一致，这一切都在项目**主页**侧栏的 **Data Foundation** 分组中完成。添加第二个系统时，您需要按主题各回答一个问题，例如它是否与已连接的系统使用相同的科目代码；管理合并则会生成已抵销集团内部往来的集团损益表。您可以将 Data Foundation 添加到任何项目中，解决方案（例如 **Enterprise Profitability**）在此基础上构建各自的报表和模型。

## 获取 Data Foundation

您可以创建带有 Data Foundation 的项目，也可以将其添加到已有项目中。

- **新项目。** 在 Analyze 中打开**项目**，然后点击**新建项目**。**起始来源**列出**空白**、**Data Foundation**、**Enterprise Profitability**、**Cost to Serve**、**Operational Transfer Pricing** 和**从模板文件创建**，列表下方有一行文字说明所选项提供的内容。**Data Foundation** 是单独的模型及其报表。三个解决方案均包含 Data Foundation，并各自添加自己的模型。若要在连接任何内容之前查看完整示例，请勾选**从示例数据开始**。点击**创建**。在您共享之前，项目仅您可见，且您是唯一的架构师。
- **首次登录。** 如果您可以创建项目，首次登录时的欢迎页面会提供**连接您的财务系统**。它会创建一个 Data Foundation 项目，为其命名，并在构建期间将其打开。
- **已有项目。** 打开项目的**主页**。在侧栏的 **Data Foundation** 标题下，**Data Foundation** 行会说明它是什么，项目的架构师会看到**添加 Data Foundation**。构建在后台运行，页面会显示**正在添加 Data Foundation。这需要几分钟。** 您自己的工作流、表和其他工作都保持不变。如果项目中已存在模型要使用的某个表，则不会安装任何内容，消息会指出该表。

**主页**是每个项目的第一个选项卡。项目拥有 Data Foundation 后，其侧栏的 **Data Foundation** 分组包含以下各行，每行都有自己的链接：

| 行 | 显示时机 |
|---|---|
| **摘要** | 始终显示。已有 Data Foundation 但尚无系统的项目会在此打开。 |
| **系统** | 项目有两个或更多系统、有系统在等待访问权限，或**摘要**上的下一步是添加、连接系统或使其保持最新时。 |
| **问题** | 有问题等待您回答时显示，并以徽章显示数量。 |
| **报表** | 始终显示。 |
| **分摊** | 在使用解决方案创建的项目中。 |

## 连接 ERP

财务系统通过其 PlaidCloud 连接接入 Data Foundation。Data Foundation 直接从中读取总账、试算平衡表、主数据、汇率、预算，以及系统中保存的子分类账、月末数据和银行余额，并且只读取。凭据只能在标准连接编辑器中输入。每个系统都有一个面向授予访问权限的管理员的页面，列在[哪些系统可以为模型提供数据](/zh-cn/guides/projects/data-foundation-getting-started/#哪些系统可以为模型提供数据)中；[Data Foundation 覆盖矩阵](/zh-cn/reference/data-foundation-coverage-matrix/)列出了各系统直接提供的数据集。

<Steps>

1. 在**摘要**上，点击**添加财务系统**。随即打开**系统**。

2. 在**添加系统**下，于**系统**中选择您的系统。接下来的操作取决于该系统的登录方式：

   - **QuickBooks Online 和 Xero** 通过在系统自己的窗口中批准访问来登录。点击 **Connect to** 和系统名称。PlaidCloud 会为项目的环境创建连接并打开批准窗口。批准后，系统即被添加并开始加载。如果浏览器拦截了该窗口，请允许该站点的弹出窗口，然后重试。
   - **使用凭据登录的系统**会在**连接**下列出您可以使用的同类连接（默认选中第一个）以及**新建连接**。选择一个，然后点击**添加系统**。**新建连接**会打开标准连接编辑器并填入项目的环境，保存连接后即添加该系统。
   - **SAP S/4HANA、SAP ECC、Oracle E-Business Suite 和 Sage 100** 通过您网络中的 PlaidLink 代理访问。请先设置代理，然后像使用凭据登录的任何系统一样选择其连接。

3. 若要在添加系统之前更改加载内容，请打开**选项**。**公司**列出该系统的公司：勾选要加载的公司，或不勾选任何公司以加载全部公司。不列出其公司的系统会要求您输入公司。**历史月数**是向前加载多少个月，范围为 1 到 120。某些系统还有**系统设置**，缺少必需设置的系统会打开**选项**并要求您提供该设置。如果不使用**选项**，将加载所有活动公司和 24 个月的历史数据。

4. 连同连接一起添加的系统会立即开始加载。如果其他工作流使用同一连接，PlaidCloud 会先询问**要从共享连接加载吗？** 并列出这些工作流，因为加载会从该连接读取数据，可能会减慢这些工作流。点击**仍然加载**以继续。

</Steps>

还没有访问权限？请选择系统，然后改为点击**还没有访问权限？** 系统将以**等待访问权限**状态添加，并会显示一份涵盖所有等待中系统的请求，可通过**复制请求**或**通过电子邮件发送请求**发送。获得访问权限后，在**添加系统**下使用其连接添加该系统。对于 QuickBooks Online 和 Xero，请点击该系统所在行上的**连接**。

若要接入另一个系统或另一个实例，请以相同方式添加。添加系统始终会保持其他系统不变，因此多个系统和实例可以共同为同一个合并模型提供数据。添加第二个系统时，Data Foundation 会按主题各询问一个问题，而不是按代码逐一询问。请参阅[跨源映射代码](#跨源映射代码)。

每次加载只读取发生变化的内容：未结账期间和最近一个已结账期间会被重新读取，已加载的已结账期间则保持不变。提高**历史月数**只会读取新增的月份。汇率、实体对照表或报告货币发生变化时，会重新读取受其影响的月份。

## 系统

项目加载所用的每个系统和实例都是一个源，您确认的文件也是源。当项目有两个或更多系统、有系统在等待访问权限，或**摘要**上的下一步是添加、连接系统或使其保持最新时，侧栏中会显示**系统**行，随之显示该页面、其按钮和**文件**卡片。如果只有一个已加载且保持最新的系统，**摘要**会改为在**您的系统**下显示它。**系统**页面列出每个系统，包含**系统**、**状态**和**上次加载**。**状态**为**等待访问权限**、**已连接**、**加载中**、**已加载**或**失败**之一。**上次加载**显示系统上次加载的时间或**尚未加载**；项目按计划刷新后，还会显示下一次刷新的时间，或自何时起已逾期。加载失败的系统，其所在行会说明原因。

每行都有与系统当前状态相符的按钮：

| 按钮 | 显示时机 |
|---|---|
| **加载** | 系统已连接或已加载。它只读取该系统，然后基于所有系统的数据重新构建模型。加载失败的系统会在其修复按钮旁提供此按钮。 |
| **打开连接** | 系统加载失败。打开其连接以查看原因并进行更正。 |
| **重新连接** | QuickBooks Online 或 Xero 的登录已过期。 |
| **连接** | QuickBooks Online 或 Xero 正在等待访问权限。 |
| **申请访问权限** | 使用凭据登录的系统正在等待访问权限。它会再次显示要发送的请求。 |

旁边的**测试连接**会登录并尝试读取每个数据集，然后将每个数据集列为**可读取**、**缺少权限**或**错误**，并列出需要请系统管理员添加的权限。**移除**会在您确认**移除此系统？** 后将系统从项目中移除。从该系统加载的所有内容都会被删除，您以后可以重新连接它。

点击系统上的**编辑**可更改其使用方式，然后点击**保存**：

| 设置 | 作用 |
|---|---|
| **名称** | 报表、问题和消息中用于该系统的标签。 |
| **Reporting books, separated by commas** | 要读取的会计账簿，适用于保存多个账簿的系统。**All reporting books** 会读取所有账簿。 |
| **此数据源提供的月份** | 对于每个**公司**，系统在 **自 (2026-01)** 和 **至 (2026-12)** 之间提供的月份。留空表示不设限制。月份写作“年-月”，例如 `2026-03`。 |
| **此数据源中的额外类别** | 对于系统带有的每个额外类别，设置其**名称**以及**显示于**的位置，或选择**排除**。 |
| **公司**和**历史月数** | 系统加载哪些公司，以及向前加载多少个月。 |

添加公司或不勾选任何公司时会立即保存。去掉某个公司时，会先要求您确认**要减少加载的公司吗？**，因为保存会立即清除从该系统加载的所有内容，下一次**加载**会重新拉取已勾选的公司。

当两个系统为同一公司提供同一个月的数据时，排在前面的系统优先，直到您选择从何时起以哪个源为准。请参阅[选择从何时起以哪个源为准](#选择从何时起以哪个源为准)。

更改源不会再次读取 ERP。每个页面上方的提示栏会一直显示**您更改了源。请点击“应用更改”以使用它们。** 直到您点击**应用更改**，该操作会基于已拉取的数据运行一次加载：按新的映射、名称和文件重新整合各源，并重新构建模型。如果还想从系统获取最新数据，请点击**加载**。

## 添加文件以补充 ERP 之外的数据

文件用于补充 ERP 连接中没有的数据，例如汇率、分摊动因、实体代码的[代码映射](#实体对照表)或保存在 ERP 之外的预算。每个文件属于[Common Finance Model 表](#common-finance-model-表)下列出的某个数据集。

<Steps>

1. 在**系统**上系统列表下方的**文件**卡片中，选择用于存放该文件的**文档账户**。

2. 将 CSV 或 Excel 文件拖放到**将 CSV 或 Excel 文件拖放到此处**，或点击**选择文件**。文件会上传到文档账户的 `/foundation/` 文件夹。

   对于文档账户中已有的文件，请打开**添加文件的更多方式**，在**添加文档账户中已有的文件**下输入其路径，例如 `/foundation/budget.csv`，然后点击**添加文件**。

   若要每月读取一个新文件，请使用**添加文件夹中所有匹配的文件**：输入文件夹，选择文件名是**包含**、**开头为**、**结尾为**、**完全等于**还是**匹配（\* 代表任意内容）** 您输入的内容，然后点击**添加文件**。其中子文件夹内的文件不会被读取。

3. PlaidCloud 会读取该文件并提出映射建议：

   - **Detected delimiter, decimal separator and dates.** 分隔符（逗号、分号、制表符或竖线）、小数分隔符和日期格式会被自动检测。
   - **数据集**：文件所属的 Common Finance Model 表，根据文件名和列标题匹配。匹配不明确时，请从列表中选择。
   - **小数分隔符**：**句点(1,234.56)** 或**逗号(1.234,56)**。
   - **日期格式**：文件包含日期时显示。如果检测到的格式有误，请更改：`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY` 或 `MM/DD/YYYY`。
   - 一个包含**文件中的列**、**类型**、**示例**和**去向**的网格。更改**去向**可将某列发送到其他字段，或设为**不加载**。

4. 回答文件引发的问题，例如 **此文件属于哪家公司?**、**金额使用什么币种?**、**这些金额是年初至今累计,还是当月金额?**、**金额以千为单位还是以百万为单位?**、**收入是否显示为负数?** 或者，对于合同文件，**每一行都是一个合同期吗？**（请参阅[合同登记表](#合同登记表)）。只有文件本身没有说明时，才会询问相应问题，但**每一行都是一个合同期吗？** 除外，每个被建议为合同的文件都会询问。

5. 检查每一列的去向，然后点击**确认映射**。处理期间，按钮下方的说明会解释为何在等待。在仍含示例数据的项目中，您确认的第一个文件也会移除示例数据，这可能需要几分钟。

</Steps>

文件适用时会出现以下选项：

| 选项 | 用途 |
|---|---|
| **Which source do these rows apply to?** | 将代码映射文件限定到某一个源。**Every source** 会将其应用于所有源。 |
| **Where does this file come from?** | 说明文件包含的是 **This project's own codes**，还是来自 **Another system**（需要您命名，例如 `SAP Germany export`）。来自其他系统的文件会像 ERP 源一样检查共用代码。 |
| **Split … into … parts at each …**（在**高级**下） | 拆分包含多个值的单列（例如 `100-200-300`），并将每一部分发送到各自的字段。 |
| **Which currency do you report in?** | 在项目尚未设置报告货币时设置报告货币。写作三个字母，例如 `USD`。 |
| **这些是合并结果或您已报告的损益（OneStream、Anaplan、SAP Group Reporting、FCCS）** | 加载合并系统的结果，以便[对账](#与合并系统对账)集团损益表。 |

若要将文件从项目中移除，请点击**文件**下该文件旁的**移除**，或其映射上的 **Remove this file**，然后确认。下次点击 **Apply changes** 时，其数字将从报表中消失。

当 PlaidCloud 无法自行确定数据集、小数分隔符或日期顺序时（例如文件中的日期既可能是日/月，也可能是月/日），它会在您确认之前请您选择。为同一数据集添加第二个文件会替换第一个文件。如果后续文件的列与数据集不匹配，加载会指出该文件和这些列，并提示您更正文件或其列名，或将步骤的 **Schema Mismatch** 设为 `union`。

接受的文件有 CSV、TSV 和 TXT 文本文件、Excel `.xlsx` 文件（读取第一个工作表）以及 Parquet 文件。

<Aside type="note">
缺失或为空的文件永远不会中止加载。添加这样的文件时会提示暂无可映射的内容，加载会在完成时给出指明路径的警告。该数据集会保留文件上次提供的行（如果有）。文件存在后再重新添加即可。
</Aside>

### 合同登记表

合同文件可以是合同期登记表，也可以是某个月末的合同，因此确认时会询问**每一行都是一个合同期吗？** 当文件有开始日期且没有月末列时，建议的答案是**是，每一行都是一个合同期**。您之前确认过的文件在再次添加时保留其答案。

- **是，每一行都是一个合同期**：每一行是合同的一个期限，带有开始日期、结束日期和年度价值。每次加载都会把每一行复制到它所跨的每个月末，从其开始日期到其结束日期，结束日期为空时则一直复制到加载所在月份，或该实体日历的最后一个月（以较早者为准）。之后才开始的已签署合同从其开始日期起计入。除加载所在月份的那一份保留该行自身的状态外，每份副本均为 `Active`。没有行号的行在其合同内编号。
- **否，该文件是某个月末的合同**：该文件是合同在某个月末的副本，与任何其他合同文件一样。

没有开始日期的行、状态表明已结束但没有结束日期的行，以及在其首月最后一天之前结束的行都不是合同期，因此会被暂扣。请参阅[被暂扣的行](#被暂扣的行)。登记表中的客户和产品代码会添加到客户和产品中，并以代码命名，除非其他源为同一代码给出了名称。其实体代码仅在没有其他源为任何实体命名时才会添加。

## 加载您的数据

加载会读取已连接的系统和您已确认的文件，将它们整合到 Common Finance Model 中，折算为报告货币，运行就绪状态检查，并重新构建模型。连同连接一起添加的系统会自行开始首次加载。在任何内容加载之前，**加载**也是**摘要**上的下一步。此后，**系统**上某个系统所在行的**加载**只读取该系统，然后基于所有系统的数据进行整合、重新构建和合并，因此添加系统时绝不会重新读取其他系统。加载运行期间，**摘要**会显示正在加载的内容。

- 一个项目同一时间只能运行一次加载。第二次**加载**或 **Apply changes** 会提示已有加载正在运行，并且加载运行期间无法更改源。
- 如果其他工作流使用同一个连接，首次加载会列出这些工作流并请您确认，因为加载会读取该系统，可能拖慢这些工作流。点击**仍然加载**即可继续。
- PlaidCloud 升级后，架构师的**加载**或**应用更改**还会更新项目生成的工作流，并创建它们所需的工作表。当有较新版本的模型可用时，每个 Data Foundation 页面上方的提示栏会显示 **Update available**，并说明架构师的**加载**或**应用更改**会安装该版本。管理者的**加载**会警告只有架构师才能更新它们。
- 应用更新时会保留您对生成步骤所做的修改。如果您更改了某个步骤而更新也更改了它，将保留您的修改。您编辑过、而更新不再生成的步骤会被保留但处于关闭状态；请将其删除，或在仍需要时重新开启。被更新替换的步骤会被点名，原有步骤仍保留在其步骤版本中。
- 如果更新中途停止，在它完成之前，其步骤可能会乱序运行。请以架构师身份再次点击**加载**以完成更新。如果再次停止，请联系支持人员。
- 加载失败的系统会在**系统**上显示**失败**，并附有原因及修复方法。如果上次加载以警告结束，**摘要**会显示 **The last Load ended with a warning:**，后面跟着该警告。
- 如果某个实体和期间读取失败，其余部分仍会加载。再次运行**加载**即可只获取失败的部分。
- 如果源中的某个数据集读取失败，该源的其余部分仍会加载，该数据集会保留其原有的行，并且在加载读取到它之前，该系统会在**系统**上显示**失败**。

### 被暂扣的行

当源重叠时，加载对每个数字只计算一次。未计入的行要么被保留，要么被暂扣。

保留的行仍留在项目中，并标记为未计入，因此系统中的任何内容都不会丢失，也不会被重复计算。以下情况的行会被保留：

- 位于源未设置读取的其他会计账簿中，例如本地账簿或税务账簿；
- 位于为其公司设置的**从**和**至**月份范围之外；
- 属于另一个源所计入的公司和月份，例如实体迁出的原系统；
- 已被该实体和月份的文件替换。

被暂扣的行会连同其源、实体和原因一起记录，加载完成时会给出写明数量的警告，例如 `120 rows of NetSuite EU carrying a code another source also uses`。原因如下：

| 原因 | 含义 |
|---|---|
| 该源的较早文件中也有 | 同一源的较早文件已覆盖该月份。 |
| 较晚的期初余额 | 该实体最早的期初余额及其后的发生额已计入。 |
| 带有另一个源也使用的代码 | 该代码需要您回答。请参阅[跨源映射代码](#跨源映射代码)。 |
| 带有映射到两个代码的代码 | 代码映射为该代码给出了两个答案。 |
| 带有其自身主数据中没有的代码 | 系统自身的科目、产品或客户列表中没有该代码。 |
| 报表合计或空行 | 文件中的合计行或空行。 |
| 没有开始日期、已结束但没有结束日期，或在其首月最后一天之前结束，因此不是合同期 | 合同登记表中不属于合同期的行。请参阅[合同登记表](#合同登记表)。 |

统计账户会转入分摊动因而不是总账，并显示为已转移，而不是问题。

### ERP 数据与文件共用

文件只替换它所覆盖的内容，ERP 的其他行保持不变。

- **主数据文件**（科目、部门、客户、产品和分部值）会替换代码相同的 ERP 行。
- **交易文件**会替换同一实体和月份的 ERP 行。总账和试算平衡表文件还按账簿匹配，预算文件按方案匹配，统计动因文件按方案和动因匹配。

如果某个文件之后不再覆盖某个月份，ERP 在该月份的数据会在下次加载时恢复。

## 实体对照表

每个源都用自己的代码命名实体。**代码映射**文件将这些代码映射到实体主数据中的实体，使各源的明细行落在同一个实体上。

若要使用，请添加 CSV 或 Excel 文件并选择**代码映射**数据集：

| 列 | 内容 |
|---|---|
| `source_code` | 源所带的代码，例如公司代码。名为 `source_entity` 的列也会与之匹配。 |
| `code` | 它所属的实体，按实体主数据中的名称。名为 `entity` 的列也会与之匹配。 |

除非文件中有 `dimension` 列另作说明，否则每一行都映射一个实体代码。请参阅[跨源映射代码](#跨源映射代码)。

- 不在代码映射中的代码按原样使用。
- 多个代码可以映射到同一个实体。它们的明细行会被合并，只有当它们全部已结账时，该月才算已结账。
- 除非您在**这些行适用于哪个来源?** 中选择了某个源，否则文件中的行适用于所有源，因此当两个源用同一代码表示不同实体时，请将文件限定到一个源。
- **实体**文件中的一行会替换 ERP 中实体代码相同的实体。

**Every entity known** 检查会标记所有实体既不在实体主数据中、也未通过代码映射映射到某个实体的明细行。在加载实体主数据之前，此检查不适用。

## 跨源映射代码

两个系统可能用相同的代码表示不同的事物，也可能用不同的代码表示同一事物。当您添加的系统与已连接的系统存在代码重叠时，Data Foundation 会按主题各询问一个问题，而不是按代码逐一询问，例如 **Does SAP ECC use the same account codes as NetSuite?** 它会针对科目、部门、利润中心、站点、产品、客户以及每个额外类别提出此类问题。

每个问题都会在**问题**页面上等待，附有 Weave 的建议答案及其依据（例如共用代码中有多少个名称相同），并说明在您回答之前有多少行被暂扣。回答 **Same codes as** 另一个系统，或 **Different codes from** 该系统。

- 在您回答之前，带有共用代码的行会被暂扣，从而使每笔金额只计算一次。
- 一旦您回答某个系统使用相同的代码，之后该系统中出现的新代码会被视为另一个系统的代码，不会再提出新问题。
- 映射按系统和维度保存，因此对某个系统的部门所做的回答绝不会改变另一个系统的科目。
- 回答在下一次**加载**或**应用更改**时生效，**摘要**上的**历史记录**会记录回答者、回答时间以及之前的值。

您也可以通过文件提供映射。添加一个 **Code map** 数据集的文件，并选择 **Which source do these rows apply to?** 将其限定到某一个源。

## 选择从何时起以哪个源为准

当某个实体从一个系统迁移到另一个系统时，两个系统都会包含该实体。**问题**会询问 **From which month does** 新系统 **count for** 该实体，并建议采用较早系统最后一个总账月份的下一个月。较早的系统保留此前的月份。

**摘要**上的**数据源覆盖范围**卡片会列出两个源同时提供的其他所有月份。在**问题**下，对于在某家公司上重叠的两个源，在**该月份为**中输入月份（例如 `2026-04`），在**从该月起采用哪个数据源？** 中选择源，点击**保存选择**，然后点击页面上方提示栏中的**应用更改**。在您做出选择之前，两者中只有第一个会被计入，另一个源保留您输入的月份之前的月份。**需要关注**会说明已按上述方式计入的重叠情况，例如两个源为同一公司给出不同汇率，并说明采用的是谁的汇率。

## 货币折算

每次加载都会将总账、试算平衡表、销售、库存、预算和子分类账金额从本位币折算为一种报告货币。报表和模型读取折算后的金额，因此来自任何系统、使用不同货币的实体都能正确合计。

### 报告货币

若要选择报告货币，请将项目变量 `reporting_currency` 设置为货币代码，例如 `USD`。请参阅[管理项目变量](/zh-cn/guides/projects/managing-projects/#管理项目变量)。在包含多个实体的项目中，也可以点击**摘要**上**集团**卡片中的**更改**，然后在**项目设置**的**报表币种**中输入代码。模板创建时它为空。在它为空时，每次加载会采用下列第一个恰好指向一种货币的来源：

1. 实体的集团货币。
2. 顶层实体（没有父级的实体）的本位币。
3. 文件的本位币。

如果没有任何一项恰好指向一种货币，请自行设置 `reporting_currency`。

已经是报告货币的金额保持不变，因此数据全部为同一种货币的项目不需要汇率。

销售、库存和预算文件也可以带货币。映射名为 `Currency` 或 `Local Currency` 的列，系统会自动识别，并将文件中的本位币金额折算为报告货币。文件中已有的集团或报告金额按原样保留。产品主数据中的标准成本已采用集团货币，不做折算。

### 汇率

汇率将一个单位的某种货币折算为某个月的报告货币：折算后的金额等于本位币金额乘以汇率。

- **来自 ERP**：每次加载都会读取 ERP 中保存的汇率。
- **来自文件**：添加 CSV 或 Excel 文件并选择**汇率**数据集。文件中的汇率会替换 ERP 中同一货币对和月份的汇率。如果要使用 ERP 未发布汇率的货币作为报告货币，或为预算月份添加计划汇率，请使用文件。

| 列 | 内容 |
|---|---|
| `from_currency` | 折算的来源货币，例如 `EUR`。 |
| `to_currency` | 报告货币，例如 `USD`。 |
| `period` | 月份，格式为 `YYYY-MM`。 |
| `average_rate` | 当月平均汇率。 |
| `closing_rate` | 月末汇率。 |
| `historical_rate` | 历史汇率，用于权益以及设置为按历史汇率折算的科目。 |

当某种货币没有折算为报告货币的汇率时，会将其反方向的汇率（即从报告货币折算为该货币的汇率）取倒数，并保留 12 位小数。如果也没有这样的汇率，则将该货币折算为另一种货币的汇率，乘以那种货币折算为报告货币的汇率。

### 适用哪种汇率

每一行都按其自身的货币折算，因此与其实体货币不同的明细行会按它所用的货币折算。适用第一条符合该行的规则：

| 行 | 汇率 |
|---|---|
| 统计账户和非过账账户 | 不折算。 |
| 已经是报告货币 | 不折算。 |
| 带汇率类型的科目 | 该汇率：平均、期末或历史。没有历史汇率时，历史汇率回退为期末汇率。来自 ERP 时，汇率类型即科目自身的汇率类型。在会计科目表文件中，将汇率类型列映射到 `fx_rate_type`，取值为 `average`、`closing` 或 `historical`。 |
| 销售明细行 | 该期间的平均汇率。 |
| 库存余额 | 该期间的期末汇率。 |
| 供应商发票、采购订单、付款、销售订单、资产变动、递延收入变动、库存变动或标准成本 | 该期间的平均汇率。 |
| 未清应收或应付款、销售订单的未结金额、合同价值或银行余额 | 其所在月末的期末汇率。 |
| 预算行 | 与总账一样按科目：损益科目用平均汇率，资产负债表科目用期末汇率。 |
| 损益科目 | 该期间的平均汇率。 |
| 权益科目 | 历史汇率；没有历史汇率时用期末汇率。 |
| 其他任何资产负债表科目 | 该期间的期末汇率。 |

折算后的金额不做四舍五入，因此合计不会产生偏差。

销售管道视图 `cfm_rv_pipeline_month`、`cfm_rv_won_booked` 和 `cfm_rv_campaign_window` 将商机的赢单、丢单和新建金额按交易成交或创建当月的平均汇率折算。某月的未结销售管道按该月的期末汇率折算；若该月自身的汇率尚未加载，则按该货币已加载的最新期末汇率折算。

<Aside type="note">
若外币交易的货币没有该月的平均汇率，其赢单、丢单或新建金额会被排除，而不会按其他汇率显示。该交易仍会被计数。外币赢单的金额在其所在月份的平均汇率加载之前不会出现在 `cfm_rv_pipeline_month`、`cfm_rv_won_booked` 和 `cfm_rv_campaign_window` 中，因此在此之前当月的外币赢单不会计入赢单金额。请将该汇率添加到**汇率**文件中，或检查连接能否读取 ERP 的汇率，然后再次运行**加载**。
</Aside>

<Aside type="note">
总账和试算平衡表保存的是各期间的发生额，因此其中的资产负债表金额是每个月的发生额按该月汇率折算的结果。合并资产负债表则改为折算余额，采用所示月份的期末汇率，差额列在权益下的折算差额行中。请参阅[管理合并](#管理合并)。
</Aside>

## 层次结构

每次加载都会根据每个源的主数据重新构建维度。起初有七个维度，另外最多可有十个额外类别：

| 维度 | 构建依据 |
|---|---|
| **实体** | 实体及其父级 |
| **科目** | 会计科目表和父级科目 |
| **部门** | 部门及其父级 |
| **客户** | 客户及其父级客户 |
| **产品** | 产品及其父级产品 |
| **Segment 1** | `segment_1` 的分部值 |
| **Segment 2** | `segment_2` 的分部值 |
| **Segment 3** 至 **Segment 10** | `segment_3` 至 `segment_10` 的分部值（当您的源带有这些值时） |

- 没有父级的记录，或将自己指定为父级的记录，会作为顶层成员加载。
- 由于每次加载都会重新构建层次结构，请在 ERP 或您的文件中更改父级，而不要在维度中更改。
- 一个层次结构中的问题只影响该维度。加载和模板的模型仍会完成。
- 您可以将每个额外类别重命名为其所含内容，例如**类别**或**区域**。在包含多个实体的项目中，点击**摘要**上**集团**卡片中的**更改**，在**项目设置**的**名称**下输入报表使用的名称，然后点击**保存**。名称可使用字母、数字、空格、点、短横线和下划线，最长 60 个字符。
- 每个源会说明其自身的每个额外类别归入您的哪个类别名称之下。在**系统**上点击源的**编辑**，在**此数据源中的额外类别**下为每个类别选择名称，或选择**排除**，然后点击**保存**。这样，用不同名称称呼同一类别的源（例如 `Class` 和 `Business area`）会共用同一个位置。

若要通过文件提供分部层次结构，请选择**分部值**数据集：

| 列 | 内容 |
|---|---|
| `segment` | 该值所属的分部：`segment_1` 至 `segment_10`。 |
| `segment_value` | 该值，与总账、销售和预算明细行所带的值一致。 |
| `segment_value_name` | 其名称。 |
| `parent_segment_value` | 同一分部内的父级值。 |

## 就绪状态检查

这些检查是**摘要**上五项保证的详细内容；请参阅[这些数字可信吗？](/zh-cn/guides/projects/data-foundation-proof/)。

每次**加载**和**应用更改**都会针对每个实体和期间运行这些检查，每项检查都计入五项保证之一。未通过的检查显示为红色。提醒显示为琥珀色：表示需要查看，但数字仍然正确。在 **CFM-Accounting - Close and assurance** 仪表板上，**What needs fixing** 选项卡会显示 **Every check, by system, month chosen**，列出每项检查在每个系统中的红色项数量，零表示无需修复。所选月份的待修复项表按从大到小排列，指出每个红色项并说明该怎么做，例如加载会计科目表、加载汇率或再次运行**加载**。请参阅[仪表板、指标和分析路径](/zh-cn/guides/projects/data-foundation-dashboards/)。

主要检查项如下：

| 检查 | 归属 | 确认内容 |
|---|---|---|
| **Every month loaded** | **无任何丢失** | 每个会计期间都有总账明细行，且每次 ERP 读取都已成功。没有明细行的已结账期间未通过检查；没有明细行的未结账期间为提醒。 |
| **Trial balance equals the ledger** | **与各系统一致** | 每个实体、期间和科目的试算平衡表都等于总账。当试算平衡表和总账都为某个科目带有部门时，还会逐个部门核对。 |
| **Sales equal the ledger** | **无任何丢失** | 每个期间的销售明细行都等于总账的收入和 COGS 科目。 |
| **Every product and customer of a sale known** | **无任何丢失** | 每条销售明细行所指的产品和客户都存在于产品主数据和客户主数据中。 |
| **Every account known** 和 **Every account typed** | **无任何丢失** | 每条总账明细行所指的科目都在会计科目表中。带有未知科目的明细行不会计入损益表。有过账但没有科目类型的科目也未通过检查；如果某个源的科目表为收入科目设置了类型，却没有销售成本科目，则为提醒。 |
| **Every amount has a rate** | **集团合计相符** | 每个总账、试算平衡表、销售、库存和预算行都有报告货币金额。没有汇率的损益行或销售行未通过检查，因为损益表读取的是折算后的金额。没有汇率的资产负债表、库存或预算行为提醒，因此请为预算月份加载计划汇率。请参阅[货币折算](#货币折算)。 |
| **Every entity known** | **无任何丢失** | 每条总账、试算平衡表和销售明细行所指的实体，都在实体主数据中，或通过**代码映射**文件映射到其中。在加载实体主数据之前不适用。请参阅[实体对照表](#实体对照表)。 |

以下检查仅在需要关注时才会提出，均归属于**无任何丢失**：

| 检查 | 确认内容 |
|---|---|
| **Reporting book chosen** | 对于为某个实体带有多个会计账簿的源，已选定报告账簿。在您选择之前，只计入第一个账簿。 |
| **Codes mapped** | 多个源使用的每个代码都已回答。请参阅[跨源映射代码](#跨源映射代码)。 |
| **One source for each key** | 除非您已选择以哪个为准，否则没有两个源提供同一公司的相同月份。 |
| **Hierarchies complete** | 维度所指的每个父级都存在，且没有成员是其自身的父级或祖先。缺失的父级会使其子级位于层次结构顶部，循环则会使该层次结构无法加载。合计不受影响。 |
| **Months placed in the fiscal calendar** | 每个实体的会计期间都是日历月，且每个月的行都能归入一个会计期间。当实体的期间不是日历月（4-4-5、13 个期间），或某个月的行可能属于多个会计期间，或财务日历缺少该月时，为提醒。 |

另有两项设置检查仅在需要关注时才会提出。当项目变量 `overhead_department` 和 `overhead_driver` 只设置了其中一个，或没有任何分摊动因与 `overhead_driver` 匹配，导致间接费用分摊不起作用时，会提出其中一项：请同时设置两者，或同时清除两者以关闭间接费用分摊。当已加载预算行，但没有任何一行属于项目设置中的**预算版本**（项目变量 `budget_version`）时，会提出另一项，因为此时预算对比为空。

## 管理合并

每次加载都会构建一个管理合并：集团中所有实体的损益表、资产负债表和现金流量表，以报告货币列示，并已抵销集团内部往来。它用于管理报告。合并系统仍是法定集团的记录依据；请按下文与其对账。

合并数字出现在任何位置时，都带有 **Management consolidation** 标签：位于**摘要**第一行旁边、每个仪表板顶部的上下文行中，以及董事会资料包的 **Basis** 列中；该资料包的 **Basis note** 列写着“Entities combined, intercompany eliminated, translated to the reporting currency. Not a statutory consolidation.”只有一个实体的项目不显示标签。

<Aside type="note">
管理合并不是法定合并或法律合并。它不会将投资与权益相抵销，也没有商誉或少数股东权益。
</Aside>

### 选择集团

在**摘要**上，**集团**卡片显示报告货币。点击**更改**打开**项目设置**，其中的**集团与行访问权限**会列出**集团内的公司**。您取消勾选的公司仍会单独出现在报表中，但不计入集团合计。点击**保存**。更改会在下次**加载**或**应用更改**时生效。新公司在您取消勾选之前都属于集团。

集团会计年度从项目变量 `group_fy_start_month` 设置的月份开始。该变量为空时（除非您设置，否则它为空），集团会计年度从顶层实体（唯一没有父级的实体）的会计年度起始月份开始；如果顶层实体没有财务日历，则从一月开始。如果有多个实体没有父级，或顶层实体是没有自身财务日历的层次结构节点，则从一月开始，并且在您设置月份之前，合并会显示为琥珀色。

### 您将得到什么

| 表 | 内容 |
|---|---|
| **Group P&L** | 每个实体、期间和明细项（收入、销售成本、运营费用、营业外项目、集团内部差异）各一行，以报告货币列示。收入和成本保留其自然符号。 |
| **Group P&L year to date** | 同上，为年初至今，截至集团最近一个完全加载的期间。 |
| `group_statements` | 按所示方式逐行列出的损益表、资产负债表和现金流量表，包含每个小计和合计，涵盖每个实体、抵销和集团，以报告货币列示。收入、资产和现金流入为正数。每行都有当月金额以及集团会计年度截至该月的累计金额；资产负债表行为当月余额。 |
| `group_result` | 按实体、明细项、科目和月份列示的同样三张报表，涵盖每个报告账簿，以报告货币列示；对于使用其他货币的实体，还以其自身货币列示。金额以借方为正，与总账相同。 |
| **Intercompany pairs** | 每对实体、每个集团和期间各一行，列出双方的金额和余额。 |
| **Intercompany lines** | 集团数字或某一对背后的总账明细行，附带交易伙伴。 |
| **Reconciliation** | 集团年初至今损益表与合并系统的对比。 |

这些表中会出现三个实体名称：

| 实体 | 含义 |
|---|---|
| **Eliminations** | 集团内部往来抵销。它们合计为零，因此集团数字应保留它们，而要得到抵销前各实体之和时则应将它们筛选掉。 |
| **Group total** | 对账中合并系统的合计。 |
| **Unmapped** | 没有期间的明细行，以及合并系统中有而本项目没有的科目或实体。 |

指标 **Consolidated income**、**Consolidated result** 和 **IC difference** 读取 **Group P&L**。它们以及 **Group P&L**、集团内部往来表和对账表各自对应的分析路径，可用于回答有关集团的问题。**CFM-Finance - Statements** 仪表板和董事会资料包会显示这三张报表。

#### 三张报表

- **损益表**：每个月按该月的平均汇率折算。
- **资产负债表**：每个科目的余额为其期初余额加上截至该月的发生额。余额按所示月份的期末汇率折算，权益按历史汇率折算；如果科目有自己的汇率类型，则按该类型折算。没有历史汇率的权益科目按期末汇率折算。以前会计年度的损益计入留存收益，本年度的损益计入本年利润，各自按其所属月份的平均汇率折算。
- 折算差额是每个实体在权益下的一行，计算方法为其权益和利润按期末汇率折算的金额减去已折算的金额。正是它使折算后的资产负债表得以平衡，它绝不是轧差数字。当使用其他货币的实体某个月没有期末汇率时，其资产负债表当月不会折算，也不会平衡，合并会显示为琥珀色，并指出该实体和月份。请加载该汇率，然后运行**应用更改**。
- **现金流量表**：根据每个资产负债表科目当月的变动，按其科目角色、以当月平均汇率计算得出。汇率变动影响行记录现金变动中（按期末汇率计）由汇率变动引起的部分。没有角色的资产负债表科目列在其他变动行中。
- 在**问题**中回答的**科目角色**会把科目放到相应的行。**佣金**是单独的一条营业费用行。**可转换票据和 SAFE** 是一条负债行，其变动列在现金流量表的筹资活动下；具有该角色的权益科目仍留在权益中。名称含佣金的费用科目会被建议为**佣金**；名称含可转换票据、SAFE 或简单协议的负债或权益科目会被建议为**可转换票据和 SAFE**；名称含股东贷款、所有者贷款或他人贷款的科目会被建议为**借款**，即使其名称同时含有应付；名称含承包商的费用科目会被建议为**人员**。

资产负债表以一个检查行结束，即资产减去负债和权益；现金流量表则以现金变动减去现金科目的变动结束。报表正确时，两者都为零。有关证明它们的保证，请参阅[这些数字可信吗？](/zh-cn/guides/projects/data-foundation-proof/)。

### 集团内部往来抵销

集团内部往来明细行按交易伙伴匹配。使用明细行上的伙伴；如果明细行没有伙伴，则使用其客户的伙伴。一对交易的双方都会被抵销，双方不一致的金额会计入集团内部差异行。每一对都会得到一个原因：

| 原因 | 含义 |
|---|---|
| **Matched** | 双方记录的金额相同。 |
| **Only one side booked** | 一个实体记录了该交易，而其伙伴没有。 |
| **Not eliminated** | 这一对中的某条明细行没有汇率，因此双方都未被抵销。 |

一对交易按其年初至今来判断。当某一对的差异超过项目变量 `group_amber`（默认 `1`）时，集团内部往来检查变为琥珀色；超过 `group_red`（默认 `1000`）时变为红色，这就是**项目设置**中的**公司间容差**。没有伙伴的明细行，或伙伴不是实体的明细行，不会被抵销，并会计入该检查。如果一个源带有伙伴而另一个不带，则显示为琥珀色。

源自身的抵销实体不计入集团损益表，合并检查会注明这一点。

在三张报表中，集团内部应收款和应付款以及集团内部收入和成本都会按对抵销。一对交易双方不一致的金额列在损益表或资产负债表的集团内部差异行中，因此集团资产负债表仍然平衡，其变动则列在现金流量表的集团内部余额变动行中。每个抵销行都带有两个实体以及它们共有的国家/地区、区域和事业部，因此某个事业部、国家或区域只抵销两个实体都在其内部的交易对，而集团会抵销所有交易对。

### 与合并系统对账

将合并系统报告的结果作为文件添加，并在确认其映射时勾选**这些是合并结果或您已报告的损益（OneStream、Anaplan、SAP Group Reporting、FCCS）**。用系统名称回答**这是数字的哪个版本?** 之后，**Reconciliation** 表会按每个实体和明细项显示年初至今的 **ours**、**reported** 和**差异**。差异通常可以由 **Eliminations**、**Group total** 和 **Unmapped** 行或系统所用的汇率来解释。对账检查会列出所有超过 `group_amber` 的明细项。

### 谁能看到

集团结果遵循项目的行访问权限。当行访问权限阻止集团结果时，合并检查显示为琥珀色。只能看到部分实体的人会看到这些实体抵销前的合计，**摘要**会告知他们：“这些数字仅涵盖您有权访问的实体，而非整个公司。”**Eliminations** 行和集团内部往来表需要有权访问所有实体。

**集团与行访问权限**中的**按实体限制行**会将被授予实体的分组限制为这些实体的行，适用于每个带有实体列的表。只有架构师能看到它。勾选或取消勾选**限制**会立即生效；如果工作区已关闭行访问权限，则会被拒绝。当分组持有实体授权时取消勾选，会先询问**是否移除实体授权?**；点击**关闭**以继续。

如果项目按集团表不带的列（例如部门）限制谁能看到哪些行，集团结果会对所有人关闭，合并检查会显示 **Group views are off**。此时只有架构师才能在**集团与行访问权限**中勾选**项目中的所有人都可以查看集团结果**并点击**保存**；其他人看不到该复选框。更改会在下次**加载**或**应用更改**时生效。

## 保持数据最新

加载完成且没有会暂扣行的问题等待回答后，**摘要**上的下一步就是**保持自动更新**，直到**项目设置**中的**刷新**设为**每天**、**每周**或**每月**。有两种方式可以为**加载**设置计划：

- **摘要**上的**操作 ▾ > 每晚刷新**会在每晚 02:00 UTC 运行**加载**。
- 在包含多个实体的项目中，点击**摘要**上**集团**卡片中的**更改**以打开**项目设置**。在**刷新**下选择**每天**、**每周**或**每月**，并设置**刷新时间 (UTC)**，以小时和分钟表示，例如 `02:00`。对于**每周**，**刷新日**为 1（星期一）到 7（星期日）；对于**每月**，则为当月的日期。点击**保存**。**按需**会移除计划。

只有当包含源的加载完成且没有红色检查时，才能设置计划，因此只有示例数据的项目无法设置计划。如果您只能看到项目的部分实体，则由架构师进行设置。无法设置计划时会显示原因。当**刷新**为**每天**、**每周**或**每月**时，**系统**页面会显示每个系统下一次刷新的时间；请参阅[各系统的数据新鲜度](/zh-cn/guides/projects/data-foundation-proof/#每个系统的数据新鲜度)。**每晚刷新**不会更改**刷新**，因此不会显示下一次刷新，**保持自动更新**仍是下一步。

计划加载以设置者的身份运行。如果该用户不能再使用某个系统的连接，加载会被跳过，并给出指明该用户和连接的警告；请重新设置计划。

计划加载时缺失或为空的文件，会在完成时给出指明路径的警告，而不是报错，模型的其余部分仍会加载。

## 业务名称

**业务名称**为模型中的代码赋予贵公司使用的名称。报表、指标和 Ask 都会显示这些名称，保存的名称立即生效，之后的加载会保留它。在包含多个实体的项目中，点击**摘要**上**集团**卡片中的**更改**；**业务名称**位于**项目设置**的**名称**卡片中。

1. 点击**添加名称**并选择**类型**：**类别**、**损益项目**、**指标**、**列**、**实体**或**科目**。
2. 输入**代码**：类别为 `segment_1` 至 `segment_10`，损益项目为该行的键，指标为指标名称，列为 `table.column`，实体或科目则为其代码。
3. 输入**名称**，最多 60 个字符，单行。
4. 点击**保存**。对话框中的所有内容保存后，对话框会关闭；被拒绝的名称会在网格下方说明，对话框保持打开。

保存会替换整个列表。名称为空的行会移除该名称，**移除所选项**会移除您勾选的行。同一个代码命名两次会被拒绝。业务名称还会写入分析路径的说明，使助手使用您的措辞，而该说明有长度限制：如果某个名称会使其过长，则不会保存任何内容，并会通知您。

## 收入类别和团队职能

收入类别是贵公司销售的收入种类，例如 SaaS 或 BPO；团队的职能说明该团队的成本用于什么。[CFM-Executive - Growth and efficiency](/zh-cn/guides/projects/data-foundation-dashboards/#增长与效率) 仪表板会读取这两者。

**项目设置**中的**收入类别**列出各个类别，每个类别包含名称和种类：**订阅**、**支持与维护**、**托管服务**、**实施**、**咨询与专业服务**或**其他**。前三种是经常性种类。项目开始时每种种类各有一个类别，以该种类命名。在包含多个实体的项目中，点击**摘要**上**集团**卡片中的**更改**以打开**项目设置**。点击**添加**可新增类别，也可重命名类别或更改其种类，或点击**移除**，然后点击**保存**。

- 每个类别都需要名称，最多 60 个字符，且两个类别不能同名。名称不能包含单引号、反斜杠或花括号，“Shared”、“Not yet classed”和“Intercompany removed”保留给报表使用。
- 重命名类别或更改其种类，会保留随该类别给出的所有答案。仪表板在下一次**加载**或**应用更改**后显示该更改。
- 移除类别时，会就每个以其作答的科目和产品重新提问。

**问题**按**科目的收入类别**、**产品的收入类别**和**团队职能**询问类别和职能：

- **科目 … 属于哪个收入类别?** 针对总账过账的每个没有类别的收入和收入成本科目，每个科目一个问题，绝不会为父级科目及其下属科目合并提一个问题。收入成本科目也可以是**由所有类别共同承担**：其成本按每个类别在截至每个月的 12 个月内的收入占比分摊到各类别。
- **产品 … 属于哪个收入类别?** 针对合同上每个没有类别的产品。产品的类别按类别拆分经常性收入；无论属于哪个类别，每个合同行都计入年度经常性收入。
- **… 的部门 … 属于哪个职能?** 针对总账过账的每个部门，或者当其系统没有部门（例如 QuickBooks Online 的 Class）时，**… 的利润中心 … 属于哪个职能?** 针对每个利润中心。答案是**收入成本**、**销售和营销**、**研发费用**或**一般及行政费用**，每个系统的团队分别询问。

建议来自名称：例如名称含订阅、SaaS 或维护的科目或产品，会被建议为该种类的类别；“non-”之后的词不计，因此“Non-recurring”不会建议经常性类别。名称无法归入任何类别的收入科目会被建议为**其他**种类的类别，或另一个非经常性类别，收入成本科目则被建议为**由所有类别共同承担**。产品只有在名称能归类时才会得到建议。团队会根据名称被建议一个职能，例如销售或营销团队被建议为**销售和营销**，否则为**一般及行政费用**。

这些问题不会暂扣任何内容：它们不会使项目变为琥珀色，也绝不会成为**摘要**上的下一步。科目回答之前，其收入为“Not yet classed”，不计为经常性收入；尚未回答的产品仍计入年度经常性收入，记为“Not yet classed”。仪表板会在受影响的数字下方指明尚未回答的内容。

## 解释数字

**解释此数字**显示一个数字由哪些部分构成。某个月加载完成后，**摘要**会给出截至最近一个完整月份的年度净收入，旁边带有**解释此数字**。它会打开 **Explain: Net income**，顶部是截至该月的年度数字，下方是其构成，每个列表都按从大到小排列：

| 列表 | 内容 |
|---|---|
| **明细行** | 相加等于该数字的报表明细项。 |
| **实体** | 每个实体所占的份额。在集团中，抵销是其中之一。 |
| **账户** | 每个科目所占的份额。 |

每个列表显示最大的十项，其余合并为一项，例如 **Other accounts (12)**，因此每个列表的合计都等于该数字。作为链接的名称会单独打开该明细项、实体或科目的解释。**最大的文档**列出该数字背后最大的十张总账凭证，包括其**系统**、**实体**、**文档**、**已过账**、**科目**、**说明**和**金额**，**导出所有文档**会下载全部凭证。**询问 Weave 变动原因**会询问 Weave 该数字在截至该月的年度中为何变化，以及是哪些实体、科目和凭证导致了变动。

窗口遵循您的行访问权限：只能解释您看得到的数字。尚不存在的表会显示为警告，而不是错误。没有任何依据的数字显示**没有可解释的内容**。

## 分摊规则

分摊把共享成本（例如间接费用）分配到部门、产品和客户。模型分为两个阶段：**第 1 阶段：间接费用分摊到部门**和**第 2 阶段：部门分摊到产品和客户**。在使用解决方案创建的项目中，点击**主页**侧栏 **Data Foundation** 分组中的**分摊**。它会打开**分摊规则**，您可以在其中查看或更改每个阶段的做法。不做更改时，它们的运行方式与向导出现之前相同。读者可以打开规则，但不能保存。

对每个阶段，向导会问四个问题：

| 步骤 | 问题 | 选项 |
|---|---|---|
| **Pool** | 您想分摊哪些成本？ | 科目的类型；阶段 1 还有承担该成本的部门，或 **All departments**。 |
| **Driver** | 您想按什么来分摊？ | 您作为分摊动因加载的 **Statistic**（例如人数或平方英尺）、**Net sales amount**、**Sales quantity** 或 **Spread evenly**。使用 **Same period** 或 **Same period last year** 的动因。 |
| **Target** | 分摊到哪里？ | 阶段 1：部门。阶段 2：产品、客户或两者。 |
| **Method** | 动因为负数时怎么办？ | **Ignore negative values** 或 **Stop and tell me**。 |

在这些步骤下方，**Preview for** 某个月份（写作年和月，例如 `2026-09`）会显示规则（包括尚未保存的规则）将产生的结果：`Pool 120,000 · Allocated 120,000 · Unallocated 0`。任何未分摊的部分都是没有动因可承接的成本。预览遵循您的行访问权限。

部门名称或统计名称不能包含单引号（`'`）、反斜杠或换行符，因为名称会写入分摊步骤的筛选器。**保存**和阶段 1 的预览会拒绝此类名称并指出它。

点击**保存**。规则会在下次**加载**时生效，或在您点击 **Apply changes** 时生效。如果您手动编辑过某个分摊步骤，您的编辑会被保留而不会被覆盖，保存时会指出该步骤。加载运行期间无法保存。

## 董事会资料包

董事会资料包会把您的结果写入文档账户中的某个文件夹，随时可以发送。在**报表**页面上，点击**董事会资料包**卡片上的**董事会材料包设置**，选择**文档账户**和**文件夹**（例如 `/board-packs`），然后点击**保存**。此后每次**加载**都会生成资料包，因此文件夹中的文件与最近一次加载保持同步。每次运行会写入：

- 一个 Excel 工作簿 `Board pack.xlsx`，包含 **Profit and loss**、**Balance sheet** 和 **Cash flow** 三个工作表：按实体列出每个月和每个明细项，并包含抵销和集团合计。只有一个实体的项目没有抵销行或集团行。
- 一份 **CFM-Finance - Statements** 仪表板的 PDF。

该仪表板构建完成后，同一卡片上的**打开董事会材料包**会将其打开。

点击**立即运行**可立即生成资料包；完成后其文件会出现在文件夹中。对话框会显示上次运行及其结果，以及下次运行。**应用更改**不会生成资料包。若要按计划生成，请为**加载**设置计划（请参阅[保持数据最新](#保持数据最新)）；在此之前，对话框会显示**尚未安排。每次加载都会生成董事会资料包：设置夜间刷新即可每晚生成。** 只有能更改项目的人才能设置。

无法完整生成的资料包绝不会导致加载失败：

- 如果您的工作区已关闭报告功能，资料包就只有 Excel 工作簿，运行结果会显示 **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- 如果他人创建的某个仪表板已占用了 Data Foundation 为财务报表仪表板所需的地址，该仪表板会保持原样，不会生成 PDF。消息会指出该地址；请在 Superset 中为另一个仪表板改用其他地址，然后再次运行**加载**。
- 如果资料包的任何步骤失败，对话框中的上次运行会显示**失败**。加载本身仍然成功。

## 还原点

每次**加载**或 **Apply changes** 开始时都会创建一个还原点，无论由谁启动，包括计划加载，并且在每次更改映射或源之前也会创建。它保存模型的表、维度，以及下次加载据以构建的设置：您的源、文件和分摊规则。系统保留为加载创建的最近七个还原点，以及在更改前创建的最近五个，因此更改不会挤掉为加载创建的还原点。更早的还原点会被淘汰。

若要回退，请打开**摘要**上的**操作 ▾ > 还原…**。每个还原点都会显示创建时间，其下方显示还原它会带回多少张表，例如 **Puts back 12 tables.**，并用一条说明指出它会保持哪些内容不变。选择一个还原点并点击**还原**。存在还原点后才提供**还原**。还原时，会先把项目当前的状态记录为一个独立的还原点，因此您可以再次回退。然后它会把表、维度和这些设置恢复到原来的样子，下次加载会基于它们构建。还原到您已有的源时，不会将其标记为已更改。还原到添加连接器或文件源之前创建的还原点，会移除该源已落地的表，并在警告中点名该源。如果您撤消该还原，加载会再次拉取连接器源的表，而对于文件源，您需要再次确认该文件。如果某个源的表无法移除，警告会说明它们会保留在该源的文件夹中，直到您手动删除，其余部分仍会还原。视图、无法保存的维度或没有已保存副本的表会在警告中点名，其余部分照常还原。已被淘汰的还原点会被拒绝，加载运行期间也无法还原。

## 克隆项目

**摘要**上的**操作 ▾ > 克隆…** 会以您给定的名称复制项目。副本保留模板、您对模型所做的修改以及您的指标和分析路径，并加载示例数据。其源未连接，因此请在副本中先连接它们再加载。副本生成期间您可以继续工作，准备就绪后，**打开项目**会带您前往。

## 另存为我的模板

保存项目的设置，以便用于下一个客户或实体。打开**摘要**上的**操作 ▾ > 另存为我的模板…**，选择文档账户并为文件命名。如果您省略了扩展名，会自动添加以 `.zip` 结尾的名称。覆盖已有文件会被拒绝，因此请选择另一个名称。

该文件包含项目的结构、您对模型所做的修改、指标和分析路径、实体和科目的业务名称，以及模板配置表的行，例如 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/) 的活动映射或 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/) 的政策区间。它不包含连接、文件、每晚计划、运行记录、还原点、董事会资料包以及谁拥有访问权限。

使用时，请创建项目，在**起始来源**下选择**从模板文件创建**，然后选择文档账户和路径。新项目仅您可见，所有源都等待连接。之后模板发布新版本时，会围绕您编辑过的步骤合并其更改。如果该路径下没有文件，则不会创建任何内容，并会通知您。任何能读取该文档账户的人都可以从该文件安装。若要在另一个工作区中使用，请下载该文件并上传到那里。

## 用 Ask 解决未决问题

加载之后，项目可能仍在等待您告知三件事：会计科目表中未设置类型的科目、多个源使用的代码，以及文件中未匹配到任何内容的列。请让助手来解决：通过 MCP 从 AI 助手使用 **Resolve Data Foundation residue** 提示。它会读取待处理的内容，并为每一项提出一个答案及理由。

助手不会写入任何内容。Weave AI 聊天也可以说明项目正在等待什么（请参阅 [Weave AI 聊天](/zh-cn/guides/ai-assistant/weave-tab/#data-foundation)），通过 MCP 连接的代理还可以自行读取并回答这些问题（请参阅[通过 MCP 连接的 AI 代理使用 Data Foundation](/zh-cn/integrations/ai-coding-agents/data-foundation/)）。您需要在本该由自己回答的位置应用它的答案：科目和代码在**问题**页面上，文件列则在文件的映射中。它绝不会提议实体。**问题**上的问题可能已带有 Weave 自己的建议；请参阅 [Data Foundation 页面](#data-foundation-页面)。

## 移交项目

当项目是为他人（例如客户）设置时，请以下列步骤收尾：

- **保持数据最新。** 为**加载**设置计划。请参阅[保持数据最新](#保持数据最新)。
- **共享项目。** 在项目的**访问与共享**页面上为团队授予访问权限。请参阅[管理项目访问权限](/zh-cn/guides/projects/managing-projects/#管理项目访问权限)。
- **保留记录。** **摘要**上的**操作 ▾ > 下载证据包**会下载一个 Excel 工作簿，其中包含 **Status**、**Sources**、**Coverage**、**Mappings**、**Consolidation**、**Reconcile** 和 **Last load** 工作表：加载了什么、来自何处、代码如何映射、集团是否一致，以及上次加载的情况。它遵循下载者的行访问权限，在项目中拥有角色的任何人都可以下载。
- **移交项目。** 将所有者设为项目的架构师，然后将自己从成员中移除。有些选择只能由架构师做出，例如让所有人查看集团结果，或将 Data Foundation 添加到项目。

## 使用模板在模型基础上构建

模板在 Common Finance Model 之上构建其报表和模型，因此无论由哪些 ERP 提供数据，它们的运作方式都相同。当您从模板（例如 **Enterprise Profitability**）启动项目时，它会创建：

- [Common Finance Model 表](#common-finance-model-表)，为空或填充了示例数据。
- 由这些表构建的**实体**、**科目**、**部门**、**客户**、**产品**、**Segment 1** 和 **Segment 2** 维度。请参阅[层次结构](#层次结构)。
- **加载**工作流，以及它为读取 ERP 和文件、整合数据、检查就绪状态和构建模板模型而运行的工作流。
- 模板自己的报表和模型。**Enterprise Profitability** 会添加一个损益表，包含收入、COGS、毛利、直接和间接运营费用、边际贡献和营业利润率，以及同比和对预算的利润桥。
- 用于就结果提问的指标和一条分析路径。

在**起始来源**下，**Data Foundation** 是单独的模型及其报表。三个解决方案各自包含 Data Foundation 并添加自己的模型，并会在侧栏中显示**分摊**：

| 解决方案 | 新增内容 |
|---|---|
| **Enterprise Profitability** | 损益表和利润桥。 |
| **Cost to Serve** | 服务每位客户的成本，以及扣除后的利润率。请参阅 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/)。 |
| **Operational Transfer Pricing** | 每个实体的利润水平与您的政策区间的对比，以及补差调整。请参阅 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)。 |

**从模板文件创建**从您保存的项目开始。请参阅[另存为我的模板](#另存为我的模板)。

若要在连接自己的 ERP 之前先做探索，请在创建项目时勾选**从示例数据开始**。项目会立即运行第一次加载，因此**摘要**会显示一个完整的示例，其中包括折算为美元的欧元实体。当您连接自己的 ERP 或添加自己的文件时，示例数据会被移除，由您的数据取而代之。如果移除被中断，下次**加载**会完成它。您自己命名为 `sample` 的文件夹绝不会被移除，但当示例数据占用该文件夹时，其中的其他表不会被读取，因此请将它们移到名称不同的文件夹中。

关于收入类别或团队职能的问题不会暂扣任何内容。请参阅[收入类别和团队职能](#收入类别和团队职能)。

更改源后，每个页面上方会出现一条提示栏：**您更改了源。请点击“应用更改”以使用它们。** 该提示栏带有**显示更改内容**和**应用更改**，是应用更改的唯一位置。**加载**或**应用更改**的结果显示在当前打开的页面上方，因此每个页面都能看到。

加载运行期间，这些页面会自动刷新，即使某次读取失败也会继续读取。如果无法读取状态，会出现**无法读取基础数据状态。** 及**重试**，后者会重新读取；页面在显示该消息之前也会自行重试一次，服务器响应后该消息会消失。

## Common Finance Model 表

Data Foundation 将每个源（无论是 ERP 还是文件）整合到同样的表中，因此基于它们构建的报表、指标和模型无论数据来自何处，运作方式都相同。每一行还会记录其来源系统和读取时间。**数据集**列是您添加文件时选择的名称。

| 数据集 | 表 | 内容 |
|---|---|---|
| 实体 | `cfm_entity` | 法人实体，含父级、本位币和集团货币、国家、区域和事业部。 |
| 代码映射 | `cfm_code_map` | 从源所带代码（例如实体、科目或部门代码）到标准代码的对照。请参阅[实体对照表](#实体对照表)和[跨源映射代码](#跨源映射代码)。 |
| 汇率 | `cfm_fx_rate` | 按货币对列示的月度平均、期末和历史汇率。请参阅[汇率](#汇率)。 |
| 财务日历 | `cfm_fiscal_calendar` | 每个实体会计期间一行，含起止日期以及是否已结账。 |
| 会计科目表 | `cfm_account` | 科目，含父级、类型（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、报表、正常余额、汇率类型、科目角色和收入类别。角色（例如现金、应收、应付或留存收益）决定科目在其报表和现金流量表中所在的行。 |
| 部门 | `cfm_department` | 部门和成本中心，含父级、利润中心和职能。 |
| 利润中心 | `cfm_profit_center` | 利润中心，含父级和职能。 |
| 产品 | `cfm_product` | 产品主数据，含父级、系列、分组、计量单位、标准成本和收入类别。 |
| 客户 | `cfm_customer` | 客户主数据，含父级、分组、区域和国家。客户名称不会被屏蔽。 |
| 分部值 | `cfm_segment` | 分部值，含名称和父级。请参阅[层次结构](#层次结构)。 |
| 总账 | `cfm_gl_journal` | 以交易货币、本位币和报告货币列示的日记账明细行。 |
| 试算平衡表 | `cfm_trial_balance` | 按实体、科目和部门列示的期间借方、贷方和净额，以本位币和报告货币列示。 |
| 销售明细行 | `cfm_sales_line` | 已开票的销售明细行，含数量、毛额、折扣、净额和 COGS 金额。 |
| 销售管道 | `cfm_opportunity` | 销售管道：每个商机明细行一行，涵盖任何阶段，每个月末保存一份副本。 |
| 库存余额 | `cfm_inventory_balance` | 按产品和仓库列示的期末库存。 |
| 预算 | `cfm_budget` | 按方案、版本、科目和部门列示的预算和预测。 |
| 按估值的 CO-PA | `cfm_copa` | SAP 获利能力分析（CO-PA），按实体、期间、科目、产品和客户列示，每种估值（法定、集团或利润中心）各一组行，绝不相加。收入为正，成本为负。在各模板中，只有 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/#co-pa-利润率) 会读取它。 |
| 分摊动因 | `cfm_stat_driver` | 统计动因，例如人数、平方英尺或单位数。 |

模型还包含子分类账及其主数据，由带有这些数据的系统填充：

| 表 | 内容 |
|---|---|
| `cfm_site` | 站点：工厂、仓库位置或办公室，各属于一个实体。 |
| `cfm_supplier` | 供应商主数据。 |
| `cfm_sales_rep` | 销售代表主数据。 |
| `cfm_project` | 项目主数据。营销活动也是一个项目。 |
| `cfm_standard_cost` | 按产品、成本核算实体和期间列示的单位标准成本。 |
| `cfm_system_balance` | 每个系统自身在每个月末按科目列示的期末余额，从其余额报表读取，绝不从日记账明细行读取。 |
| `cfm_supplier_invoice_line` | 供应商发票明细行。 |
| `cfm_purchase_order_line` | 采购订单明细行，每个月末保存一份副本。 |
| `cfm_open_item` | 未清应收款和应付款，每个月末保存一份副本。 |
| `cfm_payment` | 收到和支付的款项。 |
| `cfm_order_line` | 销售订单明细行，每个月末保存一份副本。 |
| `cfm_asset` | 固定资产登记册。 |
| `cfm_asset_movement` | 按账簿和期间列示的资产变动：增加、折旧、处置和转移。 |
| `cfm_contract` | 合同和订阅，每个月末保存一份副本。[合同登记表](#合同登记表)会复制到每个合同期所跨的每个月末。 |
| `cfm_deferred_revenue_movement` | 按合同和期间列示的递延收入变动。 |
| `cfm_bank_balance` | 银行账户及其月末账面余额。 |
| `cfm_inventory_movement` | 库存变动：入库、出库、生产、转移、调整和核销。 |

每个月末保存一份副本的表，会在每次加载时替换未结账月份的副本。单据表带有 `counts` 列：对于计入的行（来自为其实体和月份计入的系统，以及项目报告所用的账簿）为 `1`，对于从其他系统或账簿保留下来的行为 `0`。报表和指标只读取计入的行。

Foundation 项目自带[项目元素](/zh-cn/guides/projects/data-model/)，用于这些表共享的列：`entity`、`account`、`department`、`profit_center`、`product`、`customer`、`period`、`site`、`supplier`、`sales_rep` 和 `project`。每个元素都带有说明，并在适用时带有类型和维度，因此凡是包含其中某一列的表，都会显示相同的含义。Data Foundation 会添加项目缺少的任何元素，而对您已编辑过的元素则保持原样。这适用于每个 ERP 和文件来源。

期间写作 `YYYY-MM`，交易按过账期间归属。预算是可选的：没有预算的 ERP 仍会加载其他所有内容。

试算平衡表文件可以带借方和贷方列、净额列，或两者都带。只有借方和贷方时，净额为借方减贷方，空白的一侧按零计算。只有净额时，正的净额记为借方，负的净额记为贷方，以正数表示。部门列是可选的。

## 故障排除

| 现象 | 处理办法 |
|---|---|
| **测试连接**提示 ERP 拒绝了凭据 | 检查连接的凭据，并确认集成用户可以登录 ERP。 |
| **测试连接**对某个数据集显示**缺少权限** | 请 ERP 管理员添加其列出的权限。您 ERP 的[连接指南](/zh-cn/guides/connections/)列出了连接所需的内容。 |
| ERP 的错误消息比 ERP 自身的更短 | PlaidCloud 在显示提供方的错误之前会移除其中的凭据、令牌和密钥，因此部分细节会被省略。运行**测试连接**可查看受影响的数据集。 |
| 某个期间的 **Every month loaded** 未通过 | 该期间的 ERP 读取失败。再次运行**加载**；已加载的期间会被跳过。 |
| **Every account known** 未通过 | 将缺失的科目添加到 ERP 或您文件中的会计科目表，然后再次运行**加载**。 |
| **Every amount has a rate** 未通过 | 某个实体的货币在该期间没有折算为报告货币的汇率，或未找到唯一的报告货币。请将汇率添加到**汇率**文件中，检查连接能否读取 ERP 的汇率，或设置项目变量 `reporting_currency`。然后再次运行**加载**。 |
| **Every amount has a rate** 为提醒 | 资产负债表、库存或预算行在该期间没有期末、历史或计划汇率。损益表不受影响。请添加汇率（包括预算月份的计划汇率），然后再次运行**加载**。 |
| **Codes mapped** 未通过 | 打开**问题**并回答每个问题。回答在下一次**加载**或**应用更改**时生效。 |
| **One source for each key** 未通过 | 在**摘要**上的**数据源覆盖范围**下，选择月份和源，点击**保存选择**，然后点击**应用更改**。 |
| 集团内部往来检查为红色或琥珀色 | 检查 **Intercompany pairs** 中的各对交易。记录缺失的一方，为明细行添加交易伙伴，或补充缺失的汇率。 |
| **Group views are off** | 请架构师在**项目设置**的**集团与行访问权限**下勾选**项目中的所有人都可以查看集团结果**。 |
| 计划加载被跳过 | 设置计划的人不能再使用某个系统的连接。请重新设置计划。请参阅[保持数据最新](#保持数据最新)。 |
| **Every entity known** 未通过 | 将该实体添加到实体主数据，或在**代码映射**文件中将其代码映射到现有实体，然后再次运行**加载**。 |
