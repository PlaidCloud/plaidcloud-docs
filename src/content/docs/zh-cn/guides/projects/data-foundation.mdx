**Data Foundation** 是 PlaidCloud 项目的财务数据基础。其 **Common Finance Model** 将来自多个 ERP 系统（以及每个系统的多个实例）的 ERP 数据汇集到单一模型中：统一的会计科目表、统一的实体集和统一的报告货币。基于该模型构建的报表、指标和 AI 助手读取的是同一组数字，无论这些数字来自哪个 ERP。

ERP 通过其 PlaidCloud 连接接入，因此总账、试算平衡表、主数据和预算直接从源系统到达，无需导出。文件用于补充系统中没有的数据，例如汇率、分摊动因或保存在 ERP 之外的预算，也可以替换其所覆盖的 ERP 行。**加载**会将每个源整合到模型中，折算为报告货币，并检查数据是否一致，这一切都在项目的**基础数据**选项卡中完成。如果多个源对不同的事物使用了相同的代码，由您说明它们是否含义相同；管理合并则会生成已抵销公司间交易的集团损益表。模板（例如 **Enterprise Profitability**）在此基础上构建各自的报表和模型。

## 连接 ERP

ERP 通过其 PlaidCloud 连接接入 Data Foundation。Data Foundation 直接从中读取总账、试算平衡表、主数据、汇率和预算，并且只读取。您可以选择现有连接，也可以在选项卡上创建连接。每个系统都有一页面向授予访问权限的管理员，列在[哪些系统可以为模型提供数据](/zh-cn/guides/projects/data-foundation-getting-started/#哪些系统可以为模型提供数据)中；[Data Foundation 覆盖矩阵](/zh-cn/reference/data-foundation-coverage-matrix/)则显示每个系统直接提供哪些数据集。

<Steps>

1. 在 Analyze 中，打开**项目**并点击**新建项目**。输入名称，在**起始来源**下选择模板（例如 **Enterprise Profitability (template)**）而不是**空白项目**。点击**创建**。

   项目会在其**基础数据**选项卡中打开。在您共享之前，它仅对您可见，您是唯一的架构师。

2. 在**基础数据**选项卡中，为 ERP 选择现有连接，或选择**创建新连接**。每个现有连接会列出已使用它的工作流，或显示**暂无工作流使用**。

3. 对于新连接，输入**连接名称**，选择**环境**，并填写 ERP 连接所需的凭据。

   还没有凭据？表单会显示一份写给 ERP 管理员的现成访问请求。点击**复制请求**或**通过电子邮件发送请求**，将其发出，然后输入对方返回的值。

4. 点击**测试连接**。PlaidCloud 会登录并尝试读取每个数据集，然后将每个数据集列为**可读取**、**缺少权限**或**错误**。有缺失时，会列出需要请 ERP 管理员添加的权限。

5. 设置**历史月数**：要向前加载多少个月，范围为 1 到 120。默认值为 24。

6. 对于现有连接，勾选要加载的实体；全部不勾选则加载所有实体。非活动实体和抵销实体在您选择显示之前保持隐藏。然后点击**连接**。

7. 对于新连接，点击**连接**以创建它。然后勾选要加载的实体，再次点击**连接**保存。在此之前，将加载所有实体。

8. 要引入另一个 ERP 系统或另一个实例，请重复这些步骤，并在点击**连接**之前勾选 **Add this as another source instead of replacing the current one**。否则，新连接会替换当前的源。

</Steps>

连接完成后，卡片会显示项目加载所用的连接、环境、实体和历史月数。

每次加载只读取发生变化的数据：未结账期间和最近一个已结账期间会重新读取，已加载的已结账期间则保留。提高**历史月数**只会读取新增的月份。汇率、实体对照表或报告货币发生变化时，会重新读取受其影响的月份。

## 源

项目加载所用的每个 ERP 系统和实例都是一个源。**基础数据**选项卡中的**源**列表为每个源显示一行，按顺序列出其名称、上次加载时间、提供的行数以及所读取的报告账簿，例如 `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`。尚未加载的源显示 **not loaded yet**。您确认的文件同样是源。

在源上打开**高级**，可更改其使用方式：

| 设置 | 作用 |
|---|---|
| **名称** | 报表、映射问题和消息中用于该源的标签。 |
| **Place in the order** | 源的排名。当两个源覆盖同一公司的同一个月时，顺序靠前的源优先。 |
| **Reporting books, separated by commas** | 要读取的会计账簿，适用于保存多套账簿的系统。**All reporting books** 读取所有账簿。 |
| **公司**、**从 (2026-01)** 和 **至 (2026-12)** | 该源为每家公司提供的月份。月份留空表示没有限制。月份以年和月书写，例如 `2026-03`。 |

点击**保存**以保留更改。要删除某个源，请点击 **Remove this source** 并确认**移除**。从该源加载的所有内容都会被删除，您以后可以重新连接它。

更改源不会再次读取 ERP。在您点击 **Apply changes** 之前，**上次加载**卡片会显示 **Changes not applied yet**；点击后会基于已提取的数据运行一次加载：按新的顺序、映射、名称和文件重新整合各个源，并重建模型。如果还需要从 ERP 获取最新数据，请点击**加载**。

## 添加 ERP 之外的数据文件

文件用于补充 ERP 连接中没有的数据，例如汇率、分摊动因、[实体对照表](#实体对照表)或保存在 ERP 之外的预算。每个文件属于[Common Finance Model 表](#common-finance-model-表)下列出的某个数据集。

<Steps>

1. 在**文件**下，选择用于存储文件的**文档账户**。

2. 将 CSV 或 Excel 文件拖放到**将 CSV 或 Excel 文件拖放到此处**，或点击**选择文件**。文件会上传到文档账户的 `/foundation/` 文件夹。

   对于已在文档账户中的文件，输入其**文件路径**，例如 `/foundation/budget.csv`，然后点击**添加文件**。

   要每月读取新文件，可添加名称匹配的文件夹中的所有文件：输入文件夹，并指定 **File names that** 包含、开头为、结尾为、完全匹配或按模式匹配的内容，然后点击 **Add files**。其中子文件夹内的文件不会被读取。

3. PlaidCloud 读取文件并提出映射建议：

   - **检测到的分隔符、小数分隔符和日期。** 分隔符（逗号、分号、制表符或竖线）、小数分隔符和日期格式会自动检测。
   - **数据集**：文件所属的 Common Finance Model 表，根据文件名和列标题匹配。匹配不明确时，请从列表中选择。
   - **小数分隔符**：**句点(1,234.56)** 或**逗号(1.234,56)**。
   - **日期格式**：文件包含日期时显示。如果检测到的格式有误，请更改：`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY` 或 `MM/DD/YYYY`。
   - 由**文件中的列**、**类型**、**示例**和**去向**组成的网格。更改**去向**可将列送到其他字段，或设为**不加载**。

4. 回答文件引出的问题，例如 **Which company is this file for?**、**Which currency are the amounts in?**、**Are these amounts year-to-date or for the month?**、**Are the amounts shown in thousands or millions?** 或 **Are revenues shown as negative numbers?** 只有文件本身没有说明时，才会询问每个问题。

5. 检查每列的去向，然后点击**确认映射**。

</Steps>

适用时，文件上会出现以下选项：

| 选项 | 用途 |
|---|---|
| **Which source do these rows apply to?** | 将代码映射文件限定于一个源。**Every source** 将其应用于所有源。 |
| **Where does this file come from?** | 说明文件包含的是 **This project's own codes** 还是来自 **Another system**（由您命名，例如 `SAP Germany export`）。来自其他系统的文件会像 ERP 源一样检查共享代码。 |
| **Split … into … parts at each …**（在**高级**下） | 拆分包含多个值的单列（例如 `100-200-300`），并将每个部分送到各自的字段。 |
| **Which currency do you report in?** | 在项目尚无报告货币时设置报告货币。以三个字母书写，例如 `USD`。 |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 加载合并系统的结果，以便[核对](#与合并系统核对)集团损益表。 |

要将文件从项目中移除，请点击**文件**下该文件旁的**移除**，或其映射上的 **Remove this file**，并确认。其数字将在您下次点击 **Apply changes** 时从报表中消失。

当 PlaidCloud 无法自行确定数据集、小数分隔符或日期顺序时（例如文件中的日期既可能是日/月也可能是月/日），会在您确认之前要求您选择。为同一数据集添加第二个文件会替换第一个文件。如果后续文件的列与数据集不匹配，加载会指出文件和列，并提示您更正文件或其列名，或将步骤的 **Schema Mismatch** 设为 `union`。

可接受的文件包括 CSV、TSV 和 TXT 文本文件、Excel `.xlsx` 文件（从第一个工作表读取）以及 Parquet 文件。

<Aside type="note">
缺失或为空的文件永远不会中断加载。添加它时会提示暂无可映射的内容；加载完成时会给出指明路径的警告，该数据集保持为空。文件存在后，请重新添加。
</Aside>

## 加载数据

点击**加载**卡片或**上次加载**卡片上的**加载**。加载会读取已连接的 ERP 和已确认的文件，将它们整合到 Common Finance Model 中，折算为报告货币，运行就绪检查，并重建模板的模型。

- 一个项目同一时间只能运行一次加载。再次点击**加载**或 **Apply changes** 会提示已有加载正在运行，且加载运行期间无法更改源。
- 如果其他工作流使用同一个 ERP 连接，首次加载会列出这些工作流并要求您确认，因为加载会从 ERP 读取数据，可能拖慢这些工作流。点击**仍然加载**继续。
- PlaidCloud 升级后，架构师的**加载**还会更新项目生成的工作流，并创建它们所需的工作表。在此之前，状态页会显示一个琥珀色项目 “The workflows were generated by an earlier release. An Architect's Load updates them.”，管理者的**加载**则会警告只有架构师才能更新它们。
- 失败的加载以红色显示，绝不会隐藏在先前结果之后。如果合并失败，状态会指出它停止在哪个步骤，而不是显示旧的集团结果。来自较早加载的行会显示**来自较早的加载。请重新加载。**，直到加载成功。
- 如果某个实体和期间读取失败，其余部分仍会加载。再次运行**加载**即可只获取失败的部分。

### 被搁置的行

当多个源重叠时，加载会为每个数字保留一份，并搁置其余副本，而不是重复计算。被搁置的行会连同其源、实体和原因一并记录，加载结束时会给出一条列出数量的警告，例如 `120 rows of NetSuite EU also provided by a source ranked ahead`。原因如下：

| 原因 | 含义 |
|---|---|
| 在另一个会计账簿中 | 该行属于该源未设置读取的报告账簿。 |
| 超出该源提供的期间 | 该行不在为公司设置的**从**和**至**月份之内。 |
| 同时由排名靠前的源提供 | 顺序更靠前的源覆盖了同一公司和月份。 |
| 同时位于该源的较早文件中 | 同一源的较早文件已经覆盖该月。 |
| 被文件替换 | 文件替换了该实体和月份的 ERP 行。 |
| 带有另一个源也使用的代码 | 该代码需要您回答。请参阅[跨源映射代码](#跨源映射代码)。 |
| 带有映射到两个代码的代码 | 代码映射给该代码提供了两个答案。 |

统计科目会转入分摊动因而不是总账，并显示为已转移，而不是问题。

### ERP 数据与文件并用

文件只替换其覆盖的内容，ERP 的其他行保持不变。

- **主数据文件**（科目、部门、客户、产品和分部值）会替换代码相同的 ERP 行。
- **交易文件**会替换同一实体和月份的 ERP 行。总账和试算平衡表文件还按账簿匹配，预算文件按方案匹配，统计动因文件按方案和动因匹配。

如果某个文件之后不再覆盖某个月，下次加载时该月将恢复使用 ERP 的数据。

## 实体对照表

每个源用自己的代码命名实体。**实体对照表**将这些代码映射到实体主数据中的实体，使所有源的行落在同一个实体上。

要使用它，请添加 CSV 或 Excel 文件，并选择**实体对照表**数据集：

| 列 | 内容 |
|---|---|
| `source_entity` | 源所携带的代码，例如公司代码。 |
| `entity` | 它所属的实体，与实体主数据中的名称一致。 |

- 不在对照表中的代码按原样使用。
- 多个代码可以映射到同一个实体。它们的行会合并，且只有当所有这些代码都已结账时，该月才算已结账。
- 对照表中的代码适用于每个源，因此各源的实体代码在所有源之间必须唯一。
- **实体**文件中的一行会替换 ERP 中实体代码相同的实体。

**未映射的实体**检查会标记实体既不在实体主数据中、也未通过实体对照表映射到某个实体的任何行。在加载实体主数据之前，它显示 **– 不适用**。

## 跨源映射代码

两个源可能对不同的事物使用相同的代码，或对同一事物使用不同的代码。当一个代码出现在多个源中时，Data Foundation 会搁置其行，直到您说明它在各处是否含义相同，从而使每个金额只计算一次。**Codes waiting for your answer** 检查会列出这些代码，先列出前 10 个，然后是 “and K more”；**基础数据**选项卡上的 **What to do next** 卡片有一个**审核**按钮。

**审核**会打开 **Codes waiting for your answer**。它按代码的性质分组：**Account types**、**Companies**、**账户**、**部门**、**利润中心**、**客户**、**产品**以及每个额外类别。对每个代码，它会显示各个源对其的称呼和一条建议：

- 各源给代码相同的名称时，显示 **Looks like the same thing**。
- 名称不同时，显示 **Looks like different things**。
- 没有任何依据时，显示 **We can't tell. Please answer.**

可逐个代码回答 **Yes, the same** 或 **No, different**，也可以用 **Accept all**（采纳所有建议）、**All the same** 或 **All different** 一次回答整个分组。对于科目，还可以一次回答会计科目表中的整个父级分组。如果某个源不携带科目类型，请为一组科目选择 **Use this type**：**Revenue**、**Cost of goods sold**、**Operating expenses**、**Non-operating income and expenses**、**Assets**、**Liabilities** 或 **Equity**。

映射按源和维度保存，因此对一个源的部门所做的回答绝不会改变另一个源的科目。回答会随时保存，并提示 **Saved. Press Apply changes to use your answers.** 点击 **Apply changes** 使用这些回答。

您也可以通过文件提供映射。添加一个使用 **Code map** 数据集的文件，并选择 **Which source do these rows apply to?** 以将其限定于一个源。

## 选择哪个源从何时起生效

当两个源提供相同的月份时，**Which source covers which months** 检查会要求您选择。点击 **What to do next** 卡片中的 **Choose which source counts from when** 以打开 **Which source counts from when**，其中按公司列出每处重叠。选择生效的源，在 **That month is** 中输入其生效的起始月份，例如 `2026-04`，然后点击 **Apply changes**。另一个源保留较早的月份。

当两个源为某种货币给出不同的汇率时，同一对话框也会发出警告；此时使用顺序靠前的源的汇率。

## 货币折算

每次加载都会将总账、试算平衡表、销售、库存和预算金额从本位币折算为一种报告货币。报表和模型读取折算后的金额，因此不同货币、来自任何系统的实体都能正确汇总。

### 报告货币

要选择报告货币，请将项目变量 `reporting_currency` 设置为货币代码，例如 `USD`。请参阅[管理项目变量](/zh-cn/guides/projects/managing-projects/#管理项目变量)。模板创建时该变量为空。在其为空时，每次加载使用以下各项中第一个恰好指向一种货币的：

1. 实体的集团货币。
2. 顶级实体（没有父级的实体）的本位币。
3. 文件的本位币。

如果其中没有任何一项恰好指向一种货币，**货币折算**会显示问题，直到您设置 `reporting_currency`。

已经是报告货币的金额保持不变，因此数据全部使用同一种货币的项目不需要汇率。

销售、库存和预算文件也可以携带货币。映射名为 `Currency` 或 `Local Currency` 的列即可自动识别，文件中的本位币金额会折算为报告货币。文件中已有的集团金额或报告金额则原样保留。产品标准成本不做折算。

### 汇率

汇率将一个单位的某种货币折算为某个月的报告货币：折算后的金额等于本位币金额乘以汇率。

- **来自 ERP**：每次加载都会读取 ERP 持有的汇率。
- **来自文件**：添加 CSV 或 Excel 文件并选择**汇率**数据集。文件中的汇率会替换 ERP 中相同货币和月份的汇率。如果要用 ERP 不发布汇率的货币进行报告，或为预算月份添加计划汇率，请使用文件。

| 列 | 内容 |
|---|---|
| `from_currency` | 折算的源货币，例如 `EUR`。 |
| `to_currency` | 报告货币，例如 `USD`。 |
| `period` | 月份，格式为 `YYYY-MM`。 |
| `average_rate` | 当月平均汇率。 |
| `closing_rate` | 月末汇率。 |
| `historical_rate` | 历史汇率，用于权益以及设置为历史汇率的科目。 |

只使用折算为报告货币的汇率。反向报价的汇率（从报告货币折算为其他货币）不会取倒数。

### 适用哪种汇率

每一行都按其自身的货币折算，因此与其实体货币不同的行，按其所用的货币折算。第一条符合该行的规则适用：

| 行 | 汇率 |
|---|---|
| 统计科目和非过账科目 | 不折算。 |
| 已经是报告货币 | 不折算。 |
| 带有汇率类型的科目 | 该汇率：平均汇率、期末汇率或历史汇率。没有历史汇率时，历史汇率回退为期末汇率。来自 ERP 时，汇率类型是科目自身的汇率类型。在会计科目表文件中，将汇率类型列映射到 `fx_rate_type`，取值为 `average`、`closing` 或 `historical`。 |
| 销售行 | 该期间的平均汇率。 |
| 库存余额 | 该期间的期末汇率。 |
| 预算行 | 按科目处理，与总账相同：损益科目使用平均汇率，资产负债表科目使用期末汇率。 |
| 损益科目 | 该期间的平均汇率。 |
| 权益科目 | 历史汇率；没有历史汇率时使用期末汇率。 |
| 其他任何资产负债表科目 | 该期间的期末汇率。 |

折算后的金额不做四舍五入，因此合计不会产生漂移。

<Aside type="note">
试算平衡表保存的是每个期间的发生额，因此资产负债表金额是每个月的发生额按当月期末汇率折算的结果。它们不是按期末汇率重新折算的资产负债表，也没有累计折算调整或公司间抵销。请使用折算后的金额来编制损益表。
</Aside>

## 层次结构

每次加载都会根据所有源的主数据重建维度。起初有七个维度，以及最多十个额外类别：

| 维度 | 构建自 |
|---|---|
| **实体** | 实体及其父级 |
| **科目** | 会计科目表和父级科目 |
| **部门** | 部门及其父级 |
| **客户** | 客户及其父客户 |
| **产品** | 产品及其父产品 |
| **Segment 1** | `segment_1` 的分部值 |
| **Segment 2** | `segment_2` 的分部值 |
| **Segment 3** 至 **Segment 10** | `segment_3` 至 `segment_10` 的分部值（当您的源携带它们时） |

- 没有父级的记录，或把自己指定为父级的记录，会作为顶级成员加载。
- 由于每次加载都会重建层次结构，请在 ERP 或文件中更改父级，而不要在维度中更改。
- 一个层次结构中的问题只影响该维度。加载和模板的模型仍会完成。
- 您可以将每个额外类别重命名为它所包含的内容，例如 **Class** 或 **Region**。在 **Rename extra categories** 下，输入报表所用的名称并点击 **Save names**。名称可使用字母、数字、空格、点、短横线和下划线，最长 60 个字符。
- 每个源会说明它自己的每个额外类别归入您的哪个类别名称之下。在源上打开**高级**，为每个类别选择名称，或选择 **Leave out**，然后点击**保存**。这样，对同一类别使用不同名称的源（例如 `Class` 和 `Business area`）会共用一个位置。

要通过文件提供分部层次结构，请选择**分部值**数据集：

| 列 | 内容 |
|---|---|
| `segment` | 该值所属的分部：`segment_1` 至 `segment_10`。 |
| `segment_value` | 值，与总账、销售和预算行所携带的一致。 |
| `segment_value_name` | 其名称。 |
| `parent_segment_value` | 其在同一分部内的父级。 |

## 就绪检查

每次加载之后，**就绪状态**网格会列出每个实体和期间的每项检查，状态如下：

| 状态 | 含义 |
|---|---|
| **● 就绪** | 检查通过。 |
| **▲ 需要关注** | 值得查看，但数字可用。 |
| **■ 问题** | 在依赖结果之前请先修复。 |
| **– 不适用** | 此检查暂无数据。 |

检查项如下：

| 检查 | 确认内容 |
|---|---|
| **数据已加载** | 每个会计期间都有总账行，且每次 ERP 读取都已成功。没有行的已结账期间属于问题；没有行的未结账期间需要关注。 |
| **试算平衡表与总账一致** | 每个实体、期间和科目的试算平衡表都等于总账。如果某个科目在试算平衡表和总账中都携带部门，还会逐个部门核对。 |
| **销售与总账一致** | 每个期间的销售行都等于总账的收入和 COGS 科目。 |
| **未知产品/客户** | 每条销售行所指的产品和客户都存在于产品主数据和客户主数据中。 |
| **科目表中缺失的科目** | 每条总账行所指的科目都在会计科目表中。带有未知科目的行不计入损益表。有过账但没有科目类型的科目也属于问题；某个源的科目表中已为收入科目指定类型，但没有销货成本科目时，需要关注。 |
| **货币折算** | 每条总账、试算平衡表、销售、库存和预算行都有报告货币金额。没有汇率的损益行或销售行属于问题，因为损益表读取折算后的金额。没有汇率的资产负债表、库存或预算行需要关注。尚无汇率的预算月份显示为琥珀色，因此请为预算月份加载计划汇率。请参阅[货币折算](#货币折算)。 |
| **未映射的实体** | 每条总账、试算平衡表和销售行所指的实体，都直接或通过实体对照表存在于实体主数据中。在加载实体主数据之前不适用。请参阅[实体对照表](#实体对照表)。 |

包含多个源的加载会增加以下检查：

| 检查 | 确认内容 |
|---|---|
| **Reporting book** | 为某个实体携带多个会计账簿的源已选择报告账簿。在您选择之前，只有第一个账簿计入。 |
| **Codes waiting for your answer** | 被多个源使用的每个代码都已得到回答。请参阅[跨源映射代码](#跨源映射代码)。 |
| **Extra categories from your sources** | 源携带的每个额外类别都有名称或已被排除。 |
| **Which source covers which months** | 除非您选择了哪个源生效，否则没有两个源提供同一公司的相同月份。 |
| **Account types and hierarchy** | 维度所指的每个父级都存在，且没有成员是其自身的父级或祖先。缺失的父级会使其子级位于层次结构顶部，循环则会使该层次结构无法加载。合计不受影响。 |
| **财务日历** | 每个实体的会计期间都是日历月，且每个月的行都可归入某一个会计期间。当某个实体的期间不是日历月（4-4-5、13 个期间），或某个月的行可能属于多个会计期间，或财务日历缺少该月时，需要关注。 |

每个未就绪的行都会在**操作**列中说明该怎么做，例如加载会计科目表、加载汇率，或针对某个期间再次运行**加载**。

网格还会显示两项设置检查，仅在需要关注时出现：

| 检查 | 出现时机 |
|---|---|
| **间接费用分摊** | 项目变量 `overhead_department` 和 `overhead_driver` 中只设置了一个，或没有分摊动因与 `overhead_driver` 匹配，导致分摊不会产生任何效果。请同时设置二者，或同时清除二者以关闭间接费用分摊。 |
| **预算对比** | 已加载预算行，但没有任何一行属于项目变量 `budget_version` 所指定的版本，因此预算对比将为空。 |

## 管理合并

每次加载都会生成一份管理合并：集团内所有实体的集团损益表，以报告货币列示，并已抵销公司间交易。它用于管理报告。法定集团的账务记录仍以您的合并系统为准；请在下文与其核对。

<Aside type="note">
管理合并仅涵盖损益表。它不是法定合并或法律合并，没有合并资产负债表、折算调整、商誉或少数股东权益。
</Aside>

### 选择集团

在**源**下，打开 **Group** 查看集团内的公司。您清除勾选的公司仍会单独出现在报表中，但不计入集团合计。点击 **Save group**。更改将在下次**加载**或 **Apply changes** 时生效。新公司在您清除勾选之前都属于集团。

集团的会计年度从项目变量 `group_fy_start_month` 所设置的月份开始，除非您更改，否则为 `1`。

### 您会得到什么

| 表 | 内容 |
|---|---|
| **Group P&L** | 每个实体、期间和行（收入、销货成本、运营费用、非经营项目、公司间差异）一行，以报告货币列示。收入和成本保留其自然符号。 |
| **Group P&L year to date** | 同上，为本年累计，截至集团最后一个完全加载的期间。 |
| **Intercompany pairs** | 每对实体、集团和期间一行，包含双方的金额和残差。 |
| **Intercompany lines** | 集团数字或某一对背后的总账行，含交易伙伴。 |
| **对账** | 集团损益表本年累计与您的合并系统的对比。 |

这些表中会出现三个实体名称：

| 实体 | 含义 |
|---|---|
| **Eliminations** | 公司间抵销。它们的净额为零，因此集团数字应保留它们，而在计算抵销前的各实体合计时应将其筛选掉。 |
| **Group total** | 对账中合并系统的合计。 |
| **Unmapped** | 没有期间的行，以及合并系统中有而本项目没有的科目或实体。 |

指标 **Consolidated income**、**Consolidated result** 和 **IC difference**，以及每个表对应的分析路径，可用来回答有关集团的问题。

### 公司间抵销

公司间的行按交易伙伴匹配。使用行上的伙伴；行上没有伙伴时，使用其客户的伙伴。一对交易的双方都会被抵销，双方不一致的金额会记入公司间差异行。每一对都会得到一个原因：

| 原因 | 含义 |
|---|---|
| **已匹配** | 双方记录的金额相同。 |
| **Only one side booked** | 一个实体记录了交易，而其伙伴没有记录。 |
| **Not eliminated** | 该对中的某一行没有汇率，因此双方都不抵销。 |

一对交易按其本年累计进行判断。当某一对的差异超过项目变量 `group_amber`（默认 `1`）时，**Intercompany balances** 行变为琥珀色；超过 `group_red`（默认 `1000`）时变为红色。没有伙伴的行，或伙伴不是实体的行，不会被抵销，并计入该行。一个源携带伙伴而另一个源不携带时，显示为琥珀色。

某个源自己的抵销实体不计入集团损益表，**合并**行会说明这一点。

### 与合并系统核对

将合并系统报告的结果作为文件添加，并在确认其映射时勾选 **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)**。用系统名称回答 **Which version of the numbers is this?** 之后，**对账**表会按本年累计为每个实体和行显示 **ours**、**reported** 和**差异**。差异通常可以通过 **Eliminations**、**Group total** 和 **Unmapped** 行，或系统所用的汇率来解释。**Reconciliation to the source** 行会列出所有超过 `group_amber` 的行。

### 谁可以查看

集团结果遵循项目的行访问权限。当行访问权限阻止了集团结果时，状态显示为琥珀色。只能看到部分实体的人看到的是这些实体抵销前的合计。**Eliminations** 行和公司间表需要拥有所有实体的访问权限。

如果项目按集团表不携带的列（例如部门）来限制谁能看到哪些行，则集团结果对所有人关闭，**合并**会显示 **Group views are off**。此时只有架构师可以勾选 **Group** 下的 **Everyone on the project may see the group results**。更改将在下次**加载**或 **Apply changes** 时生效。

## 保持最新

当 ERP 连接的加载无任何问题地成功后，**上次加载**卡片上会出现**每晚刷新**。点击它即可每晚在您所在时区的 2:00 运行**加载**。卡片随后会显示 **Nightly refresh: Every night at 2:00** 以及设置者。

每晚加载以设置者的身份运行。如果该用户无法再使用 ERP 连接，网格会提示每晚加载被跳过；请重新设置。只有示例数据的项目无法设置计划。

每晚加载时缺失或为空的文件会以指明路径的警告结束，而不是错误，模型的其余部分仍会加载。

## 业务名称

**基础数据**选项卡上的 **Business names** 为模型中的代码提供您的业务所使用的名称。报表、指标和助手会显示这些名称，保存的名称立即生效。之后的加载会保留它。

1. 点击 **Add a name** 并选择**类型**：**Category**、**P&L line**、**Metric** 或 **Column**。
2. 输入**代码**：类别使用 `segment_1` 至 `segment_10`，损益行使用该行的键，指标使用指标名称，列使用 `table.column`。
3. 输入**名称**，单行，最多 60 个字符。
4. 点击 **Save names**。

保存会替换整个列表。名称为空的行会删除该名称，**移除所选项**会删除您勾选的行。为同一个代码命名两次会被拒绝。业务名称还会写入分析路径的描述，以便助手使用您的措辞，而该描述有长度限制：如果某个名称会使其过长，则不会保存任何内容，并会告知您。

## 解释数字

**Explain this number** 显示一个损益数字由什么构成。在**就绪状态**网格中，实体和月份所在的行有 **Explain this number**，它会打开该实体当月的营业利润率。窗口将数字拆分为多层，各层相加等于顶部的合计：

| 层 | 内容 |
|---|---|
| **From the general ledger** | 总账过账到该行的内容。 |
| **Allocated in** | 由您的[分摊规则](#分摊规则)分摊到该实体的成本。 |
| **Allocated out** | 该实体分摊给其他实体的成本。 |
| **Eliminated in the group** | 在集团结果中被抵销的公司间交易。 |

每一层都有一句说明它是什么的话，以及其最大的源单据，含源系统、单据和科目。只显示有行的层。窗口遵循您的行访问权限：您只能解释自己能看到的数字。背后没有内容的数字显示 **Nothing to explain**。

## 分摊规则

分摊把共同成本（例如间接费用）分摊到部门、产品和客户。模型分为两个阶段：**Stage 1: overhead to departments** 和 **Stage 2: departments to products and customers**。打开**操作 > 分摊...** 可查看或更改每个阶段的做法。不做更改时，它们的运作方式与向导出现之前相同。读者可以打开规则，但不能保存。

对于每个阶段，向导会提出四个问题：

| 步骤 | 问题 | 选项 |
|---|---|---|
| **Pool** | 您想分摊哪些成本？ | 科目的类型；对于阶段 1，还有承担该成本的部门，或 **All departments**。 |
| **驱动** | 您想按什么来分摊？ | 您作为分摊动因加载的 **Statistic**（例如人数或平方英尺）、**Net sales amount**、**Sales quantity** 或 **Spread evenly**。使用 **Same period** 或 **Same period last year** 的动因。 |
| **目标** | 它们落在哪里？ | 阶段 1：部门。阶段 2：产品、客户或两者。 |
| **方法** | 动因为负数时怎么办？ | **Ignore negative values** 或 **Stop and tell me**。 |

在这些步骤之下，**Preview for** 某个月（以年和月书写，例如 `2026-09`）会显示规则（包括您尚未保存的规则）将产生的结果：`Pool 120,000 · Allocated 120,000 · Unallocated 0`。任何未分摊的部分，都是没有动因承接的成本。预览遵循您的行访问权限。

点击**保存**。规则会在下次**加载**时生效，或在您点击 **Apply changes** 时生效。如果您手动编辑过某个分摊步骤，您的编辑会被保留而不是被覆盖，保存时会指出该步骤。加载运行期间无法保存。

## Board Pack

Board pack 按计划把您的结果写入文档账户中的文件夹，随时可以发送。打开**操作 > Board pack...**，选择**文档账户**和**文件夹**（例如 `/board-packs`），然后点击**保存**。每次运行会写入：

- 一个 Excel 工作簿 `Board pack.xlsx`，包含按实体划分的损益表、利润率桥接图，以及排名靠前和靠后的客户。
- 一份损益仪表板的 PDF。

如果项目还没有仪表板，则只写入工作簿，并且运行时会告知原因。点击 **Run now** 可立即生成一份；完成后其文件会出现在文件夹中。卡片会显示上次运行及其结果，以及下次运行。该 pack 由项目的 **Board pack** 工作流生成，每晚刷新不会运行它：若要按计划生成，请使用[事件计划程序](/zh-cn/administration/scheduled-events/event-scheduler/)为该工作流设置计划，例如设在每晚刷新完成之后的某个时间。只有能够更改项目的人才能设置。

## 还原点

每次**加载**或 **Apply changes** 开始时（无论由谁启动，包括计划加载），以及每次更改映射或源之前，都会创建一个还原点。它保存模型的表、维度，以及下次加载所依据的设置：您的源、文件和分摊规则。系统保留最近七个为加载创建的点和最近五个在更改之前创建的点，因此更改绝不会挤掉为加载创建的点。更早的点会被滚动清除。

要回退，请打开**操作 > 还原...**，选择一个点，然后点击**还原**。存在还原点后才会提供**还原**。还原时会先把项目当前的状态记录为一个独立的点，以便您可以再回退回来。然后它会将表、维度和这些设置恢复为原来的样子，下次加载将基于它们构建。没有已保存副本的表，或无法保存历史的引擎，会在警告中列出，其余部分照常还原。已被滚动清除的还原点会被拒绝，加载运行期间无法还原。

## 克隆项目

**操作 > 克隆...** 会以您指定的名称复制项目。副本保留模板、您对模型所做的编辑、您的指标和分析路径，并加载示例数据。它的源未连接，因此请在副本中先连接源再加载。复制期间您可以继续工作，准备就绪后，**打开项目**会带您前往副本。

## 另存为我的模板

保存项目的设置，以便用于下一个客户或实体。打开**操作 > Save as my template...**，选择文档账户，并为文件命名。如果名称未以 `.zip` 结尾，系统会自动添加。覆盖现有文件会被拒绝，因此请选择另一个名称。

该文件保存项目的结构、您对模型所做的编辑、指标和分析路径、实体和科目的业务名称，以及模板配置表的行，例如[Cost to Serve](/zh-cn/guides/projects/cost-to-serve/)的活动映射，或[Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)的政策区间。它不包含连接、文件、每晚计划、运行记录、还原点、board pack 以及访问权限。

要使用它，请创建项目，在**起始来源**下选择 **From a template file...**，并选择文档账户和路径。新项目仅对您可见，所有源都等待连接。之后模板发布新版本时，会围绕您编辑过的步骤合并其更改。如果该路径下没有文件，则不会创建任何内容，并会告知您。任何能读取该文档账户的人都可以从该文件安装。要在其他工作区中使用，请下载该文件并在那里上传。

## 使用 Ask 解决待办问题

加载之后，项目可能仍在等待您处理三类事项：会计科目表中没有类型的科目、被多个源使用的代码，以及文件中没有匹配任何内容的列。可以请助手来解决：通过 MCP 在 AI 助手中使用 **Resolve Data Foundation residue** 提示。它会读取待处理的内容，并为每一项提出一个答案和理由。

助手不会写入任何内容。您可以在自己本来会回答的地方应用它的答案：科目和代码在 **Codes waiting for your answer** 下，文件列则在文件的映射中。它从不提议实体。

## 移交项目

在**查看您的层级结构**之后，**设置**清单还有四个收尾项：

- 一旦**每晚刷新**开启，**Set up the nightly refresh** 即完成。
- 只要除设置项目的人以外还有其他成员，**与团队共享**即完成。
- 在最近一次成功加载之后下载该 pack，**Download the evidence pack** 即完成。
- 一旦存在除设置项目者之外的架构师且合计一致，**Hand the project over to its owner** 即完成。在其未完成时，清单会说明该怎么做：让客户的所有者成为此项目的架构师，然后将自己从成员中移除。

清单会说明是谁设置了项目（**Set up by**）。

## 使用模板在模型上构建

模板在 Common Finance Model 上构建其报表和模型，因此无论由哪些 ERP 提供数据，它们的运作方式都相同。当您从 **Enterprise Profitability** 等模板创建项目时，它会创建：

- [Common Finance Model 表](#common-finance-model-表)，为空或填充了示例数据。
- 基于这些表构建的**实体**、**科目**、**部门**、**客户**、**产品**、**Segment 1** 和 **Segment 2** 维度。请参阅[层次结构](#层次结构)。
- **加载**工作流，以及它运行的用于读取 ERP 和文件、整合数据、检查就绪状态并构建模板模型的工作流。
- 模板自己的报表和模型。**Enterprise Profitability** 增加了一张损益表，包含收入、COGS、毛利、直接和间接运营费用、边际贡献和营业利润率，以及同比和对比预算的利润率桥接图。
- 用于询问结果问题的指标和分析路径。

**起始来源**下有三个模板，每个都建立在同一个模型之上：

| 模板 | 增加的内容 |
|---|---|
| **Enterprise Profitability** | 损益表和利润率桥接图。 |
| **Cost to Serve** | 服务每位客户的成本，以及扣除后的利润率。请参阅 [Cost to Serve](/zh-cn/guides/projects/cost-to-serve/)。 |
| **Operational Transfer Pricing** | 每个实体的利润水平与您的政策区间的对比，以及补差调整。请参阅 [Operational Transfer Pricing](/zh-cn/guides/projects/operational-transfer-pricing/)。 |

**From a template file...** 从您保存的项目开始。请参阅[另存为我的模板](#另存为我的模板)。

要在连接自己的 ERP 之前先体验，请在创建项目时勾选**从示例数据开始**。项目会立即运行第一次加载，因此**基础数据**选项卡会显示一个完整的示例，其中包括折算为美元的欧元实体。当您连接自己的 ERP 或添加自己的文件时，示例行会被清除，由您的数据取而代之。

## “基础数据”选项卡

**基础数据**选项卡用于连接、加载和检查数据。它从上到下包含以下部分：

| 部分 | 显示内容 |
|---|---|
| **上次加载** | 上次加载是成功、失败还是仍在运行，以及**加载**、**Apply changes**、**刷新**和**每晚刷新**按钮。 |
| **What to do next** | 需要您关注的内容，按重要性排序，每项带有**审核**或 **Choose which source counts from when** 按钮。 |
| **源** | 按顺序列出的每个源，带有**高级**、**Remove this source**、**Group** 和 **Rename extra categories**。 |
| **设置** | 设置清单：**连接您的数据**、**加载您的数据**、**检查合计是否一致**、**查看您的层级结构**、**Set up the nightly refresh**、**与团队共享**、**Download the evidence pack** 和 **Hand the project over to its owner**。当前项以粗体显示。 |
| **Business names** | 您的业务用于类别、损益行、指标和列的名称。请参阅[业务名称](#业务名称)。 |
| **文件** | 您添加的每个文件、其数据集（例如**总账**或**汇率**），以及其映射是 **✓ 已确认**还是 **○ 等待确认**。 |
| **数据已加载** | 每个实体已加载的首个和最后一个期间，以及有多少个期间已就绪。 |
| **期间** | 每个实体的会计期间，以及每个期间是 **✓ 已关闭**还是 **○ 未结账**。 |
| **就绪状态** | 就绪状态网格：每个实体、期间和检查一行，含其状态和**操作**。 |
| 连接 | 连接 ERP，选择实体以及要加载的历史月数，或添加另一个源。 |
| **文件**（添加） | 添加 CSV、TSV、TXT、Excel 或 Parquet 文件，并确认其列如何映射。 |
| **加载** | 开始加载。**Apply changes** 运行一次加载，但不从 ERP 提取数据。 |

加载运行期间，选项卡会自动刷新。

设置清单会跟踪您的进度：

- 一旦附加了源且加载成功，**连接您的数据**和**加载您的数据**会自动打勾。
- 当检查合计是否一致的各项检查通过时，**检查合计是否一致**会自动打勾。
- **查看您的层级结构**：点击**打开维度**以查看实体、科目和部门层次结构，然后勾选**我已查看**。这一项由您自行确认。
- **Set up the nightly refresh**、**与团队共享**、**Download the evidence pack** 和 **Hand the project over to its owner** 位于清单末尾。请参阅[移交项目](#移交项目)和[管理项目访问权限](/zh-cn/guides/projects/managing-projects/#管理项目访问)。

**操作**菜单包含**分摊...**、**Board pack...**、**克隆...**、**还原...** 和 **Save as my template...**。请参阅[分摊规则](#分摊规则)、[Board Pack](#board-pack)、[克隆项目](#克隆项目)、[还原点](#还原点)和[另存为我的模板](#另存为我的模板)。

## Common Finance Model 表

Data Foundation 将每个源（无论是 ERP 还是文件）整合到同样的十五张表中，因此基于这些表构建的报表、指标和模型无论数据源是什么，运作方式都相同。每一行还记录其源系统和读取时间。**数据集**列是您添加文件时选择的名称。

| 数据集 | 表 | 内容 |
|---|---|---|
| 实体 | `cfm_entity` | 法人实体，含父级、本位币和集团货币以及国家。 |
| 实体对照表 | `cfm_entity_map` | 源实体代码及其所属实体。请参阅[实体对照表](#实体对照表)。 |
| 汇率 | `cfm_fx_rate` | 按货币对列示的月度平均汇率、期末汇率和历史汇率。请参阅[汇率](#汇率)。 |
| 财务日历 | `cfm_fiscal_calendar` | 每个实体的每个会计期间一行，含起止日期以及是否已结账。 |
| 会计科目表 | `cfm_account` | 科目，含父级、类型（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、报表、正常余额方向和汇率类型。 |
| 部门 | `cfm_department` | 部门和成本中心，含父级和利润中心。 |
| 产品 | `cfm_product` | 产品主数据，含父级、产品系列、产品组、计量单位和标准成本。 |
| 客户 | `cfm_customer` | 客户主数据，含父级、客户组、区域和国家。客户名称不做遮蔽。 |
| 分部值 | `cfm_segment` | 分部值，含名称和父级。请参阅[层次结构](#层次结构)。 |
| 总账 | `cfm_gl_journal` | 以交易货币、本位币和报告货币列示的日记账行。 |
| 试算平衡表 | `cfm_trial_balance` | 按实体、科目和部门列示的期间借方、贷方和净额，以本位币和报告货币列示。 |
| 销售明细行 | `cfm_sales_line` | 已开票的销售行，含数量、总额、折扣、净额和 COGS 金额。 |
| 库存余额 | `cfm_inventory_balance` | 按产品和仓库列示的期末库存。 |
| 预算 | `cfm_budget` | 按方案、版本、科目和部门列示的预算和预测。 |
| 分摊动因 | `cfm_stat_driver` | 统计动因，例如人数、平方英尺或数量。 |

期间的格式为 `YYYY-MM`，交易按过账期间归属。预算是可选的：没有预算的 ERP 仍会加载其他所有内容。

试算平衡表文件可以携带借方和贷方列、净额列，或两者都有。只有借方和贷方时，净额为借方减贷方，空白的一侧按零处理。只有净额时，正的净额成为借方，负的净额成为贷方，且取正数。部门列是可选的。

## 故障排查

| 现象 | 处理方法 |
|---|---|
| **测试连接**提示 ERP 拒绝了凭据 | 检查连接的凭据，以及集成用户是否可以登录 ERP。 |
| **测试连接**对某个数据集显示**缺少权限** | 请 ERP 管理员添加其指出的权限。您的 ERP 对应的[连接指南](/zh-cn/guides/connections/)列出了连接所需的内容。 |
| ERP 错误消息比 ERP 自身的消息短 | PlaidCloud 在显示提供商错误之前会移除其中的凭据、令牌和密钥，因此部分细节会被省略。运行**测试连接**可查看受影响的是哪个数据集。 |
| 某个期间的**数据已加载**为问题 | 该期间的 ERP 读取失败。再次运行**加载**；已加载的期间会被跳过。 |
| **科目表中缺失的科目**为问题 | 在 ERP 或您的文件中将缺失的科目添加到会计科目表，然后再次运行**加载**。 |
| **货币折算**为问题 | 某个实体的货币在该期间没有折算为报告货币的汇率，或未找到唯一的报告货币。请将汇率添加到**汇率**文件，检查连接是否可以读取 ERP 的汇率，或设置项目变量 `reporting_currency`。然后再次运行**加载**。 |
| **货币折算**需要关注 | 资产负债表、库存或预算行在该期间没有期末汇率、历史汇率或计划汇率。损益表不受影响。请添加汇率（包括预算月份的计划汇率），然后再次运行**加载**。 |
| **Codes waiting for your answer** 需要关注 | 点击**审核**，回答每个代码，然后点击 **Apply changes**。 |
| **Which source covers which months** 需要关注 | 点击 **Choose which source counts from when**，选择源，然后点击 **Apply changes**。 |
| **Intercompany balances** 为红色或琥珀色 | 检查 **Intercompany pairs** 中的各对交易。记录缺失的一方，为行添加交易伙伴，或添加缺失的汇率。 |
| **Group views are off** | 请架构师勾选 **Group** 下的 **Everyone on the project may see the group results**。 |
| **未映射的实体**为问题 | 将该实体添加到实体主数据，或在**实体对照表**文件中把其代码映射到现有实体，然后再次运行**加载**。 |
