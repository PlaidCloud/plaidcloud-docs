## 搜索

搜索项目需使用层次结构左下方的筛选框。搜索筛选器会匹配项目名称和标签，并将结果显示在上方的层次结构中。


## 创建新项目

创建新项目的步骤如下：

1. 打开 Analyze
2. 在顶部菜单栏中选择“项目”
3. 点击“新建项目”按钮
4. 填写表单信息，包括“Access Control”部分
5. 点击“创建”

此时项目已可用于更新访问权限、添加所有者和创建工作流。

<Aside>默认情况下，当前工作区的所有成员都可以访问该项目</Aside>


## 设置默认文档账户

在项目主页上的**连接环境**旁边，为项目选择一个**默认文档账户**，或选择**无**将其清除。

在项目内部，每个文件选择器都会将**项目默认值**列在首位，它代表项目当前设置的任意账户。离开项目、项目未设置默认账户、该账户已被删除或您无权访问该账户时，它会从列表中消失。

当项目设置了默认账户时，新的文件步骤会预先选中项目默认值。现有步骤绝不会被改写，每个步骤都保留其保存时使用的账户，直到您自行更改，因为文档账户是逐步骤的选择，这一点与连接环境不同。

停留在项目默认值上的步骤，会在运行时解析为项目当时的默认账户，因此在运行中途更改默认账户只会影响尚未启动的节点，这与更改连接环境相同。如果步骤使用项目默认值运行而项目未设置默认账户，运行会失败并指明该项目，而不会回退到其他账户。


## 版本历史

项目中的每个对象，包括步骤、UDF、工作流、维度、已保存的布局、文档或数据编辑器，以及项目自身的设置，都受版本历史备份的保护。系统不会在每次保存时都进行备份；相反，对象在 30 秒内没有再次保存后，会对其稳定状态进行一次备份。一连串编辑（短时间内的多次保存）只会生成一个包含最终结果的版本，而不是每次保存生成一个版本。保存绝不会因等待备份而变慢：倒计时和备份本身都在后台运行。如果需要立即获得一个版本，请使用 **Back up now** 立即捕获当前状态并等待其完成，该功能可在界面、API 中使用，也可通过 `*_versions` MCP 操作 `backup` 使用。所有方案（包括免费版）都提供版本历史。

历史版本支持时间点恢复：将对象还原到较早的版本。在已锁定的项目内，还原会被拒绝，与其中的任何其他更改一样。

版本在原位还原。还原项目、维度、用户定义函数、步骤、工作流或数据编辑器的某个版本会替换同一个项目，若指定其他项目作为目标则会被拒绝，例如“项目版本在原位还原。请省略目标，或将其设置为此项目。”还原属于对该项目的更改，因此所需角色与编辑它相同；对于[限制行](/zh-cn/administration/access/managing-security-groups-and-assignments/#谁可以更改限制行的项目)的项目，还原项目或受限列所读取的维度需要项目架构师。若要将旧的表数据恢复为单独的表，请将[表快照](/zh-cn/guides/data/table-snapshots/)还原为新表。

除了这种自动跟踪之外，项目及其元素还支持版本管理。创建版本不仅简单，还可以将更改从一个版本合并到另一个版本。这为跟踪快照提供了一种简便的方式，也可以创建用于开发的版本，并在需要时将这些更改合并到非开发版本中。有关版本管理、比较和合并的实际操作，请参阅[协作：版本、比较和共享](/zh-cn/get-started/tutorials/collaborate-versions-and-sharing/)。

表数据有自己的历史记录，即 Lakehouse 在每次写入时创建的快照，详见[表快照](/zh-cn/guides/data/table-snapshots/)。

### 通过 AI 助手或 MCP 进行还原和保留

通过 AI 助手或 MCP，`dimension_versions` 可按 `version_id` 还原、保留和释放维度版本，`restore_project` 会将项目中的每个维度回滚到其最近一次备份，并且每个 `*_versions` 列表（步骤、UDF、工作流、维度、项目）都会显示每个版本的 `version_id` 以及是否已保留。通过任何 `*_versions` 工具或 REST API 执行的 `restore` 都会在原位还原该项目：请省略目标，或将其设置为该项目本身。`project_upsert` 可以解锁已锁定的项目，并支持 `if_match`，因此如果自您上次读取项目以来发生了更改，它会失败而不是覆盖该更改。


## 管理项目访问权限

### 访问类型

项目安全性已简化为三种访问类型：

* 所有工作区成员
* 仅限指定成员
* 仅限指定安全组

设置项目安全性很容易：

1. 打开 Analyze
2. 选择“项目”
3. 点击要限制的项目的编辑图标
4. 在“Access Control”下选择所需的限制
5. 点击“更新”

只有项目架构师或租户管理员可以更改谁有权访问项目，包括其访问类型、其上的成员和安全组，以及其数据共享。其他任何人看到这些面板时均为只读，并附有说明“只有项目架构师可以更改访问权限。”


## 所有工作区成员

“所有工作区成员”访问是最简单的选项，因为它向工作区的所有成员提供访问权限，无需额外分配成员。


## 仅限指定成员

“仅限指定成员”访问设置要求将每个成员分配给项目。为项目分配成员的步骤如下：

1. 打开 Analyze
2. 在顶部菜单栏中选择“项目”
3. 点击成员图标
4. 在“访问”列中，勾选成员姓名旁边的复选框以授予访问权限
5. 点击“更新”

对于成员数量众多的云环境，这种方式往往比预期更费力，此时安全组就派上用场了。

<Aside>要添加成员，您必须是工作区的成员。</Aside>


## 仅限指定安全组

“仅限指定安全组”选项允许为特定安全组分配访问账户的权限。由于访问限制依赖于与一个或多个安全组的关联，对于较大的群体，账户访问的管理要简单得多。与单点登录的自动分组关联结合使用时尤其有用。通过单点登录设置成员的分组分配，这些分组也可以隐式地启用和禁用对项目的访问。

编辑已分配分组的步骤如下：

1. 打开 Analyze
2. 在顶部菜单栏中选择“项目”
3. 点击安全组图标
4. 在“访问”列中，勾选安全组名称旁边的复选框以授予访问权限
5. 点击“更新”


## 在项目之间共享数据

数据共享使一个项目可以访问另一个项目的表，例如，使 [Import Project Table](/zh-cn/reference/workflow-steps/import/import-project-table/) 步骤和 [Export Project Table](/zh-cn/reference/workflow-steps/export/export-project-table/) 步骤可以在两者之间移动数据。共享由数据被共享的项目授予另一个项目：

1. 打开要共享其数据的项目，进入其[项目主页](/zh-cn/guides/projects/project-home/)。
2. 打开 **Access & sharing**。在**数据共享**下，点击**新建数据共享**。
3. 在**选择项目**下，选择可以使用此项目数据的项目。
4. 在**允许的操作**下，勾选**读取**、**写入**或两者，然后点击**添加数据共享**。

**删除数据共享**会移除共享。只有项目架构师或租户管理员可以添加或删除项目的数据共享。

共享授予的是项目，因此它只代表该项目的成员及其工作流：

- 通过共享**读取**需要在被授予共享的项目中拥有角色。在该项目中没有角色的人无法通过共享获得任何内容。
- 通过共享**写入**（在共享项目中创建表、文件夹或维度）需要**写入**共享，以及您自己项目中的管理者或架构师角色，即能够在该项目中进行相同更改的角色。其他任何人都会收到提示“通过数据共享写入此项目，需要从该项目到您的项目的写入共享，以及您项目中的管理者或架构师角色。”

工作流以其所属项目自身的身份运行，因此无论谁启动运行，Import Project Table 步骤和 Export Project Table 步骤都可通过共享工作。


## 设置不同的查看角色

很多时候，一个项目可能需要多个转换和表来完成中间步骤，而最终结果可能只包含少数几个表。成员并不总是需要查看项目的所有元素，有时只需查看最终成果。PlaidCloud 允许您设置不同的查看角色，以便轻松精简并控制每个成员的可见性。

有三种内置的查看角色：**架构师、管理者**和**探索者**

**架构师**角色最为简单，因为它允许对项目、工作流、表、变量、数据编辑器、层次结构和用户定义函数拥有完全的可见性和控制权。

**管理者**和**探索者**角色没有特定的访问权限，但可以自定义。换句话说，您可以选择每个分组可以看到哪些项目。

<Aside>**管理者**和**探索者**不是安全组，它们只是提供了一种分离职责和信息可见性的便捷方式。</Aside>

如果认为需要看到项目中的所有内容，可以让所有人都成为**架构师**；否则，可以将成员指定为**管理者**和/或**探索者**项目成员，并以此控制可见性。

设置不同角色的步骤如下：

1. 打开 Analyze
2. 选择“项目”
3. 点击成员图标
4. 选择要更改其角色的成员
5. 在“Role”列中双击其当前角色
6. 选择所需的角色
7. 点击“更新”


## 管理项目变量

运行项目或工作流时，为重复性任务设置变量可能很有用，这样可以减少杂乱并节省时间。这些变量的作用就像普通的代数变量，可以设置变量代表什么，以及其后应执行什么运算。PlaidCloud 允许在项目级别设置这些变量，这会影响该项目内的所有工作流；也可以在工作流级别设置，这只会影响该特定工作流。

设置项目级变量的步骤如下：

1. 打开 Analyze
2. 选择“项目”
3. 点击“管理项目变量”图标

在变量表中，可以查看变量并查看/编辑当前值。还可以通过点击“新建项目变量”按钮来添加新变量或删除现有变量。


## 复制项目

**复制项目**可以将项目的全部内容或您选择的部分内容复制到全新的项目或已有的项目中。

复制项目的步骤如下：

1. 打开 Analyze
2. 选择“项目”
3. 选择要复制的项目
4. 点击**操作**按钮，然后选择**复制项目**
5. 选择目标，选择要带入的内容以及要复制的数据，然后点击**复制项目**
6. 查看**复制前审核**摘要，然后点击**开始复制**

### 选择要复制的内容

选择树按类型列出项目包含的内容：工作流、步骤、表、维度、数据编辑器、用户定义函数。保持全部勾选即可复制整个项目，或只勾选需要的部分。

无需自行判断这些部分依赖什么。勾选的任何内容都会带上其依赖项：步骤读取和写入的表、它加载或分摊所依据的维度、它调用的用户定义函数，以及它调用的任何子工作流或宏。工作流的传感器随工作流一起复制。

**复制的传感器处于禁用状态。** 在您于目标项目中逐一启用传感器之前，副本不会触发任何内容。覆盖重复项的导入，在目标工作流已有传感器时，不会再添加第二个传感器。

### 复制到新项目

为新项目指定名称和 ID。ID 将成为其架构名称，之后无法更改。

**计划处于暂停状态。** 将整个项目复制到新项目时，每个工作流的计划事件都会以暂停状态复制，因此副本不会自行开始运行它们。复制完成后，会有一条消息列出原项目中处于活动状态的事件。若要在副本上运行某个事件，请在**工具** > **事件调度器**中选中它，然后点击**启用所选项**，请参阅[暂停事件](/zh-cn/administration/scheduled-events/event-scheduler/#暂停事件)。

### 复制到现有项目

从项目列表中选择目标。复制会添加到该项目，而不是替换它。

**您需要有权更改目标项目。** 复制到您没有任何角色的项目，或复制到已锁定以防止更改的项目，都会被拒绝，并且在读取或写入任何内容之前就会检查，因此被拒绝的复制不会改动目标。项目也不能复制到自身。

**复制限制行的项目需要项目架构师。** 副本是一个没有[行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)限制的新项目，并且复制时会告知您：“此副本不受行限制。”请在共享副本之前，先在副本上设置行访问。复制到限制行的现有项目同样需要其架构师之一或租户管理员。

**目标保留自己的设置。** 其名称、ID、数据连接环境、存储默认值、文档账户、访问类型、访问列表和行访问授权均保持不变。只会带入您选择的内容。

设置为**项目默认值**的步骤带过去的是该设置，而不是某个账户，复制后，它会解析为目标项目所拥有的默认账户，而不是源项目中的默认账户。

当传入的项目与目标中已有的项目是同一个项目时，由您选择处理方式：

- **用传入数据覆盖重复项**：传入的版本替换目标中的版本。
- **创建重复项的新副本**：目标保留现有内容，传入的项目会添加在旁边，其名称后附加 ` copy`，如果该名称也已被占用，则再加上计数。

项目变量和工作流变量是*创建新副本*的例外：变量由其名称标识，因此无法在不重命名的情况下添加第二个副本，而重命名后的变量不会被任何内容引用。如果目标已定义了副本也携带的变量，则保留目标自己的值，并且副本会告知您跳过了哪些变量。*覆盖*则像对待其他所有内容一样对待变量，并替换它们。

这种匹配依据的是标识，而不是名称：最初来自同一项目的项目会被识别为同一项目，而两个只是碰巧同名的项目则被视为不同的项目，之后两者都会存在。

### 选择复制多少数据

在 **Data to copy** 下，有两个设置决定随所选内容一起复制哪些数据。

**表数据**设置复制每个表的多少行：

| 选项 | 复制内容 |
| --- | --- |
| **No table data** | 表、步骤和所选的其余内容，不含任何行。这是默认设置。 |
| **完整** | 每个表的所有行，在同一个 Lakehouse 上以及跨 Lakehouse 均适用。 |
| **样本** | 最多复制您输入的**每表行数**，仅适用于新项目。该数字可以是 1 到 1,000,000。 |

抽样的表最多包含该数量的行，行数不足时则包含全部行。**完整**或**样本**复制会同时复制多个表，因此表很多的项目完成得更快。

**Copy dimension members** 会复制所选内容中每个维度的成员，无论您选择哪个**表数据**选项。它默认开启，因此不含表数据的复制仍会带有已填充的维度，并且制作很快。清除它可复制不含成员的维度。

通过 REST API（`POST /rest/v1/analyze/project/copy`）或 `project_copy` MCP 工具，将 `data_mode` 设置为 `structure`、`full` 或 `sample`，将 `dimension_members` 设置为 `true` 或 `false`。省略 `dimension_members` 时，仅在复制表的行时才复制成员。`project_copy` 还会返回副本的警告，例如未复制的 ERP 写入授权。

### 审核副本

在复制任何内容之前，**复制前审核**会汇总此次复制：来源项目、目标位置、**表数据**选项、是否包含**维度成员**、表和视图的数量、大小、预计时间、源和目标 Lakehouse，以及**请注意**下的任何警告。点击**开始复制**开始，或点击**取消**返回并更改所选内容。

### 谁可以看到副本

带数据（表的行、维度成员或两者）的副本仅对创建者本人可见。准备好后，请在新项目中共享。具有行级安全的项目的副本出于同样的原因保持私有。

将数据复制到现有项目需要对该项目具有写入权限。

### 副本中的 ERP 写入授权

仅您自己可见的新副本会保留源项目的 [ERP 写入授权](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)，因此无需再次为副本授权，即可测试其过账工作流。这指的是任何带表数据（**完整**或**样本**）、维度成员或两者的、复制到新项目的副本。在以下情况下会复制授权：

- 您是源项目的架构师或工作区管理员。
- 您亲自进行复制，而不是通过代理或服务账户。

每项授权仅在您今天能够自行授予时才会复制：其连接和环境仍然存在，并且您对该连接具有写入权限。复制的授权会记录为您的授权。

**副本以模拟模式创建。** 如果源项目的 **ERP过账模式**为实时，则副本的该模式会设置为模拟，因此其工作流会构建并检查它们将要过账的内容，而不会联系 ERP。设置为模拟或关闭的源项目会保留该设置。准备好从副本进行真实过账时，请在副本主页的 **ERP过账**下将 **ERP过账模式**设置为实时，请参阅[选择过账模式](/zh-cn/guides/workflows/run-a-workflow/#选择过账模式)。计划和传感器仍按上文所述以暂停和禁用状态创建，因此在您将其开启之前，副本上不会运行任何内容。

复制到现有项目的副本，或不含表数据和维度成员的副本，不会带有源项目的授权。请先在其主页的 **ERP过账** > **ERP 写入授权**下为其授权，然后再过账。

**复制结果**会报告发生的情况，例如“已复制 2 项 ERP 写入授权；ERP 过账处于模拟模式”，以及未复制的数量。

### 复制结果

复制完成后，**复制结果**窗口会汇总已复制的表和维度成员，并按名称列出每个表和维度及其结果（**已复制**、**已复制（有更改）**、**已抽样**、**已跳过**或**失败**），以及被跳过或失败项目的原因。点击 **Retry failed items** 可再次复制失败的表和维度；它们在副本中的当前内容将被替换。复制完成或失败时，您会通过消息和电子邮件收到通知，可以从消息中重新打开结果，或稍后在**项目**选项卡上选中该副本，然后从**操作**菜单中选择**查看导入或复制结果**。

结果会一直保留在副本上，直到有人将其忽略。复制完成后，点击**忽略结果**可为所有能够打开该项目的人移除结果。项目中的任何内容都不会改变，但无法再从该窗口重试其失败项。忽略结果需要对项目具有编辑权限，并且项目不得处于锁定状态。

### 更新引用

项目的工作流步骤引用该项目内部的表和其他对象。**更新引用**会重写这些引用，使其指向副本而不是原件，这几乎总是您想要的结果，这也是它默认开启的原因。关闭它会使复制的步骤继续指向其来源项目。

<Aside>复制在后台运行。进度对话框会显示复制经过的各个阶段；您可以点击**在后台运行**将其关闭并继续工作，项目列表会自动更新，复制完成时您会收到通知。</Aside>

## 查看项目报表

当项目或工作流处于动态变化时，维护详细文档就成了一项挑战。为帮助解决这个问题，PlaidCloud 提供了生成项目级报表的功能，该报表详细记录工作流、工作流步骤、用户定义转换、变量和表。此报表按需生成，并反映项目的当前状态。

下载报表的步骤如下：

1. 打开 Analyze
2. 选择“项目”
3. 点击报表图标
