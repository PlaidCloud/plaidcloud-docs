## 搜索

使用列表底部、行数旁边的**筛选器**搜索项目。按 **/** 或 Ctrl/Cmd+F 可跳转到该处。筛选器会在项目的名称和标签中查找匹配项，并在层次结构中显示结果。


## 创建新项目

创建新项目：

1. 打开 Analyze
2. 从顶部菜单栏中选择“项目”
3. 单击“新建项目”按钮
4. 填写表单信息，包括“访问控制”部分
5. 单击“创建”

项目现已就绪，可以更新访问权限、添加所有者和创建工作流。

<Aside>默认情况下，当前工作区的所有成员都可以访问该项目</Aside>


## 设置默认文档账户

在项目主页的**连接环境**旁，为项目选择**默认文档账户**，或选择**无**将其清除。

在项目内，每个文件选择器都会将**项目默认值**列在首位，代表项目当前设置的账户。离开项目、项目未设置默认账户、该账户已被删除或您无权访问该账户时，它就会从列表中消失。

当项目设置了默认账户时，新的文件步骤会预先选中项目默认值。现有步骤绝不会被改写：每个步骤都保留其保存时使用的账户，直至您自行更改，因为文档账户是按步骤选择的，而步骤通常遵循项目的连接环境。

保持为项目默认值的步骤会在运行时解析为项目当时的默认账户，因此在运行中途更改默认账户只会影响尚未开始的节点，这与更改连接环境相同。如果步骤使用项目默认值运行，而项目未设置默认账户，则运行会失败并指出项目名称，而不会回退到其他账户。


## 将步骤固定到某一环境

步骤遵循项目的[连接环境](/zh-cn/guides/projects/project-home/#数据与连接)，因此将项目在 QA 和 Production 之间切换时，所有步骤都会随之移动。表单中带有**环境**设置的步骤在此提供两种选择：

- **Project environment** 遵循项目的连接环境。除非有理由，否则请保持此选项。
- **Fixed environment** 忽略项目的连接环境，始终使用您选择的环境。仅用于无论项目切换到哪个环境都必须停留在同一环境的步骤，例如在设置为 QA 的项目中读取 Production 的参考数据。警告图标用于提醒该步骤不会跟随切换。

固定了环境的步骤在其他环境而非项目环境上运行时，每次都会在日志中添加警告。如果其固定的环境已不存在（例如在从另一个工作区复制的步骤中），则该步骤会失败并说明原因，而不会在其他位置运行。

ERP 过账步骤始终使用项目的环境，因此这些步骤上无法使用 **Fixed environment**。

默认环境无法删除；当项目正在使用、某个步骤将其作为固定环境或某个代理为其服务时，其他环境也无法删除。消息会说明仍有什么在使用它，列出您有权访问的内容并统计其余部分的数量。


## 版本历史

项目中的每个对象（步骤、UDF、工作流、维度、已保存的布局、文档或数据编辑器，以及项目自身的设置）都纳入版本历史备份。备份并非在每次保存时都进行；相反，当某个对象在 30 秒内没有再次保存时，就会对其稳定状态进行一次备份。一连串编辑（快速连续的多次保存）只会生成一个包含最终结果的版本，而不是每次保存生成一个版本。保存绝不会因等待备份而变慢：倒计时和备份本身都在后台运行。如果现在就需要一个版本，请使用 **Back up now** 立即捕获当前状态并等待其完成，该功能可在 UI、API 以及 `*_versions` MCP 操作 `backup` 中使用。版本历史适用于所有套餐，包括免费版。

过去的版本支持时间点恢复：将对象还原到早期版本。在已锁定的项目中会拒绝还原，与那里的其他任何更改相同。

版本会就地还原。还原项目、维度、用户定义函数、步骤、工作流或数据编辑器的某个版本会替换该项本身，而将其他项指定为目标会被拒绝，例如“项目版本会就地还原。请省略目标，或将其设置为此项目。”还原是对该项的更改，因此所需角色与编辑它相同；在[限制行的项目](/zh-cn/administration/access/managing-security-groups-and-assignments/#谁可以更改限制行的项目)上，还原项目或受限列所读取的维度需要项目架构师。要将旧的表数据作为单独的表恢复，请将[表快照](/zh-cn/guides/data/table-snapshots/)还原到新表。

除了这种自动跟踪之外，项目及其元素还支持版本管理。创建版本不仅简单，还可以将更改从一个版本合并到另一个版本。这提供了一种简便的方式来跟踪快照，或创建开发版本，并在需要时将这些更改合并到非开发版本中。有关版本管理、比较和合并的实践，请参阅[协作：版本、比较和共享](/zh-cn/get-started/tutorials/collaborate-versions-and-sharing/)。

表数据有自己的历史记录，即 Lakehouse 在每次写入时生成的快照，详见[表快照](/zh-cn/guides/data/table-snapshots/)。

### 通过 AI 助手或 MCP 还原和保留

通过 AI 助手或 MCP，`dimension_versions` 可凭 `version_id` 还原、保留和释放维度版本，`restore_project` 会将项目中的每个维度回滚到其最近一次备份，并且每个 `*_versions` 列表（步骤、UDF、工作流、维度、项目）都会显示每个版本的 `version_id` 以及其是否被保留。通过任何 `*_versions` 工具或 REST API 执行的 `restore` 都会就地还原该项：省略目标，或将其设置为该项本身。`project_upsert` 可以解锁已锁定的项目，并支持 `if_match`，因此如果自您上次读取项目以来已有更改，它会失败而不是覆盖该更改。


## 管理项目访问权限

### 访问类型

项目安全性已简化为三种访问类型：

* 所有工作区成员
* 仅限指定成员
* 仅限指定安全组

设置项目安全性很简单：

1. 打开 Analyze
2. 选择“项目”
3. 单击要限制的项目的编辑图标
4. 在“访问控制”下选择所需的限制
5. 单击“更新”

只有项目架构师或租户管理员才能更改谁可以访问项目，包括其访问类型、其上的成员和安全组以及其数据共享。其他任何人看到的这些面板均为只读，并附有说明“只有项目架构师才能更改访问权限。”


## 所有工作区成员

“所有工作区成员”访问是最简单的选项，因为它为工作区的所有成员提供访问权限，无需额外分配成员。


## 仅限指定成员

“仅限指定成员”访问设置需要将每个成员分配到项目。将成员分配到项目：

1. 打开 Analyze
2. 从顶部菜单栏中选择“项目”
3. 单击成员图标
4. 在“访问”列中，通过勾选成员姓名旁边的复选框来授予成员访问权限
5. 单击“更新”

对于成员数量众多的云，这种方式通常需要比预期更多的工作量，这正是安全组发挥作用之处。

<Aside>要添加成员，您必须是工作区的成员。</Aside>


## 仅限指定安全组

“仅限指定安全组”选项允许为特定的安全组分配访问该账户的权限。由于访问限制依赖于与一个或多个安全组的关联，因此较大群体的账户访问管理要简单得多。与单点登录自动分组关联结合使用时尤其有用。通过使用单点登录来设置成员的分组分配，这些分组还可以隐式地启用和禁用对项目的访问。

编辑已分配的分组：

1. 打开 Analyze
2. 从顶部菜单栏中选择“项目”
3. 单击安全组图标
4. 在“访问”列中，通过勾选安全组名称旁边的复选框来授予安全组访问权限
5. 单击“更新”


## 在项目之间共享数据

数据共享让一个项目可以访问另一个项目的表，例如让 [Import Project Table](/zh-cn/reference/workflow-steps/import/import-project-table/) 和 [Export Project Table](/zh-cn/reference/workflow-steps/export/export-project-table/) 步骤能够在它们之间移动数据。共享由数据被共享的项目授予另一个项目：

1. 打开要共享其数据的项目，然后转到其[项目主页](/zh-cn/guides/projects/project-home/)。
2. 打开 **Access & sharing**。在**数据共享**下，单击**新建数据共享**。
3. 在**选择项目**下，选择可以使用此项目数据的项目。
4. 在**允许的操作**下，勾选**读取**、**写入**或两者，然后单击**添加数据共享**。

**删除数据共享**会在您确认后移除一个共享。只有项目架构师或租户管理员才能添加或删除项目的数据共享。

共享是授予某个项目的，因此它仅代表该项目的成员及其工作流：

- 通过共享**读取**需要在被授予共享的项目中拥有角色。在其中没有角色的人无法通过共享获得任何内容。
- 通过共享**写入**（在共享项目中创建表、文件夹或维度）需要**写入**共享，以及您自己项目中的管理者或架构师角色，即能在那里进行相同更改的角色。其他任何人会收到提示：“通过数据共享写入此项目，需要从该项目到您的项目的写入共享，以及您的项目中的管理者或架构师角色。”

工作流以其所属项目自身的身份运行，因此无论由谁启动运行，Import Project Table 和 Export Project Table 步骤都能通过共享工作。


## 设置不同的查看角色

项目往往需要多个转换和表来完成中间步骤，而最终结果可能只包含少数几个表。成员并不总是需要查看项目的所有元素，有时只需要最终成果。PlaidCloud 允许您设置不同的查看角色，以便轻松精简并控制每个成员的可见性。

内置的查看角色有三种：**架构师、管理者**和**探索者**

**架构师**角色最简单，因为它允许对项目、工作流、表、变量、数据编辑器、层次结构和用户定义函数拥有完全的可见性和控制权。

**管理者**和**探索者**角色没有特定的访问权限，但可以自定义。换句话说，您可以选择每个分组可见的项目。

<Aside>**管理者*** *和**探索者**不是安全组，它们只是提供了一种分离职责和信息可见性的便捷方式。</Aside>

如果您认为需要查看项目中的所有内容，可以将所有人设为**架构师**；否则，可以将成员指定为**管理者**和/或**探索者**项目成员，并以此控制可见性。

设置不同的角色：

1. 打开 Analyze
2. 选择“项目”
3. 单击成员图标
4. 选择要更改其角色的成员
5. 在“角色”列中双击其当前角色
6. 选择所需的角色
7. 单击“更新”


## 管理项目变量

运行项目或工作流时，为重复性任务设置变量可能很有用，以减少混乱并节省时间。这些变量的运作方式就像普通的代数变量，允许您设置变量代表什么以及其后应执行什么运算。PlaidCloud 允许在项目级别设置这些变量，这会影响该项目内的所有工作流；也可以在工作流级别设置，这只会影响该特定工作流。

设置项目级变量：

1. 打开 Analyze
2. 选择“项目”
3. 单击“管理项目变量”图标

在“变量表”中，可以查看变量并查看/编辑当前值。还可以通过单击“新建项目变量”按钮来添加新变量或删除现有变量。


## 复制项目

**复制项目**可将项目（全部或仅您选取的部分）复制到全新的项目或已有的项目中。

复制项目：

1. 打开 Analyze
2. 选择“项目”
3. 选择要复制的项目
4. 单击**操作**按钮并选择**复制项目**
5. 选择目标，选取要带入的内容和要复制的数据，然后单击**复制项目**
6. 检查**复制前审核**摘要并单击**开始复制**

### 选择要复制的内容

选择树按类型列出项目包含的内容：工作流、步骤、表、维度、数据编辑器、用户定义函数。保持全部勾选可复制整个项目，也可以只勾选所需的部分。

无需自行判断这些部分所依赖的内容。您勾选的任何内容都会连同其依赖项一起带入：步骤读取和写入的表、其加载或据以分摊的维度、其调用的用户定义函数，以及其调用的任何子工作流或宏。工作流的传感器会随工作流一起带入。

**复制的传感器默认处于禁用状态。** 在目标项目中逐个启用传感器之前，副本上不会触发任何内容。覆盖重复项的导入在目标工作流已有传感器时，不会再添加第二个传感器。

### 复制到新项目

为新项目指定名称和 ID。该 ID 将成为其架构名称，之后无法更改。

**计划默认处于暂停状态。** 将整个项目复制到新项目时，每个工作流的计划事件都会以暂停状态带入，因此副本不会自行开始运行它们。复制完成后，消息会列出原项目中处于活动状态的事件。要在副本上运行某个事件，请在**工具** > **事件调度器**中选中它并单击**启用所选项**，请参阅[暂停事件](/zh-cn/administration/scheduled-events/event-scheduler/#暂停事件)。

### 复制到现有项目

从项目列表中选择目标。复制会添加到该项目，而不是替换它。

**您需要能够更改目标。** 复制到您没有任何角色的项目会被拒绝，复制到已锁定以防止更改的项目同样会被拒绝；这在读取或写入任何内容之前就会检查，因此被拒绝的复制不会触及目标。项目也不能复制到其自身。

**复制限制行的项目需要项目架构师。** 副本是没有[行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/#管理行访问)限制的新项目，并且副本会告知您这一点：“此副本没有行限制。”请在共享之前先在副本上设置行访问。复制到限制行的现有项目同样需要其架构师之一或租户管理员。

**目标保留其自身的设置。** 其名称、ID、数据连接环境、存储默认值、文档账户、访问类型、访问列表和行访问授权均保持不变。只会带入您选择的内容。

设置为**项目默认值**的步骤带过去的是该设置，而不是某个账户；复制后，它会解析为目标项目所具有的默认账户，而不是其在源项目中的默认账户。

当传入的项与目标中已有的某项是同一项时，由您选择如何处理：

- **用传入数据覆盖重复项**：传入的版本替换目标中的版本。
- **创建重复项的新副本**：目标保留现有内容，传入的项会添加在旁边，其名称后附加 ` copy`，如果该名称也已被占用，则再加一个计数。

项目变量和工作流变量是*创建重复项的新副本*的例外：变量以其名称标识，因此无法在不将其重命名为无人引用的名称的情况下添加第二个副本。如果目标已定义了副本也携带的变量，则保留目标自身的值，并且副本会告知您哪些变量未被改动。*覆盖*会像对待其他所有内容一样对待变量，并替换它们。

这种匹配是按标识而非名称进行的：最初来自同一项目的项会被识别为同一项，而仅仅碰巧同名的两项则被视为不同的项，之后两者都会存在。

### 选择复制多少数据

在 **Data to copy** 下，有两项设置决定随所选内容一起带入哪些数据。

**表数据**设置复制每个表的多少行：

| 选择 | 复制的内容 |
| --- | --- |
| **No table data** | 表、步骤和所选的其余内容，不含行。这是默认设置。 |
| **完整** | 每个表的所有行，在同一 Lakehouse 上以及跨 Lakehouse 均可。 |
| **样本** | 最多为您输入的**每表行数**，仅适用于新项目。该数字可以是 1 到 1,000,000。 |

抽样的表最多包含该数量的行；如果行数更少，则包含其全部行。**完整**或**样本**复制会同时复制多个表，因此表较多的项目完成得更快。

**Copy dimension members** 会复制所选内容中每个维度的成员，无论您选择哪种**表数据**。它默认处于开启状态，因此不含表数据的副本仍会带有已填充的维度，并且创建速度很快。清除它可复制维度而不含其成员。

通过 REST API（`POST /rest/v1/analyze/project/copy`）或 `project_copy` MCP 工具，将 `data_mode` 设置为 `structure`、`full` 或 `sample`，并将 `dimension_members` 设置为 `true` 或 `false`。省略 `dimension_members` 时，仅在复制表行时才会复制成员。`project_copy` 还会返回该副本的警告，例如未被复制的 ERP 写入授权。

### 审核副本

在复制任何内容之前，**复制前审核**会汇总此次复制：来源项目、目标位置、**表数据**选择、是否包含**维度成员**、表和视图的数量、大小、预计时间、源和目标 Lakehouse，以及**请注意**下的任何警告。单击**开始复制**开始，或单击**取消**返回并更改所选内容。

### 谁能看到副本

带数据（表行、维度成员或两者）创建的副本仅创建者本人可见。准备好后，请从新项目中共享它。对于带有行级安全的项目，其副本出于同样的原因也保持私有。

将数据复制到现有项目需要对该项目具有写入权限。

### 副本中的 ERP 写入授权

仅您可见的新副本会保留源项目的 [ERP 写入授权](/zh-cn/guides/workflows/run-a-workflow/#授权项目过账)，因此无需再次为副本授权，即可测试其过账工作流。这适用于带表数据（**完整**或**样本**）、维度成员或两者创建的、复制到新项目的任何副本。在以下情况下会复制这些授权：

- 您是源项目的架构师或工作区管理员。
- 您亲自进行复制，而不是通过代理或服务账户。

只有在您今天自己就能授予某项授权时，才会复制该授权：其连接和环境仍然存在，并且您对该连接具有写入权限。复制的授权会记为您本人的授权。

**副本以 Simulate 模式生成。** 如果源项目的 **ERP过账模式**为 Live，副本的则设置为 Simulate，因此其工作流会构建并检查它们将要过账的内容，而不会联系 ERP。设置为 Simulate 或 Off 的源保持该设置。准备好从副本真正过账时，请在副本主页的 **ERP过账**下将 **ERP过账模式**设置为 Live，请参阅[选择过账模式](/zh-cn/guides/workflows/run-a-workflow/#选择过账模式)。计划和传感器仍如上所述以暂停和禁用状态带入，因此在您将其开启之前，副本上不会运行任何内容。

复制到现有项目，或不含表数据且不含维度成员的副本，在启动时没有源的授权。过账之前，请在其主页的 **ERP过账** > **ERP 写入授权**下为其授权。

**复制结果**会报告所发生的情况，例如“已复制 2 个 ERP 写入授权；ERP 过账处于 Simulate 模式”，以及有多少未被复制。

### 复制结果

复制完成后，**复制结果**窗口会汇总所复制的表和维度成员，并按名称列出每个表和维度及其结果（**已复制**、**已复制（有更改）**、**已抽样**、**已跳过**或**失败**），以及被跳过或失败项的原因。单击 **Retry failed items** 可再次复制失败的表和维度；它们在副本中的当前内容将被替换。复制完成或失败时，您会通过消息和电子邮件收到通知，并且可以从消息中重新打开结果，或之后在**项目**选项卡上选中该副本，然后从**操作**菜单中选择**查看导入或复制结果**。

结果会一直保留在副本上，直到有人将其忽略。复制完成后，单击**忽略结果**可为所有能打开该项目的人移除结果。项目中不会有任何更改，但其失败项将无法再从该窗口重试。忽略需要对项目具有编辑权限，且项目不得被锁定。

### 更新引用

项目的工作流步骤引用该项目内的表和其他对象。**更新引用**会重写这些引用，使其指向副本而不是原项目，这几乎总是您想要的结果，也是它默认开启的原因。关闭它会使复制的步骤仍指向其来源项目。

<Aside>复制在后台运行。进度对话框会显示复制所经历的各个阶段；您可以单击**在后台运行**将其关闭并继续工作，项目列表会自动更新，复制完成时您会收到通知。</Aside>

## 查看项目报表

当项目或工作流是动态的时，维护详细文档就成了一项挑战。为帮助解决这一问题，PlaidCloud 提供了生成项目级报表的功能，该报表详细记录工作流、工作流步骤、用户定义转换、变量和表。此报表按需生成，反映项目的当前状态。

下载报表：

1. 打开 Analyze
2. 选择“项目”
3. 单击报表图标
