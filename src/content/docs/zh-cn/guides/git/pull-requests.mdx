## 创建分支

在新分支上工作，使更改在准备就绪之前与默认分支保持分离。

**在 UI 中：**

1. 打开存储库并选择左上角附近的分支选择器（显示当前分支名称）。
2. 在搜索框中输入新的分支名称，然后选择 **Create Branch**。

**在本地：**

1. 创建并切换到该分支：`git checkout -b feature-x`
2. 进行更改，然后暂存并提交：`git add .`，然后 `git commit -m "Describe what changed"`
3. 将分支推送到 PlaidCloud Git：`git push -u origin feature-x`

## 打开拉取请求

1. 打开存储库并选择 **Pull Requests** 选项卡，然后选择 **New Pull Request**。
2. 将**比较**分支设置为功能分支，将**基础**分支设置为目标分支（通常为 `main` 或 `master`）。
3. 撰写清晰的标题和说明，解释更改了什么以及原因。
4. 要链接相关议题，请在说明中添加关闭关键字（例如 `Closes #12`），这样拉取请求合并时议题会自动关闭。
5. 如有需要，指派审查者，然后选择 **Create Pull Request**。

## 审查更改

审查者无需合并任何内容即可审查拉取请求：

1. 打开拉取请求并选择 **Files Changed** 以阅读差异。
2. 选择差异中的任意一行，即可对该处更改留下内联注释。
3. 完成后，提交整体结论：选择**批准**表示同意，或选择 **Request Changes** 要求先进行修改。
4. 作者向同一分支推送更多提交以处理反馈，拉取请求会自动更新，无需新建。
5. 每个问题得到解决后，审查者将相应的注释线程标记为已解决。

<Aside>存储库管理员可以对默认分支启用分支保护，要求拉取请求获得最低数量的批准后才能合并。</Aside>

## 合并

拉取请求获得批准后：

1. 从 **Merge** 按钮旁边的下拉列表中选择合并方式：
   - **Create a merge commit**：通过合并提交保留完整的分支历史。
   - **Squash and merge**：将分支上的所有提交合并为目标分支上的单个提交。
   - **Rebase and merge**：将分支的提交重放到目标分支上，不产生合并提交。
2. 选择 **Merge** 以完成合并。
3. 可选：当功能分支不再需要时，选择 **Delete Branch** 将其清理。
