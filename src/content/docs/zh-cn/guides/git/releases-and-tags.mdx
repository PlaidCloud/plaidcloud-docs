标签将某次提交标记为重要提交，通常是 `v1.2.0` 这样的版本号。发布版本以标签为基础，添加便于阅读的说明和可选的文件附件，使用户可以在 Web UI 中浏览并下载特定版本。

## 创建标签

可以从 UI 或本地克隆中创建标签。

**从 UI：**

1. 打开存储库并选择 **Releases**，然后选择 **Tags**。
2. 选择 **Create Tag**。
3. 输入标签名称（例如 `v1.2.0`），选择目标分支或提交，然后选择 **Create Tag**。

**从命令行：**

```bash
git tag v1.2.0
git push origin v1.2.0
```

要为过去的某次特定提交打标签，请传入其提交 ID，而不是依赖 `HEAD`：

```bash
git tag v1.2.0 abc1234
git push origin v1.2.0
```

## 发布版本

1. 打开存储库并选择 **Releases**。
2. 选择 **New Release**。
3. 在 **Tag Name** 字段中，选择现有标签，或输入新名称以在当前默认分支的最新提交处创建标签。
4. 输入 **Release Title**，并在 Markdown 正文中撰写发布说明，变更日志、升级说明和已知问题都应写在这里。
5. 如果该版本尚未可供一般使用，请选择 **This is a pre-release**；若要稍后完成而暂不发布，请选择**保存草稿**。
6. 准备就绪后，选择 **Publish Release**。

<Aside>草稿发布版本仅对具有写入权限的存储库成员可见。预发布版本对所有有访问权限的人可见，但不会被标为存储库概览中的“Latest”。</Aside>

## 附加文件

上传的文件会以命名的下载链接形式显示在发布页面上，与自动生成的源代码归档并列。

1. 在新建或编辑发布版本的表单中，转到 **Attach Files** 部分。
2. 将文件拖到上传区域，或选择该区域进行浏览，常见的选择包括构建的二进制文件、压缩归档、校验和以及签名。
3. 对每个文件重复此操作，然后发布或更新发布版本。

请将单个文件的大小控制在合理范围内，以便团队快速下载。

<Aside type="tip">对于可安装的包，如 npm 模块、容器映像、PyPI wheel 等，[包注册表](/zh-cn/guides/git/packages/)比发布附件更合适。它理解版本解析、依赖元数据和客户端工具（`npm`、`pip`、`docker pull`），这是普通文件下载做不到的。</Aside>

## 查看和下载发布版本

1. 选择 **Releases** 以查看完整列表，最新的在前。
2. 最新的非预发布版本会以 **Latest** 徽章突出显示。
3. 每个条目显示标签名称、发布标题、说明，以及指向以下内容的链接：
   - **Source code**：所打标签提交的自动生成的 `zip` 和 `tar.gz` 归档。
   - **Assets**：发布版本时附加的任何文件。
4. 选择文件链接可直接下载，或复制 URL 进行分享。

要比较两个发布版本，请将它们的标签名称作为比较 URL 打开：

```bash
https://git.example.plaidcloud.com/you/my-repo/compare/v1.1.0...v1.2.0
```
