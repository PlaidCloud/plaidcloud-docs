**货币**是专为金额值设计的列数据类型。它与我们熟悉的类型（数值、整数、文本等）一起出现在每个数据类型列表中，并将金额存储为精确的定点小数：18 位精度，4 位小数。这足以表示大约 ±100 万亿的范围，精确到单位的 1/10,000，且不存在浮点舍入。

好处在于速度。货币列占用的内存宽度是数值列的一半，因此扫描满是金额的表的仪表板和工作流步骤只需读取约一半的数据，完成得更快。数值仍然是高精度的默认类型（38 位精度，10 位小数）；而货币是更精简的类型，凡是值为金额的地方都可以选用它。

<Aside>
货币类型随当前平台版本推出。更新在您的工作区上线后，该选项就会出现在您的数据类型列表中。
</Aside>


## 何时使用货币

对于存放货币金额的列（成本、收入、价格、利润率、支出、分摊金额），请选择货币。这些列在盈利能力和财务模型中占主导地位，因此对它们重新指定类型，通常是对扫描密集的仪表板和工作流最大的单项收益。

在以下情况下，请继续使用数值：

* 值可能超过大约 ±100 万亿，或需要超过 4 位小数，例如外汇汇率、单位费率、百分比和分摊因子
* 该列将金额与其他度量混在一起，或者您不确定它会存放什么

<Aside type="note">
每个货币值都必须符合 18 位精度和 4 位小数，即在 4 位小数下约为 ±100 万亿。如果某列需要比这更大的范围或更高的精度，请使用数值。
</Aside>


## 在哪里设置

在选择列数据类型的任何地方都可以使用货币。

### 在工作流步骤的列映射中

在任何步骤的输出列映射（数据映射器网格）中，从该列的数据类型下拉列表中选择**货币**，方式与选择数值或文本相同。该步骤会从下一次运行开始将该列写为货币。

### 在表的列属性中

打开表的**列属性**，使用**数据类型**控件在**数值**和**货币**之间切换列。更改会在下次重建表时生效，例如下次生成该表的工作流步骤运行时。

### 通过 AI 助手或 MCP 工具

通过 [MCP](/zh-cn/integrations/ai-coding-agents/getting-started/) 连接的代理也可以设置该类型：在任何需要指定列类型的地方（创建列、定义表或配置步骤），数据类型的值为 `currency`。让您的助手“把金额列设为货币”，往往是为宽表重新指定类型最快的方式。


## 货币的行为方式

有几条规则让货币在整个平台中保持可预测：

* **货币始终由您明确选择。** 导入、类型自动检测、SQL 结果以及派生列（求和、表达式、分摊输出）始终默认为数值。如果希望结果为货币，请自行为该输出列重新指定类型。
* **一旦设置，就会被记住。** 声明为货币的列在读取、下游步骤和表重建过程中始终保持为货币。当下游步骤根据表填充其列映射时，货币类型会自动带入该步骤的配置。
* **聚合返回数值。** 对货币列执行 SUM 或其他聚合会产生数值结果；如果希望以货币方式存储聚合值，请将输出列重新设置为货币。
* **空单元格导入为 0。** 在文件导入中，货币列中的空单元格加载为 0，与数值完全相同。

<Aside type="caution">
在编写原始 SQL 的步骤中，**填充**按钮会根据查询结果推断输出列，而查询结果总是以数值形式返回。请在运行填充之后将金额列设置为货币，如果重新运行填充，预计需要再次设置。
</Aside>
