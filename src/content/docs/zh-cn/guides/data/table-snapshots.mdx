每次写入表时，PlaidCloud 的 Lakehouse 都会保留该时间点表的**快照**，即数据在该时间点的一致副本。借助快照，您可以回顾表在较早时包含的内容、从错误的加载中恢复，并审核表随时间的变化。可以回溯多久取决于表的时间旅行设置，默认为 1 天，对于项目默认设置或延长了该期限的表，最长可达 90 天。请参阅[管理存储](/zh-cn/guides/projects/managing-storage/)。

“快照”面板可用于浏览该历史记录，在表资源管理器中以只读方式打开任意快照，并将表回退或还原到较早的快照。

## 打开“快照”面板

在项目的**表**列表中，单击表所在行上的快照/回溯按钮。**快照**面板随即打开，按从新到旧的顺序列出该表的快照：

- **时间**：拍摄快照的日期和时间。
- **行**：该快照时表的行数。
- **Δ 行**：与上一个快照相比行数的变化，便于您了解每次写入添加或删除了什么。
- **大小**：快照的压缩存储大小。
- **标签**：名称，适用于您已命名或已固定的快照。
- **已挂起**：固定标记，适用于已挂起（保留时间超过正常保留期限）的快照。

## 查看快照时的数据

有两种方式可以查看表在较早时间点的数据。两种方式都会在**只读历史视图**中打开表资源管理器，并显示一个横幅，说明您正在查看哪个快照，以及一个**返回当前数据**按钮。

1. **从“快照”面板**：选择一个快照，然后单击**查看快照**。
2. **从表资源管理器**：使用工具栏中的 **As of** 下拉菜单。它会列出该表最近的快照；选择其中一个即可切换视图，或选择**当前（实时数据）** 返回实时数据。

<Aside>历史视图是只读的，它是通向过去的窗口，而不是可编辑的副本。如果想将旧数据恢复到表中，请使用下文的**回退**或**还原**。</Aside>

## 回退或还原快照

选择一个快照，然后单击**回退/还原**。对话框提供两种选择：

- **就地回退此表**（默认）：用快照替换表的当前数据。由于这是破坏性操作，您需要输入表名以确认。在替换数据之前，PlaidCloud 会自动为当前状态捕获一个**回退前安全快照**（在支持固定的存储引擎上），以便您始终可以回到原来的状态。在 Databend Lakehouse 上，如果自该快照以来表的列发生了变化，就地回退会被拒绝，并指明发生变化的列，此时请改为还原到新表。
- **将快照恢复到新表**：保持原表不变，并在项目中创建一个新表（由您指定名称和文件夹），其内容由该快照填充，列与源表相同。通过 AI 助手或 MCP 进行还原时，如果未指定名称，则会基于源表生成一个名称，例如 `Sales (restored 3f2a9c1d)`。

<Aside type="caution">就地回退会覆盖表的当前数据。输入确认和自动的回退前安全快照都是为了保护您，请在确认之前阅读对话框内容。项目被锁定时，回退会被阻止。</Aside>

<Aside>通过 REST API 或 MCP，可以不指定目标表或指定表本身，来就地还原快照。那里的就地还原与对话框中的回退受到同样的保护：在存储引擎支持的情况下生成回退前安全快照，并留有审核记录。如果希望在您列出其快照之后表又被写入时拒绝该操作，请将您看到的最新快照作为 `expected_current_snapshot_id` 传入。</Aside>

<Aside>如果还原到新表失败（例如因为快照已过期），则不会向项目添加新表。</Aside>

## 命名、固定和保留

快照会在每晚清理时根据表的时间旅行设置（默认 1 天，最长 90 天）过期。回退或还原可以回溯到表所显示的最早可还原时间点。要将某个快照保留更长时间：

- **创建快照**会按需对当前数据拍摄一个挂起的快照，在有风险的重新加载之前很有用（例如“Q2 重新加载之前”）。
- **挂起**会固定所选快照；**释放**会移除挂起，使其回到正常的生命周期。

<Aside type="caution">挂起保留的不止一个快照，它会保留被挂起的快照*以及*其后写入的每个快照，因此在您释放挂起之前，存储会持续增长。彻底替换表（upsert 或 SCD-2 替换）会开始全新的快照历史记录，旧历史记录上的任何挂起也会随之丢失。</Aside>

通过 REST API 一次性还原项目中的所有表时，会将每个表还原到其最近一次挂起的快照，没有挂起的表保持不变。回退前安全快照不算作挂起，尽管“快照”面板可能会将其标记为已挂起，除非您自己也挂起该快照，例如使用**挂起**。以 `pre-revert_` 开头的快照名称保留给安全快照使用。如果有任何表无法还原，其他表仍会被还原，并且请求会失败，同时指明每个未能还原的表及原因。

<Aside>为按需快照命名的功能适用于 Lakehouse (StarRocks) 表。挂起和释放快照现在也适用于基于 Databend 的表；在那里，即使没有挂起，快照仍会在保留期内保留。</Aside>

## 审核

就地回退（无论来自对话框、REST API 还是 AI 助手）都会记录在 Lakehouse 审核日志中，包括执行回退的人员、时间、回退到的快照以及保留的安全快照，因此通过此功能对表所做的更改都是可追溯的。
