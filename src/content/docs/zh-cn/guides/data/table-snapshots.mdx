每次写入表时，PlaidCloud 的 Lakehouse 都会保留表在该时刻的**快照**，即数据在某个时间点的一致性副本。借助快照，可以回看表之前包含的内容、从错误的加载中恢复，以及审计表随时间发生的变化。可回溯的时间范围取决于表的时间旅行设置：默认为 1 天，项目默认值或延长了该设置的表最长可达 90 天。请参阅[管理存储](/zh-cn/guides/projects/managing-storage/)。

要通过 SQL 读取表在某个快照时的状态，请从 [Lakehouse 窗口](/zh-cn/guides/data/lakehouse-window/#复制时间旅行查询)中该表的详细信息里复制一条 `FOR VERSION AS OF` 查询。

在“快照”面板中，可以浏览该历史记录，在表资源管理器中以只读方式打开任意快照，以及将表回退或还原到较早的快照。

## 打开快照面板

在项目的**表**列表中，单击表所在行上的快照/闪回按钮。随即打开**快照**面板，按从新到旧的顺序列出该表的快照：

- **时间** — 拍摄快照的日期和时间。
- **行** — 该快照时表的行数。
- **Δ 行** — 与上一个快照相比行数的变化，便于查看每次写入添加或删除了多少行。
- **大小** — 快照的压缩存储大小。
- **标签** — 为已命名或已固定的快照设置的名称。
- **已挂起** — 已挂起快照（保留时间超出正常保留期）的固定标记。

## 查看快照时的数据

有两种方式可以查看表在较早时间点的数据。两种方式都会在表资源管理器中打开**只读历史视图**，其中的横幅会显示正在查看的快照，并提供**返回当前数据**按钮。

1. **从快照面板** — 选择一个快照，然后单击**查看快照**。
2. **从表资源管理器** — 使用工具栏中的 **As of** 下拉列表。其中列出表的最近快照；选择一个快照即可切换视图，选择**当前（实时数据）** 则返回实时数据。

<Aside>历史视图是只读的，它是通向过去的窗口，而不是可编辑的副本。如果想把旧数据恢复到表中，请使用**回退**或**还原**（见下文）。</Aside>

## 回退或还原快照

选择一个快照，然后单击**回退/还原**。对话框提供两种选择：

- **就地回退此表**（默认）— 用快照替换表的当前数据。由于此操作具有破坏性，需要输入表名进行确认。在替换数据之前，PlaidCloud 会自动捕获当前状态的**回退前安全快照**（在支持固定的存储引擎上），因此始终可以回到原来的状态。在 Databend Lakehouse 上，如果表的列在该快照之后发生了更改，就地回退会被拒绝，并列出已更改的列；此时请改为还原到新表。
- **将快照恢复到新表** — 原始表保持不变，并在项目中创建一个新表（需为其指定名称和文件夹），用快照中的数据填充，列与源表相同。通过 AI 助手或 MCP 还原时，如果未指定名称，会根据源表生成一个名称，例如 `Sales (restored 3f2a9c1d)`。

<Aside type="caution">就地回退会覆盖表的当前数据。输入确认和自动的回退前安全快照都是为了保护数据，确认之前请仔细阅读对话框。项目锁定期间无法执行回退。</Aside>

<Aside>通过 REST API 或 MCP，不指定目标表或将目标表指定为该表本身，即可就地还原快照。这种就地还原与对话框中的回退享有相同的保护：在存储引擎支持的情况下创建回退前安全快照，并留下审计记录。如果希望在列出快照后表又被写入时拒绝该操作，请将看到的最新快照作为 `expected_current_snapshot_id` 传入。</Aside>

<Aside>如果还原到新表失败（例如快照已过期），项目中不会添加新表。</Aside>

## 命名、固定和保留

快照会在每晚的清理中按照表的时间旅行设置（默认 1 天，最长 90 天）过期。回退或还原最早可追溯到为该表显示的最早可还原时间点。要将某个快照保留更长时间：

- **创建快照**按需为当前数据创建一个挂起的快照，在进行有风险的重新加载之前很有用（例如“before Q2 reload”）。
- **挂起**固定所选快照；**释放**解除挂起，使其恢复正常的生命周期。

<Aside type="caution">挂起保留的不止一个快照：它会保留挂起的快照*以及*其后写入的每个快照，因此在解除挂起之前，存储会持续增长。直接替换表（upsert 或 SCD-2 替换）会开始一个全新的快照历史记录，旧历史记录上的任何挂起也会随之丢失。</Aside>

通过 REST API 一次性还原项目中的所有表时，每个表都会还原到其最近的挂起快照，没有挂起的表保持不变。回退前安全快照不算作挂起（尽管快照面板可能将其标记为已挂起），除非您自己也挂起了该快照，例如使用**挂起**。以 `pre-revert_` 开头的快照名称保留给安全快照使用。如果有任何表无法还原，其他表仍会被还原，而请求会失败，并列出每个未还原的表及其原因。

<Aside>为按需快照命名适用于 Lakehouse（StarRocks）表。挂起和释放快照现在也适用于基于 Databend 的表；在这些表上，即使没有挂起，快照仍会在保留期内保留。</Aside>

## 审计

就地回退无论是通过对话框、REST API 还是 AI 助手执行，都会记录在 Lakehouse 审计日志中，包括执行回退的人员、时间、回退到的快照以及保留的安全快照，因此通过此功能对表所做的更改都可追溯。
