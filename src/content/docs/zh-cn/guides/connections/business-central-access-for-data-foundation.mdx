[Data Foundation](/zh-cn/guides/projects/data-foundation/) 将您连接的每个 ERP 系统和实例中的数据汇集到同一个 Common Finance Model 中，Microsoft Dynamics 365 Business Central 就是它可直接读取的 ERP 之一。该连接使用采用客户端凭据的 Microsoft Entra ID 应用、一个只读权限集，以及几个作为 Web 服务发布的页面对象。本页面面向负责这些设置的 Business Central 管理员，以及向其提出请求的 PlaidCloud 用户。

PlaidCloud 只读取数据。切勿通过电子邮件发送客户端密钥。

## 发送访问请求

在 **主页** 的 **Data Foundation** 下打开项目的 **系统** 页面，在 **添加系统** 下的 **系统** 中选择您的系统，然后点击 **还没有访问权限？**。该系统会进入等待访问权限状态，并显示一份涵盖项目各个系统的请求。点击 **复制请求** 可将其粘贴到您自己的邮件中，点击 **通过电子邮件发送请求** 则会在您的邮件程序中打开，邮件主题为“PlaidCloud 访问权限”。

## Business Central 管理员需要完成的设置

<Steps>

1. **在 Microsoft Entra ID 中注册应用**。在 **App registrations > New registration** 下添加客户端密钥，并记下目录（租户）ID、应用程序（客户端）ID 和密钥。

2. **在 Business Central 中添加该应用**。打开 **Microsoft Entra Applications**，添加该应用程序，将其状态设为 **已启用**，并为您需要报告的每个公司仅授予权限集 **D365 READ**。它可读取下列所有页面。不要授予 **D365 BASIC** 或任何其他可写入的权限集。

3. **将页面对象发布为 Web 服务**。在 **Search > Web Services > New** 下，按以下服务名称发布这些页面对象，并勾选 **Published**。标准 API 不包含这些对象的字段：

   | 页面 | 服务名称 | 备注 |
   |---|---|---|
   | 20 G/L Entries | `GLEntries` | |
   | 16 Chart of Accounts | `GLAccounts` | |
   | 100 Accounting Periods | `AccountingPeriods` | |
   | 537 Dimension Values | `DimensionValues` | |
   | 240 Business Units | `BusinessUnits` | |
   | 605 IC Partner List | `ICPartners` | |
   | 5802 Value Entries | `ValueEntries` | 销售成本和库存余额；可选 |
   | 120 G/L Budget Entries | `GLBudgetEntries` | 预算；可选 |
   | Statistical Ledger Entries | `StatisticalLedgerEntries` | 统计动因；可选 |
   | 118 General Ledger Setup | `GeneralLedgerSetup` | 快捷维度 3 至 8；可选 |
   | 479 Dimension Set Entries | `DimensionSetEntries` | 快捷维度 3 至 8；可选 |
   | 573 Detailed Cust. Ledg. Entries | `DetailedCustLedgEntries` | 未清项和付款；可选 |
   | 574 Detailed Vendor Ledg. Entries | `DetailedVendorLedgEntries` | 未清项和付款；可选 |
   | 371 Bank Account List | `BankAccounts` | 银行余额；可选 |
   | 277 Bank Account Posting Groups | `BankAccountPostingGroups` | 银行余额；可选 |
   | Inventory Posting Setup（搜索其页面） | `InventoryPostingSetup` | 物料采购明细行的科目；可选 |

4. **告知 PlaidCloud 用户三项选择**：您的审计调整所使用的来源代码（PlaidCloud 默认为 `ADJUSTMENT`）、哪个维度代表您的部门（PlaidCloud 默认为全局维度 1，名为 `DEPARTMENT`），以及哪个维度代表您的利润中心（PlaidCloud 默认为全局维度 2，名为 `PROFITCENTER`）。站点即 Business Central 中的地点（location）。

</Steps>

## 需要回传的信息

| 管理员发送的内容 | 在 PlaidCloud 中填入的位置 |
|---|---|
| 目录（租户）ID | **Azure AD 租户 ID** |
| 应用程序（客户端）ID | **客户端 ID** |
| 客户端密钥 | **客户端密钥**，在连接编辑器中填写，不要通过电子邮件发送 |
| 环境名称，例如 `production` | **环境** |
| 一个公司的 ID | **公司 ID**：连接需要一个公司 ID，Data Foundation 会读取在 **公司** 下选择的公司 |
| 代表您部门的维度的名称 | 系统设置 **Department dimension** |
| 代表您利润中心的维度的名称 | 系统设置 **Profit centre dimension** |
| 您的审计调整所使用的来源代码 | 系统设置 **Audit adjustment source code** |
| PlaidCloud 可读取的公司 | 在 **选项** 的 **公司** 下勾选，或不勾选以读取所有公司 |

属于合并公司的公司应填入系统设置 **Consolidation companies**，这样它们的分录就不会被计为某个公司的业务活动。汇率取自一个公司：在系统设置 **Exchange rate company** 中指定该公司，否则 PlaidCloud 会使用第一个公司。

## 检查访问权限

回到 PlaidCloud，添加系统后，在 **系统** 页面上该系统所在的行中点击 **测试连接**。每个数据集会显示为 **可读取**、**缺少权限** 或 **错误**：

| 数据集 | 所需条件 |
|---|---|
| 实体、会计科目表、客户、产品、汇率、试算平衡表 | API 访问权限（权限集 D365 READ） |
| 财务日历 | `AccountingPeriods` Web 服务 |
| 部门 | `DimensionValues` Web 服务 |
| 总账 | `GLEntries` Web 服务 |
| 其他所有数据集 | 可选，不在测试范围内 |

数据集缺失时，测试会说明需要添加哪个权限或 Web 服务。请管理员添加后再次测试。

可选数据集包括站点、利润中心、供应商、月末余额、银行余额、库存余额、销售明细行、供应商发票明细行、未清项、付款、预算和分摊动因。不使用其中某项的环境仍可加载其他所有数据；下次加载后，**CFM-Accounting - Close and assurance** 仪表板上的就绪状态检查会指出 Business Central 拒绝读取的任何页面。月末余额是每个月末的试算平衡表；银行余额是您的银行账户所过账科目的该余额。当 Business Central 拒绝了构建某个月份的月末余额、银行余额、库存、销售明细行、供应商发票明细行、未清项或付款所需的读取时，该月份会保留其已有的行，并在下次加载时重新读取。
