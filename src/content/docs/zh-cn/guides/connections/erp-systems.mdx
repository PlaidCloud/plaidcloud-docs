**系统**是某个环境中的一个 ERP 连接。**过账凭证**步骤、从文件过账以及其他所有过账方式（请参阅[向 ERP 系统过账凭证](/zh-cn/guides/connections/post-documents/)）都会把每张凭证发送到某个系统，由该系统决定凭证如何构建、检查和发送。您能看到的每个 ERP 连接都会自动成为一个系统：五个 SAP 连接就是五个系统，云端和本地部署并存；同一个连接在沙盒和生产[环境](/zh-cn/guides/connections/create-connection/#环境)中则是两个系统，各自有独立的设置。

系统按环境设置一次即可。该环境中的每个项目共享“哪个实体过账到哪里”的网格以及各系统的设置。只有“上线”是按项目进行的。

## 打开系统

打开[过账登记簿](/zh-cn/guides/connections/posting-register/)，在左侧栏的**设置**下选择**系统**。页眉包含：

- 环境选择器：选择要列出其系统的环境。
- 项目选择器，初始为**无项目**。选择一个项目后，可查看每个系统在该项目中是否处于实时状态，并可上线。
- **操作**，其中有**在此项目中上线…**（向项目架构师显示）、**复制到其他环境…**（向工作区管理员显示）、**建议各实体过账到哪里…**和**更改历史**。

页面显示两张卡片：**系统 · *环境***和**哪个实体向何处过账**。如果环境中没有 ERP 连接，页面会显示**没有可过账的系统**：在“连接”中添加到 ERP 系统的连接后，它就会出现在这里。

## 系统列表

每个系统占一行：包括其名称、ERP 类型和一组标签。

| 标签 | 含义 |
|---|---|
| **云端** | 云端系统。 |
| **本地部署 · 代理在线** | 本地部署系统，其代理在最近五分钟内有过联系。 |
| **本地部署 · 代理自 *时间* 起离线** / **本地部署 · 代理未连接** | 代理不在线，或没有代理服务于此环境。 |
| **可过账** | 可以向该系统过账。 |
| **未检查** | 代理不在线的本地部署系统。 |
| **实时** / **模拟** | 仅在选择了项目时显示：该系统在该项目中是否真实过账。 |
| **已停用** | 该系统不再接受新的过账。取代“实时”或“模拟”显示。 |

一行还可以带有两个按钮：

- **重新连接**：当本地部署系统的代理不在线时显示。它会打开连接，以便您重新登录。
- **上线 ›**：在已选择项目时，向项目架构师显示，适用于未停用、可过账且仍处于“模拟”的系统。请参阅[上线](#上线)。

### 一行展开后的内容

使用行左侧的切换按钮展开一行。它会显示三项内容和一排链接。

**待办事项**是系统与过账之间仍需完成的事项清单，每项都注明由谁负责。已完成的事项会被勾选并标记为已完成。

| 事项 | 负责人 | 完成条件 |
|---|---|---|
| 服务账户及其权限 | **IT** | 目前始终已完成，无需设置。 |
| 已安装代理且代理在线（仅限本地部署） | **IT** | 代理在线。 |
| 有实体过账到此系统 | **工作区管理员** | [哪个实体向何处过账](#哪个实体向何处过账)中有一行指定了此系统。 |
| 上线 | **项目架构师** | 系统在所选项目中处于实时状态。 |

**可执行的操作**是一行文字，例如“可处理日记账、客户发票 · 可冲销日记账 · 在调用中返回结果”。它列出系统可处理的凭证类型、可冲销的类型，以及其答复是**在调用中返回结果**还是**稍后返回结果**。每个系统的完整列表见下文的[各系统能做什么](#各系统能做什么)。

**其列表的副本**显示系统的科目、公司和期间副本有多旧，并提供**立即刷新**和**查看副本**。请参阅[系统列表的副本](#系统列表的副本)。

它们下方的链接是**供 IT 使用**、**设置…**、**标记为已停用**（或**从“已停用”恢复**）以及**历史记录**，其中**历史记录**会仅针对该系统打开[更改历史](#更改历史)。

## 有哪些设置

每项设置都有初始值，大多数项目从不需要更改。

| 设置 | 位置 | 谁来更改 | 初始值 |
|---|---|---|---|
| 哪个实体向何处过账 | 每个环境一次，在[系统](#哪个实体向何处过账)中 | 工作区管理员 | 无行。没有行时，**系统**中列出的唯一未停用的系统处理所有实体。 |
| 已停用 | 系统所在行 | 工作区管理员 | 未停用 |
| 模拟或实时 | 按系统、按项目在[上线](#上线)中设置 | 项目的架构师 | 模拟 |
| **每次都需要的值** | 系统的[设置](#系统设置) | 工作区管理员 | 无 |
| **代码匹配**（包括实体匹配） | 系统的[设置](#系统设置) | 工作区管理员 | 无 |
| **客户自有函数**（SAP 本地部署） | 系统的[设置](#系统设置) | 工作区管理员 | 无，或由已转换步骤带来的函数 |
| 暂挂规则 | 按系统，在[暂挂规则](#暂挂规则)中 | 登记簿管理员（`erp.register.admin`） | 没有暂挂内容 |
| **交由人工处理** | 步骤，位于**更多 ▸** 下 | 步骤的构建者 | 没有暂挂内容 |
| **通知对象** | 步骤，位于**更多 ▸** 下 | 步骤的构建者 | **启动运行的人** |
| **舍入科目和限额** | 步骤，位于**更多 ▸** 下 | 步骤的构建者 | 不舍入 |
| **已过账凭证被更改时** | 步骤，位于**更多 ▸** 下 | 步骤的构建者 | **询问（初始值）。该凭证将列入“需要关注”，并提供两个选项。** |

这四项步骤设置与步骤一起在[向 ERP 系统过账凭证](/zh-cn/guides/connections/post-documents/)中说明；步骤自己的暂挂见[下文](#步骤自己的暂挂)。

## 系统设置

在展开的行上选择**设置…**。对话框**设置：*系统***仅工作区管理员可以编辑；其他人会看到**只有工作区管理员可以更改这些设置。** **保存**会替换该系统的全部设置，每次更改都会记录在[更改历史](#更改历史)中。

**每次都需要的值**是添加到发送给该系统的每张凭证上的值，以**值**和**设置为**成对出现。系统按名称读取它所需要的值，凭证自带的同义列优先于系统的值：

| 系统 | 值 | 用途 |
|---|---|---|
| Sage Intacct | `gl_journal_id` | 当凭证没有 `journal_type` 时，日记账分录过账到的日记账。 |
| Sage 100 | `bank_code` | 当凭证没有 `bank_code` 时，付款所使用的银行账户。 |

**代码匹配**说明这里的某个代码在系统中对应另一个代码，包含**维度**、**我方代码**和**系统中的代码**。对于在系统中公司代码不同的实体，使用维度 `entity`；对于科目，使用 `account`。[检查](#对照列表的检查)会通过匹配在系统的列表中查找代码，没有匹配时则按原样查找，实体匹配还能让网格为该实体[建议](#建议的行)此系统。

**客户自有函数**仅在 SAP 本地部署时出现。为每种**单据类型**指定函数。设置中只指定函数：每个函数的字段匹配（SAP 的哪个字段接收哪一列）原样保存在系统上，而由已转换的 SAP 过账步骤带来的函数会保留该步骤原有的字段匹配。请参阅 [SAP 本地部署](#sap-本地部署)。

## 哪个实体向何处过账

第二张卡片是一个网格，规定哪个实体从哪个日期起过账到哪个系统，按环境设置一次，并由该环境中的每个项目共享。每行包含一个实体、**→**、一个系统和一个可选的**起始日期（YYYY-MM-DD）**。

1. 选择**添加一行**，输入实体，并从**选择系统**中选择一个系统。仅提供未停用的系统。
2. **起始日期（YYYY-MM-DD）** 留空表示“从一开始”，或填写该实体开始过账到该系统的日期。若要在年中把实体转到另一个系统，请保留它的第一行，再添加第二行，写明新系统及其转入日期，例如 `2026-07-01`。
3. 选择**保存**。格式不符的日期会被拒绝，并提示**日期格式如 2026-07-01。**

编辑网格需要工作区管理员；其他人只能只读查看。已保存的实体无法重命名：请用行末的叉号删除其行，再添加另一行。凭证中出现过但尚无任何行指定的实体会列出，且不选择系统；若一个都没有，卡片会显示**暂无实体。它们是在您过账的表中找到的实体。添加一行即可指定一个。**

### 凭证如何找到其系统

凭证通过其项目所在环境的系统过账。

- 其系统是实体中“起始日期”不晚于凭证过账日期（无过账日期时为今天）的最新一行。
- 当环境的网格完全没有行，且**系统**中只列出了一个未停用的系统时，该系统处理所有凭证。
- 若没有任何行在该日期覆盖凭证的实体，则该凭证不会过账，并提示其实体没有对应的系统。
- 若凭证所在行指定的系统已停用，则该凭证不会过账，并提示该系统已停用。

### 建议的行

对于尚无任何行指定的实体，当环境中恰好有一个未停用的系统通过 `entity` [代码匹配](#系统设置)或在其自己的公司列表副本中指明了该实体时，网格会建议该系统。该行显示**建议**，并保持只读，直到您选择**接受**；只有已接受的行才会被保存。

**操作**中的**建议各实体过账到哪里…** 是 Weave 基于 Data Foundation 给出的建议：选择项目后，它会为该项目的 Foundation 加载的每个实体填入加载它的连接。不会由模型计算任何内容，也不会保存任何内容：这些行只是被填好，并有消息说明填了多少行，您逐行阅读后选择**保存**。如果没有加载任何内容，则显示**暂无建议。**

### 此处无法更改的行

- 系统已停用的行以只读方式显示，并带有**已停用**。保存网格会保留它。
- 系统您看不到的行以只读方式显示，并带有**不在此列表中**。保存网格会将其删除，因此**保存**会先请您在**保存路由**中确认。

## 上线

只有有人有意上线后，才会真实过账。上线按系统、按项目进行：在同一个项目中，有些系统可以处于实时状态，而其他系统仍处于“模拟”。新建、复制或试用的项目在每个系统上都从“模拟”开始，直到有人在其中上线。

1. 在页眉的项目选择器中选择项目。
2. 在系统所在行选择**上线 ›**，或在**操作**中选择**在此项目中上线…**，对所有可过账但尚未实时的系统上线。未选择项目时，会提示**选择要上线的项目。**
3. **上线**对话框会先检查将发生的更改（不会真正更改任何内容）并显示出来：
   - **这些将变为实时**：将真实过账的系统。
   - **项目的过账模式将变为“正式”，因此每个正式系统都会真实过账。**：当项目本身尚未处于实时模式时显示。
   - **已实时**：已经是实时状态的系统。
   - ***系统*无法上线：** 并给出原因：系统已停用、项目已锁定、您对该连接没有写入权限，或它不是您可以过账的系统。
4. 选择**上线**。仅当至少有一个系统将变为实时时，它才可用。

上线会写入项目对这些系统在该环境中的授权，并在项目的过账模式尚未为实时时将其设置为实时。每个上线的系统都会记录在[更改历史](#更改历史)中。上线绝不会复制到其他环境或项目。

上线需要项目的架构师，项目不能被锁定，并且您自己对每个连接具有写入权限。通过 REST API（`POST /erp/go-live`）和 MCP 工具 `erp_go_live` 时适用同样的检查，后者还会拒绝委托的 AI 令牌：上线由人来完成，绝不由代表人的代理完成。除非将 `dry_run` 设为 false，否则两者都只报告将发生的更改。

## 停用系统

在展开的行上选择**标记为已停用**，并用**停用**确认：系统将不再提供过账，直到被恢复。它在网格中的行会保留，路由到它的凭证不会过账。**从“已停用”恢复**则可撤销此操作。两者都需要工作区管理员，并记录在[更改历史](#更改历史)中。

## 供 IT 使用

**供 IT 使用**会打开**供 IT 使用：*系统***，其中列出产品在该系统中的操作，以便对其放行和审计：

- **登录身份**：连接登录所用的账户。
- **批大小**：系统设置所设置的批大小，或**未设置**。
- **代理**和**代理版本**：适用于本地部署系统。
- **我们的称呼**：产品按名称调用的每个函数或服务，以及上次使用的时间。对于 SAP 本地部署，这些是在[设置](#系统设置)中设置的函数。在尚未过账或测试之前，它显示**暂无内容。向此系统过账或测试后将列出。**

登录过期时，对话框会说明，并提供**重新连接**。

## 复制到其他环境

沙盒只需设置一次，然后复制到生产，而不必重新输入。在**操作**中选择**复制到其他环境…**（仅限工作区管理员）。

1. 在**复制到**下选择环境。
2. 此环境的每个系统都会列出；当同一连接在另一个环境中也是系统时，该系统会被勾选；不是的则显示为***系统*（不在此环境中）**，无法勾选。
3. 选择**复制**并确认。

对于每个已勾选的系统，复制会用这里的内容替换另一个环境中该系统的设置、代码匹配和 SAP 函数，并添加网格中指定该系统且另一个环境所没有的行（同一实体、同一起始日期）。已存在的行保持原样。结果会说明复制了多少行网格和多少个系统的设置。“上线”不会被复制：另一个环境中的每个项目都保持“模拟”，直到有人在那里上线。

## 系统列表的副本

检查会把凭证与系统自己的**科目**、**公司**和**期间**进行比较。PlaidCloud 保存其中每一项的副本，直接从系统读取：

- **在实时系统上每次实时运行开始时**，从系统读取，整个读取最多 60 秒。只有该次运行的读取才能阻止凭证。
- **在展开的行上选择立即刷新时**。刷新会像过账一样联系您的 ERP 系统，因此需要工作区管理员，以及您自己对该连接的写入权限。它会报告读取了多少个科目、公司和期间，以及读取耗时。刷新后的副本仅供查看：它不会用于检查。

每个列表都在行上显示其时效，例如“科目读取于 3 小时前”“期间部分读取，读取于 2 天前”或“公司尚未读取”，或者说明无法读取及其原因。被中断或返回为空的副本不会替换之前的副本。

**查看副本**会打开**列表的副本**，每次显示一个列表（**科目**、**公司**或**期间**），包含**代码**、**名称**、**已阻止**、**系统中的状态**、**从**和**至**。最多显示前 5,000 行。税码、客户和供应商不会被复制，留给系统处理。

“模拟”运行不会从系统读取任何内容，因此在“模拟”中这些检查不会运行，由系统在您上线时决定。

## 对照列表的检查

在实时系统上的实时运行开始时，每张凭证都会对照该次运行读取的列表进行检查。如果某个检查所需的列表无法读取、读取不完整或为空，或未能及时完成，则该检查视为未检查：既不算通过，也不会阻止，由系统决定。运行页面会显示每张凭证运行了哪些检查。

- **Period open**（期间未结）。 凭证的期间通过其期间代码查找，否则通过其过账日期所在的期间查找。只有当包含它的每个期间在系统中都已关闭过账时，才会被阻止：与其月份重叠的调整期间会使该日期保持开放。如果系统用 PlaidCloud 不认识的措辞报告期间状态，则该期间不会被检查。
- **实体是一家公司。** 读取公司列表后，凭证的实体（通过其 `entity` 代码匹配（若有），否则按原样）必须是系统中的公司之一。
- **科目存在。** 读取科目列表后，每一行的科目（通过其 `account` 代码匹配（若有），否则按原样）必须存在于系统中，且未被阻止过账。数字代码的匹配与前导零无关，因此 `6100` 能找到 `0000006100`。

被阻止的凭证显示为“未过账”并附原因，例如“第 3 行：科目 6100 不在 *系统* 中”。各 ERP 系统提供哪些列表见下表。

## 暂挂规则

在规则要求之前，不会暂挂任何内容。被规则暂挂的凭证会以“需要审批”状态等待，由人员在[审批](/zh-cn/guides/connections/posting-register/)中批准；其他通过检查的凭证则无需审批直接发送。在左侧栏的**设置**下选择**暂挂规则**。

列表包含**名称**、**适用于**、**暂挂条件**、**批准人**和**操作者**。没有规则时显示**没有暂挂内容**。拥有 `erp.register.view` 的人都可以阅读规则；添加、编辑和删除需要登记簿管理员（`erp.register.admin`），其工具栏中会显示**新建规则**、**编辑**和**删除**。删除规则后，它不再暂挂新的内容；已在等待的凭证继续等待，直到有人做出决定。每次更改都会记录在[更改历史](#更改历史)中。

### 规则的条件

**新建规则**会打开**新建暂挂规则**：

1. 为规则**命名**，例如“超过 250,000 的日记账”。
2. 在**适用于**下选择系统。会提供您能看到的所有环境中的系统。
3. 在**暂挂条件**下勾选会暂挂凭证的情形。所有已勾选的条件都必须满足才会暂挂；什么都不勾选，则不暂挂任何内容。
   - **金额超过**某个数值，**以实体自身的货币计**：凭证的大小是其借方加正的本币金额，或者当表中没有本币金额时，是其交易金额。
   - **它是从文件过账的**。
   - **它是**一笔**冲销**、**贷项**或**更正**：三者可任选其一或多个。
   - **它被标记为异常**：请参阅[标记为异常](#标记为异常)。
   - **始终暂挂，例如在结账期间**：暂挂系统上的每张凭证；它会关闭其他条件。
4. 在**批准人**下选择由谁批准：**登记簿的批准人**，或**指定人员**：勾选人员，并可选择填写他们负责批准的实体，用逗号分隔（留空表示所有实体）。
5. 选择**保存**。当规则有名称、系统、至少一个条件、为数字的金额，并且（指定人员时）至少有一个人员后，它才可用。

被暂挂的凭证会使其所在批次的其他所有凭证一并暂挂，因此一个批次会作为一个整体被批准并过账。

### 谁可以批准

批准人需要 `erp.register.approve`，并在凭证所在的连接上拥有自己的授权。当规则指定了人员时，只有这些人员可以批准，并且如果规则列出了实体，也只能批准这些实体。任何人都不能批准自己发送的凭证：既不能是启动运行的人，也不能是通过**过账这些**发送它的人。

凭证在“模拟”下发送时给出的批准，对实时发送无效：当同一张凭证之后以实时方式发送时，它会再次被暂挂，等待新的决定。

如果您的工作区要求过账职责分离，那么即使没有规则，其所涵盖的冲销、贷项或更正也会被暂挂，等待第二个人处理。

### 步骤自己的暂挂

**过账凭证**步骤可以暂挂得比其系统更多，位于**更多 ▸** → **交由人工处理**。其条件为**金额高于**、**它是从文件过账的**、**属于冲销、贷项或更正**、**它被标记为异常**和**始终**，组合方式相同；什么都不勾选，则不会再多暂挂任何内容。步骤的暂挂只是在系统规则之外增加条件，它无法放行系统规则所暂挂的内容，其凭证由登记簿的批准人批准。指定批准人须在系统规则上设置。

通过 REST API（`PUT /erp/steps/{step_id}/holds`）或 MCP 工具 `erp_hold_upsert` 更改步骤的暂挂，需要 `analyze.step.write`，以及在未锁定项目中的项目架构师或管理者角色。

### 标记为异常

与其实体之前过账的内容相比，满足以下情形时，凭证会被标记为异常：

- 其金额比同一引用的上一次过账大十倍以上或小十倍以上；
- 它使用了其实体在最近 500 张凭证中未使用过的科目、客户、供应商或交易伙伴；或
- 其过账日期不在其期间内。

每个标记都会记录说明原因的句子，例如“过账日期 2026-08-02 不在期间 2026-07 内。”该标记根据实体之前的凭证计算得出，不会调用任何 AI 模型。没有先前凭证的实体绝不会被标记。

## 各系统能做什么

下面的每个系统都可以在“模拟”中运行，“模拟”会构建并检查每张凭证，但不发送任何内容。系统不接受的类型的凭证显示为“未过账”，不会被转换为其他类型。

| 系统 | 位置 | 可处理 | 可冲销 | 答复 | 检查所用的列表 |
|---|---|---|---|---|---|
| NetSuite | 云端 | 日记账、客户发票 | 日记账 | 在调用中 | 科目、子公司、过账期间 |
| Sage Intacct | 云端 | 日记账、客户发票 | 日记账 | 在调用中 | 科目、实体、报告期间 |
| QuickBooks | 云端 | 日记账、客户发票、供应商发票、贷项通知单 | 日记账、客户发票 | 在调用中 | 科目、公司、截至账簿结账日期已关闭的月份 |
| Xero | 云端 | 日记账、客户发票、供应商发票、贷项通知单 | 日记账、客户发票 | 在调用中 | 科目、组织、截至锁定日期已关闭的月份 |
| Acumatica | 云端 | 日记账、客户发票、供应商发票、付款、贷项通知单 | 日记账 | 稍后 | 科目、分支机构、财务期间 |
| Business Central | 云端 | 日记账 | 日记账 | 在调用中 | 公司、科目、会计期间 |
| Dynamics 365 F&O | 云端 | 日记账 | 日记账 | 稍后 | 主科目、法人实体、会计期间 |
| Oracle Fusion | 云端 | 日记账 | 日记账 | 稍后 | 分类账、科目组合、会计期间 |
| S/4HANA Cloud | 云端 | 日记账 | 日记账 | 稍后 | 公司代码、总账科目：无期间，因此不检查“Period open” |
| Workday | 云端 | 日记账 | 日记账 | 稍后 | 公司、分类账科目、会计期间 |

**在调用中**返回的答复会在凭证发送时返回。**稍后**返回的答复在发送之后才到达，凭证在此之前处于“等待中”；答复始终未确定的凭证为“未确认”，您可以从[过账登记簿](/zh-cn/guides/connections/posting-register/)中处理。

### SAP 本地部署

SAP 本地部署通过代理过账，为每种单据类型调用客户自有的函数，函数在[**客户自有函数**](#系统设置)下设置。如果凭证的类型没有函数，或者函数的字段匹配中没有凭证引用对应的字段，则该凭证为“未过账”。转换现有的 SAP 过账步骤时，如果系统尚无该单据类型的函数，会把该步骤的函数和字段匹配带到系统中；请参阅[向 ERP 系统过账凭证](/zh-cn/guides/connections/post-documents/)。

- **模拟**会构建相同的请求，并在到达代理之前停止：不会有任何内容到达 SAP。
- **实时**会把凭证交给服务于系统所在环境的代理。代理把 SAP 的答复写入项目默认文档账户中的报告（位于 `/erp_posting/sap` 下），每张凭证保持“等待中”，直到读取该报告。没有默认文档账户的项目无法向 SAP 实时过账，其凭证为“未过账”并给出该原因。
- **当代理离线时**，不会发送任何内容：凭证为“未过账”，并说明代理已离线，待代理恢复后可以重试。如果代理在大约 18 秒内没有接收凭证，它们会被未发送地收回，并以同样方式显示为“未过账”。
- SAP 的报告中尚未确定的凭证为“未确认”。请从过账登记簿中处理。

### Sage 100

Sage 100 是本地部署系统，没有网络 API：凭证通过代理到达它，代理运行 Sage 的 Business Object Interface。

- **每个连接对应一家公司。** 连接指定 Sage 公司及其货币。其他公司的凭证，或有行使用其他货币的凭证，不会发送。
- **日记账**作为总账日记账分录过账。日记账的引用在 Sage 中是其描述，因此最多 30 个字符。
- **付款**作为应付手工支票过账，用于在 Sage 之外支付的款项：每笔付款对应一个供应商，引用作为支票号码（最多 7 个字符），一个 `bank_code`（来自凭证，或系统的[每次都需要的值](#系统设置)），且每一行都指明其所支付的发票并带有正金额。
- **在实时运行中**，代理会先询问 Sage：日期落在 Sage 已关闭期间的日记账会被阻止，对 Sage 中未保持未结的发票的付款也会被阻止。
- **发送之后**，只有 Sage 已过账的表中能看到某张凭证时，它才是“已过账”。已录入 Sage 批次但尚未更新的凭证保持“等待中”；后台扫描会再次询问代理，最多每小时一次，等待超过七天的凭证会变为“未确认”。

## 更改历史

对系统的每次更改都会记录是谁在何时所做：**系统设置**、**已停用**、**SAP 函数**、**代码匹配**、**哪个实体向何处过账**、**暂挂规则**、**上线**和**列表复制**（对系统列表的每次读取）。在左侧栏的**设置**下或**操作**菜单中选择**更改历史**，或在系统所在行选择**历史记录**，仅查看该系统。列表包含**时间**、**操作者**、**内容**、**系统**、**哪个**、**从**和**至**。

您可以看到自己持有授权的系统的更改；上线仅限您能访问的项目，步骤的暂挂也仅限您能访问的项目。

## 谁可以做什么

除非某行另有说明，下面的每条规则都由服务器检查，对应用、REST API 和 MCP 工具都相同。

| 要做的事 | 您需要 |
|---|---|
| 查看系统、系统的设置、网格及其列表的副本 | `analyze.connection.read`，且仅限您能看到的连接 |
| 更改设置、停用系统、保存网格、复制到其他环境 | 工作区管理员 |
| 刷新系统的列表 | 在“系统”页面上为工作区管理员，或通过 REST API 和 MCP 工具 `erp_system_lists` 拥有 `analyze.connection.read`；无论哪种方式，都需要您自己对该连接的写入权限 |
| 上线 | 未锁定项目的架构师，并且您自己对每个连接具有写入权限；必须是人，绝不能是委托的 AI 令牌 |
| 阅读暂挂规则 | `erp.register.view` |
| 添加、更改或删除系统的暂挂规则 | 登记簿管理员（`erp.register.admin`） |
| 更改步骤自己的暂挂 | `analyze.step.write`，以及在未锁定项目中的项目架构师或管理者角色 |
| 批准被暂挂的凭证 | `erp.register.approve` 以及您自己对凭证所在连接的授权；规则指定了人员时须在规则中列出；绝不能批准自己发送的凭证 |
