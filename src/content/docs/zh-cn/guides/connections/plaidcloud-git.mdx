**PlaidCloud Git 连接**可将工作流（或服务器 Panel 应用的构建）指向工作区自有托管 Git 服务器上的存储库。该 Git 服务器由系统为您托管在 `git.<your-workspace>.plaid.cloud`，并且您已通过常规 PlaidCloud 登录完成身份验证，因此连接表单比外部 Git 提供商的表单简单得多：无需输入服务器 URL，也无需管理用户名、令牌或 SSH 密钥。

<Aside type="note">PlaidCloud Git 连接无需输入服务器 URL 或凭据。工作区的 Git 服务器以及您对它的访问权限会根据 PlaidCloud 登录信息（包括 SSO）自动处理，因此无需生成、存储或轮换令牌。</Aside>

## 适用场景

当要读取的存储库位于 [PlaidCloud Git](/zh-cn/guides/git/)（工作区的内置 Git 服务）而不是外部主机上时，请使用 PlaidCloud Git 连接。最常见的用途是基于托管存储库自动构建**服务器 Panel 应用**或 **Dash 应用**：向某个分支推送代码即可重新构建并重新部署应用，无需外部 GitHub 账户或个人访问令牌。

对于托管在外部服务（GitHub、GitLab、Bitbucket、Forgejo 或 Gitea）上的存储库，请改用[外部 Git 连接](/zh-cn/reference/connectors/git/)。这类连接保留完整表单，包含**服务器 URL**、用户/令牌或 SSO 身份验证，以及 **SSL** 和 **SSH** 选项卡。

## 创建 PlaidCloud Git 连接

1. 打开 **Tools > Connections**
2. 点击 `New Connection`，然后从菜单中选择 **PlaidCloud Git**
3. 填写简化后的表单：
   - **账户名称**：连接的显示名称
   - **备注**：说明连接用途的可选备注
   - **存储库**：点击 `Refresh` 列出工作区可访问的存储库，然后选择一个（例如 `udfs` 或 `apps` 存储库）。从列表中选择，无需手动输入路径。
   - **默认分支**：从所选存储库的分支列表中，选择默认读取的分支
   - **起始路径**：可选；浏览存储库并选择一个文件夹，将所有文件查找限定在该子文件夹内；不设置则使用整个存储库
4. 设置**用法**：`Active` 表示启用连接，`Read Only` 表示连接永远不会写入
5. 设置**安全模型**：工作区中哪些成员可以使用该连接
6. 点击 `Create` 保存

整个表单就是这些内容。与外部 Git 提供商不同，这里没有服务器 URL、身份验证选项卡，也没有 SSL 或 SSH 配置，这些都已自动处理。

<Aside type="note">存储库、默认分支和起始路径均从实时列表中选择（先选存储库，再选其分支，然后浏览到文件夹），因此不会出现输入错误。每个列表都使用连接自身的访问权限读取，所以 PlaidCloud Git 连接的列表会立即填充，无需输入凭据。</Aside>

## 安全模型

`Security Model` 控制工作区中哪些成员可以使用该连接：

| 选项 | 可使用连接的对象 |
|---|---|
| 私有（仅所有者） | 仅所有者。 |
| 仅限指定成员 | 所有者以及明确列出的成员。 |
| 仅限指定安全组 | 所有者以及指定安全组的成员。 |
| 所有工作区成员 | 工作区中的所有人。 |

对于 `Specific Members Only` 或 `Specific Security Groups Only`，请在保存后通过列表的 `Actions` 菜单授予访问权限。有关共享的连接机制，请参阅[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

## 谁可以查看存储库

PlaidCloud 为您创建的每个存储库，工作区中每位已登录的成员都可以读取。这包括 Panel 应用和 Dash 应用背后的存储库，以及内置的 `apps` 和 `udfs` 存储库。未登录的人员无法读取这些存储库。

因此，成员无需为每个存储库单独设置，即可打开并重新发布应用，也可为 PlaidCloud Git 连接选择存储库。

### 高级：私有存储库

Git 管理员可以在 Git 界面中将存储库设为私有。私有存储库不再对每位成员可见，因此：

- 它不会出现在 PlaidCloud Git 连接的**存储库**列表中。
- 无法从中读取基于 Git 的 UDF 代码，因此存储在私有存储库中的基于 Git 的 UDF 无法运行。
- 成员无法从中发布应用。

若要将私有存储库用作源，请改为创建带有自己访问令牌的[外部 Git 连接](/zh-cn/reference/connectors/git/)。

## 基于托管 Git 自动构建 Panel 应用和 Dash 应用

[服务器 Panel 应用](/zh-cn/guides/panel-apps/creating/)或 [Dash 应用](/zh-cn/guides/dash-apps/)基于 Git 分支构建，并在每次向该分支推送代码时自动重新构建。将其指向 PlaidCloud Git 连接，可使整个流程保留在工作区内，无需外部主机，也无需维护个人访问令牌。

1. 将应用推送到工作区 PlaidCloud Git 服务器上的存储库，其中包含一个入口点 `.py` 文件（Panel 的调用 `.servable()`；Dash 的公开 `server = app.server`），以及位于存储库根目录或入口点旁边的可选 `requirements.txt`。有关存储库布局，请参阅[创建 Panel 应用](/zh-cn/guides/panel-apps/creating/#准备应用仓库)或[从 PlaidCloud Git 部署 Dash 应用](/zh-cn/guides/dash-apps/deploy-from-git/)。
2. 按照上述步骤创建 PlaidCloud Git 连接，其**存储库**为该存储库。
3. 在**应用**中，选择**新建应用** > **基于服务器**或 **Dash 应用**，然后在**Git 连接和发布监视器**下：
   - **Git 连接**：选择刚创建的 PlaidCloud Git 连接
   - **分支**：要构建的分支；向其推送代码会重新构建并重新部署应用
   - **入口点**：应用要提供服务的 `.py` 文件
4. 完成发布对话框，然后点击**发布**。

此后，每次向托管 Git 服务器上的该分支推送代码，都会重新构建应用，实现完全不离开 PlaidCloud 的端到端自动构建。
