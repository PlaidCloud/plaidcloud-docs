**PlaidCloud Git 连接**会让工作流（或服务器 Panel 应用的构建）指向工作区自带的托管 Git 服务器上的存储库。由于该 Git 服务器托管在 `git.<your-workspace>.plaid.cloud`，并且您已通过常规的 PlaidCloud 登录完成登录，因此连接表单比外部 Git 提供商的简单得多：无需输入服务器 URL，也无需管理用户名、令牌或 SSH 密钥。

<Aside type="note">PlaidCloud Git 连接无需输入服务器 URL 或凭据。工作区的 Git 服务器及您对它的访问权限会根据您的 PlaidCloud 登录（包括 SSO）自动处理——因此无需生成、存储或轮换令牌。</Aside>

## 何时使用

只要您要读取的存储库位于 [PlaidCloud Git](/zh-cn/guides/git/)（即工作区的内置 Git 服务）中，而不是外部主机上，就应使用 PlaidCloud Git 连接。最常见的用途是从托管存储库自动构建**服务器 Panel 应用**或 **Dash 应用**，这样推送到某个分支就会重新构建并重新部署应用，整个过程无需外部 GitHub 账户或个人访问令牌。

对于托管在外部服务（GitHub、GitLab、Bitbucket、Forgejo 或 Gitea）上的存储库，请改用[外部 Git 连接](/zh-cn/reference/connectors/git/)。这些连接保留完整的表单，包含**服务器 URL**、用户/令牌或 SSO 身份验证，以及 **SSL** 和 **SSH** 选项卡。

## 创建 PlaidCloud Git 连接

1. 打开 **Tools > Connections**
2. 点击 `New Connection` 并从菜单中选择 **PlaidCloud Git**
3. 填写简化后的表单：
   - **账户名称** — 连接的显示名称
   - **备注** — 说明该连接用途的可选备注
   - **存储库** — 点击 `Refresh` 列出工作区可访问的存储库，然后选择一个（例如您的 `udfs` 或 `apps` 存储库）。从列表中选择，而不是键入路径。
   - **默认分支** — 从所选存储库的分支列表中，选择默认读取的分支
   - **起始路径** — 可选择浏览存储库并选择一个文件夹，以便将每次文件查找限定在某个子文件夹内；不设置则使用整个存储库
4. 设置**用法** — `Active` 表示启用该连接，`Read Only` 表示该连接永不写入
5. 设置**安全模型** — 工作区中谁可以使用该连接
6. 点击 `Create` 保存

整个表单就是这些。与外部 Git 提供商不同，这里没有服务器 URL，没有身份验证选项卡，也没有 SSL 或 SSH 配置——这些都已为您处理好。

<Aside type="note">存储库、默认分支和起始路径都是从实时列表中选择的——先选择存储库，再选择其分支，然后浏览到某个文件夹——因此不会输错。每个列表都使用连接自身的访问权限读取，所以对于 PlaidCloud Git 连接，无需输入任何凭据即可立即填充。</Aside>

## 安全模型

`Security Model` 控制工作区中谁可以使用该连接：

| 选项 | 谁可以使用该连接 |
|---|---|
| Private (Only Owners) | 仅所有者。 |
| 仅限指定成员 | 所有者加上一份明确的成员列表。 |
| 仅限指定安全组 | 所有者加上指定安全组的成员。 |
| 所有工作区成员 | 工作区中的所有人。 |

对于 `Specific Members Only` 或 `Specific Security Groups Only`，请在保存后通过列表的 `Actions` 菜单授予访问权限。有关共享的连接机制，请参阅[创建和管理连接](/zh-cn/guides/connections/create-connection/#安全模型)。

## 从托管 Git 自动构建 Panel 应用和 Dash 应用

[服务器 Panel 应用](/zh-cn/guides/panel-apps/creating/)或 [Dash 应用](/zh-cn/guides/dash-apps/)从 Git 分支构建，并在每次推送到该分支时自动重新构建。将其指向 PlaidCloud Git 连接，可使整个循环保持在工作区内——无需外部主机，也无需维护个人访问令牌。

1. 将您的应用推送到工作区的 PlaidCloud Git 服务器上的存储库——一个入口点 `.py` 文件（Panel 的调用 `.servable()`；Dash 的暴露 `server = app.server`），以及位于存储库根目录或入口点旁边的可选 `requirements.txt`。有关存储库布局，请参阅[创建 Panel 应用](/zh-cn/guides/panel-apps/creating/#准备应用仓库)或[从 PlaidCloud Git 部署 Dash 应用](/zh-cn/guides/dash-apps/deploy-from-git/)。
2. 按上述步骤创建一个 PlaidCloud Git 连接，其**存储库**即为该存储库。
3. 在**我的 Panel 应用**中，点击**新建服务器应用**或**新建 Dash 应用**，然后在 **Git 连接和发布监视器**下：
   - **Git 连接** — 选择您刚创建的 PlaidCloud Git 连接
   - **分支** — 要从中构建的分支；推送到该分支会重新构建并重新部署应用
   - **入口点** — 应用要提供服务的 `.py` 文件
4. 完成发布对话框并点击**发布**。

此后，每次推送到托管 Git 服务器上的该分支都会重新构建应用——这是一条始终不离开 PlaidCloud 的端到端自动化构建。
