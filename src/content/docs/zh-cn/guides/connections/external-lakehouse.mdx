项目的表通常存放在内置的 PlaidCloud Lakehouse 中。工作区管理员也可以在 PlaidCloud 内部自行连接**您自己的 Snowflake 或 Databricks 数据仓库**，无需 PlaidCloud 工作人员协助。之后，工作流会直接在您的数据仓库中读取和写入项目表。数据保留在您的账户中，受您的治理和计费管理，而 PlaidCloud 负责在其上驱动转换、工作流和仪表板。

## 连接您的数据仓库

只有工作区管理员可以连接、更改或移除数据仓库。

1. 打开用户菜单，选择**管理数据仓库**，然后选择**添加 Warehouse**。也可以在主页清单的**使用您的数据仓库**行上选择**连接**，或在 Snowflake 或 Databricks 连接对话框中选择**改用它作为您的数据仓库**。
2. 选择 **Snowflake** 或 **Databricks**。
3. 通过两种方式之一进行连接：**Sign in with Snowflake** 或 **Sign in with Databricks**（最快捷，详见[使用 Snowflake 或 Databricks 登录](#使用-snowflake-或-databricks-登录)），或者运行设置脚本并粘贴其生成的凭据（见下文）。

### 1. 先运行设置脚本

<Aside type="caution">请在连接之前运行设置脚本。在此之前，连接检查会失败。</Aside>

对话框会根据您选择的名称生成设置脚本，并在您输入时随之更新。使用**复制脚本**将其复制，然后在您自己的账户中运行。该脚本不会更改您现有的数据仓库。

| | Snowflake | Databricks |
|---|---|---|
| 运行身份 | `ACCOUNTADMIN` | 工作区和元存储管理员 |
| 创建内容 | 一个空闲 60 秒后挂起的数据仓库，带有每月额度上限，达到 90% 时发送通知，达到 100% 时挂起；一个数据库；一个角色；一个服务用户 | 一个服务主体；一个空闲时停止的 SQL 仓库；目录（若尚不存在） |
| 可更改的名称 | Warehouse、大小、每月额度上限、数据库、角色、服务用户 | 服务主体名称、SQL 仓库名称、大小、空闲多少分钟后停止、目录 |
| 默认值 | `PLAIDCLOUD_WH`（`XSMALL`，每月 100 个额度）、`PLAIDCLOUD`、`PLAIDCLOUD_ROLE`、`PLAIDCLOUD_SVC` | `plaidcloud`、`PlaidCloud`（`2X-Small`，空闲 10 分钟）、目录 `plaidcloud` |
| 身份验证 | 密钥对（脚本会说明如何生成） | 服务主体的 OAuth 密文 |

脚本还会设置以下内容。

- **网络访问。** 脚本会列出 PlaidCloud 发起连接所用的地址：控制平面的 `130.211.116.97/32`，以及您的工作区自己的地址（当它与控制平面不同时）。Snowflake 脚本会创建一个网络策略，仅允许该服务用户使用这些地址。在 Databricks 上，如果您的工作区已强制执行 IP 访问列表，脚本会包含允许这些地址的语句；请将这些地址添加到保护您账户的任何网络策略或 IP 访问列表中。
- **策略会延续。** 在 Snowflake 上，该角色会被授予应用行访问、掩码、投影、聚合和联接策略及标签的权限，因此 PlaidCloud 重写表时您的策略依然有效。在 Databricks 上，请为服务主体授予您所用的任何行筛选器或列掩码函数的 `EXECUTE` 权限。
- **运行成本。** Snowflake 的角色会获得 `SNOWFLAKE.GOVERNANCE_VIEWER` 数据库角色，使 PlaidCloud 能读取每次运行所归属的额度，同时也涵盖[上次读取](/zh-cn/guides/projects/managing-tables-and-views/#最后读取)。Databricks 获得对 `system` 目录中查询历史记录和仓库大小的读取权限。
- **上次读取。** 在 Databricks 上，脚本还会授予 `system.access` 的 `USE SCHEMA` 权限以及 `system.access.table_lineage` 的 `SELECT` 权限，这是表的“上次读取”信息所需要的。请参阅[每次运行的仓库成本](#每次运行的仓库成本)。

### 2. 连接

| 字段 | 引擎 | 填写内容 |
|---|---|---|
| 名称 | 两者 | PlaidCloud 对该数据仓库的称呼。它会跟随地址变化，例如 `Snowflake — myorg-myaccount`，直到您输入自己的名称。 |
| 账户 URL | Snowflake | 您的账户主机，例如 `myorg-myaccount.snowflakecomputing.com`。 |
| 私钥 | Snowflake | 服务用户的私钥（PEM）。密钥对永不过期。 |
| 工作区 URL | Databricks | 您的工作区主机，例如 `adb-1234567890123456.7.azuredatabricks.net`。 |
| SQL 仓库 HTTP 路径 | Databricks | 例如 `/sql/1.0/warehouses/abc123def456`。 |
| 应用程序 ID | Databricks | 服务主体的应用程序（客户端）ID。 |
| OAuth 密文 | Databricks | 服务主体的 OAuth 密文。PlaidCloud 会为您续期。 |

在**高级**下，可以改用 Snowflake 程序化访问令牌或 Databricks 个人访问令牌。令牌会过期：到期当天，PlaidCloud 将无法访问您的数据仓库，直到您添加新令牌。到期前十四天以及到期后，横幅会告知日期并提供**轮换**，它会在该数据仓库上打开[管理数据仓库](#管理数据仓库)并要求输入新令牌。使用密钥对或 OAuth 密文可避免过期。

地址必须是账户的公共 URL，以 `.snowflakecomputing.com`、`.cloud.databricks.com`、`.azuredatabricks.net` 或 `.gcp.databricks.com` 结尾。此处不支持专用和自定义端点；若要以专用方式访问您的数据仓库，请在挂接后[请求直接连接](#直接连接)。

### 3. 检查，然后使用

- **测试连接**会测试地址、登录以及 PlaidCloud 所需的每项权限，且不会存储任何内容。
- **用作我的数据仓库**会运行同样的检查并挂接数据仓库。从**添加 Warehouse**以外的位置打开时，它还会将该数据仓库设为默认，并在工作区切换期间等待。这通常需要几分钟，您可以关闭窗口。之后工作区中的新项目将使用您的数据仓库，窗口还会提供**运行示例**（请参阅[运行示例](#运行示例)）。从**添加 Warehouse**打开时，默认设置保持不变；若希望新项目使用它，请在[管理数据仓库](#管理数据仓库)中选择**设为默认**。

检查失败时，会用通俗的语言说明问题和解决方法。缺少的必要权限会以可直接运行的 `GRANT` 语句列出，每条语句都带有**复制**按钮和一个运行后可勾选的**完成**框，另有**全部复制**按钮和**显示设置脚本**。**复制以供支持人员查看**会复制数据仓库自身的错误文本，供 PlaidCloud 支持人员查看。

检查还会在**推荐 — 启用“上次读取”**下单独列出若干授权，每项都带有**复制**。它们让表的[上次读取](/zh-cn/guides/projects/managing-tables-and-views/#最后读取)信息能够读取您数据仓库的历史记录。它们不会阻止您使用数据仓库：没有它们也能正常连接，只是“上次读取”会显示**读取历史记录不完整**。

- **Snowflake：** `GRANT DATABASE ROLE SNOWFLAKE.GOVERNANCE_VIEWER TO ROLE <role>;`（对 `SNOWFLAKE` 数据库授予 `IMPORTED PRIVILEGES` 同样可行）。“上次读取”需要 Access History，而 Snowflake Standard 版不具备此功能。
- **Databricks：** 为服务主体授予 `system` 的 `USE CATALOG`、`system.access` 的 `USE SCHEMA`，以及 `system.access.table_lineage` 的 `SELECT`。

| 您看到的情况 | 解决方法 |
|---|---|
| 服务用户无法使用某个对象 | 为其角色授予对该对象的权限。设置脚本包含所有授权。 |
| 您的数据仓库已挂起或不存在 | 检查数据仓库名称，并确认其可以自行启动（Snowflake 上为 `AUTO_RESUME`，Databricks 上为运行中的 SQL 仓库）。 |
| 您的数据仓库已用完额度配额 | 提高资源监视器的配额或预算，或等待其重置。 |
| 网络策略正在阻止 PlaidCloud | 像设置脚本那样，在策略中允许设置脚本所列的地址。 |
| 令牌或密钥已过期或不再有效 | 创建新令牌，或改用密钥对。 |
| Unity Catalog 拒绝了服务主体的访问 | 为目录授予 `USE CATALOG`、`CREATE SCHEMA` 和 `USE SCHEMA`。 |
| PlaidCloud 无法登录 | 检查用户或服务主体及其密钥、令牌或密文。 |
| PlaidCloud 无法连接到您的数据仓库 | 检查 URL，并在任何网络策略或 IP 访问列表中允许 PlaidCloud 的地址。 |
| 不支持专用或自定义端点 | 使用账户的公共 URL。 |

## 使用 Snowflake 或 Databricks 登录

管理员无需粘贴密钥、密文或令牌，也可以通过登录来挂接数据仓库。之后每个人都使用自己的 Snowflake 或 Databricks 身份登录，因此仪表板和查询会以其本人在您数据仓库中的权限运行。

### 管理员需要先完成的设置

在您自己的账户中，账户管理员需要一次性将 PlaidCloud 注册为登录应用程序。连接对话框（**使用您自己的数据仓库**，或从**管理数据仓库**打开时的**添加数据仓库**）会显示要使用的确切文本，包括 PlaidCloud 的重定向 URL。

- **Snowflake。** 运行对话框中显示的 `CREATE SECURITY INTEGRATION` 语句，然后从 `SELECT SYSTEM$SHOW_OAUTH_CLIENT_SECRETS` 语句的结果中复制 `OAUTH_CLIENT_ID`。
- **Databricks。** 在账户控制台的 **Settings > App connections** 下，添加一个名为 `PlaidCloud` 的应用。为其提供对话框中显示的重定向 URL 并授予对所有 API 的访问权限，保持 **Generate a client secret** 关闭，然后复制其客户端 ID。

### 挂接数据仓库

1. 在 **Quickest: sign in with Snowflake**（或 Databricks）中，输入**账户 URL**（或**工作区 URL**）和**客户端 ID**。
2. 在 Snowflake 上，输入**数据库**和 **PlaidCloud 的数据角色**。**Warehouse** 为可选项，默认使用您自己的。在 Databricks 上，输入 **SQL 仓库 HTTP 路径**。**目录**为可选项，默认使用您自己的。
3. 选择 **Sign in with Snowflake** 或 **Sign in with Databricks**，登录您的供应商账户并批准。

返回 PlaidCloud 后，会再次检查数据仓库。检查通过时，**您的数据仓库**会打开，并选中新的数据仓库。发现缺失项时，窗口保持打开，并列出需要修复的内容以及要复制的缺失授权。

PlaidCloud 会在您的账户中创建专用于此数据仓库的服务身份。工作流、计划以及其他没有具体人员参与的操作都以该身份运行。

- **Snowflake。** PlaidCloud 会创建一个新的服务用户，带有密钥对，且仅持有您指定的数据角色。该角色必须是普通数据角色。PlaidCloud 会拒绝以下角色：与您登录所用角色相同的角色，是或继承了 `ACCOUNTADMIN`、`SECURITYADMIN`、`USERADMIN`、`SYSADMIN` 或 `ORGADMIN` 的角色，持有 `CREATE USER`、`CREATE ROLE`、`MANAGE GRANTS`、`CREATE INTEGRATION` 或 `CREATE NETWORK POLICY` 的角色，或拥有某个用户的角色。该角色可以持有设置脚本中的 `APPLY ROW ACCESS POLICY`、`APPLY MASKING POLICY`、`APPLY PROJECTION POLICY`、`APPLY AGGREGATION POLICY`、`APPLY JOIN POLICY` 和 `APPLY TAG` 授权，重建的表需要这些授权来保留其策略。PlaidCloud 也拒绝重用已有的 Snowflake 用户。您登录所用的角色必须能够创建用户并授予该数据角色。
- **Databricks。** PlaidCloud 会创建一个新的服务主体，仅拥有对 SQL 仓库的访问权限以及目录的数据权限。请以工作区管理员身份登录，以便 PlaidCloud 创建它。

如果您缺少服务身份所需的某项权限，数据仓库仍会为已登录的用户挂接，并显示指明该权限的警告，而工作流运行会因同样的原因被拒绝，直到管理员重新登录。

### 每个人都要登录

一旦工作区拥有通过登录接入的数据仓库，每位成员都会在用户菜单中看到**登录您的仓库**。选择它，然后选择 **Sign in with Snowflake** 或 **Sign in with Databricks**。PlaidCloud 会保持您的登录状态。未登录时或登录已过期后打开仪表板，会显示*Sign in with Snowflake to view this dashboard: in PlaidCloud, open your user menu and choose Sign in to your warehouse.*（或 *Databricks*）。请从该菜单项重新登录。

此类数据仓库上的仪表板以查看者本人在其中的权限运行。尚未登录的查看者会看到提示：*Sign in with Snowflake to view this dashboard: in PlaidCloud, open your user menu and choose Sign in to your warehouse.*

## Databricks 要求

- **位于公共 URL 的工作区。** 请参阅[连接](#2-连接)中的地址规则。
- **Unity Catalog**，并带有 PlaidCloud 可在其中创建架构的目录。没有托管存储的目录会拒绝 `CREATE SCHEMA`，任何授权都无法解决。旧版 `hive_metastore` 目录没有卷，因此向其中的项目导入文件会失败，向其中的 Databricks 连接推送则会逐行运行。
- **SQL 仓库。** 我们建议使用**无服务器** SQL 仓库。已停止的经典 SQL 仓库需要几分钟才能启动，停止后的首次连接检查或查询会等待它启动，而无服务器仓库会快得多就绪。
- **工作区和元存储管理员**，用于运行设置脚本；或账户管理员，用于添加应用连接，并由工作区管理员登录。

PlaidCloud 向 Databricks 表明身份时，对您的数据仓库及其仪表板使用 User-Agent `PlaidCloud_Lakehouse`，对工作流所用的 Databricks 连接使用 `PlaidCloud_Connector`。其中绝不包含租户、组织或用户名称。

## Databricks 登录方式

PlaidCloud 通过以下三种方式之一访问 Databricks，在添加数据仓库时选择。

| 方式 | 适用情形 | 续期 |
|---|---|---|
| 使用 Databricks 登录（OAuth U2M） | 希望每个人的仪表板和查询以其本人的 Databricks 权限运行 | PlaidCloud 会保持登录状态 |
| 服务主体的 OAuth 密文（OAuth M2M） | 工作流和仪表板应以同一个服务主体运行 | PlaidCloud 会在旧访问令牌过期前签发新令牌 |
| 个人访问令牌 | 无法使用上述两种 OAuth 方式 | 令牌在到期日过期，需要您添加新令牌 |

### 使用 Databricks 登录

PlaidCloud 使用 OAuth 授权码流程和 PKCE 登录。

1. 以账户管理员身份打开 **Account console > Settings > App connections**，添加一个名为 `PlaidCloud` 的应用。为其提供连接对话框中显示的重定向 URL 并授予对所有 API 的访问权限，保持 **Generate a client secret** 关闭。必须授予对所有 API 的访问权限：PlaidCloud 会使用管理员的登录来创建其服务主体，而之后登录的人只会获得 `sql` 范围。
2. 复制该应用的客户端 ID。
3. 在 PlaidCloud 中打开用户菜单，选择**管理数据仓库**，然后选择**添加 Warehouse**，再选择 **Databricks**。
4. 在 **最快方式：使用 Databricks 登录** 下，输入**工作区 URL**、**客户端 ID** 和 **SQL 仓库 HTTP 路径**。**目录**为可选项。
5. 选择**使用 Databricks 登录**，以 Databricks 工作区管理员身份登录并批准。PlaidCloud 会为工作流创建其自己的服务主体。请参阅[挂接数据仓库](#挂接数据仓库)。

### 服务主体的 OAuth 密文

1. 在 PlaidCloud 中打开**管理数据仓库**，选择**添加 Warehouse**，然后选择 **Databricks**。
2. 以工作区和元存储管理员身份运行对话框中的设置脚本（请参阅[先运行设置脚本](#1-先运行设置脚本)）。它会创建服务主体、SQL 仓库和目录。也可以自行创建服务主体，在 Databricks 中为其生成 OAuth 密文，并授予其 [Databricks 最低权限](#databricks-最低权限)中列出的权限。
3. 在 **2. 连接**下，输入**工作区 URL**、**SQL 仓库 HTTP 路径**、**应用程序 ID**（服务主体的应用程序 ID）和 **OAuth 密文**。
4. 选择**测试连接**，然后选择**用作我的数据仓库**。

PlaidCloud 在签发令牌时会请求 `all-apis` 范围。

### 个人访问令牌

1. 在 Databricks 中，为拥有 [Databricks 最低权限](#databricks-最低权限)中所列权限的用户或服务主体创建个人访问令牌。
2. 在 PlaidCloud 中打开**管理数据仓库**，选择**添加 Warehouse**，然后选择 **Databricks**。
3. 在 **2. 连接**下，输入**工作区 URL** 和 **SQL 仓库 HTTP 路径**。
4. 选择**高级：改用个人访问令牌**，并将令牌粘贴到**令牌**中。无需**应用程序 ID** 和 **OAuth 密文**。
5. 选择**测试连接**，然后选择**用作我的数据仓库**。

令牌在到期日过期，之后 PlaidCloud 将无法访问您的数据仓库，直到您添加新令牌。有关续期横幅，请参阅[连接](#2-连接)。

## Databricks 最低权限

将这些权限授予服务主体，使用个人访问令牌时则授予该用户。**测试连接**会检查挂接数据仓库所需的权限，并将缺少的权限列为可直接运行的 `GRANT` 语句。卷授权缺失只会在导入或推送运行时才显现。

| 用途 | 授予 |
|---|---|
| 挂接数据仓库 | 目录上的 `USE CATALOG`、`CREATE SCHEMA` 和 `USE SCHEMA`，以及 SQL 仓库上的 `CAN_USE` |
| 查询和写入表 | 项目架构上的 `USE SCHEMA`、`SELECT`、`MODIFY` 和 `CREATE TABLE`，以及 SQL 仓库上的 `CAN_USE` |
| 导入文件和文档（项目架构中的 `plaid_import` 卷） | 架构上的 `CREATE VOLUME`，或管理员创建的 `plaid_import` 卷上的 `READ VOLUME` 和 `WRITE VOLUME` |
| 将表从工作流推送到 Databricks 连接（目标架构中的 `plaid_export` 卷） | 目标上的 `USE CATALOG` 和 `USE SCHEMA`，目标表上的 `MODIFY`（步骤创建该表时还需架构上的 `CREATE TABLE`），以及架构上的 `CREATE VOLUME`，或管理员创建的 `plaid_export` 卷上的 `READ VOLUME` 和 `WRITE VOLUME` |

推送会将每个批次作为 Parquet 文件暂存到卷中，并在开启 ANSI 模式的情况下用 `COPY INTO` 加载，因此无法放入其列的值会使步骤失败，而不是变成 `NULL`。没有卷授权时，推送会退回到逐行 `INSERT` 语句，速度要慢得多，步骤会发出警告并指明需要添加的授权。在 `hive_metastore` 目录上，推送始终逐行运行，且不会发出警告。

## Databricks 须知事项

- **导入文件和文档需要服务主体。** 在通过登录挂接且没有服务主体的数据仓库（仅 SQL 挂接）上，导入会停止，并提示需要工作区管理员再次使用 Databricks 登录以添加服务主体。
- **仪表板会在升级后重新注册一次。** 每个 Databricks 仪表板连接会使用 PlaidCloud 的 User-Agent 重新注册一次。您无需执行任何操作。
- **移除数据仓库无法在 Databricks 撤销登录。** Databricks 没有文档说明如何撤销 PlaidCloud 为某人持有的登录令牌。PlaidCloud 会删除其副本，并在各自为唯一时删除服务主体的密文和个人访问令牌，但登录令牌本身在 Databricks 仍然有效。PlaidCloud 不会删除其创建的服务主体，请在 Databricks 中删除。要终止登录，请在 **Account console > Settings > App connections** 下移除 `PlaidCloud` 应用连接。

## 管理数据仓库

工作区管理员打开用户菜单并选择**管理数据仓库**。**您的数据仓库**窗口会列出每个数据仓库的**名称**、**引擎**、**状态**、**默认**和**项目**。当工作区没有 Snowflake 或 Databricks 数据仓库时，列表上方的卡片会显示**您正在使用 PlaidCloud 的 Warehouse — 可改用您自己的**。

工具栏中的**添加 Warehouse**会打开与连接相同的流程，标题为**添加数据仓库**。您的数据仓库会被添加，新项目的默认值不变。

其他操作请选择一个数据仓库，然后从其行首的 ⋯、右键菜单或**操作**中选择。每个选项仅在适用时出现。

| 操作 | 作用 |
|---|---|
| **详细信息** | 打开[数据仓库详细信息](#数据仓库详细信息)。 |
| **设为默认** | 工作区切换到此数据仓库后（通常需要几分钟），新项目将使用它。已创建的项目仍保留在其创建时所用的数据仓库上。只有**活动**的数据仓库才能成为默认。 |
| **重命名…** | 更改数据仓库的名称。 |
| **续订登录…** | 对于通过登录挂接的数据仓库：重新登录 Snowflake 或 Databricks。 |
| **轮换凭据…** | 对于密钥对、令牌或 OAuth 密文：粘贴新的凭据。PlaidCloud 会先对照您的数据仓库检查它，检查通过后才会替换当前凭据。 |
| **停用…** | 暂停数据仓库。确认提示会说明有多少项目使用它；这些项目会暂停直到重新启用，并保留其数据。默认数据仓库无法停用。 |
| **启用** | 重新启用已停用的数据仓库。 |
| **移除** | 断开数据仓库。仅当该数据仓库不是默认且没有项目使用它时才有效，否则会告知原因。 |

**状态**说明每个数据仓库的当前情况。

| 状态 | 含义 |
|---|---|
| **预配中** | PlaidCloud 仍在设置该数据仓库。 |
| **正在切换…** | 更改已保存，正在发送到您的工作区。 |
| **活动** | 可以使用。 |
| **已禁用** | 使用它的项目会暂停，直到重新启用。 |
| **注意** | 上次检查失败，或其个人访问令牌将在 14 天内过期。[数据仓库详细信息](#数据仓库详细信息)会说明原因。 |

<Aside type="note">更改（例如新增数据仓库、新的默认值、新名称或停用某个数据仓库）需要几分钟才能到达您的工作区。每个工作区相互隔离运行，并自行获取配置更改，因此在更改到达之前，该数据仓库会显示**正在切换…**，新数据仓库也暂时无法被项目使用。列表会每隔几秒重新检查一次，最长 10 分钟，之后显示**仍在生效中 — 请稍后刷新。** 如果一小时后更改仍未到达，请联系 PlaidCloud 支持人员。</Aside>

移除数据仓库时，PlaidCloud 会撤销其在您账户中的凭据并删除其副本。在 Snowflake 上，这包括所有登录和服务身份。在 Databricks 上，这包括服务主体的密文，但不包括人员的登录（请参阅 [Databricks 须知事项](#databricks-须知事项)）。您的数据仍保留在您的数据仓库中。如果无法撤销凭据，PlaidCloud 会告知您自行在账户中撤销。

### 运行示例

当**您的数据仓库**在某个特定数据仓库上打开（例如通过登录挂接之后），且该数据仓库是默认并处于**活动**状态时，它会显示**您的 Warehouse 已就绪。运行示例即可查看其运行效果。** **运行示例**会先询问**是否移除示例数据？**：它会永久删除在旧数据仓库上运行过的预置示例项目，而不影响您自己的项目和数据。随后它会加载全新的示例并在您的数据仓库上运行；请在工作流中查看进度。如果示例项目含有您自己的更改，则不会被替换，也不会运行任何内容。

## 直接连接

[数据仓库详细信息](#数据仓库详细信息)中的**连接**行说明您的工作区如何访问数据仓库。PlaidCloud 根据数据仓库的地址判断其运行位置：Snowflake 账户定位符地址（例如 `xy12345.us-east-2.aws.snowflakecomputing.com`）会指明其云和区域，Databricks 地址只指明其云，而 Snowflake 组织账户地址两者都不指明。

| 连接 | 含义 |
|---|---|
| **相同的云和区域** | 数据仓库与您的工作区运行在同一云和区域。 |
| **公共互联网** | 数据仓库运行在另一个云或区域。查询会经过公共互联网，因此会产生响应时间和出口费用。 |
| **专用 — 直接链接** | 您的工作区通过专用链接（例如 AWS PrivateLink、Azure Private Link 或 Google Private Service Connect）访问数据仓库，其查询不会经过公共互联网。 |
| **未检测到** | PlaidCloud 无法判断数据仓库运行在何处。 |

直接连接会用专用路径取代您的工作区与数据仓库之间的公共路径。它适用于与您的工作区位于同一云和区域的数据仓库。

### 请求直接连接

当您的工作区套餐包含专用连接、该数据仓库是已启用的 Snowflake 或 Databricks 数据仓库，且没有未完成的请求时，**Warehouse 详细信息**中会出现**请求直接连接**。只有工作区管理员可以发起请求。选择它之后，**连接**行会随请求更新。

| 连接 | 含义 |
|---|---|
| **已请求** | PlaidCloud 已收到请求，将开始设置。 |
| **正在设置** | PlaidCloud 正在设置专用连接。 |
| **正在等待您的 Warehouse 管理员** | 连接需要您在数据仓库账户中完成几个步骤才能结束。 |
| **专用 — 直接链接** | 连接已通过检查并在使用。 |
| **需要关注** | 专用连接无法正常工作。请检查步骤，或联系 PlaidCloud。 |

在直接连接通过检查之前，您的工作区会继续沿用之前访问数据仓库的方式。PlaidCloud 检查期间，该行显示**正在检查连接…**。如果 PlaidCloud 将数据仓库恢复为公共路径，该行会再次显示数据仓库的访问方式，并再次提供**请求直接连接**。

### 在您的数据仓库账户中执行的步骤

在设置连接期间或需要关注时，**连接**行旁边的**查看步骤**会打开面向您的数据仓库管理员的步骤，带编号，附有要运行的确切文本，有文本的步骤带**复制**。等待 PlaidCloud 的步骤会一直注明这一点，直到 PlaidCloud 填写完毕。运行完成后，请告知您的 PlaidCloud 联系人。

| 引擎 | 步骤的要求 |
|---|---|
| Snowflake | Business Critical 版或更高版本。以 `ACCOUNTADMIN` 身份运行的一条语句，用于授权 PlaidCloud 的专用端点。对设置脚本创建的网络策略做出更改，须在 PlaidCloud 切换之前完成：为专用端点添加网络规则，并将 PlaidCloud 的公共地址移到单独的规则中，因为带有网络规则的策略不再读取其 IP 列表。这些语句可以安全地重复运行。 |
| Databricks | 专用连接所需层级的工作区（AWS 上为 Enterprise，Google Cloud 上为 Premium，Azure 上为 Premium 且采用 VNet 注入）。在账户控制台中为工作区注册 PlaidCloud 的端点，或在 Azure 上，在工作区的 Networking 选项卡中批准 PlaidCloud 待处理的专用端点连接。在专用访问设置中允许 PlaidCloud 通过专用方式访问，同时为 PlaidCloud 的地址保持公共访问开启。 |

<Aside type="note">PlaidCloud 的控制平面仍会通过公共地址访问您的数据仓库，以完成登录、设置和断开连接。请像这些步骤一样，为设置脚本中的地址保持公共访问开启。</Aside>

## 每次运行的仓库成本

在您自己的数据仓库上，已转换的 Alteryx 工作流的运行历史记录会显示**仓库成本**列，而[验证您的迁移](/zh-cn/guides/workflows/validate-converted-alteryx-workflows/#验证您的迁移)窗口会显示上次运行的成本以及对下次运行的估算。成本在 Snowflake 上以额度计，在 Databricks 上以 DBU 计。

| 标签 | 含义 |
|---|---|
| *attributed* | Snowflake 已将这些额度计入该运行的查询，通过 `GOVERNANCE_VIEWER` 授权读取。归属数据会在 Snowflake 的报告延迟之后出现。 |
| *estimated* | 根据查询运行时间和数据仓库大小计算得出，前面带有 ≈。在 Databricks 上始终如此；在 Snowflake 上，则出现于归属数据到达之前或没有该授权时。 |

成本涵盖由 PlaidCloud 引擎运行的步骤。部分计价的运行会标记为 *partial*，而成本尚未报告的运行也会如实说明。

## 您的策略和说明会延续

在 PlaidCloud 中设置的架构、表和列说明会作为注释写入您数据仓库自己的目录。Snowflake 上的行访问、掩码、投影、聚合和联接策略，以及 Databricks 上的行筛选器和列掩码，在 PlaidCloud 替换、重新创建或克隆表时依然保持附加。如果某个策略无法延续，PlaidCloud 会保持表原样，并在消息中指明该策略及原因。

## 将项目绑定到您的数据仓库

工作区连接数据仓库后，**新建项目**对话框（**Analyze > 项目 > 新建项目**）会提供 Lakehouse 选择器：选择**租户默认值**，或选择特定的数据仓库。**租户默认值**是内置的 PlaidCloud Lakehouse，除非某个数据仓库被设为默认，此时新项目会自动落在该数据仓库上。在[管理数据仓库](#管理数据仓库)中选择**设为默认**，或在并非从**添加 Warehouse** 打开的对话框中选择**用作我的数据仓库**，即可设置默认值。这只影响之后创建的项目；现有项目保留其创建时所用的后端。此后：

- 项目的工作流所创建、加载或转换的每个表，都在您的 Lakehouse 中创建和写入。
- 读取（在步骤、视图和仪表板中）均作为针对您数据仓库的查询运行。
- 不会向 PlaidCloud Lakehouse 复制任何内容；数据保留在您的账户中。

构建工作流的方式与在内置 Lakehouse 上完全相同——导入、转换、联接和发布步骤的工作方式都一样。后端在创建项目时设定，并适用于整个项目。

## 向绑定了 Lakehouse 的项目导入文件

向绑定了 Lakehouse 的项目导入 CSV、Parquet、XML 或 Access 文件时，会通过您数据仓库自身的**原生并行批量加载路径**加载：Snowflake 使用内部暂存区加 `COPY INTO`，Databricks 使用托管卷加 `COPY INTO`（请参阅 [Databricks 最低权限](#databricks-最低权限)），而不是通过外部云存储桶暂存文件。无需配置额外的云 IAM，并且无论您的数据仓库运行在哪个云上，工作方式都相同。

## 导出查询和表结果

从绑定了 Lakehouse 的项目导出查询或表结果时，会直接交付到云存储，而不是让每一行都经由 PlaidCloud 回传：

- **Snowflake** — 导出以 Snowflake 服务器端卸载（`COPY INTO` 到暂存区）的方式运行，由数据仓库直接将结果写入存储。大型导出会自动拆分为多个文件（此前超出 Snowflake 单文件上限的导出会失败）。
- **Databricks** — 导出以 Databricks 服务器端卸载（`INSERT OVERWRITE DIRECTORY` 到 Unity Catalog 托管卷）的方式运行，由数据仓库自行写入并编码结果，PlaidCloud 只负责将完成的文件中继到存储。大型导出会自动滚动写入多个文件，CSV 可以以 gzip 压缩的形式交付。

## 基于 Lakehouse 数据的仪表板

仪表板可在两种引擎上使用。

- **Databricks** — 仪表板通过 Databricks 驱动程序连接，使用服务主体的 OAuth 凭据（或个人访问令牌）。在通过[登录](#使用-snowflake-或-databricks-登录)挂接的数据仓库上，每位查看者的仪表板以其本人的 Databricks 身份运行。
- **Snowflake** — 仪表板使用数据仓库的服务用户和密钥对连接。在通过[登录](#使用-snowflake-或-databricks-登录)挂接的数据仓库上，每位查看者的仪表板则改为以其本人的 Snowflake 身份运行。项目的仪表板在创建或发布项目时设置。

## 让 PlaidCloud 为您注册数据仓库

您不必自己连接数据仓库。请针对您要连接的引擎，将下列详细信息提供给您的 PlaidCloud 联系人，由管理员代您注册。

### Snowflake

| 字段 | 需要提供的内容 |
|---|---|
| 主机名 | 您的 Snowflake 账户主机。 |
| 超级用户 | PlaidCloud 用于身份验证的 Snowflake 用户。 |
| 数据库 | PlaidCloud 创建并管理项目架构的数据库。 |
| Warehouse | PlaidCloud 运行查询所用的计算仓库。 |
| 角色 | PlaidCloud 所扮演的 Snowflake 角色。 |
| 私钥 | 用于密钥对身份验证的**原始、未加密** PEM 私钥——请粘贴密钥文本本身，而不是 base64 编码的副本。目前尚不支持受密码短语保护的密钥。 |

在交出私钥之前，请生成密钥对并将公钥分配给 Snowflake 超级用户。该角色必须能够在目标数据库中创建、读取和写入表。

### Databricks

| 字段 | 需要提供的内容 |
|---|---|
| 主机名 | 您的 Databricks 工作区 URL。 |
| HTTP 路径 | PlaidCloud 对其运行查询的 SQL 仓库的 HTTP 路径。 |
| Unity Catalog | PlaidCloud 创建并管理项目架构的 Unity Catalog 目录。 |
| 个人访问令牌 | 用于身份验证的 Databricks PAT。 |

令牌所属的身份必须能够在该目录中创建、读取和写入表。

两种注册都不要求提供架构——每个项目都有自己的架构，在项目绑定到 Lakehouse 时根据其 DSN 自动派生。

注册表单带有**测试连接**按钮，它会使用输入的详细信息打开一个实时连接，并报告成功或失败原因，而不保存任何内容——因此可以在注册 Lakehouse 之前验证凭据。Snowflake 测试需要原始、未加密的 PEM 私钥（受密码短语保护的密钥会被报告为不受支持）；Databricks 测试使用 PAT。

已注册的数据仓库并不会在保存的那一刻就可用。它会在**您的数据仓库**中显示为**正在切换…**，持续几分钟，原因与您自己添加的数据仓库相同（参见[管理数据仓库](#管理数据仓库)）。

<Aside type="note">Iceberg/Lakekeeper 目录连接需单独注册，且为可选项——使用 Snowflake 或 Databricks 数据仓库并不需要它。</Aside>
