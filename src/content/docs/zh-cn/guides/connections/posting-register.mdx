**过账登记簿**列出过账到您 ERP 系统的每张凭证，涵盖您有权查看的所有项目和系统。它首先显示**需要关注**，即需要人工处理的凭证，您可以从这里打开任何过账，了解它为何处于当前状态，并对其采取操作。

凭证通过**过账凭证**步骤、各 ERP 自己的过账步骤（例如 **Intacct：过账日记账分录**）、过账文件，以及下文所述的冲销、贷记和更正操作进入登记簿。运行如何启动、检查和发送，见[向 ERP 系统过账凭证](/zh-cn/guides/connections/post-documents/)；系统如何设置，见 [ERP 系统](/zh-cn/guides/connections/erp-systems/)。

## 打开登记簿

打开**过账登记簿**应用。持有[谁能看到什么](#谁能看到什么)中所述任一 `erp.register.*` 权限的成员都会看到它。它始终首先打开**需要关注**。

左侧导航栏分为三组：

| 分组 | 页面 |
|---|---|
| **过账** | **需要关注**、**过账**、**运行次数** |
| **需要我处理** | **审批**、**委派**、**我的关注** |
| **设置** | **系统**、**暂挂规则**、**更改历史**、**导出与告警**、**保留** |

**需要关注**和**审批**在导航栏上显示数量。除非您持有 `erp.register.admin`，否则**保留**处于隐藏状态。**运行次数**会打开过账运行列表，**系统**和**暂挂规则**的说明见[向 ERP 系统过账凭证](/zh-cn/guides/connections/post-documents/)和 [ERP 系统](/zh-cn/guides/connections/erp-systems/)。

您也可以从 PlaidCloud 的其他位置进入登记簿：

- **主页**在有内容需要您处理时会显示**过账登记簿**卡片，并带有**需要关注**和**等待审批**的数量。选择它会打开**需要关注**。
- 命令面板列出**需要关注**和**审批**及其数量。输入分类账 ID，然后选择 **Find posting** 加该 ID，即可打开该过账。

### 实时更新

登记簿会自动保持最新。当系统上的过账发生变化时，导航栏数量会重新读取；已打开的列表会显示**自加载以来过账已发生变化**和一个**刷新**按钮，而不是在您眼前移动行；已打开的过账会原地重新加载。

## 谁能看到什么

### 权限

四项权限用于打开和操作登记簿。持有其中一项并不会授予另一项，但每个需要 `erp.register.operate`、`erp.register.approve` 或 `erp.register.admin` 的操作也都需要 `erp.register.view`。无论屏幕上显示什么，每个操作都会在服务器上检查其所需的权限。

| 权限 | 允许的操作 |
|---|---|
| `erp.register.view` | 打开登记簿；阅读**需要关注**、**过账**以及过账的详细信息；在**过账**上提问；阅读注释和签核。 |
| `erp.register.operate` | **冲销…**、**贷记…**、**更正…** 和**下载为过账文件…**；**从已存储的报表结算**；**说明是否已过账**（还需要 `erp.register.approve`）；添加注释、签核和关注；打开**审批**、撤回您自己的请求，并在拥有批准权限时决定他人的请求；查看或撤销委派；下载、计划和审计证据导出。 |
| `erp.register.approve` | 批准冲销；阅读并决定**已暂挂的单据**；委托您的审批；说明某笔**未确认**的过账是否已通过。 |
| `erp.register.admin` | 导出，以及审计员配置下的审计证据导出；管理其他成员的计划；设置**保留**；更改[暂挂规则](/zh-cn/guides/connections/erp-systems/)。 |

四个内置安全组将这些权限捆绑在一起：**过账登记簿查看者**（查看）、**过账登记簿操作员**（增加操作）、**过账登记簿审批人**（增加批准）和**过账登记簿管理员**（全部四项）。

少数操作还需要项目权限，而不是登记簿权限：**重试**和**在系统中检查**需要 `analyze.workflow.write`，**重试**还需要在该过账所属项目中拥有架构师或管理者角色。**更改历史**需要 `analyze.connection.read`。

通过 REST API 或 MCP 工具使用登记簿时，适用相同的权限和可见性规则：每个路由和工具运行的检查与屏幕相同。

### 您能看到哪些过账

持有登记簿权限可以打开登记簿，但本身并不会让您看到任何过账。只有同时满足以下所有条件，您才能看到某笔过账：

- **您在其系统的连接上持有个人授权。** 您必须是该连接的所有者、被列在该连接上，或属于该连接上列出的某个安全组，请参阅该连接的[安全模型](/zh-cn/guides/connections/create-connection/#安全模型)。与**所有工作区成员**共享的连接不算，服务账户的授权也不算。
- **您可以打开其项目**（如果它属于某个项目）。
- **项目允许您查看其实体。** 当项目通过 `entity` 上的行访问限制成员只能查看某些实体时，您只能看到这些实体的过账。项目架构师不受限制。

您的访问权限在每次请求时都会重新读取，因此被撤销的授权会在下次加载页面时生效。没有任何连接授权的成员会看到**没有可显示的系统**，而不是空列表。

## 七种状态

每张凭证，无论由什么过账，都显示为七种状态之一。每个状态标签、筛选标签和筛选器上都使用相同的词语。

| 状态 | 含义 |
|---|---|
| **将过账** | 已检查。其系统或该次运行处于“模拟”，因此没有发送任何内容。 |
| **需要审批** | 有规则将其暂挂，等待人员批准。 |
| **等待中** | 已批准，即将发送或已发送。系统尚未答复。 |
| **已过账** | ERP 已接受此过账。 |
| **未过账** | 被检查阻止，或被系统拒绝。原因会说明是哪一种。 |
| **未确认** | 没有收到答复，且无法向系统询问。请说明它是否已过账。 |
| **已冲销** | 之后的某笔过账已取消此笔。 |

## 选择要查看的内容

**需要关注**和**过账**共用一个范围，因此在其中一个上设置的筛选器也会在另一个上生效。页眉下方的栏会显示它：您缩小过的内容都是可以移除的标签，保持默认的内容则用文字说明，例如**所有系统**。

选择**更改范围**进行编辑：

- **已过账**：**本月**、**上个月**、**最近 7 天**、**最近 30 天**或**自定义**，后者会要求填写**从**和**至**日期。默认是最近 30 天。
- **系统**和**项目**，从您能看到的系统和项目中选择。
- **实体**，位于**高级 ▾** 下。

**重置**会把范围恢复为默认值。栏下方有一排**状态**标签，可将列表缩小到某一种状态。

浏览器地址栏中带有范围，因此您可以将其加为书签，或发送给同事。无论谁打开，看到的都只是其自身访问权限所允许的内容。

## 需要关注

**需要关注**列出每一张需要人员处理的凭证，先是审批，然后是**未确认**，再是**未过账**，最后是需要查看的已过账凭证。选择一行即可打开它。页面名称下方的一行会统计需要关注的数量，以及其中有多少在等待审批，例如“12 项需要关注 · 3 项待审批”。

每一行显示**参考号**、**实体**、**系统**、**金额**、**货币**、**状态**、**原因**、**下一步**和**模式**；**项目**和**类型**是可以显示的隐藏列。**原因**是用通俗语言写出的第一个原因，还有其他原因时会带有“（另有 2 项）”，**下一步**是针对它该怎么做。

**模式**显示**实时**或**模拟**。模拟凭证同样需要人员处理（失败的检查必须先修复才能过账），因此除非链接指定了某一种模式，否则此页面会同时显示两者。

这里的**状态**标签有**需要审批**、**未过账**、**未确认**和**已过账**。没有匹配项时，页面显示**一切正常**：“没有需要人员处理的内容。每张凭证都已过账、正在等待，或将会过账。”如果您的范围已缩小，它会提供**重置范围**。

### 凭证为何需要关注

**未过账**的凭证会带有其停止的原因。来自检查的原因（在发送任何内容之前出现）需要在源头或系统中修复，然后重新运行（请参阅[向 ERP 系统过账凭证](/zh-cn/guides/connections/post-documents/)）。对于其中大多数，**下一步**显示为**修正后重新运行**；对于没有系统对应其实体的凭证，则显示为**重试**，在您添加系统后会重新为该凭证路由；对于引用包含 `~` 或过长的凭证，**下一步**为空：

| 原因（如显示） | 怎么办 |
|---|---|
| 没有为该实体设置过账的系统 | 在**系统**下为其选择一个系统。 |
| 其系统已停用 | 过账到另一个系统。 |
| 期间在系统中已关闭 | 打开该期间，或过账到下一个期间。 |
| 系统中不存在某个科目 | 在系统中创建它，或将代码匹配到另一个科目。 |
| 某个代码在系统中没有匹配 | 在**系统**下对其进行匹配。 |
| 此付款所支付的发票未结 | 在系统中检查该发票。 |
| 它属于的公司与其系统过账到的公司不同 | 将其路由到该公司的系统。 |
| 某一行使用的货币其系统不记账 | 以系统的货币过账，或过账到另一个系统。 |
| 系统需要的某个值为空 | 在源头填写。 |
| 借方和贷方不一致 | 修复源数据后重新运行。 |
| 其批次缺少一部分，或批次中的凭证不一致 | 只有批次中的每张凭证都在且彼此一致时，批次才会过账。 |
| 该引用已过账到另一个系统，或已在此系统上使用 | 修复后重新运行。 |
| 其引用包含 `~`，或对该系统来说过长 | 在源头更改引用。PlaidCloud 将 `~` 保留用于为版本编号。 |
| 此系统暂时无法处理这种类型的凭证 | 修复后重新运行。 |
| 此引用的较早版本尚无系统的答复 | 有答复后再重新运行。 |

其他原因描述的是检查通过之后发生的情况，**下一步**会为它们提供[**重试**](#重试)：批准人拒绝了它、运行在发送前被停止、该系统的代理处于离线、因在到达系统之前出现故障而未发送、系统拒绝了它，或 PlaidCloud 在截止时查看时系统中没有它。

其余情形需要关注，但不是**未过账**：

| 原因 | 状态 | 下一步 |
|---|---|---|
| 它需要人员批准，并指明暂挂它的规则 | **需要审批** | **批准**：请参阅[审批](#审批)。 |
| 系统没有及时答复，且无法询问该凭证是否已过账 | **未确认** | **说明是否已过账**：请参阅[未确认的过账](#未确认的过账)。 |
| 在过账之后源数据发生了更改 | **已过账** | **用此版本更正**或**保留已过账的**，在运行页面上回答。 |
| 其批次中只有一部分已过账 | **已过账** | **修正后重新运行** |
| 已过账，但不在系统自己的记录中，或记录不一致 | **已过账** | **在系统中检查** |
| 过账之后在系统中被更改 | **已过账** | **在系统中检查** |
| 未经 PlaidCloud 而直接在系统中录入 | **已过账** | **在系统中检查** |

未经 PlaidCloud 而直接在系统中录入的内容，会按项目、系统、实体和月份归为一行，例如“2026 年 10 月有 4 条分录并非由 PlaidCloud 创建”。只有在没有任何筛选器缩小列表时才会列出这些行，且它们不计入顶部的数量。**已过账**日期算作筛选器，且范围默认从最近 30 天开始，因此需要在**更改范围**中的**已过账**下选择**自定义**，并将**从**和**至**留空，这些行才会显示。

## 过账

**过账**列出您能看到的每张凭证，每张凭证一行：**参考号**、**类型**、**实体**、**系统**、**项目**、**金额**、**货币**、**状态**、**系统单据**、**过账日期**、**发起人**、**已批准**和**模式**。**系统单据**是系统给它的编号，一旦检查在系统自己的记录中找到它，后面会带有**账簿中**。**已批准**显示**自动**或**人工**。页面名称下方的一行会统计过账数量，并按货币汇总；不同货币绝不会相加。

在页眉中：

- 搜索框会在您输入时查找参考号、系统单据或金额。
- **提问**接受您用自己的话输入在同一搜索框中的问题，例如“10 月我们过账了什么？”。它能理解状态、实体、模式和月份，并且只能缩小您可以看到的内容。随后列表会显示前 25 个匹配项，并附一句话说明系统理解了什么。
- **实时**、**模拟**和**全部**选择要显示哪些过账。**实时**是默认值。

**状态**标签涵盖全部七种状态。较长的列表在 1,000 行处停止并显示提示；**加载更多**会读取接下来的 1,000 行。

勾选一行或多行，然后使用工具栏的**操作**菜单，对所有勾选的行一次性执行**冲销…**、**贷记…**、**更正…** 或**下载为过账文件…**。这些需要 `erp.register.operate`，其工作方式见[冲销、贷记或更正](#冲销贷记或更正)。未经 PlaidCloud 而在系统中录入的行无法在此处操作。

## 过账抽屉

从某一行的放大镜图标打开过账，或在**需要关注**上选择一行。过账会在右侧的抽屉中打开，位于列表旁边。

抽屉顶部依次显示状态标签、用通俗语言写出的每个原因（其下是系统自己的消息），然后是该过账的各项信息：**参考号**、**类型**、**金额**、**系统单据**、**系统**、**环境**、**实体**、**过账日期**、**项目**、**工作流**、**步骤**、**发起人**、**已批准**和**模式**。等待审批的冲销还会显示“此冲销需要第二个人批准。发起人本人不能批准。”

其余内容放在五个选项卡中：

| 选项卡 | 显示内容 |
|---|---|
| **明细行** | 每一行的**科目**、**说明**、**借方**、**贷方**和**维度**。 |
| **历史记录** | 凭证发生了什么、何时发生、由谁操作。 |
| **版本** | 该引用的每个版本，例如 `INV-100` 和 `INV-100~2`，及其状态，以及您正在查看的是哪一个。 |
| **链接** | 它的来源及相关内容：**源行数**、**步骤版本**、**步骤最后更改人**、**冲销对象**、**冲销者**、**贷项**和任何**附件**。 |
| **签核** | 对该过账的复核签核和注释，请参阅[签核和注释](#签核和注释)。 |

抽屉的**操作**菜单包含**复制链接**（复制一个链接，任何有权查看的人都可以通过它打开此过账），以及在适用时的**在系统中打开**（用于 QuickBooks Online 过账，可直接打开）、**关注连接**（当过账有连接时）和**关注运行**（当它有运行时）。拥有 `erp.register.operate` 的成员还会在那里看到**贷记…**、**更正…**、**下载为过账文件…** 和**在系统中检查**，并在它旁边看到作为按钮的**说明是否已过账**和**冲销…**。没有 `erp.register.operate` 时，页脚会显示“冲销需要过账登记簿操作员角色。”**重试**会出现在菜单旁边，供适用的人使用，请参阅[重试](#重试)。

每个操作只在过账的状态允许时才提供，指向灰显的项目时会说明原因。

### 重试

当**下一步**提供**重试**、凭证有分类账条目，且您持有 `analyze.workflow.write` 时，会出现**重试**。它会先检查将要发送的内容；如果没有任何内容可以重试，会说明原因。否则它会询问“再次将已存储的凭证发送到”该系统，选择**重试**后，已存储的副本会作为一次新运行再次发出，并受项目的过账限制约束。

只有在确定系统没有记账时，才会重试凭证：即**未过账**，或从未发送。您还需要在其项目中拥有架构师或管理者角色，并且自己对其连接持有授权。

### 冲销、贷记或更正

只有**已过账**的凭证才能被冲销、贷记或更正：

- **冲销…** 会在其系统中撤销该过账。
- **贷记…** 会针对已过账的发票开具贷项通知单。它只适用于客户发票和供应商发票。对单笔过账贷记时，**金额**留空表示贷记整张发票，也可以只填写其中一部分。
- **更正…** 会冲销当前版本；当 PlaidCloud 持有该凭证尚未过账的较新版本时，会将其作为下一个版本（`REF~2`）发送。对于过账后源数据发生更改的过账，也会提供此操作。

每一项都会打开一个对话框，先检查可以做什么：将对多少笔过账、在哪个系统中、以何种方式执行（“系统自己的冲销”“贷项通知单”或“反向过账”），以及哪些无法执行并附上各自的原因。冲销作为批次的一部分过账的凭证，会连带冲销该批次的其余凭证。填写**原因**，可选地更改**日期**（初始为今天），然后确认；按钮会统计过账数量，例如 **Reverse 3**。

随后该操作像任何过账一样运行：它被记录为一次新运行，经过检查，在有规则暂挂时需要批准，然后发送并确认，并打开运行页面。一个操作最多可包含 200 笔过账。

冲销、贷记和更正都是实时写入，因此当过账的项目被限制为“模拟”、项目未获授权向该系统过账，或您对其连接没有个人授权时，该过账会被拒绝。有些系统无法通过其界面撤销过账；对于这些系统，对话框会予以说明。

### 职责分离

当您的工作区开启了职责分离时，达到或超过其阈值的冲销需要第二个人的批准。职责分离及其阈值由 PlaidCloud 为您的工作区设置；登记簿中没有对应的设置。

- 该凭证在运行中显示为**需要审批**，并且审批请求会发送给在该过账的连接上持有授权的每位批准人。无需指定收件人：连接授权就是路由。
- 批准人必须持有 `erp.register.approve`，或持有来自拥有该权限者的有效委派，并且自己对该连接持有授权。请求冲销的人不能批准它，即使通过委派也不行。
- 一次批准恰好涵盖那一次冲销：该过账、其原因和其日期。批准后，待五分钟的暂挂期过去，用相同的原因和日期再次运行同一操作，即可通过。
- 提交人在过去 24 小时内对同一连接的冲销会合并计入阈值，因此无法把大额冲销拆成较小的冲销来规避阈值。
- 当在某个连接上有资格批准的成员少于两人时，需要批准的冲销会被拒绝。

### 下载为过账文件

**下载为过账文件…** 会询问**操作**（**冲销**、**贷记**或**更正**）和**格式**（**Excel** 或 **CSV**），然后保存一个已填写好的、用于该操作的过账文件。编辑金额或明细行，然后通过 REST API 或 MCP 工具从文件过账，请参阅[向 ERP 系统过账凭证](/zh-cn/guides/connections/post-documents/)。

### 在系统中检查

**在系统中检查**会立即在其系统中查找该过账，且从不模拟。它会显示**已在系统中找到。** 或**在系统中未找到。**，或说明为何无法询问系统，同时过账的**账簿中**状态会更新。它需要 `analyze.workflow.write`。

### 签核和注释

**签核**选项卡用**标记为已复核**、**标记为已清除**或**需要跟进**以及可选的**备注**来记录对该过账的复核。它显示当前的签核和之前的每一次签核。

其下方的**注释**保存关于该过账的纯文本备注。输入一条注释，列出要提及的成员 ID，然后选择**发表评论**。被提及的成员只有在通知发出时能够看到该过账，才会收到通知。

添加注释和签核需要 `erp.register.operate`，阅读需要 `erp.register.view`。尚无分类账条目的凭证会显示“此凭证暂不提供注释和签核。”

### 关注

抽屉**操作**菜单中的**关注连接**和**关注运行**，会在此后通知您该过账所属连接或运行上的活动；开启后分别显示为**正在关注连接**和**正在关注运行**。只有在您仍能看到相关过账时，才会向您发送通知。关注需要 `erp.register.operate`。

## 未确认的过账

当系统没有及时答复，且无法询问该凭证是否已过账时，过账为**未确认**。由人员根据在系统中找到的内容来处理。

### 说明是否已过账

打开该过账并选择**说明是否已过账**。在其系统中查找该凭证，然后选择：

- **已过账**，并填写其在系统中的**文档**编号。该过账变为**已过账**并带有该编号。
- **未过账**。该过账变为**未过账**，可以重试。

必须填写说明您所见内容的**备注**。错误的答复可能导致凭证被过账两次，或记录下系统从未收到过的凭证，因此这需要 `erp.register.operate`、`erp.register.approve` 以及您自己对该连接的授权；没有 `erp.register.approve` 时，按钮灰显并说明原因。如果系统自己的答复先到达，则以它的答复为准。

### 从已存储的报表结算

SAP 过账会留下其运行的报表。当有内容为**未确认**且您持有 `erp.register.operate` 时，**需要关注**的工具栏中会出现**从已存储的报表结算**。它会读取所勾选行的报表，或在没有勾选时读取您范围内每个系统的报表，说明有多少凭证将被结算为**已过账**，并列出无法结算的凭证及原因。选择统计这些凭证数量的按钮（例如 **Settle 3 documents**）即可应用。

根据报表结算只会把凭证变为**已过账**；不会有任何内容被标记为已拒绝。报表缺失、早于发送它的运行，或没有显示其已过账的凭证，保持**未确认**。

## 审批

**审批**是您决定等待您处理的事项的地方。页眉中的标签在以下几项之间切换：

- **待我处理**：您可以决定的冲销审批请求。
- **我提交的**：您提出的请求。
- **已暂挂的单据**：等待第二个人处理的冲销、贷记和更正，以及暂挂规则所暂挂的凭证，仅在您持有 `erp.register.approve` 时显示。

页眉中的**委派**链接会打开[委派](#委派)。

### 冲销请求

每个请求显示该分录、其金额和实体、谁提出以及多久之前、它所冲销到的期间，以及请求人的原因。选择**批准**或**拒绝**，填写随您的决定一起记录的原因，并确认。若要一次批准多项，请勾选它们并选择页眉的 **Approve selected (3)** 按钮，它会统计您勾选的行数。

- 批准之后，消息会提供 8 秒的**撤消**，并且在五分钟暂挂期内，该行会提供**撤销批准**。暂挂期过后，冲销可能已经进入系统。
- 在**我提交的**上，**撤回**可收回仍在等待或已批准的请求。
- 等待了四小时的请求显示**已升级**，24 小时后显示**已升级两次**。始终无人决定的请求会在七天后过期，必须重新申请。

如果您没有批准权限，页面会显示**您无权批准冲销**，而不是列出请求。

### 已暂挂的单据

**已暂挂的单据**先列出等待第二个人处理的冲销、贷记和更正，然后按从旧到新列出[暂挂规则](/zh-cn/guides/connections/erp-systems/)暂挂的凭证。它们按运行分组。被标记为金额异常的凭证显示**异常**。

选择**批准**即可发送凭证；或选择运行卡片上统计其凭证数量的按钮（例如 **Approve all 3 documents**），在确认并列出它们将发送到哪些系统之后，批准它所显示的每张凭证。**拒绝**会询问原因，并使该凭证变为**未过账**。已批准的凭证按运行的模式以及项目当前的限制和授权发送。

您不能决定由您启动或发送的运行中的凭证，也不能决定针对您所做过账的操作：必须由其他人批准。批次作为一个整体获得批准，因此其中有任何您无法决定的凭证的批次，会留给能够决定的人。

## 委派

**委派**让批准人在一段时间内（例如外出期间）把其批准权限交给另一位成员，并显示交给您的任何权限。两张卡片分别列出**您委派的**和**委派给您的**。

选择**委托审批**，选择一位**成员**，设置**天**数（默认七天，最多 30 天），并填写**原因**，它会记录在审计跟踪中。**撤销**会提前结束委派；双方都可以撤销。

- 委托需要 `erp.register.approve`。查看和撤销委派只需要 `erp.register.operate`，因为您委派的对象通常并不持有批准人权限，这正是您要委派给他们的原因。他们必须持有 `erp.register.operate`。
- 您不能委派给自己、委派给已委派给您的人，或委派给服务账户，并且被委派人不能把该权限再转交出去。
- 被委派人不能批准委派给他们的那个人所提出的请求。被委派人批准时，**审批**页眉会说明他们正在使用谁的权限，并且每个决定都会记录为在该批准人的权限下作出。

## 我的关注

**我的关注**列出您正在关注的连接和运行。选择**关注连接**可添加您能看到的某个连接，选择**停止关注**可移除一个；消息上的**撤消**会再次关注它。

## 导出和警报

**导出与告警**是登记簿以文件或通知形式离开 PlaidCloud 的地方。这里的一切都需要 `erp.register.operate`；没有它，页面会说明您可以阅读登记簿，但不能导出。

<Aside type="caution">
下载的文件会离开 PlaidCloud。每次生成文件时（包括每次计划发送）都会检查授权、角色和掩码，但交付之后不再做任何检查。自由文本字段会从所有导出中排除。
</Aside>

### 文件包含什么

每个文件都是根据您自己在生成时的访问权限，用两种配置之一生成的：

- **标准**：不包含金额、货币和过账每张凭证的成员。
- **审计员**：包含金额、货币和过账每张凭证的成员。此配置需要 `erp.register.admin`。

页面会告诉您您的导出使用哪种配置。

### 立即下载

从工具栏（或其**操作**菜单）：

- **下载 CSV**和**下载 JSON**会导出登记簿。选择了导出计划时，文件会使用该计划的筛选器。
- **审计证据导出…** 会生成一个期间的证据，请参阅[审计证据导出](#审计证据导出)。

### 计划和警报

选择**新建计划**并填写：

- **名称**和**类型**：**导出文件**或**警报**。
- 导出文件的**格式**（CSV 或 JSON），或警报的**发送时机**：**正式过账失败时**、**授权即将过期时**或**已过账冲销时**。
- **频率**：**按需**、**每天**、**每周**或**每月**。
- **收件人**：PlaidCloud 成员，绝不是电子邮件地址。
- 可选地填写**连接**和**实体**以缩小范围。

每日作业会发送自上次发送以来间隔已过的每个**每天**、**每周**和**每月**计划。**按需**计划只在您选择**立即发送**时才发送。**删除计划**会永久停止一个计划。

每个收件人在发送的那一刻获得其自身访问权限所允许的内容，因此同一计划的两个收件人可能收到不同的文件。不再持有导出角色、没有连接授权、没有电子邮件地址或已被禁用的收件人会被跳过，**立即发送**会说明谁被跳过以及原因。只有计划的所有者或持有 `erp.register.admin` 的成员才能发送或删除它。

### 审计证据导出

**审计证据导出…** 会把一个期间保存为五个部分：过账了什么、账簿中有什么、谁批准了、规则和逻辑中有什么变化，以及谁可以做什么。输入**期间**（例如 `2026-10`），可选地在**实体**下输入一个或多个实体（留空表示全部），选择 **Excel** 或 **JSON**，然后选择**下载**。

该文件涵盖您能看到的、日期落在该期间内的实时过账。标准配置不包含金额和所有人员信息，包括谁发起、请求、决定和更改了内容、批准人的原因、规则更改前后的内容以及访问部分，因此审计员配置才是包含完整记录的那一个。

## 更改历史

**更改历史**列出对系统设置的每次更改、系统的停用、SAP 函数、代码匹配、哪个实体向何处过账、暂挂规则、上线和列表复制，包含**时间**、**操作者**、**内容**、**系统**、**哪个**、**从**和**至**。它最多显示 2,000 条更改；请将其缩小到某一个系统以查看其余内容。它需要 `analyze.connection.read`。

## 保留

位于**设置**下的**保留**设置登记簿保留三类历史记录的时长：**捕获（边车请求/响应）**、**模拟存储**和**写入审计跟踪**。每一项都是一个天数（最多 3,650），或**无限制**。选择**保存**即可应用。卡片会说明最后由谁在何时设置了该策略；在有人设置之前，每个期限都是无限制。

只有持有 `erp.register.admin` 的成员才能在导航栏上看到**保留**并更改它。每日清理会应用该策略。

<Aside type="note">
保留绝不会触及已过账内容的记录，而这正是防止凭证被过账两次的依据。超过捕获期限后，过账所捕获的请求和响应会被清除，但过账本身、其状态及其详细信息会保留。超过模拟期限后，模拟过账会被删除。
</Aside>
