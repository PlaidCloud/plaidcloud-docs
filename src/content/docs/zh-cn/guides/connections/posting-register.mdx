**过账登记簿**是一个独立于任何单个项目的租户级控制台，财务和会计人员可在此跨所有有权查看的项目和连接审核 ERP 过账。[ERP 过账历史记录](/zh-cn/guides/connections/erp-post-history/)的范围限于一个您已有权访问的项目，而过账登记簿则是跨项目视图，专为需要在一处查看来自多个项目和连接的过账的审核人员而设计。

过账登记簿首先为审核而构建。两项[批量操作](#批量操作)（清除模拟过账和重试失败的过账）、详细信息抽屉中的单行**重试**、[冲销](#冲销)，以及一次性冲销整个[公司间运行](#公司间运行)，让您可以直接在网格和详细信息抽屉中执行操作；[AI 辅助](#ai-辅助)帮助您更快地查找和理解过账；[趋势](#趋势)、[谱系](#谱系)、[控制总计](#控制总计)、[关账](#关账)和[导出](#导出)让您能够分析、追溯到源头、封存期间并导出数据。[协作](#协作)让团队可以共同对过账发表评论、签核和关注，而通知中永远不会包含金额。

控制台是一个停靠式工作区，而不是一组浮动窗口。左侧的**导航栏**将每个屏幕作为**原位窗格**打开，因此切换屏幕时替换的是工作区中央的内容，而不是在上一个窗口之上再叠加一个窗口。打开一笔过账后，其详细信息会从右侧滑入，而不会遮挡您正在处理的列表。有关导航栏、标题区和范围栏如何协同工作，请参阅[工作区](#工作区)。

## 工作区

### 起始屏幕

登记簿打开时显示最需要您处理的屏幕。如果有任何过账需要关注，则打开**异常**；如果没有需要关注的过账，但有等待您处理的审批，则打开**审批**；否则打开**所有过账**。

导航栏按您正在执行的工作对屏幕进行分组：

| 分组 | 屏幕 |
|---|---|
| **需要我处理** | **异常**、**审批**、**委派**、**我的关注** |
| **登记簿** | **所有过账**、**辅助**、**模拟** |
| **洞察** | **汇总**、**趋势**、**控制总计**、**谱系** |
| **设置** | **导出和警报**、**保留** |

**异常**和**审批**在导航栏上带有计数徽章，因此无需打开即可看到有哪些内容在等待处理。您不具备相应作用域的屏幕或操作会被隐藏，详见[各角色可见的内容](#各角色可见的内容)。

### 标题区

每个屏幕都有相同的标题区。屏幕名称位于顶部，下方是一行摘要，例如有多少项未结以及最早的一项已等待多久。屏幕的主要操作（如有）是标题区右侧的一个按钮，旁边是属于该屏幕的控件，例如**实时** / **模拟** / **全部**或容差。如果屏幕有多个次要操作，它们会归集在**操作**下。

### 范围栏

标题区下方的范围栏显示您正在查看的内容。您缩小的任何条件都会显示为可移除的标签；保持默认值的条件则以文字直接说明，例如“All connections”，而不是显示为空的选择器。

- **期间**：**本月**、**上个月**、**最近 7 天**、**最近 30 天**或**自定义**（需要指定**从**和**至**日期）。
- **连接**、**项目**、**环境**和**实体**，以及**高级**下的 **ERP 类型**。
- **实时**、**模拟**或**全部**过账。

选择 **Change scope** 可一起编辑这些条件，选择**重置**可将其恢复为默认值。下次打开登记簿时会记住您上次使用的范围，而别人发送给您的链接会以其自带的范围打开。**所有过账**上的 **Saved scopes** 用于保存您想要再次使用的命名范围，这些范围仅属于您，其他成员看不到。

屏幕只提供其能够使用的范围字段，因此不会在忽略该字段的屏幕上出现无效的选择器。当列表达到上限，或者已保存的范围带有范围栏无法显示的筛选器时，标签下方会显示一条提示加以说明，例如列表上限为 500 条，应缩小搜索范围。

### 查找过账

在**异常**或**所有过账**的标题区中，于 **Find a posting by ledger id** 中输入过账的分类账 ID 并按 **Enter**，即可直接打开其详细信息抽屉，无论当前范围如何。也可以在命令面板中执行相同操作：输入分类账 ID，然后选择 **Find posting** 加该 ID。在列表上按 **/** 可跳转到其筛选框。

### 实时更新

登记簿会自动保持最新。导航栏徽章会随过账的变化而更新；当已打开列表中某个连接上的过账发生变化时，屏幕会显示 **Postings have changed since this loaded** 和一个**刷新**按钮，而不会在您操作时移动行。如果您打开了某笔过账的抽屉，其状态会原位更新。

### PlaidCloud 中的其他入口

命令面板在过账登记簿下列出**异常**和**审批**及其计数。如果有任何内容需要您处理，**主页**会在**需要关注**中显示一张**过账登记簿**卡片，其中包含未结异常和待处理审批的计数，以及进入登记簿的链接。

## 谁可以打开

打开过账登记簿需要以下四个 Keycloak 领域作用域之一：`erp.register.view`、`.operate`、`.approve` 和 `.admin`。它们是相互独立的授权，而不是逐级递增的阶梯：持有 `.admin` 本身并不授予 `.operate` 所授予的权限，每个变更或外发操作都会显式检查其所需的一个或多个作用域，而不是从更高层级推断。

| 作用域 | 授予 |
|---|---|
| `erp.register.view` | 打开登记簿并审核过账，包括异常队列、网格、汇总视图、趋势、谱系和 AI 辅助。这些操作都不会应用、导出或通知任何内容。 |
| `erp.register.operate` | 所有更改状态或离开控制台的操作的基础权限：批量操作、发起冲销、为冲销请求审批、打开审批收件箱并对您有权决定的请求作出决定、查看或交还委派、导出或计划投递、订阅 AI 辅助摘要，以及发布评论、签核或关注。受 `.approve` 和 `.admin` 控制的操作是在 `.operate` 之上额外要求的，而不是替代它，详见下文。 |
| `erp.register.approve` | 对达到或超过租户职责分离阈值的冲销拥有审批权限（直接持有此作用域，或通过持有此作用域者的有效委派获得），以及处理卡住的冲销尝试（`released` 或 `confirmed`）。将此权限委派给他人也要求您本人持有 `.approve`；使用、查看或撤销委派则不需要。以上均需同时持有 `.operate`。 |
| `erp.register.admin` | 审计员导出和截至时点读取配置（金额和制单人身份不加掩码），以及设置租户的[保留策略](#保留)，均需同时持有 `.operate`。还允许您删除或触发其他成员的计划。 |

<Aside type="note">
四个内置安全组为方便起见以累加方式捆绑了这些作用域：**过账登记簿查看者**（`.view`）、**操作员**（增加 `.operate`）、**审批人**（增加 `.approve`）和**管理员**（全部四个）。但由于各作用域互不包含，安全组矩阵允许您独立分配任意组合。`.approve` 和 `.admin` 单独使用均无意义：它们控制的每个操作都还需要 `.operate`，因此用于处理冲销或导出未掩码数据的分组需要同时显式授予 `.operate`，而不能假定从更高层级获得。请分配与成员职责相符的层级或组合，而不是为所有人只分配 `.view`。
</Aside>

### 可见性规则

持有 `erp.register.*` 作用域可以打开控制台，但其本身不会使任何过账可见。只有当您同时持有该过账所属连接的**个人连接授权**，并且（当过账属于某个项目时）有权访问该项目，该过账才会在登记簿中可见。未关联到项目的过账仅受连接授权控制。

这是与上述登记簿作用域不同的另一项授权，两者都是必需的：

- **连接授权。** 您需要是该连接的显式所有者、被单独指定，或是该连接上指定的某个安全组的成员，即连接的[安全模型](/zh-cn/guides/connections/create-connection/#安全模型)所控制的同一组授权。**设置为 `All Workspace Members` 的连接不会授予登记簿可见性。** 该设置使所有人都能使用该连接，但它不是个人、分组或所有权授权，而登记簿明确要求其中之一。
- **项目访问权限**，适用于任何属于某个项目的过账，与您其他项目工作所需的访问权限相同。

持有 `erp.register.view` 但没有任何连接授权的成员会看到一个正确为空的登记簿，控制台会向其说明这一点，而不是看起来像出了故障。连接或项目授权被撤销后，会在下次加载页面时生效，不存在需要清除的过时可见性。

## 各角色可见的内容

控制台**按角色自适应**：您不具备相应作用域的导航栏条目或操作按钮会被**隐藏，而不只是变灰**，因此工作区只显示您实际可以执行的操作。这反映的是服务器强制执行的规则，而不是取代它：

| 您持有 | 您可以看到 |
|---|---|
| `erp.register.view` | 审核屏幕：异常、所有过账、汇总、趋势、谱系、控制总计和辅助。 |
| `erp.register.operate` | 增加操作按钮：重试、冲销和清除模拟过账。 |
| `erp.register.approve` | 增加审批决定和委派您的审批。 |
| `erp.register.admin` | 增加保留设置和未掩码的审计员导出。 |

隐藏控件**仅影响显示**，目的是避免向您提供会被拒绝的操作。服务器始终具有最终决定权：每个变更或外发操作在执行时都会重新检查其所需的作用域以及您的连接和项目授权。不会因为客户端显示了某个按钮就允许某项操作，也不会仅仅因为客户端隐藏了某个按钮就真正阻止某项操作。

## 异常队列

当有任何内容需要关注时，**异常**是您看到的第一个屏幕：最可能需要您处理的过账，按时间从早到晚显示。

顶部的一排标签用于筛选队列，每个标签都带有实时计数：**所有异常**、**需要查看**、**未确认**、**待处理**、**失败**和**冲销未完成**。选择一个标签会将队列缩小到该类别，而其他标签仍显示各自的总数，因此切换到**失败**时，**需要查看**不会显示为空。

- **需要查看**：过账已提交，但尚无任何信息确认其结果。
- **未确认**：已发送到 ERP，但未在规定时间内收到答复。
- **待处理**：仍在等待 ERP，或在等待已超过截止时间的审批。
- **失败**：ERP 拒绝了该过账。打开它查看原因，然后重试。
- **冲销未完成**：已请求冲销，但尚未完成。请参阅[仍未完成的冲销](#仍未完成的冲销)。

屏幕名称下方的一行统计未结项的数量，并且在列表未达到上限时，显示有多少项已超过截止时间以及最早的一项已等待多久。**Age on this page** 一行将当前显示的行按账龄区间进行划分。

每笔过账都显示一个以通俗语言表示的状态标签，并带有工具提示，说明该状态的含义以及下一步该做什么，例如**需要查看**、**等待中**、**已发送**、**已过账**、**已拒绝**、**已冲销**，而不是原始状态代码。状态标签和工具提示在列表、抽屉和筛选标签中均保持一致。

“超龄”是根据平台自身的计时器衡量的，而不是人为设定的阈值，因此过账恰好在平台自身认定其逾期时归入相应类别。

模拟过账永远不会出现在队列或其计数中。队列会说明排除了多少条，因此当计数偏低是由于模拟所致时，不会被误认为“没有需要审核的内容”。

当没有任何内容需要关注时，队列会显示 **All clear** 并注明您的范围。如果当前范围隐藏了其他地方存在的异常，屏幕会提供 **Reset scope**。

此处适用与网格相同的可见性规则：您只能看到关联到您个人获得授权的连接、且位于您有权访问的项目中的过账的异常。

### 仍未完成的冲销

通过 API 获取的异常列表 `GET /erp/register/exceptions` 还会报告一个单独的类别 `reversal_outstanding`，在控制台中显示为**冲销未完成**：一笔已过账分录的冲销已发送但从未结清，原因可能是 ERP 未作答复，或者尝试在分派过程中被中断。它与其他类别并列，拥有自己的标签和计数，与**需要查看**一起排在最前面，每一行都会注明冲销尝试及其状态。此类分录会一直保留在列表中，直到按[冲销](#冲销)中所述的方式得到处理；它不会自行因超龄而移出。

## 连接健康状况

异常队列和汇总视图（见下文）上方的一排状态标签回答了两者各自都无法回答的问题：您的某个连接是否已中断？一切正常时，显示为 **All N connections posting normally**；否则会说明有多少个连接需要关注。对于您个人获得授权的每个连接（且仅限这些连接），它会显示最近一次成功的过账以及该连接当前是否出错。尚无任何过账的已授权连接会注明这一点，而不会从列表中省略；如果健康检查本身无法完成，状态标签行也会说明这一点，而不会默默报告一切正常。

## 金额格式

登记簿显示的每个金额，包括网格、汇总、控制总计、详细信息抽屉、异常队列、审批收件箱、AI 辅助和冲销对话框中的金额，都以会计格式呈现：使用千位分隔符，负数加括号，并使用等宽数字，使一列金额按小数点对齐。小数位数取决于货币本身，而不是统一使用两位：JPY 不显示小数，KWD 显示三位小数。

- **小计永远不会跨货币汇总。** 在[汇总视图](#汇总视图)和[控制总计](#控制总计)中，包含多种货币的分组或批次都会拆分为每种货币一行，每行标注各自的货币。平台中的任何地方都不会假定外汇汇率。
- **为显示而进行的舍入永远不会掩盖真实差异。** 如果按货币的常用小数位舍入会丢弃非零数字，详细信息抽屉会在舍入值旁边显示所捕获的精确值。出于同样的原因，[控制总计](#控制总计)中的数字从不舍入：与容差比较的差额保持完整精度，因此像 `0.004` 这样真实超出容差的差额不会在“不平衡”的结论旁显示为 `0.00`。

## 登记簿网格

**所有过账**列出您可以看到的所有项目和连接中的每笔过账，每笔过账一行，显示在带有筛选框和刷新功能的卡片中。[范围栏](#范围栏)可按期间、项目、环境、连接、ERP 类型、实体以及**实时** / **模拟** / **全部**缩小查看范围，一排状态标签（**已检查**、**等待中**、**已发送**、**已过账**、**已拒绝**、**已冲销**和**需要查看**）则按状态进行筛选。您可以从限定于您有权查看内容的选择器中进行选择，而无需输入标识符，并且可以组合多个状态标签以同时查看多种状态。

如需自行构建 ERP 类型筛选器，`GET /erp/register/erp-types` 会返回您可以看到的过账中的所有 ERP 类型，并已排序。

**实时**仅显示已到达 ERP 的过账，**模拟**仅显示来自[模拟模式](/zh-cn/guides/workflows/run-a-workflow/#选择过账模式)运行的过账，**全部**（此屏幕上的默认值）则两者都显示。网格的**过账模式**列显示每一行属于哪一种。**控制总计**和**汇总**在标题区中有各自的**实时** / **模拟** / **全部**切换，默认为**实时**。当模式不是**实时**时，金额总计旁会有一条备注，说明其中包含从未到达 ERP 的模拟过账。

标题区的主要操作是 **Retry selected…**，向具有操作权限的成员显示。**命令**保留在卡片上；其他所有操作，例如 **Retry all matching…**、**清除模拟**和**加载更多**，都位于**操作**下。如果匹配的过账多于屏幕可容纳的数量，会有一条提示说明您看到的是最新的过账，并建议使用**加载更多**或缩小范围。

当登记簿显示[异常情况](#主动卡片)时，它们会以卡片形式显示在网格上方；卡片上的**显示这些**会将网格筛选为该卡片所统计的过账。

<Aside type="note">
范围可以共享。为设置了范围的网格添加书签后，链接会携带该范围，因此您可以将指向当前所查看过账的**深层链接**发送给同事。他们仍会通过自己的授权查看，永远不会超出其有权查看的范围。已保存的范围和布局会持久保留，因此登记簿会以您上次离开时的方式打开。
</Aside>

## 批量操作

在网格中选择多笔过账，即可一起对它们执行操作。可以勾选行来选择过账，也可以选择 **Retry all matching…** 或**清除模拟**，对当前范围匹配的所有内容执行操作。这会作用于筛选器在所有页面上匹配的每笔过账，而不只是已加载的过账。

提供两项操作：

- **清除模拟过账**：对不再需要保留的模拟过账进行软删除。
- **重试失败的过账**：重新发送被 ERP 拒绝或从未发送的过账。

### 影响预览

在任一操作运行之前，PlaidCloud 会在**批量影响**对话框中显示影响预览，一侧为**将更改**，另一侧为**已跳过**：受影响的过账数量、涉及的金额（按货币细分，金额永远不会跨货币混合，未捕获的金额显示为空白，而不是 `0.00`），以及受影响的过账所属的连接和实体。选择中该操作无法处理的任何内容都会单独列出，因此“所选的 30 笔过账中有 24 笔不会有任何变化”会在您确认之前就能看到，而不是事后才发现。

### 输入确认

超过阈值时，对话框的主按钮（**Clear N postings** 或 **Retry N postings**）会保持禁用状态，直到您输入与受影响金额完全一致的数值。

<Aside type="caution">
输入金额是一项**安全提示，而不是审批步骤**。它本身不授权任何操作：无论是否超过阈值，都适用相同的权限检查，您输入的任何内容都不会发送到 ERP，也不会被记录为审批。它的作用是让您在批量写入发出之前审视其影响范围。
</Aside>

### 重试仅针对您勾选的过账运行

清除模拟过账可以针对任一种选择方式运行：勾选的行或与筛选器匹配的所有内容。而批量重试则不行：**它只会针对您逐一勾选的过账运行。** 按筛选器进行的选择没有固定的过账列表来约束重试，因此重试时会要求您将过账粘贴回来，并且除非粘贴的内容与预览所示完全一致（相同的过账、无重复、数量相同），否则会拒绝继续。正是这种绑定确保了确认的真实性：您确认的批次就是实际发送的批次。

### 可以重试的内容

只有被 ERP 拒绝或从未发送的过账才可以重试。仍在处理中、状态不明或已过账的过账无法在此处重试。

如果连接的 ERP 支持，PlaidCloud 会在重试之前直接询问 ERP：如果 ERP 已将该单据记录为已过账，则拒绝重试并建议改为冲销。如果 ERP 无法响应该检查，则拒绝重试而不是冒险执行，它从不猜测。少数连接完全不支持此检查；对于这些连接，重试依赖于过账自身记录的拒绝信息。

重试需要 `erp.register.operate`，**并且**需要您本人对该过账所属连接的个人授权，即[可见性规则](#可见性规则)要求的、查看该过账本身所需的同一连接授权。

### 从详细信息抽屉中重试

过账的详细信息抽屉中也有自己的**重试**按钮，位于关注控件旁边。这是同一个重试操作，每次处理一行，无需经过网格即可使用。它并非一键完成：打开后会显示相同的[影响预览](#影响预览)，并且在超过阈值时显示与批量操作相同的输入确认，只有一条重试路径，可从两个位置进入。对于持有 `erp.register.operate` 的成员，该按钮会在每一行上显示；抽屉在提供重试之前不会预先判断某一行是否可重试，因此最终不符合条件的行（已过账、正在处理中，或 ERP 已持有的过账）会由预览以服务器自身给出的原因拒绝，而不是被默默隐藏。

### 清除模拟过账

清除是一种软删除：PlaidCloud 会记录清除者和清除时间，并要求在启用按钮之前填写原因。它会将过账从模拟预览存储以及分类账自身的模拟日记账中移除，永远不会触及实时过账，也无法将其指向实时过账。

### 模拟过账视图

**模拟**以窗格形式从导航栏打开，列出模拟存储中的内容，而无需您在主网格中查找模拟行。可以按连接、项目、环境或模拟运行 ID 进行筛选。

- **包括已清除**是标题区中的一个切换开关，默认关闭，与服务器自身的默认值一致：已清除的行是清除操作的审计记录，因此会短暂保留，所以该视图打开时显示的是存储中仍然有效的内容，而不是其自身的历史记录。
- **从此处清除仍需经过与网格上批量操作相同的[影响预览](#影响预览)**，绝不会一键清除，其范围限于视图筛选器当前匹配的内容。
- 该视图的摘要还会报告与[异常队列](#异常队列)相同的 `simulated_excluded` 数字，即过账分类账（与模拟存储是不同的表）中有多少模拟过账被排除在队列之外，因为模拟行从未到达 ERP，因此永远不会成为异常。

## AI 辅助

**辅助**会打开一个全宽的提问框（带有**提问**按钮）、一组洞察卡片以及逐行建议。其中的每个数字都由登记簿本身根据您当前有效的授权计算得出；模型（如已配置）只负责解释或起草，从不编造数字或判定条件。

### 用通俗语言提问

输入一句话，例如“上周 EMEA 连接中状态不明的过账”，它会通过固定的对照表（而不是模型调用）解析为登记簿自身的筛选词汇：解析结果只会缩小网格本来就会显示给您的行，永远不会触及您未获授权的行。模型的唯一作用是用一句话解释解析结果：说明匹配到的字段，以及生成的筛选器在您的行中找到了多少条。

### 主动卡片

七张卡片汇总值得关注的内容，每张卡片都单独显示实时计数和指向相应过账的链接，范围限于您自己的授权：**待关账未结项**、**近似重复**、**公司间净额非零差异**、**与上次关账相比的变化**、**已在 ERP 中确认**、**账龄和负责人**以及**已冲销**。如果为您的工作区配置了 LLM 连接，卡片下方会有一句简短的叙述；如果未配置，卡片仍会完整显示，并说明缺少叙述的原因。卡片上未捕获的金额始终为空白，而不是 `0.00`，与[汇总视图](#汇总视图)遵循的规则相同。

在**所有过账**上，异常情况卡片使用相同的设计，在没有可报告的内容时隐藏。**显示这些**会将网格筛选为卡片所统计的过账，**关闭**则隐藏该卡片。

<Aside type="note">
AI 辅助中的“异常情况”与上述卡片已执行的近似重复和净额为零计算相同，不存在另一个单独评分的异常检测器。
</Aside>

### 逐行建议

选择一笔过账，即可根据其状态获得两种建议，显示在标记为 **Draft — nothing applied** 的卡片中，您可以将其**关闭**：

- **冲销草稿**，适用于任何过账：说明冲销后的结果，包括该连接的驱动程序是否支持冲销、需要对应的控制总计以及期间检查。这只是草稿，此处不会冲销任何内容。
- **失败处理方向**，适用于被拒绝或状态不明的过账：说明失败原因、应该重试还是先修正源数据、需要修正哪个字段，以及点击重试可能导致的重复风险。ERP 自身的错误消息是自由文本，因此会在服务器端将其归类为某个原因，而不是直接显示给您，这与使自由文本不出现在登记簿其他部分的规则相同。

<Aside type="caution">
此面板上没有任何应用按钮。应用冲销需通过详细信息抽屉的**冲销…** 控件（请参阅[冲销](#冲销)）或直接通过 API 完成；应用重试需通过[批量操作](#批量操作)完成。两者都需要 `erp.register.operate`，并且都有各自的确认步骤。
</Aside>

### 每日摘要

**每日摘要**切换开关用于记录您是否希望接收上述卡片的每日摘要，范围限于与关账相关的子集：待关账未结项、账龄和负责人、近似重复、公司间净额非零差异以及已在 ERP 中确认。在您开启之前，它显示为**每日摘要：关闭**，开启之后显示为**每日摘要：已保存偏好，尚未投递**。订阅只存储您的成员 ID。

<Aside type="caution">
**订阅只会记录您的偏好，目前还不会发送任何内容。**[计划导出和警报](#计划投递)会自动触发，但摘要是一个单独的机制，尚未连接任何投递渠道，因此没有每晚或定期的摘要电子邮件。请将订阅视为记录您在发送机制推出后的意向，而不是开启了发送功能。
</Aside>

## 冲销

冲销过账（即在 ERP 中创建一张新的、方向相反的单据）可通过详细信息抽屉的**冲销…** 控件完成，该控件会打开**冲销过账**对话框；也可以直接通过 API 实现自动化。

- **资格**取决于过账自身的状态（只有带有已确认 ERP 单据 ID 的已过账分录才能冲销）、连接的驱动程序（Business Central、Oracle Fusion 和 Acumatica 完全不支持以编程方式冲销，尝试时会加以说明），以及该过账上是否已有未完成的冲销尝试。抽屉会在您打开冲销时以及在您提交前的一刻再次检查资格，因此在此期间已过时的行（例如已有另一个冲销未完成）会以驱动程序自身的措辞显示其拒绝原因，而不会发出注定失败的请求。
- **冲销**需要 `erp.register.operate`，并受输入确认的约束：您需要重新输入该过账自身的 ERP 单据 ID（仅在浏览器中检查，从不发送），对话框的**冲销过账**按钮才会解锁。这与[批量操作](#批量操作)使用的影响范围模式相同，是一项安全提示而不是审批步骤。
- 冲销时可以选择将新分录重定向到与原过账不同的目标期间：对于 ERP 接受显式过账期间的适配器，会遵循该设置；对于无法指定期间的适配器，会以明确的错误拒绝。**重定向后仍可能落入与请求不同的期间：** 某些适配器只有在分派之后才知道是否遵循了该设置，因此抽屉只有在尝试实际以已冲销状态结清后才会显示落入的期间，绝不会更早显示，对于其他所有结果则以服务器自身的消息为准。一个硬性的数据库锁存可确保在有冲销尝试未完成时，绝不会分派第二次冲销尝试，即使在分派过程中进程崩溃也是如此；ERP 拒绝会自动释放该锁存，因为没有创建任何内容。
- **无论从何处发起，每次只能进行一个冲销。** 从过账登记簿发送的冲销与由工作流或项目级冲销 API 发送的冲销共享同一个锁存，并且每个冲销在持有锁存后都会重新读取过账，因此一笔过账永远不会被冲销两次，无论是因为重新运行还是因为同时发出两个请求。
- **未知的答复会被挂起，而不是猜测。** 当 ERP 超时、返回服务器错误或以 PlaidCloud 无法识别的方式答复时，冲销会被记录为 `in_doubt` 而不是被拒绝，并且锁存保持持有状态。只有当冲销单据与原单据镜像对应（实体和货币相同、日期不早于原单据、每一行的借方和贷方互换）时，才会被视为该冲销；其他任何情况都会保持状态不明，由您进行核查。
- **处于 `pending` 或 `in_doubt` 状态的冲销**（其结果未知）会保持该状态，直到被结清。对于 Workday 和 Dynamics 365 Finance & Operations，PlaidCloud 会在下次尝试冲销该过账时在 ERP 中查找 `in_doubt` 冲销，并根据查找结果将其结清。这些连接上的 `pending` 冲销以及其他所有连接上任何未结清的冲销，需使用抽屉的处理控件进行清除，这些控件除了需要 `.operate` 外还需要 `erp.register.approve`：由人员直接核查 ERP 并记录核查结果，即**释放**（ERP 中未创建任何内容，因此分类账保持不变，该过账可再次冲销）或**标记为已冲销**（存在冲销单据，并附上其 ID）。这是清除该锁存的唯一方式。将冲销标记为 `confirmed` 是永久性的，在产品中无法撤消。

### 职责分离

达到或超过租户所配置阈值的冲销需要先获得审批才能继续。审批是由审批人执行的操作，而不是由提交人在请求中提供的一个名字。

- **制单人≠复核人。** 提交冲销的成员不能同时担任其审批人，也不能担任自己的紧急授权人。
- **按绝对值衡量。** 阈值比较的是冲销的大小，而不考虑正负号：冲销贷方与冲销借方的衡量方式相同。
- **近期的冲销会计入阈值。** 滚动时间窗口会汇总提交人自己在同一连接上的冲销，因此无法将一笔大额冲销拆分为若干笔小额冲销以保持在阈值以下。金额按绝对值相加，而不是相互抵消：一笔负数冲销和一笔正数冲销不会相互抵消。
- **失败时关闭。** 如果窗口内的某笔先前冲销无法验证（例如金额或货币未捕获），则该冲销需要审批，而不是跳过检查。
- **审批人必须具备资格。** 他们需要持有 `erp.register.approve`（或来自持有者的有效委派），以及他们本人对所冲销连接的授权。如果同时具备这两项条件的成员少于两名，则达到或超过阈值的冲销会被拒绝，而不是放行。
- **紧急授权**仍然是提交人直接指定谁授权了覆盖操作的唯一途径：适用于真正的紧急情况，由独立于业务链之外的授权人决定，该授权人持有 `erp.register.admin` 但不持有 `.operate` 或 `.approve`，并持有其本人对该连接的授权。每次覆盖都会被永久记录到审计跟踪中。
- **拒绝时不说明原因。** 无论请求是没有合格的审批人、由错误的人决定，还是从未发起，冲销都会以相同的消息被拒绝。这是有意为之，以免通过拒绝信息推断出谁持有哪个角色或授权。实际原因记录在审计跟踪中，而不在错误信息中。
- **运行冲销需要每个分项分别审批，而不是整个运行一次审批。** 一次性冲销整个[公司间运行](#公司间运行)不会获得单一的运行级审批，每个分项都需要各自的审批，因为一项审批绑定到一笔过账、一个连接以及在该连接上持有授权的一名审批人，不存在可以绑定整个运行所有分项的单一名字。
- **冲销需通过登记簿进行。** 启用职责分离后，通过项目级 ERP 冲销 API（项目、用户定义函数或服务账户使用的路径）请求的冲销会在任何内容到达 ERP 之前被拒绝，并提示改为从过账登记簿进行冲销。登记簿中没有捕获详细信息的分录也无法在登记簿中冲销，必须在 ERP 中更正。过账不受影响，Business Central、Oracle Fusion 和 Acumatica 仍会给出各自的原因，即不支持冲销。

职责分离的启用及其阈值的设置由 PlaidCloud 为您的租户配置，目前还没有控制台开关。

### 审批收件箱

当阈值要求审批时，**冲销过账**对话框中提供的**请求审批**会将冲销路由给在该连接上持有有效个人授权的每位审批人。无需指定收件人，连接授权本身*就是*路由。审批人通过导航栏上的**审批**处理队列，其中有两个可以切换的视图：**Waiting on me**（等待您决定的请求）和 **Submitted by me**（您自己提出的请求）。每一行都会注明分录、金额、实体和期间、请求人及请求时间，并在请求等待时间过长时显示升级标签（**Escalated**、**Escalated twice** 或 **Expired**），因此作出决定时无需离开队列去查找其他信息。

在某一行上选择**拒绝**或**批准**，两者都会要求填写一个原因，并与您的决定一起记录。也可以勾选多行并选择 **Approve selected**。批准后，提示消息会在 8 秒内提供**撤消**。您提交的请求可以通过 **Withdraw** 撤回。当没有需要审批的内容时，屏幕会显示 **All clear**。

审批严格绑定到其所授予的内容，即过账、其连接、所述原因和目标期间，不能用于其他冲销、其他原因或更改后的目标期间；更改后的请求需要重新审批。一笔过账上同一时间只能有一个未结请求，审批在兑现的那一刻即被使用。每次审批之后都有一段短暂的保留期，在此期间审批人或提交人仍可取消；保留期一过，冲销可能已成为 ERP 中的单据，任何操作都无法撤消。在实际应用冲销时，所有内容都会再次检查，包括审批人的角色、双方对该连接的访问权限以及租户的两名审批人最低要求，因此如果审批人在此期间失去访问权限，之前授予的审批将不再有效。

### 委派

审批人可以在**委派**（导航栏）中将其审批权限委派给另一名成员，期限有限。其中有两张卡片，分别列出**您委派的**和**委派给您的**，适用于审批人将无法处理但仍有冲销需要决定的情况。选择 **Delegate approvals** 打开 **Delegate approvals** 对话框，选择**成员**，设置**天**数，并填写**原因**；原因会记录在审计跟踪中，**撤销**可提前结束委派。不持有审批权限的成员看到的是一条提示，而不是该按钮。授予委派需要 `erp.register.approve`；使用委派、查看您自己的委派以及交还委派只需要 `.operate`，因为典型的被委派人根本不持有审批人角色，这正是向其委派的意义所在。

自我委派会被拒绝，相互委派（委派给已经委派给您的人）或任何更长的委派链也会被拒绝。这些都不会生效，因此两名成员无法直接或通过中间环节悄悄地让彼此的决定同时代表双方。制单人≠复核人原则在委派中依然适用：被委派人不能审批委派人提出的请求，在任何情况下也不能审批自己的请求。被委派人作出的每个决定都会在审计跟踪中记录为在委派审批人的权限下作出，而不是记录为被委派人本身持有该角色。

### 升级

长时间未作决定的审批会触发警报，因此不会在无人关注的队列中默默超龄。每个收件人只会收到关于其本人实际可以决定的请求的通知：同事的升级电子邮件绝不会提及路由给其他人授权的请求，并且警报不包含金额和自由文本，这与登记簿其他通知遵循的最小化原则相同。

## 公司间运行

公司间运行是为一次关账而一起生成的一组过账（即其**分项**），由当时标记在过账上的**关账日期和序号**标识，而绝不由生成这些过账的工作流运行标识。（该工作流运行 ID 单独保存在分类账自身的历史记录中，其存在时间可能比过账的关账标记更长，因此不是识别运行的可靠方式。）您可以列出运行，打开某个运行查看其分项的核对和配对情况，并将整个运行作为单个受控操作进行冲销。

目前只能通过 API 访问：`GET /erp/register/runs`、`GET /erp/register/runs/{run_day}/{sequence}` 和 `POST /erp/register/runs/{run_day}/{sequence}/reverse`，尚无控制台屏幕。

<Aside type="caution">
**目前还没有任何运行带有运行数据。** 在生成过账时为其标记关账日期和序号的步骤尚未发布，仍在等待财务决定，因此目前这些端点会如实报告**零个运行**。您看到的是已存在但早于该标记的过账计数（`legacy_run_rows`），以及既没有关账标记也没有旧版工作流运行 ID 的过账的单独计数（`unattributed_rows`）。此处列表为空表示该功能完全按设计正常工作，而不是出现了故障。
</Aside>

### 净额为零与配对

打开一个运行后，其分项会以两种方式进行核对，两者的范围都限于您个人获得授权的连接，与登记簿中其他地方的[可见性规则](#可见性规则)相同，因此对于跨越您只能部分看到的连接的运行，会报告为部分可见，而不是不平衡。

- **净额为零**，按货币计算：给出**均衡**、**不平衡**或**不确定**的结论，并细分列出每项净额背后的实体。只有当某种货币中的每个分项都已捕获时，该货币才会进行核对；只要有一个分项未捕获，整个货币就会被判定为**不确定**，绝不会只根据碰巧测得的部分计算净额。
- **配对**根据过账工作流在提交之前标记到双方的配对键，将每个应付分项与其对应的应收分项相匹配。匹配的配对在一种货币中净额为零；其他所有情况都会附带一个明确的原因：您看不到对方分项、金额未捕获、净额确实不为零，或者是**跨货币**。跨货币情况会被报告但从不核对，因为平台中的任何地方都没有外汇汇率。

分项超过 200 个的运行过大，无法在一次响应中完成核对或配对：两者都会返回**不确定**，而不是基于截断的运行片段进行计算，因此大型运行绝不会仅因其规模而报告虚假的平衡或虚假的对方分项缺失。

### 冲销运行

通过 `POST /erp/register/runs/{run_day}/{sequence}/reverse` 一次性冲销运行的每个分项。

- **预先检查每个分项的资格。** 任何可以预先知道的情况（状态、适配器支持、未完成的尝试、您本人的连接授权）都会在任何请求到达 ERP 之前拒绝整个运行。
- **无法预先知道的情况会在事后按分项报告。** ERP 的实时状态和授权状态可能在运行过程中发生变化，因此即使预检时一切正常，运行也可能以**部分冲销**结束。不会进行任何自动补偿：为撤销部分失败而过账更多单据，比失败的那次写入风险更大。部分完成的运行需逐个分项进行补救，方式与单笔冲销相同。
- **重新运行运行冲销即可完成部分冲销的运行。** 先前尝试已冲销的分项会被跳过而不是被拒绝，因此再次尝试只会冲销实际剩余的分项。
- **职责分离按分项适用，而不是按运行总额适用。** 当租户的职责分离策略生效时，每个分项都需要各自的审批，运行才会分派任何内容，无论金额多少，而不仅限于超过阈值的情况。这是有意采取的保守做法：分项自身的要求只能在分派时才能确定（滚动的防拆分窗口会在运行自身的分项冲销时将其计入，而 ERP 的实时回读可能失败），因此预先要求所有审批，才能防止运行在冲销了一半分项之后才发现其余分项也需要审批。
- **批量操作可通过一次调用覆盖整个运行。**`POST /erp/register/runs/{run_day}/{sequence}/approval-requests` 为提交人可以处理的每个分项发起审批请求，`POST .../approval-decisions` 则对审批人有资格处理的每个分项作出决定。每项各只需一次调用，而不必为每个分项分别发起请求和作出决定（对于常规的 10 个分项的运行需要 20 次调用）。底层的安全模型保持不变：每个分项仍有各自的审批，绑定到该过账、其连接、原因和目标期间，审批人仍需对每个分项的连接拥有本人的访问权限。审批人无权授权的分项只会保持待处理状态，等待有权处理的人，绝不会被一并处理。完全没有审批权限的调用者会被直接拒绝，且无法得知哪些分项有未结请求。结果按分项返回，因此可部分授权的运行会准确报告哪些分项已作出决定、哪些仍待处理及其原因。
- **运行冲销不提供紧急授权。** 紧急授权是针对单笔过账的双人覆盖操作，将一名见证人的授权应用于整个运行，会使其效力按运行的分项数成倍放大。请改为通过 `POST /entries/{ledger_id}/reverse` 按分项使用紧急授权。
- **分项超过 200 个的运行无法作为单个操作冲销。** 请改为从分录列表中分批冲销。

## 趋势

**趋势**以磁贴形式显示按连接或 ERP 类型分组的失败率和延迟，以及冲销原因代码的分布。每个数字（包括每个分母）都根据您当前有效的授权计算。在时间窗口内没有任何终态过账的连接，其失败率显示为长破折号，而不是 `0%`，因为完美的零会把一个无人使用的连接排在健康列表的最前面。延迟是基于最近的终态过账的有限样本，并标注为样本，而不是表现为覆盖了整个时间窗口。冲销原因仅以其结构化代码显示，用户输入的自由文本原因绝不会在此处归类或显示。

## 谱系

**谱系**可从一笔过账追溯到生成它的工作流运行，并向外延伸到 ERP 中的单据本身。在标题区中输入运行 ID 或过账的分类账 ID 并进行追溯。按分类账 ID 查询时，会先通过您自己的授权解析运行，因此您无法查看的连接上的过账不会解析出任何结果，而不会暴露它来自哪个运行。如果 PlaidCloud 能够验证该适配器的 ERP 单据 URL 格式，谱系会包含直接指向该单据的深层链接；如果无法验证，或者该过账从未得到确认，则会说明是哪种原因，而不会猜测链接。ERP 的业务键仍然绝不会出现在此处：谱系键是工作流的 `run_id`，ERP 指针是 `confirmation_id`，与登记簿中其他地方相同。

## 关账

**请求关账**可将某个期间（针对一个或多个连接和实体）封存为一个不可变的时点快照：截至该时刻登记簿所掌握的关于这些过账的所有信息，即使之后实时行被重试、冲销或清除，也会保留。它适用于已锁定的会计期间，此时您需要一份有据可查、不会更改的记录，而不是实时网格当前显示的内容。目前只能通过 API 请求或读取关账，尚无用于请求或浏览关账的控制台屏幕。

请求关账（`erp.register.operate`）是一项租户范围的管理操作，而不是个人操作：您指定的连接和实体会被如实封存，与您自己的连接授权无关。对已关账的期间再次关账绝不会造成破坏：它总是生成一个新的、单独编号的修订版，而不是覆盖上一个修订版。

<Aside type="note">
**关账会自动生成。** 请求关账并不会立即将其封存：后台作业每天按计划自动扫描每个待处理的关账，并写入其 Iceberg 快照，无需您执行任何进一步操作。如果某个关账的扫描无法完成（例如仓库中断），该关账会被标记为失败而不是一直卡住，并会在第二天的扫描中被自动拾取并重试，绝不会被默默跳过。异常大的关账（涉及超过大约 500,000 笔过账）是唯一无法以这种方式自行解决的情况：扫描会拒绝一次性将其封存，需要 PlaidCloud 协助分批完成关账。对于大多数报告期间而言，这是一种罕见的极端情况。
</Aside>

关账生成后，读取时会应用登记簿的常规规则，并在每次读取时实时重新解析，而不是在封存时固化到快照中：您只能看到您当前获得授权的连接和项目上的行。实时网格会向任何能够看到该行的查看者显示金额和制单人身份，而关账中的数字则会被掩码，除非您持有 `erp.register.admin`，这与[导出](#导出)适用的规则相同。关账还会报告其自身的**迟到计数**：在关账的高水位标记之后提交或更改、因此未被封存捕获的过账。这些过账只能通过为同一期间请求新的关账才能看到，因为任何操作都不会重新打开旧的关账。

## 导出

**导出和警报**是登记簿以文件或通知形式离开控制台的地方，也是唯一一处 PlaidCloud 的控制在数据离开后即不再适用的界面。生成导出或计划投递需要 `erp.register.operate`；打开登记簿查看则不需要。

### 立即下载

将当前查看的登记簿导出为适合 Excel 使用的 CSV 或 JSON，在您当前有效的授权下全新生成。根据您的角色，适用两种掩码配置：

- **`erp.register.operate`** 获得标准的掩码配置：金额和制单人身份会被隐去。
- **`erp.register.admin`** 获得审计员配置，这是唯一一个不对金额和制单人身份进行掩码的配置。

每次导出都遵循与登记簿其他部分相同的规则：`natural_key` 绝不会出现，自由文本字段（评论、维度和工作标签值）会被完全排除而不仅仅是清理，未捕获的金额为空白，并与被掩码的金额加以区分，因此当空白实际表示“您的角色无法看到此内容”时，不会被误读为“没有过账任何内容”。

### 计划投递

选择 **New schedule** 打开一个对话框，其中包含**名称**、**类型**、**格式**、**频率**、**收件人**，以及可选的用于缩小范围的**连接**和**实体**。收件人为 PlaidCloud 成员。提供两种类型：

- **导出文件**：按**每天**、**每周**或**每月**的频率定期投递经过筛选的登记簿 CSV 或 JSON 文件，或仅**按需**投递。
- **警报**：在 **A live posting fails**、**An authorization is aging** 或 **A reversal is posted** 时发送通知。

<Aside type="note">
**计划的频率会自动触发。** 每个租户的一个作业每天检查一次所有计划，并发送自上次发送以来间隔已到的任何 `daily`、`weekly` 或 `monthly` 计划，其发送路径与**立即发送**相同，因此计划只有一种投递方式。**按需**计划在设计上永远不会被该扫描拾取，它们仅用于**立即发送**。
</Aside>

每个收件人的文件都是在发送时根据*其本人*当前有效的授权生成的，而不是根据计划所有者的授权，因此同一计划的两个收件人可能收到两份不同的文件。如果某个收件人此后失去了导出角色、失去了所有连接授权、已被禁用或没有登记地址，则会单独跳过该收件人并说明原因，而不会被默默略过。只有计划的所有者或持有 `erp.register.admin` 的成员才能删除或触发他人的计划。

<Aside type="note">
**投递之后发生的事情不受任何约束。** 下载或通过电子邮件发送的文件可能会被转发、打印或存档到租户之外，之后撤销任何 ACL 都无法触及它。控制台会如实说明这一点，而不是假装可以控制，这也是导出受到如此严格的控制和掩码的原因。
</Aside>

### 保留

**保留**位于导航栏的**设置**下，是一张卡片，您可以在其中设置登记簿保留三类历史记录的时长：**捕获（边车请求/响应）**、**模拟存储**和**写入审计跟踪**。每项都是一个天数或**无限制**，在租户范围内设置，需要 `erp.register.admin`；**保存**会应用这些设置，并以提示消息确认。卡片会显示上次设置该策略的人员和时间。每次保存都会写入所有字段；未配置的租户会保留所有内容。

<Aside type="caution">
保留永远无法作用于过账分类账本身：删除分类账行会释放用于防止单据重复过账的幂等键，因此有意没有可设置的分类账期限。编辑删除所捕获的负载详细信息时，过账自身的记录、状态和上下文列保持不变，只会删除敏感的详细信息。
</Aside>

执行此策略的保留扫描每天在租户范围内自动运行一次。它使用相同的周期性作业机制，该机制还负责驱动[计划导出和警报](#计划投递)、将逾期过账转入异常队列，以及使旧的模拟过账过期。

## 汇总视图

**汇总**以窗格形式从导航栏打开。按**运行**、**期间**或**连接**对登记簿进行分组，即可查看小计和状态汇总，而不是单独的行。分组方式由标题区中的**分组依据**控件设置，因此可以原位切换，无需重新打开任何内容。顶部的磁贴汇总过账及其状态，金额按货币显示，另有一张卡片列出冲销原因。

- **空白金额保持空白。** 没有捕获金额的过账（所有 SAP 过账、生成时即为终态的过账，或在此功能推出之前写入的过账）不会计入小计，也绝不会显示为 `0.00`。每个分组都会用文字说明其中的过账是全部已捕获、部分未捕获还是全部未捕获。
- **不同货币绝不会混入同一个总计。** PlaidCloud 不进行外汇换算，因此跨越多种货币的分组会为每种货币各显示一行，而不是显示一个混合的数字。请参阅[金额格式](#金额格式)。
- **达到上限的分组列表仍能正确汇总。** 如果分组产生的组数超过视图可显示的数量，总计行仍会涵盖所有分组，而不仅是显示的分组，并会加以说明。

[连接健康状况](#连接健康状况)标签也会显示在此视图中。

## 控制总计

**控制总计**以窗格形式从导航栏打开，涵盖[可见性规则](#可见性规则)已为您限定的相同连接和实体。顶部的磁贴统计**均衡**、**不平衡**和**不确定**的批次数、扫描的行数以及出现偏差的单据数；标题区中的**容差**控件用于设置仍被视为均衡的最大差额。磁贴下方会将过账分组为批次，并为每个批次给出三态结论（**均衡**、**不平衡**或**不确定**），同时附上服务器自身说明的原因，而绝不只是一个单词。

- **不确定是一个真实的答案，而不是勉强通过。** 只有当批次中的每一行都已测量且其各组相符时，该批次才为均衡。空的时间窗口、未捕获的金额、发出即不管的适配器，或者在读取整个批次之前被中断的扫描，都会返回不确定，并详细说明原因，绝不会默认显示为绿色。
- **金额为空白，而不是零。** 只要金额未被捕获或确认，分组的来源总计、已过账总计及其差额就为空白，与[汇总视图](#汇总视图)遵循的规则相同，因为编造的 `0.00` 会低估未测量的批次，却又看起来像权威数字。
- **分组按货币和实体划分，绝不相加。** PlaidCloud 不进行外汇换算，因此跨越多种货币或实体的批次会并排列出每个分组各自的总计，而不是将其混合。有关这些数字如何呈现，请参阅[金额格式](#金额格式)。
- **早于捕获功能的行有自己的 `(no batch id)` 存储桶。** 在批次捕获功能推出之前写入的过账无法被重新归入一个从未包含它的批次，因此会单独显示为一行，而不会被并入或丢弃。

同一读取还涵盖两个相关问题：**期间结账就绪状态**，按实体和期间计算，对于平台尚无数据的存储桶（例如切换期关账时早于捕获功能的行），会降级为不确定，而不是错误地显示为已阻止；以及**确认偏差**，按单据而不是按分组报告，因为同一货币/实体分组中两张朝相反方向偏差的单据可能在总计上相符，从而掩盖两者的偏差。

## 详细信息抽屉

详细信息抽屉**停靠在工作区右侧**，因此在阅读一笔过账时列表仍然可见。可以通过行的**放大镜**图标、在所选行上按 **Enter** 或**双击**该行来打开它。

抽屉顶部显示过账的状态标签，并附有一句说明该状态含义的话，然后是一张关于该过账的事实卡片，包括连接、实体、环境、ERP 单据和过账日期，均以名称而不是内部 ID 显示。如果过账失败，原因显示在选项卡上方。**重试**和**冲销…** 位于底部，供具有操作权限的成员使用；**关注连接**和**关注运行**在开启后会切换为**正在关注连接**和**正在关注运行**。**Copy link** 会复制一个直接打开此过账的链接。

其余内容分布在三个选项卡中：

| 选项卡 | 显示内容 |
|---|---|
| 行 | 过账的日记账，即按会计人员的阅读方式呈现的借方和贷方行（请参阅[日记账选项卡](#日记账选项卡)），以及发送到 ERP 的请求及其响应，已按数据最小化原则进行筛选（见下文）。 |
| 历史记录 | 过账从提交到当前状态的各个状态，按顺序排列；如果存在冲销，则显示相互链接的原过账及其冲销；以及此过账活动的只读记录，目前内容较少，请参阅[审计选项卡](#审计选项卡)。 |
| 签核 | **标记为已审核**和**标记为已清除**、过账当前的审核状态（已审核、已清除或需要跟进）及其完整历史记录，以及分线程的评论。请参阅[协作](#协作)。 |

## 日记账选项卡

**日记账**选项卡以会计人员的方式呈现一笔过账：按科目列出其借方和贷方行，而不是原始请求负载。

- **只显示每个 ERP 实际捕获的列。** 该选项卡只显示特定系统发送的字段：Acumatica 过账会显示其子科目，而从不发送子科目的系统则完全不会显示空的子科目列，因此无需浏览永远不会有内容的列。
- **维度和工作标签位于每一行下方。** 行的分析详细信息（其维度或 Workday 工作标签）显示在所属行的下方，而不是挤在顶部的额外列中。
- **按货币计算合计并进行精确的平衡检查。** 每种货币单独合计；检查绝不会混合货币，也绝不会将不平衡的过账舍入为零，因此真实的不平衡会如实显示其数字，而不会消失在 `0.00` 中。
- **不捕获行详细信息的适配器会加以说明。** 如果某个驱动程序（例如本地部署的 SAP）不记录按行细分的信息，该选项卡会明确说明这一点，而不是显示一个可能被误读为“没有行”的空网格。

<Aside type="note">
维度和工作标签**仅在控制台中向获得许可的查看者**显示在日记账选项卡上。它们绝不会包含在[导出](#导出)、摘要或[评论](#协作)中，这与防止分析性和自由文本详细信息离开控制台的[数据最小化](#数据最小化)规则相同。
</Aside>

## 键盘分类处理

在[异常队列](#异常队列)中，上下箭头键可以从一笔过账移到下一笔，**详细信息抽屉会跟随**所选内容，因此您可以完全通过键盘完成一轮分类处理，依次阅读每笔过账的详细信息，而无需使用鼠标。

在任何列表上，按 **/** 都会跳转到筛选框。主网格则有意保留鼠标选择、**Enter** 和双击：其多行选择用于驱动重试和清除模拟过账等[批量操作](#批量操作)，因此在主网格中箭头键用于移动所选内容，而不是让抽屉逐行切换。

## 协作

无需离开登记簿即可与团队协作处理过账：使用 @提及对其发表**评论**、记录**签核**，或**关注**某个连接或运行以了解其后续活动。

- **评论**是针对一笔过账的分线程纯文本备注，可在其签核选项卡中添加。通过成员 ID @提及同事即可通知对方，前提是对方当前能够看到该过账；该检查会在发送时重新执行，而绝不会根据被提及者进行推断。
- **签核**记录三种状态之一（已审核、已清除或需要跟进），可附带备注，并保留谁在何时设置了什么的完整历史记录。它只是一项记录而不是关卡：目前不会根据签核状态阻止任何过账或冲销。
- **关注**某个连接或运行（**关注连接**和**关注运行**，抽屉中两个独立的切换开关），以便今后在其中任一方有活动时收到通知。导航栏上的**我的关注**列出您正在关注的内容，并提供**停止关注**以及用于添加关注的**关注连接**。

发布评论、签核或关注需要 `erp.register.view` 和 `.operate`；读取它们只需要 `.view`。

<Aside type="note">
**通知中绝不包含金额。** 评论或关注警报会注明过账的实体并链接回该过账，但绝不包含金额、货币或您或其他任何人输入的任何自由文本，因此通知永远不会超出在抽屉中查看实际数字所需的角色权限。并且通知自身的可见性检查与登记簿完全相同：对于您不再获得授权的连接或项目，提及或关注会被默默地从投递中删除，就像撤销授权会使某一行从网格中消失一样。
</Aside>

## 数据最小化

登记簿的设计目标是显示审核人员确认过账已发生所需的信息，而不暴露过账步骤为完成过账而处理的敏感数据。

- **请求和响应负载按适配器设置允许列表。** 只有被明确归类为可安全保留的字段才会显示。银行账号、路由号码、IBAN、税号和其他个人标识符会在您看到负载之前被删除。
- **ERP 业务键被完全隐去。** 它可能嵌有供应商名称或其他参考标记，因此绝不会进入登记簿，包括 [AI 辅助](#ai-辅助)：决定您能看到什么的同一允许列表，也决定模型提示可以看到什么，负载中任何位置的自然键值都会被直接拒绝而不会发送。请通过分类账 ID 识别行，并使用 `confirmation_id` 作为 ERP 自身指向单据的指针，即 [ERP 过账历史记录](/zh-cn/guides/connections/erp-post-history/#每次过账显示的内容)中称为 `confirmation_id` 的同一字段。
- **自由文本字段在读取时按模式清理**，并且会从摘要、任何 AI 模型提示和任何[导出](#导出)中被完全排除，而不仅仅是清理。模式清理可以识别 IBAN 或税号之类的格式，但无法识别输入在备忘录中的供应商名称，因此任何以文件形式离开控制台的内容都会完全删除这些字段，而不是仅依赖清理。

<Aside type="note">
**空白金额是一种标示，而不是缺失。** 在此功能推出之前捕获的过账没有可显示的金额详细信息。SAP 过账从不包含捕获的金额，登记簿会为这些行显示“no amount captured (by design)”。这两种情况都不是错误，也都不应被理解为零。
</Aside>

### 审计选项卡

审计选项卡仅用于显示。由于底层审计词汇尚未完成分类，其详细信息在此版本中有意保持精简。预计随着这项工作的推进，内容会逐步充实，但不会改变您阅读抽屉其他部分的方式。

本页介绍的其他所有功能，包括异常队列、连接健康状况、汇总视图、批量操作、单行重试、冲销、控制总计、AI 辅助、趋势、谱系、关账、协作和导出，目前均已可用。
