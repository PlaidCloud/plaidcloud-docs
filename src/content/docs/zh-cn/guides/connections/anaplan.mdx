将 PlaidCloud 连接到 **Anaplan**，工作流即可通过 Anaplan 的大容量读取请求路径读取已保存的视图、运行现有的导出操作，或将一个或多个 Anaplan 列表读入 PlaidCloud 维度。该连接以**云端直连**方式访问 Anaplan 自身的 Integration API，这些步骤不提供本地代理路径。本指南涵盖连接、身份验证、三个读取步骤的简要介绍，以及计划注意事项。

<Aside type="note">
此连接器为只读。不会向 Anaplan 回写任何内容——没有回写步骤，也没有部分应用模式。
</Aside>

## 前提条件

您需要向 Anaplan 工作区管理员获取以下内容：

- Anaplan **用户名和密码**，或由 Anaplan 工作区管理员注册到某个 Anaplan 用户的 **CA 证书及其私钥**——该用户需对工作流将要读取的工作区和模型具有读取权限。请参阅下文的[身份验证](#身份验证)。
- 要读取的模型的**工作区 ID** 和**模型 ID**，可在 Anaplan 自身的模型设置中查看。创建连接后，也可以通过该连接实时发现这两项。
- 对于 **Anaplan：读取视图**——一个**已保存的视图**，其行、列和筛选器切片须与所需完全一致。请参阅下文的 [Anaplan：读取视图](#anaplan读取视图)。
- 对于 **Anaplan：读取导出**——模型中**已存在的导出操作**。
- 对于 **Anaplan：读取列表**——构成所需层次结构的 Anaplan **列表**。

## 身份验证

连接包含一个**身份验证模式**：**基本**（默认）或 **Certificate**。现有连接继续以“基本”模式正常工作，无需更改。

- **基本**使用 Anaplan 用户名和密码登录。
- **Certificate** 使用 CA 颁发的证书及其私钥登录，两者均以 PEM 文本粘贴。私钥必须是 **RSA 且未加密**，证书必须是 Anaplan 工作区管理员已注册到您的 Anaplan 用户的证书，并由 Anaplan 对您的租户信任的 CA 颁发。PlaidCloud 使用该密钥对随机质询签名，并按照 Anaplan 自身的证书身份验证流程将其换成 Anaplan 令牌；粘贴证书和密钥后无需其他操作，令牌刷新方式与“基本”模式相同。两个字段都会遮盖粘贴的内容，两项机密均与“基本”模式的密码一样加密存储；切换模式时不会发送另一种模式的凭据——如果将现有连接从“基本”切换为 Certificate，需要重新粘贴证书和密钥，因为它们不会被沿用。

Anaplan 的多重身份验证适用于使用电子邮件和密码登录的用户。对于自动化的计划连接，证书身份验证是无需密码的选项。

在 Certificate 模式下，如果粘贴的密钥或证书无法读取、密钥已加密或不是 RSA，或者密钥与证书不匹配，系统会在联系 Anaplan 之前拒绝。如果是 Anaplan 本身拒绝了证书，错误信息会说明证书是否已过期；常见原因是证书未注册到某个 Anaplan 用户，或 CA 不受您的租户信任。

## 创建连接

<Steps>

1. 打开 **Tools > Connections** 并点击 `New Connection`。

2. 从菜单中选择 **Anaplan**。

3. 填写字段：

   | 字段 | 值 |
   |---|---|
   | Name | 易于识别的名称，例如 `Anaplan Prod`。 |
   | API 主机 | 可选。留空则使用 Anaplan 的标准地址 `https://api.anaplan.com`。 |
   | 身份验证主机 | 可选。留空则使用 Anaplan 的标准地址 `https://auth.anaplan.com`。 |
   | 身份验证模式 | **基本**（默认）或 **Certificate**。请参阅上文的[身份验证](#身份验证)。 |
   | Username | Anaplan 账户用户名。仅限“基本”模式。 |
   | Password | Anaplan 账户密码。仅限“基本”模式。 |
   | CA 证书 | 在 Anaplan 中注册的 X.509 证书的 PEM 文本。仅限 Certificate 模式。 |
   | 私钥 | 证书的 RSA 私钥的 PEM 文本，不加密。仅限 Certificate 模式。 |
   | 默认工作区 ID | 可选。为读取步骤的 Workspace 字段提供便捷的预填值。 |
   | 默认模型 ID | 可选。为读取步骤的 Model 字段提供便捷的预填值。 |
   | Timeout (seconds) | 默认为 30。 |

4. 点击 `Test Connection`。测试成功后，会报告凭据所对应的 Anaplan 账户电子邮件地址。

5. 点击 `Create`。

</Steps>

## Anaplan：读取视图

添加 **Anaplan：读取视图**步骤，通过 Anaplan 的大容量读取请求路径读取已保存的视图。**视图将完全按其在 Anaplan 中保存时的样子读取——此步骤不提供行、列或页面选择。** 若要读取不同的切片，请在 Anaplan 中构建另一个已保存的视图；通常的做法是使用布尔型明细项加已保存的视图在 Anaplan 中进行筛选。仅当视图将**明细项放在列轴上**时，数据列才会以其声明的 Anaplan 类型加载；若明细项位于行上（普通的损益表布局）或视图中没有明细项，则所有列都以文本加载，并且该步骤会予以说明。筛选器没有匹配任何内容的视图会加载为空表并给出警告。如果某个数值型值无法被该步骤明确解析——最常见的情况是它既可能是普通小数，也可能是欧式格式——则会拒绝而不是猜测，除非同一列中的其他值能确定正确的解读方式；能够解析的值会以完整精度加载，不会有舍入误差。有关完整的字段和行为参考，请参阅 [Anaplan：读取视图](/zh-cn/reference/workflow-steps/anaplan/anaplan-read-view/)。

## Anaplan：读取导出

添加 **Anaplan：读取导出**步骤，运行**现有的** Anaplan 导出操作并加载其生成的文件。API 无法创建导出操作——请先在 Anaplan 中构建或编辑——并且该步骤无法缩小导出的内容：Anaplan 中导出操作配置为导出什么，加载的就是什么。**所有列都以文本加载。** 数字按美国格式请求；如果某列返回时仍带有千位分隔符，则原样以文本加载，并给出具名警告，而不是使运行失败。当导出失败、被取消、未产生数据、在该步骤的轮询预算用尽后仍在运行，或者生成的文件无法与该导出对应、或其行数与 Anaplan 自身报告的不一致时，该步骤会停止，而不加载表。有关完整参考，请参阅 [Anaplan：读取导出](/zh-cn/reference/workflow-steps/anaplan/anaplan-read-export/)。

## Anaplan：读取列表

添加 **Anaplan：读取列表**步骤，将一个或多个 Anaplan 列表读入 PlaidCloud 维度。**一个步骤即可读取整个复合层次结构**——按从根开始的顺序列出它涉及的所有列表（例如先 Region，再 Country，再 Store），而不要拆分到多个步骤中；暂存表在每次运行时都会被替换，因此若多个步骤指向同一个暂存表，每一个都会清除前一个的行。每条边均以普通的 `+` 汇总，因为 Anaplan 的列表层次结构没有可读取的单边权重或符号。Anaplan 的列表访问控制和子集成员关系不会被导入——它们属于元数据，而不是维度数据。节点 ID 重复、无法解析的父级引用、相互冲突的父级引用，以及与导入的元数据冲突的属性名称，都会在加载任何内容之前被拒绝。有关完整参考，请参阅 [Anaplan：读取列表](/zh-cn/reference/workflow-steps/anaplan/anaplan-read-list/)。

## 将 Anaplan 作为 Data Foundation 的数据源

[Data Foundation](/zh-cn/guides/projects/data-foundation/) 可以将 Anaplan 中保存的计划（预算、预测或合并模型的结果）读入其 Common Finance Model。它只引入计划，不引入账务，并且仅执行读取。

Data Foundation 会按模型保存时的状态运行其中一个导出操作，因此需要由您的 Anaplan 管理员先构建该导出。**基础数据**选项卡会为他们写好需求。导出必须是扁平网格，每个实体、期间、科目和部门对应一行，并且列标题必须与下面完全一致：

| 列 | 内容 |
|---|---|
| `Entity` | 实体代码。 |
| `Period` | 月份，格式为 `YYYY-MM`。 |
| `Account` | 科目代码。 |
| `Department` | 部门代码，计划中没有部门时留空。 |
| `Currency` | 金额的货币。 |
| `Amount` | 不含千位分隔符的纯数字，符号与计划中保存的一致（收入为正）。 |

然后与其他数据源一样，在**基础数据**选项卡上将该连接添加为数据源（请参阅[连接您的 ERP](/zh-cn/guides/projects/data-foundation/#连接您的-erp)），并选择：

| 设置 | 含义 |
|---|---|
| Export | 要运行的导出操作的 ID。 |
| Scenario | **预算**（默认）、**预测**或 **Consolidated**，用于集团损益表所核对的合并模型结果。 |
| Version | 标记在每一行上的标签。默认为 `Anaplan`。 |
| Entities | 要保留的导出实体。Anaplan 不提供可选择的实体列表，因此需要手动输入；留空则保留所有实体。 |

金额按原样读取，保持自然符号。如果某列返回时仍按千位分隔符分组，则会被标记出来，而不是猜测处理，这与 [Anaplan：读取导出](/zh-cn/reference/workflow-steps/anaplan/anaplan-read-export/)相同。

## 计划注意事项

Anaplan 的请求速率预算是**租户范围内共享**的——由贵组织针对该 Anaplan 租户运行的所有集成共同使用，而不仅仅是 PlaidCloud——并且 PlaidCloud 不会在并发运行之间协调计划。多个 Anaplan 步骤落在同一个 cron 分钟上，可能会在其中任何一个完成之前耗尽该预算。请**错开您的 Anaplan 工作流计划**，而不要让它们同时运行。
