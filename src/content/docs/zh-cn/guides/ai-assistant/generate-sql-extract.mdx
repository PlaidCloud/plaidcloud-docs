## 说明

**提取 SQL** 工作流步骤会对项目数据运行只读的 `SELECT`，并将结果写入新表。手动编写这样的查询，需要了解源表、它们的列，以及整理数据所需的 SQL。

步骤编辑器可以替您编写查询。用自然语言描述想要的输出，AI 助手就会生成 `SELECT`；如果您没有指定要读取的表，它会检查项目中的表并自行选出相关的表。生成的 SQL 和检测到的列会显示出来供您审阅，并且在保存步骤之前仍可完全编辑。

<Aside type="note">
这使用的是 AI 助手所用的同一个内置模型，**无需任何设置**。您不需要为此配置工作区级别的 AI 代理或 LLM 连接。
</Aside>

## 打开步骤

在工作流的**步骤**视图中，点击**创建步骤**，然后选择以下任一项：

- **表 → 提取 SQL**，或
- **AI → SQL 提取（AI 辅助）**

两者都会打开同一个提取 SQL 步骤编辑器，其中 SQL 提取参数页面顶部现在包含一个**使用 AI 生成 SQL** 面板。

## 生成查询

1. **（可选）选择源表。** 在**源表**列表中，选择查询应读取的一个或多个表。将列表留空，则由助手检查项目并为您选择相关的表。
2. **描述您的需求。** 在**描述**框中，用自然语言写出想要的结果，例如“根据科目编号范围，将每个总账科目归入某个作业池”。
3. **点击生成 SQL。** 助手会编写一条只读的 `SELECT`，通过运行它来验证，并填入：
   - **SQL 选择查询**编辑器中生成的语句，以及
   - **表数据选择**映射页面中检测到的列。

   如果您将源表列表留空，助手所选的表会在列表中被重新选中，方便您查看它使用了哪些表并进行调整。

## 审阅并保存

生成的 SQL 只是一个起点，而不是黑盒：

- **随意编辑。** SQL 编辑器完全可编辑，可以在保存前优化查询、添加联接或更改列列表。（要联接多个表，可以选择多个源表，也可以直接编辑生成的查询。）
- **请选择目标表。** 选择或命名步骤写入结果的**目标表**。
- **保存步骤。** 它会作为普通的提取 SQL 步骤保存，并像其他步骤一样作为工作流的一部分运行。

<Aside type="tip">
如果助手返回的查询无法运行，编辑器仍会显示该 SQL 及错误信息，方便您更正，或调整描述后重新生成。
</Aside>

## 说明与限制

- 助手只会编写**只读**的 `SELECT` 语句，从不生成 `INSERT`、`UPDATE`、`DELETE` 或其他更改数据的 SQL。
- 生成**不会创建或运行**步骤，它只起草查询并预览列。步骤在您保存时创建，在工作流运行时运行。
- 生成的查询使用表的**显示名称**：每个表在查询顶部以其名称绑定一次（因此列、联接和筛选器都使用易读的名称，而不是内部的 `analyzetable_…` ID）。保存时会自动还原真实标识符，因此查询无需修改即可运行。名称不唯一的表会保留其标识符。
