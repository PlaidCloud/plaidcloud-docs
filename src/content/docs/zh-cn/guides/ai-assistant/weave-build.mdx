## 说明

在 PlaidCloud 中，大多数工作都可以从用一句话告诉 Weave 您想要什么开始。
Weave 会用一张卡片作答，准确说明它将构建或更改什么，在您批准之前不会发生任何事情。本页中的一切都在
[Weave 停靠栏](/zh-cn/guides/ai-assistant/weave-dock/)中进行，每张卡片都遵循相同的规则：

- 您在浏览器中批准卡片，使用**批准 1 项更改**（或**批准 6 项更改**），
  使用**以后再说**保持现状，或使用**更改…** 再次提问。
- Weave 启动的每次运行都会关闭 ERP 过账。
- Weave 不会运行、更改在 PlaidCloud 之外写入数据的步骤，也不会为其设置计划。它会将您
  引导到步骤表单或工作流。
- Weave 只能执行您的角色允许的操作。如果您的角色无法执行某项操作，Weave 会如实说明，
  并且不会更改任何内容。

有关卡片的阅读方式以及如何撤消，请参阅[批准更改](/zh-cn/guides/ai-assistant/weave-dock/#批准更改)。

## 告诉 Weave 您想要什么

用于创建项目、工作流、步骤、导入或维度的对话框会以
**Tell Weave what you want** 打开：这是一个输入一句话的框，下方以链接形式提供几个建议的起点。

| 对话框 | 输入框提示 | 建议的起点 |
|---|---|---|
| 新建项目 | *Describe the project*，并附有示例 | **Start from a template**、**Import files from Documents**、**Copy a project** |
| 新建工作流 | *What should this workflow do?* | **Import a file into a table**、**Copy steps from another workflow**、**Reconcile two tables** |
| 新建步骤 | *What should this step do?* | **导入文件**、**Look up**、**筛选器** |
| 导入 | *Which file should become a table?* | **Import a file into a table** |
| 新建维度 | *What should this dimension hold?* | **Build from a table's column** |

键入这句话并按 Enter。停靠栏会打开，并已发送您的这句话。按
Shift+Enter 可换行。在**新建项目**中，输入框中有文本后，**询问 Weave** 就成为主按钮。

单击 **Fill in the form instead** 可使用常规表单，单击 **Tell Weave instead** 可返回
输入框。PlaidCloud 会针对每种对象记住您上次使用的方式。

工作流画布的 **New step** 菜单以 **Describe the step…** 开头，它会为当前步骤之后的步骤
打开同样的输入框。

当 Weave 聊天处于开启状态且您的角色可以创建该对象时，才会显示输入框。否则
对话框会显示表单。

### 空列表和空页面

没有任何内容的列表也从 Weave 开始：

- **项目**、**工作流**、**表**、**维度**以及工作流的步骤会显示
  输入句子的框。
- **数据编辑器**、**UDF**、**连接**和**仪表板**会显示**询问 Weave**
  按钮。
- 空的工作流画布会显示 *This workflow is empty. Tell Weave what it should do, or
  add a step.*，并附有输入框、**导入文件**起点和 **Add a step**。
- 没有工作流的项目会在其**概览**上显示 **Start with Weave** 卡片。

列表的常用按钮（例如加载示例数据）仍位于下方。

## 描述工作流并观看其构建

描述工作流应执行的操作，例如 *导入 freight.csv，查找每个承运商的
区域，并按承运商汇总运费*。Weave 会用一张计划卡片作答，标题例如
**Build 3 steps in a new workflow “Freight by Carrier”, then run it**。计划的每一行
都用通俗的话说明一个步骤的作用：

- *将 freight.csv 导入新表 Freight（Carrier、Amount、Month）。*
- *按 Carrier 在 Carriers 中查找 Region。*
- *按 Carrier 汇总 Amount，写入 Freight by Carrier。*
- *运行 Freight by Carrier。此次运行的 ERP 过账处于关闭状态。*

计划可以导入文件、提取、查找、联接、合并和汇总，后面的步骤可以
读取前面步骤创建的表。运行工作流是计划的最后一行。

您批准后，停靠栏会显示 **Creating the workflow**、**Building step 2 of 3** 和
**正在运行**。在画布上，每个步骤在创建时都会出现，并带有 **Built by Weave**
轮廓，构建结束后轮廓会淡出；工作流上方的横条会显示 *Weave is
building this workflow*。单击横条上的**停止**即可停止。随后 Weave 会说明它已经
构建了什么，例如 *Stopped part-way: built Import Freight and Lookup Region.*

- Weave 构建到高级工作流中。如果要求它构建到标准工作流中，它会
  提议改为构建一个新工作流。
- 新工作流不能使用已存在的工作流的名称。
- Weave 可以导入 CSV、Excel、Parquet 和 DB2 文件。Weave 无法构建的行会列为
  *Not added:* 并附上原因，例如文件不存在或没有标题行。

## 运行工作流或为其设置计划

请 Weave 运行一个工作流或其中一部分：*从 Allocate by
Driver 开始运行 Month-End Close*。卡片以将要运行的内容为标题，例如 **Run "Month-End Close" from the
step "Allocate by Driver"**，并列出：

- **运行次数** — 运行多少个步骤。
- **写入** — 运行写入的表。
- **ERP过账** — *ERP posting is off for this run.*，当运行中的步骤向 ERP 过账时显示。
- **撤消** — *A run can't be undone: it replaces what these tables hold.*

在标准工作流中，步骤按顺序运行，因此运行彼此不相邻的步骤时，会涵盖它们之间的所有步骤，卡片会予以说明。

运行结束后，Weave 会说明运行情况，例如 *succeeded in 4 min*，以及每个表的
行数及其是否处于通常范围内。如果工作流已在运行，
则不会启动任何内容，Weave 会让您在其完成后再次批准。

请 Weave 为工作流设置计划，例如 *每个工作日 06:00 运行 Month-End Close*，
或者更改、开启、关闭或删除其某个计划。计划卡片会显示
**时间**、**接下来**下的后续三次运行时间，以及 **Turned on**。对现有计划的更改会显示更改前后的内容。您批准后，Weave 会告诉您下一次
运行的时间。

- 运行工作流需要可以编辑工作流的角色。更改计划还需要
  可以更改项目自动化的角色。
- Weave 不会开启或更改向 ERP 过账的计划。它会提示 *This schedule
  posts to the ERP. Turn it on in Schedules.*
- Weave 不会运行将数据发送到 PlaidCloud 之外的工作流，也不会为其设置计划。请从
  工作流中运行它。

## 更改或添加步骤

请 Weave 更改某个步骤，例如 *更改 Allocate by Driver，使其按
人数拆分*。卡片标题为 **Change "Allocate by Driver"**，显示每项设置更改前后的内容，
并以 *Then: re-run Allocate by Driver with ERP posting off and check it
succeeds.* 结尾。您批准后，Weave 会保存更改、重新运行该步骤，并告诉您
结果。卡片上的**撤消**可将设置恢复原样。

请 Weave 添加一个步骤，例如 *在 Load Freight 之后添加一个只保留 2026
年各行的步骤*。卡片标题为 **Add a step "Freight 2026" after "Load Freight"**，该步骤创建的表
会标记为 **(new table)**。在高级工作流中，该步骤会放在
它所跟随的步骤右侧。

Weave 不会通过卡片更改以下内容：

- 向 ERP 过账或在 PlaidCloud 之外写入数据的步骤；
- SQL 步骤（例如 Extract: SQL 和导入：SQL）、用户定义函数步骤，以及运行脚本或 Python 的
  步骤；
- 任何清空、删除或移除表或维度的操作。

它会说明是哪些内容，并将您引导到步骤表单。运行其他工作流的步骤，或位于
多个工作流中的步骤，在更改后不会重新运行。Weave 会让您从其工作流中重新
运行它。

## 将文件拖放给 Weave

将一个文件拖到项目的**概览**上，或拖到高级工作流的画布上。
页面会显示 *Drop a file or an Alteryx workflow here*，将文件上传到文档，并
打开停靠栏，显示针对该文件的卡片：

| 您拖放的内容 | Weave 的提议 |
|---|---|
| 数据文件：CSV、TSV、TXT、Excel 或 Parquet | 在**概览**上为新表；在画布上为以该文件命名的导入步骤，放在您拖放的位置。 |
| SQL 脚本（`.sql`） | 执行该脚本所做工作的步骤。请参阅[将 SQL 脚本转换为步骤](#将-sql-脚本转换为步骤)。 |
| Alteryx 工作流（`.yxmd` 或 `.yxwz`） | 包含转换后工作流的新项目。请参阅[导入 Alteryx 工作流](#导入-alteryx-工作流)。 |
| `.zip` 文件 | 将其中的 Alteryx 工作流迁移到新项目中。 |

Weave 一次处理一个文件。如果您拖放了多个文件，它会使用第一个并予以说明。要
导入文件夹，请将其压缩后拖放 zip 文件，或将其上传到文档并在
停靠栏中指定它。Weave 无法识别的文件会保留在文档中，Weave 会告诉您其位置。

也可以指定已在文档中的文件：*从文档转换 Revenue Prep.yxmd*。

## 将 SQL 脚本转换为步骤

拖放 `.sql` 文件，或将脚本粘贴到停靠栏中。Weave 会读取脚本，并提议执行相同工作的标准
步骤，显示在计划卡片上，例如 **Build 6 steps from 4 statements in a
new workflow "Revenue Prep", then run it**。如果拖放到画布上，步骤会放入该
工作流。

卡片会注明读取脚本时所用的 SQL 方言：Databricks、Spark、Snowflake、
BigQuery、T-SQL、Oracle、PostgreSQL、MySQL 或 StarRocks。如果方言是 Weave 猜测的，而
脚本是为其他数据库编写的，请说明是哪种数据库并再次提问。

每一行都说明一个步骤的作用，例如 *按 Region 汇总 Amount，写入 Revenue by Region*。
任何无法成为步骤的内容都会列为 *Not added:*，并附上语句和
原因，例如更改数据库本身的语句，或尚未在项目中的表。
语句要么完整转换，要么不添加：Weave 绝不会只构建语句的一部分。

- Weave 可读取最大 1 MB 的脚本。请将较长的脚本拆分为多个文件。
- INSERT、UPDATE、DELETE 和 MERGE 语句会成为写入新表或
  更新某个表的步骤。Weave 不会清空表，因此不带 WHERE 的 DELETE 不会被添加。
- 脚本创建的表会被其后的语句使用。脚本读取的任何其他表
  都必须已在项目中。
- 与任何计划一样，Weave 构建到高级工作流中，最后的运行会关闭
  ERP 过账。

## 导入 Alteryx 工作流

### 单个工作流

将 Alteryx 工作流（`.yxmd` 或 `.yxwz`）拖放到项目的**概览**上，或在
文档中指定一个。卡片 **Convert “Revenue Prep” into a new project** 会显示：

- **Project name** — *Revenue Prep (from Alteryx)*。该卡片会创建一个包含
  转换后工作流及其表的新项目，并将其读取的输入文件复制到旁边的文件夹中。现有项目中的任何内容都不会更改。
- **估算** — 工作流大约有多少个工具，以及其中有多少可以转换、需要
  审核或没有 PlaidCloud 对应项。
- **Saved in** — 项目文件所放入的文档文件夹。

您批准后，Weave 会转换该工作流，并告诉您它生成了什么，附有 **Open the
project** 和**打开工作流**。它找不到的输入文件会被列出，以便您稍后将其添加到
该文件夹中。**撤消**会将新项目移到回收站。

超过 25 MB 的工作流，或估算耗时过长的工作流，会改为在
[Alteryx 转换器](/zh-cn/guides/workflows/migrate-alteryx-workflows/)中转换。

### 整个文件夹

在文档中指定一个包含 Alteryx 工作流的文件夹，例如 *迁入 Alteryx 文件夹 Finance
Close*，或将该文件夹的 `.zip` 拖放到项目的**概览**上。同时将您的 Alteryx
工作流写出的文件也放入该文件夹，Weave 会将转换后工作流的
结果与这些文件进行比较。

卡片 **Move 12 Alteryx workflows into a new project** 会显示项目名称、
工作流转换情况的估算、它将用于比较的输出文件，以及
因在 PlaidCloud 之外写入数据而被排除在检查之外的步骤。每次运行都会关闭
ERP 过账，写出输出文件的步骤在检查期间不会运行：改为比较
它们写入的表。

较大的文件夹可能需要几个小时。在它处理期间，您可以关闭 PlaidCloud。停靠栏中作业的
进度依次经过解包、转换、导入输出文件、
运行和比较，然后编写报告。结束时会显示一句话，例如
*Finance Close (from Alteryx) is ready: 9 of 12 workflows match the outputs you supplied, 2
differ, 1 didn't run. 3 need a decision on the move-in report.*，并附有 **Open the report**。

**Move-in report** 首先列出需要做出决定的工作流，然后列出每个
工作流及其被识别和转换的内容、需要审核的内容、是否 **Ran**，以及
其结果是否与您提供的文件 **Match**。每一行都有：

- **比较** — 打开该工作流结果与您的文件的比较。
- **重新检查** — 提议重新运行并比较该工作流。
- **打开** — 打开该工作流。
- **分配** — 选择由谁对该行做出决定。对方会在 PlaidCloud 中收到通知。您只能将
  某一行分配给可以打开该工作流的项目成员。

当工作流未能转换、包含没有 PlaidCloud 对应项的工具、未运行、与您的文件不同或无法比较时，需要对其做出决定。

<Aside type="note">
导入 Alteryx 工作流会创建项目，因此需要可以创建
项目的角色。该作业以您的身份运行：如果您失去了对项目的访问权限，或项目被移到
回收站，作业会停止，并保留已完成的工作。
</Aside>
