## 说明

Weave 每天读取项目中的每个[指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/)，
并查看其最近一个已结束的期间。当指标在该期间的总计超出其通常范围，
并且细分中的某一项（如某个客户、某个产品或某个工厂）的变化远大于其在总计中通常所占份额所能解释的幅度时，
Weave 会在项目的
[Weave 选项卡](/zh-cn/guides/ai-assistant/weave-tab/)上报告此情况，并指明该项。

此过程不涉及 AI 模型。检查是一条固定规则，每一句话都是根据 Weave 读取的数字预先写好的。

## 发现项的内容

```
Weave noticed the metric "Revenue": it came to 16.4M in April 2026, against an
average of 11.2M (usual range 8.9M to 13.5M) over the 12 months before.
"Seasonal Specials" (by product_group), usually 2% of the total, rose from an
average of 210.0K to 1.7M, 1.5M of the rise of 5.2M (29%); the other 3.7M came
from elsewhere
```

金额以 K、M 和 B 缩写显示，且不显示货币或单位，因为指标定义中不记录这些信息。日期列基于日历年的指标会显示月份，如 *April 2026*；其他指标则显示期间，如 *period 8 of fiscal 2025*。

当某一项的变动幅度超过整个总计的变动时，发现项会说明这一点，并说明其余各项朝相反方向变动。在更早期间没有任何数据的项，会被描述为此前没有数据。

**Weave 如何得知**显示该期间、总计、更早期间的平均值、比较的期间数、通常范围、变动最大的项，以及其他同样远超常态的项。

## Weave 检查哪些指标

指标未被停用，且满足以下条件时才会被检查：

- 它有**日期列**，或**年度和期间列**，因此有可供比较的期间；
- 它是**求和或计数**，Weave 可以将其拆分为各项的贡献；
- 它至少有一个**细分列**（如客户或工厂），用于显示变动来自何处；并且
- 它**不是由其他指标计算得出**。

Weave 以最后保存该指标的架构师的身份读取每个指标的当前版本，只能看到该架构师能看到的内容。Weave 在每个项目中最多检查 50 个指标，按保存时间从早到晚排序；超出的指标会被列为未检查。

不符合条件或 Weave 无法读取的指标会被列为 **Weave 未检查**，并附上原因。它绝不会被当作正常。

## 检查的工作方式

**被判断的期间。** 对于有日期列的指标，是至少在 7 天前结束的最近期间，因此您在结账期间仍在加载的期间不会被判断。对于有年度和期间列（不含日期）的指标，是有数据的最近常规期间的前一个期间；如果其后的调整期间（如 12 期年度中的第 13 至 16 期）已有数据，则是该年度的最后一个期间。第 0 期和调整期间永远不会被判断。

**通常范围。** Weave 将该期间的总计与其之前最多 12 个期间进行比较，且这些期间中至少需要 6 个有数据。范围根据这些期间的波动幅度得出。

**季节性期间。** 如果前三年中至少有两年的同一期间结果相近，则超出范围的总计不会被报告。在期间可划分为季度的日历上，如果总计与更早季度中相同位置（如一个五周的月份）一致，同样不会被报告。

**变动的项。** Weave 按最多五个细分列拆分总计，优先使用与维度关联的列；只有当某一项在变化中所占的份额远大于其在总计中通常所占的份额时，才会指明该项。发现项首先列出按金额计变动最大的项。分散在许多项中、且各项按比例变动的变化不会被报告。

**后续调整。** 一旦某个期间的问题被报告，只要之后的读数与其相差不超过百分之零点五，其数字就保持首次读取时的值，因此少量的后续调整不会让它被作为新问题再次报告。

## Weave 不检查的内容

- 总计超出其通常范围，但没有任何一项突出的情况。
- 总计保持在通常范围内，而某一项的份额发生变化。
- 前五个之外的细分列，或在其各项和各期间中数据超过 50,000 个的细分列。
- 变动是错误还是真实的业务情况。
- 更早的期间，它们仅用于比较。

## 谁能看到以及通知谁

发现项归**最后保存**该指标的人所有，并会在运行之间在 PlaidCloud 中通知此人。与任何发现项一样，它也会计入已开启摘要的人的[每日摘要](/zh-cn/guides/ai-assistant/weave-findings/#摘要)。如果最后保存该指标的人不再是项目的架构师，Weave 会停止检查该指标，直到当前的架构师保存它。

任何可以读取项目的人都能在 Weave 选项卡上看到该发现项。在设有[行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/)的项目中，只有架构师会收到这些发现项，因为这些数字是以保存者的访问权限读取的。

每个发现项在首次报告时都会记录到项目的 [Weave 活动历史](/zh-cn/guides/ai-assistant/weave-activity/)中。当之后对同一期间的读数不再显示该问题时，历史记录会说明 Weave 不再发现该问题。当下一个期间结束时，会说明 Weave 的每日检查已转到该期间。当指标被停用时，会说明 Weave 已停止检查它。

## 转到指标

发现项上的 **转到指标** 会打开该指标，在您点击时计算，并按您自己的行访问权限显示。对于异常总计，它显示 Weave 指明的项在其判断期间的数据。对于 Weave 无法检查的指标（包括所有由其他指标计算得出的指标），它显示该指标的总计。✓ 标明数字所来自的指标版本。这些数字是指标目前的状态，因此如果自 Weave 读取以来指标已有更改，它们可能与发现项中的数字不同。

在数字下方，**转到行**会在表资源管理器中打开该指标的源表，并按该项、该期间以及指标自身的筛选器进行筛选，以便查看变化背后的行。能读取表的人才会看到此按钮；使用查找表的指标不会显示，因为仅凭源表无法显示其行。

<Aside type="note">
新保存的指标会在一天内被读取，除非项目已有 50 个指标。在此之前，它会被列为 Weave 尚未读取的指标。
</Aside>

## 当 Weave 未检查某个指标时

| 显示的原因 | 操作 |
| --- | --- |
| 它由其他指标计算得出 | 无需操作；Weave 只检查基础指标。 |
| 它是平均值、最小值、最大值或非重复值计数 | 无需操作；只有求和与计数可以按项拆分。 |
| 它没有细分 | 添加细分列（如客户），并保存新版本。 |
| 它没有日期或期间列 | 添加时间绑定，并保存新版本。 |
| 其年度或期间列包含 *2024-01* 之类的值 | 将时间绑定指向整数的年度和期间列，或指向日期列。 |
| 它只有少数几个期间的数据 | 请等待：Weave 需要 6 个更早的期间。 |
| 它在该期间没有数据 | 检查该期间的数据是否已加载。 |
| 最后保存它的人不再是架构师 | 请当前的架构师保存它。 |
| 读取它花费了超过 2 分钟 | Weave 会在第二天重试。 |
| 它的每个细分都有超过 50,000 个数据 | 在这种情况下，Weave 不检查它。 |
| 它的总计超出通常范围，但某个细分有超过 50,000 个数据 | Weave 无法判断该细分中是否有某一项导致了变化。请自行查看该细分，或将其从指标的细分列中移除。 |
| 项目有超过 50 个指标 | 停用无人使用的指标；最早保存的会优先检查。 |
| Weave 无法读取其当前版本 | Weave 会在第二天重试。 |
| Weave 的每日检查最近一次运行是在几天前 | 请联系您的 PlaidCloud 管理员。 |
