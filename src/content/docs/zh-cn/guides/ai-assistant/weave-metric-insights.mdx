## 说明

Weave 每天读取一次项目的每个[指标](/zh-cn/integrations/ai-coding-agents/metric-definitions/)，并查看其最近一个已结束的期间。当该指标在该期间的总计超出其通常范围，并且分组中的某一项（例如某个客户、某个产品或某家工厂）的变化远大于其占总计的通常份额所能解释的幅度时，Weave 会在项目的 [Weave 选项卡](/zh-cn/guides/ai-assistant/weave-tab/)上报告此情况，并指明该项。

整个过程不涉及 AI 模型。该检查是固定规则，每句话都是根据 Weave 读取的数字预先写好的。

## 发现项说什么

```
Weave noticed the metric "Revenue": it came to 16.4M in April 2026, against an
average of 11.2M (usual range 8.9M to 13.5M) over the 12 months before.
"Seasonal Specials" (by product_group), usually 2% of the total, rose from an
average of 210.0K to 1.7M, 1.5M of the rise of 5.2M (29%); the other 3.7M came
from elsewhere
```

金额以 K、M 和 B 缩写，且不显示货币或单位，因为指标定义不记录这些。日期列基于日历年的指标会指明月份，例如 *April 2026*；其他指标则指明期间，例如 *period 8 of fiscal 2025*。

当某一项的变动超过了整个总计的变动时，发现项会说明这一点，并说明其他所有项的变动方向相反。在更早期间没有任何数值的项，会被描述为此前没有数值。

**Weave 如何得知**会显示该期间、总计、更早期间的平均值、比较了多少个期间、通常范围、变动最大的项，以及其他同样变动远超平常的项。

## Weave 检查哪些指标

当指标未被停用且满足以下条件时，会被检查：

- 它有**日期列**，或**年份和期间列**，因此有可供比较的期间；
- 它是**求和或计数**，Weave 可以将其拆分为每一项的贡献；
- 它至少有一个**分组列**（例如客户或工厂），用于显示变动来自哪里；并且
- 它**不是由其他指标计算得出的**。

Weave 以最后保存该指标的架构师的身份读取每个指标的当前版本，只能看到该架构师能看到的内容。Weave 在每个项目中最多检查 50 个指标，先检查最早保存的；超出的部分会被列为未检查。

不符合条件的指标，或 Weave 无法读取的指标，会被列为一个 **Weave 尚未检查**的指标，并附上原因。它绝不会被计为正常。

## 检查如何进行

**被判断的期间。** 对于有日期列的指标，是至少在 7 天前结束的最近一个期间，因此在您结账期间仍在加载的期间不会被判断。对于有年份和期间列的指标（这些列不带日期），则是最近一个有数据的常规期间之前的那个期间；如果其后的调整期间（例如 12 期年度中的第 13 到 16 期）已有数据，则是该年度的最后一个期间。第 0 期和调整期间绝不会被判断。

**通常范围。** Weave 将该期间的总计与其之前最多 12 个期间进行比较，并且这些期间中至少需要 6 个有数据。范围由这些期间的波动幅度得出。

**季节性期间。** 当此前三年中至少有两年的同一期间结果相近时，超出范围的总计不会被报告。在期间可划分为季度的日历上，当总计与更早季度中的相同位置相符（例如有五周的月份）时，也不会被报告。

**变动的项。** Weave 按最多五个分组列拆分总计，优先使用与维度关联的列，并且仅当某一项在变化中所占的份额远大于其占总计的通常份额时，才会指明该项。发现项以按金额变动最大的项开头。分散在许多项上、且各项按比例变动的变化不会被报告。

**后期调整。** 某个期间的问题一经报告，只要之后的读数与之相差不超过百分之零点五，其数字就保持首次读取时的值，因此小幅的后期调整不会把它再次作为新问题报告。

## Weave 不检查什么

- 总计超出其通常范围，但没有任何一项突出的情况。
- 总计保持在通常范围内，而某一项的份额发生变化的情况。
- 前五个之外的分组列，或在其各项和各期间合计超过 50,000 个数值的分组列。
- 变动究竟是错误还是真实的业务情况。
- 更早的期间，它们仅用于比较。

## 谁能看到，以及通知谁

发现项属于**最后保存**该指标的人，并且会在两次运行之间在 PlaidCloud 中通知他们。与任何发现项一样，它也会计入已开启简报的任何人的[每日简报](/zh-cn/guides/ai-assistant/weave-findings/#摘要)。如果最后保存它的人不再是项目的架构师，Weave 会停止检查该指标，直到当前的架构师保存它为止。

任何能读取该项目的人都可以在 Weave 选项卡上看到发现项。在设有[行访问](/zh-cn/administration/access/managing-security-groups-and-assignments/)的项目中，只有架构师会收到这些发现项，因为数字是以保存者的访问权限读取的。

每个发现项在首次报告时都会记录到项目的 [Weave 活动历史](/zh-cn/guides/ai-assistant/weave-activity/)中。当之后对同一期间的读取不再显示该问题时，历史会说明 Weave 不再发现它。当下一个期间结束时，历史会说明 Weave 的每日检查已转到该期间。当指标被停用时，历史会说明 Weave 已停止检查它。

## 转到行

发现项上的**转到行**会在表资源管理器中打开指标的源表，并按该项、该期间以及指标自身的筛选器进行筛选，让您看到变动背后的行。能读取表的人可以看到此按钮；对于使用查找表的指标则不显示，因为仅凭源表无法显示其行。

<Aside type="note">
新保存的指标会在一天之内被读取，除非项目已有 50 个指标。在此之前，它会被列为 Weave 尚未读取的指标。
</Aside>

## 当 Weave 尚未检查某个指标时

| 显示的原因 | 如何处理 |
| --- | --- |
| 它由其他指标计算得出 | 无需处理；Weave 只检查基础指标。 |
| 它是平均值、最小值、最大值或非重复值计数 | 无需处理；只有求和与计数才能按项拆分。 |
| 它没有分组 | 添加一个分组列（例如客户），并保存新版本。 |
| 它没有日期或期间列 | 添加时间绑定，并保存新版本。 |
| 其年份或期间列的值形如 *2024-01* | 将时间绑定指向整数的年份和期间列，或指向日期列。 |
| 它只有几个期间的数据 | 请等待：Weave 需要 6 个更早的期间。 |
| 它在该期间没有数据 | 检查该期间的数据是否已加载。 |
| 最后保存它的人不再是架构师 | 请当前的架构师保存它。 |
| 读取它耗时超过 2 分钟 | Weave 会在第二天重试。 |
| 它的每个分组都有超过 50,000 个数值 | 在此情况下，Weave 不会检查它。 |
| 它的总计超出通常范围，但某个分组有超过 50,000 个数值 | Weave 无法判断该分组中是否有某一项推动了变化。请自行查看该分组，或将其从指标的分组列中移除。 |
| 项目有超过 50 个指标 | 停用无人使用的指标；最早保存的会先被检查。 |
| Weave 无法读取其当前版本 | Weave 会在第二天重试。 |
| Weave 的每日检查上次运行已是几天前 | 请联系您的 PlaidCloud 管理员。 |
