## 说明

打开一个已保存的步骤，在其**保存**按钮上方，Weave 会说明对它的更改会波及哪些内容：

> 对此步骤的更改会影响 2 个工作流中的 8 个下游步骤。

这句话统计的是读取此步骤所写入表的步骤，读取这些步骤所写入内容的步骤，依此类推，最多追溯到下游十个步骤。它读取的是项目中各步骤已保存的设置，因此是即时的，是将这些表列为源的步骤的精确计数，也不涉及 AI。它的作用是为保存提供参考，而不是限制保存：您始终可以保存。

<Aside type="note">
这句话描述的是步骤上次保存时的状态。如果您正在更改步骤写入的表，在保存之前，列出的是读取旧表的那些步骤，它们确实会受到影响：它们将不再收到此步骤写入的内容。
</Aside>

## 这句话的含义

| Weave 显示 | 含义 |
| --- | --- |
| 对此步骤的更改会影响 2 个工作流中的 8 个下游步骤。 | 有八个步骤直接或通过其他步骤读取此步骤写入的内容，它们共分布在两个工作流中。同时位于两个工作流中的步骤只算一个步骤，但在两个工作流中都会出现。 |
| 对此步骤的更改会影响 3 个下游步骤：1 个工作流中有 2 个，另有 1 个不在任何工作流中。 | 未放置在任何工作流中的下游步骤也会被计数，并列在**不在任何工作流中**下。 |
| 对此步骤的更改会影响 3 个下游步骤，它们都不在工作流中。 | 受影响的步骤全部未被放置。只有一个步骤时：“影响 1 个下游步骤，该步骤不在任何工作流中。” |
| 对此步骤的更改会影响至少 2 个工作流中的至少 8 个下游步骤。Weave 在下游 10 个步骤处停止了查找。 | 读取者链条超过十个步骤。计数是下限而不是总数，且这句话不会按放置情况拆分。 |
| …… 您无法打开其中 2 个。 | 其中两个受影响的步骤对您的角色是隐藏的。它们会被计入，因此这句话仍然准确，但不会列出名称。当所有受影响的步骤都被隐藏时，这句话以“您无法打开其中任何一个。”结尾，只有一个步骤时则为“您无法打开它。” |
| 没有其他步骤将此步骤写入的表列为其源。 | 没有步骤把这些表中的任何一个指定为其源。通过 SQL 查询或表达式访问表的步骤不会被计入，**Weave 如何得知**中会说明这一点。 |
| 此步骤不写入表，因此 Weave 没有可追溯的下游内容。 | 该步骤产生的是项目表以外的内容，例如文件、电子邮件或 ERP 过账，Weave 无法追踪谁在使用这些内容。 |
| Weave 无法检查对此步骤的更改会影响什么。 | 无法读取预览。追溯链条需要对步骤、工作流和表的读取权限，因此缺少其中任何一项的角色都会看到此消息。保存照常进行。 |

## 查看步骤

**显示步骤**按工作流列出受影响的步骤。您可以打开的工作流在前，按名称排序；您无法打开的工作流合并为一组，排在其后；不在任何工作流中的步骤排在最后。在一个工作流内，最近的读取者排在前面，您无法打开的步骤会在列表末尾计数，而不列出名称。同时位于多个工作流中的步骤会在每个工作流下列出，**Weave 如何得知**中会说明这一点。较长的列表可以滚动。

## Weave 如何得知

这句话下方的 **Weave 如何得知**会显示 Weave 做了什么，以及哪些内容未检查：

- **Weave 所做的操作**：从此步骤写入的每个表出发，找到读取它的步骤，再继续追溯这些步骤所写入的内容，最多追溯到下游十个步骤。
- **来源**：此步骤写入的表，以及项目中每个步骤已保存的设置。您的角色看不到的表会列为您无法打开的表，步骤设置中提到但尚不存在的表会按其名称列出。
- **Weave 未检查的内容**：通过 SQL 查询或表达式而不是将其列为源来访问这些表的步骤；读取这些表的仪表板、视图、导出以及本项目之外的任何内容；受影响的步骤是会失败，还是只是在不同的数据上运行；以及您尚未保存的对此步骤的编辑。

## 何时出现

- 仅适用于已保存的步骤。尚未保存的新步骤或副本没有可计数的读取者。
- 步骤保持打开时，在**保存**之后会刷新，因为保存可能会更改步骤写入的表。
- 它读取项目已保存的设置，因此不会产生 AI 调用，在没有可用 AI 提供方时也能继续工作。
