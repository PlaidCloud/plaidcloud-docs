## 说明

在项目中选择步骤或工作流，会打开其详细信息面板。面板底部的**文档**部分会显示 Weave 根据项目已保存的设置为其编写的页面。表的详细信息面板则改为显示其**列**，包括每一列的类型和描述；下方的页面说明了 Weave 和 AI 助手对表读取的内容：

- 对于表，是写入和读取该表的步骤，以及它的列；
- 对于步骤，是它的作用及其运行位置；
- 对于工作流，是按顺序排列的步骤，以及它读取和写入的表。

每次选择该项时都会根据当时已保存的设置重新编写页面，因此内容不会过时，也无需手动刷新。页面无需 AI 参与，因此在没有可用 AI 提供商时同样可用。在同一详细信息面板中保存后（例如添加了新的描述），页面会重新编写。

Weave AI（项目 **Weave** 选项卡中的聊天）以及通过 MCP 连接的 AI 助手都可以读取同一页面。请参阅[面向 AI 助手](#面向-ai-助手)。

## 表的页面

- **描述**：表的**备注**，以引用形式显示。对于由步骤创建的表，PlaidCloud 会将备注设为 *Created dynamically*；该备注不会显示，因为它对表本身没有任何说明。
- **Written by** 和 **Read by**：每个步骤按名称列出，并附有其步骤类型和所在的工作流。*(disabled)* 表示该步骤在某个工作流中被禁用，*not in any workflow* 表示该步骤不属于任何工作流。如果某个步骤的表名包含变量，而该变量可能指向也可能不指向此表，则会标注 *depending on the values of its variables*。如果某个步骤只给出了多个表共用的名称，则会标注，例如 *unless it means another of the 2 tables with this name*，此处仅统计您可以打开的表。表：清空、表：删除或表：就地删除步骤会被视为写入其所更改的表；既读取某个表又将其写回的步骤，会同时列在两处。
- **No step in this project reads this table.** 表示此项目中没有任何步骤将其列为源。该页面不会检查仪表板、导出、其他项目或项目步骤之外的任何内容。
- **列**：每一列及其类型，如果在**列属性**中设置了描述，也会一并显示。

## 步骤的页面

**What it does** 会为步骤执行的每件事给出一句话：

| 步骤 | 页面所述内容 |
| --- | --- |
| Allocation: Split 步骤 | 从哪个表拆分哪个值，拆分到哪些列，使用哪个驱动列，以及每一份如何计算，例如“每个 `product` 的份额是其 `weight` 除以同一 `cost_center`、`year` 和 `month` 的 `weight` 总和。”列名与源表和驱动表中的名称一致。步骤的源或驱动上的筛选器会被注明，写入的表也会列出。 |
| 分摊：按维度拆分步骤 | 从哪个表拆分哪个值、使用哪个驱动列，以及它写入的每个表，包括其映射表、路径表和汇总表。 |
| 导入 | 导入的一个或多个文件，以及导入到的表。 |
| 导出 | 导出的表，以及写入的文件。 |
| 没有列出源的 Extract: SQL 步骤 | 运行 SQL 查询，以及写入的表。 |
| 表：清空、表：删除、表：就地删除步骤 | 清空、删除其表或从中删除行；如果按搜索或文件夹选择表，则说明它作用于该设置所选中的表。 |
| 导入外部项目表步骤 | 将另一个项目中的表复制到当前项目的表中。 |
| 运行另一个工作流的步骤 | 所运行的工作流及运行方式：满足条件时运行、循环运行、作为宏运行（对其源表的每一行运行一次，并发运行时则同时运行），或通过包含方式运行。由变量选定的工作流显示为步骤给出的名称，位于其他项目中的工作流则会如实说明。步骤本身读取的任何表（例如循环所遍历的表）也会一并列出。 |
| 任何其他步骤 | 它读取的表和写入的表。 |

随后，页面会说明该步骤的运行位置：*It is step 3 in* 后接工作流，编号与工作流步骤列表中的编号一致；或者说明它不在任何工作流中。

步骤通过变量指定的表会以其名称显示，后接 *(named by a variable)*。

## 工作流的页面

- **步骤**：编号与工作流步骤列表中的编号一致，并列出每个步骤的类型及其写入的表，或其运行的工作流。其所包含工作流的步骤会按步骤列表中的显示方式就地列出。
- **Reads from outside this workflow**：在此工作流中任何步骤写入之前就已被某个步骤读取的表。
- **写入**：此工作流的步骤写入的表。

已禁用的步骤会列在**步骤**中，但不会出现在另外两个列表中。页面会对此加以说明，因为已禁用步骤所写入的表可能因此被列为从外部读取。工作流中某个步骤所运行的工作流所用到的表，位于该工作流自己的页面上。

## 整个项目的交接包

要交接项目（例如在项目结束时交给客户），可一次性下载所有页面。在**项目**窗口中选择一个项目，然后从**操作**菜单或右键菜单中选择**下载交接包**。您需要拥有该项目、其步骤、工作流和表的读取权限。

交接包是一个 Markdown 文件，以项目名称命名（例如 *Month End handover.md*），内容在您下载时根据已保存的设置生成。文件开头是项目的描述以及所含内容的数量，随后分为四个部分：

- **工作流**：每个工作流的页面。没有被其他工作流运行的工作流排在最前，按名称排序，每个工作流后面紧跟它所运行的工作流，按运行顺序排列。从两处运行的工作流只列出一次。
- **表**：每个表的页面，同上，包括其列及列的描述。
- **指标**：每个指标定义的当前版本，用通俗的句子描述：衡量什么、来自哪个表、联接了哪些表、使用哪些行、其实际值行和预算行、其期间，以及可按什么进行细分。由其他指标构建的指标会说明构建方式，例如 *Revenue divided by Orders*。请参阅[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。
- **分摊模型**：每条相互衔接的分摊步骤链，包括链条末端的一个或多个步骤，以及按运行顺序排列的每个步骤的拆分。不在任何工作流中运行的步骤会被排除在外。模型以其工作流或其工作流共用的文件夹命名。如果没有这样的名称，或与另一个模型共用名称，或其名称取自您的角色所隐藏的内容，则以其中一个步骤作为标题。分摊模型在交接包之外没有自己的页面。

交接包对您的角色所隐藏内容的处理规则与单个页面相同。您无法打开的工作流、表或分摊模型会被排除，并在开头统计数量，例如 *It leaves out 2 workflows and 5 tables you can't open.* 与单个页面一样，您无法打开的步骤不会被点名。

## 您的角色所隐藏的内容

表、步骤或工作流可以对管理者或探索者角色隐藏。页面绝不会点名您的角色所隐藏的内容：

- 您无法打开的步骤会被计数，例如 *2 more steps you can't open*，并在工作流的步骤列表中保留其编号。
- 您无法打开的表、步骤或工作流，其显示方式与已不存在的项相同，例如 *a table you can't open or that no longer exists*，因此无法借助页面判断被隐藏的内容是否存在。以这种方式从工作流列表中省略的步骤会被注明，因为其中某个步骤写入的表可能因此被列为从外部读取。如果步骤所指的表是您无法打开的表或并不存在，则以步骤给出的名称显示，后接 *(not a table you can open)*；工作流同样以 *(not a workflow you can open)* 标注。
- 请求获取您的角色所隐藏项的页面时，得到的答复就好像该项不存在一样。

架构师可以打开所有内容，因此架构师看到的页面会显示 *a deleted table*、*(table not found)*、*A deleted step* 或 *(workflow not found)*。

## 不涵盖的内容

- **行数、大小和更新时间。**
- **步骤仅通过其 SQL 文本或表达式访问的表。** 页面列出的是步骤在其设置中指定的表。
- **未保存的编辑。** 页面描述的是已保存的设置。

<Aside type="note">
该页面不会解读您的数据，也不会判断某个步骤是否正确。它只用通俗的语言陈述已保存的设置所表达的内容。
</Aside>

## 面向 AI 助手

- **Weave AI** 可以在您于项目中打开的对话里被问及时读取表、步骤或工作流的页面，并根据页面内容作答。请参阅 [Weave AI 聊天](/zh-cn/guides/ai-assistant/weave-tab/#weave-ai-聊天)。
- **通过 MCP 连接的 AI 助手**可以使用 `doc_describe` 工具读取同一页面，需提供项目、该项是表、步骤还是工作流，以及其 ID。这需要拥有步骤、工作流和表的读取权限，并遵循同样的角色隐藏规则。请参阅 [AI 代理 (MCP)](/zh-cn/integrations/ai-coding-agents/)。
