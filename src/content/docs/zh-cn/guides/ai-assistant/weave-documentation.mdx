## 说明

在项目中选择某个步骤或工作流，其详情面板随即打开。底部的 **文档** 部分会显示 Weave 根据项目已保存设置为其编写的页面。表的详情面板则显示其 **列**，包括每列的类型和描述；下方页面介绍了 Weave 和 AI 助手针对表读取的内容：

- 对于表，写入和读取该表的步骤，以及其列；
- 对于步骤，其作用及运行位置；
- 对于工作流，按顺序排列的步骤，以及其读取和写入的表。

每次选择该项目时，页面都会根据当时已保存的设置重新生成，因此不会过时，也无需手动刷新。整个过程不涉及 AI，因此在没有可用 AI 提供方时也能正常使用。在同一详情面板中保存更改（例如新增描述）后，页面会重新生成。

Weave AI（项目 **Weave** 选项卡中的聊天）以及通过 MCP 连接的 AI 助手可以读取同一页面。请参阅[面向 AI 助手](#面向-ai-助手)。

## 表的页面

- **描述**：表的 **备注**，以引用形式显示。由步骤创建的表，PlaidCloud 会将其备注设为 *Created dynamically*；该备注不会显示，因为它不能说明表的任何信息。
- **写入方**和**读取方**：每个步骤按名称列出，并附带其步骤类型及所在的工作流。*（已禁用）* 表示该步骤在某个工作流中被禁用，*不在任何工作流中* 表示该步骤不属于任何工作流。如果步骤的表名包含变量，而该变量可能指向也可能不指向此表，则会标注 *取决于其变量的值*。如果步骤只给出多个表共用的名称，则会标注类似 *除非它指的是同名的另外 2 个表之一*，且只统计您可以打开的表。表：清空、表：删除或表：就地删除步骤视为写入其所更改的表，而读取某个表后又写回该表的步骤，会同时列在两处。
- **此项目中没有步骤读取此表。** 表示此项目中没有任何步骤将其列为源。页面不会检查仪表板、导出、其他项目或项目步骤之外的任何内容。
- **列**：每列及其类型，如果在 **列属性** 中设置了描述，则一并显示。

## 步骤的页面

**作用** 为步骤所做的每件事各给出一句话：

| 步骤 | 页面内容 |
| --- | --- |
| Allocation: Split | 从哪个表拆分哪个值、跨哪些列、使用哪个驱动列，以及每一份的计算方式，例如“每个 `product` 的份额，等于其 `weight` 除以同一 `cost_center`、`year` 和 `month` 下的 `weight` 总和。”列名与源表和驱动表中的名称一致。如果步骤的源或驱动上有筛选器，会予以注明，并指出所写入的表。 |
| 分摊：按维度拆分 | 从哪个表拆分哪个值，以及使用哪个驱动列，还有它写入的每个表，包括其映射表、路径表和汇总表。 |
| 导入 | 它导入的一个或多个文件，以及导入的目标表。 |
| 导出 | 它导出的表，以及写出的文件。 |
| 提取：未列出源的 SQL | 它运行一条 SQL 查询，以及写入的表。 |
| 表：清空、表：删除、表：就地删除 | 它清空、删除其表或从中删除行；如果按搜索或文件夹选择表，则说明它作用于该设置所选中的表。 |
| 导入外部项目表 | 它将另一个项目中的表复制到当前项目的某个表中。 |
| 运行另一个工作流的步骤 | 它运行的工作流及运行方式：满足条件时运行、循环运行、作为宏运行（对其源表的每一行运行一次，并发运行时则并行执行），或通过包含方式运行。由变量选定的工作流，显示为步骤所给的名称；其他项目中的工作流，则按此说明。步骤本身读取的任何表，例如循环遍历的表，也会一并列出。 |
| 任何其他步骤 | 它读取的表和写入的表。 |

随后，页面会说明步骤的运行位置：*它是第 3 步，位于* 某工作流中，编号与该工作流的步骤列表一致；或者说明它不在任何工作流中。

如果步骤通过变量指定表，则显示其名称，后跟 *（由变量命名）*。

## 工作流的页面

- **步骤**：编号与工作流的步骤列表一致，并列出每个步骤的类型及其写入的表，或其运行的工作流。其包含的工作流中的步骤会就地列出，与步骤列表中的显示一致。
- **从此工作流外部读取**：在此工作流的任何步骤写入之前就已被某个步骤读取的表。
- **写入**：工作流各步骤写入的表。

已禁用的步骤会列在 **步骤** 中，但不会出现在另外两个列表中。页面会对此加以说明，因为已禁用步骤所写入的表，此时可能被列为从外部读取。工作流中某个步骤所运行的工作流所用到的表，位于该工作流自己的页面上。

## 整个项目的交接包

要交接项目（例如在合作结束时交给客户），可以一次性下载所有页面。在 **项目** 窗口中，选择一个项目，然后从 **操作** 菜单或右键菜单中选择 **下载交接包**。您需要拥有该项目、其步骤、工作流和表的读取权限。

交接包是一个以项目命名的 Markdown 文件，例如 *Month End handover.md*，下载时根据已保存的设置生成。文件开头是项目的描述和所含内容的数量，随后分为四个部分：

- **工作流**：每个工作流的页面。没有被其他工作流运行的工作流排在最前面，按名称排序，每个工作流后面紧跟它所运行的工作流，按运行顺序排列。被两处运行的工作流只列出一次。
- **表**：每个表的页面（同上），包括其列及列的描述。
- **指标**：每个指标定义的当前版本，用通俗语句描述：衡量什么、来自哪个表、联接了哪些表、使用哪些行、实际值行和预算行、期间，以及可以按什么拆分。由其他指标构建的指标会说明构建方式，例如 *收入除以订单数*。请参阅[指标定义](/zh-cn/integrations/ai-coding-agents/metric-definitions/)。
- **分摊模型**：每条相互衔接的分摊步骤链，列出其终止的一个或多个步骤，以及按运行顺序排列的每个步骤的拆分。不在任何工作流中运行的步骤会被省略。模型以其工作流命名，或以其工作流共用的文件夹命名。如果没有这样的名称、与另一个模型共用名称，或名称取自您的角色所隐藏的内容，则改用其中一个步骤作为标题。分摊模型在交接包之外没有自己的页面。

对于您的角色所隐藏的内容，交接包遵循与单个页面相同的规则。您无法打开的工作流、表或分摊模型会被省略，并在开头计数，例如 *它省略了 2 个工作流和 5 个您无法打开的表。* 您无法打开的步骤绝不会被点名，这与单个页面相同。

## 您的角色隐藏的内容

表、步骤或工作流可以对管理者或探索者角色隐藏。页面绝不会点名您的角色所隐藏的内容：

- 您无法打开的步骤会被计数，例如 *另外 2 个您无法打开的步骤*，并在工作流的步骤列表中保留其编号。
- 您无法打开的表、步骤或工作流，其显示方式与已不存在的相同，例如 *您无法打开或已不存在的表*，因此无法借助页面得知隐藏的内容是否存在。工作流列表中以此方式省略的步骤会予以注明，因为其中某个步骤写入的表，此时可能被列为从外部读取。如果步骤指定的表您无法打开或不存在，则按步骤给出的名称显示，后跟 *（不是您可以打开的表）*；工作流同样显示为 *（不是您可以打开的工作流）*。
- 请求您的角色所隐藏项目的页面时，返回的结果就像该项目不存在一样。

架构师可以打开所有内容，因此架构师的页面会改为显示 *已删除的表*、*（未找到表）*、*已删除的步骤*或 *（未找到工作流）*。

## 不涵盖的内容

- **行数、大小和更新时间。**
- **步骤仅通过其 SQL 文本或表达式访问的表。** 页面列出步骤在其设置中指定的表。
- **未保存的编辑。** 页面描述的是已保存的设置。

<Aside type="note">
页面不会解读您的数据，也不会判断某个步骤是否正确。它只是用通俗语言陈述已保存的设置所表达的内容。
</Aside>

## 面向 AI 助手

- **Weave AI** 可以在项目中打开的对话里，在您询问时读取表、步骤或工作流的页面，并根据页面内容回答。请参阅 [Weave AI 聊天](/zh-cn/guides/ai-assistant/weave-tab/#weave-ai-聊天)。
- **通过 MCP 连接的 AI 助手** 可以使用 `doc_describe` 工具读取同一页面，需提供项目、项目类型（表、步骤或工作流）及其 ID。它需要步骤、工作流和表的读取权限，并遵循与上述相同的角色隐藏规则。请参阅 [AI 代理（MCP）](/zh-cn/integrations/ai-coding-agents/)。
