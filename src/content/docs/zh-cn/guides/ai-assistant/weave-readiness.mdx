## 说明

在最重要的日子里，例如月末、预测提交或董事会材料准备，问题不再是“Weave 注意到了什么？”，而是“我们准备好了吗？”。**就绪集**会列出某个截止日期所依赖的工作流，选中该集即可一次性回答所有这些工作流的就绪情况，并通过一份清单给出答案，清单开头即是自己的计数：

> 13 个中有 11 个就绪；1 个未就绪；1 个无法检查。

集中的每个工作流会得到三种答案之一，取其各行中最差的结果。只要有任何检查发现问题，它就是 **未就绪**；问题会列在其下方，并附带与 Weave 选项卡相同的 **修复**、**转到** 和 **Weave 如何得知** 按钮。否则，只要有任何检查无法对其做出判断，它就是 **无法检查**，并会写明原因。只有当 Weave 能够对其运行的每项检查都通过时，它才是 **就绪**。Weave 未做出判断的任何内容都不会显示为就绪，只有一个例外：上次运行的此前历史记录太少而无法比较时，按通常情况计为正常，详见[下文](#历史记录较少的工作流)。

如果某个问题被人[标记为预期](/zh-cn/guides/ai-assistant/weave-tab/#将发现项标记为预期)，对应的行仍然是 **未就绪**，并且该行会说明它已被标记为预期。Weave 选项卡不再报告此类问题，但清单仍会如实说明情况。

这些检查就是 Weave 已在运行的规则。有关这些规则读取的内容及其答案的含义，请参阅 [Weave检查内容](/zh-cn/guides/ai-assistant/weave-findings/)。

## 创建就绪集

1. 打开项目的 **Weave** 选项卡，在 **Monitor** 导航栏的 **Close checks** 下点击 **就绪状态**。
2. 点击 **新建**。为该集命名，例如“月末结账”，并勾选其所依赖的工作流。在筛选框中输入内容以查找工作流，或使用 **已分配** 仅查看已在该集中的工作流。
3. 可选：勾选 **有截止时间**，并以 cron 表达式及其所用的时区来指定该集的截止时间，选项与计划事件提供的相同。`0 9 5 * *` 表示该时区每月 5 日 09:00，`0 8 * * 1` 表示该时区每周一 08:00。偏移量的解读方式与计划事件相同：**UTC +0** 是伦敦时间，包括英国夏令时，另一些偏移量遵循处于该偏移量的某个地点的夏令时，其余偏移量则是固定的。[事件调度器](/zh-cn/administration/scheduled-events/event-scheduler/#时区)页面列出了每个偏移量的解读方式。
4. 对于设有截止时间的集，在 **Tell the owner this many hours before it is due** 下，指定 Weave 应在截止时间之前多久发送消息，范围为 1 至 168 小时。默认值为 24。
5. 点击 **保存**。

集属于项目，在项目的 Weave 选项卡中拥有 **Monitor** 的所有人都可以检查它。只有项目架构师可以创建、编辑或删除集，并且集中的每个工作流都必须在该项目中。最后保存集的人就是其所有者。同时编辑同一个集的两个人会被分隔开：第二次保存会被拒绝，系统会重新读取该集，并且表单会显示较新的副本及原因。

当项目没有就绪集，且其工作流按月度计划运行时，**发现项** 会建议一个根据这些计划生成的集。项目架构师可以点击其上的 **Make this your month-end set** 来保存它。

只有在某些信息说明输入表应在何时写入时，Weave 才能判定该表是新的：写入该表的工作流上的计划，或表上的[新鲜度阈值](/zh-cn/guides/ai-assistant/weave-findings/#weave-目前检查的内容)。请先设置这些内容，否则大多数工作流的第一行都会显示为 **无法检查**。

## 阅读清单

在左侧选择一个集。Weave 会读取整个项目（与 Weave 选项卡所做的读取相同），并对集中的每个工作流做出判断。修复问题之后，请点击 **重新检查**。

每一项都会显示工作流的名称、其判定结果，以及适用于它的每项检查各一行。当某一行显示 **无法检查** 时，原因会写在旁边；以下是您最可能遇到的原因：

| 行 | Weave 比较的内容 | 显示“无法检查”的常见原因 |
|------|---------------------|-----------------------------------------|
| **Inputs are fresh** | 工作流读取的每个表，与写入该表的工作流的计划或表自身的新鲜度阈值相比。 | 您的角色无法读取表；Weave 无法确定其读取哪些表，或其读取的表 Weave 无法追踪；其读取的某个表对您隐藏；某个步骤读取的表 Weave 无法确定，例如通过变量选取的表；其读取的某个表既没有计划的写入者，也没有新鲜度阈值，因此没有任何信息说明应在何时写入；写入该表的工作流正在运行、已排队或刚刚完成。 |
| **Last run succeeded** | 工作流最近一次运行，该运行必须已完成。失败的运行为 **未就绪**。 | 没有运行记录、无法读取其运行历史记录，或其上次运行已停止或仍在进行。 |
| **Last run looked usual** | 上次运行所用的时间，以及运行后其表中的行数、空值数量及值的分布，与之前的运行相比。 | 上次运行失败、已停止或仍在进行，因此没有可供比较的正常情况；行访问适用于其写入的某个表，因此该表的值不进行比较；运行包含您的角色看不到的步骤。 |
| **Inputs unchanged since it last ran** | 它读取的某个表在其上次读取之后是否被另一个工作流写入。 | 您的角色无法读取表；Weave 无法追踪工作流读取的内容；或工作流没有可供比较的运行记录。 |
| **Schedule is healthy** | 其计划事件：时间表有效、与调度器同步、没有错过到期的运行、没有因运行仍在进行而丢失到期时间。 | 无法读取调度器。 |
| **Reconciliations tie out** | 链接到该工作流的每个[对账](/zh-cn/guides/ai-assistant/weave-reconciliation/)，以其已批准的版本、以您的身份运行。 | 某个对账尚未获批；您的角色无法读取表数据；行访问使您只能看到某一侧的部分行；其使用的表或列已更改；清单耗尽了为它们分配的时间。 |

没有计划事件的工作流没有 **Schedule is healthy** 行，并且该项会说明其未被计划。没有链接对账的工作流没有 **Reconciliations tie out** 行。这是关于该工作流的事实，而不是 Weave 未能检查的内容。

自创建集以来已从项目中删除的工作流，或您的角色看不到的工作流，仍会被计入。它会显示为 **无法检查** 并附上原因，因此计数永远不会悄悄变少。

<Aside type="note">
**就绪** 表示 Weave 能够运行的每项检查都已通过。它并不表示工作流的数字是正确的、其仪表板是最新的，或项目之外的任何内容是正常的。各行会准确说明比较了什么，发现项上的 **Weave 如何得知** 则说明该检查遗漏了什么。
</Aside>

### 历史记录较少的工作流

一次运行只有与之前的运行相比才可能显得异常。当 Weave 此前的历史记录太少而无法比较时，**Last run looked usual** 会将该运行计为正常，并加以说明。这涵盖新的工作流或步骤、运行频率太低以致过去 30 天内没有足够运行次数的工作流（例如每周运行的工作流），以及第一次填充某个表的运行：

> Weave 此前的历史记录太少，无法与其上次运行比较，因此将其计为正常。

当运行的某些部分可以比较时，该行会指明哪些内容处于其正常范围，并补充一句“Where Weave has too little earlier history to compare with, it counts as usual.”。Weave 选项卡仍会将这些列为 Weave 无法进行的检查。从未运行过的工作流在其 **Last run succeeded** 和 **Last run looked usual** 两行上仍为 **无法检查**，其上次运行已停止或仍在进行的工作流也是如此。

## 在截止时间之前收到通知

对于设有截止时间的集，Weave 会在截止时间临近时自行运行检查，并在集每次到期时向该集的所有者（即最后保存它的人）发送一次应用内消息：

> “月末结账”将在 3 天后（10 月 31 日 17:00 UTC）到期：其 13 个工作流中 11 个就绪、1 个未就绪、1 个 Weave 无法检查。

点击消息上的 **打开 Weave**，即可打开项目的 Weave 选项卡以及该集的清单。消息仅包含计数，名称和原因在清单中。消息会在屏幕上停留 30 秒，并且仅在所有者当时已登录时才会显示；针对同一截止时间不会再次发送，但清单始终可以在窗口中查看。如果所有者已无法再打开该项目，则不会发送任何内容。

Weave 每小时检查一次，因此消息会在通知时间点后一小时内送达：如果提前 24 小时通知，则在截止时间前 24 小时的一小时内。在通知时间点已过之后保存的集，会在下一次检查时收到通知。如果检查启动较晚，并且在其运行之前截止时间已过，则该检查仍会通知所有者，措辞为“was due 20 minutes ago”，除非该集是在截止时间之后保存的。检查以所有者的身份运行，并且仅当所有者上次保存集时能够读取表时，它才会读取表。

## 隔夜准备好的结账

对于设有截止时间的已保存集，Weave 会进行结账检查：它会自行逐项处理该集，准备好能准备的内容，只把需要决定的事项留给您。它会在以下时间检查该集：

- 每天一次，在该集截止时间的那个时刻；
- 写入该集所读取的表的运行完成之后；
- 您从结账中批准的更改完成之后；以及
- 该集的所有者点击 **Check now** 时。

当该集处于截止时间前的通知时间范围内时，**发现项** 上方的卡片会显示最近一次检查的结果，例如 **Month-end close is 92% done. Two things need you.**，以及检查的时间。该百分比是该集中已就绪的行所占的比例，因此只有每一行都就绪时才会达到 100%。卡片下方会为每项决定编号：

- 失败的运行附有 Weave 为其准备的修复。
- 不是新的或已更改的输入附有一个计划：先重新运行写入它的工作流，再重新运行读取它的工作流，例如 *重新运行“Load GL”，然后运行“Allocate Costs”*，并说明这些重新运行的影响范围。
- 未启动的计划运行附有 *立即运行“Load GL”*。
- 超出通常范围的数字，或未对平的对账，是需要您回答的问题，附有 **Ask Weave about this** 和 **此为预期**，因为 Weave 没有为其准备好修复。

点击某项决定上的 **打开** 可就地查看其卡片，并在网页上点击 **批准**。每张卡片涵盖一个计划，它启动的每次运行都会关闭 ERP 过账。没有全部批准。正在等待其计划运行的工作流会列出，但不编号。**原因** 列出 Weave 无法检查的内容，由他人做出的决定只计数，不列出。

在每日检查时，如果有决定在等待处理或该集当天到期，所有者会在 PlaidCloud 中和手机上收到通知，例如 *Weave 需要您处理：Month-end close is 92% done. Two things need you.* 该检查还会以 *Close check:* 加上集的名称显示在停靠栏的作业中。运行之后的检查只更新卡片，不通知任何人。

- 结账检查属于最后保存该集的人，并以其身份运行。如果此人已无法打开该项目，检查就会停止。
- 只有所有者可以点击 **Check now**。
- 能够阅读清单的所有人都能看到结账进度。其决定会显示给所有者以及角色可以运行这些工作流的任何人。
- 检查本身不会更改任何内容，也绝不会运行在 PlaidCloud 之外写入数据的步骤。

## 通过 API

就绪集可通过平台 API 在 `/analyze/weave/readiness` 下使用：`GET /sets` 列出项目的集，`GET /set`、`POST /set`、`PUT /set` 和 `DELETE /set` 分别读取、创建、替换和删除一个集，`GET /check` 返回与窗口所示相同的清单，并附带每一行的发现项。通过 API 读取的集带有 `etag`；在 `PUT` 时将其作为 `if_match` 发回，可使覆盖较新保存内容的编辑被拒绝。如果不带它，则以最后一次写入为准。
