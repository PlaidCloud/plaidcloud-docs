借助 PlaidCloud 的 MCP 服务器，AI 代理可以协调跨多个 Alteryx 工作流的迁移。代理可以帮助在 Document 中暂存和整理文件、盘点工作流包、调用 Alteryx 转换器、整理生成的工作流、运行验证工作流，并为迁移团队汇总进度。

<Aside type="note">
  MCP 非常适合组合级规模的协调。转换仍由 PlaidCloud 导入器完成；代理负责协助规划、排序、运行和汇总工作。
</Aside>

## 何时使用 MCP

在迁移大量工作流，或希望 AI 代理协助完成可重复的迁移任务时，请使用 MCP 编排：

- 盘点暂存在 Document 中的 Alteryx 文件。
- 通过 Document 工具上传、复制、移动、重命名和整理迁移文件。
- 使用已连接的共享存储账户，例如 OneDrive、Google Drive、SharePoint、S3、Azure Blob 或 SFTP。
- 将工作流、应用和宏分组为迁移批次。
- 将每个 `.yxmd`、`.yxwz` 或 `.yxmc` 文件转换到 PlaidCloud 中。
- 跟踪整个组合的转换结果。
- 运行已转换的工作流或验证工作流。
- 生成供评审的迁移摘要。

对于单个工作流，导入表单通常是最快的途径。对于整个组合，MCP 为代理提供了一种结构化的方式，可反复协调使用相同的 PlaidCloud 功能。

## 代理可以调用的内容

MCP 工具目录包含一个名为 `alteryx_convert` 的 Alteryx 转换工具。它可基于存储在 Document 中的 Alteryx 文件创建 PlaidCloud 工作流。

转换调用包括：

- Alteryx 文件所在的源文档账户和路径。
- 目标 PlaidCloud 项目。
- 转换产物所在的目标文档账户和路径。
- 可选的工作流、步骤和表前缀。表前缀默认为工作流自身的名称，这样可使同一项目中的两次转换互不占用对方的表；传入空前缀则使用不带前缀的名称。
- 工作流类型，默认为高级工作流。

代理可以将其与常规的 MCP 项目、工作流、Document、工作流运行和表工具结合使用，以管理更大范围的迁移。

## 与代理一起准备文件

已连接 MCP 的代理可以协助完成转换前后围绕文件准备的工作：

- 在 Document 中查找 `.yxmd`、`.yxwz` 和 `.yxmc` 文件。
- 识别可能的输入文件、宏文件、报表资源、空间附属文件和预期输出。
- 创建整洁的迁移文件夹结构。
- 将文件复制、移动或重命名到该结构中。
- 将相关的工作流、宏、数据、空间、报表和验证文件放在一起。
- 在转换之前汇总该包的内容。

当迁移包包含大量文件夹，或团队希望代理在转换开始前生成可重复的清单时，这一做法很有用。

## 无需上传即可使用共享存储

迁移之前，无需先把文件上传到 PlaidCloud 所有的新文件夹中。PlaidCloud Document 可以直接连接到已包含 Alteryx 迁移包的共享存储。

常见选项包括：

- [Google Drive](/zh-cn/guides/documents/adding-accounts/add-google-drive-account/)
- [OneDrive 或 SharePoint](/zh-cn/guides/documents/adding-accounts/add-onedrive-account/)
- [AWS S3](/zh-cn/guides/documents/adding-accounts/add-aws-s3-account/)
- [Azure Blob Storage](/zh-cn/guides/documents/adding-accounts/add-azure-blob-storage-account/)
- [SFTP](/zh-cn/guides/documents/adding-accounts/add-sftp-account/)

连接文档账户后，代理即可基于该文档账户和路径开展工作。这样迁移可以贴近客户现有的共享存储，并可省去单独的上传步骤。

## 在 Document 中暂存或选择文件

在让代理编排迁移之前，请选择以下途径之一：

- 将现有的共享存储位置连接为文档账户。
- 将工作流包上传到文档账户。
- 让代理整理 Document 中已有的文件。

然后确认：

1. 工作流、应用、宏、输入文件、空间附属文件、报表和预期输出均可通过 Document 获取。
2. 已选择目标项目。
3. 已选择用于存放已转换工作流依赖项和产物的 Document 路径。
4. 代理有权使用相关的 MCP Document 和工作流工具。

之后，代理在调用转换器时即可引用稳定的 Document 路径。

## 建议的代理提示

对已连接 MCP 的代理，可以使用类似下面的提示：

```text
In PlaidCloud, migrate the Alteryx workflows in the connected Document account
"Migration Share" under /q4-alteryx-package into the project "Q4 Migration".

First inventory the .yxmd, .yxwz, and .yxmc files. Organize the package by
workflow, macro, input, spatial, report, and expected-output files. Group macros
with the workflows that call them. Then convert the workflows as Advanced
workflows using the Document output path /q4-alteryx-converted. Prefix created
workflows with "Q4 - ". After each conversion, summarize the generated workflow,
macros, readiness notes, and next validation step. Ask before making mutating calls.
```

请根据您的迁移批次调整项目名称、源路径、目标路径和前缀。

## 推荐的编排流程

对于组合级迁移，请让代理遵循以下流程：

1. 连接或选择包含迁移包的文档账户。
2. 盘点源 Document 文件夹。
3. 识别 `.yxmd`、`.yxwz` 和 `.yxmc` 文件。
4. 将文件整理为工作流、宏、输入、空间、报表和预期输出几组。
5. 将相关的工作流和宏分组。
6. 确认目标项目和 Document 输出路径。
7. 将宏和工作流转换为高级工作流。
8. 打开或描述生成的工作流。
9. 运行结构验证。
10. 在有预期输出时，运行输出一致性验证。
11. 汇总已转换的工作流、生成的宏、产物和验证状态。

这样，迁移团队可以获得覆盖整个组合的统一进度报告，同时每次转换仍使用 PlaidCloud 原生的导入器。

## 审查变更类调用

大多数 MCP 客户端会在运行前显示工具调用。批准之前，请审查转换和工作流运行类调用，尤其是在生产项目中。

对于暂存迁移，请使用专用的迁移项目和 Document 文件夹。验证之后，再把已转换的工作流提升到生产项目中。

## 跟踪结果

让代理生成一张迁移表，其中包含：

- 源 Alteryx 文件。
- 生成的 PlaidCloud 工作流。
- 生成的宏工作流。
- 转换状态。
- 验证级别。
- 输出 Document 路径。
- 后续跟进备注。

此摘要可用于项目报告、交接和生产就绪状态评审。
