验证用于确认转换后的 Alteryx 工作流已准备好在 PlaidCloud 中运行，并且在有预期输出时，能够产生相同的业务结果。

将工作流、应用或宏导入 PlaidCloud 后，请使用本指南。

<Aside type="note">
  输出一致是指架构、行数和行值相符。除非工作流将排序作为业务逻辑的一部分，否则行顺序不必一致。
</Aside>

## 选择验证级别

大多数迁移项目使用两个验证级别。

### 结构验证

结构验证用于确认 PlaidCloud 已根据 Alteryx 设计创建了完整的工作流。在评估迁移就绪状态、准备组合清单，或在预期输出可用之前转换工作流时，请使用此级别。

请检查：

1. 转换后的工作流可在可视化工作流设计器中打开。
2. 工作流图包含预期的分支、联接、宏和输出。
3. 所有必需的输入文件均已上传到选定的 Document 路径。
4. 所有必需的宏均已导入或生成。
5. 宏输入和宏输出已连接。
6. 分析应用的问题已成为带有受控输入字段的工作流变量。
7. 工作流运行完成，并针对依赖数据的条件报告清晰的就绪状态说明。

### 输出一致性验证

输出一致性验证用于确认转换后的工作流产生与 Alteryx 工作流相同的表格结果。

比较：

1. 输出表架构。
2. 行数。
3. 行值。
4. 空值处理。
5. 数值精度和舍入。
6. 日期和时间值。
7. 当空间输出属于结果的一部分时，比较几何值。

除非工作流明确对数据排序，或下游流程依赖有序的行，否则忽略行顺序。

在 PlaidCloud 的 Lakehouse v2 (StarRocks) 引擎上，以下常用转换已通过值检查，与 Alteryx 输出一致，因此无需特殊处理即可获得一致的结果：

- 文本首字母大写。
- 点之间的球面（大圆）距离。
- 样本协方差。
- 对以文本形式存储的数值求和与求平均。
- 使用正则表达式将文本拆分为列。
- 缺失值的均值填补。

<Aside type="tip" title="比较数值精度之前请重新转换">
Alteryx 的 Double 列现在会转换为 64 位数值列，而不是 32 位列，因此在此修复之前转换的工作流，可能会在大约 7 位有效数字以上的值上出现舍入。比较数值精度之前请重新导入，而不要将先前的转换结果作为基线。请参阅 [Alteryx Double 列保持完整精度](/zh-cn/guides/workflows/migrate-alteryx-workflows/#alteryx-双精度列保持完整精度)。
</Aside>

## 验证您的迁移

**验证您的迁移**会将转换后的工作流所产生的结果与 Alteryx 所产生的输出进行比较，因此无需手动逐项比对。在通过 Alteryx 覆盖率报告接入的工作区上，它会在“主页”清单中显示为**验证您的迁移**，并带有**比较**按钮，覆盖率报告也提供同样的按钮。

1. 选择**导入 Alteryx 输出…**，并导入 Alteryx 工作流产生的每个输出文件。**添加另一个输出**会再添加一对。
2. 对于每一对，选择**转换后的输出**以及与之应匹配的 **Alteryx 输出**。
3. 选择**比较**。

PlaidCloud 先检查行数，再检查每一列，然后显示仅在一侧存在的行（每侧最多 20 行），因此差异可以精确定位到其所在的列。每个输出会报告以下结果之一。

| 结果 | 含义 |
|---|---|
| *与 `<output>` 一致：两侧均为 `<n>` 行，每一列均相同。* | 两侧行数相同，且每一列均相同。 |
| *在所比较的全部内容上与 `<output>` 一致：两侧均为 `<n>` 行。* | 所比较的全部内容一致。诸如 *另有 3 列未进行比较。* 的说明会统计被排除在外的列数。 |
| *与 `<output>` 不同：转换后为 `<n>` 行，Alteryx 为 `<m>` 行。* | 行数、列或值不同。报告会列出仅在一侧存在的列，并针对每一列指出差异之处（例如总和、最小值或不同值计数）。 |

行数超过 500 万的一侧过大，无法在此处比较；请改为比较各自经过筛选的提取结果。“主页”清单行显示最近一次的结果：*输出一致*、*所比较的列输出一致*或*部分输出存在差异*。

在您自己的 [Snowflake 或 Databricks 仓库](/zh-cn/guides/connections/external-lakehouse/#每次运行的仓库成本)上，该窗口还会显示最近一次运行的**仓库成本**（标记为*归因*或*估算*），以及下一次运行的估算值。

## 验证输入

比较输出之前，请确认转换后的工作流使用相同的源数据：

1. 打开导入期间选定的 Document 文件夹。
2. 确认存在必需的文件和附属文件。
3. 确认动态输入模式解析到预期的文件。
4. 确认目标环境中有可用的数据库或 API 凭据。
5. 确认工作流变量与 Alteryx 运行时使用的值一致。

输入对齐可加快验证，并使比较专注于工作流行为。

## 验证宏

转换后的 Alteryx 宏会成为 PlaidCloud 宏工作流。请将宏和调用它的工作流一起验证：

1. 打开生成的宏工作流。
2. 确认每个宏输入都有匹配的宏输入步骤。
3. 确认每个宏输出都有匹配的宏输出步骤。
4. 运行调用该宏的工作流。
5. 确认重复运行或并发运行彼此保持隔离。
6. 当有预期的宏输出时，比较宏输出数据。
7. 对于批处理宏，确认每一轮都出现在汇总结果中，包括宏不产生任何轮次的运行，此时应返回空结果，而不是上一次运行遗留的行。如果宏逻辑取决于 Double 值的到达方式，请重新检查：Double 宏输入现在以数字而不是文本的形式到达。

## 验证分析应用

转换后的 Alteryx 分析应用使用工作流变量来实现受控的用户输入。

请检查：

- 文本框、数值输入、日期、文件选择器、文件夹选择器、列表、树、单选按钮、复选框和下拉列表会显示预期的输入控件。
- 在原应用存在默认值的地方，默认值与之相符。
- 运行工作流之前已设置必需的值。
- 对于配置的输入值，条件会产生预期的消息、警告或停止行为。

## 验证专门输出

某些转换后的工作流创建的不只是表，还有工件。请根据其使用方式验证这些输出。

对于报表、PDF、图像、图表和地图：

1. 确认工件已在预期的 Document 路径中创建。
2. 确认工件包含预期的数据、标签、图像和布局。
3. 确认下游使用者可以打开或使用该工件。
4. 如果有预期工件，请与之比较。

对于 NLP、模糊匹配和空间工作流：

1. 确认托管作业执行器已成功完成。
2. 查看执行器说明。
3. 将生成的表或得分与预期输出进行比较。
4. 当 PlaidCloud 输出与 Alteryx 桌面专用输出有意不同时，记录所有云原生工件差异。

对于机器学习工作流：

1. 确认 ML Train 步骤已写入其单行模型表，并查看记录的训练指标。
2. 将 ML Score 预测列与 Alteryx 得分进行比较。对于 XGBoost 模型，预期结果在统计上等价，而不是完全相同的值，请查看该步骤的映射说明。

## 解决验证差异

当验证发现差异时，请按以下顺序检查各项：

1. 缺失或不同的输入文件。
2. 不同的工作流变量值。
3. 不同的数据库快照或 API 响应。
4. 日期、时区、空值、舍入或字符串排序规则差异。
5. 空间参考或几何格式差异。
6. 报表、地图、专有格式或桌面专用渲染器的云原生工件差异。

纠正原因后，重新运行工作流并重复比较。

## 提升已验证的工作流

验证通过后：

1. 如果迁移是在暂存项目中完成的，请将工作流移动或复制到生产项目。
2. 确认生产环境的 Document 路径和凭据。
3. 为工作流设置计划。
4. 在运行历史中监控最初几次生产运行。
5. 将验证结果与迁移记录一并保留，以供审计和支持使用。
