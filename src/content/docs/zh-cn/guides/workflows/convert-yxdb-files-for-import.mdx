Alteryx 以两种格式写入 `.yxdb` 文件。经典格式（由原始引擎写入）已被充分了解，PlaidCloud 可直接导入。AMP 引擎写入的是较新的变体，其文件头为 `Alteryx e2 Database file`，该格式的规范是专有且未公开的，因此 Alteryx 之外的任何工具（包括 PlaidCloud）都无法读取。

迁移期间，您仍持有授权的 Alteryx Designer，而 Designer 可以读取这两种格式。请在停用 Designer 之前使用它一次，将 AMP 格式的文件重写为可移植的格式。

<Aside type="note">
  经典 `.yxdb` 文件可直接导入 PlaidCloud，无需转换。如果某个 `.yxdb` 导入时出现文件无法读取的错误，最可能的原因是它是 AMP 格式的文件。
</Aside>

## 识别 AMP 格式文件

- 生成该文件的工作流是在启用 AMP 引擎的情况下运行的。
- 同一个包中的其他 `.yxdb` 文件均可正常导入，而 PlaidCloud 在导入时报告该文件无法读取。
- 文件的前几个字节为 `Alteryx e2 Database file`，而不是 `Alteryx Database File`（在任何文本编辑器或十六进制编辑器中都可以看到）。

## 方案 A：在 Designer 中逐个重新保存文件

文件数量不多时，在 Designer 中逐个重新保存：

1. 在 Alteryx Designer 中，添加一个 **Input Data** 工具并选择该 `.yxdb` 文件。
2. 连接一个 **Output Data** 工具，并选择新的 `.yxdb` 路径。
3. 在 Output Data 工具的选项中，启用将文件保存为**与 Designer 18.1 及更早版本兼容**的选项。这会强制使用经典格式。
4. 运行工作流，然后将新文件导入 PlaidCloud。

在第 2 步中改为写入 CSV 而不是 `.yxdb` 也可以，这样可以跳过兼容性选项。

## 方案 B：使用可下载的工作流批量转换文件夹

文件较多时，下载预置的工作流并在 Designer 中运行：

<a href="/downloads/convert_yxdb_folder.yxmd" download>下载 convert_yxdb_folder.yxmd</a>

该工作流依次串联 **Directory** 工具、**Dynamic Input** 工具和 **Output Data** 工具，将文件夹中的每个 `.yxdb` 文件（无论是经典格式还是 AMP 格式）重写为名为 `converted_<original name>.csv` 的 CSV 文件。CSV 具有可移植性，PlaidCloud 可无损导入。

1. 在 Alteryx Designer 中打开 `convert_yxdb_folder.yxmd`。
2. 在 **Directory** 工具中，设置存放 `.yxdb` 文件的文件夹。
3. 在 **Dynamic Input** 工具中，将 Input Data Source Template 指向该文件夹中的任意一个 `.yxdb` 文件。
4. 在 **Output Data** 工具中，设置输出文件夹。
5. 运行工作流，然后将 CSV 上传到文档并导入。

<Aside type="caution">
  Dynamic Input 工具要求批处理中的每个文件都与模板文件具有相同的字段布局。布局不同的文件会被跳过并给出警告，Designer 的结果窗格会列出每个被跳过的文件。请将布局不同的文件分到各自的文件夹并配上各自的模板后再次运行，或使用方案 A 逐个重新保存这些遗留文件。
</Aside>

转换为 CSV 的文件会丢失 `.yxdb` 特有的类型信息（所有内容都以文本形式到达，并在导入时重新指定类型），因此请抽查导入的表的列类型，尤其是日期和高精度小数。
