如果工作流在处理过程中出现错误，工作流和出错的步骤上都会显示错误指示。PlaidCloud 可以对失败的步骤重试多次。当步骤访问的远程系统或数据可用性不高，或因未知原因间歇性失败时，这通常很有用。重试次数可设置为很多次，并可在两次重试之间添加从几秒到几小时的延迟。



服务器在运行中途丢失的步骤与重试分开处理：可安全重复执行的步骤会自动重新运行，不可重复执行的步骤则只失败一次，并显示 **已中断** 消息。请参阅[已中断的步骤](/zh-cn/guides/workflows/run-a-workflow/#已中断的步骤)。

当 PlaidCloud 因您可以自行修复的原因（例如缺少权限或设置无效）拒绝某个步骤时，步骤日志会用通俗的语言显示该消息，而不是带堆栈跟踪的服务器错误。如果 Model Loop、Model Run 或 Macro Run 步骤的子工作流失败，则会显示子工作流自己的错误消息，格式为“Child workflow run failed:”后跟该消息。

如果未选择重试，或已超过最大重试次数，该步骤将被标记为错误。此时 PlaidCloud 提供三个级别的错误处理：


* 出错时停止工作流
* 将步骤标记为错误，但继续处理工作流
* 将步骤标记为错误，并触发修正工作流流程，而不是继续当前工作流

## 停止工作流


步骤出错时停止工作流是最常见的做法，因为工作流通常应当无错误运行。这会停止工作流，并在步骤和工作流上都显示错误指示。错误也会显示在活动监视器中，但不会采取进一步操作。



## 继续处理


每个步骤都可以在步骤表单中设置为出错时继续。如果启用此复选框，任何步骤出错时都会被标记为错误，但工作流会将该错误视为步骤已完成并继续运行。当某些步骤执行的任务在数据缺失时可能出错、但对整体流程无害时，这通常很有用。



由于在这种情形下工作流出错后仍继续运行，工作流不会显示错误指示，而是继续显示运行指示。



## 触发修正工作流


在工作流设置中可以指定修正工作流，这样工作流一旦出错，就会立即停止处理当前工作流并开始处理修正工作流。请注意，如果某个步骤被标记为出错时继续，其失败不会触发修正工作流。只有那些失败后同样会导致整个工作流停止的步骤，才会触发修正流程。



修正工作流可以只用于通知相关人员发生了故障，也可以执行其他复杂处理，尝试自动纠正原工作流失败的根本原因。
