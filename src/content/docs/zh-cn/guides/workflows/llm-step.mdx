## 描述

**LLM 步骤** 将针对大语言模型运行提示词作为工作流中的一个步骤。您可以让模型限定范围地访问项目中的特定表、维度和文档，并为每一项选择 **读取**、**写入** 或两者兼有。模型读取所需数据，并在您授予 **写入** 权限的地方，将结果直接写回所选对象。无需配置单独的输出格式：启用写入的绑定 *就是* 该步骤的输出。

一个常见用途是，将财务表汇总为各业务单元的评述，并让模型把这些评述写入您以写入权限绑定的结果表（或文档文件）。

<Aside type="note">对项目数据（表、维度、文档）的限定范围访问适用于 **Anthropic** LLM 连接，这类连接通过安全连接器访问 PlaidCloud 的 MCP 工具。其他提供商仍然可以运行提示词并返回结构化 JSON，但不具备限定范围的数据访问能力：在这类连接上带有绑定的步骤会在保存时被拒绝，并且必须提供结果架构。</Aside>

## 开始之前

需要具备：

* **LLM 连接。** 该步骤需要类型为 **LLM** 的连接（例如 Anthropic）。连接中保存提供商 API 密钥、可选的默认模型以及 **代理访问** 级别。请参阅[连接](/zh-cn/guides/connections/)。
* **连接上的写入权限，仅当有任何绑定启用了写入时才需要。** 只有连接的代理访问为 **读取和写入** 时，绑定才能写入。**完整** 已弃用，将于 2027 年 1 月 15 日移除。**Read-only** 连接会在保存时拒绝写入绑定。
* **已创建好的目标对象。** 模型写入的是您选择的对象，即已有的表、维度或文档账户。请先创建并绑定目标；该步骤不会创建新对象。

## 添加 LLM 步骤

1. 打开工作流，转到 **Analyze Steps** 选项卡。
2. 在所需位置添加步骤，方法与添加标准转换相同。
3. 选择 **LLM 步骤** 作为步骤类型。编辑器会打开，包含三个部分：**LLM 请求**、**Bindings** 和 **限制**。

## 配置请求

在 **LLM 请求** 分组中：

* **LLM 连接**（*必填*）：该步骤使用的 LLM 连接。
* **模型**（*可选*）：特定的模型名称，例如 `claude-opus-4-7`。留空则使用连接的默认模型。
* **提示词**（*必填*）：发送给模型的指令。可以用 `{{tables.NAME}}`、`{{dimensions.NAME}}` 和 `{{documents.NAME}}` 在行内引用已绑定的对象；每个引用都必须与下面声明的某个绑定相匹配。请明确告诉模型要写什么、写到哪里（例如“向 `summary` 表中为每个业务单元写入一行”）。
* **Result schema**（*对 Anthropic 连接为可选；对其他提供商为必填*）：运行结构化摘要的 JSON 架构，用于留档。如果提供，其根必须是带有 `"type": "object"` 的 JSON 对象。对于 Anthropic 连接，如果模型的实际工作是通过 MCP 进行写入，可以将其留空；其他提供商没有 MCP 访问权限，结构化响应是它们唯一的输出，因此必须提供架构。

## 绑定项目数据

**Bindings** 部分用于授予访问权限，并选择步骤可以读取和写入的内容。它包含三个分组：**表**、**维度** 和 **文档**，每个分组都有 **添加** 按钮。每一行包含：

* 用于选择对象的 **选择器**：表选择器、维度选择器，或（对于文档）账户和路径浏览器。无需再手动输入 ID。
* **名称**：在提示词中引用的标签（`{{tables.NAME}}`）。
* **读取** 和 **写入** 复选框。勾选 **读取** 允许模型读取该对象，勾选 **写入** 允许模型向该对象写入，也可以两者都勾选。始终至少设置其中一项。
* 对于文档，还有一个 **格式** 提示（例如 `pdf`）。

模型通过 MCP 工具向各类对象写入的方式：

| 绑定 | 模型的写入方式 |
|---------|----------------------|
| **表**（写入） | 插入行，通常是通过 `SELECT` 生成要添加到所绑定表的行。 |
| **维度**（写入） | 在所绑定维度的层次结构中添加或更新节点。 |
| **文档**（写入） | 将文件上传到所绑定的文档账户和路径。 |

<Aside type="caution">访问权限严格限定于您绑定的对象，并按复选框区分：模型只能读取已绑定读取的对象，只能写入已绑定写入的对象。它无法访问您未绑定的对象，也无法写入只读绑定。</Aside>

## 限制

**限制** 分组用于约束请求：

* **最大输出令牌数**：模型可返回的最大响应长度（1,024 到 128,000；默认 16,000）。
* **凭据 TTL（秒）**：该步骤限定范围的临时数据访问凭据保持有效的时长（60 到 3,600；默认 1,800）。步骤的作业受此时间窗口约束，因此应设置得足够长以便模型完成，但不要超过必要时长。

## 运行步骤

LLM 步骤的运行方式与其他步骤相同，既可以作为完整工作流运行的一部分，也可以单独运行（请参阅[在工作流中运行单个步骤](/zh-cn/guides/workflows/running-one-step-in-a-workflow/)）。运行时，该步骤会签发一个短期的、限定范围的凭据，将您的提示词和已绑定的对象发送给模型，模型直接通过 MCP 工具进行读取和写入。步骤结束后凭据会立即撤销。模型调用在其自己的作业中运行，因此长时间运行的步骤不会占用工作流运行器。

<Aside type="caution">每次运行都会对您的 LLM 提供商发起真实的、计费的调用，并写入您绑定的对象。请像对待其他任何转换目标一样对待写入绑定，并在将步骤指向生产数据之前，先在临时表上测试。</Aside>
