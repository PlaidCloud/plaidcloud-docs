PlaidCloud 会将 Alteryx 分析应用的问题转换为受控的工作流变量。用户可以在运行前设置这些变量，然后 PlaidCloud 会将这些值应用于公式、筛选器、文件路径、条件、宏参数以及下游步骤设置。

<Aside type="note">
  转换后的应用输入专为可重复的云端运行而设计。计划运行的工作流请使用已保存的变量值，交互式运行请使用受控的用户输入。
</Aside>

## App Runner 前端

转换 Alteryx 分析应用（`.yxwz`）时，也会将其界面具体化为一个已发布的 Panel “App Runner”，这是一个可用的输入表单，它收集与 Alteryx 问题相同的值，并用这些值运行转换后的工作流。该前端会作为转换的一部分自动获得；没有输入控件的应用会被跳过。

应用的问题会成为 App Runner 控件：文本、数值、日期、复选框、单选按钮、下拉列表、列表框、树、文件浏览和文件夹浏览。每个控件都会写入转换后的步骤所读取的工作流变量，因此通过 App Runner 运行所驱动的逻辑，与手动设置变量相同。未绑定到真实工作流变量的控件会带有可见的说明，而不是悄无声息地收集一个无处可去的值，请审核它并将其指向预期的变量。

表单按应用作者自己的分组方式布局，即作者构建应用时使用的选项卡和带标签的框，作者的说明文字（Alteryx Label 工具）会与其所描述的问题一起显示在表单上。应用在设计时固定的问题（例如没有界面问题驱动的 Detour）根本不会作为问题显示。

表单打开时显示工作流变量上已保存的值：除非有人保存了其他值，否则为作者的默认值；没有已保存值的问题则为空白。如果已保存的值不再与问题的某个选项相符，则会被忽略，而不是显示为过时的选择。数值问题会强制执行作者设置的最小值、最大值和步长，因此限定在小范围内的问题无法在该范围之外作答。

在转换后的工作流出现分支的地方，App Runner 会将该分支显示为带标签的选项，因此运行所走的路径是在运行时选择的，与 Alteryx 应用选择路径的方式相同。

### 文件和文件夹问题

每个文件或文件夹问题都有一个**浏览**按钮，可打开文档浏览器，因此您可以选取路径，而不必凭记忆输入。

- 浏览会提供您可访问的文档账户，默认为应用自己的账户，并允许您在它们之间切换。
- 它会在问题当前答案所指向的文件夹处打开；如果问题尚无答案，则在账户顶层打开。
- 顶部的路径导航可逐级返回上层。在列表中选择文件夹会将其打开；选择文件则会选中该文件。
- 在您按下**选择**之前，它会显示将要填入的路径。未高亮任何项时，“选择”会采用您当前查看的文件夹，这就是选择账户顶层的方法。
- 如果无法列出某个文件夹，列表会说明并指出原因，并且“选择”不会填入您没有看到的路径。如果列表在 20 秒内没有得到应答，会提示账户没有响应。

## 运行应用

填写表单并按“运行”。

您的答案随运行一同发送，且仅对该次运行有效。它们绝不会保存在工作流上，因此一个人的答案绝不会影响另一个人的运行，而且运行应用也不需要更改工作流的权限，这对[限制行的项目](/zh-cn/administration/access/managing-security-groups-and-assignments/#谁可以更改限制行的项目)很重要，因为这类项目只有其架构师才能更改。要更改表单打开时显示的值，请按下文所述将它们保存在工作流上。

答案会在运行开始**之前**进行检查。从未回答的选择题会在运行开始前阻止运行并指明名称，而不是在可能耗时将近一小时的运行中途才被发现。

运行期间，表单会显示进度条、按工作流总步骤数统计的 `N of M steps`、已用时间，以及当前正在运行的一个或多个步骤。只有在运行进行时，“暂停”和“停止”才会出现在“运行”旁边；运行暂停时，“暂停”会变为“恢复”。

失败的步骤会在失败时立即在表单上指明名称，运行结束时，表单会引用每个失败步骤所报告的内容。无需打开工作流就能知道它为何停止。因前面的步骤失败而无法运行的步骤会单独显示为未运行，而不是失败，并且它们仍计入进度条，因此进度条会走到终点。

如果您关闭页面或断开连接，运行仍会继续。在该运行仍在进行时再次打开应用，会显示带有“暂停”和“停止”的运行中状态，而不是空闲的表单。

“运行”旁边的**打开工作流**链接会在新选项卡中于 PlaidCloud 里打开底层工作流；如果是 DAG 工作流，则在其画布上打开。即使表单自身的运行视图已停止更新，它也能正常使用。

仍然可以按下文所述通过设置变量直接运行工作流；App Runner 是一种额外的、应用式的入口。

## 保持应用为最新

App Runner 应用是一个 Panel 服务器应用，其 `app.py`、`widget_map.py` 和 `requirements.txt` 由 PlaidCloud 生成。当 PlaidCloud 更新 App Runner 时，您现有的应用会自行获取新版本：每个应用都会刷新为当前文件，并在 PlaidCloud 下次更新时重新构建，每当您在[我的 Panel 应用](/zh-cn/guides/panel-apps/using/#重新构建服务器应用)屏幕上**重新构建**或编辑该应用时也会如此。应用的设置及其工作流不受影响。

- **已锁定的应用保持原样。** 请先解锁，然后单击**重新构建**以将其更新。
- **对生成文件的手动编辑会被替换。** 刷新会将当前的 `app.py`、`widget_map.py` 和 `requirements.txt` 写入覆盖您的更改。应用的 Git 历史会保留早期版本。

## 转换后的输入类型

PlaidCloud 会将常见的 Alteryx 应用控件转换为带类型的工作流输入：

- 文本框成为文本变量。
- 数值控件成为数值变量。
- 日期控件成为 ISO 日期变量。
- 复选框、单选按钮、下拉列表、列表框和树成为受控选项变量。
- 文件浏览控件成为 Document 文件变量。
- 文件夹浏览控件成为 Document 文件夹变量。

转换后的工作流会在 Alteryx 应用使用原始问题值的任何位置使用这些变量。

## 运行前设置值

运行转换后的应用工作流之前：

1. 打开转换后的工作流。
2. 审核工作流变量。
3. 设置必需的文本、数值、日期、选项、文件和文件夹值。
4. 确认 Document 文件和文件夹路径指向导入的依赖项位置或其他经批准的 Document 路径。
5. 运行工作流。

对于计划运行，请保存每次计划运行时应使用的变量值。

## 条件、警告和错误

Alteryx 应用条件和错误检查会转换为 PlaidCloud 步骤条件。条件可以：

- 允许工作流继续。
- 发出警告消息。
- 在应用规则要求时，以明确的错误停止工作流。
- 通过其他分支路由执行。

借助这一行为，可以在 PlaidCloud 中运行工作流的同时保留应用级验证。

## 文件和文件夹输入

文件和文件夹问题使用 Document 路径：

- 文件输入从 Document 中选择一个文件。
- 文件夹输入选择一个 Document 文件夹。
- 导入的桌面依赖项存储在导入期间选定的 Document 路径中。
- 动态输入步骤可以使用变量在运行时解析最终的 Document 路径。

这使转换后的应用可在不同用户和计划运行之间移植。

## 宏参数

当转换后的应用调用宏时，应用变量可以为宏参数提供值。PlaidCloud 通过宏输入和控制参数处理，将这些值传递到生成的宏工作流中。

并发的宏运行相互隔离，因此多个工作流运行可以使用同一个转换后的宏，而不会共享中间状态。

## 验证清单

对于每个转换后的应用，请确认：

- 每个预期的问题都显示为一个工作流变量。
- 在配置了默认值的地方，默认值与原始应用一致。
- 受控列表包含预期的选项。
- 文件和文件夹变量指向 Document 路径。
- 条件会产生预期的消息、警告或停止行为。
- 对于所选的变量值，输出一致性验证通过。
