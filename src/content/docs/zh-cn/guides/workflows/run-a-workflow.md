可以通过两种方式触发完整的工作流运行：在**工作流**层次结构中点击运行图标，或在具体工作流的**操作**菜单中选择 **Run All**。



也可以点击工作流表格顶部的 **Toggle Start/Stop** 按钮。该切换按钮会停止正在运行的工作流，或启动工作流。

如果对已在运行的工作流点击**运行**，PlaidCloud 会提示该工作流正在运行，而不会启动第二次运行。

## 选择过账模式

每次运行都带有一个 ERP 过账模式。要在 PlaidCloud 中选择过账模式，请使用工作流右键菜单中的**按过账模式运行**，或工作流画布上的运行模式按钮；直接使用**启动工作流**或**运行工作流**则按“实时”模式请求，仍受下文所述项目上限的约束。通过运行 API 或助手启动运行时，同样可以选择模式。

| 模式 | 效果 |
|---|---|
| 实时 | 过账步骤照常过账。这是默认模式。 |
| 模拟 | 每个 ERP 过账步骤都会构建并验证它将要过账的内容，但不提交任何数据，也不会连接 ERP。将要过账的分录会记录在 [ERP 过账历史](/zh-cn/guides/connections/erp-post-history/)中并标记为模拟，便于在实时运行前先行审阅。 |
| 关闭 | 完全跳过过账步骤。 |

项目也有自己的过账模式上限，由对未锁定项目具有写入权限的任何成员通过项目 API 或助手设置。上限只会让运行更安全，绝不会放宽限制：运行的实际模式取您所选模式与项目上限中更严格的一个，因此即使以“实时”模式启动运行，上限为“模拟”的项目仍会保持模拟。

[计划事件](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)保留自己的过账模式，因此设为“模拟”的计划每次触发时都以模拟方式运行。

该模式会延续到运行涉及的所有内容。子工作流、宏，以及 **Run Model**、**Conditional Run Model** 和 **Loop Model** 步骤都继承父运行的模式，停止后[恢复](#暂停停止和恢复)的运行也是如此——模拟运行在其内部任何位置都无法真正过账。

:::caution
SAP 过账、SAP 附件和通用 SAP RFC 步骤不支持试运行。在“模拟”或“关闭”模式下，这些步骤会被直接跳过，因为 SAP 自带的测试标志仍会打开到 SAP 的真实连接——跳过步骤是确保模拟运行绝不会到达 SAP 的唯一办法。
:::

:::note
每个 ERP 过账步骤还有自己的“仅验证”设置（在某些步骤中标为“预览”或“仅测试模式”），与上述运行的过账模式相互独立。步骤编辑器始终会明确保存该设置。通过其他方式写入的步骤配置——REST API、MCP 或工作流包导入——如果完全省略该设置，现在同样默认为预览，而不是实时过账。
:::

## 授权项目过账

工作流运行是以项目的身份而不是以启动者的身份向 ERP 过账。运行过账之前，项目需要为其过账步骤使用的每个 ERP 连接和环境取得授权。没有授权时，步骤会失败，并提示“This project isn't authorized to post to connection …”，同时指明连接和环境。**Call SAP Financial Document Attachment**、**Call SAP Master Data Table RFC** 和 **Call SAP RFC** 步骤不需要授权。

要授权项目，请打开其主页，在 **ERP过账**下选择 **ERP 写入授权**。每一行对应一个环境中的一个连接。勾选**已授权**即允许项目在该处过账，取消勾选则停止。**授权人**和**授权时间**显示最近一次授权的人和时间。

- 该按钮向项目的架构师和工作区管理员显示，但只有架构师可以更改授权，且仅限项目未锁定时。不是架构师的工作区管理员可以先将自己添加为架构师。
- 选中某一行以授权或取消授权不会重新加载列表：滚动位置和您选择的列排序保持不变。窗口可以调整大小，关于公开项目的说明会完整换行显示。
- 要授权某个连接，您自己也需要对它具有写入权限：您拥有该连接，或该连接已按名称或通过您所属的某个安全组与您共享。设为**所有工作区成员**的连接不算数。
- 设为**所有工作区成员**的项目与其他项目一样可以授权。每位成员都是它的架构师，因此任何对某连接具有写入权限的成员都可以为该项目授权该连接。一旦授权，任何成员都可以从该项目的工作流向该连接过账，窗口会在网格上方说明这一点。
- 使用表数据或维度成员创建、且仅对您私有的新副本，会保留您自己有权授予的源项目授权，并且如果源项目为实时，副本会以模拟模式创建——请参阅[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。任何其他副本，或由项目归档创建的项目，都不带任何授权。过账之前请先授权。

## 跟踪步骤的状态

工作流运行时，每个步骤都带有一个状态图标，显示其所处阶段以及已运行的时长。将鼠标悬停在图标上可查看相关消息。

| 状态 | 含义 |
|---|---|
| 等待中 | 步骤已排队，尚未开始。 |
| 运行中 | 步骤正在工作，时长会随之递增。 |
| 已完成 | 步骤已成功完成。 |
| 警告 | 步骤已完成，但标记了值得在[工作流日志](/zh-cn/guides/workflows/viewing-workflow-log/)中查看的内容。 |
| 错误 | 步骤失败。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。 |
| 已跳过 | 步骤被略过——它已被禁用，或未满足其运行条件。请参阅[跳过工作流中的步骤](/zh-cn/guides/workflows/skip-steps-in-a-workflow/)。 |
| 已继续 | 步骤失败，但设置为出错后继续，因此工作流继续执行。请参阅[出错后继续](/zh-cn/guides/workflows/continue-on-error/)。 |
| 已停止 | 运行在步骤完成之前被停止。 |
| 已放弃 | 步骤的执行被中断，永远不会完成。请恢复运行，或重新运行工作流。 |

打开的工作流视图会随运行进度自动刷新，因此您看到的状态始终保持最新，无需重新加载页面。

### 已放弃的步骤

当执行步骤的进程在运行中途消失时，该步骤会被标记为**已放弃**——最常见的原因是有人按下了**停止**，或平台维护中断了运行。步骤的时长停止增长，状态提示会说明发生了什么。

已放弃的步骤没有完成，也没有产生输出。它不是运行缓慢的步骤，也不是数据或配置的问题。

要继续这项工作，可以[**恢复**](#暂停停止和恢复)运行——已放弃的步骤会再次运行——或者重新运行整个工作流。两种做法都是安全的。

### 已中断的步骤

如果运行某个步骤的服务器在运行中途丢失，PlaidCloud 会在可以安全重复时自动重新运行该步骤：替换其输出的步骤最终得到的结果与一次干净的运行相同，因此无需检查任何内容。

无法安全重复的步骤不会重新运行。它会失败一次，并给出**已中断**消息，因为第二次运行可能会重复第一次尝试已写入的内容。输出名称或路径中包含 `{date}` 的步骤也视为不可安全重复，因为重新运行可能落在不同的日期。要恢复，请检查步骤的目标中第一次尝试写入了什么，必要时将其清理，然后[重新运行该步骤](/zh-cn/guides/workflows/running-one-step-in-a-workflow/)或**恢复**运行。

### 永远不会开始的步骤

步骤在等待工作进程期间，其状态消息显示为“Waiting for a worker… N min. No import worker has picked this step up yet.”（工作进程的类型与步骤相对应，例如导入或导出）。工作开始后，该消息即会消失。

如果某个步骤的作业永远无法开始，该步骤会连同原因一起失败，而不是无限期等待：

| 原因 | 大约在此时间后失败 |
|---|---|
| 没有工作进程接手导入或维度步骤的作业 | 40 分钟 |
| 步骤的 Pod 一直处于 Pending 状态 | 20 分钟 |
| 无法拉取步骤的镜像 | 5 分钟 |
| 没有为步骤创建 Pod | 20 分钟 |
| 没有运行器接手连接器（Singer）同步 | 30 分钟 |

连接器同步消息会指明是哪个同步。如果工作进程启动了作业后又消失，步骤同样会失败，并给出说明工作进程已停止的消息。导入和维度消息会提示“Use Run from here to retry.”

## 暂停、停止和恢复

工作流运行期间，可以**暂停**它，这样正在执行的步骤会完成而新步骤会等待；也可以**停止**它，这会取消已排队的步骤以及仍在运行的任何导入或导出作业。仍在排队的导入和维度步骤会被干净地取消，因此不会阻碍工作区中后续的导入和维度加载。停止还会停止该工作流已排队或正在运行的连接器（Singer）同步，这样同步不会在工作流停止后继续运行。

**恢复**会让已暂停、已停止或失败的运行从中断处继续，而不是从头开始。只要工作流最近一次运行以暂停、停止或错误状态结束，就可以使用。

“中断处”的含义取决于工作流的运行方式：

| 执行方式 | 恢复时 |
|---|---|
| 串行 | 从运行结束时正在执行的步骤重新开始，并从那里继续。如果该步骤位于某个分组内，恢复会接续包含它的整个顶层分组：分组中已成功完成的步骤保持不动，其余步骤运行，运行在该分组之后继续。 |
| 并行 | 重新运行所有尚未成功完成的步骤，已完成的步骤保持不动。 |
| 高级（图） | 重新运行失败的节点以及仍在等待它的所有节点，已完成的节点保持不动。 |

调用另一个工作流的步骤——**Run Model**、**Conditional Run Model** 和 **Loop Model**——会恢复它们所调用的工作流，而不是重新启动，无论嵌套多少层。循环步骤会恢复被中断的那次迭代，并跳过已完成的迭代。

当您恢复的工作流是作为另一个工作流的**嵌套子工作流**运行的——即由父工作流中的 **Run Model** 步骤调用——PlaidCloud 会提供**从链顶端恢复**。单独恢复子工作流无法继续父工作流的编排，因此该选项改为恢复顶层父工作流——即链的根——并从停止处继续整条链。恢复顶层工作流的行为保持不变。链顶端在同一项目内解析：跨入其他项目的链，会从项目内部分的顶端恢复。

恢复始终继续**原始**运行。它会重新运行该次运行中未成功完成的每个步骤——失败或已放弃的步骤会重新运行，而不是视为完成——在此期间单独重新运行某个步骤，不会改变下次恢复所接续的内容。

恢复的运行会在工作流的运行历史中记录为**新运行**，只包含它重新运行的步骤。原始运行保留自己的历史记录。

:::note
循环步骤按变量值匹配其已完成的迭代。如果循环所遍历的数据在原始运行与恢复之间发生了变化，无法再匹配的迭代将被重新运行，而不是被跳过。
:::
