可以通过两种方式触发完整的工作流运行：在**工作流**层次结构中单击运行图标，或在特定工作流的**操作**菜单中选择 **Run All**。



也可以单击工作流表顶部的 **Toggle Start/Stop** 按钮。此切换按钮会停止正在运行的工作流，或启动工作流。

如果对已在运行的工作流单击**运行**，PlaidCloud 会提示该工作流正在运行，而不会启动第二次运行。

## 选择过账模式

每次运行都带有 ERP 过账模式。要在 PlaidCloud 中选择过账模式，请使用工作流右键菜单中的**按过账模式运行**，或工作流画布上的运行模式按钮；直接使用**启动工作流**或**运行工作流**时，请求的是实时模式，仍受下文所述项目上限的约束。通过运行 API 或助手启动运行时，也可以选择模式。

| 模式 | 效果 |
|---|---|
| 实时 | 过账步骤按以往方式正常过账。这是默认模式。 |
| 模拟 | 每个 ERP 过账步骤都会构建并验证其将要过账的内容，然后不提交任何内容，也从不连接 ERP。将要过账的分录会被记录下来，以便在实时运行之前进行审阅：**过账凭证**步骤的记录在[过账登记簿](/zh-cn/guides/connections/posting-register/)中显示为**将过账**（请参阅[向 ERP 系统过账凭证](/zh-cn/guides/connections/post-documents/)），系统自己的过账步骤的记录在 [ERP 过账历史记录](/zh-cn/guides/connections/erp-post-history/)中并标记为模拟。 |
| 关闭 | 完全跳过过账步骤。 |

项目也有自己的过账模式上限，具有写入权限的任何成员都可以通过项目 API 或助手为未锁定的项目设置。该上限只会让运行更安全，绝不会更宽松：运行的有效模式取您所选模式与项目上限中限制更严格的一个，因此即使以实时模式启动运行，上限为模拟的项目仍保持模拟。

[计划事件](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)保留自己的过账模式，因此设置为模拟的计划每次触发时都以模拟方式运行。

该模式会贯穿运行涉及的所有内容。子工作流、宏，以及 **Run Model**、**Conditional Run Model** 和 **Loop Model** 步骤都会继承父运行的模式，停止后[恢复](#暂停停止和恢复)的运行也是如此——模拟运行在其内部任何位置都无法进行真实过账。

:::caution
SAP 过账、SAP 附件和通用 SAP RFC 步骤不支持试运行。在模拟或关闭模式下，这些步骤会被直接跳过，因为 SAP 自带的测试标志仍会打开与 SAP 的真实连接——跳过步骤是确保模拟运行永远不会触及 SAP 的唯一办法。
:::

:::note
每个 ERP 过账步骤还有自己的 Validate Only 设置（在某些步骤上标为 Preview 或 Test Only Mode），独立于上述运行的过账模式。步骤编辑器始终会显式保存此设置。通过其他方式（REST API、MCP 或工作流包导入）写入的步骤配置如果完全省略该设置，现在同样默认为预览而不是实际过账。**过账凭证**步骤没有这样的设置：是否过账由运行的模式及其系统自己的模式决定，请参阅[向 ERP 系统过账凭证](/zh-cn/guides/connections/post-documents/)。
:::

## 授权项目过账

工作流运行以项目的身份而不是启动者的身份向 ERP 过账。运行过账之前，项目需要为其过账步骤使用的每个 ERP 连接和环境获得授权。没有授权时，步骤会失败并提示“This project isn't authorized to post to connection …”，其中会指明连接和环境。**Call SAP Financial Document Attachment**、**Call SAP Master Data Table RFC** 和 **Call SAP RFC** 步骤不需要授权。

要授权项目，请打开其主页，在 **ERP过账**下选择 **ERP 写入授权**。每一行代表一个环境中的一个连接。勾选**已授权**即可允许项目在此处过账，取消勾选则停止。**授权人**和**授权时间**显示最近一次授权的人员和时间。

- 该按钮对项目的架构师和工作区管理员可见，但只有架构师可以更改授权，且仅限项目未锁定时。不是架构师的工作区管理员可以先将自己添加为架构师。
- 选择某一行进行授权或取消授权不会重新加载列表：滚动位置和您选择的列排序保持不变。窗口可以调整大小，关于公共项目的说明会完整换行显示。
- 要授权某个连接，您自己也需要拥有它的写入权限：您是其所有者，或者它按名称或通过您的某个安全组与您共享。设置为**所有工作区成员**的连接不算数。
- 设置为**所有工作区成员**的项目与其他项目一样进行授权。每个成员都是该项目的架构师，因此对某个连接具有写入权限的任何成员都可以为该项目授权此连接。一旦授权，任何成员都可以从该项目的工作流向该连接过账，窗口会在网格上方说明这一点。
- 使用表数据或维度成员创建、仅您私有的新副本，会保留源项目中您自己有权授予的授权；如果源项目为实时模式，副本将以模拟模式生成——请参阅[副本中的 ERP 写入授权](/zh-cn/guides/projects/managing-projects/#副本中的-erp-写入授权)。任何其他副本，或从项目归档创建的项目，都没有任何授权。过账之前请先授权。

## 跟踪步骤状态

工作流运行时，每个步骤都带有状态图标，显示其当前所处状态以及已运行的时长。将鼠标悬停在图标上可查看对应的消息。

| 状态 | 含义 |
|---|---|
| 等待中 | 步骤已排队，尚未开始。 |
| 运行中 | 步骤正在工作，其时长会持续增加。 |
| 已完成 | 步骤已成功完成。 |
| 警告 | 步骤已完成，但标记了值得在[工作流日志](/zh-cn/guides/workflows/viewing-workflow-log/)中查看的内容。 |
| 错误 | 步骤失败。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。 |
| 已跳过 | 步骤被略过——已被禁用，或未满足其运行条件。请参阅[跳过工作流中的步骤](/zh-cn/guides/workflows/skip-steps-in-a-workflow/)。 |
| 已继续 | 步骤失败，但设置为出错后继续，因此工作流继续执行。请参阅[出错后继续](/zh-cn/guides/workflows/continue-on-error/)。 |
| 已停止 | 运行在步骤完成之前被停止。 |
| 已放弃 | 步骤的执行被中断，因此永远不会完成。请恢复运行，或重新运行工作流。 |

打开的工作流视图会随运行进展自动刷新，因此无需重新加载页面，所看到的状态始终是最新的。

### 已放弃的步骤

当执行步骤的进程在运行中途消失时，该步骤会被标记为**已放弃**——最常见的原因是有人按下了**停止**，或平台维护中断了运行。步骤的时长不再增加，状态提示会说明发生了什么。

已放弃的步骤没有完成，也没有产生输出。它不是运行缓慢的步骤，也不是数据或配置的问题。

要继续这项工作，可以[**恢复**](#暂停停止和恢复)运行——已放弃的步骤会再次运行——或者重新运行整个工作流。两种方式都是安全的。

### 已中断的步骤

如果运行步骤的服务器在运行中途丢失，PlaidCloud 会在可以安全重复时自动重新运行该步骤：替换其输出的步骤最终得到的结果与一次干净的运行相同，因此无需检查任何内容。步骤的日志会在第二次尝试开始处显示一条警告：“Restarted: the server running this step stopped before it finished (e.g. out of memory or a restart); running it again from the start.”

无法安全重复的步骤不会被重新运行。它会失败一次，并给出**已中断**消息，因为再次运行可能会重复第一次尝试已写入的内容。输出名称或路径中包含 `{date}` 或 `{date_iso}` 的步骤被视为不能安全重复，因为重新运行时日期可能不同。要恢复，请检查步骤的目标中第一次尝试写入了什么，必要时进行清理，然后[重新运行该步骤](/zh-cn/guides/workflows/running-one-step-in-a-workflow/)或**恢复**运行。

### 永远无法启动的步骤

步骤在等待工作进程时，其状态消息显示“Waiting for a worker… N min. No import worker has picked this step up yet.”（工作进程的类型与步骤相对应，例如导入或导出）。工作开始后，该消息会清除。

如果步骤的作业永远无法启动，该步骤会连同原因一起失败，而不是永远等待：

| 原因 | 大约在多久后失败 |
|---|---|
| 没有工作进程接手导入或维度步骤的作业 | 40 分钟 |
| 步骤的 pod 一直处于 Pending 状态 | 20 分钟 |
| 无法拉取步骤的镜像 | 5 分钟 |
| 没有为步骤创建 pod | 20 分钟 |
| 没有运行器接手连接器（Singer）同步 | 30 分钟 |

连接器同步消息会指明是哪个同步。如果工作进程启动了作业后又消失了，步骤同样会失败，并给出说明工作进程已停止的消息。导入和维度的消息会说明“Use Run from here to retry.”

### 停止响应的运行

工作背后的进程消失后，运行绝不会一直停留在**正在运行**状态。如果运行工作流的服务器丢失，该运行会以失败结束。一次运行最长持续 12 小时：届时仍在运行的运行会失败，并显示“Run failed: still running at the 12-hour limit. Re-run the workflow.”

## 运行洞察

运行洞察显示工作流的一次运行把时间花在了哪里，以及哪些步骤比平时用时更长或更短。它把每个步骤与该步骤自身最近的运行对比，因此一个一向很慢的步骤不会被特别指出。

### 打开运行洞察

- 在画布上，单击工具栏中的**历史记录**。请参阅[可视化工作流设计器](/zh-cn/guides/workflows/advanced-workflows/)。
- 在**工作流**选项卡中，选择一个工作流，然后从**操作**菜单或右键菜单中选择**运行洞察**。
- 在主页上，选择工作流卡片上的**打开最近一次运行**。
- 在运行历史记录对话框中，在**运行次数**表里选择一次运行并选择**在洞察中打开**，或打开其所在行。
- 在关于缓慢运行的应用内 Weave 消息中，单击**打开运行**。请参阅[获知运行何时结束](/zh-cn/guides/ai-assistant/weave-findings/#运行结束时收到通知)。

对话框的标题为**运行历史记录**：工作流名称。其中的**洞察** | **运行次数**开关可在此视图与过去运行的表之间切换。从检查器打开的步骤自身运行历史记录只显示表。

### 阅读标题行和关注列表

标题行用一行文字给出这次运行的结果：**耗时** *时间*；运行期间为**已运行** *时间*；已停止的最近一次运行为**运行** *时间* **后停止**；或者为 **在** *工作流* **中失败**，指出失败所在的工作流。其下一句话说明突出的情况，例如比平时运行得更慢的步骤、花在等待上的时间，或者所有有历史记录的步骤都在各自的常规范围内运行。再往下是开始时间、工作流和步骤的数量，以及当某些步骤的历史记录太少而无法判断时，有多少这样的步骤。只要有任何内容需要查看，标题行旁边就会出现一个计数，格式为 *N* **项待查看**。

标题行旁边有一条近期运行的条带，上方带有说明文字。每根条形代表一次运行，其高度即该次运行的耗时，仅在日期变化处标注日期。单击条带中的某次运行即可打开它。红色顶端和 ✕ 标记失败的运行，虚线轮廓标记运行步骤数少于大多数近期运行的运行，因为它们无法与完整运行比较。

**需要关注**按以下顺序列出：先是失败，然后是超出常规的时间，最后是等待。每一项是一张卡片，显示其名称、损失的时间或**失败**、所处位置，以及其耗时条，其中灰色表示在常规范围内，琥珀色表示超出部分，失败项的耗时条为红色。自上次运行后已保存的步骤带有**保存于** *日期*标签。单击某张卡片即可在视图中选中它，所选卡片会高亮显示。

### 流程、时间线和表

视图上方的标题栏依次显示工作流名称、**对比对象**和**视图**，其中**流程**、**时间线**和**表**按钮用于选择视图，右侧是刷新按钮。

| 视图 | 显示内容 |
|---|---|
| **流程** | 以高度表示时间的方块。琥珀色表示超出步骤常规的时间。未展开但内部含有失败的方块显示 ✕ 和红色轮廓。过短而无法显示名称的失败或选中方块会被绘制得更高，图例会说明此时不按比例。如果某个步骤调用了其他工作流，**调用开销**切片就是该步骤在这些工作流之外自身花费的时间。在没有任何步骤运行的地方，**等待中**切片会显示这段空档；并行运行的工作流不会绘制该切片。 |
| **时间线** | 从运行开始起算的时钟时间。虚线轮廓表示该方块在对比运行中用了多长时间。 |
| **表** | 按调用顺序显示所有内容，列为**名称**、**本次运行**、**常规**、**额外**、**对比运行**和**状态**。 |

调用了其他工作流的工作流会把它们显示在其内部。双击工作流方块或选择**放大**即可在其内部查看，使用视图上方的路径返回。当多个按正常节奏运行的步骤聚在一起时，**流程**会把它们折叠为一个 *N* **个正常**方块；单击它，或单击路径右侧的**显示全部** *数量* **个方块**即可展开；该数字为视图中的全部方块数。**折叠正常方块**会再次将其折叠，该按钮仅在有内容可折叠时才会出现。

选中一个方块即可看到其详细信息面板。面板显示方块的名称和位置、一个带有下列标记之一的状态标签，以及**本次运行**、**常规**、**历史记录**、**超出常规**和**对比运行**中适用的行。随后是一条趋势线：对于该次运行自身的工作流，显示其近期完整运行，若本次运行已完成，则以圆点表示本次运行；对于有常规范围的步骤，则以色带显示该范围，并以圆点表示本次运行。备注说明该标记，按钮为**在其工作流中显示**、**显示其步骤**或**放大**、**打开工作流**和**查看运行日志**。**打开工作流**会在画布上打开该工作流，**查看运行日志**会打开其[日志](/zh-cn/guides/workflows/viewing-workflow-log/)。

### 标记的含义

| 标记 | 含义 |
|---|---|
| **失败** | 某个步骤以错误结束。面板会显示其消息，除非您的角色看不到该步骤的名称。 |
| **比常规慢** | 该步骤用时超出其常规范围。 |
| **全程变慢** | 工作流中的每个步骤都慢了大致相同的幅度，这指向整个工作流共有的某种因素，而不是某一个步骤。其步骤会显示**共同变慢的一部分**。 |
| **含慢步骤** | 其内部有**内部的慢步骤**的工作流。 |
| **正常** | 该步骤在其常规范围内运行。 |
| **更快** | 该步骤比其常规范围运行得更快。 |
| **历史记录不足** | 该步骤运行次数不够，没有常规范围，因此不作判断。 |
| **出错，已继续** | 该步骤失败，但已设置为[出错时继续](/zh-cn/guides/workflows/continue-on-error/)。 |
| **已跳过** | 该步骤被略过。 |
| **正在运行** | 该步骤尚未结束。 |

近期运行本就较慢或波动较大的步骤，可能不会被标记。在期末进行的运行与普通日子对比，可能显示为全程变慢。较早停止的运行显示为一次较短的运行，而不是已停止。

面板还可以解释某个标记。**等待中**是没有任何步骤在运行的时间，因此不能归咎于任何步骤。对于比常规慢的步骤，**写入行数**将其输出与常规行数对比；当行级安全性过滤了您可以读取的内容时，会省略此项。同样对于比常规慢的步骤，**自上次运行后已保存**表示该步骤在上一次运行之后、本次运行开始之前被保存过；记录显示的是一次保存，而不是改了什么。**工作内容不同**统计没有运行的步骤和运行了但没有执行任何工作的步骤，以各步骤的历史记录为基准；与另一次运行对比时，则以那次运行为基准。**并行运行**表示工作流的各个部分同时运行，因此它们的用时相加会超过时钟时间。**调用方不确定**表示历史记录无法显示是哪个步骤调用了某个工作流。**名称已隐藏**标记您的角色看不到名称的步骤或工作流，显示为**已隐藏的步骤**或**已隐藏的工作流**。

### 对比对象

**对比对象**设定一次运行以什么为衡量基准。其菜单按钮显示所做的选择：**常规**、**常规 + 上一次运行**，或**常规 +** *开始时间* **的运行**（所选运行的开始时间）。**常规**使用每个步骤最近的运行。**常规 + 上一次运行**和**常规 + 所选运行**还会加入该次运行中每个步骤的用时，**时间线**以轮廓表示，**表**则显示在**对比运行**下。**常规 + 所选运行**会打开一个近期运行列表供您挑选。

### 较大运行中的一个工作流

打开被另一个工作流调用的工作流时，洞察只显示该工作流在这次运行中的部分。**打开整个运行**会在启动该运行的工作流上重新打开对话框。

### 进行中的运行

仍在进行的运行，在对话框可见期间每 30 秒重新读取一次。您的缩放、选择和视图保持不变。从洞察切换到**运行次数**会停止更新，返回洞察时会重新读取该运行并继续更新。刷新按钮（标题栏右侧的圆形箭头）会从头重新加载该运行，重置缩放和选择，并再次折叠正常方块。

### 面向 AI 助手和 REST API

对话框之外也可以获得同样的概要：

- REST：`GET /rest/v1/analyze/workflow/run-insight`，带 `project_id` 和 `workflow_id`。`run_id` 指定运行（省略时为最近一次），`baseline` 为 `typical`、`previous` 或 `run:<id>`。
- MCP：`workflow_describe`，带 `include=['run_insight']`，以及可选的 `run_id` 和 `baseline`。

每个工作流和步骤都会返回其用时、在运行中的位置、对照自身历史记录得出的判断，以及理由。不存在的运行，或没有步骤行的运行，会返回无概要和一条警告，而不是错误。

## 暂停、停止和恢复

工作流运行时，可以**暂停**它，使进行中的步骤完成而新步骤等待；也可以**停止**它，这会取消已排队的步骤，并在几秒内取消仍在运行的任何导入或导出作业，连同导出正在读取的仓库查询。仍在排队的导入和维度步骤会被干净地取消，因此不会阻碍工作区中后续的导入和维度加载。停止还会停止工作流中已排队或正在运行的连接器（Singer）同步，因此工作流停止后同步不会继续运行。

按下**停止**后，正在运行的导入或导出作业不会再开始新的写入：导出不会上传文件，导入不会加载表。已在进行的写入会先完成，因此不会有文件、表或维度只写了一半。多文件导出或多个表的导出会保留其已写入的文件。中途停止的多文件 CSV 导出已清空其文件夹，因此该文件夹中只包含这些文件，不包含先前运行留下的文件。维度加载以及 MongoDB 或 Kafka 导出是边处理边写入的，因此一旦开始就会运行到结束。**导入 SQL**或**导入外部数据库表**步骤会在源数据库返回其正在读取的内容后停止，因为 PlaidCloud 不会取消源数据库的查询。在 Databend 上，由 Databend 自己写入文档账户的导出是一次写入，因此会运行到结束并写入其文件。

一个宏可能同时在多处运行，由其他工作流调用，或由**宏：并发运行**步骤调用。停止该宏会停止它所有正在运行的副本。停止其中一个副本只会停止该副本及其启动的内容，而调用它的工作流会继续运行；**Macro Concurrent** 步骤放弃一个已停止响应的副本时也是如此。仅在其他工作流内部运行的宏会在工作流列表中显示为**正在运行**，并提供**停止**；打开它会显示每个步骤最近一次运行的状态、开始时间和结束时间。

**恢复**会让已暂停、已停止或失败的运行从中断处继续，而不是从头开始。只要工作流的上一次运行以暂停、停止或错误状态结束，就可以使用该功能。

“中断处”的含义取决于工作流的运行方式：

| 执行方式 | 恢复时 |
|---|---|
| 串行 | 从运行结束时正在运行的步骤重新开始，并从那里继续。如果该步骤位于某个组内，恢复会接手包含它的整个顶层组：组内已成功完成的步骤保持不动，其他步骤运行，运行在该组之后继续。 |
| 并行 | 重新运行每一个尚未成功完成的步骤，已完成的步骤保持不动。 |
| 高级（图） | 重新运行失败的节点以及仍在等待它的所有节点，已完成的节点保持不动。 |

调用另一个工作流的步骤——**Run Model**、**Conditional Run Model** 和 **Loop Model**——会恢复它们所调用的工作流，而不是重新启动，无论嵌套多少层。循环步骤会恢复被中断的迭代，并跳过已完成的迭代。

当恢复的工作流是作为另一个工作流的**嵌套子级**运行时（由父级中的 **Run Model** 步骤调用），PlaidCloud 会提供**从链顶端恢复**。单独恢复子工作流无法继续父级的编排，因此该选项会改为恢复顶层父级——即链的根——并从停止处继续整个链。恢复顶层工作流的行为不变。链顶端是在同一项目内确定的：跨入其他项目的链，会从项目内部分的顶端恢复。

恢复始终会继续**原始**运行。它会重新运行该运行中未成功完成的每一个步骤——失败或已放弃的步骤会被重新运行，而不是视为已完成——在此期间单独重新运行某个步骤，不会改变下一次恢复所接手的内容。子工作流也是如此：即使单独重新运行了它的某个步骤，恢复父级时仍会运行子工作流剩余的全部内容，而不只是那个步骤。

恢复的运行会作为**新运行**记录在工作流的运行历史记录中，其中只包含它重新运行的步骤。原始运行保留自己的历史记录条目。当一次运行多次调用同一个子工作流时，每次调用在子工作流的运行历史记录中都有自己的条目。循环步骤的各次迭代计为一次调用。

:::note
循环步骤根据变量值匹配其已完成的迭代。如果循环所迭代的数据在原始运行与恢复之间发生了变化，无法再匹配的迭代会被重新运行而不是跳过。
:::
