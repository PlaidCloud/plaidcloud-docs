可以通过两种方式触发完整的工作流运行：单击**工作流**层次结构中的运行图标，或在具体工作流的**操作**菜单中选择 **Run All**。



也可以单击工作流表顶部的 **Toggle Start/Stop** 按钮。该切换按钮可停止正在运行的工作流，或启动工作流。

如果对已在运行的工作流单击**运行**，PlaidCloud 会提示该工作流正在运行，而不会启动第二次运行。

## 选择过账模式

每次运行都带有一个 ERP 过账模式。要在 PlaidCloud 中选择过账模式，可使用工作流右键菜单中的**按过账模式运行**，或工作流画布上的运行模式按钮；直接使用**启动工作流**或**运行工作流**时，会请求 Live 模式，但仍受下文所述项目上限的约束。通过运行 API 或助手启动运行时，同样可以选择模式。

| 模式 | 效果 |
|---|---|
| Live | 过账步骤照常过账。这是默认模式。 |
| Simulate | 每个 ERP 过账步骤都会构建并验证其将要过账的内容，但不提交任何内容，也从不连接 ERP。将要过账的分录会记录在 [ERP 过账历史](/zh-cn/guides/connections/erp-post-history/)中并标记为模拟，以便在正式运行前审阅。 |
| Off | 完全跳过过账步骤。 |

项目也有自己的过账模式上限，具有未锁定项目写入权限的任何成员都可以通过项目 API 或助手进行设置。上限只会让运行更安全，绝不会更宽松：运行的有效模式取您所选模式与项目上限中限制更严格的一个，因此即使以 Live 模式启动运行，上限为 Simulate 的项目仍会保持模拟状态。

[计划事件](/zh-cn/administration/scheduled-events/event-scheduler/#erp过账模式)保留自己的过账模式，因此设置为 Simulate 的计划每次触发时都以模拟方式运行。

该模式会贯穿运行涉及的所有内容。子工作流、宏，以及 **Run Model**、**Conditional Run Model** 和 **Loop Model** 步骤都会继承父级运行的模式；停止后[恢复](#暂停停止和恢复)的运行也是如此，因此模拟运行在其内部任何位置都无法进行真实过账。

:::caution
SAP 过账、SAP 附件和通用 SAP RFC 步骤不支持试运行。在 Simulate 或 Off 模式下，这些步骤会被直接跳过，因为 SAP 自带的测试标志仍会打开与 SAP 的真实连接，只有跳过步骤才能确保模拟运行绝不会连到 SAP。
:::

:::note
单个 ERP 过账步骤还有自己的 Validate Only 设置（在某些步骤中标为 Preview 或 Test Only Mode），独立于上述运行过账模式。步骤编辑器始终会显式保存该设置。以其他方式（REST API、MCP 或工作流包导入）写入、且完全省略该设置的步骤配置，现在同样默认为预览，而不是真实过账。
:::

## 授权项目过账

工作流运行以项目的身份而不是启动者的身份向 ERP 过账。运行过账之前，项目需要为其过账步骤使用的每个 ERP 连接和环境获得授权。没有授权时，步骤会失败，并提示“This project isn't authorized to post to connection …”，同时指明连接和环境。**Call SAP Financial Document Attachment**、**Call SAP Master Data Table RFC** 和 **Call SAP RFC** 步骤不需要授权。

要授权项目，请打开其主页，在 **ERP过账**下选择 **ERP 写入授权**。每一行对应一个环境中的一个连接。勾选**已授权**即允许项目在该处过账，清除勾选则停止。**授权人**和**授权时间**显示最近一次授权的人员和时间。

- 该按钮向项目的架构师和工作区管理员显示，但只有架构师可以更改授权，且仅限项目未锁定时。不是架构师的工作区管理员可以先将自己添加为架构师。
- 选择某一行来授权或取消授权不会重新加载列表：滚动位置和所选的列排序都保持不变。窗口可以调整大小，关于公共项目的说明也会完整换行显示。
- 要授权某个连接，您自己也需要拥有该连接的写入权限：您是其所有者，或该连接按姓名或通过您所在的某个安全组与您共享。设置为**所有工作区成员**的连接不算数。
- 设置为**所有工作区成员**的项目与其他项目一样进行授权。每个成员都是该项目的架构师，因此任何对某连接具有写入权限的成员都可以为该项目授权使用该连接。授权之后，任何成员都可以从该项目的工作流向该连接过账，窗口会在网格上方说明这一点。
- 复制的项目或从项目归档创建的项目没有任何授权。过账之前请先为副本授权。

## 跟踪步骤状态

工作流运行时，每个步骤都带有一个状态图标，显示其所处阶段以及已运行的时长。将鼠标悬停在图标上可查看相关消息。

| 状态 | 含义 |
|---|---|
| 等待中 | 步骤已排队，尚未开始。 |
| 正在运行 | 步骤正在工作，其时长持续递增。 |
| 已完成 | 步骤成功完成。 |
| 警告 | 步骤已完成，但标记了值得在[工作流日志](/zh-cn/guides/workflows/viewing-workflow-log/)中阅读的内容。 |
| 错误 | 步骤失败。请参阅[管理步骤错误](/zh-cn/guides/workflows/managing-step-errors/)。 |
| 已跳过 | 步骤被略过，原因是已禁用，或未满足其运行条件。请参阅[跳过工作流中的步骤](/zh-cn/guides/workflows/skip-steps-in-a-workflow/)。 |
| 已继续 | 步骤失败，但已设置为出错后继续，因此工作流继续执行。请参阅[出错后继续](/zh-cn/guides/workflows/continue-on-error/)。 |
| 已停止 | 运行在步骤完成之前被停止。 |
| 已放弃 | 步骤的执行被中断，永远不会完成。请恢复运行，或重新运行工作流。 |

随着运行推进，打开的工作流视图会自动刷新，因此无需重新加载页面，看到的状态始终是最新的。

### 已放弃的步骤

当执行步骤的组件在运行中途消失时，该步骤会被标记为**已放弃**，最常见的原因是有人按了**停止**，或平台维护中断了运行。步骤的时长不再增加，状态提示会说明发生了什么。

已放弃的步骤没有完成，也没有产生输出。它不是运行缓慢的步骤，也不是数据或配置的问题。

要继续这项工作，可以[**恢复**](#暂停停止和恢复)运行（已放弃的步骤会再次运行），或重新运行整个工作流。两种方式都是安全的。

### 已中断的步骤

如果运行某个步骤的服务器在运行中途丢失，PlaidCloud 会在可以安全重复时自动重新运行该步骤：替换其输出的步骤最终得到的结果与一次干净运行相同，因此无需检查任何内容。

无法安全重复的步骤不会重新运行，而是以**中断**消息失败一次，因为第二次运行可能会重复第一次尝试已写入的内容。输出名称或路径中包含 `{date}` 的步骤算作不可安全重复，因为重新运行可能落在不同的日期。要恢复，请检查步骤的目标中第一次尝试写入了什么，必要时将其清理，然后[重新运行该步骤](/zh-cn/guides/workflows/running-one-step-in-a-workflow/)或**恢复**运行。

### 永远不会启动的步骤

如果约 40 分钟内没有工作器接手导入或维度步骤的作业，该步骤会失败，而不是一直显示**正在运行**直到 24 小时超时。如果工作器已启动作业后又消失，该步骤同样会失败，并给出说明工作器已停止的消息。这两条消息都写有“Use Run from here to retry.”

## 暂停、停止和恢复

工作流运行时，可以**暂停**它，这样进行中的步骤会完成，新步骤则等待；也可以**停止**它，这会取消已排队的步骤以及仍在运行的任何导入或导出作业。仍在排队的导入和维度步骤会被干净地取消，因此不会阻碍工作区中后续的导入和维度加载。

**恢复**会从中断处继续已暂停、已停止或已失败的运行，而不是重新开始。只要工作流的最近一次运行以暂停、停止或错误状态结束，就可以使用该功能。

“中断处”的含义取决于工作流的运行方式：

| 执行方式 | 恢复时 |
|---|---|
| 串行 | 从运行结束时正在运行的步骤重新开始，并由此继续。如果该步骤位于某个组内，恢复会接续包含它的整个顶层组：组内已成功完成的步骤保持不动，其余步骤运行，运行在该组之后继续。 |
| 并行 | 重新运行尚未成功完成的每个步骤，已完成的步骤保持不动。 |
| 高级（图） | 重新运行失败的节点以及仍在等待它的所有节点，已完成的节点保持不动。 |

调用其他工作流的步骤，即 **Run Model**、**Conditional Run Model** 和 **Loop Model**，会恢复其调用的工作流，而不是重新启动它，无论嵌套了多少层。循环步骤会恢复被中断的迭代，并跳过已完成的迭代。

当恢复的工作流是另一个工作流的**嵌套子工作流**（即由父级中的 **Run Model** 步骤调用）时，PlaidCloud 会提供**从链顶端恢复**。单独恢复子工作流无法继续父级的编排，因此该选项会改为恢复顶层父级（即链的根），并从停止处继续整个链。恢复顶层工作流的行为不变。链顶端在同一项目内确定：跨入另一个项目的链，会从项目内部分的顶端恢复。

恢复始终继续**原始**运行。它会重新运行该次运行中所有未成功完成的步骤（失败或已放弃的步骤会被重新运行，而不是视为已完成），期间单独重新运行某个步骤也不会改变恢复接下来要处理的内容。

恢复的运行会在工作流的运行历史中记录为**新运行**，只包含它重新运行的步骤。原始运行保留自己的历史条目。

:::note
循环步骤按变量值匹配其已完成的迭代。如果循环所遍历的数据在原始运行与恢复之间发生了变化，无法再匹配的迭代会被重新运行，而不是跳过。
:::
