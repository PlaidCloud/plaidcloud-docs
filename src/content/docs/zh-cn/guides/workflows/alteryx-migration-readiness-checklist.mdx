在将 Alteryx 工作流导入 PlaidCloud 之前，请先对照此清单检查。材料包越完整，PlaidCloud 创建高级工作流、宏工作流、基于文档的依赖项和受控运行时输入所需的后续工作就越少。

<Aside type="note">
  对于大型工作流组合，请先对整个组合运行一次此清单，再对每个高优先级的工作流系列分别运行一次。
</Aside>

## 收集工作流文件

收集属于此次迁移的所有工作流文件：

1. 标准工作流：`.yxmd`。
2. 分析应用：`.yxwz`。
3. 宏：`.yxmc`。
4. 被其他工作流引用的嵌套宏或共享宏。
5. 仍在生产环境中使用的工作流版本。

当工作流和宏相互调用时，请将它们放在一起。PlaidCloud 会利用这些关系生成宏工作流，并连接宏的输入端口和输出端口。

## 收集数据依赖项

打包工作流读取、写入或检查的文件：

- CSV、TSV、固定宽度、JSON、XML、Excel、Access、YXDB 以及数据库提取文件。
- Directory 或 Dynamic Input 工具使用的文件夹。
- 用于验证的预期输出文件。
- 报表资源，例如图像、PDF、模板和地图图层。
- 联接、公式、替换和匹配所使用的查找表和规则表。

如果工作流引用了本地桌面路径，请将该文件或文件夹包含在导入包中，并选择 PlaidCloud 存放它的文档路径。

## 收集空间数据附属文件

空间文件格式通常需要多个文件放在一起。请将所有附属文件放在同一文件夹中：

- Shapefile 文件组，例如 `.shp`、`.shx`、`.dbf` 和 `.prj`。
- MapInfo 文件组，例如 `.tab`、`.map`、`.id` 和 `.dat`。
- KML、GeoJSON 以及其他独立的空间文件。
- 工作流使用的投影或坐标参考文件。

缺少附属文件是造成空间验证差异的常见原因。

## 记录运行时输入

对于分析应用，请记录用户通常提供的值：

1. 文本、数字、日期、文件和文件夹输入。
2. 下拉列表、单选按钮、复选框、列表和树形选择。
3. 计划运行或可重复运行所使用的默认值。
4. 会触发条件、警告或错误的值。

PlaidCloud 会将这些输入转换为受控的工作流变量。

## 选择目标位置

导入之前，请确定：

1. 目标 PlaidCloud 项目。
2. 目标文档账户。
3. 用于存放导入文件的目标文档文件夹。
4. 已转换工作流和宏的命名约定。
5. 首次导入是暂存导入还是生产导入。

对于工作流组合迁移，请在文档中使用专用的迁移文件夹，以便于审核依赖项。

## 选择验证依据

对每个工作流，选择验证级别：

- 结构验证：确认工作流可转换为可运行的 PlaidCloud DAG。
- 输出一致性验证：将架构、行数和行值与可信的 Alteryx 输出进行比较。
- 产物验证：检查报表、PDF、图像、图表、地图或模型输出。

需要进行输出一致性验证时，请将预期输出与迁移包一并保存。

## 导入就绪检查清单

导入之前，请确认：

- 工作流、应用和宏文件均已就位。
- 被引用的宏均已就位。
- 输入文件和文件夹均已就位。
- 空间数据附属文件已归组放在一起。
- 迁移计划包含一致性验证时，预期输出已准备好。
- 已知分析应用的运行时输入值。
- 已选择目标项目和文档路径。
- 工作流所需的凭据或外部连接已在 PlaidCloud 中配置好。
