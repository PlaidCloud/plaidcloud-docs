PlaidCloud 从 Document 导入 Alteryx 工作流文件，并使用 Document 路径存放依赖项和产物。您可以将文件上传到 Document，让已连接 MCP 的代理帮您整理文件，或将 Document 直接连接到共享存储，例如 OneDrive、Google Drive、SharePoint、S3、Azure Blob 或 SFTP。

<Aside type="note">
  导入时使用 Document 路径选取器，可精确选择 PlaidCloud 读取源文件和存放生成产物的位置。
</Aside>

## 上传或连接共享存储

请选择最适合您迁移的源位置：

- 将包上传到文档账户。
- 将现有的共享存储位置连接为文档账户。
- 让已连接 MCP 的代理复制、移动、重命名并整理 Document 中已有的文件。

共享存储连接可以减少迁移准备工作，因为团队可以把文件保留在原本协作的位置：

- [Google Drive](/zh-cn/guides/documents/adding-accounts/add-google-drive-account/)
- [OneDrive 或 SharePoint](/zh-cn/guides/documents/adding-accounts/add-onedrive-account/)
- [AWS S3](/zh-cn/guides/documents/adding-accounts/add-aws-s3-account/)
- [Azure Blob Storage](/zh-cn/guides/documents/adding-accounts/add-azure-blob-storage-account/)
- [SFTP](/zh-cn/guides/documents/adding-accounts/add-sftp-account/)

## 推荐的文件夹结构

对每个迁移批次，请在导入之前采用类似下面的文件夹结构：

```text
workflow-package/
  workflows/
  macros/
  inputs/
  expected-outputs/
  reports/
  spatial/
```

此结构是可选的，但它能让评审和验证更轻松。

## 工作流和宏

将工作流文件和宏放在可预期的文件夹中：

- 将 `.yxmd` 和 `.yxwz` 文件放在 `workflows/` 中。
- 将 `.yxmc` 文件放在 `macros/` 中。
- 将嵌套的宏与其余宏库放在一起。
- 除非有意进行版本管理，否则不要让同名宏重复出现在同一个包中。

PlaidCloud 使用宏源文件来创建 PlaidCloud 宏工作流，并连接已转换工作流中的宏调用。

## 输入文件

将输入数据放在 `inputs/` 下：

- CSV、TSV、固定宽度、JSON、XML、Excel、Access、YXDB、SAS、SPSS、Stata、Avro、Parquet 和 HDF 文件。
- 公式、动态替换、模糊匹配或联接中使用的查找文件。
- Directory 和 Dynamic Input 工具引用的文件夹。
- Alteryx 平面 ASCII 文件：将 `.flat` 布局文件放在其所描述的数据旁边。列宽仅存在于该文件中，转换时会读取它来构建步骤。因此缺少布局文件仍可转换，但转换报告会指出需要上传的文件，请补充该文件并重新导入工作流，而不是仅仅重新运行。

PlaidCloud 导入该包时，已转换的步骤会指向所选的 Document 位置。

## 空间文件

将空间文件放在 `spatial/` 下，并让附属文件保持在一起：

- Shapefile：包含 `.shp`、`.shx`、`.dbf` 和 `.prj`。
- MapInfo 文件：包含 `.tab`、`.map`、`.id` 和 `.dat`。
- 若有投影文件和查找图层，请一并包含。
- 将 KML、GeoJSON 及其他空间输入保存在同一个依赖项包中。

不要把空间附属文件分散到不同文件夹中。PlaidCloud 需要完整的一组文件才能正确生成几何图形。

## 报表和产物资源

将报表资源放在 `reports/` 下：

- 报表编排工具使用的图像。
- PDF 输入。
- HTML 片段或模板。
- 报表地图使用的地图图层。
- 需要进行产物验证时的示例生成报表。

已转换的报表步骤会创建 PlaidCloud 产物，可从 Document 和工作流运行历史中查看。

## Excel 模板

如果任何工作流会将带格式的输出写入带样式的 Excel 模板（即保留格式的 [Export to Excel](/zh-cn/reference/workflow-steps/export/export-to-excel/) 和 [Export to Excel Sheets](/zh-cn/reference/workflow-steps/export/export-to-excel-sheets/) 步骤），请将这些模板工作簿与输入一起暂存到文档账户中。请把它们放在 `04_Templates` 文件夹中，与暂存源数据的 `03_Inputs` 相邻，以便已转换的步骤读取其要填充的模板。

<Aside type="caution">
  已转换的保留格式导出会在**运行时**从文档账户读取其模板。如果转换时模板缺失，该步骤会安全地回退为普通导出；但如果运行时已转换的保留格式导出所暂存的模板缺失，则会**明确报错失败**，而不会悄悄写出未设置格式的文件。运行已转换的工作流之前，请先暂存 `04_Templates`。
</Aside>

## 预期输出

将预期输出放在 `expected-outputs/` 下：

- 可信的 Alteryx 输出表。
- 预期的报表、PDF、地图、图像或图表。
- 关于可接受的行顺序、数值精度和日期处理方式的备注。

预期输出对结构验证是可选的，却是输出一致性验证的最佳依据。

## 外部连接

对于数据库、API 和云源工作流，请记录：

1. 源系统名称。
2. 连接类型。
3. 数据库、架构、表、端点或存储桶名称。
4. 凭据所有者或密钥名称。
5. 当输出一致性取决于某一时间点的源时，记录快照日期。

对于可重复的生产运行，请使用 PlaidCloud 连接或凭据。
