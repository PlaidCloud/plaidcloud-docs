每个已发布的应用都会显示在**我的 Panel 应用**屏幕中，并附有其**运行时**、**状态**、**标识**和时间戳。最左侧一列用于打开应用；该行的其余图标可用于锁定应用以防误改、编辑、移除，以及（对于服务器应用）重新构建、查看日志和查看使用指标。打开图标会反映应用的运行时，因此可以一眼区分 WASM 应用和服务器应用。

## 构建状态（服务器应用）

服务器应用的**状态**列会跟踪其构建过程，构建进行期间列表会自动刷新：

- **正在构建…** — PlaidCloud 正在将您的仓库构建为容器。此时应用还没有 URL。
- **就绪** — 构建成功。应用的 URL 已生效，该行会出现**打开**图标。
- **失败** — 构建未能完成。请检查入口点和分支，然后编辑应用以重新发布。

WASM 应用没有构建步骤，发布后即可使用。

## 重新构建服务器应用

点击服务器应用所在行的**重新构建**图标，即可在不更改设置的情况下重新构建并重新部署该应用。PlaidCloud 会再次构建相同的分支和入口点，在此期间应用状态会恢复为**正在构建…**，新构建生效后再切换回**就绪**。

在依赖项发生变化、基础镜像更新或构建偶发失败后，请使用**重新构建**。编辑并保存服务器应用同样会触发重新构建，但重新构建无需打开编辑表单。

对于 [App Runner](/zh-cn/guides/workflows/use-converted-alteryx-apps/#保持应用为最新) 应用（即为转换后的 Alteryx 应用生成的输入表单），**重新构建**和保存编辑都会先将其生成的文件刷新到当前的 App Runner 版本，然后再进行构建。PlaidCloud 自身更新时，也会对所有未锁定的 App Runner 应用执行同样的操作；已锁定的应用需要在解锁后进行**重新构建**。

## 锁定应用

点击应用所在行的**锁定**图标，可防止应用被意外更改。应用被锁定后：

- **编辑**、**移除**和**重新构建**会拒绝执行，并提示应用已锁定。
- **向服务器应用的分支推送不会触发重新构建** — 在您解锁应用之前，自动重新构建会被跳过。被跳过的推送不会运行任何构建，因此应用的构建日志中不会出现新内容；请在解锁后再次推送（或使用**重新构建**）以应用更改。
- 打开应用、查看其日志以及查看其使用指标都仍可正常使用 — 锁定只会阻止更改，不会限制查看者。

再次点击该图标即可解锁。图标会显示应用的当前状态：锁定时为闭合，未锁定时为打开。

锁定是防止意外的保护措施，例如误编辑、误删除，或在您演示应用时有 Git 推送落到该应用上，这与工作流和工作流步骤上的锁定相同。它**不是**安全控制：任何有权编辑 Panel 应用的人也可以将其解锁。

> 锁定不涵盖两种情况：锁定时**已在进行的构建**仍会完成并上线；**WASM** 应用的文件存放在其文档账户中，因此替换这些文件会改变正在运行的应用，而不会触及已锁定的记录。

## 打开应用

点击就绪应用所在行开头的**打开**图标，即可在新选项卡中启动该应用。

- 服务器应用的地址为 `https://<your-tenant-host>/serve/<slug>/`。
- 只有服务器应用**就绪**后，才会显示**打开**图标。

服务器应用在空闲时会缩容到零以节省资源，因此空闲一段时间后的首次打开需要先将其启动。在此期间，您会看到 **PlaidCloud 加载屏幕**（包含应用名称、进度指示器和您的工作区详情），而不是空白选项卡。应用一旦就绪就会自动出现（通常需要几秒钟，冷启动时最长约一分钟），之后会正常响应，直到下次进入空闲状态。

> 如果应用无法启动，加载屏幕会变为 **“此应用未能启动”** 消息和**重试**按钮，而不会一直转圈。如果问题持续出现，请编辑应用，检查其入口点和分支后重新发布，或联系您的 PlaidCloud 管理员。

### 外观

服务器 Panel 应用默认使用 PlaidCloud 现代的 **FAST** 设计，但当现有 CSS 依赖于 Panel 的**默认**样式时，可以通过应用的**设计**设置切换回该样式。主题（浅色、深色，或查看者可以切换的浅色/深色开关）需要在应用的模板中设置。相关写法请参阅创建指南中的[设置主题](/zh-cn/guides/panel-apps/creating/#设置主题浅色深色或切换开关)。如果应用的表或自定义样式是为浅色背景设计的，请将其固定为浅色。

## 查看日志（服务器应用）

点击服务器应用所在行的**查看日志**图标，即可打开其日志查看器。（WASM 应用完全在浏览器中运行，没有服务器日志，因此该图标只出现在服务器应用所在的行中。）

查看器有两个选项卡：

- **运行时**（显示在最前）— 正在运行的应用自身的输出：它记录的所有日志、打印的所有内容以及所有未捕获的错误。即使应用已缩容到零，这些内容也会保留，因此您可以回顾之前的会话做了什么。
- **构建** — 构建应用容器时的输出。可用它查看构建显示为**失败**的*原因*，例如某个依赖项无法安装。

每个选项卡都提供**信息 / 警告 / 错误**筛选器、**日志起始时间**时间范围（从最近一小时到 30 天，或全部）、**刷新**按钮，以及用于轮询新条目的**自动刷新**，在您观察运行中的应用或正在进行的构建时非常方便。最新的条目排在最前面。

> 如果无法捕获构建输出，“构建”选项卡会显示一条简短说明来解释原因，而不是显示为空。

### 阅读完整的日志消息

日志表会截断过长的行，以保持列表易读。选择某个日志行，即可在表格旁打开**详情窗格**，其中显示该条目的完整消息。对于表中放不下的内容（例如很长的错误消息或完整的堆栈跟踪），这是最简便的阅读方式，不会被截断。

### 复制日志行

您可以一次选择多个日志行，然后点击**复制**将它们放入剪贴板。调试应用时，若要将日志粘贴到与 AI 助手的对话中，或发送给您的团队或 PlaidCloud 支持人员，这会很方便。

### 日志行由谁触发

当您的应用让查看者登录时，每个日志行都会标记产生该会话的**用户**，因此您可以知道是哪位查看者遇到了某个特定的错误或警告。标记是尽力而为的：部分框架和启动阶段的日志行在任何查看者参与之前就已运行，可能不会显示用户。

## 使用指标（服务器应用）

点击服务器应用所在行的**使用指标**图标（位于**查看日志**旁边），即可查看该应用的使用情况。该视图汇总了以下内容：

- **唯一用户** — 有多少不同的人打开过该应用。
- **会话** — 该应用被打开的次数。
- **平均和中位会话时长** — 一次访问大致持续多久。
- **上次使用** — 应用最近一次被打开的时间。

汇总下方还提供按**用户**和按**天**的明细，方便您了解谁在使用该应用以及使用趋势如何随时间变化。

> 时长为近似值。无人使用时，服务器应用会进入空闲并缩容，因此并非总能观察到会话的确切结束时间；请将时长数据视为参考，而非精确测量值。

## 编辑应用

点击应用所在行的**铅笔**图标即可编辑。编辑表单与应用的运行时相匹配。

对于**服务器**应用，您可以更改名称、标识、分支、入口点、CPU、内存、设计、空闲时间窗口、公开标志、嵌入式服务域名和备忘。**Git 连接**在应用创建后即固定，并以只读方式显示。保存会重新构建应用，在新构建就绪之前，其状态会恢复为**正在构建…**。

## 移除应用

点击应用所在行的**减号**图标并确认；删除或取消发布应用时，始终会先要求您确认。移除服务器应用会拆除其构建和部署；移除 WASM 应用会取消发布其静态文件。应用的 URL 会立即失效。

MCP 工具 `panel_deployment_manage` 不再提供取消发布功能。请改为在此列表中移除应用。
