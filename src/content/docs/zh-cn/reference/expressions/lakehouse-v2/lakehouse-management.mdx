## 说明

**Lakehouse** 区域让您无需离开 PlaidCloud，即可通过点选操作管理工作区的 Lakehouse 计算资源和 Iceberg 目录。从主工具栏上的 **Lakehouse** 按钮打开。

窗口顶部的仓库选择器适用于每个选项卡。该区域分为七个选项卡：**查询**、**配置文件**、**目录**、**仓库**、**用户**、**加载**和**管理员**。


## 查询

监控正在运行的查询并浏览历史记录。该选项卡由可移动的分隔条分为上下两部分：

* **正在运行**：当前正在执行的查询。按您在工具栏中选择的间隔自动轮询。
* **历史记录**：最近完成的查询。

**查看查询的计划：**

1. 单击行首的 `Profile` 图标
2. 查询 SQL 会加载到**配置文件**选项卡；在那里可以运行 EXPLAIN 或 EXPLAIN ANALYZE

**终止正在运行的查询：**

1. 在**正在运行**表中选择一行或多行
2. 单击工具栏中的 `Kill selected`
3. 在对话框中确认


## 配置文件

对 SQL 语句运行 `EXPLAIN` 或 `EXPLAIN ANALYZE`，并将生成的计划可视化为热力图树。

1. 打开 **Lakehouse > 配置文件**
2. 粘贴或输入 SQL 语句
3. 单击 `EXPLAIN`（仅计划）或 `EXPLAIN ANALYZE`（计划加实际行数和耗时）

计划树会突出显示开销最大的节点，因此慢查询的瓶颈一目了然。


## 目录

浏览所选仓库的 Iceberg 目录。窗格左侧列出命名空间，右侧列出表，并配有用于创建和删除操作的操作栏。

**创建命名空间：**

1. 打开 **Lakehouse > 目录**
2. 单击 `New namespace`
3. 输入命名空间名称并确认

**删除表：**

1. 先选择命名空间，再选择表
2. 单击 `Drop table`
3. 在对话框中确认

选项卡底部的已删除表列表允许您在最近删除的表仍可恢复期间，使用 `UNDROP` 将其恢复。

<Aside>当所选仓库是工作区默认仓库时，删除命名空间、删除表等破坏性操作将被禁用。</Aside>


## 仓库

创建、列出和删除支撑 Lakehouse 的 Iceberg 仓库。

**创建仓库：**

1. 打开 **Lakehouse > 仓库**
2. 单击 `Add warehouse`
3. 输入仓库名称和存储配置
4. 单击 `Add`

**删除仓库：**

1. 选择仓库所在行
2. 单击 `Delete`
3. 在对话框中确认

<Aside>默认仓库受到保护，无法删除。</Aside>

<Aside title="空闲仓库自动缩容">仓库空闲一段时间后，其查询执行容量会缩减到较小的下限，并在查询返回时自动重新扩容，因此您未使用的空闲容量会被释放，而不是全天候计费。需要注意的是：对空闲了一段时间的仓库发出的第一个查询，可能需要稍长时间，等待容量重新上线。持续使用或繁忙的仓库不受影响，并且仓库在此期间始终可访问，绝不会因此下线。</Aside>


## 用户

管理从外部 SQL 客户端（如 DBeaver 等）连接到 Lakehouse 的数据库用户。基于密码的用户和通过 SSO 配置的用户都会列出。

**添加用户：**

1. 打开 **Lakehouse > 用户**
2. 单击 `Add user`
3. 输入用户名和密码
4. 单击 `Add`
5. 请保存密码：密码只显示一次，之后无法找回

**重置密码：**

1. 选择用户所在行
2. 单击 `Reset password`
3. 从对话框中保存新密码

**删除用户：**

1. 选择用户所在行
2. 单击 `Drop user`
3. 在对话框中确认


## 加载

一目了然地查看集群活动。该选项卡显示一排计数器（活动查询数、近期吞吐量），下方是按与**查询**选项卡相同的轮询间隔采样的迷你趋势图。


## 管理员

检查计算工作负载状态，并在需要时重启仓库计算资源。

工作负载表列出每个组件及其当前状态。**滚动重启**部分可用于循环重启所选仓库的计算 Pod。

**重启计算资源：**

1. 打开 **Lakehouse > 管理员**
2. 阅读中断警告
3. 在确认字段中输入仓库 ID
4. 单击 `Restart compute`

两次重启之间设有冷却时间，以防止意外的连续快速重启。剩余冷却时间显示在按钮旁边。

<Aside>滚动重启会短暂中断活动会话。确认之前，请先与用户协调。</Aside>

<Aside title="空闲缩容与正在运行的查询">自动空闲缩容（参见上文的**仓库**）仅在持续一段时间没有任何查询活动后才会生效，因此绝不会中断正在进行的查询。如果希望某个工作区的仓库始终保持满容量，请联系 PlaidCloud 支持团队，为该工作区禁用此功能。</Aside>
