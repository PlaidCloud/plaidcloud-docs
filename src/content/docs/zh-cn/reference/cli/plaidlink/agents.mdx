## 说明


有时需要从不允许外部访问的远程系统中访问数据或运行流程，这在防火墙后的企业环境中十分常见。PlaidCloud 通过 PlaidLink 实现这一能力，使您可以访问防火墙后的远程系统，或不希望由 PlaidCloud 直接访问的系统。



PlaidLink 采用基于代理的体系。也就是说，代理（即远程用户）安装在防火墙内或其他受限区域内的系统上。代理随后通过安全的 HTTPS websocket 连接，以出站方式发起与 PlaidCloud 的连接。其安全性与任何其他加密的网络连接相当，且通常无需开放非标准端口。获得访问权限之前，代理必须发送其代理标识符来表明身份。若代理通过身份验证，即可获准执行已批准的操作。



PlaidLink 可安装在 Windows、Unix 和 Linux 系统上，并可在低权限用户下运行。在 Windows 系统上，PlaidLink 可作为 Windows 服务运行，并可通过“服务”面板完全控制。在 Linux 或 Unix 系统上，它可作为守护进程运行。

PlaidLink 也可作为独立的 Docker 容器或 Kubernetes Pod 运行。



## 管理代理


**管理代理：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“PlaidLink 代理”

这将进入 **PlaidLink 代理表**，您可以在其中查看、修改可用代理列表，并获取其凭据。



## 创建代理


**创建代理：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“PlaidLink 代理”
4. 单击“Add PlaidLink Agent”
5. 填写必填字段
6. 单击“创建”
7. 将代理分配到所需的安全组，使其能够访问完成工作所需的资源
8. 将代理分配到所需的文档账户，使其能够访问完成工作所需的文档


<Aside type="danger">对于上述第 7 步和第 8 步，必须将 PlaidLink 代理分配到其执行预期任务所需的安全组和文档账户，否则将被拒绝访问。</Aside>

<Aside>新建代理表单中未包含的任何信息都将自动生成。</Aside>



## 获取代理凭据


要在远程系统上配置 PlaidLink 代理，必须先获取代理的标识信息以确保安全。这些信息包括公钥和私钥。



**获取这些密钥：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“PlaidLink 代理”
4. 单击编辑图标

这将打开一个表单，您可以在其中查看公钥和私钥的值。

私钥和 **查看 RPC 配置** 按钮仅对可编辑代理的成员显示；其他成员只能看到公钥。


## 重新生成代理凭据


建议定期重新生成公钥和私钥，并更新远程系统的配置，以保持安全性。



**重新生成凭据：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“PlaidLink 代理”
4. 单击重新生成图标

凭据重新生成后，可以用与获取新代理凭据相同的方式获取（见上文）。



## 启用和禁用代理


**禁用代理：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“PlaidLink 代理”
4. 取消选中“Active”复选框

<Aside>当代理未标记为活动状态时，远程系统将无法使用这些代理凭据进行连接</Aside>



## 代理环境


连接可以为每个环境保存不同的配置，因此切换项目的环境会一次性重新指向该项目使用的所有连接。代理也可以随之切换。


每个代理有两项设置：


- **Agent Group** — 由可相互替代的代理共享的名称。分组中的代理是同一工作的备选项，每个环境一个。
- **环境** — 此代理服务的连接环境。


步骤仍然指定一个具体的代理。工作流运行时，PlaidCloud 会查看该代理所属的分组，并选择服务于项目当前环境的成员。因此，项目从默认环境切换到 QA 后，其远程步骤将在 QA 机器上运行，无需编辑任何步骤。


对于名为 `Finance` 的分组，其中一个代理服务于 Default，另一个服务于 QA，指定其中任意一个的步骤都会在与项目匹配的代理上运行；即使步骤指定的是 QA 代理，项目切换回 Default 后也会在 Default 代理上运行。


**将代理分配到环境：**


1. 打开 Analyze
2. 选择“Tools”
3. 单击“PlaidLink 代理”
4. 打开代理
5. 将“Agent Group”设置为与该代理的备选项共享的名称，并将“环境”设置为此代理服务的环境
6. 在运行该代理的机器上，在 PlaidLink 配置文件中设置匹配的环境名称 — 请参阅下文的[匹配代理机器](#匹配代理机器)

<Aside>未设置分组的代理服务于所有环境，在您设置分组之前，所有代理都是如此。对于只运行单个代理的工作区，不会有任何变化。</Aside>

<Aside type="caution">设置分组后，分组中的每个代理（包括只有一个代理的分组）都会进行精确匹配。如果项目运行所在的环境没有分组中的任何代理提供服务，将会失败，并给出指明该分组和该环境的消息，而不会回退到步骤所指定的代理。这是有意为之——否则生产工作会悄悄地在测试机器上运行。请为项目运行所在的每个环境添加一个代理；对于应继续服务所有环境的代理，请将分组留空。</Aside>


将代理移出分组会缩小该分组的覆盖范围，因此其影响与添加代理同样重大。清除服务于默认环境的代理的分组，会使在该环境中运行的项目无处可解析，并在下次运行时失败。移除分组中的某个成员之前，请先将该环境移到分组中的另一个成员上。每次更改分组覆盖范围的保存，都会向您报告新的覆盖情况。


环境与连接共享，因此此处提供的环境名称与您配置连接时使用的环境名称相同。请参阅[创建和管理连接](/zh-cn/guides/connections/create-connection/#环境)。


### 匹配代理机器


此处设置的环境必须与该机器上 PlaidLink 服务所配置的环境一致。PlaidLink 会订阅其配置文件中所指定环境对应的那一个确切队列，因此如果代理记录显示 QA，而其机器仍配置为默认环境，则它监听的队列与发送工作的队列不同。步骤会等待，然后失败，并报告代理未接收作业。


在 PlaidLink 配置文件的 `environments` 块中，在该代理的条目里进行设置：


```yaml
environments:
  - name: QA
    agent_id: <agent identifier>
```


`name` 是 PlaidCloud 中显示的环境名称。省略时，代理服务于默认环境。更改后请重启 PlaidLink 服务。


<Aside type="note">单个 PlaidLink 服务可以在此块中包含多个条目，因此一台机器可以服务多个代理，或在多个环境中服务同一个代理。请参阅[运行多个代理](#运行多个代理)。</Aside>


## 运行多个代理


PlaidLink 的设计允许使用单个服务安装来运行多个代理。这种精简的安装方式使一次安装即可处理来自多个工作区的代理，以及具有不同任务执行权限级别的代理。

要启用多个代理，只需将代理凭据添加到 PlaidLink 配置文件中。

## 运行多个 PlaidLink 服务

与在一个 PlaidLink 服务中运行多个代理类似，也可以运行多个 PlaidLink 服务。

根据基于系统的安全措施的使用情况，或因网络访问限制而无法跨网络边界通信，有时需要这样做。

<Aside>通常，在一台机器上，更好的做法是在单个服务下运行多个代理，而不是运行多个服务。不过，根据使用场景，可能需要运行多个独立的服务。</Aside>

## 计算、内存和磁盘要求

PlaidLink 服务极为轻量，仅需极少的计算和内存资源即可运行。处理大量数据时，可能需要增加计算资源，尤其是内存。

通常情况下，代理使用 5% 的 CPU 和 200MB 内存即可顺畅运行。对于高强度的数据操作，建议分配一个完整的 CPU 和至少 4GB 内存。对于 Kubernetes 等动态资源分配系统，代理可使用可突发资源而非预留资源即可。

代理所需的磁盘空间同样极小。在传输大量数据时，代理操作会将磁盘空间用作数据缓冲区。通常，8GB 空间足以满足正常操作。对于高强度的数据操作，建议根据预期数据量相应扩大磁盘。由于这取决于 CPU 速度、网络速度、数据量等多种因素，因此没有固定数值。不过，可以从 20GB 开始，再根据情况调整。


## 网络要求

PlaidLink 代理设计为只需极少的配置即可运行。除允许标准 HTTPS 网络流量外，不需要任何特殊的 VPN 或网络配置。代理使用与普通基于浏览器的网络流量相同的协议进行通信。

代理服务始终由其主动向 PlaidCloud 发起通信，因此无需在防火墙中配置入站访问。

<Aside>有时防火墙规则会阻止所有访问，甚至包括标准 HTTPS 流量。如果代理在启动时报告无法连接 PlaidCloud，则需要与网络团队协作，开放 443 端口的流量。</Aside>
