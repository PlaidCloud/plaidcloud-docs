## 描述

通过您的 [Anaplan 连接](/zh-cn/guides/connections/anaplan/)读取一个或多个 Anaplan 列表，并将其加载到 PlaidCloud 维度中。**一个步骤读取整个复合层次结构**：按从根开始的顺序列出它所跨越的每个列表（例如先 Region，再 Country，再 Store），而不是将其拆分到多个步骤中。暂存表在每次运行时都会被整体替换，因此如果多个步骤指向同一个暂存表，每个步骤都会清除前一个步骤的行。

此步骤在步骤菜单的 **Anaplan** 下显示，标签为**列表读取**。

该步骤通过 Anaplan 的集成 API **直接连接云端**，不存在本地代理路径。

<Aside type="tip">
此连接器为只读，使用基本（用户名和密码）或 CA 证书凭据进行身份验证，请参阅[身份验证](/zh-cn/guides/connections/anaplan/#身份验证)。Anaplan 的请求配额在整个租户范围内共享，因此请将此步骤的计划与您的其他 Anaplan 工作流错开，请参阅[计划注意事项](/zh-cn/guides/connections/anaplan/#计划方面的注意事项)。
</Aside>

## 配置

### Anaplan 源

| 字段 | 必填 | 说明 |
|---|---|---|
| Anaplan 连接 | 是 | 用于读取的 [Anaplan 连接](/zh-cn/guides/connections/anaplan/)。 |
| 环境 | 否 | **项目环境**（默认）使用项目的连接环境。**固定环境**始终使用您选择的环境。请参阅[将步骤固定到单一环境](/zh-cn/guides/projects/managing-projects/#将步骤固定到单一环境)。 |
| 模型 | 否 | 覆盖连接上保存的模型 ID。可从连接实时发现，也可手动输入。 |
| 列表 | 是 | 层次结构所跨越的每个 Anaplan 列表，以有序列表形式给出。可添加从所选模型中发现的列表，或手动输入 ID，然后使用上移/下移重新排序。按从根开始的顺序列出更易阅读，但顺序不会改变加载的结果，因为在解析任何父级之前会先读取所有列表。 |
| 暂存表 | 是 | 原始的父级/子级/汇总/名称以及属性行会先加载到这里，然后再据此构建 PlaidCloud 维度。 |

### 目标 PlaidCloud 维度

| 字段 | 必填 | 说明 |
|---|---|---|
| 动态指定维度 | 二选一 | 目标维度名称，可包含在运行时解析的 `{variable}` 标记。默认选中。 |
| 使用特定维度 | 二选一 | 改为选取一个已存在的 PlaidCloud 维度。 |

## 预览

**源**选项卡上的**预览**会显示此列表读取将生成的列和数据类型，而不运行该步骤。在已锁定的项目中不可用。

## 此步骤无法表示的内容

| 限制 | 含义 |
|---|---|
| 每条边都以普通的 `+` 汇总 | Anaplan 列表层次结构不带每条边的权重或符号，没有任何内容可读，因此转换中不会丢失任何东西，但也无法表示更多内容。如果模型通过行项目或属性来表达排除或负向汇总，该逻辑不会带入维度，必须在下游重建。 |
| 不导入访问控制标志和子集成员关系 | 选择性访问的读/写标志以及每个项目的列表子集成员关系属于 Anaplan 元数据，而不是维度数据，将每个子集都作为单独的列导入，会在不断增长的共享命名空间中与真正的属性冲突。名称与其中任何一个冲突的真正列表属性会被拒绝，而不是悄悄地以另一个的名称加载。 |
| 行项目子集无法作为维度读取 | Anaplan 仅通过通用的维度项目端点公开它们，而不是作为此步骤可读取的列表。 |
| 此路径无法读取超过 1,000,000 条记录的列表 | 此步骤所读取的项目端点在超过该文档化上限时会直接拒绝，而不是返回部分结果，并且没有办法绕过分页，因此步骤会拒绝并指明该上限，而不是加载不完整的维度。在此期间，请在 Anaplan 中拆分该列表，或读取其子集。 |
| 一个节点只能位于一个父级之下 | 如果某个项目的父级名称与父级 ID 不一致、其父级位于此步骤不读取的列表中，或者其指定的父级根本不存在，则该项目会按名称被拒绝，而不是悄悄地重新挂到维度的根下。 |
| 不导入列表的顶级项目 | Anaplan 的顶级项目是位于列表中所有项目之上的汇总节点，而不是列表本身的项目，因此此步骤读取的项目从不会返回它。维度最终比 Anaplan 列表少一层，列表自身的根成为维度的根。当您读取的列表声明了顶级项目时，步骤会给出警告。 |
| 一起读取的所有列表中，节点 ID 必须唯一 | 节点的 ID 是项目的 Anaplan 代码，若没有代码则为其名称，而 Anaplan 代码只保证在单个列表内唯一。两个列表重复使用相同的简短代码时，会按名称被拒绝，而不是悄悄地合并为一个节点。 |
| 不支持备用层次结构 | 每个列表都加载到维度的主层次结构中。 |
| 只读 | 绝不会向 Anaplan 写回任何内容。 |
