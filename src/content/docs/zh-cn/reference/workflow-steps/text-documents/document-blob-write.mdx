## 说明

**文档：写入 Blob** 步骤是[文档：读取二进制对象](/zh-cn/reference/workflow-steps/text-documents/document-blob-extract/)的对应步骤。它将每个输入行某一列中的 Base64 字节写入文档账户中的文件，每行一个文件。输出表保持输入行不变。

步骤表单有三组选项：**表**、**写入** 和 **归档**。迁移的 KNIME 和 Alteryx 工作流使用此步骤来实现其二进制对象和文件写入器。

## 配置

- **源表** (`source`) 和 **输出表** (`target_frame`) — 要读取的表，以及原样写入输入行的表。**源列** (`source_columns`) 列出传递的列。
- **写入** — 写入本身，即 **每行一个文件** 或 **将行作为一个归档**。下面的设置保存在 `alteryx_config` 中。
  - **Blob 列** (`blob_field`) — 保存 Base64 字节的列。
  - **文件列** (`field`) — 指定每行文件名的列。
  - **文件列包含** (`method`) — **下方文件夹中的文件名** (`FileName`，默认)：文件列是放置在 **文件夹** (`path`) 中的文件名。**完整目标路径** (`Path`)：文件列是完整的目标路径。
  - **文件夹** (`path`) — 目标 `{account, path}`。
  - **已存在的文件** (`if_exists`) — 文件已存在时：**覆盖它** (`overwrite`，默认)、**使步骤失败** (`fail`) 或 **保持原样** (`skip`)。
  - **压缩** (`compress`) — **用 gzip 压缩每个文件** (`gz`) 会在写入每个文件之前，用 gzip 压缩其字节。
  - **以 < 开头的 Blob 是 XML 或 SVG 文本，而不是 Base64** (`xml_text`) — 以 `<` 开头的值按其 UTF-8 字节写入。

**将行作为一个归档** 会根据源行的 `Path` 和 `Blob` 列（以及用于命名条目的 `Selected` 和 `EntryName`，如果有），将源行写为一个归档，而不是每行一个文件。此时输出表包含 `ArchivePath` 和 `Blob`。由 **归档** 组设置，相关设置保存在 `alteryx_config.archive` 中：

  - **归档文档路径** (`destination`) — 归档的写入位置。
  - **格式** (`format`) — `zip`（默认）、`jar`、`tar`、`tar.gz`、`tar.bz2` 或 `cpio`。
  - **仅按文件名命名每个条目** (`flatten`)、**条目名称** (`truncate`) 和 **要去除的文件夹前缀** (`prefix`) — 如何根据路径构建条目名称。
  - **在条目中保留所选文件夹自身的名称** (`root`)、**条目命名所依据的文档** (`file`) 和 **有 EntryName 时按其命名条目** (`named`) — 对条目名称的进一步控制。
  - **空文件夹表** (`folders`) — 带有 `Path` 和 `Selected` 列的表，指定要作为条目添加的空文件夹。
  - **合并到现有归档** (`append`) — **否**、**条目冲突时中止** (`abort`) 或 **替换冲突的条目** (`overwrite`)。
