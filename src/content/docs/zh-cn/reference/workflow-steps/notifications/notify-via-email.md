## 描述


发送电子邮件通知。消息从 *[info@tartansolutions.com](mailto:info@tartansolutions.com)* 电子邮件账户发出，无需任何出站设置。



### 电子邮件地址


可指定任意数量的电子邮件收件人。可接受的分隔符包括分号 (;) 和逗号 (,)。



### 抄送、密送和回复地址

**抄送**（`cc_address`）、**密送**（`bcc_address`）和**回复地址**（`reply_to`）采用与收件人相同的地址格式，并接受项目变量和工作流变量。抄送和密送收件人收到相同的消息，回复则发送到回复地址。它们适用于纯文本正文和 Jinja 模板正文。请在**消息**选项卡的**更多电子邮件选项**中设置。

### 每行一封电子邮件

在**更多电子邮件选项**中，将**发送**（`request_source`）设置为**表的每行一封邮件**（`table`），并选择**驱动因素表**（`driver_table`），即可为表的每一行各发送一封电子邮件，而不是只发送一封。**最多发送的行数**（`row_limit`）限制所用的行数，默认为 10,000。驱动因素必须是表，而不是视图。

在地址、主题、消息和附件路径中使用 `{{row.column}}` 来填入每行的值。驱动因素表中不存在的列会导致步骤失败。没有收件人地址的行不会发送邮件，步骤完成时会给出指明该行的警告。

由行填入的附件路径（`{{row.column}}`）必须是单个已存在的文件，不能是文件夹，这样路径出错的行就不会把其他人的文件发出去。该路径的值为空、路径通过 `..` 跳出其文件夹，或文件缺失的行，会在不带附件的情况下发送，并给出指明该行的警告。逐行发送需要纯文本正文，不适用于 Jinja 模板正文。

### 消息


根据需要指定**主题**和**正文**。



请注意，项目变量和工作流变量都可用于此转换，主题行和消息正文中均可使用。



此外，正文中允许使用标准 HTML 代码，以进一步自定义电子邮件消息的外观。


### 附件


为电子邮件添加附件非常简单。从文档中选择要附加的文件或文件夹。如果选择文件夹，则文件夹的内容将作为单独的文件附加。路径支持变量替换，以便在发送个性化电子邮件时更好地控制文件附件。



若要附加多个文档，请勾选**将附件添加到电子邮件**，并在**更多电子邮件选项**的**更多附件**（`attachments`）下列出这些文档，每个文档都带有**账户 ID** 和**文档路径**；它们会与您选择的附件一起发送，路径同样可以使用变量和行标记。

### 优先级和纯文本

在**更多电子邮件选项**中，**优先级**（`priority`）将邮件标记为**低**、**普通**或**高**（`low`、`normal`、`high`），而将**发送格式**（`content_type`）设置为**纯文本**（`text`）则以纯文本发送正文，而不是 **HTML**（`html`，默认值）。

### 正文（Jinja 模板）


该步骤的正文以 **Jinja 模板**的形式编写，在一个或多个**框架**上渲染，生成内容丰富的 HTML 电子邮件。每个框架是一个具名的单表选择，包含**框架名称**、一个工作流表，以及可选的列选择、where 筛选器和聚合（不支持联接）。编辑器会直接打开此模板，包括框架列表、模板正文、实时预览和**向我发送测试**按钮，没有纯文本与模板之间的切换开关。**美化**按钮和插入面板（用于框架的 `render_table(...)`、`{{ cloud }}`、for 循环，以及货币/千位分隔/百分比/日期过滤器）有助于组织模板。

在模板中以 `frames['<Frame Name>'].rows` 和 `frames['<Frame Name>'].columns` 引用每个框架；只有一个框架的模板可以使用顶层的 `rows` / `columns`，它们绑定到第一个框架。该模板使用独立的沙盒渲染引擎，只有 `cloud` 会解析为工作区值，旧版的 `{project}` / `{model}` / `{date}` 标记在其中不会解析。在引入 Jinja 编写之前创建的步骤，打开时其旧正文会自动转换；无法安全转换的正文会保留为纯文本回退，并继续使用旧版 `{token}` 替换来发送。有关可用的模板变量、`render_table` 辅助函数、能通过电子邮件清理程序保留的 HTML 标签和属性，以及现有正文的迁移方式，请参阅[发送模板化 HTML 电子邮件通知](/zh-cn/guides/workflows/notify-email-templates/)。
