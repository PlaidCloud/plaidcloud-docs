## 描述

通过 [NetSuite 连接](/zh-cn/guides/connections/netsuite/)将 NetSuite 的总账交易行明细导入项目表，即余额背后的过账级别明细行，可用于对账、下钻或详细损益表。选择连接，指定目标表，并设置期间和子公司；步骤会拉取明细行并写入，无需编写或维护 SuiteQL。

这是预置的 [NetSuite 导入步骤](/zh-cn/reference/workflow-steps/netsuite/)之一。每个步骤都运行在共享的读取层之上，该层会为您刷新 OAuth 令牌、对大型结果分页并重试暂时性错误，因此无需手动调优，即可完整拉取整个期间的数据。如需期间余额而非明细行，请使用 [NetSuite：导入余额](/zh-cn/reference/workflow-steps/netsuite/import-balances/)。

## 配置

| 字段 | 是否必填 | 说明 |
|---|---|---|
| NetSuite 连接 | 是 | 用于读取的 NetSuite 连接，仅显示 NetSuite 类型的连接。 |
| 目标表 | 是 | 写入交易行的项目表。每次运行都会完全覆盖该表。 |
| 开始日期 | 否 | 要包含的最早交易日期，格式为 `YYYY-MM-DD`，含该日期。留空表示没有下限。与结束日期一起给出时，拉取会自动按日期分块，以保持在 NetSuite 的 SuiteQL 行数上限之内，参见下方的注意事项。 |
| 结束日期 | 否 | 要包含的最晚交易日期，格式为 `YYYY-MM-DD`，含该日期。留空表示没有上限。 |
| 子公司 | 否 | NetSuite 子公司内部 ID，用于将拉取范围限制为一家子公司。留空表示所有子公司。 |
| 会计账簿 | 否 | NetSuite 会计账簿内部 ID。留空则**仅拉取主账簿（内部 ID 为 1）**，输入 `all` 则对所有账簿求和。 |
| 科目编号 | 否 | 精确的总账科目编号，用于将拉取范围限制为一个科目。留空表示所有科目。 |
| 过账期间 | 否 | NetSuite 过账/会计期间内部 ID。留空表示所有期间。 |

<Aside type="caution">
**多账簿科目：**运行多账簿会计的 NetSuite 账户会为每条交易行在每个账簿中各过账一行，因此不加筛选地拉取所有账簿会使合计重复计算 N 倍。会计账簿留空时仅拉取**主账簿**。仅当您确实需要跨账簿合计时才设为 `all`，或设为特定账簿的内部 ID，仅拉取该账簿。
</Aside>

<Aside type="note">
请将期间限定在所需的范围内。每次运行都会替换整个目标表，因此计划拉取每次都会重新提取完整结果；使用滚动日期窗口可使定期的总账拉取保持快速，而不必重新读取全部历史数据。
</Aside>

<Aside type="note">
如果没有 SuiteAnalytics Connect，NetSuite 的 SuiteQL API 会将单个查询限制在约 100,000 行。同时给出开始日期和结束日期，可让 PlaidCloud 主动将拉取按日期分块，使每块保持在该上限之内。总账明细最可能接近该上限，因此这一点在这里比在“导入余额”中更重要。**开放式**拉取如果超出上限，将失败并提示您添加日期范围，而不会悄悄返回被截断的结果。
</Aside>
