## 描述

通过 [NetSuite 连接](/zh-cn/guides/connections/netsuite/)将 NetSuite 的科目余额导入项目表，即可用于构建报表的试算平衡表。选择连接，指定目标表，并设置期间和子公司；步骤会拉取余额并写入，无需编写或维护 SuiteQL。

这是预置的 [NetSuite 导入步骤](/zh-cn/reference/workflow-steps/netsuite/)之一。每个步骤都运行在共享的读取层之上，该层会为您刷新 OAuth 令牌、对大型结果分页并重试暂时性错误，因此无需手动调优，即可完整拉取全年或全部子公司的数据。如需交易级别的数据，请使用 [NetSuite：导入总账明细](/zh-cn/reference/workflow-steps/netsuite/import-gl-detail/)；如需科目、子公司和其他列表，请使用 [NetSuite：导入主数据](/zh-cn/reference/workflow-steps/netsuite/import-master-data/)。

## 配置

| 字段 | 是否必填 | 说明 |
|---|---|---|
| NetSuite 连接 | 是 | 用于读取的 NetSuite 连接，仅显示 NetSuite 类型的连接。 |
| 目标表 | 是 | 写入余额的项目表。每次运行都会完全覆盖该表。 |
| 开始日期 | 否 | 要包含的最早日期，格式为 `YYYY-MM-DD`，含该日期。留空表示没有下限。与结束日期一起给出时，拉取会自动按日期分块，以保持在 NetSuite 的 SuiteQL 行数上限之内，参见下方的注意事项。 |
| 结束日期 | 否 | 要包含的最晚日期，格式为 `YYYY-MM-DD`，含该日期。留空表示没有上限。 |
| 子公司 | 否 | NetSuite 子公司内部 ID，用于将拉取范围限制为一家子公司。留空表示所有子公司。 |
| 会计账簿 | 否 | NetSuite 会计账簿内部 ID。留空则**仅拉取主账簿（内部 ID 为 1）**，输入 `all` 则对所有账簿求和。 |
| 科目编号 | 否 | 精确的总账科目编号，用于将拉取范围限制为一个科目。留空表示所有科目。 |
| 过账期间 | 否 | NetSuite 过账/会计期间内部 ID。留空表示所有期间。 |

<Aside type="caution">
**多账簿科目：**运行多账簿会计的 NetSuite 账户会为每条交易行在每个账簿中各过账一行。会计账簿留空时仅拉取**主账簿**，这是标准试算平衡表的正确选择。仅当您确实需要跨账簿合计（对各账簿求和，而非进行对账）时才设为 `all`，或设为特定账簿的内部 ID，仅拉取该账簿。
</Aside>

<Aside type="note">
子公司和会计账簿使用 NetSuite 的内部 ID，而非名称。请使用 [NetSuite：导入主数据](/zh-cn/reference/workflow-steps/netsuite/import-master-data/)（记录类型为**子公司**）一次性拉取内部 ID，并将其保存为一张小型参考表。
</Aside>

<Aside type="note">
如果没有 SuiteAnalytics Connect，NetSuite 的 SuiteQL API 会将单个查询限制在约 100,000 行。同时给出开始日期和结束日期，可让 PlaidCloud 主动将拉取按日期分块，使每块保持在该上限之内，因此无需任何额外操作即可完整拉取全年数据。**开放式**拉取（开始日期或结束日期留空）如果超出上限，将失败并提示您添加日期范围，而不会悄悄返回被截断的结果。
</Aside>
