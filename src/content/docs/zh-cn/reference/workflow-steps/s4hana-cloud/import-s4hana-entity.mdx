## 说明

通过 [S/4HANA Cloud 连接](/zh-cn/guides/connections/s4hana-cloud/)将一个 SAP S/4HANA Cloud 实体导入到项目表中。选择连接、实体类型和所需的筛选器即可，步骤会拉取匹配的记录并写入，无需编写 OData 查询。

这是一个通用的预置步骤，一个步骤类型涵盖两个实体：用于期末报告的聚合 `trial_balance` 多维数据集，以及用于查看已过账交易明细的行项目级 `journal_entry_items`。

## 配置

| 字段 | 必填 | 备注 |
|---|---|---|
| S/4HANA 连接 | 是 | 用于读取数据的 S/4HANA Cloud 连接。 |
| 目标表 | 是 | 写入结果的项目表。每次运行都会完全覆盖该表。 |
| 实体类型 | 是 | 要拉取的实体。默认值为 `trial_balance`。可选 `trial_balance`、`journal_entry_items` 之一。 |
| 筛选器 | 否 | 范围筛选和等值筛选，会转换为请求的 OData `$filter`。每个实体仅允许使用 S/4HANA 能够在服务器端实际求值的字段进行筛选，不支持的字段会被拒绝，而不是被悄悄忽略。 |

### 实体与可筛选字段

| 实体类型 | 拉取内容 | OData 服务 | 可筛选字段 |
|---|---|---|---|
| `trial_balance` | 聚合的期末总账科目余额 | `API_OPLACCTGDOCITEMCUBE_SRV` | `CompanyCode`、`GLAccount`、`CostCenter`、`ProfitCenter`、`FiscalYear`（范围）、`FiscalPeriod`（范围）、`Ledger` |
| `journal_entry_items` | 已过账的日记账分录行项目 | `API_JOURNALENTRYITEMBASIC_SRV` | `CompanyCode`、`GLAccount`、`CostCenter`、`ProfitCenter`、`PostingDate`（范围）、`FiscalYear`（范围）、`FiscalPeriod`（范围）、`Ledger` |

<Aside type="note">
`PostingDate`、`FiscalYear` 和 `FiscalPeriod` 接受**范围**筛选（`ge`/`le` 形式的边界），这是限定 `journal_entry_items` 拉取范围的主要方式，因为不加限制地拉取行项目明细，数据量可能非常大。针对生产数据运行之前，请为大型实体至少设置一个边界。
</Aside>

<Aside type="caution">
只有当您的 Communication Scenario 公开了 `CostCenter` 和 `ProfitCenter` 时，才能对它们进行筛选。不属于该场景的维度会被当作不支持的筛选器拒绝，而不是被悄悄忽略。
</Aside>
