## 说明


基于分配维度和驱动因素数据表，将源表中的值分摊到各目标。这是最灵活的分摊步骤，适用于基于驱动因素的分摊：每个源行的去向由层次结构决定，而驱动因素值决定各去向分得*多少*。

常见模式：使用活动工时将成本中心总额分摊到产品线；按人数在各业务单位之间分配 IT 间接费用；使用自定义权重分摊共享服务成本。


## 数据表设置
### 分配维度层次结构

![分配层次结构](/images/assignment-hierarchy.png)

**分配维度层次结构**让用户可以通过点选来筛选***待分摊值表***和***驱动因素数据表***中的任意一个或两者，从而创建有针对性的分摊。
**分配维度层次结构**由引用***待分摊值表***和***驱动因素数据表***的维度组合而成。

#### 创建分配维度层次结构

要创建**分配维度层次结构**，必须先创建要用作***待分摊值表***和***驱动因素数据表***筛选器的维度。以下链接将指导您创建这些维度。

<Aside>在上面的**分配维度层次结构**中，***待分摊值表***包含 Version、Period、Account 和 Original Cost Center 列。***驱动因素数据表***包含 Resource Driver、Period、Version、Original Cost Center 和 Original Activity 列。这两个表还有其他列，但我们要使用以上这些列来创建分摊规则。</Aside>

[创建维度](https://docs.plaidcloud.com/docs/workflow-steps/dimensions/dimension-create/) 

[加载维度](https://docs.plaidcloud.com/docs/workflow-steps/dimensions/dimension-load/) 

##### 创建主层次结构

为***待分摊值表***和***驱动因素数据表***创建好维度后，下一步是确定***待分摊值表***的哪个维度将作为**分配维度层次结构**的***主层次结构***。
<Aside>分摊总账值时，通常使用_科目_或_成本中心_维度。</Aside>

复制此维度的方法是：在 PlaidCloud 中转到“维度”选项卡，单击该维度，然后依次选择***操作***和***复制维度***。
复制维度时会弹出一个窗口，要求您为复制出的维度输入名称。

<Aside>**分配维度层次结构**的名称应能表明所执行的分摊，例如“Ledger to Activity”。</Aside>


##### 向分配层次结构添加维度


打开新创建的**分配维度**，单击***属性***旁边的向下箭头，然后选择***新建属性***。

![分配层次结构属性](/images/allocation_by_dimension_add_property.png)

这将打开***属性配置***对话框：
###### 属性配置

![配置分配层次结构属性](/images/allocation_by_dimension_configure_property.png)

- **属性名称**：通常是要添加到分配层次结构的维度的名称。
- **属性显示**：应设置为“Tag”。
- **属性类型**：此属性告知分摊步骤该维度与哪个表相关，是***待分摊值表***还是***驱动因素数据表***。
  - **源**：与***待分摊值表***配合使用。
  - **目标**：与***驱动因素数据表***配合使用。
  - **驱动**：用于针对所选的特定驱动因素筛选***驱动因素数据表***。
  - **上下文**：当***待分摊值表***和***驱动因素数据表***包含相同的维度时，可使用上下文指定这些维度之间的关联方式。当两个表都包含_利润/成本中心_或_地域_时，经常使用上下文。
    - **留空**：没有自身上下文的节点会采用最近一个设置了上下文的上级的上下文，因此空白单元格表示_继承_，而不是_无上下文_。只有在没有任何上级设置上下文时，***驱动因素数据表***才会回退为按目标维度自身的设置进行筛选。
    - **当前**：起到直通作用，并根据目标维度的设置筛选***驱动因素数据表***。例如，如果***上下文***基于_利润中心_维度，且_利润中心_目标维度设置为***全部***，则驱动因素数据会按所有_利润中心_筛选。由于它是一个存储值，因此还会终止上述继承，所以当某个上级设置了上下文时，***当前***就是节点表示“此处无上下文”的方式；改为清空单元格，则会让该节点获得其上级的上下文。
    - **父级**：选中后，***待分摊值表***中_利润中心_的父级将用于筛选***驱动因素数据表***中的驱动因素值。当特定_利润中心_有时没有驱动因素值、而其父级层次上通常有时，这很有用。
    - **全部**：选中后，***待分摊值表***中的_利润中心_不会筛选***驱动因素数据表***中的驱动因素值，将使用所有_利润中心_的驱动因素值。
    - **未分配**：不使用目标维度本会选取的驱动因素行，而是仅使用其_利润中心_完全没有值或读取为 `UNASSIGNED`（任何大小写）的行，并且_利润中心_不会拆分结果。可用于分摊没有任何_利润中心_拥有的成本的规则。它只作用于设置它的规则，让同一列保持空白的其他规则不受影响。
    <Aside>当***上下文***设置为***全部***、***父级***或***未分配***时，它会覆盖目标维度上的设置。***当前***不会覆盖，而是遵从目标维度的设置；在没有上级设置上下文时，空白单元格也是如此。</Aside>
- **编辑器类型**：此下拉列表应设置为***Select Dimension***。

为要添加到分配层次结构的维度选择好相应属性后，选择“编辑配置”。
###### 维度配置

![配置分配层次结构](/images/allocation_by_dimension_configure.png)

- **维度**：使用下拉列表选择维度。
- **层次结构**：如果所选维度具有备用层次结构，它们也会与主层次结构一起显示在此处供选择。
- **Start Node**：如果不希望从顶部节点开始显示该维度，可以选择层次结构内的任意节点作为显示该维度的起始节点。
- **允许多选**：选中后，用户可以在层次结构中选择多个节点。
- **特殊情况**：选中后，特殊情况将出现在维度下拉菜单中供选择。它们通常用于***目标***维度。
  - **源**：当维度设置为_源_时，分摊在筛选***驱动因素数据表***时会忽略此维度，但分摊结果会包含该维度的值。
  - **当前**：可在维度由_源_和_目标_共享时使用。当_目标_维度设置为***当前***时，***驱动因素数据表***将在分摊运行时按_源_维度的当前值进行筛选。例如，***待分摊值表***和***驱动因素数据表***中都有多个期间，但您希望分摊在各期间内进行而不是跨期间进行。在_业务单位_、_成本中心_和_地域_上使用***当前***也很常见。
  - **未分配**：当维度设置为_未分配_时，分摊在筛选***驱动因素数据表***时会忽略此维度，并且此维度的分摊结果将为_Null_值。
  - **全部**：当维度设置为_ALL_时，分摊将使用该维度中的所有值。


***待分摊值表***、***驱动因素数据表***和***分摊结果表***可以动态或静态选择。

#### 动态表选择
动态表选项允许使用文本和变量指定表。这在使用由变量驱动的工作流时很有用，此时对表或视图的引用与所指定的变量相关。

下面的示例使用 `current_month` 变量动态指向一个表：

```text
legal_entity/inputs/{current_month}/ledger_values
```

#### 静态表选择
如需将特定表用作源，请不要选中 *Dynamic* 框，并使用下拉菜单选择源表。


任何表选择都始终可以使用表资源管理器。单击表选择右侧的“表资源管理器”按钮，将打开表资源管理器窗口。

<Aside>**分摊结果表**必须是表，而不能是视图。</Aside>

### 待分摊值表

此表包含要分摊的值，这些值通常是成本或收入值。


### 驱动因素数据表

驱动因素数据表包含分摊步骤将用来分摊成本的值。


示例：

- 供应链要将成本分配给客户时，可以使用配送数据，以配送次数或配送重量作为驱动因素。
- IT 服务台要将其成本分配给其所支持的部门时，驱动因素数据可以是按成本中心统计的工单数量。

#### 驱动因素数据符号规则
驱动因素数据可以同时包含正值和负值。**Driver Data Sign Rule** 让您决定如何处理冲突的符号。
- **Error on conficting signs**：遇到冲突的符号时，分摊步骤会产生错误并停止。
- **Proceed with warning on conflicting signs**：分摊步骤会同时使用负值和正值的驱动因素值，但会显示警告。
- **Use only positive driver values**：分摊步骤只使用正的驱动因素值，忽略负值。
- **Use only negative driver values**：分摊步骤只使用负的驱动因素值，忽略正值。
- **Use absolute values of driver data**：分摊步骤使用驱动因素数据的绝对值。

### 将记录匹配到多条规则

默认情况下，一条记录只采用它匹配的第一条规则。取消选中**仅将记录匹配到一条规则**后，它会改为采用匹配的每一条规则：该记录会针对每条规则各出现一次，而不匹配任何规则的记录会被排除。

还可以使用类型为**排序**的分配维度属性将规则拆分为多个迭代，其值是每条规则在其中运行的迭代。取消选中**仅将记录匹配到一条规则**的步骤无法同时做到这两点：如果要运行的规则分布在多个迭代中，步骤会停止并显示 *Cannot apply rules when there are multiple iterations and records can match more than one rule*。请选中该选项，或将每个迭代作为单独的步骤运行。

### 中间表
每次运行分摊步骤时都会创建_中间表_，并提供分摊处理的摘要。_中间表_可帮助了解分摊过程的运行情况，并用于排查意外结果。

- **路径**：显示从分配层次结构汇总出的唯一分摊路径数量。
- **映射**：显示***待分摊值表***的每一行如何映射到分摊目标。
- **摘要**：显示由分配层次结构产生的每条规则，以及***待分摊值表***中有多少记录与之匹配。

选中**仅将记录匹配到一条规则**时，不匹配任何规则的记录在**映射**表中的规则列为空，并计入不指明任何规则的**摘要**行。规则留空的值同样为空。这里的空是指 null，绝不是空字符串，并且无论是否选中**使用 SQL 而非 Pandas 应用规则**，这三个表的列和类型都相同。
### 分摊结果表



#### 将结果追加到目标表
如果选中此框，分摊结果将追加到分摊结果表。
如果未选中此框，则每次运行分摊步骤时都会覆盖分摊结果表。

#### 分摊结果使用单独的列

如果选中此框，则结果表会显示每条已分摊记录的金额，以及实际分摊给每条驱动因素记录的金额。

#### 重命名维度节点
如果选中此框，则分摊步骤运行时会重命名分配维度中的维度节点。

### 高级选项

#### 线程数
设置分摊步骤将使用的并发操作数量。

#### 区块大小
设置每个线程内的分摊路径数量。

<Aside type="danger">将***线程数***或***区块大小***中的任何一个或两个设置得过高，都会减慢分摊处理速度。缓慢地逐步调高这些值并观察性能，是调优分摊步骤的理想方式。</Aside>
