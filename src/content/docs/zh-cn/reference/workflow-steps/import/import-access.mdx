## 说明

从文档账户读取 Microsoft Access 数据库文件并导入其中的表——每个 Access 表对应一个项目表，表名带有您选择的前缀。

由于一个 Access 文件包含多个表，此步骤将整个文件一并导入，而不是映射单个表的列。

## 独有配置项

### 源

文档账户中的 Access 数据库文件。文件选择器还支持通过搜索而不是精确路径进行匹配，并提供递归选项，以及用于协调多个匹配文件之间架构差异的规则。

### 目标

**表前缀**——添加到每个导入表名称之前，使同一文件的表保持在一起，并避免与其他导入的表冲突。

### 未更改时跳过

默认开启。当源文件自上次运行以来没有变化，且目标表仍保留着已加载的行时，工作流运行会完全跳过导入（包括下载）。已被清空的表会重新导入。

## 文件无法读取时

步骤会失败，并指出无法读取的文件和表，而不是完成后留下一个空表。出现这种情况的原因包括：文件中没有 PlaidCloud 可读取的表、已列出某个表但无法描述其列，或读取表的行时失败——通常是因为文件由比读取器所支持版本更新的 Access 写入。请在 Access 中转换或重新导出该文件，然后再次运行导入。

如果文件中的所有表确实都是空的，则导入成功，并报告一条未加载任何记录的警告。
