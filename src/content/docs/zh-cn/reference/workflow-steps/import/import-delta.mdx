## 说明

将存储在 PlaidCloud 文档中的 [Delta Lake](https://delta.io/) 表导入项目表。将步骤指向该表的文件夹，即包含其 `_delta_log` 文件夹和数据文件的文件夹。表按最新版本读取。

步骤表单的选项卡与 [导入 Parquet 步骤](/zh-cn/reference/workflow-steps/import/import-parquet/)相同：**导入参数**用于选择**源文件**（表所在文件夹）和**目标表**；**表数据选择**用于映射列；**数据筛选器**用于筛选行。**填充**会从表的 `_delta_log` 读取列及其类型，分区列排在最后，类型为文本。当文件夹缺失或为空时，**填充**会返回*没有可填充的内容*，并给出指明路径的警告，同时保留您现有的映射。

[已迁移的 KNIME 工作流](/zh-cn/guides/workflows/migrate-knime-workflows/)会将此步骤用于 Delta Table Reader 节点。

## 配置

* `input_file`——文档账户以及 Delta 表文件夹的路径。通过搜索可找到多个表：当 `schema_mismatch` 设置为 `union`（默认）时，每个表按列名加载，表中缺少的列为 NULL，映射中未声明的列会被忽略；设置为 `error` 则步骤停止，并指出表和相关列。请通过 AI 助手或 REST API 设置 `schema_mismatch`。
* `target_frame`——写入行的目标表。
* `source_columns` 和 `target_columns`——列映射。
* `source_where`、`having`、`aggregate`、`aggregation_type` 和 `distinct`——筛选并汇总行，与其他导入步骤相同。
* `use_target_slicer`、`limit_target_start` 和 `limit_target_end`——只保留结果的一部分切片。
* `delete_file`——导入后删除已导入的文件。
* `ascii_only`——删除非 ASCII 字符。
* `skip_if_unchanged`——默认开启：当源文件和步骤设置自上次成功运行以来没有变化时，工作流运行会跳过导入。
