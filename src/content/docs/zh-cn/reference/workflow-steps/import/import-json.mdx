## 说明

从 PlaidCloud 文档中导入 JSON 文本文件。

有关 JSON 文件的更多详细信息，请参阅 JSON 官方网站：http://json.org/。

JSON 文件*不*保留列顺序。源文件中的列顺序不一定与导入数据表中的列顺序一致。

JSON 导入通过临时存储以流式方式处理，而不是将整个文档加载到内存中，因此导入超大文件也不会耗尽内存。在大型文档中较晚才首次出现的列也会包含在导入的表中。嵌套的对象和数组会导入为标准的紧凑 JSON 文本，因此下游步骤可以使用任何 JSON 工具对其进行解析。

## 独有配置项

### JSON 数据方向

请看下面的数据集：

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

JSON 文件可以从以下三种数据格式之一导入：

* Records：数据存储在 Python 字典集合中，每一行以 \{Column -> Value, …} 的格式存储。例如：


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index：数据存储在嵌套的 Python 字典集合中，每一行以 \{Index -> \{Column -> Value, …},…} 的格式存储。例如：


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split：数据存储在单个 Python 字典集合中，值存储在列表里。例如：


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

除上述格式外，还接受换行分隔的 JSON（NDJSON）：每行一个独立的 JSON 对象，没有外层数组。例如：

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### 整个文档

若要保持每个文件的 JSON 完整，请在**更多 JSON 选项**中选择**将每个文件作为包含其完整 JSON 文档的一行导入**（`whole_document`）。此时每个文件会导入为包含其完整 JSON 文档的一行，数字保持原样。

### 日期和时间戳

当字段的所有值都采用以下同一种格式时，该字段会作为日期或时间戳导入：

| 格式 | 日期 | 时间戳 |
| --- | --- | --- |
| ISO 8601 | `2026-01-23` | `2026-01-23T23:14:00` |
| 月在前 | `01-23-2026` 或 `01-23-26` | `01-23-2026 11:14:00 PM`，使用 12 小时制时间 |
| 日在前 | `23-01-2026` 或 `23-01-26` | `23-01-2026 23:14:00`，使用 24 小时制时间 |
| 两位年份在前 | `99-01-23` | `99-01-23 23:14:00`，使用 24 小时制时间 |

无论行的顺序如何，字段中的每个值都以相同方式读取。采用任何其他格式的字段（如 `01/23/2026` 或 `01-23-2026 23:14:00`）会作为文本导入。值的格式混用的字段同样如此，不过两位年份与四位年份的某些混用（如 `01-23-2026` 和 `01-24-26`）会使导入停止，并给出指明该字段的错误。

#### 值符合多种格式时

`01-03-2026` 可能是 1 月 3 日，也可能是 3 月 1 日；`23-01-26` 可能是 2026 年 1 月 23 日，若按年份在前读取，则是 2023 年 1 月 26 日。当字段的所有值都符合上述多种格式时，由步骤的**日期格式**根据日、月、年的顺序来决定：

* 以“月日”开头的选项按月在前读取：将 `01-03-2026` 读作 1 月 3 日。
* 以“日月”或“缩写”开头的选项按日在前读取：将 `01-03-2026` 读作 3 月 1 日，将 `23-01-26` 读作 2026 年 1 月 23 日。
* 选择任何其他日期格式时，导入会停止并报错，错误会指明该字段以及可以解决问题的选项。

当每个值的日和月都不大于 12 时，这些选项还会按另一种时钟读取时间戳：选择以“月日”开头的选项时，`01-03-2026 23:14:00` 读作 1 月 3 日；选择以“日月”或“缩写”开头的选项时，`01-03-2026 11:14:00 PM` 读作 3 月 1 日。任何其他日期格式则按表中方式读取：日在前使用 24 小时制时间，月在前使用 12 小时制时间。

没有任何日期格式选项会按两位年份在前读取，因此像 `26-01-23` 这样的字段，只有在其值无法以其他方式读取时才会按年份在前导入，如 `99-01-23`。若写成四位年份，如 `2026-01-23`，此类日期会按 ISO 8601 导入。

如果文件在嵌套对象或数组内还包含时间戳，则属于例外：上述检查均不适用，且符合多种格式的值在不同行中可能被读成不同结果。
