## 说明

从 PlaidCloud 文档中导入 JSON 文本文件。

有关 JSON 文件的更多详细信息，请参阅 JSON 官方网站：http://json.org/。

JSON 文件*不*保留列顺序。源文件中的列顺序不一定与导入数据表中的列顺序一致。

JSON 导入通过临时存储以流式方式处理，而不是将整个文档加载到内存中，因此导入超大文件也不会耗尽内存。在大型文档中较晚才首次出现的列也会包含在导入的表中。嵌套的对象和数组会导入为标准的紧凑 JSON 文本，因此下游步骤可以使用任何 JSON 工具对其进行解析。

## 独有配置项

### JSON 数据方向

请看下面的数据集：

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

JSON 文件可以从以下三种数据格式之一导入：

* Records：数据存储在 Python 字典集合中，每一行以 \{Column -> Value, …} 的格式存储。例如：


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index：数据存储在嵌套的 Python 字典集合中，每一行以 \{Index -> \{Column -> Value, …},…} 的格式存储。例如：


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split：数据存储在单个 Python 字典集合中，值存储在列表里。例如：


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

除上述格式外，还接受换行分隔的 JSON（NDJSON）：每行一个独立的 JSON 对象，没有外层数组。例如：

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### 整个文档

若要保持每个文件的 JSON 完整，请在**更多 JSON 选项**中选择**将每个文件作为包含其完整 JSON 文档的一行导入**（`whole_document`）。此时每个文件会导入为包含其完整 JSON 文档的一行，数字保持原样。
