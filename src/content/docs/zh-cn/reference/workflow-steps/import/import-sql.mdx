## 说明


将针对外部数据库的 SQL 查询结果导入 PlaidCloud 项目表。查询在远程数据库上运行；只有结果集会被带入 PlaidCloud。

与[导入外部数据库表步骤](/zh-cn/reference/workflow-steps/import/import-external-database-tables/)的区别在于，SQL 由您自己编写——适用于希望在数据落入 PlaidCloud 之前由源数据库执行的复杂联接、筛选或聚合。

### 列类型推测
SQL 导入可以选择在加载时尝试推测数据类型，或将所有列设置为文本类型。如果数据干净，动态设置数据类型可能更快，但在某些情况下会引发问题。

例如，如果大部分数据看起来是数值，但同时也有一些文本，它可能会尝试将其设置为数值，从而因数据类型不匹配而导致加载问题。又如，如果存在 16 位的数值产品代码，也可能出问题：它会去掉前导零，结果得到的是一个数字，而不是 16 位的代码。

不过，将数据全部设置为文本时，需要后续的提取步骤，将不应为文本的数据类型转换为相应的类型，例如日期或数值。

## 故障排除

| 现象 | 可能原因 |
| --- | --- |
| 步骤耗时明显比平时长——最多多出约半小时——而您的查询、连接或数据量并无其他变化 | 运行导入的后台工作进程在中途被中断（平台侧的重启或驱逐，而不是您工作流中的问题），平台已为您重试该表的导入。重试只会在检测到中断之后才开始，这就是多出这段时间的原因。 |
| 延迟之后步骤仍然成功完成 | 重试会完整替换表的内容，因此结果与一次干净的运行相同——无需进一步检查或重做。 |
| 步骤失败，提示 "has already been attempted and cannot be safely re-run" | 对于 Import SQL 步骤，不会再出现这种拒绝——中途中断会被重试。不过在[还原项目归档](/zh-cn/guides/projects/archive-a-project/#还原归档)或[加载维度](/zh-cn/reference/workflow-steps/dimensions/dimension-load/)时，按设计仍会看到该提示，因为重新运行会产生重复内容，而不是替换任何内容。如果在 Import SQL 步骤本身看到该提示，请提交支持工单。
