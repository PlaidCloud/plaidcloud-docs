## 描述


将针对外部数据库的 SQL 查询结果导入 PlaidCloud 项目表。查询在远程数据库上运行，只有结果集会被带入 PlaidCloud。

与[导入外部数据库表](/zh-cn/reference/workflow-steps/import/import-external-database-tables/)的区别在于，SQL 由您自己编写，这对于复杂的联接、筛选或聚合很有用，您可以让源数据库先完成这些操作，再将数据加载到 PlaidCloud。

### 列类型推测
SQL 导入可以选择在加载时尝试推测数据类型，或将所有列设置为文本类型。如果数据干净，动态设置数据类型可能更快，但在某些情况下会引发问题。

例如，如果大部分数据看起来是数值，但其中也有一些文本，它可能会尝试将其设置为数值，导致数据类型不匹配而引发加载问题。再比如，如果有一个 16 位的数字产品代码，也可能出现问题：它会裁掉前导零，得到的是一个数字，而不是 16 位代码。

不过，将数据全部设置为文本时，需要在之后使用提取步骤，把不应为文本的数据转换为合适的类型，例如日期或数值。

## 故障排除

| 症状 | 可能原因 |
| --- | --- |
| 步骤明显比平时耗时更长（最多多出约半小时），而查询、连接或数据量没有任何其他变化 | 运行导入的后台工作进程在中途被中断（平台端的重启或驱逐，而非工作流中的问题），平台为您重试了该表的导入。重试只有在检测到中断后才会开始，这就是多出的时间。 |
| 延迟之后步骤仍然成功完成 | 重试会完整替换表的内容，因此结果与一次干净的运行相同，无需进一步检查或重做。 |
| 步骤失败并提示“已尝试过，无法安全地重新运行” | 对于导入 SQL 步骤，不再出现这种拒绝，运行中途的中断会被重试。在[还原项目归档](/zh-cn/guides/projects/archive-a-project/#还原归档)或[加载维度](/zh-cn/reference/workflow-steps/dimensions/dimension-load/)时，按设计仍会看到这一提示，因为重新运行会产生重复，而不是替换任何内容。如果您在导入 SQL 步骤本身看到该提示，请提交支持工单。
