## 说明

将[宏](/zh-cn/guides/workflows/create-a-macro/)工作流作为运行隔离的子调用来调用。与[运行工作流](/zh-cn/reference/workflow-steps/workflow-control/run-workflow/)不同，每次 Macro Run 调用都会：

- 获得全新且唯一的 `run_id`。
- 在项目目录下自己的临时架构（`macrorun_<run_id>`）中运行。
- 在复制入时，将调用方的表和变量绑定到宏声明的输入端口。
- 成功时，将宏声明的输出表复制回调用方的目标位置。
- 调用结束时（成功、出错或停止）始终删除临时架构。

这种隔离使同一个宏可以安全地并发调用——无论是从父级循环、同时运行的独立工作流，还是从另一个宏递归调用——不同运行之间都不会发生中间表名冲突。

目标工作流必须标记为宏。Macro Run 步骤若指向非宏工作流，会失败并给出明确的错误消息；反过来，[运行工作流](/zh-cn/reference/workflow-steps/workflow-control/run-workflow/)或 [Workflow Loop 步骤](/zh-cn/reference/workflow-steps/workflow-control/workflow-loop/)不能以宏为目标（这些步骤不具备按运行隔离的生命周期）。

## 要运行的宏

- **项目** — 包含该宏的项目。在 v1 中必须与调用方位于同一项目。
- **宏** — 要调用的宏工作流。选定后，宏声明的输入和输出端口会填充下面的绑定列表。

## 输入端口绑定

为宏上声明的每个输入端口添加一个绑定。绑定分两轮处理：先处理标量/维度输入（写入宏的运行范围变量覆盖层），再处理表输入，因此表输入筛选器可以引用标量输入。

**表输入端口：**

- **源** — 调用方的表（按名称或 ID），其内容会以端口名称复制到宏的临时架构中。
- **列** — 可选的列投影。可选取一个子集，并按需重命名（`source` → `target`）；这些列会加引号并在复制入时应用，因此只会物化投影的列。
- **筛选器** — 可选的 `WHERE` 子句，在复制入时应用。可以按名称引用宏的输入变量（根据上面的标量绑定解析）。例如，`month = {month}` 会将复制入限制为多年表中某个月的数据切片。

**标量/维度输入端口：**

- **变量** — 要设置的宏端变量名称（与宏上声明的端口相匹配）。
- **值** — 要绑定的值，可以是字面值，也可以是调用方变量引用（在写入子调用的覆盖层之前，会根据调用方的变量进行解析）。

## 输出端口绑定

为宏上声明的每个输出端口添加一个绑定，指向调用方的目标表。目标表若不存在，会即时创建。输出复制出：

- 在宏成功完成后进行（状态为 `done` 或 `warn`）。
- 如果宏在运行中被手动停止（`stop` 状态），则**跳过**——否则不完整的输出会悄无声息地进入调用方的持久架构。
- 可选的**列**投影与输入绑定的用法相同。

## 失败时的行为

| 宏的结果                | 对调用方的影响                                                        |
|-------------------------|-----------------------------------------------------------------------|
| `done` / `warn`         | 输出表复制到调用方目标位置；临时架构被删除。                          |
| `stop`（手动停止）      | 跳过复制出；临时架构被删除；记录调用方警告。                          |
| 运行中出错              | Macro Run 步骤出错；临时架构被删除；不写入输出。                      |

宏的工作流失败时，Macro Run 步骤的日志会显示宏自身的错误消息（“Child workflow run failed:”后跟具体消息），因此无需打开宏的运行记录即可看到需要修复的内容。

临时架构始终会在 `finally` 块中回收，因此失败或被停止的宏绝不会把中间表遗留在项目架构中。
