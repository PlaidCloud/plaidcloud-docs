VSCode 中 GitHub Copilot 的[代理模式](https://docs.github.com/copilot/using-github-copilot/copilot-chat-in-ide/using-mcp-with-copilot)通过工作区或用户范围的 `.vscode/mcp.json`（工作区）或全局 VSCode `mcp.json`（用户）支持 MCP 服务器。

<Aside type="note">如果您要找的是 **Microsoft 365 Copilot**（Teams 和 Microsoft 365 应用中的助手），而不是 IDE 中的 GitHub Copilot，请参见 [Microsoft 365 Copilot](/zh-cn/integrations/microsoft-365-copilot/)。</Aside>

您也可以从 PlaidCloud 自己的**连接您的 AI** 窗口进入这些步骤：在**其他**选项卡下可以找到 GitHub Copilot，与 Gemini CLI 和 Codex CLI 放在一起。

<Aside>Copilot 的 MCP 支持受 Copilot 套餐层级和 VSCode 中 `chat.mcp.enabled` 设置的限制。配置服务器之前，请确保两者都已启用。</Aside>

## 设置

1. 在已登录 PlaidCloud 的浏览器中访问 `https://<your-workspace>.plaid.cloud/mcp/setup/token`，获取持有者令牌。

2. 在 VSCode 中，打开命令面板并运行 **MCP: Add Server**，或直接创建 `.vscode/mcp.json`：

    ```json
    {
      "servers": {
        "plaidcloud": {
          "type": "http",
          "url": "https://<your-workspace>.plaid.cloud/mcp",
          "headers": {
            "Authorization": "Bearer eyJhbGc…"
          }
        }
      }
    }
    ```

3. 重新加载 VSCode。打开 Copilot 聊天面板，将模式下拉列表切换为**代理**，并确认 PlaidCloud 工具出现在工具列表中（通常显示为 `plaidcloud_*`）。

## 使用

直接让 Copilot 执行 PlaidCloud 操作：

- “查找项目 `Q4 Forecast` 中最近一次运行失败的所有工作流。”
- “显示表 `customers` 的架构，并建议索引。”
- “运行 `daily-load` 工作流并报告运行状态。”

Copilot 会选择合适的工具，执行它，并在回复中引用结果。对于破坏性操作（删除、organize、不带 `dry_run` 的 upsert），它通常会请求确认，批准之前请审阅计划执行的操作。

## 刷新令牌

VSCode 在启动时以及文件变更时读取 `.vscode/mcp.json`。令牌过期后，重新加载 `https://<your-workspace>.plaid.cloud/mcp/setup/token` 并覆盖 `Authorization` 的值，VSCode 会自动重新加载服务器。

## 限制为特定工具

如果要限制 Copilot 可以调用哪些 PlaidCloud 工具，请使用 VSCode 的按服务器工具允许列表（设置 → Copilot → MCP → 特定服务器的工具选择）。这对只读会话很有帮助，也可以让会产生变更的工具（`*_upsert`、`*_run`）必须经过明确的重新启用。
