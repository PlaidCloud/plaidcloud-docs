PlaidCloud converts Savant Labs analyses into native Advanced workflows. The
importer maps each Savant agent to a workflow step, project variable, or
canvas object, so a converted workflow runs cloud-native.

Each agent has a mapping tier:

- **Full** — every option of the agent has a valid mapping to a PlaidCloud
  step.
- **Partial** — the agent converts, and the option named in its row has no
  mapping: it becomes a named placeholder that refuses at run time, or is
  replaced by a stated fallback, and the conversion names the loss with a
  warning code. Constructs refused by name are listed separately under Named
  Refusals and do not lower the tier.

External-system connectors are **connected, not converted** — see
[Connecting to External Systems](#connecting-to-external-systems).

A credential in an API Agent request is never copied into a workflow step. Over https it moves into a REST connection; over http, without permission to write connections, or in a conversion made through MCP it is withheld with a warning. This is by design and does not lower the tier.

## Named Refusals

Seven constructs are refused by name rather than converted. None lowers an agent's tier.

| Construct | Why It Is Refused |
| --- | --- |
| An API Agent request that carries a credential and takes its host from an input field | Each row could send the credential to a host the data chooses. The request becomes a named placeholder. A request without a credential, and a credential on a fixed host, convert. |
| A Copilot edit that has only its prompt | The prompt is no formula, and the compiled pipeline Savant keeps for it chains steps whose combination it does not document. |
| A Transform edit with no expression whose compiled pipeline chains several steps | Savant does not document how the chained steps combine, so there is no result to reproduce. A one-step pipeline converts. |
| A regex construct in a Transform or Filter expression that neither the warehouse nor the executor reads: a class inside a class, a class intersection (`&&`), or an unknown `\p{}` property | There is no engine that reads it as Java does, so the step becomes a named placeholder. |
| An aggregate or window function in a Transform or Filter expression | Savant itself fails on it at run time, so there is no result to reproduce. As a Transform calculation or in a Summarize it converts. |
| `HASH` in a Transform or Filter expression with a literal algorithm other than `md5` or `sha1` | Savant itself fails on it (the algorithm is `md5` or `sha1`). An algorithm read from a column converts, giving NULL for any other value. |
| An XML Agent path that is not XPath 1.0 | Savant cannot run it either. |

A relative API URL converts when you bind a base URL or REST connection with `api_bindings`; see [Convert-Time Bindings](/guides/workflows/migrate-savant-analyses/#convert-time-bindings).

## Expression Language

Savant expression functions and operators convert to PlaidCloud expressions. Tier: **Partial**. Every function and format converts, including `TO_TEXT` with a numeric pattern, a format known only per row, fractional-second, week-based, quarter and zone date tokens, two-digit years, and Java regex constructs the warehouse lacks: what the warehouse cannot read runs in an executor step in a Transform, Filter, Summarize or Time Series calculation, and GEO_* functions anywhere in an expression run in companion Spatial steps. The exceptions are the [named refusals](#named-refusals).

Without a mapping: Some functions compile to a function a warehouse lacks, so the step fails on that warehouse (Databend runs them all). StarRocks: JSON_FIELD in a filter (`json_field_starrocks`; in a Transform or Summarize calculation it runs in an executor step), a `yyyy` date part written with one or two digits, which StarRocks reads as 20xx (`date_short_year_starrocks`), HASH with sha1, SOUNDEX, DURING_DAYLIGHT_SAVING and DURING_STANDARD, and JSON_SET in a filter. Snowflake: REGEX_EXTRACT, REGEX_SEARCH of the first match, a case-insensitive regex (matchCase false or omitted), and JSON_FORMAT and JSON_SET in a filter.

## Export Formats

The loader accepts every observed export shape — flat, model-wrapped, server-record, recipe envelope, array-wrapped, BOM-prefixed, and legacy type aliases — and normalizes them into one model. Tier: **Full**.

## Analysis Parameters

Savant analysis parameters convert to workflow variables, and references to them inside node configs are rewritten to the PlaidCloud variable syntax. List, dictionary, and aliased parameter shapes all load. Tier: **Partial**.

Without a mapping: `parameter_secret_blanked`: a parameter whose name holds a secret word or whose value looks like a credential becomes a variable with a blank value. `parameter_undeclared`: a parameter a node uses that the export does not declare becomes a variable with an empty value.

## Connecting to External Systems

Savant connectors are source and destination targets, not steps, and an export carries no datasets or credentials. PlaidCloud reaches these systems through a connection rather than through a node on the canvas.

| Savant | Where It Goes in PlaidCloud |
| --- | --- |
| Source connector | `source_bindings` maps the Savant node or dataset to a PlaidCloud table or a Document file, read through the matching import step; an unbound source warns and processes nothing |
| Destination: CSV, Excel and other file formats | An export step ([Export: CSV](/reference/workflow-steps/export/export-to-csv/), [Export: Excel](/reference/workflow-steps/export/export-to-excel/), [Export to PDF](/reference/workflow-steps/export/export-to-pdf/)) |
| Destination: Google Sheets, Tableau, Slack | [Export to Google Spreadsheet](/reference/workflow-steps/export/export-to-google-spreadsheet/), [Publish to Tableau](/reference/workflow-steps/export/export-to-tableau/), or [Notify via Slack](/reference/workflow-steps/notifications/notify-via-slack/), through a connection you bind with `destination_bindings` |
| Destination: unbound database, warehouse or SaaS target (Oracle, generic database, Looker Studio, NetSuite, SAP, and Google Sheets, Tableau or Slack with no connection bound) | A project table named after the destination node, with a warning naming the original target |
| Destination: unbound file-system target (S3, GCS, Box, SFTP, SharePoint, Google Drive, OneDrive) | The file, in the destination's file type, in a Document folder that mirrors the target folder, with a warning. Credentials and share tokens are dropped from the folder path |
| Destination: unbound email | A CSV with a warning |
| Destination: binding that can't be used | A CSV with a warning naming the original target |

Conversion never contacts the source or destination system.

## Validating a Converted Workflow

Validation is by oracle, and the evidence label travels with every result.

- **Parity is claimed only against a real golden** — output from the customer's own system of record, compared row by row.
- **Alteryx-equivalence** is the strongest evidence available for a Savant analysis without a golden: the analysis is migrated from an Alteryx workflow with a real golden through Savant's own migration, converted, run, and diffed. A match proves the output is Alteryx-equivalent for that flow, not that it matches the Savant runtime.
- **Expected output derived from the spec** shows consistency with the documented behavior and is never reported as parity.
- Semantics Savant does not document are implemented as the Alteryx reading and reported as unverified against Savant.

Comparison checks schema, row count, and row values, and ignores row order unless the workflow depends on it.
