PlaidCloud converts Savant Labs analyses into native Advanced workflows. The
importer maps each Savant agent to a workflow step, project variable, or
canvas object, so a converted workflow runs cloud-native.

Each agent has a mapping tier:

- **Full** — every option of the agent has a valid mapping to a PlaidCloud
  step.
- **Partial** — the agent converts, and the option named in its row has no
  mapping: it becomes a named placeholder that refuses at run time, is
  refused by name, or is replaced by a stated fallback.

External-system connectors are **connected, not converted** — see
[Connecting to External Systems](#connecting-to-external-systems).

A credential in an API Agent request is never copied into a workflow step. Over https it moves into a REST connection; over http, without permission to write connections, or in a conversion made through MCP it is withheld with a warning. This is by design and does not lower the tier.

## Expression Language

Savant expression functions and operators convert to PlaidCloud expressions. Tier: **Partial**. Functions and operators convert to PlaidCloud expressions, GEO_* functions anywhere in an expression run in companion Spatial steps, and a function with no equivalent is flagged by name.

Without a mapping: TO_TEXT with a numeric pattern or a per-row format, and the S fraction, narrow MMMMM and week-based date tokens, are refused by name.

An aggregate or window function in a plain expression fails in Savant itself, so it is flagged by name; inside a calculation or a Summarize it converts.

## Export Formats

The loader accepts every observed export shape — flat, model-wrapped, server-record, recipe envelope, array-wrapped, BOM-prefixed, and legacy type aliases — and normalizes them into one model. Tier: **Full**.

## Analysis Parameters

Savant analysis parameters convert to project variables, and references to them inside node configs are rewritten to the PlaidCloud variable syntax. List, dictionary, and aliased parameter shapes all load.

## Connecting to External Systems

Savant connectors are source and destination targets, not steps, and an export carries no datasets or credentials. PlaidCloud reaches these systems through a connection rather than through a node on the canvas.

| Savant | Where It Goes in PlaidCloud |
| --- | --- |
| Source connector | `source_bindings` maps the Savant node or dataset to a PlaidCloud table or a Document file, read through the matching import step; an unbound source warns and processes nothing |
| Destination: CSV, Excel | An export step ([Export: CSV](/reference/workflow-steps/export/export-to-csv/), [Export: Excel](/reference/workflow-steps/export/export-to-excel/)) |
| Destination: other connectors | The matching export step when PlaidCloud has one for that system; otherwise a CSV or table destination with a warning naming the original target |

Conversion never contacts the source or destination system.

## Validating a Converted Workflow

Validation is by oracle, and the evidence label travels with every result.

- **Parity is claimed only against a real golden** — output from the customer's own system of record, compared row by row.
- **Alteryx-equivalence** is the strongest evidence available for a Savant analysis without a golden: the analysis is migrated from an Alteryx workflow with a real golden through Savant's own migration, converted, run, and diffed. A match proves the output is Alteryx-equivalent for that flow, not that it matches the Savant runtime.
- **Expected output derived from the spec** shows consistency with the documented behavior and is never reported as parity.
- Semantics Savant does not document are implemented as the Alteryx reading and reported as unverified against Savant.

Comparison checks schema, row count, and row values, and ignores row order unless the workflow depends on it.
