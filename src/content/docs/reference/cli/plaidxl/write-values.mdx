A [`PLAIDXL.CELL`](/reference/cli/plaidxl/functions/#cell) value isn't only for reading. Type a number over one and PlaidXL writes it to the PlaidCloud table behind it, puts the formula back, and recalculates the sheet, so the report shows the new figure and everything that rolls up from it. This is how you enter a budget, a forecast or an adjustment straight into a report.

## Type a Value

1. Select a cell that holds a `PLAIDXL.CELL` formula.
2. Type a number, or one of the [codes](#spread-adjust-and-shape) below, and press **Enter**.

The value is written to PlaidCloud straight away, and the task pane shows what changed — for example, `Jan·East·Revenue 80 → 100 · 14 rows` — with an **Undo** button. Paste or fill a range of values and they're written together.

A cell takes a typed value when it holds a single `CELL` formula, or a `CELL` multiplied, divided or negated by numbers, cells or names — for example `=-PLAIDXL.CELL(...)*$B$1/1000`. PlaidXL works the typed value back to what the `CELL` should hold before writing it. The `CELL`'s arguments must be cells or text, so PlaidXL can tell which intersection to write.

Anything else stays as you typed it:

- Text that isn't a number or a code stays in the cell, and the message says only numbers and adjustments are written.
- A value typed over any other formula isn't written.
- Pressing **Delete** on a `CELL` puts its formula back.
- A positive percentage, such as `10%`, isn't written; type `+10%` to raise the value by 10%, or `0.1` to set it.

If PlaidCloud takes too long to answer, or gives no answer for a cell, the message says the change may have been applied; check the value before writing again. A cell that couldn't be sent says nothing was written.

A value typed just before rows or columns are inserted or deleted is written to the cell Excel moved it to. A value typed into a row or column that is then deleted isn't written, and the message says how many typed values were in deleted or moved cells.

### How the Table Changes

- **sum** — the difference between the old and the new value is added as new rows. They copy the rows already at that intersection, each taking a share in proportion to its size. At an empty intersection, PlaidXL adds one row for each combination of leaf members under the cell's nodes.
- **mean**, **median**, **min** and **max** — every row at the intersection moves by the difference.
- **std** and **var** — the rows at the intersection are spread out or drawn in around their mean, which stays the same.

A single write adds at most 100,000 rows.

## Spread, Adjust and Shape

On a **sum** cell, you can type a code to choose how the value is shared among the leaf members beneath it. Letters can be upper or lower case.

| Type | What happens |
|---|---|
| `1200` | Sets the cell to 1,200, shared in proportion to what each leaf member holds now. |
| `P1200` | The same, written out: in proportion. |
| `E1200` | Sets the cell to 1,200, shared equally among the leaf members. |
| `R1200` | Sets each leaf member to 1,200, so the cell shows 1,200 times the number of members. |
| `1200 like FY2025` | Sets the cell to 1,200, shared in the same shape as the cell for **FY2025**. |
| `+50` or `-50%` | Adjusts the value up or down by an amount or a percentage. |
| `-50` | Sets the cell to -50. A minus sign alone sets a negative value; add `%` to adjust. |
| `H` | Holds the cell, or releases it if it's held. |

Numbers use your Excel decimal and thousands separators. For `like`, the member must belong to just one of the cell's dimensions; if it belongs to two, use a cell that already has it. A shape with nothing in it shares equally.

### Hold a Value

Type `H` over a `CELL` to hold it. A held cell gets a dashed border, and later writes to other cells of the same table and measure leave it as it is: a parent's new value is shared among the members that aren't held. Type `H` again to release it. A hold needs the `CELL`'s arguments to be cells or text; for a cell whose argument is a formula, the message says to hold cells whose arguments are cells or text. Holds are saved with the workbook. If every member under a cell is held, a write to it is refused.

Codes, shapes and holds work on **sum** cells only.

## Undo a Write

Excel's **Ctrl+Z** doesn't reverse a write to PlaidCloud. To undo one, click **Undo** in the message, or click **Undo last write** in the **Write** group of the ribbon (**Ctrl+Alt+Shift+Z**, or **⌘⌥⇧Z** on Mac).

**Undo last write** undoes the newest write made from this workbook, whether a typed value or a [save](/reference/cli/plaidxl/retrieve/#save-a-table-to-plaidcloud); click it again to undo the one before. The list is kept in the workbook, so it survives closing and reopening the file, and holds the last 100 writes.

- **A typed value** is undone by reversing its change, and the sheet recalculates. A write can be undone once. It can't be undone after the table's columns change, or if it was interrupted before it finished; check the cells it changed instead. How the change is reversed depends on the cell:
  - A **sum**, or a **mean** typed into an empty cell, is reversed by adding rows that cancel the ones it added, so rows written into the cell since are kept. An empty **mean** cell shows 0 afterwards, not blank.
  - A **median**, **min**, **max**, **std** or **var** typed into an empty cell is reversed by emptying the cell again, which is refused once someone has written into that cell since.
  - A **mean**, **median**, **min** or **max** typed over existing values moves the rows at the intersection back by the difference, including rows written there since.
  - A **std** or **var** typed over existing values spreads the rows back out or draws them back in, including rows written there since. After a change that drew values in, they can come back slightly off in the last decimal place. A **std** or **var** set to 0, or typed where every value was the same, puts back the rows the cell had before, replacing any written there since.
- **A save** puts the table back to the restore point taken before it. Refresh the sheet to see the restored rows.

Only the person and workspace that made a write can undo it. Someone else's entry stays in the list and says **This write was made by another user or workspace**. An entry already undone says **Already undone or no longer available**. If nothing in the workbook is yours, the message says **Nothing to undo: the writes in this workbook were made by other users or workspaces.** If PlaidCloud takes too long to answer an undo, the message says it may have been applied; try **Undo** again.

## Others Writing at the Same Time

The last write wins. If someone else changed a value after you last refreshed, your write still goes ahead, and the message adds, for example, `was 80, not 75`: PlaidCloud held 80 when you typed, not the 75 your sheet showed.

## Row Access

If your access to a table is limited to some rows, you write only within them. A typed value is shared among the members you can see, and an undo that would change rows outside your access is refused.

<Aside>
Typing values needs a PlaidCloud workspace that accepts them. If PlaidXL says the workspace doesn't take values typed in Excel yet, ask your administrator to update it.
</Aside>
