## Description


Used to extract data from an existing Analyze data table into another data table. Examples include, but are not limited to, the following:


* Sort
* Group
* Summarization
* Filter/Subset Rows
* Drop Extra Columns
* Math Operations
* String Operations

<Aside>There is no functions exclusive to this transform. All sorting, grouping, filtering, etc. can be performed in any other transform with the **Table Data Selection** and **Data Filters** tabs.</Aside>

## Columns Named at Run Time

Select **Also carry columns named at run time** to pass through, unchanged, every source column the step doesn't list, as the table has them when the step runs. Use it when an earlier step creates columns whose names depend on the data, such as a pivot, so you can't list them when you build the step. Leave it off to write only the columns you list.

When it is on, a **Carried Columns** section appears, and a **Columns Named by the Data** section is always available. They have these fields:

* **Carry As** (`carry_expression`) — write each carried column as this expression instead of unchanged, with `__column__` standing for the carried column. This is how a step that groups folds in columns only the run names; a step that aggregates carries nothing without it. **Carried Type** (`carry_dtype`) sets the data type of each carried column (default its own), and **Carried Aggregation** (`carry_agg`) sets how an aggregating step treats it (`dont_group` when the expression aggregates).
* **Rename Carried Columns** (`carry_rename`) — rename each carried column whose name the regular expression `pattern` matches, and `keep` does not, by putting `replacement` in place of each match (`\1` for a group; the first `max` matches, when set). `__index__` in `replacement` is the column's position among the renamed columns, counted from `start`. A name already taken gets ` (#n)` added.
* **Dynamic Columns** (`dynamic_columns`) — target columns named by the data, one set for each distinct value the step reads from its source, written when the step runs. Each entry gives `rows` (expressions `key`, `label`, `where` and `order` over the source), a `target` column or list of columns that uses `__key__`, `__label__` and `__index__`, and `after`, the target column the new ones follow (default the end). Values must be text, integer, boolean or NULL, the step writes at most 1,000 columns, and the output must be a table.
