## Description

Updates the rows that match your filter and writes the result to a target table. Every
source row reaches the target — the rows matching the filter with your new values, and
every other row exactly as it was. The row count of the target always equals the row
count of the source.

The filter chooses which rows are *changed*, not which rows come back. That is what
separates this step from **Table: Extract**, where the filter removes the rows that
don't match.

<Aside type="note" title="This step no longer changes the source table">
It used to update the source table in place. It now leaves the source untouched and
writes to a separate target, so the original data stays available for comparison and
the step runs on every warehouse — including those that don't allow a table to be
changed in place. Steps saved before this change need a target table selected before
they will run, and any step that read the source expecting to see the updated rows
must be pointed at the new target instead.
</Aside>

## Table Selection

On the **Update Parameters** tab:

1. Select the **Source Table** to read from. The list includes all *Project* and
   *Workflow* data tables.
2. Select the **Target Table** to write to. This must be a different table from the
   source. A view is a valid target — it stores no data and re-evaluates against the
   source each time it is read.

The target's columns always mirror the source's, so you never choose them. Columns you
don't update are carried through unchanged, including any column added to the source
after this step was last opened.

## Columns to Update

On the **Table Data Selection** tab, add a row for each column you want to change and
set exactly one of:

- **Constant** — a fixed value.
- **Expression** — a calculation, which may reference other columns of the same row.
- **Set Null** — clears the column.

Columns you don't list are left alone.

<Aside type="caution" title="Expressions read the row's original values">
An expression sees the row as it was *before* the update, so two columns can safely
swap values in a single step.
</Aside>

## Data Filters for Update

On the **Data Filters for Update** tab, enter the condition identifying the rows to
change. Leave it empty to update every row.

A row whose condition cannot be evaluated — most often because a column it tests is
empty — is treated as not matching, and passes through unchanged. This matches how a
database evaluates the same condition.
