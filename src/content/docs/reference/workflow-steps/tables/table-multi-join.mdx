## Description

The **Multi-Table Join** step joins many tables (up to 32) in a single operation using a visual **join-graph designer**, replacing the pattern of chaining several two-table join steps. You add tables, draw joins between their columns, choose a join type and conditions per join, and map the output columns.

For a full walkthrough, see the [Multi-Table Join step guide](/guides/workflows/multi-table-join-step/).

## Designer

* **Add Table** — place a source table on the canvas as a card of columns.
* **Draw joins** — drag from a column on one table to a column on another to create a join.
* **Tidy Layout** / **Fit to View** — auto-arrange the graph, or zoom to fit; pan and zoom are also manual.
* **Undo** / **Redo** / **History** — step through and review your edits.
* **Filter…** — narrow the columns shown on a table card.
* **Export** — download the join diagram as an SVG.

## Join Types

| Type | Keeps |
|------|-------|
| `INNER` | Rows that match across the joined tables. |
| `LEFT` | All rows from the left table, matched rows from the right. |
| `FULL` | All rows from both tables. |
| `CROSS` | Every combination of rows (no conditions allowed). |

## Conditions

Each non-cross join has one or more conditions combined with **AND** / **OR**, using the operators `=`, `<>`, `<`, `<=`, `>`, `>=`, `BETWEEN`, `IS NULL`, `IS NOT NULL`, `IN`, `NOT IN`, `LIKE`, `NOT LIKE`.

## Output

Map the result columns from any joined table — rename, set data type, and aggregate as needed — and optionally filter the joined result before it's written to the target table.

## Behavior

* The join graph is a tree: each table joins into the result through exactly one edge (no cycles).
* The configuration is validated both when you save the step and when it runs; errors highlight the offending table or join.

<Aside type="caution">`CROSS` joins produce the Cartesian product of their inputs and can be very expensive on large tables.</Aside>
