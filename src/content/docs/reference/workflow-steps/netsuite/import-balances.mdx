## Description

Imports account balances from NetSuite over your [NetSuite connection](/guides/connections/netsuite/) into a project table — a trial balance you can build reporting on. Pick the connection, name a target table, and set the period and subsidiary; the step pulls the balances and writes them, with no SuiteQL to author or maintain.

This is one of the canned [NetSuite import steps](/reference/workflow-steps/netsuite/). Each runs on a shared read layer that refreshes the OAuth token, pages through large results, and retries transient errors for you, so a full-year or all-subsidiary pull comes back complete without hand-tuning. For a transaction-level pull, use [NetSuite: Import GL Detail](/reference/workflow-steps/netsuite/import-gl-detail/); for accounts, subsidiaries, and other lists, use [NetSuite: Import Master Data](/reference/workflow-steps/netsuite/import-master-data/).

## Configuration

| Field | Required | Notes |
|---|---|---|
| NetSuite Connection | Yes | The NetSuite connection to read through, filtered to connections of type NetSuite. |
| Target Table | Yes | The project table the balances are written to. It is overwritten in full on every run. |
| Start Date | No | The earliest date to include, `YYYY-MM-DD`, inclusive. Leave blank for no lower bound. Given together with End Date, the pull is automatically windowed into date chunks to stay under NetSuite's SuiteQL row ceiling — see the caution below. |
| End Date | No | The latest date to include, `YYYY-MM-DD`, inclusive. Leave blank for no upper bound. |
| Subsidiary | No | A NetSuite subsidiary internal ID to restrict the pull to one subsidiary. Leave blank for all subsidiaries. |
| Accounting Book | No | A NetSuite accounting book internal ID. Leave blank to pull the **primary book (internal ID 1) only**, or enter `all` to sum across every book. |
| Account Number | No | An exact GL account number to restrict the pull to one account. Leave blank for all accounts. |
| Posting Period | No | A NetSuite posting/accounting period internal ID. Leave blank for all periods. |

<Aside type="caution">
**Multi-book accounts:** a NetSuite account running Multi-Book Accounting posts one row per book per transaction line. Leaving Accounting Book blank pulls the **primary book only** — the correct choice for a standard trial balance. Set it to `all` only if you deliberately want a cross-book total (which sums, rather than reconciles, the books), or to a specific book's internal ID for that book alone.
</Aside>

<Aside type="note">
Subsidiary and Accounting Book take NetSuite's internal ID, not a name. Pull the internal IDs once with [NetSuite: Import Master Data](/reference/workflow-steps/netsuite/import-master-data/) (record type **subsidiary**) and keep them as a small reference table.
</Aside>

<Aside type="note">
NetSuite's SuiteQL API caps a single query at ~100,000 rows without SuiteAnalytics Connect. Giving both Start Date and End Date lets PlaidCloud proactively window the pull into chunks that stay under that ceiling, so a full-year pull comes back complete without you doing anything. An **open-ended** pull (Start Date or End Date left blank) that turns out to cross the ceiling fails with a message asking you to add a date range, rather than silently returning a truncated result.
</Aside>
