## Description

The **Document: Write Blob** step is the counterpart of [Document: Read Blob](/reference/workflow-steps/text-documents/document-blob-extract/). It writes the base64 bytes in a column of each input row to a file in a Document account, one file per row. The output table holds the input rows unchanged.

Create and set the step with an AI assistant or the REST API; it does not have a step form yet. Migrated KNIME and Alteryx workflows use this step for their binary-object and file writers.

## Configuration

- `source` and `target_frame` — the table to read, and the table the input rows are written to unchanged. `source_columns` lists the columns passed through.
- `alteryx_config` — the write itself:
  - `blob_field` — the column holding the base64 bytes.
  - `field` — the column naming each row's file.
  - `method` — `FileName` (default): `field` is a file name placed in the folder of `path`. `Path`: `field` is the whole destination path.
  - `path` — the destination `{account, path}`.
  - `if_exists` — when a file is already there: `overwrite` (default), `fail` the step, or `skip` it and leave the file as it is.
  - `compress` — `gz` compresses the bytes of each file with gzip before it is written.
  - `xml_text` — a value that starts with `<` is XML or SVG text, not base64, and is written as its UTF-8 bytes.
  - `archive` — write the source rows as one archive instead of one file per row, from their `Path` and `Blob` columns (and `Selected` and `EntryName` where they name the entries). The output table then holds `ArchivePath` and `Blob`.
