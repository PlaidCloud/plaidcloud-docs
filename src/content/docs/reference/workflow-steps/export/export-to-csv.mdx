## Description



Writes a PlaidCloud project table to a document account as a CSV (comma-separated values) file. The most common export format — supported by virtually every downstream system, spreadsheet tool, and BI platform.

Configurable: delimiter (comma, tab, pipe, custom), quoting behavior, header row, and encoding.

All exported files are uncompressed, but the following compression options are available:

* No Compression

#### Delimiter
The Export CSV transform is used to export data tables into delimited text files saved in PlaidCloud Document. This includes, but is not limited to, the following delimiter types:


* Excel CSV (comma separated)
* Excel TSV (tab separated)
* User Defined Separator –>


	+ comma (,)
	+ pipe (|)
	+ semicolon (;)
	+ tab
	+ space ( )
	+ other/custom (tilde, dash, etc)

To specify a custom delimiter, select **User Defined Separator –>** and then **Other –>**, and type the custom delimiter into the text box.


#### Special Characters

The **Special Characters** section allows users to specify how to handle data with quotation marks and escape characters. Choose from the following settings:

* Special Characters (QUOTE_MINIMAL): Quote fields with special characters (anything that would confuse a parser configured with the same dialect and options). This is the default setting.
* All (QUOTE_ALL): Quote everything, regardless of type.
* Non-Numeric (QUOTE_NONNUMERIC): Quote all fields that are not integers or floats. When used with the reader, input fields that are not quoted are converted to floats.
* None (QUOTE_NONE): Do not quote anything on output. Quote characters are included in output with the escape character provided by the user. Note that only a single escape character can be provided.

By default a quote inside a quoted field is written doubled (`""`). Turn on `escape_quotes` to write it with the escape character instead, as Spark does: with `\` as the escape character, the field `say "hi"` is written `"say \"hi\""`. The setting is off by default, so existing exports are unchanged. 

A value that holds a quote character is quoted for that reason alone by default. Clear **Quote values that contain the quote character** to write such a value without surrounding quotes, as Spark does with `escapeQuotes` off; a value that holds the delimiter or a line break is still quoted. The checkbox is selected by default. Cleared, the file is written by PlaidCloud rather than the warehouse.

Leave **Quote Character** empty to write every value exactly as it is: nothing is quoted and nothing is escaped. A value that holds the delimiter or a line break then reads back as more fields, so choose a delimiter your data doesn't contain.

#### Write Header to First Row
If this checkbox is selected the table headers will be exported to the first row. If it is not there will be no headers in the exported file.

#### Include Data Types in Headers
If this checkbox is selected the headers of the exported file will contain the data type for the column.

#### Windows Line Endings

Lastly, the **Use Windows Compatible Line Endings** checkbox is selected by default to ensure compatibility with Windows systems. It is advisable to leave this setting on unless working in a unix-only environment.




### If the File Exists

`if_exists` decides what happens when the file is already there: `replace` (default) writes a new file, `append` adds the rows to the end of the existing file without a header row, and `fail` stops the step, writing nothing. An append downloads the file, adds the rows and uploads it again, so when two runs append to the same file at once, the last one to finish wins. Set `header_on_append` to write the header row again below the rows already there.

### Additional Settings

An AI assistant or the REST API can also set these keys:

* `sort_columns` — order the written rows by these source columns, first key first, each `{source, ascending, nulls}`. A key column need not be written. `nulls` defaults to `first` ascending and `last` descending. Not used with **Summarize** or **Distinct**.
* `line_ending` — the line ending of every line, `\n`, `\r\n` or `\r`, in place of **Use Windows Compatible Line Endings**.
* `quote_mode` — which values are quoted: `never`, `always`, `strings` (every value but numbers and booleans) or `delimiter` (a value that holds the delimiter). Unset, a value is quoted when it needs to be.
* `quote_end` — the closing quote, when it differs from the opening quote.
* `quote_replacement` — written in place of a closing quote inside a quoted value. Unset, the quote is doubled.
* `delimiter_replacement` — with `quote_mode` `never`, written in place of the delimiter inside a value.
* `write_bom` — start the file with a byte-order mark.
* `decimal_separator` — the character written for the decimal point of a number.
* `comment_lines` — lines written as they are before the header.
* `scientific_numbers` — write a decimal number in scientific notation from 10 million up and below 0.001, such as `1.0E10`.
* `keep_file_extension` — write each file name exactly as given, without adding `.csv` or `.tsv`.
* `exact_file_name` — with gzip compression, store the file under its name as given, without adding `.gz`.
