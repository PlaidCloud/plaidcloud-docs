## Description

Writes a project table to a document account as an [Apache Parquet](https://parquet.apache.org/) file. Parquet stores data by column rather than by row, so it compresses far better than CSV on wide tables and lets a downstream reader load only the columns it needs.

This is usually the right choice for handing large tables to a cloud data platform or a data-science workflow. Types — integers, decimals, dates, and timestamps — are preserved, and a column of whole numbers stays an integer column when some of its values are blank. Pair it with [Import Parquet](/reference/workflow-steps/import/import-parquet/).

## Unique Configuration Items

### Compression

Parquet compresses per column chunk:

* **Snappy** — fastest to read, moderate file size
* **Zstandard** — smaller files, needs a reader on Zstandard 0.8 or later

### Target File Prefix

When the step exports one table to a single file and the value already ends in `.parquet`, such as `Loadfile1.parquet`, the file is written under exactly that name. Otherwise the value is a prefix: each table is written as `<prefix><table name>.parquet`.

### Single File per Table

Parquet exports write one file for each table. Choosing to write many files is refused with a message saying so; clear that choice to run the export.

### If the File Exists

Set with an AI assistant or the REST API:

* `if_exists` — `overwrite` (default) replaces a file that is already there; `fail` stops the step, writing nothing, when a file it would write already exists.
