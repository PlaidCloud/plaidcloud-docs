## Description


Copies data from a table in a different project into the current project. The inverse of [Export Project Table](/reference/workflow-steps/export/export-project-table/) — pulls rather than pushes.

Useful when a consolidation project sources from many operational projects, or when reference data is centralized in one project and read by others. Cross-project access requires permission on both projects.


## Data Sharing Management

![Data Sharing Management](/images/import_external_project_table_1.png)

In order to import a table from another project you must first go to both projects **Home Tab** and allow the projects to share data with each other. To do this select **New Data Share** and select the project and give them **Read** access.

<Aside type="note" title="Empty source table">
If the source table has no rows when the step runs, the import finishes with a warning that the source was empty rather than a silent success — so an unexpectedly empty target is easy to spot. Most often this means the source project's workflow had not yet built that table; make sure the source is populated (and, for scheduled runs, ordered to run first) before the import.
</Aside>

<Aside type="note" title="Deleting a source table">
The source table you read from is treated as in use by this step. If you try to delete it, PlaidCloud shows the reference and makes you confirm a force-deletion — ticking **Force the delete of the table?** and choosing **Force Deletion** — rather than a plain delete, even when the import step lives in a different project that shares the data. In that cross-project case the warning lists the reference without naming the other project's step, since you may not have access to it.
</Aside>
