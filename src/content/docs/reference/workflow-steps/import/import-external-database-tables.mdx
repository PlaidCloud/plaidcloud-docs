## Description


Imports one or more tables from an external database (configured via a database connector) into project tables. Supports **delta loads** — only pulling rows that have changed since the last import — and **table name remapping** — landing the source table under a different name in PlaidCloud.

Use this for keeping PlaidCloud tables in sync with operational source systems on a schedule, without re-importing every row each time.

<Aside title="Inspect Source reads the external database">
For a table added to this step, the **Inspect Source** button reads that table's current columns straight from the connected database and refreshes just that table's mapping in place. Use it when a source table's columns have changed since you set the step up, without re-running discovery over the whole connection.
</Aside>

<Aside title="PostgreSQL column types">
On a PostgreSQL source, `uuid` columns import as text, and `json`/`jsonb` columns import as their JSON text representation.
</Aside>

<Aside title="Numeric columns import as exact decimals">
A source `numeric`/`decimal` column imports as an exact decimal value, holding up to 28 digits to the left of the decimal point and 10 digits to the right. A value with more than 10 decimal places is rounded to fit; a value with more than 28 whole digits stops the import naming the column.
</Aside>

<Aside type="caution" title="A value that doesn't fit its column stops the import">
If a source value can't fit its target column without losing data — a fraction landing in an integer column, a number too large for its column, or `NaN`/`Infinity` landing in a numeric column — the import stops with an error naming the column and its data type, rather than silently truncating or rounding it. In the step's Data Mapper, set that column's **Type** to one that can hold the value, then rerun the import.
</Aside>
