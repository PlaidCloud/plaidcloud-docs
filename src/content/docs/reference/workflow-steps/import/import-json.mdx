## Description

Import JSON text files from PlaidCloud Document.

For more details on JSON files, see the JSON official website here: http://json.org/.

JSON files do *not* retain column order. The column order in the source file does not necessarily reflect the column order in the imported data table.

JSON imports stream through temporary storage rather than loading the whole document into memory, so very large files import without running out of memory. Columns that first appear late in a large document are included in the imported table. Nested objects and arrays are imported as standard compact JSON text, so downstream steps can parse them with any JSON tooling.

## Unique Configuration Items

### JSON Data Orientation

Consider the following data set:

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

JSON files can be imported from one of three data formats:

* Records: Data is stored in Python dictionary sets, with each row stored in \{Column -> Value, …} format. For example:


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index: Data is stored in nested Python dictionary sets, with each row stored in \{Index -> \{Column -> Value, …},…} format. For example:


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split: Data is stored in a single Python dictionary set, values stored in lists. For example:


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

In addition to the formats above, newline-delimited JSON (NDJSON) is accepted: one standalone JSON object per line, with no enclosing array. For example:

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### Whole Document

To keep each file's JSON intact, select **Import each file as one row holding its whole JSON document** (`whole_document`) in **More JSON Options**. Each file then imports as one row holding its whole JSON document, with numbers kept as written.

### Dates and Timestamps

A field imports as dates or timestamps when all its values have the same one of these layouts:

| Layout | Dates | Timestamps |
| --- | --- | --- |
| ISO 8601 | `2026-01-23` | `2026-01-23T23:14:00` |
| Month first | `01-23-2026` or `01-23-26` | `01-23-2026 11:14:00 PM`, with a 12-hour time |
| Day first | `23-01-2026` or `23-01-26` | `23-01-2026 23:14:00`, with a 24-hour time |
| Two-digit year first | `99-01-23` | `99-01-23 23:14:00`, with a 24-hour time |

Every value in a field is read the same way, whatever order the rows are in. A field in any other layout, such as `01/23/2026` or `01-23-2026 23:14:00`, imports as text. So does a field whose values mix layouts, though some mixes of two-digit and four-digit years, such as `01-23-2026` and `01-24-26`, stop the import instead, with an error that names the field.

#### When a Value Fits More Than One Layout

`01-03-2026` could be 3 January or 1 March, and `23-01-26` could be 23 January 2026 or, read year first, 26 January 2023. When all of a field's values fit more than one of the layouts above, the step's **Date Format** decides by its order of day, month and year:

* A choice starting Month Day reads month first: `01-03-2026` as 3 January.
* A choice starting Day Month or Abbreviated reads day first: `01-03-2026` as 1 March, and `23-01-26` as 23 January 2026.
* With any other Date Format, the import stops with an error that names the field and the choices that would settle it.

These choices also read a timestamp on the other clock when every value's day and month are 12 or under: a Month Day choice reads `01-03-2026 23:14:00` as 3 January, and a Day Month or Abbreviated choice reads `01-03-2026 11:14:00 PM` as 1 March. Any other Date Format reads them as the table does, day first with a 24-hour time and month first with a 12-hour time.

No Date Format choice reads a two-digit year first, so a field such as `26-01-23` imports year first only when its values can't be read another way, as with `99-01-23`. Written with a four-digit year, as `2026-01-23`, such a date imports as ISO 8601.

A file that also holds a timestamp inside a nested object or array is the exception: none of the checks above apply to it, and a value that fits more than one layout may be read differently from one row to the next.
