## Description

Import delimited text files from PlaidCloud Document. This includes, but is not limited to, the following delimiter types:
* comma (, )
* pipe (|)
* semicolon (; )
* tab
* space ( )
* at symbol (@)
* tilda (~)
* colon (:)

### Inspect Selected Source File

By pressing the *Guess Settings from Source File* button, PlaidCloud will open the file and inspect it to attempt to determine the data format.  Always check
the guessed settings to make sure they seem correct.

<Aside>If a directory of files is selected for import or search is used, the first file found will be used for guessing</Aside>

A step whose file yields no columns can't be saved: saving stops with **No Columns Detected**. When PlaidCloud could not read the file, the message says why — for example, an extension that isn't typical for a delimited file, or a file path using a workflow variable that isn't defined. Otherwise check that the delimiter, quote and escape characters match the file, that it is a delimited text file, and that it isn't empty.

### Data Format

#### Delimiter
As mentioned above, **Inspect Source File** will attempt to determine the delimiter in the source file. If another delimiter is desired, use this 
section to specify the delimiter. Users can choose from a list of standard delimiters.
* comma (, )
* pipe (|)
* semicolon (; )
* tab
* space ( )
* at symbol (@)
* tilda (~)
* colon (:)

#### Header Type

Since CSVs may or may not contain headers, PlaidCloud provides a way to either use the headers, ignore headers, or use column order to determine the column alignment.
* **No Header**: The CSV file contains no header.  Use the source list in the *Data Mapper* to determine the column alignment
* **Has Header - Use Header and Override Field List**: The CSV file has a header.  Use the header names specified and ignore the source list in the *Data Mapper*.
* **Has Header - Skip Header and Use Field List Instead**: The CSV file has a header but it should be ignored.  Use the header names specified by the source list in the *Data Mapper*.

#### Date Format

This setting is useful if the dates contained in the CSV file are not readily recognizable as dates and times.  The import process attempts to convert dates but having a little extra information
can help in the import process.

A value the warehouse cannot read against the format it is given is stored as empty rather than stopping the import, so a format that doesn't match the file
produces a column of empty dates and an import that still reports success. After changing this setting, check the imported column before relying on the result.

<Aside type="caution" title="Time Columns on Lakehouse v2">
A column whose data type is **Time** imports as empty on Lakehouse v2, whatever date format you supply. The warehouse function used to parse it cannot
produce a bare time-of-day value. Import the column as **Timestamp** and read the time from it, or import it as **Text**. **Date** and **Timestamp**
columns are unaffected.
</Aside>

### Special Characters

The special character inputs control how PlaidCloud handles the presence of certain characters and what they mean in the context of processing the CSV
 * **Quote Character**: This is the character used to indicate an enclosed set of text that should be processed as a single field
 * **Escape Character**: This is the character used to indicate the following character should be processed as it is and not interpreted as a special character.  Useful when field may contain the delimiter.
 * **Null Character**: Since CSVs don't have data types, this character provides a way to indicate that the value should be NULL rather than an empty string or 0.
 * **Empty fields**: An empty field loads as NULL on every lakehouse, for text and number columns alike, so a blank number is NULL rather than 0. A cell that holds only spaces is loaded as it is.
 * **Trailing Negatives**: Some source systems generate negative numbers with trailing negative symbols instead of prefixing the negative.  This setting will process those as negative numbers.

### Row Selection

For input files with extraneous records, set **Skip Rows** to the number of lines to skip before processing the data.  This is useful if files contain header blocks that must be skipped before arriving at the tabular data.

The skipped lines include blank lines. With a **Header Type** of **Has Header - Use Header and Override Field List**, the header is read from the first line after the skipped lines, so the data maps to your target columns by header name. A file that holds only the skipped lines and a header, with no data rows, imports nothing and the step still completes.

#### Example: SAP List Export

An SAP list export such as KE24, KSB1 or FAGLL03 starts with a selection block, often with blank lines, before the column header:

```text
Line Item Journal Entries
Company Code: 1000
Posting Date: 2026-09-01 to 2026-09-30

Company Code|Document Number|Posting Date|Amount
1000|100004512|2026-09-03|1,500.00
```

The header is on line 5, so there are four lines before it. Set **Skip Rows** to `4` and **Header Type** to **Has Header - Use Header and Override Field List**. The import reads `Company Code`, `Document Number`, `Posting Date` and `Amount` as the column names, and the first data row is the line after the header.
