## Description

Not every geospatial operation needs a dedicated step. Anything that is a
single-row column expression runs as a [Table Extract](/reference/workflow-steps/tables/table-extract/)
expression cell, in the database, with no rows leaving the warehouse — so it
scales with the table rather than with the workflow engine. This is the route
[Alteryx conversion](/guides/workflows/migrate-spatial-alteryx-workflows/) picks
for the Alteryx *Create Points* and *Distance* tools.

## Portable Geometry Functions

Lakehouse v1 and v2 spell their geometry functions differently — `ST_MAKEGEOMPOINT`
against `ST_POINT`, `ST_ASWKT` against `ST_ASTEXT`. The `geom_*` family resolves
to the right one for the workspace you are running on, so an expression written
once works on both.

| Expression | Lakehouse v1 | Lakehouse v2 |
|---|---|---|
| `func.geom_from_wkt(x)` | `ST_GEOMETRYFROMWKT` | `ST_GEOMETRYFROMTEXT` |
| `func.geom_point(lon, lat)` | `ST_MAKEGEOMPOINT` | `ST_POINT` |
| `func.geom_as_wkt(g)` | `ST_ASWKT` | `ST_ASTEXT` |
| `func.geom_contains(a, b)` | `ST_CONTAINS` | `ST_CONTAINS` |
| `func.geom_within(a, b)` | `ST_WITHIN` | `ST_CONTAINS`, arguments swapped |
| `func.geom_x(g)` | `ST_X` | `ST_X` |
| `func.geom_y(g)` | `ST_Y` | `ST_Y` |

<Aside type="note" title="Not Everything Is Portable">
  `geom_area`, `geom_length`, `geom_intersects`, `geom_centroid`,
  `geom_distance`, `geom_createline`, and the bounding-box edges
  (`st_xmin`/`st_xmax`/`st_ymin`/`st_ymax`) exist on Lakehouse v1 only —
  StarRocks ships no equivalent. On a v2 workspace they fail when the
  expression compiles, with a message naming the function, rather than
  producing a wrong answer. Use the
  [geospatial steps](/reference/workflow-steps/spatial/) for those measures
  instead; they run in the workflow engine and give the same answer on every
  warehouse.
</Aside>

## Create Points

Build a WKT point from a longitude column and a latitude column:

```python
func.geom_as_wkt(
    func.geom_point(
        get_column(table, 'Longitude'),
        get_column(table, 'Latitude'),
    )
)
```

`geom_as_wkt` writes the result as WKT, the form every PlaidCloud spatial step
reads and writes.

<Aside type="caution" title="Floating-Point Lon/Lat Only">
  This is exact for plain decimal-degree coordinates. Coordinates stored as
  integers scaled by 1,000,000, or in a projected coordinate system, need
  rescaling or reprojecting first — building a point from them directly
  produces mis-scaled or unprojected geometry.
</Aside>

## Distance Between Two Points

Measure the geodesic distance between two point columns, guarding against rows
where either side is not a point:

```python
case(
    (
        and_(
            get_column(table, 'Origin').like('POINT%'),
            get_column(table, 'Destination').like('POINT%'),
        ),
        func.st_distance_sphere(
            func.geom_x(func.geom_from_wkt(get_column(table, 'Origin'))),
            func.geom_y(func.geom_from_wkt(get_column(table, 'Origin'))),
            func.geom_x(func.geom_from_wkt(get_column(table, 'Destination'))),
            func.geom_y(func.geom_from_wkt(get_column(table, 'Destination'))),
        ) * 0.0006213711922373339,
    ),
    else_=null,
)
```

`ST_DISTANCE_SPHERE` returns meters, so the trailing factor converts to the unit
you want:

| Unit | Factor |
|---|---|
| Miles | `0.0006213711922373339` |
| Kilometers | `0.001` |
| Meters | `1` |
| Feet | `3.280839895013123` |

The `LIKE 'POINT%'` guard matters: `ST_DISTANCE_SPHERE` takes four coordinates,
so a non-point geometry on either side would silently measure the wrong thing.
The `CASE` returns null for those rows instead.

## When to Use a Step Instead

| You want | Use |
|---|---|
| Distance from each row to its *nearest* rows in another table | [Spatial Find Nearest](/reference/workflow-steps/spatial/spatial-find-nearest/) |
| Distance as a filter in a spatial join | [Spatial Match](/reference/workflow-steps/spatial/spatial-match/) |
| Area, length, centroid, or bounding box | [Spatial Info](/reference/workflow-steps/spatial/spatial-info/) |
| Anything that changes the shape of a geometry | [Geospatial steps](/reference/workflow-steps/spatial/) |
