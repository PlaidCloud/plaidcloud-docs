## Description

Runs a versioned Alteryx-parity operation as a managed job. It is the general-purpose carrier for [Alteryx conversions](/guides/workflows/migrate-alteryx-workflows/) whose work needs Python libraries — Shapely, scikit-learn, NLTK, Tesseract, reportlab — rather than database SQL.

Most converted operations now have their own first-class step type, which is easier to read and edit. This step remains for the operations that do not, and it is what those step types launch underneath.

<Aside type="note" title="Usually Not Hand-Authored">
  Conversion emits this step where it is needed. You would add one by hand only
  to run a parity operation that has no step type of its own — for example
  [Spatial Info](/reference/workflow-steps/spatial/spatial-info/).
</Aside>

## Configuration

### Executor

- **Operation** — the parity operation to run.
- **Contract version** — the executor contract the operation runs under. Defaults to `v1`.

### Inputs and Outputs

- **Source** / **Target table** — the primary input and output tables.
- **Input tables** / **Output tables** — additional tables for operations that take or produce more than one.
- **Input artifacts** / **Output artifacts** — non-table inputs and outputs, such as rendered images.

### Resources

Off by default, in which case the job gets standard resources. Turn on advanced resource management to set **CPU** and **memory** explicitly — worth doing when an operation handles unusually large geometry or model training and the default allocation is not enough.
