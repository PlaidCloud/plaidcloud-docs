## Descripción

Importe archivos de texto JSON desde PlaidCloud Document.

Para obtener más detalles sobre los archivos JSON, consulte el sitio web oficial de JSON: http://json.org/.

Los archivos JSON *no* conservan el orden de las columnas. El orden de las columnas del archivo de origen no refleja necesariamente el orden de las columnas de la tabla de datos importada.

Las importaciones de JSON se transmiten a través de almacenamiento temporal en lugar de cargar todo el documento en memoria, por lo que los archivos muy grandes se importan sin agotar la memoria. Las columnas que aparecen por primera vez al final de un documento grande se incluyen en la tabla importada. Los objetos y las matrices anidados se importan como texto JSON compacto estándar, de modo que los pasos posteriores pueden analizarlos con cualquier herramienta de JSON.

## Elementos de configuración exclusivos

### Orientación de los datos JSON

Considere el siguiente conjunto de datos:

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

Los archivos JSON se pueden importar desde uno de tres formatos de datos:

* Records: los datos se almacenan en conjuntos de diccionarios de Python, con cada fila almacenada en el formato \{Column -> Value, …}. Por ejemplo:


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index: los datos se almacenan en conjuntos anidados de diccionarios de Python, con cada fila almacenada en el formato \{Index -> \{Column -> Value, …},…}. Por ejemplo:


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split: los datos se almacenan en un único conjunto de diccionario de Python, con los valores almacenados en listas. Por ejemplo:


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

Además de los formatos anteriores, se acepta JSON delimitado por saltos de línea (NDJSON): un objeto JSON independiente por línea, sin matriz envolvente. Por ejemplo:

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### Documento completo

Para mantener intacto el JSON de cada archivo, seleccione **Importar cada archivo como una fila con todo su documento JSON** (`whole_document`) en **Más opciones de JSON**. Cada archivo se importa entonces como una fila que contiene todo su documento JSON, con los números tal como están escritos.

### Fechas y marcas de tiempo

Un campo se importa como fechas o marcas de tiempo cuando todos sus valores tienen el mismo diseño de los siguientes:

| Diseño | Fechas | Marcas de tiempo |
| --- | --- | --- |
| ISO 8601 | `2026-01-23` | `2026-01-23T23:14:00` |
| Mes primero | `01-23-2026` o `01-23-26` | `01-23-2026 11:14:00 PM`, con hora de 12 horas |
| Día primero | `23-01-2026` o `23-01-26` | `23-01-2026 23:14:00`, con hora de 24 horas |
| Año de dos dígitos primero | `99-01-23` | `99-01-23 23:14:00`, con hora de 24 horas |

Todos los valores de un campo se leen de la misma manera, sea cual sea el orden de las filas. Un campo con cualquier otro diseño, como `01/23/2026` o `01-23-2026 23:14:00`, se importa como texto. Lo mismo ocurre con un campo cuyos valores mezclan diseños, aunque algunas mezclas de años de dos y cuatro dígitos, como `01-23-2026` y `01-24-26`, detienen la importación con un error que nombra el campo.

#### Cuando un valor encaja en más de un diseño

`01-03-2026` podría ser el 3 de enero o el 1 de marzo, y `23-01-26` podría ser el 23 de enero de 2026 o, leído con el año primero, el 26 de enero de 2023. Cuando todos los valores de un campo encajan en más de uno de los diseños anteriores, el **Formato de fecha** del paso decide según su orden de día, mes y año:

* Una opción que empieza por Mes y día lee el mes primero: `01-03-2026` como el 3 de enero.
* Una opción que empieza por Día y mes o por Abreviado lee el día primero: `01-03-2026` como el 1 de marzo, y `23-01-26` como el 23 de enero de 2026.
* Con cualquier otro Formato de fecha, la importación se detiene con un error que nombra el campo y las opciones que lo resolverían.

Estas opciones también leen una marca de tiempo con el otro reloj cuando el día y el mes de todos los valores son 12 o menos: una opción Mes y día lee `01-03-2026 23:14:00` como el 3 de enero, y una opción Día y mes o Abreviado lee `01-03-2026 11:14:00 PM` como el 1 de marzo. Cualquier otro Formato de fecha las lee como la tabla: día primero con hora de 24 horas y mes primero con hora de 12 horas.

Ninguna opción de Formato de fecha lee un año de dos dígitos primero, de modo que un campo como `26-01-23` se importa con el año primero solo cuando sus valores no se pueden leer de otra manera, como ocurre con `99-01-23`. Escrita con un año de cuatro dígitos, como `2026-01-23`, una fecha así se importa como ISO 8601.

Un archivo que además contiene una marca de tiempo dentro de un objeto o una matriz anidados es la excepción: ninguna de las comprobaciones anteriores se aplica, y un valor que encaja en más de un diseño puede leerse de forma distinta de una fila a otra.
