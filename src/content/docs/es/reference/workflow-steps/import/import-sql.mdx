## Descripción


Importa el resultado de una consulta SQL contra una base de datos externa en una tabla de proyecto de PlaidCloud. La consulta se ejecuta en la base de datos remota; solo el conjunto de resultados se trae a PlaidCloud.

Se diferencia de [Importar tablas de bases de datos externas](/es/reference/workflow-steps/import/import-external-database-tables/) en que usted escribe el SQL: es útil para combinaciones, filtros o agregaciones complejos que desea que realice la base de datos de origen antes de que los datos lleguen a PlaidCloud.

### Detección de tipos de columna
Las importaciones de SQL ofrecen la opción de intentar detectar el tipo de datos durante la carga, o de establecer todas las columnas con el tipo Texto. Establecer los tipos de datos de forma dinámica puede ser más rápido si los datos están limpios, pero puede causar problemas en algunas circunstancias.

Por ejemplo, si la mayoría de los datos parecen numéricos pero también hay algo de texto, puede intentar establecerlos como numéricos y causar problemas de carga por tipos de datos que no coinciden. O puede haber problemas si hay un código de producto numérico de 16 dígitos, por ejemplo. Recortaría los ceros iniciales y el resultado sería un número en lugar de un código de 16 dígitos.

Sin embargo, establecer todos los datos como texto requiere un paso de extracción posterior para convertir los tipos de datos que no deberían ser texto al tipo adecuado, como fechas o valores numéricos.

## Solución de problemas

| Síntoma | Causa probable |
| --- | --- |
| El paso tardó notablemente más de lo habitual (hasta aproximadamente media hora más) sin que cambiara nada más en su consulta, su conexión o el volumen de datos | El proceso de trabajo en segundo plano que ejecutaba la importación se interrumpió a mitad de camino (un reinicio o desalojo del lado de la plataforma, no algo de su flujo de trabajo) y la plataforma reintentó por usted la importación de la tabla. El reintento solo comienza cuando se detecta la interrupción, lo que explica el tiempo adicional. |
| El paso terminó correctamente después de ese retraso | El reintento reemplaza por completo el contenido de la tabla, por lo que el resultado es el mismo que el de una única ejecución limpia: no hay nada más que comprobar ni rehacer. |
| El paso falla con «has already been attempted and cannot be safely re-run» | Para un paso Importar SQL, este rechazo ya no se produce: una interrupción a mitad de la ejecución se reintenta. Seguirá viéndolo, por diseño, al [restaurar un archivo de proyecto](/es/guides/projects/archive-a-project/#restauración-de-un-archivo) o al [cargar una dimensión](/es/reference/workflow-steps/dimensions/dimension-load/), donde volver a ejecutar crearía un duplicado en lugar de reemplazar algo. Abra un ticket de soporte si lo ve en un paso Importar SQL.
