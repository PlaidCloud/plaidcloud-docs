## Descripción

Lee un archivo de base de datos de Microsoft Access desde una cuenta de documentos e importa sus tablas, una tabla de proyecto por cada tabla de Access, con un nombre que lleva el prefijo que usted elija.

Como un archivo de Access contiene muchas tablas, este paso importa el archivo completo en lugar de asignar las columnas de una sola tabla.

## Elementos de configuración exclusivos

### Origen

El archivo de base de datos de Access en una cuenta de documentos. El selector de archivos también admite la coincidencia por búsqueda en lugar de una ruta exacta, con una opción recursiva y una regla para conciliar las diferencias de esquema entre los archivos coincidentes.

### Destino

**Prefijo de tabla**: se antepone al nombre de cada tabla importada, de modo que las tablas de un mismo archivo permanezcan agrupadas y no colisionen con las de otra importación.

### Omitir si no hay cambios

Activado de forma predeterminada. Una ejecución del flujo de trabajo omite por completo la importación, descarga incluida, cuando el archivo de origen no ha cambiado desde la última ejecución y las tablas de destino aún contienen las filas que cargó. Una tabla que se haya vaciado se importa de nuevo.

## Cuando no se puede leer el archivo

El paso falla, e indica el archivo y la tabla que no pudo leer, en lugar de terminar y dejar una tabla vacía. Esto ocurre cuando el archivo no incluye ninguna tabla que PlaidCloud pueda leer, cuando se nombra una tabla pero no se pueden describir sus columnas, o cuando falla la lectura de las filas de una tabla; la causa habitual es un archivo escrito por una versión de Access más reciente de la que entiende el lector. Convierta o vuelva a exportar el archivo desde Access y ejecute la importación de nuevo.

Un archivo cuyas tablas están todas realmente vacías se importa correctamente e informa de una advertencia indicando que no se cargó ningún registro.
