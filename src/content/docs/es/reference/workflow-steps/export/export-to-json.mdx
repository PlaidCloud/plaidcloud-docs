## Descripción


Exporte una tabla de datos de Analyze a PlaidCloud Document como un archivo JSON. Hay varias opciones (que se muestran a continuación) para la orientación de los datos.



Para obtener más información sobre los archivos JSON, consulte el sitio web oficial de JSON aquí: http://json.org/.


<Aside>Los archivos JSON *no* conservan el orden de las columnas. El orden de las columnas de la tabla de datos de origen no se refleja necesariamente en el archivo exportado.</Aside>

### Orientación de JSON


Considere el siguiente conjunto de datos:




| ID |  Name  | Gender | State |
|----|--------|--------|-------|
| 1  | Jack   |   M    |   MO  |
| 2  | Jill   |   F    |   MO  |
| 3  | George |   M    |   VA  |
| 4  | Abe    |   M    |   KY  |

Los archivos JSON se pueden exportar en uno de cuatro formatos de datos:


* Records: los datos se almacenan en conjuntos de diccionarios de Python, y cada fila se guarda en el formato \{Column -> Value, …}. Por ejemplo: **[\{“ID”:1,”Name”:”Jack”,”Gender”:”M”,”State”:”MO”},\{“ID”:2,”Name”:”Jill”,”Gender”:”F”,”State”:”MO”},\{“ID”:3,”Name”:”George”,”Gender”:”M”,”State”:”VA”},\{“ID”:4,”Name”:”Abe”,”Gender”:”M”,”State”:”KY”}]**
* Index: los datos se almacenan en conjuntos de diccionarios de Python anidados, y cada fila se guarda en el formato \{Index -> \{Column -> Value, …},…}. Por ejemplo: **\{“0”:\{“ID”:1,”Name”:”Jack”,”Gender”:”M”,”State”:”MO”},”1”:\{“ID”:2,”Name”:”Jill”,”Gender”:”F”,”State”:”MO”},”2”:\{“ID”:3,”Name”:”George”,”Gender”:”M”,”State”:”VA”},”3”:\{“ID”:4,”Name”:”Abe”,”Gender”:”M”,”State”:”KY”}}**
* Split: los datos se almacenan en un único conjunto de diccionario de Python, y los valores se guardan en listas. Por ejemplo: **\{“columns”:[“ID”,”Name”,”Gender”,”State”],”index”:[0,1,2,3],”data”:[[1,”Jack”,”M”,”MO”],[2,”Jill”,”F”,”MO”],[3,”George”,”M”,”VA”],[4,”Abe”,”M”,”KY”]]}**
* Values: los datos se almacenan en varias listas de Python. Por ejemplo: **[[1,”Jack”,”M”,”MO”],[2,”Jill”,”F”,”MO”],[3,”George”,”M”,”VA”],[4,”Abe”,”M”,”KY”]]**


### Tratamiento de fechas


Especifique el **Formato de fecha** mediante el menú desplegable. Elija entre los siguientes formatos:


* **Epoch (Unix Timestamp – Seconds since 1/1/1970)**
* **ISO 8601 Format (YYYY-MM-DD HH:MM:SS with timeproject offset)**

Especifique la **Unidad de fecha** mediante el menú desplegable. Elija entre los siguientes formatos, enumerados en orden de precisión creciente:


* **Segundos (s)**
* **Milisegundos (ms)**
* **Microsegundos (us)**
* **Nanosegundos (ns)**

### Forzar ASCII


Seleccione esta casilla para asegurarse de que todas las cadenas se codifiquen en formato ASCII correcto. Esta opción está habilitada de forma predeterminada.



### Tipo de archivo de salida


Todos los archivos exportados se generan sin comprimir, pero están disponibles las siguientes opciones de compresión:


* Zip
* GZip
* BZip2


### Configuración adicional

* **Un archivo que ya existe** (`if_exists`), en **Si el archivo existe**: **Sobrescribirlo** (`overwrite`, predeterminado) reemplaza un archivo que ya existe; **Hacer fallar el paso sin escribir nada** (`fail`) detiene el paso sin escribir nada cuando ya existe un archivo que se iba a escribir.
* **Ordenar filas por** (`sort_columns`), en **Orden de las filas**: ordena las filas escritas según estas columnas de origen, empezando por la primera clave, cada una con una configuración de **Columna**, **Ascendente** y **Nulos**. No es necesario que se escriba la columna clave. **Nulos** es, de forma predeterminada, primero en orden ascendente y último en orden descendente. No se usa con **Resumir** ni **Distinto**.
