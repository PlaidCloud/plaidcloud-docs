## Descripción



Escribe una tabla de proyecto de PlaidCloud en una cuenta de documentos como un archivo CSV (valores separados por comas). Es el formato de exportación más habitual: lo admiten prácticamente todos los sistemas posteriores, las herramientas de hojas de cálculo y las plataformas de BI.

Configurable: delimitador (coma, tabulación, barra vertical, personalizado), comportamiento de las comillas, fila de encabezado y codificación.

### Selección de la compresión de archivo

Todos los archivos exportados están sin comprimir, pero están disponibles las siguientes opciones de compresión:

* Sin compresión
* Zip
* GZip
* BZip2



### Formato de datos

![Formato de datos de Export CSV](/images/export_file_csv_data_format.png)



#### Delimitador
La transformación Export CSV se utiliza para exportar tablas de datos a archivos de texto delimitado guardados en PlaidCloud Document. Esto incluye, entre otros, los siguientes tipos de delimitador:


* CSV de Excel (separado por comas)
* TSV de Excel (separado por tabulaciones)
* Separador definido por el usuario –>


	+ coma (,)
	+ barra vertical (|)
	+ punto y coma (;)
	+ tabulación
	+ espacio ( )
	+ otro/personalizado (virgulilla, guion, etc.)

Para especificar un delimitador personalizado, seleccione **Separador definido por el usuario –>** y después **Otro –>**, y escriba el delimitador personalizado en el cuadro de texto.


#### Caracteres especiales

La sección **Caracteres especiales** permite especificar cómo tratar los datos con comillas y caracteres de escape. Elija entre las siguientes configuraciones:

* Caracteres especiales (QUOTE_MINIMAL): entrecomilla los campos con caracteres especiales (todo lo que confundiría a un analizador configurado con el mismo dialecto y las mismas opciones). Esta es la configuración predeterminada.
* Todo (QUOTE_ALL): entrecomilla todo, sea cual sea el tipo.
* No numérico (QUOTE_NONNUMERIC): entrecomilla todos los campos que no sean enteros ni de punto flotante. Cuando se usa con el lector, los campos de entrada sin comillas se convierten en números de punto flotante.
* Ninguno (QUOTE_NONE): no entrecomilla nada en la salida. Los caracteres de comillas se incluyen en la salida con el carácter de escape que proporcione el usuario. Tenga en cuenta que solo se puede proporcionar un único carácter de escape.

De forma predeterminada, una comilla dentro de un campo entrecomillado se escribe duplicada (`""`). Active `escape_quotes` para escribirla con el carácter de escape en su lugar, como hace Spark: con `\` como carácter de escape, el campo `say "hi"` se escribe `"say \"hi\""`. La opción está desactivada de forma predeterminada, por lo que las exportaciones existentes no cambian. 

De forma predeterminada, un valor que contiene un carácter de comillas se entrecomilla solo por ese motivo. Desmarque **Entrecomillar los valores que contengan el carácter de comillas** para escribir ese valor sin comillas circundantes, como hace Spark con `escapeQuotes` desactivado; un valor que contiene el delimitador o un salto de línea sigue entrecomillándose. La casilla está marcada de forma predeterminada. Si se desmarca, el archivo lo escribe PlaidCloud en lugar del almacén.

Deje **Carácter de comillas** vacío para escribir cada valor exactamente como es: no se entrecomilla ni se escapa nada. Un valor que contiene el delimitador o un salto de línea se lee entonces como más campos, así que elija un delimitador que sus datos no contengan.

#### Escribir el encabezado en la primera fila
Si esta casilla está marcada, los encabezados de la tabla se exportan a la primera fila. Si no lo está, el archivo exportado no tendrá encabezados.

#### Incluir los tipos de datos en los encabezados
Si esta casilla está marcada, los encabezados del archivo exportado contendrán el tipo de datos de la columna.

#### Finales de línea de Windows

Por último, la casilla **Use Windows Compatible Line Endings** está marcada de forma predeterminada para garantizar la compatibilidad con los sistemas Windows. Se recomienda dejar esta configuración activada, salvo que se trabaje únicamente en un entorno unix.




### Si el archivo existe

En **Más opciones de CSV**, **Un archivo que ya existe** (`if_exists`) decide qué ocurre cuando el archivo ya está allí: `replace` (valor predeterminado) escribe un archivo nuevo, `append` agrega las filas al final del archivo existente sin una fila de encabezado y `fail` detiene el paso sin escribir nada. Una anexión descarga el archivo, agrega las filas y lo vuelve a cargar, de modo que cuando dos ejecuciones anexan al mismo archivo a la vez, prevalece la última en terminar. Con `append`, seleccione **Volver a escribir el encabezado debajo de las filas existentes** (`header_on_append`) para escribir de nuevo la fila de encabezado debajo de las filas que ya están allí.

### Configuración adicional

**Más opciones de CSV** contiene además estos campos:

* **Ordenar filas por** (`sort_columns`): ordena las filas escritas según estas columnas de origen, empezando por la primera clave, cada una con una configuración de **Columna**, **Ascendente** y **Nulos**. No es necesario que se escriba una columna clave. **Nulos** es, de forma predeterminada, primero en orden ascendente y último en orden descendente. No se usa con **Resumir** ni **Distinto**.
* **Final de línea** (`line_ending`): el final de cada línea, `\n`, `\r\n` o `\r`, en lugar de **Use Windows Compatible Line Endings**.
* **Entrecomillar** (`quote_mode`): qué valores se entrecomillan: **Nunca**, **Siempre**, **Todos los valores salvo números y booleanos** o **Un valor que contiene el delimitador**. De forma predeterminada, un valor se entrecomilla cuando es necesario.
* **Comilla de cierre** (`quote_end`): la comilla de cierre, cuando difiere de la comilla de apertura.
* **Comilla de cierre dentro de un valor** (`quote_replacement`): se escribe en lugar de una comilla de cierre dentro de un valor entrecomillado. Si se deja vacío, la comilla se duplica.
* **Delimitador dentro de un valor** (`delimiter_replacement`): con **Entrecomillar** establecido en **Nunca**, se escribe en lugar del delimitador dentro de un valor.
* **Iniciar el archivo con una marca de orden de bytes** (`write_bom`): inicia el archivo con una marca de orden de bytes.
* **Separador decimal** (`decimal_separator`): el carácter que se escribe para el punto decimal de un número.
* **Líneas antes del encabezado** (`comment_lines`): una matriz JSON de líneas que se escriben tal cual antes del encabezado.
* **Write decimal numbers as Java does** (`scientific_numbers`): escribe un número decimal en notación científica desde 10 millones en adelante y por debajo de 0.001, como `1.0E10`.
* **Escribir cada nombre de archivo tal como se indica, sin añadir .csv ni .tsv** (`keep_file_extension`): escribe cada nombre de archivo exactamente como se indica.
* **Con gzip, guardar el archivo con el nombre indicado, sin añadir .gz** (`exact_file_name`): con compresión gzip, guarda el archivo con el nombre indicado.
