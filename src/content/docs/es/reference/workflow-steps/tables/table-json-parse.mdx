## Descripción

Lee una columna que contiene texto JSON y la expande en filas de salida: una por cada valor que se encuentra en el documento. Es la contraparte del paso [Análisis de XML](/es/reference/workflow-steps/tables/table-xml-parse/) y el equivalente en PlaidCloud de la herramienta *JSON Parse* de Alteryx.

Úselo cuando un sistema anterior le entregue una carga JSON en una sola columna y necesite su contenido como filas y columnas normales.

## Elementos de configuración exclusivos

### Campo JSON

La columna que contiene el texto JSON que se analizará.

### Forma de la salida

- **Name and value only** (valor predeterminado): cada fila de salida incluye `JSON_Name` y `JSON_ValueString`. Es la opción más sencilla y basta cuando todo lo que sigue trata los valores como texto.
- **Typed values**: desactive la opción de campo único para añadir las columnas de valor específicas de cada tipo, de modo que los números y los booleanos lleguen como números y booleanos en lugar de cadenas.

### Incluir las columnas de entrada

Desactivado de forma predeterminada. Actívelo para repetir las demás columnas del registro de entrada en cada fila de valor, de modo que los valores analizados sigan unidos al registro del que proceden sin necesidad de un paso de combinación aparte.

### Otros diseños

**Salida** (`json_layout`) elige una forma de salida distinta. Cada una conserva una fila por cada fila de entrada:

- **Ancho: una columna por ruta de clave** (`wide`): las columnas de entrada, menos el campo JSON salvo que se incluya, más una columna de texto por cada ruta de clave con puntos, con NULL donde un documento no la tiene.
- **Una columna por consulta JSONPath** (`paths`): las columnas de entrada más una columna por cada consulta JSONPath. Enumere las consultas en **Consultas JSONPath** (`json_paths`), cada una con una configuración de **Columna**, **JSONPath**, **Tipo** y **Varias coincidencias** (`target`, `path`, `dtype`, `multi`): `path` es un JSONPath (nombres, índices, comodines, búsqueda profunda, segmentos, uniones y filtros), `dtype` es `text`, `integer`, `bigint`, `double`, `boolean` o `json`, y `multi` queda vacío para la primera coincidencia (NULL cuando no hay ninguna), `list` para todas las coincidencias como un valor de lista, o `paths` para las rutas que coinciden. En lugar de la lista, **Consultas desde una tabla** (`json_dictionary`) lee las consultas de las filas de una tabla: `{source, path, type, output}` indican la tabla y sus columnas que contienen cada ruta, tipo y nombre de columna de salida.
- **Columnas como las crea KNIME JSON to Table** (`table`): las columnas de entrada más las columnas que el nodo JSON to Table de KNIME genera a partir de los documentos. Las opciones de **JSON a tabla** (`json_table`) lo configuran, empezando por **Nombrar las columnas según su ruta JSON** (`paths`), **Separador de ruta** (`separator`, valor predeterminado `.`) para unir los segmentos de la ruta, **Matrices** (`arrays`) como `GenerateCollectionCells`, `GenerateColumns` o `KeepAllArrayAsJsonArray`, **Niveles que expandir** (`levels`, 0 para todos) y **Omitir los objetos que se expandieron** (`omit_objects`, valor predeterminado true) para dejar fuera los valores de objeto.

Con el diseño JSONPath o JSON a tabla, active **Omitir el campo JSON de la salida** (`json_remove_source`) para quitar el campo JSON del resultado.
