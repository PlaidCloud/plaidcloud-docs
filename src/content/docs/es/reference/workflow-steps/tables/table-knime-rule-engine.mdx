## Descripción

El paso **Tabla: Motor de reglas de KNIME** aplica una lista de reglas del Rule Engine de KNIME que se guardan en una tabla y se leen cuando se ejecuta el paso. La primera regla que coincide con una fila decide su resultado. Los [flujos de trabajo de KNIME migrados](/es/guides/workflows/migrate-knime-workflows/) usan este paso para los nodos Rule Engine (Dictionary), Rule Engine Variable (Dictionary), Rule-based Row Filter (Dictionary) y Rule-based Row Splitter (Dictionary), incluidos los conjuntos de reglas PMML, cuando las reglas proceden de una tabla que solo se conoce cuando se ejecuta el flujo de trabajo.

El paso convierte las reglas que lee del mismo modo que lo hace el conversor. Una regla que no puede admitir, como una que usa sintaxis exclusiva de Java o una variable de flujo, hace que el paso falle en lugar de escribir una columna incorrecta.

El formulario del paso tiene una sección **Tablas** donde **Usar las reglas para** elige el tipo de regla y usted selecciona las tablas de origen, de salida y de reglas, una sección **Salida**, una sección **Puntuación con conjunto de reglas** para los conjuntos de reglas PMML y una sección **Columnas**.

## Configuración

- `source` y `target_frame`: la tabla que se lee y la tabla en la que se escribe. `source_columns` y `target_columns` son las columnas que se leen y se escriben; la columna de destino indicada por `output_column` recibe el resultado de las reglas.
- `rules_source`: la tabla cuyas filas son las reglas. `rules_column` contiene cada regla, `outcome_column` su resultado y `rules_order_column`, cuando se establece, ordena las reglas.
- `rule_kind`: `engine` (valor predeterminado) escribe el resultado de las reglas en `output_column`, con el tipo que indica `output_dtype`. `filter` y `splitter` escriben las filas que las reglas conservan: `include` (valor predeterminado true) decide si un resultado TRUE de una regla conserva o descarta la fila, y `port` es `1` para las filas conservadas o `2` para el resto. `variable` escribe la tabla de una fila con el valor que calculan las reglas, sin tabla de origen.
- `outcome_cell`: el tipo de celda de KNIME de la columna de resultado, que decide cómo se escribe un resultado en una regla. `knime_types` indica el tipo de celda de KNIME de las columnas de entrada de fecha y hora con zona, duración y período.
- `dollar_references`: los resultados con la forma `$column$` indican columnas en lugar de texto. `disallow_long` (valor predeterminado true) coincide con la configuración del mismo nombre de KNIME.
- Conjuntos de reglas PMML: `default_rule` es una regla que siempre se activa y se agrega al final. `weight_column` y `default_weight` (valor predeterminado 1.0) establecen el peso de cada regla para la selección ponderada, en la que se prueba primero la regla de mayor peso. `confidence_column`, `confidence_cell`, `confidence_output` y `default_confidence_rule` escriben la confianza del resultado de cada regla.
