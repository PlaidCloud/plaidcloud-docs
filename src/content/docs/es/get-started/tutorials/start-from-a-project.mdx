*~15 minutos · copie o importe un proyecto y luego hágalo suyo*

El triunfo más rápido del primer día en PlaidCloud no es construir desde cero, sino partir de algo que ya funciona. Elija un proyecto que ya importe datos, los transforme y produzca un resultado, obtenga su propia copia y cambie las partes que son suyas.

No hay una galería de plantillas que explorar. En cambio, tiene dos maneras fundamentadas de empezar desde un proyecto que funciona:

- **Copiar un proyecto** que ya existe en su espacio de trabajo en un proyecto nuevo y propio: [Copiar un proyecto](/es/guides/projects/managing-projects/#copia-de-un-proyecto).
- **Ejecutar un paquete portátil**: un proyecto que alguien exportó como un paquete autocontenido en [formato portátil](/es/guides/projects/export-to-portable-format/), que se ejecuta por sí solo fuera de PlaidCloud.

Cuál elija depende de adónde se dirija.

| Usted quiere… | Use | Resultado |
|---|---|---|
| Construir sobre un proyecto dentro de PlaidCloud y seguir iterando | **Copiar proyecto** | Un proyecto nuevo suyo, listo para editar y ejecutar |
| Ejecutar la lógica de un proyecto sin conexión, o entregarla a alguien sin inicio de sesión en PlaidCloud | **Exportar a formato portátil** | Un paquete independiente de Python + DuckDB |

## Requisitos previos

- Un espacio de trabajo de PlaidCloud ([inicie una prueba gratuita](https://app.plaidcloud.com) si no tiene uno).
- Para la **Ruta A**: un proyecto existente que pueda ver en la pestaña **Proyectos**: uno propio, un ejemplo compartido o cualquiera al que un colega le haya dado acceso.
- Para la **Ruta B**: un `.zip` en formato portátil que alguien haya exportado, o un proyecto propio para exportar.

> **¿No está seguro de qué es un proyecto?** Un proyecto es la unidad de trabajo en PlaidCloud: posee sus propios datos, flujos de trabajo, dimensiones e historial, y no comparte estado con ningún otro proyecto. Lea primero [Proyectos](/es/guides/projects/) si esto es nuevo para usted.

## Ruta A: Copie un proyecto existente

Copiar crea un duplicado completo y editable (todo, o solo las partes que elija) en un proyecto nuevo que es totalmente suyo.

1. Abra **Analizar** y seleccione la pestaña **Proyectos**.
2. Seleccione el proyecto desde el que desea empezar.
3. Haga clic en el botón **Acciones** y elija **Copiar proyecto**.
4. Elija **a new project** como destino. Asígnele un nombre y un **ID**.
5. Deje el árbol de selección completamente marcado para llevar todo el proyecto y luego haga clic en **Copiar proyecto**.

> **El ID es permanente.** El ID que asigna al proyecto nuevo se convierte en el nombre de su esquema y no se puede cambiar después. Elija algo con lo que esté conforme: el nombre se puede cambiar en cualquier momento, el ID no.

La copia se ejecuta en segundo plano; se le notifica cuando termina. Consulte [Copiar un proyecto](/es/guides/projects/managing-projects/#copia-de-un-proyecto) para ver el cuadro de diálogo completo.

### Traiga solo las partes que quiere

No tiene que copiarlo todo. El árbol de selección enumera lo que contiene el proyecto por tipo (flujos de trabajo, pasos, tablas, dimensiones, editores de datos, funciones definidas por el usuario) y puede marcar solo las partes que desea. Todo lo que marque trae consigo sus dependencias automáticamente: las tablas que lee y escribe un paso, las dimensiones con las que carga, las funciones que invoca y cualquier subflujo de trabajo al que llame. Nunca tiene que averiguar esas dependencias usted mismo.

> **Mantenga las referencias apuntando a su copia.** Deje activada la opción **Actualizar referencias** (su valor predeterminado). Reescribe los pasos copiados para que apunten a las tablas y objetos de su proyecto nuevo en lugar de volver al original, que es casi siempre lo que quiere. Desactívela solo si desea deliberadamente que la copia siga leyendo los objetos del proyecto de origen.

## Ruta B: Comience desde un paquete portátil

Un paquete portátil es un proyecto empaquetado como un programa de Python autocontenido que se ejecuta en [DuckDB](https://duckdb.org) sin conexión con PlaidCloud. Es la forma de empezar desde un proyecto que funciona cuando quiere que se ejecute *fuera de la plataforma*: en su portátil, en un trabajo de CI o en manos de alguien que no tiene inicio de sesión en PlaidCloud.

Si un colega ya le ha dado un paquete, vaya a [Ejecútelo](#ejecútelo). Para crear uno usted mismo:

1. Abra **Analizar** y seleccione la pestaña **Proyectos**.
2. Seleccione un solo proyecto.
3. Abra el menú **Acciones** y elija **Exportar a formato portátil**.
4. Defina la **Cuenta de documentos** y la **Ruta de la carpeta** donde se escribe el paquete, deje marcada la opción **Include data** para que se ejecute sin ningún origen externo y haga clic en **Exportar**.

El resultado es un `.zip` que contiene un script de Python por flujo de trabajo, las instantáneas de datos en Parquet, un `requirements.txt` con los paquetes de Python que necesitan los scripts, y un `README.md`, un `COVERAGE.md` y un `RUN_ORDER.md`. Consulte [Exportar a formato portátil](/es/guides/projects/export-to-portable-format/) para saber qué es cada archivo.

> **Un paquete portátil es una instantánea unidireccional, no una reimportación.** Se ejecuta *fuera* de PlaidCloud y no se sincroniza de vuelta: los cambios que haga en el paquete no regresan al proyecto, y volver a exportar después de editar produce un paquete nuevo. Para seguir trabajando dentro de PlaidCloud, use en su lugar la **Ruta A**. Para seguir iterando en PlaidCloud *y* entregar una copia ejecutable, haga ambas.

> **La fidelidad es de mejor esfuerzo.** Los pasos de transformación SQL se reproducen exactamente. Los pasos propietarios y con efectos secundarios (asignaciones, cargas de dimensiones, notificaciones, pasos de documentos e informes, scripts) se exportan como marcadores que no se vuelven a ejecutar; en su lugar, su última salida materializada se incluye como instantánea. La fidelidad de cada paso se registra en `COVERAGE.md`. Para obtener resultados totalmente recalculados, ejecute el proyecto en PlaidCloud.

### Ejecútelo

Descomprima el paquete, cree un entorno de Python y ejecute cada script de flujo de trabajo en el orden que indica `RUN_ORDER.md`:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python pipeline_<workflow>.py
```

Cada script crea sus tablas en una base de datos local de DuckDB. Los pasos SQL se recalculan en vivo; los pasos sustituidos dejan en su lugar su salida de la instantánea.

## Hágalo suyo

Sea cual sea la forma en que empezó, la copia ya es suya para cambiarla: aquí es donde el triunfo del primer día da fruto. Algunos primeros movimientos:

| Haga esto | Dónde |
|---|---|
| Apunte las importaciones a *sus* datos en lugar de los del ejemplo | Los pasos de importación de cada flujo de trabajo; consulte [Cargar, transformar y publicar datos](/es/get-started/tutorials/load-and-transform-data/) |
| Cambie el nombre del proyecto o ajuste quién puede abrirlo | [Administrar proyectos](/es/guides/projects/managing-projects/) → Control de acceso |
| Defina variables de proyecto para los valores que se repiten en varios flujos de trabajo | [Administrar variables de proyecto](/es/guides/projects/managing-projects/#administración-de-las-variables-del-proyecto) |
| Confirme que todo sigue ejecutándose de principio a fin | Haga clic en **Ejecutar** en cada flujo de trabajo y observe el registro |

Como cada cambio se registra, puede experimentar libremente: el [seguimiento automático de cambios](/es/guides/projects/managing-projects/#historial-de-versiones) le permite recuperar cualquier estado anterior a un momento dado si una edición sale mal.
