**Exportar a formato portátil** empaqueta los flujos de trabajo de un proyecto como un programa de Python autónomo que se ejecuta sobre [DuckDB](https://duckdb.org) sin conexión alguna con PlaidCloud. Genera una copia portátil de la lógica y los datos del proyecto que se ejecuta por sí sola, sin conexión.

Es una exportación unidireccional. El paquete generado es una instantánea de un momento dado; no se sincroniza de vuelta, y volver a exportar después de hacer cambios produce un paquete nuevo.

<Aside type="caution" title="Fidelidad según el mejor esfuerzo">
La exportación reproduce exactamente los pasos de transformación basados en SQL. Las operaciones propietarias y con efectos secundarios (asignaciones, cargas de dimensiones, notificaciones, pasos de documentos e informes, scripts) se exportan como **stubs**: se conserva su configuración original y, cuando la tabla de salida se materializó, sus datos se incluyen como una instantánea, pero el paso en sí no se vuelve a ejecutar. La fidelidad de cada paso se registra en `COVERAGE.md` dentro del paquete. Para obtener resultados garantizados y recalculados por completo, ejecute el proyecto en PlaidCloud.
</Aside>

## Exportación de un proyecto

1. Abra **Analyze** y seleccione la pestaña **Proyectos**.
2. Seleccione un único proyecto.
3. Abra el menú **Acciones** (o haga clic con el botón derecho en el proyecto) y elija **Exportar a formato portátil**; está junto a **Export Project**.
4. En el cuadro de diálogo:
   - **Cuenta de documentos**: la cuenta de documentos en la que se escribe el paquete.
   - **Ruta de la carpeta**: la carpeta dentro de esa cuenta, por ejemplo `/exports`.
   - **Include data**: cuando está marcada (el valor predeterminado), las tablas de origen y de instantánea se incluyen como Parquet para que el paquete se ejecute sin datos externos. Desmárquela para enviar solo el código y los contratos de esquema, que luego usted rellena por su cuenta.
5. Haga clic en **Exportar**. Cuando termina, un mensaje confirma dónde se escribió el paquete y de cuántas tablas se tomó una instantánea.

La acción requiere acceso al proyecto y a la lectura de sus tablas, el mismo nivel de acceso que se necesita actualmente para exportar datos de tablas.

## Contenido del paquete

La exportación es un `.zip` que contiene:

- `pipeline_<workflow>.py`: un script por flujo de trabajo, con los pasos en orden de ejecución.
- `config.py`: la selección del motor (DuckDB de forma predeterminada) y el nombre del esquema del proyecto.
- `_runtime.py`: una pequeña capa de compatibilidad del motor; la única dependencia además de DuckDB.
- `stubs.py`: funciones sin efecto para las operaciones no portátiles, cada una con la configuración original del paso.
- `data/`: instantáneas en Parquet de las tablas de origen y congeladas (cuando se marcó **Include data**).
- `requirements.txt`: las dependencias de Python (solo `duckdb`).
- `README.md`, `COVERAGE.md`, `RUN_ORDER.md`: cómo ejecutarlo, la fidelidad por paso y el orden en que se deben ejecutar los scripts de los flujos de trabajo.

## Ejecución del paquete

1. Descomprima el paquete y cree un entorno de Python:

   ```bash
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. Ejecute cada script de flujo de trabajo, en el orden indicado en `RUN_ORDER.md`:

   ```bash
   python pipeline_<workflow>.py
   ```

Cada script crea sus tablas en una base de datos DuckDB local (`export.duckdb` de forma predeterminada). Los pasos de transformación SQL se recalculan en vivo; los pasos con stubs muestran un aviso y dejan en su lugar su salida de la instantánea. Para apuntar el paquete a su propio almacén en lugar de DuckDB, defina `ENGINE` en `config.py`.
