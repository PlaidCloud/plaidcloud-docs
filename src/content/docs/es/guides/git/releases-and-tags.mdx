Una etiqueta (tag) marca un commit como significativo, normalmente una versión como `v1.2.0`. Una versión (release) se apoya en una etiqueta y agrega notas legibles y archivos adjuntos opcionales para que los usuarios puedan explorar y descargar versiones específicas desde la interfaz web.

## Crear una etiqueta

Puede crear una etiqueta desde la interfaz o desde su clon local.

**Desde la interfaz:**

1. Abra su repositorio y seleccione **Releases** y luego **Tags**.
2. Seleccione **Create Tag**.
3. Escriba un nombre de etiqueta (por ejemplo, `v1.2.0`), elija la rama o el commit de destino y seleccione **Create Tag**.

**Desde la línea de comandos:**

```bash
git tag v1.2.0
git push origin v1.2.0
```

Para etiquetar un commit anterior específico, indique su ID de commit en lugar de depender de `HEAD`:

```bash
git tag v1.2.0 abc1234
git push origin v1.2.0
```

## Publicar una versión

1. Abra su repositorio y seleccione **Releases**.
2. Seleccione **New Release**.
3. En el campo **Tag Name**, elija una etiqueta existente o escriba un nombre nuevo para crear una en la punta actual de la rama predeterminada.
4. Escriba un **Release Title** y redacte las notas de la versión en el cuerpo en Markdown: aquí corresponden los registros de cambios, las instrucciones de actualización y los problemas conocidos.
5. Seleccione **This is a pre-release** si la versión no está lista para uso general, o **Guardar borrador** para terminarla más tarde sin publicarla.
6. Seleccione **Publish Release** cuando esté lista.

<Aside>Las versiones en borrador solo las ven los miembros del repositorio con acceso de escritura. Una versión preliminar la ve todo el que tenga acceso, pero se excluye de la designación “Latest” en la descripción general del repositorio.</Aside>

## Adjuntar archivos

Los archivos cargados aparecen en la página de la versión como vínculos de descarga con nombre, junto al archivo de código fuente generado automáticamente.

1. En el formulario de versión nueva o de edición, vaya a la sección **Attach Files**.
2. Arrastre archivos al área de carga, o selecciónela para examinar: los binarios compilados, los archivos comprimidos, las sumas de comprobación y las firmas son opciones habituales.
3. Repita para cada archivo y luego publique o actualice la versión.

Mantenga un tamaño razonable en cada archivo para que las descargas sean rápidas para su equipo.

<Aside type="tip">Para paquetes instalables, como módulos de npm, imágenes de contenedor, wheels de PyPI y similares, el [registro de paquetes](/es/guides/git/packages/) es más adecuado que los archivos adjuntos de una versión. Entiende la resolución de versiones, los metadatos de dependencias y las herramientas cliente (`npm`, `pip`, `docker pull`) de una manera que una descarga de archivo simple no puede.</Aside>

## Ver y descargar versiones

1. Seleccione **Releases** para ver la lista completa, de la más reciente a la más antigua.
2. La última versión que no es preliminar se destaca con una insignia **Latest**.
3. Cada entrada muestra el nombre de la etiqueta, el título de la versión, las notas y vínculos a:
   - **Source code** — archivos `zip` y `tar.gz` generados automáticamente del commit etiquetado.
   - **Assets** — cualquier archivo que haya adjuntado al publicar la versión.
4. Seleccione el vínculo de un archivo para descargarlo directamente, o copie la URL para compartirla.

Para comparar dos versiones, abra los nombres de sus etiquetas como una URL de comparación:

```bash
https://git.example.plaidcloud.com/you/my-repo/compare/v1.1.0...v1.2.0
```
