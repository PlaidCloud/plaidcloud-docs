Las incidencias ofrecen a su equipo un lugar compartido para dar seguimiento a errores, planificar funciones y registrar cualquier cosa que requiera atención, todo vinculado directamente al código de su repositorio.

## Crear una incidencia

1. Abra su repositorio y seleccione la pestaña **Issues**.
2. Seleccione **New Issue**.
3. Escriba un **Título** conciso que describa el problema o la tarea.
4. Redacte una **Descripción** con Markdown; incluya pasos para reproducirlo, criterios de aceptación, capturas de pantalla o bloques de código según sea necesario.
5. Seleccione **Submit New Issue** para publicarla.

<Aside>Un repositorio puede definir plantillas de incidencias reutilizables en **Configuración → Issue Templates**. Cuando hay plantillas configuradas, al abrir una nueva incidencia se muestra un selector para que los colaboradores partan de un formulario uniforme en lugar de una página en blanco.</Aside>

## Organizar con etiquetas e hitos

Las **Etiquetas** categorizan y priorizan las incidencias. Aplique una o más etiquetas desde la barra lateral derecha al ver una incidencia, o directamente desde la lista de incidencias con el filtro **Etiqueta**. Las convenciones habituales son etiquetas de tipo (`bug`, `enhancement`) junto con etiquetas de prioridad (`high`, `low`), pero puede crear las etiquetas que se ajusten a su flujo de trabajo en **Issues → Labels**.

Los **hitos** agrupan incidencias en torno a un objetivo compartido: una fecha de lanzamiento, un sprint o una meta de función. Cree hitos en **Issues → Milestones** y luego asigne una incidencia a un hito desde su barra lateral. La vista del hito muestra el progreso a medida que se cierran las incidencias.

## Asignar y comentar

- **Responsables** — use el campo **Assignees** de la barra lateral para indicar quién es responsable. Se puede asignar a cualquier miembro del espacio de trabajo con acceso al repositorio.
- **Comentarios** — agregue contexto, decisiones o actualizaciones de estado en el hilo de comentarios debajo de la descripción de la incidencia.
- **@menciones** — escriba `@username` en cualquier parte de un comentario o descripción para notificar directamente a esa persona.
- **Reacciones** — use reacciones con emoji en los comentarios para reconocer un punto sin agregar una respuesta.

## Vincular incidencias con el código

Hacer referencia a las incidencias desde los commits y las solicitudes de incorporación de cambios mantiene su historial trazable.

- **Referencia por número** — escriba `#12` en un mensaje de commit, en la descripción de una solicitud de incorporación de cambios o en un comentario para crear un vínculo en el que se puede hacer clic a la incidencia 12 del mismo repositorio.
- **Cierre automático al fusionar** — incluya una palabra clave de cierre en la descripción de una solicitud de incorporación de cambios (por ejemplo, `Closes #12`, `Fixes #34` o `Resolves #56`). Cuando la solicitud se fusiona en la rama predeterminada, las incidencias a las que hace referencia se cierran automáticamente.
- **Referencias cruzadas a otras incidencias** — use `#number` libremente en cualquier comentario de una incidencia para vincular incidencias relacionadas; cada incidencia referenciada muestra un vínculo de retorno para que la conexión sea visible desde ambos lados.

## Buscar incidencias

La lista de incidencias admite varios filtros que se pueden combinar:

| Filtro | Qué hace |
|---|---|
| **Estado** | Muestra las incidencias abiertas o cerradas |
| **Etiqueta** | Acota a una o más etiquetas |
| **Hito** | Muestra las incidencias asignadas a un hito |
| **Responsable** | Muestra las incidencias asignadas a una persona específica |
| **Autor** | Muestra las incidencias abiertas por una persona específica |

Seleccione la columna correspondiente en la barra de filtros situada sobre la lista de incidencias para aplicar cada filtro. Para buscar con palabras clave en los títulos y cuerpos de las incidencias, consulte [Búsqueda de código](/es/guides/git/searching-code/).
