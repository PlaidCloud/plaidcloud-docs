PlaidCloud Git incluye un registro de paquetes integrado para artefactos distribuibles y Git Large File Storage (LFS) para archivos binarios grandes dentro de sus repositorios.

## Acerca del registro de paquetes

El registro de paquetes es por propietario y admite una amplia variedad de formatos de ecosistemas: npm, PyPI, Maven, NuGet, RubyGems, imágenes de contenedor y más. Los paquetes son privados para su espacio de trabajo y solo pueden acceder a ellos los miembros autenticados.

Cada tipo de paquete tiene su propio punto de conexión en:

```
https://git.example.plaidcloud.com/api/packages/you/<type>
```

donde `<type>` es el identificador del ecosistema (por ejemplo, `npm`, `pypi` o `maven`).

## Autenticarse en el registro

Las operaciones del administrador de paquetes usan su nombre de usuario de PlaidCloud Git y un token de acceso personal como contraseña. Consulte [Repositorios](/es/guides/git/repositories/) para saber cómo crear un token.

## Publicar un paquete

Los pasos varían según el ecosistema, pero el patrón es el mismo: apunte su administrador de paquetes a la URL del registro y ejecute su comando de publicación estándar.

Para npm, agregue un archivo `.npmrc` a su proyecto para limitar el ámbito de los paquetes al registro:

```ini
@you:registry=https://git.example.plaidcloud.com/api/packages/you/npm/
//git.example.plaidcloud.com/api/packages/you/npm/:_authToken=YOUR_TOKEN
```

Luego publique como de costumbre:

```bash
npm publish
```

Para PyPI, Maven, NuGet y otros ecosistemas, configure el repositorio o el origen de la herramienta con la URL del registro correspondiente y use el comando de publicación estándar de esa herramienta (por ejemplo, `twine upload`, `mvn deploy` o `dotnet nuget push`).

## Instalar un paquete

Apunte su administrador de paquetes a la misma URL del registro e instale como de costumbre. Con el `.npmrc` anterior en su lugar:

```bash
npm install @you/my-package
```

Para otros ecosistemas, agregue el registro como un origen adicional en la configuración de su herramienta y use su comando de instalación estándar.

## Archivos grandes con Git LFS

Git LFS mantiene su repositorio ágil al reemplazar en el historial los archivos grandes o binarios por punteros ligeros y almacenar los datos del archivo por separado. LFS está habilitado en todos los repositorios de PlaidCloud Git.

1. Instale el cliente de LFS una sola vez en su equipo:

   ```bash
   git lfs install
   ```

2. Indique a LFS qué patrones de archivo debe rastrear, desde dentro de su repositorio:

   ```bash
   git lfs track "*.parquet"
   ```

   Esto crea o actualiza `.gitattributes`. Confirme ese archivo:

   ```bash
   git add .gitattributes
   git commit -m "Track Parquet files with LFS"
   ```

3. Agregue y envíe como de costumbre: los archivos coincidentes se cargan a LFS automáticamente:

   ```bash
   git add data/large-dataset.parquet
   git commit -m "Add dataset"
   git push origin main
   ```

<Aside type="tip">Git LFS es para archivos grandes que viven dentro del historial de un repositorio y se obtienen con `git clone` o `git pull`. El registro de paquetes es para artefactos versionados y distribuibles que los consumidores instalan con un administrador de paquetes. Si sus compañeros van a hacer `npm install` o `pip install` con él, use el registro; si lo necesitan como parte de una copia de trabajo, use LFS.</Aside>
