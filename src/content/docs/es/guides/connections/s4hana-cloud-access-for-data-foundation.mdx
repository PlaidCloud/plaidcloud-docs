[Data Foundation](/es/guides/projects/data-foundation/) reúne los datos de cada sistema ERP e instancia que usted conecta en un único Common Finance Model, y SAP S/4HANA Cloud es uno de los ERP que lee directamente. La conexión lee los servicios OData liberados del inquilino con credenciales de cliente de OAuth 2.0; no interviene ningún agente. Esta página está dirigida al administrador de S/4HANA Cloud que lo configura y al usuario de PlaidCloud que se lo solicita.

PlaidCloud solo lee datos. Nadie envía por correo electrónico una contraseña ni un secreto de cliente.

## Enviar la solicitud de acceso

En la página **Sistemas** del proyecto, en **Data Foundation** dentro de **Inicio**, elija su sistema en **Sistema**, en **Agregar un sistema**, y haga clic en **¿Aún no tiene acceso?**. El sistema queda a la espera de acceso y se muestra una única solicitud que abarca los sistemas del proyecto. Haga clic en **Copiar solicitud** para pegarla en su propio mensaje, o en **Enviar solicitud por correo** para abrirla en su programa de correo con el asunto “Acceso para PlaidCloud”.

## Qué configura el administrador de S/4HANA Cloud

<Steps>

1. **Cree un usuario de comunicación** para PlaidCloud, en la aplicación **Maintain Communication Users**. Su método de autenticación es OAuth 2.0 o nombre de usuario y contraseña, según requiera su entorno.

2. **Cree un sistema de comunicación** para PlaidCloud, en la aplicación **Communication Systems**, con ese usuario para la comunicación entrante y credenciales de cliente de OAuth 2.0.

3. **Cree un acuerdo de comunicación** para cada escenario siguiente, en la aplicación **Communication Arrangements**, todos para el sistema del paso 2. En conjunto exponen los servicios OData que lee PlaidCloud:

   | Escenario | Servicio |
   |---|---|
   | Company Code | `API_COMPANYCODE_SRV` |
   | G/L Account in Chart of Accounts | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
   | Cost Center | `API_COSTCENTER_SRV` |
   | Business Partner and Customer | `API_BUSINESS_PARTNER` |
   | Product | `API_PRODUCT_SRV` |
   | Fiscal Year Variant Periods | `API_FISCALYEARPERIODFORVARIANT_SRV` |
   | Exchange Rates | `API_EXCHANGERATE_SRV` |
   | Journal Entry Item | `API_JOURNALENTRYITEMBASIC_SRV` (el diario y el saldo arrastrado) |
   | Billing Document | `API_BILLING_DOCUMENT_SRV` (opcional: agrega ventas facturadas, documentos y partidas) |

   Para los conjuntos de datos opcionales, configure también los escenarios que exponen estos servicios:

   | Servicio | Agrega |
   |---|---|
   | `API_JOURNALENTRY_SRV` | Quién introdujo cada asiento, cuándo, y el asiento que revierte |
   | `API_BUSINESS_PARTNER` (`A_Supplier`) | Proveedores |
   | `API_PLANT_SRV` | Plantas, que se leen como sitios, y las plantas de los saldos de inventario |
   | `API_PROFITCENTER_SRV` | Centros de beneficio |
   | `API_SUPPLIERINVOICE_PROCESS_SRV` | Líneas de facturas de proveedores |
   | `API_OPLACCTGDOCITEMCUBE_SRV` | Partidas abiertas y pagos, y las fechas de vencimiento de las facturas de proveedores |
   | `API_FINPLANNINGDATA_SRV` | Presupuestos |
   | `API_MATERIAL_STOCK_SRV` | Saldos de inventario |

   Dé al usuario de comunicación acceso a cada código de empresa sobre el que informe.

</Steps>

## Qué debe enviar de vuelta

| El administrador envía | Se introduce en PlaidCloud como |
|---|---|
| El host de la API del inquilino, por ejemplo `https://my300000-api.s4hana.cloud.sap` | **URL del host de la API** |
| La URL del token: la propia del inquilino (`/sap/bc/sec/oauth2/token`), o la de su servidor de autorización XSUAA si su entorno usa uno | **URL del token OAuth2** |
| El ID de cliente | **ID de cliente** |
| El secreto de cliente, mediante el formulario de conexión seguro | **Secreto de cliente**, que su equipo introduce por sí mismo |
| Si se ha ejecutado **Carry Forward Balances** para cada ejercicio fiscal que carga | No hay nada que introducir. Los saldos iniciales se leen de ahí. |

<Aside type="caution">
No envíe nunca el secreto de cliente por correo electrónico. **Secreto de cliente** es un secreto: se almacena en la conexión y no se vuelve a mostrar.
</Aside>

## Comprobar el acceso

De vuelta en PlaidCloud, una vez agregado el sistema, haga clic en **Probar conexión** en su fila de la página **Sistemas**. Lee los conjuntos de datos obligatorios y muestra cada uno como **Legible**, **Falta un permiso** o **Error**. Los opcionales no forman parte de la prueba: si S/4HANA Cloud rechaza alguno, después de la siguiente carga las comprobaciones de preparación del panel de control **CFM-Accounting - Close and assurance** indican el servicio que debe agregarse al acuerdo de comunicación.

| Conjunto de datos | Servicio que necesita |
|---|---|
| Entidades | `API_COMPANYCODE_SRV` |
| Plan de cuentas | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
| Departamentos | `API_COSTCENTER_SRV` |
| Clientes | `API_BUSINESS_PARTNER` |
| Productos | `API_PRODUCT_SRV` |
| Tipos de cambio | `API_EXCHANGERATE_SRV` |
| Calendario fiscal | `API_FISCALYEARPERIODFORVARIANT_SRV` |
| Libro mayor | `API_JOURNALENTRYITEMBASIC_SRV` |
| Balance de comprobación | `API_JOURNALENTRYITEMBASIC_SRV` |
| Líneas de ventas | `API_BILLING_DOCUMENT_SRV` (opcional) |

Cuando un conjunto de datos muestra **Falta un permiso**, pida al administrador que agregue el acuerdo de comunicación de su servicio y vuelva a probar. Las líneas de ventas, el presupuesto, los saldos de inventario, los proveedores, los sitios, los centros de beneficio, las líneas de facturas de proveedores, las partidas abiertas y los pagos son opcionales: un inquilino que no contiene alguno de ellos carga igualmente todo lo demás. Las partidas abiertas o los pagos de un mes que no se pueden leer, y las líneas de facturas de proveedores de un mes cuya lectura falla, conservan las filas que ya tenían y se vuelven a leer en la siguiente carga.

Los servicios no informan de ningún estado de período ni de ningún saldo de cierre de mes propio, de modo que todos los períodos están abiertos y el libro mayor se compara con su propio balance de comprobación.
