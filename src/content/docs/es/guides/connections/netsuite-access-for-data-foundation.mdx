[Data Foundation](/es/guides/projects/data-foundation/) reúne los datos de cada sistema e instancia de ERP que usted conecta en un único Common Finance Model, y NetSuite es uno de los ERP que lee directamente. La conexión de NetSuite usa acceso de máquina a máquina con OAuth 2.0: un rol de solo lectura, un registro de integración que usa la concesión de credenciales de cliente y un certificado. Esta página está dirigida al administrador de NetSuite que lo configura y al usuario de PlaidCloud que se lo solicita.

PlaidCloud solo lee datos. Nadie envía por correo electrónico una contraseña, un secreto de token ni una clave privada.

## Antes de empezar: cree el certificado

El equipo del usuario de PlaidCloud crea un par de claves RSA y conserva la clave privada. A NetSuite solo se envía el certificado público. Por ejemplo, con OpenSSL:

```bash
openssl req -new -x509 -newkey rsa:3072 -nodes -days 730 \
    -keyout plaidcloud_netsuite.pem \
    -out plaidcloud_netsuite_public.pem \
    -subj "/CN=PlaidCloud"
```

Adjunte `plaidcloud_netsuite_public.pem` a la solicitud que envíe al administrador. Conserve `plaidcloud_netsuite.pem` para el campo **Certificado privado de NetSuite** de PlaidCloud.

## Enviar la solicitud de acceso

En la página **Sistemas** del proyecto, en **Data Foundation** dentro de **Inicio**, elija su sistema en **Sistema**, en **Agregar un sistema**, y haga clic en **¿Aún no tiene acceso?**. El sistema queda a la espera de acceso y se muestra una única solicitud que abarca los sistemas del proyecto. Haga clic en **Copiar solicitud** para pegarla en su propio mensaje, o en **Enviar solicitud por correo** para abrirla en su programa de correo con el asunto “Acceso para PlaidCloud”. Adjunte el certificado público.

## Lo que configura el administrador de NetSuite

<Steps>

1. **Habilite las funciones.** En **Setup > Company > Enable Features > SuiteCloud**, habilite:

   - REST Web Services
   - OAuth 2.0
   - SuiteAnalytics Workbook (necesario para SuiteQL)

2. **Cree un rol de solo lectura**, por ejemplo “PlaidCloud Read Only”, con estos permisos:

   | Permiso | Nivel |
   |---|---|
   | Setup: REST Web Services | Full |
   | Setup: Log in using OAuth 2.0 Access Tokens | Full |
   | Transactions: Invoice, Cash Sale and Credit Memo | View |
   | Lists: Items and Locations | View |
   | Transactions: Budget | View |
   | Reports: General Ledger | View |
   | Setup: Accounting Periods | View |
   | Lists: Subsidiaries | View |
   | Lists: Accounts | View |
   | Lists: Departments | View |
   | Lists: Classes | View |
   | Lists: Locations | View |
   | Lists: Customers | View |
   | Lists: Currency | View |
   | Lists: Consolidated Exchange Rates | View |
   | Lists: Custom Record Entries, si usa segmentos personalizados | View |
   | Lists: Vendors, para los proveedores | View |
   | Lists: Employees, para los representantes de ventas | View |
   | Transactions: Bills, para las líneas de facturas de proveedores, las partidas abiertas y los pagos | View |
   | Transactions: Customer Payment y Pay Bills, para las partidas abiertas y los pagos | View |
   | Transactions: Find Transaction, para lo que liquidó cada pago | View |

   Los seis últimos son opcionales. Dé al rol acceso a todas las subsidiarias sobre las que informa PlaidCloud.

3. **Cree un registro de integración.** En **Setup > Integration > Manage Integrations > New**:

   - **Nombre:** PlaidCloud
   - **Autenticación:** marque únicamente **Client Credentials (Machine to Machine) Grant**; sin autenticación basada en tokens y sin concesión de código de autorización.
   - **Ámbitos:** REST Web Services y RESTlets.

   Guárdelo y copie el **ID de cliente**. NetSuite lo muestra una sola vez, en la página de confirmación.

4. **Asigne el certificado.** En **Setup > Integration > OAuth 2.0 Client Credentials (M2M) Setup > Create New**:

   - **Entidad:** el usuario con el que actúa PlaidCloud.
   - **Rol:** el rol del paso 2.
   - **Aplicación:** PlaidCloud, la integración del paso 3.
   - **Certificado:** el certificado público adjunto a la solicitud.

   Guárdelo y copie el **ID de certificado**.

</Steps>

## Qué enviar de vuelta

| El administrador envía | Se guarda en la conexión de NetSuite como |
|---|---|
| El **ID de cuenta**, de **Setup > Company > Company Information**, por ejemplo `1234567`, o `1234567_SB1` para un sandbox | **ID de cuenta de NetSuite** |
| El **ID de cliente** del paso 3 | **ID de cliente** |
| El **ID de certificado** del paso 4 | **ID de certificado** |
| Las subsidiarias que PlaidCloud puede leer | En **Opciones**, **Empresas**, al agregar el sistema: márquelas, o no marque ninguna para leer todas las subsidiarias activas que no sean de eliminación |

La clave privada que corresponde al certificado permanece en el equipo del usuario de PlaidCloud. Ese equipo la introduce por sí mismo en el campo **Certificado privado de NetSuite** de la conexión.

<Aside type="caution">
Escriba el ID de cuenta exactamente como lo muestra NetSuite, incluido el sufijo `_SB1` en un sandbox. PlaidCloud deduce de él la dirección de NetSuite.
</Aside>

## Comprobar el acceso

De vuelta en PlaidCloud, una vez agregado el sistema, haga clic en **Probar conexión** en su fila de la página **Sistemas**. Cada conjunto de datos aparece como **Legible**, **Falta un permiso** o **Error**:

| Conjunto de datos | Permiso que necesita |
|---|---|
| Líneas de ventas | Transactions: Invoice, Cash Sale and Credit Memo (View) |
| Saldos de inventario | Lists: Items and Locations (View) |
| Presupuestos | Transactions: Budget (View) |
| Cuentas estadísticas | Reports: General Ledger (View) |
| Períodos contables | Setup: Accounting Periods (View) |
| Subsidiarias | Lists: Subsidiaries (View) |
| Tipos de cambio | Lists: Consolidated Exchange Rates (View) |
| Clases | Lists: Classes (View) |
| Ubicaciones | Lists: Locations (View) |

Cuando falta un conjunto de datos, la prueba indica los permisos que deben agregarse. Pida al administrador que los agregue al rol y vuelva a probar. Los presupuestos son opcionales: una cuenta de NetSuite que no usa presupuestos sigue cargando todo lo demás. Los tipos de cambio, las clases y las ubicaciones tampoco impiden una carga: si NetSuite rechaza uno de ellos, no se carga nada de él, y las comprobaciones de preparación indican el permiso que debe agregarse. Sin tipos de cambio, proporcione los tipos en un archivo de **Tipos de cambio**.

La prueba no lee los proveedores, los representantes de ventas, las líneas de facturas de proveedores, los saldos bancarios, las partidas abiertas ni los pagos. Son opcionales: si NetSuite rechaza alguno, después de la siguiente carga las comprobaciones de preparación del panel de control **CFM-Accounting - Close and assurance** indican el permiso que debe agregarse, y el resto se carga. Las clases se cargan como centros de beneficio y las ubicaciones como sitios. Los presupuestos, las facturas de proveedores, los saldos bancarios, las partidas abiertas o los pagos de un mes que NetSuite rechaza conservan las filas que ya tenían y se vuelven a leer en la siguiente carga. NetSuite no tiene un saldo de cierre de mes propio que Data Foundation lea, por lo que su libro mayor se compara con su propio balance de comprobación.
