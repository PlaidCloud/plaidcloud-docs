Una **conexión** es una configuración guardada que permite a PlaidCloud acceder a un sistema externo: una base de datos, un lago de datos, un ERP, una API REST, un servicio en la nube o un proveedor de Git. Los pasos del flujo de trabajo hacen referencia a la conexión por su nombre, de modo que los detalles del punto de conexión y las credenciales están en un solo lugar y se reutilizan en todos los pasos y proyectos que los necesiten.

Las conexiones se administran desde **Tools > Connections**.

## Crear una conexión

1. Abra **Tools > Connections**
2. Haga clic en `New Connection` en la barra de herramientas y elija en el menú el sistema al que desea conectarse
3. Complete el formulario de conexión (las pestañas y los campos varían según el tipo; consulte [Formulario de conexión](#formulario-de-conexión) más abajo)
4. Haga clic en `Create` para guardar

La nueva conexión aparece en la lista, con usted como propietario.

<Aside type="note">La lista de tipos de conexión y los campos que necesita cada uno están catalogados en la [referencia de conectores](/es/reference/connectors/). Para un servicio sin un conector específico, use la [conexión REST genérica](/es/reference/connectors/rest/generic-rest/).</Aside>

## Formulario de conexión

La mayoría de las conexiones abren un formulario con varias pestañas. Las pestañas exactas dependen del tipo, pero lo habitual es ver:

- **Configuración de la conexión** (o **Detalles de la conexión** en REST): el `Name` de la conexión, un `Memo` opcional, el host, puerto y base de datos (o el host y el tipo de autenticación en REST), el interruptor `Usage` (`Active`) y el `Security Model`. En una conexión de base de datos, las credenciales están aquí, en un grupo **Credenciales de autenticación**; en una conexión REST tienen su propia pestaña **Autenticación**.
- **Configuración de SSL**: `Use SSL` más el modo SSL y los certificados opcionales de cliente y raíz para una conexión cifrada.
- **Configuración de SSH**: `Use SSH` más el host bastión, el puerto, el usuario y la clave para tunelizar la conexión a través de un host de salto SSH.

Las contraseñas, los tokens y otros campos de credenciales son de solo escritura: aparecen en blanco al volver a abrir una conexión guardada, y dejarlos en blanco al guardar conserva el secreto almacenado. Vuelva a escribir un valor solo cuando quiera cambiarlo. Esto incluye la clave de API, el secreto de cliente de OAuth y el token de actualización de OAuth de una conexión REST. Las credenciales de varias líneas (un certificado privado de NetSuite, un certificado y una clave privada de Anaplan, una clave de API de Postman, una URL de webhook entrante de Slack o Teams) son de solo escritura de la misma manera y se enmascaran mientras las escribe o pega. Un reemplazo formado solo por espacios se rechaza en lugar de guardarse sobre la credencial almacenada; vacíe el campo para conservar el valor guardado. La clave de cliente SSL y la clave privada SSH de una conexión SQL o Git también son de solo escritura, pero permanecen visibles mientras las escribe. Cualquier otro campo muestra su valor guardado real en todos los lugares donde se muestra la conexión, en el editor y a través de la API, incluidos los campos que por su nombre parecen sensibles (el indicador de solo lectura de una base de datos, un identificador de cuenta, un esquema, un nombre de host): solo una credencial real se enmascara u oculta.

A través de la API REST y MCP, un campo de credencial sigue la misma regla que el editor: envíe una cadena vacía y PlaidCloud conserva el valor almacenado; envíe `null` para borrarlo. Todos los campos que no son credenciales se siguen borrando cuando se envían en blanco.

Los campos obligatorios se validan al guardar; si falta alguno, el formulario cambia a la pestaña que contiene el primer campo no válido y lo señala.

## Modelo de seguridad

El `Security Model` de una conexión controla quién del espacio de trabajo puede usarla:

| Opción | Quién puede usar la conexión |
|---|---|
| Privado (solo propietarios) | Solo los propietarios. |
| Solo miembros específicos | Los propietarios más una lista explícita de miembros. |
| Solo grupos de seguridad específicos | Los propietarios más los miembros de los grupos de seguridad indicados. |
| Todos los miembros del espacio de trabajo | Todas las personas del espacio de trabajo. |

Cuando elija `Specific Members Only` o `Specific Security Groups Only`, conceda el acceso desde el menú `Actions` de la lista: `Members` para `Specific Members Only` o `Groups` para `Specific Security Groups Only`, más `Agents` y `Owners`, abren cada uno un selector de doble lista para agregar y quitar acceso. Solo un propietario de la conexión o un administrador del espacio de trabajo puede cambiar el acceso allí. Cualquier otra persona que pueda editar conexiones puede abrirlas para ver quién tiene acceso, sin cambiarlo. Un administrador del espacio de trabajo puede cambiar el acceso a una conexión de la que no es propietario, para transferirla cuando sus propietarios se hayan ido.

## Entornos

Una conexión puede tener una configuración distinta por **entorno** (por ejemplo, un host de desarrollo y un host de producción bajo un mismo nombre de conexión). El selector de entorno de la barra de herramientas elige la configuración de qué entorno está viendo y editando.

- `New Environment`: agrega un entorno de conexión
- `Edit Environment`: cambia el nombre del entorno seleccionado
- `Delete Environment`: elimina el entorno seleccionado

La columna `Available` de la lista indica si la conexión seleccionada está configurada para el entorno elegido.

<Aside type="note">Guardar una configuración se combina con la almacenada para ese entorno, por lo que los secretos de solo escritura en blanco nunca se sobrescriben con valores vacíos.</Aside>

Los entornos se comparten con los agentes de PlaidLink, de modo que el entorno de un proyecto puede cambiar el agente que ejecuta sus pasos remotos además de las conexiones que lee. Consulte [Entornos de agentes](/es/reference/cli/plaidlink/agents/#entornos-de-agentes).

## Editar una conexión

1. Seleccione la conexión en la lista
2. Haga clic en `Edit` en la barra de herramientas (o haga clic con el botón derecho en la fila)
3. Cambie los campos y haga clic en `Update`

## Probar una conexión

La forma de probar depende del tipo:

- Las **conexiones de base de datos** (Databricks, Snowflake, PostgreSQL y Redshift) tienen un botón **Probar conexión** en el editor. Abre la conexión con las credenciales que introdujo e informa del éxito (con la versión del servidor a la que llegó) o del motivo del fallo, sin cerrar el editor, de modo que pueda corregir y reintentar en el mismo lugar.
- Las conexiones de base de datos con SSH también exponen una prueba del túnel SSH en la pestaña `SSH Config`.
- La [conexión REST genérica](/es/reference/connectors/rest/generic-rest/) tiene una pestaña `Testing` que envía una solicitud ad hoc a través de la conexión guardada.

Guarde la conexión antes de probarla: las pruebas se ejecutan con la configuración almacenada.

<Aside type="note">**Probar conexión** aparece en un tipo de conexión cuando su editor lo ofrece; actualmente, los tipos de base de datos anteriores más [TM1](/es/guides/connections/tm1/), [Oracle Essbase](/es/guides/connections/essbase/), [HFM/FCCS](/es/guides/connections/hfm-fccs/), Salesforce y Anaplan. Otras conexiones REST, como NetSuite, aún no lo tienen: pruébelas enviando una solicitud pequeña desde un paso de un flujo de trabajo (para NetSuite, consulte [Conectar con NetSuite](/es/guides/connections/netsuite/#probar-rápidamente-la-conexión)).</Aside>

## Clonar, eliminar y rastrear el uso

- **Clonar**: duplica la configuración de una conexión como base de una nueva. Consulte [Clonar una conexión](/es/guides/connections/clone-connection/).
- **Eliminar**: quita la conexión seleccionada desde la barra de herramientas (se le pide confirmación).
- **Dónde se usa…**: enumera los pasos de flujo de trabajo que hacen referencia a la conexión, para que pueda ver el impacto antes de editarla o eliminarla.

<Aside type="caution">`Edit`, `Clone` y `Delete` solo están disponibles en las conexiones de las que usted es propietario. Si esas acciones aparecen atenuadas para la fila seleccionada, usted no es propietario: pida a un propietario que haga el cambio o que lo agregue mediante `Owners`.</Aside>
