Una **conexión** es una configuración guardada que permite a PlaidCloud acceder a un sistema externo: una base de datos, un data lake, un ERP, una API REST, un servicio en la nube o un proveedor de Git. Los pasos de los flujos de trabajo hacen referencia a la conexión por su nombre, de modo que los detalles del punto de conexión y las credenciales se mantienen en un solo lugar y se reutilizan en cada paso y proyecto que los necesite.

Las conexiones se administran desde **Tools > Connections**.

## Creación de una conexión

1. Abra **Tools > Connections**
2. Haga clic en `New Connection` en la barra de herramientas y elija en el menú el sistema al que desea conectarse
3. Complete el formulario de conexión (las pestañas y los campos varían según el tipo; consulte [Formulario de conexión](#formulario-de-conexión) más abajo)
4. Haga clic en `Create` para guardar

La nueva conexión aparece en la lista, con usted como propietario.

<Aside type="note">La lista de tipos de conexión y los campos que necesita cada uno están catalogados en la [referencia de conectores](/es/reference/connectors/). Para un servicio sin un conector específico, use la [conexión REST genérica](/es/reference/connectors/rest/generic-rest/).</Aside>

## Formulario de conexión

La mayoría de las conexiones abren un formulario con varias pestañas. Las pestañas exactas dependen del tipo, pero normalmente verá:

- **Configuración de la conexión** (o **Detalles de la conexión** para REST): el `Name` de la conexión, un `Memo` opcional, el host, el puerto y la base de datos (o el host y el tipo de autenticación para REST), el conmutador `Usage` (`Active`) y el `Security Model`. En una conexión de base de datos, las credenciales están aquí, en un grupo **Credenciales de autenticación**; en una conexión REST tienen su propia pestaña **Autenticación**.
- **Configuración de SSL**: `Use SSL` más el modo SSL y los certificados opcionales de cliente y raíz para una conexión cifrada.
- **Configuración de SSH**: `Use SSH` más el host bastión, el puerto, el usuario y la clave para canalizar la conexión a través de un host intermedio SSH.

Los campos de contraseña, token y otras credenciales son de solo escritura: aparecen en blanco cuando vuelve a abrir una conexión guardada, y dejarlos en blanco al guardar conserva el secreto almacenado. Vuelva a escribir un valor solo cuando desee cambiarlo. Esto abarca la clave de API, el secreto de cliente de OAuth y el token de actualización de OAuth de una conexión REST. Las credenciales de varias líneas (un certificado privado de NetSuite, un certificado y una clave privada de Anaplan, una clave de API de Postman, una URL de webhook entrante de Slack o Teams) son de solo escritura de la misma manera y se enmascaran mientras las escribe o las pega. Un reemplazo formado solo por espacios se rechaza en lugar de guardarse sobre la credencial almacenada; borre el campo para conservar el valor guardado. La clave de cliente SSL y la clave privada SSH de una conexión SQL o Git también son de solo escritura, pero permanecen visibles mientras las escribe. Todos los demás campos muestran su valor real guardado en todos los lugares donde se muestra la conexión, en el editor y a través de la API, incluidos los campos que por su nombre parecen confidenciales (el indicador de solo lectura de una base de datos, un identificador de cuenta, un esquema, un nombre de host): solo se enmascara u oculta una credencial real.

A través de la API REST y MCP, un campo de credencial sigue la misma regla que el editor: envíe una cadena vacía y PlaidCloud conserva el valor almacenado; envíe `null` para borrarlo. Todos los campos que no son credenciales siguen borrándose cuando los envía en blanco.

Los campos obligatorios se validan al guardar; si falta algo, el formulario cambia a la pestaña que contiene el primer campo no válido y lo señala.

## Modelo de seguridad

El `Security Model` de una conexión controla quién del espacio de trabajo puede usarla:

| Opción | Quién puede usar la conexión |
|---|---|
| Privado (solo propietarios) | Solo los propietarios. |
| Solo miembros específicos | Los propietarios más una lista explícita de miembros. |
| Solo grupos de seguridad específicos | Los propietarios más los miembros de los grupos de seguridad indicados. |
| Todos los miembros del espacio de trabajo | Todas las personas del espacio de trabajo. |

Cuando elige `Specific Members Only` o `Specific Security Groups Only`, conceda el acceso desde el menú `Actions` de la lista: `Members` para `Specific Members Only` o `Groups` para `Specific Security Groups Only`, además de `Agents` y `Owners`, abren cada uno una lista de verificación filtrable en la que marca quién tiene acceso (consulte [Asignación con el selector](/es/administration/access/managing-security-groups-and-assignments/#asignación-con-el-selector)). Solo un propietario de la conexión, o un administrador del espacio de trabajo, puede cambiar el acceso allí. Cualquier otra persona que pueda editar conexiones puede abrirlas para ver quién tiene acceso, en una lista de solo lectura de las personas ya asignadas. Un administrador del espacio de trabajo puede cambiar el acceso a una conexión que no le pertenece, para transferirla cuando sus propietarios se han marchado.

## Quién ve las credenciales de una conexión

Cualquier persona que pueda usar una conexión puede abrirla y ver su configuración, y explorar los repositorios, las ramas y los archivos de una conexión de Git. Las contraseñas, los tokens y las claves de una conexión se devuelven solo a los miembros que pueden editar conexiones o flujos de trabajo. A través de la API REST y MCP, todos los demás los reciben enmascarados.

Cuando explore una conexión de Git con una URL de servidor distinta de la guardada, introduzca un token para ese servidor.

## Entornos

Una conexión puede contener una configuración distinta por **entorno** (por ejemplo, un host de desarrollo y un host de producción bajo un mismo nombre de conexión). El selector de entorno de la barra de herramientas elige la configuración de qué entorno está viendo y editando.

- `New Environment`: agrega un entorno de conexión
- `Edit Environment`: cambia el nombre del entorno seleccionado
- `Delete Environment`: elimina el entorno seleccionado, siempre que ningún proyecto lo use, ningún paso lo tenga como [entorno fijo](/es/guides/projects/managing-projects/#fijar-un-paso-a-un-entorno) y ningún agente lo atienda. En caso contrario, el mensaje indica qué lo sigue usando. El entorno predeterminado no se puede eliminar.

La columna `Available` de la lista muestra si la conexión seleccionada está configurada para el entorno elegido.

<Aside type="note">Guardar una configuración se combina con la almacenada para ese entorno, por lo que los secretos de solo escritura en blanco nunca se sobrescriben con valores vacíos.</Aside>

Los entornos se comparten con los agentes de PlaidLink, de modo que el entorno de un proyecto puede cambiar el agente que ejecuta sus pasos remotos además de las conexiones que lee. Consulte [Entornos de agentes](/es/reference/cli/plaidlink/agents/#entornos-de-agentes).

## Edición de una conexión

1. Seleccione la conexión en la lista
2. Haga clic en `Edit` en la barra de herramientas (o haga clic con el botón derecho en la fila)
3. Cambie los campos y haga clic en `Update`

## Prueba de una conexión

La forma de probar depende del tipo:

- Las **conexiones de base de datos** (Databricks, Snowflake, PostgreSQL y Redshift) tienen un botón **Probar conexión** en el editor. Abre la conexión con las credenciales que introdujo e informa del éxito (con la versión del servidor a la que llegó) o del motivo del fallo, sin cerrar el editor, de modo que pueda corregir y reintentar en el mismo lugar.
- Las conexiones de base de datos con SSH también ofrecen una prueba del túnel SSH en la pestaña `SSH Config`.
- La [conexión REST genérica](/es/reference/connectors/rest/generic-rest/) tiene una pestaña `Testing` que envía una solicitud ad hoc a través de la conexión guardada.

Guarde la conexión antes de probarla: las pruebas se ejecutan con la configuración almacenada.

<Aside type="note">**Probar conexión** aparece en un tipo de conexión una vez que su editor lo ofrece; actualmente los tipos de base de datos anteriores más [TM1](/es/guides/connections/tm1/), [Oracle Essbase](/es/guides/connections/essbase/), [HFM/FCCS](/es/guides/connections/hfm-fccs/), Salesforce y Anaplan. Otras conexiones REST, como NetSuite, aún no lo tienen: haga una prueba rápida enviando una pequeña solicitud desde un paso de un flujo de trabajo (para NetSuite, consulte [Conexión a NetSuite](/es/guides/connections/netsuite/#probar-rápidamente-la-conexión)).</Aside>

## Direcciones a las que una conexión no puede acceder

Una conexión no puede apuntar a una dirección de loopback, de enlace local ni de metadatos de la nube. PlaidCloud comprueba la dirección a la que se resuelve un nombre de host cuando prueba la conexión y cuando un paso la usa, y una dirección que no cumple los requisitos falla con un error que nombra el host y la dirección a la que se resolvió. Las direcciones de su red privada no se ven afectadas.

## Clonar, eliminar y rastrear el uso

- **Clonar**: duplica la configuración de una conexión como base para una nueva. Consulte [Clonación de una conexión](/es/guides/connections/clone-connection/).
- **Eliminar**: quita la conexión seleccionada desde la barra de herramientas (se le pide confirmación).
- **Dónde se usa…**: enumera los pasos de flujos de trabajo que hacen referencia a la conexión, para que pueda ver el impacto antes de editarla o eliminarla.

<Aside type="caution">`Edit`, `Clone` y `Delete` solo están disponibles en las conexiones de las que usted es propietario. Si esas acciones aparecen atenuadas para la fila seleccionada, usted no es propietario: pida a un propietario que haga el cambio o que lo agregue mediante `Owners`.</Aside>

Lo mismo se aplica a través de la API REST, JSON-RPC y el asistente de IA o MCP: cambiar la configuración de una conexión requiere que usted sea uno de sus propietarios, o un administrador del espacio de trabajo para una conexión sin propietario. Habilitar, deshabilitar, bloquear y desbloquear una conexión requiere un propietario o un administrador del espacio de trabajo. Una solicitud que nombra varias conexiones se aplica solo cuando usted puede cambiarlas todas.
