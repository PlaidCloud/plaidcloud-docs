[Data Foundation](/es/guides/projects/data-foundation/) reúne los datos de cada sistema ERP e instancia que usted conecta en un único Common Finance Model, y SAP ECC es uno de los ERP que lee directamente. PlaidCloud llega al sistema mediante un agente de [PlaidLink](/es/reference/cli/plaidlink/) instalado en su propia red, a través de RFC. Esta página está dirigida al administrador de SAP que lo configura y al usuario de PlaidCloud que se lo solicita.

PlaidCloud solo lee datos. Nadie envía una contraseña por correo electrónico.

## Enviar la solicitud de acceso

En la página **Sistemas** del proyecto, en **Data Foundation** dentro de **Inicio**, elija su sistema en **Sistema**, en **Agregar un sistema**, y haga clic en **¿Aún no tiene acceso?**. El sistema queda a la espera de acceso y se muestra una única solicitud que abarca los sistemas del proyecto. Haga clic en **Copiar solicitud** para pegarla en su propio mensaje, o en **Enviar solicitud por correo** para abrirla en su programa de correo con el asunto “Acceso para PlaidCloud”.

## Qué configura el administrador de SAP

<Steps>

1. **Instale el paquete ABAP de PlaidCloud** (grupo de funciones de `Z_PLAIDCL_B5_READ_TABLE`) en el mandante desde el que informa, e instale un agente de PlaidLink que pueda llegar al sistema mediante RFC.

2. **Cree un usuario de comunicación**, por ejemplo `PLAIDCLOUD_RFC`, con un rol que contenga estas autorizaciones:

   - `S_RFC`: ejecutar el grupo de funciones de `Z_PLAIDCL_B5_READ_TABLE`.
   - `S_TABU_NAM` (visualizar, `ACTVT` 03) para las tablas siguientes.

   | Tablas | Qué contienen |
   |---|---|
   | `T001` | Códigos de empresa |
   | `T009`, `T009B`, `T001B` | Variantes de ejercicio fiscal y períodos de contabilización |
   | `SKA1`, `SKAT` | Cuentas del libro mayor |
   | `FAGL_011PC`, `FAGL_011ZC` | Versión de estado financiero |
   | `CSKS`, `CSKT` | Centros de costos |
   | `SETHEADER`, `SETNODE` | Grupos de centros de costos y de centros de beneficio |
   | `CEPC`, `CEPCT` | Centros de beneficio (opcional) |
   | `KNA1`, `KNVV`, `KNVH` | Clientes y su jerarquía |
   | `MARA`, `MAKT`, `T006A` | Materiales y unidades |
   | `TCURR`, `TCURF`, `TCURX` | Tipos de cambio y decimales de moneda |
   | `BKPF`, `BSEG` | Documentos contables y sus partidas |
   | `FAGLFLEXT`, o en el libro mayor clásico `GLT0` | Totales del libro mayor |
   | `CSKB`, `CSKU`, `COEP` | Elementos de costo y partidas de control de costos: distribuciones y asignaciones |
   | `COSP`, `COSS`, `COSR` | Plan del centro de costos y cifras clave estadísticas (opcional) |
   | `VBRK`, `VBRP`, `KONV` | Documentos de facturación y sus condiciones de precio (opcional) |
   | `T001K`, `MBEW`, `MBEWH` | Áreas de valoración, valores de existencias de materiales y precios estándar (opcional) |
   | `T001W`, `TKA02` | Plantas, que se leen como sitios, y la sociedad CO de cada código de empresa (opcional) |
   | `T016T`, `TKUKT`, `KNVP`, `TSPAT`, `T052U` | Nombres de ramos y de clasificaciones de clientes, el empleado de ventas de cada cliente, y nombres de sectores y de condiciones de pago (opcional) |
   | `T012K`, `T012T` | Cuentas de bancos propios, para los saldos bancarios (opcional) |
   | `LFA1`, `LFB1` | Proveedores (opcional) |
   | `RBKP`, `RSEG` | Facturas de proveedores (opcional) |
   | `EKKO`, `EKPO`, `EKKN`, `EKET`, `EKBE` | Órdenes de compra y sus recepciones y facturas (opcional) |
   | `ANLA`, `ANLZ`, `ANLB`, `ANKA`, `T095`, `ANLC`, `ANEP`, `ANEA`, `ANLP` | El registro de activos fijos y sus movimientos (opcional) |
   | La tabla de partidas individuales de la estructura de explotación (`CE1` seguido de su nombre) | CO-PA por valoración (opcional) |

   Las partidas abiertas y los pagos se leen de las partidas de clientes y proveedores de `BSEG`, con sus cabeceras de `BKPF`.

3. **Responda las preguntas contables** (véase más abajo).

</Steps>

### Preguntas que responde el administrador

| El administrador le indica | Usted lo introduce en PlaidCloud en **Ajustes del sistema** |
|---|---|
| El tipo de tipo de cambio que contiene el tipo medio. PlaidCloud promedia los tipos de ese tipo de cada mes. Con frecuencia es `M`. | **Average rate type** |
| El tipo de tipo de cambio que contiene el tipo de cierre, su tipo al final del mes. Si no indica ninguno, el tipo de cierre es el tipo `M`. | **Closing rate type** |
| Si el sistema ejecuta el nuevo libro mayor (`FAGLFLEXT`) o el clásico (`GLT0`) | **General ledger totals table** |
| La versión de estado financiero que informa las pérdidas y ganancias de gestión y el balance general | **Financial statement version** |
| Cuáles de sus nodos son ingresos, costo de ventas, gastos operativos, no operativos, activos, pasivos, patrimonio e intercompañía | **Account type of each statement node**: una línea por nodo, con el formato `node = type`, con un tipo de los que enumera el cuadro, como `Revenue` o `Asset`. **Intercompany statement nodes** indica los nodos intercompañía. Ambos se aplican solo cuando se ha establecido **Financial statement version**. |
| Que el arrastre de saldos se ha ejecutado para cada ejercicio fiscal sobre el que informa (`FAGLGVTR`, o `F.16` en el libro mayor clásico) | No hay nada que introducir. Los saldos iniciales se leen de la tabla de totales. |
| El área de amortización de cada libro de activos, contable o fiscal. La primera es la del registro. PlaidCloud supone que el área `01` es el libro contable. | **Depreciation area of each book** |
| El tipo de movimiento de cada clase de movimiento de activos, según su primer dígito. PlaidCloud supone `1` alta, `2` baja, `3` traspaso, `6` amortización y `9` apertura. | **Movement type of each transaction type** |
| La tabla de partidas individuales de la estructura de explotación, si desea CO-PA por valoración. Si no se indica ninguna, no se lee CO-PA. | **Operating concern line item table** |
| El campo de valor de CO-PA de cada cuenta, y cuáles de ellos son costos | **Value field of each CO-PA account**, **CO-PA cost value fields** |

## Qué debe enviar de vuelta

| El administrador envía | Se introduce en PlaidCloud como |
|---|---|
| El ID del sistema y el servidor de aplicaciones (o el servidor de mensajes y el grupo de inicio de sesión) | **Host** y **Número de sistema** o, con **Usar conexión de varios sistemas con equilibrio de carga**, **Host de MS**, **Servidor de MS**, **ID del sistema** y **Grupo** |
| El mandante | **Cliente** |
| El nombre del usuario de comunicación | **Usuario** |
| La contraseña del usuario de comunicación, mediante su administrador de contraseñas | **Contraseña**, que su equipo introduce por sí mismo |
| El nombre del agente de PlaidLink que llega al sistema | El ajuste del sistema **PlaidLink agent** |
| Los códigos de empresa que PlaidCloud puede leer | En **Opciones**, **Empresas**, que SAP no puede listar: introduzca los códigos de empresa, separados por comas, o deje el campo vacío para cargar todos los códigos de empresa |

<Aside type="caution">
No envíe nunca la contraseña por correo electrónico. **Contraseña** es un secreto: se almacena en la conexión y no se vuelve a mostrar.
</Aside>

## Comprobar el acceso

SAP se lee mediante un agente de PlaidLink, por lo que **Probar conexión** no lo lee: lo hace la primera carga, que indica cualquier tabla que el usuario no tenga permiso para leer. Cada conjunto de datos lee:

| Conjunto de datos | Tablas que lee |
|---|---|
| Entidades | `T001` |
| Calendario fiscal | `T001`, `T009`, `T009B`, `T001B` |
| Tipos de cambio | `TCURR`, `TCURF` |
| Plan de cuentas | `SKA1`, `SKAT`, `FAGL_011PC`, `FAGL_011ZC`, `CSKB`, `CSKU` |
| Departamentos | `CSKS`, `CSKT`, `SETHEADER`, `SETNODE` |
| Centros de beneficio | `CEPC`, `CEPCT`, `SETHEADER`, `SETNODE` |
| Clientes | `KNA1`, `KNVV`, `KNVH` |
| Productos | `MARA`, `MAKT`, `T006A` |
| Libro mayor | `BKPF`, `BSEG`, `COEP` |
| Balance de comprobación | `FAGLFLEXT` o `GLT0` |
| Líneas de ventas | `VBRK`, `VBRP`, `KONV` |
| Presupuesto | `COSP`, `COSS` |
| Inductores de asignación | `COSR` |
| Saldos de inventario | `MBEW`, `MBEWH`, `T001K` |
| Saldo de cierre de mes | `FAGLFLEXT` o `GLT0`, el saldo al cierre de cada mes |
| Saldos bancarios | `T012K`, `T012T`, con el saldo de cierre de mes de la cuenta de mayor de cada banco propio |
| Sitios | `T001W`, `T001K` |
| Proveedores | `LFA1`, `LFB1` |
| Líneas de facturas de proveedores | `RBKP`, `RSEG`, `BKPF` |
| Órdenes de compra | `EKKO`, `EKPO`, `EKKN`, `EKET`, `EKBE` |
| Partidas abiertas, Pagos | Partidas de clientes y proveedores de `BSEG`, `BKPF` |
| Activos fijos | `ANLA`, `ANLZ`, `ANLB`, `ANKA`, `T095` |
| Movimientos de activos | `ANLC`, `ANEP`, `ANEA`, `ANLP` |
| Costos estándar | `T001K`, `MBEW`, `MBEWH` |
| CO-PA por valoración | La tabla indicada en **Operating concern line item table** |

Cuando una carga indica una tabla que el usuario no tiene permiso para leer, pida al administrador que la agregue al rol y vuelva a cargar. Los centros de beneficio, las líneas de ventas, el presupuesto, los inductores de asignación, los saldos de inventario y todos los conjuntos de datos a partir del saldo de cierre de mes son opcionales: un sistema que no contiene alguno de ellos carga igualmente todo lo demás. Los saldos bancarios, las partidas abiertas o los pagos de un mes que SAP rechaza conservan las filas que ya tenían.

Las cuentas de bancos propios que comparten una cuenta de mayor tienen una sola fila de saldo entre todas, ya que la cuenta de mayor tiene un solo saldo.
