[Data Foundation](/es/guides/projects/data-foundation/) reúne los datos de cada sistema ERP e instancia que usted conecta en un único Common Finance Model, y Microsoft Dynamics 365 Business Central es uno de los ERP que lee directamente. La conexión usa una aplicación de Microsoft Entra ID con credenciales de cliente, un conjunto de permisos de solo lectura y algunos objetos de página publicados como servicios web. Esta página está dirigida al administrador de Business Central que lo configura y al usuario de PlaidCloud que se lo solicita.

PlaidCloud solo lee datos. Nadie envía un secreto de cliente por correo electrónico.

## Enviar la solicitud de acceso

En la página **Sistemas** del proyecto, en **Data Foundation** dentro de **Inicio**, elija su sistema en **Sistema**, en **Agregar un sistema**, y haga clic en **¿Aún no tiene acceso?**. El sistema queda a la espera de acceso y se muestra una única solicitud que abarca los sistemas del proyecto. Haga clic en **Copiar solicitud** para pegarla en su propio mensaje, o en **Enviar solicitud por correo** para abrirla en su programa de correo con el asunto “Acceso para PlaidCloud”.

## Qué configura el administrador de Business Central

<Steps>

1. **Registre una aplicación en Microsoft Entra ID.** En **App registrations > New registration**, agregue un secreto de cliente y anote el Directory (tenant) ID, el Application (client) ID y el secreto.

2. **Agregue la aplicación en Business Central.** Abra **Microsoft Entra Applications**, agregue la aplicación, establezca su estado en **Habilitado** y asígnele solo el conjunto de permisos **D365 READ** para cada empresa sobre la que informe. Con él se leen todas las páginas siguientes. No le asigne **D365 BASIC** ni ningún otro conjunto de permisos que pueda escribir.

3. **Publique objetos de página como servicios web.** En **Search > Web Services > New**, publique estos objetos de página con exactamente estos nombres de servicio y con **Published** marcado. La API estándar no incluye sus campos:

   | Página | Nombre del servicio | Notas |
   |---|---|---|
   | 20 G/L Entries | `GLEntries` | |
   | 16 Chart of Accounts | `GLAccounts` | |
   | 100 Accounting Periods | `AccountingPeriods` | |
   | 537 Dimension Values | `DimensionValues` | |
   | 240 Business Units | `BusinessUnits` | |
   | 605 IC Partner List | `ICPartners` | |
   | 5802 Value Entries | `ValueEntries` | Costo de ventas y saldos de inventario; opcional |
   | 120 G/L Budget Entries | `GLBudgetEntries` | Presupuestos; opcional |
   | Statistical Ledger Entries | `StatisticalLedgerEntries` | Inductores estadísticos; opcional |
   | 118 General Ledger Setup | `GeneralLedgerSetup` | Dimensiones de acceso directo 3 a 8; opcional |
   | 479 Dimension Set Entries | `DimensionSetEntries` | Dimensiones de acceso directo 3 a 8; opcional |
   | 573 Detailed Cust. Ledg. Entries | `DetailedCustLedgEntries` | Partidas abiertas y pagos; opcional |
   | 574 Detailed Vendor Ledg. Entries | `DetailedVendorLedgEntries` | Partidas abiertas y pagos; opcional |
   | 371 Bank Account List | `BankAccounts` | Saldos bancarios; opcional |
   | 277 Bank Account Posting Groups | `BankAccountPostingGroups` | Saldos bancarios; opcional |
   | Inventory Posting Setup (busque su página) | `InventoryPostingSetup` | La cuenta de las líneas de compra de un artículo; opcional |

4. **Comunique al usuario de PlaidCloud tres decisiones:** el código de origen bajo el que se contabilizan sus ajustes de auditoría (PlaidCloud supone `ADJUSTMENT`), qué dimensión es su departamento (PlaidCloud supone la dimensión global 1, llamada `DEPARTMENT`) y cuál es su centro de beneficio (PlaidCloud supone la dimensión global 2, llamada `PROFITCENTER`). Un sitio es una ubicación de Business Central.

</Steps>

## Qué enviar de vuelta

| El administrador envía | Se introduce en PlaidCloud como |
|---|---|
| El Directory (tenant) ID | **ID de inquilino de Azure AD** |
| El Application (client) ID | **ID de cliente** |
| El secreto de cliente | **Secreto de cliente**, introducido en el editor de conexiones, no por correo electrónico |
| El nombre del entorno, por ejemplo `production` | **Entorno** |
| El ID de una empresa | **ID de empresa**: la conexión necesita uno, y Data Foundation lee las empresas elegidas en **Empresas** |
| El nombre de la dimensión que es su departamento | El ajuste del sistema **Department dimension** |
| El nombre de la dimensión que es su centro de beneficio | El ajuste del sistema **Profit centre dimension** |
| El código de origen bajo el que se contabilizan sus ajustes de auditoría | El ajuste del sistema **Audit adjustment source code** |
| Las empresas que PlaidCloud puede leer | En **Opciones**, **Empresas**: márquelas, o no marque ninguna para leer todas las empresas |

Las empresas de consolidación se indican en el ajuste del sistema **Consolidation companies**, de modo que sus asientos no se cuenten como actividad de una empresa. Los tipos de cambio provienen de una sola empresa: indíquela en el ajuste del sistema **Exchange rate company**, o PlaidCloud usa la primera empresa.

## Comprobar el acceso

De vuelta en PlaidCloud, una vez agregado el sistema, haga clic en **Probar conexión** en su fila de la página **Sistemas**. Cada conjunto de datos aparece como **Legible**, **Falta un permiso** o **Error**:

| Conjunto de datos | Qué necesita |
|---|---|
| Entidades, Plan de cuentas, Clientes, Productos, Tipos de cambio, Balance de comprobación | Acceso a la API (conjunto de permisos D365 READ) |
| Calendario fiscal | El servicio web `AccountingPeriods` |
| Departamentos | El servicio web `DimensionValues` |
| Libro mayor | El servicio web `GLEntries` |
| Todos los demás conjuntos de datos | Opcional, no forma parte de la prueba |

Cuando falta un conjunto de datos, la prueba indica qué permiso o servicio web debe agregarse. Pida al administrador que lo agregue y pruebe de nuevo.

Los conjuntos de datos opcionales son los sitios, los centros de beneficio, los proveedores, el saldo de cierre de mes, los saldos bancarios, los saldos de inventario, las líneas de ventas, las líneas de facturas de proveedores, las partidas abiertas, los pagos, los presupuestos y los inductores de asignación. Un entorno que no usa alguno de ellos carga igualmente todo lo demás y, después de la siguiente carga, las comprobaciones de preparación del panel de control **CFM-Accounting - Close and assurance** indican cualquier página que Business Central rechace. El saldo de cierre de mes es el balance de comprobación al final de cada mes; los saldos bancarios son ese saldo para las cuentas en las que contabilizan sus cuentas bancarias. Cuando Business Central rechaza una lectura a partir de la cual se construyen el saldo de cierre de mes, los saldos bancarios, el inventario, las líneas de ventas, las líneas de facturas de proveedores, las partidas abiertas o los pagos de un mes, ese mes conserva las filas que ya tenía y se vuelve a leer en la siguiente carga.
