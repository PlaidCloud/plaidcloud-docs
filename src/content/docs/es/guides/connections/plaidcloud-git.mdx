Una **conexión de PlaidCloud Git** apunta un flujo de trabajo, o la compilación de una aplicación Panel de servidor, a un repositorio del servidor Git administrado de su propio espacio de trabajo. Como ese servidor Git se aloja por usted en `git.<your-workspace>.plaid.cloud` y ya ha iniciado sesión con su inicio de sesión normal de PlaidCloud, el formulario de conexión es mucho más sencillo que el de un proveedor de Git externo: no hay que ingresar una URL de servidor ni administrar un nombre de usuario, un token o una clave SSH.

<Aside type="note">Nunca ingresa una URL de servidor ni credenciales para una conexión de PlaidCloud Git. El servidor Git de su espacio de trabajo y su acceso a él se gestionan automáticamente a partir de su inicio de sesión de PlaidCloud (incluido SSO), por lo que no hay tokens que generar, almacenar ni rotar.</Aside>

## Cuándo usarla

Use una conexión de PlaidCloud Git siempre que el repositorio que desea leer se encuentre en [PlaidCloud Git](/es/guides/git/), el servicio Git integrado de su espacio de trabajo, y no en un host externo. El uso más común es automatizar las compilaciones de **aplicaciones Panel de servidor** o **aplicaciones de Dash** desde un repositorio administrado, de modo que un push a una rama recompile y vuelva a implementar la aplicación sin una cuenta externa de GitHub ni un token de acceso personal de por medio.

Para un repositorio alojado en un servicio externo (GitHub, GitLab, Bitbucket, Forgejo o Gitea), use en su lugar una [conexión de Git externa](/es/reference/connectors/git/). Estas conservan el formulario completo con una **URL del servidor**, autenticación por usuario y token o por SSO, y las pestañas **SSL** y **SSH**.

## Crear una conexión de PlaidCloud Git

1. Abra **Tools > Connections**
2. Haga clic en `New Connection` y elija **PlaidCloud Git** en el menú
3. Complete el formulario simplificado:
   - **Nombre de la cuenta**: un nombre para mostrar de la conexión
   - **Nota**: una nota opcional sobre el propósito de la conexión
   - **Repositorio**: haga clic en `Refresh` para listar los repositorios a los que puede acceder su espacio de trabajo y elija uno (por ejemplo, su repositorio `udfs` o `apps`). Lo selecciona de la lista en lugar de escribir la ruta.
   - **Rama predeterminada**: elija la rama que se leerá de forma predeterminada de la lista de ramas del repositorio seleccionado
   - **Ruta de inicio**: opcionalmente, explore el repositorio y elija una carpeta para limitar cada búsqueda de archivos a una subcarpeta; déjela sin definir para usar todo el repositorio
4. Defina **Uso**: `Active` para habilitar la conexión y `Read Only` si la conexión nunca debe escribir
5. Defina el **Modelo de seguridad**: quién del espacio de trabajo puede usar la conexión
6. Haga clic en `Create` para guardar

Eso es todo el formulario. A diferencia de un proveedor de Git externo, no hay URL del servidor, ni pestaña de autenticación, ni configuración de SSL o SSH: todo eso se gestiona por usted.

<Aside type="note">El repositorio, la rama predeterminada y la ruta de inicio se eligen de listas en vivo (primero un repositorio, luego su rama y después una carpeta), por lo que no hay nada que escribir mal. Cada lista se lee con el acceso propio de la conexión, así que en una conexión de PlaidCloud Git se llenan de inmediato, sin credenciales que ingresar.</Aside>

## Modelo de seguridad

`Security Model` controla quién del espacio de trabajo puede usar la conexión:

| Opción | Quién puede usar la conexión |
|---|---|
| Privado (solo propietarios) | Solo los propietarios. |
| Solo miembros específicos | Los propietarios y una lista explícita de miembros. |
| Solo grupos de seguridad específicos | Los propietarios y los miembros de los grupos de seguridad indicados. |
| Todos los miembros del espacio de trabajo | Todos los usuarios del espacio de trabajo. |

Para `Specific Members Only` o `Specific Security Groups Only`, conceda el acceso desde el menú `Actions` de la lista después de guardar. Consulte [Crear y administrar una conexión](/es/guides/connections/create-connection/#modelo-de-seguridad) para conocer los mecanismos comunes de las conexiones.

## Quién puede ver los repositorios

Todos los repositorios que PlaidCloud crea para usted pueden ser leídos por cualquier miembro de su espacio de trabajo que haya iniciado sesión. Esto incluye los repositorios detrás de sus aplicaciones Panel y Dash y los repositorios integrados `apps` y `udfs`. Nadie que no haya iniciado sesión puede leerlos.

Por eso, los miembros pueden abrir y volver a publicar aplicaciones, y elegir un repositorio para una conexión de PlaidCloud Git, sin ninguna configuración por repositorio.

### Avanzado: repositorios privados

Un administrador de Git puede hacer privado un repositorio en la interfaz de Git. Un repositorio privado deja de ser visible para todos los miembros, por lo que:

- No aparece en la lista **Repositorio** de las conexiones de PlaidCloud Git.
- No se puede leer de él el código de UDF respaldado por Git, así que una UDF respaldada por Git almacenada en un repositorio privado no se ejecutará.
- Los miembros no pueden publicar una aplicación desde él.

Para usar un repositorio privado como origen, cree en su lugar una [conexión de Git externa](/es/reference/connectors/git/) con su propio token de acceso.

## Automatizar las compilaciones de aplicaciones Panel y Dash desde Git administrado

Una [aplicación Panel de servidor](/es/guides/panel-apps/creating/) o una [aplicación de Dash](/es/guides/dash-apps/) se compila desde una rama de Git y se recompila automáticamente con cada push a esa rama. Apuntarla a una conexión de PlaidCloud Git mantiene todo el ciclo dentro de su espacio de trabajo: sin host externo y sin un token de acceso personal que mantener vigente.

1. Haga push de su aplicación a un repositorio del servidor PlaidCloud Git de su espacio de trabajo: un archivo `.py` de punto de entrada (el de Panel llama a `.servable()`; el de Dash expone `server = app.server`) y un `requirements.txt` opcional en la raíz del repositorio o junto a su punto de entrada. Consulte [Crear una aplicación Panel](/es/guides/panel-apps/creating/#preparar-el-repositorio-de-la-aplicación) o [Implementar una aplicación de Dash desde PlaidCloud Git](/es/guides/dash-apps/deploy-from-git/) para conocer la estructura del repositorio.
2. Cree una conexión de PlaidCloud Git cuyo **Repositorio** sea ese repositorio, siguiendo los pasos anteriores.
3. En **Mis aplicaciones Panel**, haga clic en **Nueva aplicación de servidor** o **Nueva aplicación Dash** y, en **Conexión de Git y observador de publicación**:
   - **Conexión de Git**: elija la conexión de PlaidCloud Git que acaba de crear
   - **Rama**: la rama desde la que se compila; los push a ella recompilan y vuelven a implementar la aplicación
   - **Punto de entrada**: el archivo `.py` que debe servir la aplicación
4. Termine el cuadro de diálogo de publicación y haga clic en **Publicar**.

A partir de entonces, cada push a esa rama en su servidor Git administrado recompila la aplicación: una compilación automatizada de extremo a extremo que nunca sale de PlaidCloud.
