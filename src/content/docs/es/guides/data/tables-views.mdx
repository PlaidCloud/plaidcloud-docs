Los datos e información tabulares de PlaidCloud se almacenan en almacenes de datos Greenplum. Esto proporciona una enorme escalabilidad y rendimiento, y utiliza una tecnología madura y bien conocida para minimizar el riesgo de pérdida o corrupción de datos.

Además, el uso de un almacén de datos que opera con una sintaxis común permite que herramientas de terceros se conecten y exploren los datos directamente. En esencia, esto hace que el ecosistema de datos de PlaidCloud sea abierto y explorable, a la vez que garantiza una seguridad y unos controles de acceso líderes en el sector.

## Tablas

Las tablas contienen los datos tabulares físicos en todo PlaidCloud. Cada tabla puede contener muchos terabytes de datos si es necesario. Los datos se almacenan en numerosos servidores físicos y se replican automáticamente para garantizar la integridad de los datos y la alta disponibilidad.

Las tablas se componen de columnas de distintos tipos de datos. Usar un tipo de datos adecuado puede ayudar al rendimiento y, sobre todo, al tamaño de almacenamiento de sus datos. PlaidCloud también puede comprimir mejor los datos si utilizan el tipo de datos más apropiado. Normalmente PlaidCloud lo deduce por su cuenta, pero también es posible cambiar los tipos de datos mediante los asignadores de columnas de los pasos del flujo de trabajo.

Puede buscar tablas por el flujo de trabajo que las utiliza, por el nombre de una columna o por un valor que contengan, y ver cuándo se leyó una tabla por última vez. Consulte [Administración de tablas y vistas](/es/guides/projects/managing-tables-and-views/#buscar-tablas).

## Vistas

Las vistas funcionan igual que las tablas, pero no contienen datos físicos. Son representaciones lógicas de tablas obtenidas mediante una consulta. Usar vistas puede ahorrar almacenamiento.

Sin embargo, el uso de vistas tiene algunas limitaciones. Tenga en cuenta lo siguiente:

 * Rendimiento del apilamiento de vistas: apilar vistas (una vista de una vista de una vista, etc.) puede afectar al rendimiento en tablas muy grandes o cálculos complejos. Puede ser necesario crear tablas intermedias para mejorar el rendimiento.
 * Rendimiento de los paneles de control: aunque no hay problema en publicar una vista para usarla en un panel de control, en el caso de tablas muy grandes quizá le convenga publicar una tabla en lugar de una vista para ofrecer la mejor experiencia al usuario.
 * Datos dinámicos: los datos de una vista cambian cuando cambian los datos de la tabla subyacente a la que hace referencia. Esto puede ser una ventaja (todo se actualiza automáticamente) o un inconveniente inesperado si se deseaba un conjunto de datos estático.

<Aside>El uso de vistas puede acelerar los flujos de trabajo, ya que no es necesario mover datos en el momento de la ejecución del flujo de trabajo.</Aside>

<Aside>Como las vistas no contienen datos, no pueden utilizarse como destino de importaciones. En ese caso debe usarse una tabla.</Aside>
