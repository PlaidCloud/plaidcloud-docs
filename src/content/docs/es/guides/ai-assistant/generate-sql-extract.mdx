## Descripción

El paso de flujo de trabajo **Extraer SQL** ejecuta un `SELECT` de solo lectura sobre los datos de su proyecto
y escribe el resultado en una tabla nueva. Escribir esa consulta a mano exige
conocer las tablas de origen, sus columnas y el SQL para darles forma.

El editor del paso puede escribir la consulta por usted. Describa el resultado que desea en
lenguaje natural y el asistente de IA produce el `SELECT`; y si no le indica
de qué tablas leer, examina las tablas del proyecto y elige las
relevantes por sí mismo. El SQL generado y las columnas detectadas se muestran para
su revisión y siguen siendo totalmente editables antes de guardar el paso.

<Aside type="note">
Esto usa el mismo modelo integrado que usa el asistente de IA, por lo que **no hay nada que
configurar**. No necesita configurar un agente de IA ni una conexión de LLM por espacio de trabajo
para ello.
</Aside>

## Abrir el paso

En la vista **Pasos** de un flujo de trabajo, haga clic en **Crear paso** y elija una de estas opciones:

- **Tablas → Extraer SQL**, o
- **IA → SQL Extract (asistido por IA)**

Ambas abren el mismo editor del paso Extraer SQL, que ahora incluye un panel **Generar SQL
con IA** en la parte superior de la página Parámetros de extracción de SQL.

## Generar la consulta

1. **(Opcional) Elija las tablas de origen.** En la lista **Tablas de origen**, seleccione una
   o más tablas de las que debe leer la consulta. Deje la lista vacía para que el
   asistente examine el proyecto y elija por usted las tablas relevantes.
2. **Describa lo que desea.** En el cuadro **Describir**, escriba el resultado en lenguaje
   natural; por ejemplo, *«clasifica cada cuenta del libro mayor en un grupo de actividad
   según su rango de números de cuenta»*.
3. **Haga clic en Generar SQL.** El asistente escribe un único `SELECT` de solo lectura,
   lo valida ejecutándolo y completa:
   - el editor **Consulta SQL SELECT** con la instrucción generada, y
   - la página de asignación **Selección de datos de la tabla** con las columnas detectadas.

   Si dejó vacía la lista de orígenes, las tablas que eligió el asistente se
   seleccionan de nuevo en la lista para que pueda ver cuáles usó y ajustarlas.

## Revisar y guardar

El SQL generado es un punto de partida, no una caja negra:

- **Edítelo libremente.** El editor de SQL es totalmente editable: perfeccione la consulta, agregue una
  combinación o cambie la lista de columnas antes de guardar. (Para combinar varias tablas, puede
  seleccionar varias tablas de origen o simplemente editar la consulta generada).
- **Elija una tabla de destino.** Elija o nombre la **Tabla de destino** en la que el paso escribe
  su resultado.
- **Guarde el paso.** Se guarda como un paso Extraer SQL normal y se ejecuta como parte
  del flujo de trabajo igual que cualquier otro.

<Aside type="tip">
Si el asistente devuelve una consulta que no se ejecuta, el editor sigue mostrando el SQL
junto con el error para que pueda corregirla, o ajustar su descripción y
generarla de nuevo.
</Aside>

## Notas y límites

- El asistente solo escribe instrucciones `SELECT` **de solo lectura**; nunca produce
  `INSERT`, `UPDATE`, `DELETE` ni otro SQL que modifique datos.
- La generación **no crea ni ejecuta** el paso: solo redacta la consulta y
  muestra una vista previa de las columnas. El paso se crea cuando lo guarda y se ejecuta cuando se
  ejecuta el flujo de trabajo.
- La consulta generada lee con los **nombres para mostrar** de sus tablas: cada tabla se
  vincula una vez al inicio de la consulta con su nombre (de modo que las columnas, las combinaciones y
  los filtros se leen con nombres sencillos en lugar de identificadores internos `analyzetable_…`).
  Los identificadores reales se restauran automáticamente al guardar, por lo que la consulta
  se ejecuta sin cambios. Una tabla cuyo nombre no es único conserva su identificador.
