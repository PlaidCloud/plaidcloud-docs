Una **ruta de análisis** es un nombre sencillo para una tabla que analiza con frecuencia, como *“Resultados operativos”* o *“el estado de pérdidas y ganancias”*. Regístrela una vez y, a partir de entonces, usted (y su asistente de IA conectado) podrán hacer preguntas sobre ella por ese nombre, sin repetir cada vez a qué proyecto y a qué tabla se refiere.

Elija una como **predeterminada** del espacio de trabajo y preguntas sencillas como *“¿por qué subió esto el último trimestre?”* funcionan sin más: el asistente ya sabe a qué se refiere “esto”.

<Aside>
Las rutas de análisis son una comodidad compartida del espacio de trabajo: un administrador las configura y, después, **cualquier persona** del espacio de trabajo puede usarlas en sus preguntas, a través de [Microsoft 365 Copilot](/es/integrations/microsoft-365-copilot/) o de un agente de programación conectado mediante [MCP](../getting-started/). Cada pregunta se sigue ejecutando con los permisos propios de cada persona.
</Aside>

## Por qué usarlas

Sin una ruta de análisis, cada pregunta tiene que especificar exactamente dónde están los datos (el proyecto *y* la tabla), lo cual resulta tedioso enseguida y es fácil de hacer mal. Con una, habla de sus datos como realmente piensa en ellos:

- **Pregunte por el nombre.** *“Resume los Resultados operativos.”* en lugar de *“resume la tabla `ops_summary_v3` del proyecto `Enterprise Profitability`.”*
- **Establezca una predeterminada.** Marque su tabla más usada como predeterminada y prescinda del nombre por completo: *“¿qué cambió desde el mes pasado?”* llega automáticamente a los datos correctos.
- **Mantenga la coherencia de todos.** Cuando todo el equipo se refiere a *“el estado de pérdidas y ganancias”*, todos llegan a la misma tabla: sin adivinar, sin copias desactualizadas.

## Registrar una ruta de análisis

Si es administrador del espacio de trabajo, no necesita un formulario ni una pantalla de configuración: simplemente pida a su asistente de IA conectado, en lenguaje natural, que registre la ruta por usted:

> *“Registra una ruta de análisis llamada **Resultados operativos** que apunte a la tabla `ops_summary` del proyecto **Enterprise Profitability**.”*

El asistente confirma la ruta y queda lista para usarse de inmediato. Puede registrar tantas como quiera, una por cada tabla que analice con regularidad.

<Aside type="tip">
Elija nombres como habla su equipo: *“Resultados operativos”, “el Pronóstico”, “Plantilla de personal”.* Cuanto más sencillo sea el nombre, más naturales serán sus preguntas.
</Aside>

## Establecer una ruta predeterminada

Como administrador, marque una ruta como **predeterminada** para que las preguntas que no nombran una tabla lleguen a ella automáticamente:

> *“Haz que **Resultados operativos** sea la ruta de análisis predeterminada.”*

A partir de entonces, *“¿cuáles fueron las mayores variaciones de este trimestre?”* o *“¿por qué bajó el total?”* se ejecutan sobre esa tabla sin necesidad de especificar nada más. Hay una única ruta predeterminada para todo el espacio de trabajo, de modo que las preguntas sin destino de todos se resuelven en la misma tabla. Establecer una nueva predeterminada simplemente traspasa la corona: solo existe una, y el asistente le dice cuál es.

## Hacer que una ruta sea útil para los asistentes de IA

Un nombre y una tabla le dicen a un asistente *dónde* están los datos. No le dicen qué *significan* los datos: qué filtros se aplican siempre, cómo funciona su año fiscal, a qué se refieren las palabras de su equipo. Sin eso, un asistente adivina, y una respuesta incorrecta pero segura de sí misma es peor que una lenta. Esta sección explica los dos lugares donde se coloca ese conocimiento y por qué ambos importan.

En esta guía, **asistentes de IA** significa cualquier LLM conectado mediante MCP de PlaidCloud (Claude, Microsoft Copilot, ChatGPT y otros) más la IA integrada de PlaidCloud.

<Aside type="tip" title="La Guía para el prompt determina la calidad de las respuestas">
Una ruta con una buena Guía para el prompt y notas de columna en su tabla obtiene respuestas correctas y coherentes de todos los asistentes. Una ruta sin ninguna de las dos obtiene lo que el asistente infiere a partir de los nombres de las columnas. Diez minutos dedicados a estas dos cosas son la configuración de mayor valor que puede hacer para una ruta.
</Aside>

### Agregar la Guía para el prompt

Cada ruta de análisis tiene una **Guía para el prompt**: texto libre, escrito por usted, que indica a los asistentes cómo usar la ruta. Escriba una directiva por línea.

Para agregarla, abra el menú **Herramientas** y elija **Rutas de análisis**; luego seleccione una ruta y elija **Editar** (o elija **Nuevo** para crear una). El campo **Guía para el prompt** va después de **Tabla**, justo antes de **Establecer como predeterminada del espacio de trabajo**. Un asistente conectado con permiso para administrar rutas de análisis también puede definirla. Quienes llaman por MCP y API ven este campo como `description`, por ejemplo: *“Establece la descripción de la ruta Resultados operativos como …”*

Los asistentes usan la Guía para el prompt de dos maneras:

1. **Para elegir la ruta.** Cuando una pregunta no nombra una ruta, el asistente la compara con el nombre y la Guía para el prompt de cada ruta y elige la mejor coincidencia.
2. **Como guía permanente.** Una vez que ha elegido una ruta, el asistente aplica la Guía para el prompt a cada consulta sobre esa ruta: los filtros que debe incluir y la terminología que debe traducir. En un asistente conectado mediante MCP, las cifras de negocio provienen de las [definiciones de métricas](../metric-definitions/) del proyecto, no de la guía.

La Guía para el prompt se almacena con la ruta y es visible para todas las personas del espacio de trabajo que pueden ver las rutas de análisis. Llega a los asistentes que trabajan mediante MCP y a la IA integrada de PlaidCloud. No se transmite a la asistencia de IA dentro del paso LLM de un flujo de trabajo.

### Qué escribir

Incluya lo que habría que decirle a un analista nuevo en su primer día con esta tabla. Dé a cada directiva su propia línea.

| Escriba esto | Ejemplo |
|---|---|
| **Las preguntas que responde la ruta y las que no.** | *“Resultados operativos mensuales por unidad de negocio. Úsela para preguntas de ingresos, costo y EBITDA. No sirve para plantilla de personal ni pronósticos; use la ruta Pronóstico.”* |
| **A qué métrica corresponde una palabra del negocio**, para asistentes conectados mediante MCP. | *“‘Ingresos’ es la métrica Ingresos netos. `billed_amount` es facturación, no ingresos.”* |
| **Los filtros que siempre se aplican.** | *“Excluya siempre `scenario = 'Budget'` salvo que se pregunte por el presupuesto. Las filas entre empresas del grupo tienen `entity_type = 'IC'`; déjelas fuera de los totales.”* |
| **Convenciones de signo, calendario y granularidad.** | *“Los costos se almacenan como negativos. El año fiscal empieza en julio, así que el AF26 va de julio de 2025 a junio de 2026. Una fila por unidad de negocio y mes.”* |
| **Términos del negocio asignados a los datos.** | *“‘El Medio Oeste’ significa `region IN ('IL','IN','OH','MI')`. ‘Productos principales’ significa `product_tier = 'A'`.”* |

Sea breve y específico. Una directiva por línea es mejor que un párrafo, y el límite es de **1000 caracteres**. Se recortan los espacios iniciales y finales.

<Aside>
En un asistente conectado mediante MCP, la forma de calcular una cifra de negocio (qué columna, sumada cómo, sobre qué filas) corresponde a una [definición de métrica](../metric-definitions/), no a la Guía para el prompt. La guía indica qué filtros y términos se aplican a la ruta; una métrica indica qué es la cifra.
</Aside>

### Qué no escribir

- **Lo que los asistentes ya ven.** Los tipos de columna, las claves y los recuentos de filas se devuelven junto con la tabla. Repetirlos consume sus 1000 caracteres.
- **Lo que significa una columna.** Colóquelo en una [nota de columna](#agregar-notas-de-columna) para que permanezca con la columna, dondequiera que se use la tabla. La Guía para el prompt es para indicar cómo usar la ruta en su conjunto.
- **Nada confidencial.** La Guía para el prompt es visible en todo el espacio de trabajo, no solo para quienes tienen acceso al proyecto de la tabla. No incluya contraseñas ni claves, datos personales, ni cifras y comentarios que no mostraría a todos los miembros del espacio de trabajo.

### Guía para el prompt buena y deficiente

Los dos ejemplos siguientes son para la misma ruta y se hace la misma pregunta: *“¿Cuál fue el EBITDA del Medio Oeste el año pasado?”*

| | Guía deficiente | Guía buena |
|---|---|---|
| **Texto** | *“Datos operativos.”* | *“Resultados operativos mensuales por unidad de negocio.*<br />*EBITDA = `ebitda_adj`; ignore `ebitda`.*<br />*Excluya `scenario = 'Budget'` y las filas entre empresas del grupo (`entity_type = 'IC'`).*<br />*El año fiscal empieza en julio.*<br />*Medio Oeste = IL, IN, OH, MI.”* |
| **Qué hace el asistente** | Elige la columna `ebitda` simple, incluye las filas de presupuesto y de empresas del grupo, e interpreta “el año pasado” como el año natural. | Usa `ebitda_adj`, deja fuera las filas de presupuesto y de empresas del grupo, usa el último año fiscal completado y filtra por los cuatro estados del Medio Oeste. |
| **La respuesta** | Una cifra plausible, incorrecta y distinta de la del equipo de finanzas. | La cifra que informa el equipo de finanzas. |

La guía deficiente no es falsa. Simplemente deja cada decisión a la conjetura del asistente.

### Agregar notas de columna

La Guía para el prompt abarca la ruta en su conjunto. Una **nota de columna** explica una columna, y es como los asistentes aprenden qué contiene realmente. **Cuando el propósito de una columna no queda claro por su nombre, una nota marca la diferencia entre la columna correcta y una incorrecta pero plausible.**

Las notas de la tabla de la ruta se devuelven a los asistentes de IA junto con la lista de columnas, en `table_describe` con `include=['columns']`, como `memo` en cada columna que tiene una. Las columnas sin nota se devuelven como antes. Las mismas notas llegan a la asistencia de IA del paso LLM de un flujo de trabajo para las tablas que usa.

#### Cuándo se necesita una nota

| Agregue una nota para | Nota de ejemplo |
|---|---|
| **Códigos y abreviaturas** | `seg_cd`: *“Código de segmento de cliente: E = Empresa, M = Mediana empresa, S = Pyme.”* |
| **Medidas parecidas** | `ebitda_adj`: *“EBITDA tras eliminar las partidas excepcionales. Úselo para informes; `ebitda` no está ajustado.”* |
| **Indicadores** | `is_ic`: *“1 si la fila es una transacción entre empresas del grupo. Exclúyala de los totales consolidados.”* |
| **Unidades o moneda** | `amt_local`: *“Importe en la moneda local de la entidad, en miles.”* |
| **Valores derivados o asignados** | `alloc_cost`: *“Costo compartido asignado a esta unidad según la plantilla de personal. No se incurre directamente.”* |

Omita las columnas cuyo nombre lo dice todo, como `invoice_date` o `customer_name`. Una nota que repite el nombre no aporta nada.

#### Cómo agregar una nota

1. Abra la tabla de la ruta en el [Explorador de tablas](/es/guides/data/table-explorer/).
2. En la barra de herramientas, active **Propiedades de la columna**.
3. Seleccione la columna en la lista de columnas.
4. Escriba el texto en **Nota**.

Una nota definida en la tabla se aplica dondequiera que se use la tabla, incluida cada ruta de análisis que apunte a ella.

#### Guía para el prompt o nota

Ponga cada dato en un solo lugar.

| | Guía para el prompt | Nota de columna |
|---|---|---|
| **Abarca** | Cómo usar la ruta en su conjunto | Qué significa una columna |
| **Contenido típico** | Preguntas que responde, filtros permanentes, calendario fiscal, términos del negocio | Códigos, unidades, indicadores, cuál de las medidas parecidas usar |
| **Ejemplo** | *“Excluya las filas entre empresas del grupo de los totales.”* | `is_ic`: *“1 si la fila es entre empresas del grupo.”* |

Aquí la nota dice qué significa `is_ic`, y la Guía para el prompt dice qué hacer con ello.

<Aside>
Si su espacio de trabajo usa Microsoft 365 Copilot: una vez que su espacio de trabajo tenga esta versión, reinstale el paquete actualizado de Copilot para obtener las nuevas instrucciones. Consulte [Microsoft 365 Copilot](/es/integrations/microsoft-365-copilot/).
</Aside>

## Cómo usarlas

Una vez registradas sus rutas, simplemente pregunte:

<Steps>

1. **Por el nombre**: *“Muéstrame las primeras filas de los Resultados operativos.”*

2. **Por la predeterminada**: *“¿Qué cambió respecto del trimestre anterior?”* (sin nombrar ninguna tabla: usa la ruta predeterminada del espacio de trabajo).

3. **Cambie libremente**: *“Ahora haz lo mismo con el Pronóstico.”* El asistente le sigue, de una ruta a otra.

</Steps>

Esto se combina de forma natural con las preguntas sobre asignaciones (consulte [Rastreo de asignaciones](../tracing-allocations/)), de modo que pueda pasar de *“¿por qué se movieron los Resultados operativos?”* directamente a las cuentas y los inductores que hay detrás.

## Cómo usarlas mediante MCP

Cuando un asistente conectado mediante [MCP](../getting-started/) pasa una ruta de análisis a una herramienta, puede usar el **nombre** de la ruta (sin distinguir mayúsculas de minúsculas) o su **id**. Se rechaza una ruta actualizada con un id que no existe; para crear una ruta nueva, omita el id.

`query_data_read` acepta `analysis_path` en lugar de un proyecto y una tabla para `table`, `json_paths`, `dimension_value`, `column_values` y `aggregate`.

**Vista previa de solo algunas columnas.** Pase `columns=[...]` a `query_data_read(action='table')` para devolver únicamente las columnas que nombre. Las reglas de acceso a filas se siguen aplicando por completo. No se puede combinar con `version_id`.

**Obtenga un total filtrado en una sola llamada.** Pida a `column_values` la medida y filtre por la columna que le interese:

```
query_data_read(
  action='column_values',
  project_id=<project>,
  table_id=<table>,
  dimension_column_name=<filter column>,
  value_column_name=<measure>,
  filters={<filter column>: <value>}
)
```

Devuelve una fila para ese valor. Cuando el nombre de una columna está mal escrito, el error enumera hasta cinco coincidencias cercanas para que el asistente pueda corregirlo y reintentar.

**Totalice o desglose en una sola llamada.** Use `action='aggregate'` para agrupar por una o más columnas y totalizar, promediar o contar medidas en el servidor, en lugar de leer filas:

```
query_data_read(
  action='aggregate',
  project_id=<project>,
  table_id=<table>,
  group_by=['Product'],
  measures=[{'column': 'Revenue', 'agg': 'sum'}, {'column': 'Volume'}],
  filters={'Fiscal Year': 2027},
  order_by='Revenue',
  limit=10
)
```

`measures` acepta un `agg` de `sum` (el valor predeterminado), `avg`, `min`, `max` o `count`; `count` también acepta `'*'`. Un valor de `filters` puede ser una lista para coincidir con cualquiera de varios valores. `limit` es 50 de forma predeterminada y como máximo 500. `order_by` nombra una medida o una columna de agrupación; las medidas se ordenan de mayor a menor. La respuesta contiene `rows`, `total_groups` y `truncated`, que es verdadero cuando existen más grupos de los que devolvió `limit`. Las reglas de acceso a filas se aplican antes de calcular los totales.

## Quién puede configurarlas

La configuración de las rutas de análisis (registrarlas y elegir la predeterminada) es una acción de **administrador**, para que los nombres compartidos sigan siendo limpios y fiables para todos. Una vez que existen, cada miembro del espacio de trabajo puede usarlas en sus preguntas, viendo siempre únicamente los datos que le permiten sus propios permisos.
