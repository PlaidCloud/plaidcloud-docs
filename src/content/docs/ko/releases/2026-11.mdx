## 추가됨

- **Excel에서 PlaidXL로 작성, 드릴, 설명, 계획을 수행합니다.** **PlaidCloud** 리본 탭은 **연결**, **삽입**, **새로 고침**, **Drill**, **쓰기**, **공유**로 구성되어 있으며, 자주 쓰는 명령은 **PlaidXL** 마우스 오른쪽 클릭 메뉴와 **PlaidXL Cell** 탭에도 있고, 모든 명령에는 변경할 수 있는 키보드 단축키가 있습니다. 로그인하기 전에 실행한 명령은 로그인을 열고 로그인이 완료되면 실행되며, Office에서 Microsoft Entra 업무용 계정을 사용하면 PlaidXL이 워크스페이스를 자동으로 찾습니다. [PlaidXL 참조](/ko/reference/cli/plaidxl/)를 참조하십시오.
  - **몇 번의 클릭으로 보고서를 작성합니다.** **보고서** 탭은 테이블에서 라이브 보고서를 배치하며, 한 차원은 행으로, 다른 차원은 열로 드릴하고 모든 교차점에 `CELL` 값을 둡니다. **Build my first report**는 사용자의 데이터로 샘플을 만듭니다. 드릴하면 보고서가 행과 열 전체를 삽입하거나 제거하며, 입력한 값, 메모, 서식은 해당 행과 함께 유지됩니다. [보고서 작성](/ko/reference/cli/plaidxl/build-a-report/)을 참조하십시오.
  - **모든 셀에서 드릴합니다.** **Drill down**, **Drill up**, **Keep only**, **Remove only**는 노드, 차원 머리글 또는 보고서 값에서 노드를 라이브 `DRILL` 수식으로 바꾸고 실행 취소 가능한 한 단계로 편집합니다. **Custom drill**은 삽입하기 전에 행을 미리 보여 주며, 멤버 선택기는 멤버를 삽입하거나 노드의 하위 항목 드롭다운을 셀에 추가합니다. `DRILL`은 제외할 노드 또는 펼칠 노드를 받을 수 있고 행 방향으로도 실행할 수 있습니다. [드릴, 멤버 선택, 숫자 설명](/ko/reference/cli/plaidxl/drill/)을 참조하십시오.
  - **숫자를 설명합니다.** **Explain this number**는 값이 무엇을 계산하는지, 현재 PlaidCloud와 일치하는지, 값이 나온 테이블과 워크플로 단계를 보여 줍니다. **Show detail rows**는 값의 바탕이 되는 행을 별도의 시트에 넣고 합계가 맞는지 확인합니다.
  - **Excel의 관리되는 지표.** `PLAIDXL.METRIC`과 `PLAIDXL.METRIC_BREAKDOWN`은 대시보드에 표시되는 대로 비즈니스 지표를 반환하며, **Metric...** 버튼은 프로젝트의 지표를 현재 값과 함께 나열합니다. [지표](/ko/reference/cli/plaidxl/functions/#지표)를 참조하십시오.
  - **보고서에 직접 입력하여 계획합니다.** `CELL` 값 위에 숫자를 입력하면 PlaidCloud에 기록됩니다. 비례, 균등, 또는 다른 멤버의 형태대로 분산하거나, 금액이나 백분율로 조정할 수 있으며, 고정된 셀은 그대로 유지됩니다. 평균, 중앙값, 최솟값, 최댓값, 표준 편차, 분산 셀도 입력한 값을 받습니다. **Undo last write**는 입력한 값과 저장을 최신 항목부터 되돌립니다. [PlaidCloud에 값 입력](/ko/reference/cli/plaidxl/write-values/)을 참조하십시오.
  - **필요한 것만 새로 고칩니다.** 작업 창에 각 테이블의 진행 상황과 **취소**가 표시되는 상태로 시트, 선택 영역 또는 모든 테이블을 새로 고치거나, PlaidXL 수식만 다시 계산합니다. 가져온 테이블은 데이터 유형에 맞게 서식이 지정된 Excel 표로 들어오고, 새로 고칠 때 직접 추가한 열과 숫자 서식을 유지하며, 제자리에서 새로 고쳐집니다. 테이블을 다시 가져와도 새로 고침 목록에 두 번 추가되지 않고, **Stop refreshing**으로 하나를 목록에서 제거할 수 있으며, 차원은 테이블과 함께 새로 고쳐집니다. [모든 테이블 새로 고침](/ko/reference/cli/plaidxl/retrieve/#모든-테이블-새로-고침)을 참조하십시오.
  - **저장은 즉시 기록되며 실행 취소할 수 있습니다.** **Save to PlaidCloud**는 확인 없이 기록하고, 수행한 작업을 알려 주고, **실행 취소**를 제공합니다. 필터와 함께 가져온 시트, 상세 행 시트, 또는 일부 행에만 액세스할 수 있는 사용자는 해당 행만 교체하므로 다른 사용자의 행은 유지됩니다. [테이블을 PlaidCloud에 저장](/ko/reference/cli/plaidxl/retrieve/#테이블을-plaidcloud에-저장)을 참조하십시오.
  - **Excel에서 Weave에 문의합니다.** **Weave** 탭에서 보고서, 수식, 드릴 또는 테이블을 일상적인 말로 요청하거나 **Ask Weave about this cell**을 선택합니다. Weave는 사용자 본인으로 PlaidCloud를 읽고 통합 문서만 변경하며, 사용자가 입력한 내용을 교체하기 전에 확인하고, 모든 변경을 되돌릴 수 있습니다. [Excel에서 Weave에 문의](/ko/reference/cli/plaidxl/weave/)를 참조하십시오.
  - **한 시트 또는 통합 문서 전체의 값 전용 사본을 공유합니다.** **Convert to values**는 통합 문서 전체, 한 시트 또는 되돌릴 방법이 없는 값으로 변환하며, 시트 이름을 바꿔도 **Restore PlaidXL formulas**는 계속 작동합니다.
- **단계 양식의 미리 보기.** 가져오기: SQL, Execute: SQL, SQL 추출, 내보내기: SQL, Salesforce: 개체 쿼리 단계는 단계를 실행하지 않고도 최대 100행을 표시하며, Anaplan 뷰 읽기와 목록 읽기는 생성될 열과 유형을 표시합니다. **소스** 탭에서 **미리 보기**를 클릭합니다. 변수는 실행 시 채워지는 것과 같이 채워지지만 `{x:>9}` 같은 변수 형식은 지원되지 않습니다. 미리 보기는 표준 SQL 함수만 실행하며, 그렇지 않으면 단계를 실행하라고 안내합니다. 잠긴 프로젝트나 에이전트 기반 Execute SQL 단계에서는 사용할 수 없습니다. [SQL 가져오기](/ko/reference/workflow-steps/import/import-sql/)와 [SQL 추출](/ko/reference/workflow-steps/tables/table-extract-sql/)을 참조하십시오.
- **AI 어시스턴트가 테이블 게시를 취소하고 프로젝트의 기본 대시보드 대상을 설정할 수 있습니다.** `publish_manage`는 테이블과 함께 게시된 뷰, 그리고 차트에서 사용하지 않는 대시보드 데이터 세트의 게시를 취소합니다. 차트가 여전히 사용하는 데이터 세트는 유지되며, 보고서 뷰가 게시된 뷰를 기반으로 만들어진 경우 해당 뷰와 데이터 세트도 유지되지만 테이블의 게시는 취소됩니다. `project_upsert`는 프로젝트의 새 대시보드를 공유할 그룹인 `dashboard_default_audience`를 설정하며, `[]`는 이를 지웁니다. [게시 취소](/ko/guides/data/publish/#ai-어시스턴트-또는-mcp로-게시-취소)와 [AI 어시스턴트 또는 MCP로 기본 대상 설정](/ko/guides/dashboards/control-who-can-see-a-dashboard/#ai-어시스턴트-또는-mcp로-기본-대상-설정)을 참조하십시오.

- **모바일 Weave의 음성은 한 번의 탭으로 사용합니다.** 마이크를 탭하고 질문하면, 말을 멈춘 후 Weave가 전송합니다. 마이크를 다시 탭하면 일찍 중지되며, 아무 소리도 들리지 않으면 자동으로 꺼집니다. 문장 도중에 **Weave** 탭을 떠나거나 앱을 백그라운드로 보내면, 입력한 말이 전송되지 않은 채 질문 상자에 남아 검토할 수 있습니다. 실행, 일시 중지, 중지, 재개는 확인 시 실수로 두 번 탭해도 무시합니다. 앱 버전 1.3.0 이상이 필요합니다. [음성 사용](/ko/guides/mobile-app/weave-on-mobile/#음성-사용)을 참조하십시오.

## 변경됨

- **단계 양식이 하나의 레이아웃을 따릅니다.** 탭은 일반, 설정, 소스, 열, 필터, 출력, 고급의 표준 이름과 표준 순서를 사용하며, ERP 전기 양식에는 헤더 열과 라인 열이 추가됩니다. 필수 필드는 *로 표시되며, 양식은 단계에 필요한 항목에 대해서만 저장을 차단합니다.
- **프로젝트 복사는 테이블 데이터와 차원 멤버를 따로 선택하고, 데이터를 더 빠르게 복사하며, 비공개 사본의 ERP 쓰기 승인을 유지합니다.** **Data to copy**에서 **테이블 데이터**(**테이블 데이터 없음**(기본값), **전체** 또는 **샘플**)를 선택하고, 별도로 기본적으로 켜져 있는 **Copy dimension members**를 선택합니다. 따라서 테이블 행이 없는 사본도 채워진 차원과 함께 생성되며 빠르게 만들 수 있습니다. **전체** 및 **샘플** 복사는 여러 테이블을 동시에 복사하므로 테이블이 많은 프로젝트도 더 빨리 끝납니다. **복사 결과**는 테이블과 함께 각 차원의 결과를 나열하고, **Retry failed items**는 실패한 테이블과 차원을 함께 다시 시도합니다. 데이터와 함께 만든 새 사본은 사용자만 볼 수 있는 비공개이며, 사용자가 직접 부여할 수 있는 소스의 ERP 쓰기 승인을 유지합니다. 소스가 라이브로 전기하는 경우 사본은 시뮬레이션으로 도착하므로, 라이브로 전환하기 전에는 ERP에 아무것도 전달되지 않습니다. REST API와 `project_copy` MCP 도구도 `dimension_members`를 받습니다. [복사할 데이터 양 선택](/ko/guides/projects/managing-projects/#복사할-데이터-양-선택)과 [사본의 ERP 쓰기 승인](/ko/guides/projects/managing-projects/#복사본의-erp-쓰기-승인)을 참조하십시오.
- **행 작업 메뉴(⋯)가 모든 그리드 행의 왼쪽 가장자리에 있습니다.**
- **검증 설정이 없는 저장된 ERP 쓰기 단계는 검증 전용으로 열립니다.** SAP Post, SAP Attach, NetSuite Post, Oracle EBS GL 및 AP Post, Xero 내보내기가 해당됩니다. 라이브로 실행하도록 명시적으로 설정된 단계는 라이브로 유지됩니다.
- **오래 실행되는 작업은 모든 곳에서 같은 방식으로 진행 상황을 표시합니다.**
- **워크플로를 중지해도 이후 가져오기가 지연되지 않으며, 시작되지 않는 단계는 멈춰 있는 대신 실패합니다.** 중지하면 대기 중이던 가져오기와 차원 단계가 취소되므로, 워크스페이스의 이후 가져오기와 차원 로드가 정상적으로 시작됩니다. 약 40분 안에 어떤 워커도 단계의 작업을 시작하지 않거나, 워커가 시작한 후 사라진 경우, 단계는 24시간 시간 초과까지 실행 중으로 표시되는 대신 그 사실을 알리는 메시지와 함께 실패하며 **여기서부터 실행**을 안내합니다. [워크플로 실행](/ko/guides/workflows/run-a-workflow/#시작되지-않는-단계)을 참조하십시오.
- **워크스페이스를 업그레이드하면 REST, REST 가져오기, Postman 가져오기 단계가 REST 요청으로 변환됩니다.** 깔끔하게 변환할 수 없는 단계는 그대로 유지됩니다. [REST 요청 단계](/ko/guides/workflows/rest-request-step/)를 참조하십시오.
- **프로젝트 아키텍트는 대시보드에서 행이 제한된 테이블의 모든 행을 볼 수 있으며**, Analyze에서 보는 것과 같습니다. 아키텍트 액세스를 제거하면 대시보드에서 즉시 적용됩니다. 누군가의 역할을 변경하거나, 해당 사용자 또는 그룹을 프로젝트에서 제거하거나, 프로젝트의 액세스 유형을 변경하거나, 이전 프로젝트 버전을 복원하거나, 보안 그룹을 삭제하는 경우가 모두 해당됩니다. 이전 아키텍트는 더 이상 행이 제한된 데이터의 모든 행을 보지 못합니다. [행 액세스 관리](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리)를 참조하십시오.
- **세션이 만료된 후 연 대시보드 링크는 로그인하면 해당 대시보드로 이동합니다.** [대시보드 사용](/ko/guides/dashboards/using-dashboards/)을 참조하십시오.
- **MCP 도구는 인식하지 못하는 필드를 무시하는 대신 거부하고** 오류에 해당 필드 이름을 표시합니다. `workflow_upsert`는 `memo`를 받으며 `description`을 다른 이름으로 받습니다. [알 수 없는 필드는 거부됩니다](/ko/integrations/ai-coding-agents/getting-started/#알-수-없는-필드는-거부됩니다)를 참조하십시오.
- **Lakehouse v2에서는 lakehouse가 Parquet 내보내기를 Google Cloud Storage에 직접 기록합니다.** Google Cloud Storage 문서 계정으로 내보내면 모든 행이 먼저 PlaidCloud를 거치는 대신, 계정 자체의 자격 증명으로 계정의 버킷에 바로 기록됩니다. Amazon S3 및 Azure Blob Storage 계정으로의 내보내기는 이전과 같이 작동합니다. [Export to Parquet 단계](/ko/reference/workflow-steps/export/export-to-parquet/)를 참조하십시오.
- **Slack, Microsoft Teams, Web Hook 단계가 메시지가 전송되지 않은 이유를 알려 줍니다.** 단계 오류에는 연결을 시도한 서버와, Slack 및 Teams의 경우 연결이 표시되며 무엇이 잘못되었는지 알려 줍니다. 예를 들어 Slack이 더 이상 웹훅을 인식하지 못함, 채널에 게시할 수 없음, 서버를 찾을 수 없거나 60초 안에 응답하지 않음, 연결이 삭제됨 등입니다. 웹훅 URL을 가진 사람은 누구나 사용자의 통합으로 게시할 수 있으므로 Slack 또는 Teams 웹훅 URL은 절대 표시되지 않습니다. [Notify via Slack 단계](/ko/reference/workflow-steps/notifications/notify-via-slack/)를 참조하십시오.

## 수정됨

- **잘못된 프로젝트 설정이 명확한 메시지로 보고됩니다.** 알 수 없는 환경이나 문서 계정, 이미 사용 중이거나 예약된 슬러그, 잘못된 스토리지 유형이나 전기 모드가 이제 일반적인 서버 오류 대신 문제를 명시한 메시지를 반환합니다. REST API에서는 500이 아닌 400이며, AI 어시스턴트 또는 MCP에서는 잘못된 인수 오류입니다.
- **REST API의 차원 값 요청이 작동합니다.** `POST /rest/v1/analyze/query/retrieve-dimension-values`가 그리드 요청으로 처리되어 잘못된 요청으로 거부되었습니다. 이제 `value_columns`의 각 열에 대해 집계된 값 하나를 반환하며, 행 필터와 열 필터의 각 쌍마다 값 하나를 반환하는 그리드는 별도의 `POST /rest/v1/analyze/query/retrieve-dimension-cells`를 사용합니다.
- **느린 테이블 읽기와 파일 처리가 더 이상 다른 요청을 지연시키지 않습니다.** 웨어하우스에서 테이블의 열 읽기, Data Foundation 파일 등록, Excel로 내보내기, REST 또는 SOAP 가져오기의 응답 읽기, 문서 계정이 사용되는 위치 찾기, Panel 앱의 코드 또는 로고 확인이 각각 끝날 때까지 같은 서버가 처리하던 다른 모든 요청을 멈추게 할 수 있었습니다. 이제 이들은 다른 요청과 나란히 실행됩니다.
- **프로젝트 및 워크플로 변수 대화 상자가 스크롤됩니다.** 작은 화면이나 낮은 해상도에서 추가 및 편집 대화 상자가 창보다 커서 **만들기**와 **업데이트** 버튼에 닿지 못할 수 있었습니다. 이제 양식이 스크롤되고 버튼은 아래쪽에 유지됩니다.
- **Azure Blob Storage 문서 계정에서 256 MiB를 초과하는 파일을 복사, 이동, 이름 변경할 수 있습니다.** 이전에는 해당 크기의 파일에서 각 작업이 실패했으며, 그런 파일이 들어 있는 폴더를 이동하거나 이름을 변경하는 경우도 실패했습니다.
- **Lakehouse v2에서 테이블의 행 수가 방금 기록한 내용을 반영합니다.** 테이블을 기록한 단계나 가져오기가 기록 이전의 행 수를 저장할 수 있어서, 방금 로드한 테이블이 0행으로 표시되고 가져오기가 0행을 가져왔다고 보고할 수 있었습니다. 이제 새 행이 모든 곳에서 보이게 된 후에 개수를 읽으므로 이후 단계도 해당 행을 읽습니다. 테이블을 다른 브랜치로 전환하거나 브랜치를 병합할 때도 행 수와 열 수가 업데이트됩니다.
- **Weave의 빈 값 검사는 각 실행을 이전 실행이 실제로 남긴 값과 비교합니다.** 단계의 빈 값이 테이블을 다시 채우기 위해 비운 직후에 집계되는 경우가 많아, 이전 실행에는 빈 값이 없었던 것처럼 보이고 항상 일부가 비어 있던 열이 방금 그렇게 된 것처럼 보고되었습니다. 이제 각 실행은 단계가 테이블을 남긴 상태 그대로 집계됩니다. 이전에 기록된 개수는 올바른 값과 구별할 수 없으므로 사용되지 않습니다. 각 단계의 빈 값 검사는 기록을 처음부터 다시 시작하며, 다섯 번의 실행이 집계될 때까지 검사되지 않음으로 보고됩니다. 행 수 및 값 분포 검사도 단계가 끝난 후 2초가 넘어 다른 단계가 같은 테이블에 기록한 내용을 해당 단계의 기록으로 인정하지 않습니다. [Weave 점검 항목](/ko/guides/ai-assistant/weave-findings/)을 참조하십시오.
- **삭제된 연결을 REST API에 요청하면 404를 반환합니다.** 삭제된 연결이나 존재하지 않는 ID를 요청하면 일반적인 서버 오류(500)로 응답했습니다. 이제 연결 ID를 명시한 메시지와 함께 404를 반환합니다.

## 보안

- **계정의 소유자만 이전 버전을 복원할 수 있습니다.** 문서 계정을 이전 버전으로 복원하거나, 버전을 고정하거나 해제하거나, 백업을 만들려면 이제 계정의 소유자 중 한 명이어야 하며, 시스템에서 관리하는 계정에서는 이 중 어느 것도 사용할 수 없습니다. 계정의 버전 기록을 보려면 계정에 대한 액세스가 필요합니다.
