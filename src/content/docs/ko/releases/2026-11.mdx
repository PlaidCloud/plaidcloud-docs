## 추가됨

- **PlaidXL이 Excel에서 보고서를 만들고, 드릴하고, 숫자를 설명하고, 계획합니다.** **PlaidCloud** 리본 탭은 **연결**, **삽입**, **새로 고침**, **Drill**, **쓰기**, **공유**로 나뉘어 있으며, 자주 쓰는 명령은 **PlaidXL** 오른쪽 클릭 메뉴와 **PlaidXL Cell** 탭에도 있고, 주요 명령에는 변경할 수 있는 키보드 단축키가 있습니다. 로그인하기 전에 실행한 명령은 로그인 창을 열고 로그인이 끝나면 한 번 실행되며, Office에서 Microsoft Entra 회사 계정을 사용하면 PlaidXL이 워크스페이스를 대신 찾아 줍니다. [PlaidXL 참조](/ko/reference/cli/plaidxl/)를 참조하십시오.
  - **몇 번의 클릭으로 보고서 만들기.** **보고서** 탭은 테이블에서 실시간 보고서를 구성합니다. 한 차원은 행 방향으로, 다른 차원은 열 방향으로 드릴 다운되고, 교차 지점마다 `CELL` 값이 들어갑니다. **Build my first report**는 내 데이터로 샘플을 만듭니다. 드릴하면 보고서가 행과 열 전체를 삽입하거나 제거하며, 직접 입력한 값, 메모, 서식은 해당 행을 따라갑니다. [보고서 만들기](/ko/reference/cli/plaidxl/build-a-report/)를 참조하십시오.
  - **어느 셀에서나 드릴하기.** **Drill down**, **Drill up**, **Keep only**, **Remove only**는 노드, 차원 제목, 보고서 값에서 노드를 실시간 `DRILL` 수식으로 바꾸고 수식을 대신 편집해 줍니다. **Custom drill**은 행을 삽입하기 전에 미리 보여 주며, 멤버 선택기는 멤버를 삽입하거나 노드의 하위 항목 드롭다운을 셀에 추가합니다. `DRILL`은 제외하거나 펼칠 노드를 받을 수 있고 행 전체에 걸쳐 실행할 수도 있습니다. [드릴, 멤버 선택, 숫자 설명](/ko/reference/cli/plaidxl/drill/)을 참조하십시오.
  - **숫자 설명하기.** **Explain this number**는 값이 어떻게 계산되는지, 현재 PlaidCloud와 일치하는지, 그리고 값이 나온 테이블과 워크플로 단계를 보여 줍니다. **Show detail rows**는 값의 근거가 되는 행을 별도의 시트에 넣고 합계가 맞는지 검사합니다.
  - **Excel의 거버넌스 지표.** `PLAIDXL.METRIC`과 `PLAIDXL.METRIC_BREAKDOWN`은 대시보드에 표시되는 방식 그대로 비즈니스 지표를 반환하며, **Metric...** 명령은 프로젝트의 지표와 현재 값을 나열합니다. [지표](/ko/reference/cli/plaidxl/functions/#지표)를 참조하십시오.
  - **보고서에 직접 입력하여 계획하기.** `CELL` 값 위에 숫자를 입력하면 PlaidCloud에 기록됩니다. 비례 배분, 균등 배분, 다른 멤버의 분포에 맞춘 배분, 금액 또는 백분율 조정을 사용할 수 있으며 고정한 셀은 그대로 유지됩니다. 평균, 중앙값, 최솟값, 최댓값, 표준 편차, 분산 셀에도 입력한 값을 사용할 수 있습니다. **Undo last write**는 입력한 값과 저장 내용을 최신 순으로 되돌립니다. [PlaidCloud에 값 입력하기](/ko/reference/cli/plaidxl/write-values/)를 참조하십시오.
  - **필요한 것만 새로 고치기.** 시트, 선택 영역 또는 모든 테이블을 새로 고칠 수 있으며, 작업 창에 각 테이블의 진행 상황과 **취소**가 표시됩니다. PlaidXL 수식만 다시 계산할 수도 있습니다. 가져온 테이블은 데이터 형식에 맞게 서식이 적용된 Excel 테이블로 들어오고, 새로 고쳐도 직접 추가한 열과 숫자 서식이 유지되며, 원래 위치에서 새로 고쳐집니다. 테이블을 다시 가져와도 새로 고침 목록에 두 번 추가되지 않고, **Stop refreshing**으로 하나를 목록에서 뺄 수 있으며, 차원은 테이블과 함께 새로 고쳐집니다. [모든 테이블 새로 고치기](/ko/reference/cli/plaidxl/retrieve/#모든-테이블-새로-고침)를 참조하십시오.
  - **저장은 즉시 기록되며 되돌릴 수 있습니다.** **Save to PlaidCloud**는 확인 없이 기록하고, 무엇을 했는지 알려 주며, **실행 취소**를 제공합니다. 필터를 적용해 가져온 시트, 상세 행 시트, 또는 일부 행에만 액세스 권한이 있는 사용자의 시트는 해당 행만 바꾸므로 다른 사람의 행은 유지됩니다. [PlaidCloud에 테이블 저장하기](/ko/reference/cli/plaidxl/retrieve/#테이블을-plaidcloud에-저장)를 참조하십시오.
  - **Excel에서 Weave에 묻기.** **Weave** 탭에서 보고서, 수식, 드릴, 테이블을 일상적인 말로 요청하거나 **Ask Weave about this cell**을 선택합니다. Weave는 내 권한으로 PlaidCloud를 읽고 통합 문서만 변경하며, 내가 입력한 내용을 바꾸기 전에 먼저 묻고, 창을 다시 불러오기 전까지는 각 변경을 되돌릴 수 있습니다. [Excel에서 Weave에 묻기](/ko/reference/cli/plaidxl/weave/)를 참조하십시오.
  - **시트 하나 또는 통합 문서 전체의 값 전용 사본 공유하기.** **Convert to values**는 통합 문서 전체, 시트 하나, 또는 되돌릴 수 없는 값으로 변환하며, 시트 이름을 바꾼 후에도 **Restore PlaidXL formulas**가 계속 작동합니다.
- **단계 양식에서 미리 보기.** 가져오기: SQL, Execute: SQL, SQL 추출, 내보내기: SQL, Salesforce: 개체 쿼리 단계는 단계를 실행하지 않고도 최대 100개 행을 보여 주며, Anaplan 뷰 및 목록 읽기는 생성될 열과 유형을 보여 줍니다. **소스** 탭에서 **미리 보기**를 클릭합니다. 변수는 실행할 때와 같은 방식으로 채워지지만 `{x:>9}` 같은 변수 형식은 지원되지 않습니다. 미리 보기는 표준 SQL 함수만 실행하며, 그렇지 않으면 단계를 실행하라는 안내가 나옵니다. 잠긴 프로젝트나 에이전트 기반 Execute SQL 단계에서는 사용할 수 없습니다. [SQL 가져오기](/ko/reference/workflow-steps/import/import-sql/)와 [SQL 추출](/ko/reference/workflow-steps/tables/table-extract-sql/)을 참조하십시오.
- **사용 현황 보고서는 변경된 내용을 보여 주고, 그룹으로 범위를 좁히고, 워크플로로 이어집니다.** **개요**에는 이전 기간 대비 추세 화살표와, 비활성 멤버 및 아무도 열지 않은 대시보드와 앱을 알려 주는 **Highlights** 목록이 추가됩니다. **그룹**은 **개요**, **내용**, 비활성 목록을 하나의 보안 그룹 멤버로 한정하며, 날짜 범위에는 **Previous month**와 **This month**가 추가되고 모든 탭이 이를 공유하며 계정에 기억됩니다. 이제 모든 수치에 설명이 있고, 테이블에는 **멤버**와 **Area** 같은 쉬운 이름이 사용되며, 행은 Enter 키로 열리고, 로딩과 오류 표시가 더 명확해졌으며, 마지막 **퍼널** 단계에는 해당 단계를 완료한 멤버 수가 표시됩니다. 새로운 **Get Workspace Usage** 단계는 멤버 이름 없이 일별 또는 월별 사용량 합계를 일정에 따라 테이블에 기록하며, **Get Workspace Members**와 마찬가지로 각 실행이 **보안 로그**에 기록됩니다. [사용 현황 보고서](/ko/administration/access/usage-reports/)와 [Get Workspace Usage](/ko/reference/workflow-steps/general/get-workspace-usage/)를 참조하십시오.
- **AI 어시스턴트가 테이블 게시를 취소하고 프로젝트의 기본 대시보드 대상을 설정할 수 있습니다.** `publish_manage`는 테이블의 게시를 취소하면서 게시된 뷰와, 어떤 차트에서도 사용하지 않는 대시보드 데이터 세트도 함께 제거합니다. 차트가 아직 사용하는 데이터 세트는 남으며, 게시된 뷰를 기반으로 보고서 뷰가 만들어진 경우에는 뷰와 데이터 세트도 남지만 테이블의 게시는 취소됩니다. `project_upsert`는 프로젝트의 새 대시보드를 공유할 그룹인 `dashboard_default_audience`를 설정하며, `[]`는 이 설정을 지웁니다. [게시 취소](/ko/guides/data/publish/#ai-어시스턴트-또는-mcp로-게시-취소)와 [AI 어시스턴트 또는 MCP로 기본 대상 설정하기](/ko/guides/dashboards/control-who-can-see-a-dashboard/#ai-어시스턴트-또는-mcp로-기본-대상-설정)를 참조하십시오.

- **Git 앱이 리포지토리를 나열하고 내가 할 수 있는 일을 알려 줍니다.** 앱 목록의 **Git**에는 내 역할(**Administrator**, **Contributor** 또는 **뷰어**)과 워크스페이스의 리포지토리가 표시되며, 각 리포지토리에는 설명, 마지막 업데이트 날짜, 복사 버튼이 있는 클론 주소, **열기**가 있습니다. **Set up Git on your computer** 카드는 Git 설치, 토큰 생성, 클론 과정을 안내하며 **How to clone**으로 다시 열 수 있습니다. **View all in Git**은 전체 Git 인터페이스를 열고 **Manage who can push**는 그룹 관리를 엽니다. 액세스 수준은 **뷰어**, **Contributor**(`apps`에 앱 코드 푸시), **Administrator**(`udfs`를 포함한 모든 곳에 푸시)이며, 뷰어에게는 요청할 수 있는 워크스페이스 관리자가 최대 세 명까지 표시됩니다. 새로운 **Git Contributors** 그룹은 Contributor 수준을 부여하며 기본 그룹으로 지정할 수 있어 신규 멤버가 자동으로 받게 할 수 있고, **Git Administration**은 Administrator 수준을 부여합니다. 멤버의 **Git** 탭에는 Git 사용자 이름, 수준, 이를 부여하는 그룹이 표시됩니다. 앱 창에는 **Repository** 섹션이 표시되고 UDF에는 **열기**가 있으며, Git에는 **← Back to** your workspace 링크가 있습니다. [PlaidCloud Git](/ko/guides/git/#git-열기)을 참조하십시오.
- **모바일 Weave의 음성 입력은 한 번만 탭하면 됩니다.** 마이크를 탭하고 질문을 말하면 말을 멈추는 즉시 Weave가 한 번 전송합니다. 일찍 멈추려면 마이크를 다시 탭하며, 아무 소리도 들리지 않으면 자동으로 꺼집니다. 말하는 도중에 **Weave** 탭을 떠나거나 앱을 백그라운드로 보내면 입력한 내용이 전송되지 않은 채 질문 상자에 남아 있어 검토할 수 있습니다. 실행, 일시 중지, 중지, 재개의 확인 단계에서는 실수로 두 번 탭해도 무시됩니다. 앱 버전 1.3.0 이상이 필요합니다. [음성 사용하기](/ko/guides/mobile-app/weave-on-mobile/#음성-사용)를 참조하십시오.

## 변경됨

- **단계 양식이 하나의 레이아웃을 따릅니다.** 탭 이름과 순서가 표준화되어 일반, 설정, 소스, 열, 필터, 출력, 고급 순서이며, ERP 전기 양식에는 헤더 열과 라인 열이 추가됩니다. 필수 필드에는 *가 표시되고, 양식은 단계에 필요한 항목에 대해서만 저장을 막습니다.
- **프로젝트 복사는 테이블 데이터와 차원 멤버를 따로 선택하고, 데이터를 더 빠르게 복사하며, 비공개 사본의 ERP 쓰기 승인을 유지합니다.** **Data to copy** 아래에서 **테이블 데이터**(**테이블 데이터 없음**(기본값), **전체** 또는 **샘플**)를 선택하고, 이와 별도로 기본적으로 켜져 있는 **Copy dimension members**를 선택합니다. 따라서 테이블 행 없이 복사해도 채워진 차원이 함께 들어오며 복사본을 빠르게 만들 수 있습니다. **전체** 및 **샘플** 복사는 여러 테이블을 동시에 복사하므로 테이블이 많은 프로젝트도 더 빨리 끝납니다. **복사 결과**에는 테이블과 함께 각 차원의 결과가 나열되고, **Retry failed items**는 실패한 테이블과 차원을 함께 다시 시도합니다. 데이터와 함께 만든 새 복사본은 나만 사용할 수 있으며, 소스에서 내가 직접 부여할 수 있는 ERP 쓰기 승인을 유지합니다. 소스가 Live로 전기하는 경우 복사본은 Simulate로 들어오므로, Live로 전환하기 전에는 ERP에 아무것도 반영되지 않습니다. REST API와 `project_copy` MCP 도구도 `dimension_members`를 받습니다. [복사할 데이터의 양 선택하기](/ko/guides/projects/managing-projects/#복사할-데이터-양-선택)와 [복사본의 ERP 쓰기 승인](/ko/guides/projects/managing-projects/#복사본의-erp-쓰기-승인)을 참조하십시오.
- **행 작업 메뉴(⋯)가 모든 그리드 행의 왼쪽 가장자리에 있습니다.**
- **앱 탭 아이콘이 라이트 및 다크 모드에서 일관된 하나의 세트로 통일되었습니다.**
- **검증 설정이 없는 저장된 ERP 쓰기 단계는 검증 전용으로 열립니다.** SAP Post, SAP Attach, NetSuite Post, Oracle EBS GL 및 AP Post, Xero 내보내기가 해당됩니다. 명시적으로 실시간 실행으로 설정한 단계는 그대로 실시간으로 유지됩니다.
- **오래 걸리는 작업의 진행 상황이 모든 곳에서 같은 방식으로 표시됩니다.**
- **워크플로를 중지하면 워크플로가 시작한 모든 것이 중지되고, 끝낼 수 없는 실행이나 단계는 멈춰 있지 않고 실패합니다.** 중지하면 아직 대기 중이던 가져오기 및 차원 단계가 취소되므로 워크스페이스의 이후 가져오기와 차원 로드가 정상적으로 시작되며, 워크플로의 대기 중이거나 실행 중인 커넥터(Singer) 동기화도 중지됩니다. 단계의 작업을 시작할 수 없으면 단계가 무한정 기다리지 않고 이유와 함께 실패합니다. 약 40분 안에 어떤 작업자도 시작하지 않은 경우, 작업자가 시작한 뒤 사라진 경우, 포드가 약 20분 동안 Pending 상태로 멈춘 경우, 이미지를 약 5분 동안 가져올 수 없는 경우, 약 20분 동안 포드가 만들어지지 않는 경우가 이에 해당합니다. 약 30분 안에 어떤 러너도 가져가지 않은 커넥터 동기화는 해당 동기화 이름이 포함된 메시지와 함께 실패합니다. 단계가 작업자를 기다리는 동안 상태 메시지에 "작업자를 기다리는 중…"과 지금까지 경과한 시간(분)이 표시되며, 작업이 시작되면 사라집니다. 매크로를 중지하면 실행 중인 모든 사본이 중지되고, 다른 워크플로 안에서만 실행 중인 매크로는 워크플로 목록에 **실행 중**으로 표시되며 **중지**를 사용할 수 있고 각 단계의 상태, 시작 시간, 종료 시간은 최근 실행을 기준으로 표시됩니다. 서버를 잃은 실행은 실패로 끝나며, 12시간이 지나도 계속 실행 중인 실행은 "실행 실패: 12시간 제한까지 계속 실행 중입니다. 워크플로를 다시 실행하십시오."라는 메시지와 함께 실패합니다. [워크플로 실행하기](/ko/guides/workflows/run-a-workflow/#시작되지-않는-단계)를 참조하십시오.
- **재개, 실행 기록, 실행 상태가 실제로 실행된 내용과 일치합니다.** 상위 워크플로를 재개하면, 하위 워크플로의 단계 하나를 따로 다시 실행한 경우에도 하위 워크플로에 남아 있던 모든 것이 실행되며, 한 번의 실행 안에서 하위 워크플로를 호출할 때마다 각각 실행 기록 항목이 생깁니다. 서버가 중지되어 다시 시작되는 단계는 로그에 그렇게 표시되며, `workflow_run_status`와 REST API의 실행 결과는 실패했지만 계속 진행된 단계를 `continued_step_ids`와 `continued_step_count`에 나열하여 실행을 정상으로 보고하지 않습니다. [일시 중지, 중지, 재개](/ko/guides/workflows/run-a-workflow/#일시-중지-중지-재개)와 [오류 시 계속](/ko/guides/workflows/continue-on-error/)을 참조하십시오.
- **단계 오류에 고유한 메시지가 표시됩니다.** PlaidCloud가 예상하지 못한 오류는 "단계가 예기치 않은 오류(*유형*)로 중지되었습니다: *메시지*"로 표시됩니다. 런처의 **조치 필요** 카드에는 오류가 한 줄로 표시되며, 이후 삭제된 워크플로의 실행은 제외됩니다. [단계 오류 관리하기](/ko/guides/workflows/managing-step-errors/)를 참조하십시오.
- **ERP 추출이 끝나지 않으면 단계가 실패하고, 재개하면 이어서 진행됩니다.** **SAP: 임시 추출**이 행 또는 시간 제한에서 멈추거나 에이전트가 제때 응답하지 않는 경우, 또는 Salesforce, Oracle Fusion 대량 추출, HFM/FCCS 내보내기 작업이 단계가 기다리기를 멈출 때까지도 실행 중인 경우, 단계는 실패하여 이후 단계가 일부만 채워진 테이블에서 실행되지 않습니다. 워크플로를 재개하거나 단계를 다시 실행하면 같은 작업에서 중단된 지점부터 추출이 이어집니다. [실행 제한](/ko/guides/connections/sap-adhoc-extract/#실행-제한)과 [Salesforce: 개체 쿼리](/ko/reference/workflow-steps/salesforce/query-salesforce-object/#실행이-끝나지-않는-경우)를 참조하십시오.
- **REST, REST 가져오기, Postman 가져오기 단계는 워크스페이스를 업그레이드할 때 REST 요청 단계로 변환됩니다.** 깔끔하게 변환할 수 없는 단계는 그대로 유지됩니다. [REST 요청 단계](/ko/guides/workflows/rest-request-step/)를 참조하십시오.
- **프로젝트 아키텍트는 대시보드에서 행 제한 테이블의 모든 행을 볼 수 있으며**, 이는 Analyze에서 보는 내용과 같습니다. 아키텍트 액세스를 제거하면 대시보드에 즉시 반영됩니다. 누군가의 역할을 변경하거나, 프로젝트에서 그 사용자나 그룹을 제거하거나, 프로젝트의 액세스 유형을 변경하거나, 이전 프로젝트 버전을 복원하거나, 보안 그룹을 삭제하는 경우가 모두 해당합니다. 이전에 아키텍트였던 사용자는 더 이상 행 제한 데이터의 모든 행을 볼 수 없습니다. [행 액세스 관리하기](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리)를 참조하십시오.
- **세션이 만료된 후 연 대시보드 링크는 로그인하면 해당 대시보드로 이동합니다.** [대시보드 사용하기](/ko/guides/dashboards/using-dashboards/)를 참조하십시오.
- **MCP 도구는 인식하지 못하는 필드를 무시하는 대신 거부하며** 오류에 해당 필드를 표시합니다. `workflow_upsert`는 `memo`를 받으며 `description`도 같은 필드의 다른 이름으로 허용합니다. [알 수 없는 필드는 거부됩니다](/ko/integrations/ai-coding-agents/getting-started/#알-수-없는-필드는-거부됩니다)를 참조하십시오.
- **Lakehouse v2에서는 Lakehouse가 Parquet 내보내기를 Google Cloud Storage에 직접 기록합니다.** Google Cloud Storage 문서 계정으로의 내보내기는 모든 행이 PlaidCloud를 거치는 대신, 해당 계정 자체의 자격 증명으로 계정의 버킷에 바로 기록됩니다. Amazon S3 및 Azure Blob Storage 계정으로의 내보내기는 이전과 같이 작동합니다. [Parquet로 내보내기](/ko/reference/workflow-steps/export/export-to-parquet/)를 참조하십시오.
- **Slack, Microsoft Teams, Web Hook 단계가 메시지가 전송되지 않은 이유를 알려 줍니다.** 단계 오류에는 연결을 시도한 서버와, Slack 및 Teams의 경우 연결 이름이 표시되며 무엇이 잘못되었는지가 설명됩니다. 예를 들어 Slack이 더 이상 웹후크를 인식하지 못하는 경우, 채널에 게시할 수 없는 경우, 서버를 찾을 수 없거나 60초 안에 응답하지 않는 경우, 연결이 삭제된 경우가 있습니다. Slack 또는 Teams 웹후크 URL은 가진 사람이 누구나 내 통합으로 게시할 수 있으므로 표시되지 않습니다. [Slack으로 알림](/ko/reference/workflow-steps/notifications/notify-via-slack/)을 참조하십시오.

## 수정됨

- **잘못된 프로젝트 설정이 명확한 메시지로 보고됩니다.** 알 수 없는 환경이나 문서 계정, 이미 사용 중이거나 예약된 슬러그, 잘못된 스토리지 유형이나 전기 모드는 이제 일반적인 서버 오류 대신 문제를 알려 주는 메시지를 반환합니다. REST API에서는 500이 아닌 400이며, AI 어시스턴트나 MCP에서는 잘못된 인수 오류입니다.
- **REST API의 차원 값 요청이 작동합니다.** `POST /rest/v1/analyze/query/retrieve-dimension-values`가 그리드 요청으로 처리되어 잘못된 요청으로 거부되었습니다. 이제 `value_columns`의 각 열에 대해 집계된 값 하나를 반환하며, 행 필터와 열 필터의 각 쌍마다 값 하나를 반환하는 그리드는 별도의 `POST /rest/v1/analyze/query/retrieve-dimension-cells`를 사용합니다.
- **느린 테이블 읽기와 파일 처리가 더 이상 다른 요청을 막지 않습니다.** 웨어하우스에서 테이블의 열 읽기, Data Foundation 파일 등록, Excel로 내보내기, REST 또는 SOAP 가져오기 응답 읽기, 문서 계정이 사용되는 위치 찾기, Panel 앱의 코드나 로고 확인은 각각 끝날 때까지 같은 서버가 처리하던 다른 모든 요청을 멈추게 할 수 있었습니다. 이제 이 작업들은 다른 요청과 나란히 실행됩니다.
- **프로젝트 및 워크플로 변수 대화 상자가 스크롤됩니다.** 작은 화면이나 낮은 해상도에서는 추가 및 편집 대화 상자가 창보다 커서 **만들기**와 **업데이트** 버튼에 닿지 않을 수 있었습니다. 이제 양식이 스크롤되고 버튼은 아래쪽에 고정됩니다.
- **Azure Blob Storage 문서 계정에서 256 MiB를 넘는 파일을 복사, 이동, 이름 바꾸기할 수 있습니다.** 이전에는 이 크기의 파일에서 이 작업이 모두 실패했으며, 그런 파일이 들어 있는 폴더를 이동하거나 이름을 바꿀 때도 실패했습니다.
- **Lakehouse v2에서 테이블의 행 수가 방금 기록된 내용을 반영합니다.** 테이블에 기록한 단계나 가져오기가 기록하기 전의 행 수를 저장할 수 있어, 방금 로드한 테이블이 0개 행으로 표시되거나 가져오기가 0개 행을 가져왔다고 보고할 수 있었습니다. 이제 새 행이 모든 곳에서 보이게 된 후에 행 수를 읽으므로 이후 단계도 해당 행을 읽습니다. 테이블을 다른 브랜치로 전환하거나 브랜치를 테이블에 병합할 때도 행 수와 열 수가 업데이트됩니다.
- **Weave의 빈 값 검사는 각 실행을 이전 실행이 실제로 남긴 상태와 비교합니다.** 단계의 빈 값은 단계가 테이블을 비우고 다시 채우는 도중에 집계되는 경우가 많아, 이전 실행에는 빈 값이 없었던 것처럼 보이거나 항상 일부가 비어 있던 열이 방금 그렇게 된 것처럼 보고되었습니다. 이제 각 실행은 단계가 테이블을 남긴 상태 그대로 집계됩니다. 이전에 기록된 집계는 정상 값과 구별할 수 없으므로 사용하지 않습니다. 각 단계의 빈 값 검사는 기록을 처음부터 다시 시작하며, 다섯 번의 실행이 집계될 때까지 검사되지 않음으로 보고됩니다. 행 수와 값 분포 검사도 단계가 끝나고 2초가 지난 뒤 다른 단계가 같은 테이블에 기록한 내용을 해당 단계의 기록으로 인정하지 않습니다. [Weave 점검 항목](/ko/guides/ai-assistant/weave-findings/)을 참조하십시오.
- **삭제된 연결을 REST API에 요청하면 404를 반환합니다.** 삭제된 연결이나 존재하지 않는 ID를 요청하면 일반적인 서버 오류(500)로 응답했습니다. 이제 연결 ID가 포함된 메시지와 함께 404를 반환합니다.

## 보안

- **행 액세스를 저장할 때 소스에 더 이상 없는 부여된 값이 유지됩니다.** 보안 그룹에 부여된 값은 테이블에 해당 값이 있는 행이 없거나, 차원에서 멤버가 사라졌거나, 목록에 더 이상 없으면 다음 저장 시 부여에서 빠졌습니다. 그러면 아무것도 선택되지 않은 그룹이 **Everyone else**로 되돌아가 모든 행을 볼 수 있게 될 수 있었습니다. 이제 해당 값은 표시된 채로 그리드에 남으며, **저장**을 누르면 유지할지 제거할지 묻습니다. [행 액세스 그리드](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-그리드)를 참조하십시오.
- **계정의 소유자만 이전 버전을 복원할 수 있습니다.** 문서 계정을 이전 버전으로 복원하거나, 버전을 보류 또는 해제하거나, 백업을 만들려면 이제 해당 계정의 소유자여야 하며, 시스템에서 관리하는 계정에서는 이 중 어느 것도 사용할 수 없습니다. 계정의 버전 기록을 보려면 계정에 대한 액세스 권한이 필요합니다.
- **데이터를 읽기만 해야 하는 쿼리가 더 이상 데이터를 변경할 수 없습니다.** AI 어시스턴트와 MCP 클라이언트가 사용하는 `query_run` 도구는 데이터를 읽는 문, 즉 SELECT 또는 WITH 문 하나, 그에 대한 EXPLAIN, 또는 SHOW만 실행하며 그 외의 것은 실행하지 않고 거부합니다. 데이터를 변경하려면 `query_transform`을 사용하십시오. MCP 테이블 내보내기의 SQL도 같은 규칙을 따릅니다. REST 및 JSON-RPC API에서는 프로젝트 데이터를 변경할 수 없는 멤버에 대해 쿼리 실행, 열 패싯 만들기, 쿼리를 CSV로 다운로드, 원격 데이터베이스로 쿼리 내보내기, 직접 작성한 쿼리로 테이블 데이터 내보내기에도 이 규칙이 적용되며, 거부된 쿼리는 403을 반환합니다. Explain Analyze는 쿼리를 측정하기 위해 실행하므로 쿼리 로그와 Lakehouse에서는 이제 읽기 쿼리만 허용하며, 행 액세스가 있는 프로젝트에서는 프로젝트 아키텍트만 쿼리 로그에서 실행할 수 있습니다.
