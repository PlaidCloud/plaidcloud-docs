## 추가됨

- **PlaidXL이 Excel에서 만들고, 드릴하고, 설명하고, 계획합니다.** **PlaidCloud** 리본 탭은 **연결**, **삽입**, **새로 고침**, **Drill**, **쓰기**, **공유**로 구성되며, 자주 쓰는 명령은 **PlaidXL** 바로 가기 메뉴와 **PlaidXL Cell** 탭에서도 사용할 수 있고, 주요 명령에는 변경할 수 있는 키보드 바로 가기가 있습니다. 로그인하기 전에 실행한 명령은 로그인 창을 연 다음 로그인이 끝나면 한 번 실행되며, Office에서 Microsoft Entra 회사 계정을 사용하면 PlaidXL이 워크스페이스를 자동으로 찾습니다. [PlaidXL 참조](/ko/reference/cli/plaidxl/)를 참조하십시오.
  - **몇 번의 클릭으로 보고서를 만듭니다.** **보고서** 탭은 테이블에서 실시간 보고서를 구성하며, 한 차원은 행 방향으로, 다른 차원은 열 방향으로 드릴 다운하고 교차 지점마다 `CELL` 값을 배치합니다. **Build my first report**는 사용자의 데이터로 샘플을 만듭니다. 드릴하면 보고서가 행과 열 전체를 삽입하거나 제거하며, 직접 입력한 값, 메모, 서식은 해당 행과 함께 유지됩니다. [보고서 만들기](/ko/reference/cli/plaidxl/build-a-report/)를 참조하십시오.
  - **모든 셀에서 드릴합니다.** **Drill down**, **Drill up**, **Keep only**, **Remove only**는 노드를 실시간 `DRILL` 수식으로 바꾸고 노드, 차원 제목, 보고서 값에서 수식을 대신 편집합니다. **Custom drill**은 행을 삽입하기 전에 미리 보여 주며, 멤버 선택기는 멤버를 삽입하거나 노드의 하위 항목 드롭다운을 셀에 추가합니다. `DRILL`은 제외하거나 열 노드를 받을 수 있으며 행 방향으로도 실행할 수 있습니다. [드릴, 멤버 선택, 수치 설명](/ko/reference/cli/plaidxl/drill/)을 참조하십시오.
  - **수치를 설명합니다.** **Explain this number**는 값이 어떻게 계산되는지, 현재 PlaidCloud와 일치하는지, 값이 나온 테이블과 워크플로 단계를 보여 줍니다. **Show detail rows**는 값의 근거가 되는 행을 별도의 시트에 표시하며 합계가 맞는지 확인합니다.
  - **Excel에서 관리되는 지표.** `PLAIDXL.METRIC` 및 `PLAIDXL.METRIC_BREAKDOWN`은 대시보드에 표시되는 방식 그대로 비즈니스 지표를 반환하며, **Metric...** 항목은 프로젝트의 지표를 현재 값과 함께 나열합니다. [지표](/ko/reference/cli/plaidxl/functions/#지표)를 참조하십시오.
  - **보고서에 직접 입력하여 계획합니다.** `CELL` 값 위에 숫자를 입력하면 PlaidCloud에 기록됩니다. 비례 배분, 균등 배분, 다른 멤버의 형태에 맞춘 배분, 금액 또는 백분율 조정이 가능하며 고정된 셀은 변경되지 않습니다. 평균, 중앙값, 최솟값, 최댓값, 표준 편차, 분산 셀에도 입력한 값을 사용할 수 있습니다. **Undo last write**는 입력한 값과 저장 내용을 최신 순으로 되돌립니다. [PlaidCloud에 값 입력](/ko/reference/cli/plaidxl/write-values/)을 참조하십시오.
  - **필요한 부분만 새로 고칩니다.** 시트, 선택 영역 또는 모든 테이블을 새로 고칠 수 있으며 작업 창에 각 테이블의 진행 상황과 **취소**가 표시되고, PlaidXL 수식만 다시 계산할 수도 있습니다. 가져온 테이블은 데이터 유형에 맞게 서식이 지정된 Excel 테이블로 들어오고, 새로 고쳐도 사용자의 열과 숫자 서식이 유지되며, 제자리에서 새로 고쳐집니다. 테이블을 다시 가져와도 새로 고침 목록에 두 번 추가되지 않고, **Stop refreshing**은 목록에서 하나를 제거하며, 차원도 테이블과 함께 새로 고쳐집니다. [모든 테이블 새로 고침](/ko/reference/cli/plaidxl/retrieve/#모든-테이블-새로-고침)을 참조하십시오.
  - **저장하면 즉시 기록되며 되돌릴 수 있습니다.** **Save to PlaidCloud**는 확인 없이 기록하고, 수행한 작업을 알려 주며, **실행 취소**를 제공합니다. 필터와 함께 가져온 시트, 상세 행 시트, 일부 행에만 액세스할 수 있는 사용자는 해당 행만 대체하므로 다른 사람의 행은 유지됩니다. [PlaidCloud에 테이블 저장](/ko/reference/cli/plaidxl/retrieve/#테이블을-plaidcloud에-저장)을 참조하십시오.
  - **Excel에서 Weave에 문의합니다.** **Weave** 탭에서 일반 언어로 보고서, 수식, 드릴, 테이블을 요청하거나 **Ask Weave about this cell**을 선택합니다. Weave는 사용자 권한으로 PlaidCloud를 읽고 통합 문서만 변경하며, 입력한 내용을 대체하기 전에 확인을 요청하고, 창을 다시 로드하기 전까지는 각 변경을 되돌릴 수 있습니다. [Excel에서 Weave에 문의](/ko/reference/cli/plaidxl/weave/)를 참조하십시오.
  - **시트 하나 또는 전체 통합 문서의 값만 있는 복사본을 공유합니다.** **Convert to values**는 통합 문서 전체, 시트 하나, 또는 되돌릴 수 없는 값으로 변환하며, 시트 이름을 바꾼 후에도 **Restore PlaidXL formulas**가 계속 작동합니다.
- **단계 양식의 미리 보기.** 가져오기: SQL, Execute: SQL, SQL 추출, 내보내기: SQL, Salesforce 쿼리 양식은 단계를 실행하지 않고 최대 100개 행을 보여 주며, Anaplan: 뷰 읽기 및 Anaplan: 목록 읽기 단계는 생성될 열과 유형을 보여 줍니다. **소스** 탭에서 **미리 보기**를 클릭합니다. 변수는 실행 시와 같은 방식으로 채워지지만 `{x:>9}` 같은 변수 형식은 지원되지 않습니다. 미리 보기는 표준 SQL 함수만 실행하며, 그렇지 않으면 단계를 실행하라고 안내합니다. 잠긴 프로젝트나 에이전트 기반 Execute SQL 단계에서는 사용할 수 없습니다. [SQL 가져오기 단계](/ko/reference/workflow-steps/import/import-sql/)와 [SQL 추출 단계](/ko/reference/workflow-steps/tables/table-extract-sql/)를 참조하십시오.
- **사용 현황 보고서는 변경 내용을 보여 주고, 그룹으로 범위를 좁히며, 워크플로로 연결됩니다.** **개요**에는 이전 기간 대비 추세 화살표와 비활성 멤버, 아무도 열지 않은 대시보드와 앱을 알려 주는 **Highlights** 목록이 추가되었습니다. **그룹**은 **개요**, **내용**, 비활성 목록을 하나의 보안 그룹 멤버로 제한하며, 날짜 범위에 **Previous month**와 **This month**가 추가되어 모든 탭에서 공유되고 계정에 기억됩니다. 이제 모든 수치에 설명이 있고, 테이블은 **멤버**와 **Area** 같은 쉬운 이름을 사용하며, Enter 키로 행을 열 수 있고, 로드 및 오류 표시가 더 명확해졌으며, 마지막 **퍼널** 단계에는 이를 완료한 멤버 수가 표시됩니다. 새로운 **Get Workspace Usage** 단계는 멤버 이름 없이 일별 또는 월별 사용량 합계를 일정에 따라 테이블에 기록하며, **Get Workspace Members** 단계와 마찬가지로 각 실행이 **보안 로그**에 기록됩니다. [사용 현황 보고서](/ko/administration/access/usage-reports/)와 [Get Workspace Usage 단계](/ko/reference/workflow-steps/general/get-workspace-usage/)를 참조하십시오.
- **AI 어시스턴트가 테이블 게시를 취소하고 프로젝트의 기본 대시보드 대상을 설정할 수 있습니다.** `publish_manage`는 테이블의 게시를 취소하면서 게시된 뷰와 차트가 사용하지 않는 대시보드 데이터 세트도 함께 제거합니다. 차트가 아직 사용하는 데이터 세트는 유지되며, 게시된 뷰를 기반으로 보고서 뷰가 만들어진 경우에도 해당 뷰와 데이터 세트는 유지되지만 테이블의 게시는 취소됩니다. `project_upsert`는 프로젝트의 새 대시보드를 공유할 그룹인 `dashboard_default_audience`를 설정하며 `[]`로 지웁니다. [게시 취소](/ko/guides/data/publish/#ai-어시스턴트-또는-mcp로-게시-취소)와 [AI 어시스턴트 또는 MCP로 기본 대상 설정](/ko/guides/dashboards/control-who-can-see-a-dashboard/#ai-어시스턴트-또는-mcp로-기본-대상-설정)을 참조하십시오.

- **Cost to Serve 및 Operational Transfer Pricing 템플릿이 Common Finance Model 위에 구축됩니다.** **Cost to Serve**로 프로젝트를 시작하면 각 부서에 지정한 활동과 동인에 따라 영업비용을 고객에게 배분하고, 총계정원장과 연결된 상태로 각 고객을 서비스하는 비용을 반영한 마진을 확인할 수 있습니다. **Operational Transfer Pricing**으로 시작하면 각 엔터티의 이익 수준(매출수익률, 순원가가산율, 재판매가격 차감)을 정책 범위와 비교하여 검증하고, 범위를 벗어난 엔터티를 목표로 되돌리는 true-up을 확인할 수 있습니다. 매출수익률은 EBIT를 검증 대상 법인 매출로 나눈 값입니다. [Cost to Serve](/ko/guides/projects/cost-to-serve/)와 [Operational Transfer Pricing](/ko/guides/projects/operational-transfer-pricing/)을 참조하십시오.
- **OneStream과 Anaplan이 Data Foundation에 데이터를 공급하며, OneStream에는 읽기 단계가 있습니다.** Data Foundation은 OneStream 관리자가 만든 데이터 어댑터를 통해 OneStream 통합 결과를 읽고, 내보내기 작업을 통해 Anaplan 계획을 읽어 그룹 손익계산서를 이에 대해 대사합니다. 새로운 **OneStream: Read Adapter** 단계는 모든 워크플로에서 통합 멤버마다 한 번씩 호출하여 어댑터를 테이블로 읽어 들입니다. [Data Foundation용 OneStream](/ko/guides/connections/onestream-for-data-foundation/), [Data Foundation 소스로서의 Anaplan](/ko/guides/connections/anaplan/#data-foundation의-소스로서의-anaplan), [OneStream: Read Adapter 단계](/ko/reference/workflow-steps/onestream/onestream-read-adapter/)를 참조하십시오.
- **Data Foundation이 공통 비용을 배분하는 방식을 선택합니다.** **작업 > 배부...** 메뉴는 간접비를 부서에 배분하는 경우와 부서를 제품 및 고객에 배분하는 경우 모두에 대해, 어떤 비용을 배분할지, 무엇을 기준으로 배분할지, 어디에 반영할지, 동인이 음수일 때 어떻게 할지를 안내하며, 한 달에 대해 풀링된 금액, 배분된 금액, 배분되지 않은 금액을 보여 주는 미리 보기를 제공합니다. 직접 편집한 규칙은 유지됩니다. [배부 규칙](/ko/guides/projects/data-foundation/#배부-규칙)을 참조하십시오.
- **Data Foundation에서 수치를 설명하고 원하는 이름을 붙입니다.** **Explain this number**는 사용자의 행 액세스 범위에서 손익계산서 수치를 원장이 보유한 금액, 배분되어 들어오고 나간 금액, 그룹에서 소거된 금액으로 나누고 가장 큰 소스 문서를 함께 보여 줍니다. **Business names**는 범주, P&L 라인, 지표, 열에 비즈니스에서 사용하는 이름을 부여하여 보고서, 지표, 어시스턴트에 표시합니다. [수치 설명](/ko/guides/projects/data-foundation/#수치-설명)과 [비즈니스 이름](/ko/guides/projects/data-foundation/#비즈니스-이름)을 참조하십시오.
- **Data Foundation이 board pack을 작성하며 이전 상태로 되돌릴 수 있습니다.** **Board pack**은 요청 시 또는 일정에 따라 손익계산서 대시보드의 Excel 통합 문서와 PDF를 문서 계정의 폴더에 기록합니다. 복원 지점은 각 로드가 시작될 때와 매핑 또는 소스를 변경하기 전에 만들어지며, **작업 > 복원...** 메뉴로 프로젝트를 되돌립니다. [Board Pack](/ko/guides/projects/data-foundation/#board-pack)과 [복원 지점](/ko/guides/projects/data-foundation/#복원-지점)을 참조하십시오.
- **Data Foundation 프로젝트를 복제하거나 템플릿으로 저장합니다.** **작업 > 복제...** 메뉴는 모델 편집 내용, 지표, 분석 경로와 함께 프로젝트를 복사합니다. **Save as my template...** 항목은 설정을 문서 계정에 저장하고, **From a template file...** 항목은 이를 바탕으로 소스가 연결을 기다리는 새 비공개 프로젝트를 시작합니다. [프로젝트 복제](/ko/guides/projects/data-foundation/#프로젝트-복제)와 [내 템플릿으로 저장](/ko/guides/projects/data-foundation/#내-템플릿으로-저장)을 참조하십시오.
- **Data Foundation의 설정 체크리스트가 인계까지 이어지며, 어시스턴트가 남은 항목을 해결할 수 있습니다.** 체크리스트에 야간 새로 고침, 증거 팩, 프로젝트를 소유자에게 인계하는 항목이 추가되고 프로젝트를 설정한 사람이 표시됩니다. 유형이 없는 계정, 여러 소스가 사용하는 코드, 어디에도 일치하지 않은 파일 열에 대한 답을 어시스턴트에게 제안하도록 요청할 수 있으며, 어시스턴트는 아무것도 기록하지 않고 답은 사용자가 적용합니다. [Data Foundation 시작하기](/ko/guides/projects/data-foundation-getting-started/)와 [Ask로 미해결 질문 해결](/ko/guides/projects/data-foundation/#ask로-미해결-질문-해결)을 참조하십시오.

- **모바일 Weave의 음성 입력은 한 번 탭하면 됩니다.** 마이크를 탭하고 질문하면 말을 멈춘 뒤 Weave가 한 번 전송합니다. 일찍 멈추려면 마이크를 다시 탭하며, 아무 소리도 들리지 않으면 자동으로 꺼집니다. 문장 도중에 **Weave** 탭을 벗어나거나 앱을 백그라운드로 보내면 말한 내용이 전송되지 않은 채 질문 입력란에 남아 검토할 수 있습니다. 실행, 일시 중지, 중지, 재개는 확인 대화 상자에서 실수로 두 번 탭해도 무시합니다. 앱 버전 1.3.0 이상이 필요합니다. ## 변경됨

- **단계 양식이 하나의 레이아웃을 따릅니다.** 탭은 General, Settings, Source, Columns, Filters, Output, Advanced의 표준 이름과 표준 순서를 사용하며, ERP 전기 양식에는 Header columns와 Line columns가 있습니다. 필수 필드는 *로 표시되고, 양식은 단계에 필요한 항목에 대해서만 저장을 막습니다.
- **프로젝트 복사는 테이블 데이터와 차원 멤버를 따로 선택하고, 데이터를 더 빠르게 복사하며, 비공개 복사본의 ERP 쓰기 승인을 유지합니다.** **Data to copy**에서 **테이블 데이터**(**No table data**(기본값), **전체** 또는 **샘플**)와 별도로 기본적으로 켜져 있는 **Copy dimension members**를 선택하므로, 테이블 행 없이 복사해도 차원이 채워진 채로 도착하며 만드는 속도도 빠릅니다. **전체** 및 **샘플** 복사는 여러 테이블을 동시에 복사하므로 테이블이 많은 프로젝트가 더 빨리 끝납니다. **복사 결과**는 테이블과 함께 각 차원의 결과도 나열하며, **Retry failed items**는 실패한 테이블과 차원을 함께 다시 시도합니다. 데이터와 함께 만든 새 복사본은 본인만 볼 수 있으며, 소스의 ERP 쓰기 승인 중 본인이 직접 부여할 수 있는 것은 유지됩니다. 소스가 Live로 전기하는 경우 복사본은 Simulate로 도착하므로 Live로 전환하기 전까지는 ERP에 아무것도 전달되지 않습니다. REST API와 `project_copy` MCP 도구도 `dimension_members`를 받습니다. [복사할 데이터 양 선택](/ko/guides/projects/managing-projects/#복사할-데이터-양-선택)과 [복사본의 ERP 쓰기 승인](/ko/guides/projects/managing-projects/#복사본의-erp-쓰기-승인)을 참조하십시오.
- **행 작업 메뉴(⋯)가 모든 그리드 행의 왼쪽 가장자리에 있습니다.**
- **검증 설정이 없는 저장된 ERP 쓰기 단계는 검증 전용으로 열립니다.** SAP Post, SAP Attach, NetSuite Post, Oracle EBS GL 및 AP Post, Xero 내보내기가 해당됩니다. 명시적으로 Live 실행으로 설정된 단계는 Live로 유지됩니다.
- **장시간 실행되는 작업의 진행 상황이 모든 곳에서 같은 방식으로 표시됩니다.**
- **워크플로를 중지하면 워크플로가 시작한 모든 것이 중지되며, 시작할 수 없는 단계는 멈춰 있지 않고 실패합니다.** 중지하면 대기 중이던 가져오기 및 차원 단계가 취소되므로 워크스페이스의 이후 가져오기와 차원 로드가 정상적으로 시작되며, 워크플로의 대기 중이거나 실행 중인 커넥터(Singer) 동기화도 중지됩니다. 단계의 작업을 시작할 수 없으면 단계는 무한정 기다리는 대신 이유와 함께 실패합니다. 약 40분 내에 어떤 작업자도 시작하지 않은 경우, 작업자가 시작한 뒤 사라진 경우, 포드가 약 20분 동안 Pending 상태에 머문 경우, 이미지를 약 5분 동안 가져올 수 없는 경우, 약 20분 동안 포드가 만들어지지 않은 경우가 이에 해당합니다. 약 30분 내에 어떤 러너도 가져가지 않은 커넥터 동기화는 해당 동기화를 지정하는 메시지와 함께 실패합니다. 단계가 작업자를 기다리는 동안 상태 메시지에 지금까지의 분 수와 함께 "작업자를 기다리는 중…"이 표시되며, 작업이 시작되면 사라집니다. [워크플로 실행](/ko/guides/workflows/run-a-workflow/#시작되지-않는-단계)을 참조하십시오.
- **워크스페이스를 업그레이드하면 REST, Import REST, Import Postman 단계가 REST 요청으로 변환됩니다.** 깔끔하게 변환할 수 없는 단계는 그대로 유지됩니다. [REST 요청 단계](/ko/guides/workflows/rest-request-step/)를 참조하십시오.
- **프로젝트 아키텍트는 대시보드에서 행이 제한된 테이블의 모든 행을 볼 수 있습니다.** Analyze에서 보이는 것과 일치합니다. 아키텍트 액세스를 제거하면 대시보드에 즉시 반영됩니다. 사용자의 역할을 변경하거나, 사용자 또는 그룹을 프로젝트에서 제거하거나, 프로젝트의 액세스 유형을 변경하거나, 프로젝트의 이전 버전을 복원하거나, 보안 그룹을 삭제하는 경우가 모두 해당됩니다. 이전에 아키텍트였던 사용자는 더 이상 행이 제한된 데이터의 모든 행을 보지 못합니다. [행 액세스 관리](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리)를 참조하십시오.
- **세션이 만료된 후 연 대시보드 링크는 로그인하면 해당 대시보드로 이동합니다.** [대시보드 사용](/ko/guides/dashboards/using-dashboards/)을 참조하십시오.
- **MCP 도구는 인식하지 못하는 필드를 무시하는 대신 거부하고** 오류에 해당 필드를 명시합니다. `workflow_upsert`는 `memo`를 받으며 `description`을 같은 필드의 다른 이름으로 받아들입니다. [알 수 없는 필드는 거부됩니다](/ko/integrations/ai-coding-agents/getting-started/#알-수-없는-필드는-거부됩니다)를 참조하십시오.
- **Lakehouse v2에서 Lakehouse가 Parquet 내보내기를 Google Cloud Storage에 직접 기록합니다.** Google Cloud Storage 문서 계정으로의 내보내기는 모든 행이 먼저 PlaidCloud를 거치는 대신 계정 자체의 자격 증명으로 계정의 버킷에 바로 기록됩니다. Amazon S3 및 Azure Blob Storage 계정으로의 내보내기는 이전과 동일하게 작동합니다. [Export to Parquet 단계](/ko/reference/workflow-steps/export/export-to-parquet/)를 참조하십시오.
- **Slack, Microsoft Teams, Web Hook 단계가 메시지를 보내지 못한 이유를 알려 줍니다.** 단계 오류에는 연결을 시도한 서버와, Slack 및 Teams의 경우 연결 이름이 표시되고 무엇이 잘못되었는지 설명합니다. 예를 들어 Slack이 더 이상 웹후크를 인식하지 못하는 경우, 채널에 게시할 수 없는 경우, 서버를 찾을 수 없거나 60초 내에 응답하지 않는 경우, 연결이 삭제된 경우가 있습니다. Slack 또는 Teams 웹후크 URL은 이를 가진 사람이 누구든 통합 계정으로 게시할 수 있으므로 표시되지 않습니다. [Notify via Slack 단계](/ko/reference/workflow-steps/notifications/notify-via-slack/)를 참조하십시오.

## 수정됨

- **잘못된 프로젝트 설정이 명확한 메시지로 보고됩니다.** 알 수 없는 환경이나 문서 계정, 이미 사용 중이거나 예약된 슬러그, 잘못된 스토리지 유형 또는 전기 모드가 이제 일반적인 서버 오류 대신 문제를 명시한 메시지를 반환합니다. REST API에서는 500이 아닌 400이며, AI 어시스턴트나 MCP에서는 잘못된 인수 오류입니다.
- **REST API의 차원 값 요청이 작동합니다.** `POST /rest/v1/analyze/query/retrieve-dimension-values`는 그리드 요청으로 처리되어 잘못된 요청으로 거부되었습니다. 이제 `value_columns`의 각 열에 대해 집계된 값 하나를 반환하며, 행 필터와 열 필터의 각 쌍마다 값 하나를 반환하는 그리드는 별도의 `POST /rest/v1/analyze/query/retrieve-dimension-cells`를 사용합니다.
- **느린 테이블 읽기와 파일 처리가 더 이상 다른 요청을 막지 않습니다.** 웨어하우스에서 테이블의 열 읽기, Data Foundation 파일 등록, Excel로 내보내기, REST 또는 SOAP 가져오기의 응답 읽기, 문서 계정이 사용되는 위치 찾기, Panel 앱의 코드 또는 로고 검사는 각각 완료될 때까지 같은 서버가 처리하던 다른 모든 요청을 멈추게 할 수 있었습니다. 이제는 그 요청들과 함께 실행됩니다.
- **프로젝트 및 워크플로 변수 대화 상자가 스크롤됩니다.** 작은 화면이나 낮은 해상도에서 추가 및 편집 대화 상자가 창보다 커서 **만들기**와 **업데이트** 버튼에 닿지 않을 수 있었습니다. 이제 양식이 스크롤되고 버튼은 아래쪽에 고정됩니다.
- **Azure Blob Storage 문서 계정에서 256 MiB가 넘는 파일을 복사하고, 이동하고, 이름을 바꿀 수 있습니다.** 이전에는 이러한 작업이 그 크기의 파일에서 실패했으며, 그런 파일이 들어 있는 폴더를 이동하거나 이름을 바꿀 때도 실패했습니다.
- **Lakehouse v2에서 테이블의 행 수가 방금 기록된 내용을 반영합니다.** 테이블에 쓴 단계나 가져오기가 쓰기 이전의 행 수를 기록하여, 방금 로드한 테이블이 0개 행으로 표시되거나 가져오기가 0개 행을 가져왔다고 보고할 수 있었습니다. 이제 새 행이 모든 곳에서 보일 때 행 수를 읽으므로 이후 단계도 해당 행을 읽습니다. 테이블을 다른 브랜치로 전환하거나 브랜치를 테이블에 병합하면 행 수와 열 수도 업데이트됩니다.
- **Weave의 빈 값 검사는 각 실행을 이전 실행이 실제로 남긴 결과와 비교합니다.** 단계의 빈 값이 테이블을 비우고 다시 채운 직후에 집계되는 경우가 많아 이전 실행에 빈 값이 없었던 것처럼 보였고, 항상 일부가 비어 있던 열이 방금 비어지기 시작한 것처럼 보고되었습니다. 이제 각 실행은 단계가 테이블을 남긴 상태 그대로 집계됩니다. 이전에 기록된 집계는 정상 값과 구분할 수 없으므로 사용하지 않으며, 각 단계의 빈 값 검사는 이력을 다시 시작하고 다섯 번의 실행이 집계되기 전까지는 검사되지 않음으로 보고됩니다. 행 및 값 분포 검사도 다른 단계가 같은 테이블에 단계가 끝난 지 2초가 넘어서 기록한 쓰기를 해당 단계의 결과로 인정하지 않습니다. [Weave 점검 항목](/ko/guides/ai-assistant/weave-findings/)을 참조하십시오.
- **삭제된 연결을 REST API에 요청하면 404를 반환합니다.** 삭제된 연결이나 존재하지 않는 ID를 요청하면 일반적인 서버 오류(500)로 응답했습니다. 이제 연결 ID를 명시한 메시지와 함께 404를 반환합니다.

## 보안

- **계정의 소유자만 이전 버전을 복원할 수 있습니다.** 문서 계정을 이전 버전으로 복원하거나, 버전을 보류하거나 해제하거나, 백업을 만들려면 이제 계정의 소유자 중 한 명이어야 하며, 시스템 관리 계정에서는 어느 것도 사용할 수 없습니다. 계정의 버전 이력을 보려면 계정에 대한 액세스가 필요합니다.
