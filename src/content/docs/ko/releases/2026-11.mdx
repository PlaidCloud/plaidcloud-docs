## 추가됨

- **단계 폼의 미리 보기.** Import: SQL, Execute: SQL, Extract: SQL, Export: SQL, Salesforce 쿼리 단계는 단계를 실행하지 않고도 최대 100개 행을 표시하며, Anaplan 뷰 읽기 및 목록 읽기 단계는 생성될 열과 유형을 표시합니다. **소스** 탭에서 **미리 보기**를 클릭합니다. 변수는 실행 시 채워지는 방식 그대로 채워지지만, `{x:>9}` 같은 변수 형식은 지원되지 않습니다. 미리 보기는 표준 SQL 함수만 실행하며, 그렇지 않으면 단계를 실행하라는 안내가 표시됩니다. 잠긴 프로젝트나 에이전트 기반 Execute SQL 단계에서는 사용할 수 없습니다. [SQL 가져오기](/ko/reference/workflow-steps/import/import-sql/)와 [SQL 추출](/ko/reference/workflow-steps/tables/table-extract-sql/)을 참조하십시오.
- **사용 현황 보고서가 변경 내용을 보여 주고, 그룹으로 범위를 좁힐 수 있으며, 워크플로로 연결됩니다.** **개요**에 이전 기간 대비 추세 화살표와, 비활성 멤버 및 아무도 열지 않은 대시보드와 앱을 알려 주는 **Highlights** 목록이 추가됩니다. **그룹**은 **개요**, **내용**, 비활성 목록을 하나의 보안 그룹 멤버로 한정하며, 날짜 범위에는 **Previous month**와 **This month**가 추가되고 모든 탭이 이를 공유하며 계정에 기억됩니다. 이제 모든 수치에 설명이 있고, 테이블에는 **멤버**와 **영역** 같은 쉬운 이름이 쓰이며, Enter 키로 행을 열 수 있고, 로드 및 오류 표시가 더 명확해졌으며, 마지막 **퍼널** 단계에는 이를 완료한 멤버 수가 표시됩니다. 새 **Get Workspace Usage** 단계는 멤버 이름 없이 일별 또는 월별 사용량 합계를 일정에 따라 테이블에 기록하며, **Get Workspace Members**와 마찬가지로 각 실행이 보안 로그에 기록됩니다. [사용 현황 보고서](/ko/administration/access/usage-reports/)와 [Get Workspace Usage](/ko/reference/workflow-steps/general/get-workspace-usage/)를 참조하십시오.
- **AI 어시스턴트가 테이블 게시를 취소하고 프로젝트의 기본 대시보드 대상을 설정할 수 있습니다.** `publish_manage`는 테이블의 게시된 뷰 및 차트에서 사용하지 않는 대시보드 데이터 세트와 함께 테이블 게시를 취소합니다. 차트가 아직 사용 중인 데이터 세트는 유지되며, 게시된 뷰를 기반으로 보고서 뷰가 만들어진 경우에는 해당 뷰와 데이터 세트도 유지되지만 테이블 게시는 그대로 취소됩니다. `project_upsert`는 프로젝트의 새 대시보드를 공유할 그룹인 `dashboard_default_audience`를 설정하며, `[]`는 이를 지웁니다. [게시 취소](/ko/guides/data/publish/#ai-어시스턴트-또는-mcp로-게시-취소)와 [AI 어시스턴트 또는 MCP로 기본 대상 설정](/ko/guides/dashboards/control-who-can-see-a-dashboard/#ai-어시스턴트-또는-mcp로-기본-대상-설정)을 참조하십시오.

- **모바일 Weave에서 음성 입력이 한 번의 탭으로 가능합니다.** 마이크를 탭하고 질문하면 말을 멈춘 뒤 Weave가 한 번 전송합니다. 일찍 멈추려면 마이크를 다시 탭하며, 아무 소리도 들리지 않으면 자동으로 꺼집니다. 말하는 도중 **Weave** 탭을 벗어나거나 앱을 백그라운드로 보내면, 말한 내용이 전송되지 않은 채 질문 상자에 남아 있어 검토할 수 있습니다. 실행, 일시 중지, 중지, 재개는 확인 시 실수로 두 번 탭해도 무시합니다. 앱 버전 1.3.0 이상이 필요합니다. [음성 사용](/ko/guides/mobile-app/weave-on-mobile/#음성-사용)을 참조하십시오.

## 변경됨

- **단계 폼이 하나의 레이아웃을 따릅니다.** 탭은 일반, 설정, 소스, 열, 필터, 출력, 고급이라는 표준 이름과 표준 순서를 사용하며, ERP 전기 폼에는 헤더 열과 라인 열이 추가됩니다. 필수 필드에는 *가 표시되고, 폼은 단계에 필요한 항목에 대해서만 저장을 막습니다.
- **프로젝트 복사에서 테이블 데이터와 차원 멤버를 따로 선택하고, 데이터를 더 빠르게 복사하며, 비공개 복사본에 ERP 쓰기 승인을 유지합니다.** **Data to copy**에서 **테이블 데이터**(**테이블 데이터 없음**(기본값), **전체** 또는 **샘플**)를 선택하고, 이와 별도로 기본적으로 켜져 있는 **Copy dimension members**를 선택합니다. 따라서 테이블 행 없이 복사해도 차원은 채워진 상태로 도착하며 복사가 빠릅니다. **전체**와 **샘플** 복사는 여러 테이블을 동시에 복사하므로 테이블이 많은 프로젝트도 더 빨리 끝납니다. **복사 결과**에는 테이블과 함께 각 차원의 결과가 나열되고, **Retry failed items**는 실패한 테이블과 차원을 함께 다시 시도합니다. 데이터를 포함해 새로 만든 복사본은 본인에게만 공개되며 원본의 ERP 쓰기 승인 중 본인이 직접 부여할 수 있는 것을 유지합니다. 원본이 Live로 전기하는 경우 복사본은 Simulate로 도착하므로, Live로 전환하기 전까지는 ERP에 아무것도 전달되지 않습니다. REST API와 `project_copy` MCP 도구도 `dimension_members`를 받습니다. [복사할 데이터 양 선택](/ko/guides/projects/managing-projects/#복사할-데이터-양-선택)과 [복사본의 ERP 쓰기 승인](/ko/guides/projects/managing-projects/#복사본의-erp-쓰기-승인)을 참조하십시오.
- **행 작업 메뉴(⋯)가 모든 그리드 행의 왼쪽 가장자리에 있습니다.**
- **검증 설정이 없는 저장된 ERP 쓰기 단계는 검증 전용으로 열립니다.** SAP Post, SAP Attach, NetSuite Post, Oracle EBS GL 및 AP Post, Xero 내보내기가 해당합니다. 실시간으로 실행하도록 명시적으로 설정된 단계는 계속 실시간으로 실행됩니다.
- **장시간 실행되는 작업이 모든 곳에서 같은 방식으로 진행 상황을 표시합니다.**
- **워크플로를 중지하면 워크플로가 시작한 모든 것이 중지되며, 시작할 수 없는 단계는 멈춰 있지 않고 실패합니다.** 중지하면 아직 대기 중이던 가져오기 및 차원 단계가 취소되므로 워크스페이스의 이후 가져오기와 차원 로드가 정상적으로 시작되며, 워크플로의 대기 중이거나 실행 중인 커넥터(Singer) 동기화도 중지됩니다. 단계의 작업을 시작할 수 없으면 단계는 무한정 기다리는 대신 사유와 함께 실패합니다. 약 40분 안에 어떤 워커도 작업을 시작하지 않은 경우, 워커가 작업을 시작한 뒤 사라진 경우, 포드가 약 20분 동안 Pending 상태로 멈춘 경우, 이미지를 약 5분 동안 가져올 수 없는 경우, 약 20분 동안 포드가 생성되지 않은 경우입니다. 어떤 러너도 약 30분 안에 가져가지 않은 커넥터 동기화는 해당 동기화를 지목하는 메시지와 함께 실패합니다. 단계가 워커를 기다리는 동안 상태 메시지에는 지금까지 경과한 시간(분)과 함께 "Waiting for a worker…"가 표시되며, 작업이 시작되면 사라집니다. [워크플로 실행](/ko/guides/workflows/run-a-workflow/#시작되지-않는-단계)을 참조하십시오.
- **REST, Import REST, Import Postman 단계는 워크스페이스를 업그레이드할 때 REST 요청 단계로 변환됩니다.** 깔끔하게 변환할 수 없는 단계는 기존 상태 그대로 유지됩니다. [REST 요청 단계](/ko/guides/workflows/rest-request-step/)를 참조하십시오.
- **프로젝트 아키텍트는 행이 제한된 테이블의 모든 행을 대시보드에서 볼 수 있으며**, 이는 Analyze에서 보는 내용과 일치합니다. 아키텍트 액세스를 제거하면 대시보드에 즉시 적용됩니다. 누군가의 역할을 변경하든, 그 사람이나 그 사람의 그룹을 프로젝트에서 제거하든, 프로젝트의 액세스 유형을 변경하든, 이전 프로젝트 버전을 복원하든, 보안 그룹을 삭제하든 마찬가지입니다. 이전 아키텍트는 더 이상 행이 제한된 데이터의 모든 행을 볼 수 없습니다. [행 액세스 관리](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리)를 참조하십시오.
- **세션이 만료된 후 열린 대시보드 링크는 로그인하면 해당 대시보드로 이동합니다.** [대시보드 사용](/ko/guides/dashboards/using-dashboards/)을 참조하십시오.
- **MCP 도구는 인식하지 못하는 필드를 무시하는 대신 거부하고** 오류에 해당 필드를 명시합니다. `workflow_upsert`는 `memo`를 받으며 `description`을 그 다른 이름으로 인정합니다. [알 수 없는 필드는 거부됩니다](/ko/integrations/ai-coding-agents/getting-started/#알-수-없는-필드는-거부됩니다)를 참조하십시오.
- **Lakehouse v2에서는 Lakehouse가 Parquet 내보내기를 Google Cloud Storage에 직접 기록합니다.** Google Cloud Storage 문서 계정으로 내보내면 모든 행이 PlaidCloud를 거치는 대신 계정 자체의 자격 증명으로 계정의 버킷에 바로 기록됩니다. Amazon S3 및 Azure Blob Storage 계정으로의 내보내기는 이전과 같이 작동합니다. [Parquet로 내보내기(Export to Parquet)](/ko/reference/workflow-steps/export/export-to-parquet/)를 참조하십시오.
- **Slack, Microsoft Teams, Web Hook 단계가 메시지가 전송되지 않은 이유를 알려 줍니다.** 단계의 오류에는 연결을 시도한 서버 이름과, Slack 및 Teams의 경우 연결 이름이 표시되며, 무엇이 잘못되었는지도 알려 줍니다. 예를 들어 Slack이 더 이상 웹후크를 인식하지 못하는 경우, 채널에 게시할 수 없는 경우, 서버를 찾을 수 없거나 60초 안에 응답하지 않는 경우, 연결이 삭제된 경우입니다. 웹후크 URL을 가진 사람은 누구나 사용자의 통합으로 게시할 수 있으므로 Slack 또는 Teams 웹후크 URL은 절대 표시되지 않습니다. [Notify via Slack](/ko/reference/workflow-steps/notifications/notify-via-slack/) 단계를 참조하십시오.

## 수정됨

- **잘못된 프로젝트 설정이 명확한 메시지로 보고됩니다.** 알 수 없는 환경이나 문서 계정, 이미 사용 중이거나 예약된 슬러그, 잘못된 스토리지 유형이나 전기 모드는 이제 일반적인 서버 오류 대신 문제를 지목하는 메시지를 반환합니다. REST API에서는 500이 아니라 400이 반환되며, AI 어시스턴트나 MCP에서는 잘못된 인수 오류가 반환됩니다.
- **REST API의 차원 값 요청이 작동합니다.** `POST /rest/v1/analyze/query/retrieve-dimension-values`가 그리드 요청으로 처리되어 유효하지 않은 요청으로 거부되었습니다. 이제 `value_columns`의 각 열에 대해 집계된 값 하나를 반환하며, 행 필터와 열 필터의 각 쌍에 대해 값 하나를 반환하는 그리드에는 별도의 `POST /rest/v1/analyze/query/retrieve-dimension-cells`가 있습니다.
- **느린 테이블 읽기와 파일 처리가 더 이상 다른 요청을 지연시키지 않습니다.** 웨어하우스에서 테이블의 열 읽기, Data Foundation 파일 등록, Excel로 내보내기, REST 또는 SOAP 가져오기의 응답 읽기, 문서 계정이 사용되는 위치 찾기, Panel 앱의 코드나 로고 검사는 각각 완료될 때까지 같은 서버가 처리하던 다른 모든 요청을 멈추게 할 수 있었습니다. 이제 이러한 작업은 해당 요청과 나란히 실행됩니다.
- **프로젝트 및 워크플로 변수 대화상자가 스크롤됩니다.** 작은 화면이나 낮은 해상도에서는 추가 및 편집 대화상자가 창보다 커서 **만들기**와 **업데이트** 버튼에 닿지 못할 수 있었습니다. 이제 폼이 스크롤되며 버튼은 아래쪽에 유지됩니다.
- **Azure Blob Storage 문서 계정에서 256MiB를 초과하는 파일을 복사, 이동, 이름 바꾸기할 수 있습니다.** 이전에는 이러한 작업이 해당 크기의 파일에서 실패했으며, 그런 파일이 들어 있는 폴더를 이동하거나 이름을 바꿀 때도 실패했습니다.
- **Lakehouse v2에서 테이블의 행 수가 방금 기록된 내용을 반영합니다.** 테이블에 기록한 단계나 가져오기가 기록 이전의 행 수를 저장하는 경우가 있어, 방금 로드한 테이블이 0개 행으로 표시되거나 가져오기가 0개 행을 가져왔다고 보고할 수 있었습니다. 이제 새 행이 모든 곳에서 보이게 된 후 행 수를 읽으므로 이후 단계도 해당 행을 읽습니다. 테이블을 다른 브랜치로 전환하거나 브랜치를 테이블에 병합할 때도 행 수와 열 수가 업데이트됩니다.
- **Weave의 빈 값 검사가 이전 실행들이 실제로 남긴 내용과 각 실행을 비교합니다.** 단계의 빈 값이 단계가 테이블을 비우고 다시 채운 직후에 집계되는 경우가 많아 이전 실행에는 빈 값이 없는 것처럼 보였고, 항상 일부가 비어 있던 열이 방금 그렇게 된 것처럼 보고되었습니다. 이제 각 실행은 단계가 테이블을 남긴 상태 그대로 집계됩니다. 이전에 기록된 집계는 올바른 것과 구별할 수 없으므로 사용하지 않습니다. 각 단계의 빈 값 검사는 기록을 처음부터 다시 시작하며 다섯 번의 실행이 집계되기 전까지는 검사되지 않음으로 보고됩니다. 행 및 값 분포 검사도 더 이상 다른 단계가 같은 테이블에 단계 완료 후 2초가 지나서 수행한 쓰기를 해당 단계의 결과로 인정하지 않습니다. [Weave 점검 항목](/ko/guides/ai-assistant/weave-findings/)을 참조하십시오.
- **삭제된 연결을 REST API에 요청하면 404가 반환됩니다.** 삭제된 연결이나 존재하지 않는 ID를 요청하면 일반적인 서버 오류(500)로 응답했습니다. 이제 연결 ID를 지목하는 메시지와 함께 404를 반환합니다.

## 보안

- **계정의 소유자만 이전 버전을 복원할 수 있습니다.** 문서 계정을 이전 버전으로 복원하거나, 버전을 보류 또는 해제하거나, 백업을 수행하려면 이제 계정의 소유자 중 한 명이어야 하며, 시스템에서 관리하는 계정에서는 이 중 어느 것도 사용할 수 없습니다. 계정의 버전 기록을 보려면 계정에 대한 액세스가 필요합니다.
- **행이 제한된 테이블에 대한 DataFrame 쓰기, 레코드 저장, 지우기는 볼 수 있는 행만 변경합니다.** 행 액세스가 보이는 행을 제한하는 경우, DataFrame을 제한된 테이블에 쓰거나 Python 클라이언트로 지우는 작업, 또는 REST API로 레코드를 저장하거나 지우는 작업은 본인의 행만 변경하며, 액세스 범위를 벗어난 행이 포함된 로드는 아무것도 변경되기 전에 거부되고 발견된 값이 표시됩니다. 프로젝트 아키텍트, 모든 행을 보는 멤버, 워크플로 실행은 이전처럼 테이블 전체를 씁니다. 사람이 어느 테이블에든 수행하는 이러한 쓰기는 이제 모두 보안 로그에 기록됩니다. [제한된 테이블에 데이터 로드](/ko/administration/access/managing-security-groups-and-assignments/#제한된-테이블에-데이터-로드)를 참조하십시오.
