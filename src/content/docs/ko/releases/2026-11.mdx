## 추가됨

- **PlaidXL이 Excel에서 만들고, 드릴하고, 설명하고, 계획합니다.** **PlaidCloud** 리본 탭은 **연결**, **삽입**, **새로 고침**, **드릴**, **쓰기**, **공유**로 묶여 있으며, 자주 쓰는 명령은 **PlaidXL** 바로 가기 메뉴와 **PlaidXL Cell** 탭에도 있고, 주요 명령에는 변경할 수 있는 키보드 단축키가 있습니다. 로그인하기 전에 실행한 명령은 로그인 창을 열고 로그인한 후에 한 번 실행되며, Office에서 Microsoft Entra 회사 계정을 사용하면 PlaidXL이 워크스페이스를 자동으로 찾습니다. [PlaidXL 참조](/ko/reference/cli/plaidxl/)를 참조하십시오.
  - **몇 번의 클릭으로 보고서를 만듭니다.** **Report** 탭은 테이블에서 라이브 보고서를 구성하며, 한 차원은 행 방향으로, 다른 차원은 열 방향으로 드릴다운되고 모든 교차 지점에 `CELL` 값이 있습니다. **Build my first report**는 사용자의 데이터로 샘플을 만듭니다. 드릴하면 보고서가 행과 열 전체를 삽입하거나 제거하며, 직접 입력한 값, 메모, 서식은 해당 행과 함께 유지됩니다. [보고서 만들기](/ko/reference/cli/plaidxl/build-a-report/)를 참조하십시오.
  - **어느 셀에서든 드릴합니다.** **Drill down**, **Drill up**, **Keep only**, **Remove only**는 노드, 차원 제목 또는 보고서 값에서 노드를 라이브 `DRILL` 수식으로 바꾸고 수식을 대신 편집합니다. **Custom drill**은 삽입하기 전에 행을 미리 보여 주며, 멤버 선택기는 멤버를 삽입하거나 노드의 하위 항목 드롭다운을 셀에 추가합니다. `DRILL`은 제외하거나 열 노드를 받을 수 있고 행 방향으로도 실행할 수 있습니다. [드릴, 멤버 선택, 숫자 설명](/ko/reference/cli/plaidxl/drill/)을 참조하십시오.
  - **숫자를 설명합니다.** **Explain this number**는 값이 어떻게 계산되는지, 현재 PlaidCloud와 일치하는지, 그리고 값이 나온 테이블과 워크플로 단계를 보여 줍니다. **Show detail rows**는 값의 근거가 되는 행을 별도의 시트에 표시하고 합계가 맞는지 검사합니다.
  - **Excel의 관리되는 지표.** `PLAIDXL.METRIC`과 `PLAIDXL.METRIC_BREAKDOWN`은 대시보드에 표시되는 것과 같은 비즈니스 지표를 반환하며, **Metric...** 은 프로젝트의 지표를 현재 값과 함께 나열합니다. [지표](/ko/reference/cli/plaidxl/functions/#지표)를 참조하십시오.
  - **보고서에 입력하여 계획합니다.** `CELL` 값 위에 숫자를 입력하면 PlaidCloud에 기록됩니다. 비례 배분, 균등 배분, 다른 멤버의 형태에 따른 배분, 금액 또는 비율에 따른 조정이 가능하며 고정된 셀은 그대로 둡니다. 평균, 중앙값, 최솟값, 최댓값, 표준 편차, 분산 셀에도 입력한 값을 사용할 수 있습니다. **Undo last write**는 입력한 값과 저장을 최신 순으로 되돌립니다. [PlaidCloud에 값 입력](/ko/reference/cli/plaidxl/write-values/)을 참조하십시오.
  - **필요한 것만 새로 고칩니다.** 시트, 선택 영역 또는 모든 테이블을 새로 고치며, 작업 창에 각 테이블의 진행 상황과 **Cancel**이 표시됩니다. PlaidXL 수식만 다시 계산할 수도 있습니다. 가져온 테이블은 데이터 유형별로 서식이 지정된 Excel 표로 들어오고, 새로 고칠 때 사용자의 열과 숫자 서식을 유지하며, 제자리에서 새로 고쳐집니다. 테이블을 다시 가져와도 새로 고침 목록에 두 번 추가되지 않으며, **Stop refreshing**으로 하나를 목록에서 뺄 수 있고, 차원은 테이블과 함께 새로 고쳐집니다. [모든 테이블 새로 고침](/ko/reference/cli/plaidxl/retrieve/#모든-테이블-새로-고침)을 참조하십시오.
  - **저장하면 바로 기록되며 되돌릴 수 있습니다.** **Save to PlaidCloud**는 확인 없이 기록하고, 수행한 작업을 알려 주며, **Undo**를 제공합니다. 필터를 적용해 가져온 시트, 세부 행 시트, 또는 액세스 권한이 일부 행에만 해당하는 사용자는 해당 행만 교체하므로 다른 사용자의 행은 유지됩니다. [PlaidCloud에 테이블 저장](/ko/reference/cli/plaidxl/retrieve/#테이블을-plaidcloud에-저장)을 참조하십시오.
  - **Excel에서 Weave에 문의합니다.** **Weave** 탭에서 보고서, 수식, 드릴 또는 테이블을 쉬운 말로 요청하거나 **Weave에 문의: 이 셀**을 선택합니다. Weave는 사용자 권한으로 PlaidCloud를 읽고 통합 문서만 변경하며, 입력한 내용을 바꾸기 전에 먼저 묻고, 각 변경은 창을 다시 로드하기 전까지 되돌릴 수 있습니다. [Excel에서 Weave에 문의](/ko/reference/cli/plaidxl/weave/)를 참조하십시오.
  - **시트 하나 또는 통합 문서 전체의 값만 있는 사본을 공유합니다.** **Convert to values**는 통합 문서 전체, 시트 하나를 변환하거나 되돌릴 수 없는 값으로 변환하며, **Restore PlaidXL formulas**는 시트 이름을 바꾼 후에도 계속 작동합니다.
- **단계 양식에서 미리 보기.** 가져오기: SQL, Execute: SQL, SQL 추출, 내보내기: SQL, Salesforce: 개체 쿼리 단계는 단계를 실행하지 않고 최대 100개 행을 표시하며, Anaplan: 뷰 읽기와 Anaplan: 목록 읽기는 생성될 열과 유형을 표시합니다. **소스** 탭에서 **미리 보기**를 클릭하십시오. 변수는 실행 시와 같은 방식으로 채워지지만 `{x:>9}` 같은 변수 형식은 지원되지 않습니다. 미리 보기는 표준 SQL 함수만 실행하며, 그렇지 않으면 단계를 실행하라고 안내합니다. 잠긴 프로젝트나 에이전트 기반 Execute SQL 단계에서는 사용할 수 없습니다. [SQL 가져오기](/ko/reference/workflow-steps/import/import-sql/)와 [SQL 추출](/ko/reference/workflow-steps/tables/table-extract-sql/)을 참조하십시오.
- **사용 현황 보고서가 변경 내용을 보여 주고, 그룹으로 범위를 좁힐 수 있으며, 워크플로로 연결됩니다.** **개요**에는 이전 기간 대비 추세 화살표와, 비활성 멤버와 아무도 열지 않은 대시보드 및 앱을 알려 주는 **Highlights** 목록이 추가되었습니다. **그룹**은 **개요**, **내용**, 비활성 목록을 하나의 보안 그룹 멤버로 한정하며, 날짜 범위에는 **Previous month**와 **This month**가 추가되고 모든 탭이 공유하며 계정에 기억됩니다. 모든 수치에 설명이 추가되고, 표에는 **멤버**와 **Area**처럼 쉬운 이름이 사용되며, 행은 Enter로 열리고, 로드와 오류 표시가 더 명확해졌으며, 마지막 **퍼널** 단계는 그 단계를 완료한 멤버 수를 보여 줍니다. 새 **Get Workspace Usage** 단계는 멤버 이름 없이 일별 또는 월별 사용량 합계를 일정에 따라 테이블에 기록하며, **Get Workspace Members**처럼 각 실행이 보안 로그에 기록됩니다. [사용 현황 보고서](/ko/administration/access/usage-reports/)와 [Get Workspace Usage](/ko/reference/workflow-steps/general/get-workspace-usage/)를 참조하십시오.
- **AI 어시스턴트가 테이블 게시를 취소하고 프로젝트의 기본 대시보드 대상을 설정할 수 있습니다.** `publish_manage`는 테이블의 게시를 취소하면서 게시된 뷰와 어떤 차트도 사용하지 않는 대시보드 데이터셋도 함께 제거합니다. 차트가 아직 사용 중인 데이터셋은 남으며, 게시된 뷰를 기반으로 보고서 뷰가 만들어져 있으면 그 뷰와 데이터셋도 남지만 테이블의 게시는 취소됩니다. `project_upsert`는 프로젝트의 새 대시보드를 공유할 그룹인 `dashboard_default_audience`를 설정하며, `[]`는 이를 지웁니다. [게시 취소](/ko/guides/data/publish/#ai-어시스턴트-또는-mcp로-게시-취소)와 [AI 어시스턴트 또는 MCP로 기본 대상 설정](/ko/guides/dashboards/control-who-can-see-a-dashboard/#ai-어시스턴트-또는-mcp로-기본-대상-설정)을 참조하십시오.

- **Git 앱이 리포지토리를 나열하고 수행할 수 있는 작업을 알려 줍니다.** 앱 목록의 **Git**은 사용자의 역할(**Administrator**, **Contributor** 또는 **뷰어**)과 워크스페이스의 리포지토리를 표시하며, 각 리포지토리에는 설명, 마지막 업데이트 날짜, 복사 버튼이 있는 복제 주소, **열기**가 있습니다. **Set up Git on your computer** 카드는 Git 설치, 토큰 생성, 복제 방법을 안내하며, **How to clone**으로 다시 열 수 있습니다. **View all in Git**은 전체 Git 인터페이스를 열고 **Manage who can push**는 그룹 관리를 엽니다. 액세스 수준은 **뷰어**, **Contributor**(앱 코드를 `apps`에 푸시) 또는 **Administrator**(`udfs`를 포함한 모든 곳에 푸시)이며, 뷰어에게는 문의할 수 있는 워크스페이스 관리자가 최대 세 명까지 표시됩니다. 새 **Git Contributors** 그룹은 Contributor 권한을 부여하며 기본 그룹으로 지정할 수 있어 새 멤버가 자동으로 받습니다. **Git Administration**은 Admin 권한을 부여합니다. 멤버의 **Git** 탭에는 Git 사용자 이름, 수준, 이를 부여하는 그룹이 표시됩니다. 앱 창에는 **리포지토리** 섹션이 표시되고 UDF에는 **열기**가 있으며, Git에는 워크스페이스로 돌아가는 **← Back to** 링크가 있습니다. [PlaidCloud Git](/ko/guides/git/#git-열기)을 참조하십시오.
- **모바일의 Weave 음성은 한 번의 탭으로 사용합니다.** 마이크를 탭하고 질문하면 말을 멈춘 뒤 Weave가 한 번 전송합니다. 일찍 멈추려면 마이크를 다시 탭하며, 아무 소리도 들리지 않으면 저절로 꺼집니다. 말하는 도중에 **Weave** 탭을 벗어나거나 앱을 백그라운드로 보내면 입력한 말이 전송되지 않은 채 질문 상자에 남아 있어 검토할 수 있습니다. 실행, 일시 중지, 중지, 재개의 확인 창에서 실수로 두 번 탭해도 무시됩니다. 앱 버전 1.3.0 이상이 필요합니다. [음성 사용](/ko/guides/mobile-app/weave-on-mobile/#음성-사용)을 참조하십시오.

## 변경됨

- **단계 양식이 하나의 레이아웃을 따릅니다.** 탭은 표준 이름과 표준 순서를 사용합니다. General, Settings, Source, Columns, Filters, Output, Advanced 순이며, ERP 전기 양식에는 Header columns와 Line columns가 있습니다. 필수 필드에는 *가 표시되며, 양식은 단계에 필요한 항목만 저장을 막습니다.
- **프로젝트 복사가 테이블 데이터와 차원 멤버를 따로 선택하고, 데이터를 더 빠르게 복사하며, 비공개 복사본의 ERP 쓰기 승인을 유지합니다.** **복사할 데이터**에서 **테이블 데이터**를 선택하고(**테이블 데이터 없음**(기본값), **전체** 또는 **샘플**), 별도로 기본적으로 켜져 있는 **차원 멤버 복사**를 선택합니다. 따라서 테이블 행이 없는 복사본도 채워진 차원과 함께 만들어지며 빠르게 생성됩니다. **전체**와 **샘플** 복사는 여러 테이블을 동시에 복사하므로 테이블이 많은 프로젝트가 더 빨리 끝납니다. **복사 결과**는 테이블과 함께 각 차원의 결과를 나열하며, **Retry failed items**는 실패한 테이블과 차원을 함께 다시 시도합니다. 데이터와 함께 만든 새 복사본은 사용자에게만 비공개이며, 사용자가 직접 부여할 수 있는 소스의 ERP 쓰기 승인을 유지합니다. 소스가 Live로 전기하는 경우 복사본은 Simulate 상태로 만들어지므로 Live로 전환하기 전에는 ERP에 아무것도 전달되지 않습니다. REST API와 `project_copy` MCP 도구도 `dimension_members`를 받습니다. [복사할 데이터 양 선택](/ko/guides/projects/managing-projects/#복사할-데이터-양-선택)과 [복사본의 ERP 쓰기 승인](/ko/guides/projects/managing-projects/#복사본의-erp-쓰기-승인)을 참조하십시오.
- **행 작업 메뉴(⋯)가 모든 그리드 행의 왼쪽 가장자리에 있습니다.**
- **앱 탭 아이콘이 라이트 모드와 다크 모드 모두에서 하나의 일관된 세트로 통일되었습니다.**
- **유효성 검사 설정이 없는 저장된 ERP 쓰기 단계는 유효성 검사 전용으로 열립니다.** SAP Post, SAP Attach, NetSuite Post, Oracle EBS GL 및 AP Post, Xero 내보내기가 여기에 해당합니다. 명시적으로 라이브 실행으로 설정된 단계는 라이브로 유지됩니다.
- **오래 걸리는 작업이 어디서나 같은 방식으로 진행 상황을 표시합니다.**
- **워크플로를 중지하면 워크플로가 시작한 모든 것이 중지되며, 끝낼 수 없는 실행이나 단계는 멈춰 있지 않고 실패합니다.** 중지하면 아직 대기열에 있던 가져오기 및 차원 단계가 취소되므로 워크스페이스의 이후 가져오기와 차원 로드가 정상적으로 시작되며, 워크플로의 대기 중이거나 실행 중인 커넥터(Singer) 동기화도 중지됩니다. 단계의 작업을 시작할 수 없으면 단계는 영원히 기다리지 않고 이유와 함께 실패합니다. 약 40분 안에 어떤 워커도 시작하지 않은 경우, 워커가 시작한 후 사라진 경우, 포드가 약 20분간 Pending 상태에 머문 경우, 이미지를 약 5분간 가져올 수 없는 경우, 약 20분간 포드가 생성되지 않는 경우입니다. 약 30분 안에 어떤 러너도 가져가지 않은 커넥터 동기화는 해당 동기화를 지목하는 메시지와 함께 실패합니다. 단계가 워커를 기다리는 동안 상태 메시지에는 지금까지 경과한 시간(분)과 함께 "워커를 기다리는 중…"이라고 표시되며, 작업이 시작되면 사라집니다. 매크로를 중지하면 실행 중인 모든 복사본이 중지되며, 다른 워크플로 안에서만 실행 중인 매크로는 워크플로 목록에 **실행 중**으로 표시되고 **중지**를 사용할 수 있으며 각 단계의 상태, 시작 및 종료 시간은 가장 최근 실행에서 가져옵니다. 서버가 유실된 실행은 실패로 끝나며, 12시간 후에도 계속 실행 중인 실행은 "실행 실패: 12시간 제한에서도 계속 실행 중입니다. 워크플로를 다시 실행하십시오."와 함께 실패합니다. [워크플로 실행](/ko/guides/workflows/run-a-workflow/#시작되지-않는-단계)을 참조하십시오.
- **재개, 실행 기록, 실행 상태가 실제로 실행된 내용과 일치합니다.** 상위 워크플로를 재개하면 하위 워크플로가 남긴 모든 것이 실행되며, 하위 워크플로의 단계를 따로 다시 실행한 경우에도 마찬가지이고, 한 번의 실행 안에서 하위 워크플로를 호출할 때마다 고유한 실행 기록 항목이 생깁니다. 서버가 중지되어 다시 시작하는 단계는 로그에 그 사실을 기록하며, `workflow_run_status`와 REST API의 실행 결과는 실패했지만 계속 진행된 단계를 실행이 정상이라고 보고하는 대신 `continued_step_ids`와 `continued_step_count`에 나열합니다. [일시 중지, 중지, 재개](/ko/guides/workflows/run-a-workflow/#일시-중지-중지-재개)와 [오류 발생 시 계속](/ko/guides/workflows/continue-on-error/)을 참조하십시오.
- **단계 오류가 자체 메시지를 표시합니다.** PlaidCloud가 예상하지 못한 오류는 "단계가 예기치 않은 오류(*type*)로 중지되었습니다: *message*"로 표시됩니다. 런처의 **조치 필요** 카드는 오류를 한 줄로 표시하며, 이후 삭제된 워크플로의 실행은 제외합니다. [단계 오류 관리](/ko/guides/workflows/managing-step-errors/)를 참조하십시오.
- **끝나지 않는 ERP 추출은 해당 단계를 실패시키며, 재개하면 이어서 진행됩니다.** **SAP: 임시 추출**이 행 또는 시간 제한에서 일시 중지되거나 에이전트가 제때 응답하지 않는 경우, 또는 단계가 대기를 멈출 때 Salesforce, Oracle Fusion 대량 또는 HFM/FCCS 내보내기 작업이 아직 실행 중인 경우, 단계가 실패하므로 이후 단계가 일부만 채워진 테이블에서 실행되지 않습니다. 워크플로를 재개하거나 단계를 다시 실행하면 추출이 중단된 지점부터 같은 작업에서 이어집니다. [실행 제한](/ko/guides/connections/sap-adhoc-extract/#실행-제한)과 [Salesforce: 개체 쿼리](/ko/reference/workflow-steps/salesforce/query-salesforce-object/#실행이-끝나지-않는-경우)를 참조하십시오.
- **REST, Import REST, Import Postman 단계는 워크스페이스를 업그레이드할 때 REST 요청으로 변환됩니다.** 깔끔하게 변환할 수 없는 단계는 그대로 유지됩니다. [REST 요청 단계](/ko/guides/workflows/rest-request-step/)를 참조하십시오.
- **프로젝트 아키텍트는 행이 제한된 테이블의 모든 행을 대시보드에서 볼 수 있으며**, Analyze에서 보는 것과 일치합니다. 아키텍트 액세스를 제거하면 대시보드에 즉시 반영됩니다. 누군가의 역할을 바꾸거나, 그 사람이나 그룹을 프로젝트에서 제거하거나, 프로젝트의 액세스 유형을 바꾸거나, 이전 프로젝트 버전을 복원하거나, 보안 그룹을 삭제하는 경우가 모두 해당합니다. 이전 아키텍트는 더 이상 행이 제한된 데이터의 모든 행을 볼 수 없습니다. [행 액세스 관리](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리)를 참조하십시오.
- **세션이 만료된 후 열린 대시보드 링크는 로그인하면 해당 대시보드로 이동합니다.** [대시보드 사용](/ko/guides/dashboards/using-dashboards/)을 참조하십시오.
- **MCP 도구는 인식하지 못하는 필드를 무시하는 대신 거부하고** 오류에 해당 필드를 명시합니다. `workflow_upsert`는 `memo`를 받으며 `description`을 그 다른 이름으로 허용합니다. [알 수 없는 필드는 거부됨](/ko/integrations/ai-coding-agents/getting-started/#알-수-없는-필드는-거부됩니다)을 참조하십시오.
- **Lakehouse v2에서는 레이크하우스가 Parquet 내보내기를 Google Cloud Storage에 직접 기록합니다.** Google Cloud Storage 문서 계정으로의 내보내기는 모든 행이 먼저 PlaidCloud를 거치는 대신 계정 자체의 자격 증명으로 계정의 버킷에 바로 기록됩니다. Amazon S3 및 Azure Blob Storage 계정으로의 내보내기는 이전과 같이 작동합니다. [Parquet로 내보내기](/ko/reference/workflow-steps/export/export-to-parquet/)를 참조하십시오.
- **Slack, Microsoft Teams, Web Hook 단계가 메시지가 전송되지 않은 이유를 알려 줍니다.** 단계의 오류에는 연결을 시도한 서버와, Slack 및 Teams의 경우 연결이 명시되며, 무엇이 잘못되었는지도 알려 줍니다. 예를 들어 Slack이 더 이상 웹훅을 인식하지 못하는 경우, 채널에 게시할 수 없는 경우, 서버를 찾을 수 없거나 60초 안에 응답하지 않는 경우, 연결이 삭제된 경우입니다. 웹훅 URL이 있으면 누구나 사용자의 통합으로 게시할 수 있으므로 Slack 또는 Teams 웹훅 URL은 절대 표시되지 않습니다. [Slack으로 알림](/ko/reference/workflow-steps/notifications/notify-via-slack/)을 참조하십시오.

## 수정됨

- **잘못된 프로젝트 설정이 명확한 메시지로 보고됩니다.** 알 수 없는 환경 또는 문서 계정, 이미 사용 중이거나 예약된 슬러그, 잘못된 스토리지 유형 또는 전기 모드는 이제 일반적인 서버 오류 대신 문제를 명시한 메시지를 반환합니다. REST API에서는 500이 아닌 400이며, AI 어시스턴트 또는 MCP에서는 잘못된 인수 오류입니다.
- **REST API의 차원 값 요청이 작동합니다.** `POST /rest/v1/analyze/query/retrieve-dimension-values`가 그리드 요청으로 처리되어 잘못된 요청으로 거부되었습니다. 이제 `value_columns`의 각 열에 대해 집계된 값 하나를 반환하며, 행 필터와 열 필터의 각 쌍마다 값 하나를 반환하는 그리드에는 전용 `POST /rest/v1/analyze/query/retrieve-dimension-cells`가 있습니다.
- **느린 테이블 읽기와 파일 처리가 더 이상 다른 요청을 지연시키지 않습니다.** 웨어하우스에서 테이블의 열 읽기, Data Foundation 파일 등록, Excel로 내보내기, REST 또는 SOAP 가져오기 응답 읽기, 문서 계정이 사용되는 위치 찾기, Panel 앱의 코드 또는 로고 검사는 각각 완료될 때까지 같은 서버가 처리하던 다른 모든 요청을 멈출 수 있었습니다. 이제는 그러한 요청과 나란히 실행됩니다.
- **프로젝트 및 워크플로 변수 대화 상자가 스크롤됩니다.** 작은 화면이나 낮은 해상도에서 추가 및 편집 대화 상자가 창보다 커서 **만들기**와 **업데이트** 버튼에 손이 닿지 않을 수 있었습니다. 이제 양식이 스크롤되며 버튼은 맨 아래에 유지됩니다.
- **Azure Blob Storage 문서 계정의 256MiB 초과 파일을 복사, 이동, 이름 바꾸기 할 수 있습니다.** 이전에는 이 크기의 파일에서 각 작업이 실패했으며, 그러한 파일이 들어 있는 폴더를 이동하거나 이름을 바꾸는 작업도 실패했습니다.
- **Lakehouse v2에서 테이블의 행 수가 방금 기록된 내용을 반영합니다.** 테이블을 기록한 단계나 가져오기가 기록 전의 행 수를 저장할 수 있어서, 방금 로드한 테이블이 0개 행으로 표시되거나 가져오기가 0개 행을 가져왔다고 보고할 수 있었습니다. 이제 새 행이 모든 곳에서 보이게 된 후에 행 수를 읽으므로 이후 단계도 해당 행을 읽습니다. 테이블을 다른 브랜치로 전환하거나 브랜치를 테이블에 병합할 때도 행 수와 열 수가 업데이트됩니다.
- **Weave의 빈 값 검사는 각 실행을 이전 실행이 실제로 남긴 내용과 비교합니다.** 단계의 빈 값은 단계가 테이블을 비우고 다시 채운 직후에 집계되는 경우가 많아서 이전 실행에는 빈 값이 없는 것처럼 보였고, 항상 일부가 비어 있던 열이 방금 비게 된 것처럼 보고되었습니다. 이제 각 실행은 단계가 테이블을 남긴 상태 그대로 집계됩니다. 이전에 기록된 수치는 올바른 것과 구별할 수 없으므로 사용하지 않습니다. 각 단계의 빈 값 검사는 기록을 처음부터 다시 시작하며, 실행 5회가 집계될 때까지 검사되지 않은 것으로 보고됩니다. 행 및 값 분포 검사도 더 이상 다른 단계가 완료 후 2초보다 늦게 같은 테이블에 수행한 쓰기를 해당 단계의 쓰기로 인정하지 않습니다. [Weave 점검 항목](/ko/guides/ai-assistant/weave-findings/)을 참조하십시오.
- **삭제된 연결을 REST API에 요청하면 404를 반환합니다.** 삭제된 연결이나 존재하지 않는 ID를 요청하면 일반적인 서버 오류(500)로 응답했습니다. 이제 연결 ID를 명시한 메시지와 함께 404를 반환합니다.

## 보안

- **행 액세스를 저장해도 소스에 더 이상 없는 부여된 값이 유지됩니다.** 보안 그룹에 부여된 값은 테이블에 해당 값을 가진 행이 없거나, 차원에서 멤버가 사라졌거나, 목록에 더 이상 없으면 다음 저장 때 부여에서 빠졌습니다. 그러면 선택된 값이 없게 된 그룹이 **그 외 모든 사용자** 설정으로 되돌아갔고, 이는 모든 행을 의미할 수 있었습니다. 이제 값은 표시가 붙은 채 그리드에 남으며, **저장**은 유지할지 제거할지 묻습니다. [행 액세스 그리드](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-그리드)를 참조하십시오.
- **계정의 소유자만 이전 버전을 복원할 수 있습니다.** 문서 계정을 이전 버전으로 복원하거나, 버전을 보류 또는 해제하거나, 백업을 만들려면 이제 계정의 소유자 중 한 명이어야 하며, 시스템에서 관리하는 계정에서는 이 중 어느 것도 사용할 수 없습니다. 계정의 버전 기록을 보려면 계정에 대한 액세스가 필요합니다.
- **데이터를 읽기만 해야 하는 쿼리가 더 이상 데이터를 변경할 수 없습니다.** AI 어시스턴트와 MCP 클라이언트가 사용하는 `query_run` 도구는 데이터를 읽는 문, 즉 SELECT 또는 WITH 문 하나, 그 EXPLAIN, 또는 SHOW만 실행하며 그 밖의 것은 실행하지 않고 거부합니다. 데이터를 변경하려면 `query_transform`을 사용하십시오. MCP 테이블 내보내기의 SQL도 같은 규칙을 따릅니다. REST 및 JSON-RPC API에서는 프로젝트 데이터를 변경할 수 없는 멤버에 대해 쿼리 실행, 열 패싯 생성, 쿼리를 CSV로 다운로드, 쿼리를 원격 데이터베이스로 내보내기, 자체 쿼리로 테이블 데이터 내보내기에도 적용되며, 거부된 쿼리는 403을 반환합니다. Explain Analyze는 측정을 위해 쿼리를 실행하므로, 쿼리 로그와 레이크하우스에서는 이제 읽기 쿼리만 허용하며 행 액세스가 있는 프로젝트에서는 프로젝트 아키텍트만 쿼리 로그에서 실행할 수 있습니다.
- **행이 제한된 테이블에 대한 DataFrame 쓰기, 레코드 저장, 지우기는 볼 수 있는 행만 변경합니다.** 행 액세스가 행을 제한할 때, Python 클라이언트로 DataFrame을 제한된 테이블에 쓰거나 테이블을 지우는 작업, 또는 REST API로 레코드를 저장하거나 지우는 작업은 본인의 행만 변경하며, 액세스 범위를 벗어난 행이 포함된 로드는 아무것도 변경되기 전에 발견된 값을 명시하여 거부됩니다. 프로젝트 아키텍트, 모든 행을 볼 수 있는 멤버, 워크플로 실행은 이전과 같이 테이블 전체를 씁니다. 사람이 어떤 테이블에 수행하는 이러한 쓰기는 모두 이제 보안 로그에 기록됩니다. [제한된 테이블에 데이터 로드](/ko/administration/access/managing-security-groups-and-assignments/#제한된-테이블에-데이터-로드)를 참조하십시오.
- **가져오기, 복사, 복원, 삭제가 더 이상 볼 수 없는 행을 교체하지 않습니다.** 행 액세스가 행을 제한할 때, 제한된 테이블로 파일 가져오기, 다른 프로젝트에서 테이블 복사, 브랜치 전환 또는 병합, 복원, 삭제, 테이블 전체를 교체하는 그 밖의 모든 작업은 볼 수 없는 행이 테이블에 있는 동안 거부되며 아무것도 변경되지 않습니다. REST API로 테이블의 행을 저장하는 작업도 이제 다른 로드와 마찬가지로 본인의 행만 변경합니다. 프로젝트 아키텍트, 모든 행을 볼 수 있는 멤버, 워크플로 실행은 영향을 받지 않으며, 이러한 작업도 보안 로그에 기록됩니다.
