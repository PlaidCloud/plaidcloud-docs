## 추가됨

- **PlaidXL에서 Excel로 보고서를 만들고, 드릴하고, 설명하고, 계획합니다.** **PlaidCloud** 리본 탭은 **연결**, **삽입**, **새로 고침**, **Drill**, **쓰기**, **공유**로 구성되며, 자주 쓰는 명령은 **PlaidXL** 바로 가기 메뉴와 **PlaidXL Cell** 탭에서도 사용할 수 있습니다. 주요 명령에는 변경할 수 있는 키보드 단축키가 있으며, 필드에 입력하는 동안에는 작동하지 않습니다. 명령이 실패하면 어떤 명령이 왜 실패했는지 알려 줍니다. 로그인하기 전에 명령을 실행하면 로그인 창이 열리고 로그인한 후 한 번 실행됩니다. 로그인은 하나의 워크스페이스에서만 유효하므로 워크스페이스를 전환하면 새 워크스페이스에 로그인하라는 안내가 표시되고(다시 돌아올 때는 표시되지 않음), Office에서 Microsoft Entra 업무 계정을 사용하면 PlaidXL이 워크스페이스를 자동으로 찾습니다. [PlaidXL 참조](/ko/reference/cli/plaidxl/)를 참조하십시오.
  - **몇 번의 클릭으로 보고서를 만듭니다.** **보고서** 탭은 테이블에서 실시간 보고서를 구성합니다. 한 차원은 행 방향으로, 다른 차원은 열 방향으로 드릴하고, 교차 지점마다 `CELL` 값을 둡니다. **Build my first report**는 내 데이터로 샘플을 만듭니다. 드릴하면 보고서가 행과 열 전체를 삽입하고 제거하며, 직접 입력한 값, 메모, 서식은 해당 행과 함께 유지됩니다. [보고서 만들기](/ko/reference/cli/plaidxl/build-a-report/)를 참조하십시오.
  - **모든 셀에서 드릴합니다.** **Drill down**, **Drill up**, **Keep only**, **Remove only**는 노드, 차원 제목 또는 보고서 값에서 노드를 실시간 `DRILL` 수식으로 바꾸고 대신 편집해 줍니다. **Custom drill**은 삽입하기 전에 행을 미리 보여 주며, 멤버 선택기는 멤버를 삽입하거나 노드의 하위 항목 드롭다운을 셀에 추가합니다. `DRILL`은 제외하거나 펼칠 노드를 받을 수 있고 행 전체에 걸쳐 실행할 수 있습니다. [드릴, 멤버 선택, 숫자 설명](/ko/reference/cli/plaidxl/drill/)을 참조하십시오.
  - **숫자를 설명합니다.** **Explain this number**는 값이 어떻게 계산되는지, 지금 PlaidCloud와 일치하는지, 그리고 값의 출처가 되는 테이블과 워크플로 단계를 보여 줍니다. **Show detail rows**는 값의 근거가 되는 행을 별도의 시트에 표시하고 합계가 일치하는지 검사합니다.
  - **Excel의 관리되는 지표.** `PLAIDXL.METRIC`과 `PLAIDXL.METRIC_BREAKDOWN`은 대시보드에 표시되는 방식 그대로 비즈니스 지표를 반환합니다. 집계할 항목이 없는 `CELL` 또는 `CELLS`는 합계의 경우 `0`을, 그 외에는 이유와 함께 `#VALUE!`를 표시하며(`CELLS` 스필에서는 비어 있음), **Metric...** 항목은 프로젝트의 지표와 현재 값을 나열합니다. 지표는 둘 이상의 대체 계층으로 필터링할 수 있으며, 대체 계층의 멤버와 다른 차원의 멤버를 함께 사용할 수 있습니다. [지표](/ko/reference/cli/plaidxl/functions/#지표)를 참조하십시오.
  - **보고서에 직접 입력하여 계획합니다.** `CELL` 값 위에 숫자를 입력하면 PlaidCloud에 기록됩니다. 비례 배분, 균등 배분, 다른 멤버의 분포에 맞춘 배분, 금액 또는 백분율 조정을 사용할 수 있으며, 고정된 셀은 그대로 유지됩니다. 평균, 중앙값, 최솟값, 최댓값, 표준편차, 분산 셀도 입력한 값을 받으며, 입력한 값은 행이나 열을 삽입하거나 삭제해도 해당 셀을 따라갑니다(삭제된 셀의 값은 보고됨). **Undo last write**는 입력한 값과 저장을 최신 항목부터 되돌리며, 기록을 만든 사람과 워크스페이스만 되돌릴 수 있습니다. 합계나 빈 셀에 입력한 평균을 되돌리면 이후 같은 셀에 기록된 내용은 유지되며, 완료되기 전에 중단된 기록은 되돌릴 수 없습니다. [PlaidCloud에 값 입력](/ko/reference/cli/plaidxl/write-values/)을 참조하십시오.
  - **필요한 것만 새로 고칩니다.** 시트, 선택 영역 또는 모든 테이블을 새로 고치거나, PlaidXL 수식만 다시 계산할 수 있으며, 작업 창에 각 테이블의 진행 상황과 **취소**가 표시됩니다. 검색된 테이블은 데이터 형식에 맞게 서식이 지정된 Excel 테이블로 도착하고, 새로 고칠 때 사용자의 열과 숫자 서식이 유지되며, 제자리에서 새로 고쳐집니다. 검색하거나 새로 고쳐도 다른 셀을 덮어쓰거나 다른 Excel 테이블과 겹치지 않으며, Excel에서 다룰 수 없을 만큼 큰 정수 ID와 1900년 이전 날짜는 텍스트로 도착합니다. 테이블을 다시 검색해도 새로 고침 목록에 두 번 추가되지 않고, **Stop refreshing**은 목록에서 하나를 제거하며, 차원은 테이블과 함께 새로 고쳐집니다. [모든 테이블 새로 고침](/ko/reference/cli/plaidxl/retrieve/#refresh-all-tables)을 참조하십시오.
  - **저장하면 바로 기록되며 되돌릴 수 있습니다.** **Save to PlaidCloud**는 확인 없이 기록하고 수행한 작업을 알려 주며 **실행 취소**를 제공합니다. 실행 취소는 Lakehouse 테이블에서 저장 후 최대 7일 동안 사용할 수 있습니다. 필터로 검색한 시트, 세부 행 시트, 또는 일부 행에만 액세스할 수 있는 사용자의 경우 해당 행만 교체되므로 다른 사용자의 행은 유지됩니다. 검색한 이후 멤버가 변경된 드릴스루 시트는 저장되지 않으며, 저장에 실패하면 테이블을 복원할 수 있도록 복원 지점의 이름이 표시됩니다. [PlaidCloud에 테이블 저장](/ko/reference/cli/plaidxl/retrieve/#테이블을-plaidcloud에-저장)을 참조하십시오.
  - **Excel에서 Weave에 문의합니다.** **Weave** 탭에서 보고서, 수식, 드릴, 테이블을 일상적인 말로 요청하거나 **Ask Weave about this cell**을 선택합니다. Weave는 사용자 권한으로 PlaidCloud를 읽고 통합 문서만 변경하며, 입력한 내용을 바꾸기 전에 먼저 묻고, 통합 문서 밖을 참조하는 수식은 작성하지 않습니다. 각 변경은 창을 다시 로드하기 전까지 되돌릴 수 있습니다. [Excel에서 Weave에 문의](/ko/reference/cli/plaidxl/weave/)를 참조하십시오.
  - **시트 하나 또는 통합 문서 전체의 값 전용 사본을 공유합니다.** **Convert to values**는 통합 문서 전체, 시트 하나 또는 되돌릴 수 없는 값으로(먼저 확인함) 변환하며, PlaidXL 수식과 해당 스필만 변경하고, 아직 계산 중인 수식은 다시 시도할 수 있도록 남겨 둡니다. **Restore PlaidXL formulas**는 시트 이름을 바꾼 후에도 계속 작동합니다.
- **전기 등록부는 내 확인이 필요한 항목에서 시작합니다.** 확인이 필요한 항목이 있으면 **예외**에서, 승인을 기다리는 요청이 있으면 **승인**에서, 그렇지 않으면 **모든 전기**에서 열립니다. 레일은 화면을 **내 확인 필요**, **등록부**, **인사이트**, **설정**으로 묶고 **예외**와 **승인**에 개수를 표시합니다. 모든 화면은 하나의 머리글과 범위 표시줄을 공유하며, 기간(**이번 달**, **이전 달**, **지난 7일**, **지난 30일**, **사용자 지정**), 연결, 프로젝트, 환경 또는 엔터티, 그리고 **실거래**, **시뮬레이션** 또는 **모두**를 선택한 다음 **재설정**하거나 **저장된 범위**를 유지할 수 있습니다. 마지막으로 사용한 범위는 기억됩니다.
  - **예외는 확인이 필요한 항목을 정리합니다.** **Needs a look**, **미확인**, **대기 중**, **실패**, **Reversal outstanding** 칩에 각각의 개수가 표시되고, 연결 상태 줄에는 "All N connections posting normally"라고 표시되며, 모든 전기에는 다음에 할 일을 알려 주는 툴팁이 있는 쉬운 말의 상태가 표시됩니다. 열려 있는 항목이 없으면 **All clear**가 표시됩니다. **Find a posting by ledger id** 또는 명령 팔레트에 원장 ID를 붙여 넣으면 해당 전기가 바로 열립니다.
  - **승인, 위임, 감시는 받은 편지함 화면입니다.** **Waiting on me**와 **Submitted by me**를 전환하고, 사유와 함께 **승인**하거나 **거부**하며, 여러 건을 한 번에 승인하고, 알림 메시지에서 승인을 **실행 취소**할 수 있습니다. **Delegate approvals**는 짧은 대화 상자이고, **내 감시 목록**에는 팔로우 중인 항목이 나열됩니다. **전기 되돌리기**와 일괄 다시 시도 및 지우기 대화 상자는 하나의 레이아웃을 공유합니다.
  - **전기 서랍에서 무슨 일이 있었는지 알 수 있습니다.** 상태와 그 의미, 이름이 붙은 주요 사실, **Lines**, **기록**, **승인** 탭이 표시되며, **검토됨으로 표시**, **다시 시도**, **되돌리기…**, **연결 감시**, **실행 감시**, **Copy link**를 사용할 수 있습니다. **Copy link**는 해당 전기를 바로 엽니다.
  - **지원, 내보내기, 보존에도 같은 디자인이 적용됩니다.** **지원**에는 질문 상자와 인사이트 카드, **Draft — nothing applied**로 표시된 조언, 그리고 **모든 전기**의 이상 징후 카드와 **보기**가 있습니다. **내보내기 및 알림**에는 **New schedule**이 있고, **보존**은 카드 하나입니다.
  - **등록부는 항상 최신 상태로 유지됩니다.** 전기가 바뀌면 레일 배지가 업데이트되고, 열려 있는 목록은 전기가 변경되었을 때 **새로 고침**을 제공하며, 열려 있는 서랍은 제자리에서 업데이트됩니다. **홈**에는 **조치 필요** 아래에 **전기 등록부** 카드가 표시됩니다. [전기 등록부 검토](/ko/guides/connections/posting-register/)를 참조하십시오.
- **단계 양식의 미리 보기.** Import: SQL, Execute: SQL, Extract: SQL, Export: SQL, Salesforce Query 단계는 단계를 실행하지 않고도 최대 100개 행을 보여 주며, Anaplan 뷰 및 목록 읽기는 생성될 열과 유형을 보여 줍니다. **소스** 탭에서 **미리 보기**를 클릭하십시오. 변수는 실행할 때와 같은 방식으로 채워지지만 `{x:>9}`와 같은 변수 형식은 지원되지 않습니다. 미리 보기는 표준 SQL 함수만 실행하며, 그렇지 않으면 단계를 실행하라고 안내합니다. 잠긴 프로젝트나 에이전트 기반 Execute SQL 단계에서는 사용할 수 없습니다. [SQL 가져오기](/ko/reference/workflow-steps/import/import-sql/) 및 [SQL 추출](/ko/reference/workflow-steps/tables/table-extract-sql/)을 참조하십시오.
- **사용 현황 보고서는 변경된 내용을 보여 주고, 그룹으로 범위를 좁히며, 워크플로로 연결됩니다.** **개요**에는 이전 기간 대비 추세 화살표와, 비활성 멤버와 아무도 열지 않은 대시보드 및 앱을 알려 주는 **Highlights** 목록이 추가되었습니다. 비활성화된 멤버는 집계나 비활성 목록에 포함되지 않습니다. **그룹**은 **개요**, **내용**, 비활성 목록을 하나의 보안 그룹 멤버로 한정하며, 날짜 범위에 **Previous month**와 **This month**가 추가되어 모든 탭에서 공유되고 계정에 기억됩니다. 이제 모든 수치에 설명이 있고, 테이블에는 **멤버**와 **Area**처럼 쉬운 이름이 사용되며, Enter 키로 행이 열리고, 로딩과 오류 표시가 더 명확해졌으며, 마지막 **퍼널** 단계는 몇 명의 멤버가 완료했는지 보여 줍니다. 새로운 **Get Workspace Usage** 단계는 멤버 이름 없이 일별 또는 월별 사용량 합계를 일정에 따라 테이블에 기록하며, **Get Workspace Members**와 마찬가지로 각 실행이 보안 로그에 기록됩니다. [사용 현황 보고서](/ko/administration/access/usage-reports/) 및 [Get Workspace Usage](/ko/reference/workflow-steps/general/get-workspace-usage/)를 참조하십시오.
- **AI 어시스턴트가 테이블의 게시를 취소하고 프로젝트의 기본 대시보드 대상을 설정할 수 있습니다.** `publish_manage`는 테이블의 게시를 취소할 때 게시된 뷰와 어떤 차트에서도 사용하지 않는 대시보드 데이터 세트도 함께 취소합니다. 차트가 아직 사용하는 데이터 세트는 그대로 유지되며, 보고서 뷰가 게시된 뷰를 기반으로 만들어진 경우 해당 뷰와 데이터 세트도 유지되지만 테이블의 게시는 취소됩니다. `project_upsert`는 프로젝트의 새 대시보드를 공유할 그룹인 `dashboard_default_audience`를 설정하며, `[]`는 이를 지웁니다. [게시 취소](/ko/guides/data/publish/#ai-어시스턴트-또는-mcp로-게시-취소) 및 [AI 어시스턴트 또는 MCP로 기본 대상 설정](/ko/guides/dashboards/control-who-can-see-a-dashboard/#ai-어시스턴트-또는-mcp로-기본-대상-설정)을 참조하십시오.

- **Git 앱이 리포지토리를 나열하고 수행할 수 있는 작업을 알려 줍니다.** 앱 목록의 **Git**에는 사용자의 역할(**Administrator**, **Contributor** 또는 **뷰어**)과 워크스페이스의 리포지토리가 표시되며, 각 리포지토리에는 설명, 마지막 업데이트 날짜, 복사 버튼이 있는 복제 주소, **열기**가 있습니다. **Set up Git on your computer** 카드는 Git 설치, 토큰 만들기, 복제 과정을 안내하며, **How to clone**으로 다시 열 수 있습니다. **View all in Git**은 전체 Git 인터페이스를 열고 **Manage who can push**는 그룹 관리를 엽니다. 액세스 수준은 **뷰어**, **Contributor**(`apps`에 앱 코드 푸시) 또는 **Administrator**(`udfs`를 포함한 모든 곳에 푸시)이며, 뷰어에게는 문의할 수 있는 워크스페이스 관리자가 최대 세 명까지 표시됩니다. 새로운 **Git Contributors** 그룹은 Contributor 권한을 부여하며 기본 그룹으로 지정할 수 있으므로 새 멤버가 자동으로 권한을 받습니다. **Git Administration**은 관리자 권한을 부여합니다. 멤버의 **Git** 탭에는 Git 사용자 이름, 수준, 권한을 부여하는 그룹이 표시됩니다. 멤버의 Git 계정은 멤버십을 따릅니다. 멤버를 비활성화하거나 제거하면 약 1시간 이내에 토큰과 SSH 키를 포함한 Git 계정이 차단되고, 다시 활성화하면 차단이 해제되며, 리포지토리와 기록은 유지됩니다. 싱글 사인온으로 Git에 로그인하면 멤버 본인의 계정이 열립니다. Contributor는 워크스페이스의 Git 조직에 리포지토리를 직접 만들지 않으며, 리포지토리는 PlaidCloud를 통해 만들어집니다. 앱 창에는 **Repository** 섹션이 표시되고 UDF에는 **열기**가 있으며, Git에는 워크스페이스로 돌아가는 **← Back to** 링크가 있습니다. 앱 리포지토리와 기본 제공 `apps` 및 `udfs` 리포지토리를 포함하여 플랫폼이 만드는 모든 리포지토리는 워크스페이스에 로그인한 모든 멤버가 읽을 수 있으므로, 멤버는 리포지토리별 설정 없이 앱을 열고 다시 게시할 수 있습니다. Git 관리자는 여전히 리포지토리를 비공개로 만들 수 있으며, 이 경우 리포지토리 선택기에서 숨겨지고 멤버가 해당 리포지토리에서 게시하거나 그 안에 저장된 Git 기반 UDF 코드를 실행할 수 없게 됩니다. [PlaidCloud Git](/ko/guides/git/#git-열기) 및 [리포지토리를 볼 수 있는 사용자](/ko/guides/connections/plaidcloud-git/#리포지토리를-볼-수-있는-사용자)를 참조하십시오.
- **Cost to Serve 및 Operational Transfer Pricing 템플릿은 Common Finance Model을 기반으로 합니다.** **Cost to Serve**로 프로젝트를 시작하면 각 부서에 설정한 활동과 동인에 따라 영업 비용을 고객에게 배분하고, 총계정원장과 연결된 상태로 고객별로 서비스 제공 비용을 반영한 마진을 볼 수 있습니다. **Operational Transfer Pricing**으로 시작하면 각 엔터티의 이익 수준(매출 수익률, 순비용 가산 또는 재판매가 차감)을 정책 범위와 비교하여 테스트하고, 범위를 벗어난 엔터티를 목표로 되돌리는 정산을 확인할 수 있습니다. 매출 수익률은 EBIT를 검증 대상 당사자 매출로 나눈 값입니다. [Cost to Serve](/ko/guides/projects/cost-to-serve/) 및 [Operational Transfer Pricing](/ko/guides/projects/operational-transfer-pricing/)을 참조하십시오.
- **OneStream과 Anaplan이 Data Foundation에 데이터를 제공하며, OneStream에는 읽기 단계가 있습니다.** Data Foundation은 OneStream 관리자가 만드는 데이터 어댑터를 통해 OneStream 연결 결과를, 내보내기 작업을 통해 Anaplan 플랜을 읽고, 그룹 손익계산서를 이들과 대사합니다. 새로운 **OneStream: Read Adapter** 단계는 모든 워크플로에서 연결 멤버마다 한 번씩 호출하여 어댑터를 읽고 테이블에 기록합니다. [Data Foundation용 OneStream](/ko/guides/connections/onestream-for-data-foundation/), [Data Foundation 소스로서의 Anaplan](/ko/guides/connections/anaplan/#data-foundation의-소스로서의-anaplan), [OneStream: Read Adapter](/ko/reference/workflow-steps/onestream/onestream-read-adapter/)를 참조하십시오.
- **Data Foundation이 공통 비용을 배부하는 방식을 선택합니다.** **작업 > Allocations...** 메뉴는 간접비를 부서에, 부서 비용을 제품과 고객에 배부할 때 어떤 비용을 배부할지, 무엇을 기준으로 배부할지, 어디에 반영할지, 음수 동인을 어떻게 처리할지를 차례로 안내하며, 한 달 분량을 미리 보여 주어 풀링된 금액, 배부된 금액, 배부되지 않은 금액을 확인할 수 있습니다. 직접 편집한 규칙은 유지됩니다. [배부 규칙](/ko/guides/projects/data-foundation/#배부-규칙)을 참조하십시오.
- **Data Foundation에서 숫자를 설명하고 원하는 이름을 붙입니다.** **Explain this number**는 손익계산서 수치를 원장에 있는 금액, 안팎으로 배부된 금액, 그룹에서 제거된 금액으로 나누어 보여 주며, 사용자의 행 액세스 범위 안에서 가장 큰 원천 문서를 함께 표시합니다. **Business names**는 범주, 손익계산서 라인, 지표, 열에 비즈니스에서 쓰는 이름을 지정하며, 보고서, 지표, 어시스턴트에 적용됩니다. [숫자 설명](/ko/guides/projects/data-foundation/#수치-설명) 및 [Business Names](/ko/guides/projects/data-foundation/#비즈니스-이름)를 참조하십시오.
- **Data Foundation은 로드할 때마다 보드 팩을 작성하며 이전 상태로 되돌릴 수 있습니다.** **로드**를 실행할 때마다 손익계산서 대시보드의 Excel 통합 문서와 PDF가 문서 계정의 폴더에 기록되며, 보고를 끄면 팩은 통합 문서만 포함하고 대화 상자에 그렇게 안내됩니다. 로드가 시작될 때와 매핑 또는 소스를 변경하기 전에 복원 지점이 만들어지며, **작업 > Restore...** 메뉴는 각 복원 지점이 되돌리는 테이블 수를 보여 주고 차원을 포함한 프로젝트를 되돌립니다. **Foundation** 탭은 진행 상황을 더 명확하게 보여 줍니다. 아직 실행 중이거나 중간에 중지된 업데이트를 표시하고, 테이블 폴더가 소스가 될 수 없는 이유를 설명하며, 합치된 항목이 생기기 전까지 **합계 일치 여부 확인**을 대기 상태로 유지하고, 상태 읽기가 실패해도 복구됩니다. 업데이트를 적용할 때 생성된 단계와 메모에 대한 직접 편집 내용은 유지되고 충돌은 기록됩니다. [보드 팩](/ko/guides/projects/data-foundation/#이사회-자료-팩) 및 [복원 지점](/ko/guides/projects/data-foundation/#복원-지점)을 참조하십시오.
- **Data Foundation 프로젝트를 복제하거나 템플릿으로 저장합니다.** **작업 > Clone...** 메뉴는 모델 편집 내용, 지표, 분석 경로와 함께 프로젝트를 복사합니다. **Save as my template...** 옵션은 설정을 문서 계정에 저장하고, **From a template file...** 옵션은 이를 바탕으로 소스를 연결하기 전 상태의 새 비공개 프로젝트를 시작합니다. [프로젝트 복제](/ko/guides/projects/data-foundation/#프로젝트-복제) 및 [내 템플릿으로 저장](/ko/guides/projects/data-foundation/#내-템플릿으로-저장)을 참조하십시오.
- **Data Foundation 설정 체크리스트는 인계까지 이어지며, 어시스턴트가 남은 항목을 해결할 수 있습니다.** 체크리스트에 야간 새로 고침, 증거 팩, 프로젝트를 소유자에게 인계하는 항목이 추가되었으며 누가 프로젝트를 설정했는지도 표시됩니다. 어시스턴트에게 유형이 없는 계정, 여러 소스에서 사용하는 코드, 어느 항목과도 일치하지 않는 파일 열에 대한 답을 제안하도록 요청할 수 있습니다. 어시스턴트는 아무것도 기록하지 않으며 답은 사용자가 적용합니다. [Data Foundation 시작하기](/ko/guides/projects/data-foundation-getting-started/) 및 [Ask로 미해결 질문 해결](/ko/guides/projects/data-foundation/#ask로-미해결-질문-처리)을 참조하십시오.

- **모바일 Weave의 음성 입력은 한 번의 탭으로 시작합니다.** 마이크를 탭하고 질문하면 말을 멈춘 후 Weave가 한 번 전송합니다. 일찍 멈추려면 마이크를 다시 탭하며, 아무 소리도 들리지 않으면 자동으로 꺼집니다. 문장 도중에 **Weave** 탭을 떠나거나 앱을 백그라운드로 보내면 말한 내용이 전송되지 않은 채 질문 상자에 남으므로 검토할 수 있습니다. 실행, 일시 중지, 중지, 재개는 확인 시 실수로 두 번 탭해도 무시합니다. 앱 버전 1.3.0 이상이 필요합니다. ## 변경됨

- **PlaidCloud의 웹 앱과 Python 클라이언트 라이브러리는 REST API를 사용하며, JSON-RPC는 더 이상 사용되지 않습니다.** 웹 앱은 요청을 REST API로 보냅니다. `plaidcloud-rpc` 1.25.0 이상에서는 `SimpleRPC` 호출이 코드 변경 없이 REST API로 전달되며, REST API가 아직 지원하지 않는 호출이나 이전 릴리스를 사용하는 워크스페이스는 이전처럼 JSON-RPC를 사용합니다. JSON-RPC는 이후 릴리스에서 제거될 예정이므로 스크립트와 노트북을 `plaidcloud-rpc` 1.25.0 이상으로 업그레이드하고 새 통합은 REST API를 기준으로 작성하십시오. [명령줄](/ko/reference/cli/jupyter/command-line/)을 참조하십시오.
- **단계 양식이 하나의 레이아웃을 따릅니다.** 탭은 표준 이름과 표준 순서를 사용합니다. 일반, 설정, 소스, 열, 필터, 출력, 고급이며, ERP 전기 양식에는 헤더 열과 라인 열이 추가됩니다. 필수 필드에는 *가 표시되며, 양식은 단계에 필요한 항목이 없을 때만 저장을 막습니다.
- **프로젝트 복사에서 테이블 데이터와 차원 멤버를 따로 선택하고, 데이터를 더 빠르게 복사하며, 비공개 사본의 ERP 쓰기 승인을 유지합니다.** **Data to copy**에서 **테이블 데이터**(**테이블 데이터 없음**(기본값), **전체** 또는 **샘플**)를 선택하고, 별도로 기본적으로 켜져 있는 **Copy dimension members**를 선택합니다. 따라서 테이블 행 없이 복사해도 차원이 채워진 상태로 도착하며 만드는 속도도 빠릅니다. **전체** 및 **샘플** 복사는 여러 테이블을 동시에 복사하므로 테이블이 많은 프로젝트도 더 빨리 끝납니다. **복사 결과**에는 테이블과 함께 각 차원의 결과가 나열되며, **Retry failed items**는 실패한 테이블과 차원을 함께 다시 시도합니다. 데이터와 함께 만든 새 사본은 사용자에게만 비공개로 설정되며, 사용자가 직접 부여할 수 있었던 원본의 ERP 쓰기 승인을 유지합니다. 원본이 실거래로 전기하는 경우 사본은 시뮬레이션 상태로 도착하므로 실거래로 전환하기 전까지 ERP에는 아무것도 전달되지 않습니다. REST API와 `project_copy` MCP 도구도 `dimension_members`를 받습니다. [복사할 데이터 양 선택](/ko/guides/projects/managing-projects/#복사할-데이터-양-선택) 및 [사본의 ERP 쓰기 승인](/ko/guides/projects/managing-projects/#복사본의-erp-쓰기-승인)을 참조하십시오.
- **테이블의 세부 정보 패널이 해당 테이블을 사용하는 단계를 더 빠르게 보여 줍니다.** 다른 테이블을 선택하면 이전 테이블의 단계가 즉시 지워지며, 이 프로젝트의 데이터를 공유하는 다른 프로젝트의 단계는 패널 전체를 지연시키지 않고 나머지 항목보다 잠시 뒤에 추가됩니다. [테이블이 사용되는 위치 확인](/ko/guides/projects/managing-tables-and-views/#테이블이-사용되는-위치-보기)을 참조하십시오.
- **행 작업이 모든 목록에서 동일하게 작동합니다.** 행 시작 부분의 **⋯** 버튼을 클릭하거나, 행을 마우스 오른쪽 단추로 클릭하거나, 도구 모음의 **작업** 메뉴에서 행 메뉴를 엽니다. 메뉴에는 항상 **열기**, **세부 정보**, **편집**이 먼저 나열되고, 이어서 목록 고유의 작업, 마지막으로 **삭제** 또는 **제거**가 나열되며, 행에 적용되지 않는 작업은 제자리에 회색으로 표시됩니다. **Enter**와 **Del**은 해당 키로 실행되는 항목에 표시됩니다. 행에 작업이 하나뿐인 목록에서는 **⋯** 대신 그 작업의 아이콘이 표시되며, 내 대시보드, 내 Panel 앱, JupyterLite에는 **열기** 아이콘이 다시 표시됩니다. [행 작업 메뉴](/ko/guides/dashboards/using-dashboards/#행-작업-메뉴)를 참조하십시오.
- **앱 탭 아이콘이 라이트와 다크 모두에서 하나의 일관된 세트로 통일되었습니다.**
- **검증 설정이 없는 저장된 ERP 쓰기 단계는 검증 전용으로 열립니다.** SAP Post, SAP Attach, NetSuite Post, Oracle EBS GL 및 AP Post, Xero 내보내기가 해당됩니다. 명시적으로 실거래 실행으로 설정된 단계는 그대로 실거래로 유지됩니다.
- **장시간 실행되는 작업은 모든 곳에서 같은 방식으로 진행 상황을 표시합니다.**
- **워크플로가 정직하게 중지되고, 실패하고, 보고됩니다.** 워크플로를 중지하면 워크플로가 시작한 모든 것이 중지되고, 끝낼 수 없는 실행이나 단계는 멈춰 있는 대신 이유와 함께 실패하며, 실행 상태는 실제로 실행된 내용과 일치합니다.
  - **워크플로를 중지하면 워크플로가 시작한 모든 것이 중지되며, 끝낼 수 없는 실행이나 단계는 멈춰 있지 않고 실패합니다.** 중지하면 아직 대기 중이던 가져오기 및 차원 단계가 취소되므로 워크스페이스의 이후 가져오기와 차원 로드가 정상적으로 시작되며, 워크플로의 대기 중이거나 실행 중인 커넥터(Singer) 동기화도 중지됩니다. 단계의 작업을 시작할 수 없으면 영원히 기다리는 대신 이유와 함께 단계가 실패합니다. 약 40분 이내에 어떤 워커도 시작하지 않은 경우, 워커가 시작한 후 사라진 경우, 포드가 약 20분 동안 Pending 상태에 머무는 경우, 이미지를 약 5분 동안 가져올 수 없는 경우, 또는 약 20분 동안 포드가 만들어지지 않는 경우가 해당됩니다. 약 30분 이내에 어떤 러너도 가져가지 않은 커넥터 동기화는 해당 동기화를 지칭하는 메시지와 함께 실패합니다. 단계가 워커를 기다리는 동안 상태 메시지에는 지금까지 경과한 시간(분)과 함께 "Waiting for a worker…"가 표시되며, 작업이 시작되면 사라집니다. 매크로를 중지하면 실행 중인 모든 사본이 중지되지만, 하나의 사본만 중지하거나 **Macro Concurrent** 단계가 응답하지 않는 사본을 포기하는 경우에는 이를 호출한 워크플로가 계속 실행됩니다. 다른 워크플로 안에서만 실행되는 매크로는 워크플로 목록에 **실행 중**으로 표시되고, **중지**를 사용할 수 있으며, 각 단계의 상태와 시작 및 종료 시간은 최근 실행에서 가져옵니다. 서버를 잃은 실행은 실패로 끝나며, 12시간이 지나도 계속 실행 중인 실행은 "Run failed: still running at the 12-hour limit. Re-run the workflow."라는 메시지와 함께 실패합니다. [워크플로 실행](/ko/guides/workflows/run-a-workflow/#시작되지-않는-단계)을 참조하십시오.
  - **재개, 실행 기록, 실행 상태는 실제로 실행된 내용과 일치합니다.** 부모 워크플로를 재개하면 자식 워크플로의 단계 하나를 따로 다시 실행한 후에도 자식 워크플로에 남아 있던 모든 작업이 실행되며, 하나의 실행 안에서 자식 워크플로를 호출할 때마다 고유한 실행 기록 항목이 생깁니다. 서버가 중지되어 다시 시작되는 단계는 로그에 그 사실이 기록되며, `workflow_run_status`와 REST API의 실행 결과는 실행을 정상으로 보고하는 대신 실패했지만 계속된 단계를 `continued_step_ids`와 `continued_step_count`에 나열합니다. [일시 중지, 중지, 재개](/ko/guides/workflows/run-a-workflow/#일시-중지-중지-재개) 및 [오류 발생 시 계속](/ko/guides/workflows/continue-on-error/)을 참조하십시오.
  - **단계 오류에는 자체 메시지가 표시됩니다.** PlaidCloud가 예상하지 못한 오류는 "The step stopped on an unexpected error (*type*): *message*"로 표시됩니다. 런처의 **조치 필요** 카드는 오류를 한 줄로 보여 주며, 이후 삭제된 워크플로의 실행은 제외합니다. [단계 오류 관리](/ko/guides/workflows/managing-step-errors/)를 참조하십시오.
  - **끝나지 않는 ERP 추출은 해당 단계를 실패시키며, 재개하면 이어서 진행됩니다.** **SAP: 임시 추출**이 행 또는 시간 제한에서 일시 중지되거나 에이전트가 제시간에 응답하지 않을 때, 또는 Salesforce, Oracle Fusion 대량 또는 HFM/FCCS 내보내기 작업이 단계가 기다리기를 멈출 때까지 아직 실행 중일 때 단계가 실패하므로 이후 단계가 일부만 채워진 테이블에서 실행되지 않습니다. 워크플로를 재개하거나 단계를 다시 실행하면 추출이 중단된 지점부터 같은 작업으로 이어집니다. [실행 한도](/ko/guides/connections/sap-adhoc-extract/#실행-제한) 및 [Salesforce: 개체 쿼리](/ko/reference/workflow-steps/salesforce/query-salesforce-object/#실행이-끝나지-않는-경우)를 참조하십시오.
  - **내보내기를 취소하면 웨어하우스에서 해당 쿼리도 중지됩니다.** 워크플로를 중지하는 경우를 포함하여 내보내기나 다운로드를 취소하면, 데이터를 읽는 쿼리도 Lakehouse v2, Snowflake, Databricks, PostgreSQL, Greenplum에서 함께 중지되며, 원격 데이터베이스로의 내보내기는 끝까지 실행되는 대신 소스 읽기를 중지합니다.
- **REST, Import REST, Import Postman 단계는 워크스페이스를 업그레이드할 때 REST 요청으로 변환됩니다.** 깔끔하게 변환할 수 없는 단계는 그대로 유지됩니다. [REST 요청 단계](/ko/guides/workflows/rest-request-step/)를 참조하십시오.
- **세션이 만료된 후 연 대시보드 링크는 로그인하면 해당 대시보드로 이동합니다.** [대시보드 사용](/ko/guides/dashboards/using-dashboards/)을 참조하십시오.
- **MCP 도구는 인식하지 못하는 필드를 무시하지 않고 거부하며** 오류에 해당 필드를 명시합니다. `workflow_upsert`는 `memo`를 받으며 `description`을 그 다른 이름으로 허용합니다. [알 수 없는 필드는 거부됨](/ko/integrations/ai-coding-agents/getting-started/#알-수-없는-필드는-거부됩니다)을 참조하십시오.
- **Lakehouse v2에서는 Lakehouse가 Parquet 내보내기를 Google Cloud Storage에 직접 기록합니다.** Google Cloud Storage 문서 계정으로의 내보내기는 모든 행이 먼저 PlaidCloud를 거치는 대신 계정의 자체 자격 증명으로 계정의 버킷에 바로 기록됩니다. Amazon S3 및 Azure Blob Storage 계정으로의 내보내기는 이전처럼 작동합니다. [Export to Parquet](/ko/reference/workflow-steps/export/export-to-parquet/)를 참조하십시오.
- **Slack, Microsoft Teams, Web Hook 단계는 메시지가 전송되지 않은 이유를 알려 줍니다.** 단계 오류에는 연결을 시도한 서버와, Slack 및 Teams의 경우 연결이 명시되며 무엇이 잘못되었는지 설명합니다. 예를 들어 Slack이 더 이상 웹후크를 인식하지 못하거나, 채널에 게시할 수 없거나, 서버를 찾을 수 없거나 60초 안에 응답하지 않거나, 연결이 삭제된 경우입니다. 웹후크 URL이 있으면 누구나 사용자의 통합으로 게시할 수 있으므로 Slack 또는 Teams 웹후크 URL은 표시되지 않습니다. [Notify via Slack](/ko/reference/workflow-steps/notifications/notify-via-slack/)을 참조하십시오.
- **프로젝트 서비스 계정의 액세스 토큰은 최소 24시간 동안 유효합니다.** UDF 단계처럼 프로젝트로 실행되는 워크플로 작업은 24시간 동안 유효한 토큰을 받습니다. 더 짧은 수명은 워크스페이스를 업그레이드할 때 늘어나며, 직접 설정한 더 긴 수명은 유지됩니다.
- **워크스페이스의 조직, 소유자, 릴리스, 버전은 PlaidCloud가 설정하며, 데이터 센터는 사용자가 선택합니다.** 컨트롤 플레인에서 만든 워크스페이스는 사용자가 소유하고 PlaidCloud가 설정한 릴리스 채널에 배치되며, 가입 시 제공되는 리전에서 **Data Center**를 선택합니다. 워크스페이스를 편집할 때 조직, 소유자, 릴리스, 버전은 읽기 전용입니다. 버전을 변경하려면 **Set Version**을 사용하고, 워크스페이스 이동, 소유자 또는 채널 변경, 고정은 PlaidCloud 지원팀에 요청하십시오. [워크스페이스 구성](/ko/administration/control-plane/workspace-configuration/#기본-설정)을 참조하십시오.

## 수정됨

- **잘못된 프로젝트 설정이 명확한 메시지로 보고됩니다.** 알 수 없는 환경 또는 문서 계정, 이미 사용 중이거나 예약된 슬러그, 잘못된 스토리지 유형 또는 전기 모드는 이제 일반적인 서버 오류 대신 문제를 명시한 메시지를 반환합니다. REST API에서는 500이 아닌 400이며, AI 어시스턴트 또는 MCP에서는 잘못된 인수 오류입니다.
- **REST API의 차원 값 요청이 작동합니다.** `POST /rest/v1/analyze/query/retrieve-dimension-values`가 그리드 요청으로 처리되어 잘못된 요청으로 거부되었습니다. 이제 `value_columns`의 각 열에 대해 집계된 값 하나를 반환하며, 행 필터와 열 필터의 각 쌍에 대해 값 하나를 반환하는 그리드는 별도의 `POST /rest/v1/analyze/query/retrieve-dimension-cells`를 사용합니다.
- **느린 테이블 읽기와 파일 처리가 다른 요청을 더 이상 지연시키지 않습니다.** 웨어하우스에서 테이블의 열 읽기, Data Foundation 파일 등록, Excel로 내보내기, REST 또는 SOAP 가져오기 응답 읽기, 문서 계정이 사용되는 위치 찾기, Panel 앱의 코드 또는 로고 검사는 각각 완료될 때까지 같은 서버가 처리하던 다른 모든 요청을 멈추게 할 수 있었습니다. 이제 해당 요청과 나란히 실행됩니다.
- **프로젝트 및 워크플로 변수 대화 상자가 스크롤됩니다.** 작은 화면이나 낮은 해상도에서는 추가 및 편집 대화 상자가 창보다 커서 **만들기** 및 **업데이트** 버튼에 손이 닿지 않을 수 있었습니다. 이제 양식이 스크롤되고 버튼은 아래쪽에 유지됩니다.
- **Azure Blob Storage 문서 계정에서 256 MiB를 넘는 파일을 복사, 이동, 이름 바꾸기할 수 있습니다.** 이전에는 이런 크기의 파일에서 각 작업이 실패했으며, 해당 파일이 들어 있는 폴더를 이동하거나 이름을 바꿀 때도 실패했습니다.
- **Lakehouse v2에서 테이블의 행 개수에 방금 기록된 내용이 반영됩니다.** 테이블을 기록한 단계나 가져오기가 기록 이전의 행 개수를 저장하는 경우가 있어, 방금 로드한 테이블이 0개 행으로 표시되거나 가져오기가 0개 행을 가져왔다고 보고할 수 있었습니다. 이제 새 행이 모든 곳에서 보이게 된 후에 개수를 읽으므로 이후 단계도 해당 행을 읽습니다. 테이블을 다른 브랜치로 전환하거나 브랜치를 병합할 때도 행 및 열 개수가 업데이트됩니다.
- **Weave의 빈 값 검사는 각 실행을 이전 실행이 실제로 남긴 내용과 비교합니다.** 단계가 테이블을 다시 채우기 위해 비운 직후에 단계의 빈 값이 집계되는 경우가 많아 이전 실행에는 빈 값이 없었던 것처럼 보였고, 항상 일부가 비어 있던 열이 방금 비게 된 것처럼 보고되었습니다. 이제 각 실행은 단계가 테이블을 남긴 상태 그대로 집계됩니다. 이전에 기록된 개수는 정상 값과 구별할 수 없으므로 사용하지 않습니다. 각 단계의 빈 값 검사는 기록을 다시 시작하며, 실행 5회가 집계되기 전까지는 검사되지 않음으로 보고됩니다. 행 및 값 분포 검사도 단계가 끝난 후 2초가 넘어 다른 단계가 같은 테이블에 수행한 기록을 해당 단계의 기록으로 인정하지 않습니다. [Weave 점검 항목](/ko/guides/ai-assistant/weave-findings/)을 참조하십시오.
- **Data Foundation이 반전된 환율과 소수 임계값의 정밀도를 유지합니다.** 환율이 보고 통화에서 다른 통화로 표시되어 PlaidCloud가 이를 뒤집는 경우 소수점 여섯 자리로 반올림될 수 있었으며, 인도네시아 루피아처럼 환율이 작은 통화의 금액이 약 1% 어긋났습니다. 이제 반전된 환율은 소수점 12자리를 유지합니다. `0.5`처럼 소수가 있는 `group_amber` 또는 `group_red` 임계값은 정수로 반올림되었습니다. 다음 **로드**부터 정확한 값이 사용됩니다. [환율](/ko/guides/projects/data-foundation/#환율)을 참조하십시오.
- **비활성화된 멤버의 알림과 다이제스트가 중지됩니다.** 소유자가 비활성화된 Panel 앱 알림 또는 다이제스트가 계속 확인하고 전송했습니다. 이제 소유자가 비활성화된 동안에는 일시 중지되고, 다시 활성화되면 재개됩니다. [알림 및 다이제스트](/ko/guides/panel-apps/alerts-and-digests/)를 참조하십시오.
- **삭제된 연결을 REST API에 요청하면 404를 반환합니다.** 삭제된 연결이나 존재하지 않는 ID를 요청하면 일반적인 서버 오류(500)로 응답했습니다. 이제 연결 ID를 명시한 메시지와 함께 404를 반환합니다.

## 보안

- **암호 로그인에는 인증 앱이 필요하며 암호가 더 강력해졌습니다.** PlaidCloud 암호로 로그인하는 멤버는 다음 로그인 시 인증 앱을 설정하라는 안내를 받으며, 그 이후에는 매번 인증 앱의 코드를 입력합니다. 싱글 사인온, Google, Microsoft, GitHub 로그인, API 토큰, 서비스 계정은 변경되지 않습니다. 새 암호는 12자 이상이어야 하며 사용자 이름이나 최근 사용한 암호 6개와 같을 수 없고, 로그인 시도가 반복해서 실패하면 계정이 잠시 잠깁니다. 워크스페이스에 이미 있던 더 엄격한 규칙은 유지됩니다. [멤버 인증](/ko/administration/access/member-authentication/)을 참조하십시오.
- **연결은 공용 및 사설 네트워크 주소를 가리킵니다.** 연결은 루프백, 링크 로컬 또는 클라우드 메타데이터 주소를 가리킬 수 없으며, 오류에는 호스트와 해석된 주소가 명시됩니다. 사설 네트워크의 주소는 영향을 받지 않습니다. [연결이 접근할 수 없는 주소](/ko/guides/connections/create-connection/#연결이-접근할-수-없는-주소)를 참조하십시오.
- **저장된 연결 자격 증명은 연결 또는 워크플로를 편집할 수 있는 멤버에게만 표시됩니다.** REST API와 MCP를 통해 다른 멤버에게는 저장된 연결의 암호, 토큰, 키가 마스킹되며, 이들도 연결을 열고 탐색할 수는 있습니다. [연결 자격 증명을 볼 수 있는 사용자](/ko/guides/connections/create-connection/#연결-자격-증명을-볼-수-있는-사람)를 참조하십시오.
- **앱 빌드는 워크스페이스의 Git 자격 증명에 액세스하지 않고 실행됩니다.**
- **에이전트의 개인 키는 에이전트를 편집할 수 있는 멤버에게만 표시됩니다.** REST API와 MCP를 통한 에이전트 목록이나 세부 정보에 키가 더 이상 나타나지 않으며, 에이전트 양식은 에이전트를 편집할 수 있는 멤버에게만 **개인 키**와 **RPC 구성 보기**를 표시합니다. 서비스 계정, 프로젝트 및 에이전트 토큰, AI에 위임된 토큰은 키나 RPC 구성을 가져올 수 없습니다. 실행 중인 에이전트는 영향을 받지 않으며 공개 키는 계속 표시됩니다. [에이전트 자격 증명 가져오기](/ko/reference/cli/plaidlink/agents/#에이전트-자격-증명-가져오기)를 참조하십시오.
- **프록시 다운로드 링크는 1시간 동안 유효합니다.** **Use PlaidCloud Proxy Download**를 켠 경우 링크가 만료되면 다운로드를 다시 열어 새 링크를 받으십시오. [서비스](/ko/administration/control-plane/workspace-configuration/#서비스)를 참조하십시오.
- **보안 그룹에 사람을 추가하는 일은 보유한 권한을 따릅니다.** 그룹이 부여하는 모든 권한을 보유한 경우에만 멤버를 보안 그룹에 추가하거나, 멤버의 그룹을 선택하거나, 아키텍트를 초대할 수 있습니다. 워크스페이스 관리자는 제한이 없습니다. [보안 그룹 관리](/ko/administration/access/managing-security-groups-and-assignments/#보안-그룹-관리)를 참조하십시오.
- **연결의 소유자 또는 워크스페이스 관리자가 연결의 설정을 변경하고 켜거나 끌 수 있습니다.** REST API, JSON-RPC, AI 어시스턴트 또는 MCP를 통해 연결의 설정을 변경하려면 연결 소유자 중 한 명이어야 하며, 소유자가 없는 연결은 워크스페이스 관리자여야 합니다. 연결을 사용 설정, 사용 중지, 잠금, 잠금 해제하려면 소유자 또는 워크스페이스 관리자여야 하며, 여러 연결을 지정한 요청은 모든 연결을 변경할 수 있을 때만 적용됩니다. 워크스페이스의 기본 AI 연결은 워크스페이스 관리자만 선택할 수 있으며, 멤버가 소유한 연결은 관리자가 소유했거나 소유자가 없는 연결 중 기본값이 될 수 있는 연결이 없을 때만 기본값이 됩니다. [연결 편집](/ko/guides/connections/create-connection/#연결-편집) 및 [LLM 공급자](/ko/integrations/ai-architecture/llm-providers/#연결이-담고-있는-내용)를 참조하십시오.
- **행 액세스는 멤버가 제한된 테이블로 수행하는 모든 작업에 적용됩니다.** 멤버는 대시보드, 자신의 SQL, 로드에서 부여된 권한이 허용하는 행만 보고 변경할 수 있습니다.
  - **프로젝트 아키텍트는 대시보드에서 행이 제한된 테이블의 모든 행을 봅니다.** Analyze에서 보는 것과 같습니다. 아키텍트 액세스를 제거하면 대시보드에서 즉시 적용됩니다. 누군가의 역할을 변경하거나, 프로젝트에서 사용자나 그룹을 제거하거나, 프로젝트의 액세스 유형을 변경하거나, 이전 프로젝트 버전을 복원하거나, 보안 그룹을 삭제하는 경우가 모두 해당됩니다. [행 액세스 관리](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리)를 참조하십시오.
  - **행 액세스로 제한된 멤버가 자신의 SQL 쿼리를 실행하고 결과를 내보낼 수 있습니다.** 행 액세스가 설정된 프로젝트에서 아키텍트가 아닌 멤버는 쿼리 화면에서 자신의 쿼리로 부여된 권한이 허용하는 행을 정확히 얻고, **액세스 권한에 따라 행이 제한됨** 안내와 함께 CSV, Excel, JSON으로 내보낼 수 있습니다. 이전에는 거부되었습니다. 퍼센트 기호(`%`)가 포함된 부여 값은 이제 쿼리 화면에서 해당 행을 반환하며, 이러한 쿼리를 CSV로 다운로드하는 것도 작동합니다. Snowflake나 Databricks에서의 자유 형식 SQL, Postgres 계열 웨어하우스에서의 자신의 SQL 내보내기, 스냅샷 기준 시점의 관리 대상 테이블 읽기는 여전히 거부되며, 뷰는 필터링되려면 관리 대상 열을 원래 이름으로 유지해야 합니다. [행 액세스와 직접 작성하는 쿼리](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스와-직접-작성한-쿼리)를 참조하십시오.
  - **행 액세스를 저장하면 소스에 없는 부여 값이 유지됩니다.** 보안 그룹에 부여된 값이 테이블에 해당 행이 없거나, 차원에 해당 멤버가 없거나, 목록에 없는 경우에도 해당 값은 표시된 채 그리드에 남습니다. **저장**은 이러한 각 값을 유지할지 제거할지 묻습니다. [행 액세스 그리드](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-그리드)를 참조하십시오.
  - **행이 제한된 테이블에 대한 DataFrame 쓰기, 레코드 저장, 지우기는 볼 수 있는 행만 변경합니다.** 행 액세스가 행을 제한하는 경우, Python 클라이언트로 제한된 테이블에 DataFrame을 쓰거나 지울 때, 또는 REST API로 레코드를 저장하거나 지울 때 자신의 행만 변경되며, 액세스 범위 밖의 행이 포함된 로드는 아무것도 변경되기 전에 발견된 값을 명시하며 거부됩니다. 프로젝트 아키텍트, 모든 행을 볼 수 있는 멤버, 워크플로 실행은 테이블 전체에 씁니다. 사람이 어떤 테이블에 수행하든 이러한 쓰기는 각각 보안 로그에 기록됩니다. [제한된 테이블에 데이터 로드](/ko/administration/access/managing-security-groups-and-assignments/#제한된-테이블에-데이터-로드)를 참조하십시오.
  - **행이 제한된 테이블의 가져오기, 복사, 복원, 삭제는 모든 행이 사용자에게 보여야 합니다.** 행 액세스가 행을 제한하는 경우, 제한된 테이블로 파일 가져오기, 다른 프로젝트에서 테이블 복사, 브랜치 전환 또는 병합, 복원, 삭제, 삭제 후 되살리기, 또는 테이블 전체를 교체하는 모든 작업은 테이블의 모든 행을 볼 수 있을 때만 실행되며, 그렇지 않으면 거부되고 아무것도 변경되지 않습니다. REST API로 테이블의 행을 저장하면 다른 로드와 마찬가지로 자신의 행만 변경됩니다. 프로젝트 아키텍트, 모든 행을 볼 수 있는 멤버, 워크플로 실행은 영향을 받지 않으며, 이러한 작업도 보안 로그에 기록됩니다. [제한된 테이블에 데이터 로드](/ko/administration/access/managing-security-groups-and-assignments/#제한된-테이블에-데이터-로드)를 참조하십시오.
- **계정의 소유자만 이전 버전을 복원할 수 있습니다.** 문서 계정을 이전 버전으로 복원하거나, 버전을 보류하거나 해제하거나, 백업을 만들려면 계정 소유자 중 한 명이어야 하며, 시스템에서 관리하는 계정에서는 이 중 어느 것도 사용할 수 없습니다. 계정의 버전 기록을 보려면 계정에 대한 액세스가 필요합니다.
- **`query_run`은 읽기 전용 문을 실행합니다.** AI 어시스턴트와 MCP 클라이언트가 사용하는 `query_run` 도구는 SELECT 또는 WITH 문 하나, 그 EXPLAIN, 또는 SHOW를 받으며, 그 밖의 문은 실행되지 않습니다. 데이터를 변경하려면 `query_transform`을 사용하십시오. MCP 테이블 내보내기의 SQL도 같은 규칙을 따릅니다. REST 및 JSON-RPC API에서는 프로젝트 데이터를 변경할 수 없는 멤버의 쿼리 실행, 열 패싯 생성, 쿼리를 CSV로 다운로드, 쿼리를 원격 데이터베이스로 내보내기, 직접 작성한 쿼리로 테이블 데이터 내보내기에도 적용되며, 거부된 쿼리는 403을 반환합니다. Explain Analyze는 측정을 위해 쿼리를 실행하므로 쿼리 로그와 Lakehouse에서는 읽기만 하는 쿼리만 허용하며, 행 액세스가 설정된 프로젝트에서는 프로젝트 아키텍트만 쿼리 로그에서 실행할 수 있습니다.
