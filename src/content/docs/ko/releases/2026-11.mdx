## 추가됨

- **단계 양식의 미리 보기.** Import: SQL, Execute: SQL, Extract: SQL, Export: SQL 및 Salesforce Query 단계는 단계를 실행하지 않고도 최대 100개 행을 표시하며, Anaplan 뷰 및 목록 읽기 단계는 생성될 열과 유형을 표시합니다. **소스** 탭에서 **미리 보기**를 클릭하십시오. 변수는 실행 시와 같은 방식으로 채워지지만 `{x:>9}` 같은 변수 형식은 지원되지 않습니다. 미리 보기는 표준 SQL 함수만 실행하며, 그렇지 않으면 단계를 실행하라고 안내합니다. 잠긴 프로젝트나 에이전트 기반 Execute SQL 단계에서는 사용할 수 없습니다. [SQL 가져오기](/ko/reference/workflow-steps/import/import-sql/)와 [SQL 추출](/ko/reference/workflow-steps/tables/table-extract-sql/)을 참조하십시오.
- **AI 어시스턴트가 테이블 게시를 취소하고 프로젝트의 기본 대시보드 대상을 설정할 수 있습니다.** `publish_manage`는 테이블의 게시를 취소하면서 게시된 뷰와 어떤 차트도 사용하지 않는 대시보드 데이터 세트도 함께 취소합니다. 차트가 아직 사용하는 데이터 세트는 그대로 남으며, 게시된 뷰를 기반으로 보고서 뷰가 만들어진 경우에도 뷰와 데이터 세트가 남지만 테이블의 게시는 취소됩니다. `project_upsert`는 프로젝트의 새 대시보드를 공유할 그룹인 `dashboard_default_audience`를 설정하며, `[]`를 지정하면 비워집니다. [게시 취소](/ko/guides/data/publish/#ai-어시스턴트-또는-mcp로-게시-취소)와 [AI 어시스턴트 또는 MCP로 기본 대상 설정](/ko/guides/dashboards/control-who-can-see-a-dashboard/#ai-어시스턴트-또는-mcp로-기본-대상-설정)을 참조하십시오.

- **모바일 Weave의 음성 입력은 한 번의 탭으로 시작합니다.** 마이크를 탭하고 질문하면 말을 멈출 때 Weave가 한 번 전송합니다. 일찍 멈추려면 마이크를 다시 탭하며, 아무 소리도 들리지 않으면 자동으로 꺼집니다. 말하는 도중에 **Weave** 탭을 벗어나거나 앱을 백그라운드로 전환하면 입력한 내용이 전송되지 않은 채 질문 상자에 남아 있어 검토할 수 있습니다. 실행, 일시 중지, 중지, 재개 확인 창은 실수로 두 번 탭해도 무시합니다. 앱 버전 1.3.0 이상이 필요합니다. [음성 사용](/ko/guides/mobile-app/weave-on-mobile/#음성-사용)을 참조하십시오.

## 변경됨

- **단계 양식이 하나의 레이아웃을 따릅니다.** 탭의 이름과 순서가 표준화되어 General, Settings, Source, Columns, Filters, Output, Advanced 순서이며, ERP 전기 양식에는 Header columns와 Line columns가 추가됩니다. 필수 필드에는 *가 표시되며, 양식은 단계에 필요한 항목만 저장을 막습니다.
- **행 작업 메뉴(⋯)가 모든 그리드 행의 왼쪽 가장자리에 있습니다.**
- **검증 설정이 없는 저장된 ERP 쓰기 단계는 검증 전용으로 열립니다.** SAP Post, SAP Attach, NetSuite Post, Oracle EBS GL 및 AP Post, Xero 내보내기가 해당합니다. 라이브로 실행하도록 명시적으로 설정된 단계는 라이브로 유지됩니다.
- **오래 실행되는 작업은 어디서나 같은 방식으로 진행 상황을 표시합니다.**
- **워크플로를 중지해도 이후 가져오기가 더 이상 지연되지 않으며, 시작되지 않는 단계는 멈춰 있는 대신 실패합니다.** 중지하면 대기열에 있던 가져오기 및 차원 단계가 취소되므로 워크스페이스의 이후 가져오기와 차원 로드가 정상적으로 시작됩니다. 약 40분 안에 어떤 워커도 단계의 작업을 시작하지 않거나, 워커가 작업을 시작한 뒤 사라지면, 24시간 제한 시간까지 실행 중으로 표시되는 대신 단계가 그 사실을 알리고 **여기서부터 실행**을 안내하는 메시지와 함께 실패합니다. [워크플로 실행](/ko/guides/workflows/run-a-workflow/#시작되지-않는-단계)을 참조하십시오.
- **워크스페이스를 업그레이드하면 REST, Import REST, Import Postman 단계가 REST 요청 단계로 변환됩니다.** 깔끔하게 변환할 수 없는 단계는 그대로 유지됩니다. [REST 요청 단계](/ko/guides/workflows/rest-request-step/)를 참조하십시오.
- **프로젝트 아키텍트는 대시보드에서 행이 제한된 테이블의 모든 행을 볼 수 있으며**, Analyze에서 보는 것과 일치합니다. 아키텍트 액세스를 제거하면 대시보드에 즉시 적용됩니다. 누군가의 역할을 변경하거나, 프로젝트에서 그 사람 또는 그룹을 제거하거나, 프로젝트의 액세스 유형을 변경하거나, 이전 프로젝트 버전을 복원하거나, 보안 그룹을 삭제하는 경우가 모두 해당합니다. 이전 아키텍트는 더 이상 행이 제한된 데이터의 모든 행을 볼 수 없습니다. [행 액세스 관리](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리)를 참조하십시오.
- **세션이 만료된 뒤 대시보드 링크를 열면 로그인한 후 해당 대시보드로 이동합니다.** [대시보드 사용](/ko/guides/dashboards/using-dashboards/)을 참조하십시오.
- **MCP 도구는 인식하지 못하는 필드를 무시하는 대신 거부하며** 오류에 해당 필드를 표시합니다. `workflow_upsert`는 `memo`를 받으며 `description`을 그 대체 이름으로 허용합니다. [알 수 없는 필드는 거부됨](/ko/integrations/ai-coding-agents/getting-started/#알-수-없는-필드는-거부됩니다)을 참조하십시오.
- **Lakehouse v2에서는 Lakehouse가 Parquet 내보내기를 Google Cloud Storage에 직접 기록합니다.** Google Cloud Storage 문서 계정으로의 내보내기는 모든 행이 먼저 PlaidCloud를 거치는 대신 계정 자체의 자격 증명으로 계정의 버킷에 바로 기록됩니다. Amazon S3 및 Azure Blob Storage 계정으로의 내보내기는 이전과 같이 작동합니다. [Parquet로 내보내기](/ko/reference/workflow-steps/export/export-to-parquet/)를 참조하십시오.

## 수정됨

- **잘못된 프로젝트 설정이 명확한 메시지로 보고됩니다.** 알 수 없는 환경이나 문서 계정, 이미 사용 중이거나 예약된 슬러그, 잘못된 스토리지 유형이나 전기 모드는 이제 일반적인 서버 오류 대신 문제를 알려 주는 메시지를 반환합니다. REST API에서는 500이 아닌 400이며, AI 어시스턴트 또는 MCP에서는 잘못된 인수 오류입니다.
- **REST API의 차원 값 요청이 작동합니다.** `POST /rest/v1/analyze/query/retrieve-dimension-values`는 그리드 요청으로 처리되어 유효하지 않은 것으로 거부되었습니다. 이제 `value_columns`의 각 열에 대해 집계된 값을 하나씩 반환하며, 행 필터와 열 필터의 각 쌍마다 값을 하나씩 반환하는 그리드는 별도의 `POST /rest/v1/analyze/query/retrieve-dimension-cells`를 사용합니다.
- **느린 테이블 읽기와 파일 처리가 더 이상 다른 요청을 지연시키지 않습니다.** 웨어하우스에서 테이블의 열 읽기, Data Foundation 파일 등록, Excel로 내보내기, REST 또는 SOAP 가져오기의 응답 읽기, 문서 계정이 사용되는 위치 찾기, Panel 앱의 코드 또는 로고 확인은 각각 끝날 때까지 같은 서버가 처리하던 다른 모든 요청을 멈추게 할 수 있었습니다. 이제 이러한 요청과 나란히 실행됩니다.
- **프로젝트 및 워크플로 변수 대화 상자가 스크롤됩니다.** 작은 화면이나 낮은 해상도에서는 추가 및 편집 대화 상자가 창보다 커서 **만들기**와 **업데이트** 버튼에 닿지 않을 수 있었습니다. 이제 양식이 스크롤되고 버튼은 아래쪽에 유지됩니다.
- **Azure Blob Storage 문서 계정에서 256 MiB를 초과하는 파일을 복사, 이동, 이름 바꾸기할 수 있습니다.** 이전에는 이 크기의 파일에서 이러한 작업이 모두 실패했으며, 해당 파일이 들어 있는 폴더를 이동하거나 이름을 바꾸는 작업도 실패했습니다.
- **Lakehouse v2에서는 테이블의 행 수가 방금 기록된 내용을 반영합니다.** 테이블에 기록한 단계나 가져오기가 기록 이전의 행 수를 저장할 수 있어서, 방금 로드한 테이블이 0개 행으로 표시되고 가져오기에서 0개 행을 가져왔다고 보고될 수 있었습니다. 이제 새 행이 모든 곳에서 보이게 된 후에 행 수를 읽으므로 이후 단계에서도 해당 행을 읽습니다. 테이블을 다른 브랜치로 전환하거나 브랜치를 테이블에 병합해도 테이블의 행 수와 열 수가 업데이트됩니다.

## 보안

- **계정의 소유자만 이전 버전을 복원할 수 있습니다.** 문서 계정을 이전 버전으로 복원하거나, 버전을 보존 또는 해제하거나, 백업을 수행하려면 이제 계정의 소유자 중 한 명이어야 하며, 시스템에서 관리하는 계정에서는 이 중 어느 것도 사용할 수 없습니다. 계정의 버전 기록을 보려면 계정에 대한 액세스가 필요합니다.
