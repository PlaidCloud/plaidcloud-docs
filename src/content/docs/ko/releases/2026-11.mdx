## 추가됨

- **컨트롤 플레인의 Trust Center가 보안 팀에 PlaidCloud의 보안 문서를 제공합니다.** Admin 및 Security 사용자는 조직의 **Trust Center**를 열어 하위 처리자 목록과 DPA 같은 공개 문서를 바로 내려받을 수 있으며, 조직에서 보안 문서 NDA에 한 번 서명하면 SOC 2 Type II 보고서 같은 제한 문서가 열립니다. 다른 Admin 및 Security 사용자는 누가 언제 서명했는지 볼 수 있습니다. 계약에 이미 NDA가 포함된 조직은 NDA를 파일로 보유 중이라고 표시하여 서명 없이도 문서가 열리게 할 수 있습니다. 제한 문서 다운로드에는 워터마크가 적용되고 기록되며, 새 NDA 버전은 다시 수락해야 합니다. Admin 및 Security 사용자는 조직별로 새 문서나 업데이트된 문서와 새 NDA 버전을 요약한 일일 이메일을 받도록 선택할 수도 있으며, 이 이메일에는 문서 자체가 포함되지 않습니다. [Trust Center](/ko/administration/control-plane/trust-center/)를 참조하십시오.
- **PlaidXL이 Excel에서 만들고, 드릴하고, 설명하고, 계획합니다.** **PlaidCloud** 리본 탭은 **연결**, **삽입**, **새로 고침**, **Drill**, **쓰기**, **공유**로 그룹화되어 있고, 자주 쓰는 명령은 **PlaidXL** 바로 가기 메뉴와 **PlaidXL Cell** 탭에도 있으며, 주요 명령에는 변경할 수 있는 키보드 단축키가 있습니다. 이 단축키는 필드에 입력하는 동안에는 작동하지 않습니다. 명령이 실패하면 어떤 명령이 왜 실패했는지 알려 줍니다. 로그인하기 전에 실행한 명령은 로그인 창을 열고 로그인이 끝나면 한 번 실행되며, 로그인은 워크스페이스 하나에만 유효하므로 워크스페이스를 전환하면 새 워크스페이스에 로그인하라는 안내가 표시되고(다시 돌아올 때는 표시되지 않습니다), Office에서 Microsoft Entra 회사 계정을 사용하면 PlaidXL이 사용자의 워크스페이스를 자동으로 찾습니다. [PlaidXL 참조](/ko/reference/cli/plaidxl/)를 참조하십시오.
  - **클릭 몇 번으로 보고서를 만듭니다.** **보고서** 탭은 테이블에서 라이브 보고서를 배치하며, 한 차원은 행 방향으로, 다른 차원은 열 방향으로 드릴 다운하고 각 교차 지점에는 `CELL` 값이 표시됩니다. **Build my first report**는 사용자의 데이터로 샘플을 만듭니다. 드릴하면 보고서가 행과 열 전체를 삽입하고 제거하며, 직접 입력한 값, 메모, 서식은 해당 행을 따라갑니다. [보고서 만들기](/ko/reference/cli/plaidxl/build-a-report/)를 참조하십시오.
  - **어느 셀에서든 드릴합니다.** **Drill down**, **Drill up**, **Keep only**, **Remove only**는 노드를 라이브 `DRILL` 수식으로 바꾸고 노드, 차원 제목 또는 보고서 값에서 그 수식을 대신 편집해 줍니다. **Custom drill**은 행을 삽입하기 전에 미리 보여 주며, 멤버 선택기는 멤버를 삽입하거나 노드의 하위 항목으로 구성된 드롭다운을 셀에 추가합니다. `DRILL`은 제외하거나 펼칠 노드를 받을 수 있고 행 방향으로도 실행할 수 있습니다. [드릴, 멤버 선택, 숫자 설명](/ko/reference/cli/plaidxl/drill/)을 참조하십시오.
  - **숫자를 설명합니다.** **Explain this number**는 값이 어떻게 계산되는지, 현재 PlaidCloud와 일치하는지, 그리고 값이 나온 테이블과 워크플로 단계를 보여 줍니다. **Show detail rows**는 값의 근거가 되는 행을 별도의 시트에 표시하고 합계가 맞는지 검사합니다.
  - **Excel에서 관리되는 지표를 사용합니다.** `PLAIDXL.METRIC`과 `PLAIDXL.METRIC_BREAKDOWN`은 대시보드에 표시되는 것과 같은 비즈니스 지표를 반환합니다. 집계할 대상이 없는 `CELL` 또는 `CELLS`는 합계이면 `0`을, 그렇지 않으면 이유와 함께 `#VALUE!`를 표시하며(`CELLS` 스필에서는 비어 있음), **Metric...** 옵션은 프로젝트의 지표와 현재 값을 나열합니다. 지표는 둘 이상의 대체 계층으로 필터링할 수 있고, 대체 계층 멤버를 다른 차원의 멤버와 함께 사용할 수 있습니다. [지표](/ko/reference/cli/plaidxl/functions/#지표)를 참조하십시오.
  - **보고서에 직접 입력하여 계획합니다.** `CELL` 값 위에 숫자를 입력하면 PlaidCloud에 기록됩니다. 비례 배분, 균등 배분, 다른 멤버의 형태에 따른 배분, 금액 또는 백분율로 조정할 수 있으며 고정된 셀은 그대로 유지됩니다. 평균, 중앙값, 최솟값, 최댓값, 표준 편차, 분산 셀에도 입력 값을 쓸 수 있고, 입력한 값은 행이나 열을 삽입하거나 삭제해도 해당 셀을 따라갑니다(삭제된 셀의 값은 보고됩니다). **Undo last write**는 입력한 값과 저장을 최신 항목부터 되돌리며, 기록을 만든 사용자와 워크스페이스만 되돌릴 수 있습니다. 합계나 빈 셀에 입력한 평균을 되돌릴 때는 같은 셀에 그 이후 기록된 내용이 유지되며, 완료되기 전에 중단된 기록은 되돌릴 수 없습니다. [PlaidCloud에 값 입력](/ko/reference/cli/plaidxl/write-values/)을 참조하십시오.
  - **필요한 것만 새로 고칩니다.** 시트, 선택 영역 또는 모든 테이블을 새로 고칠 수 있으며 작업 창에 각 테이블의 진행률과 **취소**가 표시되고, PlaidXL 수식만 다시 계산할 수도 있습니다. 큰 테이블은 웹용 Excel과 최신 데스크톱 Excel에서 훨씬 빠르게 가져옵니다(143,000행 77열 테이블이 10분 넘게 걸리던 것이 약 1분 걸립니다. 이전 Excel 버전은 기존과 같이 작동합니다). Excel 셀이 담을 수 있는 길이를 넘는 텍스트는 표시되며 잘린 채 저장되지 않습니다. 가져온 테이블은 데이터 형식에 따라 서식이 지정된 Excel 테이블로 도착하고, 새로 고침할 때 사용자가 추가한 열과 숫자 서식을 유지하며, 자기 자리에서 새로 고쳐집니다. 가져오기나 새로 고침은 다른 셀을 덮어쓰거나 다른 Excel 테이블과 겹치지 않으며, Excel에서 표현하기에 너무 큰 정수 ID와 1900년 이전 날짜는 텍스트로 도착합니다. 테이블을 다시 가져와도 새로 고침 목록에 두 번 추가되지 않으며, **Stop refreshing**으로 목록에서 하나를 뺄 수 있고, 차원은 테이블과 함께 새로 고쳐집니다. [모든 테이블 새로 고침](/ko/reference/cli/plaidxl/retrieve/#모든-테이블-새로-고치기)을 참조하십시오.
  - **저장하면 바로 기록되며 되돌릴 수 있습니다.** **Save to PlaidCloud**는 확인 없이 기록하고 수행한 작업을 알려 주며 **실행 취소**를 제공합니다. 실행 취소는 Lakehouse 테이블에서 각 저장 후 최대 7일 동안 사용할 수 있습니다. 필터로 가져온 시트, 세부 행 시트, 또는 액세스 권한이 일부 행에만 해당하는 사용자는 해당 행만 바꾸므로 다른 사람의 행은 유지됩니다. 가져온 이후 멤버가 변경된 드릴스루 시트는 저장되지 않으며, 저장에 실패하면 테이블을 되돌릴 수 있도록 복원 지점이 표시됩니다. [PlaidCloud에 테이블 저장](/ko/reference/cli/plaidxl/retrieve/#테이블을-plaidcloud에-저장)을 참조하십시오.
  - **Excel에서 Weave에 문의합니다.** **Weave** 탭에서 보고서, 수식, 드릴 또는 테이블을 일상적인 말로 요청하거나 **Ask Weave about this cell**을 선택합니다. Weave는 사용자 권한으로 PlaidCloud를 읽고 워크북만 변경하며, 입력한 내용을 바꾸기 전에 먼저 묻고, 워크북 밖을 참조하는 수식은 절대 작성하지 않으며, 각 변경은 창을 다시 로드하기 전까지 되돌릴 수 있습니다. [Excel에서 Weave에 문의](/ko/reference/cli/plaidxl/weave/)를 참조하십시오.
  - **시트 하나 또는 전체 워크북의 값만 담은 사본을 공유합니다.** **Convert to values**는 전체 워크북이나 시트 하나를 변환하거나 되돌릴 수 없는 값으로 변환하며(먼저 확인을 요청합니다), PlaidXL 수식과 해당 스필만 변경하고, 아직 계산 중인 수식은 다시 시도할 수 있도록 남겨 두며, **Restore PlaidXL formulas**는 시트 이름을 바꾼 후에도 여전히 작동합니다.
  - **작업 창의 디자인이 새로워졌습니다.** PlaidCloud 웹 앱과 같은 모양으로, 브랜드 블루, 레일 스타일 탭과 목록, 크기가 제한된 스크롤 카드에 담긴 테이블, 차원, 프로젝트, 열을 제공합니다. 키보드 포커스는 뚜렷한 링으로 표시되며 작업 창은 Office의 밝은 테마 또는 어두운 테마를 따릅니다. 탭은 좁은 창에서는 가로 3개, 세로 2줄로 배치되고 너비 560픽셀부터는 한 줄로 배치됩니다. [밝은 테마와 어두운 테마](/ko/reference/cli/plaidxl/connect/#밝은-테마와-어두운-테마)를 참조하십시오.
  - **작업 창의 숫자가 Excel의 표시 언어를 따릅니다.** 행 및 열 수와 새로 고침, 다시 계산, 설명, 수식, 보고서, 계획 메시지가 사용자의 Excel과 같은 방식으로 숫자를 표시하므로, 독일어 Excel에서는 4.812.233으로 표시됩니다. 셀에 기록되는 값은 변경되지 않습니다.
  - **새로 고치는 동안 시트 탭이 노란색으로 바뀝니다.** 작업 창, 리본 또는 Weave 어디에서 실행하든 **Refresh All Tables**를 실행하는 동안 해당 시트가 새로 고쳐지는 중에는 시트 탭이 노란색이고, 새로 고침이 끝나거나 실패하거나 취소되면 사용자가 지정한 색을 포함한 이전 색으로 돌아갑니다. 중간에 워크북을 저장하고 닫으면 다음에 PlaidXL이 시작될 때 탭 색이 복구됩니다. [모든 테이블 새로 고침](/ko/reference/cli/plaidxl/retrieve/#모든-테이블-새로-고치기)을 참조하십시오.
- **전기 등록부는 확인이 필요한 항목에서 열립니다.** 확인이 필요한 항목이 있으면 **예외**에서, 승인을 기다리는 요청이 있으면 **승인**에서, 그렇지 않으면 **모든 전기**에서 열립니다. 레일은 화면을 **내 확인 필요**, **등록부**, **인사이트**, **설정**으로 묶고 **예외**와 **승인**에 건수를 표시하며, 모든 화면이 하나의 헤더와 범위 표시줄을 공유합니다. 기간(**이번 달**, **이전 달**, **지난 7일**, **지난 30일** 또는 **사용자 지정**), 연결, 프로젝트, 환경 또는 엔터티, 그리고 **실거래**, **시뮬레이션** 또는 **모두**를 선택한 다음 **재설정**하거나 **Saved scope**를 유지할 수 있습니다. 마지막으로 사용한 범위가 기억됩니다.
  - **예외 화면이 확인이 필요한 항목을 정리합니다.** **확인 필요**, **미확인**, **대기 중**, **실패**, **되돌리기 미완료** 칩에 건수가 표시되고, 연결 상태 줄에는 "All N connections posting normally"라고 표시되며, 모든 전기에는 다음에 해야 할 일을 알려 주는 툴팁이 있는 쉬운 말의 상태가 표시됩니다. 열려 있는 항목이 없으면 **All clear**가 표시됩니다. **Find a posting by ledger id** 또는 명령 팔레트에 원장 ID를 붙여넣으면 해당 전기가 바로 열립니다.
  - **승인, 위임, 감시는 받은 편지함 화면입니다.** **Waiting on me**와 **Submitted by me** 사이를 전환하고, 이유와 함께 **승인** 또는 **거부**하며, 여러 건을 한 번에 승인하고, 토스트에서 승인을 **실행 취소**할 수 있습니다. **Delegate approvals**는 짧은 대화 상자이고 **내 감시 목록**에는 팔로우하는 항목이 나열됩니다. **전기 되돌리기**와 일괄 재시도 및 지우기 대화 상자는 같은 레이아웃을 공유합니다.
  - **전기의 서랍이 무슨 일이 있었는지 알려 줍니다.** 상태와 그 의미, 이름이 붙은 주요 사실, 그리고 **라인**, **기록**, **승인** 탭이 표시되며, **검토됨으로 표시**, **다시 시도**, **되돌리기…** 버튼, **연결 감시**, **실행 감시**, 해당 전기를 바로 여는 **링크 복사**가 있습니다.
  - **지원, 내보내기, 보존도 같은 디자인을 따릅니다.** **지원**에는 질문 상자와 인사이트 카드, **Draft — nothing applied**로 표시되는 조언, **모든 전기**의 **보기** 버튼이 있는 이상 징후 카드가 있습니다. **내보내기 및 알림**에는 **New schedule**이 있고 **보존**은 카드 하나입니다.
  - **등록부가 최신 상태로 유지됩니다.** 전기가 변경되면 레일 배지가 업데이트되고, 열려 있는 목록은 전기가 변경된 경우 **새로 고침**을 제공하며, 열려 있는 서랍은 제자리에서 업데이트됩니다. **홈**에는 **조치 필요** 아래에 **전기 등록부** 카드가 표시됩니다. [전기 등록부 검토](/ko/guides/connections/posting-register/)를 참조하십시오.

[Panel Studio](/ko/guides/panel-apps/studio/#앱이-저장되는-위치)를 참조하십시오.
- **Git 앱이 리포지토리를 나열하고 할 수 있는 작업을 알려 줍니다.** 앱 목록의 **Git**은 사용자의 역할(**Administrator**, **Contributor** 또는 **뷰어**)과 워크스페이스의 리포지토리를 표시하며, 각 리포지토리에는 설명, 마지막 업데이트 날짜, 복사 버튼이 있는 복제 주소, **열기**가 있습니다. **Set up Git on your computer** 카드는 Git 설치, 토큰 생성, 복제 과정을 안내하며 **How to clone**으로 다시 열 수 있습니다. **View all in Git**은 전체 Git 인터페이스를 열고 **Manage who can push**는 그룹 관리를 엽니다. 액세스 수준은 **뷰어**, **Contributor**(`apps`에 앱 코드 푸시), **Administrator**(`udfs`를 포함해 모든 곳에 푸시)이며, 뷰어에게는 문의할 수 있는 워크스페이스 관리자가 최대 세 명까지 표시됩니다. 새 **Git Contributors** 그룹은 Contributor 권한을 부여하며 기본 그룹으로 지정할 수 있어 신규 멤버가 자동으로 권한을 얻고, **Git Administration**은 관리자 권한을 부여합니다. 멤버의 **Git** 탭에는 해당 멤버의 Git 사용자 이름, 수준, 그 수준을 부여하는 그룹이 표시됩니다. 멤버의 Git 계정은 멤버십을 따릅니다. 멤버를 비활성화하거나 제거하면 토큰과 SSH 키를 포함해 약 한 시간 안에 Git 계정이 차단되고, 다시 활성화하면 차단이 해제되며 리포지토리와 기록은 유지됩니다. 싱글 사인온으로 Git에 로그인하면 멤버 본인의 계정이 열립니다. Contributor는 워크스페이스의 Git 조직에서 리포지토리를 직접 만들지 않으며, 리포지토리는 PlaidCloud를 통해 만들어집니다. 앱 창에는 **리포지토리** 섹션이 표시되고 UDF에는 **열기**가 있으며, Git에는 워크스페이스로 돌아가는 **← Back to** 링크가 있습니다. 앱 리포지토리와 기본 제공 `apps` 및 `udfs` 리포지토리를 포함해 플랫폼이 만드는 모든 리포지토리는 워크스페이스에 로그인한 모든 멤버가 읽을 수 있으므로, 멤버가 리포지토리별 설정 없이 앱을 열고 다시 게시할 수 있습니다. Git 관리자는 여전히 리포지토리를 비공개로 만들 수 있으며, 이 경우 리포지토리 선택기에서 숨겨지고 멤버가 해당 리포지토리에서 게시하거나 그 안에 저장된 Git 기반 UDF 코드를 실행할 수 없게 됩니다. [PlaidCloud Git](/ko/guides/git/#git-열기)과 [리포지토리를 볼 수 있는 사용자](/ko/guides/connections/plaidcloud-git/#리포지토리를-볼-수-있는-사용자)를 참조하십시오.
- **Cost to Serve 및 Operational Transfer Pricing 템플릿은 Common Finance Model을 기반으로 합니다.** **Cost to Serve**에서 프로젝트를 시작하면 각 부서에 설정한 활동과 동인에 따라 영업 비용을 고객에게 배부하고, 총계정원장과 연결된 고객별 서비스 제공 비용 차감 후 마진을 확인할 수 있습니다. **Operational Transfer Pricing**에서 시작하면 각 엔터티의 이익 수준(매출 대비 수익률, 순원가 가산 또는 재판매 가격 차감)을 정책 범위와 비교하여 검증하고, 범위를 벗어난 엔터티를 목표로 되돌리는 정산 조정도 확인할 수 있습니다. 매출 대비 수익률은 EBIT를 검증 대상 당사자의 매출로 나눈 값입니다. [Cost to Serve](/ko/guides/projects/cost-to-serve/)와 [Operational Transfer Pricing](/ko/guides/projects/operational-transfer-pricing/)을 참조하십시오.
- **OneStream과 Anaplan이 Data Foundation에 데이터를 제공하며, OneStream 읽기 단계가 추가되었습니다.** Data Foundation은 OneStream 관리자가 구성한 데이터 어댑터를 통해 OneStream 연결 결산 결과를 읽고, 내보내기 작업을 통해 Anaplan 계획을 읽어 그룹 손익계산서를 이들과 대사합니다. 새 **OneStream: Read Adapter** 단계는 모든 워크플로에서 어댑터를 읽어 연결 멤버마다 한 번씩 호출하고 그 결과를 테이블에 기록합니다. [Data Foundation용 OneStream](/ko/guides/connections/onestream-for-data-foundation/), [Data Foundation 소스로서의 Anaplan](/ko/guides/connections/anaplan/#data-foundation의-소스로서의-anaplan), [OneStream: Read Adapter](/ko/reference/workflow-steps/onestream/onestream-read-adapter/)를 참조하십시오.
- **Data Foundation이 공유 비용을 배부하는 방식을 선택합니다.** **작업 > Allocations...** 메뉴는 부서에 대한 간접비와 부서에서 제품 및 고객으로의 배부에 대해, 어떤 비용을 배부할지, 무엇을 기준으로 배부할지, 어디에 귀속시킬지, 음수 동인을 어떻게 처리할지를 차례로 안내하며, 한 달 분량의 미리 보기에서 풀링된 금액, 배부된 금액, 배부되지 않은 금액을 보여 줍니다. 직접 편집한 규칙은 유지됩니다. [배부 규칙](/ko/guides/projects/data-foundation/#배부-규칙)을 참조하십시오.
- **Data Foundation에서 숫자를 설명하고 원하는 이름으로 부릅니다.** **Explain this number**는 사용자의 행 액세스 권한 범위에서 손익계산서 수치를 원장이 보유한 금액, 배부로 유입 및 유출된 금액, 그룹 내에서 제거된 금액으로 나누어 가장 큰 원본 문서와 함께 보여 줍니다. **Business names**는 범주, 손익계산서 라인, 지표, 열에 비즈니스에서 쓰는 이름을 지정하여 보고서, 지표, 어시스턴트에 사용합니다. [숫자 설명](/ko/guides/projects/data-foundation/#숫자-설명)과 [비즈니스 이름](/ko/guides/projects/data-foundation/#비즈니스-이름)을 참조하십시오.
- **Data Foundation은 로드할 때마다 이사회 보고 자료를 작성하며 이전 상태로 되돌릴 수 있습니다.** **로드**를 실행할 때마다 Excel 통합 문서와 손익계산서 대시보드 PDF가 문서 계정의 폴더에 기록되며, 보고를 끄면 보고 자료는 통합 문서만 만들어지고 대화 상자에 그 사실이 표시됩니다. 각 로드가 시작될 때와 매핑 또는 소스를 변경하기 전에 복원 지점이 만들어지고, **작업 > Restore...** 메뉴는 각 복원 지점이 되돌리는 테이블 수를 보여 주며 차원을 포함한 프로젝트를 되돌립니다. **Foundation** 탭에는 **상태**, **필요한 답변**, **소스 범위**, **소스** 페이지가 있는 자체 레일이 있고, 조치가 필요한 항목에 대한 배지, 모든 페이지 위에서 변경 사항을 적용하는 하나의 표시줄이 있으며, 진행 상황이 더 명확하게 표시됩니다. 아직 실행 중이거나 중간에 중단된 업데이트를 보여 주고, 테이블 폴더가 소스가 될 수 없는 이유를 알려 주며, 일치하는 항목이 생길 때까지 **합계 일치 여부 확인**을 대기 상태로 유지하고, 상태 읽기가 실패해도 복구됩니다. 업데이트를 적용해도 생성된 단계에 대한 사용자의 편집 내용이 유지되며 충돌이 있으면 그 내용이 기록됩니다. [이사회 보고 자료](/ko/guides/projects/data-foundation/#이사회-보고-자료)와 [복원 지점](/ko/guides/projects/data-foundation/#복원-지점)을 참조하십시오.
- **Data Foundation은 여러 ERP와 시스템을 하나의 모델로 통합하며, 각 시스템에서 로드할 회사를 선택할 수 있습니다.** **소스** 페이지의 **Connect a system**은 시스템 종류마다 타일을 제공하고, **Connect another system**은 기존 항목을 바꾸지 않고 다른 ERP 또는 다른 인스턴스를 추가합니다. **Load order**에서 소스의 **편집**을 선택하면 해당 소스의 자회사 목록인 **Companies**가 있으며, 로드할 회사를 선택하거나 하나도 선택하지 않으면 모두 로드합니다. 회사를 제외하려고 하면 먼저 확인을 요청하는데, 저장할 때 이미 로드된 해당 회사의 행이 지워지고 다음 **로드**에서 선택한 회사를 다시 가져오기 때문입니다. 소스의 연결이 이제 다른 계정을 읽는 경우 다른 소스를 변경하는 대신 메시지와 함께 저장이 거부됩니다. [소스](/ko/guides/projects/data-foundation/#소스)를 참조하십시오.
- **Data Foundation 프로젝트를 복제하거나 템플릿으로 저장합니다.** **작업 > 복제...** 메뉴는 모델 편집 내용, 지표, 분석 경로와 함께 프로젝트를 복사합니다. **Save as my template...** 옵션은 설정을 문서 계정에 저장하고, **From a template file...** 옵션은 이 파일에서 소스가 연결을 기다리는 새 비공개 프로젝트를 시작합니다. [프로젝트 복제](/ko/guides/projects/data-foundation/#프로젝트-복제)와 [내 템플릿으로 저장](/ko/guides/projects/data-foundation/#내-템플릿으로-저장)을 참조하십시오.
- **Data Foundation의 설정 체크리스트가 인계까지 이어지며, 어시스턴트가 남은 항목을 해결할 수 있습니다.** 체크리스트에 야간 새로 고침, 증빙 자료, 프로젝트를 소유자에게 인계하는 항목이 추가되었으며 누가 프로젝트를 설정했는지도 표시됩니다. 어시스턴트에게 유형이 없는 계정, 여러 소스에서 사용하는 코드, 어떤 항목과도 일치하지 않은 파일 열에 대한 답변을 제안해 달라고 요청할 수 있습니다. 어시스턴트는 아무것도 기록하지 않으며 답변은 사용자가 적용합니다. [Data Foundation 시작하기](/ko/guides/projects/data-foundation-getting-started/)와 [Ask로 미해결 질문 해결](/ko/guides/projects/data-foundation/#ask로-미해결-질문-해결)을 참조하십시오.

- **Weave에 모니터가 추가되었습니다.** **Weave** 탭의 **결과 항목** 페이지가 이제 **모니터**가 되었습니다. 모니터의 레일에는 **결과 항목**, **Team**, **활동**, **월별 요약**, **예상됨**이 묶여 있고, 마감 점검 항목인 **준비 상태**와 **대사**는 **마감 점검** 아래에 묶여 있습니다. **결과 항목**에는 미해결 문제, 담당자가 없는 문제, 가장 오래된 미해결 문제에 대한 타일이 표시되고, 결과 항목이 심각도별로 묶이며, 각 행에 소유자, 미해결 기간, 작업 하나가 표시됩니다. **수정** 또는 **열기**가 먼저 표시되고 나머지는 **⋯** 아래에 있습니다. 행을 열면 Weave의 문장, 근거, Weave가 이를 아는 방법, 댓글을 읽을 수 있으며, **소유자**와 **워크플로**로 필터링할 수 있습니다. [Weave 탭](/ko/guides/ai-assistant/weave-tab/)을 참조하십시오.
- **Weave가 모든 앱 옆에 있으며, 오른쪽 클릭으로 Weave에 물어볼 수 있습니다.** 창 오른쪽의 **Weave 도크**에는 Weave 대화, Weave가 제안하는 변경 사항, 작업이 담겨 있습니다. 클릭하거나 **Ctrl+J**(Mac에서는 **Cmd+J**)를 눌러 열 수 있고, 너비를 기억하며, 현재 열려 있는 항목에서 시작하고 이 항목은 제거할 수 있는 칩으로 표시됩니다. 단계, 여러 단계, 워크플로, 테이블, 열, 대시보드 또는 로그의 오류 줄을 오른쪽 클릭하여 **설명**, **사용되는 위치**, **변경 내용**, **검사**, **수정**, **변경…**, **문서** 또는 **Weave에 문의**를 선택합니다. 대부분은 AI 모델을 호출하지 않고 답하며, Weave가 어떻게 아는지 알려 줍니다. 요청하기 전에는 아무것도 스캔하지 않습니다. [Weave 도크](/ko/guides/ai-assistant/weave-dock/)을 참조하십시오.
- **실패한 단계를 한 번에 수정합니다.** 단계를 오른쪽 클릭하고 **수정**을 선택합니다. Weave는 무엇이 바뀌는지, 영향이 어디까지 미치는지, 다음에 무엇이 일어나는지를 담은 카드를 보여 줍니다. 승인을 한 번 하면 여러 단계에 걸친 변경도 적용되고, ERP 전기를 끈 상태로 수정된 단계를 다시 실행하며, 문제가 해결되었는지 분명하게 알려 줍니다. 승인은 브라우저에서만 할 수 있습니다. 자리를 비운 동안 Weave가 준비한 카드는 대화 안에서 열 수 있는 **Waiting for you** 행으로 기다리며, 그사이 바뀐 것이 있으면 현재 상태를 보여 줍니다. Weave가 만든 변경 중 실행 취소할 수 있는 모든 변경에는 **실행 취소**가 있으며, 카드 전체를 한 번에 되돌릴 수 있고, 무엇을 복원할지 먼저 보여 줍니다. [AI로 워크플로 오류 수정](/ko/guides/ai-assistant/fixing-workflow-errors/)을 참조하십시오.
- **자리를 비워도 Weave 작업이 계속 진행됩니다.** **Weave** 버튼에서 **Weave 작업…** 메뉴를 선택하면 각 작업의 상태를 보고, 진행 상황을 따라가고, 대화를 열거나 작업을 중지할 수 있습니다. 도크나 탭을 닫아도 작업은 계속되며, 작업이 끝나거나 확인이 필요하면 메시지를 받고, 1분 넘게 실행되었고 중지되지 않은 작업이라면 앱을 사용하는 경우 휴대폰 알림도 받습니다. [계속 진행되는 작업](/ko/guides/ai-assistant/weave-dock/#계속-진행되는-작업)을 참조하십시오.
- **결과 항목이 유용했는지 Weave에 알려 줄 수 있습니다.** 일부 결과 항목은 알려 줄 가치가 있었는지 엄지 위와 엄지 아래로 물으며, **월별 요약**에는 Weave의 결과 항목과 답변이 얼마나 유용했는지 표시됩니다. [Weave 탭](/ko/guides/ai-assistant/weave-tab/)을 참조하십시오.
- **모바일 Weave의 음성 입력은 한 번만 탭하면 됩니다.** 마이크를 탭하고 질문하면 말을 멈추는 즉시 Weave가 질문을 보냅니다. 일찍 멈추려면 마이크를 다시 탭하며, 아무 소리도 들리지 않으면 저절로 꺼집니다. 말하는 도중에 **Weave** 탭을 벗어나거나 앱을 백그라운드로 보내면 말한 내용이 전송되지 않은 채 질문 상자에 남아 있어 검토할 수 있습니다. 실행, 일시 중지, 중지, 재개는 확인 단계에서 실수로 두 번 탭해도 무시합니다. 앱 버전 1.3.0 이상이 필요합니다. [음성 사용](/ko/guides/mobile-app/weave-on-mobile/#음성-사용)을 참조하십시오.
- **Weave가 문제를 이메일로 알려 줍니다.** 워크플로 실행이 확인해야 할 심각한 문제로 끝났을 때 받는 이메일과, Weave가 알려 주었지만 아직 읽지 않은 문제를 원하는 시간에 정리해 주는 일일 요약을 본인에게 사용 설정할 수 있습니다. 이메일에는 프로젝트와 각 워크플로, 단계, 테이블 또는 지표의 이름이 문제 종류와 함께 표시되고, **Weave** 탭으로 돌아가는 링크가 있으며, 데이터의 수치나 값은 절대 포함되지 않습니다. 워크스페이스 관리자는 모든 사용자의 Weave 이메일을 끌 수 있으며, 각 멤버의 시간대를 기준으로 방해 금지 시간을 설정하여 그 시간이 끝날 때까지 알림을 보류할 수 있습니다. [Weave 이메일](/ko/guides/ai-assistant/weave-email/)을 참조하십시오.
- **Weave가 데이터를 사용하는 방식.** **Weave** 메뉴, 모든 AI 채팅 아래, **AI 기능**에 새 패널이 추가되었습니다. 이 패널은 워크스페이스에서 Weave에 응답하는 AI 공급자와 그 위치, Weave가 공급자에게 보내는 내용, 학습과 보존에 관해 아직 확인 중인 사항을 알려 줍니다. [Weave의 고객 데이터 사용 방식](/ko/guides/ai-assistant/weave-data-use/)을 참조하십시오.

## 변경됨

- **하나의 필터링 가능한 체크리스트로 어디에서나 사용자, 그룹, 워크플로를 할당합니다.** 보안 그룹 멤버, 멤버의 그룹 연결, 배포 목록 멤버, 문서 계정 멤버, 그룹, 에이전트와 소유자, 연결 액세스, Weave 준비 상태 집합의 워크플로가 두 목록 사이에서 끌어다 놓는 대신 같은 선택기를 사용합니다. 이름이나 이메일(`@example.com` 같은 도메인 포함)로 필터링하려면 입력하고, 정확히 그 사람들만 일치시키려면 이메일 목록을 붙여넣고, **모두**, **할당됨**, **할당되지 않음** 사이를 전환하며, **Assign all shown** 또는 **Unassign all shown**을 사용합니다. 변경한 행에는 **Will add** 또는 **Will remove** 표시가 붙고, **Undo changes**로 되돌릴 수 있으며, 저장 버튼은 변경된 내용이 있을 때만 사용할 수 있습니다. 필터에서 **Enter**를 눌러도 저장되지 않고, **Space**는 선택한 행을 선택(체크)합니다. 액세스를 볼 수는 있지만 변경할 수 없는 경우 목록은 읽기 전용입니다.
- **워크스페이스에서 Grok을 사용하면 모바일의 Weave가 AI 고지에 다시 동의하도록 요청합니다.** 고지에서는 더 이상 xAI가 사용자의 데이터로 모델을 학습하지 않는다고 하지 않습니다. 이제 PlaidCloud는 xAI와 데이터 무보존 계약이 없으므로 xAI가 데이터를 보관하고 표준 약관이 허용하는 대로 사용할 수 있다고 안내합니다. [Weave가 데이터를 사용하는 방식](/ko/guides/ai-assistant/weave-data-use/)을 참조하십시오.
- **가정 분석 창이 한 번에 한 기간씩 읽습니다.** Allocation Split 단계의 출력에 기간 열이 있으면 창이 가장 최근 기간에서 열리고, **기간:** 상자에서 다른 기간 또는 **모든 기간**을 선택할 수 있습니다. 동인이 모든 기간마다 라인을 가지고 있어 전체 기간을 한꺼번에 읽기에는 너무 큰 단계도 이제 한 기간에 대해 열고 답합니다. 저장된 시나리오는 저장할 때의 기간이 있으면 그 기간을 유지하며, 시나리오를 열면 해당 기간이 아직 목록에 있는 동안 창이 그 기간으로 이동합니다. [기간 선택](/ko/guides/allocations/results/driver-what-if/#기간-선택)을 참조하십시오.
- **PlaidCloud의 웹 앱과 Python 클라이언트 라이브러리는 REST API를 사용하며 JSON-RPC는 더 이상 사용되지 않습니다.** 웹 앱은 요청을 REST API로 보냅니다. `plaidcloud-rpc` 1.25.0 이상에서는 `SimpleRPC` 호출이 코드를 변경하지 않아도 REST API로 전달되며, REST API가 아직 지원하지 않는 호출이나 이전 릴리스를 사용하는 워크스페이스에서는 이전과 같이 JSON-RPC를 사용합니다. JSON-RPC는 이후 릴리스에서 제거될 예정이므로 스크립트와 노트북을 `plaidcloud-rpc` 1.25.0 이상으로 업그레이드하고 새 통합은 REST API를 기준으로 작성하십시오. [명령줄](/ko/reference/cli/jupyter/command-line/)을 참조하십시오.
- **단계는 다른 환경으로 고정하지 않는 한 프로젝트의 연결 환경을 따릅니다.** 프로젝트를 QA와 프로덕션 같은 환경 사이에서 전환하면 모든 단계가 함께 이동합니다. 한 환경에 머물러야 하는 단계에는 대신 **Fixed environment**를 지정할 수 있습니다. 양식에는 경고 표시가 있고, 단계 로그에는 프로젝트의 환경이 아닌 환경에서 실행될 때마다 기록되며, 프로젝트를 전환할 때 따라가지 않는 단계의 이름이 표시됩니다. ERP 전기 단계는 항상 프로젝트의 환경을 사용합니다. 프로젝트, 고정된 단계 또는 에이전트가 사용 중인 환경은 삭제할 수 없으며, 에이전트 양식의 필드는 이제 **Environment this agent serves**입니다. [단계를 하나의 환경에 고정](/ko/guides/projects/managing-projects/#단계를-하나의-환경에-고정)을 참조하십시오.
- **단계 양식이 하나의 레이아웃을 따릅니다.** 탭은 표준 이름과 표준 순서를 사용합니다. General, Settings, Source, Columns, Filters, Output, Advanced이며 ERP 전기 양식에는 Header columns와 Line columns가 있습니다. 필수 필드에는 *가 표시되며, 양식은 단계에 필요한 항목이 없을 때만 저장을 막습니다.
- **Acumatica, Bill.com, Dynamics, Eclipse, HFM/FCCS, NetSuite, Workday, Workday Financials 연결을 설정을 잃지 않고 만들고, 편집하고, 단계에서 선택할 수 있습니다.** 이 연결은 REST 연결로 저장되며 **연결** 목록에 해당 서비스 고유의 유형이 표시됩니다. 연결을 마우스 오른쪽 버튼으로 클릭하고 **Edit REST settings**를 선택하면 연결의 헤더, 인증, 페이지 매김이 열립니다. 저장된 NetSuite 및 HFM/FCCS 연결에서는 **연결 테스트**가 작동합니다. Workday Financials 연결은 통합 시스템 사용자와 암호를 함께 입력하거나 OAuth 클라이언트로 로그인하며, Workday, Bill.com, Dynamics, Eclipse 양식에는 **API 호스트** 필드가 있습니다. [연결 만들기 및 관리](/ko/guides/connections/create-connection/)를 참조하십시오.
- **데이터 입력 양식이 각 필드를 레이블 옆에 배치합니다.** 필드는 오른쪽 끝에 고정되지 않고 일정한 너비로 왼쪽에 정렬되며, Data Foundation의 **연결** 및 **소스**, 문서 계정 설정, 멤버 프로필에 적용됩니다.
- **프로젝트 복사는 테이블 데이터와 차원 멤버를 따로 선택하고, 데이터를 더 빠르게 복사하며, 비공개 사본의 ERP 쓰기 승인을 유지합니다.** **Data to copy**에서 **테이블 데이터**(**테이블 데이터 없음**(기본값), **전체** 또는 **샘플**)와 별도로 **Copy dimension members**(기본적으로 켜져 있음)를 선택하므로, 테이블 행이 없는 복사본도 채워진 차원과 함께 만들어지며 빠르게 만들 수 있습니다. **전체**와 **샘플** 복사는 여러 테이블을 동시에 복사하므로 테이블이 많은 프로젝트가 더 빨리 끝납니다. **복사 결과**에는 테이블과 함께 각 차원의 결과가 나열되고, **Retry failed items**는 실패한 테이블과 차원을 함께 다시 시도합니다. 데이터와 함께 만든 새 사본은 사용자에게만 비공개이며 직접 부여할 수 있는 원본의 ERP 쓰기 승인을 유지합니다. 원본이 실거래로 전기하는 경우 사본은 시뮬레이션 상태로 만들어지므로 실거래로 전환하기 전에는 ERP에 아무것도 전달되지 않습니다. REST API와 `project_copy` MCP 도구도 `dimension_members`를 받습니다. [복사할 데이터 양 선택](/ko/guides/projects/managing-projects/#복사할-데이터-양-선택)과 [복사본의 ERP 쓰기 승인](/ko/guides/projects/managing-projects/#복사본의-erp-쓰기-승인)을 참조하십시오.
- **테이블의 세부 정보 패널이 사용하는 단계를 더 빨리 표시합니다.** 다른 테이블을 선택하면 이전 테이블의 단계가 즉시 지워지며, 이 프로젝트의 데이터를 공유하는 다른 프로젝트의 단계는 패널 전체를 지연시키지 않고 나머지보다 잠시 뒤에 추가됩니다. [테이블 사용 위치 확인](/ko/guides/projects/managing-tables-and-views/#테이블이-사용되는-위치-보기)을 참조하십시오.
- **행 작업이 모든 목록에서 같은 방식으로 작동합니다.** 행 시작 부분의 **⋯** 버튼, 행을 마우스 오른쪽 버튼으로 클릭, 또는 도구 모음의 **작업** 메뉴에서 행의 메뉴를 엽니다. 메뉴에는 항상 **열기**, **세부 정보**, **편집**이 먼저 나오고, 그다음 목록 고유의 작업, 마지막으로 **삭제** 또는 **제거**가 나오며, 행에 적용되지 않는 작업은 그 자리에서 회색으로 표시됩니다. **Enter**와 **Del**은 실행하는 항목에 표시됩니다. 행에 작업이 하나뿐인 목록은 **⋯** 대신 그 작업의 아이콘을 표시하며, 대시보드, 앱, 노트북은 다시 **열기** 아이콘을 표시합니다. [행 작업 메뉴](/ko/guides/dashboards/using-dashboards/#행-작업-메뉴)를 참조하십시오.
- **PlaidCloud의 파란색 디자인이 새로워졌으며 밝은 테마와 어두운 테마를 모두 지원합니다.** 버튼, 확인란, 선택한 행, 탭, 링크, 워크스페이스 페이지를 나열하는 레일이 하나의 PlaidCloud 블루를 사용하며, 두 테마 모두에서 읽을 수 있는 대비를 갖추었습니다. 앱 탭 아이콘은 일관된 하나의 세트입니다.
- **새로운 로딩 화면.** PlaidCloud가 밝은 테마 또는 어두운 테마를 따르는 더 깔끔한 로딩 화면에서 열립니다. 유휴 상태에서 깨어나는 Panel 또는 Dash 앱은 **시작 중**, **준비 중**, **앱 로드 중** 순으로 진행 상황을 표시하며, 시작되지 않으면 어느 단계에서 멈췄는지 알려 주고 **다시 시도**를 제공합니다. [Panel 앱 사용](/ko/guides/panel-apps/using/)을 참조하십시오.
- **검증 설정이 없는 저장된 ERP 쓰기 단계는 검증 전용으로 열립니다.** SAP Post, SAP Attach, NetSuite Post, Oracle EBS GL 및 AP Post, Xero 내보내기가 이에 해당합니다. 명시적으로 실거래로 실행하도록 설정된 단계는 계속 실거래로 유지됩니다.
- **장시간 실행되는 작업이 어디에서나 같은 방식으로 진행률을 표시합니다.**
- **워크플로가 정직하게 중지되고, 실패하고, 보고됩니다.** 워크플로를 중지하면 그것이 시작한 모든 것이 중지되고, 끝낼 수 없는 실행이나 단계는 멈춰 있는 대신 이유와 함께 실패하며, 실행 상태는 실제로 실행된 내용과 일치합니다.
  - **워크플로를 중지하면 그것이 시작한 모든 것이 중지되며, 끝낼 수 없는 실행이나 단계는 멈춰 있는 대신 실패합니다.** 중지하면 대기 중이던 가져오기와 차원 단계가 취소되므로 워크스페이스의 이후 가져오기와 차원 로드가 정상적으로 시작되며, 워크플로의 대기 중이거나 실행 중인 커넥터(Singer) 동기화도 중지됩니다. 단계의 작업을 시작할 수 없으면 단계가 영원히 기다리는 대신 이유와 함께 실패합니다. 약 40분 안에 어떤 워커도 이를 시작하지 않는 경우, 워커가 시작한 뒤 사라진 경우, 포드가 약 20분 동안 Pending 상태에 머무는 경우, 이미지를 약 5분 동안 가져올 수 없는 경우, 약 20분 동안 포드가 만들어지지 않는 경우가 이에 해당합니다. 약 30분 안에 어떤 러너도 가져가지 않은 커넥터 동기화는 해당 동기화의 이름이 담긴 메시지와 함께 실패합니다. 단계가 워커를 기다리는 동안 상태 메시지에는 지금까지 경과한 시간(분)과 함께 "Waiting for a worker…"가 표시되며, 작업이 시작되면 지워집니다. 매크로를 중지하면 실행 중인 모든 복사본이 중지되며, 복사본 하나를 중지하거나 **Macro Concurrent** 단계가 응답이 없는 복사본을 포기해도 이를 호출한 워크플로는 계속 실행됩니다. 다른 워크플로 안에서만 실행되는 매크로는 워크플로 목록에 **실행 중**으로 표시되고 **중지**를 사용할 수 있으며 각 단계의 상태, 시작 및 종료 시간은 가장 최근 실행에서 가져옵니다. 서버가 유실된 실행은 실패로 끝나며, 12시간이 지나도 계속 실행 중인 실행은 "Run failed: still running at the 12-hour limit. Re-run the workflow."라는 메시지와 함께 실패합니다. [워크플로 실행](/ko/guides/workflows/run-a-workflow/#시작되지-않는-단계)을 참조하십시오.
  - **재개, 실행 기록, 실행 상태가 실제로 실행된 내용과 일치합니다.** 상위 워크플로를 재개하면 하위 워크플로의 단계 하나를 따로 다시 실행한 뒤에도 하위 워크플로에 남아 있던 모든 것이 실행되며, 한 번의 실행 안에서 하위 워크플로를 호출할 때마다 각각 실행 기록 항목이 생깁니다. 서버가 중지되어 다시 시작되는 단계는 로그에 그 사실을 표시하고, `workflow_run_status`와 REST API의 실행 결과는 실패했지만 계속 진행된 단계를 실행이 깨끗했다고 보고하는 대신 `continued_step_ids`와 `continued_step_count`에 나열합니다. [일시 중지, 중지, 재개](/ko/guides/workflows/run-a-workflow/#일시-중지-중지-재개)와 [오류 발생 시 계속](/ko/guides/workflows/continue-on-error/)을 참조하십시오.
  - **단계 오류에 고유한 메시지가 표시됩니다.** PlaidCloud가 예상하지 못한 오류는 "The step stopped on an unexpected error (*type*): *message*"로 표시됩니다. 런처의 **조치 필요** 카드는 오류를 한 줄로 보여 주며 이후에 삭제된 워크플로의 실행은 제외합니다. [단계 오류 관리](/ko/guides/workflows/managing-step-errors/)를 참조하십시오.
  - **끝나지 않는 ERP 추출은 해당 단계를 실패시키며, 재개하면 계속됩니다.** **SAP: 임시 추출**이 행 또는 시간 제한에서 일시 중지되거나 에이전트가 제때 응답하지 않는 경우, 또는 Salesforce, Oracle Fusion 대량 또는 HFM/FCCS 내보내기 작업이 단계가 기다리기를 멈출 때까지 여전히 실행 중인 경우, 단계가 실패하므로 그 뒤의 단계가 일부만 채워진 테이블에서 실행되지 않습니다. 워크플로를 재개하거나 단계를 다시 실행하면 추출이 중단된 지점부터 같은 작업에서 계속됩니다. [실행 제한](/ko/guides/connections/sap-adhoc-extract/#실행-제한)과 [Salesforce: 개체 쿼리](/ko/reference/workflow-steps/salesforce/query-salesforce-object/#실행이-끝나지-않는-경우)를 참조하십시오.
  - **내보내기를 취소하면 웨어하우스의 쿼리도 중지됩니다.** 워크플로를 중지하는 경우를 포함하여 내보내기나 다운로드를 취소하면, Lakehouse v2, Snowflake, Databricks, PostgreSQL, Greenplum에서 데이터를 읽는 쿼리도 중지되고, 원격 데이터베이스로의 내보내기는 끝까지 계속 실행되는 대신 소스 읽기를 중지합니다.
- **워크스페이스를 업그레이드하면 REST, Import REST, Import Postman 단계가 REST 요청 단계로 변환됩니다.** 깔끔하게 변환할 수 없는 단계는 그대로 유지됩니다. [REST 요청 단계](/ko/guides/workflows/rest-request-step/)를 참조하십시오.
- **세션이 만료된 후 열린 대시보드 링크는 로그인하면 해당 대시보드로 이동합니다.** [대시보드 사용](/ko/guides/dashboards/using-dashboards/)을 참조하십시오.
- **MCP 도구는 인식하지 못하는 필드를 무시하는 대신 거부하고** 오류에 그 필드의 이름을 표시합니다. `workflow_upsert`는 `memo`를 받으며 `description`도 같은 이름의 대체 이름으로 허용합니다. [인식되지 않는 필드는 거부됨](/ko/integrations/ai-coding-agents/getting-started/#알-수-없는-필드는-거부됩니다)을 참조하십시오.
- **Lakehouse v2에서는 Lakehouse가 Parquet 내보내기를 Google Cloud Storage에 직접 기록합니다.** Google Cloud Storage 문서 계정으로의 내보내기는 모든 행이 먼저 PlaidCloud를 거치는 대신 계정 자체의 자격 증명으로 계정의 버킷에 바로 기록됩니다. Amazon S3 및 Azure Blob Storage 계정으로의 내보내기는 이전과 같이 작동합니다. [Parquet로 내보내기](/ko/reference/workflow-steps/export/export-to-parquet/)를 참조하십시오.
- **Slack, Microsoft Teams, Web Hook 단계가 메시지를 보내지 못한 이유를 알려 줍니다.** 단계의 오류에는 연결을 시도한 서버와(Slack 및 Teams의 경우) 연결의 이름이 표시되고 무엇이 잘못되었는지 알려 줍니다. 예를 들어 Slack이 더 이상 웹후크를 인식하지 못하는 경우, 채널에 게시할 수 없는 경우, 서버를 찾을 수 없거나 60초 안에 응답하지 않는 경우, 연결이 삭제된 경우입니다. 웹후크 URL을 가진 사람은 누구나 통합으로 게시할 수 있으므로 Slack 또는 Teams 웹후크 URL은 절대 표시되지 않습니다. [Slack으로 알림](/ko/reference/workflow-steps/notifications/notify-via-slack/)을 참조하십시오.
- **프로젝트 서비스 계정의 액세스 토큰은 최소 24시간 동안 유효합니다.** UDF 단계처럼 프로젝트로 실행되는 워크플로 작업은 24시간 동안 유효한 토큰을 받습니다. 더 짧은 수명은 워크스페이스를 업그레이드할 때 늘어나며, 직접 설정한 더 긴 수명은 유지됩니다.
- **워크스페이스의 조직, 소유자, 릴리스, 버전은 PlaidCloud가 설정하며, 데이터 센터는 사용자가 선택합니다.** 컨트롤 플레인에서 만든 워크스페이스는 사용자가 소유하고 PlaidCloud가 설정한 릴리스 채널에 배치되며, 가입 시 제공되는 리전 중에서 **Data Center**를 선택합니다. 조직, 소유자, 릴리스, 버전은 워크스페이스를 편집할 때 읽기 전용입니다. 버전을 변경하려면 **Set Version**을 사용하고, 워크스페이스 이동, 소유자 또는 채널 변경, 고정은 PlaidCloud 지원팀에 요청하십시오. [워크스페이스 구성](/ko/administration/control-plane/workspace-configuration/#기본-설정)을 참조하십시오.
- **인코딩 변환 단계가 폴더의 하위 폴더를 유지할 수 있습니다.** **문서: 파일을 ASCII 인코딩으로 변환**, **문서: 파일을 유니코드(UTF-8) 인코딩으로 변환**, **문서: 파일을 유니코드(UTF-16) 인코딩으로 변환**에 **하위 폴더 유지** 확인란이 있습니다. 이 항목을 선택하면 입력 폴더의 하위 폴더에 있는 각 파일이 대상의 같은 하위 폴더에 기록되며, 압축 파일의 내용은 해당 파일이 있던 하위 폴더로 들어갑니다. 선택하지 않으면 이전과 같이 모든 파일이 대상 자체에 기록됩니다. [문서 인코딩을 UTF-16으로 변환](/ko/reference/workflow-steps/document/convert-document-encoding-to-utf-16/)을 참조하십시오.
- **소스 테이블이 설정과 일치하지 않는 단계는 아무것도 기록하기 전에 중지되며 모든 문제를 한꺼번에 알려 줍니다.** Table Extract, Table Lookup, Table Inner Join, Table Cross Join, Table Outer Join, Table Anti Join, 다중 테이블 조인, Table Union Distinct, Table Union All, Table Pivot, Table Melt, Table In-Place Delete, Table Upsert, Table Append 단계는 기록하기 전에 소스 테이블을 검사합니다. 단계가 읽는 열이 테이블에 없거나, 조인 키가 없거나 단계의 소스 열에 없거나, 단계가 읽는 소스 테이블이 아직 만들어지지 않은 경우, 각 문제와 해결 방법을 알려 주는 하나의 오류와 함께 단계가 중지되며, 이미 존재하던 대상 테이블은 가지고 있던 내용을 유지합니다. 아직 만들어지지 않은 소스 테이블에 대해서는 Table Union Distinct와 Table Union All이 예외입니다. 이전과 같이 경고 없이 해당 테이블을 제외하고 나머지를 결합하며, 만들어진 것이 하나도 없으면 실패하는 대신 경고와 함께 완료됩니다. 단계가 나열했지만 읽지 않으며 테이블에 더 이상 없는 열은 경고로 처리되므로 이전에 실행되던 단계는 계속 실행됩니다. 대상이 뷰인 단계에서는, 웨어하우스가 어차피 뷰 생성을 거부하는 경우에만 단계가 나열한 열과 조인 키를 해당 테이블에 대해 검사합니다. 이러한 실패는 예전에는 데이터베이스가 자체 표현으로 열 하나씩 알려 주었고, 대상 테이블을 교체하는 단계는 이미 테이블을 비운 뒤였습니다. 워크플로의 오류 처리가 데이터베이스의 텍스트를 기준으로 일치시키고 있다면 업데이트하십시오. [단계가 실행되는 시점](/ko/reference/workflow-steps/tables/table-extract/#실행-시점에-지정되는-열)을 참조하십시오.
- **테이블이 없는 내보내기는 완료되는 대신 중지됩니다.** 테이블이 없는 Export to Parquet, Export to ORC, Export to Avro 단계는 파일을 기록하지 않고 완료되었으며, 테이블이 없는 Export to XML 단계는 아무것도 담지 않은 파일을 기록했습니다. 이제 이러한 단계는 아무것도 기록하기 전에 *No Tables Specified*와 함께 중지됩니다. 테이블 목록이 전혀 없이 저장되어 내부 설정을 지목하는 예기치 않은 오류로 실패하던 단계도 이제 같은 메시지와 함께 중지됩니다.

## 수정됨

- **잘못된 프로젝트 설정이 명확한 메시지로 보고됩니다.** 알 수 없는 환경이나 문서 계정, 이미 사용 중이거나 예약된 슬러그, 잘못된 스토리지 유형이나 전기 모드는 이제 일반적인 서버 오류 대신 문제를 지목하는 메시지를 반환합니다. REST API에서는 500이 아니라 400이며, AI 어시스턴트나 MCP에서는 잘못된 인수 오류입니다.
- **REST API의 차원 값 요청이 작동합니다.** `POST /rest/v1/analyze/query/retrieve-dimension-values`가 그리드 요청으로 처리되어 잘못된 요청으로 거부되었습니다. 이제 `value_columns`의 각 열에 대해 집계된 값 하나를 반환하며, 행 필터와 열 필터의 각 쌍에 대해 값 하나를 반환하는 그리드는 별도의 `POST /rest/v1/analyze/query/retrieve-dimension-cells`를 사용합니다.
- **느린 테이블 읽기와 파일 처리가 더 이상 다른 요청을 지연시키지 않습니다.** 웨어하우스에서 테이블의 열 읽기, Data Foundation 파일 등록, Excel로 내보내기, REST 또는 SOAP 가져오기의 응답 읽기, 문서 계정 사용 위치 찾기, Panel 앱의 코드나 로고 확인은 각각 끝날 때까지 같은 서버가 처리하던 다른 모든 요청을 일시 중지시킬 수 있었습니다. 이제 이러한 요청과 나란히 실행됩니다.
- **프로젝트 및 워크플로 변수 대화 상자가 스크롤됩니다.** 작은 화면이나 낮은 해상도에서 추가 및 편집 대화 상자가 창보다 커서 **만들기** 및 **업데이트** 버튼에 닿지 못할 수 있었습니다. 이제 양식이 스크롤되며 버튼은 맨 아래에 유지됩니다.
- **Azure Blob Storage 문서 계정에서 256MiB를 넘는 파일을 복사하고, 이동하고, 이름을 바꿀 수 있습니다.** 이전에는 이 크기의 파일에서 각 작업이 실패했으며, 그런 파일이 들어 있는 폴더를 이동하거나 이름을 바꿀 때도 실패했습니다.
- **Lakehouse v2에서 테이블의 행 수가 방금 기록된 내용을 반영합니다.** 테이블을 기록한 단계나 가져오기가 기록 이전의 행 수를 저장할 수 있어서 방금 로드한 테이블이 0행으로 표시되고 가져오기가 가져온 행이 0개라고 보고할 수 있었습니다. 이제 새 행이 모든 곳에서 보이게 된 뒤에 행 수를 읽으므로 그 이후 단계도 새 행을 읽습니다. 테이블을 다른 브랜치로 전환하거나 브랜치를 병합할 때도 행 수와 열 수가 업데이트됩니다.
- **Weave의 빈 값 검사가 각 실행을 이전 실행이 실제로 남긴 상태와 비교합니다.** 단계의 빈 값이 단계가 테이블을 다시 채우려고 비운 직후에 집계되는 경우가 많아, 이전 실행에는 빈 값이 없었던 것처럼 보였고 항상 일부가 비어 있던 열이 방금 비게 된 것처럼 보고되었습니다. 이제 각 실행은 단계가 테이블을 남긴 상태 그대로 집계됩니다. 이전에 기록된 집계는 올바른 값과 구분할 수 없어 사용하지 않으므로, 각 단계의 빈 값 검사는 기록을 다시 시작하며 실행 다섯 번이 집계될 때까지 검사되지 않음으로 보고됩니다. 행 및 값 분포 검사도 더 이상 단계가 끝난 지 2초가 지난 뒤에 다른 단계가 같은 테이블에 수행한 기록을 해당 단계의 것으로 인정하지 않습니다. [Weave 점검 항목](/ko/guides/ai-assistant/weave-findings/)을 참조하십시오.
- **Data Foundation이 역환율과 소수 임계값의 정밀도를 유지합니다.** 환율이 보고 통화에서 다른 통화로 표시되어 있어 PlaidCloud가 뒤집는 환율은 소수점 여섯 자리로 반올림될 수 있었고, 인도네시아 루피아처럼 환율이 작은 통화의 금액이 약 1% 어긋났습니다. 이제 역환율은 소수점 12자리를 유지합니다. `0.5`처럼 소수가 있는 `group_amber` 또는 `group_red` 임계값은 정수로 반올림되었습니다. 다음 **로드**부터는 정밀한 값을 사용합니다. [환율](/ko/guides/projects/data-foundation/#환율)을 참조하십시오.
- **비활성화된 멤버의 알림과 요약이 중지됩니다.** 소유자가 비활성화된 Panel 앱 알림 또는 요약이 계속 검사하고 전송되었습니다. 이제 소유자가 비활성화된 동안에는 일시 중지되고 다시 활성화되면 재개됩니다. [알림 및 요약](/ko/guides/panel-apps/alerts-and-digests/)을 참조하십시오.
- **삭제된 연결을 REST API에 요청하면 404를 반환합니다.** 삭제된 연결이나 존재하지 않는 ID를 요청하면 일반적인 서버 오류(500)로 응답했습니다. 이제 연결 ID를 지목하는 메시지와 함께 404를 반환합니다.
- **템플릿 기반 테이블 내보내기가 AI 어시스턴트와 MCP에서 작동합니다.** `table_data_export`의 `templated` 형식은 테이블을 지정하면 항상 실패했습니다. 이제 사용자가 읽을 수 있는 행으로 제한하여 템플릿을 통해 테이블을 내보냅니다. 템플릿에서 테이블의 행은 테이블 ID로 지칭되며 각 `-`는 `_`로 표기됩니다.
- **Amazon S3 및 S3 호환 문서 계정이 리전을 유지합니다.** 이러한 계정을 저장할 때 입력한 **리전**이 버려져서 다음에 계정을 열면 필드가 비어 있었습니다. 이제 리전이 저장됩니다. 이 수정 이전에 저장한 계정은 리전을 다시 입력하고 저장하십시오. [AWS S3 계정 추가](/ko/guides/documents/adding-accounts/add-aws-s3-account/)를 참조하십시오.
- **폴더의 인코딩을 변환할 때 같은 이름의 다른 파일을 더 이상 덮어쓰지 않습니다.** 대상의 같은 위치로 가는 두 파일(예를 들어 서로 다른 하위 폴더에 있는 같은 이름의 두 파일)은 마지막에 기록한 것만 남았습니다. 이제 단계는 두 번째 파일을 기록하기 전에 중지하고, 두 파일과 각 파일이 가게 될 위치를 알려 주며, **하위 폴더 유지**를 선택하면 둘을 분리할 수 있는 경우 그 사실도 알려 줍니다.
- **문서: 파일을 ASCII 인코딩으로 변환에서 문자 바꾸기를 해제하면 적용됩니다.** **대상 인코딩에서 표현할 수 없는 문자를 ?로 바꾸기**를 선택한 채 저장한 단계는 확인란을 해제하고 다시 저장해도 그대로 유지되었습니다. 이제 해제하면 바꾸기가 꺼집니다.
- **AI 어시스턴트와 JSON-RPC가 더 이상 역할이 숨기는 테이블을 사용하는 단계의 이름을 알려 주지 않습니다.** 그런 테이블이 어디에 사용되는지 물으면, 역할이 볼 수 있는 단계 중 해당 테이블을 읽거나 쓰는 각 단계를 설정과 워크플로와 함께 알려 주었습니다. 이제 프로젝트의 테이블 참조와 마찬가지로 단계 이름을 밝히지 않고 단계가 해당 테이블을 사용한다고만 알려 줍니다. [역할이 숨기는 내용](/ko/guides/ai-assistant/weave-tab/#역할이-숨기는-항목)을 참조하십시오.
- **선택한 기본 AI 연결이 기본으로 유지됩니다.** AI 연결을 워크스페이스 기본값으로 표시하면 성공한 것처럼 보였지만 실제로는 저장되지 않아서, 기본값에 의존하는 에이전트와 단계는 가장 최근에 업데이트된 연결을 계속 사용했습니다. 이제 선택한 값이 저장됩니다. [LLM 공급자](/ko/integrations/ai-architecture/llm-providers/#연결이-담고-있는-내용)를 참조하십시오.
- **Weave 기록에서 대화를 마우스 오른쪽 버튼으로 클릭해도 더 이상 스레드 삭제 위에 이름 바꾸기가 열리지 않습니다.** 이제 **이름 바꾸기**는 채팅 탭에 있으며, 지금까지 아무것도 제공하지 않던 탭을 마우스 오른쪽 버튼으로 클릭하면 됩니다. [Weave 탭의 탭](/ko/guides/ai-assistant/weave-tab/#weave-탭의-탭)을 참조하십시오.
- **빈 메모가 더 이상 저장을 막지 않습니다.** **메모** 상자를 비워 둔 채 프로젝트, 차원, 테이블, 웨어하우스, 편집기, 예약된 워크플로 이벤트 또는 배포 목록을 만들거나 저장하면 "Memo: Input should be a valid string"과 함께 실패했습니다. 이제 빈 메모가 허용됩니다.
- **하나의 값이 필요한 곳에 여러 값을 반환하는 식은 거부되며, Table Extract 또는 Table Union All 단계는 대상 테이블의 데이터를 유지합니다.** 일반적인 원인은 `table.amount,`처럼 끝에 쉼표가 있거나 `table.region == ('EU', 'US')`처럼 여러 값과 비교하는 경우입니다. Databend에서는 단계가 실패했고, Table Extract 또는 Table Union All 단계는 그 시점에 이미 대상 테이블을 비운 상태였습니다. 일부 다른 웨어하우스는 이러한 식을 실행했지만 항상 작성한 대로 실행하지는 않았으므로, 오류 없이 실행되던 단계가 이제 거부될 수 있습니다. 단계 양식은 단계를 저장할 때 해당 식을 거부하며 메시지에 무엇을 바꿔야 하는지 표시됩니다. [하나의 값이 필요한 곳의 여러 값](/ko/reference/workflow-steps/common/advanced-data-mapper-usage/#하나가-필요한-곳에-여러-값이-있는-경우)을 참조하십시오.
- **출력 열 이름이 두 번 나오는 단계는 대상을 비우기 전에 중지됩니다.** Table Lookup, Table Extract 또는 조인에서 같은 이름의 **대상 출력 열**이 두 개 있으면 단계가 대상 테이블을 비운 다음 불분명한 오류와 함께 실패했습니다. 이제 단계가 먼저 중지되며 반복된 열을 지목하는 메시지가 표시되므로 각 출력 열에 고유한 이름을 지정할 수 있습니다. 쿼리가 반환하는 순서대로 열을 기록하는 SQL 추출은 변경되지 않습니다. [Table Lookup](/ko/reference/workflow-steps/tables/table-lookup/)을 참조하십시오.
- **소스 열 없이 저장된 유니온 소스가 무엇이 빠졌는지 알려 줍니다.** REST API, JSON-RPC, 또는 AI 어시스턴트나 MCP를 통해 소스 열 목록 없이 저장한 Table Union All 또는 Table Union Distinct 소스는 단계가 실행될 때 내부 설정을 지목하는 예기치 않은 오류와 함께 실패했습니다. 이제 이를 저장하면 소스를 지목하며 거부되고, 이전에 저장된 소스를 읽는 단계는 아무것도 기록하기 전에 소스를 지목하며 중지됩니다. 테이블의 모든 열을 가져오거나 위치로 쌓는 변환된 Table Union All은 목록이 필요하지 않으며 목록이 없다는 이유로 거부되지 않습니다.
- **열의 상수가 숫자, `0` 또는 `false`일 수 있습니다.** 출력 열의 상수가 숫자인 단계는 예기치 않은 오류와 함께 실패했습니다. `0` 또는 `false` 상수는 상수가 전혀 없는 것으로 처리되어 열이 식이나 소스 열을 사용하거나, 열에 읽을 것이 없어 단계가 실패했습니다. 이제 이러한 상수는 모든 행에 기록되고 열의 데이터 형식으로 변환되며, AI 어시스턴트가 이러한 상수가 있는 단계를 제안할 수 있습니다.
- **변환된 Alteryx Data Cleansing 도구가 null 행을 제거합니다.** **Remove Null Rows**를 선택한 Data Cleansing 또는 Data Cleanse Pro 도구는 변환 보고서에서 검토 대상으로 표시되었고, 변환된 단계는 모든 행을 그대로 유지했습니다. 이제 이 단계는 Alteryx와 마찬가지로 모든 열이 null인 행을 제거합니다. 빈 텍스트 값이 들어 있는 행은 유지됩니다. Data Cleanse Pro는 다른 옵션을 처리한 뒤에 각 행을 검사하므로, null을 빈 값으로 바꾼 행도 유지됩니다. **Remove Null Columns**는 계속 검토 대상으로 표시됩니다. 이 수정을 적용하려면 워크플로를 다시 가져오십시오.
- **열을 지정하지 않은 이메일 알림은 모든 열을 포함합니다.** 열을 선택하지 않은 Notify Via Email 프레임은 실행을 실패시켰습니다. 템플릿 본문에서는 제목의 `{variable}` 자리 표시자가 예약 발송, 미리보기, **나에게 테스트 보내기**에서 채워집니다.
- **식 검증이 실행에서 허용되는 함수를 허용합니다.** `int(...)` 같은 함수를 호출하는 유효한 식을 확인할 때 거부되었습니다.

## 보안

- **Weave가 더 이상 각 대화를 시작할 때 사용자의 이름과 이메일 주소를 AI 공급자에게 보내지 않습니다.** 이 정보를 사용한 적은 없습니다.
- **비밀번호 로그인에는 인증 앱이 필요하며 비밀번호가 더 강력해졌습니다.** PlaidCloud 비밀번호로 로그인하는 멤버는 다음 로그인 때 인증 앱을 설정하도록 안내받으며, 그 이후에는 로그인할 때마다 해당 코드를 입력합니다. 싱글 사인온, Google, Microsoft 및 GitHub 로그인, API 토큰, 서비스 계정은 변경되지 않습니다. 새 비밀번호는 12자 이상이어야 하고 사용자 이름이거나 최근 사용한 비밀번호 여섯 개 중 하나일 수 없으며, 로그인 시도가 반복해서 실패하면 계정이 잠시 잠깁니다. 워크스페이스에 이미 있던 더 엄격한 규칙은 유지됩니다. [멤버 인증](/ko/administration/access/member-authentication/)을 참조하십시오.
- **연결은 공용 및 사설 네트워크 주소를 가리킵니다.** 연결은 루프백, 링크 로컬 또는 클라우드 메타데이터 주소를 가리킬 수 없으며, 오류에는 호스트와 해당 호스트가 확인된 주소가 표시됩니다. 사설 네트워크의 주소는 영향을 받지 않습니다. [연결이 도달할 수 없는 주소](/ko/guides/connections/create-connection/#연결이-접근할-수-없는-주소)를 참조하십시오.
- **저장된 연결 자격 증명은 연결이나 워크플로를 편집할 수 있는 멤버에게만 표시됩니다.** REST API와 MCP를 통해 저장된 연결의 비밀번호, 토큰, 키는 다른 멤버에게 마스킹되며, 해당 멤버는 연결을 열고 찾아볼 수는 있습니다. [연결의 자격 증명을 볼 수 있는 사용자](/ko/guides/connections/create-connection/#연결의-자격-증명을-볼-수-있는-사용자)를 참조하십시오.
- **앱 빌드는 워크스페이스의 Git 자격 증명에 접근하지 않고 실행됩니다.**
- **에이전트의 개인 키는 에이전트를 편집할 수 있는 멤버에게만 표시됩니다.** REST API와 MCP를 통한 에이전트 목록이나 세부 정보에 더 이상 키가 표시되지 않으며, 에이전트 양식은 **개인 키**와 **RPC 구성 보기**를 에이전트를 편집할 수 있는 멤버에게만 표시합니다. 서비스 계정, 프로젝트 및 에이전트 토큰, AI 위임 토큰은 키나 RPC 구성을 가져올 수 없습니다. 실행 중인 에이전트는 영향을 받지 않으며 공개 키는 계속 표시됩니다. [에이전트 자격 증명 확보](/ko/reference/cli/plaidlink/agents/#에이전트-자격-증명-가져오기)를 참조하십시오.
- **프록시 다운로드 링크는 한 시간 동안 유효합니다.** **Use PlaidCloud Proxy Download**를 켠 경우, 링크가 만료되면 다운로드를 다시 열어 새 링크를 받으십시오. [서비스](/ko/administration/control-plane/workspace-configuration/#서비스)를 참조하십시오.
- **보안 그룹에 사람을 추가하는 일은 보유한 권한을 따릅니다.** 그룹이 부여하는 모든 권한을 보유한 경우에 멤버를 보안 그룹에 추가하고, 멤버의 그룹을 선택하거나 아키텍트를 초대할 수 있습니다. 워크스페이스 관리자는 제한을 받지 않습니다. [보안 그룹 관리](/ko/administration/access/managing-security-groups-and-assignments/#보안-그룹-관리)를 참조하십시오.
- **연결의 소유자 또는 워크스페이스 관리자가 연결의 설정을 변경하고 켜거나 끕니다.** REST API, JSON-RPC, AI 어시스턴트 또는 MCP를 통해 연결의 설정을 변경하려면 소유자 중 한 명이 필요하며, 소유자가 없는 연결은 워크스페이스 관리자가 필요합니다. 연결을 사용, 사용 안 함, 잠금, 잠금 해제하려면 소유자 또는 워크스페이스 관리자가 필요하며, 여러 연결을 지정한 요청은 모두 변경할 수 있을 때만 적용됩니다. 워크스페이스의 기본 AI 연결은 워크스페이스 관리자만 선택할 수 있으며, 멤버가 소유한 연결은 관리자가 소유했거나 소유자가 없는 연결이 기본이 될 수 없는 경우에만 기본이 됩니다. [연결 편집](/ko/guides/connections/create-connection/#연결-편집)과 [LLM 공급자](/ko/integrations/ai-architecture/llm-providers/#연결이-담고-있는-내용)를 참조하십시오.
- **행 액세스는 멤버가 제한된 테이블로 수행하는 모든 작업에 적용됩니다.** 멤버는 대시보드, 자신의 SQL, 로드에서 부여받은 행만 보고 변경할 수 있습니다.
  - **프로젝트 아키텍트는 대시보드에서 행이 제한된 테이블의 모든 행을 봅니다.** Analyze에서 보는 것과 같습니다. 아키텍트 액세스를 제거하면 대시보드에 즉시 적용됩니다. 누군가의 역할을 변경하거나, 프로젝트에서 그 사람 또는 그룹을 제거하거나, 프로젝트의 액세스 유형을 변경하거나, 이전 프로젝트 버전을 복원하거나, 보안 그룹을 삭제하는 경우 모두 해당됩니다. [행 액세스 관리](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리)를 참조하십시오.
  - **행 액세스로 제한된 멤버가 자신의 SQL 쿼리를 실행하고 결과를 내보낼 수 있습니다.** 행 액세스가 있는 프로젝트에서 아키텍트가 아닌 멤버는 쿼리 화면에서 자신의 쿼리에 대해 부여받은 행만 정확히 얻고, **액세스 권한에 따라 행이 제한됨** 알림과 함께 CSV, Excel 또는 JSON으로 내보낼 수 있습니다. 이전에는 이러한 작업이 거부되었습니다. 퍼센트 기호(`%`)가 포함된 부여 값은 이제 쿼리 화면에서 해당 행을 반환하며, 이러한 쿼리를 CSV로 다운로드하는 것도 작동합니다. Snowflake 또는 Databricks에서의 자체 자유 형식 SQL, Postgres 계열 웨어하우스에서 자체 SQL의 내보내기, 스냅샷 시점의 관리되는 테이블 읽기는 여전히 거부되며, 뷰는 필터링되려면 관리되는 열을 원래 이름으로 유지해야 합니다. [행 액세스와 직접 작성하는 쿼리](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스와-직접-작성하는-쿼리)를 참조하십시오.
  - **행 액세스를 저장할 때 소스에 없는 부여 값이 유지됩니다.** 보안 그룹에 부여된 값은 테이블에 해당 값이 있는 행이 없거나, 차원에 해당 멤버가 없거나, 목록에 해당 값이 없더라도 표시된 채로 그리드에 남아 있습니다. **저장**은 이러한 값을 각각 유지할지 제거할지 묻습니다. [행 액세스 그리드](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-그리드)를 참조하십시오.
  - **행이 제한된 테이블에 대한 DataFrame 쓰기, 레코드 저장, 지우기는 볼 수 있는 행만 변경합니다.** 행 액세스가 행을 제한하면, Python 클라이언트로 제한된 테이블에 DataFrame을 쓰거나 지우거나, REST API로 레코드를 저장하거나 지울 때 사용자 본인의 행만 변경되며, 액세스 범위를 벗어난 행이 포함된 로드는 아무것도 변경되기 전에 거부되고 발견된 값이 표시됩니다. 프로젝트 아키텍트, 모든 행을 볼 수 있는 멤버, 워크플로 실행은 테이블 전체에 씁니다. 사람이 어떤 테이블에 수행하는 이러한 쓰기는 모두 **보안 로그**에 기록됩니다. [제한된 테이블에 데이터 로드](/ko/administration/access/managing-security-groups-and-assignments/#제한된-테이블에-데이터-로드)를 참조하십시오.
  - **행이 제한된 테이블의 가져오기, 복사, 복원, 삭제에는 모든 행이 사용자에게 보여야 합니다.** 행 액세스가 행을 제한하는 경우, 제한된 테이블로 파일을 가져오거나, 다른 프로젝트에서 테이블을 복사해 오거나, 브랜치를 전환하거나 병합하거나, 복원하거나, 삭제하거나, 삭제 후 되살리거나, 테이블 전체를 교체하는 그 밖의 작업은 테이블의 모든 행을 볼 수 있을 때만 실행되며, 그렇지 않으면 거부되고 아무것도 변경되지 않습니다. REST API로 테이블의 행을 저장하면 다른 로드와 마찬가지로 본인의 행만 변경됩니다. 프로젝트 아키텍트, 모든 행을 볼 수 있는 멤버, 워크플로 실행은 영향을 받지 않으며, 이러한 작업도 **보안 로그**에 기록됩니다. [제한된 테이블에 데이터 로드](/ko/administration/access/managing-security-groups-and-assignments/#제한된-테이블에-데이터-로드)를 참조하십시오.
- **계정의 소유자만 이전 버전을 복원할 수 있습니다.** 문서 계정을 이전 버전으로 복원하거나, 버전을 보류하거나 해제하거나, 백업하려면 계정의 소유자 중 한 명이 필요하며, 시스템 관리 계정에서는 이 중 어느 것도 사용할 수 없습니다. 계정의 버전 기록을 보려면 계정에 대한 액세스 권한이 필요합니다.
- **`query_run`은 읽기 전용 문만 실행합니다.** AI 어시스턴트와 MCP 클라이언트가 사용하는 `query_run` 도구는 SELECT 또는 WITH 문 하나, 그에 대한 EXPLAIN, 또는 SHOW를 받으며, 그 밖의 문은 실행되지 않습니다. 데이터를 변경하려면 `query_transform`을 사용하십시오. MCP 테이블 내보내기의 SQL도 같은 규칙을 따릅니다. REST 및 JSON-RPC API에서는 프로젝트 데이터를 변경할 수 없는 멤버에 대해 쿼리 실행, 열 패싯 만들기, 쿼리를 CSV로 다운로드, 쿼리를 원격 데이터베이스로 내보내기, 자체 쿼리로 테이블 데이터 내보내기에도 이 규칙이 적용되며, 거부된 쿼리는 403을 반환합니다. Explain Analyze는 측정하기 위해 쿼리를 실행하므로 쿼리 로그와 Lakehouse에서는 읽기만 하는 쿼리만 허용하며, 행 액세스가 있는 프로젝트에서는 프로젝트 아키텍트만 쿼리 로그에서 실행할 수 있습니다.
- **테이블 탐색기 필터, PlaidCloud로 보내는 쿼리, Table Extract 단계의 동적 열을 찾는 쿼리는 SQL을 실행하거나 서버의 파일을 읽는 함수를 호출할 수 없습니다.** `query_to_xml`, `dblink`, `pg_read_file` 같은 함수를 호출하면 거부되며 오류에 함수 이름이 표시됩니다. 같은 위치에서 `.op()`는 연산자만 받고 `literal_column`은 유니코드 이스케이프 따옴표를 사용할 수 없습니다. 동적 열 쿼리는 단계의 필터와 소스에서 열 이름을 읽는 식을 포함하므로, 규칙을 위반하는 쿼리는 단계가 실행될 때 단계를 실패시킵니다. [거부되는 함수와 연산자](/ko/reference/workflow-steps/common/advanced-data-mapper-usage/#거부되는-함수와-연산자)를 참조하십시오.
- **Data Foundation 배부 규칙은 작은따옴표, 백슬래시 또는 줄 바꿈이 포함된 부서 또는 통계 이름을 거부합니다.** 이름이 배부 단계의 필터에 기록되므로 **저장**과 1단계 미리 보기는 이를 거부하고 해당 값을 지목합니다. [배부 규칙](/ko/guides/projects/data-foundation/#배부-규칙)을 참조하십시오.
