## 설명

PlaidCloud의 공유 ERP 쓰기 파이프라인을 통해 [Acumatica 연결](/ko/guides/connections/acumatica/)로 Acumatica에 문서를 전기합니다. 이 단계는 헤더 테이블(문서당 한 행)과 라인 테이블(문서당 하나 이상의 행)을 입력으로 받아 각 문서를 **JournalTransaction**, **SalesInvoice**, **Bill** 또는 **Payment**로 전기합니다. **Validate Only**는 원장 클레임과 전기 없이 모든 문서를 만들고 검사하며, 선택 사항인 결과 테이블에는 각 문서의 결과가 기록됩니다.

<Aside type="caution">
이 단계로 라이브 문서를 무인 전기하기 전에, 모든 배치를 먼저 **Validate Only**로 실행하여 결과 테이블을 검토하고 Acumatica에서 직접 몇 건의 전기 내역을 대사하십시오.
</Aside>

## 구성

### 연결

- **Acumatica 연결** — 전기에 사용할 Acumatica 연결입니다.
- **환경** — 연결의 환경입니다.

### 데이터

- **헤더 테이블** — 문서당 한 행: `ref`(문서 식별자, 필수), `doc_type`(`JournalTransaction`/`SalesInvoice`/`Bill`/`Payment`, 필수), `posting_date`, `party_id`(문서 유형에 필요한 경우 고객/공급업체), `memo`, `due_date`, `branch_id`. 한 배치에 여러 문서 유형을 섞을 수 있으며, PlaidCloud가 전기 전에 `doc_type`별로 나눕니다.
- **라인 테이블** — `ref`당 하나 이상의 행이며 문서 유형에 맞는 형태입니다.

  | 문서 유형 | 라인 열 |
  |---|---|
  | JournalTransaction | `account`, `subaccount`, `branch`, `debit`, `credit` |
  | SalesInvoice | `item`, `qty`, `unit_price`, `amount` |
  | Bill | `account`, `amount` |
  | Payment | `linked_txn_id`, `amount` |

- **결과 테이블** — 출력 테이블 ID: 문서당 한 행이며 `ref`, `doc_type`, `natural_key`, `confirmation_id`, `status`(`posted`/`validated`/`error`), `message`를 포함합니다.
- **Validate Only** — 기본적으로 선택되어 있습니다. 사전 검사만 수행하며 원장 클레임도 전기도 하지 않습니다. 이 필드가 아예 없는 단계 구성(예: REST API, MCP 또는 워크플로 번들 가져오기로 작성한 구성)도 라이브 전기가 아니라 Validate Only가 기본값입니다.
- **Continue On Error** — 기본적으로 선택되어 있습니다. 한 문서가 실패한 후에도 나머지 문서를 계속 전기합니다. 선택 해제하면 첫 번째 실패에서 배치를 중지합니다.

## 전기 방식

Acumatica는 모든 문서를 **보류 상태**로 만든 다음, PlaidCloud가 릴리스 작업을 호출합니다. 이 작업은 비동기로 실행되며, `202` 수락 응답을 받고 완료될 때까지 폴링한 뒤 `204`로 릴리스를 확인합니다. PlaidCloud는 **문서의 Hold 플래그를 다시 읽어 false로 확인된** 후에만 `posted`로 보고합니다. 문서가 생성되었지만 릴리스가 확인되지 않은 경우에는 단순히 문서가 존재한다는 이유로 성공으로 기록하지 않고, 격리 상태로 유지됩니다(전기된 것으로 보고되지도, 조용히 누락되지도 않음).

## 기능 제한

| 제한 사항 | 의미 |
|---|---|
| 기본 제공 멱등성 키 없음 | Acumatica의 PUT 기반 쓰기 API에는 멱등성 필드가 없습니다. 재시도나 재실행 시 이중 전기를 막는 유일한 보호 장치는 Acumatica 측 키가 아니라 PlaidCloud 자체의 원장 클레임입니다. |
| 역분개는 수동 | 계약 기반 API에는 문서화된 무효화/역분개 작업이 있는 문서 유형이 없습니다. `reversal_mode`는 모든 곳에서 `NONE`이며, 거부될 뿐 가장하지 않습니다. 잘못 전기된 문서는 Acumatica에서 직접 수정하십시오. |
| 결제는 신뢰할 만한 조회 수단 없음 | 모호한 결과가 나온 뒤 결제를 PlaidCloud의 요청과 연결해 주는 문서화된 필드가 없습니다. 불확실한 결제는 추측하지 않고 수동 해결을 위해 격리됩니다. |
| 라인 항목 필터링은 서버 측에서 지원되지 않음 | (가져오기 단계의) 서버 측 필터는 문서의 라인 항목 차원에 적용되지 않습니다. 헤더/엔터티 수준에서 필터링하고 워크플로에서 라인 범위를 지정하십시오. |
