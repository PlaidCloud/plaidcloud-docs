## 설명

PlaidCloud Document에 저장된 [Delta Lake](https://delta.io/) 테이블을 프로젝트 테이블로 가져옵니다. 단계가 테이블의 폴더, 즉 `_delta_log` 폴더와 데이터 파일이 들어 있는 폴더를 가리키도록 지정하십시오. 테이블은 최신 버전으로 읽습니다.

단계 양식의 탭은 [Parquet 가져오기](/ko/reference/workflow-steps/import/import-parquet/)와 같습니다. **가져오기 매개변수**에서는 테이블의 폴더인 **소스 파일**과 **대상 테이블**을 선택하고, **테이블 데이터 선택**에서는 열을 매핑하며, **데이터 필터**에서는 행을 필터링합니다. **채우기**는 테이블의 `_delta_log`에서 열과 해당 유형을 읽으며, 파티션 열은 텍스트로 마지막에 놓입니다. 폴더가 없거나 비어 있으면 **채우기**는 경로를 명시한 경고와 함께 *채울 항목이 없습니다*라고 응답하고 기존 매핑을 유지합니다.

[마이그레이션된 KNIME 워크플로](/ko/guides/workflows/migrate-knime-workflows/)는 Delta Table Reader 노드에 이 단계를 사용합니다.

## 구성

* `input_file` — Delta 테이블 폴더의 문서 계정과 경로입니다. 검색하면 여러 테이블을 찾을 수 있습니다. `schema_mismatch`를 `union`(기본값)으로 설정하면 각 테이블을 열 이름으로 로드하고, 테이블에 없는 열은 NULL이 되며, 매핑에 선언되지 않은 열은 제외됩니다. `error`로 설정하면 테이블과 열을 명시하며 단계가 중지됩니다. `schema_mismatch`는 AI 어시스턴트 또는 REST API로 설정합니다.
* `target_frame` — 행을 기록할 테이블입니다.
* `source_columns` 및 `target_columns` — 열 매핑입니다.
* `source_where`, `having`, `aggregate`, `aggregation_type`, `distinct` — 다른 가져오기 단계와 마찬가지로 행을 필터링하고 요약합니다.
* `use_target_slicer`, `limit_target_start`, `limit_target_end` — 결과의 일부만 유지합니다.
* `delete_file` — 가져오기 후 가져온 파일을 삭제합니다.
* `ascii_only` — ASCII가 아닌 문자를 제거합니다.
* `skip_if_unchanged` — 기본적으로 켜져 있습니다. 소스 파일과 단계 설정이 마지막으로 성공한 실행 이후 변경되지 않았으면 워크플로 실행이 가져오기를 건너뜁니다.
