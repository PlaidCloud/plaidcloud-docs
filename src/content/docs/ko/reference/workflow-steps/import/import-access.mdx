## 설명

문서 계정에서 Microsoft Access 데이터베이스 파일을 읽고, 해당 파일의 테이블을 Access 테이블마다 프로젝트 테이블 하나씩 가져옵니다. 테이블 이름에는 사용자가 정한 접두사가 붙습니다.

Access 파일에는 여러 테이블이 들어 있으므로, 이 단계는 개별 테이블의 열을 매핑하지 않고 파일 전체를 가져옵니다.

## 고유 구성 항목

### 소스

문서 계정에 있는 Access 데이터베이스 파일입니다. 파일 선택기는 정확한 경로 대신 검색 일치도 지원하며, 재귀 옵션과 일치한 파일 간 스키마 차이를 조정하는 규칙도 제공합니다.

### 대상

**테이블 접두사** — 가져온 각 테이블 이름 앞에 붙습니다. 이렇게 하면 한 파일의 테이블이 함께 묶이고 다른 가져오기의 테이블과 충돌하지 않습니다.

### 변경 없으면 건너뛰기

기본적으로 켜져 있습니다. 소스 파일이 지난 실행 이후 변경되지 않았고 대상 테이블에 가져온 행이 그대로 남아 있으면, 워크플로 실행은 다운로드를 포함한 가져오기 전체를 건너뜁니다. 비워진 테이블은 다시 가져옵니다.

## 파일을 읽을 수 없는 경우

이 단계는 완료한 뒤 빈 테이블을 남겨 두는 대신, 읽을 수 없었던 파일과 테이블을 명시하며 실패합니다. 파일에 PlaidCloud가 읽을 수 있는 테이블이 없는 경우, 테이블 이름은 있지만 해당 열을 설명할 수 없는 경우, 또는 테이블의 행을 읽는 데 실패한 경우에 발생합니다. 리더가 이해하지 못하는 최신 버전의 Access에서 작성한 파일이 가장 흔한 원인입니다. Access에서 파일을 변환하거나 다시 내보낸 후 가져오기를 다시 실행하십시오.

모든 테이블이 실제로 비어 있는 파일은 정상적으로 가져오며, 로드된 레코드가 없다는 경고를 보고합니다.
