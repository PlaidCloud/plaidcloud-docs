## 설명

PlaidCloud Document에서 JSON 텍스트 파일을 가져옵니다.

JSON 파일에 대한 자세한 내용은 JSON 공식 웹 사이트(http://json.org/)를 참조하십시오.

JSON 파일은 열 순서를 유지하지 *않습니다*. 소스 파일의 열 순서가 가져온 데이터 테이블의 열 순서를 그대로 반영하지는 않습니다.

JSON 가져오기는 문서 전체를 메모리에 로드하지 않고 임시 저장소를 통해 스트리밍하므로, 매우 큰 파일도 메모리 부족 없이 가져올 수 있습니다. 큰 문서의 뒷부분에서 처음 나타나는 열도 가져온 테이블에 포함됩니다. 중첩된 객체와 배열은 표준 압축 JSON 텍스트로 가져오므로, 이후 단계에서 어떤 JSON 도구로든 구문 분석할 수 있습니다.

## 고유 구성 항목

### JSON 데이터 방향

다음 데이터 세트를 가정합니다.

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

JSON 파일은 다음 세 가지 데이터 형식 중 하나로 가져올 수 있습니다.

* Records: 데이터를 Python 사전 집합으로 저장하며, 각 행은 \{Column -> Value, …} 형식으로 저장됩니다. 예를 들면 다음과 같습니다.


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index: 데이터를 중첩된 Python 사전 집합으로 저장하며, 각 행은 \{Index -> \{Column -> Value, …},…} 형식으로 저장됩니다. 예를 들면 다음과 같습니다.


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split: 데이터를 하나의 Python 사전 집합에 저장하며, 값은 목록에 저장됩니다. 예를 들면 다음과 같습니다.


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

위 형식 외에 줄 바꿈으로 구분된 JSON(NDJSON)도 허용됩니다. 줄마다 독립된 JSON 객체 하나가 있으며 이를 감싸는 배열은 없습니다. 예를 들면 다음과 같습니다.

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### 전체 문서

각 파일의 JSON을 그대로 유지하려면 **추가 JSON 옵션**에서 **각 파일을 전체 JSON 문서가 담긴 한 행으로 가져오기**(`whole_document`)를 선택합니다. 그러면 각 파일이 전체 JSON 문서가 담긴 한 행으로 가져와지며, 숫자는 작성된 그대로 유지됩니다.

### 날짜 및 타임스탬프

필드의 모든 값이 아래 레이아웃 중 같은 하나를 따를 때 해당 필드는 날짜 또는 타임스탬프로 가져옵니다.

| 레이아웃 | 날짜 | 타임스탬프 |
| --- | --- | --- |
| ISO 8601 | `2026-01-23` | `2026-01-23T23:14:00` |
| 월 우선 | `01-23-2026` 또는 `01-23-26` | `01-23-2026 11:14:00 PM`, 12시간제 시간 |
| 일 우선 | `23-01-2026` 또는 `23-01-26` | `23-01-2026 23:14:00`, 24시간제 시간 |
| 두 자리 연도 우선 | `99-01-23` | `99-01-23 23:14:00`, 24시간제 시간 |

필드의 모든 값은 행의 순서와 관계없이 같은 방식으로 읽습니다. `01/23/2026` 또는 `01-23-2026 23:14:00`처럼 그 밖의 레이아웃인 필드는 텍스트로 가져옵니다. 값에 여러 레이아웃이 섞인 필드도 마찬가지이지만, `01-23-2026`과 `01-24-26`처럼 두 자리 연도와 네 자리 연도가 섞인 일부 경우에는 가져오기가 중지되고 해당 필드를 지목하는 오류가 표시됩니다.

#### 값이 둘 이상의 레이아웃에 맞는 경우

`01-03-2026`은 1월 3일일 수도 3월 1일일 수도 있으며, `23-01-26`은 2026년 1월 23일일 수도, 연도를 먼저 읽으면 2023년 1월 26일일 수도 있습니다. 필드의 모든 값이 위 레이아웃 중 둘 이상에 맞는 경우, 단계의 **날짜 형식**이 일, 월, 연도의 순서로 결정합니다.

* 월 일로 시작하는 선택 항목은 월을 먼저 읽습니다. `01-03-2026`은 1월 3일입니다.
* 일 월 또는 약어로 시작하는 선택 항목은 일을 먼저 읽습니다. `01-03-2026`은 3월 1일이고, `23-01-26`은 2026년 1월 23일입니다.
* 그 밖의 날짜 형식에서는 가져오기가 중지되고, 해당 필드와 문제를 해결할 수 있는 선택 항목을 알려 주는 오류가 표시됩니다.

이 선택 항목은 모든 값의 일과 월이 12 이하일 때 다른 시계 방식의 타임스탬프도 읽습니다. 월 일 선택 항목은 `01-03-2026 23:14:00`을 1월 3일로 읽고, 일 월 또는 약어 선택 항목은 `01-03-2026 11:14:00 PM`을 3월 1일로 읽습니다. 그 밖의 날짜 형식은 표와 같이 읽습니다. 일 우선은 24시간제 시간으로, 월 우선은 12시간제 시간으로 읽습니다.

어떤 날짜 형식 선택 항목도 두 자리 연도 우선을 읽지 않으므로, `26-01-23` 같은 필드는 `99-01-23`처럼 값을 다른 방식으로 읽을 수 없을 때만 연도 우선으로 가져옵니다. `2026-01-23`처럼 네 자리 연도로 작성한 날짜는 ISO 8601로 가져옵니다.

중첩된 객체나 배열 안에 타임스탬프도 들어 있는 파일은 예외입니다. 위의 검사가 하나도 적용되지 않으며, 둘 이상의 레이아웃에 맞는 값이 행마다 다르게 읽힐 수 있습니다.
