## 설명

PlaidCloud Document에서 JSON 텍스트 파일을 가져옵니다.

JSON 파일에 대한 자세한 내용은 JSON 공식 웹 사이트(http://json.org/)를 참조하십시오.

JSON 파일은 열 순서를 유지하지 *않습니다*. 소스 파일의 열 순서가 가져온 데이터 테이블의 열 순서를 그대로 반영하지는 않습니다.

JSON 가져오기는 문서 전체를 메모리에 로드하지 않고 임시 저장소를 통해 스트리밍하므로, 매우 큰 파일도 메모리 부족 없이 가져올 수 있습니다. 큰 문서의 뒷부분에서 처음 나타나는 열도 가져온 테이블에 포함됩니다. 중첩된 객체와 배열은 표준 압축 JSON 텍스트로 가져오므로, 이후 단계에서 어떤 JSON 도구로든 구문 분석할 수 있습니다.

## 고유 구성 항목

### JSON 데이터 방향

다음 데이터 세트를 가정합니다.

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

JSON 파일은 다음 세 가지 데이터 형식 중 하나로 가져올 수 있습니다.

* Records: 데이터를 Python 사전 집합으로 저장하며, 각 행은 \{Column -> Value, …} 형식으로 저장됩니다. 예를 들면 다음과 같습니다.


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index: 데이터를 중첩된 Python 사전 집합으로 저장하며, 각 행은 \{Index -> \{Column -> Value, …},…} 형식으로 저장됩니다. 예를 들면 다음과 같습니다.


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split: 데이터를 하나의 Python 사전 집합에 저장하며, 값은 목록에 저장됩니다. 예를 들면 다음과 같습니다.


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

위 형식 외에 줄 바꿈으로 구분된 JSON(NDJSON)도 허용됩니다. 줄마다 독립된 JSON 객체 하나가 있으며 이를 감싸는 배열은 없습니다. 예를 들면 다음과 같습니다.

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### 전체 문서

각 파일의 JSON을 그대로 유지하려면 **추가 JSON 옵션**에서 **각 파일을 전체 JSON 문서가 담긴 한 행으로 가져오기**(`whole_document`)를 선택합니다. 그러면 각 파일이 전체 JSON 문서가 담긴 한 행으로 가져와지며, 숫자는 작성된 그대로 유지됩니다.
