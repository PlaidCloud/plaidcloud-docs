## 설명


다른 프로젝트의 테이블 데이터를 현재 프로젝트로 복사합니다. [Export Project Table 단계](/ko/reference/workflow-steps/export/export-project-table/)의 반대로, 푸시하는 대신 가져옵니다.

통합 프로젝트가 여러 운영 프로젝트에서 데이터를 가져오는 경우, 또는 참조 데이터를 한 프로젝트에 중앙 집중화하고 다른 프로젝트에서 읽는 경우에 유용합니다. 소스 프로젝트는 이 프로젝트에 **읽기** 데이터 공유를 허용해야 합니다.


## 데이터 공유 관리

![데이터 공유 관리](/images/import_external_project_table_1.png)

다른 프로젝트의 테이블을 가져오려면 먼저 해당 프로젝트가 이 프로젝트의 읽기를 허용해야 합니다. **소스** 프로젝트의 **홈** 탭을 열고 **데이터 공유 관리**에서 **새 데이터 공유**를 클릭한 다음, 이 프로젝트를 선택하고 **허용된 작업**에서 **읽기**를 선택한 후 **데이터 공유 추가**를 클릭합니다. [프로젝트 간 데이터 공유](/ko/guides/projects/managing-projects/#프로젝트-간-데이터-공유)를 참조하십시오.

이 단계는 이 프로젝트 자체의 ID로 실행되므로, 누가 시작하든 실행은 공유를 통해 동작합니다.

## 외부 프로젝트 테이블 가져오기

![소스 및 대상 가져오기](/images/import_external_project_table_2.png)

### 읽기 원본
드롭다운에서 **소스 프로젝트**와 **소스 테이블**을 선택합니다.

### 쓰기 대상

<SnippetCommonImportTargetSelection />

<Aside type="note" title="빈 소스 테이블">
단계가 실행될 때 소스 테이블에 행이 없으면, 가져오기는 조용히 성공하는 대신 소스가 비어 있었다는 경고와 함께 완료되므로 예상치 못하게 비어 있는 대상을 쉽게 알아볼 수 있습니다. 대개 소스 프로젝트의 워크플로가 아직 해당 테이블을 빌드하지 않았다는 의미입니다. 가져오기 전에 소스에 데이터가 채워져 있는지(일정에 따른 실행의 경우 먼저 실행되도록 순서가 지정되어 있는지) 확인하십시오.
</Aside>

<Aside type="note" title="소스 테이블 삭제">
읽어 오는 소스 테이블은 이 단계에서 사용 중인 것으로 취급됩니다. 이 테이블을 삭제하려고 하면 일반 삭제 대신 PlaidCloud가 참조를 표시하며, **테이블을 강제로 삭제하시겠습니까?**를 선택하고 **강제 삭제**를 선택하여 강제 삭제를 확인하도록 요구합니다. 가져오기 단계가 데이터를 공유하는 다른 프로젝트에 있는 경우에도 마찬가지입니다. 이처럼 프로젝트 간에 걸친 경우에는 다른 프로젝트의 단계에 접근할 수 없을 수 있으므로, 경고는 해당 단계의 이름을 밝히지 않고 참조만 나열합니다.
</Aside>
