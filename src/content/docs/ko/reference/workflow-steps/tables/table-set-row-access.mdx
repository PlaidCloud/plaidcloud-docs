## 설명

행 액세스 설정 단계는 소스 테이블에서 관리 대상 열의 행 액세스 권한을 다시 계산하여 적용합니다.
각 행이 보안 그룹과 해당 그룹이 볼 수 있는 값을 짝지어 담고 있는 테이블을 열에 지정하면, 이 단계가 그 행을 읽고 그 결과로
권한을 기록합니다. 따라서 소스 데이터가 바뀌어도 행 액세스가 항상 최신 상태로 유지되며, 누구도 그리드를 직접 편집할 필요가 없습니다.

열은 이미 행을 제한하고 있어야 하므로, 먼저 행 액세스 그리드에서 설정하십시오. 이 단계를 처음 실행하면 열이 소스 테이블에 바인딩됩니다.
열에 직접 설정한 권한은 지워지고 테이블의 행으로 대체됩니다. 그 이후 행 액세스 그리드에서 해당 열은 소스 배지와 함께 잠긴 상태로 표시되며,
누군가 **바인딩 제거**를 클릭하기 전에는 그리드에서 직접 편집할 수 없습니다. 행 액세스 가이드의
[Binding Grants to a Source Table](/ko/administration/access/managing-security-groups-and-assignments/#소스-테이블에-부여-바인딩)을 참조하십시오.

<Aside type="note" title="변경되는 데이터와 권한을 동기화하려면 이 단계를 사용하십시오">
일반적인 사용 방법은 소스 테이블을 로드하거나 새로 고치는 워크플로 다음에 이 단계를 예약하는 것입니다. 이렇게 하면 새 그룹, 제거된 값, 재할당된 영역이
다음 실행 때 행 액세스에 자동으로 반영되므로, 누군가 그리드를 직접 업데이트해야 한다는 점을 기억할 필요가 없습니다.
</Aside>

## 매개변수

- **프로젝트** — 이 단계가 업데이트할 관리 대상 열이 있는 프로젝트입니다.
- **열** — 관리 대상 열이며, 프로젝트의 실제 열 중에서 선택합니다.
- **소스 테이블** — (그룹, 값) 행을 제공하는 테이블입니다. 열이 바인딩된 테이블과 다른 테이블을 지정하면 열이 새 테이블에 다시 바인딩됩니다.
- **그룹 열** — 보안 그룹을 지정하는 소스 테이블의 열입니다.
- **값 열** — 해당 그룹이 볼 수 있는 값을 지정하는 소스 테이블의 열입니다.

## 동작

실행할 때마다 소스 테이블에 현재 있는 모든 (그룹, 값) 행을 읽고 열의 권한을 정확히 그 집합으로 바꿉니다. 소스 테이블에 더 이상 없는 그룹은
이 단계가 이전에 부여한 모든 권한을 잃습니다. 존재하지 않는 보안 그룹을 지정한 행은 단계를 실패시키지 않고 건너뜁니다. 업데이트는 수동으로 저장했을 때와
마찬가지로 PlaidCloud 자체 쿼리와 Superset 대시보드 모두에 반영되며, 보통 1분 이내에 적용됩니다.

소스 테이블이 누가 무엇을 볼 수 있는지를 결정하므로, 테이블이 바인딩된 이후에는 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트 자체 워크플로만 테이블의 행을 변경하거나 테이블을 삭제할 수 있습니다.

<Aside type="caution">
이 단계는 관리하는 권한 집합 *전체*를 바꿉니다. 열의 일부 권한은 직접 관리하고 나머지는 소스 테이블에서 관리한다면, 둘을 서로 다른 열로 분리하십시오.
소스에 바인딩된 열에서 직접 편집한 권한은 실행 사이에 유지되지 않습니다.
</Aside>
