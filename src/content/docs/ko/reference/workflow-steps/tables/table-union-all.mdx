## 설명


열 구조가 같은 여러 데이터 테이블을 하나의 데이터 테이블로 결합하는 데 사용합니다. 예를 들어 시계열 데이터가 이 변환의 대표적인 대상입니다. 결과에는 결합된 테이블의 모든 레코드가 포함됩니다.

<Aside>**Union All**은 중복을 제거하지 않습니다. 중복 레코드를 제거하려면 대신 **Union Distinct**를 사용하십시오.</Aside>

## 소스


**소스** 섹션은 함께 추가할 모든 데이터 테이블의 모음입니다. 일반적으로 모든 데이터 테이블의 열 구조는 같거나 비슷합니다. 목록에 데이터 테이블을 추가하는 버튼은 두 가지입니다.


* **행 삽입**
* **행 추가**

또한 **편집할 소스 선택** 창에서 마우스 오른쪽 버튼으로 클릭하면 같은 옵션이 표시됩니다. 이미 추가한 테이블에서 마우스 오른쪽 버튼으로 클릭하면 **삭제** 옵션도 표시됩니다.


변환이 올바르게 실행되려면 **소스** 섹션에 함께 추가할 소스 데이터 테이블마다 항목이 하나씩 있어야 합니다. 이 항목은 추가될 순서대로 나열됩니다. 순서를 조정하려면 테이블을 마우스 오른쪽 버튼으로 클릭하여 다음 옵션을 표시합니다.


* **아래로 이동**(해당하는 경우)
* **맨 아래로 이동**(해당하는 경우)
* **위로 이동**(해당하는 경우)
* **맨 위로 이동**(해당하는 경우)

기본적으로 각 소스의 이름은 *New Frame*이지만, 이름을 더블 클릭하여 이름을 바꿔 설명이 되는 이름을 지정하도록 모델러에게 권장합니다.


<Aside>표시된 텍스트는 소스 데이터 테이블의 이름과 **관련이 없다**는 점을 기억하는 것이 중요합니다. 모델러가 설명이 되는 이름을 지정하기를 권장하며, 흔히 소스 데이터 테이블과 같은 이름을 사용하지만 이름 사이에는 어떠한 연결도 없다는 점을 유의하십시오.</Aside>


## 대상 테이블


기본적으로 **대상 테이블**은 비어 있습니다. 이름을 지정하기 전에 데이터 테이블은 Linux 명명 규칙을 따라야 한다는 점에 유의하십시오. 따라서 이름은 영숫자 문자로만 구성하기를 권장합니다. Analyze는 이름에서 잘못된 문자를 자동으로 제거합니다. 또한 길이를 256자로 제한하므로 간결하게 지정하십시오!

## 열 일치

**대상 테이블** 아래의 **열 일치 기준**은 소스가 정렬되는 방식을 선택합니다.

* **이름**(기본값) — 각 소스의 열이 첫 번째 소스의 열과 이름으로 일치됩니다.
* **위치** — 소스가 순서대로 쌓이며, Spark의 `union`과 같습니다. 결과는 첫 번째 소스의 열 이름을 사용하며, 모든 소스의 열 수가 같아야 합니다. 각 소스의 열 매핑은 사용되지 않으므로 해당 **열** 탭은 비활성화됩니다.

**위치**를 사용하면 각 열은 모든 소스에 맞는 유형을 갖습니다. 두 숫자 유형은 더 넓은 유형이 되고, 날짜와 타임스탬프는 타임스탬프가 되며, 그 외의 조합은 텍스트가 됩니다. 다른 유형과 섞인 부울 또는 바이너리 열은 공통 유형이 없어 단계가 실패하며, 열 수가 서로 다른 소스도 마찬가지입니다.

모든 소스 테이블이 없으면 두 모드 모두에서 단계가 실패하는 대신 경고와 함께 완료됩니다.

## 저장할 때 검사하는 항목

모든 소스는 첫 번째 소스와 같은 열을 생성해야 합니다. 열 이름이 같아야 하고, 양쪽이 유형을 선언한 경우 유형도 같아야 합니다. 대상 테이블은 첫 번째 소스의 열로 구성됩니다. 열이 이름으로 일치되므로 소스는 열을 다른 순서로 나열할 수 있습니다. 소스가 서로 다른 단계를 저장하면 각 차이를 명시하며 거부됩니다. *소스 'east'는 'west'와 같은 열을 생성해야 합니다. 누락: region, 'west'에 없음: area.*

저장할 때는 소스 테이블은 있지만 소스 열이나 대상 열이 없는 각 소스의 매핑도 **두 매핑 테이블 모두 채우기**를 사용했을 때와 같이 해당 테이블에서 채웁니다.
