## 설명

JSON 텍스트가 들어 있는 열을 읽어 문서에서 발견한 값마다 하나씩 출력 행으로 확장합니다. [Table XML Parse](/ko/reference/workflow-steps/tables/table-xml-parse/) 단계의 짝이 되는 단계이며, Alteryx *JSON Parse* 도구에 해당하는 PlaidCloud 기능입니다.

업스트림 시스템이 JSON 페이로드를 열 하나에 담아 전달하는데 그 내용을 일반 행과 열로 사용해야 할 때 사용합니다.

## 고유 구성 항목

### JSON 필드

구문 분석할 JSON 텍스트가 들어 있는 열입니다.

### 출력 형태

- **Name and value only**(기본값) — 각 출력 행에 `JSON_Name`과 `JSON_ValueString`이 들어갑니다. 가장 단순하며, 다운스트림에서 모든 값을 텍스트로 취급할 때 충분합니다.
- **Typed values** — 단일 필드 옵션을 끄면 유형별 값 열이 함께 추가되어 숫자와 불리언이 문자열이 아닌 숫자와 불리언으로 전달됩니다.

### 입력 열 전달

기본적으로 꺼져 있습니다. 켜면 입력 레코드의 다른 열이 모든 값 행에 반복되므로, 별도의 조인 단계 없이도 구문 분석된 값이 원래 레코드와 계속 연결됩니다.

### 기타 레이아웃

**출력**(`json_layout`)은 다른 출력 형태를 선택합니다. 다음 레이아웃은 모두 입력 행마다 행 하나를 유지합니다.

- **와이드: 키 경로마다 열 하나**(`wide`) — 입력 열(JSON 필드를 포함하도록 설정하지 않았다면 JSON 필드 제외)에 점으로 구분된 키 경로마다 텍스트 열 하나를 더한 형태이며, 문서에 해당 경로가 없으면 NULL입니다.
- **JSONPath 쿼리마다 열 하나**(`paths`) — 입력 열에 JSONPath 쿼리마다 열 하나를 더한 형태입니다. **JSONPath 쿼리**(`json_paths`)에 쿼리를 나열하며, 각 쿼리에는 **열**, **JSONPath**, **유형**, **여러 일치** 설정(`target`, `path`, `dtype`, `multi`)이 있습니다. `path`는 JSONPath(이름, 인덱스, 와일드카드, 깊은 검색, 슬라이스, 유니온, 필터)이고, `dtype`은 `text`, `integer`, `bigint`, `double`, `boolean`, `json` 중 하나이며, `multi`는 비워 두면 첫 번째 일치 항목(없으면 NULL), `list`이면 모든 일치 항목을 목록 값으로, `paths`이면 일치하는 경로를 반환합니다. 목록 대신 **테이블의 쿼리**(`json_dictionary`)를 사용하면 테이블의 행에서 쿼리를 읽습니다. `{source, path, type, output}`은 테이블과, 각 경로·유형·출력 열 이름이 들어 있는 해당 테이블의 열을 지정합니다.
- **KNIME JSON to Table이 만드는 열**(`table`) — 입력 열에 KNIME의 JSON to Table 노드가 문서로부터 만드는 열을 더한 형태입니다. **JSON을 테이블로** 옵션(`json_table`)으로 설정하며, 먼저 **JSON 경로로 열 이름 지정**(`paths`)이 있고, 경로 세그먼트를 연결하는 **경로 구분 기호**(`separator`, 기본값 `.`), `GenerateCollectionCells`, `GenerateColumns`, `KeepAllArrayAsJsonArray` 중에서 고르는 **배열**(`arrays`), **확장할 수준**(`levels`, 0은 모두), 개체 값을 제외하는 **확장된 개체 제외**(`omit_objects`, 기본값 true)가 있습니다.

JSONPath 또는 JSON to Table 레이아웃에서는 **출력에서 JSON 필드 제외**(`json_remove_source`)를 켜면 결과에서 JSON 필드를 제거합니다.
