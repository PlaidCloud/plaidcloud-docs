## 설명

**테이블: KNIME 규칙 엔진** 단계는 단계가 실행될 때 읽는 테이블에 보관된 KNIME Rule Engine 규칙 목록을 적용합니다. 행과 처음으로 일치하는 규칙이 그 행의 결과를 결정합니다. [마이그레이션된 KNIME 워크플로](/ko/guides/workflows/migrate-knime-workflows/)는 규칙이 워크플로를 실행할 때에야 알 수 있는 테이블에서 올 때 Rule Engine (Dictionary), Rule Engine Variable (Dictionary), Rule-based Row Filter (Dictionary), Rule-based Row Splitter (Dictionary) 노드(PMML 규칙 집합 포함)에 이 단계를 사용합니다.

이 단계는 읽은 규칙을 변환기와 같은 방식으로 변환합니다. Java 전용 구문이나 플로 변수를 사용하는 규칙처럼 처리할 수 없는 규칙이 있으면 잘못된 열을 기록하는 대신 단계가 실패합니다.

단계 양식에는 **규칙의 용도**로 규칙 종류를 고르고 소스, 출력, 규칙 테이블을 선택하는 **테이블** 섹션, **출력** 섹션, PMML 규칙 집합을 위한 **규칙 집합 채점** 섹션, **열** 섹션이 있습니다.

## 구성

- `source` 및 `target_frame` — 읽을 테이블과 기록할 테이블입니다. `source_columns`와 `target_columns`는 읽고 쓰는 열이며, `output_column`으로 지정한 대상 열에 규칙의 결과가 들어갑니다.
- `rules_source` — 행이 곧 규칙인 테이블입니다. `rules_column`은 각 규칙을, `outcome_column`은 그 결과를 담고 있으며, `rules_order_column`을 지정하면 규칙의 순서가 정해집니다.
- `rule_kind` — `engine`(기본값)은 규칙의 결과를 `output_column`에 `output_dtype` 유형으로 기록합니다. `filter`와 `splitter`는 규칙이 유지하는 행을 기록합니다. `include`(기본값 true)는 규칙 결과가 TRUE일 때 행을 유지할지 버릴지를 정하며, `port`는 유지된 행이면 `1`, 나머지이면 `2`입니다. `variable`은 소스 테이블 없이 규칙이 계산한 값의 한 행짜리 테이블을 기록합니다.
- `outcome_cell` — 결과 열의 KNIME 셀 유형으로, 규칙에서 결과를 쓰는 방식을 결정합니다. `knime_types`는 시간대 포함 날짜-시간, 기간(duration), 기간(period) 입력 열의 KNIME 셀 유형을 지정합니다.
- `dollar_references` — `$column$` 형태의 결과는 텍스트가 아니라 열을 가리킵니다. `disallow_long`(기본값 true)은 이름이 같은 KNIME 설정과 일치합니다.
- PMML 규칙 집합 — `default_rule`은 항상 실행되며 맨 마지막에 추가되는 규칙입니다. `weight_column`과 `default_weight`(기본값 1.0)는 가중 선택에서 각 규칙의 가중치를 정하며, 가중치가 가장 큰 규칙을 먼저 적용합니다. `confidence_column`, `confidence_cell`, `confidence_output`, `default_confidence_rule`은 각 규칙 결과의 신뢰도를 기록합니다.
