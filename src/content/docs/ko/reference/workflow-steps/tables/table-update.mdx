## 설명

필터와 일치하는 행을 업데이트하고 결과를 대상 테이블에 기록합니다. 모든 소스 행이 대상에 도달합니다. 필터와 일치하는 행은 새 값으로,
그 밖의 모든 행은 원래 그대로 전달됩니다. 대상의 행 수는 항상 소스의 행 수와 같습니다.

필터는 어떤 행이 *변경*되는지를 선택하며, 어떤 행이 반환되는지를 선택하지 않습니다. 이 점이 이 단계와
[Table Extract 단계](/ko/reference/workflow-steps/tables/table-extract/)의 차이입니다.
Table Extract에서는 필터가 일치하지 않는 행을 제거합니다.

<Aside type="note" title="이 단계는 더 이상 소스 테이블을 변경하지 않습니다">
이전에는 소스 테이블을 제자리에서 업데이트했습니다. 이제는 소스를 그대로 두고 별도의 대상에 기록하므로, 원본 데이터를 비교용으로 계속 사용할 수 있으며
테이블을 제자리에서 변경할 수 없는 웨어하우스를 포함한 모든 웨어하우스에서 단계가 실행됩니다. 이 변경 이전에 저장한 단계는 실행하기 전에 대상 테이블을 선택해야 하며,
업데이트된 행을 볼 것으로 기대하고 소스를 읽던 단계는 새 대상을 가리키도록 변경해야 합니다.
</Aside>

## 업데이트 매개변수

<SnippetCommonTableSourceAndTarget />

대상은 소스와 다른 테이블이어야 합니다. 이 단계는 모든 소스 행을 읽어 기록하므로, 대상을 소스 자체로 지정하면 방금 읽은 데이터에 결과가 추가됩니다.

<Aside type="note" title="소스는 뷰가 아니라 테이블이어야 합니다">
뷰는 **대상**으로 선택할 수 있으며(뷰는 데이터를 저장하지 않고 읽을 때마다 소스에 대해 다시 평가하므로 이 경우에 적합합니다), **소스**로는 선택할 수 없습니다.
이 단계는 대상의 열 목록을 소스 테이블 자체의 스키마에서 가져오는데, 뷰에는 스키마가 없기 때문입니다.
</Aside>

대상의 열은 항상 소스의 열을 그대로 따르므로 직접 선택하지 않습니다. 업데이트하지 않는 열은 이 단계를 마지막으로 연 이후 소스에 추가된 열을 포함하여 변경 없이 그대로 전달됩니다.

## 업데이트할 열

**테이블 데이터 선택** 탭에서 변경하려는 열마다 행을 추가하고 다음 중 정확히 하나를 설정합니다.

- **상수** — 고정된 값입니다.
- **식** — 계산이며, 같은 행의 다른 열을 참조할 수 있습니다.
- **Null로 설정** — 열을 비웁니다.

나열하지 않은 열은 그대로 둡니다.

왼쪽의 소스 열에 나열되지 않은 **업데이트 열**은 **상수**, **식** 또는 **Null로 설정**이 있는 행이라도 ⚠ 경고 표시와 함께 빨간색으로 표시됩니다. 단계가 해당 열을 정확한 이름으로 업데이트하기 때문입니다. 이러한 행이 있는 상태로 저장하면 **오래된 열 발견** 대화상자가 열리고, **모두 제거 후 저장**, **그대로 저장** 또는 **취소**를 선택할 수 있습니다.

저장할 때는 소스 열 목록과 관계없이 각 **업데이트 열**이 소스 테이블의 현재 상태에 정확한 이름으로 존재하는지도 검사합니다. 테이블에 없는 업데이트 열은 **누락된 소스 열** 대화상자에 이름이 표시되는데, 실행할 때 해당 열 때문에 단계가 실패하기 때문입니다. 소스 열 목록 자체는 테이블에 대해 검사하지 않습니다. 이 단계는 목록이 아니라 테이블을 있는 그대로 읽기 때문입니다.

<Aside type="caution" title="식은 행의 원래 값을 읽습니다">
식은 업데이트 *이전*의 행을 봅니다. 따라서 두 열이 한 단계에서 값을 안전하게 서로 바꿀 수 있습니다.
</Aside>

## 업데이트용 데이터 필터

**업데이트용 데이터 필터** 탭에서 변경할 행을 식별하는 조건을 입력합니다. 모든 행을 업데이트하려면 비워 두십시오.

조건을 평가할 수 없는 행(대개 조건이 검사하는 열이 null이기 때문)은 일치하지 않는 것으로 간주되어 변경 없이 그대로 전달됩니다. 이는 데이터베이스가 같은 조건을 평가하는 방식과 같습니다.
