## 설명


열 구조가 같은 여러 데이터 테이블을 하나의 데이터 테이블로 결합할 때 사용합니다. 예를 들어 시계열 데이터가 이 변환에 가장 적합합니다. 결과는 데이터를 결합한 뒤 항상 고유한 레코드 집합입니다.

<Aside>**Union Distinct**는 중복을 제거합니다. 모든 레코드를 유지하려면 **Union All**을 대신 사용하십시오.</Aside>

## 소스


**소스** 섹션은 함께 추가할 모든 데이터 테이블의 모음입니다. 일반적으로 모든 데이터 테이블은 열 구조가 같거나 비슷합니다. 목록에 데이터 테이블을 추가하는 버튼은 두 가지가 있습니다.


* **행 삽입**
* **행 추가**

또한 **편집할 소스 선택** 창에서 마우스 오른쪽 버튼을 클릭해도 같은 옵션이 표시됩니다. 이미 추가한 테이블을 마우스 오른쪽 버튼으로 클릭하면 **삭제** 옵션도 표시됩니다.


변환을 올바르게 실행하려면 추가할 소스 데이터 테이블마다 **소스** 섹션에 항목이 하나씩 있어야 합니다. 이러한 항목은 추가될 순서대로 나열됩니다. 순서를 조정하려면 테이블을 마우스 오른쪽 버튼으로 클릭하여 다음 옵션을 표시합니다.


* **아래로 이동**(해당하는 경우)
* **맨 아래로 이동**(해당하는 경우)
* **위로 이동**(해당하는 경우)
* **맨 위로 이동**(해당하는 경우)

기본적으로 각 소스의 이름은 *New Frame*이지만, 이름을 두 번 클릭하여 설명이 되는 이름으로 바꾸는 것이 좋습니다.


<Aside>표시되는 텍스트는 소스 데이터 테이블의 이름과 **관련이 없다**는 점을 기억하는 것이 중요합니다. 설명이 되는 이름을 지정하는 것이 좋으며, 소스 데이터 테이블과 같은 이름을 쓰는 경우가 많지만 두 이름 사이에는 아무런 연결이 없다는 점에 유의하십시오.</Aside>


## 대상 테이블


기본적으로 **대상 테이블**은 비어 있습니다. 이름을 지정하기 전에 데이터 테이블은 Linux 명명 규칙을 따라야 한다는 점에 유의하십시오. 따라서 이름은 영숫자로만 구성하는 것이 좋습니다. Analyze는 이름에서 유효하지 않은 문자를 자동으로 제거합니다. 또한 길이를 256자로 제한하므로 간결하게 지정하십시오.

## 저장할 때 검사하는 항목

모든 소스는 첫 번째 소스와 같은 열을 생성해야 합니다. 열 이름이 같아야 하고, 양쪽에서 형식을 선언한 경우에는 형식도 같아야 합니다. 대상 테이블은 첫 번째 소스의 열로 만들어집니다. 열은 이름으로 일치시키므로 소스가 열을 다른 순서로 나열해도 됩니다. 소스가 서로 다른 단계를 저장하면 거부되며, 각 차이점이 표시됩니다. 예: *Source 'east' must produce the same columns as 'west': missing region; not in 'west': area.*

또한 저장할 때 소스 테이블은 있지만 소스 열이나 대상 열이 없는 각 소스의 매핑을 **두 매핑 테이블 모두 채우기**를 실행한 것처럼 해당 테이블에서 채웁니다.
