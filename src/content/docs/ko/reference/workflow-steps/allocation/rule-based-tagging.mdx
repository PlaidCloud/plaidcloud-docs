## 설명



정의한 규칙에 따라 소스 테이블의 행에 차원의 속성으로 태그를 지정합니다. 출력 테이블에는 원래 열과 새 태그 열이 포함되며, 이후의 배부 또는 분석 단계에서 이 태그 열로 레코드를 라우팅하거나 그룹화할 수 있습니다.

배부나 분석이 행의 특성에 따라 달라지게 하려는 경우에 사용합니다. 예를 들어 각 비용 행에 배부 풀, 대상 계층 또는 처리 범주를 태그로 지정하면 다음 단계에서 태그 값마다 다르게 분배할 수 있습니다.

## 데이터 테이블 설정

**소스 테이블**과 **태깅 결과 테이블**은 동적 또는 정적으로 선택할 수 있습니다.

### 동적 테이블 선택
동적 테이블 옵션을 사용하면 텍스트와 변수로 테이블을 지정할 수 있습니다. 테이블 또는 뷰 참조가 지정한 변수에 따라 달라지는 변수 기반 워크플로를 사용할 때 유용합니다.

`current_month` 변수를 사용하여 테이블을 동적으로 가리키는 예:

```text
legal_entity/inputs/{current_month}/ledger_values
```

### 정적 테이블 선택
특정 테이블을 소스로 사용하려면 *Dynamic* 상자를 선택하지 않은 채로 두고 드롭다운 메뉴에서 소스 테이블을 선택합니다.


테이블 탐색기는 모든 테이블 선택에서 항상 사용할 수 있습니다. 테이블 선택 오른쪽에 있는 테이블 탐색기 버튼을 클릭하면 테이블 탐색기 창이 열립니다.

<Aside>**태깅 결과 테이블**은 뷰가 아니라 테이블이어야 합니다.</Aside>

### 소스 테이블

_할당 차원_의 속성을 추가하려는 데이터가 들어 있는 테이블입니다.

![규칙 기반 태깅](/images/rule_based_tagging_source.png)


### 태깅 결과 테이블

_태깅 결과 테이블_에는 _소스 데이터 테이블_의 데이터와 _할당 차원 계층_에 포함된 속성이 들어 있습니다.

**레코드를 하나의 규칙에만 일치**를 선택한 상태에서 어떤 규칙에도 일치하지 않는 행도 기록되며, 이 행의 태그 열은 비어 있습니다. 일치하는 규칙이 비워 둔 태그도 비어 있고, 비어 있던 소스 값은 비어 있는 채로 유지됩니다. 비어 있다는 것은 **Pandas가 아닌 SQL을 사용하여 규칙 적용**의 선택 여부와 관계없이 빈 문자열이 아니라 null을 뜻합니다. 따라서 이런 행을 골라내는 후속 단계는 `''`가 아니라 null을 찾아야 합니다.

![규칙 기반 태깅](/images/rule_based_tagging_target.png)

### 레코드를 둘 이상의 규칙에 일치시키기

기본적으로 레코드는 처음으로 일치하는 규칙 하나만 적용합니다. **레코드를 하나의 규칙에만 일치**를 선택 해제하면 일치하는 모든 규칙을 적용합니다. 이 경우 레코드는 일치하는 규칙마다 한 번씩 나타나며, 어떤 규칙에도 일치하지 않는 레코드는 제외됩니다.

규칙은 **시퀀싱** 유형의 할당 차원 속성으로 반복 단위로 나눌 수도 있으며, 이 속성의 값은 각 규칙이 실행되는 반복입니다. **레코드를 하나의 규칙에만 일치**를 선택 해제한 단계는 두 가지를 함께 할 수 없습니다. 실행되는 규칙이 둘 이상의 반복에 걸쳐 있으면 단계는 *Cannot apply rules when there are multiple iterations and records can match more than one rule* 메시지와 함께 중지됩니다. 이 옵션을 선택하거나 각 반복을 별도의 단계로 실행하십시오.

### 할당 차원 계층

![규칙 기반 태깅](/images/rule_based_tagging_assignment.png)

**할당 차원 계층**을 사용하면 ***소스 테이블***을 지정하고 클릭하여 필터링함으로써 ***태깅 결과 테이블***에 속성을 추가할 수 있습니다.
**할당 차원 계층**은 ***소스 테이블***을 참조하는 차원을 조합하여 만듭니다.

#### 할당 차원 계층 만들기

**할당 차원 계층**을 만들려면 먼저 ***소스 테이블***의 필터로 사용할 차원을 만들어야 합니다. 아래 링크에서 이러한 차원을 만드는 방법을 안내합니다.


[차원 만들기](https://docs.plaidcloud.com/docs/workflow-steps/dimensions/dimension-create/) 

[차원 로드](https://docs.plaidcloud.com/docs/workflow-steps/dimensions/dimension-load/) 

##### 기본 계층 만들기

***소스 테이블***의 차원을 만들었다면, 다음 단계는 ***소스 테이블***의 차원 중 어느 것을 **할당 차원 계층**의 ***기본 계층***으로 사용할지 결정하는 것입니다.

PlaidCloud의 차원 탭으로 이동하여 차원을 클릭한 다음 ***작업***과 ***차원 복사***를 선택하여 이 차원을 복사합니다.
차원을 복사하면 복사된 차원의 이름을 입력하라는 팝업이 나타납니다.

<Aside>**할당 차원 계층**의 이름은 "Ledger to Activity"처럼 어떤 배부를 수행하는지 알 수 있어야 합니다.</Aside>


##### 할당 계층에 차원 추가

새로 만든 **할당 차원**을 열고 ***속성*** 옆의 아래쪽 화살표를 클릭한 다음 ***새 속성***을 선택합니다.

![할당 계층 속성](/images/allocation_by_dimension_add_property.png)

그러면 ***속성 구성*** 대화 상자가 열립니다.
###### 속성 구성

![할당 계층 속성 구성](/images/allocation_by_dimension_configure_property.png)

- **속성 이름** - 보통 할당 계층에 추가하는 차원의 이름입니다.
- **속성 표시** - "Tag"로 설정해야 합니다.
- **속성 유형** - _규칙 기반 태깅_에서는 속성 유형을 _소스_로 설정해야 합니다.
  - **소스** - ***소스 테이블***과 함께 사용합니다.

- **편집기 유형** - 이 드롭다운은 ***Select Dimension***으로 설정해야 합니다.

할당 계층에 추가하는 차원의 적절한 속성을 선택했다면 "구성 편집"을 선택합니다.
###### 차원 구성

![할당 계층 구성](/images/allocation_by_dimension_configure.png)

- **차원** - 드롭다운을 사용하여 차원을 선택합니다.
- **계층** - 선택한 차원에 대체 계층이 있으면 기본 계층과 함께 여기에 표시되어 선택할 수 있습니다.
- **Start Node** - 차원을 최상위 노드부터 표시하지 않으려면 계층 내의 임의 노드를 차원이 표시될 시작 노드로 선택할 수 있습니다.
- **여러 항목 선택 허용** - 선택하면 사용자가 계층에서 여러 노드를 선택할 수 있습니다.
- **특수 사례** - _규칙 기반 태깅_에서는 사용하지 않습니다.
