## 설명

[Xero 연결](/ko/guides/connections/xero/)을 통해 연결된 조직 범위의 Xero Accounting API 엔터티 하나를 프로젝트 테이블로 가져옵니다. 연결, 엔터티 유형, 필요한 필터를 선택하면 이 단계가 조건에 맞는 레코드를 가져와 기록하며, 작성해야 할 쿼리는 없습니다.

하나의 단계 유형으로 기준 데이터(계정과목표, 연락처, 항목, 세율, 통화)부터 트랜잭션 레코드(송장, 대변 메모, 결제, 수동 분개, 은행 거래)까지 11개 엔터티를 모두 다룹니다.

## 구성

| 필드 | 필수 | 참고 |
|---|---|---|
| Xero 연결 | 예 | 읽어 올 때 사용할 Xero 연결입니다. |
| 대상 테이블 | 예 | 결과를 기록할 프로젝트 테이블입니다. |
| 엔터티 유형 | 예 | 가져올 엔터티입니다. 기본값은 **송장**입니다. |
| Status | 아니요 | `AUTHORISED` 또는 `PAID`처럼 단일 Xero `Status` 값으로 좁힙니다. |
| 시작 날짜 | 아니요 | 엔터티의 `Date`에 대한 `YYYY-MM-DD` 형식의 하한입니다. |
| 종료 날짜 | 아니요 | 엔터티의 `Date`에 대한 `YYYY-MM-DD` 형식의 상한입니다. |
| 업데이트 기준일 | 아니요 | 수정 기준일 컷오프로 전송되며, 그 이후에 변경된 행만 반환됩니다. 비워 두면 모두 가져옵니다. |

<Aside type="note">
**업데이트 기준일**은 저장된 워터마크가 없는 요청 측 필터입니다. PlaidCloud는 마지막 실행이 어디에서 멈췄는지 기억하지 않으므로, 증분 동작을 원하면 실행할 때마다 직접 컷오프를 지정하십시오.
</Aside>

## 엔터티 유형

| 엔터티 유형 | 포함하는 내용 |
|---|---|
| 계정과목표 | 계정 코드, 이름, 유형, 클래스, 세금 유형, 상태, 보고 코드. |
| 연락처 | 고객과 공급업체, 그리고 상태, 세금 번호, 기본 통화. |
| 송장 | 판매 및 구매 송장, 그리고 연락처, 날짜, 상태, 합계, 미지급 금액. |
| 대변 메모 | 판매 또는 구매에 대한 대변 메모, 그리고 연락처, 날짜, 상태, 합계. |
| 결제 | 날짜, 금액, 상태, 은행 계좌가 포함된 결제. |
| 수동 분개 | 분개 설명, 날짜, 상태. |
| 은행 거래 | 지출 및 수금 거래, 그리고 날짜, 상태, 합계, 대사 플래그. |
| 항목 | 재고 및 서비스 항목, 그리고 추적 플래그와 보유 수량. |
| 추적 범주 | 추적 범주 이름과 상태. |
| 세율 | 세율 이름, 유형, 상태, 유효 세율. |
| 통화 | 통화 코드와 설명. |

<Aside type="note">
모든 엔터티가 모든 필터를 지원하는 것은 아닙니다. 항목과 통화는 어느 필터도 사용하지 않으며, 계정과목표와 연락처는 상태 필터는 사용하지만 날짜 범위는 사용하지 않습니다. 필터 필드는 모든 엔터티에서 활성화된 상태로 유지됩니다. Xero는 엔터티가 지원하지 않는 필터를 거부하므로, 이 단계는 잘못된 결과 집합을 반환하는 대신 오류를 보고합니다.
</Aside>

<Aside type="caution">
**조직은 이 단계가 아니라 연결에서 결정됩니다.** 모든 Xero 요청은 하나의 조직을 지정하며 연결이 이를 담고 있으므로 단계에는 조직 필드가 없습니다. 두 번째 조직에서 같은 엔터티를 가져오려면 해당 조직을 가리키는 두 번째 Xero 연결을 만드십시오.
</Aside>
