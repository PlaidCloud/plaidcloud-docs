## 설명

**문서: Blob 쓰기** 단계는 [문서: Blob 읽기](/ko/reference/workflow-steps/text-documents/document-blob-extract/)와 짝을 이루는 단계입니다. 각 입력 행의 열에 있는 Base64 바이트를 문서 계정의 파일에 쓰며, 행마다 파일 하나가 만들어집니다. 출력 테이블에는 입력 행이 변경 없이 그대로 담깁니다.

단계 양식에는 **테이블**, **쓰기**, **아카이브**의 세 가지 옵션 그룹이 있습니다. 마이그레이션된 KNIME 및 Alteryx 워크플로는 바이너리 객체 및 파일 쓰기 기능에 이 단계를 사용합니다.

## 구성

- **소스 테이블** (`source`)과 **출력 테이블** (`target_frame`) — 읽을 테이블과 입력 행이 변경 없이 기록되는 테이블입니다. **소스 열** (`source_columns`)은 그대로 전달되는 열을 나열합니다.
- **쓰기** — 쓰기 자체이며, **행마다 파일 하나** 또는 **행을 하나의 보관 파일로** 중에서 선택합니다. 아래 설정은 `alteryx_config`에 저장됩니다.
  - **Blob 열** (`blob_field`) — Base64 바이트가 들어 있는 열입니다.
  - **파일 열** (`field`) — 각 행의 파일 이름을 지정하는 열입니다.
  - **파일 열의 내용** (`method`) — **아래 폴더의 파일 이름** (`FileName`, 기본값): 파일 열은 **폴더** (`path`)에 놓이는 파일 이름입니다. **전체 대상 경로** (`Path`): 파일 열은 전체 대상 경로입니다.
  - **폴더** (`path`) — 대상 `{account, path}`입니다.
  - **이미 있는 파일** (`if_exists`) — 파일이 이미 있는 경우의 동작으로, **덮어쓰기** (`overwrite`, 기본값), **단계 실패 처리** (`fail`) 또는 **그대로 두기** (`skip`) 중에서 선택합니다.
  - **압축** (`compress`) — **각 파일을 gzip으로 압축** (`gz`)은 각 파일의 바이트를 쓰기 전에 gzip으로 압축합니다.
  - **< 로 시작하는 Blob은 Base64가 아니라 XML 또는 SVG 텍스트입니다** (`xml_text`) — `<`로 시작하는 값은 UTF-8 바이트로 기록됩니다.

**행을 하나의 보관 파일로**를 선택하면 행마다 파일 하나를 쓰는 대신, 소스 행의 `Path` 및 `Blob` 열(항목 이름을 지정하는 경우 `Selected` 및 `EntryName` 열 포함)을 사용하여 하나의 아카이브로 씁니다. 이때 출력 테이블에는 `ArchivePath`와 `Blob`이 담깁니다. **아카이브** 그룹에서 설정하며, 설정은 `alteryx_config.archive`에 저장됩니다.

  - **보관 문서 경로** (`destination`) — 아카이브가 기록되는 위치입니다.
  - **형식** (`format`) — `zip`(기본값), `jar`, `tar`, `tar.gz`, `tar.bz2` 또는 `cpio`입니다.
  - **파일 이름만으로 각 항목 이름 지정** (`flatten`), **항목 이름** (`truncate`), **제거할 폴더 접두사** (`prefix`) — 경로에서 항목 이름을 만드는 방식입니다.
  - **선택한 폴더 자체의 이름을 항목에 유지** (`root`), **항목 이름의 기준이 되는 문서** (`file`), **EntryName이 있으면 그것으로 항목 이름 지정** (`named`) — 항목 이름에 대한 추가 제어입니다.
  - **빈 폴더 테이블** (`folders`) — 항목으로 추가할 빈 폴더를 지정하는 `Path` 및 `Selected` 열이 있는 테이블입니다.
  - **기존 보관 파일에 병합** (`append`) — **아니요**, **충돌하는 항목이 있으면 중단** (`abort`) 또는 **충돌하는 항목 바꾸기** (`overwrite`) 중에서 선택합니다.
