## 설명

**가장 가까운 항목 찾기** 단계는 *대상* 테이블의 각 행을 지리적으로 가장 가까운
*유니버스* 테이블의 행과 짝짓습니다. 각 대상 행에 대해 양쪽의 지오메트리
열 사이의 거리를 기준으로 가장 가까운 유니버스 행 `N`개를 유지하고,
계산된 `Distance` 열을 추가합니다.

Alteryx *Find Nearest* 도구에 해당하는 SQL 네이티브 단계입니다. 작업이
거리 순위가 매겨진 교차 조인으로 데이터베이스 내에서 전부 실행되므로, 행을 워크플로 엔진으로 가져오지 않고도
큰 테이블까지 확장됩니다.

두 지오메트리 열 모두 **WKT**(well-known text) 형식의 지오메트리를 담고 있으며,
이는 다른 PlaidCloud 공간 도우미가 생성하고 사용하는 것과 같은
표현입니다.

## 소스 및 옵션

- **대상 테이블** — 이웃을 찾으려는 *대상* 행입니다. 조건을 만족하는 모든
  대상 행이 출력에 나타납니다(가장 가까운 유니버스 행과 짝지어서).
- **유니버스 테이블** — 검색 대상이 되는 이웃 후보입니다.
- **출력 테이블** — 결과를 기록할 테이블입니다.
- **대상 지오메트리 / 유니버스 지오메트리** — 거리를 측정하는 양쪽의
  WKT 지오메트리 열입니다.
- **최근접 개수(N)** — 대상 행마다 유지할 가장 가까운 유니버스 행의 수입니다
  (기본값 1).
- **최대 거리** — 선택 사항입니다. 설정하면 대상에서 이 거리보다 먼 유니버스 행은
  순위를 매기기 전에 제외됩니다. 제한이 없으면 비워 두거나 0으로 둡니다.
- **거리 단위** — `Distance` 출력과 *최대 거리*를 표현하는 단위로,
  마일, 킬로미터, 미터 또는 피트입니다.
- **Ignore zero-distance matches** — 대상과 정확히 같은 위치에 있는(거리 0) 유니버스 행을 건너뜁니다.
  예를 들어 대상과 유니버스가 같은 데이터 집합일 때 점이 자기 자신과 매치되는 것을 방지합니다.

## 대상 및 유니버스 매핑

각 입력에는 해당 테이블에서 사용할 수 있는 열을 나열하는 별도의 매핑 탭이 있으며,
위의 지오메트리 선택기를 채우고 출력에서 열을 사용할 수 있게
하는 데 쓰입니다.

## 출력 열

출력으로 전달할 열과 각 열이 어느 쪽(대상 또는
유니버스)에서 오는지를 선택하고, 필요하면 이름을 바꿉니다. 계산된 **거리** 열
(선택한 단위로 나타낸 일치한 유니버스 행까지의 평면 거리)은 자동으로
추가되며, 이름을 바꾸거나 끌 수 있습니다.

### 오래된 열

출력 열 행은 해당 쪽의 매핑 탭(**대상 매핑** 또는 **유니버스 매핑**)에 더 이상 나열되지 않는 열을 가리킬 수 있습니다. 단계는 그런 행을 자동으로 제거하지 않습니다. 대신 열 이름이 ⚠ 경고 표시 뒤에 빨간색으로 표시되며, 마우스를 올리면 어느 매핑에서 해당 열이 빠졌는지 알려 줍니다. 열이 하나도 나열되지 않은 매핑은 검사 대상이 아닙니다.

표시된 행이 남아 있는 단계를 저장하면 **오래된 열 발견** 대화 상자에 해당 행이 나열되고 세 가지 선택지가 제공됩니다.

- **모두 제거 후 저장** — 표시된 행을 제거한 다음 저장합니다.
- **그대로 저장** — 단계를 현재 상태 그대로 저장합니다.
- **취소** — 저장하지 않고 단계로 돌아갑니다.

행을 유지하면서 경고를 해제하려면 매핑 탭에 해당 열을 다시 추가하거나 매핑에 나열된 열을 선택합니다.

## 참고

거리는 평면 거리이며(지오메트리의 좌표에서 계산한 뒤 요청한 단위로 환산),
다른 PlaidCloud 공간 단계와 일관됩니다. 경도/위도 데이터의 경우 이는 근사값이지만,
최근접 이웃 분석에서 일반적인 가까운 거리(상점 상권, 서비스 영역 등)에서는
정확합니다.
