## 설명

**공간 매치** 단계는 *대상* 테이블의 각 행을 지오메트리가 선택한 공간 관계를 만족하는
*유니버스* 테이블의 행과 짝짓습니다. 일치하는 모든 대상/유니버스 쌍에 대해
양쪽에서 선택한 열을 담은 출력 행을 하나씩 출력합니다.

Alteryx *Spatial Match* 도구의 매치 경로에 해당하는 SQL 네이티브 단계입니다. 작업이
공간 조건자 조인으로 데이터베이스 내에서 전부 실행되므로, 행을 워크플로 엔진으로 가져오지 않고도
확장됩니다.

두 지오메트리 열 모두 **WKT**(well-known text) 형식의 지오메트리를 담고 있으며,
이는 다른 PlaidCloud 공간 도우미가 생성하고 사용하는 것과 같은
표현입니다.

## 소스 및 옵션

- **대상 테이블** — 매치를 찾으려는 행입니다.
- **유니버스 테이블** — 매치 대상이 되는 후보 행입니다.
- **출력 테이블** — 일치한 쌍을 기록할 테이블입니다.
- **대상 지오메트리 / 유니버스 지오메트리** — 관계를 검사할 양쪽의
  WKT 지오메트리 열입니다.
- **관계** — 대상 지오메트리가 유니버스 지오메트리와 어떤 관계여야 하는지를 정합니다.
  - **교차(intersects)** — 두 지오메트리가 한 점이라도 공유합니다.
  - **내부(within)** — 대상 지오메트리가 유니버스 지오메트리 안에 있습니다.
  - **포함** — 대상 지오메트리가 유니버스 지오메트리를 포함합니다.

일치하는 유니버스 행이 없는 대상 행은 출력에서 제외됩니다(이 단계는
매치이며 왼쪽 조인이 아닙니다).

## 대상 및 유니버스 매핑

각 입력에는 해당 테이블에서 사용할 수 있는 열을 나열하는 별도의 매핑 탭이 있으며,
위의 지오메트리 선택기를 채우고 출력에서 열을 사용할 수 있게
하는 데 쓰입니다.

## 출력 열

출력으로 전달할 열과 각 열이 어느 쪽(대상 또는
유니버스)에서 오는지를 선택하고, 필요하면 이름을 바꿉니다.

### 오래된 열

출력 열 행은 해당 쪽의 매핑 탭(**대상 매핑** 또는 **유니버스 매핑**)에 더 이상 나열되지 않는 열을 가리킬 수 있습니다. 단계는 그런 행을 자동으로 제거하지 않습니다. 대신 열 이름이 ⚠ 경고 표시 뒤에 빨간색으로 표시되며, 마우스를 올리면 어느 매핑에서 해당 열이 빠졌는지 알려 줍니다. 열이 하나도 나열되지 않은 매핑은 검사 대상이 아닙니다.

표시된 행이 남아 있는 단계를 저장하면 **오래된 열 발견** 대화 상자에 해당 행이 나열되고 세 가지 선택지가 제공됩니다.

- **모두 제거 후 저장** — 표시된 행을 제거한 다음 저장합니다.
- **그대로 저장** — 단계를 현재 상태 그대로 저장합니다.
- **취소** — 저장하지 않고 단계로 돌아갑니다.

행을 유지하면서 경고를 해제하려면 매핑 탭에 해당 열을 다시 추가하거나 매핑에 나열된 열을 선택합니다.

## 참고

관계는 지오메트리의 좌표를 기준으로 평가되며, 다른
PlaidCloud 공간 단계와 일관됩니다.

Alteryx Spatial Match 도구의 *intersection object* 출력(겹치는 영역 자체의 지오메트리)과
*Unmatched* 출력(매치되지 않은 대상 행)은 대신
[Spatial Match (Intersect / Unmatched) 단계](/ko/reference/workflow-steps/spatial/spatial-match-executor/)에서
제공됩니다. 둘 다 데이터베이스 조건자 조인으로 표현할 수 없으므로
워크플로 엔진에서 실행됩니다.
