## 설명

모든 지리 공간 작업에 전용 단계가 필요한 것은 아닙니다. 단일 행 열 식에 해당하는 모든 작업은 [Table Extract 단계](/ko/reference/workflow-steps/tables/table-extract/)의
식 셀로 데이터베이스에서 실행되며 행이 웨어하우스 밖으로 나가지 않으므로,
워크플로 엔진이 아니라 테이블 크기에 맞게 확장됩니다. [Alteryx 변환](/ko/guides/workflows/migrate-spatial-alteryx-workflows/)은
Alteryx *Create Points* 및 *Distance* 도구에 대해 이 경로를 선택합니다.

## 이식 가능한 지오메트리 함수

Lakehouse v1과 v2는 지오메트리 함수의 철자가 서로 다릅니다. 예를 들어 `ST_MAKEGEOMPOINT`와
`ST_POINT`, `ST_ASWKT`와 `ST_ASTEXT`가 그렇습니다. `geom_*` 계열은
실행 중인 워크스페이스에 맞는 함수로 자동 연결되므로, 한 번 작성한 식이
두 곳 모두에서 작동합니다.

| 식 | Lakehouse v1 | Lakehouse v2 |
|---|---|---|
| `func.geom_from_wkt(x)` | `ST_GEOMETRYFROMWKT` | `ST_GEOMETRYFROMTEXT` |
| `func.geom_point(lon, lat)` | `ST_MAKEGEOMPOINT` | `ST_POINT` |
| `func.geom_as_wkt(g)` | `ST_ASWKT` | `ST_ASTEXT` |
| `func.geom_contains(a, b)` | `ST_CONTAINS` | `ST_CONTAINS` |
| `func.geom_within(a, b)` | `ST_WITHIN` | `ST_CONTAINS`, 인수 순서 바꿈 |
| `func.geom_x(g)` | `ST_X` | `ST_X` |
| `func.geom_y(g)` | `ST_Y` | `ST_Y` |

<Aside type="note" title="모든 것이 이식 가능한 것은 아닙니다">
  `geom_area`, `geom_length`, `geom_intersects`, `geom_centroid`,
  `geom_distance`, `geom_createline` 및 경계 상자 가장자리
  (`st_xmin`/`st_xmax`/`st_ymin`/`st_ymax`)는 Lakehouse v1에만 있으며,
  StarRocks에는 이에 해당하는 함수가 없습니다. v2 워크스페이스에서는 식을 컴파일할 때
  잘못된 결과를 내는 대신 함수 이름을 명시한 메시지와 함께 실패합니다.
  이러한 측정값에는 대신
  [지리 공간 단계](/ko/reference/workflow-steps/spatial/)를 사용하십시오.
  이 단계들은 워크플로 엔진에서 실행되며 모든 웨어하우스에서 같은 결과를 냅니다.
</Aside>

## 점 만들기

경도 열과 위도 열로 WKT 점을 만듭니다.

```python
func.geom_as_wkt(
    func.geom_point(
        get_column(table, 'Longitude'),
        get_column(table, 'Latitude'),
    )
)
```

`geom_as_wkt`는 결과를 WKT로 기록하며, 이는 모든 PlaidCloud 공간 단계가
읽고 쓰는 형식입니다.

<Aside type="caution" title="십진 도 또는 정수 경도/위도">
  이는 일반 십진 도 좌표와, 1,000,000을 곱한 정수
  좌표(Create Points가 다시 나누어 줍니다)에서 정확합니다.
  투영 좌표계의 좌표는 먼저 WGS84
  경도/위도로 다시 투영해야 하며, 이를 직접 사용해 점을 만들면 투영되지 않은
  지오메트리가 만들어집니다.
</Aside>

## 두 점 사이의 거리

거리는 여기서 **이식 가능한 표기가 없는** 유일한 작업입니다. 두
Lakehouse는 함수와 반환 단위가 모두 다르므로 식이
버전마다 다릅니다.

<Aside type="caution" title="워크스페이스에 맞는 형식을 선택하십시오">
  `ST_DISTANCE_SPHERE`는 Lakehouse v2에만 있고, `geom_distance`는
  Lakehouse v1에만 있습니다. 어느 쪽도 상대편으로 대체되지 않습니다. 두 곳에서 모두
  작동하는 단일 단계가 필요하면
  [Spatial Find Nearest 단계](/ko/reference/workflow-steps/spatial/spatial-find-nearest/)를
  사용하십시오. 실행되는 워크스페이스에 맞는 식을 알아서 선택합니다.
</Aside>

### Lakehouse v2

`ST_DISTANCE_SPHERE`는 좌표 네 개를 받아 **미터** 단위로 반환합니다.

```python
case(
    (
        and_(
            get_column(table, 'Origin').like('POINT%'),
            get_column(table, 'Destination').like('POINT%'),
        ),
        func.st_distance_sphere(
            func.geom_x(func.geom_from_wkt(get_column(table, 'Origin'))),
            func.geom_y(func.geom_from_wkt(get_column(table, 'Origin'))),
            func.geom_x(func.geom_from_wkt(get_column(table, 'Destination'))),
            func.geom_y(func.geom_from_wkt(get_column(table, 'Destination'))),
        ) * 0.0006213711922373339,
    ),
    else_=null,
)
```

| 단위 | 미터 기준 계수 |
|---|---|
| 마일 | `0.0006213711922373339` |
| 킬로미터 | `0.001` |
| 미터 | `1` |
| 피트 | `3.280839895013123` |

### Lakehouse v1

`geom_distance`는 두 지오메트리에 대한 **평면** 거리이며 **도** 단위로 반환하므로,
계수는 미터가 아니라 도에서 변환합니다.

```python
func.geom_distance(
    func.geom_from_wkt(get_column(table, 'Origin')),
    func.geom_from_wkt(get_column(table, 'Destination')),
) * 69.1709
```

| 단위 | 도 기준 계수 |
|---|---|
| 마일 | `69.1709` |
| 킬로미터 | `111.32` |
| 미터 | `111320.0` |
| 피트 | `364566.929` |

평면 방식이므로 적도에서 멀어질수록 정확도가 떨어지는 근사값입니다. 상권 분석에서
흔한 가까운 거리에서는 문제없지만 대륙 규모에서는 그렇지 않습니다.

v2 형식의 `LIKE 'POINT%'` 조건은 중요합니다. `ST_DISTANCE_SPHERE`는 좌표 네 개를 받으므로,
양쪽 중 하나라도 점이 아닌 지오메트리이면 조용히 잘못된 값을 측정하게 됩니다.
`CASE`는 해당 행에 대해 대신 null을 반환합니다.
