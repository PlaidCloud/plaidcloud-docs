## 설명

[Anaplan 연결](/ko/guides/connections/anaplan/)을 통해 하나 이상의 Anaplan 목록을 읽어 PlaidCloud 차원으로 로드합니다. **하나의 단계가 전체 복합 계층을 읽습니다.** 계층에 걸쳐 있는 모든 목록을 루트부터 순서대로 지정하십시오(예: Region, Country, Store). 여러 단계로 나누지 마십시오. 스테이징 테이블은 실행할 때마다 통째로 교체되므로, 하나의 스테이징 테이블을 가리키는 여러 단계는 서로 앞선 단계의 행을 지우게 됩니다.

이 단계는 단계 메뉴의 **Anaplan** 아래에 **목록 읽기**라는 이름으로 표시됩니다.

이 단계는 Anaplan의 Integration API를 통해 Anaplan에 **클라우드 직접** 연결합니다. 온프레미스 에이전트 경로는 없습니다.

<Aside type="tip">
이 커넥터는 읽기 전용이며, 기본(사용자 이름과 비밀번호) 자격 증명 또는 CA 인증서 자격 증명으로 인증합니다. [인증](/ko/guides/connections/anaplan/#인증)을 참조하십시오. Anaplan의 요청 한도는 테넌트 전체에서 공유되므로, 이 단계의 일정을 다른 Anaplan 워크플로와 겹치지 않게 분산하십시오. [일정 관련 고려 사항](/ko/guides/connections/anaplan/#일정-관련-고려-사항)을 참조하십시오.
</Aside>

## 구성

### Anaplan 소스

| 필드 | 필수 | 참고 |
|---|---|---|
| Anaplan 연결 | 예 | 데이터를 읽을 [Anaplan 연결](/ko/guides/connections/anaplan/)입니다. |
| 환경 | 예 | 연결의 환경입니다. |
| 모델 | 아니요 | 연결에 저장된 모델 ID를 재정의합니다. 연결에서 실시간으로 검색하거나 직접 입력합니다. |
| 목록 | 예 | 계층에 걸쳐 있는 모든 Anaplan 목록을 순서가 있는 목록으로 지정합니다. 선택한 모델에서 검색한 목록을 추가하거나 ID를 직접 입력한 다음, 위로 이동/아래로 이동으로 순서를 변경합니다. 루트부터 나열하면 읽기 편하지만, 상위 항목을 확인하기 전에 모든 목록을 먼저 읽으므로 순서가 결과에 영향을 주지는 않습니다. |
| 스테이징 테이블 | 예 | PlaidCloud 차원을 만들기 전에 원시 상위/하위/통합/이름 및 속성 행이 이 테이블에 저장됩니다. |

### 대상 PlaidCloud 차원

| 필드 | 필수 | 참고 |
|---|---|---|
| 차원을 동적으로 지정 | 둘 중 하나 | 대상 차원 이름이며, 실행 시점에 확인되는 `{variable}` 토큰을 포함할 수 있습니다. 기본으로 선택되어 있습니다. |
| 특정 차원 사용 | 둘 중 하나 | 대신 이미 있는 PlaidCloud 차원을 선택합니다. |

## 이 단계에서 표현할 수 없는 항목

| 제한 사항 | 의미 |
|---|---|
| 모든 에지가 단순 `+`로 롤업됨 | Anaplan 목록 계층에는 에지별 가중치나 부호가 없습니다. 읽어 올 값이 없으므로 변환 과정에서 손실되는 것은 없지만, 그 이상을 표현할 수도 없습니다. 모델이 라인 항목이나 속성을 통해 제외 또는 음수 롤업을 표현한다면, 그 로직은 차원으로 전달되지 않으므로 다운스트림에서 다시 구성해야 합니다. |
| 액세스 제어 플래그와 하위 집합 멤버십은 가져오지 않음 | 선택적 액세스 읽기/쓰기 플래그와 각 항목의 목록 하위 집합 멤버십은 차원 데이터가 아니라 Anaplan 메타데이터입니다. 모든 하위 집합을 각각 별도의 열로 가져오면 계속 늘어나는 공유 네임스페이스에서 실제 속성과 충돌하게 됩니다. 이름이 둘 중 하나와 충돌하는 실제 목록 속성은 다른 이름으로 조용히 저장하지 않고 거부됩니다. |
| 라인 항목 하위 집합은 차원으로 읽을 수 없음 | Anaplan은 이를 이 단계가 읽을 수 있는 목록이 아니라 일반 차원 항목 엔드포인트를 통해서만 제공합니다. |
| 레코드가 1,000,000개를 넘는 목록은 이 경로로 읽을 수 없음 | 이 단계가 읽는 항목 엔드포인트는 문서화된 한도를 넘으면 부분 결과를 반환하지 않고 즉시 거부하며, 페이지를 나누어 우회할 방법도 제공하지 않습니다. 따라서 이 단계는 부분 차원을 로드하는 대신 거부하고 해당 한도를 알려 줍니다. 그동안에는 Anaplan에서 목록을 분할하거나 목록의 일부만 읽으십시오. |
| 노드는 정확히 하나의 상위 항목 아래에 있음 | 상위 항목 이름과 상위 항목 ID가 서로 다르거나, 상위 항목이 이 단계가 읽지 않는 목록에 있거나, 지정한 상위 항목이 아예 없는 항목은 차원의 루트로 조용히 옮겨지지 않고 이름과 함께 거부됩니다. |
| 목록의 최상위 항목은 가져오지 않음 | Anaplan의 최상위 항목은 목록 자체의 항목이 아니라 목록의 모든 항목 위에 있는 롤업 노드이므로, 이 단계가 읽는 항목에는 포함되지 않습니다. 그 결과 차원은 Anaplan 목록보다 한 레벨 얕아지고, 목록 자체의 루트가 차원의 루트가 됩니다. 읽는 목록에 이러한 최상위 항목이 선언되어 있으면 이 단계가 경고합니다. |
| 노드 ID는 함께 읽는 모든 목록에서 고유해야 함 | 노드 ID는 항목의 Anaplan 코드이며, 코드가 없으면 이름입니다. Anaplan 코드는 하나의 목록 안에서만 고유함이 보장됩니다. 같은 짧은 코드를 재사용하는 두 목록은 하나의 노드로 조용히 병합되지 않고 이름과 함께 거부됩니다. |
| 대체 계층은 지원되지 않음 | 모든 목록은 차원의 기본 계층으로 로드됩니다. |
| 읽기 전용 | Anaplan에는 아무것도 다시 쓰지 않습니다. |
