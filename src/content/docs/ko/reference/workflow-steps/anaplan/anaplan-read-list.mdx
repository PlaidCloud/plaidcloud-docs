## 설명

[Anaplan 연결](/ko/guides/connections/anaplan/)을 통해 하나 이상의 Anaplan 목록을 읽어 PlaidCloud 차원으로 로드합니다. **단계 하나가 전체 복합 계층을 읽습니다.** 여러 단계로 나누지 말고 계층이 포함하는 모든 목록을 루트부터 순서대로 지정하십시오(예: Region, Country, Store). 스테이징 테이블은 실행할 때마다 완전히 교체되므로, 여러 단계가 하나의 스테이징 테이블을 가리키면 각 단계가 이전 단계의 행을 지워 버립니다.

이 단계는 단계 메뉴의 **Anaplan** 아래에 **목록 읽기**라는 이름으로 표시됩니다.

이 단계는 Anaplan의 Integration API를 통해 Anaplan에 **클라우드에서 직접** 접근하며, 온프레미스 에이전트 경로는 없습니다.

<Aside type="tip">
이 커넥터는 읽기 전용이며 기본(사용자 이름과 비밀번호) 또는 CA 인증서 자격 증명으로 인증합니다. [인증](/ko/guides/connections/anaplan/#인증)을 참조하십시오. Anaplan의 요청 한도는 테넌트 전체에서 공유되므로, 이 단계의 일정을 다른 Anaplan 워크플로와 엇갈리게 설정하십시오. [일정 고려 사항](/ko/guides/connections/anaplan/#일정-관련-고려-사항)을 참조하십시오.
</Aside>

## 구성

### Anaplan 소스

| 필드 | 필수 | 참고 |
|---|---|---|
| Anaplan 연결 | 예 | 읽을 때 사용할 [Anaplan 연결](/ko/guides/connections/anaplan/)입니다. |
| 환경 | 아니요 | **프로젝트 환경**(기본값)은 프로젝트의 연결 환경을 사용합니다. **고정 환경**은 항상 사용자가 선택한 환경을 사용합니다. [단계를 하나의 환경에 고정](/ko/guides/projects/managing-projects/#단계를-하나의-환경에-고정)을 참조하십시오. |
| 모델 | 아니요 | 연결에 저장된 모델 ID를 재정의합니다. 연결에서 실시간으로 검색하거나 직접 입력합니다. |
| 목록 | 예 | 계층이 포함하는 모든 Anaplan 목록을 순서가 있는 목록으로 지정합니다. 선택한 모델에서 검색된 목록을 추가하거나 ID를 직접 입력한 다음 위로 이동 / 아래로 이동으로 순서를 바꿉니다. 루트부터 나열하면 읽기 좋지만, 어떤 부모도 확인되기 전에 모든 목록을 읽으므로 순서가 적재 결과를 바꾸지는 않습니다. |
| 스테이징 테이블 | 예 | 원시 부모/자식/통합/이름 및 속성 행이 여기에 적재된 뒤 PlaidCloud 차원이 이를 기반으로 만들어집니다. |

### 대상 PlaidCloud 차원

| 필드 | 필수 | 참고 |
|---|---|---|
| 차원을 동적으로 지정 | 둘 중 하나 | 대상 차원 이름이며, 실행 시점에 확인되는 `{variable}` 토큰을 포함할 수 있습니다. 기본적으로 선택되어 있습니다. |
| 특정 차원 사용 | 둘 중 하나 | 대신 기존 PlaidCloud 차원을 선택합니다. |

## 미리 보기

**소스** 탭의 **미리 보기**는 단계를 실행하지 않고 이 목록 읽기가 생성할 열과 데이터 유형을 보여 줍니다. 잠긴 프로젝트에서는 사용할 수 없습니다.

## 이 단계에서 표현할 수 없는 항목

| 제한 사항 | 의미 |
|---|---|
| 모든 에지는 단순한 `+`로 집계됨 | Anaplan 목록 계층에는 에지별 가중치나 부호가 없습니다. 읽을 것이 없으므로 변환 과정에서 손실되는 것은 없지만, 그 이상을 표현할 수도 없습니다. 모델이 라인 항목이나 속성을 통해 제외나 음수 집계를 표현하는 경우 해당 로직은 차원으로 전달되지 않으므로 다운스트림에서 다시 만들어야 합니다. |
| 액세스 제어 플래그와 하위 집합 멤버십은 가져오지 않음 | 선택적 액세스 읽기/쓰기 플래그와 각 항목의 목록 하위 집합 멤버십은 차원 데이터가 아니라 Anaplan 메타데이터입니다. 모든 하위 집합을 각각의 열로 가져오면 계속 커지는 공유 네임스페이스에서 실제 속성과 충돌하게 됩니다. 이름이 둘 중 하나와 충돌하는 실제 목록 속성은 다른 이름으로 조용히 적재되는 대신 거부됩니다. |
| 라인 항목 하위 집합은 차원으로 읽을 수 없음 | Anaplan은 이를 이 단계가 읽을 수 있는 목록이 아니라 일반 차원 항목 엔드포인트를 통해서만 노출합니다. |
| 레코드가 1,000,000개를 넘는 목록은 이 경로에서 읽을 수 없음 | 이 단계가 읽는 항목 엔드포인트는 문서화된 상한을 넘으면 부분 결과를 반환하지 않고 완전히 거부하며, 이를 우회하여 페이징할 방법도 제공하지 않습니다. 따라서 단계는 부분 차원을 적재하는 대신 상한을 명시하며 거부합니다. 그동안은 Anaplan에서 목록을 분할하거나 그 하위 집합을 읽으십시오. |
| 노드는 정확히 하나의 부모 아래에 있음 | 부모 이름과 부모 ID가 일치하지 않거나, 부모가 이 단계가 읽지 않는 목록에 있거나, 지정된 부모가 아예 없는 항목은 차원의 루트로 조용히 재배치되는 대신 이름과 함께 거부됩니다. |
| 목록의 최상위 항목은 가져오지 않음 | Anaplan의 최상위 항목은 목록 자체의 항목이 아니라 목록의 모든 항목 위에 있는 집계 노드이므로, 이 단계가 읽는 항목에서는 반환되지 않습니다. 따라서 차원은 Anaplan 목록보다 한 수준 얕아지며, 목록 자체의 루트가 차원의 루트가 됩니다. 읽는 목록에 최상위 항목이 선언되어 있으면 단계가 경고합니다. |
| 노드 ID는 함께 읽는 모든 목록에서 고유해야 함 | 노드의 ID는 항목의 Anaplan 코드이거나, 코드가 없으면 이름입니다. Anaplan 코드는 하나의 목록 안에서만 고유함이 보장됩니다. 같은 짧은 코드를 재사용하는 두 목록은 하나의 노드로 조용히 병합되는 대신 이름과 함께 거부됩니다. |
| 대체 계층은 지원되지 않음 | 모든 목록은 차원의 기본 계층으로 로드됩니다. |
| 읽기 전용 | Anaplan에는 아무것도 다시 쓰지 않습니다. |
