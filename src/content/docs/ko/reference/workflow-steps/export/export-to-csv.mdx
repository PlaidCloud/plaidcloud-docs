## 설명



PlaidCloud 프로젝트 테이블을 CSV(쉼표로 구분된 값) 파일로 문서 계정에 기록합니다. 가장 일반적인 내보내기 형식으로, 거의 모든 하위 시스템, 스프레드시트 도구, BI 플랫폼에서 지원합니다.

구분 기호(쉼표, 탭, 파이프, 사용자 지정), 따옴표 처리 방식, 머리글 행, 인코딩을 구성할 수 있습니다.

#### 구분 기호
CSV 내보내기 변환은 데이터 테이블을 PlaidCloud 문서에 저장되는 구분된 텍스트 파일로 내보내는 데 사용됩니다. 지원하는 구분 기호 유형에는 다음이 포함되며 이에 국한되지 않습니다.


* Excel CSV(쉼표로 구분)
* Excel TSV(탭으로 구분)
* 사용자 정의 구분 기호 –>


	+ 쉼표(,)
	+ 파이프(|)
	+ 세미콜론(;)
	+ 탭
	+ 공백( )
	+ 기타/사용자 지정(물결표, 대시 등)

사용자 지정 구분 기호를 지정하려면 **사용자 정의 구분 기호 –>** 옵션을 선택한 다음 **기타 –>** 옵션을 선택하고 텍스트 상자에 사용자 지정 구분 기호를 입력합니다.


#### 특수 문자

**특수 문자** 섹션에서는 따옴표와 이스케이프 문자가 포함된 데이터를 처리하는 방법을 지정할 수 있습니다. 다음 설정 중에서 선택합니다.

* 특수 문자(QUOTE_MINIMAL): 특수 문자가 있는 필드(같은 방언과 옵션으로 구성된 파서를 혼동시킬 수 있는 모든 것)를 따옴표로 묶습니다. 기본 설정입니다.
* 모두(QUOTE_ALL): 형식에 관계없이 모든 것을 따옴표로 묶습니다.
* 숫자 아님(QUOTE_NONNUMERIC): 정수나 부동 소수점이 아닌 모든 필드를 따옴표로 묶습니다. 리더와 함께 사용하면 따옴표로 묶이지 않은 입력 필드는 부동 소수점으로 변환됩니다.
* 없음(QUOTE_NONE): 출력에서 아무것도 따옴표로 묶지 않습니다. 따옴표 문자는 사용자가 지정한 이스케이프 문자와 함께 출력에 포함됩니다. 이스케이프 문자는 하나만 지정할 수 있습니다.

기본적으로 따옴표로 묶인 필드 안의 따옴표는 두 번 겹쳐(`""`) 기록됩니다. 대신 Spark처럼 이스케이프 문자로 기록하려면 `escape_quotes`를 켭니다. 이스케이프 문자가 `\`이면 필드 `say "hi"`는 `"say \"hi\""`로 기록됩니다. 이 설정은 기본적으로 꺼져 있으므로 기존 내보내기는 바뀌지 않습니다. 

따옴표 문자를 포함한 값은 기본적으로 그 이유만으로 따옴표로 묶입니다. 이런 값을 Spark에서 `escapeQuotes`를 끈 경우처럼 둘러싸는 따옴표 없이 기록하려면 **따옴표 문자를 포함한 값을 따옴표로 묶기**를 해제합니다. 구분 기호나 줄 바꿈을 포함한 값은 여전히 따옴표로 묶입니다. 이 확인란은 기본적으로 선택되어 있습니다. 해제하면 파일은 웨어하우스가 아니라 PlaidCloud가 기록합니다.

모든 값을 있는 그대로 기록하려면 **따옴표 문자**를 비워 두십시오. 아무것도 따옴표로 묶이지 않고 이스케이프되지 않습니다. 이 경우 구분 기호나 줄 바꿈을 포함한 값은 읽을 때 여러 필드로 나뉘므로, 데이터에 포함되지 않은 구분 기호를 선택하십시오.

#### 첫 번째 행에 머리글 쓰기
이 확인란을 선택하면 테이블 머리글이 첫 번째 행으로 내보내집니다. 선택하지 않으면 내보낸 파일에 머리글이 없습니다.

#### 머리글에 데이터 형식 포함
이 확인란을 선택하면 내보낸 파일의 머리글에 열의 데이터 형식이 포함됩니다.

#### Windows 줄 끝

마지막으로 **Windows 호환 줄 끝 사용** 확인란은 Windows 시스템과의 호환성을 위해 기본적으로 선택되어 있습니다. UNIX 전용 환경에서 작업하는 경우가 아니라면 이 설정을 켜 두는 것이 좋습니다.




### 파일이 있는 경우

**추가 CSV 옵션**에서 **이미 있는 파일**(`if_exists`)은 파일이 이미 있을 때의 동작을 결정합니다. `replace`(기본값)는 새 파일을 기록하고, `append`는 머리글 행 없이 기존 파일의 끝에 행을 추가하며, `fail`은 아무것도 기록하지 않고 단계를 중지합니다. 추가는 파일을 내려받아 행을 추가한 다음 다시 업로드하므로, 두 실행이 동시에 같은 파일에 추가하면 마지막에 끝나는 실행이 이깁니다. `append`에서는 **기존 행 아래에 머리글을 다시 기록**(`header_on_append`)을 선택하여 이미 있는 행 아래에 머리글 행을 다시 기록할 수 있습니다.

### 추가 설정

**추가 CSV 옵션**에는 다음 필드도 있습니다.

* **행 정렬 기준**(`sort_columns`) — 기록되는 행을 이 소스 열로 정렬하며 첫 번째 키부터 적용하고, 각 키마다 **열**, **오름차순**, **NULL 값** 설정이 있습니다. 키 열을 반드시 기록할 필요는 없습니다. **NULL 값**의 기본값은 오름차순에서는 먼저, 내림차순에서는 나중입니다. **요약** 또는 **고유**와 함께 사용하지 않습니다.
* **줄 끝**(`line_ending`) — 모든 줄의 줄 끝으로 `\n`, `\r\n` 또는 `\r`이며 **Windows 호환 줄 끝 사용**을 대체합니다.
* **따옴표로 묶기**(`quote_mode`) — 따옴표로 묶을 값으로 **안 함**, **항상**, **숫자와 부울을 제외한 모든 값** 또는 **구분 기호가 포함된 값**입니다. 기본적으로 값은 필요할 때 따옴표로 묶입니다.
* **닫는 따옴표**(`quote_end`) — 여는 따옴표와 다를 때의 닫는 따옴표입니다.
* **값 안의 닫는 따옴표**(`quote_replacement`) — 따옴표로 묶인 값 안의 닫는 따옴표 대신 기록됩니다. 비워 두면 따옴표를 두 번 겹쳐 기록합니다.
* **값 안의 구분 기호**(`delimiter_replacement`) — **따옴표로 묶기**를 **안 함**으로 설정한 경우 값 안의 구분 기호 대신 기록됩니다.
* **파일 앞에 바이트 순서 표시 추가**(`write_bom`) — 파일을 바이트 순서 표시로 시작합니다.
* **소수 구분 기호**(`decimal_separator`) — 숫자의 소수점으로 기록되는 문자입니다.
* **머리글 앞 줄**(`comment_lines`) — 머리글 앞에 그대로 기록되는 줄의 JSON 배열입니다.
* **Java 방식으로 소수 기록**(`scientific_numbers`) — 1천만 이상 0.001 미만의 소수를 `1.0E10`과 같은 과학적 표기법으로 기록합니다.
* **.csv나 .tsv를 붙이지 않고 지정한 대로 각 파일 이름 기록**(`keep_file_extension`) — 각 파일 이름을 지정한 그대로 기록합니다.
* **gzip을 사용할 때 .gz를 붙이지 않고 지정한 이름으로 파일 저장**(`exact_file_name`) — gzip 압축을 사용할 때 파일을 지정한 이름 그대로 저장합니다.
