## 설명


Analyze 데이터 테이블을 JSON 파일로 PlaidCloud Document에 내보냅니다. 데이터 방향에 대해 아래와 같은 여러 옵션이 있습니다.



JSON 파일에 대한 자세한 내용은 JSON 공식 웹사이트(http://json.org/)를 참조하십시오.


<Aside>JSON 파일은 열 순서를 유지하지 *않습니다*. 소스 데이터 테이블의 열 순서가 내보낸 파일의 열 순서와 반드시 같지는 않습니다.</Aside>

### JSON 방향


다음 데이터 세트를 생각해 보십시오.




| ID |  Name  | Gender | State |
|----|--------|--------|-------|
| 1  | Jack   |   M    |   MO  |
| 2  | Jill   |   F    |   MO  |
| 3  | George |   M    |   VA  |
| 4  | Abe    |   M    |   KY  |

JSON 파일은 다음 네 가지 데이터 형식 중 하나로 내보낼 수 있습니다.


* Records: 데이터를 Python 딕셔너리 집합으로 저장하며, 각 행을 \{Column -> Value, …} 형식으로 저장합니다. 예: **[\{“ID”:1,”Name”:”Jack”,”Gender”:”M”,”State”:”MO”},\{“ID”:2,”Name”:”Jill”,”Gender”:”F”,”State”:”MO”},\{“ID”:3,”Name”:”George”,”Gender”:”M”,”State”:”VA”},\{“ID”:4,”Name”:”Abe”,”Gender”:”M”,”State”:”KY”}]**
* Index: 데이터를 중첩된 Python 딕셔너리 집합으로 저장하며, 각 행을 \{Index -> \{Column -> Value, …},…} 형식으로 저장합니다. 예: **\{“0”:\{“ID”:1,”Name”:”Jack”,”Gender”:”M”,”State”:”MO”},”1”:\{“ID”:2,”Name”:”Jill”,”Gender”:”F”,”State”:”MO”},”2”:\{“ID”:3,”Name”:”George”,”Gender”:”M”,”State”:”VA”},”3”:\{“ID”:4,”Name”:”Abe”,”Gender”:”M”,”State”:”KY”}}**
* Split: 데이터를 하나의 Python 딕셔너리 집합에 저장하며, 값은 리스트로 저장합니다. 예: **\{“columns”:[“ID”,”Name”,”Gender”,”State”],”index”:[0,1,2,3],”data”:[[1,”Jack”,”M”,”MO”],[2,”Jill”,”F”,”MO”],[3,”George”,”M”,”VA”],[4,”Abe”,”M”,”KY”]]}**
* Values: 데이터를 여러 Python 리스트로 저장합니다. 예: **[[1,”Jack”,”M”,”MO”],[2,”Jill”,”F”,”MO”],[3,”George”,”M”,”VA”],[4,”Abe”,”M”,”KY”]]**


### 날짜 처리


드롭다운 메뉴에서 **날짜 형식**을 지정합니다. 다음 형식 중에서 선택합니다.


* **Epoch (Unix Timestamp – Seconds since 1/1/1970)**
* **ISO 8601 Format (YYYY-MM-DD HH:MM:SS with timeproject offset)**

드롭다운 메뉴에서 **날짜 단위**를 지정합니다. 정밀도가 높아지는 순서로 나열된 다음 형식 중에서 선택합니다.


* **초(s)**
* **밀리초(ms)**
* **마이크로초(us)**
* **나노초(ns)**

### ASCII 강제


이 확인란을 선택하면 모든 문자열이 올바른 ASCII 형식으로 인코딩됩니다. 기본적으로 사용하도록 설정되어 있습니다.



### 출력 파일 유형


내보낸 모든 파일은 기본적으로 압축되지 않지만, 다음 압축 옵션을 사용할 수 있습니다.


* Zip
* GZip
* BZip2


### 추가 설정

* **파일이 있는 경우** 아래의 **이미 있는 파일**(`if_exists`) — **덮어쓰기**(`overwrite`, 기본값)는 이미 있는 파일을 대체하고, **아무것도 기록하지 않고 단계 실패**(`fail`)는 기록하려는 파일이 이미 있으면 아무것도 기록하지 않고 단계를 중단합니다.
* **행 순서** 아래의 **행 정렬 기준**(`sort_columns`) — 기록되는 행을 이 소스 열을 기준으로 정렬합니다. 첫 번째 키가 가장 우선하며, 각 키에는 **열**, **오름차순**, **NULL 값** 설정이 있습니다. 키 열을 반드시 기록해야 하는 것은 아닙니다. **NULL 값**의 기본값은 오름차순일 때 처음, 내림차순일 때 마지막입니다. **요약** 또는 **고유**와 함께 사용되지 않습니다.
