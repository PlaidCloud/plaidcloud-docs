## 설명


현재 프로젝트의 테이블에서 다른 프로젝트의 테이블로 데이터를 복사합니다. 프로젝트 간에 참조 데이터를 공유하거나, 통합 프로젝트가 여러 운영 프로젝트에서 데이터를 가져오거나, 처리된 결과를 다른 팀의 프로젝트로 넘길 때 유용합니다.

소스와 대상 사이에 스키마가 호환되어야 합니다. 대상 프로젝트는 이 프로젝트에 **쓰기** 데이터 공유를 부여해야 합니다.


## 데이터 공유 관리

![데이터 공유 관리](/images/import_external_project_table_1.png)

다른 프로젝트로 테이블을 내보내려면 먼저 해당 프로젝트가 이 프로젝트의 쓰기를 허용해야 합니다. **대상** 프로젝트의 **홈** 탭을 열고 **데이터 공유 관리**에서 **새 데이터 공유**를 클릭한 다음, 이 프로젝트를 선택하고 **허용된 작업**에서 **쓰기**를 선택한 후 **데이터 공유 추가**를 클릭합니다. [프로젝트 간 데이터 공유](/ko/guides/projects/managing-projects/#프로젝트-간-데이터-공유)를 참조하십시오.

이 단계는 이 프로젝트 자체의 ID로 실행되므로, 누가 시작하든 실행은 공유를 통해 작동합니다.

## 외부 프로젝트 테이블 내보내기

![외부 프로젝트 테이블 내보내기](/images/export_external_project_table.png)

### 읽기 원본
드롭다운 메뉴에서 **소스 테이블**을 선택합니다.

<Aside type="note" title="비어 있는 소스 테이블">
단계가 실행될 때 소스 테이블에 행이 없으면, 내보내기는 조용히 성공하는 대신 소스가 비어 있었다는 경고와 함께 완료되므로 대상이 예상치 못하게 비어 있는 경우를 쉽게 알아챌 수 있습니다. 대개 워크플로가 아직 해당 테이블을 만들지 않았다는 뜻이므로, 내보내기 전에 소스가 채워져 있는지(일정에 따른 실행에서는 먼저 실행되도록 순서가 정해져 있는지) 확인하십시오.
</Aside>

### 쓰기 대상

#### 대상 프로젝트
드롭다운 메뉴에서 **대상 프로젝트**를 선택합니다.

#### 대상 테이블 정적

대상 테이블을 지정하려면 **대상 테이블** 드롭다운에서 기존 테이블을 대상 테이블로 선택하거나, 녹색 **"+"** 기호를 클릭하여 새 테이블을 대상으로 만듭니다.

##### 테이블 생성
새 테이블을 만들 때 **뷰** 또는 **테이블**로 만들 수 있습니다.
###### 뷰:
뷰는 테이블을 사용할 때보다 단계 실행에 걸리는 시간이 훨씬 짧다는 장점이 있습니다. 단점은 테이블의 세부 정보 모드에서 데이터를 탐색하는 데 유용하지 않다는 것입니다.

###### 테이블:
테이블을 대상으로 사용하면 단계 실행에 시간이 더 걸리지만, 세부 정보 모드에서 데이터를 탐색하는 속도가 뷰보다 훨씬 빠릅니다.

<Aside>데이터 검증이나 즉석 분석이 필요한 워크플로의 핵심 단계에는 테이블을 사용하십시오. 그 밖의 모든 단계에는 뷰를 사용하여 전체 워크플로 계산 시간을 줄이십시오. 테이블을 뷰로, 또는 그 반대로 변경할 수 있으므로 나중에 언제든 대상 테이블 유형을 업데이트할 수 있습니다.</Aside>

#### 대상 테이블 동적

동적 옵션을 사용하면 변수를 포함한 텍스트로 테이블을 지정할 수 있습니다. 테이블과 뷰 참조가 지정한 변수에 상대적인 변수 기반 워크플로를 사용할 때 유용합니다.

`current_month` 변수를 사용하여 대상 테이블을 동적으로 가리키는 예는 다음과 같습니다.

```text
legal_entity/inputs/{current_month}/ledger_values
```

<Aside>테이블이 없으면 가져오기 프로세스가 실행될 때 동적으로 만들어집니다</Aside>

#### 기존 데이터에 추가

소스 테이블의 데이터를 대상 테이블에 추가하려면 ***기존 데이터에 추가*** 확인란을 선택합니다.
