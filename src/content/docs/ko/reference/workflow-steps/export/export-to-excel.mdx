## 설명


Analyze 데이터 테이블을 Microsoft Excel 파일로 PlaidCloud Document에 내보냅니다. PlaidCloud Analyze는 Microsoft Excel의 최신 버전(2007-2016)과 이전 버전(2000/2003)을 모두 지원합니다.

### 대상 시트 이름
대상 시트 이름을 지정합니다. 기본값은 ***Sheet1***입니다.


### 분할

**분할**은 한 열의 값을 기준으로 테이블을 여러 출력으로 나눕니다.

* **분할 안 함**(기본값) — 테이블이 **대상 시트 이름** 시트에 담긴 통합 문서 하나를 만듭니다.
* **개별 파일** — 열의 고유 값마다 통합 문서를 하나씩 만들고, 해당 값의 행을 담습니다.
* **개별 워크시트** — 고유 값마다 시트가 하나씩 있는 통합 문서 하나를 만들고, 각 시트에 값의 이름을 붙입니다. **대상 시트 이름**은 사용되지 않습니다.

**열 기준 분할**에는 나눌 기준이 되는 열을 설정합니다. 내보내기에서 기록하는 열이어야 합니다. **파일 이름 지정 기준**은 개별 파일에서 각 통합 문서의 이름을 정하는 방식을 설정합니다. **파일 이름 접미사** 또는 **파일 이름 접두사**는 파일 이름에 값을 덧붙이고, **파일 이름**은 값 자체를 전체 이름으로 사용합니다. **분할 열을 출력에 유지**를 선택하면 분할 열도 각 출력에 기록합니다.

값이 비어 있는 행은 기록되지 않으며, 단계는 경고와 함께 완료됩니다. 개별 워크시트는 서로 다른 두 값이 같은 시트 이름이 되면 해당 값을 알려 주고 중단됩니다.

### 파일 압축 선택

내보낸 모든 파일은 기본적으로 압축되지 않지만, 다음 압축 옵션을 사용할 수 있습니다.

* 압축 안 함
* Zip
* GZip
* BZip2

### 첫 번째 행에 머리글 기록
이 확인란을 선택하면 테이블 머리글이 첫 번째 행으로 내보내집니다. 선택하지 않으면 내보낸 파일에 머리글이 없습니다.

### 파일이 있는 경우

**추가 Excel 옵션**의 **이미 있는 파일**(`if_exists`)은 통합 문서가 이미 있을 때의 동작을 결정합니다. `replace`(기본값)는 새 통합 문서를 기록하고, `append`는 시트에서 마지막으로 사용한 행 아래에 A열부터 행을 기록하며, `fail`은 아무것도 기록하지 않고 단계를 중단합니다. 추가 시에는 통합 문서를 내려받아 행을 추가한 뒤 다시 업로드하므로, 두 실행이 같은 파일에 동시에 추가하면 나중에 끝나는 실행의 결과만 남습니다. **기존 행 아래에 머리글을 다시 기록**(`header_on_append`)을 선택하면 기존 행 아래에 머리글 행을 다시 기록합니다.

### 추가 설정

**추가 Excel 옵션**에는 다음 필드도 있습니다.

* **행 정렬 기준**(`sort_columns`) — 기록되는 행을 이 소스 열을 기준으로 정렬합니다. 첫 번째 키가 가장 우선하며, 각 키에는 **열**, **오름차순**, **NULL 값** 설정이 있습니다. 키 열을 반드시 기록해야 하는 것은 아닙니다. **NULL 값**의 기본값은 오름차순일 때 처음, 내림차순일 때 마지막입니다. **요약** 또는 **고유**와 함께 사용되지 않습니다.
* **누락된 셀 값**(`null_as`) — 숫자 열을 포함하여 비어 있는 모든 셀에 기록되는 텍스트입니다.
* **이미 있는 시트**(`if_sheet_exists`) — **서식을 유지하며 기존 통합 문서에 기록**(`preserve_format`)을 선택하고 통합 문서에 해당 시트가 이미 있는 경우의 동작입니다. **단계 실패 처리**(`fail`)는 단계를 중단하고, **그대로 두기**(`skip`)는 해당 시트를 그대로 둡니다. 기본적으로 **데이터 기록**은 시트에 데이터를 기록합니다.

## 크기 제한

Excel 워크시트에는 최대 1,048,576개의 행(머리글 행 포함)과 16,384개의 열을 담을 수 있습니다. 이보다 많은 데이터를 생성하게 되는 단계는 Excel에서 열리지 않는 파일을 만드느라 내보내기를 진행하지 않고 즉시 중단되며, 그 사실을 알려 줍니다.

행과 열의 수가 범위 안에 있더라도 매우 큰 내보내기는 파일 형식 자체가 허용하는 한도를 초과할 수 있습니다. 이 경우 단계는 시트 데이터가 너무 크다고 보고합니다.

이 크기를 넘는 데이터는 CSV 또는 Parquet으로 내보내십시오. 두 형식 모두 행 제한이 없으며, 생성 속도가 훨씬 빠르고 저장 용량도 더 작습니다.
