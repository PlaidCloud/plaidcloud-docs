## 설명

Intacct의 REST v1 API를 사용하여 Sage Intacct 연결을 통해 분개 전표를 Sage Intacct에 전기합니다. 전기용 사용자 정의 함수(UDF)를 직접 작성하는 방식을 대체하는 로우코드 네이티브 방식으로, 연결을 선택하고 열을 매핑하면 인증, 배치 처리, 전표별 오류 처리를 이 단계가 대신 처리합니다.

이 단계는 업스트림에서 이미 구성해 둔 두 테이블, 즉 **헤더 테이블**과 **라인 테이블**을 읽어 각 분개 전표를 검증한 다음 전기합니다. 한 번의 실행에서 많은 분개 전표를 각각 독립적으로 전기하고 추적하는 배치 경우를 처리합니다.

<Aside type="danger" title="중복 방지 기능 없음 — 다시 실행하기 전에 결과 테이블을 확인하십시오">
이 단계는 이미 전기된 전표를 추적하지 **않습니다**. 다시 실행하면 지난번에 성공적으로 전기된 전표를 포함하여 헤더 테이블의 **모든** 전표를 다시 전기하며, 중복 제거 기능은 없습니다. 다시 실행하기 전에 지난 실행의 결과 테이블을 열어 실제로 전기해야 하는 전표가 무엇인지 확인하십시오. 이전 실행에서 `status`가 `unknown`인 전표가 남아 있다면, 다른 작업을 하기 전에 아래의 [결과 테이블](#결과-테이블)을 참조하십시오.
</Aside>

## 데이터 형태 규약

이 단계는 어느 행이 어느 분개 전표에 속하는지 추론하지 않습니다. 이 단계를 실행하기 전에 표준 단계(할당 식, 집계)로 업스트림에서 그 구조를 만들어야 합니다.

- **헤더 테이블**은 **분개 전표당 정확히 한 행**을 가지며, 그 행에는 **`entry_key`** 열이 있습니다. 전표마다 고유한 값이면 무엇이든 됩니다(배치 번호, 날짜와 설명을 이은 값, 생성된 시퀀스 등).
- **라인 테이블**은 전기 라인당 한 행을 가지며, **모든 라인이 속한 헤더 행과 같은 `entry_key` 값**을 가집니다.

분개 전표 하나만 전기하는 경우(배치 처리 없음)에도 이 형태가 필요합니다. 두 테이블의 모든 행에 동일한 상수 `entry_key`를 지정하십시오.

이 단계는 검증하거나 전기하기 전에 두 테이블을 `entry_key`로 그룹화하므로, 일치하는 라인이 없는 헤더 행, 일치하는 헤더가 없는 라인, 같은 키를 가진 헤더 행이 둘 이상인 경우는 모두 잘못된 전기를 만들어 내는 대신 해당 전표의 검증에서 실패합니다.

## 고유 구성 항목

### Sage 연결

전기에 사용할 **Sage Intacct** 연결입니다. 전기에는 Sage Intacct 연결만 가지고 있는 Intacct 전용 토큰 교환과 회사/엔터티 확인이 필요하므로, 여기에는 Sage Intacct 연결만 표시되고 일반 REST 연결은 허용되지 않습니다.

같은 연결을 다른 곳에서 Intacct에서 *읽는* 데에도 사용합니다(예: [Import Sage AP](/ko/reference/workflow-steps/sage-intacct/import-sage-ap/) 단계 또는 [Import Sage Intacct Query](/ko/reference/workflow-steps/sage-intacct/import-intacct-query/) 단계). 하나의 연결이 양방향을 모두 처리합니다. [Sage Intacct REST 커넥터](/ko/reference/connectors/rest/sage-intacct/)를 참조하십시오.

### Entry Key

헤더 소스 열과 라인 소스 열 양쪽에 존재하며, 헤더 행과 라인 행을 하나의 분개 전표로 그룹화하는 열의 이름입니다. 위의 [데이터 형태 규약](#데이터-형태-규약)을 참조하십시오.

### 소스 열

탭마다 하나씩 두 개의 별도 열 매핑이 있으며, 각각 소스 열을 해당 열이 채우는 분개 전표 필드에 매핑합니다.

- **헤더 열** — 분개 전표 수준의 필드입니다. 분개장, 전기 날짜, 설명, 참조 번호, 선택 사항인 `base_location`(전표를 전기할 Intacct 엔터티/위치이며 단일 엔터티 회사라면 생략), **Entry Key**로 지정한 상관 관계 열, 그리고 이와 유사한 헤더 수준 상세 정보가 있습니다.
- **라인 열** — 전기 라인별 필드입니다. 총계정원장 계정, 차변/대변 금액, 라인 설명, 동일한 **Entry Key** 열, 차원(위치, 부서, 직원, 클래스 등)이 있습니다.

소스 열의 이름을 바꿀 필요는 없습니다. 열의 이름이 무엇이든 위의 대상 필드 이름에 매핑하면 됩니다.

### 결과 테이블

이 단계가 분개 전표당 한 행씩 기록하는 대상 테이블로, 각 전표를 검증하고 (미리보기가 아닌 경우) 전기한 결과를 기록합니다. 열과 `status` 값은 아래의 [결과 테이블](#결과-테이블)을 참조하십시오.

### Preview

**기본적으로 선택되어 있는** 체크박스입니다. Preview를 켜면 이 단계는 모든 분개 전표를 검증하고 실제 실행과 똑같이 결과 테이블을 기록하지만, Intacct에 인증하지 않으며 아무것도 전기하지 **않습니다**. Preview 모드에서는 Intacct로 가는 네트워크 호출이 전혀 없습니다. 행은 `status = preview`로 결과 테이블에 기록되므로, 원장에 아무것도 반영되기 전에 어떤 전표가 문제없이 전기되고 어떤 전표가 검증에서 실패할지 확인할 수 있습니다.

실제 실행과 마찬가지로 Preview도 결과 테이블을 이번 실행의 행으로 **교체**합니다. 결과 테이블은 누적 로그가 아니라 단계의 실행별 출력이므로, 실제 실행 후에 Preview를 실행하면 그 실행의 `posted` 행과 `unknown` 행이 덮어써집니다. 지난 실행의 결과 테이블이 여전히 필요하다면 다시 실행하기(Preview든 실제든) 전에 열어서 복사해 두십시오.

Preview는 Intacct **자격 증명**을 검증하지 않습니다. 연결하지 않으므로 잘못된 연결이나 만료된 자격 증명은 여기에 나타나지 않습니다. 자격 증명은 연결의 **연결 테스트** 동작(**도구 > 연결**)으로 별도로 확인하십시오.

이 필드를 완전히 생략한 단계 구성(예: REST API, MCP 또는 워크플로 번들 가져오기로 작성한 구성)도 실제 전기가 아니라 Preview로 기본 설정됩니다.

실제로 전기할 준비가 되었을 때만 Preview를 선택 해제하십시오. 먼저 Preview를 켜고 실행해 결과 테이블을 검토한 다음, Preview를 끄고 다시 실행하는 것이 좋습니다.

## 결과 테이블

Preview든 실제 실행이든 모든 실행은 분개 전표마다 결과 테이블에 한 행을 기록합니다.

| 열 | 설명 |
|---|---|
| `entry_key` | 이 행이 보고하는 분개 전표입니다. |
| `status` | `preview`, `posted`, `failed`, `unknown` 중 하나입니다. 아래를 참조하십시오. |
| `intacct_key` | 전기된 전표에 대해 Intacct가 할당한 키이며, 사용할 수 있는 경우에만 제공됩니다. |
| `http_status` | 전기 시도에 대해 Intacct가 반환한 HTTP 상태이며, 사용할 수 있는 경우에만 제공됩니다. |
| `error_message` | `status`가 `failed` 또는 `unknown`일 때 무엇이 잘못되었는지에 대한 간단하고 정제된 설명입니다. |
| `line_count` | 이 전표와 일치한 라인의 수입니다. |
| `posting_date` | Intacct로 전송된(Preview에서는 전송될) 전기 날짜입니다. |

### 상태 값

- **`preview`** — Preview 모드입니다. 전표가 검증되었으며 전기되지 않았습니다.
- **`posted`** — 전표가 Intacct에 성공적으로 전기되었습니다.
- **`failed`** — Intacct가 전표를 명확하게 거부했거나(또는 전기를 시도하기 전에 검증에서 실패했습니다). 근본 원인을 수정한 다음 해당 전표만 다시 전기해도 안전합니다.
- **`unknown`** — 결과를 확인할 수 없었습니다. 시간 초과, 연결 끊김, 또는 Intacct로부터 명확한 응답이 없는 서버 오류입니다.

<Aside type="danger" title="unknown은 실패했다는 뜻이 아닙니다">
`unknown` 전표는 이미 Intacct에 성공적으로 전기되었을 수 있습니다. 연결이 끊기거나 응답이 반환되지 않기 전에 요청이 수신되어 커밋되었을 수 있기 때문입니다. **이 단계를 다시 실행하기 전에 Intacct에서 해당 전표의 상태를 직접 확인하십시오.** `unknown` 전표를 확인 없이 다시 전기하면 원장에 분개 전표가 중복 생성될 위험이 있습니다.
</Aside>

`failed` 또는 `unknown` 행이 있는 실행은 결과 테이블을 열지 않아도 알 수 있도록 경고를 보고하지만, 다음에 무엇을 해야 하는지는 결과 테이블이 기준입니다.
