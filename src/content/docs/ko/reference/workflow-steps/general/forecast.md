## 설명

**예측** 단계는 입력 테이블에서 시계열을 읽고 예측 모델을 적합시킨 다음, 미래의 예측값을 출력 테이블에 기록합니다. 날짜별 과거 값이 있고 워크플로에서 반복 가능한 예측을 생성하려는 경우에 사용합니다.

## 구성

### 예측 매개변수

* **입력 테이블** *(필수)* — 과거 시계열이 들어 있는 테이블입니다.
* **출력 테이블** *(필수)* — 예측 행을 기록할 테이블입니다.
* **날짜 열** *(필수)* — 각 관측값의 날짜 또는 타임스탬프가 들어 있는 매핑된 대상 열입니다. 기본값은 `ds`입니다.
* **값 열** *(필수)* — 예측할 숫자 값이 들어 있는 매핑된 대상 열입니다.
* **계열 열** *(선택)* — 같은 테이블 안에서 고객, 제품, 지역, 계정처럼 서로 다른 계열을 구분하는 매핑된 대상 열입니다.
* **빈도** — `Auto`, `Hourly`, `Daily`, `Weekly`, `Monthly`, `Quarterly` 중 하나입니다. 입력 날짜가 듬성듬성하거나 불규칙할 때는 빈도를 명시적으로 지정하십시오.
* **예측 기간** — 예측할 미래 기간의 수입니다. 기본값은 12입니다.
* **모델** — 기본값은 `Automatic`입니다. `AutoETS`, `AutoARIMA`, `Seasonal Naive`, `Naive`, `AutoTheta`를 선택할 수도 있습니다.

### 테이블 데이터 선택

테이블 데이터 선택 탭을 사용하여 예측 전에 입력 테이블의 형태를 조정합니다. 매핑된 대상 열에는 **날짜 열**, **값 열**, 그리고 모든 **계열 열**이 포함되어야 합니다.

**소스 검사**를 사용하면 선택한 입력 테이블에서 매핑을 채웁니다. 열을 조정하기 전에 매핑의 양쪽, 소스 쪽만 또는 대상 쪽만 채울 수 있습니다.

매핑에 소스 열이 없는 경우 — *소스 열이 필요합니다. 채우기를 사용하여 입력 테이블에서 읽어 오십시오.* — 그리고 대상 열에 **날짜 열**, **값 열** 또는 **계열 열**이 빠져 있는 동안에는 저장이 거부됩니다.

### 데이터 필터

필터 탭을 사용하여 예측이 실행되기 전에 행을 제한하거나, 조건을 적용하거나, 입력 데이터를 집계하거나, 결과를 분할합니다.

## 동작

단계는 선택한 예측 기간만큼의 예측 행으로 구성된 출력 테이블을 만들거나 업데이트합니다. **계열 열**을 구성하면 PlaidCloud는 각 계열을 따로 예측하고 출력에 계열 값을 포함합니다.

## ARIMA 모델, 적합 및 진단

**모델 설정** 섹션에는 다음 필드가 있습니다.

* **모델**(`forecast_model`) — 위의 모델(`automatic`, `auto_ets`, `auto_arima`, `seasonal_naive`, `naive`, `auto_theta`) 외에도 **ARIMA**, **계절 ARIMA(SARIMA)**, **회귀자가 있는 계절 ARIMA(SARIMAX)**(`arima`, `sarima`, `sarimax`)는 사용자가 지정한 차수로 적합합니다. **ARIMA 차수(p, d, q)**(`order`)는 `[p, d, q]`이고, **계절 차수(P, D, Q, m)**(`seasonal_order`)는 `[P, D, Q, s]`(`sarima`, `sarimax`)이며, **회귀자 열**(`exog_columns`)은 외생 회귀자 열의 이름을 지정합니다(`sarimax`).
* **모드**(`mode`) — `forecast`(기본값)는 모든 계열의 예측을 기록합니다. `fit`은 `arima`, `sarima` 또는 `sarimax`로 계열 하나를 적합시키고 모델을 테이블로 기록합니다. `apply`는 **모델 테이블**(`model_frame`)에 지정된 모델 테이블의 예측을 기록하며, `sarimax` 모델의 경우 입력 테이블에 미래의 회귀자가 들어 있습니다.
* **값의 로그에 적합**(`log_transform`) — 값의 자연로그에 적합시킵니다. `apply`에서는 예측값을 로그 척도에서 반환할지 여부를 나타냅니다.
* **대신 진단 기록**(`diagnostics`) — 예측 대신 테이블 하나를 기록합니다. `model_frame` 모델의 `residuals` 또는 `coefficients`, 입력 값 열의 `autocorrelation`(ACF 및 PACF) 또는 `residual_stats`, 또는 모델 잔차의 각 지연에 대한 Q 통계량과 p-값인 `ljung_box`(모델이 없으면 입력 값 열의 것)입니다. **최대 지연**(`max_lag`, 기본값 40)은 `autocorrelation`과 `ljung_box`의 최대 지연이며, **동적으로 예측(예측값을 되먹임)**(`dynamic`)은 `residuals`가 동적 표본 내 예측을 사용하도록 합니다.
* **KNIME 시계열 노드**(`knime_config`) — 예측 대신 KNIME 시계열 준비 노드를 실행합니다. `aggregate_granularity`는 값을 연, 분기, 월, 주, 일, 시, 분 또는 초 단위로 집계하고, `align_timestamps`는 값을 기간에 맞춰 정렬합니다.

AI 어시스턴트나 REST API로 예측 구간 수준인 `interval_levels`를 설정할 수도 있으며, 사용할 수 있는 수준은 `95`뿐입니다.

## 리소스

예측 처리는 별도의 작업에서 실행됩니다. 예측에 기본 요청보다 많은 CPU 또는 메모리가 필요할 때만 **고급 리소스 관리 사용**을 켜십시오. 리소스 요청을 늘리면 용량이 일정에 반영되는 동안 예측 시작이 지연될 수 있습니다. 이 옵션과 함께 `cpu`(1~7, 기본값 1)와 `memory`(8~56GiB, 기본값 8)를 설정합니다.
