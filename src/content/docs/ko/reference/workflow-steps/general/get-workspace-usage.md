## 설명

워크스페이스 사용 현황을 프로젝트 테이블에 기록합니다. 시간에 따른 도입 추이를 추적하고, 부서나 팀별 사용 현황을 보고하고, 자체 대시보드를 만들거나, 예약된 워크플로에서 활동 감소를 감지하는 데 사용합니다. 수치는 [사용 현황 보고서](/ko/administration/access/usage-reports/)에 표시되는 값과 같습니다.

데이터 세트 세 개는 합계만 포함합니다. 멤버 이름이 들어 있는 행은 없으며 노트북 경로는 `*`로 대체됩니다. 나머지 네 개(**멤버**, **멤버별 일간**, **내용**, **멤버별 내용**)는 보고용으로 만들어졌습니다. **멤버**, **멤버별 일간**, **멤버별 내용**에는 멤버 ID 정보(사용자 ID, 사용자 이름, 이메일, 이름과 성, 보안 그룹)가 들어 있으므로 대상 테이블을 멤버 목록과 같은 수준으로 취급하십시오. 이 단계를 실행할 때마다 보안 로그에 기록됩니다.

## 구성

### 사용 데이터

**데이터 세트**는 각 행에 담길 내용을 선택합니다.

| 데이터 세트 | 행 단위 | ID 정보 포함 |
|---|---|---|
| **항목별 일간** | 일, 영역, 이벤트, 대상 | 아니요 |
| **항목별 월간** | 월, 영역, 이벤트, 대상 | 아니요 |
| **월간 합계**(기본값) | 월, 영역 | 아니요 |
| **멤버** | 워크스페이스의 사람 | 예 |
| **멤버별 일간** | 사람, 일, 영역 | 예 |
| **내용** | 대시보드, 앱 또는 노트북 | 아니요 |
| **멤버별 내용** | 사람, 항목 | 예 |

**영역**은 행을 하나의 영역으로 제한합니다. **PlaidCloud 앱**, **대시보드**, **앱**, **앱 방문**, **노트북** 중에서 선택할 수 있습니다. 모든 영역을 포함하려면 **모든 영역**으로 두십시오.

### 열

#### 항목별 일간

`day`, `source`, `event`, `subject`, `events`.

#### 항목별 월간

`month`, `source`, `event`, `subject`, `users`, `events`, `unattributed_events`, `coverage_start`, `partial`.

#### 월간 합계

`month`, `source`, `active_users`, `coverage_start`, `partial`.

`partial`은 기록이 전체를 포함하지 않는 월에 대해 true이며, `coverage_start`는 수집이 시작된 날짜입니다. 월은 마감되어 안정화된 후에 포함되며, 이는 3일이 걸립니다.

#### 멤버 열

**멤버**, **멤버별 일간**, **멤버별 내용**은 동일한 일곱 개의 열로 시작합니다.

| 열 | 내용 |
|---|---|
| `user_id` | 멤버의 ID입니다. |
| `user_name` | 멤버의 사용자 이름입니다. |
| `email` | 멤버의 이메일 주소이며 소문자입니다. |
| `first_name` | 이름입니다. |
| `last_name` | 성입니다. |
| `is_active` | 멤버가 활성 상태이면 true, 비활성화되었으면 false입니다. |
| `groups` | 멤버의 보안 그룹이며 `; `로 구분됩니다. |

`groups`에는 최상위 그룹만 나열됩니다. 하위 그룹은 확장되지 않습니다.

#### 멤버

멤버 열 다음에 이어지는 열은 다음과 같습니다.

| 열 | 내용 |
|---|---|
| `first_seen` | 날짜 범위와 관계없이 멤버가 PlaidCloud를 처음 사용한 날입니다. |
| `last_seen` | 범위 내에서 멤버가 마지막으로 활동한 날입니다. |
| `active_days` | 범위 내에서 활동이 있었던 일수입니다. |
| `events` | 범위 내의 활동 이벤트 수입니다. |
| `active_minutes` | 활동 시간(분)입니다. 영역 간에 겹치는 시간은 한 번만 계산됩니다. |
| `session_minutes` | 세션 시간(분)입니다. |
| `app_open_minutes` | 멤버가 Panel 앱을 열어 둔 시간(분)입니다. |

워크스페이스의 모든 사람에게 행이 있습니다. 범위 내에 활동이 없는 멤버는 `groups` 뒤의 값이 비어 있습니다. 이후 삭제된 멤버를 제외하면 합계는 [사용 현황 보고서](/ko/administration/access/usage-reports/)와 일치합니다.

#### 멤버별 일간

멤버 열 다음에 `day`, `source`(영역), `events`, `active_minutes`, `session_minutes`, `first_at`, `last_at`(그날의 첫 활동 시각과 마지막 활동 시각)이 이어집니다.

#### 내용

| 열 | 내용 |
|---|---|
| `type` | `dashboard`, `panel_app`, `wasm_app` 또는 `notebook`입니다. |
| `subject` | 항목의 ID입니다. 모든 노트북은 하나의 행을 공유하며 여기에 `*`가 표시됩니다. |
| `name` | 항목의 이름이며 노트북은 `*`입니다. |
| `deleted` | 항목이 이후 삭제되었으면 true입니다. |
| `users` | 항목을 연 멤버 수입니다. |
| `opens` | 항목을 연 횟수입니다. |
| `last_used` | 마지막으로 사용된 시점입니다. |
| `app_open_minutes` | Panel 앱이 열려 있던 시간(분)입니다. |

#### 멤버별 내용

멤버 열 다음에 `type`, `subject`, `name`(**내용**과 동일), `opens`(이 멤버가 항목을 연 횟수), `last_day`(멤버가 마지막으로 사용한 날)가 이어집니다.

### 멤버 데이터 세트 관련 참고 사항

- 에이전트, 서비스 계정, 이후 삭제된 멤버의 활동은 ID 열이 비어 있습니다. 삭제된 멤버는 `user_id`만 유지되고 나머지는 남지 않습니다.
- **내용**의 열기 횟수는 **멤버별 내용**의 열기 횟수 합계보다 클 수 있습니다. 그 차이는 대시보드의 임베드 보기나 게스트 보기처럼 멤버에게 귀속할 수 없는 열기 횟수입니다. **내용**은 이를 계산하지만 **멤버별 내용**은 계산할 수 없습니다.

### 예: 부서별 활동 시간

**멤버**와 **멤버별 내용**에는 소문자로 된 멤버의 `email`이 포함되어 있으므로, 인사 마스터 테이블이나 조직 마스터 테이블 같은 자체 테이블과 조인하여 부서별로 보고할 수 있습니다.

1. **데이터 세트**를 **멤버**로 설정하고 대상 테이블을 `usage_members` 등으로 지정하여 **Get Workspace Usage** 단계를 추가합니다.
2. 소문자 `email` 열이 일치하는 조건으로 `usage_members`를 조직 테이블과 조인하는 **테이블: 내부 조인** 단계를 추가합니다. 부서는 조직 테이블에서, `active_minutes`와 `events` 열은 `usage_members`에서 가져옵니다.
3. 같은 단계에서 부서별로 집계하고 `active_minutes`를 합산합니다.

결과는 부서별 활동 시간입니다. 조직 테이블에 없는 멤버는 내부 조인에서 제외되므로, 이들을 확인하려면 왼쪽 조인을 사용하십시오. **멤버별 내용**에 대해 두 번째 단계로 같은 작업을 반복하고 부서별로 `opens`를 합산하면 어느 부서가 어떤 대시보드와 앱을 사용하는지 보고할 수 있습니다.

### 날짜 범위

**범위**는 읽을 날짜를 선택합니다.

- **최근 일수**(기본값 30)는 오늘을 포함하여 가장 최근 며칠을 읽습니다.
- **이전 달**은 지난 한 달 전체를 읽습니다.
- **이번 달 누계**는 이번 달 1일부터 오늘까지 읽습니다.
- **날짜 사이**는 **시작 날짜**부터 **종료 날짜**까지 읽습니다. 오늘까지 읽으려면 **종료 날짜**를 비워 두십시오.

일과 날짜는 UTC입니다. **일**, **시작 날짜**, **종료 날짜**에는 숫자나 `YYYY-MM-DD` 날짜뿐 아니라 `{report_start}` 같은 [변수](/ko/guides/workflows/manage-workflow-variables/)도 사용할 수 있습니다. 시작은 종료보다 늦으면 안 됩니다.

### 사용 대상

**대상 테이블**이 결과를 받습니다. 이 단계는 테이블의 기존 내용을 대체하며, 행이 없는 경우에도 항상 데이터 세트의 열을 기록합니다.

## 경고

다음은 단계를 실패하게 하지 않습니다. 단계는 발생한 상황을 설명하는 경고와 함께 완료되며 테이블도 기록됩니다.

- 워크스페이스에 아직 사용량 수집이 설정되지 않았습니다.
- 범위 내에 사용량이 없었습니다.
- 범위가 보관된 기간보다 앞에서 시작하므로, 기록이 시작되는 지점부터 시작하도록 잘렸습니다. 일간 데이터는 180일, 월간 데이터는 25개월 동안 보관됩니다.

## 보안 로그

실행할 때마다 데이터 세트, 범위, 대상 테이블, 워크플로, 단계, 실행, 기록된 행 수를 기록하는 항목이 보안 로그에 기록됩니다.
