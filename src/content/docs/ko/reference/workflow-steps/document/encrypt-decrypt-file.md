## 설명

**문서: 파일 암호화**는 문서 계정의 파일 하나를 암호화하여 결과를 다른 파일에 기록합니다. **문서: 파일 암호 해독**은 그 반대로 작동합니다. 두 단계는 설정이 같습니다. 파트너로부터 암호화된 파일을 받아 가져오기에서 읽기 전에 암호를 해독하거나, 내보내기 파일을 다른 시스템으로 보내기 전에 암호화할 때 사용합니다.

## 파일

| 설정 | 필수 | 기능 |
| --- | --- | --- |
| 소스 파일 | 예 | 암호화하거나 암호를 해독할 파일입니다. |
| 대상 파일 | 예 | 기록할 파일입니다. 다시 실행해도 자신의 출력에 대해 작업하지 않도록 소스와 다른 파일이어야 합니다. |
| 대상 파일을 기록한 후 소스 파일 삭제 | 아니요 | 대상 파일이 안전하게 기록된 후 소스 파일을 제거합니다. |

없는 소스 파일은 오류가 아닙니다. 단계는 경로를 알려 주는 경고와 함께 완료되며 아무것도 기록하지 않고 워크플로는 계속됩니다. 비어 있는 소스 파일은 경고와 함께 비어 있는 대상 파일을 기록합니다. 다만 AES 또는 Blowfish로 빈 파일을 암호화하면 실제 암호화된 파일이 기록됩니다. 파일을 다시 읽을 수 없으므로 Smartsheet 문서 계정은 사용할 수 없습니다.

## 매개변수

| 설정 | 기능 |
| --- | --- |
| 알고리즘 | 암호 그룹에서 **AES-128(16바이트 키)**, **AES-192(24바이트 키)**, **AES-256(32바이트 키)**, **Blowfish(4~56바이트 키)** 또는 **Excel 통합 문서 암호** 중에서 선택합니다. |
| 모드 | **CBC**(기본값), **ECB** 또는 **GCM**입니다. Blowfish는 CBC 또는 ECB만 사용할 수 있습니다. |
| 키 변수 | `{aes_key}`와 같이 암호화 키를 보관하는 워크플로 변수 또는 프로젝트 변수입니다. AES와 Blowfish에는 필수입니다. |
| 키 및 IV 인코딩 | 키와 IV를 표현하는 방식으로 **텍스트(UTF-8)**, **16진수** 또는 **Base64**입니다. |
| 고정 IV | 초기화 벡터입니다. 비워 두면 암호화가 임의의 IV로 파일을 시작하며, 암호 해독은 파일 시작 부분에서 이를 다시 읽습니다. GCM 암호화는 항상 임의의 IV를 사용하므로 GCM에서는 비워 두십시오. |
| 통합 문서 암호 변수 | `{xlsx_password}`와 같이 Excel 통합 문서에 설정하거나 통합 문서에서 제거할 암호를 보관하는 워크플로 변수 또는 프로젝트 변수입니다. **Excel 통합 문서 암호**에는 필수입니다. |

CBC와 ECB는 PKCS7로 패딩하며, GCM은 암호화된 데이터 뒤에 16바이트 인증 태그를 추가합니다. GCM 파일은 최대 256MB까지 가능합니다. 키 또는 IV가 잘못되면 단계가 오류와 함께 중지되고 일부만 기록된 파일은 남지 않습니다.

## 키는 변수에 보관

**키 변수**와 **통합 문서 암호 변수**에는 키나 암호 자체가 아니라 `{aes_key}`와 같은 변수 참조만 입력할 수 있으며, 다른 값을 넣고 단계를 저장하면 거부됩니다. 비밀 값은 [워크플로 변수](/ko/guides/workflows/manage-workflow-variables/) 또는 프로젝트 변수에 두십시오. 그러면 한 곳에서 설정되며 단계, 단계 버전, 사본, AI 어시스턴트가 다시 읽는 내용에 나타나지 않습니다. 단계는 실행할 때 변수의 값을 읽습니다. **고정 IV**는 암호 필드이므로 양식에서 값이 숨겨집니다.

이 규칙 이전에 입력한 키나 암호를 보관하던 단계는 해당 값이 아키텍트에게만 보이는 새 프로젝트 변수로 자동 이동되었으며, 이제 그 변수를 참조합니다.
