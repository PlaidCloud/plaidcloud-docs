## 설명

텍스트 파일을 UTF-16으로 다시 씁니다. 다운스트림 시스템이 UTF-16을 요구하거나, 소스에 여러 인코딩이 섞여 있어 다른 도구가 처리하지 못할 때 유용합니다.

## 입력

- **입력 파일 또는 디렉터리** — 변환할 텍스트 파일 또는 압축 파일, 또는 그 파일들이 들어 있는 폴더입니다.
- **대상 위치** — 변환된 파일을 쓸 위치입니다.
- **압축** — 출력에 대해 압축 안 함, Zip, GZip 또는 BZip2 중에서 선택합니다.
- **하위 폴더 유지** — 폴더의 경우 선택하면 하위 폴더의 각 파일이 대상 위치의 일치하는 하위 폴더에 쓰입니다.
- **엔디언 (바이트 순서)** — 리틀 엔디언 또는 빅 엔디언입니다.
- **Include BOM** — 선택하면 파일이 바이트 순서 표시(리틀 엔디언은 `FF FE`, 빅 엔디언은 `FE FF`)로 시작합니다. 표시가 필요 없으면 선택을 해제합니다.

## 작동 방식

- 소스의 인코딩이 감지됩니다. UTF-8 파일은 UTF-8로 읽으며, Word나 Excel에서 붙여 넣은 곡선 따옴표 같은 Windows 문자도 몇 개든 그대로 처리됩니다. 다른 인코딩의 파일은 유효한 UTF-8이 아닌 첫 부분에서 감지된 인코딩으로 읽습니다.
- 텍스트는 변경 없이 기록됩니다. 악센트가 있는 문자, 기호, 기타 문자가 원래 그대로 유지됩니다.
- 인코딩을 감지할 수 없는 파일이 있으면 파일 이름을 알려 주며 단계가 실패합니다.
- 입력 경로가 없거나 그 안에 파일이 없으면 단계는 경로를 알려 주는 경고와 함께 아무것도 처리하지 않고 완료되며, 워크플로는 계속 진행됩니다.
- 압축 파일(zip, gzip 또는 bzip2 파일 등)은 먼저 압축이 풀리고, 그 안의 각 파일이 변환됩니다.
- 폴더의 경우 각 파일이 변환되어 자신의 이름으로 대상 위치에 쓰입니다. **하위 폴더 유지**를 선택하면 하위 폴더의 파일이 대신 대상 위치의 일치하는 하위 폴더에 쓰이며, 압축 파일의 내용은 해당 압축 파일이 있던 하위 폴더에 들어갑니다.
- 같은 대상 위치에 두 파일이 쓰이게 되면 단계는 두 번째 파일을 쓰기 전에 실패하며, 첫 번째 파일을 대체하지 않습니다. 메시지에는 두 파일(또는 두 파일이 모두 들어 있던 압축 파일)과 해당 위치가 표시되며, **하위 폴더 유지**를 선택하면 서로 다른 위치에 쓰이는 경우 그 사실도 알려 줍니다.

## 예시

입력 파일을 선택하고 해당 위치에서 파일을 찾아봅니다. 원하는 출력 위치를 선택하고 바이트 순서를 고른 다음, 수신 시스템에서 BOM이 필요하면 **Include BOM**을 선택합니다. 저장한 후 실행합니다.
