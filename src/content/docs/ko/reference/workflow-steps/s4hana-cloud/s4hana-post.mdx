## 설명

[S/4HANA Cloud 연결](/ko/guides/connections/s4hana-cloud/)을 통해 총계정원장 분개 전표를 SAP S/4HANA Cloud에 전기하며, PlaidCloud의 공유 ERP 쓰기 파이프라인을 거칩니다. 이 단계는 헤더 테이블(분개 전표당 한 행)과 라인 테이블(전표당 한 개 이상의 차변/대변 행)을 입력으로 받아 각 전표를 S/4HANA Cloud의 `JournalEntryBulkCreateRequest_In` SOAP 서비스에 제출합니다. **Validate Only**는 원장 점유와 전기 없이 모든 전표를 생성하고 검사하며, 선택 사항인 결과 테이블에는 각 전표의 결과가 기록됩니다.

<Aside type="caution">
이 단계로 실제 전표를 무인으로 전기하기 전에, 먼저 모든 배치를 **Validate Only**로 실행하고 결과 테이블을 검토하며 몇 건의 전기 내역을 S/4HANA에서 직접 대조하십시오.
</Aside>

## 구성

### 연결

- **S/4HANA 연결** — 전기에 사용할 S/4HANA Cloud 연결입니다.

### 데이터

- **헤더 테이블** — 분개 전표당 한 행: `journal_id`(사용자의 전표 식별자, 필수), `company_code`(필수), `document_date`, `posting_date`, `fiscal_year`, `ledger`, `header_text`.
- **라인 테이블** — `journal_id`당 한 개 이상의 행: `gl_account`, `debit`, `credit`, 그리고 원장에서 요구하는 `cost_center`/`profit_center` 차원 열.
- **결과 테이블** — 출력 테이블 ID: 전표당 한 행이며 `journal_id`, `natural_key`, `confirmation_id`, `status`(`posted`/`validated`/`error`), `message`를 포함합니다.
- **Validate Only** — 기본적으로 선택되어 있습니다. 사전 점검만 수행하며 원장 점유와 전기는 하지 않습니다. 이 필드를 완전히 생략한 단계 구성(예: REST API, MCP 또는 워크플로 번들 가져오기로 작성한 구성)도 실제 전기가 아니라 Validate Only로 기본 설정됩니다.
- **Continue On Error** — 기본적으로 선택되어 있습니다. 한 전표가 실패한 후에도 나머지 전표를 계속 전기하며, 선택 해제하면 첫 번째 실패에서 배치를 중지합니다.

## 전기 방식

PlaidCloud는 `JournalEntryBulkCreateRequest_In`을 통해 각 전표를 제출한 다음, 전표의 최종 처리 상태를 보고하는 해당 `JournalEntryBulkCreateConfirmation_Out` 메시지를 폴링합니다. 이 확인 메시지를 **수신**해야만 전표가 `posted`로 보고됩니다. 제출은 수락되었지만 확인 메시지가 끝내 도착하지 않은 전표는 제출이 수락되었다는 사실만으로 성공으로 기록되지 않고, 전기된 것으로 보고되지도 조용히 버려지지도 않은 채 격리 상태로 유지됩니다.

## 전기된 전표 정정

이 단계는 전기된 전표를 삭제하거나 다시 쓰지 않습니다. 전기된 전표를 정정하려면 원본을 직접 수정하는 대신, 원본과 차변 및 대변을 맞바꾼 새 전표, 즉 전기된 역분개 전표를 전기하십시오.

## 기능 제한

| 제한 사항 | 의미 |
|---|---|| 확인 지연 시간 | 대량 생성 서비스는 요청을 비동기로 처리하므로, 최종 상태 폴링은 동기 결과를 받는 대신 확인 메시지를 기다립니다. |
| 역분개는 제자리 수정이 아니라 새 전표입니다 | 정정은 차변과 대변을 맞바꾼 새 역분개 전표를 전기하여 수행합니다. 이미 전기된 전표를 무효화하거나 삭제할 수는 없습니다. |
| 차원 검증은 원장 설정에 따라 달라집니다 | 계정 구조에 유효하지 않은 원가 객체 또는 차원 조합은 PlaidCloud가 사전에 잡아내지 않고 S/4HANA 자체 검증에서 실패하며, `error` 행으로 표시됩니다. |
