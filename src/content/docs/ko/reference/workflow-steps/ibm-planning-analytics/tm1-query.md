## 설명

[TM1 연결](/ko/guides/connections/tm1/)을 통해 IBM **TM1 / Planning Analytics** 큐브에서 데이터를 읽습니다. 저장된 **뷰**를 실행하거나 **MDX** 쿼리를 직접 작성하여 사용할 수 있습니다. 관점(POV)을 사용하면 뷰나 MDX가 이미 고정한 값 외에 추가 차원 멤버를 고정할 수 있습니다. 반환된 셀셋은 프로젝트 테이블로 저장되며, 스키마는 읽을 때 결정됩니다. 쿼리 자체의 축에서 생성된 차원 열과 `Value` 측정값 열로 구성됩니다.

이 단계는 단계 메뉴의 **IBM TM1 / Planning Analytics** 아래에 표시됩니다.

이 단계는 REST API를 통해 TM1에 **클라우드 직접** 연결합니다. 온프레미스 에이전트는 사용되지 않으며, 이 단계에서는 아직 사용할 수 없습니다.

## 구성

### 소스 및 대상

| 필드 | 필수 | 참고 |
|---|---|---|
| TM1 연결 | 예 | 데이터를 읽을 [TM1 연결](/ko/guides/connections/tm1/)입니다. |
| 환경 | 예 | 연결의 환경입니다. |
| 데이터베이스 | 예 | 쿼리할 TM1 데이터베이스(인스턴스)입니다. 연결에 기본 데이터베이스가 설정되어 있으면 이를 기본값으로 사용합니다. |
| 큐브 | 예 | 쿼리할 TM1 큐브입니다. 연결된 데이터베이스에서 실시간으로 검색하거나 직접 입력합니다. |
| 대상 테이블 | 예 | 반환된 셀셋을 저장할 프로젝트 테이블입니다. |

### 슬라이스

| 필드 | 필수 | 참고 |
|---|---|---|
| 소스 모드 | 예 | `By View`(기본값)는 저장된 TM1 뷰를 실행합니다. `By MDX`는 직접 작성한 MDX 쿼리를 실행합니다. |
| 뷰 | 뷰 기준 선택 시 | 실행할 저장된 TM1 큐브 뷰입니다. 큐브를 선택하면 실시간으로 검색하거나 직접 입력합니다. |
| MDX | MDX 기준 선택 시 | 큐브에 대해 실행할 MDX 쿼리입니다. |

### 관점

뷰나 MDX가 이미 고정한 값 외에 슬라이스 범위를 더 좁히려면 차원마다 멤버 하나를 고정합니다. 증분 추출에 유용합니다(아래 참조). 차원 행을 추가하고 차원을 선택한 다음 멤버를 입력합니다. 멤버 값은 리터럴(`Jan-2026`)이거나, MDX 필드 자체에 적용되는 것과 동일한 방식으로 실행 시 워크플로 자체 변수에서 확인되는 `{variable}` 토큰일 수 있습니다. 일반 뷰 또는 MDX 읽기에서는 관점을 비워 둡니다. `By View`와 함께 관점을 적용하는 것은 지원되지 않습니다. 관점이 필요하면 `By MDX`를 사용하십시오.

### 옵션

| 필드 | 기본값 | 참고 |
|---|---|---|
| 0/빈 셀 숨기기 | 끔 | 가져온 **이후** 값이 정확히 숫자 `0`인 셀을 제거합니다. 대역폭은 절약되지 않으며, 게시된 `0`이 실제 사실인 계획 큐브에서는 해당 값이 버려집니다. TM1이 처음부터 계산하지 않도록 쿼리 자체에서 0을 숨기는 방식(MDX의 `NON EMPTY` 또는 저장된 뷰 자체의 숨기기 설정)을 권장합니다. |
| 행 제한 | 250,000 | 반환되는 셀 수의 상한을 지정합니다. 비워 두면 기본 상한인 250,000이 적용되며, 명시적으로 늘리거나 줄일 수 있습니다. 행 제한을 설정하지 않았다고 해서 무제한이 되는 것은 아닙니다. 유효 제한을 초과하는 쿼리는 조용히 잘리지 않고 거부됩니다. |

## 증분 추출

TM1에는 기본 제공 변경 추적 기능이 없으므로 "마지막 이후 변경된 것만 가져오기"와 같은 호출은 없습니다. 대신 실행할 때마다 **기간(또는 버전)별로 슬라이스**하는 패턴을 사용합니다. 관점에서 `Period`를 리터럴 멤버 이름이 아닌 `{period}` 워크플로 변수로 고정하면, 각 실행이 해당 실행의 대상 기간으로 치환되어 큐브 전체가 아니라 한 기간의 데이터만 가져옵니다. 이를 예약된 워크플로 및 실행할 때마다 값이 진행되는 변수와 결합하면 한 번에 한 기간씩 증분 이력을 구축할 수 있습니다.

## 미리 보기

저장하기 전에 **미리 보기**를 사용하면 현재 슬라이스를 TM1에 대해 실행하여 처음 몇 개 행과 셀 수를 표시합니다. 이때 단계 자체에 구성된 행 제한과는 별개로 작은 행 제한이 적용됩니다.

## Value가 텍스트로 저장되는 경우

TM1 측정값 차원에는 숫자 요소(`Sales`, `Cost`)와 문자열 요소(`Comment`, `Status`)가 같은 차원에 함께 있는 경우가 흔합니다. 두 종류에 걸친 슬라이스는 `Value` 열을 텍스트로 저장합니다. 열은 하나의 물리적 유형만 가지며, 슬라이스에 숫자가 아닌 셀이 하나만 있어도 유형이 결정되기 때문입니다.

이는 올바른 처리입니다. 문자열 셀을 null로 설정하면 데이터가 손실되고, 쿼리를 실패시키면 정상적인 큐브를 사용할 수 없게 되며, 열을 둘로 나누면 스키마가 반환된 데이터에 좌우되기 때문입니다. 대신 이 단계는 이 사실을 알려 줍니다. 열, 규모, 원인이 되는 요소를 명시한 경고를 표시합니다. 예를 들면 다음과 같습니다.

> Column Value landed as text: 3 of 4,812 cells are non-numeric (text or boolean), and a column can only have one type. The non-numeric cells come from element Comment. Exclude that element from the slice, or query it separately, to keep this column numeric.

**미리 보기**는 저장하기 전에 동일한 세부 정보를 보여 주며, 관점 멤버 선택기는 각 요소의 TM1 유형(숫자, 문자열 또는 통합)을 표시하므로 문자열 요소를 고정하기 전에 확인할 수 있습니다. 관점에서 문자열 요소를 고정하는 것은 차단되지 않으며, 텍스트 측정값을 읽는 올바른 방법이기도 합니다. 다만 이 경우 측정값이 축이 아니라 관점에 있으므로 `Value` 열 전체가 텍스트로 저장됩니다. 이때 경고는 요소를 지정하지 않고 건수만 보고합니다. 축의 모든 멤버가 똑같이 숫자가 아니어서 어느 것도 슬라이스를 구분하지 못하기 때문입니다.

`Value`를 숫자로 유지하려면 슬라이스에서 문자열 요소를 제외하거나, 문자열 측정값과 숫자 측정값을 별도로 쿼리하십시오.

## 기능 제한

| 제한 사항 | 의미 |
|---|---|
| 읽기 전용 | TM1에서 큐브 데이터를 읽습니다. 쓰기 되돌리기와 TI 프로세스 실행은 지원되지 않습니다. |
| 클라우드 직접 연결만 지원 | 이 단계에는 아직 온프레미스 PlaidLink 에이전트 경로가 없습니다. TM1 서버에 PlaidCloud가 직접 접근할 수 있는 네트워크 경로가 필요합니다. |
| 변경 추적 없음 | TM1은 델타/변경 이후 API를 제공하지 않습니다. 대신 실행할 때마다 기간 또는 버전별로 슬라이스하십시오(위의 증분 추출 참조). |
| 차원/계층 가져오기 없음 | 이 단계는 큐브 데이터를 읽습니다. TM1 차원 계층을 PlaidCloud 차원으로 가져오는 기능은 아직 제공되지 않습니다. |
