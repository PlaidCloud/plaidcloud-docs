PlaidXL은 PlaidCloud 데이터를 셀로 바로 읽어 오는 함수를 Excel에 추가합니다. 셀에 `=PLAIDXL.`을 입력하면 Excel 자동 완성에 함수가 인수별 간단한 설명과 함께 나열됩니다. 작업 창의 **Formulas** 탭에서 수식을 대신 작성할 수도 있습니다. [작업 창에서 수식 삽입](#작업-창에서-수식-삽입)을 참조하십시오.

| 그룹 | 함수 | 용도 |
|---|---|---|
| 목록 | [`LIST_PROJECTS`](#list_projects), [`TABLE.TBL_LIST`](#tbl_list), [`TABLE.GET_COLUMNS`](#get_columns), [`DIMENSION.DIM_LIST`](#dim_list) | 기반으로 사용할 수 있는 항목 확인 |
| 테이블 | [`TABLE.GET_TABLE`](#get_table) | 테이블 전체를 범위로 읽기 |
| 계층 | [`DIMENSION.GET_DIMENSION`](#get_dimension), [`DRILL`](#drill) | 차원의 노드를 보고서 행으로 배치 |
| 값 | [`CELL`](#cell), [`CELLS`](#cells) | 노드의 임의 조합에 대한 롤업 값 계산 |
| 구성 요소 | [`REPR.TABLE_REPR`](#table_repr), [`REPR.MEASURE`](#measure), [`REPR.MEASURES`](#measures), [`REPR.MEASURE_TYPE`](#measure_type), [`REPR.DIMENSION_REPR`](#dimension_repr), [`REPR.DRILL_KEY`](#drill_key) | `CELL`, `CELLS`, `DRILL`이 사용하는 테이블, 측정값, 집계, 노드, 드릴 깊이 설명 |

[사용자 지정 함수로 보고서 만들기](/ko/reference/cli/plaidxl/build-a-report/)에서 이 함수들이 함께 작동하는 모습을 볼 수 있습니다.

## 함수의 작동 방식

- **먼저 로그인합니다.** 함수는 PlaidCloud 로그인으로 읽으므로 사용하기 전에 작업 창에서 [로그인](/ko/reference/cli/plaidxl/connect/)하십시오.
- **통합 문서의 프로젝트에서 읽습니다.** 모든 함수는 작업 창에서 통합 문서에 연결된 프로젝트에서 읽습니다. `GET_TABLE`, `TBL_LIST`, `DIM_LIST`는 연결을 바꾸지 않고 다른 프로젝트를 읽을 수 있도록 선택적 프로젝트 ID도 받습니다. 각 통합 문서에는 자체 프로젝트가 있으므로 열려 있는 두 통합 문서가 서로 다른 프로젝트에서 읽을 수 있습니다.
- **결과가 펼쳐집니다.** 목록이나 테이블을 반환하는 함수는 그 아래(또는 오른쪽)의 셀을 채웁니다. 결과를 위한 공간을 남겨 두십시오. 방해되는 항목이 있으면 Excel에 `#SPILL!` 오류가 표시됩니다.
- **변경 사항을 반영하려면 다시 계산합니다.** PlaidXL 수식은 인수 중 하나가 변경될 때 다시 가져옵니다. PlaidCloud의 새 데이터나 작업 창에서 연결한 다른 프로젝트를 반영하려면 전체 다시 계산을 강제로 실행하십시오. Windows에서는 **Ctrl+Alt+F9**를 누릅니다. **Refresh All Tables**는 가져온 테이블을 새로 고치며 수식은 새로 고치지 않습니다.
- **정확한 이름을 사용합니다.** 테이블, 열, 차원, 노드 이름은 PlaidCloud에 표시되는 그대로 입력하십시오.

대괄호 안의 인수는 선택 사항입니다.

## 목록

### LIST_PROJECTS

`=PLAIDXL.LIST_PROJECTS([horizontal])`

열 수 있는 프로젝트의 이름을 이름순으로 나열합니다.

- `horizontal` — 행 방향으로 나열하려면 `TRUE`입니다. 기본값은 열 방향인 `FALSE`입니다.

### TBL_LIST

`=PLAIDXL.TABLE.TBL_LIST([project_id], [horizontal])`

프로젝트의 테이블 이름을 이름순으로 나열합니다.

- `project_id` — 읽을 프로젝트입니다. 기본값은 통합 문서의 프로젝트입니다.
- `horizontal` — 행 방향으로 나열하려면 `TRUE`입니다. 기본값은 열 방향인 `FALSE`입니다.

### GET_COLUMNS

`=PLAIDXL.TABLE.GET_COLUMNS(table_name, [column_filter], [orientation])`

선택한 프로젝트에 있는 테이블의 열 이름을 나열합니다.

- `table_name` — PlaidCloud에서의 테이블 이름입니다.
- `column_filter` — `"text"` 같은 데이터 유형으로, 해당 유형의 열만 나열합니다. 생략하면 모든 열을 나열합니다.
- `orientation` — 열 방향은 `"vertical"`(기본값), 행 방향은 `"horizontal"`입니다.

### DIM_LIST

`=PLAIDXL.DIMENSION.DIM_LIST([project_id], [horizontal])`

프로젝트의 차원 이름을 나열합니다.

- `project_id` — 읽을 프로젝트입니다. 기본값은 통합 문서의 프로젝트입니다.
- `horizontal` — 행 방향으로 나열하려면 `TRUE`입니다. 기본값은 열 방향인 `FALSE`입니다.

## 테이블

### GET_TABLE

`=PLAIDXL.TABLE.GET_TABLE(table_name, [project_id], [limit])`

테이블의 행을 머리글 행과 함께 수식이 있는 셀에서 펼쳐 반환합니다. 빈 값은 빈 셀로 반환됩니다.

- `table_name` — PlaidCloud에서의 테이블 이름입니다.
- `project_id` — 읽을 프로젝트입니다. 기본값은 통합 문서의 프로젝트입니다.
- `limit` — 반환할 최대 행 수입니다. 기본값은 머리글 행 아래에 워크시트가 담을 수 있는 최대 행 수인 1,048,575입니다.

`GET_TABLE`은 모든 열을 반환합니다. 열을 선택하거나 행을 필터링하려면 대신 [작업 창에서 테이블을 가져오십시오](/ko/reference/cli/plaidxl/retrieve/#테이블-가져오기).

## 계층

### GET_DIMENSION

`=PLAIDXL.DIMENSION.GET_DIMENSION(dimension_name, start_node, [hierarchy], [orientation], [generation_limit])`

`start_node`에서 시작하여 하위 노드까지 내려가며 차원의 노드를 배치합니다. 각 세대는 상위 세대보다 공백 네 칸만큼 더 들여쓰기되며, Excel 윤곽선 그룹으로 각 레벨을 접거나 펼 수 있습니다.

- `dimension_name` — 차원의 이름 또는 프로젝트 내 경로입니다.
- `start_node` — 시작할 노드입니다(예: 차원의 루트).
- `hierarchy` — 따를 [대체 계층](/ko/guides/dimensions/dimensions/#대체특성-계층)입니다. 기본값은 `"main"`입니다.
- `orientation` — 노드를 열 방향으로 나열하려면 `"vertical"`(기본값), 행 방향으로 나열하려면 `"horizontal"`입니다.
- `generation_limit` — `start_node`를 첫 번째로 세어 반환할 세대 수입니다. `2`는 시작 노드와 그 하위 노드를 반환합니다. 생략하면 모든 세대를 반환합니다.

### DRILL

`=PLAIDXL.DRILL(dimension_name, start_node, drill_key, [hierarchy])`

`start_node`와 `drill_key`가 요청하는 그 아래의 노드를 열 방향으로 반환하며, 세대별로 들여쓰기되고 Excel 윤곽선으로 그룹화됩니다.

- `dimension_name` — 차원의 이름 또는 프로젝트 내 경로입니다.
- `start_node` — 드릴을 시작할 노드입니다.
- `drill_key` — 드릴할 범위로, [`DRILL_KEY`](#drill_key)에서 지정합니다. 모든 하위 노드, 리프만, 지정한 레벨 수, 또는 세대 범위입니다.
- `hierarchy` — 따를 대체 계층입니다. 기본값은 `"main"`입니다.

예를 들어 `=PLAIDXL.DRILL("Region", "Total", PLAIDXL.REPR.DRILL_KEY("leaves"))`는 **Total** 다음에 그 아래의 모든 리프 리전을 나열합니다.

[리본의 확장 명령](/ko/reference/cli/plaidxl/ribbon/#드릴-함수)은 수식을 작성하지 않고도 두 셀에 입력한 차원과 노드에 대해 동일한 작업을 수행합니다.

## 값

`CELL`과 `CELLS`는 테이블의 숫자 열인 측정값을, 하나 이상의 차원에서 선택한 노드로 롤업하여 계산합니다. 각 호출을 보고서의 교차 지점 하나로 생각하십시오. **FY2026**의 **EMEA**에 대한 **Revenue**와 같습니다.

아래의 구성 요소 함수로 교차 지점을 설명한 다음, 보통 각각 별도의 셀에 두고, 그 셀들을 순서에 상관없이 `CELL` 또는 `CELLS`에 전달합니다.

| 인수 | 만드는 함수 | 필수 여부 |
|---|---|---|
| 읽을 테이블 | [`TABLE_REPR`](#table_repr) | 정확히 하나 |
| 집계할 열 | `CELL`은 [`MEASURE`](#measure), `CELLS`는 [`MEASURES`](#measures) 또는 여러 개의 `MEASURE` 셀 | 예 |
| 집계 방식 | [`MEASURE_TYPE`](#measure_type) | 아니요 — 기본값은 `sum` |
| 열에 대한 필터 | [`DIMENSION_REPR`](#dimension_repr) | 최소 하나, 열당 하나 |

각 필터는 **테이블의 열**과 값을 지정합니다. 해당 열이 PlaidCloud에서 차원에 연결되어 있으면 값은 노드이며, 필터에는 차원의 기본 계층에서 해당 노드로 롤업되는 모든 항목이 포함됩니다. 지리 차원에 연결된 **Region** 열에서 노드 **EMEA**는 그 아래의 모든 국가를 포함합니다. 차원에 연결되지 않은 열에서는 필터가 값과 정확히 일치하는 항목을 찾습니다.

이 페이지의 예제는 **Region** 열과 **Period** 열이 차원에 연결된 테이블을 사용합니다. 사용하는 테이블의 열 이름을 사용하십시오.

### CELL

`=PLAIDXL.CELL(table, measure, [measure_type], node, [node], ...)`

숫자 하나를 반환합니다. 전달한 모든 노드에 속하는 행에 걸쳐 집계된 측정값입니다.

```text
A1  =PLAIDXL.REPR.TABLE_REPR("Sales")
A2  =PLAIDXL.REPR.MEASURE("revenue")
A3  =PLAIDXL.REPR.MEASURE_TYPE("sum")
A4  =PLAIDXL.REPR.DIMENSION_REPR("Region", "EMEA")
A5  =PLAIDXL.REPR.DIMENSION_REPR("Period", "FY2026")
B1  =PLAIDXL.CELL(A1, A2, A3, A4, A5)
```

`B1`에는 FY2026 EMEA의 총 revenue가 표시됩니다.

`CELL` 수식으로 가득 찬 시트도 빠르게 다시 계산됩니다. 다시 계산에서 같은 테이블의 많은 값을 요청하면 PlaidXL은 셀마다 요청하지 않고 한꺼번에 PlaidCloud로 보냅니다. 값을 계산할 수 없으면 셀에 `#VALUE!`가 표시되고, 셀 위에 마우스를 올리면 테이블에 없는 필터 열이나 멤버가 없는 노드처럼 PlaidCloud가 보고한 이유가 표시됩니다. `CELLS`는 전체 결과에 대해 첫 번째 이유를 표시합니다.

### CELLS

`=PLAIDXL.CELLS(table, measures, [measure_type], node, [node], ...)`

`CELL`과 같지만 여러 측정값을 한 번에 처리합니다. 측정값마다 숫자 하나를 나열한 순서대로 열 방향으로 반환합니다.

```text
D1:F1  revenue | cost | units
D2     =PLAIDXL.REPR.MEASURES(D1:F1)
B2     =PLAIDXL.CELLS(A1, D2#, A3, A4, A5)
```

`D2#`은 `MEASURES`의 펼쳐진 결과 전체를 전달합니다. `B2:B4`에는 FY2026 EMEA의 revenue, cost, units가 표시됩니다.

## 구성 요소

이 함수들은 데이터를 직접 읽지 않습니다. 각 함수는 계산의 한 부분을 설명하는 짧은 텍스트를 반환하며, `CELL`, `CELLS`, `DRILL`에 전달할 수 있습니다. 참조할 셀에 두면 하나만 변경해도(예: 다른 기간) 이를 사용하는 모든 수식이 업데이트됩니다.

### TABLE_REPR

`=PLAIDXL.REPR.TABLE_REPR(table_name)`

`CELL`과 `CELLS`가 읽는 테이블로, 선택한 프로젝트에서의 이름으로 지정합니다.

### MEASURE

`=PLAIDXL.REPR.MEASURE(column_name)`

`CELL`이 집계하는 숫자 열입니다.

### MEASURES

`=PLAIDXL.REPR.MEASURES(column_names)`

`CELLS`용 여러 측정값 열로, 열 이름이 들어 있는 셀 범위에서 가져옵니다. 결과는 열마다 셀 하나씩 펼쳐지며, `D2#`처럼 스필 연산자를 사용하여 `CELLS`에 전달합니다.

### MEASURE_TYPE

`=PLAIDXL.REPR.MEASURE_TYPE(agg_function)`

측정값을 집계하는 방식입니다. `agg_function`은 다음 중 하나이며 소문자로 입력합니다.

| 값 | 반환 값 |
|---|---|
| `sum` | 합계(측정값 유형을 전달하지 않았을 때의 기본값) |
| `mean` | 평균 |
| `median` | 중앙값 |
| `min` | 최솟값 |
| `max` | 최댓값 |
| `std` | 표준 편차 |
| `var` | 분산 |

### DIMENSION_REPR

`=PLAIDXL.REPR.DIMENSION_REPR(dimension_name, start_node)`

`CELL`과 `CELLS`용 필터입니다. 필터링할 각 열마다 하나씩 전달합니다.

- `dimension_name` — **테이블에 있는 열**의 이름으로, `"Region"`처럼 차원의 값이 들어 있는 열입니다. 열 이름과 정확히 일치해야 하며, 테이블에 없는 열은 오류를 반환합니다.
- `start_node` — 롤업할 노드입니다(예: `"EMEA"`). 차원에 연결되지 않은 열에서는 일치시킬 값입니다.

그리드를 만들려면 노드에 셀을 참조하십시오. `=PLAIDXL.REPR.DIMENSION_REPR("Region", $A7)`. 앞뒤 공백은 무시되므로 `DRILL`이 배치한 들여쓰기된 노드 이름을 가리켜도 됩니다.

### DRILL_KEY

`=PLAIDXL.REPR.DRILL_KEY(d_key)`

[`DRILL`](#drill)이 시작 노드 아래로 내려가는 범위입니다. `d_key`는 일반 텍스트이며, 단어 형식이거나 직접 작성한 드릴 키입니다.

| `d_key` | 드릴 범위 |
|---|---|
| `"all"` | 모든 하위 노드 |
| `"leaves"` | 리프만, 즉 아래에 노드가 없는 노드 |
| `"1 level"`, `"2 levels"`, … | 해당 세대 수만큼 아래로 |
| `">[...]"` | 다음 표와 같이 직접 작성한 드릴 키 |

숫자는 아라비아 숫자로 작성하십시오. `"two levels"`가 아니라 `"2 levels"`입니다. 앞에 오는 `drill`은 무시되므로 `"drill 2 levels"`도 작동합니다.

직접 작성한 키는 시작 노드를 기준으로 아래로 내려가는 세대 수를 계산하며, 시작 노드는 세대 0이고 항상 포함됩니다. 음수는 각 브랜치의 리프에서 위로 세므로 들쭉날쭉한 계층도 예상대로 작동합니다.

| 키 | 포함 항목 |
|---|---|
| `>[*]` 또는 `>[:]` | 모든 노드 |
| `>[]` 또는 `>[-1]` | 리프만 |
| `>[n]` | 시작 노드와 그 아래 `n`세대. `>[0]`은 시작 노드만입니다. |
| `>[a:]` | 시작 노드, 그리고 세대 `a`와 그 아래 모든 항목 |
| `>[a:b]` | 시작 노드, 그리고 세대 `a`부터 `b - 1`까지 |
| `>[0:-k]` | 시작 노드와 아래에 `k`세대 이상이 있는 모든 노드로, 각 브랜치의 마지막 `k`세대는 제외됩니다. `>[0:-1]`은 리프를 제외한 모든 노드입니다. |
| `>[a:-k]` | 동일하지만 세대 `a`에서 시작 |

`A`가 하위 노드 `B`, `C`, `D`를 가지고, `B`는 `B1`과 `B2`를, `C`는 `C1`을 가지는 계층의 경우:

| 키 | 결과 |
|---|---|
| `>[1]` | `A`, `B`, `C`, `D` |
| `>[2]` | `A`, `B`, `B1`, `B2`, `C`, `C1`, `D` |
| `>[]` | `A`, `B1`, `B2`, `C1`, `D` |
| `>[0:-1]` | `A`, `B`, `C` |
| `>[2:]` | `A`, `B1`, `B2`, `C1` |

노드는 각각 자신의 상위 노드 아래에 계층 순서대로 나열되며, Excel 윤곽선 그룹도 같은 순서를 따릅니다. 키 안의 공백은 무시됩니다. 이러한 형식 중 어느 것과도 일치하지 않는 키는 유효한 형식을 나열하는 오류를 반환합니다.

<Aside type="caution">
`>[-1]`과 `>[0:-1]`은 이전 버전의 PlaidXL에서와 의미가 다르며, 이전에는 반대로 동작했습니다. 이제 `>[-1]`은 리프만 반환하고 `>[0:-1]`은 리프를 제외한 모든 항목을 반환합니다. 드릴 키를 직접 작성한 통합 문서는 검토하십시오. 단어 형식인 `"all"`, `"leaves"`, `"2 levels"`는 변경되지 않았습니다.
</Aside>

<Aside type="note">
`CELL`, `CELLS`, `DRILL`은 이러한 구성 요소 함수의 출력을 기대합니다. 텍스트를 직접 입력하지 말고 각 인수를 해당 함수로 만드십시오.
</Aside>

## 작업 창에서 수식 삽입

작업 창의 **Formulas** 탭에서 수식을 대신 작성합니다. **What do you want in the cell?** 옵션에서 다음 중 하나를 선택합니다.

- **A whole table**(`GET_TABLE`) — 테이블을 선택하거나 입력하고, 선택적으로 최대 행 수를 지정합니다.
- **One number**(`CELL`) — 테이블을 선택하거나 입력하고, **Column to total**과 **How to combine the values**를 선택합니다.
- **A list of dimension nodes**(`DRILL`) — 차원과 시작 노드를 선택하거나 입력하고, **All levels**, **Lowest level only** 또는 **Down** 레벨 수(**levels**)를 선택하며, 선택적으로 **대체 계층**을 지정합니다.

**Formula** 미리 보기에는 필드를 채우는 동안 결과가 표시됩니다. 선택한 셀에 넣으려면 **Insert in active cell**을 클릭하고, 직접 붙여 넣으려면 **복사**를 클릭합니다. **테이블** 탭에서 테이블을 선택하거나 **차원** 탭에서 차원을 선택하면 해당 필드가 채워집니다.
