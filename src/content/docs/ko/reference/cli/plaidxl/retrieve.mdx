[로그인](/ko/reference/cli/plaidxl/connect/)하면 작업 창에 프로젝트 목록이 표시됩니다. 프로젝트를 선택한 다음 해당 프로젝트의 테이블과 차원을 통합 문서로 가져옵니다.

## 프로젝트 선택

작업 창 머리글에는 워크스페이스와 이 통합 문서에 연결된 프로젝트가 표시됩니다. 프로젝트 이름을 클릭하면 PlaidCloud와 같은 폴더 구조로 열 수 있는 모든 프로젝트가 나열된 프로젝트 목록이 열립니다. 폴더는 처음에 접혀 있으며, 클릭하여 펼치거나 **Filter projects by name**에 입력하여 목록을 좁힐 수 있습니다. 워크스페이스에서 열 수 있는 프로젝트가 하나뿐이면 PlaidXL이 통합 문서를 해당 프로젝트에 자동으로 연결하며, 머리글에 프로젝트와 함께 **Linked to**가 표시되고 그 옆에 **change**가 표시됩니다.

프로젝트를 클릭하여 선택합니다. 프로젝트의 테이블은 **테이블** 탭에, 차원은 **차원** 탭에 표시됩니다.

### 프로젝트는 통합 문서에 속합니다

선택한 프로젝트는 통합 문서에 저장되므로 통합 문서마다 고유한 프로젝트를 가집니다. 이 프로젝트는 해당 통합 문서에서 PlaidXL [사용자 지정 함수](/ko/reference/cli/plaidxl/functions/)와 드릴 명령이 데이터를 읽어 오는 프로젝트입니다. 통합 문서 두 개를 열면 각각 자신의 프로젝트에서 읽어 오며, 통합 문서를 다시 열면 작업 창이 해당 프로젝트로 돌아갑니다. 프로젝트는 파일과 함께 전달되므로, 파일을 열고 해당 프로젝트에 대한 액세스 권한으로 로그인하는 누구에게나 적용됩니다.

프로젝트는 하나의 워크스페이스에 속합니다. [워크스페이스를 전환](/ko/reference/cli/plaidxl/connect/#로그아웃-또는-워크스페이스-전환)하면 이전 워크스페이스의 프로젝트에 연결되어 있던 통합 문서는 프로젝트를 다시 선택할 때까지 프로젝트가 없는 상태가 됩니다. 이전 워크스페이스에서 가져온 테이블과 차원은 통합 문서에 남아 있지만 새로 고치거나 저장되지 않습니다. **Refresh All Tables**는 다른 워크스페이스의 테이블 또는 차원이 새로 고쳐지지 않았다고 알려 줍니다. 새 워크스페이스에서 다시 가져오면 연결됩니다.

## 테이블 가져오기

1. **테이블** 탭에서 테이블을 클릭합니다. 목록이 길면 **Filter tables by name**을 사용하여 찾습니다. 각 테이블 옆의 **행**과 **열**로 테이블의 크기를 알 수 있습니다.
2. **열**에서 필요하지 않은 열의 확인란을 선택 해제합니다. 처음에는 모든 열이 선택되어 있습니다.
3. 일부 행만 가져오려면 **고급**을 선택하고 필터를 만듭니다. [행 필터링](#행-필터링)을 참조하십시오.
4. **Select where to place this table**에서 다음 중 하나를 선택합니다.
   - **Matching Worksheet** — 테이블 이름을 딴 워크시트의 A1 셀부터 배치합니다. 시트가 없으면 PlaidXL이 만듭니다.
   - **Current Selection** — 활성 시트에서 선택한 셀부터 배치합니다.
5. **Retrieve Table**을 클릭합니다.

데이터는 PlaidCloud 테이블 이름을 딴 Excel 테이블로 들어오므로, 이를 참조하는 수식, 피벗 테이블, 차트는 데이터가 늘어나거나 줄어드는 대로 따라갑니다. 숫자, 날짜, 시간에는 데이터 형식에 맞는 서식 또는 PlaidCloud에서 열에 지정한 숫자 서식이 적용됩니다. 텍스트 열은 텍스트로 서식이 지정되므로 `0012` 같은 코드도 앞의 0이 유지됩니다. 테이블을 처음 가져올 때는 머리글 행이 고정되고 열 너비가 내용에 맞게 조정됩니다.

테이블이 들어갈 셀에 PlaidXL 테이블이 아닌 다른 내용이 이미 있으면, PlaidXL은 대신 새 시트에 테이블을 배치하고 위치를 알려 줍니다. 테이블이 PlaidXL이 관리하지 않는 Excel 테이블의 일부와 겹치게 되는 경우에는 아무것도 변경되지 않으며, 메시지에 **Move that Table or convert it to a range, then try again.** 메시지가 표시됩니다.

이미 시트에 있는 테이블을 다시 가져오면 제자리에서 새로 고쳐집니다. 직접 추가한 열은 그대로 유지되고, 선택 해제한 원본 열은 머리글만 남고 그 아래 셀은 비워집니다.

Excel이 정확하게 저장할 수 없을 만큼 큰 정수 ID(9,007,199,254,740,991 초과)와 1900년 3월 1일 이전 날짜는 텍스트로 들어오므로 정확하게 표시되고 그대로 다시 저장됩니다.

워크시트 이름을 지을 때 PlaidXL은 일반 영문자(A–Z), 숫자, 밑줄, 공백만 남기고, 공백을 밑줄로 바꾸며, Excel의 제한인 31자로 이름을 자릅니다. **Q3 Revenue (EMEA)** 테이블은 `Q3_Revenue_EMEA` 시트로, **sales_2024** 테이블은 `sales_2024` 시트로 가져옵니다. 악센트 문자는 제거됩니다.

대용량 테이블은 웹용 Excel과 최신 데스크톱 Excel에서 훨씬 빠르게 가져옵니다. 70,000행 17열 테이블은 웹에서 약 15~20초가 걸리고, 143,000행 77열 테이블은 예전에 10분 넘게 걸리던 것이 약 1분 걸립니다. 이전 버전의 Excel에서도 작동하지만 이러한 속도 향상은 적용되지 않습니다. 열 너비는 머리글과 처음 몇 행에 맞게 조정됩니다.

<Aside type="tip">열이 많은 테이블은 Excel로 불러오는 속도가 가장 느립니다. 필요하지 않은 열을 선택 해제하면 대용량 테이블을 가장 빠르게 가져올 수 있습니다.</Aside>

### Excel 셀보다 긴 텍스트

Excel 셀에는 최대 32,767자까지 담을 수 있으므로 이보다 긴 텍스트는 잘려서 표시됩니다. 테이블에 이러한 텍스트가 있으면 작업 창에 어느 테이블의 어느 열에 Excel 셀의 한도인 32,767자보다 긴 텍스트가 있으며 Excel에서 잘려 표시된다는 메시지가 표시되고, 해당 테이블은 저장이 꺼집니다. 저장하면 PlaidCloud에서도 텍스트가 잘리므로 **Save to PlaidCloud**는 해당 테이블의 저장을 거부합니다.

### 빨간색으로 표시되는 테이블

테이블의 행이 1,048,575개를 초과하거나 열이 16,384개를 초과하는 경우, 또는 아직 로드된 적이 없는 테이블처럼 PlaidCloud가 크기를 보고할 수 없는 경우에는 테이블이 빨간색으로 표시되며 **Too large for an Excel worksheet**라는 도구 설명이 나타납니다. 이 경우에도 가져올 수 있습니다. 한 워크시트에 들어가지 않는 행은 첫 번째 시트 이름 뒤에 ` (2)`, ` (3)` 등을 붙인 다음 시트에 이어서 배치됩니다. 여러 시트로 나뉜 테이블은 PlaidCloud에 다시 저장할 수 없으므로, 편집하려는 경우 **고급**으로 행을 필터링하고 열을 선택 해제하여 한 시트에 들어가도록 하십시오.

## 행 필터링

**고급**을 선택하면 필터 작성기가 열립니다. 각 규칙은 열, **같음**, **in**, **포함**, **시작 문자**, **비어 있음** 같은 비교 방식, 값을 선택합니다. 규칙을 결합하려면 **AND** 그룹, **OR** 그룹 또는 둘 다를 사용합니다.

필터는 값을 텍스트로 비교하므로 정확한 값과 텍스트 패턴과 일치시킬 수 있습니다. 숫자나 날짜 범위는 사용할 수 없습니다. 범위를 가져오려면 **in**으로 필요한 값을 필터링하거나, 테이블을 가져온 다음 Excel에서 필터링하십시오.

- 값은 따옴표 없이 입력합니다. `"EMEA"`가 아니라 `EMEA`로 입력합니다.
- **in**처럼 여러 값을 받는 비교에서는 쉼표와 공백으로 값을 구분합니다. 예: `EMEA, APAC, NA`.

필터는 **고급**을 선택한 동안에만 적용됩니다. PlaidXL은 가져온 각 테이블에 대해 필터와 선택한 열을 기억하고 새로 고칠 때 다시 사용합니다. **AND**로 연결된 **같음** 및 **in** 규칙으로만 구성된 필터는 [저장](#테이블을-plaidcloud에-저장) 시 바뀌는 행도 결정합니다.

## Refresh All Tables

PlaidXL은 통합 문서로 가져온 테이블과 차원의 목록을 유지하며, 각각에 대해 선택한 열과 필터를 적용하여 새로 고칩니다. 이 목록은 통합 문서에 저장되므로, 파일을 열고 같은 프로젝트에 대한 액세스 권한으로 로그인하는 누구나 새로 고침을 사용할 수 있습니다.

- 작업 창의 **Refresh This Sheet**는 활성 시트의 테이블을 새로 고칩니다.
- 작업 창의 **Refresh All Tables**는 통합 문서의 모든 테이블과 차원을 새로 고칩니다.
- 리본의 **새로 고침** 메뉴에서도 시트, 선택 영역 또는 모든 테이블을 새로 고치고 PlaidXL 수식을 다시 계산할 수 있습니다. [새로 고침](/ko/reference/cli/plaidxl/ribbon/#새로-고침)을 참조하십시오.

새로 고치는 동안 작업 창에는 각 테이블의 진행률(PlaidCloud 쿼리 후 기록된 행의 비율)이 **취소** 버튼과 함께 표시됩니다. 테이블은 한 번에 세 개씩 새로 고쳐지며, 다른 새로 고침을 시작하면 이미 실행 중인 새로 고침에 추가됩니다. 완료되면 창에 각 테이블의 행 수 또는 실패 사유가 나열됩니다. 목록에서 테이블을 클릭하면 해당 테이블이 선택됩니다. 한 테이블이 실패해도 다른 테이블은 계속 진행됩니다.

**취소**하면 통합 문서가 새로 고침 이전 상태로 유지됩니다. 테이블의 데이터는 모든 행이 도착한 후에만 바뀝니다. StarRocks 테이블에서는 PlaidCloud의 쿼리도 중지되며, Databend나 Snowflake 같은 다른 엔진에서는 PlaidXL이 기다리기를 중단하지만 PlaidCloud에서 쿼리는 중지되지 않습니다. 데이터를 기록하는 동안 Excel 계산은 일시 중지되었다가 마지막에 한 번 실행됩니다.

### 새로 고침 시 유지되는 항목

테이블은 현재 위치와 관계없이 같은 Excel 테이블로 새로 고쳐집니다. **Current Selection**으로 가져온 테이블은 Excel 테이블을 옮기거나 이름을 바꾼 후에도 해당 시트의 원래 셀에서 새로 고쳐집니다. Excel 테이블은 새 데이터에 맞게 늘어나거나 줄어들고, 이전에 더 큰 테이블을 가져왔을 때 남은 행과 열은 지워집니다.

- **직접 추가한 열** — Excel 테이블 안에서 데이터 옆에 추가한 열은 유지됩니다. 모든 행에서 같은 수식은 새 행까지 아래로 채워집니다. 메모 같은 다른 값은 PlaidCloud 테이블에 키 열이 있으면 해당 행을 따라가며, 사라진 행의 메모는 테이블 아래에 보관됩니다. 키 열이 없으면 메모는 위치를 기준으로 제자리에 유지됩니다.
- **서식** — 열에 지정한 숫자 서식은 유지됩니다.

다른 셀이나 해당 테이블 소유가 아닌 Excel 테이블 위로 확장되는 새로 고침은 아무것도 변경하지 않으며 **Move what is there, then try again.** 메시지가 표시됩니다. 행이 도착하는 동안 Excel 테이블이 변경된 경우에는 다시 시도하라는 메시지가 표시됩니다.

테이블의 워크시트가 삭제된 경우 해당 테이블은 건너뛰며 PlaidXL에서 **Recreate sheet** 또는 **Stop refreshing**을 선택할 수 있습니다.

Excel이 최종 쓰기의 일부를 거부하면 창에 테이블이 일부만 기록되었다는 메시지가 사유와 함께 표시되고, 저장하기 전에 새로 고치라는 안내가 나옵니다. 새로 고침이 성공할 때까지 **Save to PlaidCloud**는 해당 테이블을 거부합니다.

### 새로 고침 목록에서 테이블 제거

**On this sheet** 아래에는 활성 시트로 가져온 각 테이블과 차원이 행 수 및 마지막으로 새로 고친 시점과 함께 작업 창에 나열됩니다. 새로 고침 목록에서 제거하려면 **Stop refreshing**을 클릭합니다. 데이터는 시트에 그대로 남으며, 메시지에 **실행 취소** 옵션이 표시됩니다.

목록에 이미 있는 테이블 위에 다시 가져오면 목록의 항목이 대체되므로, 테이블을 몇 번을 가져오든 한 번만 새로 고쳐집니다. 각 테이블 옆의 **복사**를 누르면 수식에서 사용할 Excel 테이블 이름이 복사됩니다.

## 차원 가져오기

**차원** 탭에는 프로젝트의 [차원](/ko/guides/dimensions/dimensions/)이 나열됩니다.

1. 차원을 클릭합니다. **Filter dimensions by name**을 사용하여 찾을 수 있습니다.
2. **Select where to place this dimension**에서 **Matching Worksheet** 또는 **Current Selection**을 선택합니다.
3. **Retrieve Dimension**을 클릭합니다.

PlaidXL은 차원의 노드를 계층 순서대로 한 열에 기록합니다. 차원에는 열 필터나 행 필터가 없습니다. **Refresh All Tables**는 테이블과 함께 차원도 새로 고칩니다.

들여쓰기와 Excel 윤곽 그룹으로 계층을 배치하거나 특정 노드 또는 대체 계층에서 시작하려면 대신 [드릴 명령](/ko/reference/cli/plaidxl/drill/) 또는 [`PLAIDXL.DRILL`](/ko/reference/cli/plaidxl/functions/#drill)을 사용하십시오. 셀에 멤버 하나를 넣으려면 **차원** 탭에서 **Pick member...** 를 클릭하십시오. [멤버 선택](/ko/reference/cli/plaidxl/drill/#멤버-선택)을 참조하십시오.

## 테이블을 PlaidCloud에 저장

통합 문서로 가져온 테이블은 다시 저장할 수 있으며, 이때 PlaidCloud 테이블의 행이 시트에 있는 내용으로 바뀝니다.

1. 가져온 테이블이 있는 워크시트로 이동합니다. **On this sheet** 아래에 해당 시트로 가져온 각 테이블이 작업 창에 나열됩니다. 테이블이 없으면 먼저 테이블을 가져오라는 안내가 창에 표시됩니다.
2. 테이블 옆의 **Save to PlaidCloud**를 클릭하거나, 리본의 **쓰기** 그룹에서 **Save sheet to PlaidCloud...** 를 클릭하여(**Ctrl+Alt+Shift+W**, Mac에서는 **⌘⌥⇧W**) 시트의 모든 테이블을 저장합니다.

저장은 확인 없이 바로 이루어집니다. 메시지에는 저장된 행 수, 알아 두어야 할 사항이 표시되며 **실행 취소** 옵션이 제공됩니다.

PlaidXL은 테이블의 머리글 행과 그 아래 행을 읽습니다. 머리글은 가져온 열과 여전히 일치해야 하며, 값은 각 열의 데이터 형식으로 변환됩니다. 값을 변환할 수 없으면 아무것도 기록되지 않으며 실패한 행이 나열됩니다. PlaidCloud의 열 정의는 그대로 유지됩니다.

### 저장되는 항목

- 빈 셀은 빈 값으로 저장됩니다.
- `1,5`처럼 쉼표로 쓴 숫자는 15로 읽지 않습니다. 열에 비해 너무 큰 정수는 해당 행에 대해 보고되며, Excel이 잘못 만들어 낸 1900년 2월 29일 날짜는 거부됩니다.
- 가져온 행 사이의 빈 행은 건너뜁니다. 그 아래에서는 첫 번째 빈 행에서 테이블이 끝나며, 그보다 아래에 있는 행은 저장되지 않고 메시지에 해당 행이 명시됩니다.
- 가져오지 않은 열은 PlaidCloud에서 비워지며, 메시지에 해당 열이 명시됩니다.
- 가져온 이후 PlaidCloud에서 테이블이 변경된 경우 저장하면 해당 테이블이 대체되며 메시지에 이 사실이 표시됩니다. 복원 지점에는 이전 내용이 보관됩니다.
- 드릴스루 시트를 저장하는데 가져온 이후 그 노드 아래의 멤버가 변경된 경우 아무것도 기록되지 않으며 **Retrieve again before saving.** 메시지가 표시됩니다. 가져오기나 새로 고침을 하면 시트가 대체되므로, 저장하지 않은 편집 내용이 있으면 먼저 복사해 두십시오.

### 일부 행만 바꾸는 저장

다음 경우에는 저장 시 해당 행만 바뀌고 나머지 테이블은 유지됩니다.

- **테이블을 필터와 함께 가져온 경우** — 필터가 **AND**로 연결된 **같음** 및 **in** 규칙으로 구성되어 있어야 합니다. 필터가 포함하는 행만 바뀌며, 필터 밖에 추가한 행도 저장되고 메시지에 그 개수가 표시됩니다. 그 밖의 필터로 가져온 테이블은 저장할 수 없습니다. 이 경우 해당 필터로 다시 가져오거나 필터 없이 가져오십시오.
- **시트에 [상세 행 표시](/ko/reference/cli/plaidxl/drill/#상세-행-표시)의 상세 행이 표시된 경우** — 해당 값에 속한 행만 바뀝니다.
- **테이블에 대한 액세스가 일부 행으로 제한된 경우** — 볼 수 있는 행만 바뀌므로 다른 사람의 행은 유지됩니다. 시트에 액세스 권한 밖의 행이 있으면 아무것도 저장되지 않으며 메시지에 해당 행이 나열됩니다. 해당 행을 제거한 다음 다시 저장하십시오.

### 저장 실행 취소

PlaidXL은 기록하기 전에 복원 지점을 만듭니다. 저장할 때마다 자체 복원 지점이 7일 동안 유지되므로, 이후에 다시 저장했더라도 각 저장 후 최대 7일 동안 **실행 취소**를 사용할 수 있습니다. 이 기능은 Lakehouse 테이블에 적용됩니다. 쓰기가 실패하면 테이블은 원래대로 복원되고 변경 사항은 시트에 그대로 남습니다. 단, 쓰기가 시작된 후 다른 사람이 테이블을 변경한 경우에는 테이블을 그대로 두며 메시지에 그 사실이 표시됩니다.

저장을 실행 취소하려면 메시지에서 **실행 취소**를 클릭하거나, 리본의 **쓰기** 그룹에서 **Undo last write**를 클릭합니다. 테이블은 저장하기 전 상태로 돌아가며, 일부 행만 바꾼 저장이라면 해당 행만 돌아갑니다. 시트를 새로 고쳐 확인하십시오. [쓰기 실행 취소](/ko/reference/cli/plaidxl/write-values/#쓰기-실행-취소)를 참조하십시오. 저장을 완료할 수도 없고 되돌릴 수도 없는 경우 메시지에 복원 지점이 명시되어 테이블을 복원할 수 있으며, 이때 **실행 취소**는 그 이후 테이블에 이루어진 변경 사항도 덮어씁니다. 복원 지점을 만들 수 없는 테이블도 저장은 되며, 메시지에 해당 저장을 실행 취소할 수 없다고 표시됩니다.

쓰기를 실행한 사용자와 워크스페이스만 해당 쓰기를 실행 취소할 수 있습니다.
