[로그인](/ko/reference/cli/plaidxl/connect/)하면 작업 창에 프로젝트 목록이 표시됩니다. 프로젝트를 선택한 다음 해당 프로젝트의 테이블과 차원을 워크북으로 가져옵니다.

## 프로젝트 선택

작업 창 머리글에는 워크스페이스와 이 워크북이 연결된 프로젝트가 표시됩니다. 프로젝트 이름을 클릭하면 PlaidCloud에서 보는 것과 같은 폴더 구조로 열 수 있는 모든 프로젝트가 표시되는 프로젝트 목록이 열립니다. 폴더는 접힌 상태로 시작하며, 폴더를 클릭하여 열거나 **Filter projects by name**에 입력하여 목록을 좁힐 수 있습니다. 워크스페이스에서 열 수 있는 프로젝트가 하나뿐이면 PlaidXL이 워크북을 해당 프로젝트에 자동으로 연결하며, 머리글에 프로젝트와 함께 **Linked to**가 표시되고 그 옆에 **change**가 표시됩니다.

프로젝트를 클릭하여 선택합니다. 해당 프로젝트의 테이블은 **테이블** 탭에, 차원은 **차원** 탭에 표시됩니다.

### 프로젝트는 워크북에 속합니다

선택한 프로젝트는 워크북에 저장되므로 각 워크북은 자체 프로젝트를 가집니다. 해당 워크북에서 PlaidXL [사용자 지정 함수](/ko/reference/cli/plaidxl/functions/)와 드릴 명령이 읽는 프로젝트입니다. 워크북 두 개를 열면 각각 자신의 프로젝트에서 읽으며, 워크북을 다시 열면 작업 창이 해당 워크북의 프로젝트로 돌아갑니다. 프로젝트는 파일과 함께 이동하므로, 파일을 열고 해당 프로젝트에 액세스할 수 있는 계정으로 로그인한 모든 사용자에게 적용됩니다.

프로젝트는 하나의 워크스페이스에 속합니다. [워크스페이스를 전환](/ko/reference/cli/plaidxl/connect/#로그아웃-또는-워크스페이스-전환)하면 이전 워크스페이스의 프로젝트에 연결된 워크북은 프로젝트를 선택하기 전까지 프로젝트가 없는 상태가 됩니다. 이전 워크스페이스에서 가져온 테이블과 차원은 워크북에 남아 있지만 새로 고쳐지거나 저장되지 않습니다. **Refresh All Tables**는 다른 워크스페이스의 테이블 또는 차원이 새로 고쳐지지 않았다고 알려 줍니다. 새 워크스페이스에서 다시 가져와 연결하십시오.

## 테이블 가져오기

1. **테이블** 탭에서 테이블을 클릭합니다. 목록이 길면 **Filter tables by name**을 사용하여 찾습니다. 각 테이블 옆의 **행**과 **열**은 테이블의 크기를 알려 줍니다.
2. **열** 아래에서 필요하지 않은 열의 확인란을 선택 해제합니다. 처음에는 모든 열이 선택되어 있습니다.
3. 일부 행만 가져오려면 **고급**을 선택하고 필터를 만듭니다. [행 필터링](#행-필터링)을 참조하십시오.
4. **Select where to place this table** 아래에서 다음 중 하나를 선택합니다.
   - **Matching Worksheet** — 테이블 이름을 딴 워크시트이며 A1 셀부터 시작합니다. 시트가 없으면 PlaidXL이 만듭니다.
   - **Current Selection** — 활성 시트에서 선택한 셀부터 시작합니다.
5. **Retrieve Table**을 클릭합니다.

데이터는 PlaidCloud 테이블의 이름을 딴 Excel 표로 들어오므로, 이를 참조하는 수식, 피벗 테이블, 차트가 데이터의 증가나 감소를 따라갑니다. 숫자, 날짜, 시간에는 데이터 형식에 맞는 서식 또는 PlaidCloud의 열에 설정된 숫자 서식이 적용됩니다. 텍스트 열은 텍스트로 서식이 지정되므로 `0012` 같은 코드가 앞의 0을 유지합니다. 테이블을 처음 가져올 때는 머리글 행이 고정되고 열 너비가 내용에 맞게 조정됩니다.

테이블이 들어갈 셀에 PlaidXL 테이블이 아닌 내용이 이미 있으면 PlaidXL은 대신 새 시트에 테이블을 넣고 위치를 알려 줍니다.

워크시트 이름을 정할 때 PlaidXL은 일반 문자(A–Z), 숫자, 밑줄, 공백만 유지하고 공백을 밑줄로 바꾸며 이름을 Excel의 제한인 31자로 자릅니다. **Q3 Revenue (EMEA)** 라는 테이블은 `Q3_Revenue_EMEA` 시트로, **sales_2024**는 `sales_2024`로 가져옵니다. 악센트가 있는 문자는 제거됩니다.

<Aside type="tip">너비가 넓은 테이블은 Excel로 로드하는 데 시간이 오래 걸립니다. 필요하지 않은 열을 선택 해제하는 것이 큰 테이블을 더 빠르게 가져오는 가장 빠른 방법입니다.</Aside>

### 빨간색으로 표시되는 테이블

테이블에 행이 1,048,575개를 초과하거나 열이 16,384개를 초과하는 경우, 또는 한 번도 로드된 적이 없는 테이블처럼 PlaidCloud가 크기를 보고할 수 없는 경우 테이블이 빨간색으로 표시되고 **Too large for an Excel worksheet**라는 툴팁이 나타납니다. 이런 테이블도 가져올 수 있습니다. 한 워크시트에 들어가지 않는 행은 다음 워크시트에 이어지며, 시트 이름은 첫 번째 이름에 ` (2)`, ` (3)` 등을 붙인 것입니다. 여러 시트로 나뉜 테이블은 PlaidCloud에 다시 저장할 수 없으므로, 편집할 계획이라면 **고급**으로 행을 필터링하고 열을 선택 해제하여 한 시트에 들어가도록 하십시오.

## 행 필터링

**고급**을 선택하면 필터 빌더가 열립니다. 각 규칙은 열, **equal**, **in**, **contains**, **begins with**, **is empty** 같은 비교, 값을 선택합니다. **AND** 그룹, **OR** 그룹 또는 둘 다를 사용하여 규칙을 결합합니다.

필터는 값을 텍스트로 비교하므로 정확한 값과 텍스트 패턴과 일치합니다. 숫자나 날짜의 범위는 사용할 수 없습니다. 범위를 가져오려면 **in**으로 필요한 값을 필터링하거나, 테이블을 가져온 다음 Excel에서 필터링하십시오.

- 값은 따옴표 없이 입력합니다. `"EMEA"`가 아니라 `EMEA`입니다.
- **in**처럼 여러 값을 받는 비교에서는 값을 쉼표와 공백으로 구분합니다. `EMEA, APAC, NA`입니다.

필터는 **고급**이 선택되어 있는 동안에만 적용됩니다. PlaidXL은 가져온 각 테이블마다 필터와 선택한 열을 기억하고 새로 고칠 때 다시 사용합니다. **AND**로 연결된 **equal** 및 **in** 규칙으로만 만든 필터는 [저장](#테이블을-plaidcloud에-저장) 시 바뀌는 행도 결정합니다.

## 모든 테이블 새로 고침

PlaidXL은 워크북으로 가져온 테이블과 차원의 목록을 유지하며, 각각에 대해 선택한 열과 필터로 새로 고칩니다. 목록은 워크북에 저장되므로 파일을 열고 같은 프로젝트에 액세스할 수 있는 계정으로 로그인한 모든 사용자가 새로 고칠 수 있습니다.

- 작업 창의 **Refresh This Sheet**는 활성 시트의 테이블을 새로 고칩니다.
- 작업 창의 **Refresh All Tables**는 워크북의 모든 테이블과 차원을 새로 고칩니다.
- 리본의 **새로 고침** 메뉴도 시트, 선택 영역, 모든 테이블을 새로 고치고 PlaidXL 수식을 다시 계산합니다. [새로 고침](/ko/reference/cli/plaidxl/ribbon/#새로-고침)을 참조하십시오.

새로 고침이 실행되는 동안 작업 창에는 테이블별 진행률(PlaidCloud 쿼리, 그다음 기록된 행의 비율)이 **취소** 버튼과 함께 표시됩니다. 한 번에 세 개의 테이블이 새로 고쳐지며, 다른 새로 고침을 시작하면 이미 실행 중인 새로 고침에 추가됩니다. 새로 고침이 끝나면 창에 각 테이블이 행 수와 함께, 실패한 경우 그 이유와 함께 나열됩니다. 목록에서 테이블을 클릭하면 선택됩니다. 한 테이블이 실패해도 다른 테이블은 중단되지 않습니다.

**취소**하면 워크북은 새로 고침 이전 상태로 유지됩니다. 테이블의 데이터는 모든 행이 도착한 후에야 교체되기 때문입니다. StarRocks 테이블에서는 PlaidCloud의 쿼리가 중지되며, Databend나 Snowflake 같은 다른 엔진에서는 PlaidXL이 기다리기를 멈추지만 PlaidCloud의 쿼리는 중지되지 않습니다. 데이터를 쓰는 동안 Excel의 계산은 일시 중지되었다가 마지막에 한 번 실행됩니다.

### 새로 고침 시 유지되는 항목

테이블은 현재 어디에 있든 같은 Excel 표로 새로 고쳐집니다. **Current Selection**으로 가져온 테이블은 Excel 표를 이동하거나 이름을 바꾸더라도 자신의 시트에서 자신의 셀에 새로 고쳐집니다. 표는 새 데이터에 맞게 늘어나거나 줄어들고, 더 큰 이전 가져오기에서 남은 행과 열은 지워집니다.

- **사용자가 추가한 열** — Excel 표 안에서 데이터 옆에 추가한 열은 유지됩니다. 모든 행에서 동일한 수식은 새 행으로 채워집니다. 메모 같은 다른 값은 PlaidCloud의 테이블에 키 열이 있으면 해당 행을 따라가며, 사라진 행의 메모는 표 아래에 보관됩니다. 키 열이 없으면 메모는 위치를 기준으로 제자리에 남습니다.
- **사용자가 지정한 서식** — 열에 설정한 숫자 서식은 유지됩니다.

테이블의 워크시트가 삭제된 경우 테이블은 건너뛰며 PlaidXL이 **Recreate sheet** 또는 **Stop refreshing**을 제안합니다.

### 새로 고침 목록에서 테이블 제거

**On this sheet** 아래에서 작업 창은 활성 시트로 가져온 각 테이블과 차원을 행 수 및 마지막 새로 고침 시점과 함께 나열합니다. **Stop refreshing**을 클릭하면 새로 고침 목록에서 제거됩니다. 데이터는 시트에 남아 있으며 메시지에 **실행 취소**가 표시됩니다.

이미 목록에 있는 테이블 위로 테이블을 가져오면 목록에서 교체되므로, 몇 번을 가져오든 테이블은 한 번만 새로 고쳐집니다. 각 테이블 옆의 **복사**는 수식에서 사용할 Excel 표 이름을 복사합니다.

## 차원 가져오기

**차원** 탭에는 프로젝트의 [차원](/ko/guides/dimensions/dimensions/)이 나열됩니다.

1. 차원을 클릭합니다. **Filter dimensions by name**을 사용하여 찾습니다.
2. **Select where to place this dimension** 아래에서 **Matching Worksheet** 또는 **Current Selection**을 선택합니다.
3. **Retrieve Dimension**을 클릭합니다.

PlaidXL은 차원의 노드를 계층 순서대로 하나의 열에 씁니다. 차원에는 열 필터나 행 필터가 없습니다. **Refresh All Tables**는 테이블과 함께 차원도 새로 고칩니다.

들여쓰기와 Excel 개요 그룹화로 계층을 배치하거나 특정 노드 또는 대체 계층에서 시작하려면 대신 [드릴 명령](/ko/reference/cli/plaidxl/drill/) 또는 [`PLAIDXL.DRILL`](/ko/reference/cli/plaidxl/functions/#drill)을 사용하십시오. 셀에 멤버 하나를 넣으려면 **차원** 탭에서 **Pick member...** 를 클릭하십시오. [멤버 선택](/ko/reference/cli/plaidxl/drill/#멤버-선택)을 참조하십시오.

## 테이블을 PlaidCloud에 저장

워크북으로 가져온 테이블은 다시 저장할 수 있으며, PlaidCloud 테이블의 행이 시트에 있는 내용으로 바뀝니다.

1. 가져온 테이블이 있는 워크시트로 이동합니다. **On this sheet** 아래에 작업 창이 해당 시트로 가져온 각 테이블을 나열합니다. 테이블이 없으면 창에서 먼저 그곳에 테이블을 가져오라고 안내합니다.
2. 테이블 옆의 **Save to PlaidCloud**를 클릭하거나, 시트의 모든 테이블을 저장하려면 리본의 **쓰기** 그룹에서 **Save sheet to PlaidCloud...** 를 클릭합니다(**Ctrl+Alt+Shift+W**, Mac에서는 **⌘⌥⇧W**).

저장은 확인 없이 바로 이루어집니다. 메시지에 저장된 행 수가 표시되고, 알아야 할 사항이 안내되며, **실행 취소**가 제공됩니다.

PlaidXL은 테이블의 머리글 행과 그 아래 행을 읽습니다. 머리글은 가져온 열과 여전히 일치해야 하며, 값은 각 열의 데이터 형식으로 변환됩니다. 값을 변환할 수 없으면 아무것도 기록되지 않고 실패한 행이 나열됩니다. PlaidCloud의 열 정의는 그대로 유지됩니다.

### 저장되는 항목

- 빈 셀은 빈 값으로 저장됩니다.
- 가져온 행 안의 빈 행은 건너뜁니다. 그 아래에서 테이블은 첫 번째 빈 행에서 끝나며, 그보다 더 아래의 행은 저장되지 않고 메시지에 해당 행이 표시됩니다.
- 가져오지 않은 열은 PlaidCloud에서 비워지며 메시지에 해당 열이 표시됩니다.
- 가져온 후 PlaidCloud에서 테이블이 변경된 경우 저장하면 해당 테이블이 교체되며 메시지에 그 사실이 표시됩니다. 복원 지점에는 기존 내용이 보관됩니다.

### 일부 행만 교체하는 저장

다음과 같은 경우 저장은 자신의 행만 교체하고 나머지 테이블은 유지합니다.

- **테이블을 필터와 함께 가져온 경우** — 필터가 **AND**로 연결된 **equal** 및 **in** 규칙으로 만들어진 경우입니다. 필터가 포함하는 행만 교체됩니다. 필터 범위 밖에 추가한 행도 저장되며 메시지에 몇 개인지 표시됩니다. 다른 필터로 가져온 테이블은 저장할 수 없습니다. 그런 필터로 다시 가져오거나 필터 없이 다시 가져오십시오.
- **시트에 [Show detail rows](/ko/reference/cli/plaidxl/drill/#상세-행-표시)의 상세 행이 표시된 경우** — 해당 값의 근거가 되는 행만 교체됩니다.
- **테이블에 대한 액세스가 일부 행으로 제한된 경우** — 볼 수 있는 행만 교체되므로 다른 사용자의 행은 유지됩니다. 시트에 액세스 범위 밖의 행이 있으면 아무것도 저장되지 않고 메시지에 해당 행이 나열됩니다. 해당 행을 제거한 다음 다시 저장하십시오.

### 저장 실행 취소

PlaidXL은 쓰기 전에 복원 지점을 만들고 7일 동안 보관합니다. 쓰기가 실패하면 테이블이 원래대로 복원되고 변경 내용은 시트에 남습니다. 단, 쓰기가 시작된 후 다른 사용자가 테이블을 변경했다면 테이블은 그대로 두며 메시지에 그 사실이 표시됩니다.

저장을 취소하려면 메시지의 **실행 취소**를 클릭하거나 리본의 **쓰기** 그룹에서 **Undo last write**를 클릭합니다. 테이블은 저장하기 전 상태로 돌아가며, 일부 행만 교체한 저장의 경우 해당 행만 돌아갑니다. 시트를 새로 고쳐 확인하십시오. [쓰기 실행 취소](/ko/reference/cli/plaidxl/write-values/#쓰기-실행-취소)를 참조하십시오. 복원 지점을 만들 수 없는 테이블도 저장은 되며, 메시지에 저장을 취소할 수 없다고 표시됩니다.
