## 설명


외부 접근을 허용하지 않는 원격 시스템의 데이터에 접근하거나 해당 시스템에서 프로세스를 실행해야 하는 경우가 있습니다. 방화벽 뒤에 있는 엔터프라이즈 환경에서는 흔한 일입니다. PlaidCloud는 PlaidLink를 사용하여 방화벽 뒤에 있거나 PlaidCloud에서의 직접 접근을 원하지 않는 원격 시스템에 접근할 수 있게 합니다.



PlaidLink는 에이전트 기반 시스템을 사용합니다. 즉, 원격 사용자 역할을 하는 에이전트를 방화벽 안쪽이나 기타 제한된 영역 내부의 시스템에 설치합니다. 그러면 에이전트는 보안 HTTPS 웹소켓 연결을 통해 외부로 향하는 시작 방식으로 PlaidCloud에 연결할 수 있습니다. 다른 암호화된 웹 연결과 똑같이 안전하며 대개 비표준 포트를 열 필요가 없습니다. 접근 권한을 얻기 전에 에이전트는 에이전트 식별자를 보내 자신을 식별해야 합니다. 인증 과정이 성공하면 에이전트는 승인된 작업에 대한 접근 권한을 부여받습니다.



PlaidLink는 Windows, Unix, Linux 시스템에 설치할 수 있으며 낮은 권한의 사용자로 실행할 수 있습니다. Windows 시스템에서는 PlaidLink를 Windows 서비스로 실행할 수 있으며 서비스 패널에서 전체를 제어할 수 있습니다. Linux 또는 Unix 시스템에서는 데몬 프로세스로 실행할 수 있습니다.

PlaidLink는 독립 실행형 Docker 컨테이너나 Kubernetes 파드로도 실행할 수 있습니다.



## 에이전트 관리


**에이전트를 관리하려면:**


1. Analyze를 엽니다
2. "Tools"를 선택합니다
3. "PlaidLink Agents"를 클릭합니다

그러면 사용 가능한 에이전트 목록을 보고, 수정하고, 자격 증명을 얻을 수 있는 **PlaidLink Agents Table**로 이동합니다.



## 에이전트 만들기


**에이전트를 만들려면:**


1. Analyze를 엽니다
2. "Tools"를 선택합니다
3. "PlaidLink Agents"를 클릭합니다
4. "Add PlaidLink Agent"를 클릭합니다
5. 필수 필드를 입력합니다
6. "Create"를 클릭합니다
7. 에이전트가 작업을 수행하는 데 필요한 리소스에 접근할 수 있도록 필요한 보안 그룹에 에이전트를 할당합니다
8. 에이전트가 작업을 수행하는 데 필요한 문서에 접근할 수 있도록 필요한 문서 계정에 에이전트를 할당합니다


<Aside type="danger">위 7단계와 8단계에서 PlaidLink 에이전트는 에이전트가 수행하기를 기대하는 작업에 필요한 보안 그룹과 문서 계정에 할당되어야 합니다. 그렇지 않으면 접근이 거부됩니다.</Aside>

<Aside>새 에이전트 양식에 없는 정보는 자동으로 생성됩니다.</Aside>



## 에이전트 자격 증명 얻기


원격 시스템에서 PlaidLink 에이전트를 구성하려면 보안을 유지하기 위해 먼저 에이전트의 식별 정보를 얻어야 합니다. 이 정보에는 공개 키와 개인 키가 모두 포함됩니다.



**이 키를 얻으려면:**


1. Analyze를 엽니다
2. "Tools"를 선택합니다
3. "PlaidLink Agents"를 클릭합니다
4. 편집 아이콘을 클릭합니다

그러면 공개 키와 개인 키 값을 볼 수 있는 양식이 열립니다.


## 에이전트 자격 증명 다시 생성


보안을 유지하려면 주기적으로 공개 키와 개인 키를 다시 생성하고 원격 시스템의 구성을 업데이트하는 것이 좋습니다.



**자격 증명을 다시 생성하려면:**


1. Analyze를 엽니다
2. "Tools"를 선택합니다
3. "PlaidLink Agents"를 클릭합니다
4. 다시 생성 아이콘을 클릭합니다

자격 증명이 다시 생성되면 새 에이전트의 자격 증명을 얻는 방법(위에서 설명)과 같은 방법으로 얻을 수 있습니다.



## 에이전트 사용 및 사용 안 함


**에이전트를 사용하지 않도록 설정하려면:**


1. Analyze를 엽니다
2. "Tools"를 선택합니다
3. "PlaidLink Agents"를 클릭합니다
4. "Active" 확인란의 선택을 해제합니다

<Aside>에이전트가 활성으로 표시되어 있지 않으면 원격 시스템은 해당 에이전트 자격 증명으로 연결할 수 없습니다.</Aside>



## 에이전트 환경


연결은 환경마다 다른 구성을 가질 수 있으므로, 프로젝트의 환경을 전환하면 해당 프로젝트가 사용하는 모든 연결이 한 번에 새 환경으로 바뀝니다. 에이전트도 같은 전환을 따르도록 할 수 있습니다.


각 에이전트에는 두 가지 설정이 있습니다.


- **Agent Group** — 서로 대신할 수 있는 에이전트들이 공유하는 이름입니다. 그룹 안의 에이전트는 환경당 하나씩, 같은 작업을 대신하는 대안입니다.
- **Environment** — 이 에이전트가 담당하는 연결 환경입니다.


단계는 여전히 특정 에이전트 하나를 지정합니다. 워크플로가 실행되면 PlaidCloud는 해당 에이전트가 속한 그룹을 확인하고 프로젝트의 현재 환경을 담당하는 멤버를 선택합니다. 따라서 기본 환경에서 QA로 옮긴 프로젝트는 어떤 단계도 편집하지 않고 QA 머신에서 원격 단계를 실행합니다.


`Finance`라는 그룹에 기본값(Default)을 담당하는 에이전트와 QA를 담당하는 에이전트가 하나씩 있는 경우, 둘 중 어느 쪽을 지정한 단계든 프로젝트에 맞는 에이전트에서 실행됩니다. 기본값으로 다시 전환한 프로젝트는 단계가 QA 에이전트를 지정했더라도 기본값 에이전트에서 실행됩니다.


**에이전트를 환경에 할당하려면:**


1. Analyze를 엽니다
2. "Tools"를 선택합니다
3. "PlaidLink Agents"를 클릭합니다
4. 에이전트를 엽니다
5. "Agent Group"을 해당 에이전트의 대안들과 공유하는 이름으로 설정하고, "Environment"를 이 에이전트가 담당하는 환경으로 설정합니다
6. 해당 에이전트를 실행하는 머신의 PlaidLink 구성 파일에 일치하는 환경 이름을 설정합니다. 아래 [에이전트 머신 일치시키기](#에이전트-머신-일치시키기)를 참조하십시오

<Aside>그룹이 설정되지 않은 에이전트는 모든 환경을 담당하며, 그룹을 설정하기 전에는 모든 에이전트가 그렇습니다. 에이전트를 하나만 실행하는 워크스페이스에서는 아무것도 바뀌지 않습니다.</Aside>

<Aside type="caution">그룹을 설정하면 그룹이 하나뿐인 경우를 포함하여 그룹 내 모든 에이전트에 대해 일치 조건이 정확해야 합니다. 프로젝트가 그룹 내 어떤 에이전트도 담당하지 않는 환경에서 실행되면, 단계가 지정한 에이전트로 대체되지 않고 그룹과 환경을 알려 주는 메시지와 함께 실패합니다. 이는 의도된 동작입니다. 대안은 운영 작업이 테스트 머신에서 조용히 실행되는 것이기 때문입니다. 프로젝트가 실행되는 각 환경마다 에이전트를 추가하고, 계속 모든 환경을 담당해야 하는 에이전트는 그룹을 비워 두십시오.</Aside>


에이전트를 그룹에서 빼면 그룹이 포괄하는 범위가 좁아지므로, 추가하는 것만큼 영향이 큽니다. 기본 환경을 담당하던 에이전트의 그룹을 지우면 그 환경에서 실행되는 프로젝트가 연결될 대상이 없어져 다음 실행에서 실패합니다. 그룹의 멤버를 제거하기 전에 해당 환경을 그룹의 다른 멤버로 옮기십시오. 그룹이 포괄하는 범위를 바꾸는 저장을 할 때마다 새 포괄 범위가 보고됩니다.


환경은 연결과 공유되므로, 여기에서 제공되는 환경 이름은 연결을 구성할 때 사용하는 이름과 같습니다. [연결 만들기 및 관리](/ko/guides/connections/create-connection/#환경)를 참조하십시오.


### 에이전트 머신 일치시키기


여기에서 설정한 Environment는 해당 머신의 PlaidLink 서비스가 구성된 환경과 일치해야 합니다. PlaidLink는 구성 파일에 지정된 환경에 해당하는 정확한 큐 하나를 구독합니다. 따라서 에이전트 레코드에는 QA로 되어 있는데 머신은 여전히 기본 환경으로 구성되어 있다면, 작업이 전송되는 큐와 다른 큐를 수신하게 됩니다. 단계는 대기하다가 에이전트가 작업을 가져가지 않는다는 보고와 함께 실패합니다.


PlaidLink 구성 파일의 `environments` 블록에서 해당 에이전트의 항목에 설정하십시오.


```yaml
environments:
  - name: QA
    agent_id: <agent identifier>
```


`name`은 PlaidCloud에 표시되는 환경 이름입니다. 생략하면 에이전트는 기본 환경을 담당합니다. 변경한 후에는 PlaidLink 서비스를 다시 시작하십시오.


<Aside type="note">하나의 PlaidLink 서비스는 이 블록에 여러 항목을 둘 수 있으므로, 한 머신이 에이전트를 둘 이상 담당하거나 같은 에이전트를 둘 이상의 환경에서 담당할 수 있습니다. [여러 에이전트 실행](#여러-에이전트-실행)을 참조하십시오.</Aside>


## 여러 에이전트 실행


PlaidLink는 단일 서비스 설치로 여러 에이전트를 운영할 수 있도록 설계되었습니다. 이러한 간소화된 설치 방식을 통해 한 번의 설치로 여러 워크스페이스의 에이전트나 작업 실행 권한 수준이 서로 다른 에이전트를 처리할 수 있습니다.

여러 에이전트를 사용하려면 PlaidLink 구성 파일에 에이전트 자격 증명을 추가하기만 하면 됩니다.

## 여러 PlaidLink 서비스 실행

하나의 PlaidLink 서비스 안에서 여러 에이전트를 실행하는 것과 마찬가지로, 여러 PlaidLink 서비스를 실행할 수도 있습니다.

시스템 기반 보안을 사용하거나 네트워크 경계를 넘는 통신을 막는 네트워크 접근 제한이 있는 경우에는 이것이 필요할 때가 있습니다.

<Aside>일반적으로는 한 머신에서 여러 서비스를 실행하기보다 단일 서비스 아래에서 여러 에이전트를 실행하는 것이 더 좋습니다. 그러나 사용 사례에 따라 서로 구분되는 여러 서비스를 실행해야 할 수도 있습니다.</Aside>

## 컴퓨팅, 메모리, 디스크 요구 사항

PlaidLink 서비스는 매우 가벼우며 작동에 최소한의 컴퓨팅과 메모리만 필요합니다.  상당한 양의 데이터를 처리할 때는 컴퓨팅 리소스, 특히 메모리를 늘려야 할 수 있습니다.

일반적으로 에이전트는 CPU 5%와 메모리 200MB만으로도 문제없이 실행됩니다.  집약적인 데이터 작업에는 CPU 하나 전체와 최소 4GB의 RAM을 할당하는 것이 좋습니다.  Kubernetes와 같은 동적 리소스 할당 시스템에서는 에이전트가 예약된 리소스가 아니라 버스트 가능한 리소스에 접근할 수 있어도 괜찮습니다.

에이전트의 디스크 공간도 최소한입니다.  에이전트 작업은 대량의 데이터를 전송할 때 디스크 공간을 데이터 버퍼로 사용합니다.  일반적인 작업에는 보통 8GB면 충분합니다.  집약적인 데이터 작업에는 예상 데이터 양에 맞춰 디스크를 늘리는 것이 좋습니다.  CPU 속도, 네트워크 속도, 데이터 양 등 여러 요인에 따라 달라지므로 정해진 용량은 없습니다.  그러나 20GB에서 시작하여 조정하는 것이 좋은 출발점입니다.


## 네트워크 요구 사항

PlaidLink 에이전트는 최소한의 구성만으로 작동하도록 설계되었습니다.  표준 HTTPS 네트워크 트래픽을 허용하는 것 외에는 특별한 VPN이나 네트워크 구성이 필요하지 않습니다.  에이전트는 일반 웹 브라우저 기반 트래픽과 동일한 프로토콜로 통신합니다.

에이전트 서비스가 항상 PlaidCloud와의 통신을 시작하므로 방화벽에서 인바운드 접근을 구성할 필요가 없습니다.

<Aside>방화벽 규칙이 표준 HTTPS 트래픽을 포함한 모든 접근을 차단하는 경우가 있습니다. 에이전트가 시작할 때 PlaidCloud에 연결할 수 없다고 보고하면 네트워크 팀과 협력하여 트래픽을 위해 443 포트를 열어야 합니다.</Aside>
