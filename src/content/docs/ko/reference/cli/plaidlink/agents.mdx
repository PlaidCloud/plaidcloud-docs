## 설명


외부 접근을 허용하지 않는 원격 시스템의 데이터에 접근하거나 프로세스를 실행해야 하는 경우가 있습니다. 방화벽 뒤에 있는 엔터프라이즈 환경에서 흔히 발생하는 상황입니다. PlaidCloud는 PlaidLink를 통해 방화벽 뒤에 있거나 PlaidCloud에서 직접 접근하기를 원하지 않는 원격 시스템에 접근할 수 있도록 합니다.



PlaidLink는 에이전트 기반 시스템을 사용합니다. 즉, 원격 사용자인 에이전트를 방화벽 내부 또는 기타 제한된 영역의 시스템에 설치합니다. 그러면 에이전트는 보안 HTTPS 웹소켓 연결을 통한 아웃바운드 시작 방식으로 PlaidCloud에 연결할 수 있습니다. 이는 다른 암호화된 웹 연결과 동일한 수준으로 안전하며, 일반적으로 비표준 포트를 열 필요가 없습니다. 접근 권한을 얻기 전에 에이전트는 에이전트 식별자를 전송하여 자신을 식별해야 합니다. 이후 에이전트가 인증 과정을 성공적으로 통과하면 승인된 작업에 대한 접근 권한이 부여됩니다.



PlaidLink는 Windows, Unix, Linux 시스템에 설치할 수 있으며 낮은 권한의 사용자로 실행할 수 있습니다. Windows 시스템에서는 PlaidLink가 Windows 서비스로 작동하며 서비스 패널에서 전체 제어가 가능합니다. Linux 또는 Unix 시스템에서는 데몬 프로세스로 실행할 수 있습니다.

PlaidLink는 독립 실행형 Docker 컨테이너 또는 Kubernetes 파드로도 실행할 수 있습니다.



## 에이전트 관리


**에이전트를 관리하려면:**


1. Analyze를 엽니다.
2. “도구”를 선택합니다.
3. “PlaidLink 에이전트”를 클릭합니다.

그러면 사용 가능한 에이전트 목록을 보고, 수정하고, 자격 증명을 가져올 수 있는 **PlaidLink 에이전트 테이블**로 이동합니다.



## 에이전트 만들기


**에이전트를 만들려면:**


1. Analyze를 엽니다.
2. “도구”를 선택합니다.
3. “PlaidLink 에이전트”를 클릭합니다.
4. “PlaidLink 에이전트 추가”를 클릭합니다.
5. 필수 필드를 입력합니다.
6. “만들기”를 클릭합니다.
7. 에이전트가 작업을 수행하는 데 필요한 리소스에 접근할 수 있도록 필요한 보안 그룹에 에이전트를 할당합니다.
8. 에이전트가 작업을 수행하는 데 필요한 문서에 접근할 수 있도록 필요한 문서 계정에 에이전트를 할당합니다.


<Aside type="danger">위의 7단계와 8단계에서 PlaidLink 에이전트는 예상하는 작업을 수행하는 데 필요한 보안 그룹과 문서 계정에 할당되어야 합니다. 그렇지 않으면 접근이 거부됩니다.</Aside>

<Aside>새 에이전트 양식에 없는 정보는 자동으로 생성됩니다.</Aside>



## 에이전트 자격 증명 가져오기


원격 시스템에서 PlaidLink 에이전트를 구성하려면 보안 유지를 위해 먼저 에이전트의 식별 정보를 가져와야 합니다. 이 정보에는 공개 키와 개인 키가 모두 포함됩니다.



**이 키를 가져오려면:**


1. Analyze를 엽니다.
2. “도구”를 선택합니다.
3. “PlaidLink 에이전트”를 클릭합니다.
4. 편집 아이콘을 클릭합니다.

그러면 공개 키와 개인 키 값을 볼 수 있는 양식이 열립니다.

개인 키와 **RPC 구성 보기** 버튼은 에이전트를 편집할 수 있는 멤버에게만 표시되며, 다른 멤버에게는 공개 키만 표시됩니다.


## 에이전트 자격 증명 다시 생성


보안을 유지하려면 공개 키와 개인 키를 주기적으로 다시 생성하고 원격 시스템의 구성을 업데이트하는 것이 좋습니다.



**자격 증명을 다시 생성하려면:**


1. Analyze를 엽니다.
2. “도구”를 선택합니다.
3. “PlaidLink 에이전트”를 클릭합니다.
4. 다시 생성 아이콘을 클릭합니다.

자격 증명을 다시 생성한 후에는 새 에이전트의 자격 증명을 가져오는 방법(위에서 설명)과 동일하게 가져올 수 있습니다.



## 에이전트 활성화 및 비활성화


**에이전트를 비활성화하려면:**


1. Analyze를 엽니다.
2. “도구”를 선택합니다.
3. “PlaidLink 에이전트”를 클릭합니다.
4. “활성” 확인란의 선택을 해제합니다.

<Aside>에이전트가 활성 상태로 표시되지 않으면 원격 시스템은 해당 에이전트 자격 증명을 사용하여 연결할 수 없습니다.</Aside>



## 에이전트 환경


연결은 환경별로 서로 다른 구성을 가질 수 있으므로, 프로젝트의 환경을 전환하면 해당 프로젝트가 사용하는 모든 연결이 한 번에 다시 지정됩니다. 에이전트도 같은 전환을 따르도록 할 수 있습니다.


각 에이전트에는 두 가지 설정이 있습니다.


- **에이전트 그룹** — 서로 대신할 수 있는 에이전트들이 공유하는 이름입니다. 그룹 내 에이전트는 같은 작업을 위한 대체 수단이며, 환경당 하나씩 둡니다.
- **이 에이전트가 서비스하는 환경** — 이 에이전트가 담당하는 연결 환경입니다. 에이전트의 PlaidLink 구성에 있는 환경과 일치해야 합니다.


단계는 여전히 특정 에이전트 하나를 지정합니다. 워크플로가 실행되면 PlaidCloud는 해당 에이전트가 속한 그룹을 확인하여 프로젝트의 현재 환경을 담당하는 멤버를 선택합니다. 따라서 기본 환경에서 QA로 전환된 프로젝트는 단계를 수정하지 않아도 원격 단계를 QA 머신에서 실행합니다.


`Finance`라는 그룹에 기본 환경을 담당하는 에이전트와 QA를 담당하는 에이전트가 하나씩 있는 경우, 둘 중 어느 쪽을 지정한 단계든 프로젝트에 맞는 에이전트에서 실행됩니다. 기본 환경으로 되돌린 프로젝트는 단계가 QA 에이전트를 지정하더라도 기본 환경 에이전트에서 실행됩니다.


**에이전트를 환경에 할당하려면:**


1. Analyze를 엽니다.
2. “도구”를 선택합니다.
3. “PlaidLink 에이전트”를 클릭합니다.
4. 에이전트를 엽니다.
5. “에이전트 그룹”을 해당 에이전트의 대체 에이전트들과 공유하는 이름으로 설정하고, “이 에이전트가 서비스하는 환경”을 이 에이전트가 작업을 실행하는 환경(예: QA)으로 설정합니다.
6. 해당 에이전트를 실행하는 머신에서 PlaidLink 구성 파일에 일치하는 환경 이름을 설정합니다. 아래의 [에이전트 머신 일치시키기](#에이전트-머신-일치시키기)를 참조하십시오.

<Aside>그룹이 설정되지 않은 에이전트는 모든 환경을 담당합니다. 그룹을 설정하기 전까지는 모든 에이전트가 여기에 해당합니다. 에이전트를 하나만 실행하는 워크스페이스에는 아무 변화도 없습니다.</Aside>

<Aside type="caution">그룹을 설정하면 그룹이 하나뿐인 경우를 포함하여 그룹 내 모든 에이전트에 대해 정확히 일치하는 환경만 허용됩니다. 그룹 내 어떤 에이전트도 담당하지 않는 환경에서 실행되는 프로젝트는 단계가 지정한 에이전트로 대체되지 않고, 그룹과 환경 이름을 알리는 메시지와 함께 실패합니다. 이는 의도된 동작입니다. 그렇지 않으면 운영 작업이 테스트 머신에서 조용히 실행될 수 있기 때문입니다. 프로젝트가 실행되는 각 환경마다 에이전트를 추가하고, 모든 환경을 계속 담당해야 하는 에이전트는 그룹을 비워 두십시오.</Aside>


에이전트를 그룹에서 빼면 그룹이 담당하는 범위가 좁아지므로, 그룹에 추가하는 것만큼 영향이 큽니다. 기본 환경을 담당하던 에이전트의 그룹을 지우면 해당 환경에서 실행되는 프로젝트가 연결할 대상을 잃어 다음 실행 시 실패합니다. 그룹의 멤버를 제거하기 전에 해당 환경을 그룹 내 다른 멤버로 옮기십시오. 그룹이 담당하는 범위를 변경하는 저장 작업마다 새로운 담당 범위가 보고됩니다.


환경은 연결과 공유되므로 여기에서 제공되는 환경 이름은 연결에서 구성하는 환경 이름과 같습니다. [연결 만들기 및 관리](/ko/guides/connections/create-connection/#환경)를 참조하십시오.


### 에이전트 머신 일치시키기


여기에서 설정한 환경은 해당 머신의 PlaidLink 서비스가 구성된 환경과 일치해야 합니다. PlaidLink는 구성 파일에 명시된 환경의 정확한 큐 하나를 구독합니다. 따라서 에이전트 레코드에는 QA로 되어 있지만 머신은 여전히 기본 환경으로 구성된 경우, 에이전트는 작업이 전송되는 큐와 다른 큐를 수신하게 됩니다. 단계는 대기하다가 에이전트가 작업을 가져가지 않는다는 오류와 함께 실패합니다.


PlaidLink 구성 파일의 `environments` 블록에서 해당 에이전트의 항목에 설정합니다.


```yaml
environments:
  - name: QA
    agent_id: <agent identifier>
```


`name`은 PlaidCloud에 표시되는 환경 이름입니다. 생략하면 에이전트는 기본 환경을 담당합니다. 변경한 후에는 PlaidLink 서비스를 다시 시작하십시오.


<Aside type="note">하나의 PlaidLink 서비스가 이 블록에 여러 항목을 둘 수 있으므로, 한 머신이 둘 이상의 에이전트를 담당하거나 동일한 에이전트를 둘 이상의 환경에서 담당할 수 있습니다. [여러 에이전트 실행](#여러-에이전트-실행)을 참조하십시오.</Aside>


## 여러 에이전트 실행


PlaidLink는 단일 서비스 설치로 여러 에이전트를 운영할 수 있도록 설계되었습니다. 이렇게 간소화된 설치 방식을 사용하면 하나의 설치로 여러 워크스페이스의 에이전트 및/또는 작업 실행 권한 수준이 서로 다른 에이전트를 처리할 수 있습니다.

여러 에이전트를 사용하려면 PlaidLink 구성 파일에 에이전트 자격 증명을 추가하기만 하면 됩니다.

## 여러 PlaidLink 서비스 실행

하나의 PlaidLink 서비스 내에서 여러 에이전트를 실행하는 것과 마찬가지로, 여러 PlaidLink 서비스를 실행하는 것도 가능합니다.

시스템 기반 보안을 사용하거나 네트워크 경계 간 통신을 막는 네트워크 접근 제한이 있는 경우에 필요할 수 있습니다.

<Aside>일반적으로 한 머신에서 여러 서비스를 실행하기보다는 단일 서비스에서 여러 에이전트를 실행하는 것이 더 좋습니다. 그러나 사용 사례에 따라 서로 구별되는 여러 서비스를 실행해야 할 수도 있습니다.</Aside>

## 컴퓨팅, 메모리 및 디스크 요구 사항

PlaidLink 서비스는 매우 가벼우며 작동하는 데 최소한의 컴퓨팅과 메모리만 필요합니다. 대용량 데이터를 처리할 때는 컴퓨팅 리소스, 특히 메모리를 늘려야 할 수 있습니다.

일반적으로 에이전트는 CPU 5%와 메모리 200MB로 원활하게 실행됩니다. 집약적인 데이터 작업에는 CPU 전체와 최소 4GB의 RAM을 할당할 것을 권장합니다. Kubernetes와 같은 동적 리소스 할당 시스템에서는 에이전트가 예약된 리소스가 아닌 버스트 가능한 리소스를 사용할 수 있어도 문제없습니다.

에이전트에 필요한 디스크 공간도 최소한입니다. 에이전트 작업은 대용량 데이터를 전송할 때 디스크 공간을 데이터 버퍼로 사용합니다. 일반적인 작업에는 보통 8GB면 충분합니다. 집약적인 데이터 작업에서는 예상 데이터 볼륨에 맞게 디스크를 늘릴 것을 권장합니다. CPU 속도, 네트워크 속도, 데이터 양 등 여러 요인에 따라 달라지므로 정해진 용량은 없습니다. 다만 20GB로 시작하여 필요에 따라 조정하는 것이 좋습니다.


## 네트워킹 요구 사항

PlaidLink 에이전트는 최소한의 구성만으로 작동하도록 설계되었습니다. 표준 HTTPS 네트워크 트래픽을 허용하는 것 외에는 별도의 VPN이나 네트워크 구성이 필요하지 않습니다. 에이전트는 일반 웹 브라우저 기반 트래픽과 동일한 프로토콜로 통신합니다.

에이전트 서비스는 항상 PlaidCloud와의 통신을 먼저 시작하므로 방화벽에서 인그레스 접근을 구성할 필요가 없습니다.

<Aside>방화벽 규칙이 표준 HTTPS 트래픽을 포함한 모든 접근을 차단하는 경우도 있습니다. 시작 시 에이전트가 PlaidCloud에 연결할 수 없다고 보고하면 네트워킹 팀과 협의하여 포트 443의 트래픽을 열어야 합니다.</Aside>
