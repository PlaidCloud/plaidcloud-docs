## 만들게 될 내용

다음을 수행하는 작은 워크플로입니다.

1. CSV를 프로젝트 테이블로 가져옵니다
2. 몇 개의 단계로 데이터를 필터링하고 변환합니다
3. 다른 도구에서 사용할 수 있도록 결과를 게시합니다

<Aside>
이 안내서는 의도적으로 가볍게 구성했습니다. 깊이 파고들기보다 구성 요소를 둘러보는 과정입니다. 마치고 나면 [개념](/ko/get-started/concepts/) 페이지에서 구성이 왜 이런 방식으로 되어 있는지 설명하고, [가이드](/ko/guides/) 섹션에서 각 작업을 자세히 다룹니다.
</Aside>

## 샘플 프로젝트로 시작하기

직접 만들기 전에 완성된 결과를 먼저 보고 싶다면 이 지름길을 이용하십시오. 새 워크스페이스에는 **샘플 로드** 버튼이 나타납니다. 워크스페이스에서 안내형 샘플을 둘 이상 제공하는 경우, 먼저 짧은 목록에서 로드할 샘플을 선택합니다.

- **Retail Sales Analysis** — 소매 및 판매
- **Campaign Performance by Channel** — 마케팅
- **Inventory Status Report** — 공급망 및 운영
- **Budget vs Actual by Department** — 재무

각 샘플은 PlaidCloud의 로우코드 변환 단계만으로 만든 작고 현실적인 데이터 세트이며 직접 작성한 SQL이 없으므로, 나중에 완성된 워크플로를 열어 어떻게 동작하는지 정확히 확인할 수 있습니다. 하나를 선택하면(사용 가능한 샘플이 하나뿐이면 PlaidCloud가 바로 로드합니다) PlaidCloud가 프로젝트를 구성하고 워크플로를 실행하면서 각 단계의 진행 상황을 보여 줍니다. 파일을 **가져오는 중**, **정리 중**, 몇 개의 병렬 요약으로 분기, 그리고 이를 하나의 최종 결과 테이블로 결합하는 과정을 거친 뒤 결과를 열어 줍니다. 실행이 끝나면 PlaidCloud는 결과 테이블을 보고용으로 게시하고, 이를 바탕으로 KPI 요약, 시간에 따른 추이, 샘플의 주요 범주별 분석, 그리고 소매 및 재고 샘플의 경우 미국 주별 분석으로 구성된 대시보드를 자동으로 만듭니다. 첫 실행은 웨어하우스를 준비하는 동안 약 1분이 걸리며, 이후의 실행은 거의 즉시 끝납니다. 화면에도 이 점이 안내되므로 기다리는 시간이 뜻밖으로 느껴지지 않습니다. 아무것도 직접 만들지 않고도 몇 분 안에 실제 첫 결과와 완성된 대시보드를 확인할 수 있으며, 생성된 모든 구성 요소는 직접 열고 변경하고 다시 실행할 수 있습니다. 샘플을 로드하거나 실행하는 중에 문제가 발생하면 PlaidCloud가 이를 알리고 다시 시도하도록 안내합니다.

샘플 프로젝트와 해당 워크플로, 그리고 생성되는 각 대시보드는 만들어지는 즉시 전체 워크스페이스와 공유됩니다. 뷰어 권한이 있는 팀원도 별도의 공유 절차 없이 여러분과 동일한 완성된 샘플을 볼 수 있습니다.

빈 화면마다 빈 그리드를 그대로 보여 주는 대신 다음 단계를 안내합니다. **프로젝트**, **워크플로**, **테이블**, **연결**, **대시보드** 화면은 각각 짧은 설명과 주요 작업(**새 프로젝트**, **새 워크플로**, **테이블 번들 가져오기** 등)을 보여 주므로 항상 명확한 진행 방법이 있습니다. 이러한 화면과 시작 패널의 **도움이 필요하십니까?** 링크를 누르면 막혔을 때 바로 지원 페이지로 이동합니다. 뷰어로 워크스페이스에 추가된 경우에는 수행할 수 없는 작업은 제시하지 않고 지금 보고 있는 내용을 설명해 줍니다. 또한 뷰어가 아직 표시할 콘텐츠가 없는 워크스페이스에 들어오면, 짧은 사용 방법 소개, 앱 안내 투어, 도움말 바로 가기가 있는 시작 화면이 표시되어 항상 다음 단계가 있습니다.

이 안내형 첫 실행은 모든 요금제의 모든 새 워크스페이스에 나타납니다. 이미 사용법을 알고 있다면 시작 패널에서 **닫기**를 선택하십시오. 간단한 확인 메시지가 안내가 계속 제공된다는 점을 알려 주며, 안내는 화면에서 사라집니다. 언제든 다시 불러오려면 오른쪽 위 모서리의 사용자 메뉴를 열고 **온보딩 다시 시작**을 선택하십시오.

## 내 CSV로 시작하기

샘플 대신 내 데이터로 시작하려면 **내 데이터 가져오기**를 선택하십시오. 이 항목은 비어 있는 **프로젝트** 화면의 **샘플 로드** 옆에 있으며 홈에서도 제공됩니다. 이 항목을 보려면 프로젝트와 테이블을 만들고 문서 스토리지에 쓸 수 있는 권한이 필요합니다. 프로젝트가 이미 있다면 **프로젝트** 화면에서 **새로 만들기** > **CSV 파일에서 프로젝트 만들기**를 선택해 같은 창을 열 수 있으며, 이미 있는 프로젝트에 CSV를 추가하려면 [CSV 파일 가져오기](/ko/guides/projects/managing-tables-and-views/#csv-파일-가져오기)를 참조하십시오.

CSV 파일을 상자에 놓거나 **CSV 파일 선택**을 선택해 파일을 고르십시오. `.csv`로 끝나는 파일만 허용됩니다. PlaidCloud는 파일을 **Personal Temp Drive**에 업로드하며, 없으면 워크스페이스의 **Temp Drive**에 업로드합니다. 그런 다음 파일 이름을 딴 프로젝트를 만들고 파일 이름을 딴 테이블로 가져옵니다. 예를 들어 `Sales Data.csv`는 프로젝트 **Sales Data**와 테이블 `sales_data`가 되며, 새 프로젝트의 **테이블** 목록이 열립니다. 이어서 **권장 다음 단계** 패널이 열리고, PlaidCloud가 테이블을 처음 살펴보고 나면 이 패널이 **데이터 한눈에 보기**로 바뀌어 테이블의 행 수와, 처음 여섯 개 열 각각의 유형, 비어 있는 값의 비율, 고유 값의 수를 보여 줍니다.

그 아래에는 시작용 막대 차트가 있습니다. 막대는 지역처럼 반복되는 값이 적은 열의 값이며, 각 막대는 해당 값에 대한 숫자 열의 합계나 평균 또는 행 수를 나타냅니다. 합리적인 차트가 둘 이상일 때는 PlaidCloud의 AI가 하나를 골라 제목을 붙입니다. AI는 열 이름, 유형, 개수만 볼 뿐 파일의 어떤 값도 보지 않습니다. 반복되는 값이 적은 열이 없으면 패널에 시작용 차트가 없다고 표시됩니다.

보고 기능이 켜져 있고 테이블을 게시할 권한이 있으면 PlaidCloud는 보고용으로 테이블도 게시하고 차트를 바탕으로 시작용 대시보드를 만들며, **대시보드 열기**를 선택하면 새 탭에서 열립니다. 대시보드의 차트는 "지역별 총 매출"처럼 표시하는 열의 이름을 따라 명명되며, AI가 붙인 제목은 패널의 차트에만 나타납니다. 다른 새 대시보드와 마찬가지로 처음에는 프로젝트의 모든 사용자에게 표시됩니다. 이를 변경하려면 [대시보드를 볼 수 있는 사용자 제어](/ko/guides/dashboards/control-who-can-see-a-dashboard/)를 참조하십시오.

패널에서는 검토할 준비가 된 단계를 여는 **이 데이터 정리** 또는 **이 데이터 요약**을 선택하거나, 건너뛰려면 **나중에**를 선택할 수도 있습니다.

가져오기가 실패하면 PlaidCloud는 방금 만든 프로젝트를 제거하고 무엇이 잘못되었는지 알려 줍니다. PlaidCloud는 가져오기가 끝나면 성공 여부와 관계없이 임시 드라이브에서 업로드한 파일을 삭제하며, 삭제하지 못한 경우에는 임시 드라이브가 하루 뒤에 삭제합니다. 워크스페이스에 임시 드라이브가 없으면 창에 파일을 저장할 곳이 없다고 표시되며, 워크스페이스 관리자가 지원팀에 문의해야 합니다.

## 홈에서 진행 상황 확인

워크스페이스에 들어가면 홈에 설정을 단계별로 추적하는 **시작하기** 카드가 하나 표시되며, 진행률 표시기("N/M")가 기본으로 들어 있습니다. 표시되는 내용은 역할에 따라 다릅니다. 관리자에게는 샘플 사용해 보기, 데이터 연결, 첫 워크플로 만들기, 대시보드 게시, 팀 초대의 다섯 단계가, 빌더에게는 샘플 사용해 보기, 첫 워크플로 만들기, 대시보드 게시의 세 단계가 표시되고, 뷰어에게는 이 카드가 표시되지 않습니다.

카드는 항상 아직 하지 않은 작업을 주요 동작으로 가장 먼저 보여 주며, 그 밖의 남은 단계는 각각 바로 해당 위치로 이동하는 클릭 가능한 행으로 표시됩니다. 완료한 단계는 영구적으로 체크 표시되어 다시 해제되지 않으며, 완료한 단계는 접혀서 카드가 남은 작업에 집중하도록 유지됩니다.

<Aside>
"대시보드 게시"는 직접 게시한 대시보드만 인정합니다. 팀원이 대시보드를 게시해도 내 항목은 완료로 표시되지 않습니다.
</Aside>

카드를 보고 싶지 않다면 **숨기기**를 선택하십시오. 카드가 도구 모음의 작은 "시작하기 · N/M" 버튼으로 접히며, 이 버튼을 클릭하면 언제든 전체 카드를 다시 볼 수 있습니다. 사용자 메뉴의 **온보딩 다시 시작**으로도 다시 표시됩니다. 온보딩을 완전히 끄려면 대신 **온보딩 닫기**를 사용하십시오. 이 설정은 **온보딩 다시 시작**을 선택할 때까지 꺼진 상태로 유지됩니다.

모든 단계를 완료하면 카드는 스스로 사라집니다. 홈에서 카드가 없어지고 "모든 준비가 끝났습니다"라는 축하 메시지가 한 번 표시되며, 몇 개의 기기나 브라우저를 사용하든 워크스페이스당 한 번만 표시됩니다.

진행 상황, 카드의 숨김 또는 표시 상태, 투어, 팁, 홈에서 닫은 모든 항목은 브라우저가 아니라 계정을 따릅니다. 새 기기, 다른 브라우저, 시크릿 창에서 로그인해도 처음부터 다시 시작하지 않고 중단한 곳에서 이어서 진행할 수 있습니다.

이 빠른 시작의 나머지 부분에서는 각 구성 요소를 확인할 수 있도록 같은 종류의 워크플로를 직접 만들어 봅니다.

## 1. 프로젝트 열기

로그인하면 워크스페이스로 이동합니다. **프로젝트** 탭을 열고 "Quickstart"처럼 알아보기 쉬운 이름으로 새 프로젝트를 만드십시오. 프로젝트는 데이터, 워크플로, 차원이 함께 있는 곳입니다.

프로젝트 수명 주기에 관한 자세한 내용은 [프로젝트 관리](/ko/guides/projects/managing-projects/)를 참조하십시오.

## 2. CSV 가져오기

프로젝트 안에서 **워크플로** 탭을 열고 새 워크플로를 만드십시오. **Import → CSV** 단계를 추가합니다. 로컬 컴퓨터에서 작은 CSV를 업로드하거나, 연결된 문서 저장소의 CSV를 지정하십시오.

해당 단계를 실행합니다. CSV가 프로젝트의 테이블로 생성됩니다. **테이블** 탭을 열어 확인하십시오.

참조: [Import CSV 단계](/ko/reference/workflow-steps/import/import-csv/) · 가이드: [워크플로는 어디에 있습니까?](/ko/guides/workflows/where-are-workflows/)

## 3. 변환 단계 추가

워크플로로 돌아가 **Tables → Table Lookup** 단계(또는 다른 테이블 단계)를 추가합니다. 소스와 대상을 구성하고, 유지할 열을 선택하고, 간단한 필터를 적용하십시오.

단계를 실행하면 결과로 미리 볼 수 있는 새 테이블이 생성됩니다.

참조: [워크플로 단계](/ko/reference/workflow-steps/)

## 4. 결과 게시

마지막에 **게시** 단계(**Data → Publish** 아래)를 추가하면 테이블을 대시보드, BI 도구 또는 외부 소비자가 사용할 수 있게 됩니다.

가이드: [데이터 게시](/ko/guides/data/publish/)

## 5. 전체 워크플로 실행

워크플로에서 **실행**을 클릭하십시오. 각 단계가 실행되는 동안 로그를 확인합니다. 오류가 발생하면 [단계 오류 관리](/ko/guides/workflows/managing-step-errors/) 가이드에서 디버깅 방법을 다룹니다.
