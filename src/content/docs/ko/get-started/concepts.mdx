## 조직, 워크스페이스, 멤버

계정은 청구 및 ID의 경계인 **조직** 수준에서 시작합니다. 조직 안에는 하나 이상의 **워크스페이스**가 있으며, 워크스페이스는 실제 작업이 이루어지는 격리된 환경입니다. **멤버**는 조직에 속한 사용자로, 특정 워크스페이스에 대한 액세스를 특정 역할로 부여받습니다.

- 대부분의 팀은 환경(개발, 스테이징, 운영)별로 워크스페이스를 하나씩 두거나 사업부별로 하나씩 두는 것으로 시작합니다.
- 워크스페이스 내의 보안 그룹이 각 멤버가 할 수 있는 작업을 제어합니다.

자세히 보기: [액세스 관리](/ko/administration/access/)

## 프로젝트

**프로젝트**는 워크스페이스 안의 작업 단위입니다. 각 프로젝트는 자체 데이터, 워크플로, 차원, 감사 이력을 소유합니다. 프로젝트는 서로 상태를 공유하지 않고 격리되어 있습니다.

프로젝트를 사용해 서로 다른 분석, 비즈니스 프로세스, 데이터 제품을 구분하십시오.

자세히 보기: [프로젝트](/ko/guides/projects/)

## 연결

**연결**은 PlaidCloud가 데이터베이스, 클라우드 스토리지 계정, ERP, REST API 같은 외부 시스템에 접근할 수 있게 해 주는 저장된 구성입니다. 연결은 워크플로 단계에서 재사용되므로 자격 증명이 단계마다 중복되지 않습니다.

자세히 보기: [연결(작업)](/ko/guides/connections/) · [커넥터(참조)](/ko/reference/connectors/)

## 테이블과 뷰

**테이블**은 프로젝트 안의 구조화된 데이터로, SQL 테이블처럼 행과 열로 이루어져 있습니다. 테이블은 가져오기, 변환 또는 외부 소스에서 생성됩니다. **뷰**는 테이블 위에 계층화된 저장된 쿼리 결과입니다.

자세히 보기: [테이블 및 뷰](/ko/guides/data/)

## 워크플로와 단계

**워크플로**는 테이블을 대상으로 동작하는 파이프라인입니다. 각 워크플로는 일련의 **단계**로 구성됩니다. CSV 가져오기, 두 테이블 조인, 행 필터링, JSON으로 내보내기, 알림 전송 등이 그 예입니다. 단계는 순차적으로, 병렬로, 조건부로 또는 반복문으로 실행할 수 있습니다.

단계는 다음과 같은 범주로 나뉩니다.

- **가져오기** — 데이터 수집(CSV, Excel, SQL, Parquet, JSON 등)
- **테이블** — 테이블 변환(조인, 필터, 멜트, 피벗, 추가, 업서트)
- **내보내기** — 데이터 내보내기
- **문서** — PDF, 이미지, 임의의 파일 처리
- **알림** — 이메일, Slack, Teams, SMS, 웹훅으로 메시지 전송
- **배부** — 비용 배부 모델 실행
- **차원** — 계층 구축 및 수정
- **SAP / SAP-PCM** — SAP 전용 작업 호출
- **워크플로 제어** — 변수, 반복문, 하위 워크플로

자세히 보기: [워크플로(작업)](/ko/guides/workflows/) · [워크플로 단계(참조)](/ko/reference/workflow-steps/)

## 차원

**차원**은 계층으로, 일반적으로 데이터를 나누어 보거나 집계하는 데 사용됩니다. 코스트 센터, 제품, 지역, 시간이 그 예입니다. 차원은 테이블에서 구축하거나 외부 소스에서 로드하거나 점진적으로 수정할 수 있습니다.

배부는 차원을 사용해 *무엇을 무엇에 배부할지* 결정합니다.

자세히 보기: [차원](/ko/guides/dimensions/)

## 배부

**배부**는 동인 데이터와 규칙에 따라 한 행 집합의 값을 다른 행 집합으로 분배합니다. 이전 가격, 활동 기준 원가 계산, IT 비용 청구, 수익성 분석 등 소비자 간에 분배해야 하는 비용 풀이 있을 때마다 사용합니다.

배부는 테이블(값, 동인, 결과), 차원(규칙), 워크플로 단계(모델 실행)를 조합합니다.

자세히 보기: [배부](/ko/guides/allocations/)

## 대시보드

**대시보드**는 프로젝트 데이터의 게시된 대화형 보기입니다. 게시된 테이블과 뷰를 기반으로 구축합니다.

자세히 보기: [대시보드](/ko/guides/dashboards/)

## AI 어시스턴트

데이터와 워크플로에 대해 질문하는 프로젝트 범위의 채팅입니다. 대화는 유지되며 프로젝트별로 격리됩니다.

자세히 보기: [AI 어시스턴트](/ko/guides/ai-assistant/)

## 전체 구성 요소의 연결

일반적인 엔드투엔드 흐름은 다음과 같습니다.

1. 원본 시스템에 대한 **연결을 설정**합니다.
2. **프로젝트** 안에서 다음을 수행하는 **워크플로**를 구축합니다.
   - 연결을 통해 데이터를 **가져옵니다**(테이블 생성).
   - 테이블 단계로 **변환합니다**.
   - 컨텍스트를 위해 **차원**과 **조인합니다**.
   - 비용을 분산하는 경우 **배부합니다**.
   - 결과를 **게시합니다**.
3. **대시보드**가 게시된 테이블을 읽습니다.
4. **워크스페이스 멤버**는 대시보드를 둘러보거나 AI 어시스턴트를 통해 결과를 쿼리합니다.
