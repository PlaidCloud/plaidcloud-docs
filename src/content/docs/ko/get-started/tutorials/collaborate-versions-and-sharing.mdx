*약 25분 · 버전 기록, 비교, 공유 링크*

여러 사람이 같은 프로젝트에서 작업할 때 첫날부터 중요한 질문은 늘 같습니다. *무엇이 바뀌었나? 이전 상태로 되돌릴 수 있나? 한 프로젝트의 변경 사항을 다른 프로젝트로 옮기려면 어떻게 하나? 지금 보고 있는 항목으로 동료를 바로 안내하려면 어떻게 하나?* PlaidCloud는 이 네 가지에 기본으로 답합니다. 작업은 **버전이 관리되고, 비교할 수 있으며, 공유할 수 있습니다**. 이 튜토리얼에서 각각을 차례로 살펴봅니다.

기억해야 할 메시지는 이것입니다. 사라지는 것은 없습니다. 모든 변경이 추적되고, 어떤 두 프로젝트든 비교할 수 있으며, 모든 화면에 링크가 있습니다.

## 진행할 내용

1. 프로젝트의 자동 변경 기록을 확인하고 로그를 읽습니다.
2. 두 프로젝트를 비교하고 병합이 하는 일을 이해합니다.
3. 나중에 다시 찾을 수 있도록 레이블로 작업을 정리합니다.
4. 동료를 정확한 위치로 안내하는 딥 링크를 복사합니다.

## 사전 요구 사항

- PlaidCloud 워크스페이스와 열 수 있는 프로젝트.
- 실제 콘텐츠로 비교를 체험하려면 두 번째 프로젝트(복사본 또는 QA/프로덕션 상대 프로젝트). [복사한 프로젝트](/ko/guides/projects/managing-projects/#프로젝트-복사)가 적합합니다.

## 1부: 작업의 버전이 관리됩니다

프로젝트에서 만드는 모든 것이 자동으로 추적되며, 이 기능을 따로 켤 필요가 없습니다.

> **사라지는 것은 없습니다.** 워크플로, 데이터 편집기, 계층, 테이블 구조, 사용자 정의 함수를 포함한 프로젝트의 모든 변경 사항이 추적되며 **특정 시점 복구**가 가능합니다. 즉, 실수로 변경한 내용을 복구할 수 있고 이전 시점을 비교용으로 복사해 낼 수 있습니다.

이러한 자동 추적에 더해 프로젝트와 그 요소는 **버전 관리**를 지원합니다. 버전 만들기는 쉬우며, **한 버전의 변경 사항을 다른 버전으로 병합**할 수 있습니다. 스냅샷을 보관하거나, 한 버전에서 개발하다가 준비되면 변경 사항을 비개발 버전에 병합하는 간단한 방법입니다.

### 프로젝트 로그 읽기

프로젝트 로그는 개별 워크플로 로그를 모두 하나로 모아 멤버 지정, 워크플로 실행 등 프로젝트 활동을 한곳에서 보여 줍니다.

1. **분석**을 엽니다.
2. **프로젝트**를 선택합니다.
3. **로그** 탭(프로젝트 로그)을 엽니다.

내용이 많은 로그를 좁히려면 로그 메시지 옆의 필터 컨트롤을 사용하여 필터 조건을 선택합니다. 항목 하나를 전체로 읽으려면 마우스 오른쪽 버튼으로 클릭하고 **로그 메시지** 상자를 확인합니다.

> **로그를 지우면 하위 로그도 삭제됩니다.** **로그 지우기** 버튼은 프로젝트 로그와 그 아래의 모든 워크플로 하위 로그를 *함께* 제거합니다. 해당 기록이 정말 필요 없을 때만 지우십시오.

## 2부: 두 프로젝트 비교하기

비교를 사용하면 두 프로젝트의 차이를 정확히 확인하고, 안전하게 복사할 수 있는 부분에 대해서는 선택한 변경 사항을 한 프로젝트에서 다른 프로젝트로 병합할 수 있습니다. 일상적인 두 가지 상황에 적합합니다. **환경 간 변경 사항 승격**(QA 프로젝트를 프로덕션 상대 프로젝트로)과 **이전 복사본과 비교 검토**(매월 복제본에서 무엇이 바뀌었는지 확인)입니다.

처음부터 끝까지 사용자가 제어합니다. 특정 항목을 선택해 적용하기 전에는 아무것도 기록되지 않으며, 먼저 테스트 실행으로 검증할 수 있습니다.

### 비교 열기

1. **분석**을 열고 **프로젝트**를 선택합니다.
2. 시작할 프로젝트를 마우스 오른쪽 버튼으로 클릭하거나(또는 해당 프로젝트의 작업 메뉴 사용) **비교 대상...** 을 선택합니다.
3. 시작한 프로젝트가 **소스**로 채워집니다. 드롭다운에서 **대상**을 선택합니다.
4. **비교**를 클릭합니다.

두 프로젝트는 같은 워크스페이스에 있어야 합니다. 비교하기 전에 **바꾸기**를 사용하여 소스와 대상을 서로 바꿀 수 있습니다. 병합은 소스*에서* 대상*으로* 복사하므로 방향이 중요합니다.

### 비교 결과 읽기

왼쪽에는 모든 차이가 범주별로 그룹화되어 표시됩니다. **워크플로**(**단계**가 중첩됨), **변수**, **차원**, **편집기**, **UDF**, **뷰**, **테이블**입니다. 각 항목에는 상태 배지가 붙습니다.

| 배지 | 의미 |
|---|---|
| **추가됨** | 소스에는 있고 대상에는 없음 (대상에 생성됨) |
| **수정됨** | 양쪽에 있지만 구성이 다름 |
| **삭제됨** | 대상에는 있고 소스에는 없음 |
| **변경 없음** | 양쪽이 동일함 (기본적으로 숨겨짐) |

변경된 항목을 선택하면 오른쪽에 **필드 / 소스 / 대상** 테이블이 표시되고, 그 아래에 전체 **구성 차이**가 표시됩니다. 긴 목록에 집중하려면 이름 또는 경로로 필터링하거나 상태 확인란을 전환하십시오.

### 병합이 하는 일 이해하기

모든 차이를 안전하게 복사할 수 있는 것은 아니므로, 비교에서는 각 항목에 레이블을 붙입니다.

- **워크플로, 단계, 변수**는 병합할 수 있습니다.
- **차원, 편집기, UDF, 뷰, 테이블**은 **보기 전용**입니다. 여기서 검토하되, 각각의 전용 도구로 복사해야 합니다.

병합하려면 병합 가능한 항목을 선택하고, **테스트 실행**을 클릭하여 기록 없이 검증한 다음, **적용**하고 확인합니다. 병합된 항목은 대상에서 식별 정보를 유지하므로, 나중에 다시 비교하고 중복 없이 추가 변경 사항을 병합할 수 있습니다.

> **병합은 대상을 변경합니다.** 적용하기 전에 차이를 검토하고, 테스트 실행을 하고, 소스와 대상의 방향이 맞는지 확인하십시오. 비교를 불러온 뒤 다른 사람이 대상을 편집했다면 병합은 그 작업을 덮어쓰지 않고 중단됩니다. 새로 고침한 다음 다시 적용하십시오.

서로 복사된 프로젝트 사이에서 개발 → QA → 프로덕션으로 승격하려면 [복사한 원본 프로젝트에서 다시 동기화](/ko/guides/projects/compare-and-merge-projects/#복사해-온-프로젝트에서-다시-동기화하기)를 참조하십시오. 이 방법은 이름이 아니라 복사 계보로 항목을 짝짓습니다.

## 3부: 레이블로 정리하기

**레이블**은 프로젝트 자체와 그 워크플로, 단계, 테이블, 차원, 데이터 편집기, UDF 등 개체에 붙이는 자유 형식 태그입니다. 작업 단계, 소스 시스템, 소유자, 릴리스 등 중요한 기준으로 관련 항목을 묶어 두고 빠르게 다시 찾을 수 있습니다.

태그를 붙일 수 있는 모든 개체의 세부 정보 패널에는 **레이블** 상자가 있습니다.

1. **레이블** 상자의 아무 곳이나 클릭하여 커서를 놓습니다.
2. 레이블 텍스트를 입력합니다.
3. **Enter**를 누르거나(또는 쉼표를 입력하여) 추가합니다.

칩의 **×** 로 레이블을 제거하거나, 입력 필드가 비어 있을 때 **Backspace**를 눌러 마지막 레이블을 삭제합니다.

> **레이블은 소문자로 저장됩니다.** PlaidCloud는 각 레이블을 자동으로 소문자로 바꾸고 같은 개체의 중복 레이블은 허용하지 않습니다. 레이블 체계를 일관되게 유지하면 큰 프로젝트를 나눠 보는 가벼운 방법이 됩니다.

태그가 붙은 항목을 찾으려면 프로젝트 목록의 필터 상자에 레이블을 입력하십시오. 검색은 항목 이름과 함께 레이블 텍스트도 찾습니다.

## 4부: 딥 링크 공유하기

PlaidCloud는 주소 표시줄을 열려 있는 항목과 항상 맞춥니다. 워크플로, 테이블 또는 차원을 열면 URL이 해당 항목으로의 **딥 링크**가 됩니다. 별도의 공유 버튼은 없으며, 주소 표시줄 *자체가* 링크입니다.

1. 공유할 개체를 엽니다.
2. 브라우저 주소 표시줄에서 URL 전체를 복사합니다.
3. 보냅니다. 링크를 여는 사람은 같은 화면으로 이동합니다.

링크는 프로젝트가 우선입니다. 프로젝트가 먼저 오고, 그 안의 개체가 `~`로 구분되어 이어집니다.

| 화면 | 링크 끝부분 |
|---|---|
| 프로젝트 | `#p~<project>` |
| 워크플로(단계 그리드) | `#p~<project>~w~<workflow>` |
| 워크플로(시각적 워크플로 디자이너 캔버스) | `#p~<project>~c~<workflow>` |
| 워크플로 안의 단계 | `…~w~<workflow>~s~<step>` |
| 테이블 탐색기 | `#p~<project>~t~<table>` |
| 차원 계층 | `#p~<project>~d~<dimension>` |
| 데이터 편집기 | `#p~<project>~e~<editor>` |

링크를 열면 창 하나만이 아니라 **상위 컨텍스트**가 복원됩니다. 워크플로 링크는 해당 프로젝트도 함께 다시 열어, 받는 사람이 탭 표시줄에 주변 프로젝트가 있는 상태로 도착합니다. 단계 링크는 해당 단계를 선택까지 해 줍니다.

> **링크에는 *위치*만 담기며 권한은 담기지 않습니다.** 링크를 여는 사람에게도 프로젝트에 대한 액세스 권한이 필요합니다. 권한이 없는 사람에게는 개체가 표시되지 않으므로 링크를 공유해도 안전합니다. 누가 무엇을 볼 수 있는지는 [데이터 액세스 제어](/ko/get-started/tutorials/control-data-access/)에서 제어합니다.

이전의 `#te?p=…&t=…` 형식 링크도 계속 작동하며, 처음 이동할 때 현재의 더 읽기 쉬운 형식으로 조용히 다시 작성됩니다.

**사라지는 것은 없으며, 이제 직접 보여 줄 수 있습니다.** 프로젝트의 기록을 읽고, 두 프로젝트를 비교하여 한 방향으로 안전하게 병합하고, 나중에 찾을 수 있도록 레이블로 작업을 정리하고, 동료를 지금 있는 위치로 바로 안내하는 딥 링크를 전달했습니다.
