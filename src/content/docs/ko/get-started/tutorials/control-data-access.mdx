*약 20분 · 보안 그룹, 할당된 멤버, 범위가 지정된 액세스*

방금 PlaidCloud 워크스페이스의 관리자가 되었고, 사람들이 들어오기를 기다리고 있지만 모든 사람이 모든 것을 볼 수 있어서는 안 됩니다. 이 튜토리얼에서는 전체 과정을 한 번에 따라갑니다. 적합한 사람들을 워크스페이스에 들어오게 하고, 일련의 권한을 **보안 그룹**으로 묶고, 멤버를 그룹에 할당한 다음, 그룹이 접근할 수 있는 범위를 프로젝트 단위로, 그리고 설정된 경우 개별 행 단위까지 좁힙니다.

여러분이 다루게 될 요소인 조직, 워크스페이스, 멤버, 보안 그룹은 정해진 방식으로 서로 맞물립니다. 이 모델이 낯설다면 먼저 다이어그램이 있는 [ID 및 액세스 관리(IAM)](/ko/administration/access/)를 읽어 보십시오. 요약하면 조직에는 워크스페이스가 있고, 워크스페이스에는 멤버가 있으며, **보안 그룹은 하나의 워크스페이스 안에서 멤버를 할당하는 권한 묶음**입니다. 여기서 하는 어떤 작업도 워크스페이스 간에 영향을 주지 않으며, 각 워크스페이스는 자체 액세스를 관리합니다.

이후 작업은 대부분 워크스페이스 왼쪽의 **ID** 탭에서 이루어집니다. 그곳에서 보안을 관리할 수 있을 만큼의 관리 권한이 필요합니다.

> **가지고 있는 권한만 부여할 수 있습니다.** 그룹의 권한을 저장할 때 PlaidCloud는 본인이 가지고 있지 않은 권한을 표시하지도 않고 조용히 그대로 둡니다. 부여해야 하는 기능이 매트릭스에 없다면 해당 권한을 가진 사람에게 요청하십시오. 매트릭스에서는 본인이 제어할 수 있는 권한만 편집할 수 있습니다.

## 1단계: 적합한 사람들을 워크스페이스에 들어오게 하기

보안 그룹은 이미 워크스페이스에 있는 멤버에게만 할당할 수 있으므로 여기서 시작합니다. 멤버는 **조직**에 속해 있어야 하며 멤버 관리 양식에 표시되어야 워크스페이스에 추가할 수 있습니다.

워크스페이스에 새 멤버를 추가하려면 다음과 같이 합니다.

1. **ID**를 열고 **멤버** 탭을 선택합니다.
2. 드롭다운 메뉴에서 **모두**를 클릭하여 현재 멤버를 나열합니다.
3. **작업 영역 멤버 추가**를 클릭하고 필수 필드를 입력한 다음 **만들기**를 클릭합니다.

새 멤버에게는 로그인 자격 증명이 포함된 환영 이메일이 자동으로 발송됩니다. 이미 조직에 있는 사람을 *이* 워크스페이스에 추가하려면 **Organization Settings**(오른쪽 위 메뉴) → **Workspaces** → 멤버 아이콘을 사용하여 해당 사람을 워크스페이스로 끌어다 놓고 **제출**을 클릭합니다. 그 사람이 아직 조직에 전혀 속해 있지 않다면 같은 화면의 초대 아이콘을 사용하여 이메일로 초대장을 보내십시오.

> **멤버십은 바깥쪽 관문이며 세밀한 제어 수단이 아닙니다.** 워크스페이스에 속해 있으면 멤버가 워크스페이스에 접근할 수 있을 뿐입니다. 안에 들어온 뒤 *무엇을* 할 수 있는지는 해당 멤버가 할당된 보안 그룹이 결정하며, 이는 다음 세 단계에서 다룹니다.

추가, 초대, 제거의 전체 절차는 [작업 영역 멤버 관리](/ko/administration/access/overview/managing-workspace-members/)와 [멤버 관리](/ko/administration/access/member-management/)를 참고하십시오.

## 2단계: 보안 그룹 만들기

보안 그룹은 이름이 지정된 권한 묶음입니다. 한 사람씩 기능을 부여하는 대신 묶음을 한 번 정의하고 거기에 사람들을 할당합니다.

1. **ID**를 열고 **보안** 탭을 선택합니다.
2. 드롭다운 메뉴에서 **보안 그룹**을 클릭합니다. 기존 그룹이 양식에 표시됩니다.
3. **보안 그룹 만들기**를 클릭하고 `Analysts`, `Report Viewers`, `Workspace Admins`처럼 역할에 기반한 명확한 이름을 지정합니다.
4. 그룹의 권한을 설정하려면 그룹 옆의 가장 왼쪽 아이콘을 클릭하여 권한 매트릭스를 열고, 이 그룹이 가져야 할 기능을 선택한 다음 저장합니다.

매트릭스에서 사용할 수 있는 권한은 워크스페이스에 있는 애플리케이션에서 가져오며, 각 애플리케이션이 자체 권한 집합을 게시합니다. 그룹을 만들기 전에 애플리케이션이 제공하는 전체 목록을 살펴보려면 **보안** 드롭다운에서 **Security Bins**를 클릭하고 왼쪽의 태그 아이콘으로 애플리케이션을 엽니다. 이 보기는 정보 제공용이며, 실제 권한 부여는 위의 그룹 매트릭스에서 합니다.

> **그룹은 많게 말고 적게.** 워크스페이스에서는 보안 그룹을 무제한으로 만들 수 있지만, 그룹이 하나 늘 때마다 감사 시점에 따져 봐야 할 대상이 하나 늘어납니다. 사람들이 공유하는 실제 역할을 기준으로 그룹을 구성하고, 업무가 허용하는 한 그룹 수를 적게 유지하십시오.

## 3단계: 그룹에 멤버 할당하기

그룹을 정의했으면 사람들을 그룹에 넣습니다.

1. **ID → 보안 → 보안 그룹**에서 그룹 옆의 **멤버** 아이콘을 클릭합니다.
2. 이 그룹의 권한을 가져야 하는 사람들을 **할당되지 않은 멤버** 열에서 **할당된 멤버** 열로 끌어다 놓습니다. 누군가에게서 그룹을 제거하려면 반대 방향으로 다시 끌어다 놓습니다.
3. 저장합니다.

이것이 권한 부여의 전부입니다. **할당된 멤버** 열에 있는 멤버는 그룹이 묶은 모든 권한을 가지며, 그렇지 않은 멤버는 가지지 않습니다.

> **빈 할당은 의도적으로 아무 동작도 하지 않습니다.** **할당된 멤버** 열을 비워 둔 채 그룹을 저장하면 변경 사항이 없으며 그 사실을 알려 줍니다. 모든 사람에게서 그룹의 권한을 없애려면 그룹의 권한을 제거하거나 그룹을 삭제하십시오. 멤버 목록을 비워서 권한을 철회하려고 하지 마십시오.

### 선택 사항: 그룹을 신규 멤버의 기본값으로 지정하기

모든 신규 멤버가 기본 권한(예: 공유 보고서에 대한 읽기 액세스)으로 시작해야 한다면 그룹을 기본값으로 표시하십시오. 그러면 신규 멤버가 자동으로 해당 그룹에 할당되므로 직접 할당하는 것을 잊지 않아도 됩니다. 그룹을 만들거나 편집할 때 보안 그룹 창 하단의 **신규 사용자에게 기본으로 할당**을 선택합니다.

## 4단계: 그룹이 접근할 수 있는 범위 설정하기

이제 정의된 권한 집합을 가진 멤버가 생겼습니다. PlaidCloud는 **조직 → 워크스페이스 → 프로젝트**의 단계적인 계층으로 액세스 범위를 지정하므로 바깥쪽에서 안쪽으로 점점 좁힐 수 있습니다.

| 계층 | 제어 대상 | 설정 위치 |
|---|---|---|
| 워크스페이스 | 멤버가 워크스페이스에 접근할 수 있는지 여부 | 워크스페이스 멤버십(1단계) |
| 보안 그룹 | 안에 들어온 뒤 가지는 기능 | 그룹 권한(2단계) |
| 프로젝트 | 아키텍트 및 기타 프로젝트 수준 권한 | 프로젝트별 보안 그룹 권한 |
| 행(선택 사항) | 그룹이 볼 수 있는 관리 대상 테이블의 *행* | 행 액세스(아래 참조) |

대부분의 팀에서는 처음 세 계층이면 충분합니다. 사람들을 워크스페이스에 넣고, 각 그룹에는 역할에 필요한 권한만 부여하며, 프로젝트에 대한 **아키텍트** 같은 프로젝트 수준 권한은 그룹의 권한을 통해 범위를 지정합니다. 프로젝트에 대한 권한이 없는 그룹은 해당 프로젝트에서 아무 작업도 할 수 없습니다.

### 행 단위 제어가 필요한 경우

두 사람이 *같은* 테이블을 보되 *서로 다른 행*을 봐야 하는 경우, 예를 들어 지역 관리자가 각자 자기 지역만 봐야 한다면 **행 액세스**를 사용하십시오. 프로젝트의 열(예: `region`)을 보안 그룹이 볼 수 있는 행을 결정하는 기준으로 지정한 다음, 특정 값(`East`, `Central`)을 특정 그룹에 부여할 수 있습니다. 이는 가장 세밀한 계층이며 선택 사항입니다. 사용하지 않으면 그룹은 다른 권한이 허용하는 모든 행을 봅니다.

프로젝트 아키텍트는 **테이블 탐색기**의 테이블, 열의 패싯 메뉴 또는 프로젝트의 보안 탭에서 행 액세스를 열 수 있으며, 저장하면 즉시 적용됩니다. 대시보드에는 약 1분 이내에 반영되며 추가로 적용할 작업은 없습니다. 열 제한, 값 부여, 대시보드에 반영되는 과정 등 구체적인 방법은 [행 액세스 관리](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리)에서 자세히 다루며, 이 튜토리얼은 의도적으로 그곳을 안내하는 데까지만 다룹니다.

> **행 액세스는 사람이 데이터를 읽는 모든 곳에서 그 사람을 따라갑니다.** 저장하고 나면 그룹의 행 권한 부여가 대시보드와 보는 사람의 권한으로 읽는 앱에서 해당 멤버가 보는 내용을 필터링합니다. 이는 Panel 앱이 로그인한 사용자로 인증할 때 사용하는 사용자별 모델과 같습니다. 해당 경로는 [데이터 읽기와 로그인한 사용자](/ko/guides/panel-apps/accessing-data/)를 참고하십시오.

> **행을 제한하면 프로젝트를 변경할 수 있는 사람도 좁아집니다.** 프로젝트가 열을 제한하면 아키텍트와 테넌트 관리자만 해당 프로젝트의 워크플로, 단계, 사용자 정의 함수, 일정, 변수를 변경할 수 있으며, 다른 사람은 여전히 이를 실행할 수 있습니다. [행을 제한하는 프로젝트를 변경할 수 있는 사람](/ko/administration/access/managing-security-groups-and-assignments/#행을-제한하는-프로젝트를-변경할-수-있는-사람)을 참고하십시오.

## 5단계: 작업 결과 확인하기

완료했다고 판단하기 전에 할당이 의도한 대로인지 확인하십시오.

1. **ID → 보안**을 열고 드롭다운 메뉴에서 **보안 그룹 감사**를 클릭합니다.
2. 모든 멤버와 그룹의 그룹 멤버십을 한곳에서 검토합니다.
3. 기록을 남기려면 표에서 **사용자 이름** 오른쪽 끝에 있는 아이콘을 클릭하고 **CSV 내보내기** 또는 **Export XLSX**를 선택합니다.

역할이 바뀔 때마다 이 감사를 다시 실행하십시오. 누가 어떤 그룹에 속해 있는지 전체 그림을 보여 주는 유일한 화면입니다.

**설정이 끝났습니다.** 이제 보안 그룹, 그 그룹에 할당된 멤버, 그리고 워크스페이스에서 프로젝트까지, 필요한 경우 개별 행까지 범위가 지정된 액세스가 준비되었습니다.
