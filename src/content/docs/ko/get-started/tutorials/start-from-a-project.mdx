*약 15분 · 프로젝트 복사 또는 가져오기 후 자신에게 맞게 변경*

PlaidCloud에서 첫날 가장 빠르게 성과를 내는 방법은 아무것도 없는 상태에서 만드는 것이 아니라 이미 작동하는 것에서 시작하는 것입니다. 데이터를 가져오고, 변환하고, 결과를 생성하는 프로젝트를 골라 자신의 사본을 만든 다음, 자신에게 해당하는 부분을 변경하십시오.

둘러볼 템플릿 갤러리는 없습니다. 대신 작동하는 프로젝트에서 시작하는 두 가지 확실한 방법이 있습니다.

- 워크스페이스에 이미 있는 **프로젝트를 복사**하여 자신만의 새 프로젝트를 만듭니다. [프로젝트 복사](/ko/guides/projects/managing-projects/#프로젝트-복사)를 참조하십시오.
- **이식 가능한 번들을 실행**합니다. 누군가 독립적인 [이식 가능한 형식](/ko/guides/projects/export-to-portable-format/) 패키지로 내보낸 프로젝트이며, PlaidCloud 밖에서 단독으로 실행됩니다.

어느 쪽이 적합한지는 앞으로 어떻게 할지에 따라 다릅니다.

## 사전 요구 사항

- PlaidCloud 워크스페이스(없는 경우 [무료 체험을 시작하십시오](https://app.plaidcloud.com)).
- **경로 A**의 경우: **프로젝트** 탭에서 볼 수 있는 기존 프로젝트. 직접 만든 프로젝트, 공유된 샘플 또는 동료가 액세스 권한을 부여한 프로젝트면 됩니다.
- **경로 B**의 경우: 누군가 내보낸 이식 가능한 형식의 `.zip` 또는 내보낼 수 있는 직접 만든 프로젝트.

> **프로젝트가 무엇인지 잘 모르시나요?** 프로젝트는 PlaidCloud의 작업 단위입니다. 자체 데이터, 워크플로, 차원, 기록을 소유하며 다른 프로젝트와 상태를 공유하지 않습니다. 처음이라면 [프로젝트](/ko/guides/projects/)를 먼저 읽으십시오.

## 경로 A: 기존 프로젝트 복사

복사하면 전체 또는 선택한 일부를 완전히 사용자 소유인 새 프로젝트에 편집 가능한 전체 복제본으로 만듭니다.

1. **분석**을 열고 **프로젝트** 탭을 선택합니다.
2. 시작할 프로젝트를 선택합니다.
3. **작업** 버튼을 클릭하고 **프로젝트 복사**를 선택합니다.
4. 대상으로 **새 프로젝트**를 선택합니다. 이름과 **ID**를 지정합니다.
5. 프로젝트 전체를 가져오려면 선택 트리를 모두 선택한 상태로 두고 **프로젝트 복사**를 클릭합니다.

> **ID는 영구적입니다.** 새 프로젝트에 지정한 ID는 스키마 이름이 되며 나중에 변경할 수 없습니다. 계속 사용해도 좋은 ID를 선택하십시오. 이름은 언제든 자유롭게 변경할 수 있지만 ID는 그렇지 않습니다.

복사는 백그라운드에서 실행되며 완료되면 알림을 받습니다. 전체 대화 상자는 [프로젝트 복사](/ko/guides/projects/managing-projects/#프로젝트-복사)를 참조하십시오.

### 원하는 부분만 가져오기

모든 것을 복사할 필요는 없습니다. 선택 트리는 프로젝트에 있는 항목을 워크플로, 단계, 테이블, 차원, 데이터 편집기, 사용자 정의 함수 등 유형별로 나열하며, 원하는 부분만 선택할 수 있습니다. 선택한 항목은 종속 항목을 자동으로 함께 가져옵니다. 단계가 읽고 쓰는 테이블, 단계가 로드하는 차원, 호출하는 함수, 호출하는 하위 워크플로가 포함됩니다. 이러한 종속성을 직접 파악할 필요가 없습니다.

> **참조가 사본을 가리키도록 유지하십시오.** **참조 업데이트**를 켠 상태(기본값)로 두십시오. 복사된 단계가 원본이 아니라 새 프로젝트의 테이블과 개체를 가리키도록 다시 작성하며, 거의 항상 원하는 동작입니다. 사본이 계속 원본 프로젝트의 개체를 읽도록 의도한 경우에만 끄십시오.

## 경로 B: 이식 가능한 번들에서 시작

이식 가능한 번들은 PlaidCloud에 연결하지 않고 [DuckDB](https://duckdb.org)에서 실행되는 독립적인 Python 프로그램으로 패키징된 프로젝트입니다. 작동하는 프로젝트를 노트북, CI 작업, PlaidCloud 로그인이 없는 사람의 환경 등 *플랫폼 밖*에서 실행하려는 경우 여기서 시작하는 방법입니다.

동료에게 이미 번들을 받았다면 [실행](#실행)으로 건너뛰십시오. 직접 만들려면 다음과 같이 합니다.

1. **분석**을 열고 **프로젝트** 탭을 선택합니다.
2. 프로젝트 하나를 선택합니다.
3. **작업** 메뉴를 열고 **이식 가능한 형식으로 내보내기**를 선택합니다.
4. 패키지를 기록할 **문서 계정**과 **폴더 경로**를 설정하고, 외부 소스 없이 실행되도록 **Include data**를 선택한 상태로 두고 **내보내기**를 클릭합니다.

결과는 워크플로당 하나의 Python 스크립트, Parquet 데이터 스냅샷, 스크립트에 필요한 Python 패키지를 나열한 `requirements.txt`, 그리고 `README.md`, `COVERAGE.md`, `RUN_ORDER.md`가 들어 있는 `.zip`입니다. 각 파일에 대한 설명은 [이식 가능한 형식으로 내보내기](/ko/guides/projects/export-to-portable-format/)를 참조하십시오.

> **이식 가능한 번들은 다시 가져오기가 아니라 단방향 스냅샷입니다.** PlaidCloud *밖*에서 실행되며 다시 동기화되지 않습니다. 패키지에 변경한 내용은 프로젝트로 돌아가지 않으며, 편집 후 다시 내보내면 새 패키지가 생성됩니다. PlaidCloud 안에서 계속 작업하려면 대신 **경로 A**를 사용하십시오. PlaidCloud에서 계속 반복 작업하면서 실행 가능한 사본도 배포하려면 둘 다 수행하십시오.

> **충실도는 최선을 다하는 수준입니다.** SQL 변환 단계는 그대로 재현됩니다. 배부, 차원 로드, 알림, 문서 및 보고서 단계, 스크립트 같은 독점 단계와 부수 효과가 있는 단계는 다시 실행되지 않는 스텁으로 내보내지며, 대신 마지막으로 구체화된 출력이 스냅샷으로 번들에 포함됩니다. 각 단계의 충실도는 `COVERAGE.md`에 기록됩니다. 결과를 완전히 다시 계산하려면 PlaidCloud에서 프로젝트를 실행하십시오.

### 실행

패키지의 압축을 풀고 Python 환경을 만든 다음 `RUN_ORDER.md`에 나열된 순서대로 각 워크플로 스크립트를 실행합니다.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python pipeline_<workflow>.py
```

각 스크립트는 로컬 DuckDB 데이터베이스에 테이블을 만듭니다. SQL 단계는 실시간으로 다시 계산되고, 스텁 처리된 단계는 스냅샷으로 저장된 출력을 그대로 둡니다.

## 자신에게 맞게 바꾸기

어떤 방법으로 시작했든 이제 사본은 변경할 수 있는 사용자의 것입니다. 첫날의 성과가 결실을 맺는 지점입니다. 처음 해 볼 만한 작업은 다음과 같습니다.

| 작업 | 위치 |
|---|---|
| 가져오기가 샘플 대신 *사용자의* 데이터를 가리키도록 설정 | 각 워크플로의 가져오기 단계 — [데이터 로드, 변환 및 게시](/ko/get-started/tutorials/load-and-transform-data/) 참조 |
| 프로젝트 이름 변경 또는 열 수 있는 사용자 조정 | [프로젝트 관리](/ko/guides/projects/managing-projects/) → 액세스 제어 |
| 워크플로 전반에서 반복되는 값에 프로젝트 변수 설정 | [프로젝트 변수 관리](/ko/guides/projects/managing-projects/#프로젝트-변수-관리) |
| 전체가 처음부터 끝까지 여전히 실행되는지 확인 | 각 워크플로에서 **실행**을 클릭하고 로그 확인 |

모든 변경 사항이 추적되므로 자유롭게 실험할 수 있습니다. [자동 변경 추적](/ko/guides/projects/managing-projects/#버전-기록)을 사용하면 편집이 잘못되었을 때 이전의 특정 시점 상태로 복구할 수 있습니다.
