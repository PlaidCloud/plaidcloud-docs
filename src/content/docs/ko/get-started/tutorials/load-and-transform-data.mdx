이 튜토리얼은 약 1시간이 걸립니다. 마치고 나면 CSV를 가져오고, 몇 개의 테이블 단계로 변환하고, 결과를 게시하는 동작하는 워크플로가 생깁니다.

## 만들 내용

원시 판매 CSV를 가져와 정리하고, 제품 참조 테이블과 조인하고, 파생 열을 계산한 다음, 결과를 깨끗한 팩트 테이블로 게시하는 워크플로입니다.

```text
sales.csv  →  import  →  filter  →  join with products  →  add columns  →  publish
                              ↓
                       products.csv  →  import
```

## 사전 요구 사항

- PlaidCloud 워크스페이스(없다면 [무료 체험을 시작](https://app.plaidcloud.com)하십시오)
- 작업할 프로젝트(필요하면 **프로젝트** 탭에서 만드십시오)
- 가져올 CSV 파일 두 개. 이 튜토리얼에서는 간단한 판매 거래 파일과 제품 카탈로그 파일을 사용합니다. 직접 준비한 파일을 사용하거나 아무 스프레드시트 도구로 샘플 데이터를 생성해도 됩니다

## 1단계: 워크플로 만들기

<Steps>

1. 프로젝트를 열고 **워크플로** 탭으로 전환합니다.
2. **새 워크플로**를 클릭합니다. "Sales Cleanup"처럼 설명이 되는 이름을 지정합니다.
3. **만들기**를 클릭합니다. 빈 워크플로가 목록에 나타납니다.
4. 워크플로를 두 번 클릭하여 워크플로 탐색기를 엽니다.

</Steps>

## 2단계: 판매 CSV 가져오기

<Steps>

1. 워크플로 탐색기에서 새 단계를 추가합니다.
2. **Import → CSV**(또는 소스 형식에 맞는 다른 가져오기 단계)를 선택합니다.
3. 단계 구성에서 다음을 설정합니다.
   - **소스 파일** — 판매 CSV를 지정합니다(업로드하거나 연결된 문서 계정에서 선택)
   - **대상 테이블** — 이름을 `sales_raw`로 지정합니다
   - **구분 기호, 따옴표 문자, 머리글 행** — 파일이 표준 형식이 아니면 조정합니다
4. 단계를 실행합니다. CSV가 프로젝트에 새 테이블로 적재됩니다.

</Steps>

**테이블** 탭에서 `sales_raw`를 확인하십시오. 클릭해서 열 개수, 샘플 행, 데이터 형식 등 데이터가 올바른지 확인합니다.

## 3단계: 제품 카탈로그 가져오기

제품 CSV로 2단계를 반복하고, 대상 테이블 이름은 `products_raw`로 지정합니다. 이렇게 하면 조인에 필요한 참조 테이블 두 개가 준비됩니다.

## 4단계: 잘못된 행 걸러내기

실제 판매 데이터에는 공백이 있습니다. null 금액, 테스트 거래, 주 팩트 테이블에 포함하고 싶지 않은 환불 등입니다. 필터 단계를 추가하여 제거하십시오.

<Steps>

1. **테이블 → Table Lookup** 단계(또는 필터링할 수 있는 다른 테이블 변환)를 추가합니다.
2. 다음과 같이 구성합니다.
   - **소스 테이블**: `sales_raw`
   - **대상 테이블**: `sales_clean`
   - **필터 조건**: 예: `amount > 0 AND status = 'completed'`
3. 단계를 실행합니다. `sales_clean`의 행이 `sales_raw`보다 적어야 합니다.

</Steps>

<Aside>
필터는 데이터가 소스에서 대상으로 흐르는 동안 적용됩니다. 소스 테이블은 변경되지 않습니다. 이것은 PlaidCloud의 핵심 패턴입니다. 각 단계는 하나 이상의 소스에서 읽어 하나 이상의 대상에 쓰며, 감사 가능성을 위해 원본을 그대로 유지합니다.
</Aside>

## 5단계: 제품 카탈로그와 조인하기

이제 정리된 판매 행을 카탈로그의 제품 세부 정보와 결합합니다.

<Steps>

1. **테이블 → Table Inner Join** 단계를 추가합니다.
2. 다음과 같이 구성합니다.
   - **왼쪽 테이블**: `sales_clean`
   - **오른쪽 테이블**: `products_raw`
   - **조인 키**: 두 테이블을 연결하는 열(예: `product_id`)
   - **대상 테이블**: `sales_enriched`
3. 단계를 실행합니다.

</Steps>

이제 `sales_enriched`에는 두 테이블의 모든 열이 있습니다. 아마 일부만 필요할 것입니다. 그것이 다음 단계입니다.

## 6단계: 열 선택 및 계산하기

정리 작업은 일반적으로 필요하지 않은 열을 삭제하고 파생 열을 계산하는 것입니다. 다른 테이블 단계를 추가하십시오.

<Steps>

1. **테이블 → Table Lookup** 단계를 추가합니다(여기서는 열 선택과 계산에 사용합니다).
2. 다음과 같이 구성합니다.
   - **소스**: `sales_enriched`
   - **대상**: `sales_final`
   - **유지할 열**: 하위 소비자에게 필요한 부분 집합
   - **계산 열**: 예: `revenue = amount * price`, `margin = revenue - cost`
3. 단계를 실행합니다.

</Steps>

열 단위 계산에 사용할 수 있는 모든 함수(문자열 연산, 날짜 계산, 조건 논리, 집계)는 [식 참조](/ko/reference/expressions/)에서 다룹니다.

## 7단계: 결과 게시하기

`sales_final`을 대시보드와 하위 시스템에서 사용할 수 있게 합니다.

<Steps>

1. **Data → 게시** 단계를 추가합니다(또는 테이블에서 직접 **게시** 옵션을 사용합니다).
2. 게시된 테이블을 읽을 수 있는 대상을 구성합니다. 일반적으로 워크스페이스의 다른 멤버와 액세스 권한이 있는 외부 시스템입니다.
3. 단계를 실행합니다.

</Steps>

이제 게시된 테이블은 [대시보드](/ko/guides/dashboards/), BI 도구, 적절한 권한이 있는 모든 외부 소비자가 사용할 수 있습니다.

## 8단계: 전체 워크플로 실행하기

단계 하나가 아니라 워크플로의 **실행**을 클릭합니다. 각 단계가 순서대로 실행되는 동안 로그를 지켜보십시오. CSV 가져오기부터 게시까지 전체 파이프라인이 실행됩니다.

단계에서 오류가 발생하면 [단계 오류 관리](/ko/guides/workflows/managing-step-errors/) 가이드에서 디버깅 방법을 다룹니다. 가장 흔한 문제는 잘못된 조인 키(테이블 간 불일치)와 계산 열의 예기치 않은 null 값입니다.
