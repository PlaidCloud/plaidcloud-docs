*약 30분 · 준비 상태 검사, 가져오기, 검증된 실행*

Alteryx 워크플로 하나를 PlaidCloud로 처음부터 끝까지 옮겨 봅니다. 준비 상태를 검사하고, 가져와서 변환하고, 깔끔하게 변환된 부분과 확인이 필요한 부분을 파악한 다음 실행합니다. 이 튜토리얼은 모든 기능을 둘러보는 것이 아니라 자신감을 키우기 위한 첫 마이그레이션입니다. 잘 이해하고 있는 워크플로를 선택하고, 가능하면 정상으로 확인된 출력이 있는 워크플로를 선택하십시오. 그래야 변환된 실행이 올바른지 판단할 수 있습니다.

PlaidCloud의 임포터는 워크플로 그래프를 보존하고, 참조된 파일을 Document에 업로드하고, 매크로 워크플로를 생성하며, 각 Alteryx 도구를 네이티브 워크플로 단계 또는 관리형 실행기에 매핑합니다. 워크플로 대부분은 수작업을 거의 들이지 않고 변환됩니다. 이 튜토리얼에서 솔직하게 다룰 부분은 나머지입니다. 일부 도구는 주의가 필요하며, PlaidCloud가 어떤 도구인지 정확히 알려 주므로 해당 도구로 바로 이동할 수 있습니다.

## 사전 요구 사항

- PlaidCloud 워크스페이스와 가져올 프로젝트. 종속성을 쉽게 감사할 수 있도록 마이그레이션 전용 프로젝트를 사용하십시오.
- Alteryx 워크플로 파일 하나: `.yxmd`(워크플로), `.yxwz`(분석 앱) 또는 `.yxmc`(매크로).
- 해당 워크플로가 런타임에 읽는 파일. 워크플로와 함께 보관하십시오.
- PlaidCloud가 가져온 파일을 저장할 문서 계정과 폴더.

## 1단계: 준비 상태 검사

깔끔한 가져오기는 완전한 패키지에서 시작됩니다. 임포터를 열기 전에 워크플로가 사용하는 모든 항목을 모으십시오.

1. 워크플로 파일 자체와 워크플로가 호출하는 모든 매크로(중첩 매크로 포함)의 `.yxmc` 파일.
2. 입력 데이터 파일: CSV, TSV, Excel, Access, YXDB, XML, JSON 및 데이터베이스 추출 파일.
3. 같은 폴더에 있는 공간 보조 파일: 셰이프파일 그룹(`.shp`, `.shx`, `.dbf`, `.prj`), MapInfo 그룹(`.tab`, `.map`, `.id`, `.dat`) 및 모든 투영 파일. 보조 파일이 없으면 공간 데이터에 차이가 생기는 경우가 많습니다.
4. 워크플로가 참조하는 보고서 자산: 이미지, PDF, 템플릿, 지도 레이어.
5. 분석 앱의 경우 사용자가 일반적으로 입력하는 값: 텍스트, 숫자, 날짜, 파일 및 폴더 선택, 드롭다운 또는 확인란 선택 항목. 이 값은 실행 전에 설정할 워크플로 변수가 됩니다.

그런 다음 두 가지를 결정하십시오. 업로드한 파일을 보관할 Document 폴더, 그리고 이 워크플로를 구조적으로(변환되고 실행되는가?) 검증할지 정상으로 확인된 출력과 비교하여(같은 결과를 내는가?) 검증할지입니다.

> **정상으로 확인된 출력을 준비하십시오.** Alteryx 실행에서 신뢰할 수 있는 결과가 있다면 패키지와 함께 보관하십시오. 4단계에서 "실행되었다"를 "올바르다"로 바꿔 주는 기준이 됩니다.

[Alteryx 마이그레이션 준비 상태 체크리스트](/ko/guides/workflows/alteryx-migration-readiness-checklist/)는 워크플로 하나에서 포트폴리오 전체로 확장할 때 사용하는 이 단계의 전체 버전입니다.

## 2단계: 가져오기 및 변환

1. PlaidCloud에서 대상 프로젝트를 엽니다.
2. **도구 → Alteryx 워크플로 가져오기**를 엽니다.
3. 대상 프로젝트를 선택하고 `.yxmd`, `.yxwz` 또는 `.yxmc` 파일을 선택합니다.
4. 필요한 경우 워크플로, 단계, 테이블 이름 접두사를 설정합니다. 테이블 이름에는 이미 워크플로 자체 이름이 접두사로 붙으므로, 워크플로 하나에는 별도의 접두사가 필요하지 않습니다.
5. 가져온 파일을 저장할 문서 계정과 폴더를 선택합니다.
6. 워크플로가 런타임에 필요로 하는 참조 파일 또는 폴더를 추가합니다.
7. 가져오기를 시작합니다.

가져오기가 끝나면 창의 양식이 **변환 보고서**로 바뀝니다. 높은 신뢰도로 매핑된 단계 수, 검토가 필요한 단계 수, 그리고 해당하는 단계가 있으면 신뢰도가 낮은 각 단계의 이름, 작업, 신뢰도, 참고 사항을 보여 주는 테이블이 표시됩니다. 이 보고서가 마이그레이션의 핵심입니다. 표시된 모든 단계에는 캔버스의 단계 메모에도 같은 참고 사항이 있으므로 해당 단계로 바로 이동할 수 있습니다.

PlaidCloud는 가져온 종속 파일을 선택한 Document 폴더에 저장하고 변환된 단계가 해당 경로를 가리키도록 하므로, 데스크톱 파일 시스템 없이도 워크플로를 반복해서 실행할 수 있습니다.

> **주석과 컨테이너도 함께 가져옵니다.** 주석 상자는 메모와 강조 상자로, Tool Container는 그룹으로 가져옵니다. Alteryx에서와 똑같이 워크플로를 설명하며 런타임 작업은 추가하지 않습니다. **Control Container**의 게이트도 유지됩니다. 해당 단계는 게이트로 제어되는 데이터에 행이 있을 때만 실행되도록 설정된 상태로 가져옵니다.

## 3단계: 변환된 항목과 주의가 필요한 항목 검토

생성된 고급 워크플로를 열고 변환 보고서를 위에서 아래로 확인하십시오. 대부분의 단계는 높은 신뢰도로 변환되며 사용자가 할 일이 없습니다. 첫 마이그레이션에서 신뢰를 쌓는 부분은 표시된 단계입니다. 각 참고 사항을 읽고 판단하십시오.

부분 변환의 실제 모습과 각 경우의 의미는 다음과 같습니다.

| 표시 내용 | 의미 | 조치 사항 |
|---|---|---|
| 높은 신뢰도 단계 | 네이티브 단계 또는 실행기에 깔끔하게 매핑됨 | 없음 — 원하면 표본 확인 |
| 검토 대상으로 표시된 단계 | 변환되었지만 확인할 만한 주의 사항이 있음 | 참고 사항을 읽고 결과가 예상과 일치하는지 확인 |
| 변환되지 않음으로 표시된 단계 | 임포터가 잘못 추측하는 대신 변환을 거부함 | Alteryx에서 원인을 수정한 후 다시 가져오거나 단계를 직접 구성 |
| 아직 존재하지 않는 테이블에 대한 참조 | 워크플로가 만들지 않은 Calgary 또는 외부에서 구축된 데이터 세트 | 실행 전에 해당 이름의 테이블을 로드 |

첫 마이그레이션에서 자주 만나게 되는 표시 항목은 다음과 같습니다.

- **무작위 샘플링**(Create Samples, Random % Sample)은 크기와 비율이 정확히 이전되지만, PlaidCloud는 자체적으로 레코드를 추출합니다. 어떤 행이 선택되었는지가 아니라 개수와 비율을 기준으로 검증하십시오.
- **XGBoost 모델**은 scikit-learn 그래디언트 부스팅 분류기로 변환됩니다. 값이 동일하지는 않고 통계적으로 동등한 결과가 나오므로 단계의 참고 사항을 확인하십시오.
- **변환되지 않은 단계는 워크플로가 해당 단계에 도달하면 의도적으로 실패합니다.** 따라서 해결되지 않은 게이트나 누락된 테이블이 있는 변환을 아무 문제 없는 것처럼 끝까지 실행할 수 없습니다. 이 투명성은 의도된 것입니다. 임포터가 잘못된 수치를 올바른 수치로 보고하는 것을 거부하는 것입니다.

> **오류 없는 실행이 곧 올바른 실행은 아닙니다.** 보고서는 어디를 확인해야 하는지 알려 주고, 다음 단계의 검증은 수치를 신뢰해도 되는지 알려 줍니다. 다른 사람이 출력에 의존하는 워크플로라면 검증을 건너뛰지 마십시오.

각 도구 계열의 변환 방식 전체 목록은 [Alteryx 변환 매트릭스](/ko/reference/alteryx-conversion-matrix/)를 참조하십시오.

## 4단계: 변수 설정, 실행 및 검증

1. 변환된 워크플로 캔버스에서 생성된 단계와 분기를 검토합니다.
2. **워크플로 변수**를 설정합니다. 변환된 앱 질문과 런타임 매개변수입니다. 파일 및 폴더 변수는 2단계의 Document 경로를 가리키도록 하고, 값은 Alteryx 실행에서 사용한 값과 일치시키십시오.
3. 단계 하나가 아니라 워크플로에서 **실행**을 클릭하고, 각 단계가 순서대로 실행되는 동안 로그를 확인합니다.
4. 실행 기록, 단계 출력 및 준비 상태 참고 사항을 검토합니다.

그런 다음 1단계에서 선택한 수준으로 검증하십시오.

- **구조적 검증** — 워크플로가 열리고, 그래프에 예상한 분기와 매크로가 있으며, 입력이 업로드되고, 변수가 나타나고, 실행이 완료되었는지 확인합니다. 준비 상태 확인과 인벤토리 작성에는 충분합니다.
- **출력 일치 검증** — 스키마, 행 수, 행 값을 신뢰할 수 있는 Alteryx 출력과 비교합니다. 워크플로가 명시적으로 정렬하지 않는 한 행 순서는 무시합니다. 해당하는 경우 null 처리, 숫자 정밀도, 날짜, 지오메트리도 확인하십시오.

비교 결과가 다르면 다음 순서로 원인을 찾으십시오. 누락되었거나 다른 입력 파일, 다른 변수 값, 다른 소스 스냅샷, 그다음 null/날짜/반올림/정렬 순서 차이, 마지막으로 공간 참조 또는 지오메트리 형식입니다. 원인을 수정하고 다시 실행한 후 다시 비교하십시오. [검증 가이드](/ko/guides/workflows/validate-converted-alteryx-workflows/)에 전체 체크리스트가 있습니다.

> **다시 가져와도 안전합니다.** 패키지를 수정하고 다시 가져오면 첫 번째 가져오기를 덮어쓰지 않고 별도의 테이블 세트가 생성됩니다. 새 워크플로에 만족하면 이전 워크플로와 해당 테이블을 삭제하십시오.

## 워크플로 마이그레이션을 마쳤습니다

Alteryx 워크플로 하나를 준비 상태 검사부터 검증된 PlaidCloud 실행까지 진행했으며, 그에 못지않게 중요하게는 변환 보고서를 읽고 깔끔하게 변환된 부분과 확인이 필요한 부분을 구별할 수 있게 되었습니다. 이것이 전체 과정입니다. 워크플로마다 반복하고, 포트폴리오가 클 때는 전용 프로젝트에 일괄적으로 마이그레이션하십시오.
