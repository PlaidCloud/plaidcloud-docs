*약 20분 · 실패하는 단계, AI 진단, 적용된 수정*

워크플로를 실행했는데 단계가 빨간색으로 바뀌고, 오류 텍스트만으로는 무엇을 바꿔야 할지 알 수 없습니다. 이 튜토리얼은 바로 그 순간을 따라갑니다. PlaidCloud에 내장된 **AI 어시스턴트**를 열어 실제 데이터를 기준으로 실패한 단계를 진단하게 하고, 제안된 수정을 승인한 다음, 다시 실행하여 확인합니다. 그런 다음 같은 어시스턴트로 일상적인 언어 설명에서 SQL 추출 단계를 작성합니다.

여기서 다루는 것은 워크플로를 만들고 수정하도록 돕는 제품 내 AI 어시스턴트입니다. 외부 AI 코딩 에이전트(Claude Code, Cursor, MCP)를 테넌트에 연결하는 것과는 **다릅니다**. 그 보완적인 방법은 [AI 코딩 에이전트 연결하기](/ko/get-started/tutorials/mcp-with-ai-agent/)에서 다룹니다.

## 진행 내용

| 단계 | 사용하는 도구 |
|---|---|
| 단계가 실패하는 것을 확인하고 오류 읽기 | 프로젝트 **로그** 탭 |
| 실패한 단계를 진단하고 수정 | 로그 항목의 **AI 어시스턴트** 탭에 있는 수정 어시스턴트 |
| 수정 확인 | 어시스턴트가 단계를 다시 실행할지 물을 때 승인 |
| SQL을 작성하지 않고 새 쿼리 추가 | SQL 추출 단계의 **AI로 SQL 생성** |

## 사전 요구 사항

- PlaidCloud 워크스페이스(없다면 [무료 체험을 시작](https://app.plaidcloud.com)하십시오)와 편집할 수 있는 프로젝트.
- 단계가 하나 이상 있는 워크플로. 가능하면 실패하는 워크플로이거나, 실패하게 만들 수 있는 워크플로가 좋습니다. 변환에서 열 이름을 잘못 입력하는 것만으로도 시나리오를 재현할 수 있습니다.

> **어시스턴트는 사용자의 권한으로 수정합니다.** 사용자가 이미 직접 편집할 수 있는 단계만 변경할 수 있으며, 어시스턴트가 수행하는 모든 변경은 다시 실행하거나 단계를 직접 편집하여 되돌릴 수 있습니다. [AI로 워크플로 오류 수정하기](/ko/guides/ai-assistant/fixing-workflow-errors/)를 참고하십시오.

## 1단계: 워크플로를 실행하고 오류 찾기

단계가 실패하면 워크플로와 실패한 단계 모두에 오류 표시가 나타나고, 실패 내용이 워크플로 로그에 기록됩니다.

1. 프로젝트를 열고 워크플로(또는 테스트 중인 단일 단계)를 실행합니다.
2. 프로젝트의 **로그** 탭으로 전환합니다. 로그에는 단계가 실행되면서 발생하는 경고와 오류를 포함한 이벤트가 나열됩니다.
3. 로그 목록에서 실패한 단계의 항목을 선택합니다. 트레이스백을 포함한 전체 메시지가 오른쪽 패널의 **로그 메시지** 탭에 열립니다.

> **망가진 워크플로가 없나요? 30초 만에 하나 만드십시오.** 변환 단계에서 한 열의 식을 존재하지 않는 열을 참조하도록 편집한 다음 저장합니다. 예를 들어 `net_amount`를 `net_amnt`로 바꿉니다. 단계를 실행하면 `net_amnt` 열이 존재하지 않는다는 오류가 로그에 표시되며 실패합니다. 이는 수정 어시스턴트가 잡아내도록 만들어진 실제 구성 오류이므로 이 튜토리얼을 처음부터 끝까지 따라가기에 좋은 방법입니다.

오류가 표시되는 방식과 처리 옵션에 대한 자세한 내용은 [단계 오류 관리](/ko/guides/workflows/managing-step-errors/)와 [워크플로 로그 보기](/ko/guides/workflows/viewing-workflow-log/)를 참고하십시오.

## 2단계: 수정 어시스턴트 열기

수정 어시스턴트는 원시 오류 바로 옆에 있으며, 이미 실패한 단계를 가리키고 있습니다.

1. 실패한 로그 항목을 선택한 상태에서 **로그 메시지**를 표시하는 오른쪽 패널을 찾습니다.
2. 해당 패널을 **AI 어시스턴트** 탭으로 전환합니다.

**AI 어시스턴트** 채팅은 선택한 로그 항목이 발생한 워크플로와 단계를 이미 가리킨 상태로 열리므로 어떤 단계가 실패했는지 알려 줄 필요가 없습니다. **로그 메시지**에서 원시 오류를 읽으면서 **AI 어시스턴트**에서 어시스턴트와 나란히 대화할 수 있습니다.

대부분의 오류에서는 즉시 진단을 시작합니다. 존재하지 않는 열을 지정한 식과 같은 몇 가지 일반적인 오류의 경우, 첫 응답은 PlaidCloud에 이미 준비되어 있는 해당 유형의 오류에 대한 짧은 설명입니다. 일반적인 원인, 오류 메시지에서 살펴볼 단어, 해결 방법이 담겨 있습니다. 이 설명은 사용자의 단계를 살펴보지 않습니다. *"이 단계를 확인하고 수정해 주세요"*와 같이 응답하면 어시스턴트가 그다음부터 진행합니다. [일반적인 오류](/ko/guides/ai-assistant/fixing-workflow-errors/#흔한-오류)를 참고하십시오.

## 3단계: 진단하고 수정안 제안받기

어시스턴트는 정해진 순서로 작동하며, 사용자가 승인하기 전에는 아무것도 저장되지 않습니다.

1. **진단** — 실패한 단계의 구성과 해당 단계가 다루는 테이블 및 열을 읽고, 오류 텍스트만으로 추측하지 않고 데이터를 기준으로 판단을 검증합니다.
2. **제안** — 실제 구성 오류를 발견하면 수정된 단계 구성을 보여 주고 무엇을 왜 바꿨는지 쉽게 설명합니다. 이 시점에서는 아무것도 기록되지 않습니다.
3. **사용자 승인** — 사용자의 명시적인 승인을 기다립니다. 모호한 응답은 승인으로 간주되지 않습니다.
4. **적용** — 승인하면 단계 편집기가 사용하는 것과 동일한 경로로 수정된 구성을 단계에 기록합니다.
5. **다시 실행 제안** — 지금 단계를 다시 실행할지 묻습니다. 승인하면 단계를 실행하고 수정이 효과가 있었는지 알려 줍니다.

승인하기 전에 제안된 변경 사항을 읽어 보십시오. 어시스턴트는 오류가 발생한 단계 하나의 구성을 복구합니다. 예를 들어 잘못 입력한 열 또는 함수 이름, 잘못된 식, 잘못된 데이터 형식 또는 캐스트, 잘못된 SQL 등이며, 오류를 해결하는 최소한만 변경합니다.

> **고칠 수 없는 것에 대해서도 솔직합니다.** 어시스턴트가 다룰 수 있는 것은 해당 단계 하나의 구성뿐입니다. 단계를 만들거나, 삭제하거나, 순서를 바꾸거나, 다른 단계를 편집하거나, 데이터를 변경하지 않습니다. 많은 실패는 구성 문제가 전혀 아닙니다. 소스 데이터가 없거나 형식이 잘못된 경우, 상위 단계가 먼저 실패한 경우, 일시적이거나 인프라 관련 오류, 권한 문제, 변환이나 UDF 내부의 로직 오류 등입니다. 이런 경우에는 편집을 억지로 해결책처럼 꾸미지 않고, 발견한 내용을 설명하고 실제 수정이 필요한 위치를 알려 줍니다.

## 4단계: 승인하고 다시 실행하기

1. 제안된 구성이 올바르게 보이면 변경 사항을 명시적으로 확인합니다. 어시스턴트가 이를 단계에 적용합니다.
2. 어시스턴트가 단계를 다시 실행할지 물으면 승인합니다. 단계를 실행하고 성공했는지, 다시 실패했는지 알려 줍니다. 단계나 워크플로를 직접 다시 실행해도 됩니다.

어시스턴트가 원인이 단계 구성 밖에 있다고 알려 준 경우(잘못된 데이터, 상위 단계 실패, 권한 문제) 그것이 답입니다. 어시스턴트에게 어떻게든 단계를 편집하라고 요청하지 말고, 실제 문제가 있는 곳에서 해결하십시오.

> **경고는 대개 무해합니다.** 로그 항목이 심각한 실패가 아니라 경고인 경우, 어시스턴트는 편집을 억지로 만들어 내지 않고 변경이 필요 없다고 알려 주는 경우가 많습니다. 이는 막다른 길이 아니라 올바른 결과입니다.

## 5단계: AI로 SQL 추출 단계 생성하기

이제 수리뿐 아니라 새로운 작업을 추가하는 데도 같은 어시스턴트를 사용합니다. **SQL 추출** 단계는 읽기 전용 `SELECT`를 실행하여 결과를 새 테이블에 기록하며, 단계 편집기가 해당 쿼리를 대신 작성해 줄 수 있습니다.

1. 워크플로의 **단계** 보기에서 **단계 만들기**를 클릭하고 **테이블 → SQL 추출** 또는 **AI → SQL 추출(AI 지원)** 중 하나를 선택합니다. 두 가지 모두 같은 편집기를 열며, SQL 추출 매개변수 페이지 상단에 **AI로 SQL 생성** 패널이 있습니다.
2. **(선택 사항) 소스 테이블을 선택합니다.** **소스 테이블** 목록에서 쿼리가 읽을 테이블을 하나 이상 선택합니다. 비워 두면 어시스턴트가 프로젝트를 살펴보고 관련 테이블을 직접 선택합니다.
3. **원하는 내용을 설명합니다.** **설명** 상자에 원하는 결과를 일상적인 언어로 작성합니다. 예: *"계정 번호 범위에 따라 각 원장 계정을 활동 풀로 분류"*.
4. **SQL 생성을 클릭합니다.** 어시스턴트가 읽기 전용 `SELECT` 하나를 작성하고, 실행하여 검증한 다음, **SQL Select 쿼리** 편집기와 **테이블 데이터 선택** 매핑 페이지를 감지된 열로 채웁니다. 소스 목록을 비워 두었다면 어시스턴트가 선택한 테이블이 목록에서 선택된 상태로 표시되므로 무엇을 사용했는지 확인할 수 있습니다.

> **설정할 것이 없습니다.** AI 어시스턴트가 사용하는 것과 동일한 내장 모델을 사용하므로, 이를 위해 워크스페이스별 AI 에이전트나 LLM 연결을 구성할 필요가 없습니다.

## 6단계: 단계 검토 및 저장하기

생성된 SQL은 블랙박스가 아니라 출발점입니다.

1. **자유롭게 편집합니다.** SQL 편집기는 완전히 편집할 수 있습니다. 저장하기 전에 쿼리를 다듬거나, 조인을 추가하거나, 열 목록을 변경하십시오.
2. **대상 테이블을 선택하십시오.** 단계가 결과를 기록할 **대상 테이블**을 선택하거나 이름을 지정합니다.
3. **단계를 저장합니다.** 일반적인 SQL 추출 단계로 저장되며 다른 단계와 마찬가지로 워크플로의 일부로 실행됩니다.

어시스턴트는 읽기 전용 `SELECT` 문만 작성하며, `INSERT`, `UPDATE`, `DELETE` 등 데이터를 변경하는 SQL은 절대 작성하지 않습니다. 생성은 초안 작성과 미리 보기만 수행하며, 단계는 저장할 때 만들어지고 워크플로가 실행될 때 실행됩니다. 생성된 쿼리가 실행되지 않으면 편집기가 SQL과 오류를 함께 표시하므로 직접 수정하거나, 설명을 조정하여 다시 생성할 수 있습니다. 자세한 내용은 [AI로 SQL 추출 단계 생성하기](/ko/guides/ai-assistant/generate-sql-extract/)에 있습니다.

**이것이 AI 지원입니다.** 실제 데이터를 기준으로 실패한 단계를 진단하고, AI의 수정을 승인하여 적용하고, 다시 실행하여 확인했으며, 일상적인 한 문장으로 동작하는 SQL 추출 단계를 생성했습니다. 같은 어시스턴트가 망가진 것을 고치고 새로운 것을 만들었습니다.
