*약 25분 · 예약된 실행, 실행 기록, 처리된 실패*

이미 워크플로가 있다고 가정합니다. 예를 들어 [데이터 로드, 변환 및 게시](/ko/get-started/tutorials/load-and-transform-data/)의 판매 데이터 정리 파이프라인입니다. 지금은 **실행**을 클릭하면 실행됩니다. 이 튜토리얼에서는 그 일을 PlaidCloud에 맡깁니다. 워크플로가 달력에 따라 스스로 실행되고, 사용자는 실행을 모니터링하고, 실행되었음을 확인하고, 실행이 실패했을 때 복구하는 방법을 배웁니다.

수동 파이프라인을 자동화된 파이프라인으로 바꾸는 요소는 세 가지이며, 이 튜토리얼에서 차례로 다룹니다.

- **일정** — 선택한 시간에 워크플로를 실행하는 규칙.
- **신뢰할 수 있는 기록** — 사용자가 지켜보지 않는 동안 무슨 일이 있었는지 알려 주는 실행 기록과 로그.
- **실패 대응 계획** — 무인으로 실행되는 작업은 언젠가 잘못된 데이터를 만나기 마련이며, 조용히 실패해서는 안 되기 때문입니다.

## 사전 요구 사항

- 직접 실행했을 때 이미 올바르게 실행되는 워크플로가 있는 PlaidCloud 워크스페이스. 없다면 먼저 [데이터 로드, 변환 및 게시](/ko/get-started/tutorials/load-and-transform-data/)로 만드십시오.
- 해당 워크스페이스의 **분석 → 도구 → 이벤트 스케줄러**에 대한 액세스 권한.

> **이미 통과하는 워크플로를 예약하십시오.** 자동화는 워크플로가 하는 모든 일을 반복하며, 실수도 이제 무인으로 반복됩니다. 일정에 올리기 전에 수동으로 한 번 문제없이 끝까지 실행하십시오.

## 1단계: 수동으로 실행되는지 확인

워크플로를 열어 수동 방식으로 한 번 실행하여 비교할 기준을 마련하십시오.

1. 프로젝트를 열고 **워크플로** 계층으로 이동합니다.
2. 워크플로의 **실행** 아이콘을 클릭하거나, 워크플로를 열고 **작업** 메뉴에서 **Run All**을 선택합니다. (워크플로 테이블 맨 위의 **Toggle Start/Stop** 버튼도 같은 작업을 수행하며 진행 중인 실행을 중지합니다.)
3. 실행이 진행되는 동안 단계 상태 아이콘을 확인합니다. 각 단계에는 현재 상태와 실행된 시간이 표시되며, 아이콘 위에 마우스를 올리면 해당 메시지를 볼 수 있습니다.

표시되는 상태와 각 상태의 의미는 다음과 같습니다.

| 상태 | 의미 |
|---|---|
| 대기 중 | 대기열에 있으며 아직 시작되지 않았습니다. |
| 실행 중 | 작업 중이며 경과 시간이 증가합니다. |
| 완료됨 | 성공적으로 끝났습니다. |
| 경고 | 끝났지만 로그에서 읽어 볼 만한 사항이 표시되었습니다. |
| 오류 | 단계가 실패했습니다. [단계 오류 관리](/ko/guides/workflows/managing-step-errors/)를 참조하십시오. |
| 건너뜀 | 비활성화되었거나 실행 조건이 충족되지 않아 건너뛰었습니다. |
| 계속됨 | 실패했지만 오류 시 계속하도록 설정되어 있어 실행이 계속되었습니다. |

문제없는 실행은 모든 단계가 **완료됨**으로 끝납니다. 이것이 정상 기준입니다. 상태에 대한 자세한 내용은 [워크플로 실행](/ko/guides/workflows/run-a-workflow/)에 있습니다.

## 2단계: 일정 만들기

이제 그 실행을 이벤트 스케줄러에 맡깁니다.

1. **분석**을 열고 **도구**를 선택한 다음 **이벤트 스케줄러**를 클릭합니다. **Events Table**에 워크스페이스에 이미 구성된 모든 이벤트가 나열됩니다.
2. **예약된 이벤트 추가**를 클릭합니다.
3. 양식에 표시된 필수 필드를 작성하고, 방금 실행한 워크플로(및 해당 프로젝트)를 이벤트가 가리키도록 합니다.
4. **Event Schedule** 탭을 열고 **Schedule type**을 선택합니다.
   - **Use Classic Schedule** — 실행할 특정 월, 일, 시, 분을 선택합니다. 곧 실행되는 것을 볼 수 있도록 지금부터 몇 분 뒤 같은 시간으로 시작하십시오.
   - **Use Workday Schedule** — 시계 시간 대신 재무 영업일을 선택합니다. 영업일 일정은 휴일 달력도 반영할 수 있어 실행이 올바른 영업일에 이루어집니다.
5. **만들기**를 클릭합니다.

이제 Events Table에 이벤트가 나열되며, 설명 열에 월별, 일/시/분별 또는 영업일별 중 어떤 방식으로 예약되었는지 표시됩니다.

> **별도로 지정하지 않으면 시간은 런던 시간입니다.** 새 이벤트의 기본값은 **UTC +0**이며, 영국 하계 표준시를 포함한 런던 시간으로 해석됩니다. "오전 9시"가 사용자가 있는 곳의 오전 9시를 의미해야 한다면 이벤트의 **시간대** 필드를 설정하십시오. 그렇지 않으면 예약된 실행이 예상보다 몇 시간 어긋날 수 있습니다. 대부분의 다른 오프셋도 해당 지역의 현지 시간을 따릅니다. [이벤트 스케줄러](/ko/administration/scheduled-events/event-scheduler/#시간대)를 참조하십시오.

> **테스트 일정에는 제한을 두어 영원히 실행되지 않게 하십시오.** **Limit Running** 섹션은 지정한 기간 동안, 지정한 횟수만큼만 이벤트를 실행합니다. 시험 삼아 만드는 일정에서는 이 설정으로 몇 분마다 몇 주 동안 조용히 실행되는 작업을 방지할 수 있습니다.

## 3단계: 실행 시점 미리 보기

일정을 신뢰하기 전에 실제로 어떻게 동작하는지 확인하십시오.

1. **예정된 실행 캘린더**를 엽니다. 읽기 전용 미리 보기이며 실제 실행을 구동하는 것과 같은 일정을 펼쳐 보여 주므로, 보이는 것이 실제로 실행될 내용이고 확인만으로는 아무것도 트리거되지 않습니다.
2. **월**, **주**, **일정** 보기를 전환하고, **이전**, **다음**, **오늘**로 시간을 이동하며, **새로 고침**으로 최신 정보를 다시 가져옵니다.
3. 예상한 시간에 이벤트가 표시되는지 확인합니다. 각 실행은 워크플로의 일반적인 소요 시간에 맞는 크기의 막대로 표시됩니다.

> **나란히 있는 막대는 겹침을 의미합니다.** 두 실행의 막대가 같은 시간대에 나란히 있으면 해당 실행이 충돌하는 것입니다. 같은 데이터나 리소스를 두고 경쟁한다면 일정을 서로 어긋나게 설정하십시오. 이벤트 기반 센서는 고정된 미래 시간이 없으므로 여기에 표시되지 않습니다. [예정된 실행 캘린더](/ko/administration/scheduled-events/upcoming-runs-calendar/)를 참조하십시오.

시계를 기다리고 싶지 않다면 Events Table에서 이벤트를 선택하고 **선택한 이벤트 실행**을 클릭하여 즉시 실행하십시오. 예약된 경로가 처음부터 끝까지 작동하는지 지금 바로 확인하는 좋은 방법입니다.

## 4단계: 실행 기록과 로그 확인

자동화된 실행은 사용자가 다른 일을 하는 동안 이루어지므로, 실행이 남기는 기록이 실제로 의지하게 되는 정보입니다.

- **실행 기록**은 워크플로에 있습니다. 각 실행은 별도의 항목입니다. 재개된 실행은 다시 실행한 단계만 포함하는 *새로운* 실행으로 기록되고 원래 실행은 자체 항목을 유지하므로, 기록은 덮어쓰이는 한 줄이 아니라 실제로 일어난 일의 순서를 정확하게 보여 줍니다.
- **워크플로 로그**는 단계 실행, 발생한 경고 등의 이벤트를 발생하는 대로 기록합니다. **프로젝트** 영역의 **로그** 탭에서 열 수 있으며, 더 넓은 범위의 프로젝트 로그에도 취합되므로 여러 워크플로를 한꺼번에 볼 수 있습니다. 뷰어에서 정렬과 필터링이 가능하고 항목을 열어 세부 정보를 볼 수 있습니다. [워크플로 로그 보기](/ko/guides/workflows/viewing-workflow-log/)를 참조하십시오.
- **워크플로 보고서**는 단계, 함수, 변수를 포함한 워크플로의 현재 상태를 문서화합니다. **워크플로** 계층의 **보고서** 아이콘에서 필요할 때 생성되며, 자동화된 작업이 실제로 무엇을 하는지 누군가 물을 때 유용합니다. [워크플로 보고서 보기](/ko/guides/workflows/view-workflow-report/)를 참조하십시오.

예약된 실행 또는 온디맨드 실행 후 로그를 열어 예상한 실행이 있고 의도한 대로 끝났는지 확인하십시오.

## 5단계: 실패 처리

무인 작업은 언젠가 잘못된 데이터를 만납니다. 그런 일이 생겼을 때 어떻게 할지 지금 결정하십시오. PlaidCloud는 세 가지 대응을 제공하며, 적절한 대응은 단계에 따라 다릅니다.

| 선택 | 동작 | 사용하는 경우 |
|---|---|---|
| 워크플로 중지 | 실행이 중단되고 단계와 워크플로 모두에 오류 표시기가 나타납니다. | 기본값입니다. 대부분의 단계는 실제 실패를 넘어 진행해서는 안 됩니다. |
| 오류 시 계속 | 단계에 오류가 표시되지만 실행은 해당 단계를 완료된 것으로 처리하고 계속합니다. | 데이터가 없어도 문제없이 실패할 수 있는 단계. |
| 복구 워크플로 | 실패한 실행이 중지되고 대신 두 번째 워크플로가 시작됩니다. | 실패 시 누군가에게 알리거나 자동 수정을 시도하려는 경우. |

이를 결정하는 설정은 두 가지이며, 둘 다 단계 양식의 **일반** 탭에 있습니다(워크플로 테이블에서 단계의 톱니바퀴 아이콘을 클릭하거나, 마우스 오른쪽 버튼으로 클릭한 후 **단계 세부 정보 편집**을 선택).

- **다시 시도** — 실패한 단계를 지정한 횟수만큼 다시 시도할 수 있으며, 시도 사이의 지연은 몇 초부터 몇 시간까지 설정할 수 있습니다. 원격 시스템을 잠시 사용할 수 없어서 생기는 대부분의 실패는 이것만으로 해결됩니다. [단계 오류 관리](/ko/guides/workflows/managing-step-errors/)를 참조하십시오.
- **오류 발생 시 수행할 작업** — **계속**을 선택하면 단계가 실패해도 워크플로가 중지되지 않습니다. 이렇게 설정된 단계는 워크플로 테이블에 특별한 표시기가 나타납니다. [오류 시 계속](/ko/guides/workflows/continue-on-error/)을 참조하십시오.

> **오류 시 계속은 복구 계획에서 실패를 숨깁니다.** 계속하도록 표시된 단계는 워크플로를 중지시키지 않으므로 복구 워크플로도 트리거하지 않습니다. 그렇지 않으면 실행을 중단시켰을 실패만 복구 워크플로를 트리거합니다. 오류 시 계속은 무시해도 괜찮은 실패에만 사용하십시오.

예약된 실행이 실제로 실패했을 때도 처음부터 다시 시작할 필요는 거의 없습니다. **재개**는 중지되었거나 오류가 발생한 실행을 중단된 지점부터 이어서 진행합니다. 성공적으로 끝나지 않은 단계는 다시 실행하고 완료된 단계는 그대로 둡니다. 워크플로의 마지막 실행이 일시 중지, 중지 또는 오류 상태로 끝났다면 언제든지 재개할 수 있습니다.

## 6단계: 필요할 때 일시 중지

끌 수 없는 자동화는 부담이 됩니다. 일정을 삭제하지 않고 오프라인으로 전환하려면 다음과 같이 합니다.

1. **분석 → 도구 → 이벤트 스케줄러**를 열고 이벤트의 **편집** 아이콘을 클릭합니다.
2. **활성** 확인란의 선택을 해제하고 **업데이트**를 클릭합니다.

다시 활성화할 때까지 이벤트는 일정에 따라 실행되지 않습니다. 같은 편집 경로에서 **활성**을 다시 선택하면 됩니다. 완전히 제거하려면 대신 **삭제** 아이콘을 사용하십시오. 활성 이벤트는 Events Table에 **활성** 아이콘이 표시되므로 한눈에 어떤 이벤트가 활성 상태인지 알 수 있습니다.

**설정이 끝났습니다.** 이제 예약된 이벤트, 확인할 실행 기록, 첫 번째 실패를 처리하는 방법이 준비되었으며, 전체를 삭제하지 않고 일시 중지할 수도 있습니다.
