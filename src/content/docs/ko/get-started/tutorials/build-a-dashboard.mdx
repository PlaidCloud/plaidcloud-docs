*약 30분 · 게시된 테이블, 차트, 공유된 대시보드*

워크플로에서 게시한 깔끔한 테이블이 있습니다. 이 튜토리얼에서는 이를 한눈에 읽을 수 있는 형태로 만듭니다. 먼저 차트를 만들고, 그 차트를 중심으로 대시보드를 구성한 다음, 대시보드를 적절한 사람들과 공유합니다. 첫 차트를 화면에 표시하는 데 SQL은 필요하지 않으며, 가리키고 클릭하고 쿼리하면 됩니다.

[데이터 로드, 변환 및 게시](/ko/get-started/tutorials/load-and-transform-data/)를 따라 했다면, 거기서 게시한 `sales_final` 테이블이 이 튜토리얼이 가정하는 출발점입니다. 게시된 테이블이면 무엇이든 마찬가지로 사용할 수 있습니다.

## 만들 내용

게시된 테이블 하나를 기반으로 한 차트 두 개가 있는 단일 대시보드입니다. 총매출을 보여 주는 Big Number와 그룹화 열별로 매출을 나눠 보여 주는 막대 차트이며, 서식을 지정하고 저장하여 워크스페이스에서 볼 수 있게 합니다.

## 사전 요구 사항

- PlaidCloud 워크스페이스와 열 수 있는 프로젝트.
- 해당 프로젝트의 **게시된** 테이블. 없다면 먼저 [데이터 로드, 변환 및 게시](/ko/get-started/tutorials/load-and-transform-data/)를 따라 하거나, 기존 테이블을 게시하십시오. **테이블** 탭에서 테이블을 마우스 오른쪽 버튼으로 클릭하고 **Set Published Table Reporting Name**을 선택합니다. [테이블 게시](/ko/guides/data/publish/)를 참조하십시오.
- 대시보드 영역에서는 설치할 것이 없습니다. PlaidCloud에서 처음 대시보드를 열 때 대시보드 계정이 자동으로 만들어집니다.

> **게시된 테이블만 대시보드에 연결됩니다.** 대시보드는 내부 테이블 이름이 아니라 게시된 보고 이름으로 테이블을 읽습니다. 나중에 테이블이 데이터 세트로 표시되지 않는다면, 대개 게시되지 않았거나 알아보지 못하는 이름으로 게시된 것이 원인입니다. **테이블** 탭의 **게시 이름** 열을 확인하십시오.

## 1단계: 대시보드 영역 열기

1. PlaidCloud의 프로젝트에서 **대시보드** 영역을 엽니다.
2. 처음 열면 대시보드 계정이 자동으로 설정되므로 직접 만들 필요가 없습니다. 볼 수 있는 항목은 워크스페이스 멤버십과 보안 그룹에 따라 결정됩니다.
3. 게시된 테이블이 사용자가 액세스할 수 있는 프로젝트에 속해 있으므로 이제 **데이터 세트**로 사용할 수 있습니다.

대시보드 가시성이 워크스페이스 멤버십과 어떻게 대응되는지는 [대시보드 사용](/ko/guides/dashboards/using-dashboards/)을 참조하십시오.

## 2단계: 데이터 세트 준비하기

차트를 만들기 전에 각 열이 어떻게 동작해야 하는지 대시보드에 알려 줍니다. 테이블마다 한 번만 하는 설정이며, 클릭 방식 탐색기가 잘 동작하게 해 줍니다.

1. 데이터 세트의 편집 아이콘을 클릭합니다.
2. **List Columns** 탭을 엽니다.
3. 각 열에 해당하는 역할을 설정한 다음 **저장**합니다.

| 설정 | 켜는 경우 |
|---|---|
| **Groupable** | 이 필드(지역, 제품, 월)별로 지표를 나눠 보려는 경우 |
| **Filterable** | 이 필드로 필터링하려는 경우 |
| **합계** / **최솟값** / **최댓값** | 합산하거나 요약할 숫자형 측정값인 경우 |
| **Count Distinct** | 이 필드의 고유 값 개수를 세려는 경우 |
| **Is temporal** | 날짜 또는 시간 필드인 경우 |

> **날짜 열을 temporal로 표시하십시오.** 탐색기의 시간 기반 필터와 "Since / Until" 컨트롤은 **Is temporal**로 표시된 열에서만 작동합니다. 가장 놓치기 쉬운 설정입니다.

## 3단계: 첫 차트 만들기

일반 Table View로 열리는 탐색기에서 시작하여 총매출을 보여 주는 Big Number로 구성합니다.

> **사용자의 측정값 열을 사용하십시오.** 이 튜토리얼에서는 `revenue` 열을 차트로 만들지만 사전 요구 사항은 "게시된 테이블이면 무엇이든"뿐입니다. `revenue`가 나오는 곳마다, 실제로 합산하려는 숫자 열(`amount`, `sales`, `quantity` 등)로 바꾸십시오.

1. 데이터 세트를 클릭하여 엽니다. 기본적으로 **Table View**가 표시됩니다.
2. 지표 섹션에서 원하는 측정값을 추가합니다. 누계를 구하려면 직접 입력하고 합산할 열을 선택하거나(예: `revenue`의 `SUM`), **COUNT(\*)** 를 사용하여 행 개수를 셉니다.
3. 숫자를 나눠 보려는 **그룹화 기준** 필드를 추가합니다. 대표 숫자 하나만 보려면 그룹화 기준을 비워 둡니다.
4. **쿼리**를 클릭하여 실행하고 결과를 확인합니다.
5. **Chart Options**(또는 시각화 유형 선택기)로 스크롤하여 차트 유형을 **Big Number**로 전환합니다. 차트는 Table, Big Number, Bar Chart 등이 될 수 있으며, 각각 동일한 쿼리 결과를 다르게 표시합니다.
6. **쿼리**를 다시 클릭하여 다시 그립니다.

이제 같은 측정값을 나눠 보여 주는 두 번째 차트를 만듭니다.

1. 같은 데이터 세트에서 새 탐색을 시작합니다.
2. `revenue`의 `SUM`을 지표로 유지하고, `region`이나 `product`와 같은 groupable 열에 **그룹화 기준**을 추가합니다.
3. 차트 유형을 **Bar Chart**로 설정하고 **쿼리**합니다.
4. 상위 행만 보려면 **옵션**을 열고 **행 제한**을 설정합니다. 예를 들어 상위 10개 막대 차트라면 `10`입니다.

> **데이터를 바꾸기보다 표시 서식을 사용하십시오.** 값을 반올림하거나 서식을 바꾸는 방법은 두 가지입니다. 테이블에서 변환하거나, 표시할 때 서식을 지정하는 것입니다. 일반적으로는 표시 서식을 선택합니다. 원본 값은 전체 정밀도를 유지하고 모든 보는 사람에게 깔끔한 숫자가 표시됩니다. 이것이 다음 단계입니다.

## 4단계: 숫자 서식 지정하기

원시 측정값은 서식이 없는 상태로 반환됩니다. 데이터가 아니라 차트에서 해결하십시오.

- **Big Number:** 차트를 편집하고 **Customize** 탭을 열어 **Number Format**을 설정합니다.
- **테이블:** 차트를 편집하고 **Customize** 탭을 열어 **Customize Column**에서 숫자 열(`#`으로 표시됨)을 선택한 다음 **D3 Format**을 설정합니다.

기본값은 값에 맞춰 조정되는 **Adaptive formatting**입니다. 서식을 고정하려면 드롭다운에서 선택하거나 D3 서식 문자열을 입력합니다.

| 서식 | 입력 | 표시 |
|---|---|---|
| `,d` | `12345.67` | `12,346` |
| `$,d` | `12345.67` | `$12,346` |
| `$,.2f` | `12345.67` | `$12,345.67` |
| `,.2%` | `13.215` | `1,321.50%` |

통화 기호, 패딩, 정밀도, SI 접두사 등 전체 서식 문법은 [숫자 및 기타 데이터 유형 서식 지정](/ko/guides/dashboards/formatting-numbers/)에 있습니다.

> **달러 단위로 반올림하시나요? `,.0f`가 아니라 `,d` 또는 `$,d`를 사용하십시오.** `,.0f` 형식은 숫자 서식이 깨지는 것으로 알려진 원인입니다. `,d`(정수로 반올림한 10진수)가 소수점 이하를 없애는 안정적인 방법입니다.

## 5단계: 계산된 측정값 추가하기(선택 사항)

원하는 숫자가 단순한 열이 아니라면(비율, 마진율, 조건부 합계), 지표로 작성하십시오. 지표와 계산 열은 데이터 세트에서 PostgreSQL 방식의 SQL로 작성합니다.

```sql
SUM("revenue") / (COUNT(*) + 0.00001)
```

`+ 0.00001`은 그룹에 행이 없을 때 0으로 나누는 오류를 방지합니다. `CASE` 로직, null에 대한 `COALESCE`, 조건부 합계 등 더 많은 패턴은 [지표 예제](/ko/guides/dashboards/example-metrics/)와 [계산 열 예제](/ko/guides/dashboards/example-calculated-columns/)를 참조하십시오.

## 6단계: 대시보드 구성하기

대시보드는 저장된 차트의 레이아웃입니다. 만든 각 차트를 같은 대시보드에 연결하여 함께 표시되게 합니다.

1. Big Number에서 **Edit Chart**를 엽니다.
2. **대시보드** 섹션에 차트가 표시될 대시보드의 이름을 입력합니다. 대시보드가 아직 없다면 여기서 이름을 지정합니다.
3. 저장하고, 막대 차트도 같은 대시보드를 지정하여 반복합니다.
4. 대시보드를 열어 두 차트를 확인합니다. 대시보드 자체의 편집 모드에서 타일을 배치하고, 크기를 조정하고, 필터를 추가할 수 있습니다.

레이아웃, 필터, 상호 작용 옵션의 전체 범위는 [대시보드 알아보기](/ko/guides/dashboards/learning-dashboard/)를 참조하십시오.

## 7단계: 공유하기

대시보드를 볼 수 있는 사람은 먼저 PlaidCloud 액세스에 따라 결정되고, 그 위에 대시보드 서비스 역할이 적용됩니다.

- **기본적으로 프로젝트 구성원에게 표시됩니다.** PlaidCloud의 대시보드 목록에는 사용자가 액세스할 수 있는 프로젝트에 속한 게시된 대시보드가 표시되므로, 프로젝트를 열 수 있는 사람은 추가 단계 없이 대시보드를 찾을 수 있습니다.
- **진행하면서 차트 소유자를 추가하십시오.** 차트를 저장할 때 해당 차트가 필요한 모든 사람을 차트의 **소유자**에 추가하십시오. 그렇지 않으면 동료가 접근할 수 없는 차트에서 "requires the datasource… permission" 오류를 만날 수 있습니다. 저장할 때 소유자를 추가하는 것이 나중에 액세스를 보완하는 것보다 쉽습니다.
- **필요한 경우에만 특정 역할로 제한하십시오.** 대시보드는 대시보드 서비스의 특정 역할로 제한할 수 있으며, 대시보드 자체의 속성에서 설정합니다. 제한된 대시보드는 일치하는 역할이 없는 사람에게 목록에서 숨겨지므로, 제한한다면 대시보드를 볼 수 있어야 하는 사람들에게 알리십시오. PlaidCloud의 프로젝트 액세스는 그 위에 여전히 적용됩니다. 역할 부여로 누군가 접근할 수 없는 프로젝트의 대시보드가 제공되는 일은 없습니다.

전체 가시성 규칙은 [대시보드 사용](/ko/guides/dashboards/using-dashboards/)을 참조하십시오.

## 대시보드를 최신 상태로 유지하기

대시보드를 직접 새로 고칠 필요는 없습니다. 워크플로가 차트의 기반이 되는 테이블을 다시 게시하면 그 테이블을 읽는 모든 차트가 캐시된 결과를 버리고, 다음에 대시보드를 여는 사람이 새 숫자를 보게 됩니다.

> **오래되어 보이는 대시보드의 원인은 거의 캐시가 아닙니다.** 워크플로 실행 후 숫자가 오래되어 보이면 캐시가 아니라 워크플로를 확인하십시오. 실행이 끝났는지, 예상한 테이블을 다시 게시했는지 확인합니다. **같은** 게시 이름으로 다시 게시해야 하기도 합니다. 차트는 이름에 연결되어 있으므로 새 이름으로 테이블을 다시 만들면 기존 차트는 오래된 데이터를 가리키게 됩니다.

강제로 새로 고쳐야 한다면 **Edit dashboard** 옆의 메뉴를 열고 **Force refresh dashboard**를 선택합니다. 결과가 보관되는 기간을 포함한 자세한 내용은 [대시보드 캐싱](/ko/guides/dashboards/dashboard-caching/)에 있습니다.
