## 설명

**SQL 추출** 워크플로 단계는 프로젝트의 데이터에 대해 읽기 전용 `SELECT`를 실행하고 그 결과를 새 테이블에 씁니다. 쿼리를 직접 작성하려면 소스 테이블과 해당 열, 그리고 데이터를 가공하는 SQL을 알아야 합니다.

단계 편집기가 쿼리를 대신 작성해 줄 수 있습니다. 원하는 출력을 일반 언어로 설명하면 AI Assistant가 `SELECT`를 만들고, 읽어 올 테이블을 알려 주지 않으면 프로젝트의 테이블을 살펴보고 관련 있는 테이블을 직접 선택합니다. 생성된 SQL과 감지된 열은 검토용으로 표시되며, 단계를 저장하기 전까지 자유롭게 편집할 수 있습니다.

<Aside type="note">
이 기능은 AI Assistant가 사용하는 것과 동일한 기본 제공 모델을 사용하므로 **별도로 설정할 것이 없습니다**. 이를 위해 워크스페이스별 AI 에이전트나 LLM 연결을 구성할 필요가 없습니다.
</Aside>

## 단계 열기

워크플로의 **단계** 보기에서 **단계 만들기**를 클릭하고 다음 중 하나를 선택합니다.

- **테이블 → SQL 추출** 또는
- **AI → SQL 추출(AI 지원)**

두 경우 모두 동일한 SQL 추출 단계 편집기가 열리며, SQL 추출 매개변수 페이지 맨 위에 **Generate SQL with AI** 패널이 있습니다.

## 쿼리 생성하기

1. **(선택 사항) 소스 테이블을 선택합니다.** **소스 테이블** 목록에서 쿼리가 읽어야 할 테이블을 하나 이상 선택합니다. 목록을 비워 두면 어시스턴트가 프로젝트를 살펴보고 관련 테이블을 대신 선택합니다.
2. **원하는 내용을 설명합니다.** **설명** 상자에 원하는 결과를 일반 언어로 적습니다. 예: *"계정 번호 범위에 따라 각 원장 계정을 활동 풀로 분류합니다"*.
3. **SQL 생성을 클릭합니다.** 어시스턴트가 읽기 전용 `SELECT` 하나를 작성하고, 실행해서 검증한 다음 다음 내용을 채웁니다.
   - **SQL Select 쿼리** 편집기에 생성된 문장
   - **테이블 데이터 선택** 매핑 페이지에 감지된 열

   소스 목록을 비워 두었다면 어시스턴트가 선택한 테이블이 목록에서 선택된 상태로 표시되므로, 무엇을 사용했는지 확인하고 조정할 수 있습니다.

## 검토 및 저장

생성된 SQL은 블랙박스가 아니라 출발점입니다.

- **자유롭게 편집하십시오.** SQL 편집기는 완전히 편집할 수 있습니다. 저장하기 전에 쿼리를 다듬거나, 조인을 추가하거나, 열 목록을 변경하십시오. (여러 테이블을 조인하려면 소스 테이블을 여러 개 선택하거나 생성된 쿼리를 직접 편집하면 됩니다.)
- **대상 테이블을 선택하십시오.** 단계가 결과를 쓸 **대상 테이블**을 선택하거나 이름을 지정합니다.
- **단계를 저장하십시오.** 일반 SQL 추출 단계로 저장되며, 다른 단계와 마찬가지로 워크플로의 일부로 실행됩니다.

<Aside type="tip">
어시스턴트가 반환한 쿼리가 실행되지 않으면 편집기에 SQL이 오류와 함께 계속 표시되므로, 직접 수정하거나 설명을 조정해서 다시 생성할 수 있습니다.
</Aside>

## 참고 및 제한 사항

- 어시스턴트는 **읽기 전용** `SELECT` 문만 작성하며, `INSERT`, `UPDATE`, `DELETE` 등 데이터를 변경하는 SQL은 만들지 않습니다.
- 생성은 단계를 **만들거나 실행하지 않습니다**. 쿼리 초안을 작성하고 열을 미리 볼 뿐입니다. 단계는 저장할 때 만들어지고 워크플로가 실행될 때 실행됩니다.
- 생성된 쿼리는 테이블의 **표시 이름**으로 작성됩니다. 각 테이블은 쿼리 맨 위에서 해당 이름으로 한 번 바인딩되므로, 열, 조인, 필터가 내부 `analyzetable_…` ID가 아닌 알아보기 쉬운 이름으로 표시됩니다. 저장할 때 실제 식별자가 자동으로 복원되므로 쿼리는 변경 없이 실행됩니다. 이름이 고유하지 않은 테이블은 식별자를 그대로 유지합니다.
