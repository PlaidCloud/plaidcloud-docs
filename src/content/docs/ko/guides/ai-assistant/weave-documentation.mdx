## 설명

프로젝트에서 테이블, 단계 또는 워크플로를 선택하면 세부 정보 패널이 열립니다. 패널 하단의 **문서** 섹션에는 프로젝트의 저장된 설정으로 Weave가 해당 항목에 대해 작성한 페이지가 표시됩니다.

- 테이블의 경우: 테이블을 쓰고 읽는 단계, 그리고 테이블의 열
- 단계의 경우: 단계가 하는 일과 실행되는 위치
- 워크플로의 경우: 순서대로 나열된 단계와 워크플로가 읽고 쓰는 테이블

페이지는 항목을 선택할 때마다 그 시점에 저장된 설정으로 작성되므로 오래된 내용이 되지 않으며 직접 새로 고칠 필요도 없습니다. AI를 사용하지 않으므로 사용 가능한 AI 공급자가 없어도 작동합니다. 같은 세부 정보 패널에서 새 설명을 저장하는 등 저장한 뒤에는 페이지가 다시 작성됩니다.

Weave AI, 프로젝트의 **Weave** 탭에 있는 채팅, MCP로 연결된 AI 어시스턴트도 같은 페이지를 읽을 수 있습니다. [AI 어시스턴트용](#ai-어시스턴트용)을 참조하십시오.

## 테이블 페이지

- **설명** — 테이블의 **메모**이며 인용문으로 표시됩니다. 단계가 만든 테이블에는 PlaidCloud가 *Created dynamically*라는 메모를 설정하는데, 이 메모는 테이블에 대해 아무것도 알려 주지 않으므로 표시하지 않습니다.
- **작성하는 단계**와 **읽는 단계** — 각 단계가 이름, 단계 유형, 속한 워크플로와 함께 표시됩니다. 단계가 비활성화된 워크플로 뒤에는 *(비활성화됨)*이 붙고, 어떤 워크플로에도 없는 단계에는 *어떤 워크플로에도 없음*이 표시됩니다. 테이블 이름에 이 테이블을 가리킬 수도 있고 아닐 수도 있는 변수가 포함된 단계는 *변수 값에 따라 다름*과 함께 나열됩니다. 여러 테이블이 공유하는 이름만 지정한 단계는, 예를 들어 *이 이름을 가진 테이블 2개 중 다른 테이블을 의미하지 않는 한*과 함께 나열되며, 사용자가 열 수 있는 테이블만 센 것입니다. 테이블: 비우기, 테이블: 삭제(Drop), 테이블: 제자리 삭제 단계는 변경하는 테이블을 쓰는 것으로 계산되고, 테이블을 읽어서 다시 쓰는 단계는 두 곳 모두에 나열됩니다.
- **이 프로젝트의 어떤 단계도 이 테이블을 읽지 않습니다.** 는 이 프로젝트의 어떤 단계도 이 테이블을 소스로 나열하지 않는다는 뜻입니다. 페이지는 대시보드, 내보내기, 다른 프로젝트, 프로젝트 단계 외부의 어떤 것도 검사하지 않습니다.
- **열** — 각 열과 해당 유형이 표시되며, **열 속성**에 설명이 설정되어 있으면 함께 표시됩니다.

## 단계 페이지

**수행하는 작업**은 단계가 하는 일마다 한 문장씩 설명합니다.

| 단계 | 페이지 설명 |
| --- | --- |
| Allocation: Split | 어떤 테이블의 어떤 값을 어떤 열에 걸쳐 어떤 드라이버 열을 사용해 분할하는지, 각 몫이 어떻게 계산되는지를 설명합니다. 예: "각 `product`의 몫은 같은 `cost_center`, `year`, `month`에 대한 총 `weight`로 나눈 해당 `weight`입니다." 열 이름은 소스 테이블과 드라이버 테이블에서 부르는 이름 그대로 표시됩니다. 단계의 소스나 드라이버에 필터가 있으면 그 사실이 표시되고, 쓰는 테이블의 이름도 표시됩니다. |
| 배부: 차원을 사용하여 분할 | 어떤 테이블의 어떤 값을 어떤 드라이버 열로 분할하는지, 그리고 매핑, 경로, 요약 테이블을 포함해 쓰는 모든 테이블을 설명합니다. |
| 가져오기 | 가져오는 파일과 가져올 대상 테이블을 설명합니다. |
| 내보내기 | 내보내는 테이블과 쓰는 파일을 설명합니다. |
| 추출: 나열된 소스가 없는 SQL | SQL 쿼리를 실행한다는 사실과 쓰는 테이블을 설명합니다. |
| 테이블: 비우기, 테이블: 삭제(Drop), 테이블: 제자리 삭제 | 테이블을 비우거나, 삭제하거나, 행을 삭제한다는 사실을 설명하며, 검색이나 폴더로 테이블을 선택하는 경우에는 해당 설정이 선택하는 테이블에 대해 동작한다는 사실을 설명합니다. |
| 외부 프로젝트 테이블 가져오기 | 다른 프로젝트의 테이블을 이 프로젝트의 테이블로 복사한다는 사실을 설명합니다. |
| 다른 워크플로를 실행하는 단계 | 실행하는 워크플로와 실행 방식을 설명합니다. 조건이 충족될 때, 루프로, 매크로로(소스 테이블의 각 행마다 한 번씩, 동시 실행의 경우), 또는 포함하는 방식으로 실행합니다. 변수로 선택한 워크플로는 단계가 지정한 이름으로 표시되고, 다른 프로젝트에 있는 워크플로는 그렇다고 설명됩니다. 루프가 단계별로 거치는 테이블처럼 단계 자체가 읽는 테이블도 나열됩니다. |
| 그 밖의 단계 | 읽는 테이블과 쓰는 테이블을 설명합니다. |

그런 다음 페이지에는 단계가 실행되는 위치가 표시됩니다. 워크플로의 단계 목록에서 매겨진 번호대로 *워크플로 ... 의 3번째 단계입니다*라고 표시되거나, 어떤 워크플로에도 없다고 표시됩니다.

단계가 변수를 통해 지정한 테이블은 해당 이름 뒤에 *(변수로 지정됨)*이 붙어 표시됩니다.

## 워크플로 페이지

- **단계** — 워크플로의 단계 목록에서와 같은 번호로 표시되며, 각 단계의 유형과 쓰는 테이블 또는 실행하는 워크플로가 함께 표시됩니다. 포함하는 워크플로의 단계는 단계 목록에서 보이는 것처럼 해당 위치에 나열됩니다.
- **이 워크플로 외부에서 읽는 항목** — 이 워크플로의 어떤 단계가 쓰기 전에 단계가 읽는 테이블입니다.
- **쓰기** — 워크플로의 단계가 쓰는 테이블입니다.

비활성화된 단계는 **단계**에는 나열되지만 나머지 두 목록에서는 제외됩니다. 비활성화된 단계가 쓰는 테이블이 외부에서 읽는 것으로 나열될 수 있으므로, 페이지에 그 사실이 표시됩니다. 워크플로의 단계가 실행하는 워크플로에서 사용하는 테이블은 해당 워크플로 자체 페이지에 있습니다.

## 프로젝트 전체의 인계 패키지

예를 들어 계약이 끝날 때 고객에게 프로젝트를 인계하려면 모든 페이지를 한 번에 다운로드합니다. **프로젝트** 창에서 프로젝트 하나를 선택하고 **작업** 메뉴 또는 오른쪽 클릭 메뉴에서 **인계 패키지 다운로드**를 선택합니다. 프로젝트와 해당 단계, 워크플로, 테이블에 대한 읽기 권한이 필요합니다.

패키지는 프로젝트 이름을 딴 Markdown 파일 하나이며(예: *Month End handover.md*), 다운로드할 때 저장된 설정으로 작성됩니다. 프로젝트 설명과 포함된 항목 수로 시작하며, 이어서 네 개의 섹션이 있습니다.

- **워크플로** — 각 워크플로의 페이지입니다. 다른 워크플로가 실행하지 않는 워크플로가 이름순으로 먼저 나오고, 각각 뒤에 그것이 실행하는 워크플로가 실행 순서대로 이어집니다. 두 곳에서 실행되는 워크플로는 한 번만 나열됩니다.
- **테이블** — 위에서 설명한 것과 같이 열과 열 설명을 포함한 각 테이블의 페이지입니다.
- **지표** — 각 지표 정의의 현재 버전을 쉬운 문장으로 설명합니다. 무엇을 측정하는지, 어떤 테이블에서 가져오는지, 조인하는 테이블, 사용하는 행, 실적 행과 예산 행, 기간, 분류할 수 있는 기준을 설명합니다. 다른 지표로 만든 지표는 *매출을 주문 수로 나눈 값*처럼 방법을 설명합니다. [지표 정의](/ko/integrations/ai-coding-agents/metric-definitions/)를 참조하십시오.
- **배부 모델** — 서로 입력이 되는 배부 단계의 각 체인이며, 체인이 끝나는 단계와 각 단계의 분할이 실행 순서대로 나열됩니다. 어떤 워크플로에서도 실행되지 않는 단계는 제외됩니다. 모델의 이름은 해당 워크플로 또는 워크플로들이 공유하는 폴더에서 따옵니다. 그런 이름이 없거나, 다른 모델과 이름을 공유하거나, 역할에 표시되지 않는 항목에서 이름을 가져와야 하는 경우에는 대신 단계 중 하나의 이름으로 제목이 붙습니다. 배부 모델에는 패키지 밖에서 자체 페이지가 없습니다.

패키지는 역할에 표시되지 않는 항목에 대해 단일 페이지와 같은 규칙을 따릅니다. 열 수 없는 워크플로, 테이블, 배부 모델은 제외되고 맨 위에 개수로 표시됩니다. 예: *열 수 없는 워크플로 2개와 테이블 5개를 제외했습니다.* 열 수 없는 단계는 단일 페이지와 마찬가지로 이름이 표시되지 않습니다.

## 역할에 표시되지 않는 항목

테이블, 단계, 워크플로는 관리자 또는 탐색기 역할에게 숨겨질 수 있습니다. 페이지에는 사용자의 역할에 표시되지 않는 항목의 이름이 표시되지 않습니다.

- 열 수 없는 단계는 개수로 표시되며(예: *열 수 없는 단계 2개 더*) 워크플로의 단계 목록에서 번호를 유지합니다.
- 열 수 없는 테이블, 단계 또는 워크플로는 더 이상 존재하지 않는 항목과 똑같이 표시됩니다. 예: *열 수 없거나 더 이상 존재하지 않는 테이블*. 따라서 페이지로 숨겨진 항목의 존재 여부를 알아낼 수 없습니다. 이런 식으로 워크플로의 목록에서 제외된 단계는 별도로 표시되는데, 그 단계가 쓰는 테이블이 외부에서 읽는 것으로 나열될 수 있기 때문입니다. 단계가 지정한 테이블이 열 수 없거나 존재하지 않으면 단계가 부여한 이름 뒤에 *(열 수 있는 테이블이 아님)*이 붙어 표시되며, 워크플로도 마찬가지로 *(열 수 있는 워크플로가 아님)*이 붙습니다.
- 역할에 표시되지 않는 항목의 페이지를 요청하면 항목이 없는 것처럼 응답합니다.

아키텍트는 모든 것을 열 수 있으므로, 아키텍트의 페이지에는 대신 *삭제된 테이블*, *(테이블을 찾을 수 없음)*, *삭제된 단계*, *(워크플로를 찾을 수 없음)*이 표시됩니다.

## 다루지 않는 내용

- **행 수, 크기, 업데이트 시간.**
- **SQL 텍스트나 식을 통해서만 접근하는 테이블.** 페이지에는 단계가 설정에서 지정한 테이블이 나열됩니다.
- **저장하지 않은 편집 내용.** 페이지는 저장된 설정을 설명합니다.

<Aside type="note">
페이지는 데이터를 해석하거나 단계가 올바른지 판단하지 않습니다. 저장된 설정의 내용을 쉬운 말로 기술할 뿐입니다.
</Aside>

## AI 어시스턴트용

- **Weave AI**는 프로젝트에서 연 대화에서 테이블, 단계 또는 워크플로에 대해 물으면 해당 페이지를 읽고 페이지 내용을 바탕으로 답할 수 있습니다. [Weave AI 채팅](/ko/guides/ai-assistant/weave-tab/#weave-ai-채팅)을 참조하십시오.
- **MCP로 연결된 AI 어시스턴트**는 프로젝트, 항목이 테이블인지 단계인지 워크플로인지, 그리고 해당 ID가 주어지면 `doc_describe` 도구로 같은 페이지를 읽을 수 있습니다. 단계, 워크플로, 테이블에 대한 읽기 권한이 필요하며, 역할에 표시되지 않는 항목에 대해 같은 규칙을 따릅니다. [AI 에이전트(MCP)](/ko/integrations/ai-coding-agents/)를 참조하십시오.
