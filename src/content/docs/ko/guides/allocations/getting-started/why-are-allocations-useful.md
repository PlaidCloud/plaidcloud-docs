배부는 값의 풀(일반적으로 비용이지만 모든 집계값에 사용할 수 있습니다)을 측정 가능한 드라이버를 기준으로 사용처에 나누어 줍니다. 배부는 *이 비용이 발생했다면 이를 사용하는 대상에 어떻게 할당해야 하는가?*라는 질문에 답합니다.

## 일반적인 사용 사례

### 활동 기준 원가 계산

분기별 총 마케팅 지출은 알고 있습니다. 이를 캠페인 시간, 생성된 리드, 적격 영업 기회처럼 측정 가능한 기준에 따라 특정 제품에 귀속시키려 합니다. 배부는 선택한 드라이버를 사용해 마케팅 풀을 제품별로 나누어, 각 제품에 간접비까지 모두 반영된 비용을 제공합니다.

### IT 차지백

공유 인프라(컴퓨팅, 스토리지, 라이선스)를 운영하는 데 $X를 지출합니다. 각 사업부는 서로 다른 양을 사용합니다. 배부는 VM 시간, 스토리지 GB, 라이선스 좌석 수와 같은 사용량 지표를 기준으로 IT 비용을 각 사업부에 나누어, 각 사업부의 손익계산서에 실제 사용한 만큼이 반영되도록 합니다.

### 공유 서비스 분배

재무, 인사, 법무, 시설처럼 회사 전체를 지원하는 중앙 부서가 있습니다. 배부는 이들의 비용을 지원 대상 부문에 분배하며, 일반적으로 인원수, 매출 또는 가중 혼합 기준을 사용합니다.

### 이전 가격

다중 엔터티 조직에서 배부는 엔터티 간 내부 서비스의 가격이 어떻게 책정되는지 모델링합니다. 출력은 내부 거래 분개를 생성하는 데 사용됩니다.

### 수익성 분석

제품 또는 고객 수준의 매출이 있고, 여러 풀(영업, 지원, 인프라, 매출원가)에 비용이 있습니다. 배부는 모든 것을 제품/고객 단위로 모아 실제 마진을 확인할 수 있게 해 줍니다.

### 자재 명세서 원가 계산

비용은 구성 요소의 계층을 따라 아래로 흐릅니다. 자재 명세서의 각 단계는 하나의 배부입니다. 하위 조립품 비용은 조립품으로, 조립품은 완제품으로, 완제품은 SKU로 배부됩니다.

## 배부로 피할 수 있는 문제

배부 엔진이 없다면 이러한 모델을 스프레드시트로 만들어야 하는데, 이는 취약하고 감사하기 어려우며 갱신된 데이터로 반복하기도 어렵습니다. PlaidCloud 배부는 다음을 제공합니다.

- 소스 데이터가 새로 고쳐지면 자동으로 다시 실행되는 **재현 가능한 모델**
- 어떤 소스 행이 어떤 대상 행에 기여했는지 보여 주는 **감사 추적**
- 출력이 다음 배부의 입력이 되는 **계층형 배부**
- 기존 계층을 그대로 따르는 **차원 통합**
