**연결**은 PlaidCloud가 외부 시스템(데이터베이스, 데이터 레이크, ERP, REST API, 클라우드 서비스 또는 Git 공급자)에 접속할 수 있도록 하는 저장된 구성입니다. 워크플로 단계는 이름으로 연결을 참조하므로 엔드포인트 세부 정보와 자격 증명이 한곳에 있으며, 이를 필요로 하는 모든 단계와 프로젝트에서 재사용됩니다.

연결은 **Tools > Connections**에서 관리합니다.

## 연결 만들기

1. **Tools > Connections**를 엽니다
2. 도구 모음에서 `New Connection`을 클릭하고 메뉴에서 연결할 시스템을 선택합니다
3. 연결 양식을 입력합니다(탭과 필드는 유형에 따라 다릅니다. 아래의 [연결 양식](#연결-양식) 참조)
4. `Create`를 클릭하여 저장합니다

새 연결이 사용자 소유로 목록에 표시됩니다.

<Aside type="note">연결 유형 목록과 각 유형에 필요한 필드는 [커넥터 참조](/ko/reference/connectors/)에 정리되어 있습니다. 전용 커넥터가 없는 서비스에는 [Generic REST 연결](/ko/reference/connectors/rest/generic-rest/)을 사용하십시오.</Aside>

## 연결 양식

대부분의 연결은 여러 탭으로 된 양식을 엽니다. 정확한 탭은 유형에 따라 다르지만 일반적으로 다음이 표시됩니다.

- **연결 구성**(REST의 경우 **연결 세부 정보**) — 연결 `Name`, 선택 사항인 `Memo`, 호스트/포트/데이터베이스(REST의 경우 호스트/인증 유형), `Usage` 토글(`Active`), `Security Model`. 데이터베이스 연결에서는 자격 증명이 **인증 자격 증명** 그룹에 있고, REST 연결에서는 자체 **인증** 탭이 있습니다.
- **SSL 구성** — `Use SSL`과 SSL 모드, 암호화된 연결을 위한 선택적 클라이언트/루트 인증서.
- **SSH 구성** — `Use SSH`와 SSH 점프 호스트를 통해 연결을 터널링하기 위한 배스천 호스트, 포트, 사용자, 키.

암호, 토큰 및 기타 자격 증명 필드는 쓰기 전용입니다. 저장된 연결을 다시 열면 비어 있는 것으로 표시되며, 저장할 때 비워 두면 저장된 비밀 값이 유지됩니다. 값을 변경하려는 경우에만 다시 입력하십시오. 여기에는 REST 연결의 API 키, OAuth 클라이언트 시크릿, OAuth 새로 고침 토큰이 포함됩니다. NetSuite 개인 인증서, Anaplan 인증서와 개인 키, Postman API 키, Slack 또는 Teams 수신 웹후크 URL 같은 여러 줄 자격 증명도 같은 방식으로 쓰기 전용이며, 입력하거나 붙여 넣을 때 가려집니다. 공백으로만 이루어진 대체 값은 저장된 자격 증명을 덮어쓰지 않고 거부되므로, 저장된 값을 유지하려면 필드를 지우십시오. SQL 또는 Git 연결의 SSL 클라이언트 키와 SSH 개인 키도 쓰기 전용이지만 입력하는 동안에는 표시됩니다. 그 밖의 모든 필드는 이름상 민감해 보이는 필드(데이터베이스의 읽기 전용 플래그, 계정 식별자, 스키마, 호스트 이름)를 포함하여 편집기와 API 등 연결이 표시되는 모든 곳에 실제 저장된 값이 표시되며, 실제 자격 증명만 가려지거나 숨겨집니다.

REST API와 MCP에서도 자격 증명 필드는 편집기와 같은 규칙을 따릅니다. 빈 문자열을 보내면 PlaidCloud가 저장된 값을 유지하고, `null`을 보내면 지웁니다. 자격 증명이 아닌 모든 필드는 비워서 보내면 여전히 지워집니다.

필수 필드는 저장할 때 검증되며, 누락된 항목이 있으면 양식이 첫 번째로 유효하지 않은 필드가 있는 탭으로 전환되어 해당 필드를 표시합니다.

## 보안 모델

연결의 `Security Model`은 워크스페이스에서 누가 연결을 사용할 수 있는지를 제어합니다.

| 옵션 | 연결을 사용할 수 있는 사람 |
|---|---|
| 비공개(소유자만) | 소유자만. |
| 특정 멤버만 | 소유자와 명시적으로 지정한 멤버 목록. |
| 특정 보안 그룹만 | 소유자와 지정한 보안 그룹의 멤버. |
| 모든 작업 영역 멤버 | 워크스페이스의 모든 사용자. |

`Specific Members Only` 또는 `Specific Security Groups Only`를 선택하면 목록의 `Actions` 메뉴에서 액세스 권한을 부여합니다. `Specific Members Only`에는 `Members`, `Specific Security Groups Only`에는 `Groups`가 있으며, `Agents`와 `Owners`도 각각 액세스를 추가하고 제거하기 위한 이중 목록 선택기를 엽니다. 연결의 소유자 또는 워크스페이스 관리자만 여기에서 액세스를 변경할 수 있습니다. 연결을 편집할 수 있는 다른 사용자는 연결을 열어 누구에게 액세스 권한이 있는지 볼 수는 있지만 변경할 수는 없습니다. 워크스페이스 관리자는 소유자가 떠난 연결을 다른 사람에게 넘기기 위해 자신이 소유하지 않은 연결의 액세스도 변경할 수 있습니다.

## 환경

연결은 **환경**별로 서로 다른 구성을 가질 수 있습니다(예: 하나의 연결 이름 아래에 개발 호스트와 프로덕션 호스트). 도구 모음의 환경 선택기에서 어떤 환경의 구성을 보고 편집할지 선택합니다.

- `New Environment` — 연결 환경 추가
- `Edit Environment` — 선택한 환경의 이름 바꾸기
- `Delete Environment` — 선택한 환경 제거

목록의 `Available` 열은 선택한 연결이 선택한 환경에 대해 구성되어 있는지 보여 줍니다.

<Aside type="note">구성을 저장하면 해당 환경의 저장된 구성에 병합되므로, 비어 있는 쓰기 전용 비밀 값이 빈 값으로 덮어써지는 일은 없습니다.</Aside>

환경은 PlaidLink 에이전트와 공유되므로, 프로젝트의 환경에 따라 원격 단계를 실행하는 에이전트와 프로젝트가 읽는 연결을 함께 전환할 수 있습니다. [에이전트 환경](/ko/reference/cli/plaidlink/agents/#에이전트-환경)을 참조하십시오.

## 연결 편집

1. 목록에서 연결을 선택합니다
2. 도구 모음에서 `Edit`을 클릭합니다(또는 행을 마우스 오른쪽 단추로 클릭합니다)
3. 필드를 변경하고 `Update`를 클릭합니다

## 연결 테스트

테스트 방법은 유형에 따라 다릅니다.

- **데이터베이스 연결**(Databricks, Snowflake, PostgreSQL, Redshift)은 편집기에 **연결 테스트** 버튼이 있습니다. 입력한 자격 증명으로 연결을 열고 편집기를 닫지 않은 채 성공(접속한 서버 버전 포함) 또는 실패 이유를 보고하므로, 그 자리에서 수정하고 다시 시도할 수 있습니다.
- SSH를 사용하는 데이터베이스 연결은 `SSH Config` 탭에서 SSH 터널 테스트도 제공합니다.
- [Generic REST 연결](/ko/reference/connectors/rest/generic-rest/)에는 저장된 연결을 통해 임시 요청을 보내는 `Testing` 탭이 있습니다.

테스트는 저장된 구성을 대상으로 실행되므로 테스트하기 전에 연결을 저장하십시오.

<Aside type="note">**연결 테스트**는 편집기에서 제공하는 연결 종류에 표시되며, 현재는 위의 데이터베이스 유형과 [TM1](/ko/guides/connections/tm1/), [Oracle Essbase](/ko/guides/connections/essbase/), [HFM/FCCS](/ko/guides/connections/hfm-fccs/), Salesforce, Anaplan입니다. NetSuite 같은 다른 REST 연결에는 아직 없습니다. 이러한 연결은 워크플로 단계에서 작은 요청을 보내 테스트하십시오(NetSuite의 경우 [NetSuite에 연결](/ko/guides/connections/netsuite/#연결-스모크-테스트) 참조).</Aside>

## 복제, 삭제, 사용 추적

- **복제** — 연결의 구성을 복제하여 새 연결의 기반으로 삼습니다. [연결 복제](/ko/guides/connections/clone-connection/)를 참조하십시오.
- **삭제** — 도구 모음에서 선택한 연결을 제거합니다(확인 메시지가 표시됨).
- **사용 위치…** — 연결을 참조하는 워크플로 단계를 나열하므로 편집하거나 삭제하기 전에 영향을 확인할 수 있습니다.

<Aside type="caution">`Edit`, `Clone`, `Delete`는 사용자가 소유한 연결에서만 사용할 수 있습니다. 선택한 행에서 이러한 작업이 비활성화되어 있다면 소유자가 아닙니다. 소유자에게 변경을 요청하거나 `Owners`를 통해 사용자를 추가해 달라고 요청하십시오.</Aside>
