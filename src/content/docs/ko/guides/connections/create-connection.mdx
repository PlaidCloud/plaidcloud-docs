**연결**은 PlaidCloud가 데이터베이스, 데이터 레이크, ERP, REST API, 클라우드 서비스, Git 공급자와 같은 외부 시스템에 접근할 수 있게 해 주는 저장된 구성입니다. 워크플로 단계는 연결을 이름으로 참조하므로 엔드포인트 세부 정보와 자격 증명이 한 곳에 있으며, 이를 필요로 하는 모든 단계와 프로젝트에서 재사용됩니다.

연결은 **Tools > Connections**에서 관리합니다.

## 연결 만들기

1. **Tools > Connections**를 엽니다
2. 도구 모음에서 `New Connection`을 클릭하고 메뉴에서 연결할 시스템을 선택합니다
3. 연결 양식을 작성합니다(탭과 필드는 유형에 따라 다릅니다. 아래 [연결 양식](#연결-양식)을 참조하십시오)
4. `Create`를 클릭하여 저장합니다

새 연결이 목록에 표시되며 소유자는 사용자 본인입니다.

Acumatica, Bill.com, Dynamics, Eclipse, HFM/FCCS, NetSuite, Workday, Workday Financials 연결은 REST 연결로 저장되며 목록의 **유형** 열에는 해당 서비스 고유의 유형이 표시됩니다. 각 연결은 만들기, 편집, 단계에서 선택하기를 위한 전용 양식에서 열립니다. 헤더, 인증, 페이지 매김은 마우스 오른쪽 버튼 클릭 메뉴에서 이동하는 **Edit REST settings**에 있습니다([연결 편집](#연결-편집) 참조).

<Aside type="note">연결 유형 목록과 각 유형에 필요한 필드는 [커넥터 참조](/ko/reference/connectors/)에 정리되어 있습니다. 전용 커넥터가 없는 서비스에는 [범용 REST 연결](/ko/reference/connectors/rest/generic-rest/)을 사용하십시오.</Aside>

## 연결 양식

대부분의 연결은 여러 탭으로 구성된 양식을 엽니다. 정확한 탭은 유형에 따라 다르지만, 일반적으로 다음과 같은 탭이 표시됩니다.

- **연결 구성**(REST의 경우 **연결 세부 정보**) — 연결 `Name`, 선택 사항인 `Memo`, 호스트/포트/데이터베이스(REST의 경우 호스트/인증 유형), `Usage` 토글(`Active`), `Security Model`입니다. 데이터베이스 연결에서는 자격 증명이 **인증 자격 증명** 그룹에 있고, REST 연결에서는 별도의 **인증** 탭에 있습니다.
- **SSL 구성** — `Use SSL`과 함께 암호화된 연결을 위한 SSL 모드, 선택 사항인 클라이언트/루트 인증서를 설정합니다.
- **SSH 구성** — `Use SSH`와 함께 SSH 점프 호스트를 통해 연결을 터널링하기 위한 배스천 호스트, 포트, 사용자, 키를 설정합니다.

암호, 토큰 및 기타 자격 증명 필드는 쓰기 전용입니다. 저장된 연결을 다시 열면 비어 있는 것으로 표시되며, 저장할 때 비워 두면 저장된 비밀 값이 유지됩니다. 값을 변경하려는 경우에만 다시 입력하십시오. 여기에는 REST 연결의 API 키, OAuth 클라이언트 비밀 값, OAuth 새로 고침 토큰이 포함됩니다. 여러 줄로 된 자격 증명(NetSuite 개인 인증서, Anaplan 인증서와 개인 키, Postman API 키, Slack 또는 Teams 수신 웹훅 URL)도 같은 방식으로 쓰기 전용이며 입력하거나 붙여넣을 때 가려집니다. 공백으로만 이루어진 대체 값은 저장된 자격 증명 위에 저장되지 않고 거부되므로, 저장된 값을 유지하려면 필드를 비우십시오. SQL 또는 Git 연결의 SSL 클라이언트 키와 SSH 개인 키도 쓰기 전용이지만 입력하는 동안에는 보입니다. 그 밖의 모든 필드는 이름만 보면 민감해 보이는 필드(데이터베이스의 읽기 전용 플래그, 계정 식별자, 스키마, 호스트 이름)를 포함하여 편집기와 API를 비롯해 연결이 표시되는 모든 곳에서 실제 저장된 값을 보여 주며, 실제 자격 증명만 가려지거나 숨겨집니다.

REST API와 MCP에서도 자격 증명 필드는 편집기와 같은 규칙을 따릅니다. 빈 문자열을 보내면 PlaidCloud가 저장된 값을 유지하고, `null`을 보내면 지웁니다. 자격 증명이 아닌 모든 필드는 비워서 보내면 여전히 지워집니다.

필수 필드는 저장할 때 검증됩니다. 누락된 항목이 있으면 양식이 첫 번째 잘못된 필드가 있는 탭으로 전환되고 해당 필드를 표시합니다.

## 보안 모델

연결의 `Security Model`은 워크스페이스에서 누가 해당 연결을 사용할 수 있는지를 제어합니다.

| 옵션 | 연결을 사용할 수 있는 사용자 |
|---|---|
| 비공개(소유자만) | 소유자만 사용할 수 있습니다. |
| 특정 멤버만 | 소유자와 명시적으로 지정한 멤버 목록입니다. |
| 특정 보안 그룹만 | 소유자와 지정한 보안 그룹의 멤버입니다. |
| 모든 작업 영역 멤버 | 워크스페이스의 모든 사용자입니다. |

`Specific Members Only` 또는 `Specific Security Groups Only`를 선택한 경우 목록의 `Actions` 메뉴에서 액세스 권한을 부여합니다. `Specific Members Only`에는 `Members`, `Specific Security Groups Only`에는 `Groups`가 있으며, 여기에 `Agents`와 `Owners`가 더해집니다. 각 항목은 액세스 권한이 있는 대상을 선택하는 필터링 가능한 체크리스트를 엽니다([선택기로 할당하기](/ko/administration/access/managing-security-groups-and-assignments/#선택기로-할당하기) 참조). 연결의 소유자 또는 워크스페이스 관리자만 여기에서 액세스를 변경할 수 있습니다. 연결을 편집할 수 있는 다른 사용자는 연결을 열어 액세스 권한이 있는 사람을 이미 지정된 사람의 읽기 전용 목록으로 볼 수 있습니다. 워크스페이스 관리자는 소유자가 떠났을 때 연결을 넘겨주기 위해 자신이 소유하지 않은 연결의 액세스를 변경할 수 있습니다.

## 연결의 자격 증명을 볼 수 있는 사용자

연결을 사용할 수 있는 사람은 누구나 연결을 열어 설정을 볼 수 있으며, Git 연결의 리포지토리, 브랜치, 파일을 탐색할 수 있습니다. 연결의 암호, 토큰, 키는 연결 또는 워크플로를 편집할 수 있는 멤버에게만 반환됩니다. REST API와 MCP를 통해서는 그 외의 모든 사용자에게 가려진 상태로 제공됩니다.

저장된 서버 URL과 다른 서버 URL로 Git 연결을 탐색할 때는 해당 서버의 토큰을 입력하십시오.

## 환경

연결은 **환경**별로 서로 다른 구성을 가질 수 있습니다(예: 하나의 연결 이름 아래에 개발 호스트와 운영 호스트). 도구 모음의 환경 선택기에서 보고 편집할 환경의 구성을 선택합니다.

- `New Environment` — 연결 환경을 추가합니다
- `Edit Environment` — 선택한 환경의 이름을 바꿉니다
- `Delete Environment` — 어떤 프로젝트도 사용하지 않고, 어떤 단계도 이를 [고정 환경](/ko/guides/projects/managing-projects/#단계를-하나의-환경에-고정)으로 사용하지 않으며, 어떤 에이전트도 이를 제공하지 않을 때 선택한 환경을 제거합니다. 그렇지 않으면 메시지에 아직 사용 중인 대상이 표시됩니다. 기본 환경은 삭제할 수 없습니다.

목록의 `Available` 열은 선택한 연결이 선택한 환경에 대해 구성되어 있는지를 보여 줍니다.

<Aside type="note">구성을 저장하면 해당 환경에 저장된 구성에 병합되므로, 비어 있는 쓰기 전용 비밀 값이 빈 값으로 덮어써지는 일은 없습니다.</Aside>

환경은 PlaidLink 에이전트와 공유되므로 프로젝트의 환경에 따라 연결뿐 아니라 원격 단계를 실행하는 에이전트도 전환할 수 있습니다. [에이전트 환경](/ko/reference/cli/plaidlink/agents/#에이전트-환경)을 참조하십시오.

## 연결 편집

1. 목록에서 연결을 선택합니다
2. 도구 모음에서 `Edit`를 클릭합니다(또는 행을 마우스 오른쪽 버튼으로 클릭합니다)
3. 필드를 변경하고 `Update`를 클릭합니다

Acumatica, Bill.com, Dynamics, Eclipse, HFM/FCCS, NetSuite, Workday 또는 Workday Financials 연결에서는 `Edit`가 해당 서비스 전용 양식을 엽니다. 기반이 되는 REST 연결의 헤더, 인증, 페이지 매김을 변경하려면 연결을 마우스 오른쪽 버튼으로 클릭하고 **Edit REST settings**를 선택하십시오.

## 연결 테스트

테스트 방법은 유형에 따라 다릅니다.

- **데이터베이스 연결**(Databricks, Snowflake, PostgreSQL, Redshift)에는 편집기에 **연결 테스트** 버튼이 있습니다. 입력한 자격 증명으로 연결을 열고 성공(도달한 서버 버전 포함) 또는 실패 사유를 편집기를 닫지 않고 보고하므로 그 자리에서 수정하고 다시 시도할 수 있습니다.
- SSH를 사용하는 데이터베이스 연결은 `SSH Config` 탭에서 SSH 터널 테스트도 제공합니다.
- [범용 REST 연결](/ko/reference/connectors/rest/generic-rest/)에는 저장된 연결을 통해 임시 요청을 보내는 `Testing` 탭이 있습니다.

테스트는 저장된 구성에 대해 실행되므로 테스트하기 전에 연결을 저장하십시오.

<Aside type="note">**연결 테스트**는 연결 종류의 편집기에서 제공하는 경우에 표시됩니다. 현재는 위의 데이터베이스 유형과 [TM1](/ko/guides/connections/tm1/), [Oracle Essbase](/ko/guides/connections/essbase/), [HFM/FCCS](/ko/guides/connections/hfm-fccs/), [NetSuite](/ko/guides/connections/netsuite/), Salesforce, Anaplan입니다. 다른 REST 연결은 워크플로 단계에서 작은 요청을 보내 확인하십시오.</Aside>

## 연결이 접근할 수 없는 주소

연결은 루프백, 링크 로컬 또는 클라우드 메타데이터 주소를 가리킬 수 없습니다. PlaidCloud는 연결을 테스트할 때와 단계에서 사용할 때 호스트 이름이 확인되는 주소를 검사하며, 조건에 맞지 않는 주소는 호스트와 확인된 주소를 명시한 오류로 실패합니다. 사설 네트워크의 주소는 영향을 받지 않습니다.

## 복제, 삭제, 사용 추적

- **복제** — 연결의 구성을 새 연결의 기반으로 복제합니다. [연결 복제](/ko/guides/connections/clone-connection/)를 참조하십시오.
- **삭제** — 도구 모음에서 선택한 연결을 제거합니다(확인을 요청받습니다).
- **사용 위치…** — 연결을 참조하는 워크플로 단계를 나열하므로 편집하거나 삭제하기 전에 영향을 확인할 수 있습니다.

<Aside type="caution">`Edit`, `Clone`, `Delete`는 사용자가 소유한 연결에서만 사용할 수 있습니다. 선택한 행에서 이러한 작업이 회색으로 표시된다면 소유자가 아닌 것이므로, 소유자에게 변경을 요청하거나 `Owners`를 통해 본인을 추가해 달라고 요청하십시오.</Aside>

REST API, JSON-RPC, AI 어시스턴트 또는 MCP를 통해서도 마찬가지입니다. 연결의 설정을 변경하려면 소유자 중 한 명이어야 하며, 소유자가 없는 연결은 워크스페이스 관리자여야 합니다. 연결을 사용 설정하거나, 사용 중지하거나, 잠그거나, 잠금 해제하려면 소유자 또는 워크스페이스 관리자여야 합니다. 여러 연결을 지정한 요청은 그 모든 연결을 변경할 수 있을 때에만 적용됩니다.
