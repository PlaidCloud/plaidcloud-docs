**PlaidCloud Git 연결**은 워크플로 또는 서버 Panel 앱의 빌드가 워크스페이스 자체 관리형 Git 서버의 리포지토리를 가리키도록 합니다. 이 Git 서버는 `git.<your-workspace>.plaid.cloud`에서 사용자를 위해 호스팅되며 일반 PlaidCloud 로그인으로 이미 로그인되어 있으므로, 연결 양식이 외부 Git 공급자의 양식보다 훨씬 단순합니다. 입력할 서버 URL이 없고 관리할 사용자 이름, 토큰, SSH 키도 없습니다.

<Aside type="note">PlaidCloud Git 연결에는 서버 URL이나 자격 증명을 입력하지 않습니다. 워크스페이스의 Git 서버와 해당 서버에 대한 액세스는 PlaidCloud 로그인(SSO 포함)을 통해 자동으로 처리되므로 발급하거나 저장하거나 교체할 토큰이 없습니다.</Aside>

## 사용 시기

읽어 오려는 리포지토리가 외부 호스트가 아니라 워크스페이스의 기본 제공 Git 서비스인 [PlaidCloud Git](/ko/guides/git/)에 있다면 PlaidCloud Git 연결을 사용하십시오. 가장 일반적인 용도는 관리형 리포지토리에서 **서버 Panel 앱** 또는 **Dash 앱** 빌드를 자동화하는 것입니다. 브랜치에 푸시하면 외부 GitHub 계정이나 개인 액세스 토큰 없이 앱이 다시 빌드되고 재배포됩니다.

GitHub, GitLab, Bitbucket, Forgejo, Gitea 같은 외부 서비스에 호스팅된 리포지토리에는 대신 [외부 Git 연결](/ko/reference/connectors/git/)을 사용하십시오. 외부 Git 연결에는 **서버 URL**, 사용자/토큰 또는 SSO 인증, **SSL** 및 **SSH** 탭이 있는 전체 양식이 유지됩니다.

## PlaidCloud Git 연결 만들기

1. **Tools > Connections**를 엽니다.
2. `New Connection`을 클릭하고 메뉴에서 **PlaidCloud Git**을 선택합니다.
3. 간소화된 양식을 작성합니다.
   - **계정 이름** — 연결의 표시 이름
   - **메모** — 연결의 용도에 대한 선택적 메모
   - **리포지토리** — `Refresh`를 클릭하여 워크스페이스에서 접근할 수 있는 리포지토리를 나열한 다음 하나를 선택합니다(예: `udfs` 또는 `apps` 리포지토리). 경로를 직접 입력하는 대신 목록에서 선택합니다.
   - **기본 브랜치** — 선택한 리포지토리의 브랜치 목록에서 기본적으로 읽어 올 브랜치를 선택합니다.
   - **시작 경로** — 선택적으로 리포지토리를 탐색하여 폴더를 선택하면 모든 파일 조회가 하위 폴더로 한정됩니다. 설정하지 않으면 전체 리포지토리를 사용합니다.
4. **사용법**을 설정합니다. 연결을 활성화하려면 `Active`, 연결이 쓰기를 하지 않아야 하면 `Read Only`를 선택합니다.
5. **보안 모델**을 설정합니다. 워크스페이스에서 누가 연결을 사용할 수 있는지 지정합니다.
6. `Create`를 클릭하여 저장합니다.

양식은 이것이 전부입니다. 외부 Git 공급자와 달리 서버 URL, 인증 탭, SSL 또는 SSH 구성이 없으며 모두 자동으로 처리됩니다.

<Aside type="note">리포지토리, 기본 브랜치, 시작 경로는 실시간 목록에서 선택합니다. 먼저 리포지토리를 선택하고 그다음 브랜치를 선택한 뒤 폴더를 탐색하므로 잘못 입력할 일이 없습니다. 각 목록은 연결 자체의 액세스 권한으로 읽으므로, PlaidCloud Git 연결에서는 입력할 자격 증명 없이 바로 채워집니다.</Aside>

## 보안 모델

`Security Model`은 워크스페이스에서 누가 연결을 사용할 수 있는지 제어합니다.

| 옵션 | 연결을 사용할 수 있는 대상 |
|---|---|
| 비공개(소유자만) | 소유자만 사용할 수 있습니다. |
| 특정 멤버만 | 소유자와 명시적으로 지정한 멤버 목록. |
| 특정 보안 그룹만 | 소유자와 지정한 보안 그룹의 멤버. |
| 모든 작업 영역 멤버 | 워크스페이스의 모든 사용자. |

`Specific Members Only` 또는 `Specific Security Groups Only`의 경우 저장한 후 목록의 `Actions` 메뉴에서 액세스 권한을 부여합니다. 공통 연결 방식은 [연결 만들기 및 관리](/ko/guides/connections/create-connection/#보안-모델)를 참조하십시오.

## 리포지토리를 볼 수 있는 사용자

PlaidCloud가 만드는 모든 리포지토리는 워크스페이스에 로그인한 모든 멤버가 읽을 수 있습니다. 여기에는 Panel 앱과 Dash 앱의 리포지토리, 기본 제공 `apps` 및 `udfs` 리포지토리가 포함됩니다. 로그인하지 않은 사용자는 읽을 수 없습니다.

이 때문에 멤버는 리포지토리별 설정 없이 앱을 열고 다시 게시할 수 있으며, PlaidCloud Git 연결에 사용할 리포지토리를 선택할 수 있습니다.

### 고급: 비공개 리포지토리

Git 관리자는 Git 인터페이스에서 리포지토리를 비공개로 설정할 수 있습니다. 비공개 리포지토리는 더 이상 모든 멤버에게 표시되지 않으므로 다음과 같습니다.

- PlaidCloud Git 연결의 **리포지토리** 목록에 나타나지 않습니다.
- Git 기반 UDF 코드를 읽을 수 없으므로 비공개 리포지토리에 저장된 Git 기반 UDF는 실행되지 않습니다.
- 멤버가 해당 리포지토리에서 앱을 게시할 수 없습니다.

비공개 리포지토리를 소스로 사용하려면 대신 자체 액세스 토큰을 사용하는 [외부 Git 연결](/ko/reference/connectors/git/)을 만드십시오.

## 관리형 Git에서 Panel 앱 및 Dash 앱 빌드 자동화

[서버 Panel 앱](/ko/guides/panel-apps/creating/) 또는 [Dash 앱](/ko/guides/dash-apps/)은 Git 브랜치에서 빌드되며 해당 브랜치에 푸시할 때마다 자동으로 다시 빌드됩니다. 앱이 PlaidCloud Git 연결을 가리키게 하면 전체 과정이 워크스페이스 안에서 이루어지므로 외부 호스트도, 유지해야 하는 개인 액세스 토큰도 필요하지 않습니다.

1. 워크스페이스의 PlaidCloud Git 서버에 있는 리포지토리에 앱을 푸시합니다. 진입점 `.py` 파일(Panel은 `.servable()`을 호출하고 Dash는 `server = app.server`를 노출)과, 리포지토리 루트 또는 진입점 옆에 선택적 `requirements.txt`가 필요합니다. 리포지토리 구성은 [Panel 앱 만들기](/ko/guides/panel-apps/creating/#앱-리포지토리-준비) 또는 [PlaidCloud Git에서 Dash 앱 배포](/ko/guides/dash-apps/deploy-from-git/)를 참조하십시오.
2. 위의 단계에 따라 **리포지토리**가 해당 리포지토리인 PlaidCloud Git 연결을 만듭니다.
3. **앱**에서 **새 앱** > **서버 기반** 또는 **Dash 앱**을 선택하고 **Git 연결 및 게시 감시기**에서 다음을 설정합니다.
   - **Git 연결** — 방금 만든 PlaidCloud Git 연결을 선택합니다.
   - **브랜치** — 빌드할 브랜치입니다. 이 브랜치에 푸시하면 앱이 다시 빌드되고 재배포됩니다.
   - **진입점** — 앱이 제공해야 하는 `.py` 파일입니다.
4. 게시 대화 상자를 완료하고 **게시**를 클릭합니다.

이후에는 관리형 Git 서버의 해당 브랜치에 푸시할 때마다 앱이 다시 빌드됩니다. PlaidCloud를 벗어나지 않는 엔드 투 엔드 자동 빌드입니다.
