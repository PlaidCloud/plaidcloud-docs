**문서 전기** 단계는 하나의 테이블에 있는 문서를 ERP 시스템에 전기합니다. 이 단계에는 시스템을 지정하지 않습니다. 각 문서는 해당 엔터티가 전기하는 시스템으로 전송되므로 하나의 단계로 여러 시스템과 같은 ERP의 여러 인스턴스에 동시에 전기할 수 있습니다. 단계, 파일, REST API, MCP 도구 등 모든 전기 방법은 같은 검사를 거치며 자체 [실행 페이지](#실행-페이지)가 있는 실행으로 기록됩니다.

이 페이지는 단계, 단계의 테이블과 설정, 시뮬레이션과 실거래, 실행 페이지, 다시 실행, 파일 또는 배부에서 전기, SAP 전기 단계 변환을 다룹니다. 시스템 자체의 설정, 즉 어느 엔터티가 어디에 전기하는지, 라이브 전환, 보류 규칙, 각 ERP가 지원하는 항목은 [ERP 시스템](/ko/guides/connections/erp-systems/)에 있습니다. 이후 전기를 검토, 승인, 되돌리기, 확정하는 방법은 [전기 등록부](/ko/guides/connections/posting-register/)에 있습니다.

## 시작하기 전에

- 전기할 각 ERP는 PlaidCloud가 전기할 수 있는 연결이며, 해당 시스템에 전기하는 엔터티와 함께 시스템으로 설정됩니다. [ERP 시스템](/ko/guides/connections/erp-systems/)을 참조하십시오.
- 실제로 전기하려면 실행이 실거래여야 하고 각 문서의 시스템이 프로젝트에서 실거래여야 합니다. 그 전까지는 모든 항목이 검사되어 **전기 예정**으로 표시되며 아무것도 전송되지 않습니다. [시뮬레이션과 실거래](#시뮬레이션과-실거래)를 참조하십시오.

## 문서가 전기되는 방법

1. 균형 및 세트: 분개는 사용하는 각 통화에서 균형이 맞아야 하며 세트는 전체적으로 균형이 맞아야 합니다. [세트](#세트)와 [단계 설정](#단계-설정)의 반올림 설정을 참조하십시오.
2. 라우팅: 문서의 엔터티가 [ERP 시스템](/ko/guides/connections/erp-systems/)에 설정된 대로 시스템을 결정합니다. 엔터티에 시스템이 없는 문서는 전기되지 않습니다.
3. 검사: [다섯 가지 검사](#다섯-가지-검사)가 PlaidCloud가 시스템에 대해 알고 있는 내용을 기준으로 실행됩니다.
4. 보류: 시스템의 보류 규칙 또는 단계 자체의 보류가 있으면 사람이 [전기 등록부](/ko/guides/connections/posting-register/)에서 승인할 때까지 문서가 **승인 필요** 상태로 유지됩니다.
5. 전송: 문서가 시스템 자체 형식으로 변환되어 전송되며, 실행 또는 해당 시스템이 시뮬레이션이면 **전기 예정**으로 기록됩니다.

각 상태의 의미와 상태별 대처 방법은 [전기 등록부](/ko/guides/connections/posting-register/)에 있습니다.

## 단계 추가

워크플로에 **문서 전기** 단계를 추가합니다. 단계 메뉴의 **외부 시스템** 아래와 단계 팔레트의 **외부 시스템** 폴더에 있습니다. 양식에는 세 개의 섹션이 있고 그 뒤에 단계 설정을 여는 **더 보기 ▸** 링크가 있습니다.

1. **1 · 테이블** — 문서의 **테이블**을 선택합니다. 한 행이 한 라인입니다. 첫 번째 문서가 만들어지면 섹션에 테이블에서 읽은 라인 수와 문서 수가 표시됩니다.
2. **2 · 열 매칭** — 단계가 테이블의 각 열에서 인식한 내용입니다. 이름이 전기 필드인 열은 **이름으로 일치**이고, 알려진 대체 이름인 열은 **대체 이름으로 일치**입니다. 단계가 인식하지 못하는 열에는 목록이 제공됩니다. **이 열은 무엇입니까?** 에서 해당 열이 담고 있는 필드를 선택하면 **직접 선택함**으로 표시됩니다. 직접 선택한 열만 단계와 함께 저장됩니다. 두 열이 같은 필드를 가질 수는 없으며, 먼저 선택한 열이 필드를 유지합니다.
3. **3 · 시스템이 받게 될 첫 번째 문서** — 테이블의 첫 번째 문서를 라우팅하여 해당 시스템의 형식으로 변환한 것이며 라인과 함께, 테이블에 없는 열에 해당 시스템이 지정한 고정값이 있으면 그 값도 표시됩니다([시스템 설정](/ko/guides/connections/erp-systems/#시스템-설정) 참조). 아직 만들 수 없는 경우 섹션에서 전기되지 않음 사유와 같은 표현으로 이유를 알려 줍니다.

단계에는 **테이블**이 필요합니다. 보류 금액을 선택하는 경우 금액은 숫자여야 하며, 반올림 라인을 추가하는 경우 계정이 필요합니다.

## 테이블

테이블은 Data Foundation의 열 이름을 사용합니다. Data Foundation 형태의 분개는 매칭할 필요 없이 전기되고, 송장 처리된 판매 라인 테이블은 `account`와 `document_type`을 추가하면 전기됩니다. 한 행은 한 라인이며, `entity`와 `doc_number`가 같은 행은 하나의 문서입니다.

| 열 | 내용 |
|---|---|
| `doc_number` | 문서의 참조. 필수입니다. 이 열이 없는 테이블은 단계를 중지시킵니다. PlaidCloud가 버전 번호에 사용하는 `~`를 포함할 수 없습니다. |
| `entity` | 문서가 속한 엔터티. 시스템을 결정합니다. |
| `posting_date`, `document_date`, `period`, `fiscal_year`, `fiscal_period`, `period_type`, `ledger`, `journal_type` | 문서의 날짜와 기간. |
| `account` | 라인의 계정. |
| `amount_txn` 및 `currency_txn` | 라인의 금액과 통화. 현지 통화만 사용하는 테이블은 대신 `amount_local`과 `currency_local`을 사용할 수 있으며, 금액 대신 `debit`과 `credit`도 사용할 수 있습니다. |
| `description`, `line_number`, `quantity`, `unit` | 라인 텍스트, 순서, 수량. |
| `department`, `profit_center`, `product`, `customer`, `supplier`, `project`, `site`, `trading_partner`, `segment_1`~`segment_10` | 라인의 차원. |
| `tax_code`, `tax_amount_local`, `withholding_code`, `withholding_amount_local` | 세금 및 원천징수. |
| `due_date`, `payment_terms`, `supplier_invoice_number`, `purchase_order_number`, `invoice_no` | 송장 세부 정보. |
| `document_type` | `journal`(비워 두면), `customer_invoice`, `supplier_invoice`, `credit_memo`, `debit_memo` 또는 `payment`. 각 시스템이 받는 유형은 [ERP 시스템](/ko/guides/connections/erp-systems/)에 있습니다. |
| `set` | 세트 이름. 같은 이름을 공유하는 문서는 함께 전기되거나 전혀 전기되지 않습니다. [세트](#세트)를 참조하십시오. |

다음 대체 이름도 대소문자를 구분하지 않고 매칭됩니다. `doc_number`에는 `invoice_number`, `reference`, `journal id`, `posting_date`에는 `invoice_date`, `amount_local`에는 `net_amount_local`, `description`에는 `memo`, `department`에는 `cost center`, `supplier`에는 `vendor`입니다. 이 중 어디에도 해당하지 않는 열(예: 사용자 자신의 차원)은 이를 매핑하는 시스템 형식을 위해 문서와 라인에 그대로 전달됩니다.

일부 열은 전기 자체에 속하며 아직 사용할 수 없습니다. `action`이 `post`가 아닌 행이나 `reverse_on`을 설정하는 행은 전기되지 않습니다. 실행 페이지에는 "This is not available yet."라고 표시되며, 결과 테이블과 REST 응답에는 "only posting is available yet" 또는 "a date to reverse on is not available yet"라는 메시지가 포함됩니다. 전기를 되돌리거나 대변 처리하거나 정정하려면 [전기 등록부](/ko/guides/connections/posting-register/)를 사용하십시오.

문서는 월이 아니라 유형, 엔터티, 참조로 식별되므로 다른 월로 옮긴 문서도 같은 문서입니다.

### 세트

`set` 값이 같은 문서는 함께 전기되거나 전혀 전기되지 않습니다.

- 세트는 반올림 한도를 허용 오차로 하여 전체적으로 균형이 맞아야 합니다. 맞지 않으면 모든 멤버가 차이와 함께 전기되지 않습니다.
- 멤버 중 하나라도 검사에서 중단되면 나머지 세트도 "another document in set … was not posted"로 전기되지 않습니다. 멤버 중 하나라도 승인을 위해 보류되면 전체 세트가 **승인 필요** 상태로 대기합니다.
- 멤버 중 하나라도 시스템이 실거래가 아니면 전체 세트가 **전기 예정**이 되므로 일부도 실제로 전송되지 않습니다.

## 단계 설정

**더 보기 ▸** 메뉴는 단계의 네 가지 설정을 엽니다. 각 설정에는 초기값이 있으며 대부분의 단계는 변경하지 않습니다.

| 설정 | 초기값 | 기능 |
|---|---|---|
| **담당자 확인까지 보류** | 보류된 항목 없음 | 선택한 조건이 충족되면 승인을 위해 문서를 보류합니다. |
| **알림 대상** | **실행을 시작한 사람** | 조치가 필요한 문서가 있는 상태로 실행이 끝났을 때 알림을 받는 사람. |
| **반올림 계정 및 한도** | 반올림 없음 | 균형이 한도 이내로만 어긋난 문서에 반올림 라인을 추가합니다. |
| **전기된 문서가 변경되어 돌아올 때** | 묻기 | 전기된 이후 변경된 문서를 이후 실행이 어떻게 처리하는지. |

### 담당자 확인까지 보류

사람이 승인할 때까지 문서를 보류할 조건을 선택합니다.

- **금액이 다음을 초과하는 경우** — 금액. 문서 자체 통화로 된 문서 금액과 비교됩니다.
- **비정상으로 표시된 경우**
- **항상**

둘 이상을 선택하면 모두 참일 때만 문서가 보류됩니다. 아무것도 선택하지 않으면 단계는 자체 보류를 추가하지 않으며, 시스템의 보류 규칙과 역분개, 대변 또는 정정에 필요할 수 있는 두 번째 사람은 여전히 문서를 보류합니다. 단계의 보류는 시스템에 이미 있는 보류 규칙에 더해질 뿐입니다. 보류된 문서는 같은 세트의 나머지도 보류합니다. 문서를 보류시킨 전송을 수행한 사람과 해당 실행을 시작한 사람은 승인할 수 없습니다. 승인과 승인자는 [전기 등록부](/ko/guides/connections/posting-register/)와 [ERP 시스템](/ko/guides/connections/erp-systems/)에 있습니다.

### 알림 대상

**실행을 시작한 사람**이 초기값입니다. 대신 알림을 받을 멤버를 지정하려면 **사용자 목록…** 항목을 선택합니다. 조치가 필요한 문서가 있는 상태로 실행이 끝나면 알림을 받습니다.

### 반올림 계정 및 한도

**불균형 문서에 반올림 행 추가**를 선택한 다음 **계정**과 **한도**를 지정합니다. 한 통화에서 한도 이내로만 균형이 어긋난 분개에는 해당 계정에 대한 라인이 "Rounding"이라는 설명으로 추가되어 통과하며, 더 큰 차이나 둘 이상의 통화에서 발생한 차이는 차이 금액과 함께 불균형으로 중단됩니다. 한도는 세트 전체의 허용 오차이기도 합니다. 설정을 선택하지 않으면 아무것도 반올림되지 않습니다.

### 전기된 문서가 변경되어 돌아올 때

| 선택 | 이후 실행이 변경된 문서를 처리하는 방법 |
|---|---|
| **묻기(초기값). 두 가지 선택지와 함께 확인 필요 항목으로 이동합니다.** | 변경된 문서는 "The source changed after this was posted."라는 사유로 전기되지 않으며, 사람이 [실행 페이지](#변경된-문서)에서 **이 버전으로 수정** 또는 **게시된 항목 유지**를 선택할 때까지 대기합니다. |
| **정정. 되돌린 뒤 새 버전을 전기합니다. 매 기간 다시 실행하는 단계에 사용합니다.** | 실거래 실행에서는 전기된 문서가 되돌려지고 변경된 문서가 다음 버전으로 전송됩니다. |

## 시뮬레이션과 실거래

문서는 다음 두 조건이 모두 참일 때만 해당 시스템으로 전송됩니다.

- 실행이 실거래입니다. 워크플로 실행에는 프로젝트 자체 모드로 상한이 정해지는 전기 모드가 있으며, [전기 모드 선택](/ko/guides/workflows/run-a-workflow/#전기-모드-선택)에 설명되어 있습니다. 시뮬레이션 실행은 아무것도 전송하지 않으며 끔 모드의 실행은 단계를 건너뜁니다.
- 문서의 시스템이 프로젝트에서 실거래입니다. 프로젝트의 전기 모드가 실거래이고 시스템의 연결과 환경에 대한 프로젝트의 쓰기 승인이 있는 상태입니다. [프로젝트에 전기 권한 부여](/ko/guides/workflows/run-a-workflow/#프로젝트에-전기-권한-부여)와 [ERP 시스템](/ko/guides/connections/erp-systems/)의 라이브 전환을 참조하십시오.

그렇지 않으면 문서는 검사되어 **전기 예정**으로 기록되며 아무것도 전송되지 않습니다. 시뮬레이션은 시스템에 접속하지 않습니다. 시뮬레이션 실행에서는 시스템에 문의해야 하는 검사도 수행되지 않습니다. 단계에는 자체 드라이 런 설정이 없습니다. 유일한 예외는 전기를 테스트하도록 설정된 SAP 전기 단계에서 변환된 단계입니다. 이 단계는 항상 시뮬레이션으로 실행되며, 문서는 실행 페이지의 **이 항목 게시**를 통해서만 전기됩니다.

시뮬레이션 실행은 전기될 내용을 정확히 확인하는 방법입니다. 결과가 올바르면 [실행 페이지](#이-항목-게시)의 **이 항목 게시**가 고정된 같은 문서를 전송합니다.

## 다섯 가지 검사

전송 전에 모든 문서는 다섯 가지 검사를 거칩니다. 실행 페이지에는 각 검사가 통과, 실패 또는 확인되지 않음 중 어느 것인지 표시됩니다.

| 검사 | 문서가 중단되는 경우 |
|---|---|
| Balanced | 차변과 대변이 일치하지 않으며 반올림 한도를 초과함. |
| Period open | 시스템에서 마감된 기간에 속한 전기 날짜. |
| Accounts exist | 시스템에 없는 계정, 매칭되지 않는 코드, 시스템이 필요로 하는 빈 값, 미결이 아닌 송장, 다른 회사, 또는 시스템이 기록하지 않는 통화. |
| Not posted before | 이미 다른 시스템에 전기되었거나 이 시스템에서 이미 사용된 참조. |
| Sets agree | 멤버가 누락되었거나 문서의 합이 맞지 않는 세트. |

**Period open**과 **Accounts exist**는 실거래 시스템으로의 실거래 실행이 시작될 때 PlaidCloud가 시스템에서 읽는 목록을 사용합니다. 시뮬레이션 실행이거나 목록 읽기가 일부만 되었거나 비었거나 늦은 경우 이 검사는 확인되지 않음으로 표시됩니다. [ERP 시스템](/ko/guides/connections/erp-systems/)에서 **지금 새로 고침**이 보관하는 목록 사본은 보기용이며 검사에 사용되지 않습니다. 실거래 시스템으로의 실거래 실행은 시스템 형식에 해당 검사가 있는 경우 시스템 자체의 검사도 수행하며, 시뮬레이션 실행은 수행하지 않습니다.

문서에서 실행되지 않은 검사는 확인되지 않음으로 간주되며 통과로 간주되지 않습니다. 실행 페이지에는 다섯 가지 검사 이름이 모든 언어에서 영어로 표시됩니다.

## 단계가 실행될 때

- 단계는 시스템이 응답할 때까지 최대 10분을 기다립니다. 그때까지 응답이 없는 문서는 기록에서 계속 진행되며, 응답이 도착하면 실행 페이지가 채워집니다.
- 실행 로그에 "Posted n of m · k need attention"이라는 한 줄이 남습니다. 조치가 필요한 문서가 있으면 단계는 "k of m documents need attention"이라는 경고와 함께 끝나며 **알림 대상**의 사용자에게 알림이 전송됩니다. 워크플로의 나머지는 계속 진행됩니다.
- 존재하지 않거나 열이 없거나 행이 없는 테이블은 경고이며 아무것도 전기되지 않습니다. `doc_number` 열이 없는 테이블은 오류와 함께 단계를 중지시킵니다.
- 단계의 구성에 결과 테이블이 지정되어 있으면 단계는 문서당 한 행을 기록합니다. `doc_number`, `action`, `state`, `source_system`(전기한 시스템), `source_doc`(시스템이 부여한 번호), `message`입니다.

## 실행 페이지

모든 실행에는 페이지가 있습니다. 단계의 실행, 파일의 실행, REST 또는 MCP로 시작한 실행, 재시도, 되돌리기가 모두 해당됩니다. [전기 등록부](/ko/guides/connections/posting-register/)의 **실행 횟수**에서 **열기**로 엽니다. 페이지에는 볼 수 있는 문서만 표시되며, 볼 수 있는 문서가 없으면 "This run was not given any document you may see."라고 표시됩니다.

페이지 상단에는 실행 상태가 표시됩니다.

- 시뮬레이션: "This run is in Simulate. Nothing has been sent to any system. Post these sends the same frozen documents."
- 실거래이며 아직 실행 중: 전기하기 위해 누를 것이 없습니다. 시스템이 응답하는 대로 페이지가 채워지며 아직 전송되지 않은 문서 수가 표시됩니다. 실행 중이거나 대기 중인 항목이 있는 동안 스스로 실행을 다시 읽습니다.
- 실거래이며 완료: "Live. Every system answered."
- 중지됨: "This run was stopped. What had not been sent is Not posted."

문서 위의 **요약**은 열고 닫을 수 있으며 마지막 상태가 유지됩니다. 실행에 문서가 있으면 닫힌 상태로 시작합니다. 다음이 포함됩니다.

- 단계의 실행인 경우 먼저 비교 결과입니다. 예: "121 unchanged, 19 changed, 2 new." [다시 실행](#다시-실행)을 참조하십시오.
- 실행의 문서, 세트, 시스템, 금액과 각 상태에 있는 수.
- [다섯 가지 검사](#다섯-가지-검사). 각 검사에 체크 표시, ×, 또는 아무것도 도달하지 않은 경우 대시가 표시됩니다. 실패한 검사에는 통과하지 못한 문서 수가 표시됩니다.
- **시스템별**: 시스템당 한 줄로 각 상태의 수와 금액, 그리고 **합계**. 모드가 실행의 모드와 다른 시스템에는 시뮬레이션 또는 실거래로 표시됩니다. 각 수를 선택하면 해당 문서가 열립니다.
- 테이블 자체의 합계와 문서의 합계 비교: "Equal. No row of the table was left out." 또는 "They differ. A row of the table was left out or counted twice." 일부 엔터티만 볼 수 있는 경우 합계는 볼 수 있는 항목의 합계입니다.
- 각 시스템의 기간 및 계정 사본이 얼마나 오래되었는지, 또는 아직 사본이 없다는 사실.

그 아래의 **문서** 목록은 사람의 조치가 필요한 항목을 먼저 보여 줍니다. 각 행에는 참조(`JE-1001~2`와 같은 버전 포함), 엔터티, 시스템, 세트, 금액, 상태, **이유와 다음 단계**가 있습니다. **그룹화 기준**은 문서를 **엔터티**, **유형**, **세트** 또는 **시스템**별로 그룹화합니다. 문서 하나를 선택하면 사유와 다음 단계를 전체로 읽을 수 있으며, 해당하는 경우 **변경된 내용**, **거부 해결 방법**, **비정상**도 볼 수 있습니다. 각 행은 **전기 열기**로 [전기 등록부](/ko/guides/connections/posting-register/)에서 해당 전기를 열고, **해당 세트 표시**로 세트를 표시하며, 재시도가 도움이 되는 경우 **다시 시도**를 제공합니다.

### 이 항목 게시

**전기 예정** 상태의 문서가 있는 실행은 "Post these sends exactly the documents shown." 옆에 문서 수와 함께 **이 항목 게시**를 제공합니다. 이 버튼은 현재 시점으로 한 번 더 검사하여 해당 문서를 전송합니다. 프로젝트가 실거래를 허용해야 하고, 시뮬레이션 실행 이후 참조가 전기되지 않았어야 하며, 시스템 자체의 검사가 다시 실행됩니다. 아직 시뮬레이션인 시스템의 문서는 **전기 예정**으로 남습니다. 실행은 실거래가 되며 페이지에 전송된 수와 다시 검사되어 전기되지 않은 수가 표시됩니다.

- 일부 시스템이 아직 실거래가 아니면 버튼에 **라이브로 전환하여 게시**가 표시되거나 실거래로 전환할 시스템 이름이 표시됩니다. 먼저 프로젝트에서 해당 시스템을 실거래로 만들며, 실거래로 전환할 수 없는 시스템이 있으면 아무것도 전송되지 않습니다. 시스템을 실거래로 전환할 수 있는 사람에게만 표시되며, 다른 사용자는 시스템의 현재 상태 그대로 전기합니다. [ERP 시스템](/ko/guides/connections/erp-systems/)을 참조하십시오.
- 보류 규칙이 보류한 문서는 이번 전송에서 다시 보류됩니다. **이 항목 게시**를 누른 사람과 실행을 시작한 사람은 승인할 수 없습니다.
- 볼 수 있는 문서만 전송됩니다. 저장된 사본이 만료된 문서는 전기되지 않으며, 실행 페이지에는 "This is not available yet."라고 표시되고 REST 응답에는 "The stored document has expired; run again."이라는 메시지가 포함됩니다.

### 시스템에서 확인

전기된 문서가 있는 실행은 **시스템에서 확인**을 제공하며, 문서가 모두 한 시스템에 있으면 *시스템 이름* **에서 체크인**을 제공합니다. 이는 각 시스템에 실행에서 전기된 문서가 있는지 묻고 그 답을 기록합니다. [전기 등록부](/ko/guides/connections/posting-register/)에서 시스템에서 찾은 문서는 **시스템 문서** 옆에 **장부 반영**으로 표시되고, 없거나 다른 문서는 **조치 필요**로 이동합니다. 권한을 보유한 연결의 문서, 접근할 수 있는 프로젝트의 문서에 대해서만 묻고 `analyze.workflow.write`가 필요합니다.

### 실행 중지

아직 실행 중이며 전송되지 않은 문서가 있는 실거래 실행은 **실행 중지**를 제공합니다. 아직 전송되지 않은 문서는 전기되지 않음이 되며 실행 페이지에 "The run was stopped before this was sent."라고 표시됩니다. 이미 전송된 문서는 그대로 두며, 페이지에 중지된 수와 이미 전송된 수가 표시됩니다. 실거래 실행이 전송 중간에 있고 아직 문서가 기록되지 않은 동안에는 중지할 수 없습니다.

### 다시 시도

행의 **다시 시도** 또는 세트의 **나머지 다시 시도**는 전기되지 않은 문서를 고정된 상태 그대로 프로젝트의 전기 모드에 따른 새 실행으로 다시 전송합니다. 이미 전기된 문서는 다시 전송되지 않습니다. 원인이 문서 밖에 있는 경우, 즉 승인자가 거절했거나, 실행이 중지되었거나, 에이전트가 오프라인이었거나, 시스템이 거부했거나, 기한에 찾지 못했거나, 전송되지 않았거나, 엔터티에 시스템이 없었던 경우 다시 시도를 제공합니다. 검사에서 중단된 문서는 소스를 수정한 뒤 단계를 다시 실행해야 합니다.

### 사람의 조치가 필요한 세트

**사람의 조치가 필요한 세트**는 일부만 전기되었거나 멤버가 통과하지 못해 아무것도 전송되지 않은 세트를 나열합니다. **세트 표시**는 문서를 해당 세트로 필터링합니다. 일부만 전기된 세트의 경우 **나머지 다시 시도**는 전기되지 않은 항목을 다시 시도하고, **전기된 항목 되돌리기**는 어떤 시스템에서 무엇이 되돌려질지 보여 준 다음 세트의 일부는 전기되고 나머지는 전기되지 않았다는 사유로 되돌립니다. 두 번째 사람이 필요한 되돌리기는 **승인 필요** 상태로 대기하며, 페이지는 **되돌리기 실행 열기**로 해당 되돌리기의 실행 페이지에 연결합니다.

### 변경된 문서

단계가 묻기로 설정되어 있고 실행에서 전기 이후 변경된 문서를 발견하면 페이지에 선택을 기다리는 문서 수가 표시됩니다.

- **모두 정정** 또는 선택한 문서의 **이 버전으로 수정**은 전기된 문서를 되돌리고 변경된 문서를 해당 참조의 새 버전으로 전기합니다.
- **모두 유지** 또는 선택한 문서의 **게시된 항목 유지**는 전기된 버전을 유지하고 변경된 문서를 버립니다.

각각 먼저 확인을 요청합니다.

## 실행 횟수

전기 등록부의 **실행 횟수**는 전기 단계 또는 전기 파일의 모든 실행을 최신순으로 나열하며 **모드**, 시작한 사람, 결과가 함께 표시됩니다. **열기**는 해당 실행 페이지를 엽니다.

목록 위에는 지난달 요약이 표시됩니다. 시스템당 한 줄로, 몇 개 중 몇 개의 문서가 전기되었는지, 금액, 시스템 자체 장부에 몇 개가 있는지, 몇 개의 전기에 조치가 필요한지가 표시됩니다. 그 전달에 시스템에 전기했지만 그 달에 실행되지 않은 단계는 그 아래에 이름이 표시됩니다. 줄의 **열기**는 그 시스템의 해당 월 전기를 열며, 월이 완료되지 않았으면 **'조치 필요' 열기**가 남은 항목으로 이동합니다. 요약은 단계의 실거래 실행을 집계합니다.

## 다시 실행

참조는 한 번 전기됩니다. 실행에 이미 기록에 있는 문서가 있으면 다음과 같이 처리됩니다.

- 변경되지 않은 문서는 그대로 둡니다.
- 변경된 문서는 단계의 [전기된 문서가 변경되어 돌아올 때](#전기된-문서가-변경되어-돌아올-때) 설정(묻기 또는 정정)을 따릅니다. 정정은 `JE-1001~2`와 같은 참조의 다음 버전을 전기하며 시스템도 버전을 인식합니다.
- 이전 버전이 아직 시스템의 응답을 받지 못한 문서는 "An earlier version of this reference has no answer from the system yet. Run again once it has one."라는 사유로 전기되지 않습니다.

키에 엔터티가 포함되는 시스템에서는 다른 엔터티의 같은 참조는 다른 문서입니다. 그 밖의 시스템에서는 "This reference is already used on this system."이라는 사유로 거부됩니다.

단계가 이전에 전기했지만 이번에 생성하지 않은 문서는 그대로 둡니다. 단계의 실거래 실행이 끝나면 해당 페이지에 "3 documents posted before were not produced this time. They are left alone."와 같이 각 문서의 참조와 시스템과 함께 나열됩니다. 목록에는 이 실행 문서의 기간에 단계가 실거래로 전기한 문서 중 여전히 **전기됨** 상태이고, 전액 대변 처리되지 않았으며, 볼 수 있는 것이 포함됩니다. 실행이 더 이상 보관되지 않는 문서는 나열되지 않으므로 [전기 등록부](/ko/guides/connections/posting-register/)에서 되돌리십시오.

**이 항목 되돌리기**는 **이 3건 되돌리기**와 같이 개수와 함께 표시되며, 확인하면 해당 문서를 새 실행으로 되돌립니다. 두 번째 사람이 승인해야 하는 되돌리기는 **승인 필요** 상태로 대기하며, **되돌리기 실행 열기**로 새 실행을 엽니다. 이 버튼은 잠기지 않은 프로젝트의 아키텍트 또는 관리자에게 표시되며, 지금 되돌릴 수 있는 문서, 즉 권한을 보유한 시스템에 있고 프로젝트가 실거래로 전기할 수 있는 문서만 셉니다. 한 번의 작업으로 처리할 수 있는 200개를 넘으면 목록은 200개에서 멈추고 버튼은 표시되지 않습니다. REST API에서는 실행과 함께 `POST /rest/v1/analyze/erp/reverse/these`가 같은 작업을 하거나 지정한 문서만 되돌리며, 아직 실행 중이거나 시뮬레이션된 실행은 거부합니다.

배부를 전기하는 단계처럼 매 기간 다시 실행하는 단계에서는 **전기된 문서가 변경되어 돌아올 때**를 한 번 정정으로 설정하십시오.

## 파일에서 전기

스프레드시트에 있는 소수의 분개는 워크플로 없이 파일을 전기할 수 있습니다.

[전기 등록부](/ko/guides/connections/posting-register/)에서 범위를 하나의 프로젝트로 좁힌 다음 **전기** 도구 모음의 **작업** 메뉴에서 **파일에서 전기…** 항목을 선택합니다. `erp.register.operate` 권한이 있는 멤버에게 제공되며, 범위에 단일 프로젝트가 없으면 "Choose one project in the scope first."라고 표시됩니다. **파일에서 전기** 창에는 카드가 세 개 있습니다.

1. **1 · 시스템 및 문서 유형 선택** — **환경**, **시스템**, 해당 시스템이 받는 **문서** 종류. **시작 파일 다운로드**는 해당 시스템과 문서에 맞는 열 제목과 예시 행을 Excel 파일로 다운로드합니다.
2. **2 · 파일 업로드** — **여기에 스프레드시트를 놓으십시오**에 스프레드시트(`.xlsx` 또는 `.csv`)를 놓습니다. 함께 놓은 추가 파일은 보조 파일로 실행과 함께 보관되지만 아직 시스템으로 전송되지 않습니다. 실행이 준비되면 실행 페이지가 열립니다.
3. **이전 파일 실행** — 프로젝트의 이전 파일 실행이며 각각 **다시 전기**가 있습니다.

REST API 또는 MCP 도구를 사용하는 경우:

1. `GET /erp/file-post/starter`에 `connection_id`, `document_type`, `format`(`xlsx` 또는 `csv`)을 지정하면 해당 시스템에서 그 종류의 문서에 맞는 열 제목과 예시 행이 다운로드됩니다. 시스템이 받지 않는 종류의 문서는 거부됩니다.
2. `POST /erp/file-post`는 스프레드시트(`.xlsx` 또는 `.csv`)를 `file`로, `project_id`와 함께 받습니다. `attachments`로 보낸 추가 파일은 보조 파일로 실행과 함께 보관되지만 아직 시스템으로 전송되지 않습니다. MCP 도구 `erp_file_post`는 대신 PlaidCloud 문서의 파일을 `account_id`와 `path`로 받습니다.
3. 실행은 시뮬레이션으로 열리며 아무것도 전송되지 않습니다. [실행 페이지](#실행-페이지)에서 검토하고 **이 항목 게시**로 전기합니다.

- 각 문서는 다른 실행과 마찬가지로 해당 엔터티가 전기하는 시스템으로 전송됩니다.
- `doc_number` 열이 없는 파일은 아무것도 준비하지 않고 **이 파일을 하나의 분개로 처리하시겠습니까?** 질문을 표시합니다. **예, 하나의 분개**는 파일 이름을 참조로 하여 파일 전체를 하나의 분개로 전기하고, **아니요**는 `doc_number` 열을 추가한 뒤 파일을 다시 선택하도록 요청합니다. REST API에서는 `ask: one_journal`로 응답합니다. `one_journal`을 true로 설정하여 다시 보내면 하나의 분개가 되고, false로 설정하면 각 행을 파일 이름에 번호를 붙인 개별 분개로 전기합니다.
- `doc_number` 열이 있는 파일에서는 값이 없는 행이 경고와 함께 제외됩니다. 전기 열이 아닌 제목은 무시되며 경고에 해당 제목이 표시됩니다.
- 비어 있거나 행이 없는 파일은 아무것도 준비하지 않으며 그렇게 안내합니다. 전기가 끔인 프로젝트도 마찬가지입니다.

### 다시 전기

다시 전기는 매월 반복되는 분개를 위해 파일 실행의 문서를 새 전기 날짜와 새 참조로 다시 전기합니다.

앱에서 파일 실행의 페이지는 문서가 보관되어 있는 동안 잠기지 않은 프로젝트의 아키텍트 또는 관리자에게 **다시 전기**를 제공하며, **파일에서 전기**의 **이전 파일 실행**에도 있습니다. **전기일**을 선택한 다음:

- **다시 전기**는 각 참조에 접미사를 붙여 반복 전기가 이미 전기됨으로 거부되지 않게 하고 새 실행을 시뮬레이션으로 엽니다.
- **매월 반복**은 대신 일정으로 등록합니다. 전기일과 같은 날(최대 28일), 06:00 UTC에 실행하며 각 반복은 실행하는 날짜로 표시됩니다. 이 파일의 문서가 실거래로 전기된 경우 프로젝트가 허용하는 범위에서 실거래로 전기합니다.

REST API에서는 `POST /erp/file-post/{run_id}/again`으로 다시 전기하거나 MCP 도구 `erp_file_post_again`을 사용합니다:

- `posting_date`는 ISO 날짜, `today`, `first_of_month`, `last_of_month`, `first_of_next_month`, `last_of_prev_month` 중 하나, 또는 각 문서 자체의 전기 날짜를 기준으로 한 `+1m` 또는 `-7d`와 같은 이동 값입니다.
- `references`를 `suffix`로 설정하면 각 참조에 `JE-1001-202612`와 같이 새 월의 접미사가 붙어 반복 전기가 이미 전기됨으로 거부되지 않습니다. REST에서는 대신 각 참조를 새 참조에 매핑할 수 있습니다. MCP 도구는 항상 접미사를 추가합니다.
- 문서 날짜는 전기 날짜와 함께 이동하고, 만기일은 같은 일수만큼 이동하며, 시스템이 새 날짜에서 기간을 가져오도록 기간 열은 제거됩니다.
- 새 실행은 `live`로 실거래를 요청하지 않는 한 시뮬레이션으로 열리며 프로젝트의 전기 모드를 넘지 않습니다. 볼 수 있는 엔터티의 문서만 다시 전기됩니다.

`POST /erp/file-post/{run_id}/schedule`은 `cron`과 `timezone`, 실행할 때마다 계산되는 `posting_date`, `suffix`로 설정된 `references`와 함께 다시 전기를 일정에 등록합니다. 사용자 자신으로 실행되며 볼 수 있는 엔터티만 전기합니다. 누군가 이 파일의 문서를 이미 실거래로 전기한 경우에만 실거래로 전기하며 프로젝트의 전기 모드를 넘지 않습니다. 일정에는 MCP 도구가 없습니다.

실행의 문서는 시뮬레이션된 경우 30일, 응답을 받은 후 90일 동안 보관됩니다. 그 이후에는 다시 전기가 준비할 것이 없으며 그렇게 안내합니다.

### 이미 전기됨으로 기록

PlaidCloud를 사용하기 전에 시스템에 전기된 문서는 `POST /erp/record-posted`로 시스템에 접속하지 않고 전기됨으로 기록하므로, 해당 문서가 있는 이후 실행은 다시 전기하는 것을 거부합니다. 스프레드시트를 `file`로, 시스템의 `connection_id`와 `environment_id`와 함께 보냅니다. `reference`와 `system_document` 열이 필요하며 선택적으로 `entity`, `posting_date`, `document_type`(생략하면 분개)이 있습니다. 앱에서는 `erp.register.operate` 권한이 있는 멤버에게 **파일에서 전기**에 **이 제품을 사용하기 전에 전기하셨습니까? 이미 전기됨으로 기록**이 표시됩니다. 이를 선택하면 **이미 전기됨으로 기록**이 열리며, 여기서 **환경**과 **시스템**을 선택하고 스프레드시트를 놓은 다음 **전기됨으로 기록**을 선택합니다. MCP 도구는 없습니다.

- PlaidCloud가 이미 전기됨으로 가지고 있는 문서, 아직 응답을 기다리는 문서, 또는 다른 시스템 문서로 가지고 있는 참조는 기록되지 않음으로 이유와 함께 나열됩니다.
- 파일의 미확인 문서는 전기 등록부 승인자 역할이 있는 사람만 전기됨으로 확정할 수 있으며, 다른 사람은 기록되지 않음으로 돌려받습니다.

## 배부에서 전기

**배부: 차원을 사용하여 분할** 단계는 결과를 문서 테이블로 기록하여 문서 전기 단계가 전기하도록 할 수도 있으며, 단계 구성의 `post_documents` 설정을 통해 이루어집니다. 설정에는 기록할 문서 `table`과 결과의 `rule`, `account`, `source_account`, `amount`, `posting_date`(모두 필요) 열, 선택적으로 `entity`와 `currency_txn`이 지정되며, `set`은 문서에 고정된 세트 이름을 부여합니다.

- 각 규칙은 월마다 하나의 문서이며 규칙과 월로 참조됩니다(예: `RENT-202611`). 각 결과 행은 해당 계정에 대한 라인과 원천 계정에 대한 상계 라인이 되므로 모든 문서의 균형이 맞습니다.
- 규칙이 없거나 금액이 0인 행은 라인을 만들지 않습니다. 금액이 숫자가 아닌 행은 해당 행을 알리는 경고와 함께 제외됩니다. 전기할 항목이 남지 않으면 단계는 경고하고 문서 테이블을 비웁니다.
- 같은 월에 배부를 다시 실행하면 같은 참조가 만들어지므로 전기 단계의 [전기된 문서가 변경되어 돌아올 때](#전기된-문서가-변경되어-돌아올-때)를 정정으로 설정하십시오.

## SAP 전기 단계 변환

기존 SAP 전기 단계를 문서 전기 단계로 바꿀 수 있습니다. 저절로 변환되는 것은 없습니다. 캔버스에서 단계를 마우스 오른쪽 버튼으로 클릭하고 **문서 전기로 변환…** 항목을 선택하거나, 단계 양식의 **문서 전기로 변환…** 항목을 사용합니다. PlaidCloud는 먼저 변환될 내용을 보여 줍니다. 문서 필드에 매칭된 열, 시스템으로 라우팅된 엔터티, 기존처럼 계속 전기되는지 시뮬레이션으로 시작하는지, 그리고 경고를 보여 주며, **변환**으로 확인합니다. 이전 설정은 단계의 버전에 남습니다.

- SAP 전기 단계만 변환됩니다. 함수나 헤더 열이 설정되지 않았거나 문서 키가 회사 코드와 하나의 문서 번호가 아닌 단계는 변환되지 않으며, PlaidCloud가 이유를 알려 줍니다.
- 단계의 필터에 있는 엔터티는 해당 연결로의 경로로 제안됩니다. 필터에 엔터티가 없으면 전기하기 전에 [ERP 시스템](/ko/guides/connections/erp-systems/)에서 라우팅을 설정하십시오.
- 변환된 단계에 테이블을 설정하기 전까지는 이전 단계의 헤더, 라인, VAT, 원천징수 테이블을 직접 읽습니다.
- 변환된 단계는 이전 단계가 전기한 내용의 기록을 유지하므로 이전 단계가 이미 전기한 기간은 다시 전기되지 않습니다.
- 전기를 테스트하도록 설정된 단계는 계속 시뮬레이션으로 실행됩니다. [시뮬레이션과 실거래](#시뮬레이션과-실거래)를 참조하십시오.

## REST 및 MCP로

같은 전기를 REST API의 `/rest/v1/analyze/erp` 아래와 MCP 도구로도 사용할 수 있습니다.

| 작업 | REST | MCP |
|---|---|---|
| 테이블의 첫 번째 문서를 시스템이 받게 될 형태로 보기 | `POST /erp/post/preview` | `erp_post_preview` |
| 테이블 또는 문서 목록 전기 | `POST /erp/post` | `erp_post_documents` |
| 실행과 실행 페이지 읽기 | `GET /erp/runs`, `GET /erp/runs/{run_id}` | `erp_run_find`, `erp_run_describe` |
| 이 항목 게시 또는 실행 중지 | `POST /erp/runs/{run_id}/post`, `POST /erp/runs/{run_id}/stop` | `erp_run_post`, `erp_run_stop` |
| 변경된 문서에 대해 묻기에 응답 | `POST /erp/ask` | `erp_ask_answer` |
| 문서 다시 시도 | `POST /erp/retry` | `erp_retry` |
| 시작 파일 다운로드 | `GET /erp/file-post/starter` | — |
| 파일에서 전기 및 다시 전기 | `POST /erp/file-post`, `POST /erp/file-post/{run_id}/again` | `erp_file_post`, `erp_file_post_again` |
| 일정에 따라 다시 전기 | `POST /erp/file-post/{run_id}/schedule` | — |
| 이미 전기됨으로 기록 | `POST /erp/record-posted` | — |
| SAP 전기 단계 변환 | `POST /erp/convert` | `erp_convert_step` |

- REST 또는 MCP 전기는 실거래를 요청하지 않는 한 시뮬레이션으로 실행되며 프로젝트의 전기 모드를 넘지 않습니다.
- 테이블의 REST 전기는 최대 100,000행을 읽습니다. 더 긴 테이블은 통째로 거부되며 대신 단계로 전기합니다.
- `erp_file_post`는 PlaidCloud 문서의 파일을 받습니다. 파일이 없으면 경고이며 아무것도 준비되지 않습니다.
- 변환과 재시도는 달리 지정하지 않으면 드라이 런입니다.
- 사용자를 대신하는 AI 어시스턴트는 실거래 전기, **이 항목 게시**, 정정, 실제 재시도, 실제 변환, 다시 전기가 거부됩니다. 이런 작업은 사람이 합니다.

## 권한별 수행 가능 작업

| 작업 | 필요한 권한 |
|---|---|
| 단계 빌드 및 첫 번째 문서 미리 보기 | `analyze.step.write` |
| REST 또는 MCP로 전기 | `analyze.workflow.write` 및 프로젝트에 대한 쓰기 권한 |
| 시작 파일 다운로드 | `analyze.connection.read` |
| 파일에서 전기 | `analyze.workflow.write` 및 프로젝트에 대한 권한 |
| 실행 페이지 열기 | `analyze.project.read`. 볼 수 있는 엔터티의 문서가 표시됩니다 |
| 전기 등록부의 **실행 횟수** 보기 | `erp.register.view` |
| **이 항목 게시**, **실행 중지**, 정정 또는 유지, 다시 전기와 그 일정, 실행이 생성하지 않은 항목 되돌리기 | `analyze.workflow.write`, 그리고 잠기지 않은 프로젝트의 아키텍트 또는 관리자 |
| 전기하면서 시스템을 실거래로 전환 | 잠기지 않은 프로젝트의 아키텍트이며 연결에 대한 본인의 쓰기 권한 |
| **다시 시도** | `analyze.workflow.write`, 그리고 잠기지 않은 프로젝트의 아키텍트 또는 관리자이며 문서의 연결에 대한 본인의 쓰기 권한 |
| **전기된 항목 되돌리기** | `erp.register.view` 및 `erp.register.operate` |
| 이미 전기됨으로 기록 | `erp.register.view` 및 `erp.register.operate`와 연결에 대한 본인의 쓰기 권한. 미확인 문서를 확정하려면 `erp.register.approve`도 필요 |
| SAP 전기 단계 변환 | `analyze.step.write`와 프로젝트에 대한 쓰기 권한 |

모든 경로는 같은 규칙을 적용합니다. UI, REST API, MCP 도구는 같은 검사를 호출합니다.
