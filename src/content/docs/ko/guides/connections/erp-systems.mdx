**시스템**은 하나의 환경에 있는 하나의 ERP 연결입니다. **문서 전기** 단계, 파일에서 전기 및 그 밖의 모든 전기 방법([ERP 시스템에 문서 전기](/ko/guides/connections/post-documents/) 참조)은 각 문서를 시스템으로 전송하며, 문서를 어떻게 만들고 검사하고 보낼지는 시스템이 결정합니다. 볼 수 있는 모든 ERP 연결은 각각 하나의 시스템으로 표시됩니다. SAP 연결 다섯 개는 시스템 다섯 개이며 클라우드와 온프레미스가 나란히 표시됩니다. 같은 연결이라도 샌드박스와 프로덕션 [환경](/ko/guides/connections/create-connection/#환경)에 있으면 각자의 설정을 가진 두 개의 시스템입니다.

시스템은 환경별로 한 번만 설정하면 됩니다. 해당 환경의 모든 프로젝트는 어느 엔터티가 어디에 전기하는지에 대한 그리드와 각 시스템의 설정을 공유합니다. 라이브 전환만 프로젝트별입니다.

## 시스템 열기

[전기 등록부](/ko/guides/connections/posting-register/)를 열고 레일의 **설정** 아래에서 **시스템**을 선택합니다. 헤더에는 다음이 있습니다.

- 환경 선택기: 시스템을 나열할 환경.
- 프로젝트 선택기: 처음에는 **프로젝트 없음**입니다. 프로젝트를 선택하면 각 시스템이 해당 프로젝트에서 실거래인지 확인하고 라이브로 전환할 수 있습니다.
- **작업**: **이 프로젝트에서 라이브 전환…**(프로젝트 아키텍트에게 표시), **다른 환경으로 복사…**(워크스페이스 관리자에게 표시), **어느 법인이 어디에 전기할지 제안…** 및 **변경 내역**.

페이지에는 **시스템 · *환경***과 **어떤 법인이 어디에 전기하는가**라는 두 개의 카드가 표시됩니다. 환경에 ERP 연결이 없으면 페이지에 **전기할 시스템 없음**이라고 표시됩니다. 연결에서 ERP 시스템에 대한 연결을 추가하면 여기에 나타납니다.

## 시스템 목록

각 시스템은 이름, ERP 유형 및 여러 개의 필 배지로 이루어진 한 행입니다.

| 필 배지 | 의미 |
|---|---|
| **클라우드** | 클라우드 시스템. |
| **온프레미스 · 에이전트 온라인** | 에이전트가 최근 5분 이내에 통신한 온프레미스 시스템. |
| **온프레미스 · 에이전트 오프라인(*시간* 이후)** / **온프레미스 · 에이전트 연결 안 됨** | 에이전트가 온라인이 아니거나, 이 환경을 담당하는 에이전트가 없음. |
| **전기 가능** | 시스템에 전기할 수 있음. |
| **확인되지 않음** | 에이전트가 온라인이 아닌 온프레미스 시스템. |
| **실거래** / **시뮬레이션** | 프로젝트를 선택한 경우에만 표시됩니다. 이 시스템이 해당 프로젝트에서 실제로 전기하는지 여부. |
| **사용 종료** | 시스템이 새 전기를 받지 않음. 실거래 또는 시뮬레이션 대신 표시됩니다. |

행에는 두 개의 버튼이 표시될 수도 있습니다.

- **다시 연결** — 온프레미스 시스템의 에이전트가 온라인이 아닐 때 표시됩니다. 연결을 열어 다시 로그인할 수 있습니다.
- **라이브 전환 ›** — 프로젝트를 선택한 상태에서 사용 종료가 아니고, 전기할 수 있으며, 아직 시뮬레이션인 시스템에 대해 프로젝트 아키텍트에게 표시됩니다. [라이브 전환](#라이브-전환)을 참조하십시오.

### 행을 열면 나타나는 내용

행 왼쪽의 토글로 행을 엽니다. 세 가지 항목과 링크 행이 표시됩니다.

**남은 작업**은 시스템이 전기하기까지 남은 일의 체크리스트이며 각 항목에 담당자가 표시됩니다. 완료된 항목에는 체크 표시가 되고 완료로 표시됩니다.

| 항목 | 담당 | 완료 조건 |
|---|---|---|
| 서비스 계정 및 권한 | **IT** | 현재는 항상 완료 상태이며 설정할 것이 없습니다. |
| 에이전트 설치 및 온라인(온프레미스만 해당) | **IT** | 에이전트가 온라인입니다. |
| 엔터티가 이 시스템에 전기 | **워크스페이스 관리자** | [어떤 법인이 어디에 전기하는가](#어떤-법인이-어디에-전기하는가)의 행 하나가 이 시스템을 지정합니다. |
| 라이브 전환 | **프로젝트 아키텍트** | 선택한 프로젝트에서 시스템이 실거래입니다. |

**수행 가능한 작업**은 "Takes journals, customer invoices · reverses journals · answers in the call"과 같은 한 줄입니다. 시스템이 받는 문서 유형, 되돌릴 수 있는 유형, 응답이 **호출 시 응답**으로 오는지 **나중에 응답**으로 오는지를 나열합니다. 각 시스템의 전체 목록은 아래 [각 시스템이 할 수 있는 작업](#각-시스템이-할-수-있는-작업)에 있습니다.

**해당 목록의 사본**은 시스템의 계정, 회사 및 기간 사본이 얼마나 오래되었는지를 **지금 새로 고침** 및 **사본 보기**와 함께 보여 줍니다. [시스템 목록의 사본](#시스템-목록의-사본)을 참조하십시오.

그 아래의 링크는 **IT용**, **설정…**, **사용 종료로 표시**(또는 **사용 종료에서 복원**) 및 **기록**이며, **기록**은 이 시스템만의 [변경 내역](#변경-내역)을 엽니다.

## 설정 종류

모든 설정에는 초기값이 있으며 대부분의 프로젝트는 이를 변경하지 않습니다.

| 설정 | 위치 | 변경 권한 | 초기값 |
|---|---|---|---|
| 어느 엔터티가 어디에 전기하는가 | 환경별로 한 번, [시스템](#어떤-법인이-어디에-전기하는가) | 워크스페이스 관리자 | 행 없음. 행이 없으면 **시스템**에 나열된 사용 종료가 아닌 유일한 시스템이 모든 엔터티를 받습니다. |
| 사용 종료 | 시스템의 행 | 워크스페이스 관리자 | 사용 종료 아님 |
| 시뮬레이션 또는 실거래 | 시스템별, 프로젝트별 [라이브 전환](#라이브-전환) | 프로젝트의 아키텍트 | 시뮬레이션 |
| **매번 필요한 값** | 시스템의 [설정](#시스템-설정) | 워크스페이스 관리자 | 없음 |
| **코드 매칭**(엔터티 매칭 포함) | 시스템의 [설정](#시스템-설정) | 워크스페이스 관리자 | 없음 |
| **고객 자체 함수**(SAP 온프레미스) | 시스템의 [설정](#시스템-설정) | 워크스페이스 관리자 | 없음, 또는 변환된 단계가 가져온 함수 |
| 보류 규칙 | 시스템별 [보류 규칙](#보류-규칙) | 등록부 관리자(`erp.register.admin`) | 보류된 항목 없음 |
| **담당자 확인까지 보류** | 단계의 **더 보기 ▸** 메뉴 | 단계의 빌더 | 보류된 항목 없음 |
| **알림 대상** | 단계의 **더 보기 ▸** 메뉴 | 단계의 빌더 | **실행을 시작한 사람** |
| **반올림 계정 및 한도** | 단계의 **더 보기 ▸** 메뉴 | 단계의 빌더 | 반올림 없음 |
| **전기된 문서가 변경되어 돌아올 때** | 단계의 **더 보기 ▸** 메뉴 | 단계의 빌더 | **묻기(초기값). 두 가지 선택지와 함께 확인 필요 항목으로 이동합니다.** |

네 가지 단계 설정은 [ERP 시스템에 문서 전기](/ko/guides/connections/post-documents/)의 단계 설명에서 다루며, 단계 자체의 보류는 [아래](#단계-자체의-보류)에서 설명합니다.

## 시스템 설정

열린 행에서 **설정…** 항목을 선택합니다. 대화 상자 **설정: *시스템***은 워크스페이스 관리자만 편집할 수 있으며, 다른 사용자에게는 **Only a workspace administrator can change these.** 가 표시됩니다. **저장**은 시스템의 전체 설정을 대체하며, 모든 변경은 [변경 내역](#변경-내역)에 기록됩니다.

**매번 필요한 값**은 이 시스템으로 보내는 모든 문서에 추가되는 값이며 **값**과 **설정값** 쌍으로 지정합니다. 시스템은 필요한 값을 이름으로 읽으며, 같은 의미를 가진 문서 자체의 열이 있으면 시스템의 값보다 우선합니다.

| 시스템 | 값 | 용도 |
|---|---|---|
| Sage Intacct | `gl_journal_id` | 문서에 `journal_type`이 없을 때 분개 항목이 전기되는 분개장. |
| Sage 100 | `bank_code` | 문서에 `bank_code`가 없을 때 결제가 인출되는 은행 계정. |

**코드 매칭**은 여기의 코드가 시스템에서는 어떤 다른 코드인지를 지정하며 **차원**, **자체 코드**, **시스템의 코드**로 구성됩니다. 시스템의 회사 코드가 다른 엔터티에는 차원 `entity`를, 계정에는 `account`를 사용하십시오. [검사](#목록-대조-검사)는 매칭을 통해, 매칭이 없으면 작성된 그대로 시스템의 목록에서 코드를 찾으며, 엔터티 매칭이 있으면 그리드가 해당 엔터티에 이 시스템을 [제안](#추천-행)할 수도 있습니다.

**고객 자체 함수**는 SAP 온프레미스에만 표시됩니다. 각 **문서 유형**에 대한 함수 이름을 지정합니다. 설정은 함수 이름만 지정합니다. 각 함수의 필드 매칭, 즉 어떤 SAP 필드가 어떤 열을 받는지는 시스템에 그대로 유지되며, 변환된 SAP 전기 단계가 가져온 함수는 그 단계가 가지고 있던 필드 매칭을 유지합니다. [SAP 온프레미스](#sap-온프레미스)를 참조하십시오.

## 어떤 법인이 어디에 전기하는가

두 번째 카드는 어느 엔터티가 어느 시스템에 어느 날짜부터 전기하는지를 나타내는 그리드이며, 환경별로 한 번 설정하고 해당 환경의 모든 프로젝트가 공유합니다. 각 행은 엔터티, **→**, 시스템 및 선택 사항인 **시작일 (YYYY-MM-DD)** 로 구성됩니다.

1. **행 추가**를 선택하고 엔터티를 입력한 다음 **시스템 선택**에서 시스템을 선택합니다. 사용 종료가 아닌 시스템만 표시됩니다.
2. "처음부터"를 의미하려면 **시작일 (YYYY-MM-DD)** 을 비워 두고, 엔터티가 해당 시스템에 전기를 시작하는 날짜를 지정할 수도 있습니다. 연도 중간에 엔터티를 다른 시스템으로 옮기려면 첫 번째 행은 그대로 두고 옮기는 날짜(예: `2026-07-01`)부터 새 시스템에 대한 두 번째 행을 추가합니다.
3. **저장**을 선택합니다. 해당 형식이 아닌 날짜는 **날짜는 2026-07-01과 같은 형식입니다.** 라는 메시지와 함께 거부됩니다.

그리드 편집에는 워크스페이스 관리자가 필요하며, 다른 사용자에게는 읽기 전용으로 표시됩니다. 이미 저장된 엔터티의 이름은 바꿀 수 없습니다. 행 끝의 ×로 행을 제거한 다음 다른 행을 추가하십시오. 문서가 이름을 지정했지만 아직 어떤 행도 지정하지 않은 엔터티는 시스템이 선택되지 않은 상태로 나열되며, 그런 엔터티가 전혀 없으면 카드에 **아직 법인이 없습니다. 전기하는 테이블에서 발견된 법인이 여기에 표시됩니다. 행을 추가하여 법인을 지정하십시오.** 이라고 표시됩니다.

### 문서가 시스템을 찾는 방법

문서는 프로젝트 환경의 시스템을 통해 전기됩니다.

- 문서의 시스템은 **시작** 날짜가 문서의 전기 날짜(없으면 오늘) 이전이거나 같은 엔터티의 가장 최근 행입니다.
- 환경의 그리드에 행이 전혀 없고 **시스템**에 나열된 사용 종료가 아닌 시스템이 하나뿐이면, 그 시스템이 모든 문서를 받습니다.
- 해당 날짜에 엔터티를 포함하는 행이 없는 문서는 전기되지 않으며, 해당 엔터티에 대한 시스템이 없다고 표시됩니다.
- 행이 사용 종료된 시스템을 지정한 문서는 전기되지 않으며, 시스템이 사용 종료되었다고 표시됩니다.

### 추천 행

아직 어떤 행도 지정하지 않은 엔터티에 대해, 환경에서 사용 종료가 아닌 시스템 중 정확히 하나가 `entity` [코드 매칭](#시스템-설정)을 통해 또는 자체 회사 목록 사본에서 해당 엔터티를 지정하면 그리드가 시스템을 제안합니다. 행에는 **추천**이 표시되며 **수락**을 선택할 때까지 읽기 전용으로 유지되고, 수락한 행만 저장됩니다.

**작업**의 **어느 법인이 어디에 전기할지 제안…** 항목은 Data Foundation을 기반으로 한 Weave의 제안입니다. 프로젝트를 선택하면 프로젝트의 Data Foundation이 로드한 각 엔터티를 로드한 연결과 함께 채워 줍니다. 모델이 계산하는 것은 없고 저장되는 것도 없습니다. 행이 채워지고 몇 개인지 메시지로 알려 주며, 각 행을 읽은 후 **저장**을 선택합니다. 로드된 것이 없으면 **아직 제안이 없습니다.** 라고 표시됩니다.

### 여기서 변경할 수 없는 행

- 시스템이 사용 종료된 행은 **사용 종료**와 함께 읽기 전용으로 표시됩니다. 그리드를 저장해도 유지됩니다.
- 볼 수 없는 시스템의 행은 **이 목록에 없음**과 함께 읽기 전용으로 표시됩니다. 그리드를 저장하면 제거되므로 **저장**을 선택하면 먼저 **라우팅 저장**에서 확인을 요청합니다.

## 라이브 전환

누군가 의도적으로 라이브로 전환하기 전까지는 아무것도 실제로 전기되지 않습니다. 라이브 전환은 시스템별, 프로젝트별입니다. 한 프로젝트에서 일부 시스템은 실거래이고 다른 시스템은 아직 시뮬레이션일 수 있습니다. 새로 만들었거나 복사했거나 체험 중인 프로젝트는 누군가 그 프로젝트에서 라이브로 전환하기 전까지 모든 시스템이 시뮬레이션으로 시작합니다.

1. 헤더의 프로젝트 선택기에서 프로젝트를 선택합니다.
2. 시스템 행의 **라이브 전환 ›** 을 선택하거나, 전기할 수 있고 아직 실거래가 아닌 모든 시스템에 대해 **작업**의 **이 프로젝트에서 라이브 전환…** 항목을 선택합니다. 프로젝트를 선택하지 않으면 **라이브로 전환할 프로젝트를 선택하십시오.** 라는 메시지가 표시됩니다.
3. **라이브 전환** 대화 상자는 먼저 아무것도 변경하지 않고 무엇이 바뀔지 확인하여 보여 줍니다.
   - **라이브로 전환되는 시스템**: 실제로 전기하게 될 시스템.
   - **프로젝트의 전기 모드가 라이브로 변경되므로 모든 라이브 시스템이 실제로 전기합니다.** — 프로젝트 자체가 아직 실거래 모드가 아닐 때 표시됩니다.
   - **이미 실거래**: 이미 실거래인 시스템.
   - ***시스템*을(를) 라이브로 전환할 수 없음:** 그 이유와 함께 표시됩니다. 시스템이 사용 종료되었거나, 프로젝트가 잠겨 있거나, 해당 연결에 대한 쓰기 권한이 없거나, 전기할 수 있는 시스템이 아닌 경우입니다.
4. **라이브 전환**을 선택합니다. 하나 이상의 시스템이 실거래가 되는 경우에만 활성화됩니다.

라이브로 전환하면 해당 환경에서 그 시스템들에 대한 프로젝트의 승인이 기록되고, 아직 실거래 모드가 아니었다면 프로젝트의 전기 모드가 실거래로 설정됩니다. 라이브로 전환된 각 시스템은 [변경 내역](#변경-내역)에 기록됩니다. 라이브 전환은 다른 환경이나 프로젝트로 복사되지 않습니다.

라이브 전환에는 잠기지 않은 프로젝트의 아키텍트가 필요하며, 각 연결에 대한 본인의 쓰기 권한이 있어야 합니다. REST API(`POST /erp/go-live`)와 MCP 도구 `erp_go_live`에도 같은 검사가 적용되며, MCP 도구는 위임된 AI 토큰도 거부합니다. 라이브 전환은 사람이 하는 것이며 사람을 대신하는 에이전트가 하는 것이 아닙니다. 둘 다 `dry_run`을 false로 설정하지 않는 한 변경될 내용만 보고합니다.

## 시스템 사용 종료

열린 행에서 **사용 종료로 표시**를 선택하고 **폐기**로 확인합니다. 시스템이 다시 복원될 때까지 전기 대상으로 제공되지 않습니다. 그리드의 해당 행은 유지되며, 해당 시스템으로 라우팅된 문서는 전기되지 않습니다. **사용 종료에서 복원**은 이를 되돌립니다. 둘 다 워크스페이스 관리자가 필요하며 [변경 내역](#변경-내역)에 기록됩니다.

## IT용

**IT용**은 **IT용: *시스템***을 열어, 제품이 이 시스템에서 수행하는 작업을 허용하고 감사할 수 있도록 보여 줍니다.

- **로그인 계정** — 연결이 로그인하는 계정.
- **배치 크기** — 시스템의 설정에 지정된 배치 크기 또는 **설정되지 않음**.
- **에이전트** 및 **에이전트 버전** — 온프레미스 시스템의 경우.
- **당사 명칭** — 제품이 이름으로 호출하는 각 함수 또는 서비스와 마지막으로 사용된 시점. SAP 온프레미스의 경우 [설정](#시스템-설정)에서 지정한 함수입니다. 아무것도 전기하거나 테스트하지 않은 상태에서는 **아직 없습니다. 이 시스템에 전기하거나 테스트하면 표시됩니다.** 라고 표시됩니다.

로그인이 만료되면 대화 상자가 이를 알리고 **다시 연결**을 제공합니다.

## 다른 환경으로 복사

샌드박스를 한 번 설정한 다음 다시 입력하지 않고 프로덕션으로 복사하십시오. **작업**에서 **다른 환경으로 복사…** 항목을 선택합니다(워크스페이스 관리자만 가능).

1. **복사 대상**에서 환경을 선택합니다.
2. 이 환경의 모든 시스템이 나열되며, 같은 연결이 다른 환경에도 시스템으로 있으면 선택되어 있습니다. 그렇지 않은 시스템은 ***system* (not in this environment)** 으로 표시되며 선택할 수 없습니다.
3. **복사**를 선택하고 확인합니다.

선택된 각 시스템에 대해 복사는 다른 환경에 있는 해당 시스템의 설정, 코드 매칭 및 SAP 함수를 이 환경의 것으로 대체하고, 그 시스템을 지정하면서 다른 환경에 없는 그리드 행(같은 날짜의 같은 엔터티)을 추가합니다. 이미 있는 행은 그대로 둡니다. 결과에는 복사된 그리드 행 수와 시스템 설정 수가 표시됩니다. 라이브 전환은 복사되지 않습니다. 누군가 그곳에서 라이브로 전환하기 전까지 다른 환경의 모든 프로젝트는 시뮬레이션 상태로 유지됩니다.

## 시스템 목록의 사본

검사는 문서를 시스템 자체의 **계정**, **회사** 및 **기간**과 비교합니다. PlaidCloud는 시스템에서 직접 읽어 온 각 목록의 사본을 보관합니다.

- **실거래 시스템에서 모든 실거래 실행을 시작할 때** 시스템에서 읽으며, 전체 읽기에 최대 60초가 주어집니다. 문서를 중단시킬 수 있는 것은 해당 실행의 읽기뿐입니다.
- 열린 행의 **지금 새로 고침**을 선택할 때. 새로 고침은 전기할 때와 마찬가지로 ERP 시스템에 접속하므로 워크스페이스 관리자와 해당 연결에 대한 본인의 쓰기 권한이 필요합니다. 읽은 계정, 회사, 기간의 수와 읽는 데 걸린 시간을 보고합니다. 새로 고친 사본은 보기용이며 검사에 사용되지 않습니다.

각 목록은 행에 경과 시간을 표시합니다. 예를 들어 "Accounts read 3 hours ago", "Periods partial, read 2 days ago", "Companies not read yet"와 같이 표시되거나, 읽을 수 없었다는 사실과 그 이유가 표시됩니다. 중간에 끊겼거나 비어서 돌아온 사본은 이전 사본을 대체하지 않습니다.

**사본 보기**는 한 번에 하나의 목록(**계정**, **회사** 또는 **기간**)씩 **목록 사본**을 열고, **코드**, **이름**, **차단됨**, **시스템 내 상태**, **시작** 및 **종료**를 보여 줍니다. 처음 5,000행까지 표시합니다. 세금 코드, 고객, 공급업체는 복사되지 않으며 시스템에 맡깁니다.

시뮬레이션 실행은 시스템에서 아무것도 읽지 않으므로 시뮬레이션에서는 이러한 검사가 실행되지 않으며, 라이브로 전환할 때 시스템이 결정합니다.

## 목록 대조 검사

시스템의 실거래 실행을 시작할 때 각 문서는 해당 실행이 읽은 목록과 대조하여 검사됩니다. 목록을 읽을 수 없었거나, 일부만 돌아왔거나, 비어 있거나, 제시간에 끝나지 않은 검사는 확인하지 않은 것으로 처리됩니다. 통과로 처리되지도 중단 사유가 되지도 않으며 시스템이 결정합니다. 실행 페이지에는 각 문서에서 어떤 검사가 실행되었는지 표시됩니다.

- **Period open** (미마감 기간). 문서의 기간은 기간 코드로 찾거나, 없으면 전기 날짜가 속하는 기간으로 찾습니다. 해당 기간 전체가 시스템에서 전기 마감된 경우에만 중단됩니다. 해당 월과 겹치는 조정 기간이 있으면 날짜는 열린 상태로 유지됩니다. 시스템이 PlaidCloud가 모르는 표현으로 상태를 보고하는 기간은 검사하지 않습니다.
- **엔터티가 회사입니다.** 회사 목록을 읽었으면 `entity` 코드 매칭이 있으면 그 매칭을 통해, 없으면 작성된 그대로 확인한 문서의 엔터티가 시스템의 회사 중 하나여야 합니다.
- **계정이 존재합니다.** 계정 목록을 읽었으면 `account` 코드 매칭이 있으면 그 매칭을 통해, 없으면 작성된 그대로 확인한 모든 행의 계정이 시스템에 있어야 하고 전기가 차단되지 않아야 합니다. 숫자 코드는 앞의 0과 관계없이 일치하므로 `6100`은 `0000006100`을 찾습니다.

중단된 문서는 "Line 3: account 6100 is not in *시스템*"과 같은 사유와 함께 전기되지 않음 상태가 됩니다. 각 ERP 시스템이 제공하는 목록은 아래 표에 있습니다.

## 보류 규칙

규칙이 지정하지 않는 한 아무것도 보류되지 않습니다. 규칙이 보류한 문서는 사람이 승인할 때까지 승인 필요 상태로 대기하며, [승인](/ko/guides/connections/posting-register/)에서 승인합니다. 검사를 통과한 나머지는 모두 승인 없이 전송됩니다. 레일의 **설정** 아래에서 **보류 규칙**을 선택합니다.

목록에는 **이름**, **적용 대상**, **보류 조건**, **승인자** 및 **수행자**가 있습니다. 규칙이 없으면 **보류된 항목 없음**이라고 표시됩니다. `erp.register.view`가 있는 사용자는 누구나 규칙을 읽을 수 있으며, 추가, 편집 및 삭제에는 등록부 관리자(`erp.register.admin`)가 필요하고 도구 모음에 **새 규칙**, **편집**, **삭제**가 표시됩니다. 규칙을 삭제하면 새로운 항목을 더 이상 보류하지 않으며, 이미 대기 중인 문서는 누군가 결정할 때까지 계속 대기합니다. 모든 변경은 [변경 내역](#변경-내역)에 기록됩니다.

### 규칙의 조건

**새 규칙**은 **새 보류 규칙**을 엽니다.

1. 규칙의 **이름**을 지정합니다. 예: "250,000 초과 분개".
2. **적용 대상**에서 시스템을 선택합니다. 볼 수 있는 모든 환경의 시스템이 제공됩니다.
3. **보류 조건**에서 문서를 보류할 조건을 선택합니다. 선택한 조건이 모두 충족되어야 하며, 아무것도 선택하지 않으면 아무것도 보류되지 않습니다.
   - **금액이 다음을 초과함** 기준 금액, **법인 자체 통화** 기준: 문서의 크기는 차변과 양수 현지 금액의 합이며, 테이블에 현지 금액이 없으면 거래 금액입니다.
   - **파일에서 전기된 경우**.
   - **다음 유형입니다** — **역분개**, **대변**, **수정** 중 원하는 것을 선택합니다.
   - **비정상으로 표시된 경우** — [비정상으로 표시되는 경우](#비정상으로-표시되는-경우)를 참조하십시오.
   - **항상, 예: 결산 중** — 시스템의 모든 문서를 보류하며 다른 조건을 끕니다.
4. **승인자**에서 승인할 사람을 선택합니다. **등록부의 승인자** 또는 **지정된 사람**을 선택할 수 있으며, 지정된 사람은 사람을 선택하고 선택적으로 승인 대상 엔터티를 쉼표로 구분하여 입력합니다(비워 두면 모든 엔터티).
5. **저장**을 선택합니다. 규칙에 이름, 시스템, 하나 이상의 조건, 숫자인 금액이 있고 지정된 사람인 경우 한 명 이상이 있으면 활성화됩니다.

보류된 문서는 같은 세트의 다른 모든 문서도 보류하므로 세트는 하나로 승인되고 하나로 전기됩니다.

### 승인할 수 있는 사람

승인자에게는 `erp.register.approve`와 문서의 연결에 대한 본인의 권한이 필요합니다. 규칙이 사람을 지정하면 해당 사람만 승인할 수 있으며, 엔터티를 나열한 경우에는 나열된 엔터티에 대해서만 승인할 수 있습니다. 본인이 보낸 문서는 아무도 승인할 수 없습니다. 실행을 시작한 사람도, **이 항목 게시**로 보낸 사람도 마찬가지입니다.

문서를 시뮬레이션으로 보냈을 때 받은 승인은 실거래 전송에는 인정되지 않습니다. 같은 문서를 나중에 실거래로 보내면 새로운 결정을 위해 다시 보류됩니다.

워크스페이스에서 전기에 대한 업무 분장을 요구하는 경우, 이에 해당하는 역분개, 대변 또는 수정은 규칙이 없어도 두 번째 사람을 위해 보류됩니다.

### 단계 자체의 보류

**문서 전기** 단계는 **더 보기 ▸** → **담당자 확인까지 보류** 메뉴에서 시스템보다 더 많이 보류할 수 있습니다. 조건은 **금액이 다음을 초과하는 경우**, **파일에서 전기된 경우**, **역분개, 대변 또는 정정 문서입니다**, **비정상으로 표시된 경우** 및 **항상**이며 같은 방식으로 조합되고, 아무것도 선택하지 않으면 추가로 보류되는 것이 없습니다. 단계의 보류는 시스템의 규칙에 더해질 뿐이며 시스템 규칙이 보류한 것을 풀 수는 없습니다. 단계의 문서는 등록부의 승인자가 승인합니다. 지정된 승인자는 시스템 규칙에서 설정합니다.

REST API(`PUT /erp/steps/{step_id}/holds`) 또는 MCP 도구 `erp_hold_upsert`로 단계의 보류를 변경하려면 `analyze.step.write`와, 잠기지 않은 프로젝트의 아키텍트 또는 관리자 역할이 필요합니다.

### 비정상으로 표시되는 경우

문서는 해당 엔터티가 이전에 전기한 내용과 비교하여 다음 경우에 비정상으로 표시됩니다.

- 금액이 같은 참조의 마지막 전기보다 10배 넘게 크거나 작은 경우.
- 엔터티가 최근 500개 문서에서 사용하지 않은 계정, 고객, 공급업체 또는 거래 파트너를 사용하는 경우.
- 전기 날짜가 해당 기간을 벗어나는 경우.

각 표시에는 "The posting date 2026-08-02 is outside the period 2026-07."과 같이 이유를 설명하는 문장이 기록됩니다. 표시는 엔터티의 이전 문서로 계산되며 AI 모델은 호출되지 않습니다. 이전 문서가 없는 엔터티는 표시되지 않습니다.

### SAP 온프레미스

SAP 온프레미스는 문서 유형별로 고객 자체 함수를 호출하는 방식으로 에이전트를 통해 전기하며, 이 함수는 [**고객 자체 함수**](#시스템-설정)에서 설정합니다. 유형에 함수가 없거나 함수의 필드 매칭에 문서의 참조에 해당하는 필드가 없는 문서는 전기되지 않습니다. 기존 SAP 전기 단계를 변환하면 시스템에 해당 문서 유형의 함수가 아직 없는 경우 그 단계의 함수와 필드 매칭을 시스템으로 가져옵니다. [ERP 시스템에 문서 전기](/ko/guides/connections/post-documents/)를 참조하십시오.

- **시뮬레이션**은 같은 요청을 만들고 에이전트 앞에서 멈춥니다. SAP에는 아무것도 전달되지 않습니다.
- **실거래**는 시스템 환경을 담당하는 에이전트에 문서를 넘깁니다. 에이전트는 SAP의 응답을 프로젝트의 기본 문서 계정(`/erp_posting/sap` 아래)에 있는 보고서에 기록하며, 해당 보고서를 읽을 때까지 각 문서는 대기 중 상태로 유지됩니다. 기본 문서 계정이 없는 프로젝트는 SAP에 실거래로 전기할 수 없으며, 해당 사유와 함께 문서가 전기되지 않습니다.
- **에이전트가 오프라인이면** 아무것도 전송되지 않습니다. 문서는 에이전트가 오프라인이었다는 사유와 함께 전기되지 않으며, 에이전트가 다시 연결되면 재시도할 수 있습니다. 에이전트가 약 18초 이내에 문서를 가져가지 않으면 문서는 전송되지 않은 채 회수되어 같은 방식으로 전기되지 않습니다.
- SAP 보고서가 결정하지 못한 문서는 미확인 상태가 됩니다. 전기 등록부에서 확정하십시오.

### Sage 100

Sage 100은 온프레미스이며 네트워크 API가 없습니다. 문서는 Sage의 Business Object Interface를 실행하는 에이전트를 통해 전달됩니다.

- **연결당 하나의 회사.** 연결이 Sage 회사와 해당 통화를 지정합니다. 다른 회사의 문서이거나 다른 통화의 행이 있는 문서는 전송되지 않습니다.
- **분개**는 GL 분개 항목으로 전기됩니다. 분개의 참조는 Sage에서 설명이 되므로 최대 30자일 수 있습니다.
- **결제**는 Sage 밖에서 이루어진 결제에 대한 AP 수동 수표로 전기됩니다. 결제당 공급업체 하나, 참조가 수표 번호(최대 7자), `bank_code`(문서 또는 시스템의 [매번 필요한 값](#시스템-설정)에서), 그리고 각 행이 결제하는 송장을 양수 금액으로 지정합니다.
- **실거래 실행에서** 에이전트가 먼저 Sage에 문의합니다. Sage가 마감한 기간의 날짜를 가진 분개는 중단되며, Sage에 미결로 없는 송장에 대한 결제도 중단됩니다.
- **전송 후에는** Sage의 전기된 테이블에 나타날 때에만 문서가 전기됨 상태가 됩니다. Sage 배치에 입력되었지만 아직 업데이트되지 않은 문서는 대기 중 상태로 유지됩니다. 백그라운드 점검이 에이전트에 다시 문의하며 최대 한 시간에 한 번 수행하고, 7일이 지나도 여전히 대기 중인 문서는 미확인 상태가 됩니다.

## 변경 내역

시스템에 대한 모든 변경은 변경한 사람과 시점과 함께 기록됩니다. **시스템 설정**, **사용 종료**, **SAP 함수**, **코드 매칭**, **어떤 법인이 어디에 전기하는가**, **보류 규칙**, **라이브 전환**, **목록 복사**(시스템 목록을 읽을 때마다)가 해당됩니다. 레일의 **설정** 아래 또는 **작업** 메뉴에서 **변경 내역**을 선택하거나, 해당 시스템만 보려면 시스템 행의 **기록**을 선택합니다. 목록에는 **시점**, **수행자**, **항목**, **시스템**, **대상**, **시작** 및 **종료**가 있습니다.

권한이 있는 시스템에 대한 변경 내역이 표시되며, 라이브 전환은 접근할 수 있는 프로젝트의 것만, 단계의 보류는 접근할 수 있는 프로젝트의 것만 표시됩니다.

## 권한별 수행 가능 작업

아래의 모든 규칙은 해당 행에 달리 명시되어 있지 않은 한 앱, REST API 및 MCP 도구에서 동일하게 서버가 검사합니다.

| 작업 | 필요한 권한 |
|---|---|
| 시스템, 시스템 설정, 그리드 및 목록 사본 보기 | `analyze.connection.read`, 그리고 볼 수 있는 연결만 해당 |
| 설정 변경, 시스템 사용 종료, 그리드 저장, 다른 환경으로 복사 | 워크스페이스 관리자 |
| 시스템 목록 새로 고침 | 시스템 페이지에서는 워크스페이스 관리자, REST API와 MCP 도구 `erp_system_lists`에서는 `analyze.connection.read`. 어느 쪽이든 해당 연결에 대한 본인의 쓰기 권한 필요 |
| 라이브 전환 | 잠기지 않은 프로젝트의 아키텍트이며 각 연결에 대한 본인의 쓰기 권한이 있어야 함. 사람이어야 하며 위임된 AI 토큰은 불가 |
| 보류 규칙 읽기 | `erp.register.view` |
| 시스템의 보류 규칙 추가, 변경 또는 삭제 | 등록부 관리자(`erp.register.admin`) |
| 단계 자체의 보류 변경 | `analyze.step.write`, 그리고 잠기지 않은 프로젝트의 아키텍트 또는 관리자 역할 |
| 보류된 문서 승인 | `erp.register.approve`와 문서의 연결에 대한 본인의 권한. 규칙이 사람을 지정한 경우 해당 규칙에 이름이 있어야 하며, 본인이 보낸 문서는 불가 |
