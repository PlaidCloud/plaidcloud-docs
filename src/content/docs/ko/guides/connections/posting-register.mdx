**전기 등록부**는 볼 수 있는 모든 프로젝트와 시스템에 걸쳐 ERP 시스템에 전기된 모든 문서를 나열합니다. 사람이 조치해야 하는 문서인 **조치 필요**에서 열리며, 여기에서 전기를 열어 현재 상태인 이유를 확인하고 조치할 수 있습니다.

문서는 **문서 전기** 단계, 각 ERP 자체의 전기 단계(예: **Intacct: 분개 전표 전기**), 전기 파일, 아래에 설명된 되돌리기, 대변, 정정 작업을 통해 등록부에 도착합니다. 실행을 시작하고, 검사하고, 전송하는 방법은 [ERP 시스템에 문서 전기](/ko/guides/connections/post-documents/)에서, 시스템을 설정하는 방법은 [ERP 시스템](/ko/guides/connections/erp-systems/)에서 다룹니다.

## 등록부 열기

**전기 등록부** 앱을 엽니다. [누가 무엇을 볼 수 있는가](#누가-무엇을-볼-수-있는가)에 설명된 `erp.register.*` 권한 중 하나를 가진 모든 멤버에게 표시됩니다. 항상 **조치 필요**에서 열립니다.

왼쪽의 레일에는 세 개의 그룹이 있습니다.

| 그룹 | 페이지 |
|---|---|
| **전기** | **조치 필요**, **전기**, **실행 횟수** |
| **내 확인 필요** | **승인**, **위임**, **내 감시 목록** |
| **설정** | **시스템**, **보류 규칙**, **변경 내역**, **내보내기 및 알림**, **보존** |

**조치 필요**와 **승인**은 레일에 개수가 표시됩니다. **보존**은 `erp.register.admin`이 없으면 숨겨집니다. **실행 횟수**는 전기 실행 목록을 열며, **시스템**과 **보류 규칙**은 [ERP 시스템에 문서 전기](/ko/guides/connections/post-documents/)와 [ERP 시스템](/ko/guides/connections/erp-systems/)에서 설명합니다.

PlaidCloud의 다른 곳에서도 등록부에 접근할 수 있습니다.

- **홈**에는 확인이 필요한 항목이 있는 동안 **전기 등록부** 카드가 표시되며 **조치 필요**와 **승인 대기 중** 개수가 함께 표시됩니다. 카드를 선택하면 **조치 필요**가 열립니다.
- 명령 팔레트에는 **조치 필요**와 **승인**이 개수와 함께 나열됩니다. 원장 ID를 입력하고 **Find posting**과 ID를 차례로 선택하면 해당 전기가 열립니다.

### 실시간 업데이트

등록부는 스스로 최신 상태를 유지합니다. 시스템에서 전기가 변경되면 레일의 개수를 다시 읽고, 열려 있는 목록에는 행을 움직이는 대신 **새로 고침** 버튼과 함께 **불러온 이후 전기 내용이 변경되었습니다**가 표시되며, 열려 있는 전기는 그 자리에서 다시 로드됩니다.

## 누가 무엇을 볼 수 있는가

### 권한

네 가지 권한으로 등록부를 열고 조치합니다. 하나를 가지고 있다고 다른 권한이 부여되는 것은 아니지만, `erp.register.operate`, `erp.register.approve` 또는 `erp.register.admin`이 필요한 모든 작업에는 `erp.register.view`도 필요합니다. 화면에 무엇이 표시되든 모든 작업은 필요한 권한을 서버에서 검사합니다.

| 권한 | 허용되는 작업 |
|---|---|
| `erp.register.view` | 등록부 열기, **조치 필요**, **전기** 및 전기 세부 정보 읽기, **전기**에서 질문하기, 댓글과 승인 읽기. |
| `erp.register.operate` | **되돌리기…**, **대변 전표…**, **정정…** 및 **전기 파일로 다운로드…**, **저장된 보고서에서 확정**, **게시 여부 보고**(`erp.register.approve`도 함께 필요), 댓글 작성, 승인 및 감시, **승인** 열기, 본인 요청 철회, 승인 권한이 있으면 다른 사람의 요청 결정, 위임 보기 또는 취소, 다운로드, 일정 및 증빙 내보내기. |
| `erp.register.approve` | 되돌리기 승인, **보류된 문서** 읽기 및 결정, 본인의 승인 위임, **미확인** 전기가 처리되었는지 보고. |
| `erp.register.admin` | 감사자 프로필의 내보내기 및 증빙 내보내기, 다른 멤버의 일정 관리, **보존** 설정, [보류 규칙](/ko/guides/connections/erp-systems/) 변경. |

네 개의 기본 제공 보안 그룹이 이들을 묶어 제공합니다. **Posting Register Viewer**(view), **Posting Register Operator**(operate 추가), **Posting Register Approver**(approve 추가), **Posting Register Admin**(네 가지 모두)입니다.

일부 작업은 등록부 권한이 아니라 프로젝트 권한도 필요합니다. **다시 시도**와 **시스템에서 확인**에는 `analyze.workflow.write`가 필요하며, **다시 시도**에는 전기가 속한 프로젝트의 아키텍트 또는 관리자 역할도 필요합니다. **변경 내역**에는 `analyze.connection.read`가 필요합니다.

REST API 또는 MCP 도구로 등록부를 사용할 때도 같은 권한과 가시성 규칙이 적용됩니다. 각 경로와 도구는 화면과 같은 검사를 실행합니다.

### 볼 수 있는 전기

등록부 권한이 있으면 등록부는 열리지만 그것만으로는 전기가 하나도 표시되지 않습니다. 다음 조건이 모두 충족될 때만 전기가 보입니다.

- **시스템 연결에 대한 개인 권한이 있습니다.** 연결을 소유하거나, 연결에 이름이 지정되어 있거나, 연결에 이름이 지정된 보안 그룹에 속해야 합니다. 연결의 [보안 모델](/ko/guides/connections/create-connection/#보안-모델)을 참조하십시오. **모든 작업 영역 멤버**와 공유된 연결이나 서비스 계정의 권한은 해당되지 않습니다.
- **프로젝트에 속한 경우 해당 프로젝트를 열 수 있습니다.**
- **프로젝트가 해당 엔터티를 볼 수 있도록 허용합니다.** 프로젝트가 `entity`에 대한 행 액세스로 멤버를 특정 엔터티로 제한하면 해당 엔터티의 전기만 볼 수 있습니다. 프로젝트 아키텍트는 제한되지 않습니다.

액세스는 모든 요청에서 다시 읽으므로 취소된 권한은 다음 페이지를 로드할 때 적용됩니다. 연결 권한이 없는 멤버에게는 빈 목록 대신 **표시할 시스템이 없습니다**가 표시됩니다.

## 일곱 가지 상태

모든 문서는 무엇이 전기했든 일곱 가지 상태 중 하나로 표시됩니다. 모든 필, 칩, 필터에 같은 표현이 사용됩니다.

| 상태 | 의미 |
|---|---|
| **전기 예정** | 검사되었습니다. 시스템 또는 실행이 시뮬레이션이므로 아무것도 전송되지 않았습니다. |
| **승인 필요** | 규칙에 의해 사람이 승인할 때까지 보류되었습니다. |
| **대기 중** | 승인되었고 전송될 예정이거나 전송되었습니다. 시스템이 아직 응답하지 않았습니다. |
| **전기됨** | ERP가 이 전기를 수락했습니다. |
| **전기되지 않음** | 검사에서 중단되었거나 시스템이 거부했습니다. 사유에 어느 쪽인지 표시됩니다. |
| **미확인** | 응답이 오지 않았으며 시스템에 문의할 수 없습니다. 전기되었는지 보고하십시오. |
| **되돌려짐** | 이후 전기가 이 전기를 취소했습니다. |

## 확인할 범위 선택

**조치 필요**와 **전기**는 하나의 범위를 공유하므로 한 곳에서 설정한 필터가 다른 곳에도 적용됩니다. 페이지 헤더 아래의 표시줄에 범위가 표시됩니다. 좁혀 놓은 항목은 제거할 수 있는 칩으로 표시되고, 기본값 그대로인 항목은 **모든 시스템**처럼 말로 표시됩니다.

**범위 변경**을 선택하여 편집합니다.

- **전기됨** — **이번 달**, **이전 달**, **지난 7일**, **지난 30일** 또는 **사용자 지정**이며, 사용자 지정은 **시작**과 **종료** 날짜를 요청합니다. 기본값은 지난 30일입니다.
- **시스템**과 **프로젝트**. 볼 수 있는 항목 중에서 선택합니다.
- **엔터티**. **고급 ▾** 아래에 있습니다.

**재설정**은 범위를 기본값으로 되돌립니다. 표시줄 아래의 **상태** 칩 행은 목록을 하나의 상태로 좁힙니다.

브라우저 주소에 범위가 포함되므로 북마크하거나 동료에게 보낼 수 있습니다. 주소를 여는 사람에게는 본인의 액세스가 허용하는 항목만 표시됩니다.

## 조치 필요

**조치 필요**는 사람이 조치해야 하는 모든 문서를 승인, **미확인**, **전기되지 않음**, 확인이 필요한 전기된 문서 순서로 나열합니다. 행을 선택하면 열립니다. 페이지 이름 아래의 줄에는 조치가 필요한 항목 수와 그중 승인을 기다리는 수가 "12 need attention · 3 to approve"와 같이 표시됩니다.

각 행에는 **참조**, **엔터티**, **시스템**, **금액**, **통화**, **상태**, **이유**, **다음**, **모드**가 표시되며 **프로젝트**와 **유형**은 표시할 수 있는 숨겨진 열입니다. **이유**는 첫 번째 사유를 쉬운 말로 보여 주고 다른 사유가 있으면 "(and 2 more)"가 붙으며, **다음**은 그에 대해 할 일입니다.

**모드**에는 **실거래** 또는 **시뮬레이션**이 표시됩니다. 시뮬레이션된 문서도 사람의 확인이 필요합니다. 전기하기 전에 실패한 검사를 수정해야 하기 때문입니다. 그래서 링크가 하나의 모드를 지정하지 않는 한 이 페이지에는 둘 다 표시됩니다.

여기의 **상태** 칩은 **승인 필요**, **전기되지 않음**, **미확인**, **전기됨**입니다. 일치하는 항목이 없으면 페이지에 **이상 없음**이 표시되며 "Nothing needs a person. Every document is posted, waiting, or would post."라고 안내합니다. 범위가 좁혀져 있으면 **범위 초기화**를 제공합니다.

### 문서에 조치가 필요한 이유

**전기되지 않음** 문서에는 중단된 사유가 있습니다. 아무것도 전송되기 전에 검사에서 비롯된 사유는 소스나 시스템에서 수정한 다음 다시 실행합니다([ERP 시스템에 문서 전기](/ko/guides/connections/post-documents/) 참조). 대부분의 경우 **다음**에는 **수정 후 다시 실행**이 표시되고, 엔터티에 시스템이 없는 문서에는 **다시 시도**가 표시되어 시스템을 추가하면 문서를 다시 라우팅하며, `~`가 들어 있거나 너무 긴 참조의 경우 **다음**이 비어 있습니다.

| 표시되는 사유 | 조치 |
|---|---|
| No system is set to post for the entity | **시스템**에서 해당 엔터티의 시스템을 선택합니다. |
| Its system is retired | 다른 시스템에 전기합니다. |
| The period is closed in the system | 기간을 열거나 다음 기간에 전기합니다. |
| An account does not exist in the system | 시스템에서 만들거나 코드를 다른 계정에 매칭합니다. |
| A code has no match in the system | **시스템**에서 매칭합니다. |
| An invoice this payment pays is not open | 시스템에서 송장을 확인합니다. |
| It is for another company than its system posts to | 해당 회사의 시스템으로 라우팅합니다. |
| A line is in a currency its system does not book | 시스템의 통화로 전기하거나 다른 시스템에 전기합니다. |
| The system needs a value that is empty | 소스에서 값을 채웁니다. |
| Debits and credits do not match | 소스를 수정하고 다시 실행합니다. |
| Part of its set is missing, or the documents of its set do not agree | 세트는 모든 문서가 있고 서로 일치할 때만 전기됩니다. |
| The reference was already posted to another system, or is already used on this system | 수정한 다음 다시 실행합니다. |
| Its reference contains `~`, or is too long for the system | 소스에서 참조를 변경합니다. PlaidCloud는 `~`를 버전 번호에 사용합니다. |
| This system cannot take this kind of document yet | 수정한 다음 다시 실행합니다. |
| An earlier version of this reference has no answer from the system yet | 응답이 오면 다시 실행합니다. |

그 밖의 사유는 검사를 통과한 후 일어난 일을 설명하며, **다음**은 이들에 대해 [**다시 시도**](#다시-시도)를 제공합니다. 승인자가 거절했거나, 전송 전에 실행이 중지되었거나, 시스템의 에이전트가 오프라인이었거나, 시스템에 도달하기 전에 무언가 실패하여 전송되지 않았거나, 시스템이 거부했거나, PlaidCloud가 기한에 확인했을 때 시스템에 문서가 없었던 경우입니다.

나머지는 **전기되지 않음**이 아니면서 조치가 필요한 경우입니다.

| 사유 | 상태 | 다음 |
|---|---|---|
| 사람이 승인해야 하며 이를 보류하는 규칙의 이름이 표시됨 | **승인 필요** | **승인** — [승인](#승인)을 참조하십시오. |
| 시스템이 제때 응답하지 않았으며 문서가 전기되었는지 문의할 수 없음 | **미확인** | **게시 여부 보고** — [미확인 전기](#미확인-전기)를 참조하십시오. |
| 전기된 이후 소스가 변경됨 | **전기됨** | 실행 페이지에서 응답하는 **이 버전으로 수정** 또는 **게시된 항목 유지**. |
| 세트의 일부만 전기됨 | **전기됨** | **수정 후 다시 실행** |
| 전기되었으나 시스템 자체 기록에 없거나 기록이 다름 | **전기됨** | **시스템에서 확인** |
| 전기된 이후 시스템에서 변경됨 | **전기됨** | **시스템에서 확인** |
| PlaidCloud를 거치지 않고 시스템에 입력됨 | **전기됨** | **시스템에서 확인** |

PlaidCloud 없이 시스템에서 직접 입력한 항목은 프로젝트, 시스템, 엔터티, 월별로 한 행씩 묶여 "2026년 10월에 PlaidCloud에서 만들지 않은 항목 4건"처럼 표시됩니다. 이러한 행은 목록을 좁히는 필터가 없을 때만 나열되며 맨 위의 개수에는 포함되지 않습니다. **전기됨** 날짜도 필터로 간주되고 범위는 지난 30일로 시작하므로, **범위 변경**의 **전기됨**에서 **사용자 지정**을 선택하고 **시작**과 **종료**를 비워 두면 이러한 행이 표시됩니다.

## 전기

**전기**는 볼 수 있는 모든 문서를 문서당 한 행으로 나열합니다. **참조**, **유형**, **엔터티**, **시스템**, **프로젝트**, **금액**, **통화**, **상태**, **시스템 문서**, **전기일**, **시작한 사용자**, **승인됨**, **모드**입니다. **시스템 문서**는 시스템이 부여한 번호이며, 검사에서 시스템 자체 기록에서 찾으면 **장부 반영**이 뒤따릅니다. **승인됨**에는 **자동** 또는 **사용자 수동 처리**가 표시됩니다. 페이지 이름 아래의 줄은 전기 수를 세고 통화별로 합계를 보여 주며, 통화는 절대 합산되지 않습니다.

헤더에는 다음이 있습니다.

- 검색 상자는 입력하는 대로 참조, 시스템 문서 또는 금액을 찾습니다.
- **질문**은 같은 검색 상자에 입력한 자신의 말로 된 질문을 받습니다. 예: "What did we post in October?" 질문은 상태, 엔터티, 모드, 월을 이해하며 볼 수 있는 항목을 좁히기만 합니다. 그러면 목록에 처음 25개의 일치 항목과 이해한 내용을 설명하는 문장이 표시됩니다.
- **실거래**, **시뮬레이션**, **모두**는 표시할 전기를 선택합니다. **실거래**가 기본값입니다.

**상태** 칩은 일곱 가지 상태를 모두 포함합니다. 긴 목록은 알림과 함께 1,000행에서 멈추며, **더 로드**는 다음 1,000행을 읽습니다.

하나 이상의 행을 선택한 다음 도구 모음의 **작업** 메뉴에서 **되돌리기…**, **대변 전표…**, **정정…** 또는 **전기 파일로 다운로드…** 를 선택하면 선택한 모든 행에 한꺼번에 적용됩니다. 이 작업에는 `erp.register.operate`가 필요하며 [되돌리기, 대변 또는 정정](#되돌리기-대변-또는-정정)에 설명된 대로 동작합니다. PlaidCloud 없이 시스템에 입력된 행은 여기서 조치할 수 없습니다.

## 전기 드로어

행의 돋보기 아이콘 또는 **조치 필요**에서 행을 선택하여 전기를 엽니다. 전기는 목록 옆 오른쪽의 드로어에서 열립니다.

드로어 상단에는 상태 필이 표시되고, 각 사유가 쉬운 말과 그 아래 시스템 자체의 메시지로 표시되며, 이어서 전기의 정보가 표시됩니다. **참조**, **유형**, **금액**, **시스템 문서**, **시스템**, **환경**, **엔터티**, **전기일**, **프로젝트**, **워크플로**, **단계**, **시작한 사용자**, **승인됨**, **모드**입니다. 승인을 기다리는 되돌리기에는 "This reversal needs a second person to approve it. Whoever started it cannot."도 표시됩니다.

나머지는 다섯 개의 탭에 있습니다.

| 탭 | 표시 내용 |
|---|---|
| **라인** | 각 라인의 **계정**, **설명**, **차변**, **대변**, **차원**. |
| **기록** | 문서에 일어난 일, 시점, 수행한 사람. |
| **버전** | `INV-100`과 `INV-100~2`처럼 참조의 모든 버전과 각 상태, 현재 보고 있는 버전. |
| **링크** | 출처와 관련 항목: **소스 행**, **단계 버전**, **단계를 마지막으로 변경한 사용자**, **취소 대상**, **취소 문서**, **대변** 및 **첨부 파일**. |
| **승인** | 전기에 대한 검토 승인과 댓글 — [검토 승인 및 댓글](#검토-승인-및-댓글)을 참조하십시오. |

드로어의 **작업** 메뉴에는 이 전기를 볼 수 있는 모든 사람에게 열리는 링크를 복사하는 **링크 복사**와, 해당하는 경우 **시스템에서 열기**(직접 열 수 있는 QuickBooks Online 전기용), **연결 지켜보기**(전기에 연결이 있을 때), **실행 지켜보기**(실행이 있을 때)가 있습니다. `erp.register.operate`가 있는 멤버는 여기서 **대변 전표…**, **정정…**, **전기 파일로 다운로드…**, **시스템에서 확인**도 사용할 수 있으며, 메뉴 옆의 버튼으로 **게시 여부 보고**와 **되돌리기…** 도 사용할 수 있습니다. `erp.register.operate`가 없으면 푸터에 "Reversing needs the Posting Register Operator role."이라고 표시됩니다. **다시 시도**는 해당되는 모든 사용자에게 메뉴 옆에 나타납니다. [다시 시도](#다시-시도)를 참조하십시오.

각 작업은 전기의 상태가 허용하는 경우에만 제공되며, 회색으로 표시된 항목은 가리키면 이유를 알려 줍니다.

### 다시 시도

**다시 시도**는 **다음**이 제공하고, 문서에 원장 항목이 있고, `analyze.workflow.write`가 있을 때 나타납니다. 먼저 전송될 내용을 확인하며, 다시 시도할 수 있는 것이 없으면 이유를 알려 줍니다. 그렇지 않으면 시스템에 "Send the stored document again to"를 묻고, **다시 시도**를 선택하면 저장된 사본이 프로젝트의 전기 제한에 따라 새 실행으로 다시 전송됩니다.

시스템이 전기하지 않았음이 확실한 경우에만 문서를 다시 시도합니다. **전기되지 않음**이거나 전송된 적이 없는 경우입니다. 해당 프로젝트의 아키텍트 또는 관리자 역할과 해당 연결에 대한 본인의 권한도 필요합니다.

### 되돌리기, 대변 또는 정정

**전기됨** 문서만 되돌리거나 대변 처리하거나 정정할 수 있습니다.

- **되돌리기…** 는 시스템에서 전기를 취소합니다.
- **대변 전표…** 는 전기된 송장에 대한 대변 메모를 발행합니다. 고객 및 공급업체 송장에만 적용됩니다. 단일 전기를 대변 처리할 때 **금액**을 비워 두면 송장 전체가 대변 처리되며, 일부만 입력할 수도 있습니다.
- **정정…** 은 현재 버전을 되돌리고, PlaidCloud에 아직 전기되지 않은 더 새로운 버전의 문서가 있으면 이를 다음 버전(`REF~2`)으로 전송합니다. 전기된 이후 소스가 변경된 전기에도 제공됩니다.

각각 먼저 무엇을 할 수 있는지 확인하는 대화 상자를 엽니다. 몇 개의 전기가 어느 시스템에서 어떤 방식으로 처리되는지("the system's own reversal", "a credit memo" 또는 "an opposite posting"), 그리고 처리할 수 없는 전기와 각각의 이유를 보여 줍니다. 세트의 일부로 전기된 문서를 되돌리면 세트의 나머지도 함께 되돌려집니다. **사유**를 입력하고, 선택적으로 **날짜**(오늘로 시작)를 변경한 다음 확인합니다. 버튼에는 **되돌리기 3**처럼 전기 수가 표시됩니다.

작업은 이후 다른 전기와 똑같이 실행됩니다. 새 실행으로 기록되고, 검사되고, 규칙이 보류하면 승인되고, 전송되고, 확인되며, 실행 페이지가 열립니다. 하나의 작업에는 최대 200개의 전기를 담을 수 있습니다.

되돌리기, 대변, 정정은 실거래 쓰기이므로 프로젝트가 시뮬레이션으로 제한되어 있거나, 프로젝트가 해당 시스템에 전기할 권한이 없거나, 연결에 대한 개인 권한이 없는 경우 전기가 거부됩니다. 일부 시스템에는 인터페이스를 통해 전기를 취소할 방법이 없으며, 대화 상자가 그런 경우를 알려 줍니다.

### 직무 분리

작업 영역에서 업무 분장을 켜면 임계값 이상의 되돌리기에는 두 번째 사람의 승인이 필요합니다. 업무 분장과 임계값은 PlaidCloud가 작업 영역에 대해 설정하며 등록부에는 이를 위한 설정이 없습니다.

- 문서는 실행에서 **승인 필요**로 표시되며 승인 요청은 해당 전기의 연결에 대한 권한을 가진 모든 승인자에게 전달됩니다. 지정할 수신자는 없으며 연결 권한이 라우팅입니다.
- 승인자는 `erp.register.approve` 또는 이를 가진 사람의 활성 위임, 그리고 연결에 대한 본인의 권한이 있어야 합니다. 되돌리기를 요청한 사람은 위임을 통해서라도 승인할 수 없습니다.
- 승인은 정확히 그 되돌리기, 즉 전기, 사유, 날짜에만 적용됩니다. 승인되고 5분간의 보류가 지나면 같은 사유와 날짜로 같은 작업을 다시 실행하며 통과됩니다.
- 같은 연결에서 최근 24시간 동안 제출자가 한 되돌리기는 임계값에 합산되므로, 큰 되돌리기를 작게 나누어 임계값 아래로 맞출 수 없습니다.
- 연결에서 승인할 자격이 있는 멤버가 두 명 미만이면 승인이 필요한 되돌리기는 거부됩니다.

### 전기 파일로 다운로드

**전기 파일로 다운로드…** 는 **작업**(**되돌리기**, **대변 전표** 또는 **정정**)과 **형식**(**Excel** 또는 **CSV**)을 묻고, 해당 작업을 위해 채워진 전기 파일을 저장합니다. 금액이나 라인을 편집한 다음 REST API 또는 MCP 도구를 통해 파일에서 전기합니다. [ERP 시스템에 문서 전기](/ko/guides/connections/post-documents/)를 참조하십시오.

### 시스템에서 확인

**시스템에서 확인**은 지금 시스템에서 전기를 조회하며 시뮬레이션하지 않습니다. **시스템에서 찾았습니다.** 또는 **시스템에서 찾을 수 없습니다.**, 또는 시스템에 문의할 수 없었던 이유를 알려 주며 전기의 **장부 반영** 상태가 업데이트됩니다. `analyze.workflow.write`가 필요합니다.

### 검토 승인 및 댓글

**승인** 탭은 **검토됨으로 표시**, **정리됨으로 표시** 또는 **후속 조치 필요**와 선택적 **메모**로 전기에 대한 검토를 기록합니다. 현재 승인과 이전의 모든 승인을 보여 줍니다.

그 아래의 **댓글**은 전기에 대한 일반 텍스트 메모를 담습니다. 댓글을 입력하고 멘션할 멤버 ID를 나열한 다음 **댓글 게시**를 선택합니다. 멘션된 멤버는 알림이 전송되는 시점에 전기를 볼 수 있는 경우에만 알림을 받습니다.

댓글과 승인은 추가하려면 `erp.register.operate`가, 읽으려면 `erp.register.view`가 필요합니다. 아직 원장 항목이 없는 문서에는 "Comments and sign-off are not available for this document yet."라고 표시됩니다.

### 감시

드로어의 **작업** 메뉴에 있는 **연결 지켜보기**와 **실행 지켜보기**는 이후 해당 전기의 연결 또는 실행에서 일어나는 활동을 알려 줍니다. 켜면 **연결 지켜보는 중**과 **실행 지켜보는 중**으로 표시됩니다. 알림은 해당 전기를 볼 수 있는 동안에만 전달됩니다. 감시에는 `erp.register.operate`가 필요합니다.

## 미확인 전기

시스템이 제때 응답하지 않았고 문서가 전기되었는지 문의할 수 없으면 전기가 **미확인**입니다. 사람이 시스템에서 찾은 내용으로 이를 확정합니다.

### 게시 여부 보고

전기를 열고 **게시 여부 보고**를 선택합니다. 시스템에서 문서를 찾은 다음 다음 중에서 선택합니다.

- **전기됨**을 선택하고 **시스템의 문서 번호**를 입력합니다. 전기는 해당 번호와 함께 **전기됨**이 됩니다.
- **전기되지 않음**을 선택합니다. 전기는 **전기되지 않음**이 되며 다시 시도할 수 있습니다.

본 내용을 설명하는 **메모**는 필수입니다. 잘못된 응답은 문서를 두 번 전기하거나 시스템이 받지 못한 문서를 기록할 수 있으므로 `erp.register.operate`, `erp.register.approve` 및 연결에 대한 본인의 권한이 필요하며, `erp.register.approve`가 없으면 버튼이 회색으로 표시되고 그 이유를 알려 줍니다. 시스템 자체의 응답이 먼저 도착하면 그 응답이 우선합니다.

### 저장된 보고서에서 확정

SAP 전기는 실행의 보고서를 남깁니다. **조치 필요**에서 **미확인** 항목이 있고 `erp.register.operate`가 있으면 도구 모음에 **저장된 보고서에서 확정**이 나타납니다. 선택한 행의 보고서를 읽거나, 선택한 행이 없으면 범위 안의 모든 시스템의 보고서를 읽어 **전기됨**으로 확정될 문서 수를 알려 주고 확정할 수 없는 문서를 이유와 함께 나열합니다. **문서 3개 확정**처럼 개수가 표시된 버튼을 선택하여 적용합니다.

보고서에서 확정하면 문서는 **전기됨**으로만 이동하며 거부로 표시되는 것은 없습니다. 보고서가 없거나, 전송한 실행보다 오래되었거나, 전기된 것으로 표시되지 않은 문서는 **미확인**으로 남습니다.

## 승인

**승인**은 사용자를 기다리는 항목을 결정하는 곳입니다. 헤더의 칩으로 다음을 전환합니다.

- **나를 기다리는 항목** — 결정할 수 있는 되돌리기 승인 요청.
- **내가 제출함** — 사용자가 한 요청.
- **보류된 문서** — 두 번째 사람을 기다리는 되돌리기, 대변, 정정과 보류 규칙이 보류 중인 문서이며, `erp.register.approve`가 있는 경우에만 표시됩니다.

헤더의 **위임** 링크는 [위임](#위임)을 엽니다.

### 되돌리기 요청

각 요청에는 항목, 금액과 엔터티, 요청한 사람과 경과 시간, 되돌릴 기간, 요청자의 사유가 표시됩니다. **승인** 또는 **거부**를 선택하고 결정과 함께 기록될 사유를 입력한 다음 확인합니다. 여러 건을 한꺼번에 승인하려면 선택한 다음 선택한 행 수가 표시된 헤더의 **선택 항목 승인(3)** 버튼을 선택합니다.

- 승인하면 메시지에 8초 동안 **실행 취소**가 제공되고, 5분의 보류가 유지되는 동안 행에 **승인 취소**가 제공됩니다. 보류가 지나면 되돌리기가 이미 시스템에 반영되었을 수 있습니다.
- **내가 제출함**에서 **요청 철회**는 아직 대기 중이거나 승인된 요청을 철회합니다.
- 4시간 동안 대기한 요청에는 **에스컬레이션됨**이, 24시간 후에는 **두 번 에스컬레이션됨**이 표시됩니다. 결정되지 않은 요청은 7일 후 만료되며 다시 요청해야 합니다.

승인 권한이 없으면 페이지에 요청을 나열하는 대신 **되돌리기를 승인할 수 없습니다**가 표시됩니다.

### 보류된 문서

**보류된 문서**는 두 번째 사람을 기다리는 되돌리기, 대변, 정정을 먼저, 그다음 [보류 규칙](/ko/guides/connections/erp-systems/)이 보류 중인 문서를 오래된 순으로 나열합니다. 실행별로 그룹화됩니다. 비정상적인 규모로 표시된 문서에는 **비정상**이 표시됩니다.

**승인**을 선택하면 문서가 전송되며, 실행 카드에서 문서 수가 표시된 버튼(예: **문서 3개 모두 승인**)을 선택하면 해당 실행이 보여 주는 모든 문서가 전송됩니다. 문서가 전송될 시스템을 알려 주는 확인이 먼저 표시됩니다. **거부**는 이유를 묻고 문서를 **전기되지 않음**으로 만듭니다. 승인된 문서는 실행의 모드와 프로젝트의 현재 제한 및 권한에 따라 전송됩니다.

사용자가 시작했거나 보낸 실행의 문서, 또는 사용자가 한 전기에 대해 작용하는 문서는 결정할 수 없습니다. 다른 사람이 승인해야 합니다. 세트는 통째로 승인되므로 결정할 수 없는 문서가 하나라도 있는 세트는 결정할 수 있는 사람에게 남겨집니다.

## 위임

**위임**은 승인자가 휴가 등으로 자리를 비울 때 일정 기간 다른 멤버에게 승인 권한을 넘기도록 하며, 사용자에게 넘겨진 권한도 보여 줍니다. 두 개의 카드에 **위임함**과 **나에게 위임됨**이 나열됩니다.

**승인 위임**을 선택하고 **멤버**를 선택하고 **일**수(기본값 7일, 최대 30일)를 설정한 다음 감사 추적에 기록되는 **사유**를 입력합니다. **취소**는 위임을 일찍 종료하며 양쪽 모두 취소할 수 있습니다.

- 위임에는 `erp.register.approve`가 필요합니다. 위임을 보고 취소하는 데는 `erp.register.operate`만 필요합니다. 위임받는 사람은 보통 승인자 권한이 없기 때문이며, 그래서 위임하는 것입니다. 위임받는 사람은 `erp.register.operate`가 있어야 합니다.
- 자기 자신, 자신에게 위임한 사람, 서비스 계정에는 위임할 수 없으며 위임받은 사람이 권한을 다시 넘길 수 없습니다.
- 위임받은 사람은 자신에게 위임한 사람이 한 요청을 승인할 수 없습니다. 위임받은 사람이 승인하는 동안 **승인** 헤더에 누구의 권한을 사용하는지 표시되며 각 결정은 해당 승인자의 권한으로 이루어진 것으로 기록됩니다.

## 내 감시 목록

**내 감시 목록**은 감시 중인 연결과 실행을 나열합니다. **연결 감시**를 선택하면 볼 수 있는 연결 중 하나를 추가하고, **감시 중지**를 선택하면 하나를 제거합니다. 메시지의 **실행 취소**는 다시 감시합니다.

## 내보내기 및 알림

**내보내기 및 알림**은 등록부가 파일이나 알림으로 PlaidCloud를 벗어나는 곳입니다. 여기의 모든 기능에는 `erp.register.operate`가 필요하며, 없으면 페이지에서 등록부를 읽을 수는 있지만 내보낼 수는 없다고 설명합니다.

<Aside type="caution">
다운로드한 파일은 PlaidCloud를 벗어납니다. 권한, 역할, 마스킹은 파일을 만들 때마다(예약된 전송마다 포함) 확인되지만 전달된 이후에는 아무것도 확인되지 않습니다. 자유 형식 텍스트 필드는 모든 내보내기에서 제외됩니다.
</Aside>

### 파일에 포함되는 내용

모든 파일은 만들어지는 시점의 사용자 본인의 액세스를 기준으로 두 가지 프로필 중 하나로 만들어집니다.

- **표준** — 금액, 통화, 각 문서를 전기한 멤버는 제외됩니다.
- **감사자** — 금액, 통화, 각 문서를 전기한 멤버가 포함됩니다. 이 프로필에는 `erp.register.admin`이 필요합니다.

페이지에는 내보내기에 어느 프로필이 사용되는지 표시됩니다.

### 지금 다운로드

도구 모음(또는 **작업** 메뉴)에서 다음을 선택합니다.

- **CSV 다운로드**와 **JSON 다운로드**는 등록부를 내보냅니다. 내보내기 일정을 선택한 경우 파일은 해당 일정의 필터를 사용합니다.
- **증빙 내보내기…** 는 한 기간의 증빙을 만듭니다. [증빙 내보내기](#증빙-내보내기)를 참조하십시오.

### 일정 및 알림

**새 일정**을 선택하고 다음을 입력합니다.

- **이름**과 **종류**: **내보내기 파일** 또는 **알림**.
- 내보내기 파일의 **형식**(CSV 또는 JSON), 또는 알림의 **전송 조건**: **실제 전기가 실패할 때**, **승인이 오래 지연될 때** 또는 **역분개가 전기될 때**.
- **주기**: **요청 시**, **매일**, **매주** 또는 **매월**.
- **수신자**: PlaidCloud 멤버이며 이메일 주소는 불가.
- 선택적으로 범위를 좁히는 **연결**과 **엔터티**.

매일 실행되는 작업이 마지막 전송 이후 간격이 지난 모든 **매일**, **매주**, **매월** 일정을 전송합니다. **요청 시** 일정은 **지금 보내기**를 선택할 때만 전송됩니다. **일정 삭제**는 일정을 완전히 중지합니다.

각 수신자는 전송 시점에 본인의 액세스가 허용하는 내용을 받으므로, 한 일정의 두 수신자가 서로 다른 파일을 받을 수 있습니다. 내보내기 역할이 더 이상 없거나, 연결 권한이 없거나, 이메일 주소가 없거나, 비활성화된 수신자는 건너뛰며, **지금 보내기**는 건너뛴 사람과 이유를 알려 줍니다. 일정의 소유자 또는 `erp.register.admin`이 있는 멤버만 일정을 보내거나 삭제할 수 있습니다.

### 증빙 내보내기

**증빙 내보내기…** 는 한 기간을 다섯 부분으로 저장합니다. 전기된 내용, 장부에 있는 내용, 승인한 사람, 규칙과 로직에서 변경된 내용, 누가 무엇을 할 수 있었는지입니다. **기간**(예: `2026-10`)을 입력하고, 선택적으로 **엔터티** 아래에 하나 이상의 엔터티(비워 두면 모두)를 입력하고, **Excel** 또는 **JSON**을 선택한 다음 **다운로드**를 선택합니다.

파일에는 해당 기간 날짜의 볼 수 있는 실거래 전기가 포함됩니다. 표준 프로필은 금액과 모든 사람(시작한 사람, 요청한 사람, 결정한 사람, 변경한 사람, 승인자의 사유, 규칙의 변경 전후, 액세스 섹션)을 제외하므로 전체 기록을 담는 것은 감사자 프로필입니다.

## 변경 내역

**변경 내역**은 시스템 설정, 시스템 사용 종료, SAP 함수, 코드 매칭, 어느 엔터티가 어디에 전기하는지, 보류 규칙, 라이브 전환, 목록 복사에 대한 모든 변경을 **시점**, **수행자**, **항목**, **시스템**, **대상**, **시작**, **종료**와 함께 나열합니다. 최대 2,000건의 변경을 표시하며, 나머지를 보려면 하나의 시스템으로 좁히십시오. `analyze.connection.read`가 필요합니다.

## 보존

**설정** 아래의 **보존**은 등록부가 세 가지 이력을 얼마나 오래 보관할지 설정합니다. **캡처 (사이드카 요청/응답)**, **시뮬레이션 저장소**, **감사 추적 쓰기**입니다. 각각 최대 3,650일의 일수 또는 **무제한**입니다. **저장**을 선택하여 적용합니다. 카드에는 정책을 마지막으로 설정한 사람과 시점이 표시되며, 누군가 설정하기 전까지는 모든 기한이 무제한입니다.

`erp.register.admin`이 있는 멤버만 레일에서 **보존**을 보고 변경할 수 있습니다. 매일 실행되는 정리 작업이 정책을 적용합니다.

<Aside type="note">
보존은 전기된 내용의 기록에는 영향을 주지 않으며, 이 기록이 문서가 두 번 전기되는 것을 막습니다. 캡처 기한이 지나면 전기의 캡처된 요청과 응답은 삭제되지만 전기, 상태, 세부 정보는 남습니다. 시뮬레이션 기한이 지나면 시뮬레이션된 전기가 삭제됩니다.
</Aside>
