PlaidCloud를 **Anaplan**에 연결하면 워크플로가 Anaplan의 대용량 읽기 요청 경로로 저장된 뷰를 읽거나, 기존 내보내기 작업을 실행하거나, 하나 이상의 Anaplan 목록을 PlaidCloud 차원으로 읽어 올 수 있습니다. 이 연결은 Anaplan 자체 Integration API에 **클라우드 직접** 방식으로 접속하며, 이 단계에는 온프레미스 에이전트 경로가 없습니다. 이 가이드에서는 연결, 인증, 세 가지 읽기 단계 각각에 대한 간단한 소개, 일정 관련 고려 사항을 다룹니다.

<Aside type="note">
이 커넥터는 읽기 전용입니다. Anaplan에는 아무것도 다시 쓰지 않으며, 쓰기 단계도 없고 부분 적용 모드도 없습니다.
</Aside>

## 사전 요구 사항

Anaplan 워크스페이스 관리자로부터 다음을 받아야 합니다.

- Anaplan **사용자 이름과 암호**, 또는 Anaplan 워크스페이스 관리자가 Anaplan 사용자에게 등록한 **CA 인증서와 개인 키**. 워크플로가 읽을 워크스페이스와 모델에 대한 읽기 권한이 있어야 합니다. 아래 [인증](#인증)을 참조하십시오.
- 읽어 올 모델의 **워크스페이스 ID**와 **모델 ID**. Anaplan의 모델 설정에서 확인할 수 있습니다. 연결을 만든 후에는 연결에서 실시간으로 조회할 수도 있습니다.
- **Anaplan: 뷰 읽기**의 경우 원하는 행, 열, 필터 범위로 정확히 구성한 **저장된 뷰**. 아래 [Anaplan: 뷰 읽기](#anaplan-뷰-읽기)를 참조하십시오.
- **Anaplan: 내보내기 읽기**의 경우 모델에 **이미 존재하는 내보내기 작업**.
- **Anaplan: 목록 읽기**의 경우 읽으려는 계층을 구성하는 Anaplan **목록**.

## 인증

연결에는 **인증 모드**가 있으며, **기본**(기본값) 또는 **인증서** 중에서 선택합니다. 기존 연결은 변경 없이 기본 모드로 계속 작동합니다.

- **기본**은 Anaplan 사용자 이름과 암호로 로그인합니다.
- **인증서**는 CA에서 발급한 인증서와 그 개인 키로 로그인하며, 둘 다 PEM 텍스트로 붙여 넣습니다. 개인 키는 **RSA이며 암호화되지 않은 것**이어야 하고, 인증서는 Anaplan 워크스페이스 관리자가 Anaplan 사용자에게 등록한 것으로서 해당 테넌트에서 Anaplan이 신뢰하는 CA가 발급한 것이어야 합니다. PlaidCloud는 키로 임의의 챌린지에 서명한 뒤 이를 Anaplan 토큰으로 교환하며, 이는 Anaplan 자체 인증서 인증 흐름을 따릅니다. 인증서와 키를 붙여 넣은 후에는 따로 할 일이 없으며, 토큰 갱신은 기본 모드와 동일하게 작동합니다. 두 필드 모두 붙여 넣은 내용을 가리며, 두 비밀 값은 기본 모드의 암호와 마찬가지로 암호화되어 저장됩니다. 모드를 전환해도 다른 모드의 자격 증명은 전송되지 않습니다. 기존 연결을 기본에서 인증서로 전환하는 경우 인증서와 키는 이월되지 않으므로 다시 붙여 넣어야 합니다.

Anaplan의 다단계 인증은 이메일과 암호로 로그인하는 사용자에게 적용됩니다. 인증서 인증은 자동으로 예약 실행되는 연결에 사용할 수 있는 비암호 방식입니다.

인증서 모드는 붙여 넣은 키나 인증서를 읽을 수 없거나, 키가 암호화되어 있거나 RSA가 아니거나, 키가 인증서와 일치하지 않는 경우 Anaplan에 접속하기 전에 거부합니다. Anaplan 자체가 인증서를 거부하면 오류 메시지에 만료 여부가 표시됩니다. 일반적인 원인은 인증서가 Anaplan 사용자에게 등록되지 않았거나, 해당 테넌트에서 신뢰하지 않는 CA가 발급한 경우입니다.

## 연결 만들기

<Steps>

1. **Tools > Connections**를 열고 `New Connection`을 클릭합니다.

2. 메뉴에서 **Anaplan**을 선택합니다.

3. 필드를 입력합니다.

   | 필드 | 값 |
   |---|---|
   | 이름 | 알아보기 쉬운 이름입니다(예: `Anaplan Prod`). |
   | API 호스트 | 선택 사항입니다. Anaplan의 표준 주소 `https://api.anaplan.com`을 사용하려면 비워 둡니다. |
   | 인증 호스트 | 선택 사항입니다. Anaplan의 표준 주소 `https://auth.anaplan.com`을 사용하려면 비워 둡니다. |
   | 인증 모드 | **기본**(기본값) 또는 **인증서**입니다. 위의 [인증](#인증)을 참조하십시오. |
   | 사용자 이름 | Anaplan 계정의 사용자 이름입니다. 기본 모드에서만 사용합니다. |
   | 암호 | Anaplan 계정의 암호입니다. 기본 모드에서만 사용합니다. |
   | CA 인증서 | Anaplan에 등록된 X.509 인증서의 PEM 텍스트입니다. 인증서 모드에서만 사용합니다. |
   | 개인 키 | 인증서의 RSA 개인 키 PEM 텍스트이며 암호화되지 않은 것이어야 합니다. 인증서 모드에서만 사용합니다. |
   | 기본 작업 영역 ID | 선택 사항입니다. 읽기 단계의 워크스페이스 필드를 미리 채우는 편의 기능입니다. |
   | 기본 모델 ID | 선택 사항입니다. 읽기 단계의 모델 필드를 미리 채우는 편의 기능입니다. |
   | 제한 시간(초) | 기본값은 30입니다. |

4. `Test Connection`을 클릭합니다. 테스트에 성공하면 자격 증명이 가리키는 Anaplan 계정의 이메일이 표시됩니다.

5. `Create`를 클릭합니다.

</Steps>

## Anaplan: 뷰 읽기

**Anaplan: 뷰 읽기** 단계를 추가하면 Anaplan의 대용량 읽기 요청 경로로 저장된 뷰를 읽을 수 있습니다. **뷰는 Anaplan에 저장된 그대로 읽으며, 이 단계에는 행, 열, 페이지 선택 기능이 없습니다.** 다른 범위를 읽으려면 Anaplan에서 다른 저장된 뷰를 만드십시오. Anaplan에서 필터링할 때는 일반적으로 Boolean 라인 항목과 저장된 뷰를 함께 사용합니다. 데이터 열은 뷰에서 **라인 항목이 열 축에** 있을 때만 Anaplan에 선언된 유형으로 저장됩니다. 라인 항목이 행에 있거나(일반적인 손익계산서 레이아웃) 뷰에 없으면 모든 열이 텍스트로 저장되며, 단계에서 이를 알려 줍니다. 필터와 일치하는 데이터가 없는 뷰는 경고와 함께 빈 테이블로 저장됩니다. 숫자 값을 모호하지 않게 읽을 수 없는 경우(대부분 일반 소수와 유럽식 표기 모두로 해석될 수 있는 값)에는 같은 열의 다른 값으로 올바른 해석이 정해지지 않는 한 추측하지 않고 거부합니다. 구문 분석된 값은 반올림 오차 없이 전체 정밀도로 저장됩니다. 전체 필드 및 동작 참조는 [Anaplan: 뷰 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-view/)를 참조하십시오.

## Anaplan: 내보내기 읽기

**Anaplan: 내보내기 읽기** 단계를 추가하면 **기존** Anaplan 내보내기 작업을 실행하고 그 결과 파일을 저장할 수 있습니다. API로는 내보내기 작업을 만들 수 없으므로 먼저 Anaplan에서 작업을 만들거나 수정하십시오. 또한 이 단계는 내보내는 내용을 좁힐 수 없으며, Anaplan에서 해당 작업이 내보내도록 구성된 내용이 그대로 저장됩니다. **모든 열은 텍스트로 저장됩니다.** 숫자는 미국식 서식으로 요청되며, 그래도 천 단위 구분 기호가 포함되어 반환된 열은 변경 없이 텍스트로 저장되고 실행이 실패하는 대신 명명된 경고가 표시됩니다. 내보내기가 실패하거나 취소되거나 데이터를 생성하지 않는 경우, 단계의 폴링 허용량이 소진될 때까지 계속 실행 중인 경우, 내보내기와 연결할 수 없는 파일이 생성되거나 행 수가 Anaplan 자체 보고 값과 다른 경우에는 테이블을 저장하는 대신 단계가 중지됩니다. 전체 참조는 [Anaplan: 내보내기 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-export/)를 참조하십시오.

## Anaplan: 목록 읽기

**Anaplan: 목록 읽기** 단계를 추가하면 하나 이상의 Anaplan 목록을 PlaidCloud 차원으로 읽을 수 있습니다. **하나의 단계가 복합 계층 전체를 읽습니다.** 여러 단계로 나누지 말고, 계층이 걸쳐 있는 모든 목록을 루트부터 순서대로 지정하십시오(예: 지역, 국가, 매장). 스테이징 테이블은 실행할 때마다 교체되므로, 하나의 스테이징 테이블을 가리키는 여러 단계가 있으면 각 단계가 이전 단계의 행을 지우게 됩니다. Anaplan 목록 계층에는 읽을 수 있는 에지별 가중치나 부호가 없으므로 모든 에지는 단순한 `+`로 롤업됩니다. Anaplan의 목록 액세스 제어와 하위 집합 멤버십은 차원 데이터가 아니라 메타데이터이므로 가져오지 않습니다. 노드 ID 중복, 해석할 수 없는 부모 참조, 충돌하는 부모 참조, 가져온 메타데이터와 이름이 겹치는 속성 이름은 아무것도 저장되기 전에 거부됩니다. 전체 참조는 [Anaplan: 목록 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-list/)를 참조하십시오.

## Data Foundation의 소스로서의 Anaplan

[Data Foundation](/ko/guides/projects/data-foundation/)은 Anaplan에 있는 계획(예산, 예측, 연결 모델의 결과)을 읽어 Common Finance Model로 가져올 수 있습니다. 계획만 가져오고 원장은 가져오지 않으며, 읽기만 수행합니다.

Data Foundation은 모델의 내보내기 작업 하나를 저장된 그대로 실행하므로, Anaplan 관리자가 먼저 해당 내보내기를 만들어야 합니다. **Foundation** 탭에서 관리자에게 보낼 요청서를 작성해 줍니다. 내보내기는 엔터티, 기간, 계정, 부서마다 한 행씩 있는 평면 그리드여야 하며 열 제목은 정확히 다음과 같아야 합니다.

| 열 | 내용 |
|---|---|
| `Entity` | 엔터티 코드입니다. |
| `Period` | `YYYY-MM` 형식의 월입니다. |
| `Account` | 계정 코드입니다. |
| `Department` | 부서 코드이며, 계획에 부서가 없으면 비워 둡니다. |
| `Currency` | 금액의 통화입니다. |
| `Amount` | 천 단위 구분 기호가 없는 일반 숫자이며, 계획이 유지되는 부호를 따릅니다(수익은 양수). |

그런 다음 다른 소스와 마찬가지로 **Foundation** 탭에서 이 연결을 소스로 추가합니다([ERP 연결](/ko/guides/projects/data-foundation/#erp-연결) 참조). 새 연결에서는 **사용자 이름**, **암호**, **워크스페이스 ID**, **모델 ID**를 요청합니다. Anaplan은 선택할 엔터티 목록을 제공하지 않으므로 양식에서 하나를 묻습니다. 유지할 내보내기의 엔터티를 **이름**에 입력하거나, 모든 엔터티를 유지하려면 비워 두십시오. 그런 다음 다음 이름으로 표시되는 **시스템 설정**을 입력합니다.

| 설정 | 의미 |
|---|---|
| `export` | 실행할 내보내기 작업의 ID입니다. |
| `scenario` | `Budget`(기본값), `Forecast` 또는 `Consolidated`이며, 이는 그룹 손익계산서가 조정되는 대상인 연결 모델의 결과에 사용합니다. |
| `version` | 모든 행에 찍히는 레이블입니다. 기본값은 `Anaplan`입니다. |

금액은 자연 부호 그대로 읽습니다. 천 단위 구분 기호로 묶인 채 반환된 열은 [Anaplan: 내보내기 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-export/)와 마찬가지로 추측하지 않고 표시만 합니다.

## 일정 관련 고려 사항

Anaplan의 요청 속도 예산은 PlaidCloud만이 아니라 해당 Anaplan 테넌트에 대해 조직이 실행하는 모든 통합에 걸쳐 **테넌트 전체에서 공유**되며, PlaidCloud는 동시에 실행되는 작업 간에 일정을 조정하지 않습니다. 같은 cron 분에 여러 Anaplan 단계가 실행되면 어느 것도 끝나기 전에 이 예산이 소진될 수 있습니다. Anaplan 워크플로 일정을 한꺼번에 실행하지 말고 **시차를 두어 설정**하십시오.
