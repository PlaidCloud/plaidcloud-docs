PlaidCloud를 **Anaplan**에 연결하면 워크플로가 Anaplan의 대용량 읽기 요청 경로로 저장된 뷰를 읽거나, 기존 내보내기 작업을 실행하거나, Anaplan 목록을 하나 이상 PlaidCloud 차원으로 읽을 수 있습니다. 이 연결은 Anaplan 자체 Integration API에 **클라우드 직접** 방식으로 접속하므로, 이러한 단계에는 온프레미스 에이전트 경로가 없습니다. 이 가이드에서는 연결, 인증, 세 가지 읽기 단계의 간단한 소개, 그리고 일정 관련 고려 사항을 다룹니다.

<Aside type="note">
이 커넥터는 읽기 전용입니다. Anaplan에는 아무것도 다시 쓰지 않습니다. 쓰기 단계도 없고 부분 적용 모드도 없습니다.
</Aside>

## 사전 요구 사항

Anaplan 워크스페이스 관리자로부터 다음을 받아야 합니다.

- Anaplan **사용자 이름과 비밀번호**, 또는 Anaplan 워크스페이스 관리자가 Anaplan 사용자에게 등록한 **CA 인증서와 그 개인 키**. 워크플로가 읽을 워크스페이스와 모델에 대한 읽기 권한이 있어야 합니다. 아래 [인증](#인증)을 참조하십시오.
- 읽으려는 모델의 **워크스페이스 ID**와 **모델 ID**. Anaplan의 모델 설정에서 확인할 수 있습니다. 연결을 만든 뒤 연결에서 직접 조회할 수도 있습니다.
- **Anaplan: 뷰 읽기**의 경우: 원하는 행, 열, 필터 범위로 정확히 만들어 둔 **저장된 뷰**. 아래 [Anaplan: 뷰 읽기](#anaplan-뷰-읽기)를 참조하십시오.
- **Anaplan: 내보내기 읽기**의 경우: 모델에 **이미 존재하는 내보내기 작업**.
- **Anaplan: 목록 읽기**의 경우: 읽으려는 계층을 구성하는 Anaplan **목록**.

## 인증

연결에는 **인증 모드**가 있습니다. **기본**(기본값) 또는 **Certificate** 중에서 선택합니다. 기존 연결은 변경 없이 기본 모드로 계속 동작합니다.

- **기본**은 Anaplan 사용자 이름과 비밀번호로 로그인합니다.
- **Certificate**는 CA에서 발급한 인증서와 그 개인 키로 로그인하며, 둘 다 PEM 텍스트로 붙여 넣습니다. 개인 키는 **RSA이며 암호화되어 있지 않아야** 하고, 인증서는 Anaplan 워크스페이스 관리자가 사용자의 Anaplan 사용자에게 등록한 인증서여야 하며, 테넌트에 대해 Anaplan이 신뢰하는 CA에서 발급한 것이어야 합니다. PlaidCloud는 키로 임의의 챌린지에 서명하고 Anaplan의 인증서 인증 흐름에 따라 이를 Anaplan 토큰으로 교환합니다. 인증서와 키를 붙여 넣으면 더 할 일은 없으며, 토큰 갱신도 기본 모드와 동일하게 동작합니다. 두 필드 모두 붙여 넣은 내용을 가리며, 두 비밀 값 모두 기본 모드 비밀번호와 마찬가지로 암호화되어 저장됩니다. 모드를 전환해도 다른 모드의 자격 증명은 전송되지 않습니다. 기존 연결을 기본에서 Certificate로 전환하면 인증서와 키는 이월되지 않으므로 다시 붙여 넣어야 합니다.

Anaplan의 다단계 인증은 이메일과 비밀번호로 로그인하는 사용자에게 적용됩니다. Certificate 인증은 자동화된 예약 연결을 위한 비밀번호 없는 방식입니다.

붙여 넣은 키나 인증서를 읽을 수 없거나, 키가 암호화되어 있거나 RSA가 아니거나, 키가 인증서와 일치하지 않으면 Certificate 모드는 Anaplan에 접속하기 전에 거부합니다. Anaplan 자체가 인증서를 거부하면 오류 메시지에 만료 여부가 표시됩니다. 일반적인 원인은 Anaplan 사용자에게 등록되지 않은 인증서이거나 테넌트에서 신뢰하지 않는 CA입니다.

## 연결 만들기

<Steps>

1. **Tools > Connections**를 열고 `New Connection`을 클릭합니다.

2. 메뉴에서 **Anaplan**을 선택합니다.

3. 필드를 입력합니다.

   | 필드 | 값 |
   |---|---|
   | 이름 | 알아보기 쉬운 이름입니다. 예: `Anaplan Prod`. |
   | API 호스트 | 선택 사항입니다. Anaplan의 표준 `https://api.anaplan.com`을 사용하려면 비워 둡니다. |
   | 인증 호스트 | 선택 사항입니다. Anaplan의 표준 `https://auth.anaplan.com`을 사용하려면 비워 둡니다. |
   | 인증 모드 | **기본**(기본값) 또는 **Certificate**. 위의 [인증](#인증)을 참조하십시오. |
   | 사용자 이름 | Anaplan 계정의 사용자 이름입니다. 기본 모드에서만 사용합니다. |
   | 비밀번호 | Anaplan 계정의 비밀번호입니다. 기본 모드에서만 사용합니다. |
   | CA 인증서 | Anaplan에 등록된 X.509 인증서의 PEM 텍스트입니다. Certificate 모드에서만 사용합니다. |
   | 개인 키 | 인증서의 RSA 개인 키(암호화되지 않음)의 PEM 텍스트입니다. Certificate 모드에서만 사용합니다. |
   | 기본 작업 영역 ID | 선택 사항입니다. 읽기 단계의 워크스페이스 필드를 미리 채우는 편의 기능입니다. |
   | 기본 모델 ID | 선택 사항입니다. 읽기 단계의 모델 필드를 미리 채우는 편의 기능입니다. |
   | 시간 제한(초) | 기본값은 30입니다. |

4. `Test Connection`을 클릭합니다. 테스트에 성공하면 자격 증명이 가리키는 Anaplan 계정의 이메일이 표시됩니다.

5. `Create`를 클릭합니다.

</Steps>

## Anaplan: 뷰 읽기

**Anaplan: 뷰 읽기** 단계를 추가하면 Anaplan의 대용량 읽기 요청 경로로 저장된 뷰를 읽습니다. **뷰는 Anaplan에 저장된 그대로 읽으며, 이 단계에서는 행, 열, 페이지를 선택할 수 없습니다.** 다른 범위를 읽으려면 Anaplan에서 다른 저장된 뷰를 만드십시오. 일반적으로 Anaplan에서 필터링할 때는 Boolean 라인 항목과 저장된 뷰를 함께 사용합니다. 데이터 열은 뷰에서 **라인 항목이 열 축**에 있을 때만 선언된 Anaplan 유형으로 적재됩니다. 라인 항목이 행에 있거나(일반적인 손익계산서 레이아웃) 뷰에 없으면 모든 열이 텍스트로 적재되며, 단계가 이를 알려 줍니다. 필터에 일치하는 항목이 없는 뷰는 경고와 함께 빈 테이블로 적재됩니다. 이 단계가 명확하게 읽을 수 없는 숫자 값(대부분 일반 소수 표기인지 유럽식 표기인지 모호한 경우)은 추측하지 않고 거부합니다. 단, 같은 열의 다른 값으로 어느 해석이 맞는지 판별되는 경우는 예외입니다. 파싱되는 값은 반올림 오차 없이 전체 정밀도로 적재됩니다. 전체 필드와 동작 참조는 [Anaplan: 뷰 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-view/)를 참조하십시오.

## Anaplan: 내보내기 읽기

**Anaplan: 내보내기 읽기** 단계를 추가하면 **기존** Anaplan 내보내기 작업을 실행하고 그 결과 파일을 적재합니다. API로는 내보내기 작업을 만들 수 없으므로 먼저 Anaplan에서 작업을 만들거나 편집해야 하며, 이 단계에서는 출력 내용을 좁힐 수 없습니다. Anaplan에서 내보내도록 구성된 내용이 그대로 적재됩니다. **모든 열이 텍스트로 적재됩니다.** 숫자는 미국식 서식으로 요청하며, 그래도 천 단위 구분 기호가 포함되어 반환된 열은 변경 없이 텍스트로 적재되고 실행을 실패시키는 대신 이름이 있는 경고가 표시됩니다. 내보내기가 실패하거나 취소되거나, 데이터가 생성되지 않거나, 단계의 폴링 허용 시간이 끝난 뒤에도 계속 실행 중이거나, 내보내기와 연결할 수 없는 파일을 생성하거나, 행 수가 Anaplan이 직접 보고한 수와 다르면 단계는 테이블을 적재하지 않고 중지됩니다. 전체 참조는 [Anaplan: 내보내기 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-export/)를 참조하십시오.

## Anaplan: 목록 읽기

**Anaplan: 목록 읽기** 단계를 추가하면 Anaplan 목록을 하나 이상 PlaidCloud 차원으로 읽습니다. **하나의 단계가 복합 계층 전체를 읽습니다.** 계층이 걸쳐 있는 모든 목록을 루트부터 순서대로 지정하고(예: Region, Country, Store) 여러 단계로 나누지 마십시오. 스테이징 테이블은 실행할 때마다 교체되므로, 여러 단계가 하나의 스테이징 테이블을 가리키면 각 단계가 이전 단계의 행을 지웁니다. Anaplan 목록 계층에는 읽을 수 있는 에지별 가중치나 부호가 없으므로 모든 에지는 단순 `+`로 롤업됩니다. Anaplan의 목록 액세스 제어와 하위 집합 멤버십은 차원 데이터가 아니라 메타데이터이므로 가져오지 않습니다. 중복된 노드 ID, 확인할 수 없는 상위 참조, 충돌하는 상위 참조, 가져온 메타데이터와 이름이 충돌하는 속성은 아무것도 적재되기 전에 거부됩니다. 전체 참조는 [Anaplan: 목록 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-list/)를 참조하십시오.

## Data Foundation 소스로서의 Anaplan

[Data Foundation](/ko/guides/projects/data-foundation/)은 Anaplan이 보유한 계획(예산, 예측, 통합 모델의 결과)을 Common Finance Model로 읽어 올 수 있습니다. 계획만 가져오고 원장은 가져오지 않으며, 읽기만 합니다.

Data Foundation은 모델에 저장된 그대로 내보내기 작업 하나를 실행하므로, Anaplan 관리자가 먼저 해당 내보내기를 만들어야 합니다. **Foundation** 탭에서 관리자에게 보낼 요청서를 작성해 줍니다. 내보내기는 엔터티, 기간, 계정, 부서마다 한 행씩 있는 평면 그리드여야 하며, 열 제목은 다음과 정확히 같아야 합니다.

| 열 | 내용 |
|---|---|
| `Entity` | 엔터티 코드입니다. |
| `Period` | `YYYY-MM` 형식의 월입니다. |
| `Account` | 계정 코드입니다. |
| `Department` | 부서 코드입니다. 계획에 부서가 없으면 비워 둡니다. |
| `Currency` | 금액의 통화입니다. |
| `Amount` | 천 단위 구분 기호가 없는 일반 숫자이며, 계획이 유지하는 부호 기준입니다(수익은 양수). |

그런 다음 다른 소스와 마찬가지로 **Foundation** 탭에서 이 연결을 소스로 추가하고([ERP 연결](/ko/guides/projects/data-foundation/#erp-연결) 참조) 다음을 선택합니다.

| 설정 | 의미 |
|---|---|
| 내보내기 | 실행할 내보내기 작업의 ID입니다. |
| 시나리오 | **예산**(기본값), **예측** 또는 **통합**. 통합은 그룹 손익계산서가 대사되는 통합 모델의 결과를 위한 것입니다. |
| 버전 | 모든 행에 기록되는 레이블입니다. 기본값은 `Anaplan`입니다. |
| 엔터티 | 내보내기에서 유지할 엔터티입니다. Anaplan은 선택할 목록을 제공하지 않으므로 직접 입력합니다. 비워 두면 모든 엔터티를 유지합니다. |

금액은 자연 부호 그대로 읽습니다. 여전히 천 단위 구분 기호로 묶여 반환된 열은 추측하지 않고 표시됩니다. 이는 [Anaplan: 내보내기 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-export/)와 같습니다.

## 일정 관련 고려 사항

Anaplan의 요청 속도 한도는 PlaidCloud만이 아니라 해당 Anaplan 테넌트에 대해 조직이 실행하는 모든 통합에 걸쳐 **테넌트 전체에서 공유**되며, PlaidCloud는 동시 실행 간의 일정을 조율하지 않습니다. 같은 cron 분에 여러 Anaplan 단계가 적재되면 어느 것이든 끝나기 전에 이 한도가 소진될 수 있습니다. Anaplan 워크플로를 모두 한꺼번에 실행하지 말고 **일정을 분산하십시오**.
