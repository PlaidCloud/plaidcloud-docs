PlaidCloud를 **Anaplan**에 연결하면 워크플로가 Anaplan의 대용량 읽기 요청 경로로 저장된 뷰를 읽거나, 기존 내보내기 작업을 실행하거나, Anaplan 목록을 하나 이상 PlaidCloud 차원으로 읽어 올 수 있습니다. 이 연결은 Anaplan 자체 Integration API에 **클라우드로 직접** 연결되며, 이러한 단계에는 온프레미스 에이전트 경로가 없습니다. 이 가이드에서는 연결, 인증, 세 가지 읽기 단계 각각에 대한 간단한 소개, 일정 관련 고려 사항을 다룹니다.

<Aside type="note">
이 커넥터는 읽기 전용입니다. Anaplan에는 아무것도 다시 기록되지 않으며, 쓰기 단계나 부분 적용 모드도 없습니다.
</Aside>

## 사전 요구 사항

Anaplan 워크스페이스 관리자로부터 다음이 필요합니다.

- Anaplan **사용자 이름과 암호**, 또는 워크스페이스 관리자가 Anaplan 사용자에게 등록한 **CA 인증서와 그 개인 키**. 워크플로가 읽을 워크스페이스와 모델에 대한 읽기 권한이 있어야 합니다. 아래의 [인증](#인증)을 참조하십시오.
- 읽어 올 모델의 **워크스페이스 ID**와 **모델 ID**. Anaplan의 모델 설정에서 확인할 수 있습니다. 연결을 만든 후에는 연결에서 실시간으로 검색할 수도 있습니다.
- **Anaplan: 뷰 읽기**의 경우 — 원하는 행, 열, 필터 슬라이스로 정확하게 만든 **저장된 뷰**. 아래의 [Anaplan: 뷰 읽기](#anaplan-뷰-읽기)를 참조하십시오.
- **Anaplan: 내보내기 읽기**의 경우 — 모델에 **이미 있는 내보내기 작업**.
- **Anaplan: 목록 읽기**의 경우 — 읽으려는 계층을 구성하는 Anaplan **목록**.

## 인증

연결에는 **인증 모드**가 있으며 **기본**(기본값) 또는 **인증서** 중에서 선택합니다. 기존 연결은 변경 없이 기본 모드로 계속 동작합니다.

- **기본**은 Anaplan 사용자 이름과 암호로 로그인합니다.
- **인증서**는 CA에서 발급한 인증서와 그 개인 키로 로그인하며, 둘 다 PEM 텍스트로 붙여 넣습니다. 개인 키는 **RSA이며 암호화되지 않은 키**여야 하고, 인증서는 Anaplan 워크스페이스 관리자가 Anaplan 사용자에게 등록한 인증서여야 하며 사용자의 테넌트에서 Anaplan이 신뢰하는 CA가 발급한 것이어야 합니다. PlaidCloud는 키로 임의의 챌린지에 서명하고 Anaplan 자체의 인증서 인증 흐름에 따라 이를 Anaplan 토큰으로 교환합니다. 인증서와 키를 붙여 넣은 후에는 따로 할 일이 없으며 토큰 새로 고침도 기본 모드와 동일하게 동작합니다. 두 필드 모두 붙여 넣은 내용을 가리며, 두 비밀 값 모두 기본 모드의 암호와 마찬가지로 암호화되어 저장되고, 모드를 전환해도 다른 모드의 자격 증명은 전송되지 않습니다. 기존 연결을 기본에서 인증서로 전환하는 경우 인증서와 키는 이어지지 않으므로 직접 붙여 넣어야 합니다.

Anaplan의 다단계 인증은 이메일과 암호로 로그인하는 사용자에게 적용됩니다. 인증서 인증은 자동으로 예약 실행되는 연결에 적합한 비암호 옵션입니다.

인증서 모드는 붙여 넣은 키나 인증서를 읽을 수 없거나, 키가 암호화되어 있거나 RSA가 아니거나, 키가 인증서와 일치하지 않으면 Anaplan에 접속하기 전에 거부합니다. Anaplan 자체가 인증서를 거부하는 경우 오류에 인증서 만료 여부가 표시됩니다. 일반적인 원인은 Anaplan 사용자에게 등록되지 않은 인증서이거나 테넌트에서 신뢰하지 않는 CA입니다.

## 연결 만들기

<Steps>

1. **Tools > Connections**를 열고 `New Connection`을 클릭합니다.

2. 메뉴에서 **Anaplan**을 선택합니다.

3. 필드를 입력합니다.

   | 필드 | 값 |
   |---|---|
   | 이름 | 알아보기 쉬운 이름(예: `Anaplan Prod`). |
   | API 호스트 | 선택 사항. 비워 두면 Anaplan 표준 `https://api.anaplan.com`을 사용합니다. |
   | 인증 호스트 | 선택 사항. 비워 두면 Anaplan 표준 `https://auth.anaplan.com`을 사용합니다. |
   | 인증 모드 | **기본**(기본값) 또는 **인증서**. 위의 [인증](#인증)을 참조하십시오. |
   | 사용자 이름 | Anaplan 계정 사용자 이름. 기본 모드에서만 사용합니다. |
   | 암호 | Anaplan 계정 암호. 기본 모드에서만 사용합니다. |
   | CA 인증서 | Anaplan에 등록된 X.509 인증서의 PEM 텍스트. 인증서 모드에서만 사용합니다. |
   | 개인 키 | 인증서의 RSA 개인 키의 PEM 텍스트(암호화되지 않은 것). 인증서 모드에서만 사용합니다. |
   | 기본 작업 영역 ID | 선택 사항. 읽기 단계의 워크스페이스 필드를 미리 채워 주는 편의 기능입니다. |
   | 기본 모델 ID | 선택 사항. 읽기 단계의 모델 필드를 미리 채워 주는 편의 기능입니다. |
   | 시간 제한(초) | 기본값은 30입니다. |

4. `Test Connection`을 클릭합니다. 테스트에 성공하면 자격 증명이 확인된 Anaplan 계정 이메일이 표시됩니다.

5. `Create`를 클릭합니다.

</Steps>

## Anaplan: 뷰 읽기

Anaplan의 대용량 읽기 요청 경로로 저장된 뷰를 읽으려면 **Anaplan: 뷰 읽기** 단계를 추가합니다. **뷰는 Anaplan에 저장된 그대로 읽히며, 이 단계에는 행, 열, 페이지 선택 기능이 없습니다.** 다른 슬라이스를 읽으려면 Anaplan에서 다른 저장된 뷰를 만드십시오. 일반적으로 Anaplan에서 필터링하려면 Boolean 라인 항목과 저장된 뷰를 사용합니다. 데이터 열은 뷰에서 **열 축에 라인 항목**이 있을 때만 선언된 Anaplan 유형으로 가져와집니다. 라인 항목이 행에 있거나(일반적인 손익계산서 레이아웃) 뷰에 없으면 모든 열이 텍스트로 가져와지며, 단계가 이를 알려 줍니다. 필터와 일치하는 항목이 없는 뷰는 경고와 함께 빈 테이블로 가져와집니다. 일반 소수로도, 유럽식 표기로도 읽을 수 있는 경우처럼 단계가 모호하지 않게 읽을 수 없는 Number 값은 같은 열의 다른 값이 올바른 해석을 결정해 주지 않는 한 추측하지 않고 거부됩니다. 구문 분석에 성공한 값은 반올림 오차 없이 전체 정밀도로 가져와집니다. 전체 필드 및 동작 참조는 [Anaplan: 뷰 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-view/)를 참조하십시오.

## Anaplan: 내보내기 읽기

**기존** Anaplan 내보내기 작업을 실행하고 그 결과 파일을 가져오려면 **Anaplan: 내보내기 읽기** 단계를 추가합니다. API로는 내보내기 작업을 만들 수 없으므로 먼저 Anaplan에서 작업을 만들거나 수정하십시오. 또한 이 단계에서는 내보내는 내용을 좁힐 수 없으며, Anaplan에서 내보내도록 구성된 내용이 그대로 가져와집니다. **모든 열이 텍스트로 가져와집니다.** 숫자는 미국식 서식으로 요청되며, 그래도 천 단위 구분 기호가 포함되어 반환되는 열은 변경 없이 텍스트로 가져와지고 실행이 실패하는 대신 이름이 지정된 경고가 표시됩니다. 내보내기가 실패하거나 취소되거나 데이터를 생성하지 않는 경우, 단계의 폴링 예산이 소진된 후에도 여전히 실행 중인 경우, 내보내기와 연결할 수 없는 파일이 생성되거나 행 수가 Anaplan 자체가 보고하는 값과 일치하지 않는 경우에는 테이블을 가져오지 않고 단계가 중지됩니다. 전체 참조는 [Anaplan: 내보내기 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-export/)를 참조하십시오.

## Anaplan: 목록 읽기

Anaplan 목록을 하나 이상 PlaidCloud 차원으로 읽어 오려면 **Anaplan: 목록 읽기** 단계를 추가합니다. **단계 하나로 복합 계층 전체를 읽습니다.** 여러 단계로 나누지 말고, 계층이 포함하는 모든 목록의 이름을 루트부터 순서대로 지정하십시오(예: Region, Country, Store). 스테이징 테이블은 실행할 때마다 교체되므로 하나의 스테이징 테이블을 가리키는 여러 단계가 있으면 각 단계가 이전 단계의 행을 지워 버립니다. Anaplan 목록 계층에는 읽어 올 에지별 가중치나 부호가 없으므로 모든 에지는 단순 `+`로 롤업됩니다. Anaplan의 목록 액세스 제어와 하위 집합 멤버십은 차원 데이터가 아니라 메타데이터이므로 가져오지 않습니다. 중복된 노드 ID, 확인할 수 없는 부모 참조, 충돌하는 부모 참조, 가져온 메타데이터와 이름이 충돌하는 속성 이름이 있으면 아무것도 가져오기 전에 거부됩니다. 전체 참조는 [Anaplan: 목록 읽기](/ko/reference/workflow-steps/anaplan/anaplan-read-list/)를 참조하십시오.

## 일정 관련 고려 사항

Anaplan의 요청 속도 예산은 PlaidCloud만이 아니라 해당 Anaplan 테넌트에 대해 조직이 실행하는 모든 통합에 걸쳐 **테넌트 전체에서 공유**되며, PlaidCloud는 동시 실행 간에 일정을 조율하지 않습니다. 같은 크론 분에 여러 Anaplan 단계가 실행되면 어느 것도 끝나기 전에 이 예산이 소진될 수 있습니다. Anaplan 워크플로를 한꺼번에 실행하지 말고 **Anaplan 워크플로 일정을 서로 엇갈리게 지정**하십시오.
