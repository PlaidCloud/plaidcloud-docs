[Data Foundation](/ko/guides/projects/data-foundation/)은 연결한 모든 ERP 시스템과 인스턴스의 데이터를 하나의 Common Finance Model로 통합합니다. Workday는 Data Foundation이 직접 읽는 시스템 중 하나입니다. Workday에는 분개 전표 라인이나 잔액을 제공하는 웹 서비스가 없으므로, 이 페이지는 Data Foundation이 읽을 보고서를 구축하는 Workday 관리자와, 관리자에게 구축을 요청하는 PlaidCloud 사용자를 위한 안내입니다.

PlaidCloud는 데이터를 읽기만 합니다. 암호는 이메일로 보내지 마십시오.

## 액세스 요청 보내기

프로젝트의 **Foundation** 탭에서 **새 연결 만들기**를 선택하고 **Workday**를 고릅니다. 양식에 보고서 사양이 표시됩니다. **요청 복사**를 클릭하여 직접 작성하는 메시지에 붙여 넣거나, **이메일 요청**을 클릭하여 메일 프로그램에서 여십시오.

## Workday 관리자가 설정하는 항목

<Steps>

1. **사용자 지정 보고서(RaaS) 10개를 구축하고**(그중 4개는 선택 사항) 통합 시스템 사용자와 공유합니다. 열 이름은 정확히 그대로 사용하십시오. Data Foundation은 이름으로 매핑하므로 이름이 바뀐 열은 읽을 수 없습니다. 모든 코드 열은 "C100 Acme US"와 같은 설명 값이 아니라 개체의 Reference ID여야 합니다. 모든 보고서의 출력 형식은 JSON입니다.

2. **Financial_Management 웹 서비스** `Get_Workday_Companies`와 `Get_Currency_Conversion_Rates`를 같은 사용자에게 부여합니다.

3. **보고서 URL**과 통합 시스템 사용자의 세부 정보를 보냅니다.

</Steps>

| 보고서 | 필수 여부 | 내용 |
|---|---|---|
| Journal Lines | 예 | 전기된 분개 전표 라인당 한 행. 프롬프트: Company(라인의 회사, Reference ID) 및 Period(회계 기간의 Reference ID). 워크태그 Region, Fund, Program, Project, 내부 거래 관계사(Intercompany affiliate), 거래 통화 및 원장 통화 금액, 장부(book)를 포함합니다 |
| Beginning Balances | 예 | 회사, 회계 기간, 원장 계정별로 한 행: 기간 시작 시점의 잔액. Asset, Liability, Equity 계정만 로드됩니다 |
| Ledger Accounts | 예 | 계정, 이름, 유형, 내부 거래 플래그, 선택 사항인 범주 및 상위 계정 |
| Cost Centers | 예 | 코스트 센터, 이름, 상위 항목 |
| Fiscal Periods | 예 | 회사와 회계 기간(조정 기간 포함)별로 한 행, 시작일, 종료일, 상태 포함 |
| Headcount | 선택 사항 | 코스트 센터별 각 기간 말의 재직 인원과 FTE |
| Worktag Values | 선택 사항 | Region, Fund, Program, Project 값당 한 행, 상위 항목 포함 |
| Customers | 선택 사항 | 고객, 이름, 상위 항목, 범주, 지역, 국가 |
| Sales Items | 선택 사항 | 품목, 이름, 상위 항목, 그룹, 측정 단위 |
| Sales Invoice Lines | 선택 사항 | 고객 청구서 라인당 한 행, 수량, 총액, 할인, 순액, 원가 금액 포함 |

각 보고서의 전체 열 목록은 Foundation 탭의 사양에 있습니다. 보고서가 반환하는 내용에는 다음 규칙이 적용됩니다.

- Posted 상태의 분개 전표 라인만 로드되며, Actuals 원장만 해당합니다. Commitment 원장과 Obligation 원장은 로드되지 않습니다.
- 비어 있는 Book_Code는 기본 장부를 의미합니다. 비어 있는 라인은 해당 회사와 기간의 모든 장부에 포함되며, Book_Code가 있는 라인은 해당 장부에만 속합니다.
- 분개 전표의 회사보다 라인의 회사가 우선합니다.
- Ledger_Account_Type_ID는 Revenue, COGS, Opex, NonOperating, Asset, Liability, Equity 중 하나입니다. Workday에는 Expense 유형이 하나뿐이며 Opex로 로드됩니다. 매출원가나 영업 외 비용을 구분하려면 COGS 또는 NonOperating을 반환하는 계산 필드를 출력하십시오. 유형이 없는 계정은 손익계산서에 로드되지 않습니다.
- Draft, In Progress, Canceled, Denied 상태의 청구서는 로드되지 않습니다.
- 예산은 파일에서 로드됩니다. Adaptive Planning은 연결되어 있지 않습니다.

## 회신할 내용

| 관리자가 보내는 내용 | PlaidCloud에 입력하는 위치 |
|---|---|
| Workday 호스트 | **Workday 호스트** |
| 테넌트 이름 | **테넌트** |
| 통합 시스템 사용자의 이름 | **통합 시스템 사용자** |
| 필수 보고서 각각의 URL | **Journal Lines report URL**, **Beginning Balances report URL**, **Ledger Accounts report URL**, **Cost Centers report URL**, **Fiscal Periods report URL** |
| 구축한 선택 보고서 각각의 URL | **Headcount report URL (optional)**, **Worktag Values report URL (optional)**, **Customers report URL (optional)**, **Sales Items report URL (optional)**, **Sales Invoice Lines report URL (optional)** |
| PlaidCloud가 읽을 수 있는 회사의 Reference ID | **Companies**에서 선택합니다. 비워 두면 모든 회사를 로드합니다 |

PlaidCloud 사용자는 통합 시스템 사용자의 **암호**를 직접 붙여 넣습니다. 암호는 비밀 정보이므로 이메일로 보내지 않습니다.

**System settings**의 **Retained earnings account**에는 계정 이름만으로 알 수 없는 경우, 기초 손익이 이월되는 Equity 계정의 이름을 지정합니다. 이 설정은 선택 사항입니다.

<Aside type="note">
Workday의 Expense 유형은 하나뿐이며 Opex로 로드되고, Data Foundation의 준비 상태 검사에서 이를 표시합니다. 매출원가 계정이나 영업 외 비용 계정을 구분해야 한다면 위에서 설명한 계산 필드를 사용하십시오.
</Aside>

## 액세스 확인

PlaidCloud로 돌아가 **연결 테스트**를 클릭합니다. 각 데이터 세트는 **읽기 가능**, **권한 누락**, **오류** 중 하나로 표시됩니다.

| 데이터 세트 | 출처 |
|---|---|
| 엔터티 | `Get_Workday_Companies` |
| 계정과목표 | Ledger Accounts 보고서 |
| 부서 | Cost Centers 보고서 |
| 회계 달력 | Fiscal Periods 보고서 |
| 환율 | `Get_Currency_Conversion_Rates` |
| 시산표 | Beginning Balances 보고서 |
| 총계정원장 | Journal Lines 보고서 |
| 배부 동인(선택 사항) | Headcount 보고서 |
| 세그먼트 값(선택 사항) | Worktag Values 보고서 |
| 고객(선택 사항) | Customers 보고서 |
| 제품(선택 사항) | Sales Items 보고서 |
| 판매 라인(선택 사항) | Sales Invoice Lines 보고서 |

데이터 세트가 **권한 누락**으로 표시되면 테스트에서 해당 보고서나 웹 서비스의 이름을 알려 줍니다. 관리자에게 통합 시스템 사용자와 공유하도록 요청한 후 다시 테스트하십시오. 선택 보고서가 없는 테넌트에서도 나머지 데이터는 모두 로드됩니다.
