[Data Foundation](/ko/guides/projects/data-foundation/)은 연결한 모든 ERP 시스템과 인스턴스의 데이터를 하나의 Common Finance Model로 통합합니다. Workday는 Data Foundation이 직접 읽는 시스템 중 하나입니다. Workday에는 분개 전표 라인이나 잔액을 제공하는 웹 서비스가 없으므로, 이 페이지는 Data Foundation이 읽을 보고서를 구축하는 Workday 관리자와, 관리자에게 구축을 요청하는 PlaidCloud 사용자를 위한 안내입니다.

PlaidCloud는 데이터를 읽기만 합니다. 암호는 이메일로 보내지 마십시오.

## 액세스 요청 보내기

**홈**의 **Data Foundation** 아래에 있는 프로젝트의 **시스템** 페이지에서 **시스템 추가** 아래의 **시스템**에서 사용 중인 시스템을 선택하고 **아직 액세스 권한이 없으십니까?** 버튼을 클릭합니다. 시스템이 액세스 대기 상태가 되고, 프로젝트의 시스템을 모두 다루는 요청 하나가 Workday용 보고서 사양과 함께 표시됩니다. **요청 복사**를 클릭하여 직접 작성하는 메시지에 붙여 넣거나, **이메일 요청**을 클릭하여 메일 프로그램에서 여십시오.

## Workday 관리자가 설정하는 항목

<Steps>

1. **사용자 지정 보고서(RaaS) 18개를 구축하고**(그중 13개는 선택 사항) 통합 시스템 사용자와 공유합니다. 열 이름은 정확히 그대로 사용하십시오. Data Foundation은 이름으로 매핑하므로 이름이 바뀐 열은 읽을 수 없습니다. 모든 코드 열은 "C100 Acme US"와 같은 설명 값이 아니라 개체의 Reference ID여야 합니다. 모든 보고서의 출력 형식은 JSON입니다.

2. **Financial_Management 웹 서비스** `Get_Workday_Companies`와 `Get_Currency_Conversion_Rates`를 같은 사용자에게 부여합니다.

3. **보고서 URL**과 통합 시스템 사용자의 세부 정보를 보냅니다.

</Steps>

| 보고서 | 필수 여부 | 내용 |
|---|---|---|
| Journal Lines | 예 | 전기된 분개 전표 라인당 한 행. 프롬프트: Company(라인의 회사, Reference ID) 및 Period(회계 기간의 Reference ID). 워크태그 Region, Fund, Program, Project, 내부 거래 관계사(Intercompany affiliate), 거래 통화 및 원장 통화 금액, 장부(book)와 함께 사이트(위치), 분개 소스, 문서 일자, 작성자와 승인자 및 작성 일시, 역분개 대상 분개, 세금 코드와 세액을 포함합니다 |
| Beginning Balances | 예 | 모든 기간에 대해 회사, 회계 기간, 원장 계정별로 한 행: 기간 시작 시점의 잔액과 Ending_Balance의 기간 종료 시점 잔액. 종료 잔액은 원장이 비교되는 월말 잔액이며, 이 값이 없으면 원장은 자체 기초 잔액과 비교됩니다 |
| Ledger Accounts | 예 | 계정, 이름, 유형, 내부 거래 플래그, 선택 사항인 범주 및 상위 계정 |
| Cost Centers | 예 | 코스트 센터, 이름, 상위 항목 |
| Fiscal Periods | 예 | 회사와 회계 기간(조정 기간 포함)별로 한 행, 시작일, 종료일, 상태 포함 |
| Headcount | 선택 사항 | 코스트 센터별 각 기간 말의 재직 인원과 FTE |
| Worktag Values | 선택 사항 | Region, Fund, Program, Project 값당 한 행, 상위 항목 포함 |
| Customers | 선택 사항 | 고객, 이름, 상위 항목, 범주, 지역, 국가, 산업, 세그먼트, 첫 청구서 일자 |
| Sales Items | 선택 사항 | 품목, 이름, 상위 항목, 그룹, 측정 단위, 제품군 |
| Sales Invoice Lines | 선택 사항 | 고객 청구서 라인당 한 행, 수량, 총액, 할인, 순액, 원가 금액, 사이트, 만기일, 조건, 세금, 청구서 통화 금액 포함 |
| Statistical Drivers | 선택 사항 | 회사, 기간 말, 동인별 생산량, 면적(제곱피트) 등 |
| Suppliers | 선택 사항 | 공급업체, 이름, 상위 항목, 범주, 국가, 지급 조건, 세금 ID |
| Customer Invoices | 선택 사항 | 각 월말 시점의 미결 매출채권을 위한 전체 이력의 모든 고객 청구서 및 대변 메모 |
| Supplier Invoices | 선택 사항 | 미결 매입채무를 위한 공급업체 청구서의 동일한 정보 |
| Supplier Invoice Lines | 선택 사항 | 공급업체 청구서 라인당 한 행, 계정, 코스트 센터, 사이트, 프로젝트, 품목, 수량, 가격, 세금 포함 |
| Payments | 선택 사항 | 결제가 정산하는 문서마다 한 행, 그리고 계정에 남은 금액에 대한 한 행 |
| Bank Balances | 선택 사항 | 각 기간 말 시점의 각 은행 계정 자체 잔액 |
| Budgets | 선택 사항 | 시나리오, 버전, 회사, 기간 말, 계정, 코스트 센터별 예산 및 예측 |

각 보고서의 전체 열 목록은 액세스 요청에 있습니다. 보고서가 반환하는 내용에는 다음 규칙이 적용됩니다.

- Posted 상태의 분개 전표 라인만 로드되며, Actuals 원장만 해당합니다. Commitment 원장과 Obligation 원장은 로드되지 않습니다.
- 비어 있는 Book_Code는 기본 장부를 의미합니다. 비어 있는 라인은 해당 회사와 기간의 모든 장부에 포함되며, Book_Code가 있는 라인은 해당 장부에만 속합니다.
- 분개 전표의 회사보다 라인의 회사가 우선합니다.
- Ledger_Account_Type_ID는 Revenue, COGS, Opex, NonOperating, Asset, Liability, Equity 중 하나입니다. Workday에는 Expense 유형이 하나뿐이며 Opex로 로드됩니다. 매출원가나 영업 외 비용을 구분하려면 COGS 또는 NonOperating을 반환하는 계산 필드를 출력하십시오. 유형이 없는 계정은 손익계산서에 로드되지 않습니다.
- Draft, In Progress, Canceled, Denied 상태의 청구서와 결제는 로드되지 않습니다.
- Payments 보고서에서 문서에 적용된 대변 메모나 조정, 조정 또는 대손 상각은 자금 이동이 없습니다. Payment_Type_ID가 `Applied Credit`, `Adjustment` 또는 `Write-off`인 행으로 출력하십시오. 이 행은 미결 항목을 정산하며 결제가 아닙니다.
- 구축하지 않은 선택 보고서에 의존하는 항목은 비어 있습니다. Customer Invoices, Supplier Invoices, Supplier Invoice Lines, Payments 또는 Bank Balances가 없으면 해당 보고서가 제공하는 월은 로드되지 않으며 로드에서 경고가 표시됩니다.
- Adaptive Planning은 연결되어 있지 않습니다.

## 회신할 내용

| 관리자가 보내는 내용 | Workday 연결에 저장되는 항목 |
|---|---|
| Workday 호스트 | **Workday 호스트** |
| 테넌트 이름 | **테넌트** |
| 통합 시스템 사용자의 이름 | **통합 시스템 사용자** |
| 필수 보고서 각각의 URL | **Journal Lines report URL**, **Beginning Balances report URL**, **Ledger Accounts report URL**, **Cost Centers report URL**, **Fiscal Periods report URL** |
| 구축한 선택 보고서 각각의 URL | **Headcount report URL (optional)**, **Worktag Values report URL (optional)**, **Customers report URL (optional)**, **Sales Items report URL (optional)**, **Sales Invoice Lines report URL (optional)**, **Statistical Drivers report URL (optional)**, **Suppliers report URL (optional)**, **Customer Invoices report URL (optional)**, **Supplier Invoices report URL (optional)**, **Supplier Invoice Lines report URL (optional)**, **Payments report URL (optional)**, **Bank Balances report URL (optional)**, **Budgets report URL (optional)** |
| PlaidCloud가 읽을 수 있는 회사의 Reference ID | 시스템을 추가할 때 **옵션**의 **회사**: 회사를 선택하거나, 모든 회사를 읽으려면 선택하지 않습니다 |

PlaidCloud 사용자는 통합 시스템 사용자의 암호를 연결에 직접 입력합니다. 암호는 비밀 정보이므로 이메일로 보내지 않습니다. 보고서 URL은 **시스템 설정**이 아니라 연결의 설정입니다.

**System settings**의 **Retained earnings account**에는 계정 이름만으로 알 수 없는 경우, 기초 손익이 이월되는 Equity 계정의 이름을 지정합니다. 이 설정은 선택 사항입니다.

<Aside type="note">
Workday의 Expense 유형은 하나뿐이며 Opex로 로드되고, Data Foundation의 준비 상태 검사에서 이를 표시합니다. 매출원가 계정이나 영업 외 비용 계정을 구분해야 한다면 위에서 설명한 계산 필드를 사용하십시오.
</Aside>

## 액세스 확인

PlaidCloud로 돌아가 시스템이 추가되면 **시스템** 페이지에서 해당 시스템 행의 **연결 테스트**를 클릭합니다. 테스트는 필수 데이터 세트를 읽고 각각을 **읽기 가능**, **권한 누락**, **오류** 중 하나로 표시합니다. 선택 사항 데이터 세트는 테스트에 포함되지 않습니다.

| 데이터 세트 | 출처 |
|---|---|
| 엔터티 | `Get_Workday_Companies` |
| 계정과목표 | Ledger Accounts 보고서 |
| 부서 | Cost Centers 보고서 |
| 회계 달력 | Fiscal Periods 보고서 |
| 환율 | `Get_Currency_Conversion_Rates` |
| 시산표 | Beginning Balances 보고서 |
| 총계정원장 | Journal Lines 보고서 |
| 배부 동인(선택 사항) | Headcount 및 Statistical Drivers 보고서 |
| 세그먼트 값(선택 사항) | Worktag Values 보고서 |
| 고객(선택 사항) | Customers 보고서 |
| 제품(선택 사항) | Sales Items 보고서 |
| 판매 라인(선택 사항) | Sales Invoice Lines 보고서 |
| 공급업체(선택 사항) | Suppliers 보고서 |
| 월말 잔액(선택 사항) | Beginning Balances 보고서의 Ending_Balance |
| 은행 잔액(선택 사항) | Bank Balances 보고서 |
| 공급업체 청구서 라인(선택 사항) | Supplier Invoice Lines 및 Supplier Invoices 보고서 |
| 미결 항목(선택 사항) | Customer Invoices, Supplier Invoices, Payments 보고서 |
| 결제(선택 사항) | Payments 보고서 |
| 예산(선택 사항) | Budgets 보고서 |

데이터 세트가 **권한 누락**으로 표시되면 테스트에서 해당 보고서나 웹 서비스의 이름을 알려 줍니다. 관리자에게 통합 시스템 사용자와 공유하도록 요청한 후 다시 테스트하십시오. 선택 보고서가 없는 테넌트에서도 나머지 데이터는 모두 로드됩니다.
