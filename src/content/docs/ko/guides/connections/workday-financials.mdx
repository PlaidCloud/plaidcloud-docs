Integration System User(ISU)와 고객이 제공하는 Report-as-a-Service(RaaS) 보고서를 사용하여 PlaidCloud를 Workday Financial Management에 연결해 재무 데이터를 가져오고, Workday의 SOAP API를 통해 회계 분개를 다시 전기합니다. 이 가이드에서는 연결, 가져오기 단계, 전기 단계를 설명합니다.

<Aside type="caution">
모든 가져오기는 먼저 샌드박스 테넌트에서 실행하고, 실제 전기 전에 모든 전기 배치에 대해 아래의 **Validate Only** 절차를 거치십시오.
</Aside>

<Aside type="note">
이 연결은 HR 및 급여 데이터를 위한 Workday REST API를 대상으로 하는 일반 [Workday REST 커넥터](/ko/reference/connectors/rest/workday/)와는 다릅니다. Workday Financials는 Workday의 SOAP 웹 서비스와 RaaS 보고를 사용하므로, 재무 데이터와 분개 전기에는 이 커넥터를 사용하십시오.
</Aside>

## 사전 요구 사항

Workday에서 다음이 필요합니다.

- PlaidCloud 전용 **Integration System User(ISU)**. 재무 데이터와 Submit Accounting Journal 비즈니스 프로세스에 대한 액세스를 부여하는 Integration System Security Group이 지정되어 있어야 합니다.
- Workday **테넌트 호스트**(예: `wd5-impl.workday.com`)와 **테넌트 이름**.
- 가져오려는 데이터를 반환하도록 Workday에서 직접 만든 **Report-as-a-Service(RaaS) 보고서**. PlaidCloud가 해당 URL을 직접 호출할 수 있도록 **Web Service** 액세스로 게시되어야 합니다.

<Aside type="note">
Workday Financials는 NetSuite나 Business Central처럼 고정된 기본 제공 엔터티 집합을 노출하지 않습니다. 대신 Workday의 자체 보고서 작성기를 사용하여 RaaS 보고서로 추출을 구성하고 해당 보고서의 URL을 PlaidCloud에 제공합니다. 이렇게 하면 가져오기에서 어떤 필드와 행이 반환되는지를 직접 제어할 수 있습니다.
</Aside>

## 연결 만들기

<Steps>

1. **Tools > Connections**를 열고 `New Connection`을 클릭합니다.

2. 메뉴에서 **Workday Financials**를 선택합니다.

3. 필드를 입력합니다.

   | 필드 | 값 |
   |---|---|
   | 이름 | 알아보기 쉬운 이름(예: `Workday Financials Prod`). |
   | 테넌트 호스트 | Workday 호스트(예: `wd5-impl.workday.com`). |
   | 테넌트 이름 | Workday 테넌트 이름. |
   | ISU 사용자 이름 | Integration System User의 사용자 이름. |
   | ISU 암호 | Integration System User의 암호. |

4. `Create`를 클릭합니다.

</Steps>

## 연결 스모크 테스트

<Steps>

1. Workday에서 작은 RaaS 보고서를 만들고 Web Service 액세스로 게시합니다.

2. 워크플로에 **Import Workday Entity** 단계를 추가하고, **Workday 연결**을 사용할 연결로, **RaaS Report URL**을 보고서의 URL로, **대상 테이블**을 임시 테이블로 설정합니다.

3. 단계를 실행합니다([워크플로에서 단일 단계 실행](/ko/guides/workflows/running-one-step-in-a-workflow/) 참조).

</Steps>

대상 테이블에 데이터가 채워지면 ISU 자격 증명, 테넌트 호스트, 보고서 URL이 모두 올바른 것입니다. 오류가 발생하면 문제의 원인이 표시됩니다. 예를 들어 잘못된 자격 증명, 잘못된 테넌트 호스트, 또는 보고서에 대한 액세스 권한이 없는 ISU입니다.

## 데이터 가져오기

<Steps>

1. **Import Workday Entity** 단계를 추가하고 **Workday 연결**, **RaaS Report URL**, **대상 테이블**을 설정합니다.

2. **필터**를 추가해 가져올 범위를 제한합니다. `company`, `ledger`, `period`, `accounting_date`(범위), `ledger_account`(범위), `cost_center`는 RaaS 보고서에 일치하는 프롬프트가 정의되어 있으면 보고서 매개변수로 전달됩니다.

3. 단계를 실행하고 대상 테이블을 확인합니다.

</Steps>

<Aside type="caution">
필터는 RaaS 보고서에 프롬프트로 실제 정의된 보고서 매개변수에만 전달됩니다. 설정한 필터에 일치하는 프롬프트가 보고서에 없으면 PlaidCloud는 이를 조용히 무시하지 않고 거부합니다. 먼저 Workday의 보고서에 프롬프트를 추가하십시오.
</Aside>

## 분개 전기

**Workday Financials: Post Journal Entry** 단계는 Workday의 `Submit_Accounting_Journal` SOAP 작업을 사용하여 PlaidCloud의 공유 ERP 쓰기 파이프라인을 통해 회계 분개를 전기합니다.

<Steps>

1. 분개 한 건당 한 행으로 구성된 **헤더 테이블**을 만듭니다. `journal_id`(분개 식별자), `company`, `ledger`, `accounting_date`, `memo` 열이 필요합니다.

2. `journal_id`당 하나 이상의 행으로 구성된 **라인 테이블**을 만듭니다. `ledger_account`, `debit`, `credit` 열과 분개에 필요한 worktag(코스트 센터, 프로젝트) 열이 필요합니다.

3. **Workday Financials: Post Journal Entry** 단계를 추가하고 **Workday 연결**, **헤더 테이블**, **라인 테이블**, **결과 테이블**을 설정합니다.

4. **Validate Only**를 선택한 상태로 두고 단계를 실행합니다. PlaidCloud는 원장 클레임 없이, 아무것도 전기하지 않은 채 모든 분개를 구성하고 검사합니다.

5. 결과 테이블(분개당 한 행: `journal_id`, `natural_key`, `confirmation_id`, `status`, `message`)을 검토합니다. `error` 행이 있으면 수정한 후 다시 검증합니다.

6. **Validate Only** 선택을 해제하고 다시 실행하여 실제로 전기합니다. 첫 번째 분개가 실패했을 때 배치를 즉시 중단하려는 경우가 아니라면 **오류 발생 시 계속**을 선택한 상태로 두십시오.

</Steps>

### 전기 방식

PlaidCloud는 각 분개에 대해 `Submit_Accounting_Journal`을 호출합니다. Workday 자체의 비즈니스 프로세스 승인 체인이 제출된 분개를 실제 전기 전에 보류할 수 있으므로, 분개의 비즈니스 프로세스 상태가 최종 상태에 도달할 때까지 폴링합니다. 최종 상태가 **확인된** 후에만 분개가 `posted`로 보고됩니다. 제출되었지만 승인 단계에서 멈춘 분개는 전기된 것으로 기록되지 않고 격리 상태로 유지되므로, 보류 중인 승인이 조용히 성공으로 처리되는 일은 없습니다. PlaidCloud 자체의 원장 클레임은 배치를 재시도하거나 다시 실행할 때 같은 분개가 두 번 제출되는 것을 방지합니다.

### 전기된 분개 수정

이 단계는 전기된 분개를 삭제하거나 다시 쓰지 않습니다. 분개를 수정하려면 원본을 직접 편집하는 대신, 원본과 차변 및 대변을 맞바꾼 새 분개, 즉 **전기된 역분개**를 전기하십시오. 이렇게 하면 Workday 자체의 감사 추적이 보존되며, 애플리케이션에서 직접 수정하는 방식과 일치합니다.

### 기능 제한 - 실제 전기 전에 읽어 보십시오

<Aside type="caution">
- **가져오기는 전적으로 사용자가 만든 RaaS 보고서에 따라 달라집니다.** PlaidCloud에는 기본 제공 Workday Financials 엔터티가 없습니다. 보고서의 필드, 프롬프트, 액세스 제어는 이 커넥터가 아니라 모두 Workday에서 정의됩니다. Workday에서 보고서를 변경하면 PlaidCloud 쪽에서 아무것도 바꾸지 않아도 가져오기의 구조가 달라질 수 있습니다.
- **비즈니스 프로세스 승인으로 지연이 발생합니다.** Submit Accounting Journal 비즈니스 프로세스가 승인 단계를 거치도록 구성되어 있으면, 전기된 분개는 Workday에서 누군가 승인할 때까지 `pending` 상태로 남아 있을 수 있습니다. 최종 상태 폴링이 이를 기다리므로, 전기는 승인 체인이 없는 ERP 호출보다 훨씬 오래 걸릴 수 있습니다.
- **이 커넥터는 일반 [Workday REST 커넥터](/ko/reference/connectors/rest/workday/)와 별개입니다.** 해당 커넥터는 Workday의 REST API(HR/급여)를 대상으로 합니다. Workday Financials에 연결하지 않는 경우에만 사용하십시오.
</Aside>
