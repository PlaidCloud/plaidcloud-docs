SuiteQL을 작성하지 않고도 기본 제공 NetSuite 가져오기 단계로 일반적인 NetSuite 재무 및 참조 데이터를 프로젝트 테이블로 가져옵니다. 대부분의 가져오기는 세 단계로 처리됩니다. 시산표용 **잔액 가져오기**, 시산표의 근거가 되는 전기 수준 라인용 **총계정원장 상세 가져오기**, 이러한 가져오기가 참조하는 계정, 자회사, 차원용 **마스터 데이터 가져오기**입니다. 각 단계는 OAuth 토큰을 갱신하고, 큰 결과를 페이지 단위로 읽고, 일시적인 오류를 재시도하는 공유 읽기 계층에서 실행되므로 전체 기간 또는 전체 자회사 가져오기도 빠짐없이 완료됩니다.

<Aside type="tip">
기본 제공 단계로 처리되지 않는 맞춤형 가져오기에는 [REST 요청 단계](/ko/guides/workflows/rest-request-step/)로 직접 SuiteQL을 작성하십시오. [NetSuite SuiteQL 쿼리 예제](/ko/guides/connections/netsuite-financial-queries/)를 참조하십시오. 이러한 일반적인 가져오기에는 아래의 기본 제공 단계가 더 간단합니다.
</Aside>

## 사전 요구 사항

- 읽으려는 레코드에 대한 보기 권한이 있는 작동하는 [NetSuite 연결](/ko/guides/connections/netsuite/).
- 단계를 추가할 워크플로.

## 시산표 가져오기

<Steps>

1. 워크플로에 **NetSuite: 잔액 가져오기** 단계를 추가합니다.

2. **NetSuite 연결**을 사용자의 연결로, **대상 테이블**을 잔액이 저장될 프로젝트 테이블로 설정합니다. 이 단계는 실행할 때마다 이 테이블을 전부 덮어씁니다.

3. **시작 날짜**와 **종료 날짜**를 원하는 기간으로 설정합니다. 각각 `YYYY-MM-DD` 형식이며 양쪽 모두 해당 날짜를 포함합니다. 한쪽을 비워 두면 해당 방향의 범위가 제한되지 않습니다.

4. 가져오기를 한 자회사로 제한하려면 **Subsidiary**를 NetSuite 내부 ID로 설정하고, 모든 자회사를 가져오려면 비워 둡니다. (ID가 아니라 이름을 가지고 있다면 [내부 ID 확인](#마스터-데이터로-내부-id-확인)을 참조하십시오.)

5. Multi-Book Accounting 계정에서는 **Accounting Book**을 비워 두면 **기본 장부만** 가져옵니다. 이는 표준 시산표에 맞는 올바른 기본값입니다. 장부 간 합계가 의도적으로 필요한 경우에만 `all`로 설정하거나, 특정 장부의 내부 ID로 설정하십시오.

6. 전체 계정과목표나 범위 내 모든 기간이 필요하지 않다면 **계정 번호**(정확한 총계정원장 계정) 또는 **Posting Period**(NetSuite 기간 내부 ID)로 범위를 더 좁히십시오.

7. 단계를 실행하고([워크플로에서 단일 단계 실행](/ko/guides/workflows/running-one-step-in-a-workflow/) 참조) 대상 테이블을 확인합니다.

</Steps>

<Aside type="caution">
**Multi-Book 계정은 기본 장부를 기본값으로 사용합니다.** 이 동작이 적용되기 전에는 Multi-Book Accounting 계정에서 필터 없이 가져오면 모든 장부가 합산되어 잔액이 조용히 N배로 계산되었습니다. 이제 **Accounting Book**을 비워 두면 표준 시산표가 기대하는 대로 기본 장부만 가져옵니다. 이전의 장부 간 합계에 의존하고 있었다면 **Accounting Book**을 `all`로 명시적으로 설정하십시오.
</Aside>

## 총계정원장 상세 가져오기

**NetSuite: 총계정원장 상세 가져오기** 단계는 연결, 대상 테이블, 날짜 범위, 자회사, 회계 장부, 계정 번호, 전기 기간을 동일한 방식으로 구성하지만, 기간 잔액이 아니라 거래 라인 상세를 반환합니다. 잔액의 근거가 되는 전기 내역으로 대사하거나, 드릴다운하거나, 상세 손익계산서를 다시 구성할 때 사용하십시오.

<Aside type="note">
날짜 범위를 필요한 슬라이스로 제한하십시오. 실행할 때마다 대상 테이블 전체가 교체되므로, 예약된 총계정원장 가져오기는 매번 전체 결과를 다시 추출합니다. 롤링 날짜 범위를 사용하면 전체 기록을 다시 읽지 않고 반복 가져오기를 빠르게 유지할 수 있습니다.
</Aside>

<Aside type="note">
NetSuite는 단일 SuiteQL 쿼리를 약 100,000행으로 제한합니다. **시작 날짜**와 **종료 날짜**를 모두 지정하면 PlaidCloud가 넓은 범위의 가져오기를 이 한도 아래의 더 작은 날짜 청크로 자동 분할하므로, 아무것도 하지 않아도 1년 전체 총계정원장 가져오기가 빠짐없이 완료됩니다. 한도를 넘을 만큼 큰 가져오기에서 둘 다 비워 두면 이제 결과가 조용히 잘리는 대신 날짜 범위를 추가하라는 메시지와 함께 실패합니다.
</Aside>

## 마스터 데이터로 내부 ID 확인

NetSuite의 자회사, 계정, 차원 필드는 이름이 아니라 내부 ID입니다. **NetSuite: 마스터 데이터 가져오기**로 해당 목록을 가져와 잔액이나 상세 데이터와 조인하면 읽기 쉬운 이름을 추가할 수 있습니다.

<Steps>

1. **NetSuite: 마스터 데이터 가져오기** 단계를 추가하고 **NetSuite 연결**과 **대상 테이블**을 설정합니다.

2. **레코드 유형**을 원하는 목록으로 설정합니다. **account**, **subsidiary**, **department**, **class**, **location**, **vendor**, **customer** 중에서 선택합니다.

3. 활성 레코드만 가져오려면 **Include Inactive**를 끈 상태로 두고, 비활성 레코드도 포함하려면 켭니다.

4. 단계를 실행한 후, 해당 테이블을 내부 ID를 기준으로 잔액 또는 총계정원장 상세와 조인하여 모든 행에 이름을 추가합니다.

</Steps>

## 가져오기 예약

지속적인 피드가 필요하면 [워크플로를 예약](/ko/get-started/tutorials/schedule-a-workflow/)하십시오. 각 단계는 대상 테이블 전체를 교체하므로, 예약된 실행은 항상 사용자가 지정한 기간에 대한 NetSuite의 현재 상태를 반영합니다.
