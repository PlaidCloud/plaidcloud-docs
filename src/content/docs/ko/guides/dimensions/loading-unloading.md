워크플로 작업에서 데이터를 로드하여 차원을 유지 관리할 수 있습니다. 또한 차원 데이터를 표 형식 데이터로 평면화하여 테이블에 저장할 수도 있습니다. 이는 보고 및 분석 데이터를 보강하는 데 유용한 경우가 많습니다.


## 차원 로드

차원은 계층형 데이터 구조를 나타내므로, 로드 과정에서 데이터의 관계가 전달되어야 합니다. PlaidCloud는 차원을 로드하기 위해 두 가지 데이터 구조를 지원합니다.
 * 상위-하위 - 데이터가 세로로 구성되며, *상위* 열과 *하위* 열이 구조 전체에서 각 하위 노드의 상위 노드를 정의합니다
 * 레벨 - 데이터가 가로로 구성되며, 각 열이 왼쪽에서 오른쪽으로 계층의 한 레벨을 나타냅니다

 구조 외에도 값, 별칭, 속성과 같은 다른 차원 정보를 로드 과정에 포함할 수 있습니다.

 레벨(평면) 로드는 로드가 만드는 모든 중간 노드가 받는 기본 통합을 사용하며, 리프 열을 지정할 수 있습니다. 리프 열을 지정하면 그 열이 행의 별칭, 속성, 값을 가질 노드를 결정하고, 그렇지 않으면 마지막으로 채워진 레벨이 리프가 됩니다.

 상위-하위 로드의 기본 통합 유형은 자체 통합이 비어 있거나 인식되지 않는 모든 행에 적용되므로, 테이블에 통합 열이 지정되어 있더라도 유효한 유형 중 하나여야 합니다. 로드가 대상으로 하는 계층의 이름은 로드가 매핑하는 열의 이름과 같아서는 안 됩니다. 그런 이름의 열은 각 행이 속한 계층으로 읽히므로, 둘 다 지정한 로드는 한쪽 해석을 따르고 다른 쪽을 무시하는 대신 거부됩니다.

 별칭, 속성 또는 값 로드는 아무것도 쓰기 전에 모든 행의 멤버를 확인합니다. 어떤 행이든 차원에 없는 멤버를 지정하면 로드가 실패하고 해당 이름을 보고하며, 해당 로드의 어떤 내용도 저장되지 않습니다. 구조를 먼저 로드하거나 누락된 멤버를 구조에 포함한 다음, 특성을 로드하십시오.

 자세한 내용은 [Dimension Load](/ko/reference/workflow-steps/dimensions/dimension-load) 워크플로 단계를 참조하십시오.


## 차원 언로드(내보내기)

차원을 테이블로 내보낼 때는 두 가지 구조 방식을 지원합니다.
 * 상위-하위 - 데이터가 세로로 구성되며, *상위* 열과 *하위* 열이 구조 전체에서 각 하위 노드의 상위 노드를 정의합니다
 * 레벨 - 데이터가 가로로 구성되며, 각 열이 왼쪽에서 오른쪽으로 계층의 한 레벨을 나타냅니다

속성과 값도 평면화된 표 형식 데이터에 포함할 수 있습니다.

 자세한 내용은 [Dimension Export](/ko/reference/workflow-steps/dimensions/dimension-export) 워크플로 단계를 참조하십시오.
