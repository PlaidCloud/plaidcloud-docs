**Cost to Serve** 템플릿은 고객별 서비스 제공 비용과 그 이후에 남는 마진을 보여 줍니다. [Common Finance Model](/ko/guides/projects/data-foundation/)을 기반으로 하므로 프로젝트에 데이터를 공급하는 모든 ERP에서 작동하며, **Enterprise Profitability**가 구축하는 모든 것을 포함합니다.

## 작동 방식

1. 영업비용을 엔터티, 기간, 그리고 비용이 기록된 부서별로 풀(pool)로 묶습니다.
2. 각 풀은 해당 부서에 대해 **활동 맵**이 지정한 활동과 드라이버를 적용받습니다.
3. 각 고객의 드라이버는 프로젝트의 청구된 판매 라인에서 가져옵니다.
4. 각 풀은 엔터티와 기간 내에서 드라이버를 기준으로 고객에게 나뉩니다.

해당 엔터티와 기간에 드라이버 값이 양수가 아닌 풀은 고객 없이 그대로 통과하므로, 배분 합계는 항상 풀과 일치합니다.

## 활동 맵

활동 맵은 `cts_activity_map` 테이블입니다. 직접 편집하는 테이블이며, 모델은 여기에 쓰지 않습니다. 각 행은 부서에 **활동**과 **드라이버**를 지정합니다.

| 열 | 내용 |
|---|---|
| `department` | 부서 코드이며, 나열되지 않은 모든 부서는 `*`입니다. |
| `activity` | 활동 이름입니다. 예: Warehousing. |
| `driver` | 해당 부서의 비용을 나눌 기준입니다(아래 참조). |

| 드라이버 | 비용을 나누는 기준 |
|---|---|
| `orders` | 고객별 주문 수(고유 송장 수)입니다. |
| `lines` | 송장 라인 수입니다. |
| `quantity` | 처리한 수량입니다. 반품도 처리되므로 그 크기만큼 계산됩니다. |
| `revenue` | 대변 전표를 상계한 순수익입니다. |

샘플 데이터에는 `SALES`, `SERVICE`, `OPS` 부서와 나머지를 위한 `*` 행이 포함되어 있습니다. 이를 사용자의 부서와 활동으로 변경한 다음 **Foundation** 탭에서 **Apply changes**를 클릭하십시오.

## 결과물

| 출력 | 내용 |
|---|---|
| `cts_by_customer` | 엔터티, 기간, 고객, 활동별 서비스 제공 비용과 고객의 수익, 매출원가, 매출총이익, 서비스 제공 비용 반영 후 순마진, 주문 수입니다. |
| `cts_per_order` | 주문당 서비스 제공 비용입니다. |
| `cts_tie_out` | 엔터티와 기간별로, 원장의 영업비용과 고객에게 배분된 비용을 대조한 결과입니다. 누락되거나 이중 계산된 것이 없으면 차이는 0입니다. |

어시스턴트와 대시보드용 지표: 엔터티, 고객 또는 활동별 **Cost to Serve**, **Net margin after CTS**, **Orders**, **CTS per order**. 활동이 `Unmapped`이거나 고객이 없는 비용은 어떤 활동이나 드라이버로도 배치할 수 없었던 영업비용입니다.

## 프로젝트 시작

<Steps>

1. Analyze에서 **프로젝트**를 열고 **새 프로젝트**를 클릭합니다.

2. **시작 기준**에서 **Cost to Serve (template)** 옵션을 선택합니다. 먼저 작업 예제를 보려면 **샘플 데이터로 시작**을 선택합니다.

3. ERP를 연결하고 **로드**를 실행합니다. [Data Foundation 시작하기](/ko/guides/projects/data-foundation-getting-started/)를 참조하십시오.

4. 부서에 맞게 활동 맵을 편집하고 **Apply changes**를 클릭합니다.

</Steps>

**작업 > Save as my template...** 메뉴를 사용하여 활동 맵을 프로젝트와 함께 저장합니다. [내 템플릿으로 저장](/ko/guides/projects/data-foundation/#내-템플릿으로-저장)을 참조하십시오.
