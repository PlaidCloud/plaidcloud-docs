PlaidCloud는 주소 표시줄을 열려 있는 항목과 일치하게 유지합니다. 워크플로, 테이블, 차원, 또는 대시보드, 문서, ID의 화면을 열면 URL이 해당 항목으로 연결되는 **딥 링크**가 됩니다. 이 URL을 복사하여 메시지나 티켓에 붙여넣으면 이를 여는 사람은 같은 화면으로 이동합니다.

## 링크 복사

1. 공유하려는 화면(프로젝트, 워크플로, 테이블, 차원, 데이터 편집기 또는 다른 앱의 화면)을 엽니다.
2. 브라우저의 주소 표시줄에서 전체 URL을 복사합니다.
3. 전달합니다.

별도의 "공유" 버튼은 없습니다. 주소 표시줄이 곧 링크입니다. 브라우저의 북마크 기능도 이러한 URL에서 작동하므로, 자주 돌아가는 화면은 다른 웹 페이지처럼 북마크할 수 있습니다.

<Aside type="note">
링크에는 *위치*만 담겨 있을 뿐 이를 볼 수 있는 권한은 담겨 있지 않습니다. 링크를 여는 사람에게도 프로젝트에 대한 액세스 권한이 필요합니다. 권한이 없는 사람에게는 해당 개체가 표시되지 않습니다.

워크스페이스에 해당 앱이 포함되어 있지 않거나 권한이 부여되지 않아 사용할 수 없는 앱으로의 링크는 아무 반응이 없는 것처럼 보이는 대신, 링크를 사용할 수 없다는 안내와 함께 홈으로 이동합니다.
</Aside>

## 링크할 수 있는 대상

### Analyze

| 화면 | 링크 끝부분 |
|---|---|
| 프로젝트 | `#p~<project>` |
| 워크플로(단계 그리드) | `#p~<project>~w~<workflow>` |
| 워크플로(시각적 워크플로 디자이너 캔버스) | `#p~<project>~c~<workflow>` |
| 워크플로 내부의 단계 | `…~w~<workflow>~s~<step>` 또는 `…~c~<workflow>~s~<step>` |
| 단독 단계 | `#p~<project>~s~<step>` |
| 테이블 탐색기 | `#p~<project>~t~<table>` |
| 차원 계층 | `#p~<project>~d~<dimension>` |
| 데이터 편집기 | `#p~<project>~e~<editor>` |
| 홈 | `#home` |

링크의 프로젝트 부분은 프로젝트에 사용자 지정 스키마가 있으면 해당 **스키마**이므로, 링크가 16진수 문자열이 아니라 `#p~acme_budget~w~…`처럼 읽힙니다. 기본 스키마를 사용하는 프로젝트는 프로젝트 자체의 식별자를 대신 사용합니다. 두 형식 모두 같은 프로젝트를 열므로, 스키마를 설정한 후에도 이전 링크가 계속 작동합니다.

### 대시보드, 문서, ID

다른 앱의 화면은 직접 이름이 지정되므로 링크가 화면 자체로 읽힙니다.

| 앱 | 화면 | 링크 |
|---|---|---|
| 대시보드 | 대시보드 | `#dashboard.dashboards` |
| 대시보드 | 앱 | `#dashboard.panel_apps` |
| 대시보드 | 노트북 | `#dashboard.jupyterlite_deployments` |
| 문서 | 관리 | `#document.accounts` |
| 문서 | 내 계정 | `#document.your_accounts` |
| 문서 | 한 계정의 파일 찾아보기 | `#document.browser~…` |
| ID | 멤버 | `#identity.members` |
| ID | 디렉터리 | `#identity.member_directory` |
| ID | 배포 목록 | `#identity.distro.lists` |
| ID | 보안 그룹 | `#identity.security_groups` |
| ID | 그룹 감사 | `#identity.security_group_audit` |
| ID | 모든 범위 | `#identity.scopes` |
| ID | 세션 | `#identity.sessions` |
| ID | API 클라이언트 | `#identity.api_client_list` |
| ID | 보안 로그 | `#identity.security_log` |

일부 화면은 링크에 설정을 기억합니다. 멤버 및 멤버 디렉터리 목록은 각각 **모두**, **활성만**, **비활성만** 중 무엇을 보고 있었는지 유지하고, 계정 찾아보기는 어느 계정인지 유지하며, 브라우저는 이를 화면 이름 뒤의 인코딩된 접미사로 표시합니다. 전체 URL을 복사하여 붙여넣으면 보고 있던 화면이 열립니다. 해당 화면이 이미 열려 있을 때 링크를 열면 창이 하나 더 쌓이는 대신 해당 창이 앞으로 나옵니다.

<Aside type="note">
이러한 링크는 화면 안의 레코드가 아니라 화면을 가리킵니다. 멤버 링크는 멤버 목록을 열 뿐이며 특정 멤버의 양식을 열지는 않습니다.
</Aside>

## 다른 사람이 링크를 열면 일어나는 일

- **소유 프로젝트도 함께 열립니다.** 워크플로, 테이블, 단계, 차원 또는 데이터 편집기로의 링크는 해당 프로젝트도 화면 하단의 탭으로 열므로, 받는 사람은 홀로 떠 있는 창 하나가 아니라 주변 맥락과 함께 도착합니다.
- **단계 링크는 단계를 선택합니다.** 워크플로 내부의 단계로 연결되는 링크는 워크플로를 열고 해당 단계를 강조 표시합니다. 시각적 워크플로 디자이너 캔버스에서는 단계의 노드가 선택됩니다.
- **차원은 편집할 준비가 된 상태로 열립니다.** 프로젝트가 잠겨 있지 않을 때 그렇고, 잠겨 있으면 읽기 전용으로 열립니다. 프로젝트에서 열 때 적용되는 규칙과 같습니다.
- **새로 고침해도 현재 위치가 유지됩니다.** 페이지를 다시 로드하면 처음으로 돌아가는 대신 링크가 가리키는 항목이 다시 열립니다.

## 화면 간 이동

URL은 보고 있는 항목을 따라갑니다.

- 화면을 열면 주소 표시줄이 업데이트되며, 브라우저의 **뒤로** 버튼을 누르면 이전 화면으로 돌아갑니다.
- **어떤 경로로 이동했든 마찬가지입니다.** 활동 스트림, 홈 카드, **워크플로로 드릴** 작업, "사용 위치" 목록 또는 로그에서 워크플로를 열면 프로젝트의 워크플로 목록에서 열 때와 마찬가지로 링크가 업데이트되며, 이미 열려 있는 화면을 다시 열 때도 그렇습니다.
- 화면 하단에서 창의 탭을 선택하면 해당 창의 링크가 주소 표시줄에 다시 표시되므로, 열려 있는 화면 사이를 전환해도 URL이 정확하게 유지됩니다.
- 링크할 수 있는 항목이 열려 있지 않은 앱으로 전환하면 방금 떠난 앱을 가리키는 채로 두는 대신 링크를 **지웁니다**.
- 창을 닫으면 URL이 창을 열었던 위치로 되돌아갑니다. 워크플로 캔버스에서 연 테이블을 닫으면 URL이 해당 캔버스로 돌아가고, 프로젝트에서 연 테이블을 닫으면 프로젝트로 돌아갑니다.
- 프로젝트의 마지막 창을 닫으면 링크가 지워집니다.

## 이번 변경 이전에 저장된 링크

이전 `#te?p=…&t=…` 형식의 링크도 계속 작동합니다. 이를 열면 같은 위치로 이동하며 주소 표시줄이 현재 형식으로 자동으로 다시 작성되므로, 거기에서 다시 복사하면 더 읽기 쉬운 최신 링크를 얻을 수 있습니다.
