PlaidCloud는 주소 표시줄을 사용자가 열어 둔 화면과 일치시킵니다. 워크플로, 테이블, 차원 또는 Dashboards, Documents, Identity의 화면을 열면 URL이 해당 화면의 **딥 링크**가 됩니다. 이 URL을 복사하여 메시지나 티켓에 붙여 넣으면, 링크를 여는 사람은 같은 화면으로 이동합니다.

## 링크 복사

1. 공유하려는 화면(프로젝트, 워크플로, 테이블, 차원, 데이터 편집기 또는 다른 앱의 화면)을 엽니다.
2. 브라우저 주소 표시줄에서 URL 전체를 복사합니다.
3. 전달합니다.

별도의 "공유" 버튼은 없으며 주소 표시줄이 곧 링크입니다. 브라우저의 북마크 기능도 이러한 URL에서 작동하므로, 자주 돌아가는 화면은 다른 웹 페이지처럼 북마크할 수 있습니다.

<Aside type="note">
링크는 *위치*만 담고 있을 뿐 이를 볼 수 있는 권한은 담고 있지 않습니다. 링크를 여는 사람도 프로젝트에 대한 액세스 권한이 있어야 합니다. 권한이 없는 사용자에게는 개체가 표시되지 않습니다.

워크스페이스에 포함되지 않았거나 권한이 부여되지 않아 사용할 수 없는 앱으로의 링크는 아무 반응이 없는 것처럼 보이지 않고, 링크를 사용할 수 없다는 안내와 함께 홈으로 이동합니다.
</Aside>

## 링크할 수 있는 대상

### Analyze

| 화면 | 링크 끝부분 |
|---|---|
| 프로젝트 | `#p~<project>` |
| 워크플로(단계 그리드) | `#p~<project>~w~<workflow>` |
| 워크플로(시각적 워크플로 디자이너 캔버스) | `#p~<project>~c~<workflow>` |
| 워크플로 내부의 단계 | `…~w~<workflow>~s~<step>` 또는 `…~c~<workflow>~s~<step>` |
| 단독 단계 | `#p~<project>~s~<step>` |
| 테이블 탐색기 | `#p~<project>~t~<table>` |
| 차원 계층 | `#p~<project>~d~<dimension>` |
| 데이터 편집기 | `#p~<project>~e~<editor>` |
| 홈 | `#home` |

링크의 프로젝트 부분은 프로젝트에 사용자 지정 **스키마**가 있으면 그 스키마를 사용하므로, 링크가 16진수 문자열이 아니라 `#p~acme_budget~w~…`처럼 읽힙니다. 기본 스키마를 유지한 프로젝트는 프로젝트 자체의 식별자를 사용합니다. 두 형식 모두 같은 프로젝트를 열므로, 스키마를 설정한 후에도 이전 링크가 계속 작동합니다.

### Dashboards, Documents, Identity

다른 앱의 화면은 이름으로 직접 지정되므로 링크가 화면 자체처럼 읽힙니다.

| 앱 | 화면 | 링크 |
|---|---|---|
| Dashboards | 내 대시보드 | `#dashboard.dashboards` |
| Dashboards | 앱 | `#dashboard.panel_apps` |
| Dashboards | Jupyter Lite | `#dashboard.jupyterlite_deployments` |
| Documents | 모든 계정 | `#document.accounts` |
| Documents | 공유 계정 | `#document.shared_accounts` |
| Documents | 비공개 계정 | `#document.private_accounts` |
| Documents | 한 계정의 파일 찾아보기 | `#document.browser~…` |
| Identity | 멤버 | `#identity.members` |
| Identity | 멤버 디렉터리 | `#identity.member_directory` |
| Identity | 배포 목록 | `#identity.distro.lists` |
| Identity | 보안 그룹 | `#identity.security_groups` |
| Identity | 보안 그룹 감사 | `#identity.security_group_audit` |
| Identity | 범위 | `#identity.scopes` |
| Identity | 세션 | `#identity.sessions` |
| Identity | API 클라이언트 | `#identity.api_client_list` |
| Identity | 보안 로그 | `#identity.security_log` |

일부 화면은 링크에 설정을 기억합니다. 멤버 및 멤버 디렉터리 목록은 각각 **모두**, **활성만**, **비활성만** 중 무엇을 보고 있었는지 기억하고, 계정 찾아보기는 어느 계정인지 기억합니다. 브라우저에는 이것이 화면 이름 뒤의 인코딩된 접미사로 표시됩니다. URL 전체를 복사하여 붙여 넣으면 보던 화면이 열립니다. 해당 화면이 이미 열려 있을 때 링크를 열면 두 번째 창을 쌓지 않고 그 창을 앞으로 가져옵니다.

<Aside type="note">
이러한 링크는 화면 내부의 레코드가 아니라 화면을 가리킵니다. 멤버 링크는 멤버 목록을 열 뿐 특정 멤버의 양식을 열지 않습니다.
</Aside>

## 링크를 열면 일어나는 일

- **소유 프로젝트도 함께 열립니다.** 워크플로, 테이블, 단계, 차원 또는 데이터 편집기 링크는 해당 프로젝트도 화면 하단의 탭으로 열므로, 받는 사람은 창 하나만 덩그러니 떠 있는 것이 아니라 주변 맥락과 함께 도착합니다.
- **단계 링크는 단계를 선택합니다.** 워크플로 내부 단계로의 링크는 워크플로를 열고 해당 단계를 강조 표시합니다. 시각적 워크플로 디자이너 캔버스에서는 단계의 노드가 선택됩니다.
- **차원은 프로젝트의 잠금이 해제되어 있으면 편집할 수 있는 상태로** 열리고, 잠겨 있으면 읽기 전용으로 열립니다. 프로젝트에서 열 때와 같은 규칙입니다.
- **새로 고쳐도 현재 위치가 유지됩니다.** 페이지를 다시 로드하면 처음으로 돌아가지 않고 링크가 가리키는 항목이 다시 열립니다.

## 화면 간 이동

URL은 보고 있는 화면을 따라갑니다.

- 화면을 열면 주소 표시줄이 업데이트되며, 브라우저의 **뒤로** 버튼으로 이전 화면으로 돌아갑니다.
- **어떤 경로로 도착했든 동일합니다.** 활동 스트림, 홈 카드, **워크플로로 드릴** 작업, "사용 위치" 목록 또는 로그에서 워크플로를 열면 프로젝트의 워크플로 목록에서 열 때와 마찬가지로 링크가 업데이트되며, 이미 보고 있는 화면을 다시 열 때도 그렇습니다.
- 화면 하단에서 창의 탭을 선택하면 해당 창의 링크가 주소 표시줄에 다시 입력되므로, 열려 있는 화면 사이를 전환해도 URL이 정확하게 유지됩니다.
- 링크할 수 있는 항목이 열려 있지 않은 앱으로 전환하면, 방금 떠난 앱을 계속 가리키지 않고 링크를 **지웁니다**.
- 창을 닫으면 URL이 창을 연 위치로 돌아갑니다. 워크플로 캔버스에서 연 테이블을 닫으면 URL이 해당 캔버스로 돌아가고, 프로젝트에서 연 테이블을 닫으면 프로젝트로 돌아갑니다.
- 프로젝트의 마지막 창을 닫으면 링크가 지워집니다.

## 이 변경 전에 저장된 링크

이전 `#te?p=…&t=…` 형식의 링크도 계속 작동합니다. 링크를 열면 같은 위치로 이동하며 주소 표시줄이 조용히 현재 형식으로 다시 쓰이므로, 거기서 다시 복사하면 더 읽기 쉬운 새 링크를 얻을 수 있습니다.
