**이식 가능한 형식으로 내보내기**는 프로젝트의 워크플로를 PlaidCloud에 연결하지 않고 [DuckDB](https://duckdb.org)에서 실행되는 독립형 Python 프로그램으로 패키징합니다. 프로젝트의 로직과 데이터를 오프라인에서 단독으로 실행할 수 있는 이식 가능한 사본으로 만들어 줍니다.

단방향 내보내기입니다. 생성된 패키지는 특정 시점의 스냅샷이며 다시 동기화되지 않습니다. 변경 후 다시 내보내면 새 패키지가 만들어집니다.

<Aside type="caution" title="최선의 충실도">
내보내기는 SQL 기반 변환 단계를 정확하게 재현합니다. 배부, 차원 로드, 알림, 문서 및 보고서 단계, 스크립트와 같은 독점적이거나 부작용이 있는 작업은 **스텁**으로 내보내집니다. 원래 구성은 보존되고, 출력 테이블이 구체화된 경우에는 해당 데이터가 스냅샷으로 번들되지만, 단계 자체는 다시 실행되지 않습니다. 각 단계의 충실도는 패키지 안의 `COVERAGE.md`에 기록됩니다. 완전히 다시 계산된 결과가 보장되어야 한다면 PlaidCloud에서 프로젝트를 실행하십시오.
</Aside>

## 프로젝트 내보내기

1. **Analyze**를 열고 **프로젝트** 탭을 선택합니다.
2. 프로젝트를 하나 선택합니다.
3. **작업** 메뉴를 열거나(또는 프로젝트를 마우스 오른쪽 버튼으로 클릭하고) **이식 가능한 형식으로 내보내기**를 선택합니다. 이 항목은 **Export Project** 옆에 있습니다.
4. 대화 상자에서 다음을 설정합니다.
   - **문서 계정** — 패키지를 기록할 문서 계정입니다.
   - **폴더 경로** — 해당 계정 내의 폴더입니다(예: `/exports`).
   - **Include data** — 선택하면(기본값) 소스 및 스냅샷 테이블이 Parquet으로 번들되어 외부 데이터 없이 패키지를 실행할 수 있습니다. 선택을 해제하면 코드와 스키마 계약만 제공되며, 데이터는 직접 채워야 합니다.
5. **내보내기**를 클릭합니다. 완료되면 패키지가 기록된 위치와 스냅샷으로 저장된 테이블 수를 알려 주는 메시지가 표시됩니다.

이 작업에는 프로젝트에 대한 액세스 권한과 프로젝트의 테이블을 읽을 수 있는 권한이 필요합니다. 현재 테이블 데이터를 내보낼 때 필요한 것과 같은 수준의 액세스 권한입니다.

## 패키지 구성

내보내기는 다음을 포함하는 `.zip` 파일입니다.

- `pipeline_<workflow>.py` — 워크플로마다 하나씩 있는 스크립트로, 단계가 실행 순서대로 들어 있습니다.
- `config.py` — 엔진 선택(기본값은 DuckDB)과 프로젝트 스키마 이름입니다.
- `_runtime.py` — 작은 엔진 shim으로, DuckDB 외에 유일한 종속성입니다.
- `stubs.py` — 이식할 수 없는 작업을 위한 no-op 함수로, 각각 원래 단계 구성을 담고 있습니다.
- `data/` — 소스 테이블과 고정된 테이블의 Parquet 스냅샷입니다(**Include data**를 선택한 경우).
- `requirements.txt` — Python 종속성입니다(`duckdb`뿐).
- `README.md`, `COVERAGE.md`, `RUN_ORDER.md` — 각각 실행 방법, 단계별 충실도, 워크플로 스크립트를 실행할 순서입니다.

## 패키지 실행

1. 패키지의 압축을 풀고 Python 환경을 만듭니다.

   ```bash
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. `RUN_ORDER.md`에 나열된 순서대로 각 워크플로 스크립트를 실행합니다.

   ```bash
   python pipeline_<workflow>.py
   ```

각 스크립트는 로컬 DuckDB 데이터베이스(기본값 `export.duckdb`)에 테이블을 빌드합니다. SQL 변환 단계는 실시간으로 다시 계산되고, 스텁 처리된 단계는 알림을 출력하고 스냅샷으로 저장된 출력을 그대로 둡니다. DuckDB 대신 자체 웨어하우스를 사용하도록 패키지를 지정하려면 `config.py`에서 `ENGINE`을 설정하십시오.
