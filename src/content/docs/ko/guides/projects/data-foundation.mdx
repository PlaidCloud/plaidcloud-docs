**Data Foundation**은 PlaidCloud 프로젝트의 재무 데이터 기반입니다. **Common Finance Model**은 여러 ERP 시스템과 각 시스템의 여러 인스턴스에서 가져온 ERP 데이터를 하나의 계정과목표, 하나의 엔터티 집합, 하나의 보고 통화를 갖춘 단일 모델로 통합합니다. 이 모델을 기반으로 만든 보고서, 지표, AI 어시스턴트는 데이터가 어느 ERP에서 왔든 모두 같은 숫자를 읽습니다.

ERP는 PlaidCloud 연결을 통해 연결되므로 총계정원장, 시산표, 마스터 데이터, 예산이 내보내기 작업 없이 소스에서 직접 들어옵니다. 파일은 환율, 배부 동인, ERP 외부에서 관리하는 예산처럼 시스템에 없는 데이터를 추가하며, 해당 파일이 다루는 ERP 행을 대체할 수도 있습니다. **로드**는 프로젝트의 **Foundation** 탭에서 모든 소스를 모델에 맞게 표준화하고, 보고 통화로 환산하고, 금액이 일치하는지 검사합니다. 소스마다 같은 코드를 서로 다른 대상에 사용하는 경우 같은 의미인지 지정할 수 있으며, 관리 통합은 내부 거래를 제거한 그룹 손익계산서를 작성합니다. **Enterprise Profitability** 같은 템플릿은 이 모델 위에 보고서와 모델을 구축합니다.

## ERP 연결

ERP는 PlaidCloud 연결을 통해 Data Foundation에 연결됩니다. Data Foundation은 이 연결에서 총계정원장, 시산표, 마스터 데이터, 환율, 예산을 직접 읽으며, 읽기만 수행합니다. 기존 연결을 선택하거나 탭에서 새 연결을 만들 수 있습니다. 시스템마다 액세스 권한을 부여하는 관리자를 위한 페이지가 있으며 [모델에 데이터를 공급할 수 있는 시스템](/ko/guides/projects/data-foundation-getting-started/#모델에-데이터를-제공할-수-있는-시스템)에 나열되어 있습니다. 각 시스템이 직접 공급하는 데이터 세트는 [Data Foundation 지원 범위 매트릭스](/ko/reference/data-foundation-coverage-matrix/)에서 확인할 수 있습니다.

<Steps>

1. Analyze에서 **프로젝트**를 열고 **새 프로젝트**를 클릭합니다. 이름을 입력하고 **시작 기준**에서 **빈 프로젝트** 대신 **Enterprise Profitability (템플릿)** 같은 템플릿을 선택합니다. **만들기**를 클릭합니다.

   프로젝트가 **Foundation** 탭에서 열립니다. 공유하기 전까지 프로젝트는 본인만 사용할 수 있으며 본인이 유일한 아키텍트입니다.

2. **Foundation** 탭에서 **소스**를 열고 **Connect a system**에서 해당 타일을 눌러 시스템 종류를 선택합니다. 그런 다음 해당 시스템의 기존 연결을 선택하거나 **새 연결 만들기**를 선택합니다. 각 기존 연결에는 이미 해당 연결을 사용하는 워크플로가 나열되거나 **아직 어떤 워크플로에서도 사용되지 않음**이 표시되며, 이미 소스로 사용 중인 연결은 **already a source**로 표시되어 다시 선택할 수 없습니다.

3. 새 연결의 경우 **연결 이름**을 입력하고 **환경**을 선택한 다음 ERP 연결에서 요구하는 자격 증명을 입력합니다.

   아직 자격 증명이 없습니까? 양식에 ERP 관리자에게 보낼 수 있는 액세스 요청이 미리 작성되어 있습니다. **요청 복사** 또는 **이메일 요청**을 클릭하여 요청을 보내고, 관리자가 회신한 값을 입력합니다.

4. **연결 테스트**를 클릭합니다. PlaidCloud가 로그인하여 각 데이터 세트를 읽어 본 다음, 각각을 **읽기 가능**, **권한 누락** 또는 **오류**로 표시합니다. 누락된 항목이 있으면 ERP 관리자에게 추가를 요청해야 할 권한을 알려 줍니다.

5. **이력 개월 수**를 설정합니다. 몇 개월 전까지 로드할지를 1에서 120 사이로 지정합니다. 기본값은 24입니다.

6. 기존 연결의 경우 로드할 엔터티를 선택하거나, 모든 엔터티를 로드하려면 모두 선택 해제한 상태로 둡니다. 비활성 엔터티와 제거 엔터티는 표시하도록 선택하기 전까지 숨겨집니다. 그런 다음 **연결**을 클릭합니다.

7. 새 연결의 경우 **연결**을 클릭하여 연결을 만듭니다. 그런 다음 로드할 엔터티를 선택하고 **연결**을 다시 클릭하여 저장합니다. 저장하기 전까지는 모든 엔터티가 로드됩니다.

8. 다른 ERP 시스템이나 다른 인스턴스를 가져오려면 **Connect another system**을 열고 이 단계를 반복합니다. 연결하면 항상 소스가 추가되고 기존 소스는 그대로 유지되므로, 여러 ERP 시스템과 인스턴스가 하나의 통합 모델에 데이터를 공급할 수 있습니다.

</Steps>

연결되면 카드에 프로젝트가 로드하는 연결, 환경, 엔터티, 이력 개월 수가 표시됩니다.

각 로드는 변경된 내용만 읽습니다. 미마감 기간과 마지막 마감된 기간은 다시 읽고, 이미 로드된 마감된 기간은 그대로 유지합니다. **이력 개월 수**를 늘리면 추가된 개월만 읽습니다. 환율, 엔터티 매핑표 또는 보고 통화가 변경되면 영향을 받는 개월을 다시 읽습니다.

## 소스

프로젝트가 데이터를 로드하는 모든 ERP 시스템과 인스턴스는 소스입니다. **Foundation** 탭의 **소스** 페이지에 있는 **Load order** 목록에는 소스마다 한 줄씩 순서대로 표시되며, 각 줄에는 이름과 시스템, **회사**, **마지막 로드 시각**, **행**, **상태**가 나타납니다. **회사**에는 **모두** 또는 선택된 회사 수가 표시됩니다. 아직 로드되지 않은 소스에는 **아직 로드되지 않음**이 표시됩니다. 확정한 파일도 소스입니다.

소스에서 **편집**을 클릭하여 소스의 사용 방식을 변경합니다.

| 설정 | 기능 |
|---|---|
| **이름** | 보고서, 매핑 질문, 메시지에서 소스를 가리키는 레이블입니다. |
| **순서상 위치** | 소스의 우선순위입니다. 두 소스가 같은 회사의 같은 월을 다루면 순서가 더 높은 소스가 우선합니다. |
| **보고 장부(쉼표로 구분)** | 장부를 둘 이상 관리하는 시스템에서 읽을 회계 장부입니다. **모든 보고 장부**는 모든 장부를 읽습니다. |
| **회사** | 시스템 소스에서 해당 소스가 로드하는 회사(자회사)입니다. 이 목록은 패널을 처음 열 때 시스템에서 읽어 오며, 현재 소스가 로드하는 회사를 보여 줍니다. 로드할 회사를 선택하거나, 모든 회사를 로드하려면 아무것도 선택하지 않습니다. 시스템이 회사 목록을 제공하지 않으면 회사 이름을 쉼표로 구분하여 입력합니다. |
| **회사**, **시작 (2026-01)** 및 **종료 (2026-12)** | 이 소스가 각 회사에 제공하는 월입니다. 제한하지 않으려면 월을 비워 둡니다. 월은 연도와 월로 작성합니다. 예: `2026-03` |

변경 내용을 유지하려면 **저장**을 클릭합니다. 회사를 추가하거나 아무것도 선택하지 않으면 바로 저장됩니다. 회사를 제외하면 먼저 **Load fewer companies?** 확인을 요청합니다. 저장하는 즉시 해당 소스에서 로드된 모든 데이터가 지워지고, 다음 **로드**에서 선택한 회사의 데이터를 다시 가져오기 때문입니다. 소스의 연결이 소스를 설정할 때와 다른 계정을 읽게 되면 저장이 거부되고 그 사실을 알리는 메시지가 표시되므로, 변경으로 인해 다른 소스가 대체되는 일은 없습니다. 이 경우 해당 계정을 별도의 소스로 다시 연결하십시오. 소스를 삭제하려면 **Remove this source**를 클릭하고 **제거**로 확인합니다. 해당 소스에서 로드된 모든 데이터가 삭제되며, 나중에 다시 연결할 수 있습니다.

소스를 변경해도 ERP를 다시 읽지는 않습니다. **Apply changes**를 클릭할 때까지 모든 페이지 위에 **You have changed your sources. Press Apply changes to use them.** 표시줄이 나타납니다. 이 버튼은 이미 가져온 데이터로 로드를 실행합니다. 즉, 새 순서, 매핑, 이름, 파일로 소스를 다시 표준화하고 모델을 다시 작성합니다. ERP에서 최신 데이터도 가져오려면 **로드**를 클릭합니다.

## ERP 외부 데이터용 파일 추가

파일은 환율, 배부 동인, [엔터티 매핑표](#엔터티-매핑표), ERP 외부에서 관리하는 예산처럼 시스템에 없는 데이터로 ERP 연결을 보완합니다. 각 파일은 [Common Finance Model 테이블](#common-finance-model-테이블)에 나열된 데이터 세트 중 하나에 속합니다.

<Steps>

1. **파일**에서 파일을 저장할 **문서 계정**을 선택합니다.

2. CSV 또는 Excel 파일을 **CSV 또는 Excel 파일을 여기에 놓으십시오** 영역에 끌어다 놓거나 **파일 선택**을 클릭합니다. 파일은 문서 계정의 `/foundation/` 폴더에 업로드됩니다.

   이미 문서 계정에 있는 파일의 경우 **파일 경로**(예: `/foundation/budget.csv`)를 입력하고 **파일 추가**를 클릭합니다.

   매월 새 파일을 읽으려면 폴더에서 이름이 일치하는 모든 파일을 추가합니다. 폴더와, **File names that** 조건(포함, 시작, 끝, 정확히 일치, 패턴 일치)을 입력하고 **Add files**를 클릭합니다. 하위 폴더에 있는 파일은 읽지 않습니다.

3. PlaidCloud가 파일을 읽고 매핑을 제안합니다.

   - **구분 기호, 소수점 구분 기호, 날짜 감지.** 구분 기호(쉼표, 세미콜론, 탭 또는 파이프), 소수점 구분 기호, 날짜 형식이 자동으로 감지됩니다.
   - **데이터 세트**: 파일 이름과 열 머리글을 기준으로 일치시킨, 파일이 속하는 Common Finance Model 테이블입니다. 일치 여부가 명확하지 않으면 목록에서 선택합니다.
   - **소수점 구분 기호**: **마침표 (1,234.56)** 또는 **쉼표 (1.234,56)**.
   - **날짜 형식**: 파일에 날짜가 있을 때 표시됩니다. 감지된 형식이 잘못되었으면 `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` 또는 `MM/DD/YYYY` 중에서 변경합니다.
   - **파일의 열**, **유형**, **예제**, **이동 위치**로 구성된 그리드입니다. 열을 다른 필드로 보내려면 **이동 위치**를 변경하고, 로드하지 않으려면 **로드 안 함**으로 변경합니다.

4. **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?**, **Are revenues shown as negative numbers?** 같이 파일과 관련된 질문에 답합니다. 각 질문은 파일에 해당 정보가 아직 없을 때만 표시됩니다.

5. 각 열이 어디로 이동하는지 확인한 다음 **매핑 확정**을 클릭합니다. 처리하는 동안 버튼 아래의 메모에 대기 중인 이유가 표시됩니다. 아직 샘플 데이터가 있는 프로젝트에서는 처음 확정하는 파일이 샘플도 제거하며, 이 작업은 몇 분 정도 걸릴 수 있습니다.

</Steps>

다음 옵션은 해당되는 경우 파일에 표시됩니다.

| 옵션 | 용도 |
|---|---|
| **Which source do these rows apply to?** | 코드 맵 파일을 하나의 소스로 제한합니다. **Every source**는 모든 소스에 적용합니다. |
| **Where does this file come from?** | 파일에 **This project's own codes**가 있는지, 아니면 이름을 지정한 **Another system**(예: `SAP Germany export`)에서 온 것인지 지정합니다. 다른 시스템에서 온 파일은 ERP 소스와 마찬가지로 공유 코드를 검사합니다. |
| **Split … into … parts at each …**(**고급** 아래) | `100-200-300`처럼 여러 값이 들어 있는 하나의 열을 분할하여 각 부분을 별도 필드로 보냅니다. |
| **Which currency do you report in?** | 프로젝트에 아직 보고 통화가 없을 때 보고 통화를 설정합니다. 세 글자로 작성합니다. 예: `USD` |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 그룹 손익계산서를 [대사](#통합-시스템과-대사)할 수 있도록 통합 시스템의 결과를 로드합니다. |

프로젝트에서 파일을 빼려면 **파일** 아래에서 파일 옆의 **제거**를 클릭하거나 매핑에서 **Remove this file**을 클릭하고 확인합니다. 다음에 **Apply changes**를 클릭하면 해당 파일의 수치가 보고서에서 제외됩니다.

예를 들어 날짜를 일/월 또는 월/일로 모두 읽을 수 있는 파일처럼 PlaidCloud가 데이터 세트, 소수점 구분 기호 또는 날짜 순서를 스스로 결정할 수 없으면 확정하기 전에 선택하라는 메시지가 표시됩니다. 같은 데이터 세트에 두 번째 파일을 추가하면 첫 번째 파일이 대체됩니다. 이후 파일의 열이 데이터 세트와 일치하지 않으면 로드에서 파일과 열 이름을 알려 주고 파일이나 열 이름을 수정하거나 단계의 **Schema Mismatch**를 `union`으로 설정하라고 안내합니다.

허용되는 파일은 CSV, TSV, TXT 텍스트 파일, Excel `.xlsx` 파일(첫 번째 시트를 읽음), Parquet 파일입니다.

<Aside type="note">
파일이 없거나 비어 있어도 로드가 중단되지 않습니다. 이런 파일을 추가하면 아직 매핑할 내용이 없다고 표시되며, 로드는 경로를 알려 주는 경고와 함께 완료되고 해당 데이터 세트는 비어 있는 상태로 남습니다. 파일이 생기면 다시 추가합니다.
</Aside>

## 데이터 로드

**상태**에서 **로드**를 클릭합니다. 로드는 연결된 ERP와 확정된 파일을 읽어 Common Finance Model에 맞게 표준화하고, 보고 통화로 환산하고, 준비 상태 검사를 실행하고, 템플릿의 모델을 다시 작성합니다.

- 프로젝트당 한 번에 하나의 로드만 실행됩니다. 두 번째 **로드** 또는 **Apply changes**를 실행하면 이미 로드가 실행 중이라는 메시지가 표시되며, 로드가 실행되는 동안에는 소스를 변경할 수 없습니다.
- 다른 워크플로가 같은 ERP 연결을 사용하는 경우, 로드가 ERP에서 데이터를 읽으면서 해당 워크플로의 속도를 늦출 수 있으므로 첫 번째 로드에서 해당 워크플로를 나열하고 확인을 요청합니다. 계속하려면 **그래도 로드**를 클릭합니다.
- PlaidCloud가 업그레이드된 후 아키텍트가 **로드**를 실행하면 프로젝트에서 생성된 워크플로도 업데이트되며, 워크플로에 필요한 작업 테이블이 만들어집니다. 그 전까지 상태 페이지에는 "The workflows were generated by an earlier release. An Architect's Load updates them."이라는 주황색 항목이 표시되며, 관리자가 **로드**를 실행하면 아키텍트만 업데이트할 수 있다는 경고가 표시됩니다.
- 업데이트를 적용해도 생성된 단계에 직접 수정한 내용은 유지됩니다. 사용자가 변경한 단계를 업데이트에서도 변경한 경우 사용자의 수정 내용이 유지되며, 상태 페이지에 단계 이름과 함께 충돌이 기록됩니다. 사용자가 수정한 단계를 업데이트에서 더 이상 생성하지 않으면 해당 단계는 유지되지만 비활성화됩니다. 단계를 삭제하거나, 계속 필요하면 다시 활성화합니다. 업데이트로 대체되는 단계는 이름이 표시되며, 이전 단계는 단계 버전에 남아 있습니다.
- 업데이트가 중간에 중단되었거나 아직 실행 중이면 상태 페이지에 그 사실이 표시되며, 업데이트가 완료될 때까지 단계가 순서 없이 실행될 수 있습니다. 업데이트를 완료하려면 아키텍트로서 **로드**를 다시 누릅니다. 다시 중단되면 지원팀에 문의하십시오.
- 실패한 로드는 빨간색으로 표시되며 이전 결과 뒤에 가려지지 않습니다. 통합이 실패하면 상태에 이전 그룹 결과 대신 중단된 단계의 이름이 표시됩니다. 이전 로드의 행에는 로드가 성공할 때까지 **이전 로드의 결과입니다. 다시 로드하십시오.** 메시지가 표시됩니다.
- 하나의 엔터티와 기간을 읽지 못해도 나머지는 계속 로드됩니다. 실패한 항목만 가져오려면 **로드**를 다시 실행합니다.

### 보류된 행

소스가 겹치면 로드는 각 수치를 한 번만 유지하고, 나머지는 이중으로 집계하지 않도록 보류합니다. 보류된 행은 소스, 엔터티, 사유와 함께 기록되며, 로드는 건수를 알려 주는 경고와 함께 완료됩니다. 예: `120 rows of NetSuite EU also provided by a source ranked ahead`. 사유는 다음과 같습니다.

| 사유 | 의미 |
|---|---|
| 다른 회계 장부에 있음 | 행이 소스에서 읽도록 설정되지 않은 보고 장부에 속합니다. |
| 소스가 제공하는 기간을 벗어남 | 행이 회사에 설정된 **시작** 및 **종료** 월을 벗어납니다. |
| 순서가 앞선 소스에서도 제공됨 | 순서가 더 높은 소스가 같은 회사와 월을 다룹니다. |
| 소스의 이전 파일에도 있음 | 같은 소스의 이전 파일이 이미 해당 월을 다룹니다. |
| 파일로 대체됨 | 파일이 해당 엔터티와 월의 ERP 행을 대체합니다. |
| 다른 소스도 사용하는 코드를 포함함 | 코드에 대한 답변이 필요합니다. [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오. |
| 두 코드에 매핑된 코드를 포함함 | 코드 맵이 해당 코드에 두 가지 답을 지정합니다. |

통계 계정은 원장 대신 배부 동인으로 이동하며, 문제가 아닌 이동된 항목으로 표시됩니다.

### ERP 데이터와 파일 함께 사용

파일은 파일이 다루는 범위만 대체하며, ERP의 나머지 행은 그대로 유지됩니다.

- **마스터 파일**(계정, 부서, 고객, 제품, 세그먼트 값)은 같은 코드를 가진 ERP 행을 대체합니다.
- **트랜잭션 파일**은 같은 엔터티와 월의 ERP 행을 대체합니다. 총계정원장 및 시산표 파일은 원장으로도 일치시키고, 예산 파일은 시나리오로, 통계 동인 파일은 시나리오와 동인으로 일치시킵니다.

나중에 파일이 특정 월을 더 이상 다루지 않으면 다음 로드에서 해당 월의 ERP 데이터가 다시 반영됩니다.

## 엔터티 매핑표

각 소스는 자체 코드로 엔터티 이름을 지정합니다. **엔터티 매핑표**는 이러한 코드를 엔터티 마스터의 엔터티에 매핑하므로 모든 소스의 라인이 같은 엔터티에 반영됩니다.

엔터티 매핑표를 사용하려면 CSV 또는 Excel 파일을 추가하고 **엔터티 매핑표** 데이터 세트를 선택합니다.

| 열 | 내용 |
|---|---|
| `source_entity` | 소스에 기록된 코드(예: 회사 코드)입니다. |
| `entity` | 코드가 속하는 엔터티로, 엔터티 마스터에 지정된 이름입니다. |

- 매핑표에 없는 코드는 그대로 사용됩니다.
- 여러 코드를 하나의 엔터티에 매핑할 수 있습니다. 해당 라인은 합쳐지며, 모든 코드에서 마감된 월만 마감된 것으로 간주됩니다.
- 매핑표의 코드는 모든 소스에 적용되므로 각 소스의 엔터티 코드는 소스 간에 고유해야 합니다.
- **엔터티** 파일 행은 같은 엔터티 코드를 가진 ERP 엔터티를 대체합니다.

**매핑되지 않은 엔터티** 검사는 엔터티가 엔터티 마스터에 없고 매핑표로 매핑되지도 않은 라인을 표시합니다. 엔터티 마스터가 로드되기 전까지는 **– 해당 없음**이 표시됩니다.

## 소스 간 코드 매핑

두 소스가 같은 코드를 서로 다른 대상에 사용하거나, 서로 다른 코드를 같은 대상에 사용할 수 있습니다. 코드가 둘 이상의 소스에 나타나면 Data Foundation은 각 금액이 한 번만 집계되도록 그 코드가 모든 곳에서 같은 의미인지 지정할 때까지 해당 행을 보류합니다. **Codes waiting for your answer** 검사는 처음 10개 코드를 나열한 다음 "and K more"를 표시하며, **상태**의 **What to do next** 목록에서 **Answer codes ›** 버튼을 클릭하면 해당 코드가 열립니다.

**Answer codes ›** 버튼을 클릭하면 **Codes waiting for your answer**가 나열된 **필요한 답변**이 열립니다. 코드는 **계정 유형**, **회사**, **계정**, **부서**, **이익 센터**, **고객**, **제품** 및 각 추가 범주별로 그룹화됩니다. 각 코드에 대해 소스별 명칭과 제안이 표시됩니다.

- 소스들이 코드에 같은 이름을 지정하면 **Looks like the same thing**이 표시됩니다.
- 이름이 다르면 **Looks like different things**가 표시됩니다.
- 판단할 근거가 없으면 **We can't tell. Please answer.** 제안이 표시됩니다.

코드마다 **Yes, the same** 또는 **No, different**로 하나씩 답하거나, **Accept all**(모든 제안 수락), **All the same**, **All different**로 그룹 전체에 한 번에 답합니다. 계정의 경우 계정과목표의 상위 그룹 전체에 한 번에 답할 수도 있습니다. 소스에 계정 유형이 없으면 계정 그룹에 대해 **Use this type**을 선택합니다. 유형은 **수익**, **매출원가**, **영업비용**, **영업외 손익**, **자산**, **부채**, **자본** 중 하나입니다.

매핑은 소스와 차원별로 유지되므로 한 소스의 부서에 대한 답변이 다른 소스의 계정을 변경하지 않습니다. 답변은 진행하면서 저장되며 **Saved. Press Apply changes to use your answers.** 메시지가 표시됩니다. 답변을 사용하려면 **Apply changes**를 클릭합니다.

매핑을 파일로 제공할 수도 있습니다. **Code map** 데이터 세트로 파일을 추가하고, 하나의 소스로 제한하려면 **Which source do these rows apply to?** 를 선택합니다.

## 기간별 기준 소스 선택

두 소스가 같은 월을 제공하면 **Which source covers which months** 검사에서 선택을 요청합니다. **상태**의 **What to do next** 목록에서 **Choose sources ›** 버튼을 클릭하여 **소스 적용 범위**를 엽니다. 여기에는 회사별로 겹치는 항목이 나열됩니다. 기준으로 삼을 소스를 선택하고 **That month is**에 기준 시작 월(예: `2026-04`)을 입력한 다음 **Save choice**를 클릭하고, 페이지 위의 표시줄에서 **Apply changes**를 클릭합니다. 다른 소스는 그 이전 월을 유지합니다.

같은 대화 상자에서 두 소스가 같은 통화에 대해 서로 다른 환율을 제공하면 경고가 표시되며, 순서가 더 높은 소스의 환율이 사용됩니다.

## 통화 환산

각 로드는 총계정원장, 시산표, 판매, 재고, 예산 금액을 현지 통화에서 하나의 보고 통화로 환산합니다. 보고서와 모델은 환산된 금액을 읽으므로 어느 시스템에서 왔든 통화가 서로 다른 엔터티도 올바르게 합산됩니다.

### 보고 통화

보고 통화를 선택하려면 프로젝트 변수 `reporting_currency`를 `USD` 같은 통화 코드로 설정합니다. [프로젝트 변수 관리](/ko/guides/projects/managing-projects/#프로젝트-변수-관리)를 참조하십시오. 템플릿은 이 변수를 빈 값으로 만듭니다. 변수가 비어 있는 동안 각 로드는 다음 중 정확히 하나의 통화를 지정하는 첫 번째 항목을 사용합니다.

1. 엔터티의 그룹 통화
2. 최상위 엔터티(상위 엔터티가 없는 엔터티)의 현지 통화
3. 파일의 현지 통화

어느 항목도 정확히 하나의 통화를 지정하지 않으면 `reporting_currency`를 설정할 때까지 **통화 환산**에 문제가 표시됩니다.

이미 보고 통화로 된 금액은 그대로 유지되므로 모든 데이터가 하나의 통화로 된 프로젝트에는 환율이 필요하지 않습니다.

판매, 재고, 예산 파일에도 통화를 포함할 수 있습니다. `Currency` 또는 `Local Currency`라는 열을 매핑하면 자동으로 인식되며, 파일의 현지 금액이 보고 통화로 환산됩니다. 파일에 이미 있는 그룹 금액이나 보고 금액은 그대로 유지됩니다. 제품 표준 원가는 환산되지 않습니다.

### 환율

환율은 특정 월에 한 통화 1단위를 보고 통화로 환산합니다. 환산 금액은 현지 금액에 환율을 곱한 값입니다.

- **ERP에서**: 각 로드는 ERP에 있는 환율을 읽습니다.
- **파일에서**: CSV 또는 Excel 파일을 추가하고 **환율** 데이터 세트를 선택합니다. 파일의 환율은 같은 통화와 월에 대한 ERP 환율을 대체합니다. ERP에서 환율을 게시하지 않는 통화로 보고하거나 예산 월의 계획 환율을 추가하려면 파일을 사용합니다.

| 열 | 내용 |
|---|---|
| `from_currency` | 환산할 원래 통화입니다. 예: `EUR` |
| `to_currency` | 보고 통화입니다. 예: `USD` |
| `period` | `YYYY-MM` 형식의 월입니다. |
| `average_rate` | 해당 월의 평균 환율입니다. |
| `closing_rate` | 해당 월말의 환율입니다. |
| `historical_rate` | 자본 계정과 역사적 환율로 설정된 계정에 사용하는 역사적 환율입니다. |

통화에 보고 통화로의 환율이 없으면 반대 방향, 즉 보고 통화에서 해당 통화로의 환율을 역수로 바꾸어 소수점 이하 12자리까지 유지합니다. 그것도 없으면 다른 통화로의 환율에 그 통화의 보고 통화 환율을 곱합니다.

### 적용되는 환율

각 행은 자체 통화에서 환산되므로 엔터티와 다른 통화로 된 라인은 해당 라인의 통화에서 환산됩니다. 행에 맞는 첫 번째 규칙이 적용됩니다.

| 행 | 환율 |
|---|---|
| 통계 계정 및 비전기 계정 | 환산하지 않습니다. |
| 이미 보고 통화로 된 행 | 환산하지 않습니다. |
| 환율 유형이 있는 계정 | 해당 환율(평균, 기말 또는 역사적 환율)을 사용합니다. 역사적 환율이 없으면 기말 환율을 사용합니다. ERP에서 가져온 경우 환율 유형은 계정 자체의 환율 유형입니다. 계정과목표 파일에서는 환율 유형 열을 `fx_rate_type`에 매핑하고 `average`, `closing` 또는 `historical`을 지정합니다. |
| 판매 라인 | 해당 기간의 평균 환율을 사용합니다. |
| 재고 잔액 | 해당 기간의 기말 환율을 사용합니다. |
| 예산 행 | 총계정원장과 마찬가지로 계정별로 적용합니다. 손익 계정에는 평균 환율, 재무상태표 계정에는 기말 환율을 사용합니다. |
| 손익 계정 | 해당 기간의 평균 환율을 사용합니다. |
| 자본 계정 | 역사적 환율을 사용하며, 역사적 환율이 없으면 기말 환율을 사용합니다. |
| 기타 재무상태표 계정 | 해당 기간의 기말 환율을 사용합니다. |

환산 금액은 반올림하지 않으므로 합계에 차이가 생기지 않습니다.

<Aside type="note">
시산표에는 각 기간의 변동분이 들어 있으므로 재무상태표 금액은 각 월의 변동분을 해당 월의 기말 환율로 환산한 값입니다. 기말 환율로 다시 환산한 재무상태표가 아니며, 누적 환산 조정이나 내부 거래 제거는 포함되지 않습니다. 환산된 금액은 손익계산서에 사용하십시오.
</Aside>

## 계층

로드할 때마다 모든 소스의 마스터 데이터로 차원을 다시 만듭니다. 처음에는 일곱 개의 차원이 있으며, 추가 범주를 최대 열 개까지 둘 수 있습니다.

| 차원 | 생성 기준 |
|---|---|
| **엔터티** | 엔터티와 그 상위 항목 |
| **계정** | 계정과목표와 상위 계정 |
| **부서** | 부서와 그 상위 항목 |
| **고객** | 고객과 상위 고객 |
| **제품** | 제품과 상위 제품 |
| **세그먼트 1** | `segment_1`의 세그먼트 값 |
| **세그먼트 2** | `segment_2`의 세그먼트 값 |
| **세그먼트 3**~**세그먼트 10** | 소스에 있는 경우 `segment_3`~`segment_10`의 세그먼트 값 |

- 상위 항목이 없거나 자기 자신을 상위 항목으로 지정한 레코드는 최상위 멤버로 로드됩니다.
- 로드할 때마다 계층을 다시 만들므로 상위 항목은 차원이 아니라 ERP나 파일에서 변경하십시오.
- 한 계층의 문제는 해당 차원에만 영향을 줍니다. 로드와 템플릿의 모델은 그대로 완료됩니다.
- 각 추가 범주의 이름을 그 내용에 맞게 바꿀 수 있습니다(예: **클래스** 또는 **리전**). **소스** 페이지의 **이름**에서 보고서에 사용하는 이름을 입력하고 **Save names**를 클릭합니다. 이름에는 문자, 숫자, 공백, 마침표, 대시, 밑줄을 최대 60자까지 사용할 수 있습니다.
- 각 소스는 자체 추가 범주가 사용자가 정한 범주 이름 중 어디에 들어가는지 지정합니다. 소스에서 **편집**을 클릭하고 각 범주의 이름을 선택하거나 **Leave out**을 선택한 다음 **저장**을 클릭합니다. 그러면 `Class`와 `Business area`처럼 범주를 서로 다른 이름으로 부르는 소스들이 하나의 슬롯을 공유합니다.

파일에서 세그먼트 계층을 제공하려면 **세그먼트 값** 데이터 세트를 선택합니다.

| 열 | 내용 |
|---|---|
| `segment` | 값이 속한 세그먼트: `segment_1`~`segment_10`. |
| `segment_value` | 총계정원장, 판매 및 예산 라인에 기록된 그대로의 값. |
| `segment_value_name` | 값의 이름. |
| `parent_segment_value` | 같은 세그먼트 내의 상위 값. |

## 준비 상태 검사

각 로드 후 **준비 상태** 그리드에는 모든 엔터티와 기간에 대한 모든 검사가 다음 상태 중 하나와 함께 표시됩니다.

| 상태 | 의미 |
|---|---|
| **● 준비됨** | 검사를 통과했습니다. |
| **▲ 확인 필요** | 살펴볼 필요가 있지만 숫자는 사용할 수 있습니다. |
| **■ 문제** | 결과를 신뢰하기 전에 수정하십시오. |
| **– 해당 없음** | 아직 이 검사에 대한 데이터가 없습니다. |

검사 항목은 다음과 같습니다.

| 검사 | 확인 내용 |
|---|---|
| **데이터 로드됨** | 모든 회계 기간에 총계정원장 라인이 있고 모든 ERP 읽기가 성공했습니다. 라인이 없는 마감된 기간은 문제이고, 라인이 없는 미마감 기간은 확인이 필요합니다. |
| **시산표와 총계정원장 일치** | 각 엔터티, 기간, 계정별로 시산표가 총계정원장과 같습니다. 한 계정에 대해 시산표와 총계정원장 모두 부서를 기록하는 경우 부서별로도 일치하는지 확인합니다. |
| **판매와 총계정원장 일치** | 각 기간의 판매 라인이 총계정원장의 수익 및 매출원가(COGS) 계정과 같습니다. |
| **알 수 없는 제품/고객** | 모든 판매 라인이 제품 및 고객 마스터에 있는 제품과 고객을 지정합니다. |
| **계정과목표에 없는 계정** | 모든 총계정원장 라인이 계정과목표에 있는 계정을 지정합니다. 알 수 없는 계정이 있는 라인은 손익계산서에서 제외됩니다. 전기 내역은 있지만 계정 유형이 없는 계정도 문제이며, 계정과목표에 Revenue 계정 유형은 있지만 매출원가 계정이 없는 소스는 확인이 필요합니다. |
| **통화 환산** | 모든 총계정원장, 시산표, 판매, 재고 및 예산 행에 보고 통화 금액이 있습니다. 손익계산서는 환산된 금액을 읽으므로 환율이 없는 손익계산서 행이나 판매 행은 문제입니다. 환율이 없는 재무상태표, 재고 또는 예산 행은 확인이 필요합니다. 아직 환율이 없는 예산 월은 주황색으로 표시되므로 예산 월에 대한 계획 환율을 로드하십시오. [통화 환산](#통화-환산)을 참조하십시오. |
| **매핑되지 않은 엔터티** | 모든 총계정원장, 시산표 및 판매 라인이 엔터티 마스터에 있는 엔터티를 직접 또는 엔터티 매핑표를 통해 지정합니다. 엔터티 마스터가 로드될 때까지는 해당되지 않습니다. [엔터티 매핑표](#엔터티-매핑표)를 참조하십시오. |

소스가 둘 이상인 로드에는 다음 검사가 추가됩니다.

| 검사 | 확인 내용 |
|---|---|
| **보고 장부** | 한 엔터티에 대해 여러 회계 장부를 가진 소스의 보고 장부가 선택되었습니다. 선택하기 전까지는 첫 번째 장부만 집계됩니다. |
| **답변 대기 중인 코드** | 둘 이상의 소스에서 사용하는 모든 코드에 답변했습니다. [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오. |
| **소스의 추가 범주** | 소스에 있는 모든 추가 범주에 이름이 지정되었거나 제외되었습니다. |
| **소스별 적용 월** | 어느 소스를 집계할지 선택하지 않은 한, 두 소스가 한 회사의 같은 월을 제공하지 않습니다. |
| **계정 유형 및 계층** | 차원에서 지정하는 모든 상위 항목이 존재하며, 어떤 멤버도 자기 자신의 상위 항목이나 조상이 아닙니다. 상위 항목이 없으면 그 하위 항목이 계층의 최상위에 놓이고, 순환이 있으면 해당 계층이 로드되지 않습니다. 합계에는 영향이 없습니다. |
| **회계 달력** | 각 엔터티의 회계 기간이 역월이며 모든 월의 행을 하나의 회계 기간에 배치할 수 있습니다. 엔터티의 기간이 역월이 아닌 경우(4-4-5, 13기간), 한 월의 행이 둘 이상의 회계 기간에 속할 수 있는 경우, 또는 회계 달력에 해당 월이 없는 경우 확인이 필요합니다. |

준비되지 않은 각 행은 **조치 사항** 열에 계정과목표 로드, 환율 로드, 기간에 대해 **로드** 다시 실행 등 해야 할 일을 표시합니다.

그리드에는 확인이 필요할 때만 나타나는 설정 검사 두 가지도 표시됩니다.

| 검사 | 표시되는 경우 |
|---|---|
| **간접비 배부** | 프로젝트 변수 `overhead_department`와 `overhead_driver` 중 하나만 설정되었거나 `overhead_driver`와 일치하는 배부 동인이 없어 배부가 아무 작업도 하지 않는 경우입니다. 둘 다 설정하거나, 간접비 배부를 끄려면 둘 다 지우십시오. |
| **예산 비교** | 예산 행이 로드되었지만 프로젝트 변수 `budget_version`이 지정하는 버전에 해당하는 행이 없어 예산 비교가 비어 있는 경우입니다. |

## 관리 통합

각 로드는 관리 통합을 만듭니다. 관리 통합은 그룹 내 모든 엔터티의 그룹 손익계산서로, 보고 통화로 작성되고 내부거래가 제거됩니다. 관리 보고용입니다. 법정 그룹의 공식 기록은 여전히 기존 통합 시스템이며, 아래에서 설명하는 대로 그 시스템과 대사하십시오.

<Aside type="note">
관리 통합은 손익계산서만 다룹니다. 법정 또는 법적 통합이 아니며 연결 재무상태표, 환산 조정, 영업권 또는 비지배 지분이 없습니다.
</Aside>

### 그룹 선택

**소스** 페이지에서 **Group and row access**를 열어 그룹에 속한 회사를 확인합니다. 선택을 해제한 회사는 개별적으로는 보고서에 계속 표시되지만 그룹 합계에서는 제외됩니다. **Save group**을 클릭합니다. 변경 사항은 다음 **로드** 또는 **Apply changes** 때 적용됩니다. 새 회사는 선택을 해제할 때까지 그룹에 포함됩니다.

그룹의 회계연도는 프로젝트 변수 `group_fy_start_month`로 설정한 월에 시작하며, 변경하지 않으면 `1`입니다.

| 테이블 | 내용 |
|---|---|
| **그룹 손익계산서** | 엔터티, 기간, 항목(수익, 매출원가, 영업비용, 영업외, 내부거래 차이)별로 한 행씩, 보고 통화로 작성됩니다. 수익과 비용은 원래 부호를 유지합니다. |
| **그룹 손익계산서 연초 누계** | 같은 내용을 그룹의 마지막으로 완전히 로드된 기간까지 연초부터 누계한 것입니다. |
| **내부거래 쌍** | 엔터티 쌍, 그룹, 기간별로 한 행씩, 양측의 금액과 잔차를 포함합니다. |
| **내부거래 라인** | 그룹 수치나 쌍의 근거가 되는 원장 라인과 거래 상대방입니다. |
| **대사** | 그룹 손익계산서 연초 누계를 통합 시스템과 비교한 결과입니다. |

이 테이블에는 세 가지 엔터티 이름이 나타납니다.

| 엔터티 | 의미 |
|---|---|
| **제거** | 내부거래 제거 항목입니다. 합하면 0이 되므로 그룹 수치에는 포함하고, 제거 전 엔터티 합계를 볼 때는 필터로 제외하십시오. |
| **그룹 합계** | 대사에서 사용하는 통합 시스템의 합계입니다. |
| **매핑되지 않음** | 기간이 없는 라인, 그리고 이 프로젝트에 없는 통합 시스템의 계정이나 엔터티입니다. |

지표 **통합 이익**, **통합 결과**, **내부거래 차이**와 각 테이블의 분석 경로로 그룹에 관한 질문에 답할 수 있습니다.

### 내부거래 제거

내부거래 라인은 거래 상대방을 기준으로 일치시킵니다. 라인의 거래 상대방을 사용하며, 라인에 거래 상대방이 없으면 해당 고객의 거래 상대방을 사용합니다. 쌍의 양측이 모두 제거되며, 양측 금액의 불일치분은 내부거래 차이 항목으로 기장됩니다. 각 쌍에는 사유가 지정됩니다.

| 사유 | 의미 |
|---|---|
| **일치** | 양측이 같은 금액을 기장했습니다. |
| **한쪽만 기장됨** | 한 엔터티는 거래를 기장했지만 거래 상대방은 기장하지 않았습니다. |
| **제거되지 않음** | 쌍의 라인 중 하나에 환율이 없어 어느 쪽도 제거되지 않았습니다. |

쌍은 연초 누계를 기준으로 판단합니다. **내부거래 잔액** 행은 쌍의 차이가 프로젝트 변수 `group_amber`(기본값 `1`)를 넘으면 주황색, `group_red`(기본값 `1000`)를 넘으면 빨간색으로 바뀝니다. 거래 상대방이 없거나 거래 상대방이 엔터티가 아닌 라인은 제거되지 않고 해당 행에 집계됩니다. 거래 상대방을 기록하는 소스와 기록하지 않는 소스가 함께 있으면 주황색으로 표시됩니다.

소스 자체의 제거 엔터티는 그룹 손익계산서에서 제외되며, **통합** 행에 그 사실이 표시됩니다.

### 통합 시스템과 대사

통합 시스템이 보고하는 결과를 파일로 추가하고, 매핑을 확정할 때 **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** 확인란을 선택합니다. **Which version of the numbers is this?** 질문에는 시스템 이름을 입력합니다. 그러면 **대사** 테이블에 각 엔터티와 항목별로 연초 누계 기준 **자체 계산**, **보고값**, **차이**가 표시됩니다. 차이는 보통 **제거**, **그룹 합계**, **매핑되지 않음** 행이나 시스템이 사용하는 환율로 설명됩니다. **소스와의 대사** 행에는 `group_amber`를 넘는 모든 항목이 나열됩니다.

### 볼 수 있는 사용자

그룹 결과는 프로젝트의 행 액세스를 따릅니다. 행 액세스 때문에 그룹 결과를 표시할 수 없으면 상태가 주황색으로 표시됩니다. 일부 엔터티만 볼 수 있는 사용자는 해당 엔터티의 제거 전 합계를 봅니다. **제거** 행과 내부거래 테이블을 보려면 모든 엔터티에 대한 액세스 권한이 필요합니다.

프로젝트가 부서처럼 그룹 테이블에 없는 열을 기준으로 볼 수 있는 행을 제한하는 경우, 그룹 결과는 모든 사용자에게 꺼진 상태로 유지되고 **통합**에 **Group views are off**가 표시됩니다. 이 경우 아키텍트만 **그룹**에서 **Everyone on the project may see the group results** 확인란을 선택할 수 있습니다. 변경 사항은 다음 **로드** 또는 **Apply changes** 때 적용됩니다.

## 최신 상태 유지

ERP 연결에서의 로드가 문제 없이 성공하면 **상태**에 **야간 새로 고침**이 나타납니다. 이를 클릭하면 매일 밤 사용자 시간대 기준 2:00에 **로드**가 실행됩니다. 그러면 **상태**에 **Nightly refresh: Every night at 2:00**과 설정한 사람이 표시됩니다.

야간 로드는 설정한 사람의 권한으로 실행됩니다. 그 사람이 더 이상 ERP 연결을 사용할 수 없으면 그리드에 야간 로드를 건너뛰었다고 표시되므로 다시 설정하십시오. 샘플 데이터만 있는 프로젝트는 일정을 설정할 수 없습니다.

야간 로드에서 파일이 없거나 비어 있으면 오류가 아니라 해당 경로를 알려 주는 경고와 함께 완료되며, 모델의 나머지 부분은 계속 로드됩니다.

## 비즈니스 이름

**Foundation** 탭의 **소스** 페이지에서 **이름** 아래에 있는 **Business names**는 모델의 코드에 비즈니스에서 사용하는 이름을 붙입니다. 보고서, 지표 및 어시스턴트에 이 이름이 표시되며, 저장한 이름은 즉시 적용됩니다. 이후 로드에서도 유지됩니다.

1. **Add a name**을 클릭하고 **종류**로 **범주**, **손익계산서 항목**, **지표** 또는 **열**을 선택합니다.
2. **코드**를 입력합니다. 범주는 `segment_1`~`segment_10`, 손익계산서 항목은 항목의 키, 지표는 지표 이름, 열은 `table.column`입니다.
3. **이름**을 한 줄, 최대 60자로 입력합니다.
4. **Save names**를 클릭합니다.

저장하면 목록 전체가 바뀝니다. 이름이 비어 있는 행은 해당 이름을 제거하며, **선택 항목 제거**는 선택한 행을 제거합니다. 같은 코드에 이름을 두 번 지정하면 거부됩니다. 비즈니스 이름은 어시스턴트가 사용자의 용어를 쓰도록 분석 경로의 설명에도 기록되는데, 이 설명에는 길이 제한이 있습니다. 이름 때문에 설명이 너무 길어지면 아무것도 저장되지 않고 그 사실이 안내됩니다.

## 숫자 설명

**Explain this number**는 손익계산서 수치 하나가 무엇으로 구성되는지 보여 줍니다. **준비 상태** 그리드에서 엔터티와 월에 해당하는 행에 **Explain this number**가 있으며, 이를 클릭하면 해당 월의 엔터티 영업 이익률이 열립니다. 창은 숫자를 맨 위의 합계로 합산되는 계층으로 나눕니다.

| 계층 | 내용 |
|---|---|
| **From the general ledger** | 원장이 해당 항목에 전기한 금액입니다. |
| **Allocated in** | [배부 규칙](#배부-규칙)에 따라 이 엔터티로 배부된 비용입니다. |
| **Allocated out** | 이 엔터티가 다른 곳으로 배부한 비용입니다. |
| **Eliminated in the group** | 그룹 결과에서 제거된 내부거래입니다. |

각 계층에는 그 계층이 무엇인지와 가장 큰 원천 문서를 원천 시스템, 문서, 계정과 함께 설명하는 문장이 있습니다. 행이 있는 계층만 표시됩니다. 창은 행 액세스를 따르므로 볼 수 있는 수치만 설명할 수 있습니다. 근거가 없는 숫자에는 **Nothing to explain**이 표시됩니다.

## 배부 규칙

배부는 간접비 같은 공유 비용을 부서, 제품, 고객에 분산합니다. 모델에는 **Stage 1: overhead to departments**와 **Stage 2: departments to products and customers**의 두 단계가 있습니다. 각 단계의 처리 방식을 확인하거나 변경하려면 **작업 > 배부...** 메뉴를 엽니다. 변경하지 않으면 마법사가 생기기 전과 같은 방식으로 작동합니다. 읽기 권한만 있는 사용자는 규칙을 열 수 있지만 저장할 수는 없습니다.

마법사는 각 단계마다 네 가지를 묻습니다.

| 단계 | 질문 | 선택 항목 |
|---|---|---|
| **풀** | 어떤 비용을 분산하시겠습니까? | 계정 종류와, 1단계의 경우 비용을 보유한 부서 또는 **All departments**. |
| **드라이버** | 무엇을 기준으로 분산하시겠습니까? | 배부 동인으로 로드한 **Statistic**(예: 인원수, 면적), **Net sales amount**, **Sales quantity** 또는 **Spread evenly**. **Same period** 또는 **Same period last year**의 드라이버를 사용합니다. |
| **대상** | 어디에 배부됩니까? | 1단계: 부서. 2단계: 제품, 고객 또는 둘 다. |
| **방법** | 드라이버가 음수이면 어떻게 합니까? | **Ignore negative values** 또는 **Stop and tell me**. |

단계 아래의 **Preview for**에 `2026-09`처럼 연도와 월로 월을 입력하면, 아직 저장하지 않은 규칙을 포함해 규칙이 어떤 결과를 내는지 보여 줍니다: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. 미배부 금액은 배부받을 드라이버가 없었던 비용입니다. 미리 보기는 행 액세스를 따릅니다.

부서 이름이나 통계 이름에는 작은따옴표(`'`), 백슬래시, 줄바꿈을 넣을 수 없습니다. 이름이 워크플로의 배부 단계 필터에 기록되기 때문입니다. **저장**과 1단계 미리 보기는 이런 이름을 거부하고 표시합니다.

**저장**을 클릭합니다. 규칙은 다음 **로드** 때 또는 **Apply changes**를 클릭할 때 적용됩니다. 배부 단계를 직접 편집한 경우 편집 내용은 덮어쓰이지 않고 유지되며, 저장 시 해당 단계가 표시됩니다. 로드가 실행 중일 때는 저장할 수 없습니다.

## 이사회 보고 자료

이사회 보고 자료는 결과를 문서 계정의 폴더에 바로 보낼 수 있는 형태로 기록합니다. **작업 > 이사회 보고 자료...** 메뉴를 열고 **문서 계정**과 `/board-packs` 같은 **폴더**를 선택한 다음 **저장**을 클릭합니다. 그러면 **로드**할 때마다 보고 자료가 만들어지므로 폴더의 파일은 마지막 로드 시점의 최신 상태를 유지합니다. 각 실행에서 다음을 기록합니다.

- 엔터티별 손익계산서, 이익률 브리지, 상위 및 하위 고객이 담긴 Excel 통합 문서 `Board pack.xlsx`.
- 손익계산서 대시보드의 PDF.

즉시 보고 자료를 만들려면 **Run now**를 클릭합니다. 완료되면 파일이 폴더에 나타납니다. 대화 상자에는 마지막 실행과 그 결과, 다음 실행이 표시됩니다. **Apply changes**로는 보고 자료가 만들어지지 않습니다. 매일 밤 만들려면 야간 새로 고침을 설정하십시오([최신 상태 유지](#최신-상태-유지) 참조). 설정하기 전까지 대화 상자에는 **Not scheduled yet**이 표시됩니다. 프로젝트를 변경할 수 있는 사용자만 설정할 수 있습니다.

보고 자료를 완전히 만들 수 없어도 로드가 실패하지는 않습니다.

- 워크스페이스에서 보고 기능이 꺼져 있으면 보고 자료는 Excel 통합 문서만으로 구성되며, 실행 결과에 **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.** 메시지가 표시됩니다.
- 다른 사람이 만든 대시보드가 이미 Data Foundation이 손익계산서 대시보드에 필요로 하는 주소를 사용하고 있으면 해당 대시보드는 그대로 두고 PDF는 만들지 않습니다. 메시지에 주소가 표시되므로 다른 대시보드에 다른 주소를 지정한 다음 **로드**를 다시 실행하십시오.
- 보고 자료의 단계 중 하나라도 실패하면 **상태** 목록에 해당 단계와 이유를 알려 주는 주황색 **이사회 보고 자료** 행이 표시됩니다. 로드 자체는 성공한 것입니다.

## 복원 지점

복원 지점은 누가 시작했든(예약된 로드 포함) 각 **로드** 또는 **Apply changes**가 시작될 때, 그리고 매핑이나 소스를 변경하기 전에 만들어집니다. 복원 지점에는 모델의 테이블, 차원, 그리고 다음 로드의 기반이 되는 설정(소스, 파일, 배부 규칙)이 포함됩니다. 로드 시 만든 지점은 최근 일곱 개, 변경 전에 만든 지점은 최근 다섯 개가 유지되므로 변경 때문에 로드 시 만든 지점이 밀려나지 않습니다. 오래된 지점은 순서대로 삭제됩니다.

되돌리려면 **작업 > 복원...** 메뉴를 엽니다. 각 지점에는 생성 시각과 그 아래에 복원 시 되돌아오는 테이블 수(예: **Puts back 12 tables.**)가 경고와 함께 표시됩니다. 지점을 선택하고 **복원**을 클릭합니다. **복원**은 지점이 하나 이상 있을 때 제공됩니다. 복원하면 먼저 현재 프로젝트 상태를 별도의 지점으로 기록하므로 다시 되돌릴 수 있습니다. 그런 다음 테이블, 차원 및 해당 설정을 이전 상태로 되돌리며, 다음 로드는 이를 기반으로 합니다. 이미 있던 소스로 복원하면 소스가 변경된 것으로 표시되지 않습니다. 뷰, 저장할 수 없는 차원, 저장된 사본이 없는 테이블은 경고에 표시되며 나머지는 복원됩니다. 이미 삭제된 복원 지점은 거부되며, 로드가 실행 중일 때는 복원할 수 없습니다.

## 프로젝트 복제

**작업 > 복제...** 메뉴는 지정한 이름으로 프로젝트를 복사합니다. 복사본에는 템플릿, 모델에 대한 편집 내용, 지표 및 분석 경로가 유지되고 샘플 데이터가 로드됩니다. 소스는 연결되지 않으므로 로드하기 전에 복사본에서 소스를 연결하십시오. 복사본을 만드는 동안 계속 작업할 수 있으며, 준비되면 **프로젝트 열기**로 이동할 수 있습니다.

## 내 템플릿으로 저장

프로젝트 설정을 저장하여 다음 클라이언트나 엔터티에 재사용할 수 있습니다. **작업 > 내 템플릿으로 저장...** 메뉴를 열고 문서 계정을 선택한 다음 파일 이름을 지정합니다. 이름 끝에 `.zip`을 생략하면 자동으로 추가됩니다. 기존 파일을 덮어쓰는 저장은 거부되므로 다른 이름을 선택하십시오.

파일에는 프로젝트 구조, 모델에 대한 편집 내용, 지표 및 분석 경로, 엔터티와 계정의 비즈니스 이름, 그리고 [Cost to Serve](/ko/guides/projects/cost-to-serve/)의 활동 맵이나 [Operational Transfer Pricing](/ko/guides/projects/operational-transfer-pricing/)의 정책 범위 같은 템플릿 구성 테이블의 행이 포함됩니다. 연결, 파일, 야간 일정, 실행, 복원 지점, 이사회 보고 자료, 액세스 권한자는 제외됩니다.

사용하려면 프로젝트를 만들고 **시작 기준**에서 **From a template file...** 옵션을 선택한 다음 문서 계정과 경로를 선택합니다. 새 프로젝트는 본인만 볼 수 있으며 모든 소스가 연결 대기 상태입니다. 이후 템플릿의 새 릴리스는 사용자가 편집한 단계를 피해 변경 사항을 병합합니다. 경로에 파일이 없으면 아무것도 만들어지지 않고 그 사실이 안내됩니다. 문서 계정을 읽을 수 있는 사람은 누구나 파일에서 설치할 수 있습니다. 다른 워크스페이스에서 사용하려면 파일을 다운로드한 다음 그곳에 업로드하십시오.

## Ask로 미해결 질문 해결

로드 후에도 프로젝트는 계정과목표에서 유형이 지정되지 않은 계정, 둘 이상의 소스가 사용하는 코드, 파일에서 아무것과도 일치하지 않은 열이라는 세 가지 사항에 대한 답을 기다리고 있을 수 있습니다. 어시스턴트에게 해결을 요청하십시오. MCP를 통한 AI 어시스턴트에서 **Resolve Data Foundation residue** 프롬프트를 사용합니다. 어시스턴트는 대기 중인 항목을 읽고 각 항목에 대해 이유와 함께 하나의 답을 제안합니다.

어시스턴트는 아무것도 기록하지 않습니다. 직접 답했을 위치에 어시스턴트의 답을 적용합니다. 계정과 코드는 **답변 대기 중인 코드**에서, 파일 열은 파일의 매핑에서 적용합니다. 어시스턴트는 엔터티를 제안하지 않습니다.

## 프로젝트 인계

**설정** 체크리스트에는 **계층 구조 검토** 다음에 마무리 항목 네 개가 있습니다.

- **야간 새로 고침 설정**은 **야간 새로 고침**이 켜지면 완료됩니다.
- **팀과 공유**는 프로젝트를 설정한 사람 외에 다른 사람이 멤버가 되면 완료됩니다.
- **증빙 자료 팩 다운로드**는 마지막으로 성공한 로드 이후 자료 팩을 다운로드하면 완료됩니다.
- **소유자에게 프로젝트 인계**는 설정한 사람 이외의 아키텍트가 있고 합계가 일치하면 완료됩니다. 완료되지 않은 동안에는 체크리스트에 해야 할 일이 표시됩니다. 클라이언트의 소유자를 이 프로젝트의 아키텍트로 지정한 다음 멤버에서 본인을 제거하십시오.

체크리스트에는 프로젝트를 설정한 사람(**Set up by**)이 표시됩니다.

## 템플릿으로 모델 확장

템플릿은 보고서와 모델을 Common Finance Model 위에 구축하므로 어떤 ERP에서 데이터를 공급하든 동일하게 작동합니다. **Enterprise Profitability** 같은 템플릿으로 프로젝트를 시작하면 다음이 만들어집니다.

- 비어 있거나 샘플 데이터로 채워진 [Common Finance Model 테이블](#common-finance-model-테이블).
- 해당 테이블로 만든 **엔터티**, **계정**, **부서**, **고객**, **제품**, **세그먼트 1**, **세그먼트 2** 차원. [계층](#계층)을 참조하십시오.
- **로드** 워크플로와, ERP와 파일을 읽고 표준화하고 준비 상태를 검사하고 템플릿의 모델을 만들기 위해 이 워크플로가 실행하는 워크플로.
- 템플릿 고유의 보고서와 모델. **Enterprise Profitability**는 수익, 매출원가, 매출총이익, 직접 및 간접 영업비용, 공헌이익, 영업이익을 포함하는 손익계산서 테이블과 전년 대비 및 예산 대비 이익률 브리지를 추가합니다.
- 결과에 대해 질문할 수 있는 지표와 분석 경로.

**시작 기준**에서 세 가지 템플릿을 사용할 수 있으며, 모두 같은 모델을 기반으로 합니다.

| 템플릿 | 추가 항목 |
|---|---|
| **Enterprise Profitability** | 손익계산서와 이익률 브리지. |
| **Cost to Serve** | 각 고객에게 서비스하는 비용과 그 이후의 이익률. [Cost to Serve](/ko/guides/projects/cost-to-serve/)를 참조하십시오. |
| **Operational Transfer Pricing** | 정책 범위 대비 각 엔터티의 이익 수준과 정산 조정. [Operational Transfer Pricing](/ko/guides/projects/operational-transfer-pricing/)을 참조하십시오. |

**From a template file...** 옵션은 저장한 프로젝트에서 시작합니다. [내 템플릿으로 저장](#내-템플릿으로-저장)을 참조하십시오.

자체 ERP를 연결하기 전에 먼저 살펴보려면 프로젝트를 만들 때 **샘플 데이터로 시작**을 선택합니다. 프로젝트는 즉시 첫 번째 로드를 실행하므로 **Foundation** 탭에 미국 달러로 환산된 유로 엔터티를 포함한 완전한 예제가 표시됩니다. 자체 ERP를 연결하거나 자체 파일을 추가하면 샘플이 제거되고 사용자의 데이터로 대체됩니다. 제거가 중단되면 다음 **로드**에서 마무리됩니다. 사용자가 직접 만든 `sample` 폴더는 제거되지 않습니다. 상태 페이지에 샘플이 해당 폴더를 점유하고 있어 그 안의 다른 테이블은 읽지 않는다는 안내가 표시되며, 해당 테이블을 다른 이름의 폴더로 옮기도록 요청합니다.

## Foundation 탭

**Foundation** 탭에서 데이터를 연결하고 로드하고 검사합니다. 왼쪽 레일에 네 개의 페이지가 나열됩니다.

| 페이지 | 표시 내용 |
|---|---|
| **상태** | 프로젝트의 상태: **로드**, **새로 고침**, **야간 새로 고침** 버튼이 있는 **마지막 로드**, **What to do next**, **설정** 체크리스트, **데이터 로드됨**, **기간**, **준비 상태**, **작업** 메뉴. |
| **필요한 답변** | 둘 이상의 소스가 사용하는 코드처럼 같은 의미인지 답해야 하는, 사용자를 기다리는 질문. |
| **소스 적용 범위** | 회사와 월에 대해 소스가 겹치거나 공백이 있는 곳, 그리고 어느 시점부터 어느 소스를 집계하는지. |
| **소스** | 각 소스를 **Load order** 순서대로 표시하며, **편집**과 **Remove this source**, **그룹** 및 **이름** 카드, 그리고 **Connect a system**(또는 **Connect another system**)이 있습니다. 여기에서 시스템 종류를 고르고, 연결을 선택하고, 회사와 로드할 이력 개월 수를 선택하거나 파일을 추가합니다. 추가한 파일은 **파일** 카드에 있습니다. |

레일의 배지는 확인이 필요한 항목 수를 표시합니다. **필요한 답변**에는 미해결 질문, **소스 적용 범위**에는 적용 범위 문제, **소스**에는 소스 수가 표시됩니다. **상태**에는 배지가 표시되지 않습니다. **로드** 또는 **Apply changes**의 결과와 상태 배너는 어느 페이지를 열든 그 위에 표시되므로 모든 페이지에서 볼 수 있습니다. **상태**에서 질문이나 적용 범위 문제를 가리키는 **Answer codes ›** 버튼, **Choose sources ›** 버튼 등을 누르면 해당 페이지로 이동합니다. **필요한 답변** 또는 **소스 적용 범위**를 닫으면 **상태**로 돌아갑니다.

소스를 변경하면 모든 페이지 위에 **You have changed your sources. Press Apply changes to use them.** 표시줄이 나타납니다. 이 표시줄에는 **Show what changed**와 **Apply changes** 버튼이 있으며, 변경 내용을 적용하는 곳은 이곳뿐입니다. 적용할 변경 내용이 없으면 **상태**의 주 버튼은 **로드**입니다. **상태**에서 **What to do next**는 문제를 먼저 나열한 다음 확인이 필요한 항목을 나열하며, 두 그룹에 걸쳐 번호가 이어집니다. **필요한 답변**에서 **Answer all**은 **Accept suggestions**, **All the same**, **All different**를 제공합니다. **소스 적용 범위**에서 **Save choice**는 어느 시점부터 어느 소스를 집계할지에 대한 선택을 저장합니다.

**설정** 체크리스트는 **데이터 연결**, **데이터 로드**, **합계 일치 여부 확인**, **계층 구조 검토**, **야간 새로 고침 설정**, **팀과 공유**, **증빙 자료 팩 다운로드**, **소유자에게 프로젝트 인계**로 구성됩니다. 현재 항목은 굵게 표시됩니다. 비즈니스 이름, 추가한 파일과 매핑 상태(**✓ 확정됨** 또는 **○ 확정 대기 중**), 그리고 엔터티, 기간, 검사별로 한 행씩 **조치 사항**과 함께 표시되는 준비 상태 그리드도 같은 페이지에 있습니다. [비즈니스 이름](#비즈니스-이름)을 참조하십시오.

로드가 실행되는 동안 탭은 자동으로 새로 고쳐지며, 읽기 한 번이 실패해도 계속 읽습니다. 상태를 읽을 수 없으면 **Foundation 상태를 읽을 수 없습니다.** 메시지가 **다시 시도**와 함께 나타나며, 이를 누르면 상태를 다시 읽습니다. 탭은 메시지를 표시하기 전에 한 번 자동으로 재시도하며, 서버가 응답하면 메시지가 사라집니다.

**상태** 페이지에는 다음 사항도 표시됩니다.

- `/sources/` 아래의 폴더 중 테이블에 필요한 열이 없는 폴더는 소스로 추가되지 않습니다. 제외된 각 테이블과 누락된 열이 안내됩니다. 열을 추가한 다음 **로드** 또는 **Apply changes**를 누르십시오.
- 로드는 성공했지만 비교할 원장 라인을 가져오지 못한 경우 주황색 **모델 손익계산서와 총계정원장 일치** 행에 일치한 항목이 없다고 표시됩니다. 일치하는 항목이 생길 때까지 설정 체크리스트의 **합계 일치 여부 확인**은 완료되지 않고 대기 상태로 남습니다. 원장 라인이 있는 소스를 추가한 다음 **로드**를 누르십시오.

설정 체크리스트로 진행 상황을 추적할 수 있습니다.

- **데이터 연결**과 **데이터 로드**는 소스가 연결되고 로드가 성공하면 자동으로 체크됩니다.
- **합계 일치 여부 확인**은 일치 검사를 통과하면 자동으로 체크됩니다.
- **계층 구조 검토**: **차원 열기**를 클릭하여 엔터티, 계정, 부서 계층을 검토한 다음 **검토했습니다**를 선택합니다. 이 항목은 직접 확정해야 합니다.
- **야간 새로 고침 설정**, **팀과 공유**, **증빙 자료 팩 다운로드**, **소유자에게 프로젝트 인계**로 목록이 마무리됩니다. [프로젝트 인계](#프로젝트-인계) 및 [프로젝트 액세스 관리](/ko/guides/projects/managing-projects/#프로젝트-액세스-관리)를 참조하십시오.

**작업** 메뉴에는 **배부...**, **이사회 보고 자료...**, **복제...**, **복원...**, **내 템플릿으로 저장...** 항목이 있습니다. [배부 규칙](#배부-규칙), [이사회 보고 자료](#이사회-보고-자료), [프로젝트 복제](#프로젝트-복제), [복원 지점](#복원-지점), [내 템플릿으로 저장](#내-템플릿으로-저장)을 참조하십시오.

## Common Finance Model 테이블

Data Foundation은 ERP든 파일이든 모든 소스를 동일한 열다섯 개 테이블로 표준화하므로, 이 테이블을 기반으로 만든 보고서, 지표, 모델은 소스와 관계없이 동일하게 작동합니다. 각 행에는 원천 시스템과 읽은 시각도 기록됩니다. **데이터 세트** 열은 파일을 추가할 때 선택하는 이름입니다.

| 데이터 세트 | 테이블 | 내용 |
|---|---|---|
| 엔터티 | `cfm_entity` | 상위 항목, 현지 및 그룹 통화, 국가가 포함된 법인. |
| 엔터티 매핑표 | `cfm_entity_map` | 소스 엔터티 코드와 각 코드가 속한 엔터티. [엔터티 매핑표](#엔터티-매핑표)를 참조하십시오. |
| 환율 | `cfm_fx_rate` | 통화 쌍별 월 평균, 기말 및 역사적 환율. [환율](#환율)을 참조하십시오. |
| 회계 달력 | `cfm_fiscal_calendar` | 엔터티 회계 기간별로 한 행씩, 시작일과 종료일 및 마감 여부. |
| 계정과목표 | `cfm_account` | 상위 항목, 유형(`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), 재무제표, 정상 잔액 및 환율 유형이 포함된 계정. |
| 부서 | `cfm_department` | 상위 항목과 이익 센터가 포함된 부서 및 코스트 센터. |
| 제품 | `cfm_product` | 상위 항목, 제품군, 그룹, 측정 단위 및 표준 원가가 포함된 제품 마스터. |
| 고객 | `cfm_customer` | 상위 항목, 그룹, 지역 및 국가가 포함된 고객 마스터. 고객 이름은 마스킹되지 않습니다. |
| 세그먼트 값 | `cfm_segment` | 이름과 상위 항목이 포함된 세그먼트 값. [계층](#계층)을 참조하십시오. |
| 총계정원장 | `cfm_gl_journal` | 거래 통화, 현지 통화 및 보고 통화로 기록된 분개 라인. |
| 시산표 | `cfm_trial_balance` | 엔터티, 계정, 부서별 기간 차변, 대변 및 순액(현지 통화 및 보고 통화). |
| 판매 라인 | `cfm_sales_line` | 수량, 총액, 할인, 순액 및 매출원가 금액이 포함된 송장 발행 판매 라인. |
| 재고 잔액 | `cfm_inventory_balance` | 제품 및 창고별 기말 재고. |
| 예산 | `cfm_budget` | 시나리오, 버전, 계정, 부서별 예산 및 예측. |
| 배부 동인 | `cfm_stat_driver` | 인원수, 면적, 단위 같은 통계 드라이버. |

기간은 `YYYY-MM` 형식으로 기록되며, 거래는 전기 기간을 기준으로 배치됩니다. 예산은 선택 사항입니다. 예산이 없는 ERP도 나머지는 모두 로드됩니다.

시산표 파일에는 차변 및 대변 열, 순액 열 또는 둘 다를 포함할 수 있습니다. 차변과 대변만 있으면 순액은 차변에서 대변을 뺀 값이며, 비어 있는 쪽은 0으로 계산됩니다. 순액만 있으면 양수 순액은 차변이 되고 음수 순액은 양수 금액으로 대변이 됩니다. 부서 열은 선택 사항입니다.

## 문제 해결

| 증상 | 조치 사항 |
|---|---|
| **연결 테스트**에서 ERP가 자격 증명을 거부했다고 표시됨 | 연결의 자격 증명과 통합 사용자가 ERP에 로그인할 수 있는지 확인하십시오. |
| **연결 테스트**에서 데이터 세트에 **권한 누락**이 표시됨 | ERP 관리자에게 표시된 권한을 추가해 달라고 요청하십시오. 해당 ERP의 [연결 가이드](/ko/guides/connections/)에 연결에 필요한 권한이 나와 있습니다. |
| ERP 오류 메시지가 ERP 자체의 메시지보다 짧음 | PlaidCloud는 공급자 오류를 표시하기 전에 자격 증명, 토큰 및 키를 제거하므로 일부 세부 정보가 생략됩니다. **연결 테스트**를 실행하여 영향을 받는 데이터 세트를 확인하십시오. |
| 한 기간의 **데이터 로드됨**이 문제로 표시됨 | 해당 기간의 ERP 읽기가 실패했습니다. **로드**를 다시 실행하십시오. 이미 로드된 기간은 건너뜁니다. |
| **계정과목표에 없는 계정**이 문제로 표시됨 | 누락된 계정을 ERP 또는 파일의 계정과목표에 추가하고 **로드**를 다시 실행하십시오. |
| **통화 환산**이 문제로 표시됨 | 해당 기간에 엔터티 통화에서 보고 통화로의 환율이 없거나 단일 보고 통화를 찾지 못했습니다. **환율** 파일에 환율을 추가하거나, 연결이 ERP의 환율을 읽을 수 있는지 확인하거나, 프로젝트 변수 `reporting_currency`를 설정하십시오. 그런 다음 **로드**를 다시 실행하십시오. |
| **통화 환산**에 확인 필요가 표시됨 | 재무상태표, 재고 또는 예산 행에 해당 기간의 기말, 역사적 또는 계획 환율이 없습니다. 손익계산서에는 영향이 없습니다. 예산 월의 계획 환율을 포함해 환율을 추가하고 **로드**를 다시 실행하십시오. |
| **답변 대기 중인 코드**에 확인 필요가 표시됨 | **Answer codes ›** 버튼을 클릭하고 각 코드에 답한 다음 **Apply changes**를 클릭하십시오. |
| **소스별 적용 월**에 확인 필요가 표시됨 | **Choose sources ›** 버튼을 클릭하고 소스를 선택한 다음 **Save choice**를 클릭하고 **Apply changes**를 클릭하십시오. |
| **내부거래 잔액**이 빨간색 또는 주황색으로 표시됨 | **내부거래 쌍**에서 쌍을 확인하십시오. 누락된 쪽을 기장하거나, 라인에 거래 상대방을 추가하거나, 누락된 환율을 추가하십시오. |
| **Group views are off** | 아키텍트에게 **그룹**에서 **Everyone on the project may see the group results** 확인란을 선택해 달라고 요청하십시오. |
| **매핑되지 않은 엔터티**가 문제로 표시됨 | 엔터티 마스터에 엔터티를 추가하거나 **엔터티 매핑표** 파일에서 해당 코드를 기존 엔터티에 매핑한 다음 **로드**를 다시 실행하십시오. |
