**Data Foundation**은 PlaidCloud 프로젝트를 위한 재무 데이터 기반입니다. **Common Finance Model**은 여러 ERP 시스템과 각 시스템의 여러 인스턴스에서 가져온 ERP 데이터를 하나의 계정과목표, 하나의 엔터티 집합, 하나의 보고 통화를 갖춘 단일 모델로 통합합니다. 이 모델을 기반으로 만든 보고서, 지표, AI 어시스턴트는 어떤 ERP에서 왔든 모두 같은 수치를 읽습니다.

ERP는 PlaidCloud 연결을 통해 연결되므로 총계정원장, 시산표, 마스터 데이터, 예산이 내보내기 없이 원본에서 직접 들어옵니다. 파일은 환율, 배부 동인, ERP 외부에서 관리하는 예산처럼 시스템에 없는 데이터를 추가하며, 파일이 다루는 범위의 ERP 행을 대체할 수 있습니다. **로드**는 모든 소스를 모델에 맞게 변환하고, 보고 통화로 환산하고, 합계가 일치하는지 검사하며, 이 모든 과정은 프로젝트의 **Foundation** 탭에서 이루어집니다. **Enterprise Profitability** 같은 템플릿은 그 위에 보고서와 모델을 구축합니다.

## ERP 연결

ERP는 PlaidCloud 연결을 통해 Data Foundation에 연결됩니다. Data Foundation은 이 연결에서 총계정원장, 시산표, 마스터 데이터, 환율, 예산을 직접 읽으며 읽기만 수행합니다. 기존 연결을 선택하거나 탭에서 새로 만들 수 있으며, 각 ERP의 액세스 설정은 [연결 가이드](/ko/guides/connections/)에서 다룹니다.

<Steps>

1. Analyze에서 **프로젝트**를 열고 **새 프로젝트**를 클릭합니다. 이름을 입력하고 **시작 기준**에서 **빈 프로젝트** 대신 **Enterprise Profitability (템플릿)** 같은 템플릿을 선택합니다. **만들기**를 클릭합니다.

   프로젝트가 **Foundation** 탭에서 열립니다. 프로젝트를 공유하기 전까지는 나만 볼 수 있으며, 내가 유일한 아키텍트입니다.

2. **Foundation** 탭에서 ERP용 기존 연결을 선택하거나 **새 연결 만들기**를 선택합니다. 기존 연결마다 해당 연결을 이미 사용하는 워크플로가 나열되며, 사용하는 워크플로가 없으면 **아직 어떤 워크플로에서도 사용되지 않음**이라고 표시됩니다.

3. 새 연결의 경우 **연결 이름**을 입력하고 **환경**을 선택한 다음 ERP 연결에서 요구하는 자격 증명을 입력합니다.

   아직 자격 증명이 없습니까? 양식에는 ERP 관리자에게 보낼 수 있는 액세스 요청서가 준비되어 있습니다. **요청 복사** 또는 **이메일 요청**을 클릭해 보낸 다음, 회신받은 값을 입력하십시오.

4. **연결 테스트**를 클릭합니다. PlaidCloud가 로그인하여 각 데이터 세트를 읽어 보고, 각각을 **읽기 가능**, **권한 누락** 또는 **오류**로 나열합니다. 누락된 항목이 있으면 ERP 관리자에게 추가를 요청해야 하는 권한의 이름을 알려 줍니다.

5. **이력 개월 수**를 설정합니다. 몇 개월 전까지 로드할지 1에서 120 사이로 지정하며 기본값은 24입니다.

6. 기존 연결의 경우 로드할 엔터티를 선택하거나, 모두 선택하지 않고 두어 모든 엔터티를 로드합니다. 비활성 엔터티와 제거(elimination) 엔터티는 표시하도록 선택하기 전까지 숨겨져 있습니다. 그런 다음 **연결**을 클릭합니다.

7. 새 연결의 경우 **연결**을 클릭해 연결을 만듭니다. 그런 다음 로드할 엔터티를 선택하고 **연결**을 다시 클릭해 저장합니다. 저장하기 전까지는 모든 엔터티가 로드됩니다.

</Steps>

연결되면 카드에 프로젝트가 로드하는 연결, 환경, 엔터티, 이력 개월 수가 표시됩니다.

각 로드는 변경된 내용만 읽습니다. 미마감 기간과 마지막으로 마감된 기간은 다시 읽고, 이미 로드된 마감된 기간은 그대로 유지합니다. **이력 개월 수**를 늘리면 추가된 개월만 읽습니다. 환율, 엔터티 매핑표 또는 보고 통화가 변경되면 영향을 받는 개월을 다시 읽습니다.

## ERP 외부 데이터를 위한 파일 추가

파일은 환율, 배부 동인, [엔터티 매핑표](#엔터티-매핑표), ERP 외부에서 관리하는 예산처럼 시스템에 없는 데이터로 ERP 연결을 보완합니다. 각 파일은 [Common Finance Model 테이블](#common-finance-model-테이블)에 나열된 데이터 세트 중 하나에 속합니다.

<Steps>

1. **파일**에서 파일을 저장할 **문서 계정**을 선택합니다.

2. **CSV 또는 Excel 파일을 여기에 놓으십시오**에 CSV 또는 Excel 파일을 놓거나 **파일 선택**을 클릭합니다. 파일은 문서 계정의 `/foundation/` 폴더에 업로드됩니다.

   이미 문서 계정에 있는 파일은 `/foundation/budget.csv`처럼 **파일 경로**를 입력하고 **파일 추가**를 클릭합니다.

3. PlaidCloud가 파일을 읽고 매핑을 제안합니다.

   - **감지된 구분 기호, 소수점 구분 기호, 날짜.** 구분 기호(쉼표, 세미콜론, 탭, 파이프), 소수점 구분 기호, 날짜 형식이 자동으로 감지됩니다.
   - **데이터 세트**: 파일 이름과 열 제목으로 일치시킨 파일이 속하는 Common Finance Model 테이블입니다. 일치 여부가 불분명하면 목록에서 선택합니다.
   - **소수점 구분 기호**: **마침표 (1,234.56)** 또는 **쉼표 (1.234,56)**.
   - **날짜 형식**: 파일에 날짜가 있을 때 표시됩니다. 감지된 형식이 틀렸다면 `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY`, `MM/DD/YYYY` 중에서 변경합니다.
   - **파일의 열**, **유형**, **예제**, **이동 위치**로 구성된 그리드. **이동 위치**를 변경하면 열을 다른 필드로 보내거나 **로드 안 함**으로 지정할 수 있습니다.

4. 각 열이 어디로 이동하는지 확인한 다음 **매핑 확정**을 클릭합니다.

</Steps>

PlaidCloud가 데이터 세트, 소수점 구분 기호 또는 날짜 순서를 스스로 결정할 수 없는 경우, 예를 들어 날짜가 일/월 또는 월/일로 읽힐 수 있는 파일이라면 확정하기 전에 선택하도록 요청합니다. 같은 데이터 세트에 두 번째 파일을 추가하면 첫 번째 파일이 대체됩니다.

허용되는 파일은 CSV, TSV, TXT 텍스트 파일, Excel `.xlsx` 파일(첫 번째 시트를 읽음), Parquet 파일입니다.

<Aside type="note">
파일이 없거나 비어 있어도 로드는 중단되지 않습니다. 파일을 추가하면 아직 매핑할 내용이 없다고 안내하고, 로드는 경로를 알리는 경고와 함께 완료되며 해당 데이터 세트는 비어 있게 됩니다. 파일이 생기면 다시 추가하십시오.
</Aside>

## 데이터 로드

**로드** 카드 또는 **마지막 로드** 카드에서 **로드**를 클릭합니다. 로드는 연결된 ERP와 확정된 파일을 읽어 Common Finance Model에 맞게 변환하고, 보고 통화로 환산하고, 준비 상태 검사를 실행하고, 템플릿의 모델을 다시 구축합니다.

- 프로젝트당 한 번에 하나의 로드만 실행됩니다. **로드**를 한 번 더 누르면 이미 로드가 실행 중이라고 안내합니다.
- 다른 워크플로가 같은 ERP 연결을 사용하는 경우 첫 로드에서 해당 워크플로를 나열하고 확인을 요청합니다. 로드는 ERP에서 읽기 때문에 해당 워크플로의 속도가 느려질 수 있기 때문입니다. 계속하려면 **그래도 로드**를 클릭합니다.
- 실패한 로드는 빨간색으로 표시되며 이전 결과 뒤에 가려지지 않습니다. 이전 로드의 행에는 로드가 성공할 때까지 **이전 로드의 결과입니다. 다시 로드하십시오.** 메시지가 표시됩니다.
- 한 엔터티와 기간을 읽는 데 실패해도 나머지는 계속 로드됩니다. **로드**를 다시 실행하면 실패한 부분만 가져옵니다.

### ERP 데이터와 파일의 병용

파일은 자신이 다루는 범위만 대체하며, ERP의 나머지 행은 그대로 유지됩니다.

- **마스터 파일**(계정, 부서, 고객, 제품, 세그먼트 값)은 코드가 같은 ERP 행을 대체합니다.
- **트랜잭션 파일**은 같은 엔터티와 월의 ERP 행을 대체합니다. 총계정원장 및 시산표 파일은 원장도 함께 일치시키고, 예산 파일은 시나리오, 통계 동인 파일은 시나리오와 동인도 함께 일치시킵니다.

파일이 나중에 어떤 월을 더 이상 다루지 않으면 다음 로드에서 해당 월의 ERP 데이터가 다시 사용됩니다.

## 엔터티 매핑표

각 소스는 자체 코드로 엔터티를 지칭합니다. **엔터티 매핑표**는 이러한 코드를 엔터티 마스터의 엔터티에 매핑하므로, 모든 소스의 라인이 같은 엔터티에 귀속됩니다.

사용하려면 CSV 또는 Excel 파일을 추가하고 **엔터티 매핑표** 데이터 세트를 선택합니다.

| 열 | 내용 |
|---|---|
| `source_entity` | 회사 코드처럼 소스가 사용하는 그대로의 코드. |
| `entity` | 엔터티 마스터에 명명된 대로의, 해당 코드가 속한 엔터티. |

- 매핑표에 없는 코드는 그대로 사용됩니다.
- 여러 코드를 하나의 엔터티에 매핑할 수 있습니다. 이 경우 해당 라인이 합산되며, 모든 코드가 마감되어야 해당 월이 마감된 것으로 간주됩니다.
- 매핑표의 코드는 모든 소스에 적용되므로 각 소스의 엔터티 코드는 소스 간에 고유해야 합니다.
- **엔터티** 파일의 행은 엔터티 코드가 같은 ERP의 엔터티를 대체합니다.

**매핑되지 않은 엔터티** 검사는 엔터티가 엔터티 마스터에도 없고 매핑표를 통해 엔터티에 매핑되지도 않은 라인을 표시합니다. 엔터티 마스터가 로드되기 전에는 **– 해당 없음**으로 표시됩니다.

## 통화 환산

각 로드는 총계정원장, 시산표, 판매, 재고, 예산 금액을 현지 통화에서 하나의 보고 통화로 환산합니다. 보고서와 모델은 환산된 금액을 읽으므로, 어떤 시스템에서 왔든 통화가 다른 엔터티가 올바르게 합산됩니다.

### 보고 통화

보고 통화를 선택하려면 프로젝트 변수 `reporting_currency`를 `USD` 같은 통화 코드로 설정합니다. [프로젝트 변수 관리](/ko/guides/projects/managing-projects/#프로젝트-변수-관리)를 참조하십시오. 템플릿은 이 변수를 빈 값으로 만듭니다. 비어 있는 동안에는 각 로드가 다음 중 정확히 하나의 통화를 지칭하는 첫 번째 항목을 사용합니다.

1. 엔터티의 그룹 통화.
2. 상위 엔터티가 없는 최상위 엔터티의 현지 통화.
3. 파일의 현지 통화.

어느 것도 정확히 하나의 통화를 지칭하지 않으면 `reporting_currency`를 설정하기 전까지 **통화 환산**에 문제가 표시됩니다.

이미 보고 통화로 된 금액은 그대로 유지되므로, 모든 데이터가 하나의 통화로 되어 있는 프로젝트에는 환율이 필요하지 않습니다.

판매, 재고, 예산 파일에도 통화를 포함할 수 있습니다. `Currency` 또는 `Local Currency`라는 열을 매핑하면 자동으로 인식되며, 파일의 현지 금액이 보고 통화로 환산됩니다. 파일에 이미 있는 그룹 또는 보고 금액은 그대로 유지됩니다. 제품 표준 원가는 환산되지 않습니다.

### 환율

환율은 한 통화 단위를 해당 월의 보고 통화로 변환합니다. 환산된 금액은 현지 금액에 환율을 곱한 값입니다.

- **ERP에서**: 각 로드는 ERP가 보유한 환율을 읽습니다.
- **파일에서**: CSV 또는 Excel 파일을 추가하고 **환율** 데이터 세트를 선택합니다. 파일의 환율은 같은 통화와 월에 대한 ERP의 환율을 대체합니다. ERP가 환율을 게시하지 않는 통화로 보고하거나 예산 월에 대한 계획 환율을 추가할 때 파일을 사용합니다.

| 열 | 내용 |
|---|---|
| `from_currency` | 환산 대상 통화. 예: `EUR`. |
| `to_currency` | 보고 통화. 예: `USD`. |
| `period` | `YYYY-MM` 형식의 월. |
| `average_rate` | 해당 월의 평균 환율. |
| `closing_rate` | 월말 환율. |
| `historical_rate` | 자본 계정과 과거 환율로 설정된 계정에 사용하는 과거 환율. |

보고 통화로의 환율만 사용됩니다. 보고 통화에서 다른 통화로 반대 방향으로 표시된 환율은 역수로 변환되지 않습니다.

### 적용되는 환율

각 행은 자신의 통화에서 환산되므로, 엔터티와 통화가 다른 라인은 해당 라인의 통화에서 환산됩니다. 행에 맞는 첫 번째 규칙이 적용됩니다.

| 행 | 환율 |
|---|---|
| 통계 계정 및 비전기 계정 | 환산하지 않음. |
| 이미 보고 통화인 경우 | 환산하지 않음. |
| 환율 유형이 있는 계정 | 해당 환율: 평균, 마감 또는 과거. 과거 환율이 없으면 마감 환율로 대체됩니다. ERP에서는 환율 유형이 계정 자체의 환율 유형입니다. 계정과목표 파일에서는 환율 유형 열을 `average`, `closing` 또는 `historical` 값으로 `fx_rate_type`에 매핑합니다. |
| 판매 라인 | 해당 기간의 평균 환율. |
| 재고 잔액 | 해당 기간의 마감 환율. |
| 예산 행 | 총계정원장처럼 계정별로 적용: 손익계산서 계정은 평균 환율, 재무상태표 계정은 마감 환율. |
| 손익계산서 계정 | 해당 기간의 평균 환율. |
| 자본 계정 | 과거 환율이며, 과거 환율이 없으면 마감 환율. |
| 그 밖의 재무상태표 계정 | 해당 기간의 마감 환율. |

환산된 금액은 반올림되지 않으므로 합계가 어긋나지 않습니다.

<Aside type="note">
시산표에는 각 기간의 변동액이 들어 있으므로 재무상태표 금액은 해당 월의 변동액을 그 월의 마감 환율로 환산한 값입니다. 기말 환율로 재환산한 재무상태표가 아니며, 누적 환산 조정이나 내부 거래 제거도 없습니다. 환산된 금액은 손익계산서에 사용하십시오.
</Aside>

## 계층

각 로드는 모든 소스의 마스터 데이터로 일곱 개의 차원을 다시 구축합니다.

| 차원 | 구축 원본 |
|---|---|
| **엔터티** | 엔터티와 그 상위 엔터티 |
| **계정** | 계정과목표와 상위 계정 |
| **부서** | 부서와 그 상위 부서 |
| **고객** | 고객과 그 상위 고객 |
| **제품** | 제품과 그 상위 제품 |
| **세그먼트 1** | `segment_1`의 세그먼트 값 |
| **세그먼트 2** | `segment_2`의 세그먼트 값 |

- 상위가 없거나 자기 자신을 상위로 지정한 레코드는 최상위 멤버로 로드됩니다.
- 각 로드가 계층을 다시 구축하므로, 차원이 아니라 ERP나 파일에서 상위를 변경하십시오.
- 한 계층의 문제는 해당 차원에만 영향을 줍니다. 로드와 템플릿의 모델은 그대로 완료됩니다.
- **세그먼트 1**과 **세그먼트 2**의 이름을 **클래스**와 **위치**처럼 실제 내용에 맞게 변경할 수 있습니다.

파일로 세그먼트 계층을 제공하려면 **세그먼트 값** 데이터 세트를 선택합니다.

| 열 | 내용 |
|---|---|
| `segment` | 값이 속한 세그먼트: `segment_1`부터 `segment_5`까지. **세그먼트 1**과 **세그먼트 2**에는 차원이 있습니다. |
| `segment_value` | 총계정원장, 판매, 예산 라인이 사용하는 그대로의 값. |
| `segment_value_name` | 값의 이름. |
| `parent_segment_value` | 같은 세그먼트 내의 상위 값. |

## 준비 상태 검사

각 로드 후 **준비 상태** 그리드에 모든 엔터티와 기간에 대한 모든 검사가 다음 상태 중 하나와 함께 나열됩니다.

| 상태 | 의미 |
|---|---|
| **● 준비됨** | 검사를 통과했습니다. |
| **▲ 확인 필요** | 살펴볼 만하지만 수치는 사용할 수 있습니다. |
| **■ 문제** | 결과를 신뢰하기 전에 해결하십시오. |
| **– 해당 없음** | 이 검사에 해당하는 데이터가 아직 없습니다. |

검사 항목은 다음과 같습니다.

| 검사 | 확인하는 내용 |
|---|---|
| **데이터 로드됨** | 모든 회계 기간에 총계정원장 라인이 있고 모든 ERP 읽기가 성공했습니다. 라인이 없는 마감된 기간은 문제이고, 라인이 없는 미마감 기간은 확인이 필요합니다. |
| **시산표와 총계정원장 일치** | 시산표가 엔터티, 기간, 계정별로 총계정원장과 같습니다. 시산표와 총계정원장이 모두 계정에 부서를 포함하는 경우 부서별로도 일치하는지 확인합니다. |
| **판매와 총계정원장 일치** | 판매 라인이 기간별로 총계정원장의 매출 및 매출원가(COGS) 계정과 같습니다. |
| **알 수 없는 제품/고객** | 모든 판매 라인이 제품 마스터와 고객 마스터에 존재하는 제품과 고객을 지칭합니다. |
| **계정과목표에 없는 계정** | 모든 총계정원장 라인이 계정과목표에 있는 계정을 지칭합니다. 알 수 없는 계정이 있는 라인은 손익계산서에서 제외됩니다. |
| **통화 환산** | 모든 총계정원장, 시산표, 판매, 재고, 예산 행에 보고 통화 금액이 있습니다. 환율이 없는 손익계산서 또는 판매 행은 손익계산서가 환산된 금액을 읽으므로 문제입니다. 환율이 없는 재무상태표, 재고, 예산 행은 확인이 필요합니다. 아직 환율이 없는 예산 월은 주황색으로 표시되므로 예산 월에 대한 계획 환율을 로드하십시오. [통화 환산](#통화-환산)을 참조하십시오. |
| **매핑되지 않은 엔터티** | 모든 총계정원장, 시산표, 판매 라인이 엔터티 마스터에 있는 엔터티를 직접 또는 엔터티 매핑표를 통해 지칭합니다. 엔터티 마스터가 로드되기 전에는 해당 없음입니다. [엔터티 매핑표](#엔터티-매핑표)를 참조하십시오. |

준비되지 않은 각 행은 **조치 사항** 열에 계정과목표 로드, 환율 로드, 특정 기간에 대한 **로드** 재실행 등 해야 할 일을 알려 줍니다.

그리드에는 설정 검사도 두 가지 표시되며, 확인이 필요할 때만 나타납니다.

| 검사 | 나타나는 경우 |
|---|---|
| **간접비 배부** | 프로젝트 변수 `overhead_department`와 `overhead_driver` 중 하나만 설정되었거나, `overhead_driver`와 일치하는 배부 동인이 없어 배부가 아무 작업도 하지 않는 경우. 둘 다 설정하거나, 간접비 배부를 끄려면 둘 다 비우십시오. |
| **예산 비교** | 예산 행이 로드되었지만 프로젝트 변수 `budget_version`이 지정한 버전에 해당하는 행이 없어 예산 비교가 비어 있게 되는 경우. |

## 최신 상태 유지

ERP 연결에서 로드가 문제 없이 성공하면 **마지막 로드** 카드에 **야간 새로 고침**이 나타납니다. 이를 클릭하면 사용자의 시간대 기준 매일 밤 2:00에 **로드**가 실행됩니다. 그러면 카드에 **야간 새로 고침: 매일 밤 2:00**과 설정한 사람이 표시됩니다.

야간 로드는 설정한 사람의 권한으로 실행됩니다. 그 사람이 더 이상 ERP 연결을 사용할 수 없으면 그리드에 야간 로드가 건너뛰어진다고 표시되므로 다시 설정하십시오. 샘플 데이터만 있는 프로젝트는 일정을 지정할 수 없습니다.

야간 로드에서 파일이 없거나 비어 있으면 오류가 아니라 경로를 알리는 경고와 함께 완료되며, 모델의 나머지는 계속 로드됩니다.

## 템플릿으로 모델 위에 구축

템플릿은 Common Finance Model 위에 보고서와 모델을 구축하므로, 어떤 ERP가 데이터를 공급하든 동일하게 동작합니다. **Enterprise Profitability** 같은 템플릿으로 프로젝트를 시작하면 다음이 생성됩니다.

- 비어 있거나 샘플 데이터로 채워진 [Common Finance Model 테이블](#common-finance-model-테이블).
- 해당 테이블로 구축된 **엔터티**, **계정**, **부서**, **고객**, **제품**, **세그먼트 1**, **세그먼트 2** 차원. [계층](#계층)을 참조하십시오.
- **로드** 워크플로, 그리고 ERP와 파일을 읽고, 변환하고, 준비 상태를 검사하고, 템플릿의 모델을 구축하기 위해 이 워크플로가 실행하는 워크플로.
- 템플릿 자체의 보고서와 모델. **Enterprise Profitability**는 매출, 매출원가, 매출총이익, 직접 및 간접 영업 비용, 기여 이익, 영업 이익률이 포함된 손익계산서 테이블과 전년 대비 및 예산 대비 이익률 브리지를 추가합니다.
- 결과에 대해 질문하기 위한 지표와 분석 경로.

자신의 ERP를 연결하기 전에 살펴보려면 프로젝트를 만들 때 **샘플 데이터로 시작**을 선택합니다. 프로젝트가 즉시 첫 로드를 실행하므로 **Foundation** 탭에 유로 엔터티를 미국 달러로 환산하는 예를 포함한 완전한 예제가 표시됩니다. 자신의 ERP를 연결하거나 자신의 파일을 추가하면 샘플 행이 지워지고 내 데이터가 그 자리를 차지합니다.

## Foundation 탭

**Foundation** 탭은 데이터를 연결하고, 로드하고, 검사하는 곳입니다. 위에서 아래로 다음 섹션으로 구성됩니다.

| 섹션 | 표시되는 내용 |
|---|---|
| **마지막 로드** | 마지막 로드의 성공, 실패 또는 실행 중 여부와 **로드**, **새로 고침**, **야간 새로 고침** 버튼. |
| **설정** | 설정 체크리스트: **데이터 연결**, **데이터 로드**, **합계 일치 여부 확인**, **계층 구조 검토**, **팀과 공유**. 현재 항목은 굵게 표시됩니다. |
| **파일** | 추가한 각 파일, **총계정원장** 또는 **환율** 같은 해당 데이터 세트, 매핑이 **✓ 확정됨**인지 **○ 확정 대기 중**인지 여부. |
| **데이터 로드됨** | 엔터티별로 로드된 첫 기간과 마지막 기간, 준비된 기간의 수. |
| **기간** | 각 엔터티의 회계 기간과 각 기간이 **✓ 종료됨**인지 **○ 열림**인지 여부. |
| **준비 상태** | 준비 상태 그리드: 엔터티, 기간, 검사별로 한 행이며 상태와 **조치 사항**이 표시됩니다. |
| 연결 | ERP를 연결하고, 엔터티와 로드할 이력 개월 수를 선택합니다. |
| **파일**(추가) | CSV, TSV, TXT, Excel 또는 Parquet 파일을 추가하고 열 매핑을 확정합니다. |
| **로드** | 로드를 시작합니다. |

로드가 실행되는 동안 탭은 자동으로 새로 고쳐집니다.

설정 체크리스트는 진행 상황을 추적합니다.

- **데이터 연결**과 **데이터 로드**는 소스가 연결되고 로드가 성공하면 자동으로 체크됩니다.
- **합계 일치 여부 확인**은 합계 일치 검사를 통과하면 자동으로 체크됩니다.
- **계층 구조 검토**: **차원 열기**를 클릭해 엔터티, 계정, 부서 계층을 검토한 다음 **검토했습니다**를 선택합니다. **직접 확정해야 합니다**.
- **팀과 공유**: 프로젝트가 준비되면 공유합니다. [프로젝트 액세스 관리](/ko/guides/projects/managing-projects/#프로젝트-액세스-관리)를 참조하십시오.

## Common Finance Model 테이블

Data Foundation은 ERP이든 파일이든 모든 소스를 동일한 열다섯 개의 테이블로 변환하므로, 이를 기반으로 구축한 보고서, 지표, 모델은 소스와 관계없이 동일하게 동작합니다. 각 행에는 원본 시스템과 읽은 시점도 기록됩니다. **데이터 세트** 열은 파일을 추가할 때 선택하는 이름입니다.

| 데이터 세트 | 테이블 | 내용 |
|---|---|---|
| 엔터티 | `cfm_entity` | 상위, 현지 및 그룹 통화, 국가가 있는 법인 엔터티. |
| 엔터티 매핑표 | `cfm_entity_map` | 소스 엔터티 코드와 각 코드가 속한 엔터티. [엔터티 매핑표](#엔터티-매핑표)를 참조하십시오. |
| 환율 | `cfm_fx_rate` | 통화 쌍별 월간 평균, 마감, 과거 환율. [환율](#환율)을 참조하십시오. |
| 회계 달력 | `cfm_fiscal_calendar` | 엔터티 회계 기간당 한 행으로, 시작일과 종료일 및 마감 여부가 포함됩니다. |
| 계정과목표 | `cfm_account` | 상위, 유형(`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), 재무제표, 정상 잔액, 환율 유형이 있는 계정. |
| 부서 | `cfm_department` | 상위와 이익 센터가 있는 부서와 코스트 센터. |
| 제품 | `cfm_product` | 상위, 제품군, 그룹, 단위, 표준 원가가 있는 제품 마스터. |
| 고객 | `cfm_customer` | 상위, 그룹, 지역, 국가가 있는 고객 마스터. 고객 이름은 마스킹되지 않습니다. |
| 세그먼트 값 | `cfm_segment` | 이름과 상위가 있는 세그먼트 값. [계층](#계층)을 참조하십시오. |
| 총계정원장 | `cfm_gl_journal` | 거래, 현지, 보고 통화의 분개 라인. |
| 시산표 | `cfm_trial_balance` | 엔터티, 계정, 부서별 기간 차변, 대변, 순액(현지 및 보고 통화). |
| 판매 라인 | `cfm_sales_line` | 수량, 총액, 할인, 순액, 매출원가 금액이 있는 청구된 판매 라인. |
| 재고 잔액 | `cfm_inventory_balance` | 제품과 창고별 기말 재고. |
| 예산 | `cfm_budget` | 시나리오, 버전, 계정, 부서별 예산 및 예측. |
| 배부 동인 | `cfm_stat_driver` | 인원수, 평방피트, 수량 같은 통계 동인. |

기간은 `YYYY-MM` 형식으로 기록되며, 거래는 전기 기간에 따라 배치됩니다. 예산은 선택 사항입니다. 예산이 없는 ERP도 나머지는 모두 로드됩니다.

시산표 파일에는 차변과 대변 열, 순액 열 또는 둘 다 포함할 수 있습니다. 차변과 대변만 있으면 순액은 차변에서 대변을 뺀 값이며, 비어 있는 쪽은 0으로 계산됩니다. 순액만 있으면 양수 순액은 차변이 되고 음수 순액은 양수 금액으로 대변이 됩니다. 부서 열은 선택 사항입니다.

## 문제 해결

| 증상 | 조치 사항 |
|---|---|
| **연결 테스트**에서 ERP가 자격 증명을 거부했다고 표시됨 | 연결의 자격 증명과 통합 사용자가 ERP에 로그인할 수 있는지 확인하십시오. |
| **연결 테스트**에서 데이터 세트에 **권한 누락**이 표시됨 | ERP 관리자에게 표시된 권한을 추가해 달라고 요청하십시오. 해당 ERP의 [연결 가이드](/ko/guides/connections/)에 연결에 필요한 항목이 나와 있습니다. |
| ERP 오류 메시지가 ERP 자체의 메시지보다 짧음 | PlaidCloud는 공급자 오류를 표시하기 전에 자격 증명, 토큰, 키를 제거하므로 일부 세부 정보가 빠집니다. **연결 테스트**를 실행해 어느 데이터 세트가 영향을 받는지 확인하십시오. |
| 특정 기간에서 **데이터 로드됨**이 문제임 | 해당 기간의 ERP 읽기가 실패했습니다. **로드**를 다시 실행하십시오. 이미 로드된 기간은 건너뜁니다. |
| **계정과목표에 없는 계정**이 문제임 | ERP 또는 파일의 계정과목표에 누락된 계정을 추가하고 **로드**를 다시 실행하십시오. |
| **통화 환산**이 문제임 | 엔터티의 통화에 해당 기간의 보고 통화로의 환율이 없거나, 단일 보고 통화를 찾지 못했습니다. **환율** 파일에 환율을 추가하거나, 연결이 ERP의 환율을 읽을 수 있는지 확인하거나, 프로젝트 변수 `reporting_currency`를 설정하십시오. 그런 다음 **로드**를 다시 실행하십시오. |
| **통화 환산**에 확인이 필요함 | 재무상태표, 재고, 예산 행에 해당 기간의 마감, 과거 또는 계획 환율이 없습니다. 손익계산서는 영향을 받지 않습니다. 예산 월의 계획 환율을 포함한 환율을 추가하고 **로드**를 다시 실행하십시오. |
| **매핑되지 않은 엔터티**가 문제임 | 엔터티를 엔터티 마스터에 추가하거나 **엔터티 매핑표** 파일에서 해당 코드를 기존 엔터티에 매핑한 다음 **로드**를 다시 실행하십시오. |
