**Data Foundation**은 PlaidCloud 프로젝트를 위한 재무 데이터 기반입니다. **Common Finance Model**은 여러 ERP 시스템과 각 시스템의 여러 인스턴스에서 가져온 ERP 데이터를 하나의 모델로 통합합니다. 하나의 계정과목표, 하나의 엔터티 집합, 하나의 보고 통화를 사용합니다. 이 모델을 기반으로 만든 보고서, 지표, AI 어시스턴트는 어느 ERP에서 온 데이터이든 모두 같은 수치를 읽습니다.

ERP는 PlaidCloud 연결을 통해 연결되므로 총계정원장, 시산표, 마스터 데이터, 예산이 내보내기 없이 소스에서 직접 들어옵니다. 파일은 환율, 배부 동인, ERP 밖에서 관리하는 예산처럼 시스템에 없는 데이터를 추가하며, 해당 파일이 다루는 ERP 행을 대체할 수 있습니다. 프로젝트의 **Foundation** 탭에서 **로드**를 실행하면 모든 소스가 모델에 맞게 표준화되고, 보고 통화로 환산되며, 합계가 일치하는지 검사됩니다. 소스들이 같은 코드를 서로 다른 의미로 사용하는 경우에는 그 의미가 같은지 직접 지정하며, 관리 목적 통합이 회사 간 거래를 소거한 그룹 손익계산서를 만듭니다. **Enterprise Profitability** 같은 템플릿이 그 위에 보고서와 모델을 구축합니다.

## ERP 연결

ERP는 PlaidCloud 연결을 통해 Data Foundation에 연결됩니다. Data Foundation은 이 연결에서 총계정원장, 시산표, 마스터 데이터, 환율, 예산을 직접 읽으며 읽기만 수행합니다. 기존 연결을 선택하거나 탭에서 새로 만들 수 있습니다. 각 ERP의 액세스 설정은 [연결 가이드](/ko/guides/connections/)에서 다룹니다.

<Steps>

1. Analyze에서 **프로젝트**를 열고 **새 프로젝트**를 클릭합니다. 이름을 입력하고 **시작 기준**에서 **빈 프로젝트** 대신 **Enterprise Profitability (템플릿)** 같은 템플릿을 선택합니다. **만들기**를 클릭합니다.

   프로젝트가 **Foundation** 탭에서 열립니다. 공유하기 전까지는 본인만 볼 수 있는 비공개 프로젝트이며, 본인이 유일한 아키텍트입니다.

2. **Foundation** 탭에서 ERP에 사용할 기존 연결을 선택하거나 **새 연결 만들기**를 선택합니다. 기존 연결마다 이미 해당 연결을 사용하는 워크플로가 표시되며, 없으면 **아직 어떤 워크플로에서도 사용되지 않음**이라고 표시됩니다.

3. 새 연결인 경우 **연결 이름**을 입력하고 **환경**을 선택한 다음 ERP 연결에 필요한 자격 증명을 입력합니다.

   아직 자격 증명이 없다면 양식에 ERP 관리자에게 보낼 수 있는 액세스 요청서가 준비되어 있습니다. **요청 복사** 또는 **이메일 요청**을 클릭해 요청서를 보내고, 관리자가 보내 준 값을 입력하십시오.

4. **연결 테스트**를 클릭합니다. PlaidCloud가 로그인하여 각 데이터 세트를 읽어 보고 **읽기 가능**, **권한 누락**, **오류** 중 하나로 표시합니다. 누락된 항목이 있으면 ERP 관리자에게 추가를 요청해야 할 권한을 알려 줍니다.

5. **이력 개월 수**를 설정합니다. 몇 개월 전 데이터까지 로드할지를 1에서 120 사이로 지정하며, 기본값은 24입니다.

6. 기존 연결인 경우 로드할 엔터티를 선택하고, 모두 선택하지 않으면 모든 엔터티를 로드합니다. 비활성 엔터티와 소거 엔터티는 표시하도록 선택하기 전까지 숨겨져 있습니다. 그런 다음 **연결**을 클릭합니다.

7. 새 연결인 경우 **연결**을 클릭해 연결을 만듭니다. 그런 다음 로드할 엔터티를 선택하고 **연결**을 다시 클릭해 저장합니다. 이렇게 하기 전에는 모든 엔터티가 로드됩니다.

8. 다른 ERP 시스템이나 다른 인스턴스를 추가하려면 이 단계를 반복하되, **연결**을 클릭하기 전에 **Add this as another source instead of replacing the current one**을 선택합니다. 선택하지 않으면 새 연결이 현재 소스를 대체합니다.

</Steps>

연결되면 카드에 프로젝트가 로드하는 연결, 환경, 엔터티, 이력 개월 수가 표시됩니다.

각 로드는 변경된 부분만 읽습니다. 미마감 기간과 마지막으로 마감된 기간은 다시 읽고, 이미 로드된 마감된 기간은 그대로 유지합니다. **이력 개월 수**를 늘리면 추가된 개월만 읽습니다. 환율, 엔터티 매핑표 또는 보고 통화가 바뀌면 영향을 받는 개월을 다시 읽습니다.

## 소스

프로젝트가 로드하는 모든 ERP 시스템과 인스턴스는 소스입니다. **Foundation** 탭의 **소스** 목록에는 소스마다 한 줄씩 순서대로 표시되며, 이름, 마지막으로 로드된 시점, 제공한 행 수, 읽는 보고 장부가 나옵니다. 예: `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. 아직 로드되지 않은 소스에는 **not loaded yet**이라고 표시됩니다. 확정한 파일도 소스입니다.

소스에서 **고급**을 열어 해당 소스의 사용 방식을 변경합니다.

| 설정 | 기능 |
|---|---|
| **이름** | 보고서, 매핑 질문, 메시지에서 소스를 가리키는 레이블입니다. |
| **Place in the order** | 소스의 순위입니다. 두 소스가 같은 회사의 같은 월을 다루면 순서에서 더 위에 있는 소스가 우선합니다. |
| **Reporting books, separated by commas** | 읽을 회계 장부입니다. 장부를 둘 이상 유지하는 시스템에 사용합니다. **All reporting books**는 모든 장부를 읽습니다. |
| **회사**, **시작 (2026-01)**, **종료 (2026-12)** | 이 소스가 각 회사에 제공하는 월입니다. 제한이 없으면 월을 비워 두십시오. 월은 연도와 월로 씁니다. 예: `2026-03`. |

변경 사항을 유지하려면 **저장**을 클릭합니다. 소스를 삭제하려면 **Remove this source**를 클릭하고 **제거**를 눌러 확인합니다. 해당 소스에서 로드된 모든 데이터가 삭제되며, 나중에 다시 연결할 수 있습니다.

소스를 변경해도 ERP를 다시 읽지는 않습니다. **마지막 로드** 카드에는 **Apply changes**를 클릭할 때까지 **Changes not applied yet**이라고 표시됩니다. **Apply changes**는 이미 가져온 데이터로 로드를 실행하여 새 순서, 매핑, 이름, 파일에 맞게 소스를 다시 표준화하고 모델을 다시 빌드합니다. ERP의 최신 데이터도 필요하면 **로드**를 클릭합니다.

## ERP 밖의 데이터를 위한 파일 추가

파일은 환율, 배부 동인, [엔터티 매핑표](#엔터티-매핑표), ERP 밖에서 관리하는 예산처럼 시스템에 없는 데이터로 ERP 연결을 보완합니다. 각 파일은 [Common Finance Model 테이블](#common-finance-model-테이블)에 나열된 데이터 세트 중 하나에 속합니다.

<Steps>

1. **파일** 아래에서 파일을 저장할 **문서 계정**을 선택합니다.

2. **CSV 또는 Excel 파일을 여기에 놓으십시오**에 CSV 또는 Excel 파일을 놓거나 **파일 선택**을 클릭합니다. 파일은 문서 계정의 `/foundation/` 폴더에 업로드됩니다.

   이미 문서 계정에 있는 파일이면 **파일 경로**(예: `/foundation/budget.csv`)를 입력하고 **파일 추가**를 클릭합니다.

   매달 새 파일을 읽으려면 이름이 일치하는 폴더의 모든 파일을 추가합니다. 폴더와 **File names that** 조건(포함, 시작, 끝, 정확히 일치, 패턴 일치)을 입력하고 **Add files**를 클릭합니다. 그 안의 하위 폴더에 있는 파일은 읽지 않습니다.

3. PlaidCloud가 파일을 읽고 매핑을 제안합니다.

   - **구분 기호, 소수점 구분 기호, 날짜가 감지됩니다.** 구분 기호(쉼표, 세미콜론, 탭, 파이프), 소수점 구분 기호, 날짜 형식은 자동으로 감지됩니다.
   - **데이터 세트**: 파일이 속한 Common Finance Model 테이블로, 파일 이름과 열 머리글을 바탕으로 맞춥니다. 일치 항목이 분명하지 않으면 목록에서 선택합니다.
   - **소수점 구분 기호**: **마침표 (1,234.56)** 또는 **쉼표 (1.234,56)**.
   - **날짜 형식**: 파일에 날짜가 있을 때 표시됩니다. 감지된 형식이 틀리면 변경합니다: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` 또는 `MM/DD/YYYY`.
   - **파일의 열**, **유형**, **예제**, **이동 위치**로 구성된 그리드. 열을 다른 필드로 보내거나 **로드 안 함**으로 지정하려면 **이동 위치**를 변경합니다.

4. 파일이 제기하는 질문에 답합니다. 예를 들어 **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?**, **Are revenues shown as negative numbers?** 같은 질문입니다. 각 질문은 파일에 해당 정보가 없을 때만 표시됩니다.

5. 각 열이 어디로 가는지 확인한 다음 **매핑 확정**을 클릭합니다.

</Steps>

다음 옵션은 해당하는 경우 파일에 표시됩니다.

| 옵션 | 용도 |
|---|---|
| **Which source do these rows apply to?** | 코드 매핑 파일을 하나의 소스로 한정합니다. **Every source**는 모든 소스에 적용합니다. |
| **Where does this file come from?** | 파일이 **This project's own codes**를 담고 있는지, 이름을 직접 지정하는 **Another system**에서 온 것인지(예: `SAP Germany export`) 지정합니다. 다른 시스템의 파일은 ERP 소스처럼 공유 코드를 검사합니다. |
| **Split … into … parts at each …** (**고급** 아래) | `100-200-300`처럼 여러 값을 담은 열 하나를 나누어 각 부분을 별도의 필드로 보냅니다. |
| **Which currency do you report in?** | 프로젝트에 아직 보고 통화가 없을 때 보고 통화를 설정합니다. 세 글자로 씁니다. 예: `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 통합 시스템의 결과를 로드하여 그룹 손익계산서를 [대사](#통합-시스템과-대사)할 수 있도록 합니다. |

프로젝트에서 파일을 제거하려면 **파일** 아래 해당 파일 옆의 **제거**를 클릭하거나 매핑에서 **Remove this file**을 클릭하고 확인합니다. 해당 파일의 수치는 다음에 **Apply changes**를 클릭할 때 보고서에서 빠집니다.

PlaidCloud가 데이터 세트, 소수점 구분 기호 또는 날짜 순서를 스스로 결정할 수 없으면(예: 날짜를 일/월 또는 월/일로 읽을 수 있는 파일) 확정하기 전에 선택하도록 요청합니다. 같은 데이터 세트에 두 번째 파일을 추가하면 첫 번째 파일이 대체됩니다. 이후 파일의 열이 데이터 세트와 일치하지 않으면 로드가 해당 파일과 열을 알려 주며, 파일 또는 열 이름을 수정하거나 스텝의 **Schema Mismatch**를 `union`으로 설정하라고 안내합니다.

사용할 수 있는 파일은 CSV, TSV, TXT 텍스트 파일, Excel `.xlsx` 파일(첫 번째 시트에서 읽음), Parquet 파일입니다.

<Aside type="note">
누락되었거나 비어 있는 파일은 로드를 중단시키지 않습니다. 이러한 파일을 추가하면 아직 매핑할 내용이 없다고 알려 주며, 로드는 경로를 알려 주는 경고와 함께 완료되고 해당 데이터 세트는 비어 있게 됩니다. 파일이 준비되면 다시 추가하십시오.
</Aside>

## 데이터 로드

**로드** 카드 또는 **마지막 로드** 카드에서 **로드**를 클릭합니다. 로드는 연결된 ERP와 확정된 파일을 읽어 Common Finance Model에 맞게 표준화하고, 보고 통화로 환산하며, 준비 상태 검사를 실행하고, 템플릿의 모델을 다시 빌드합니다.

- 프로젝트당 한 번에 하나의 로드만 실행됩니다. 두 번째 **로드** 또는 **Apply changes**는 이미 로드가 실행 중이라고 알려 주며, 로드가 실행되는 동안에는 소스를 변경할 수 없습니다.
- 다른 워크플로가 같은 ERP 연결을 사용하는 경우, 로드는 ERP에서 읽으므로 해당 워크플로가 느려질 수 있기 때문에 첫 번째 로드는 그 워크플로 목록을 보여 주고 확인을 요청합니다. 계속하려면 **그래도 로드**를 클릭합니다.
- PlaidCloud를 업그레이드한 후에는 아키텍트가 **로드**하면 프로젝트의 생성된 워크플로도 업데이트되며, 필요한 작업 테이블이 있으면 만들어집니다. 그 전까지 **마지막 로드** 카드에는 **Changes not applied yet**이라고 표시되고, 매니저가 **로드**하면 아키텍트의 **로드**가 이를 업데이트한다는 경고가 표시됩니다.
- 실패한 로드는 빨간색으로 표시되며 이전 결과 뒤에 가려지지 않습니다. 통합이 실패하면 이전 그룹 결과를 보여 주는 대신 상태에 중단된 스텝의 이름이 표시됩니다. 이전 로드의 행에는 로드가 성공할 때까지 **이전 로드의 결과입니다. 다시 로드하십시오.** 메시지가 표시됩니다.
- 엔터티 하나와 기간 하나를 읽지 못해도 나머지는 계속 로드됩니다. **로드**를 다시 실행하면 실패한 부분만 가져옵니다.

### 보류된 행

소스가 겹치면 로드는 각 수치의 사본을 하나만 유지하고, 같은 수치를 두 번 계산하지 않도록 나머지는 보류합니다. 보류된 행은 소스, 엔터티, 사유와 함께 기록되며, 로드는 건수를 알려 주는 경고와 함께 완료됩니다. 예: `120 rows of NetSuite EU also provided by a source ranked ahead`. 사유는 다음과 같습니다.

| 사유 | 의미 |
|---|---|
| 다른 회계 장부에 있음 | 행이 소스가 읽도록 설정되지 않은 보고 장부에 속합니다. |
| 소스가 제공하는 기간 밖 | 행이 해당 회사에 설정된 **시작** 및 **종료** 월 밖에 있습니다. |
| 순위가 더 높은 소스도 제공함 | 순서에서 더 위에 있는 소스가 같은 회사와 월을 다룹니다. |
| 소스의 앞선 파일에도 있음 | 같은 소스의 앞선 파일이 이미 해당 월을 다룹니다. |
| 파일로 대체됨 | 파일이 해당 엔터티와 월의 ERP 행을 대체합니다. |
| 다른 소스도 사용하는 코드 | 코드에 대한 답변이 필요합니다. [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오. |
| 두 코드에 매핑된 코드 | 코드 매핑이 해당 코드에 두 가지 답을 줍니다. |

통계 계정은 원장 대신 배부 동인으로 이동하며, 문제가 아니라 이동한 것으로 표시됩니다.

### ERP 데이터와 파일 함께 사용

파일은 자신이 다루는 부분만 대체하며, ERP의 나머지 행은 그대로 유지됩니다.

- **마스터 파일**(계정, 부서, 고객, 제품, 세그먼트 값)은 코드가 같은 ERP 행을 대체합니다.
- **트랜잭션 파일**은 같은 엔터티와 월의 ERP 행을 대체합니다. 총계정원장 및 시산표 파일은 추가로 원장 기준으로, 예산 파일은 시나리오 기준으로, 통계 동인 파일은 시나리오와 동인 기준으로도 일치시킵니다.

나중에 파일이 어떤 월을 더 이상 다루지 않으면 다음 로드에서 해당 월의 ERP 데이터가 다시 적용됩니다.

## 엔터티 매핑표

각 소스는 고유한 코드로 엔터티를 지칭합니다. **엔터티 매핑표**는 이러한 코드를 엔터티 마스터의 엔터티에 매핑하여 모든 소스의 라인이 같은 엔터티에 반영되도록 합니다.

사용하려면 CSV 또는 Excel 파일을 추가하고 **엔터티 매핑표** 데이터 세트를 선택합니다.

| 열 | 내용 |
|---|---|
| `source_entity` | 소스가 가진 그대로의 코드(예: 회사 코드). |
| `entity` | 엔터티 마스터에 나와 있는 대로의, 해당 코드가 속한 엔터티. |

- 매핑표에 없는 코드는 그대로 사용됩니다.
- 여러 코드를 하나의 엔터티에 매핑할 수 있습니다. 해당 라인은 합쳐지며, 월은 모든 코드에서 마감되어야 마감된 것으로 간주됩니다.
- 매핑표의 코드는 모든 소스에 적용되므로 각 소스의 엔터티 코드는 소스 간에 고유해야 합니다.
- **엔터티** 파일의 행은 엔터티 코드가 같은 ERP의 엔터티를 대체합니다.

**매핑되지 않은 엔터티** 검사는 엔터티가 엔터티 마스터에도 없고 매핑표로 매핑되지도 않은 라인을 표시합니다. 엔터티 마스터가 로드되기 전에는 **– 해당 없음**으로 표시됩니다.

## 소스 간 코드 매핑

두 소스가 같은 코드를 서로 다른 대상에 사용하거나, 서로 다른 코드를 같은 대상에 사용할 수 있습니다. 코드가 둘 이상의 소스에 나타나면 Data Foundation은 그 코드가 모든 곳에서 같은 의미인지 답할 때까지 해당 행을 보류하므로 각 금액은 한 번만 계산됩니다. **Codes waiting for your answer** 검사가 처음 10개를 나열하고 나머지는 "외 K개"로 표시하며, **Foundation** 탭의 **What to do next** 카드에 **검토** 버튼이 있습니다.

**검토**를 클릭하면 **Codes waiting for your answer**가 열립니다. 코드를 종류별로 묶어 **계정 유형**, **회사**, **계정**, **부서**, **이익 센터**, **고객**, **제품**, 각 추가 범주로 보여 줍니다. 각 코드에 대해 소스별 이름과 제안을 표시합니다.

- 소스들이 코드에 같은 이름을 붙이면 **Looks like the same thing**이 표시됩니다.
- 이름이 다르면 **Looks like different things**가 표시됩니다.
- 판단할 근거가 없으면 **We can't tell. Please answer.** 메시지가 표시됩니다.

코드를 하나씩 **Yes, the same** 또는 **No, different**으로 답하거나, 그룹 전체를 한 번에 **Accept all**(모든 제안 수락), **All the same** 또는 **All different**로 답할 수 있습니다. 계정은 계정과목표의 상위 그룹 전체에 한 번에 답할 수도 있습니다. 소스에 계정 유형이 없으면 계정 그룹에 **Use this type**을 선택합니다: **수익**, **매출원가**, **영업 비용**, **영업 외 수익 및 비용**, **자산**, **부채**, **자본**.

매핑은 소스와 차원별로 유지되므로 한 소스의 부서에 대한 답이 다른 소스의 계정을 바꾸는 일은 없습니다. 답은 진행하는 동안 저장되며 **Saved. Press Apply changes to use your answers.** 메시지가 표시됩니다. 답을 사용하려면 **Apply changes**를 클릭합니다.

매핑을 파일로 제공할 수도 있습니다. **Code map** 데이터 세트로 파일을 추가하고, 하나의 소스로 한정하려면 **Which source do these rows apply to?** 옵션을 선택합니다.

## 어느 소스를 언제부터 적용할지 선택

두 소스가 같은 월을 제공하면 **Which source covers which months** 검사가 선택을 요청합니다. **What to do next** 카드에서 **Choose which source counts from when**을 클릭하면 회사별 중복 항목을 나열하는 **Which source counts from when**이 열립니다. 적용할 소스를 선택하고, 적용을 시작할 월을 **That month is**에 입력(예: `2026-04`)한 다음 **Apply changes**를 클릭합니다. 다른 소스는 이전 월을 유지합니다.

같은 대화 상자는 두 소스가 한 통화에 서로 다른 환율을 제공할 때도 경고하며, 순서에서 더 위에 있는 소스의 환율이 사용됩니다.

## 통화 환산

각 로드는 총계정원장, 시산표, 판매, 재고, 예산 금액을 현지 통화에서 하나의 보고 통화로 환산합니다. 보고서와 모델은 환산된 금액을 읽으므로 어떤 시스템에서 왔든 통화가 서로 다른 엔터티도 합계가 정확합니다.

### 보고 통화

보고 통화를 선택하려면 프로젝트 변수 `reporting_currency`를 `USD` 같은 통화 코드로 설정합니다. [프로젝트 변수 관리](/ko/guides/projects/managing-projects/#프로젝트-변수-관리)를 참조하십시오. 템플릿은 이 변수를 비워 둔 채로 만듭니다. 비어 있는 동안에는 각 로드가 다음 중 정확히 하나의 통화를 가리키는 첫 번째 항목을 사용합니다.

1. 엔터티의 그룹 통화.
2. 상위 엔터티가 없는 최상위 엔터티의 현지 통화.
3. 파일의 현지 통화.

어느 것도 정확히 하나의 통화를 가리키지 않으면 `reporting_currency`를 설정할 때까지 **통화 환산**에 문제가 표시됩니다.

이미 보고 통화로 된 금액은 그대로 유지되므로, 모든 데이터가 한 통화인 프로젝트에는 환율이 필요하지 않습니다.

판매, 재고, 예산 파일도 통화를 가질 수 있습니다. `Currency` 또는 `Local Currency`라는 열을 매핑하면 자동으로 인식되며, 파일의 현지 금액이 보고 통화로 환산됩니다. 파일에 이미 있는 그룹 또는 보고 금액은 그대로 유지됩니다. 제품 표준 비용은 환산되지 않습니다.

### 환율

환율은 한 월에 대해 통화 한 단위를 보고 통화로 변환하는 비율이며, 환산 금액은 현지 금액에 환율을 곱한 값입니다.

- **ERP에서**는 로드할 때마다 ERP가 보유한 환율을 읽습니다.
- **파일에서**는 CSV 또는 Excel 파일을 추가하고 **환율** 데이터 세트를 선택합니다. 파일의 환율은 같은 통화와 월에 대한 ERP의 환율을 대체합니다. ERP가 환율을 게시하지 않는 통화로 보고하거나 예산 월에 대한 계획 환율을 추가할 때 파일을 사용하십시오.

| 열 | 내용 |
|---|---|
| `from_currency` | 환산 원본 통화. 예: `EUR`. |
| `to_currency` | 보고 통화. 예: `USD`. |
| `period` | 월. `YYYY-MM` 형식. |
| `average_rate` | 해당 월의 평균 환율. |
| `closing_rate` | 월말 환율. |
| `historical_rate` | 자본 계정과 과거 환율로 설정된 계정에 쓰는 과거 환율. |

보고 통화로 변환하는 환율만 사용됩니다. 반대 방향, 즉 보고 통화에서 다른 통화로 표시된 환율은 역수로 변환되지 않습니다.

### 적용되는 환율

각 행은 자체 통화에서 환산되므로, 엔터티와 통화가 다른 라인도 해당 라인의 통화에서 환산됩니다. 행에 맞는 첫 번째 규칙이 적용됩니다.

| 행 | 환율 |
|---|---|
| 통계 계정 및 비전기 계정 | 환산하지 않습니다. |
| 이미 보고 통화인 행 | 환산하지 않습니다. |
| 환율 유형이 있는 계정 | 해당 환율(평균, 기말 또는 과거)이 적용됩니다. 과거 환율이 없으면 기말 환율로 대체됩니다. ERP에서 가져온 경우 환율 유형은 계정 자체의 환율 유형입니다. 계정과목표 파일에서는 환율 유형 열을 `fx_rate_type`에 매핑하고 값은 `average`, `closing` 또는 `historical`로 지정합니다. |
| 판매 라인 | 해당 기간의 평균 환율. |
| 재고 잔액 | 해당 기간의 기말 환율. |
| 예산 행 | 총계정원장처럼 계정별로 적용합니다. 손익계산서 계정은 평균 환율, 재무상태표 계정은 기말 환율입니다. |
| 손익계산서 계정 | 해당 기간의 평균 환율. |
| 자본 계정 | 과거 환율. 과거 환율이 없으면 기말 환율. |
| 그 밖의 재무상태표 계정 | 해당 기간의 기말 환율. |

환산 금액은 반올림되지 않으므로 합계가 어긋나지 않습니다.

<Aside type="note">
시산표는 각 기간의 변동액을 담고 있으므로 재무상태표 금액은 각 월의 변동액을 해당 월의 기말 환율로 환산한 값입니다. 기간 말 환율로 재환산한 재무상태표가 아니며, 누적 환산 조정이나 회사 간 거래 소거도 없습니다. 환산된 금액은 손익계산서에 사용하십시오.
</Aside>

## 계층

각 로드는 모든 소스의 마스터 데이터로 차원을 다시 빌드합니다. 기본으로 일곱 개의 차원이 있으며, 추가 범주는 최대 열 개까지 사용할 수 있습니다.

| 차원 | 구성 원본 |
|---|---|
| **엔터티** | 엔터티와 그 상위 엔터티 |
| **계정** | 계정과목표와 상위 계정 |
| **부서** | 부서와 그 상위 부서 |
| **고객** | 고객과 상위 고객 |
| **제품** | 제품과 상위 제품 |
| **세그먼트 1** | `segment_1`의 세그먼트 값 |
| **세그먼트 2** | `segment_2`의 세그먼트 값 |
| **세그먼트 3**에서 **세그먼트 10**까지 | 소스에 있는 경우 `segment_3`에서 `segment_10`까지의 세그먼트 값 |

- 상위가 없거나 자신을 상위로 지정한 레코드는 최상위 멤버로 로드됩니다.
- 로드할 때마다 계층을 다시 빌드하므로, 상위를 변경할 때는 차원이 아니라 ERP나 파일에서 변경하십시오.
- 한 계층의 문제는 해당 차원에만 영향을 줍니다. 로드와 템플릿의 모델은 그대로 완료됩니다.
- 각 추가 범주의 이름을 담고 있는 내용에 맞게 바꿀 수 있습니다. 예: **클래스** 또는 **리전**. **Rename extra categories** 아래에 보고서에서 사용할 이름을 입력하고 **Save names**를 클릭합니다. 이름에는 문자, 숫자, 공백, 마침표, 하이픈, 밑줄을 사용할 수 있으며 최대 60자입니다.
- 각 소스는 자체 추가 범주가 각각 어느 범주 이름에 속하는지 지정합니다. 소스에서 **고급**을 열고 각각의 이름을 선택하거나 **Leave out**을 선택한 다음 **저장**을 클릭합니다. 그러면 `Class`와 `Business area`처럼 서로 다른 이름으로 범주를 부르는 소스가 하나의 슬롯을 공유합니다.

파일로 세그먼트 계층을 제공하려면 **세그먼트 값** 데이터 세트를 선택합니다.

| 열 | 내용 |
|---|---|
| `segment` | 값이 속한 세그먼트. `segment_1`에서 `segment_10`까지. |
| `segment_value` | 총계정원장, 판매, 예산 라인에 나오는 그대로의 값. |
| `segment_value_name` | 값의 이름. |
| `parent_segment_value` | 같은 세그먼트 안에서의 상위 값. |

## 준비 상태 검사

각 로드가 끝나면 **준비 상태** 그리드에 모든 엔터티와 기간의 모든 검사가 다음 상태 중 하나와 함께 나열됩니다.

| 상태 | 의미 |
|---|---|
| **● 준비됨** | 검사를 통과했습니다. |
| **▲ 확인 필요** | 확인할 만하지만 수치는 사용할 수 있습니다. |
| **■ 문제** | 결과를 신뢰하기 전에 해결하십시오. |
| **– 해당 없음** | 이 검사에 대한 데이터가 아직 없습니다. |

검사 항목은 다음과 같습니다.

| 검사 | 확인 내용 |
|---|---|
| **데이터 로드됨** | 모든 회계 기간에 총계정원장 라인이 있고 모든 ERP 읽기가 성공했습니다. 라인이 없는 마감된 기간은 문제이며, 라인이 없는 미마감 기간은 조치가 필요합니다. |
| **시산표와 총계정원장 일치** | 시산표가 엔터티, 기간, 계정별로 총계정원장과 같습니다. 계정에 대해 시산표와 총계정원장 모두 부서를 가진 경우 부서별로도 일치하는지 확인합니다. |
| **판매와 총계정원장 일치** | 판매 라인이 기간별 총계정원장의 수익 및 매출원가(COGS) 계정과 같습니다. |
| **알 수 없는 제품/고객** | 모든 판매 라인이 제품 및 고객 마스터에 존재하는 제품과 고객을 지정합니다. |
| **계정과목표에 없는 계정** | 모든 총계정원장 라인이 계정과목표에 있는 계정을 지정합니다. 알 수 없는 계정의 라인은 손익계산서에서 제외됩니다. 전기는 있으나 계정 유형이 없는 계정도 문제이며, 계정과목표가 수익 계정에는 유형을 지정했지만 매출원가 계정에는 지정하지 않은 소스는 주의가 필요합니다. |
| **통화 환산** | 모든 총계정원장, 시산표, 판매, 재고, 예산 행에 보고 통화 금액이 있습니다. 환율이 없는 손익계산서 또는 판매 행은 손익계산서가 환산된 금액을 읽기 때문에 문제입니다. 환율이 없는 재무상태표, 재고, 예산 행은 조치가 필요합니다. 아직 환율이 없는 예산 월은 주황색으로 표시되므로 예산 월의 계획 환율을 로드하십시오. [통화 환산](#통화-환산)을 참조하십시오. |
| **매핑되지 않은 엔터티** | 모든 총계정원장, 시산표, 판매 라인이 엔터티 마스터에 있는 엔터티를 직접 또는 엔터티 매핑표를 통해 지정합니다. 엔터티 마스터가 로드되기 전에는 해당 없음입니다. [엔터티 매핑표](#엔터티-매핑표)를 참조하십시오. |

소스가 둘 이상인 로드에는 다음 검사가 추가됩니다.

| 검사 | 확인 내용 |
|---|---|
| **Reporting book** | 한 엔터티에 대해 회계 장부를 여러 개 유지하는 소스에는 보고용 장부를 선택했습니다. 선택하기 전에는 첫 번째 장부만 집계됩니다. |
| **Codes waiting for your answer** | 둘 이상의 소스에서 사용되는 모든 코드에 답했습니다. [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오. |
| **Extra categories from your sources** | 소스가 가진 모든 추가 범주에 이름이 있거나 제외되었습니다. |
| **Which source covers which months** | 어느 소스를 적용할지 선택하지 않은 한, 두 소스가 한 회사의 같은 월을 제공하지 않습니다. |
| **Account types and hierarchy** | 차원이 지정한 모든 상위 항목이 존재하며, 어떤 멤버도 자기 자신의 상위 항목이나 조상이 아닙니다. 상위 항목이 없으면 그 하위 항목은 계층의 최상위에 표시되고, 순환이 있으면 해당 계층이 로드되지 않습니다. 합계는 영향을 받지 않습니다. |
| **회계 달력** | 각 엔터티의 회계 기간이 달력 월이며, 한 달 분량의 모든 행을 하나의 회계 기간에 배치할 수 있습니다. 엔터티의 기간이 달력 월이 아니거나(4-4-5, 13개 기간), 한 달 분량의 행이 둘 이상의 회계 기간에 속할 수 있거나 회계 달력에 해당 월이 없으면 주의가 필요합니다. |

준비되지 않은 각 행은 **조치 사항** 열에 해야 할 일을 알려 줍니다. 예를 들어 계정과목표 로드, 환율 로드, 특정 기간에 대한 **로드** 다시 실행 등이 있습니다.

그리드에는 설정 검사 두 가지도 표시되며, 조치가 필요할 때만 나타납니다.

| 검사 | 표시되는 경우 |
|---|---|
| **간접비 배부** | 프로젝트 변수 `overhead_department`와 `overhead_driver` 중 하나만 설정되었거나, `overhead_driver`와 일치하는 배부 동인이 없어 배부가 아무 작업도 하지 않을 때. 둘 다 설정하거나 둘 다 지워 간접비 배부를 끄십시오. |
| **예산 비교** | 예산 행이 로드되었지만 프로젝트 변수 `budget_version`이 지정한 버전에 속하는 행이 없어 예산 비교가 비어 있을 때. |

## 관리 목적 통합

각 로드는 관리 목적 통합, 즉 그룹에 속한 모든 엔터티의 그룹 손익계산서를 보고 통화로, 회사 간 거래를 소거하여 만듭니다. 관리 보고용입니다. 법정 그룹의 공식 기록은 통합 시스템이 계속 담당하므로, 아래 방법으로 통합 시스템과 대사하십시오.

<Aside type="note">
관리 목적 통합은 손익계산서만 다룹니다. 법정 통합이나 법적 통합이 아니며, 통합 재무상태표, 환산 조정, 영업권, 소수 지분도 없습니다.
</Aside>

### 그룹 선택

**소스** 아래에서 **그룹**을 열면 그룹에 속한 회사를 볼 수 있습니다. 선택을 해제한 회사는 보고서에는 단독으로 남지만 그룹 합계에서는 제외됩니다. **Save group**을 클릭합니다. 변경 사항은 다음 **로드** 또는 **Apply changes** 때 적용됩니다. 새 회사는 선택을 해제하기 전까지 그룹에 포함됩니다.

그룹의 회계 연도는 프로젝트 변수 `group_fy_start_month`가 지정한 월에 시작하며, 변경하지 않으면 `1`입니다.

### 제공되는 결과

| 테이블 | 내용 |
|---|---|
| **Group P&L** | 엔터티, 기간, 라인(수익, 매출원가, 영업 비용, 영업 외, 회사 간 거래 차이)별로 한 행씩, 보고 통화로 표시합니다. 수익과 비용은 본래의 부호를 가집니다. |
| **Group P&L year to date** | 동일한 내용을 연초부터 그룹의 마지막으로 완전히 로드된 기간까지 누적한 값입니다. |
| **Intercompany pairs** | 엔터티 쌍, 그룹, 기간마다 한 행씩, 각 측의 금액과 잔차를 담습니다. |
| **Intercompany lines** | 그룹 수치 또는 쌍의 근거가 되는 원장 라인과 거래 상대방을 담습니다. |
| **대사** | 연초부터 누적한 그룹 손익계산서와 통합 시스템의 수치를 비교합니다. |

이 테이블에는 세 가지 엔터티 이름이 나타납니다.

| 엔터티 | 의미 |
|---|---|
| **Eliminations** | 회사 간 거래 소거. 합계가 0이 되므로 그룹 수치에는 포함하고, 소거 전 엔터티 합계에는 필터로 제외합니다. |
| **Group total** | 대사에서 사용되는 통합 시스템의 합계. |
| **Unmapped** | 기간이 없는 라인, 그리고 이 프로젝트에 없는 통합 시스템의 계정 또는 엔터티. |

지표 **Consolidated income**, **Consolidated result**, **IC difference**와 각 테이블의 분석 경로가 그룹에 대한 질문에 답합니다.

### 회사 간 거래 소거

회사 간 거래 라인은 거래 상대방으로 매칭됩니다. 라인에 있는 상대방을 사용하며, 라인에 없으면 해당 고객의 상대방을 사용합니다. 쌍의 양쪽이 소거되고, 양쪽이 일치하지 않는 금액은 회사 간 거래 차이 라인에 기록됩니다. 각 쌍에는 사유가 붙습니다.

| 사유 | 의미 |
|---|---|
| **일치** | 양쪽이 같은 금액을 기록했습니다. |
| **한쪽만 기록됨** | 한 엔터티는 거래를 기록했지만 상대방은 기록하지 않았습니다. |
| **소거되지 않음** | 쌍의 한 라인에 환율이 없어 어느 쪽도 소거되지 않습니다. |

쌍은 연초 누계를 기준으로 판단합니다. 쌍의 차이가 프로젝트 변수 `group_amber`(기본값 `1`)를 넘으면 **Intercompany balances** 행이 주황색으로, `group_red`(기본값 `1000`)를 넘으면 빨간색으로 바뀝니다. 상대방이 없거나 상대방이 엔터티가 아닌 라인은 소거되지 않으며 해당 행에 집계됩니다. 상대방 정보가 있는 소스와 없는 소스가 함께 있으면 주황색으로 표시됩니다.

소스 자체의 소거 엔터티는 그룹 손익계산서에서 제외되며, **통합** 행에 이 사실이 표시됩니다.

### 통합 시스템과 대사

통합 시스템이 보고하는 결과를 파일로 추가하고, 매핑을 확정할 때 **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** 옵션을 선택합니다. **Which version of the numbers is this?** 질문에는 시스템 이름으로 답합니다. 그러면 **대사** 테이블에 연초 누계 기준으로 엔터티와 라인별 **당사**, **보고됨**, **차이**가 표시됩니다. 차이는 보통 **Eliminations**, **Group total**, **Unmapped** 행이나 시스템이 사용하는 환율로 설명됩니다. **Reconciliation to the source** 행에는 `group_amber`를 넘는 모든 라인이 나열됩니다.

### 볼 수 있는 사용자

그룹 결과는 프로젝트의 행 액세스를 따릅니다. 행 액세스 때문에 그룹 결과를 볼 수 없으면 상태가 주황색으로 표시됩니다. 일부 엔터티만 볼 수 있는 사용자는 해당 엔터티의 소거 전 합계를 봅니다. **Eliminations** 행과 회사 간 거래 테이블을 보려면 모든 엔터티에 대한 액세스가 필요합니다.

프로젝트가 그룹 테이블에 없는 열(예: 부서)을 기준으로 어떤 사용자가 어떤 행을 볼 수 있는지 제한하는 경우, 그룹 결과는 모든 사용자에게 꺼진 상태로 유지되며 **통합**에 **Group views are off**라고 표시됩니다. 이 경우 아키텍트만 **그룹** 아래에서 **Everyone on the project may see the group results**를 선택할 수 있습니다. 변경 사항은 다음 **로드** 또는 **Apply changes** 때 적용됩니다.

## 최신 상태 유지

ERP 연결에서 가져온 로드가 문제 없이 성공하면 **마지막 로드** 카드에 **야간 새로 고침**이 나타납니다. 이를 클릭하면 사용자의 시간대 기준 매일 밤 2:00에 **로드**가 실행됩니다. 그러면 카드에 **Nightly refresh: Every night at 2:00**과 설정한 사람이 표시됩니다.

야간 로드는 설정한 사람의 권한으로 실행됩니다. 그 사람이 더 이상 ERP 연결을 사용할 수 없으면 그리드에 야간 로드가 건너뛰어졌다고 표시되므로 다시 설정하십시오. 샘플 데이터만 있는 프로젝트는 일정을 지정할 수 없습니다.

야간 로드에서 누락되었거나 비어 있는 파일이 있으면 오류가 아니라 경로를 알려 주는 경고와 함께 완료되며, 모델의 나머지는 계속 로드됩니다.

## 템플릿으로 모델 위에 구축

템플릿은 Common Finance Model 위에 보고서와 모델을 구축하므로 어떤 ERP가 데이터를 공급하든 동일하게 작동합니다. **Enterprise Profitability** 같은 템플릿으로 프로젝트를 시작하면 다음이 만들어집니다.

- [Common Finance Model 테이블](#common-finance-model-테이블)(비어 있거나 샘플 데이터로 채워짐).
- 해당 테이블에서 빌드한 **엔터티**, **계정**, **부서**, **고객**, **제품**, **세그먼트 1**, **세그먼트 2** 차원. [계층](#계층)을 참조하십시오.
- **로드** 워크플로와, 이 워크플로가 실행하여 ERP와 파일을 읽고, 표준화하고, 준비 상태를 검사하고, 템플릿의 모델을 빌드하는 워크플로.
- 템플릿 자체의 보고서와 모델. **Enterprise Profitability**는 수익, 매출원가(COGS), 매출총이익, 직접 및 간접 영업 비용, 공헌이익, 영업이익률이 포함된 손익계산서 테이블과, 전년 대비 및 예산 대비 마진 브리지를 추가합니다.
- 결과에 대해 질문하기 위한 지표와 분석 경로.

자체 ERP를 연결하기 전에 살펴보려면 프로젝트를 만들 때 **샘플 데이터로 시작**을 선택합니다. 프로젝트가 즉시 첫 번째 로드를 실행하므로 **Foundation** 탭에 미국 달러로 환산된 유로 엔터티를 포함한 완전한 예제가 표시됩니다. 자체 ERP를 연결하거나 자체 파일을 추가하면 샘플 행이 삭제되고 사용자의 데이터가 그 자리를 대신합니다.

## Foundation 탭

**Foundation** 탭에서 데이터를 연결하고, 로드하고, 검사합니다. 위에서 아래로 다음 섹션이 있습니다.

| 섹션 | 표시 내용 |
|---|---|
| **마지막 로드** | 마지막 로드의 성공, 실패 또는 실행 중 여부와 **로드**, **Apply changes**, **새로 고침**, **야간 새로 고침** 버튼. |
| **What to do next** | 주의가 필요한 항목을 중요한 순서대로 표시하며, 각각에 **검토** 또는 **Choose which source counts from when** 버튼이 있습니다. |
| **소스** | 각 소스를 순서대로 표시하며 **고급**, **Remove this source**, **그룹**, **Rename extra categories**가 있습니다. |
| **설정** | 설정 체크리스트: **데이터 연결**, **데이터 로드**, **합계 일치 여부 확인**, **계층 구조 검토**, **팀과 공유**. 현재 항목은 굵게 표시됩니다. |
| **파일** | 추가한 각 파일, 해당 데이터 세트(예: **총계정원장** 또는 **환율**), 매핑이 **✓ 확정됨**인지 **○ 확정 대기 중**인지. |
| **데이터 로드됨** | 각 엔터티에 대해 로드된 첫 번째와 마지막 기간 및 준비된 기간 수. |
| **기간** | 각 엔터티의 회계 기간과, 각 기간이 **✓ 종료됨**인지 **○ 열림**인지. |
| **준비 상태** | 준비 상태 그리드: 엔터티, 기간, 검사마다 한 행이며 상태와 **조치 사항**이 표시됩니다. |
| 연결 | ERP를 연결하고, 엔터티와 로드할 이력 개월 수를 선택하거나, 다른 소스를 추가합니다. |
| **파일** (추가) | CSV, TSV, TXT, Excel 또는 Parquet 파일을 추가하고 열 매핑을 확인합니다. |
| **로드** | 로드를 시작합니다. **Apply changes**는 ERP에서 가져오지 않고 로드를 실행합니다. |

로드가 실행되는 동안 탭은 자동으로 새로 고침됩니다.

설정 체크리스트로 진행 상황을 추적합니다.

- **데이터 연결**과 **데이터 로드**는 소스가 연결되고 로드가 성공하면 자동으로 체크됩니다.
- **합계 일치 여부 확인**은 합계 일치 검사를 통과하면 자동으로 체크됩니다.
- **계층 구조 검토**: **차원 열기**를 클릭해 엔터티, 계정, 부서 계층을 검토한 다음 **검토했습니다**를 선택합니다. 이 항목은 직접 확정해야 합니다.
- **팀과 공유**: 준비되면 프로젝트를 공유합니다. [프로젝트 액세스 관리](/ko/guides/projects/managing-projects/#프로젝트-액세스-관리)를 참조하십시오.

## Common Finance Model 테이블

Data Foundation은 ERP이든 파일이든 모든 소스를 동일한 열다섯 개의 테이블로 표준화하므로, 그 위에 구축된 보고서, 지표, 모델은 소스와 관계없이 동일하게 작동합니다. 각 행에는 소스 시스템과 읽은 시점도 기록됩니다. **데이터 세트** 열은 파일을 추가할 때 선택하는 이름입니다.

| 데이터 세트 | 테이블 | 내용 |
|---|---|---|
| 엔터티 | `cfm_entity` | 상위 엔터티, 현지 통화와 그룹 통화, 국가를 가진 법인. |
| 엔터티 매핑표 | `cfm_entity_map` | 소스 엔터티 코드와 각 코드가 속한 엔터티. [엔터티 매핑표](#엔터티-매핑표)를 참조하십시오. |
| 환율 | `cfm_fx_rate` | 통화 쌍별 월 평균, 기말, 과거 환율. [환율](#환율)을 참조하십시오. |
| 회계 달력 | `cfm_fiscal_calendar` | 엔터티 회계 기간마다 한 행이며, 시작일과 종료일, 마감 여부를 담습니다. |
| 계정과목표 | `cfm_account` | 상위 계정, 유형(`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), 재무제표, 정상 잔액, 환율 유형을 가진 계정. |
| 부서 | `cfm_department` | 상위 부서와 이익 센터를 가진 부서 및 비용 센터. |
| 제품 | `cfm_product` | 상위 제품, 제품군, 그룹, 단위, 표준 비용을 가진 제품 마스터. |
| 고객 | `cfm_customer` | 상위 고객, 그룹, 리전, 국가를 가진 고객 마스터. 고객 이름은 마스킹되지 않습니다. |
| 세그먼트 값 | `cfm_segment` | 이름과 상위를 가진 세그먼트 값. [계층](#계층)을 참조하십시오. |
| 총계정원장 | `cfm_gl_journal` | 거래 통화, 현지 통화, 보고 통화의 분개 라인. |
| 시산표 | `cfm_trial_balance` | 엔터티, 계정, 부서별 기간 차변, 대변, 순액(현지 통화와 보고 통화). |
| 판매 라인 | `cfm_sales_line` | 수량, 총액, 할인, 순액, 매출원가 금액이 있는 청구된 판매 라인. |
| 재고 잔액 | `cfm_inventory_balance` | 제품과 창고별 기말 재고. |
| 예산 | `cfm_budget` | 시나리오, 버전, 계정, 부서별 예산 및 예측. |
| 배부 동인 | `cfm_stat_driver` | 인원수, 제곱피트, 수량 같은 통계 동인. |

기간은 `YYYY-MM`으로 표기하며, 거래는 전기 기간 기준으로 배치됩니다. 예산은 선택 사항입니다. 예산이 없는 ERP도 나머지는 모두 로드됩니다.

시산표 파일은 차변 및 대변 열, 순액 열 또는 둘 다를 가질 수 있습니다. 차변과 대변만 있으면 순액은 차변에서 대변을 뺀 값이며 비어 있는 쪽은 0으로 계산합니다. 순액만 있으면 양수 순액은 차변이 되고 음수 순액은 양수 금액으로서 대변이 됩니다. 부서 열은 선택 사항입니다.

## 문제 해결

| 증상 | 조치 |
|---|---|
| **연결 테스트**에서 ERP가 자격 증명을 거부했다고 표시됨 | 연결의 자격 증명을 확인하고, 통합 사용자가 ERP에 로그인할 수 있는지 확인합니다. |
| 어떤 데이터 세트에 대해 **연결 테스트**가 **권한 누락**을 표시함 | ERP 관리자에게 표시된 권한을 추가해 달라고 요청합니다. ERP의 [연결 가이드](/ko/guides/connections/)에 연결에 필요한 권한이 나와 있습니다. |
| ERP 오류 메시지가 ERP 자체의 메시지보다 짧음 | PlaidCloud는 공급자 오류를 표시하기 전에 자격 증명, 토큰, 키를 제거하므로 일부 세부 정보가 빠집니다. **연결 테스트**를 실행하여 영향을 받는 데이터 세트를 확인하십시오. |
| 어떤 기간에 대해 **데이터 로드됨**이 문제임 | 해당 기간의 ERP 읽기가 실패했습니다. **로드**를 다시 실행하십시오. 이미 로드된 기간은 건너뜁니다. |
| **계정과목표에 없는 계정**이 문제임 | ERP나 파일의 계정과목표에 누락된 계정을 추가하고 **로드**를 다시 실행하십시오. |
| **통화 환산**이 문제임 | 엔터티의 통화에 해당 기간의 보고 통화 환율이 없거나, 단일 보고 통화를 찾을 수 없습니다. **환율** 파일에 환율을 추가하거나, 연결이 ERP의 환율을 읽을 수 있는지 확인하거나, 프로젝트 변수 `reporting_currency`를 설정합니다. 그런 다음 **로드**를 다시 실행하십시오. |
| **통화 환산**에 조치가 필요함 | 재무상태표, 재고, 예산 행에 해당 기간의 기말, 과거 또는 계획 환율이 없습니다. 손익계산서에는 영향이 없습니다. 예산 월의 계획 환율을 포함해 환율을 추가하고 **로드**를 다시 실행하십시오. |
| **Codes waiting for your answer**에 조치가 필요함 | **검토**를 클릭하고 각 코드에 답한 다음 **Apply changes**를 클릭합니다. |
| **Which source covers which months**에 조치가 필요함 | **Choose which source counts from when**을 클릭하고 소스를 선택한 다음 **Apply changes**를 클릭합니다. |
| **Intercompany balances**가 빨간색 또는 주황색임 | **Intercompany pairs**에서 쌍을 확인합니다. 누락된 쪽을 기록하거나, 라인에 거래 상대방을 추가하거나, 누락된 환율을 추가합니다. |
| **Group views are off** | 아키텍트에게 **그룹** 아래의 **Everyone on the project may see the group results**를 선택하도록 요청합니다. |
| **매핑되지 않은 엔터티**가 문제임 | 엔터티 마스터에 엔터티를 추가하거나, **엔터티 매핑표** 파일에서 코드를 기존 엔터티에 매핑한 다음 **로드**를 다시 실행하십시오. |
