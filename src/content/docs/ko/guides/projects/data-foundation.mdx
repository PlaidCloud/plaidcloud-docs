**Data Foundation**은 PlaidCloud 프로젝트의 재무 데이터 기반입니다. **Common Finance Model**은 여러 ERP 시스템과 각 시스템의 여러 인스턴스에서 가져온 ERP 데이터를 하나의 계정과목표, 하나의 엔터티 집합, 하나의 보고 통화를 갖춘 단일 모델로 통합합니다. 이 모델을 기반으로 만든 보고서, 지표, AI 어시스턴트는 데이터가 어느 ERP에서 왔든 모두 같은 숫자를 읽습니다.

ERP는 PlaidCloud 연결을 통해 연결되므로 총계정원장, 시산표, 마스터 데이터, 예산이 내보내기 작업 없이 소스에서 직접 들어옵니다. 파일은 환율, 배부 동인, ERP 외부에서 관리하는 예산처럼 시스템에 없는 데이터를 추가하며, 해당 파일이 다루는 ERP 행을 대체할 수도 있습니다. **로드**는 프로젝트 **홈** 레일의 **Data Foundation** 그룹에서 모든 소스를 모델에 맞게 표준화하고, 보고 통화로 환산하고, 합계가 일치하는지 검사합니다. 두 번째 시스템을 추가하면 이미 연결된 시스템과 같은 계정 코드를 사용하는지 등 주제별로 질문 하나에 답하며, 관리 통합은 내부거래를 제거한 그룹 손익계산서를 만듭니다. Data Foundation은 어떤 프로젝트에든 추가할 수 있으며, **Enterprise Profitability** 같은 솔루션은 그 위에 보고서와 모델을 구축합니다.

## Data Foundation 사용 시작

Data Foundation으로 프로젝트를 시작하거나 기존 프로젝트에 Data Foundation을 추가할 수 있습니다.

- **새 프로젝트.** Analyze에서 **프로젝트**를 열고 **새 프로젝트**를 클릭합니다. **시작 기준**에는 **Blank**, **Data Foundation**, **Enterprise Profitability**, **Cost to Serve**, **Operational Transfer Pricing**, **템플릿 파일에서**가 나열되며, 목록 아래 줄에 선택한 항목이 무엇을 제공하는지 설명이 표시됩니다. **Data Foundation**은 모델과 해당 보고서만 제공합니다. 세 가지 솔루션은 각각 Data Foundation을 포함하며 자체 모델을 추가합니다. 아무것도 연결하기 전에 완전한 예제를 보려면 **샘플 데이터로 시작**을 선택합니다. **만들기**를 클릭합니다. 프로젝트를 공유하기 전까지는 본인만 볼 수 있으며, 본인이 유일한 아키텍트입니다.
- **처음 로그인할 때.** 프로젝트를 만들 수 있으면 처음 로그인할 때 표시되는 환영 화면에서 **재무 시스템 연결**을 제공합니다. 이 옵션은 Data Foundation 프로젝트를 만들고 이름을 지정한 다음, 빌드되는 동안 프로젝트를 엽니다.
- **기존 프로젝트.** 프로젝트의 **홈**을 엽니다. 레일의 **Data Foundation** 제목 아래에 있는 **Data Foundation** 행에 그 내용이 설명되며, 프로젝트의 아키텍트에게는 **Data Foundation 추가**가 표시됩니다. 빌드는 백그라운드에서 실행되며 페이지에 **Data Foundation을 추가하는 중입니다. 몇 분 정도 걸립니다.** 메시지가 표시됩니다. 사용자의 워크플로, 테이블 및 기타 작업은 그대로 유지됩니다. 모델이 사용하는 위치에 프로젝트의 테이블이 이미 있으면 아무것도 설치되지 않으며 메시지에 해당 테이블 이름이 표시됩니다.

**홈**은 모든 프로젝트의 첫 번째 탭입니다. 프로젝트에 Data Foundation이 있으면 레일의 **Data Foundation** 그룹에 다음 행이 표시되며, 각 행에는 고유한 링크가 있습니다.

| 행 | 표시되는 경우 |
|---|---|
| **요약** | 항상 표시됩니다. Data Foundation이 있지만 아직 시스템이 없는 프로젝트는 이 행에서 열립니다. |
| **시스템** | 프로젝트에 시스템이 둘 이상 있거나, 액세스를 기다리는 시스템이 있거나, **요약**의 다음 단계가 시스템 추가, 연결 또는 최신 상태 유지인 경우 표시됩니다. |
| **질문** | 답변을 기다리는 질문이 있는 동안 표시되며, 질문 수가 배지로 표시됩니다. |
| **보고서** | 항상 표시됩니다. |
| **배부** | 솔루션으로 만든 프로젝트에서 표시됩니다. |

## ERP 연결

재무 시스템은 PlaidCloud 연결을 통해 Data Foundation에 연결됩니다. Data Foundation은 총계정원장, 시산표, 마스터 데이터, 환율, 예산과, 시스템에 있는 경우 보조원장, 월말 잔액 및 은행 잔액을 시스템에서 직접 읽으며, 읽기만 합니다. 자격 증명은 표준 연결 편집기에서만 입력합니다. 각 시스템에는 액세스 권한을 부여하는 관리자를 위한 페이지가 있으며 [모델에 데이터를 제공할 수 있는 시스템](/ko/guides/projects/data-foundation-getting-started/#모델에-데이터를-제공할-수-있는-시스템)에 나열되어 있고, [Data Foundation 지원 범위 매트릭스](/ko/reference/data-foundation-coverage-matrix/)에서 각 시스템이 직접 제공하는 데이터 세트를 확인할 수 있습니다.

<Steps>

1. **요약**에서 **재무 시스템 추가**를 클릭합니다. **시스템**이 열립니다.

2. **시스템 추가**의 **시스템**에서 사용하는 시스템을 선택합니다. 다음 단계는 시스템의 로그인 방식에 따라 다릅니다.

   - **QuickBooks Online 및 Xero**는 시스템 자체 창에서 액세스를 승인하여 로그인합니다. **Connect to**와 시스템 이름이 표시된 버튼을 클릭합니다. PlaidCloud가 프로젝트 환경에 대한 연결을 만들고 승인 창을 엽니다. 승인하면 시스템이 추가되고 로드가 시작됩니다. 브라우저가 창을 차단하면 사이트의 팝업을 허용하고 다시 시도하십시오.
   - **자격 증명으로 로그인하는 시스템**은 **연결** 아래에 사용할 수 있는 같은 종류의 연결을 첫 번째 연결이 선택된 상태로 나열하며, **새 연결**도 함께 표시합니다. 하나를 선택하고 **시스템 추가**를 클릭합니다. **새 연결**을 선택하면 프로젝트 환경이 입력된 표준 연결 편집기가 열리며, 연결을 저장하면 시스템이 추가됩니다.
   - **SAP S/4HANA, SAP ECC, Oracle E-Business Suite 및 Sage 100**은 네트워크의 PlaidLink 에이전트를 통해 연결합니다. 먼저 에이전트를 설정한 다음, 자격 증명으로 로그인하는 다른 시스템과 마찬가지로 해당 연결을 선택합니다.

3. 시스템을 추가하기 전에 로드할 내용을 변경하려면 **옵션**을 엽니다. **회사**에는 시스템의 회사가 나열됩니다. 로드할 회사를 선택하거나, 모두 로드하려면 아무것도 선택하지 않습니다. 회사를 나열하지 않는 시스템은 회사를 입력하도록 요청합니다. **이력 개월 수**는 몇 개월 전까지 로드할지를 1~120 사이로 지정합니다. 일부 시스템에는 **시스템 설정**도 있으며, 반드시 필요한 설정이 있는 시스템은 **옵션**을 열고 해당 설정을 요청합니다. **옵션**을 사용하지 않으면 모든 활성 회사와 24개월의 이력이 로드됩니다.

4. 연결과 함께 추가한 시스템은 즉시 로드를 시작합니다. 다른 워크플로가 같은 연결을 사용하면 로드가 연결에서 데이터를 읽어 해당 워크플로의 속도를 늦출 수 있으므로, PlaidCloud가 먼저 해당 워크플로의 이름과 함께 **공유 연결에서 로드하시겠습니까?** 메시지를 표시합니다. 계속하려면 **그래도 로드**를 클릭합니다.

</Steps>

아직 액세스 권한이 없습니까? 시스템을 선택하고 대신 **아직 액세스 권한이 없으십니까?** 버튼을 클릭합니다. 시스템이 **액세스 대기 중**으로 추가되고, 대기 중인 모든 시스템을 포함하는 요청 하나가 표시되며, **요청 복사** 또는 **이메일 요청**으로 바로 보낼 수 있습니다. 액세스 권한을 받으면 **시스템 추가**에서 해당 연결로 시스템을 추가합니다. QuickBooks Online 및 Xero의 경우 시스템 행에서 **연결**을 클릭합니다.

다른 시스템이나 다른 인스턴스를 가져오려면 같은 방법으로 추가합니다. 시스템을 추가해도 다른 시스템은 항상 그대로 유지되므로 여러 시스템과 인스턴스가 하나의 통합 모델에 데이터를 제공합니다. 두 번째 시스템을 추가하면 Data Foundation은 코드마다 질문하는 대신 주제별로 질문 하나를 합니다. [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오.

각 로드는 변경된 내용만 읽습니다. 미마감 기간과 마지막 마감된 기간은 다시 읽고, 이미 로드된 마감된 기간은 그대로 유지합니다. **이력 개월 수**를 늘리면 추가된 개월만 읽습니다. 환율, 엔터티 매핑표 또는 보고 통화가 변경되면 영향을 받는 개월을 다시 읽습니다.

## 시스템

프로젝트가 로드하는 모든 시스템과 인스턴스는 소스이며, 확정한 파일도 소스입니다. 레일의 **시스템** 행과 이에 따른 페이지, 버튼, **파일** 카드는 프로젝트에 시스템이 둘 이상 있거나, 액세스를 기다리는 시스템이 있거나, **요약**의 다음 단계가 시스템 추가, 연결 또는 최신 상태 유지인 경우에 표시됩니다. 로드되어 최신 상태로 유지되는 시스템이 하나뿐이면 대신 **요약**의 **내 시스템** 아래에 표시됩니다. **시스템** 페이지에는 모든 시스템이 **시스템**, **상태**, **마지막 로드**와 함께 나열됩니다. **상태**는 **액세스 대기 중**, **연결됨**, **로드 중**, **로드됨**, **실패** 중 하나입니다. **마지막 로드**에는 시스템이 마지막으로 로드된 시점 또는 **아직 로드되지 않음**이 표시되며, 프로젝트가 일정에 따라 새로 고쳐지면 다음 새로 고침 예정 시각이나 기한을 넘긴 시점도 표시됩니다. 실패한 시스템의 행에는 그 이유가 표시됩니다.

각 행에는 시스템 상태에 맞는 버튼이 있습니다.

| 버튼 | 표시되는 경우 |
|---|---|
| **로드** | 시스템이 연결되었거나 로드된 경우. 해당 시스템만 읽은 다음 모든 시스템의 데이터로 모델을 다시 만듭니다. 실패한 시스템에는 해결 방법 옆에 이 버튼이 표시됩니다. |
| **연결 열기** | 시스템 로드에 실패한 경우. 연결을 열어 원인을 확인하고 수정합니다. |
| **다시 연결** | QuickBooks Online 또는 Xero 로그인이 만료된 경우. |
| **연결** | QuickBooks Online 또는 Xero가 액세스를 기다리는 경우. |
| **액세스 요청** | 자격 증명으로 로그인하는 시스템이 액세스를 기다리는 경우. 다시 보낼 요청을 표시합니다. |

그 옆의 **연결 테스트**는 로그인하여 각 데이터 세트를 읽어 본 다음 각각을 **읽기 가능**, **권한 누락** 또는 **오류**로 나열하고, 시스템 관리자에게 추가를 요청할 권한을 알려 줍니다. **제거**는 **이 시스템을 제거하시겠습니까?** 메시지를 확인한 후 프로젝트에서 시스템을 제거합니다. 시스템에서 로드한 모든 항목이 삭제되며, 나중에 다시 연결할 수 있습니다.

시스템의 사용 방식을 변경하려면 시스템에서 **편집**을 클릭하고 다음 항목을 변경한 다음 **저장**을 클릭합니다.

| 설정 | 기능 |
|---|---|
| **이름** | 보고서, 질문, 메시지에서 시스템을 가리키는 레이블입니다. |
| **보고 장부(쉼표로 구분)** | 장부를 둘 이상 관리하는 시스템에서 읽을 회계 장부입니다. **모든 보고 장부**는 모든 장부를 읽습니다. |
| **이 소스가 제공하는 월** | 각 **회사**에 대해 시스템이 제공하는 월로, 첫 월은 **시작 (2026-01)** 열에, 마지막 월은 **종료 (2026-12)** 열에 지정합니다. 제한하지 않으려면 월을 비워 둡니다. 월은 연도와 월로 작성합니다. 예: `2026-03` |
| **이 소스의 추가 범주** | 시스템에 있는 각 추가 범주의 **이름**과 **표시 위치**, 또는 **제외**입니다. |
| **회사** 및 **이력 개월 수** | 시스템이 로드하는 회사와 로드할 이전 개월 수입니다. |

회사를 추가하거나 아무것도 선택하지 않으면 즉시 저장됩니다. 회사를 제외하면 먼저 **불러올 회사를 줄이시겠습니까?** 메시지에서 확인을 요청합니다. 저장하면 해당 시스템에서 로드한 모든 항목이 즉시 지워지고, 다음 **로드**에서 선택한 회사를 다시 가져오기 때문입니다.

두 시스템이 같은 회사의 같은 월을 제공하면, 어느 시점부터 어느 소스를 집계할지 선택할 때까지 목록에서 위에 있는 시스템이 집계됩니다. [기간별 기준 소스 선택](#기간별-기준-소스-선택)을 참조하십시오.

소스를 변경해도 ERP를 다시 읽지는 않습니다. **변경 사항 적용**을 클릭할 때까지 모든 페이지 위에 **소스를 변경하셨습니다. 적용하려면 변경 사항 적용을 누르십시오.** 표시줄이 나타납니다. 이 버튼은 이미 가져온 데이터로 로드를 실행합니다. 즉, 새 매핑, 이름, 파일로 소스를 다시 표준화하고 모델을 다시 작성합니다. 시스템에서 최신 데이터도 가져오려면 **로드**를 클릭합니다.

## ERP 외부 데이터용 파일 추가

파일은 환율, 배부 동인, 엔터티 코드의 [코드 매핑](#엔터티-매핑표), ERP 외부에서 관리하는 예산처럼 시스템에 없는 데이터로 ERP 연결을 보완합니다. 각 파일은 [Common Finance Model 테이블](#common-finance-model-테이블)에 나열된 데이터 세트 중 하나에 속합니다.

<Steps>

1. **시스템**의 시스템 목록 아래에 있는 **파일** 카드에서 파일을 저장할 **문서 계정**을 선택합니다.

2. CSV 또는 Excel 파일을 **CSV 또는 Excel 파일을 여기에 놓으십시오** 영역에 끌어다 놓거나 **파일 선택**을 클릭합니다. 파일은 문서 계정의 `/foundation/` 폴더에 업로드됩니다.

   문서 계정에 이미 있는 파일이면 **파일을 추가하는 다른 방법**을 열고 **문서 계정에 이미 있는 파일 추가**에서 `/foundation/budget.csv`처럼 경로를 입력한 다음 **파일 추가**를 클릭합니다.

   매월 새 파일을 읽으려면 **폴더의 일치하는 파일 모두 추가**를 사용합니다. 폴더를 입력하고, 입력한 값과 파일 이름을 비교할 조건으로 **포함**, **다음으로 시작**, **다음으로 끝남**, **이(가) 정확히 일치** 또는 **패턴 일치(\*는 모든 문자)** 중 하나를 선택한 다음 **파일 추가**를 클릭합니다. 하위 폴더의 파일은 읽지 않습니다.

3. PlaidCloud가 파일을 읽고 매핑을 제안합니다.

   - **구분 기호, 소수점 구분 기호, 날짜 감지.** 구분 기호(쉼표, 세미콜론, 탭 또는 파이프), 소수점 구분 기호, 날짜 형식이 자동으로 감지됩니다.
   - **데이터 세트**: 파일 이름과 열 머리글을 기준으로 일치시킨, 파일이 속하는 Common Finance Model 테이블입니다. 일치 여부가 명확하지 않으면 목록에서 선택합니다.
   - **소수점 구분 기호**: **마침표 (1,234.56)** 또는 **쉼표 (1.234,56)**.
   - **날짜 형식**: 파일에 날짜가 있을 때 표시됩니다. 감지된 형식이 잘못되었으면 `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` 또는 `MM/DD/YYYY` 중에서 변경합니다.
   - **파일의 열**, **유형**, **예제**, **이동 위치**로 구성된 그리드입니다. 열을 다른 필드로 보내려면 **이동 위치**를 변경하고, 로드하지 않으려면 **로드 안 함**으로 변경합니다.

4. **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?**, **Are revenues shown as negative numbers?** 같이 파일과 관련된 질문에 답합니다. 각 질문은 파일에 해당 정보가 아직 없을 때만 표시됩니다.

5. 각 열이 어디로 이동하는지 확인한 다음 **매핑 확정**을 클릭합니다. 처리하는 동안 버튼 아래의 메모에 대기 중인 이유가 표시됩니다. 아직 샘플 데이터가 있는 프로젝트에서는 처음 확정하는 파일이 샘플도 제거하며, 이 작업은 몇 분 정도 걸릴 수 있습니다.

</Steps>

다음 옵션은 해당되는 경우 파일에 표시됩니다.

| 옵션 | 용도 |
|---|---|
| **Which source do these rows apply to?** | 코드 맵 파일을 하나의 소스로 제한합니다. **Every source**는 모든 소스에 적용합니다. |
| **Where does this file come from?** | 파일에 **This project's own codes**가 있는지, 아니면 이름을 지정한 **Another system**(예: `SAP Germany export`)에서 온 것인지 지정합니다. 다른 시스템에서 온 파일은 ERP 소스와 마찬가지로 공유 코드를 검사합니다. |
| **Split … into … parts at each …**(**고급** 아래) | `100-200-300`처럼 여러 값이 들어 있는 하나의 열을 분할하여 각 부분을 별도 필드로 보냅니다. |
| **Which currency do you report in?** | 프로젝트에 아직 보고 통화가 없을 때 보고 통화를 설정합니다. 세 글자로 작성합니다. 예: `USD` |
| **연결 결과 또는 보고된 손익입니다(OneStream, Anaplan, SAP Group Reporting, FCCS)** | 그룹 손익계산서를 [대사](#통합-시스템과-대사)할 수 있도록 통합 시스템의 결과를 로드합니다. |

프로젝트에서 파일을 빼려면 **파일** 아래에서 파일 옆의 **제거**를 클릭하거나 매핑에서 **Remove this file**을 클릭하고 확인합니다. 다음에 **Apply changes**를 클릭하면 해당 파일의 수치가 보고서에서 제외됩니다.

예를 들어 날짜를 일/월 또는 월/일로 모두 읽을 수 있는 파일처럼 PlaidCloud가 데이터 세트, 소수점 구분 기호 또는 날짜 순서를 스스로 결정할 수 없으면 확정하기 전에 선택하라는 메시지가 표시됩니다. 같은 데이터 세트에 두 번째 파일을 추가하면 첫 번째 파일이 대체됩니다. 이후 파일의 열이 데이터 세트와 일치하지 않으면 로드에서 파일과 열 이름을 알려 주고 파일이나 열 이름을 수정하거나 단계의 **Schema Mismatch**를 `union`으로 설정하라고 안내합니다.

허용되는 파일은 CSV, TSV, TXT 텍스트 파일, Excel `.xlsx` 파일(첫 번째 시트를 읽음), Parquet 파일입니다.

<Aside type="note">
파일이 없거나 비어 있어도 로드가 중단되지 않습니다. 이런 파일을 추가하면 아직 매핑할 내용이 없다고 표시되며, 로드는 경로를 알려 주는 경고와 함께 완료되고 해당 데이터 세트는 비어 있는 상태로 남습니다. 파일이 생기면 다시 추가합니다.
</Aside>

## 데이터 로드

로드는 연결된 시스템과 확정된 파일을 읽어 Common Finance Model에 맞게 표준화하고, 보고 통화로 환산하고, 준비 상태 검사를 실행하고, 모델을 다시 만듭니다. 연결과 함께 추가한 시스템은 첫 번째 로드를 자동으로 시작합니다. 아무것도 로드되기 전에는 **로드**가 **요약**의 다음 단계이기도 합니다. 그 이후에는 **시스템**에서 시스템 행의 **로드**가 해당 시스템만 읽은 다음 모든 시스템의 데이터로 표준화, 재구축, 통합을 수행하므로, 시스템을 추가해도 다른 시스템을 다시 읽지 않습니다. 로드가 실행되는 동안 **요약**에 로드 중인 항목이 표시됩니다.

- 프로젝트당 한 번에 하나의 로드만 실행됩니다. 두 번째 **로드** 또는 **Apply changes**를 실행하면 이미 로드가 실행 중이라는 메시지가 표시되며, 로드가 실행되는 동안에는 소스를 변경할 수 없습니다.
- 다른 워크플로가 같은 연결을 사용하는 경우, 로드가 시스템에서 데이터를 읽으면서 해당 워크플로의 속도를 늦출 수 있으므로 첫 번째 로드에서 해당 워크플로를 나열하고 확인을 요청합니다. 계속하려면 **그래도 로드**를 클릭합니다.
- PlaidCloud가 업그레이드된 후 아키텍트가 **로드** 또는 **변경 사항 적용**을 실행하면 프로젝트에서 생성된 워크플로도 업데이트되며, 워크플로에 필요한 작업 테이블이 만들어집니다. 새 버전의 모델을 사용할 수 있으면 모든 Data Foundation 페이지 위의 표시줄에 **Update available**과 함께 아키텍트의 **로드** 또는 **변경 사항 적용**으로 설치된다는 안내가 표시됩니다. 관리자가 **로드**를 실행하면 아키텍트만 업데이트할 수 있다는 경고가 표시됩니다.
- 업데이트를 적용해도 생성된 단계에 직접 수정한 내용은 유지됩니다. 사용자가 변경한 단계를 업데이트에서도 변경한 경우 사용자의 수정 내용이 유지됩니다. 사용자가 수정한 단계를 업데이트에서 더 이상 생성하지 않으면 해당 단계는 유지되지만 비활성화됩니다. 단계를 삭제하거나, 계속 필요하면 다시 활성화합니다. 업데이트로 대체되는 단계는 이름이 표시되며, 이전 단계는 단계 버전에 남아 있습니다.
- 업데이트가 중간에 중단되면 업데이트가 완료될 때까지 단계가 순서 없이 실행될 수 있습니다. 업데이트를 완료하려면 아키텍트로서 **로드**를 다시 누릅니다. 다시 중단되면 지원팀에 문의하십시오.
- 로드에 실패한 시스템은 **시스템**에 **실패**로 표시되며, 그 이유와 해결 방법이 함께 표시됩니다. 마지막 로드가 경고와 함께 끝나면 **요약**에 **The last Load ended with a warning:** 다음에 경고가 표시됩니다.
- 하나의 엔터티와 기간을 읽지 못해도 나머지는 계속 로드됩니다. 실패한 항목만 가져오려면 **로드**를 다시 실행합니다.
- 소스의 데이터 세트 하나를 읽지 못해도 소스의 나머지는 계속 로드되며, 해당 데이터 세트는 기존 행을 유지하고, 로드에서 해당 데이터 세트를 읽을 때까지 시스템이 **시스템**에 **실패**로 표시됩니다.

### 보류된 행

소스가 겹치면 로드는 각 수치를 한 번만 집계합니다. 집계하지 않는 행은 보존되거나 보류됩니다.

보존된 행은 집계되지 않은 것으로 표시된 채 프로젝트에 남으므로, 시스템에 있는 데이터는 손실되지 않고 이중으로 집계되지도 않습니다. 다음과 같은 행은 보존됩니다.

- 소스가 읽도록 설정되지 않은 다른 회계 장부(예: 현지 장부 또는 세무 장부)에 있는 행
- 회사에 설정된 **시작** 및 **종료** 월을 벗어나는 행
- 다른 소스가 집계하는 회사와 월에 해당하는 행(예: 엔터티가 이전하기 전의 시스템)
- 해당 엔터티와 월에 대해 파일로 대체된 행

보류된 행은 소스, 엔터티, 사유와 함께 기록되며, 로드는 건수를 알려 주는 경고와 함께 완료됩니다. 예: `120 rows of NetSuite EU carrying a code another source also uses`. 사유는 다음과 같습니다.

| 사유 | 의미 |
|---|---|
| 소스의 이전 파일에도 있음 | 같은 소스의 이전 파일이 이미 해당 월을 다룹니다. |
| 이후의 기초 잔액 | 엔터티의 가장 이른 기초 잔액과 그 이후의 활동이 이미 집계됩니다. |
| 다른 소스도 사용하는 코드를 포함함 | 코드에 대한 답변이 필요합니다. [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오. |
| 두 코드에 매핑된 코드를 포함함 | 코드 맵이 해당 코드에 두 가지 답을 지정합니다. |
| 자체 마스터에 없는 코드를 포함함 | 시스템 자체의 계정, 제품 또는 고객 목록에 해당 코드가 없습니다. |
| 보고서 합계 또는 빈 라인 | 파일의 합계 행 또는 빈 행입니다. |

통계 계정은 원장 대신 배부 동인으로 이동하며, 문제가 아닌 이동된 항목으로 표시됩니다.

### ERP 데이터와 파일 함께 사용

파일은 파일이 다루는 범위만 대체하며, ERP의 나머지 행은 그대로 유지됩니다.

- **마스터 파일**(계정, 부서, 고객, 제품, 세그먼트 값)은 같은 코드를 가진 ERP 행을 대체합니다.
- **트랜잭션 파일**은 같은 엔터티와 월의 ERP 행을 대체합니다. 총계정원장 및 시산표 파일은 원장으로도 일치시키고, 예산 파일은 시나리오로, 통계 동인 파일은 시나리오와 동인으로 일치시킵니다.

나중에 파일이 특정 월을 더 이상 다루지 않으면 다음 로드에서 해당 월의 ERP 데이터가 다시 반영됩니다.

## 엔터티 매핑표

각 소스는 자체 코드로 엔터티 이름을 지정합니다. **코드 매핑** 파일은 이러한 코드를 엔터티 마스터의 엔터티에 매핑하므로 모든 소스의 라인이 같은 엔터티에 반영됩니다.

코드 매핑을 사용하려면 CSV 또는 Excel 파일을 추가하고 **코드 매핑** 데이터 세트를 선택합니다.

| 열 | 내용 |
|---|---|
| `source_code` | 소스에 기록된 코드(예: 회사 코드)입니다. `source_entity`라는 열도 이 열에 일치시킵니다. |
| `code` | 코드가 속하는 엔터티로, 엔터티 마스터에 지정된 이름입니다. `entity`라는 열도 이 열에 일치시킵니다. |

파일에 다르게 지정하는 `dimension` 열이 없으면 각 행은 엔터티 코드를 매핑합니다. [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오.

- 코드 매핑에 없는 코드는 그대로 사용됩니다.
- 여러 코드를 하나의 엔터티에 매핑할 수 있습니다. 해당 라인은 합쳐지며, 모든 코드에서 마감된 월만 마감된 것으로 간주됩니다.
- **이 행은 어느 소스에 적용되나요?** 옵션에서 소스를 선택하지 않으면 파일의 행은 모든 소스에 적용되므로, 두 소스가 같은 코드를 서로 다른 엔터티에 사용하는 경우 파일을 하나의 소스로 제한하십시오.
- **엔터티** 파일 행은 같은 엔터티 코드를 가진 ERP 엔터티를 대체합니다.

**Every entity known** 검사는 엔터티가 엔터티 마스터에 없고 코드 매핑으로 매핑되지도 않은 라인을 표시합니다. 엔터티 마스터가 로드될 때까지는 해당되지 않습니다.

## 소스 간 코드 매핑

두 시스템이 같은 코드를 서로 다른 대상에 사용하거나, 서로 다른 코드를 같은 대상에 사용할 수 있습니다. 이미 연결된 시스템과 코드가 겹치는 시스템을 추가하면 Data Foundation은 코드마다 질문하는 대신 주제별로 질문 하나를 합니다. 예: **Does SAP ECC use the same account codes as NetSuite?** 계정, 부서, 이익 센터, 사이트, 제품, 고객 및 각 추가 범주에 대해 이렇게 질문합니다.

각 질문은 Weave가 제안한 답변과 그 근거(예: 공유 코드 중 이름이 같은 코드 수)와 함께 **질문** 페이지에서 대기하며, 답변할 때까지 보류되는 행 수를 알려 줍니다. 다른 시스템과 같은 코드이면 **Same codes as**, 다른 코드이면 **Different codes from**으로 답합니다.

- 답변할 때까지 공유 코드를 포함한 행은 보류되므로 각 금액은 한 번만 집계됩니다.
- 시스템이 같은 코드를 사용한다고 답하면, 나중에 해당 시스템에 새로 나타나는 코드는 새 질문 없이 다른 시스템의 코드로 간주됩니다.
- 매핑은 시스템과 차원별로 유지되므로 한 시스템의 부서에 대한 답변이 다른 시스템의 계정을 변경하지 않습니다.
- 답변은 다음 **로드** 또는 **변경 사항 적용** 때 적용되며, **요약**의 **기록**에 답변한 사람, 시각, 이전 값이 기록됩니다.

매핑을 파일로 제공할 수도 있습니다. **Code map** 데이터 세트로 파일을 추가하고, 하나의 소스로 제한하려면 **Which source do these rows apply to?** 를 선택합니다.

## 기간별 기준 소스 선택

엔터티가 한 시스템에서 다른 시스템으로 이전하면 두 시스템 모두에 해당 엔터티가 있습니다. **질문**에서는 **From which month does** 새 시스템 **count for** 해당 엔터티라는 질문으로 새 시스템이 어느 월부터 집계되는지 묻고, 이전 시스템의 마지막 원장 월의 다음 월을 제안합니다. 이전 시스템은 그 이전 월을 유지합니다.

**요약**의 **소스 적용 범위** 카드에는 두 소스가 모두 제공하는 그 밖의 월이 나열됩니다. **문제**에서 한 회사에 대해 겹치는 두 소스의 경우 **해당 월**에 `2026-04`처럼 월을 입력하고 **해당 월부터 어느 소스를 사용합니까?** 목록에서 소스를 선택하고 **선택 저장**을 클릭한 다음 페이지 위 표시줄에서 **변경 사항 적용**을 클릭합니다. 선택하기 전까지는 두 소스 중 첫 번째 소스만 집계되며, 다른 소스는 입력한 월 이전의 월을 유지합니다. **조치 필요**에서는 한 회사에 대해 서로 다른 환율을 제공하는 두 소스처럼 설명된 방식으로 집계되는 겹침을 설명하고, 어느 쪽 환율이 사용되는지 알려 줍니다.

## 통화 환산

각 로드는 총계정원장, 시산표, 판매, 재고, 예산, 보조원장 금액을 현지 통화에서 하나의 보고 통화로 환산합니다. 보고서와 모델은 환산된 금액을 읽으므로 어느 시스템에서 왔든 통화가 서로 다른 엔터티도 올바르게 합산됩니다.

### 보고 통화

보고 통화를 선택하려면 프로젝트 변수 `reporting_currency`를 `USD` 같은 통화 코드로 설정합니다. [프로젝트 변수 관리](/ko/guides/projects/managing-projects/#프로젝트-변수-관리)를 참조하십시오. 엔터티가 둘 이상인 프로젝트에서는 대신 **요약**의 **그룹** 카드에서 **변경**을 클릭하고 **프로젝트 설정**의 **보고 통화**에 코드를 입력할 수 있습니다. 템플릿은 이 변수를 빈 값으로 만듭니다. 변수가 비어 있는 동안 각 로드는 다음 중 정확히 하나의 통화를 지정하는 첫 번째 항목을 사용합니다.

1. 엔터티의 그룹 통화
2. 최상위 엔터티(상위 엔터티가 없는 엔터티)의 현지 통화
3. 파일의 현지 통화

이 중 어느 것도 정확히 하나의 통화를 지정하지 않으면 `reporting_currency`를 직접 설정하십시오.

이미 보고 통화로 된 금액은 그대로 유지되므로 모든 데이터가 하나의 통화로 된 프로젝트에는 환율이 필요하지 않습니다.

판매, 재고, 예산 파일에도 통화를 포함할 수 있습니다. `Currency` 또는 `Local Currency`라는 열을 매핑하면 자동으로 인식되며, 파일의 현지 금액이 보고 통화로 환산됩니다. 파일에 이미 있는 그룹 금액이나 보고 금액은 그대로 유지됩니다. 제품 마스터의 표준 원가는 이미 그룹 통화로 되어 있으므로 환산되지 않습니다.

### 환율

환율은 특정 월에 한 통화 1단위를 보고 통화로 환산합니다. 환산 금액은 현지 금액에 환율을 곱한 값입니다.

- **ERP에서**: 각 로드는 ERP에 있는 환율을 읽습니다.
- **파일에서**: CSV 또는 Excel 파일을 추가하고 **환율** 데이터 세트를 선택합니다. 파일의 환율은 같은 통화와 월에 대한 ERP 환율을 대체합니다. ERP에서 환율을 게시하지 않는 통화로 보고하거나 예산 월의 계획 환율을 추가하려면 파일을 사용합니다.

| 열 | 내용 |
|---|---|
| `from_currency` | 환산할 원래 통화입니다. 예: `EUR` |
| `to_currency` | 보고 통화입니다. 예: `USD` |
| `period` | `YYYY-MM` 형식의 월입니다. |
| `average_rate` | 해당 월의 평균 환율입니다. |
| `closing_rate` | 해당 월말의 환율입니다. |
| `historical_rate` | 자본 계정과 역사적 환율로 설정된 계정에 사용하는 역사적 환율입니다. |

통화에 보고 통화로의 환율이 없으면 반대 방향, 즉 보고 통화에서 해당 통화로의 환율을 역수로 바꾸어 소수점 이하 12자리까지 유지합니다. 그것도 없으면 다른 통화로의 환율에 그 통화의 보고 통화 환율을 곱합니다.

### 적용되는 환율

각 행은 자체 통화에서 환산되므로 엔터티와 다른 통화로 된 라인은 해당 라인의 통화에서 환산됩니다. 행에 맞는 첫 번째 규칙이 적용됩니다.

| 행 | 환율 |
|---|---|
| 통계 계정 및 비전기 계정 | 환산하지 않습니다. |
| 이미 보고 통화로 된 행 | 환산하지 않습니다. |
| 환율 유형이 있는 계정 | 해당 환율(평균, 기말 또는 역사적 환율)을 사용합니다. 역사적 환율이 없으면 기말 환율을 사용합니다. ERP에서 가져온 경우 환율 유형은 계정 자체의 환율 유형입니다. 계정과목표 파일에서는 환율 유형 열을 `fx_rate_type`에 매핑하고 `average`, `closing` 또는 `historical`을 지정합니다. |
| 판매 라인 | 해당 기간의 평균 환율을 사용합니다. |
| 재고 잔액 | 해당 기간의 기말 환율을 사용합니다. |
| 공급업체 청구서, 구매 주문, 지급, 판매 주문, 자산 변동, 이연 수익 변동, 재고 변동 또는 표준 원가 | 해당 기간의 평균 환율을 사용합니다. |
| 미결 채권 또는 채무, 판매 주문의 미결 금액, 계약 금액 또는 은행 잔액 | 해당 항목이 보유된 월말의 기말 환율을 사용합니다. |
| 예산 행 | 총계정원장과 마찬가지로 계정별로 적용합니다. 손익 계정에는 평균 환율, 재무상태표 계정에는 기말 환율을 사용합니다. |
| 손익 계정 | 해당 기간의 평균 환율을 사용합니다. |
| 자본 계정 | 역사적 환율을 사용하며, 역사적 환율이 없으면 기말 환율을 사용합니다. |
| 기타 재무상태표 계정 | 해당 기간의 기말 환율을 사용합니다. |

환산 금액은 반올림하지 않으므로 합계에 차이가 생기지 않습니다.

파이프라인 뷰 `cfm_rv_pipeline_month`, `cfm_rv_won_booked`, `cfm_rv_campaign_window`는 영업 기회의 수주, 실주, 생성 금액을 거래가 종료되거나 생성된 월의 평균 환율로 환산합니다. 월별 미결 파이프라인은 해당 월의 기말 환율로 환산되며, 해당 월의 환율이 아직 로드되지 않은 동안에는 해당 통화에 대해 로드된 가장 최근의 기말 환율로 환산됩니다.

<Aside type="note">
외화 거래의 통화에 해당 월의 평균 환율이 없으면 그 거래의 수주, 실주 또는 생성 금액은 다른 환율로 표시되지 않고 제외됩니다. 거래 자체는 계속 집계됩니다. 외화 수주 건의 금액은 해당 월의 평균 환율이 로드될 때까지 `cfm_rv_pipeline_month`, `cfm_rv_won_booked`, `cfm_rv_campaign_window`에서 제외되므로, 그때까지 당월의 외화 수주 건은 수주 금액에서 누락됩니다. **환율** 파일에 환율을 추가하거나 연결이 ERP의 환율을 읽을 수 있는지 확인한 다음 **로드**를 다시 실행하십시오.
</Aside>

<Aside type="note">
총계정원장과 시산표는 각 기간의 변동액을 담고 있으므로, 재무상태표 금액은 각 월의 변동액을 해당 월의 환율로 환산한 것입니다. 연결 재무상태표는 대신 잔액을 표시된 월의 기말 환율로 환산하며, 그 차이는 자본 아래의 환산 차이 라인에 표시됩니다. [관리 통합](#관리-통합)을 참조하십시오.
</Aside>

## 계층

로드할 때마다 모든 소스의 마스터 데이터로 차원을 다시 만듭니다. 처음에는 일곱 개의 차원이 있으며, 추가 범주를 최대 열 개까지 둘 수 있습니다.

| 차원 | 생성 기준 |
|---|---|
| **엔터티** | 엔터티와 그 상위 항목 |
| **계정** | 계정과목표와 상위 계정 |
| **부서** | 부서와 그 상위 항목 |
| **고객** | 고객과 상위 고객 |
| **제품** | 제품과 상위 제품 |
| **세그먼트 1** | `segment_1`의 세그먼트 값 |
| **세그먼트 2** | `segment_2`의 세그먼트 값 |
| **세그먼트 3**~**세그먼트 10** | 소스에 있는 경우 `segment_3`~`segment_10`의 세그먼트 값 |

- 상위 항목이 없거나 자기 자신을 상위 항목으로 지정한 레코드는 최상위 멤버로 로드됩니다.
- 로드할 때마다 계층을 다시 만들므로 상위 항목은 차원이 아니라 ERP나 파일에서 변경하십시오.
- 한 계층의 문제는 해당 차원에만 영향을 줍니다. 로드와 템플릿의 모델은 그대로 완료됩니다.
- 각 추가 범주의 이름을 그 내용에 맞게 바꿀 수 있습니다(예: **클래스** 또는 **리전**). 엔터티가 둘 이상인 프로젝트에서는 **요약**의 **그룹** 카드에서 **변경**을 클릭하고 **프로젝트 설정**의 **이름**에 보고서에서 사용하는 이름을 입력한 다음 **저장**을 클릭합니다. 이름에는 문자, 숫자, 공백, 점, 대시, 밑줄을 최대 60자까지 사용할 수 있습니다.
- 각 소스는 자체 추가 범주가 사용자가 정한 범주 이름 중 어디에 들어가는지 지정합니다. **시스템**에서 소스의 **편집**을 클릭하고 **이 소스의 추가 범주**에서 각 범주의 이름을 선택하거나 **제외**를 선택한 다음 **저장**을 클릭합니다. 그러면 `Class`와 `Business area`처럼 범주를 서로 다른 이름으로 부르는 소스들이 하나의 슬롯을 공유합니다.

파일에서 세그먼트 계층을 제공하려면 **세그먼트 값** 데이터 세트를 선택합니다.

| 열 | 내용 |
|---|---|
| `segment` | 값이 속한 세그먼트: `segment_1`~`segment_10`. |
| `segment_value` | 총계정원장, 판매 및 예산 라인에 기록된 그대로의 값. |
| `segment_value_name` | 값의 이름. |
| `parent_segment_value` | 같은 세그먼트 내의 상위 값. |

## 준비 상태 검사

이 검사는 **요약**에 있는 다섯 가지 보증의 세부 정보입니다. [수치를 신뢰할 수 있습니까?](/ko/guides/projects/data-foundation-proof/)를 참조하십시오.

각 **로드**와 **변경 사항 적용**은 모든 엔터티와 기간에 대해 검사를 실행하며, 각 검사는 다섯 가지 보증 중 하나에 포함됩니다. 실패한 검사는 빨간색입니다. 주의는 주황색으로, 살펴볼 필요는 있지만 수치는 올바릅니다. **CFM-Accounting - Close and assurance** 대시보드의 **What needs fixing** 탭에는 **Every check, by system, month chosen**이 표시되며, 각 검사의 시스템별 빨간색 항목 수를 보여 주고 0은 수정할 것이 없음을 뜻합니다. 선택한 월에 대해 큰 항목부터 정렬된 수정 항목 테이블은 각 빨간색 항목을 표시하고 계정과목표 로드, 환율 로드, **로드** 다시 실행 등 해야 할 일을 알려 줍니다. [대시보드, 지표 및 분석 경로](/ko/guides/projects/data-foundation-dashboards/)를 참조하십시오.

주요 검사 항목은 다음과 같습니다.

| 검사 | 보증 | 확인 내용 |
|---|---|---|
| **Every month loaded** | **누락된 항목 없음** | 모든 회계 기간에 총계정원장 라인이 있고 모든 ERP 읽기가 성공했습니다. 라인이 없는 마감된 기간은 실패이고, 라인이 없는 미마감 기간은 주의입니다. |
| **Trial balance equals the ledger** | **각 시스템과 일치함** | 각 엔터티, 기간, 계정별로 시산표가 총계정원장과 같습니다. 한 계정에 대해 시산표와 총계정원장 모두 부서를 기록하는 경우 부서별로도 일치하는지 확인합니다. |
| **Sales equal the ledger** | **누락된 항목 없음** | 각 기간의 판매 라인이 총계정원장의 수익 및 매출원가(COGS) 계정과 같습니다. |
| **Every product and customer of a sale known** | **누락된 항목 없음** | 모든 판매 라인이 제품 및 고객 마스터에 있는 제품과 고객을 지정합니다. |
| **Every account known** 및 **Every account typed** | **누락된 항목 없음** | 모든 총계정원장 라인이 계정과목표에 있는 계정을 지정합니다. 알 수 없는 계정이 있는 라인은 손익계산서에서 제외됩니다. 전기 내역이 있지만 계정 유형이 없는 계정도 실패하며, 계정과목표에서 Revenue 계정에는 유형을 지정했지만 매출원가 계정이 없는 소스는 주의입니다. |
| **Every amount has a rate** | **그룹 합계가 일치함** | 모든 총계정원장, 시산표, 판매, 재고 및 예산 행에 보고 통화 금액이 있습니다. 손익계산서는 환산된 금액을 읽으므로 환율이 없는 손익계산서 또는 판매 행은 실패합니다. 환율이 없는 재무상태표, 재고 또는 예산 행은 주의이므로 예산 월에 대한 계획 환율을 로드하십시오. [통화 환산](#통화-환산)을 참조하십시오. |
| **Every entity known** | **누락된 항목 없음** | 모든 총계정원장, 시산표 및 판매 라인이 엔터티 마스터에 있는 엔터티를 직접 또는 **코드 매핑** 파일의 매핑을 통해 지정합니다. 엔터티 마스터가 로드될 때까지는 해당되지 않습니다. [엔터티 매핑표](#엔터티-매핑표)를 참조하십시오. |

다음 검사는 확인이 필요할 때만 표시되며, 모두 **누락된 항목 없음**에 포함됩니다.

| 검사 | 확인 내용 |
|---|---|
| **Reporting book chosen** | 한 엔터티에 대해 여러 회계 장부를 가진 소스의 보고 장부가 선택되었습니다. 선택하기 전까지는 첫 번째 장부만 집계됩니다. |
| **Codes mapped** | 둘 이상의 소스에서 사용하는 모든 코드에 답변했습니다. [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오. |
| **One source for each key** | 어느 소스를 집계할지 선택하지 않은 한, 두 소스가 한 회사의 같은 월을 제공하지 않습니다. |
| **Hierarchies complete** | 차원에서 지정하는 모든 상위 항목이 존재하며, 어떤 멤버도 자기 자신의 상위 항목이나 조상이 아닙니다. 상위 항목이 없으면 그 하위 항목이 계층의 최상위에 놓이고, 순환이 있으면 해당 계층이 로드되지 않습니다. 합계에는 영향이 없습니다. |
| **Months placed in the fiscal calendar** | 각 엔터티의 회계 기간이 역월이며 모든 월의 행을 하나의 회계 기간에 배치할 수 있습니다. 엔터티의 기간이 역월이 아닌 경우(4-4-5, 13기간), 한 월의 행이 둘 이상의 회계 기간에 속할 수 있는 경우, 또는 회계 달력에 해당 월이 없는 경우 주의입니다. |

확인이 필요할 때만 표시되는 설정 검사가 두 가지 있습니다. 하나는 프로젝트 변수 `overhead_department`와 `overhead_driver` 중 하나만 설정되었거나 `overhead_driver`와 일치하는 배부 동인이 없어 간접비 배부가 아무 작업도 하지 않을 때 표시됩니다. 둘 다 설정하거나, 간접비 배부를 끄려면 둘 다 지우십시오. 다른 하나는 예산 행이 로드되었지만 프로젝트 설정의 **예산 버전**(프로젝트 변수 `budget_version`)에 해당하는 행이 없어 예산 비교가 비어 있을 때 표시됩니다.

## 관리 통합

각 로드는 관리 통합을 만듭니다. 관리 통합은 그룹 내 모든 엔터티의 손익계산서, 재무상태표, 현금흐름표로, 보고 통화로 작성되고 내부거래가 제거됩니다. 관리 보고용입니다. 법정 그룹의 공식 기록은 여전히 기존 통합 시스템이며, 아래에서 설명하는 대로 그 시스템과 대사하십시오.

통합 수치가 표시되는 곳에는 항상 **Management consolidation** 레이블이 붙습니다. **요약**의 첫 줄 옆, 각 대시보드 맨 위의 컨텍스트 줄, 이사회 자료의 **Basis** 열에 표시되며, **Basis note** 열에는 "Entities combined, intercompany eliminated, translated to the reporting currency. Not a statutory consolidation."이라고 표시됩니다. 엔터티가 하나인 프로젝트에는 레이블이 표시되지 않습니다.

<Aside type="note">
관리 통합은 법정 또는 법적 통합이 아닙니다. 투자와 자본을 상계 제거하지 않으며 영업권이나 비지배 지분이 없습니다.
</Aside>

### 그룹 선택

**요약**의 **그룹** 카드에는 보고 통화가 표시됩니다. **변경**을 클릭하여 **프로젝트 설정**을 열면 **그룹 및 행 액세스**에 **그룹 내 회사**가 나열됩니다. 선택을 해제한 회사는 개별적으로는 보고서에 계속 표시되지만 그룹 합계에서는 제외됩니다. **저장**을 클릭합니다. 변경 사항은 다음 **로드** 또는 **변경 사항 적용** 때 적용됩니다. 새 회사는 선택을 해제할 때까지 그룹에 포함됩니다.

그룹의 회계연도는 프로젝트 변수 `group_fy_start_month`로 설정한 월에 시작합니다. 이 변수는 직접 설정하지 않는 한 비어 있으며, 비어 있는 동안 그룹의 회계연도는 최상위 엔터티(상위 항목이 없는 유일한 엔터티)의 회계연도가 시작하는 월에 시작하고, 최상위 엔터티에 회계 달력이 없으면 1월에 시작합니다. 상위 항목이 없는 엔터티가 둘 이상이거나 최상위 엔터티가 자체 회계 달력이 없는 계층 노드이면 1월에 시작하며, 월을 설정할 때까지 통합이 주황색으로 표시됩니다.

| **내부거래 라인** | 그룹 수치나 쌍의 근거가 되는 원장 라인과 거래 상대방입니다. |
| **대사** | 그룹 손익계산서 연초 누계를 통합 시스템과 비교한 결과입니다. |

이 테이블에는 세 가지 엔터티 이름이 나타납니다.

| 엔터티 | 의미 |
|---|---|
| **제거** | 내부거래 제거 항목입니다. 합하면 0이 되므로 그룹 수치에는 포함하고, 제거 전 엔터티 합계를 볼 때는 필터로 제외하십시오. |
| **그룹 합계** | 대사에서 사용하는 통합 시스템의 합계입니다. |
| **매핑되지 않음** | 기간이 없는 라인, 그리고 이 프로젝트에 없는 통합 시스템의 계정이나 엔터티입니다. |

지표 **통합 이익**, **통합 결과**, **내부거래 차이**는 **그룹 손익계산서**를 읽습니다. 이 지표들과 **그룹 손익계산서**, 내부거래, 대사 테이블별 분석 경로로 그룹에 관한 질문에 답할 수 있습니다. **CFM-Finance - Statements** 대시보드와 이사회 자료에 세 가지 재무제표가 표시됩니다.

#### 세 가지 재무제표

- **손익계산서**: 각 월을 해당 월의 평균 환율로 환산합니다.
- **재무상태표**: 각 계정의 잔액은 기초 잔액에 해당 월까지의 활동을 더한 금액입니다. 잔액은 표시된 월의 기말 환율로, 자본은 역사적 환율 또는 계정 자체에 환율 유형이 있으면 그 환율로 환산합니다. 역사적 환율이 없는 자본 계정은 기말 환율로 환산합니다. 이전 회계연도의 손익은 이익잉여금에, 당해 연도의 손익은 당기 이익에 포함되며, 각각 해당 월의 평균 환율로 환산됩니다.
- 환산 차이는 각 엔터티의 자본 아래에 있는 라인으로, 기말 환율로 환산한 자본과 이익에서 실제 환산된 금액을 뺀 값입니다. 환산된 재무상태표의 균형을 맞추는 것은 이 라인이며, 결코 균형을 맞추기 위한 임의의 수치가 아닙니다. 다른 통화를 사용하는 엔터티에 해당 월의 기말 환율이 없으면 그 월의 재무상태표는 환산되지 않아 균형이 맞지 않으며, 통합은 해당 엔터티와 월을 표시하며 주황색으로 나타납니다. 환율을 로드한 다음 **변경 사항 적용**을 실행하십시오.
- **현금흐름표**: 각 재무상태표 계정의 해당 월 변동액을 계정 역할에 따라 해당 월의 평균 환율로 계산합니다. 환율 변동 효과 라인에는 기말 환율 기준 현금 변동 중 환율 변동에서 비롯된 부분이 표시됩니다. 역할이 없는 재무상태표 계정은 기타 변동 라인에 표시됩니다.

재무상태표는 자산에서 부채와 자본을 뺀 검사 라인으로 끝나고, 현금흐름표는 현금 변동에서 현금 계정의 변동액을 뺀 검사 라인으로 끝납니다. 재무제표가 올바르면 둘 다 0입니다. 이를 증명하는 보증은 [수치를 신뢰할 수 있습니까?](/ko/guides/projects/data-foundation-proof/)를 참조하십시오.

### 내부거래 제거

내부거래 라인은 거래 상대방을 기준으로 일치시킵니다. 라인의 거래 상대방을 사용하며, 라인에 거래 상대방이 없으면 해당 고객의 거래 상대방을 사용합니다. 쌍의 양측이 모두 제거되며, 양측 금액의 불일치분은 내부거래 차이 항목으로 기장됩니다. 각 쌍에는 사유가 지정됩니다.

| 사유 | 의미 |
|---|---|
| **일치** | 양측이 같은 금액을 기장했습니다. |
| **한쪽만 기장됨** | 한 엔터티는 거래를 기장했지만 거래 상대방은 기장하지 않았습니다. |
| **제거되지 않음** | 쌍의 라인 중 하나에 환율이 없어 어느 쪽도 제거되지 않았습니다. |

쌍은 연초 누계를 기준으로 판단합니다. 내부거래 검사는 쌍의 차이가 프로젝트 변수 `group_amber`(기본값 `1`)를 넘으면 주황색, **프로젝트 설정**의 **내부거래 허용 오차**인 `group_red`(기본값 `1000`)를 넘으면 빨간색으로 바뀝니다. 거래 상대방이 없거나 거래 상대방이 엔터티가 아닌 라인은 제거되지 않고 해당 검사에 집계됩니다. 거래 상대방을 기록하는 소스와 기록하지 않는 소스가 함께 있으면 주황색으로 표시됩니다.

소스 자체의 제거 엔터티는 그룹 손익계산서에서 제외되며, 통합 검사에 그 사실이 표시됩니다.

세 가지 재무제표에서는 내부거래 수익과 비용뿐 아니라 내부거래 채권과 채무도 쌍별로 제거됩니다. 쌍의 양쪽이 일치하지 않는 금액은 손익계산서 또는 재무상태표의 내부거래 차이 라인에 표시되므로 그룹 재무상태표는 여전히 균형을 이루며, 그 변동은 현금흐름표의 내부거래 잔액 변동 라인에 표시됩니다. 각 제거 행에는 두 엔터티와 두 엔터티가 공유하는 국가, 지역, 사업부가 기록되므로, 사업부, 국가 또는 지역은 두 엔터티가 모두 그 안에 있는 쌍만 제거하고, 그룹은 모든 쌍을 제거합니다.

### 통합 시스템과 대사

통합 시스템이 보고하는 결과를 파일로 추가하고, 매핑을 확정할 때 **연결 결과 또는 보고된 손익입니다(OneStream, Anaplan, SAP Group Reporting, FCCS)** 확인란을 선택합니다. **이것은 숫자의 어떤 버전입니까?** 질문에는 시스템 이름을 입력합니다. 그러면 **대사** 테이블에 각 엔터티와 항목별로 연초 누계 기준 **자체 계산**, **보고값**, **차이**가 표시됩니다. 차이는 보통 **제거**, **그룹 합계**, **매핑되지 않음** 행이나 시스템이 사용하는 환율로 설명됩니다. 대사 검사에는 `group_amber`를 넘는 모든 항목이 나열됩니다.

### 볼 수 있는 사용자

그룹 결과는 프로젝트의 행 액세스를 따릅니다. 행 액세스 때문에 그룹 결과를 표시할 수 없으면 통합 검사가 주황색으로 표시됩니다. 일부 엔터티만 볼 수 있는 사용자는 해당 엔터티의 제거 전 합계를 보며, **요약**에 "이 수치는 회사 전체가 아니라 액세스 권한이 있는 엔터티만 포함합니다."라는 안내가 표시됩니다. **제거** 행과 내부거래 테이블을 보려면 모든 엔터티에 대한 액세스 권한이 필요합니다.

**그룹 및 행 액세스**의 **엔터티별로 행 제한**은 엔터티 권한을 부여받은 그룹을 엔터티 열이 있는 모든 테이블에서 해당 엔터티의 행으로 제한합니다. 이 옵션은 아키텍트에게만 표시됩니다. **제한**을 선택하거나 해제하면 즉시 적용되며, 워크스페이스에서 행 액세스가 꺼져 있으면 거부됩니다. 그룹에 엔터티 권한이 있는 동안 선택을 해제하면 먼저 **엔터티 권한을 제거하시겠습니까?** 메시지가 표시됩니다. 계속하려면 **끄기**를 클릭합니다.

프로젝트가 부서처럼 그룹 테이블에 없는 열을 기준으로 볼 수 있는 행을 제한하는 경우, 그룹 결과는 모든 사용자에게 꺼진 상태로 유지되고 통합 검사에 **Group views are off**가 표시됩니다. 이 경우 아키텍트만 **그룹 및 행 액세스**에서 **프로젝트의 모든 사용자가 그룹 결과를 볼 수 있음** 확인란을 선택하고 **저장**을 클릭할 수 있으며, 다른 사용자에게는 이 확인란이 표시되지 않습니다. 변경 사항은 다음 **로드** 또는 **변경 사항 적용** 때 적용됩니다.

## 최신 상태 유지

로드가 완료되고 대기 중인 질문이 없으면, **프로젝트 설정**의 **새로 고침**이 **매일**, **매주** 또는 **매월**이 될 때까지 **요약**의 다음 단계는 **항상 최신 상태로 유지**입니다. **로드** 일정을 설정하는 방법은 두 가지입니다.

- **요약**의 **작업 ▾ > 야간 새로 고침**은 매일 밤 02:00 UTC에 **로드**를 실행합니다.
- 엔터티가 둘 이상인 프로젝트에서는 **요약**의 **그룹** 카드에서 **변경**을 클릭하여 **프로젝트 설정**을 엽니다. **새로 고침**에서 **매일**, **매주** 또는 **매월**을 선택하고, **새로 고침 시간 (UTC)** 필드에 `02:00`처럼 시와 분으로 시간을 입력합니다. **매주**의 경우 **새로 고침 일**은 1(월요일)~7(일요일)이고, **매월**의 경우 해당 월의 날짜입니다. **저장**을 클릭합니다. **요청 시**를 선택하면 일정이 제거됩니다.

일정은 소스가 있는 로드가 빨간색 검사 없이 완료된 후에 설정할 수 있으므로, 샘플 데이터만 있는 프로젝트는 일정을 설정할 수 없습니다. 프로젝트의 일부 엔터티만 볼 수 있다면 아키텍트가 일정을 설정합니다. 일정을 설정할 수 없으면 그 이유가 표시됩니다. **새로 고침**이 **매일**, **매주** 또는 **매월**인 동안 **시스템** 페이지에 각 시스템의 다음 새로 고침 예정 시각이 표시됩니다. [각 시스템의 최신 상태](/ko/guides/projects/data-foundation-proof/#각-시스템의-최신-상태)를 참조하십시오. **야간 새로 고침**은 **새로 고침**을 그대로 두므로 다음 새로 고침이 표시되지 않으며 **항상 최신 상태로 유지**가 계속 다음 단계로 남습니다.

예약된 로드는 설정한 사람의 권한으로 실행됩니다. 그 사람이 더 이상 시스템의 연결을 사용할 수 없으면 해당 사람과 연결을 알려 주는 경고와 함께 로드를 건너뜁니다. 일정을 다시 설정하십시오.

예약된 로드에서 파일이 없거나 비어 있으면 오류가 아니라 해당 경로를 알려 주는 경고와 함께 완료되며, 모델의 나머지 부분은 계속 로드됩니다.

## 비즈니스 이름

**비즈니스 이름**은 모델의 코드에 비즈니스에서 사용하는 이름을 붙입니다. 보고서, 지표 및 Ask에 이 이름이 표시되며, 저장한 이름은 즉시 적용됩니다. 이후 로드에서도 유지됩니다. 엔터티가 둘 이상인 프로젝트에서는 **요약**의 **그룹** 카드에서 **변경**을 클릭합니다. **비즈니스 이름**은 **프로젝트 설정**의 **이름** 카드에 있습니다.

1. **이름 추가**를 클릭하고 **종류**로 **범주**, **손익 항목**, **메트릭**, **열**, **엔터티** 또는 **계정**을 선택합니다.
2. **코드**를 입력합니다. 범주는 `segment_1`~`segment_10`, 손익계산서 항목은 항목의 키, 지표는 지표 이름, 열은 `table.column`, 엔터티나 계정은 해당 코드입니다.
3. **이름**을 한 줄, 최대 60자로 입력합니다.
4. **저장**을 클릭합니다. 모든 내용이 저장되면 대화 상자가 닫힙니다. 거부된 이름은 그리드 아래에 표시되며 대화 상자는 열린 상태로 유지됩니다.

저장하면 목록 전체가 바뀝니다. 이름이 비어 있는 행은 해당 이름을 제거하며, **선택 항목 제거**는 선택한 행을 제거합니다. 같은 코드에 이름을 두 번 지정하면 거부됩니다. 비즈니스 이름은 어시스턴트가 사용자의 용어를 쓰도록 분석 경로의 설명에도 기록되는데, 이 설명에는 길이 제한이 있습니다. 이름 때문에 설명이 너무 길어지면 아무것도 저장되지 않고 그 사실이 안내됩니다.

## 숫자 설명

**이 숫자 설명**은 수치가 무엇으로 구성되는지 보여 줍니다. 한 달이 로드되면 **요약**에 최근 완료 월까지의 연초 누계 당기순이익이 표시되며, 그 옆에 **이 숫자 설명**이 있습니다. 이를 클릭하면 **Explain: Net income**이 열리며, 맨 위에 해당 월까지의 연초 누계 수치가 표시되고 그 아래에 구성 요소가 목록마다 큰 항목부터 표시됩니다.

| 목록 | 내용 |
|---|---|
| **라인** | 수치를 구성하는 재무제표 라인입니다. |
| **엔터티** | 각 엔터티의 몫입니다. 그룹에서는 제거 항목도 그중 하나입니다. |
| **계정** | 각 계정의 몫입니다. |

각 목록에는 가장 큰 10개 항목이 표시되고 나머지는 **Other accounts (12)** 같은 하나의 항목으로 묶이므로 모든 목록의 합계가 수치와 같습니다. 링크로 된 이름을 클릭하면 해당 라인, 엔터티 또는 계정만의 설명이 열립니다. **가장 큰 문서**에는 수치의 근거가 되는 가장 큰 원장 문서 10개가 **시스템**, **엔터티**, **문서**, **전기됨**, **계정**, **설명**, **금액**과 함께 나열되며, **모든 문서 내보내기**는 모든 문서를 다운로드합니다. **Weave에게 변동 이유 묻기**는 해당 월까지의 연초 누계 수치가 변동한 이유와 그 변동을 일으킨 엔터티, 계정, 문서를 Weave에게 묻습니다.

이 창은 행 액세스를 따르므로 볼 수 있는 수치만 설명할 수 있습니다. 아직 없는 테이블은 오류가 아니라 경고로 표시됩니다. 근거가 없는 숫자에는 **설명할 내용 없음**이 표시됩니다.

## 배부 규칙

배부는 간접비 같은 공유 비용을 부서, 제품, 고객에 분산합니다. 모델에는 **1단계: 간접비를 부서로**와 **2단계: 부서를 제품과 고객으로**의 두 단계가 있습니다. 솔루션으로 만든 프로젝트에서는 **홈** 레일의 **Data Foundation** 그룹에 있는 **배부**를 클릭합니다. **배부 규칙**이 열리며, 여기에서 각 단계의 처리 방식을 확인하거나 변경합니다. 변경하지 않으면 마법사가 생기기 전과 같은 방식으로 작동합니다. 읽기 권한만 있는 사용자는 규칙을 열 수 있지만 저장할 수는 없습니다.

마법사는 각 단계마다 네 가지를 묻습니다.

| 단계 | 질문 | 선택 항목 |
|---|---|---|
| **풀** | 어떤 비용을 분산하시겠습니까? | 계정 종류와, 1단계의 경우 비용을 보유한 부서 또는 **All departments**. |
| **드라이버** | 무엇을 기준으로 분산하시겠습니까? | 배부 동인으로 로드한 **Statistic**(예: 인원수, 면적), **Net sales amount**, **Sales quantity** 또는 **Spread evenly**. **Same period** 또는 **Same period last year**의 드라이버를 사용합니다. |
| **대상** | 어디에 배부됩니까? | 1단계: 부서. 2단계: 제품, 고객 또는 둘 다. |
| **방법** | 드라이버가 음수이면 어떻게 합니까? | **Ignore negative values** 또는 **Stop and tell me**. |

단계 아래의 **Preview for**에 `2026-09`처럼 연도와 월로 월을 입력하면, 아직 저장하지 않은 규칙을 포함해 규칙이 어떤 결과를 내는지 보여 줍니다: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. 미배부 금액은 배부받을 드라이버가 없었던 비용입니다. 미리 보기는 행 액세스를 따릅니다.

부서 이름이나 통계 이름에는 작은따옴표(`'`), 백슬래시, 줄바꿈을 넣을 수 없습니다. 이름이 워크플로의 배부 단계 필터에 기록되기 때문입니다. **저장**과 1단계 미리 보기는 이런 이름을 거부하고 표시합니다.

**저장**을 클릭합니다. 규칙은 다음 **로드** 때 또는 **Apply changes**를 클릭할 때 적용됩니다. 배부 단계를 직접 편집한 경우 편집 내용은 덮어쓰이지 않고 유지되며, 저장 시 해당 단계가 표시됩니다. 로드가 실행 중일 때는 저장할 수 없습니다.

## 이사회 보고 자료

이사회 보고 자료는 결과를 문서 계정의 폴더에 바로 보낼 수 있는 형태로 기록합니다. **보고서** 페이지의 **이사회 자료** 카드에서 **이사회 자료 설정**을 클릭하고 **문서 계정**과 `/board-packs` 같은 **폴더**를 선택한 다음 **저장**을 클릭합니다. 그러면 **로드**할 때마다 보고 자료가 만들어지므로 폴더의 파일은 마지막 로드 시점의 최신 상태를 유지합니다. 각 실행에서 다음을 기록합니다.

- **Profit and loss**, **Balance sheet**, **Cash flow** 시트가 있는 Excel 통합 문서 `Board pack.xlsx`: 각 월과 라인을 엔터티별로, 제거 항목 및 그룹 합계와 함께 보여 줍니다. 엔터티가 하나인 프로젝트에는 제거 항목이나 그룹 행이 없습니다.
- **CFM-Finance - Statements** 대시보드의 PDF.

해당 대시보드가 만들어지면 같은 카드의 **이사회 자료 열기**로 엽니다.

즉시 보고 자료를 만들려면 **지금 실행**을 클릭합니다. 완료되면 파일이 폴더에 나타납니다. 대화 상자에는 마지막 실행과 그 결과, 다음 실행이 표시됩니다. **변경 사항 적용**으로는 보고 자료가 만들어지지 않습니다. 일정에 따라 만들려면 **로드** 일정을 설정하십시오([최신 상태 유지](#최신-상태-유지) 참조). 설정하기 전까지 대화 상자에는 **아직 예약되지 않았습니다. 로드할 때마다 이사회 자료가 만들어집니다. 매일 밤 만들려면 야간 새로 고침을 설정하십시오.** 메시지가 표시됩니다. 프로젝트를 변경할 수 있는 사용자만 설정할 수 있습니다.

보고 자료를 완전히 만들 수 없어도 로드가 실패하지는 않습니다.

- 워크스페이스에서 보고 기능이 꺼져 있으면 보고 자료는 Excel 통합 문서만으로 구성되며, 실행 결과에 **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.** 메시지가 표시됩니다.
- 다른 사람이 만든 대시보드가 이미 Data Foundation이 재무제표 대시보드에 필요로 하는 주소를 사용하고 있으면 해당 대시보드는 그대로 두고 PDF는 만들지 않습니다. 메시지에 주소가 표시되므로 Superset에서 다른 대시보드에 다른 주소를 지정한 다음 **로드**를 다시 실행하십시오.
- 보고 자료의 단계 중 하나라도 실패하면 대화 상자의 마지막 실행에 **실패**가 표시됩니다. 로드 자체는 성공한 것입니다.

## 복원 지점

복원 지점은 누가 시작했든(예약된 로드 포함) 각 **로드** 또는 **Apply changes**가 시작될 때, 그리고 매핑이나 소스를 변경하기 전에 만들어집니다. 복원 지점에는 모델의 테이블, 차원, 그리고 다음 로드의 기반이 되는 설정(소스, 파일, 배부 규칙)이 포함됩니다. 로드 시 만든 지점은 최근 일곱 개, 변경 전에 만든 지점은 최근 다섯 개가 유지되므로 변경 때문에 로드 시 만든 지점이 밀려나지 않습니다. 오래된 지점은 순서대로 삭제됩니다.

되돌리려면 **요약**에서 **작업 ▾ > 복원…** 메뉴를 엽니다. 각 지점에는 생성 시각과 그 아래에 복원 시 되돌아오는 테이블 수(예: **테이블 12개를 복원합니다.**)가 표시되고, 그대로 남는 항목이 메모 하나로 표시됩니다. 지점을 선택하고 **복원**을 클릭합니다. **복원**은 지점이 하나 이상 있을 때 제공됩니다. 복원하면 먼저 현재 프로젝트 상태를 별도의 지점으로 기록하므로 다시 되돌릴 수 있습니다. 그런 다음 테이블, 차원 및 해당 설정을 이전 상태로 되돌리며, 다음 로드는 이를 기반으로 합니다. 이미 있던 소스로 복원하면 소스가 변경된 것으로 표시되지 않습니다. 뷰, 저장할 수 없는 차원, 저장된 사본이 없는 테이블은 경고에 표시되며 나머지는 복원됩니다. 이미 삭제된 복원 지점은 거부되며, 로드가 실행 중일 때는 복원할 수 없습니다.

## 프로젝트 복제

**요약**의 **작업 ▾ > 복제…** 메뉴는 지정한 이름으로 프로젝트를 복사합니다. 복사본에는 템플릿, 모델에 대한 편집 내용, 지표 및 분석 경로가 유지되고 샘플 데이터가 로드됩니다. 소스는 연결되지 않으므로 로드하기 전에 복사본에서 소스를 연결하십시오. 복사본을 만드는 동안 계속 작업할 수 있으며, 준비되면 **프로젝트 열기**로 이동할 수 있습니다.

## 내 템플릿으로 저장

프로젝트 설정을 저장하여 다음 클라이언트나 엔터티에 재사용할 수 있습니다. **요약**에서 **작업 ▾ > 내 템플릿으로 저장…** 메뉴를 열고 문서 계정을 선택한 다음 파일 이름을 지정합니다. 이름 끝에 `.zip`을 생략하면 자동으로 추가됩니다. 기존 파일을 덮어쓰는 저장은 거부되므로 다른 이름을 선택하십시오.

파일에는 프로젝트 구조, 모델에 대한 편집 내용, 지표 및 분석 경로, 엔터티와 계정의 비즈니스 이름, 그리고 [Cost to Serve](/ko/guides/projects/cost-to-serve/)의 활동 맵이나 [Operational Transfer Pricing](/ko/guides/projects/operational-transfer-pricing/)의 정책 범위 같은 템플릿 구성 테이블의 행이 포함됩니다. 연결, 파일, 야간 일정, 실행, 복원 지점, 이사회 보고 자료, 액세스 권한자는 제외됩니다.

사용하려면 프로젝트를 만들고 **시작 기준**에서 **템플릿 파일에서** 옵션을 선택한 다음 문서 계정과 경로를 선택합니다. 새 프로젝트는 본인만 볼 수 있으며 모든 소스가 연결 대기 상태입니다. 이후 템플릿의 새 릴리스는 사용자가 편집한 단계를 피해 변경 사항을 병합합니다. 경로에 파일이 없으면 아무것도 만들어지지 않고 그 사실이 안내됩니다. 문서 계정을 읽을 수 있는 사람은 누구나 파일에서 설치할 수 있습니다. 다른 워크스페이스에서 사용하려면 파일을 다운로드한 다음 그곳에 업로드하십시오.

## Ask로 미해결 질문 해결

로드 후에도 프로젝트는 계정과목표에서 유형이 지정되지 않은 계정, 둘 이상의 소스가 사용하는 코드, 파일에서 아무것과도 일치하지 않은 열이라는 세 가지 사항에 대한 답을 기다리고 있을 수 있습니다. 어시스턴트에게 해결을 요청하십시오. MCP를 통한 AI 어시스턴트에서 **Resolve Data Foundation residue** 프롬프트를 사용합니다. 어시스턴트는 대기 중인 항목을 읽고 각 항목에 대해 이유와 함께 하나의 답을 제안합니다.

어시스턴트는 아무것도 기록하지 않습니다. Weave AI 채팅에서도 프로젝트가 무엇을 기다리고 있는지 알려 주며([Weave AI 채팅](/ko/guides/ai-assistant/weave-tab/#data-foundation) 참조), MCP로 연결된 에이전트가 질문을 직접 읽고 답할 수도 있습니다([MCP로 연결된 AI 에이전트와 Data Foundation](/ko/integrations/ai-coding-agents/data-foundation/) 참조). 직접 답했을 위치에 어시스턴트의 답을 적용합니다. 계정과 코드는 **질문** 페이지에서, 파일 열은 파일의 매핑에서 적용합니다. 어시스턴트는 엔터티를 제안하지 않습니다. **질문**의 질문에는 Weave 자체의 제안이 이미 포함되어 있을 수 있습니다. [Data Foundation 페이지](#data-foundation-페이지)를 참조하십시오.

## 프로젝트 인계

클라이언트처럼 다른 사람을 위해 프로젝트를 설정한 경우 다음 단계로 마무리합니다.

- **최신 상태로 유지합니다.** **로드** 일정을 설정합니다. [최신 상태 유지](#최신-상태-유지)를 참조하십시오.
- **공유합니다.** 프로젝트의 **액세스 및 공유** 페이지에서 팀에 액세스 권한을 부여합니다. [프로젝트 액세스 관리](/ko/guides/projects/managing-projects/#프로젝트-액세스-관리)를 참조하십시오.
- **기록을 남깁니다.** **요약**의 **작업 ▾ > 증빙 자료 팩 다운로드**는 **Status**, **Sources**, **Coverage**, **Mappings**, **Consolidation**, **Reconcile**, **Last load** 시트가 있는 Excel 통합 문서를 다운로드합니다. 무엇이 어디에서 로드되었는지, 코드가 어떻게 매핑되었는지, 그룹이 일치하는지, 마지막 로드가 어떻게 진행되었는지를 담고 있습니다. 다운로드하는 사람의 행 액세스를 따르며, 프로젝트에 역할이 있는 사람은 누구나 다운로드할 수 있습니다.
- **인계합니다.** 소유자를 프로젝트의 아키텍트로 지정한 다음 멤버에서 본인을 제거합니다. 모든 사용자가 그룹 결과를 볼 수 있도록 허용하거나 프로젝트에 Data Foundation을 추가하는 것처럼 일부 선택은 아키텍트만 할 수 있습니다.

## 템플릿으로 모델 확장

템플릿은 보고서와 모델을 Common Finance Model 위에 구축하므로 어떤 ERP에서 데이터를 공급하든 동일하게 작동합니다. **Enterprise Profitability** 같은 템플릿으로 프로젝트를 시작하면 다음이 만들어집니다.

- 비어 있거나 샘플 데이터로 채워진 [Common Finance Model 테이블](#common-finance-model-테이블).
- 해당 테이블로 만든 **엔터티**, **계정**, **부서**, **고객**, **제품**, **세그먼트 1**, **세그먼트 2** 차원. [계층](#계층)을 참조하십시오.
- **로드** 워크플로와, ERP와 파일을 읽고 표준화하고 준비 상태를 검사하고 템플릿의 모델을 만들기 위해 이 워크플로가 실행하는 워크플로.
- 템플릿 고유의 보고서와 모델. **Enterprise Profitability**는 수익, 매출원가, 매출총이익, 직접 및 간접 영업비용, 공헌이익, 영업이익을 포함하는 손익계산서 테이블과 전년 대비 및 예산 대비 이익률 브리지를 추가합니다.
- 결과에 대해 질문할 수 있는 지표와 분석 경로.

**시작 기준**에서 **Data Foundation**은 모델과 해당 보고서만 제공합니다. 세 가지 솔루션은 각각 Data Foundation을 포함하며 자체 모델을 추가하고, 레일에 **배부**를 표시합니다.

| 솔루션 | 추가 항목 |
|---|---|
| **Enterprise Profitability** | 손익계산서와 이익률 브리지. |
| **Cost to Serve** | 각 고객에게 서비스하는 비용과 그 이후의 이익률. [Cost to Serve](/ko/guides/projects/cost-to-serve/)를 참조하십시오. |
| **Operational Transfer Pricing** | 정책 범위 대비 각 엔터티의 이익 수준과 정산 조정. [Operational Transfer Pricing](/ko/guides/projects/operational-transfer-pricing/)을 참조하십시오. |

**템플릿 파일에서** 옵션은 저장한 프로젝트에서 시작합니다. [내 템플릿으로 저장](#내-템플릿으로-저장)을 참조하십시오.

자체 ERP를 연결하기 전에 먼저 살펴보려면 프로젝트를 만들 때 **샘플 데이터로 시작**을 선택합니다. 프로젝트는 즉시 첫 번째 로드를 실행하므로 **요약**에 미국 달러로 환산된 유로 엔터티를 포함한 완전한 예제가 표시됩니다. 자체 ERP를 연결하거나 자체 파일을 추가하면 샘플이 제거되고 사용자의 데이터로 대체됩니다. 제거가 중단되면 다음 **로드**에서 마무리됩니다. 사용자가 직접 만든 `sample` 폴더는 제거되지 않지만, 샘플이 해당 폴더를 점유하는 동안 그 안의 다른 테이블은 읽지 않으므로 해당 테이블을 다른 이름의 폴더로 옮기십시오.

## Data Foundation 페이지

프로젝트 **홈** 레일의 **Data Foundation** 그룹에서 데이터를 연결하고 로드하고 검사합니다. 표시되는 행은 [Data Foundation 사용 시작](#data-foundation-사용-시작)에 설명되어 있습니다.

| 페이지 | 표시 내용 |
|---|---|
| **요약** | Data Foundation의 현재 상태, 수치를 신뢰할 수 있는지 여부, 다음에 할 일. 아래를 참조하십시오. |
| **시스템** | 보고에 사용하는 모든 시스템과 각 시스템의 상태 및 마지막 로드 시점, **시스템 추가**, **파일** 카드. [ERP 연결](#erp-연결), [시스템](#시스템), [ERP 외부 데이터용 파일 추가](#erp-외부-데이터용-파일-추가)를 참조하십시오. |
| **질문** | 답변을 기다리는 모든 항목. 아래를 참조하십시오. |
| **보고서** | 페르소나별 대시보드(각각 새 탭에서 열림)와 **이사회 자료** 카드. [대시보드, 지표 및 분석 경로](/ko/guides/projects/data-foundation-dashboards/) 및 [이사회 보고 자료](#이사회-보고-자료)를 참조하십시오. |
| **배부** | 솔루션으로 만든 프로젝트에서 **배부 규칙**을 엽니다. [배부 규칙](#배부-규칙)을 참조하십시오. |

**요약**은 위에서부터 다음과 같이 구성됩니다.

- 프로젝트 상태를 보여 주는 한 줄과 **재무 시스템 추가**, **로드**, **질문 1개에 답변**, **항상 최신 상태로 유지**, **보고서 열기** 같은 다음 단계 버튼 하나, 그리고 **이 숫자 설명**이 있는 당기순이익 줄. [숫자 설명](#숫자-설명)을 참조하십시오.
- 엔터티가 둘 이상인 프로젝트에서는 **그룹**: 그룹이 얼마나 완료되었는지, 보고 통화, 회계연도가 시작하는 월이 표시되며, **변경**으로 **프로젝트 설정**을 엽니다.
- 다섯 가지 보증인 **수치를 신뢰할 수 있습니까?**, 시스템이 하나이면 **내 시스템**, 내용이 있으면 **변경된 내용**, 그리고 **월 마감**. [Data Foundation: 수치를 신뢰할 수 있습니까?](/ko/guides/projects/data-foundation-proof/)를 참조하십시오.
- **Weave에 문의**: 시작할 때 사용할 수 있는 질문.
- **기록**: 각 답변, 일치, 마감, 재작성을 수행한 사람, 시각, 이전 값과 함께 표시합니다. 목록을 보려면 **기록 표시**를, 이전 항목은 **더 보기**를, Excel 통합 문서로 다운로드하려면 **내보내기**를 클릭합니다.
- **소스 적용 범위**: 두 소스가 같은 월을 제공할 때 어느 소스를 집계할지 선택합니다. [기간별 기준 소스 선택](#기간별-기준-소스-선택)을 참조하십시오.

행 액세스로 일부 엔터티만 볼 수 있으면 **요약**에 **이 수치는 회사 전체가 아니라 액세스 권한이 있는 엔터티만 포함합니다.** 메시지가 표시됩니다.

**요약** 맨 위의 **작업 ▾** 메뉴에는 **계층…**, **야간 새로 고침**, **증빙 자료 팩 다운로드**, **복제…**, **복원…**, **내 템플릿으로 저장…** 항목이 있습니다. [계층](#계층), [최신 상태 유지](#최신-상태-유지), [프로젝트 인계](#프로젝트-인계), [프로젝트 복제](#프로젝트-복제), [복원 지점](#복원-지점), [내 템플릿으로 저장](#내-템플릿으로-저장)을 참조하십시오. 프로젝트를 변경하는 항목은 프로젝트를 변경할 수 있는 사용자만 사용할 수 있습니다.

**질문**에는 답변을 기다리는 모든 항목이 주제별로 묶여 각 주제의 질문 수와 함께 나열됩니다. 시스템을 추가하면 코드마다 질문에 답하는 대신, 이미 연결된 시스템과 같은 코드를 사용하는지 등 주제별로 질문 하나에 답합니다. 수치에서 행을 보류하는 질문에는 보류된 행 수와 금액이 표시됩니다. **Weave suggests:** 항목에는 Weave의 답변과 그 근거가 표시됩니다. **이 답변 사용**을 클릭하거나, 목록에서 다른 답변을 선택하고 **답변**을 클릭합니다. **제안된 항목 모두 수락**은 제안이 있는 모든 질문에 답합니다. 답변은 다음 **로드** 또는 **변경 사항 적용** 때 적용됩니다. **질문** 행은 대기 중인 질문이 있을 때만 표시됩니다.

소스를 변경하면 모든 페이지 위에 **소스를 변경하셨습니다. 적용하려면 변경 사항 적용을 누르십시오.** 표시줄이 나타납니다. 이 표시줄에는 **변경 내용 표시**와 **변경 사항 적용**이 있으며, 변경 사항을 적용하는 유일한 위치입니다. **로드** 또는 **변경 사항 적용**의 결과는 열려 있는 페이지 위에 표시되므로 모든 페이지에서 확인할 수 있습니다.

로드가 실행되는 동안 페이지는 자동으로 새로 고쳐지며, 읽기 한 번이 실패해도 계속 읽습니다. 상태를 읽을 수 없으면 **Foundation 상태를 읽을 수 없습니다.** 메시지가 **다시 시도**와 함께 표시되며, 이 버튼은 상태를 새로 읽습니다. 페이지도 메시지를 표시하기 전에 자동으로 한 번 다시 시도하며, 서버가 응답하면 메시지가 사라집니다.

## Common Finance Model 테이블

Data Foundation은 ERP든 파일이든 모든 소스를 동일한 테이블로 표준화하므로, 이 테이블을 기반으로 만든 보고서, 지표, 모델은 소스와 관계없이 동일하게 작동합니다. 각 행에는 원천 시스템과 읽은 시각도 기록됩니다. **데이터 세트** 열은 파일을 추가할 때 선택하는 이름입니다.

| 데이터 세트 | 테이블 | 내용 |
|---|---|---|
| 엔터티 | `cfm_entity` | 상위 항목, 현지 및 그룹 통화, 국가, 지역 및 사업부가 포함된 법인. |
| 코드 매핑 | `cfm_code_map` | 소스에 기록된 코드(예: 엔터티, 계정 또는 부서 코드)를 표준 코드에 연결하는 매핑표. [엔터티 매핑표](#엔터티-매핑표) 및 [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오. |
| 환율 | `cfm_fx_rate` | 통화 쌍별 월 평균, 기말 및 역사적 환율. [환율](#환율)을 참조하십시오. |
| 회계 달력 | `cfm_fiscal_calendar` | 엔터티 회계 기간별로 한 행씩, 시작일과 종료일 및 마감 여부. |
| 계정과목표 | `cfm_account` | 상위 항목, 유형(`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), 재무제표, 정상 잔액, 환율 유형 및 계정 역할이 포함된 계정. 현금, 채권, 채무, 이익잉여금 같은 역할에 따라 계정이 재무제표와 현금흐름 라인에 배치됩니다. |
| 부서 | `cfm_department` | 상위 항목과 이익 센터가 포함된 부서 및 코스트 센터. |
| 이익 센터 | `cfm_profit_center` | 상위 항목이 포함된 이익 센터. |
| 제품 | `cfm_product` | 상위 항목, 제품군, 그룹, 측정 단위 및 표준 원가가 포함된 제품 마스터. |
| 고객 | `cfm_customer` | 상위 항목, 그룹, 지역 및 국가가 포함된 고객 마스터. 고객 이름은 마스킹되지 않습니다. |
| 세그먼트 값 | `cfm_segment` | 이름과 상위 항목이 포함된 세그먼트 값. [계층](#계층)을 참조하십시오. |
| 총계정원장 | `cfm_gl_journal` | 거래 통화, 현지 통화 및 보고 통화로 기록된 분개 라인. |
| 시산표 | `cfm_trial_balance` | 엔터티, 계정, 부서별 기간 차변, 대변 및 순액(현지 통화 및 보고 통화). |
| 판매 라인 | `cfm_sales_line` | 수량, 총액, 할인, 순액 및 매출원가 금액이 포함된 송장 발행 판매 라인. |
| 파이프라인 | `cfm_opportunity` | 판매 파이프라인: 단계에 관계없이 영업 기회 라인당 한 행, 월말마다 사본 하나. |
| 재고 잔액 | `cfm_inventory_balance` | 제품 및 창고별 기말 재고. |
| 예산 | `cfm_budget` | 시나리오, 버전, 계정, 부서별 예산 및 예측. |
| 평가 기준별 CO-PA | `cfm_copa` | 엔터티, 기간, 계정, 제품, 고객별 SAP 수익성 분석(CO-PA)으로, 평가 기준(법정, 그룹 또는 이익 센터)마다 한 세트의 행이 있으며 서로 합산되지 않습니다. 수익은 양수, 비용은 음수입니다. 템플릿 중에서는 [Operational Transfer Pricing](/ko/guides/projects/operational-transfer-pricing/#co-pa-마진)만 이 테이블을 읽습니다. |
| 배부 동인 | `cfm_stat_driver` | 인원수, 면적, 단위 같은 통계 드라이버. |

모델에는 보조원장과 그 마스터도 포함되며, 이를 보유한 시스템에서 채워집니다.

| 테이블 | 내용 |
|---|---|
| `cfm_site` | 사이트: 공장, 창고 위치 또는 사무소이며 각각 하나의 엔터티에 속합니다. |
| `cfm_supplier` | 공급업체 마스터. |
| `cfm_sales_rep` | 영업 담당자 마스터. |
| `cfm_project` | 프로젝트 마스터. 마케팅 캠페인도 프로젝트입니다. |
| `cfm_standard_cost` | 제품, 원가 계산 엔터티, 기간별 단위당 표준 원가. |
| `cfm_system_balance` | 각 월말의 계정별 시스템 자체 기말 잔액으로, 분개 라인이 아니라 항상 시스템의 잔액 보고서에서 읽습니다. |
| `cfm_supplier_invoice_line` | 공급업체 청구서 라인. |
| `cfm_purchase_order_line` | 구매 주문 라인, 월말마다 사본 하나. |
| `cfm_open_item` | 미결 채권 및 채무, 월말마다 사본 하나. |
| `cfm_payment` | 수금 및 지급. |
| `cfm_order_line` | 판매 주문 라인, 월말마다 사본 하나. |
| `cfm_asset` | 고정자산 대장. |
| `cfm_asset_movement` | 장부 및 기간별 자산 변동: 취득, 감가상각, 처분, 이전. |
| `cfm_contract` | 계약 및 구독, 월말마다 사본 하나. |
| `cfm_deferred_revenue_movement` | 계약 및 기간별 이연 수익 변동. |
| `cfm_bank_balance` | 은행 계좌와 월말 장부 잔액. |
| `cfm_inventory_movement` | 재고 변동: 입고, 출고, 생산, 이동, 조정, 폐기. |

월말마다 사본 하나를 유지하는 테이블은 각 로드에서 미마감 월의 사본을 대체합니다. 문서 테이블에는 `counts` 열이 있습니다. `1`은 해당 엔터티와 월을 집계하는 시스템과 프로젝트가 보고하는 장부에서 온 집계되는 행이고, `0`은 다른 시스템이나 장부에서 보존된 행입니다. 보고서와 지표는 집계되는 행만 읽습니다.

Foundation 프로젝트에는 이 테이블들이 공유하는 열인 `entity`, `account`, `department`, `profit_center`, `product`, `customer`, `period`, `site`, `supplier`, `sales_rep`, `project`에 대한 [프로젝트 요소](/ko/guides/projects/data-model/)가 함께 제공됩니다. 각 요소에는 설명이 있고, 해당하는 경우 유형과 차원도 있으므로 이러한 열이 있는 모든 테이블에서 같은 의미가 표시됩니다. Data Foundation은 프로젝트에 없는 요소를 추가하고, 사용자가 편집한 요소는 그대로 둡니다. 이는 모든 ERP와 파일 소스에 적용됩니다.

기간은 `YYYY-MM` 형식으로 기록되며, 거래는 전기 기간을 기준으로 배치됩니다. 예산은 선택 사항입니다. 예산이 없는 ERP도 나머지는 모두 로드됩니다.

시산표 파일에는 차변 및 대변 열, 순액 열 또는 둘 다를 포함할 수 있습니다. 차변과 대변만 있으면 순액은 차변에서 대변을 뺀 값이며, 비어 있는 쪽은 0으로 계산됩니다. 순액만 있으면 양수 순액은 차변이 되고 음수 순액은 양수 금액으로 대변이 됩니다. 부서 열은 선택 사항입니다.

## 문제 해결

| 증상 | 조치 사항 |
|---|---|
| **연결 테스트**에서 ERP가 자격 증명을 거부했다고 표시됨 | 연결의 자격 증명과 통합 사용자가 ERP에 로그인할 수 있는지 확인하십시오. |
| **연결 테스트**에서 데이터 세트에 **권한 누락**이 표시됨 | ERP 관리자에게 표시된 권한을 추가해 달라고 요청하십시오. 해당 ERP의 [연결 가이드](/ko/guides/connections/)에 연결에 필요한 권한이 나와 있습니다. |
| ERP 오류 메시지가 ERP 자체의 메시지보다 짧음 | PlaidCloud는 공급자 오류를 표시하기 전에 자격 증명, 토큰 및 키를 제거하므로 일부 세부 정보가 생략됩니다. **연결 테스트**를 실행하여 영향을 받는 데이터 세트를 확인하십시오. |
| 한 기간의 **Every month loaded**이 실패함 | 해당 기간의 ERP 읽기가 실패했습니다. **로드**를 다시 실행하십시오. 이미 로드된 기간은 건너뜁니다. |
| **Every account known**이 실패함 | 누락된 계정을 ERP 또는 파일의 계정과목표에 추가하고 **로드**를 다시 실행하십시오. |
| **Every amount has a rate**이 실패함 | 해당 기간에 엔터티 통화에서 보고 통화로의 환율이 없거나 단일 보고 통화를 찾지 못했습니다. **환율** 파일에 환율을 추가하거나, 연결이 ERP의 환율을 읽을 수 있는지 확인하거나, 프로젝트 변수 `reporting_currency`를 설정하십시오. 그런 다음 **로드**를 다시 실행하십시오. |
| **Every amount has a rate**이 주의로 표시됨 | 재무상태표, 재고 또는 예산 행에 해당 기간의 기말, 역사적 또는 계획 환율이 없습니다. 손익계산서에는 영향이 없습니다. 예산 월의 계획 환율을 포함해 환율을 추가하고 **로드**를 다시 실행하십시오. |
| **Codes mapped**이 실패함 | **질문**을 열고 각 질문에 답하십시오. 답변은 다음 **로드** 또는 **변경 사항 적용** 때 적용됩니다. |
| **One source for each key**가 실패함 | **요약**의 **소스 적용 범위**에서 월과 소스를 선택하고 **선택 저장**을 클릭한 다음 **변경 사항 적용**을 클릭하십시오. |
| 내부거래 검사가 빨간색 또는 주황색으로 표시됨 | **내부거래 쌍**에서 쌍을 확인하십시오. 누락된 쪽을 기장하거나, 라인에 거래 상대방을 추가하거나, 누락된 환율을 추가하십시오. |
| **Group views are off** | 아키텍트에게 **프로젝트 설정**의 **그룹 및 행 액세스**에서 **프로젝트의 모든 사용자가 그룹 결과를 볼 수 있음** 확인란을 선택해 달라고 요청하십시오. |
| 예약된 로드를 건너뜀 | 일정을 설정한 사람이 더 이상 시스템의 연결을 사용할 수 없습니다. 일정을 다시 설정하십시오. [최신 상태 유지](#최신-상태-유지)를 참조하십시오. |
| **Every entity known**이 실패함 | 엔터티 마스터에 엔터티를 추가하거나 **코드 매핑** 파일에서 해당 코드를 기존 엔터티에 매핑한 다음 **로드**를 다시 실행하십시오. |
