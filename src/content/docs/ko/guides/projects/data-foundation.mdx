**Data Foundation**은 PlaidCloud 프로젝트를 위한 재무 데이터 기반입니다. **Common Finance Model**은 여러 ERP 시스템과 각 시스템의 여러 인스턴스에서 가져온 ERP 데이터를 하나의 계정과목표, 하나의 엔터티 집합, 하나의 보고 통화를 갖춘 단일 모델로 통합합니다. 이 모델을 기반으로 만든 보고서, 지표, AI 어시스턴트는 어느 ERP에서 온 데이터이든 모두 같은 수치를 읽습니다.

ERP는 PlaidCloud 연결을 통해 연결되므로 총계정원장, 시산표, 마스터 데이터, 예산이 내보내기 작업 없이 원본에서 직접 들어옵니다. 파일은 환율, 배부 동인, ERP 외부에서 관리하는 예산처럼 시스템에 없는 데이터를 추가하며, 파일이 다루는 ERP 행을 대체할 수도 있습니다. **로드**는 프로젝트의 **Foundation** 탭에서 모든 소스를 모델에 맞게 변환하고, 보고 통화로 환산하며, 합계가 일치하는지 검사합니다. 소스들이 같은 코드를 서로 다른 의미로 사용하는 경우에는 코드가 같은 의미인지 직접 알려 주며, 관리 통합(management consolidation)은 내부거래를 소거한 그룹 손익계산서를 만듭니다. **Enterprise Profitability** 같은 템플릿은 이 모델 위에 보고서와 모델을 구축합니다.

## ERP 연결

ERP는 PlaidCloud 연결을 통해 Data Foundation에 연결됩니다. Data Foundation은 이 연결에서 총계정원장, 시산표, 마스터 데이터, 환율, 예산을 직접 읽으며 읽기만 수행합니다. 기존 연결을 선택하거나 탭에서 새 연결을 만들 수 있습니다. 각 시스템에는 접근 권한을 부여하는 관리자를 위한 페이지가 있으며 [모델에 데이터를 공급할 수 있는 시스템](/ko/guides/projects/data-foundation-getting-started/#모델에-데이터를-공급할-수-있는-시스템)에 나열되어 있습니다. [Data Foundation 지원 범위 매트릭스](/ko/reference/data-foundation-coverage-matrix/)에서는 각 시스템이 직접 제공하는 데이터 세트를 확인할 수 있습니다.

<Steps>

1. Analyze에서 **프로젝트**를 열고 **새 프로젝트**를 클릭합니다. 이름을 입력하고 **시작 기준**에서 **빈 프로젝트** 대신 **Enterprise Profitability (템플릿)** 같은 템플릿을 선택합니다. **만들기**를 클릭합니다.

   프로젝트가 **Foundation** 탭으로 열립니다. 프로젝트를 공유하기 전까지는 본인만 볼 수 있으며, 본인이 유일한 아키텍트입니다.

2. **Foundation** 탭에서 ERP용 기존 연결을 선택하거나 **새 연결 만들기**를 선택합니다. 기존 연결마다 해당 연결을 이미 사용하는 워크플로가 나열되며, 사용하는 워크플로가 없으면 **아직 어떤 워크플로에서도 사용되지 않음**으로 표시됩니다.

3. 새 연결은 **연결 이름**을 입력하고 **환경**을 선택한 다음, ERP 연결이 요구하는 자격 증명을 입력합니다.

   아직 자격 증명이 없나요? 양식에 ERP 관리자에게 보낼 수 있는 접근 요청서가 준비되어 있습니다. **요청 복사** 또는 **이메일 요청**을 클릭하여 요청서를 보내고, 받은 값을 입력합니다.

4. **연결 테스트**를 클릭합니다. PlaidCloud가 로그인하여 각 데이터 세트를 읽어 보고, 각각을 **읽기 가능**, **권한 누락**, **오류** 중 하나로 표시합니다. 누락된 항목이 있으면 ERP 관리자에게 추가를 요청해야 할 권한을 알려 줍니다.

5. **이력 개월 수**를 설정합니다. 몇 개월 전까지 로드할지를 1에서 120 사이로 지정하며, 기본값은 24입니다.

6. 기존 연결인 경우 로드할 엔터티를 선택합니다. 모두 선택하지 않으면 모든 엔터티를 로드합니다. 비활성 엔터티와 소거 엔터티는 표시하도록 선택하기 전까지 숨겨져 있습니다. 그런 다음 **연결**을 클릭합니다.

7. 새 연결인 경우 **연결**을 클릭하여 연결을 만듭니다. 그런 다음 로드할 엔터티를 선택하고 **연결**을 다시 클릭하여 저장합니다. 저장하기 전까지는 모든 엔터티가 로드됩니다.

8. 다른 ERP 시스템이나 다른 인스턴스를 추가하려면 이 단계를 반복하되, **연결**을 클릭하기 전에 **Add this as another source instead of replacing the current one**을 선택합니다. 선택하지 않으면 새 연결이 현재 소스를 대체합니다.

</Steps>

연결되면 카드에 프로젝트가 로드하는 연결, 환경, 엔터티, 이력 개월 수가 표시됩니다.

로드할 때마다 변경된 내용만 읽습니다. 미마감 기간과 마지막 마감된 기간은 다시 읽고, 이미 로드된 마감된 기간은 그대로 유지합니다. **이력 개월 수**를 늘리면 추가된 개월만 읽습니다. 환율, 엔터티 매핑표, 보고 통화가 변경되면 영향을 받는 개월을 다시 읽습니다.

## 소스

프로젝트가 로드하는 모든 ERP 시스템과 인스턴스가 하나의 소스입니다. **Foundation** 탭의 **소스** 목록에는 소스마다 한 줄씩 순서대로 이름, 마지막 로드 시각, 제공한 행 수, 읽는 보고 장부가 표시됩니다. 예를 들면 `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`와 같습니다. 아직 로드되지 않은 소스는 **not loaded yet**으로 표시됩니다. 확정한 파일도 소스입니다.

소스의 사용 방식을 변경하려면 소스에서 **고급**을 엽니다.

| 설정 | 기능 |
|---|---|
| **이름** | 보고서, 매핑 질문, 메시지에서 소스를 가리키는 레이블입니다. |
| **Place in the order** | 소스의 순위입니다. 두 소스가 같은 회사의 같은 월을 다루는 경우 순서가 더 높은 소스가 우선합니다. |
| **Reporting books, separated by commas** | 장부를 둘 이상 관리하는 시스템에서 읽을 회계 장부입니다. **All reporting books**는 모든 장부를 읽습니다. |
| **회사**, **시작 (2026-01)**, **종료 (2026-12)** | 이 소스가 회사별로 제공하는 개월입니다. 한도를 두지 않으려면 월을 비워 둡니다. 월은 `2026-03`처럼 연도와 월로 씁니다. |

변경 사항을 유지하려면 **저장**을 클릭합니다. 소스를 삭제하려면 **Remove this source**를 클릭하고 **제거**를 확인합니다. 해당 소스에서 로드된 모든 내용이 삭제되며, 나중에 다시 연결할 수 있습니다.

소스를 변경해도 ERP를 다시 읽지는 않습니다. **마지막 로드** 카드에는 **Apply changes**를 클릭하기 전까지 **Changes not applied yet**이 표시됩니다. **Apply changes**는 이미 가져온 데이터로 로드를 실행하여, 새 순서, 매핑, 이름, 파일로 소스를 다시 변환하고 모델을 다시 구축합니다. ERP에서 최신 데이터도 가져오려면 **로드**를 클릭합니다.

## ERP 외부 데이터용 파일 추가

파일은 환율, 배부 동인, [엔터티 매핑표](#엔터티-매핑표), ERP 외부에서 관리하는 예산처럼 시스템에 없는 데이터로 ERP 연결을 보완합니다. 각 파일은 [Common Finance Model 테이블](#common-finance-model-테이블)에 나열된 데이터 세트 중 하나에 속합니다.

<Steps>

1. **파일**에서 파일을 저장할 **문서 계정**을 선택합니다.

2. **CSV 또는 Excel 파일을 여기에 놓으십시오** 영역에 CSV 또는 Excel 파일을 놓거나 **파일 선택**을 클릭합니다. 파일은 문서 계정의 `/foundation/` 폴더에 업로드됩니다.

   문서 계정에 이미 있는 파일은 **파일 경로**(예: `/foundation/budget.csv`)를 입력하고 **파일 추가**를 클릭합니다.

   매월 새 파일을 읽으려면 이름이 일치하는 폴더의 모든 파일을 추가합니다. 폴더와 **File names that** 조건(포함, 시작, 끝, 정확히 일치, 패턴 일치)을 입력하고 **Add files**를 클릭합니다. 그 안에 있는 하위 폴더의 파일은 읽지 않습니다.

3. PlaidCloud가 파일을 읽고 매핑을 제안합니다.

   - **구분 기호, 소수점 구분 기호, 날짜 자동 감지.** 구분 기호(쉼표, 세미콜론, 탭, 파이프), 소수점 구분 기호, 날짜 형식이 자동으로 감지됩니다.
   - **데이터 세트**: 파일 이름과 열 제목을 바탕으로 일치시킨, 파일이 속한 Common Finance Model 테이블입니다. 일치 결과가 분명하지 않으면 목록에서 선택합니다.
   - **소수점 구분 기호**: **마침표 (1,234.56)** 또는 **쉼표 (1.234,56)** 입니다.
   - **날짜 형식**: 파일에 날짜가 있을 때 표시됩니다. 감지된 형식이 틀리면 `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY`, `MM/DD/YYYY` 중에서 변경합니다.
   - **파일의 열**, **유형**, **예제**, **이동 위치**로 이루어진 표입니다. 열을 다른 필드로 보내거나 **로드 안 함**으로 지정하려면 **이동 위치**를 변경합니다.

4. 파일에서 제기되는 질문에 답합니다. 예를 들어 **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?**, **Are revenues shown as negative numbers?** 같은 질문이 있습니다. 각 질문은 파일에 해당 정보가 없을 때만 표시됩니다.

5. 각 열의 이동 위치를 확인한 다음 **매핑 확정**을 클릭합니다.

</Steps>

다음 옵션은 해당하는 경우 파일에 표시됩니다.

| 옵션 | 용도 |
|---|---|
| **Which source do these rows apply to?** | 코드 매핑 파일을 하나의 소스로 제한합니다. **Every source**는 모든 소스에 적용합니다. |
| **Where does this file come from?** | 파일이 **This project's own codes**를 담고 있는지, 이름을 지정하는 **Another system**(예: `SAP Germany export`)에서 온 것인지 지정합니다. 다른 시스템에서 온 파일은 ERP 소스처럼 공유 코드 여부를 검사합니다. |
| **Split … into … parts at each …** (**고급** 아래) | `100-200-300`처럼 여러 값을 담은 열 하나를 분할하여 각 부분을 별도 필드로 보냅니다. |
| **Which currency do you report in?** | 프로젝트에 보고 통화가 아직 없을 때 보고 통화를 설정합니다. `USD`처럼 세 글자로 씁니다. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 통합 시스템의 결과를 로드하여 그룹 손익계산서를 [대사](#통합-시스템과-대사)할 수 있게 합니다. |

프로젝트에서 파일을 제거하려면 **파일** 아래에서 파일 옆의 **제거**를 클릭하거나 매핑 화면에서 **Remove this file**을 클릭한 다음 확인합니다. 해당 파일의 수치는 다음에 **Apply changes**를 클릭할 때 보고서에서 사라집니다.

PlaidCloud가 데이터 세트, 소수점 구분 기호, 날짜 순서를 스스로 결정할 수 없는 경우(예: 날짜를 일/월 또는 월/일로 읽을 수 있는 파일)에는 확정하기 전에 선택하도록 요청합니다. 같은 데이터 세트에 두 번째 파일을 추가하면 첫 번째 파일이 대체됩니다. 이후 파일의 열이 데이터 세트와 일치하지 않으면 로드가 해당 파일과 열을 알려 주고, 파일이나 열 이름을 수정하거나 단계의 **Schema Mismatch**를 `union`으로 설정하라고 안내합니다.

사용할 수 있는 파일은 CSV, TSV, TXT 텍스트 파일, Excel `.xlsx` 파일(첫 번째 시트를 읽음), Parquet 파일입니다.

<Aside type="note">
없거나 비어 있는 파일 때문에 로드가 중단되는 일은 없습니다. 파일을 추가하면 아직 매핑할 내용이 없다고 알려 주며, 로드는 경로를 알리는 경고와 함께 끝나고 해당 데이터 세트는 비어 있게 됩니다. 파일이 준비되면 다시 추가합니다.
</Aside>

## 데이터 로드

**로드** 카드 또는 **마지막 로드** 카드에서 **로드**를 클릭합니다. 로드는 연결된 ERP와 확정한 파일을 읽어 Common Finance Model에 맞게 변환하고, 보고 통화로 환산하며, 준비 상태 검사를 실행하고, 템플릿의 모델을 다시 구축합니다.

- 프로젝트당 한 번에 하나의 로드만 실행됩니다. 두 번째 **로드** 또는 **Apply changes**는 이미 로드가 실행 중이라고 알려 주며, 로드가 실행되는 동안에는 소스를 변경할 수 없습니다.
- 다른 워크플로가 같은 ERP 연결을 사용하는 경우, 로드는 ERP에서 읽기 때문에 해당 워크플로가 느려질 수 있으므로 첫 로드에서 그 워크플로들을 나열하고 확인을 요청합니다. 계속하려면 **그래도 로드**를 클릭합니다.
- PlaidCloud를 업그레이드한 후에는 아키텍트의 **로드**가 프로젝트의 생성된 워크플로도 업데이트하고 필요한 작업 테이블을 만듭니다. 그때까지 상태 페이지에는 "워크플로가 이전 릴리스에서 생성되었습니다. 아키텍트가 로드하면 업데이트됩니다."라는 주황색 항목이 표시되며, 관리자의 **로드**는 아키텍트만 업데이트할 수 있다고 경고합니다.
- 실패한 로드는 빨간색으로 표시되며 이전 결과 뒤에 가려지지 않습니다. 통합이 실패하면 상태에 이전 그룹 결과를 보여 주는 대신 중단된 단계가 표시됩니다. 이전 로드의 행에는 로드에 성공하기 전까지 **이전 로드의 결과입니다. 다시 로드하십시오.** 가 표시됩니다.
- 엔터티와 기간 하나를 읽지 못해도 나머지는 로드됩니다. **로드**를 다시 실행하면 실패한 부분만 가져옵니다.

### 보류된 행

소스가 겹치는 경우 로드는 각 수치의 사본을 하나만 유지하고 나머지는 이중으로 계산하지 않도록 보류합니다. 보류된 행은 소스, 엔터티, 사유와 함께 기록되며, 로드는 건수를 알리는 경고와 함께 끝납니다. 예를 들면 `120 rows of NetSuite EU also provided by a source ranked ahead`와 같습니다. 사유는 다음과 같습니다.

| 사유 | 의미 |
|---|---|
| 다른 회계 장부에 있음 | 행이 소스가 읽도록 설정되지 않은 보고 장부에 속합니다. |
| 소스가 제공하는 기간 밖임 | 행이 회사에 설정된 **시작** 및 **종료** 월 밖에 있습니다. |
| 더 높은 순위의 소스도 제공함 | 순서가 더 높은 소스가 같은 회사와 월을 다룹니다. |
| 소스의 이전 파일에도 있음 | 같은 소스의 이전 파일이 이미 해당 월을 다룹니다. |
| 파일로 대체됨 | 파일이 해당 엔터티와 월의 ERP 행을 대체합니다. |
| 다른 소스도 사용하는 코드임 | 코드에 대한 사용자의 답변이 필요합니다. [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오. |
| 두 코드에 매핑된 코드임 | 코드 매핑이 해당 코드에 두 가지 답을 줍니다. |

통계 계정은 원장 대신 배부 동인으로 이동하며, 문제가 아니라 이동한 것으로 표시됩니다.

### ERP 데이터와 파일 함께 사용

파일은 자신이 다루는 범위만 대체하며, ERP의 나머지 행은 그대로 유지됩니다.

- **마스터 파일**(계정, 부서, 고객, 제품, 세그먼트 값)은 같은 코드를 가진 ERP 행을 대체합니다.
- **트랜잭션 파일**은 같은 엔터티와 월의 ERP 행을 대체합니다. 총계정원장 및 시산표 파일은 원장 기준으로도, 예산 파일은 시나리오 기준으로도, 통계 동인 파일은 시나리오와 동인 기준으로도 일치시킵니다.

파일이 나중에 어떤 월을 더 이상 다루지 않으면 다음 로드에서 해당 월의 ERP 데이터가 다시 사용됩니다.

## 엔터티 매핑표

각 소스는 자체 코드로 엔터티의 이름을 지정합니다. **엔터티 매핑표**는 이러한 코드를 엔터티 마스터의 엔터티에 매핑하여 모든 소스의 라인이 같은 엔터티에 반영되도록 합니다.

사용하려면 CSV 또는 Excel 파일을 추가하고 **엔터티 매핑표** 데이터 세트를 선택합니다.

| 열 | 내용 |
|---|---|
| `source_entity` | 회사 코드처럼 소스가 가진 코드입니다. |
| `entity` | 엔터티 마스터에 나와 있는 해당 코드가 속한 엔터티입니다. |

- 매핑표에 없는 코드는 그대로 사용됩니다.
- 여러 코드를 하나의 엔터티에 매핑할 수 있습니다. 해당 라인은 합산되며, 모든 코드가 마감되어야 해당 월이 마감된 것으로 간주됩니다.
- 매핑표의 코드는 모든 소스에 적용되므로 각 소스의 엔터티 코드는 소스 간에 고유해야 합니다.
- **엔터티** 파일의 행은 같은 엔터티 코드를 가진 ERP의 엔터티를 대체합니다.

**매핑되지 않은 엔터티** 검사는 엔터티가 엔터티 마스터에도 없고 매핑표로 매핑되지도 않은 모든 라인을 표시합니다. 엔터티 마스터가 로드되기 전에는 **– 해당 없음**으로 표시됩니다.

## 소스 간 코드 매핑

두 소스가 같은 코드를 서로 다른 대상에 사용하거나, 같은 대상에 서로 다른 코드를 사용할 수 있습니다. 코드가 둘 이상의 소스에 나타나면 Data Foundation은 모든 곳에서 같은 의미인지 직접 알려 줄 때까지 해당 행을 보류하여 각 금액이 한 번만 계산되도록 합니다. **Codes waiting for your answer** 검사는 이러한 코드를 처음 10개까지 나열하고 "외 K개"로 표시하며, **Foundation** 탭의 **What to do next** 카드에는 **검토** 버튼이 있습니다.

**검토**는 **Codes waiting for your answer**를 엽니다. 코드를 **Account types**, **Companies**, **Accounts**, **Departments**, **Profit centers**, **Customers**, **Products**와 추가 범주 각각으로 구분하여 그룹화합니다. 각 코드에 대해 소스별 이름과 제안이 표시됩니다.

- **Looks like the same thing**: 소스들이 코드에 같은 이름을 사용한 경우입니다.
- **Looks like different things**: 이름이 서로 다른 경우입니다.
- **We can't tell. Please answer.**: 판단할 근거가 없는 경우입니다.

코드를 하나씩 **Yes, the same** 또는 **No, different**로 답하거나, 그룹 전체에 **Accept all**(모든 제안 수락), **All the same**, **All different**로 한 번에 답할 수 있습니다. 계정의 경우 계정과목표의 상위 그룹 전체에 한 번에 답할 수도 있습니다. 소스에 계정 유형이 없는 경우 계정 그룹에 **Use this type**을 선택합니다. 선택할 수 있는 유형은 **수익**, **매출원가**, **영업비용**, **영업외손익**, **자산**, **부채**, **자본**입니다.

매핑은 소스와 차원별로 유지되므로 한 소스의 부서에 대한 답이 다른 소스의 계정을 변경하는 일은 없습니다. 답변은 진행하는 대로 저장되며 **Saved. Press Apply changes to use your answers.** 메시지가 표시됩니다. 답변을 사용하려면 **Apply changes**를 클릭합니다.

파일로 매핑을 제공할 수도 있습니다. **Code map** 데이터 세트로 파일을 추가하고, **Which source do these rows apply to?** 를 선택하여 하나의 소스로 제한합니다.

## 기준 소스 전환 시점 선택

두 소스가 같은 개월을 제공하는 경우 **Which source covers which months** 검사가 선택을 요청합니다. **What to do next** 카드에서 **Choose which source counts from when**을 클릭하면 회사별로 겹치는 구간을 나열한 **Which source counts from when**이 열립니다. 적용할 소스를 선택하고 **That month is**에 적용 시작 월(예: `2026-04`)을 입력한 다음 **Apply changes**를 클릭합니다. 다른 소스는 그 이전 개월을 유지합니다.

두 소스가 한 통화에 대해 서로 다른 환율을 제공하면 같은 대화 상자에서 경고하며, 순서가 더 높은 소스의 환율이 사용됩니다.

## 통화 환산

로드할 때마다 총계정원장, 시산표, 판매, 재고, 예산 금액이 현지 통화에서 하나의 보고 통화로 환산됩니다. 보고서와 모델은 환산된 금액을 읽으므로 어느 시스템에서 왔든 서로 다른 통화의 엔터티가 올바르게 합산됩니다.

### 보고 통화

보고 통화를 선택하려면 프로젝트 변수 `reporting_currency`를 `USD` 같은 통화 코드로 설정합니다. [프로젝트 변수 관리](/ko/guides/projects/managing-projects/#프로젝트-변수-관리)를 참조하십시오. 템플릿은 이 변수를 빈 값으로 만듭니다. 비어 있는 동안 각 로드는 다음 중 정확히 하나의 통화를 가리키는 첫 번째 항목을 사용합니다.

1. 엔터티의 그룹 통화.
2. 상위가 없는 최상위 엔터티의 현지 통화.
3. 파일의 현지 통화.

어느 것도 정확히 하나의 통화를 가리키지 않으면 `reporting_currency`를 설정하기 전까지 **통화 환산**에 문제가 표시됩니다.

이미 보고 통화로 된 금액은 그대로 유지되므로 모든 데이터가 한 통화인 프로젝트에는 환율이 필요하지 않습니다.

판매, 재고, 예산 파일도 통화를 포함할 수 있습니다. `Currency` 또는 `Local Currency`라는 열을 매핑하면 자동으로 인식되며, 파일의 현지 금액이 보고 통화로 환산됩니다. 파일에 이미 있는 그룹 또는 보고 금액은 그대로 유지됩니다. 제품 표준 원가는 환산되지 않습니다.

### 환율

환율은 특정 월에 통화 한 단위를 보고 통화로 변환하는 비율이며, 환산된 금액은 현지 금액에 환율을 곱한 값입니다.

- **ERP에서**: 로드할 때마다 ERP가 보유한 환율을 읽습니다.
- **파일에서**: CSV 또는 Excel 파일을 추가하고 **환율** 데이터 세트를 선택합니다. 파일의 환율은 같은 통화 쌍과 월에 대한 ERP의 환율을 대체합니다. ERP가 환율을 게시하지 않는 통화로 보고하거나 예산 월에 대한 계획 환율을 추가할 때 파일을 사용합니다.

| 열 | 내용 |
|---|---|
| `from_currency` | 환산 전 통화입니다(예: `EUR`). |
| `to_currency` | 보고 통화입니다(예: `USD`). |
| `period` | `YYYY-MM` 형식의 월입니다. |
| `average_rate` | 해당 월의 평균 환율입니다. |
| `closing_rate` | 월말 환율입니다. |
| `historical_rate` | 자본 및 역사적 환율로 설정된 계정에 사용하는 역사적 환율입니다. |

보고 통화로 환산하는 환율만 사용됩니다. 반대로 보고 통화에서 다른 통화로 표시된 환율은 역수로 변환되지 않습니다.

### 적용되는 환율

각 행은 자체 통화에서 환산되므로 엔터티와 통화가 다른 라인은 해당 라인의 통화에서 환산됩니다. 행에 맞는 첫 번째 규칙이 적용됩니다.

| 행 | 환율 |
|---|---|
| 통계 계정 및 비전기 계정 | 환산하지 않습니다. |
| 이미 보고 통화인 행 | 환산하지 않습니다. |
| 환율 유형이 있는 계정 | 해당 환율(평균, 기말, 역사적)을 적용합니다. 역사적 환율이 없으면 기말 환율을 대신 사용합니다. ERP에서는 계정 자체의 환율 유형이 사용됩니다. 계정과목표 파일에서는 환율 유형 열을 `average`, `closing`, `historical` 값과 함께 `fx_rate_type`에 매핑합니다. |
| 판매 라인 | 해당 기간의 평균 환율입니다. |
| 재고 잔액 | 해당 기간의 기말 환율입니다. |
| 예산 행 | 총계정원장처럼 계정별로 적용합니다. 손익계산서 계정은 평균 환율, 재무상태표 계정은 기말 환율입니다. |
| 손익계산서 계정 | 해당 기간의 평균 환율입니다. |
| 자본 계정 | 역사적 환율이며, 역사적 환율이 없으면 기말 환율입니다. |
| 그 밖의 재무상태표 계정 | 해당 기간의 기말 환율입니다. |

환산된 금액은 반올림하지 않으므로 합계에 오차가 누적되지 않습니다.

<Aside type="note">
시산표에는 각 기간의 변동액이 담기므로, 재무상태표 금액은 각 월의 변동액을 해당 월의 기말 환율로 환산한 값입니다. 기말 환율로 다시 환산한 재무상태표가 아니며, 누적 환산 조정이나 내부거래 소거도 없습니다. 환산된 금액은 손익계산서에 사용하십시오.
</Aside>

## 계층

로드할 때마다 모든 소스의 마스터 데이터로 차원을 다시 구축합니다. 기본 차원은 7개이며 추가 범주는 최대 10개입니다.

| 차원 | 구성 기준 |
|---|---|
| **엔터티** | 엔터티와 상위 엔터티 |
| **계정** | 계정과목표와 상위 계정 |
| **부서** | 부서와 상위 부서 |
| **고객** | 고객과 상위 고객 |
| **제품** | 제품과 상위 제품 |
| **세그먼트 1** | `segment_1`의 세그먼트 값 |
| **세그먼트 2** | `segment_2`의 세그먼트 값 |
| **세그먼트 3**~**세그먼트 10** | 소스에 있는 경우 `segment_3`~`segment_10`의 세그먼트 값 |

- 상위가 없거나 자기 자신을 상위로 지정한 레코드는 최상위 멤버로 로드됩니다.
- 로드할 때마다 계층을 다시 구축하므로, 상위 항목은 차원이 아니라 ERP나 파일에서 변경합니다.
- 한 계층의 문제는 해당 차원에만 영향을 줍니다. 로드와 템플릿의 모델은 계속 완료됩니다.
- 각 추가 범주의 이름을 담고 있는 내용에 맞게 **클래스**나 **리전**처럼 바꿀 수 있습니다. **Rename extra categories**에서 보고서에 사용하는 이름을 입력하고 **Save names**를 클릭합니다. 이름에는 문자, 숫자, 공백, 마침표, 대시, 밑줄을 사용할 수 있으며 최대 60자입니다.
- 각 소스는 자체 추가 범주가 사용자의 어떤 범주 이름 아래에 들어갈지 지정합니다. 소스에서 **고급**을 열어 각 범주의 이름을 선택하거나 **Leave out**을 선택한 다음 **저장**을 클릭합니다. `Class`와 `Business area`처럼 범주를 서로 다른 이름으로 부르는 소스들은 하나의 슬롯을 공유하게 됩니다.

파일로 세그먼트 계층을 제공하려면 **세그먼트 값** 데이터 세트를 선택합니다.

| 열 | 내용 |
|---|---|
| `segment` | 값이 속한 세그먼트입니다(`segment_1`~`segment_10`). |
| `segment_value` | 총계정원장, 판매, 예산 라인에 있는 그대로의 값입니다. |
| `segment_value_name` | 값의 이름입니다. |
| `parent_segment_value` | 같은 세그먼트 내의 상위 값입니다. |

## 준비 상태 검사

각 로드 후 **준비 상태** 그리드에 모든 엔터티와 기간의 모든 검사가 나열되며, 상태는 다음 중 하나입니다.

| 상태 | 의미 |
|---|---|
| **● 준비됨** | 검사를 통과했습니다. |
| **▲ 확인 필요** | 살펴볼 필요는 있지만 수치는 사용할 수 있습니다. |
| **■ 문제** | 결과를 사용하기 전에 해결하십시오. |
| **– 해당 없음** | 이 검사에 대한 데이터가 아직 없습니다. |

검사 항목은 다음과 같습니다.

| 검사 | 확인하는 내용 |
|---|---|
| **데이터 로드됨** | 모든 회계 기간에 총계정원장 라인이 있고 모든 ERP 읽기가 성공했습니다. 라인이 없는 마감된 기간은 문제이며, 라인이 없는 미마감 기간은 확인이 필요합니다. |
| **시산표와 총계정원장 일치** | 엔터티, 기간, 계정별로 시산표가 총계정원장과 같습니다. 시산표와 총계정원장 모두 계정에 부서가 있는 경우에는 부서별로도 일치하는지 확인합니다. |
| **판매와 총계정원장 일치** | 기간별로 판매 라인이 총계정원장의 수익 및 매출원가 계정과 같습니다. |
| **알 수 없는 제품/고객** | 모든 판매 라인이 제품 마스터와 고객 마스터에 있는 제품과 고객을 지정합니다. |
| **계정과목표에 없는 계정** | 모든 총계정원장 라인이 계정과목표에 있는 계정을 지정합니다. 알 수 없는 계정이 있는 라인은 손익계산서에서 제외됩니다. 전기 내역은 있으나 계정 유형이 없는 계정도 문제이며, 계정과목표에서 수익 계정에는 유형이 있으나 매출원가 계정이 없는 소스는 확인이 필요합니다. |
| **통화 환산** | 모든 총계정원장, 시산표, 판매, 재고, 예산 행에 보고 통화 금액이 있습니다. 환율이 없는 손익계산서 또는 판매 행은 손익계산서가 환산된 금액을 읽기 때문에 문제입니다. 환율이 없는 재무상태표, 재고, 예산 행은 확인이 필요합니다. 아직 환율이 없는 예산 월은 주황색으로 표시되므로 예산 월에 대한 계획 환율을 로드하십시오. [통화 환산](#통화-환산)을 참조하십시오. |
| **매핑되지 않은 엔터티** | 모든 총계정원장, 시산표, 판매 라인이 직접 또는 엔터티 매핑표를 통해 엔터티 마스터의 엔터티를 지정합니다. 엔터티 마스터가 로드되기 전에는 해당 없음입니다. [엔터티 매핑표](#엔터티-매핑표)를 참조하십시오. |

소스가 둘 이상인 로드에는 다음 검사가 추가됩니다.

| 검사 | 확인하는 내용 |
|---|---|
| **Reporting book** | 엔터티에 회계 장부가 여러 개인 소스에서 보고 장부를 선택했습니다. 선택하기 전에는 첫 번째 장부만 계산됩니다. |
| **Codes waiting for your answer** | 둘 이상의 소스가 사용하는 모든 코드에 답했습니다. [소스 간 코드 매핑](#소스-간-코드-매핑)을 참조하십시오. |
| **Extra categories from your sources** | 소스에 있는 모든 추가 범주에 이름이 있거나 제외되었습니다. |
| **Which source covers which months** | 어느 쪽을 적용할지 선택하지 않은 경우 두 소스가 한 회사의 같은 개월을 제공하지 않습니다. |
| **Account types and hierarchy** | 차원이 지정하는 모든 상위 항목이 존재하며, 어떤 멤버도 자기 자신의 상위이거나 조상이 아닙니다. 상위가 없으면 그 하위 항목이 계층의 최상위에 놓이고, 순환이 있으면 해당 계층의 로드가 중단됩니다. 합계에는 영향이 없습니다. |
| **회계 달력** | 각 엔터티의 회계 기간이 달력 월이며, 모든 월의 행을 하나의 회계 기간에 배치할 수 있습니다. 엔터티의 기간이 달력 월이 아니거나(4-4-5, 13기간), 한 월의 행이 둘 이상의 회계 기간에 속할 수 있거나, 회계 달력에 해당 월이 없으면 확인이 필요합니다. |

준비되지 않은 각 행은 **조치 사항** 열에 해야 할 일을 알려 줍니다. 예를 들어 계정과목표를 로드하거나, 환율을 로드하거나, 해당 기간에 대해 **로드**를 다시 실행하라는 안내가 있습니다.

그리드에는 확인이 필요할 때만 나타나는 두 가지 설정 검사도 표시됩니다.

| 검사 | 표시되는 경우 |
|---|---|
| **간접비 배부** | 프로젝트 변수 `overhead_department`와 `overhead_driver` 중 하나만 설정되었거나 `overhead_driver`와 일치하는 배부 동인이 없어 배부가 아무 일도 하지 않는 경우입니다. 둘 다 설정하거나, 간접비 배부를 끄려면 둘 다 비웁니다. |
| **예산 비교** | 예산 행이 로드되었지만 프로젝트 변수 `budget_version`이 지정한 버전에 해당하는 행이 없어 예산 비교가 비어 있는 경우입니다. |

## 관리 통합

로드할 때마다 관리 통합을 만듭니다. 이는 그룹에 속한 모든 엔터티의 그룹 손익계산서이며, 보고 통화로 표시되고 내부거래가 소거됩니다. 관리 보고용입니다. 법정 그룹의 공식 기록은 통합 시스템이 계속 담당하므로 아래 방법으로 통합 시스템과 대사하십시오.

<Aside type="note">
관리 통합은 손익계산서만 다룹니다. 법정 통합이나 법적 통합이 아니며, 통합 재무상태표, 환산 조정, 영업권, 비지배지분은 없습니다.
</Aside>

### 그룹 선택

**소스** 아래에서 **그룹**을 열어 그룹에 속한 회사를 확인합니다. 선택을 해제한 회사는 보고서에는 단독으로 계속 표시되지만 그룹 합계에서는 제외됩니다. **Save group**을 클릭합니다. 변경 사항은 다음 **로드** 또는 **Apply changes** 때 적용됩니다. 새 회사는 선택을 해제하기 전까지 그룹에 포함됩니다.

그룹의 회계 연도는 프로젝트 변수 `group_fy_start_month`가 지정한 월에 시작하며, 변경하지 않으면 `1`입니다.

### 제공되는 항목

| 테이블 | 내용 |
|---|---|
| **Group P&L** | 엔터티, 기간, 라인(수익, 매출원가, 영업비용, 영업외손익, 내부거래 차이)별로 한 행이며 보고 통화로 표시됩니다. 수익과 비용은 본래의 부호를 유지합니다. |
| **Group P&L year to date** | 같은 내용을 연초부터 그룹의 마지막으로 완전히 로드된 기간까지 누계로 보여 줍니다. |
| **Intercompany pairs** | 엔터티 쌍, 그룹, 기간별로 한 행이며 양쪽의 금액과 잔차가 있습니다. |
| **Intercompany lines** | 그룹 수치 또는 쌍의 근거가 되는 원장 라인과 거래 상대방입니다. |
| **Reconciliation** | 연초부터 누계 그룹 손익계산서와 통합 시스템을 비교한 결과입니다. |

이 테이블에는 세 가지 엔터티 이름이 나타납니다.

| 엔터티 | 의미 |
|---|---|
| **Eliminations** | 내부거래 소거입니다. 합이 0이 되므로 그룹 수치에는 포함하고, 소거 전 엔터티 합계에서는 필터링하여 제외합니다. |
| **Group total** | 대사에서 통합 시스템의 합계입니다. |
| **Unmapped** | 기간이 없는 라인과 통합 시스템에는 있지만 이 프로젝트에는 없는 계정 또는 엔터티입니다. |

**Consolidated income**, **Consolidated result**, **IC difference** 지표와 각 테이블용 분석 경로는 그룹에 관한 질문에 답합니다.

### 내부거래 소거

내부거래 라인은 거래 상대방으로 매칭됩니다. 라인의 상대방을 사용하며, 라인에 상대방이 없으면 해당 고객의 상대방을 사용합니다. 쌍의 양쪽이 모두 소거되며, 두 쪽이 일치하지 않는 금액은 내부거래 차이 라인으로 기록됩니다. 각 쌍에는 사유가 표시됩니다.

| 사유 | 의미 |
|---|---|
| **일치** | 양쪽이 같은 금액을 기록했습니다. |
| **한쪽만 기록됨** | 한 엔터티는 거래를 기록했지만 상대방은 기록하지 않았습니다. |
| **소거되지 않음** | 쌍의 한 라인에 환율이 없어 양쪽 모두 소거되지 않습니다. |

쌍은 연초부터 누계 기준으로 판단합니다. 쌍의 차이가 프로젝트 변수 `group_amber`(기본값 `1`)를 넘으면 **Intercompany balances** 행이 주황색으로, `group_red`(기본값 `1000`)를 넘으면 빨간색으로 바뀝니다. 상대방이 없거나 상대방이 엔터티가 아닌 라인은 소거되지 않으며 해당 행에 건수로 집계됩니다. 상대방이 있는 소스와 없는 소스가 함께 있으면 주황색으로 표시됩니다.

소스 자체의 소거 엔터티는 그룹 손익계산서에서 제외되며 **통합** 행에 이 사실이 표시됩니다.

### 통합 시스템과 대사

통합 시스템이 보고하는 결과를 파일로 추가하고 매핑을 확정할 때 **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** 를 선택합니다. **Which version of the numbers is this?** 에는 시스템 이름으로 답합니다. 그러면 **Reconciliation** 테이블에 엔터티와 라인별로 연초부터 누계 **ours**, **reported**, **차이**가 표시됩니다. 차이는 대개 **Eliminations**, **Group total**, **Unmapped** 행이나 시스템이 사용하는 환율로 설명됩니다. **Reconciliation to the source** 행에는 `group_amber`를 넘는 모든 라인이 나열됩니다.

### 볼 수 있는 사람

그룹 결과는 프로젝트의 행 액세스를 따릅니다. 행 액세스 때문에 그룹 결과를 볼 수 없으면 상태가 주황색으로 표시됩니다. 일부 엔터티만 볼 수 있는 사람은 해당 엔터티의 소거 전 합계를 봅니다. **Eliminations** 행과 내부거래 테이블을 보려면 모든 엔터티에 대한 액세스가 필요합니다.

프로젝트가 부서처럼 그룹 테이블에 없는 열을 기준으로 누가 어떤 행을 볼 수 있는지 제한하는 경우, 그룹 결과는 모든 사용자에게 꺼지고 **통합**에 **Group views are off**가 표시됩니다. 이 경우 아키텍트만 **그룹** 아래에서 **Everyone on the project may see the group results**를 선택할 수 있습니다. 변경 사항은 다음 **로드** 또는 **Apply changes** 때 적용됩니다.

## 최신 상태 유지

ERP 연결에서의 로드가 문제 없이 성공하면 **마지막 로드** 카드에 **야간 새로 고침**이 나타납니다. 이를 클릭하면 사용자의 시간대 기준 매일 밤 2:00에 **로드**가 실행됩니다. 그러면 카드에 **Nightly refresh: Every night at 2:00**과 설정한 사람이 표시됩니다.

야간 로드는 설정한 사람의 권한으로 실행됩니다. 해당 사람이 더 이상 ERP 연결을 사용할 수 없으면 그리드에 야간 로드를 건너뛴다고 표시되므로 다시 설정하십시오. 샘플 데이터만 있는 프로젝트는 일정을 설정할 수 없습니다.

야간 로드에서 없거나 비어 있는 파일은 오류가 아니라 경로를 알리는 경고와 함께 끝나며, 나머지 모델은 계속 로드됩니다.

## 비즈니스 이름

**Foundation** 탭의 **Business names**는 모델의 코드에 비즈니스에서 쓰는 이름을 지정합니다. 보고서, 지표, 어시스턴트가 이 이름을 표시하며, 저장한 이름은 즉시 적용됩니다. 이후 로드에서도 유지됩니다.

1. **Add a name**을 클릭하고 **종류**를 선택합니다. **범주**, **P&L line**, **지표**, **열** 중에서 선택합니다.
2. **코드**를 입력합니다. 범주는 `segment_1`~`segment_10`, P&L 라인은 라인의 키, 지표는 지표의 이름, 열은 `table.column`을 입력합니다.
3. **이름**을 한 줄로 최대 60자까지 입력합니다.
4. **Save names**를 클릭합니다.

저장하면 전체 목록이 대체됩니다. 이름이 비어 있는 행은 해당 이름을 제거하며, **선택 항목 제거**는 선택한 행을 제거합니다. 같은 코드에 이름을 두 번 지정하는 것은 거부됩니다. 비즈니스 이름은 어시스턴트가 사용자의 용어를 쓰도록 분석 경로의 설명에도 기록되는데, 이 설명에는 길이 제한이 있습니다. 이름 때문에 설명이 너무 길어지면 아무것도 저장되지 않고 그 사실이 안내됩니다.

## 수치 설명

**Explain this number**는 손익계산서 수치 하나가 무엇으로 구성되는지 보여 줍니다. **준비 상태** 그리드에서 엔터티와 월의 행에 있는 **Explain this number**를 클릭하면 해당 월의 엔터티 영업이익률이 열립니다. 창은 수치를 맨 위의 합계가 되도록 합산되는 계층으로 나눕니다.

| 계층 | 내용 |
|---|---|
| **From the general ledger** | 원장이 해당 라인에 전기한 내용입니다. |
| **Allocated in** | [배부 규칙](#배부-규칙)에 따라 이 엔터티로 배분된 비용입니다. |
| **Allocated out** | 이 엔터티가 다른 곳으로 배분한 비용입니다. |
| **Eliminated in the group** | 그룹 결과에서 소거된 내부거래입니다. |

각 계층에는 그 계층이 무엇인지 설명하는 문장과, 소스 시스템, 문서, 계정이 포함된 가장 큰 소스 문서가 표시됩니다. 행이 있는 계층만 표시됩니다. 창은 행 액세스를 따르므로 볼 수 있는 수치만 설명할 수 있습니다. 근거가 없는 수치에는 **Nothing to explain**이 표시됩니다.

## 배부 규칙

배부는 간접비 같은 공통 비용을 부서, 제품, 고객에게 배분합니다. 모델에는 **Stage 1: overhead to departments**와 **Stage 2: departments to products and customers**의 두 단계가 있습니다. **작업 > 배부...** 메뉴를 열어 각 단계의 방식을 확인하거나 변경합니다. 변경하지 않으면 마법사가 도입되기 전과 동일하게 동작합니다. 읽기 권한만 있는 사용자는 규칙을 열 수는 있지만 저장할 수 없습니다.

마법사는 각 단계마다 네 가지 질문을 합니다.

| 단계 | 질문 | 선택 항목 |
|---|---|---|
| **Pool** | 어떤 비용을 배분하시겠습니까? | 계정의 종류이며, 1단계에서는 비용을 보유한 부서 또는 **All departments**입니다. |
| **Driver** | 무엇을 기준으로 배분하시겠습니까? | 헤드카운트나 면적(제곱피트)처럼 배부 동인으로 로드한 **Statistic**, **Net sales amount**, **Sales quantity**, **Spread evenly** 중에서 선택합니다. **Same period** 또는 **Same period last year**의 동인을 사용합니다. |
| **대상** | 어디에 반영됩니까? | 1단계: 부서. 2단계: 제품, 고객 또는 둘 다. |
| **메서드** | 동인이 음수이면 어떻게 합니까? | **Ignore negative values** 또는 **Stop and tell me**. |

단계 아래의 **Preview for**에 `2026-09`처럼 연도와 월로 쓴 월을 입력하면 저장하지 않은 규칙을 포함해 규칙이 어떤 결과를 내는지 `Pool 120,000 · Allocated 120,000 · Unallocated 0`과 같이 표시합니다. 배분되지 않은 금액은 이를 받을 동인이 없던 비용입니다. 미리 보기는 행 액세스를 따릅니다.

**저장**을 클릭합니다. 규칙은 다음 **로드** 때 또는 **Apply changes**를 클릭하면 적용됩니다. 배부 단계를 직접 수정한 경우 수정 내용은 덮어쓰지 않고 유지되며, 저장 시 해당 단계가 안내됩니다. 로드가 실행되는 동안에는 저장할 수 없습니다.

## Board Pack

Board pack은 결과를 일정에 따라 문서 계정의 폴더에 기록하여 바로 보낼 수 있게 준비합니다. **작업 > Board pack...** 메뉴를 열고 **문서 계정**과 `/board-packs` 같은 **폴더**를 선택한 다음 **저장**을 클릭합니다. 실행할 때마다 다음이 기록됩니다.

- 엔터티별 손익계산서, 마진 브리지, 상위 및 하위 고객이 담긴 Excel 통합 문서 `Board pack.xlsx`.
- 손익계산서 대시보드의 PDF.

프로젝트에 대시보드가 아직 없으면 통합 문서만 기록되고 실행 결과에 그 이유가 표시됩니다. **Run now**를 클릭하면 즉시 팩을 만들며, 완료되면 파일이 폴더에 나타납니다. 카드에는 마지막 실행과 그 결과, 다음 실행이 표시됩니다. 팩은 프로젝트의 **Board pack** 워크플로가 만들며 야간 새로 고침은 이 워크플로를 실행하지 않습니다. 일정에 따라 만들려면 야간 새로 고침이 끝난 이후 시각 등으로 [이벤트 스케줄러](/ko/administration/scheduled-events/event-scheduler/)에서 이 워크플로의 일정을 설정합니다. 프로젝트를 변경할 수 있는 사람만 설정할 수 있습니다.

## 복원 지점

복원 지점은 일정에 따른 로드를 포함하여 누가 시작하든 각 **로드** 또는 **Apply changes**가 시작될 때, 그리고 매핑이나 소스를 변경하기 전에 만들어집니다. 여기에는 모델의 테이블, 차원, 그리고 다음 로드가 구축에 사용하는 설정, 즉 소스, 파일, 배부 규칙이 담깁니다. 로드를 위해 만든 마지막 7개 지점과 변경 전에 만든 마지막 5개 지점이 유지되므로, 변경으로 인해 로드용 지점이 밀려나는 일은 없습니다. 더 오래된 지점은 삭제됩니다.

이전 상태로 돌아가려면 **작업 > 복원...** 메뉴를 열고 지점을 선택한 다음 **복원**을 클릭합니다. **복원**은 지점이 하나라도 있어야 제공됩니다. 복원하면 먼저 현재 프로젝트 상태를 별도의 지점으로 기록하므로 다시 돌아갈 수 있습니다. 그런 다음 테이블, 차원, 위 설정을 이전 상태로 되돌리며 다음 로드는 이를 기준으로 구축합니다. 저장된 복사본이 없는 테이블이나 이력을 보관할 수 없는 엔진은 경고에 표시되고 나머지는 복원됩니다. 삭제된 복원 지점은 거부되며, 로드가 실행되는 동안에는 복원할 수 없습니다.

## 프로젝트 복제

**작업 > 복제...** 메뉴는 지정한 이름으로 프로젝트를 복사합니다. 복사본은 템플릿, 모델에 대한 편집 내용, 지표, 분석 경로를 유지하며 샘플 데이터를 로드합니다. 소스는 연결되지 않으므로 로드하기 전에 복사본에서 연결하십시오. 복사본이 만들어지는 동안 작업을 계속할 수 있으며, 준비되면 **프로젝트 열기**를 클릭하여 이동합니다.

## 내 템플릿으로 저장

프로젝트 설정을 저장해 두었다가 다음 고객이나 엔터티에 재사용할 수 있습니다. **작업 > Save as my template...** 메뉴를 열고 문서 계정을 선택한 다음 파일 이름을 지정합니다. 이름 끝에 `.zip`이 없으면 자동으로 추가됩니다. 기존 파일을 덮어쓰는 것은 거부되므로 다른 이름을 선택하십시오.

파일에는 프로젝트의 구조, 모델에 대한 편집 내용, 지표, 분석 경로, 엔터티와 계정의 비즈니스 이름, 그리고 [Cost to Serve](/ko/guides/projects/cost-to-serve/)의 활동 매핑이나 [Operational Transfer Pricing](/ko/guides/projects/operational-transfer-pricing/)의 정책 범위처럼 템플릿의 구성 테이블 행이 담깁니다. 연결, 파일, 야간 일정, 실행 이력, 복원 지점, board pack, 액세스 권한은 포함되지 않습니다.

사용하려면 프로젝트를 만들고 **시작 기준**에서 **From a template file...** 을 선택한 다음 문서 계정과 경로를 지정합니다. 새 프로젝트는 본인만 볼 수 있으며 모든 소스가 연결을 기다리는 상태입니다. 이후 템플릿 릴리스는 사용자가 편집한 단계를 피해 변경 사항을 병합합니다. 해당 경로에 파일이 없으면 아무것도 만들어지지 않고 그 사실이 안내됩니다. 문서 계정을 읽을 수 있는 사람은 누구나 이 파일로 설치할 수 있습니다. 다른 워크스페이스에서 사용하려면 파일을 다운로드하여 해당 워크스페이스에 업로드합니다.

## Ask로 미해결 질문 해결

로드 후에도 프로젝트에는 답을 기다리는 항목이 세 가지 남아 있을 수 있습니다. 계정과목표에서 유형이 지정되지 않은 계정, 둘 이상의 소스가 사용하는 코드, 파일에서 어디에도 일치하지 않은 열입니다. 어시스턴트에게 이를 해결하도록 요청하십시오. MCP를 통한 AI 어시스턴트에서는 **Resolve Data Foundation residue** 프롬프트를 사용합니다. 이 프롬프트는 대기 중인 항목을 읽고 각 항목에 대해 이유와 함께 하나의 답을 제안합니다.

어시스턴트는 아무것도 기록하지 않습니다. 직접 답했을 위치에서 제안된 답을 적용합니다. 계정과 코드는 **Codes waiting for your answer**에서, 파일 열은 파일의 매핑에서 적용합니다. 어시스턴트는 엔터티를 제안하지 않습니다.

## 프로젝트 인계

**설정** 체크리스트에는 **계층 구조 검토** 뒤에 마무리 항목이 네 개 있습니다.

- **Set up the nightly refresh**는 **야간 새로 고침**이 켜지면 완료됩니다.
- **팀과 공유**는 프로젝트를 설정한 사람 외에 다른 사람이 멤버가 되면 완료됩니다.
- **Download the evidence pack**은 마지막 성공한 로드 이후 팩을 다운로드하면 완료됩니다.
- **Hand the project over to its owner**는 프로젝트를 설정한 사람이 아닌 아키텍트가 있고 합계가 일치하면 완료됩니다. 완료되지 않은 동안 체크리스트가 해야 할 일을 안내합니다. 고객의 소유자를 이 프로젝트의 아키텍트로 지정한 다음, 본인을 멤버에서 제거합니다.

체크리스트에는 프로젝트를 설정한 사람이 표시됩니다(**Set up by**).

## 템플릿으로 모델 위에 구축

템플릿은 Common Finance Model 위에 보고서와 모델을 구축하므로 어떤 ERP가 데이터를 공급하든 동일하게 동작합니다. **Enterprise Profitability** 같은 템플릿으로 프로젝트를 시작하면 다음이 만들어집니다.

- 비어 있거나 샘플 데이터로 채워진 [Common Finance Model 테이블](#common-finance-model-테이블).
- 해당 테이블로 구축된 **엔터티**, **계정**, **부서**, **고객**, **제품**, **세그먼트 1**, **세그먼트 2** 차원. [계층](#계층)을 참조하십시오.
- **로드** 워크플로와, ERP와 파일을 읽고 변환하며 준비 상태를 검사하고 템플릿의 모델을 구축하기 위해 이 워크플로가 실행하는 워크플로.
- 템플릿 자체의 보고서와 모델. **Enterprise Profitability**는 수익, 매출원가, 매출총이익, 직접 및 간접 영업비용, 공헌이익, 영업이익률이 포함된 손익계산서 테이블과, 전년 대비 및 예산 대비 마진 브리지를 추가합니다.
- 결과에 대해 질문할 수 있는 지표와 분석 경로.

**시작 기준** 아래에서 세 가지 템플릿을 사용할 수 있으며, 모두 같은 모델 위에 구축됩니다.

| 템플릿 | 추가되는 내용 |
|---|---|
| **Enterprise Profitability** | 손익계산서와 마진 브리지. |
| **Cost to Serve** | 고객별 서비스 제공 비용과 그 이후의 마진. [Cost to Serve](/ko/guides/projects/cost-to-serve/)를 참조하십시오. |
| **Operational Transfer Pricing** | 정책 범위에 대비한 각 엔터티의 이익 수준과 true-up. [Operational Transfer Pricing](/ko/guides/projects/operational-transfer-pricing/)을 참조하십시오. |

**From a template file...** 은 저장해 둔 프로젝트에서 시작합니다. [내 템플릿으로 저장](#내-템플릿으로-저장)을 참조하십시오.

자신의 ERP를 연결하기 전에 살펴보려면 프로젝트를 만들 때 **샘플 데이터로 시작**을 선택합니다. 프로젝트가 즉시 첫 번째 로드를 실행하므로 **Foundation** 탭에서 유로 엔터티를 미국 달러로 환산하는 것을 포함한 완전한 예제를 볼 수 있습니다. 자신의 ERP를 연결하거나 자신의 파일을 추가하면 샘플 행이 삭제되고 자신의 데이터로 대체됩니다.

## Foundation 탭

**Foundation** 탭에서 데이터를 연결하고, 로드하고, 검사합니다. 위에서 아래로 다음 섹션이 있습니다.

| 섹션 | 표시되는 내용 |
|---|---|
| **마지막 로드** | 마지막 로드의 성공, 실패, 실행 중 여부와 **로드**, **Apply changes**, **새로 고침**, **야간 새로 고침** 버튼. |
| **What to do next** | 주의가 필요한 항목이 중요한 순서대로 표시되며, 각 항목에 **검토** 또는 **Choose which source counts from when** 버튼이 있습니다. |
| **소스** | 순서대로 나열된 각 소스와 **고급**, **Remove this source**, **그룹**, **Rename extra categories**. |
| **설정** | 설정 체크리스트: **데이터 연결**, **데이터 로드**, **합계 일치 여부 확인**, **계층 구조 검토**, **Set up the nightly refresh**, **팀과 공유**, **Download the evidence pack**, **Hand the project over to its owner**. 현재 항목은 굵게 표시됩니다. |
| **Business names** | 비즈니스에서 범주, P&L 라인, 지표, 열에 사용하는 이름. [비즈니스 이름](#비즈니스-이름)을 참조하십시오. |
| **파일** | 추가한 각 파일, 해당 데이터 세트(예: **총계정원장** 또는 **환율**), 매핑이 **✓ 확정됨**인지 **○ 확정 대기 중**인지 여부. |
| **데이터 로드됨** | 엔터티별로 로드된 첫 기간과 마지막 기간, 준비된 기간 수. |
| **기간** | 각 엔터티의 회계 기간과 각 기간이 **✓ 종료됨**인지 **○ 열림**인지 여부. |
| **준비 상태** | 준비 상태 그리드: 엔터티, 기간, 검사별로 한 행이며 상태와 **조치 사항**이 표시됩니다. |
| 연결 | ERP를 연결하고, 엔터티와 로드할 이력 개월 수를 선택하거나, 다른 소스를 추가합니다. |
| **파일**(추가) | CSV, TSV, TXT, Excel 또는 Parquet 파일을 추가하고 열 매핑을 확정합니다. |
| **로드** | 로드를 시작합니다. **Apply changes**는 ERP에서 가져오지 않고 로드를 실행합니다. |

로드가 실행되는 동안 탭은 자동으로 새로 고침됩니다.

설정 체크리스트는 진행 상황을 추적합니다.

- **데이터 연결**과 **데이터 로드**는 소스가 연결되고 로드가 성공하면 자동으로 체크됩니다.
- **합계 일치 여부 확인**은 합계 일치 검사를 통과하면 자동으로 체크됩니다.
- **계층 구조 검토**: **차원 열기**를 클릭하여 엔터티, 계정, 부서 계층을 검토한 다음 **검토했습니다**를 선택합니다. 이 항목은 **직접 확정해야 합니다**.
- **Set up the nightly refresh**, **팀과 공유**, **Download the evidence pack**, **Hand the project over to its owner**가 목록을 마무리합니다. [프로젝트 인계](#프로젝트-인계)와 [프로젝트 액세스 관리](/ko/guides/projects/managing-projects/#프로젝트-액세스-관리)를 참조하십시오.

**작업** 메뉴에는 **배부...**, **Board pack...**, **복제...**, **복원...**, **Save as my template...** 항목이 있습니다. [배부 규칙](#배부-규칙), [Board Pack](#board-pack), [프로젝트 복제](#프로젝트-복제), [복원 지점](#복원-지점), [내 템플릿으로 저장](#내-템플릿으로-저장)을 참조하십시오.

## Common Finance Model 테이블

Data Foundation은 ERP이든 파일이든 모든 소스를 동일한 15개 테이블에 맞게 변환하므로, 이 테이블을 기반으로 구축한 보고서, 지표, 모델은 소스와 관계없이 동일하게 동작합니다. 각 행에는 소스 시스템과 읽은 시각도 기록됩니다. **데이터 세트** 열은 파일을 추가할 때 선택하는 이름입니다.

| 데이터 세트 | 테이블 | 내용 |
|---|---|---|
| 엔터티 | `cfm_entity` | 상위, 현지 및 그룹 통화, 국가가 포함된 법인. |
| 엔터티 매핑표 | `cfm_entity_map` | 소스 엔터티 코드와 각 코드가 속한 엔터티. [엔터티 매핑표](#엔터티-매핑표)를 참조하십시오. |
| 환율 | `cfm_fx_rate` | 통화 쌍별 월간 평균, 기말, 역사적 환율. [환율](#환율)을 참조하십시오. |
| 회계 달력 | `cfm_fiscal_calendar` | 엔터티 회계 기간당 한 행이며 시작일과 종료일, 마감 여부가 포함됩니다. |
| 계정과목표 | `cfm_account` | 상위, 유형(`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), 재무제표, 정상 잔액, 환율 유형이 포함된 계정. |
| 부서 | `cfm_department` | 상위와 이익 센터가 포함된 부서 및 원가 센터. |
| 제품 | `cfm_product` | 상위, 제품군, 그룹, 단위, 표준 원가가 포함된 제품 마스터. |
| 고객 | `cfm_customer` | 상위, 그룹, 지역, 국가가 포함된 고객 마스터. 고객 이름은 마스킹되지 않습니다. |
| 세그먼트 값 | `cfm_segment` | 이름과 상위가 포함된 세그먼트 값. [계층](#계층)을 참조하십시오. |
| 총계정원장 | `cfm_gl_journal` | 거래 통화, 현지 통화, 보고 통화로 된 분개 라인. |
| 시산표 | `cfm_trial_balance` | 엔터티, 계정, 부서별 기간 차변, 대변, 순액(현지 통화 및 보고 통화). |
| 판매 라인 | `cfm_sales_line` | 수량, 총액, 할인, 순액, 매출원가 금액이 포함된 청구 판매 라인. |
| 재고 잔액 | `cfm_inventory_balance` | 제품 및 창고별 기말 재고. |
| 예산 | `cfm_budget` | 시나리오, 버전, 계정, 부서별 예산 및 예측. |
| 배부 동인 | `cfm_stat_driver` | 헤드카운트, 면적(제곱피트), 수량 같은 통계 동인. |

기간은 `YYYY-MM`으로 쓰며 거래는 전기 기간으로 배치됩니다. 예산은 선택 사항이며 예산이 없는 ERP도 나머지는 모두 로드됩니다.

시산표 파일에는 차변 및 대변 열, 순액 열, 또는 둘 다 포함할 수 있습니다. 차변과 대변만 있으면 순액은 차변에서 대변을 뺀 값이며, 비어 있는 쪽은 0으로 간주합니다. 순액만 있으면 양수 순액은 차변이 되고 음수 순액은 양수 금액의 대변이 됩니다. 부서 열은 선택 사항입니다.

## 문제 해결

| 증상 | 조치 사항 |
|---|---|
| **연결 테스트**에서 ERP가 자격 증명을 거부했다고 표시됩니다 | 연결의 자격 증명과 통합 사용자가 ERP에 로그인할 수 있는지 확인하십시오. |
| **연결 테스트**에서 데이터 세트에 **권한 누락**이 표시됩니다 | ERP 관리자에게 표시된 권한을 추가하도록 요청하십시오. 연결에 필요한 권한은 ERP용 [연결 가이드](/ko/guides/connections/)에 나와 있습니다. |
| ERP 오류 메시지가 ERP 자체의 메시지보다 짧습니다 | PlaidCloud는 공급자 오류를 표시하기 전에 자격 증명, 토큰, 키를 제거하므로 일부 세부 정보가 생략됩니다. **연결 테스트**를 실행하여 어떤 데이터 세트가 영향을 받는지 확인하십시오. |
| 어떤 기간에 대해 **데이터 로드됨**이 문제입니다 | 해당 기간의 ERP 읽기가 실패했습니다. **로드**를 다시 실행하십시오. 로드된 기간은 건너뜁니다. |
| **계정과목표에 없는 계정**이 문제입니다 | ERP 또는 파일의 계정과목표에 누락된 계정을 추가하고 **로드**를 다시 실행하십시오. |
| **통화 환산**이 문제입니다 | 엔터티의 통화에 해당 기간의 보고 통화로의 환율이 없거나 단일 보고 통화를 찾지 못했습니다. **환율** 파일에 환율을 추가하거나, 연결이 ERP의 환율을 읽을 수 있는지 확인하거나, 프로젝트 변수 `reporting_currency`를 설정하십시오. 그런 다음 **로드**를 다시 실행하십시오. |
| **통화 환산**에 확인이 필요합니다 | 재무상태표, 재고, 예산 행에 해당 기간의 기말, 역사적, 계획 환율이 없습니다. 손익계산서는 영향을 받지 않습니다. 예산 월의 계획 환율을 포함하여 환율을 추가하고 **로드**를 다시 실행하십시오. |
| **Codes waiting for your answer**에 확인이 필요합니다 | **검토**를 클릭하고 각 코드에 답한 다음 **Apply changes**를 클릭하십시오. |
| **Which source covers which months**에 확인이 필요합니다 | **Choose which source counts from when**을 클릭하여 소스를 선택한 다음 **Apply changes**를 클릭하십시오. |
| **Intercompany balances**가 빨간색 또는 주황색입니다 | **Intercompany pairs**의 쌍을 확인하십시오. 누락된 쪽을 기록하거나, 라인에 거래 상대방을 추가하거나, 누락된 환율을 추가하십시오. |
| **Group views are off** | 아키텍트에게 **그룹** 아래에서 **Everyone on the project may see the group results**를 선택하도록 요청하십시오. |
| **매핑되지 않은 엔터티**가 문제입니다 | 엔터티 마스터에 엔터티를 추가하거나 **엔터티 매핑표** 파일에서 해당 코드를 기존 엔터티에 매핑한 다음 **로드**를 다시 실행하십시오. |
