## 검색

프로젝트 검색은 계층 왼쪽 아래에 있는 필터 상자를 사용합니다. 검색 필터는 프로젝트 이름과 레이블에서 일치하는 항목을 찾아 위쪽 계층에 결과를 표시합니다.


## 새 프로젝트 만들기

새 프로젝트를 만들려면 다음과 같이 합니다.

1. Analyze를 엽니다
2. 상단 메뉴 표시줄에서 “프로젝트”를 선택합니다
3. “새 프로젝트” 버튼을 클릭합니다
4. “액세스 제어” 섹션을 포함하여 양식 정보를 작성합니다
5. “만들기”를 클릭합니다

이제 프로젝트에서 액세스 권한을 업데이트하고, 소유자를 추가하고, 워크플로를 만들 수 있습니다.

<Aside>기본적으로 프로젝트는 현재 워크스페이스의 모든 멤버가 액세스할 수 있습니다</Aside>


## 기본 문서 계정 설정

프로젝트 홈의 **연결 환경** 옆에서 프로젝트의 **기본 문서 계정**을 선택하거나, 지우려면 **없음**을 선택합니다.

프로젝트 내부에서는 모든 파일 선택기가 **프로젝트 기본값**을 가장 먼저 나열하며, 이는 프로젝트에 현재 설정된 계정을 대신합니다. 프로젝트를 벗어나거나, 프로젝트에 기본값이 설정되어 있지 않거나, 해당 계정이 삭제되었거나, 해당 계정에 대한 액세스 권한이 없으면 목록에서 사라집니다.

새 파일 단계는 프로젝트에 기본값이 있으면 프로젝트 기본값을 미리 선택합니다. 기존 단계는 절대 다시 쓰이지 않습니다. 문서 계정은 단계별로 선택하는 항목인 반면 단계는 보통 프로젝트의 연결 환경을 따르므로, 각 단계는 사용자가 직접 변경하기 전까지 저장될 때의 계정을 유지합니다.

프로젝트 기본값으로 남겨 둔 단계는 실행 시점에 프로젝트의 기본값인 계정으로 확인됩니다. 따라서 실행 도중 기본값을 변경하면 아직 시작되지 않은 노드에만 영향을 주며, 연결 환경을 변경할 때와 같습니다. 단계가 프로젝트 기본값으로 실행되는데 프로젝트에 기본값이 설정되어 있지 않으면, 다른 계정으로 대체하지 않고 프로젝트를 명시하며 실행이 실패합니다.


## 단계를 하나의 환경에 고정

단계는 프로젝트의 [연결 환경](/ko/guides/projects/project-home/#데이터-및-연결)을 따르므로, 프로젝트를 QA와 프로덕션 사이에서 전환하면 모든 단계가 함께 이동합니다. 양식에 **환경** 설정이 있는 단계에서는 다음 두 가지를 선택할 수 있습니다.

- **프로젝트 환경**은 프로젝트의 연결 환경을 따릅니다. 특별한 이유가 없다면 이 설정을 유지하십시오.
- **고정 환경**은 프로젝트의 연결 환경을 무시하고 항상 사용자가 선택한 환경을 사용합니다. 프로젝트를 어떤 환경으로 전환하든 하나의 환경에 머물러야 하는 단계에만 사용하십시오. 예를 들어 QA로 설정된 프로젝트에서 프로덕션의 참조 데이터를 읽는 경우입니다. 경고 아이콘은 해당 단계가 전환을 따르지 않는다는 것을 알려 줍니다.

고정 환경이 있는 단계는 프로젝트의 환경이 아닌 다른 환경에서 실행될 때마다 로그에 경고를 추가합니다. 고정 환경이 더 이상 존재하지 않으면(예: 다른 워크스페이스에서 복사한 단계) 단계는 다른 곳에서 실행되지 않고 실패하며 그 사실을 알려 줍니다.

ERP 전기 단계는 항상 프로젝트의 환경을 사용하므로 이 단계에서는 **고정 환경**을 사용할 수 없습니다.

기본 환경은 삭제할 수 없으며, 다른 환경도 프로젝트가 해당 환경을 사용하거나, 단계가 해당 환경을 고정 환경으로 지정했거나, 에이전트가 해당 환경을 서비스하는 동안에는 삭제할 수 없습니다. 메시지에는 무엇이 여전히 해당 환경을 사용하는지 표시되며, 액세스 권한이 있는 항목은 이름으로 표시하고 나머지는 개수로 표시합니다.


## 버전 기록

프로젝트의 모든 개체(단계, UDF, 워크플로, 차원, 저장된 레이아웃, 문서 또는 데이터 편집기, 프로젝트 자체의 설정)는 버전 기록 백업의 대상입니다. 백업은 저장할 때마다 개별적으로 만들어지지 않습니다. 개체가 추가 저장 없이 30초가 지나면 안정된 상태를 한 번 백업합니다. 짧은 시간에 여러 번 저장하는 것과 같은 연속 편집은 저장마다 버전 하나가 아니라 최종 결과를 담은 버전 하나를 만듭니다. 저장은 백업을 기다리느라 느려지지 않습니다. 카운트다운과 백업 자체가 모두 백그라운드에서 실행됩니다. 지금 바로 버전이 필요하면 **지금 백업**을 사용하여 현재 상태를 즉시 캡처하고 완료될 때까지 기다리십시오. 이 기능은 UI, API, `*_versions` MCP 작업 `backup`에서 사용할 수 있습니다. 버전 기록은 Free를 포함한 모든 요금제에서 사용할 수 있습니다.

과거 버전은 특정 시점 복구를 지원합니다. 개체를 이전 버전으로 복원할 수 있습니다. 잠긴 프로젝트에서는 다른 변경과 마찬가지로 복원이 거부됩니다.

버전은 제자리에서 복원됩니다. 프로젝트, 차원, 사용자 정의 함수, 단계, 워크플로 또는 데이터 편집기의 버전을 복원하면 같은 항목이 대체되며, 다른 항목을 대상으로 지정하면 거부됩니다. 예를 들어 “프로젝트 버전은 제자리에서 복원됩니다. 대상을 생략하거나 이 프로젝트로 설정하십시오.”와 같은 메시지가 표시됩니다. 복원은 항목에 대한 변경이므로 편집할 때와 같은 역할이 필요합니다. [행을 제한하는](/ko/administration/access/managing-security-groups-and-assignments/#행을-제한하는-프로젝트를-변경할-수-있는-사용자) 프로젝트에서 프로젝트 또는 제한된 열이 읽는 차원을 복원하려면 프로젝트 아키텍트가 필요합니다. 이전 테이블 데이터를 별도의 테이블로 되살리려면 [테이블 스냅샷](/ko/guides/data/table-snapshots/)을 새 테이블로 복원하십시오.

이러한 자동 추적 외에도 프로젝트와 프로젝트 요소는 버전 관리를 지원합니다. 버전을 쉽게 만들 수 있을 뿐 아니라 한 버전의 변경 사항을 다른 버전에 병합할 수도 있습니다. 이를 통해 스냅샷을 간단히 추적하거나, 개발용 버전을 만들었다가 원할 때 그 변경 사항을 비개발 버전에 병합할 수 있습니다. 버전 관리, 비교, 병합의 실제 사용법은 [협업: 버전, 비교, 공유](/ko/get-started/tutorials/collaborate-versions-and-sharing/)를 참조하십시오.

테이블 데이터에는 자체 기록이 있습니다. Lakehouse가 쓰기마다 만드는 스냅샷이며, [테이블 스냅샷](/ko/guides/data/table-snapshots/)에서 다룹니다.

### AI 어시스턴트 또는 MCP를 통한 복원과 보류

AI 어시스턴트나 MCP를 통해 `dimension_versions`는 `version_id`로 차원 버전을 복원, 보류, 해제하고, `restore_project`는 프로젝트의 모든 차원을 마지막 백업으로 롤백하며, 모든 `*_versions` 목록(단계, UDF, 워크플로, 차원, 프로젝트)은 각 버전의 `version_id`와 보류 여부를 보여 줍니다. `*_versions` 도구 또는 REST API를 통한 `restore`는 항목을 제자리에서 복원합니다. 대상을 생략하거나 항목 자체로 설정하십시오. `project_upsert`는 잠긴 프로젝트의 잠금을 해제할 수 있으며, `if_match`를 지원하므로 프로젝트를 마지막으로 읽은 이후의 변경 사항을 덮어쓰지 않고 실패합니다.


## 프로젝트 액세스 관리

### 액세스 유형

프로젝트 보안은 세 가지 액세스 유형으로 단순화되었습니다.

* 모든 작업 영역 멤버
* 특정 멤버만
* 특정 보안 그룹만

프로젝트 보안은 쉽게 설정할 수 있습니다.

1. Analyze를 엽니다
2. “프로젝트”를 선택합니다
3. 제한하려는 프로젝트의 편집 아이콘을 클릭합니다
4. “액세스 제어”에서 원하는 제한을 선택합니다
5. “업데이트”를 클릭합니다

프로젝트의 액세스 유형, 프로젝트에 지정된 멤버와 보안 그룹, 데이터 공유와 같이 프로젝트에 액세스할 수 있는 사용자는 프로젝트 아키텍트 또는 테넌트 관리자만 변경할 수 있습니다. 그 외의 사용자에게는 해당 패널이 읽기 전용으로 표시되며 “프로젝트 아키텍트만 액세스를 변경할 수 있습니다.”라는 안내가 나타납니다.


## 모든 작업 영역 멤버

“모든 작업 영역 멤버” 액세스는 워크스페이스의 모든 멤버에게 액세스를 제공하며 멤버를 추가로 지정할 필요가 없으므로 가장 간단한 옵션입니다.


## 특정 멤버만

“특정 멤버만” 액세스 설정은 각 멤버를 프로젝트에 지정해야 합니다. 프로젝트에 멤버를 지정하려면 다음과 같이 합니다.

1. Analyze를 엽니다
2. 상단 메뉴 표시줄에서 “프로젝트”를 선택합니다
3. 멤버 아이콘을 클릭합니다
4. “액세스” 열에서 멤버 이름 옆의 확인란을 선택하여 멤버에게 액세스 권한을 부여합니다
5. “업데이트”를 클릭합니다

멤버 수가 많은 클라우드에서는 이 방식이 원하는 것보다 많은 노력이 필요할 수 있으며, 이때 보안 그룹이 유용합니다.

<Aside>멤버를 추가하려면 워크스페이스의 멤버여야 합니다.</Aside>


## 특정 보안 그룹만

“특정 보안 그룹만” 옵션을 사용하면 특정 보안 그룹에 계정에 액세스할 권한을 지정할 수 있습니다. 액세스 제한이 하나 이상의 보안 그룹과의 연결에 따라 결정되므로 규모가 큰 그룹의 계정 액세스 관리가 훨씬 간단해집니다. 이는 싱글 사인온 자동 그룹 연결과 함께 사용할 때 특히 유용합니다. 싱글 사인온으로 멤버의 그룹 지정을 설정하면 해당 그룹이 프로젝트에 대한 액세스를 암묵적으로 사용 설정하거나 사용 중지할 수도 있습니다.

지정된 그룹을 편집하려면 다음과 같이 합니다.

1. Analyze를 엽니다
2. 상단 메뉴 표시줄에서 “프로젝트”를 선택합니다
3. 보안 그룹 아이콘을 클릭합니다
4. “액세스” 열에서 보안 그룹 이름 옆의 확인란을 선택하여 보안 그룹에 액세스 권한을 부여합니다
5. “업데이트”를 클릭합니다


## 프로젝트 간 데이터 공유

데이터 공유를 사용하면 한 프로젝트가 다른 프로젝트의 테이블에 접근할 수 있습니다. 예를 들어 [Import Project Table](/ko/reference/workflow-steps/import/import-project-table/) 단계와 [Export Project Table](/ko/reference/workflow-steps/export/export-project-table/) 단계가 프로젝트 간에 데이터를 이동할 수 있습니다. 공유는 데이터가 공유되는 프로젝트가 다른 프로젝트 하나에 부여합니다.

1. 데이터를 공유하려는 프로젝트를 열고 해당 프로젝트의 [프로젝트 홈](/ko/guides/projects/project-home/)으로 이동합니다.
2. **액세스 및 공유**를 엽니다. **데이터 공유**에서 **새 데이터 공유**를 클릭합니다.
3. **프로젝트 선택**에서 이 프로젝트의 데이터를 사용할 수 있는 프로젝트를 선택합니다.
4. **허용된 작업**에서 **읽기**, **쓰기** 또는 둘 다 선택하고 **데이터 공유 추가**를 클릭합니다.

**데이터 공유 삭제**는 공유를 제거합니다. 프로젝트 아키텍트 또는 테넌트 관리자만 프로젝트의 데이터 공유를 추가하거나 삭제할 수 있습니다.

공유는 프로젝트에 부여되므로 해당 프로젝트의 멤버와 워크플로에만 적용됩니다.

- 공유를 통한 **읽기**에는 공유가 부여된 프로젝트의 역할이 필요합니다. 그 프로젝트에 역할이 없는 사용자는 공유로 아무것도 얻을 수 없습니다.
- 공유를 통한 **쓰기**(공유하는 프로젝트에 테이블, 폴더, 차원을 만드는 작업)에는 **쓰기** 공유와 사용자 자신의 프로젝트에서 아키텍트 또는 관리자 역할이 필요하며, 이는 그 프로젝트에서 같은 변경을 할 수 있는 역할입니다. 그렇지 않은 사용자에게는 “이 프로젝트에 데이터 공유를 통해 쓰려면 이 프로젝트에서 사용자의 프로젝트로 부여된 쓰기 공유와 사용자의 프로젝트에서 아키텍트 또는 관리자 역할이 필요합니다.”라는 메시지가 표시됩니다.

워크플로는 해당 프로젝트 자체의 ID로 실행되므로, 누가 실행을 시작하든 Import Project Table 단계와 Export Project Table 단계는 공유를 통해 작동합니다.


## 다양한 보기 역할 설정

프로젝트에는 중간 단계를 완료하기 위해 여러 변환과 테이블이 필요한데 최종 결과는 몇 개의 테이블로만 구성되는 경우가 많습니다. 멤버가 프로젝트의 모든 요소를 볼 필요는 없으며, 때로는 최종 결과물만 필요합니다. PlaidCloud에서는 다양한 보기 역할을 설정하여 각 멤버에게 보이는 항목을 간편하게 정리하고 제어할 수 있습니다.

기본 제공 보기 역할은 **아키텍트**, **관리자**, **탐색기**의 세 가지입니다.

**아키텍트** 역할은 프로젝트, 워크플로, 테이블, 변수, 데이터 편집기, 계층, 사용자 정의 함수를 모두 보고 제어할 수 있으므로 가장 단순합니다.

**관리자**와 **탐색기** 역할에는 특정 액세스 권한이 없지만 사용자 지정으로 정의할 수 있습니다. 즉, 각 그룹에 보이는 항목을 선택할 수 있습니다.

<Aside>**관리자**와 **탐색기**는 보안 그룹이 아니며, 업무 분리와 정보 가시성을 편리하게 구분하는 방법일 뿐입니다.</Aside>

프로젝트 내 모든 항목을 볼 수 있어야 한다고 판단되면 모든 사람을 **아키텍트**로 지정할 수 있습니다. 그렇지 않으면 멤버를 **관리자** 및/또는 **탐색기** 프로젝트 멤버로 지정하여 가시성을 제어할 수 있습니다.

다른 역할을 설정하려면 다음과 같이 합니다.

1. Analyze를 엽니다
2. “프로젝트”를 선택합니다
3. 멤버 아이콘을 클릭합니다
4. 역할을 변경하려는 멤버를 선택합니다
5. “역할” 열에서 현재 역할을 두 번 클릭합니다
6. 원하는 역할을 선택합니다
7. “업데이트”를 클릭합니다


## 프로젝트 변수 관리

프로젝트나 워크플로를 실행할 때 반복 작업에 변수를 설정하면 복잡함을 줄이고 시간을 절약할 수 있습니다. 이러한 변수는 일반적인 대수 변수처럼 작동하여 변수가 나타내는 값과 그 뒤에 따라올 연산을 설정할 수 있습니다. PlaidCloud에서는 이러한 변수를 프로젝트 수준에서 설정하여 해당 프로젝트의 모든 워크플로에 영향을 주도록 하거나, 워크플로 수준에서 설정하여 해당 워크플로에만 영향을 주도록 할 수 있습니다.

프로젝트 수준 변수를 설정하려면 다음과 같이 합니다.

1. Analyze를 엽니다
2. “프로젝트”를 선택합니다
3. 프로젝트 변수 관리 아이콘을 클릭합니다

변수 테이블에서 변수를 보고 현재 값을 보거나 편집할 수 있습니다. “새 프로젝트 변수” 버튼을 클릭하여 변수를 새로 추가하거나 기존 변수를 삭제할 수도 있습니다.


## 프로젝트 복사

**프로젝트 복사**는 프로젝트 전체 또는 선택한 일부를 완전히 새로운 프로젝트나 이미 있는 프로젝트로 복사합니다.

프로젝트를 복사하려면 다음과 같이 합니다.

1. Analyze를 엽니다
2. "프로젝트"를 선택합니다
3. 복사할 프로젝트를 선택합니다
4. **작업** 버튼을 클릭하고 **프로젝트 복사**를 선택합니다
5. 대상을 선택하고, 가져올 항목과 복사할 데이터를 선택한 다음 **프로젝트 복사**를 클릭합니다
6. **복사 전 검토** 요약을 확인하고 **복사 시작**을 클릭합니다

### 복사할 항목 선택

선택 트리에는 프로젝트에 포함된 항목이 워크플로, 단계, 테이블, 차원, 데이터 편집기, 사용자 정의 함수와 같은 유형별로 나열됩니다. 프로젝트 전체를 복사하려면 모든 항목을 선택한 상태로 두고, 원하는 부분만 복사하려면 해당 부분만 선택합니다.

이러한 부분이 무엇에 의존하는지 직접 파악할 필요는 없습니다. 선택한 항목은 종속 항목을 함께 가져옵니다. 단계가 읽고 쓰는 테이블, 단계가 로드하거나 배부 기준으로 사용하는 차원, 단계가 호출하는 사용자 정의 함수, 단계가 호출하는 하위 워크플로나 매크로가 해당됩니다. 워크플로의 센서는 워크플로와 함께 복사됩니다.

**복사된 센서는 비활성화된 상태로 도착합니다.** 대상 프로젝트에서 각 센서를 직접 켜기 전까지는 복사본에서 아무것도 실행되지 않습니다. 중복 항목을 덮어쓰는 가져오기는 대상 워크플로에 센서가 이미 있으면 센서를 하나 더 추가하지 않습니다.

### 새 프로젝트로 복사

새 프로젝트의 이름과 ID를 지정합니다. ID는 스키마 이름이 되며 나중에 변경할 수 없습니다.

**일정은 일시 중지된 상태로 도착합니다.** 프로젝트 전체를 새 프로젝트로 복사하면 각 워크플로의 예약된 이벤트가 일시 중지된 상태로 복사되므로, 복사본이 이를 자동으로 실행하기 시작하지 않습니다. 복사가 완료되면 원본에서 활성 상태였던 이벤트를 나열하는 메시지가 표시됩니다. 복사본에서 이벤트를 실행하려면 **도구** > **이벤트 스케줄러**에서 이벤트를 선택하고 **선택 항목 사용**을 클릭하십시오. [이벤트 일시 중지](/ko/administration/scheduled-events/event-scheduler/#이벤트-일시-중지)를 참조하십시오.

### 기존 프로젝트로 복사

프로젝트 목록에서 대상을 선택합니다. 복사본은 해당 프로젝트를 대체하지 않고 추가됩니다.

**대상을 변경할 수 있어야 합니다.** 역할이 없는 프로젝트로의 복사는 거부되며, 변경을 방지하도록 잠긴 프로젝트로의 복사도 거부됩니다. 이는 무엇이든 읽거나 쓰기 전에 확인되므로, 거부된 복사는 대상을 그대로 둡니다. 또한 프로젝트를 자기 자신으로 복사할 수 없습니다.

**행을 제한하는 프로젝트를 복사하려면 프로젝트 아키텍트여야 합니다.** 복사본은 [행 액세스](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리) 제한이 없는 새 프로젝트이며, 복사본은 이를 “이 복사본은 행이 제한되지 않았습니다.”라고 알려 줍니다. 복사본을 공유하기 전에 복사본에서 행 액세스를 설정하십시오. 행을 제한하는 기존 프로젝트로 복사하는 경우에도 해당 프로젝트의 아키텍트 또는 테넌트 관리자가 필요합니다.

**대상은 자체 설정을 유지합니다.** 이름, ID, 데이터 연결 환경, 스토리지 기본값, 문서 계정, 액세스 유형, 액세스 목록, 행 액세스 부여는 모두 그대로 유지됩니다. 선택한 내용만 가져옵니다.

**프로젝트 기본값**으로 설정된 단계는 계정이 아니라 그 설정을 그대로 가져갑니다. 복사된 후에는 원본 프로젝트의 기본값이 아니라 대상 프로젝트의 기본값으로 확인됩니다.

들어오는 항목이 대상에 이미 있는 항목과 같은 항목인 경우 처리 방법을 선택합니다.

- **중복 항목을 수신 데이터로 덮어쓰기** — 들어오는 버전이 대상의 항목을 대체합니다.
- **중복 항목의 새 사본 만들기** — 대상은 기존 항목을 유지하고, 들어오는 항목은 이름 뒤에 ` copy`가 붙은 채로 함께 추가되며, 그 이름도 이미 있으면 숫자가 붙습니다.

프로젝트 변수와 워크플로 변수는 *중복 항목의 새 사본 만들기*의 예외입니다. 변수는 이름으로 식별되므로, 아무것도 참조하지 않는 이름으로 바꾸지 않고는 두 번째 사본을 추가할 방법이 없습니다. 복사본이 가져오는 변수를 대상이 이미 정의하고 있으면 대상 자체의 값이 유지되며, 복사본은 그대로 둔 변수를 알려 줍니다. *덮어쓰기*는 변수를 다른 항목과 동일하게 취급하여 대체합니다.

이 일치 여부는 이름이 아니라 ID로 판단합니다. 원래 같은 프로젝트에서 온 항목은 같은 항목으로 인식되고, 우연히 이름만 같은 두 항목은 서로 다른 항목으로 취급되어 이후에 둘 다 존재합니다.

### 복사할 데이터 양 선택

**복사할 데이터**에서 두 가지 설정이 선택 항목과 함께 가져올 데이터를 결정합니다.

**테이블 데이터**는 각 테이블에서 복사할 행 수를 설정합니다.

| 선택 | 복사 내용 |
| --- | --- |
| **테이블 데이터 없음** | 행 없이 테이블, 단계 및 나머지 선택 항목을 복사합니다. 기본값입니다. |
| **전체** | 같은 Lakehouse 내에서와 Lakehouse 간에 모든 테이블의 행을 복사합니다. |
| **샘플** | 입력한 **테이블당 행 수**까지 복사하며, 새 프로젝트에만 사용할 수 있습니다. 숫자는 1에서 1,000,000까지 지정할 수 있습니다. |

샘플링된 테이블은 해당 행 수까지, 행이 더 적으면 모든 행을 담습니다. **전체** 또는 **샘플** 복사는 여러 테이블을 동시에 복사하므로 테이블이 많은 프로젝트도 더 빨리 완료됩니다.

**차원 멤버 복사**는 어떤 **테이블 데이터** 선택을 하든 선택 항목에 포함된 모든 차원의 멤버를 복사합니다. 기본적으로 켜져 있으므로 테이블 데이터 없이 복사해도 채워진 차원이 포함되어 빠르게 만들 수 있습니다. 차원을 멤버 없이 복사하려면 이를 해제하십시오.

REST API(`POST /rest/v1/analyze/project/copy`) 또는 `project_copy` MCP 도구에서 `data_mode`를 `structure`, `full` 또는 `sample`로, `dimension_members`를 `true` 또는 `false`로 설정합니다. `dimension_members`를 생략하면 테이블 행을 복사할 때만 멤버가 복사됩니다. `project_copy`는 복사되지 않은 ERP 쓰기 승인과 같은 복사본의 경고도 반환합니다.

### 복사 검토

복사하기 전에 **복사 전 검토**가 원본 프로젝트, 대상 위치, **테이블 데이터** 선택, **차원 멤버** 포함 여부, 테이블과 뷰의 수, 크기, 예상 시간, 원본 및 대상 Lakehouse, **참고** 아래의 경고를 요약합니다. 시작하려면 **복사 시작**을 클릭하고, 돌아가서 선택을 변경하려면 **취소**를 클릭합니다.

### 복사본을 볼 수 있는 사용자

데이터(테이블 행, 차원 멤버 또는 둘 다)와 함께 만든 복사본은 만든 사람만 볼 수 있습니다. 준비되면 새 프로젝트에서 공유하십시오. 행 수준 보안이 있는 프로젝트의 복사본도 같은 이유로 비공개로 유지됩니다.

기존 프로젝트로 데이터를 복사하려면 해당 프로젝트에 대한 쓰기 액세스가 필요합니다.

### 복사본의 ERP 쓰기 승인

사용자에게만 비공개인 새 복사본은 원본 프로젝트의 [ERP 쓰기 승인](/ko/guides/workflows/run-a-workflow/#프로젝트에-전기-권한-부여)을 유지하므로, 복사본을 다시 승인하지 않고도 전기 워크플로를 테스트할 수 있습니다. 테이블 데이터(**전체** 또는 **샘플**), 차원 멤버 또는 둘 다와 함께 만든 새 프로젝트로의 모든 복사가 해당됩니다. 승인은 다음 경우에 복사됩니다.

- 원본 프로젝트의 아키텍트이거나 워크스페이스 관리자입니다.
- 에이전트나 서비스 계정이 아니라 사용자가 직접 복사합니다.

각 승인은 현재 사용자가 직접 부여할 수 있는 경우에만 복사됩니다. 즉 해당 연결과 환경이 여전히 존재하고 연결에 대한 쓰기 액세스가 있어야 합니다. 복사된 승인은 사용자가 승인한 것으로 기록됩니다.

**복사본은 시뮬레이션 상태로 도착합니다.** 원본 프로젝트의 **ERP 전기 모드**가 실거래이면 복사본의 모드는 시뮬레이션으로 설정되므로, 복사본의 워크플로는 ERP에 접속하지 않고 전기할 내용을 만들고 검사합니다. 시뮬레이션 또는 끄기로 설정된 원본은 그 설정을 유지합니다. 복사본에서 실제로 전기할 준비가 되면 복사본의 홈 페이지에 있는 **ERP 전기**에서 **ERP 전기 모드**를 실거래로 설정하십시오. [전기 모드 선택](/ko/guides/workflows/run-a-workflow/#전기-모드-선택)을 참조하십시오. 일정과 센서는 위에서 설명한 대로 여전히 일시 중지 및 비활성화된 상태로 도착하므로, 사용자가 켜기 전까지는 복사본에서 아무것도 실행되지 않습니다.

기존 프로젝트로의 복사, 또는 테이블 데이터와 차원 멤버가 없는 복사는 원본의 승인 없이 시작됩니다. 전기하기 전에 홈 페이지의 **ERP 전기** > **ERP 쓰기 승인**에서 승인하십시오.

**복사 결과**는 예를 들어 “ERP 쓰기 승인 2개 복사됨, ERP 전기는 시뮬레이션 상태”와 같이 무슨 일이 있었는지와 복사되지 않은 승인의 수를 보고합니다.

### 복사 결과

복사가 완료되면 **복사 결과** 창이 복사된 테이블과 차원 멤버를 요약하고, 각 테이블과 차원을 이름과 결과(**복사됨**, **변경하여 복사됨**, **샘플링됨**, **건너뜀** 또는 **실패**)와 함께 나열하며, 건너뛰었거나 실패한 항목의 이유도 표시합니다. **Retry failed items**를 클릭하면 실패한 테이블과 차원을 다시 복사하며, 복사본에서 해당 항목의 현재 내용은 대체됩니다. 복사가 완료되거나 실패하면 메시지와 이메일로 알림을 받으며, 메시지에서 결과를 다시 열거나 나중에 **프로젝트** 탭에서 복사본을 선택하고 **작업** 메뉴에서 **가져오기 또는 복사 결과 보기**를 선택하여 다시 열 수 있습니다.

결과는 누군가 삭제할 때까지 복사본에 유지됩니다. 복사가 끝나면 **결과 삭제**를 클릭하여 프로젝트를 열 수 있는 모든 사용자에 대해 결과를 제거합니다. 프로젝트에서 바뀌는 것은 없지만, 실패한 항목은 더 이상 창에서 다시 시도할 수 없습니다. 삭제하려면 프로젝트에 대한 편집 액세스가 필요하고 프로젝트가 잠겨 있지 않아야 합니다.

### 참조 업데이트

프로젝트의 워크플로 단계는 해당 프로젝트 내부의 테이블과 기타 개체를 참조합니다. **참조 업데이트**는 이러한 참조가 원본이 아니라 복사본을 가리키도록 다시 씁니다. 이는 거의 항상 원하는 동작이므로 기본적으로 켜져 있습니다. 이 옵션을 끄면 복사된 단계가 원래 프로젝트를 다시 가리킵니다.

<Aside>복사는 백그라운드에서 실행됩니다. 진행률 대화 상자에 복사가 각 단계를 거치며 진행되는 모습이 표시되며, **백그라운드에서 실행**을 클릭하여 대화 상자를 닫고 계속 작업할 수 있습니다. 프로젝트 목록은 자동으로 업데이트되고 복사가 완료되면 알림을 받습니다.</Aside>

## 프로젝트 보고서 보기

프로젝트나 워크플로가 동적일 때는 자세한 문서를 유지하기가 어렵습니다. 이 문제를 해결하기 위해 PlaidCloud는 워크플로, 워크플로 단계, 사용자 정의 변환, 변수, 테이블에 대한 자세한 문서를 제공하는 프로젝트 수준 보고서를 생성하는 기능을 제공합니다. 이 보고서는 요청 시 생성되며 프로젝트의 현재 상태를 반영합니다.

보고서를 다운로드하려면 다음과 같이 합니다.

1. Analyze를 엽니다
2. “프로젝트”를 선택합니다
3. 보고서 아이콘을 클릭합니다
