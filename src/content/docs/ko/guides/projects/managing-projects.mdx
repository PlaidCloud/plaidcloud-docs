## 검색

프로젝트 검색은 계층 구조 왼쪽 하단의 필터 상자를 사용합니다. 검색 필터는 프로젝트 이름과 레이블에서 일치하는 항목을 찾아 위쪽 계층 구조에 결과를 표시합니다.


## 새 프로젝트 만들기

새 프로젝트를 만드는 방법은 다음과 같습니다.

1. Analyze를 엽니다.
2. 상단 메뉴 표시줄에서 “프로젝트”를 선택합니다.
3. “새 프로젝트” 버튼을 클릭합니다.
4. “Access Control” 섹션을 포함하여 양식 정보를 모두 입력합니다.
5. “Create”를 클릭합니다.

이제 프로젝트에서 액세스 권한을 업데이트하고, 소유자를 추가하고, 워크플로를 만들 수 있습니다.

<Aside>기본적으로 프로젝트는 현재 워크스페이스의 모든 멤버가 액세스할 수 있습니다.</Aside>


## 기본 문서 계정 설정

프로젝트 홈에서 **연결 환경** 옆에 있는 **기본 문서 계정**을 선택합니다. 지정을 해제하려면 **없음**을 선택합니다.

프로젝트 내부에서는 모든 파일 선택기의 맨 위에 **Project Default**가 표시되며, 프로젝트에 현재 설정된 계정을 대신합니다. 프로젝트를 벗어나거나, 프로젝트에 기본값이 설정되어 있지 않거나, 해당 계정이 삭제되었거나, 해당 계정에 대한 액세스 권한이 없으면 목록에서 사라집니다.

새 파일 단계를 만들면 프로젝트에 기본값이 있는 경우 Project Default가 미리 선택됩니다. 기존 단계는 절대 다시 쓰이지 않습니다. 각 단계는 사용자가 직접 변경할 때까지 저장된 계정을 그대로 유지합니다. 문서 계정은 연결 환경과 달리 단계별로 선택하는 항목이기 때문입니다.

Project Default로 설정된 단계는 실행될 때 프로젝트의 기본 계정으로 확인됩니다. 따라서 실행 도중 기본값을 변경하면 아직 시작되지 않은 노드에만 영향을 줍니다. 연결 환경을 변경할 때와 같습니다. 단계가 Project Default로 실행되는데 프로젝트에 기본값이 설정되어 있지 않으면, 다른 계정으로 대체하지 않고 프로젝트 이름을 알려 주며 실행이 실패합니다.


## 버전 기록

프로젝트의 모든 개체(단계, UDF, 워크플로, 차원, 저장된 레이아웃, 문서 또는 데이터 편집기, 프로젝트 자체 설정)는 버전 기록 백업의 대상입니다. 저장할 때마다 백업하지는 않습니다. 개체가 마지막으로 저장된 후 30초 동안 추가 저장이 없으면, 안정된 상태를 한 번 백업합니다. 짧은 시간 안에 여러 번 저장하는 연속 편집은 저장 횟수만큼의 버전이 아니라 최종 결과를 담은 버전 하나만 만듭니다. 저장은 백업을 기다리느라 느려지지 않습니다. 카운트다운과 백업 자체가 모두 백그라운드에서 실행됩니다. 지금 바로 버전이 필요하면 **Back up now**를 사용하여 현재 상태를 즉시 캡처하고 완료될 때까지 기다릴 수 있습니다. 이 기능은 UI, API, 그리고 `*_versions` MCP 작업 `backup`에서 사용할 수 있습니다. 버전 기록은 Free를 포함한 모든 요금제에서 제공됩니다.

과거 버전은 특정 시점 복구를 지원합니다. 즉, 개체를 이전 버전으로 복원할 수 있습니다. 잠긴 프로젝트에서는 다른 모든 변경과 마찬가지로 복원이 거부됩니다.

버전은 제자리에서 복원됩니다. 프로젝트, 차원, 사용자 정의 함수, 단계, 워크플로 또는 데이터 편집기의 버전을 복원하면 해당 항목 자체가 대체되며, 다른 항목을 대상으로 지정하면 거부됩니다. 예를 들어 "A project version is restored in place. Leave the target out, or set it to this project."라는 메시지가 표시됩니다. 복원은 항목을 변경하는 작업이므로 편집할 때와 동일한 역할이 필요합니다. [행을 제한하는](/ko/administration/access/managing-security-groups-and-assignments/#행을-제한하는-프로젝트를-변경할-수-있는-사람) 프로젝트에서는 프로젝트나 제한된 열이 읽는 차원을 복원하려면 프로젝트 아키텍트여야 합니다. 이전 테이블 데이터를 별도의 테이블로 되살리려면 [테이블 스냅샷](/ko/guides/data/table-snapshots/)을 새 테이블로 복원하십시오.

이러한 자동 추적 외에도 프로젝트와 그 요소는 버전 관리를 지원합니다. 버전을 만드는 일이 간단할 뿐 아니라, 한 버전의 변경 사항을 다른 버전으로 병합할 수도 있습니다. 이를 통해 스냅샷을 간편하게 관리하거나, 개발용 버전을 만들어 두었다가 원할 때 그 변경 사항을 비개발 버전에 병합할 수 있습니다. 버전 관리, 비교, 병합의 실제 사용법은 [협업: 버전, 비교, 공유](/ko/get-started/tutorials/collaborate-versions-and-sharing/)를 참조하십시오.

테이블 데이터에는 별도의 기록이 있습니다. Lakehouse가 모든 쓰기 시점에 만드는 스냅샷이며, [테이블 스냅샷](/ko/guides/data/table-snapshots/)에서 설명합니다.

### AI 어시스턴트 또는 MCP를 통한 복원 및 보관

AI 어시스턴트나 MCP에서 `dimension_versions`는 `version_id`로 차원 버전을 복원, 보관, 보관 해제합니다. `restore_project`는 프로젝트의 모든 차원을 마지막 백업 상태로 되돌립니다. 모든 `*_versions` 목록(단계, UDF, 워크플로, 차원, 프로젝트)에는 각 버전의 `version_id`와 보관 여부가 표시됩니다. 어떤 `*_versions` 도구나 REST API를 통한 `restore`든 항목을 제자리에서 복원합니다. 대상을 생략하거나 항목 자신으로 지정하십시오. `project_upsert`는 잠긴 프로젝트의 잠금을 해제할 수 있으며, `if_match`를 지원하므로 마지막으로 프로젝트를 읽은 이후 다른 변경이 있었다면 덮어쓰지 않고 실패합니다.


## 프로젝트 액세스 관리

### 액세스 유형

프로젝트 보안은 세 가지 액세스 유형으로 단순화되었습니다.

* 모든 작업 영역 멤버
* 특정 멤버만
* 특정 보안 그룹만

프로젝트 보안은 쉽게 설정할 수 있습니다.

1. Analyze를 엽니다.
2. “프로젝트”를 선택합니다.
3. 제한하려는 프로젝트의 편집 아이콘을 클릭합니다.
4. “Access Control”에서 원하는 제한을 선택합니다.
5. “Update”를 클릭합니다.

프로젝트 아키텍트 또는 테넌트 관리자만 프로젝트에 액세스할 수 있는 대상, 즉 액세스 유형, 프로젝트에 지정된 멤버와 보안 그룹, 데이터 공유를 변경할 수 있습니다. 그 외의 사용자에게는 해당 패널이 읽기 전용으로 표시되며 “Only project Architects can change access.”라는 안내가 나타납니다.


## 모든 작업 영역 멤버

“모든 작업 영역 멤버” 액세스는 워크스페이스의 모든 멤버에게 액세스를 제공하므로 멤버를 따로 지정할 필요가 없어 가장 간단한 옵션입니다.


## 특정 멤버만

“특정 멤버만” 액세스 설정은 각 멤버를 프로젝트에 지정해야 합니다. 프로젝트에 멤버를 지정하는 방법은 다음과 같습니다.

1. Analyze를 엽니다.
2. 상단 메뉴 표시줄에서 “프로젝트”를 선택합니다.
3. 멤버 아이콘을 클릭합니다.
4. “Access” 열에서 멤버 이름 옆의 확인란을 선택하여 멤버에게 액세스 권한을 부여합니다.
5. “Update”를 클릭합니다.

멤버 수가 많은 클라우드에서는 이 방식이 원하는 것보다 많은 작업이 필요할 수 있으며, 이럴 때 보안 그룹이 유용합니다.

<Aside>멤버를 추가하려면 해당 워크스페이스의 멤버여야 합니다.</Aside>


## 특정 보안 그룹만

“특정 보안 그룹만” 옵션을 사용하면 특정 보안 그룹에 계정 액세스 권한을 지정할 수 있습니다. 액세스 제한을 하나 이상의 보안 그룹과의 연결에 의존하므로, 규모가 큰 그룹의 계정 액세스 관리가 훨씬 간단해집니다. 싱글 사인온 자동 그룹 연결과 함께 사용하면 특히 유용합니다. 싱글 사인온으로 멤버의 그룹 지정을 설정하면 이러한 그룹이 프로젝트 액세스를 암묵적으로 사용하거나 사용하지 않게 할 수도 있습니다.

지정된 그룹을 편집하는 방법은 다음과 같습니다.

1. Analyze를 엽니다.
2. 상단 메뉴 표시줄에서 “프로젝트”를 선택합니다.
3. 보안 그룹 아이콘을 클릭합니다.
4. “Access” 열에서 보안 그룹 이름 옆의 확인란을 선택하여 보안 그룹에 액세스 권한을 부여합니다.
5. “Update”를 클릭합니다.


## 프로젝트 간 데이터 공유

데이터 공유를 사용하면 한 프로젝트가 다른 프로젝트의 테이블에 접근할 수 있습니다. 예를 들어 [Import Project Table](/ko/reference/workflow-steps/import/import-project-table/) 및 [Export Project Table](/ko/reference/workflow-steps/export/export-project-table/) 단계가 두 프로젝트 사이에서 데이터를 이동할 수 있게 됩니다. 공유는 데이터를 공유하는 프로젝트가 다른 프로젝트 하나에 부여합니다.

1. 데이터를 공유하려는 프로젝트를 열고 해당 프로젝트의 **홈** 탭으로 이동합니다.
2. **데이터 공유 관리**에서 **새 데이터 공유**를 클릭합니다.
3. **프로젝트 선택**에서 이 프로젝트의 데이터를 사용할 수 있는 프로젝트를 선택합니다.
4. **허용된 작업**에서 **읽기**, **쓰기** 또는 둘 다를 선택한 후 **데이터 공유 추가**를 클릭합니다.

**데이터 공유 삭제**는 공유를 제거합니다. 프로젝트 아키텍트 또는 테넌트 관리자만 프로젝트의 데이터 공유를 추가하거나 삭제할 수 있습니다.

공유는 프로젝트에 부여되므로 해당 프로젝트의 멤버와 워크플로에만 적용됩니다.

- 공유를 통한 **읽기**에는 공유가 부여된 프로젝트에서의 역할이 필요합니다. 그 프로젝트에 역할이 없는 사용자는 공유로 아무것도 얻을 수 없습니다.
- 공유를 통한 **쓰기**(공유한 프로젝트에 테이블, 폴더 또는 차원 만들기)에는 **쓰기** 공유와 본인 프로젝트에서의 관리자 또는 아키텍트 역할이 필요합니다. 이는 그 프로젝트에서 같은 변경을 할 수 있는 역할입니다. 그렇지 않은 사용자에게는 "Writing to this project through a data share needs a write share from it to your project, and the Manager or Architect role in your project."라는 메시지가 표시됩니다.

워크플로는 해당 프로젝트 자체의 ID로 실행되므로, 누가 실행을 시작하든 Import Project Table 및 Export Project Table 단계는 공유를 통해 작동합니다.


## 다양한 보기 역할 설정

프로젝트에는 중간 단계를 완료하기 위해 여러 변환과 테이블이 필요한 경우가 많지만, 최종 결과는 몇 개의 테이블로만 구성될 수 있습니다. 멤버가 프로젝트의 모든 요소를 볼 필요는 없으며, 최종 산출물만 필요한 경우도 있습니다. PlaidCloud에서는 다양한 보기 역할을 설정하여 각 멤버에게 보이는 항목을 간편하게 정리하고 제어할 수 있습니다.

기본 제공 보기 역할은 **아키텍트**, **관리자**, **탐색기**의 세 가지입니다.

**아키텍트** 역할은 프로젝트, 워크플로, 테이블, 변수, 데이터 편집기, 계층, 사용자 정의 함수를 모두 보고 제어할 수 있어 가장 단순합니다.

**관리자**와 **탐색기** 역할에는 정해진 액세스 권한이 없지만 사용자 지정으로 정의할 수 있습니다. 즉, 각 그룹에 어떤 항목이 보일지 직접 선택할 수 있습니다.

<Aside>**관리자*** *와 **탐색기**는 보안 그룹이 아니며, 업무 분리와 정보 가시성 분리를 편리하게 해 주는 수단일 뿐입니다.</Aside>

프로젝트 내 모든 항목을 볼 필요가 있다고 판단되면 모든 사용자를 **아키텍트**로 지정할 수 있습니다. 그렇지 않다면 멤버를 **관리자** 및/또는 **탐색기** 프로젝트 멤버로 지정하여 가시성을 제어할 수 있습니다.

역할을 설정하는 방법은 다음과 같습니다.

1. Analyze를 엽니다.
2. “프로젝트”를 선택합니다.
3. 멤버 아이콘을 클릭합니다.
4. 역할을 변경하려는 멤버를 선택합니다.
5. “Role” 열에서 현재 역할을 두 번 클릭합니다.
6. 원하는 역할을 선택합니다.
7. “Update”를 클릭합니다.


## 프로젝트 변수 관리

프로젝트나 워크플로를 실행할 때 반복 작업에 변수를 설정해 두면 복잡함을 줄이고 시간을 절약할 수 있습니다. 이러한 변수는 일반적인 대수 변수처럼 작동하여, 변수가 나타내는 값과 그 뒤에 이어질 연산을 지정할 수 있습니다. PlaidCloud에서는 프로젝트 수준에서 변수를 설정하여 해당 프로젝트 내 모든 워크플로에 영향을 주거나, 워크플로 수준에서 설정하여 해당 워크플로에만 영향을 주도록 할 수 있습니다.

프로젝트 수준 변수를 설정하는 방법은 다음과 같습니다.

1. Analyze를 엽니다.
2. “프로젝트”를 선택합니다.
3. Manage Project Variables 아이콘을 클릭합니다.

변수 테이블에서 변수를 확인하고 현재 값을 보거나 편집할 수 있습니다. “New Project Variable” 버튼을 클릭하여 새 변수를 추가하거나 기존 변수를 삭제할 수도 있습니다.


## 프로젝트 복사

**프로젝트 복사**는 프로젝트 전체 또는 선택한 일부를 완전히 새로운 프로젝트나 이미 있는 프로젝트로 복사합니다.

프로젝트를 복사하는 방법은 다음과 같습니다.

1. Analyze를 엽니다.
2. "프로젝트"를 선택합니다.
3. 복사할 프로젝트를 선택합니다.
4. **작업** 버튼을 클릭하고 **프로젝트 복사**를 선택합니다.
5. 대상을 선택하고, 가져올 항목과 데이터 양을 선택한 후 **프로젝트 복사**를 클릭합니다.
6. **복사 전 검토** 요약을 확인하고 **복사 시작**을 클릭합니다.

### 복사할 항목 선택

선택 트리에는 프로젝트에 있는 항목이 워크플로, 단계, 테이블, 차원, 데이터 편집기, 사용자 정의 함수 등 유형별로 나열됩니다. 모든 항목을 선택한 상태로 두면 프로젝트 전체가 복사되며, 원하는 부분만 선택할 수도 있습니다.

선택한 항목이 의존하는 대상을 직접 파악할 필요는 없습니다. 선택한 항목은 종속 항목을 함께 가져옵니다. 단계가 읽고 쓰는 테이블, 단계가 로드하거나 배부 기준으로 삼는 차원, 단계가 호출하는 사용자 정의 함수, 단계가 호출하는 하위 워크플로나 매크로가 모두 포함됩니다. 워크플로의 센서는 워크플로와 함께 복사됩니다.

**복사된 센서는 비활성화된 상태로 도착합니다.** 대상 프로젝트에서 각 센서를 직접 켜기 전에는 복사본에서 아무것도 트리거되지 않습니다. 중복 항목을 덮어쓰는 가져오기에서는 대상 워크플로에 이미 센서가 있어도 센서가 하나 더 추가되지 않습니다.

### 새 프로젝트로 복사

새 프로젝트의 이름과 ID를 지정합니다. ID는 스키마 이름이 되며 나중에 변경할 수 없습니다.

**일정은 일시 중지된 상태로 도착합니다.** 프로젝트 전체를 새 프로젝트로 복사하면 각 워크플로의 예약된 이벤트가 일시 중지된 상태로 넘어오므로, 복사본이 이벤트를 자동으로 실행하기 시작하지 않습니다. 복사가 끝나면 원본에서 활성 상태였던 이벤트를 나열한 메시지가 표시됩니다. 복사본에서 이벤트를 실행하려면 **도구** > **이벤트 스케줄러**에서 해당 이벤트를 선택하고 **선택 항목 사용**을 클릭하십시오. [이벤트 일시 중지](/ko/administration/scheduled-events/event-scheduler/#이벤트-일시-중지)를 참조하십시오.

### 기존 프로젝트로 복사

프로젝트 목록에서 대상을 선택합니다. 복사 내용은 해당 프로젝트를 대체하지 않고 추가됩니다.

**대상을 변경할 수 있어야 합니다.** 역할이 없는 프로젝트로의 복사와 변경을 막기 위해 잠긴 프로젝트로의 복사는 거부됩니다. 이 검사는 무엇이든 읽거나 쓰기 전에 수행되므로, 거부된 복사는 대상을 전혀 건드리지 않습니다. 프로젝트를 자기 자신에 복사할 수도 없습니다.

**행을 제한하는 프로젝트를 복사하려면 프로젝트 아키텍트여야 합니다.** 복사본은 [행 액세스](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리) 제한이 없는 새 프로젝트이며, 복사 시 “This copy is not row-restricted.”라는 안내가 표시됩니다. 복사본을 공유하기 전에 복사본에 행 액세스를 설정하십시오. 행을 제한하는 기존 프로젝트로 복사하는 경우에도 해당 프로젝트의 아키텍트 또는 테넌트 관리자여야 합니다.

**대상은 자체 설정을 유지합니다.** 이름, ID, 데이터 연결 환경, 스토리지 기본값, 문서 계정, 액세스 유형, 액세스 목록, 행 액세스 권한 부여는 모두 그대로 유지됩니다. 선택한 콘텐츠만 가져옵니다.

**Project Default**로 설정된 단계는 계정이 아니라 해당 설정이 그대로 넘어옵니다. 복사된 후에는 원본 프로젝트의 기본값이 아니라 대상 프로젝트에 설정된 기본값으로 확인됩니다.

들어오는 항목이 대상에 이미 있는 항목과 동일한 항목이면 처리 방법을 선택합니다.

- **중복 항목을 수신 데이터로 덮어쓰기** — 수신 버전이 대상의 항목을 대체합니다.
- **중복 항목의 새 사본 만들기** — 대상은 기존 항목을 유지하고, 수신 항목은 이름 뒤에 ` copy`가 붙어 나란히 추가되며, 그 이름도 이미 사용 중이면 숫자가 붙습니다.

프로젝트 변수와 워크플로 변수는 *새로 만들기*의 예외입니다. 변수는 이름으로 식별되므로, 아무것도 참조하지 않는 이름으로 바꾸지 않고서는 두 번째 사본을 추가할 수 없습니다. 복사본이 가져오는 변수를 대상이 이미 정의하고 있으면 대상의 값이 유지되며, 복사 시 건드리지 않은 변수가 무엇인지 알려 줍니다. *덮어쓰기*는 변수도 다른 항목과 똑같이 취급하여 대체합니다.

이러한 일치 판단은 이름이 아니라 ID를 기준으로 합니다. 원래 같은 프로젝트에서 온 항목은 동일한 항목으로 인식되지만, 이름만 우연히 같은 두 항목은 서로 다른 항목으로 취급되어 이후에 둘 다 존재하게 됩니다.

### 복사할 데이터 양 선택

| 모드 | 복사되는 항목 |
| --- | --- |
| **구조만** | 행 없이 테이블, 단계 및 나머지 선택 항목. |
| **전체 데이터** | 같은 Lakehouse 내에서든 Lakehouse 간이든 모든 테이블의 행. |
| **샘플** | 각 테이블에서 입력한 행 수까지, 새 프로젝트에만 해당. 숫자는 1에서 1,000,000까지 가능합니다. |

샘플링된 테이블에는 해당 행 수까지가 들어 있으며, 행이 그보다 적으면 모든 행이 들어 있습니다.

### 복사 검토

복사하기 전에 **복사 전 검토**에 복사 요약이 표시됩니다. 원본 프로젝트, 대상 위치, 데이터 모드, 테이블과 뷰의 수, 크기, 예상 소요 시간, 원본 및 대상 Lakehouse, **참고**에 나열되는 경고가 포함됩니다. **복사 시작**을 클릭하여 시작하거나 **취소**를 클릭하여 돌아가 선택을 변경합니다.

### 복사본을 볼 수 있는 사람

데이터와 함께 만든 복사본은 만든 사람만 볼 수 있습니다. 준비가 되면 새 프로젝트에서 공유하십시오. 행 수준 보안이 있는 프로젝트의 복사본도 같은 이유로 비공개로 유지됩니다.

기존 프로젝트로 데이터를 복사하려면 해당 프로젝트에 대한 쓰기 액세스가 필요합니다.

### 복사 결과

복사가 끝나면 **복사 결과** 창에 테이블별 결과가 이름과 함께 나열되며, 실패한 테이블에는 그 이유가 표시됩니다. **실패한 테이블 다시 시도**를 클릭하면 해당 테이블만 다시 복사하며, 다시 시도한 테이블의 내용은 대체됩니다. 복사가 끝나거나 실패하면 메시지와 이메일로 알림을 받으며, 메시지에서 결과를 다시 열거나, 나중에 **프로젝트** 탭에서 복사본을 선택하고 **작업** 메뉴에서 **가져오기 또는 복사 결과 보기**를 선택하여 열 수 있습니다.

결과는 누군가 닫을 때까지 복사본에 남아 있습니다. 복사가 끝난 후 **결과 삭제**를 클릭하면 프로젝트를 열 수 있는 모든 사람에게서 결과가 제거됩니다. 프로젝트에서 바뀌는 것은 없지만, 실패한 테이블은 이 창에서 더 이상 다시 시도할 수 없습니다. 결과를 삭제하려면 프로젝트에 대한 편집 액세스가 필요하며 프로젝트가 잠겨 있지 않아야 합니다.

### 참조 업데이트

프로젝트의 워크플로 단계는 해당 프로젝트 내부의 테이블과 다른 개체를 참조합니다. **참조 업데이트**는 이러한 참조를 원본이 아니라 복사본을 가리키도록 다시 작성합니다. 거의 항상 원하는 동작이므로 기본적으로 켜져 있습니다. 끄면 복사된 단계가 원래 프로젝트를 계속 가리킵니다.

<Aside>복사는 백그라운드에서 실행됩니다. 진행률 대화 상자에서 복사가 각 단계를 거쳐 진행되는 모습을 볼 수 있으며, **백그라운드에서 실행**을 클릭하면 대화 상자를 닫고 계속 작업할 수 있습니다. 프로젝트 목록은 자동으로 업데이트되고 복사가 끝나면 알림을 받습니다.</Aside>

## 프로젝트 보고서 보기

프로젝트나 워크플로가 동적일 때는 상세한 문서를 유지하기가 어렵습니다. 이 문제를 해결하기 위해 PlaidCloud는 워크플로, 워크플로 단계, 사용자 정의 변환, 변수, 테이블을 상세하게 문서화하는 프로젝트 수준 보고서를 생성하는 기능을 제공합니다. 이 보고서는 요청 시 생성되며 프로젝트의 현재 상태를 반영합니다.

보고서를 다운로드하는 방법은 다음과 같습니다.

1. Analyze를 엽니다.
2. “프로젝트”를 선택합니다.
3. 보고서 아이콘을 클릭합니다.
