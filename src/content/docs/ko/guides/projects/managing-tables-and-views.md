PlaidCloud에서는 레이블을 포함하여 테이블을 정리하고 관리할 수 있습니다. 테이블은 프로젝트 내의 모든 워크플로에서 사용할 수 있으며 다양한 도구와 옵션을 제공합니다.


테이블 외에도 PlaidCloud는 테이블 데이터를 기반으로 하는 뷰를 제공합니다. 뷰를 사용하면 기반 테이블이 변경될 때 즉시 업데이트되며 데이터 스토리지 공간도 절약됩니다.



옵션은 다음과 같습니다.


* 같은 테이블이 계층의 여러 경로에 존재할 수 있습니다(대체 계층)
* 테이블에 태그를 지정하여 PlaidCloud 프로세스에서 더 쉽게 검색하고 포함할 수 있습니다
* 테이블은 버전을 관리할 수 있습니다
* 테이블을 게시하여 대시보드 시각화에서 사용할 수 있습니다

PlaidCloud는 일련의 폴더를 탐색할 때처럼 경로 기반 시스템으로 테이블을 정리하므로 테이블을 더 유연하고 논리적으로 구성할 수 있습니다. 이 시스템을 사용하면 테이블을 계층 내에서 이동하거나, 계층의 여러 위치에서 하나의 테이블을 여러 번 참조(대체 계층)하도록 만들 수 있습니다. 이러한 방식으로 테이블을 관리하면 구조에 운영, 보고 및 통제 요구 사항을 반영할 수 있습니다.



## 테이블 찾기


계층 왼쪽 아래의 필터 상자를 사용하여 테이블 이름과 레이블을 검색합니다. 일치하는 항목은 위의 계층에 표시됩니다.


### 워크플로별

**테이블** 탭 끝에 있는 **워크플로별** 폴더는 테이블을 읽거나 쓰는 워크플로별로 테이블을 그룹화합니다. 워크플로를 열면 해당 테이블을 볼 수 있습니다. 이 폴더는 같은 테이블의 뷰이므로 여기서 항목을 이동하거나 복사할 수 없습니다.


### 열별

**테이블** 탭의 열 검색 상자에 열 이름을 입력하고 Enter를 누르거나 옆의 돋보기를 선택하면 해당 이름의 열이 있는 테이블만 표시됩니다. 검색은 데이터가 아니라 열 이름을 읽으므로 빠릅니다. 이름 전체 대신 열 이름의 일부와 일치시키려면 **포함**을 선택합니다. 상자를 지우면 모든 테이블이 다시 표시됩니다. 긴 검색은 여러 페이지로 반환될 수 있으며 상태 줄에 아직 검색 중이거나 불완전할 수 있다고 표시됩니다.

**열 트리**를 선택하면 별도의 창에서 검색할 수 있습니다. 해당 열이 있는 각 테이블은 두 개의 목록으로 펼쳐집니다.

* **공급 원본** — 열을 공급하는 테이블
* **공급 대상** — 열이 이어서 공급하는 테이블

MCP로 연결된 AI 어시스턴트는 `table_find(column=...)`로 같은 테이블을 찾으며 이름 전체 또는 일부와 일치시킵니다.


### 값 검색

어떤 테이블에 특정 값이 있는지 찾으려면 **테이블** 탭의 **작업** 메뉴에서 **데이터에서 값 검색… (느림)** 옵션을 선택하거나, 테이블을 마우스 오른쪽 버튼으로 클릭하여 선택하면 해당 테이블만 검색합니다. 값을 입력하고, 값의 일부와 일치시키려면 **포함**을 선택한 다음 **검색**을 선택합니다. 값이 있는 각 테이블이 값이 나타나는 열과 일치하는 값 몇 개와 함께 나열됩니다. 테이블을 두 번 클릭하거나 Enter를 누르면 **테이블 탐색기**에서 열립니다. 열을 선택하면 일치하는 행으로 필터링된 테이블이 열립니다. 열 검색 상자에 텍스트가 있으면 찾을 값이 자동으로 채워집니다.

검색하기 전에 다음 사항을 알아 두십시오.

* 검색은 검색 대상 모든 테이블의 모든 행을 읽으므로 매우 느릴 수 있고 웨어하우스 리소스를 많이 사용할 수 있습니다. 창에서 이를 경고하며 검색이 끝날 때까지 검색 버튼이 꺼져 있습니다.
* 이미 열 수 있는 행만 표시됩니다. 행 수준 보안이 모든 검색에 적용됩니다.
* 웨어하우스의 쿼리 기록에 검색한 값이 기록됩니다.
* 검색은 테이블의 텍스트 열을 대상으로 합니다. 아직 빌드되지 않은 테이블은 건너뛰며 경고에 이름이 표시됩니다.
* 결과는 페이지로 나뉘어 제공됩니다. 상태 줄에 검색이 일찍 중단되었다고 표시되면 **더 검색**를 선택하여 아직 검색하지 않은 테이블로 계속합니다.

MCP로 연결된 AI 어시스턴트는 `table_value_search`를 사용합니다. 이 도구는 값을 보유한 테이블과 열을 반환하며 값 자체는 반환하지 않습니다. 프로젝트에서 AI 어시스턴트에게 값을 찾도록 요청하면 Weave는 일치하는 테이블과 열의 이름을 언어 모델 공급자에게 보냅니다.



## CSV 파일 가져오기

**CSV 파일을 이 프로젝트의 새 테이블로 변환하려면:**

1. 컴퓨터에서 파일을 프로젝트의 **테이블** 목록으로 끌어다 놓거나, 도구 모음에서 **새로 만들기** > **CSV 파일에서 테이블 만들기**를 선택한 다음 파일을 상자에 놓거나 **CSV 파일 선택**을 클릭합니다.
2. PlaidCloud는 파일을 **Personal Temp Drive**에 업로드하고(없으면 워크스페이스의 **Temp Drive**에 업로드) 목록 최상위에 파일 이름을 딴 새 테이블로 가져옵니다. `Sales Data.csv`는 `sales_data`가 됩니다. 프로젝트에 이미 같은 이름의 테이블이 있으면 새 테이블에는 `sales_data_2`와 같이 번호가 붙습니다.
3. 목록이 새로 고쳐지면서 새 테이블이 선택되고 **데이터 한눈에 보기**가 해당 테이블에서 열립니다. 패널에 표시되는 내용은 [내 CSV로 시작하기](/ko/get-started/quickstart/#내-csv로-시작하기)를 참조하십시오.

`.csv`로 끝나는 파일만 허용됩니다. 테이블을 만들고 문서 스토리지에 쓸 수 있는 권한이 필요하며, 잠긴 프로젝트는 잠금이 해제될 때까지 CSV를 받지 않습니다. 가져오기가 실패하면 창에 이유가 표시되며 프로젝트는 이전 상태 그대로 유지됩니다. PlaidCloud는 가져오기가 끝나면 성공 여부와 관계없이 임시 드라이브에서 업로드된 파일을 삭제하며, 삭제하지 못하면 임시 드라이브가 하루 후에 삭제합니다.

## 이동


**테이블을 이동하려면:**


1. 원하는 위치의 폴더로 끌어다 놓습니다

## 이름 바꾸기


**테이블 이름을 바꾸려면:**


1. 테이블을 마우스 오른쪽 버튼으로 클릭합니다
2. 이름 바꾸기 옵션을 선택합니다
3. 새 이름을 입력하고 저장합니다
4. 테이블 이름이 바뀌지만 원래의 고유 식별자는 유지됩니다.

## 비우기


**테이블을 비우려면:**


1. 계층에서 테이블을 선택합니다 ‘
2. 맨 위 도구 모음에서 비우기 버튼을 클릭합니다.

*참고: 테이블을 하나만 또는 여러 개 비울 수 있습니다*



## 삭제


**테이블을 삭제하려면:**


1. 계층에서 테이블을 선택합니다
2. 맨 위 도구 모음에서 삭제 버튼을 클릭합니다
3. 삭제 작업은 테이블이 워크플로 단계나 뷰에서 사용 중인지 확인합니다. 사용 중이면 삭제하기 전에 해당 연결을 제거하라는 메시지가 표시됩니다.

*참고: 테이블을 강제로 삭제할 수도 있습니다. 강제 삭제하면 참조가 끊어진 상태로 남으므로 드물게 사용해야 합니다.*


### 마지막 읽기

삭제 창에는 테이블이 마지막으로 읽힌 시점이 표시됩니다. 예를 들어 **Last read 3 days ago by** 뒤에 사용자 또는 단계가 표시되므로 아무도 사용하지 않는 테이블과 아직 사용 중인 테이블을 구분할 수 있습니다. PlaidCloud는 웨어하우스 자체의 쿼리 기록에서 이를 가져오며 PlaidCloud 자체의 정리 작업이 수행한 읽기는 제외합니다.

| 웨어하우스 | 필요한 항목 |
| --- | --- |
| Snowflake | 읽기 정보는 Access History에서 가져오며 Snowflake는 이를 최대 약 3시간 늦게 기록합니다. 연결의 역할에는 `SNOWFLAKE.GOVERNANCE_VIEWER` 데이터베이스 역할이 필요합니다(`SNOWFLAKE` 데이터베이스에 대한 `IMPORTED PRIVILEGES`도 작동합니다). Snowflake Standard 에디션에는 Access History가 없습니다. |
| Databricks | 읽기 정보는 계보 테이블에서 가져오며 Databricks도 이를 지연하여 기록하므로 최근 읽기는 아직 표시되지 않을 수 있습니다. 연결의 ID에는 `system`에 대한 `USE CATALOG`, `system.access`에 대한 `USE SCHEMA`, `system.access.table_lineage`에 대한 `SELECT`가 필요합니다. |
| PlaidCloud Lakehouse | 읽기 기록은 아직 사용할 수 없습니다. 창에 **Read history incomplete**가 표시됩니다. |

웨어하우스를 연결하면 [연결 검사](/ko/guides/connections/external-lakehouse/#3-검사-후-사용)가 누락된 권한을 각각 실행할 문으로 함께 권장합니다. 이 권한은 필수가 아니라 권장 사항입니다. 없어도 웨어하우스는 연결되며 창에 **Read history incomplete**가 표시됩니다.

PlaidCloud가 전체 기록을 읽을 수 없으면 해당 줄에 **Read history incomplete**가 표시되며 "읽기 없음"으로 대신 보고하지 않습니다. 웨어하우스에 직접 SQL 액세스 권한이 있는 사용자는 누구나 자신의 읽기에 붙는 레이블을 바꾸는 세션 태그를 설정할 수 있습니다.

MCP로 연결된 AI 어시스턴트는 `table_describe(include=['last_read'])`에서 같은 답을 얻습니다.



## 테이블의 열 보기


테이블을 선택하면 세부 정보 패널이 열립니다. **열** 섹션에는 각 열이 **유형** 및 **설명**과 함께 나열되며, 설명은 **열 속성**에서 가져옵니다. 긴 설명 전체를 읽으려면 행을 가리키십시오.

데이터가 만료되었거나 어떤 단계도 빌드하지 않아 현재 웨어하우스에 없는 테이블에는 나열할 열이 없습니다. 섹션에 이 점이 표시되며 테이블에 몇 개의 열이 있는지 보여 줍니다. 열을 나열하려면 해당 테이블을 쓰는 단계를 실행하십시오.


## 테이블이 사용되는 위치 보기


테이블을 선택하면 해당 테이블을 사용하는 워크플로 단계를 나열하는 세부 정보 패널이 열립니다.


* **테이블 생성자** — 테이블에 쓰는 단계
* **테이블 기여 대상** — 테이블에서 읽는 단계
* **이 테이블을 참조할 수 있음** — 해결할 수 없는 변수를 통해 테이블에 접근하는 단계입니다. 이 섹션은 해당 단계가 있을 때만 나타납니다.


단계는 테이블을 직접 지정하거나 `/Periods/{period}/Sales`처럼 변수가 포함된 경로를 통해 접근할 수 있습니다. 해당 변수에 현재 값이 있으면 단계가 처음 두 목록에 정보 아이콘과 함께 나타납니다. 행을 가리키면 단계가 저장한 경로를 볼 수 있습니다.


이러한 행은 더 약한 답이라는 점을 감안하여 해석하십시오. 이 행은 지금 시작하는 실행이 건드릴 대상을 설명하며, 테이블에 지금까지 접근한 모든 항목을 설명하는 것은 아닙니다. 변수를 바꾸면 다른 테이블을 읽게 됩니다.


일부 변수는 해결할 수 없습니다. 변수를 설정한 항목이 전혀 없거나, 실행에서 사용하는 값이 저장된 값에서 오지 않는 경우입니다. Workflow Loop 단계는 반복하면서 데이터에서 변수를 가져오고, Set Variable 단계는 실행 중에 값을 할당하며, 매크로는 호출하는 단계가 변수를 전달하고, 센서가 시작한 실행은 해당 센서 자체의 세부 정보를 가집니다. 각 경우에 실행 사이에 저장된 값은 신뢰할 수 있는 값이 아니라 마지막 실행에서 남은 값입니다. PlaidCloud는 잘못된 테이블일 수 있는 항목으로 해결하는 대신, 해결하지 못한 변수와 함께 단계를 이름으로 **이 테이블을 참조할 수 있음** 아래에 나열하므로 단계를 열어 확인할 수 있습니다.


역할이 볼 수 없는 단계도 나열되므로 테이블이 사용 중임을 알 수 있지만 이름이나 워크플로는 표시되지 않으며 열 수 없습니다. 테이블을 삭제할 때에도 계속 집계됩니다. 볼 수 있는 단계는 역할에서 숨겨진 워크플로 없이 나열됩니다. 아키텍트에게는 숨겨지는 항목이 없습니다.


*참고: **테이블** 목록에서 테이블을 삭제할 때, 변수 유무와 관계없이 경로를 통해 테이블에 접근하는 단계는 변수를 해결할 수 없더라도 해당 테이블을 사용하는 것으로 집계됩니다. 삭제 창에 해당 단계가 나열되며 강제로 삭제할 때만 삭제가 진행됩니다.*



## 새 디렉터리 구조 만들기


**새 폴더를 추가하려면:**


1. 도구 모음에서 새 폴더 버튼을 클릭합니다

**기존 폴더에 폴더를 추가하려면:**


1. 폴더를 마우스 오른쪽 버튼으로 클릭합니다
2. 새 폴더를 선택합니다


## 데이터 보기(테이블 탐색기)


테이블 데이터는 테이블 탐색기를 사용하여 봅니다. 테이블 탐색기는 데이터의 그리드 뷰와 값 및 통계의 열별 요약을 제공합니다. 포인트 앤 클릭 필터링과 익숙한 파일 형식으로의 내보내기를 모두 사용할 수 있습니다. 필터 선택 내용은 워크플로에서 사용할 수 있는 추출 단계로 저장할 수도 있습니다.



## 보고용 테이블 게시


대시보드 시각화는 의도적으로 게시된 테이블로 제한됩니다. 테이블을 게시할 때 데이터를 구별할 수 있는 고유한 이름을 지정할 수 있습니다. 테이블을 생성한 워크플로의 일부에서는 이름이 모호하지만 대시보드를 만드는 사용자에게는 더 명확한 이름이 필요할 때 유용할 수 있습니다.


게시된 테이블에는 연결된 경로가 없습니다. 대시보드 영역에서 사용할 수 있는 테이블 목록으로 표시됩니다.



## 보기 역할에 맞게 테이블 표시


탐색기 또는 관리자 확인란을 클릭하여 다양한 역할이 테이블을 볼 수 있는지 제어할 수 있습니다. 여러 테이블을 업데이트해야 하면 계층에서 테이블을 선택하고 맨 위 도구 모음의 작업 메뉴에서 원하는 보기 역할을 선택합니다.



## 테이블 내용을 설명하는 메모


데이터를 이해하는 데 도움이 되도록 테이블에 메모를 추가합니다.



## 테이블 구조, 크기 및 마지막 업데이트 시간 보기


각 테이블의 행 수, 열 수, 데이터 크기가 테이블 계층에 표시됩니다. 매우 큰 테이블(수백만 행)의 경우 행 수가 추정치일 수 있으며 대략적인 행 수임을 나타내는 표시가 나타납니다.



## 추가 테이블 속성 보기


**다른 테이블 속성을 보고 편집하려면:**


1. 테이블을 선택합니다
2. 오른쪽의 테이블 컨텍스트 양식 보기를 클릭합니다.


## 테이블 복제


**테이블을 복제하려면:**


1. 테이블을 선택합니다
2. 맨 위 도구 모음에서 복제 버튼을 클릭합니다.


## 테이블에서 Panel 앱 만들기


테이블 또는 뷰를 선택하고 **새로 만들기** 메뉴 또는 마우스 오른쪽 버튼 메뉴에서 **Panel 앱 만들기**을 선택합니다. 프로젝트와 테이블이 이미 선택된 상태로 **새 Studio 앱** 대화 상자가 열립니다. 앱 이름을 지정하고 **만들기**를 선택하면 Panel Studio에서 Weave가 첫 페이지를 빌드할 준비가 된 상태로 앱이 열립니다. 이 명령은 테이블 또는 뷰를 하나만 선택하고, 프로젝트에 대한 편집 액세스 권한이 있으며, 프로젝트가 읽기 전용이 아닐 때 사용할 수 있습니다. [Panel 앱 만들기](/ko/guides/panel-apps/creating/#테이블에서-시작)를 참조하십시오.


## 테이블에 저장된 내용 보기


**테이블** 목록에는 각 테이블의 크기 옆에 **현재 데이터**, **기록**, **참고** 열이 표시되고 그 뒤에 **타임 트래블 일수**가 표시됩니다. 목록 위의 줄에는 프로젝트의 합계, 즉 저장하는 총량과 그중 현재 데이터와 기록의 양이 표시됩니다. PlaidCloud가 아직 측정하지 않은 테이블에는 크기가 없습니다.

도구 모음에서 **스토리지**를 선택하면 공간을 확보하기 위한 제안과 타임 트래블 설정이 있는 프로젝트의 **스토리지** 창이 열립니다. [스토리지 관리](/ko/guides/projects/managing-storage/#프로젝트의-스토리지-창)를 참조하십시오.


## 테이블에서 데이터 편집기 만들기


테이블을 선택하고 **새로 만들기** 메뉴 또는 마우스 오른쪽 버튼 메뉴에서 **테이블에서 데이터 편집기 만들기**를 선택하면 한 번에 테이블을 구성된 데이터 편집기로 바꿀 수 있습니다. PlaidCloud는 테이블의 열을 검사하여 편집기의 입력 컨트롤을 미리 빌드합니다. 자세한 내용은 [테이블에서 데이터 편집기 만들기](/ko/guides/projects/managing-data-editors/#테이블에서-데이터-편집기-만들기)를 참조하십시오.
