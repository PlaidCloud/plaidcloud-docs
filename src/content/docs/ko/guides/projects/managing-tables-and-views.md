PlaidCloud에서는 레이블을 포함하여 테이블을 구성하고 관리할 수 있습니다. 테이블은 프로젝트 내 모든 워크플로에서 사용할 수 있으며 다양한 도구와 옵션을 제공합니다.


테이블 외에도 PlaidCloud는 테이블 데이터를 기반으로 한 뷰를 제공합니다. 뷰를 사용하면 기본 테이블이 변경될 때 즉시 업데이트되며 데이터 스토리지 공간도 절약됩니다.



옵션은 다음과 같습니다.


* 동일한 테이블을 계층 구조의 여러 경로에 둘 수 있습니다(대체 계층).
* 테이블에 태그를 지정하여 PlaidCloud 프로세스에서 더 쉽게 검색하고 포함할 수 있습니다.
* 테이블의 버전을 관리할 수 있습니다.
* 테이블을 게시하여 대시보드 시각화에서 사용할 수 있습니다.

PlaidCloud는 일련의 폴더를 탐색할 때처럼 경로 기반 시스템으로 테이블을 구성하므로 테이블을 더 유연하고 논리적으로 구성할 수 있습니다. 이 시스템에서는 계층 구조 내에서 테이블을 이동하거나, 계층 구조의 여러 위치에서 하나의 테이블을 여러 번 참조(대체 계층)하도록 만들 수 있습니다. 이러한 방식으로 테이블을 관리하면 운영, 보고, 통제의 필요에 맞게 구조를 반영할 수 있습니다.



## 테이블 찾기


계층 구조 왼쪽 하단의 필터 상자를 사용하여 테이블 이름과 레이블을 검색합니다. 일치하는 항목이 위쪽 계층 구조에 표시됩니다.


### 워크플로별

**테이블** 탭 끝에 있는 **By Workflow** 폴더는 테이블을 읽거나 쓰는 각 워크플로 아래에 테이블을 그룹화합니다. 워크플로를 열면 해당 워크플로의 테이블을 볼 수 있습니다. 이 폴더는 동일한 테이블을 보여 주는 뷰이므로 여기에서 이동하거나 복사할 수 없습니다.


### 열별

**테이블** 탭의 열 검색 상자에 열 이름을 입력하면 해당 이름의 열이 있는 테이블만 표시됩니다. **포함**을 선택하면 전체 이름이 아니라 열 이름의 일부와 일치하는 항목을 찾습니다. 상자를 비우면 모든 테이블이 다시 표시됩니다. 긴 검색은 여러 페이지로 나뉘어 반환될 수 있으며, 상태 줄에 아직 검색 중이거나 결과가 불완전할 수 있다는 내용이 표시됩니다.

**Column Tree**를 선택하면 별도의 창에서 검색합니다. 해당 열이 있는 각 테이블을 펼치면 두 개의 목록이 나타납니다.

* **Fed by** — 해당 열을 공급하는 테이블
* **Feeds** — 해당 열이 이어서 공급하는 테이블

MCP로 연결된 AI 어시스턴트는 `table_find(column=...)`로 동일한 테이블을 찾으며, 전체 이름 또는 일부와 일치하는 항목을 찾습니다.


### 값 검색

어떤 테이블에 특정 값이 있는지 찾으려면 **테이블** 탭에서 **Search Values**를 선택하거나, 테이블을 마우스 오른쪽 버튼으로 클릭하고 **Search Value**를 선택하여 해당 테이블만 검색합니다. 값을 입력하고, 값의 일부와 일치시키려면 **포함**을 선택한 다음 **검색**을 선택합니다. 해당 값이 있는 각 테이블이 값이 나타나는 열 및 일치하는 값 몇 개와 함께 나열됩니다.

검색하기 전에 다음 사항을 알아 두십시오.

* 이미 열 수 있는 행만 표시됩니다. 행 수준 보안은 모든 검색에 적용됩니다.
* 웨어하우스의 쿼리 기록에 검색한 값이 기록됩니다.
* 검색은 테이블의 텍스트 열을 대상으로 합니다. 아직 빌드되지 않은 테이블은 건너뛰며 경고에 이름이 표시됩니다.
* 결과는 페이지 단위로 제공됩니다. 상태 줄에 검색이 일찍 중단되었다고 표시되면 **Search more**를 선택하여 아직 검색하지 않은 테이블에서 계속합니다.

MCP로 연결된 AI 어시스턴트는 `table_value_search`를 사용합니다. 이 도구는 값을 포함하는 테이블과 열을 반환할 뿐 값 자체는 반환하지 않습니다. 프로젝트에서 AI 어시스턴트에게 값을 찾아 달라고 요청하면 Weave는 일치하는 테이블과 열의 이름을 언어 모델 제공업체에 전송합니다.



## CSV 파일 가져오기

**CSV 파일을 이 프로젝트의 새 테이블로 만들려면 다음과 같이 합니다.**

1. 컴퓨터의 파일을 프로젝트의 **테이블** 목록으로 끌어다 놓거나, 도구 모음에서 **새로 만들기** > **CSV 파일에서 테이블 만들기**를 선택한 다음 파일을 상자에 놓거나 **CSV 파일 선택**을 클릭합니다.
2. PlaidCloud는 파일을 **Personal Temp Drive**에 업로드하며, 없으면 워크스페이스의 **Temp Drive**에 업로드합니다. 그런 다음 목록 최상위에 파일 이름을 딴 새 테이블로 가져옵니다. `Sales Data.csv`는 `sales_data`가 됩니다. 프로젝트에 같은 이름의 테이블이 이미 있으면 `sales_data_2`처럼 새 테이블에 번호가 붙습니다.
3. 목록이 새로 고쳐지면서 새 테이블이 선택되고 **데이터 한눈에 보기**가 해당 테이블에서 열립니다. 이 패널에 표시되는 내용은 [내 CSV로 시작하기](/ko/get-started/quickstart/#내-csv로-시작하기)를 참조하십시오.

`.csv`로 끝나는 파일만 허용됩니다. 테이블을 만들 권한과 문서 스토리지에 쓸 권한이 필요하며, 잠긴 프로젝트는 잠금을 해제하기 전에는 CSV를 받지 않습니다. 가져오기가 실패하면 창에 이유가 표시되고 프로젝트는 원래 상태로 유지됩니다. PlaidCloud는 가져오기가 끝나면 성공 여부와 관계없이 임시 드라이브에서 업로드된 파일을 삭제하며, 삭제하지 못한 경우 임시 드라이브가 하루 뒤에 삭제합니다.

## 이름 바꾸기


**테이블 이름을 바꾸려면 다음과 같이 합니다.**


1. 테이블을 마우스 오른쪽 버튼으로 클릭합니다.
2. 이름 바꾸기 옵션을 선택합니다.
3. 새 이름을 입력하고 저장합니다.
4. 테이블 이름이 바뀌지만 원래의 고유 식별자는 유지됩니다.

## 지우기


**테이블을 지우려면 다음과 같이 합니다.**


1. 계층 구조에서 테이블을 선택합니다.
2. 상단 도구 모음에서 지우기 버튼을 클릭합니다.

*참고: 테이블 하나 또는 여러 개를 지울 수 있습니다.*



## 삭제


**테이블을 삭제하려면 다음과 같이 합니다.**


1. 계층 구조에서 테이블을 선택합니다.
2. 상단 도구 모음에서 삭제 버튼을 클릭합니다.
3. 삭제 작업은 테이블이 워크플로 단계나 뷰에서 사용 중인지 확인합니다. 사용 중이면 삭제하기 전에 해당 연결을 제거하라는 안내가 표시됩니다.

*참고: 테이블을 강제로 삭제할 수도 있습니다. 강제 삭제하면 참조가 끊어진 상태로 남으므로 가급적 사용하지 마십시오.*


### 마지막 읽기

삭제 창에는 테이블을 마지막으로 읽은 시점이 표시됩니다(예: **Last read 3 days ago by** 뒤에 사용자 또는 단계). 이를 통해 아무도 사용하지 않는 테이블과 아직 사용 중인 테이블을 구분할 수 있습니다. PlaidCloud는 웨어하우스 자체의 쿼리 기록에서 이 정보를 가져오며, PlaidCloud 자체의 유지 관리 작업에서 발생한 읽기는 제외합니다.

| 웨어하우스 | 필요한 항목 |
| --- | --- |
| Snowflake | 읽기 정보는 Access History에서 가져오며, Snowflake는 이를 최대 약 3시간 늦게 기록합니다. 연결의 역할에 `SNOWFLAKE.GOVERNANCE_VIEWER` 데이터베이스 역할이 필요합니다(`SNOWFLAKE` 데이터베이스의 `IMPORTED PRIVILEGES`도 사용 가능). Snowflake Standard 에디션에는 Access History가 없습니다. |
| Databricks | 읽기 정보는 계보 테이블에서 가져오며, Databricks도 이를 지연하여 기록하므로 최근 읽기는 아직 표시되지 않을 수 있습니다. 연결의 ID에 `system`에 대한 `USE CATALOG`, `system.access`에 대한 `USE SCHEMA`, `system.access.table_lineage`에 대한 `SELECT`가 필요합니다. |
| PlaidCloud Lakehouse | 읽기 기록은 아직 사용할 수 없습니다. 창에 **Read history incomplete**가 표시됩니다. |

웨어하우스를 연결하면 [연결 검사](/ko/guides/connections/external-lakehouse/#3-검사-후-사용)에서 누락된 권한 부여를 실행할 문장과 함께 권장합니다. 이는 권장 사항이며 필수가 아닙니다. 없어도 웨어하우스는 연결되며 창에 **Read history incomplete**가 표시됩니다.

PlaidCloud가 전체 기록을 읽을 수 없으면 해당 줄에 **Read history incomplete**가 표시되며, 이를 "읽기 없음"으로 대신 표시하지 않습니다. 웨어하우스에 직접 SQL 액세스 권한이 있는 사용자는 누구나 자신의 읽기 레이블 방식을 바꾸는 세션 태그를 설정할 수 있습니다.

MCP로 연결된 AI 어시스턴트는 `table_describe(include=['last_read'])`로 동일한 답을 얻습니다.



## 테이블이 사용되는 위치 확인


테이블을 선택하면 해당 테이블과 관련된 워크플로 단계를 나열하는 세부 정보 패널이 열립니다.


* **테이블 생성자** — 테이블에 쓰는 단계
* **테이블 기여 대상** — 테이블에서 읽는 단계
* **이 테이블을 참조할 수 있음** — 확인할 수 없는 변수를 통해 테이블에 접근하는 단계. 이러한 단계가 있을 때만 이 섹션이 나타납니다.


단계는 테이블을 직접 지정하거나 `/Periods/{period}/Sales`처럼 변수가 포함된 경로를 통해 접근할 수 있습니다. 해당 변수에 현재 값이 있으면 단계가 처음 두 목록에 정보 아이콘과 함께 나타납니다. 행 위에 마우스를 올리면 단계에 저장된 경로를 볼 수 있습니다.


이러한 행은 그만큼 신뢰도가 낮은 답이라고 보십시오. 지금 시작하는 실행이 접근할 대상을 설명할 뿐, 테이블에 지금까지 접근한 모든 것을 설명하지는 않습니다. 변수를 바꾸면 다른 테이블을 읽게 됩니다.


일부 변수는 확인할 수 없습니다. 변수를 설정한 것이 전혀 없거나, 실행에 사용되는 값이 저장된 값에서 오지 않기 때문입니다. 예를 들어 Workflow Loop는 반복하면서 데이터에서 변수를 가져오고, Set Variable 단계는 실행 중에 값을 할당하며, 매크로는 자신을 호출하는 단계로부터 변수를 전달받고, 센서가 시작한 실행은 해당 센서 자체의 세부 정보를 가집니다. 어느 경우든 실행 사이에 저장된 값은 신뢰할 수 있는 값이 아니라 마지막 실행에서 남은 것입니다. PlaidCloud는 이러한 변수를 잘못된 테이블일 수도 있는 대상으로 확인하는 대신, 확인하지 못한 변수와 함께 단계 이름을 **이 테이블을 참조할 수 있음** 아래에 나열하므로 단계를 열어 직접 확인할 수 있습니다.


역할상 볼 수 없는 단계도 나열되므로 테이블이 사용 중임을 알 수 있지만, 이름이나 워크플로는 표시되지 않고 열 수도 없습니다. 이 단계도 테이블을 삭제할 때 사용 중인 것으로 계산됩니다. 볼 수 있는 단계는 역할에 숨겨진 워크플로를 제외하고 나열됩니다. 아키텍트에게는 숨겨지는 항목이 없습니다.


*참고: **테이블** 목록에서 테이블을 삭제할 때, 변수 사용 여부와 관계없이 경로를 통해 테이블에 접근하는 단계는 변수를 확인할 수 없더라도 해당 테이블을 사용하는 것으로 계산됩니다. 삭제 창에 해당 단계가 나열되며, 강제로 삭제하는 경우에만 삭제가 진행됩니다.*

## 데이터 보기(테이블 탐색기)


테이블 데이터는 테이블 탐색기로 봅니다. 테이블 탐색기는 데이터의 그리드 보기와 함께 열별 값 및 통계 요약을 제공합니다. 포인트 앤드 클릭 필터링과 익숙한 파일 형식으로의 내보내기를 모두 사용할 수 있습니다. 필터 선택 내용을 워크플로에서 사용할 수 있는 Extract 단계로 저장할 수도 있습니다.



## 보고용 테이블 게시


대시보드 시각화는 게시된 테이블로 의도적으로 제한됩니다. 테이블을 게시할 때 데이터를 구분할 수 있는 고유한 이름을 지정할 수 있습니다. 테이블을 생성한 워크플로 부분에서는 이름이 모호하지만 대시보드를 만드는 사용자에게는 더 명확한 이름이 필요할 때 유용합니다.


게시된 테이블에는 경로가 연결되어 있지 않습니다. 대시보드 영역에서 사용할 수 있는 테이블 목록으로 나타납니다.



## 보기 역할에 맞게 테이블 표시


탐색기 또는 관리자 확인란을 클릭하여 다양한 역할이 테이블을 볼 수 있는지 제어할 수 있습니다. 여러 테이블을 업데이트해야 하면 계층 구조에서 테이블을 선택하고 상단 도구 모음의 **작업** 메뉴에서 원하는 보기 역할을 선택합니다.



## 메모로 테이블 내용 설명


테이블에 메모를 추가하면 데이터를 이해하는 데 도움이 됩니다.



## 테이블 형태, 크기 및 마지막 업데이트 시간 보기


각 테이블의 행 수, 열 수, 데이터 크기가 테이블 계층 구조에 표시됩니다. 매우 큰 테이블(수백만 행)의 경우 행 수가 추정치일 수 있으며, 이때는 대략적인 행 수임을 나타내는 표시가 나타납니다.



## 추가 테이블 속성 보기


**다른 테이블 속성을 보고 편집하려면 다음과 같이 합니다.**


1. 테이블을 선택합니다.
2. 오른쪽에 있는 테이블 컨텍스트 양식 보기를 클릭합니다.


## 테이블 복제


**테이블을 복제하려면 다음과 같이 합니다.**


1. 테이블을 선택합니다.
2. 상단 도구 모음에서 복제 버튼을 클릭합니다.


## 테이블에서 데이터 편집기 만들기


테이블을 선택하고 **새로 만들기** 메뉴 또는 마우스 오른쪽 버튼 메뉴에서 **테이블에서 데이터 편집기 만들기**를 선택하면 테이블을 구성된 데이터 편집기로 한 번에 바꿀 수 있습니다. PlaidCloud가 테이블의 열을 검사하여 편집기의 입력 컨트롤을 미리 만들어 줍니다. 자세한 내용은 [테이블에서 데이터 편집기 만들기](/ko/guides/projects/managing-data-editors/#테이블에서-데이터-편집기-만들기)를 참조하십시오.
