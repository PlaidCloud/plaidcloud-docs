Analyze 창은 서로 위에 겹쳐서 열립니다. 프로젝트 안의 워크플로, 그 워크플로 안의 단계, 결과를 확인하려고 연 테이블이 그 예입니다. 지금 어디에 있는지 쉽게 파악하고 다시 빠져나올 수 있도록 두 가지 기능이 제공됩니다. 각 창 제목의 **이동 경로**와, 보고 있는 대상을 따라가는 **URL**입니다. 덕분에 어떤 보기든 북마크하거나 동료에게 붙여넣어 전달할 수 있습니다.

## 이동 경로

프로젝트에 속한 창은 창의 제목 표시줄에 계층 구조를 제목으로 표시합니다.

```
My Project › Workflow › Nightly Load
```

각 부분을 세그먼트라고 하며, 가장 바깥쪽 컨테이너에서 안쪽으로 왼쪽에서 오른쪽 순서로 읽습니다.

1. **프로젝트** — 보고 있는 대상을 소유한 프로젝트입니다.
2. **개체 유형** — 워크플로, 테이블, 단계, 차원 또는 데이터 편집기입니다.
3. **개체 자체** — 현재 워크플로, 테이블, 단계 등입니다. 이 마지막 세그먼트는 이미 있는 위치이므로 클릭할 수 없습니다.

### 이동 경로로 탐색하기

처음 두 세그먼트 중 하나를 선택하면 위로 이동합니다.

| 세그먼트 | 도구 설명 | 동작 |
|---|---|---|
| 프로젝트 이름 | 프로젝트 열기 | 해당 프로젝트를 열거나, 이미 열려 있으면 맨 앞으로 가져옵니다 |
| 워크플로 | 모든 워크플로 표시 | 프로젝트를 워크플로 목록으로 엽니다 |
| 테이블 | 모든 테이블 표시 | 프로젝트를 테이블 목록으로 엽니다 |
| 단계 | 모든 단계 표시 | 프로젝트를 단계 목록으로 엽니다 |
| 차원 | 모든 차원 표시 | 프로젝트를 차원 목록으로 엽니다 |
| 데이터 편집기 | 모든 데이터 편집기 표시 | 프로젝트를 데이터 편집기 목록으로 엽니다 |

유형 세그먼트는 같은 수준의 다른 개체로 가는 가장 빠른 방법입니다. 한 워크플로에서 한 번 클릭하면 같은 프로젝트의 전체 워크플로 목록으로 이동하므로 다른 워크플로를 바로 열 수 있습니다.

<Aside type="note">
이전에 있던 창은 열린 상태로 유지됩니다. 이동 경로로 탐색하면 프로젝트가 맨 앞으로 오지만 보고 있던 창이 닫히지는 않으며, 화면 아래쪽의 탭 표시줄에서 다시 돌아갈 수 있습니다.
</Aside>

### 이동 경로가 표시되는 위치

- **워크플로** 창 — 표준 워크플로의 단계 그리드
- **시각적 워크플로 디자이너** — 고급 워크플로의 캔버스 보기
- **테이블 탐색기**
- 단독으로 열린 **단계** 창
- **차원** 계층 창
- **데이터 편집기** 창

단계는 둘 이상의 워크플로에 속할 수 있으므로, 단계의 이동 경로에는 소유 워크플로 하나를 지정하는 대신 `Project › Step › name`이 표시됩니다.

### 키보드 및 화면 낭독기 접근

클릭할 수 있는 세그먼트는 일반 컨트롤입니다. **Tab** 키로 세그먼트로 이동하고 **Enter** 또는 **Space** 키로 포커스된 세그먼트를 활성화하므로, 계층 구조를 위로 이동하는 데 마우스가 전혀 필요하지 않습니다. 각 세그먼트는 버튼으로 안내되고, 마지막 세그먼트는 현재 페이지로 안내되며, `›` 구분 기호는 소리 내어 읽지 않고 건너뜁니다.

### 저장되지 않은 변경 사항이 있는 데이터 편집기 나가기

데이터 편집기는 이동 경로를 통해 이동하기 전에 확인을 요청하는 유일한 창입니다. 진행 중인 편집 내용이 있을 때 세그먼트를 선택하면 *변경 사항을 저장하지 않고 데이터 편집기를 닫으시겠습니까?*라는 **저장되지 않은 변경 사항** 프롬프트가 표시되며, 그래도 나가려면 **편집기 닫기**를 선택합니다. 프롬프트를 취소하면 변경 사항이 그대로 유지된 채 편집기에 남아 있습니다.

이는 편집기 자체의 **닫기** 버튼이 표시하는 것과 같은 프롬프트이므로, 확인 없이 작업 내용을 버리고 데이터 편집기를 나가는 경로는 없습니다.

## 공유 가능한 링크

주소 표시줄에는 항상 맨 앞에 있는 창이 표시됩니다. 워크플로를 열면 URL이 해당 워크플로의 링크가 되고, 테이블을 열면 테이블의 링크가 됩니다. 이 링크가 공유의 단위입니다.

**보고 있는 대상을 공유하려면** 브라우저 주소 표시줄에서 URL을 복사하여 보내십시오. 해당 프로젝트에 액세스할 수 있는 사람은 누구나 같은 보기를 열 수 있습니다. 북마크해 두면 나중에도 계속 작동합니다.

### 누군가 링크를 열면 일어나는 일

링크를 열거나 새로 고치면 창 하나만이 아니라 **상위 컨텍스트**가 복원됩니다. 워크플로 링크는 해당 프로젝트도 함께 다시 열므로, 창 하나만 따로 떠 있는 상태가 아니라 탭 표시줄에서 프로젝트를 사용할 수 있는 상태로 도착합니다. 직접 탐색해서 도달했을 때와 같은 위치입니다.

### 링크 형식

링크는 프로젝트 우선 형식입니다. 프로젝트가 먼저 오고, 그 안의 개체가 `~`로 구분되어 이어집니다.

```
#p~my-project                        a project
#p~my-project~w~<workflow>           a standard workflow
#p~my-project~c~<workflow>           a workflow in the Visual Workflow Designer
#p~my-project~w~<workflow>~s~<step>  a step within a workflow
#p~my-project~t~<table>              a table in the Table Explorer
#p~my-project~d~<dimension>          a dimension hierarchy
#p~my-project~e~<editor>             a Data Editor
#home                                the Home landing page
```

프로젝트에 스키마 이름이 있으면 링크에 그 이름을 사용하므로(위의 `my-project`) 링크가 읽기 쉽고 안정적입니다. 그렇지 않으면 프로젝트의 식별자를 사용합니다. 두 형식 모두 같은 프로젝트를 엽니다.

<Aside type="note">
프로젝트 우선 형식이 도입되기 전에 만든 링크도 계속 작동합니다. 이전의 `?p=…&t=…` 형식 링크도 올바른 보기를 계속 열며, 주소 표시줄은 처음 탐색할 때 현재 형식으로 자동 업데이트됩니다.
</Aside>

### 링크를 열 수 없는 경우

링크의 개체가 이후에 삭제되었거나 해당 프로젝트에 대한 액세스 권한이 없으면, 링크는 실패하지 않고 해당 보기 없이 앱을 엽니다. 주소 표시줄에 링크가 있는 창을 닫으면 URL이 해당 창을 소유한 프로젝트로 돌아가므로, 주소 표시줄이 더 이상 열려 있지 않은 대상을 가리키는 일은 없습니다.
