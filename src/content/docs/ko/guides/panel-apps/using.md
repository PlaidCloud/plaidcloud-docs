게시된 모든 앱은 **내 Panel 앱** 화면에 **런타임**, **상태**, **슬러그**, 타임스탬프와 함께 표시됩니다. 가장 왼쪽 열에서는 앱을 열 수 있고, 나머지 행 아이콘으로는 실수로 인한 변경을 막기 위해 앱을 잠그거나, 앱을 편집하거나, 제거할 수 있습니다. 서버 앱의 경우 다시 빌드하고, 로그를 보고, 사용 지표를 볼 수도 있습니다. 열기 아이콘은 앱의 런타임에 따라 달라지므로 WASM 앱과 서버 앱을 한눈에 구분할 수 있습니다.

## 빌드 상태(서버 앱)

서버 앱의 **상태** 열에는 빌드 진행 상황이 표시되며, 빌드가 진행되는 동안에는 목록이 자동으로 새로 고쳐집니다.

- **빌드 중…** — PlaidCloud가 리포지토리를 컨테이너로 빌드하고 있습니다. 앱에는 아직 URL이 없습니다.
- **준비됨** — 빌드가 성공했습니다. 앱의 URL이 활성화되고 해당 행에 **열기** 아이콘이 나타납니다.
- **실패** — 빌드가 완료되지 않았습니다. 진입점과 브랜치를 확인한 다음 앱을 편집하여 다시 게시하십시오.

WASM 앱은 빌드 단계가 없으며 게시되는 즉시 사용할 수 있습니다.

## 서버 앱 다시 빌드하기

서버 앱의 행에서 **다시 빌드** 아이콘을 클릭하면 설정을 변경하지 않고 앱을 다시 빌드하고 배포합니다. PlaidCloud가 동일한 브랜치와 진입점을 다시 빌드하는 동안 앱의 상태는 **빌드 중…** 상태로 돌아갔다가, 새 빌드가 활성화되면 다시 **준비됨**으로 바뀝니다.

종속성이 변경되었거나, 기본 이미지가 업데이트되었거나, 일시적인 오류로 빌드가 실패한 경우 **다시 빌드**를 사용하십시오. 서버 앱을 편집하고 저장해도 다시 빌드되지만, 다시 빌드하려고 편집 양식을 열 필요는 없습니다.

변환된 Alteryx 앱을 위해 생성된 입력 양식인 [App Runner](/ko/guides/workflows/use-converted-alteryx-apps/#앱을-최신-상태로-유지) 앱의 경우, **다시 빌드**와 편집 저장은 먼저 생성된 파일을 현재 App Runner 버전으로 새로 고친 다음 빌드합니다. PlaidCloud 자체가 업데이트될 때도 잠기지 않은 모든 App Runner 앱에 대해 같은 작업이 수행됩니다. 잠긴 앱은 잠금을 해제한 후 **다시 빌드**해야 합니다.

## 앱 잠그기

앱의 행에서 **잠금** 아이콘을 클릭하면 실수로 인한 변경으로부터 앱을 보호할 수 있습니다. 앱이 잠겨 있는 동안에는 다음과 같이 동작합니다.

- **편집**, **제거**, **다시 빌드**가 실행되지 않으며 앱이 잠겨 있다고 알려 줍니다.
- **서버 앱의 브랜치에 푸시해도 앱이 다시 빌드되지 않습니다.** 앱의 잠금을 해제할 때까지 자동 다시 빌드가 건너뜁니다. 건너뛴 푸시에서는 빌드가 실행되지 않으므로 앱의 빌드 로그에 새 항목이 나타나지 않습니다. 변경 사항을 반영하려면 잠금을 해제한 후 다시 푸시하거나 **다시 빌드**를 사용하십시오.
- 앱 열기, 로그 보기, 사용 지표 보기는 모두 계속 사용할 수 있습니다. 잠금은 변경만 막을 뿐 뷰어를 막지 않습니다.

아이콘을 다시 클릭하면 잠금이 해제됩니다. 아이콘은 앱의 현재 상태를 보여 줍니다. 잠겨 있으면 닫힌 모양이고, 잠겨 있지 않으면 열린 모양입니다.

잠금은 워크플로 및 워크플로 단계의 잠금과 마찬가지로 잘못된 편집, 의도하지 않은 삭제, 시연 중인 앱에 대한 Git 푸시 같은 실수를 막기 위한 장치입니다. 보안 제어 수단이 **아닙니다**. Panel 앱을 편집할 수 있는 사용자는 누구나 잠금을 해제할 수도 있습니다.

> 잠금이 적용되지 않는 경우가 두 가지 있습니다. 잠그는 시점에 **이미 진행 중인 빌드**는 그대로 완료되어 배포됩니다. 또한 **WASM** 앱의 파일은 해당 문서 계정에 있으므로, 그 파일을 교체하면 잠긴 레코드를 건드리지 않고도 실행 중인 앱이 변경됩니다.

## 앱 열기

준비된 앱의 행 맨 앞에 있는 **열기** 아이콘을 클릭하면 새 탭에서 앱이 실행됩니다.

- 서버 앱은 `https://<your-tenant-host>/serve/<slug>/`에서 제공됩니다.
- **열기** 아이콘은 서버 앱이 **준비됨** 상태가 된 후에만 나타납니다.

서버 앱은 리소스를 절약하기 위해 유휴 상태에서 0으로 축소되므로, 유휴 기간 이후 처음 열 때는 앱을 다시 시작해야 합니다. 이 과정에서는 빈 탭 대신 앱 이름, 진행률 표시기, 워크스페이스 세부 정보가 포함된 **PlaidCloud 로딩 화면**이 표시됩니다. 앱이 준비되면 자동으로 나타나며(보통 몇 초, 콜드 스타트의 경우 최대 1분 정도 걸립니다), 이후 다시 유휴 상태가 될 때까지 정상적으로 응답합니다.

> 앱이 시작되지 않으면 로딩 화면이 계속 돌지 않고 **다시 시도** 버튼이 있는 **"이 앱이 시작되지 않았습니다"** 메시지로 바뀝니다. 이 문제가 계속되면 앱을 편집하여 진입점과 브랜치를 확인하고 다시 게시하거나, PlaidCloud 관리자에게 문의하십시오.

### 모양

서버 Panel 앱은 기본적으로 PlaidCloud의 최신 **FAST** 디자인을 사용하지만, 기존 CSS가 Panel의 기본 스타일에 의존하는 경우 앱의 **디자인** 설정에서 Panel의 **기본값** 스타일로 되돌릴 수 있습니다. 라이트, 다크 또는 뷰어가 전환할 수 있는 라이트/다크 스위치 같은 테마는 앱의 템플릿에서 설정합니다. 패턴은 만들기 가이드의 [테마 설정하기](/ko/guides/panel-apps/creating/#테마-설정하기-라이트-다크-또는-전환)를 참조하십시오. 앱의 테이블이나 사용자 지정 스타일이 밝은 배경에 맞춰져 있다면 라이트로 고정하십시오.

## 로그 보기(서버 앱)

서버 앱의 행에서 **로그 보기** 아이콘을 클릭하면 로그 뷰어가 열립니다. (WASM 앱은 브라우저에서만 실행되며 서버 로그가 없으므로 이 아이콘은 서버 앱 행에만 나타납니다.)

뷰어에는 두 개의 탭이 있습니다.

- **런타임**(먼저 표시됨) — 실행 중인 앱 자체의 출력입니다. 앱이 기록하거나 출력한 모든 내용과 처리되지 않은 오류가 포함됩니다. 앱이 0으로 축소된 후에도 보관되므로 이전 세션의 동작을 검토할 수 있습니다.
- **빌드** — 앱의 컨테이너를 빌드하는 동안의 출력입니다. 빌드가 **실패**로 표시되는 *이유*(예: 설치되지 않은 종속성)를 확인하는 데 사용하십시오.

각 탭에서는 **정보 / 경고 / 오류** 필터, **다음 시점 이후 로그** 시간 범위(최근 1시간부터 최대 30일 또는 전체), **새로 고침** 버튼, 새 항목을 폴링하는 **자동 새로 고침**을 사용할 수 있습니다. 실행 중인 앱이나 진행 중인 빌드를 지켜볼 때 유용합니다. 최신 항목이 먼저 나열됩니다.

> 빌드 출력을 캡처하지 못한 경우 빌드 탭은 빈 상태로 표시되는 대신 그 이유를 설명하는 짧은 메모를 보여 줍니다.

### 전체 로그 메시지 읽기

로그 테이블은 목록을 읽기 쉽게 유지하기 위해 긴 줄을 잘라서 표시합니다. 로그 행을 선택하면 테이블 옆에 항목의 전체 메시지를 보여 주는 **세부 정보 창**이 열립니다. 긴 오류 메시지나 전체 스택 트레이스처럼 테이블에 다 표시되지 않는 내용을 잘리지 않게 읽는 가장 쉬운 방법입니다.

### 로그 줄 복사하기

여러 로그 행을 한 번에 선택하고 **복사**를 클릭하여 클립보드에 넣을 수 있습니다. 앱을 디버깅하면서 AI 어시스턴트와의 채팅에 로그를 붙여넣거나, 팀 또는 PlaidCloud 지원팀에 보내는 메시지에 붙여넣을 때 유용합니다.

### 로그 줄을 발생시킨 사용자

앱에서 뷰어를 로그인시키는 경우, 각 로그 줄에는 해당 세션에서 발생한 **사용자**가 태그로 표시되므로 어떤 뷰어에게 특정 오류나 경고가 발생했는지 알 수 있습니다. 태그 지정은 최선의 노력으로 이루어집니다. 일부 프레임워크 및 시작 로그 줄은 뷰어가 관여하기 전에 실행되므로 사용자가 표시되지 않을 수 있습니다.

## 사용 지표(서버 앱)

서버 앱의 행에서 **로그 보기** 옆에 있는 **Usage Metrics** 아이콘을 클릭하면 앱이 어떻게 사용되고 있는지 확인할 수 있습니다. 이 보기에는 다음 내용이 요약됩니다.

- **고유 사용자** — 앱을 연 서로 다른 사람의 수입니다.
- **세션** — 앱이 열린 횟수입니다.
- **평균 및 중앙값 세션 시간** — 한 번 방문했을 때 대략 얼마나 머무는지를 나타냅니다.
- **마지막 사용** — 앱이 가장 최근에 열린 시점입니다.

요약 아래에는 **사용자별** 및 **일별** 내역이 표시되므로, 누가 앱을 사용하고 있는지와 시간에 따른 사용 추세를 확인할 수 있습니다.

> 시간은 근사치입니다. 서버 앱은 아무도 사용하지 않을 때 유휴 상태가 되어 축소되므로 세션의 정확한 종료 시점이 항상 관찰되는 것은 아닙니다. 시간 수치는 정확한 측정값이 아니라 참고용으로 읽으십시오.

## 앱 편집하기

앱의 행에서 **연필** 아이콘을 클릭하면 앱을 편집할 수 있습니다. 편집 양식은 앱의 런타임에 맞게 표시됩니다.

**서버** 앱에서는 이름, 슬러그, 브랜치, 진입점, CPU, 메모리, 디자인, 유휴 시간, 공개 플래그, 임베디드 서비스 도메인, 메모를 변경할 수 있습니다. **Git 연결**은 앱을 만든 후에는 고정되며 읽기 전용으로 표시됩니다. 저장하면 앱이 다시 빌드되며, 새 빌드가 준비될 때까지 상태가 **빌드 중…** 상태로 돌아갑니다.

## 앱 제거하기

앱의 행에서 **빼기** 아이콘을 클릭한 다음 확인하십시오. 앱을 삭제하거나 게시를 취소할 때는 항상 먼저 확인을 요청합니다. 서버 앱을 제거하면 해당 빌드와 배포가 삭제되고, WASM 앱을 제거하면 정적 파일의 게시가 취소됩니다. 앱의 URL은 즉시 작동하지 않게 됩니다.

MCP 도구 `panel_deployment_manage`는 더 이상 게시 취소를 제공하지 않습니다. 대신 이 목록에서 앱을 제거하십시오.
