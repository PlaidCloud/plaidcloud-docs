프로젝트를 한 번에 하나씩 Lakehouse v1에서 Lakehouse v2로 옮길 수 있습니다. 같은 워크스페이스의 다른 프로젝트는 마이그레이션하기 전까지 계속 v1에서 실행되므로, 단일 프로젝트만 마이그레이션하고 나머지는 그대로 둘 수 있습니다.

마이그레이션은 프로젝트의 테이블과 그 위에 구축된 모든 항목(쿼리, 식, 뷰, Superset 데이터 세트, 계산된 열, 지표, 행 액세스 규칙)을 옮깁니다.

<Aside type="caution" title="마이그레이션 중 변경한 내용은 사라집니다">
마이그레이션은 실행이 시작되는 시점의 데이터를 그대로 복사합니다. 그 이후에 프로젝트에 기록된 모든 내용(워크플로 실행, 가져온 파일, 편집한 테이블)은 **옮겨지지 않으며** 마이그레이션된 사본에서 **복구할 수도 없습니다**. 프로젝트 자체의 워크플로 일정은 마이그레이션이 실행되는 동안 일시 중지되었다가 이후 복원되지만, 수동 실행이나 가져오기는 막지 않습니다. 마이그레이션 중에 워크플로를 시작하면 경고가 표시됩니다. 마이그레이션이 끝날 때까지 프로젝트 멤버가 프로젝트에 접근하지 않도록 안내하십시오.
</Aside>

<Aside type="caution" title="마이그레이션은 단방향입니다">
다시 마이그레이션해서 되돌리는 기능은 없습니다. [마이그레이션 실행 취소](#마이그레이션-실행-취소)에 설명된 대로, 실행 취소 기간 안에는 마이그레이션을 취소하고 프로젝트를 Lakehouse v1로 되돌릴 수 있습니다. 그 기간이 지나면 원본 데이터는 삭제됩니다.
</Aside>

## 시작하기 전에

- **프로젝트를 Lakehouse v2로 마이그레이션…** 은 프로젝트를 편집할 수 있는 멤버의 도구 메뉴에 표시됩니다. 프로젝트의 아키텍트만 마이그레이션할 수 있습니다. 마이그레이션의 시작, 예약, 취소, 실행 취소에는 모두 프로젝트에 대한 아키텍트 액세스가 필요합니다.
- 프로젝트에 대한 아키텍트 액세스가 필요하며, 프로젝트가 잠겨 있지 않아야 합니다.
- 요금제에 복사본을 위한 공간이 있어야 합니다. [저장 공간 검사](#저장-공간-검사)를 참조하십시오.
- 프로젝트를 열 수 있는 사용자는 누구나 준비 상태 검사를 실행할 수 있습니다.
- 먼저 준비 상태 검사를 실행하고 검사에서 거부한 항목을 모두 해결하십시오. 변환할 수 없는 프로젝트에서 마이그레이션을 시작하면 중간에 중단됩니다.
- 실행 중에 기록된 내용은 사라지므로, 실행하는 동안 프로젝트를 사용할 수 없다고 가정하고 계획하십시오.
- 다른 프로젝트가 데이터 공유를 통해 이 프로젝트의 테이블을 읽는 경우, 해당 프로젝트를 먼저 마이그레이션하거나 공유를 제거하십시오. 다른 프로젝트가 데이터 공유로 읽는 프로젝트는 그 프로젝트들보다 나중에 마이그레이션됩니다.

## 마이그레이션 준비 상태 확인

준비 상태 검사는 무엇이든 확정하기 전에 프로젝트에 어떤 일이 일어날지 보고합니다. 아무것도 변경하지 않습니다.

<Steps>

1. **도구** 메뉴를 엽니다.

2. **마이그레이션 준비 상태 확인…** 을 선택합니다.

3. 프로젝트를 선택합니다.

</Steps>

프로젝트가 이미 Lakehouse v2에 있으면, 검사는 그 사실과 마이그레이션할 항목이 없다는 것을 알려 줍니다.

보고서는 각 영역을 다음 중 하나로 표시합니다.

| 상태 | 의미 |
| --- | --- |
| **지우기** | PlaidCloud가 해당 영역을 검사했으며 아무것도 발견하지 못했습니다. |
| **검토 필요** | 무언가가 변경되며, 실행 전에 이를 확인해야 합니다. |
| **차단됨** | 해결되기 전에는 마이그레이션을 시작할 수 없습니다. |
| **마이그레이션 중 확인** | 마이그레이션이 실행되는 동안 검사하는 영역이므로, 사전에 정상으로 표시되지 않습니다. |

영역은 테이블, 뷰, 단계, 대시보드, 데이터 공유, 용량입니다. 모든 결과 항목에는 쉬운 설명이 함께 제공되며, 제안된 재작성 방법이 있으면 함께 표시됩니다.

### 준비 상태 검사가 거부하는 항목

| 거부 사유 | 이유 |
| --- | --- |
| Lakehouse v2에 대응하는 유형이 없는 열 | 마이그레이션은 열을 조용히 텍스트로 바꾸는 대신 거부합니다. 프로젝트에서 열의 유형을 변경한 다음 검사를 다시 실행하십시오. |
| 대상 Lakehouse v2 웨어하우스를 확인할 수 없음 | 마이그레이션을 실행하는 서비스에서 워크스페이스의 v2 Lakehouse가 보이지 않습니다. 이는 프로젝트에서 해결할 수 있는 문제가 아니라 관리 측면의 문제입니다. |
| 스토리지 버킷의 삭제 보호를 확인할 수 없음 | 실행 취소 기간이 이에 의존하므로, 삭제 보호가 없으면 마이그레이션이 시작되지 않습니다. |

JSON 열은 마이그레이션됩니다. 이전 릴리스에서는 JSON 열을 거부했지만 이제는 지원됩니다.

## 저장 공간 검사

실행을 시작하기 전에 PlaidCloud는 요금제에 복사본을 위한 공간이 있는지 확인합니다.

- **저장 공간 한도가 있는 요금제**에서는 마이그레이션된 사본이 한도 안에 들어가지 않으면 실행이 거부됩니다. 진행 중인 다른 마이그레이션도 한도에 포함됩니다.
- **추가 저장 공간에 대해 요금이 청구되는 요금제**에서는 예상 초과분에 대한 경고와 함께 실행이 시작됩니다.

## v2에서 체험

**v2에서 체험…** 은 실제 프로젝트를 마이그레이션하기 전에 결과를 확인할 수 있도록 Lakehouse v2에 프로젝트의 비공개 평가용 사본을 만듭니다. 평가용 사본에서는 일정과 센서가 꺼지고 ERP 전기는 시뮬레이션 모드로 동작합니다. SFTP, 이메일, REST 게시처럼 PlaidCloud 외부에 기록하는 단계는 확인하기 전에 경고로 나열됩니다. **평가판 시작**을 선택하면 사본이 만들어집니다. 이미 평가판이 있는 프로젝트에는 **기존 평가판 열기**와 **평가판 교체…** 옵션이 표시됩니다.

## 마이그레이션 실행

<Steps>

1. **도구** 메뉴를 엽니다.

2. **프로젝트를 Lakehouse v2로 마이그레이션…** 을 선택합니다. 창에 워크스페이스의 마이그레이션 실행 목록이 표시됩니다.

3. 새 실행을 시작하고 프로젝트를 선택합니다.

4. 창에 표시된 준비 상태 보고서를 읽고 명시된 각 결과 항목을 확인합니다. 결과 항목을 수락하면 해당 특정 항목에 대해서만 수락한 것입니다.

5. **마이그레이션 시작**을 선택하거나, **예약된 시간에 시작**을 선택하고 시간을 설정한 다음 **마이그레이션 예약**을 선택합니다. 예약된 마이그레이션은 프로젝트에 배너를 표시하며, 시작되기 전에 취소할 수 있습니다. 마이그레이션이 시작되면 PlaidCloud는 준비 상태, 호환성, 용량, 사용자의 권한을 다시 확인합니다.

6. 실행을 시작합니다. 진행 대화 상자에 복사 및 검사되는 각 테이블이 표시됩니다. 프로젝트의 활성화된 워크플로 일정은 실행하는 동안 일시 중지됩니다. 대화 상자를 닫았다가 실행 목록에서 다시 열 수 있으며, 어느 경우든 실행은 계속됩니다.

</Steps>

실행이 프로젝트를 Lakehouse v2로 전환하기 시작하면 중지할 수 없습니다. 전환 자체가 도중에 실패하면 실행에는 **재개**를 제공하는 대신 **지원팀에 문의하십시오. 다시 시도하지 마십시오.** 가 표시됩니다. 지원팀에 문의하고 실행은 현재 상태 그대로 두십시오.

실행이 끝나면 프로젝트가 Lakehouse v2에 바인딩되어 쿼리가 v2를 사용하기 시작하고, 일시 중지된 일정이 복원됩니다. 마이그레이션 중에 편집하거나 삭제한 일정은 편집하거나 삭제한 상태 그대로 유지되며 보고서에 이름이 표시됩니다. 원래의 Lakehouse v1 사본은 프로젝트에서 사용할 수 없는 상태로 실행 취소 기간 동안 보관됩니다. 마이그레이션이 끝나거나 실패하면 메시지와 이메일로 알림을 받습니다.

### 실패한 마이그레이션

실패한 마이그레이션에는 실패한 이유와, 그 이후에는 소스에 대한 쓰기가 사라지는 시각이 표시됩니다. **재개**를 선택하면 계속할 수 있습니다. Lakehouse v2에서 실행할 수 없는 뷰는 실행을 중단하지 않고 건너뛰며 목록으로 표시됩니다.

## 변경 내용

마이그레이션 후에는 해당 실행의 **변경 내용…** 을 엽니다. 여기에는 각 테이블이 복사됨, 명시된 누락과 함께 복사됨, 건너뜀, 실패 중 어느 상태인지가 행 수와 사유와 함께 나열되며, 건너뛴 뷰, 실행 중에 소스에서 만들어지거나 삭제된 테이블, 일시 중지 후 복원된 일정도 함께 표시됩니다.

## 주 단위 그룹화가 하루씩 이동합니다

Lakehouse v2는 한 주를 **일요일**에 시작합니다. Lakehouse v1은 **월요일**에 시작했습니다.

주 단위로 그룹화한 모든 항목이 그에 따라 바뀌며, 오류나 경고는 표시되지 않습니다. 6월 14일 일요일 날짜의 행은 v1에서는 6월 8일 월요일에 시작하는 주에 속했습니다. v2에서는 6월 14일 일요일에 시작하는 주에 속합니다.

이 경계 양쪽의 합계가 이동합니다. 주간 차트, 주간 요약 테이블, 주 단위로 그룹화한 보고서는 모두 계속 동작하지만 이전과 다른 숫자를 표시합니다. 마이그레이션 후에는 의존하는 모든 주간 수치를 확인하고, 실수가 아니라 하루 단위의 이동이 발생한 것으로 예상하십시오.

## 이전되지 않는 항목

데이터는 마이그레이션됩니다. 이전 엔진 위에 구축된 일부 항목과 열 선언 방식의 일부 세부 사항은 이전되지 않습니다.

| 항목 | 동작 |
| --- | --- |
| 스냅샷 기록, 타임 트래블, 플래시백 | 이전되지 않습니다. 마이그레이션된 테이블은 새 기록으로 시작하므로 마이그레이션 이전 시점의 프로젝트를 쿼리할 수 없습니다. |
| 테이블 브랜치 및 태그 | 기존 브랜치와 태그는 이전되지 않습니다. |
| `VARCHAR(n)` 길이 제한 | 길이 제한이 제거됩니다. 텍스트 열은 제약 없는 텍스트가 되며, 기존 값은 영향을 받지 않습니다. |
| 좁은 정수 너비 | 작은 정수 유형은 32비트 정수가 됩니다. 값은 영향을 받지 않습니다. |
| 타임스탬프의 소수 초 정밀도 | 선언된 정밀도가 제거됩니다. |
| 공간, 지오메트리, 비트맵 열 | 마이그레이션되지만 자동 값 비교에서는 제외되므로 직접 확인하십시오. |
| 바이너리, 배열, 맵 열 | 마이그레이션되지만 자동 값 비교에서는 제외되므로 직접 확인하십시오. |
| JSON 열 | 유형이 유지된 채 마이그레이션됩니다. 정확하게 저장하기에는 너무 큰 JSON 내부의 숫자는 배정밀도로 저장되며 보고됩니다. |

<Aside type="caution" title="매우 큰 부호 없는 정수">
9,223,372,036,854,775,807을 초과하는 값이 들어 있는 부호 없는 64비트 정수 열은 Lakehouse v2에서 표현할 수 없으며, 이러한 값은 거부 사유로 보고되지 않습니다. 프로젝트가 이 한도에 가까운 부호 없는 정수를 저장한다면 마이그레이션 전후에 확인하십시오.
</Aside>

## 마이그레이션 실행 취소

실행이 완료된 후 실행 취소 기간 동안에는 원래의 Lakehouse v1 데이터가 손상되지 않은 채 프로젝트에서 분리되어 보관됩니다. **마이그레이션 실행 취소…** 는 이 기간 안에 프로젝트를 Lakehouse v1로 되돌립니다. 프로젝트에 대한 아키텍트 액세스가 필요합니다.

실행 취소를 확인하려면 프로젝트 이름을 입력해야 합니다. **Lakehouse v2로 전환한 이후 프로젝트에 가한 모든 변경 내용이 사라집니다.** 실행 취소가 진행되는 동안 진행 상황이 표시됩니다. 실행 취소가 거부되면 사유(예: 실행 취소 기간이 종료됨)가 표시됩니다.

마이그레이션 후 결과가 잘못된 것처럼 보이면 사용하십시오. 이동이 예상되는 주간 수치는 제외합니다.

실행 취소 기간이 지나면 원본 데이터가 삭제되고 마이그레이션이 확정됩니다.

## 마이그레이션 후

이미 열려 있던 세션은 종료될 때까지 처음 시작한 사본을 계속 읽습니다. 특히 오래 지속되는 Panel 애플리케이션 세션은 다시 시작할 때까지 이전 데이터를 계속 제공합니다. 마이그레이션 후에는 장시간 실행되는 세션을 다시 시작하여 Lakehouse v2를 사용하도록 하십시오.
