테이블 탐색기는 필터링, 요약 등의 기능이 기본 제공되는 강력하고 접근하기 쉬운 데이터 탐색 도구로, 
대규모의 복잡한 데이터를 다루는 작업을 수월하게 만들어 줍니다.

테이블 탐색기는 어떤 크기의 데이터 세트에서도 탐색을 지원하므로 데이터가 아무리 늘어나도 같은 도구를 사용할 수 있습니다. 또한 필요한 데이터를 정확히 찾아낼 수 있도록 
포인트 앤 클릭 필터링과 고급 필터 기능을 함께 제공합니다. 가장 좋은 점은 PlaidCloud에서 테이블이나 뷰가 있는 어디에서든 
해당 테이블과 뷰를 클릭해 테이블 탐색기로 탐색할 수 있다는 것입니다. 완전히 통합되어 있어 데이터 액세스가 클릭 한 번이면 됩니다.

`Grid` 뷰는 데이터를 표 형태로 보여 줍니다. `Details` 뷰는 각 열의 요약, 고유 값 개수, 모든 열의 프로파일링 통계를 제공합니다.

필터링된 집합에서 데이터를 바로 내보낼 수 있으며, 필터를 저장하여 다른 사람과 공유할 수도 있습니다. 마지막으로 필터와 열 설정을 
워크플로 `Extract` 단계로 바로 저장할 수 있습니다.


## Grid 뷰

Grid 뷰는 데이터를 표 형태로 보여 줍니다.


### 행 제한 설정

기본적으로 행 제한은 5,000행으로 설정되어 있습니다. 하지만 이 값을 조정하거나 완전히 해제할 수 있습니다.

표 하단에는 표시된 행 수와 데이터 세트의 전체 크기가 표시됩니다. 이 정보는 세 가지 핵심 정보를 제공합니다.
 1. 적용된 행 제한에 따라 현재 표시된 행 수
 2. 필터를 적용한 후의 전체 데이터 크기
 3. 필터를 적용하지 않은 전체 데이터 크기

<Aside type="caution">더 큰 데이터(예: 수백만 행)를 볼 때는 행 제한 기능을 해제하지 않도록 주의하십시오. 브라우저가 느려질 수 있습니다. 대신 필터를 사용하여 데이터를 찾아 보십시오.</Aside>


### 상위 행 또는 무작위 행 선택

행 제한 옆에는 그리드를 채우는 행을 *어떤 기준으로* 가져올지 제어하는 **상위 / 무작위** 선택기가 있습니다.

 * **상위**(기본값)는 테이블의 첫 번째 행들을 반환합니다. 가장 빠른 옵션이며 간단히 훑어보고 싶을 때 적합합니다.
 * **무작위**는 테이블 전체에서 추출한 빠른 무작위 샘플을 반환하므로, 미리 보기가 처음 부분만이 아니라 데이터의 전체 범위를 반영합니다. 첫 번째 행들이 대표성을 갖지 않는 대규모 테이블에서 데이터 품질을 표본 점검할 때 유용합니다.

무작위 샘플링은 스토리지 엔진에 내장된 샘플링을 사용하므로 매우 큰 테이블에서도 빠르게 동작합니다. 요청한 수만큼의 행을 테이블 전체에서 무작위로 추출하여 반환하며, 테이블의 행이 제한보다 적으면 모든 행을 반환합니다. 새로 고칠 때마다 다른 샘플이 나옵니다. 이 선택기는 그리드 미리 보기에만 적용되며 저장된 뷰, 추출, 다운로드, 보고되는 행 수에는 영향을 주지 않습니다. 무작위를 사용하려면 행 제한이 활성화되어 있어야 합니다.

<Aside type="note">열 머리글을 기준으로 정렬하면 현재 가져온 행만 정렬됩니다. 따라서 무작위와 함께 정렬하면 테이블 전체가 아니라 샘플링된 행만 정렬됩니다.</Aside>


### 로컬 정렬과 전역 정렬

Grid 뷰에서는 열 머리글을 클릭하여 해당 열을 기준으로 데이터를 정렬할 수 있습니다. 하지만 이 방법은 이미 가져온 데이터 세트만 정렬하며 
전체 데이터 세트를 기준으로 정렬하지 않습니다. 가져온 데이터에 전체 데이터 세트가 들어 있다면 이 차이는 문제가 되지 않지만, 전체 데이터 세트가 브라우저에 표시되는 것보다 크다면 원하는 정렬 결과가 아닐 수 있습니다.

브라우저에 표시될 제한된 데이터를 가져오기 전에 전역 데이터 세트를 정렬하려면, `Details` 뷰에서 각 열 위쪽의 `Sort` 아이콘을 클릭하여 열에 정렬을 적용할 수 있습니다. 전역 정렬 방식의 또 다른 장점은 여러 정렬을 적용하고 정렬 방향도 섞어서 사용할 수 있다는 것입니다.


## 빠른 참조 열 목록

기본적으로 테이블 또는 뷰의 모든 열이 테이블 탐색기 창의 왼쪽에 표시됩니다. 이 열 목록은 
열 목록 전환 버튼으로 켜고 끌 수 있습니다.

열 목록은 다음과 같은 유용한 빠른 액세스 기능을 제공합니다.
 * 항목을 두 번 클릭하면 `Grid` 또는 `Details` 뷰의 해당 열로 이동합니다
 * 표시 여부 확인란으로 열의 표시 여부를 제어합니다
 * 다중 선택과 마우스 오른쪽 클릭을 사용하여 여러 열을 한 번에 포함하거나 제외합니다
 * 데이터 유형 아이콘으로 각 열의 데이터 유형을 빠르게 확인합니다
 * 전체 열 수를 확인합니다


## 행 액세스 제한

프로젝트 아키텍트나 테넌트 관리자에게는 도구 모음의 **행 액세스** 버튼이 탐색 중인 테이블의 [행 액세스](/ko/administration/access/managing-security-groups-and-assignments/#행-액세스-관리)를 엽니다. 테이블에 이미 행 제한이 있으면 버튼에 배지가 표시됩니다. 열의 패싯 메뉴에도 같은 화면을 해당 열 기준으로 여는 **이 열로 행 제한…** 이 있으며, 이미 행을 제한하는 열에서는 **이 열로 제한된 행 — 편집…** 으로 표시됩니다.

사용자 본인의 권한 부여로 인해 그리드에 로드된 데이터가 필터링되는 경우 도구 모음에 **액세스 권한에 따라 행이 제한됨**이 표시되며, 필터링될 다운로드를 시작할 때도 이를 알려 줍니다. 그리드, 열 패싯, 다운로드에는 모두 사용자가 볼 수 있는 행만 포함됩니다. [제한된 멤버에게 표시되는 내용](/ko/administration/access/managing-security-groups-and-assignments/#제한된-멤버가-보는-내용)을 참조하십시오.

## Details 뷰

`Details` 뷰는 데이터를 높은 수준에서 효율적으로 보여 주며, 
포인트 앤 클릭 작업으로 필요한 정보로 빠르게 좁혀 갈 수 있는 도구를 제공합니다.

<Aside>뷰에서는 열 요약이 자동으로 생성되지 않습니다. 열 새로 고침 버튼을 클릭하면 세부 정보를 계산할 수 있습니다.</Aside>


### 열 데이터와 고유 값 개수

표시하도록 설정된 각 열이 표시됩니다. 열 요약에는 개수 기준으로 상위 1,000개의 고유 값이 표시됩니다. 표시되는 고유 값의 
수는 `Detailed Rows Displayed` 선택 항목을 다른 값으로 바꿔 조정할 수 있습니다.

숫자 열에는 값 목록 대신 통계가 표시됩니다. 최솟값, 최댓값, 평균, 합계, 표준 편차, 분산입니다. Null은 이러한 통계에서 제외되며, null만 있는 열에는 대신 값 개수가 표시됩니다. 이는 StarRocks를 포함한 모든 Lakehouse 엔진에 적용됩니다.

요약을 계산하는 데 너무 오래 걸리는 열에는 **프로필 시간 초과**가 표시되고, 요약을 로드할 수 없는 열에는 **프로필 실패**가 표시됩니다. 배지 위에 마우스를 올리면 이유를 볼 수 있습니다. 필터에 문제가 있으면 해당 내용이 표시되고, PlaidCloud 측 오류에는 PlaidCloud 팀이 추적에 사용할 수 있는 ID가 포함됩니다. 다시 시도하려면 해당 열의 새로 고침 버튼을 사용하십시오.


### 포인트 앤 클릭 필터 관리

각 열은 열 위쪽의 필터 전환을 활성화하여 포인트 앤 클릭 필터링을 사용할 수 있습니다. 결과 데이터에 
포함할 열의 항목을 선택합니다. 다중 선택이 지원됩니다.

필터를 적용한 후에는 일부 항목을 제거하거나, 다른 모든 필터는 유지한 채 해당 열의 필터만 해제하고 싶을 수 있습니다. 이는 
열 필터 버튼의 드롭다운에서 항목의 선택을 해제하거나 맨 위의 모두 지우기 옵션을 선택하여 수행합니다.


### 요약 관리

`Summarize` 버튼을 `On`으로 전환하면 데이터를 요약할 수 있습니다. `Summarize` 버튼이 활성화되면 각 열에 적용할 
요약 유형이 표시됩니다. 각 열에 원하는 요약 유형을 조정합니다.

원하는 요약을 모두 설정했으면 데이터를 새로 고치면 요약이 적용됩니다.

요약 유형의 예로는 Min, Max, Sum, Count, Count Distinct가 있습니다.


### 고유 값 찾기

`Distinct` 버튼을 활성화하면 데이터를 고유한 레코드 집합으로만 줄일 수 있습니다. `Distinct` 버튼이 활성화되면 각 열에 *Distinct* 확인란이 나타납니다. 데이터 세트에서 해당 열의 고유성을 정의하지 *않는* 열의 선택을 해제하십시오. 예를 들어 고객 주문 테이블에서 고유한 고객 집합을 찾으려면 고객 주문 번호까지 포함하지 말고 고객 열만 선택해야 합니다.

<Aside type="caution">고유 레코드를 결정하는 데 너무 많은 열을 포함하면 실제보다 훨씬 많은 고유 결과가 있는 것처럼 보입니다.</Aside>


### 열 프로파일링 통계

모든 열은 데이터 유형에 관계없이 열 정보 하단에 프로파일링 통계를 표시합니다.

[Vector](/ko/guides/data/vector-data-type/) 열은 유일한 예외입니다. 프로파일링에서 제외되며 값 목록도 만들어지지 않습니다. 최솟값, 평균, 상위 값 목록은 임베딩에 대해 아무 의미가 없으며, 값 목록은 각각 수백 개의 숫자로 이루어진 원시 배열이 되기 때문입니다.

정수 및 숫자 열은 **필터링된** 전체 데이터 세트를 기준으로 계산한 다음 통계를 표시합니다.
 * 최솟값
 * 최댓값
 * 평균
 * 표준 편차
 * 합계

숫자, 텍스트, 날짜 등 모든 열은 **필터링되지 않은** 전체 테이블을 기준으로 계산한 다음 통계도 표시합니다.
 * `Null Count (All Rows)` — 전체 테이블의 null 값 개수
 * `Null % (All Rows)` — 전체 테이블에서 null 값이 차지하는 비율
 * `Blank Count (All Rows)` — 텍스트 열 전용입니다. 공백 값은 비어 있거나 공백 문자로만 이루어진 값이며, 공백을 제거한 후 판단하므로 null과는 구별됩니다.
 * `Blank % (All Rows)` — 전체 테이블에서 공백 값이 차지하는 비율
 * `Distinct % of Non-Null (All Rows)` — 실제로 값이 있는 행에서 고유 값이 차지하는 비율입니다. null은 고유 값 개수와 전체 개수에서 모두 제외되므로, 90%가 null이지만 값이 있는 항목이 모두 고유한 열은 10%가 아니라 100%로 표시됩니다.

<Aside type="note">`(All Rows)` 접미사는 이유가 있어서 붙어 있습니다. 이 다섯 가지 통계는 적용한 필터와 관계없이 항상 전체 테이블을 대상으로 하며, 현재 필터를 따르는 위의 최솟값, 최댓값, 평균, 표준 편차, 합계와 다릅니다. 하나의 패널에 범위가 다른 두 종류의 숫자가 있으므로, 같은 범위로 오해하지 않도록 레이블이 필요합니다.</Aside>

이러한 `(All Rows)` 통계는 AI나 샘플링 없이 서버 측에서 결정적으로 계산되므로, 같은 열은 항상 같은 숫자를 반환합니다. 행 수준 보안을 따르므로 볼 권한이 있는 행에 대해 계산된 통계만 표시됩니다. 계산에는 전체 테이블 쿼리가 한 번 더 필요하며, 다른 열 패싯과 같은 60초 제한 시간이 적용됩니다. 해당 쿼리가 시간 초과되어도 그리드의 나머지 부분에는 영향이 없습니다.


### 분포 형태

숫자 열의 경우 테이블 탐색기는 값이 어디에 모여 있는지뿐 아니라 어떻게 분포하는지도 보고합니다.

* `Skewness (All Rows)` — 열의 값이 평균의 한쪽으로 치우쳐 있는지, 평균을 중심으로 고르게 균형을 이루는지를 측정합니다. 0에 가까운 값은 값이 대체로 대칭이라는 뜻이고, 크게 양수이거나 음수이면 열의 한쪽 끝으로 긴 꼬리가 뻗어 있다는 뜻입니다. 평균과 표준 편차만으로는 드러나지 않는 형태, 예를 들어 소수의 매우 큰 값이 평균을 끌어올리는 반면 열의 대부분은 훨씬 낮은 값에 있는 경우를 확인할 수 있습니다.
* 각 숫자 열 통계 아래의 히스토그램은 열의 전체 범위를 10개의 동일한 너비 구간으로 나누어 값을 묶어 보여 주므로, 분포의 형태를 한눈에 볼 수 있습니다. 막대 위에 마우스를 올리면 해당 막대가 포함하는 정확한 값 범위와 그 범위에 속하는 행 수를 볼 수 있습니다.

다른 `(All Rows)` 통계와 마찬가지로 왜도(Skewness)와 히스토그램은 현재 필터와 관계없이 항상 전체 테이블을 대상으로 합니다. 값이 두 개 미만이거나 변동이 전혀 없는 열은 의미 있게 계산할 수 없으므로 왜도를 0이나 오류로 표시하지 않고 생략합니다. 전부 null인 열처럼 계산 가능한 범위가 없는 열에서는 히스토그램도 같은 방식으로 생략됩니다.


### 데이터 품질 레이더

테이블 탐색기는 더 자세히 살펴볼 만한 데이터를 표시하기 위해 모든 열에 대해 다섯 가지 자동 검사를 실행합니다.

* `Outliers` — 열의 나머지 값과 통계적으로 멀리 떨어진 숫자 값(평균에서 표준 편차 3배 초과)입니다.
* `Format` — 열의 나머지 부분에서 발견되는 우세한 패턴과 일치하지 않는 텍스트 값입니다. 예를 들어 거의 모든 값이 날짜인 열에 자유 텍스트 값이 몇 개 섞여 있는 경우입니다. 이 검사는 공백이 아닌 값이 100개 이상인 열에서만 실행되며, 하나의 패턴이 명확히 우세할 때(열 값의 95% 초과가 일치할 때)에만 불일치를 표시합니다.
* `Duplicates` — 모든 값이 고유해야 하는 테이블의 선언된 행 키에 속한 열에서 반복되는 값입니다. 이 검사는 행 키가 선언된 테이블에서만 실행되며, 테이블의 업데이트 키가 행 키로 사용됩니다.
* `Orphans` — 차원에 연결된 열의 값 중 해당 차원의 어떤 멤버와도 일치하지 않는 값입니다.
* `Constant` — 열의 null이 아닌 모든 값이 같은 경우로, 대개 해당 열에 유용한 정보가 없다는 뜻입니다.

이 검사는 위의 `(All Rows)` 통계와 마찬가지로 전체 테이블을 대상으로 실행되므로 현재 필터의 영향을 받지 않습니다.

무언가를 발견한 검사가 있으면 `Details` 뷰의 해당 열에 바로 배지가 나타나고, 완료되지 못한 검사에는 흐린 배지가 나타납니다. `Actions` 메뉴에서 `Data Quality Radar`를 열면 정상으로 나왔거나 해당하지 않는 검사까지 포함하여 모든 열에 대한 다섯 가지 검사의 순위별 요약을 볼 수 있습니다. 표시된 항목만 나오는 것이 아닙니다.

각 검사는 표시됨, 정상, 해당 없음, 시간 초과, 사용할 수 없음 중 하나의 결과를 독립적으로 보고합니다. 검사가 조용히 건너뛰어지는 일은 없으므로, 특정 검사에서 열에 판정이 없는 이유를 항상 확인할 수 있습니다.


### 상관관계

숫자 열의 경우 테이블 탐색기는 열의 값이 테이블의 다른 숫자 열과 얼마나 강하게 함께 움직이는지도 보고합니다.

* `Pearson r vs <column> (Complete Cases)` — 두 열이 직선 관계로 얼마나 강하게 함께 움직이는지를 -1(완전히 반대)에서 0(선형 관계 없음), +1(완전히 같은 방향)까지의 값으로 나타냅니다.
* `Spearman ρ vs <column> (Complete Cases)` — 관계가 직선이든 아니든 두 열이 순위 순서로 얼마나 강하게 함께 움직이는지를 나타냅니다. 일관되게 함께 증가하지만 직선이 아니라 곡선을 이루는 쌍은 Pearson보다 Spearman에서 더 높은 점수를 받을 수 있습니다.
* `Complete Cases (All Rows)` — 위의 계수가 실제로 계산된 행의 수입니다.

상관관계는 `Details` 뷰에 현재 표시된 다른 숫자 열 최대 10개를 대상으로, 비교하는 쌍뿐 아니라 그 모든 숫자 열에 값이 있는 행만 사용하여 계산됩니다. 그래서 범위가 `(All Rows)`가 아니라 `(Complete Cases)`로 표시됩니다. 이는 테이블의 더 좁은 리스트와이즈(listwise) 부분 집합이므로 `(All Rows)`라고 하면 계수가 설명하는 범위를 과장하게 됩니다. `Complete Cases (All Rows)` 개수 자체는 다른 `(All Rows)` 통계와 마찬가지로 전체 테이블을 기준으로 측정되므로 현재 필터의 영향을 받지 않지만, 표시되는 숫자 열을 바꾸면 달라집니다.

완전한 행이 최소 10개 이상이고 테이블의 10% 이상일 때만 상관관계가 표시되며, 근거가 너무 적으면 상관관계를 표시하지 않고 전체를 생략합니다. 짝이 되는 열 하나의 계수를 계산할 수 없는 경우(예: 해당 열에 변동이 없음)에는 전체 집합이 아니라 해당 행 하나만 제외됩니다.


## 데이터 복사

PlaidCloud에서 선택한 데이터를 복사하여 스프레드시트 같은 
다른 애플리케이션에 붙여 넣을 수 있으면 유용할 때가 있습니다.

오른쪽 위의 복사 버튼에서 데이터에 사용할 수 있는 여러 복사 옵션이 제공됩니다.
 * 모두 복사 - 모든 데이터를 클립보드에 복사합니다
 * 선택 항목 복사 - 선택한 데이터를 클립보드에 복사합니다
 * 셀 복사 - 단일 셀의 내용만 클립보드에 복사합니다
 * 열 복사 - 열의 전체 내용을 클립보드에 복사합니다


## 데이터 내보내기

테이블 탐색기 인터페이스에서 데이터를 내보내면 표시된 열만 포함하여 필터링된 데이터를 내보낼 수 있습니다. 다음 
형식으로 내보낼 수 있습니다.
 * Microsoft Excel (xlsx)
 * CSV (쉼표)
 * TSV (탭)
 * PSV (파이프)

다운로드 메뉴에서는 브라우저에 표시된 행만 다운로드할 수도 있습니다. 이는 지정한 행 제한을 기준으로 합니다.


## 추가 작업

`Actions` 메뉴에서 유용한 추가 작업을 사용할 수 있습니다.


### 추출 단계로 저장

데이터를 탐색하는 것은 대개 데이터 파이프라인 프로세스에서 데이터를 어떻게 필터링할지 판단하기 위한 것입니다. 이때는 원하는 결과로 좁히기 위해 고급 필터를 포함한 
여러 필터를 적용하는 경우가 많습니다.

모든 필터, 열, 요약, 정렬을 추출 단계에서 일일이 다시 만들려고 하는 대신, 현재 테이블 탐색기 설정을 
새 추출 단계로 바로 저장할 수 있습니다. 


### 뷰로 저장

위에서 설명한 현재 테이블 탐색기 설정을 추출 단계로 저장하는 것과 마찬가지로, 설정을 뷰로 바로 저장할 수도 있습니다.

데이터 파이프라인이 필요하지 않은 보고나 기타 다운스트림 프로세스를 위해 데이터 일부를 구성할 때 특히 
유용할 수 있습니다.


### 저장된 필터 관리

필터링 작업을 잃어버릴 일이 없습니다. 테이블 탐색기 설정을 저장된 필터로 저장할 수 있습니다. 저장된 필터에는 열 표시 여부, 요약, 
열 필터, 고급 필터, 정렬도 포함됩니다.

필터를 저장할 때 `Public` 확인란을 선택하면 다른 사람이 저장된 필터를 사용하도록 할 수도 있습니다.

`Actions` 메뉴에서 저장된 필터를 삭제하거나 이름을 바꿀 수도 있습니다.


## 고급 필터

포인트 앤 클릭 열 필터를 사용하면 원하는 결과로 좁히는 필터를 빠르게 적용할 수 있지만, 필터 조건이 복잡하여 
더 고급 사양이 필요한 경우도 있습니다.

고급 필터 영역은 `Summarize`가 활성화된 경우 집계 전 필터와 집계 후 필터를 모두 제공합니다.

데이터의 하위 집합을 만들 때는 유효한 Python 식이면 무엇이든 사용할 수 있습니다. 자세한 내용과 예제는 [식](/ko/reference/expressions/)을 참조하십시오.
