PlaidCloud의 테이블 형식 데이터와 정보는 Greenplum 데이터 웨어하우스에 저장됩니다. 이를 통해 방대한 확장성과 성능을 확보하면서, 검증되고 성숙한 기술을 사용하여 데이터 손실이나 손상의 위험을 최소화합니다.

또한 공통 구문으로 동작하는 데이터 웨어하우스를 사용하므로 타사 도구가 데이터에 직접 연결하여 탐색할 수 있습니다. 결과적으로 PlaidCloud 데이터 생태계는 개방적이고 탐색 가능하면서도 업계 최고 수준의 보안 및 액세스 제어를 보장합니다.

## 테이블

테이블은 PlaidCloud 전반에서 실제 테이블 형식 데이터를 보관합니다. 개별 테이블은 필요하면 수 테라바이트의 데이터를 담을 수 있습니다. 데이터는 여러 물리 서버에 분산 저장되며, 데이터 무결성과 고가용성을 위해 자동으로 미러링됩니다.

테이블은 다양한 데이터 유형의 열로 구성됩니다. 적절한 데이터 유형을 사용하면 성능, 특히 데이터의 저장 크기에 도움이 됩니다. 가장 적합한 데이터 유형을 사용하면 PlaidCloud가 데이터를 더 효과적으로 압축할 수도 있습니다. 데이터 유형은 대개 PlaidCloud가 추정하지만, 워크플로 단계의 열 매퍼를 사용하여 변경할 수도 있습니다.

테이블은 해당 테이블을 사용하는 워크플로, 열 이름 또는 테이블에 들어 있는 값으로 찾을 수 있으며, 테이블을 마지막으로 읽은 시점도 확인할 수 있습니다. [테이블 및 뷰 관리](/ko/guides/projects/managing-tables-and-views/#테이블-찾기)를 참조하십시오.

## 뷰

뷰는 테이블과 똑같이 동작하지만 실제 데이터를 보관하지 않습니다. 쿼리로 파생된 테이블의 논리적 표현입니다. 뷰를 사용하면 저장 공간을 절약할 수 있습니다.

다만 뷰를 사용할 때는 몇 가지 제한 사항이 있으므로 다음 내용에 유의하십시오.

 * 뷰 중첩 성능 - 뷰 중첩(뷰의 뷰의 뷰...)은 매우 큰 테이블이나 복잡한 계산에서 성능에 영향을 줄 수 있습니다. 성능을 개선하려면 중간 테이블을 만들어야 할 수도 있습니다.
 * 대시보드 성능 - 대시보드에 사용할 뷰를 게시하는 것은 전혀 문제가 없지만, 매우 큰 테이블에서는 최적의 사용자 경험을 위해 뷰 대신 테이블을 게시하는 것이 좋을 수 있습니다.
 * 동적 데이터 - 뷰의 데이터는 참조하는 기본 테이블의 데이터가 변경되면 함께 바뀝니다. 모든 것이 자동으로 업데이트된다는 장점이 될 수도 있지만, 고정된 데이터 세트를 원했다면 예상치 못한 골칫거리가 될 수도 있습니다.

<Aside>뷰를 사용하면 워크플로 실행 시점에 데이터 이동이 필요하지 않으므로 워크플로 속도를 높이는 데 도움이 됩니다.</Aside>

<Aside>뷰에는 데이터가 없으므로 가져오기의 대상으로 사용할 수 없습니다. 이 경우에는 테이블을 사용해야 합니다.</Aside>
