## 개요

워크플로 단계는 일반적으로 워크플로에 정의된 순서대로 실행됩니다.  하지만 미리 정의한 조건이 충족될 때만 특정 단계를 실행하면 유용한 경우가 많습니다.  단계 조건 기능을 사용하면 다음 옵션을 기준으로 실행을 제어할 수 있습니다.
 - 변수 값
 - 테이블에 행이 있거나 비어 있음
 - 테이블이 존재하거나 존재하지 않음
 - Document에 파일이 있음
 - Document에 파일이 없음
 - 테이블 쿼리 결과
 - 날짜 및 시간 조건 충족

변수 또는 테이블 쿼리 결과를 비교할 때는 다음 비교 방식을 사용할 수 있습니다.
 - 같음
 - 같지 않음
 - 포함
 - 포함하지 않음
 - 다음으로 시작
 - 다음으로 끝남
 - 보다 큼
 - 보다 작음
 - 크거나 같음
 - 작거나 같음

또 한 가지 중요한 점은, 단계가 실행되려면 충족해야 하는 조건을 여러 개 둘 수 있다는 것입니다.  이를 통해 단계가 정확히 언제 실행되어야 하는지를 강력하게 제어할 수 있습니다.

## 조건 추가 및 제어

단계에서 조건을 활성화하고 추가하려면 다음과 같이 합니다.
1) 조건을 추가할 단계를 찾습니다
2) 단계를 마우스 오른쪽 버튼으로 클릭하고 **단계 세부 정보 편집**을 선택하거나, 톱니바퀴 아이콘을 클릭하고 **일반** 탭으로 전환합니다
3) **일반** 탭 맨 아래에 있는 **조건 확인** 섹션으로 스크롤합니다
4) **실행 전 조건 확인** 체크박스를 선택하여 대화 상자를 활성화하고 조건을 추가합니다.
5) 왼쪽의 **조건 확인** 섹션에서 "+"를 선택하여 새 조건을 추가합니다
6) 오른쪽의 탭 섹션에서 조건을 추가합니다
7) 필요한 만큼 5, 6단계를 반복하여 모든 조건을 추가합니다

## 시각적 캔버스에서 조건 보기

단계를 열지 않아도 시각적 캔버스에서 단계의 조건을 확인할 수 있습니다. 조건부 단계로 들어가는 연결선은 **점선**이며 화살촉 위치에 작은 **방패** 아이콘이 있습니다. 방패가 너무 작아 알아보기 힘들 만큼 멀리 축소했을 때는 점선으로 구분합니다.

방패를 클릭하면 **조건 확인**이 이미 보이도록 스크롤된 상태로 단계가 열립니다. 연결선을 마우스 오른쪽 버튼으로 클릭하고 **조건 편집…** 을 선택해도 같은 동작을 합니다. 단계 타일의 왼쪽 아래에 있는 방패는 이전과 마찬가지로 해당 단계가 조건부임을 나타냅니다.

다음 두 경우에는 의도적으로 화살표에 방패를 표시하지 않습니다.

- **들어오는 연결선이 없는 단계.** 날짜나 변수를 조건으로 하는 단계는 앞에 연결된 것이 없이 워크플로의 시작에 놓일 수 있습니다. 표시할 화살표가 없으므로 타일의 방패만 나타납니다.
- **접힌 그룹 안의 단계.** 단계의 타일이 그룹의 타일에 합쳐지고 화살표가 단계가 아닌 그룹에 고정되므로, 여기에 표시하면 조건을 엉뚱한 대상에 귀속시키게 됩니다.

들어오는 연결선이 여러 개인 단계에는 화살표마다가 아니라 방패가 하나만 표시됩니다.

:::note
이 방법으로 조건을 열면 네이티브 단계 양식을 사용하는 단계 유형은 조건 확인 위치로 이동합니다. 이전 구성 창을 여전히 사용하는 단계 유형은 맨 위에서 열립니다. 조건은 있지만 해당 위치로 스크롤되지 않을 뿐입니다.
:::

### 방패가 알려 주는 검사 내용

방패의 툴팁에는 단계가 무언가를 검사한다는 사실만 알려 주는 것이 아니라, 단계가 실제로 검사하는 내용이 나열됩니다.

```
Table Row Count (sales_2026) > 0 where region = 'EU'
Day of Week = Monday (UTC+2)
Project Variable (run_mode) = "full"
```

검사는 최대 세 개까지 나열되고 그 뒤에 나머지 개수(*…and 2 more checks*)가 표시되므로, 조건이 많은 단계에서도 목록을 읽기 쉽게 유지됩니다. 같은 요약이 단계 타일의 방패에도 나타나며, 들어오는 연결선이 없는 단계에서는 이것이 유일한 방패입니다.

단계를 선택하면 같은 목록이 Inspector 패널의 **조건** 섹션에 표시되며, 긴 목록은 여기에서 읽는 것이 더 편합니다.

표시 문구에 대해 알아 둘 점은 다음과 같습니다.

- **요일과 월 검사는 저장된 숫자가 아니라 이름으로 표시됩니다.** *Day of Week = 3*이 아니라 *Day of Week = Monday*로 표시됩니다.
- **시간대는 UTC가 아닐 때만 표시됩니다.** 위의 *(UTC+2)*가 그 예입니다.
- **테이블 검사의 필터는** `where` 뒤에 표시되며, 길면 줄여서 표시됩니다.
- **집계 비교는 집계라고 표시됩니다.** *Query Value (aggregated sales_2026.amount) >= 100*은 테이블 전체의 합계를 비교하는 반면, *Query Value (sales_2026.amount) >= 100*은 한 행의 값을 비교합니다.
- **문서 검사는 경로는 표시하지만 계정은 표시하지 않습니다.** 서로 다른 문서 계정에서 같은 경로를 검사하는 두 조건은 똑같이 표시되므로, 구분하려면 단계를 열어 확인하십시오.
- **트리 브라우저에서 선택한 테이블은** 워크플로가 어딘가에서 해당 테이블을 읽거나 쓰는 경우 이름이 표시됩니다. 그렇지 않은 경우 내부 식별자 대신 테이블 이름 없이 검사만 표시됩니다.


### 게이트로 인한 영향

클릭하지 않고 방패 위에 마우스를 올리면, 캔버스에서 조건부 단계와 그 하위 단계 전체가 점선 강조 표시로 윤곽이 표시됩니다. 해당 조건이 실행을 막을 경우 실행되지 않을 단계들입니다. 아무것도 변경되지 않으며, 포인터를 치우면 강조 표시가 사라집니다. *상위* 단계는 어느 경우에나 실행되므로 강조 표시되지 않습니다.

이것은 사용 안 함 그룹의 **사용 안 함** 칩이 보여 주는 미리 보기와 같지만, 문구에 중요한 차이가 있습니다. 사용 안 함 그룹은 실제로 꺼져 있으므로 칩에는 몇 개의 단계를 건너뛰*게 되는지*가 표시됩니다. 조건은 실행이 그 지점에 도달했을 때만 평가되므로, 방패에는 조건이 실행을 막**는다면** 몇 개의 단계가 실행되지 *않을지*가 표시됩니다. 모든 단계를 통과시킬 수도 있습니다.

### 방패가 알려 주는 마지막 실행 결과

방패는 가장 최근 실행에서 일어난 일도 보여 주므로, 끝난 흐름을 따라가며 어디서 멈췄는지 확인할 수 있습니다.

| 방패 | 의미 |
| --- | --- |
| 기본 방패 | 단계가 조건부입니다. 아직 실행되지 않았거나 지금 실행 중입니다. |
| **+** 가 있는 방패 | 마지막 실행에서 단계가 실행되었습니다. |
| **−** 가 있는 방패 | 마지막 실행에서 단계가 실행되지 않았습니다. |

세 가지는 색이 아니라 모양으로 구분되며, 방패의 툴팁에 상태가 문장으로 설명됩니다. 워크플로가 실행되는 동안 실시간으로 업데이트되므로, 실행이 게이트에 도달하는 것을 보기 위해 캔버스를 다시 로드할 필요가 없습니다.

:::caution
**−** 가 있는 방패는 단계가 실행되지 않았다는 것만 알려 줄 뿐 *그 이유*는 알려 주지 않으므로, "조건이 막았다"는 뜻으로 해석하면 안 됩니다. 단계가 사용 안 함 상태이거나, 해당 그룹이 사용 안 함 상태이거나, 상위 단계가 실패했거나, 부분 실행의 범위를 벗어난 경우에도 단계는 실행되지 않은 것으로 기록됩니다. 도구 모음의 **로그 보기**를 열면 [실행 로그](/ko/guides/workflows/viewing-workflow-log/)가 열리며, 건너뛴 각 단계의 이유가 나와 있습니다. 중단점에서 멈춰 있는 단계만 의도적으로 제외됩니다. 그 지점에서 멈춘 것은 실행의 결과가 아니라 사용자가 정한 것이므로 기본 방패를 유지합니다.
:::


## 조건 관리

**조건 확인** 섹션에서 필요한 만큼 조건을 추가할 수 있습니다.  조건을 추가할 때 나중에 쉽게 찾을 수 있도록 알아보기 쉬운 이름을 지정해 두는 것이 좋습니다.

조건을 추가한 후 왼쪽에서 선택하면 오른쪽에서 조건 평가 기준을 편집할 수 있습니다.

조건 이름을 바꾸려면 조건을 선택하고 오른쪽 구성 패널 맨 위의 **이름** 필드를 편집하거나, 목록에서 조건을 두 번 클릭합니다. 조건을 마우스 오른쪽 버튼으로 클릭해 **이름 바꾸기**와 **삭제**를 선택할 수도 있으며, **삭제**는 목록 위의 "−" 버튼에서도 사용할 수 있습니다.

조건 유형이 선택되지 않은 조건(예: 이전 버전이나 가져온 워크플로에서 넘어온 조건)은 평가할 수 없습니다. 이런 조건은 충족되지 않은 것으로 처리되어 단계를 건너뛰며, 단계의 메시지에 조건이 무엇을 검사할지 지정하지 않았다고 표시됩니다. 조건을 열어 무엇을 검사할지 선택하십시오.


## 변수 조건

변수 조건을 검사할 때는 비교가 이루어지도록 **Value Check Parameters** 섹션을 작성해야 합니다.

**Variable or Table Field**에 변수 이름을 입력합니다.  비교 유형을 선택하고 비교 값을 입력합니다.


## 기본 테이블 조건

테이블에 행이 있는지 또는 비어 있는지를 검사하는 조건이라면, **테이블 데이터 선택** 탭에서 테이블도 정의해야 합니다.


## 테이블 존재 조건

테이블 존재 조건은 테이블이 웨어하우스에 생성된 경우에만, 또는 생성되지 않은 경우에만 단계를 실행합니다. 이 조건은 테이블의 행을 읽지 않으며, 행이 0개인 상태로 기록된 테이블도 존재하는 것으로 간주합니다. 프로젝트의 어떤 테이블과도 일치하지 않는 테이블 이름은 없는 것으로 간주합니다. 첫 실행에서는 테이블을 만들고 이후에는 그대로 두거나, 이전 단계가 만들지 않았을 수 있는 테이블을 읽는 단계를 건너뛰려는 경우에 사용하십시오.

두 가지 검사 유형은 `radio_table_exists`와 `radio_table_not_exists`입니다. 기본 테이블 조건과 같은 방식으로 테이블을 선택합니다. 조건은 AI 어시스턴트나 REST API로 설정하며, **조건 확인** 탭에는 아직 표시되지 않습니다.

## 고급 테이블 조건

고급 테이블 조건을 사용할 때는 비교가 이루어지도록 **Value Check Parameters** 섹션을 작성해야 합니다.

**Variable or Table Field**에 테이블 선택에서 가져온 필드 이름을 입력합니다.  비교 유형을 선택하고 비교 값을 입력합니다.

**테이블 데이터 선택** 탭에서 테이블을 선택하고, 최소한 조건 비교에서 참조하는 필드를 포함하여 데이터 매핑 섹션을 작성합니다.

## 문서 경로 조건

파일이 존재하는지 검사하는 조건이라면, **문서 경로** 탭에서 문서 계정을 선택하고 검사할 문서 경로를 지정해야 합니다. 이 검사는 파일을 대상으로 하므로, 해당 경로에 있는 폴더는 없는 것으로 간주합니다.

## 날짜 및 시간 조건

날짜 또는 시간을 선택할 때 여러 조건을 조합해야 하면 조건을 여러 개 추가할 수 있습니다.  예를 들어 단계를 월요일 오전 2시 5분에만 실행하려면 세 가지 조건을 만듭니다.
 - 요일 조건을 월요일(1)로 설정
 - 시(hour) 조건을 2로 설정
 - 분(minute) 조건을 5로 설정

### 시간대 오프셋

각 날짜 및 시간 조건에는 자체 **시간대 오프셋**이 있으며, 대표 시간대의 이름을 붙인 정수 시간 단위 오프셋으로 표시됩니다. 예를 들어 *Eastern Time (US & Canada) (UTC -5)*나 *Asia/Tokyo (UTC +9)*가 있습니다. 입력한 시간은 해당 시간대의 시계와 비교됩니다.

새 조건은 브라우저가 보고하는 오프셋으로 시작하므로 대부분의 경우 그대로 두면 됩니다. 일정이 현재 위치가 아닌 다른 곳을 기준으로 한다면 직접 설정하십시오. 예를 들어 재무 팀의 시계를 기준으로 실행되는 마감이 그렇습니다. 정수 시간 단위만 선택할 수 있으므로, 인도(UTC +5:30)처럼 30분 단위 시간대는 가장 가까운 정수 시간으로 반올림해야 합니다.

이 설정이 적용되기 전에 저장된 조건은 시간대를 선택할 때까지 계속 UTC를 기준으로 평가되므로, 기존 조건은 이전과 똑같이 동작합니다.

:::caution
**요일** 조건은 현재 어떤 오프셋을 선택하든 UTC를 기준으로 비교합니다. UTC에서 멀리 떨어진 시간대에서 요일 조건이 특정 요일에 해당해야 한다면, 자정을 전후한 몇 시간 동안은 현지 요일과 다를 수 있다는 점에 유의하십시오.
:::

### 재무 마감 영업일

**Use Financial Close Workday**의 경우, 필드 옆의 힌트에 표시된 대로 카운트는 **매월 1일을 0으로** 시작합니다. 따라서 마감이 매월 5일째에 이루어지면 `5`가 아니라 `4`입니다.

:::caution
이 조건은 현재 일치하는 경우가 없으므로, 이 조건으로 제어되는 단계는 실행되지 않습니다. 이 문제가 해결될 때까지는 **Day of the month** 조건을 사용하십시오. 월말부터 거꾸로 세도록 의도된 음수 값도 동작하지 않습니다.
:::

## AI 어시스턴트로 조건 설정

워크스페이스에 연결된 AI 어시스턴트는 단계를 만들 때든 기존 단계를 편집할 때든 단계의 조건을 대신 추가하거나 변경할 수 있습니다. **Workday 재무 마감 확인**을 제외하고, 앞에서 설명한 모든 조건 유형을 어시스턴트가 사용할 수 있습니다. 어시스턴트가 이 조건을 작성할 수는 있지만 일치하는 경우가 없으므로, 모르고 넘어가지 않도록 어시스턴트가 경고합니다. 이 조건은 직접 **조건** 탭에서 설정하십시오.

직접 조건을 편집하는 것과 다르게 동작하는 부분이 세 가지 있습니다.

- **매번 전체 목록이 교체됩니다.** 조건 하나를 추가하거나 변경해 달라고 요청하면 어시스턴트가 전체 목록을 보내므로, 빠뜨린 조건은 제거됩니다. 모든 조건이 포함되어 있는지 확실하지 않다면, 쓰기 전에 단계의 현재 조건 목록을 보여 달라고 요청하십시오.
- **평가할 수 없는 조건은 거부됩니다.** 무엇을 검사하는지 지정하지 않은 조건은 저장되지 않고 거부되며, 단계는 기존 조건을 그대로 유지합니다. 요청을 수정하여 다시 요청하십시오.
- **불완전한 조건은 경고와 함께 저장됩니다.** 비교할 값이 없는 조건이나, **실행 전 조건 확인**이 선택되지 않은 상태로 추가된 조건은 저장된 뒤 경고로 보고됩니다. **조건** 탭을 열어 마무리하십시오. 그렇지 않으면 단계가 요청한 대로 동작하지 않습니다.

어시스턴트는 단계의 잠금, 관리자 및 탐색기 보기에서의 표시 여부, 재시도 설정, 오류 시 이동할 단계도 설정할 수 있습니다.
