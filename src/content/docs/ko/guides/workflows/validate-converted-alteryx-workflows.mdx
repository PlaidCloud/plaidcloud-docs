검증은 변환된 Alteryx 워크플로가 PlaidCloud에서 실행할 준비가 되었는지, 그리고 예상 출력이 있는 경우 동일한 비즈니스 결과를 생성하는지 확인합니다.

워크플로, 앱 또는 매크로를 PlaidCloud로 가져온 후 이 가이드를 사용하십시오.

<Aside type="note">
  출력 동등성이란 스키마, 행 수, 행 값이 일치한다는 뜻입니다. 워크플로가 비즈니스 로직의 일부로 정렬을 사용하는 경우가 아니라면 행 순서는 일치하지 않아도 됩니다.
</Aside>

## 검증 수준 선택

대부분의 마이그레이션 프로그램은 두 가지 검증 수준을 사용합니다.

### 구조 검증

구조 검증은 PlaidCloud가 Alteryx 설계에서 완전한 워크플로를 생성했는지 확인합니다. 마이그레이션 준비 상태를 측정하거나, 포트폴리오 인벤토리를 준비하거나, 예상 출력이 준비되기 전에 워크플로를 변환할 때 이 수준을 사용하십시오.

다음을 확인합니다.

1. 변환된 워크플로가 시각적 워크플로 디자이너에서 열립니다.
2. 워크플로 그래프에 예상한 분기, 조인, 매크로, 출력이 포함되어 있습니다.
3. 필요한 모든 입력 파일이 선택한 Document 경로에 업로드되었습니다.
4. 필요한 모든 매크로를 가져왔거나 생성했습니다.
5. 매크로 입력과 매크로 출력이 연결되어 있습니다.
6. 분석 앱 질문이 제어되는 입력 필드가 있는 워크플로 변수가 되었습니다.
7. 워크플로 실행이 완료되고 데이터에 의존하는 조건에 대해 명확한 준비 상태 참고 사항을 보고합니다.

### 출력 동등성 검증

출력 동등성 검증은 변환된 워크플로가 Alteryx 워크플로와 동일한 테이블 결과를 생성하는지 확인합니다.

다음을 비교합니다.

1. 출력 테이블 스키마.
2. 행 수.
3. 행 값.
4. null 처리.
5. 숫자 정밀도 및 반올림.
6. 날짜 및 시간 값.
7. 공간 출력이 결과에 포함된 경우 지오메트리 값.

워크플로가 데이터를 명시적으로 정렬하거나 하위 프로세스가 정렬된 행에 의존하는 경우가 아니라면 행 순서는 무시합니다.

PlaidCloud의 Lakehouse v2(StarRocks) 엔진에서는 자주 사용되는 다음 변환이 Alteryx 출력과 일치하도록 값이 검증되므로, 별도 처리 없이 일치하는 결과를 기대할 수 있습니다.

- 텍스트 제목 대/소문자 변환.
- 점 사이의 구면(대원) 거리.
- 표본 공분산.
- 텍스트로 저장된 숫자 값에 대한 합계와 평균.
- 정규식으로 텍스트를 열로 분할.
- 결측값의 평균 대체.

<Aside type="tip" title="숫자 정밀도를 비교하기 전에 다시 변환하십시오">
Alteryx Double 열은 이제 32비트가 아닌 64비트 숫자 열로 변환되므로, 이 수정 이전에 변환된 워크플로에서는 유효 숫자 약 7자리를 넘는 값에서 반올림이 나타날 수 있습니다. 이전 변환을 기준으로 삼지 말고, 숫자 정밀도를 비교하기 전에 다시 가져오십시오. [Alteryx Double 열은 전체 정밀도를 유지합니다](/ko/guides/workflows/migrate-alteryx-workflows/#alteryx-배정밀도-열은-전체-정밀도를-유지합니다)를 참조하십시오.
</Aside>

## 마이그레이션 검증

**마이그레이션 검증**은 변환된 워크플로가 생성한 결과를 Alteryx가 생성한 출력과 비교하므로, 직접 비교하지 않아도 됩니다. Alteryx 커버리지 보고서를 통해 들어온 워크스페이스에서는 홈 체크리스트에 **Compare** 버튼이 있는 **마이그레이션 검증**으로 표시되며, 커버리지 보고서에도 같은 버튼이 있습니다.

1. **Alteryx 출력 가져오기…** 를 선택하고 Alteryx 워크플로가 생성한 출력 파일을 각각 가져옵니다. **출력 추가**로 쌍을 추가할 수 있습니다.
2. 각 쌍에서 **변환된 출력**과 이와 일치해야 하는 **Alteryx 출력**을 선택합니다.
3. **비교**를 선택합니다.

PlaidCloud는 먼저 행 수를 확인하고, 이어서 모든 열을 확인한 다음, 한쪽에서만 발견된 행(각각 최대 20개)을 표시하므로 차이를 해당 열까지 정확히 짚을 수 있습니다. 각 출력은 다음 결과 중 하나를 보고합니다.

| 결과 | 의미 |
|---|---|
| *Matches `<output>`: `<n>` rows on both sides, every column the same.* | 양쪽의 행 수가 같고 모든 열이 같습니다. |
| *Matches `<output>` on everything compared: `<n>` rows on both sides.* | 비교한 모든 항목이 일치합니다. *3 more columns were not compared.*와 같은 참고 사항은 비교에서 제외된 열의 수를 알려 줍니다. |
| *Differs from `<output>`: `<n>` rows converted, `<m>` rows from Alteryx.* | 행 수, 열 또는 값이 다릅니다. 보고서에는 한쪽에서만 발견된 열이 나열되며, 각 열에서 무엇이 다른지(예: 합계, 최솟값, 고유 개수)가 표시됩니다. |

500만 행을 초과하는 쪽은 여기서 비교하기에는 너무 크므로, 대신 각각의 필터링된 추출본을 비교하십시오. 홈 체크리스트 행에는 마지막 결과가 표시됩니다. 즉 *출력이 일치합니다*, *비교한 열에서 출력이 일치합니다*, *일부 출력이 다릅니다* 중 하나입니다.

사용자의 [Snowflake 또는 Databricks 웨어하우스](/ko/guides/connections/external-lakehouse/#실행당-웨어하우스-비용)에서는 창에 마지막 실행의 **웨어하우스 비용**(*attributed* 또는 *estimated*로 표시)과 다음 실행의 예상 비용도 표시됩니다.

## 입력 검증

출력을 비교하기 전에 변환된 워크플로가 같은 소스 데이터를 사용하는지 확인합니다.

1. 가져오는 동안 선택한 Document 폴더를 엽니다.
2. 필수 파일과 사이드카 파일이 있는지 확인합니다.
3. 동적 입력 패턴이 의도한 파일로 해석되는지 확인합니다.
4. 데이터베이스 또는 API 자격 증명을 대상 환경에서 사용할 수 있는지 확인합니다.
5. 워크플로 변수가 Alteryx 실행에서 사용한 값과 일치하는지 확인합니다.

입력을 맞추면 검증이 더 빨라지고 비교가 워크플로 동작에 집중됩니다.

## 매크로 검증

변환된 Alteryx 매크로는 PlaidCloud 매크로 워크플로가 됩니다. 매크로와 호출하는 워크플로를 함께 검증합니다.

1. 생성된 매크로 워크플로를 엽니다.
2. 각 매크로 입력에 일치하는 매크로 입력 단계가 있는지 확인합니다.
3. 각 매크로 출력에 일치하는 매크로 출력 단계가 있는지 확인합니다.
4. 매크로를 호출하는 워크플로를 실행합니다.
5. 반복 실행 또는 동시 실행이 서로 격리된 상태로 유지되는지 확인합니다.
6. 예상 매크로 출력이 있으면 매크로 출력 데이터를 비교합니다.
7. 배치 매크로의 경우 모든 패스가 수집된 결과에 나타나는지 확인합니다. 매크로가 패스를 생성하지 않는 실행도 이전 실행에서 남은 행이 아니라 빈 결과를 반환해야 합니다. 매크로 로직이 Double 값이 전달되는 방식에 의존한다면 다시 확인하십시오. 이제 Double 매크로 입력은 텍스트가 아니라 숫자로 전달됩니다.

## 분석 앱 검증

변환된 Alteryx 분석 앱은 제어되는 사용자 입력을 위해 워크플로 변수를 사용합니다.

다음을 확인합니다.

- 텍스트 상자, 숫자 입력, 날짜, 파일 선택기, 폴더 선택기, 목록, 트리, 라디오 버튼, 체크박스, 드롭다운이 예상한 입력 컨트롤로 표시됩니다.
- 기본값이 있었던 경우 원래 앱과 일치합니다.
- 워크플로를 실행하기 전에 필수 값이 설정되어 있습니다.
- 구성된 입력 값에 대해 조건이 예상한 메시지, 경고 또는 중지 동작을 생성합니다.

## 특수 출력 검증

일부 변환된 워크플로는 테이블뿐 아니라 아티팩트도 생성합니다. 이러한 출력은 사용되는 방식에 따라 검증하십시오.

보고서, PDF, 이미지, 차트, 지도의 경우:

1. 아티팩트가 예상한 Document 경로에 생성되었는지 확인합니다.
2. 아티팩트에 예상한 데이터, 레이블, 이미지, 레이아웃이 포함되어 있는지 확인합니다.
3. 하위 프로세스의 사용자가 아티팩트를 열거나 사용할 수 있는지 확인합니다.
4. 예상 아티팩트가 있으면 비교합니다.

NLP, 퍼지 매칭, 공간 워크플로의 경우:

1. 관리형 작업 실행기가 성공적으로 완료되었는지 확인합니다.
2. 실행기 참고 사항을 검토합니다.
3. 생성된 테이블 또는 점수를 예상 출력과 비교합니다.
4. PlaidCloud 출력이 Alteryx 데스크톱 전용 출력과 의도적으로 다른 경우 클라우드 네이티브 아티팩트 차이를 문서화합니다.

머신러닝 워크플로의 경우:

1. ML Train 단계가 한 행짜리 모델 테이블을 기록했는지 확인하고 기록된 학습 지표를 검토합니다.
2. ML Score 예측 열을 Alteryx 점수와 비교합니다. XGBoost 모델의 경우 값이 동일하기보다 통계적으로 동등할 것으로 예상하고, 단계의 매핑 참고 사항을 검토하십시오.

## 검증 차이 해결

검증에서 차이가 발견되면 다음 순서로 항목을 검토합니다.

1. 누락되었거나 다른 입력 파일.
2. 다른 워크플로 변수 값.
3. 다른 데이터베이스 스냅샷 또는 API 응답.
4. 날짜, 시간대, null, 반올림 또는 문자열 정렬 방식의 차이.
5. 공간 참조 또는 지오메트리 형식의 차이.
6. 보고서, 지도, 독점 형식 또는 데스크톱 전용 렌더러에 대한 클라우드 네이티브 아티팩트 차이.

원인을 수정한 후 워크플로를 다시 실행하고 비교를 반복합니다.

## 검증된 워크플로 승격

검증을 통과하면 다음을 수행합니다.

1. 마이그레이션을 스테이징 프로젝트에서 수행했다면 워크플로를 프로덕션 프로젝트로 이동하거나 복사합니다.
2. 프로덕션 Document 경로와 자격 증명을 확인합니다.
3. 워크플로 일정을 설정합니다.
4. 실행 이력에서 처음 몇 번의 프로덕션 실행을 모니터링합니다.
5. 감사와 지원을 위해 검증 결과를 마이그레이션 기록과 함께 보관합니다.
