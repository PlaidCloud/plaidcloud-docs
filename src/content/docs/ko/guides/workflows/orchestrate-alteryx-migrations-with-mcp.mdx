PlaidCloud의 MCP 서버를 사용하면 AI 에이전트가 여러 Alteryx 워크플로에 걸친 마이그레이션을 조율할 수 있습니다. 에이전트는 Document에서 파일을 준비하고 정리하고, 워크플로 패키지의 목록을 작성하고, Alteryx 변환기를 호출하고, 생성된 워크플로를 정리하고, 검증 워크플로를 실행하고, 마이그레이션 팀을 위해 진행 상황을 요약하는 일을 도울 수 있습니다.

<Aside type="note">
  MCP는 포트폴리오 규모의 조율에 적합합니다. 변환은 여전히 PlaidCloud 가져오기 도구가 수행하며, 에이전트는 작업을 계획하고, 순서를 정하고, 실행하고, 요약하는 일을 돕습니다.
</Aside>

## MCP를 사용해야 하는 경우

많은 워크플로를 마이그레이션하거나 AI 에이전트가 반복 가능한 마이그레이션 작업을 돕도록 하려면 MCP 조율을 사용합니다.

- Document에 준비된 Alteryx 파일의 목록을 작성합니다.
- Document 도구로 마이그레이션 파일을 업로드, 복사, 이동, 이름 변경, 정리합니다.
- OneDrive, Google Drive, SharePoint, S3, Azure Blob, SFTP 같은 연결된 공유 스토리지 계정에서 작업합니다.
- 워크플로, 앱, 매크로를 마이그레이션 배치로 그룹화합니다.
- 각 `.yxmd`, `.yxwz`, `.yxmc` 파일을 PlaidCloud로 변환합니다.
- 포트폴리오 전체의 변환 결과를 추적합니다.
- 변환된 워크플로 또는 검증 워크플로를 실행합니다.
- 검토를 위한 마이그레이션 요약을 작성합니다.

워크플로 하나라면 가져오기 양식이 가장 빠른 경로인 경우가 많습니다. 포트폴리오라면 MCP를 통해 에이전트가 동일한 PlaidCloud 기능을 반복해서 조율할 수 있는 구조화된 방법이 생깁니다.

## 에이전트가 호출할 수 있는 도구

MCP 도구 카탈로그에는 `alteryx_convert`라는 Alteryx 변환 도구가 포함되어 있습니다. 이 도구는 Document에 저장된 Alteryx 파일에서 PlaidCloud 워크플로를 생성합니다.

변환 호출에는 다음이 포함됩니다.

- Alteryx 파일의 소스 문서 계정과 경로
- 대상 PlaidCloud 프로젝트
- 변환 아티팩트의 대상 문서 계정과 경로
- 선택적인 워크플로, 단계, 테이블 접두사. 테이블 접두사의 기본값은 워크플로 자체의 이름이며, 이렇게 하면 한 프로젝트에서 두 변환이 서로의 테이블을 침범하지 않습니다. 접두사 없이 이름 그대로 사용하려면 빈 접두사를 전달합니다.
- 워크플로 유형(기본값은 고급 워크플로)

에이전트는 이를 일반 MCP 프로젝트, 워크플로, Document, 워크플로 실행, 테이블 도구와 함께 사용하여 전체 마이그레이션을 관리할 수 있습니다.

## 에이전트로 파일 준비

MCP에 연결된 에이전트는 변환 전후의 파일 준비 작업을 도울 수 있습니다.

- Document에서 `.yxmd`, `.yxwz`, `.yxmc` 파일을 찾습니다.
- 입력 파일, 매크로 파일, 보고서 자산, 공간 사이드카, 예상 출력으로 보이는 파일을 식별합니다.
- 깔끔한 마이그레이션 폴더 구조를 만듭니다.
- 파일을 그 구조로 복사, 이동 또는 이름 변경합니다.
- 관련된 워크플로, 매크로, 데이터, 공간, 보고서, 검증 파일을 함께 보관합니다.
- 변환하기 전에 패키지를 요약합니다.

마이그레이션 패키지에 폴더가 많거나, 팀이 변환을 시작하기 전에 에이전트가 반복 가능한 목록을 작성하기를 원할 때 유용합니다.

## 업로드 없이 공유 스토리지 사용

마이그레이션 전에 새로운 PlaidCloud 소유 폴더에 파일을 업로드할 필요는 없습니다. PlaidCloud Document는 Alteryx 마이그레이션 패키지가 이미 들어 있는 공유 스토리지에 직접 연결할 수 있습니다.

일반적인 옵션은 다음과 같습니다.

- [Google Drive](/ko/guides/documents/adding-accounts/add-google-drive-account/)
- [OneDrive 또는 SharePoint](/ko/guides/documents/adding-accounts/add-onedrive-account/)
- [AWS S3](/ko/guides/documents/adding-accounts/add-aws-s3-account/)
- [Azure Blob Storage](/ko/guides/documents/adding-accounts/add-azure-blob-storage-account/)
- [SFTP](/ko/guides/documents/adding-accounts/add-sftp-account/)

문서 계정이 연결되면 에이전트는 해당 문서 계정과 경로에서 작업할 수 있습니다. 이렇게 하면 마이그레이션이 고객의 기존 공유 스토리지와 가까이 유지되며 별도의 업로드 단계를 없앨 수 있습니다.

## Document에서 파일 준비 또는 선택

에이전트에게 마이그레이션 조율을 요청하기 전에 다음 경로 중 하나를 선택합니다.

- 기존 공유 스토리지 위치를 문서 계정으로 연결합니다.
- 워크플로 패키지를 문서 계정에 업로드합니다.
- 에이전트에게 Document에 이미 있는 파일을 정리하도록 요청합니다.

그런 다음 다음을 확인합니다.

1. 워크플로, 앱, 매크로, 입력 파일, 공간 사이드카, 보고서, 예상 출력을 Document를 통해 사용할 수 있습니다.
2. 대상 프로젝트가 선택되어 있습니다.
3. 변환된 워크플로 종속 항목과 아티팩트를 위한 Document 경로가 선택되어 있습니다.
4. 에이전트에게 관련 MCP Document 및 워크플로 도구를 사용할 권한이 있습니다.

그러면 에이전트가 변환기를 호출할 때 안정적인 Document 경로를 참조할 수 있습니다.

## 권장 에이전트 프롬프트

MCP에 연결된 에이전트에 다음과 같은 프롬프트를 사용합니다.

```text
In PlaidCloud, migrate the Alteryx workflows in the connected Document account
"Migration Share" under /q4-alteryx-package into the project "Q4 Migration".

First inventory the .yxmd, .yxwz, and .yxmc files. Organize the package by
workflow, macro, input, spatial, report, and expected-output files. Group macros
with the workflows that call them. Then convert the workflows as Advanced
workflows using the Document output path /q4-alteryx-converted. Prefix created
workflows with "Q4 - ". After each conversion, summarize the generated workflow,
macros, readiness notes, and next validation step. Ask before making mutating calls.
```

마이그레이션 배치에 맞게 프로젝트 이름, 소스 경로, 대상 경로, 접두사를 조정하십시오.

## 권장 조율 흐름

포트폴리오 마이그레이션에서는 에이전트에게 다음 흐름을 따르도록 요청합니다.

1. 마이그레이션 패키지가 들어 있는 문서 계정을 연결하거나 선택합니다.
2. 소스 Document 폴더의 목록을 작성합니다.
3. `.yxmd`, `.yxwz`, `.yxmc` 파일을 식별합니다.
4. 파일을 워크플로, 매크로, 입력, 공간, 보고서, 예상 출력 그룹으로 정리합니다.
5. 관련된 워크플로와 매크로를 그룹화합니다.
6. 대상 프로젝트와 Document 출력 경로를 확인합니다.
7. 매크로와 워크플로를 고급 워크플로로 변환합니다.
8. 생성된 워크플로를 열거나 설명합니다.
9. 구조 검증을 실행합니다.
10. 예상 출력이 있는 경우 출력 일치 검증을 실행합니다.
11. 변환된 워크플로, 생성된 매크로, 아티팩트, 검증 상태를 요약합니다.

이렇게 하면 각 변환에 PlaidCloud의 기본 가져오기 도구를 계속 사용하면서도, 마이그레이션 팀은 포트폴리오 전체에 대한 하나의 진행 보고서를 받을 수 있습니다.

## 변경 호출 검토

대부분의 MCP 클라이언트는 도구 호출을 실행하기 전에 표시합니다. 특히 프로덕션 프로젝트에서는 변환 및 워크플로 실행 호출을 승인하기 전에 검토하십시오.

스테이징 마이그레이션에는 전용 마이그레이션 프로젝트와 Document 폴더를 사용하십시오. 검증 후 변환된 워크플로를 프로덕션 프로젝트로 승격합니다.

## 결과 추적

에이전트에게 다음을 포함하는 마이그레이션 테이블을 작성하도록 요청합니다.

- 소스 Alteryx 파일
- 생성된 PlaidCloud 워크플로
- 생성된 매크로 워크플로
- 변환 상태
- 검증 수준
- 출력 Document 경로
- 후속 조치 메모

이 요약은 프로젝트 보고, 인수인계, 프로덕션 준비 상태 검토에 유용합니다.
