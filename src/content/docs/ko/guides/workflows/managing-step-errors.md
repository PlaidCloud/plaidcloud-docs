워크플로가 처리 중 오류를 겪으면 워크플로와 오류가 발생한 단계 모두에 오류 표시가 나타납니다. PlaidCloud는 실패한 단계를 여러 번 재시도할 수 있습니다. 단계가 가용성이 높지 않거나 알 수 없는 이유로 간헐적으로 실패하는 원격 시스템이나 데이터에 접근하는 경우에 유용한 경우가 많습니다. 재시도 횟수를 여러 번으로 설정할 수 있으며, 재시도 사이에 초 단위에서 시간 단위까지 지연을 추가할 수도 있습니다.



실행 도중 서버를 잃은 단계는 재시도와는 별도로 처리됩니다. 반복해도 안전한 단계는 자동으로 다시 실행되고, 그렇지 않은 단계는 **중단됨** 메시지와 함께 한 번 실패합니다. [중단된 단계](/ko/guides/workflows/run-a-workflow/#중단된-단계)를 참조하십시오.

권한 누락이나 유효하지 않은 설정처럼 사용자가 해결할 수 있는 이유로 PlaidCloud가 단계를 거부하면, 단계 로그에는 스택 트레이스가 포함된 서버 오류 대신 쉬운 말로 된 메시지가 표시됩니다. 하위 워크플로가 실패한 Model Loop 단계, Model Run 단계 또는 Macro Run 단계에는 하위 워크플로 자체의 오류 메시지가 “Child workflow run failed:” 뒤에 이어서 표시됩니다.

재시도를 선택하지 않았거나 최대 재시도 횟수를 초과하면 단계가 오류로 표시됩니다. 이 경우 PlaidCloud는 세 가지 수준의 오류 처리를 제공합니다.


* 오류가 발생하면 워크플로 중지
* 단계를 오류로 표시하되 워크플로 처리는 계속
* 단계를 오류로 표시하고 현재 워크플로를 계속하는 대신 복구 워크플로 프로세스 트리거

## 워크플로 중지


단계에서 오류가 발생할 때 워크플로를 중지하는 것이 가장 일반적인 방식입니다. 워크플로는 일반적으로 오류 없이 실행되어야 하기 때문입니다. 워크플로가 중지되고 단계와 워크플로 모두에 오류 표시가 나타납니다. 오류는 활동 모니터에도 표시되지만 그 외의 추가 조치는 수행되지 않습니다.



## 처리 계속


각 단계는 단계 양식에서 오류 시 계속하도록 설정할 수 있습니다. 이 확인란을 활성화하면 오류가 발생해도 해당 단계는 오류로 표시되지만, 워크플로는 이 오류를 단계의 완료로 간주하고 계속 진행합니다. 데이터가 없을 때 오류가 발생할 수 있지만 전체 프로세스에는 해가 없는 작업을 수행하는 단계가 있는 경우에 유용한 경우가 많습니다.



이 시나리오에서는 워크플로가 오류가 발생해도 계속 진행하므로 워크플로에 오류 표시가 나타나지 않고 실행 중 표시가 계속 유지됩니다.



## 복구 워크플로 트리거


워크플로 설정에서 복구 워크플로를 지정하면, 워크플로 오류가 발생할 때 현재 워크플로의 처리가 즉시 중지되고 복구 워크플로의 처리가 시작됩니다. 오류 시 계속하도록 표시된 단계가 실패하는 경우에는 복구 워크플로가 트리거되지 않습니다. 실패했을 때 전체 워크플로도 중지시키는 단계만 복구 프로세스를 트리거합니다.



복구 워크플로는 단순히 실패가 발생했음을 사람들에게 알리는 용도로 사용할 수도 있고, 원래 워크플로가 실패한 근본 원인을 자동으로 바로잡기 위한 다른 복잡한 처리를 수행할 수도 있습니다.
