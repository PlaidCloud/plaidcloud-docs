Alteryx는 `.yxdb` 파일을 두 가지 형식으로 씁니다. 기존 형식(원래 엔진에서 작성)은 잘 알려져 있으며 PlaidCloud에서 직접 가져옵니다. AMP 엔진은 더 새로운 변형 형식을 작성하는데, 파일 헤더가 `Alteryx e2 Database file`로 시작하며 그 사양은 비공개이고 공개되지 않았으므로 PlaidCloud를 포함하여 Alteryx 외부의 어떤 도구도 읽을 수 없습니다.

마이그레이션 중에는 아직 라이선스가 있는 Alteryx Designer가 있으며, Designer는 두 형식을 모두 읽을 수 있습니다. Designer를 사용 중지하기 전에 한 번 사용하여 AMP 형식 파일을 이식 가능한 형식으로 다시 작성하십시오.

<Aside type="note">
  기존 `.yxdb` 파일은 변환 없이 PlaidCloud로 직접 가져옵니다. `.yxdb` 가져오기가 읽을 수 없는 파일 오류로 실패하면 AMP 형식 파일이 가장 유력한 원인입니다.
</Aside>

## AMP 형식 파일 식별

- 파일을 생성한 워크플로가 AMP 엔진을 사용하도록 설정된 상태로 실행되었습니다.
- 같은 패키지의 다른 `.yxdb` 파일은 정상적으로 가져와지는데, PlaidCloud가 가져오기 중에 해당 파일을 읽을 수 없다고 보고합니다.
- 파일의 첫 바이트가 `Alteryx Database File`이 아니라 `Alteryx e2 Database file`로 시작합니다(모든 텍스트 또는 16진수 편집기에서 확인 가능).

## 옵션 A: Designer에서 파일을 하나씩 다시 저장

파일이 몇 개뿐이라면 Designer에서 각 파일을 다시 저장하십시오.

1. Alteryx Designer에서 **Input Data** 도구를 추가하고 `.yxdb` 파일을 선택합니다.
2. **Output Data** 도구를 연결하고 새 `.yxdb` 경로를 선택합니다.
3. Output Data 도구의 옵션에서 **Designer 18.1 및 이전 버전과 호환**되도록 파일을 저장하는 옵션을 활성화합니다. 이렇게 하면 기존 형식이 강제로 사용됩니다.
4. 워크플로를 실행한 다음 새 파일을 PlaidCloud로 가져옵니다.

2단계에서 `.yxdb` 대신 CSV로 쓰는 방법도 가능하며, 이 경우 호환성 옵션은 건너뜁니다.

## 옵션 B: 다운로드 가능한 워크플로로 폴더 일괄 변환

파일이 많은 경우 미리 만들어진 워크플로를 다운로드하여 Designer에서 실행하십시오.

<a href="/downloads/convert_yxdb_folder.yxmd" download>convert_yxdb_folder.yxmd 다운로드</a>

이 워크플로는 **Directory** 도구, **Dynamic Input** 도구, **Output Data** 도구를 연결하여 폴더의 모든 `.yxdb` 파일(기존 형식이든 AMP 형식이든)을 `converted_<original name>.csv`라는 이름의 CSV 파일로 다시 작성합니다. CSV는 이식 가능하며 PlaidCloud는 이를 손실 없이 가져옵니다.

1. Alteryx Designer에서 `convert_yxdb_folder.yxmd`를 엽니다.
2. **Directory** 도구에서 `.yxdb` 파일이 들어 있는 폴더를 설정합니다.
3. **Dynamic Input** 도구에서 Input Data Source Template이 해당 폴더의 `.yxdb` 파일 중 아무거나 하나를 가리키도록 합니다.
4. **Output Data** 도구에서 출력 폴더를 설정합니다.
5. 워크플로를 실행한 다음 CSV를 문서에 업로드하고 가져옵니다.

<Aside type="caution">
  Dynamic Input 도구는 배치의 모든 파일이 템플릿 파일과 같은 필드 레이아웃을 가져야 합니다. 레이아웃이 다른 파일은 경고와 함께 건너뛰며, Designer의 결과 창에 건너뛴 각 파일이 표시됩니다. 레이아웃이 다른 파일은 별도의 템플릿이 있는 자체 폴더로 묶어 다시 실행하거나, 옵션 A를 사용하여 남은 파일을 하나씩 다시 저장하십시오.
</Aside>

CSV로 변환된 파일은 `.yxdb` 고유의 데이터 유형 지정을 잃습니다(모든 값이 텍스트로 들어오고 가져올 때 유형이 다시 지정됨). 따라서 가져온 테이블의 열 유형, 특히 날짜와 고정밀 소수를 확인하십시오.
