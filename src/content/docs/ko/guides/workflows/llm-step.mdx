## 설명

**LLM 단계**는 워크플로의 한 단계로 대규모 언어 모델에 프롬프트를 실행합니다. 프로젝트의 특정 테이블, 차원, 문서에 대해 범위가 지정된 액세스를 모델에 부여하며, 각 항목마다 **읽기**, **쓰기** 또는 둘 다를 선택합니다. 모델은 필요한 데이터를 읽고, **쓰기**를 허용한 경우에는 결과를 선택한 객체에 곧바로 다시 기록합니다. 별도로 구성할 출력 형식은 없습니다. 쓰기가 활성화된 바인딩 자체가 단계의 출력입니다.

일반적인 사용 사례는 재무 테이블을 사업부별 논평으로 요약하고, 모델이 그 논평을 쓰기 액세스로 바인딩한 결과 테이블(또는 문서 파일)에 기록하도록 하는 것입니다.

<Aside type="note">프로젝트 데이터(테이블, 차원, 문서)에 대한 범위 지정 액세스는 보안 커넥터를 통해 PlaidCloud의 MCP 도구에 접근하는 **Anthropic** LLM 연결에서 사용할 수 있습니다. 다른 공급자도 프롬프트를 실행하고 구조화된 JSON을 반환할 수 있지만 범위 지정 데이터 액세스는 제공되지 않습니다. 이러한 연결에 바인딩이 있는 단계는 저장할 때 거부되며, 결과 스키마가 필요합니다.</Aside>

## 시작하기 전에

다음이 필요합니다.

* **LLM 연결.** 이 단계에는 **LLM** 종류의 연결(예: Anthropic)이 필요합니다. 연결에는 공급자 API 키, 선택 사항인 기본 모델, **에이전트 액세스** 수준이 저장됩니다. [연결](/ko/guides/connections/)을 참조하십시오.
* **연결의 쓰기 액세스 — 쓰기가 활성화된 바인딩이 있는 경우에만 필요합니다.** 연결의 에이전트 액세스가 **읽기 및 쓰기**인 경우에만 바인딩이 쓸 수 있습니다. **전체**는 더 이상 사용되지 않으며 2027년 1월 15일에 제거됩니다. **읽기 전용** 연결은 저장할 때 쓰기 바인딩을 거부합니다.
* **이미 만들어진 대상 객체.** 모델은 사용자가 선택한 객체(기존 테이블, 차원 또는 문서 계정) *안에* 기록합니다. 대상을 먼저 만들고 바인딩하십시오. 이 단계는 새 객체를 만들지 않습니다.

## LLM 단계 추가

1. 워크플로를 열고 **Analyze Steps** 탭으로 이동합니다.
2. 표준 변환을 추가할 때와 같은 방식으로 원하는 위치에 단계를 추가합니다.
3. 단계 유형으로 **LLM 단계**를 선택합니다. 편집기에 **LLM 요청**, **바인딩**, **한도**의 세 섹션이 열립니다.

## 요청 구성

**LLM 요청** 그룹에서 다음을 설정합니다.

* **LLM 연결** *(필수)* — 단계에서 사용하는 LLM 연결입니다.
* **모델** *(선택 사항)* — `claude-opus-4-7`과 같은 특정 모델 이름입니다. 비워 두면 연결의 기본 모델을 사용합니다.
* **프롬프트** *(필수)* — 모델에 전송되는 지시문입니다. `{{tables.NAME}}`, `{{dimensions.NAME}}`, `{{documents.NAME}}`으로 바인딩된 객체를 인라인으로 참조할 수 있으며, 각 참조는 아래에서 선언한 바인딩과 일치해야 합니다. 무엇을 어디에 기록할지 모델에 명확히 알려 주십시오(예: "사업부당 한 행씩 `summary` 테이블에 기록").
* **결과 스키마** *(Anthropic 연결에서는 선택 사항, 다른 공급자에서는 필수)* — 기록용으로 저장되는 실행 요약 구조를 정의하는 JSON 스키마입니다. 제공하는 경우 루트는 `"type": "object"`인 JSON 객체여야 합니다. Anthropic 연결에서는 모델의 실제 작업이 MCP를 통한 쓰기인 경우 비워 둘 수 있습니다. 다른 공급자는 MCP 액세스가 없으므로 구조화된 응답이 유일한 출력이며 스키마가 필요합니다.

## 프로젝트 데이터 바인딩

**바인딩** 섹션에서 액세스를 부여하고 단계가 읽고 쓸 수 있는 대상을 선택합니다. **테이블**, **차원**, **문서**의 세 그룹이 있으며 각각 **추가** 버튼이 있습니다. 모든 행은 다음으로 구성됩니다.

* 객체를 선택하는 **선택기**: 테이블 선택기, 차원 선택기 또는 (문서의 경우) 계정 및 경로 브라우저입니다. 더 이상 ID를 직접 입력할 필요가 없습니다.
* **이름** — 프롬프트에서 참조하는 레이블(`{{tables.NAME}}`)입니다.
* **읽기** 및 **쓰기** 확인란. **읽기**를 선택하면 모델이 객체를 읽을 수 있고, **쓰기**를 선택하면 객체에 기록할 수 있으며, 둘 다 선택할 수도 있습니다. 항상 하나 이상 설정됩니다.
* 문서의 경우 `pdf`와 같은 **형식** 힌트.

모델이 MCP 도구를 통해 각 종류에 쓰는 방식은 다음과 같습니다.

| 바인딩 | 모델이 쓰는 방식 |
|---------|----------------------|
| **테이블**(쓰기) | 행 삽입 — 일반적으로 바인딩된 테이블에 추가할 행을 생성하는 `SELECT`입니다. |
| **차원**(쓰기) | 바인딩된 차원의 계층에 노드를 추가하거나 업데이트합니다. |
| **문서**(쓰기) | 바인딩된 문서 계정과 경로에 파일을 업로드합니다. |

<Aside type="caution">액세스는 확인란별로 바인딩한 객체로만 정확히 제한됩니다. 모델은 읽기로 바인딩된 객체만 읽을 수 있고 쓰기로 바인딩된 객체에만 쓸 수 있습니다. 바인딩하지 않은 객체에는 접근할 수 없으며, 읽기 전용 바인딩에는 쓸 수 없습니다.</Aside>

## 한도

**한도** 그룹은 요청의 범위를 제한합니다.

* **최대 출력 토큰** — 모델이 반환할 수 있는 최대 응답 크기입니다(1,024~128,000, 기본값 16,000).
* **자격 증명 TTL(초)** — 단계의 범위가 지정된 임시 데이터 액세스 자격 증명이 유효한 기간입니다(60~3,600, 기본값 1,800). 단계의 작업은 이 기간으로 제한되므로 모델이 끝낼 수 있을 만큼 길게 설정하되 필요 이상으로 길게 설정하지 마십시오.

## 단계 실행

LLM 단계는 다른 단계와 마찬가지로 전체 워크플로 실행의 일부로, 또는 단독으로 실행됩니다([워크플로에서 단일 단계 실행](/ko/guides/workflows/running-one-step-in-a-workflow/) 참조). 실행되면 단계는 수명이 짧고 범위가 지정된 자격 증명을 발급하고, 프롬프트와 바인딩된 객체를 모델에 보내며, 모델은 MCP 도구를 통해 직접 읽고 씁니다. 자격 증명은 단계가 끝나는 즉시 취소됩니다. 모델 호출은 별도의 작업에서 실행되므로 장시간 실행되는 단계가 워크플로 러너를 점유하지 않습니다.

<Aside type="caution">실행할 때마다 LLM 공급자에 대한 실제 과금 호출이 발생하며 바인딩된 객체에 기록됩니다. 쓰기 바인딩을 다른 변환 대상과 마찬가지로 취급하고, 단계를 운영 데이터에 연결하기 전에 스크래치 테이블에서 테스트하십시오.</Aside>
