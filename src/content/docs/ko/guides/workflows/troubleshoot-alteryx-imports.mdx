PlaidCloud는 Alteryx 워크플로를 고급 워크플로로 가져오며 가져오는 동안 변환 세부 정보를 보고합니다. 이 가이드를 사용하여 종속성 패키지를 빠르게 완성하고, 생성된 매크로를 검토하고, 변수를 조정하고, 검증 비교 결과를 해석하십시오.

<Aside type="note">
  변환 요약부터 확인하십시오. 개별 단계를 살펴보기 전에 종속성, 매크로, 변수, 실행기, 검증 항목이 요약에 강조 표시됩니다.
</Aside>

## 입력 파일 완성

증상:

- 변환 보고서에 누락된 파일이 나열됩니다.
- 실행이 "No files found at &lt;path&gt;; the target table was created empty." 경고와 함께 끝납니다.
- 동적 입력이 파일을 찾지 못합니다.
- 검증 행 수가 예상보다 적습니다.

워크플로는 읽어야 할 파일이 없어도 변환되므로, 보고서를 보면 남은 항목을 가장 빠르게 파악할 수 있습니다. 보고서에는 누락된 각 파일을 업로드할 Document 경로, 원래 Alteryx 경로, 예상 시트, 해당 파일을 읽는 도구가 표시됩니다.

꺼져 있는 Alteryx 도구 컨테이너 안의 도구만 읽는 파일은 해당 도구도 가져오지 않으므로 이 목록에 나타나지 않습니다. [캔버스의 주석과 도구 컨테이너](/ko/guides/workflows/migrate-alteryx-workflows/#캔버스의-주석-및-tool-container)를 참조하십시오. 해당 파일이 포함되도록 하려면 컨테이너를 켜거나, 꺼져 있는 컨테이너의 도구를 일반 단계로 가져오는 옵션을 사용하여 다시 가져오십시오.

조치 사항:

1. 보고서에 나열된 각 파일을 표시된 Document 경로에 업로드합니다.
2. 대부분의 파일은 업로드한 후 워크플로를 다시 실행하면 되며 다시 가져올 필요가 없습니다.
3. 플랫 ASCII 레이아웃, 와일드카드 입력, 동적 입력 템플릿, FirstRow 이름 바꾸기 원본이 누락된 경우에는 다시 실행하는 것만으로는 부족하고 워크플로를 다시 가져와야 합니다. 이 항목들은 변환 시점에 읽기 때문입니다.
4. 업로드 후에도 동적 파일 패턴이 계속 일치하는지 확인합니다.

## 공간 사이드카 파일 완성

증상:

- 공간 입력에 보조 파일이 필요합니다.
- 지오메트리 필드가 비어 있습니다.
- 공간 출력이 예상 결과와 다릅니다.

조치 사항:

1. 모든 shapefile 또는 MapInfo 사이드카 파일이 포함되었는지 확인합니다.
2. 사이드카 파일을 같은 Document 폴더에 보관합니다.
3. 워크플로가 좌표 참조 동작에 의존하는 경우 투영 파일이 있는지 확인합니다.
4. 패키지를 수정한 후 워크플로를 다시 실행합니다.

## 매크로 완성 또는 명확화

증상:

- 매크로 호출을 해석할 수 없습니다.
- 매크로 입력 또는 출력이 연결되어 있지 않습니다.
- 워크플로가 구조적으로는 가져와졌지만 매크로 출력을 연결해야 합니다.

조치 사항:

1. 참조되는 각 매크로의 `.yxmc` 파일을 포함합니다.
2. 해당 매크로가 호출하는 중첩 매크로도 포함합니다.
3. 패키지에 버전별 매크로를 의도적으로 포함하는 경우가 아니라면 중복된 매크로 이름을 피합니다.
4. 생성된 PlaidCloud 매크로에 매크로 입력 및 매크로 출력 단계가 있는지 확인합니다.

## 읽을 수 없는 .yxdb 파일

증상:

- 같은 패키지의 다른 파일은 정상적으로 가져와지는데 `.yxdb` 파일 하나가 가져오기에 실패합니다.
- 파일의 첫 바이트가 `Alteryx Database File`이 아니라 `Alteryx e2 Database file`로 읽힙니다.

이 파일은 Alteryx AMP 엔진이 PlaidCloud에서 읽을 수 없는 독점 형식으로 기록한 것입니다. Alteryx Designer를 아직 사용할 수 있을 때 다시 기록하십시오. 파일을 개별적으로 다시 저장하거나, 다운로드할 수 있는 워크플로로 폴더 전체를 CSV로 일괄 변환할 수 있습니다. [가져오기를 위한 .yxdb 파일 변환](/ko/guides/workflows/convert-yxdb-files-for-import/)을 참조하십시오.

## 읽을 수 없는 .cydb(Calgary) 데이터베이스

증상:

- 변환된 Calgary 단계가 중지되고 아직 존재하지 않는 `calgary_<database>` 테이블을 지정합니다.
- 소스가 `.cydb` 파일입니다. Alteryx가 제공하는 라이선스가 필요한 인구 통계 또는 참조 데이터베이스(Experian, Census 등)인 경우가 많습니다.

Alteryx Calgary 데이터베이스는 공개된 리더가 없는 독점 인덱스 저장소이므로 PlaidCloud는 `.cydb`를 직접 로드할 수 없습니다. Calgary 도구 자체는 변환되며, 각 `.cydb`는 `calgary_<database>`라는 이름의 일반 [대체 테이블](/ko/guides/workflows/migrate-alteryx-workflows/#calgary-데이터베이스)이 됩니다. 단, 해당 테이블의 데이터는 직접 제공해야 합니다.

1. Alteryx에서 `.cydb`를 읽는 Calgary Input을 추가한 다음, 그 레코드를 개방형 형식으로 다시 내보냅니다. **Output Data** 도구로 CSV나 Parquet 또는 웨어하우스 테이블에 내보낼 수 있습니다.
2. 해당 파일을 변환된 워크플로가 기대하는 `calgary_<database>` 테이블로 PlaidCloud에 가져옵니다.
3. Skip Records 또는 Max Records로 읽기 범위가 제한된 경우, 대체 테이블에는 고유한 레코드 순서가 없으므로 내보내기에 순서 열을 포함합니다.

다시 내보낼 수 없는 라이선스 참조 데이터베이스의 경우, 같은 데이터의 라이선스 사본을 직접 준비하여 지정된 테이블에 로드하십시오.

## 워크플로 변수 문제

증상:

- 변환된 앱 입력이 설정되어 있지 않습니다.
- 조건이 예기치 않게 발동합니다.
- 파일 또는 폴더 변수가 데스크톱 경로를 가리킵니다.

조치 사항:

1. 실행하기 전에 워크플로 변수를 검토합니다.
2. 필수 값을 설정합니다.
3. 데스크톱 파일 경로를 Document 파일 또는 폴더 경로로 바꿉니다.
4. 제어되는 선택 항목이 예상한 앱 선택 항목과 일치하는지 확인합니다.
5. 워크플로를 다시 실행합니다.

## 검증 차이

증상:

- 스키마가 다릅니다.
- 행 수가 다릅니다.
- 행 값이 다릅니다.
- 아티팩트 출력에 검토해야 할 차이가 있습니다.

조치 사항:

1. 두 실행에서 같은 입력 데이터를 사용했는지 확인합니다.
2. 변수 값이 일치하는지 확인합니다.
3. 소스 시스템이 같은 스냅샷 날짜의 것인지 확인합니다.
4. null 처리, 날짜 처리, 숫자 정밀도, 문자열 정렬 방식을 검토합니다.
5. 공간 출력의 경우 지오메트리 형식과 좌표 참조 동작을 검토합니다.
6. 아티팩트의 경우 의도한 클라우드 네이티브 출력을 확인하고 비즈니스 내용을 비교합니다.

## 실행기 참고 사항

퍼지 매칭, 공간 처리, PDF 추출, OCR, NLP, 보고와 같은 특수한 작업은 관리형 실행기를 통해 실행할 수 있습니다. (머신러닝 파이프라인은 대신 네이티브 [ML: 모델 학습](/ko/reference/workflow-steps/machine-learning/ml-train/) 및 [ML: 점수 산출](/ko/reference/workflow-steps/machine-learning/ml-score/) 단계로 변환됩니다.)

실행기가 참고 사항을 보고하는 경우:

1. 워크플로 실행 세부 정보를 엽니다.
2. 단계 참고 사항을 검토합니다.
3. 필수 입력과 매개변수가 있는지 확인합니다.
4. 동등성 검증이 필요한 경우 예상 출력을 사용할 수 있는지 확인합니다.
5. 입력이나 설정을 수정한 후 다시 실행합니다.

## 다시 가져와야 하는 경우

다음과 같은 경우에 다시 가져옵니다.

- 원래 패키지 이후에 중요한 파일이나 매크로가 추가된 경우.
- 잘못된 Document 경로를 선택한 경우.
- 더 새로운 워크플로 버전으로 가져온 버전을 대체해야 하는 경우.
- 워크플로 패키지의 종속성 구성을 더 깔끔하게 정리해야 하는 경우.

변수 값, 자격 증명 또는 Document 경로만 바뀐 경우에는 변환된 워크플로를 업데이트하는 것만으로 충분할 수 있습니다.
