고급 워크플로에서는 캔버스의 커넥터가 단계의 실행 순서를 결정합니다. 테이블을 읽는 단계는 그 테이블을 기록하는 단계 뒤에 실행되어야 하지만, 해당 커넥터를 반드시 그리도록 강제하는 것은 없습니다. 커넥터가 없으면 두 단계가 동시에 실행될 수 있고, 두 번째 단계가 첫 번째 단계의 기록이 끝나기 전에 테이블을 읽을 수 있습니다. 변환했거나 복사했거나 다른 워크플로에서 조립한 워크플로에서 흔히 발생합니다.

**종속성 동기화**는 각 단계가 읽고 쓰는 테이블을 확인하여 이러한 단계를 찾고, 순서를 맞추는 커넥터를 제안합니다. 모든 제안을 직접 검토하며, **커넥터 추가**를 선택하기 전에는 아무것도 변경되지 않습니다.

종속성 동기화는 커넥터를 추가만 합니다. 커넥터를 제거하거나 이동하지 않으며, 단계를 변경하지도 않습니다.

## 제안된 커넥터 검토

1. [고급 워크플로 캔버스](/ko/guides/workflows/advanced-workflows/)에서 워크플로를 엽니다.
2. 도구 모음에서 **검사** 옆에 있는 **종속성 동기화**를 선택합니다. Weave에 이미 제안이 있으면 도구 모음 아래의 배너에 알려 줍니다. 예: *Weave suggests 3 connectors so that each step runs after the step that writes a table it reads.* 배너에서 **검토…** 를 선택하면 같은 창이 열립니다.
3. **종속성 동기화** 창에는 행마다 제안이 하나씩 나열됩니다. 예: *Run “Load Sales” before “Report”, which reads “sales”*. 각 행에는 체크박스가 있습니다.
4. 추가할 커넥터는 선택하고 추가하지 않을 커넥터는 선택을 해제합니다.
5. **커넥터 추가**를 선택합니다.

커넥터가 캔버스에 바로 나타납니다. **실행 취소**를 하면 한 번에 모두 제거되고, **다시 실행**을 하면 모두 복원됩니다.

워크플로를 편집하고 해당 테이블을 읽을 수 있는 경우에 **종속성 동기화** 버튼이 표시됩니다.

## 선택되어 있는 제안

두 단계가 모두 **테이블: 추출**, **테이블: 복사**, **테이블: 멜트(열을 행으로)**, **테이블: 피벗(행을 열로)**, **테이블: 피처 빌드**인 경우 제안이 선택된 상태로 표시됩니다. 이 단계들은 테이블 하나를 읽고 실행할 때마다 대상을 교체하므로 순서가 분명합니다.

그 밖의 모든 제안은 나열되지만 선택되지 않습니다. 추가(**테이블: 추가**), 가져오기, 조인 또는 조회를 하는 단계나 **Extract: SQL**처럼 여러 테이블을 읽는 단계가 관련된 경우입니다. 해당 단계가 다른 단계를 기다려야 한다면 선택하십시오.

<Aside type="tip">행을 추가하기 전에 각 행을 읽어 보십시오. 단계가 다른 단계가 *이전* 실행에서 기록한 내용을 읽도록 의도된 경우가 있습니다. 그런 제안은 선택하지 않은 채로 두십시오.</Aside>

## 창에서 추가로 알려 주는 내용

- **이미 잘못된 순서인 단계.** 이미 있는 커넥터 때문에 단계가 자신이 읽는 테이블을 기록하는 단계보다 *먼저* 실행되는 경우, 창에서 그 개수를 알려 줍니다. 종속성 동기화는 단계의 순서를 바꾸지 않으므로, 해당 커넥터는 캔버스에서 확인하십시오.
- **열 수 없는 단계.** 사용자의 역할에서 숨겨진 단계와 관련된 제안은 목록에 표시되지 않고 개수만 집계됩니다.
- **Weave가 검사할 수 없는 워크플로.** 단계가 다른 워크플로를 실행하거나, Weave가 추적할 수 없는 테이블을 사용하거나, 커넥터가 순환을 이루는 경우, 창에서 Weave가 워크플로의 단계 순서를 검사할 수 없다고 알려 주며 아무것도 제안하지 않습니다.
- **추가할 항목 없음.** 모든 단계가 이미 자신이 읽는 테이블을 기록하는 단계 뒤에 실행되는 경우 창에서 그렇게 알려 줍니다.

## Weave가 검사하지 않는 항목

Weave는 순서가 확실한 경우에만 커넥터를 제안합니다. 다음 경우는 판단하지 않습니다.

- 워크플로의 둘 이상의 단계가 기록하거나 다른 워크플로도 기록하는 테이블. 단계가 다른 워크플로의 출력을 읽도록 의도되었을 수 있기 때문입니다. 다른 단계도 기록하는 테이블을 읽고 쓰는 단계도 마찬가지로 처리됩니다.
- 단계가 변수로 선택하는 테이블, 여러 테이블이 공유하는 이름, 뷰 또는 다른 프로젝트의 테이블.
- 워크플로의 단계가 지우거나, 행을 삭제하거나, 삭제(drop)하는 테이블. 테이블을 로드하기 전에 비우는 것은 의도적인 순서이기 때문입니다.
- [실행 컨테이너](/ko/guides/workflows/advanced-workflows/#실행-컨테이너) 안의 단계.
- 사용 안 함 단계와 사용 안 함 컨테이너 안의 단계. 사용 안 함 단계를 거치는 커넥터 경로도 계속 유효한 것으로 계산합니다. 워크플로가 그 단계를 그대로 통과하기 때문입니다.

Weave는 단계가 실행되는 순서를 검사하며, 단계가 생성하는 데이터는 검사하지 않습니다.

## 검토하는 동안 워크플로가 변경되는 경우

창이 열려 있는 동안 다른 사람이 워크플로를 변경했거나 제안이 더 이상 적용되지 않는 경우, **커넥터 추가**를 선택하면 **워크플로 변경됨** 알림이 나타나고 캔버스가 다시 로드됩니다. **종속성 동기화**를 다시 선택하면 Weave가 지금 제안하는 내용을 볼 수 있습니다.

잠긴 워크플로에서는 커넥터를 추가하거나 실행 취소하기 전에 잠금을 해제하십시오.

## Weave가 스스로 찾는 경우

이러한 단계를 찾기 위해 캔버스를 열 필요는 없습니다. Weave는 한 번도 실행된 적이 없는 워크플로를 포함해 모든 고급 워크플로를 백그라운드에서 검사하고, **Weave** 탭에 **Steps that can run before the table they read is written**을 보고합니다. 커넥터가 누락된 경우 해당 결과 항목의 **수정**을 선택하면 워크플로 캔버스에서 이 창이 열립니다. [Weave 결과 항목](/ko/guides/ai-assistant/weave-findings/#현재-weave가-검사하는-항목)을 참조하십시오.
