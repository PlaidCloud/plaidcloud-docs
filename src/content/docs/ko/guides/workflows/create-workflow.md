새 워크플로를 만들려면 기존 프로젝트가 필요합니다. 아직 프로젝트가 없다면 [프로젝트 관리](/ko/guides/projects/managing-projects/)를 참조하십시오.

## 단계

1. 워크플로를 포함할 프로젝트를 엽니다.
2. **워크플로** 탭으로 전환합니다.
3. 도구 모음에서 **새 워크플로**를 클릭합니다.
4. 양식을 작성합니다.
   - **이름** — 짧고 알아보기 쉬운 이름(예: "월 마감 — 실적 로드")
   - **메모** — 맥락을 설명하는 선택 사항의 긴 설명
   - **워크플로 유형** — 표준 직렬(기본값), 표준 병렬 또는 고급 (DAG 캔버스). 아래의 [워크플로 유형 선택](#워크플로-유형-선택)을 참조하십시오.
   - **오류 시 복구 워크플로 트리거** — 선택 사항이며, 활성화하면 복구 워크플로를 지정할 수 있습니다(아래의 [복구 워크플로 정보](#복구-워크플로-정보) 참조).
5. **만들기**를 클릭합니다.

워크플로가 워크플로 탭에 나타나며 단계를 추가할 준비가 됩니다. 더블 클릭하여 [워크플로 탐색기](/ko/guides/workflows/workflow-explorer/)를 열고 구성을 시작하십시오.

## 소스 테이블이 마지막으로 변경된 시점 확인

단계 양식에서 테이블 선택기는 선택한 테이블 아래에 날짜와 시간(사용자의 현지 시간 기준)이 표시된 흐린 **마지막 업데이트** 줄을 보여 주므로 데이터가 최신인지 한눈에 알 수 있습니다. 줄 위에 마우스를 올리면 전체 텍스트가 표시됩니다. 선택이 동적이거나 테이블이 한 번도 업데이트된 적이 없으면 이 줄은 숨겨집니다.

## 워크플로 유형 선택

워크플로를 만들 때 선택하는 **워크플로 유형**에 따라 단계가 배열되고 실행되는 방식이 결정됩니다. 기본값은 **표준 직렬**이며, 새 워크플로 양식의 유형 선택기에서 설정합니다.

| 유형 | 단계가 배열되고 실행되는 방식 |
|------|--------------------------------|
| **표준 직렬** | 단계가 **단계 목록**에서 순서대로 하나씩 실행됩니다. |
| **표준 병렬** | 단계가 **단계 목록**에서 실행되며, 종속성이 허용하는 경우 병렬로 실행됩니다. |
| **고급 (DAG 캔버스)** | 단계가 **시각적 캔버스**에 배치되고 종속성 순서대로 실행되며, 독립적인 브랜치는 병렬로 실행됩니다. 고급 유형에서는 중단점, 컨테이너, 여기서부터 실행, 시뮬레이션, 실시간 공동 작업도 사용할 수 있습니다. |

네 번째 유형인 **매크로**(입력과 출력이 선언된 재사용 가능한 호출형 워크플로)는 곧 제공될 예정이며 선택기에 비활성 상태로 표시됩니다.

:::note
단계는 워크플로에 한 번만 나타날 수 있습니다. 단계를 삽입, 복사, 복제 또는 가져와서 워크플로에 두 번 배치되는 위치에 놓으려 하면 단계 이름과 함께 거부되므로, 앞으로 이런 상태를 만들 수 없습니다. 이 수정 이전부터 워크플로에 단계가 두 곳에 있는 경우, **표준 직렬** 실행은 중복된 단계 이름이 포함된 오류와 함께 즉시 실패합니다. 선택한 종료 단계에서 멈추는 **표준 병렬** 실행도 마찬가지입니다([워크플로의 단계 범위 실행](/ko/guides/workflows/running-a-range-of-steps-in-a-workflow/) 참조). 종료 지점까지 실행하는 경우에도 순차적으로 실행되기 때문입니다. 끝까지 실행하는 **표준 병렬** 실행은 중복을 허용하고 해당 단계를 한 번만 실행합니다. 어느 경우든 중복 단계를 삭제하여 워크플로를 복구하십시오. 단계 삭제는 제한되지 않습니다.
:::

처음부터 [시각적 워크플로 디자이너](/ko/guides/workflows/advanced-workflows/)를 사용하려면 여기서 **고급 (DAG 캔버스)** 을 선택하십시오. 이 선택은 영구적이지 않습니다. 나중에 워크플로 목록에서 **고급으로 변환…** 옵션을 사용하여 표준 워크플로를 승격할 수 있습니다.

## 복구 워크플로 정보

새 워크플로가 오류로 끝나면 PlaidCloud가 이에 대응하여 **복구 워크플로**를 자동으로 실행할 수 있습니다. 다음과 같은 경우에 유용합니다.

- Slack 채널, 이메일 배포 그룹 또는 웹훅으로 알림을 보내 누군가 조사하도록 하기
- 정상 상태로 복원하는 롤백 또는 정리 워크플로 트리거
- 감사 테이블에 실패 기록

복구 워크플로는 선택 사항입니다. 지금은 비워 두었다가 나중에 필요하면 구성할 수 있습니다. 복구 워크플로는 최종 실패에서만 실행되며, 단계별 경고에서는 실행되지 않습니다.
