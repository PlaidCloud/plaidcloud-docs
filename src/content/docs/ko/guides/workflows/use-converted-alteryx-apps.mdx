PlaidCloud는 Alteryx 분석 앱의 질문을 제어되는 워크플로 변수로 변환합니다. 사용자는 실행 전에 이 변수를 설정할 수 있으며, PlaidCloud는 그 값을 식, 필터, 파일 경로, 조건, 매크로 매개변수, 하위 단계 설정에 적용합니다.

<Aside type="note">
  변환된 앱 입력은 반복 가능한 클라우드 실행을 위해 설계되었습니다. 예약된 워크플로에는 저장된 변수 값을, 대화형 실행에는 제어되는 사용자 입력을 사용하십시오.
</Aside>

## App Runner 프런트엔드

Alteryx 분석 앱(`.yxwz`)을 변환하면 해당 앱의 인터페이스도 게시된 Panel "App Runner"로 함께 만들어집니다. 이 앱은 Alteryx 질문이 수집하던 값과 같은 값을 수집하여 그 값으로 변환된 워크플로를 실행하는 작동하는 입력 양식입니다. 이 프런트엔드는 변환 과정에서 자동으로 제공되며, 입력 위젯이 없는 앱은 건너뜁니다.

앱의 질문은 App Runner 컨트롤이 됩니다. 텍스트, 숫자, 날짜, 확인란, 라디오 버튼, 드롭다운, 목록 상자, 트리, 파일 찾아보기, 폴더 찾아보기가 이에 해당합니다. 각 컨트롤은 변환된 단계가 읽는 워크플로 변수에 값을 기록하므로, App Runner에서 실행하면 변수를 직접 설정했을 때와 같은 로직이 실행됩니다. 실제 워크플로 변수에 바인딩되지 않은 컨트롤은 값을 조용히 수집만 하고 어디에도 쓰이지 않게 두는 대신 눈에 보이는 메모와 함께 표시되므로, 검토한 뒤 의도한 변수에 연결하십시오.

양식은 앱 작성자가 구성한 그대로의 그룹, 즉 작성자가 앱을 만들 때 사용한 탭과 레이블이 있는 상자로 배치되며, 작성자의 설명 텍스트(Alteryx Label 도구)도 해당 질문 옆에 함께 표시됩니다. 설계 시점에 고정된 질문, 예를 들어 이를 제어하는 인터페이스 질문이 없는 Detour는 질문으로 표시되지 않습니다.

양식은 워크플로 변수에 저장된 값으로 열립니다. 다른 값을 저장한 사람이 없다면 작성자의 기본값이며, 저장된 값이 없는 질문은 비어 있습니다. 저장된 값이 질문의 선택 항목 중 어느 것과도 더 이상 일치하지 않으면 오래된 선택으로 표시되지 않고 무시됩니다. 숫자 질문은 작성자가 설정한 최솟값, 최댓값, 증분을 적용하므로 작은 범위로 제한된 질문에는 그 범위를 벗어난 값을 입력할 수 없습니다.

변환된 워크플로가 분기되는 곳에서는 App Runner가 분기를 레이블이 있는 선택 항목으로 표시하므로, Alteryx 앱이 경로를 선택하던 방식과 같이 실행이 거치는 경로를 실행 시점에 고를 수 있습니다.

### 파일 및 폴더 질문

각 파일 또는 폴더 질문에는 문서 브라우저를 여는 **찾아보기** 버튼이 있어 경로를 기억에 의존해 입력하는 대신 직접 선택할 수 있습니다.

- 찾아보기는 접근할 수 있는 문서 계정을 보여 주며 기본값은 앱 자체의 계정이고, 계정 간에 전환할 수 있습니다.
- 질문의 현재 답변이 가리키는 폴더에서 열리며, 아직 답변이 없는 질문이면 계정의 최상위에서 열립니다.
- 위쪽의 경로 표시줄로 상위 폴더로 돌아갈 수 있습니다. 목록에서 폴더를 선택하면 열리고, 파일을 선택하면 선택됩니다.
- **선택**을 누르기 전에 채워질 경로가 표시됩니다. 아무것도 강조 표시하지 않은 상태에서 선택을 누르면 현재 보고 있는 폴더가 선택되며, 이것이 계정의 최상위를 선택하는 방법입니다.
- 폴더를 나열할 수 없으면 목록에 그 사실과 이유가 표시되며, 선택은 보이지 않은 경로를 채우지 않습니다. 20초 안에 응답을 받지 못한 목록은 계정이 응답하지 않았다고 알려 줍니다.

## 앱 실행

양식을 작성하고 실행을 누릅니다.

입력한 답변은 해당 실행과 함께 전달되며 그 실행에서만 유지됩니다. 답변은 워크플로에 저장되지 않으므로 한 사람의 답변이 다른 사람의 실행에 영향을 주지 않으며, 앱을 실행하는 데 워크플로를 변경할 권한이 필요하지 않습니다. 이 점은 [행을 제한하는](/ko/administration/access/managing-security-groups-and-assignments/#행을-제한하는-프로젝트를-변경할-수-있는-사용자) 프로젝트에서 중요한데, 해당 프로젝트는 아키텍트만 변경할 수 있기 때문입니다. 양식이 열릴 때 사용하는 값을 바꾸려면 아래 설명처럼 워크플로에 값을 저장하십시오.

답변은 실행이 시작되기 **전에** 검사됩니다. 답변하지 않은 선택형 질문은 한 시간 가까이 걸릴 수 있는 실행 도중에 발견되는 대신, 실행이 시작되기 전에 해당 질문이 지목되며 실행이 중지됩니다.

실행 중에는 양식에 진행률 표시줄, 워크플로의 전체 단계 수를 기준으로 센 `N of M steps`, 경과 시간, 현재 실행 중인 단계가 표시됩니다. 일시 중지와 중지는 실행 중일 때만 실행 옆에 나타나며, 일시 중지 상태에서는 일시 중지가 다시 시작으로 바뀝니다.

실패한 단계는 실패하는 즉시 양식에 지목되고, 실행이 끝나면 양식에 실패한 각 단계의 메시지가 인용됩니다. 중지된 이유를 알기 위해 워크플로를 열 필요가 없습니다. 앞선 단계가 실패하여 실행하지 못한 단계는 실패가 아니라 실행되지 않음으로 따로 표시되며, 진행률 표시줄에는 그대로 포함되어 끝까지 채워집니다.

페이지를 닫거나 연결이 끊겨도 실행은 계속됩니다. 해당 실행이 아직 진행되는 동안 앱을 다시 열면 유휴 상태의 양식 대신 일시 중지와 중지가 있는 진행 중인 실행이 표시됩니다.

실행 옆의 **워크플로 열기** 링크는 기본 워크플로를 새 탭에서 PlaidCloud로 엽니다. DAG 워크플로이면 캔버스에서 열립니다. 양식 자체의 실행 상태 보기가 업데이트를 멈춘 경우에도 작동합니다.

아래 설명처럼 변수를 설정하여 워크플로를 직접 실행할 수도 있습니다. App Runner는 앱 방식의 추가 진입 경로입니다.

## 앱을 최신 상태로 유지

App Runner 앱은 PlaidCloud가 `app.py`, `widget_map.py`, `requirements.txt`를 생성하는 Panel 서버 앱입니다. PlaidCloud가 App Runner를 업데이트하면 기존 앱은 새 버전을 자동으로 반영합니다. 각 앱은 PlaidCloud가 다음에 업데이트될 때 현재 파일로 새로 고쳐지고 다시 빌드되며, [내 Panel 앱](/ko/guides/panel-apps/using/#서버-앱-다시-빌드) 화면에서 앱을 **다시 빌드**하거나 편집할 때마다 다시 그렇게 됩니다. 앱의 설정과 워크플로는 변경되지 않습니다.

- **파일이 저장되는 위치.** 관리형 PlaidCloud Git 연결에서 App Runner 앱은 워크스페이스의 `apps` 리포지토리 안에서 앱 이름을 딴 폴더이며, 다른 Panel 앱 옆에 있습니다. 자체 리포지토리가 있던 앱은 자동으로 해당 폴더로 이동되고, 이전 리포지토리는 보관 처리됩니다(읽기 전용으로 유지되며 삭제되지 않습니다). `apps`에 푸시하면 해당 앱의 폴더 또는 리포지토리 루트의 `requirements.txt`가 변경된 경우에만 앱이 다시 빌드됩니다.
- **잠긴 앱은 그대로 유지됩니다.** 잠금을 해제하고 **다시 빌드**를 클릭하면 최신 상태가 됩니다.
- **생성된 파일을 직접 편집한 내용은 대체됩니다.** 새로 고치면 현재 `app.py`, `widget_map.py`, `requirements.txt`가 변경 내용 위에 기록됩니다. 앱의 Git 기록에는 이전 버전이 남습니다.

## 변환된 입력 유형

PlaidCloud는 일반적인 Alteryx 앱 컨트롤을 유형이 지정된 워크플로 입력으로 변환합니다.

- 텍스트 상자는 텍스트 변수가 됩니다.
- 숫자 컨트롤은 숫자 변수가 됩니다.
- 날짜 컨트롤은 ISO 날짜 변수가 됩니다.
- 확인란, 라디오 버튼, 드롭다운, 목록 상자, 트리는 제어되는 선택 변수가 됩니다.
- 파일 찾아보기 컨트롤은 문서 파일 변수가 됩니다.
- 폴더 찾아보기 컨트롤은 문서 폴더 변수가 됩니다.

변환된 워크플로는 Alteryx 앱이 원래 질문 값을 사용하던 모든 곳에서 이 변수를 사용합니다.

## 실행 전에 값 설정

변환된 앱 워크플로를 실행하기 전에 다음을 수행합니다.

1. 변환된 워크플로를 엽니다.
2. 워크플로 변수를 검토합니다.
3. 필수 텍스트, 숫자, 날짜, 선택, 파일, 폴더 값을 설정합니다.
4. 문서 파일 및 폴더 경로가 가져온 종속 항목의 위치 또는 다른 승인된 문서 경로를 가리키는지 확인합니다.
5. 워크플로를 실행합니다.

예약된 실행의 경우 일정이 실행될 때마다 사용할 변수 값을 저장하십시오.

## 조건, 경고, 오류

Alteryx 앱 조건과 오류 검사는 PlaidCloud 단계 조건으로 변환됩니다. 조건은 다음을 수행할 수 있습니다.

- 워크플로가 계속 진행되도록 허용합니다.
- 경고 메시지를 내보냅니다.
- 앱 규칙에서 요구하면 명확한 오류와 함께 워크플로를 중지합니다.
- 실행을 다른 브랜치로 분기합니다.

PlaidCloud에서 워크플로를 실행하면서 앱 수준의 유효성 검사를 유지하려면 이 동작을 사용하십시오.

## 파일 및 폴더 입력

파일 및 폴더 질문은 문서 경로를 사용합니다.

- 파일 입력은 문서에서 파일을 선택합니다.
- 폴더 입력은 문서 폴더를 선택합니다.
- 가져온 데스크톱 종속 항목은 가져오기 중에 선택한 문서 경로에 저장됩니다.
- 동적 입력 단계는 변수를 사용하여 실행 시점에 최종 문서 경로를 확인할 수 있습니다.

이렇게 하면 변환된 앱을 사용자와 예약된 실행 전반에서 이식할 수 있습니다.

## 매크로 매개변수

변환된 앱이 매크로를 호출하면 앱 변수가 매크로 매개변수를 채울 수 있습니다. PlaidCloud는 매크로 입력 및 제어 매개변수 처리를 통해 이 값을 생성된 매크로 워크플로에 전달합니다.

동시 매크로 실행은 격리되므로 여러 워크플로 실행이 중간 상태를 공유하지 않고 같은 변환된 매크로를 사용할 수 있습니다.

## 검증 체크리스트

변환된 각 앱에서 다음을 확인하십시오.

- 예상되는 모든 질문이 워크플로 변수로 나타납니다.
- 기본값이 구성되어 있던 경우 기본값이 원래 앱과 일치합니다.
- 제어되는 목록에 예상되는 선택 항목이 들어 있습니다.
- 파일 및 폴더 변수가 문서 경로를 가리킵니다.
- 조건이 예상되는 메시지, 경고, 중지 동작을 생성합니다.
- 선택한 변수 값에 대해 출력 일치 검증을 통과합니다.
