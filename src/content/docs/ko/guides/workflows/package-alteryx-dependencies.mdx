PlaidCloud는 Document에서 Alteryx 워크플로 파일을 가져오며, 종속 항목과 아티팩트에는 Document 경로를 사용합니다. 파일을 Document에 업로드하거나, MCP에 연결된 에이전트에게 파일 정리를 요청하거나, Document를 OneDrive, Google Drive, SharePoint, S3, Azure Blob, SFTP 같은 공유 스토리지에 직접 연결할 수 있습니다.

<Aside type="note">
  가져오는 동안 Document 경로 선택기를 사용하여 PlaidCloud가 소스 파일을 읽고 생성된 아티팩트를 저장할 위치를 정확히 선택하십시오.
</Aside>

## 공유 스토리지 업로드 또는 연결

마이그레이션에 가장 적합한 소스 위치를 선택합니다.

- 패키지를 문서 계정에 업로드합니다.
- 기존 공유 스토리지 위치를 문서 계정으로 연결합니다.
- MCP에 연결된 에이전트에게 Document에 이미 있는 파일을 복사, 이동, 이름 변경, 정리하도록 요청합니다.

공유 스토리지 연결을 사용하면 팀이 이미 협업하는 위치에 파일을 그대로 둘 수 있으므로 마이그레이션 준비를 줄일 수 있습니다.

- [Google Drive](/ko/guides/documents/adding-accounts/add-google-drive-account/)
- [OneDrive 또는 SharePoint](/ko/guides/documents/adding-accounts/add-onedrive-account/)
- [AWS S3](/ko/guides/documents/adding-accounts/add-aws-s3-account/)
- [Azure Blob Storage](/ko/guides/documents/adding-accounts/add-azure-blob-storage-account/)
- [SFTP](/ko/guides/documents/adding-accounts/add-sftp-account/)

## 권장 폴더 구조

각 마이그레이션 배치에서는 가져오기 전에 다음과 같은 폴더 구조를 사용합니다.

```text
workflow-package/
  workflows/
  macros/
  inputs/
  expected-outputs/
  reports/
  spatial/
```

이 구조는 선택 사항이지만 검토와 검증이 더 쉬워집니다.

## 워크플로와 매크로

워크플로 파일과 매크로는 예측 가능한 폴더에 둡니다.

- `.yxmd` 및 `.yxwz` 파일은 `workflows/`에 둡니다.
- `.yxmc` 파일은 `macros/`에 둡니다.
- 중첩된 매크로는 나머지 매크로 라이브러리와 함께 보관합니다.
- 의도적으로 버전을 구분한 경우가 아니라면 같은 패키지에 이름이 중복된 매크로를 두지 마십시오.

PlaidCloud는 매크로 소스 파일을 사용하여 PlaidCloud 매크로 워크플로를 만들고, 변환된 워크플로의 매크로 호출을 연결합니다.

## 입력 파일

입력 데이터는 `inputs/` 아래에 둡니다.

- CSV, TSV, 고정 너비, JSON, XML, Excel, Access, YXDB, SAS, SPSS, Stata, Avro, Parquet, HDF 파일
- 수식, 동적 바꾸기, 퍼지 매칭, 조인에서 사용하는 조회 파일
- Directory 및 Dynamic Input 도구에서 참조하는 폴더
- Alteryx 플랫 ASCII 파일: 설명 대상 데이터 옆에 `.flat` 레이아웃 파일을 포함하십시오. 열 너비는 이 파일에만 있으며 변환 시 이를 읽어 단계를 구성합니다. 따라서 레이아웃 파일이 없어도 변환은 되지만, 변환 보고서에 업로드해야 할 파일이 표시됩니다. 단순히 다시 실행하지 말고 해당 파일을 제공한 뒤 워크플로를 다시 가져오십시오.

PlaidCloud가 패키지를 가져오면 변환된 단계가 선택한 Document 위치를 가리킵니다.

## 공간 파일

공간 파일은 `spatial/` 아래에 두고 사이드카를 함께 보관합니다.

- 셰이프파일: `.shp`, `.shx`, `.dbf`, `.prj`를 포함합니다.
- MapInfo 파일: `.tab`, `.map`, `.id`, `.dat`를 포함합니다.
- 투영 파일과 조회 레이어가 있으면 포함합니다.
- KML, GeoJSON 및 기타 공간 입력을 동일한 종속 항목 패키지에 보관합니다.

공간 사이드카를 여러 폴더에 나누지 마십시오. PlaidCloud가 지오메트리를 올바르게 구체화하려면 전체 그룹이 필요합니다.

## 보고서 및 아티팩트 자산

보고서 자산은 `reports/` 아래에 둡니다.

- 보고서 작성기 도구에서 사용하는 이미지
- PDF 입력
- HTML 조각 또는 템플릿
- 보고서 맵에서 사용하는 맵 레이어
- 아티팩트 검증이 필요한 경우 생성된 예시 보고서

변환된 보고서 단계는 Document와 워크플로 실행 기록에서 검토할 수 있는 PlaidCloud 아티팩트를 만듭니다.

## Excel 템플릿

워크플로가 서식이 지정된 Excel 템플릿에 서식이 적용된 출력을 기록하는 경우(서식을 유지하는
[Export to Excel](/ko/reference/workflow-steps/export/export-to-excel/) 단계와
[Export to Excel Sheets](/ko/reference/workflow-steps/export/export-to-excel-sheets/)
단계), 해당 템플릿 통합 문서를 입력과 함께 문서 계정에 준비하십시오. 소스 데이터를 준비한
`03_Inputs` 옆의 `04_Templates` 폴더에 두면 변환된 단계가 채울 템플릿을 읽을 수 있습니다.

<Aside type="caution">
  서식을 유지하도록 변환된 내보내기는 **실행 시점**에 문서 계정에서 템플릿을 읽습니다.
  변환을 실행할 때 템플릿이 없으면 단계는 안전하게 일반 내보내기로 대체됩니다. 그러나
  서식을 유지하도록 변환된 내보내기에서 준비된 템플릿이 실행 시점에 없으면 서식이 없는
  파일을 조용히 기록하지 않고 **명확하게 실패합니다**. 변환된 워크플로를 실행하기 전에
  `04_Templates`를 준비하십시오.
</Aside>

## 예상 출력

예상 출력은 `expected-outputs/` 아래에 둡니다.

- 신뢰할 수 있는 Alteryx 출력 테이블
- 예상 보고서, PDF, 맵, 이미지 또는 차트
- 허용되는 행 순서, 숫자 정밀도, 날짜 처리에 대한 메모

예상 출력은 구조 검증에는 선택 사항이며, 출력 일치 검증을 위한 가장 좋은 근거입니다.

## 외부 연결

데이터베이스, API, 클라우드 소스 워크플로에서는 다음을 기록해 둡니다.

1. 소스 시스템 이름
2. 연결 유형
3. 데이터베이스, 스키마, 테이블, 엔드포인트 또는 버킷 이름
4. 자격 증명 소유자 또는 시크릿 이름
5. 출력 일치가 특정 시점의 소스에 의존하는 경우 스냅샷 날짜

반복 가능한 프로덕션 실행에는 PlaidCloud 연결 또는 자격 증명을 사용하십시오.
