**워크플로** 계층에서 실행 아이콘을 클릭하거나, 특정 워크플로 안의 **작업** 메뉴에서 **Run All**을 선택하면 전체 워크플로 실행을 시작할 수 있습니다.



워크플로 테이블 상단의 **Toggle Start/Stop** 버튼을 클릭할 수도 있습니다. 이 토글 버튼은 실행 중인 워크플로를 중지하거나 워크플로를 시작합니다.

이미 실행 중인 워크플로에서 **실행**을 클릭하면 PlaidCloud는 두 번째 실행을 시작하지 않고 이미 실행 중이라고 알려 줍니다.

## 전기 모드 선택

모든 실행에는 ERP 전기 모드가 적용됩니다. PlaidCloud에서 모드를 선택하려면 워크플로의 마우스 오른쪽 클릭 메뉴에서 **전기 모드로 실행**을 사용하거나 워크플로 캔버스의 실행 모드 버튼을 사용합니다. 일반 **워크플로 시작** 또는 **워크플로 실행**은 Live 모드로 실행되며, 아래에 설명된 프로젝트 상한이 계속 적용됩니다. 실행 API나 어시스턴트를 통해 실행을 시작할 때도 모드를 선택할 수 있습니다.

| 모드 | 동작 |
|---|---|
| Live | 전기 단계가 기존과 똑같이 전기합니다. 기본값입니다. |
| Simulate | 모든 ERP 전기 단계가 전기할 내용을 그대로 구성하고 검증하지만, 아무것도 커밋하지 않으며 ERP에 연결하지도 않습니다. 전기될 항목은 시뮬레이션으로 표시되어 [ERP 전기 이력](/ko/guides/connections/erp-post-history/)에 기록되므로, Live로 실행하기 전에 검토할 수 있습니다. |
| Off | 전기 단계를 완전히 건너뜁니다. |

프로젝트에도 자체 전기 모드 상한이 있으며, 잠기지 않은 프로젝트에 쓰기 권한이 있는 멤버라면 누구나 프로젝트 API나 어시스턴트를 통해 설정할 수 있습니다. 상한은 실행을 더 안전하게 만들 뿐 더 느슨하게 만들지는 않습니다. 실행의 유효 모드는 사용자가 선택한 모드와 프로젝트 상한 중 더 제한적인 쪽이므로, Simulate로 제한된 프로젝트는 Live로 실행을 시작하더라도 계속 시뮬레이션으로 실행됩니다.

[예약된 이벤트](/ko/administration/scheduled-events/event-scheduler/#erp-전기-모드)는 자체 전기 모드를 유지하므로, Simulate로 설정된 일정은 실행될 때마다 시뮬레이션으로 실행됩니다.

모드는 실행이 접하는 모든 항목에 적용됩니다. 하위 워크플로, 매크로, **Run Model**, **Conditional Run Model**, **Loop Model** 단계는 모두 상위 실행의 모드를 상속하며, 중지 후 [재개](#일시-중지-중지-및-재개)하는 실행도 마찬가지입니다. 시뮬레이션 실행은 내부 어디에서도 실제로 전기할 수 없습니다.

:::caution
SAP 전기, SAP 첨부 파일, 일반 SAP RFC 단계는 드라이 런을 지원하지 않습니다. Simulate 또는 Off에서는 이러한 단계를 아예 건너뜁니다. SAP 자체의 테스트 플래그도 SAP에 실제 연결을 열기 때문에, 단계를 건너뛰는 것이 시뮬레이션 실행이 SAP에 도달하지 않도록 하는 유일한 방법입니다.
:::

:::note
개별 ERP 전기 단계에는 위의 실행 전기 모드와는 별개로 자체 Validate Only 설정(일부 단계에서는 Preview 또는 Test Only Mode로 표시)이 있습니다. 단계 편집기는 이 값을 항상 명시적으로 저장합니다. REST API, MCP, 워크플로 번들 가져오기 등 다른 방식으로 작성된 단계 구성에서 이 설정을 아예 생략하면, 이제 실제 전기 대신 미리 보기가 기본값이 됩니다.
:::

## 프로젝트에 전기 권한 부여

워크플로 실행은 실행을 시작한 사람이 아니라 프로젝트의 자격으로 ERP에 전기합니다. 실행이 전기하려면, 전기 단계가 사용하는 각 ERP 연결과 환경에 대해 프로젝트에 승인이 있어야 합니다. 승인이 없으면 단계가 연결과 환경을 명시한 "This project isn't authorized to post to connection …" 오류와 함께 실패합니다. **Call SAP Financial Document Attachment**, **Call SAP Master Data Table RFC**, **Call SAP RFC** 단계에는 승인이 필요하지 않습니다.

프로젝트에 권한을 부여하려면 프로젝트 홈 페이지를 열고 **ERP 전기** 아래에서 **ERP 쓰기 승인**을 선택합니다. 각 행은 하나의 환경에 있는 하나의 연결입니다. 프로젝트가 해당 연결에 전기하도록 허용하려면 **승인됨**을 선택하고, 중지하려면 선택을 해제합니다. **승인자**와 **승인 시각**에는 마지막으로 승인한 사람과 시각이 표시됩니다.

- 이 버튼은 프로젝트의 아키텍트와 워크스페이스 관리자에게 표시되지만, 승인을 변경할 수 있는 사람은 아키텍트뿐이며 프로젝트가 잠기지 않은 경우에만 가능합니다. 아키텍트가 아닌 워크스페이스 관리자는 먼저 자신을 아키텍트로 추가할 수 있습니다.
- 행을 선택해 승인하거나 해제해도 목록이 다시 로드되지 않으므로, 스크롤 위치와 선택한 열 정렬이 그대로 유지됩니다. 창 크기를 조정할 수 있으며, 공개 프로젝트에 대한 안내 문구는 전체가 줄 바꿈되어 표시됩니다.
- 연결을 승인하려면 사용자 본인에게도 해당 연결에 대한 쓰기 권한이 있어야 합니다. 즉, 연결을 소유하고 있거나 이름 또는 사용자가 속한 보안 그룹을 통해 연결이 공유되어 있어야 합니다. **모든 작업 영역 멤버**로 설정된 연결은 해당되지 않습니다.
- **모든 작업 영역 멤버**로 설정된 프로젝트도 다른 프로젝트와 똑같이 승인됩니다. 모든 멤버가 해당 프로젝트의 아키텍트이므로, 연결에 대한 쓰기 권한이 있는 멤버라면 누구나 그 연결에 대해 프로젝트를 승인할 수 있습니다. 승인되고 나면 어떤 멤버든 프로젝트의 워크플로에서 해당 연결로 전기할 수 있으며, 창의 그리드 위에 이 내용이 표시됩니다.
- 복사한 프로젝트나 프로젝트 아카이브로 만든 프로젝트에는 승인이 없는 상태로 시작합니다. 전기하기 전에 복사본을 승인하십시오.

## 단계 상태 확인

워크플로가 실행되는 동안 각 단계에는 현재 상태를 나타내는 상태 아이콘이 표시되며, 실행된 시간도 함께 표시됩니다. 아이콘 위에 마우스를 올리면 해당 상태의 메시지를 볼 수 있습니다.

| 상태 | 의미 |
|---|---|
| Waiting | 단계가 대기열에 있으며 아직 시작되지 않았습니다. |
| Running | 단계가 작업 중이며 소요 시간이 계속 증가합니다. |
| Completed | 단계가 성공적으로 완료되었습니다. |
| Warning | 단계가 완료되었지만 [워크플로 로그](/ko/guides/workflows/viewing-workflow-log/)에서 확인할 만한 내용이 있습니다. |
| Error | 단계가 실패했습니다. [단계 오류 관리](/ko/guides/workflows/managing-step-errors/)를 참조하십시오. |
| Skipped | 단계를 건너뛰었습니다. 단계가 사용 안 함 상태이거나 실행 조건이 충족되지 않았습니다. [워크플로에서 단계 건너뛰기](/ko/guides/workflows/skip-steps-in-a-workflow/)를 참조하십시오. |
| Continued | 단계가 실패했지만 오류 시 계속하도록 설정되어 있어 워크플로가 계속 진행되었습니다. [오류 시 계속](/ko/guides/workflows/continue-on-error/)을 참조하십시오. |
| Stopped | 단계가 끝나기 전에 실행이 중지되었습니다. |
| Abandoned | 단계의 실행이 중단되어 끝나지 않습니다. 실행을 재개하거나 워크플로를 다시 실행하십시오. |

실행이 진행되는 동안 열려 있는 워크플로 보기는 자동으로 새로 고쳐지므로, 페이지를 다시 로드하지 않아도 보고 있는 상태가 최신으로 유지됩니다.

### 포기된 단계

단계를 실행하던 대상이 실행 도중 사라지면 해당 단계는 **abandoned**(포기됨)로 표시됩니다. 대부분 누군가 **중지**를 눌렀거나 플랫폼 유지 보수로 실행이 중단된 경우입니다. 단계의 소요 시간은 더 이상 증가하지 않으며, 상태 툴팁에서 무슨 일이 있었는지 설명합니다.

포기된 단계는 완료되지 않았으며 출력도 생성하지 않았습니다. 느린 단계가 아니며, 데이터나 구성의 문제도 아닙니다.

작업을 다시 이어 가려면 실행을 [**재개**](#일시-중지-중지-및-재개)하거나(포기된 단계가 다시 실행됩니다) 전체 워크플로를 다시 실행하십시오. 두 방법 모두 안전합니다.

### 중단된 단계

단계를 실행하던 서버가 실행 도중 사라지면, PlaidCloud는 반복해도 안전한 경우 해당 단계를 자동으로 다시 실행합니다. 출력을 대체하는 단계는 한 번 깨끗하게 실행한 것과 같은 결과가 되므로 확인할 것이 없습니다.

안전하게 반복할 수 없는 단계는 다시 실행하지 않습니다. 이 경우 단계는 **interrupted**(중단됨) 메시지와 함께 한 번 실패합니다. 두 번째로 실행하면 첫 번째 시도에서 이미 기록한 내용이 중복될 수 있기 때문입니다. 이름이나 경로에 `{date}`가 포함된 출력을 기록하는 단계는 다시 실행하면 다른 날짜로 기록될 수 있으므로 안전하게 반복할 수 없는 것으로 간주합니다. 복구하려면 단계의 대상에서 첫 번째 시도가 기록한 내용을 확인하고 필요하면 정리한 다음, [단계를 다시 실행](/ko/guides/workflows/running-one-step-in-a-workflow/)하거나 실행을 **재개**하십시오.

## 일시 중지, 중지 및 재개

워크플로가 실행되는 동안 **일시 중지**하면 진행 중인 단계는 끝까지 실행되고 새 단계는 대기합니다. **중지**하면 대기열에 있던 단계와 아직 실행 중인 가져오기 또는 내보내기 작업이 취소됩니다.

**재개**는 일시 중지, 중지 또는 실패한 실행을 처음부터 다시 시작하지 않고 중단된 지점부터 이어서 실행합니다. 워크플로의 마지막 실행이 일시 중지, 중지 또는 오류 상태로 끝난 경우 언제든지 사용할 수 있습니다.

"중단된 지점"이 의미하는 바는 워크플로의 실행 방식에 따라 다릅니다.

| 실행 방식 | 재개 시 동작 |
|---|---|
| 직렬 | 실행이 끝났을 때 실행 중이던 단계에서 다시 시작하여 거기서부터 계속합니다. 해당 단계가 그룹 안에 있으면, 재개는 그 단계를 포함하는 최상위 그룹 전체를 대상으로 합니다. 그룹에서 이미 성공적으로 완료된 단계는 그대로 두고 나머지를 실행하며, 그룹 이후부터 실행을 계속합니다. |
| 병렬 | 아직 성공적으로 완료되지 않은 모든 단계를 다시 실행하고, 완료된 단계는 그대로 둡니다. |
| 고급(그래프) | 실패한 노드와 그 노드를 기다리고 있는 모든 노드를 다시 실행하고, 완료된 노드는 그대로 둡니다. |

다른 워크플로를 호출하는 단계인 **Run Model**, **Conditional Run Model**, **Loop Model**은 호출한 워크플로를 처음부터 다시 시작하지 않고 재개하며, 중첩이 몇 단계이든 마찬가지입니다. 반복 단계는 중단된 반복을 재개하고 이미 완료된 반복은 건너뜁니다.

다른 워크플로의 **중첩된 하위**로 실행된 워크플로(상위 워크플로의 **Run Model** 단계가 호출한 워크플로)를 재개하면 PlaidCloud는 **체인 최상위에서 재개**를 제안합니다. 하위 워크플로만 재개해서는 상위 워크플로의 오케스트레이션을 이어 갈 수 없으므로, 이 옵션은 체인의 루트인 최상위 상위 워크플로를 재개하고 중단된 지점부터 전체 체인을 이어서 실행합니다. 최상위 워크플로를 재개하는 동작은 달라지지 않습니다. 체인의 최상위는 같은 프로젝트 안에서 결정되므로, 다른 프로젝트로 이어지는 체인은 프로젝트 내 부분의 최상위에서 재개됩니다.

재개는 항상 **원래** 실행을 이어서 진행합니다. 해당 실행에서 성공적으로 끝나지 않은 모든 단계를 다시 실행하며, 실패했거나 포기된 단계는 완료된 것으로 처리되지 않고 다시 실행됩니다. 그 사이에 개별 단계를 단독으로 다시 실행하더라도 다음 재개가 가져가는 대상은 달라지지 않습니다.

재개된 실행은 다시 실행한 단계만 포함하는 **새 실행**으로 워크플로의 실행 이력에 기록됩니다. 원래 실행은 자체 이력 항목을 그대로 유지합니다.

:::note
반복 단계는 완료된 반복을 변수 값으로 대응시킵니다. 원래 실행과 재개 사이에 반복 대상 데이터가 변경되었다면, 더 이상 대응시킬 수 없는 반복은 건너뛰지 않고 다시 실행됩니다.
:::
