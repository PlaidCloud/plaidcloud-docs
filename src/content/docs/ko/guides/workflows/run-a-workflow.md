**워크플로** 계층에서 실행 아이콘을 클릭하거나, 특정 워크플로의 **작업** 메뉴에서 **Run All**을 선택하면 전체 워크플로를 실행할 수 있습니다.



워크플로 테이블 상단의 **Toggle Start/Stop** 버튼을 클릭할 수도 있습니다. 이 토글 버튼은 실행 중인 워크플로를 중지하거나 워크플로를 시작합니다.

이미 실행 중인 워크플로에서 **실행**을 클릭하면 PlaidCloud는 두 번째 실행을 시작하지 않고 이미 실행 중이라고 알려 줍니다.

## 전기 모드 선택

모든 실행에는 ERP 전기 모드가 있습니다. PlaidCloud에서 모드를 선택하려면 워크플로의 마우스 오른쪽 클릭 메뉴에서 **전기 모드로 실행**을 사용하거나 워크플로 캔버스의 실행 모드 버튼을 사용합니다. 단순히 **워크플로 시작** 또는 **워크플로 실행**을 선택하면 Live로 요청되며, 아래에 설명된 프로젝트의 상한이 여전히 적용됩니다. 실행 API나 어시스턴트를 통해 실행을 시작할 때도 모드를 선택할 수 있습니다.

| 모드 | 동작 |
|---|---|
| Live | 전기 단계가 기존과 똑같이 전기됩니다. 기본값입니다. |
| Simulate | 모든 ERP 전기 단계가 전기할 내용을 그대로 빌드하고 검증한 다음, 아무것도 커밋하지 않으며 ERP에 연결하지도 않습니다. 전기될 항목은 Live로 실행하기 전에 검토할 수 있도록 기록됩니다. **문서 전기** 단계의 항목은 [전기 등록부](/ko/guides/connections/posting-register/)에 **전기 예정**으로 기록되며([ERP 시스템에 문서 전기](/ko/guides/connections/post-documents/) 참조), 시스템 자체 전기 단계의 항목은 [ERP 전기 기록](/ko/guides/connections/erp-post-history/)에 시뮬레이션으로 표시되어 기록됩니다. |
| Off | 전기 단계를 완전히 건너뜁니다. |

프로젝트에도 자체 전기 모드 상한이 있으며, 잠기지 않은 프로젝트에 대한 쓰기 권한이 있는 모든 멤버가 프로젝트 API 또는 어시스턴트를 통해 설정합니다. 상한은 실행을 더 안전하게 만들 뿐 더 허용적으로 만들지는 않습니다. 실행의 유효 모드는 사용자가 선택한 모드와 프로젝트 상한 중 더 제한적인 모드이므로, Simulate로 제한된 프로젝트는 Live로 실행을 시작하더라도 시뮬레이션 상태를 유지합니다.

[예약된 이벤트](/ko/administration/scheduled-events/event-scheduler/#erp-전기-모드)는 자체 전기 모드를 유지하므로, Simulate로 설정된 일정은 실행될 때마다 시뮬레이션으로 실행됩니다.

모드는 실행이 다루는 모든 항목에 전달됩니다. 하위 워크플로, 매크로, **Run Model**, **Conditional Run Model**, **Loop Model** 단계는 모두 상위 실행의 모드를 상속하며, 중지 후 [재개](#일시-중지-중지-재개)하는 실행도 마찬가지입니다. 시뮬레이션 실행은 내부 어디에서도 실제로 전기할 수 없습니다.

:::caution
SAP 전기, SAP 첨부, 일반 SAP RFC 단계는 드라이 런을 지원하지 않습니다. Simulate 또는 Off에서는 완전히 건너뜁니다. SAP 자체의 테스트 플래그도 SAP에 실제 연결을 열기 때문에, 단계를 건너뛰는 것이 시뮬레이션 실행이 SAP에 도달하지 않도록 하는 유일한 방법입니다.
:::

:::note
개별 ERP 전기 단계에는 위의 실행 전기 모드와 별개로 자체 Validate Only 설정(일부 단계에서는 Preview 또는 Test Only Mode로 표시)이 있습니다. 단계 편집기는 이 설정을 항상 명시적으로 저장합니다. REST API, MCP, 워크플로 번들 가져오기 등 다른 방식으로 작성된 단계 구성에서 이 설정을 완전히 생략하면 이제 기본값이 실제 전기가 아니라 미리 보기가 됩니다. **문서 전기** 단계에는 이런 설정이 없으며, 실행의 모드와 해당 시스템 자체의 모드가 전기 여부를 결정합니다. [ERP 시스템에 문서 전기](/ko/guides/connections/post-documents/)를 참조하십시오.
:::

## 프로젝트에 전기 권한 부여

워크플로 실행은 시작한 사람이 아니라 프로젝트의 자격으로 ERP에 전기합니다. 실행이 전기하려면 프로젝트의 전기 단계가 사용하는 각 ERP 연결과 환경에 대한 승인이 프로젝트에 있어야 합니다. 승인이 없으면 단계가 연결과 환경을 명시한 "This project isn't authorized to post to connection …" 오류와 함께 실패합니다. **Call SAP Financial Document Attachment**, **Call SAP Master Data Table RFC**, **Call SAP RFC** 단계에는 승인이 필요하지 않습니다.

프로젝트를 승인하려면 프로젝트 홈 페이지를 열고 **ERP 전기** 아래에서 **ERP 쓰기 승인**을 선택합니다. 각 행은 하나의 환경에 있는 하나의 연결입니다. **승인됨**을 선택하면 프로젝트가 해당 연결에 전기할 수 있고, 선택을 해제하면 중단됩니다. **승인자**와 **승인 시각**에는 마지막으로 승인한 사람과 시각이 표시됩니다.

- 이 버튼은 프로젝트의 아키텍트와 워크스페이스 관리자에게 표시되지만, 승인을 변경할 수 있는 사람은 아키텍트뿐이며 프로젝트가 잠겨 있지 않을 때만 가능합니다. 아키텍트가 아닌 워크스페이스 관리자는 먼저 자신을 아키텍트로 추가할 수 있습니다.
- 행을 선택하여 승인하거나 해제해도 목록이 다시 로드되지 않으므로 스크롤 위치와 선택한 열 정렬이 그대로 유지됩니다. 창 크기를 조정할 수 있으며, 공개 프로젝트에 관한 안내는 전체가 줄 바꿈되어 표시됩니다.
- 연결을 승인하려면 본인도 해당 연결에 대한 쓰기 권한이 있어야 합니다. 즉, 직접 소유하고 있거나, 이름으로 또는 보안 그룹을 통해 공유받은 연결이어야 합니다. **모든 작업 영역 멤버**로 설정된 연결은 해당하지 않습니다.
- **모든 작업 영역 멤버**로 설정된 프로젝트도 다른 프로젝트와 똑같이 승인됩니다. 모든 멤버가 해당 프로젝트의 아키텍트이므로, 연결에 대한 쓰기 권한이 있는 모든 멤버가 해당 프로젝트에 대해 승인할 수 있습니다. 승인이 완료되면 모든 멤버가 프로젝트의 워크플로에서 해당 연결로 전기할 수 있으며, 창의 그리드 위에 이 내용이 표시됩니다.
- 테이블 데이터 또는 차원 멤버와 함께 만든, 사용자만 볼 수 있는 새 복사본은 사용자가 직접 부여할 수 있는 원본의 승인을 유지하며, 원본이 Live였다면 Simulate 상태로 생성됩니다. [복사본의 ERP 쓰기 승인](/ko/guides/projects/managing-projects/#사본의-erp-쓰기-승인)을 참조하십시오. 그 외의 복사본이나 프로젝트 아카이브에서 만든 프로젝트에는 승인이 없는 상태로 시작합니다. 전기하기 전에 승인하십시오.

## 단계 상태 확인

워크플로가 실행되는 동안 각 단계에는 현재 상태를 나타내는 상태 아이콘과 실행된 시간이 함께 표시됩니다. 아이콘 위에 포인터를 올리면 해당 상태의 메시지를 볼 수 있습니다.

| 상태 | 의미 |
|---|---|
| 대기 중 | 단계가 대기열에 있으며 아직 시작되지 않았습니다. |
| 실행 중 | 단계가 작업 중이며 진행되는 동안 실행 시간이 증가합니다. |
| 완료됨 | 단계가 성공적으로 완료되었습니다. |
| 경고 | 단계는 완료되었지만 [워크플로 로그](/ko/guides/workflows/viewing-workflow-log/)에서 확인할 만한 내용이 표시되었습니다. |
| 오류 | 단계가 실패했습니다. [단계 오류 관리](/ko/guides/workflows/managing-step-errors/)를 참조하십시오. |
| 건너뜀 | 단계를 건너뛰었습니다. 비활성화되었거나 실행 조건이 충족되지 않았기 때문입니다. [워크플로에서 단계 건너뛰기](/ko/guides/workflows/skip-steps-in-a-workflow/)를 참조하십시오. |
| 계속됨 | 단계가 실패했지만 오류 시 계속하도록 설정되어 있어 워크플로가 계속 진행되었습니다. [오류 시 계속](/ko/guides/workflows/continue-on-error/)을 참조하십시오. |
| 중지됨 | 단계가 끝나기 전에 실행이 중지되었습니다. |
| 중단됨 | 단계의 실행이 중단되어 끝낼 수 없습니다. 실행을 재개하거나 워크플로를 다시 실행하십시오. |

실행이 진행되는 동안 열려 있는 워크플로 보기는 자동으로 새로 고쳐지므로 페이지를 다시 로드하지 않아도 표시된 상태가 최신으로 유지됩니다.

### 중단된 단계

단계를 실행하던 대상이 실행 도중 사라지면 단계가 **abandoned**로 표시됩니다. 가장 흔한 원인은 누군가 **중지**를 눌렀거나 플랫폼 유지 관리로 실행이 중단된 경우입니다. 단계의 실행 시간 증가가 멈추고 상태 툴팁에 무슨 일이 있었는지 설명됩니다.

중단된 단계는 완료되지 않았으며 출력도 생성하지 않았습니다. 느린 단계가 아니며, 데이터나 구성의 문제도 아닙니다.

작업을 다시 이어가려면 실행을 [**재개**](#일시-중지-중지-재개)하거나 전체 워크플로를 다시 실행합니다. 재개하면 중단된 단계가 다시 실행됩니다. 두 방법 모두 안전합니다.

### 인터럽트된 단계

단계를 실행하던 서버가 실행 도중 사라지면, 반복해도 안전한 경우 PlaidCloud가 해당 단계를 자동으로 다시 실행합니다. 출력을 대체하는 단계는 한 번 깔끔하게 실행한 것과 같은 결과가 되므로 확인할 필요가 없습니다. 두 번째 시도가 시작되는 지점에는 단계 로그에 "Restarted: the server running this step stopped before it finished (e.g. out of memory or a restart); running it again from the start."라는 경고가 표시됩니다.

안전하게 반복할 수 없는 단계는 다시 실행되지 않습니다. 두 번째 실행이 첫 번째 시도에서 이미 기록한 내용을 중복시킬 수 있으므로, **interrupted** 메시지와 함께 한 번 실패합니다. 이름이나 경로에 `{date}` 또는 `{date_iso}`가 있는 출력을 쓰는 단계는 다시 실행하면 다른 날짜에 기록될 수 있으므로 안전하게 반복할 수 없는 것으로 간주됩니다. 복구하려면 단계의 대상에서 첫 번째 시도가 기록한 내용을 확인하고 필요하면 정리한 다음, [단계를 다시 실행](/ko/guides/workflows/running-one-step-in-a-workflow/)하거나 실행을 **재개**하십시오.

### 시작되지 않는 단계

단계가 워커를 기다리는 동안 상태 메시지에 "Waiting for a worker… N min. No import worker has picked this step up yet."가 표시됩니다(워커의 종류는 가져오기나 내보내기 등 단계에 따라 다릅니다). 작업이 시작되면 메시지가 사라집니다.

단계의 작업이 시작될 수 없는 경우에는 무한정 기다리지 않고 원인과 함께 단계가 실패합니다.

| 원인 | 실패까지 걸리는 시간(약) |
|---|---|
| 가져오기 또는 차원 단계의 작업을 맡는 워커가 없음 | 40분 |
| 단계의 파드가 Pending 상태에 머무름 | 20분 |
| 단계의 이미지를 가져올 수 없음 | 5분 |
| 단계에 대해 파드가 생성되지 않음 | 20분 |
| 커넥터(Singer) 동기화를 맡는 러너가 없음 | 30분 |

커넥터 동기화 메시지에는 동기화 이름이 표시됩니다. 워커가 작업을 시작한 뒤 사라진 경우에도 워커가 중지되었다는 메시지와 함께 단계가 실패합니다. 가져오기 및 차원 메시지에는 "Use Run from here to retry."가 포함됩니다.

### 응답하지 않는 실행

실행을 뒷받침하던 작업이 사라진 뒤에도 실행이 **실행 중** 상태로 남아 있지는 않습니다. 워크플로를 실행하던 서버가 사라지면 해당 실행은 실패로 끝납니다. 실행은 최대 12시간까지 지속될 수 있으며, 그 시점에 아직 실행 중인 실행은 "Run failed: still running at the 12-hour limit. Re-run the workflow." 메시지와 함께 실패합니다.

## Run Insight

Run Insight는 워크플로를 한 번 실행하는 동안 시간이 어디에 쓰였는지, 그리고 어떤 단계가 평소보다 오래 또는 짧게 걸렸는지 보여 줍니다. 각 단계를 그 단계 자체의 최근 실행과 비교하여 판정하므로, 항상 느린 단계가 따로 지목되지 않습니다.

### Run Insight 열기

- 캔버스에서 도구 모음의 **기록**을 클릭합니다. [시각적 워크플로 디자이너](/ko/guides/workflows/advanced-workflows/)를 참조하십시오.
- **워크플로** 탭에서 워크플로 하나를 선택하고 **작업** 메뉴나 마우스 오른쪽 클릭 메뉴에서 **Run Insight**를 선택합니다.
- 홈에서 워크플로 카드의 **최근 실행 열기**를 선택합니다.
- 실행 기록 대화 상자에서 **실행 횟수** 테이블의 실행을 골라 **Insight에서 열기**를 선택하거나, 해당 행을 엽니다.
- 느린 실행에 대한 앱 내 Weave 메시지에서 **실행 열기**를 클릭합니다. [실행 종료 알림 받기](/ko/guides/ai-assistant/weave-findings/#실행이-끝날-때-알림-받기)를 참조하십시오.

대화 상자의 제목은 **실행 기록** — 워크플로 이름입니다. **Insight** | **실행 횟수** 스위치로 이 뷰와 과거 실행 테이블 사이를 전환합니다. 인스펙터에서 연 단계 자체의 실행 기록에는 테이블만 표시됩니다.

### 요약 줄과 확인이 필요한 항목 읽기

요약 줄은 실행 결과를 한 줄로 알려 줍니다. *시간* **소요**, 실행 중에는 *시간*째 **실행 중**, 중지된 최근 실행에는 *시간* 후 **중지됨**, 또는 실패한 워크플로가 있는 *워크플로*에서 **실패**입니다. 그 아래 문장은 평소보다 느리게 실행된 단계, 대기에 쓰인 시간, 또는 이력이 있는 모든 단계가 평소 범위 안에서 실행되었다는 점처럼 눈에 띄는 내용을 알려 줍니다. 그다음에는 시작 시간, 워크플로와 단계의 수, 그리고 일부 단계의 이력이 너무 적어 판정할 수 없을 때 그 수가 표시됩니다. 확인이 필요한 항목이 있으면 요약 줄 옆에 **확인할 항목** *N*개 형태로 개수가 나타납니다.

요약 줄 옆에는 위에 캡션이 달린 최근 실행의 띠가 있습니다. 각 막대는 하나의 실행이며 소요 시간만큼 높고, 날짜는 날짜가 바뀌는 곳에만 표시됩니다. 띠에서 실행을 클릭하면 그 실행이 열립니다. 빨간 캡과 ✕는 실패한 실행을, 점선 윤곽은 최근 실행 대부분보다 적은 단계를 실행한 실행을 나타내며, 후자는 전체 실행과 비교할 수 없기 때문입니다.

**확인이 필요한 항목**에는 실패가 먼저, 그다음 평소를 넘은 시간, 그다음 대기 순으로 나열됩니다. 각 항목은 카드이며 이름, 손실된 시간 또는 **실패**, 위치, 그리고 시간을 나타내는 막대가 표시되는데, 회색은 평소 범위 안, 황색은 그 초과이며, 실패 항목의 막대는 빨간색입니다. 마지막 실행 이후 저장된 단계에는 *날짜* **저장됨** 태그가 붙습니다. 카드를 클릭하면 뷰에서 해당 항목이 선택되며, 선택된 카드는 강조 표시됩니다.

### 흐름, 타임라인, 테이블

뷰 위의 헤더에는 워크플로 이름, 그다음 **비교 대상**, 그다음 **뷰**가 있으며, **뷰**의 **흐름**, **타임라인**, **테이블** 버튼으로 뷰를 선택합니다. 오른쪽 끝에는 새로 고침 버튼이 있습니다.

| 뷰 | 표시 내용 |
|---|---|
| **흐름** | 높이가 시간을 나타내는 블록입니다. 황색은 단계의 평소를 넘은 시간입니다. 열지 않았지만 실패를 포함하는 블록은 ✕와 빨간 윤곽으로 표시됩니다. 이름을 표시하기에 너무 짧은 실패 블록이나 선택된 블록은 더 크게 그려지며, 범례에 이때는 축척에 맞지 않는다고 표시됩니다. 단계가 다른 워크플로를 호출한 경우, **호출 오버헤드** 조각은 해당 워크플로 밖에서 단계 자체가 쓴 시간입니다. 실행 중인 단계가 없던 경우에는 **대기 중** 조각이 그 공백을 보여 주며, 병렬로 실행된 워크플로에는 이 조각이 그려지지 않습니다. |
| **타임라인** | 실행 시작부터의 시계 시간입니다. 점선 윤곽은 비교 대상 실행에서 블록에 걸린 시간입니다. |
| **테이블** | 호출 순서대로 모든 항목을 표시하며, 열은 **이름**, **이번 실행**, **평소**, **추가**, **비교 대상 실행**, **상태**입니다. |

다른 워크플로를 호출한 워크플로는 그 안에 호출된 워크플로를 표시합니다. 워크플로 블록을 두 번 클릭하거나 **확대**를 선택하면 그 안에서 작업할 수 있으며, 돌아오려면 뷰 위의 경로를 사용합니다. 정상 속도 단계 여러 개가 함께 있으면 **흐름**은 이를 하나의 **정상 속도** *N* 블록으로 접으며, 이를 클릭하거나 경로 오른쪽의 **블록** *개수***개 모두 표시**를 클릭하면 펼쳐지며, 개수는 뷰에 있는 모든 블록의 수입니다. **정상 속도 블록 접기**는 다시 접으며, 이 버튼은 접을 수 있는 항목이 있을 때만 나타납니다.

블록을 선택하면 세부 정보 패널이 표시됩니다. 패널에는 블록의 이름과 위치, 아래 표시 중 하나가 담긴 상태 알약, 그리고 **이번 실행**, **평소**, **기록**, **평소 초과**, **비교 대상 실행** 중 해당하는 항목의 행이 나옵니다. 그 뒤에 추세선이 이어집니다. 실행 자체의 워크플로에는 최근 완료된 실행들이 표시되며 이번 실행이 완료되었으면 점으로 표시되고, 평소 범위가 있는 단계에는 그 범위가 띠로, 이번 실행이 점으로 표시됩니다. 참고 사항은 표시를 설명하며, 버튼은 **워크플로에서 표시**, **단계 표시** 또는 **확대**, **워크플로 열기**, **실행 로그 보기**입니다. **워크플로 열기**는 캔버스에서 워크플로를 열고 **실행 로그 보기**는 해당 [로그](/ko/guides/workflows/viewing-workflow-log/)를 엽니다.

### 표시의 의미

| 표시 | 의미 |
|---|---|
| **실패** | 단계가 오류로 끝났습니다. 패널에 해당 메시지가 표시되지만, 역할로는 단계의 이름을 볼 수 없는 경우에는 표시되지 않습니다. |
| **평소보다 느림** | 단계가 평소 범위보다 오래 걸렸습니다. |
| **전반적으로 느림** | 워크플로의 모든 단계가 비슷한 정도로 느려졌으며, 이는 단계 하나가 아니라 워크플로 전체가 공유하는 무언가를 가리킵니다. 해당 단계에는 **공통 지연의 일부**가 표시됩니다. |
| **느린 단계 있음** | **내부의 느린 단계**가 있는 워크플로입니다. |
| **정상 속도** | 단계가 평소 범위 안에서 실행되었습니다. |
| **더 빠름** | 단계가 평소 범위보다 빠르게 실행되었습니다. |
| **이력 부족** | 단계가 평소 범위를 가질 만큼 자주 실행되지 않아 판정하지 않습니다. |
| **오류, 계속됨** | 단계가 실패했지만 [오류 발생 시 계속](/ko/guides/workflows/continue-on-error/)으로 설정되어 있습니다. |
| **건너뜀** | 단계가 건너뛰어졌습니다. |
| **실행 중** | 단계가 아직 끝나지 않았습니다. |

최근 실행이 이미 느렸거나 편차가 큰 단계는 플래그가 지정되지 않을 수 있습니다. 기간 말의 실행을 평범한 날과 비교하면 전반적으로 느리게 보일 수 있습니다. 이전에 중지된 실행은 중지된 실행이 아니라 짧은 실행으로 표시됩니다.

패널은 표시를 설명해 주기도 합니다. **대기 중**은 실행 중인 단계가 없던 시간이므로 어떤 단계도 원인이 아닙니다. 평소보다 느리게 실행된 단계에서는 **기록된 행**이 그 출력을 평소 개수와 비교하며, 행 수준 보안이 읽을 수 있는 내용을 걸러 내는 경우에는 표시되지 않습니다. 마찬가지로 평소보다 느리게 실행된 단계에서는 **마지막 실행 이후 저장됨**은 단계가 이전 실행 이후, 이번 실행이 시작되기 전에 저장되었다는 뜻이며, 기록에는 저장 사실만 남고 무엇이 바뀌었는지는 남지 않습니다. **다른 작업**은 실행되지 않은 단계와 작업 없이 실행된 단계의 수를 각 단계의 이력을 기준으로, 다른 실행과 비교할 때는 그 실행을 기준으로 셉니다. **병렬 실행**은 워크플로의 각 부분이 동시에 실행되어 시간의 합이 시계 시간보다 크다는 뜻입니다. **호출자 불확실**은 이력만으로는 어떤 단계가 워크플로를 호출했는지 알 수 없다는 뜻입니다. **이름 숨김**은 역할로는 이름을 볼 수 없는 단계나 워크플로를 나타내며, **숨겨진 단계** 또는 **숨겨진 워크플로**로 표시됩니다.

### 비교 대상

**비교 대상**은 실행을 무엇과 비교할지 정합니다. 메뉴 버튼에는 선택한 항목이 표시되며, **평소**, **평소 + 이전 실행**, 또는 **평소 +** *시작 시간* **실행**(선택한 실행의 시작 시간)입니다. **평소**는 각 단계의 최근 실행을 사용합니다. **평소 + 이전 실행**과 **평소 + 선택한 실행**은 해당 실행에서의 각 단계 시간도 추가하며, 이는 **타임라인**에 윤곽으로, **테이블**에는 **비교 대상 실행** 아래에 표시됩니다. **평소 + 선택한 실행**은 고를 수 있는 최근 실행 목록을 엽니다.

### 더 큰 실행 안의 워크플로 하나

다른 워크플로가 호출한 워크플로를 열면 Insight에는 그 워크플로가 담당한 부분의 실행만 표시됩니다. **전체 실행 열기**는 실행을 시작한 워크플로로 대화 상자를 다시 엽니다.

### 진행 중인 실행

아직 진행 중인 실행은 대화 상자가 표시되는 동안 30초마다 다시 읽습니다. 확대 상태, 선택, 뷰는 그대로 유지됩니다. Insight에서 **실행 횟수**로 이동하면 갱신이 멈추고, Insight로 돌아오면 실행을 다시 읽고 재개합니다. 새로 고침 버튼(헤더 오른쪽 끝의 원형 화살표)은 실행을 처음부터 다시 불러오며 확대 상태와 선택을 초기화하고 정상 속도 블록을 다시 접습니다.

### AI 어시스턴트와 REST API용

같은 프로파일을 대화 상자 밖에서도 사용할 수 있습니다.

- REST: `project_id`와 `workflow_id`를 지정한 `GET /rest/v1/analyze/workflow/run-insight`. `run_id`로 실행을 고르며(생략하면 최근 실행), `baseline`은 `typical`, `previous` 또는 `run:<id>`입니다.
- MCP: `include=['run_insight']`를 지정한 `workflow_describe`이며, `run_id`와 `baseline`을 선택적으로 지정할 수 있습니다.

각 워크플로와 단계에 대해 시간, 실행 내 위치, 자체 이력에 대한 판정, 그리고 그 이유가 반환됩니다. 존재하지 않는 실행이나 단계 행이 없는 실행은 오류 대신 프로파일 없이 경고를 반환합니다.

## 일시 중지, 중지, 재개

워크플로가 실행되는 동안 **일시 중지**하면 진행 중인 단계는 끝까지 실행되고 새 단계는 대기하며, **중지**하면 대기열에 있던 단계와, 몇 초 이내에 아직 실행 중인 가져오기 또는 내보내기 작업이 내보내기가 읽고 있던 웨어하우스 쿼리와 함께 취소됩니다. 대기열에 있던 가져오기 및 차원 단계는 깔끔하게 취소되므로 워크스페이스의 이후 가져오기와 차원 로드를 지연시키지 않습니다. 중지하면 워크플로의 대기 중이거나 실행 중인 커넥터(Singer) 동기화도 함께 중지되므로, 워크플로가 중지된 후에도 동기화가 계속 실행되지 않습니다.

**중지**를 누르면 실행 중인 가져오기 또는 내보내기 작업은 새로운 쓰기를 시작하지 않습니다. 내보내기는 파일을 업로드하지 않고, 가져오기는 테이블을 로드하지 않습니다. 이미 진행 중인 쓰기는 먼저 끝까지 완료되므로 파일, 테이블, 차원이 반쯤 기록된 채로 남지 않습니다. 여러 파일을 내보내거나 여러 테이블을 내보내는 경우, 이미 기록된 파일은 그대로 유지됩니다. 도중에 중지된 여러 파일 CSV 내보내기는 이미 폴더를 비운 상태이므로, 폴더에는 해당 파일만 남고 이전 실행의 파일은 남지 않습니다. 차원 로드와 MongoDB 또는 Kafka 내보내기는 진행하면서 기록하므로, 이미 시작된 것은 끝까지 실행됩니다. **SQL 가져오기** 또는 **외부 데이터베이스 테이블 가져오기** 단계는 PlaidCloud가 소스의 쿼리를 취소하지 않으므로, 소스 데이터베이스가 읽고 있던 내용을 반환한 후에 중지됩니다. Databend에서는 Databend가 문서 계정에 직접 기록하는 내보내기가 하나의 쓰기이므로, 끝까지 실행되어 파일을 기록합니다.

매크로는 다른 워크플로나 **매크로: 동시 실행** 단계에서 호출되어 여러 곳에서 동시에 실행될 수 있습니다. 매크로를 중지하면 실행 중인 모든 사본이 중지됩니다. 사본 하나를 중지하면 그 사본과 그 사본이 시작한 것만 중지되고 그 사본을 호출한 워크플로는 계속 실행되며, 응답하지 않게 된 사본을 **Macro Concurrent** 단계가 포기하는 경우에도 마찬가지입니다. 다른 워크플로 안에서만 실행 중인 매크로는 워크플로 목록에 **실행 중**으로 표시되고 **중지**를 사용할 수 있으며, 매크로를 열면 최근 실행에서의 각 단계의 상태, 시작 시간, 종료 시간이 표시됩니다.

**재개**는 일시 중지, 중지 또는 실패한 실행을 처음부터 다시 시작하지 않고 중단된 지점부터 이어서 실행합니다. 워크플로의 마지막 실행이 일시 중지, 중지 또는 오류 상태로 끝난 경우 언제든지 사용할 수 있습니다.

"중단된 지점"의 의미는 워크플로가 실행되는 방식에 따라 다릅니다.

| 실행 방식 | 재개 시 동작 |
|---|---|
| 직렬 | 실행이 끝났을 때 실행 중이던 단계에서 다시 시작하여 거기서부터 계속합니다. 해당 단계가 그룹 안에 있으면 재개는 그 단계를 포함한 최상위 그룹 전체를 다시 가져옵니다. 그룹에서 이미 성공적으로 끝난 단계는 그대로 두고 나머지를 실행하며, 그룹 이후부터 실행이 계속됩니다. |
| 병렬 | 아직 성공적으로 끝나지 않은 모든 단계를 다시 실행하고 완료된 단계는 그대로 둡니다. |
| 고급(그래프) | 실패한 노드와 그 노드를 기다리는 모든 항목을 다시 실행하고 완료된 노드는 그대로 둡니다. |

다른 워크플로를 호출하는 단계인 **Run Model**, **Conditional Run Model**, **Loop Model**은 호출한 워크플로를 다시 시작하지 않고 재개하며, 중첩 수준에 관계없이 동일하게 적용됩니다. 루프 단계는 중단된 반복을 재개하고 이미 완료된 반복은 건너뜁니다.

다른 워크플로의 **중첩된 하위**(상위의 **Run Model** 단계가 호출한 워크플로)로 실행된 워크플로를 재개하면 PlaidCloud가 **체인 최상위에서 재개**를 제공합니다. 하위 워크플로만 단독으로 재개해서는 상위의 오케스트레이션을 이어갈 수 없으므로, 이 옵션은 대신 최상위 상위 워크플로(체인의 루트)를 재개하고 전체 체인을 중지된 지점부터 계속합니다. 최상위 워크플로의 재개는 변경되지 않습니다. 체인의 최상위는 같은 프로젝트 안에서 결정되며, 다른 프로젝트에 걸친 체인은 프로젝트 내 부분의 최상위에서 재개됩니다.

재개는 항상 **원래** 실행을 이어갑니다. 해당 실행에서 성공적으로 끝나지 않은 모든 단계를 다시 실행하며, 실패했거나 중단된 단계는 완료된 것으로 취급하지 않고 다시 실행합니다. 그 사이에 개별 단계를 따로 다시 실행해도 재개가 다음에 이어받는 내용은 달라지지 않습니다. 이는 하위 워크플로에도 마찬가지입니다. 하위 워크플로의 단계 하나를 따로 다시 실행했더라도, 상위 워크플로를 재개하면 해당 단계만이 아니라 하위 워크플로에 남아 있던 모든 작업이 실행됩니다.

재개된 실행은 워크플로의 실행 기록에 **새 실행**으로 기록되며, 다시 실행한 단계만 포함합니다. 원래 실행은 자체 기록 항목을 유지합니다. 하나의 실행이 같은 하위 워크플로를 여러 번 호출하면, 각 호출은 하위 워크플로의 실행 기록에 각자의 항목을 가집니다. 루프 단계의 반복은 하나의 호출로 간주됩니다.

:::note
루프 단계는 완료된 반복을 변수 값으로 대조합니다. 원래 실행과 재개 사이에 루프가 반복하는 데이터가 변경되면, 더 이상 대조할 수 없는 반복은 건너뛰지 않고 다시 실행됩니다.
:::
