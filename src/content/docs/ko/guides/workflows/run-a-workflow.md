**워크플로** 계층에서 실행 아이콘을 클릭하거나, 특정 워크플로의 **작업** 메뉴에서 **Run All**을 선택하면 전체 워크플로를 실행할 수 있습니다.



워크플로 테이블 상단의 **Toggle Start/Stop** 버튼을 클릭할 수도 있습니다. 이 토글 버튼은 실행 중인 워크플로를 중지하거나 워크플로를 시작합니다.

이미 실행 중인 워크플로에서 **실행**을 클릭하면 PlaidCloud는 두 번째 실행을 시작하지 않고 이미 실행 중이라고 알려 줍니다.

## 전기 모드 선택

모든 실행에는 ERP 전기 모드가 있습니다. PlaidCloud에서 모드를 선택하려면 워크플로의 마우스 오른쪽 클릭 메뉴에서 **전기 모드로 실행**을 사용하거나 워크플로 캔버스의 실행 모드 버튼을 사용합니다. 단순히 **워크플로 시작** 또는 **워크플로 실행**을 선택하면 Live로 요청되며, 아래에 설명된 프로젝트의 상한이 여전히 적용됩니다. 실행 API나 어시스턴트를 통해 실행을 시작할 때도 모드를 선택할 수 있습니다.

| 모드 | 동작 |
|---|---|
| Live | 전기 단계가 기존과 똑같이 전기됩니다. 기본값입니다. |
| Simulate | 모든 ERP 전기 단계가 전기할 내용을 그대로 빌드하고 검증한 다음, 아무것도 커밋하지 않으며 ERP에 연결하지도 않습니다. 전기될 항목은 시뮬레이션으로 표시되어 [ERP 전기 기록](/ko/guides/connections/erp-post-history/)에 기록되므로 Live로 실행하기 전에 검토할 수 있습니다. |
| Off | 전기 단계를 완전히 건너뜁니다. |

프로젝트에도 자체 전기 모드 상한이 있으며, 잠기지 않은 프로젝트에 대한 쓰기 권한이 있는 모든 멤버가 프로젝트 API 또는 어시스턴트를 통해 설정합니다. 상한은 실행을 더 안전하게 만들 뿐 더 허용적으로 만들지는 않습니다. 실행의 유효 모드는 사용자가 선택한 모드와 프로젝트 상한 중 더 제한적인 모드이므로, Simulate로 제한된 프로젝트는 Live로 실행을 시작하더라도 시뮬레이션 상태를 유지합니다.

[예약된 이벤트](/ko/administration/scheduled-events/event-scheduler/#erp-전기-모드)는 자체 전기 모드를 유지하므로, Simulate로 설정된 일정은 실행될 때마다 시뮬레이션으로 실행됩니다.

모드는 실행이 다루는 모든 항목에 전달됩니다. 하위 워크플로, 매크로, **Run Model**, **Conditional Run Model**, **Loop Model** 단계는 모두 상위 실행의 모드를 상속하며, 중지 후 [재개](#일시-중지-중지-재개)하는 실행도 마찬가지입니다. 시뮬레이션 실행은 내부 어디에서도 실제로 전기할 수 없습니다.

:::caution
SAP 전기, SAP 첨부, 일반 SAP RFC 단계는 드라이 런을 지원하지 않습니다. Simulate 또는 Off에서는 완전히 건너뜁니다. SAP 자체의 테스트 플래그도 SAP에 실제 연결을 열기 때문에, 단계를 건너뛰는 것이 시뮬레이션 실행이 SAP에 도달하지 않도록 하는 유일한 방법입니다.
:::

:::note
개별 ERP 전기 단계에는 위의 실행 전기 모드와 별개로 자체 Validate Only 설정(일부 단계에서는 Preview 또는 Test Only Mode로 표시)이 있습니다. 단계 편집기는 이 설정을 항상 명시적으로 저장합니다. REST API, MCP, 워크플로 번들 가져오기 등 다른 방식으로 작성된 단계 구성에서 이 설정을 완전히 생략하면 이제 기본값이 실제 전기가 아니라 미리 보기가 됩니다.
:::

## 프로젝트에 전기 권한 부여

워크플로 실행은 시작한 사람이 아니라 프로젝트의 자격으로 ERP에 전기합니다. 실행이 전기하려면 프로젝트의 전기 단계가 사용하는 각 ERP 연결과 환경에 대한 승인이 프로젝트에 있어야 합니다. 승인이 없으면 단계가 연결과 환경을 명시한 "This project isn't authorized to post to connection …" 오류와 함께 실패합니다. **Call SAP Financial Document Attachment**, **Call SAP Master Data Table RFC**, **Call SAP RFC** 단계에는 승인이 필요하지 않습니다.

프로젝트를 승인하려면 프로젝트 홈 페이지를 열고 **ERP 전기** 아래에서 **ERP 쓰기 승인**을 선택합니다. 각 행은 하나의 환경에 있는 하나의 연결입니다. **승인됨**을 선택하면 프로젝트가 해당 연결에 전기할 수 있고, 선택을 해제하면 중단됩니다. **승인자**와 **승인 시각**에는 마지막으로 승인한 사람과 시각이 표시됩니다.

- 이 버튼은 프로젝트의 아키텍트와 워크스페이스 관리자에게 표시되지만, 승인을 변경할 수 있는 사람은 아키텍트뿐이며 프로젝트가 잠겨 있지 않을 때만 가능합니다. 아키텍트가 아닌 워크스페이스 관리자는 먼저 자신을 아키텍트로 추가할 수 있습니다.
- 행을 선택하여 승인하거나 해제해도 목록이 다시 로드되지 않으므로 스크롤 위치와 선택한 열 정렬이 그대로 유지됩니다. 창 크기를 조정할 수 있으며, 공개 프로젝트에 관한 안내는 전체가 줄 바꿈되어 표시됩니다.
- 연결을 승인하려면 본인도 해당 연결에 대한 쓰기 권한이 있어야 합니다. 즉, 직접 소유하고 있거나, 이름으로 또는 보안 그룹을 통해 공유받은 연결이어야 합니다. **모든 작업 영역 멤버**로 설정된 연결은 해당하지 않습니다.
- **모든 작업 영역 멤버**로 설정된 프로젝트도 다른 프로젝트와 똑같이 승인됩니다. 모든 멤버가 해당 프로젝트의 아키텍트이므로, 연결에 대한 쓰기 권한이 있는 모든 멤버가 해당 프로젝트에 대해 승인할 수 있습니다. 승인이 완료되면 모든 멤버가 프로젝트의 워크플로에서 해당 연결로 전기할 수 있으며, 창의 그리드 위에 이 내용이 표시됩니다.
- 테이블 데이터 또는 차원 멤버와 함께 만든, 사용자만 볼 수 있는 새 복사본은 사용자가 직접 부여할 수 있는 원본의 승인을 유지하며, 원본이 Live였다면 Simulate 상태로 생성됩니다. [복사본의 ERP 쓰기 승인](/ko/guides/projects/managing-projects/#복사본의-erp-쓰기-승인)을 참조하십시오. 그 외의 복사본이나 프로젝트 아카이브에서 만든 프로젝트에는 승인이 없는 상태로 시작합니다. 전기하기 전에 승인하십시오.

## 단계 상태 확인

워크플로가 실행되는 동안 각 단계에는 현재 상태를 나타내는 상태 아이콘과 실행된 시간이 함께 표시됩니다. 아이콘 위에 포인터를 올리면 해당 상태의 메시지를 볼 수 있습니다.

| 상태 | 의미 |
|---|---|
| 대기 중 | 단계가 대기열에 있으며 아직 시작되지 않았습니다. |
| 실행 중 | 단계가 작업 중이며 진행되는 동안 실행 시간이 증가합니다. |
| 완료됨 | 단계가 성공적으로 완료되었습니다. |
| 경고 | 단계는 완료되었지만 [워크플로 로그](/ko/guides/workflows/viewing-workflow-log/)에서 확인할 만한 내용이 표시되었습니다. |
| 오류 | 단계가 실패했습니다. [단계 오류 관리](/ko/guides/workflows/managing-step-errors/)를 참조하십시오. |
| 건너뜀 | 단계를 건너뛰었습니다. 비활성화되었거나 실행 조건이 충족되지 않았기 때문입니다. [워크플로에서 단계 건너뛰기](/ko/guides/workflows/skip-steps-in-a-workflow/)를 참조하십시오. |
| 계속됨 | 단계가 실패했지만 오류 시 계속하도록 설정되어 있어 워크플로가 계속 진행되었습니다. [오류 시 계속](/ko/guides/workflows/continue-on-error/)을 참조하십시오. |
| 중지됨 | 단계가 끝나기 전에 실행이 중지되었습니다. |
| 중단됨 | 단계의 실행이 중단되어 끝낼 수 없습니다. 실행을 재개하거나 워크플로를 다시 실행하십시오. |

실행이 진행되는 동안 열려 있는 워크플로 보기는 자동으로 새로 고쳐지므로 페이지를 다시 로드하지 않아도 표시된 상태가 최신으로 유지됩니다.

### 중단된 단계

단계를 실행하던 대상이 실행 도중 사라지면 단계가 **abandoned**로 표시됩니다. 가장 흔한 원인은 누군가 **중지**를 눌렀거나 플랫폼 유지 관리로 실행이 중단된 경우입니다. 단계의 실행 시간 증가가 멈추고 상태 툴팁에 무슨 일이 있었는지 설명됩니다.

중단된 단계는 완료되지 않았으며 출력도 생성하지 않았습니다. 느린 단계가 아니며, 데이터나 구성의 문제도 아닙니다.

작업을 다시 이어가려면 실행을 [**재개**](#일시-중지-중지-재개)하거나 전체 워크플로를 다시 실행합니다. 재개하면 중단된 단계가 다시 실행됩니다. 두 방법 모두 안전합니다.

### 인터럽트된 단계

단계를 실행하던 서버가 실행 도중 사라지면, 반복해도 안전한 경우 PlaidCloud가 해당 단계를 자동으로 다시 실행합니다. 출력을 대체하는 단계는 한 번 깔끔하게 실행한 것과 같은 결과가 되므로 확인할 필요가 없습니다. 두 번째 시도가 시작되는 지점에는 단계 로그에 "Restarted: the server running this step stopped before it finished (e.g. out of memory or a restart); running it again from the start."라는 경고가 표시됩니다.

안전하게 반복할 수 없는 단계는 다시 실행되지 않습니다. 두 번째 실행이 첫 번째 시도에서 이미 기록한 내용을 중복시킬 수 있으므로, **interrupted** 메시지와 함께 한 번 실패합니다. 이름이나 경로에 `{date}`가 있는 출력을 쓰는 단계는 다시 실행하면 다른 날짜에 기록될 수 있으므로 안전하게 반복할 수 없는 것으로 간주됩니다. 복구하려면 단계의 대상에서 첫 번째 시도가 기록한 내용을 확인하고 필요하면 정리한 다음, [단계를 다시 실행](/ko/guides/workflows/running-one-step-in-a-workflow/)하거나 실행을 **재개**하십시오.

### 시작되지 않는 단계

단계가 워커를 기다리는 동안 상태 메시지에 "Waiting for a worker… N min. No import worker has picked this step up yet."가 표시됩니다(워커의 종류는 가져오기나 내보내기 등 단계에 따라 다릅니다). 작업이 시작되면 메시지가 사라집니다.

단계의 작업이 시작될 수 없는 경우에는 무한정 기다리지 않고 원인과 함께 단계가 실패합니다.

| 원인 | 실패까지 걸리는 시간(약) |
|---|---|
| 가져오기 또는 차원 단계의 작업을 맡는 워커가 없음 | 40분 |
| 단계의 파드가 Pending 상태에 머무름 | 20분 |
| 단계의 이미지를 가져올 수 없음 | 5분 |
| 단계에 대해 파드가 생성되지 않음 | 20분 |
| 커넥터(Singer) 동기화를 맡는 러너가 없음 | 30분 |

커넥터 동기화 메시지에는 동기화 이름이 표시됩니다. 워커가 작업을 시작한 뒤 사라진 경우에도 워커가 중지되었다는 메시지와 함께 단계가 실패합니다. 가져오기 및 차원 메시지에는 "Use Run from here to retry."가 포함됩니다.

### 응답하지 않는 실행

실행을 뒷받침하던 작업이 사라진 뒤에도 실행이 **실행 중** 상태로 남아 있지는 않습니다. 워크플로를 실행하던 서버가 사라지면 해당 실행은 실패로 끝납니다. 실행은 최대 12시간까지 지속될 수 있으며, 그 시점에 아직 실행 중인 실행은 "Run failed: still running at the 12-hour limit. Re-run the workflow." 메시지와 함께 실패합니다.

## 일시 중지, 중지, 재개

워크플로가 실행되는 동안 **일시 중지**하면 진행 중인 단계는 끝까지 실행되고 새 단계는 대기하며, **중지**하면 대기열에 있던 단계와 아직 실행 중인 가져오기 또는 내보내기 작업이 내보내기가 읽고 있던 웨어하우스 쿼리와 함께 취소됩니다. 대기열에 있던 가져오기 및 차원 단계는 깔끔하게 취소되므로 워크스페이스의 이후 가져오기와 차원 로드를 지연시키지 않습니다. 중지하면 워크플로의 대기 중이거나 실행 중인 커넥터(Singer) 동기화도 함께 중지되므로, 워크플로가 중지된 후에도 동기화가 계속 실행되지 않습니다.

매크로는 다른 워크플로나 **매크로: 동시 실행** 단계에서 호출되어 여러 곳에서 동시에 실행될 수 있습니다. 매크로를 중지하면 실행 중인 모든 사본이 중지됩니다. 사본 하나를 중지하면 그 사본과 그 사본이 시작한 것만 중지되고 그 사본을 호출한 워크플로는 계속 실행되며, 응답하지 않게 된 사본을 **Macro Concurrent** 단계가 포기하는 경우에도 마찬가지입니다. 다른 워크플로 안에서만 실행 중인 매크로는 워크플로 목록에 **실행 중**으로 표시되고 **중지**를 사용할 수 있으며, 매크로를 열면 최근 실행에서의 각 단계의 상태, 시작 시간, 종료 시간이 표시됩니다.

**재개**는 일시 중지, 중지 또는 실패한 실행을 처음부터 다시 시작하지 않고 중단된 지점부터 이어서 실행합니다. 워크플로의 마지막 실행이 일시 중지, 중지 또는 오류 상태로 끝난 경우 언제든지 사용할 수 있습니다.

"중단된 지점"의 의미는 워크플로가 실행되는 방식에 따라 다릅니다.

| 실행 방식 | 재개 시 동작 |
|---|---|
| 직렬 | 실행이 끝났을 때 실행 중이던 단계에서 다시 시작하여 거기서부터 계속합니다. 해당 단계가 그룹 안에 있으면 재개는 그 단계를 포함한 최상위 그룹 전체를 다시 가져옵니다. 그룹에서 이미 성공적으로 끝난 단계는 그대로 두고 나머지를 실행하며, 그룹 이후부터 실행이 계속됩니다. |
| 병렬 | 아직 성공적으로 끝나지 않은 모든 단계를 다시 실행하고 완료된 단계는 그대로 둡니다. |
| 고급(그래프) | 실패한 노드와 그 노드를 기다리는 모든 항목을 다시 실행하고 완료된 노드는 그대로 둡니다. |

다른 워크플로를 호출하는 단계인 **Run Model**, **Conditional Run Model**, **Loop Model**은 호출한 워크플로를 다시 시작하지 않고 재개하며, 중첩 수준에 관계없이 동일하게 적용됩니다. 루프 단계는 중단된 반복을 재개하고 이미 완료된 반복은 건너뜁니다.

다른 워크플로의 **중첩된 하위**(상위의 **Run Model** 단계가 호출한 워크플로)로 실행된 워크플로를 재개하면 PlaidCloud가 **체인 최상위에서 재개**를 제공합니다. 하위 워크플로만 단독으로 재개해서는 상위의 오케스트레이션을 이어갈 수 없으므로, 이 옵션은 대신 최상위 상위 워크플로(체인의 루트)를 재개하고 전체 체인을 중지된 지점부터 계속합니다. 최상위 워크플로의 재개는 변경되지 않습니다. 체인의 최상위는 같은 프로젝트 안에서 결정되며, 다른 프로젝트에 걸친 체인은 프로젝트 내 부분의 최상위에서 재개됩니다.

재개는 항상 **원래** 실행을 이어갑니다. 해당 실행에서 성공적으로 끝나지 않은 모든 단계를 다시 실행하며, 실패했거나 중단된 단계는 완료된 것으로 취급하지 않고 다시 실행합니다. 그 사이에 개별 단계를 따로 다시 실행해도 재개가 다음에 이어받는 내용은 달라지지 않습니다. 이는 하위 워크플로에도 마찬가지입니다. 하위 워크플로의 단계 하나를 따로 다시 실행했더라도, 상위 워크플로를 재개하면 해당 단계만이 아니라 하위 워크플로에 남아 있던 모든 작업이 실행됩니다.

재개된 실행은 워크플로의 실행 기록에 **새 실행**으로 기록되며, 다시 실행한 단계만 포함합니다. 원래 실행은 자체 기록 항목을 유지합니다. 하나의 실행이 같은 하위 워크플로를 여러 번 호출하면, 각 호출은 하위 워크플로의 실행 기록에 각자의 항목을 가집니다. 루프 단계의 반복은 하나의 호출로 간주됩니다.

:::note
루프 단계는 완료된 반복을 변수 값으로 대조합니다. 원래 실행과 재개 사이에 루프가 반복하는 데이터가 변경되면, 더 이상 대조할 수 없는 반복은 건너뛰지 않고 다시 실행됩니다.
:::
