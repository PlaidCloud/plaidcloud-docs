## 설명

**다중 테이블 조인** 단계는 한 번의 작업으로 여러 테이블을 조인합니다. 두 테이블 조인을 계속 이어 붙이면 전체 그림을 놓치고 같은 출력 매핑을 반복하게 됩니다. 대신 모든 테이블을 시각적 **조인 그래프 디자이너**에 배치하고, 열 사이에 조인을 그려서 결과 테이블 하나를 만듭니다.

이 단계는 분석에서 흔히 쓰는 조인 형태, 즉 팩트 테이블 하나를 여러 차원 테이블이나 조회 테이블에 조인하는 경우를 위해 만들어졌습니다. 한 번에 최대 32개의 테이블을 조인할 수 있습니다.

<Aside type="note">이 단계는 내부 조인/외부 조인 단계를 여러 개 이어 붙이던 패턴을 대체합니다. 단계 하나, 다이어그램 하나, 출력 매핑 하나로 처리하며, 테이블이 서로 어떻게 맞물리는지 하나의 공유된 뷰로 볼 수 있습니다.</Aside>

## 다중 테이블 조인 추가

다른 단계와 마찬가지로 추가하고 **다중 테이블 조인**을 선택합니다(단계 메뉴의 **테이블** 그룹에서 선택하거나 [고급 워크플로 캔버스](/ko/guides/workflows/advanced-workflows/)의 팔레트에서 끌어 옵니다). 단계 편집기에는 세 개의 탭이 있습니다.

1. **소스** — 테이블을 추가하고 조인을 그리는 시각적 디자이너입니다.
2. **열** — 결과 테이블에 포함될 열입니다.
3. **필터** — 조인된 결과에 적용되는 선택적 필터입니다.

작업하는 동안 상태 표시기에 **저장 준비됨** 또는 **저장되지 않은 변경 사항**이 표시됩니다.

## 테이블 및 조인

### 테이블 추가

**테이블 추가**를 선택하면 소스 테이블이 캔버스에 놓입니다. 각 테이블은 열이 나열된 카드로 표시되며 **별칭**을 갖습니다. 별칭은 다른 곳에서 해당 테이블의 열을 참조할 때(`alias.column` 형태) 사용하는 짧은 이름입니다. 별칭은 문자나 밑줄로 시작해야 하며 SQL 키워드일 수 없습니다. 필요한 만큼(최대 32개) 추가하고, 결과를 쓸 **대상 테이블**을 선택합니다.

카탈로그에서 테이블의 열이 변경되면 **서버에서 다시 가져오기**를 사용하여 카드의 열을 최신 값으로 바꿉니다.

### 동적 테이블과 변수

소스 테이블과 **대상 테이블** 모두 목록에서 선택하는 대신 **참조**로 지정할 수 있습니다. 테이블 선택기에서 **동적**을 선택하고 다음 중 하나를 입력합니다.

- 테이블 **이름** — `FACT_GL`
- 프로젝트 **경로** — `/03 Results/FACT_GL`

둘 다 `{variable}` 토큰을 포함할 수 있으며, 워크플로를 실행할 때 대체됩니다. 따라서 `/03 Results/FACT_GL_{year}`는 프로젝트 변수나 워크플로 변수에 따라 기간마다 다른 테이블에 씁니다. 대상 테이블이 없으면 새로 만듭니다.

<Aside type="note">동적 **소스**는 설계 시점에 열을 읽을 수 없습니다. 지정한 테이블이 실행 시점까지 알려지지 않기 때문입니다. 카드가 비어 있는 상태로 나타나므로 측면 패널에서 열을 직접 추가하고, 그 열로 조인을 그립니다. 동적 **대상**에는 이러한 제한이 없습니다.</Aside>

짝이 맞지 않는 중괄호는 저장할 때 감지되므로, 잘못 입력한 `FACT_{year`는 실행 도중에 실패하는 대신 단계에서 보고됩니다.

### 조인 그리기

한 테이블의 열 점에서 다른 테이블의 열로 끌어 **조인**(에지)을 만듭니다. 에지를 선택하면 오른쪽에 편집기가 열리며 다음을 설정할 수 있습니다.

- **조인 유형:**

  | 유형 | 유지 대상 |
  |------|-------|
  | **INNER** | 일치하는 행만 |
  | **LEFT** | 왼쪽 테이블의 모든 행 |
  | **FULL** | 양쪽의 모든 행 |
  | **CROSS** | 왼쪽의 모든 행과 오른쪽의 모든 행의 조합(조건 없음) |

- **조인 조건** — 두 테이블의 열 사이의 비교를 하나 이상 지정합니다. **+ 조건 추가**로 더 추가하고, **AND** / **OR**로 결합하며, 모든 연산자(`=`, `<>`, `<`, `<=`, `>`, `>=`, `BETWEEN`, `IS NULL`, `IS NOT NULL`, `IN`, `NOT IN`, `LIKE`, `NOT LIKE`)를 사용할 수 있습니다.
- **레이블(선택 사항)** — 조인에 이름을 지정하면(예: `customer-to-orders`) 다이어그램을 읽기 쉬워집니다.

디자이너는 조인 그래프를 트리로 유지합니다. 각 테이블은 정확히 하나의 조인을 통해 결과에 연결되므로 순환이나 모호한 경로가 없으며, 테이블을 자기 자신과 조인할 수 없습니다. 조인을 제거하려면 에지를 선택하고 **에지 삭제**를 선택합니다.

### 조인 전에 테이블 필터링

각 소스 테이블에는 조인 *전에* 적용되는 **인바운드 필터**가 있습니다. 이를 사용하여 테이블을 필요한 행으로 줄이십시오(`alias.column`으로 열을 참조). 이는 모든 조인 *이후에* 실행되는 **Post-Join Filter**와 별개입니다.

### 디자이너 도구 모음

- **레이아웃 정리**는 조인 순서에 따라 테이블과 조인을 왼쪽에서 오른쪽으로 자동 배치합니다.
- 확대/축소 수준 옆의 확대/축소 단추로 보기를 확대하거나 축소하고, **맞춤**은 전체 그래프가 들어오도록 크기를 조정하고 가운데로 맞추며, **1:1**은 100%로 되돌립니다. 마우스 휠로 확대/축소하고, 가운데 단추 클릭이나 Shift를 누른 채 끌기로 이동합니다.
- 캔버스 모서리의 미니맵에는 전체 그래프가 표시되고 보이는 부분이 윤곽선으로 표시됩니다. 그곳을 클릭하거나 끌어 해당 위치로 이동할 수 있습니다. 미니맵 단추로 미니맵을 숨기거나 표시할 수 있으며, PlaidCloud는 사용자의 선택을 기억합니다.
- **열 필터링…** 버튼은 테이블에 열이 많을 때 카드에 표시되는 열을 좁힙니다.
- **실행 취소** / **다시 실행**은 편집 내용을 뒤로, 앞으로 이동하며(Ctrl+Z / Ctrl+Y), **기록**은 대화 상자를 연 이후의 모든 변경 사항 패널을 열고 **복원**할 수 있습니다.
- 내보내기 단추는 조인 다이어그램을 PDF로 다운로드하며, 메뉴에 **PDF로 내보내기**와 **PNG로 내보내기**가 있습니다. 문서화나 검토에 유용합니다.

## 출력 열

**열** 탭에서 결과 테이블에 포함할 열을 선택합니다. 조인된 모든 테이블에서 선택할 수 있습니다. **캔버스에서 선택…** 버튼을 사용하면 모든 소스의 열 중에서 시각적으로 선택하고, **모든 소스 열 추가**를 사용하면 한 번에 모두 가져옵니다. 각 열은 이름을 바꾸고, 데이터 유형을 설정하고, 집계를 적용할 수 있습니다. 두 소스 열의 이름이 같으면 PlaidCloud가 소스 별칭을 접두사로 붙여 충돌하지 않게 합니다.

각 출력 열은 다음 세 가지 중 정확히 **하나**에서 값을 가져옵니다.

- **소스 열** — **소스 별칭**을 해당 열을 소유한 캔버스 별칭으로, **소스**를 `alias.column` 참조로 설정합니다. 둘 다 필수이며, 소스 열은 항상 출처 테이블을 명시합니다.
- **상수** — 모든 행에서 같은 고정 값입니다.
- **식** — **표현식 열 추가**를 선택하면 행이 추가되고 식 편집기가 열립니다. 식은 캔버스의 **모든** 소스 별칭을 `alias.column`으로 참조할 수 있으므로, 조인된 여러 테이블에 걸친 값(두 테이블에 걸친 `CASE`, 연결, 계산된 금액)을 이렇게 만듭니다. 식 행에서는 **소스 별칭**과 **소스**를 비워 둡니다.

둘 이상을 채우는 것은 오류이며, 하나도 채우지 않는 것도 오류입니다.

**식** 셀은 표준 PlaidCloud 식 편집기를 열며, 열 브라우저에 캔버스의 모든 테이블이 나타나고 함수 목록과 자동 완성을 사용할 수 있습니다.

출력 열은 캔버스를 따릅니다. **소스** 탭에서 소스의 이름을 바꾸면 해당 출력 열이 새 별칭으로 이동하고, 소스를 제거하면 해당 출력 열이 삭제됩니다. 따라서 더 이상 조인에 없는 테이블을 가리키는 열이 남지 않습니다.

## Post-Join Filter

**Post-Join Filter** 탭은 조인된 결과를 대상 테이블에 쓰기 전에 선택적 필터를 적용하며, SQL `HAVING` 절에 해당합니다. 상자를 클릭하면 식 편집기가 열립니다. 출력 열이 열 브라우저에 나열되며 `result.column_name`으로 참조합니다. 소스 별칭은 여기에서 사용할 수 없습니다. 상자 아래의 **Available references**에는 사용할 수 있는 모든 참조가 나열됩니다. 후처리 필터링을 건너뛰려면 비워 두십시오.

## 유효성 검사

PlaidCloud는 조인을 구성하는 동안, 그리고 단계가 실행될 때 다시 유효성을 검사합니다. 지원되지 않는 구성, 순환, 중복된 별칭, 소스/상수/식 중 아무것도 설정하지 않았거나(또는 둘 이상 설정한) 출력 열, 더 이상 존재하지 않는 열 등에 문제가 있으면 탭에 개수가 표시된 ⚠ 배지가 나타나고, 디자이너가 문제의 테이블이나 조인을 표시하며, 저장이 이유와 함께 거부됩니다. 해결되지 않은 문제가 있는 상태로 저장하면 첫 번째 문제가 있는 탭으로 전환되며, **문제로 이동**을 사용하면 언제든 같은 동작을 합니다.

저장할 때 PlaidCloud는 각 출력 열 식을 단계가 실행되는 방식대로 조인 자체의 입력에 대해 별칭(`alias.column`)으로 검사하고, Post-Join Filter도 검사합니다. 잘못된 식은 해당 출력 열에, 잘못된 Post-Join Filter는 필터에 보고됩니다. 조인이 **실행 시점에 지정된 열도 함께 전달**로 설정되어 있고 요약하지 않는 경우, 열이 실행 시점에 추가되므로 저장할 때 식 검사를 건너뛰며, 해당 식은 단계가 실행될 때 검사합니다. 소스별 필터도 단계가 실행될 때 검사합니다.

<Aside type="tip">`CROSS` 조인은 행의 모든 조합을 만들며 조건이 없습니다. 큰 테이블에서는 비용이 매우 클 수 있으므로 의도적으로 사용하십시오.</Aside>

## 단계 실행

다중 테이블 조인은 다른 단계와 마찬가지로 실행됩니다. 모든 조인을 한 번의 작업으로 실행하고 매핑된 열을 대상 테이블에 씁니다.
