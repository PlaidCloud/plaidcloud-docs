## 개요

대시보드를 사용하면 액세스할 수 있는 모든 프로젝트 또는 워크스페이스의 데이터를 기반으로 대화형 뷰를 만들 수 있습니다. 하나의 대시보드에서 여러 프로젝트의 테이블을 결합하고, 시각화와 원시 데이터 탐색을 함께 사용할 수 있으며, 정기 보고서와 임시 분석 모두에 활용할 수 있습니다. 대시보드는 구성을 변경하지 않고도 작은 참조 테이블부터 수십억 행의 데이터 세트까지 확장됩니다.

## 대시보드 계정

대시보드 계정은 PlaidCloud에서 처음 대시보드를 열 때 자동으로 설정되므로 직접 만들 필요가 없습니다. 볼 수 있는 내용은 PlaidCloud 워크스페이스 멤버십과 보안 그룹에 따라 결정됩니다.

<Aside>사람의 추가, 변경, 제거는 대시보드 서비스 안이 아니라 PlaidCloud에서 수행하십시오. [워크스페이스 멤버 관리](/ko/administration/access/overview/managing-workspace-members/)를 참조하십시오. 대시보드 서비스에서 직접 사용자 계정을 만드는 것은 관리자 전용 작업이며, 그렇게 만든 계정은 워크스페이스 멤버십과 연결되지 않습니다.</Aside>

## 표시되는 대시보드

PlaidCloud의 **대시보드** 페이지에는 액세스할 수 있는 프로젝트에 속한 게시된 대시보드가 표시됩니다. 이것이 일반적인 경우이며 거의 모든 대시보드가 여기에 해당합니다.

대시보드의 소유자와 워크스페이스 관리자는 대시보드를 특정 보안 그룹으로 제한할 수 있습니다. 제한된 대시보드는 해당 그룹의 멤버와 소유자, 그리고 모든 대시보드를 볼 수 있는 워크스페이스 관리자에게만 표시됩니다. 제한이 없는 대시보드는 해당 프로젝트에 액세스할 수 있는 모든 사람에게 표시되므로, 하나의 대시보드를 제한해도 다른 대시보드를 볼 수 있는 사람은 바뀌지 않습니다.

목록에 대시보드가 보이지 않는 경우 알아 두면 좋은 사항이 두 가지 있습니다.

- **제한된 대시보드는 열 수 없을 뿐 아니라 목록에서도 숨겨집니다.** 대시보드의 프로젝트에 액세스할 수 있고 해당 링크를 열면 **Request access** 페이지가 표시됩니다. 그렇지 않으면 삭제되었다고 가정하지 말고 소유자에게 문의하십시오.
- **제한된 대시보드가 표시되려면 대시보드 계정이 있어야 합니다.** 계정은 PlaidCloud에서 처음 대시보드를 열 때 만들어지며, 그때 그룹이 적용됩니다.

<Aside>PlaidCloud에서 **누가 볼 수 있습니까?** 로 대시보드를 볼 수 있는 사람을 설정합니다. [대시보드를 볼 수 있는 사람 제어](/ko/guides/dashboards/control-who-can-see-a-dashboard/)를 참조하십시오. 프로젝트 액세스는 그 위에 계속 적용됩니다. 대시보드를 볼 수 있다고 해서 액세스할 수 없는 프로젝트의 데이터에 접근할 수 있게 되는 것은 아닙니다.</Aside>

## 대시보드 워크스페이스

**대시보드**는 왼쪽의 레일과 그 옆에 선택한 페이지가 표시된 상태로 열립니다. 페이지를 열 수 없는 멤버에게는 해당 항목이 표시되지 않습니다. 페이지는 맨 위에 제목이 있고 짧은 부제목이 함께 표시되는 경우가 많으며, 작업은 그 옆의 머리글에 있습니다.

| 레일 항목 | 표시되는 내용 |
|---|---|
| **개요** | **대시보드**, **Visible to everyone**, **제한됨**, **You manage**, **Apps ready**, **Apps failed** 타일. 타일을 선택하면 이미 필터링된 목록이 열립니다. **Recently opened and favorites**에는 이 기기에서 최근에 열었거나 별표를 붙인 항목이 나열됩니다. **조치 필요**에는 실패한 앱과 사용자의 처리를 기다리는 액세스 요청이 나열되며, 내가 관리하는 대시보드를 여는 **검토**가 함께 표시됩니다. **Most opened in the last 30 days**는 사용량 액세스 권한이 있는 멤버에게 표시됩니다. |
| **대시보드** | 볼 수 있는 대시보드입니다. 목록 위에서 **모두**, **You manage**, **즐겨찾기** 중에서 선택합니다. 열에는 **대상**, **소유자**, **Opens (30 days)** 등이 포함됩니다. **Import dashboard archive…** 및 **대상 사용자 설정…** 은 도구 모음에 있습니다. |
| **앱** | 프로젝트를 기반으로 만든 Panel, Dash 및 브라우저 앱이며, **종류**, **상태**, **프로젝트**가 함께 표시됩니다. 상태는 실시간으로 업데이트됩니다. **New app** 메뉴에는 **패널 앱** 제목 아래에 **Studio**, **Browser only**, **Server based**가 있고, 그 다음에 **Dash 앱**과 **From gallery…** 가 있습니다. **유형** 열에서도 같은 이름을 사용합니다. |
| **Notebooks** | JupyterLite 배포입니다. |
| **액세스 검토** | **관리자** 아래에 있으며 워크스페이스 관리자용입니다. [대시보드를 볼 수 있는 사람 제어](/ko/guides/dashboards/control-who-can-see-a-dashboard/#대시보드-액세스-검토)를 참조하십시오. |
| **Open navigator ↗** | 레일 하단에 있습니다. 화살표는 이 항목이 자체 창, 즉 새 탭에서 대시보드 서비스를 여는 유일한 항목임을 나타냅니다. |

**대시보드**와 **앱** 옆의 숫자는 볼 수 있는 항목의 수를 나타냅니다.

## 대시보드 페이지에서 대시보드 열기

**대시보드** 페이지에서 대시보드 행 맨 앞의 **열기** 아이콘을 클릭하면 새 탭에서 대시보드가 열립니다. 행을 더블 클릭해도 열립니다.

### 행 작업 메뉴

**대시보드** 페이지를 포함하여 행별 작업이 있는 PlaidCloud의 모든 목록에는 행 작업 메뉴가 있습니다. 행 맨 앞의 **⋯** 버튼에서, 행을 마우스 오른쪽 버튼으로 클릭하여, 또는 도구 모음의 **작업** 메뉴에서 엽니다. 메뉴의 구성은 항상 같습니다.

1. **열기**, **세부 정보**, **편집**이 이 순서로 있습니다.
2. **액세스**, **그룹**, **암호 재설정**, **복제** 등 목록 고유의 작업이 있습니다.
3. **삭제** 또는 **제거**가 마지막에 있습니다.

구분선으로 그룹이 나뉩니다. 선택한 행에 적용되지 않는 작업은 제자리에 회색으로 표시되므로, 행이 바뀌어도 항목의 위치는 바뀌지 않습니다.

두 항목에는 단축키가 표시됩니다. **Enter** 키로 실행되는 항목, 즉 행을 여는 항목에는 **Enter**가 표시됩니다. **Delete** 키로 실행되는 항목에는 **Del**(Mac에서는 **Backspace**)이 표시됩니다.

행에 작업이 하나뿐인 목록에서는 **⋯** 대신 행 맨 앞에 해당 작업의 아이콘이 표시됩니다. 아이콘을 클릭하면 작업이 실행되며, 파괴적인 작업은 여전히 확인을 요청합니다. 해당 작업을 수행할 수 없는 행에는 아이콘이 표시되지 않습니다.

### 표준, 여유, 카드 보기

**대시보드**, **앱**, ERP **등록부**, Identity **멤버** 등 PlaidCloud의 워크스페이스 앱에 있는 목록에는 도구 모음에 세 가지 선택지가 있는 **뷰** 메뉴가 있습니다.

- **Standard rows**: 행당 한 줄로 표시되는 간결한 목록입니다.
- **Roomy rows**: 각 행 주위에 더 많은 공간이 있는 동일한 목록입니다.
- **Cards**: 행당 카드 하나입니다. **대시보드** 카드에는 대시보드의 썸네일이 표시되고, ERP 등록부 카드에는 금액, 날짜, 엔터티, 연결, 문서가 표시됩니다.

카드는 목록과 같은 방식으로 동작합니다. 카드를 선택하고, Shift로 선택 범위를 확장하고, **뷰** 메뉴에서 정렬하고 열을 선택하며, 마우스 오른쪽 버튼으로 **복사**와 행의 작업을 사용할 수 있고, **대시보드**와 **앱**처럼 즐겨찾기가 있는 목록에서는 별표를 클릭하여 즐겨찾기에 추가할 수 있습니다.

## 숫자가 그렇게 나온 이유 묻기

대시보드에서 차트의 한 점이나 테이블 차트의 셀을 마우스 오른쪽 버튼으로 클릭하고
**Why this number**를 선택합니다. 새 탭에서 PlaidCloud가 열리며, Weave가 해당 수치를
기록하는 단계, 수치의 출처, 이전 실행 이후 어떻게 변했는지를 알려 줍니다.
[숫자가 그렇게 나온 이유](/ko/guides/ai-assistant/weave-numbers/#why-this-number)를 참조하십시오.

## 세션이 만료된 후 대시보드 링크 열기

대시보드 링크를 열 때 세션이 만료되어 있으면 로그인하라는 안내가 표시되며, 로그인한 후에는 대시보드 홈 페이지가 아니라 해당 대시보드로 이동합니다.

## 표시 컨트롤

표시 컨트롤은 필터 바 컨트롤로, 대시보드를 보는 누구나 차트를 편집하기 위해 열지 않고도 차트의 그룹화 기준을 변경할 수 있게 해 줍니다. 예를 들어 "지역"을 "제품 라인"으로 바꿀 수 있습니다. 대시보드 편집자는 필터 바의 설정 메뉴에서 표시 컨트롤을 추가하고 구성합니다. **Add or edit filters and controls**를 선택한 다음 **새로 만들기** 메뉴에서 **Add display control**을 선택합니다.

### 표시되는 열 제한

기본적으로 표시 컨트롤의 드롭다운에는 기반 데이터 세트에서 **Is filterable**로 표시된 모든 열이 나열됩니다. 열이 많은 데이터 세트에서는 원하는 열을 찾기 위해 수백 개의 열을 스크롤해야 할 수 있습니다.

이제 모든 표시 컨트롤의 구성 패널에 고유한 **Available columns** 필드가 있습니다. 이 필드를 특정 열 목록으로 설정하면 컨트롤의 드롭다운에는 해당 열만 표시됩니다. 비워 두면 컨트롤은 이전과 똑같이 동작하여 필터링 가능한 모든 열을 제공하므로, 기존 대시보드는 변경하지 않아도 이전과 같이 계속 작동합니다.

표시 컨트롤을 제한하려면:

1. 필터 바의 설정 메뉴에서 **Add or edit filters and controls**를 엽니다.
2. 제한하려는 표시 컨트롤을 선택하거나 새로 추가합니다.
3. **Available columns**에서 뷰어에게 보여 줄 열을 검색하여 선택합니다.
4. 저장합니다.

### "Is Filterable"과의 상호작용

**Available columns**에는 데이터 세트에서 이미 **Is filterable**로 표시된 열만 표시됩니다. 이 목록을 더 좁힐 뿐 우회하지는 않습니다. 열에서 **Is filterable** 선택을 해제하면 **Available columns**, 임시 필터, 기본 필터, 해당 데이터 세트를 기반으로 만든 모든 차트의 **Simple Metric** 선택기 등 모든 곳에서 열이 제거됩니다.

이렇게 영향 범위가 넓기 때문에 **Available columns**가 존재합니다. 이 기능이 생기기 전에는 표시 컨트롤의 드롭다운을 줄이려면 표시하고 싶지 않은 열에서 **Is filterable** 선택을 해제하는 방법뿐이었는데, 그러면 같은 열이 해당 데이터 세트의 모든 차트 지표 선택기에서도 숨겨졌습니다. 차트에 지표나 임시 필터로 필요할 수 있는 모든 열에서는 **Is filterable**을 선택한 상태로 유지하고, 각 표시 컨트롤의 고유한 **Available columns**로 해당 컨트롤의 Group By 드롭다운에 표시할 열을 결정하십시오.

<Aside type="caution">표시 컨트롤의 **Available columns** 목록에 있는 열의 이름을 바꾸거나 삭제해도 자동으로 감지되지 않습니다. 컨트롤을 다음에 열 때 경고 없이 더 적은 열만 표시됩니다. 데이터 세트의 열 이름을 바꾸거나 열을 제거한 후에는 표시 컨트롤의 **Available columns**를 다시 확인하십시오.</Aside>

### 저장되는 위치

**Available columns**는 해당 컨트롤의 나머지 설정과 함께 표시 컨트롤별로 저장됩니다. 내보내기와 가져오기를 통해 대시보드와 함께 이동하며, 같은 대시보드나 같은 데이터 세트로 만든 다른 대시보드의 다른 컨트롤에는 영향을 주지 않습니다.

## 테이블 편집


새 테이블을 만든 후 받는 메시지에서도 테이블 구성을 편집하도록 안내합니다. 구성을 편집하는 더 고급 기능도 있지만, 여기서는 제한적이고 더 간단한 부분부터 시작합니다. 테이블 구성을 편집하려면:


1. 원하는 테이블의 편집 아이콘을 클릭합니다.
2. “List Columns” 탭을 클릭합니다.
3. 원하는 대로 열을 정렬합니다.
4. “Save”를 클릭합니다.

이렇게 하면 데이터를 탐색할 때 테이블의 특정 열을 어떻게 사용할지 정의할 수 있습니다.


* **그룹화 가능:** 사용자가 특정 필드를 기준으로 지표를 그룹화하게 하려는 경우
* **필터링 가능:** 특정 필드를 기준으로 필터링해야 하는 경우
* **고유 개수:** 이 필드의 고유한 개수를 구하려는 경우
* **합계:** 합산하려는 지표인 경우
* **최솟값:** 기본 요약 통계를 수집하려는 지표인 경우
* **최댓값:** 기본 요약 통계를 수집하려는 지표인 경우
* **시간 정보 여부:** 날짜 또는 시간 필드에는 이 항목을 선택해야 합니다

## 데이터 탐색


데이터 탐색을 시작하려면 원하는 테이블을 클릭하기만 하면 됩니다. 기본적으로 테이블 뷰가 표시됩니다.



### 데이터 개수 구하기


테이블에 있는 모든 레코드의 개수를 구하려면:


1. 필터를 “Since”로 변경합니다.
2. 원하는 since 필터를 입력합니다.


	* “3 years ago”와 같은 간단한 표현을 사용할 수 있습니다.
3. 원하는 until 필터를 입력합니다.


	* 시간 기본 상한은 “now”입니다.
4. “그룹화 기준” 머리글을 선택합니다.
5. 지표 섹션에 “Count”를 입력합니다.
6. “COUNT(*)”를 선택합니다.
7. “Query” 버튼을 클릭합니다.

그러면 테이블에 결과가 표시됩니다.

**특정 필드나 제한 조건의 개수를 구하려면:**

1. “그룹화 기준” 필드에 원하는 제한 조건을 입력합니다.
2. 쿼리를 실행합니다.

<Aside>제한 조건에서 “measurement”를 사용하면 측정 유형에 따라 달라지는 측정값을 가리킵니다. 따라서 “filter section (e.g. weather_description and Maximum temperature.)”에서 측정 유형이 동일한지 확인해야 합니다.</Aside>

### 결과 수 제한

상위 10개와 같이 일정 개수의 결과만 필요한 경우:

1. “Options”를 선택합니다.
2. “Row Limit” 섹션에 원하는 최대 결과 수를 입력합니다.
3. “Query”를 클릭합니다.

### 추가 시각화 도구

약어로 표시된 값을 전체 길이로 확장하려면:

1. “Edit Table Config”를 선택합니다.
2. “List Sql Metric”을 클릭합니다.
3. “Edit Metric”을 클릭합니다.
4. “D3Format”을 클릭합니다.

측정 단위를 편집하려면:


1. “Edit Table Config”를 선택합니다.
2. “List Sql Metric”을 클릭합니다.
3. “Edit Metric”을 클릭합니다.
4. “SQL Expression”을 클릭합니다.

차트 유형을 변경하려면:


1. “Chart Options”로 스크롤합니다.
2. 필수 필드를 입력합니다.
3. “Query”를 클릭합니다.

여기에서 축 레이블, 여백, 눈금 등을 설정할 수 있습니다.
