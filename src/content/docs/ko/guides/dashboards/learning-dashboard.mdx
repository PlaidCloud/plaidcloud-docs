## 설명


대시보드는 정적 보고부터 동적 분석까지 다양한 사용 사례를 지원합니다. 대시보드는 복잡한 보고 요구 사항을 지원하면서 직관적인 포인트 앤 클릭 인터페이스도 제공합니다. 문제가 발생할 때도 있을 것입니다. PlaidCloud 지원팀 담당자가 항상 도움을 드릴 수 있지만, 비슷한 문제가 발생할 경우를 대비해 아래에 몇 가지 팁도 정리해 두었습니다.



## **대시보드에 관한 자주 묻는 질문과 답변**



### 권장 브라우저


잦은 캐싱 때문에 대시보드에는 일반적으로 Google Chrome이 가장 적합한 웹 브라우저입니다. 다른 브라우저를 사용하다가 문제가 발생하면 먼저 캐시와 쿠키를 지워 문제가 해결되는지 확인하십시오. 해결되지 않으면 Google Chrome으로 전환하여 문제가 다시 발생하는지 확인하십시오.



### 동기화 지연


* *문제:* 대시보드 영역에서 테이블을 게시 취소하고 다시 게시한 후 데이터가 제대로 동기화되지 않는 것 같습니다.
* *해결 방법:* 테이블을 다시 게시하면 해당 테이블을 읽는 모든 차트의 캐시된 결과가 지워지므로, 워크플로 실행 후 대시보드를 열면 수동으로 새로 고치지 않아도 새 데이터가 표시됩니다. 표시되지 않으면 실행이 완료되었는지, 그리고 예상한 테이블을 다시 게시했는지 확인하십시오. [대시보드 캐싱](/ko/guides/dashboards/dashboard-caching/)을 참조하십시오.

### 테이블 동기화 오류


* *문제:* 이전 테이블과 같은 게시 이름으로 테이블을 다시 만든 후, 대시보드에서 새로 고침을 누르고 테이블을 게시, 게시 취소, 다시 게시해도 테이블이 동기화되지 않습니다.
* *해결 방법:* 테이블을 다른 이름으로 다시 게시하십시오. 대시보드 데이터 모델은 중복 테이블, 즉 게시 이름과 프로젝트 ID가 같은 테이블을 허용하지 않습니다.

### 캐시 경고


* *문제:* 오른쪽 위에 "Loaded data cached **3 hours ago**. Click to force-refresh."라는 경고가 표시되었습니다.
* *해결 방법:* 경고를 클릭하여 캐시를 강제로 새로 고칩니다. "Edit dashboard" 옆의 드롭다운 메뉴를 클릭하고 "Force refresh dashboard"를 선택해도 됩니다. 두 방법 모두 시스템 내에서 새로 고치며, 웹 브라우저 자체를 새로 고치는 것보다 권장됩니다. 결과를 보관하는 기간은 구성할 수 있습니다. [대시보드 캐싱](/ko/guides/dashboards/dashboard-caching/)을 참조하십시오.

### 권한 경고


* *문제:* 게시한 대시보드의 데이터가 표시되어야 하는 각 섹션에 "This endpoint requires the datasource… permission"이라는 동일한 오류가 표시됩니다.
* *해결 방법:* 데이터 소스가 오래되지 않았는지 확인하십시오. 차트가 오래된 자료에서 데이터를 가져오고 있을 가능성이 큽니다. 이런 경우 차트를 새 데이터 소스로 업데이트하십시오.
* *문제:* 위와 같은 권한 경고가 표시되지만 동료는 차트 데이터를 볼 수 있습니다.
* *해결 방법:* 한 사용자는 차트의 데이터를 볼 수 있고 다른 사용자는 볼 수 없는 경우, 허용된 범주에 속한 사용자가 두 번째 사용자에게 권한을 부여해야 할 수 있습니다. 방법은 다음과 같습니다.


	1. Charts로 이동합니다
	2. 액세스 권한을 부여하려는 차트 옆에서 연필과 종이 모양의 두 번째 작은 아이콘을 선택합니다
	3. Edit Table을 클릭합니다
	4. Detail을 클릭합니다
	5. Owners를 클릭하고 액세스 권한을 부여하려는 사용자의 이름을 추가한 다음 저장합니다.

<Aside>모범 사례로, 새 차트를 만들고 저장할 때마다 해당하는 모든 사용자를 Owners 섹션에 그때 추가하십시오. 그렇지 않으면 새로운 사용자에게 액세스 권한이 필요할 때마다 다시 돌아가 Owners를 편집하고 추가해야 합니다.</Aside>


### 수정한 필터를 대시보드에 저장


* *문제:* 초안 모델에서 필터를 수정했고 이를 대시보드에 저장하려고 합니다. 필터가 목록에 없습니다. 초안 모델에 "There is no chart definition associated with this component, could it have been deleted? Delete this container and save to remove this message."라는 경고가 표시되었습니다.
* *해결 방법:* "Edit Chart"로 이동합니다. 그곳에서 "Dashboards" 섹션에 올바른 대시보드가 입력되어 있는지 확인합니다. 비어 있으면 올바른 대시보드 이름을 추가합니다.

### 숫자 서식: 깨짐


* *문제:* 숫자 서식이 깨지고 순서가 맞지 않습니다.
* *해결 방법:* 이러한 깨짐의 가장 가능성 높은 원인은 숫자 열에 null이 있는 것입니다. 필터를 사용하여 null인 숫자 열을 모두 제거한 다음 다시 실행해 보십시오. 그래도 해결되지 않으면 http://bl.ocks.org/zanarmstrong/05c1e95bf7aa16c4768e 또는 https://github.com/apache-superset/superset-ui/issues 에 있는 자료를 검토하십시오. 마지막으로 언제든지 PlaidCloud 지원팀 담당자에게 문의하십시오. 이 문제는 알려진 문제이며 보다 근본적인 해결책을 개발하고 있습니다.

### 숫자 서식


숫자를 가장 가까운 정수로 반올림하려면 다음과 같이 합니다.


1. *사용하지 마십시오:* ,.0f
2. *대신 사용하십시오:* ,d 또는 달러의 경우 $,d

### 기존 대시보드 가져오기


* *문제:* 기존 대시보드를 가져오는데 내보내기 파일에서 오류가 발생합니다.
* *해결 방법:* 먼저 파일을 확인하십시오. 대시보드와 데이터셋은 **내보내기**가 생성하는 ZIP 파일에서 가져옵니다. 이전 JSON 또는 YAML 내보내기 파일은 거부되므로 대시보드를 다시 내보내고 새 ZIP 파일을 가져오십시오.
* 그런 다음 대시보드에 "Slug"가 있는지 확인하십시오. 대시보드 편집을 열면 두 번째 섹션의 제목이 Slug입니다. 해당 섹션이 비어 있거나 "null"이라고 표시되면 문제의 원인이 아닙니다. 그렇지 않으면 슬러그가 고유해야 합니다. 다른 대시보드에서 사용하지 않는 값으로 변경하고 다시 내보낸 다음 새 파일을 가져오십시오.
