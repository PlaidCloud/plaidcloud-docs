대시보드는 그리는 모든 차트의 결과를 캐시합니다. 대시보드를 처음 여는 사람은
쿼리를 데이터 웨어하우스에 대해 실행하고, 그 이후에 여는 모든 사용자는 저장된
결과를 받으므로 두 번째 조회가 첫 번째보다 훨씬 빠릅니다.

캐시된 결과는 두 가지 경우에 폐기되며, 다음 조회 시 웨어하우스를 다시 쿼리합니다.
차트의 기반이 되는 테이블이 다시 게시되었거나, 결과가 캐시 수명이 끝났을 때입니다.

## 테이블을 다시 게시하면 캐시된 결과가 지워짐

워크플로 실행이 테이블을 다시 게시하면 해당 테이블을 읽는 모든 차트가 캐시된
결과를 즉시 삭제합니다. 다음으로 대시보드를 여는 사람은 기다리거나 수동으로
새로 고침을 강제하지 않아도 갱신된 숫자를 봅니다.

따라서 대시보드가 캐싱 때문에 새로 고침 이전의 숫자를 표시하는 일은 없습니다.
워크플로 실행 후 대시보드가 오래된 것처럼 보인다면 원인은 캐시가 아니라 워크플로입니다.
실행이 완료되었는지, 그리고 예상한 테이블을 다시 게시했는지 확인하십시오.

<Aside type="caution" title="고정된 이름으로 게시">
캐시된 결과는 게시된 테이블별로 추적됩니다. 테이블을 다른 게시 이름으로 다시 빌드하면,
이전 이름을 가리키는 차트는 계속 이전 테이블의 데이터를 제공합니다. 이미 만든
차트가 계속 연결되도록 같은 이름으로 다시 게시하십시오.
</Aside>

## 캐시 수명

캐시된 모든 결과에는 수명도 있으며, 수명이 지나면 저절로 만료됩니다. 기본값은
**1시간**입니다.

대시보드를 최신 상태로 유지하는 것은 수명이 아니라 다시 게시입니다. 따라서 워크플로가
실행될 때만 변경되는 데이터에서는 짧은 수명이 얻는 것은 없고 비용만 크게 듭니다.
마지막 결과가 만료된 후의 조회는 모두 웨어하우스를 처음부터 다시 쿼리하기 때문입니다.
아침 검토나 월말 마감처럼 집중적으로 사용하는 대시보드는 거의 모든 로드에서 이 비용을 치릅니다.

기본값은 2026년 8월까지 5분이었습니다. 다시 게시해도 캐시된 결과가 안정적으로
지워지지 않아서 만료만이 대시보드를 최신 상태로 유지하는 유일한 수단이었기 때문에 짧게
설정했습니다. 이제 다시 게시하면 결과가 지워지므로 1시간이 안전하면서도 훨씬 저렴합니다.

변경이 덜 잦은 테이블은 수명을 더 늘리십시오. 밤사이 다시 로드되는 테이블에는 하루가
적합하며, 테이블을 다시 로드하는 워크플로가 새 데이터가 들어오는 즉시 캐시를 지웁니다.

<Aside type="caution">
수명을 길게 두어도 안전한 것은 PlaidCloud를 통해 변경되는 데이터뿐입니다. 차트가
PlaidCloud 외부에서 기록하는 테이블을 읽는 경우 대시보드에 캐시를 삭제하라고 알리는
신호가 없으며, 수명만이 캐시를 새로 고치는 유일한 수단입니다. 이러한 데이터셋에는 짧은
수명을 설정하십시오. 기본값 1시간에서는 데이터가 최대 1시간 뒤처질 수 있으며, 이전에는
최대 5분 뒤처졌습니다.
</Aside>

## 캐시 수명 변경

수명은 데이터베이스 또는 개별 데이터셋에 초 단위로 설정합니다. 데이터셋의 값이
데이터베이스의 값보다 우선하며, 둘 다 설정하지 않은 곳에는 기본값 1시간이 적용됩니다.
둘 중 하나를 변경하려면 대시보드 영역에서 해당하는 편집 권한이 필요합니다.

**데이터베이스의 모든 데이터셋에 적용하려면:**

1. 대시보드 영역에서 **Data → Databases**로 이동합니다
2. 데이터베이스의 편집 아이콘을 클릭합니다
3. **고급** 탭을 연 다음 **Performance**를 엽니다
4. **Chart cache timeout**에 초 단위 값을 입력합니다. 예를 들어 1시간은 `3600`입니다
5. **Finish**를 클릭합니다

**단일 데이터셋에 적용하려면:**

1. **Data → Datasets**로 이동합니다
2. 데이터셋의 편집 아이콘을 클릭합니다
3. **설정** 탭을 엽니다
4. **Cache timeout**에 초 단위 값을 입력합니다
5. **저장**을 클릭합니다

두 가지 값은 특별한 의미가 있습니다. `0`은 만료되지 않음을 의미하며 결과는 다시 게시할 때만
지워집니다. `-1`은 해당 데이터베이스나 데이터셋의 캐싱을 완전히 비활성화합니다.

변경 사항은 그 시점부터 캐시되는 결과에 적용됩니다. 이미 캐시에 있는 결과는 만료되거나
테이블이 다시 게시될 때까지 저장될 때의 수명을 유지합니다.

## 대시보드 수동 새로 고침

그럴 필요는 거의 없지만 대시보드의 캐시된 결과를 직접 폐기할 수 있습니다.
**Edit dashboard** 옆의 메뉴를 열고 **Force refresh dashboard**를 선택합니다. 차트가
이전 결과를 제공하고 있으면 오른쪽 위의 메모가 데이터가 캐시된 지 얼마나 되었는지 알려 주며,
이를 클릭하면 같은 새로 고침이 강제됩니다.

브라우저 페이지를 다시 로드하는 것보다 이 두 방법 중 하나를 사용하십시오. 브라우저를
다시 로드하면 차트를 다시 요청하지만 여전히 캐시된 결과를 받습니다.
