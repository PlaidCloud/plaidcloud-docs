## 브랜치 만들기

변경 사항이 준비될 때까지 기본 브랜치와 분리되도록 새 브랜치에서 작업합니다.

**UI에서:**

1. 리포지토리를 열고 왼쪽 위 근처의 브랜치 선택기(현재 브랜치 이름이 표시됨)를 선택합니다.
2. 검색 상자에 새 브랜치 이름을 입력하고 **Create Branch**를 선택합니다.

**로컬에서:**

1. 브랜치를 만들고 전환합니다: `git checkout -b feature-x`
2. 변경한 다음 스테이징하고 커밋합니다: `git add .` 다음 `git commit -m "Describe what changed"`
3. 브랜치를 PlaidCloud Git에 푸시합니다: `git push -u origin feature-x`

## 풀 리퀘스트 열기

1. 리포지토리를 열고 **Pull Requests** 탭을 선택한 다음 **New Pull Request**를 선택합니다.
2. **비교** 브랜치를 기능 브랜치로, **기본** 브랜치를 대상 브랜치(보통 `main` 또는 `master`)로 설정합니다.
3. 명확한 제목과 변경 내용 및 이유를 설명하는 설명을 작성합니다.
4. 관련 이슈를 연결하려면 설명에 닫기 키워드(예: `Closes #12`)를 추가합니다. 그러면 풀 리퀘스트가 병합될 때 이슈가 자동으로 닫힙니다.
5. 필요하면 검토자를 지정한 다음 **Create Pull Request**를 선택합니다.

## 변경 사항 검토

검토자는 아무것도 병합하지 않고 풀 리퀘스트를 검토합니다.

1. 풀 리퀘스트를 열고 **Files Changed**를 선택하여 diff를 읽습니다.
2. diff에서 줄을 선택하면 해당 변경 사항에 인라인 댓글을 남길 수 있습니다.
3. 검토를 마치면 전체 의견을 제출합니다. 승인하려면 **승인**을, 먼저 수정을 요청하려면 **Request Changes**를 선택합니다.
4. 작성자는 같은 브랜치에 커밋을 더 푸시하여 피드백을 반영합니다. 풀 리퀘스트가 자동으로 업데이트되므로 새로 열 필요가 없습니다.
5. 검토자는 각 우려 사항이 해결되면 개별 댓글 스레드를 해결됨으로 표시합니다.

<Aside>리포지토리 관리자는 기본 브랜치에 브랜치 보호를 활성화하여 풀 리퀘스트를 병합하기 전에 최소 승인 횟수를 요구할 수 있습니다.</Aside>

## 병합

풀 리퀘스트가 승인되면 다음을 수행합니다.

1. **Merge** 버튼 옆의 드롭다운에서 병합 방식을 선택합니다.
   - **Create a merge commit** — 병합 커밋으로 브랜치의 전체 기록을 보존합니다.
   - **Squash and merge** — 브랜치의 모든 커밋을 대상 브랜치의 단일 커밋으로 합칩니다.
   - **Rebase and merge** — 병합 커밋 없이 브랜치의 커밋을 대상 브랜치 위에 다시 적용합니다.
2. **Merge**를 선택하여 완료합니다.
3. 필요하면 **Delete Branch**를 선택하여 더 이상 필요하지 않은 기능 브랜치를 정리합니다.
