PlaidCloud Git은 워크스페이스에 내장된 비공개 Git 서비스입니다. 각 워크스페이스에는 코드, 구성, 노트북 및 기타 버전 관리 파일을 저장하는 전용 Git 서버가 제공되며, 팀이 이를 두고 협업하는 데 사용하는 이슈, 풀 리퀘스트, 프로젝트 보드도 함께 제공됩니다.

PlaidCloud 계정으로 로그인하므로 별도의 사용자 이름이나 암호를 설정할 필요가 없습니다. 새 리포지토리는 기본적으로 비공개이며, 액세스 권한을 부여한 멤버에게만 표시됩니다.

## Git 열기

워크스페이스의 앱 목록에서 **Git**을 선택합니다. 워크스페이스 호스트, 사용자의 역할, **Repositories** 목록이 표시된 **Git** 탭이 열립니다. **View all in Git**을 사용하면 Git 웹 인터페이스로 이동하고, **Manage who can push**(그룹을 관리할 수 있는 경우)를 사용하면 그룹 관리가 열리며, 새로 고침 버튼을 사용하면 다시 불러옵니다. **← Back to** your workspace in Git을 사용하면 PlaidCloud로 돌아갑니다.

역할 표시기에는 **관리자**, **기여자**, **뷰어** 중 사용자의 수준이 표시되며, 그 수준에서 할 수 있는 일을 설명하는 한 줄이 함께 표시됩니다. 각 리포지토리 행에는 이름, 설명(있는 경우), 날짜가 표시된 **업데이트됨**, 복사 버튼이 있는 읽기 전용 복제 필드, Git에서 리포지토리를 여는 **열기**가 표시됩니다. 비공개로 만든 리포지토리는 이 목록이 아니라 Git에서 바로 확인할 수 있습니다.

## 리포지토리 복제

리포지토리 행에서 복제 주소를 복사합니다. 처음 복사하면 아래 단계가 담긴 **Set up Git on your computer** 카드가 나타납니다. **닫기**를 선택하면 숨겨지고, 헤더의 **How to clone**을 선택하면 다시 표시됩니다.

1. 컴퓨터에 Git이 설치되어 있어야 합니다.
2. **설정 → 애플리케이션**에서 **write:repository** 권한이 있는 토큰을 만듭니다. 카드에 해당 페이지로 가는 링크가 있습니다.
3. 표시된 두 명령 `git config --global user.name`과 `user.email`로 Git에 사용자가 누구인지 알려 줍니다. 이 명령에는 이미 이름과 이메일이 들어 있습니다.
4. 표시된 `git clone` 명령으로 리포지토리를 복제합니다. Git에서 암호를 요청하면 PlaidCloud 암호가 아니라 이 토큰을 붙여 넣습니다.

각 명령에는 별도의 복사 버튼이 있습니다. 전체 안내는 [리포지토리](/ko/guides/git/repositories/)를 참조하십시오. 복사하려면 푸시 권한과 활성화된 Git 계정이 필요합니다. 복사 버튼이 비활성화되어 있으면 아무 리포지토리나 한 번 열어 계정을 활성화하거나, **뷰어**인 경우 아래 설명에 따라 푸시 권한을 요청하십시오.

## 액세스 수준

Git에 액세스할 수 있는 모든 사용자는 워크스페이스의 공유 리포지토리를 읽을 수 있습니다. 두 가지 추가 수준을 통해 푸시할 수 있습니다.

| 역할 | 할 수 있는 일 | 부여 주체 |
|---|---|---|
| **뷰어** | 공유 리포지토리를 보고 복제합니다. | 모든 멤버에게 기본 부여됩니다. |
| **기여자** | 읽기로 할 수 있는 모든 일과, [Panel](/ko/guides/panel-apps/deploy-from-git/) 및 [Dash](/ko/guides/dash-apps/deploy-from-git/) 앱 코드가 있는 `apps` 리포지토리로 푸시. | **Git Contributors** 보안 그룹. |
| **관리자** | 기여자가 할 수 있는 모든 일과, `udfs`를 포함한 모든 리포지토리로 푸시, 조직 만들기. | **Git Administration** 보안 그룹. |

`udfs` 리포지토리는 관리자로 제한됩니다. 사용자 정의 함수는 이를 호출하는 워크플로의 ID로 실행되기 때문입니다.

**뷰어**인 경우 **Git** 탭에 **Git Contributors**에 추가해 달라고 요청할 수 있는 워크스페이스 관리자가 최대 세 명까지 표시됩니다.

## 앱과 UDF에서의 Git

Panel 또는 Dash 앱 창에는 리포지토리, 브랜치, 빌드 상태를 보여 주는 **리포지토리** 섹션이 있으며, 푸시할 수 있는 멤버에게는 **Edit in browser**와 **Copy clone URL**이 표시됩니다. Git 기반 UDF의 도구 모음에는 해당 브랜치의 리포지토리를 Git에서 여는 **열기**가 있고, 관리자에게는 **Edit in browser**가 표시됩니다.

## Git 액세스 권한 부여

워크스페이스 관리자는 **ID**에서 멤버를 보안 그룹에 추가하거나 직접 만든 그룹에 권한을 추가하여 액세스 권한을 부여합니다.

1. 멤버가 앱 코드를 푸시할 수 있게 하려면 **Git Contributors**에 추가하고, Git 관리자로 지정하려면 **Git Administration**에 추가합니다.
2. 모든 새 멤버에게 앱 코드 푸시 권한을 부여하려면 **Git Contributors**를 기본 그룹에 추가합니다. **Git Administration**은 기본 그룹으로 지정할 수 없습니다.
3. 멤버가 할 수 있는 일을 확인하려면 해당 멤버를 열고 **Git** 탭을 선택합니다. 멤버의 Git 사용자 이름, 수준, 그 수준을 부여하는 그룹이 표시됩니다.

변경 사항은 멤버가 다음에 Git에 로그인하거나 **Git** 탭을 열 때 적용됩니다. 멤버의 Git 계정은 PlaidCloud 멤버십을 따릅니다. 멤버를 비활성화하거나 제거하면 토큰과 SSH 키를 포함한 Git 계정이 약 한 시간 이내에 차단되고, 다시 활성화하면 차단이 해제됩니다. 삭제되는 것은 없으며 리포지토리와 기록은 그대로 유지됩니다. 싱글 사인온으로 Git에 로그인하면 해당 멤버 본인의 계정이 열립니다. PlaidCloud 지원 담당자에게는 관리자 액세스가 자동으로 부여됩니다.

## 이 섹션의 내용

- [리포지토리](/ko/guides/git/repositories/) - 리포지토리를 만든 다음 작업을 복제, 커밋, 푸시합니다

- [풀 리퀘스트](/ko/guides/git/pull-requests/) - 브랜치에서 변경을 제안하고 병합하기 전에 검토합니다
- [프로젝트 보드](/ko/guides/git/projects/) - 칸반 보드에서 이슈와 풀 리퀘스트를 정리합니다
- [릴리스와 태그](/ko/guides/git/releases-and-tags/) - 리포지토리의 버전 스냅샷을 표시하고 게시합니다
- [위키](/ko/guides/git/wikis/) - 긴 문서를 코드 옆에 보관합니다
- [패키지](/ko/guides/git/packages/) - 리포지토리 레지스트리에서 빌드 아티팩트를 게시하고 설치합니다
- [코드 검색](/ko/guides/git/searching-code/) - 모든 리포지토리에서 코드, 이슈, 풀 리퀘스트를 찾습니다
