이슈는 버그를 추적하고, 기능을 계획하고, 주의가 필요한 모든 사항을 기록하는 팀 공용 공간이며, 리포지토리의 코드와 직접 연결됩니다.

## 이슈 만들기

1. 리포지토리를 열고 **Issues** 탭을 선택합니다.
2. **New Issue**를 선택합니다.
3. 문제나 작업을 설명하는 간결한 **제목**을 입력합니다.
4. Markdown으로 **설명**을 작성합니다. 필요에 따라 재현 단계, 승인 기준, 스크린샷, 코드 블록을 포함합니다.
5. **Submit New Issue**를 선택하여 게시합니다.

<Aside>리포지토리는 **Settings → Issue Templates**에서 재사용 가능한 이슈 템플릿을 정의할 수 있습니다. 템플릿이 구성되어 있으면 새 이슈를 열 때 선택기가 표시되어, 기여자가 빈 페이지가 아니라 일관된 양식에서 시작할 수 있습니다.</Aside>

## 레이블과 마일스톤으로 정리

**레이블**은 이슈를 분류하고 우선순위를 지정합니다. 이슈를 볼 때 오른쪽 사이드바에서 레이블을 하나 이상 적용하거나, 이슈 목록에서 **레이블** 필터를 사용해 바로 적용합니다. 일반적으로 유형 레이블(`bug`, `enhancement`)과 우선순위 레이블(`high`, `low`)을 함께 사용하지만, **Issues → Labels**에서 워크플로에 맞는 레이블을 자유롭게 만들 수 있습니다.

**마일스톤**은 릴리스 날짜, 스프린트, 기능 목표처럼 공통의 목표를 향해 이슈를 묶습니다. **Issues → Milestones**에서 마일스톤을 만든 다음 이슈의 사이드바에서 해당 마일스톤에 이슈를 할당합니다. 마일스톤 보기에서는 이슈가 닫힐 때마다 진행 상황이 표시됩니다.

## 담당자 지정과 논의

- **담당자** — 사이드바의 **Assignees** 필드를 사용하여 책임자를 지정합니다. 리포지토리에 액세스할 수 있는 모든 워크스페이스 멤버를 담당자로 지정할 수 있습니다.
- **댓글** — 이슈 설명 아래의 댓글 스레드에 맥락, 결정 사항, 상태 업데이트를 추가합니다.
- **@멘션** — 댓글이나 설명 어디에서든 `@username`을 입력하면 해당 사용자에게 직접 알림이 갑니다.
- **리액션** — 댓글에 이모지 리액션을 사용하면 답글을 달지 않고도 의견에 공감을 표시할 수 있습니다.

## 이슈를 코드에 연결

커밋과 풀 리퀘스트에서 이슈를 참조하면 기록을 추적할 수 있습니다.

- **번호로 참조** — 커밋 메시지, 풀 리퀘스트 설명, 댓글에 `#12`를 입력하면 같은 리포지토리의 12번 이슈로 연결되는 링크가 만들어집니다.
- **병합 시 자동 닫기** — 풀 리퀘스트 설명에 닫기 키워드를 포함합니다(예: `Closes #12`, `Fixes #34`, `Resolves #56`). 풀 리퀘스트가 기본 브랜치에 병합되면 참조된 이슈가 자동으로 닫힙니다.
- **다른 이슈 상호 참조** — 이슈 댓글에서 `#number`를 자유롭게 사용하여 관련 이슈를 연결합니다. 참조된 이슈에는 역방향 링크가 표시되어 양쪽에서 연결을 확인할 수 있습니다.

## 이슈 찾기

이슈 목록은 여러 필터를 조합하여 사용할 수 있습니다.

| 필터 | 기능 |
|---|---|
| **상태** | 열린 이슈 또는 닫힌 이슈 표시 |
| **레이블** | 하나 이상의 레이블로 범위 좁히기 |
| **Milestone** | 마일스톤에 할당된 이슈 표시 |
| **Assignee** | 특정 사람에게 할당된 이슈 표시 |
| **Author** | 특정 사람이 연 이슈 표시 |

이슈 목록 위의 필터 표시줄에서 해당 열을 선택하여 각 필터를 적용합니다. 키워드로 이슈 제목과 본문을 검색하려면 [코드 검색](/ko/guides/git/searching-code/)을 참조하십시오.
