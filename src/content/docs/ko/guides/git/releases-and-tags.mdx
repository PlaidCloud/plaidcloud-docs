태그는 `v1.2.0` 같은 버전처럼 중요한 커밋을 표시합니다. 릴리스는 태그에 사람이 읽을 수 있는 노트와 선택 사항인 첨부 파일을 더한 것으로, 사용자가 웹 UI에서 특정 버전을 찾아보고 다운로드할 수 있게 합니다.

## 태그 만들기

UI 또는 로컬 클론에서 태그를 만들 수 있습니다.

**UI에서:**

1. 리포지토리를 열고 **Releases**, **Tags**를 차례로 선택합니다.
2. **Create Tag**를 선택합니다.
3. 태그 이름(예: `v1.2.0`)을 입력하고 대상 브랜치나 커밋을 선택한 다음 **Create Tag**를 선택합니다.

**명령줄에서:**

```bash
git tag v1.2.0
git push origin v1.2.0
```

과거의 특정 커밋에 태그를 지정하려면 `HEAD`에 의존하지 말고 커밋 ID를 지정합니다.

```bash
git tag v1.2.0 abc1234
git push origin v1.2.0
```

## 릴리스 게시

1. 리포지토리를 열고 **Releases**를 선택합니다.
2. **New Release**를 선택합니다.
3. **Tag Name** 필드에서 기존 태그를 선택하거나 새 이름을 입력하여 현재 기본 브랜치의 끝에 태그를 만듭니다.
4. **Release Title**을 입력하고 Markdown 본문에 릴리스 노트를 작성합니다. 변경 내역, 업그레이드 안내, 알려진 문제를 모두 여기에 작성합니다.
5. 해당 버전이 일반 사용에 적합하지 않으면 **This is a pre-release**를 선택하고, 게시하지 않고 나중에 마무리하려면 **초안 저장**을 선택합니다.
6. 준비가 되면 **Publish Release**를 선택합니다.

<Aside>초안 릴리스는 쓰기 권한이 있는 리포지토리 멤버에게만 표시됩니다. 프리릴리스는 액세스 권한이 있는 모든 사용자에게 표시되지만 리포지토리 개요의 "Latest" 지정에서는 제외됩니다.</Aside>

## 파일 첨부

업로드한 파일은 자동 생성된 소스 아카이브와 함께 릴리스 페이지에 이름이 지정된 다운로드 링크로 표시됩니다.

1. 새 릴리스 또는 릴리스 편집 양식에서 **Attach Files** 섹션으로 이동합니다.
2. 업로드 영역에 파일을 끌어다 놓거나 영역을 선택하여 찾아봅니다. 빌드된 바이너리, 압축 아카이브, 체크섬, 서명이 일반적인 선택입니다.
3. 파일마다 반복한 다음 릴리스를 게시하거나 업데이트합니다.

팀의 다운로드가 빠르게 유지되도록 개별 파일 크기는 적절하게 유지하십시오.

<Aside type="tip">npm 모듈, 컨테이너 이미지, PyPI 휠 등 설치 가능한 패키지에는 릴리스 첨부 파일보다 [패키지 레지스트리](/ko/guides/git/packages/)가 더 적합합니다. 패키지 레지스트리는 단순한 파일 다운로드와 달리 버전 확인, 종속성 메타데이터, 클라이언트 도구(`npm`, `pip`, `docker pull`)를 이해합니다.</Aside>

## 릴리스 보기 및 다운로드

1. **Releases**를 선택하면 최신순으로 전체 목록이 표시됩니다.
2. 프리릴리스가 아닌 가장 최근 릴리스에는 **Latest** 배지가 강조 표시됩니다.
3. 각 항목에는 태그 이름, 릴리스 제목, 노트, 그리고 다음 링크가 표시됩니다.
   - **Source code** — 태그가 지정된 커밋의 자동 생성된 `zip` 및 `tar.gz` 아카이브입니다.
   - **Assets** — 릴리스를 게시할 때 첨부한 모든 파일입니다.
4. 파일 링크를 선택하면 바로 다운로드할 수 있으며, URL을 복사하여 공유할 수도 있습니다.

두 릴리스를 비교하려면 태그 이름을 사용하여 비교 URL을 엽니다.

```bash
https://git.example.plaidcloud.com/you/my-repo/compare/v1.1.0...v1.2.0
```
