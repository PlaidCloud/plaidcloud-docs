PlaidCloud 데이터를 **Microsoft 365 Copilot**으로 가져오십시오. PlaidCloud 에이전트를 설치하고
사용자에게 액세스 권한을 부여하면, 별도의 로그인이나 PlaidCloud 창, SQL 없이도 일상적인 말로
Copilot에게 프로젝트, 테이블, 차원, 배부 모델에 대해 물어볼 수 있습니다.

> *"내 PlaidCloud 프로젝트를 나열해 주세요."*
> *"Enterprise Profitability에는 어떤 테이블이 있나요? 그중 하나의 첫 몇 행을 보여 주세요."*
> *"지난 분기에 애틀랜타 비용 센터에 배부된 IT 비용이 왜 늘었나요?"*

<Aside type="note">
이 문서는 개발자의 IDE를 PlaidCloud에 연결하는 [GitHub Copilot](/ko/integrations/ai-coding-agents/copilot/)과
다릅니다. 이 페이지에서 다루는 것은 **Microsoft 365 Copilot**, 즉 팀 전체가 이미 사용하는
Teams, Outlook, Microsoft 365 앱 안의 어시스턴트입니다.
</Aside>

## 작동 방식

PlaidCloud는 Microsoft 365 Copilot에 연결되는 작은 **에이전트**를 게시합니다. 누군가 Copilot에게
데이터에 관해 질문하면 에이전트가 PlaidCloud 워크스페이스에 안전하게 연결하여 해당 사용자의
권한으로 요청을 실행하고, Copilot이 그 답을 설명합니다.

- **대부분의 사용자에게는 읽기 전용입니다.** 일반적인 액세스 수준은 읽기 전용이며, 프로젝트와 테이블을
  나열하고 설명하고, 테이블 데이터를 읽고, 차원 멤버를 나열하고, 배부 결과를 설명할 수 있습니다.
  숫자를 지어내지 않으며, 모든 답변은 사용자의 데이터에 대한 실제 쿼리에서 나오고, 각 답변에는
  신뢰도 신호와 쉬운 말로 된 주의 사항이 함께 제공됩니다. [신뢰할 수 있는 답변](/ko/integrations/ai-coding-agents/honest-answers/)을 참조하십시오.
- **각 사용자는 자신의 데이터만 봅니다.** 요청은 로그인한 사용자로서 실행되며, 해당 사용자가 이미 가진
  PlaidCloud 역할과 액세스 제어의 범위를 벗어나지 않습니다. 에이전트는 자격 증명, ID,
  액세스 제어 설정에는 접근할 수 없습니다.
- **권한이 부여되기 전에는 액세스할 수 없습니다.** 에이전트를 설치하는 것과 액세스 권한을 부여하는
  것은 다릅니다. 로그인한 사용자는 PlaidCloud 관리자가 액세스 수준을 부여하기 전까지
  *"액세스 권한이 부여되지 않았습니다"* 라는 메시지를 받습니다. 이는 의도된 동작이며,
  [액세스 수준](#액세스-수준)을 참조하십시오.

이러한 동작의 배경, 즉 게시된 에이전트 패키지, 전용 OAuth 클라이언트, 액세스 수준이 확인되고 적용되는
방식은 [Copilot 아키텍처](/ko/integrations/ai-architecture/microsoft-365-copilot/)를 참조하십시오.

## 설정 한눈에 보기

전체 순서입니다. 최대 세 가지 역할이 관여하며, 한 사람이 둘 이상의 역할을 맡는 경우가 많습니다.
**1~5단계에서 에이전트를 설치하고, 6단계에서 비로소 데이터가 흐릅니다.**

| # | 단계 | 담당 | 위치 |
|---|---|---|---|
| 1 | [에이전트 패키지 다운로드](#1단계--에이전트-패키지-다운로드)(`.zip`) | PlaidCloud 워크스페이스 관리자 | PlaidCloud 컨트롤 플레인 → **워크스페이스** |
| 2 | [사용자 지정 앱 허용](#2단계--사용자-지정-앱-허용) | Microsoft 365 / Teams 관리자 | Teams 관리 센터 → **Setup policies** |
| 3 | [패키지 업로드](#3단계--패키지-업로드) | Microsoft 365 / Teams 관리자 | Teams 관리 센터 → **Manage apps → 작업** |
| 4 | [Copilot에 에이전트 추가](#4단계--copilot에-에이전트-추가) | 각 사용자 | Microsoft 365 Copilot → **More agents** |
| 5 | [로그인](#5단계--로그인) | 각 사용자 | Copilot(한 번만) |
| 6 | [액세스 수준 부여](#6단계--액세스-수준-부여) | PlaidCloud 관리자 | PlaidCloud |

<Aside type="caution">
**6단계 전까지 에이전트는 연결되지만 데이터를 반환하지 않습니다.** 로그인에 성공한 뒤
*"액세스 권한이 부여되지 않았습니다"* 라는 답변이 나오면 모든 것이 정상 작동하는 것이며, 해당 사용자에게
액세스 수준만 부여하면 됩니다. 오류가 아닙니다.
</Aside>

## 1단계 — 에이전트 패키지 다운로드

조직의 에이전트 패키지는 하나의 `.zip` 파일이며, [PlaidCloud 컨트롤 플레인](/ko/administration/control-plane/)에서
직접 다운로드할 수 있습니다. 따로 요청하거나 파일을 기다릴 필요가 없습니다.

<Steps>

1. **PlaidCloud 컨트롤 플레인**에 로그인하고 왼쪽 탐색 메뉴에서 **워크스페이스**를 엽니다.

2. 데이터가 있는 워크스페이스를 엽니다(**편집** 또는 **뷰** 작업).

3. 워크스페이스 대화상자 맨 아래에서 **Download Copilot Package**를 클릭하고 `.zip` 파일을 저장합니다.

</Steps>

<Aside type="note">
**Download Copilot Package** 버튼은 PlaidCloud가 워크스페이스의 Copilot 연결을 설정한 후에만
표시됩니다. 버튼이 보이지 않으면 연결이 아직 준비되지 않은 것이므로 PlaidCloud 담당자에게 문의하십시오.
(이 버튼은 관리자 전용 Tenants 화면이 아니라 **워크스페이스** 화면에 있습니다.)
</Aside>

## 2단계 — 사용자 지정 앱 허용

*Microsoft 365 / Teams 관리자 대상.* Microsoft 365는 기본적으로 공개 스토어에 없는 앱을 차단하므로,
이 설정을 켜기 전에는 PlaidCloud 에이전트를 설치할 수 없습니다.

<Steps>

1. [Teams 관리 센터](https://admin.teams.microsoft.com/)에서 **Teams apps → Setup
   policies → Global (Org-wide default)** 정책으로 이동합니다.

2. **Upload custom apps**를 **사용**으로 설정한 다음 **저장**을 클릭합니다.

</Steps>

<Aside type="caution">
전역 관리자라고 해서 이 설정이 켜져 있는 것은 **아닙니다**. 이는 별도의 정책입니다. 이 단계를 건너뛰면
업로드가 *"Uploading custom apps is not allowed."* 오류와 함께 실패합니다. 정책 변경이 적용되기까지
최대 24시간 정도 걸릴 수 있습니다(대개는 훨씬 짧습니다). 조직 전체가 아니라 시범 그룹에만 적용하려면
별도의 설정 정책을 만들어 해당 사용자에게 할당하십시오.
</Aside>

## 3단계 — 패키지 업로드

*Microsoft 365 / Teams 관리자 대상.* `.zip` 파일을 조직의 앱 카탈로그에 추가합니다.

<Steps>

1. Teams 관리 센터에서 **Teams apps → Manage apps**로 이동합니다.

2. 페이지 **오른쪽 위**의 **작업** 메뉴를 클릭한 다음 **Upload new app**을 클릭합니다.

   <Aside type="note">
   "Upload new app"은 오른쪽 위 모서리의 **작업** 메뉴에 있으며, 이미 선택된 앱에 대해 동작하는 회색
   도구 모음(Edit installs / Edit availability / …)에는 없습니다.
   </Aside>

3. 다운로드한 `.zip` 파일을 선택합니다. 앱이 업로드되고 게시되며(**Published
   version 1.0.0**이 표시됨), Teams, Outlook, Copilot에서 지원됩니다.

4. 앱 페이지에서 **Availability**를 설정합니다. 일반 배포에는 **Everyone (org-wide default)** 옵션을, 시범 운영에는 특정 그룹을 선택합니다.

</Steps>

<Aside type="tip">
**조직 전체에 배포하지 않고 바로 직접 테스트해 보고 싶으신가요?** 관리 센터를 건너뛰고
[Microsoft 365 Copilot](https://m365.cloud.microsoft/chat)을 연 다음 **에이전트** 아래에서 사용자 지정 앱을
업로드하도록 선택하고 `.zip` 파일을 선택하십시오. 본인에게만 사이드로드되며 즉시 표시됩니다.
</Aside>

## 4단계 — Copilot에 에이전트 추가

이제 각 사용자의 Copilot에 에이전트를 추가해야 합니다.

<Steps>

1. **Microsoft 365 Copilot**([m365.cloud.microsoft/chat](https://m365.cloud.microsoft/chat)
   또는 Teams)을 열고 에이전트 목록에서 **More agents**를 클릭합니다.

2. **PlaidCloud** 에이전트를 찾아 **추가**를 클릭합니다. 그러면 에이전트 목록에 나타나 바로 열 수 있습니다.
   모든 워크스페이스의 에이전트 이름은 **PlaidCloud**이며, 워크스페이스가 둘 이상이면 에이전트 설명에
   워크스페이스 이름이 표시되어 구분할 수 있습니다.

</Steps>

<Aside type="note">
새로 **조직 전체에 게시된** 에이전트는 Microsoft가 전파하는 동안 **More agents** 아래에 표시되기까지
몇 분, 때로는 몇 시간이 걸릴 수 있습니다. **사이드로드한** 앱(3단계의 팁)은 즉시 표시됩니다. 모든 사용자가
직접 추가하지 않아도 되도록 에이전트를 미리 설치하려면 Teams **설정 정책**으로 고정하십시오.
</Aside>

## 5단계 — 로그인

사용자가 처음 에이전트를 열고 질문하면 Copilot이 **로그인**을 요청합니다. 이는 한 번만 거치는 일반적인
단계입니다.

<Steps>

1. 에이전트를 열고 *"내 PlaidCloud 프로젝트를 나열해 주세요."* 같은 질문을 합니다.

2. 안내가 표시되면 **Sign in**을 선택하고 PlaidCloud 로그인을 완료합니다.

</Steps>

이후에는 연결이 기억되므로 매번, 또는 매일 로그인하지 않아도 됩니다. 새로 로그인해야 하는 경우는
가끔(대략 한 달에 한 번)이거나 액세스가 변경되었을 때뿐입니다.

<Aside type="note">
이미 Microsoft 365에 로그인되어 있어도 로그인 과정은 대화형으로 진행됩니다. Copilot이 기존 세션을
이어받지 않는 자체 로그인 창을 열기 때문이며, 이는 정상입니다. 이 창에는 PlaidCloud 고유의 브랜딩이
표시되므로 PlaidCloud 로그인 화면이 나타나면 올바른 화면입니다.
</Aside>

에이전트가 PlaidCloud 데이터를 처음 읽을 때 Copilot이 한 번 묻습니다. *"PlaidCloud에 연결하여 이 요청과 이후 요청을 처리하겠습니다. 설정에서 언제든지 액세스를 관리할 수 있습니다."* **허용**을 선택하십시오. 이후에는 에이전트가
다시 묻지 않고 읽기 전용 조회를 실행하므로 여러 단계로 된 질문도 한 번에 답변됩니다. 에이전트의 모든
PlaidCloud 데이터 조회는 읽기 전용이며, 액세스는 여전히 해당 사용자의 PlaidCloud 액세스 수준, 권한,
행 수준 보안이 허용하는 범위로 제한됩니다.

## 6단계 — 액세스 수준 부여

*"액세스 권한이 부여되지 않았습니다"* 라는 메시지를 실제 답변으로 바꾸는 단계입니다. 사용자가 로그인한 후
**PlaidCloud 관리자**가 액세스 수준을 부여합니다(아래 [액세스 수준](#액세스-수준) 참조). 액세스는
**기본적으로 거부**됩니다. 수준이 지정되지 않으면 에이전트는 연결되지만 데이터를 반환하지 않습니다.

각 수준은 PlaidCloud 그룹이며, 사용자는 그중 하나에 속합니다.

| 수준 | 그룹 |
|---|---|
| 읽기 전용 | **Microsoft 365 Copilot Read Only** |
| 읽기/쓰기 | **Microsoft 365 Copilot Read and Write** |
| 전체 | **Microsoft 365 Copilot Full Access** |

이 그룹 중 어디에도 속하지 않은 사용자는 관리자에게 **Microsoft 365 Copilot Read Only** 그룹(또는 나머지 두 그룹 중
하나)에 추가해 달라고 요청하라는 메시지를 받습니다. 필요한 액세스에 맞는 그룹에 추가하십시오.

수준이 부여되면 사용자는 그냥 **다시 질문**하면 됩니다. 로그아웃하거나 다시 설치할 필요가 없습니다.
액세스는 모든 요청에서 실시간으로 확인되므로 다음 메시지부터 데이터가 반환됩니다.

<Aside type="note">
액세스 수준은 PlaidCloud 측에서 관리합니다. 사용자에게 수준을 부여하거나 변경하려면 PlaidCloud 담당자 또는
[support@plaidcloud.com](mailto:support@plaidcloud.com)에 문의하십시오. PlaidCloud 관리자가 ID를 직접 관리하는 경우에는
PlaidCloud의 ID 관리에서 수준을 할당하십시오.
</Aside>

## 액세스 수준

모든 PlaidCloud Copilot 사용자는 세 가지 수준 중 하나를 가집니다. 이 수준은 에이전트가 할 수 있는 작업의
**상한**이며, 그 범위 안에서도 사용자 본인의 PlaidCloud 권한이 계속 적용되므로 에이전트는 사용자가 직접 접근할 수
없는 데이터를 보여 주거나 변경할 수 없습니다.

| 수준 | 에이전트가 로드하는 도구 | 쓰기 가능 여부 | 원시 SQL | 일반적인 사용 |
|---|---|---|---|---|
| **읽기 전용** | 읽기 및 조회 도구만 제공합니다. 프로젝트와 테이블을 나열하고 설명하며, 테이블 데이터를 읽고, 차원 멤버를 나열하고, 배부를 설명합니다. | 아니요. 읽기와 설명만 가능합니다. | 읽기 전용 쿼리만 가능합니다(`SELECT` 및 집합 연산). 쓰기가 되는 문은 거부됩니다. | 대부분의 사용자. 안전한 기본값입니다. |
| **읽기/쓰기** | 읽기 전용의 모든 기능과 함께, 테이블 데이터 업데이트, 차원 노드 편집, 문서 업로드처럼 사용자에게 허용된 쓰기 도구를 제공합니다. | 예. 구조화된 쓰기만 가능하며, 각각 사용자 본인의 권한 범위로 제한됩니다. | 읽기 전용 쿼리만 가능합니다. 변경은 쓰기 도구를 통해서만 이루어지며 원시 쓰기 SQL은 사용할 수 없습니다. | 데이터를 관리하는 분석가. |
| **전체** *(사용 중단됨 — 2027년 1월 15일 제거)* | 아래의 항상 차단되는 작업을 제외한 사용자의 전체 PlaidCloud 도구 세트입니다. | 예. 구조화된 쓰기와 쓰기 원시 SQL이 가능하며, 사용자 본인의 데이터베이스 역할 범위로 제한됩니다. | 읽기 및 쓰기 SQL. | 파워 유저와 빌더. |

모든 수준에 적용되는 몇 가지 규칙이 있습니다.

- **기본적으로 거부.** 수준이 지정되지 않으면 액세스할 수 없습니다. 누군가에게 수준이 부여되기 전에는
  아무것도 노출되지 않습니다.
- **가장 높은 권한이 우선합니다.** 사용자가 어떤 이유로 둘 이상의 수준을 가진 경우 가장 높은 수준이 적용됩니다.
- **일부 작업은 전체 수준에서도 에이전트가 절대 사용할 수 없습니다.** 자격 증명, ID, 액세스 제어, 코드 배포
  도구는 사용자 본인의 PlaidCloud 권한과 관계없이 사람만 사용할 수 있습니다. 에이전트는 어떤 수준에서도
  다음을 할 수 없습니다.
  - **자격 증명 또는 액세스 제어 변경** — 데이터 연결 자격 증명과 연결의 소유자 또는 액세스 권한, 문서 저장소 자격 증명과 그 액세스 제어,
    프로젝트 액세스 제어, 프로젝트의 ERP 전기 모드, 멤버 계정, 그룹 멤버십과 역할, 배포 목록,
    비밀번호 재설정 또는 게시
  - **코드 배포 또는 작성** — 사용자 정의 함수 코드, JupyterLite 앱 또는 패널 앱

## 에이전트 사용하기

Copilot을 열고 PlaidCloud 에이전트를 선택한 다음 일상적인 말로 질문하십시오. 시작하기 좋은 질문은 다음과 같습니다.

- **내 작업 찾기:** *"내 PlaidCloud 프로젝트를 나열해 주세요."* / *"프로젝트 X에는 어떤 테이블이 있나요?"*
- **데이터 읽기:** *"customers 테이블의 처음 20행을 보여 주세요."* / *"Region 차원에는 어떤 값이 있나요?"*
- **결과 설명:** *"1분기와 2분기 사이에 애틀랜타 비용 센터에 배부된 비용이 왜 달라졌나요?"*
- **가져가기:** *"이것을 스프레드시트로 내보내 주세요."* 에이전트가 가져온 데이터로 CSV, Excel,
  PowerPoint 또는 Word 파일을 만듭니다.

에이전트는 알맞은 도구를 선택해 데이터에 대해 쿼리를 실행하고, Copilot이 결과를 먼저 제시한 다음 짧은
표나 요약으로 답변합니다. 요청이 사용자가 액세스할 수 없는 데이터나 사용자의 수준을 넘어서는 변경을 필요로 하면,
추측하지 않고 그렇다고 알려 줍니다.

## 바로 답을 얻는 질문 방법

Copilot은 비즈니스 질문에 맞는 분석 경로, 프로젝트, 테이블을 찾고, PlaidCloud가 반환한 오류를 읽어 요청을
수정한 뒤 다시 시도하므로 일시적인 문제 후에 질문을 다시 쓸 필요가 없습니다. 몇 가지 습관을 들이면 답변이
더 빠르고 정확해집니다.

- **측정값과 필터를 쉬운 말로 지정하십시오.** *"UDM, Allocated, DairyCheese의 FY2027 EBITDA"*는
  측정값(EBITDA)과 필터(회계 연도, 단위, 시나리오, 사업 부문)를 지정합니다. 필터가 적용된 합계는 한 번의
  조회로 반환됩니다.
- **어느 범위를 의미하는지 말하십시오.** 합계가 회사 전체, 사업부 또는 하나의 사업 부문일 수 있다면 어느 쪽인지
  말하십시오. 모호한 경우 Copilot은 추측하지 않고 되묻습니다.
- **Copilot이 밝힌 필터를 확인하십시오.** 모든 답변에는 적용된 필터가 나열됩니다. 의도와 다른 필터가 있으면
  알려 주십시오. Copilot이 다시 실행합니다.
- **둘 이상의 분석 경로를 사용할 때는 분석 경로의 이름을 지정하십시오.** [분석 경로](/ko/integrations/ai-coding-agents/analysis-paths/)를 참조하십시오.

## 잘 답하는 질문

에이전트는 구체적인 비즈니스 질문에서 가장 잘 작동합니다. 예시는 다음과 같습니다.

| 질문 | 에이전트의 동작 |
|---|---|
| *"UDM, Allocated 기준 DairyCheese의 FY2027 EBITDA"* | 필터가 적용된 합계를 반환하며, [지표 정의](/ko/integrations/ai-coding-agents/metric-definitions/)가 있으면 이를 사용하고 적용한 필터를 나열합니다. |
| *"제품별 매출, 수량, 비용을 보여 주세요"* | 일부 행의 샘플이 아니라 전체 테이블을 한 번에 읽어 각 제품의 모든 측정값을 합산합니다. |
| *"12번 공장의 파운드당 비용은 얼마인가요?"* | $/lb 같은 이름 있는 수치를 해당 지표 정의에서 가져와 답합니다. |
| *"IT 비용은 비용 센터에 어떻게 배부되나요?"* | 사용자의 배부 모델에서 어떤 동인을 어떤 기준으로 사용하는지 방법론을 설명합니다. |
| *"이것을 스프레드시트로 내보내 주세요"* | 방금 가져온 데이터로 CSV, Excel, PowerPoint 또는 Word 파일을 만듭니다. |

에이전트는 각 분석 경로의 설명에서 고정 필터, 부호 규칙, 사용자의 비즈니스 용어도 읽어 해당 경로의 모든
질문에 적용합니다.

## 관리자 설정 체크리스트

에이전트의 정확도는 관리자가 제공하는 컨텍스트에 달려 있습니다. 설치가 끝나면 다음을 수행하십시오.

1. **각 분석 경로에 설명을 작성하십시오.** 테이블이 무엇인지, 부호 규칙, 항상 적용되는 필터, 비즈니스 용어를
   적습니다. 에이전트는 해당 경로에 대한 모든 쿼리 전에 이를 읽습니다. [AI 어시스턴트에 유용한 경로 만들기](/ko/integrations/ai-coding-agents/analysis-paths/#ai-어시스턴트에-유용한-경로-만들기)를 참조하십시오.
2. **사람들이 묻는 비즈니스 지표를 정의하십시오.** 프로젝트에 지표 정의가 있으면 에이전트는 매출이나
   파운드당 비용 같은 이름 있는 수치를 이를 기준으로 답하므로, 모든 사용자가 같은 숫자를 얻습니다.
   [지표 정의](/ko/integrations/ai-coding-agents/metric-definitions/)를 참조하십시오.
3. **패키지를 최신으로 유지하십시오.** 파일 만들기와 지표, 세분화, 배부 방법론 답변에는 패키지 버전 1.4.0
   이상이 필요합니다. 패키지를 다시 다운로드하여 [업데이트](#에이전트-패키지-업데이트)하십시오.

## 문제 해결

| 증상 | 원인 및 해결 방법 |
|---|---|
| Manage apps에서 **Upload new app**을 찾을 수 없음 | 회색 도구 모음이 아니라 페이지 오른쪽 위의 **작업** 메뉴에 있습니다. 아예 보이지 않으면 [사용자 지정 앱 허용](#2단계--사용자-지정-앱-허용)이 아직 켜져 있지 않은 것입니다. |
| 설치 시 **"Uploading custom apps is not allowed"** 오류 | *Upload custom apps* 정책이 꺼져 있습니다. 이를 켜고([2단계](#2단계--사용자-지정-앱-허용)) 전파될 때까지 기다린 다음 다시 시도하십시오. |
| Copilot의 에이전트 목록에 에이전트가 없음 | **More agents** 아래를 확인하고 **추가**를 클릭하십시오. 조직 전체에 게시된 에이전트는 표시되기까지 시간이 걸릴 수 있습니다. 지금 테스트하려면 본인에게 [`.zip`을 사이드로드](#3단계--패키지-업로드)하십시오. |
| **"No Microsoft 365 Copilot access has been granted to this user"** | [액세스 수준이 부여](#6단계--액세스-수준-부여)되기 전에는 정상입니다. 사용자는 로그인하여 연결된 상태이며 수준만 있으면 됩니다. 부여한 직후 다시 질문하십시오. |
| **"Ask an administrator to add you to the Microsoft 365 Copilot Read Only group"**(또는 다른 수준) | 사용자가 아직 Copilot 액세스 그룹에 속해 있지 않습니다. 필요한 수준에 해당하는 [그룹에 추가](#6단계--액세스-수준-부여)한 다음 다시 질문하게 하십시오. |
| Copilot이 PlaidCloud를 쿼리할 도구가 없다고 응답함 | 에이전트 패키지가 오래되었습니다. 컨트롤 플레인에서 최신 버전으로 [업데이트](#에이전트-패키지-업데이트)하고 새 채팅을 시작하십시오. |
| 데이터 변경 요청이 거부됨 | 사용자의 액세스 수준(또는 사용자 본인의 PlaidCloud 권한)이 해당 쓰기를 허용하지 않습니다. 적절하다면 [액세스 수준](#액세스-수준)을 높이십시오. |
| 잘 작동하다가 다시 로그인하라는 요청을 받음 | 정상입니다. 저장된 연결은 주기적으로(대략 한 달에 한 번) 갱신됩니다. 한 번 더 로그인하고 계속하십시오. |
| 답변에 사용자가 접근할 수 없는 데이터가 필요해 보임 | 정상입니다. 에이전트는 로그인한 사용자가 이미 볼 수 있는 데이터만 반환합니다. |
| **읽기 전용** 사용자가 로그인할 수 있지만 테이블을 읽을 수 없음 | 임시 사항이며 해결 중입니다. 현재 읽기 전용 Copilot 사용자가 테이블을 읽으려면 더 넓은 분석 액세스가 필요합니다. [support@plaidcloud.com](mailto:support@plaidcloud.com)에 문의하십시오. |

## 에이전트 패키지 업데이트

PlaidCloud가 에이전트 패키지의 새 버전을 릴리스하면 관리자가 세 단계로 업데이트합니다.

<Steps>

1. 컨트롤 플레인에서 패키지를 다시 다운로드합니다([1단계](#1단계--에이전트-패키지-다운로드)).

2. Teams 관리 센터에서 **Manage apps**를 열고 PlaidCloud 에이전트를 선택한 다음 **업데이트**를 선택하여
   새 `.zip` 파일을 업로드합니다([3단계](#3단계--패키지-업로드)).

3. 사용자에게 에이전트와 **새 채팅**을 시작하도록 안내합니다. 이미 열려 있는 채팅은 이전 동작을 유지합니다.

</Steps>

액세스 수준과 로그인은 그대로 유지되므로 다시 로그인할 필요가 없습니다. 업데이트 후에도 Copilot이 이전 버전을
계속 사용하면 에이전트를 제거했다가 다시 추가하십시오. Agent Store를 열고 에이전트의 **…** 메뉴에서
**Uninstall**을 선택한 다음 **Built by your org**에서 다시 추가합니다. 이후 새 채팅을 시작하십시오.
