VSCode의 GitHub Copilot [에이전트 모드](https://docs.github.com/copilot/using-github-copilot/copilot-chat-in-ide/using-mcp-with-copilot)는 워크스페이스 범위 또는 사용자 범위의 `.vscode/mcp.json`(워크스페이스) 또는 전역 VSCode `mcp.json`(사용자)을 통해 MCP 서버를 지원합니다.

<Aside type="note">IDE의 GitHub Copilot이 아니라 Teams와 Microsoft 365 앱의 어시스턴트인 **Microsoft 365 Copilot**을 찾고 계신가요? [Microsoft 365 Copilot](/ko/integrations/microsoft-365-copilot/)을 참조하십시오.</Aside>

PlaidCloud 자체의 **AI 연결** 창에서도 이 단계에 접근할 수 있습니다. **기타** 탭에서 Gemini CLI, Codex CLI와 함께 GitHub Copilot을 찾을 수 있습니다.

<Aside>Copilot의 MCP 지원은 Copilot 요금제와 VSCode의 `chat.mcp.enabled` 설정에 따라 제한됩니다. 서버를 구성하기 전에 둘 다 활성화되어 있는지 확인하십시오.</Aside>

## 설정

1. PlaidCloud에 로그인한 브라우저에서 `https://<your-workspace>.plaid.cloud/mcp/setup/token`에 접속하여 전달자 토큰을 가져옵니다.

2. VSCode에서 명령 팔레트를 열고 **MCP: Add Server**를 실행하거나 `.vscode/mcp.json`을 직접 만듭니다.

    ```json
    {
      "servers": {
        "plaidcloud": {
          "type": "http",
          "url": "https://<your-workspace>.plaid.cloud/mcp",
          "headers": {
            "Authorization": "Bearer eyJhbGc…"
          }
        }
      }
    }
    ```

3. VSCode를 다시 로드합니다. Copilot 채팅 패널을 열고 모드 드롭다운을 **에이전트**로 전환한 다음 도구 목록(일반적으로 `plaidcloud_*`로 표시)에 PlaidCloud 도구가 나타나는지 확인합니다.

## 사용법

Copilot에게 PlaidCloud 작업을 직접 요청하십시오.

- "프로젝트 `Q4 Forecast`에서 마지막 실행이 실패한 모든 워크플로를 찾아 줘."
- "`customers` 테이블의 스키마를 보여 주고 인덱스를 제안해 줘."
- "`daily-load` 워크플로를 실행하고 실행 상태를 알려 줘."

Copilot은 적절한 도구를 선택해 실행하고 결과를 답변에 인용합니다. 삭제, 구성 변경, `dry_run` 없는 업서트 같은 파괴적 작업의 경우 일반적으로 확인을 요청하므로, 승인하기 전에 계획된 작업을 검토하십시오.

## 토큰 새로 고침

VSCode는 시작할 때와 파일이 변경될 때 `.vscode/mcp.json`을 읽습니다. 토큰이 만료되면 `https://<your-workspace>.plaid.cloud/mcp/setup/token`을 다시 불러와서 `Authorization` 값을 덮어쓰십시오. VSCode가 서버를 자동으로 다시 로드합니다.

## 특정 도구로 제한

Copilot이 호출할 수 있는 PlaidCloud 도구를 제한하려면 VSCode의 서버별 도구 허용 목록(Settings → Copilot → MCP → 서버별 도구 선택)을 사용하십시오. 읽기 전용 세션이나, 변경 도구(`*_upsert`, `*_run`)를 명시적으로 다시 활성화해야만 쓸 수 있도록 제한하려는 경우에 유용합니다.
