OData 피드는 프로젝트의 테이블을 OData v4 서비스로 제공합니다. Power BI, Excel, Tableau는 별도로 설치할 것 없이 자체 OData 커넥터로 이 피드를 읽습니다. 연결하기 전에 BI 피드 클라이언트를 만들어 프로젝트에 추가하십시오. [BI 도구 연결](/ko/integrations/bi-tools/)을 참조하십시오.

피드의 주소는 프로젝트의 **액세스 및 공유** 페이지에 있는 **BI 피드 클라이언트** 카드의 **피드 URL**입니다.

```text
https://odata.<workspace host>/v1/projects/<project id>/
```

모든 도구는 기본 인증으로 로그인합니다. 클라이언트 ID를 사용자 이름으로, 클라이언트 시크릿을 암호로 입력합니다. 본인으로서 읽으려면 이 단계에서 클라이언트 ID와 시크릿을 입력하라고 한 곳에 이메일 주소를 사용자 이름으로, [개인 액세스 토큰](/ko/integrations/bi-tools/#개인-액세스-토큰으로-로그인)을 암호로 입력하십시오. 토큰은 BI 피드 클라이언트가 필요 없으며 사용자가 열 수 있는 모든 프로젝트를 읽습니다.

<Aside type="caution">
클라이언트 ID와 시크릿은 도구가 자격 증명을 요청하는 곳에만 입력하십시오. 토큰을 가져오거나 시크릿을 직접 보내기 위해 Power Query(M) 쿼리에서 `Web.Contents`를 호출하지 마십시오. 피드에는 토큰이 필요 없으며, 쿼리에 작성한 내용은 보고서나 통합 문서에 저장되어 파일을 여는 누구나 읽을 수 있습니다.
</Aside>

## Power BI Desktop

1. **Get data** > **OData feed**를 선택합니다.
2. 프로젝트의 **피드 URL**을 붙여넣고 **OK**를 선택합니다.
3. Power BI가 자격 증명을 요청하면 **Basic**을 선택하고 클라이언트 ID를 **User name**으로, 시크릿을 **Password**로 입력한 다음 **Connect**를 선택합니다.
4. **Navigator**에서 로드할 테이블을 선택합니다.

Power BI는 테이블을 가져옵니다. OData 피드는 DirectQuery를 제공하지 않습니다.

행이 1,000,000개를 넘고 [페이지 단위로 제공](#페이지-단위로-제공되는-테이블)되지 않는 테이블은 로드하기 전에 필터링하거나 [증분 새로 고침](#power-bi에서-증분-새로-고침-사용)을 설정하십시오. [읽기 한 번을 행 수 제한 이내로 유지](#읽기-한-번을-행-수-제한-이내로-유지)를 참조하십시오.

## Power BI Service

Power BI Desktop에서 보고서를 게시한 다음 시맨틱 모델에 클라이언트의 자격 증명을 지정합니다.

1. 시맨틱 모델의 설정에서 **Data source credentials**를 열고 OData 원본의 **Edit credentials**를 선택합니다.
2. **Authentication method**로 **Basic**을 선택하고 클라이언트 ID와 시크릿을 입력한 다음 로그인합니다.
3. 예약된 새로 고침을 설정합니다.

Power BI Service는 피드를 직접 새로 고치므로 온-프레미스 데이터 게이트웨이가 필요하지 않습니다. Microsoft의 클라우드 주소에서 접속하므로 워크스페이스에서 모든 주소를 허용해야 합니다. [외부 액세스 켜기](/ko/integrations/bi-tools/#외부-액세스-켜기)를 참조하십시오.

클라이언트의 시크릿을 다시 생성하면 여기에도 새 시크릿을 입력하십시오. 그렇지 않으면 다음 새로 고침이 실패합니다.

Power BI Service는 분당 약 100만 개의 행으로 피드를 읽으므로 행이 1,000만 개인 테이블은 새로 고치는 데 약 10분이 걸립니다. 속도는 테이블과 웨어하우스에 따라 다릅니다. 시크릿을 다시 생성했거나 클라이언트를 프로젝트에서 제거한 경우처럼 피드가 새로 고침을 거부하면, Power BI Service는 실패를 보고하기 전에 여러 번 다시 시도하며 이 과정에 15분 정도 걸릴 수 있습니다.

## Excel

1. **Data** 탭에서 **Get Data** > **From Other Sources** > **From OData Feed**를 선택합니다.
2. 프로젝트의 **피드 URL**을 붙여넣고 **OK**를 선택합니다.
3. **Basic**을 선택하고 클라이언트 ID를 **User name**으로, 시크릿을 **Password**로 입력한 다음 **Connect**를 선택합니다.
4. **Navigator**에서 테이블을 선택한 다음 **Load**를 선택합니다.

워크시트에는 최대 1,048,576개의 행을 담을 수 있습니다. 더 큰 테이블은 **Load To...** 를 사용하여 데이터 모델에 로드하십시오.

## Tableau

Tableau Desktop에서:

1. **Connect**에서 **To a Server** > **OData**를 선택합니다.
2. 프로젝트의 **피드 URL**을 **Server**로 붙여넣습니다.
3. **Authentication**에서 **Username and Password**를 선택하고 클라이언트 ID와 시크릿을 입력한 다음 **Sign In**을 선택합니다.

Tableau Cloud에서는 데이터에 연결할 때 **OData** 커넥터를 선택하고 같은 **피드 URL**, 클라이언트 ID, 시크릿을 입력합니다.

Tableau는 OData 피드를 추출로 읽습니다. 테이블 전체를 읽기 전에 읽기를 시작했다가 중간에 멈춰 샘플을 가져오므로 각 테이블이 두 번 이상 읽힙니다. Tableau Cloud에서 추출을 새로 고치려면 자격 증명을 포함하여 데이터 원본을 게시하십시오. Tableau Cloud는 자체 주소에서 접속하며 워크스페이스에서 이 주소를 허용해야 합니다. [외부 액세스 켜기](/ko/integrations/bi-tools/#외부-액세스-켜기)를 참조하십시오.

Lakehouse v2에서 Tableau Desktop은 [페이지 단위 읽기](#페이지-단위로-제공되는-테이블)를 끝까지 따라가므로 크기와 관계없이 페이지 단위로 제공되는 테이블을 읽습니다. 그렇지 않으면 행 수 제한보다 큰 테이블은 Tableau Desktop 또는 Tableau Server에서 행 수 제한이 없는 [Flight SQL](/ko/integrations/bi-tools/flight-sql/#tableau-desktop과-tableau-server)로 읽으십시오.

## 읽기 한 번을 행 수 제한 이내로 유지

요청 하나는 최대 1,000,000개의 행을 반환합니다. 테이블이 [페이지 단위로 제공](#페이지-단위로-제공되는-테이블)되지 않는 한, 그보다 많은 행을 반환하게 되는 읽기는 아무 말 없이 중간에 멈추는 대신 다음 메시지와 함께 실패합니다.

> This table has more rows than one OData request may return (1,000,000). Filter it with $filter, or use incremental refresh.

제한 이내로 유지하려면 다음과 같이 하십시오.

- **Power Query에서 값 또는 범위로 필터링합니다.** 값과 같은 행 또는 두 숫자나 날짜 사이의 행만 유지하는 필터는 피드로 전달되므로 조건을 통과한 행만 읽습니다.
- **Power BI에서 증분 새로 고침을 사용합니다.** 그러면 새로 고칠 때마다 한 번에 하나의 날짜 범위를 읽습니다. [아래](#power-bi에서-증분-새로-고침-사용)를 참조하십시오.

### Power BI와 Excel이 피드로 보내는 것

Power BI와 Excel의 Power Query는 일부 단계를 피드에 넘기고 나머지는 직접 처리합니다.

- **피드가 처리하는 것:** 값, 숫자 범위, 날짜 범위에 대한 필터, 열 선택, 정렬, 상위 행 유지.
- **Power Query가 처리하는 것:** **Contains**(`Text.Contains`)와 같은 텍스트 필터와 행 수 세기(`Table.RowCount`). Power Query는 테이블 전체를 읽어 로컬에서 처리하므로, 큰 테이블에서는 대신 값 또는 범위로 필터링하십시오.
- **피드가 처리할 수 없는 단계 이후:** 예를 들어 추가된 열이 있으면 Power Query는 테이블 전체를 읽고 오류 없이 쿼리의 나머지를 직접 마칩니다. 필터는 이러한 단계보다 앞에 두십시오.

Power Query는 보내는 읽기마다 앞서 같은 쿼리의 처음 1,000개 행도 읽습니다.

### 페이지 단위로 제공되는 테이블

Lakehouse v2(StarRocks)에서는 제한보다 행이 많은 테이블을 페이지 단위로 제공할 수 있습니다. 각 페이지는 다음 페이지로 가는 링크로 끝나며, Power BI, Excel, Tableau Desktop은 이를 자동으로 따라갑니다. 페이지의 크기는 서로 다릅니다. 각 페이지는 행 수 제한의 절반 이상, 제한 이하의 행을 담으며 마지막 페이지에는 남은 행이 담깁니다. 모든 페이지는 첫 페이지를 읽은 시점의 테이블을 읽으므로, 새로 고치는 동안 쓰기가 있어도 행이 누락되거나 반복되지 않습니다.

페이지 단위 읽기는 각 페이지를 이전 페이지로부터 15분 이내에 가져와야 하며 첫 페이지로부터 6시간 이내에 끝내야 합니다. 그렇지 않거나 테이블이 교체된 경우처럼 읽고 있는 테이블의 버전이 더 이상 보존되지 않으면, 새로 고침이 실패하고 다시 새로 고치라는 메시지가 표시됩니다.

Lakehouse v1(Databend) 또는 자체 Snowflake나 Databricks 웨어하우스에서는, 그리고 `$orderby`로 정렬하거나 행 수 제한 이하의 `$top`을 요청하거나 `_row_id`라는 자체 열이 있는 테이블을 읽을 때는 페이지 단위로 읽지 않습니다. Lakehouse의 카탈로그가 제때 응답하지 않는 경우처럼 PlaidCloud가 읽는 테이블의 버전을 고정할 수 없을 때도 페이지 단위로 읽지 않습니다. 이때는 요청 하나가 행 수 제한까지 테이블을 반환합니다.

## Power BI에서 증분 새로 고침 사용

큰 테이블에는 증분 새로 고침을 설정하십시오. 그러면 Power BI가 한 번에 하나의 날짜 범위씩 테이블을 새로 고치므로 각 요청이 행 수 제한 이내로 유지됩니다.

1. Power Query에서 유형이 **Date/Time**인 `RangeStart`와 `RangeEnd`라는 두 매개변수를 만듭니다.
2. 테이블의 날짜 또는 타임스탬프 열을 `RangeStart` 이상이고 `RangeEnd` 미만인 행으로 필터링합니다.
3. Power BI Desktop에서 테이블의 증분 새로 고침 정책을 설정한 다음 게시합니다.

매개변수는 일반 날짜와 시간이지만 피드는 타임스탬프를 표준 시간대와 함께 UTC로, 날짜는 시간 없이 보냅니다. 따라서 타임스탬프 열은 `RangeStart` 자체가 아니라 `DateTime.AddZone(RangeStart, 0)`과 비교하고, 날짜 열은 `Date.From(RangeStart)`와 비교하십시오. 타임스탬프 열을 `RangeStart` 자체와 비교하면 `We cannot apply operator < to types DateTime and DateTimeZone.` 오류와 함께 새로 고침이 실패합니다.

예를 들면 다음과 같습니다.

```text
let
    Source = OData.Feed("https://odata.<workspace host>/v1/projects/<project id>/", null, [Implementation = "2.0"]),
    Orders = Source{[Name = "Orders"]}[Data],
    InRange = Table.SelectRows(Orders, each [OrderDate] >= DateTime.AddZone(RangeStart, 0) and [OrderDate] < DateTime.AddZone(RangeEnd, 0))
in
    InRange
```

Power BI는 필터를 피드의 `$filter`로 변환하므로 각 범위의 새로 고침은 해당 범위의 행만 읽습니다. 필터는 테이블을 선택한 직후, 피드에 넘길 수 없는 단계보다 앞에 두십시오.

## 쿼리 옵션

| 옵션 | 피드의 동작 |
| --- | --- |
| `$select` | 지정한 속성만 반환합니다. |
| `$filter` | 조건을 통과한 행만 반환합니다. [필터](#필터)를 참조하십시오. |
| `$orderby` | 하나 이상의 속성을 `asc` 또는 `desc`로 정렬합니다. 빈 값은 오름차순에서 먼저, 내림차순에서 마지막에 정렬됩니다. |
| `$top` | 최대 지정한 수만큼의 행을 반환합니다. |
| `$skip` | `$orderby`와 함께 사용할 때만 지정한 수만큼의 행을 건너뜁니다. |
| `/$count` | `<entity set>/$count`는 `$filter`가 유지하는 행 수를 일반 텍스트로 반환합니다. |
| `$format` | JSON만 지원합니다. |

피드는 `$expand`, `$search`, `$apply`, `$count=true`(대신 `/$count`를 요청하십시오)에 응답하지 않으며, `$orderby` 없는 `$skip`과 식에 대한 `$orderby`에도 응답하지 않습니다. 이 경우 Power BI와 Excel은 해당 옵션 없이 테이블을 가져온 다음 그 단계를 직접 적용합니다.

### 필터

`$filter`는 다음을 받습니다.

- **비교:** `eq`, `ne`, `gt`, `ge`, `lt`, `le`, `in`. `eq null`과 `ne null`은 비어 있는 값과 채워진 값을 찾습니다.
- **논리 및 산술:** `and`, `or`, `not`, `add`, `sub`, `mul`, `div`, `mod`.
- **텍스트 함수:** `contains`, `startswith`, `endswith`, `length`, `indexof`, `substring`, `tolower`, `toupper`, `trim`, `concat`, `matchesPattern`.
- **날짜 및 시간 함수:** `year`, `month`, `day`, `hour`, `minute`, `second`, `date`, `now`.
- **숫자 함수:** `round`, `floor`, `ceiling`.

날짜는 `2024-01-31`, 타임스탬프는 `2024-01-31T09:00:00Z`(다른 오프셋이 있는 타임스탬프는 UTC의 같은 시점으로 해석됩니다)로 작성하고, 텍스트는 작은따옴표로 묶되 내부의 따옴표는 두 번 씁니다(`'O''Neil'`). 소수는 작성한 그대로 최대 38자리까지 정확히 비교하며, 정수는 64비트에 들어가야 합니다.

`cast`, `isof`, `time`, 기간, 지리 함수, 날짜 및 시간에 대한 산술은 지원되지 않습니다.

위 내용은 도구가 보낼 때 피드가 응답하는 범위입니다. Power BI와 Excel은 이 중 일부만 보냅니다. [Power BI와 Excel이 피드로 보내는 것](#power-bi와-excel이-피드로-보내는-것)을 참조하십시오.

## 피드가 제공하는 내용

### 테이블과 이름

클라이언트가 읽을 수 있는 각 테이블은 엔터티 집합이고 각 열은 속성입니다. 뷰는 포함되지 않습니다.

이름은 테이블과 열의 이름에서 만들어집니다.

- A~Z 문자, 숫자, 밑줄로 이루어지고 문자 또는 밑줄로 시작하는 이름은 그대로 사용됩니다.
- 그 외의 이름에서는 공백이나 구두점과 같은 다른 문자의 연속이 각각 밑줄 하나로 바뀌며 양쪽 끝에는 밑줄이 남지 않습니다. A~Z 이외의 문자는 유지되지만, A~Z 또는 밑줄로 시작하지 않는 이름에는 앞에 밑줄이 붙습니다. 따라서 `Sales 2024 (EMEA)`는 `Sales_2024_EMEA`가 되고, `2024 Sales`는 `_2024_Sales`가 되며, `Cost Center Name` 열은 `Cost_Center_Name`이 됩니다.
- 테이블 이름은 125자, 열 이름은 128자로 잘립니다.

이름은 Power BI가 비교하는 방식대로 대소문자를 구분하지 않고 비교합니다. `Sales`와 `SALES`, `Sales 2024`와 `Sales_2024`처럼 두 이름이 같아지면, 각각 밑줄과 해당 테이블 또는 열에서 만든 `Sales_1a2b3c4d`와 같은 짧은 코드를 받습니다. 이 코드는 새로 고칠 때마다 같게 유지됩니다. 다만 이름을 바꾸어 한 테이블의 이름이 다른 테이블과 충돌하게 되면 둘 다 코드를 받으므로, 일반 이름으로 둘 중 하나를 읽는 보고서는 아무것도 찾지 못합니다. 이를 해결하려면 테이블 중 하나의 이름을 바꾸십시오.

### 키

각 엔터티 집합의 키는 테이블에 업데이트 키가 있고 그 중 부동 소수점 수나 바이너리가 없으면 해당 업데이트 키입니다. 그렇지 않으면 둘 다 아닌 테이블의 첫 번째 열이며, 그런 열이 없으면 첫 번째 열입니다. 키는 고유하거나 채워져 있지 않아도 됩니다. Power BI와 Excel은 키 값이 반복되거나 비어 있는 테이블도 로드합니다.

### 유형

| 열에 담긴 값 | OData 유형 |
| --- | --- |
| 참 또는 거짓 | `Edm.Boolean` |
| 정수 | 크기에 따라 `Edm.Int16`, `Edm.Int32` 또는 `Edm.Int64` |
| 통화를 포함한 소수 | 열의 전체 자릿수와 소수 자릿수를 가진 `Edm.Decimal` |
| 부동 소수점 수 | `Edm.Double` |
| 텍스트 | `Edm.String`(열에 최대 길이가 있으면 그 길이 포함) |
| 날짜 | `Edm.Date` |
| 타임스탬프 | UTC의 `Edm.DateTimeOffset` |
| 하루 중 시각 | `Edm.TimeOfDay` |
| 일과 시간의 간격 | `Edm.Duration` |
| 바이너리 | `Edm.Binary` |
| JSON, 목록, 구조체, UUID, 64비트보다 큰 정수, 월이 포함된 간격 및 그 외 모든 값 | 값을 텍스트로 담은 `Edm.String` |

피드는 소수와 64비트 정수를 자릿수 그대로 정확하게 보냅니다. 그러나 Power BI와 Excel은 숫자를 유효 자릿수 약 15자리를 유지하는 double로 보관하므로, 그보다 자릿수가 많은 소수는 마지막 자릿수를 잃으며 9,007,199,254,740,992를 넘는 정수도 마찬가지입니다. 금액의 경우 Power Query에서 열의 유형을 소수점 이하 네 자리를 정확히 유지하는 **Fixed decimal number**로 변경하십시오.

## 읽기가 실패하는 경우

로그인 메시지는 [BI 도구 연결](/ko/integrations/bi-tools/#도구가-로그인할-수-없거나-테이블이-보이지-않는-경우)에 나열되어 있습니다. 로그인한 후에는 다음과 같습니다.

| 메시지 | 조치 사항 |
| --- | --- |
| This table has more rows than one OData request may return (1,000,000). Filter it with $filter, or use incremental refresh. | [읽기 한 번을 행 수 제한 이내로 유지](#읽기-한-번을-행-수-제한-이내로-유지)를 참조하십시오. |
| This feed has no entity set … | 테이블이 없어졌거나, 이름이 바뀌었거나, 이제 클라이언트의 역할에 표시되지 않거나, 이름이 이제 [다른 이름과 충돌](#테이블과-이름)합니다. 도구의 테이블 목록을 새로 고치십시오. |
| … not a property of … | 쿼리가 테이블에 더 이상 없는 열을 지정했거나 피드에서 사용하는 이름을 쓰지 않았습니다. |
| The $filter is not valid … | 도구가 피드에서 읽을 수 없는 필터를 보냈습니다. 메시지에 읽을 수 없었던 내용이 표시됩니다. |
| This next link has expired … | [페이지 단위 읽기](#페이지-단위로-제공되는-테이블)가 페이지 사이에서 15분 넘게 기다렸습니다. 다시 새로 고치십시오. |
| This read began more than 6 hours ago … | 페이지 단위 읽기가 6시간을 넘겼습니다. 다시 새로 고치십시오. |
| The table changed while this feed was reading it, or was written to a moment ago. Refresh to read it again. | 테이블이 교체된 경우처럼 페이지 단위 읽기가 읽던 테이블의 버전을 잃었습니다. 다시 새로 고치십시오. |
