**LLM 공급자 연결**은 워크스페이스의 AI를 구동할 모델을 선택하는 곳입니다. 공급자, API 키, 기본 모델, 상시 지침을 담고 있으며, 관리자가 모델이 수행할 수 있는 작업의 범위를 결정하는 지점이기도 합니다.

## 연결이 담고 있는 내용

| 필드 | 기능 |
|---|---|
| **공급자** | Anthropic, OpenAI, Google Gemini, xAI Grok, Azure OpenAI 또는 GitHub Models. |
| **API 키** | 사용자 본인의 키입니다. 사용량은 PlaidCloud를 통해 재판매되지 않고 해당 공급자의 사용자 계정으로 청구됩니다. |
| **기본 모델** | 사용자의 API 키로 가져온, 공급자의 최신 모델 목록에서 선택합니다. **기타…** 를 선택하면 목록에 없는 모델의 ID를 직접 입력할 수 있습니다. |
| **기본 URL** | 이를 읽는 공급자에만 표시됩니다. Azure OpenAI에서는 필수(사용자 리소스 엔드포인트)이고, OpenAI, Grok, GitHub Models에서는 선택적 재정의입니다. Anthropic과 Gemini는 사용하지 않습니다. |
| **API 버전** | Azure OpenAI 전용입니다. |
| **규칙** | 모든 시스템 메시지 앞에 추가되는 상시 지침입니다. 조직 규칙, 어조, 절대 하지 말아야 할 일 등을 담습니다. |
| **에이전트 액세스** | 이 연결을 사용하는 에이전트와 단계가 수행할 수 있는 작업의 상한입니다. 높이지 않으면 읽기 전용입니다. |

이름, 메모, 연결을 볼 수 있는 사용자도 여기에서 설정하며, **연결 테스트**로 키를 사용하기 전에 확인할 수 있습니다.

워크스페이스에는 여러 연결을 둘 수 있으며, 그중 하나가 기본값으로 지정됩니다. 워크플로 단계에서 워크스페이스 기본값과 다른 모델이 필요하면 특정 연결을 지정할 수 있습니다.

공급자가 하나의 연결 유형 안의 필드가 되기 전에 만든 이전 **Anthropic Claude** 연결이 워크스페이스에 남아 있을 수도 있습니다. 이 연결은 동일한 설정을 담고 있고 동일한 편집기에서 열리며, 공급자가 Anthropic으로 고정되어 있습니다. 새 연결은 **LLM 공급자**로 만드십시오.

<Aside type="tip">
**모델 목록은 PlaidCloud가 아니라 공급자에서 가져옵니다.** 연결을 열면 사용자의 키로 접근할 수 있는 모델을 공급자에게 요청하므로, 오늘 아침에 출시된 모델도 PlaidCloud 릴리스를 기다리지 않고 제공됩니다. 임베딩, 음성, 이미지, 모더레이션 모델처럼 프롬프트에 답할 수 없는 모델은 제외됩니다.

공급자에 연결할 수 없는 경우(아직 입력하지 않은 키, 잘못된 키 또는 장애) 목록은 PlaidCloud에 내장된 목록으로 대체되며 그 사실이 표시됩니다. **기타…** 는 이 경우에도 입력한 모든 모델 ID를 받아들입니다.
</Aside>

## 공급자와 어댑터

사용자에게 보이는 여섯 공급자가 네 가지 실행 어댑터에 매핑됩니다. 어댑터는 요청의 구성 방식과 모델이 접근할 수 있는 범위를 결정합니다. 아래 공급자 이름은 연결 양식의 드롭다운에 표시되는 레이블입니다.

| 공급자 | 어댑터 | 참고 |
|---|---|---|
| Anthropic (Claude) | `anthropic` | 범위가 제한된 테이블, 차원, 문서 바인딩을 지원하는 유일한 경로입니다. |
| OpenAI (ChatGPT) | `openai_compatible` | |
| xAI (Grok) | `openai_compatible` | |
| GitHub Models | `openai_compatible` | GitHub 중심 팀을 위한 GitHub 호스팅 모델입니다. |
| Google (Gemini) | `gemini` | |
| Azure OpenAI | `azure` | 사용자의 리소스 엔드포인트를 사용하며, "모델"은 **배포 이름**이고 API 버전은 연결에서 가져옵니다. |

<Aside type="caution">
**GitHub Copilot은 여기서 선택할 수 없으며, 이는 누락이 아닙니다.** Copilot에는 서버가 연결할 수 있는 독립형 채팅 API가 없습니다. OAuth 토큰을 편집기 사용 권한으로 교환하는 방식입니다. Copilot 급 GPT 모델을 위한 Microsoft 경로는 **Azure OpenAI**(또는 GitHub Models)입니다. *IDE 클라이언트로서의* GitHub Copilot이 PlaidCloud에 연결하는 것은 전혀 다른 일이며 정상적으로 작동합니다. [GitHub Copilot](/ko/integrations/ai-coding-agents/copilot/)을 참조하십시오.
</Aside>

## 도구가 중개되는 방식

LLM은 PlaidCloud 도구를 호출할 수 있어야 여기서 유용합니다. **대화형** 어시스턴트에는 두 가지 메커니즘이 있으며, 어느 것이 실행되는지는 공급자에 따라 달라집니다. (무인 [LLM 워크플로 단계](#llm-워크플로-단계는-다릅니다)는 다르게 동작하므로 해당 섹션도 읽어 보십시오.)

### 서버 측 커넥터 — Anthropic

Anthropic의 API가 수명이 짧은 위임 토큰을 가지고 PlaidCloud MCP 엔드포인트에 직접 연결합니다. 도구 카탈로그는 Anthropic 측에서 관리하므로, 모델은 토큰이 호출할 수 있는 모든 것을 볼 수 있고 별도의 도움 없이 도구를 찾아냅니다.

이는 아래에서 설명하는 **범위가 제한된 바인딩**을 지원하는 유일한 경로이기도 합니다.

### 클라이언트 측 루프 — 그 외 모든 공급자

다른 공급자에는 이에 해당하는 커넥터가 없으므로 PlaidCloud가 루프를 직접 구동합니다. 자체 MCP 서버에 클라이언트로 연결해 도구를 나열하고, 이를 네이티브 함수 정의로 모델에 전달하며, 모델이 요청한 호출을 실행하고, 결과를 다시 전달하는 과정을 모델이 답변을 만들 때까지 반복합니다.

두 가지 제한으로 동작을 예측 가능하게 유지합니다.

- **제한된 도구 범위.** 공급자는 한 요청에 선언할 수 있는 함수의 수를 제한하며, 스키마마다 프롬프트 토큰이 소모됩니다. 노출되는 도구 집합에는 상한이 있고, 검색용 메타 도구는 항상 포함되므로 모델은 직접 목록에 없는 것도 찾아 호출할 수 있습니다.
- **고정된 왕복 횟수 제한.** 도구 루프가 폭주하면 토큰을 무한정 소모하지 않고 중단됩니다.

<Aside type="note">
중개 방식은 다르지만 적용되는 제한은 같습니다. 클라이언트 측 루프는 동일한 위임 토큰으로 동일한 MCP 서버를 호출하므로, 범위, ACL, 에이전트 액세스, 거부 목록이 Anthropic 경로와 똑같이 적용됩니다.
</Aside>

## LLM 워크플로 단계는 다릅니다

위의 내용은 모두 대화형 AI에 대한 설명입니다. 무인 **LLM 워크플로 단계**는 클라이언트 측 루프를 전혀 사용하지 않으며, 단계에 사용할 공급자를 고르기 전에 이 차이를 이해해 두는 것이 좋습니다.

| 단계의 연결에 있는 공급자 | 단계가 할 수 있는 작업 |
|---|---|
| **Anthropic** | MCP 커넥터를 통해 데이터에 접근하되, 단계에서 지정한 특정 테이블, 차원, 문서(각각 읽기 또는 쓰기로 표시)로 구성된 **범위가 제한된 바인딩**으로 제한됩니다. 도구가 존재하더라도 이 개체 밖의 모든 것은 거부됩니다. |
| **그 외 모든 공급자** | **데이터 액세스 없음.** 이 단계는 프롬프트, 규칙, 스키마를 입력하면 JSON을 출력하는 단일 구조화 완성입니다. |

여기에서 두 가지 결과가 곧바로 따라옵니다.

- **Anthropic이 아닌 단계에서는 바인딩이 무시됩니다.** 조용히 적용되지도 않고 오류도 아닙니다. 단계는 범위가 제한된 데이터 액세스가 Anthropic 전용이라는 내용을 로그에 남기고 바인딩 없이 실행됩니다. 바인딩된 단계를 Anthropic에서 다른 공급자로 전환하면 데이터를 읽지 않게 됩니다.
- **Anthropic이 아닌 단계에서는 결과 스키마가 필요합니다.** 호출할 도구가 없으므로 구조화된 출력이 단계가 만드는 유일한 결과입니다.

<Aside type="caution">
단계에서 프로젝트 개체를 읽거나 써야 한다면 Anthropic 연결에 두십시오. 다른 공급자에서는 프롬프트로 전달한 텍스트를 분류, 요약, 추출, 다시 쓰기하는 작업은 여전히 가능하지만, 무언가를 가져올 수는 없습니다.
</Aside>

## 에이전트 액세스

모든 LLM 연결에는 **에이전트 액세스** 설정이 있습니다. 이는 **상한**이며 항상 작업을 수행하는 사람의 실제 권한과 교집합으로 적용됩니다.

| 에이전트 액세스 | 이 연결의 에이전트와 단계가 수행할 수 있는 작업 |
|---|---|
| **읽기 전용** *(기본값)* | 나열, 설명, 테이블 데이터 읽기, 차원 멤버 읽기, 문서 읽기, 읽기 전용 SQL 실행. |
| **읽기 및 쓰기** | 위의 작업에 더해, 사용자가 이미 변경할 권한을 가진 사항을 PlaidCloud의 쓰기 도구로 변경합니다. 원시 SQL은 계속 읽기 전용입니다. |
| **전체** *(지원 중단 예정 — 2027년 1월 15일 제거)* | 쓰기 SQL을 포함한 사용자의 전체 도구 집합. 대신 **읽기 및 쓰기**를 사용하십시오. |

모든 에이전트 액세스 설정에는 무조건 적용되는 거부 목록이 있습니다. 연결 및 자격 증명 설정, 연결의 소유자 또는 액세스 권한자, 문서 계정 자격 증명과 ACL, 멤버 및 그룹 관리, 비밀번호 재설정, 프로젝트 ACL, 프로젝트의 ERP 전기 모드, 게시, 사용자 정의 함수 코드, 앱 배포가 여기에 해당합니다. 이러한 작업은 AI 자격 증명으로 호출할 수 없습니다.

Anthropic 워크플로 단계에서는 에이전트 액세스가 **바인딩**과 상호작용합니다. **읽기 및 쓰기**에서는 쓰기가 바인딩된 개체별로 부여되므로, 단계는 선택한 하나의 테이블에만 쓸 수 있고 그 외에는 쓸 수 없습니다.

## 구조화된 결과

단계에서 결과 스키마를 선언하면 답변은 본문에서 파싱되는 것이 아니라 스키마에 대해 검증됩니다. 공급자마다 스키마를 표현하는 방식이 다르므로 스키마는 공급자별로 변환되며(OpenAI 호환 엔드포인트에는 엄격한 JSON 방언, Gemini에는 OpenAPI 하위 집합), 거부 응답이나 잘린 응답은 혼란스러운 "잘못된 JSON" 대신 별도의 오류로 표시됩니다.

## 알아 둘 보호 장치

- **아웃바운드 URL은 호출 전에 검증됩니다.** 기본 URL은 HTTPS여야 하고 공개 주소로 확인되어야 합니다. 루프백, 사설 대역, 링크 로컬, 클라우드 메타데이터 주소는 거부되며, 응답이 호출을 다른 곳으로 우회시키지 못하도록 리디렉션이 비활성화됩니다.
- **키는 로그와 오류에 남지 않습니다.** 공급자 오류는 자격 증명이 포함된 채 그대로 반환되지 않고 정제됩니다.
- **규칙은 지침이며 권한이 아닙니다.** 연결의 상시 규칙은 모델의 동작 방식을 조정합니다. 모델이 접근할 수 있는 범위를 높일 수는 없습니다.
