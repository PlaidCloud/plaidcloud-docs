**Workspaces** 페이지에는 관리할 수 있는 PlaidCloud 워크스페이스가 나열됩니다. 이 페이지에서 워크스페이스를 만들고, 워크스페이스 설정을 편집하고, 워크스페이스를 열고, 대시보드를 열고, SQL 콘솔을 열고, 로그와 지표를 보거나, 선택한 워크스페이스에 일괄 작업을 적용할 수 있습니다.

<Aside type="caution">
	삭제하면 워크스페이스와 관련 데이터가 제거됩니다. 워크스페이스를 삭제하기 전에 백업과 보존 요구 사항을 확인하십시오.
</Aside>

## 워크스페이스 목록

워크스페이스 테이블에는 이름, 고유 ID, 버전, 릴리스 채널, 상태, 일시 중지 상태, 생성일, 프로비저닝 상태, 클러스터, 유지 관리 요일, 유지 관리 시간이 포함됩니다. 이 테이블은 검색, 새로 고침, 행 작업, 일괄 작업을 지원합니다.

사용할 수 있는 행 작업은 다음과 같습니다.

| 작업 | 설명 |
| --- | --- |
| 보기 | 읽기 전용 워크스페이스 세부 정보를 엽니다. |
| 편집 | 워크스페이스 구성을 변경합니다. |
| 삭제 | 워크스페이스를 삭제합니다. |
| 홈 | 워크스페이스 애플리케이션을 엽니다. |
| 대시보드 | 워크스페이스 대시보드 서비스를 엽니다. |
| SQL | 워크스페이스 SQL 콘솔을 엽니다. |
| 로그 및 지표 | 워크스페이스의 운영 로그와 지표를 엽니다. |

홈, 대시보드, SQL, 로그 및 지표의 네 가지 서비스 작업은 실행 중인 워크스페이스에서만, 그리고 해당 워크스페이스에서 사용 설정된 서비스에 대해서만 표시됩니다. 아직 만드는 중인 워크스페이스에는 서비스 아이콘이 전혀 표시되지 않으므로 클릭해도 아무 곳으로도 이동하지 않는 링크는 없습니다.

## 프로비저닝 상태

워크스페이스를 만드는 데는 몇 분이 걸리며, 완료되기 전까지는 워크스페이스가 존재하더라도 열 수 없습니다. **생성됨**, **상태**, **Provisioning** 열은 진행 상황을 알려 주며, 워크스페이스 세부 정보 대화상자의 **Provisioning** 탭에는 한 워크스페이스에 대해 같은 정보가 해당 워크스페이스에 현재 게시된 서비스 URL과 함께 표시됩니다.

| 열 | 알려 주는 내용 |
| --- | --- |
| 생성됨 | 워크스페이스 레코드가 만들어진 시점입니다. 첫 번째 프로비저닝 시도가 시작된 시점이기도 합니다. |
| 상태 | 프로비저닝이 진행 중인 단계이며, 예를 들어 `activating`입니다. 완료된 워크스페이스는 `running`으로 표시됩니다. |
| 프로비저닝 | 단계를 한 단어로 요약한 값으로, `provisioning`, `running`, `failed`, `paused`, `trashed`, `deleting` 중 하나입니다. |

약 30분 넘게 같은 단계에 머물러 있는 워크스페이스는 멈춘 것이며, `failed`로 표시된 워크스페이스는 중단된 것입니다. 어느 경우든 워크스페이스 ID와 표시된 단계를 알려 PlaidCloud 지원팀에 문의하십시오. 실패 세부 정보에는 PlaidCloud 내부 구성 요소 이름이 포함되므로 여기에 표시되지 않고 PlaidAdmin 영역에서 보관합니다.

<Aside type="note">
	배포가 끝났다고 해서 워크스페이스가 자체 설정을 마친 것은 아니므로, 워크스페이스가 배포 도구에서는 정상으로 보이더라도 아직 사용할 수 없을 수 있습니다. **Provisioning** 열은 워크스페이스 자체의 설정 상태를 보고하며, 로그인할 수 있는지 여부는 이 설정 상태가 결정합니다.
</Aside>

## Single Sign-On

회사의 ID 공급자를 사용하여 별도의 PlaidCloud 비밀번호 없이 워크스페이스에 로그인할 수 있게 합니다. **Workspaces** 페이지에서 해당 워크스페이스의 **Single sign-on**을 선택합니다. 대화상자에는 현재 **Sign-in options**가 각각의 상태(**사용** 또는 **끄기**), **Test sign-in**, **제거**와 함께 나열되며, **Add an identity provider** 아래에서 새 옵션을 추가합니다.

### 요금제와 로그인 방법

Free(Sandbox)를 포함한 모든 요금제에는 다단계 인증(MFA)을 사용하는 비밀번호 로그인과 Google, Microsoft(개인 또는 조직 “common” 로그인), GitHub를 이용한 소셜 로그인이 포함됩니다. 상위 요금제에서는 자체 ID 공급자를 사용하는 엔터프라이즈 Single Sign-On이 추가됩니다.

| 요금제 | 추가되는 항목 |
| --- | --- |
| Free (Sandbox) | 모든 요금제에 포함된 로그인 방법 외에는 없음 |
| Starter | 모든 요금제에 포함된 로그인 방법 외에는 없음 |
| Team | SAML |
| Business | Microsoft Entra ID 및 Okta |
| Enterprise | 기타 OpenID Connect 공급자 및 SCIM |

각 요금제에는 그 아래 요금제의 모든 기능이 포함됩니다. Free(Sandbox)와 Starter에서는 **Single sign-on** 대화상자에 ID 공급자 선택 항목 대신 업그레이드 안내가 표시됩니다.

요금제를 다운그레이드하면 이미 추가한 공급자는 계속 나열되며 제거할 수 있지만, 해당 요금제에 포함되지 않은 공급자는 새로 추가할 수 없습니다.

### ID 공급자 추가

1. 요금제에 따라 **Identity provider**를 선택합니다. **Microsoft Entra ID**, **Okta**, **Other (OpenID Connect)** 중에서 선택할 수 있습니다.
2. **복사**로 **Redirect URI**를 복사한 다음 아래 설명에 따라 ID 공급자에 등록합니다.
3. 해당 공급자의 필드를 입력하고 **Add provider**를 선택합니다.
4. **Test sign-in**을 선택하면 워크스페이스가 열리며, 시크릿 창에서 새 공급자를 통해 로그인해 볼 수 있습니다. 팀에 알리기 전에 테스트하십시오.

| 공급자 | ID 공급자에 등록할 내용 | PlaidCloud에 입력할 내용 |
|---|---|---|
| Microsoft Entra ID | Microsoft Entra 관리 센터에서 리디렉션 URI를 사용하여 앱(Web 플랫폼)을 등록하고, **Certificates & secrets**에서 클라이언트 비밀을 추가하고, **Token configuration**에서 ID 토큰에 선택적 `email` 클레임을 추가합니다. | **Directory (tenant) ID**, **클라이언트 ID**, **클라이언트 시크릿** |
| Okta | Okta Admin Console에서 리디렉션 URI를 로그인 리디렉션 URI로 하는 OIDC 웹 애플리케이션을 만들고, 액세스 권한을 가져야 할 사람들을 할당합니다. | **Okta domain**(예: `acme.okta.com`), **클라이언트 ID**, **클라이언트 시크릿** |
| 기타(OpenID Connect) | 리디렉션 URI로 기밀 웹 클라이언트를 등록합니다. | **Button label**, **Discovery URL**, **클라이언트 ID**, **클라이언트 시크릿** |

**Other (OpenID Connect)** 의 경우 PlaidCloud는 검색 URL에서 엔드포인트를 읽습니다. 그곳에서 구성을 읽을 수 없거나 발급자가 검색 URL과 다른 사이트에 있으면 **Enter endpoints manually**를 선택하고 **Issuer**, **Authorization URL**, **Token URL**, **JWKS URL**, 그리고 선택적으로 **Userinfo URL (optional)** 을 입력합니다. 공급자 주소는 PlaidCloud가 접근할 수 있는 공개 호스트여야 합니다.

**Button label**은 로그인 페이지에서 사람들에게 표시되는 이름이며, 예를 들어 *Acme SSO*입니다.

### 기존 계정과 이메일 확인

- 같은 이메일로 이미 PlaidCloud 계정이 있는 사람은 해당 계정에 한 번 로그인하여 연결합니다. PlaidCloud는 이메일이 일치한다는 이유만으로 계정을 연결하지 않습니다.
- **Trust email addresses from this provider (new people skip email verification)** 은 기본적으로 꺼져 있습니다. 신규 사용자는 처음 로그인할 때 이메일 주소를 확인합니다. ID 공급자가 보내는 주소를 보증하는 경우에만 이 옵션을 켜십시오.

### ID 공급자 제거

공급자 옆의 **제거**를 선택합니다. 이후 사람들은 해당 공급자로 로그인할 수 없습니다. 이미 있는 계정은 그대로 유지되며, 비밀번호를 재설정하여 로그인할 수 있습니다.

## 일괄 작업

일괄 작업을 사용하려면 워크스페이스를 하나 이상 선택합니다.

| 일괄 작업 | 설명 |
| --- | --- |
| 버전 설정 | 선택한 워크스페이스를 지정한 버전에 고정합니다. 선택한 모든 워크스페이스가 동일한 릴리스 채널을 사용해야 합니다. |
| 일시 중지 | 선택한 워크스페이스를 일시 중지합니다. |
| 일시 중지 해제 | 일시 중지된 선택한 워크스페이스를 복원합니다. |

## 기본 설정

기본 설정은 워크스페이스를 식별하고, 소유권을 할당하고, 릴리스 동작을 제어합니다.

| 설정 | 설명 |
| --- | --- |
| 이름 | 워크스페이스의 표시 이름입니다. |
| ID | 고유한 워크스페이스 식별자입니다. 워크스페이스 ID의 일부가 되며 생성 중에 설정됩니다. |
| 메모 | 선택 사항인 설명 또는 관리 메모입니다. |
| 조직 | 워크스페이스를 소유한 조직입니다. |
| 소유자 | 워크스페이스 소유자의 이메일입니다. |
| 데이터 센터(클러스터) | 워크스페이스가 실행되는 데이터 센터 또는 클러스터입니다. |
| 릴리스 | 릴리스 채널: Rapid, Regular, Stable 또는 No Release(고정)입니다. |
| 버전 | 배포된 특정 버전입니다. |
| 활성 | 워크스페이스를 활성으로 표시합니다. |
| 일시 중지됨 | 워크스페이스를 삭제하지 않고 운영을 일시 중지합니다. |
| 초대 링크 유효 기간 | 신규 사용자 초대 링크가 유효한 기간입니다. 옵션은 12시간, 1일, 2일, 3일, 5일, 7일, 10일, 14일입니다. |

## 릴리스 옵션

| 릴리스 | 일반적인 사용 용도 |
| --- | --- |
| Rapid | 업데이트를 가장 먼저 받습니다. 더 빠른 제품 변경을 수용할 수 있는 워크스페이스에 사용합니다. |
| Regular | 대부분의 워크스페이스에 적용되는 기본 업데이트 주기입니다. |
| Stable | 업데이트 안정성을 우선하는 워크스페이스를 위한 더 느린 주기입니다. |
| No Release(고정) | 관리자가 변경할 때까지 워크스페이스를 선택한 버전으로 유지합니다. |

유지 관리 기간은 자동 릴리스 업데이트가 적용되는 시점을 결정합니다.

## 자동 릴리스 업데이트

PlaidCloud는 새 릴리스를 지속적으로 게시하고 워크스페이스에 자동으로 전달합니다. 업데이트를 요청하거나 설치할 필요가 없습니다. 릴리스가 워크스페이스의 릴리스 채널에 도달하면 PlaidCloud가 유지 관리 기간에 워크스페이스를 업그레이드합니다. 릴리스 채널은 릴리스가 얼마나 빨리 도착하는지를 결정하고, 유지 관리 기간은 업그레이드가 하루 중 언제 적용되는지를 결정합니다.

### 릴리스가 워크스페이스에 도달하는 과정

1. PlaidCloud가 채널에 릴리스를 게시합니다. Rapid가 가장 먼저 받고, 그다음 Regular, 그다음 Stable이 받습니다.
2. 업그레이드 최소 7일 전에 조직의 모든 구성원에게 릴리스 이름과 적용 날짜를 알리는 사전 공지 이메일이 전송됩니다.
3. 공지 이후 워크스페이스의 첫 번째 유지 관리 기간에 PlaidCloud가 워크스페이스를 해당 릴리스로 업그레이드합니다. 기본 유지 관리 기간은 일요일 02:00 UTC이며, 요일과 시간은 [유지 관리](#유지-관리)에서 설정합니다.
4. 워크스페이스의 **버전**이 새 릴리스로 업데이트됩니다. 사용자나 워크스페이스 사용자가 별도로 해야 할 작업은 없습니다.

워크스페이스는 자체 유지 관리 기간에만 업그레이드되므로 업데이트는 예측 가능하고 트래픽이 적은 시간에 적용되며, 7일 전 공지 덕분에 모든 조직이 변경에 맞춰 계획할 시간을 가질 수 있습니다.

### 워크스페이스를 고정하여 제외하기

워크스페이스를 현재 버전에 유지하려면 **Release** 채널을 **No Release (pinned)** 로 설정합니다. 자동 업그레이드는 고정된 워크스페이스를 건너뛰며, 관리자가 새 버전을 선택하거나 채널로 다시 옮길 때까지 선택한 버전에 머뭅니다. 검증 주기나 규제 대상 마감 기간처럼 워크스페이스를 고정해 두어야 할 때 고정하십시오.

고정은 이후의 업그레이드만 중지하며 이미 적용된 업그레이드를 되돌리지는 않습니다. 고정된 워크스페이스를 다시 앞으로 이동하려면 특정 **버전**을 선택하거나 Rapid, Regular 또는 Stable 채널을 선택하십시오. 그러면 워크스페이스가 자동 일정에 다시 참여합니다.

## 테마

테마 설정은 워크스페이스의 진입점 전반에서 브랜딩을 사용자 지정합니다.

| 설정 | 설명 |
| --- | --- |
| 앱 로고 | 워크스페이스 애플리케이션에 표시되는 로고입니다. |
| 시작 화면 로고 | 워크스페이스 시작 화면 또는 로그인 화면에 표시되는 로고입니다. |
| Superset 로고 | 대시보드 서비스에 표시되는 로고입니다. |
| Superset 사용자 지정 테마 | 워크스페이스에서 사용할 수 있는 사용자 지정 대시보드 색상 테마입니다. |

## 서비스

서비스 설정은 워크스페이스 내부의 선택적 애플리케이션과 지원 서비스를 사용 설정합니다.

| 설정 | 설명 |
| --- | --- |
| JupyterHub | 워크스페이스 사용자를 위한 호스팅 노트북 액세스를 사용 설정합니다. |
| 웹 SQL 콘솔(CloudBeaver) | 브라우저 기반 SQL 액세스를 사용 설정합니다. |
| 대시보드(Apache Superset) | 대시보드 서비스를 사용 설정합니다. |
| 사용자 양식 및 워크플로(Forms Flow) | 양식 및 워크플로 앱 지원을 사용 설정합니다. |
| 변경 데이터 캡처(Apache Flink) | 변경 데이터 캡처 처리를 사용 설정합니다. |
| SFTP 액세스 및 웹 UI | SFTP 액세스와 SFTP 웹 인터페이스를 사용 설정합니다. |
| PlaidCloud 프록시 다운로드 사용 | 다운로드를 PlaidCloud 프록시 경로로 라우팅합니다. |
| 벡터 데이터베이스(Weaviate) 활성화 | 벡터 데이터베이스 지원을 사용 설정합니다. |
| 사용자 지정 앱 샌드박스 활성화 | 사용자 지정 앱 샌드박스 지원을 사용 설정합니다. |
| 프로젝트 관리 앱 활성화 | 프로젝트 관리 애플리케이션을 사용 설정합니다. |

일부 서비스는 사용자가 사용하기 전에 컨트롤 플레인 양식 외부에서 추가 프로비저닝이 필요할 수 있습니다.

## Lakehouse

Lakehouse 설정은 외부 데이터베이스 연결과 추가 데이터베이스 사용자를 제어합니다.

| 설정 | 설명 |
| --- | --- |
| 외부 데이터베이스 액세스 사용 | 외부 클라이언트가 워크스페이스 Lakehouse에 연결할 수 있게 합니다. |
| 허용된 CIDR | 연결이 허용되는 CIDR 범위이며 쉼표로 구분합니다. 허용 목록이 필요하지 않으면 비워 둡니다. |
| 거부된 CIDR | 거부되는 CIDR 범위이며 쉼표로 구분합니다. |
| 추가 Lakehouse 사용자 | 데이터베이스 액세스를 위한 추가 Lakehouse 사용자 이름과 비밀번호입니다. |

사용자와 통합을 지원하는 범위에서 가장 좁은 CIDR 범위를 사용하십시오. 더 이상 액세스가 필요하지 않으면 사용하지 않는 Lakehouse 사용자를 제거하십시오.

## 유지 관리

유지 관리 설정은 워크스페이스에서 선호하는 업데이트 기간을 정의합니다.

| 설정 | 설명 |
| --- | --- |
| 요일 | 유지 관리 요일: 일요일부터 토요일까지입니다. |
| 시간 | 15분 단위의 하루 중 시간입니다. |

릴리스 채널 업그레이드는 워크스페이스 유지 관리 기간을 사용합니다. 고정된 워크스페이스는 관리자가 새 버전이나 채널을 선택할 때까지 자동 릴리스 채널 업그레이드에서 제외됩니다.
