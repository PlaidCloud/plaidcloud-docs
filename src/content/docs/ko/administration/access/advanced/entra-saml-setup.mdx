PlaidCloud는 SAML 2.0을 통한 싱글 사인온(SSO)을 지원합니다. 이 가이드에서는 조직의 사용자가 PlaidCloud에 접속할 때 Entra를 통해 인증할 수 있도록 Microsoft Entra ID(이전 이름: Azure Active Directory)를 SAML ID 공급자로 구성하는 방법을 안내합니다.

<Aside>PlaidCloud 측 구성은 PlaidCloud 팀이 처리합니다. 사용자는 Entra에서 엔터프라이즈 애플리케이션을 설정하고 **App Federation Metadata URL**을 PlaidCloud에 제공해야 합니다. 나머지 구성은 PlaidCloud 지원팀이 완료합니다.</Aside>

## 사전 요구 사항

- 활성 Microsoft Entra ID(Azure AD) 테넌트
- 다음 Entra 역할 중 하나가 있는 계정: **Global Administrator**, **Cloud Application Administrator** 또는 **Application Administrator**
- 설정을 조율하고 구성 값을 주고받기 위한 PlaidCloud 지원팀과의 연락

## 개요

설정 과정에서는 두 당사자가 SAML 메타데이터를 교환합니다.

1. **사용자가 구성합니다.** Entra ID에서 엔터프라이즈 애플리케이션을 구성하고, App Federation Metadata URL을 PlaidCloud에 제공합니다.
2. **PlaidCloud가 제공합니다.** Entra 구성을 완료하는 데 필요한 서비스 공급자(SP) Entity ID와 Reply URL(Assertion Consumer Service URL)을 제공합니다.

아래 3단계를 완료하기 전에 PlaidCloud 지원팀과 협의하여 SP 값을 받으십시오.

## 1단계: 엔터프라이즈 애플리케이션 만들기

1. [Azure portal](https://portal.azure.com)에 로그인하여 **Microsoft Entra ID**로 이동합니다.
2. 왼쪽 사이드바에서 **Enterprise Applications**를 선택합니다.
3. **+ New application**을 클릭합니다.
4. **+ Create your own application**을 클릭합니다.
5. 애플리케이션 이름을 입력합니다(예: `PlaidCloud SSO`).
6. **Integrate any other application you don't find in the gallery (Non-gallery)** 를 선택합니다.
7. **만들기**를 클릭합니다.

## 2단계: SAML 기반 싱글 사인온 사용

1. 애플리케이션을 만든 후 왼쪽 사이드바의 **관리** 아래에서 **Single sign-on**을 선택합니다.
2. "Select a single sign-on method" 화면에서 **SAML**을 클릭합니다.

## 3단계: 기본 SAML 설정 구성

<Aside>이 단계를 완료하려면 PlaidCloud에서 받은 **SP Entity ID**와 **Reply URL(ACS URL)** 이 필요합니다. 이 값은 PlaidCloud 지원팀에 문의하여 받으십시오.</Aside>

1. **Basic SAML Configuration** 섹션에서 **편집**을 클릭합니다.
2. **Identifier (Entity ID)** 필드에 PlaidCloud에서 제공한 SP Entity ID를 입력합니다.
3. **Reply URL (Assertion Consumer Service URL)** 필드에 PlaidCloud에서 제공한 ACS URL을 입력합니다.
4. **저장**을 클릭합니다.

## 4단계: 특성 및 클레임 구성

기본적으로 Entra는 SAML 어설션으로 사용자의 이메일 주소와 이름을 전달합니다. PlaidCloud 구성에서 SSO의 보안 그룹 할당을 사용하는 경우 그룹 클레임도 포함해야 합니다.

### 그룹 클레임 추가

1. **Attributes & Claims** 섹션에서 **편집**을 클릭합니다.
2. **+ Add a group claim**을 클릭합니다.
3. **Groups assigned to the application**을 선택합니다(토큰 크기를 제한하려면 이 옵션을 권장합니다).
4. **Source attribute**에서 적절한 값을 선택합니다.
   - **그룹 ID** — 그룹의 Azure 개체 ID(UUID)를 전달합니다.
   - **Cloud-only group display names** — 사람이 읽을 수 있는 그룹 이름을 전달합니다(클라우드 전용 그룹용).
   - **sAMAccountName** — 온프레미스 그룹 이름을 전달합니다(하이브리드/동기화 환경용).
5. **저장**을 클릭합니다.

<Aside>PlaidCloud에서 그룹 기반 보안 역할 할당이 올바르게 작동하려면 어떤 그룹 속성 형식이 필요한지 PlaidCloud 지원팀과 협의하십시오.</Aside>

## 5단계: 애플리케이션에 사용자 및 그룹 할당

엔터프라이즈 애플리케이션에 할당된 사용자와 그룹만 이 SSO 구성을 통해 인증할 수 있습니다.

1. 왼쪽 사이드바의 **관리** 아래에서 **Users and groups**를 선택합니다.
2. **+ Add user/group**을 클릭합니다.
3. PlaidCloud SSO 액세스 권한을 부여할 사용자 또는 그룹을 선택합니다.
4. **할당**을 클릭합니다.

## 6단계: App Federation Metadata URL 확인 및 전송

애플리케이션 구성이 끝나면 Federation Metadata URL을 찾아 PlaidCloud에 보내 통합을 완료합니다.

1. 엔터프라이즈 애플리케이션의 **Single sign-on** 페이지로 이동합니다.
2. **SAML Certificates** 섹션까지 스크롤합니다.
3. **App Federation Metadata URL**을 복사합니다.

**이 URL을 PlaidCloud 지원팀에 보내십시오.** 이 URL은 PlaidCloud가 ID 공급자 측에서 신뢰 관계를 구성하는 데 필요한 Entity Descriptor URL입니다. PlaidCloud가 이 URL을 받으면 팀에서 Keycloak 구성을 완료하고 SSO를 테스트할 준비가 되었을 때 알려 드립니다.

## 통합 테스트

PlaidCloud에서 구성이 완료되었다고 확인한 후 다음을 수행합니다.

1. 조직의 PlaidCloud 워크스페이스로 이동합니다(예: `https://my-workspace.plaid.cloud`).
2. Microsoft 로그인 페이지로 리디렉션됩니다.
3. Entra ID 자격 증명으로 로그인합니다.
4. 인증에 성공하면 PlaidCloud로 다시 리디렉션됩니다.

오류가 발생하면 다음을 확인하십시오.
- SP Entity ID와 Reply URL이 PlaidCloud에서 제공한 값과 정확히 일치하는지 확인합니다.
- 로그인하려는 사용자가 엔터프라이즈 애플리케이션에 할당되어 있는지 확인합니다.
- PlaidCloud에 보낸 App Federation Metadata URL에 접근할 수 있는지 확인합니다(방화벽 또는 조건부 액세스 정책에 의해 차단되지 않아야 합니다).
