PlaidCloud는 SAML 2.0을 통한 싱글 사인온(SSO)을 지원합니다. 이 가이드에서는 조직의 사용자가 PlaidCloud에 접속할 때 Google을 통해 인증할 수 있도록 Google Workspace를 SAML ID 공급자로 구성하는 방법을 안내합니다.

<Aside>PlaidCloud 측 구성은 PlaidCloud 팀이 처리합니다. 사용자는 Google Workspace에서 사용자 지정 SAML 앱을 설정하고 **IdP Metadata URL**을 PlaidCloud에 제공해야 합니다. 나머지 구성은 PlaidCloud 지원팀이 완료합니다.</Aside>

## 사전 요구 사항

- Google Workspace 계정(Business Starter 이상)
- **Super Admin** 역할이 있는 Google Workspace 계정
- 설정을 조율하고 구성 값을 주고받기 위한 PlaidCloud 지원팀과의 연락

## 개요

설정 과정에서는 두 당사자가 SAML 메타데이터를 교환합니다.

1. **사용자가 구성합니다.** Google Workspace에서 사용자 지정 SAML 앱을 구성하고, IdP Metadata URL을 PlaidCloud에 제공합니다.
2. **PlaidCloud가 제공합니다.** Google Workspace 구성을 완료하는 데 필요한 서비스 공급자(SP) Entity ID와 ACS URL(Assertion Consumer Service URL)을 제공합니다.

아래 3단계를 완료하기 전에 PlaidCloud 지원팀과 협의하여 SP 값을 받으십시오.

## 1단계: 사용자 지정 SAML 앱 만들기

1. Super Admin으로 [Google Admin console](https://admin.google.com)에 로그인합니다.
2. **앱** > **Web and mobile apps**로 이동합니다.
3. **Add app** > **Add custom SAML app**을 클릭합니다.
4. 앱 이름을 입력하고(예: `PlaidCloud SSO`) 필요하면 설명과 아이콘을 추가합니다.
5. **계속**을 클릭합니다.

## 2단계: IdP Metadata URL 확인

**Google Identity Provider details** 화면에는 PlaidCloud에 필요한 ID 공급자 정보가 표시됩니다.

1. **SSO URL**과 **Entity ID**를 복사하고 **Certificate**를 다운로드하거나,
2. **IDP metadata** URL 옆의 **복사**를 클릭합니다(형식: `https://accounts.google.com/o/saml2/idp?idpid=XXXXXXXXX`).

**이 IdP Metadata URL을 PlaidCloud 지원팀에 보내십시오.** 이 URL은 PlaidCloud가 ID 공급자 측에서 신뢰 관계를 구성하는 데 필요한 Entity Descriptor URL입니다. PlaidCloud가 이 URL을 받으면 팀에서 Keycloak 구성을 완료하고 SSO를 테스트할 준비가 되었을 때 알려 드립니다.

3. **계속**을 클릭하여 서비스 공급자 구성으로 이동합니다.

## 3단계: 서비스 공급자 세부 정보 구성

<Aside>이 단계를 완료하려면 PlaidCloud에서 받은 **SP Entity ID**와 **ACS URL**이 필요합니다. 이 값은 PlaidCloud 지원팀에 문의하여 받으십시오.</Aside>

1. **ACS URL** 필드에 PlaidCloud에서 제공한 ACS URL을 입력합니다.
2. **Entity ID** 필드에 PlaidCloud에서 제공한 SP Entity ID를 입력합니다.
3. PlaidCloud 지원팀에서 별도로 안내하지 않는 한 **Start URL**은 비워 둡니다.
4. **Name ID format**을 **EMAIL**로 설정합니다.
5. **Name ID**를 **기본 정보 > Primary email**로 설정합니다.
6. **계속**을 클릭합니다.

## 4단계: 속성 매핑 구성

Google Workspace는 SAML 어설션으로 사용자 속성을 PlaidCloud에 전달합니다. 최소한 사용자의 이메일 주소는 매핑해야 합니다. PlaidCloud 구성에서 그룹 기반 보안 역할 할당을 사용하는 경우 그룹 멤버십도 매핑합니다.

### 기본 속성 매핑

**Attribute mapping** 화면에서 다음 속성 매핑을 추가합니다.

| Google 디렉터리 속성 | 앱 속성 |
|---|---|
| Primary email | `email` |
| First name | `firstName` |
| Last name | `lastName` |

**Add mapping**을 클릭하여 각 행을 추가합니다.

### 그룹 멤버십(선택 사항)

PlaidCloud가 Google 그룹 멤버십에 따라 사용자를 보안 그룹에 자동으로 할당하도록 하려면 다음을 수행합니다.

1. **Add mapping**을 클릭합니다.
2. **Google Directory attributes**에서 **Group membership**을 선택하고 해당 Google 그룹을 선택합니다.
3. **App attribute** 이름을 `groups`로 설정합니다(필요한 이름은 PlaidCloud 지원팀에 확인하십시오).

<Aside>PlaidCloud에서 그룹 기반 보안 역할 할당이 올바르게 작동하려면 어떤 그룹 속성 이름과 형식이 필요한지 PlaidCloud 지원팀과 협의하십시오.</Aside>

**Finish**를 클릭합니다.

## 5단계: 사용자에게 앱 사용 설정

기본적으로 새 SAML 앱은 모든 사용자에게 사용 중지되어 있습니다. 적절한 조직 단위 또는 그룹에 대해 사용하도록 설정합니다.

1. 앱 상세 페이지에서 **User access**를 클릭합니다.
2. PlaidCloud SSO 액세스 권한을 부여할 조직 단위 또는 그룹을 선택합니다.
3. 서비스 상태를 **사용**으로 설정합니다.
4. **저장**을 클릭합니다.

## 통합 테스트

PlaidCloud에서 구성이 완료되었다고 확인한 후 다음을 수행합니다.

1. 조직의 PlaidCloud 워크스페이스로 이동합니다(예: `https://my-workspace.plaid.cloud`).
2. Google 로그인 페이지로 리디렉션됩니다.
3. Google Workspace 자격 증명으로 로그인합니다.
4. 인증에 성공하면 PlaidCloud로 다시 리디렉션됩니다.

오류가 발생하면 다음을 확인하십시오.
- SP Entity ID와 ACS URL이 PlaidCloud에서 제공한 값과 정확히 일치하는지 확인합니다.
- 로그인하려는 사용자가 앱이 사용 설정된 조직 단위 또는 그룹에 속해 있는지 확인합니다.
- Name ID format이 **EMAIL**로 설정되어 있고 **Primary email**에 매핑되어 있는지 확인합니다.
- PlaidCloud에 보낸 IdP Metadata URL에 접근할 수 있는지 확인합니다.
