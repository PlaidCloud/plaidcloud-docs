PlaidCloud는 SAML 2.0을 통한 싱글 사인온(SSO)을 지원합니다. 이 가이드에서는 조직의 사용자가 PlaidCloud에 접속할 때 Okta를 통해 인증할 수 있도록 Okta를 SAML ID 공급자로 구성하는 방법을 안내합니다.

<Aside>PlaidCloud 측 구성은 PlaidCloud 팀이 처리합니다. 사용자는 Okta에서 SAML 애플리케이션을 설정하고 **Identity Provider Metadata URL**을 PlaidCloud에 제공해야 합니다. 나머지 구성은 PlaidCloud 지원팀이 완료합니다.</Aside>

## 사전 요구 사항

- **Administrator** 역할(Super Admin 또는 Org Admin)이 있는 Okta 계정
- 설정을 조율하고 구성 값을 주고받기 위한 PlaidCloud 지원팀과의 연락

## 개요

설정 과정에서는 두 당사자가 SAML 메타데이터를 교환합니다.

1. **사용자가 구성합니다.** Okta에서 SAML 애플리케이션을 구성하고, Identity Provider Metadata URL을 PlaidCloud에 제공합니다.
2. **PlaidCloud가 제공합니다.** Okta 애플리케이션 구성을 완료하는 데 필요한 서비스 공급자(SP) Entity ID와 Single Sign-On URL(ACS URL)을 제공합니다.

아래 3단계를 완료하기 전에 PlaidCloud 지원팀과 협의하여 SP 값을 받으십시오.

## 1단계: 새 SAML 애플리케이션 만들기

1. [Okta Admin console](https://your-org.okta.com/admin)에 로그인합니다.
2. 왼쪽 사이드바에서 **Applications** > **Applications**로 이동합니다.
3. **Create App Integration**을 클릭합니다.
4. 로그인 방법으로 **SAML 2.0**을 선택합니다.
5. **다음**을 클릭합니다.
6. 애플리케이션 이름을 입력하고(예: `PlaidCloud SSO`) 필요하면 로고를 업로드합니다.
7. **다음**을 클릭합니다.

## 2단계: SAML 설정 구성

<Aside>이 단계를 완료하려면 PlaidCloud에서 받은 **SP Entity ID**와 **Single Sign-On URL(ACS URL)**이 필요합니다. 이 값은 PlaidCloud 지원팀에 문의하여 받으십시오.</Aside>

1. **Single sign-on URL** 필드에 PlaidCloud에서 제공한 ACS URL을 입력합니다.
2. **Audience URI (SP Entity ID)** 필드에 PlaidCloud에서 제공한 SP Entity ID를 입력합니다.
3. PlaidCloud 지원팀에서 별도로 안내하지 않는 한 **Default RelayState**는 비워 둡니다.
4. **Name ID format**을 **EmailAddress**로 설정합니다.
5. **Application username**을 **이메일**로 설정합니다.
6. **다음**을 클릭합니다.

## 3단계: 속성 문 구성

같은 SAML 설정 화면에서 PlaidCloud가 SAML 어설션으로 사용자 정보를 받을 수 있도록 속성 문을 추가합니다.

### 사용자 속성

**Attribute Statements** 섹션에서 다음을 추가합니다.

| 이름 | 이름 형식 | 값 |
|---|---|---|
| `email` | Unspecified | `user.email` |
| `firstName` | Unspecified | `user.firstName` |
| `lastName` | Unspecified | `user.lastName` |

### 그룹 속성(선택 사항)

PlaidCloud 구성에서 그룹 기반 보안 역할 할당을 사용하는 경우 어설션으로 그룹 멤버십이 전달되도록 그룹 속성 문을 추가합니다.

**Group Attribute Statements** 섹션에서 다음을 추가합니다.

| 이름 | 이름 형식 | 필터 |
|---|---|---|
| `groups` | Unspecified | **Matches regex** — `.*` (또는 포함할 그룹을 제한하는 더 구체적인 패턴) |

<Aside>PlaidCloud에서 그룹 기반 보안 역할 할당이 올바르게 작동하려면 어떤 그룹 속성 이름과 필터가 필요한지 PlaidCloud 지원팀과 협의하십시오.</Aside>

**다음**을 클릭한 다음 **I'm an Okta customer adding an internal app**을 선택하고 **Finish**를 클릭합니다.

## 4단계: Identity Provider Metadata URL 확인 및 전송

애플리케이션을 만든 후 메타데이터 URL을 찾아 PlaidCloud에 보내 통합을 완료합니다.

1. 애플리케이션 상세 페이지에서 **Sign On** 탭을 선택합니다.
2. **SAML 2.0** 섹션까지 스크롤하여 **More details**를 클릭합니다.
3. **Metadata URL**을 복사합니다(형식: `https://your-org.okta.com/app/your-app-id/sso/saml/metadata`).

**이 Metadata URL을 PlaidCloud 지원팀에 보내십시오.** 이 URL은 PlaidCloud가 ID 공급자 측에서 신뢰 관계를 구성하는 데 필요한 Entity Descriptor URL입니다. PlaidCloud가 이 URL을 받으면 팀에서 Keycloak 구성을 완료하고 SSO를 테스트할 준비가 되었을 때 알려 드립니다.

## 5단계: 애플리케이션에 사용자 및 그룹 할당

애플리케이션에 할당된 사용자와 그룹만 이 SSO 구성을 통해 인증할 수 있습니다.

1. 애플리케이션 상세 페이지에서 **Assignments** 탭을 선택합니다.
2. **할당**을 클릭하고 **Assign to People** 또는 **Assign to Groups**를 선택합니다.
3. PlaidCloud SSO 액세스 권한을 부여할 사용자 또는 그룹을 선택하고 **할당**을 클릭합니다.
4. **완료**를 클릭합니다.

## 통합 테스트

PlaidCloud에서 구성이 완료되었다고 확인한 후 다음을 수행합니다.

1. 조직의 PlaidCloud 워크스페이스로 이동합니다(예: `https://my-workspace.plaid.cloud`).
2. Okta 로그인 페이지로 리디렉션됩니다.
3. Okta 자격 증명으로 로그인합니다.
4. 인증에 성공하면 PlaidCloud로 다시 리디렉션됩니다.

오류가 발생하면 다음을 확인하십시오.
- ACS URL과 SP Entity ID가 PlaidCloud에서 제공한 값과 정확히 일치하는지 확인합니다.
- 로그인하려는 사용자가 Okta의 애플리케이션에 할당되어 있는지 확인합니다.
- Name ID format이 **EmailAddress**로 설정되어 있고 애플리케이션 사용자 이름이 **이메일**로 설정되어 있는지 확인합니다.
- PlaidCloud에 보낸 Metadata URL에 접근할 수 있는지 확인합니다.
