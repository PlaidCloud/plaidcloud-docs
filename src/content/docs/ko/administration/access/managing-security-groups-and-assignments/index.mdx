PlaidCloud의 보안 및 액세스 관리는 간단합니다. 멤버가 속한 그룹에 따라 멤버의 액세스가 허용되거나 거부됩니다. 멤버의 보안 연결을 추가하거나 변경하는 작업은 쉽게 사용자 지정할 수 있습니다.

<Aside>각 워크스페이스에서는 보안 그룹을 무제한으로 만들 수 있지만, 보안 관리를 쉽게 하려면 그룹 수를 최소화하는 것이 좋습니다.</Aside>



## 보안 그룹 관리


보안 그룹은 추가, 업데이트 또는 삭제할 수 있습니다.



**보안 그룹을 관리하려면 다음과 같이 합니다.**


1. ID를 엽니다
2. 레일에서 **보안 그룹**을 선택합니다(기존 그룹 목록이 표시됩니다)
3. 그룹을 추가하려면 **New group**을 클릭합니다
4. 그룹의 권한을 편집하려면 가장 왼쪽 아이콘을 클릭합니다

**그룹 멤버를 관리하려면 다음과 같이 합니다.**


1. ID를 엽니다
2. 레일에서 **보안 그룹**을 선택합니다
3. 멤버 아이콘을 클릭합니다
4. 그룹에 속해야 하는 멤버를 선택하고, 속하지 않아야 하는 멤버는 선택을 해제합니다. 필터 상자로 사람을 찾을 수 있습니다. [선택기로 할당하기](#선택기로-할당하기)를 참조하십시오
5. **할당 업데이트**를 클릭합니다

<Aside>아무도 할당하지 않고 저장하면 변경 사항이 없으며 그렇다고 알려 줍니다. 모든 사람에게서 그룹을 제거하려면 멤버십을 비우는 대신 그룹의 권한을 제거하거나 그룹을 삭제하십시오.</Aside>

<Aside>그룹에 [행 액세스](#행-액세스-관리)로 행이 부여된 경우 멤버십 변경은 약 1분 이내에 대시보드에 반영됩니다. 사용자가 추가한 사람은 대시보드에서 그룹의 행을 보게 되고, 제거한 사람은 더 이상 보지 못합니다. 멤버를 비활성화하거나 삭제하는 경우와 그룹을 삭제하는 경우에도 같은 방식으로 적용됩니다.</Aside>

<Aside type="caution">직접 부여할 수 없는 권한은 그룹의 권한 매트릭스를 저장할 때 그대로 유지되며 매트릭스에 표시되지 않습니다. 변경해야 하는 경우 해당 권한을 가진 사람에게 요청하십시오. 매트릭스는 사용자가 제어하는 항목만 편집합니다.</Aside>

<Aside type="caution">그룹이 부여하는 모든 권한을 보유한 경우에만 멤버를 그룹에 추가하거나 멤버의 그룹을 선택할 수 있습니다. 아키텍트로 누군가를 초대하는 경우에도 마찬가지입니다. 워크스페이스 관리자는 이러한 제한을 받지 않습니다.</Aside>

## 선택기로 할당하기

사람, 그룹 또는 다른 항목에 무언가에 대한 액세스를 부여하는 모든 곳에서 기존의 목록 두 개 대신 하나의 체크리스트를 사용합니다. 모든 행에 체크박스가 있으며 선택된 행이 할당된 것입니다. 이를 사용하여 그룹의 멤버, 멤버의 보안 그룹, 계정의 멤버, 그룹, 에이전트, 소유자, 연결의 액세스, 배포 목록의 워크스페이스 멤버, Weave 준비 상태 세트의 워크플로를 설정합니다.

- **필터.** 필터 상자에 입력하여 목록을 좁힙니다. 일치는 부분 일치이며 대소문자를 구분하지 않으므로 `smith`는 이를 포함하는 모든 이름이나 이메일을 찾고 `@example.com`은 해당 도메인의 모든 사람을 찾습니다. 여러 단어를 입력하면 모든 단어와 일치하는 행만 남습니다.
- **이메일 목록 붙여넣기.** 공백, 쉼표, 세미콜론 또는 줄 바꿈으로 구분된 여러 이메일 주소를 붙여넣으면 목록에 정확히 해당 사람들만 표시됩니다. `@example.com`과 같은 전체 도메인을 섞어 넣을 수도 있습니다. 필터 아래의 줄에 붙여넣은 항목 중 몇 개가 일치했는지 표시되고 찾을 수 없는 항목이 나열됩니다. **할당** 뒤에 일치한 수가 붙은 버튼을 사용하면 일치한 모든 사람을 한 번의 클릭으로 선택합니다.
- **모두, 할당됨, 할당되지 않음.** 목록 위의 세 버튼은 전체, 할당된 항목만, 할당되지 않은 항목만을 전환하며 각각 개수가 표시됩니다. 필터와 함께 사용할 수 있습니다.
- **Assign all shown 및 Unassign all shown.** 필터와 보기에 현재 표시된 모든 행을 선택하거나 해제하며 숨겨진 행은 그대로 둡니다. 목록 위의 줄에 전체 중 몇 개 행이 표시되는지 나옵니다.
- **Will add 및 Will remove.** 저장 버튼을 클릭하기 전에는 아무것도 저장되지 않습니다. 선택한 행에는 **Will add** 알약 표시가, 선택을 해제한 행에는 **Will remove**가 표시됩니다. 요약은 예를 들어 `12 assigned · +3 to add · −1 to remove`와 같이 표시됩니다. **Undo changes**는 창을 열었을 때의 상태로 모든 것을 되돌립니다.
- **변경 사항이 있을 때만 저장.** **할당 업데이트**, **멤버 업데이트**, **그룹 업데이트**와 같은 저장 버튼은 변경한 경우에만 사용할 수 있습니다.
- **키보드.** **공백**은 선택한 행을 선택하거나 해제합니다. 필터 상자에서 **Enter**를 눌러도 저장되지 않으므로 검색하는 동안 눌러도 액세스가 변경되는 일은 없습니다.

소유하지 않은 연결처럼 누가 액세스 권한을 가졌는지는 볼 수 있지만 변경할 수 없는 경우 선택기는 읽기 전용입니다. 이미 할당된 사람만 나열되며 변경할 수 있는 체크박스나 버튼은 없습니다.

## 행 액세스 관리

행 액세스는 하나의 열 값을 기준으로 보안 그룹이 볼 수 있는 테이블의 행을 제한합니다. 예를 들어 `region` 열로 액세스를 제한할 수 있으며, `East`와 `Central`이 부여된 그룹은 해당 값을 가진 행으로 제한됩니다. 프로젝트와 열에 대한 모든 작업, 즉 열 선택, 값의 출처 선택, 어느 그룹이 무엇을 볼지 결정하는 작업이 하나의 화면에서 이루어지며 저장하면 즉시 적용됩니다.

행 액세스를 설정하고 변경하려면 프로젝트 아키텍트 또는 테넌트 관리자여야 합니다. 그 외의 사용자가 프로젝트의 **보안** 탭을 열면 행 액세스는 아키텍트 전용이라는 안내를 받으며, 아래의 진입점은 표시되지 않습니다.

### 행 액세스 열기

모든 진입점은 같은 행 액세스 화면을 엽니다.

- **테이블 탐색기의 도구 모음**에는 **행 액세스** 버튼이 있으며, 테이블이 이미 행을 제한하는 경우 배지가 표시됩니다. 제한된 열이 있으면 테이블의 첫 번째 제한된 열에서 열리며, 테이블의 다른 열로 전환할 수 있습니다.
- **열의 패싯 메뉴**에는 해당 열에서 행 액세스를 여는 **이 열로 행 제한…** 항목이 있습니다. 이미 행을 제한하는 열에서는 항목이 **이 열로 제한된 행 — 편집…** 항목으로 표시됩니다.
- **프로젝트의 보안 탭**에는 프로젝트의 제한된 열이 모두 나열되며, 적용되는 테이블, 부여를 가진 그룹, **동기화** 상태가 함께 표시됩니다. 열을 선택하여 편집하거나 **열 제한…** 버튼을 클릭하여 새로 시작합니다. 테이블을 선택한 다음 열을 선택합니다. 이미 행을 제한하는 열에는 잠금 표시가 있습니다.
- **ID → 멤버**의 멤버 **행 액세스** 탭과 **ID → 보안 → 보안 그룹**의 그룹 행 액세스 요약입니다. **행 액세스 열기**(또는 **편집**)는 선택한 열을 열며, **추가**는 해당 행의 프로젝트에서 다른 열을 제한합니다.

열에서 열면 화면은 해당 열에 그대로 머뭅니다. **열 제한…** 또는 **추가**로 열면 열을 선택할 수 있습니다.

### 행 액세스 그리드

열로 테이블을 제한하려면 다음과 같이 합니다.

1. 위의 진입점 중 하나에서 행 액세스를 열고, 열 없이 들어온 경우 열을 선택합니다. 선택기에는 자유 텍스트가 아니라 테이블의 실제 열이 표시됩니다.
2. **값 소스**를 선택합니다. **열**(테이블 열의 고유한 값), **차원**(차원의 노드), **목록**(직접 입력하는 값) 중에서 선택합니다. 값 유형은 열의 데이터 유형을 따릅니다.
3. 각 보안 그룹에 대해 해당 그룹이 볼 수 있는 값을 선택합니다. 그리드에는 프로젝트에 액세스할 수 있는 그룹과 해당 열에 이미 부여를 가진 모든 그룹이 나열됩니다.
4. **Everyone else**를 **sees all rows** 또는 **sees no rows**로 설정합니다. 그리드에서 선택된 항목이 없는 모든 그룹에 적용됩니다.
5. **저장**을 클릭합니다.

저장은 즉시 적용됩니다. PlaidCloud 자체 쿼리는 변경 사항을 즉시 따르고 Superset 대시보드는 약 1분 이내에 따릅니다. 적용하는 별도 단계는 없으며, 부여에 해당 소스에 더 이상 없는 값이 있을 때만 **저장**이 멈추고 확인을 요청합니다(아래 참조). 화면의 동기화 상태는 변경 사항이 어디까지 진행되었는지 보여 줍니다. [대시보드 동기화 유지](#대시보드-동기화-유지)를 참조하십시오.

그리드는 세부 사항도 처리합니다.

- **많은 값.** 값은 정렬됩니다. 열에 표시할 수 있는 것보다 많은 값이 있으면 그리드에 "More values than fit here — type to search."라고 표시되고 필터 상자가 열 전체를 검색하며 그룹이 이미 가진 모든 값은 유지됩니다.
- **소스에 더 이상 없는 값.** 그룹에 부여된 값은 소스에서 사라져도 그리드에 남습니다. 즉, 테이블의 어떤 행에도 해당 값이 없거나, 차원에 해당 멤버가 더 이상 없거나, 목록에 더 이상 없는 경우입니다. 열 머리글에 경고 아이콘이 표시되며 마우스를 올리면 이유가 나옵니다. **모두 선택**, **선택 반전**, **붙여넣기**는 이러한 값을 각 그룹이 가진 그대로 둡니다. 선택을 해제하지 않는 한 부여에서 아무것도 제거되지 않습니다. 그룹이 아직 그러한 값을 가진 상태에서 **저장**을 클릭하면 행 액세스가 **Values No Longer in the Source**에 그룹과 값을 명시하고 묻습니다. **Keep and Save**는 그대로 저장하고, **Remove and Save**는 먼저 모든 그룹의 부여에서 제거하며, 질문을 닫으면 아무것도 저장되지 않습니다. 제거하면 그룹에 선택된 항목이 하나도 남지 않는 경우, 질문에서 **Everyone else** 설정에 따라 해당 그룹이 모든 행을 보게 되는지 아니면 하나도 보지 못하게 되는지 알려 줍니다. 아직 저장하지 않은 선택은 해당 값과 함께 사라집니다. 열에 표시할 수 있는 것보다 많은 값이 있거나 테이블이 아직 빌드되지 않은 경우 행 액세스는 테이블에 없는 값을 알 수 없으므로 부여된 모든 값을 표시 없이 유지합니다.
- **빈 값.** **빈 값 - 부여된 모든 그룹에 표시** 체크박스 하나가 열에 값이 없는 행을 결정합니다. 선택하면 열에 부여가 하나라도 있는 모든 그룹이 해당 행을 봅니다.
- **아직 빌드되지 않은 테이블**에는 빈 목록 대신 **먼저 이 테이블을 빌드하십시오(테이블을 만드는 워크플로 실행)** 가 표시됩니다.
- **저장은 화면의 값을 기다립니다.** 값 소스, 차원, 테이블을 전환하거나 템플릿을 적용한 후 값을 불러오는 동안 **저장**은 "Save is available once this source's values load." 툴팁과 함께 비활성화됩니다. 불러오기에 실패하면 그리드가 그렇다고 알리고 소스를 다시 선택하라고 요청하며, 불러오기가 성공하기 전에는 아무것도 저장되지 않습니다.

### 하나의 열 이름, 모든 테이블

제한은 단일 테이블이 아니라 프로젝트의 열 *이름*에 속합니다. `region`이 행을 제한하면 프로젝트에서 `region`이라는 이름의 열이 있는 모든 테이블이 PlaidCloud 자체 쿼리와 대시보드 모두에서 이를 기준으로 필터링됩니다. 그리드의 **Applies to** 목록에 해당 테이블이 표시됩니다. 열 이름이 결정하므로 읽기 전용이며, 나중에 같은 열이 있는 테이블을 추가하면 게시되는 즉시 적용 대상이 됩니다.

프로젝트의 어떤 테이블에도 해당 이름의 열이 없으면 창에 **Applies to 0 tables**가 표시되는 것에 더해, 테이블이 생기기 전까지 제한이 어떤 대시보드도 필터링하지 않는다는 경고가 표시됩니다. 테이블에 열을 추가하거나 열 이름을 수정하면 경고가 사라집니다.

<Aside type="caution">
**열 이름은 대소문자와 공백을 포함하여 정확히 일치해야 합니다.** `Region`과 `region`은 다른 이름이며, `region`과 뒤에 공백이 있는 `region `도 마찬가지입니다. 선택기에는 실제 열 이름만 표시되므로 다른 곳에서 열 이름이 바뀌었을 때 주로 문제가 되며, 이 경우 행 액세스는 아무것도 제한하지 않은 채 두는 대신 경고하고 찾은 가장 가까운 열의 이름을 알려 줍니다.
</Aside>

<Aside type="caution">
**행을 제한하는 테이블을 게시하면 같은 단계에서 대시보드 필터가 설정됩니다.** 대시보드는 게시된 보고 뷰를 통해 테이블을 읽으므로, 제한된 열이 있는 테이블을 게시하거나 다시 게시할 때 PlaidCloud는 게시가 완료되기 전에 해당 테이블의 대시보드 필터를 등록합니다. 등록할 수 없으면 게시가 거부되고 해당 시도에서 만들어진 것은 롤백되므로 제한된 테이블이 필터링되지 않은 채 대시보드에 남는 일은 없습니다. 뷰의 쿼리가 제한된 열의 이름을 바꾸거나 파생할 수 있으므로 행을 제한하는 프로젝트에서는 *뷰*를 게시할 수 없습니다. [테이블 게시](/ko/guides/data/publish/)를 참조하십시오.
</Aside>

### 제한 중지

그리드의 **제한 중지**는 인라인 확인 후 제한을 제거합니다. "Stop restricting rows by ‘region’? Every group's grant on it is removed and everyone sees its rows." 그러면 행 액세스가 "Rows in ‘region’ are no longer restricted."라고 확인합니다. 차트가 아직 사용 중이 아니라면 열의 Superset 데이터 세트도 함께 제거되며, 사용 중이면 행 액세스가 데이터 세트가 유지된다는 점과 몇 개의 차트가 사용하는지 알려 줍니다.

열이 행을 제한하는 동안에는 이름을 바꾸거나 삭제할 수 없습니다. 아키텍트에게는 먼저 행 액세스에서 제한을 중지하라고 안내하며, 그 외의 사용자에게는 프로젝트 아키텍트에게 요청하라고 안내합니다.

### 행을 제한하는 프로젝트를 변경할 수 있는 사람

프로젝트의 워크플로, 단계, 사용자 정의 함수는 모든 행을 읽는 프로젝트 자체의 서비스 ID로 실행됩니다. 이를 변경할 수 있는 사람은 부여받지 않은 행을 자신이 읽을 수 있는 테이블로 복사하는 단계를 만들 수 있으므로, 프로젝트에서 행을 제한하면 프로젝트가 수행하는 작업을 변경할 수 있는 사람도 제한됩니다. 프로젝트에서 열을 하나 이상 제한하면 다음과 같이 적용됩니다.

- **자동화는 아키텍트 전용입니다.** 프로젝트 아키텍트와 테넌트 관리자만 워크플로, 단계, 사용자 정의 함수, 일정, 워크플로 및 프로젝트 변수, 알림 이메일 템플릿을 변경할 수 있으며, 같은 이유로 워크플로 번들 가져오기, Alteryx 워크플로 변환, 프로젝트로의 가져오기, 복사 또는 복원, 프로젝트의 연결 환경, 기본 문서 계정 또는 ERP 전기 모드 변경도 할 수 있습니다. 그 외의 사용자는 프로젝트의 워크플로를 계속 실행할 수 있으며 **시작**, **중지**, **재개**, **선택한 단계 실행**을 사용할 수 있습니다. 단계 편집기, 워크플로의 작성 컨트롤, UDF 편집기, 일정 양식은 이들에게 읽기 전용으로 열리며, 요청할 아키텍트를 알려 주는 배너가 표시됩니다. "This project restricts rows, so only its Architects can change workflows, steps, UDFs, schedules, variables and notify templates. You can still run them."
- **제한된 열이 읽는 차원은 아키텍트 전용입니다.** 누가 어느 행을 보는지 결정하는 차원, 즉 제한된 열의 값 소스는 프로젝트 아키텍트 또는 테넌트 관리자와 프로젝트 자체의 워크플로만 변경할 수 있습니다. 여기에는 노드의 추가, 이동, 이름 바꾸기, 복사, 지우기, 로드, 복원과 차원 자체가 포함됩니다. 그 외의 사용자는 "This dimension decides who sees which rows of ‘region’, so only a project Architect can change it."라는 안내를 받습니다. 어떤 제한도 읽지 않는 차원은 영향을 받지 않습니다.
- **부여 소스 테이블은 아키텍트 전용입니다.** 열의 [부여 소스](#부여를-소스-테이블에-바인딩)로 바인딩된 테이블은 데이터 편집기, 가져오기, 커넥터 로드 또는 API 어느 쪽을 통하든 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트의 워크플로만 행을 변경하거나 삭제할 수 있습니다.
- **프로젝트 복사는 아키텍트 전용이며**, 복사본에는 "This copy is not row-restricted."라고 표시됩니다. 새 프로젝트는 제한을 설정하기 전까지 제한이 없습니다.
- **이전 버전 복원은 다른 변경과 같은 변경입니다.** 프로젝트 자체의 설정이나 위에 나열된 차원을 복원하려면 프로젝트 아키텍트여야 합니다. 복원은 항상 버전이 속한 항목에 적용되므로 이를 우회하기 위해 다른 프로젝트를 가리키도록 할 수 없습니다. [버전 기록](/ko/guides/projects/managing-projects/#버전-기록)을 참조하십시오.
- **제한된 테이블의 데이터 편집**에는 [행 액세스와 데이터 편집기](#행-액세스와-데이터-편집기)에 설명된 대로 아키텍트가 필요합니다.
- **제한된 테이블에 대한 DataFrame 쓰기, 레코드 저장 및 지우기**는 [제한된 테이블에 데이터 로드](#제한된-테이블에-데이터-로드)에 설명된 대로 모든 행을 볼 수 있지 않은 한 사용자 본인의 행만 변경합니다.
- **제한된 테이블의 가져오기, 복사, 브랜치 전환, 복원, 삭제는** [제한된 테이블에 데이터 로드](#제한된-테이블에-데이터-로드)에 설명된 대로 볼 수 없는 행이 있는 동안 거부됩니다.

프로젝트에서 첫 번째 열을 제한하기 전에 행 액세스가 영향을 받는 사람을 알려 줍니다. "Restricting rows here means only Architects can change this project's workflows, steps, UDFs, schedules and notify templates. N members can change them today; they will still be able to run them."

실행은 예약된 실행을 포함하여 프로젝트의 서비스 ID로 실행되므로 이전과 똑같이 계속 작동합니다. 실행이 생성하는 결과는 아키텍트가 설계한 대로 따릅니다. 제한된 열이 없는 출력 테이블, 내보내기 파일, 알림 이메일, 로그 줄은 읽는 사람에 따라 필터링되지 않습니다.

**실행을 시작할 때 지정하는 값.** 워크플로를 실행할 수 있는 사람은 누구나 변수에 대해 직접 지정한 값으로 시작할 수 있습니다. [앱 러너](/ko/guides/workflows/use-converted-alteryx-apps/#app-runner-프런트엔드)는 양식의 응답으로 이를 수행하며, API와 AI 도구도 가능합니다. 이러한 값은 해당 실행에만 적용되며 워크플로에 저장되지 않고 다른 실행, 내보내기 또는 읽는 사람에게는 보이지 않습니다. 실행이 서비스 ID로 이루어지므로 이러한 값은 해당 실행이 읽고 쓰는 대상을 바꿀 수 있습니다. 따라서 워크플로를 실행할 권한은 신뢰하는 사람에게만 부여하십시오.

**행을 제한하지 않는 프로젝트.** 이 규칙은 프로젝트에서 열을 제한한 후에만 적용됩니다. 어떤 열도 제한하지 않는 프로젝트에서는 프로젝트의 자동화를 변경할 수 있는 사람이 프로젝트의 서비스 ID로 실행되면서 프로젝트의 액세스를 변경하여 자신을 아키텍트 중 한 명으로 만드는 단계나 사용자 정의 함수를 작성할 수 있습니다. 이는 설계된 동작이며, 이러한 프로젝트는 행 격리를 약속하지 않습니다. 해당 프로젝트에서는 작성 권한을 아키텍트로 신뢰할 만한 사람에게만 부여하거나 열을 제한하십시오.

### 대시보드 동기화 유지

행 액세스는 그리드와 프로젝트 **보안** 탭의 **동기화** 열에서 변경 사항이 대시보드로 가는 도중 어디에 있는지 보여 줍니다.

| 상태 | 의미 |
|---|---|
| **대기 중** | 변경 사항이 저장되어 대시보드로 가는 중입니다. 보통 약 1분 이내에 해소됩니다. |
| **재시도 중** | 전송이 실패하여 다시 시도하고 있습니다. 실패 사유가 상태 옆에 표시되며, **다시 시도**로 즉시 다시 전송할 수 있습니다. |
| **아직 적용되지 않음** | 프로젝트의 제한이 아직 대시보드로 전송되지 않았습니다. |
| **적용됨** | 제한을 대시보드로 전송하려는 마지막 시도가 성공했습니다. |
| **대시보드와 동기화됨** | 행 액세스가 대시보드가 적용하는 내용과 자신이 기록할 내용을 비교했으며 일치합니다. |
| **대시보드와 다름** | 대시보드가 행 액세스가 기록할 내용을 적용하지 않습니다. Superset에서 규칙이 변경되거나 삭제되었거나 테이블의 게시된 뷰를 확인할 수 없습니다. |
| **오류** | 제한 전송에 실패했습니다. 사유가 상태 옆에 표시됩니다. |

변경 사항이 **적용됨**에 도달하면 그리드가 대시보드와 비교하여 **대시보드와 동기화됨** 또는 **대시보드와 다름**으로 넘어갑니다. **대시보드와 다름**과 **오류**는 모두 프로젝트의 제한을 다시 전송하는 **다시 시도**를 제공합니다. 상태를 전혀 읽을 수 없으면 그리드에 "Couldn't check sync status."라고 표시됩니다.

테이블 하나가 원인인 **오류**는 테이블을 명시하고 해야 할 일을 알려 줍니다. 예를 들어 제한된 열 없이 게시된 테이블("Republish or unpublish it.")이나 게시되지 않은 제한된 열이 있는 테이블이며, 게시되기 전에는 대시보드가 필터링할 수 없습니다. 테이블을 게시하거나 대신 게시된 테이블의 열을 제한할 때까지 상태는 **오류**로 유지되며 게시되지 않은 테이블의 이름이 표시됩니다. 이런 테이블이 프로젝트의 나머지를 막지는 않으며 다른 모든 테이블은 계속 동기화됩니다.

대시보드는 PlaidCloud 자체 쿼리와 같은 부여를 따릅니다.

- **해당 열이 있는 게시된 모든 테이블이 필터링되며**, 제한을 설정할 때 보고 있던 테이블만 필터링되는 것이 아닙니다.
- **일부 값만 부여된 그룹은 다른 모든 사람이 모든 행을 보더라도 필터링되며**, 대시보드 데이터 세트가 있는 모든 테이블에 적용됩니다.
- **프로젝트 아키텍트는 모든 행을 봅니다.** 테이블 탐색기와 PlaidCloud의 나머지 부분에서처럼 대시보드에서도 마찬가지입니다. 이는 프로젝트의 아키텍트 그룹과 개별 멤버와 공유된 프로젝트의 아키텍트에게 적용됩니다. 아키텍트 액세스를 제거하면 멤버의 역할을 변경하거나, 멤버 또는 해당 그룹을 프로젝트에서 제거하거나, 프로젝트의 액세스 유형을 변경하거나, 이전 프로젝트 버전을 복원하거나, 그룹을 삭제하는 어느 경우든 대시보드에서 즉시 적용됩니다.
- **보안 그룹 멤버십 변경은 대시보드에 자동으로 반영됩니다.** PlaidCloud에서 누군가를 그룹에 추가하거나 제거하는 경우, 멤버를 비활성화하거나 삭제하는 경우, 그룹을 삭제하는 경우, 기본 보안 그룹에 가입하는 새 멤버를 추가하는 경우 해당 그룹에 값을 부여하는 모든 프로젝트에서 대시보드에 표시되는 내용이 약 1분 이내에 업데이트되며 누구도 행 액세스를 다시 열 필요가 없습니다. Keycloak에서 직접 하거나 싱글 사인온이 로그인 시 누군가를 그룹에 넣는 것과 같이 PlaidCloud 외부에서 이루어진 멤버십 변경은 저장하거나 다시 시도할 것 없이 약 15분 이내에 대시보드에 반영됩니다.

### 차원 부여

값 소스로 **차원**을 사용하면 노드를 선택하여 그 아래의 모든 것을 부여합니다. 부여는 차원을 따릅니다. 선택한 노드 아래에 추가된 멤버는 차원이 저장된 후 다음 동기화에서 해당 그룹에 부여되며, 그 아래에서 이동하거나 제거된 멤버는 더 이상 부여되지 않으므로 아무도 그리드를 다시 열 필요가 없습니다. 다시 열면 선택했던 노드가 선택된 상태로 표시됩니다.

노드를 통하지 않고 멤버만 따로 선택한 경우, 차원에서 제거되어도 계속 부여된 상태로 남으며 그리드가 이를 소스에 더 이상 없는 값으로 표시합니다.

선택된 노드 아래의 항목 중 하나라도 선택을 해제하면 노드도 선택 해제되며 그룹에는 여전히 선택된 멤버만 남습니다. 해당 멤버를 다시 선택해도 노드가 다시 선택되지는 않으므로, 이를 위해서는 노드 자체의 체크박스를 클릭하십시오. **붙여넣기**, **모두 선택**, **선택 반전**은 멤버를 선택하며 노드는 선택하지 않습니다.

이름을 행 액세스 값으로 사용할 수 없는 차원 멤버는 저장할 때 해당 멤버를 명시하며 거부됩니다. 나중에 그런 멤버가 나타나면 해당 행은 누구에게도 부여되지 않으며 동기화 상태에 해당 멤버가 표시됩니다. "Dimension ‘…’ member ‘…’ cannot be used as a row access value, so its rows are not granted. Rename it in the dimension."

### 부여를 소스 테이블에 바인딩

값을 직접 선택하는 대신 제한된 열을 이미 답을 가지고 있는 소스 테이블, 즉 그룹마다 한 행과 해당 그룹이 볼 수 있는 값을 가진 테이블에 연결할 수 있습니다. 먼저 그리드에서 열을 제한한 다음, 열, 소스 테이블, 소스 테이블의 그룹 열과 값 열을 지정하는 [**행 액세스 설정**](/ko/reference/workflow-steps/tables/table-set-row-access/) 워크플로 단계를 추가합니다. 단계를 처음 실행하면 열이 해당 테이블에 바인딩됩니다. 열에 직접 설정한 부여는 지워지고 부여가 테이블의 행에서 설정됩니다.

바인딩되면 열은 **소스 소유**가 됩니다. 행 액세스 그리드에 열이 잠긴 상태로 소스 테이블 이름이 있는 배지와 함께 표시되며, **바인딩 제거**를 클릭하기 전에는 부여를 직접 편집할 수 없습니다.

이후 단계를 실행할 때마다 소스 테이블을 다시 읽고 부여를 다시 적용합니다. 해당 테이블을 로드하거나 새로 고치는 워크플로 뒤에 실행되도록 일정을 설정하면, 소스 데이터에서 추가, 제거 또는 재할당된 그룹이 다음 실행 때 행 액세스에 반영되며 아무도 그리드를 직접 편집할 필요가 없습니다.

소스 테이블이 누가 무엇을 보는지 결정하므로 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트 자체의 워크플로만 해당 행을 변경하거나 삭제할 수 있습니다. 그 외의 사용자는 "This table supplies the row access grants for ‘region’, so only a project Architect can change its rows or delete it."라는 안내를 받습니다.

### 제한 템플릿

같은 값 소스, 값 유형, 빈 값 설정과 같이 재사용하려는 제한 형태를 만들었다면 열마다 다시 만드는 대신 한 번 저장하고 필요한 곳마다 적용하십시오.

- 열려 있는 행 액세스 화면의 **템플릿으로 저장…** 항목은 현재 열의 형태를 이름이 있는 테넌트 수준 템플릿으로 저장합니다. 형태만 저장되며 부여는 함께 저장되지 않습니다.
- 다른 프로젝트의 열에서 **템플릿 적용**을 사용하면 해당 열이 템플릿의 형태로 시작되며, 모든 그룹의 부여는 비어 있어 직접 채울 수 있습니다.

모든 프로젝트 아키텍트가 템플릿을 저장하고 적용할 수 있습니다. 템플릿은 테넌트 전체에서 공유되므로 이름 바꾸기(**이름 바꾸기…**)와 삭제(**삭제**)에는 테넌트 관리자가 필요합니다. 템플릿을 삭제해도 템플릿이 적용된 열은 제한된 상태로 그대로 유지됩니다.

<Aside type="note">
템플릿은 링크가 아니라 사본입니다. 나중에 템플릿을 편집해도 이미 템플릿을 적용한 열은 변경되지 않으며, 열을 이후 개정판에 맞게 최신 상태로 만들려면 템플릿을 다시 적용하십시오.
</Aside>

### SSO 그룹 특성에서 부여

열은 PlaidCloud 대신 ID 공급자에서 부여를 가져올 수도 있습니다. 프로젝트 아키텍트가 행 액세스에서 **Accept row-access grants from SSO group attributes**를 사용 설정하여 열에 이를 적용합니다.

사용 설정하면 보안 그룹의 Keycloak 특성 `row_access.<column>`이 해당 열을 통해 그룹이 볼 수 있는 값을 설정합니다. Keycloak의 그룹에 특성을 설정하면 PlaidCloud가 이미 프로젝트에 액세스할 수 있는 모든 그룹에 대해 이를 자동으로 가져옵니다. 행 액세스 자체에서 구성할 것은 더 없으며, 부여는 PlaidCloud 자체 쿼리와 Superset 대시보드 모두에서 동기화된 상태로 유지됩니다.

<Aside type="caution">
이는 이미 프로젝트에 접근할 수 있는 그룹에만 값을 부여합니다. 프로젝트 액세스가 없는 그룹에 `row_access.region`을 추가해도 그룹에 프로젝트 액세스도 부여되기 전에는 아무것도 부여되지 않습니다.
</Aside>

### 저장하기 전에 미리 보기

행 액세스는 변경 사항을 확정하기 전에 그것이 무엇을 의미하는지 보여 줍니다.

- **다음 사용자로 미리 보기** 바닥글에는 그룹이 전체 중 테이블의 몇 개 행을 보게 되는지와 행의 샘플이 표시되며, 그리드에서 아무 그룹이나 선택하여 미리 볼 수 있습니다. 미리 보기는 저장한 후 새로 고쳐집니다.
- 저장하기 전에 행 액세스는 다시 살펴볼 만한 모든 항목을 경고합니다. 선택된 항목이 없는 그룹과 **Everyone else** 설정에 따라 그것이 모든 행을 보는 것인지 하나도 보지 못하는 것인지, 어떤 그룹의 부여에도 포함되지 않는 프로젝트 액세스 권한이 있는 멤버, 해당 열의 값이 비어 있고(`NULL`) 어떤 그룹에도 부여되지 않은 행입니다.

### 제한된 멤버가 보는 내용

제한된 멤버가 이름으로 테이블을 읽는 모든 곳에서 자신의 행만 보입니다. 테이블 탐색기의 그리드, 열 패싯 및 다운로드, 테이블 다운로드 대화 상자, 보는 사람 권한으로 읽는 앱과 도구, 대시보드가 해당됩니다. 테이블 탐색기는 보고 있는 그리드가 사용자의 부여로 필터링된 경우 도구 모음에 **액세스 권한에 따라 행이 제한됨**을 표시하며, 필터링될 다운로드를 시작하면 "Rows limited by your access."라고 표시됩니다. 모든 행을 읽는 아키텍트에게는 두 알림 모두 표시되지 않습니다.

### 행 액세스와 직접 작성하는 쿼리

행 액세스가 행을 제한하는 경우 프로젝트의 쿼리 화면에서 직접 SQL 쿼리를 실행하면 부여가 허용하는 행만 정확히 얻습니다. 결과를 CSV, Excel 또는 JSON으로 내보낼 수 있으며, 내보내기에는 해당 행만 포함되고 **액세스 권한에 따라 행이 제한됨** 알림이 함께 표시됩니다. 아키텍트는 이미 제한된 모든 열의 모든 값을 스스로 부여할 수 있으므로 프로젝트 아키텍트는 모든 행을 읽으며 알림이 표시되지 않습니다.

퍼센트 기호(`%`)를 포함하는 부여 값은 쿼리 화면에서 부여된 행을 반환하며, 해당 쿼리를 CSV로 다운로드하는 것도 작동합니다.

프로젝트 아키텍트가 아닌 멤버에게는 다음이 여전히 거부됩니다.

- Snowflake 또는 Databricks 프로젝트 웨어하우스에서 자유 형식 SQL을 직접 실행하는 것.
- Postgres 계열 웨어하우스에서 직접 작성한 SQL의 결과를 내보내는 것.
- 직접 작성한 SQL의 결과를 다른 데이터베이스로 내보내는 것.
- 팬아웃 단계의 "Test row 1" 미리 보기에 행 조건을 입력하는 것.
- 관리되는 테이블을 이전 스냅샷 시점으로 읽는 것(타임 트래블).

거부된 사람에게는 어느 프로젝트였는지 알려 주고 이름으로 읽는 방식을 안내합니다. 이름으로 테이블을 읽는 것은 앱과 도구가 데이터를 읽는 일반적인 방식이며 부여를 적용하여 보는 사람이 볼 자격이 있는 행을 반환합니다. 단일 테이블에 대한 일반 쿼리로 작성된 열 패싯도 이름으로 읽으므로 거부되지 않고 멤버 자신의 값을 반환합니다. 프로젝트 아키텍트는 이 모든 작업을 작성된 그대로 실행할 수 있습니다.

행 액세스는 관리 대상 열에서 뷰를 필터링하므로 뷰는 해당 열을 원래 이름으로 유지해야 합니다. 관리 대상 열을 삭제하거나 이름을 바꾸는 뷰는 필터링되지 않습니다.

스프레드시트 가져오기는 그 자체로는 직접 작성한 쿼리가 아닙니다. 일반 파일 가져오기는 제한된 데이터를 전혀 읽지 않으며 업로드한 파일에서 프로젝트 자체의 새 테이블만 만들기 때문에 행 액세스의 영향을 받지 않습니다. 예외는 데이터 프로젝션을 호출자가 제공하는 가져오기, 즉 열별 식이나 동적 Excel 매핑입니다. 대화형 가져오기 화면에서는 이러한 가져오기가 위의 자유 형식 SQL 화면과 같은 방식으로 거부되며 프로젝트 아키텍트가 필요합니다. 호출자가 제공한 프로젝션이 다른 테이블을 읽을 수 있기 때문입니다. 워크플로에서 실행하는 가져오기는 프로젝트 자체의 서비스 ID로 실행되므로 어느 쪽이든 영향을 받지 않습니다.

<Aside type="caution">
프로젝트에서 첫 번째 열을 제한하면 이를 사용하는 모든 사람에게 이 동작이 변경됩니다. 해당 프로젝트의 Panel 앱, 노트북 또는 통합이 Snowflake나 Databricks 웨어하우스에서 자체 SQL을 구성하거나 Postgres 계열 웨어하우스에서 자체 쿼리 결과를 내보내는 경우, 제한하기 전에 이름으로 테이블을 읽도록 전환하십시오. 그렇지 않으면 아키텍트가 아닌 모든 사람에게 작동하지 않게 됩니다.
</Aside>

### 행 액세스와 데이터 편집기

데이터 편집기는 테이블을 직접 읽고 쓰므로 행 액세스는 양쪽 모두에 적용됩니다.

데이터 편집기에서 제한된 테이블을 열면 보안 그룹에 부여된 행만 표시됩니다. 이는 대시보드로 이어지는 것과 같은 필터이며 제한된 열이 그리드에 표시되는 열이 아니어도 적용됩니다.

편집 내용을 저장하려면 프로젝트에 대한 **Architect**가 필요합니다. 저장은 테이블의 행을 읽지 않고 통째로 교체하며 행 단위로 필터링되지 않으므로, 제한된 테이블의 데이터 편집은 읽기가 아니라 작성 작업으로 취급됩니다. 아키텍트가 아니면 필요하다는 안내를 받습니다. 제한된 열이 없는 테이블은 이전과 같이 편집되며, 행을 제한하지 않는 프로젝트도 마찬가지입니다.

### 제한된 테이블에 데이터 로드

행 액세스가 볼 수 있는 행을 제한하는 경우 Python 클라이언트(`PlaidConnection`)로 DataFrame을 제한된 테이블에 쓰거나 지우는 작업, 또는 REST API로 레코드를 저장하거나 지우는 작업은 사용자 본인의 행에서만 작동합니다. 테이블의 데이터를 교체하면 볼 수 있는 행만 교체되고, 지우면 해당 행만 지워지며, 추가하면 행이 추가됩니다. 다른 모든 행은 그대로 유지됩니다.

액세스 범위를 벗어난 행이 포함된 로드는 아무것도 변경되기 전에 거부되며, 오류는 액세스 범위를 벗어난 각 값과 해당 값을 가진 행 수를 명시합니다. 제한된 열을 생략한 행은 해당 열이 비어 있는 것으로 검사되므로, 액세스에 빈 행이 포함되지 않으면 거부됩니다. 열의 유형이 변경되는 방식으로 데이터를 교체하는 것도 거부되며, 이러한 변경은 프로젝트 아키텍트에게 요청하십시오.

프로젝트 아키텍트, 부여가 모든 행을 포함하는 멤버, 프로젝트의 서비스 ID로 실행되는 워크플로 실행은 테이블 전체에 씁니다. 제한된 열이 없는 테이블은 영향을 받지 않습니다.

제한된 테이블 전체를 교체하거나 제거하는 그 밖의 모든 작업은 볼 수 없는 행이 테이블에 있는 동안 거부되며 아무것도 변경되지 않습니다. 파일을 테이블로 가져오기, 다른 프로젝트에서 테이블 복사, 브랜치 전환 또는 병합, 아카이브에서 복원하거나 프로젝트의 보관된 스냅샷 복원의 일부로 복원, 삭제, 삭제 후 되살리기, 테이블을 다시 채우기 전에 비우는 모든 작업이 해당됩니다. 제한된 열이 비어 있는 행은 액세스에 빈 행이 포함되지 않는 한 볼 수 없는 행으로 간주됩니다. 본인의 행만 담아 만든 테이블처럼 모든 행을 볼 수 있는 테이블은 교체하거나 삭제할 수 있습니다.

사람이 어떤 테이블에든 수행하는 이러한 각 쓰기는 거부된 것을 포함하여 보안 로그에 기록됩니다. 워크플로 실행은 거기에 기록되지 않습니다.

### 행 수와 테이블 크기

테이블의 행 수와 저장소 크기는 볼 수 있는 행이 아니라 테이블 전체를 나타내므로, 제한된 독자에게 부여 범위를 벗어난 행이 몇 개 있는지 알려 주게 됩니다. 행을 제한하는 프로젝트에서는 읽기가 필터링되는 모든 사용자에게 프로젝트의 어떤 테이블에 대해서도 행 수나 크기가 표시되지 않습니다. 테이블 목록, 검색, 테이블 세부 정보, 스냅샷과 MCP로 연결된 AI 어시스턴트 및 AI 도구에서 모두 그렇습니다. 여기에는 제한된 열이 없는 테이블을 포함하여 프로젝트의 모든 테이블이 포함됩니다. 홈, 프로젝트 목록 및 검색, 프로젝트 세부 정보의 전체 행 수와 크기와 같은 프로젝트 자체의 합계도 이들에게 숨겨집니다.

워크플로 실행 기록에도 같은 규칙이 적용됩니다. 각 실행과 단계가 기록한 읽은 행과 쓴 행도 테이블 전체를 나타내므로, 같은 독자에게는 워크플로와 단계의 실행 기록 및 MCP로 연결된 AI 어시스턴트와 AI 도구에서 해당 수치가 비어 있습니다. 이들에 대해서는 [Weave](/ko/guides/ai-assistant/weave-findings/)가 이전 실행과 다른 행 수나 빈 값을 단계에서 검사하지 않습니다. 결과 항목 자체가 테이블 전체의 개수가 바뀌었음을 알려 주기 때문입니다.

프로젝트 아키텍트는 이전과 같이 수치를 보며, 행을 제한하지 않는 프로젝트의 모든 사용자도 마찬가지입니다.

### 멤버가 볼 수 있는 내용 확인

그룹에 부여된 내용이 아니라 특정 사람이 볼 수 있는 내용을 확인하려면 **ID → 멤버**를 열고 멤버를 선택한 다음 해당 멤버의 **행 액세스** 탭을 엽니다. **유효 액세스** 열에는 제한된 모든 프로젝트와 열에 대해 SSO 그룹 특성에서 온 부여와 그룹의 부여에 포함된 경우의 빈(`NULL`) 행을 포함하여 해당 멤버가 모든 그룹을 합쳐서 보는 값이 나열됩니다. 아키텍트는 모든 행을 읽으므로 프로젝트 아키텍트는 **모든 행 볼 수 있음(Architect)** 으로 표시됩니다. PlaidCloud 자체 쿼리가 적용하는 것과 같은 답이므로 지원에 유용하며, 누군가 문제를 보고하기 전에 변경이 의도한 대로 작동했는지 확인하는 데 유용합니다.

### 더 명확한 오류

행 액세스가 작업을 차단하는 경우, 즉 제한된 프로젝트에서 직접 작성한 쿼리, 아키텍트 없는 편집, 자동화, 차원 또는 부여 소스 테이블의 변경, 위에 설명된 그 밖의 경우에는 일반적인 실패 대신 무엇이 제한되어 있는지와 요청할 아키텍트와 같은 다음 단계를 메시지가 알려 줍니다.

### 행 액세스는 감사됩니다

열을 제한하거나 제한을 해제하는 것, 그룹의 부여를 편집하는 것은 모두 해당 프로젝트의 [프로젝트 로그](/ko/get-started/tutorials/collaborate-versions-and-sharing/#프로젝트-로그-읽기)에 누가 언제 변경했는지 항목을 기록합니다. 프로젝트에서 **Analyze → Projects → Log**를 열어 확인하십시오. 이 추적을 얻기 위해 행 액세스에서 켜야 할 것은 없으며, 프로젝트에 대해 추적되는 다른 모든 변경과 같은 방식으로 기록됩니다.

## 기본 보안 그룹 설정


새 멤버를 추가하는 데 필요한 시간을 줄이려면 기본 보안 그룹 세트를 지정하십시오. 이렇게 하면 각 사람을 수동으로 할당하지 않고도 새 멤버에게 기준이 되는 보안 그룹 세트를 제공합니다. 새 보안 그룹을 추가할 때 보안 그룹 창 아래쪽의 “신규 사용자에게 기본으로 할당” 확인란을 선택하면 이 설정을 사용할 수 있습니다.



## 보안 감사 수행


보안 감사 기능을 사용하면 모든 멤버와 그룹에 걸친 그룹 멤버십을 볼 수 있습니다.



**보안 감사를 수행하려면 다음과 같이 합니다.**


1. ID를 엽니다
2. 레일의 **보안** 아래에서 **Group audit**를 선택합니다

PlaidCloud의 모든 테이블은 CSV 파일 형식으로 내보낼 수 있으므로, 그룹 멤버 연결은 이력 확인 목적이든 단지 오프라인에서 재미 삼아 보려는 목적이든 PlaidCloud 밖에서 검토할 수 있습니다.



**“Security Group Audit” 양식에서 내보내려면 다음과 같이 합니다.**


1. ID를 엽니다
2. 레일의 **보안** 아래에서 **Group audit**를 선택합니다
3. 표에서 “사용자 이름” 맨 오른쪽의 작은 아이콘을 클릭합니다
4. 원하는 방식에 따라 “CSV 내보내기” 또는 “Export XLSX”를 클릭합니다

## 사용 가능한 권한 설정 보기


워크스페이스에서 사용하는 각 애플리케이션에는 사용 가능한 특정 권한이 있습니다. 보안 그룹 권한은 이러한 애플리케이션 권한을 기반으로 합니다.


각 애플리케이션에서 사용 가능한 전체 권한 목록은 Security Bin에서 볼 수 있습니다.



**Security Bin에 액세스하려면 다음과 같이 합니다.**


1. ID를 엽니다
2. “보안”을 선택합니다
3. 드롭다운 메뉴에서 “Security Bins”를 클릭합니다

각 애플리케이션의 자세한 보안 설정을 보려면 맨 왼쪽의 태그 아이콘을 선택합니다.



이 사용 가능한 보안 설정 정보는 정보 제공용입니다. 권한 관리에 대한 자세한 내용은 위의 보안 그룹 관리 섹션을 참조하십시오.
