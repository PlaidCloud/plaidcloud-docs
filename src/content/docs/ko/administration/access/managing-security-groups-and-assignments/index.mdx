PlaidCloud의 보안 및 액세스 관리는 간단합니다. 멤버가 속한 그룹에 따라 액세스가 허용되거나 거부됩니다. 멤버의 보안 연결은 쉽게 추가하거나 변경할 수 있습니다.

<Aside>각 워크스페이스에서는 보안 그룹을 무제한으로 만들 수 있지만, 보안 관리를 쉽게 하려면 그룹 수를 최소한으로 유지하는 것이 좋습니다.</Aside>



## 보안 그룹 관리


보안 그룹은 추가, 업데이트 또는 삭제할 수 있습니다.



**보안 그룹을 관리하려면:**


1. Identity를 엽니다.
2. 레일에서 **보안 그룹**을 선택합니다(기존 그룹 목록이 표시됩니다).
3. 그룹을 추가하려면 **New group**을 클릭합니다.
4. 그룹의 권한을 편집하려면 가장 왼쪽에 있는 아이콘을 클릭합니다.

**그룹 멤버를 관리하려면:**


1. Identity를 엽니다.
2. 레일에서 **보안 그룹**을 선택합니다.
3. 멤버 아이콘을 클릭합니다.
4. 그룹에 속해야 하는 멤버는 선택하고, 속하지 않아야 하는 멤버는 선택을 해제합니다. 필터 상자를 사용하여 사람을 찾을 수 있습니다. [선택기로 할당하기](#선택기로-할당하기)를 참조하십시오.
5. **할당 업데이트**를 클릭합니다.

<Aside>할당된 사람이 없는 상태로 저장하면 아무것도 변경되지 않으며, 그 사실이 안내됩니다. 그룹을 모든 사람에게서 제거하려면 멤버십을 비우지 말고 그룹의 권한을 제거하거나 그룹을 삭제하십시오.</Aside>

<Aside>그룹이 [행 액세스](#행-액세스-관리)를 통해 행을 부여받은 경우, 멤버십 변경은 약 1분 이내에 대시보드에 반영됩니다. 추가한 사람은 대시보드에서 그룹의 행을 볼 수 있게 되고, 제거한 사람은 더 이상 볼 수 없게 됩니다. 멤버를 비활성화하거나 삭제하는 경우와 그룹을 삭제하는 경우에도 같은 방식으로 적용됩니다.</Aside>

<Aside type="caution">자신이 부여할 수 없는 권한은 그룹의 권한 매트릭스를 저장할 때 그대로 유지되며, 매트릭스에 표시되지 않습니다. 그러한 권한을 변경해야 하면 해당 권한을 보유한 사람에게 요청하십시오. 매트릭스에서는 본인이 제어할 수 있는 권한만 편집할 수 있습니다.</Aside>

<Aside type="caution">그룹이 부여하는 모든 권한을 보유한 경우에만 멤버를 그룹에 추가하거나 멤버의 그룹을 선택할 수 있습니다. 아키텍트로 사용자를 초대할 때도 마찬가지입니다. 워크스페이스 관리자에게는 이러한 제한이 없습니다.</Aside>

## 선택기로 할당하기

사람, 그룹 또는 기타 항목에 무언가에 대한 액세스 권한을 부여하는 모든 곳에서는, 이전의 두 목록 대신 하나의 체크리스트를 사용합니다. 모든 행에는 확인란이 있으며, 선택된 행이 할당된 항목입니다. 각 행에는 이름과 이메일이 별도의 열로 표시됩니다. 이 체크리스트는 그룹의 멤버, 멤버의 보안 그룹, 계정의 멤버·그룹·에이전트·소유자, 연결의 액세스, 배포 목록의 워크스페이스 멤버, Weave 준비 상태 세트의 워크플로를 설정할 때 사용합니다.

- **필터.** 필터 상자에 입력하면 목록이 좁혀집니다. 일치는 부분 일치이며 대소문자를 구분하지 않으므로, `smith`는 해당 문자열이 포함된 모든 이름이나 이메일을 찾고, `@example.com`은 해당 도메인의 모든 사람을 찾습니다. 여러 단어를 입력하면 모든 단어와 일치하는 행만 남습니다.
- **이메일 목록 붙여넣기.** 공백, 쉼표, 세미콜론 또는 줄 바꿈으로 구분된 여러 이메일 주소를 붙여넣으면, 목록에 정확히 그 사람들만 표시됩니다. `@example.com`과 같은 도메인 전체를 섞어 넣을 수도 있습니다. 필터 아래의 한 줄은 붙여넣은 항목 중 일치한 개수를 알려 주고 찾지 못한 항목을 나열합니다. **할당** 뒤에 일치한 개수가 표시된 버튼을 클릭하면 일치한 모든 사람이 한 번에 선택됩니다.
- **All, Assigned and Not assigned.** 목록 위의 세 버튼은 전체, 할당된 항목만, 할당되지 않은 항목만 표시하도록 전환하며 각각 개수가 표시됩니다. 필터와 함께 적용됩니다.
- **Assign all shown and Unassign all shown.** 현재 필터와 보기에 표시된 모든 행을 선택하거나 선택 해제하며, 숨겨진 행은 그대로 둡니다. 목록 위의 한 줄은 전체 행 중 몇 개가 표시되고 있는지 알려 줍니다.
- **Will add and Will remove.** 저장 버튼을 클릭하기 전에는 아무것도 저장되지 않습니다. 선택한 행은 색이 칠해지고 **Will add** 표시가 나타나며, 선택을 해제한 행에는 **Will remove**이 표시됩니다. 목록 위의 요약에는 할당된 개수와 보류 중인 변경 사항이 표시됩니다. 요약은 예를 들어 `12 assigned · +3 to add · −1 to remove`와 같이 표시됩니다. **변경 내용 실행 취소**를 누르면 창을 열었을 때의 상태로 모두 되돌아갑니다.
- **변경 사항이 있을 때만 저장.** **할당 업데이트**, **멤버 업데이트**, **그룹 업데이트**와 같은 저장 버튼은 변경한 내용이 있을 때만 사용할 수 있습니다.
- **키보드.** **Space**는 선택한 행을 선택하거나 선택 해제합니다. 필터 상자에서 **Enter**를 눌러도 저장되지 않으므로, 검색하는 중에 눌러도 액세스가 변경되는 일은 없습니다.

액세스 권한을 볼 수는 있지만 변경할 수 없는 경우(예: 본인이 소유하지 않은 연결)에는 선택기가 읽기 전용입니다. 이를 알리는 메모가 표시되고, 이미 할당된 사람만 확인란 대신 이니셜과 함께 나열되며, 변경하는 버튼은 표시되지 않습니다.

## 행 액세스 관리

행 액세스는 한 열의 값을 기준으로 보안 그룹이 볼 수 있는 테이블의 행을 제한합니다. 예를 들어 `region` 열로 액세스를 제한하여, `East`와 `Central`이 부여된 그룹은 해당 값을 가진 행만 볼 수 있게 할 수 있습니다. 프로젝트와 열에 대한 모든 설정, 즉 열 선택, 값의 출처 선택, 어느 그룹이 무엇을 볼지 결정하는 작업이 하나의 화면에서 이루어지며, 저장하면 즉시 적용됩니다.

행 액세스를 설정하고 변경하려면 프로젝트 아키텍트 또는 테넌트 관리자여야 합니다. 그 밖의 사용자가 프로젝트의 보안 탭을 열면 행 액세스는 아키텍트 전용이라는 안내가 표시되며, 아래의 진입점도 표시되지 않습니다.

### 행 액세스 열기

모든 진입점은 동일한 행 액세스 화면을 엽니다.

- **테이블 탐색기의 도구 모음**에는 **행 액세스** 버튼이 있으며, 테이블이 이미 행을 제한하는 경우 배지가 표시됩니다. 제한된 열이 있으면 테이블의 첫 번째 제한된 열에서 열리며, 테이블의 다른 열로 전환할 수 있습니다.
- **열의 패싯 메뉴**에는 **이 열로 행 제한…** 이 있으며, 이 항목은 해당 열에서 행 액세스를 엽니다. 이미 행을 제한하는 열에서는 항목이 **이 열로 제한된 행 — 편집…** 으로 표시됩니다.
- **프로젝트의 보안 탭**에는 프로젝트의 제한된 모든 열이 나열되며, 각 열에 적용되는 테이블, 권한을 가진 그룹, **동기화** 상태가 표시됩니다. 열을 선택하여 편집하거나 **열 제한…** 을 클릭하여 새로 시작합니다. 먼저 테이블을 선택한 다음 열을 선택합니다. 이미 행을 제한하는 열에는 잠금 표시가 붙습니다.
- **Identity → Member**의 멤버 **행 액세스** 탭과 **Identity → 보안 → 보안 그룹**의 그룹 행 액세스 요약. **행 액세스 열기**(또는 **편집**)는 선택한 열을 열고, **추가**는 해당 행의 프로젝트에서 다른 열을 제한합니다.

열에서 열면 화면은 해당 열에 유지됩니다. **열 제한…** 또는 **추가**로 열면 열을 선택할 수 있습니다.

### 행 액세스 그리드

열을 기준으로 테이블을 제한하려면:

1. 위의 진입점 중 하나에서 행 액세스를 열고, 열을 지정하지 않은 상태로 들어온 경우 열을 선택합니다. 선택기에는 자유 텍스트가 아니라 테이블의 실제 열이 표시됩니다.
2. **값 소스**를 선택합니다. **열**(테이블 열의 고유한 값), **차원**(차원의 노드) 또는 **목록**(직접 입력하는 값) 중에서 선택합니다. 값 유형은 열의 데이터 유형에 따라 결정됩니다.
3. 각 보안 그룹에 대해 해당 그룹이 볼 수 있는 값을 선택합니다. 그리드에는 프로젝트에 액세스할 수 있는 그룹과, 해당 열에 이미 권한이 있는 그룹이 나열됩니다.
4. **Everyone else**를 **sees all rows** 또는 **sees no rows**로 설정합니다. 이 설정은 그리드에서 아무것도 선택되지 않은 모든 그룹에 적용됩니다.
5. **저장**을 클릭합니다.

저장은 즉시 적용됩니다. PlaidCloud 자체 쿼리에는 변경 사항이 바로 반영되고 Superset 대시보드에는 약 1분 이내에 반영됩니다. 별도로 적용하는 단계는 없으며, 부여된 값 중 소스에서 더 이상 존재하지 않는 값이 있을 때만 **저장** 시 확인 창이 표시됩니다(아래 참조). 화면의 동기화 상태에는 변경 사항이 어디까지 진행되었는지 표시됩니다. [대시보드 동기화 유지](#대시보드-동기화-유지)를 참조하십시오.

그리드는 다음과 같은 세부 사항도 자동으로 처리합니다.

- **많은 값.** 값은 정렬되어 표시됩니다. 열의 값이 한 화면에 다 들어가지 않으면 그리드에 "More values than fit here — type to search."라고 표시되며, 필터 상자는 열 전체를 검색하고 그룹이 이미 가진 모든 값을 유지합니다.
- **소스에 더 이상 없는 값.** 그룹에 부여된 값은 소스에서 사라져도 그리드에 남아 있습니다. 테이블의 어떤 행에도 해당 값이 없거나, 차원에 더 이상 해당 멤버가 없거나, 목록에 더 이상 해당 값이 없는 경우입니다. 해당 열 머리글에 경고 아이콘이 표시되며, 마우스를 올리면 이유가 표시됩니다. **모두 선택**, **선택 반전**, **붙여넣기**는 이러한 값을 각 그룹이 가진 상태 그대로 둡니다. 선택을 해제하지 않는 한 부여에서 아무것도 제거되지 않습니다. 그룹이 그러한 값을 아직 가지고 있는 상태에서 **저장**을 클릭하면 행 액세스가 **Values No Longer in the Source** 창에 해당 그룹과 값을 알려 주고 확인을 요청합니다. **Keep and Save**는 값을 그대로 저장하고, **Remove and Save**는 모든 그룹의 부여에서 해당 값을 먼저 제거하며, 창을 닫으면 아무것도 저장되지 않습니다. 값을 제거하면 선택된 항목이 하나도 없는 그룹이 생기는 경우, 이 창에는 **Everyone else** 설정에 따라 해당 그룹이 모든 행을 보게 되는지 아니면 아무 행도 보지 못하게 되는지 표시됩니다. 아직 저장하지 않은 선택은 해당 값과 함께 사라집니다. 열에 한 화면에 다 들어가지 않는 값이 있거나 테이블이 아직 빌드되지 않은 경우에는 행 액세스가 테이블에 없는 값을 판단할 수 없으므로, 부여된 모든 값을 표시 없이 유지합니다.
- **빈 값.** **빈 값 - 부여된 모든 그룹에 표시** 확인란 하나로 열에 값이 없는 행을 어떻게 처리할지 결정합니다. 이 확인란을 선택하면 해당 열에 어떤 권한이든 가진 모든 그룹이 해당 행을 볼 수 있습니다.
- **아직 빌드되지 않은 테이블**에는 빈 목록 대신 **먼저 이 테이블을 빌드하십시오(테이블을 만드는 워크플로 실행)** 가 표시됩니다.
- **저장은 화면의 값이 로드될 때까지 대기합니다.** 값 소스, 차원 또는 테이블을 전환하거나 템플릿을 적용한 후 값을 로드하는 동안에는 **저장**이 비활성화되며 "Save is available once this source's values load."라는 도구 설명이 표시됩니다. 로드에 실패하면 그리드에 그 사실이 표시되고 소스를 다시 선택하도록 안내합니다. 로드에 성공하기 전에는 아무것도 저장되지 않습니다.

### 하나의 열 이름, 모든 테이블

제한은 단일 테이블이 아니라 프로젝트의 열 *이름*에 속합니다. `region`이 행을 제한하면, 프로젝트에서 `region`이라는 이름의 열을 가진 모든 테이블이 PlaidCloud 자체 쿼리와 대시보드 모두에서 해당 제한으로 필터링됩니다. 그리드의 **Applies to** 목록에 해당 테이블이 표시됩니다. 열 이름에 따라 결정되므로 읽기 전용이며, 나중에 같은 열을 가진 테이블을 추가하면 게시되는 즉시 적용 대상에 포함됩니다.

프로젝트의 어떤 테이블에도 해당 이름의 열이 없으면, **Applies to 0 tables**이라고 표시되는 것에 더해 해당 이름의 열을 가진 테이블이 생기기 전까지는 제한이 어떤 대시보드도 필터링하지 않는다는 경고가 창에 표시됩니다. 테이블에 열을 추가하거나 열 이름을 수정하면 경고가 사라집니다.

<Aside type="caution">
**열 이름은 대소문자와 공백을 포함하여 정확히 일치해야 합니다.** `Region`과 `region`은 서로 다른 이름이며, `region`과 끝에 공백이 있는 `region `도 마찬가지입니다. 선택기에는 실제 열 이름만 표시되므로, 이 문제는 주로 다른 곳에서 열 이름이 바뀐 경우에 해당합니다. 이 경우 행 액세스는 아무것도 제한하지 않은 채 넘어가는 대신 경고를 표시하고 찾은 가장 가까운 열의 이름을 알려 줍니다.
</Aside>

<Aside type="caution">
**행을 제한하는 테이블을 게시하면 같은 단계에서 대시보드 필터도 설정됩니다.** 대시보드는 게시된 보고용 뷰를 통해 테이블을 읽으므로, 제한된 열이 있는 테이블을 게시하거나 다시 게시하면 게시가 완료되기 전에 PlaidCloud가 해당 테이블의 대시보드 필터를 등록합니다. 등록할 수 없으면 게시가 거부되고 해당 시도에서 만들어진 모든 것이 롤백되므로, 제한된 테이블이 필터링되지 않은 채 대시보드에 남는 일은 없습니다. 뷰의 쿼리가 제한된 열의 이름을 바꾸거나 파생할 수 있으므로, 행을 제한하는 프로젝트에서는 *뷰*를 게시할 수 없습니다. [테이블 게시](/ko/guides/data/publish/)를 참조하십시오.
</Aside>

### 제한 중지

그리드의 **제한 중지**는 인라인 확인 후 제한을 제거합니다. 확인 문구는 "Stop restricting rows by ‘region’? Every group's grant on it is removed and everyone sees its rows."입니다. 이후 행 액세스는 "Rows in ‘region’ are no longer restricted."라고 확인해 줍니다. 해당 열의 Superset 데이터 세트도 함께 제거되지만, 차트가 아직 사용 중이면 제거되지 않습니다. 이 경우 행 액세스는 데이터 세트가 유지되며 몇 개의 차트가 사용 중인지 알려 줍니다.

행을 제한하는 열은 이름을 바꾸거나 삭제할 수 없습니다. 아키텍트에게는 먼저 행 액세스에서 제한을 중지하도록 안내하고, 그 외의 사용자에게는 프로젝트 아키텍트에게 요청하도록 안내합니다.

### 행을 제한하는 프로젝트를 변경할 수 있는 사용자

프로젝트의 워크플로, 단계, 사용자 정의 함수는 프로젝트 자체의 서비스 ID로 실행되며, 이 ID는 모든 행을 읽습니다. 이를 변경할 수 있는 사람은 부여받지 않은 행을 자신이 읽을 수 있는 테이블로 복사하는 단계를 만들 수 있으므로, 프로젝트에서 행을 제한하면 프로젝트가 하는 일을 누가 변경할 수 있는지도 함께 제한됩니다. 프로젝트에서 열을 하나 이상 제한하면 다음이 적용됩니다.

- **자동화는 아키텍트 전용입니다.** 프로젝트 아키텍트와 테넌트 관리자만 워크플로, 단계, 사용자 정의 함수, 일정, 워크플로 및 프로젝트 변수, 알림 이메일 템플릿을 변경할 수 있습니다. 같은 이유로 워크플로 번들 가져오기, Alteryx 워크플로 변환, 프로젝트로의 가져오기·복사·복원, 프로젝트의 연결 환경, 기본 문서 계정 또는 ERP 전기 모드 변경도 이들만 할 수 있습니다. 그 외의 사용자도 프로젝트의 워크플로를 실행할 수는 있으며, **시작**, **중지**, **재개**, **선택한 단계 실행**은 계속 사용할 수 있습니다. 단계 편집기, 워크플로의 작성 컨트롤, UDF 편집기, 일정 양식은 이들에게 읽기 전용으로 열리며, 문의할 아키텍트를 알려 주는 배너가 표시됩니다. "This project restricts rows, so only its Architects can change workflows, steps, UDFs, schedules, variables and notify templates. You can still run them."
- **제한된 열이 읽는 차원은 아키텍트 전용입니다.** 누가 어떤 행을 볼지 결정하는 차원, 즉 제한된 열의 값 소스는 프로젝트 아키텍트나 테넌트 관리자, 그리고 프로젝트 자체의 워크플로만 변경할 수 있습니다. 여기에는 차원의 노드를 추가, 이동, 이름 바꾸기, 복사, 지우기, 로드, 복원하는 작업과 차원 자체가 포함됩니다. 그 외의 사용자에게는 "This dimension decides who sees which rows of ‘region’, so only a project Architect can change it."라고 안내됩니다. 어떤 제한도 읽지 않는 차원은 영향을 받지 않습니다.
- **부여 소스 테이블은 아키텍트 전용입니다.** [부여 소스](#부여를-소스-테이블에-바인딩)로 바인딩된 테이블은 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트의 워크플로만 행을 변경하거나 테이블을 삭제할 수 있습니다. 데이터 편집기, 가져오기, 커넥터 로드, API 중 어느 경로로든 마찬가지입니다.
- **프로젝트 복사는 아키텍트 전용이며**, 복사본에는 "This copy is not row-restricted."라고 표시됩니다. 새 프로젝트는 제한을 설정하기 전까지 어떤 제한도 갖지 않습니다.
- **이전 버전 복원도 다른 변경과 같은 변경입니다.** 프로젝트 자체의 설정이나 위에 나열된 차원을 복원하려면 프로젝트 아키텍트여야 합니다. 복원은 항상 해당 버전이 속한 항목에 적용되므로, 이 제한을 우회하기 위해 다른 프로젝트를 대상으로 지정할 수 없습니다. [버전 기록](/ko/guides/projects/managing-projects/#버전-기록)을 참조하십시오.
- **제한된 테이블의 데이터 편집**에는 [행 액세스와 데이터 편집기](#행-액세스와-데이터-편집기)에서 설명하는 대로 아키텍트가 필요합니다.
- **제한된 테이블에 대한 DataFrame 쓰기, 레코드 저장, 지우기**는 모든 행을 볼 수 있는 경우가 아니면 [제한된 테이블에 데이터 로드](#제한된-테이블에-데이터-로드)에서 설명하는 대로 본인의 행에만 영향을 줍니다.
- **제한된 테이블의 가져오기, 복사, 브랜치 전환, 복원, 삭제**는 [제한된 테이블에 데이터 로드](#제한된-테이블에-데이터-로드)에서 설명하는 대로, 테이블에 볼 수 없는 행이 있는 동안에는 거부됩니다.

프로젝트에서 첫 번째 열을 제한하기 전에 행 액세스는 영향을 받는 사람을 알려 줍니다. "Restricting rows here means only Architects can change this project's workflows, steps, UDFs, schedules and notify templates. N members can change them today; they will still be able to run them."

실행은 예약된 실행을 포함하여 프로젝트의 서비스 ID로 실행되므로 이전과 똑같이 동작합니다. 실행의 결과물은 아키텍트가 설계한 방식을 따릅니다. 제한된 열이 없는 출력 테이블, 내보내기 파일, 알림 이메일 또는 로그 줄은 이를 읽는 사람에 대해 필터링되지 않습니다.

**실행을 시작할 때 지정하는 값.** 워크플로를 실행할 수 있는 사람은 누구나 변수에 대해 자신의 값을 지정하여 워크플로를 시작할 수 있습니다. [앱 러너](/ko/guides/workflows/use-converted-alteryx-apps/#app-runner-프런트엔드)는 양식에 입력된 답변으로 이를 수행하며, API와 AI 도구도 마찬가지로 할 수 있습니다. 이러한 값은 해당 실행에만 유효하며 워크플로에 저장되지 않고, 다른 실행, 내보내기 또는 읽는 사람에게는 보이지 않습니다. 실행은 서비스 ID로 수행되므로 이 값은 해당 실행이 읽고 쓰는 내용을 바꿀 수 있습니다. 따라서 워크플로를 실행할 권한은 신뢰할 수 있는 사람에게만 부여하십시오.

**행을 제한하지 않는 프로젝트.** 이러한 규칙은 프로젝트에서 열을 제한하는 순간부터 적용됩니다. 행을 제한하지 않는 프로젝트에서는, 프로젝트의 자동화를 변경할 수 있는 사람이 프로젝트의 서비스 ID로 실행되는 단계나 사용자 정의 함수를 작성하여 프로젝트의 액세스를 변경하고 스스로를 프로젝트 아키텍트 중 한 명으로 만들 수 있습니다. 이는 의도된 동작이며, 이러한 프로젝트는 행 격리를 보장하지 않습니다. 이러한 프로젝트에서는 작성 권한을 아키텍트로 신뢰할 수 있는 사람에게만 부여하거나, 열을 제한하십시오.

### 대시보드 동기화 유지

행 액세스는 그리드와 프로젝트 보안 탭의 **동기화** 열에, 변경 사항이 대시보드로 가는 도중 어디까지 진행되었는지 표시합니다.

| 상태 | 의미 |
|---|---|
| **대기 중** | 변경 사항이 저장되어 대시보드로 전달되는 중입니다. 보통 약 1분 이내에 사라집니다. |
| **재시도 중** | 전송이 실패하여 다시 시도하는 중입니다. 실패 이유가 상태 옆에 표시되며, **다시 시도**를 누르면 즉시 다시 전송합니다. |
| **아직 적용되지 않음** | 프로젝트의 제한이 아직 대시보드로 전송되지 않았습니다. |
| **적용됨** | 제한을 대시보드로 보내려는 마지막 시도가 성공했습니다. |
| **대시보드와 동기화됨** | 행 액세스가 대시보드가 적용하는 내용과 자신이 기록할 내용을 비교했으며 서로 일치합니다. |
| **대시보드와 다름** | 대시보드가 행 액세스가 기록할 내용을 적용하고 있지 않습니다. Superset에서 규칙이 변경 또는 삭제되었거나, 테이블의 게시된 뷰를 확인할 수 없는 경우입니다. |
| **오류** | 제한을 전송하지 못했습니다. 이유가 상태 옆에 표시됩니다. |

변경 사항이 **적용됨**에 도달하면 그리드가 이를 대시보드와 대조하여 **대시보드와 동기화됨** 또는 **대시보드와 다름**으로 넘어갑니다. **대시보드와 다름**과 **오류**에서는 모두 **다시 시도**를 사용할 수 있으며, 이 버튼은 프로젝트의 제한을 다시 전송합니다. 상태를 전혀 읽을 수 없으면 그리드에 "Couldn't check sync status."라고 표시됩니다.

하나의 테이블 때문에 발생한 **오류**에는 테이블 이름과 해야 할 일이 표시됩니다. 예를 들어 제한된 열 없이 게시된 테이블은 ("Republish or unpublish it.") 다시 게시하거나 게시를 취소하라고 안내하고, 제한된 열이 있지만 게시되지 않은 테이블은 게시되기 전까지 대시보드가 필터링할 수 없다고 안내합니다. 해당 테이블을 게시하거나 게시된 테이블에서 열을 제한할 때까지 상태는 **오류**로 유지되며 게시되지 않은 테이블의 이름이 표시됩니다. 이러한 테이블이 프로젝트의 나머지 부분을 막지는 않으며, 다른 모든 테이블은 계속 동기화됩니다.

대시보드는 PlaidCloud 자체 쿼리와 동일한 부여를 따릅니다.

- **해당 열이 있는 게시된 모든 테이블이 필터링됩니다.** 제한을 설정할 때 보고 있던 테이블만이 아닙니다.
- **일부 값만 부여된 그룹은 다른 모든 사용자가 모든 행을 보더라도 필터링됩니다.** 대시보드 데이터 세트가 존재하는 모든 테이블에 적용됩니다.
- **프로젝트 아키텍트는 모든 행을 봅니다.** 테이블 탐색기와 PlaidCloud의 다른 모든 곳에서와 마찬가지로 대시보드에서도 그렇습니다. 이는 프로젝트의 아키텍트 그룹과, 개별 멤버와 공유된 프로젝트의 아키텍트에게 적용됩니다. 아키텍트 액세스를 제거하면, 멤버의 역할을 변경하든, 멤버나 그룹을 프로젝트에서 제거하든, 프로젝트의 액세스 유형을 변경하든, 이전 프로젝트 버전을 복원하든, 그룹을 삭제하든 대시보드에 즉시 적용됩니다.
- **보안 그룹 멤버십 변경은 저절로 대시보드에 반영됩니다.** PlaidCloud에서 그룹에 사람을 추가하거나 제거하는 경우, 멤버를 비활성화하거나 삭제하는 경우, 그룹을 삭제하는 경우, 기본 보안 그룹에 가입하는 새 멤버를 추가하는 경우, 해당 그룹에 값을 부여하는 모든 프로젝트에서 대시보드에 표시되는 내용이 행 액세스를 다시 열 필요 없이 약 1분 이내에 업데이트됩니다. PlaidCloud 외부에서, 예를 들어 Keycloak에서 직접 또는 싱글 사인온이 로그인 시 사람을 그룹에 배치하여 이루어진 멤버십 변경은 저장하거나 다시 시도할 필요 없이 약 15분 이내에 대시보드에 반영됩니다.

### 차원 부여

**차원**을 값 소스로 사용하는 경우 노드를 선택하면 그 아래의 모든 항목이 부여됩니다. 부여는 차원을 따릅니다. 선택한 노드 아래에 추가된 멤버는 차원이 저장된 후 다음 동기화 때 해당 그룹에 부여되고, 그 아래에서 이동되거나 제거된 멤버는 더 이상 부여되지 않습니다. 그리드를 다시 열 필요가 없습니다. 그리드를 다시 열면 선택한 노드가 선택된 상태로 표시됩니다.

노드를 통하지 않고 단독으로 선택한 멤버는 차원에서 제거되어도 계속 부여된 상태로 남으며, 그리드에는 소스에 더 이상 없는 값으로 표시됩니다.

선택된 노드 아래의 항목 중 하나라도 선택을 해제하면 노드의 선택도 해제되며, 그룹에는 아직 선택된 멤버만 남습니다. 해당 멤버를 다시 선택해도 노드가 다시 선택되지는 않으므로, 노드를 선택하려면 노드 자체의 확인란을 클릭하십시오. **붙여넣기**, **모두 선택**, **선택 반전**은 멤버만 선택하며 노드는 선택하지 않습니다.

이름을 행 액세스 값으로 사용할 수 없는 차원 멤버는 저장할 때 해당 멤버의 이름과 함께 거부됩니다. 이러한 멤버가 나중에 나타나면 해당 멤버의 행은 누구에게도 부여되지 않으며, 동기화 상태에 해당 멤버의 이름이 표시됩니다. "Dimension ‘…’ member ‘…’ cannot be used as a row access value, so its rows are not granted. Rename it in the dimension."

### 부여를 소스 테이블에 바인딩

값을 직접 선택하는 대신, 제한된 열을 이미 답을 가지고 있는 소스 테이블, 즉 그룹과 해당 그룹이 볼 수 있는 값이 한 행씩 있는 테이블에 연결할 수 있습니다. 먼저 그리드에서 열을 제한한 다음, 열, 소스 테이블, 소스 테이블의 그룹 열과 값 열을 지정하는 [**행 액세스 설정**](/ko/reference/workflow-steps/tables/table-set-row-access/) 워크플로 단계를 추가합니다. 이 단계를 처음 실행하면 열이 해당 테이블에 바인딩됩니다. 열에 직접 설정한 부여는 지워지고, 부여는 테이블의 행에서 설정됩니다.

바인딩되면 해당 열은 **source-owned**가 됩니다. 행 액세스 그리드에는 소스 테이블 이름이 표시된 배지와 함께 잠긴 상태로 표시되며, **바인딩 제거**를 클릭하기 전에는 부여를 직접 편집할 수 없습니다.

이후 단계를 실행할 때마다 소스 테이블을 다시 읽어 부여를 다시 적용합니다. 해당 테이블을 로드하거나 새로 고치는 워크플로 뒤에 실행되도록 일정을 지정하면, 소스 데이터에서 추가, 제거 또는 재할당된 그룹이 아무도 그리드를 직접 편집하지 않아도 다음 실행 때 행 액세스에 반영됩니다.

누가 무엇을 볼지를 소스 테이블이 결정하므로, 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트 자체의 워크플로만 테이블의 행을 변경하거나 테이블을 삭제할 수 있습니다. 그 외의 사용자에게는 "This table supplies the row access grants for ‘region’, so only a project Architect can change its rows or delete it."라고 안내됩니다.

### 제한 템플릿

동일한 값 소스, 값 유형, 빈 값 설정 등 재사용하려는 제한 형태를 만들어 두었다면, 열마다 다시 만들지 말고 한 번 저장해 두었다가 필요한 곳에 적용하십시오.

- 열려 있는 행 액세스 화면의 **템플릿으로 저장…** 은 현재 열의 형태를 이름이 지정된 테넌트 수준 템플릿으로 저장합니다. 형태만 저장되며 부여는 함께 저장되지 않습니다.
- 다른 프로젝트의 열에서 **템플릿 적용**을 사용하면 해당 열이 템플릿의 형태로 시작하며, 모든 그룹의 부여는 비어 있어 직접 채울 수 있습니다.

모든 프로젝트 아키텍트가 템플릿을 저장하고 적용할 수 있습니다. 템플릿은 테넌트 전체에서 공유되므로 템플릿의 이름 바꾸기(**이름 바꾸기…**)와 삭제(**삭제**)에는 테넌트 관리자가 필요합니다. 템플릿을 삭제해도 해당 템플릿이 적용된 열은 제한된 상태 그대로 유지됩니다.

<Aside type="note">
템플릿은 링크가 아니라 복사본입니다. 나중에 템플릿을 편집해도 이미 템플릿을 적용한 열은 변경되지 않으며, 열을 이후 수정 내용에 맞추려면 템플릿을 다시 적용하십시오.
</Aside>

### SSO 그룹 속성에서 가져오는 부여

열은 PlaidCloud가 아닌 ID 공급자에서 부여를 가져올 수도 있습니다. 프로젝트 아키텍트가 행 액세스에서 **Accept row-access grants from SSO group attributes**을 사용하도록 설정하여 열을 지정합니다.

사용하도록 설정하면 보안 그룹의 Keycloak 속성 `row_access.<column>`이 해당 그룹이 그 열을 통해 볼 수 있는 값을 결정합니다. Keycloak에서 그룹에 속성을 설정하면 PlaidCloud가 프로젝트에 이미 액세스할 수 있는 모든 그룹에 대해 이를 자동으로 가져옵니다. 행 액세스 자체에서 추가로 구성할 내용은 없으며, 부여는 PlaidCloud 자체 쿼리와 Superset 대시보드 모두에서 동기화된 상태로 유지됩니다.

<Aside type="caution">
이 기능은 이미 프로젝트에 접근할 수 있는 그룹에만 값을 부여합니다. 프로젝트 액세스가 없는 그룹에 `row_access.region`을 추가해도, 그룹이 프로젝트에 대한 액세스 권한을 받기 전에는 아무것도 부여되지 않습니다.
</Aside>

### 저장 전 미리 보기

행 액세스는 변경 사항을 확정하기 전에 그 의미를 보여 줍니다.

- **다음 사용자로 미리 보기** 바닥글에는 그룹이 전체 행 중 몇 개의 테이블 행을 볼 수 있는지가 행 샘플과 함께 표시됩니다. 그리드에서 아무 그룹이나 선택하여 미리 볼 수 있습니다. 미리 보기는 저장한 후 새로 고쳐집니다.
- 저장하기 전에 행 액세스는 다시 확인해 볼 만한 사항을 경고합니다. 선택된 항목이 없는 그룹(그리고 **Everyone else** 설정에 따라 그 그룹이 모든 행을 보는지 아니면 아무 행도 보지 못하는지), 프로젝트 액세스는 있지만 어느 그룹의 부여에도 포함되지 않는 멤버, 해당 열의 값이 비어 있고(`NULL`) 어느 그룹에도 부여되지 않은 행이 이에 해당합니다.

### 제한된 멤버가 보는 내용

제한된 멤버가 이름으로 테이블을 읽는 모든 곳에서는 본인의 행만 표시됩니다. 테이블 탐색기의 그리드, 열 패싯, 다운로드, 테이블 다운로드 대화 상자, 뷰어로서 읽는 앱과 도구, 대시보드가 이에 해당합니다. 테이블 탐색기는 보고 있는 그리드가 사용자의 부여에 따라 필터링된 경우 도구 모음에 **액세스 권한에 따라 행이 제한됨**을 표시하며, 필터링될 다운로드를 시작하면 "Rows limited by your access."라고 표시됩니다. 모든 행을 읽는 아키텍트에게는 이러한 안내가 모두 표시되지 않습니다.

### 행 액세스와 직접 작성한 쿼리

행 액세스가 행을 제한하는 경우에도 프로젝트의 쿼리 화면에서 자신의 SQL 쿼리를 실행하면 부여된 행만 정확히 반환됩니다. 결과를 CSV, Excel 또는 JSON으로 내보낼 수 있으며, 내보내기에는 해당 행만 포함되고 **액세스 권한에 따라 행이 제한됨** 안내가 표시됩니다. 프로젝트 아키텍트는 제한된 모든 열의 모든 값을 스스로 부여할 수 있으므로 모든 행을 읽으며, 안내는 표시되지 않습니다.

퍼센트 기호(`%`)가 포함된 부여 값은 쿼리 화면에서 부여된 행을 반환하며, 이러한 쿼리를 CSV로 다운로드하는 것도 정상적으로 작동합니다.

프로젝트 아키텍트가 아닌 멤버에게는 다음 작업이 계속 거부됩니다.

- Snowflake 또는 Databricks 프로젝트 웨어하우스에서 자유 형식 SQL을 직접 실행하기
- Postgres 계열 웨어하우스에서 자신의 SQL 결과를 내보내기
- 자신의 SQL 결과를 다른 데이터베이스로 내보내기
- 팬아웃 단계의 "Test row 1" 미리 보기에 행 조건 입력하기
- 거버넌스가 적용된 테이블을 이전 스냅샷 시점으로 읽기(타임 트래블)

거부된 사용자에게는 어느 프로젝트인지 안내되고 이름으로 읽는 방법이 제시됩니다. 이름으로 테이블을 읽는 것은 앱과 도구가 데이터를 읽는 일반적인 방법이며, 부여를 적용하여 뷰어에게 권한이 있는 행을 반환합니다. 단일 테이블에 대한 단순 쿼리로 작성된 열 패싯도 이름으로 읽으므로, 거부되는 대신 멤버 자신의 값을 반환합니다. 프로젝트 아키텍트는 이러한 작업을 작성한 그대로 실행할 수 있습니다.

행 액세스는 거버넌스가 적용된 열을 기준으로 뷰를 필터링하므로, 뷰는 해당 열을 원래 이름으로 유지해야 합니다. 거버넌스가 적용된 열을 제외하거나 이름을 바꾼 뷰는 필터링되지 않습니다.

스프레드시트 가져오기는 그 자체로는 직접 작성한 쿼리가 아닙니다. 일반적인 파일 가져오기는 제한된 데이터를 전혀 읽지 않으며 업로드한 파일에서 프로젝트 자체의 새 테이블만 만들기 때문에, 행 액세스의 영향을 받지 않습니다. 예외는 데이터 프로젝션을 호출자가 제공하는 가져오기, 즉 열별 식이나 동적 Excel 매핑입니다. 대화형 가져오기 화면에서는 이러한 항목이 위의 자유 형식 SQL 화면과 같은 방식으로 거부되며 프로젝트 아키텍트가 필요합니다. 호출자가 제공한 프로젝션이 다른 테이블을 읽을 수 있기 때문입니다. 워크플로에서 실행하는 가져오기는 프로젝트 자체의 서비스 ID로 실행되므로 어느 경우에도 영향을 받지 않습니다.

<Aside type="caution">
프로젝트에서 첫 번째 열을 제한하면 이를 사용하는 모든 사람에게 이 동작이 바뀝니다. 해당 프로젝트의 Panel 앱, 노트북 또는 통합이 Snowflake 또는 Databricks 웨어하우스에서 자체 SQL을 구성하거나 Postgres 계열 웨어하우스에서 자체 쿼리 결과를 내보내는 경우, 제한하기 전에 이름으로 테이블을 읽도록 전환하십시오. 그렇지 않으면 아키텍트가 아닌 모든 사람에게 작동하지 않게 됩니다.
</Aside>

### 행 액세스와 데이터 편집기

데이터 편집기는 테이블을 직접 읽고 쓰므로 행 액세스가 양쪽 모두에 적용됩니다.

데이터 편집기에서 제한된 테이블을 열면 보안 그룹에 부여된 행만 표시됩니다. 이는 대시보드에서도 적용되는 것과 동일한 필터이며, 제한된 열이 그리드에 표시된 열 중 하나가 아니어도 적용됩니다.

편집 내용을 저장하려면 프로젝트에 대한 **아키텍트** 권한이 필요합니다. 저장은 테이블의 행을 읽지 않고 통째로 교체하며 행 단위로 필터링되지 않으므로, 제한된 테이블의 데이터 편집은 읽기가 아니라 작성 작업으로 취급됩니다. 아키텍트가 아닌 사용자에게는 아키텍트 권한이 필요하다고 안내됩니다. 제한된 열이 없는 테이블은 이전과 같이 편집할 수 있으며, 행을 제한하지 않는 프로젝트도 마찬가지입니다.

### 제한된 테이블에 데이터 로드

행 액세스가 보이는 행을 제한하는 경우, Python 클라이언트(`PlaidConnection`)로 DataFrame을 제한된 테이블에 쓰거나 테이블을 지우거나, REST API로 레코드를 저장하거나 지우는 작업은 본인의 행에만 적용됩니다. 테이블의 데이터를 교체하면 볼 수 있는 행만 교체되고, 지우면 해당 행만 지워지며, 추가하면 행이 추가됩니다. 그 외의 행은 그대로 유지됩니다.

액세스 범위를 벗어난 행이 포함된 로드는 아무것도 변경되기 전에 거부되며, 오류에는 액세스 범위를 벗어난 각 값과 해당 값을 가진 행의 개수가 표시됩니다. 제한된 열을 생략한 행은 해당 열이 비어 있는 것으로 검사되므로, 액세스 범위에 빈 행이 포함되어 있지 않으면 거부됩니다. 열의 유형이 변경되는 방식으로 데이터를 교체하는 작업도 거부되므로, 프로젝트 아키텍트에게 해당 변경을 요청하십시오.

프로젝트 아키텍트, 부여가 모든 행을 포함하는 멤버, 프로젝트의 서비스 ID로 실행되는 워크플로 실행은 전체 테이블에 쓸 수 있습니다. 제한된 열이 없는 테이블은 영향을 받지 않습니다.

제한된 테이블 전체를 교체하거나 제거하는 그 밖의 작업은 테이블에 볼 수 없는 행이 있는 동안 거부되며 아무것도 변경되지 않습니다. 파일을 테이블로 가져오기, 다른 프로젝트에서 테이블 복사하기, 브랜치 전환 또는 병합하기, 아카이브나 프로젝트의 보관된 스냅샷 복원의 일부로 복원하기, 삭제하기, 삭제 후 다시 가져오기, 테이블을 비운 후 다시 채우는 그 밖의 모든 작업이 이에 해당합니다. 제한된 열이 비어 있는 행은 액세스 범위에 빈 행이 포함되어 있지 않으면 볼 수 없는 행으로 간주됩니다. 모든 행을 볼 수 있는 테이블, 예를 들어 본인의 행만 담아 직접 만든 테이블은 교체하거나 삭제할 수 있습니다.

사람이 어떤 테이블에든 수행하는 이러한 쓰기는 거부된 경우를 포함하여 모두 보안 로그에 기록됩니다. 워크플로 실행은 여기에 기록되지 않습니다.

### 행 수와 테이블 크기

테이블의 행 수와 저장 크기는 볼 수 있는 행이 아니라 테이블 전체를 나타내므로, 제한된 읽기 사용자에게 부여 범위 밖에 몇 개의 행이 있는지 알려 주게 됩니다. 행을 제한하는 프로젝트에서는 읽기가 필터링되는 모든 사용자에게 프로젝트의 어떤 테이블에 대해서도 행 수나 크기가 표시되지 않습니다. 테이블 목록, 검색, 테이블 세부 정보, 스냅샷, 그리고 AI 어시스턴트와 MCP로 연결된 AI 도구에서 모두 마찬가지입니다. 이는 제한된 열이 없는 테이블을 포함하여 프로젝트의 모든 테이블에 적용됩니다. 프로젝트 자체의 합계도 이들에게는 숨겨집니다. 홈, 프로젝트 목록과 검색, 프로젝트 세부 정보에 표시되는 전체 행 수와 크기가 이에 해당합니다.

워크플로 실행 기록에도 같은 규칙이 적용됩니다. 각 실행과 단계가 기록한 읽은 행 수와 쓴 행 수도 테이블 전체를 나타내므로, 같은 읽기 사용자에게는 워크플로와 단계의 실행 기록, 그리고 AI 어시스턴트와 MCP로 연결된 AI 도구에서 해당 수치가 비어 있습니다. 이들에 대해서는 [Weave](/ko/guides/ai-assistant/weave-findings/)가 이전 실행과 달라진 행 수나 빈 값에 대해 단계를 검사하지 않습니다. 결과 항목 자체가 테이블 전체의 행 수가 바뀌었음을 알려 주게 되기 때문입니다.

프로젝트 아키텍트에게는 이전과 같이 수치가 표시되며, 행을 제한하지 않는 프로젝트의 모든 사용자에게도 마찬가지입니다.

### 멤버가 볼 수 있는 내용 확인

그룹에 부여된 내용이 아니라 특정 사람이 볼 수 있는 내용을 확인하려면 **Identity → Member**를 열고 멤버를 선택한 다음 해당 멤버의 **행 액세스** 탭을 엽니다. **유효 액세스** 열에는 제한된 모든 프로젝트와 열에 대해, 멤버가 모든 그룹을 합쳐서 볼 수 있는 값이 표시되며, SSO 그룹 속성의 부여와 그룹의 부여에 포함된 빈(`NULL`) 행도 포함됩니다. 프로젝트 아키텍트는 모든 행을 읽으므로 **모든 행 볼 수 있음(Architect)** 으로 표시됩니다. 이는 PlaidCloud 자체 쿼리가 적용하는 것과 동일한 결과이므로, 지원 업무에 유용하고 누군가가 문제를 보고하기 전에 변경 사항이 의도한 대로 동작하는지 확인하는 데에도 유용합니다.

### 더 명확한 오류

직접 작성한 제한된 프로젝트의 쿼리, 아키텍트 없이 하는 편집, 자동화·차원·부여 소스 테이블의 변경 등 위에서 설명한 경우에 행 액세스가 작업을 차단하면, 일반적인 실패 메시지 대신 무엇이 제한되어 있는지와 문의할 아키텍트 등 다음에 해야 할 일이 메시지에 표시됩니다.

### 행 액세스 감사

열을 제한하거나 제한을 해제하는 작업과 그룹의 부여를 편집하는 작업은 모두 해당 프로젝트의 [프로젝트 로그](/ko/get-started/tutorials/collaborate-versions-and-sharing/#프로젝트-로그-읽기)에 누가 언제 변경했는지가 기록됩니다. 확인하려면 프로젝트에서 **Analyze → Projects → Log**를 여십시오. 이 기록을 남기기 위해 행 액세스에서 별도로 켜야 하는 설정은 없으며, 프로젝트에 대한 다른 모든 추적 대상 변경과 같은 방식으로 기록됩니다.

## 기본 보안 그룹 설정


새 멤버를 추가하는 데 걸리는 시간을 줄이려면 기본 보안 그룹 집합을 지정하십시오. 이렇게 하면 각 사람을 수동으로 할당하지 않고도 새 멤버에게 기본 보안 그룹을 제공할 수 있습니다. 새 보안 그룹을 추가할 때 보안 그룹 창 하단의 “Assign to New Users by Default” 확인란을 선택하면 이 설정을 사용할 수 있습니다.



## 보안 감사 수행


보안 감사 기능을 사용하면 모든 멤버와 그룹에 걸친 그룹 멤버십을 볼 수 있습니다.



**보안 감사를 수행하려면:**


1. Identity를 엽니다.
2. 레일의 **보안** 아래에서 **Group audit**를 선택합니다.

PlaidCloud의 모든 테이블은 CSV 파일 형식으로 내보낼 수 있으므로, 과거 기록 확인이나 단순한 오프라인 열람을 위해 PlaidCloud 밖에서 그룹과 멤버의 연결을 검토할 수 있습니다.



**“Security Group Audit” 양식에서 내보내려면:**


1. Identity를 엽니다.
2. 레일의 **보안** 아래에서 **Group audit**를 선택합니다.
3. 테이블에서 “Username” 오른쪽 끝에 있는 작은 아이콘을 클릭합니다.
4. 원하는 형식에 따라 “Export CSV” 또는 “Export XLXS”를 클릭합니다.

## 사용 가능한 권한 설정 보기


워크스페이스에서 사용하는 각 애플리케이션에는 사용 가능한 고유한 권한이 있습니다. 보안 그룹 권한은 이러한 애플리케이션 권한을 기반으로 합니다.


각 애플리케이션에서 사용 가능한 권한의 전체 목록은 보안 빈에서 볼 수 있습니다.



**보안 빈에 액세스하려면:**


1. Identity를 엽니다.
2. “Security”를 선택합니다.
3. 드롭다운 메뉴에서 “Security Bins”를 클릭합니다.

각 애플리케이션의 세부 보안 설정을 보려면 맨 왼쪽의 태그 아이콘을 선택합니다.



이 사용 가능한 보안 설정 정보는 참고용입니다. 권한 관리에 관한 자세한 내용은 위의 보안 그룹 관리 섹션을 참조하십시오.
