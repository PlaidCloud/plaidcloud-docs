PlaidCloud의 보안 및 액세스 관리는 간단합니다. 멤버가 속한 그룹에 따라 멤버의 액세스가 허용되거나 거부됩니다. 멤버의 보안 연결을 추가하거나 변경하는 작업도 쉽게 사용자 지정할 수 있습니다.

<Aside>각 워크스페이스에서는 보안 그룹을 개수 제한 없이 만들 수 있지만, 보안 관리를 쉽게 하려면 그룹 수를 최소화하는 것이 좋습니다.</Aside>



## 보안 그룹 관리


보안 그룹은 추가, 업데이트 또는 삭제할 수 있습니다.



**보안 그룹을 관리하려면 다음과 같이 합니다.**


1. Identity를 엽니다.
2. “보안” 탭을 선택합니다.
3. 드롭다운 메뉴에서 “보안 그룹”을 클릭합니다(기존 그룹이 있는 양식이 표시됩니다).
4. 그룹을 추가하려면 “보안 그룹 만들기”를 클릭합니다.
5. 그룹의 권한을 편집하려면 맨 왼쪽 아이콘을 클릭합니다.

**그룹 멤버를 관리하려면 다음과 같이 합니다.**


1. Identity를 엽니다.
2. “보안” 탭을 선택합니다.
3. 드롭다운 메뉴에서 “보안 그룹”을 클릭합니다.
4. 멤버 아이콘을 클릭합니다.
5. 원하는 멤버를 “할당되지 않은 멤버” 열에서 “할당된 멤버” 열로 끌어다 놓습니다. 반대로 끌어다 놓으면 멤버가 제거됩니다.

<Aside>“할당된 멤버” 열을 비운 채로 저장하면 아무것도 변경되지 않으며, 그 사실이 안내됩니다. 그룹을 모든 사람에게서 제외하려면 멤버십을 비우는 대신 그룹의 권한을 제거하거나 그룹을 삭제하십시오.</Aside>

<Aside>그룹에 [행 액세스](#행-액세스-관리)를 통해 행이 부여된 경우, 멤버십 변경은 약 1분 이내에 대시보드에 반영됩니다. 추가한 사람은 대시보드에서 그 그룹의 행을 보게 되고, 제거한 사람은 더 이상 보지 못합니다. 멤버를 비활성화하거나 삭제하는 경우와 그룹을 삭제하는 경우에도 같은 방식으로 적용됩니다.</Aside>

<Aside type="caution">직접 부여할 수 없는 권한은 그룹의 권한 매트릭스를 저장할 때 변경되지 않으며 매트릭스에 표시되지도 않습니다. 그런 권한을 변경해야 하는 경우 해당 권한을 가진 사람에게 요청하십시오. 매트릭스에서는 본인이 제어할 수 있는 권한만 편집할 수 있습니다.</Aside>

## 행 액세스 관리

행 액세스는 한 열의 값을 기준으로 보안 그룹이 볼 수 있는 테이블의 행을 제한합니다. 예를 들어 `region` 열로 액세스를 제한하여, `East`와 `Central`을 부여받은 그룹이 해당 값을 가진 행만 보도록 할 수 있습니다. 프로젝트와 열에 관한 모든 작업, 즉 열 선택, 값의 출처 선택, 어떤 그룹이 무엇을 볼지 결정하는 작업이 하나의 화면에서 이루어지며, 저장하면 즉시 적용됩니다.

행 액세스를 설정하고 변경하려면 프로젝트 아키텍트 또는 테넌트 관리자여야 합니다. 그 외의 사용자가 프로젝트의 보안 탭을 열면 행 액세스는 아키텍트 전용이라는 안내가 표시되며, 아래의 진입점도 나타나지 않습니다.

### 행 액세스 열기

모든 진입점은 동일한 행 액세스 화면을 엽니다.

- **테이블 탐색기의 도구 모음**에는 **행 액세스** 버튼이 있으며, 테이블이 이미 행을 제한하고 있으면 배지가 표시됩니다. 테이블에 제한된 열이 있으면 첫 번째 제한 열에서 열리고, 테이블의 다른 열로 전환할 수 있습니다.
- **열의 패싯 메뉴**에는 **이 열로 행 제한…** 항목이 있으며, 이 항목은 해당 열에서 행 액세스를 엽니다. 이미 행을 제한하는 열에서는 이 항목이 **이 열로 제한된 행 — 편집…** 으로 표시됩니다.
- **프로젝트의 보안 탭**에는 프로젝트에서 제한된 모든 열이 적용 대상 테이블, 부여를 보유한 그룹, **동기화** 상태와 함께 나열됩니다. 열을 선택하여 편집하거나 **열 제한…** 항목을 클릭하여 새로 시작할 수 있습니다. 테이블을 선택한 다음 열을 선택하십시오. 이미 행을 제한하는 열에는 잠금 표시가 있습니다.
- **Identity → 멤버**의 멤버 **행 액세스** 탭과 **Identity → 보안 → 보안 그룹**의 그룹 행 액세스 요약에서 열 수 있습니다. **행 액세스 열기**(또는 **편집**)는 선택한 열을 열고, **추가**는 해당 행의 프로젝트에서 다른 열을 제한합니다.

열에서 연 경우 화면은 그 열에 머무릅니다. **열 제한…** 또는 **추가**로 연 경우에는 열을 선택할 수 있습니다.

### 행 액세스 그리드

열을 기준으로 테이블을 제한하려면 다음과 같이 합니다.

1. 위의 진입점 중 하나에서 행 액세스를 열고, 열을 지정하지 않은 상태로 들어왔다면 열을 선택합니다. 선택기에는 자유 입력 텍스트가 아니라 테이블의 실제 열이 표시됩니다.
2. **값 소스**를 선택합니다. **열**(테이블 열의 고유 값), **차원**(차원의 노드) 또는 **목록**(직접 입력하는 값) 중에서 고릅니다. 값 유형은 열의 데이터 유형에 따라 정해집니다.
3. 각 보안 그룹에 대해 해당 그룹이 볼 수 있는 값을 선택합니다. 그리드에는 프로젝트에 액세스할 수 있는 그룹과, 해당 열에 이미 부여를 보유한 그룹이 나열됩니다.
4. **그 외 모든 사용자**를 **모든 행 보기** 또는 **행 보지 않기**로 설정합니다. 이 설정은 그리드에서 선택된 값이 없는 모든 그룹에 적용됩니다.
5. **저장**을 클릭합니다.

저장은 즉시 적용됩니다. PlaidCloud의 자체 쿼리에는 변경 사항이 바로 반영되고, Superset 대시보드에는 약 1분 이내에 반영됩니다. 적용하기 위한 별도 단계나 승인 대화 상자는 없습니다. 화면의 동기화 상태에서 변경 사항이 어디까지 전달되었는지 확인할 수 있습니다. [대시보드 동기화 유지](#대시보드-동기화-유지)를 참조하십시오.

그리드는 다음과 같은 세부 사항도 알아서 처리합니다.

- **많은 값.** 값은 정렬되어 표시됩니다. 열의 값이 화면에 다 들어가지 않을 만큼 많으면 그리드에 "More values than fit here — type to search."라는 메시지가 표시되며, 필터 상자는 열 전체를 검색하고 그룹이 이미 보유한 값은 모두 유지합니다.
- **빈 값.** **빈 값 - 부여된 모든 그룹에 표시** 확인란 하나로 열에 값이 없는 행을 처리할지 결정합니다. 이 확인란을 선택하면 해당 열에 부여가 하나라도 있는 모든 그룹이 그 행을 봅니다.
- **아직 빌드되지 않은 테이블**에는 빈 목록 대신 **먼저 이 테이블을 빌드하십시오(테이블을 만드는 워크플로 실행)** 가 표시됩니다.
- **저장은 화면의 값이 로드될 때까지 기다립니다.** 값소스, 차원 또는 테이블을 바꾸거나 템플릿을 적용한 후 값을 로드하는 동안에는 **저장**이 비활성화되며 "Save is available once this source's values load."라는 도구 설명이 표시됩니다. 로드에 실패하면 그리드가 그 사실을 알리고 소스를 다시 선택하도록 요청하며, 로드에 성공할 때까지는 아무것도 저장되지 않습니다.

### 하나의 열 이름, 모든 테이블

제한은 단일 테이블이 아니라 프로젝트의 열 *이름*에 속합니다. `region`이 행을 제한하기 시작하면 프로젝트에서 `region`이라는 열이 있는 모든 테이블이 PlaidCloud의 자체 쿼리와 대시보드 모두에서 이 제한에 따라 필터링됩니다. 그리드의 **적용 대상** 목록에 해당 테이블이 표시됩니다. 열 이름에 따라 결정되므로 이 목록은 읽기 전용이며, 나중에 같은 열이 있는 테이블을 추가하면 게시되는 즉시 적용 대상에 포함됩니다.

프로젝트에 해당 이름의 열이 있는 테이블이 없으면 **0개 테이블에 적용**이라는 표시와 함께, 테이블이 생길 때까지 제한이 어떤 대시보드도 필터링하지 않는다는 경고가 창에 표시됩니다. 테이블에 열을 추가하거나 열 이름을 바로잡으면 경고가 사라집니다.

<Aside type="caution">
**열 이름은 대소문자와 공백을 포함하여 정확히 일치해야 합니다.** `Region`과 `region`은 서로 다른 이름이며, `region`과 끝에 공백이 있는 `region `도 마찬가지입니다. 선택기에는 실제 열 이름만 표시되므로 이 점은 주로 다른 곳에서 열 이름이 바뀐 경우에 문제가 됩니다. 그런 경우 행 액세스는 아무것도 제한하지 않은 채 넘어가지 않고, 찾은 가장 가까운 열의 이름을 알려 주며 경고합니다.
</Aside>

<Aside type="caution">
**행을 제한하는 테이블을 게시하면 같은 단계에서 해당 대시보드 필터가 설정됩니다.** 대시보드는 게시된 보고용 뷰를 통해 테이블을 읽으므로, 제한된 열이 있는 테이블을 게시하거나 다시 게시하면 PlaidCloud가 게시를 완료하기 전에 그 테이블의 대시보드 필터를 등록합니다. 등록할 수 없으면 게시가 거부되고 해당 시도에서 만들어진 항목은 모두 롤백되므로, 제한된 테이블이 필터 없이 대시보드에 남는 일은 없습니다. 행을 제한하는 프로젝트에서는 *뷰*를 게시할 수 없습니다. 뷰의 쿼리가 제한된 열의 이름을 바꾸거나 그 열에서 파생된 값을 만들 수 있기 때문입니다. [테이블 게시](/ko/guides/data/publish/)를 참조하십시오.
</Aside>

### 제한 중지

그리드의 **제한 중지**는 인라인 확인 후 제한을 제거합니다. 확인 문구는 "Stop restricting rows by ‘region’? Every group's grant on it is removed and everyone sees its rows."이며, 이후 행 액세스에서 "Rows in ‘region’ are no longer restricted."라고 알립니다. 열의 Superset 데이터 세트도 함께 제거되지만, 차트가 아직 사용 중이면 제거되지 않습니다. 이 경우 행 액세스는 데이터 세트가 남아 있다는 사실과 이를 사용하는 차트 수를 알려 줍니다.

행을 제한하는 열은 이름을 바꾸거나 삭제할 수 없습니다. 아키텍트에게는 먼저 행 액세스에서 제한을 중지하라고 안내하고, 그 외 사용자에게는 프로젝트 아키텍트에게 요청하라고 안내합니다.

### 행을 제한하는 프로젝트를 변경할 수 있는 사람

프로젝트의 워크플로, 단계, 사용자 정의 함수는 모든 행을 읽을 수 있는 프로젝트 자체의 서비스 ID로 실행됩니다. 이를 변경할 수 있는 사람은 부여받지 않은 행을 자신이 읽을 수 있는 테이블로 복사하는 단계를 만들 수 있으므로, 프로젝트의 행을 제한하면 프로젝트의 동작을 누가 변경할 수 있는지도 함께 제한됩니다. 프로젝트가 하나 이상의 열을 제한하면 다음이 적용됩니다.

- **자동화는 아키텍트 전용입니다.** 프로젝트 아키텍트와 테넌트 관리자만 워크플로, 단계, 사용자 정의 함수, 일정, 워크플로 및 프로젝트 변수, 알림 이메일 템플릿을 변경할 수 있습니다. 같은 이유로 워크플로 번들 가져오기, Alteryx 워크플로 변환, 프로젝트로의 가져오기·복사·복원, 연결 환경, 기본 문서 계정 또는 ERP 전기 모드 변경도 이들만 할 수 있습니다. 그 외 사용자는 프로젝트의 워크플로를 계속 실행할 수 있어서 **시작**, **중지**, **재개**, **선택한 단계 실행**을 사용할 수 있습니다. 단계 편집기, 워크플로의 작성 컨트롤, UDF 편집기, 일정 양식은 이들에게 읽기 전용으로 열리며, 요청할 아키텍트를 알려 주는 배너가 표시됩니다. 배너 문구는 "This project restricts rows, so only its Architects can change workflows, steps, UDFs, schedules, variables and notify templates. You can still run them."입니다.
- **제한된 열이 읽는 차원은 아키텍트 전용입니다.** 누가 어떤 행을 볼지 결정하는 차원, 즉 제한된 열의 값 소스는 프로젝트 아키텍트 또는 테넌트 관리자와 프로젝트 자체의 워크플로만 변경할 수 있습니다. 여기에는 차원의 노드를 추가, 이동, 이름 변경, 복사, 지우기, 로드, 복원하는 작업과 차원 자체에 대한 작업이 포함됩니다. 그 외 사용자에게는 "This dimension decides who sees which rows of ‘region’, so only a project Architect can change it."라는 안내가 표시됩니다. 어떤 제한도 읽지 않는 차원은 영향을 받지 않습니다.
- **부여 소스 테이블은 아키텍트 전용입니다.** 열의 [부여 소스](#소스-테이블에-부여-바인딩)로 바인딩된 테이블은 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트의 워크플로만 행을 변경하거나 테이블을 삭제할 수 있습니다. 데이터 편집기, 가져오기, 커넥터 로드, API 중 어느 경로를 통하든 마찬가지입니다.
- **프로젝트 복사는 아키텍트 전용이며**, 복사본에는 "This copy is not row-restricted."라고 표시됩니다. 새 프로젝트는 제한을 설정하기 전까지 아무 제한도 갖지 않습니다.
- **이전 버전 복원도 다른 변경과 마찬가지로 하나의 변경입니다.** 프로젝트 자체의 설정이나 위에 나열된 차원을 복원하려면 프로젝트 아키텍트여야 합니다. 복원은 항상 해당 버전이 속한 항목에 적용되므로, 이를 우회하려고 다른 프로젝트를 대상으로 지정할 수 없습니다. [버전 기록](/ko/guides/projects/managing-projects/#버전-기록)을 참조하십시오.
- **제한된 테이블의 데이터 편집**에는 [행 액세스와 데이터 편집기](#행-액세스와-데이터-편집기)에 설명된 대로 아키텍트가 필요합니다.

프로젝트의 첫 번째 열을 제한하기 전에 행 액세스는 영향을 받는 사람을 알려 줍니다. "Restricting rows here means only Architects can change this project's workflows, steps, UDFs, schedules and notify templates. N members can change them today; they will still be able to run them."

예약된 실행을 포함하여 실행은 프로젝트의 서비스 ID로 수행되므로 이전과 똑같이 계속 동작합니다. 실행이 만들어 내는 결과는 아키텍트가 설계한 방식을 따릅니다. 제한된 열이 없는 출력 테이블, 내보내기 파일, 알림 이메일, 로그 줄은 그것을 읽는 사람에 따라 필터링되지 않습니다.

**실행을 시작할 때 지정하는 값.** 워크플로를 실행할 수 있는 사람은 누구나 변수에 자신의 값을 지정하여 워크플로를 시작할 수 있습니다. [App Runner](/ko/guides/workflows/use-converted-alteryx-apps/#app-runner-프런트엔드)는 양식의 응답으로 이 작업을 하며, API와 AI 도구도 할 수 있습니다. 이 값은 해당 실행에만 적용되며 워크플로에 저장되지 않고, 다른 실행, 내보내기, 독자에게는 보이지 않습니다. 실행은 서비스 ID로 수행되므로 이 값이 해당 실행이 읽고 쓰는 내용을 바꿀 수 있습니다. 따라서 워크플로 실행 권한은 신뢰할 수 있는 사람에게만 부여하십시오.

**행을 제한하지 않는 프로젝트.** 이 규칙은 프로젝트가 열을 제한한 이후에만 적용됩니다. 어떤 열도 제한하지 않는 프로젝트에서는 프로젝트의 자동화를 변경할 수 있는 사람이 프로젝트의 서비스 ID로 실행되면서 프로젝트의 액세스를 변경하여 자신을 아키텍트로 만드는 단계나 사용자 정의 함수를 작성할 수 있습니다. 그런 프로젝트는 행 격리를 약속하지 않으므로 의도된 동작입니다. 그런 프로젝트에서는 아키텍트로 신뢰할 수 있는 사람에게만 작성 권한을 주거나, 열을 제한하십시오.

### 대시보드 동기화 유지

행 액세스는 변경 사항이 대시보드로 전달되는 과정의 현재 위치를 그리드와 프로젝트 보안 탭의 **동기화** 열에 표시합니다.

| 상태 | 의미 |
|---|---|
| **대기 중** | 변경 사항이 저장되어 대시보드로 전달되는 중입니다. 보통 약 1분 이내에 사라집니다. |
| **재시도 중** | 전송이 실패하여 다시 시도하고 있습니다. 실패 사유가 상태 옆에 표시되며, **다시 시도**로 즉시 다시 전송할 수 있습니다. |
| **아직 적용되지 않음** | 프로젝트의 제한이 아직 대시보드로 전송되지 않았습니다. |
| **적용됨** | 제한을 대시보드로 보내려는 마지막 시도가 성공했습니다. |
| **대시보드와 동기화됨** | 행 액세스가 대시보드에서 적용 중인 내용과 자신이 기록할 내용을 비교했으며, 둘이 일치합니다. |
| **대시보드와 다름** | 대시보드에서 적용 중인 내용이 행 액세스가 기록할 내용과 다릅니다. Superset에서 규칙이 변경되거나 삭제되었거나, 테이블의 게시된 뷰를 확인할 수 없는 경우입니다. |
| **오류** | 제한을 전송하지 못했습니다. 사유가 상태 옆에 표시됩니다. |

변경 사항이 **적용됨**에 도달하면 그리드는 이를 대시보드와 비교하여 **대시보드와 동기화됨** 또는 **대시보드와 다름**으로 넘어갑니다. **대시보드와 다름**과 **오류** 모두 **다시 시도**를 제공하며, 이를 누르면 프로젝트의 제한을 다시 전송합니다. 상태를 전혀 읽을 수 없으면 그리드에 "Couldn't check sync status."라고 표시됩니다.

테이블 하나가 원인인 **오류**에는 해당 테이블의 이름과 조치 방법이 표시됩니다. 예를 들어 제한된 열 없이 게시된 테이블("Republish or unpublish it."), 또는 제한된 열이 있지만 게시되지 않은 테이블은 게시될 때까지 대시보드가 필터링할 수 없습니다. 테이블을 게시하거나 대신 게시된 테이블에서 열을 제한할 때까지 상태는 **오류**로 유지되며 게시되지 않은 테이블의 이름이 표시됩니다. 이런 테이블이 프로젝트의 나머지 부분을 막지는 않으며, 다른 모든 테이블은 계속 동기화됩니다.

대시보드는 PlaidCloud의 자체 쿼리와 동일한 부여를 따릅니다.

- **해당 열이 있는 게시된 모든 테이블이 필터링됩니다.** 제한을 설정할 때 보고 있던 테이블만 필터링되는 것이 아닙니다.
- **일부 값만 부여된 그룹은 다른 모든 사용자가 모든 행을 보는 경우에도 필터링되며**, 대시보드 데이터 세트가 있는 모든 테이블에 적용됩니다.
- **프로젝트 아키텍트는 모든 행을 봅니다.** 테이블 탐색기와 PlaidCloud의 다른 부분에서와 마찬가지로 대시보드에서도 마찬가지입니다. 이는 프로젝트의 아키텍트 그룹과, 개별 멤버와 공유된 프로젝트의 아키텍트에게 적용됩니다. 아키텍트 액세스를 제거하면 대시보드에 즉시 반영됩니다. 멤버의 역할을 변경하거나, 멤버 또는 그 그룹을 프로젝트에서 제거하거나, 프로젝트의 액세스 유형을 변경하거나, 이전 프로젝트 버전을 복원하거나, 그룹을 삭제하는 경우 모두 해당됩니다.
- **보안 그룹 멤버십 변경은 저절로 대시보드에 반영됩니다.** PlaidCloud에서 그룹에 사람을 추가하거나 제거하는 경우, 멤버를 비활성화하거나 삭제하는 경우, 그룹을 삭제하는 경우, 기본 보안 그룹에 가입하는 새 멤버를 추가하는 경우, 해당 그룹에 값을 부여하는 모든 프로젝트에서 그 사람이 대시보드에서 보는 내용이 약 1분 이내에 업데이트되며, 행 액세스를 다시 열 필요가 없습니다. Keycloak에서 직접 변경하거나 로그인 시 싱글 사인온이 사람을 그룹에 배치하는 등 PlaidCloud 외부에서 이루어진 멤버십 변경은 약 15분 이내에 대시보드에 반영되며, 저장하거나 다시 시도할 필요가 없습니다.

### 차원 부여

값 소스로 **차원**을 사용하면 노드를 선택하여 그 아래의 모든 항목을 부여할 수 있습니다. 부여는 차원을 따라갑니다. 선택한 노드 아래에 추가된 멤버는 차원을 저장한 후 다음 동기화에서 해당 그룹에 부여되고, 그 아래에서 이동되거나 제거된 멤버는 더 이상 부여되지 않으므로 그리드를 다시 열 필요가 없습니다. 그리드를 다시 열면 선택했던 노드가 선택된 상태로 표시됩니다.

선택한 노드 아래의 항목 중 하나라도 선택을 해제하면 노드의 선택이 해제되고, 그룹은 여전히 선택된 멤버만 보유합니다. 그 멤버를 다시 선택해도 노드가 다시 선택되지는 않으며, 노드를 다시 선택하려면 노드 자체의 확인란을 클릭하십시오. **붙여넣기**, **모두 선택**, **선택 반전**은 멤버만 선택하며 노드는 선택하지 않습니다.

이름을 행 액세스 값으로 사용할 수 없는 차원 멤버는 저장할 때 해당 멤버의 이름과 함께 거부됩니다. 이런 멤버가 나중에 나타나면 그 멤버의 행은 누구에게도 부여되지 않으며, 동기화 상태에 해당 멤버의 이름이 표시됩니다. "Dimension ‘…’ member ‘…’ cannot be used as a row access value, so its rows are not granted. Rename it in the dimension."

### 소스 테이블에 부여 바인딩

값을 직접 선택하는 대신, 제한된 열을 이미 답을 가지고 있는 소스 테이블, 즉 그룹과 그 그룹이 볼 수 있는 값이 한 행씩 있는 테이블에 연결할 수 있습니다. 먼저 그리드에서 열을 제한한 다음, 열, 소스 테이블, 소스 테이블의 그룹 열과 값 열을 지정하는 [**행 액세스 설정**](/ko/reference/workflow-steps/tables/table-set-row-access/) 워크플로 단계를 추가하십시오. 이 단계를 처음 실행하면 열이 해당 테이블에 바인딩되고, 열에 직접 설정한 부여는 지워지며 부여는 테이블의 행으로 설정됩니다.

바인딩되면 해당 열은 **소스 소유**가 됩니다. 행 액세스 그리드에는 소스 테이블 이름이 적힌 배지와 함께 잠긴 상태로 표시되며, **바인딩 제거**를 클릭하기 전까지는 부여를 직접 편집할 수 없습니다.

이후 이 단계를 실행할 때마다 소스 테이블을 다시 읽고 부여를 다시 적용합니다. 해당 테이블을 로드하거나 새로 고치는 워크플로 다음에 실행되도록 일정을 잡으면, 소스 데이터에서 그룹이 추가, 제거 또는 재할당될 때 아무도 그리드를 직접 편집하지 않아도 다음 실행에서 행 액세스에 반영됩니다.

소스 테이블이 누가 무엇을 볼지 결정하므로, 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트 자체의 워크플로만 해당 테이블의 행을 변경하거나 테이블을 삭제할 수 있습니다. 그 외 사용자에게는 "This table supplies the row access grants for ‘region’, so only a project Architect can change its rows or delete it."라는 안내가 표시됩니다.

### 제한 템플릿

동일한 값 소스, 값 유형, 빈 값 설정 등 재사용하려는 제한 구성을 만들어 두었다면 열마다 다시 만드는 대신 한 번 저장해 두었다가 필요한 곳에 적용하십시오.

- 열려 있는 행 액세스 화면의 **템플릿으로 저장…** 은 현재 열의 구성을 이름이 있는 테넌트 수준 템플릿으로 저장합니다. 구성만 저장되며 부여는 함께 저장되지 않습니다.
- 다른 프로젝트의 열에서 **템플릿 적용**을 하면 해당 열이 템플릿의 구성으로 시작하며, 모든 그룹의 부여는 비어 있어 직접 채울 수 있습니다.

프로젝트 아키텍트라면 누구나 템플릿을 저장하고 적용할 수 있습니다. 템플릿은 테넌트 전체에서 공유되므로 이름 바꾸기(**이름 바꾸기…**)와 삭제(**삭제**)에는 테넌트 관리자가 필요합니다. 템플릿을 삭제해도 그것을 적용했던 열은 제한된 상태 그대로 유지됩니다.

<Aside type="note">
템플릿은 링크가 아니라 복사본입니다. 템플릿을 나중에 편집해도 이미 그것을 적용한 열은 바뀌지 않습니다. 열을 이후 수정본에 맞추려면 템플릿을 다시 적용하십시오.
</Aside>

### SSO 그룹 속성의 부여

열은 PlaidCloud 대신 ID 공급자에서 부여를 가져올 수도 있습니다. 프로젝트 아키텍트가 행 액세스에서 **Accept row-access grants from SSO group attributes**를 사용하도록 설정하여 열을 옵트인합니다.

이 기능을 사용하도록 설정하면 보안 그룹의 Keycloak 속성 `row_access.<column>`이 해당 그룹이 그 열을 통해 볼 수 있는 값을 설정합니다. Keycloak에서 그룹에 속성을 설정하면 PlaidCloud가 프로젝트에 이미 액세스할 수 있는 모든 그룹에 대해 이를 자동으로 가져옵니다. 행 액세스 자체에서는 더 구성할 것이 없으며, 부여는 PlaidCloud의 자체 쿼리와 Superset 대시보드 모두에서 동기화된 상태로 유지됩니다.

<Aside type="caution">
이는 이미 프로젝트에 접근할 수 있는 그룹에만 값을 부여합니다. 프로젝트 액세스가 없는 그룹에 `row_access.region`을 추가해도, 그 그룹에 프로젝트 액세스도 부여하기 전까지는 아무것도 부여되지 않습니다.
</Aside>

### 저장하기 전 미리 보기

행 액세스는 변경 사항을 확정하기 전에 그것이 무엇을 의미하는지 보여 줍니다.

- **다음 사용자로 미리 보기** 바닥글에는 그룹이 전체 중 테이블의 몇 개 행을 보게 되는지와 해당 행의 샘플이 표시됩니다. 그리드에서 아무 그룹이나 선택하여 미리 볼 수 있습니다. 미리 보기는 저장한 후 새로 고쳐집니다.
- 저장하기 전에 행 액세스는 다시 살펴볼 만한 사항을 경고합니다. 선택된 항목이 없는 그룹(**그 외 모든 사용자** 설정에 따라 모든 행을 보는지 아니면 하나도 보지 못하는지 포함), 프로젝트 액세스가 있지만 어떤 그룹의 부여에도 포함되지 않는 멤버, 해당 열의 값이 비어 있고(`NULL`) 어떤 그룹에도 부여되지 않은 행이 그 대상입니다.

### 제한된 멤버가 보는 내용

제한된 멤버가 이름으로 테이블을 읽는 모든 곳, 즉 테이블 탐색기의 그리드, 열 패싯과 다운로드, 테이블 다운로드 대화 상자, 뷰어로서 읽는 앱과 도구, 대시보드에서는 자신의 행만 표시됩니다. 보고 있는 그리드가 사용자의 부여에 따라 필터링된 경우 테이블 탐색기는 도구 모음에 **액세스 권한에 따라 행이 제한됨**을 표시하며, 필터링될 다운로드를 시작할 때에도 "Rows limited by your access."라는 안내가 표시됩니다. 모든 행을 읽는 아키텍트에게는 두 안내 모두 표시되지 않습니다.

### 행 액세스와 직접 작성하는 쿼리

행 액세스는 정의된 대상 테이블을 필터링하여 그룹이 볼 수 있는 행을 제한합니다. 사용자가 직접 작성한 쿼리는 필터를 붙일 단일 테이블이 없습니다. 쿼리는 원하는 만큼 많은 테이블을 조인하거나 결합하거나 중첩할 수 있기 때문입니다. 따라서 행을 제한하는 프로젝트에서 PlaidCloud는 검증되지 않은 행을 반환하지 않도록 호출자가 제공한 쿼리의 실행을 거부합니다.

이는 직접 작성한 SQL을 통한 읽기, 직접 작성한 SQL의 결과를 파일이나 다른 데이터베이스로 내보내기, 팬아웃 단계의 "Test row 1" 미리 보기에 행 조건을 입력하는 경우에 적용됩니다. 앱과 도구가 데이터를 읽는 일반적인 방법인 이름으로 테이블을 읽는 경우에는 적용되지 **않습니다**. 이런 읽기는 부여를 적용하고 뷰어가 볼 수 있는 행을 반환합니다. 단일 테이블에 대한 일반 쿼리로 작성된 열 패싯도 이름으로 읽는 것이므로 거부되지 않고 멤버 본인의 값을 반환합니다.

거부된 사용자에게는 어떤 프로젝트였는지가 안내되며 이름으로 읽는 방법이 소개됩니다. 아키텍트는 이미 모든 제한된 열의 모든 값을 자신에게 부여할 수 있으므로, 프로젝트 아키텍트는 쿼리를 작성한 그대로 실행하고 그 결과를 어떤 형식으로든 내보낼 수 있습니다.

스프레드시트 가져오기는 그 자체로는 직접 작성한 쿼리가 아닙니다. 일반적인 파일 가져오기는 제한된 데이터를 전혀 읽지 않고 업로드한 파일로 프로젝트 자체의 새 테이블만 만들므로 행 액세스의 영향을 받지 않습니다. 예외는 데이터 프로젝션을 호출자가 제공하는 가져오기, 즉 열별 식이나 동적 Excel 매핑입니다. 대화형 가져오기 화면에서는 이런 항목이 위의 자유 형식 SQL 화면과 같은 방식으로 거부되며 프로젝트 아키텍트가 필요합니다. 호출자가 제공한 프로젝션이 다른 테이블을 읽을 수 있기 때문입니다. 워크플로에서 실행하는 가져오기는 프로젝트 자체의 서비스 ID로 실행되므로 어느 쪽이든 영향을 받지 않습니다.

<Aside type="caution">
프로젝트의 첫 번째 열을 제한하면 그 프로젝트를 사용하는 모든 사람에게 이 동작이 바뀝니다. 해당 프로젝트의 Panel 앱, 노트북 또는 통합이 직접 구성한 SQL로 데이터를 읽는다면, 제한하기 전에 이름으로 테이블을 읽도록 전환하십시오. 그렇지 않으면 아키텍트가 아닌 모든 사용자에게서 작동하지 않게 됩니다.
</Aside>

### 행 액세스와 데이터 편집기

데이터 편집기는 테이블을 직접 읽고 쓰므로 행 액세스는 양쪽 모두에 적용됩니다.

제한된 테이블을 데이터 편집기에서 열면 보안 그룹이 부여받은 행만 표시됩니다. 이는 대시보드에서도 적용되는 동일한 필터이며, 제한된 열이 그리드에 표시된 열에 포함되지 않아도 적용됩니다.

편집 내용을 저장하려면 프로젝트에 대한 **아키텍트** 권한이 필요합니다. 저장은 테이블의 행을 읽지 않고 통째로 교체하며 행 단위로 필터링되지 않으므로, 제한된 테이블의 데이터 편집은 읽기가 아니라 작성 작업으로 취급되어 아키텍트가 아닌 사용자에게는 아키텍트 권한이 필요하다고 안내됩니다. 제한된 열이 없는 테이블과 행을 제한하지 않는 프로젝트는 이전처럼 편집됩니다.

### 행 수와 테이블 크기

테이블의 행 수와 저장소 크기는 사용자가 볼 수 있는 행이 아니라 테이블 전체를 나타내므로, 제한된 읽기 권한자에게 부여받은 범위 밖에 행이 몇 개나 있는지 알려 주게 됩니다. 행을 제한하는 프로젝트에서는 읽기가 필터링되는 모든 사용자에게 프로젝트의 어떤 테이블에 대해서도 행 수나 크기가 표시되지 않습니다. 테이블 목록, 검색, 테이블 세부 정보, 스냅샷은 물론 MCP로 연결된 AI 어시스턴트와 AI 도구에서도 마찬가지입니다. 여기에는 제한된 열이 없는 테이블을 포함하여 프로젝트의 모든 테이블이 해당됩니다. 홈, 프로젝트 목록과 검색, 프로젝트 세부 정보에 표시되는 전체 행 수와 크기 등 프로젝트 자체의 합계도 이들에게는 숨겨집니다.

워크플로 실행 기록에도 같은 규칙이 적용됩니다. 각 실행과 단계가 기록한 읽은 행 수와 쓴 행 수도 테이블 전체를 설명하므로, 같은 읽기 권한자에게는 워크플로와 단계의 실행 기록, 그리고 MCP로 연결된 AI 어시스턴트와 AI 도구에서 해당 수치가 비어 있습니다. 이들에 대해서는 [Weave](/ko/guides/ai-assistant/weave-findings/)가 이전 실행과 달라진 행 수나 빈 값을 확인하지 않습니다. 결과 항목 자체가 전체 테이블의 행 수가 바뀌었음을 알려 주게 되기 때문입니다.

프로젝트 아키텍트에게는 이전처럼 수치가 표시되며, 행을 제한하지 않는 프로젝트의 모든 사용자에게도 마찬가지입니다.

### 멤버가 볼 수 있는 내용 확인

그룹이 부여받은 내용이 아니라 특정 사람이 볼 수 있는 내용을 확인하려면 **Identity → 멤버**를 열고 멤버를 선택한 다음 해당 멤버의 **행 액세스** 탭을 여십시오. **유효 액세스** 열에는 제한된 모든 프로젝트와 열에 대해, 멤버가 속한 모든 그룹을 합쳐서 그 멤버가 볼 수 있는 값이 나열됩니다. 여기에는 SSO 그룹 속성의 부여와, 그룹의 부여에 포함된 빈(`NULL`) 행이 포함됩니다. 프로젝트 아키텍트는 모든 행을 읽으므로 **모든 행 볼 수 있음(Architect)** 으로 표시됩니다. PlaidCloud의 자체 쿼리가 적용하는 것과 동일한 결과이므로, 지원 업무와 문제가 보고되기 전에 변경 사항이 의도한 대로 동작했는지 확인하는 데 유용합니다.

### 더 명확한 오류

행 액세스가 작업을 차단하는 경우, 즉 행을 제한하는 프로젝트에서 직접 작성한 쿼리, 아키텍트 없는 편집, 자동화나 차원 또는 부여 소스 테이블의 변경 등 위에 설명한 여러 경우에는 일반적인 실패 메시지 대신 무엇이 제한되어 있고 다음에 무엇을 해야 하는지가 메시지에 표시되며, 요청할 아키텍트도 함께 안내됩니다.

### 행 액세스는 감사됩니다

열의 제한 설정 또는 해제와 그룹의 부여 편집은 모두 해당 프로젝트의 [프로젝트 로그](/ko/get-started/tutorials/collaborate-versions-and-sharing/#프로젝트-로그-읽기)에 항목을 기록하며, 누가 언제 변경했는지가 남습니다. 확인하려면 프로젝트에서 **Analyze → 프로젝트 → 로그**를 여십시오. 이 기록을 얻기 위해 행 액세스에서 켜야 할 설정은 없으며, 프로젝트에 대해 추적되는 다른 모든 변경과 같은 방식으로 기록됩니다.

## 기본 보안 그룹 설정


새 멤버를 추가하는 데 드는 시간을 줄이려면 기본 보안 그룹 집합을 지정하십시오. 그러면 각 사람을 수동으로 할당하지 않아도 새 멤버에게 기본 보안 그룹 집합이 제공됩니다. 이 설정은 새 보안 그룹을 추가할 때 보안 그룹 창 맨 아래의 “Assign to New Users by Default” 확인란을 선택하면 사용할 수 있습니다.



## 보안 감사 수행


보안 감사 기능을 사용하면 모든 멤버와 그룹에 걸친 그룹 멤버십을 확인할 수 있습니다.



**보안 감사를 수행하려면 다음과 같이 합니다.**


1. Identity를 엽니다.
2. “보안” 탭을 선택합니다.
3. 드롭다운 메뉴에서 “보안 그룹 감사”를 클릭합니다.

PlaidCloud의 모든 테이블은 CSV 파일 형식으로 내보낼 수 있으므로, 그룹과 멤버의 연결 정보를 PlaidCloud 밖에서 과거 기록용으로 검토하거나 오프라인에서 가볍게 살펴볼 수도 있습니다.



**“보안 그룹 감사” 양식에서 내보내려면 다음과 같이 합니다.**


1. Identity를 엽니다.
2. “보안” 탭을 선택합니다.
3. 드롭다운 메뉴에서 “보안 그룹 감사”를 클릭합니다.
4. 테이블에서 “사용자 이름” 오른쪽 끝에 있는 작은 아이콘을 클릭합니다.
5. 원하는 방식에 따라 “CSV 내보내기” 또는 “XLXS 내보내기”를 클릭합니다.

## 사용 가능한 권한 설정 보기


워크스페이스에서 사용하는 각 애플리케이션에는 사용할 수 있는 고유한 권한이 있습니다. 보안 그룹 권한은 이러한 애플리케이션 권한을 기반으로 합니다.


각 애플리케이션에 사용할 수 있는 전체 권한 목록은 보안 빈에서 확인할 수 있습니다.



**보안 빈에 액세스하려면 다음과 같이 합니다.**


1. Identity를 엽니다.
2. “보안”을 선택합니다.
3. 드롭다운 메뉴에서 “보안 빈”을 클릭합니다.

각 애플리케이션의 자세한 보안 설정을 보려면 맨 왼쪽의 태그 아이콘을 선택하십시오.



사용 가능한 보안 설정에 대한 이 정보는 참고용입니다. 권한 관리에 대한 자세한 내용은 위의 보안 그룹 관리 섹션을 참조하십시오.
