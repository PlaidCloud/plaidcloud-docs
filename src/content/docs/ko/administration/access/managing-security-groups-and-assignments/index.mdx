PlaidCloud의 보안 및 액세스 관리는 간단합니다. 멤버가 속한 그룹에 따라 멤버의 액세스가 허용되거나 거부됩니다. 멤버의 보안 연결을 추가하거나 변경하는 작업도 쉽게 사용자 지정할 수 있습니다.

<Aside>워크스페이스마다 보안 그룹을 제한 없이 만들 수 있지만, 보안 관리를 쉽게 하려면 그룹 수를 최소화하는 것이 좋습니다.</Aside>



## 보안 그룹 관리


보안 그룹은 추가, 업데이트 또는 삭제할 수 있습니다.



**보안 그룹을 관리하려면 다음을 수행합니다.**


1. Identity를 엽니다.
2. “Security” 탭을 선택합니다.
3. 드롭다운 메뉴에서 “Security Groups”를 클릭합니다(기존 그룹이 있는 양식이 표시됩니다).
4. 그룹을 추가하려면 “Create Security Group”을 클릭합니다.
5. 그룹의 권한을 편집하려면 가장 왼쪽 아이콘을 클릭합니다.

**그룹 멤버를 관리하려면 다음을 수행합니다.**


1. Identity를 엽니다.
2. “Security” 탭을 선택합니다.
3. 드롭다운 메뉴에서 “Security Groups”를 클릭합니다.
4. 멤버 아이콘을 클릭합니다.
5. 원하는 멤버를 “Unassigned Members” 열에서 “Assigned Members” 열로 끌어다 놓습니다. 멤버를 제거하려면 반대로 끌어다 놓습니다.

<Aside>“Assigned Members” 열을 비워 둔 채 저장하면 변경 사항이 없으며, 그렇다는 메시지가 표시됩니다. 그룹을 모든 사람에게서 해제하려면 멤버 목록을 비우지 말고 그룹의 권한을 제거하거나 그룹을 삭제하십시오.</Aside>

<Aside>그룹에 [행 액세스](#행-액세스-관리)로 행이 부여된 경우, 멤버십 변경은 약 1분 이내에 대시보드에 반영됩니다. 그룹에 추가한 사용자는 대시보드에서 해당 그룹의 행을 보게 되고, 제거한 사용자는 더 이상 보지 못합니다. 멤버를 사용 중지하거나 삭제하는 경우와 그룹을 삭제하는 경우에도 같은 방식으로 적용됩니다.</Aside>

<Aside type="caution">직접 부여할 수 없는 권한은 그룹의 권한 매트릭스를 저장할 때 그대로 유지되며 매트릭스에 표시되지 않습니다. 해당 권한을 변경해야 하면 그 권한을 가진 사람에게 요청하십시오. 매트릭스에서는 본인이 제어할 수 있는 권한만 편집할 수 있습니다.</Aside>

## 행 액세스 관리

행 액세스는 한 열의 값을 기준으로 보안 그룹이 테이블에서 볼 수 있는 행을 제한합니다. 예를 들어 `region` 열로 액세스를 제한하고, `East`와 `Central`을 부여받은 그룹은 해당 값이 있는 행만 볼 수 있게 할 수 있습니다. 프로젝트와 열에 관한 모든 작업, 즉 열 선택, 값의 출처 선택, 어떤 그룹이 무엇을 볼지 결정하는 작업이 하나의 화면에서 이루어지며, 저장하면 즉시 적용됩니다.

행 액세스를 설정하고 변경하려면 프로젝트 아키텍트 또는 테넌트 관리자여야 합니다. 그 외 사용자가 프로젝트의 Security 탭을 열면 행 액세스는 아키텍트 전용이라는 안내가 표시되며, 아래의 진입점도 나타나지 않습니다.

### 행 액세스 열기

모든 진입점은 동일한 행 액세스 화면을 엽니다.

- **테이블 탐색기의 도구 모음**에는 **행 액세스** 버튼이 있으며, 테이블에서 이미 행을 제한하고 있으면 배지가 표시됩니다. 테이블에 제한된 열이 있으면 첫 번째 제한 열에서 열리며, 테이블의 다른 열로 전환할 수 있습니다.
- **열의 패싯 메뉴**에는 **이 열로 행 제한…** 항목이 있으며, 이 항목은 해당 열에서 행 액세스를 엽니다. 이미 행을 제한하는 열에서는 항목이 **이 열로 제한된 행 — 편집…** 으로 표시됩니다.
- **프로젝트의 Security 탭**에는 프로젝트의 제한된 열이 모두 나열되며, 각 열이 적용되는 테이블, 부여를 보유한 그룹, **동기화** 상태가 함께 표시됩니다. 열을 선택하여 편집하거나 **열 제한…** 버튼을 클릭하여 새로 시작하십시오. 테이블을 선택한 다음 열을 선택합니다. 이미 행을 제한하는 열에는 잠금 표시가 붙습니다.
- 멤버의 **행 액세스** 탭이 있는 **Identity → Member**와 그룹의 행 액세스 요약이 있는 **Identity → Security → 보안 그룹**. **행 액세스 열기**(또는 **편집**)는 선택한 열을 열고, **추가**는 해당 행의 프로젝트에서 다른 열을 제한합니다.

열에서 열면 화면이 해당 열에 고정됩니다. **열 제한…** 버튼 또는 **추가**로 열면 열을 선택할 수 있습니다.

### 행 액세스 그리드

열을 기준으로 테이블을 제한하려면 다음을 수행합니다.

1. 위의 진입점 중 하나에서 행 액세스를 열고, 열 없이 들어왔다면 열을 선택합니다. 선택기에는 자유 텍스트가 아니라 테이블의 실제 열이 표시됩니다.
2. **값 소스**를 선택합니다. **열**(테이블 열의 고유 값), **차원**(차원의 노드) 또는 **목록**(직접 입력하는 값) 중에서 선택합니다. 값 유형은 열의 데이터 유형을 따릅니다.
3. 보안 그룹마다 해당 그룹이 볼 수 있는 값을 선택합니다. 그리드에는 프로젝트에 액세스할 수 있는 그룹과 해당 열에 이미 부여를 보유한 모든 그룹이 나열됩니다.
4. **Everyone else**를 **sees all rows** 또는 **sees no rows**로 설정합니다. 그리드에서 선택된 항목이 없는 모든 그룹에 적용됩니다.
5. **저장**을 클릭합니다.

저장은 즉시 반영됩니다. PlaidCloud 자체 쿼리는 변경 사항을 바로 따르고 Superset 대시보드는 약 1분 이내에 따릅니다. 변경 사항을 적용하는 별도 단계나 승인 대화 상자는 없습니다. 화면의 동기화 상태에서 변경 사항이 어디까지 반영되었는지 확인할 수 있습니다. [대시보드 동기화 유지](#대시보드-동기화-유지)를 참조하십시오.

그리드는 다음과 같은 세부 사항도 알아서 처리합니다.

- **많은 값.** 값은 정렬됩니다. 열에 표시할 수 있는 수보다 많은 값이 있으면 그리드에 "More values than fit here — type to search."라고 표시되며, 필터 상자는 열 전체를 검색하고 그룹이 이미 보유한 모든 값을 유지합니다.
- **빈 값.** **빈 값 - 부여된 모든 그룹에 표시** 확인란 하나로 열에 값이 없는 행을 처리할지 결정합니다. 이를 선택하면 해당 열에 부여가 하나라도 있는 모든 그룹이 그 행을 봅니다.
- **아직 빌드되지 않은 테이블**은 빈 목록 대신 **먼저 이 테이블을 빌드하십시오(테이블을 만드는 워크플로 실행)** 라고 표시합니다.
- **저장은 화면의 값이 로드될 때까지 기다립니다.** 값 소스, 차원 또는 테이블을 전환하거나 템플릿을 적용한 후 값을 로드하는 동안에는 **저장**이 비활성화되며 "Save is available once this source's values load."라는 툴팁이 표시됩니다. 로드에 실패하면 그리드에서 알려 주고 소스를 다시 선택하도록 안내하며, 로드에 성공할 때까지 아무것도 저장되지 않습니다.

### 하나의 열 이름, 모든 테이블

제한은 단일 테이블이 아니라 프로젝트의 열 *이름*에 속합니다. `region`이 행을 제한하면 프로젝트에서 `region`이라는 이름의 열이 있는 모든 테이블이 PlaidCloud 자체 쿼리와 대시보드 모두에서 해당 제한으로 필터링됩니다. 그리드의 **Applies to** 목록에 해당 테이블이 표시됩니다. 열 이름으로 결정되므로 이 목록은 읽기 전용이며, 나중에 같은 열이 있는 테이블을 추가하면 게시되는 즉시 적용됩니다.

프로젝트에 해당 이름의 열이 있는 테이블이 없으면 **Applies to 0 tables**가 표시될 뿐 아니라, 테이블이 생기기 전까지는 제한이 어떤 대시보드도 필터링하지 않는다는 경고도 창에 표시됩니다. 테이블에 열을 추가하거나 열 이름을 바로잡으면 경고가 사라집니다.

<Aside type="caution">
**열 이름은 대소문자와 공백까지 정확히 일치해야 합니다.** `Region`과 `region`은 서로 다른 이름이며, `region`과 끝에 공백이 있는 `region `도 마찬가지입니다. 선택기에는 실제 열 이름만 표시되므로 이 문제는 다른 곳에서 열 이름이 바뀐 경우에 주로 해당합니다. 이때 행 액세스는 아무것도 제한하지 않은 채 넘어가지 않고, 찾은 가장 가까운 열의 이름을 알려 주며 경고합니다.
</Aside>

<Aside type="caution">
**행을 제한하는 테이블을 게시하면 같은 단계에서 대시보드 필터도 설정됩니다.** 대시보드는 게시된 보고용 뷰를 통해 테이블을 읽기 때문에, 제한된 열이 있는 테이블을 게시하거나 다시 게시하면 PlaidCloud는 게시가 완료되기 전에 해당 테이블의 대시보드 필터를 등록합니다. 등록할 수 없으면 게시가 거부되고 해당 시도에서 만든 항목은 롤백되므로, 제한된 테이블이 필터링되지 않은 채 대시보드에 남는 일은 없습니다. 행을 제한하는 프로젝트에서는 *뷰*를 게시할 수 없습니다. 뷰의 쿼리가 제한된 열의 이름을 바꾸거나 새로 파생시킬 수 있기 때문입니다. [테이블 게시](/ko/guides/data/publish/)를 참조하십시오.
</Aside>

### 제한 중지

그리드의 **제한 중지**는 인라인 확인 후 제한을 제거합니다. 확인 메시지는 "Stop restricting rows by ‘region’? Every group's grant on it is removed and everyone sees its rows."이며, 이후 행 액세스는 "Rows in ‘region’ are no longer restricted."라고 알려 줍니다. 열의 Superset 데이터 세트도 함께 제거됩니다. 단, 차트가 아직 사용 중이면 제거되지 않으며, 이 경우 행 액세스는 데이터 세트가 남아 있다는 사실과 이를 사용하는 차트의 수를 알려 줍니다.

행을 제한하는 열은 이름을 바꾸거나 삭제할 수 없습니다. 아키텍트에게는 먼저 행 액세스에서 제한을 중지하라고 안내하며, 그 외 사용자에게는 프로젝트 아키텍트에게 요청하라고 안내합니다.

### 행을 제한하는 프로젝트를 변경할 수 있는 사람

프로젝트의 워크플로, 단계, 사용자 정의 함수는 프로젝트 자체의 서비스 ID로 실행되며 이 ID는 모든 행을 읽습니다. 이를 변경할 수 있는 사람이라면 부여받지 않은 행을 자신이 읽을 수 있는 테이블로 복사하는 단계를 만들 수 있으므로, 프로젝트에서 행을 제한하면 프로젝트의 작업 내용을 변경할 수 있는 사람도 제한됩니다. 프로젝트가 하나 이상의 열을 제한하면 다음이 적용됩니다.

- **자동화는 아키텍트 전용입니다.** 프로젝트 아키텍트와 테넌트 관리자만 워크플로, 단계, 사용자 정의 함수, 일정, 워크플로 및 프로젝트 변수, 알림 이메일 템플릿을 변경할 수 있습니다. 같은 이유로 워크플로 번들 가져오기, Alteryx 워크플로 변환, 프로젝트로의 가져오기, 복사 또는 복원, 프로젝트의 연결 환경, 기본 문서 계정 또는 ERP 전기 모드 변경도 마찬가지입니다. 그 외 사용자는 여전히 프로젝트의 워크플로를 실행할 수 있습니다. **시작**, **중지**, **재개**, **선택한 단계 실행**은 계속 사용할 수 있습니다. 단계 편집기, 워크플로의 작성 컨트롤, UDF 편집기, 일정 양식은 이들에게 읽기 전용으로 열리며, 요청할 아키텍트를 알려 주는 배너가 표시됩니다. "This project restricts rows, so only its Architects can change workflows, steps, UDFs, schedules, variables and notify templates. You can still run them."
- **제한된 열이 읽는 차원은 아키텍트 전용입니다.** 어떤 사용자가 어떤 행을 볼지 결정하는 차원, 즉 제한된 열의 값 소스는 프로젝트 아키텍트 또는 테넌트 관리자와 프로젝트 자체의 워크플로만 변경할 수 있습니다. 여기에는 노드의 추가, 이동, 이름 바꾸기, 복사, 지우기, 로드, 복원과 차원 자체가 포함됩니다. 그 외 사용자에게는 "This dimension decides who sees which rows of ‘region’, so only a project Architect can change it."라고 안내합니다. 어떤 제한도 읽지 않는 차원은 영향을 받지 않습니다.
- **부여 소스 테이블은 아키텍트 전용입니다.** 열의 [부여 소스](#소스-테이블에-부여-바인딩)로 바인딩된 테이블은 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트의 워크플로만 행을 변경하거나 테이블을 삭제할 수 있습니다. 데이터 편집기, 가져오기, 커넥터 로드, API 모두 마찬가지입니다.
- **프로젝트 복사는 아키텍트 전용이며**, 복사본에는 "This copy is not row-restricted."라고 표시됩니다. 새 프로젝트는 제한을 설정하기 전까지 어떤 제한도 갖지 않습니다.
- **이전 버전 복원도 다른 변경과 같은 변경입니다.** 프로젝트 자체 설정이나 위에 나열한 차원을 복원하려면 프로젝트 아키텍트여야 합니다. 복원은 항상 해당 버전이 속한 항목에 적용되므로 이를 우회하기 위해 다른 프로젝트를 지정할 수 없습니다. [버전 기록](/ko/guides/projects/managing-projects/#버전-기록)을 참조하십시오.
- **제한된 테이블의 데이터 편집**에는 [행 액세스와 데이터 편집기](#행-액세스와-데이터-편집기)에 설명된 대로 아키텍트가 필요합니다.

프로젝트에서 첫 번째 열을 제한하기 전에 행 액세스는 영향을 받는 대상을 알려 줍니다. "Restricting rows here means only Architects can change this project's workflows, steps, UDFs, schedules and notify templates. N members can change them today; they will still be able to run them."

실행은 예약된 실행을 포함해 프로젝트의 서비스 ID로 실행되므로 이전과 똑같이 계속 작동합니다. 실행 결과는 아키텍트가 설계한 방식을 따릅니다. 제한된 열이 없는 출력 테이블, 내보내기 파일, 알림 이메일, 로그 줄은 읽는 사람에 따라 필터링되지 않습니다.

**실행 시작 시 지정하는 값.** 워크플로를 실행할 수 있는 사람은 누구나 변수에 자신의 값을 지정하여 시작할 수 있습니다. [앱 러너](/ko/guides/workflows/use-converted-alteryx-apps/#app-runner-프런트엔드)는 양식의 응답으로 이를 수행하며, API와 AI 도구도 가능합니다. 이 값은 해당 실행에만 유효하며 워크플로에 저장되지 않고 다른 실행, 내보내기, 읽는 사람에게는 보이지 않습니다. 실행은 서비스 ID로 이루어지므로 이 값이 해당 실행이 읽고 쓰는 내용을 바꿀 수 있습니다. 따라서 워크플로를 실행할 권한은 신뢰할 수 있는 사람에게만 부여하십시오.

**행을 제한하지 않는 프로젝트.** 이 규칙은 프로젝트가 열을 제한한 이후에만 적용됩니다. 행을 제한하지 않는 프로젝트에서는 프로젝트 자동화를 변경할 수 있는 사람이면 누구나, 프로젝트의 서비스 ID로 실행되면서 프로젝트의 액세스를 변경하여 자신을 아키텍트로 만드는 단계나 사용자 정의 함수를 작성할 수 있습니다. 이는 의도된 동작입니다. 이러한 프로젝트는 행 격리를 보장하지 않습니다. 이런 프로젝트에서는 작성 권한을 아키텍트로 신뢰할 수 있는 사람에게만 부여하거나, 열을 제한하십시오.

### 대시보드 동기화 유지

행 액세스는 변경 사항이 대시보드로 가는 과정에서 어디에 있는지를 그리드와 프로젝트 Security 탭의 **동기화** 열에 표시합니다.

| 상태 | 의미 |
|---|---|
| **대기 중** | 변경 사항이 저장되어 대시보드로 전송되는 중입니다. 보통 약 1분 이내에 해소됩니다. |
| **재시도 중** | 전송에 실패하여 다시 시도하는 중입니다. 실패 이유가 상태 옆에 표시되며, **다시 시도**로 즉시 다시 전송할 수 있습니다. |
| **아직 적용되지 않음** | 프로젝트의 제한이 아직 대시보드로 전송되지 않았습니다. |
| **적용됨** | 제한을 대시보드로 보내려는 마지막 시도가 성공했습니다. |
| **대시보드와 동기화됨** | 행 액세스가 대시보드가 적용하는 내용과 자신이 기록할 내용을 비교했고 두 내용이 일치합니다. |
| **대시보드와 다름** | 대시보드가 행 액세스가 기록할 내용을 적용하지 않습니다. Superset에서 규칙이 변경되거나 삭제되었거나, 테이블의 게시된 뷰를 확인할 수 없는 경우입니다. |
| **오류** | 제한 전송에 실패했습니다. 이유가 상태 옆에 표시됩니다. |

변경 사항이 **적용됨**에 도달하면 그리드는 이를 대시보드와 비교하여 **대시보드와 동기화됨** 또는 **대시보드와 다름**으로 넘어갑니다. **대시보드와 다름**과 **오류**는 모두 **다시 시도**를 제공하며, 이를 누르면 프로젝트의 제한이 다시 전송됩니다. 상태를 전혀 읽을 수 없으면 그리드에 "Couldn't check sync status."라고 표시됩니다.

테이블 하나 때문에 발생한 **오류**에는 테이블 이름과 조치 방법이 표시됩니다. 예를 들어 제한된 열 없이 게시된 테이블("Republish or unpublish it."), 또는 제한된 열이 있으나 게시되지 않은 테이블이며, 게시되기 전까지 대시보드는 이를 필터링할 수 없습니다. 게시하거나 게시된 테이블의 열을 대신 제한할 때까지 상태는 **오류**로 유지되며 게시되지 않은 테이블의 이름이 표시됩니다. 이런 테이블이 프로젝트의 나머지를 지연시키지는 않으며, 다른 모든 테이블은 계속 동기화됩니다.

대시보드는 PlaidCloud 자체 쿼리와 같은 부여를 따릅니다.

- **해당 열이 있는 게시된 모든 테이블이 필터링됩니다.** 제한을 설정할 때 보고 있던 테이블만 필터링되는 것이 아닙니다.
- **일부 값만 부여받은 그룹은 다른 모든 사람이 모든 행을 보더라도 필터링됩니다.** 대시보드 데이터 세트가 있는 모든 테이블에 적용됩니다.
- **보안 그룹 멤버십 변경은 저절로 대시보드에 반영됩니다.** PlaidCloud에서 그룹에 사용자를 추가하거나 제거하는 경우, 멤버를 사용 중지하거나 삭제하는 경우, 그룹을 삭제하는 경우, 기본 보안 그룹에 가입하는 새 멤버를 추가하는 경우, 누구도 행 액세스를 다시 열 필요 없이 해당 그룹에 값을 부여하는 모든 프로젝트에서 대시보드에 표시되는 내용이 약 1분 이내에 업데이트됩니다. Keycloak에서 직접 수행하거나 로그인 시 싱글 사인온이 사용자를 그룹에 배치하는 등 PlaidCloud 밖에서 이루어진 멤버십 변경은 저장하거나 다시 시도할 필요 없이 약 15분 이내에 대시보드에 반영됩니다.

### 차원 부여

값 소스가 **차원**이면 노드를 선택하여 그 아래의 모든 항목을 부여합니다. 부여는 차원을 따릅니다. 선택한 노드 아래에 추가된 멤버는 차원을 저장한 후 다음 동기화 때 해당 그룹에 부여되고, 그 아래에서 이동하거나 제거된 멤버는 더 이상 부여되지 않습니다. 그리드를 다시 열 필요가 없습니다. 다시 열면 선택했던 노드가 선택된 상태로 표시됩니다.

선택한 노드 아래의 항목을 하나라도 선택 해제하면 노드의 선택도 해제되며, 그룹에는 여전히 선택된 멤버만 남습니다. 해당 멤버를 다시 선택해도 노드가 다시 선택되지 않습니다. 노드는 노드 자체의 확인란을 클릭하십시오. **붙여넣기**, **모두 선택**, **선택 반전**은 멤버를 선택하며 노드는 선택하지 않습니다.

이름을 행 액세스 값으로 사용할 수 없는 차원 멤버는 저장할 때 해당 멤버의 이름과 함께 거부됩니다. 이런 멤버가 나중에 나타나면 그 행은 누구에게도 부여되지 않으며, 동기화 상태에 해당 멤버의 이름이 표시됩니다. "Dimension ‘…’ member ‘…’ cannot be used as a row access value, so its rows are not granted. Rename it in the dimension."

### 소스 테이블에 부여 바인딩

값을 직접 선택하는 대신, 제한된 열을 이미 답을 가지고 있는 소스 테이블, 즉 그룹과 해당 그룹이 볼 수 있는 값이 한 행씩 있는 테이블에 연결할 수 있습니다. 먼저 그리드에서 열을 제한한 다음, 열, 소스 테이블, 소스 테이블의 그룹 열과 값 열을 지정하는 [**행 액세스 설정**](/ko/reference/workflow-steps/tables/table-set-row-access/) 워크플로 단계를 추가합니다. 이 단계를 처음 실행하면 열이 해당 테이블에 바인딩됩니다. 열에 직접 설정한 부여는 지워지고, 테이블의 행에서 부여가 설정됩니다.

바인딩되면 열은 **소스 소유**가 됩니다. 행 액세스 그리드에 열이 잠긴 상태로 표시되고 소스 테이블 이름이 있는 배지가 붙으며, **바인딩 제거**를 클릭하기 전까지는 부여를 직접 편집할 수 없습니다.

이후 단계를 실행할 때마다 소스 테이블을 다시 읽어 부여를 다시 적용합니다. 해당 테이블을 로드하거나 새로 고치는 워크플로 뒤에 이 단계가 실행되도록 일정을 잡으면, 소스 데이터에서 그룹을 추가, 제거 또는 재할당했을 때 그리드를 직접 편집하지 않아도 다음 실행 시 행 액세스에 반영됩니다.

소스 테이블이 누가 무엇을 볼지 결정하므로, 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트 자체의 워크플로만 해당 테이블의 행을 변경하거나 테이블을 삭제할 수 있습니다. 그 외 사용자에게는 "This table supplies the row access grants for ‘region’, so only a project Architect can change its rows or delete it."라고 안내합니다.

### 제한 템플릿

같은 값 소스, 값 유형, 빈 값 설정 등 재사용하려는 제한 형태를 만들었다면 열마다 다시 만드는 대신 한 번 저장해 두고 필요한 곳에 적용할 수 있습니다.

- 열려 있는 행 액세스 화면의 **템플릿으로 저장…** 은 현재 열의 형태를 이름이 있는 테넌트 수준 템플릿으로 저장합니다. 형태만 저장되며 부여는 함께 저장되지 않습니다.
- 다른 프로젝트의 열에서 **템플릿 적용**을 사용하면 템플릿의 형태로 해당 열을 시작하며, 모든 그룹의 부여는 비어 있어 직접 채울 수 있습니다.

프로젝트 아키텍트라면 누구나 템플릿을 저장하고 적용할 수 있습니다. 템플릿은 테넌트 전체에서 공유되므로 이름 바꾸기(**이름 바꾸기…**)와 삭제(**삭제**)에는 테넌트 관리자가 필요합니다. 템플릿을 삭제해도 이미 적용된 열의 제한은 그대로 유지됩니다.

<Aside type="note">
템플릿은 링크가 아니라 복사본입니다. 나중에 템플릿을 편집해도 이미 템플릿을 적용한 열은 바뀌지 않습니다. 열을 이후 수정본에 맞게 업데이트하려면 템플릿을 다시 적용하십시오.
</Aside>

### SSO 그룹 속성의 부여

열은 PlaidCloud 대신 ID 공급자에서 부여를 가져올 수도 있습니다. 프로젝트 아키텍트가 행 액세스에서 **Accept row-access grants from SSO group attributes**를 사용하도록 설정하여 열을 선택합니다.

이 옵션을 사용하면 보안 그룹의 Keycloak 속성 `row_access.<column>`이 해당 열을 통해 그룹이 볼 수 있는 값을 설정합니다. Keycloak에서 그룹에 속성을 설정하면 PlaidCloud가 프로젝트에 이미 액세스할 수 있는 모든 그룹에 대해 이를 자동으로 가져옵니다. 행 액세스 자체에서 더 구성할 것은 없으며, 부여는 PlaidCloud 자체 쿼리와 Superset 대시보드 모두에서 동기화 상태로 유지됩니다.

<Aside type="caution">
이 옵션은 프로젝트에 이미 액세스할 수 있는 그룹에만 값을 부여합니다. 프로젝트 액세스 권한이 없는 그룹에 `row_access.region`을 추가해도 그룹에 프로젝트 액세스 권한을 함께 부여하기 전까지는 아무것도 부여되지 않습니다.
</Aside>

### 저장하기 전에 미리 보기

행 액세스는 변경 내용을 확정하기 전에 그 의미를 보여 줍니다.

- **다음 사용자로 미리 보기…** 바닥글에는 그룹이 전체 행 중 몇 개를 볼 수 있는지와 실제 행의 샘플이 표시됩니다. 그리드에서 아무 그룹이나 선택하면 미리 볼 수 있습니다. 미리 보기는 저장한 후 새로 고쳐집니다.
- 저장하기 전에 행 액세스는 다시 확인할 만한 항목을 경고합니다. 아무것도 선택되지 않은 그룹이 있으면 **Everyone else** 설정에 따라 모든 행을 보는지 아니면 하나도 보지 못하는지, 프로젝트 액세스 권한이 있지만 어떤 그룹의 부여에도 포함되지 않은 멤버, 열 값이 비어 있어(`NULL`) 어떤 그룹에도 부여되지 않은 행을 알려 줍니다.

### 제한된 멤버가 보는 내용

제한된 멤버가 이름으로 테이블을 읽는 모든 곳, 즉 테이블 탐색기의 그리드, 열 패싯, 다운로드, 테이블 다운로드 대화 상자, 보는 사람으로서 읽는 앱과 도구, 대시보드에서 자신의 행만 표시됩니다. 보고 있는 그리드가 부여에 따라 필터링된 경우 테이블 탐색기는 도구 모음에 **액세스 권한에 따라 행이 제한됨**을 표시하며, 필터링될 다운로드를 시작할 때는 "Rows limited by your access."라고 안내합니다. 모든 행을 읽는 아키텍트에게는 두 안내 모두 표시되지 않습니다.

### 행 액세스와 직접 작성한 쿼리

행 액세스는 정의된 테이블을 필터링하여 그룹이 볼 수 있는 행을 제한합니다. 직접 작성한 쿼리에는 이 필터를 적용할 단일 테이블이 없습니다. 쿼리는 원하는 만큼 많은 테이블을 조인, 결합 또는 중첩할 수 있기 때문입니다. 따라서 행을 제한하는 프로젝트에서는 PlaidCloud가 검증되지 않은 행을 반환하는 대신 호출자가 제공한 쿼리의 실행을 거부합니다.

이는 직접 작성한 SQL로 읽기, 직접 작성한 SQL의 결과를 파일이나 다른 데이터베이스로 내보내기, 팬아웃 단계의 "Test row 1" 미리 보기에 행 조건 입력하기에 적용됩니다. 앱과 도구가 데이터를 읽는 일반적인 방법인 이름으로 테이블 읽기에는 적용되지 **않습니다**. 이러한 읽기는 부여를 적용하여 보는 사람이 볼 수 있는 행을 반환합니다. 단일 테이블의 일반 쿼리로 작성된 열 패싯도 이름으로 읽으므로 거부되지 않고 멤버 본인의 값을 반환합니다.

거부된 사용자에게는 어떤 프로젝트였는지 안내하고 이름으로 읽는 방법을 알려 줍니다. 프로젝트 아키텍트는 쿼리를 작성한 그대로 실행하고 결과를 어떤 형식으로든 내보낼 수 있습니다. 아키텍트는 이미 모든 제한된 열의 모든 값을 스스로 부여할 수 있기 때문입니다.

스프레드시트 가져오기는 그 자체로 직접 작성한 쿼리가 아닙니다. 일반적인 파일 가져오기는 제한된 데이터를 전혀 읽지 않고 업로드한 파일로 프로젝트 자체의 새 테이블만 만들므로 행 액세스의 영향을 받지 않습니다. 예외는 데이터 프로젝션을 호출자가 제공하는 가져오기, 즉 열별 식이나 동적 Excel 매핑입니다. 대화형 가져오기 화면에서는 이러한 가져오기가 위의 자유 형식 SQL 화면과 같은 방식으로 거부되며 프로젝트 아키텍트가 필요합니다. 호출자가 제공한 프로젝션이 다른 테이블을 읽을 수 있기 때문입니다. 워크플로에서 실행하는 가져오기는 프로젝트 자체의 서비스 ID로 실행되므로 어느 경우에도 영향을 받지 않습니다.

<Aside type="caution">
프로젝트에서 첫 번째 열을 제한하면 해당 프로젝트를 사용하는 모든 사람에게 이 동작이 변경됩니다. 프로젝트의 패널 앱, 노트북 또는 통합이 직접 구성한 SQL로 데이터를 읽는 경우 제한하기 전에 이름으로 테이블을 읽도록 전환하십시오. 그렇지 않으면 아키텍트가 아닌 모든 사람에게 작동하지 않게 됩니다.
</Aside>

### 행 액세스와 데이터 편집기

데이터 편집기는 테이블을 직접 읽고 쓰므로 행 액세스가 양쪽 모두에 적용됩니다.

데이터 편집기에서 제한된 테이블을 열면 보안 그룹이 부여받은 행만 표시됩니다. 대시보드에서 적용되는 것과 같은 필터이며, 제한된 열이 그리드에 표시된 열이 아니더라도 적용됩니다.

편집 내용을 저장하려면 프로젝트에 대한 **아키텍트** 권한이 필요합니다. 저장하면 테이블의 행을 읽지 않고 통째로 바꾸며 행 단위로 필터링되지 않으므로, 제한된 테이블의 데이터 편집은 읽기가 아니라 작성 작업으로 취급됩니다. 아키텍트가 아닌 사용자에게는 아키텍트 권한이 필요하다고 안내합니다. 제한된 열이 없는 테이블은 이전과 같이 편집되며, 행을 제한하지 않는 프로젝트도 마찬가지입니다.

### 행 수와 테이블 크기

테이블의 행 수와 저장소 크기는 볼 수 있는 행이 아니라 테이블 전체를 나타내므로, 제한된 사용자에게 부여 범위를 넘어 존재하는 행의 수를 알려 주게 됩니다. 행을 제한하는 프로젝트에서 읽기가 필터링되는 사용자에게는 테이블 목록, 검색, 테이블 세부 정보, 스냅샷, 그리고 MCP를 통해 연결된 AI 어시스턴트와 AI 도구에서 프로젝트의 어떤 테이블에 대해서도 행 수나 크기가 표시되지 않습니다. 제한된 열이 없는 테이블을 포함한 프로젝트의 모든 테이블에 적용됩니다. 프로젝트 자체 합계, 즉 홈, 프로젝트 목록과 검색, 프로젝트 세부 정보에 표시되는 총 행 수와 크기도 이들에게는 숨겨집니다.

워크플로 실행 기록에도 같은 규칙이 적용됩니다. 각 실행과 단계에서 기록한 읽은 행 수와 쓴 행 수도 테이블 전체를 나타내므로, 같은 사용자에게는 워크플로와 단계의 실행 기록, 그리고 MCP를 통해 연결된 AI 어시스턴트와 AI 도구에서 이러한 수치가 비어 있습니다. 이들에게는 [Weave](/ko/guides/ai-assistant/weave-findings/)가 이전 실행과 다른 행 수나 빈 값을 단계에서 검사하지 않습니다. 결과 항목 자체가 전체 테이블의 행 수가 변경되었음을 알려 주게 되기 때문입니다.

프로젝트 아키텍트에게는 수치가 이전처럼 표시되며, 행을 제한하지 않는 프로젝트의 모든 사용자에게도 마찬가지입니다.

### 멤버가 볼 수 있는 내용 확인

그룹에 부여된 내용이 아니라 특정 사람이 볼 수 있는 내용을 확인하려면 **Identity → Member**를 열고 멤버를 선택한 다음 해당 멤버의 **행 액세스** 탭을 엽니다. **유효 액세스** 열에는 제한된 모든 프로젝트와 열에 대해, SSO 그룹 속성의 부여와 그룹의 부여에 포함된 빈 값(`NULL`) 행을 포함하여 해당 멤버가 모든 그룹을 합쳐서 볼 수 있는 값이 나열됩니다. 프로젝트 아키텍트는 모든 행을 읽으므로 **모든 행 볼 수 있음(Architect)** 으로 표시됩니다. 이는 PlaidCloud 자체 쿼리가 적용하는 것과 같은 결과이므로, 지원 업무와 누군가 문제를 보고하기 전에 변경 사항이 의도대로 적용되었는지 확인하는 데 유용합니다.

### 더 명확한 오류

행 액세스가 작업을 차단하는 경우, 즉 제한된 프로젝트에서 직접 작성한 쿼리, 아키텍트 없이 수행한 편집, 자동화, 차원 또는 부여 소스 테이블의 변경 등 위에 설명한 여러 경우에는 일반적인 실패 메시지 대신 무엇이 제한되는지와 다음에 할 일(예: 요청할 아키텍트)을 알려 주는 메시지가 표시됩니다.

### 행 액세스 감사

열의 제한 설정이나 해제, 그룹의 부여 편집은 모두 해당 프로젝트의 [프로젝트 로그](/ko/get-started/tutorials/collaborate-versions-and-sharing/#프로젝트-로그-읽기)에 항목을 기록합니다. 누가 언제 변경했는지가 남습니다. 이 기록을 보려면 프로젝트에서 **Analyze → Projects → Log**를 여십시오. 이 기록을 남기기 위해 행 액세스에서 켜야 하는 항목은 없으며, 프로젝트에 대한 다른 모든 추적 대상 변경과 동일한 방식으로 기록됩니다.

## 기본 보안 그룹 설정


새 멤버를 추가하는 데 필요한 시간을 줄이려면 기본 보안 그룹 집합을 지정하십시오. 그러면 각 사람을 수동으로 할당하지 않아도 새 멤버에게 기본 보안 그룹 집합이 제공됩니다. 이 설정은 새 보안 그룹을 추가할 때 Security Group 창 하단의 “Assign to New Users by Default” 확인란을 선택하면 사용할 수 있습니다.



## 보안 감사 수행


보안 감사 기능을 사용하면 모든 멤버와 그룹의 그룹 멤버십을 확인할 수 있습니다.



**보안 감사를 수행하려면 다음을 수행합니다.**


1. Identity를 엽니다.
2. “Security” 탭을 선택합니다.
3. 드롭다운 메뉴에서 “Security Group Audit”를 클릭합니다.

PlaidCloud의 모든 테이블은 CSV 파일 형식으로 내보낼 수 있으므로, 그룹 멤버 연결 정보는 기록 보관용으로든 단순히 오프라인에서 재미 삼아 보기 위해서든 PlaidCloud 밖에서 검토할 수 있습니다.



**“Security Group Audit” 양식에서 내보내려면 다음을 수행합니다.**


1. Identity를 엽니다.
2. “Security” 탭을 선택합니다.
3. 드롭다운 메뉴에서 “Security Group Audit”를 클릭합니다.
4. 테이블에서 “Username” 오른쪽 끝에 있는 작은 아이콘을 클릭합니다.
5. 선호에 따라 “Export CSV” 또는 “Export XLXS”를 클릭합니다.

## 사용 가능한 권한 설정 보기


워크스페이스에서 사용하는 각 애플리케이션에는 사용할 수 있는 고유한 권한이 있습니다. 보안 그룹 권한은 이러한 애플리케이션 권한을 기반으로 합니다.


각 애플리케이션에서 사용할 수 있는 전체 권한 목록은 Security Bin에서 볼 수 있습니다.



**Security Bin에 액세스하려면 다음을 수행합니다.**


1. Identity를 엽니다.
2. “Security”를 선택합니다.
3. 드롭다운 메뉴에서 “Security Bins”를 클릭합니다.

각 애플리케이션의 상세 보안 설정을 보려면 가장 왼쪽의 태그 아이콘을 선택합니다.



이 사용 가능한 보안 설정 정보는 참고용입니다. 권한 관리에 대한 자세한 내용은 위의 보안 그룹 관리 섹션을 참조하십시오.
