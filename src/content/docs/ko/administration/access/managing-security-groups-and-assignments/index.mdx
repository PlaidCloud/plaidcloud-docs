PlaidCloud의 보안 및 액세스 관리는 간단합니다. 멤버는 소속된 그룹에 따라 액세스가 허용되거나 거부됩니다. 멤버의 보안 연결을 추가하거나 변경하는 작업은 손쉽게 맞춤 설정할 수 있습니다.

<Aside>워크스페이스당 보안 그룹의 수에는 제한이 없지만, 보안 관리를 쉽게 하려면 그룹 수를 최소화하는 것이 좋습니다.</Aside>



## 보안 그룹 관리


보안 그룹은 추가, 업데이트 또는 삭제할 수 있습니다.



**보안 그룹을 관리하려면 다음과 같이 합니다.**


1. Identity를 엽니다.
2. 레일에서 **보안 그룹**을 선택합니다(기존 그룹 목록이 표시됩니다).
3. 그룹을 추가하려면 **새 그룹**을 클릭합니다.
4. 그룹의 권한을 편집하려면 가장 왼쪽 아이콘을 클릭합니다.

**그룹 멤버를 관리하려면 다음과 같이 합니다.**


1. Identity를 엽니다.
2. 레일에서 **보안 그룹**을 선택합니다.
3. 멤버 아이콘을 클릭합니다.
4. 원하는 멤버를 "할당되지 않은 멤버" 열에서 "할당된 멤버" 열로 끌어다 놓습니다. 멤버를 제거하려면 반대로 끌어다 놓습니다.

<Aside>"할당된 멤버" 열을 비워 둔 채 저장하면 아무것도 변경되지 않으며, 그 사실이 안내됩니다. 그룹을 모든 사용자에게서 제거하려면 멤버십을 비우는 대신 그룹의 권한을 제거하거나 그룹을 삭제하십시오.</Aside>

<Aside>그룹에 [행 액세스](#행-액세스-관리)를 통해 행이 부여된 경우, 멤버십 변경은 약 1분 이내에 대시보드에 반영됩니다. 추가한 사용자는 대시보드에서 해당 그룹의 행을 볼 수 있게 되고, 제거한 사용자는 더 이상 볼 수 없게 됩니다. 멤버를 비활성화하거나 삭제하는 경우와 그룹을 삭제하는 경우에도 같은 방식으로 적용됩니다.</Aside>

<Aside type="caution">직접 부여할 수 없는 권한은 그룹의 권한 매트릭스를 저장할 때 변경되지 않고 그대로 유지되며, 매트릭스에도 표시되지 않습니다. 해당 권한을 변경해야 하면 그 권한을 가진 사용자에게 요청하십시오. 매트릭스에서는 본인이 제어할 수 있는 권한만 편집할 수 있습니다.</Aside>

<Aside type="caution">그룹이 부여하는 모든 권한을 가지고 있을 때 멤버를 그룹에 추가하거나 멤버의 그룹을 선택할 수 있습니다. 누군가를 Architect로 초대할 때도 마찬가지입니다. 워크스페이스 관리자는 이 제한을 받지 않습니다.</Aside>

## 행 액세스 관리

행 액세스는 한 열의 값을 기준으로 보안 그룹이 볼 수 있는 테이블의 행을 제한합니다. 예를 들어 `region` 열로 액세스를 제한하면, `East`와 `Central`을 부여받은 그룹은 해당 값을 가진 행으로만 제한됩니다. 프로젝트와 열에 대한 모든 작업, 즉 열 선택, 값의 출처 선택, 어느 그룹이 무엇을 볼 수 있는지 결정하는 작업이 하나의 화면에서 이루어지며, 저장하면 즉시 적용됩니다.

행 액세스를 설정하고 변경하려면 프로젝트 아키텍트 또는 테넌트 관리자여야 합니다. 그 밖의 사용자가 프로젝트의 보안 탭을 열면 행 액세스는 아키텍트 전용이라는 안내가 표시되며, 아래의 진입점도 나타나지 않습니다.

### 행 액세스 열기

모든 진입점은 같은 행 액세스 화면을 엽니다.

- **테이블 탐색기의 도구 모음**에는 **행 액세스** 버튼이 있으며, 테이블이 이미 행을 제한하고 있으면 배지가 표시됩니다. 제한된 열이 있으면 테이블의 첫 번째 제한된 열에서 열리며, 테이블의 다른 열로 전환할 수 있습니다.
- **열의 패싯 메뉴**에는 **이 열로 행 제한…** 항목이 있으며, 이 항목을 선택하면 해당 열에서 행 액세스가 열립니다. 이미 행을 제한하는 열에서는 항목이 **이 열로 제한된 행 — 편집…** 으로 표시됩니다.
- **프로젝트의 보안 탭**에는 프로젝트에서 제한된 모든 열이 적용 대상 테이블, 부여를 보유한 그룹, **동기화** 상태와 함께 나열됩니다. 열을 선택하여 편집하거나 **열 제한…** 을 클릭하여 새로 시작할 수 있습니다. 테이블을 고른 다음 열을 고릅니다. 이미 행을 제한하는 열에는 잠금 표시가 있습니다.
- **Identity → 멤버**에서 멤버의 **행 액세스** 탭, 그리고 **Identity → 보안 → 보안 그룹**에서 그룹의 행 액세스 요약입니다. **행 액세스 열기**(또는 **편집**)를 선택하면 선택한 열이 열리고, **추가**를 선택하면 해당 행의 프로젝트에서 다른 열을 제한합니다.

열을 지정해서 열면 화면은 그 열에 고정됩니다. **열 제한…** 또는 **추가**로 열면 열을 선택할 수 있습니다.

### 행 액세스 그리드

열을 기준으로 테이블을 제한하려면 다음과 같이 합니다.

1. 위의 진입점 중 하나에서 행 액세스를 열고, 열을 지정하지 않고 들어왔다면 열을 선택합니다. 선택기에는 자유 입력 텍스트가 아니라 테이블의 실제 열이 표시됩니다.
2. **값 소스**를 선택합니다. **열**(테이블 열의 고유한 값), **차원**(차원의 노드) 또는 **목록**(직접 입력하는 값) 중에서 고릅니다. 값 유형은 열의 데이터 유형을 따릅니다.
3. 각 보안 그룹에 대해 해당 그룹이 볼 수 있는 값을 선택합니다. 그리드에는 프로젝트에 액세스할 수 있는 그룹과, 해당 열에 이미 부여를 보유한 그룹이 나열됩니다.
4. **그 외 모든 사용자**를 **모든 행 볼 수 있음** 또는 **행을 볼 수 없음**으로 설정합니다. 그리드에서 선택된 값이 없는 모든 그룹에 적용됩니다.
5. **저장**을 클릭합니다.

저장하면 바로 적용됩니다. PlaidCloud 자체 쿼리에는 변경 사항이 즉시 반영되고 Superset 대시보드에는 약 1분 이내에 반영됩니다. 적용을 위한 별도 단계는 없으며, 부여가 보유한 값이 소스에서 사라진 경우에만 **저장**이 확인을 요청합니다(아래 참조). 화면의 동기화 상태에는 변경 사항이 어디까지 전달되었는지 표시됩니다. [대시보드 동기화 유지](#대시보드-동기화-유지)를 참조하십시오.

그리드는 다음과 같은 세부 사항도 처리합니다.

- **많은 값.** 값은 정렬됩니다. 열에 표시할 수 있는 것보다 많은 값이 있으면 그리드에 "표시할 수 있는 값보다 많습니다. 검색하려면 입력하십시오."라고 표시되며, 필터 상자는 열 전체를 검색하고 그룹이 이미 보유한 모든 값을 유지합니다.
- **소스에 더 이상 없는 값.** 그룹에 부여된 값은 소스에서 사라져도 그리드에 남아 있습니다. 테이블의 어떤 행에도 해당 값이 없거나, 차원에 해당 멤버가 더 이상 없거나, 목록에 해당 값이 더 이상 없는 경우입니다. 해당 열 머리글에는 경고 아이콘이 표시되며, 아이콘 위로 마우스를 가져가면 이유가 나타납니다. **모두 선택**, **선택 반전**, **붙여넣기**는 이러한 값을 각 그룹이 보유한 상태 그대로 둡니다. 선택을 해제하지 않는 한 부여에서 아무것도 제거되지 않습니다. 그룹이 이러한 값을 아직 보유한 상태에서 **저장**을 클릭하면 행 액세스가 **소스에 더 이상 없는 값**에 해당 그룹과 값을 표시하고 확인을 요청합니다. **유지하고 저장**은 값을 그대로 저장하고, **제거하고 저장**은 먼저 모든 그룹의 부여에서 해당 값을 제거하며, 확인 창을 닫으면 아무것도 저장되지 않습니다. 값을 제거했을 때 선택된 값이 없는 그룹이 생기면, 확인 창에 **그 외 모든 사용자** 설정에 따라 해당 그룹이 모든 행을 보게 되는지 아니면 아무 행도 보지 못하게 되는지 안내됩니다. 아직 저장하지 않은 선택은 해당 값과 함께 사라집니다. 열에 표시할 수 있는 것보다 많은 값이 있거나 테이블이 아직 빌드되지 않은 경우에는 행 액세스가 테이블에 없는 값을 알 수 없으므로 부여된 모든 값을 표시 없이 유지합니다.
- **빈 값.** **빈 값 - 부여된 모든 그룹에 표시** 확인란 하나로 열에 값이 없는 행을 처리할지 결정합니다. 이 확인란을 선택하면 해당 열에 부여가 하나라도 있는 모든 그룹이 그 행을 볼 수 있습니다.
- **아직 빌드되지 않은 테이블**은 빈 목록 대신 **먼저 이 테이블을 빌드하십시오(테이블을 만드는 워크플로 실행)** 라고 표시합니다.
- **저장은 화면에 표시된 값이 로드될 때까지 기다립니다.** 값 소스, 차원 또는 테이블을 전환하거나 템플릿을 적용한 후 값을 로드하는 동안에는 **저장**이 비활성화되며 "이 소스의 값이 로드되면 저장할 수 있습니다."라는 툴팁이 표시됩니다. 로드에 실패하면 그리드에 그 사실이 표시되고 소스를 다시 선택하도록 안내하며, 로드에 성공할 때까지는 아무것도 저장되지 않습니다.

### 하나의 열 이름, 모든 테이블

제한은 개별 테이블이 아니라 프로젝트의 열 *이름*에 속합니다. `region`이 행을 제한하면, 프로젝트에서 `region`이라는 이름의 열이 있는 모든 테이블이 PlaidCloud 자체 쿼리와 대시보드 모두에서 그 제한에 따라 필터링됩니다. 그리드의 **적용 대상** 목록에는 해당 테이블이 표시됩니다. 열 이름이 대상을 결정하므로 이 목록은 읽기 전용이며, 나중에 같은 열을 가진 테이블을 추가하면 게시되는 즉시 적용 대상에 포함됩니다.

프로젝트에 해당 이름의 열을 가진 테이블이 없으면, 창에 **0개 테이블에 적용**이 표시되는 것과 함께, 테이블이 생길 때까지 해당 제한이 어떤 대시보드도 필터링하지 않는다는 경고가 표시됩니다. 테이블에 열을 추가하거나 열 이름을 수정하면 경고가 사라집니다.

<Aside type="caution">
**열 이름은 대소문자와 공백까지 정확히 일치해야 합니다.** `Region`과 `region`은 서로 다른 이름이며, `region`과 끝에 공백이 있는 `region `도 마찬가지입니다. 선택기는 실제 열 이름만 제시하므로, 이 점은 주로 다른 곳에서 열 이름이 바뀐 경우에 문제가 됩니다. 이 경우 행 액세스는 아무것도 제한하지 않은 채 조용히 넘어가지 않고, 경고와 함께 찾아낸 가장 가까운 열의 이름을 알려 줍니다.
</Aside>

<Aside type="caution">
**행을 제한하는 테이블을 게시하면 같은 단계에서 해당 대시보드 필터가 설정됩니다.** 대시보드는 게시된 보고용 뷰를 통해 테이블을 읽으므로, 제한된 열이 있는 테이블을 게시하거나 다시 게시하면 게시가 완료되기 전에 PlaidCloud가 해당 테이블의 대시보드 필터를 등록합니다. 등록할 수 없으면 게시가 거부되고 그 시도에서 만들어진 모든 항목이 롤백되므로, 제한된 테이블이 필터 없이 대시보드에 남는 일은 없습니다. 뷰의 쿼리는 제한된 열의 이름을 바꾸거나 그 열에서 값을 파생시킬 수 있으므로, 행을 제한하는 프로젝트에서는 *뷰*를 게시할 수 없습니다. [테이블 게시](/ko/guides/data/publish/)를 참조하십시오.
</Aside>

### 제한 중지

그리드의 **제한 중지**는 인라인 확인 후 제한을 제거합니다. "'region'으로 행 제한을 중지하시겠습니까? 해당 열에 대한 모든 그룹의 부여가 제거되고 모든 사용자가 그 행을 볼 수 있습니다." 그러면 행 액세스가 "'region'의 행이 더 이상 제한되지 않습니다."라고 알려 줍니다. 해당 열의 Superset 데이터셋도 함께 제거되지만, 차트가 아직 그 데이터셋을 사용 중이면 제거되지 않으며 이 경우 행 액세스가 데이터셋이 남아 있다는 사실과 이를 사용하는 차트 수를 알려 줍니다.

열이 행을 제한하는 동안에는 그 열의 이름을 바꾸거나 삭제할 수 없습니다. 아키텍트에게는 먼저 행 액세스에서 제한을 중지하라고 안내되고, 그 외 사용자에게는 프로젝트 아키텍트에게 요청하라고 안내됩니다.

### 행을 제한하는 프로젝트를 변경할 수 있는 사용자

프로젝트의 워크플로, 단계, 사용자 정의 함수는 프로젝트 자체의 서비스 ID로 실행되며, 이 ID는 모든 행을 읽습니다. 이를 변경할 수 있는 사용자는 단계가 자신에게 부여되지 않은 행을 자신이 읽을 수 있는 테이블로 복사하게 만들 수 있으므로, 프로젝트에서 행을 제한하면 프로젝트의 동작을 누가 변경할 수 있는지도 함께 제한됩니다. 프로젝트가 하나 이상의 열을 제한하면 다음이 적용됩니다.

- **자동화는 아키텍트 전용입니다.** 프로젝트 아키텍트와 테넌트 관리자만 워크플로, 단계, 사용자 정의 함수, 일정, 워크플로 및 프로젝트 변수, 알림 이메일 템플릿을 변경할 수 있습니다. 같은 이유로 워크플로 번들 가져오기, Alteryx 워크플로 변환, 프로젝트로의 가져오기·복사·복원, 연결 환경, 기본 문서 계정 또는 ERP 전기 모드 변경도 이들만 할 수 있습니다. 그 외 사용자도 프로젝트의 워크플로는 계속 실행할 수 있으며, **시작**, **중지**, **재개**, **선택한 단계 실행**을 사용할 수 있습니다. 단계 편집기, 워크플로의 작성 컨트롤, UDF 편집기, 일정 양식은 이들에게 읽기 전용으로 열리며, 문의할 아키텍트를 알려 주는 배너가 표시됩니다. "이 프로젝트는 행을 제한하므로 아키텍트만 워크플로, 단계, UDF, 일정, 변수 및 알림 템플릿을 변경할 수 있습니다. 실행은 계속 하실 수 있습니다."
- **제한된 열이 읽는 차원은 아키텍트 전용입니다.** 어떤 사용자가 어떤 행을 볼지 결정하는 차원, 즉 제한된 열의 값 소스는 프로젝트 아키텍트 또는 테넌트 관리자와 프로젝트 자체의 워크플로만 변경할 수 있습니다. 여기에는 노드의 추가, 이동, 이름 바꾸기, 복사, 지우기, 로드, 복원과 차원 자체가 포함됩니다. 그 외 사용자에게는 "이 차원은 'region'의 어떤 행을 누가 볼지 결정하므로 프로젝트 아키텍트만 변경할 수 있습니다."라고 안내됩니다. 어떤 제한도 읽지 않는 차원은 영향을 받지 않습니다.
- **부여 소스 테이블은 아키텍트 전용입니다.** 열의 [부여 소스](#소스-테이블에-부여-바인딩)로 바인딩된 테이블은 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트의 워크플로만 행을 변경하거나 테이블을 삭제할 수 있습니다. 데이터 편집기, 가져오기, 커넥터 로드, API 모두 마찬가지입니다.
- **프로젝트 복사는 아키텍트 전용이며**, 복사본에는 "이 복사본은 행이 제한되어 있지 않습니다."라고 표시됩니다. 새 프로젝트는 제한을 설정하기 전까지는 어떤 제한도 갖지 않습니다.
- **이전 버전 복원도 다른 변경과 마찬가지입니다.** 프로젝트 자체의 설정이나 위에 나열된 차원을 복원하려면 프로젝트 아키텍트여야 합니다. 복원은 항상 버전이 속한 항목에 적용되므로 이를 우회하려고 다른 프로젝트를 지정할 수 없습니다. [버전 기록](/ko/guides/projects/managing-projects/#버전-기록)을 참조하십시오.
- **제한된 테이블의 데이터 편집**에는 [행 액세스와 데이터 편집기](#행-액세스와-데이터-편집기)에 설명된 대로 아키텍트가 필요합니다.
- **제한된 테이블에 대한 DataFrame 쓰기, 레코드 저장, 지우기**는 모든 행을 볼 수 있는 경우가 아니라면 [제한된 테이블에 데이터 로드](#제한된-테이블에-데이터-로드)에 설명된 대로 본인의 행만 변경합니다.
- **제한된 테이블의 가져오기, 복사, 브랜치 전환, 복원, 삭제는** 볼 수 없는 행이 테이블에 있는 동안 거부되며, [제한된 테이블에 데이터 로드](#제한된-테이블에-데이터-로드)에 설명되어 있습니다.

프로젝트에서 첫 번째 열을 제한하기 전에 행 액세스는 이 변경의 영향을 받는 사용자를 알려 줍니다. "여기서 행을 제한하면 아키텍트만 이 프로젝트의 워크플로, 단계, UDF, 일정, 알림 템플릿을 변경할 수 있습니다. 현재 N명의 멤버가 변경할 수 있으며, 이들은 앞으로도 실행은 할 수 있습니다."

실행은 프로젝트의 서비스 ID로 실행되므로, 예약된 실행을 포함해 이전과 똑같이 계속 작동합니다. 실행이 만들어 내는 결과는 아키텍트가 설계한 대로 따릅니다. 제한된 열이 없는 출력 테이블, 내보내기 파일, 알림 이메일, 로그 줄은 이를 읽는 사용자에 맞게 필터링되지 않습니다.

**실행을 시작할 때 지정하는 값.** 워크플로를 실행할 수 있는 사용자는 누구나 변수에 자신의 값을 지정하여 워크플로를 시작할 수 있습니다. [앱 러너](/ko/guides/workflows/use-converted-alteryx-apps/#app-runner-프런트엔드)는 양식에 입력된 답변으로 이를 수행하며, API와 AI 도구도 이를 수행할 수 있습니다. 이 값은 해당 실행에만 적용되며 워크플로에 저장되지 않고, 다른 실행, 내보내기 또는 읽는 사용자에게도 보이지 않습니다. 실행은 서비스 ID로 수행되므로 이 값이 해당 실행이 읽고 쓰는 내용을 바꿀 수 있습니다. 따라서 워크플로를 실행할 권한은 신뢰할 수 있는 사람에게만 부여하십시오.

**행을 제한하지 않는 프로젝트.** 이 규칙은 프로젝트가 열을 제한한 후에만 적용됩니다. 어떤 열도 제한하지 않는 프로젝트에서는 프로젝트의 자동화를 변경할 수 있는 사용자라면 누구나, 프로젝트의 서비스 ID로 실행되며 프로젝트의 액세스를 변경하는 단계나 사용자 정의 함수를 작성하여 스스로를 프로젝트의 아키텍트 중 한 명으로 만들 수 있습니다. 이는 의도된 동작입니다. 이러한 프로젝트는 행 격리를 약속하지 않습니다. 그런 프로젝트에서는 작성 권한을 아키텍트로 신뢰할 만한 사람에게만 부여하거나, 열을 제한하십시오.

### 대시보드 동기화 유지

행 액세스는 그리드와 프로젝트 보안 탭의 **동기화** 열에서 변경 사항이 대시보드로 전달되는 과정의 현재 위치를 보여 줍니다.

| 상태 | 의미 |
|---|---|
| **대기 중** | 변경 사항이 저장되어 대시보드로 전달되는 중입니다. 보통 약 1분 이내에 해소됩니다. |
| **재시도 중** | 전송에 실패하여 다시 시도하는 중입니다. 실패 이유가 상태 옆에 표시되며, 즉시 다시 보내는 **다시 시도**가 제공됩니다. |
| **아직 적용되지 않음** | 프로젝트의 제한이 아직 대시보드로 전송되지 않았습니다. |
| **적용됨** | 제한을 대시보드로 보내려는 마지막 시도가 성공했습니다. |
| **대시보드와 동기화됨** | 행 액세스가 대시보드가 적용하는 내용과 자신이 기록할 내용을 비교했으며 둘이 일치합니다. |
| **대시보드와 다름** | 대시보드가 행 액세스가 기록할 내용을 적용하고 있지 않습니다. Superset에서 규칙이 변경되었거나 삭제되었거나, 테이블의 게시된 뷰를 검사할 수 없는 경우입니다. |
| **오류** | 제한을 보내지 못했습니다. 이유가 상태 옆에 표시됩니다. |

변경 사항이 **적용됨**에 도달하면 그리드가 이를 대시보드와 대조하여 **대시보드와 동기화됨** 또는 **대시보드와 다름**으로 넘어갑니다. **대시보드와 다름**과 **오류**에는 모두 프로젝트의 제한을 다시 보내는 **다시 시도**가 제공됩니다. 상태를 전혀 읽을 수 없으면 그리드에 "동기화 상태를 검사할 수 없음"이라고 표시됩니다.

하나의 테이블 때문에 발생한 **오류**는 해당 테이블의 이름과 해야 할 일을 알려 줍니다. 예를 들어 제한된 열 없이 게시된 테이블("다시 게시하거나 게시를 취소하십시오."), 또는 제한된 열이 있지만 게시되지 않은 테이블이 있습니다. 게시되지 않은 테이블은 게시되기 전까지 대시보드가 필터링할 수 없습니다. 상태는 **오류**로 유지되며 해당 테이블을 게시하거나 게시된 테이블에서 열을 제한할 때까지 게시되지 않은 테이블의 이름이 표시됩니다. 이러한 테이블이 프로젝트의 나머지를 막지는 않으며, 다른 모든 테이블은 계속 동기화됩니다.

대시보드는 PlaidCloud 자체 쿼리와 동일한 부여를 따릅니다.

- **해당 열이 있는 게시된 모든 테이블이 필터링됩니다.** 제한을 설정할 때 보고 있던 테이블만 필터링되는 것이 아닙니다.
- **일부 값만 부여받은 그룹은 그 외 모든 사용자가 모든 행을 볼 수 있는 경우에도 필터링됩니다.** 대시보드 데이터셋이 존재하는 모든 테이블에서 그렇습니다.
- **프로젝트 아키텍트는 모든 행을 봅니다.** 테이블 탐색기와 PlaidCloud의 다른 부분에서와 마찬가지로 대시보드에서도 그렇습니다. 이는 프로젝트의 아키텍트 그룹과, 개별 멤버와 공유된 프로젝트의 아키텍트에게 적용됩니다. 아키텍트 액세스를 제거하면 멤버의 역할 변경, 프로젝트에서 멤버 또는 해당 그룹 제거, 프로젝트의 액세스 유형 변경, 이전 프로젝트 버전 복원, 그룹 삭제 중 어떤 방법을 쓰더라도 대시보드에 즉시 반영됩니다.
- **보안 그룹 멤버십 변경은 저절로 대시보드에 반영됩니다.** PlaidCloud에서 그룹에 사용자를 추가하거나 제거하는 경우, 멤버를 비활성화하거나 삭제하는 경우, 그룹을 삭제하는 경우, 기본 보안 그룹에 가입하는 새 멤버를 추가하는 경우, 해당 그룹에 값을 부여하는 모든 프로젝트에서 사용자가 대시보드에서 보는 내용이 약 1분 이내에 업데이트되며, 누군가 행 액세스를 다시 열 필요가 없습니다. Keycloak에서 직접 변경하거나 로그인 시 싱글 사인온이 사용자를 그룹에 배치하는 것과 같이 PlaidCloud 밖에서 이루어진 멤버십 변경은 약 15분 이내에 대시보드에 반영되며, 저장하거나 다시 시도할 필요가 없습니다.

### 차원 부여

값 소스가 **차원**이면 노드를 선택하여 그 아래의 모든 항목을 부여합니다. 부여는 차원을 따릅니다. 선택된 노드 아래에 추가된 멤버는 차원을 저장한 후 다음 동기화에서 해당 그룹에 부여되고, 그 아래에서 이동되거나 제거된 멤버는 더 이상 부여되지 않습니다. 그리드를 다시 열 필요가 없습니다. 그리드를 다시 열면 선택했던 노드가 선택된 상태로 표시됩니다.

노드를 통하지 않고 멤버를 직접 선택한 경우, 해당 멤버가 차원에서 제거되어도 부여는 유지되며, 그리드는 이를 소스에 더 이상 없는 값으로 표시합니다.

선택된 노드 아래의 항목 중 하나라도 선택을 해제하면 노드의 선택도 해제되고, 그룹은 여전히 선택된 멤버만 유지합니다. 그 멤버를 다시 선택해도 노드는 다시 선택되지 않습니다. 노드를 다시 선택하려면 노드 자체의 확인란을 클릭하십시오. **붙여넣기**, **모두 선택**, **선택 반전**은 멤버를 선택하며 노드는 선택하지 않습니다.

이름을 행 액세스 값으로 사용할 수 없는 차원 멤버는 저장할 때 해당 멤버를 지목하여 거부됩니다. 나중에 그러한 멤버가 나타나면 해당 행은 누구에게도 부여되지 않으며, 동기화 상태에 해당 멤버가 표시됩니다. "차원 '…'의 멤버 '…'는 행 액세스 값으로 사용할 수 없으므로 해당 행이 부여되지 않습니다. 차원에서 이름을 바꾸십시오."

### 소스 테이블에 부여 바인딩

값을 직접 선택하는 대신, 답을 이미 담고 있는 소스 테이블, 즉 그룹과 해당 그룹이 볼 수 있는 값이 한 행씩 있는 테이블에 제한된 열을 연결할 수 있습니다. 먼저 그리드에서 열을 제한한 다음, 열, 소스 테이블, 소스 테이블의 그룹 열과 값 열을 지정하는 [**행 액세스 설정**](/ko/reference/workflow-steps/tables/table-set-row-access/) 워크플로 단계를 추가합니다. 이 단계를 처음 실행하면 열이 해당 테이블에 바인딩되고, 열에 직접 설정한 부여는 지워지며, 부여는 테이블의 행으로 설정됩니다.

바인딩되면 열은 **소스 소유**가 됩니다. 행 액세스 그리드에는 열이 잠긴 상태로 소스 테이블 이름이 적힌 배지와 함께 표시되며, **바인딩 제거**를 클릭하기 전까지는 부여를 직접 편집할 수 없습니다.

이후 단계를 실행할 때마다 소스 테이블을 다시 읽고 부여를 다시 적용합니다. 해당 테이블을 로드하거나 새로 고치는 워크플로 뒤에 이 단계가 실행되도록 일정을 설정하면, 소스 데이터에서 그룹이 추가, 제거 또는 재할당되었을 때 아무도 그리드를 직접 편집하지 않아도 다음 실행 시 행 액세스에 반영됩니다.

소스 테이블이 누가 무엇을 볼 수 있는지 결정하므로, 프로젝트 아키텍트, 테넌트 관리자 또는 프로젝트 자체의 워크플로만 해당 테이블의 행을 변경하거나 삭제할 수 있습니다. 그 외 사용자에게는 "이 테이블은 'region'의 행 액세스 부여를 제공하므로 프로젝트 아키텍트만 행을 변경하거나 삭제할 수 있습니다."라고 안내됩니다.

### 제한 템플릿

같은 값 소스, 값 유형, 빈 값 설정 등 재사용하려는 제한 형태를 만들어 두었다면, 열마다 다시 만들지 말고 한 번 저장해 두었다가 필요한 곳에 적용하십시오.

- 열려 있는 행 액세스 화면에서 **템플릿으로 저장…** 을 선택하면 현재 열의 형태가 이름이 지정된 테넌트 수준 템플릿으로 저장됩니다. 형태만 저장되며 부여는 함께 저장되지 않습니다.
- 다른 프로젝트의 열에서 **템플릿 적용**을 선택하면 해당 열이 템플릿의 형태로 시작되며, 모든 그룹의 부여는 비어 있어 직접 채울 수 있습니다.

프로젝트 아키텍트라면 누구나 템플릿을 저장하고 적용할 수 있습니다. 템플릿은 테넌트 전체에서 공유되므로 템플릿의 이름 바꾸기(**이름 바꾸기…**)와 삭제(**삭제**)는 테넌트 관리자가 해야 합니다. 템플릿을 삭제해도 그 템플릿을 적용했던 열은 제한된 상태 그대로 유지됩니다.

<Aside type="note">
템플릿은 링크가 아니라 복사본입니다. 나중에 템플릿을 편집해도 이미 템플릿을 적용한 열은 변경되지 않습니다. 열을 이후 수정본에 맞게 업데이트하려면 템플릿을 다시 적용하십시오.
</Aside>

### SSO 그룹 속성의 부여

열은 PlaidCloud가 아니라 ID 공급자로부터 부여를 가져올 수도 있습니다. 프로젝트 아키텍트가 행 액세스에서 **SSO 그룹 속성의 행 액세스 부여 허용**을 사용 설정하여 열을 옵트인합니다.

사용 설정하면 보안 그룹의 Keycloak 속성 `row_access.<column>`이 해당 그룹이 그 열을 통해 볼 수 있는 값을 설정합니다. Keycloak에서 그룹에 속성을 설정하면 프로젝트에 이미 액세스할 수 있는 모든 그룹에 대해 PlaidCloud가 자동으로 이를 가져옵니다. 행 액세스 자체에서는 더 구성할 것이 없으며, 부여는 PlaidCloud 자체 쿼리와 Superset 대시보드 양쪽에서 동기화 상태로 유지됩니다.

<Aside type="caution">
이는 이미 프로젝트에 액세스할 수 있는 그룹에만 값을 부여합니다. 프로젝트 액세스가 없는 그룹에 `row_access.region`을 추가해도, 그 그룹에 프로젝트 액세스를 함께 부여하기 전에는 아무것도 부여되지 않습니다.
</Aside>

### 저장 전 미리 보기

행 액세스는 변경 사항을 확정하기 전에 그것이 무엇을 의미하는지 보여 줍니다.

- **다음 사용자로 미리 보기** 바닥글에는 전체 행 중 그룹이 볼 수 있는 테이블 행의 수와 행의 샘플이 표시됩니다. 그리드에서 미리 볼 그룹을 선택하십시오. 미리 보기는 저장한 후 새로 고쳐집니다.
- 저장하기 전에 행 액세스는 다시 살펴볼 만한 사항을 경고합니다. 선택된 값이 없는 그룹이 있는 경우와 **그 외 모든 사용자** 설정에 따라 그 그룹이 모든 행을 볼지 아무 행도 볼 수 없을지, 프로젝트 액세스가 있지만 어떤 그룹의 부여에도 포함되지 않은 멤버, 또는 해당 열의 값이 비어 있고(`NULL`) 어느 그룹에도 부여되지 않은 행입니다.

### 제한된 멤버가 보는 내용

제한된 멤버가 이름으로 테이블을 읽는 모든 곳에서 해당 멤버는 자신의 행만 받습니다. 테이블 탐색기의 그리드, 열 패싯, 다운로드, 테이블 다운로드 대화 상자, 뷰어로서 읽는 앱과 도구, 대시보드가 여기에 해당합니다. 보고 있는 그리드가 부여에 따라 필터링된 경우 테이블 탐색기는 도구 모음에 **액세스 권한에 따라 행이 제한됨**을 표시하며, 필터링될 다운로드를 시작하면 "액세스 권한에 따라 행이 제한됨"이라고 표시됩니다. 모든 행을 읽는 아키텍트에게는 두 알림 모두 표시되지 않습니다.

### 행 액세스와 직접 작성한 쿼리

행 액세스가 행을 제한하는 경우에도 프로젝트의 쿼리 화면에서 직접 SQL 쿼리를 실행할 수 있으며, 부여가 허용하는 행만 정확히 받습니다. 결과를 CSV, Excel 또는 JSON으로 내보낼 수 있으며, 내보낸 파일에는 해당 행만 포함되고 **액세스 권한에 따라 행이 제한됨** 알림이 함께 표시됩니다. 아키텍트는 이미 제한된 모든 열의 모든 값을 스스로에게 부여할 수 있으므로 프로젝트 아키텍트는 모든 행을 읽으며 알림도 표시되지 않습니다.

퍼센트 기호(`%`)가 포함된 부여 값도 쿼리 화면에서 부여된 행을 반환하며, 이러한 쿼리를 CSV로 다운로드할 수도 있습니다.

프로젝트 아키텍트가 아닌 멤버에게는 다음 작업이 여전히 거부됩니다.

- Snowflake 또는 Databricks 프로젝트 웨어하우스에서 직접 작성한 자유 형식 SQL 실행.
- Postgres 계열 웨어하우스에서 직접 작성한 SQL의 결과 내보내기.
- 직접 작성한 SQL의 결과를 다른 데이터베이스로 내보내기.
- 팬아웃 단계의 "1행 테스트" 미리 보기에 행 조건 입력.
- 관리 대상 테이블을 이전 스냅샷 시점으로 읽기(시간 이동).

거부된 사용자에게는 어떤 프로젝트였는지가 안내되고 이름으로 읽는 방법이 제시됩니다. 테이블을 이름으로 읽는 것은 앱과 도구가 데이터를 읽는 일반적인 방식이며, 부여를 적용하여 뷰어가 볼 수 있는 행을 반환합니다. 단일 테이블에 대한 일반 쿼리로 작성된 열 패싯도 이름으로 읽기 때문에 거부되지 않고 멤버 자신의 값을 반환합니다. 프로젝트 아키텍트는 이 모든 작업을 작성한 그대로 실행할 수 있습니다.

행 액세스는 관리 대상 열을 기준으로 뷰를 필터링하므로, 뷰는 해당 열을 원래 이름 그대로 유지해야 합니다. 관리 대상 열을 제외하거나 이름을 바꾼 뷰는 필터링되지 않습니다.

스프레드시트 가져오기는 그 자체로 직접 작성한 쿼리가 아닙니다. 일반적인 파일 가져오기는 제한된 데이터를 전혀 읽지 않고, 업로드한 파일로 프로젝트 자체의 새 테이블을 만들기만 하므로 행 액세스의 영향을 받지 않습니다. 예외는 데이터 프로젝션을 호출자가 제공하는 가져오기, 즉 열별 식 또는 동적 Excel 매핑입니다. 대화형 가져오기 화면에서는 이러한 가져오기가 위의 자유 형식 SQL 화면과 같은 방식으로 거부되며, 호출자가 제공한 프로젝션이 다른 테이블을 읽을 수 있으므로 프로젝트 아키텍트가 필요합니다. 워크플로에서 실행하는 가져오기는 프로젝트 자체의 서비스 ID로 실행되므로 어느 경우든 영향을 받지 않습니다.

<Aside type="caution">
프로젝트에서 첫 번째 열을 제한하면 이를 사용하는 모든 사용자에게 이 동작이 바뀝니다. 해당 프로젝트의 Panel 앱, 노트북 또는 통합이 Snowflake 또는 Databricks 웨어하우스에서 자체 SQL을 구성하거나 Postgres 계열 웨어하우스에서 자체 쿼리 결과를 내보낸다면, 제한하기 전에 테이블을 이름으로 읽도록 바꾸십시오. 그렇지 않으면 아키텍트가 아닌 모든 사용자에게 작동하지 않게 됩니다.
</Aside>

### 행 액세스와 데이터 편집기

데이터 편집기는 테이블을 직접 읽고 쓰므로 행 액세스는 양쪽 모두에 적용됩니다.

제한된 테이블을 데이터 편집기에서 열면 보안 그룹에 부여된 행만 표시됩니다. 이는 대시보드에서도 동일하게 적용되는 필터이며, 제한된 열이 그리드에 표시된 열이 아니더라도 적용됩니다.

편집 내용을 저장하려면 프로젝트의 **아키텍트**여야 합니다. 저장은 테이블의 행을 읽지 않고 통째로 교체하며 행 단위로 필터링되지 않으므로, 제한된 테이블의 데이터 편집은 읽기가 아니라 작성 작업으로 취급됩니다. 아키텍트가 아닌 사용자에게는 아키텍트가 필요하다고 안내됩니다. 제한된 열이 없는 테이블은 이전과 같이 편집되며, 행을 제한하지 않는 프로젝트도 마찬가지입니다.

### 제한된 테이블에 데이터 로드

행 액세스가 볼 수 있는 행을 제한할 때, Python 클라이언트(`PlaidConnection`)로 DataFrame을 제한된 테이블에 쓰거나 테이블을 지우는 작업, 또는 REST API로 레코드를 저장하거나 지우는 작업은 본인의 행에 대해서만 수행됩니다. 테이블의 데이터를 교체하면 볼 수 있는 행만 교체되고, 지우면 해당 행만 지워지며, 추가하면 행이 추가됩니다. 그 외 모든 행은 그대로 유지됩니다.

액세스 범위를 벗어난 행이 포함된 로드는 아무것도 변경되기 전에 거부되며, 오류에는 액세스 범위를 벗어난 각 값과 해당 값을 가진 행의 수가 표시됩니다. 제한된 열이 빠진 행은 해당 열이 비어 있는 것으로 검사되므로, 액세스에 빈 행이 포함되지 않으면 거부됩니다. 열의 유형이 바뀌는 방식으로 데이터를 교체하는 것도 거부되므로, 프로젝트 아키텍트에게 해당 변경을 요청하십시오.

프로젝트 아키텍트, 부여가 모든 행을 포함하는 멤버, 프로젝트의 서비스 ID로 실행되는 워크플로 실행은 테이블 전체를 씁니다. 제한된 열이 없는 테이블은 영향을 받지 않습니다.

제한된 테이블 전체를 교체하거나 제거하는 그 밖의 모든 작업은 볼 수 없는 행이 테이블에 있는 동안 거부되며 아무것도 변경되지 않습니다. 파일을 테이블로 가져오기, 다른 프로젝트에서 테이블로 복사, 브랜치 전환 또는 병합, 아카이브에서 복원 또는 프로젝트의 보관된 스냅샷 복원의 일부로 복원, 삭제, 삭제 후 복구, 다시 채우기 전에 테이블을 비우는 그 밖의 모든 작업이 여기에 해당합니다. 제한된 열이 비어 있는 행은 액세스에 빈 행이 포함되지 않는 한 볼 수 없는 행으로 간주됩니다. 본인의 행만 담아 직접 만든 테이블처럼 모든 행을 볼 수 있는 테이블은 교체하거나 삭제할 수 있습니다.

사람이 어떤 테이블에 수행하는 이러한 쓰기는 모두 거부된 경우를 포함하여 보안 로그에 기록됩니다. 워크플로 실행은 여기에 기록되지 않습니다.

### 행 수와 테이블 크기

테이블의 행 수와 저장소 크기는 볼 수 있는 행이 아니라 테이블 전체를 나타내므로, 제한된 사용자에게 부여 범위 밖에 행이 몇 개나 있는지 알려 주게 됩니다. 행을 제한하는 프로젝트에서는 읽기가 필터링되는 모든 사용자에게 프로젝트의 어떤 테이블에 대해서도 행 수나 크기가 표시되지 않습니다. 테이블 목록, 검색, 테이블 세부 정보, 스냅샷, MCP로 연결된 AI 어시스턴트와 AI 도구에서 모두 그렇습니다. 이는 제한된 열이 없는 테이블을 포함하여 프로젝트의 모든 테이블에 적용됩니다. 홈, 프로젝트 목록과 검색, 프로젝트 세부 정보의 총 행 수와 크기 같은 프로젝트 자체의 합계도 이들에게는 숨겨집니다.

워크플로 실행 기록에도 같은 규칙이 적용됩니다. 각 실행과 단계가 기록한 읽은 행 수와 쓴 행 수도 테이블 전체를 나타내므로, 같은 사용자에게는 워크플로와 단계의 실행 기록, 그리고 MCP로 연결된 AI 어시스턴트와 AI 도구에서 해당 수치가 비어 있습니다. 이들에 대해서는 [Weave](/ko/guides/ai-assistant/weave-findings/)가 이전 실행과 달라진 행 수나 빈 값을 단계에서 검사하지 않습니다. 그러한 결과 항목 자체가 테이블 전체의 수가 바뀌었다는 사실을 알려 주기 때문입니다.

프로젝트 아키텍트에게는 이전과 같이 수치가 표시되며, 행을 제한하지 않는 프로젝트의 모든 사용자도 마찬가지입니다.

### 멤버가 볼 수 있는 내용 확인

그룹에 부여된 내용이 아니라 특정 사람이 볼 수 있는 내용을 확인하려면 **Identity → 멤버**를 열고 멤버를 선택한 다음 해당 멤버의 **행 액세스** 탭을 엽니다. **유효 액세스** 열에는 제한된 모든 프로젝트와 열에 대해, 멤버가 모든 그룹을 합쳐서 볼 수 있는 값이 나열됩니다. 여기에는 SSO 그룹 속성의 부여와, 그룹의 부여에 포함된 경우 빈(`NULL`) 행이 포함됩니다. 아키텍트는 모든 행을 읽으므로 프로젝트 아키텍트는 **모든 행 볼 수 있음(Architect)** 으로 표시됩니다. 이는 PlaidCloud 자체 쿼리가 적용하는 것과 같은 결과이므로, 지원 업무와, 누군가 문제를 보고하기 전에 변경이 의도한 대로 되었는지 확인하는 데 유용합니다.

### 더 명확한 오류

행 액세스가 작업을 차단하는 경우, 즉 제한된 프로젝트에서 직접 작성한 쿼리, 아키텍트 없이 하는 편집, 자동화·차원·부여 소스 테이블의 변경, 그 밖에 위에 설명된 경우에는 일반적인 실패 메시지 대신 무엇이 제한되어 있는지와 다음에 해야 할 일, 예를 들어 문의할 아키텍트가 메시지에 명시됩니다.

### 행 액세스 감사

열의 제한 또는 제한 해제와 그룹의 부여 편집은 모두 해당 프로젝트의 [프로젝트 로그](/ko/get-started/tutorials/collaborate-versions-and-sharing/#프로젝트-로그-읽기)에 항목을 기록하며, 누가 언제 변경했는지가 남습니다. 이를 보려면 프로젝트에서 **Analyze → Projects → Log**를 여십시오. 이 기록을 남기기 위해 행 액세스에서 켜야 하는 항목은 없으며, 프로젝트에 대한 다른 추적 대상 변경과 같은 방식으로 기록됩니다.

## 기본 보안 그룹 설정


새 멤버를 추가하는 데 걸리는 시간을 줄이려면 기본 보안 그룹 집합을 지정하십시오. 이렇게 하면 각 사람을 수동으로 할당하지 않고도 새 멤버에게 기본 보안 그룹 집합이 제공됩니다. 새 보안 그룹을 추가할 때 보안 그룹 창 맨 아래에 있는 "기본적으로 새 사용자에게 할당" 확인란을 선택하면 이 설정을 사용할 수 있습니다.



## 보안 감사 수행


보안 감사 기능을 사용하면 모든 멤버와 그룹에 걸친 그룹 멤버십을 볼 수 있습니다.



**보안 감사를 수행하려면 다음과 같이 합니다.**


1. Identity를 엽니다.
2. 레일의 **보안** 아래에서 **그룹 감사**를 선택합니다.

PlaidCloud의 모든 테이블은 CSV 파일 형식으로 내보낼 수 있으므로, 그룹과 멤버의 연결 내용은 과거 기록 용도로든 단지 재미 삼아 오프라인에서 보기 위해서든 PlaidCloud 밖에서 검토할 수 있습니다.



**"보안 그룹 감사" 양식에서 내보내려면 다음과 같이 합니다.**


1. Identity를 엽니다.
2. 레일의 **보안** 아래에서 **그룹 감사**를 선택합니다.
3. 표에서 "사용자 이름" 오른쪽 끝에 있는 작은 아이콘을 클릭합니다.
4. 원하는 형식에 따라 "CSV 내보내기" 또는 "XLXS 내보내기"를 클릭합니다.

## 사용 가능한 권한 설정 보기


워크스페이스에서 사용하는 각 애플리케이션에는 사용 가능한 고유한 권한이 있습니다. 보안 그룹 권한은 이러한 애플리케이션 권한을 기반으로 합니다.


각 애플리케이션에서 사용 가능한 전체 권한 목록은 보안 빈에서 볼 수 있습니다.



**보안 빈에 액세스하려면 다음과 같이 합니다.**


1. Identity를 엽니다.
2. "보안"을 선택합니다.
3. 드롭다운 메뉴에서 "보안 빈"을 클릭합니다.

각 애플리케이션의 자세한 보안 설정을 보려면 가장 왼쪽의 태그 아이콘을 선택합니다.



사용 가능한 보안 설정 정보는 참고용입니다. 권한 관리에 대한 자세한 내용은 위의 보안 그룹 관리 섹션을 참조하십시오.
