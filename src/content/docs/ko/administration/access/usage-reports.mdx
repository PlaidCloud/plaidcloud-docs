**사용 현황 보고서**는 워크스페이스에서 누가 무엇을 사용하는지 보여 줍니다. 멤버가 여는 화면, 대시보드, 앱, 노트북, 다시 방문하는 멤버 수, 그리고 다음에 이동하는 위치를 확인할 수 있습니다. 멤버가 어떤 기능을 도입하는지, 어떤 대시보드와 앱이 제 몫을 하는지, 프로세스의 어느 단계에서 사람들이 이탈하는지 파악하는 데 사용하십시오.

**ID** 탭의 레일에서 **인사이트** 아래에 있는 **사용 현황 보고서**로 엽니다. 별도의 창이 아니라 레일 옆에 ID 안의 페이지로 열립니다.

## 열람 권한

사용 현황 보고서에는 보안 로그와 동일한 권한인 `identity.security_log.read`가 필요합니다. 이 권한이 없으면 버튼이 표시되지 않으며, 그래도 보고서를 여는 멤버에게는 액세스 권한이 없다는 안내가 표시됩니다.

보고서는 다음 위치에서 멤버별 사용 현황을 보여 줍니다. **멤버** 탭, **내용**과 **개요**에서 여는 멤버 목록, 그리고 멤버 ID가 포함된 **구성원별 일별 활동** 및 **최초 사용** 내보내기입니다. 그 밖의 모든 항목은 멤버 전체를 기준으로 집계됩니다. 개별 활동을 볼 수 있어야 하는 사람에게만 이 권한을 부여하십시오.

## 집계 대상

사용 현황 보고서는 다섯 가지 영역을 통합합니다. **영역**에서 하나를 선택하거나 **모든 영역**으로 두십시오.

| 영역 | 기록되는 내용 |
|---|---|
| PlaidCloud 앱 | 멤버가 앱에서 여는 화면과 수행하는 작업입니다. |
| 대시보드 | 대시보드 및 차트 조회입니다. |
| 앱 | 앱 방문과 멤버가 각 앱에서 보낸 시간입니다. |
| 노트북 서버 | 멤버가 노트북 서버 세션에서 보낸 시간입니다. |
| 노트북 | 멤버가 열고 저장하는 노트북입니다. |

노트북 서버와 노트북은 별개의 영역이므로 둘 중 하나를 선택할 수 있습니다. 앱은 하나의 영역입니다. 노트북 이벤트는 기본 노트북 이미지에서 실행되는 노트북에 대해서만 기록됩니다. 사용자 지정 이미지는 이를 보고하지 않습니다.

<Aside type="note">
보고서의 모든 날짜는 UTC 기준입니다. 아메리카 대륙에서 저녁 늦게 작업하는 멤버는 다음 날에 나타날 수 있습니다.
</Aside>

## 보고서 읽기

페이지 상단의 막대에 필터가 있습니다. 각 탭은 처음 열 때와 필터를 변경할 때 다시 로드됩니다.

| 필터 | 기능 |
|---|---|
| **영역** | 보고서를 하나의 영역으로 제한합니다. 단계마다 영역을 선택하는 **퍼널**과 자체 선택 항목이 있는 **내보내기**에서는 숨겨집니다. |
| **그룹** | 보고서를 하나의 보안 그룹 멤버로 제한합니다. [그룹으로 좁히기](#그룹으로-좁히기)를 참조하십시오. |
| **날짜 범위** | **지난 7일**, **지난 30일**, **지난 90일**, **지난 180일**, **이번 달**, **지난달**, 또는 최대 180일까지 시작일과 종료일을 지정하는 **사용자 지정…** 옵션입니다. |
| **새로 고침** | 수치를 다시 로드합니다(F5). **업데이트됨**은 마지막으로 로드한 시점을 보여 줍니다. |

날짜 범위는 모든 탭에서 공유되며, 보고 있던 탭과 선택한 범위는 계정 설정에 저장되므로 어느 컴퓨터에서든 마지막으로 본 위치에서 페이지가 다시 열립니다. 범위를 변경하면 현재 탭이 다시 로드되고, 다른 탭은 열 때 다시 로드됩니다. 각 탭에는 자체 설명이 있으므로 제목이나 숫자에 포인터를 올리면 그 의미를 확인할 수 있습니다.

탭이 로드되는 동안에는 빈 페이지 대신 자리 표시자가 표시됩니다. 보고서를 로드할 수 없으면 탭에 사유가 **다시 시도**와 **Copy details**와 함께 표시됩니다. 범위에 활동이 없으면 탭에서 더 긴 범위를 시도해 보라고 안내합니다. 행을 열려면 두 번 클릭하거나 선택한 다음 Enter 키를 누르십시오. **뒤로**는 연 항목에서 목록으로 돌아갑니다.

### 개요

해당 범위의 주요 수치이며, 각 수치에는 같은 길이의 이전 기간 대비 변화를 보여 주는 화살표와 백분율이 함께 표시됩니다.

| 수치 | 의미 |
|---|---|
| **활성 멤버** | 활동이 있는 멤버입니다. |
| **신규 멤버** | 해당 범위에서 처음 확인된 멤버입니다. 범위가 수집 시작 이전에 시작되면 이전의 최초 사용을 알 수 없으므로 대시로 표시됩니다. |
| **재방문 멤버** | 범위 이전에 처음 확인된 활성 멤버입니다. |
| **활동 시간(분)** | 추정치입니다. 작업이나 조회가 있었던 5분 단위 구간마다 5분으로 계산합니다. |
| **앱 열람 시간(분)** | 앱과 노트북 서버가 열려 있던 시간이며 유휴 시간을 포함합니다. 활동 시간(분)과 별도로 집계됩니다. |
| **이벤트** | 기록된 모든 항목입니다. |

멤버와 연결할 수 없는 이벤트는 수치 아래의 한 줄에 별도로 집계됩니다. 이러한 이벤트는 멤버가 아니라 이벤트로만 집계됩니다.

**Highlights**에는 살펴볼 만한 항목이 최대 네 개 나열되며, 각 항목은 자세한 내용을 볼 수 있는 위치로 연결되는 링크입니다.

- 이전 기간에 비해 활성 멤버가 10% 이상 증가하거나 감소한 경우.
- 해당 범위에서 활동이 없는 멤버 수. 선택하면 비활성 멤버 목록이 열립니다.
- 아무도 열지 않은 대시보드와 앱의 수. 선택하면 사용되지 않은 항목이 먼저 표시된 **내용**이 열립니다.
- 가장 많이 사용된 항목. 최소 5명의 멤버가 사용한 경우에 해당합니다.

하이라이트는 알릴 내용이 있을 때만 표시됩니다. PlaidCloud가 개수를 계산할 수 없으면 0을 표시하는 대신 해당 하이라이트를 숨기며, 눈에 띄는 항목이 없으면 **No notable changes in this range.** 메시지가 표시됩니다.

**Most used**에는 각 화면, 대시보드, 차트 또는 항목이 영역, 이벤트, 멤버 수, 그리고 해당 범위에서 이를 사용한 활성 멤버의 비율인 **도달률**과 함께 나열됩니다. 열 선택기에서 **이벤트**와 **멤버와 연결되지 않은 이벤트**를 추가할 수 있습니다. **월별(전체 기록)** 항목에는 월별 활성 멤버, 일평균 멤버, **고착도**가 표시되며, 해당 월이 아직 진행 중이거나 일부만 포함된 경우 안내가 함께 표시됩니다. 고착도는 일평균 활성 멤버를 해당 월의 활성 멤버로 나눈 값이므로, 값이 높을수록 사람들이 더 많은 날에 다시 방문한다는 뜻입니다.

### 활동

**매일**, **매주** 또는 **매월** 기간별 활성 멤버와 **첫 주 기준 리텐션**을 보여 줍니다. 리텐션은 멤버가 처음 나타난 주별로 **Cohort size**와 이후 각 주에 여전히 활동 중인 멤버의 비율을 나타냅니다. 별표가 붙은 기간은 전체가 범위 안에 있지 않습니다.

### 경로

영역 전반에서 화면 간에 가장 많이 이루어진 이동을 **이동 출발**, **이동 도착**, **이동 횟수**로 보여 줍니다. 경로는 최대 지난 30일까지만 다룹니다.

### 멤버

**표시**는 두 가지 목록 사이를 전환합니다.

- **활성**에는 해당 범위에서 확인된 멤버당 한 행이 있으며 이름, 사용자 이름, 활동 일수, 이벤트, 활동 시간(분), 앱 열람 시간(분), 처음 및 마지막으로 확인된 시점이 표시됩니다. 행을 열면 해당 멤버의 일별 이벤트와 사용한 항목을 볼 수 있습니다.
- **비활성**에는 해당 범위에서 활동이 없는 현재 멤버가 멤버가 된 시점과 마지막으로 확인된 시점과 함께 나열됩니다. **None recorded**는 보관된 기록에 활동이 없음을 의미하며, 보관 기간은 최대 25개월이고 수집이 시작된 이후부터만 해당합니다. **CSV 다운로드**로 목록을 다운로드합니다. 비활성은 모든 영역에서 활동이 없음을 의미하므로 **영역**을 무시합니다. 워크스페이스에서 제거되었거나 비활성화된 멤버는 나열되거나 집계되지 않습니다.

### 내용

모든 대시보드, 앱, 노트북이 **유형**, **멤버**, **도달률**, **열람**, **앱 열람 시간(분)**(앱에만 해당), 주별 **추세**, **마지막 사용** 시점과 함께 표시됩니다. **유형**을 선택하여 목록을 좁히거나, **Hide unused**를 선택하여 아무도 열지 않은 항목을 제외하십시오. 행을 열면 해당 항목을 사용한 멤버를 볼 수 있으며, **CSV 다운로드**로 두 목록 모두 다운로드할 수 있습니다. 목록 아래의 안내는 아직 수집되지 않았거나 이후 날짜부터만 수집된 유형을 알려 줍니다.

### 그룹으로 좁히기

**그룹**은 **개요**, **내용**, **비활성** 목록을 하나의 보안 그룹 멤버로 제한합니다. 제한을 해제하려면 **모든 사람**을 선택하십시오. 상자에 입력하여 워크스페이스의 그룹을 검색합니다. 보고서는 활동이 발생한 시점이 아니라 현재의 그룹 멤버십을 사용하며, 필터 옆에 그 사실이 표시됩니다.

- **활성** 멤버, **활동**, **경로**, **내보내기**는 좁혀지지 않습니다. 해당 탭에서는 필터가 비활성화되며 그 이유가 표시됩니다.
- 월별 기록은 모든 사용자를 대상으로 보관되므로 그룹에는 **월별**이 표시되지 않습니다.
- 멤버가 없는 그룹이나 더 이상 존재하지 않는 그룹은 오류가 아니라 빈 결과와 그 사실을 알리는 경고를 반환합니다.
- 워크스페이스의 보안 그룹을 읽을 수 없으면 필터가 제공되지 않습니다.

### 내보내기

요약을 CSV로 다운로드합니다. **요약**과 **날짜 범위**를 선택한 다음 **CSV 다운로드**를 선택하십시오. 범위는 최대 25개월입니다.

| 요약 | 내용 |
|---|---|
| **일별 활동** | 날짜, 영역, 이벤트, 대상별 멤버와 이벤트입니다. |
| **구성원별 일별 활동** | 멤버 ID와 함께 각 멤버에 대해 같은 정보를 제공합니다. |
| **월별 도입률** | 월, 영역, 이벤트, 대상별 멤버와 이벤트입니다. |
| **월별 활성 멤버** | 월과 영역별 활성 멤버입니다. |
| **최초 사용** | 각 멤버가 각 영역을 처음 사용한 시점이며 멤버 ID가 포함됩니다. |

내보내기는 탭 위에서 선택한 영역을 사용합니다. 큰 요약은 최대 50,000행 단위로 나누어 다운로드되며, 페이지가 이를 하나의 파일로 합칩니다. 파일이 페이지에서 만들 수 있는 크기보다 크면 가진 만큼 저장하고 파일이 불완전하다고 알려 줍니다. 나머지를 받으려면 더 짧은 범위를 선택하십시오.

모든 내보내기는 누가 어떤 요약을, 어떤 범위로, 몇 행을 내보냈는지 기록하는 항목을 보안 로그에 남깁니다. 여러 배치에 걸친 요약은 배치마다 항목을 남깁니다.

이러한 수치를 일정에 따라 테이블에 넣으려면 [Get Workspace Usage 단계](/ko/reference/workflow-steps/general/get-workspace-usage/)를 사용하십시오.

<Aside type="caution">
월별 요약에는 각 이벤트의 합계 행이 포함되며, 대상은 `*`입니다. 이 행은 해당 이벤트의 모든 대상에 걸친 고유 멤버와 이벤트를 나타냅니다. 이 행을 대상 행에 더하지 마십시오. 모든 항목이 두 번 집계됩니다.
</Aside>

### 퍼널

멤버가 일련의 단계를 거치는 수를 확인합니다. 단계는 특정 대상 또는 **모든 대상**에 대한, 영역 중 하나의 이벤트입니다. 퍼널은 선택한 날짜 범위를 최대 지난 90일까지 사용하며, 더 긴 범위를 줄일 때는 그 사실을 알려 줍니다.

1. **단계 추가**를 선택하고 각 단계의 영역, 이벤트, 대상을 선택합니다. 퍼널은 2~6개의 단계로 구성됩니다.
2. **단계 간 허용 시간**을 선택합니다. 1, 6, 24, 72 또는 168시간 중에서 고릅니다.
3. **퍼널 실행**을 선택합니다.

결과에는 각 단계에 도달한 멤버 수, 시작한 멤버 대비 비율, 이전 단계로부터의 중앙값 시간이 표시됩니다. 마지막 단계를 제외한 각 단계에는 그 지점에서 멈춘 멤버 수가 표시됩니다. 마지막 단계에는 퍼널을 완료한 멤버 수가 표시됩니다. 단계에서 영역을 섞을 수 있으므로 멤버가 PlaidCloud 화면에서 대시보드로 이동하는 과정을 따라갈 수 있습니다. **최근 퍼널**은 이전에 실행한 퍼널을 다시 엽니다. 단계 목록에는 해당 범위에 기록된 이벤트만 제공됩니다.

## 귀속되지 않은 사용 현황

일부 이벤트는 PlaidCloud 멤버와 연결할 수 없습니다. 이러한 이벤트는 **이벤트**와 **미귀속 이벤트**에는 집계되지만 멤버 수에는 집계되지 않습니다. 주요 사례는 다음과 같습니다.

- PlaidCloud를 통하지 않고 Superset 내부에서 생성된 Superset 계정.
- Superset 사용자가 없는 임베디드 대시보드 조회.
- 플랫폼 로그에서 멤버와 연결할 수 없는 앱 및 노트북 서버 활동. 이 활동의 귀속은 해당 로그에서 가져오므로 최선의 추정치로 취급하십시오.

한 영역에서 귀속되지 않은 비율이 크면 해당 영역의 멤버 수가 실제보다 적게 집계된 것입니다.

## 기록이 시작되는 시점

기록은 워크스페이스에서 사용 현황 수집을 켠 시점부터 시작되며, 그 이전의 날짜나 월에는 활동이 표시되지 않습니다. 데이터가 있는 첫 번째 월은 부분 데이터로 표시됩니다.

Panel과 JupyterHub는 약 90일 동안 보관되는 플랫폼 로그에서 읽습니다. 수집이 시작되면 이 두 영역은 그 기간만큼의 이전 기록만 채워집니다. Superset은 자체 로그에서 최대 180일까지 채워집니다. 수집이 시작될 때 아무것도 없는 상태에서 시작하는 것은 PlaidCloud 앱뿐입니다.

사용 현황 보고서는 원시 이벤트를 180일 동안 보관하므로 가장 긴 범위가 180일이며, 월별 요약은 25개월 동안 보관합니다. SCIM이나 Keycloak 등 PlaidCloud 외부에서 멤버를 제거하면 해당 멤버의 원시 사용 기록은 180일 후에, 최초 사용 기록은 25개월 후에 만료됩니다.

## 멤버의 사용 기록 삭제

`identity.security_log.read` 권한이 있는 워크스페이스 관리자(또는 슈퍼 사용자)는 한 멤버의 사용 기록을 삭제하고 수집을 중단했다가 나중에 삭제를 해제할 수 있습니다. 삭제와 복원 모두 해당 권한과 역할이 필요합니다. 이 두 작업은 REST API로만 사용할 수 있습니다.

| 작업 | 요청 |
|---|---|
| 삭제 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 복원 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

삭제하면 멤버의 이벤트와 최초 사용 기록이 제거되며, 그 시점부터 보고서와 내보내기에서 해당 멤버가 제외됩니다. 해당 멤버의 사용 기록은 다시 수집되지 않으며, 이후 Panel과 JupyterHub 로그에서 읽어 오는 기록도 삭제됩니다. 제거를 한 번에 완료할 수 없으면 응답에 그 사실이 표시되며 다음 시간별 유지 관리 실행에서 완료됩니다.

복원하면 삭제가 해제되어 새 활동이 다시 수집됩니다. 삭제된 내용은 복구되지 않습니다.

두 작업 모두 보안 로그에 항목을 남깁니다.
