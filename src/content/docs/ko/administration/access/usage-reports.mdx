**사용 현황 보고서**는 워크스페이스에서 누가 무엇을 사용하는지 보여 줍니다. 사람들이 어떤 화면, 대시보드, 앱, 노트북을 여는지, 얼마나 많은 사람이 다시 돌아오는지, 다음에 어디로 이동하는지 확인할 수 있습니다. 이 보고서를 통해 멤버가 어떤 기능을 도입하는지, 어떤 대시보드, 앱, 노트북이 제 역할을 하고 어떤 것을 아무도 사용하지 않는지, 누가 한동안 접속하지 않았는지, 프로세스의 어느 지점에서 사람들이 이탈하는지 파악합니다.

**ID** 탭에서 보안 로그 옆에 있는 항목으로 엽니다.

## 열람 권한

사용 현황 보고서에는 보안 로그와 같은 권한인 `identity.security_log.read`가 필요합니다. 이 권한이 없으면 해당 버튼이 표시되지 않으며, 그래도 보고서를 연 멤버에게는 액세스 권한이 없다는 알림이 표시됩니다.

보고서는 여러 위치에서 멤버별 사용 현황을 보여 줍니다. **사용자** 탭과 멤버 프로필, **내용** 탭의 각 항목별 멤버 목록, 그리고 멤버 ID가 포함된 **구성원별 일별 활동** 및 **최초 사용** 내보내기가 해당합니다. 그 밖의 모든 항목은 멤버 전체를 합산한 값입니다. 개별 활동을 확인해야 하는 사람에게만 이 권한을 부여하십시오.

특정 멤버의 프로필을 열거나, **미확인** 멤버를 나열하거나, 항목의 멤버 목록을 열거나, CSV를 다운로드할 때마다 보안 로그에 항목이 기록됩니다. [개인정보 보호 및 감사](#개인정보-보호-및-감사)를 참고하십시오.

## 집계 대상

사용 현황 보고서는 다음 소스를 결합합니다. **소스**에서 하나를 선택하거나 **모든 소스**로 그대로 둘 수 있습니다.

| 소스 | 기록되는 내용 |
|---|---|
| PlaidCloud 앱 | 멤버가 여는 화면과 앱에서 수행하는 작업입니다. |
| Superset | 대시보드와 차트 조회입니다. |
| 패널 앱 | 앱 방문과 멤버가 각 앱에서 보낸 시간입니다. |
| 앱 방문 | Dash 앱과 WASM 앱 방문입니다. |
| JupyterHub | 멤버가 JupyterHub 세션에서 보낸 시간입니다. |
| Jupyter 노트북 | 멤버가 열고 저장하는 노트북입니다. |

JupyterHub 세션과 Jupyter 노트북은 별개의 소스이므로 둘 중 하나를 선택할 수 있습니다. 패널 앱은 하나의 소스이며, 앱 방문은 Dash 앱과 WASM 앱을 포함합니다. 노트북 이벤트는 기본 노트북 이미지에서 실행되는 노트북에 대해서만 기록됩니다. 사용자 지정 이미지는 이를 보고하지 않습니다.

이벤트, 소스, 화면은 내부 코드가 아니라 Dash 앱 열림, WASM 앱 열림, 노트북 열림, 앱 방문과 같은 읽기 쉬운 이름으로 표시됩니다. 이후에 삭제된 대시보드나 앱은 삭제된 대시보드 또는 삭제된 앱으로 표시됩니다.

<Aside type="note">
보고서의 모든 날짜는 UTC 기준입니다. 미주 지역에서 저녁 늦게 작업하는 멤버는 다음 날에 나타날 수 있습니다.
</Aside>

## 보고서 보기

창 위쪽에서 소스와 **날짜 범위**를 선택한 다음 **새로 고침**을 선택합니다. 범위는 최근 7일, 30일, 90일, 180일입니다. 각 탭은 처음 열 때, 그리고 소스나 범위를 변경할 때 다시 로드됩니다.

### 개요

해당 범위의 주요 수치입니다.

| 수치 | 의미 |
|---|---|
| **활성 사용자** | 활동이 하나라도 있는 멤버입니다. |
| **신규 사용자** | 해당 범위에서 처음 확인된 멤버입니다. |
| **재방문 사용자** | 범위 이전에 처음 확인된 활성 멤버입니다. |
| **활동 시간(분)** | 추정값입니다. 작업이나 조회가 하나라도 있는 5분 구간마다 5분으로 계산합니다. |
| **이벤트** | 기록된 모든 항목입니다. |
| **미귀속 이벤트** | 멤버를 특정할 수 없는 이벤트입니다. 이벤트로는 집계되지만 사용자로는 집계되지 않습니다. |
| **앱 열림 시간(분)** | 패널 앱과 JupyterHub 서버가 열려 있던 시간이며, 유휴 시간을 포함합니다. 활동 시간(분)과는 별도로 집계합니다. |

각 수치에는 같은 길이의 직전 기간과 비교한 **변경 사항**이 표시됩니다. 예를 들어 30일 범위는 그 이전 30일과 비교합니다. **새로 만들기**는 수치가 0에서 증가했음을 뜻합니다. 대시(**—**)는 직전 기간이 보관된 기록으로 완전히 채워지지 않아 공정하게 비교할 대상이 없음을 뜻합니다.

워크스페이스의 기록이 범위 안에서 시작되는 경우 **기록 시작** 배너에 해당 날짜가 표시됩니다. 그 이전 날짜에 활동이 없는 것으로 보이는 이유는 아무도 제품을 사용하지 않았기 때문이 아니라 수집된 데이터가 없기 때문입니다.

**도입률**은 각 화면, 대시보드, 차트 또는 항목을 소스, 이벤트, 사용자 수, 활성 사용자 중 비율, 이벤트, 미귀속 이벤트와 함께 나열합니다. **월별**은 월마다 활성 사용자, 일평균 사용자, 고착도(stickiness)를 보여 주며, 해당 월이 아직 진행 중이거나 일부만 집계되었거나 고정된 스냅샷이면 그 사실을 알리는 참고 문구가 표시됩니다.

### 활동

**매일**, **매주** 또는 **매월** 기간별 활성 사용자와 함께 **첫 주 기준 리텐션**을 보여 줍니다. 리텐션은 멤버가 처음 나타난 주마다 이후 각 주에 몇 명이 다시 돌아왔는지를 나타냅니다. 별표가 붙은 기간은 전체가 범위 안에 있지 않은 기간입니다.

### 경로

화면 간 이동 중 가장 많이 사용된 경로를 앱과 소스에 걸쳐 **이동 출발**, **이동 도착**, **이동 횟수**로 보여 줍니다. 경로는 최대 최근 30일을 대상으로 합니다.

### 사용자

**확인됨** 또는 **미확인**을 선택합니다.

**확인됨**은 멤버마다 한 행을 표시합니다. 이름, 사용자 이름, 활동 일수, 이벤트, **활동 시간(분)**, **앱 열림 시간(분)**, 처음 확인된 시점과 마지막으로 확인된 시점이 표시됩니다. 멤버를 선택하면 해당 프로필이 열립니다.

멤버의 프로필에는 **활동 일수**, **이벤트**, **활동 시간(분)**, **앱 열림 시간(분)**, 처음과 마지막으로 확인된 시점, 일별 이벤트 차트, 그리고 사용한 항목이 표시됩니다. 각 항목에는 소스, 이벤트, 이벤트 수, 마지막 사용 시점이 함께 표시됩니다. 항목은 대시보드나 앱 제목과 같은 읽기 쉬운 이름으로 나타납니다. **뒤로**를 선택하면 목록으로 돌아갑니다.

**미확인**은 범위 안에 활동이 없는 멤버를 **가입일**과 **마지막 확인** 날짜와 함께 나열합니다. **기록 없음**은 보관된 기록, 즉 최대 25개월 이내이면서 수집이 시작된 이후의 기록에 활동이 없음을 뜻합니다. **CSV 다운로드**를 선택하면 목록을 저장합니다.

### 내용

각 대시보드, 패널 앱, Dash 앱, WASM 앱, 노트북이 얼마나 사용되는지 확인합니다. **유형**으로 필터링하거나 모든 유형으로 그대로 둘 수 있습니다.

| 열 | 의미 |
|---|---|
| **이름** | 항목의 이름입니다. 삭제된 항목은 삭제된 대시보드 또는 삭제된 앱으로 표시됩니다. 노트북은 몇 사람의 서버에 있든 경로 기준으로 한 번만 집계합니다. |
| **유형** | 대시보드, 패널 앱, Dash 앱, WASM 앱 또는 노트북입니다. |
| **사용자** | 해당 범위에서 사용한 고유 멤버 수입니다. |
| **도입률** | 해당 범위의 활성 사용자 중 사용자가 차지하는 비율입니다. |
| **열람** | 대시보드는 페이지 로드, 패널 앱은 시작된 세션, 노트북은 멤버당 노트북당 30분마다 한 번씩 계산한 열기, Dash 앱과 WASM 앱은 방문입니다. |
| **앱 열림 시간(분)** | 패널 앱에만 해당합니다. 앱이 열려 있던 시간이며, 유휴 시간을 포함합니다. |
| **추세** | 범위 내 주간 열람 수이며, 오래된 순서입니다. |
| **마지막 사용(UTC)** | 멤버가 마지막으로 사용한 시점입니다. |

범위 안에서 아무도 사용하지 않은 항목도 함께 나열되므로 정리할 대상을 파악할 수 있습니다. 이러한 항목을 제외하려면 **사용되지 않는 항목 숨기기**를 선택합니다. 항목을 선택하면 해당 항목을 사용한 멤버가 **열람** 수 및 각자 마지막으로 사용한 시점과 함께 표시됩니다. **CSV 다운로드**는 항목 목록 또는 항목의 멤버 목록을 저장합니다.

노트북은 누군가 열어 본 뒤에 나타납니다. Dash 앱과 WASM 앱 방문은 이 릴리스가 워크스페이스에 적용된 시점부터만 집계되며, 목록 위의 참고 문구에 각 유형의 수집이 시작된 시점이 표시됩니다.

대시보드와 앱의 이름을 조회할 수 없으면 **지금은 이름을 사용할 수 없으므로 아무도 사용하지 않은 항목은 표시되지 않습니다**라는 경고가 표시됩니다. 사용된 항목은 계속 표시됩니다.

### 내보내기

요약을 CSV로 다운로드합니다. **요약**과 최대 25개월의 **날짜 범위**를 선택한 다음 **CSV 다운로드**를 선택합니다.

| 요약 | 내용 |
|---|---|
| **일별 활동** | 일, 소스, 이벤트, 대상별 사용자 수와 이벤트 수입니다. |
| **구성원별 일별 활동** | 위와 같은 내용을 멤버별로 보여 주며, 멤버 ID가 포함됩니다. |
| **월별 도입률** | 월, 소스, 이벤트, 대상별 사용자 수와 이벤트 수입니다. |
| **월간 활성 사용자** | 월과 소스별 활성 사용자 수입니다. |
| **최초 사용** | 각 멤버가 각 소스를 처음 사용한 시점이며, 멤버 ID가 포함됩니다. |

내보내기는 탭 위에서 선택한 소스를 사용합니다. 큰 요약은 최대 50,000행씩 나뉘어 다운로드되며, 창에서 이를 하나의 파일로 결합합니다. 파일이 창에서 만들 수 있는 크기보다 크면 현재까지의 내용을 저장하고 파일이 불완전하다고 알려 줍니다. 나머지를 받으려면 더 짧은 범위를 선택하십시오.

내보낼 때마다 누가 어떤 요약을 어떤 범위로 몇 행 내보냈는지 보안 로그에 기록됩니다. 여러 배치에 걸친 요약은 배치마다 항목이 기록됩니다.

<Aside type="caution">
월별 요약에는 각 이벤트의 합계 행이 포함되며, 대상은 `*`입니다. 이 행은 해당 이벤트의 모든 대상에 걸친 고유 사용자 수와 이벤트 수입니다. 대상 행에 이 행을 더하지 마십시오. 그렇게 하면 모든 것이 두 번 집계됩니다.
</Aside>

### 퍼널

일련의 단계를 거치는 멤버가 몇 명인지 확인합니다. 단계는 소스 중 하나에서 발생한 이벤트이며, 특정 대상 또는 **모든 대상**에 대해 지정합니다.

1. **단계 추가**를 선택하고 각 단계의 소스, 이벤트, 대상을 선택합니다. 퍼널은 2~6개의 단계로 구성됩니다.
2. **단계 간 허용 시간**을 1, 6, 24, 72 또는 168시간 중에서 선택합니다.
3. **날짜 범위**를 7일, 30일 또는 90일 중에서 선택합니다.
4. **퍼널 실행**을 선택합니다.

결과에는 각 단계에 도달한 멤버 수, 시작한 멤버 중 비율, 해당 단계에서 멈춘 멤버 수, 이전 단계로부터의 중앙값 소요 시간이 표시됩니다. 단계에는 여러 소스를 섞을 수 있으므로 PlaidCloud 화면에서 Superset 대시보드까지 멤버를 따라갈 수 있습니다. **최근 퍼널**은 이전에 실행한 퍼널을 다시 엽니다. 단계 목록에는 해당 범위에서 기록된 이벤트만 표시됩니다.

## 귀속되지 않은 사용 현황

일부 이벤트는 PlaidCloud 멤버와 연결할 수 없습니다. 이러한 이벤트는 **이벤트**와 **미귀속 이벤트**에는 집계되지만 사용자 수에는 집계되지 않습니다. 주요 사례는 다음과 같습니다.

- PlaidCloud를 통하지 않고 Superset 안에서 생성된 Superset 계정.
- Superset 사용자가 없는 임베드된 대시보드의 조회.
- 플랫폼 로그에서 멤버와 연결할 수 없는 패널 및 JupyterHub 활동. 이러한 활동의 귀속은 해당 로그에 의존하므로 최선의 추정으로 간주하십시오.

소스에서 귀속되지 않은 비율이 크면 해당 소스의 사용자 수는 실제보다 적게 집계된 것입니다.

## 기록 시작 시점

기록은 워크스페이스에서 사용 현황 수집을 켠 시점부터 시작되며, 그 이전의 일이나 월에는 활동이 표시되지 않습니다. 데이터가 있는 첫 번째 월은 부분 집계로 표시됩니다.

패널과 JupyterHub는 약 90일 동안 보관되는 플랫폼 로그에서 읽어 옵니다. 수집이 시작되면 이 두 소스는 최대 그 기간만큼 이전 기록을 채웁니다. Superset은 자체 로그에서 최대 180일까지 채웁니다. 수집이 시작될 때 처음부터 시작하는 것은 PlaidCloud 앱뿐입니다.

사용 현황 보고서는 상세 활동을 180일 동안 보관하며, 이것이 가장 긴 범위가 180일인 이유입니다. 또한 각 멤버와 항목의 최초 및 마지막 사용 시점은 월별 요약과 함께 25개월 동안 보관합니다. 180일보다 이전에 시작하는 범위에서는 누가 활동하지 않았는지 판단하는 데 필요한 상세 정보가 없어졌으므로 **미확인** 목록과 아무도 사용하지 않은 항목 대신 경고가 표시됩니다. SCIM이나 Keycloak 등 PlaidCloud 외부에서 멤버가 제거되면 해당 멤버의 원시 사용 기록은 180일 후에, 최초 사용 기록은 25개월 후에 사라집니다.

## 개인정보 보호 및 감사

특정 멤버의 사용 현황을 조회하는 것 자체도 감사 대상입니다. 다음 작업은 수행한 사람을 기록하는 항목이 보안 로그에 남습니다.

- 특정 멤버의 프로필 열기.
- **미확인** 멤버 나열.
- 항목을 사용한 멤버 목록 열기.
- **내보내기** 탭, **미확인** 목록 또는 **내용** 탭에서의 모든 CSV 다운로드.

`identity.security_log.read` 권한이 있는 멤버만 보고서를 열 수 있습니다.

## 멤버의 사용 기록 삭제

`identity.security_log.read` 권한이 있는 워크스페이스 관리자(또는 슈퍼 사용자)는 한 멤버의 사용 기록을 삭제하고 수집을 중단할 수 있으며, 나중에 삭제 상태를 해제할 수도 있습니다. 삭제와 복원 모두 해당 권한과 역할이 필요합니다. 이 두 작업은 REST API로만 사용할 수 있습니다.

| 작업 | 요청 |
|---|---|
| 삭제 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 복원 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

삭제하면 해당 멤버의 이벤트와 최초 사용 기록이 제거되며, 그 시점부터 보고서와 내보내기에서 해당 멤버가 제외됩니다. 이후 해당 멤버의 사용 기록은 다시 수집되지 않으며, 나중에 패널 및 JupyterHub 로그에서 읽어 오는 기록도 제외됩니다. 제거를 즉시 완료할 수 없는 경우 응답에서 이를 알려 주며, 다음 시간별 유지 관리 실행에서 완료됩니다.

복원하면 삭제 상태가 해제되어 새로운 활동이 다시 수집됩니다. 삭제된 내용은 복구되지 않습니다.

두 작업 모두 보안 로그에 항목이 기록됩니다.
