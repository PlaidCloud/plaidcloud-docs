**사용 현황 보고서**는 워크스페이스에서 누가 무엇을 사용하는지 보여 줍니다. 사람들이 어떤 화면, 대시보드, 앱, 노트북을 열었는지, 몇 명이 다시 방문하는지, 다음에 어디로 이동하는지를 확인할 수 있습니다. 멤버가 무엇을 도입하는지, 어떤 대시보드와 앱이 제 몫을 하는지, 프로세스의 어느 지점에서 사람들이 이탈하는지 파악하는 데 활용하십시오.

**ID** 탭에서 보안 로그 옆에 있는 항목으로 엽니다.

## 열람 권한

사용 현황 보고서에는 보안 로그와 같은 권한인 `identity.security_log.read`가 필요합니다. 이 권한이 없으면 버튼이 표시되지 않으며, 그래도 보고서를 여는 멤버에게는 접근 권한이 없다는 알림이 표시됩니다.

보고서는 두 곳에서 멤버별 사용 현황을 보여 줍니다. **사용자** 탭, 그리고 멤버 ID가 포함된 **구성원별 일별 활동** 및 **최초 사용** 내보내기입니다. 그 밖의 모든 항목은 멤버 전체를 합산해 집계합니다. 개별 활동을 볼 수 있어야 하는 사람에게만 이 권한을 부여하십시오.

## 집계 대상

사용 현황 보고서는 다섯 가지 소스를 결합합니다. **소스**에서 하나를 선택하거나 **모든 소스**로 두십시오.

| 소스 | 기록되는 내용 |
|---|---|
| PlaidCloud 앱 | 멤버가 여는 화면과 앱에서 수행하는 작업. |
| Superset | 대시보드 및 차트 조회. |
| 패널 앱 | 앱 방문과 멤버가 각 앱에서 보내는 시간. |
| JupyterHub | 멤버가 JupyterHub 세션에서 보내는 시간. |
| Jupyter 노트북 | 멤버가 열고 저장하는 노트북. |

JupyterHub 세션과 Jupyter 노트북은 별개의 소스이므로 둘 중 하나를 선택할 수 있습니다. 패널 앱은 하나의 소스입니다. 노트북 이벤트는 기본 노트북 이미지에서 실행되는 노트북에 대해서만 기록됩니다. 사용자 지정 이미지는 이를 보고하지 않습니다.

<Aside type="note">
보고서의 모든 날짜는 UTC 기준입니다. 아메리카 대륙에서 저녁 늦게 작업하는 멤버는 다음 날에 표시될 수 있습니다.
</Aside>

## 보고서 읽기

창 상단에서 소스와 **날짜 범위**를 선택한 다음 **새로 고침**을 선택합니다. 범위는 최근 7일, 30일, 90일 또는 180일입니다. 각 탭은 처음 열 때, 그리고 소스나 범위를 변경할 때 다시 로드됩니다.

### 개요

선택한 범위의 핵심 수치입니다.

| 수치 | 의미 |
|---|---|
| **활성 사용자** | 활동이 있는 멤버. |
| **신규 사용자** | 해당 범위에서 처음 확인된 멤버. |
| **재방문 사용자** | 범위 이전에 처음 확인된 활성 멤버. |
| **활동 시간(분)** | 근사치: 활동이 있는 구간마다 5분으로 계산. |
| **이벤트** | 기록된 모든 항목. |
| **미귀속 이벤트** | 멤버를 특정할 수 없는 이벤트. 이벤트로는 집계되지만 사용자로는 집계되지 않습니다. |
| **세션 시간(분)** | 패널 및 JupyterHub 세션 시간으로, 활동 시간과 별도로 집계됩니다. |

**도입률**에는 각 화면, 대시보드, 차트 또는 항목이 소스, 이벤트, 사용자 수, 활성 사용자 중 비율, 이벤트, 미귀속 이벤트와 함께 나열됩니다. **월별**에는 월마다 활성 사용자, 일평균 사용자, 고착도가 표시되며, 해당 월이 아직 진행 중이거나 일부만 포함되었거나 고정된 스냅샷인 경우 이를 알리는 참고가 함께 표시됩니다.

### 활동

**매일**, **매주** 또는 **매월** 기간별 활성 사용자와 **첫 주 기준 리텐션**을 보여 줍니다. 리텐션은 멤버가 처음 나타난 주마다 그 이후 각 주에 몇 명이 다시 방문했는지를 나타냅니다. 별표가 붙은 기간은 전체가 범위 안에 있지 않습니다.

### 경로

화면 간에 가장 많이 이루어진 이동을 앱과 소스에 걸쳐 **이동 출발**, **이동 도착**, **이동 횟수**로 보여 줍니다. 경로는 최대 최근 30일을 다룹니다.

### 사용자

멤버당 한 행으로, 이름, 사용자 이름, 활동 일수, 이벤트, 활동 시간(분), 세션 시간(분), 처음 및 마지막으로 확인된 시점이 표시됩니다.

### 내보내기

요약을 CSV로 다운로드합니다. **요약**과 최대 25개월의 **날짜 범위**를 선택한 다음 **CSV 다운로드**를 선택합니다.

| 요약 | 내용 |
|---|---|
| **일별 활동** | 날짜, 소스, 이벤트, 대상별 사용자 및 이벤트. |
| **구성원별 일별 활동** | 멤버별로 동일한 내용이며 멤버 ID가 포함됩니다. |
| **월별 도입률** | 월, 소스, 이벤트, 대상별 사용자 및 이벤트. |
| **월간 활성 사용자** | 월 및 소스별 활성 사용자. |
| **최초 사용** | 각 멤버가 각 소스를 처음 사용한 시점이며 멤버 ID가 포함됩니다. |

내보내기에는 탭 위에서 선택한 소스가 사용됩니다. 큰 요약은 최대 50,000행 단위의 배치로 다운로드되며, 창에서 이를 하나의 파일로 합칩니다. 파일이 창이 생성할 수 있는 크기보다 크면 현재까지의 내용을 저장하고 파일이 불완전하다고 알려 줍니다. 나머지를 받으려면 더 짧은 범위를 선택하십시오.

내보내기를 수행할 때마다 보안 로그에 누가 어떤 요약을 어떤 범위로 몇 행 내보냈는지 기록하는 항목이 작성됩니다. 여러 배치에 걸친 요약은 배치마다 항목을 작성합니다.

<Aside type="caution">
월별 요약에는 이벤트마다 대상이 `*`인 합계 행이 포함됩니다. 이 행은 해당 이벤트의 모든 대상에 걸친 고유 사용자 수와 이벤트 수입니다. 대상 행에 더하지 마십시오. 그렇게 하면 모든 항목이 두 번 집계됩니다.
</Aside>

### 퍼널

멤버가 일련의 단계를 거치는 비율을 확인합니다. 단계는 소스 중 하나의 이벤트를 특정 대상 또는 **모든 대상**에 대해 지정한 것입니다.

1. **단계 추가**를 선택하고 각 단계의 소스, 이벤트, 대상을 선택합니다. 퍼널은 2~6개의 단계로 구성됩니다.
2. **단계 간 허용 시간**을 선택합니다. 1, 6, 24, 72 또는 168시간 중에서 고를 수 있습니다.
3. 7일, 30일 또는 90일 중에서 **날짜 범위**를 선택합니다.
4. **퍼널 실행**을 선택합니다.

결과에는 단계마다 도달한 멤버 수, 시작한 멤버 중 비율, 해당 단계에서 중단한 멤버 수, 이전 단계로부터의 소요 시간 중앙값이 표시됩니다. 단계에는 여러 소스를 섞을 수 있으므로 PlaidCloud 화면에서 Superset 대시보드로 이동하는 멤버를 따라갈 수 있습니다. **최근 퍼널**에서는 이전에 실행한 퍼널을 다시 열 수 있습니다. 단계 목록에는 해당 범위에서 기록된 이벤트만 표시됩니다.

## 미귀속 사용 기록

일부 이벤트는 PlaidCloud 멤버와 연결할 수 없습니다. 이러한 이벤트는 **이벤트**와 **미귀속 이벤트**에는 집계되지만 사용자 수에는 절대 집계되지 않습니다. 주요 사례는 다음과 같습니다.

- PlaidCloud를 거치지 않고 Superset 내부에서 생성된 Superset 계정.
- Superset 사용자가 없는 임베디드 대시보드 조회.
- 플랫폼 로그로 멤버를 특정할 수 없는 패널 및 JupyterHub 활동. 이들의 귀속은 해당 로그에서 가져오므로 최선의 추정치로 보십시오.

한 소스에서 미귀속 비중이 크다면 해당 소스의 사용자 수가 실제보다 적게 집계된 것입니다.

## 이력의 시작 시점

이력은 워크스페이스에서 사용 현황 수집을 켠 시점부터 시작되며, 그 이전의 날짜나 월에는 활동이 표시되지 않습니다. 데이터가 있는 첫 달은 일부만 포함된 것으로 표시됩니다.

패널과 JupyterHub는 약 90일 동안 보관되는 플랫폼 로그에서 읽어 옵니다. 수집이 시작되면 이 두 소스는 최대 그 기간만큼의 이전 이력을 채웁니다. Superset은 자체 로그에서 최대 180일까지 채웁니다. 수집이 시작될 때 처음부터 시작하는 것은 PlaidCloud 앱뿐입니다.

사용 현황 보고서는 원시 이벤트를 180일 동안 보관하므로 가장 긴 범위가 180일이며, 월별 요약은 25개월 동안 보관합니다. SCIM이나 Keycloak 등 PlaidCloud 외부에서 멤버를 제거하면 해당 멤버의 원시 사용 기록은 180일 후에, 최초 사용 기록은 25개월 후에 만료되어 삭제됩니다.

## 멤버의 사용 기록 삭제

`identity.security_log.read` 권한을 가진 워크스페이스 관리자(또는 슈퍼 사용자)는 한 멤버의 사용 기록을 삭제하고 수집을 중단할 수 있으며, 나중에 삭제를 해제할 수도 있습니다. 삭제와 복원 모두 해당 권한과 역할이 필요합니다. 이 두 작업은 REST API를 통해서만 사용할 수 있습니다.

| 작업 | 요청 |
|---|---|
| 삭제 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 복원 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

삭제하면 해당 멤버의 이벤트와 최초 사용 기록이 제거되며, 그 시점부터 보고서와 내보내기에서 해당 멤버가 제외됩니다. 이후 해당 멤버의 사용 기록은 수집되지 않으며, 나중에 패널 및 JupyterHub 로그에서 읽어 오는 이력도 함께 삭제됩니다. 제거를 한 번에 완료할 수 없는 경우 응답에 그 사실이 표시되며 다음 시간별 유지 관리 실행에서 완료됩니다.

복원하면 삭제가 해제되어 새로운 활동이 다시 수집됩니다. 삭제된 내용은 되돌아오지 않습니다.

두 작업 모두 보안 로그에 항목을 작성합니다.
