## Was Sie erstellen

Einen kleinen Workflow, der:

1. eine CSV-Datei in eine Projekttabelle importiert,
2. die Daten mit ein paar Schritten filtert und transformiert,
3. das Ergebnis veröffentlicht, damit andere Tools es nutzen können.

<Aside>
Das Ganze ist bewusst schlank gehalten – es ist ein Rundgang durch die einzelnen Bausteine, keine Detailtiefe. Wenn Sie fertig sind, erklärt die Seite [Konzepte](/de/get-started/concepts/), *warum* die Dinge so organisiert sind, und der Bereich [Anleitungen](/de/guides/) behandelt jede Aufgabe im Detail.
</Aside>

## Mit dem Beispielprojekt beginnen

Wenn Sie lieber zuerst ein fertiges Ergebnis sehen möchten, nehmen Sie die Abkürzung. In einem brandneuen Workspace erscheint die Schaltfläche **Beispiel laden**. Wenn Ihr Workspace mehr als ein geführtes Beispiel anbietet, wählen Sie zuerst aus einer kurzen Liste aus, welches geladen werden soll:

- **Retail Sales Analysis** – Handel und Vertrieb
- **Campaign Performance by Channel** – Marketing
- **Inventory Status Report** – Lieferkette und Betrieb
- **Budget vs Actual by Department** – Finanzen

Jedes Beispiel ist ein kleiner, realistischer Datensatz, der vollständig aus den Low-Code-Transformationsschritten von PlaidCloud aufgebaut ist – ohne handgeschriebenes SQL –, sodass Sie anschließend den fertigen Workflow öffnen und genau nachvollziehen können, wie er funktioniert. Wählen Sie eines aus (oder, wenn nur ein Beispiel verfügbar ist, lädt PlaidCloud es direkt), und PlaidCloud legt das Projekt an und führt dessen Workflow aus. Dabei zeigt es Ihnen jede Phase: eine Datei wird importiert (**Importing**), bereinigt (**Cleaning**), verzweigt sich in ein paar parallele Zusammenfassungen und wird dann zu einer abschließenden Ergebnistabelle zusammengeführt – bevor das Ergebnis für Sie geöffnet wird. Sobald die Ausführung beendet ist, veröffentlicht PlaidCloud die Ergebnistabelle außerdem für das Reporting und erstellt daraus automatisch ein Dashboard: eine KPI-Zusammenfassung, einen Verlauf über die Zeit, eine Aufschlüsselung nach der Hauptkategorie des Beispiels und – bei den Handels- und Bestandsbeispielen – eine Aufschlüsselung nach US-Bundesstaat. Die erste Ausführung dauert etwa eine Minute, während Ihr Warehouse hochfährt; jede weitere ist nahezu sofort fertig, und der Bildschirm weist Sie darauf hin, damit die Wartezeit keine Überraschung ist. Sie erreichen in wenigen Minuten ein echtes erstes Ergebnis und ein fertiges Dashboard, ohne etwas selbst zu erstellen, und jedes erzeugte Element können Sie öffnen, ändern und erneut ausführen. Wenn beim Laden oder Ausführen des Beispiels ein Problem auftritt, teilt PlaidCloud Ihnen das mit und bietet an, es erneut zu versuchen.

Das Beispielprojekt, sein Workflow und jedes Dashboard, das es erstellt, werden in dem Moment für den gesamten Workspace freigegeben, in dem sie erstellt werden – ein Teammitglied mit Viewer-Zugriff sieht dasselbe fertige Beispiel wie Sie, ohne dass ein separater Freigabeschritt nötig ist.

Auch jeder leere Bildschirm führt Sie zum nächsten Schritt, statt Sie vor einem leeren Raster stehen zu lassen. **Projekte**, **Workflows**, **Tabellen**, **Verbindungen** und **Dashboards** begrüßen Sie jeweils mit einer kurzen Erklärung und einer Hauptaktion – **Neues Projekt**, **Neuer Workflow**, **Tabellenpaket importieren** und so weiter –, sodass es immer einen naheliegenden Weg nach vorn gibt. Ein Link **Brauchen Sie Hilfe?** auf diesen Bildschirmen und im Willkommensbereich führt Sie direkt zum Support, falls Sie nicht weiterkommen. Wenn Sie einem Workspace als Viewer hinzugefügt wurden, erklären diese Bildschirme, was Sie sehen, und bieten keine Aktionen an, die Sie nicht ausführen können. Und wenn ein Viewer in einem Workspace ohne sichtbare Inhalte landet, begrüßt ihn eine kurze Einführung, eine geführte Tour durch die App und schneller Zugriff auf Hilfe – so gibt es immer einen nächsten Schritt.

Diese geführte erste Ausführung erscheint in jedem neuen Workspace und in jedem Tarif. Wenn Sie sich bereits auskennen, wählen Sie im Willkommensbereich **Schließen** – eine kurze Bestätigung erinnert Sie daran, dass die Hilfestellung weiterhin verfügbar ist –, und sie tritt in den Hintergrund. Um sie jederzeit wieder einzublenden, öffnen Sie das Benutzermenü oben rechts und wählen Sie **Onboarding neu starten**.

## Mit der eigenen CSV-Datei beginnen

Wenn Sie statt eines Beispiels mit Ihren eigenen Daten beginnen möchten, wählen Sie **Eigene Daten verwenden**. Die Schaltfläche befindet sich neben **Beispiel laden** auf einem leeren Bildschirm **Projekte**, und auch Home bietet sie an. Um sie zu sehen, benötigen Sie die Berechtigung, Projekte und Tabellen zu erstellen und in den Dokumentspeicher zu schreiben. Sobald Sie Projekte haben, öffnet **Neu** > **Projekt aus CSV-Datei** auf dem Bildschirm **Projekte** dasselbe Fenster. Wie Sie eine CSV-Datei zu einem bereits vorhandenen Projekt hinzufügen, lesen Sie unter [CSV-Datei importieren](/de/guides/projects/managing-tables-and-views/#eine-csv-datei-importieren).

Legen Sie eine CSV-Datei auf dem Feld ab oder wählen Sie **CSV-Datei auswählen**, um eine auszuwählen; akzeptiert werden nur Dateien mit der Endung `.csv`. PlaidCloud lädt die Datei in Ihr **Personal Temp Drive** hoch – oder, falls Sie keines haben, in das **Temp Drive** des Workspace –, erstellt ein nach ihr benanntes Projekt, importiert sie in eine nach ihr benannte Tabelle – aus `Sales Data.csv` wird das Projekt **Sales Data** mit der Tabelle `sales_data` – und öffnet die Liste **Tabellen** des neuen Projekts. Anschließend öffnet sich der Bereich **Empfohlener nächster Schritt**, der – sobald PlaidCloud die Tabelle erstmals untersucht hat – zu **Ihre Daten auf einen Blick** wird. Er zeigt, wie viele Zeilen die Tabelle hat, und für die ersten sechs Spalten jeweils den Typ, den Anteil leerer Werte und die Anzahl der unterschiedlichen Werte.

Darunter folgt ein einfaches Balkendiagramm. Seine Balken stehen für die Werte einer Spalte mit einer kurzen Liste wiederkehrender Werte, etwa einer Region, und jeder Balken summiert oder mittelt eine Zahlenspalte für diesen Wert oder zählt seine Zeilen. Wenn mehr als ein sinnvolles Diagramm infrage kommt, wählt die KI von PlaidCloud eines aus und gibt ihm einen Titel; sie sieht nur die Spaltennamen, Typen und Anzahlen, nie einen Wert aus Ihrer Datei. Gibt es keine Spalte mit einer kurzen Liste wiederkehrender Werte, teilt der Bereich mit, dass es kein Startdiagramm gibt.

Ist das Reporting eingeschaltet und haben Sie die Berechtigung, Tabellen zu veröffentlichen, veröffentlicht PlaidCloud die Tabelle außerdem für das Reporting und erstellt aus dem Diagramm ein Start-Dashboard; mit **Dashboard öffnen** öffnen Sie es in einem neuen Tab. Die Diagramme des Dashboards sind nach den Spalten benannt, die sie zeigen, etwa „Total revenue by region“; der Titel der KI erscheint nur am Diagramm im Bereich. Wie jedes neue Dashboard ist es zunächst für alle im Projekt sichtbar; wie Sie das ändern, lesen Sie unter [Festlegen, wer ein Dashboard sehen kann](/de/guides/dashboards/control-who-can-see-a-dashboard/).

Der Bereich bietet außerdem **Diese Daten bereinigen** oder **Diese Daten zusammenfassen** an, die jeweils einen zur Prüfung bereiten Schritt öffnen, oder **Jetzt nicht**, um zu überspringen.

Wenn der Import fehlschlägt, entfernt PlaidCloud das gerade erstellte Projekt und teilt Ihnen mit, was schiefgelaufen ist. PlaidCloud löscht die hochgeladene Datei aus dem Temp Drive, sobald der Import beendet ist – unabhängig davon, ob er erfolgreich war; andernfalls löscht das Temp Drive sie nach einem Tag. Hat der Workspace kein Temp Drive, meldet das Fenster, dass es keinen Speicherort für Ihre Datei gibt, und ein Workspace-Administrator muss sich an den Support wenden.

## Ihren Fortschritt auf Home verfolgen

Sobald Sie in einem Workspace sind, zeigt Home eine einzelne Karte **Erste Schritte**, die Ihre Einrichtung Schritt für Schritt verfolgt – mit einer integrierten Fortschrittsanzeige („N von M“). Was Sie sehen, hängt von Ihrer Rolle ab: Administratoren erhalten fünf Schritte – das Beispiel ausprobieren, die eigenen Daten verbinden, den ersten Workflow erstellen, ein Dashboard veröffentlichen und das Team einladen; Builder erhalten drei – das Beispiel ausprobieren, den ersten Workflow erstellen und ein Dashboard veröffentlichen; Viewer sehen die Karte gar nicht.

Die Karte stellt immer das, was Sie noch nicht erledigt haben, als Hauptaktion voran, und jeder andere offene Schritt ist eine eigene anklickbare Zeile, die Sie direkt dorthin führt. Ein abgeschlossener Schritt bleibt dauerhaft abgehakt – er wird nie wieder zurückgesetzt –, und abgeschlossene Schritte werden eingeklappt, damit die Karte auf das konzentriert bleibt, was noch aussteht.

<Aside>
„Ein Dashboard veröffentlichen“ zählt nur ein Dashboard, das Sie selbst veröffentlicht haben – wenn ein Teammitglied eines veröffentlicht, wird Ihr Kästchen nicht abgehakt.
</Aside>

Wenn Sie die Karte nicht sehen möchten, wählen Sie **Ausblenden**; sie klappt dann zu einer kleinen Schaltfläche „Erste Schritte · N/M“ in der Symbolleiste zusammen, auf die Sie jederzeit klicken können, um die vollständige Karte zurückzuholen. Auch **Onboarding neu starten** im Benutzermenü bringt sie zurück. Um das Onboarding ganz auszuschalten, verwenden Sie stattdessen **Onboarding schließen**; es bleibt ausgeschaltet, bis Sie **Onboarding neu starten** wählen.

Wenn Sie jeden Schritt abgeschlossen haben, verabschiedet sich die Karte selbst: Sie verschwindet von Home, und eine einmalige „Sie sind startklar“-Meldung begrüßt Sie – einmal pro Workspace, egal wie viele Geräte oder Browser Sie dafür verwenden.

Ihr Fortschritt, der ausgeblendete oder angezeigte Zustand der Karte, Touren, Tipps und alles, was Sie auf Home geschlossen haben, folgen Ihrem Konto und nicht Ihrem Browser. Melden Sie sich auf einem neuen Gerät, in einem anderen Browser oder in einem Inkognito-Fenster an, und Sie machen genau dort weiter, wo Sie aufgehört haben, statt von vorn zu beginnen.

Im weiteren Verlauf dieses Schnellstarts erstellen Sie denselben Workflow von Hand, damit Sie jeden Baustein kennenlernen.

## 1. Ein Projekt öffnen

Nach der Anmeldung landen Sie in Ihrem Workspace. Öffnen Sie die Registerkarte **Projekte** und erstellen Sie ein neues Projekt – geben Sie ihm einen aussagekräftigen Namen wie „Quickstart“. In einem Projekt liegen Ihre Daten, Workflows und Dimensionen zusammen.

Mehr zum Lebenszyklus eines Projekts finden Sie unter [Projekte verwalten](/de/guides/projects/managing-projects/).

## 2. Eine CSV-Datei importieren

Öffnen Sie im Projekt die Registerkarte **Workflows** und erstellen Sie einen neuen Workflow. Fügen Sie einen Schritt **Import → CSV** hinzu. Laden Sie entweder eine kleine CSV-Datei von Ihrem lokalen Rechner hoch oder verweisen Sie auf eine CSV-Datei in einem verbundenen Dokumentspeicher.

Führen Sie diesen Schritt aus. Die CSV-Datei landet als Tabelle in Ihrem Projekt. Öffnen Sie die Registerkarte **Tabellen**, um sie zu sehen.

Referenz: [Schritt CSV importieren](/de/reference/workflow-steps/import/import-csv/) · Anleitung: [Wo befinden sich Workflows?](/de/guides/workflows/where-are-workflows/)

## 3. Einen Transformationsschritt hinzufügen

Fügen Sie im Workflow einen Schritt **Tabellen → Table Lookup** hinzu (oder einen beliebigen anderen Tabellenschritt). Konfigurieren Sie Quelle und Ziel, wählen Sie die beizubehaltenden Spalten aus und wenden Sie einen einfachen Filter an.

Wenn Sie den Schritt ausführen, ist das Ergebnis eine neue Tabelle, die Sie in der Vorschau ansehen können.

Referenz: [Workflow-Schritte](/de/reference/workflow-steps/)

## 4. Das Ergebnis veröffentlichen

Fügen Sie einen abschließenden Schritt **Veröffentlichen** hinzu (unter **Daten → Veröffentlichen**), damit die Tabelle für Dashboards, BI-Tools oder externe Verbraucher verfügbar wird.

Anleitung: [Daten veröffentlichen](/de/guides/data/publish/)

## 5. Den gesamten Workflow ausführen

Klicken Sie im Workflow auf **Ausführen**. Verfolgen Sie im Protokoll, wie die einzelnen Schritte ausgeführt werden. Falls ein Fehler auftritt, behandelt die Anleitung [Schrittfehler verwalten](/de/guides/workflows/managing-step-errors/) die Fehlersuche.

## Wie es weitergeht

- **Das Modell verstehen** – [Konzepte](/de/get-started/concepts/) erklärt, was ein Workspace, ein Projekt, ein Workflow, eine Tabelle und eine Dimension eigentlich sind.

- **Etwas nachschlagen** – die [Referenz](/de/reference/) enthält jeden Workflow-Schritt, Ausdruck und Konnektor.
