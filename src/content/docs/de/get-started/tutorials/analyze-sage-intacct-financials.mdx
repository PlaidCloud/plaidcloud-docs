*~40 Minuten · eine aktive Sage-Intacct-Verbindung, eine geladene Saldenliste, eine GuV nach Abteilungen, ein Dashboard und eine geplante Aktualisierung*

Dies ist der Einstieg für Controller und FP&A-Analysten mit Sage Intacct: Am Ende haben Sie **Kontensalden nach Dimension** direkt aus Intacct abgerufen, daraus eine **Saldenliste und GuV nach Abteilungen** erstellt, die sich wie ein Finanzbericht lesen lässt, auf einem Dashboard dargestellt und das Ganze so eingerichtet, dass es sich selbstständig aktualisiert. Kein Export vorgefertigter Berichte, kein manuelles Neuerfassen — die Zahlen stammen aus Intacct und bleiben aktuell.

Sie stellen einmal die Verbindung her, rufen die Daten einmal ab und widmen sich dann dem Teil, auf den es wirklich ankommt: rohe Salden zu den Zusammenfassungen aufzubereiten, die ein Geschäftsanwender am Montagmorgen liest.

## Voraussetzungen

- Ein PlaidCloud-Workspace und ein Projekt, in dem Sie arbeiten ([starten Sie eine Testversion](https://app.plaidcloud.com), falls Sie noch keinen haben).
- **Eine funktionierende Sage-Intacct-Verbindung.** Folgen Sie zuerst der Anleitung [Mit Sage Intacct verbinden](/de/guides/connections/sage-intacct/) — Sie benötigen aktivierte Web Services, einen Webservice-Benutzer mit Berechtigung für die Objekte, die Sie lesen, und die vier Anmeldedatenfelder der Verbindung: **Client-ID**, **Client-Secret**, **Benutzername des Webservice-Benutzers** und **Unternehmens-ID**. Vergewissern Sie sich, dass die Verbindung funktioniert, bevor Sie hier beginnen.
- Kennen Sie Ihre **operativen Entitäten** (die Entitäts-IDs, über die Sie berichten) und ungefähr den **Kontonummernbereich**, der Ihre GuV-Konten (Erlöse und Aufwände) enthält. Die Beispiele unten verwenden `201` und `301` als Entitäten und `4010`–`9999` als GuV-Bereich — setzen Sie Ihre eigenen Werte ein.

<Aside type="note">
Alles nach dem Abruf geschieht per Mausklick — ohne SQL, ohne Code. Das einzige Intacct-spezifische Element ist der Schritt **Sage importieren**, der die *Kontensalden nach Dimension* von Intacct für ein Datum und einen Kontobereich liest. Er liefert eine Zeile pro Konto und Dimensionskombination, jeweils mit Eröffnungs-, Perioden- und Endsaldo.
</Aside>

## Schritt 1: Einen Workflow erstellen

Der Workflow ist die Pipeline, die die Daten abruft und aufbereitet.

<Steps>

1. Öffnen Sie Ihr Projekt und wechseln Sie zur Registerkarte **Workflows**.
2. Klicken Sie auf **Neuer Workflow**, geben Sie ihm einen Namen wie `Intacct Financials` und öffnen Sie ihn.

</Steps>

## Schritt 2: Die Saldenliste abrufen

Der [Schritt Sage importieren](/de/reference/workflow-steps/sage-intacct/import-sage/) ruft Kontensalden für einen Datumsbereich und einen Kontobereich ab und überträgt die von Ihnen gewählten Dimensionen in jede Zeile — das ist Ihre Saldenliste.

<Steps>

1. Fügen Sie einen Schritt **Sage importieren** hinzu.

2. Legen Sie in seiner Konfiguration Folgendes fest:

   | Feld | Wert |
   |---|---|
   | **Verbindung** | Ihre Sage-Intacct-Verbindung |
   | **Unternehmen** | das Intacct-Unternehmen, aus dem gelesen wird |
   | **Startdatum** / **Enddatum** | die Periode, die Sie abschließen — z. B. der erste und der letzte Tag des Monats |
   | **Startkonto** / **Endkonto** | Ihr GuV-Bereich, z. B. `4010` bis `9999` |
   | **Entitäten** | Ihre operativen Entitäten, z. B. `201`, `301` |
   | **Dimensionen** | aktivieren Sie diejenigen, nach denen Sie berichten — üblich sind **Standort**, **Abteilung**, **Mitarbeiter** und **Klasse** |

3. Legen Sie das **Ziel** auf eine neue Tabelle mit dem Namen `intacct_trial_balance` fest.

4. Führen Sie den Schritt aus. Sie haben jetzt eine Zeile pro Konto und Dimensionskombination, mit den Spalten `startbalance`, `periodbalance` und `endbalance` sowie einem ID-/Namenspaar für jede aktivierte Dimension (z. B. `departmentid` / `departmentname`, `locationname`).

</Steps>

<Aside type="caution">
Intacct liefert jede Spalte als **Text**, und Sage-Abrufe sind **Einzelanfragen** (ohne Paginierung) — Ergebnisse von Kontensalden sind klein, sodass das hier unproblematisch ist; verwenden Sie diesen Schritt aber nicht für Einzelposten-Details mit hohem Volumen. Die tatsächlichen Spaltentypen legen Sie im nächsten Schritt fest, wo sie relevant sind.
</Aside>

<Aside type="note">
Sowohl **Startdatum** als auch **Enddatum** müssen festgelegt sein — ein einzelnes Start- oder Enddatum wird ignoriert. Wenn Sie eine Dimension aktiviert haben, deren ID und Namen Sie nicht benötigen, können Sie die überzählige Spalte im nächsten Schritt weglassen. (Das Kontrollkästchen für die Dimension **Warehouse** hat keine Wirkung; verwenden Sie **Benutzerdefinierte Dimensionen**, wenn Sie das Warehouse in der Ausgabe benötigen.)
</Aside>

## Schritt 3: Die Salden zu einer GuV aufbereiten

Jetzt folgt die Analyse mit einer einzigen Transformation per Mausklick — ohne SQL. Ihr GuV-Bereich wird pro Abteilung zu wenigen Berichtszeilen verdichtet, mit umgekehrtem Vorzeichen, sodass Erlöse positiv erscheinen. Ein [Table-Extract-Schritt](/de/reference/workflow-steps/tables/table-extract/) erledigt all das auf seinen Registerkarten **Tabellendatenauswahl** und **Filter**.

<Steps>

1. Fügen Sie einen **Table Extract**-Schritt hinzu. Legen Sie seine **Quelle** auf `intacct_trial_balance` und sein **Ziel** auf eine neue Tabelle `intacct_pnl` fest.

2. Klicken Sie auf der Registerkarte **Spalten** auf **Zusammenfassen**, um die Aggregation einzuschalten, und richten Sie dann drei Zielspalten ein:

   - **`departmentname`** — direkt aus der Quelle zugeordnet. Typ **Text**, Zusammenfassen: **Gruppieren nach**.
   - **`pnl_line`** — ein **Ausdruck** (siehe unten), der die Kontonummer in eine Berichtszeile umwandelt. Typ **Text**, Zusammenfassen: **Gruppieren nach**.
   - **`amount`** — ein **Ausdruck** `func.to_float64(intacct_trial_balance.endbalance) * -1`, der den Text-Saldo in eine Zahl umwandelt und das Vorzeichen umkehrt. Typ **Währung**, Zusammenfassen: **Summe**.

   Dass Sie den **Typ** der Zielspalte `amount` auf **Währung** setzen, ermöglicht es, den Text-Saldo zu addieren. Doppelklicken Sie für `pnl_line` in die Zelle **Ausdruck** und geben Sie Folgendes ein (Spalten und die Funktion `case` aus der Gruppe **Bedingungen** wählen Sie per Mausklick aus):

   ```python
   case(
       (func.to_float64(intacct_trial_balance.glaccountno) < 5000, '1 - Revenue'),
       (func.to_float64(intacct_trial_balance.glaccountno) < 6000, '2 - Cost of Goods Sold'),
       else_='3 - Operating Expenses',
   )
   ```

3. Führen Sie den Schritt aus.

</Steps>

Das `* -1` ist der einzige buchhalterische Kniff: Intacct führt Erlöse im Haben (negativ) und Aufwände im Soll (positiv), sodass das Negieren des Endsaldos **Erlöse positiv und Kosten negativ** darstellt — die Zeilen jeder Abteilung *ergeben dann in Summe den Jahresüberschuss*. Passen Sie die Kontonummern-Grenzwerte in `case()` an Ihren Kontenplan an. Ausdrücke verwenden den Editor von PlaidCloud mit Auswahl per Mausklick — siehe [Erweiterte Nutzung des Data Mappers](/de/reference/workflow-steps/common/advanced-data-mapper-usage/) und die [Ausdrucksreferenz](/de/reference/expressions/).

<Aside type="tip">
Sie möchten stattdessen eine unternehmensweite GuV statt nach Abteilungen? Entfernen Sie `departmentname` aus den Zielspalten und behalten Sie nur `pnl_line` (Gruppieren nach) und `amount` (Summe).
</Aside>

## Schritt 4: Wie ein Finanzexperte lesen

Öffnen Sie die Tabelle `intacct_pnl`. Für jede Abteilung haben Sie drei Zahlen:

| departmentname | pnl_line | amount |
|---|---|---|
| Operations | 1 - Revenue | 486,200.00 |
| Operations | 2 - Cost of Goods Sold | -190,540.00 |
| Operations | 3 - Operating Expenses | -212,880.00 |

Direkt daraus ablesbar:

- **Rohertrag** = Erlöse + Herstellungskosten (die Herstellungskosten sind bereits negativ) → `486,200 − 190,540 = 295,660`.
- **Jahresüberschuss** = die Summe der drei Zeilen → `82,780`.
- **Rohertragsmarge in %** = Rohertrag ÷ Erlöse → ca. 61 %.

Als Erstes sollten Sie **abstimmen**: Führen Sie die eigene GuV von Intacct (Finanzberichte) für dieselbe Periode und dieselben Entitäten aus und prüfen Sie, ob Erlöse und Jahresüberschuss übereinstimmen. Wenn nicht, liegt es fast immer an einem Unterschied im Umfang — an einer Entität, die Sie nicht einbezogen haben, an einem Kontobereich, der einen Teil der GuV abschneidet, oder an einer abweichenden Periodenabgrenzung. Vertrauen Sie der Pipeline erst, wenn die Werte übereinstimmen.

<Aside type="tip">
Sie möchten das klassische Layout mit den Perioden in den Spaltenköpfen? Fügen Sie einen [Table-Pivot-Schritt](/de/reference/workflow-steps/tables/table-pivot/) hinzu, der `intacct_pnl` liest: Pivotieren Sie die Periode in Spalten, behalten Sie `pnl_line` als Zeile und summieren Sie `amount`. Um überhaupt eine Periodenspalte zu erhalten, fügen Sie in Schritt 3 `end_date` als Spalte mit **Gruppieren nach** hinzu. So erhalten Sie den Vergleich von Monat zu Monat auf einen Blick, ohne SQL.
</Aside>

## Schritt 5: Auf einem Dashboard darstellen

Zahlen in einer Tabelle sind in Ordnung; ein Diagramm schicken Sie an den CFO. [Veröffentlichen Sie](/de/get-started/tutorials/load-and-transform-data/#schritt-7-das-ergebnis-veröffentlichen) `intacct_pnl` und folgen Sie dann der Anleitung [Dashboard erstellen](/de/get-started/tutorials/build-a-dashboard/), um Folgendes hinzuzufügen:

- ein **Balkendiagramm** des Jahresüberschusses (oder der Erlöse) nach `departmentname` und
- ein **Balkendiagramm** jeder `pnl_line`, damit die Zusammensetzung aus Erlösen, Herstellungskosten und Betriebskosten auf einen Blick sichtbar ist.

Das ist ein aktives Sage-Intacct-Finanz-Dashboard — ohne Export, aktualisiert bei jeder Ausführung des Workflows.

## Schritt 6: Die Aktualisierung planen

<Steps>

1. Führen Sie den gesamten Workflow einmal von oben nach unten aus, um zu bestätigen, dass jeder Schritt grün ist.
2. [Planen Sie den Workflow](/de/get-started/tutorials/schedule-a-workflow/) — monatlich im Rhythmus des Abschlusses oder wöchentlich, wenn die Zahlen im Laufe des Monats aktuell sein sollen.

</Steps>

Da der Abruf die gesamte Tabelle ersetzt, liest jede Ausführung die Salden für das von Ihnen festgelegte Datum und den Kontobereich erneut — beschränken Sie diese auf das benötigte Fenster (die laufende Periode, Ihre GuV-Konten) statt auf die gesamte Historie.

## Schritt 7: Eine Kennzahl pro Kopf mit statistischen Konten ergänzen

Intacct führt neben Ihrem Finanzkontenplan auch nicht monetäre **statistische Konten** — Mitarbeiterzahl, Fläche in Quadratmetern, Stückzahlen. Rufen Sie sie mit einem zweiten Schritt **Sage importieren** im statistischen Modus ab und verknüpfen Sie sie dann mit der GuV, um eine Kennzahl wie die Betriebskosten pro Mitarbeiter nach Abteilung zu lesen. Drei weitere Standardschritte, weiterhin ohne SQL.

<Steps>

1. Fügen Sie einen zweiten Schritt **Sage importieren** hinzu. Legen Sie in seiner Konfiguration Folgendes fest:

   | Feld | Wert |
   |---|---|
   | **Verbindung** | Ihre Sage-Intacct-Verbindung |
   | **Unternehmen** | das Intacct-Unternehmen, aus dem gelesen wird |
   | **Startdatum** / **Enddatum** | dieselbe Periode wie in Schritt 2 |
   | **Statistisch** | **Nur statistisch** |
   | **Startkonto** / **Endkonto** | `0000` bis `9999` — statistische Konten liegen nicht zwingend innerhalb der Nummerierung Ihres Finanzkontenplans, daher rufen Sie den vollständigen Bereich statt des GuV-Bereichs aus Schritt 2 ab |
   | **Entitäten** | Ihre operativen Entitäten, z. B. `201`, `301` |
   | **Dimensionen** | **Abteilung** — die Dimension, nach der Sie pro Kopf berichten |

2. Legen Sie das **Ziel** auf eine neue Tabelle mit dem Namen `intacct_statistics` fest.

3. Führen Sie den Schritt aus. Sie erhalten eine Zeile pro statistischem Konto und Abteilung, wobei `endbalance` die Statistik selbst enthält — z. B. die Mitarbeiterzahl dieser Abteilung am Periodenende.

</Steps>

Bringen Sie nun die Mitarbeiterzahl in die GuV und teilen Sie — aber nicht direkt von `intacct_statistics` aus. Diese Tabelle hat eine Zeile *pro statistischem Konto und Abteilung* (Mitarbeiterzahl, Fläche, Stückzahlen, was auch immer Sie erfassen). Ein Join allein über `departmentname` würde daher jede GuV-Zeile für jedes statistische Konto dieser Abteilung vervielfachen, und `amount_per_head` würde durch dasjenige statistische Konto geteilt, das zufällig in der Zeile landet. Filtern Sie zuerst auf die Mitarbeiterzahl, damit der Join eine Zeile pro Abteilung ergibt und die Kennzahl tatsächlich aussagekräftig ist.

<Steps>

1. Fügen Sie einen **Table Extract**-Schritt hinzu. Legen Sie seine **Quelle** auf `intacct_statistics` und sein **Ziel** auf eine neue Tabelle `intacct_headcount` fest. Übernehmen Sie unter **Spalten** alle Spalten unverändert — hier ist keine Aggregation nötig. Fügen Sie auf der Registerkarte **Filter** einen Filter **Teilmenge der Daten auswählen** auf die Quelldaten hinzu: `intacct_statistics.glaccountno == '9000'` — ersetzen Sie `9000` durch die Nummer Ihres eigenen statistischen Kontos für die Mitarbeiterzahl (filtern Sie stattdessen nach der Spalte mit dem Kontonamen, falls Ihr Abruf diese liefert; `glaccountno` ist weiterhin Text, vergleichen Sie es daher mit einer Zeichenfolge in Anführungszeichen). Führen Sie den Schritt aus — `intacct_headcount` hat jetzt genau eine Zeile pro Abteilung.

2. Fügen Sie einen [Table-Outer-Join-Schritt](/de/reference/workflow-steps/tables/table-outer-join/) hinzu. Legen Sie **Tabelle 1** auf `intacct_pnl` und **Tabelle 2** auf `intacct_headcount` fest und verknüpfen Sie über `departmentname` — jetzt eine saubere 1:1-Zuordnung pro Abteilung. Belassen Sie den **Verknüpfungstyp** auf seinem Standard **Left Join** — jede GuV-Zeile bleibt erhalten, und die Mitarbeiterzahl wird eingetragen, wo die Abteilung übereinstimmt. Legen Sie als Ziel eine neue Tabelle `intacct_pnl_with_headcount` fest und übernehmen Sie alle Spalten aus beiden Tabellen.

3. Führen Sie den Schritt aus und fügen Sie dann einen **Table Extract**-Schritt hinzu, der `intacct_pnl_with_headcount` liest und in eine neue Tabelle `intacct_pnl_per_head` schreibt. Übernehmen Sie unter **Spalten** die vorhandenen Spalten und fügen Sie eine weitere Zielspalte hinzu: `amount_per_head`, ein **Ausdruck** `intacct_pnl_with_headcount.amount / func.to_float64(intacct_pnl_with_headcount.endbalance)`, Typ **Währung**.

4. Führen Sie den Schritt aus.

</Steps>

Lesen Sie `amount_per_head` in der Zeile **`3 - Operating Expenses`** für die Betriebskosten pro Mitarbeiter nach Abteilung — dieselbe Lesart wie in Schritt 4, nur eine Spalte tiefer. Nehmen Sie sie neben der GuV in das Dashboard auf oder binden Sie sie in den Zeitplan aus Schritt 6 ein, damit sie zusammen mit allem anderen aktualisiert wird.

## Was Sie aufgebaut haben

Ausgehend von einem leeren Workflow haben Sie aktuelle Kontensalden aus Sage Intacct abgerufen, mit einem einzigen Standard-Transformationsschritt zu einer **GuV nach Abteilungen** aufbereitet, statistische Konten für eine Kennzahl pro Kopf hinzugefügt — ohne SQL in der gesamten Pipeline —, auf einem Dashboard dargestellt und so eingerichtet, dass sie sich aktualisieren — der zentrale Berichtszyklus eines Finanzteams, jetzt automatisiert.
