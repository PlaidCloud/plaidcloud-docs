*ca. 10 Minuten · Ihre CSV-Datei, eine abgelegte Tabelle, ein erstes Ergebnis*

Dies ist die Kurzfassung. Sie bringen eine CSV-Datei mit, und am Ende haben Sie sie importiert, als Tabelle abgelegt, eine einzelne Transformation ausgeführt und ein echtes Ergebnis aus Ihren eigenen Daten gelesen.

Es ist das schnelle Gegenstück zu [Daten laden, transformieren und veröffentlichen](/de/get-started/tutorials/load-and-transform-data/) – jenes Tutorial dauert etwa eine Stunde und baut eine vollständige mehrstufige Pipeline mit Joins und einer Veröffentlichung auf. Kommen Sie zuerst hierher für den schnellen Erfolg; wechseln Sie dorthin, wenn Sie mehr in die Tiefe gehen möchten.

## Voraussetzungen

- Ein PlaidCloud-Workspace ([starten Sie eine kostenlose Testversion](https://app.plaidcloud.com), falls Sie noch keinen haben).
- Ein Projekt, in dem Sie arbeiten – erstellen Sie auf der Registerkarte **Projekte** eines, falls Sie noch keins haben.
- Eine CSV-Datei Ihrer eigenen Daten. Alles mit einer Kopfzeile und einer numerischen Spalte eignet sich – Umsätze, Ausgaben, eine Liste von Bestellungen.

## Schritt 1: Einen Workflow erstellen

Ein Workflow ist die Pipeline, die Ihre Daten importiert und transformiert.

1. Öffnen Sie Ihr Projekt und wechseln Sie zur Registerkarte **Workflows**.
2. Klicken Sie in der Symbolleiste auf **Neuer Workflow**.
3. Geben Sie ihm einen Namen wie „CSV Quick Start“ und lassen Sie **Workflow-Typ** auf dem Standardwert **Standard seriell**.
4. Klicken Sie auf **Erstellen** und doppelklicken Sie dann auf den neuen Workflow, um den [Workflow Explorer](/de/guides/workflows/workflow-explorer/) zu öffnen.

## Schritt 2: Ihre CSV-Datei importieren

1. Fügen Sie einen neuen Schritt hinzu und wählen Sie einen Schritt **Import → CSV** (oder den Importschritt, der zum Format Ihrer Datei passt).
2. Nehmen Sie in der Schrittkonfiguration folgende Einstellungen vor:
   - **Quelldatei** – verweisen Sie auf Ihre CSV-Datei: Laden Sie sie hoch oder wählen Sie sie aus einem verbundenen Dokumentenkonto aus.
   - **Zieltabelle** – nennen Sie sie `my_data`.
   - **Trennzeichen, Anführungszeichen, Kopfzeile** – passen Sie diese nur an, wenn Ihre Datei vom Standard abweicht; die Standardwerte kommen mit einer typischen kommagetrennten Datei mit Kopfzeile zurecht.
3. Führen Sie den Schritt aus.

Ihre CSV-Datei liegt jetzt als [Tabelle](/de/guides/data/tables-views/) im Projekt. Eine Tabelle enthält die physischen Zeilen- und Spaltendaten; alles, was danach kommt, liest daraus.

> **Die Quelle bleibt unangetastet.** Jeder Schritt liest aus einer Quelle und schreibt in ein Ziel, das Original bleibt unverändert. Ihr CSV-Import hat `my_data` geschrieben; die Transformation im nächsten Schritt liest diese Tabelle und schreibt an eine neue Stelle.

## Schritt 3: Die abgelegte Tabelle prüfen

Wechseln Sie zur Registerkarte **Tabellen** und öffnen Sie `my_data`. Prüfen Sie die Anzahl der Spalten, einige Beispielzeilen und ob die Datentypen stimmen – eine numerische Spalte sollte als Zahl erscheinen, nicht als Text. Ist ein Typ falsch, können Sie ihn mit den Spaltenzuordnungen im Importschritt korrigieren und den Schritt erneut ausführen.

## Schritt 4: Eine Transformation ausführen

Jetzt machen Sie aus der Rohtabelle eine Antwort. Dieses Beispiel filtert auf die relevanten Zeilen und behält nur die Spalten, die Sie interessieren – passen Sie die Einzelheiten an Ihre Datei an.

1. Fügen Sie einen Schritt **Tabellen → Table Lookup** hinzu (oder eine beliebige Tabellentransformation, mit der Sie filtern und Spalten auswählen können).
2. Konfigurieren Sie:
   - **Quelltabelle** – `my_data`
   - **Zieltabelle** – `my_result`
   - **Filterbedingungen** – eine Bedingung, die die Zeilen eingrenzt, z. B. `amount > 0`
   - **Zu behaltende Spalten** – die Teilmenge, die Sie lesen möchten, plus eine berechnete Spalte wie `revenue = quantity * price`
3. Führen Sie den Schritt aus.

Alle Funktionen, die Sie in einer berechneten Spalte verwenden können – Zeichenfolgenoperationen, Datumsberechnungen, bedingte Logik –, finden Sie in der [Referenz zu Ausdrücken](/de/reference/expressions/).

> **Was Sie sehen sollten.** Nach der Ausführung des Schritts enthält `my_result` weniger Zeilen als `my_data` – der Filter hat sie eingegrenzt –, und Ihre berechnete Spalte (etwa `revenue`) ist in jeder verbleibenden Zeile vorhanden und befüllt. Wenn sich die Zeilenanzahl nicht verringert hat oder die berechnete Spalte leer ist, prüfen Sie Filterbedingung und Ausdruck noch einmal, bevor Sie weitermachen.

## Schritt 5: Das Ergebnis lesen

Öffnen Sie die Registerkarte **Tabellen** und dann `my_result`. Weniger Zeilen als in `my_data`, nur die Spalten, die Sie behalten haben, und Ihre berechnete Spalte befüllt – das ist Ihre erste Antwort, direkt aus Ihren eigenen Daten.

Sie können auch beide Schritte auf einmal ausführen: Klicken Sie zurück im Workflow auf **Ausführen** (oder im Menü **Aktionen** auf **Run All**), um alles der Reihe nach auszuführen. Jeder Schritt zeigt während der Ausführung ein Statussymbol – **Completed** bedeutet, dass er sauber abgeschlossen wurde. Was die einzelnen Status bedeuten und wie Sie eine gestoppte Ausführung fortsetzen, steht unter [Run a Workflow](/de/guides/workflows/run-a-workflow/).

> **Ein Fehler aufgetreten?** Die beiden häufigsten Ursachen sind ein Datentyp, der als Text importiert wurde, obwohl Sie eine Zahl brauchten, und eine Filterbedingung, die auf einen Spaltennamen verweist, der in der Tabelle nicht existiert. Prüfen Sie die Tabelle aus Schritt 3 und führen Sie den Schritt dann erneut aus. Alles Weitere behandelt [Managing step errors](/de/guides/workflows/managing-step-errors/).
