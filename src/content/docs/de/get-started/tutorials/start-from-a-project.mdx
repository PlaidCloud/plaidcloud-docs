*~15 Minuten · ein Projekt kopieren oder importieren und dann anpassen*

Der schnellste Erfolg an Tag 1 in PlaidCloud besteht nicht darin, bei null anzufangen, sondern mit etwas zu beginnen, das bereits funktioniert. Wählen Sie ein Projekt, das bereits Daten importiert, transformiert und ein Ergebnis erzeugt, besorgen Sie sich Ihre eigene Kopie und ändern Sie die Teile, die Ihre sind.

Es gibt keine Vorlagengalerie zum Stöbern. Stattdessen haben Sie zwei bewährte Wege, mit einem funktionierenden Projekt zu beginnen:

- **Ein Projekt kopieren**, das in Ihrem Workspace bereits existiert, in ein ganz neues eigenes Projekt – [Ein Projekt kopieren](/de/guides/projects/managing-projects/#ein-projekt-kopieren).
- **Ein portables Bundle ausführen** – ein Projekt, das jemand als eigenständiges Paket im [portablen Format](/de/guides/projects/export-to-portable-format/) exportiert hat und das außerhalb von PlaidCloud für sich allein läuft.

Welches Sie möchten, hängt davon ab, wohin Sie wollen.

| Sie möchten … | Verwenden Sie | Ergebnis |
|---|---|---|
| In PlaidCloud auf einem Projekt aufbauen und weiter iterieren | **Projekt kopieren** | Ein neues eigenes Projekt, bereit zum Bearbeiten und Ausführen |
| Die Logik eines Projekts offline ausführen oder an jemanden ohne PlaidCloud-Anmeldung weitergeben | **In portables Format exportieren** | Ein eigenständiges Python- + DuckDB-Paket |

## Voraussetzungen

- Ein PlaidCloud-Workspace ([starten Sie eine kostenlose Testversion](https://app.plaidcloud.com), falls Sie noch keinen haben).
- Für **Weg A**: ein vorhandenes Projekt, das Sie auf der Registerkarte **Projekte** sehen – eines Ihrer eigenen, ein freigegebenes Beispiel oder alles, worauf Ihnen ein Kollege Zugriff gegeben hat.
- Für **Weg B**: eine `.zip`-Datei im portablen Format, die jemand exportiert hat, oder ein eigenes Projekt zum Exportieren.

> **Sie sind nicht sicher, was ein Projekt ist?** Ein Projekt ist die Arbeitseinheit in PlaidCloud – es besitzt seine eigenen Daten, Workflows, Dimensionen und seinen Verlauf und teilt keinen Zustand mit anderen Projekten. Lesen Sie zuerst [Projekte](/de/guides/projects/), falls das neu für Sie ist.

## Weg A: Ein vorhandenes Projekt kopieren

Das Kopieren erzeugt ein vollständiges, bearbeitbares Duplikat – ganz oder nur die Teile, die Sie auswählen – in einem ganz neuen Projekt, das ausschließlich Ihnen gehört.

1. Öffnen Sie **Analyze** und wählen Sie die Registerkarte **Projekte**.
2. Wählen Sie das Projekt aus, mit dem Sie beginnen möchten.
3. Klicken Sie auf die Schaltfläche **Aktionen** und wählen Sie **Projekt kopieren**.
4. Wählen Sie **a new project** als Ziel. Geben Sie einen Namen und eine **ID** an.
5. Lassen Sie die Auswahlstruktur vollständig angehakt, um das gesamte Projekt zu übernehmen, und klicken Sie dann auf **Projekt kopieren**.

> **Die ID ist dauerhaft.** Die ID, die Sie dem neuen Projekt geben, wird zu seinem Schemanamen und kann später nicht geändert werden. Wählen Sie etwas, mit dem Sie leben können – der Name lässt sich jederzeit ändern, die ID nicht.

Das Kopieren läuft im Hintergrund; Sie werden benachrichtigt, wenn es fertig ist. Das vollständige Dialogfeld finden Sie unter [Ein Projekt kopieren](/de/guides/projects/managing-projects/#ein-projekt-kopieren).

### Nur die gewünschten Teile übernehmen

Sie müssen nicht alles kopieren. Die Auswahlstruktur listet nach Typ auf, was das Projekt enthält – Workflows, Schritte, Tabellen, Dimensionen, Dateneditoren, benutzerdefinierte Funktionen –, und Sie können nur die gewünschten Teile anhaken. Alles, was Sie anhaken, bringt seine Abhängigkeiten automatisch mit: die Tabellen, die ein Schritt liest und schreibt, die Dimensionen, gegen die er lädt, die Funktionen, die er aufruft, und jeden Unter-Workflow, den er aufruft. Sie müssen diese Abhängigkeiten nie selbst ermitteln.

> **Lassen Sie Verweise auf Ihre Kopie zeigen.** Lassen Sie **Referenzen aktualisieren** eingeschaltet (der Standard). Die Option schreibt die kopierten Schritte so um, dass sie auf die Tabellen und Objekte in Ihrem neuen Projekt verweisen statt zurück auf das Original – fast immer das, was Sie wollen. Schalten Sie sie nur aus, wenn die Kopie bewusst weiter die Objekte des Quellprojekts lesen soll.

## Weg B: Mit einem portablen Bundle beginnen

Ein portables Bundle ist ein Projekt, das als eigenständiges Python-Programm verpackt ist und auf [DuckDB](https://duckdb.org) ohne Verbindung zu PlaidCloud läuft. Es ist der Weg, mit einem funktionierenden Projekt zu beginnen, wenn es *außerhalb der Plattform* laufen soll – auf Ihrem Laptop, in einem CI-Job oder in den Händen von jemandem ohne PlaidCloud-Anmeldung.

Wenn ein Kollege Ihnen bereits ein Bundle gegeben hat, springen Sie zu [Ausführen](#ausführen). So erstellen Sie selbst eines:

1. Öffnen Sie **Analyze** und wählen Sie die Registerkarte **Projekte**.
2. Wählen Sie ein einzelnes Projekt aus.
3. Öffnen Sie das Menü **Aktionen** und wählen Sie **In portables Format exportieren**.
4. Legen Sie das **Dokumentkonto** und den **Ordnerpfad** fest, in den das Paket geschrieben wird, lassen Sie **Include data** angehakt, damit es ohne externe Quelle läuft, und klicken Sie auf **Exportieren**.

Das Ergebnis ist eine `.zip`-Datei mit einem Python-Skript pro Workflow, den Parquet-Daten-Snapshots, einer `requirements.txt`, die die von den Skripten benötigten Python-Pakete auflistet, sowie `README.md`, `COVERAGE.md` und `RUN_ORDER.md`. Was jede Datei ist, finden Sie unter [In portables Format exportieren](/de/guides/projects/export-to-portable-format/).

> **Ein portables Bundle ist ein Snapshot in eine Richtung, kein erneuter Import.** Es läuft *außerhalb* von PlaidCloud und synchronisiert nicht zurück – Änderungen, die Sie am Paket vornehmen, gelangen nicht ins Projekt zurück, und ein erneuter Export nach Änderungen erzeugt ein frisches Paket. Um weiter innerhalb von PlaidCloud zu arbeiten, verwenden Sie stattdessen **Weg A**. Um in PlaidCloud weiter zu iterieren *und* eine lauffähige Kopie weiterzugeben, tun Sie beides.

> **Die Wiedergabetreue ist bestmöglich.** SQL-Transformationsschritte werden exakt reproduziert. Proprietäre Schritte und solche mit Nebenwirkungen – Umlagen, Dimensionsladevorgänge, Benachrichtigungen, Dokument- und Berichtsschritte, Skripte – werden als Platzhalter exportiert, die nicht erneut ausgeführt werden; stattdessen wird ihre zuletzt materialisierte Ausgabe als Snapshot mitgeliefert. Die Wiedergabetreue jedes Schritts ist in `COVERAGE.md` festgehalten. Für vollständig neu berechnete Ergebnisse führen Sie das Projekt in PlaidCloud aus.

### Ausführen

Entpacken Sie das Paket, erstellen Sie eine Python-Umgebung und führen Sie jedes Workflow-Skript in der Reihenfolge aus, die `RUN_ORDER.md` auflistet:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python pipeline_<workflow>.py
```

Jedes Skript baut seine Tabellen in einer lokalen DuckDB-Datenbank auf. SQL-Schritte werden live neu berechnet; Platzhalterschritte lassen ihre als Snapshot gesicherte Ausgabe an Ort und Stelle.

## Zu Ihrem eigenen machen

Wie auch immer Sie begonnen haben: Die Kopie gehört nun Ihnen und kann geändert werden – hier zahlt sich der Erfolg an Tag 1 aus. Ein paar erste Schritte:

| Tun Sie dies | Wo |
|---|---|
| Imports auf *Ihre* Daten statt auf die des Beispiels richten | Die Importschritte in jedem Workflow – siehe [Daten laden, transformieren und veröffentlichen](/de/get-started/tutorials/load-and-transform-data/) |
| Das Projekt umbenennen oder anpassen, wer es öffnen darf | [Projekte verwalten](/de/guides/projects/managing-projects/) → Zugriffssteuerung |
| Projektvariablen für Werte festlegen, die in mehreren Workflows wiederkehren | [Projektvariablen verwalten](/de/guides/projects/managing-projects/#projektvariablen-verwalten) |
| Bestätigen, dass das Ganze weiterhin durchgängig läuft | Klicken Sie bei jedem Workflow auf **Ausführen** und beobachten Sie das Protokoll |

Da jede Änderung nachverfolgt wird, können Sie frei experimentieren – die [automatische Änderungsverfolgung](/de/guides/projects/managing-projects/#versionsverlauf) lässt Sie jeden früheren Zustand zu einem bestimmten Zeitpunkt wiederherstellen, wenn eine Bearbeitung schiefgeht.
