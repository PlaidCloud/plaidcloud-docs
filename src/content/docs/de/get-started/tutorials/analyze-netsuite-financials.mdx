*~45 Minuten · eine aktive NetSuite-Verbindung, ein geladenes Hauptbuch, eine monatliche GuV, eine Debitoren-Altersstruktur und eine geplante Aktualisierung*

Dies ist der Einstieg für Controller und FP&A-Analysten: Am Ende haben Sie Ihr **Hauptbuch** direkt aus NetSuite abgerufen, daraus eine **monatliche Gewinn- und Verlustrechnung (GuV)** erstellt, die sich wie ein Finanzbericht lesen lässt, eine **Debitoren-Altersstruktur** aufgebaut, beides auf einem Dashboard dargestellt und das Ganze so eingerichtet, dass es sich selbstständig aktualisiert. Kein Tabellenexport, kein manuelles Neuerfassen — die Zahlen stammen aus NetSuite und bleiben aktuell.

Sie stellen einmal die Verbindung her, rufen die Daten einmal ab und widmen sich dann dem Teil, auf den es wirklich ankommt: rohe Hauptbuchzeilen zu den Zusammenfassungen aufzubereiten, die ein Geschäftsanwender am Montagmorgen liest.

## Voraussetzungen

- Ein PlaidCloud-Workspace und ein Projekt, in dem Sie arbeiten ([starten Sie eine Testversion](https://app.plaidcloud.com), falls Sie noch keinen haben).
- **Eine funktionierende NetSuite-Verbindung.** Folgen Sie zuerst der Anleitung [Mit NetSuite verbinden](/de/guides/connections/netsuite/) — Sie benötigen OAuth 2.0 und REST Web Services in NetSuite, die Client-ID der Integration, eine Zertifikats-ID, Ihre Konto-ID und den privaten Schlüssel als PEM. Vergewissern Sie sich, dass **Testanfrage senden** grün ist, bevor Sie hier beginnen.
- Für die Aufbereitung der Daten ist kein SQL nötig — dafür verwenden Sie Standard-Transformationsschritte. Der einzige Abfragetext ist der **Abruf** aus NetSuite, und alle Abruf-Abfragen werden bereitgestellt. Halten Sie [SuiteQL-Abfragebeispiele für NetSuite](/de/guides/connections/netsuite-financial-queries/) in einem Tab geöffnet; dieses Tutorial greift darauf zurück.

<Aside type="note">
Die einzige Stelle, an der Sie Abfragetext schreiben, ist der **Abruf** aus NetSuite — das ist **SuiteQL**, das *innerhalb von NetSuite* ausgeführt wird. Alles danach — das Gruppieren des Hauptbuchs zu einer GuV, das Einteilen der Forderungen in Klassen — erledigen Sie mit den Transformationsschritten von PlaidCloud per Mausklick, ohne SQL. (Wenn Sie mit SQL vertraut sind: Dafür gibt es einen Schritt „SQL extrahieren“, den Sie hier aber nicht brauchen.)
</Aside>

## Schritt 1: Einen Workflow erstellen

Der Workflow ist die Pipeline, die die Daten abruft und aufbereitet.

<Steps>

1. Öffnen Sie Ihr Projekt und wechseln Sie zur Registerkarte **Workflows**.
2. Klicken Sie auf **Neuer Workflow**, geben Sie ihm einen Namen wie `NetSuite Financials` und öffnen Sie ihn.

</Steps>

## Schritt 2: Das Hauptbuch abrufen

Eine SuiteQL-Abfrage liefert Ihnen ein Jahr an Buchungsaktivität — jedes Konto, jeden Monat. Das genügt, um eine GuV und später weitere Berichte aufzubauen.

<Steps>

1. Fügen Sie einen [REST-Anfrage-Schritt](/de/guides/workflows/rest-request-step/) hinzu. Legen Sie auf der Registerkarte **Anfrage** die **Verbindung** auf Ihre NetSuite-Verbindung, die **Methode** auf `POST` und den **Endpunkt** auf `/services/rest/query/v1/suiteql` fest.

2. Geben Sie im **Body** dieses SuiteQL ein, eingebettet als `{"q": "…"}`:

   ```sql
   SELECT
       TO_CHAR(t.trandate, 'YYYY-MM')  AS period,
       a.accttype                      AS account_type,
       a.acctnumber                    AS account_number,
       BUILTIN.DF(a.id)                AS account_name,
       tal.amount                      AS amount
   FROM transactionaccountingline tal
       JOIN transaction t ON t.id = tal.transaction
       JOIN account a     ON a.id = tal.account
   WHERE tal.posting = 'T'
       AND tal.accountingbook = 1
       AND t.trandate BETWEEN TO_DATE('2026-01-01', 'YYYY-MM-DD')
                          AND TO_DATE('2026-12-31', 'YYYY-MM-DD')
   ORDER BY period, a.acctnumber
   ```

3. Legen Sie auf der Registerkarte **Antwort** das Ziel auf **Tabelle** fest — nennen Sie sie `netsuite_gl` — und bestimmen Sie die Spaltentypen: `amount` → **Währung**, alle übrigen → **Text**. (SuiteQL liefert Zahlen und Datumswerte als Text; erst der Typ ermöglicht es, `amount` zu addieren.)

4. Klicken Sie auf **Testanfrage senden**, um zu bestätigen, dass die Anfrage funktioniert, und führen Sie dann den Schritt aus. Sie haben jetzt eine Tabelle `netsuite_gl`: eine Zeile pro Konto und Monat, mit einem vorzeichenbehafteten Buchungsbetrag.

</Steps>

<Aside type="note">
`amount` ist **im Soll positiv, im Haben negativ** — so lautet die Hauptbuchkonvention von NetSuite. Das ist die unverfälschte Rohform; der nächste Schritt macht daraus einen lesbaren Bericht. Wenn Ihre Bücher mehr als eine Tochtergesellschaft oder Währung umfassen, filtern Sie auf eine Tochtergesellschaft (`t.subsidiary = <id>`) — beachten Sie den Hinweis zu mehreren Währungen in den [Abfragebeispielen](/de/guides/connections/netsuite-financial-queries/#in-jedem-rezept-verwendete-konventionen).
</Aside>

## Schritt 3: Das Hauptbuch zu einer GuV aufbereiten

Jetzt folgt die Analyse mit einer einzigen Transformation per Mausklick — ohne SQL. Eine GuV ist einfach das verdichtete Hauptbuch: Ertrags- und Aufwandskonten, zu wenigen Zeilen gruppiert, mit umgekehrtem Vorzeichen, sodass Umsatz positiv erscheint. Ein [Table-Extract-Schritt](/de/reference/workflow-steps/tables/table-extract/) erledigt all das auf seinen Registerkarten **Tabellendatenauswahl** und **Filter**.

<Steps>

1. Fügen Sie einen **Table Extract**-Schritt hinzu. Legen Sie seine **Quelle** auf `netsuite_gl` und sein **Ziel** auf eine neue Tabelle `netsuite_pnl` fest.

2. Behalten Sie auf der Registerkarte **Filter** nur die Ertrags- und Aufwandskonten (Bilanzkonten lassen Sie weg): Fügen Sie einen Filter hinzu, bei dem **`account_type` ist eines von** `Income`, `OthIncome`, `COGS`, `Expense`, `OthExpense`.

3. Klicken Sie auf der Registerkarte **Spalten** auf **Zusammenfassen**, um die Aggregation einzuschalten, und richten Sie dann drei Zielspalten ein:

   - **`period`** — direkt aus der Quelle zugeordnet. Zusammenfassen: **Gruppieren nach**.
   - **`pnl_line`** — ein **Ausdruck** (siehe unten), der jeden Kontotyp in eine Berichtszeile umwandelt. Zusammenfassen: **Gruppieren nach**.
   - **`amount`** — ein **Ausdruck** `netsuite_gl.amount * -1` (die Vorzeichenumkehr). Zusammenfassen: **Summe**.

   Doppelklicken Sie für `pnl_line` in die Zelle **Ausdruck** und geben Sie Folgendes ein (im Editor können Sie die Spalten und die Funktion `case` aus der Gruppe **Bedingungen** per Mausklick auswählen):

   ```python
   case(
       (netsuite_gl.account_type.in_(['Income', 'OthIncome']),  '1 - Revenue'),
       (netsuite_gl.account_type == 'COGS',                     '2 - Cost of Goods Sold'),
       (netsuite_gl.account_type.in_(['Expense', 'OthExpense']), '3 - Operating Expenses'),
   )
   ```

4. Führen Sie den Schritt aus.

</Steps>

Der Ausdruck `amount * -1` ist der einzige buchhalterische Kniff: Durch das Negieren des im Soll positiven Betrags wird **Umsatz positiv und werden Kosten negativ**, sodass die drei Zeilen jedes Monats *in Summe den Jahresüberschuss ergeben*. Anschließend verdichtet **Summe** mit **Gruppieren nach** auf `period` und `pnl_line` jedes Konto zu diesen drei Zeilen pro Monat. Ausdrücke verwenden den Editor von PlaidCloud mit Auswahl per Mausklick — siehe [Erweiterte Nutzung des Data Mappers](/de/reference/workflow-steps/common/advanced-data-mapper-usage/) und die [Ausdrucksreferenz](/de/reference/expressions/).

<Aside type="tip">
Mehrere Dutzend Konten zu drei Zeilen zu gruppieren, ist für einen ersten Durchgang bewusst grob gehalten. Um die Betriebskosten nach Abteilungen aufzuschlüsseln, ergänzen Sie `department` (über `BUILTIN.DF(tl.department)`, mit einem Join auf `transactionline`) im Abruf aus Schritt 2 und fügen dann `department` hier als weitere Spalte mit **Gruppieren nach** hinzu.
</Aside>

## Schritt 4: Wie ein Finanzexperte lesen

Öffnen Sie die Tabelle `netsuite_pnl`. Für jeden Monat haben Sie drei Zahlen:

| period | pnl_line | amount |
|---|---|---|
| 2026-01 | 1 - Revenue | 486,200.00 |
| 2026-01 | 2 - Cost of Goods Sold | -190,540.00 |
| 2026-01 | 3 - Operating Expenses | -212,880.00 |

Direkt daraus ablesbar:

- **Rohertrag** = Umsatz + Herstellungskosten (die Herstellungskosten sind bereits negativ) → `486,200 − 190,540 = 295,660`.
- **Jahresüberschuss** = die Summe der drei Zeilen → `82,780`.
- **Rohertragsmarge in %** = Rohertrag ÷ Umsatz → ca. 61 %.

Als Erstes sollten Sie **abstimmen**: Führen Sie die eigene Erfolgsrechnung von NetSuite für denselben Monat aus und prüfen Sie, ob Umsatz und Jahresüberschuss übereinstimmen. Wenn nicht, liegt es fast immer an einem Unterschied im Umfang — an einem Filter für Tochtergesellschaft oder Währung oder an der Abgrenzung zwischen Buchungsperiode und Transaktionsdatum (siehe den [Hinweis zu Perioden](/de/guides/connections/netsuite-financial-queries/#saldenliste)). Vertrauen Sie der Pipeline erst, wenn die Werte übereinstimmen.

<Aside type="tip">
Sie möchten das klassische Layout mit den Monaten in den Spaltenköpfen? Fügen Sie einen [Table-Pivot-Schritt](/de/reference/workflow-steps/tables/table-pivot/) hinzu, der `netsuite_pnl` liest: Pivotieren Sie `period` in Spalten, behalten Sie `pnl_line` als Zeile und summieren Sie `amount`. So erhalten Sie eine Spalte pro Monat und eine Zeile pro GuV-Position — der Vergleich von Monat zu Monat auf einen Blick, ohne SQL.
</Aside>

## Schritt 5: Eine Debitoren-Altersstruktur aufbauen

Der zweite Erfolg am ersten Tag folgt demselben Muster aus Verbinden, Abrufen und Aufbereiten. Beginnen Sie mit dem Rezept für offene Forderungen und ordnen Sie sie dann danach in Klassen ein, wie überfällig jede Rechnung ist.

<Steps>

1. Fügen Sie einen weiteren **REST-Anfrage**-Schritt hinzu (dieselbe Verbindung, `POST`, derselbe SuiteQL-Endpunkt) mit diesem Body:

   ```sql
   SELECT
       t.tranid                            AS invoice_number,
       BUILTIN.DF(t.entity)                AS customer,
       TO_CHAR(t.trandate, 'YYYY-MM-DD')   AS invoice_date,
       TO_CHAR(t.duedate, 'YYYY-MM-DD')    AS due_date,
       t.foreigntotal                      AS invoice_total,
       t.foreignamountunpaid               AS amount_unpaid
   FROM transaction t
   WHERE t.type = 'CustInvc'
       AND t.foreignamountunpaid <> 0
   ORDER BY t.tranid
   ```

   Legen Sie das Ergebnis als `netsuite_open_ar` ab, mit `invoice_total` und `amount_unpaid` → **Währung**, `invoice_date` und `due_date` → **Datum**, alle übrigen → **Text**.

2. Fügen Sie einen **Table Extract**-Schritt hinzu, der `netsuite_open_ar` in eine neue Tabelle `netsuite_ar_aging` liest. Klicken Sie auf der Registerkarte **Spalten** auf **Zusammenfassen** und richten Sie drei Zielspalten ein:

   - **`aging_bucket`** — ein **Ausdruck** (siehe unten), der jede Rechnung danach kennzeichnet, wie überfällig sie ist. Zusammenfassen: **Gruppieren nach**.
   - **`invoices`** — eine beliebige Spalte, z. B. `invoice_number`. Zusammenfassen: **Anzahl**.
   - **`balance`** — zugeordnet aus `amount_unpaid`. Zusammenfassen: **Summe**.

   Geben Sie für `aging_bucket` diesen Ausdruck ein — er misst die Tage seit der Fälligkeit (ein Datum minus ein Datum ergibt Tage) und kennzeichnet die Klasse:

   ```python
   case(
       ((func.today() - netsuite_open_ar.due_date) <= 0,  '0 - Current'),
       ((func.today() - netsuite_open_ar.due_date) <= 30, '1 - 1-30 days'),
       ((func.today() - netsuite_open_ar.due_date) <= 60, '2 - 31-60 days'),
       ((func.today() - netsuite_open_ar.due_date) <= 90, '3 - 61-90 days'),
       else_='4 - Over 90 days',
   )
   ```

3. Führen Sie den Schritt aus. `netsuite_ar_aging` zeigt Ihnen jetzt in fünf Zeilen, wie viel aktuell und wie viel seit 30/60/90+ Tagen überfällig ist — die Inkasso-Sicht, die ein Unternehmen zuerst liest. (`due_date` muss als **Datum** typisiert sein, damit die Datumssubtraktion funktioniert — das haben Sie oben auf der Registerkarte **Antwort** des REST-Anfrage-Schritts festgelegt.)

</Steps>

## Schritt 6: Auf einem Dashboard darstellen

Zahlen in einer Tabelle sind in Ordnung; ein Diagramm schicken Sie an den CFO. [Veröffentlichen Sie](/de/get-started/tutorials/load-and-transform-data/#schritt-7-das-ergebnis-veröffentlichen) `netsuite_pnl` und `netsuite_ar_aging` und folgen Sie dann der Anleitung [Dashboard erstellen](/de/get-started/tutorials/build-a-dashboard/), um Folgendes hinzuzufügen:

- ein **Balkendiagramm** des Jahresüberschusses (oder Umsatzes) nach `period` und
- ein **Kreis- oder Balkendiagramm** des Debitoren-`balance` nach `aging_bucket`.

Das ist ein aktives NetSuite-Finanz-Dashboard — ohne Export, aktualisiert bei jeder Ausführung des Workflows.

## Schritt 7: Die Aktualisierung planen

<Steps>

1. Führen Sie den gesamten Workflow einmal von oben nach unten aus, um zu bestätigen, dass jeder Schritt grün ist.
2. [Planen Sie den Workflow](/de/get-started/tutorials/schedule-a-workflow/) — monatlich im Rhythmus des Abschlusses oder nachts, wenn die Debitoren-Altersstruktur jeden Morgen aktuell sein soll.

</Steps>

Da jeder Abruf die gesamte Tabelle ersetzt, extrahiert jede Ausführung erneut den Ausschnitt, den ihre `WHERE`-Klausel definiert — beschränken Sie diesen auf das benötigte Fenster (das laufende Jahr, nur offene Rechnungen) statt auf die gesamte Historie.

## Was Sie aufgebaut haben

Ausgehend von einem leeren Workflow haben Sie das aktuelle NetSuite-Hauptbuch und die Forderungen abgerufen, mit zwei Standard-Transformationsschritten — ohne SQL — zu einer **monatlichen GuV** und einer **Debitoren-Altersstruktur** aufbereitet, auf einem Dashboard dargestellt und so eingerichtet, dass sie sich aktualisieren — der zentrale Berichtszyklus eines Finanzteams, jetzt automatisiert.
