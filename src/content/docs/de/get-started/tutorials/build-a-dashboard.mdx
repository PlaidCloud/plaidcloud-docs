*~30 Minuten · eine veröffentlichte Tabelle, ein Diagramm, ein freigegebenes Dashboard*

Sie haben eine saubere, aus einem Workflow veröffentlichte Tabelle. Dieses Tutorial macht daraus etwas, das man auf einen Blick lesen kann: ein Diagramm, dann ein darauf aufgebautes Dashboard und schließlich ein Dashboard, das mit den richtigen Personen geteilt wird. Für ein erstes Diagramm ist kein SQL erforderlich – Sie zeigen, klicken und fragen ab.

Wenn Sie [Daten laden, transformieren und veröffentlichen](/de/get-started/tutorials/load-and-transform-data/) durchgearbeitet haben, ist die dort veröffentlichte Tabelle `sales_final` genau der Ausgangspunkt, von dem dieses Tutorial ausgeht. Jede andere veröffentlichte Tabelle funktioniert ebenso gut.

## Was Sie Erstellen

Ein einzelnes Dashboard mit zwei Diagrammen über einer veröffentlichten Tabelle – eine Big Number mit dem Gesamtumsatz und ein Balkendiagramm, das den Umsatz nach einer Gruppierungsspalte aufschlüsselt – formatiert, gespeichert und für Ihren Workspace sichtbar.

## Voraussetzungen

- Ein PlaidCloud-Workspace und ein Projekt, das Sie öffnen können.
- Eine **veröffentlichte** Tabelle in diesem Projekt. Falls Sie keine haben, folgen Sie zuerst [Daten laden, transformieren und veröffentlichen](/de/get-started/tutorials/load-and-transform-data/) oder veröffentlichen Sie eine beliebige vorhandene Tabelle – klicken Sie sie auf der Registerkarte **Tabellen** mit der rechten Maustaste an und wählen Sie **Set Published Table Reporting Name**. Siehe [Tabellen veröffentlichen](/de/guides/data/publish/).
- Im Bereich „Dashboards“ ist nichts zu installieren – Ihr Dashboard-Konto wird beim ersten Öffnen eines Dashboards aus PlaidCloud für Sie angelegt.

> **Nur veröffentlichte Tabellen gelangen in Dashboards.** Ein Dashboard liest eine Tabelle über ihren veröffentlichten Berichtsnamen, nicht über ihren internen Tabellennamen. Wenn Ihre Tabelle später nicht als Dataset erscheint, wurde sie in der Regel nie veröffentlicht oder unter einem Namen veröffentlicht, den Sie nicht erkennen – prüfen Sie die Spalte **Veröffentlicht als** auf der Registerkarte **Tabellen**.

## Schritt 1: Den Bereich „Dashboards“ Öffnen

1. Öffnen Sie in PlaidCloud aus Ihrem Projekt den Bereich **Dashboards**.
2. Beim ersten Mal wird Ihr Dashboard-Konto automatisch eingerichtet – Sie müssen nichts von Hand anlegen. Was Sie sehen können, ergibt sich aus Ihrer Workspace-Mitgliedschaft und Ihren Sicherheitsgruppen.
3. Ihre veröffentlichte Tabelle steht jetzt als **Dataset** zur Verfügung, weil sie zu einem Projekt gehört, auf das Sie zugreifen können.

Wie die Sichtbarkeit von Dashboards mit der Workspace-Mitgliedschaft zusammenhängt, erfahren Sie unter [Dashboards verwenden](/de/guides/dashboards/using-dashboards/).

## Schritt 2: Das Dataset Vorbereiten

Bevor Sie ein Diagramm erstellen, legen Sie fest, wie sich jede Spalte im Dashboard verhalten soll. Das ist eine einmalige Einrichtung pro Tabelle, durch die der Mausklick-Explorer gut funktioniert.

1. Klicken Sie auf das Bearbeiten-Symbol Ihres Datasets.
2. Öffnen Sie die Registerkarte **List Columns**.
3. Legen Sie für jede Spalte die zutreffenden Rollen fest und klicken Sie dann auf **Speichern**:

| Einstellung | Aktivieren, wenn |
|---|---|
| **Groupable** | Sie Kennzahlen nach diesem Feld aufschlüsseln möchten (Region, Produkt, Monat) |
| **Filterable** | Sie nach diesem Feld filtern möchten |
| **Summe** / **Min** / **Max** | Es sich um ein numerisches Maß handelt, das Sie summieren oder zusammenfassen |
| **Count Distinct** | Sie eindeutige Werte dieses Feldes zählen möchten |
| **Is temporal** | Es sich um ein Datums- oder Zeitfeld handelt |

> **Kennzeichnen Sie Ihre Datumsspalte als temporal.** Zeitbasierte Filter und die Steuerelemente „Since / Until“ im Explorer funktionieren nur bei einer Spalte, die mit **Is temporal** markiert ist. Diese Einstellung wird am leichtesten übersehen.

## Schritt 3: Ihr Erstes Diagramm Erstellen

Beginnen Sie im Explorer, der als einfache Table View geöffnet wird, und formen Sie daraus eine Big Number für den Gesamtumsatz.

> **Verwenden Sie Ihre eigene Maßspalte.** Dieses Tutorial erstellt ein Diagramm über eine Spalte `revenue`, die Voraussetzung ist aber nur „eine beliebige veröffentlichte Tabelle“ – setzen Sie überall dort, wo `revenue` steht, die numerische Spalte ein, die Sie tatsächlich summieren möchten (`amount`, `sales`, `quantity` usw.).

1. Klicken Sie auf das Dataset, um es zu öffnen. Standardmäßig erhalten Sie eine **Table View**.
2. Fügen Sie im Bereich für Kennzahlen das gewünschte Maß hinzu – für eine laufende Summe geben Sie es ein und wählen Ihre summierte Spalte (z. B. eine `SUM` von `revenue`), oder verwenden Sie **COUNT(\*)**, um Zeilen zu zählen.
3. Fügen Sie beliebige Felder für **Gruppieren nach** hinzu, nach denen die Zahl aufgeschlüsselt werden soll. Für eine einzelne Schlagzahl lassen Sie „Gruppieren nach“ leer.
4. Klicken Sie auf **Abfrage**, um sie auszuführen und das Ergebnis zu sehen.
5. Scrollen Sie zu **Chart Options** (oder zur Auswahl des Visualisierungstyps) und stellen Sie den Diagrammtyp auf **Big Number** um. Diagramme können Tables, Big Numbers, Bar Charts und mehr sein – jedes stellt dasselbe Abfrageergebnis anders dar.
6. Klicken Sie erneut auf **Abfrage**, um neu zu zeichnen.

Erstellen Sie nun ein zweites Diagramm, das dasselbe Maß aufschlüsselt:

1. Starten Sie eine neue Exploration auf demselben Dataset.
2. Behalten Sie die `SUM` von `revenue` als Kennzahl bei und fügen Sie ein **Gruppieren nach** auf eine gruppierbare Spalte wie `region` oder `product` hinzu.
3. Stellen Sie den Diagrammtyp auf **Bar Chart** und klicken Sie auf **Abfrage**.
4. Wenn Sie nur die obersten Zeilen möchten, öffnen Sie **Optionen** und legen Sie ein **Zeilenlimit** fest – zum Beispiel `10` für ein Balkendiagramm der Top Ten.

> **Bevorzugen Sie Anzeigeformatierung gegenüber Änderungen an den Daten.** Werte lassen sich auf zwei Arten runden oder umformatieren: in der Tabelle transformieren oder bei der Anzeige formatieren. Die Formatierung bei der Anzeige ist die übliche Wahl – die zugrunde liegenden Werte behalten ihre volle Genauigkeit, und jeder Betrachter sieht eine saubere Zahl. Das ist der nächste Schritt.

## Schritt 4: Die Zahlen Formatieren

Rohe Maße kommen unformatiert zurück. Beheben Sie das im Diagramm, nicht in den Daten.

- **Big Number:** Bearbeiten Sie das Diagramm, öffnen Sie die Registerkarte **Customize** und legen Sie **Number Format** fest.
- **Tabelle:** Bearbeiten Sie das Diagramm, öffnen Sie die Registerkarte **Customize**, wählen Sie unter **Customize Column** eine Zahlenspalte (mit einem `#` angezeigt) und legen Sie ihr **D3 Format** fest.

Standard ist **Adaptive formatting**, das sich an die Werte anpasst. Um ein Format festzulegen, wählen Sie eines aus der Dropdown-Liste oder geben Sie eine D3-Formatzeichenfolge ein:

| Format | Eingabe | Anzeige |
|---|---|---|
| `,d` | `12345.67` | `12,346` |
| `$,d` | `12345.67` | `$12,346` |
| `$,.2f` | `12345.67` | `$12,345.67` |
| `,.2%` | `13.215` | `1,321.50%` |

Die vollständige Formatgrammatik – Währungssymbole, Auffüllung, Genauigkeit, SI-Präfixe – finden Sie unter [Zahlen und andere Datentypen formatieren](/de/guides/dashboards/formatting-numbers/).

> **Auf ganze Dollar runden? Verwenden Sie `,d` oder `$,d`, nicht `,.0f`.** Die Form `,.0f` ist eine bekannte Ursache für fehlerhafte Zahlenformatierung; `,d` (dezimal, auf eine ganze Zahl gerundet) ist der zuverlässige Weg, die Nachkommastellen zu entfernen.

## Schritt 5: Ein Berechnetes Maß Hinzufügen (Optional)

Wenn die gewünschte Zahl keine einfache Spalte ist – ein Verhältnis, ein Margenprozentsatz, eine bedingte Summe –, schreiben Sie sie als Kennzahl. Kennzahlen und berechnete Spalten werden auf dem Dataset in SQL im PostgreSQL-Dialekt geschrieben.

```sql
SUM("revenue") / (COUNT(*) + 0.00001)
```

Das `+ 0.00001` vermeidet eine Division durch null, wenn eine Gruppe keine Zeilen hat. Weitere Muster – `CASE`-Logik, `COALESCE` für Nullwerte, bedingte Summen – finden Sie unter [Beispielkennzahlen](/de/guides/dashboards/example-metrics/) und [Beispiele für berechnete Spalten](/de/guides/dashboards/example-calculated-columns/).

## Schritt 6: Das Dashboard Zusammenstellen

Ein Dashboard ist ein Layout gespeicherter Diagramme. Ordnen Sie jedes erstellte Diagramm demselben Dashboard zu, damit sie zusammen erscheinen.

1. Öffnen Sie **Edit Chart** bei Ihrer Big Number.
2. Geben Sie im Abschnitt **Dashboards** den Namen des Dashboards ein, auf dem sie erscheinen soll. Falls das Dashboard noch nicht existiert, benennen Sie es hier.
3. Speichern Sie und wiederholen Sie das für Ihr Balkendiagramm, wobei Sie es auf dasselbe Dashboard verweisen lassen.
4. Öffnen Sie das Dashboard, um beide Diagramme zu sehen. Im eigenen Bearbeitungsmodus des Dashboards können Sie die Kacheln anordnen, ihre Größe ändern und Filter hinzufügen.

Alle Optionen für Layout, Filter und Interaktion finden Sie unter [Mehr über Dashboards](/de/guides/dashboards/learning-dashboard/).

## Schritt 7: Teilen

Wer das Dashboard sieht, richtet sich zuerst nach dem PlaidCloud-Zugriff und dann nach etwaigen Rollen des Dashboard-Dienstes obendrauf.

- **Standardmäßig ist es für die Personen des Projekts sichtbar.** Die Dashboard-Liste in PlaidCloud zeigt die veröffentlichten Dashboards der Projekte, auf die eine Person zugreifen kann – jeder, der das Projekt öffnen kann, findet also Ihr Dashboard, ohne zusätzlichen Schritt.
- **Fügen Sie Diagrammeigentümer laufend hinzu.** Wenn Sie ein Diagramm speichern, fügen Sie allen, die es benötigen, den **Eigentümern** des Diagramms hinzu – sonst stößt ein Kollege bei einem Diagramm, auf das er keinen Zugriff hat, möglicherweise auf den Fehler „requires the datasource… permission“. Eigentümer beim Speichern hinzuzufügen ist einfacher, als den Zugriff nachträglich einzurichten.
- **Beschränken Sie nur dann auf bestimmte Rollen, wenn es nötig ist.** Ein Dashboard kann auf bestimmte Rollen im Dashboard-Dienst beschränkt werden, festgelegt in den Eigenschaften des Dashboards selbst. Ein eingeschränktes Dashboard wird in der Liste für alle ohne passende Rolle ausgeblendet – wenn Sie eines einschränken, sagen Sie es also den Personen, die Zugriff haben sollen. Der Projektzugriff in PlaidCloud gilt weiterhin obendrauf: Eine Rollenzuweisung gibt nie ein Dashboard zu einem Projekt frei, auf das jemand nicht zugreifen kann.

Die vollständigen Sichtbarkeitsregeln finden Sie unter [Dashboards verwenden](/de/guides/dashboards/using-dashboards/).

## Das Dashboard Aktuell Halten

Dashboards aktualisieren Sie nicht von Hand. Wenn ein Workflow die Tabelle hinter einem Diagramm erneut veröffentlicht, verwirft jedes Diagramm, das sie liest, seine zwischengespeicherten Ergebnisse, und die nächste Person, die das Dashboard öffnet, sieht die neuen Zahlen.

> **Ein veraltet wirkendes Dashboard liegt fast nie am Cache.** Wenn die Zahlen nach einer Workflow-Ausführung alt aussehen, prüfen Sie den Workflow – ob die Ausführung abgeschlossen wurde und die erwartete Tabelle erneut veröffentlicht hat –, nicht den Cache. Veröffentlichen Sie außerdem unter **demselben** veröffentlichten Namen: Diagramme bleiben an einen Namen gebunden, sodass eine unter neuem Namen neu aufgebaute Tabelle die alten Diagramme auf alte Daten zeigen lässt.

Falls Sie die Aktualisierung doch einmal erzwingen müssen, öffnen Sie das Menü neben **Edit dashboard** und wählen Sie **Force refresh dashboard**. Alle Details, auch dazu, wie lange Ergebnisse vorgehalten werden, finden Sie unter [Dashboard-Caching](/de/guides/dashboards/dashboard-caching/).
