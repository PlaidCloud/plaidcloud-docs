*ca. 30 Minuten · eine Dimension, eine Alternativhierarchie, nachgelagert verwendet*

Dimensionen sind die Hierarchien, auf denen alles andere in PlaidCloud aufbaut – Umlagen zielen auf sie, Dashboards gliedern nach ihnen, Berichte verdichten über sie. Dennoch *verweisen* die meisten Anleitungen nur auf Dimensionen, ohne Ihnen beizubringen, wie Sie eine aufbauen. Dieses Tutorial schließt diese Lücke: Sie erstellen eine Kostenstellen-Dimension, geben ihr eine zweite Verdichtungsmöglichkeit, befüllen sie aus einer Tabelle und übergeben sie an einen nachgelagerten Verbraucher.

## Was Sie aufbauen

Eine Kostenstellen-Dimension mit einer **Haupthierarchie**, die Kostenstellen nach Abteilung gruppiert, sowie einer **Alternativhierarchie**, die dieselben Kostenstellen nach Region neu gruppiert. Anschließend laden Sie sie aus einer Quelltabelle und richten eine Umlage darauf aus.

## Voraussetzungen

- Ein PlaidCloud-Workspace ([starten Sie eine kostenlose Testversion](https://app.plaidcloud.com), falls Sie noch keinen haben)
- Ein Projekt, in dem Sie arbeiten (erstellen Sie bei Bedarf auf der Registerkarte **Projekte** eines)
- Vertrautheit mit den [Konzepten](/de/get-started/concepts/) – Workspace, Projekt, Workflow, Dimension
- Optional eine Quelltabelle mit Kostenstellenstruktur für das Laden in Schritt 4 (Sie können den Baum auch von Hand aufbauen)

> **Neu in diesem Thema? Lesen Sie zuerst [Getting Started with Dimensions](/de/guides/dimensions/getting-started/).** Dort wird erklärt, wann sich eine Dimension lohnt und wie Haupt- und Alternativhierarchien zusammenhängen – das Vokabular, das dieses Tutorial voraussetzt.

## Schritt 1: Die Dimension erstellen

Dimensionen befinden sich auf der Registerkarte **Dimensionen** jedes Projekts.

<Steps>

1. Öffnen Sie Ihr Projekt und wechseln Sie zur Registerkarte **Dimensionen**.
2. Wählen Sie in der Symbolleiste über die Schaltfläche **Neu** den Eintrag **Neue Dimension**.
3. Geben Sie einen **Namen** (z. B. `Cost Centers`), ein **Verzeichnis** für die ordnerartige Organisation und eine aussagekräftige **Notiz** ein.
4. Klicken Sie auf **Erstellen**. Die Dimension ist sofort bereit.

</Steps>

Sie haben jetzt eine leere Dimension – eine Hülle mit einer Haupthierarchie, in der noch nichts steht. Der nächste Schritt gibt ihr Struktur.

## Schritt 2: Die Haupthierarchie aufbauen

Jede Dimension hat genau eine **Haupthierarchie**: den kanonischen Baum als einzige Wahrheit, in dem jedes Blattmitglied genau einmal registriert ist. Bauen Sie hier die Abteilungsstruktur auf.

<Steps>

1. Wählen Sie bei geöffneter Dimension die Wurzel aus und klicken Sie in der Hierarchie-Symbolleiste auf **Mitglied hinzufügen**, um die übergeordneten Knoten der obersten Ebene zu erstellen – `Sales` und `Operations`.
2. Wählen Sie eine Abteilung aus und verwenden Sie erneut **Mitglied hinzufügen**, um die Blatt-Kostenstellen anzulegen, die darauf verdichtet werden:

   | Übergeordneter Knoten | Blattmitglieder |
   |---|---|
   | Vertrieb | CC-100, CC-200 |
   | Betrieb | CC-300, CC-400 |
3. Mit der Hierarchie-Symbolleiste können Sie Mitglieder außerdem nach oben und unten verschieben und direkt umhängen, sodass Sie jedes falsch platzierte Mitglied korrigieren können.

</Steps>

> **Jedes Blatt muss in der Haupthierarchie liegen.** Alles in der Dimension ist zuerst ein Mitglied des Hauptbaums – offen ist nur, *wo* es sitzt. Alternativhierarchien (nächster Schritt) verwenden diese Blätter erneut; sie führen nie neue ein.

Bei großen Bäumen wird das Anordnen von Mitgliedern von Hand mühsam. Der Workflow-Schritt [Dimension Sort](/de/reference/workflow-steps/dimensions/dimension-sort/) sortiert programmgesteuert – eine echte Zeitersparnis nach einem Ladevorgang oder einer größeren Umstrukturierung.

## Schritt 3: Eine Alternativhierarchie hinzufügen

Eine **Alternativhierarchie** ist eine andere Sicht auf dieselben Blätter. Sie kann eine Teilmenge auswählen, sie anders gruppieren oder eine völlig andere Verdichtung verwenden. Hier gruppieren Sie die vier Kostenstellen nach Region statt nach Abteilung neu.

<Steps>

1. Fügen Sie der Dimension eine neue Alternativhierarchie hinzu und nennen Sie sie `By Region`.
2. Erstellen Sie in der neuen Hierarchie mit **Mitglied hinzufügen** zwei übergeordnete Knoten – `East` und `West` – und fügen Sie dann die vorhandenen Blätter darunter ein:

   | Regionaler übergeordneter Knoten | Blattmitglieder |
   |---|---|
   | Ost | CC-100, CC-300 |
   | West | CC-200, CC-400 |

</Steps>

Die Blätter sind *dieselben* Mitglieder wie in der Haupthierarchie – Sie hängen sie für diese Sicht um, Sie duplizieren sie nicht. Mitglieder der Haupthierarchie tragen Attributbezeichnungen, die zeigen, zu welchen Alternativhierarchien sie ebenfalls gehören, sodass Sie auf einen Blick sehen, dass CC-100 sowohl eine Vertriebs- als auch eine Ost-Kostenstelle ist.

> **Zwei gängige Alternativmuster.** Eine *Teilmengensicht* zieht eine gezielte Auswahl von Blättern für einen Bericht oder eine Umlage in einen Baum; sie übernimmt Mitgliederänderungen aus der Hauptsicht. Eine *andere Verdichtung* behält jedes Blatt, gruppiert sie aber neu, wie es `By Region` hier tut. Beides beschreibt [Using Dimensions (Hierarchies)](/de/guides/dimensions/dimensions/#alternative-attribut-hierarchien).

## Schritt 4: Aus einer Tabelle laden

Ein paar Knoten von Hand aufzubauen ist für ein Tutorial in Ordnung. In der Praxis befüllen Sie eine Dimension über einen Workflow aus einer Quelltabelle, sodass sie sich aktualisiert, wenn sich die Quelle ändert. PlaidCloud liest zwei Datenformen:

| Format | Form | Am besten geeignet für |
|---|---|---|
| **Parent-Child** | Zwei Spalten – ein übergeordneter, ein untergeordneter Knoten – eine Kante pro Zeile | Beliebig tiefe, unregelmäßige Hierarchien |
| **Levels** | Eine Spalte pro Ebene, ein vollständiger Pfad pro Zeile | Regelmäßige Hierarchien mit vorhersehbarer Tiefe |

<Steps>

1. Wechseln Sie zur Registerkarte **Workflows** und erstellen Sie einen Workflow (z. B. `Load Cost Centers`).
2. Fügen Sie einen Schritt [Dimension Load](/de/reference/workflow-steps/dimensions/dimension-load/) hinzu.
3. Verweisen Sie ihn auf Ihre Quelltabelle, wählen Sie **Parent-Child** oder **Levels** und ordnen Sie die Spalten zu, die die Struktur enthalten.
4. Ein Ladevorgang kann mehr als Struktur transportieren – **Werte, Aliase und Eigenschaften** können im selben Schritt mitgeladen werden. Ordnen Sie auch diese Spalten zu, wenn Ihre Quelle sie enthält.
5. Führen Sie den Schritt aus und öffnen Sie dann die Registerkarte **Dimensionen** erneut, um zu prüfen, ob der Baum zu Ihrer Quelle passt.

</Steps>

> **Ein Ladevorgang baut Struktur auf; er setzt die Dimension nicht zurück.** Um eine Dimension vor dem erneuten Laden vollständig zu leeren – Struktur, Werte, Aliase, Eigenschaften und Alternativhierarchien –, verwenden Sie zuerst [Dimension Clear](/de/reference/workflow-steps/dimensions/dimension-clear/). Den gesamten Rundlauf, einschließlich des Exports der Hierarchie in eine flache Tabelle für Berichte, beschreibt [Loading and Unloading Dimensions](/de/guides/dimensions/loading-unloading/).

## Schritt 5: Knoten anreichern (optional)

Eine Hierarchie kann mehr sein als ein Baum aus Namen. Jeder Knoten kann **Eigenschaften** (die Währung einer Kostenstelle, ihre zuständige Geschäftseinheit), **Aliase** und **Werte** tragen. Schalten Sie in der Hierarchie-Symbolleiste **Eigenschaften** ein, um pro Eigenschaft eine Spalte anzuzeigen, und fügen Sie mit **Neue Eigenschaft** eine hinzu.

Sie können Werte auch direkt in der Hierarchie berechnen. **Aggregationen** holen summierte, gezählte, minimale oder maximale Werte aus einer Tabelle in jeden Knoten, und **Ausdrücke** rechnen mit diesen Aggregationen unter Verwendung von Rechenoperatoren, Bedingungen und Funktionen wie `Column(...)`, `Leafcount()` und `Parentvalue(...)`. Den vollständigen Umfang beschreibt [Dimension Functions for Expressions and Aggregations](/de/guides/dimensions/function-expressions/).

## Schritt 6: Nachgelagert verwenden

Der Nutzen: Sie definieren den Baum einmal und verweisen überall darauf. Ihre Dimension ist jetzt ein Ziel für den Rest von PlaidCloud.

- **Umlagen** zielen auf eine Dimension, um einen Kostenpool auf ihre Blätter zu verteilen – der naheliegende nächste Schritt weiter unten.
- **Berichte und Dashboards** gliedern und führen durch die Hierarchie, mit dem Hauptbaum für die eine Verdichtung und `By Region` für eine andere, aus denselben zugrunde liegenden Blättern.
- **Dimensionszugeordnete Spalten** in einem [Dateneditor](/de/guides/projects/managing-data-editors/) oder in der Eigenschaft **Auswahl (Dimension)** einer anderen Dimension lassen Benutzer über eine Mitgliederauswahl Mitglieder aus Ihrem Baum wählen.

Damit eine Umlage funktioniert, halten Sie die Namen der Blattmitglieder in Ihrer Dimension identisch mit den Schlüsseln in Ihren Treiber- und Quelldaten – eine Abweichung bei Leerzeichen oder Groß- und Kleinschreibung bedeutet, dass ein Blatt nichts erhält. Genau auf diesem Vertrag baut das nächste Umlagen-Tutorial auf.
