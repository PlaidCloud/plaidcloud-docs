PlaidCloud konvertiert KNIME-Workflows (`.knwf`) und Workflow-Gruppen (`.knar`)
in native erweiterte Workflows. Der Importer ordnet jeden KNIME-Node einem
Workflow-Schritt, einer Projektvariablen oder einem Arbeitsflächenobjekt zu und
löst Metanodes und Komponenten auf, sodass ein konvertierter Workflow
Cloud-nativ ausgeführt wird.

98,5 % der KNIME-Node-Konfigurationen werden vollständig konvertiert, und 205 der 207 Kern-Node-Typen
sind vollständig unterstützt. Wie Sie eine Konvertierung durchführen, lesen Sie unter
[KNIME-Workflows migrieren](/de/guides/workflows/migrate-knime-workflows/).

Jeder Node hat einen Status:

- **Vollständig** — Der Node hat eine gültige Zuordnung zu PlaidCloud-Schritten.
- **Teilweise** — Der Node wird für seinen üblichen Einsatz konvertiert, während ein bestimmter
  *Funktionsmodus* nicht abgebildet wird; der Modus wird benannt.
- **Nicht unterstützt** — Keine Konvertierung; der Node bleibt als benannter
  Platzhalter auf der Arbeitsfläche, und die Funktion wird stattdessen nativ neu aufgebaut.

Ältere und veraltete Varianten eines Nodes sind unter dem Node aufgeführt, der sie
ersetzt.

Die wenigen Verhaltensweisen, die ein konvertierter Workflow nicht abbildet, sind unter
[Bekannte Sonderfälle](#bekannte-sonderfälle) aufgeführt.

Ein Connector-Node wird zur PlaidCloud-Verbindung, auf der seine Schritte ausgeführt werden — siehe
[Anbindung externer Systeme](#anbindung-externer-systeme).

## Node-Unterstützung

Von den 207 Kern-Nodes sind 205 vollständig, 2 teilweise und 0 nicht unterstützt.

## Familien von Erweiterungs-Nodes

Auch Nodes aus den Erweiterungsfamilien von KNIME werden in Standard-PlaidCloud-Schritte
konvertiert: Datenbank, REST und Webservices, Skripting in Python, R und Java, maschinelles
Lernen, JSON und XML, Textverarbeitung, Benachrichtigung und Berichterstellung, Zeitreihen,
Geodaten, Big Data, Bildverarbeitung, Chemie, Workflow-Services
und der lange Schwanz von Kern-Hilfs-Nodes. Ein Node ohne Konvertierungspfad
bleibt als benannter Platzhalter erhalten; siehe [Nicht konvertiert](#nicht-konvertiert).

## Nicht konvertiert

Ein Node ohne Konvertierungspfad bleibt als benannter Platzhalter auf der Arbeitsfläche.
Der Platzhalter reicht seine Daten durch, fügt eine Warnung hinzu, die den KNIME-Node
nennt, und lässt die Konvertierung nie fehlschlagen — eine fehlende oder nicht gebundene Eingabe ist eine
Warnung, kein Fehler. Jeder Schritt hinter einem Platzhalter wird markiert, sodass ein
fehlendes Ergebnis nie unbemerkt bleibt.

## Anbindung externer Systeme

Ein KNIME-Connector-Node wird zur Verbindung, auf der seine Schritte ausgeführt werden. Anmeldedaten
werden nie importiert, sodass Sie jede Verbindung im Ziel-Workspace
selbst auswählen, und die Warnung am Schritt nennt, was einzustellen ist.

| KNIME | Was Sie in PlaidCloud festlegen |
| --- | --- |
| Database connectors | Eine Datenbankverbindung, die bei der Konvertierung gebunden oder am Schritt ausgewählt wird. |
| REST and web service nodes that sign in | Eine [REST-Verbindung](/de/reference/connectors/rest/generic-rest/), die bei der Konvertierung gebunden oder am Schritt ausgewählt wird. |
| Speech Recognizer (IBM Watson) | Eine REST-Verbindung zur Watson-Service-URL, deren Basic-Anmeldung den Benutzer `apikey` mit Ihrem API-Schlüssel als Kennwort verwendet. |
| Email Connector, Email Reader, Email Mover | Das Mailserver-Kennwort in der Projektvariablen, die die Warnung des Schritts nennt. Host und Benutzer stammen vom Email Connector. |
| Password-protected Excel workbooks | Das Arbeitsmappen-Kennwort in der Projektvariablen, die die Warnung des Schritts nennt. |
| LLM connectors and authenticators | Eine LLM-Verbindung am KI-Schritt. |
| Views, charts and reporting layout | Nichts; diese Nodes haben keine Auswirkung auf die Daten und sind im Konvertierungsbericht aufgeführt. |

Die Konvertierung kontaktiert nie ein Quell- oder Zielsystem.

## Einen konvertierten Workflow prüfen

Zeilenreihenfolge und RowID werden durch die Nodes hindurchgereicht, die sie lesen, sodass ein
Workflow, der von der Zeilenreihenfolge abhängt, sie über diese Nodes hinweg beibehält. Vergleichen Sie die Ausgabe des
konvertierten Workflows mit der Ausgabe Ihres KNIME-Workflows: Schema, Zeilenanzahl
und Zeilenwerte.
