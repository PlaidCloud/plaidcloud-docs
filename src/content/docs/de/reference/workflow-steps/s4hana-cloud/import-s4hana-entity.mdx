## Beschreibung

Importiert eine SAP-S/4HANA-Cloud-Entität über Ihre [S/4HANA-Cloud-Verbindung](/de/guides/connections/s4hana-cloud/) in eine Projekttabelle. Wählen Sie die Verbindung, den Entitätstyp und beliebige Filter; der Schritt ruft die passenden Datensätze ab und schreibt sie, ohne dass Sie eine OData-Abfrage verfassen müssen.

Dies ist ein generischer vorgefertigter Schritt – ein Schritttyp deckt zwei Entitäten ab: einen aggregierten `trial_balance`-Cube für die Periodenabschlussberichterstattung und `journal_entry_items` auf Positionsebene für detaillierte gebuchte Transaktionen.

## Konfiguration

| Feld | Erforderlich | Hinweise |
|---|---|---|
| S/4HANA Connection | Ja | Die S/4HANA-Cloud-Verbindung, über die gelesen wird. |
| Zieltabelle | Ja | Die Projekttabelle, in die die Ergebnisse geschrieben werden. Sie wird bei jeder Ausführung vollständig überschrieben. |
| Entitätstyp | Ja | Welche Entität abgerufen wird. Standard ist `trial_balance`. Eines von `trial_balance`, `journal_entry_items`. |
| Filter | Nein | Bereichs- und Gleichheitsfilter, die in den OData-`$filter` der Anfrage übersetzt werden. Jede Entität beschränkt Filter auf die Felder, die S/4HANA serverseitig tatsächlich auswerten kann – ein nicht unterstütztes Feld wird abgelehnt und nicht stillschweigend verworfen. |

### Entitäten und filterbare Felder

| Entitätstyp | Was abgerufen wird | OData-Dienst | Filterbare Felder |
|---|---|---|---|
| `trial_balance` | Aggregierte Hauptbuchkontensalden zum Periodenende | `API_OPLACCTGDOCITEMCUBE_SRV` | `CompanyCode`, `GLAccount`, `CostCenter`, `ProfitCenter`, `FiscalYear` (Bereich), `FiscalPeriod` (Bereich), `Ledger` |
| `journal_entry_items` | Gebuchte Journalbuchungspositionen | `API_JOURNALENTRYITEMBASIC_SRV` | `CompanyCode`, `GLAccount`, `CostCenter`, `ProfitCenter`, `PostingDate` (Bereich), `FiscalYear` (Bereich), `FiscalPeriod` (Bereich), `Ledger` |

<Aside type="note">
`PostingDate`, `FiscalYear` und `FiscalPeriod` akzeptieren **Bereichsfilter** (Grenzen im Stil von `ge`/`le`) – die wichtigste Möglichkeit, einen Abruf von `journal_entry_items` zu begrenzen, da ein unbegrenzter Abruf von Positionsdetails sehr groß werden kann. Legen Sie bei einer großen Entität mindestens eine Grenze fest, bevor Sie den Schritt gegen Produktionsdaten ausführen.
</Aside>

<Aside type="caution">
`CostCenter` und `ProfitCenter` sind nur filterbar, wenn Ihr Communication Scenario sie bereitstellt. Eine Dimension, die nicht Teil dieses Szenarios ist, wird als nicht unterstützter Filter abgelehnt und nicht stillschweigend ignoriert.
</Aside>
