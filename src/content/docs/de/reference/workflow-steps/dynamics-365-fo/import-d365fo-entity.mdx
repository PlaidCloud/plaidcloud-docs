## Beschreibung

Importiert eine Dynamics-365-Finance-&-Operations-Entität über Ihre [D365-F&O-Verbindung](/de/guides/connections/dynamics-365-fo/) in eine Projekttabelle. Wählen Sie die Verbindung, den Entitätstyp, den Synchronisierungsmodus und beliebige Filter; der Schritt lädt die passenden Datensätze und schreibt sie, ohne dass Sie eine OData-Abfrage verfassen müssen.

Dies ist ein generischer vorgefertigter Schritt – ein Schritttyp deckt sechs Entitäten ab, von Stamm-/Referenzdaten (Hauptkonten, Währungen, Kunden, Lieferanten, freigegebene Produkte) bis zu Bewegungsdaten (Hauptbuch-Journalköpfe), entweder über einen direkten OData-Aufruf oder einen asynchronen DMF-Bulk-Extrakt.

## Konfiguration

| Feld | Erforderlich | Hinweise |
|---|---|---|
| D365-F&O-Verbindung | Ja | Die D365-F&O-Verbindung, über die gelesen wird. |
| Zieltabelle | Ja | Die Projekttabelle, in die die Ergebnisse geschrieben werden. Sie wird bei jeder Ausführung vollständig überschrieben. |
| Entitätstyp | Ja | Welche Entität geladen wird. Standard `main_accounts`. Eine von `main_accounts`, `currencies`, `customers`, `vendors`, `released_products`, `ledger_journal_headers`. |
| Synchronisierungsmodus | Ja | Standard `odata`. `odata` ruft den standardmäßigen OData-Endpunkt der Entität direkt auf. `dmf` übergibt einen asynchronen Data-Management-Framework-Exportauftrag und lädt das Ergebnis herunter, sobald er abgeschlossen ist – für Abrufe, die über reines OData-Paging zu groß oder zu langsam sind. |
| Filter | Nein | Bereichs- und Gleichheitsfilter, die in den OData-`$filter` der Anfrage übersetzt werden. Jede Entität beschränkt Filter auf die Felder, die D365 F&O serverseitig tatsächlich auswerten kann – ein nicht unterstütztes Feld wird abgelehnt, nicht stillschweigend verworfen. |

### Entitäten und filterbare Felder

| Entitätstyp | Was geladen wird | Filterbare Felder |
|---|---|---|
| `main_accounts` | Kontenplan | Kontenbereich, Dimension |
| `currencies` | Währungsstamm | — |
| `customers` | Kundenstamm | Kontenbereich |
| `vendors` | Lieferantenstamm | Kontenbereich |
| `released_products` | Stamm der freigegebenen Produkte | — |
| `ledger_journal_headers` | Journalköpfe, gebucht und ungebucht | Datumsbereich, Kontenbereich, Dimension |

<Aside type="note">
**Bereichsfilter** (Grenzen im Stil von `ge`/`le`) für Datum, Konto und Dimension sind der wichtigste Weg, einen Abruf von `ledger_journal_headers` zu begrenzen – ein unbegrenzter Abruf des Buchungsverlaufs kann sehr groß werden. Setzen Sie bei einer großen Entität mindestens eine Grenze, bevor Sie gegen Produktionsdaten ausführen.
</Aside>

<Aside type="caution">
Der Modus `dmf` (Bulk) wartet auf einen asynchronen Exportauftrag und ist für dieselbe Entität und denselben Filtersatz deutlich langsamer als der Modus `odata`. Reservieren Sie ihn für Extrakte, die für einen direkten OData-Abruf zu groß sind.
</Aside>
