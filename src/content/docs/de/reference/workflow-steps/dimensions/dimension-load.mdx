## Beschreibung

Lädt oder aktualisiert eine Dimension aus Daten in einer PlaidCloud-Tabelle. Unterstützt sowohl Erstladungen (die Hierarchie wird von Grund auf aufgebaut) als auch inkrementelle Aktualisierungen (Mitglieder hinzufügen, übergeordnete Elemente ändern, Eigenschaften aktualisieren, ohne bei null neu aufzubauen).

Unterstützt zwei Formen von Quelldaten: **Parent-Child** (eine Zeile pro Kante im Baum) und **Levels** (eine Spalte pro Hierarchieebene, ein vollständiger Pfad pro Zeile). Werte, Aliasnamen und Eigenschaften können zusammen mit den Strukturdaten geladen werden.


## Dimensionsauswahl
### Dimension dynamisch angeben
Um eine Dimension dynamisch anzugeben, nehmen Sie **Projekt**- und/oder **lokale** Variablen in den Namen auf.


Variablen sind nützlich, wenn Dimensionen regelmäßig aktualisiert werden und die historische Sicht erhalten bleiben soll.

Ein Beispiel, das die Variable `current_month` verwendet, um die Dimension dynamisch zu laden:

```text
dimension_name_{current_month}
```
### Bestimmte Dimension verwenden

Um eine bestimmte Dimension zu verwenden, wählen Sie die **Dimension** im Dropdown-Menü aus.


### In Alternativhierarchie laden

Um eine Alternativhierarchie zu laden, wählen Sie zuerst die Dimension dynamisch oder bestimmt aus, aktivieren das Kontrollkästchen „In Alternativhierarchie laden“ und geben den Namen der zu ladenden Alternativhierarchie ein.

<Aside>Es ist oft sinnvoll, alternative Sichten bzw. Aufsummierungen der Hauptdimension zu haben. Kostenstellen haben zum Beispiel meist eine buchhalterische Aufsummierung, es kann aber eine alternative Sicht auf Grundlage der Organisationsstruktur gewünscht sein.</Aside>

Ein Mitglied, das nicht in der Haupthierarchie liegt, kann sich in nur einer Alternativhierarchie befinden. Ein Ladevorgang, der es auch in eine zweite Alternativhierarchie einordnen würde, schlägt fehl und nennt das Mitglied sowie die Alternativhierarchie, die es bereits enthält. Um ein Blatt in mehreren Alternativhierarchien zu verwenden, fügen Sie es zuerst der Haupthierarchie hinzu. Ein übergeordnetes Element braucht in jeder Alternativhierarchie einen eigenen Namen, weil eine Alternativhierarchie keine Mitglieder unter einem Mitglied der Haupthierarchie hinzufügen kann.

## Quelltabelle

### Dynamisch 
Um die Quelltabelle dynamisch anzugeben, aktivieren Sie das **Kontrollkästchen „Dynamisch“** und geben den Tabellennamen einschließlich der **Projekt**- und/oder **lokalen** Variablen im Namen ein.

### Statisch

Um eine bestimmte **Quelltabelle** zu verwenden, wählen Sie die Tabelle im Dropdown-Menü aus.

## Dimensionseigenschaften und Tabellenlayout

### Standard-Konsolidierungstyp

Es gibt drei Optionen für Konsolidierungstypen:
* **"+"**: Aggregiert Werte in der Dimension.
* **"-"**: Subtrahiert Werte in der Dimension.
* **"~"**: Es wird keine Aggregation in der Dimension durchgeführt.

<Aside>In der Quelldatentabelle können Sie den **Konsolidierungstyp** als Spalte aufnehmen, sodass innerhalb einer Dimension mehrere Konsolidierungstypen verwendet werden können. Die Spalte **Konsolidierungstyp** wird dann im Abschnitt **Spaltenzuordnung** weiter unten verwendet.</Aside>

### Tabellenspaltenformat
Beim Laden einer Dimension gibt es zwei Optionen für die Formatierung der **Quelltabelle**. 
#### Parent Child
In einer Parent-Child-Tabelle stellen zwei Spalten die Struktur der Dimension dar, **Parent** und **Child**.

**BEISPIEL PARENT CHILD**

| PARENT    | CHILD    | Konsolidierungstyp |
|-----------|----------|--------------------|
|Parent All | Parent 1 |        ~           |
|Parent All | Parent 2 | ~                  |
| Parent 1  | Child 1  | +                  |
| Parent 2  | Child 2  | +                  |
| Child 1   | Child 3  | +                  |
| Child 1   | Child 4  | +                  |
| Child 2   | Child 5  | +                  |

<Aside>Im Parent-Child-Tabellenformat können Sie außerdem eine Spalte **Konsolidierungstyp** in die Tabelle aufnehmen. Der **Konsolidierungstyp** gehört zum untergeordneten Element.</Aside>

Eine Zeile mit leerem übergeordnetem Element lädt ihr untergeordnetes Element als Mitglied der obersten Ebene direkt unter der Wurzel. Eine Zeile mit leerem untergeordnetem Element wird übersprungen.

#### Flattened Levels
In einer Flattened-Level-Tabelle gibt es beliebig viele Spalten, wobei jede Spalte eine Ebene der Dimension darstellt.

**BEISPIEL FLATTENED LEVELS**

|Ebene 1   |Ebene 2 |Ebene 3|Ebene 4|
|----------|--------|-------|-------|
|Parent All|Parent 1|Child 1|Child 3|
|Parent All|Parent 1|Child 1|Child 4|
|Parent All|Parent 2|Child 2|Child 5|

## Spaltenzuordnung

Mit der Menüschaltfläche **Quelle untersuchen** wird die **Quellspalte** im Data Mapper gefüllt.
Sobald die **Quellspalte** gefüllt ist, ordnen Sie über das Dropdown-Menü **Art** die **Quellspalten** dem passenden Spaltentyp zu.
