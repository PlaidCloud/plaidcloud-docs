## Beschreibung

Der Schritt **Räumlich: Datei-Export** schreibt eine Tabelle in eine Geodatei in einem Dokumentenkonto, ein Feature pro Zeile: die Geometrie aus einer WKT-Spalte und die übrigen Spalten als Attribute des Features. Setzen Sie ihn zusammen mit [Räumlicher Dateiimport](/de/reference/workflow-steps/spatial/spatial-file-import/) ein.

Das Schrittformular hat einen Abschnitt **Quelle und Datei** für die Quelltabelle, ihre Spalten, die Ausgabedatei und das Verhalten bei vorhandener Datei sowie einen Abschnitt **Geometrie** für die Geometriespalte und das Koordinatensystem. [Migrierte KNIME-Workflows](/de/guides/workflows/migrate-knime-workflows/) verwenden diesen Schritt für ihre Geodaten-Dateischreiber.

## Konfiguration

- **Quelltabelle** (`source`) — die Tabelle, die exportiert wird. **Quellspalten** (`source_columns`) listet die geschriebenen Spalten auf.
- **Ausgabedatei** (`output_file`) — das Dokumentenkonto und der Pfad der Datei. Die Dateiendung bestimmt das Format: `.shp` (ESRI-Shapefile), `.geojson` oder `.json` (GeoJSON), `.gpkg` (GeoPackage), `.kml`, `.gml` oder `.tab` und `.mif` (MapInfo). Ein Format aus mehreren Dateien, etwa ein Shapefile, wird samt seinen Begleitdateien daneben geschrieben.
- **Geometriespalte** (`geometry_column`) — die Spalte, die die Geometrie jedes Features als WKT enthält. Standard ist `SpatialObj`.
- **Koordinatensystem** (`crs`) — das Koordinatenreferenzsystem, in dem die Geometrien vorliegen, etwa `EPSG:4326`; es wird mit der Datei geschrieben.
- **Eine bereits vorhandene Datei** (`if_exists`) — **Überschreiben** (`overwrite`, Standard) ersetzt eine bereits vorhandene Datei; **Den Schritt fehlschlagen lassen, ohne etwas zu schreiben** (`fail`) bricht den Schritt ab, bevor etwas geschrieben wird.
