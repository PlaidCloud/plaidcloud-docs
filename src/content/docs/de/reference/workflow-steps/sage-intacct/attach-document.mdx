## Beschreibung

Hängt Belege über Ihre [Sage-Intacct-Verbindung](/de/guides/connections/sage-intacct/) an Sage-Intacct-Datensätze an, geleitet über die gemeinsame ERP-Schreibpipeline von PlaidCloud. Jede Zeile der Quelltabelle ist eine Datei – ihre Bytes, ihr Name und der Schlüssel des Intacct-Datensatzes, an den sie angehängt wird –, die der Schritt als Sage-Intacct-Beleg (`supdoc`) anlegt und mit diesem Datensatz verknüpft. **Validate Only** prüft jede Zeile, ohne in Intacct etwas anzulegen; die Ergebnistabelle hält das Ergebnis pro Anhang fest.

Verwenden Sie ihn, um Dateien, die ein Workflow bereits vorliegen hat – ein gerendertes Rechnungs-PDF, einen eingescannten Beleg, einen exportierten Bericht –, in derselben Ausführung, die sie erzeugt oder bucht, an die Intacct-Transaktionen oder -Datensätze zu übertragen, zu denen sie gehören. Er passt gut zu [Intacct: Journalbuchung buchen](/de/reference/workflow-steps/sage-intacct/export-to-sage/): Buchen Sie die Buchungen und hängen Sie dann deren Belege mit dem Intacct-Schlüssel an, den jede Buchung zurückgegeben hat.

## Datenstruktur-Vertrag

Erstellen Sie die Anhangstabelle vorgelagert mit Standardschritten, sodass jede Zeile eine vollständige Datei ist, die an einen Datensatz gebunden ist:

- **`parent_key`** – der Sage-Intacct-Datensatz, an den die Datei angehängt wird. Eine Datei, ein übergeordneter Datensatz pro Zeile; um dieselbe Datei an mehrere Datensätze anzuhängen, wiederholen Sie sie in mehreren Zeilen.
- **`file_name`** – der Dateiname des Belegs, einschließlich Erweiterung (`invoice-1043.pdf`).
- **`mime_type`** – der Inhaltstyp der Datei (`application/pdf`, `image/png`), damit Intacct sie korrekt speichert und ausliefert.
- **`content_base64`** – die Bytes der Datei, Base64-kodiert, in der Zeile.

## Konfiguration

### Verbindung

- **Sage-Intacct-Verbindung** – die Sage-Intacct-Verbindung, über die angehängt wird. Es werden nur Sage-Intacct-Verbindungen angeboten; dieselbe Verbindung liest aus Intacct und schreibt dorthin.
- **Umgebung** – die Umgebung der Verbindung.

### Daten

- **Anhangstabelle** – die oben beschriebene Quelltabelle: eine Zeile pro Datei, mit `parent_key`, `file_name`, `mime_type` und `content_base64`.
- **Ergebnistabelle** – Ausgabetabellen-ID: eine Zeile pro Anhang mit `parent_key`, `file_name`, `supdoc_id`, `status`, `message`.
- **Validate Only** – standardmäßig aktiviert. Nur Vorabprüfung; prüft jede Zeile und schreibt die Ergebnistabelle, legt aber in Intacct keinen Beleg an. Eine Schrittkonfiguration, die dieses Feld ganz weglässt – etwa eine über die REST-API, MCP oder einen Workflow-Bundle-Import erstellte –, verwendet ebenfalls standardmäßig Validate Only statt eines echten Anhängens.
- **Continue On Error** – standardmäßig aktiviert. Hängt die übrigen Dateien weiter an, nachdem eine fehlgeschlagen ist; ist die Option deaktiviert, stoppt der Schritt beim ersten Fehler.

## Ergebnistabelle

Jede Ausführung – Validate Only oder echt – schreibt pro Quellzeile eine Zeile in die Ergebnistabelle:

| Spalte | Beschreibung |
|---|---|
| `parent_key` | Der Intacct-Datensatz, auf den dieser Anhang zielt. |
| `file_name` | Der Dateiname aus der Quellzeile. |
| `supdoc_id` | Die Sage-Intacct-Beleg-ID, die für die Datei angelegt wurde, wenn das Anhängen erfolgreich war. |
| `status` | Das Ergebnis für diese Zeile – validiert, angehängt oder fehlgeschlagen. |
| `message` | Eine kurze, bereinigte Beschreibung dessen, was schiefgegangen ist, wenn die Zeile fehlgeschlagen ist. |
