## Beschreibung

Importiert ein Sage-Intacct-Objekt über Ihre [Sage-Intacct-Verbindung](/de/guides/connections/sage-intacct/) in eine Projekttabelle und nutzt dabei die Operationen `readByQuery`/`readMore` des Intacct XML Gateway, um die gesamte Ergebnismenge automatisch seitenweise zu lesen. Wählen Sie die Verbindung, das Objekt und beliebige Filter; der Schritt ruft die passenden Datensätze ab und schreibt sie, ohne dass Sie die Paginierung selbst verwalten müssen.

Dies ist ein generischer vorgefertigter Schritt – ein Schritttyp deckt sieben Objekte ab, von Hauptbuch-Transaktions- und Saldendetails (`GLDETAIL`, `GLACCOUNTBALANCE`, `GLENTRY`) über Dimensionsstammdaten (`LOCATION`, `DEPARTMENT`, `CLASS`) bis zu Auftragsbelegen (`SODOCUMENT`).

<Aside type="note">
Dieser Schritt unterscheidet sich von [Import Sage Intacct Query](/de/reference/workflow-steps/sage-intacct/import-intacct-query/), der **jedes** Intacct-Objekt mit einer universellen Feldauswahl anspricht. `Import Intacct Entity` ist der Schritt mit nativem Katalog speziell für diese sieben Objekte, mit einer kuratierten Filter-Allowlist pro Objekt und automatischer `readMore`-Paginierung für große Ergebnismengen (insbesondere Hauptbuchdetails können weit über eine einzelne Intacct-API-Seite hinausgehen).
</Aside>

## Konfiguration

| Feld | Erforderlich | Hinweise |
|---|---|---|
| Sage-Verbindung | Ja | Die Sage-Intacct-Verbindung, über die gelesen wird. |
| Zieltabelle | Ja | Die Projekttabelle, in die die Ergebnisse geschrieben werden. Sie wird bei jeder Ausführung vollständig überschrieben. |
| Objekt | Ja | Welches Intacct-Objekt abgerufen wird. Eines von `GLDETAIL`, `GLACCOUNTBALANCE`, `GLENTRY`, `LOCATION`, `DEPARTMENT`, `CLASS`, `SODOCUMENT`. |
| Filter | Nein | Ein Array von `{field, operator, value}`-Klauseln. Zu den Operatoren gehören `eq`, `ne`, `gt`, `ge`, `lt`, `le`. Ein Bereich wird als zwei Klauseln für dasselbe Feld ausgedrückt – eine mit `ge`, eine mit `le`. Jedes Objekt beschränkt Filter auf seine eigene Allowlist aus Feld und Operator; eine nicht unterstützte Kombination aus Feld und Operator wird abgelehnt und nicht stillschweigend verworfen. |

### Objekte und typische Bereichsfilter

| Objekt | Was abgerufen wird | Gängige Bereichsfilter |
|---|---|---|
| `GLDETAIL` | Hauptbuch-Transaktionspositionen im Detail | Buchungsdatum (`ge`/`le`), Betrag (`ge`/`le`) |
| `GLACCOUNTBALANCE` | Kontensalden nach Periode | Periodenenddatum (`ge`/`le`) |
| `GLENTRY` | Gebuchte Journalbuchungspositionen | Buchungsdatum (`ge`/`le`) |
| `LOCATION` | Stammdaten der Dimension Standort | – (nur Gleichheitsfilter) |
| `DEPARTMENT` | Stammdaten der Dimension Abteilung | – (nur Gleichheitsfilter) |
| `CLASS` | Stammdaten der Dimension Klasse | – (nur Gleichheitsfilter) |
| `SODOCUMENT` | Kundenauftragsbelege | Belegdatum (`ge`/`le`) |

## So funktioniert die Paginierung

Das XML Gateway von Intacct liefert Ergebnisse seitenweise. Dieser Schritt sendet zunächst den Aufruf `readByQuery` und folgt dann mit `readMore`-Aufrufen unter Verwendung der von Intacct zurückgegebenen Ergebnismengen-ID, bis jede Seite gelesen wurde – ein Abruf von `GLDETAIL` mit Zehntausenden Positionen wird daher in einer einzigen Schrittausführung abgeschlossen, ohne dass Sie die Seitengröße anpassen müssen.

<Aside type="caution">
Ein sehr breiter, ungefilterter Abruf von `GLDETAIL` oder `GLENTRY` kann trotzdem lange dauern, bis er vollständig seitenweise gelesen ist. Begrenzen Sie einen großen Abruf mit einem Buchungsdatumsbereich, statt sich allein auf die Paginierung zu verlassen, um ihn schnell zu machen.
</Aside>
