## Beschreibung

Importiert eine Oracle-Fusion-Cloud-Entität über Ihre [Oracle-Fusion-Verbindung](/de/guides/connections/oracle-fusion/) in eine Projekttabelle und ruft dabei die OData- bzw. BI-Publisher-(BIP-)Endpunkte von Fusion direkt auf. Wählen Sie die Verbindung, den Entitätstyp und beliebige Filter; der Schritt ruft die passenden Datensätze ab und schreibt sie, ohne dass Sie eine OData-Abfrage verfassen müssen.

Für einen Abruf, der für einen direkten Aufruf zu groß ist, verwenden Sie stattdessen [Import Fusion Bulk Extract](/de/reference/workflow-steps/oracle-fusion/import-fusion-bulk-extract/).

## Konfiguration

| Feld | Erforderlich | Hinweise |
|---|---|---|
| Fusion Connection | Ja | Die Oracle-Fusion-Verbindung, über die gelesen wird. |
| Zieltabelle | Ja | Die Projekttabelle, in die die Ergebnisse geschrieben werden. Sie wird bei jeder Ausführung vollständig überschrieben. |
| Entitätstyp | Ja | Welche Entität abgerufen wird. Standard ist `gl_balances`. Eines von `gl_balances`, `journal_batches`. |
| Filter | Nein | Bereichsfilter (`ge`/`le`) für Datums-, Buchungsperioden- und numerische Saldo-/Betragsfelder sowie Gleichheitsfilter für diskrete Felder (Hauptbuch, Währung). Jede Entität beschränkt Filter auf die Felder, die Oracle Fusion serverseitig tatsächlich auswerten kann – ein nicht unterstütztes Feld wird abgelehnt und nicht stillschweigend verworfen. |

### Entitäten und filterbare Felder

| Entitätstyp | Was abgerufen wird | Filterbare Felder |
|---|---|---|
| `gl_balances` | Kontensalden des Hauptbuchs | Buchungsperiodenbereich (`ge`/`le`), Kontenbereich, Saldenbetragsbereich (`ge`/`le`) |
| `journal_batches` | Kopfdaten und Status von Journalstapeln | Datumsbereich (`ge`/`le`), Buchungsperiodenbereich (`ge`/`le`) |

<Aside type="note">
Ein Bereichsfilter ist schon mit nur einer Grenze nützlich – `accounting_date ge 2026-01-01` ohne obere Grenze ruft alles ab diesem Datum ab. Geben Sie beide Grenzen an, um einen Abruf eng einzugrenzen.
</Aside>
