## Beschreibung

Importiert eine Oracle-Fusion-Cloud-Entität über Ihre [Oracle-Fusion-Verbindung](/de/guides/connections/oracle-fusion/) auf dem FBDI/BI-Publisher-Bulk-Extract-Pfad von Oracle: PlaidCloud übermittelt einen Exportjob, fragt ihn bis zum Abschluss ab, lädt die resultierende Datei herunter und schreibt sie in eine Projekttabelle. Verwenden Sie diesen Schritt statt [Import Fusion Entity](/de/reference/workflow-steps/oracle-fusion/import-fusion-entity/) für einen Abruf, der für einen direkten OData-/BIP-Aufruf zu groß oder zu langsam ist.

## Konfiguration

| Feld | Erforderlich | Hinweise |
|---|---|---|
| Fusion-Verbindung | Ja | Die Oracle-Fusion-Verbindung, über die gelesen wird. |
| Zieltabelle | Ja | Die Projekttabelle, in die die Ergebnisse geschrieben werden. Sie wird bei jeder Ausführung vollständig überschrieben. |
| Entitätstyp | Ja | Welche Entität extrahiert wird. Standard `gl_balances`. Eines von `gl_balances`, `journal_batches`. |
| Filter | Nein | Derselbe Filtersatz wie bei [Import Fusion Entity](/de/reference/workflow-steps/oracle-fusion/import-fusion-entity/): Bereichsfilter (`ge`/`le`) auf Datums-, Buchungsperioden- und numerischen Saldo-/Betragsfeldern sowie Gleichheitsfilter auf diskreten Feldern. Werden auf Ebene des Extraktjobs angewendet. |

<Aside type="caution">
Dieser Schritt wartet auf einen asynchronen Exportjob – rechnen Sie bei gleicher Zeilenanzahl mit deutlich längerer Dauer als bei [Import Fusion Entity](/de/reference/workflow-steps/oracle-fusion/import-fusion-entity/). Verwenden Sie ihn nur, wenn der Abruf wirklich zu groß für einen direkten OData-/BIP-Aufruf ist.
</Aside>
