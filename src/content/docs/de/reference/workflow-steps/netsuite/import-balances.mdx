## Beschreibung

Importiert Kontensalden aus NetSuite über Ihre [NetSuite-Verbindung](/de/guides/connections/netsuite/) in eine Projekttabelle – eine Saldenliste, auf der Sie Berichte aufbauen können. Wählen Sie die Verbindung, benennen Sie eine Zieltabelle und legen Sie Periode und Tochtergesellschaft fest; der Schritt ruft die Salden ab und schreibt sie, ohne dass Sie SuiteQL erstellen oder pflegen müssen.

Dies ist einer der vorgefertigten [NetSuite-Importschritte](/de/reference/workflow-steps/netsuite/). Alle laufen auf einer gemeinsamen Leseschicht, die das OAuth-Token erneuert, große Ergebnisse seitenweise abruft und vorübergehende Fehler für Sie wiederholt, sodass ein Abruf für ein ganzes Jahr oder alle Tochtergesellschaften ohne manuelles Feintuning vollständig zurückkommt. Für einen Abruf auf Transaktionsebene verwenden Sie [NetSuite: Hauptbuchdetails importieren](/de/reference/workflow-steps/netsuite/import-gl-detail/); für Konten, Tochtergesellschaften und andere Listen verwenden Sie [NetSuite: Stammdaten importieren](/de/reference/workflow-steps/netsuite/import-master-data/).

## Konfiguration

| Feld | Erforderlich | Hinweise |
|---|---|---|
| NetSuite-Verbindung | Ja | Die NetSuite-Verbindung, über die gelesen wird, gefiltert auf Verbindungen vom Typ NetSuite. |
| Zieltabelle | Ja | Die Projekttabelle, in die die Salden geschrieben werden. Sie wird bei jeder Ausführung vollständig überschrieben. |
| Startdatum | Nein | Das früheste einzuschließende Datum, `YYYY-MM-DD`, einschließlich. Lassen Sie das Feld leer für keine Untergrenze. Zusammen mit Enddatum angegeben, wird der Abruf automatisch in Datumsabschnitte unterteilt, um unter der SuiteQL-Zeilenobergrenze von NetSuite zu bleiben – siehe den Achtung-Hinweis unten. |
| Enddatum | Nein | Das späteste einzuschließende Datum, `YYYY-MM-DD`, einschließlich. Lassen Sie das Feld leer für keine Obergrenze. |
| Tochtergesellschaft | Nein | Die interne ID einer NetSuite-Tochtergesellschaft, um den Abruf auf eine Tochtergesellschaft zu beschränken. Lassen Sie das Feld leer für alle Tochtergesellschaften. |
| Rechnungslegungsbuch | Nein | Die interne ID eines NetSuite-Rechnungslegungsbuchs. Lassen Sie das Feld leer, um **nur das primäre Buch (interne ID 1)** abzurufen, oder geben Sie `all` ein, um über alle Bücher zu summieren. |
| Kontonummer | Nein | Eine exakte Hauptbuch-Kontonummer, um den Abruf auf ein Konto zu beschränken. Lassen Sie das Feld leer für alle Konten. |
| Buchungsperiode | Nein | Die interne ID einer NetSuite-Buchungs- bzw. Rechnungslegungsperiode. Lassen Sie das Feld leer für alle Perioden. |

<Aside type="caution">
**Konten mit mehreren Büchern:** Ein NetSuite-Konto mit Multi-Book Accounting bucht pro Buch und Transaktionszeile eine Zeile. Bleibt das Rechnungslegungsbuch leer, wird **nur das primäre Buch** abgerufen – die richtige Wahl für eine Standard-Saldenliste. Setzen Sie es nur dann auf `all`, wenn Sie bewusst eine buchübergreifende Summe wünschen (die die Bücher addiert, statt sie abzustimmen), oder auf die interne ID eines bestimmten Buchs, um nur dieses Buch abzurufen.
</Aside>

<Aside type="note">
Tochtergesellschaft und Rechnungslegungsbuch erwarten die interne ID von NetSuite, keinen Namen. Rufen Sie die internen IDs einmal mit [NetSuite: Stammdaten importieren](/de/reference/workflow-steps/netsuite/import-master-data/) ab (Datensatztyp **subsidiary**) und halten Sie sie als kleine Referenztabelle vor.
</Aside>

<Aside type="note">
Die SuiteQL-API von NetSuite begrenzt eine einzelne Abfrage ohne SuiteAnalytics Connect auf ca. 100.000 Zeilen. Wenn Sie sowohl Startdatum als auch Enddatum angeben, kann PlaidCloud den Abruf vorausschauend in Abschnitte unterteilen, die unter dieser Obergrenze bleiben, sodass ein Abruf für ein ganzes Jahr ohne Ihr Zutun vollständig zurückkommt. Ein **offener** Abruf (Startdatum oder Enddatum leer), der die Obergrenze überschreitet, schlägt mit einer Meldung fehl, die Sie bittet, einen Datumsbereich anzugeben, statt stillschweigend ein abgeschnittenes Ergebnis zurückzugeben.
</Aside>
