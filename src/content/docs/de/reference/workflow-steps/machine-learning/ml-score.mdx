## Beschreibung

Der Schritt **ML: Bewerten** bewertet eine Datentabelle mit einem Modell, das von [ML: Modell trainieren](/de/reference/workflow-steps/machine-learning/ml-train/) trainiert wurde, und schreibt die Daten mit einer angefügten Vorhersagespalte. Da das Modell als gewöhnliche Tabelle vorliegt, können Sie einmal trainieren und viele Tabellen bewerten oder jedes Mal neu bewerten, wenn neue Daten eintreffen. Der Schritt läuft als verwalteter PlaidCloud-Auftrag (wie der LLM-Schritt).

## Registerkarte „Bewertung“

- **Datentabelle** – die zu bewertende Tabelle. Sie muss jede Merkmalsspalte enthalten, mit der das Modell trainiert wurde.
- **Modelltabelle** – eine Modelltabelle, die von einem Schritt „ML: Modell trainieren“ geschrieben wurde. Der Schritt schlägt fehl, wenn die Tabelle leer ist oder ein Teil des gespeicherten Modells fehlt.
- **Ausgabetabelle** – wohin die bewerteten Daten geschrieben werden.
- **Vorhersagespalte** – der Name der angefügten Spalte. Lassen Sie das Feld leer, um `prediction` zu verwenden. Der Schritt schlägt fehl, wenn der Name in der Datentabelle bereits existiert.

## Ausgabe

Die Ausgabetabelle enthält jede Spalte der Datentabelle plus die Vorhersagespalte: Klassenbezeichnungen als Text bei Klassifikatoren, numerische Werte bei Regressoren. Merkmalswerte werden genau so aufbereitet wie beim Training, und kategoriale Werte, die das Modell beim Training nie gesehen hat, werden ignoriert, statt einen Fehler zu verursachen.

Die Modelltabelle muss die Form haben, die ein Schritt „ML: Modell trainieren“ schreibt – den vollständigen Satz an Modellspalten, einen bekannten Algorithmus und alle vorhandenen Teile des gespeicherten Modells. Das Modell selbst wird unter einer Einschränkung geladen, die alles außerhalb des standardmäßigen wissenschaftlichen Stacks ablehnt, sodass eine von Hand erstellte Modellzeile keinen beliebigen Code ausführen kann.

### Weitere Ausgabespalten

Der Abschnitt **Bewertungsoptionen** hat diese Felder. Konvertierte KNIME-Workflows verwenden sie ebenfalls.

- **Klassenwahrscheinlichkeitsspalten** (`probability_column_template`) – fügt bei einem Klassifikator pro Klasse eine Wahrscheinlichkeitsspalte an, benannt nach dieser Vorlage, wobei `{class}` ersetzt wird. **Wahrscheinlichkeiten vor der Vorhersage** (`probabilities_first`) stellt sie vor die Vorhersagespalte, und **Klassen in der Reihenfolge ihres ersten Auftretens im Training ordnen** (`classes_in_domain_order`) ordnet sie nach der Reihenfolge, in der die Klassen in den Trainingsdaten zuerst auftreten, statt sortiert.
- **Konfidenzspalte** (`confidence_column`) – fügt bei einem Klassifikator die Wahrscheinlichkeit der gewinnenden Klasse unter diesem Namen an.
- **Varianzspalte** (`variance_column`) – fügt bei einem Forest-Regressor die Varianz der Vorhersagen der Bäume unter diesem Namen an.
- **Modellanzahlspalte** (`model_count_column`) – fügt bei einem Baummodell die Anzahl der Bäume unter diesem Namen an.
- **Reihenfolge der angehängten Spalten** (`column_order`) – die Reihenfolge der angefügten Spalten. Leer: Vorhersage, Wahrscheinlichkeiten, Konfidenz, Varianz, dann Modellanzahl.
- **Stattdessen schreiben** (`report`) – schreibt eine der eigenen Tabellen des Modells statt der bewerteten Daten, etwa `variable_importance`, `coefficients`, `statistics`, `pmml` (das Modell als PMML-Dokument), `centers`, `cluster_counts` oder `association_rules`.
- **Modellformat** (`model_format`) – `pmml` bewertet mit einem PMML-Dokument: Die Modelltabelle enthält das Dokument oder das Modell eines Lerners, der eine PMML-Form hat.
- **Algorithmuseinstellungen** (`algorithm_settings`) – Einstellungen der Bewertung oder des Berichts, die für den Algorithmus des Modells spezifisch sind, etwa die Anzahl der Komponenten, auf die ein `pca`-Modell projiziert.
- **Dritte Tabelle** (`source_c`) – eine dritte Tabelle, die manche Algorithmen lesen, etwa der Random Forest, den ein `knn_distance`-Modell verwendet.

Ein KI-Assistent oder die REST-API kann `report` auch auf `shap_values` setzen.

## Grenzen und Einschränkungen

- **Arbeitsmenge im Arbeitsspeicher** – die Datentabelle wird in den Arbeitsspeicher gelesen, daher zielt der Schritt auf etwa eine Million Zeilen pro Ausführung.
- **Konvertierte Alteryx-Workflows** – ein konvertiertes Predict-Tool legt die Vorhersagespalte auf den Namen der Zielvariable mit dem Suffix `_predicted` fest.
