## Beschreibung


Kopiert Daten aus einer Tabelle im aktuellen Projekt in eine Tabelle eines anderen Projekts. Nützlich, wenn Projekte Referenzdaten gemeinsam nutzen, wenn ein Konsolidierungsprojekt Daten aus mehreren operativen Projekten bezieht oder wenn Sie verarbeitete Ergebnisse an das Projekt eines anderen Teams übergeben möchten.

Das Schema von Quelle und Ziel muss kompatibel sein. Das Zielprojekt muss diesem Projekt eine Datenfreigabe mit **Schreiben** erteilen.


## Datenfreigabe-Verwaltung

![Datenfreigabe-Verwaltung](/images/import_external_project_table_1.png)

Bevor Sie eine Tabelle in ein anderes Projekt exportieren können, muss dieses Projekt diesem hier das Schreiben erlauben. Öffnen Sie die Registerkarte **Startseite** des **Zielprojekts**, klicken Sie unter **Datenfreigabe-Verwaltung** auf **Neue Datenfreigabe**, wählen Sie dieses Projekt aus, aktivieren Sie unter **Zulässige Vorgänge** die Option **Schreiben** und klicken Sie auf **Datenfreigabe hinzufügen**. Siehe [Daten zwischen Projekten freigeben](/de/guides/projects/managing-projects/#daten-zwischen-projekten-freigeben).

Der Schritt läuft mit der eigenen Identität dieses Projekts, sodass eine Ausführung über die Freigabe funktioniert, wer sie auch startet.

## Externe Projekttabelle exportieren

![Externe Projekttabelle exportieren](/images/export_external_project_table.png)

### Lesen aus
Wählen Sie die **Quelltabelle** im Dropdown-Menü aus.

<Aside type="note" title="Leere Quelltabelle">
Wenn die Quelltabelle bei der Ausführung des Schritts keine Zeilen hat, endet der Export mit einer Warnung, dass die Quelle leer war, statt mit einem stillen Erfolg – so fällt ein unerwartet leeres Ziel leicht auf. Meist bedeutet das, dass der Workflow diese Tabelle noch nicht aufgebaut hatte; stellen Sie vor dem Export sicher, dass die Quelle gefüllt ist (und bei geplanten Ausführungen zuerst läuft).
</Aside>

### Schreiben nach

#### Zielprojekt
Wählen Sie das **Zielprojekt** im Dropdown-Menü aus.

#### Statische Zieltabelle

Um die Zieltabelle festzulegen, wählen Sie entweder über die Dropdown-Liste **Zieltabelle** eine vorhandene Tabelle als Zieltabelle aus oder klicken Sie auf das grüne **„+“**-Zeichen, um eine neue Tabelle als Ziel zu erstellen. 

##### Tabelle erstellen
Beim Erstellen einer neuen Tabelle können Sie wählen, ob sie als **Ansicht** oder als **Tabelle** erstellt wird. 
###### Ansichten:
Ansichten sind nützlich, weil die Ausführungszeit eines Schritts deutlich kürzer ist als bei einer Tabelle. Der Nachteil von Ansichten ist, dass sie sich im Detailmodus der Tabelle nicht gut für die Datenerkundung eignen.

###### Tabellen:
Bei einer Tabelle als Ziel dauert die Ausführung eines Schritts länger, aber die Datenerkundung im Detailmodus ist deutlich schneller als bei einer Ansicht.

<Aside>Verwenden Sie Tabellen für Schlüsselschritte in Ihren Workflows, bei denen Datenvalidierung oder Ad-hoc-Analysen nötig sind. Verwenden Sie für alle anderen Schritte Ansichten, um die gesamte Berechnungszeit des Workflows zu verkürzen. Eine Tabelle lässt sich in eine Ansicht umwandeln und umgekehrt, sodass Sie den Zieltabellentyp später jederzeit ändern können.</Aside>

#### Dynamische Zieltabelle

Die Option **Dynamisch** erlaubt die Angabe einer Tabelle als Text, einschließlich Variablen. Das ist nützlich bei variablengesteuerten Workflows, in denen Tabellen- und Ansichtsverweise relativ zu den angegebenen Variablen sind.

Ein Beispiel, das die Variable `current_month` verwendet, um dynamisch auf die Zieltabelle zu verweisen:

```text
legal_entity/inputs/{current_month}/ledger_values
```

<Aside>Wenn die Tabelle nicht existiert, wird sie dynamisch erstellt, wenn der Importvorgang läuft</Aside>

#### An vorhandene Daten anfügen

Um die Daten der Quelltabelle an die Zieltabelle anzufügen, aktivieren Sie das Kontrollkästchen ***An vorhandene Daten anfügen***.
