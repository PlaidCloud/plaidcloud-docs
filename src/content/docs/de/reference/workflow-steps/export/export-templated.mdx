## Beschreibung

Rendert Projekttabellen über eine Vorlage zu einem strukturierten Dokument, statt des rohen Spaltenauszugs, den die anderen Exportschritte schreiben. Verwenden Sie ihn, wenn das empfangende System eine bestimmte XML-Form oder ein anderes Textformat statt einer Tabelle verlangt.

## Spezifische Konfigurationselemente

### Quellvorlage

Die Jinja-Vorlage, aus der die Ausgabe gerendert wird. Siehe [Was eine Vorlage verwenden kann](#was-eine-vorlage-verwenden-kann).

### Zielausgabe

Das Dokumentenkonto, der Ordner und der Dateiname für das gerenderte Ergebnis. Die Vorlage bestimmt, was die Datei enthält; ein Dateiname ohne Erweiterung erhält `.xml`.

**Pandas-Dataframes für Tabellendaten verwenden** ändert, wie die Zeilen jeder Quelle die Vorlage erreichen. Siehe [Quellzeilen als Tabelle](#quellzeilen-als-tabelle).

### Quelltabelle

Benennen Sie die Tabellen ausdrücklich oder finden Sie sie über einen Pfad und eine Suchregel – exakt, beginnt mit, endet mit, enthält oder Glob.

## Was eine Vorlage verwenden kann

Die Vorlage wird in einer Sandbox gerendert: Sie liest die Daten, die der Schritt ihr gibt, und sonst nichts.

- **Jede Quelle unter ihrem Namen (Name).** Jede Quelltabelle, die Sie auflisten, steht der Vorlage unter dem **Name** zur Verfügung, den Sie ihr geben; verwenden Sie daher einen Namen, der als Variable funktioniert, etwa `invoices`.
- **Die Variablen des Workflows** als `variable` – zum Beispiel `{{ variable.region }}`.

```jinja
<Invoices>
{% for row in invoices %}
  <Invoice id="{{ row.invoice_id }}" amount="{{ row.amount }}" />
{% endfor %}
</Invoices>
```

### Quellzeilen als Liste

Ist **Pandas-Dataframes für Tabellendaten verwenden** deaktiviert, ist eine Quelle eine schreibgeschützte Liste von Zeilen. Durchlaufen Sie sie in einer Schleife oder verwenden Sie `|length`, `keys()`, `first()`, `one()`, `all()`, `scalar()`, `scalars()`, `mappings()`, `fetchmany(n)` und `columns('a', 'b')`. Einen Wert aus einer Zeile lesen Sie als `row.amount`, `row['amount']` oder `row[0]`; `row._mapping`, `row._asdict()` und `row._fields` funktionieren ebenfalls. Zeilen aus `columns('a', 'b')` akzeptieren `row.amount` oder `row[0]`, nicht `row['amount']`.

### Quellzeilen als Tabelle

Ist **Pandas-Dataframes für Tabellendaten verwenden** aktiviert, ist eine Quelle eine schreibgeschützte Tabelle. Beim Durchlaufen in einer Schleife erhalten Sie jede Zeile als Dictionary, sodass sowohl `row.amount` als auch `row['amount']` funktionieren. Außerdem können Sie verwenden:

- `columns`, `empty`, `shape`, `values` und `index`
- `head(n)` und `tail(n)`
- `itertuples()`, das die Zeilenposition als `Index` an den Anfang setzt, sodass `r[1]` die erste Spalte ist; `itertuples(index=False)` lässt sie weg
- `iterrows()`, das die Zeilenposition und die Zeile liefert
- `invoices['amount']`, die Werte einer Spalte, mit `sum()`, `min()`, `max()`, `mean()`, `unique()` und `tolist()`; `sum`, `min`, `max` und `mean` überspringen Nullwerte

Andere Pandas-Methoden wie `loc` und `groupby` sind nicht verfügbar. Bringen Sie die Daten in einem früheren Schritt in Form und exportieren Sie das Ergebnis.

### Was eine Vorlage nicht kann

- Eine Methode aufrufen, deren Name mit `to_` beginnt, auf einem beliebigen Wert – `to_csv` und `to_json`, aber auch harmlose wie `to_pydatetime`.
- Ein Attribut lesen, dessen Name mit einem Unterstrich beginnt, außer `_mapping`, `_asdict` und `_fields` einer Zeile.
- Dateien schreiben oder öffnen.

Ein `to_`-Aufruf oder eine Dateioperation lässt den Schritt fehlschlagen. Ein Unterstrich-Attribut außer diesen dreien wird einfach als nichts gerendert.
