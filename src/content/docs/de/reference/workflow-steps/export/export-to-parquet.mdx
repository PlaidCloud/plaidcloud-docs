## Beschreibung

Schreibt eine Projekttabelle als [Apache-Parquet](https://parquet.apache.org/)-Datei in ein Dokumentenkonto. Parquet speichert Daten spaltenweise statt zeilenweise. Dadurch lassen sich breite Tabellen deutlich besser komprimieren als mit CSV, und ein nachgelagerter Leser kann nur die Spalten laden, die er benötigt.

Das ist in der Regel die richtige Wahl, um große Tabellen an eine Cloud-Datenplattform oder einen Data-Science-Workflow zu übergeben. Typen wie Ganzzahlen, Dezimalzahlen, Datums- und Zeitstempelwerte bleiben erhalten, und eine Spalte mit ganzen Zahlen bleibt eine Ganzzahlspalte, auch wenn einige ihrer Werte leer sind. Kombinieren Sie ihn mit [Import Parquet](/de/reference/workflow-steps/import/import-parquet/).

## Besondere Konfigurationselemente

### Komprimierung

Parquet komprimiert pro Spaltenblock:

* **Snappy** — am schnellsten zu lesen, mittlere Dateigröße
* **Zstandard** — kleinere Dateien, erfordert einen Leser ab Zstandard 0.8

### Präfix der Zieldatei

Wenn der Schritt eine Tabelle in eine einzelne Datei exportiert und der Wert bereits auf `.parquet` endet, etwa `Loadfile1.parquet`, wird die Datei genau unter diesem Namen geschrieben. Andernfalls ist der Wert ein Präfix: Jede Tabelle wird als `<prefix><table name>.parquet` geschrieben.

### Eine Datei pro Tabelle

Parquet-Exporte schreiben eine Datei pro Tabelle. Die Auswahl, mehrere Dateien zu schreiben, wird mit einer entsprechenden Meldung abgelehnt. Heben Sie diese Auswahl auf, um den Export auszuführen.

### Wenn die Datei existiert

**Eine bereits vorhandene Datei** (`if_exists`), unter **Wenn die Datei existiert** auf der Seite **Dateiparameter**:

* **Überschreiben** (`overwrite`, Standard) ersetzt eine bereits vorhandene Datei.
* **Den Schritt fehlschlagen lassen, ohne etwas zu schreiben** (`fail`) beendet den Schritt, ohne etwas zu schreiben, wenn eine Datei, die er schreiben würde, bereits existiert.
