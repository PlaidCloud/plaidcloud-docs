## Beschreibung

Schreibt eine Projekttabelle als [Apache-Avro](https://avro.apache.org/)-Datei in ein Dokumentenkonto. Avro trägt sein Schema in der Datei selbst, sodass Spaltennamen und -typen den Hin- und Rückweg ohne separate Schemadefinition überstehen – was es zur guten Wahl für die Übergabe von Daten an einen Kafka-, Spark- oder Hadoop-Konsumenten macht.

Kombinieren Sie ihn mit [Avro importieren](/de/reference/workflow-steps/import/import-avro/), um Tabellen ohne Typverlust zwischen Projekten zu verschieben.

## Spezifische Konfigurationselemente

### Komprimierung

Die geschriebene Datei kann beim Ausgeben komprimiert werden:

* Keine Komprimierung
* Zip
* GZip
* BZip2

### Dateiname

Die Datei wird nach dem **Dateinamen** des Exports benannt; die Erweiterung `.avro` wird ergänzt, wenn der Name keine Erweiterung hat. Ein Export mit dem Namen `customers` schreibt `customers.avro`. Schreibt der Export mehrere Tabellen, wird jede Datei nach dem Export benannt, gefolgt vom Alias der Tabelle, etwa `customers_orders.avro`. Ist **Many Files** aktiviert, schreibt der Export einen Ordner dieses Namens mit `data1.avro`, `data2.avro` und so weiter, jeweils mit höchstens der Stapelgröße an Zeilen.

### Wenn die Datei existiert

**Eine bereits vorhandene Datei** (`if_exists`), unter **Wenn die Datei existiert** auf der Seite **Dateiparameter**:

* **Überschreiben** (`overwrite`, Standard) ersetzt eine bereits vorhandene Datei.
* **Den Schritt fehlschlagen lassen, ohne etwas zu schreiben** (`fail`) stoppt den Schritt, ohne etwas zu schreiben, wenn eine Datei, die er schreiben würde, bereits existiert.
