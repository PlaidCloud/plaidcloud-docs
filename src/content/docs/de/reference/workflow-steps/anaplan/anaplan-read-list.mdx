## Beschreibung

Liest eine oder mehrere Anaplan-Listen über Ihre [Anaplan-Verbindung](/de/guides/connections/anaplan/) und lädt sie in eine PlaidCloud-Dimension. **Ein Schritt liest eine ganze zusammengesetzte Hierarchie** — nennen Sie jede Liste, die sie umfasst, beginnend mit der Wurzel (zum Beispiel Region, dann Land, dann Filiale) —, statt sie auf mehrere Schritte aufzuteilen: Die Staging-Tabelle wird bei jeder Ausführung vollständig ersetzt, sodass mehrere Schritte, die auf dieselbe Staging-Tabelle zeigen, jeweils die Zeilen des vorherigen löschen würden.

Dieser Schritt erscheint im Schrittmenü unter **Anaplan** mit der Bezeichnung **Listen lesen**.

Der Schritt erreicht Anaplan **direkt über die Cloud** mit seiner Integration API — es gibt keinen Pfad über einen lokalen Agent.

<Aside type="tip">
Dieser Konnektor ist schreibgeschützt und authentifiziert sich mit Basic-Anmeldedaten (Benutzername und Passwort) oder CA-Zertifikat — siehe [Authentifizierung](/de/guides/connections/anaplan/#authentifizierung). Das Anfragebudget von Anaplan wird mandantenweit geteilt, daher sollten Sie den Zeitplan dieses Schritts gegenüber Ihren anderen Anaplan-Workflows zeitlich versetzen — siehe [Überlegungen zum Zeitplan](/de/guides/connections/anaplan/#hinweise-zu-zeitplänen).
</Aside>

## Konfiguration

### Anaplan-Quelle

| Feld | Erforderlich | Hinweise |
|---|---|---|
| Anaplan-Verbindung | Ja | Die [Anaplan-Verbindung](/de/guides/connections/anaplan/), über die gelesen wird. |
| Umgebung | Ja | Die Umgebung der Verbindung. |
| Modell | Nein | Überschreibt die in der Verbindung gespeicherte Modell-ID. Wird live aus der Verbindung ermittelt oder von Hand eingegeben. |
| Listen | Ja | Jede Anaplan-Liste, die die Hierarchie umfasst, als geordnete Liste. Fügen Sie aus dem gewählten Modell ermittelte Listen hinzu oder geben Sie eine ID von Hand ein und ordnen Sie sie dann mit Nach oben / Nach unten neu an. Eine Auflistung mit der Wurzel zuerst liest sich gut, ändert aber nichts an dem, was geladen wird — jede Liste wird gelesen, bevor ein Elternelement aufgelöst wird. |
| Staging-Tabelle | Ja | Die rohen Zeilen für Eltern/Kind/Konsolidierung/Name und Eigenschaften landen hier, bevor die PlaidCloud-Dimension daraus aufgebaut wird. |

### PlaidCloud-Zieldimension

| Feld | Erforderlich | Hinweise |
|---|---|---|
| Dimension dynamisch angeben | Eines von beiden | Name der Zieldimension, der `{variable}`-Token enthalten kann, die zur Laufzeit aufgelöst werden. Standardmäßig ausgewählt. |
| Bestimmte Dimension verwenden | Eines von beiden | Wählen Sie stattdessen eine bereits vorhandene PlaidCloud-Dimension. |

## Vorschau

**Vorschau** auf der Registerkarte **Quelle** zeigt die Spalten und Datentypen an, die dieser Listenlesevorgang erzeugen würde, ohne den Schritt auszuführen. Sie ist in einem gesperrten Projekt nicht verfügbar.

## Was dieser Schritt nicht abbilden kann

| Einschränkung | Bedeutung |
|---|---|
| Jede Kante wird mit einem einfachen `+` verdichtet | Anaplan-Listenhierarchien tragen kein Gewicht und kein Vorzeichen pro Kante — es gibt nichts zu lesen, sodass bei der Übersetzung nichts verloren geht, aber auch nicht mehr abgebildet werden kann. Wenn ein Modell Ausschlüsse oder negative Verdichtungen über eine Zeilenposition oder eine Eigenschaft ausdrückt, wird diese Logik nicht in die Dimension übernommen und muss nachgelagert neu aufgebaut werden. |
| Zugriffssteuerungs-Flags und Teilmengenzugehörigkeit werden nicht importiert | Die Lese-/Schreib-Flags des selektiven Zugriffs und die Teilmengenzugehörigkeit jedes Elements sind Anaplan-Metadaten, keine Dimensionsdaten — würde jede Teilmenge als eigene Spalte importiert, würde sie sonst in einem wachsenden, gemeinsam genutzten Namensraum mit echten Eigenschaften kollidieren. Eine echte Listeneigenschaft, deren Name mit einem von beiden kollidiert, wird abgelehnt, statt stillschweigend unter dem Namen des anderen geladen zu werden. |
| Teilmengen von Zeilenpositionen sind nicht als Dimensionen lesbar | Anaplan stellt sie nur über einen generischen Endpunkt für Dimensionselemente bereit, nicht als Liste, die dieser Schritt lesen kann. |
| Eine Liste mit mehr als 1.000.000 Datensätzen kann auf diesem Pfad nicht gelesen werden | Der Elemente-Endpunkt, aus dem dieser Schritt liest, lehnt oberhalb dieser dokumentierten Obergrenze rundweg ab, statt ein Teilergebnis zurückzugeben, und bietet keine Möglichkeit, sie per Paginierung zu umgehen — daher lehnt der Schritt ab und nennt die Obergrenze, statt eine Teildimension zu laden. Teilen Sie die Liste in Anaplan auf oder lesen Sie vorerst eine Teilmenge davon. |
| Ein Knoten hat genau ein Elternelement | Ein Element, dessen Elternname und Eltern-ID nicht übereinstimmen, dessen Elternelement in einer Liste liegt, die dieser Schritt nicht liest, oder dessen benanntes Elternelement gar nicht existiert, wird unter Nennung des Namens abgelehnt, statt stillschweigend der Wurzel der Dimension zugeordnet zu werden. |
| Das oberste Element einer Liste wird nicht importiert | Das oberste Element von Anaplan ist ein Verdichtungsknoten, der über jedem Element der Liste steht und nicht selbst ein Element der Liste ist, daher wird es von den Elementen, die dieser Schritt liest, nie zurückgegeben. Die Dimension ist am Ende eine Ebene flacher als die Anaplan-Liste, und die eigenen Wurzeln der Liste werden zu den Wurzeln der Dimension. Der Schritt warnt, wenn eine von Ihnen gelesene Liste eines deklariert. |
| Knoten-IDs müssen über alle gemeinsam gelesenen Listen eindeutig sein | Die ID eines Knotens ist der Anaplan-Code des Elements oder sein Name, wenn es keinen hat — und ein Anaplan-Code ist nur innerhalb einer Liste garantiert eindeutig. Zwei Listen, die dieselben kurzen Codes wiederverwenden, werden unter Nennung des Namens abgelehnt, statt stillschweigend zu einem Knoten zusammengeführt zu werden. |
| Alternative Hierarchien werden nicht unterstützt | Jede Liste wird in die Haupthierarchie der Dimension geladen. |
| Schreibgeschützt | Es wird nie etwas zurück nach Anaplan geschrieben. |
