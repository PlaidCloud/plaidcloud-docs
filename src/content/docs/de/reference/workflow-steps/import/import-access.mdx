## Beschreibung

Liest eine Microsoft-Access-Datenbankdatei aus einem Dokumentenkonto und importiert ihre Tabellen – eine Projekttabelle pro Access-Tabelle, benannt mit einem Präfix Ihrer Wahl.

Da eine Access-Datei viele Tabellen enthält, importiert dieser Schritt die Datei als Ganzes, statt die Spalten einer einzelnen Tabelle zuzuordnen.

## Spezifische Konfigurationselemente

### Quelle

Die Access-Datenbankdatei in einem Dokumentenkonto. Die Dateiauswahl unterstützt auch den Abgleich per Suche statt über einen exakten Pfad, mit einer rekursiven Option und einer Regel zum Abgleich von Schemaunterschieden zwischen den gefundenen Dateien.

### Ziel

**Tabellenpräfix** – wird dem Namen jeder importierten Tabelle vorangestellt, sodass die Tabellen einer Datei gruppiert bleiben und nicht mit denen eines anderen Imports kollidieren.

### Überspringen, wenn unverändert

Standardmäßig aktiviert. Eine Workflow-Ausführung überspringt den Import vollständig – einschließlich des Downloads –, wenn sich die Quelldatei seit der letzten Ausführung nicht geändert hat und die Zieltabellen noch die geladenen Zeilen enthalten. Eine Tabelle, die geleert wurde, wird erneut importiert.

## Wenn die Datei nicht gelesen werden kann

Der Schritt schlägt fehl und nennt die Datei sowie die Tabelle, die nicht gelesen werden konnte, statt abzuschließen und eine leere Tabelle zu hinterlassen. Das geschieht, wenn die Datei keine Tabellen enthält, die PlaidCloud lesen kann, wenn eine Tabelle zwar benannt ist, ihre Spalten aber nicht beschrieben werden können, oder wenn das Lesen der Zeilen einer Tabelle fehlschlägt – die übliche Ursache ist eine Datei, die von einer neueren Access-Version geschrieben wurde, als der Reader versteht. Konvertieren Sie die Datei oder exportieren Sie sie erneut aus Access und führen Sie den Import noch einmal aus.

Eine Datei, deren Tabellen alle tatsächlich leer sind, wird erfolgreich importiert und meldet eine Warnung, dass keine Datensätze geladen wurden.
