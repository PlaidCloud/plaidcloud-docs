## Beschreibung

Importieren Sie JSON-Textdateien aus PlaidCloud Document.

Weitere Einzelheiten zu JSON-Dateien finden Sie auf der offiziellen JSON-Website: http://json.org/.

JSON-Dateien behalten die Spaltenreihenfolge *nicht* bei. Die Spaltenreihenfolge in der Quelldatei spiegelt nicht zwangsläufig die Spaltenreihenfolge in der importierten Datentabelle wider.

JSON-Importe werden über temporären Speicher gestreamt, statt das gesamte Dokument in den Arbeitsspeicher zu laden, sodass auch sehr große Dateien ohne Speichermangel importiert werden. Spalten, die in einem großen Dokument erst spät auftauchen, werden in die importierte Tabelle aufgenommen. Verschachtelte Objekte und Arrays werden als standardmäßiger kompakter JSON-Text importiert, sodass nachgelagerte Schritte sie mit beliebigen JSON-Werkzeugen parsen können.

## Spezifische Konfigurationselemente

### JSON-Datenausrichtung

Betrachten Sie den folgenden Datensatz:

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

JSON-Dateien können aus einem von drei Datenformaten importiert werden:

* Records: Die Daten werden in Python-Dictionary-Mengen gespeichert, wobei jede Zeile im Format \{Column -> Value, …} abgelegt ist. Zum Beispiel:


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index: Die Daten werden in verschachtelten Python-Dictionary-Mengen gespeichert, wobei jede Zeile im Format \{Index -> \{Column -> Value, …},…} abgelegt ist. Zum Beispiel:


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split: Die Daten werden in einer einzelnen Python-Dictionary-Menge gespeichert, die Werte in Listen. Zum Beispiel:


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

Zusätzlich zu den oben genannten Formaten wird zeilenweise getrenntes JSON (NDJSON) akzeptiert: ein eigenständiges JSON-Objekt pro Zeile, ohne umschließendes Array. Zum Beispiel:

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### Gesamtes Dokument

Um das JSON jeder Datei unverändert zu behalten, wählen Sie unter **Weitere JSON-Optionen** die Option **Jede Datei als eine Zeile mit ihrem gesamten JSON-Dokument importieren** (`whole_document`). Jede Datei wird dann als eine Zeile importiert, die ihr gesamtes JSON-Dokument enthält, wobei Zahlen so bleiben, wie sie geschrieben sind.

### Datums- und Zeitstempelwerte

Ein Feld wird als Datums- bzw. Zeitstempelwert importiert, wenn alle seine Werte dasselbe der folgenden Layouts haben:

| Layout | Datumswerte | Zeitstempel |
| --- | --- | --- |
| ISO 8601 | `2026-01-23` | `2026-01-23T23:14:00` |
| Monat zuerst | `01-23-2026` oder `01-23-26` | `01-23-2026 11:14:00 PM`, mit einer 12-Stunden-Zeit |
| Tag zuerst | `23-01-2026` oder `23-01-26` | `23-01-2026 23:14:00`, mit einer 24-Stunden-Zeit |
| Zweistelliges Jahr zuerst | `99-01-23` | `99-01-23 23:14:00`, mit einer 24-Stunden-Zeit |

Jeder Wert eines Feldes wird auf dieselbe Weise gelesen, unabhängig von der Reihenfolge der Zeilen. Ein Feld in einem anderen Layout, etwa `01/23/2026` oder `01-23-2026 23:14:00`, wird als Text importiert. Das gilt auch für ein Feld, dessen Werte verschiedene Layouts mischen; allerdings stoppen manche Mischungen aus zwei- und vierstelligen Jahren, etwa `01-23-2026` und `01-24-26`, den Import stattdessen mit einem Fehler, der das Feld nennt.

#### Wenn ein Wert zu mehr als einem Layout passt

`01-03-2026` könnte der 3. Januar oder der 1. März sein, und `23-01-26` könnte der 23. Januar 2026 oder, mit dem Jahr zuerst gelesen, der 26. Januar 2023 sein. Passen alle Werte eines Feldes zu mehr als einem der obigen Layouts, entscheidet das **Datumsformat** des Schritts anhand seiner Reihenfolge von Tag, Monat und Jahr:

* Eine Auswahl, die mit Monat Tag beginnt, liest den Monat zuerst: `01-03-2026` als 3. Januar.
* Eine Auswahl, die mit Tag Monat oder Abgekürzt beginnt, liest den Tag zuerst: `01-03-2026` als 1. März und `23-01-26` als 23. Januar 2026.
* Bei jedem anderen Datumsformat stoppt der Import mit einem Fehler, der das Feld und die Auswahlmöglichkeiten nennt, die es klären würden.

Diese Auswahlmöglichkeiten lesen einen Zeitstempel auch nach der jeweils anderen Uhr, wenn bei jedem Wert Tag und Monat 12 oder kleiner sind: Eine Auswahl mit Monat Tag liest `01-03-2026 23:14:00` als 3. Januar, und eine Auswahl mit Tag Monat oder Abgekürzt liest `01-03-2026 11:14:00 PM` als 1. März. Jedes andere Datumsformat liest sie wie in der Tabelle, Tag zuerst mit einer 24-Stunden-Zeit und Monat zuerst mit einer 12-Stunden-Zeit.

Keine Auswahl des Datumsformats liest ein zweistelliges Jahr zuerst, daher wird ein Feld wie `26-01-23` nur dann mit dem Jahr zuerst importiert, wenn sich seine Werte nicht anders lesen lassen, wie bei `99-01-23`. Mit vierstelligem Jahr geschrieben, etwa `2026-01-23`, wird ein solches Datum als ISO 8601 importiert.

Eine Datei, die außerdem einen Zeitstempel in einem verschachtelten Objekt oder Array enthält, ist die Ausnahme: Keine der obigen Prüfungen gilt für sie, und ein Wert, der zu mehr als einem Layout passt, kann von Zeile zu Zeile unterschiedlich gelesen werden.
