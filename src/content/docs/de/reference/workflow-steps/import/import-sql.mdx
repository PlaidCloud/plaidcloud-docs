## Beschreibung


Importiert das Ergebnis einer SQL-Abfrage gegen eine externe Datenbank in eine PlaidCloud-Projekttabelle. Die Abfrage läuft auf der entfernten Datenbank; nur die Ergebnismenge wird nach PlaidCloud geholt.

Unterscheidet sich von [Externe Datenbanktabellen importieren](/de/reference/workflow-steps/import/import-external-database-tables/) dadurch, dass Sie das SQL selbst schreiben – nützlich für komplexe Joins, Filter oder Aggregationen, die die Quelldatenbank ausführen soll, bevor die Daten in PlaidCloud landen.

### Spaltentyp-Erkennung
SQL-Importe können beim Laden versuchen, den Datentyp zu erraten, oder alle Spalten auf den Typ Text setzen. Die dynamische Festlegung der Datentypen kann schneller sein, wenn die Daten sauber sind, kann aber unter Umständen zu Problemen führen.

Wenn zum Beispiel die meisten Daten numerisch erscheinen, aber auch Text enthalten ist, wird möglicherweise versucht, die Spalte als numerisch festzulegen, was beim Laden zu Problemen durch nicht passende Datentypen führt. Probleme kann es auch bei einem numerischen Produktcode mit 16 Stellen geben: Führende Nullen würden abgeschnitten, sodass eine Zahl statt eines 16-stelligen Codes entsteht.

Alle Daten auf Text zu setzen, erfordert dagegen einen nachfolgenden Extract-Schritt, um Datentypen, die nicht Text sein sollen, in den passenden Typ umzuwandeln, etwa Datums- oder Zahlenwerte.

## Fehlerbehebung

| Symptom | Wahrscheinliche Ursache |
| --- | --- |
| Der Schritt dauerte deutlich länger als üblich – bis zu etwa eine halbe Stunde mehr –, ohne dass sich an Ihrer Abfrage, der Verbindung oder dem Datenvolumen etwas geändert hat | Der Hintergrund-Worker, der den Import ausführte, wurde mittendrin unterbrochen (ein plattformseitiger Neustart oder eine Verdrängung, nichts in Ihrem Workflow), und die Plattform hat den Import der Tabelle für Sie wiederholt. Die Wiederholung beginnt erst, wenn die Unterbrechung erkannt wird, was die zusätzliche Zeit erklärt. |
| Der Schritt wurde nach dieser Verzögerung trotzdem erfolgreich abgeschlossen | Die Wiederholung ersetzt den Inhalt der Tabelle vollständig, das Ergebnis entspricht also einer einzigen sauberen Ausführung – es gibt nichts weiter zu prüfen oder zu wiederholen. |
| Der Schritt schlägt mit „has already been attempted and cannot be safely re-run“ fehl | Bei einem Import-SQL-Schritt tritt diese Ablehnung nicht mehr auf – eine Unterbrechung mitten in der Ausführung wird stattdessen wiederholt. Sie sehen sie weiterhin, und zwar bewusst, beim [Wiederherstellen eines Projektarchivs](/de/guides/projects/archive-a-project/#ein-archiv-wiederherstellen) oder beim [Laden einer Dimension](/de/reference/workflow-steps/dimensions/dimension-load/), wo eine erneute Ausführung ein Duplikat erzeugen würde, statt etwas zu ersetzen. Öffnen Sie ein Support-Ticket, wenn Sie sie bei einem Import-SQL-Schritt selbst sehen.
