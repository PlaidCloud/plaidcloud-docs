## Beschreibung


Importiert das Ergebnis einer SQL-Abfrage auf einer externen Datenbank in eine PlaidCloud-Projekttabelle. Die Abfrage wird auf der entfernten Datenbank ausgeführt; nur die Ergebnismenge wird nach PlaidCloud übernommen.

Unterscheidet sich von [Externe Datenbanktabellen importieren](/de/reference/workflow-steps/import/import-external-database-tables/) dadurch, dass Sie das SQL selbst schreiben — nützlich für komplexe Joins, Filter oder Aggregationen, die die Quelldatenbank ausführen soll, bevor die Daten in PlaidCloud landen.

### Spaltentyp-Erkennung
Bei SQL-Importen können Sie versuchen, den Datentyp beim Laden zu erraten, oder alle Spalten auf den Typ Text setzen. Das dynamische Festlegen der Datentypen kann schneller sein, wenn die Daten sauber sind, kann aber unter manchen Umständen Probleme verursachen.

Wenn beispielsweise die meisten Daten numerisch aussehen, aber auch etwas Text enthalten ist, wird möglicherweise versucht, die Spalte als numerisch festzulegen, was zu Ladeproblemen durch nicht passende Datentypen führt. Probleme sind auch möglich, wenn es beispielsweise einen numerischen Produktcode mit 16 Stellen gibt. Dabei würden die führenden Nullen abgeschnitten, und es ergäbe sich eine Zahl statt eines 16-stelligen Codes.

Wenn Sie die Daten dagegen vollständig auf Text setzen, ist anschließend ein Extract-Schritt erforderlich, um alle Datentypen, die nicht Text sein sollen, in den passenden Typ umzuwandeln, etwa Datumswerte oder numerische Werte.

## Fehlerbehebung

| Symptom | Wahrscheinliche Ursache |
| --- | --- |
| Der Schritt dauerte spürbar länger als sonst — bis zu etwa eine halbe Stunde mehr —, ohne dass sich etwas an Ihrer Abfrage, Verbindung oder Datenmenge geändert hat | Der Hintergrund-Worker, der den Import ausführt, wurde mittendrin unterbrochen (ein plattformseitiger Neustart oder eine Verdrängung, nichts in Ihrem Workflow), und die Plattform hat den Import der Tabelle für Sie wiederholt. Die Wiederholung beginnt erst, sobald die Unterbrechung erkannt wird, was die zusätzliche Zeit erklärt. |
| Der Schritt wurde nach dieser Verzögerung trotzdem erfolgreich beendet | Die Wiederholung ersetzt den Inhalt der Tabelle vollständig, sodass das Ergebnis dasselbe ist wie bei einer einzelnen sauberen Ausführung — es gibt nichts weiter zu prüfen oder zu wiederholen. |
| Der Schritt schlägt mit „wurde bereits versucht und kann nicht sicher erneut ausgeführt werden“ fehl | Bei einem Schritt SQL importieren tritt diese Ablehnung nicht mehr auf — eine Unterbrechung mitten in der Ausführung wird stattdessen wiederholt. Sie sehen sie weiterhin, systembedingt, beim [Wiederherstellen eines Projektarchivs](/de/guides/projects/archive-a-project/#ein-archiv-wiederherstellen) oder [Laden einer Dimension](/de/reference/workflow-steps/dimensions/dimension-load/), wo eine erneute Ausführung ein Duplikat erzeugen würde, statt etwas zu ersetzen. Öffnen Sie ein Support-Ticket, wenn Sie sie bei einem Schritt SQL importieren selbst sehen.
