## Beschreibung

Importiert über Ihre [Xero-Verbindung](/de/guides/connections/xero/) eine Entität der Xero Accounting API, bezogen auf die Organisation der Verbindung, in eine Projekttabelle. Wählen Sie die Verbindung, den Entitätstyp und beliebige Filter aus; der Schritt lädt passende Datensätze und schreibt sie, ohne dass Sie eine Abfrage verfassen müssen.

Ein Schritttyp deckt elf Entitäten ab – von Referenzdaten (Kontenplan, Kontakte, Artikel, Steuersätze, Währungen) bis zu Transaktionsdatensätzen (Rechnungen, Gutschriften, Zahlungen, manuelle Journale, Banktransaktionen).

## Konfiguration

| Feld | Erforderlich | Hinweise |
|---|---|---|
| Xero-Verbindung | Ja | Die Xero-Verbindung, über die gelesen wird. |
| Zieltabelle | Ja | Die Projekttabelle, in die die Ergebnisse geschrieben werden. |
| Entitätstyp | Ja | Welche Entität geladen wird. Standard ist **Rechnungen**. |
| Status | Nein | Schränkt auf einen einzelnen Xero-`Status`-Wert ein, zum Beispiel `AUTHORISED` oder `PAID`. |
| Datum von | Nein | Untere Grenze im Format `YYYY-MM-DD` für das `Date` der Entität. |
| Datum bis | Nein | Obere Grenze im Format `YYYY-MM-DD` für das `Date` der Entität. |
| Aktualisiert nach | Nein | Wird als Stichtag für Änderungen gesendet, sodass nur Zeilen zurückgegeben werden, die danach geändert wurden. Bleibt das Feld leer, wird alles geladen. |

<Aside type="note">
**Aktualisiert nach** ist ein anfrageseitiger Filter ohne gespeichertes Wasserzeichen – PlaidCloud merkt sich nicht, wo die letzte Ausführung aufgehört hat. Geben Sie den Stichtag daher bei jeder Ausführung selbst an, um ein inkrementelles Verhalten zu erhalten.
</Aside>

## Entitätstypen

| Entitätstyp | Was er enthält |
|---|---|
| Kontenplan | Kontocode, Name, Typ, Klasse, Steuertyp, Status, Berichtscode. |
| Kontakte | Kunden und Lieferanten mit Status, Steuernummer und Standardwährung. |
| Rechnungen | Verkaufs- und Einkaufsrechnungen mit Kontakt, Datumsangaben, Status, Summen und offenem Betrag. |
| Gutschriften | Gutschriften zu Verkäufen oder Einkäufen mit Kontakt, Datum, Status und Summe. |
| Zahlungen | Zahlungen mit Datum, Betrag, Status und Bankkonto. |
| Manuelle Journale | Journalbeschreibung, Datum und Status. |
| Banktransaktionen | Ausgaben- und Eingangstransaktionen mit Datum, Status, Summe und Abstimmungskennzeichen. |
| Artikel | Lager- und Dienstleistungsartikel mit Tracking-Kennzeichen und Lagerbestand. |
| Tracking-Kategorien | Namen und Status von Tracking-Kategorien. |
| Steuersätze | Namen, Typen, Status und effektiver Satz von Steuersätzen. |
| Währungen | Währungscodes und Beschreibungen. |

<Aside type="note">
Nicht jede Entität unterstützt jeden Filter – Artikel und Währungen unterstützen keinen von beiden, und Kontenplan und Kontakte unterstützen einen Status, aber keinen Datumsbereich. Die Filterfelder bleiben für jede Entität aktiviert; Xero lehnt einen Filter ab, den eine Entität nicht unterstützt, sodass der Schritt den Fehler meldet, statt eine falsche Ergebnismenge zurückzugeben.
</Aside>

<Aside type="caution">
**Die Organisation stammt aus der Verbindung, nicht aus diesem Schritt.** Jede Xero-Anfrage nennt genau eine Organisation, und die Verbindung enthält diese Angabe – daher gibt es im Schritt kein Feld für die Organisation. Um dieselbe Entität aus einer zweiten Organisation zu laden, erstellen Sie eine zweite Xero-Verbindung, die auf diese zeigt.
</Aside>
