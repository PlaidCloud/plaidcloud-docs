## Beschreibung



Versieht Zeilen einer Quelltabelle anhand von Regeln, die Sie definieren, mit Attributen aus einer Dimension. Die Ausgabetabelle enthält die ursprünglichen Spalten plus neue Tag-Spalten, mit denen nachgelagerte Umlage- oder Analyseschritte Datensätze weiterleiten oder gruppieren können.

Verwenden Sie ihn, wenn Umlagen oder Analysen je nach Zeileneigenschaften variieren sollen — taggen Sie zum Beispiel jede Kostenzeile mit ihrem Umlagepool, ihrer Zielhierarchie oder ihrer Behandlungskategorie, damit der nächste Schritt je nach Tag-Wert unterschiedlich verteilen kann.

## Datentabelleneinstellungen

Die **Quelltabelle** und die **Tagging-Ergebnistabelle** können dynamisch oder statisch ausgewählt werden.

### Dynamische Tabellenauswahl
Die dynamische Tabellenoption erlaubt es, eine Tabelle mit Text und Variablen anzugeben. Das ist nützlich bei variablengesteuerten Workflows, in denen die Tabellen- oder Ansichtsverweise relativ zu den angegebenen Variablen sind.

Ein Beispiel, das die Variable `current_month` verwendet, um dynamisch auf eine Tabelle zu verweisen:

```text
legal_entity/inputs/{current_month}/ledger_values
```

### Statische Tabellenauswahl
Wenn eine bestimmte Tabelle als Quelle gewünscht ist, lassen Sie das Kontrollkästchen *Dynamic* deaktiviert und wählen Sie die Quelltabelle im Dropdown-Menü aus.


Der Tabellen-Explorer ist bei jeder Tabellenauswahl verfügbar. Klicken Sie auf die Schaltfläche „Tabellen-Explorer“ rechts neben der Tabellenauswahl, und ein Fenster des Tabellen-Explorers wird geöffnet.

<Aside>Die **Tagging-Ergebnistabelle** muss eine Tabelle sein und keine Ansicht.</Aside>

### Quelltabelle

Dies ist die Tabelle, die die Daten enthält, denen Sie die Attribute aus der _Zuweisungsdimension_ hinzufügen möchten. 

![Rule Based Tagging](/images/rule_based_tagging_source.png)


### Tagging-Ergebnistabelle

Die _Tagging-Ergebnistabelle_ enthält die Daten aus der _Quelldatentabelle_ mit den Attributen aus der _Zuweisungsdimensionshierarchie_. 

Ist **Datensätze nur einer Regel zuordnen** aktiviert, wird eine Zeile, auf die keine Regel passt, trotzdem geschrieben, mit leeren Tag-Spalten. Auch ein Tag, den eine passende Regel leer lässt, ist leer, und ein Quellwert, der leer war, bleibt leer. Leer bedeutet ein Null, nie eine leere Zeichenfolge, unabhängig davon, ob **Regeln mit SQL statt Pandas anwenden** aktiviert ist — ein späterer Schritt, der diese Zeilen herausgreift, sollte daher nach einem Null suchen, nicht nach `''`.

![Rule Based Tagging](/images/rule_based_tagging_target.png)

### Datensätze mehr als einer Regel zuordnen

Standardmäßig übernimmt ein Datensatz nur die erste Regel, auf die er passt. Deaktivieren Sie **Datensätze nur einer Regel zuordnen**, dann übernimmt er stattdessen jede Regel, auf die er passt: Der Datensatz erscheint einmal für jede davon, und ein Datensatz, der auf keine Regel passt, wird ausgelassen.

Regeln können auch mit einer Zuweisungsdimensions-Eigenschaft vom Typ **Sequenzierung** in Iterationen aufgeteilt werden, deren Wert die Iteration ist, in der jede Regel ausgeführt wird. Ein Schritt mit deaktiviertem **Datensätze nur einer Regel zuordnen** kann nicht beides: Fallen die ausgeführten Regeln in mehr als eine Iteration, stoppt der Schritt mit *Cannot apply rules when there are multiple iterations and records can match more than one rule*. Aktivieren Sie die Option oder führen Sie jede Iteration als separaten Schritt aus.

### Zuweisungsdimensionshierarchie

![Rule Based Tagging](/images/rule_based_tagging_assignment.png)

Die **Zuweisungsdimensionshierarchie** gibt dem Benutzer die Möglichkeit, die ***Quelltabelle*** per Klick auszuwählen und zu filtern, um der ***Tagging-Ergebnistabelle*** Attribute hinzuzufügen. 
Die **Zuweisungsdimensionshierarchie** entsteht durch die Kombination von Dimensionen, die auf die ***Quelltabelle*** verweisen.

#### Eine Zuweisungsdimensionshierarchie erstellen

Um die **Zuweisungsdimensionshierarchie** zu erstellen, müssen Sie zuerst die Dimensionen erstellen, die Sie als Filter für die ***Quelltabelle*** verwenden möchten. Die folgenden Links führen Sie durch das Erstellen dieser Dimensionen.


[Dimensionen erstellen](https://docs.plaidcloud.com/docs/workflow-steps/dimensions/dimension-create/) 

[Dimensionen laden](https://docs.plaidcloud.com/docs/workflow-steps/dimensions/dimension-load/) 

##### Die Haupthierarchie erstellen

Nachdem die Dimensionen für die ***Quelltabelle*** erstellt wurden, entscheiden Sie als Nächstes, welche der Dimensionen für die ***Quelltabelle*** als ***Haupthierarchie*** für die **Zuweisungsdimensionshierarchie** dient. 

Kopieren Sie diese Dimension, indem Sie in PlaidCloud zur Registerkarte „Dimensionen“ wechseln, auf die Dimension klicken und dann ***Aktionen*** und ***Dimension kopieren*** auswählen.
Beim Kopieren der Dimension erscheint ein Popup, in dem Sie einen Namen für die kopierte Dimension eingeben.

<Aside>Der Name der **Zuweisungsdimensionshierarchie** sollte vermitteln, welche Umlage durchgeführt wird, etwa „Hauptbuch zu Aktivität“.</Aside>


##### Dimensionen zur Zuweisungshierarchie hinzufügen


Öffnen Sie die neu erstellte **Zuweisungsdimension**, klicken Sie auf den Pfeil nach unten neben ***Eigenschaften*** und wählen Sie ***Neue Eigenschaft***.

![Assignment Hierarchy Property](/images/allocation_by_dimension_add_property.png)

Dadurch öffnet sich das Dialogfeld ***Eigenschaftskonfiguration***:
###### Eigenschaftskonfiguration

![Assignment Hierarchy Configure Property](/images/allocation_by_dimension_configure_property.png)

- **Eigenschaftsname** - Dies ist normalerweise der Name der Dimension, die der Zuweisungshierarchie hinzugefügt wird.
- **Eigenschaftsanzeige** - Dies sollte auf „Tag“ gesetzt werden.
- **Eigenschaftstyp** - Für _Rule Based Tagging_ sollte der Eigenschaftstyp auf _Quelle_ gesetzt werden. 
  - **Quelle** - Wird zusammen mit der ***Quelltabelle*** verwendet.

- **Editortyp** - Dieses Dropdown sollte auf ***Select Dimension*** gesetzt werden.

Wählen Sie, sobald die passenden Eigenschaften für die der Zuweisungshierarchie hinzugefügte Dimension ausgewählt sind, „Konfiguration bearbeiten“.
###### Dimensionskonfiguration

![Assignment Hierarchy Configure](/images/allocation_by_dimension_configure.png)

- **Dimension** - Wählen Sie die Dimension im Dropdown aus.
- **Hierarchie** - Hat die ausgewählte Dimension alternative Hierarchien, erscheinen diese hier ebenfalls und sind zusätzlich zur Haupthierarchie auswählbar.
- **Start Node** - Wenn die Dimension nicht ab dem obersten Knoten angezeigt werden soll, können Sie einen beliebigen Knoten in der Hierarchie als den Knoten wählen, ab dem die Dimension angezeigt wird.
- **Mehrfachauswahl zulassen** - Wenn aktiviert, kann der Benutzer mehrere Knoten in der Hierarchie auswählen.
- **Sonderfälle** - Werden in _Rule Based Tagging_ nicht verwendet.
