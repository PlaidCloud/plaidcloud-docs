## Beschreibung


Führt einen Outer Join auf zwei Datentabellen aus und kombiniert sie anhand der angegebenen Join-Schlüssel zu einer einzigen Datentabelle. Das Steuerelement **Verknüpfungstyp** wählt, welche nicht übereinstimmenden Zeilen behalten werden: ein **Left**, **Right** oder **Full Outer** Join. Standard ist ein Left Join (jede Zeile aus Tabelle A, wobei die Spalten von Tabelle B dort befüllt werden, wo die Schlüssel übereinstimmen).


Weitere Informationen zur Methodik des Outer Join finden Sie hier: [Wikipedia SQL Join](http://en.wikipedia.org/wiki/Join_%28SQL%29)

## Zur Laufzeit benannte Spalten

Wählen Sie **Auch zur Laufzeit benannte Spalten übernehmen**, um jede Quellspalte, die der Schritt nicht aufführt, unverändert weiterzugeben, so wie die Tabelle sie bei der Ausführung des Schritts hat. Verwenden Sie die Option, wenn ein vorheriger Schritt Spalten erzeugt, deren Namen von den Daten abhängen (zum Beispiel ein Pivot), sodass Sie sie beim Erstellen des Schritts nicht auflisten können. Lassen Sie sie deaktiviert, um nur die von Ihnen aufgeführten Spalten zu schreiben.

### Verknüpfungstyp

Wählen Sie, wie nicht übereinstimmende Zeilen behalten werden:

- **Left Join**: Behält jede Zeile aus Tabelle A; die Spalten von Tabelle B werden nur dort befüllt, wo die Join-Schlüssel übereinstimmen. Dies ist der Standard.
- **Right Join**: Behält jede Zeile aus Tabelle B; die Spalten von Tabelle A werden nur dort befüllt, wo die Join-Schlüssel übereinstimmen.
- **Full Outer Join**: Behält jede Zeile beider Tabellen, unabhängig davon, ob es auf der anderen Seite eine Übereinstimmung gibt.

## Beispiele


### Automobilhersteller mit Modellen verknüpfen


Betrachten Sie in diesem Beispiel die folgenden Quelldatentabellen. Die erste ist eine Liste von Automobilherstellern.




| Mfg_ID | Manufacturer |
|--------|--------------|
|    1   | Aston Martin |
|    2   | Porsche      |
|    3   | Lamborghini  |
|    4   | Ferrari      |
|    5   | Koenigsegg   |


Die nächste ist eine Liste von Automodellen mit einer Hersteller-ID. Beachten Sie, dass es mehrere Modelle ohne Hersteller gibt.




| ModelName          | Mfg_ID |
|--------------------|--------|
| Aventador          |    3   |
| Countach           |    3   |
| DBS                |    1   |
| Enzo               |    4   |
| One-77             |    1   |
| Optimus Prime      |        |
| Batmobile          |        |
| Agera              |    5   |
| Lightning McQueen  |        |

Um eine Liste der Modelle nach Hersteller zu erhalten, bietet sich ein Join über *Mfg_ID* an. Durch den Einsatz von Outer-Join-Konzepten kann die Ausgabe auch die Einträge zeigen, die keine Übereinstimmung haben.



Legen Sie zunächst die Parameter für **Table 1 Data Selection** fest. Die Quelldatentabelle ist ausgewählt, und alle Spalten sind aufgelistet.



Legen Sie als Nächstes die Parameter für **Table 2 Data Selection.** fest. Auch hier ist die Quelldatentabelle ausgewählt, und alle Spalten sind aufgelistet.



Zum Schluss werden die Join-Bedingungen in der Registerkarte **Table Output** festgelegt. Mit der Schaltfläche **Erraten** erkennt Analyze die Spalte *Mfg_ID* korrekt als **Join Key**. Da dieses Beispiel nicht übereinstimmende Zeilen aus beiden Tabellen behält, setzen Sie den **Verknüpfungstyp** auf **Full Outer Join**. Die 


**Zielausgabespalten** werden anschließend mit der Schaltfläche **Weitergeben** automatisch festgelegt. Damit sind effektiv alle Spalten aller Tabellen enthalten, wobei Join-Spalten selbstverständlich nur einmal vorkommen. Beachten Sie, dass die Spalten alphabetisch sortiert sind, zuerst nach *Manufacturer* und dann nach *ModelName*.



Wie erwartet enthält die endgültige Ausgabe alle Zeilen beider Tabellen, unabhängig davon, ob sie in beiden Tabellen eine Übereinstimmung hatten. So erscheint *Porsche* diesmal tatsächlich, obwohl es keine Modelle hat. Außerdem sind *Batmobile*, *Lightning McQueen* und *Optimus Prime* in den Ergebnissen enthalten, obwohl keiner von ihnen einen Hersteller hat. Wer könnte zu ihnen auch schon „Nein“ sagen?
