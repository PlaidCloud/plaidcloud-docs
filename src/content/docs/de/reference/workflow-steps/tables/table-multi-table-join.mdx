## Beschreibung

Der Schritt **Mehrtabellen-Join** verknüpft viele Tabellen (bis zu 32) in einem einzigen Vorgang mit einem visuellen **Join-Graph-Designer** und ersetzt damit das Muster, mehrere Zwei-Tabellen-Join-Schritte aneinanderzureihen. Sie fügen Tabellen hinzu, zeichnen Joins zwischen ihren Spalten, wählen pro Join einen Verknüpfungstyp und Bedingungen und ordnen die Ausgabespalten zu. Der Editor hat drei Registerkarten: **Tables & Joins**, **Ausgabespalten** und **Post-Join Filter**.

Eine vollständige Anleitung finden Sie im [Leitfaden zum Mehrtabellen-Join-Schritt](/de/guides/workflows/multi-table-join-step/).

## Designer

* **Tabelle hinzufügen** — platzieren Sie eine Quelltabelle als Karte mit Spalten auf der Arbeitsfläche. Jede Tabelle hat einen **Alias** (verwendet als `alias.column`), der mit einem Buchstaben oder Unterstrich beginnen muss und kein SQL-Schlüsselwort sein darf.
* **Zieltabelle** — die Tabelle, in die das verknüpfte Ergebnis geschrieben wird; wird angelegt, wenn sie nicht existiert.
* **Dynamisch** — geben Sie eine Quelle oder das Ziel als Verweis an, statt sie auszuwählen: ein Tabellenname, ein Projektpfad (`/03 Results/FACT_GL`) oder beides mit `{variable}`-Token, die zur Laufzeit aufgelöst werden. Die Spalten einer dynamischen Quelle können zur Entwurfszeit nicht gelesen werden, daher werden sie im Seitenbereich von Hand eingegeben.
* **Joins zeichnen** — ziehen Sie von einem Spaltenpunkt einer Tabelle zu einer Spalte einer anderen, um einen Join zu erstellen; eine optionale **Bezeichnung** benennt die Kante.
* **Eingangsfilter** — ein Filter pro Tabelle, der *vor* dem Join angewendet wird.
* **Erneut vom Server abrufen** — aktualisiert die Spalten einer Tabellenkarte aus dem aktuellen Katalog.
* **Layout bereinigen** / **Einpassen** / **1:1** — ordnet den Graphen automatisch an, zoomt, bis er passt, oder kehrt zu 100 % zurück; die Zoom-Schaltflächen, das Mausrad und das Verschieben sind ebenfalls verfügbar, und eine Minimap zeigt den gesamten Graphen.
* **Rückgängig** / **Wiederholen** / **Verlauf** — Bearbeitungen durchgehen, prüfen und wiederherstellen.
* **Spalten filtern…** — schränkt die auf einer Tabellenkarte angezeigten Spalten ein.
* **Als PDF exportieren** / **Als PNG exportieren** — lädt das Join-Diagramm über die Export-Schaltfläche und ihr Menü herunter.

## Verknüpfungstypen

| Typ | Behält |
|------|-------|
| `INNER` | Zeilen, die über die verknüpften Tabellen hinweg übereinstimmen. |
| `LEFT` | Alle Zeilen der linken Tabelle, übereinstimmende Zeilen der rechten. |
| `FULL` | Alle Zeilen beider Tabellen. |
| `CROSS` | Jede Kombination von Zeilen (keine Bedingungen erlaubt). |

## Bedingungen

Jeder Join außer Cross hat eine oder mehrere Bedingungen, die mit **AND** / **OR** kombiniert werden und die Operatoren `=`, `<>`, `<`, `<=`, `>`, `>=`, `BETWEEN`, `IS NULL`, `IS NOT NULL`, `IN`, `NOT IN`, `LIKE`, `NOT LIKE` verwenden.

Eine Bedingung kann eine Spalte benennen, deren Name Leerzeichen oder Satzzeichen enthält, etwa `Build Plant` oder `Cust (Id)`; die Spalte muss in dieser Eingabe existieren. Namen mit einem doppelten Anführungszeichen, Backtick, Backslash oder Steuerzeichen werden abgelehnt.

Bei `BETWEEN` wird eine Grenze, die als Alias einer Eingabe, ein Punkt und eine Spalte geschrieben ist (`cust.Max Id`), als Spalte dieser Eingabe gelesen. Jede andere Grenze ist Literaltext, auch ein bloßer Aliasname ohne Punkt. Eine Textgrenze, die mit einem Alias und einem Punkt beginnt, etwa `cust.2024`, wenn eine Eingabe den Alias `cust` hat, wird daher als Spalte gelesen und als fehlend gemeldet.

## Ausgabe

Ordnen Sie auf der Registerkarte **Spalten** die Ergebnisspalten zu; benennen Sie um, legen Sie den Datentyp fest und aggregieren Sie nach Bedarf. Gleichnamigen Spalten wird automatisch ihr Quellalias vorangestellt, um Kollisionen zu vermeiden.

Jede Zeile bezieht ihren Wert aus genau einem von drei Feldern — mehr als eines oder keines zu setzen, wird abgelehnt:

| Art | Felder |
|------|--------|
| Quellspalte | **Quellalias** (der zugehörige Arbeitsflächen-Alias) plus **Quelle** (`alias.column`). Beides erforderlich. |
| Konstante | **Konstante** — derselbe feste Wert in jeder Zeile. |
| Ausdruck | **Ausdruck** — ein SQLAlchemy-Ausdruck, der auf jeden Arbeitsflächen-Alias als `alias.column` verweisen kann. |

* **Aus Arbeitsfläche auswählen…** — wählen Sie Spalten aus jeder Quelle auf der Arbeitsfläche aus.
* **Alle Quellspalten hinzufügen** — hängt jede Spalte jeder Quelle an.
* **Ausdrucksspalte hinzufügen** — hängt eine Ausdruckszeile an und öffnet den Ausdruckseditor.

<Aside type="caution" title="Jede Ausgabespalte benötigt einen Datentyp">
Eine Ausgabespalte ohne **Typ** hält diesen Schritt an, wobei die Spalte benannt wird, damit Sie den Typ festlegen können. Andere Schritte greifen auf den Typ der Quellspalte zurück, die diese Ausgabe liest — dieser nicht, und zwar bewusst: Er führt seine Spalten nach Quellalias, sodass bei einem Join über mehrere Tabellen eine Vermutung ebenso wahrscheinlich falsch wie richtig wäre, und der Hinweis, welche Spalte zu korrigieren ist, nützt mehr als eine stille Umwandlung.
</Aside>

Die Registerkarte **Post-Join Filter** wendet einen optionalen Filter auf das verknüpfte Ergebnis an (ein Äquivalent zu SQL-`HAVING`), bevor es geschrieben wird, und wird im selben Ausdruckseditor bearbeitet. Er verweist auf Ausgabespalten als `result.column_name`; Quellaliasse liegen dort außerhalb des Gültigkeitsbereichs.

## Zur Laufzeit benannte Spalten

Wählen Sie **Auch zur Laufzeit benannte Spalten übernehmen**, um jede Quellspalte, die der Schritt nicht auflistet, unverändert so durchzureichen, wie die Tabelle sie bei der Ausführung des Schritts hat. Verwenden Sie dies, wenn ein früherer Schritt Spalten erzeugt, deren Namen von den Daten abhängen, etwa ein Pivot, sodass Sie sie beim Aufbau des Schritts nicht auflisten können. Lassen Sie es ausgeschaltet, um nur die Spalten zu schreiben, die Sie auflisten.

## Verhalten

* Der Join-Graph ist ein Baum: Jede Tabelle ist über genau eine Kante mit dem Ergebnis verbunden (keine Zyklen), und eine Tabelle kann nicht mit sich selbst verknüpft werden.
* Die Konfiguration wird sowohl beim Speichern des Schritts als auch bei seiner Ausführung validiert; Fehler markieren die betroffene Tabelle oder den betroffenen Join mit einem ⚠-Zeichen, ein fehlgeschlagenes Speichern wechselt zur Registerkarte mit dem ersten Problem, und **Zum Problem springen** navigiert auf Abruf dorthin. Ausdrücke der Ausgabespalten und der Post-Join Filter werden beim Speichern geprüft; ein Join, der zur Laufzeit benannte Spalten mitführt, überspringt die Ausdrucksprüfung beim Speichern und wird bei der Ausführung des Schritts geprüft.

<Aside type="caution">`CROSS`-Joins erzeugen das kartesische Produkt ihrer Eingaben und können bei großen Tabellen sehr aufwendig sein.</Aside>
