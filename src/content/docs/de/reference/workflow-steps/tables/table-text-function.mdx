## Beschreibung

Der Schritt **Tabelle: Textfunktion** wendet eine Textfunktion auf die Spalten jeder Zeile an, die die Funktion liest, und schreibt das Ergebnis in eine neue Spalte einer Kopie der Quelltabelle. Ein NULL in einer beliebigen Spalte, die die Funktion liest, ergibt NULL.

## Quelle & Optionen

- **Quelltabelle** und **Ausgabetabelle** — die Tabelle, die gelesen wird, und die Tabelle, in die geschrieben wird.
- **Funktion** — die anzuwendende Funktion. Das Formular bietet die Funktionen in den beiden folgenden Tabellen an und zeigt für jedes Argument, das die gewählte Funktion liest, ein Spaltenfeld mit der Bezeichnung seiner Rolle.
- **Argumentspalten** — die Spalten, die die Funktion liest, in der Reihenfolge der Tabelle. Jede ist erforderlich.
- **Ausgabespalte** — der Name der Spalte, die der Kopie der Quelle hinzugefügt wird.

| Funktion | Argumente | Ergebnis |
| --- | --- | --- |
| `levenshtein` | Erste Spalte, Zweite Spalte | Editierdistanz mit Beachtung der Groß-/Kleinschreibung, als ganze Zahl |
| `soundex` | Text | Text |
| `json_format` | JSON | Formatierter JSON-Text |
| `json_field` | JSON, Pfad | Text |
| `json_set_text`, `json_set_number`, `json_set_boolean` | JSON, Pfad, Wert | JSON-Text mit gesetztem Wert |
| `regex_match` | Text, Muster, Groß-/Kleinschreibung beachten | Wahr oder falsch |
| `regex_search` | Text, Muster, Vorkommen, Groß-/Kleinschreibung beachten | Position, als ganze Zahl |
| `regex_extract` | Text, Muster, Vorkommen, Groß-/Kleinschreibung beachten | Text |
| `regex_replace` | Text, Muster, Ersetzung, Groß-/Kleinschreibung beachten | Text |
| `to_text_number` | Zahl, Muster | Text: die Zahl, geschrieben mit einem Muster im DecimalFormat-Stil |
| `to_text_datetime` | Datum/Uhrzeit, Muster | Text: das Datum, geschrieben mit einem Datum-Uhrzeit-Muster |
| `parse_date` | Text, Muster | Der als Datum gelesene Text |
| `parse_datetime` | Text, Muster | Der als Datum mit Uhrzeit gelesene Text |

Eine konvertierte Savant-Analyse kann jede dieser Funktionen enthalten, und sie laufen auf dieselbe Weise. Eine Funktion, die das Formular nicht anbietet, zeigt ihre gespeicherten Spalten und bleibt genau so erhalten, wie sie gespeichert wurde.

### Weitere Funktionen

Die Liste **Funktion** bietet außerdem diese Funktionen an. Auch konvertierte KNIME-Workflows verwenden sie.

| Funktion | Argumente | Ergebnis |
| --- | --- | --- |
| `damerau_levenshtein`, `hamming`, `lcs` | Erste Spalte, Zweite Spalte | Die jeweilige Editierdistanz, als ganze Zahl |
| `jaro`, `jaro_winkler` | Erste Spalte, Zweite Spalte | 1 minus die Ähnlichkeit, 0 bei gleichen Texten |
| `ngram_distance` | Erste Spalte, Zweite Spalte | 1 minus der Dice-Koeffizient der Zeichen-Bigramme |
| `jaccard_tokens`, `dice_tokens`, `cosine_tokens` | Erste Spalte, Zweite Spalte | 1 minus die Mengenähnlichkeit der Wörter der beiden Texte, 1 wenn einer von beiden keine hat |
| `java_compare` | Erste Spalte, Zweite Spalte | Die Differenz der ersten abweichenden Zeichen, wie sie `compareTo` von Java liefert, als ganze Zahl |
| `java_regex` | Text, Muster, Ersetzung *(nur im Ersetzungsmodus)* | Ein aus einer Spalte gelesener regulärer Java-Ausdruck: wahr oder falsch in den Modi `matches` und `find`, Text in `extract` und `replace` |
| `knime_count` | Text, Suchtext | Wie oft der Suchtext vorkommt, als ganze Zahl |
| `knime_binomial`, `long_pow` | Zwei Zahlen | Der Binomialkoeffizient oder die ganzzahlige Potenz, in 64-Bit-Arithmetik mit Überlauf |
| `encode`, `decode` | Text | Der Text als Base64-Bytes in einem Zeichensatz und zurück |
| `url_encode` | Text | Der Text als Formularwert prozentkodiert, ein Leerzeichen wird als `+` geschrieben |
| `list_sort_numeric` | Text | Eine als getrennter Text gespeicherte Liste, nach numerischem Wert sortiert |
| `geojson_to_wkt` | JSON, Pfad | Die GeoJSON-Geometrie an einem Pfad wie `$.a[0]`, oder `$` für den Text selbst, als WKT |
| `json_patch_apply` | JSON | Das Dokument mit angewendetem JSON Patch oder Merge Patch |
| `json_diff` | Erstes JSON, Zweites JSON | Der JSON Patch, der das erste Dokument in das zweite überführt |
| `json_schema_check` | JSON | Die Fehler, die das Dokument gegenüber einem JSON-Schema hat, als JSON; NULL, wenn es keine hat |
| `json_normalize` | JSON | Das Dokument als normalisierter JSON-Text |
| `json_to_xml`, `xml_to_json` | Dokument | Das in XML oder in JSON konvertierte Dokument |
| `xml_well_formed` | XML | Der Text, wenn er wohlgeformtes XML ist, sonst NULL |
| `xslt` | XML, Stylesheet | Das mit dem XSLT-Stylesheet transformierte Dokument |
| `message_text`, `message_tool_calls` | JSON | Der Text einer KI-Nachricht oder ihre Tool-Aufrufe als JSON |

Optionen einer Funktion legen Sie in `function_options` fest:

- `java_regex` — `mode`: `matches` (Standard, der gesamte Text), `find` (irgendwo), `extract` (Gruppe `group` des ersten Treffers, Standard 0) oder `replace` (jeder Treffer); `flags` `i` ignoriert die Groß-/Kleinschreibung.
- `knime_count` — `modifiers`: `i` ignoriert die Groß-/Kleinschreibung, `w` zählt ganze Wörter zwischen Leerraum.
- `encode` und `decode` — `charset`, ein Java-Zeichensatzname; Standard ist UTF-8.
- `json_patch_apply` — `patch`, das JSON-Patch-Array oder das Merge-Patch-Objekt; `merge` ist wahr für einen Merge Patch; `keep` behält das Dokument bei, wenn ein Patch-Test fehlschlägt.
- `json_schema_check` — `schema`; `fail` stoppt den Schritt beim ersten Fehler, statt ihn zurückzugeben.
- `json_normalize` — `comments` erlaubt Kommentare mit `/* */` und `//`; `fail` (Standard wahr) stoppt den Schritt bei Text, der kein JSON ist, und falsch ergibt NULL.
- `json_to_xml` — `root`, `item`, `typed`, `parent_keys`, `namespace`, `text_key` und `text_key_enabled`. `xml_to_json` — `text_key`, `comments` und `pis`.
- `list_sort_numeric` — `separator`; `empty`, der Text, der für eine Liste ohne Elemente geschrieben wird; und `missing`, der Text eines fehlenden Elements, das zuletzt sortiert wird.

Standardmäßig liest der Schritt jede Spalte der Quelle und schreibt jede Quellspalte gefolgt von der Ausgabespalte. Mit `source_columns` lesen Sie nur einige Spalten, und mit `target_columns` (jeweils `{source, target, dtype}`) wählen Sie die geschriebenen Spalten und ihre Reihenfolge. Eine Zielspalte, die wie die Ausgabespalte heißt, nimmt deren Platz ein, mit dem angegebenen Datentyp.
