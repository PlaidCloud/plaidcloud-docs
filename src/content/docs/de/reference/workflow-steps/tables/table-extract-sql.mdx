## Beschreibung

Befüllt eine Zieltabelle aus einem `SELECT`, das Sie selbst in SQL schreiben. Während der [Table-Extract-Schritt](/de/reference/workflow-steps/tables/table-extract/) die Abfrage aus zugeordneten Spalten und Ausdrücken aufbaut, übergibt dieser Schritt die Abfrage direkt an das Warehouse — für die Fälle, in denen sich das SQL direkt leichter ausdrücken lässt, als es im Mapper zusammenzubauen.

Setzen Sie ihn ein, wenn Sie ein Konstrukt benötigen, das der Mapper nicht abdeckt: ein rekursives CTE, eine Fensterfunktion über eine Partition, die der Mapper nicht beschreiben kann, oder eine Abfrage über mehrere Tabellen, die ein Join-Schritt unübersichtlicher machen würde.

## Spezifische Konfigurationselemente

### SQL-Select-Abfrage

Der Abfragetext. Formatieren Sie ihn als lesbares, mehrzeiliges, eingerücktes SQL — eine Spalte oder Klausel pro Zeile — statt als eine einzige lange Zeile; der Schritt behält bei, was Sie schreiben, und die nächste Person, die ihn öffnet, muss es lesen.

Die Abfrage läuft auf dem Lakehouse des Projekts, daher sind die verfügbaren Funktionen je nach Workspace die Menge von [Lakehouse v1](/de/reference/expressions/lakehouse-v1/) oder [v2](/de/reference/expressions/lakehouse-v2/).

<SnippetCommonStepPreview />

Anders als die übrigen SQL-Schritte setzt dieser Schritt keine Variablen ein, daher tut es auch seine Vorschau nicht.
