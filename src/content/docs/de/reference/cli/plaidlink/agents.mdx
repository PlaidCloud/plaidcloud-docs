## Beschreibung


Manchmal ist es notwendig und wünschenswert, von einem Remote-System aus, das keinen externen Zugriff zulässt, auf Daten zuzugreifen oder Prozesse auszuführen. Das ist in Unternehmensumgebungen hinter Firewalls üblich. PlaidCloud ermöglicht dies mit PlaidLink, das den Zugriff auf Remote-Systeme hinter einer Firewall oder dort erlaubt, wo ein direkter Zugriff von PlaidCloud nicht gewünscht ist.



PlaidLink verwendet ein agentenbasiertes System. Das heißt, ein Agent, der Remote-Benutzer, wird auf einem System innerhalb der Firewall oder eines anderen eingeschränkten Bereichs installiert. Der Agent kann sich dann über einen ausgehend initiierten Vorgang per sicherer HTTPS-WebSocket-Verbindung mit PlaidCloud verbinden. Diese Verbindung ist so sicher wie jede andere verschlüsselte Webverbindung und erfordert in der Regel nicht, dass Sie nicht standardmäßige Ports öffnen. Bevor der Agent Zugriff erhält, muss er sich identifizieren, indem er seine Agent-Kennung sendet. Wenn die Authentifizierung des Agents anschließend erfolgreich ist, erhält er Zugriff auf die genehmigten Operationen.



PlaidLink kann auf Windows-, Unix- und Linux-Systemen installiert werden und unter Benutzern mit geringen Berechtigungen laufen. Unter Windows kann PlaidLink als Windows-Dienst mit vollständiger Steuerung über das Dienstefenster betrieben werden. Unter Linux oder Unix kann es als Daemon-Prozess laufen.

PlaidLink kann außerdem als eigenständiger Docker-Container oder als Kubernetes-Pod ausgeführt werden.



## Agents verwalten


**So verwalten Sie Agents:**


1. Öffnen Sie Analyze.
2. Wählen Sie „Tools“.
3. Klicken Sie auf „PlaidLink-Agents“.

Damit gelangen Sie zur **PlaidLink-Agents-Tabelle**, in der Sie die Liste der verfügbaren Agents anzeigen und ändern sowie deren Anmeldedaten abrufen können.



## Agent erstellen


**So erstellen Sie einen Agent:**


1. Öffnen Sie Analyze.
2. Wählen Sie „Tools“.
3. Klicken Sie auf „PlaidLink-Agents“.
4. Klicken Sie auf „PlaidLink-Agent hinzufügen“.
5. Füllen Sie die erforderlichen Felder aus.
6. Klicken Sie auf „Erstellen“.
7. Weisen Sie den Agent den Sicherheitsgruppen zu, die er für den Zugriff auf die benötigten Ressourcen braucht.
8. Weisen Sie den Agent den Dokumentenkonten zu, die er für den Zugriff auf die benötigten Dokumente braucht.


<Aside type="danger">Für die Schritte 7 und 8 oben muss der PlaidLink-Agent den Sicherheitsgruppen und Dokumentenkonten zugewiesen werden, die für die Aufgaben erforderlich sind, die der Agent ausführen soll. Andernfalls wird ihm der Zugriff verweigert.</Aside>

<Aside>Alle Informationen, die im Formular für den neuen Agent nicht enthalten sind, werden automatisch generiert.</Aside>



## Agent-Anmeldedaten abrufen


Um PlaidLink-Agents auf dem Remote-System zu konfigurieren, müssen Sie zunächst die Identifikationsdaten des Agents abrufen, um die Sicherheit zu gewährleisten. Diese Daten umfassen einen öffentlichen und einen privaten Schlüssel.



**So rufen Sie diese Schlüssel ab:**


1. Öffnen Sie Analyze.
2. Wählen Sie „Tools“.
3. Klicken Sie auf „PlaidLink-Agents“.
4. Klicken Sie auf das Symbol „Bearbeiten“.

Damit öffnen Sie ein Formular, in dem Sie die Werte des öffentlichen und des privaten Schlüssels anzeigen können.

Der private Schlüssel und die Schaltfläche **RPC-Konfiguration anzeigen** erscheinen nur für Mitglieder, die Agents bearbeiten dürfen; andere Mitglieder sehen nur den öffentlichen Schlüssel.


## Agent-Anmeldedaten neu generieren


Es empfiehlt sich, den öffentlichen und den privaten Schlüssel regelmäßig neu zu generieren und die Konfiguration der Remote-Systeme zu aktualisieren, um die Sicherheit zu gewährleisten.



**So generieren Sie die Anmeldedaten neu:**


1. Öffnen Sie Analyze.
2. Wählen Sie „Tools“.
3. Klicken Sie auf „PlaidLink-Agents“.
4. Klicken Sie auf das Symbol „Neu generieren“.

Nach der Neugenerierung der Anmeldedaten können Sie diese auf dieselbe Weise abrufen wie die Anmeldedaten eines neuen Agents (siehe oben).



## Agent aktivieren und deaktivieren


**So deaktivieren Sie einen Agent:**


1. Öffnen Sie Analyze.
2. Wählen Sie „Tools“.
3. Klicken Sie auf „PlaidLink-Agents“.
4. Deaktivieren Sie das Kontrollkästchen „Aktiv“.

<Aside>Wenn ein Agent nicht als aktiv markiert ist, können sich Remote-Systeme nicht mit den Anmeldedaten dieses Agents verbinden.</Aside>



## Agent-Umgebungen


Eine Verbindung kann pro Umgebung eine andere Konfiguration enthalten. Beim Wechsel der Umgebung eines Projekts werden daher alle von ihm verwendeten Verbindungen gleichzeitig umgestellt. Agents können demselben Wechsel folgen.


Jeder Agent hat zwei Einstellungen:


- **Agent-Gruppe** — ein Name, den Agents gemeinsam verwenden, die sich gegenseitig vertreten. Agents in einer Gruppe sind Alternativen für dieselbe Aufgabe, jeweils einer pro Umgebung.
- **Von diesem Agenten bediente Umgebung** — die Verbindungsumgebung, die dieser Agent bedient. Sie muss mit der Umgebung in der PlaidLink-Konfiguration des Agents übereinstimmen.


Ein Schritt nennt weiterhin einen bestimmten Agent. Bei der Ausführung des Workflows sucht PlaidCloud die Gruppe, zu der dieser Agent gehört, und wählt das Mitglied aus, das die aktuelle Umgebung des Projekts bedient. Ein Projekt, das von Ihrer Standardumgebung auf QA umgestellt wird, führt seine Remote-Schritte daher auf dem QA-Rechner aus, ohne dass ein Schritt bearbeitet werden muss.


Bei einer Gruppe namens `Finance`, in der ein Agent die Umgebung „Default“ und ein weiterer „QA“ bedient, läuft ein Schritt, der einen der beiden nennt, auf demjenigen, der zum Projekt passt. Ein wieder auf „Default“ zurückgestelltes Projekt läuft auf dem Default-Agent, auch wenn der Schritt den QA-Agent nennt.


**So weisen Sie einen Agent einer Umgebung zu:**


1. Öffnen Sie Analyze.
2. Wählen Sie „Tools“.
3. Klicken Sie auf „PlaidLink-Agents“.
4. Öffnen Sie den Agent.
5. Legen Sie „Agent-Gruppe“ auf einen Namen fest, den die Alternativen des Agents gemeinsam verwenden, und legen Sie „Von diesem Agenten bediente Umgebung“ fest.
6. Legen Sie auf dem Rechner, auf dem dieser Agent läuft, den passenden Umgebungsnamen in der PlaidLink-Konfigurationsdatei fest — siehe [Abgleich mit dem Agent-Rechner](#abgleich-mit-dem-agent-rechner) weiter unten.

<Aside>Ein Agent ohne festgelegte Gruppe bedient alle Umgebungen; das gilt für jeden Agent, bis Sie eine Gruppe festlegen. Für einen Workspace, der einen einzelnen Agent betreibt, ändert sich nichts.</Aside>

<Aside type="caution">Das Festlegen einer Gruppe macht die Zuordnung für jeden Agent darin exakt, auch bei einer Gruppe mit nur einem Agent. Ein Projekt, das in einer Umgebung läuft, die kein Agent der Gruppe bedient, schlägt mit einer Meldung fehl, die die Gruppe und die Umgebung nennt, statt auf den Agent auszuweichen, den der Schritt genannt hat. Das ist beabsichtigt — die Alternative wäre, dass Produktivarbeit unbemerkt auf einem Testrechner läuft. Fügen Sie für jede Umgebung, in der Ihre Projekte laufen, einen Agent hinzu, und lassen Sie die Gruppe bei einem Agent leer, der weiterhin alles bedienen soll.</Aside>


Einen Agent aus einer Gruppe zu entfernen, verringert den Umfang, den die Gruppe abdeckt, und ist daher ebenso folgenreich wie das Hinzufügen. Wenn Sie die Gruppe bei dem Agent leeren, der Ihre Standardumgebung bedient hat, haben Projekte, die dort laufen, kein Ziel mehr und schlagen bei ihrer nächsten Ausführung fehl. Verschieben Sie die Umgebung auf ein anderes Mitglied der Gruppe, bevor Sie eines entfernen. Jedes Speichern, das ändert, was eine Gruppe abdeckt, meldet Ihnen die neue Abdeckung zurück.


Umgebungen werden mit Verbindungen gemeinsam genutzt, daher sind die hier angebotenen Umgebungsnamen dieselben, unter denen Sie eine Verbindung konfigurieren. Siehe [Verbindung erstellen und verwalten](/de/guides/connections/create-connection/#umgebungen).


### Abgleich mit dem Agent-Rechner


Die hier festgelegte Umgebung muss mit der Umgebung übereinstimmen, für die der PlaidLink-Dienst auf diesem Rechner konfiguriert ist. PlaidLink abonniert genau eine Warteschlange für die Umgebung, die in seiner Konfigurationsdatei genannt wird. Ein Agent, dessen Datensatz QA angibt, dessen Rechner aber noch für die Standardumgebung konfiguriert ist, lauscht daher auf einer anderen Warteschlange als der, an die die Arbeit gesendet wird. Der Schritt wartet und schlägt dann mit der Meldung fehl, dass der Agent den Auftrag nicht aufnimmt.


Legen Sie sie im Block `environments` der PlaidLink-Konfigurationsdatei im Eintrag für diesen Agent fest:


```yaml
environments:
  - name: QA
    agent_id: <agent identifier>
```


Der `name` ist der Umgebungsname, wie er in PlaidCloud erscheint. Wenn er fehlt, bedient der Agent die Standardumgebung. Starten Sie den PlaidLink-Dienst nach der Änderung neu.


<Aside type="note">Ein einzelner PlaidLink-Dienst kann mehrere Einträge in diesem Block enthalten, sodass ein Rechner mehr als einen Agent oder denselben Agent in mehr als einer Umgebung bedienen kann. Siehe [Mehrere Agents betreiben](#mehrere-agents-betreiben).</Aside>


## Mehrere Agents betreiben


PlaidLink ist so konzipiert, dass sich mehrere Agents mit einer einzigen Dienstinstallation betreiben lassen. Eine solche schlanke Installation ermöglicht es, dass eine Installation Agents aus mehreren Workspaces und/oder Agents mit unterschiedlichen Berechtigungsstufen für die Aufgabenausführung verarbeitet.

Um mehrere Agents zu aktivieren, fügen Sie einfach die Anmeldedaten der Agents zur PlaidLink-Konfigurationsdatei hinzu.

## Mehrere PlaidLink-Dienste betreiben

Ähnlich wie beim Betrieb mehrerer Agents innerhalb eines PlaidLink-Dienstes ist es auch möglich, mehrere PlaidLink-Dienste zu betreiben.

Das ist je nach Nutzung systembasierter Sicherheit oder Netzwerkzugriffsbeschränkungen, die die Kommunikation über Netzwerkgrenzen hinweg verhindern, manchmal erforderlich.

<Aside>In der Regel ist es besser, mehrere Agents unter einem einzigen Dienst zu betreiben als mehrere Dienste auf einem einzelnen Rechner. Je nach Anwendungsfall kann es jedoch erforderlich sein, mehrere getrennte Dienste zu betreiben.</Aside>

## Anforderungen an Rechenleistung, Arbeitsspeicher und Festplatte

Der PlaidLink-Dienst ist extrem schlank und benötigt nur minimale Rechenleistung und minimalen Arbeitsspeicher. Bei der Verarbeitung erheblicher Datenmengen kann es notwendig sein, die Rechenressourcen und insbesondere den Arbeitsspeicher zu erhöhen.

Normalerweise läuft der Agent problemlos mit 5 % CPU und 200 MB Arbeitsspeicher. Für intensive Datenoperationen empfiehlt es sich, eine ganze CPU und mindestens 4 GB RAM zuzuweisen. Bei Systemen mit dynamischer Ressourcenzuweisung wie Kubernetes genügt es, wenn der Agent Zugriff auf Burst-fähige statt auf reservierte Ressourcen hat.

Auch der Speicherplatz für den Agent ist minimal. Agent-Operationen nutzen Festplattenspeicher als Datenpuffer bei der Übertragung großer Datenmengen. Üblicherweise genügen 8 GB für den normalen Betrieb. Für intensive Datenoperationen wird empfohlen, den Speicher entsprechend den erwarteten Datenmengen zu erhöhen. Es gibt keinen festen Wert, da er von mehreren Faktoren abhängt, darunter CPU-Geschwindigkeit, Netzwerkgeschwindigkeit und Datenmenge. Ein guter Ausgangspunkt sind jedoch 20 GB, die Sie danach anpassen.


## Netzwerkanforderungen

Der PlaidLink-Agent ist so konzipiert, dass er mit minimaler Konfiguration funktioniert. Er benötigt kein spezielles VPN und keine besondere Netzwerkkonfiguration, außer dass normaler HTTPS-Netzwerkverkehr zugelassen sein muss. Agents kommunizieren über dasselbe Protokoll wie der normale browserbasierte Datenverkehr.

Der Agent-Dienst initiiert die Kommunikation mit PlaidCloud immer selbst, sodass in Firewalls kein Ingress-Zugriff konfiguriert werden muss.

<Aside>Manchmal blockieren Firewall-Regeln jeglichen Zugriff, sogar normalen HTTPS-Datenverkehr. Wenn der Agent beim Start meldet, dass er PlaidCloud nicht erreichen kann, müssen Sie gemeinsam mit Ihrem Netzwerkteam Port 443 für den Datenverkehr öffnen.</Aside>
