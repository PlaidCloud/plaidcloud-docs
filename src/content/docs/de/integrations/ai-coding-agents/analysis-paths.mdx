Ein **Analysepfad** ist ein verständlicher Name für eine Tabelle, die Sie häufig analysieren – etwa *„Betriebsergebnisse“* oder *„die GuV“*. Registrieren Sie ihn einmal, und von da an können Sie (und Ihr verbundener KI-Assistent) Fragen dazu unter diesem Namen stellen, ohne jedes Mal erneut anzugeben, welches Projekt und welche Tabelle Sie meinen.

Legen Sie einen als **Standard** des Workspace fest, und einfache Fragen wie *„Warum ist das im letzten Quartal gestiegen?“* funktionieren einfach – der Assistent weiß bereits, worauf sich „das“ bezieht.

<Aside>
Analysepfade sind eine gemeinsame Erleichterung im Workspace: Ein Administrator richtet sie ein, und danach kann **jeder** im Workspace sie in seinen Fragen verwenden – über [Microsoft 365 Copilot](/de/integrations/microsoft-365-copilot/) oder einen Coding-Agent, der über [MCP](../getting-started/) verbunden ist. Jede Frage läuft weiterhin unter den eigenen Berechtigungen der jeweiligen Person.
</Aside>

## Warum sie nützlich sind

Ohne Analysepfad muss jede Frage genau angeben, wo die Daten liegen – das Projekt *und* die Tabelle –, was schnell mühsam und leicht fehleranfällig wird. Mit einem Analysepfad sprechen Sie über Ihre Daten so, wie Sie tatsächlich über sie denken:

- **Fragen Sie nach Namen.** *„Fasse die Betriebsergebnisse zusammen.“* statt *„Fasse die Tabelle `ops_summary_v3` im Projekt `Enterprise Profitability` zusammen.“*
- **Legen Sie einen Standard fest.** Markieren Sie Ihre am häufigsten genutzte Tabelle als Standard und lassen Sie den Namen ganz weg – *„Was hat sich seit letztem Monat geändert?“* landet automatisch bei den richtigen Daten.
- **Sorgen Sie für Einheitlichkeit.** Wenn das ganze Team von *„der GuV“* spricht, erreichen alle dieselbe Tabelle – kein Raten, keine veralteten Kopien.

## Einen Analysepfad registrieren

Wenn Sie Workspace-Administrator sind, brauchen Sie weder ein Formular noch einen Einstellungsbildschirm – bitten Sie einfach Ihren verbundenen KI-Assistenten in normaler Sprache, den Pfad für Sie zu registrieren:

> *„Registriere einen Analysepfad namens **Betriebsergebnisse**, der auf die Tabelle `ops_summary` im Projekt **Enterprise Profitability** zeigt.“*

Der Assistent bestätigt den Pfad, und er ist sofort einsatzbereit. Sie können beliebig viele registrieren – einen pro Tabelle, die Sie regelmäßig analysieren.

<Aside type="tip">
Wählen Sie Namen so, wie Ihr Team spricht: *„Betriebsergebnisse“, „der Forecast“, „Mitarbeiterzahl“.* Je verständlicher der Name, desto natürlicher werden Ihre Fragen.
</Aside>

## Einen Standardpfad festlegen

Markieren Sie als Administrator einen Pfad als **Standard**, damit Fragen, die keine Tabelle nennen, automatisch dort landen:

> *„Mache **Betriebsergebnisse** zum Standard-Analysepfad.“*

Von da an laufen Fragen wie *„Was waren in diesem Quartal die größten Veränderungen?“* oder *„Warum ist die Summe gesunken?“* gegen diese Tabelle, ohne dass sonst etwas angegeben werden muss. Es gibt einen einzigen Standard für den gesamten Workspace, sodass die unspezifischen Fragen aller bei derselben Tabelle landen. Wenn Sie einen neuen Standard festlegen, wandert die Krone einfach weiter – es gibt immer nur einen, und der Assistent nennt Ihnen, welcher es ist.

## Einen Pfad für KI-Assistenten nützlich machen

Ein Name und eine Tabelle sagen einem Assistenten, *wo* die Daten liegen. Sie sagen ihm nicht, was die Daten *bedeuten*: welche Filter immer gelten, wie Ihr Geschäftsjahr funktioniert, worauf sich die Begriffe Ihres Teams beziehen. Ohne das rät ein Assistent, und eine selbstsichere falsche Antwort ist schlimmer als eine langsame. Dieser Abschnitt behandelt die beiden Stellen, an denen Sie dieses Wissen hinterlegen, und warum beide wichtig sind.

In dieser Anleitung bezeichnet **KI-Assistenten** jedes LLM, das über PlaidCloud MCP verbunden ist (Claude, Microsoft Copilot, ChatGPT und andere), sowie die integrierte KI von PlaidCloud.

<Aside type="tip" title="Prompt-Hinweise bestimmen, wie gut die Antworten sind">
Ein Pfad mit guten Prompt-Hinweisen und Spaltennotizen in seiner Tabelle erhält von jedem Assistenten korrekte, konsistente Antworten. Ein Pfad ohne beides erhält, was der Assistent aus Spaltennamen ableitet. Zehn Minuten für diese beiden Dinge sind die wertvollste Einrichtung, die Sie für einen Pfad vornehmen können.
</Aside>

### Prompt-Hinweise hinzufügen

Jeder Analysepfad hat **Prompt-Hinweise**: Freitext, von Ihnen verfasst, der Assistenten sagt, wie der Pfad zu verwenden ist. Schreiben Sie eine Anweisung pro Zeile.

Um sie hinzuzufügen, öffnen Sie das Menü **Werkzeuge** und wählen Sie **Analysepfade**, wählen Sie dann einen Pfad aus und klicken Sie auf **Bearbeiten** (oder auf **Neu**, um einen zu erstellen). Das Feld **Prompt-Hinweise** folgt auf **Tabelle**, direkt vor **Als Standard des Arbeitsbereichs festlegen**. Ein Assistent, der mit der Berechtigung zur Verwaltung von Analysepfaden verbunden ist, kann sie ebenfalls festlegen. MCP- und API-Aufrufer sehen dieses Feld als `description`, zum Beispiel: *„Set the description of the Operations Results path to …“*

Assistenten verwenden die Prompt-Hinweise auf zwei Arten:

1. **Um den Pfad auszuwählen.** Wenn eine Frage keinen Pfad nennt, vergleicht der Assistent sie mit dem Namen und den Prompt-Hinweisen jedes Pfads und wählt die beste Übereinstimmung.
2. **Als ständige Anleitung.** Sobald er einen Pfad gewählt hat, wendet der Assistent die Prompt-Hinweise auf jede Abfrage gegen diesen Pfad an: die einzuschließenden Filter, die zu übersetzende Terminologie. Bei einem Assistenten, der über MCP verbunden ist, stammen die Geschäftskennzahlen selbst aus den [Kennzahldefinitionen](../metric-definitions/) des Projekts, nicht aus den Hinweisen.

Die Prompt-Hinweise werden mit dem Pfad gespeichert und sind für alle im Workspace sichtbar, die Analysepfade sehen können. Sie erreichen Assistenten, die über MCP arbeiten, und die integrierte KI von PlaidCloud. Sie werden nicht an die KI-Unterstützung im LLM-Schritt eines Workflows weitergegeben.

### Was Sie schreiben sollten

Schreiben Sie auf, was ein neuer Analyst an seinem ersten Tag mit dieser Tabelle erfahren müsste. Geben Sie jeder Anweisung eine eigene Zeile.

| Schreiben Sie dies | Beispiel |
|---|---|
| **Fragen, die der Pfad beantwortet, und was nicht.** | *„Monatliche Betriebsergebnisse nach Geschäftseinheit. Für Fragen zu Umsatz, Kosten und EBITDA verwenden. Nicht für Mitarbeiterzahl oder Prognosen; dafür den Forecast-Pfad verwenden.“* |
| **Welche Kennzahl ein Geschäftsbegriff bedeutet**, für Assistenten, die über MCP verbunden sind. | *„‚Umsatz‘ ist die Kennzahl Nettoumsatz. `billed_amount` ist Fakturierung, nicht Umsatz.“* |
| **Filter, die immer gelten.** | *„`scenario = 'Budget'` immer ausschließen, außer bei Fragen zum Budget. Intercompany-Zeilen haben `entity_type = 'IC'`; in Summen weglassen.“* |
| **Vorzeichenkonventionen, Kalender und Granularität.** | *„Kosten werden als negative Werte gespeichert. Das Geschäftsjahr beginnt im Juli, GJ26 ist also Juli 2025 bis Juni 2026. Eine Zeile pro Geschäftseinheit und Monat.“* |
| **Geschäftsbegriffe, zugeordnet zu Daten.** | *„‚Der Mittlere Westen‘ bedeutet `region IN ('IL','IN','OH','MI')`. ‚Kernprodukte‘ bedeutet `product_tier = 'A'`.“* |

Fassen Sie sich kurz und konkret. Eine Anweisung pro Zeile ist besser als ein Absatz, und das Limit liegt bei **1.000 Zeichen**. Führende und nachgestellte Leerzeichen werden entfernt.

<Aside>
Bei einem Assistenten, der über MCP verbunden ist, gehört die Berechnung einer Geschäftskennzahl – welche Spalte, wie summiert, über welche Zeilen – in eine [Kennzahldefinition](../metric-definitions/), nicht in die Prompt-Hinweise. Die Hinweise sagen, welche Filter und Begriffe für den Pfad gelten; eine Kennzahl sagt, was die Zahl ist.
</Aside>

### Was Sie nicht schreiben sollten

- **Was Assistenten bereits sehen.** Spaltentypen, Schlüssel und Zeilenanzahlen werden mit der Tabelle zurückgegeben. Sie zu wiederholen verbraucht Ihre 1.000 Zeichen.
- **Was eine einzelne Spalte bedeutet.** Legen Sie das in einer [Spaltennotiz](#spaltennotizen-hinzufügen) ab, damit es bei der Spalte bleibt, wo auch immer die Tabelle verwendet wird. Die Prompt-Hinweise sind dafür da, wie der Pfad als Ganzes zu verwenden ist.
- **Alles Vertrauliche.** Prompt-Hinweise sind im gesamten Workspace sichtbar, nicht nur für Personen mit Zugriff auf das Projekt der Tabelle. Nehmen Sie keine Kennwörter oder Schlüssel, personenbezogenen Daten oder Zahlen und Kommentare auf, die Sie nicht jedem Workspace-Mitglied zeigen würden.

### Gute und schwache Prompt-Hinweise

Beide Beispiele unten gehören zum selben Pfad, und es wird dieselbe Frage gestellt: *„Wie hoch war das EBITDA für den Mittleren Westen im letzten Jahr?“*

| | Schwache Hinweise | Gute Hinweise |
|---|---|---|
| **Text** | *„Betriebsdaten.“* | *„Monatliche Betriebsergebnisse nach Geschäftseinheit.*<br />*EBITDA = `ebitda_adj`; `ebitda` ignorieren.*<br />*`scenario = 'Budget'` und Intercompany-Zeilen (`entity_type = 'IC'`) ausschließen.*<br />*Das Geschäftsjahr beginnt im Juli.*<br />*Mittlerer Westen = IL, IN, OH, MI.“* |
| **Was der Assistent tut** | Wählt die einfache Spalte `ebitda`, schließt Budget- und Intercompany-Zeilen ein und liest „letztes Jahr“ als Kalenderjahr. | Verwendet `ebitda_adj`, lässt Budget- und Intercompany-Zeilen weg, nimmt das letzte abgeschlossene Geschäftsjahr und filtert auf die vier Staaten des Mittleren Westens. |
| **Die Antwort** | Eine Zahl, die plausibel, falsch und anders als die der Finanzabteilung ist. | Die Zahl, die die Finanzabteilung berichtet. |

Die schwachen Hinweise sind nicht falsch. Sie überlassen nur jede Entscheidung dem Raten des Assistenten.

### Spaltennotizen hinzufügen

Die Prompt-Hinweise decken den Pfad als Ganzes ab. Eine **Spaltennotiz** erklärt eine einzelne Spalte, und so erfahren Assistenten, was eine Spalte tatsächlich enthält. **Wenn der Zweck einer Spalte aus ihrem Namen nicht hervorgeht, ist eine Notiz der Unterschied zwischen der richtigen Spalte und einer plausiblen falschen.**

Notizen zur Tabelle des Pfads werden KI-Assistenten zusammen mit der Spaltenliste zurückgegeben, in `table_describe` mit `include=['columns']`, als `memo` bei jeder Spalte, die eine hat. Spalten ohne Notiz werden wie bisher zurückgegeben. Dieselben Notizen erreichen die KI-Unterstützung im LLM-Schritt eines Workflows für die Tabellen, die er verwendet.

#### Wann eine Notiz nötig ist

| Fügen Sie eine Notiz hinzu für | Beispielnotiz |
|---|---|
| **Codes und Abkürzungen** | `seg_cd`: *„Kundensegmentcode: E = Enterprise, M = Mittelstand, S = Kleinunternehmen.“* |
| **Ähnlich aussehende Messgrößen** | `ebitda_adj`: *„EBITDA nach Bereinigung um einmalige Posten. Für die Berichterstattung verwenden; `ebitda` ist nicht bereinigt.“* |
| **Flags** | `is_ic`: *„1, wenn die Zeile eine Intercompany-Transaktion ist. Aus konsolidierten Summen ausschließen.“* |
| **Einheiten oder Währung** | `amt_local`: *„Betrag in der lokalen Währung der Entität, in Tausend.“* |
| **Abgeleitete oder umgelegte Werte** | `alloc_cost`: *„Gemeinkosten, die dieser Einheit nach Mitarbeiterzahl umgelegt wurden. Nicht direkt angefallen.“* |

Lassen Sie Spalten aus, deren Namen alles sagen, etwa `invoice_date` oder `customer_name`. Eine Notiz, die den Namen wiederholt, bringt nichts.

#### So fügen Sie eine Notiz hinzu

1. Öffnen Sie die Tabelle des Pfads im [Tabellen-Explorer](/de/guides/data/table-explorer/).
2. Aktivieren Sie in der Symbolleiste **Spalteneigenschaften**.
3. Wählen Sie die Spalte in der Spaltenliste aus.
4. Geben Sie den Text unter **Notiz** ein.

Eine Notiz, die an der Tabelle festgelegt wird, gilt überall, wo die Tabelle verwendet wird, einschließlich jedes Analysepfads, der darauf zeigt.

#### Prompt-Hinweise oder Notiz

Legen Sie jede Information an einer Stelle ab.

| | Prompt-Hinweise | Spaltennotiz |
|---|---|---|
| **Betrifft** | Wie der Pfad als Ganzes zu verwenden ist | Was eine einzelne Spalte bedeutet |
| **Typischer Inhalt** | Fragen, die er beantwortet, ständige Filter, Geschäftskalender, Geschäftsbegriffe | Codes, Einheiten, Flags, welche der ähnlichen Spalten zu verwenden ist |
| **Beispiel** | *„Intercompany-Zeilen aus Summen ausschließen.“* | `is_ic`: *„1, wenn die Zeile Intercompany ist.“* |

Hier sagt die Notiz, was `is_ic` bedeutet, und die Prompt-Hinweise sagen, was damit zu tun ist.

## Verwendung

Sobald Ihre Pfade registriert sind, fragen Sie einfach:

<Steps>

1. **Nach Namen** – *„Zeig mir die ersten Zeilen der Betriebsergebnisse.“*

2. **Über den Standard** – *„Was hat sich gegenüber dem letzten Quartal geändert?“* (keine Tabelle genannt – es wird der Standardpfad des Workspace verwendet).

3. **Frei wechseln** – *„Mach jetzt dasselbe für den Forecast.“* Der Assistent folgt Ihnen, von Pfad zu Pfad.

</Steps>

Das passt natürlich zu Umlagefragen – siehe [Umlagen nachverfolgen](../tracing-allocations/) –, sodass Sie von *„Warum haben sich die Betriebsergebnisse verändert?“* direkt zu den dahinterliegenden Konten und Treibern gelangen.

## Verwendung über MCP

Wenn ein Assistent, der über [MCP](../getting-started/) verbunden ist, einem Werkzeug einen Analysepfad übergibt, kann er entweder den **Namen** des Pfads (ohne Beachtung der Groß-/Kleinschreibung) oder seine **ID** verwenden. Ein Pfad, der mit einer nicht existierenden ID aktualisiert wird, wird abgelehnt; um einen neuen Pfad zu erstellen, lassen Sie die ID weg.

`query_data_read` akzeptiert `analysis_path` anstelle eines Projekts und einer Tabelle für `table`, `json_paths`, `dimension_value`, `column_values` und `aggregate`.

**Nur einige Spalten in der Vorschau anzeigen.** Übergeben Sie `columns=[...]` an `query_data_read(action='table')`, um nur die von Ihnen genannten Spalten zurückzugeben. Die Zugriffsregeln auf Zeilenebene gelten weiterhin vollständig. Es kann nicht mit `version_id` kombiniert werden.

**Eine gefilterte Summe in einem Aufruf erhalten.** Fragen Sie bei `column_values` die Messgröße ab und filtern Sie nach der gewünschten Spalte:

```
query_data_read(
  action='column_values',
  project_id=<project>,
  table_id=<table>,
  dimension_column_name=<filter column>,
  value_column_name=<measure>,
  filters={<filter column>: <value>}
)
```

Es liefert eine Zeile für diesen Wert. Wenn ein Spaltenname falsch geschrieben ist, listet der Fehler bis zu fünf ähnliche Treffer auf, damit der Assistent ihn korrigieren und es erneut versuchen kann.

**Summieren oder aufschlüsseln in einem Aufruf.** Verwenden Sie `action='aggregate'`, um nach einer oder mehreren Spalten zu gruppieren und Messgrößen auf dem Server zu summieren, zu mitteln oder zu zählen, statt Zeilen zu lesen:

```
query_data_read(
  action='aggregate',
  project_id=<project>,
  table_id=<table>,
  group_by=['Product'],
  measures=[{'column': 'Revenue', 'agg': 'sum'}, {'column': 'Volume'}],
  filters={'Fiscal Year': 2027},
  order_by='Revenue',
  limit=10
)
```

`measures` akzeptiert für `agg` die Werte `sum` (Standard), `avg`, `min`, `max` oder `count`; `count` akzeptiert auch `'*'`. Ein Wert in `filters` kann eine Liste sein, um auf einen von mehreren Werten zu treffen. `limit` ist standardmäßig 50 und höchstens 500. `order_by` nennt eine Messgröße oder eine Gruppenspalte; Messgrößen werden mit dem höchsten Wert zuerst sortiert. Die Antwort enthält `rows`, `total_groups` und `truncated`, was wahr ist, wenn mehr Gruppen existieren, als `limit` zurückgegeben hat. Die Zugriffsregeln auf Zeilenebene werden angewendet, bevor die Summen berechnet werden.

## Wer sie einrichten kann

Das Einrichten von Analysepfaden – ihre Registrierung und die Wahl des Standards – ist eine Aktion für **Administratoren**, damit die gemeinsamen Namen für alle sauber und vertrauenswürdig bleiben. Sobald sie existieren, kann jedes Mitglied des Workspace sie in seinen Fragen verwenden und sieht dabei weiterhin nur die Daten, die seine eigenen Berechtigungen zulassen.
