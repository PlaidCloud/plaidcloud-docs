Der Launcher ist das Erste, was Sie nach der Anmeldung bei einem Workspace sehen.
Er bündelt das, womit Sie am häufigsten arbeiten – Projekte, Workflows, Tabellen, Dashboards,
Panel-Apps, Dimensionen, Dateneditoren und Dokumente – auf einer Seite mit Kacheln,
sodass Sie dort weitermachen können, wo Sie aufgehört haben, ohne jede App einzeln zu durchsuchen.

## Bereiche

Die Seite ist von oben nach unten in drei Bereiche gegliedert. Ein Bereich erscheint nur dann,
wenn er etwas anzuzeigen hat.

- **Erfordert Aufmerksamkeit** – Workflows, deren letzte Ausführung fehlgeschlagen ist, sodass
  Probleme sofort beim Öffnen auffallen. Jede Karte verweist direkt auf die fehlgeschlagene Ausführung,
  und Sie können eine bereits erledigte mit **Schließen** ausblenden.
- **Angeheftet** – alles, was Sie als Favorit markiert haben, in der Reihenfolge, in der Sie es angeheftet haben.
  Jeder Elementtyp kann hier angeheftet werden (siehe [Anheften](#anheften-favoriten)).
- **Zuletzt verwendet** – Projekte, Dashboards und Panel-Apps, die Sie kürzlich geöffnet oder bearbeitet haben.

<Aside type="note">
Nur Projekte, Dashboards und Panel-Apps erscheinen nach Aktualität – es gibt meist
viel zu viele Workflows, Tabellen, Dimensionen, Dateneditoren und Dokumente, um sie
auf diese Weise aufzulisten. Heften Sie diejenigen an, zu denen Sie zurückkehren, dann warten sie
im Bereich **Angeheftet** auf Sie.
</Aside>

## Projektkacheln

Eine Projektkachel fasst das Projekt auf einen Blick zusammen:

| Kennzahl | Bedeutung |
|---|---|
| **Workflow-Ausführungen** | Abgeschlossene Workflow-Ausführungen im jüngsten Zeitfenster |
| **Letzte Ausführung** | Wann die letzte Ausführung beendet wurde |
| **Workflows** | Workflows, die das Projekt enthält |
| **Tabellen** | Tabellen, die das Projekt enthält |
| **Datensätze** | Gesamtzahl der Zeilen in diesen Tabellen (ein `~` kennzeichnet eine Schätzung) |

Ein Projekt ohne Ausführungsverlauf zeigt statt der Ausführungszahlen **Zuletzt bearbeitet** an,
und Zählwerte werden vollständig weggelassen, wenn sie null sind.

### Kachelbilder

Jede Projektkachel trägt ein verblasstes Hintergrundbild. Standardmäßig ist das der
PlaidCloud-Fächer, aber Sie können einem Projekt ein eigenes Bild geben – etwa ein Kundenlogo
oder etwas, das die Arbeit auf einen Blick erkennbar macht –, damit es auf einem
vollen Launcher hervorsticht.

So legen Sie eines fest:

1. Öffnen Sie das Projekt und wechseln Sie zur Registerkarte **Startseite**.
2. Scrollen Sie in der linken Spalte ganz nach unten zu **Launcher-Kachelbild**.
3. Wählen Sie das Dokumentenkonto, das das Bild enthält, und klicken Sie dann auf **Durchsuchen**, um die Bilddatei auszuwählen.
4. Mit **Leeren** kehren Sie zum Standard zurück.

Das Bild wird hinter den Kennzahlen ausgeblendet, damit diese lesbar bleiben. Wählen Sie also
etwas, das auch verblasst gut wirkt. Breite Bilder passen besser zur Form der Kachel
als hohe. Zum Festlegen benötigen Sie die Berechtigung zum Bearbeiten des Projekts; ein
Betrachter mit reinem Lesezugriff sieht die Auswahl deaktiviert.

<Aside type="note">
Jeder, der das Projekt sehen kann, sieht auch sein Kachelbild, doch das Bild wird
nur an Personen ausgeliefert, die auch das Dokumentenkonto lesen dürfen, in dem es liegt. Ein Betrachter
ohne diesen Zugriff sieht einfach den Standardfächer.
</Aside>

Dashboard-Kacheln funktionieren anders – sie zeigen eine automatisch erzeugte
Miniaturansicht des Dashboards selbst, sodass nichts auszuwählen ist.

## Elemente öffnen

Jede Karte und jede Listenzeile hat eine Hauptaktion und, wo sinnvoll, zusätzliche
Aktionen:

| Element | Öffnet | Außerdem verfügbar |
|---|---|---|
| Projekt | Das Projekt | |
| Workflow | Den Workflow | Ausführen, Letzte Ausführung öffnen, Live-Status **Wird ausgeführt** |
| Tabelle | Die Tabelle | Im Tabellen-Explorer öffnen |
| Dimension | Ihren Hierarchie-Editor | |
| Dateneditor | Sein Projekt | |
| Dashboard | Das Dashboard | In neuem Tab öffnen |
| Panel-App | Die App | In neuem Tab öffnen |
| Dash-App | Die App | In neuem Tab öffnen |
| Dokument | Die Datei oder den Ordner | |

Ein laufender Workflow zeigt eine Live-Statusanzeige, die sich von selbst aktualisiert – Sie
müssen nicht aktualisieren.

## Anheften (Favoriten)

Klicken Sie auf den **Stern** einer beliebigen Launcher-Karte oder Listenzeile, um sie anzuheften. Angeheftete Elemente
erscheinen immer im Bereich **Angeheftet**, unabhängig davon, wie kürzlich Sie sie verwendet haben,
sodass das, was Ihnen wichtig ist, nie aus der Reichweite scrollt.

Sie können auch dort anheften, wo Sie ohnehin arbeiten, ohne zuerst den Launcher zu öffnen –
achten Sie auf die Sternspalte:

- **Projekte, Workflows, Tabellen, Dimensionen und Dateneditoren** – die Sternspalte
  in der jeweiligen Liste innerhalb des Projekts.
- **Dashboards**, **Panel-Apps** und **Dash-Apps** – die Sternspalte unter **Meine Dashboards**
  und **Meine Panel-Apps**.
- **Dokumente** – klicken Sie im Dokumentenbrowser mit der rechten Maustaste auf eine Datei *oder* einen Ordner
  und wählen Sie **An Launcher anheften**.

Klicken Sie irgendwo auf einen gefüllten Stern, um das Anheften aufzuheben. Überall vorgenommene Anheftungen werden
sofort im Launcher widergespiegelt.

## Kacheln oder Liste

Mit dem Schalter **Kacheln / Liste** in der Symbolleiste wechseln Sie zwischen der großzügigen Kartenansicht
und einer dichten, einzeiligen Liste. Ihre Auswahl wird gespeichert, und der Wechsel erfolgt
sofort – es wird neu gezeichnet, was bereits geladen ist, ohne erneut abzurufen.

## Nach Typ filtern

Die Chip-Reihe links in der Symbolleiste hat einen Chip pro Typ, jeweils mit eigenem
Symbol – **Projekte**, **Dashboards**, **Panel-Apps**, **Workflows**, **Tabellen**,
**Dimensionen**, **Dateneditoren** und **Dokumente**. Ein gedrückter Chip bedeutet, dass dieser
Typ angezeigt wird; klicken Sie darauf, um diesen Typ in den Bereichen **Zuletzt verwendet** und **Angeheftet**
auszublenden. Ihr Filter wird zwischen den Besuchen gespeichert.

Der Bereich **Erfordert Aufmerksamkeit** wird nie gefiltert – ein fehlgeschlagener Workflow
erscheint immer, auch wenn der Chip seines Typs deaktiviert ist.

## Suche und Befehle

Drücken Sie auf jedem Bildschirm **Strg/Cmd-K** – oder klicken Sie in der Launcher-Symbolleiste auf **Suchen** –,
um die Befehlspalette zu öffnen. Die einzige Ausnahme ist das Buchungsregister, das
**Strg/Cmd-K** für seine eigene Palette beansprucht.

Bevor Sie etwas eingeben, listet sie zwei Dinge auf:

- **Aktionen** – Befehle, die Sie von hier aus ausführen können: zur Startseite, zu Projekten,
  Dashboards oder Dokumenten wechseln, zwischen heller und dunkler Darstellung umschalten,
  Ihre KI verbinden und Hilfe aufrufen. Die Aktionen **Gehe zu** erscheinen nur für Apps,
  die Ihr Workspace hat.
- **Zuletzt verwendet** – die letzten acht geöffneten Elemente, das jüngste zuerst: Projekte,
  Workflows, Tabellen, Dimensionen, Dateneditoren, Dashboards, Panel-Apps und
  Dokumente, die aus dem Launcher oder der Palette geöffnet wurden, sowie jedes Projekt, das Sie
  irgendwo öffnen. Etwas, das innerhalb eines Projekts geöffnet wird – etwa ein Workflow oder
  eine Dimension –, wird nicht hinzugefügt. Diese Liste wird in Ihrem Browser gespeichert, wird also nicht
  zwischen Geräten geteilt, und sie ist vom Bereich **Zuletzt verwendet** des Launchers
  getrennt (siehe [Bereiche](#bereiche)).

Sobald Sie zu tippen beginnen, werden beide Listen gleichzeitig eingegrenzt – die eingegebenen Zeichen müssen nur
der Reihe nach vorkommen, sodass `proj` **Zu den Projekten** findet –, wobei der beste Treffer
zuerst steht. Ab zwei Zeichen durchsucht die Palette außerdem Projekte,
Workflows, Tabellen, Dashboards und Panel-Apps und fügt diese Ergebnisse darunter hinzu,
nach Typ gruppiert, jeweils mit denselben Öffnen-Aktionen und demselben Anheft-Stern wie auf dem Board.
Ein Ergebnis, das bereits unter **Zuletzt verwendet** angezeigt wird, wird nicht wiederholt.

- **Nach oben / Nach unten** verschieben die Auswahl.
- **Enter** führt die ausgewählte Aktion aus oder öffnet das ausgewählte Element.
- **Escape** schließt die Palette.

Dimensionen, Dateneditoren und Dokumente sind nicht durchsuchbar – erreichen Sie sie durch
Anheften, über **Zuletzt verwendet**, sobald Sie sie aus dem Launcher geöffnet haben, oder über
das Projekt, zu dem sie gehören.

Ein Klick auf ein Ergebnis öffnet es; ein Klick auf seinen **Stern** heftet es an und lässt die Palette
geöffnet, sodass Sie mehrere Dinge in einem Durchgang anheften können.

## Aktualisieren

Der Launcher aktualisiert sich von selbst, wenn Sie zu ihm zurückkehren und seine Daten veraltet sind.
Um sofort die neuesten Daten abzurufen, klicken Sie in der Symbolleiste auf **Aktualisieren**.

## Woanders starten

PlaidCloud öffnet sich standardmäßig im Launcher. Um stattdessen in einer anderen App zu starten,
deaktivieren Sie im Optionsmenü die Option **Im Launcher starten**.

## Darstellung (Hell, Dunkel, Automatisch)

Die Schaltfläche **Darstellung** in der oberen Symbolleiste – das Kontrastsymbol neben dem
Kontomenü – schaltet PlaidCloud zwischen heller und dunkler Darstellung um. Sie gilt
überall: im Launcher, in jeder App und in jedem Fenster und Dialog darin.

| Auswahl | Wirkung |
| --- | --- |
| **Hell** | Immer die helle Darstellung verwenden, unabhängig von der Einstellung Ihres Geräts. |
| **Dunkel** | Immer die dunkle Darstellung verwenden, unabhängig von der Einstellung Ihres Geräts. |
| **Automatisch (System)** | Der Darstellungseinstellung Ihres Betriebssystems folgen. |

**Automatisch (System)** ist der Standard und folgt Ihrem System live: Wenn Ihr
Computer abends auf Dunkel umschaltet, folgt PlaidCloud im selben Moment,
ohne Neuladen. Wenn Sie **Hell** oder **Dunkel** wählen, wird die Darstellung fixiert und
die Systemeinstellung fortan ignoriert.

<Aside type="note">
Ihre Auswahl wird in dem Browser gespeichert, in dem Sie sie getroffen haben, und wird daher nicht
in einen anderen Browser oder auf einen anderen Computer übernommen – legen Sie sie in jedem einmal fest.
Das Löschen der Websitedaten Ihres Browsers setzt sie auf **Automatisch** zurück. Wenn Ihr Browser den
lokalen Speicher blockiert (manche Modi für privates Surfen tun das), funktioniert der Umschalter
weiterhin für die Sitzung, beginnt aber beim nächsten Mal wieder bei **Automatisch**.
</Aside>

Eingebettete Inhalte behalten ihre eigenen Farben: Dashboards und Panel-Apps werden von dieser
Einstellung nicht neu gestaltet.
