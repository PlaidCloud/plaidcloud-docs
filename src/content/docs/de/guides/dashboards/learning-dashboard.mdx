## Beschreibung


Dashboards unterstützen eine breite Palette von Anwendungsfällen, von statischem Reporting bis zu dynamischer Analyse. Sie bewältigen komplexe Reporting-Anforderungen und bieten zugleich eine intuitive Point-and-Click-Oberfläche. Manchmal treten Probleme auf. Ein Mitglied des PlaidCloud-Support-Teams steht Ihnen jederzeit zur Seite, wir haben aber auch einige Tipps zusammengestellt, falls Sie auf ein ähnliches Problem stoßen.



## **Häufige Fragen und Antworten zu Dashboards**



### Bevorzugter Browser


Wegen des häufigen Cachings ist Google Chrome in der Regel der beste Webbrowser für Dashboards. Wenn Sie einen anderen Browser verwenden und auf ein Problem stoßen, empfehlen wir, zunächst Cache und Cookies zu leeren und zu prüfen, ob das Problem damit behoben ist. Falls nicht, wechseln Sie zu Google Chrome und prüfen, ob das Problem erneut auftritt.



### Synchronisierungsverzögerung


* *Problem:* Nach dem Aufheben und erneuten Veröffentlichen von Tabellen im Dashboard-Bereich scheinen die Daten nicht richtig synchronisiert zu werden.
* *Lösungen:* Das erneute Veröffentlichen einer Tabelle leert die zwischengespeicherten Ergebnisse jedes Diagramms, das sie liest, sodass ein Dashboard, das nach der Workflow-Ausführung geöffnet wird, die neuen Daten ohne manuelle Aktualisierung zeigt. Falls nicht, prüfen Sie, ob die Ausführung abgeschlossen wurde und die erwartete Tabelle erneut veröffentlicht hat. Siehe [Dashboard-Caching](/de/guides/dashboards/dashboard-caching/).

### Tabellensynchronisierungsfehler


* *Problem:* Nachdem eine Tabelle unter demselben veröffentlichten Namen wie eine frühere Tabelle neu erstellt wurde, wird sie nicht synchronisiert – auch nicht nach dem Aktualisieren des Dashboards sowie dem Aufheben und erneuten Veröffentlichen der Tabelle.
* *Lösungen:* Veröffentlichen Sie die Tabelle unter einem anderen Namen erneut. Das Datenmodell des Dashboards lässt keine doppelten Tabellen oder Tabellen mit demselben veröffentlichten Namen und derselben Projekt-ID zu.

### Cache-Warnung


* *Problem:* Oben rechts erscheint eine Warnung: „Loaded data cached **3 hours ago**. Click to force-refresh.“
* *Lösungen:* Klicken Sie auf die Warnung, um den Cache zwangsweise zu aktualisieren. Alternativ klicken Sie auf das Dropdown-Menü neben „Edit dashboard“ und wählen dort „Force refresh dashboard“. Beide Optionen aktualisieren im System und sind dem Neuladen des Webbrowsers vorzuziehen. Wie lange ein Ergebnis vorgehalten wird, ist konfigurierbar – siehe [Dashboard-Caching](/de/guides/dashboards/dashboard-caching/).

### Berechtigungswarnung


* *Problem:* Mein veröffentlichtes Dashboard zeigt in jedem Bereich, in dem Daten erscheinen sollten, denselben Fehler: „This endpoint requires the datasource… permission“
* *Lösungen:* Prüfen Sie, ob die Datenquellen nicht veraltet sind. Höchstwahrscheinlich beziehen die Diagramme ihre Daten aus veraltetem Material. Aktualisieren Sie in diesem Fall die Diagramme mit neuen Datenquellen.
* *Problem:* Ich erhalte dieselbe Berechtigungswarnung wie oben, aber mein Kollege kann die Diagrammdaten sehen.
* *Lösungen:* Wenn eine Person die Daten in den Diagrammen sehen kann und eine andere nicht, muss die zweite Person möglicherweise von jemandem aus der berechtigten Kategorie freigeschaltet werden. Gehen Sie dazu so vor:


	1. Gehen Sie zu Charts
	2. Wählen Sie das zweite kleine Symbol mit Stift und Papier neben dem Diagramm, für das Sie Zugriff gewähren möchten
	3. Klicken Sie auf Edit Table
	4. Klicken Sie auf Detail
	5. Klicken Sie auf Owners, fügen Sie den Namen der Person hinzu, der Sie Zugriff gewähren möchten, und speichern Sie.

<Aside>Bewährte Vorgehensweise: Fügen Sie jedes Mal, wenn Sie ein neues Diagramm erstellen und speichern, sofort alle zutreffenden Personen zum Abschnitt „Owners“ hinzu. Andernfalls müssen Sie jedes Mal zurückgehen, um Eigentümer zu bearbeiten und hinzuzufügen, wenn jemand Neues Zugriff benötigt.</Aside>


### Geänderte Filter im Dashboard speichern


* *Problem:* Ich habe Filter in meinem Entwurfsmodell geändert und möchte sie in meinem Dashboard speichern. Die Filter sind nicht in der Liste. In meinem Entwurfsmodell erschien eine Warnung: „There is no chart definition associated with this component, could it have been deleted? Delete this container and save to remove this message.“
* *Lösungen:* Gehen Sie zu „Edit Chart“. Stellen Sie dort sicher, dass der Abschnitt „Dashboards“ mit dem richtigen Dashboard gefüllt ist. Ist er leer, tragen Sie den richtigen Dashboard-Namen ein.

### Zahlenformatierung: Fehler


* *Problem:* Meine Zahlenformatierung ist defekt und durcheinander.
* *Lösungen:* Der wahrscheinlichste Grund für diesen Fehler sind Nullwerte in einer numerischen Spalte. Entfernen Sie mit einem Filter alle numerischen Spalten mit Nullwerten und führen Sie die Abfrage erneut aus. Hilft das nicht, sehen Sie sich das hier bereitgestellte Material an: http://bl.ocks.org/zanarmstrong/05c1e95bf7aa16c4768e oder hier: https://github.com/apache-superset/superset-ui/issues. Und schließlich: Wenden Sie sich jederzeit gern an ein Mitglied des PlaidCloud-Support-Teams. Dieses Problem ist bekannt, und an einer dauerhafteren Lösung wird gearbeitet.

### Zahlenformatierung


So runden Sie Zahlen auf die nächste ganze Zahl:


1. *Nicht verwenden:* ,.0f
2. *Stattdessen verwenden:* ,d oder $,d für Dollar

### Vorhandenes Dashboard importieren


* *Problem:* Ich importiere ein vorhandenes Dashboard und erhalte bei meinem Export einen Fehler.
* *Lösungen:* Prüfen Sie zuerst die Datei. Dashboards und Datasets werden aus der ZIP-Datei importiert, die **Exportieren** erzeugt. Eine ältere JSON- oder YAML-Exportdatei wird abgelehnt – exportieren Sie das Dashboard daher erneut und importieren Sie die neue ZIP-Datei.
* Prüfen Sie dann, ob das Dashboard einen „Slug“ hat. Öffnen Sie dazu Edit Dashboard; der zweite Abschnitt heißt Slug. Ist dieser Abschnitt leer oder steht dort „null“, liegt es nicht daran. Andernfalls muss der Slug eindeutig sein: Ändern Sie ihn in etwas, das kein anderes Dashboard verwendet, exportieren Sie erneut und importieren Sie die neue Datei.
