## Beschreibung

Wenn Sie eine PlaidCloud-**Organisation** (einen „Partner“) verwalten, können Sie festlegen, wer in Ihrem Team den Support übernimmt und wie diese Personen benachrichtigt werden. Für Organisationsadministratoren (und PlaidCloud-Mitarbeiter) erscheint in der linken Navigation der Eintrag **Support Agents**. Dort weisen Sie Agenten zu und konfigurieren das Benachrichtigungsrouting pro Organisation.

Die **Workspaces** einer Organisation sind ihre Mandanten. Ein von Ihnen zugewiesener Support-Agent kann auf *alle* Workspaces der Organisation oder auf eine bestimmte Auswahl beschränkt werden.

## Zuerst Personen zu Ihrer Organisation hinzufügen

Nur Mitglieder Ihrer Organisation können zu Support-Agenten gemacht werden, und zwar Mitglieder mit der Rolle **Administrator** oder **Workspace**. Der erste Schritt ist daher sicherzustellen, dass die Person in der Organisation ist.

1. Öffnen Sie den Bereich **Organizations**
2. Wählen Sie Ihre Organisation aus
3. Öffnen Sie ihre **Mitglieder**
4. Laden Sie die Person ein oder fügen Sie sie hinzu und gewähren Sie ihr die Rolle **Administrator** oder **Workspace**

<Aside type="note">
Die Person muss sich mindestens einmal bei PlaidCloud angemeldet haben, bevor sie hinzugefügt werden kann, und sie benötigt die Rolle Administrator oder Workspace. Eine schreibgeschützte Verzeichnisrolle reicht nicht aus, um als Support-Agent zugewiesen zu werden.
</Aside>

Sobald die Person Mitglied mit der Rolle Administrator oder Workspace ist, erscheint sie im nächsten Schritt als zuweisbarer Kandidat.

## Einen Support-Agenten zuweisen

1. Öffnen Sie **Support Agents**
2. Wählen Sie Ihre Organisation in der Auswahl **Organization** aus
3. Klicken Sie auf `Add Agent`
4. Wählen Sie das **Mitglied** aus, das zugewiesen werden soll
5. Wählen Sie **Workspace access**:
   - **All workspaces**: Der Agent sieht Tickets für jeden Workspace der Organisation
   - **Specific workspaces**: Wählen Sie genau die Workspaces aus, die der Agent abdecken soll
6. Klicken Sie auf `Save`

Der Agent sieht nun die Konsole **Support**, beschränkt auf die Workspaces, die Sie gewährt haben (siehe [Die Support-Konsole](/de/guides/support/support-console/)). Bearbeiten Sie einen Agenten, um seinen Bereich zu ändern, oder entfernen Sie ihn, um den Zugriff zu entziehen. Ein Workspace, der später in den Papierkorb verschoben oder aus der Organisation herausgenommen wird, fällt automatisch aus dem Bereich eines Agenten heraus.

## Benachrichtigungen und Eskalation konfigurieren

Damit Ihr Team schnell reagiert, leiten Sie Benachrichtigungen zu neuen Tickets an einen gemeinsamen Kanal weiter und richten Sie eine Eskalation für Tickets ein, die zu lange liegen bleiben.

1. Öffnen Sie **Support Agents** und wählen Sie Ihre Organisation
2. Klicken Sie auf `Notification Settings`
3. Konfigurieren Sie die folgenden Optionen
4. Klicken Sie auf `Save` oder zuerst auf `Send Test`, um eine Testnachricht an Ihren Kanal zu senden

### Team-Kanal

Wohin eine Benachrichtigung zu einem **neuen Ticket / einer neuen nicht übernommenen Nachricht** gesendet wird:

- **Aus**: keine Benachrichtigungen im Team-Kanal
- **Slack**: Fügen Sie eine **Incoming-Webhook**-URL von Slack ein
- **Microsoft Teams**: Fügen Sie eine **Workflow-(Incoming-Webhook-)** URL von Teams ein
- **E-Mail**: Geben Sie eine E-Mail-Adresse ein

Die Benachrichtigung wird ausgelöst, wenn ein Kunde einen Thread eröffnet, der einen Verantwortlichen benötigt, und enthält den Mandanten und die Ticketnummer.

### Benachrichtigungen an den Ticket-Verantwortlichen

Lassen Sie **Email the ticket owner when a customer replies** aktiviert, damit der Agent, der ein Ticket übernommen hat, jedes Mal per E-Mail benachrichtigt wird, wenn der Kunde eine Antwort hinzufügt.

### Eskalation

Aktivieren Sie **Escalate tickets left unclaimed and unanswered**, um Ihr Team an Tickets zu erinnern, die niemand übernommen hat:

- **Escalate after (minutes)**: wie lange ein Ticket nicht übernommen und unbeantwortet bleiben darf, bevor es eskaliert wird
- **Escalation contact email** (optional): ein Ansprechpartner, der bei einer Eskalation per E-Mail benachrichtigt wird; bleibt das Feld leer, wird stattdessen der Team-Kanal erneut benachrichtigt
- **Max reminders**: wie viele Eskalationsbenachrichtigungen gesendet werden, bevor sie enden

Der Eskalationszeitgeber wird zurückgesetzt, sobald ein Ticket übernommen, beantwortet oder gelöst wird.

<Aside type="note">
Incoming-Webhook-Kanäle posten in einen gemeinsamen Kanal und können keine Direktnachrichten an eine Person senden. Deshalb wird der Ticket-Verantwortliche per **E-Mail** benachrichtigt, während Benachrichtigungen zu neuen Tickets und Eskalationen an den **Team-Kanal** gehen.
</Aside>
