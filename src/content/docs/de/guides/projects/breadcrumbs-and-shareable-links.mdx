Analyze-Fenster öffnen sich übereinander – ein Workflow innerhalb eines Projekts, ein Schritt innerhalb dieses Workflows, eine Tabelle, die Sie geöffnet haben, um ein Ergebnis zu prüfen. Zwei Funktionen machen es leicht zu sehen, wo Sie sich befinden, und wieder zurückzufinden: ein **Breadcrumb** im Titel jedes Fensters und eine **URL, die dem folgt, was Sie gerade ansehen**, sodass sich jede Ansicht als Lesezeichen speichern oder an Kollegen senden lässt.

## Der Breadcrumb

Fenster, die zu einem Projekt gehören, zeigen ihre Herkunft als Titel in der Titelleiste des Fensters:

```
My Project › Workflow › Nightly Load
```

Jeder Teil wird als Segment bezeichnet, und die Segmente lesen sich von links nach rechts vom äußersten Container nach innen:

1. **Das Projekt** – das Projekt, dem das gehört, was Sie gerade ansehen.
2. **Der Objekttyp** – Workflow, Tabelle, Schritt, Dimension oder Dateneditor.
3. **Das Objekt selbst** – der aktuelle Workflow, die aktuelle Tabelle, der aktuelle Schritt usw. Dieses letzte Segment ist der Ort, an dem Sie sich bereits befinden, und ist daher nicht anklickbar.

### Damit navigieren

Wählen Sie eines der ersten beiden Segmente aus, um nach oben zu wechseln:

| Segment | Tooltip | Aktion |
|---|---|---|
| Der Projektname | Projekt öffnen | Öffnet dieses Projekt oder bringt es in den Vordergrund, wenn es bereits geöffnet ist |
| Workflow | Alle Workflows anzeigen | Öffnet das Projekt mit seiner Liste der Workflows |
| Tabelle | Alle Tabellen anzeigen | Öffnet das Projekt mit seiner Liste der Tabellen |
| Schritt | Alle Schritte anzeigen | Öffnet das Projekt mit seiner Liste der Schritte |
| Dimension | Alle Dimensionen anzeigen | Öffnet das Projekt mit seiner Liste der Dimensionen |
| Dateneditor | Alle Dateneditoren anzeigen | Öffnet das Projekt mit seiner Liste der Dateneditoren |

Das Typ-Segment ist der schnelle Weg zu einem Geschwisterobjekt: Von einem Workflow aus gelangen Sie mit einem Klick zur vollständigen Liste der Workflows im selben Projekt und können einen anderen öffnen.

<Aside type="note">
Das Fenster, von dem Sie kommen, bleibt geöffnet. Die Navigation über einen Breadcrumb bringt das Projekt in den Vordergrund – sie schließt nicht, was Sie angesehen haben, und Sie können über die Registerkartenleiste am unteren Bildschirmrand dorthin zurückkehren.
</Aside>

### Wo Breadcrumbs erscheinen

- **Workflow**-Fenster – das Schrittraster eines Standard-Workflows
- **Visueller Workflow-Designer** – die Arbeitsflächenansicht eines erweiterten Workflows
- **Tabellen-Explorer**
- **Schritt**-Fenster, die einzeln geöffnet wurden
- **Dimension**-Hierarchiefenster
- **Dateneditor**-Fenster

Ein Schritt kann zu mehr als einem Workflow gehören, daher zeigt der Breadcrumb eines Schritts `Project › Step › name`, statt einen einzelnen zugehörigen Workflow zu nennen.

### Zugriff per Tastatur und Screenreader

Anklickbare Segmente sind gewöhnliche Steuerelemente: Mit dem **Tabulator** gelangen Sie darauf, und **Eingabetaste** oder **Leerzeichen** aktiviert das Segment mit dem Fokus, sodass Sie für den Weg nach oben in der Hierarchie nie eine Maus benötigen. Jedes Segment wird als Schaltfläche angesagt, das letzte Segment als aktuelle Seite, und die Trennzeichen `›` werden übersprungen, statt vorgelesen zu werden.

### Einen Dateneditor mit nicht gespeicherten Änderungen verlassen

Der Dateneditor ist das einzige Fenster, das nachfragt, bevor ein Breadcrumb Sie von dort wegführt. Wenn Sie Änderungen in Bearbeitung haben, zeigt die Auswahl eines Segments die Abfrage **Nicht gespeicherte Änderungen** – *Dateneditor ohne Speichern der Änderungen schließen?* – mit **Editor schließen**, um ihn trotzdem zu verlassen. Brechen Sie die Abfrage ab, bleiben Sie mit Ihren Änderungen im Editor.

Es ist dieselbe Abfrage, die auch die Schaltfläche **Schließen** des Editors anzeigt, sodass es keinen Weg aus einem Dateneditor gibt, der Arbeit ohne Rückfrage verwirft.

## Teilbare Links

Die Adressleiste nennt stets das Fenster im Vordergrund. Öffnen Sie einen Workflow, wird die URL zum Link dieses Workflows; öffnen Sie eine Tabelle, wird sie zum Link der Tabelle. Dieser Link ist die Einheit, die Sie teilen.

**Um zu teilen, was Sie gerade ansehen**, kopieren Sie die URL aus der Adressleiste des Browsers und senden Sie sie. Jeder mit Zugriff auf dieses Projekt öffnet dieselbe Ansicht. Als Lesezeichen gespeichert, funktioniert sie auch später noch.

### Was passiert, wenn jemand den Link öffnet

Das Öffnen oder Aktualisieren eines Links stellt den **übergeordneten Kontext** wieder her, nicht nur das eine Fenster. Ein Link zu einem Workflow öffnet auch dessen Projekt, sodass Sie mit dem Projekt in der Registerkartenleiste ankommen statt mit einem einzelnen frei schwebenden Fenster – am selben Ort, den Sie auch durch eigene Navigation erreicht hätten.

### Linkformate

Links sind projektorientiert: Zuerst steht das Projekt, dann das Objekt darin, getrennt durch `~`.

```
#p~my-project                        a project
#p~my-project~w~<workflow>           a standard workflow
#p~my-project~c~<workflow>           a workflow in the Visual Workflow Designer
#p~my-project~w~<workflow>~s~<step>  a step within a workflow
#p~my-project~t~<table>              a table in the Table Explorer
#p~my-project~d~<dimension>          a dimension hierarchy
#p~my-project~e~<editor>             a Data Editor
#home                                the Home landing page
```

Hat ein Projekt einen Schemanamen, verwendet der Link ihn (oben `my-project`), was den Link lesbar und stabil macht. Andernfalls wird die Kennung des Projekts verwendet. Beide Formen öffnen dasselbe Projekt.

<Aside type="note">
Links, die vor dem projektorientierten Format erstellt wurden, funktionieren weiterhin. Ältere Links im Stil `?p=…&t=…` öffnen weiterhin die richtige Ansicht, und die Adressleiste stellt sich bei Ihrer ersten Navigation selbst auf das aktuelle Format um.
</Aside>

### Wenn ein Link nicht geöffnet werden kann

Wurde das Objekt in einem Link inzwischen gelöscht oder haben Sie keinen Zugriff auf sein Projekt, öffnet der Link die App ohne diese Ansicht, statt fehlzuschlagen. Wenn Sie ein Fenster schließen, dessen Link in der Adressleiste steht, setzt sich die URL auf das zugehörige Projekt zurück, sodass die Adressleiste nie auf etwas verweist, das nicht mehr geöffnet ist.
