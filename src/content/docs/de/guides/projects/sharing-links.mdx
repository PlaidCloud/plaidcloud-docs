PlaidCloud hält die Adressleiste im Einklang mit dem, was Sie geöffnet haben. Öffnen Sie einen Workflow, eine Tabelle, eine Dimension oder einen Bildschirm in Dashboards, Documents oder Identity, und die URL wird zu einem **Deeplink** darauf. Kopieren Sie diese URL und fügen Sie sie in eine Nachricht oder ein Ticket ein, und wer sie öffnet, landet auf demselben Bildschirm.

## Einen Link kopieren

1. Öffnen Sie den Bildschirm, den Sie teilen möchten: ein Projekt, einen Workflow, eine Tabelle, eine Dimension, einen Dateneditor oder einen Bildschirm in einer der anderen Apps.
2. Kopieren Sie die gesamte URL aus der Adressleiste Ihres Browsers.
3. Senden Sie sie weiter.

Es gibt keine eigene Schaltfläche zum Teilen: Die Adressleiste *ist* der Link. Auch die Lesezeichenfunktion Ihres Browsers funktioniert mit diesen URLs, sodass Sie einen Bildschirm, zu dem Sie häufig zurückkehren, wie jede andere Webseite als Lesezeichen speichern können.

<Aside type="note">
Ein Link enthält nur den *Ort*, nicht die Berechtigung, ihn zu sehen. Wer den Link öffnet, benötigt weiterhin Zugriff auf das Projekt. Wer ihn nicht hat, sieht das Objekt nicht.

Ein Link in eine App, die jemand nicht hat, weil sein Workspace sie nicht enthält oder sie ihm nicht gewährt wurde, führt zur Startseite mit dem Hinweis, dass der Link nicht verfügbar war, statt scheinbar nichts zu bewirken.
</Aside>

## Worauf Sie verlinken können

### Analyze

| Bildschirm | Link endet mit |
|---|---|
| Projekt | `#p~<project>` |
| Workflow (Raster der Schritte) | `#p~<project>~w~<workflow>` |
| Workflow (Arbeitsfläche des Visuellen Workflow-Designers) | `#p~<project>~c~<workflow>` |
| Ein Schritt innerhalb eines Workflows | `…~w~<workflow>~s~<step>` oder `…~c~<workflow>~s~<step>` |
| Ein einzelner Schritt | `#p~<project>~s~<step>` |
| Tabellen-Explorer | `#p~<project>~t~<table>` |
| Dimensionshierarchie | `#p~<project>~d~<dimension>` |
| Dateneditor | `#p~<project>~e~<editor>` |
| Startseite | `#home` |

Der Projektteil des Links ist das **Schema** Ihres Projekts, wenn es ein eigenes hat, sodass Links als `#p~acme_budget~w~…` statt als Folge von Hexadezimalzeichen erscheinen. Projekte mit dem Standardschema verwenden stattdessen die eigene Kennung des Projekts. Beide Formen öffnen dasselbe Projekt, sodass ein älterer Link auch nach dem Festlegen eines Schemas weiter funktioniert.

### Dashboards, Documents und Identity

Bildschirme in den anderen Apps werden direkt benannt, sodass ihre Links den Bildschirm selbst widerspiegeln:

| App | Bildschirm | Link |
|---|---|---|
| Dashboards | Meine Dashboards | `#dashboard.dashboards` |
| Dashboards | Apps | `#dashboard.panel_apps` |
| Dashboards | Jupyter Lite | `#dashboard.jupyterlite_deployments` |
| Documents | Alle Konten | `#document.accounts` |
| Documents | Freigegebene Konten | `#document.shared_accounts` |
| Documents | Private Konten | `#document.private_accounts` |
| Documents | Dateien eines Kontos durchsuchen | `#document.browser~…` |
| Identity | Mitglieder | `#identity.members` |
| Identity | Mitgliederverzeichnis | `#identity.member_directory` |
| Identity | Verteilerlisten | `#identity.distro.lists` |
| Identity | Sicherheitsgruppen | `#identity.security_groups` |
| Identity | Sicherheitsgruppen-Audit | `#identity.security_group_audit` |
| Identity | Scopes | `#identity.scopes` |
| Identity | Sitzungen | `#identity.sessions` |
| Identity | API-Clients | `#identity.api_client_list` |
| Identity | Sicherheitsprotokoll | `#identity.security_log` |

Manche Bildschirme merken sich eine Einstellung im Link: Die Listen Mitglieder und Mitgliederverzeichnis behalten jeweils, ob Sie **Alle**, **Nur aktive** oder **Nur inaktive** angesehen haben, und beim Durchsuchen eines Kontos bleibt das Konto erhalten. Ihr Browser zeigt das als codiertes Suffix nach dem Bildschirmnamen. Wenn Sie die gesamte URL kopieren und einfügen, öffnet sie den Bildschirm, auf dem Sie waren. Wird sie geöffnet, während dieser Bildschirm bereits geöffnet ist, wird dieses Fenster nach vorn geholt, statt ein zweites zu stapeln.

<Aside type="note">
Diese Links benennen den Bildschirm, nicht einen Datensatz darin. Ein Link zu Mitgliedern öffnet die Mitgliederliste, nicht das Formular eines einzelnen Mitglieds.
</Aside>

## Was passiert, wenn jemand einen Link öffnet

- **Das zugehörige Projekt wird ebenfalls geöffnet.** Ein Link zu einem Workflow, einer Tabelle, einem Schritt, einer Dimension oder einem Dateneditor öffnet auch das zugehörige Projekt als Registerkarte am unteren Bildschirmrand, sodass der Empfänger mit dem umgebenden Kontext ankommt und nicht mit einem einzelnen frei schwebenden Fenster.
- **Ein Schrittlink wählt den Schritt aus.** Ein Link zu einem Schritt innerhalb eines Workflows öffnet den Workflow und hebt diesen Schritt hervor. Auf der Arbeitsfläche des Visuellen Workflow-Designers wird der Knoten des Schritts ausgewählt.
- **Eine Dimension öffnet sich bearbeitbar**, wenn das Projekt entsperrt ist, und schreibgeschützt, wenn es gesperrt ist. Es gilt dieselbe Regel wie beim Öffnen aus dem Projekt.
- **Aktualisieren behält Ihre Position.** Das erneute Laden der Seite öffnet erneut, was der Link benennt, statt Sie an den Anfang zurückzuwerfen.

## Zwischen Bildschirmen wechseln

Die URL folgt dem, was Sie gerade ansehen:

- Das Öffnen eines Bildschirms aktualisiert die Adressleiste, und die Schaltfläche **Zurück** Ihres Browsers bringt Sie zum vorherigen.
- **Egal, wie Sie dorthin gelangt sind.** Wenn Sie einen Workflow aus dem Aktivitätsstrom, von einer Karte auf der Startseite, über eine Aktion **Zum Workflow wechseln**, aus einer Liste „Wo verwendet“ oder aus dem Protokoll öffnen, wird der Link genauso aktualisiert wie beim Öffnen aus der Workflow-Liste des Projekts, und ebenso beim erneuten Öffnen des Bildschirms, auf dem Sie sich bereits befinden.
- Wenn Sie die Registerkarte eines Fensters am unteren Bildschirmrand auswählen, steht der Link dieses Fensters wieder in der Adressleiste, sodass die URL beim Wechsel zwischen geöffneten Bildschirmen stimmt.
- Der Wechsel zu einer App, in der nichts Verlinkbares geöffnet ist, **leert** den Link, statt ihn auf die App zeigen zu lassen, die Sie gerade verlassen haben.
- Das Schließen eines Fensters setzt die URL auf die Stelle zurück, von der aus Sie es geöffnet haben. Schließen Sie eine Tabelle, die Sie von einer Workflow-Arbeitsfläche aus geöffnet haben, kehrt die URL zu dieser Arbeitsfläche zurück; schließen Sie eine aus einem Projekt geöffnete, kehrt sie zum Projekt zurück.
- Das Schließen des letzten Fensters eines Projekts leert den Link.

## Vor dieser Änderung gespeicherte Links

Links im älteren Stil `#te?p=…&t=…` funktionieren weiterhin. Das Öffnen eines solchen Links führt Sie an dieselbe Stelle und schreibt die Adressleiste unbemerkt in die aktuelle Form um. Wenn Sie ihn von dort erneut kopieren, erhalten Sie den neueren, besser lesbaren Link.
