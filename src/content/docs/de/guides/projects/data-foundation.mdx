**Data Foundation** ist das Finanzdatenfundament für Ihre PlaidCloud-Projekte. Sein **Common Finance Model** führt ERP-Daten aus mehreren ERP-Systemen und mehreren Instanzen jedes Systems in einem einzigen Modell zusammen: ein Kontenplan, ein Satz Entitäten und eine Berichtswährung. Berichte, Kennzahlen und KI-Assistenten, die auf dem Modell aufbauen, lesen alle dieselben Zahlen, aus welchem ERP sie auch stammen.

Ihr ERP wird über seine PlaidCloud-Verbindung angebunden, sodass Hauptbuch, Saldenliste, Stammdaten und Budgets direkt aus der Quelle eintreffen, ohne dass etwas exportiert werden muss. Dateien ergänzen Daten, die ein System nicht enthält, etwa Wechselkurse, Verteilungstreiber oder ein außerhalb des ERP geführtes Budget, und können die ERP-Zeilen ersetzen, die sie abdecken. **Laden** überführt jede Quelle in das Modell, rechnet sie in die Berichtswährung um und prüft, ob alles abgestimmt ist – alles auf der Registerkarte **Foundation** des Projekts. Wo Quellen denselben Code für verschiedene Dinge verwenden, legen Sie fest, ob sie dasselbe bedeuten, und eine Management-Konsolidierung erstellt die Konzern-Gewinn- und Verlustrechnung mit eliminierten Intercompany-Beträgen. Vorlagen wie **Enterprise Profitability** bauen ihre Berichte und Modelle darauf auf.

## ERP verbinden

Ihr ERP wird über seine PlaidCloud-Verbindung an Data Foundation angebunden. Data Foundation liest daraus Hauptbuch, Saldenliste, Stammdaten, Wechselkurse und Budgets direkt und liest dabei ausschließlich. Sie können eine bestehende Verbindung auswählen oder auf der Registerkarte eine neue erstellen; die [Verbindungsanleitungen](/de/guides/connections/) behandeln die Zugriffseinrichtung jedes ERP.

<Steps>

1. Öffnen Sie in Analyze **Projekte** und klicken Sie auf **Neues Projekt**. Geben Sie einen Namen ein und wählen Sie unter **Starten mit** eine Vorlage, etwa **Enterprise Profitability (Vorlage)**, statt **Leeres Projekt**. Klicken Sie auf **Erstellen**.

   Das Projekt öffnet sich auf seiner Registerkarte **Foundation**. Es ist privat für Sie, und Sie sind sein einziger Architect, bis Sie es freigeben.

2. Wählen Sie auf der Registerkarte **Foundation** eine bestehende Verbindung für Ihr ERP aus oder wählen Sie **Neue Verbindung erstellen**. Jede bestehende Verbindung listet die Workflows auf, die sie bereits verwenden, oder meldet **Noch von keinem Workflow verwendet**.

3. Geben Sie für eine neue Verbindung einen **Verbindungsname** ein, wählen Sie die **Umgebung** und füllen Sie die Zugangsdaten aus, die Ihre ERP-Verbindung verlangt.

   Haben Sie die Zugangsdaten noch nicht? Das Formular zeigt eine fertige Zugriffsanfrage für Ihren ERP-Administrator. Klicken Sie auf **Anfrage kopieren** oder **Anfrage per E-Mail senden**, versenden Sie sie und tragen Sie die Werte ein, die Sie zurückbekommen.

4. Klicken Sie auf **Verbindung testen**. PlaidCloud meldet sich an und versucht, jedes Dataset zu lesen, und listet dann jedes als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** auf. Fehlt etwas, nennt es die Berechtigungen, die Ihr ERP-Administrator hinzufügen soll.

5. Legen Sie **Monate Verlauf** fest: wie viele Monate rückwirkend geladen werden, von 1 bis 120. Standard sind 24.

6. Aktivieren Sie bei einer bestehenden Verbindung die zu ladenden Entitäten oder lassen Sie alle deaktiviert, um jede Entität zu laden. Inaktive Entitäten und Eliminierungsentitäten bleiben verborgen, bis Sie sie einblenden. Klicken Sie dann auf **Verbinden**.

7. Klicken Sie bei einer neuen Verbindung auf **Verbinden**, um sie zu erstellen. Aktivieren Sie dann die zu ladenden Entitäten und klicken Sie erneut auf **Verbinden**, um sie zu speichern. Solange Sie das nicht tun, wird jede Entität geladen.

8. Um ein weiteres ERP-System oder eine weitere Instanz einzubinden, wiederholen Sie diese Schritte und aktivieren Sie **Add this as another source instead of replacing the current one**, bevor Sie auf **Verbinden** klicken. Ohne diese Option ersetzt die neue Verbindung die aktuelle Quelle.

</Steps>

Nach dem Verbinden nennt die Karte, welche Verbindung, Umgebung, Entitäten und wie viele Monate Verlauf das Projekt lädt.

Jedes Laden liest nur, was sich geändert hat: Offene Perioden und die zuletzt abgeschlossene Periode werden erneut gelesen, bereits geladene abgeschlossene Perioden bleiben erhalten. Eine Erhöhung von **Monate Verlauf** liest nur die hinzugekommenen Monate. Ein geänderter Wechselkurs, eine geänderte Entitätszuordnung oder eine geänderte Berichtswährung liest die betroffenen Monate erneut.

## Quellen

Jedes ERP-System und jede Instanz, aus denen das Projekt lädt, ist eine Quelle. Die Liste **Quellen** auf der Registerkarte **Foundation** zeigt je eine Zeile pro Quelle, in Reihenfolge, mit ihrem Namen, dem Zeitpunkt des letzten Ladens, der Anzahl gelieferter Zeilen und den Berichtsbüchern, die sie liest, zum Beispiel `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Eine Quelle, die noch nicht geladen wurde, meldet **not loaded yet**. Dateien, die Sie bestätigen, sind ebenfalls Quellen.

Öffnen Sie **Erweitert** bei einer Quelle, um zu ändern, wie sie verwendet wird:

| Einstellung | Was sie bewirkt |
|---|---|
| **Name** | Die Bezeichnung, die Berichte, Zuordnungsfragen und Meldungen für die Quelle verwenden. |
| **Place in the order** | Der Rang der Quelle. Decken zwei Quellen denselben Monat desselben Unternehmens ab, gewinnt die in der Reihenfolge weiter oben stehende. |
| **Reporting books, separated by commas** | Die zu lesenden Buchhaltungsbücher, bei einem System, das mehr als eines führt. **All reporting books** liest jedes Buch. |
| **Unternehmen**, **Von (2026-01)** und **Bis (2026-12)** | Die Monate, die diese Quelle für jedes Unternehmen liefert. Lassen Sie einen Monat leer für keine Begrenzung. Schreiben Sie Monate als Jahr und Monat, zum Beispiel `2026-03`. |

Klicken Sie auf **Speichern**, um Ihre Änderungen zu behalten. Um eine Quelle zu entfernen, klicken Sie auf **Remove this source** und bestätigen Sie mit **Entfernen**. Alles, was daraus geladen wurde, wird gelöscht, und Sie können sie später erneut verbinden.

Das Ändern von Quellen liest Ihr ERP nicht erneut. Die Karte **Letzter Ladevorgang** meldet **Changes not applied yet**, bis Sie auf **Apply changes** klicken; das führt ein Laden aus den bereits abgerufenen Daten aus: Es überführt die Quellen mit Ihrer neuen Reihenfolge, Ihren Zuordnungen, Namen und Dateien erneut in das Modell und baut es neu auf. Klicken Sie auf **Laden**, wenn Sie zusätzlich frische Daten aus den ERPs möchten.

## Dateien für Daten außerhalb Ihres ERP hinzufügen

Dateien ergänzen Ihre ERP-Verbindung um Daten, die ein System nicht enthält, etwa Wechselkurse, Verteilungstreiber, eine [Entitätszuordnung](#entitätszuordnung) oder ein außerhalb des ERP geführtes Budget. Jede Datei gehört zu einem der Datasets, die unter [Tabellen des Common Finance Model](#tabellen-des-common-finance-model) aufgeführt sind.

<Steps>

1. Wählen Sie unter **Dateien** das **Dokumentenkonto**, in dem die Datei gespeichert wird.

2. Legen Sie eine CSV- oder Excel-Datei auf **CSV- oder Excel-Datei hier ablegen** ab oder klicken Sie auf **Datei auswählen**. Die Datei wird in den Ordner `/foundation/` des Dokumentenkontos hochgeladen.

   Geben Sie für eine Datei, die bereits im Dokumentenkonto liegt, deren **Dateipfad** ein, zum Beispiel `/foundation/budget.csv`, und klicken Sie auf **Datei hinzufügen**.

   Um jeden Monat eine neue Datei zu lesen, fügen Sie jede Datei in einem Ordner hinzu, deren Name passt: Geben Sie den Ordner ein und wählen Sie, ob **File names that** etwas enthalten, damit beginnen, darauf enden, genau übereinstimmen oder einem Muster entsprechen, und klicken Sie auf **Add files**. Dateien in Ordnern darin werden nicht gelesen.

3. PlaidCloud liest die Datei und schlägt eine Zuordnung vor:

   - **Erkanntes Trennzeichen, Dezimaltrennzeichen und Datumsangaben.** Das Trennzeichen (Komma, Semikolon, Tabulator oder senkrechter Strich), das Dezimaltrennzeichen und das Datumsformat werden für Sie erkannt.
   - **Dataset**: die Tabelle des Common Finance Model, zu der die Datei gehört, abgeleitet aus Dateiname und Spaltenüberschriften. Ist die Zuordnung nicht eindeutig, wählen Sie sie aus der Liste.
   - **Dezimaltrennzeichen**: **Punkt (1,234.56)** oder **Komma (1.234,56)**.
   - **Datumsformat**: wird angezeigt, wenn die Datei Datumsangaben enthält. Ändern Sie es, wenn das erkannte Format falsch ist: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` oder `MM/DD/YYYY`.
   - Ein Raster aus **Spalte in Datei**, **Typ**, **Beispiele** und **Geht nach**. Ändern Sie **Geht nach**, um eine Spalte einem anderen Feld zuzuweisen oder auf **Nicht laden** zu setzen.

4. Beantworten Sie die Fragen, die die Datei aufwirft, etwa **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** oder **Are revenues shown as negative numbers?** Jede wird nur gestellt, wenn die Datei die Antwort nicht schon enthält.

5. Prüfen Sie, wohin jede Spalte geht, und klicken Sie dann auf **Zuordnung bestätigen**.

</Steps>

Diese Optionen erscheinen bei einer Datei, wenn sie zutreffen:

| Option | Verwenden Sie sie, um |
|---|---|
| **Which source do these rows apply to?** | eine Codezuordnungsdatei auf eine Quelle zu beschränken. **Every source** wendet sie auf alle an. |
| **Where does this file come from?** | anzugeben, ob die Datei **This project's own codes** enthält oder aus einem **Another system** stammt, das Sie benennen, zum Beispiel `SAP Germany export`. Eine Datei aus einem anderen System wird wie eine ERP-Quelle auf gemeinsame Codes geprüft. |
| **Split … into … parts at each …** (unter **Erweitert**) | eine Spalte, die mehrere Werte enthält, etwa `100-200-300`, aufzuteilen und jeden Teil seinem eigenen Feld zuzuweisen. |
| **Which currency do you report in?** | die Berichtswährung festzulegen, wenn das Projekt noch keine hat. Schreiben Sie sie dreibuchstabig, zum Beispiel `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | die Ergebnisse Ihres Konsolidierungssystems zu laden, damit die Konzern-Gewinn- und Verlustrechnung [abgestimmt](#auf-ihr-konsolidierungssystem-abstimmen) werden kann. |

Um eine Datei aus dem Projekt zu nehmen, klicken Sie unter **Dateien** neben ihr auf **Entfernen** oder bei ihrer Zuordnung auf **Remove this file** und bestätigen Sie. Ihre Zahlen verschwinden aus Ihren Berichten, sobald Sie das nächste Mal auf **Apply changes** klicken.

Kann PlaidCloud das Dataset, das Dezimaltrennzeichen oder die Datumsreihenfolge nicht selbst entscheiden, zum Beispiel bei einer Datei, deren Datumsangaben als Tag/Monat oder Monat/Tag gelesen werden könnten, bittet es Sie vor dem Bestätigen um eine Auswahl. Das Hinzufügen einer zweiten Datei für dasselbe Dataset ersetzt die erste. Passen die Spalten einer späteren Datei nicht zum Dataset, nennt das Laden die Datei und die Spalten und fordert Sie auf, die Datei oder ihre Spaltennamen zu korrigieren oder das **Schema Mismatch** des Schritts auf `union` zu setzen.

Akzeptiert werden CSV-, TSV- und TXT-Textdateien, Excel-Dateien im Format `.xlsx` (gelesen wird das erste Blatt) und Parquet-Dateien.

<Aside type="note">
Eine fehlende oder leere Datei stoppt ein Laden nie. Beim Hinzufügen heißt es, dass noch nichts zuzuordnen ist, und ein Laden endet mit einer Warnung, die den Pfad nennt, und lässt dieses Dataset leer. Fügen Sie die Datei erneut hinzu, sobald sie existiert.
</Aside>

## Daten laden

Klicken Sie auf der Karte **Laden** oder der Karte **Letzter Ladevorgang** auf **Laden**. Das Laden liest Ihr verbundenes ERP und Ihre bestätigten Dateien, überführt sie in das Common Finance Model, rechnet sie in die Berichtswährung um, führt die Bereitschaftsprüfungen aus und baut die Modelle der Vorlage neu auf.

- Pro Projekt läuft jeweils nur ein Laden. Ein zweites **Laden** oder **Apply changes** meldet, dass bereits ein Laden läuft, und Quellen lassen sich nicht ändern, solange eines läuft.
- Verwenden andere Workflows dieselbe ERP-Verbindung, listet das erste Laden sie auf und bittet um Bestätigung, da ein Laden aus dem ERP liest und diese Workflows verlangsamen kann. Klicken Sie auf **Trotzdem laden**, um fortzufahren.
- Nach einem Upgrade von PlaidCloud aktualisiert das **Laden** eines Architect auch die generierten Workflows des Projekts und erstellt alle benötigten Arbeitstabellen. Bis dahin führt die Statusseite einen gelben Eintrag auf, „The workflows were generated by an earlier release. An Architect's Load updates them.“, und das **Laden** eines Managers warnt, dass nur ein Architect sie aktualisieren kann.
- Ein fehlgeschlagenes Laden wird rot angezeigt und versteckt sich nie hinter früheren Ergebnissen. Schlägt die Konsolidierung fehl, nennt der Status den Schritt, an dem sie gestoppt hat, statt alte Konzernergebnisse anzuzeigen. Zeilen aus einem früheren Laden zeigen **Aus einem früheren Ladevorgang. Erneut laden.**, bis ein Laden erfolgreich ist.
- Schlägt das Lesen einer Entität und Periode fehl, werden die übrigen trotzdem geladen. Führen Sie **Laden** erneut aus, um nur nachzuladen, was fehlgeschlagen ist.

### Zurückgehaltene Zeilen

Überschneiden sich Quellen, behält ein Laden von jeder Zahl eine Kopie und hält die anderen zurück, statt sie doppelt zu zählen. Zurückgehaltene Zeilen werden mit ihrer Quelle, ihrer Entität und dem Grund festgehalten, und das Laden endet mit einer Warnung, die die Anzahlen nennt, zum Beispiel `120 rows of NetSuite EU also provided by a source ranked ahead`. Die Gründe sind:

| Grund | Bedeutung |
|---|---|
| In einem anderen Buchhaltungsbuch | Die Zeile gehört zu einem Berichtsbuch, das die Quelle nicht lesen soll. |
| Außerhalb der Perioden, die die Quelle liefert | Die Zeile liegt außerhalb der für das Unternehmen festgelegten Monate **Von** und **Bis**. |
| Auch von einer höher eingestuften Quelle geliefert | Eine in der Reihenfolge höhere Quelle deckt dasselbe Unternehmen und denselben Monat ab. |
| Auch in einer früheren Datei der Quelle | Eine frühere Datei derselben Quelle deckt den Monat bereits ab. |
| Durch eine Datei ersetzt | Eine Datei ersetzt die ERP-Zeilen für diese Entität und diesen Monat. |
| Mit einem Code, den auch eine andere Quelle verwendet | Der Code braucht Ihre Antwort. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| Mit einem Code, der zwei Codes zugeordnet ist | Die Codezuordnung gibt dem Code zwei Antworten. |

Statistische Konten wandern zu den Verteilungstreibern statt ins Hauptbuch und erscheinen als verschoben, nicht als Problem.

### ERP-Daten und Dateien zusammen

Eine Datei ersetzt nur, was sie abdeckt, und die übrigen Zeilen aus Ihrem ERP bleiben bestehen.

- **Stammdatendateien** (Konten, Abteilungen, Kunden, Produkte und Segmentwerte) ersetzen die ERP-Zeilen mit demselben Code.
- **Bewegungsdatendateien** ersetzen die ERP-Zeilen für dieselbe Entität und denselben Monat. Hauptbuch- und Saldenlistendateien gleichen zusätzlich nach Buch ab, Budgetdateien nach Szenario und Dateien mit statistischen Treibern nach Szenario und Treiber.

Deckt eine Datei später einen Monat nicht mehr ab, kehren die ERP-Daten für diesen Monat beim nächsten Laden zurück.

## Entitätszuordnung

Jede Quelle benennt ihre Entitäten mit eigenen Codes. Die **Entitätszuordnung** ordnet diese Codes den Entitäten in Ihrem Entitätsstamm zu, sodass die Zeilen aller Quellen auf derselben Entität landen.

Um eine zu verwenden, fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Entitätszuordnung**:

| Spalte | Enthält |
|---|---|
| `source_entity` | Den Code, wie die Quelle ihn führt, etwa einen Unternehmenscode. |
| `entity` | Die Entität, zu der er gehört, wie der Entitätsstamm sie benennt. |

- Ein Code, der nicht in der Zuordnung steht, wird unverändert verwendet.
- Mehrere Codes können einer Entität zugeordnet sein. Ihre Zeilen werden zusammengeführt, und ein Monat gilt als abgeschlossen, sobald er für alle abgeschlossen ist.
- Die Codes der Zuordnung gelten für jede Quelle, daher müssen die Entitätscodes jeder Quelle über alle Quellen hinweg eindeutig sein.
- Eine Zeile einer **Entitäten**-Datei ersetzt die Entität des ERP mit demselben Entitätscode.

Die Prüfung **Nicht zugeordnete Entitäten** markiert jede Zeile, deren Entität weder im Entitätsstamm steht noch durch die Zuordnung einer zugeordnet wird. Solange kein Entitätsstamm geladen ist, zeigt sie **– Nicht zutreffend**.

## Codes quellenübergreifend zuordnen

Zwei Quellen können denselben Code für verschiedene Dinge oder verschiedene Codes für dasselbe verwenden. Erscheint ein Code in mehr als einer Quelle, hält Data Foundation seine Zeilen zurück, bis Sie sagen, ob er überall dasselbe bedeutet, damit jeder Betrag nur einmal gezählt wird. Die Prüfung **Codes waiting for your answer** listet sie auf, die ersten 10 und dann „and K more“, und die Karte **Was zu tun ist** auf der Registerkarte **Foundation** hat eine Schaltfläche **Prüfen**.

**Prüfen** öffnet **Codes waiting for your answer**. Es gruppiert die Codes danach, was sie sind: **Kontotypen**, **Unternehmen**, **Konten**, **Abteilungen**, **Profit-Center**, **Kunden**, **Produkte** und jede zusätzliche Kategorie. Für jeden Code zeigt es, wie jede Quelle ihn nennt, und einen Vorschlag:

- **Looks like the same thing**, wenn die Quellen dem Code denselben Namen geben.
- **Looks like different things**, wenn die Namen sich unterscheiden.
- **We can't tell. Please answer.**, wenn es keinen Anhaltspunkt gibt.

Beantworten Sie jeweils einen Code mit **Yes, the same** oder **No, different**, oder eine ganze Gruppe auf einmal mit **Accept all** (jeden Vorschlag übernehmen), **All the same** oder **All different**. Bei Konten können Sie auch eine ganze übergeordnete Gruppe des Kontenplans auf einmal beantworten. Wo eine Quelle keine Kontotypen mitliefert, wählen Sie für eine Gruppe von Konten **Use this type**: **Umsatz**, **Herstellkosten der verkauften Waren**, **Betriebsaufwand**, **Neutrale Erträge und Aufwendungen**, **Aktiva**, **Passiva** oder **Eigenkapital**.

Zuordnungen werden pro Quelle und Dimension gehalten, sodass eine Antwort für die Abteilungen einer Quelle nie die Konten einer anderen ändert. Antworten werden laufend gespeichert, mit **Saved. Press Apply changes to use your answers.** Klicken Sie auf **Apply changes**, um sie zu verwenden.

Sie können die Zuordnungen auch in einer Datei liefern. Fügen Sie eine Datei mit dem Dataset **Code map** hinzu und wählen Sie **Which source do these rows apply to?**, um sie auf eine Quelle zu beschränken.

## Wählen, welche Quelle ab wann zählt

Liefern zwei Quellen dieselben Monate, bittet die Prüfung **Which source covers which months** Sie um eine Auswahl. Klicken Sie in der Karte **Was zu tun ist** auf **Choose which source counts from when**, um **Which source counts from when** zu öffnen, das jede Überschneidung nach Unternehmen auflistet. Wählen Sie die Quelle, die zählt, geben Sie in **That month is** den Monat ein, ab dem sie zählt, zum Beispiel `2026-04`, und klicken Sie auf **Apply changes**. Die andere Quelle behält die früheren Monate.

Derselbe Dialog warnt, wenn zwei Quellen für eine Währung unterschiedliche Wechselkurse liefern; verwendet werden die Kurse der in der Reihenfolge höheren Quelle.

## Währungsumrechnung

Jedes Laden rechnet die Beträge von Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget aus ihrer Lokalwährung in eine Berichtswährung um. Berichte und Modelle lesen die umgerechneten Beträge, sodass Entitäten in verschiedenen Währungen aus beliebigen Systemen korrekt summiert werden.

### Die Berichtswährung

Um die Berichtswährung zu wählen, setzen Sie die Projektvariable `reporting_currency` auf einen Währungscode wie `USD`. Siehe [Projektvariablen verwalten](/de/guides/projects/managing-projects/#projektvariablen-verwalten). Die Vorlage legt sie leer an. Solange sie leer ist, verwendet jedes Laden die erste der folgenden Angaben, die genau eine Währung nennt:

1. Die Konzernwährung der Entitäten.
2. Die Lokalwährung der obersten Entitäten, also derer ohne übergeordnete Entität.
3. Die Lokalwährung der Dateien.

Nennt keine davon genau eine Währung, zeigt **Währungsumrechnung** ein Problem an, bis Sie `reporting_currency` festlegen.

Beträge, die bereits in der Berichtswährung vorliegen, bleiben unverändert, sodass ein Projekt, dessen Daten alle in einer Währung vorliegen, keine Kurse braucht.

Auch Umsatz-, Lagerbestands- und Budgetdateien können eine Währung enthalten. Ordnen Sie eine Spalte namens `Currency` oder `Local Currency` zu, und sie wird automatisch erkannt; die Lokalbeträge der Datei werden dann in die Berichtswährung umgerechnet. Ein Konzern- oder Berichtsbetrag, der bereits in der Datei steht, bleibt unverändert. Die Standardkosten eines Produkts werden nicht umgerechnet.

### Wechselkurse

Ein Kurs rechnet eine Einheit einer Währung für einen Monat in die Berichtswährung um: Der umgerechnete Betrag ist der Lokalbetrag mal dem Kurs.

- **Aus Ihrem ERP** liest jedes Laden die Wechselkurse, die das ERP führt.
- **Aus einer Datei**: Fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Wechselkurse**. Ein Kurs in der Datei ersetzt den Kurs des ERP für dieselben Währungen und denselben Monat. Verwenden Sie eine Datei, um in einer Währung zu berichten, für die Ihre ERPs keine Kurse veröffentlichen, oder um geplante Kurse für Budgetmonate zu ergänzen.

| Spalte | Enthält |
|---|---|
| `from_currency` | Die Währung, aus der umgerechnet wird, zum Beispiel `EUR`. |
| `to_currency` | Die Berichtswährung, zum Beispiel `USD`. |
| `period` | Den Monat im Format `YYYY-MM`. |
| `average_rate` | Den Durchschnittskurs des Monats. |
| `closing_rate` | Den Kurs am Monatsende. |
| `historical_rate` | Den historischen Kurs, für Eigenkapital und für Konten, die auf den historischen Kurs gesetzt sind. |

Verwendet werden nur Kurse in die Berichtswährung. Ein umgekehrt notierter Kurs, von der Berichtswährung in eine andere Währung, wird nicht invertiert.

### Welcher Kurs gilt

Jede Zeile wird aus ihrer eigenen Währung umgerechnet; eine Zeile in einer anderen Währung als ihre Entität wird also aus der Währung umgerechnet, in der sie vorliegt. Es gilt die erste Regel, die auf die Zeile passt:

| Zeile | Kurs |
|---|---|
| Statistische und nicht buchende Konten | Nicht umgerechnet. |
| Bereits in der Berichtswährung | Nicht umgerechnet. |
| Konto mit Kurstyp | Dieser Kurs: Durchschnitt, Stichtag oder historisch. Historisch fällt auf den Stichtagskurs zurück, wenn kein historischer Kurs vorliegt. Aus einem ERP ist der Kurstyp der eigene Kurstyp des Kontos. Ordnen Sie in einer Kontenplandatei eine Kurstyp-Spalte `fx_rate_type` mit `average`, `closing` oder `historical` zu. |
| Umsatzzeile | Der Durchschnittskurs der Periode. |
| Lagerbestand | Der Stichtagskurs der Periode. |
| Budgetzeile | Nach Konto wie im Hauptbuch: der Durchschnittskurs für GuV-Konten und der Stichtagskurs für Bilanzkonten. |
| GuV-Konto | Der Durchschnittskurs der Periode. |
| Eigenkapitalkonto | Der historische Kurs oder der Stichtagskurs, wenn kein historischer Kurs vorliegt. |
| Jedes andere Bilanzkonto | Der Stichtagskurs der Periode. |

Umgerechnete Beträge werden nicht gerundet, sodass die Summen nicht abdriften.

<Aside type="note">
Die Saldenliste enthält die Bewegungen jeder Periode; Bilanzbeträge sind also die Bewegungen jedes Monats, umgerechnet zum Stichtagskurs dieses Monats. Sie sind keine zum Periodenendkurs neu umgerechnete Bilanz, und es gibt weder eine kumulierte Umrechnungsanpassung noch eine Intercompany-Eliminierung. Verwenden Sie die umgerechneten Beträge für die Gewinn- und Verlustrechnung.
</Aside>

Jedes Laden baut die Dimensionen aus den Stammdaten jeder Quelle neu auf. Zu Beginn gibt es sieben Dimensionen und bis zu zehn zusätzliche Kategorien:

| Dimension | Aufgebaut aus |
|---|---|
| **Entität** | Entitäten und ihren übergeordneten Entitäten |
| **Konto** | Kontenplan und übergeordneten Konten |
| **Abteilung** | Abteilungen und ihren übergeordneten Abteilungen |

Geben Sie unter **Rename extra categories** die Namen ein, die Ihre Berichte verwenden, und klicken Sie auf **Save names**. Quellen, die eine Kategorie unterschiedlich nennen, etwa `Class` und `Business area`, teilen sich dann einen Platz.

Um Segmenthierarchien aus einer Datei zu liefern, wählen Sie das Dataset **Segmentwerte**:

| Spalte | Enthält |
|---|---|
| `segment` | Zu welchem Segment der Wert gehört: `segment_1` bis `segment_10`. |
| `segment_value` | Den Wert, wie ihn die Zeilen von Hauptbuch, Umsatz und Budget führen. |
| `segment_value_name` | Seinen Namen. |
| `parent_segment_value` | Sein übergeordnetes Element im selben Segment. |

## Bereitschaftsprüfungen

Nach jedem Laden listet das Raster **Bereitschaft** jede Prüfung für jede Entität und Periode auf, mit einem dieser Status:

| Status | Bedeutung |
|---|---|
| **● Bereit** | Die Prüfung wurde bestanden. |
| **▲ Aufmerksamkeit erforderlich** | Einen Blick wert, aber die Zahlen sind verwendbar. |
| **■ Problem** | Beheben Sie dies, bevor Sie sich auf die Ergebnisse verlassen. |
| **– Nicht zutreffend** | Für diese Prüfung liegen noch keine Daten vor. |

Die Prüfungen sind:

| Prüfung | Was sie bestätigt |
|---|---|
| **Daten geladen** | Jede Geschäftsperiode hat Hauptbuchzeilen, und jedes Lesen aus dem ERP war erfolgreich. Eine abgeschlossene Periode ohne Zeilen ist ein Problem; eine offene Periode ohne Zeilen erfordert Aufmerksamkeit. |
| **Saldenliste stimmt mit Hauptbuch überein** | Die Saldenliste entspricht dem Hauptbuch für jede Entität, Periode und jedes Konto. Führen sowohl die Saldenliste als auch das Hauptbuch für ein Konto Abteilungen, wird zusätzlich jede Abteilung abgestimmt. |
| **Umsatz stimmt mit Hauptbuch überein** | Die Umsatzzeilen entsprechen für jede Periode den Umsatz- und COGS-Konten des Hauptbuchs. |
| **Unbekannte Produkte/Kunden** | Jede Umsatzzeile nennt ein Produkt und einen Kunden, die in den Produkt- und Kundenstammdaten existieren. |
| **Konten fehlen im Kontenplan** | Jede Hauptbuchzeile nennt ein Konto im Kontenplan. Zeilen mit unbekanntem Konto bleiben in der Gewinn- und Verlustrechnung unberücksichtigt. Ein Konto mit Buchungen, aber ohne Kontotyp ist ebenfalls ein Problem, und eine Quelle, deren Kontenplan Umsatzkonten typisiert, aber kein Konto für Herstellkosten der verkauften Waren, erfordert Aufmerksamkeit. |
| **Währungsumrechnung** | Jede Zeile von Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget hat einen Betrag in der Berichtswährung. Eine GuV- oder Umsatzzeile ohne Kurs ist ein Problem, weil die Gewinn- und Verlustrechnung umgerechnete Beträge liest. Eine Bilanz-, Lagerbestands- oder Budgetzeile ohne Kurs erfordert Aufmerksamkeit. Ein Budgetmonat ohne Kurs erscheint gelb, laden Sie daher geplante Kurse für Budgetmonate. Siehe [Währungsumrechnung](#währungsumrechnung). |
| **Nicht zugeordnete Entitäten** | Jede Zeile von Hauptbuch, Saldenliste und Umsatz nennt eine Entität im Entitätsstamm, direkt oder über die Entitätszuordnung. Nicht zutreffend, bis ein Entitätsstamm geladen ist. Siehe [Entitätszuordnung](#entitätszuordnung). |

Laden mit mehr als einer Quelle fügen diese Prüfungen hinzu:

| Prüfung | Was sie bestätigt |
|---|---|
| **Reporting book** | Für eine Quelle, die mehrere Buchhaltungsbücher je Entität führt, wurde das Berichtsbuch gewählt. Bis Sie wählen, zählt nur das erste Buch. |
| **Codes waiting for your answer** | Jeder Code, den mehr als eine Quelle verwendet, wurde beantwortet. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| **Extra categories from your sources** | Jede zusätzliche Kategorie, die eine Quelle führt, hat einen Namen oder wurde ausgelassen. |
| **Which source covers which months** | Keine zwei Quellen liefern dieselben Monate eines Unternehmens, es sei denn, Sie haben gewählt, welche zählt. |
| **Account types and hierarchy** | Jedes übergeordnete Element, das eine Dimension nennt, existiert, und kein Mitglied ist sein eigenes übergeordnetes Element oder Vorfahre. Ein fehlendes übergeordnetes Element setzt seine untergeordneten an die Spitze der Hierarchie, und eine Schleife verhindert das Laden dieser Hierarchie. Die Summen sind nicht betroffen. |
| **Geschäftskalender** | Die Geschäftsperioden jeder Entität sind Kalendermonate, und jeder Monat an Zeilen lässt sich in genau einer Geschäftsperiode platzieren. Aufmerksamkeit ist erforderlich, wenn die Perioden einer Entität keine Kalendermonate sind (4-4-5, 13 Perioden) oder wenn die Zeilen eines Monats in mehr als eine Geschäftsperiode fallen könnten oder dem Geschäftskalender der Monat fehlt. |

Jede Zeile, die nicht bereit ist, sagt in der Spalte **Was zu tun ist**, was zu tun ist, etwa den Kontenplan zu laden, Wechselkurse zu laden oder **Laden** für eine Periode erneut auszuführen.

Das Raster zeigt außerdem zwei Einrichtungsprüfungen, die nur erscheinen, wenn sie Aufmerksamkeit erfordern:

| Prüfung | Wann sie erscheint |
|---|---|
| **Gemeinkostenumlage** | Nur eine der Projektvariablen `overhead_department` und `overhead_driver` ist gesetzt, oder kein Verteilungstreiber passt zu `overhead_driver`, sodass die Umlage nichts bewirken würde. Setzen Sie beide oder leeren Sie beide, um die Gemeinkostenumlage auszuschalten. |
| **Budgetvergleich** | Budgetzeilen sind geladen, aber keine liegt in der Version, die die Projektvariable `budget_version` nennt, sodass der Budgetvergleich leer wäre. |

## Management-Konsolidierung

Jedes Laden erstellt eine Management-Konsolidierung: die Konzern-Gewinn- und Verlustrechnung jeder Entität im Konzern, in der Berichtswährung, mit eliminierten Intercompany-Beträgen. Sie dient dem Management-Reporting. Ihr Konsolidierungssystem bleibt die maßgebliche Aufzeichnung für den gesetzlichen Konzern; stimmen Sie darauf ab, wie unten beschrieben.

<Aside type="note">
Die Management-Konsolidierung umfasst nur die Gewinn- und Verlustrechnung. Sie ist keine gesetzliche oder rechtliche Konsolidierung und hat weder eine konsolidierte Bilanz noch eine Umrechnungsanpassung, einen Geschäfts- oder Firmenwert oder Anteile Dritter.
</Aside>

### Den Konzern wählen

Öffnen Sie unter **Quellen** die Option **Gruppe**, um die Unternehmen im Konzern zu sehen. Ein Unternehmen, dessen Auswahl Sie aufheben, bleibt für sich in Ihren Berichten, wird aber aus der Konzernsumme ausgelassen. Klicken Sie auf **Save group**. Die Änderung gilt ab dem nächsten **Laden** oder **Apply changes**. Ein neues Unternehmen gehört zum Konzern, bis Sie seine Auswahl aufheben.

Das Geschäftsjahr des Konzerns beginnt in dem Monat, den die Projektvariable `group_fy_start_month` festlegt; das ist `1`, sofern Sie es nicht ändern.

### Was Sie erhalten

| Tabelle | Enthält |
|---|---|
| **Group P&L** | Eine Zeile je Entität, Periode und Zeile (Umsatz, Herstellkosten der verkauften Waren, Betriebsaufwand, nicht operativ, Intercompany-Differenz), in der Berichtswährung. Umsatz und Kosten tragen ihr natürliches Vorzeichen. |
| **Group P&L year to date** | Dasselbe, kumuliert, bis zur letzten vollständig geladenen Periode des Konzerns. |
| **Intercompany pairs** | Eine Zeile je Paar aus Entitäten, Konzern und Periode, mit dem Betrag jeder Seite und dem Rest. |
| **Intercompany lines** | Die Hauptbuchzeilen hinter einer Konzernzahl oder einem Paar, mit dem Handelspartner. |
| **Abstimmung** | Die kumulierte Konzern-GuV gegenüber Ihrem Konsolidierungssystem. |

In diesen Tabellen erscheinen drei Entitätsnamen:

| Entität | Bedeutung |
|---|---|
| **Eliminations** | Die Intercompany-Eliminierungen. Sie saldieren sich zu null, belassen Sie sie daher für die Konzernzahlen und filtern Sie sie für die Summe der Entitäten vor der Eliminierung heraus. |
| **Group total** | Die Summe des Konsolidierungssystems, in der Abstimmung. |
| **Unmapped** | Zeilen ohne Periode sowie Konten oder Entitäten Ihres Konsolidierungssystems, die dieses Projekt nicht hat. |

Die Kennzahlen **Consolidated income**, **Consolidated result** und **IC difference** sowie ein Analysepfad für jede Tabelle beantworten Fragen zum Konzern.

### Intercompany-Eliminierungen

Intercompany-Zeilen werden nach Handelspartner abgeglichen. Verwendet wird der Partner der Zeile; hat eine Zeile keinen, ist es der Partner ihres Kunden. Beide Seiten eines Paares werden eliminiert, und der Betrag, um den die beiden Seiten nicht übereinstimmen, wird auf eine Intercompany-Differenzzeile gebucht. Jedes Paar erhält einen Grund:

| Grund | Bedeutung |
|---|---|
| **Abgeglichen** | Beide Seiten haben denselben Betrag gebucht. |
| **Only one side booked** | Eine Entität hat die Transaktion gebucht und ihr Partner nicht. |
| **Not eliminated** | Eine Zeile des Paares hat keinen Wechselkurs, daher wird keine Seite eliminiert. |

Ein Paar wird anhand seines kumulierten Stands beurteilt. Die Zeile **Intercompany balances** wird gelb, wenn die Differenz eines Paares über der Projektvariablen `group_amber` liegt (Standard `1`), und rot über `group_red` (Standard `1000`). Zeilen ohne Partner oder mit einem Partner, der keine Entität ist, werden nicht eliminiert und in dieser Zeile gezählt. Eine Quelle, die Partner führt, neben einer, die das nicht tut, erscheint gelb.

Die eigenen Eliminierungsentitäten einer Quelle bleiben aus der Konzern-GuV heraus, und die Zeile **Konsolidierung** sagt das.

### Auf Ihr Konsolidierungssystem abstimmen

Fügen Sie die Ergebnisse, die Ihr Konsolidierungssystem berichtet, als Datei hinzu und aktivieren Sie **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)**, wenn Sie ihre Zuordnung bestätigen. Beantworten Sie **Which version of the numbers is this?** mit dem Namen des Systems. Die Tabelle **Abstimmung** zeigt dann **ours**, **reported** und **Differenz** für jede Entität und Zeile, kumuliert. Eine Differenz erklärt sich meist in den Zeilen **Eliminations**, **Group total** und **Unmapped** oder durch die Wechselkurse, die das System verwendet. Die Zeile **Reconciliation to the source** listet jede Zeile über `group_amber` auf.

### Wer es sehen kann

Konzernergebnisse folgen dem Zeilenzugriff des Projekts. Wenn der Zeilenzugriff die Konzernergebnisse stoppt, ist der Status gelb. Wer nur einige Entitäten sieht, sieht die Summen dieser Entitäten vor der Eliminierung. Die Zeilen **Eliminations** und die Intercompany-Tabellen erfordern Zugriff auf jede Entität.

Beschränkt das Projekt, wer welche Zeilen sieht, anhand einer Spalte, die die Konzerntabellen nicht führen, etwa der Abteilung, bleiben die Konzernergebnisse für alle ausgeschaltet, und **Konsolidierung** meldet **Group views are off**. Nur ein Architect kann dann unter **Gruppe** die Option **Everyone on the project may see the group results** aktivieren. Die Änderung gilt ab dem nächsten **Laden** oder **Apply changes**.

## Aktuell halten

Nachdem ein Laden aus Ihrer ERP-Verbindung ohne Probleme erfolgreich war, erscheint auf der Karte **Letzter Ladevorgang** die Option **Nächtlich aktualisieren**. Klicken Sie darauf, um **Laden** jede Nacht um 2:00 Uhr in Ihrer Zeitzone auszuführen. Die Karte zeigt dann **Nightly refresh: Every night at 2:00** und wer es eingerichtet hat.

Das nächtliche Laden läuft als die Person, die es eingerichtet hat. Kann diese Person die ERP-Verbindung nicht mehr verwenden, meldet das Raster, dass das nächtliche Laden übersprungen wird; richten Sie es erneut ein. Ein Projekt, das nur Beispieldaten hat, lässt sich nicht planen.

Eine Datei, die bei einem nächtlichen Laden fehlt oder leer ist, führt zu einer Warnung, die den Pfad nennt, nicht zu einem Fehler, und der Rest des Modells wird weiter geladen.

## Geschäftsbezeichnungen

**Business names** auf der Registerkarte **Foundation** geben den Codes in Ihrem Modell die Namen, die Ihr Unternehmen verwendet. Berichte, Kennzahlen und der Assistent zeigen diese Namen an, und ein gespeicherter Name gilt sofort. Spätere Ladevorgänge behalten ihn bei.

1. Klicken Sie auf **Add a name** und wählen Sie die **Art**: **Kategorie**, **GuV-Zeile**, **Kennzahl** oder **Spalte**.
2. Geben Sie den **Code** ein: `segment_1` bis `segment_10` für eine Kategorie, den Schlüssel der Zeile für eine GuV-Zeile, den Namen der Kennzahl oder `table.column` für eine Spalte.
3. Geben Sie den **Name** ein, höchstens 60 Zeichen in einer Zeile.
4. Klicken Sie auf **Save names**.

Das Speichern ersetzt die gesamte Liste. Eine Zeile mit leerem Namen entfernt diesen Namen, und **Ausgewählte entfernen** entfernt die Zeilen, die Sie aktiviert haben. Denselben Code zweimal zu benennen wird abgelehnt. Geschäftsbezeichnungen werden auch in die Beschreibung des Analysepfads geschrieben, damit der Assistent Ihre Begriffe verwendet, und diese Beschreibung hat eine Längenbegrenzung: Würde ein Name sie zu lang machen, wird nichts gespeichert, und Sie werden informiert.

## Eine Zahl erklären

**Explain this number** zeigt, woraus sich eine Zahl der Gewinn- und Verlustrechnung zusammensetzt. Im Raster **Bereitschaft** hat eine Zeile für eine Entität und einen Monat **Explain this number**, das die operative Marge der Entität für diesen Monat öffnet. Das Fenster teilt die Zahl in Ebenen auf, die sich zur Gesamtsumme oben addieren:

| Ebene | Was sie enthält |
|---|---|
| **From the general ledger** | Was das Hauptbuch auf die Zeile gebucht hat. |
| **Allocated in** | Kosten, die Ihre [Umlageregeln](#umlageregeln) auf diese Entität verteilt haben. |
| **Allocated out** | Kosten, die diese Entität auf andere verteilt hat. |
| **Eliminated in the group** | Intercompany, das im Konzernergebnis eliminiert wurde. |

Jede Ebene hat einen Satz, der sagt, was sie ist, und ihre größten Quellbelege, mit Quellsystem, Beleg und Konto. Nur Ebenen mit Zeilen werden angezeigt. Das Fenster folgt Ihrem Zeilenzugriff: Sie erklären nur die Zahlen, die Sie sehen können. Eine Zahl ohne Grundlage meldet **Nothing to explain**.

## Umlageregeln

Umlagen verteilen gemeinsame Kosten, etwa Gemeinkosten, auf Abteilungen, Produkte und Kunden. Das Modell hat zwei Stufen: **Stage 1: overhead to departments** und **Stage 2: departments to products and customers**. Öffnen Sie **Aktionen > Umlagen...**, um zu sehen oder zu ändern, wie jede ausgeführt wird. Ohne Änderungen arbeiten sie wie vor der Einführung des Assistenten. Ein Leser kann die Regeln öffnen, aber nicht speichern.

Für jede Stufe stellt der Assistent vier Fragen:

| Schritt | Frage | Auswahl |
|---|---|---|
| **Pool** | Welche Kosten möchten Sie verteilen? | Die Art des Kontos und, für Stufe 1, die Abteilung, die die Kosten trägt, oder **All departments**. |
| **Treiber** | Wonach möchten Sie sie verteilen? | **Statistic**, die Sie als Verteilungstreiber geladen haben, etwa Mitarbeiterzahl oder Quadratmeter, **Net sales amount**, **Sales quantity** oder **Spread evenly**. Verwenden Sie den Treiber von **Same period** oder **Same period last year**. |
| **Ziel** | Wohin gelangen sie? | Stufe 1: Abteilungen. Stufe 2: Produkte, Kunden oder beides. |
| **Methode** | Was geschieht, wenn ein Treiber negativ ist? | **Ignore negative values** oder **Stop and tell me**. |

Unter den Schritten zeigt **Preview for** einen Monat, geschrieben als Jahr und Monat wie `2026-09`, was die Regeln – auch noch nicht gespeicherte – bewirken würden: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Alles Nicht-Umgelegte sind Kosten, für die kein Treiber vorhanden war. Die Vorschau folgt Ihrem Zeilenzugriff.

Klicken Sie auf **Speichern**. Die Regeln gelten ab dem nächsten **Laden** oder wenn Sie auf **Apply changes** klicken. Haben Sie einen Umlageschritt von Hand bearbeitet, bleibt Ihre Änderung erhalten und wird nicht überschrieben, und das Speichern nennt ihn. Während ein Laden läuft, können Sie nicht speichern.

## Board Pack

Ein Board Pack schreibt Ihre Ergebnisse nach Zeitplan in einen Ordner eines Dokumentenkontos, versandfertig. Öffnen Sie **Aktionen > Board pack...**, wählen Sie ein **Dokumentenkonto** und einen **Ordner**, etwa `/board-packs`, und klicken Sie auf **Speichern**. Jede Ausführung schreibt:

- Eine Excel-Arbeitsmappe, `Board pack.xlsx`, mit der Gewinn- und Verlustrechnung nach Entität, einer Margenbrücke sowie den besten und schlechtesten Kunden.
- Ein PDF des Dashboards der Gewinn- und Verlustrechnung.

Hat das Projekt noch kein Dashboard, wird nur die Arbeitsmappe geschrieben, und die Ausführung sagt, warum. Klicken Sie auf **Run now**, um sofort ein Pack zu erstellen; seine Dateien erscheinen im Ordner, sobald es fertig ist. Die Karte zeigt die letzte Ausführung und ihr Ergebnis sowie die nächste Ausführung. Das Pack läuft mit der nächtlichen Aktualisierung, sobald diese eingerichtet ist. Nur wer das Projekt ändern kann, richtet es ein.

## Wiederherstellungspunkte

Vor jedem Laden und vor jeder Änderung an Zuordnungen oder Quellen wird ein Wiederherstellungspunkt erstellt. Er enthält die Tabellen des Modells, die Dimensionen und die Einstellungen, aus denen das nächste Laden aufbaut: Ihre Quellen, Dateien und Umlageregeln. Neuere Punkte werden behalten, ältere fallen heraus, und Änderungen verdrängen nie die vor dem Laden erstellten Punkte.

Um zurückzugehen, öffnen Sie **Aktionen > Wiederherstellen...**, wählen Sie einen Punkt und klicken Sie auf **Wiederherstellen**. **Wiederherstellen** wird angeboten, sobald ein Punkt existiert. Das Wiederherstellen setzt die Tabellen, die Dimensionen und diese Einstellungen so zurück, wie sie waren, und das nächste Laden baut daraus auf. Eine Tabelle ohne gespeicherte Kopie oder eine Engine, die keinen Verlauf halten kann, wird in einer Warnung genannt, und der Rest wird wiederhergestellt. Ein Wiederherstellungspunkt, der herausgefallen ist, wird abgelehnt, und während ein Laden läuft, können Sie nicht wiederherstellen.

## Ein Projekt klonen

**Aktionen > Klonen...** kopiert das Projekt unter einem Namen, den Sie angeben. Die Kopie behält die Vorlage, Ihre Änderungen am Modell sowie Ihre Kennzahlen und Analysepfade und lädt die Beispieldaten. Ihre Quellen sind nicht verbunden, verbinden Sie sie daher in der Kopie, bevor Sie laden. Sie können weiterarbeiten, während die Kopie erstellt wird, und **Projekt öffnen** bringt Sie dorthin, sobald sie fertig ist.

## Als meine Vorlage speichern

Speichern Sie die Einrichtung eines Projekts, um sie für den nächsten Kunden oder die nächste Entität wiederzuverwenden. Öffnen Sie **Aktionen > Save as my template...**, wählen Sie das Dokumentenkonto und benennen Sie die Datei. Ein Name mit der Endung `.zip` wird ergänzt, wenn Sie sie weglassen. Das Überschreiben einer bestehenden Datei wird abgelehnt, wählen Sie daher einen anderen Namen.

Die Datei enthält die Struktur des Projekts, Ihre Änderungen am Modell, Kennzahlen und Analysepfade, die Geschäftsbezeichnungen für Entitäten und Konten sowie die Zeilen der Konfigurationstabellen der Vorlage, etwa die Aktivitätszuordnung von [Cost to Serve](/de/guides/projects/cost-to-serve/) oder die Richtwertbereiche von [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/). Nicht enthalten sind Verbindungen, Dateien, der nächtliche Zeitplan, Ausführungen, Wiederherstellungspunkte, das Board Pack und wer Zugriff hat.

Um sie zu verwenden, erstellen Sie ein Projekt, wählen Sie unter **Starten mit** die Option **From a template file...** und geben Sie Dokumentenkonto und Pfad an. Das neue Projekt ist privat für Sie, und jede Quelle wartet darauf, verbunden zu werden. Ein späteres Release der Vorlage führt seine Änderungen um die von Ihnen bearbeiteten Schritte herum zusammen. Gibt es unter dem Pfad keine Datei, wird nichts erstellt, und Sie werden informiert. Jeder, der das Dokumentenkonto lesen kann, kann aus der Datei installieren. Um sie in einem anderen Workspace zu verwenden, laden Sie die Datei herunter und dort hoch.

## Offene Fragen mit Ask klären

Nach einem Laden kann ein Projekt noch auf Antworten zu drei Dingen warten: Konten, für die der Kontenplan keinen Typ angibt, Codes, die mehr als eine Quelle verwendet, und Spalten Ihrer Dateien, die nichts getroffen haben. Bitten Sie den Assistenten, sie zu klären: Verwenden Sie in einem KI-Assistenten über MCP den Prompt **Resolve Data Foundation residue**. Er liest, was aussteht, und schlägt für jeden Eintrag eine Antwort mit Begründung vor.

Der Assistent schreibt nichts. Sie übernehmen seine Antworten dort, wo Sie selbst geantwortet hätten: Konten und Codes unter **Codes waiting for your answer** und Dateispalten in der Zuordnung der Datei. Er schlägt nie eine Entität vor.

## Das Projekt übergeben

Die Checkliste **Einrichtung** hat nach **Hierarchien prüfen** vier abschließende Punkte:

- **Set up the nightly refresh** ist erledigt, sobald **Nächtlich aktualisieren** eingeschaltet ist.
- **Mit Ihrem Team teilen** ist erledigt, sobald außer der Person, die das Projekt eingerichtet hat, jemand Mitglied ist.
- **Download the evidence pack** ist erledigt, wenn Sie das Paket nach dem letzten erfolgreichen Laden herunterladen.
- **Hand the project over to its owner** ist erledigt, sobald es einen Architect gibt, der nicht die Person ist, die es eingerichtet hat, und die Summen übereinstimmen. Solange das nicht der Fall ist, sagt die Checkliste, was zu tun ist: den Eigentümer des Kunden zum Architect dieses Projekts machen und sich dann aus seinen Mitgliedern entfernen.

Die Checkliste nennt, wer das Projekt eingerichtet hat (**Set up by**).

## Mit einer Vorlage auf dem Modell aufbauen

Eine Vorlage baut ihre Berichte und Modelle auf dem Common Finance Model auf, sodass sie gleich funktionieren, welche ERPs es auch speisen. Wenn Sie ein Projekt aus einer Vorlage starten, etwa **Enterprise Profitability**, erstellt sie:

- Die [Tabellen des Common Finance Model](#tabellen-des-common-finance-model), leer oder mit Beispieldaten gefüllt.
- Die Dimensionen **Entität**, **Konto**, **Abteilung**, **Kunde**, **Produkt**, **Segment 1** und **Segment 2**, aufgebaut aus diesen Tabellen. Siehe [Hierarchien](#hierarchien).
- Den Workflow **Laden** und die Workflows, die er ausführt, um Ihr ERP und Ihre Dateien zu lesen, sie zu überführen, die Bereitschaft zu prüfen und die Modelle der Vorlage aufzubauen.
- Die eigenen Berichte und Modelle der Vorlage. **Enterprise Profitability** ergänzt eine Tabelle der Gewinn- und Verlustrechnung mit Umsatz, COGS, Bruttomarge, direktem und Gemeinkosten-Betriebsaufwand, Deckungsbeitrag und operativer Marge sowie Margenbrücken im Jahresvergleich und gegenüber dem Budget.
- Kennzahlen und einen Analysepfad, um Fragen zu den Ergebnissen zu stellen.

Unter **Starten mit** stehen drei Vorlagen zur Verfügung, die jeweils auf demselben Modell aufbauen:

| Vorlage | Ergänzt |
|---|---|
| **Enterprise Profitability** | Die Gewinn- und Verlustrechnung und Margenbrücken. |
| **Cost to Serve** | Die Kosten der Betreuung jedes Kunden und die Marge danach. Siehe [Cost to Serve](/de/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | Das Gewinnniveau jeder Entität gegenüber Ihrem Richtwertbereich und die Ausgleichszahlung. Siehe [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/). |

**From a template file...** startet aus einem Projekt, das Sie gespeichert haben. Siehe [Als meine Vorlage speichern](#als-meine-vorlage-speichern).

Um sich umzusehen, bevor Sie Ihr eigenes ERP verbinden, aktivieren Sie beim Erstellen des Projekts **Mit Beispieldaten starten**. Das Projekt führt sofort ein erstes Laden aus, sodass die Registerkarte **Foundation** ein vollständiges Beispiel zeigt, einschließlich einer Euro-Entität, die in US-Dollar umgerechnet wird. Wenn Sie Ihr eigenes ERP verbinden oder eigene Dateien hinzufügen, werden die Beispielzeilen gelöscht und Ihre Daten treten an ihre Stelle.

## Die Registerkarte Foundation

Auf der Registerkarte **Foundation** verbinden, laden und prüfen Sie Ihre Daten. Sie hat diese Abschnitte, von oben nach unten:

| Abschnitt | Was er zeigt |
|---|---|
| **Letzter Ladevorgang** | Ob das letzte Laden erfolgreich war, fehlgeschlagen ist oder noch läuft, mit den Schaltflächen **Laden**, **Apply changes**, **Aktualisieren** und **Nächtlich aktualisieren**. |
| **Was zu tun ist** | Was Ihre Aufmerksamkeit braucht, das Wichtigste zuerst, jeweils mit einer Schaltfläche **Prüfen** oder **Choose which source counts from when**. |
| **Quellen** | Jede Quelle in Reihenfolge, mit **Erweitert**, **Remove this source**, **Gruppe** und **Rename extra categories**. |
| **Einrichtung** | Die Einrichtungs-Checkliste: **Daten verbinden**, **Daten laden**, **Prüfen, ob die Summen übereinstimmen**, **Hierarchien prüfen**, **Set up the nightly refresh**, **Mit Ihrem Team teilen**, **Download the evidence pack** und **Hand the project over to its owner**. Der aktuelle Punkt ist fett. |
| **Business names** | Die Namen, die Ihr Unternehmen für Kategorien, GuV-Zeilen, Kennzahlen und Spalten verwendet. Siehe [Geschäftsbezeichnungen](#geschäftsbezeichnungen). |
| **Dateien** | Jede hinzugefügte Datei, ihr Dataset, etwa **Hauptbuch** oder **Wechselkurse**, und ob ihre Zuordnung **✓ Bestätigt** oder **○ Wartet auf Bestätigung** ist. |
| **Daten geladen** | Für jede Entität die erste und die letzte geladene Periode und wie viele Perioden bereit sind. |
| **Perioden** | Die Geschäftsperioden jeder Entität und ob jede **✓ Geschlossen** oder **○ Offen** ist. |
| **Bereitschaft** | Das Bereitschaftsraster: eine Zeile je Entität, Periode und Prüfung, mit ihrem Status und **Was zu tun ist**. |
| Verbindung | Verbinden Sie Ihr ERP, wählen Sie die Entitäten und wie viele Monate Verlauf geladen werden, oder fügen Sie eine weitere Quelle hinzu. |
| **Dateien** (hinzufügen) | Fügen Sie eine CSV-, TSV-, TXT-, Excel- oder Parquet-Datei hinzu und bestätigen Sie, wie ihre Spalten zugeordnet werden. |
| **Laden** | Starten Sie ein Laden. **Apply changes** führt eines aus, ohne aus den ERPs zu laden. |

Während ein Laden läuft, aktualisiert sich die Registerkarte von selbst.

Die Einrichtungs-Checkliste verfolgt Ihren Fortschritt:

- **Daten verbinden** und **Daten laden** haken sich selbst ab, sobald eine Quelle angehängt und ein Laden erfolgreich ist.
- **Prüfen, ob die Summen übereinstimmen** hakt sich selbst ab, wenn die Abstimmungsprüfungen bestanden sind.
- **Hierarchien prüfen**: Klicken Sie auf **Dimensionen öffnen**, um die Hierarchien für Entität, Konto und Abteilung zu prüfen, und aktivieren Sie dann **Ich habe sie geprüft**. **Diese bestätigen Sie selbst**.
- **Set up the nightly refresh**, **Mit Ihrem Team teilen**, **Download the evidence pack** und **Hand the project over to its owner** schließen die Liste ab. Siehe [Das Projekt übergeben](#das-projekt-übergeben) und [Projektzugriff verwalten](/de/guides/projects/managing-projects/#projektzugriff-verwalten).

Das Menü **Aktionen** enthält **Umlagen...**, **Board pack...**, **Klonen...**, **Wiederherstellen...** und **Save as my template...**. Siehe [Umlageregeln](#umlageregeln), [Board Pack](#board-pack), [Ein Projekt klonen](#ein-projekt-klonen), [Wiederherstellungspunkte](#wiederherstellungspunkte) und [Als meine Vorlage speichern](#als-meine-vorlage-speichern).

## Tabellen des Common Finance Model

Data Foundation überführt jede Quelle, ERP oder Datei, in dieselben fünfzehn Tabellen, sodass darauf aufgebaute Berichte, Kennzahlen und Modelle unabhängig von der Quelle gleich funktionieren. Jede Zeile hält außerdem ihr Quellsystem fest und wann sie gelesen wurde. Die Spalte **Dataset** ist der Name, den Sie beim Hinzufügen einer Datei wählen.

| Dataset | Tabelle | Enthält |
|---|---|---|
| Entitäten | `cfm_entity` | Juristische Personen mit übergeordneter Entität, Lokal- und Konzernwährung und Land. |
| Entitätszuordnung | `cfm_entity_map` | Entitätscodes der Quelle und die Entität, zu der jeder gehört. Siehe [Entitätszuordnung](#entitätszuordnung). |
| Wechselkurse | `cfm_fx_rate` | Monatliche Durchschnitts-, Stichtags- und historische Kurse je Währungspaar. Siehe [Wechselkurse](#wechselkurse). |
| Geschäftskalender | `cfm_fiscal_calendar` | Eine Zeile je Geschäftsperiode einer Entität, mit Start- und Enddatum und ob sie abgeschlossen ist. |
| Kontenplan | `cfm_account` | Konten mit übergeordnetem Konto, Typ (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), Abschluss, Normalsaldo und Kurstyp. |
| Abteilungen | `cfm_department` | Abteilungen und Kostenstellen mit übergeordnetem Element und Profitcenter. |
| Produkte | `cfm_product` | Produktstamm mit übergeordnetem Produkt, Familie, Gruppe, Mengeneinheit und Standardkosten. |
| Kunden | `cfm_customer` | Kundenstamm mit übergeordnetem Kunden, Gruppe, Region und Land. Kundennamen werden nicht maskiert. |
| Segmentwerte | `cfm_segment` | Segmentwerte mit Name und übergeordnetem Element. Siehe [Hierarchien](#hierarchien). |
| Hauptbuch | `cfm_gl_journal` | Journalzeilen in Transaktions-, Lokal- und Berichtswährung. |
| Saldenliste | `cfm_trial_balance` | Soll, Haben und Saldo der Periode nach Entität, Konto und Abteilung, in Lokal- und Berichtswährung. |
| Verkaufspositionen | `cfm_sales_line` | Fakturierte Verkaufszeilen mit Menge sowie Brutto-, Rabatt-, Netto- und COGS-Beträgen. |
| Lagerbestände | `cfm_inventory_balance` | Lagerbestand am Periodenende nach Produkt und Lager. |
| Budget | `cfm_budget` | Budget und Prognose nach Szenario, Version, Konto und Abteilung. |
| Verteilungstreiber | `cfm_stat_driver` | Statistische Treiber wie Mitarbeiterzahl, Quadratmeter oder Einheiten. |

Perioden werden als `YYYY-MM` geschrieben, und Transaktionen werden nach Buchungsperiode eingeordnet. Das Budget ist optional: Ein ERP ohne Budgets lädt dennoch alles andere.

Eine Saldenlistendatei kann Soll- und Haben-Spalten, eine Saldospalte oder beides enthalten. Mit nur Soll und Haben ist der Saldo Soll minus Haben, und eine leere Seite zählt als null. Mit nur einem Saldo wird ein positiver Saldo zum Soll und ein negativer zum Haben, als positiver Betrag. Eine Abteilungsspalte ist optional.

## Fehlerbehebung

| Symptom | Was zu tun ist |
|---|---|
| **Verbindung testen** meldet, dass das ERP die Zugangsdaten abgelehnt hat | Prüfen Sie die Zugangsdaten der Verbindung und ob sich der Integrationsbenutzer am ERP anmelden kann. |
| **Verbindung testen** zeigt für ein Dataset **Fehlende Berechtigung** | Bitten Sie Ihren ERP-Administrator, die genannten Berechtigungen hinzuzufügen. Die [Verbindungsanleitung](/de/guides/connections/) für Ihr ERP listet auf, was die Verbindung braucht. |
| Eine ERP-Fehlermeldung ist kürzer als die des ERP selbst | PlaidCloud entfernt Zugangsdaten, Token und Schlüssel aus Fehlern des Anbieters, bevor es sie anzeigt, sodass manche Details fehlen. Führen Sie **Verbindung testen** aus, um zu sehen, welches Dataset betroffen ist. |
| **Daten geladen** ist für eine Periode ein Problem | Ein ERP-Lesevorgang für diese Periode ist fehlgeschlagen. Führen Sie **Laden** erneut aus; bereits geladene Perioden werden übersprungen. |
| **Konten fehlen im Kontenplan** ist ein Problem | Fügen Sie die fehlenden Konten dem Kontenplan im ERP oder in Ihrer Datei hinzu und führen Sie **Laden** erneut aus. |
| **Währungsumrechnung** ist ein Problem | Die Währung einer Entität hat für diese Periode keinen Kurs in die Berichtswährung, oder es wurde keine einzelne Berichtswährung gefunden. Fügen Sie die Kurse einer Datei **Wechselkurse** hinzu, prüfen Sie, ob die Verbindung die Wechselkurse des ERP lesen kann, oder setzen Sie die Projektvariable `reporting_currency`. Führen Sie dann **Laden** erneut aus. |
| **Währungsumrechnung** erfordert Aufmerksamkeit | Bilanz-, Lagerbestands- oder Budgetzeilen haben für die Periode keinen Stichtags-, historischen oder geplanten Kurs. Die Gewinn- und Verlustrechnung ist nicht betroffen. Fügen Sie die Kurse hinzu, einschließlich geplanter Kurse für Budgetmonate, und führen Sie **Laden** erneut aus. |
| **Codes waiting for your answer** erfordert Aufmerksamkeit | Klicken Sie auf **Prüfen**, beantworten Sie jeden Code und klicken Sie auf **Apply changes**. |
| **Which source covers which months** erfordert Aufmerksamkeit | Klicken Sie auf **Choose which source counts from when**, wählen Sie die Quelle und klicken Sie auf **Apply changes**. |
| **Intercompany balances** ist rot oder gelb | Prüfen Sie die Paare in **Intercompany pairs**. Buchen Sie die fehlende Seite, fügen Sie den Zeilen den Handelspartner hinzu oder ergänzen Sie den fehlenden Kurs. |
| **Group views are off** | Bitten Sie einen Architect, unter **Gruppe** die Option **Everyone on the project may see the group results** zu aktivieren. |
| **Nicht zugeordnete Entitäten** ist ein Problem | Fügen Sie die Entität dem Entitätsstamm hinzu oder ordnen Sie ihren Code in der Datei **Entitätszuordnung** einer bestehenden Entität zu, und führen Sie **Laden** erneut aus. |
