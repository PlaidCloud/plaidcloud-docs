**Data Foundation** ist die Finanzdatenbasis für Ihre PlaidCloud-Projekte. Das **Common Finance Model** führt ERP-Daten aus mehreren ERP-Systemen – und mehreren Instanzen jedes Systems – in einem einzigen Modell zusammen: ein Kontenplan, ein Satz Entitäten und eine Berichtswährung. Berichte, Kennzahlen und KI-Assistenten, die auf dem Modell aufbauen, lesen alle dieselben Zahlen, unabhängig davon, aus welchem ERP sie stammen.

Ihr ERP wird über seine PlaidCloud-Verbindung angebunden, sodass Hauptbuch, Saldenliste, Stammdaten und Budgets direkt aus der Quelle eintreffen, ohne dass Sie etwas exportieren müssen. Dateien ergänzen Daten, die ein System nicht vorhält, etwa Wechselkurse, Verteilungstreiber oder ein außerhalb des ERP geführtes Budget, und können die ERP-Zeilen ersetzen, die sie abdecken. **Laden** überführt jede Quelle in das Modell, rechnet sie in die Berichtswährung um und prüft, ob alles übereinstimmt – alles über die Registerkarte **Foundation** des Projekts. Wo Quellen denselben Code für unterschiedliche Dinge verwenden, legen Sie fest, ob sie dasselbe bedeuten, und eine Managementkonsolidierung erstellt die Konzern-Gewinn- und Verlustrechnung ohne die konzerninternen Posten. Vorlagen wie **Enterprise Profitability** bauen ihre Berichte und Modelle darauf auf.

## Ihr ERP verbinden

Ihr ERP wird über seine PlaidCloud-Verbindung mit Data Foundation verbunden. Data Foundation liest Hauptbuch, Saldenliste, Stammdaten, Wechselkurse und Budgets direkt daraus und greift dabei ausschließlich lesend zu. Sie können eine vorhandene Verbindung auswählen oder auf der Registerkarte eine neue erstellen. Für jedes System gibt es eine Seite für den Administrator, der den Zugriff gewährt; diese Seiten sind unter [Welche Systeme das Modell speisen können](/de/guides/projects/data-foundation-getting-started/#welche-systeme-das-modell-speisen-können) aufgeführt, und die [Data Foundation-Abdeckungsmatrix](/de/reference/data-foundation-coverage-matrix/) zeigt, welche Datasets jedes System direkt liefert.

<Steps>

1. Öffnen Sie in Analyze **Projekte** und klicken Sie auf **Neues Projekt**. Geben Sie einen Namen ein und wählen Sie unter **Starten mit** eine Vorlage wie **Enterprise Profitability (Vorlage)** statt **Leeres Projekt**. Klicken Sie auf **Erstellen**.

   Das Projekt öffnet sich auf seiner Registerkarte **Foundation**. Es ist privat und Sie sind sein einziger Architect, bis Sie es freigeben.

2. Öffnen Sie auf der Registerkarte **Foundation** den Bereich **Quellen** und wählen Sie unter **Connect a system** die Kachel Ihrer Systemart. Wählen Sie dann eine vorhandene Verbindung dafür aus oder wählen Sie **Neue Verbindung erstellen**. Jede vorhandene Verbindung listet die Workflows auf, die sie bereits verwenden, oder zeigt **Noch von keinem Workflow verwendet** an; eine Verbindung, die bereits eine Quelle ist, wird als **already a source** aufgeführt und kann nicht erneut ausgewählt werden.

3. Geben Sie für eine neue Verbindung einen **Verbindungsname** ein, wählen Sie die **Umgebung** aus und tragen Sie die Anmeldedaten ein, die Ihre ERP-Verbindung verlangt.

   Sie haben die Anmeldedaten noch nicht? Das Formular zeigt eine vorbereitete Zugriffsanfrage für Ihren ERP-Administrator. Klicken Sie auf **Anfrage kopieren** oder **Anfrage per E-Mail senden**, senden Sie sie ab und geben Sie die Werte ein, die Sie zurückerhalten.

4. Klicken Sie auf **Verbindung testen**. PlaidCloud meldet sich an, versucht jedes Dataset zu lesen und führt jedes als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** auf. Fehlt etwas, nennt es die Berechtigungen, die Ihr ERP-Administrator hinzufügen muss.

5. Legen Sie **Monate Verlauf** fest: wie viele Monate rückwirkend geladen werden, von 1 bis 120. Der Standard ist 24.

6. Markieren Sie bei einer vorhandenen Verbindung die zu ladenden Entitäten oder lassen Sie alle Markierungen leer, um jede Entität zu laden. Inaktive Entitäten und Eliminierungsentitäten bleiben ausgeblendet, bis Sie sie einblenden. Klicken Sie dann auf **Verbinden**.

7. Klicken Sie bei einer neuen Verbindung auf **Verbinden**, um sie zu erstellen. Markieren Sie dann die zu ladenden Entitäten und klicken Sie erneut auf **Verbinden**, um sie zu speichern. Bis Sie das tun, wird jede Entität geladen.

8. Um ein weiteres ERP-System oder eine weitere Instanz einzubinden, öffnen Sie **Connect another system** und wiederholen Sie diese Schritte. Beim Verbinden wird immer eine Quelle hinzugefügt und die vorhandenen bleiben unverändert, sodass mehrere ERP-Systeme und Instanzen das eine konsolidierte Modell speisen können.

</Steps>

Nach dem Verbinden zeigt die Karte, welche Verbindung, Umgebung, Entitäten und Monate Verlauf das Projekt lädt.

Jeder Ladevorgang liest nur, was sich geändert hat: Offene Perioden und die letzte abgeschlossene Periode werden erneut gelesen, bereits geladene abgeschlossene Perioden bleiben erhalten. Wenn Sie **Monate Verlauf** erhöhen, werden nur die hinzugekommenen Monate gelesen. Ein geänderter Wechselkurs, eine geänderte Entitätszuordnung oder eine geänderte Berichtswährung liest die betroffenen Monate erneut.

## Quellen

Jedes ERP-System und jede Instanz, aus der das Projekt lädt, ist eine Quelle. Die Liste **Load order** auf der Seite **Quellen** der Registerkarte **Foundation** zeigt für jede eine Zeile in Reihenfolge, mit Name und System, **Unternehmen**, **Zuletzt geladen**, **Zeilen** und **Status**. **Unternehmen** zeigt **Alle** oder wie viele ausgewählt sind. Eine Quelle, die noch nicht geladen wurde, zeigt **Not loaded yet**. Dateien, die Sie bestätigen, sind ebenfalls Quellen.

Klicken Sie bei einer Quelle auf **Bearbeiten**, um zu ändern, wie sie verwendet wird:

| Einstellung | Funktion |
|---|---|
| **Name** | Die Bezeichnung, die Berichte, Zuordnungsfragen und Meldungen für die Quelle verwenden. |
| **Position in der Reihenfolge** | Der Rang der Quelle. Wenn zwei Quellen denselben Monat desselben Unternehmens abdecken, gewinnt die weiter oben stehende. |
| **Berichtsbücher, durch Kommas getrennt** | Die zu lesenden Buchhaltungsbücher bei einem System, das mehrere führt. **Alle Berichtsbücher** liest jedes Buch. |
| **Unternehmen** | Bei einer Systemquelle, welche ihrer Unternehmen (Tochtergesellschaften) die Quelle lädt. Die Liste wird beim ersten Öffnen des Bereichs aus dem System gelesen und zeigt die Unternehmen, die die Quelle derzeit lädt. Markieren Sie die zu ladenden oder markieren Sie keines, um alle zu laden. Wenn das System seine Unternehmen nicht auflistet, geben Sie deren Namen durch Kommas getrennt ein. |
| **Unternehmen**, **Von (2026-01)** und **Bis (2026-12)** | Die Monate, die diese Quelle für jedes Unternehmen liefert. Lassen Sie einen Monat leer, um keine Begrenzung festzulegen. Schreiben Sie Monate als Jahr und Monat, zum Beispiel `2026-03`. |

Klicken Sie auf **Speichern**, um Ihre Änderungen zu übernehmen. Das Hinzufügen von Unternehmen oder das Markieren keines Unternehmens wird sofort gespeichert. Wenn Sie ein Unternehmen weglassen, müssen Sie zuerst **Load fewer companies?** bestätigen, weil beim Speichern sofort alles gelöscht wird, was aus dieser Quelle geladen wurde, und der nächste **Laden**-Vorgang die markierten Unternehmen erneut abruft. Liest die Verbindung der Quelle inzwischen ein anderes Konto als das, für das die Quelle eingerichtet wurde, wird das Speichern mit einer entsprechenden Meldung abgelehnt, sodass eine Änderung nie eine andere Quelle ersetzen kann. Verbinden Sie dieses Konto stattdessen als eigene Quelle. Um eine Quelle zu entfernen, klicken Sie auf **Remove this source** und bestätigen Sie mit **Entfernen**. Alles, was aus ihr geladen wurde, wird gelöscht, und Sie können sie später erneut verbinden.

Das Ändern von Quellen liest Ihr ERP nicht erneut. Die Leiste über jeder Seite zeigt **You have changed your sources. Press Apply changes to use them.**, bis Sie auf **Apply changes** klicken. Dadurch wird ein Ladevorgang aus den bereits abgerufenen Daten ausgeführt: Die Quellen werden mit Ihrer neuen Reihenfolge, Ihren Zuordnungen, Namen und Dateien erneut überführt und das Modell wird neu aufgebaut. Klicken Sie auf **Laden**, wenn Sie auch frische Daten aus den ERPs abrufen möchten.

## Dateien für Daten außerhalb Ihres ERP hinzufügen

Dateien ergänzen Ihre ERP-Verbindung um Daten, die ein System nicht vorhält, etwa Wechselkurse, Verteilungstreiber, eine [Entitätszuordnung](#entitätszuordnung) oder ein außerhalb des ERP geführtes Budget. Jede Datei gehört zu einem der Datasets, die unter [Tabellen des Common Finance Model](#tabellen-des-common-finance-model) aufgeführt sind.

<Steps>

1. Wählen Sie unter **Dateien** das **Dokumentenkonto**, in dem die Datei gespeichert werden soll.

2. Legen Sie eine CSV- oder Excel-Datei auf **CSV- oder Excel-Datei hier ablegen** ab oder klicken Sie auf **Datei auswählen**. Die Datei wird in den Ordner `/foundation/` des Dokumentenkontos hochgeladen.

   Für eine Datei, die bereits im Dokumentenkonto liegt, geben Sie ihren **Dateipfad** ein, zum Beispiel `/foundation/budget.csv`, und klicken Sie auf **Datei hinzufügen**.

   Um jeden Monat eine neue Datei zu lesen, fügen Sie jede Datei eines Ordners hinzu, deren Name passt: Geben Sie den Ordner an und was **File names that** enthalten, womit sie beginnen, enden, was sie exakt treffen oder welchem Muster sie entsprechen, und klicken Sie auf **Add files**. Dateien in Unterordnern werden nicht gelesen.

3. PlaidCloud liest die Datei und schlägt eine Zuordnung vor:

   - **Erkanntes Trennzeichen, Dezimaltrennzeichen und Datumsangaben.** Das Trennzeichen (Komma, Semikolon, Tabulator oder senkrechter Strich), das Dezimaltrennzeichen und das Datumsformat werden automatisch erkannt.
   - **Dataset**: die Tabelle des Common Finance Model, zu der die Datei gehört, ermittelt aus Dateiname und Spaltenüberschriften. Wenn die Zuordnung nicht eindeutig ist, wählen Sie sie aus der Liste.
   - **Dezimaltrennzeichen**: **Punkt (1,234.56)** oder **Komma (1.234,56)**.
   - **Datumsformat**: wird angezeigt, wenn die Datei Datumsangaben enthält. Ändern Sie es, wenn das erkannte Format falsch ist: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` oder `MM/DD/YYYY`.
   - Ein Raster mit **Spalte in Datei**, **Typ**, **Beispiele** und **Geht nach**. Ändern Sie **Geht nach**, um eine Spalte an ein anderes Feld zu senden oder auf **Nicht laden** zu setzen.

4. Beantworten Sie die Fragen, die die Datei aufwirft, etwa **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** oder **Are revenues shown as negative numbers?** Jede Frage wird nur gestellt, wenn die Datei die Antwort nicht bereits enthält.

5. Prüfen Sie, wohin jede Spalte geht, und klicken Sie dann auf **Zuordnung bestätigen**. Während der Verarbeitung erklärt der Hinweis unter der Schaltfläche, worauf gewartet wird. In einem Projekt, das noch die Beispieldaten enthält, entfernt die erste bestätigte Datei auch die Beispieldaten, was einige Minuten dauern kann.

</Steps>

Diese Optionen erscheinen bei einer Datei, wenn sie zutreffen:

| Option | Verwendung |
|---|---|
| **Which source do these rows apply to?** | Eine Code-Zuordnungsdatei auf eine Quelle beschränken. **Every source** wendet sie auf alle an. |
| **Where does this file come from?** | Angeben, ob die Datei **This project's own codes** enthält oder aus **Another system** stammt, das Sie benennen, zum Beispiel `SAP Germany export`. Eine Datei aus einem anderen System wird wie eine ERP-Quelle auf gemeinsam verwendete Codes geprüft. |
| **Split … into … parts at each …** (unter **Erweitert**) | Eine Spalte, die mehrere Werte enthält, etwa `100-200-300`, aufteilen und jeden Teil an ein eigenes Feld senden. |
| **Which currency do you report in?** | Die Berichtswährung festlegen, wenn das Projekt noch keine hat. Geben Sie sie mit drei Buchstaben an, zum Beispiel `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Die Ergebnisse Ihres Konsolidierungssystems laden, damit die Konzern-Gewinn- und Verlustrechnung [abgestimmt](#mit-ihrem-konsolidierungssystem-abstimmen) werden kann. |

Um eine Datei aus dem Projekt zu nehmen, klicken Sie unter **Dateien** daneben auf **Entfernen** oder in ihrer Zuordnung auf **Remove this file** und bestätigen Sie. Ihre Zahlen verschwinden aus Ihren Berichten, sobald Sie das nächste Mal auf **Apply changes** klicken.

Wenn PlaidCloud das Dataset, das Dezimaltrennzeichen oder die Datumsreihenfolge nicht selbst bestimmen kann – zum Beispiel bei einer Datei, deren Datumsangaben als Tag/Monat oder Monat/Tag gelesen werden könnten –, werden Sie vor dem Bestätigen um eine Auswahl gebeten. Eine zweite Datei für dasselbe Dataset ersetzt die erste. Passen die Spalten einer späteren Datei nicht zum Dataset, nennt der Ladevorgang die Datei und die Spalten und fordert Sie auf, die Datei oder ihre Spaltennamen zu korrigieren oder die Einstellung **Schema Mismatch** des Schritts auf `union` zu setzen.

Akzeptiert werden CSV-, TSV- und TXT-Textdateien, Excel-Dateien im Format `.xlsx` (gelesen wird das erste Blatt) sowie Parquet-Dateien.

<Aside type="note">
Eine fehlende oder leere Datei stoppt einen Ladevorgang nie. Beim Hinzufügen wird gemeldet, dass noch nichts zuzuordnen ist, und ein Ladevorgang endet mit einer Warnung, die den Pfad nennt, und lässt dieses Dataset leer. Fügen Sie die Datei erneut hinzu, sobald sie existiert.
</Aside>

## Daten laden

Klicken Sie auf **Status** auf **Laden**. Der Ladevorgang liest Ihr verbundenes ERP und Ihre bestätigten Dateien, überführt sie in das Common Finance Model, rechnet sie in die Berichtswährung um, führt die Bereitschaftsprüfungen aus und baut die Modelle der Vorlage neu auf.

- Pro Projekt wird jeweils nur ein Ladevorgang ausgeführt. Ein zweites **Laden** oder **Apply changes** meldet, dass bereits ein Ladevorgang läuft, und während er läuft, können Sie keine Quellen ändern.
- Wenn andere Workflows dieselbe ERP-Verbindung verwenden, listet der erste Ladevorgang sie auf und bittet Sie um Bestätigung, da ein Ladevorgang aus dem ERP liest und diese Workflows verlangsamen kann. Klicken Sie auf **Trotzdem laden**, um fortzufahren.
- Nach einem Upgrade von PlaidCloud aktualisiert das **Laden** durch einen Architect auch die generierten Workflows des Projekts und erstellt dabei alle benötigten Arbeitstabellen. Bis dahin listet die Statusseite einen gelben Eintrag, "The workflows were generated by an earlier release. An Architect's Load updates them.", und ein **Laden** durch einen Manager warnt, dass nur ein Architect sie aktualisieren kann.
- Beim Anwenden eines Updates bleiben Ihre eigenen Änderungen an den generierten Schritten erhalten. Wenn Sie einen Schritt geändert haben und das Update ihn ebenfalls geändert hat, bleibt Ihre Änderung erhalten und die Statusseite vermerkt den Konflikt mit dem Schrittnamen. Ein von Ihnen bearbeiteter Schritt, den das Update nicht mehr generiert, bleibt erhalten, wird aber deaktiviert; löschen Sie ihn oder aktivieren Sie ihn wieder, wenn Sie ihn noch benötigen. Ein Schritt, den das Update ersetzt, wird benannt, und der frühere bleibt in seinen Schrittversionen erhalten.
- Wenn ein Update mittendrin angehalten hat oder noch läuft, zeigt die Statusseite das an, und seine Schritte können bis zum Abschluss in falscher Reihenfolge laufen. Klicken Sie als Architect erneut auf **Laden**, um es abzuschließen. Hält es erneut an, wenden Sie sich an den Support.
- Ein fehlgeschlagener Ladevorgang wird rot angezeigt und versteckt sich nie hinter früheren Ergebnissen. Schlägt die Konsolidierung fehl, nennt der Status den Schritt, an dem sie angehalten hat, statt alte Konzernergebnisse anzuzeigen. Zeilen aus einem früheren Ladevorgang zeigen **Aus einem früheren Ladevorgang. Erneut laden.**, bis ein Ladevorgang erfolgreich ist.
- Wenn eine Entität und Periode nicht gelesen werden kann, wird der Rest trotzdem geladen. Führen Sie **Laden** erneut aus, um nur das Fehlgeschlagene abzurufen.

### Zurückgehaltene Zeilen

Wenn sich Quellen überschneiden, behält ein Ladevorgang eine Kopie jeder Zahl und hält die anderen zurück, statt sie doppelt zu zählen. Zurückgehaltene Zeilen werden mit Quelle, Entität und Grund erfasst, und der Ladevorgang endet mit einer Warnung, die die Anzahlen nennt, zum Beispiel `120 rows of NetSuite EU also provided by a source ranked ahead`. Die Gründe sind:

| Grund | Bedeutung |
|---|---|
| In einem anderen Buchhaltungsbuch | Die Zeile gehört zu einem Berichtsbuch, das die Quelle nicht lesen soll. |
| Außerhalb der Perioden, die die Quelle liefert | Die Zeile liegt außerhalb der für das Unternehmen festgelegten Monate **Von** und **Bis**. |
| Auch von einer höher eingestuften Quelle geliefert | Eine weiter oben stehende Quelle deckt dasselbe Unternehmen und denselben Monat ab. |
| Auch in einer früheren Datei der Quelle | Eine frühere Datei derselben Quelle deckt den Monat bereits ab. |
| Durch eine Datei ersetzt | Eine Datei ersetzt die ERP-Zeilen für diese Entität und diesen Monat. |
| Enthält einen Code, den auch eine andere Quelle verwendet | Der Code benötigt Ihre Antwort. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| Enthält einen Code, der zwei Codes zugeordnet ist | Die Code-Zuordnung gibt dem Code zwei Antworten. |

Statistische Konten werden statt ins Hauptbuch zu den Verteilungstreibern verschoben und als verschoben angezeigt, nicht als Problem.

### ERP-Daten und Dateien zusammen

Eine Datei ersetzt nur, was sie abdeckt; die übrigen Zeilen aus Ihrem ERP bleiben erhalten.

- **Stammdatendateien** (Konten, Abteilungen, Kunden, Produkte und Segmentwerte) ersetzen die ERP-Zeilen mit demselben Code.
- **Transaktionsdateien** ersetzen die ERP-Zeilen für dieselbe Entität und denselben Monat. Hauptbuch- und Saldenlistendateien werden zusätzlich nach Ledger abgeglichen, Budgetdateien nach Szenario und statistische Treiberdateien nach Szenario und Treiber.

Deckt eine Datei einen Monat später nicht mehr ab, kehren die ERP-Daten für diesen Monat beim nächsten Ladevorgang zurück.

## Entitätszuordnung

Jede Quelle benennt ihre Entitäten mit eigenen Codes. Die **Entitätszuordnung** ordnet diese Codes den Entitäten in Ihren Entitätsstammdaten zu, sodass Zeilen aus jeder Quelle auf derselben Entität landen.

Um eine zu verwenden, fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Entitätszuordnung**:

| Spalte | Inhalt |
|---|---|
| `source_entity` | Der Code, wie die Quelle ihn führt, etwa ein Unternehmenscode. |
| `entity` | Die Entität, zu der er gehört, wie sie in den Entitätsstammdaten heißt. |

- Ein Code, der nicht in der Entitätszuordnung steht, wird unverändert verwendet.
- Mehrere Codes können einer Entität zugeordnet werden. Ihre Zeilen werden zusammengefasst, und ein Monat gilt als abgeschlossen, sobald er für alle abgeschlossen ist.
- Codes in der Entitätszuordnung gelten für jede Quelle, daher müssen die Entitätscodes jeder Quelle quellenübergreifend eindeutig sein.
- Eine Zeile einer **Entitäten**-Datei ersetzt die ERP-Entität mit demselben Entitätscode.

Die Prüfung **Nicht zugeordnete Entitäten** markiert jede Zeile, deren Entität weder in den Entitätsstammdaten steht noch über die Entitätszuordnung einer zugeordnet ist. Bis Entitätsstammdaten geladen sind, zeigt sie **– Nicht zutreffend**.

## Codes quellenübergreifend zuordnen

Zwei Quellen können denselben Code für unterschiedliche Dinge verwenden oder unterschiedliche Codes für dasselbe. Wenn ein Code in mehr als einer Quelle vorkommt, hält Data Foundation seine Zeilen zurück, bis Sie angeben, ob er überall dasselbe bedeutet, sodass jeder Betrag nur einmal gezählt wird. Die Prüfung **Codes, die auf Ihre Antwort warten** listet sie auf, die ersten 10 und dann "and K more", und **Answer codes ›** in der Liste **What to do next** auf **Status** öffnet sie.

**Answer codes ›** öffnet **Benötigte Antworten**, wo **Codes, die auf Ihre Antwort warten** aufgeführt sind. Die Codes sind nach Art gruppiert: **Kontotypen**, **Unternehmen**, **Konten**, **Abteilungen**, **Profit-Center**, **Kunden**, **Produkte** und jede zusätzliche Kategorie. Für jeden Code wird angezeigt, wie jede Quelle ihn nennt, sowie ein Vorschlag:

- **Looks like the same thing**, wenn die Quellen dem Code denselben Namen geben.
- **Looks like different things**, wenn sich die Namen unterscheiden.
- **We can't tell. Please answer.**, wenn es keinen Anhaltspunkt gibt.

Beantworten Sie einen Code nach dem anderen mit **Yes, the same** oder **No, different**, oder beantworten Sie eine ganze Gruppe auf einmal mit **Accept all** (jeden Vorschlag übernehmen), **All the same** oder **All different**. Bei Konten können Sie auch eine ganze übergeordnete Gruppe des Kontenplans auf einmal beantworten. Wenn eine Quelle keine Kontotypen führt, wählen Sie für eine Gruppe von Konten **Use this type**: **Umsatz**, **Umsatzkosten**, **Betriebsaufwendungen**, **Nicht betriebliche Erträge und Aufwendungen**, **Vermögenswerte**, **Verbindlichkeiten** oder **Eigenkapital**.

Zuordnungen werden pro Quelle und Dimension gespeichert, sodass eine Antwort für die Abteilungen einer Quelle nie die Konten einer anderen Quelle ändert. Antworten werden laufend gespeichert, mit der Meldung **Saved. Press Apply changes to use your answers.** Klicken Sie auf **Apply changes**, um sie zu verwenden.

Sie können die Zuordnungen auch in einer Datei bereitstellen. Fügen Sie eine Datei mit dem Dataset **Code map** hinzu und wählen Sie **Which source do these rows apply to?**, um sie auf eine Quelle zu beschränken.

## Festlegen, welche Quelle ab wann zählt

Wenn zwei Quellen dieselben Monate liefern, fordert die Prüfung **Welche Quelle welche Monate abdeckt** Sie zu einer Auswahl auf. Klicken Sie in der Liste **What to do next** auf **Status** auf **Choose sources ›**, um **Quellenabdeckung** zu öffnen; dort ist jede Überschneidung nach Unternehmen aufgeführt. Wählen Sie die Quelle, die zählt, geben Sie in **That month is** den Monat ein, ab dem sie zählt, zum Beispiel `2026-04`, klicken Sie auf **Save choice** und dann in der Leiste über der Seite auf **Apply changes**. Die andere Quelle behält die früheren Monate.

Derselbe Dialog warnt, wenn zwei Quellen unterschiedliche Wechselkurse für eine Währung liefern; verwendet werden die Kurse der weiter oben stehenden Quelle.

## Währungsumrechnung

Jeder Ladevorgang rechnet die Beträge aus Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget von ihrer Landeswährung in eine Berichtswährung um. Berichte und Modelle lesen die umgerechneten Beträge, sodass sich Entitäten in unterschiedlichen Währungen aus jedem System korrekt summieren.

### Die Berichtswährung

Um die Berichtswährung festzulegen, setzen Sie die Projektvariable `reporting_currency` auf einen Währungscode wie `USD`. Siehe [Projektvariablen verwalten](/de/guides/projects/managing-projects/#projektvariablen-verwalten). Die Vorlage legt sie leer an. Solange sie leer ist, verwendet jeder Ladevorgang die erste der folgenden Angaben, die genau eine Währung nennt:

1. Die Konzernwährung der Entitäten.
2. Die Landeswährung der obersten Entitäten, also derjenigen ohne übergeordnete Entität.
3. Die Landeswährung der Dateien.

Nennt keine davon genau eine Währung, zeigt **Währungsumrechnung** ein Problem an, bis Sie `reporting_currency` festlegen.

Beträge, die bereits in der Berichtswährung vorliegen, bleiben unverändert, sodass ein Projekt, dessen Daten alle in einer Währung vorliegen, keine Kurse benötigt.

Auch Umsatz-, Lagerbestands- und Budgetdateien können eine Währung enthalten. Ordnen Sie eine Spalte mit dem Namen `Currency` oder `Local Currency` zu; sie wird automatisch erkannt, und die lokalen Beträge der Datei werden in die Berichtswährung umgerechnet. Ein Konzern- oder Berichtsbetrag, der bereits in der Datei steht, bleibt unverändert. Standardkosten von Produkten werden nicht umgerechnet.

### Wechselkurse

Ein Kurs rechnet eine Einheit einer Währung für einen Monat in die Berichtswährung um: Der umgerechnete Betrag ist der lokale Betrag mal dem Kurs.

- **Aus Ihrem ERP** liest jeder Ladevorgang die Wechselkurse, die das ERP vorhält.
- **Aus einer Datei**: Fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Wechselkurse**. Ein Kurs in der Datei ersetzt den ERP-Kurs für dieselben Währungen und denselben Monat. Verwenden Sie eine Datei, um in einer Währung zu berichten, für die Ihre ERPs keine Kurse veröffentlichen, oder um Plankurse für Budgetmonate hinzuzufügen.

| Spalte | Inhalt |
|---|---|
| `from_currency` | Die Ausgangswährung, zum Beispiel `EUR`. |
| `to_currency` | Die Berichtswährung, zum Beispiel `USD`. |
| `period` | Der Monat im Format `YYYY-MM`. |
| `average_rate` | Der Durchschnittskurs des Monats. |
| `closing_rate` | Der Kurs am Monatsende. |
| `historical_rate` | Der historische Kurs für Eigenkapital und für Konten, die auf den historischen Kurs eingestellt sind. |

Hat eine Währung keinen Kurs in die Berichtswährung, wird ihr Kurs in umgekehrter Richtung – von der Berichtswährung in diese Währung – umgekehrt, mit 12 Dezimalstellen. Fehlt auch dieser, wird ihr Kurs in eine andere Währung mit dem Kurs dieser Währung in die Berichtswährung multipliziert.

### Welcher Kurs gilt

Jede Zeile wird aus ihrer eigenen Währung umgerechnet, sodass eine Zeile in einer anderen Währung als ihre Entität aus der Währung umgerechnet wird, in der sie vorliegt. Es gilt die erste Regel, die auf die Zeile zutrifft:

| Zeile | Kurs |
|---|---|
| Statistische und nicht buchende Konten | Nicht umgerechnet. |
| Bereits in der Berichtswährung | Nicht umgerechnet. |
| Konto mit Kurstyp | Dieser Kurs: Durchschnitts-, Stichtags- oder historischer Kurs. Historisch fällt auf den Stichtagskurs zurück, wenn kein historischer Kurs vorhanden ist. Aus einem ERP ist der Kurstyp der eigene Kurstyp des Kontos. Ordnen Sie in einer Kontenplandatei eine Kurstyp-Spalte `fx_rate_type` mit `average`, `closing` oder `historical` zu. |
| Verkaufsposition | Der Durchschnittskurs der Periode. |
| Lagerbestand | Der Stichtagskurs der Periode. |
| Budgetzeile | Nach Konto, wie beim Hauptbuch: der Durchschnittskurs für GuV-Konten und der Stichtagskurs für Bilanzkonten. |
| GuV-Konto | Der Durchschnittskurs der Periode. |
| Eigenkapitalkonto | Der historische Kurs oder der Stichtagskurs, wenn kein historischer Kurs vorhanden ist. |
| Jedes andere Bilanzkonto | Der Stichtagskurs der Periode. |

Umgerechnete Beträge werden nicht gerundet, sodass Summen nicht abweichen.

<Aside type="note">
Die Saldenliste enthält die Bewegungen jeder Periode, daher sind Bilanzbeträge die Bewegungen jedes Monats, umgerechnet zum Stichtagskurs dieses Monats. Sie sind keine zum Periodenendkurs neu umgerechnete Bilanz, und es gibt weder eine kumulierte Umrechnungsdifferenz noch eine konzerninterne Eliminierung. Verwenden Sie die umgerechneten Beträge für die Gewinn- und Verlustrechnung.
</Aside>

## Hierarchien

Jeder Ladevorgang baut die Dimensionen aus den Stammdaten jeder Quelle neu auf. Zu Beginn gibt es sieben Dimensionen und bis zu zehn zusätzliche Kategorien:

| Dimension | Aufgebaut aus |
|---|---|
| **Entität** | Entitäten und ihren übergeordneten Entitäten |
| **Konto** | Kontenplan und übergeordneten Konten |
| **Abteilung** | Abteilungen und ihren übergeordneten Abteilungen |
| **Kunde** | Kunden und ihren übergeordneten Kunden |
| **Produkt** | Produkten und ihren übergeordneten Produkten |
| **Segment 1** | Segmentwerten für `segment_1` |
| **Segment 2** | Segmentwerten für `segment_2` |
| **Segment 3** bis **Segment 10** | Segmentwerten für `segment_3` bis `segment_10`, wenn Ihre Quellen sie führen |

- Ein Datensatz ohne übergeordnetes Element oder einer, der sich selbst als übergeordnetes Element nennt, wird als oberstes Element geladen.
- Da jeder Ladevorgang die Hierarchien neu aufbaut, ändern Sie ein übergeordnetes Element im ERP oder in Ihrer Datei, nicht in der Dimension.
- Ein Problem in einer Hierarchie betrifft nur diese Dimension. Der Ladevorgang und die Modelle der Vorlage werden trotzdem abgeschlossen.
- Sie können jede zusätzliche Kategorie nach ihrem Inhalt umbenennen, zum Beispiel **Klasse** oder **Region**. Geben Sie auf der Seite **Quellen** unter **Names** die Namen ein, die Ihre Berichte verwenden, und klicken Sie auf **Save names**. Namen bestehen aus Buchstaben, Ziffern, Leerzeichen, Punkten, Bindestrichen und Unterstrichen, bis zu 60 Zeichen.
- Jede Quelle gibt an, unter welchem Ihrer Kategorienamen jede ihrer eigenen zusätzlichen Kategorien eingeordnet wird. Klicken Sie bei der Quelle auf **Bearbeiten**, wählen Sie für jede den Namen oder **Leave out** und klicken Sie auf **Speichern**. Quellen, die eine Kategorie unterschiedlich benennen, etwa `Class` und `Business area`, teilen sich dann einen Platz.

Um Segmenthierarchien aus einer Datei bereitzustellen, wählen Sie das Dataset **Segmentwerte**:

| Spalte | Inhalt |
|---|---|
| `segment` | Zu welchem Segment der Wert gehört: `segment_1` bis `segment_10`. |
| `segment_value` | Der Wert, wie Hauptbuch-, Umsatz- und Budgetzeilen ihn führen. |
| `segment_value_name` | Sein Name. |
| `parent_segment_value` | Sein übergeordneter Wert innerhalb desselben Segments. |

## Bereitschaftsprüfungen

Nach jedem Ladevorgang listet das Raster **Bereitschaft** jede Prüfung für jede Entität und Periode mit einem dieser Status auf:

| Status | Bedeutung |
|---|---|
| **● Bereit** | Die Prüfung war erfolgreich. |
| **▲ Aufmerksamkeit erforderlich** | Einen Blick wert, aber die Zahlen sind verwendbar. |
| **■ Problem** | Beheben Sie dies, bevor Sie sich auf die Ergebnisse verlassen. |
| **– Nicht zutreffend** | Für diese Prüfung liegen noch keine Daten vor. |

Die Prüfungen sind:

| Prüfung | Was sie bestätigt |
|---|---|
| **Daten geladen** | Jede Geschäftsperiode hat Hauptbuchzeilen, und jeder ERP-Lesevorgang war erfolgreich. Eine abgeschlossene Periode ohne Zeilen ist ein Problem; eine offene Periode ohne Zeilen erfordert Aufmerksamkeit. |
| **Saldenliste stimmt mit Hauptbuch überein** | Die Saldenliste entspricht dem Hauptbuch für jede Entität, Periode und jedes Konto. Wenn sowohl die Saldenliste als auch das Hauptbuch für ein Konto Abteilungen führen, wird auch jede Abteilung abgestimmt. |
| **Umsatz stimmt mit Hauptbuch überein** | Die Verkaufspositionen entsprechen den Umsatz- und Umsatzkostenkonten des Hauptbuchs für jede Periode. |
| **Unbekannte Produkte/Kunden** | Jede Verkaufsposition nennt ein Produkt und einen Kunden, die in den Produkt- und Kundenstammdaten vorhanden sind. |
| **Konten fehlen im Kontenplan** | Jede Hauptbuchzeile nennt ein Konto aus dem Kontenplan. Zeilen mit unbekanntem Konto werden in der Gewinn- und Verlustrechnung nicht berücksichtigt. Ein Konto mit Buchungen, aber ohne Kontotyp ist ebenfalls ein Problem, und eine Quelle, deren Kontenplan Umsatzkonten typisiert, aber kein Umsatzkostenkonto, erfordert Aufmerksamkeit. |
| **Währungsumrechnung** | Jede Zeile aus Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget hat einen Betrag in der Berichtswährung. Eine GuV- oder Umsatzzeile ohne Kurs ist ein Problem, weil die Gewinn- und Verlustrechnung umgerechnete Beträge liest. Eine Bilanz-, Lagerbestands- oder Budgetzeile ohne Kurs erfordert Aufmerksamkeit. Ein Budgetmonat, für den noch kein Kurs vorliegt, wird gelb angezeigt; laden Sie daher Plankurse für Budgetmonate. Siehe [Währungsumrechnung](#währungsumrechnung). |
| **Nicht zugeordnete Entitäten** | Jede Zeile aus Hauptbuch, Saldenliste und Umsatz nennt eine Entität aus den Entitätsstammdaten, direkt oder über die Entitätszuordnung. Nicht zutreffend, bis Entitätsstammdaten geladen sind. Siehe [Entitätszuordnung](#entitätszuordnung). |

Ladevorgänge mit mehr als einer Quelle fügen diese Prüfungen hinzu:

| Prüfung | Was sie bestätigt |
|---|---|
| **Berichtsbuch** | Für eine Quelle, die für eine Entität mehrere Buchhaltungsbücher führt, wurde das Berichtsbuch ausgewählt. Bis Sie eine Auswahl treffen, zählt nur das erste Buch. |
| **Codes, die auf Ihre Antwort warten** | Jeder Code, den mehr als eine Quelle verwendet, wurde beantwortet. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| **Zusätzliche Kategorien aus Ihren Quellen** | Jede zusätzliche Kategorie, die eine Quelle führt, hat einen Namen oder wurde ausgelassen. |
| **Welche Quelle welche Monate abdeckt** | Keine zwei Quellen liefern dieselben Monate eines Unternehmens, es sei denn, Sie haben festgelegt, welche zählt. |
| **Kontotypen und Hierarchie** | Jedes übergeordnete Element, das eine Dimension nennt, existiert, und kein Element ist sein eigenes übergeordnetes Element oder sein eigener Vorfahr. Ein fehlendes übergeordnetes Element setzt seine untergeordneten Elemente an die Spitze der Hierarchie, und eine Schleife verhindert das Laden dieser Hierarchie. Summen sind nicht betroffen. |
| **Geschäftskalender** | Die Geschäftsperioden jeder Entität sind Kalendermonate, und jeder Monat mit Zeilen lässt sich genau einer Geschäftsperiode zuordnen. Die Prüfung erfordert Aufmerksamkeit, wenn die Perioden einer Entität keine Kalendermonate sind (4-4-5, 13 Perioden) oder wenn die Zeilen eines Monats in mehr als einer Geschäftsperiode liegen könnten oder dem Geschäftskalender der Monat fehlt. |

Jede Zeile, die nicht bereit ist, nennt in der Spalte **Was zu tun ist**, was zu tun ist, etwa den Kontenplan laden, Wechselkurse laden oder **Laden** für eine Periode erneut ausführen.

Das Raster zeigt außerdem zwei Einrichtungsprüfungen, die nur erscheinen, wenn sie Aufmerksamkeit erfordern:

| Prüfung | Wann sie erscheint |
|---|---|
| **Gemeinkostenumlage** | Nur eine der Projektvariablen `overhead_department` und `overhead_driver` ist gesetzt, oder kein Verteilungstreiber entspricht `overhead_driver`, sodass die Umlage nichts bewirken würde. Setzen Sie beide oder leeren Sie beide, um die Gemeinkostenumlage zu deaktivieren. |
| **Budgetvergleich** | Budgetzeilen sind geladen, aber keine liegt in der Version, die die Projektvariable `budget_version` nennt, sodass der Budgetvergleich leer wäre. |

## Managementkonsolidierung

Jeder Ladevorgang erstellt eine Managementkonsolidierung: die Konzern-Gewinn- und Verlustrechnung aller Entitäten des Konzerns in der Berichtswährung, ohne konzerninterne Posten. Sie dient dem Management-Reporting. Ihr Konsolidierungssystem bleibt das maßgebliche System für den gesetzlichen Konzernabschluss; stimmen Sie wie unten beschrieben mit ihm ab.

<Aside type="note">
Die Managementkonsolidierung umfasst nur die Gewinn- und Verlustrechnung. Sie ist keine gesetzliche oder rechtliche Konsolidierung und enthält keine konsolidierte Bilanz, keine Umrechnungsdifferenz, keinen Geschäfts- oder Firmenwert und keine Minderheitsanteile.
</Aside>

### Den Konzern auswählen

Öffnen Sie auf der Seite **Quellen** den Bereich **Group and row access**, um die Unternehmen des Konzerns anzuzeigen. Ein Unternehmen, dessen Markierung Sie entfernen, bleibt eigenständig in Ihren Berichten, wird aber nicht in die Konzernsumme einbezogen. Klicken Sie auf **Save group**. Die Änderung gilt beim nächsten **Laden** oder **Apply changes**. Ein neues Unternehmen gehört zum Konzern, bis Sie seine Markierung entfernen.

Das Geschäftsjahr des Konzerns beginnt in dem Monat, den die Projektvariable `group_fy_start_month` festlegt; sie ist `1`, sofern Sie sie nicht ändern.

### Was Sie erhalten

| Tabelle | Inhalt |
|---|---|
| **Konzern-GuV** | Eine Zeile pro Entität, Periode und Position (Umsatz, Umsatzkosten, Betriebsaufwendungen, nicht betriebliches Ergebnis, konzerninterne Differenz) in der Berichtswährung. Umsatz und Kosten tragen ihr natürliches Vorzeichen. |
| **Konzern-GuV seit Jahresbeginn** | Dasselbe kumuliert seit Jahresbeginn bis zur letzten vollständig geladenen Periode des Konzerns. |
| **Konzerninterne Paare** | Eine Zeile pro Entitätenpaar, Konzern und Periode mit dem Betrag jeder Seite und der Restdifferenz. |
| **Konzerninterne Positionen** | Die Hauptbuchzeilen hinter einer Konzernzahl oder einem Paar, mit dem Partnerunternehmen. |
| **Abstimmung** | Die Konzern-GuV seit Jahresbeginn im Vergleich zu Ihrem Konsolidierungssystem. |

In diesen Tabellen erscheinen drei Entitätsnamen:

| Entität | Bedeutung |
|---|---|
| **Eliminations** | Die konzerninternen Eliminierungen. Sie gleichen sich zu null aus; lassen Sie sie daher für die Konzernzahlen drin und filtern Sie sie für die Summe der Entitäten vor Eliminierung heraus. |
| **Group total** | Die Summe des Konsolidierungssystems in der Abstimmung. |
| **Unmapped** | Zeilen ohne Periode sowie Konten oder Entitäten Ihres Konsolidierungssystems, die dieses Projekt nicht hat. |

Die Kennzahlen **Consolidated income**, **Consolidated result** und **IC difference** sowie ein Analysepfad für jede Tabelle beantworten Fragen zum Konzern.

### Konzerninterne Eliminierungen

Konzerninterne Zeilen werden über das Partnerunternehmen abgeglichen. Verwendet wird der Partner auf der Zeile; hat eine Zeile keinen, wird der Partner ihres Kunden verwendet. Beide Seiten eines Paares werden eliminiert, und der Betrag, um den die beiden Seiten voneinander abweichen, wird auf eine Zeile für konzerninterne Differenzen gebucht. Jedes Paar erhält einen Grund:

| Grund | Bedeutung |
|---|---|
| **Abgeglichen** | Beide Seiten haben denselben Betrag gebucht. |
| **Nur eine Seite gebucht** | Eine Entität hat die Transaktion gebucht, ihr Partner nicht. |
| **Nicht eliminiert** | Eine Zeile des Paares hat keinen Wechselkurs, daher wird keine Seite eliminiert. |

Ein Paar wird anhand seines kumulierten Werts seit Jahresbeginn beurteilt. Die Zeile **Intercompany balances** wird gelb, wenn die Differenz eines Paares über der Projektvariable `group_amber` liegt (Standard `1`), und rot über `group_red` (Standard `1000`). Zeilen ohne Partner oder mit einem Partner, der keine Entität ist, werden nicht eliminiert und in dieser Zeile gezählt. Eine Quelle, die Partner führt, neben einer, die keine führt, wird gelb angezeigt.

Die eigenen Eliminierungsentitäten einer Quelle bleiben außerhalb der Konzern-GuV, und die Zeile **Konsolidierung** weist darauf hin.

### Mit Ihrem Konsolidierungssystem abstimmen

Fügen Sie die Ergebnisse, die Ihr Konsolidierungssystem ausweist, als Datei hinzu und markieren Sie beim Bestätigen der Zuordnung **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)**. Beantworten Sie **Which version of the numbers is this?** mit dem Namen des Systems. Die Tabelle **Abstimmung** zeigt dann für jede Entität und Position **unsere**, **berichtet** und **Differenz**, kumuliert seit Jahresbeginn. Eine Differenz erklärt sich meist durch die Zeilen **Eliminations**, **Group total** und **Unmapped** oder durch die Wechselkurse, die das System verwendet. Die Zeile **Reconciliation to the source** listet jede Position über `group_amber` auf.

### Wer es sehen kann

Konzernergebnisse folgen dem Zeilenzugriff des Projekts. Wenn der Zeilenzugriff die Konzernergebnisse sperrt, zeigt der Status Gelb. Eine Person, die nur einige Entitäten sieht, sieht deren Summen vor Eliminierung. Die Zeilen **Eliminations** und die konzerninternen Tabellen erfordern Zugriff auf jede Entität.

Wenn das Projekt über eine Spalte, die die Konzerntabellen nicht führen – etwa die Abteilung –, einschränkt, wer welche Zeilen sieht, bleiben die Konzernergebnisse für alle ausgeschaltet, und **Konsolidierung** zeigt **Group views are off**. Nur ein Architect kann dann unter **Gruppe** die Option **Everyone on the project may see the group results** markieren. Die Änderung gilt beim nächsten **Laden** oder **Apply changes**.

## Aktuell halten

Nachdem ein Ladevorgang aus Ihrer ERP-Verbindung ohne Probleme erfolgreich war, erscheint auf **Status** die Schaltfläche **Nächtlich aktualisieren**. Klicken Sie darauf, um **Laden** jede Nacht um 2:00 Uhr in Ihrer Zeitzone auszuführen. **Status** zeigt dann **Nightly refresh: Every night at 2:00** und wer ihn eingerichtet hat.

Der nächtliche Ladevorgang wird im Namen der Person ausgeführt, die ihn eingerichtet hat. Kann diese Person die ERP-Verbindung nicht mehr verwenden, meldet das Raster, dass der nächtliche Ladevorgang übersprungen wird; richten Sie ihn erneut ein. Ein Projekt, das nur Beispieldaten enthält, kann nicht eingeplant werden.

Eine Datei, die bei einem nächtlichen Ladevorgang fehlt oder leer ist, führt zu einer Warnung, die den Pfad nennt, nicht zu einem Fehler, und der Rest des Modells wird trotzdem geladen.

## Geschäftsbezeichnungen

**Business names** unter **Names** auf der Seite **Quellen** der Registerkarte **Foundation** geben den Codes in Ihrem Modell die Bezeichnungen, die Ihr Unternehmen verwendet. Berichte, Kennzahlen und der Assistent zeigen diese Bezeichnungen an, und eine gespeicherte Bezeichnung gilt sofort. Spätere Ladevorgänge behalten sie bei.

1. Klicken Sie auf **Add a name** und wählen Sie die **Art**: **Kategorie**, **GuV-Position**, **Kennzahl** oder **Spalte**.
2. Geben Sie den **Code** ein: `segment_1` bis `segment_10` für eine Kategorie, den Schlüssel der Position für eine GuV-Position, den Namen der Kennzahl oder `table.column` für eine Spalte.
3. Geben Sie den **Name** ein, höchstens 60 Zeichen in einer Zeile.
4. Klicken Sie auf **Save names**.

Beim Speichern wird die gesamte Liste ersetzt. Eine Zeile mit leerem Namen entfernt diese Bezeichnung, und **Ausgewählte entfernen** entfernt die markierten Zeilen. Denselben Code zweimal zu benennen wird abgelehnt. Geschäftsbezeichnungen werden auch in die Beschreibung des Analysepfads geschrieben, damit der Assistent Ihre Begriffe verwendet, und diese Beschreibung hat eine Längenbegrenzung: Würde eine Bezeichnung sie zu lang machen, wird nichts gespeichert und Sie erhalten eine Meldung.

## Eine Zahl erklären

**Explain this number** zeigt, woraus sich eine Zahl der Gewinn- und Verlustrechnung zusammensetzt. Im Raster **Bereitschaft** hat eine Zeile für eine Entität und einen Monat die Option **Explain this number**, die die operative Marge der Entität für diesen Monat öffnet. Das Fenster zerlegt die Zahl in Ebenen, die sich zur Summe oben addieren:

| Ebene | Inhalt |
|---|---|
| **From the general ledger** | Was das Hauptbuch auf die Position gebucht hat. |
| **Allocated in** | Kosten, die Ihre [Umlageregeln](#umlageregeln) auf diese Entität verteilt haben. |
| **Allocated out** | Kosten, die diese Entität auf andere verteilt hat. |
| **Eliminated in the group** | Konzerninterne Posten, die im Konzernergebnis eliminiert wurden. |

Jede Ebene hat einen Satz, der beschreibt, was sie ist, sowie ihre größten Quelldokumente mit Quellsystem, Dokument und Konto. Nur Ebenen mit Zeilen werden angezeigt. Das Fenster folgt Ihrem Zeilenzugriff: Sie können nur die Zahlen erklären, die Sie sehen. Eine Zahl, hinter der nichts steht, zeigt **Nothing to explain**.

## Umlageregeln

Umlagen verteilen gemeinsame Kosten wie Gemeinkosten auf Abteilungen, Produkte und Kunden. Das Modell hat zwei Stufen: **Stage 1: overhead to departments** und **Stage 2: departments to products and customers**. Öffnen Sie **Aktionen > Umlagen...**, um zu sehen oder zu ändern, wie jede Stufe durchgeführt wird. Ohne Änderungen funktionieren sie wie vor der Einführung des Assistenten. Ein Leser kann die Regeln öffnen, aber nicht speichern.

Für jede Stufe stellt der Assistent vier Fragen:

| Schritt | Frage | Auswahl |
|---|---|---|
| **Pool** | Welche Kosten möchten Sie verteilen? | Die Kontenart und für Stufe 1 die Abteilung, die die Kosten trägt, oder **All departments**. |
| **Treiber** | Wonach möchten Sie sie verteilen? | **Statistic**, die Sie als Verteilungstreiber geladen haben, etwa Mitarbeiterzahl oder Quadratmeter, **Net sales amount**, **Sales quantity** oder **Spread evenly**. Verwenden Sie den Treiber aus **Same period** oder **Same period last year**. |
| **Ziel** | Wo landen sie? | Stufe 1: Abteilungen. Stufe 2: Produkte, Kunden oder beides. |
| **Methode** | Was passiert, wenn ein Treiber negativ ist? | **Ignore negative values** oder **Stop and tell me**. |

Unter den Schritten zeigt **Preview for** für einen Monat, angegeben als Jahr und Monat wie `2026-09`, was die Regeln – einschließlich noch nicht gespeicherter – bewirken würden: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Alles Nicht-Umgelegte sind Kosten, für die es keinen Treiber gab. Die Vorschau folgt Ihrem Zeilenzugriff.

Klicken Sie auf **Speichern**. Die Regeln werden beim nächsten **Laden** wirksam oder wenn Sie auf **Apply changes** klicken. Wenn Sie einen Umlageschritt von Hand bearbeitet haben, bleibt Ihre Änderung erhalten und wird nicht überschrieben; die Speicherung nennt ihn. Während ein Ladevorgang läuft, können Sie nicht speichern.

## Board Pack

Ein Board Pack schreibt Ihre Ergebnisse versandfertig in einen Ordner eines Dokumentenkontos. Öffnen Sie **Aktionen > Board pack...**, wählen Sie ein **Dokumentenkonto** und einen **Ordner**, etwa `/board-packs`, und klicken Sie auf **Speichern**. Jedes **Laden** erstellt dann das Pack, sodass die Dateien im Ordner so aktuell sind wie der letzte Ladevorgang. Jede Ausführung schreibt:

- Eine Excel-Arbeitsmappe, `Board pack.xlsx`, mit der Gewinn- und Verlustrechnung nach Entität, einer Margenbrücke sowie den umsatzstärksten und -schwächsten Kunden.
- Ein PDF des GuV-Dashboards.

Klicken Sie auf **Run now**, um sofort ein Pack zu erstellen; seine Dateien erscheinen im Ordner, sobald es fertig ist. Der Dialog zeigt die letzte Ausführung und ihr Ergebnis sowie die nächste Ausführung. **Apply changes** erstellt kein Pack. Um jede Nacht eines zu erstellen, richten Sie die nächtliche Aktualisierung ein (siehe [Aktuell halten](#aktuell-halten)); bis dahin zeigt der Dialog **Not scheduled yet**. Einrichten kann dies nur, wer das Projekt ändern darf.

Ein Pack, das nicht vollständig erstellt werden kann, lässt den Ladevorgang nie fehlschlagen:

- Ist das Reporting für Ihren Workspace deaktiviert, besteht das Pack nur aus der Excel-Arbeitsmappe, und die Ausführung meldet **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- Hat ein von jemand anderem erstelltes Dashboard bereits die Adresse, die Data Foundation für das GuV-Dashboard benötigt, bleibt dieses Dashboard unverändert und das PDF wird nicht erstellt. Die Meldung nennt die Adresse; geben Sie dem anderen Dashboard eine andere Adresse und führen Sie dann **Laden** erneut aus.
- Schlägt ein Schritt des Packs fehl, zeigt die Liste **Status** eine gelbe Zeile **Board pack**, die den Schritt und den Grund nennt. Der Ladevorgang selbst war dennoch erfolgreich.

## Wiederherstellungspunkte

Ein Wiederherstellungspunkt wird zu Beginn jedes **Laden** oder **Apply changes** erstellt, unabhängig davon, wer ihn startet, einschließlich eines geplanten Ladevorgangs, sowie vor jeder Änderung an Zuordnungen oder Quellen. Er enthält die Tabellen des Modells, die Dimensionen und die Einstellungen, auf denen der nächste Ladevorgang aufbaut: Ihre Quellen, Dateien und Umlageregeln. Die letzten sieben für Ladevorgänge erstellten Punkte und die letzten fünf vor Änderungen erstellten Punkte bleiben erhalten, sodass Änderungen nie die für Ladevorgänge erstellten Punkte verdrängen. Ältere Punkte entfallen.

Um zurückzugehen, öffnen Sie **Aktionen > Wiederherstellen...**. Jeder Punkt zeigt, wann er erstellt wurde, und darunter, wie viele Tabellen seine Wiederherstellung zurückbringt, zum Beispiel **Puts back 12 tables.**, sowie eventuelle Warnungen. Wählen Sie einen Punkt und klicken Sie auf **Wiederherstellen**. **Wiederherstellen** wird angeboten, sobald ein Punkt existiert. Beim Wiederherstellen wird zuerst der aktuelle Zustand des Projekts als eigener Punkt festgehalten, sodass Sie erneut zurückgehen können. Anschließend werden die Tabellen, die Dimensionen und diese Einstellungen auf den früheren Stand zurückgesetzt, und der nächste Ladevorgang baut darauf auf. Eine Wiederherstellung auf die Quellen, die Sie bereits hatten, markiert diese nicht als geändert. Eine Ansicht, eine Dimension, die nicht gespeichert werden kann, oder eine Tabelle ohne gespeicherte Kopie wird in einer Warnung genannt, und der Rest wird wiederhergestellt. Ein bereits entfallener Wiederherstellungspunkt wird abgelehnt, und während ein Ladevorgang läuft, können Sie nicht wiederherstellen.

## Ein Projekt klonen

**Aktionen > Klonen...** kopiert das Projekt unter einem von Ihnen vergebenen Namen. Die Kopie behält die Vorlage, Ihre Änderungen am Modell sowie Ihre Kennzahlen und Analysepfade und lädt die Beispieldaten. Ihre Quellen sind nicht verbunden; verbinden Sie sie daher in der Kopie, bevor Sie laden. Sie können weiterarbeiten, während die Kopie erstellt wird, und **Projekt öffnen** bringt Sie zu ihr, sobald sie bereit ist.

## Als eigene Vorlage speichern

Speichern Sie die Einrichtung eines Projekts, um sie für den nächsten Kunden oder die nächste Entität wiederzuverwenden. Öffnen Sie **Aktionen > Save as my template...**, wählen Sie das Dokumentenkonto und benennen Sie die Datei. Die Endung `.zip` wird ergänzt, wenn Sie sie weglassen. Das Überschreiben einer vorhandenen Datei wird abgelehnt; wählen Sie daher einen anderen Namen.

Die Datei enthält die Struktur des Projekts, Ihre Änderungen am Modell, Kennzahlen und Analysepfade, die Geschäftsbezeichnungen für Entitäten und Konten sowie die Zeilen der Konfigurationstabellen der Vorlage, etwa die Aktivitätszuordnung von [Cost to Serve](/de/guides/projects/cost-to-serve/) oder die Richtlinienbandbreiten von [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/). Nicht enthalten sind Verbindungen, Dateien, der nächtliche Zeitplan, Ausführungen, Wiederherstellungspunkte, das Board Pack und die Zugriffsberechtigungen.

Um sie zu verwenden, erstellen Sie ein Projekt, wählen Sie unter **Starten mit** die Option **From a template file...** und wählen Sie Dokumentenkonto und Pfad. Das neue Projekt ist privat, und jede Quelle wartet darauf, verbunden zu werden. Eine spätere Version der Vorlage führt ihre Änderungen um die von Ihnen bearbeiteten Schritte herum zusammen. Gibt es unter dem Pfad keine Datei, wird nichts erstellt und Sie erhalten eine Meldung. Jeder, der das Dokumentenkonto lesen kann, kann aus der Datei installieren. Um sie in einem anderen Workspace zu verwenden, laden Sie die Datei herunter und dort wieder hoch.

## Offene Fragen mit Ask klären

Nach einem Ladevorgang kann ein Projekt noch auf drei Arten von Angaben warten: Konten, die der Kontenplan ohne Typ lässt, Codes, die mehr als eine Quelle verwendet, und Spalten in Ihren Dateien, die keiner Zuordnung entsprechen. Bitten Sie den Assistenten, sie zu klären: Verwenden Sie in einem KI-Assistenten über MCP den Prompt **Resolve Data Foundation residue**. Er liest, was aussteht, und schlägt für jeden Punkt eine Antwort mit Begründung vor.

Der Assistent schreibt nichts. Sie übernehmen seine Antworten dort, wo Sie auch selbst geantwortet hätten: Konten und Codes unter **Codes, die auf Ihre Antwort warten** und Dateispalten in der Zuordnung der Datei. Er schlägt nie eine Entität vor.

## Das Projekt übergeben

Die Checkliste **Einrichtung** hat nach **Hierarchien prüfen** vier abschließende Punkte:

- **Nächtliche Aktualisierung einrichten** ist erledigt, sobald **Nächtlich aktualisieren** aktiviert ist.
- **Mit Ihrem Team teilen** ist erledigt, sobald außer der Person, die das Projekt eingerichtet hat, noch jemand Mitglied ist.
- **Nachweispaket herunterladen** ist erledigt, wenn Sie das Paket nach dem letzten erfolgreichen Ladevorgang herunterladen.
- **Projekt an seinen Eigentümer übergeben** ist erledigt, sobald ein anderer Architect als die Person existiert, die das Projekt eingerichtet hat, und die Summen übereinstimmen. Solange dieser Punkt nicht erledigt ist, nennt die Checkliste, was zu tun ist: Machen Sie den Verantwortlichen des Kunden zum Architect dieses Projekts und entfernen Sie sich dann aus dessen Mitgliedern.

Die Checkliste zeigt, wer das Projekt eingerichtet hat (**Set up by**).

## Mit einer Vorlage auf dem Modell aufbauen

Eine Vorlage baut ihre Berichte und Modelle auf dem Common Finance Model auf, sodass sie unabhängig davon, welche ERPs es speisen, gleich funktionieren. Wenn Sie ein Projekt aus einer Vorlage wie **Enterprise Profitability** starten, erstellt sie:

- Die [Tabellen des Common Finance Model](#tabellen-des-common-finance-model), leer oder mit Beispieldaten gefüllt.
- Die Dimensionen **Entität**, **Konto**, **Abteilung**, **Kunde**, **Produkt**, **Segment 1** und **Segment 2**, aufgebaut aus diesen Tabellen. Siehe [Hierarchien](#hierarchien).
- Den Workflow **Laden** und die Workflows, die er ausführt, um Ihr ERP und Ihre Dateien zu lesen, zu überführen, die Bereitschaft zu prüfen und die Modelle der Vorlage aufzubauen.
- Die eigenen Berichte und Modelle der Vorlage. **Enterprise Profitability** fügt eine GuV-Tabelle mit Umsatz, Umsatzkosten, Bruttomarge, direkten und Gemeinkosten-Betriebsaufwendungen, Deckungsbeitrag und operativer Marge hinzu, dazu Margenbrücken im Vorjahres- und Budgetvergleich.
- Kennzahlen und einen Analysepfad, um Fragen zu den Ergebnissen zu stellen.

Unter **Starten mit** stehen drei Vorlagen zur Verfügung, die alle auf demselben Modell aufbauen:

| Vorlage | Fügt hinzu |
|---|---|
| **Enterprise Profitability** | Die Gewinn- und Verlustrechnung und Margenbrücken. |
| **Cost to Serve** | Die Kosten der Betreuung jedes Kunden und die Marge danach. Siehe [Cost to Serve](/de/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | Das Gewinnniveau jeder Entität im Vergleich zu Ihrer Richtlinienbandbreite sowie die Anpassung. Siehe [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/). |

**From a template file...** startet mit einem von Ihnen gespeicherten Projekt. Siehe [Als eigene Vorlage speichern](#als-eigene-vorlage-speichern).

Um sich umzusehen, bevor Sie Ihr eigenes ERP verbinden, markieren Sie beim Erstellen des Projekts **Mit Beispieldaten starten**. Das Projekt führt sofort einen ersten Ladevorgang aus, sodass die Registerkarte **Foundation** ein vollständiges Beispiel zeigt, einschließlich einer Euro-Entität, die in US-Dollar umgerechnet wird. Wenn Sie Ihr eigenes ERP verbinden oder eigene Dateien hinzufügen, werden die Beispieldaten entfernt und Ihre Daten treten an ihre Stelle. Wird das Entfernen unterbrochen, schließt der nächste **Laden**-Vorgang es ab. Ein eigener Ordner namens `sample` wird nie entfernt: Die Statusseite weist darauf hin, dass die Beispieldaten diesen Ordner belegen und die anderen Tabellen darin daher nicht gelesen werden, und bittet Sie, sie in einen Ordner mit einem anderen Namen zu verschieben.

## Die Registerkarte Foundation

Auf der Registerkarte **Foundation** verbinden, laden und prüfen Sie Ihre Daten. Eine Leiste links listet vier Seiten auf:

| Seite | Inhalt |
|---|---|
| **Status** | Der Zustand des Projekts: **Letzter Ladevorgang** mit den Schaltflächen **Laden**, **Aktualisieren** und **Nächtlich aktualisieren**, **What to do next**, die Checkliste **Einrichtung**, **Daten geladen**, **Perioden**, **Bereitschaft** und das Menü **Aktionen**. |
| **Benötigte Antworten** | Die Fragen, die auf Sie warten, etwa Codes, die mehr als eine Quelle verwendet, bei denen Sie angeben, ob sie dasselbe bedeuten. |
| **Quellenabdeckung** | Wo sich Quellen für ein Unternehmen und einen Monat überschneiden oder Lücken lassen und welche Quelle ab wann zählt. |
| **Quellen** | Jede Quelle in **Load order**, mit **Bearbeiten** und **Remove this source**, die Karten **Gruppe** und **Names** sowie **Connect a system** (oder **Connect another system**), wo Sie eine Systemart wählen, ihre Verbindung auswählen, die Unternehmen und die Anzahl der zu ladenden Monate Verlauf festlegen oder eine Datei hinzufügen. Die hinzugefügten Dateien befinden sich in der Karte **Dateien**. |

Badges in der Leiste zählen, was Aufmerksamkeit erfordert: die offenen Fragen auf **Benötigte Antworten**, die Abdeckungsprobleme auf **Quellenabdeckung** und die Quellen auf **Quellen**. **Status** zeigt kein Badge. Das Ergebnis eines **Laden** oder **Apply changes** und das Statusbanner werden über der jeweils geöffneten Seite angezeigt, sodass Sie sie auf jeder Seite sehen. Die Schaltflächen auf **Status**, die auf eine Frage oder ein Abdeckungsproblem verweisen, etwa **Answer codes ›** und **Choose sources ›**, führen Sie zu dieser Seite. Wenn Sie **Benötigte Antworten** oder **Quellenabdeckung** schließen, kehren Sie zu **Status** zurück.

Wenn Sie Ihre Quellen ändern, zeigt eine Leiste über jeder Seite **You have changed your sources. Press Apply changes to use them.** Sie enthält **Show what changed** und **Apply changes** und ist die einzige Stelle, an der eine Änderung angewendet wird. Wenn nichts auf die Anwendung wartet, ist **Laden** die Hauptschaltfläche auf **Status**. Auf **Status** listet **What to do next** zuerst Probleme und dann Punkte, die Aufmerksamkeit erfordern, durchgehend über beide Gruppen nummeriert. Auf **Benötigte Antworten** bietet **Answer all** die Optionen **Accept suggestions**, **All the same** und **All different**. Auf **Quellenabdeckung** speichert **Save choice**, welche Quelle ab wann zählt.

Die Checkliste **Einrichtung** lautet: **Daten verbinden**, **Daten laden**, **Prüfen, ob die Summen übereinstimmen**, **Hierarchien prüfen**, **Nächtliche Aktualisierung einrichten**, **Mit Ihrem Team teilen**, **Nachweispaket herunterladen** und **Projekt an seinen Eigentümer übergeben**. Der aktuelle Punkt ist fett dargestellt. Geschäftsbezeichnungen, die hinzugefügten Dateien und ihr Zuordnungsstatus (**✓ Bestätigt** oder **○ Wartet auf Bestätigung**) sowie das Bereitschaftsraster mit einer Zeile pro Entität, Periode und Prüfung und der zugehörigen Spalte **Was zu tun ist** befinden sich auf denselben Seiten. Siehe [Geschäftsbezeichnungen](#geschäftsbezeichnungen).

Während ein Ladevorgang läuft, aktualisiert sich die Registerkarte selbst und liest weiter, auch wenn ein Lesevorgang fehlschlägt. Kann der Status nicht gelesen werden, erscheint **Der Foundation-Status konnte nicht gelesen werden.** mit **Erneut versuchen**, das ihn neu liest; die Registerkarte versucht es außerdem einmal selbst erneut, bevor sie die Meldung anzeigt, und die Meldung verschwindet, sobald der Server antwortet.

Die Seite **Status** weist außerdem auf Folgendes hin:

- Ein Ordner unter `/sources/`, dessen Tabellen die benötigten Spalten fehlen, wird nicht als Quelle hinzugefügt. Ein Hinweis nennt jede ausgelassene Tabelle und die fehlende Spalte. Fügen Sie die Spalte hinzu und klicken Sie dann auf **Laden** oder **Apply changes**.
- War ein Ladevorgang erfolgreich, hat aber keine Hauptbuchzeilen zum Vergleich geliefert, meldet eine gelbe Zeile **Model P&L ties to GL**, dass nichts abgestimmt wurde. **Prüfen, ob die Summen übereinstimmen** bleibt in der Einrichtungs-Checkliste ausstehend und nicht erledigt, bis etwas abgestimmt wurde. Fügen Sie eine Quelle mit Hauptbuchzeilen hinzu und klicken Sie dann auf **Laden**.

Die Einrichtungs-Checkliste verfolgt Ihren Fortschritt:

- **Daten verbinden** und **Daten laden** werden automatisch abgehakt, sobald eine Quelle angebunden ist und ein Ladevorgang erfolgreich war.
- **Prüfen, ob die Summen übereinstimmen** wird automatisch abgehakt, wenn die Abstimmungsprüfungen erfolgreich sind.
- **Hierarchien prüfen**: Klicken Sie auf **Dimensionen öffnen**, um die Hierarchien für Entität, Konto und Abteilung zu prüfen, und markieren Sie dann **Ich habe sie geprüft**. Diese bestätigen Sie selbst.
- **Nächtliche Aktualisierung einrichten**, **Mit Ihrem Team teilen**, **Nachweispaket herunterladen** und **Projekt an seinen Eigentümer übergeben** schließen die Liste ab. Siehe [Das Projekt übergeben](#das-projekt-übergeben) und [Projektzugriff verwalten](/de/guides/projects/managing-projects/#projektzugriff-verwalten).

Das Menü **Aktionen** enthält **Umlagen...**, **Board pack...**, **Klonen...**, **Wiederherstellen...** und **Save as my template...**. Siehe [Umlageregeln](#umlageregeln), [Board Pack](#board-pack), [Ein Projekt klonen](#ein-projekt-klonen), [Wiederherstellungspunkte](#wiederherstellungspunkte) und [Als eigene Vorlage speichern](#als-eigene-vorlage-speichern).

## Tabellen des Common Finance Model

Data Foundation überführt jede Quelle, ob ERP oder Datei, in dieselben fünfzehn Tabellen, sodass darauf aufbauende Berichte, Kennzahlen und Modelle unabhängig von der Quelle gleich funktionieren. Jede Zeile erfasst außerdem ihr Quellsystem und den Zeitpunkt des Lesens. Die Spalte **Dataset** enthält den Namen, den Sie beim Hinzufügen einer Datei wählen.

| Dataset | Tabelle | Inhalt |
|---|---|---|
| Entitäten | `cfm_entity` | Rechtliche Einheiten mit übergeordneter Entität, Landes- und Konzernwährung sowie Land. |
| Entitätszuordnung | `cfm_entity_map` | Entitätscodes der Quellen und die Entität, zu der jeder gehört. Siehe [Entitätszuordnung](#entitätszuordnung). |
| Wechselkurse | `cfm_fx_rate` | Monatliche Durchschnitts-, Stichtags- und historische Kurse je Währungspaar. Siehe [Wechselkurse](#wechselkurse). |
| Geschäftskalender | `cfm_fiscal_calendar` | Eine Zeile pro Geschäftsperiode einer Entität, mit Start- und Enddatum und der Angabe, ob sie abgeschlossen ist. |
| Kontenplan | `cfm_account` | Konten mit übergeordnetem Konto, Typ (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), Abschlussbestandteil, Normalsaldo und Kurstyp. |
| Abteilungen | `cfm_department` | Abteilungen und Kostenstellen mit übergeordneter Abteilung und Profitcenter. |
| Produkte | `cfm_product` | Produktstammdaten mit übergeordnetem Produkt, Familie, Gruppe, Mengeneinheit und Standardkosten. |
| Kunden | `cfm_customer` | Kundenstammdaten mit übergeordnetem Kunden, Gruppe, Region und Land. Kundennamen werden nicht maskiert. |
| Segmentwerte | `cfm_segment` | Segmentwerte mit Name und übergeordnetem Wert. Siehe [Hierarchien](#hierarchien). |
| Hauptbuch | `cfm_gl_journal` | Journalzeilen in Transaktions-, Landes- und Berichtswährung. |
| Saldenliste | `cfm_trial_balance` | Soll, Haben und Saldo je Periode nach Entität, Konto und Abteilung, in Landes- und Berichtswährung. |
| Verkaufspositionen | `cfm_sales_line` | Fakturierte Verkaufspositionen mit Menge, Brutto-, Rabatt-, Netto- und Umsatzkostenbeträgen. |
| Lagerbestände | `cfm_inventory_balance` | Lagerbestand am Periodenende nach Produkt und Lager. |
| Budget | `cfm_budget` | Budget und Prognose nach Szenario, Version, Konto und Abteilung. |
| Verteilungstreiber | `cfm_stat_driver` | Statistische Treiber wie Mitarbeiterzahl, Quadratmeter oder Stückzahlen. |

Perioden werden als `YYYY-MM` geschrieben, und Transaktionen werden nach Buchungsperiode zugeordnet. Das Budget ist optional: Ein ERP ohne Budgets lädt trotzdem alles andere.

Eine Saldenlistendatei kann Soll- und Habenspalten, eine Saldospalte oder beides enthalten. Gibt es nur Soll und Haben, ist der Saldo Soll minus Haben, und eine leere Seite zählt als null. Gibt es nur einen Saldo, wird ein positiver Saldo zum Soll und ein negativer Saldo zum Haben, als positiver Betrag. Eine Abteilungsspalte ist optional.

## Fehlerbehebung

| Symptom | Was zu tun ist |
|---|---|
| **Verbindung testen** meldet, dass das ERP die Anmeldedaten abgelehnt hat | Prüfen Sie die Anmeldedaten der Verbindung und ob sich der Integrationsbenutzer beim ERP anmelden kann. |
| **Verbindung testen** zeigt **Fehlende Berechtigung** für ein Dataset | Bitten Sie Ihren ERP-Administrator, die genannten Berechtigungen hinzuzufügen. Der [Verbindungsleitfaden](/de/guides/connections/) für Ihr ERP listet auf, was die Verbindung benötigt. |
| Eine ERP-Fehlermeldung ist kürzer als die des ERP selbst | PlaidCloud entfernt Anmeldedaten, Token und Schlüssel aus Anbieterfehlern, bevor sie angezeigt werden, daher fehlen einige Details. Führen Sie **Verbindung testen** aus, um zu sehen, welches Dataset betroffen ist. |
| **Daten geladen** ist für eine Periode ein Problem | Ein ERP-Lesevorgang für diese Periode ist fehlgeschlagen. Führen Sie **Laden** erneut aus; bereits geladene Perioden werden übersprungen. |
| **Konten fehlen im Kontenplan** ist ein Problem | Fügen Sie die fehlenden Konten dem Kontenplan im ERP oder in Ihrer Datei hinzu und führen Sie **Laden** erneut aus. |
| **Währungsumrechnung** ist ein Problem | Für die Währung einer Entität gibt es für diese Periode keinen Kurs in die Berichtswährung, oder es wurde keine eindeutige Berichtswährung gefunden. Fügen Sie die Kurse einer Datei **Wechselkurse** hinzu, prüfen Sie, ob die Verbindung die Wechselkurse des ERP lesen kann, oder setzen Sie die Projektvariable `reporting_currency`. Führen Sie dann **Laden** erneut aus. |
| **Währungsumrechnung** erfordert Aufmerksamkeit | Bilanz-, Lagerbestands- oder Budgetzeilen haben für die Periode keinen Stichtags-, historischen oder Plankurs. Die Gewinn- und Verlustrechnung ist nicht betroffen. Fügen Sie die Kurse hinzu, einschließlich Plankursen für Budgetmonate, und führen Sie **Laden** erneut aus. |
| **Codes, die auf Ihre Antwort warten** erfordert Aufmerksamkeit | Klicken Sie auf **Answer codes ›**, beantworten Sie jeden Code und klicken Sie auf **Apply changes**. |
| **Welche Quelle welche Monate abdeckt** erfordert Aufmerksamkeit | Klicken Sie auf **Choose sources ›**, wählen Sie die Quelle, klicken Sie auf **Save choice** und klicken Sie auf **Apply changes**. |
| **Intercompany balances** ist rot oder gelb | Prüfen Sie die Paare in **Konzerninterne Paare**. Buchen Sie die fehlende Seite, ergänzen Sie das Partnerunternehmen auf den Zeilen oder fügen Sie den fehlenden Kurs hinzu. |
| **Group views are off** | Bitten Sie einen Architect, unter **Gruppe** die Option **Everyone on the project may see the group results** zu markieren. |
| **Nicht zugeordnete Entitäten** ist ein Problem | Fügen Sie die Entität den Entitätsstammdaten hinzu oder ordnen Sie ihren Code in der Datei **Entitätszuordnung** einer vorhandenen Entität zu und führen Sie **Laden** erneut aus. |
