**Data Foundation** ist die Finanzdatenbasis für Ihre PlaidCloud-Projekte. Sein **Common Finance Model** führt ERP-Daten aus mehreren ERP-Systemen und aus mehreren Instanzen jedes Systems in einem einzigen Modell zusammen: ein Kontenplan, ein Satz von Entitäten und eine Berichtswährung. Berichte, Kennzahlen und KI-Assistenten, die auf dem Modell aufbauen, lesen alle dieselben Zahlen, unabhängig davon, aus welchem ERP sie stammen.

Ihr ERP wird über seine PlaidCloud-Verbindung angebunden, sodass Hauptbuch, Saldenliste, Stammdaten und Budgets direkt aus der Quelle ankommen, ohne dass etwas exportiert werden muss. Dateien ergänzen Daten, die ein System nicht enthält, etwa Wechselkurse, Verteilungstreiber oder ein Budget, das außerhalb des ERP geführt wird, und können die ERP-Zeilen ersetzen, die sie abdecken. **Laden** überführt jede Quelle in das Modell, rechnet sie in die Berichtswährung um und prüft, ob sie übereinstimmt, alles auf der Registerkarte **Foundation** des Projekts. Wenn Quellen denselben Code für verschiedene Dinge verwenden, legen Sie fest, ob sie dasselbe meinen, und eine Management-Konsolidierung erstellt die Gewinn- und Verlustrechnung des Konzerns mit eliminierten Intercompany-Beziehungen. Vorlagen wie **Enterprise Profitability** bauen ihre Berichte und Modelle darauf auf.

## ERP verbinden

Ihr ERP wird über seine PlaidCloud-Verbindung an Data Foundation angebunden. Data Foundation liest Hauptbuch, Saldenliste, Stammdaten, Wechselkurse und Budgets direkt daraus und liest ausschließlich. Sie können eine vorhandene Verbindung auswählen oder auf der Registerkarte eine neue erstellen; die [Verbindungsanleitungen](/de/guides/connections/) behandeln die Zugriffseinrichtung jedes ERP.

<Steps>

1. Öffnen Sie in Analyze **Projekte** und klicken Sie auf **Neues Projekt**. Geben Sie einen Namen ein und wählen Sie unter **Starten mit** eine Vorlage, etwa **Enterprise Profitability (Vorlage)**, statt **Leeres Projekt**. Klicken Sie auf **Erstellen**.

   Das Projekt öffnet sich auf seiner Registerkarte **Foundation**. Es ist privat für Sie, und Sie sind sein einziger Architect, bis Sie es teilen.

2. Wählen Sie auf der Registerkarte **Foundation** eine vorhandene Verbindung für Ihr ERP aus oder wählen Sie **Neue Verbindung erstellen**. Jede vorhandene Verbindung listet die Workflows auf, die sie bereits verwenden, oder zeigt **Noch von keinem Workflow verwendet** an.

3. Geben Sie für eine neue Verbindung einen **Verbindungsname** ein, wählen Sie die **Umgebung** und füllen Sie die Anmeldeinformationen aus, die Ihre ERP-Verbindung verlangt.

   Haben Sie die Anmeldeinformationen noch nicht? Das Formular zeigt eine vorbereitete Zugriffsanfrage für Ihren ERP-Administrator. Klicken Sie auf **Anfrage kopieren** oder **Anfrage per E-Mail senden**, senden Sie sie ab und geben Sie die Werte ein, die Sie zurückerhalten.

4. Klicken Sie auf **Verbindung testen**. PlaidCloud meldet sich an und versucht, jedes Dataset zu lesen, und listet dann jedes als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** auf. Fehlt etwas, nennt es die Berechtigungen, die Sie Ihren ERP-Administrator hinzufügen lassen sollten.

5. Legen Sie **Monate Verlauf** fest: wie viele Monate rückwirkend geladen werden, von 1 bis 120. Der Standard ist 24.

6. Markieren Sie bei einer vorhandenen Verbindung die zu ladenden Entitäten, oder lassen Sie alle unmarkiert, um jede Entität zu laden. Inaktive Entitäten und Eliminierungsentitäten bleiben ausgeblendet, bis Sie sich für ihre Anzeige entscheiden. Klicken Sie dann auf **Verbinden**.

7. Klicken Sie bei einer neuen Verbindung auf **Verbinden**, um sie zu erstellen. Markieren Sie dann die zu ladenden Entitäten und klicken Sie erneut auf **Verbinden**, um sie zu speichern. Bis dahin wird jede Entität geladen.

8. Um ein weiteres ERP-System oder eine weitere Instanz einzubinden, wiederholen Sie diese Schritte und markieren Sie **Add this as another source instead of replacing the current one**, bevor Sie auf **Verbinden** klicken. Ohne dies ersetzt die neue Verbindung die aktuelle Quelle.

</Steps>

Nach dem Verbinden gibt die Karte an, welche Verbindung, Umgebung, Entitäten und Monate Verlauf das Projekt lädt.

Jeder Ladevorgang liest nur, was sich geändert hat: Offene Perioden und die letzte abgeschlossene Periode werden erneut gelesen, und bereits geladene abgeschlossene Perioden bleiben erhalten. Wenn Sie **Monate Verlauf** erhöhen, werden nur die hinzugekommenen Monate gelesen. Ein geänderter Wechselkurs, eine geänderte Entitätszuordnung oder eine geänderte Berichtswährung liest die betroffenen Monate erneut.

## Quellen

Jedes ERP-System und jede Instanz, aus der das Projekt lädt, ist eine Quelle. Die Liste **Quellen** auf der Registerkarte **Foundation** zeigt für jede eine Zeile der Reihe nach, mit ihrem Namen, wann sie zuletzt geladen wurde und wie viele Zeilen sie geliefert hat, sowie den Berichtsbüchern, die sie liest, zum Beispiel `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Eine Quelle, die noch nicht geladen wurde, zeigt **not loaded yet** an. Dateien, die Sie bestätigen, sind ebenfalls Quellen.

Öffnen Sie **Erweitert** bei einer Quelle, um zu ändern, wie sie verwendet wird:

| Einstellung | Was sie bewirkt |
|---|---|
| **Name** | Die Bezeichnung, die Berichte, Zuordnungsfragen und Meldungen für die Quelle verwenden. |
| **Platz in der Reihenfolge** | Wo die Quelle eingeordnet ist. Wenn zwei Quellen denselben Monat desselben Unternehmens abdecken, gewinnt die in der Reihenfolge höhere. |
| **Berichtsbücher, durch Kommas getrennt** | Die zu lesenden Buchführungsbücher, für ein System, das mehr als eines führt. **Alle Berichtsbücher** liest jedes Buch. |
| **Unternehmen**, **Von (2026-01)** und **Bis (2026-12)** | Die Monate, die diese Quelle für jedes Unternehmen liefert. Lassen Sie einen Monat leer für keine Begrenzung. Schreiben Sie Monate als Jahr und Monat, zum Beispiel `2026-03`. |

Klicken Sie auf **Speichern**, um Ihre Änderungen zu behalten. Um eine Quelle zu entfernen, klicken Sie auf **Diese Quelle entfernen** und bestätigen Sie mit **Entfernen**. Alles, was daraus geladen wurde, wird gelöscht, und Sie können sie später erneut verbinden.

Das Ändern von Quellen liest Ihr ERP nicht erneut. Die Karte **Letzter Ladevorgang** zeigt **Changes not applied yet** an, bis Sie auf **Änderungen anwenden** klicken, was einen Ladevorgang aus den bereits abgerufenen Daten ausführt: Er überführt die Quellen erneut mit Ihrer neuen Reihenfolge, den Zuordnungen, Namen und Dateien und baut das Modell neu auf. Klicken Sie auf **Laden**, wenn Sie zusätzlich frische Daten aus den ERPs wollen.

## Dateien für Daten außerhalb Ihres ERP hinzufügen

Dateien ergänzen Ihre ERP-Verbindung um Daten, die ein System nicht enthält, etwa Wechselkurse, Verteilungstreiber, eine [Entitätszuordnung](#entitätszuordnung) oder ein Budget, das außerhalb des ERP geführt wird. Jede Datei gehört zu einem der Datasets, die unter [Tabellen des Common Finance Model](#tabellen-des-common-finance-model) aufgeführt sind.

<Steps>

1. Wählen Sie unter **Dateien** das **Dokumentenkonto** aus, in dem die Datei gespeichert wird.

2. Legen Sie eine CSV- oder Excel-Datei auf **CSV- oder Excel-Datei hier ablegen** ab oder klicken Sie auf **Datei auswählen**. Die Datei wird in den Ordner `/foundation/` des Dokumentenkontos hochgeladen.

   Geben Sie für eine Datei, die sich bereits im Dokumentenkonto befindet, ihren **Dateipfad** ein, zum Beispiel `/foundation/budget.csv`, und klicken Sie auf **Datei hinzufügen**.

   Um jeden Monat eine neue Datei zu lesen, fügen Sie jede Datei in einem Ordner mit passendem Namen hinzu: Geben Sie den Ordner ein und was **File names that** enthalten, mit denen sie beginnen, mit denen sie enden, genau übereinstimmen oder als Muster übereinstimmen, und klicken Sie auf **Add files**. Dateien in Ordnern darin werden nicht gelesen.

3. PlaidCloud liest die Datei und schlägt eine Zuordnung vor:

   - **Erkanntes Trennzeichen, Dezimaltrennzeichen und Datumsangaben.** Das Trennzeichen (Komma, Semikolon, Tabulator oder senkrechter Strich), das Dezimaltrennzeichen und das Datumsformat werden für Sie erkannt.
   - **Dataset**: die Tabelle des Common Finance Model, zu der die Datei gehört, abgeleitet aus dem Dateinamen und den Spaltenüberschriften. Wenn die Zuordnung nicht eindeutig ist, wählen Sie sie aus der Liste.
   - **Dezimaltrennzeichen**: **Punkt (1,234.56)** oder **Komma (1.234,56)**.
   - **Datumsformat**: wird angezeigt, wenn die Datei Datumsangaben enthält. Ändern Sie es, wenn das erkannte Format falsch ist: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` oder `MM/DD/YYYY`.
   - Ein Raster aus **Spalte in Datei**, **Typ**, **Beispiele** und **Geht nach**. Ändern Sie **Geht nach**, um eine Spalte an ein anderes Feld zu senden oder auf **Nicht laden**.

4. Beantworten Sie die Fragen, die die Datei aufwirft, etwa **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** oder **Are revenues shown as negative numbers?** Jede wird nur gestellt, wenn die Datei es nicht bereits sagt.

5. Prüfen Sie, wohin jede Spalte geht, und klicken Sie dann auf **Zuordnung bestätigen**.

</Steps>

Diese Optionen erscheinen bei einer Datei, wenn sie zutreffen:

| Option | Verwenden Sie sie, um |
|---|---|
| **Which source do these rows apply to?** | eine Codezuordnungsdatei auf eine Quelle zu beschränken. **Every source** wendet sie auf alle an. |
| **Where does this file come from?** | festzulegen, ob die Datei **This project's own codes** enthält oder von **Another system** stammt, das Sie benennen, zum Beispiel `SAP Germany export`. Eine Datei aus einem anderen System wird wie eine ERP-Quelle auf gemeinsame Codes geprüft. |
| **Split … into … parts at each …** (unter **Erweitert**) | eine Spalte aufzuteilen, die mehrere Werte enthält, etwa `100-200-300`, und jeden Teil an ein eigenes Feld zu senden. |
| **Which currency do you report in?** | die Berichtswährung festzulegen, wenn das Projekt noch keine hat. Schreiben Sie sie mit drei Buchstaben, zum Beispiel `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | die Ergebnisse Ihres Konsolidierungssystems zu laden, damit die Gewinn- und Verlustrechnung des Konzerns [abgestimmt](#mit-ihrem-konsolidierungssystem-abstimmen) werden kann. |

Um eine Datei aus dem Projekt zu entfernen, klicken Sie unter **Dateien** neben ihr auf **Entfernen** oder bei ihrer Zuordnung auf **Remove this file** und bestätigen Sie. Ihre Zahlen verlassen Ihre Berichte beim nächsten Klick auf **Änderungen anwenden**.

Wenn PlaidCloud das Dataset, das Dezimaltrennzeichen oder die Datumsreihenfolge nicht selbst bestimmen kann, zum Beispiel bei einer Datei, deren Datumsangaben als Tag/Monat oder Monat/Tag gelesen werden könnten, bittet es Sie, vor dem Bestätigen zu wählen. Das Hinzufügen einer zweiten Datei für dasselbe Dataset ersetzt die erste.

Akzeptierte Dateien sind CSV-, TSV- und TXT-Textdateien, Excel-`.xlsx`-Dateien (gelesen wird das erste Blatt) und Parquet-Dateien.

<Aside type="note">
Eine fehlende oder leere Datei stoppt nie einen Ladevorgang. Beim Hinzufügen heißt es, dass noch nichts zuzuordnen ist, und ein Ladevorgang endet mit einer Warnung, die den Pfad nennt, und lässt dieses Dataset leer. Fügen Sie die Datei erneut hinzu, sobald sie existiert.
</Aside>

## Daten laden

Klicken Sie auf **Laden** auf der Karte **Laden** oder der Karte **Letzter Ladevorgang**. Der Ladevorgang liest Ihr verbundenes ERP und Ihre bestätigten Dateien, überführt sie in das Common Finance Model, rechnet sie in die Berichtswährung um, führt die Bereitschaftsprüfungen aus und baut die Modelle der Vorlage neu auf.

- Pro Projekt läuft jeweils nur ein Ladevorgang. Ein zweites **Laden** oder **Änderungen anwenden** meldet, dass bereits ein Ladevorgang läuft, und Sie können Quellen nicht ändern, solange einer läuft.
- Wenn andere Workflows dieselbe ERP-Verbindung verwenden, listet der erste Ladevorgang sie auf und bittet Sie um Bestätigung, weil ein Ladevorgang aus dem ERP liest und diese Workflows verlangsamen kann. Klicken Sie auf **Trotzdem laden**, um fortzufahren.
- Ein fehlgeschlagener Ladevorgang wird rot angezeigt und versteckt sich nie hinter früheren Ergebnissen. Zeilen aus einem früheren Ladevorgang zeigen **Aus einem früheren Ladevorgang. Erneut laden.** an, bis ein Ladevorgang erfolgreich ist.
- Wenn eine Entität und Periode nicht gelesen werden kann, werden die übrigen trotzdem geladen. Führen Sie **Laden** erneut aus, um nur nachzuholen, was fehlgeschlagen ist.

### Zurückgehaltene Zeilen

Wenn sich Quellen überschneiden, behält ein Ladevorgang von jeder Zahl eine Kopie und hält die anderen zurück, statt sie doppelt zu zählen. Zurückgehaltene Zeilen werden mit ihrer Quelle, ihrer Entität und dem Grund erfasst, und der Ladevorgang endet mit einer Warnung, die die Anzahlen nennt, zum Beispiel `120 rows of NetSuite EU also provided by a source ranked ahead`. Die Gründe sind:

| Grund | Bedeutung |
|---|---|
| In einem anderen Buchführungsbuch | Die Zeile gehört zu einem Berichtsbuch, das die Quelle nicht lesen soll. |
| Außerhalb der Perioden, die die Quelle liefert | Die Zeile liegt außerhalb der Monate **Von** und **Bis**, die für das Unternehmen festgelegt sind. |
| Auch von einer höher eingestuften Quelle geliefert | Eine in der Reihenfolge höhere Quelle deckt dasselbe Unternehmen und denselben Monat ab. |
| Auch in einer früheren Datei der Quelle | Eine frühere Datei derselben Quelle deckt den Monat bereits ab. |
| Durch eine Datei ersetzt | Eine Datei ersetzt die ERP-Zeilen für diese Entität und diesen Monat. |
| Mit einem Code, den auch eine andere Quelle verwendet | Der Code braucht Ihre Antwort. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| Mit einem Code, der zwei Codes zugeordnet ist | Die Codezuordnung gibt dem Code zwei Antworten. |

Statistische Konten wandern zu den Verteilungstreibern statt ins Hauptbuch und werden als verschoben angezeigt, nicht als Problem.

### ERP-Daten und Dateien zusammen

Eine Datei ersetzt nur, was sie abdeckt, und die übrigen Zeilen aus Ihrem ERP bleiben.

- **Stammdatendateien** (Konten, Abteilungen, Kunden, Produkte und Segmentwerte) ersetzen die ERP-Zeilen mit demselben Code.
- **Bewegungsdatendateien** ersetzen die ERP-Zeilen für dieselbe Entität und denselben Monat. Hauptbuch- und Saldenlistendateien stimmen außerdem nach Ledger ab, Budgetdateien nach Szenario und statistische Treiberdateien nach Szenario und Treiber.

Wenn eine Datei später einen Monat nicht mehr abdeckt, kommen die Daten des ERP für diesen Monat beim nächsten Ladevorgang zurück.

## Entitätszuordnung

Jede Quelle benennt ihre Entitäten mit eigenen Codes. Die **Entitätszuordnung** ordnet diese Codes den Entitäten in Ihrem Entitätsstamm zu, sodass die Zeilen aus jeder Quelle bei derselben Entität landen.

Um eine zu verwenden, fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Entitätszuordnung**:

| Spalte | Enthält |
|---|---|
| `source_entity` | Den Code, wie die Quelle ihn führt, etwa einen Unternehmenscode. |
| `entity` | Die Entität, zu der er gehört, wie der Entitätsstamm sie benennt. |

- Ein Code, der nicht in der Zuordnung steht, wird unverändert verwendet.
- Mehrere Codes können einer Entität zugeordnet werden. Ihre Zeilen werden zusammengefasst, und ein Monat gilt als abgeschlossen, sobald er für alle abgeschlossen ist.
- Codes in der Zuordnung gelten für jede Quelle, daher müssen die Entitätscodes jeder Quelle quellenübergreifend eindeutig sein.
- Eine Zeile einer Datei **Entitäten** ersetzt die Entität des ERP mit demselben Entitätscode.

Die Prüfung **Nicht zugeordnete Entitäten** markiert jede Zeile, deren Entität weder im Entitätsstamm steht noch durch die Zuordnung einer zugeordnet ist. Solange kein Entitätsstamm geladen ist, zeigt sie **– Nicht zutreffend** an.

## Codes quellenübergreifend zuordnen

Zwei Quellen können denselben Code für verschiedene Dinge oder verschiedene Codes für dieselbe Sache verwenden. Wenn ein Code in mehr als einer Quelle vorkommt, hält Data Foundation seine Zeilen zurück, bis Sie sagen, ob er überall dasselbe bedeutet, damit jeder Betrag einmal gezählt wird. Die Prüfung **Codes, die auf Ihre Antwort warten** listet sie auf, und die Karte **Was als Nächstes zu tun ist** auf der Registerkarte **Foundation** hat eine Schaltfläche **Prüfen**.

**Prüfen** öffnet **Codes, die auf Ihre Antwort warten**. Es gruppiert die Codes danach, was sie sind: **Kontotypen**, **Unternehmen**, **Konten**, **Abteilungen**, **Profit-Center**, **Kunden**, **Produkte** und jede zusätzliche Kategorie. Für jeden Code zeigt es, wie ihn jede Quelle nennt, und einen Vorschlag:

- **Looks like the same thing**, wenn die Quellen dem Code denselben Namen geben.
- **Looks like different things**, wenn die Namen abweichen.
- **We can't tell. Please answer.**, wenn es keinen Anhaltspunkt gibt.

Beantworten Sie einen Code nach dem anderen mit **Yes, the same** oder **No, different**, oder beantworten Sie eine ganze Gruppe auf einmal mit **Accept all** (jeden Vorschlag übernehmen), **All the same** oder **All different**. Bei Konten können Sie auch eine ganze übergeordnete Gruppe des Kontenplans auf einmal beantworten. Wenn eine Quelle keine Kontotypen führt, wählen Sie **Use this type** für eine Gruppe von Konten: **Umsatz**, **Umsatzkosten**, **Betriebsaufwand**, **Neutrale Erträge und Aufwendungen**, **Vermögenswerte**, **Verbindlichkeiten** oder **Eigenkapital**.

Zuordnungen werden für jede Quelle und Dimension gespeichert, sodass eine Antwort für die Abteilungen einer Quelle nie die Konten einer anderen Quelle ändert. Antworten werden während der Eingabe gespeichert, mit **Saved. Press Apply changes to use your answers.** Klicken Sie auf **Änderungen anwenden**, um sie zu verwenden.

Sie können die Zuordnungen auch in einer Datei bereitstellen. Fügen Sie eine Datei mit dem Dataset **Code map** hinzu und wählen Sie **Which source do these rows apply to?**, um sie auf eine Quelle zu beschränken.

## Festlegen, welche Quelle ab wann zählt

Wenn zwei Quellen dieselben Monate liefern, bittet die Prüfung **Welche Quelle welche Monate abdeckt** Sie um eine Auswahl. Klicken Sie auf der Karte **Was als Nächstes zu tun ist** auf **Wählen, welche Quelle ab wann zählt**, um **Welche Quelle ab wann zählt** zu öffnen, das jede Überschneidung nach Unternehmen auflistet. Wählen Sie die Quelle, die zählt, geben Sie in **That month is** den Monat ein, ab dem sie zählt, zum Beispiel `2026-04`, und klicken Sie auf **Änderungen anwenden**. Die andere Quelle behält die früheren Monate.

Derselbe Dialog warnt, wenn zwei Quellen für eine Währung unterschiedliche Wechselkurse liefern; verwendet werden die Kurse der in der Reihenfolge höheren Quelle.

## Währungsumrechnung

Jeder Ladevorgang rechnet die Beträge aus Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget von ihrer lokalen Währung in eine Berichtswährung um. Berichte und Modelle lesen die umgerechneten Beträge, sodass Entitäten in verschiedenen Währungen aus jedem System korrekt summiert werden.

### Die Berichtswährung

Um die Berichtswährung zu wählen, setzen Sie die Projektvariable `reporting_currency` auf einen Währungscode wie `USD`. Siehe [Projektvariablen verwalten](/de/guides/projects/managing-projects/#projektvariablen-verwalten). Die Vorlage legt sie leer an. Solange sie leer ist, verwendet jeder Ladevorgang die erste der folgenden Möglichkeiten, die genau eine Währung nennt:

1. Die Konzernwährung der Entitäten.
2. Die lokale Währung der Entitäten der obersten Ebene, also derer ohne übergeordnete Entität.
3. Die lokale Währung der Dateien.

Wenn keine davon genau eine Währung nennt, zeigt **Währungsumrechnung** ein Problem an, bis Sie `reporting_currency` festlegen.

Beträge, die bereits in der Berichtswährung vorliegen, bleiben unverändert, sodass ein Projekt, dessen Daten alle in einer Währung vorliegen, keine Kurse braucht.

Umsatz-, Lagerbestands- und Budgetdateien können ebenfalls eine Währung tragen. Ordnen Sie eine Spalte mit dem Namen `Currency` oder `Local Currency` zu, und sie wird automatisch erkannt, und die lokalen Beträge der Datei werden in die Berichtswährung umgerechnet. Ein Konzern- oder Berichtsbetrag, der bereits in der Datei steht, bleibt unverändert. Die Standardkosten eines Produkts werden nicht umgerechnet.

### Wechselkurse

Ein Kurs rechnet für einen Monat eine Einheit einer Währung in die Berichtswährung um: Der umgerechnete Betrag ist der lokale Betrag mal dem Kurs.

- **Aus Ihrem ERP** liest jeder Ladevorgang die Wechselkurse, die das ERP führt.
- **Aus einer Datei**: Fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Wechselkurse**. Ein Kurs in der Datei ersetzt den Kurs des ERP für dieselben Währungen und denselben Monat. Verwenden Sie eine Datei, um in einer Währung zu berichten, für die Ihre ERPs keine Kurse veröffentlichen, oder um geplante Kurse für Budgetmonate hinzuzufügen.

| Spalte | Enthält |
|---|---|
| `from_currency` | Die Währung, aus der umgerechnet wird, zum Beispiel `EUR`. |
| `to_currency` | Die Berichtswährung, zum Beispiel `USD`. |
| `period` | Den Monat als `YYYY-MM`. |
| `average_rate` | Den Durchschnittskurs für den Monat. |
| `closing_rate` | Den Kurs am Monatsende. |
| `historical_rate` | Den historischen Kurs, für das Eigenkapital und für Konten, die auf den historischen Kurs gesetzt sind. |

Es werden nur Kurse in die Berichtswährung verwendet. Ein umgekehrt notierter Kurs, von der Berichtswährung in eine andere Währung, wird nicht invertiert.

### Welcher Kurs gilt

Jede Zeile wird aus ihrer eigenen Währung umgerechnet, sodass eine Zeile in einer anderen Währung als ihre Entität aus der Währung umgerechnet wird, in der sie vorliegt. Es gilt die erste Regel, die zur Zeile passt:

| Zeile | Kurs |
|---|---|
| Statistische und nicht buchende Konten | Nicht umgerechnet. |
| Bereits in der Berichtswährung | Nicht umgerechnet. |
| Konto mit einer Kursart | Dieser Kurs: Durchschnitts-, Stichtags- oder historischer Kurs. Historisch fällt auf den Stichtagskurs zurück, wenn kein historischer Kurs vorhanden ist. Aus einem ERP ist die Kursart die eigene Kursart des Kontos. Ordnen Sie in einer Kontenplandatei eine Spalte der Kursart `fx_rate_type` mit `average`, `closing` oder `historical` zu. |
| Umsatzzeile | Der Durchschnittskurs der Periode. |
| Lagerbestand | Der Stichtagskurs der Periode. |
| Budgetzeile | Nach Konto, wie das Hauptbuch: der Durchschnittskurs für Konten der Gewinn- und Verlustrechnung und der Stichtagskurs für Bilanzkonten. |
| Konto der Gewinn- und Verlustrechnung | Der Durchschnittskurs der Periode. |
| Eigenkapitalkonto | Der historische Kurs oder der Stichtagskurs, wenn kein historischer Kurs vorhanden ist. |
| Jedes andere Bilanzkonto | Der Stichtagskurs der Periode. |

Umgerechnete Beträge werden nicht gerundet, damit sich die Summen nicht verschieben.

<Aside type="note">
Die Saldenliste enthält die Bewegungen jeder Periode, sodass Bilanzbeträge die zum Stichtagskurs des jeweiligen Monats umgerechneten Bewegungen jedes Monats sind. Sie sind keine zum Kurs am Periodenende neu umgerechnete Bilanz, und es gibt weder eine kumulierte Umrechnungsdifferenz noch eine Intercompany-Eliminierung. Verwenden Sie die umgerechneten Beträge für die Gewinn- und Verlustrechnung.
</Aside>

## Hierarchien

Jeder Ladevorgang baut die Dimensionen aus den Stammdaten jeder Quelle neu auf. Zu Beginn gibt es sieben Dimensionen und bis zu zehn zusätzliche Kategorien:

| Dimension | Aufgebaut aus |
|---|---|
| **Entität** | Entitäten und ihren übergeordneten Entitäten |
| **Konto** | Kontenplan und übergeordneten Konten |
| **Abteilung** | Abteilungen und ihren übergeordneten Abteilungen |
| **Kunde** | Kunden und ihren übergeordneten Kunden |
| **Produkt** | Produkten und ihren übergeordneten Produkten |
| **Segment 1** | Segmentwerten für `segment_1` |
| **Segment 2** | Segmentwerten für `segment_2` |
| **Segment 3** bis **Segment 10** | Segmentwerten für `segment_3` bis `segment_10`, wenn Ihre Quellen sie führen |

- Ein Datensatz ohne übergeordneten Datensatz oder einer, der sich selbst als übergeordneten nennt, wird als Mitglied der obersten Ebene geladen.
- Da jeder Ladevorgang die Hierarchien neu aufbaut, ändern Sie einen übergeordneten Datensatz im ERP oder in Ihrer Datei, nicht in der Dimension.
- Ein Problem in einer Hierarchie betrifft nur diese Dimension. Der Ladevorgang und die Modelle der Vorlage werden trotzdem abgeschlossen.
- Sie können jede zusätzliche Kategorie nach ihrem Inhalt umbenennen, zum Beispiel **Klasse** oder **Region**. Geben Sie unter **Zusätzliche Kategorien umbenennen** die Namen ein, die Ihre Berichte verwenden, und klicken Sie auf **Save names**. Namen bestehen aus Buchstaben, Ziffern, Leerzeichen, Punkten, Bindestrichen und Unterstrichen, bis zu 60 Zeichen.
- Jede Quelle gibt an, unter welchem Ihrer Kategorienamen jede ihrer eigenen zusätzlichen Kategorien läuft. Öffnen Sie **Erweitert** bei der Quelle, wählen Sie den Namen für jede oder wählen Sie **Leave out**, und klicken Sie auf **Speichern**. Quellen, die eine Kategorie unterschiedlich nennen, etwa `Class` und `Business area`, teilen sich dann einen Platz.

Um Segmenthierarchien aus einer Datei bereitzustellen, wählen Sie das Dataset **Segmentwerte**:

| Spalte | Enthält |
|---|---|
| `segment` | Zu welchem Segment der Wert gehört: `segment_1` bis `segment_10`. |
| `segment_value` | Den Wert, wie Hauptbuch-, Umsatz- und Budgetzeilen ihn führen. |
| `segment_value_name` | Seinen Namen. |
| `parent_segment_value` | Seinen übergeordneten Wert innerhalb desselben Segments. |

## Bereitschaftsprüfungen

Nach jedem Ladevorgang listet das Raster **Bereitschaft** jede Prüfung für jede Entität und Periode mit einem dieser Status auf:

| Status | Bedeutung |
|---|---|
| **● Bereit** | Die Prüfung wurde bestanden. |
| **▲ Aufmerksamkeit erforderlich** | Einen Blick wert, aber die Zahlen sind verwendbar. |
| **■ Problem** | Beheben Sie dies, bevor Sie sich auf die Ergebnisse verlassen. |
| **– Nicht zutreffend** | Für diese Prüfung gibt es noch keine Daten. |

Die Prüfungen sind:

| Prüfung | Was sie bestätigt |
|---|---|
| **Daten geladen** | Jede Geschäftsperiode hat Hauptbuchzeilen, und jedes Lesen aus dem ERP war erfolgreich. Eine abgeschlossene Periode ohne Zeilen ist ein Problem; eine offene Periode ohne Zeilen erfordert Aufmerksamkeit. |
| **Saldenliste stimmt mit Hauptbuch überein** | Die Saldenliste entspricht dem Hauptbuch für jede Entität, Periode und jedes Konto. Wenn sowohl die Saldenliste als auch das Hauptbuch für ein Konto Abteilungen führen, wird auch jede Abteilung abgestimmt. |
| **Umsatz stimmt mit Hauptbuch überein** | Umsatzzeilen entsprechen den Umsatz- und Umsatzkostenkonten des Hauptbuchs für jede Periode. |
| **Unbekannte Produkte/Kunden** | Jede Umsatzzeile nennt ein Produkt und einen Kunden, die in den Produkt- und Kundenstammdaten vorhanden sind. |
| **Konten fehlen im Kontenplan** | Jede Hauptbuchzeile nennt ein Konto im Kontenplan. Zeilen mit einem unbekannten Konto bleiben in der Gewinn- und Verlustrechnung unberücksichtigt. Ein Konto mit Buchungen, aber ohne Kontotyp, ist ebenfalls ein Problem, und eine Quelle, deren Kontenplan Erlöskonten, aber kein Konto für Herstellungskosten typisiert, braucht Aufmerksamkeit. |
| **Währungsumrechnung** | Jede Zeile aus Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget hat einen Betrag in der Berichtswährung. Eine Zeile der Gewinn- und Verlustrechnung oder des Umsatzes ohne Kurs ist ein Problem, weil die Gewinn- und Verlustrechnung umgerechnete Beträge liest. Eine Bilanz-, Lagerbestands- oder Budgetzeile ohne Kurs erfordert Aufmerksamkeit. Ein Budgetmonat ohne Kurs wird gelb angezeigt, laden Sie daher geplante Kurse für Budgetmonate. Siehe [Währungsumrechnung](#währungsumrechnung). |
| **Nicht zugeordnete Entitäten** | Jede Zeile aus Hauptbuch, Saldenliste und Umsatz nennt eine Entität im Entitätsstamm, direkt oder über die Entitätszuordnung. Nicht zutreffend, bis ein Entitätsstamm geladen ist. Siehe [Entitätszuordnung](#entitätszuordnung). |

Ladevorgänge mit mehr als einer Quelle fügen diese Prüfungen hinzu:

| Prüfung | Was sie bestätigt |
|---|---|
| **Berichtsbuch** | Eine Quelle, die für eine Entität mehrere Buchführungsbücher führt, hat ein Berichtsbuch gewählt bekommen. Bis Sie eines wählen, zählt nur das erste Buch. |
| **Codes, die auf Ihre Antwort warten** | Jeder Code, den mehr als eine Quelle verwendet, wurde beantwortet. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| **Zusätzliche Kategorien aus Ihren Quellen** | Jede zusätzliche Kategorie, die eine Quelle führt, hat einen Namen oder wurde ausgelassen. |
| **Welche Quelle welche Monate abdeckt** | Keine zwei Quellen liefern dieselben Monate eines Unternehmens, es sei denn, Sie haben gewählt, welche zählt. |
| **Kontotypen und Hierarchie** | Jedes Elternelement, das eine Dimension nennt, ist vorhanden, und kein Mitglied ist sein eigenes Elternelement oder Vorfahre. Fehlt ein Elternelement, erscheinen seine Kinder auf oberster Ebene der Hierarchie, und eine Schleife verhindert, dass diese Hierarchie geladen wird. Die Summen bleiben unberührt. |
| **Geschäftskalender** | Die Geschäftsperioden jeder Entität sind Kalendermonate, und jeder Monat an Zeilen lässt sich genau einer Geschäftsperiode zuordnen. Es braucht Aufmerksamkeit, wenn die Perioden einer Entität keine Kalendermonate sind (4-4-5, 13 Perioden) oder wenn die Zeilen eines Monats in mehr als eine Geschäftsperiode fallen könnten oder dem Geschäftskalender der Monat fehlt. |

Jede Zeile, die nicht bereit ist, sagt in der Spalte **Was zu tun ist**, was zu tun ist, etwa den Kontenplan zu laden, Wechselkurse zu laden oder **Laden** für eine Periode erneut auszuführen.

Das Raster zeigt außerdem zwei Einrichtungsprüfungen, die nur erscheinen, wenn sie Aufmerksamkeit erfordern:

| Prüfung | Wann sie erscheint |
|---|---|
| **Gemeinkostenumlage** | Nur eine der Projektvariablen `overhead_department` und `overhead_driver` ist gesetzt, oder kein Verteilungstreiber passt zu `overhead_driver`, sodass die Umlage nichts bewirken würde. Setzen Sie beide oder leeren Sie beide, um die Gemeinkostenumlage auszuschalten. |
| **Budgetvergleich** | Budgetzeilen sind geladen, aber keine davon liegt in der Version, die die Projektvariable `budget_version` nennt, sodass der Budgetvergleich leer wäre. |

## Management-Konsolidierung

Jeder Ladevorgang erstellt eine Management-Konsolidierung: die Gewinn- und Verlustrechnung des Konzerns aus jeder Entität der Gruppe, in der Berichtswährung, mit eliminierten Intercompany-Beziehungen. Sie dient dem Management-Reporting. Ihr Konsolidierungssystem bleibt das Referenzsystem für den gesetzlichen Konzern; stimmen Sie weiter unten mit ihm ab.

<Aside type="note">
Die Management-Konsolidierung deckt nur die Gewinn- und Verlustrechnung ab. Sie ist keine gesetzliche oder rechtliche Konsolidierung und hat weder eine konsolidierte Bilanz noch eine Umrechnungsdifferenz, einen Geschäfts- oder Firmenwert oder Anteile Dritter.
</Aside>

### Die Gruppe auswählen

Öffnen Sie unter **Quellen** die **Gruppe**, um die Unternehmen der Gruppe zu sehen. Ein Unternehmen, dessen Markierung Sie entfernen, bleibt für sich in Ihren Berichten, wird aber aus der Gruppensumme ausgelassen. Klicken Sie auf **Save group**. Die Änderung gilt beim nächsten **Laden** oder **Änderungen anwenden**. Ein neues Unternehmen gehört zur Gruppe, bis Sie die Markierung entfernen.

Das Geschäftsjahr der Gruppe beginnt in dem Monat, den die Projektvariable `group_fy_start_month` festlegt, das ist `1`, sofern Sie es nicht ändern.

### Was Sie erhalten

| Tabelle | Enthält |
|---|---|
| **Konzern-GuV** | Eine Zeile pro Entität, Periode und Position (Umsatz, Umsatzkosten, Betriebsaufwand, neutrales Ergebnis, Intercompany-Differenz), in der Berichtswährung. Umsatz und Kosten tragen ihr natürliches Vorzeichen. |
| **Konzern-GuV kumuliert** | Dasselbe, kumuliert für das Jahr, bis zur zuletzt vollständig geladenen Periode der Gruppe. |
| **Intercompany-Paare** | Eine Zeile pro Entitätspaar, Gruppe und Periode, mit dem Betrag jeder Seite und dem Restbetrag. |
| **Intercompany-Positionen** | Die Hauptbuchzeilen hinter einer Konzernzahl oder einem Paar, mit dem Handelspartner. |
| **Abstimmung** | Die kumulierte Konzern-GuV im Vergleich zu Ihrem Konsolidierungssystem. |

In diesen Tabellen erscheinen drei Entitätsnamen:

| Entität | Bedeutung |
|---|---|
| **Eliminations** | Die Intercompany-Eliminierungen. Sie saldieren sich zu null, belassen Sie sie also für die Konzernzahlen und filtern Sie sie für die Summe der Entitäten vor der Eliminierung heraus. |
| **Group total** | Die Summe des Konsolidierungssystems, in der Abstimmung. |
| **Unmapped** | Zeilen ohne Periode sowie Konten oder Entitäten Ihres Konsolidierungssystems, die dieses Projekt nicht hat. |

Die Kennzahlen **Consolidated income**, **Consolidated result** und **IC difference** sowie ein Analysepfad für jede Tabelle beantworten Fragen zur Gruppe.

### Intercompany-Eliminierungen

Intercompany-Zeilen werden nach Handelspartner abgeglichen. Es wird der Partner der Zeile verwendet; hat eine Zeile keinen, der Partner ihres Kunden. Beide Seiten eines Paars werden eliminiert, und der Betrag, um den die beiden Seiten voneinander abweichen, wird auf eine Zeile für die Intercompany-Differenz gebucht. Jedes Paar erhält einen Grund:

| Grund | Bedeutung |
|---|---|
| **Abgeglichen** | Beide Seiten haben denselben Betrag gebucht. |
| **Nur eine Seite gebucht** | Eine Entität hat die Transaktion gebucht, ihr Partner nicht. |
| **Nicht eliminiert** | Eine Zeile des Paars hat keinen Wechselkurs, sodass keine der Seiten eliminiert wird. |

Ein Paar wird anhand seines Jahres bis heute beurteilt. Die Zeile **Intercompany-Salden** wird gelb, wenn die Differenz eines Paars über der Projektvariablen `group_amber` (Standard `1`) liegt, und rot über `group_red` (Standard `1000`). Zeilen ohne Partner oder mit einem Partner, der keine Entität ist, werden nicht eliminiert und in dieser Zeile gezählt. Eine Quelle, die Partner führt, neben einer, die das nicht tut, wird gelb angezeigt.

Die eigenen Eliminierungsentitäten einer Quelle bleiben aus der Konzern-GuV heraus, und die Zeile **Konsolidierung** sagt das.

### Mit Ihrem Konsolidierungssystem abstimmen

Fügen Sie die Ergebnisse, die Ihr Konsolidierungssystem meldet, als Datei hinzu und markieren Sie **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)**, wenn Sie ihre Zuordnung bestätigen. Beantworten Sie **Which version of the numbers is this?** mit dem Namen des Systems. Die Tabelle **Abstimmung** zeigt dann **eigene**, **gemeldet** und **Differenz** für jede Entität und Position, kumuliert für das Jahr. Eine Differenz erklärt sich meist in den Zeilen **Eliminations**, **Group total** und **Unmapped** oder durch die Wechselkurse, die das System verwendet. Die Zeile **Abstimmung mit der Quelle** listet jede Position über `group_amber` auf.

### Wer es sehen kann

Die Konzernergebnisse folgen dem Zeilenzugriff des Projekts. Eine Person, die nur einige Entitäten sieht, sieht die Summen dieser Entitäten vor der Eliminierung. Die Zeilen **Eliminations** und die Intercompany-Tabellen setzen Zugriff auf alle Entitäten voraus.

Wenn das Projekt anhand einer Spalte einschränkt, wer welche Zeilen sieht, die die Konzerntabellen nicht führen, etwa der Abteilung, bleiben die Konzernergebnisse für alle ausgeschaltet, und **Konsolidierung** zeigt **Group views are off** an. Nur ein Architect kann dann unter **Gruppe** **Everyone on the project may see the group results** markieren. Die Änderung gilt beim nächsten **Laden** oder **Änderungen anwenden**.

## Aktuell halten

Nachdem ein Ladevorgang aus Ihrer ERP-Verbindung ohne Probleme erfolgreich war, erscheint **Nächtlich aktualisieren** auf der Karte **Letzter Ladevorgang**. Klicken Sie darauf, um **Laden** jede Nacht um 2:00 Uhr in Ihrer Zeitzone auszuführen. Die Karte zeigt dann **Nightly refresh: Every night at 2:00** und wer es eingerichtet hat.

Der nächtliche Ladevorgang läuft als die Person, die ihn eingerichtet hat. Wenn diese Person die ERP-Verbindung nicht mehr verwenden kann, sagt das Raster, dass der nächtliche Ladevorgang übersprungen wird; richten Sie ihn erneut ein. Ein Projekt, das nur Beispieldaten hat, kann nicht geplant werden.

Eine Datei, die bei einem nächtlichen Ladevorgang fehlt oder leer ist, endet mit einer Warnung, die den Pfad nennt, nicht mit einem Fehler, und der Rest des Modells wird trotzdem geladen.

## Mit einer Vorlage auf dem Modell aufbauen

Eine Vorlage baut ihre Berichte und Modelle auf dem Common Finance Model auf, sodass sie unabhängig davon, welche ERPs es speisen, gleich funktionieren. Wenn Sie ein Projekt aus einer Vorlage starten, etwa **Enterprise Profitability**, erstellt sie:

- Die [Tabellen des Common Finance Model](#tabellen-des-common-finance-model), leer oder mit Beispieldaten gefüllt.
- Die Dimensionen **Entität**, **Konto**, **Abteilung**, **Kunde**, **Produkt**, **Segment 1** und **Segment 2**, aufgebaut aus diesen Tabellen. Siehe [Hierarchien](#hierarchien).
- Den Workflow **Laden** und die Workflows, die er ausführt, um Ihr ERP und Ihre Dateien zu lesen, sie zu überführen, die Bereitschaft zu prüfen und die Modelle der Vorlage aufzubauen.
- Die eigenen Berichte und Modelle der Vorlage. **Enterprise Profitability** ergänzt eine Tabelle der Gewinn- und Verlustrechnung mit Umsatz, Umsatzkosten, Bruttomarge, direktem und Gemeinkosten-Betriebsaufwand, Deckungsbeitrag und Betriebsmarge sowie Margenbrücken im Jahresvergleich und gegen das Budget.
- Kennzahlen und einen Analysepfad, um Fragen zu den Ergebnissen zu stellen.

Um zu erkunden, bevor Sie Ihr eigenes ERP verbinden, markieren Sie beim Erstellen des Projekts **Mit Beispieldaten starten**. Das Projekt führt sofort einen ersten Ladevorgang aus, sodass die Registerkarte **Foundation** ein vollständiges Beispiel zeigt, einschließlich einer Euro-Entität, die in US-Dollar umgerechnet wird. Wenn Sie Ihr eigenes ERP verbinden oder eigene Dateien hinzufügen, werden die Beispielzeilen gelöscht, und Ihre Daten treten an ihre Stelle.

## Die Registerkarte Foundation

Auf der Registerkarte **Foundation** verbinden, laden und prüfen Sie Ihre Daten. Sie hat diese Abschnitte, von oben nach unten:

| Abschnitt | Was er zeigt |
|---|---|
| **Letzter Ladevorgang** | Ob der letzte Ladevorgang erfolgreich war, fehlgeschlagen ist oder noch läuft, mit den Schaltflächen **Laden**, **Änderungen anwenden**, **Aktualisieren** und **Nächtlich aktualisieren**. |
| **Was als Nächstes zu tun ist** | Was Ihre Aufmerksamkeit braucht, das Wichtigste zuerst, jeweils mit einer Schaltfläche **Prüfen** oder **Wählen, welche Quelle ab wann zählt**. |
| **Quellen** | Jede Quelle der Reihe nach, mit **Erweitert**, **Diese Quelle entfernen**, **Gruppe** und **Zusätzliche Kategorien umbenennen**. |
| **Einrichtung** | Die Einrichtungs-Checkliste: **Daten verbinden**, **Daten laden**, **Prüfen, ob die Summen übereinstimmen**, **Hierarchien prüfen** und **Mit Ihrem Team teilen**. Der aktuelle Punkt ist fett. |
| **Dateien** | Jede Datei, die Sie hinzugefügt haben, ihr Dataset, etwa **Hauptbuch** oder **Wechselkurse**, und ob ihre Zuordnung **✓ Bestätigt** oder **○ Wartet auf Bestätigung** ist. |
| **Daten geladen** | Für jede Entität die erste und die letzte geladene Periode und wie viele Perioden bereit sind. |
| **Perioden** | Die Geschäftsperioden jeder Entität und ob jede **✓ Geschlossen** oder **○ Offen** ist. |
| **Bereitschaft** | Das Bereitschaftsraster: eine Zeile pro Entität, Periode und Prüfung, mit ihrem Status und **Was zu tun ist**. |
| Verbindung | Verbinden Sie Ihr ERP, wählen Sie die Entitäten und wie viele Monate Verlauf geladen werden, oder fügen Sie eine weitere Quelle hinzu. |
| **Dateien** (hinzufügen) | Fügen Sie eine CSV-, TSV-, TXT-, Excel- oder Parquet-Datei hinzu und bestätigen Sie, wie ihre Spalten zugeordnet werden. |
| **Laden** | Starten Sie einen Ladevorgang. **Änderungen anwenden** führt einen aus, ohne aus den ERPs abzurufen. |

Während ein Ladevorgang läuft, aktualisiert sich die Registerkarte von selbst.

Die Einrichtungs-Checkliste verfolgt Ihren Fortschritt:

- **Daten verbinden** und **Daten laden** haken sich von selbst ab, sobald eine Quelle angebunden und ein Ladevorgang erfolgreich ist.
- **Prüfen, ob die Summen übereinstimmen** hakt sich von selbst ab, wenn die Abstimmungsprüfungen bestanden werden.
- **Hierarchien prüfen**: Klicken Sie auf **Dimensionen öffnen**, um die Hierarchien Entität, Konto und Abteilung zu prüfen, und markieren Sie dann **Ich habe sie geprüft**. **Diese bestätigen Sie selbst**.
- **Mit Ihrem Team teilen**: Teilen Sie das Projekt, wenn es bereit ist. Siehe [Projektzugriff verwalten](/de/guides/projects/managing-projects/#projektzugriff-verwalten).

## Tabellen des Common Finance Model

Data Foundation überführt jede Quelle, ob ERP oder Datei, in dieselben fünfzehn Tabellen, sodass darauf aufbauende Berichte, Kennzahlen und Modelle unabhängig von der Quelle gleich funktionieren. Jede Zeile erfasst außerdem ihr Quellsystem und wann sie gelesen wurde. Die Spalte **Dataset** ist der Name, den Sie beim Hinzufügen einer Datei wählen.

| Dataset | Tabelle | Enthält |
|---|---|---|
| Entitäten | `cfm_entity` | Rechtliche Entitäten mit übergeordneter Entität, lokaler Währung und Konzernwährung sowie Land. |
| Entitätszuordnung | `cfm_entity_map` | Entitätscodes der Quellen und die Entität, zu der jeder gehört. Siehe [Entitätszuordnung](#entitätszuordnung). |
| Wechselkurse | `cfm_fx_rate` | Monatliche Durchschnitts-, Stichtags- und historische Kurse nach Währungspaar. Siehe [Wechselkurse](#wechselkurse). |
| Geschäftskalender | `cfm_fiscal_calendar` | Eine Zeile pro Geschäftsperiode einer Entität, mit Start- und Enddatum und ob sie abgeschlossen ist. |
| Kontenplan | `cfm_account` | Konten mit übergeordnetem Konto, Typ (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), Abschluss, normalem Saldo und Kursart. |
| Abteilungen | `cfm_department` | Abteilungen und Kostenstellen mit übergeordneter Einheit und Profitcenter. |
| Produkte | `cfm_product` | Produktstamm mit übergeordnetem Produkt, Familie, Gruppe, Maßeinheit und Standardkosten. |
| Kunden | `cfm_customer` | Kundenstamm mit übergeordnetem Kunden, Gruppe, Region und Land. Kundennamen werden nicht maskiert. |
| Segmentwerte | `cfm_segment` | Segmentwerte mit Name und übergeordnetem Wert. Siehe [Hierarchien](#hierarchien). |
| Hauptbuch | `cfm_gl_journal` | Journalzeilen in Transaktions-, lokaler und Berichtswährung. |
| Saldenliste | `cfm_trial_balance` | Soll, Haben und Saldo der Periode nach Entität, Konto und Abteilung, in lokaler und Berichtswährung. |
| Verkaufspositionen | `cfm_sales_line` | Fakturierte Verkaufspositionen mit Menge, Brutto-, Rabatt-, Netto- und Umsatzkostenbeträgen. |
| Lagerbestände | `cfm_inventory_balance` | Lagerbestand am Periodenende nach Produkt und Lager. |
| Budget | `cfm_budget` | Budget und Prognose nach Szenario, Version, Konto und Abteilung. |
| Verteilungstreiber | `cfm_stat_driver` | Statistische Treiber wie Mitarbeiterzahl, Quadratmeter oder Einheiten. |

Perioden werden als `YYYY-MM` geschrieben, und Transaktionen werden nach Buchungsperiode eingeordnet. Budget ist optional: Ein ERP ohne Budgets lädt trotzdem alles andere.

Eine Saldenlistendatei kann Soll- und Haben-Spalten, eine Saldo-Spalte oder beides enthalten. Mit nur Soll und Haben ist der Saldo Soll minus Haben, und eine leere Seite zählt als null. Mit nur einem Saldo wird ein positiver Saldo zum Soll und ein negativer Saldo zum Haben, als positiver Betrag. Eine Abteilungsspalte ist optional.

## Fehlerbehebung

| Symptom | Was zu tun ist |
|---|---|
| **Verbindung testen** meldet, dass das ERP die Anmeldeinformationen abgelehnt hat | Prüfen Sie die Anmeldeinformationen der Verbindung und ob sich der Integrationsbenutzer beim ERP anmelden kann. |
| **Verbindung testen** zeigt **Fehlende Berechtigung** für ein Dataset | Bitten Sie Ihren ERP-Administrator, die genannten Berechtigungen hinzuzufügen. Die [Verbindungsanleitung](/de/guides/connections/) für Ihr ERP listet auf, was die Verbindung braucht. |
| Eine ERP-Fehlermeldung ist kürzer als die des ERP selbst | PlaidCloud entfernt Anmeldeinformationen, Token und Schlüssel aus Anbieterfehlern, bevor es sie anzeigt, sodass manche Details fehlen. Führen Sie **Verbindung testen** aus, um zu sehen, welches Dataset betroffen ist. |
| **Daten geladen** ist ein Problem für eine Periode | Ein ERP-Lesevorgang für diese Periode ist fehlgeschlagen. Führen Sie **Laden** erneut aus; Perioden, die geladen wurden, werden übersprungen. |
| **Konten fehlen im Kontenplan** ist ein Problem | Fügen Sie die fehlenden Konten dem Kontenplan im ERP oder in Ihrer Datei hinzu und führen Sie **Laden** erneut aus. |
| **Währungsumrechnung** ist ein Problem | Die Währung einer Entität hat für diese Periode keinen Kurs in die Berichtswährung, oder es wurde keine einzelne Berichtswährung gefunden. Fügen Sie die Kurse einer Datei **Wechselkurse** hinzu, prüfen Sie, ob die Verbindung die Wechselkurse des ERP lesen kann, oder legen Sie die Projektvariable `reporting_currency` fest. Führen Sie dann **Laden** erneut aus. |
| **Währungsumrechnung** erfordert Aufmerksamkeit | Bilanz-, Lagerbestands- oder Budgetzeilen haben keinen Stichtags-, historischen oder geplanten Kurs für die Periode. Die Gewinn- und Verlustrechnung ist nicht betroffen. Fügen Sie die Kurse hinzu, einschließlich geplanter Kurse für Budgetmonate, und führen Sie **Laden** erneut aus. |
| **Codes, die auf Ihre Antwort warten** erfordert Aufmerksamkeit | Klicken Sie auf **Prüfen**, beantworten Sie jeden Code und klicken Sie auf **Änderungen anwenden**. |
| **Welche Quelle welche Monate abdeckt** erfordert Aufmerksamkeit | Klicken Sie auf **Wählen, welche Quelle ab wann zählt**, wählen Sie die Quelle und klicken Sie auf **Änderungen anwenden**. |
| **Intercompany-Salden** ist rot oder gelb | Prüfen Sie die Paare in **Intercompany-Paare**. Buchen Sie die fehlende Seite, fügen Sie den Zeilen den Handelspartner hinzu oder ergänzen Sie den fehlenden Kurs. |
| **Group views are off** | Bitten Sie einen Architect, unter **Gruppe** **Everyone on the project may see the group results** zu markieren. |
| **Nicht zugeordnete Entitäten** ist ein Problem | Fügen Sie die Entität dem Entitätsstamm hinzu oder ordnen Sie ihren Code in der Datei **Entitätszuordnung** einer vorhandenen Entität zu und führen Sie **Laden** erneut aus. |
