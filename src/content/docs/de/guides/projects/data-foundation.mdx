**Data Foundation** ist die Finanzdatenbasis für Ihre PlaidCloud-Projekte. Das **Common Finance Model** führt ERP-Daten aus mehreren ERP-Systemen – und mehreren Instanzen jedes Systems – in einem einzigen Modell zusammen: ein Kontenplan, ein Satz Entitäten und eine Berichtswährung. Berichte, Kennzahlen und KI-Assistenten, die auf dem Modell aufbauen, lesen alle dieselben Zahlen, unabhängig davon, aus welchem ERP sie stammen.

Ihr ERP wird über seine PlaidCloud-Verbindung angebunden, sodass Hauptbuch, Saldenliste, Stammdaten und Budgets direkt aus der Quelle eintreffen, ohne dass Sie etwas exportieren müssen. Dateien ergänzen Daten, die ein System nicht vorhält, etwa Wechselkurse, Verteilungstreiber oder ein außerhalb des ERP geführtes Budget, und können die ERP-Zeilen ersetzen, die sie abdecken. **Laden** überführt jede Quelle in das Modell, rechnet sie in die Berichtswährung um und prüft, ob alles übereinstimmt – alles über die Gruppe **Data Foundation** der Leiste **Startseite** des Projekts. Wenn Sie ein zweites System hinzufügen, beantworten Sie eine Frage pro Thema, etwa ob es dieselben Kontocodes verwendet wie ein bereits verbundenes System, und eine Managementkonsolidierung erstellt die Konzern-Gewinn- und Verlustrechnung ohne die konzerninternen Posten. Sie können Data Foundation jedem Projekt hinzufügen, und Lösungen wie **Enterprise Profitability** bauen ihre Berichte und Modelle darauf auf.

## Data Foundation erhalten

Sie können ein Projekt mit Data Foundation beginnen oder Data Foundation einem bereits vorhandenen Projekt hinzufügen.

- **Ein neues Projekt.** Öffnen Sie in Analyze **Projekte** und klicken Sie auf **Neues Projekt**. **Starten mit** listet **Leer**, **Data Foundation**, **Enterprise Profitability**, **Cost to Serve**, **Operational Transfer Pricing** und **Aus einer Vorlagendatei** auf, und eine Zeile unter der Liste beschreibt, was die Auswahl bietet. **Data Foundation** ist das Modell allein, mit seinen Berichten. Jede der drei Lösungen enthält Data Foundation und fügt eigene Modelle hinzu. Um ein vollständiges Beispiel zu sehen, bevor Sie etwas verbinden, aktivieren Sie **Mit Beispieldaten starten**. Klicken Sie auf **Erstellen**. Das Projekt ist privat, und Sie sind sein einziger Architect, bis Sie es freigeben.
- **Ihre erste Anmeldung.** Wenn Sie Projekte erstellen können, bietet die Begrüßung bei Ihrer ersten Anmeldung **Finanzsystem verbinden** an. Dadurch wird ein Data-Foundation-Projekt erstellt, für Sie benannt und geöffnet, während es aufgebaut wird.
- **Ein bereits vorhandenes Projekt.** Öffnen Sie die **Startseite** des Projekts. Unter der Überschrift **Data Foundation** der Leiste erklärt die Zeile **Data Foundation**, worum es sich handelt, und ein Architect des Projekts sieht **Data Foundation hinzufügen**. Der Aufbau läuft im Hintergrund, und die Seite zeigt **Data Foundation wird hinzugefügt. Das dauert einige Minuten.** Ihre eigenen Workflows, Tabellen und sonstigen Arbeiten bleiben unverändert. Hat das Projekt bereits eine Tabelle an der Stelle, an der das Modell eine führt, wird nichts installiert, und die Meldung nennt die Tabelle.

**Startseite** ist die erste Registerkarte jedes Projekts. Sobald ein Projekt Data Foundation hat, enthält die Gruppe **Data Foundation** seiner Leiste diese Zeilen, jede mit einem eigenen Link:

| Zeile | Wann sie angezeigt wird |
|---|---|
| **Zusammenfassung** | Immer. Ein Projekt mit Data Foundation, aber noch ohne System öffnet sich darauf. |
| **Systeme** | Wenn das Projekt zwei oder mehr Systeme hat, ein System auf Zugang wartet oder der nächste Schritt auf **Zusammenfassung** darin besteht, ein System hinzuzufügen, zu verbinden oder aktuell zu halten. |
| **Fragen** | Solange eine Frage auf Ihre Antwort wartet, mit der Anzahl als Badge. |
| **Berichte** | Immer. |
| **Umlagen** | In einem Projekt, das mit einer Lösung erstellt wurde. |

## Ihr ERP verbinden

Ihr Finanzsystem wird über seine PlaidCloud-Verbindung mit Data Foundation verbunden. Data Foundation liest Hauptbuch, Saldenliste, Stammdaten, Wechselkurse, Budgets und, sofern das System sie führt, Nebenbücher, Monatsendsalden und Banksalden direkt daraus und greift dabei ausschließlich lesend zu. Anmeldedaten werden ausschließlich im Standard-Verbindungseditor eingegeben. Für jedes System gibt es eine Seite für den Administrator, der den Zugriff gewährt; diese Seiten sind unter [Welche Systeme das Modell speisen können](/de/guides/projects/data-foundation-getting-started/#welche-systeme-das-modell-speisen-können) aufgeführt, und die [Data Foundation-Abdeckungsmatrix](/de/reference/data-foundation-coverage-matrix/) zeigt, welche Datasets jedes System direkt liefert.

<Steps>

1. Klicken Sie auf der Seite **Zusammenfassung** auf **Fügen Sie Ihr Finanzsystem hinzu**. Dadurch wird **Systeme** geöffnet.

2. Wählen Sie unter **System hinzufügen** im Feld **System** Ihr System aus. Wie es weitergeht, hängt davon ab, wie sich das System anmeldet:

   - **QuickBooks Online und Xero** melden sich an, indem Sie den Zugriff im eigenen Fenster des Systems genehmigen. Klicken Sie auf **Connect to** und den Namen des Systems. PlaidCloud erstellt die Verbindung für die Umgebung des Projekts und öffnet das Genehmigungsfenster. Sobald Sie genehmigen, wird das System hinzugefügt und beginnt zu laden. Blockiert Ihr Browser das Fenster, lassen Sie Pop-ups für die Website zu und versuchen Sie es erneut.
   - **Ein System, bei dem Sie sich mit Anmeldedaten anmelden**, listet unter **Verbindung** die Verbindungen seiner Art auf, die Sie verwenden können, wobei die erste ausgewählt ist, sowie **Neue Verbindung**. Wählen Sie eine aus und klicken Sie auf **System hinzufügen**. **Neue Verbindung** öffnet den Standard-Verbindungseditor mit bereits eingetragener Umgebung des Projekts, und das System wird hinzugefügt, wenn Sie die Verbindung speichern.
   - **SAP S/4HANA, SAP ECC, Oracle E-Business Suite und Sage 100** werden über einen PlaidLink-Agent in Ihrem Netzwerk erreicht. Richten Sie zuerst den Agent ein und wählen Sie dann seine Verbindung wie bei jedem System, das sich mit Anmeldedaten anmeldet.

3. Um vor dem Hinzufügen des Systems zu ändern, was geladen wird, öffnen Sie **Optionen**. **Gesellschaften** listet die Gesellschaften des Systems auf: Markieren Sie die zu ladenden oder keine, um alle zu laden. Ein System, das seine Gesellschaften nicht auflistet, fordert Sie auf, sie einzugeben. **Monate Verlauf** gibt an, wie viele Monate rückwirkend geladen werden, von 1 bis 120. Einige Systeme haben außerdem **Systemeinstellungen**, und ein System mit einer Einstellung, auf die es nicht verzichten kann, öffnet **Optionen** und fragt danach. Ohne **Optionen** werden jede aktive Gesellschaft und 24 Monate Verlauf geladen.

4. Ein System, das mit seiner Verbindung hinzugefügt wurde, beginnt sofort mit dem Laden. Wenn andere Workflows dieselbe Verbindung verwenden, fragt PlaidCloud zuerst **Über eine gemeinsam genutzte Verbindung laden?** und nennt sie, da das Laden aus der Verbindung liest und diese Workflows verlangsamen kann. Klicken Sie auf **Trotzdem laden**, um fortzufahren.

</Steps>

Noch keinen Zugang? Wählen Sie das System und klicken Sie stattdessen auf **Noch keinen Zugang?** Das System wird als **Warten auf Zugang** hinzugefügt, und es wird eine Anfrage angezeigt, die jedes wartende System abdeckt und mit **Anfrage kopieren** oder **Anfrage per E-Mail senden** versandbereit ist. Wenn der Zugang eintrifft, fügen Sie das System mit seiner Verbindung unter **System hinzufügen** hinzu. Bei QuickBooks Online und Xero klicken Sie in der Zeile des Systems auf **Verbinden**.

Um ein weiteres System oder eine weitere Instanz einzubinden, fügen Sie es auf dieselbe Weise hinzu. Beim Hinzufügen eines Systems bleiben die anderen immer unverändert, sodass mehrere Systeme und Instanzen das eine konsolidierte Modell speisen. Wenn Sie ein zweites System hinzufügen, stellt Data Foundation eine Frage pro Thema statt einer pro Code. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen).

Jeder Ladevorgang liest nur, was sich geändert hat: Offene Perioden und die letzte abgeschlossene Periode werden erneut gelesen, bereits geladene abgeschlossene Perioden bleiben erhalten. Wenn Sie **Monate Verlauf** erhöhen, werden nur die hinzugekommenen Monate gelesen. Ein geänderter Wechselkurs, eine geänderte Entitätszuordnung oder eine geänderte Berichtswährung liest die betroffenen Monate erneut.

## Systeme

Jedes System und jede Instanz, aus der das Projekt lädt, ist eine Quelle, und Dateien, die Sie bestätigen, sind ebenfalls Quellen. Die Zeile **Systeme** der Leiste und mit ihr die Seite, ihre Schaltflächen und ihre Karte **Dateien** werden angezeigt, wenn das Projekt zwei oder mehr Systeme hat, ein System auf Zugang wartet oder der nächste Schritt auf **Zusammenfassung** darin besteht, ein System hinzuzufügen, zu verbinden oder aktuell zu halten. Bei einem einzigen System, das geladen ist und aktuell gehalten wird, zeigt **Zusammenfassung** es stattdessen unter **Your system** an. Die Seite **Systeme** listet jedes System mit **System**, **Status** und **Letzter Ladevorgang** auf. **Status** ist entweder **Warten auf Zugang**, **Verbunden**, **Wird geladen**, **Geladen** oder **Fehlgeschlagen**. **Letzter Ladevorgang** gibt an, wann das System zuletzt geladen wurde, oder **Noch nicht geladen**, und, sobald das Projekt nach Zeitplan aktualisiert wird, wann die nächste Aktualisierung fällig ist oder seit wann sie überfällig ist. Unter einem fehlgeschlagenen System nennt seine Zeile den Grund.

Jede Zeile hat die Schaltfläche, die zum Stand des Systems passt:

| Schaltfläche | Wann sie angezeigt wird |
|---|---|
| **Laden** | Das System ist verbunden oder geladen. Sie liest nur dieses System und baut das Modell dann aus den Daten aller Systeme neu auf. Ein fehlgeschlagenes System bietet sie neben seiner Korrektur an. |
| **Verbindung öffnen** | Das System konnte nicht geladen werden. Öffnen Sie seine Verbindung, um den Grund zu sehen und ihn zu beheben. |
| **Erneut verbinden** | Die Anmeldung bei QuickBooks Online oder Xero ist abgelaufen. |
| **Verbinden** | QuickBooks Online oder Xero wartet auf Zugang. |
| **Zugang anfordern** | Ein System, das sich mit Anmeldedaten anmeldet, wartet auf Zugang. Die Schaltfläche zeigt die Anfrage zum erneuten Senden an. |

Daneben meldet sich **Verbindung testen** an, versucht jedes Dataset zu lesen, führt jedes als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** auf und nennt die Berechtigungen, die der Administrator Ihres Systems hinzufügen muss. **Entfernen** nimmt ein System aus dem Projekt, nachdem Sie **Dieses System entfernen?** bestätigt haben. Alles, was daraus geladen wurde, wird gelöscht, und Sie können es später erneut verbinden.

Klicken Sie bei einem System auf **Bearbeiten**, um zu ändern, wie es verwendet wird, und klicken Sie dann auf **Speichern**:

| Einstellung | Funktion |
|---|---|
| **Name** | Die Bezeichnung, die Berichte, Fragen und Meldungen für das System verwenden. |
| **Berichtsbücher, durch Kommas getrennt** | Die zu lesenden Buchhaltungsbücher bei einem System, das mehrere führt. **Alle Berichtsbücher** liest jedes Buch. |
| **Monate, die diese Quelle liefert** | Für jedes **Unternehmen** die Monate von **Von (2026-01)** bis **Bis (2026-12)**, die das System liefert. Lassen Sie einen Monat leer, um keine Begrenzung festzulegen. Schreiben Sie Monate als Jahr und Monat, zum Beispiel `2026-03`. |
| **Zusätzliche Kategorien in dieser Quelle** | Für jede zusätzliche Kategorie, die das System führt, ihr **Name** und unter welchem Eintrag sie angezeigt wird (**Angezeigt unter**), oder **Weglassen**. |
| **Gesellschaften** und **Monate Verlauf** | Welche Gesellschaften das System lädt und wie viele Monate rückwirkend. |

Das Hinzufügen von Gesellschaften oder das Markieren keiner Gesellschaft wird sofort gespeichert. Wenn Sie eine Gesellschaft weglassen, müssen Sie zuerst **Weniger Gesellschaften laden?** bestätigen, weil beim Speichern sofort alles gelöscht wird, was aus diesem System geladen wurde, und der nächste **Laden**-Vorgang die markierten Gesellschaften erneut abruft.

Wenn zwei Systeme denselben Monat für dieselbe Gesellschaft liefern, zählt das weiter oben aufgeführte, bis Sie festlegen, welches ab wann zählt. Siehe [Festlegen, welche Quelle ab wann zählt](#festlegen-welche-quelle-ab-wann-zählt).

Das Ändern von Quellen liest Ihr ERP nicht erneut. Die Leiste über jeder Seite zeigt **Sie haben Ihre Quellen geändert. Klicken Sie auf „Änderungen anwenden“, um sie zu verwenden.**, bis Sie auf **Änderungen anwenden** klicken. Dadurch wird ein Ladevorgang aus den bereits abgerufenen Daten ausgeführt: Die Quellen werden mit Ihren neuen Zuordnungen, Namen und Dateien erneut überführt, und das Modell wird neu aufgebaut. Klicken Sie auf **Laden**, wenn Sie auch frische Daten aus Ihren Systemen abrufen möchten.

## Dateien für Daten außerhalb Ihres ERP hinzufügen

Dateien ergänzen Ihre ERP-Verbindung um Daten, die ein System nicht vorhält, etwa Wechselkurse, Verteilungstreiber, eine [Code-Zuordnung](#entitätszuordnung) von Entitätscodes oder ein außerhalb des ERP geführtes Budget. Jede Datei gehört zu einem der Datasets, die unter [Tabellen des Common Finance Model](#tabellen-des-common-finance-model) aufgeführt sind.

<Steps>

1. Wählen Sie in der Karte **Dateien** unter den Systemen auf **Systeme** das **Dokumentenkonto**, in dem die Datei gespeichert werden soll.

2. Legen Sie eine CSV- oder Excel-Datei auf **CSV- oder Excel-Datei hier ablegen** ab oder klicken Sie auf **Datei auswählen**. Die Datei wird in den Ordner `/foundation/` des Dokumentenkontos hochgeladen.

   Für eine Datei, die bereits im Dokumentenkonto liegt, öffnen Sie **Weitere Möglichkeiten zum Hinzufügen von Dateien**, geben Sie unter **Datei hinzufügen, die bereits im Dokumentenkonto liegt** ihren Pfad ein, zum Beispiel `/foundation/budget.csv`, und klicken Sie auf **Datei hinzufügen**.

   Um jeden Monat eine neue Datei zu lesen, verwenden Sie **Alle passenden Dateien eines Ordners hinzufügen**: Geben Sie den Ordner ein, wählen Sie, ob der Dateiname Ihre Eingabe **enthält**, **beginnt mit**, **endet mit**, **genau lautet** oder ihr **entspricht (\* steht für beliebige Zeichen)**, und klicken Sie auf **Dateien hinzufügen**. Dateien in Unterordnern werden nicht gelesen.

3. PlaidCloud liest die Datei und schlägt eine Zuordnung vor:

   - **Erkanntes Trennzeichen, Dezimaltrennzeichen und Datumsangaben.** Das Trennzeichen (Komma, Semikolon, Tabulator oder senkrechter Strich), das Dezimaltrennzeichen und das Datumsformat werden automatisch erkannt.
   - **Dataset**: die Tabelle des Common Finance Model, zu der die Datei gehört, ermittelt aus Dateiname und Spaltenüberschriften. Wenn die Zuordnung nicht eindeutig ist, wählen Sie sie aus der Liste.
   - **Dezimaltrennzeichen**: **Punkt (1,234.56)** oder **Komma (1.234,56)**.
   - **Datumsformat**: wird angezeigt, wenn die Datei Datumsangaben enthält. Ändern Sie es, wenn das erkannte Format falsch ist: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` oder `MM/DD/YYYY`.
   - Ein Raster mit **Spalte in Datei**, **Typ**, **Beispiele** und **Geht nach**. Ändern Sie **Geht nach**, um eine Spalte an ein anderes Feld zu senden oder auf **Nicht laden** zu setzen.

4. Beantworten Sie die Fragen, die die Datei aufwirft, etwa **Für welche Gesellschaft ist diese Datei?**, **In welcher Währung sind die Beträge?**, **Sind diese Beträge kumuliert für das Jahr oder für den Monat?**, **Sind die Beträge in Tausend oder Millionen angegeben?**, **Werden Erlöse als negative Zahlen dargestellt?** oder, bei einer Vertragsdatei, **Ist jede Zeile eine Vertragslaufzeit?** (siehe [Vertragsregister](#vertragsregister)). Jede Frage wird nur gestellt, wenn die Datei die Antwort nicht bereits enthält, außer **Ist jede Zeile eine Vertragslaufzeit?**, die jede als Vertragsdatei vorgeschlagene Datei stellt.

5. Prüfen Sie, wohin jede Spalte geht, und klicken Sie dann auf **Zuordnung bestätigen**. Während der Verarbeitung erklärt der Hinweis unter der Schaltfläche, worauf gewartet wird. In einem Projekt, das noch die Beispieldaten enthält, entfernt die erste bestätigte Datei auch die Beispieldaten, was einige Minuten dauern kann.

</Steps>

Diese Optionen erscheinen bei einer Datei, wenn sie zutreffen:

| Option | Verwendung |
|---|---|
| **Which source do these rows apply to?** | Eine Code-Zuordnungsdatei auf eine Quelle beschränken. **Every source** wendet sie auf alle an. |
| **Where does this file come from?** | Angeben, ob die Datei **This project's own codes** enthält oder aus **Another system** stammt, das Sie benennen, zum Beispiel `SAP Germany export`. Eine Datei aus einem anderen System wird wie eine ERP-Quelle auf gemeinsam verwendete Codes geprüft. |
| **Split … into … parts at each …** (unter **Erweitert**) | Eine Spalte, die mehrere Werte enthält, etwa `100-200-300`, aufteilen und jeden Teil an ein eigenes Feld senden. |
| **Which currency do you report in?** | Die Berichtswährung festlegen, wenn das Projekt noch keine hat. Geben Sie sie mit drei Buchstaben an, zum Beispiel `USD`. |
| **Dies sind konsolidierte Ergebnisse oder Ihre berichtete GuV (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Die Ergebnisse Ihres Konsolidierungssystems laden, damit die Konzern-Gewinn- und Verlustrechnung [abgestimmt](#mit-ihrem-konsolidierungssystem-abstimmen) werden kann. |

Um eine Datei aus dem Projekt zu nehmen, klicken Sie unter **Dateien** daneben auf **Entfernen** oder in ihrer Zuordnung auf **Remove this file** und bestätigen Sie. Ihre Zahlen verschwinden aus Ihren Berichten, sobald Sie das nächste Mal auf **Apply changes** klicken.

Wenn PlaidCloud das Dataset, das Dezimaltrennzeichen oder die Datumsreihenfolge nicht selbst bestimmen kann – zum Beispiel bei einer Datei, deren Datumsangaben als Tag/Monat oder Monat/Tag gelesen werden könnten –, werden Sie vor dem Bestätigen um eine Auswahl gebeten. Eine zweite Datei für dasselbe Dataset ersetzt die erste. Passen die Spalten einer späteren Datei nicht zum Dataset, nennt der Ladevorgang die Datei und die Spalten und fordert Sie auf, die Datei oder ihre Spaltennamen zu korrigieren oder die Einstellung **Schema Mismatch** des Schritts auf `union` zu setzen.

Akzeptiert werden CSV-, TSV- und TXT-Textdateien, Excel-Dateien im Format `.xlsx` (gelesen wird das erste Blatt) sowie Parquet-Dateien.

<Aside type="note">
Eine fehlende oder leere Datei stoppt einen Ladevorgang nie. Beim Hinzufügen wird gemeldet, dass noch nichts zuzuordnen ist, und ein Ladevorgang endet mit einer Warnung, die den Pfad nennt. Das Dataset behält die Zeilen, die die Datei ihm zuletzt geliefert hat, falls vorhanden. Fügen Sie die Datei erneut hinzu, sobald sie existiert.
</Aside>

### Vertragsregister

Eine Vertragsdatei kann ein Register von Vertragslaufzeiten sein oder die Verträge zu einem Monatsende enthalten; deshalb fragt das Bestätigen einer solchen Datei **Ist jede Zeile eine Vertragslaufzeit?**. Vorgeschlagen wird die Antwort **Ja, jede Zeile ist eine Vertragslaufzeit**, wenn die Datei ein Startdatum und keine Spalte für das Monatsende hat. Eine Datei, die Sie schon einmal bestätigt haben, behält ihre Antwort, wenn Sie sie erneut hinzufügen.

- **Ja, jede Zeile ist eine Vertragslaufzeit**: Jede Zeile ist eine Laufzeit eines Vertrags, mit Startdatum, Enddatum und Jahreswert. Jeder Ladevorgang kopiert jede Zeile in jedes Monatsende, über das sie läuft, von ihrem Startdatum bis zu ihrem Enddatum oder, solange das Enddatum leer ist, weiter bis zum Monat des Ladevorgangs oder zum letzten Monat des Kalenders der Entität, falls dieser früher liegt. Ein unterzeichneter Vertrag, der später beginnt, zählt ab seinem Start. Jede Kopie ist `Active`, außer der Kopie im Monat des Ladevorgangs, die den eigenen Status der Zeile behält. Eine Zeile ohne Positionsnummer wird innerhalb ihres Vertrags nummeriert.
- **Nein, die Datei enthält die Verträge zu einem Monatsende**: Die Datei ist die Kopie der Verträge zu einem Monatsende, wie jede andere Vertragsdatei.

Eine Zeile ohne Startdatum, eine Zeile, deren Status besagt, dass sie beendet ist, die aber kein Enddatum hat, und eine Zeile, die vor dem letzten Tag ihres ersten Monats endet, sind keine Vertragslaufzeiten und werden zurückgehalten. Siehe [Zurückgehaltene Zeilen](#zurückgehaltene-zeilen). Die Kunden- und Produktcodes eines Registers werden den Kunden und Produkten hinzugefügt, benannt nach dem Code, es sei denn, eine andere Quelle gibt demselben Code einen Namen. Seine Entitätscodes werden nur hinzugefügt, wenn keine andere Quelle Entitäten benennt.

## Daten laden

Ein Ladevorgang liest Ihre verbundenen Systeme und Ihre bestätigten Dateien, überführt sie in das Common Finance Model, rechnet sie in die Berichtswährung um, führt die Bereitschaftsprüfungen aus und baut die Modelle neu auf. Ein System, das mit seiner Verbindung hinzugefügt wurde, startet seinen ersten Ladevorgang von selbst. Bevor etwas geladen wurde, ist **Laden** auch der nächste Schritt auf **Zusammenfassung**. Danach liest **Laden** in der Zeile eines Systems auf **Systeme** nur dieses System und überführt, baut und konsolidiert dann aus den Daten aller Systeme, sodass beim Hinzufügen eines Systems die anderen nie erneut gelesen werden. Während der Ladevorgang läuft, zeigt **Zusammenfassung** an, was geladen wird.

- Pro Projekt wird jeweils nur ein Ladevorgang ausgeführt. Ein zweites **Laden** oder **Apply changes** meldet, dass bereits ein Ladevorgang läuft, und während er läuft, können Sie keine Quellen ändern.
- Wenn andere Workflows dieselbe Verbindung verwenden, listet der erste Ladevorgang sie auf und bittet Sie um Bestätigung, da ein Ladevorgang aus dem System liest und diese Workflows verlangsamen kann. Klicken Sie auf **Trotzdem laden**, um fortzufahren.
- Nach einem Upgrade von PlaidCloud aktualisiert **Laden** oder **Änderungen anwenden** durch einen Architect auch die generierten Workflows des Projekts und erstellt dabei alle benötigten Arbeitstabellen. Wenn eine neuere Version des Modells verfügbar ist, zeigt die Leiste über jeder Data-Foundation-Seite **Update available** und dass **Laden** oder **Änderungen anwenden** durch einen Architect sie installiert. Ein **Laden** durch einen Manager warnt, dass nur ein Architect sie aktualisieren kann.
- Beim Anwenden eines Updates bleiben Ihre eigenen Änderungen an den generierten Schritten erhalten. Wenn Sie einen Schritt geändert haben und das Update ihn ebenfalls geändert hat, bleibt Ihre Änderung erhalten. Ein von Ihnen bearbeiteter Schritt, den das Update nicht mehr generiert, bleibt erhalten, wird aber deaktiviert; löschen Sie ihn oder aktivieren Sie ihn wieder, wenn Sie ihn noch benötigen. Ein Schritt, den das Update ersetzt, wird benannt, und der frühere bleibt in seinen Schrittversionen erhalten.
- Wenn ein Update mittendrin angehalten hat, können seine Schritte bis zum Abschluss in falscher Reihenfolge laufen. Klicken Sie als Architect erneut auf **Laden**, um es abzuschließen. Hält es erneut an, wenden Sie sich an den Support.
- Ein System, das nicht geladen werden kann, zeigt auf der Seite **Systeme** den Status **Fehlgeschlagen** mit Grund und Korrektur. Endete der letzte Ladevorgang mit einer Warnung, zeigt **Zusammenfassung** die Meldung **The last Load ended with a warning:**, gefolgt von der Warnung.
- Wenn eine Entität und Periode nicht gelesen werden kann, wird der Rest trotzdem geladen. Führen Sie **Laden** erneut aus, um nur das Fehlgeschlagene abzurufen.
- Wenn ein Dataset einer Quelle nicht gelesen werden kann, wird der Rest der Quelle trotzdem geladen, dieses Dataset behält die Zeilen, die es hatte, und das System zeigt auf der Seite **Systeme** den Status **Fehlgeschlagen**, bis ein Ladevorgang es liest.

### Zurückgehaltene Zeilen

Wenn sich Quellen überschneiden, zählt ein Ladevorgang jede Zahl nur einmal. Zeilen, die er nicht zählt, werden entweder aufbewahrt oder zurückgehalten.

Aufbewahrte Zeilen bleiben im Projekt, als nicht gezählt markiert, sodass nichts verloren geht, was ein System enthält, und nichts doppelt gezählt wird. Eine Zeile wird aufbewahrt, wenn sie:

- in einem anderen Buchhaltungsbuch liegt, etwa einem lokalen oder steuerlichen Buch, das die Quelle nicht lesen soll;
- außerhalb der für ihr Unternehmen festgelegten Monate **Von** und **Bis** liegt;
- zu einem Unternehmen und Monat gehört, die eine andere Quelle zählt, zum Beispiel das System, aus dem eine Entität gewechselt ist;
- für diese Entität und diesen Monat durch eine Datei ersetzt wird.

Zurückgehaltene Zeilen werden mit Quelle, Entität und Grund erfasst, und der Ladevorgang endet mit einer Warnung, die die Anzahlen nennt, zum Beispiel `120 rows of NetSuite EU carrying a code another source also uses`. Die Gründe sind:

| Grund | Bedeutung |
|---|---|
| Auch in einer früheren Datei der Quelle | Eine frühere Datei derselben Quelle deckt den Monat bereits ab. |
| Ein späterer Eröffnungssaldo | Der früheste Eröffnungssaldo der Entität und die Bewegungen seitdem zählen bereits. |
| Enthält einen Code, den auch eine andere Quelle verwendet | Der Code benötigt Ihre Antwort. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| Enthält einen Code, der zwei Codes zugeordnet ist | Die Code-Zuordnung gibt dem Code zwei Antworten. |
| Enthält einen Code, den die eigenen Stammdaten nicht haben | Die eigene Liste der Konten, Produkte oder Kunden des Systems enthält den Code nicht. |
| Berichtssummen oder Leerzeilen | Summen- oder Leerzeilen einer Datei. |
| Ohne Startdatum, beendet ohne Enddatum oder endet vor dem letzten Tag seines ersten Monats, also keine Vertragslaufzeit | Eine Zeile eines Vertragsregisters, die keine Vertragslaufzeit ist. Siehe [Vertragsregister](#vertragsregister). |

Statistische Konten werden statt ins Hauptbuch zu den Verteilungstreibern verschoben und als verschoben angezeigt, nicht als Problem.

### ERP-Daten und Dateien zusammen

Eine Datei ersetzt nur, was sie abdeckt; die übrigen Zeilen aus Ihrem ERP bleiben erhalten.

- **Stammdatendateien** (Konten, Abteilungen, Kunden, Produkte und Segmentwerte) ersetzen die ERP-Zeilen mit demselben Code.
- **Transaktionsdateien** ersetzen die ERP-Zeilen für dieselbe Entität und denselben Monat. Hauptbuch- und Saldenlistendateien werden zusätzlich nach Ledger abgeglichen, Budgetdateien nach Szenario und statistische Treiberdateien nach Szenario und Treiber.

Deckt eine Datei einen Monat später nicht mehr ab, kehren die ERP-Daten für diesen Monat beim nächsten Ladevorgang zurück.

## Entitätszuordnung

Jede Quelle benennt ihre Entitäten mit eigenen Codes. Eine Datei **Code-Zuordnung** ordnet diese Codes den Entitäten in Ihren Entitätsstammdaten zu, sodass Zeilen aus jeder Quelle auf derselben Entität landen.

Um eine zu verwenden, fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Code-Zuordnung**:

| Spalte | Inhalt |
|---|---|
| `source_code` | Der Code, wie die Quelle ihn führt, etwa ein Unternehmenscode. Eine Spalte namens `source_entity` wird ebenfalls zugeordnet. |
| `code` | Die Entität, zu der er gehört, wie sie in den Entitätsstammdaten heißt. Eine Spalte namens `entity` wird ebenfalls zugeordnet. |

Jede Zeile ordnet einen Entitätscode zu, sofern die Datei keine Spalte `dimension` hat, die etwas anderes angibt. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen).

- Ein Code, der nicht in der Code-Zuordnung steht, wird unverändert verwendet.
- Mehrere Codes können einer Entität zugeordnet werden. Ihre Zeilen werden zusammengefasst, und ein Monat gilt als abgeschlossen, sobald er für alle abgeschlossen ist.
- Die Zeilen der Datei gelten für jede Quelle, sofern Sie nicht unter **Für welche Quelle gelten diese Zeilen?** eine auswählen; beschränken Sie die Datei daher auf eine Quelle, wenn zwei Quellen denselben Code für unterschiedliche Entitäten verwenden.
- Eine Zeile einer **Entitäten**-Datei ersetzt die ERP-Entität mit demselben Entitätscode.

Die Prüfung **Every entity known** markiert jede Zeile, deren Entität weder in den Entitätsstammdaten steht noch über die Code-Zuordnung einer zugeordnet ist. Sie ist nicht zutreffend, bis Entitätsstammdaten geladen sind.

## Codes quellenübergreifend zuordnen

Zwei Systeme können denselben Code für unterschiedliche Dinge verwenden oder unterschiedliche Codes für dasselbe. Wenn Sie ein System hinzufügen, dessen Codes sich mit denen eines bereits verbundenen Systems überschneiden, stellt Data Foundation eine Frage pro Thema statt einer pro Code, zum Beispiel **Does SAP ECC use the same account codes as NetSuite?** Diese Frage wird für Konten, Abteilungen, Profitcenter, Standorte, Produkte, Kunden und jede zusätzliche Kategorie gestellt.

Jede Frage wartet auf der Seite **Fragen** mit der von Weave vorgeschlagenen Antwort und den Belegen dafür, etwa wie viele der gemeinsamen Codes denselben Namen haben, und gibt an, wie viele Zeilen bis zu Ihrer Antwort zurückgehalten werden. Antworten Sie mit **Same codes as** (dieselben Codes wie das andere System) oder **Different codes from** (andere Codes als dieses).

- Bis Sie antworten, werden die Zeilen mit den gemeinsamen Codes zurückgehalten, sodass jeder Betrag nur einmal gezählt wird.
- Sobald Sie angeben, dass ein System dieselben Codes verwendet, wird ein später für dieses System neuer Code als Code des anderen Systems übernommen, ohne neue Frage.
- Zuordnungen werden pro System und Dimension gespeichert, sodass eine Antwort für die Abteilungen eines Systems nie die Konten eines anderen Systems ändert.
- Eine Antwort gilt beim nächsten **Laden** oder **Änderungen anwenden**, und **Verlauf** auf **Zusammenfassung** hält fest, wer sie wann gegeben hat und welcher Wert vorher galt.

Sie können die Zuordnungen auch in einer Datei bereitstellen. Fügen Sie eine Datei mit dem Dataset **Code map** hinzu und wählen Sie **Which source do these rows apply to?**, um sie auf eine Quelle zu beschränken.

## Festlegen, welche Quelle ab wann zählt

Wenn eine Entität von einem System in ein anderes wechselt, führen beide Systeme sie. **Fragen** fragt **From which month does** das neue System **count for** die Entität und schlägt den Monat nach dem letzten Hauptbuchmonat des früheren Systems vor. Das frühere System behält die Monate davor.

Die Karte **Quellenabdeckung** auf **Zusammenfassung** listet alle weiteren Monate auf, die zwei Quellen beide liefern. Geben Sie unter **Probleme** für zwei Quellen, die sich bei einem Unternehmen überschneiden, in **Dieser Monat ist** den Monat ein, zum Beispiel `2026-04`, wählen Sie unter **Welche Quelle zählt ab diesem Monat?** die Quelle, klicken Sie auf **Auswahl speichern** und dann in der Leiste über der Seite auf **Änderungen anwenden**. Bis Sie eine Auswahl treffen, wird nur die erste der beiden gezählt, und die andere Quelle behält die Monate vor dem eingegebenen Monat. **Erfordert Aufmerksamkeit** erklärt Überschneidungen, die wie beschrieben gezählt werden, etwa zwei Quellen, die unterschiedliche Wechselkurse für ein Unternehmen liefern, und gibt an, wessen Kurse verwendet werden.

Nur die Quellen, die ein Hauptbuch oder eine Saldenliste laden, und ein aus einer Datei geladener Geschäftskalender konkurrieren um den Geschäftskalender einer Entität. Eine Quelle, die kein Hauptbuch lädt, etwa Salesforce, konkurriert nie mit ihnen: Für einen Monat, den eine von ihnen liefert, zählt deren Kalender unabhängig von der Ladereihenfolge, und der Kalender der anderen Quelle füllt nur die Monate, die keine von ihnen liefert. Lädt keine Quelle ein Hauptbuch und wird kein Geschäftskalender aus einer Datei geladen, konkurrieren die Kalender aller Quellen wie oben beschrieben.

## Währungsumrechnung

Jeder Ladevorgang rechnet die Beträge aus Hauptbuch, Saldenliste, Umsatz, Lagerbestand, Budget und Nebenbüchern von ihrer Landeswährung in eine Berichtswährung um. Berichte und Modelle lesen die umgerechneten Beträge, sodass sich Entitäten in unterschiedlichen Währungen aus jedem System korrekt summieren.

### Die Berichtswährung

Um die Berichtswährung festzulegen, setzen Sie die Projektvariable `reporting_currency` auf einen Währungscode wie `USD`. Siehe [Projektvariablen verwalten](/de/guides/projects/managing-projects/#projektvariablen-verwalten). Sie können stattdessen **Aktionen ▾ > Projekteinstellungen…** auf **Zusammenfassung** öffnen und den Code in **Berichtswährung** eingeben. Die Vorlage legt sie leer an. Solange sie leer ist, verwendet jeder Ladevorgang die erste der folgenden Angaben, die genau eine Währung nennt:

1. Die Konzernwährung der Entitäten.
2. Die Landeswährung der obersten Entitäten, also derjenigen ohne übergeordnete Entität.
3. Die Landeswährung der Dateien.

Nennt keine davon genau eine Währung, legen Sie `reporting_currency` selbst fest.

Beträge, die bereits in der Berichtswährung vorliegen, bleiben unverändert, sodass ein Projekt, dessen Daten alle in einer Währung vorliegen, keine Kurse benötigt.

Auch Umsatz-, Lagerbestands- und Budgetdateien können eine Währung enthalten. Ordnen Sie eine Spalte mit dem Namen `Currency` oder `Local Currency` zu; sie wird automatisch erkannt, und die lokalen Beträge der Datei werden in die Berichtswährung umgerechnet. Ein Konzern- oder Berichtsbetrag, der bereits in der Datei steht, bleibt unverändert. Die Standardkosten der Produktstammdaten liegen bereits in der Konzernwährung vor und werden nicht umgerechnet.

### Wechselkurse

Ein Kurs rechnet eine Einheit einer Währung für einen Monat in die Berichtswährung um: Der umgerechnete Betrag ist der lokale Betrag mal dem Kurs.

- **Aus Ihrem ERP** liest jeder Ladevorgang die Wechselkurse, die das ERP vorhält.
- **Aus einer Datei**: Fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Wechselkurse**. Ein Kurs in der Datei ersetzt den ERP-Kurs für dieselben Währungen und denselben Monat. Verwenden Sie eine Datei, um in einer Währung zu berichten, für die Ihre ERPs keine Kurse veröffentlichen, oder um Plankurse für Budgetmonate hinzuzufügen.

| Spalte | Inhalt |
|---|---|
| `from_currency` | Die Ausgangswährung, zum Beispiel `EUR`. |
| `to_currency` | Die Berichtswährung, zum Beispiel `USD`. |
| `period` | Der Monat im Format `YYYY-MM`. |
| `average_rate` | Der Durchschnittskurs des Monats. |
| `closing_rate` | Der Kurs am Monatsende. |
| `historical_rate` | Der historische Kurs für Eigenkapital und für Konten, die auf den historischen Kurs eingestellt sind. |

Hat eine Währung keinen Kurs in die Berichtswährung, wird ihr Kurs in umgekehrter Richtung – von der Berichtswährung in diese Währung – umgekehrt, mit 12 Dezimalstellen. Fehlt auch dieser, wird ihr Kurs in eine andere Währung mit dem Kurs dieser Währung in die Berichtswährung multipliziert.

### Welcher Kurs gilt

Jede Zeile wird aus ihrer eigenen Währung umgerechnet, sodass eine Zeile in einer anderen Währung als ihre Entität aus der Währung umgerechnet wird, in der sie vorliegt. Es gilt die erste Regel, die auf die Zeile zutrifft:

| Zeile | Kurs |
|---|---|
| Statistische und nicht buchende Konten | Nicht umgerechnet. |
| Bereits in der Berichtswährung | Nicht umgerechnet. |
| Konto mit Kurstyp | Dieser Kurs: Durchschnitts-, Stichtags- oder historischer Kurs. Historisch fällt auf den Stichtagskurs zurück, wenn kein historischer Kurs vorhanden ist. Aus einem ERP ist der Kurstyp der eigene Kurstyp des Kontos. Ordnen Sie in einer Kontenplandatei eine Kurstyp-Spalte `fx_rate_type` mit `average`, `closing` oder `historical` zu. |
| Verkaufsposition | Der Durchschnittskurs der Periode. |
| Lagerbestand | Der Stichtagskurs der Periode. |
| Lieferantenrechnung, Bestellung, Zahlung, Kundenauftrag, Anlagenbewegung, Bewegung abgegrenzter Erlöse, Lagerbewegung oder Standardkosten | Der Durchschnittskurs der Periode. |
| Offene Forderung oder Verbindlichkeit, offener Betrag eines Kundenauftrags, Wert eines Vertrags oder Banksaldo | Der Stichtagskurs des Monatsendes, zu dem sie geführt werden. |
| Budgetzeile | Nach Konto, wie beim Hauptbuch: der Durchschnittskurs für GuV-Konten und der Stichtagskurs für Bilanzkonten. |
| GuV-Konto | Der Durchschnittskurs der Periode. |
| Eigenkapitalkonto | Der historische Kurs oder der Stichtagskurs, wenn kein historischer Kurs vorhanden ist. |
| Jedes andere Bilanzkonto | Der Stichtagskurs der Periode. |

Umgerechnete Beträge werden nicht gerundet, sodass Summen nicht abweichen.

Die Pipeline-Ansichten `cfm_rv_pipeline_month`, `cfm_rv_won_booked` und `cfm_rv_campaign_window` rechnen die gewonnenen, verlorenen und erstellten Beträge von Verkaufschancen zum Durchschnittskurs des Monats um, in dem das Geschäft abgeschlossen oder erstellt wurde. Die offene Pipeline eines Monats wird zum Stichtagskurs dieses Monats umgerechnet oder, solange dessen eigener Kurs noch nicht geladen ist, zum zuletzt für die Währung geladenen Stichtagskurs.

<Aside type="note">
Der gewonnene, verlorene oder erstellte Betrag eines Geschäfts in Fremdwährung wird ausgelassen, wenn seine Währung für diesen Monat keinen Durchschnittskurs hat, und nicht zu einem anderen Kurs angezeigt. Das Geschäft wird dennoch mitgezählt. Der Betrag eines gewonnenen Geschäfts in Fremdwährung fehlt in `cfm_rv_pipeline_month`, `cfm_rv_won_booked` und `cfm_rv_campaign_window`, bis der Durchschnittskurs für seinen Monat geladen ist, sodass die gewonnenen Fremdwährungsgeschäfte des aktuellen Monats bis dahin in den gewonnenen Beträgen fehlen. Fügen Sie den Kurs einer Datei **Wechselkurse** hinzu oder prüfen Sie, ob die Verbindung die Wechselkurse des ERP lesen kann, und führen Sie dann **Laden** erneut aus.
</Aside>

<Aside type="note">
Hauptbuch und Saldenliste enthalten die Bewegungen jeder Periode, daher sind ihre Bilanzbeträge die Bewegungen jedes Monats, umgerechnet zum Kurs dieses Monats. Die konsolidierte Bilanz rechnet stattdessen Salden um, zum Stichtagskurs des angezeigten Monats, mit der Differenz auf einer Zeile für Umrechnungsdifferenzen unter dem Eigenkapital. Siehe [Managementkonsolidierung](#managementkonsolidierung).
</Aside>

## Hierarchien

Jeder Ladevorgang baut die Dimensionen aus den Stammdaten jeder Quelle neu auf. Zu Beginn gibt es sieben Dimensionen und bis zu zehn zusätzliche Kategorien:

| Dimension | Aufgebaut aus |
|---|---|
| **Entität** | Entitäten und ihren übergeordneten Entitäten |
| **Konto** | Kontenplan und übergeordneten Konten |
| **Abteilung** | Abteilungen und ihren übergeordneten Abteilungen |
| **Kunde** | Kunden und ihren übergeordneten Kunden |
| **Produkt** | Produkten und ihren übergeordneten Produkten |
| **Segment 1** | Segmentwerten für `segment_1` |
| **Segment 2** | Segmentwerten für `segment_2` |
| **Segment 3** bis **Segment 10** | Segmentwerten für `segment_3` bis `segment_10`, wenn Ihre Quellen sie führen |

- Ein Datensatz ohne übergeordnetes Element oder einer, der sich selbst als übergeordnetes Element nennt, wird als oberstes Element geladen.
- Da jeder Ladevorgang die Hierarchien neu aufbaut, ändern Sie ein übergeordnetes Element im ERP oder in Ihrer Datei, nicht in der Dimension.
- Ein Problem in einer Hierarchie betrifft nur diese Dimension. Der Ladevorgang und die Modelle der Vorlage werden trotzdem abgeschlossen.
- Sie können jede zusätzliche Kategorie nach ihrem Inhalt umbenennen, zum Beispiel **Klasse** oder **Region**. Öffnen Sie **Aktionen ▾ > Projekteinstellungen…** auf **Zusammenfassung**, geben Sie unter **Projekteinstellungen** im Bereich **Namen** die Namen ein, die Ihre Berichte verwenden, und klicken Sie auf **Speichern**. Namen bestehen aus Buchstaben, Ziffern, Leerzeichen, Punkten, Bindestrichen und Unterstrichen, bis zu 60 Zeichen.
- Jede Quelle gibt an, unter welchem Ihrer Kategorienamen jede ihrer eigenen zusätzlichen Kategorien eingeordnet wird. Klicken Sie auf **Systeme** bei der Quelle auf **Bearbeiten**, wählen Sie unter **Zusätzliche Kategorien in dieser Quelle** für jede den Namen oder **Weglassen** und klicken Sie auf **Speichern**. Quellen, die eine Kategorie unterschiedlich benennen, etwa `Class` und `Business area`, teilen sich dann einen Platz.

Um Segmenthierarchien aus einer Datei bereitzustellen, wählen Sie das Dataset **Segmentwerte**:

| Spalte | Inhalt |
|---|---|
| `segment` | Zu welchem Segment der Wert gehört: `segment_1` bis `segment_10`. |
| `segment_value` | Der Wert, wie Hauptbuch-, Umsatz- und Budgetzeilen ihn führen. |
| `segment_value_name` | Sein Name. |
| `parent_segment_value` | Sein übergeordneter Wert innerhalb desselben Segments. |

## Bereitschaftsprüfungen

Diese Prüfungen sind das Detail unter den fünf Zusicherungen auf **Zusammenfassung**; siehe [Sind die Zahlen verlässlich?](/de/guides/projects/data-foundation-proof/).

Jedes **Laden** und jedes **Änderungen anwenden** führt sie für jede Entität und Periode aus, und jede Prüfung zählt unter einer der fünf Zusicherungen. Eine Prüfung, die fehlschlägt, ist rot. Ein Warnhinweis ist gelb: etwas, das einen Blick wert ist, die Zahlen aber nicht verfälscht. Auf dem Dashboard **CFM-Accounting - Close and assurance** zeigt die Registerkarte **What needs fixing** die Ansicht **Every check, by system, month chosen** mit der Anzahl roter Elemente jeder Prüfung je System, wobei null bedeutet, dass nichts zu beheben ist. Die Tabelle der zu behebenden Elemente für den gewählten Monat, die größten zuerst, nennt jedes rote Element und gibt an, was zu tun ist, etwa den Kontenplan laden, Wechselkurse laden oder **Laden** erneut ausführen. Siehe [Dashboards, Kennzahlen und Analysepfade](/de/guides/projects/data-foundation-dashboards/).

Die wichtigsten Prüfungen sind:

| Prüfung | Zusicherung | Was sie bestätigt |
|---|---|---|
| **Every month loaded** | **Unterwegs ging nichts verloren** | Jede Geschäftsperiode hat Hauptbuchzeilen, und jeder ERP-Lesevorgang war erfolgreich. Eine abgeschlossene Periode ohne Zeilen schlägt fehl; eine offene Periode ohne Zeilen ist ein Warnhinweis. |
| **Trial balance equals the ledger** | **Mit jedem System abgestimmt** | Die Saldenliste entspricht dem Hauptbuch für jede Entität, Periode und jedes Konto. Wenn sowohl die Saldenliste als auch das Hauptbuch für ein Konto Abteilungen führen, wird auch jede Abteilung abgestimmt. |
| **Sales equal the ledger** | **Unterwegs ging nichts verloren** | Die Verkaufspositionen entsprechen den Umsatz- und Umsatzkostenkonten des Hauptbuchs für jede Periode. |
| **Every product and customer of a sale known** | **Unterwegs ging nichts verloren** | Jede Verkaufsposition nennt ein Produkt und einen Kunden, die in den Produkt- und Kundenstammdaten vorhanden sind. |
| **Every account known** und **Every account typed** | **Unterwegs ging nichts verloren** | Jede Hauptbuchzeile nennt ein Konto aus dem Kontenplan. Zeilen mit unbekanntem Konto werden in der Gewinn- und Verlustrechnung nicht berücksichtigt. Ein Konto mit Buchungen, aber ohne Kontotyp schlägt ebenfalls fehl, und eine Quelle, deren Kontenplan Umsatzkonten typisiert, aber kein Umsatzkostenkonto, ist ein Warnhinweis. |
| **Every amount has a rate** | **Der Konzern geht auf** | Jede Zeile aus Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget hat einen Betrag in der Berichtswährung. Eine GuV- oder Umsatzzeile ohne Kurs schlägt fehl, weil die Gewinn- und Verlustrechnung umgerechnete Beträge liest. Eine Bilanz-, Lagerbestands- oder Budgetzeile ohne Kurs ist ein Warnhinweis; laden Sie daher Plankurse für Budgetmonate. Siehe [Währungsumrechnung](#währungsumrechnung). |
| **Every entity known** | **Unterwegs ging nichts verloren** | Jede Zeile aus Hauptbuch, Saldenliste und Umsatz nennt eine Entität aus den Entitätsstammdaten, direkt oder über eine Datei **Code-Zuordnung** einer zugeordnet. Nicht zutreffend, bis Entitätsstammdaten geladen sind. Siehe [Entitätszuordnung](#entitätszuordnung). |

Diese Prüfungen werden nur gemeldet, wenn sie Aufmerksamkeit erfordern, alle unter **Unterwegs ging nichts verloren**:

| Prüfung | Was sie bestätigt |
|---|---|
| **Reporting book chosen** | Für eine Quelle, die für eine Entität mehrere Buchhaltungsbücher führt, wurde das Berichtsbuch ausgewählt. Bis Sie eine Auswahl treffen, zählt nur das erste Buch. |
| **Codes mapped** | Jeder Code, den mehr als eine Quelle verwendet, wurde beantwortet. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| **One source for each key** | Keine zwei Quellen liefern dieselben Monate eines Unternehmens, es sei denn, Sie haben festgelegt, welche zählt. Der Geschäftskalender einer Quelle, die kein Hauptbuch lädt, zählt nicht gegen den einer Hauptbuch-Quelle. |
| **Hierarchies complete** | Jedes übergeordnete Element, das eine Dimension nennt, existiert, und kein Element ist sein eigenes übergeordnetes Element oder sein eigener Vorfahr. Ein fehlendes übergeordnetes Element setzt seine untergeordneten Elemente an die Spitze der Hierarchie, und eine Schleife verhindert das Laden dieser Hierarchie. Summen sind nicht betroffen. |
| **Months placed in the fiscal calendar** | Die Geschäftsperioden jeder Entität sind Kalendermonate, und jeder Monat mit Zeilen lässt sich genau einer Geschäftsperiode zuordnen. Die Prüfung ist ein Warnhinweis, wenn die Perioden einer Entität keine Kalendermonate sind (4-4-5, 13 Perioden) oder wenn die Zeilen eines Monats in mehr als einer Geschäftsperiode liegen könnten oder dem Geschäftskalender der Monat fehlt. |

Zwei Einrichtungsprüfungen werden nur gemeldet, wenn sie Aufmerksamkeit erfordern. Die eine wird gemeldet, wenn nur eine der Projektvariablen `overhead_department` und `overhead_driver` gesetzt ist oder kein Verteilungstreiber `overhead_driver` entspricht, sodass die Gemeinkostenumlage nichts bewirken würde: Setzen Sie beide oder leeren Sie beide, um die Gemeinkostenumlage zu deaktivieren. Die andere wird gemeldet, wenn Budgetzeilen geladen sind, aber keine in der **Budgetversion** der Projekteinstellungen (der Projektvariable `budget_version`) liegt, sodass der Budgetvergleich leer wäre.

## Managementkonsolidierung

Jeder Ladevorgang erstellt eine Managementkonsolidierung: Gewinn- und Verlustrechnung, Bilanz und Kapitalflussrechnung aller Entitäten des Konzerns in der Berichtswährung, ohne konzerninterne Posten. Sie dient dem Management-Reporting. Ihr Konsolidierungssystem bleibt das maßgebliche System für den gesetzlichen Konzernabschluss; stimmen Sie wie unten beschrieben mit ihm ab.

Wo immer konsolidierte Zahlen erscheinen, tragen sie die Bezeichnung **Management consolidation**: neben der ersten Zeile von **Zusammenfassung**, in der Kontextzeile oben auf jedem Dashboard und in der Spalte **Basis** des Board Packs, deren Spalte **Basis note** lautet: "Entities combined, intercompany eliminated, translated to the reporting currency. Not a statutory consolidation." Ein Projekt mit einer einzigen Entität zeigt keine Bezeichnung.

<Aside type="note">
Die Managementkonsolidierung ist keine gesetzliche oder rechtliche Konsolidierung. Sie eliminiert keine Beteiligungen gegen das Eigenkapital und enthält keinen Geschäfts- oder Firmenwert und keine Minderheitsanteile.
</Aside>

### Den Konzern auswählen

Auf **Zusammenfassung** zeigt die Karte **Der Konzern** die Berichtswährung. Klicken Sie auf **Ändern** oder öffnen Sie **Aktionen ▾ > Projekteinstellungen…** auf **Zusammenfassung**, um **Projekteinstellungen** zu öffnen; dort listet **Gruppen- und Zeilenzugriff** die **Gesellschaften in der Gruppe** auf. Eine Gesellschaft, deren Markierung Sie entfernen, bleibt eigenständig in Ihren Berichten, wird aber nicht in die Konzernsumme einbezogen. Klicken Sie auf **Speichern**. Die Änderung gilt beim nächsten **Laden** oder **Änderungen anwenden**. Eine neue Gesellschaft gehört zum Konzern, bis Sie ihre Markierung entfernen.

Das Geschäftsjahr des Konzerns beginnt in dem Monat, den die Projektvariable `group_fy_start_month` festlegt. Solange sie leer ist – und das ist sie, sofern Sie sie nicht festlegen –, beginnt das Geschäftsjahr des Konzerns in dem Monat, in dem das Geschäftsjahr der obersten Entität beginnt, also der einen Entität ohne übergeordnete Entität, oder im Januar, wenn die oberste Entität keinen Geschäftskalender hat. Haben mehrere Entitäten keine übergeordnete Entität oder ist die oberste Entität ein Hierarchieknoten ohne eigenen Geschäftskalender, beginnt es im Januar, und die Konsolidierung wird gelb angezeigt, bis Sie den Monat festlegen.

### Was Sie erhalten

| Tabelle | Inhalt |
|---|---|
| **Konzern-GuV** | Eine Zeile pro Entität, Periode und Position (Umsatz, Umsatzkosten, Betriebsaufwendungen, nicht betriebliches Ergebnis, konzerninterne Differenz) in der Berichtswährung. Umsatz und Kosten tragen ihr natürliches Vorzeichen. |
| **Konzern-GuV seit Jahresbeginn** | Dasselbe kumuliert seit Jahresbeginn bis zur letzten vollständig geladenen Periode des Konzerns. |
| `group_statements` | Gewinn- und Verlustrechnung, Bilanz und Kapitalflussrechnung wie angezeigt, Position für Position mit jeder Zwischensumme und Summe, für jede Entität, die Eliminierungen und den Konzern, in der Berichtswährung. Erträge, Vermögenswerte und Mittelzuflüsse sind positiv. Jede Position hat den Betrag des Monats und den Wert des Konzerngeschäftsjahres bis zu diesem Monat; eine Bilanzposition hat den Saldo des Monats. |
| `group_result` | Dieselben drei Finanzberichte nach Entität, Position, Konto und Monat, in jedem Berichtsbuch, in der Berichtswährung und, bei einer Entität in einer anderen Währung, in ihrer eigenen. Beträge sind sollpositiv, wie im Hauptbuch. |
| **Konzerninterne Paare** | Eine Zeile pro Entitätenpaar, Konzern und Periode mit dem Betrag jeder Seite und der Restdifferenz. |
| **Konzerninterne Positionen** | Die Hauptbuchzeilen hinter einer Konzernzahl oder einem Paar, mit dem Partnerunternehmen. |
| **Abstimmung** | Die Konzern-GuV seit Jahresbeginn im Vergleich zu Ihrem Konsolidierungssystem. |

In diesen Tabellen erscheinen drei Entitätsnamen:

| Entität | Bedeutung |
|---|---|
| **Eliminations** | Die konzerninternen Eliminierungen. Sie gleichen sich zu null aus; lassen Sie sie daher für die Konzernzahlen drin und filtern Sie sie für die Summe der Entitäten vor Eliminierung heraus. |
| **Group total** | Die Summe des Konsolidierungssystems in der Abstimmung. |
| **Unmapped** | Zeilen ohne Periode sowie Konten oder Entitäten Ihres Konsolidierungssystems, die dieses Projekt nicht hat. |

Die Kennzahlen **Consolidated income**, **Consolidated result** und **IC difference** lesen **Konzern-GuV**. Sie und ein Analysepfad für jede der Tabellen **Konzern-GuV**, Intercompany und Abstimmung beantworten Fragen zum Konzern. Das Dashboard **CFM-Finance - Statements** und das Board Pack zeigen die drei Finanzberichte.

#### Die drei Finanzberichte

- **Gewinn- und Verlustrechnung**: jeder Monat zum Durchschnittskurs dieses Monats.
- **Bilanz**: Der Saldo jedes Kontos ist sein Eröffnungssaldo zuzüglich seiner Bewegungen bis einschließlich des Monats. Salden werden zum Stichtagskurs des angezeigten Monats ausgewiesen, Eigenkapital zum historischen Kurs oder zum eigenen Kurstyp des Kontos, sofern es einen hat. Ein Eigenkapitalkonto ohne historischen Kurs wird zum Stichtagskurs ausgewiesen. Die Gewinn- und Verlustrechnung früherer Geschäftsjahre steht in den Gewinnrücklagen, die des laufenden Jahres im Ergebnis des laufenden Jahres, jeweils zu den Durchschnittskursen der eigenen Monate.
- Die Umrechnungsdifferenz ist eine Position unter dem Eigenkapital für jede Entität, berechnet als ihr Eigenkapital und Ergebnis zum Stichtagskurs abzüglich des umgerechneten Werts. Sie sorgt dafür, dass eine umgerechnete Bilanz ausgeglichen ist, und ist nie ein Ausgleichsposten. Hat eine Entität in einer anderen Währung für einen Monat keinen Stichtagskurs, wird ihre Bilanz in diesem Monat nicht umgerechnet und ist nicht ausgeglichen, und die Konsolidierung wird gelb angezeigt und nennt Entität und Monat. Laden Sie den Kurs und führen Sie dann **Änderungen anwenden** aus.
- **Kapitalflussrechnung**: berechnet aus der Bewegung jedes Bilanzkontos im Monat, nach seiner Kontorolle, zum Durchschnittskurs des Monats. Eine Position für wechselkursbedingte Effekte enthält den Teil der Veränderung der liquiden Mittel zu Stichtagskursen, der auf Kursänderungen zurückgeht. Ein Bilanzkonto ohne Rolle steht in der Position für sonstige Veränderungen.
- Auf **Fragen** beantwortete **Kontorollen** ordnen Konten ihren Positionen zu. **Provisionen** ist eine eigene Position der Betriebsaufwendungen. **Wandelanleihen und SAFEs** ist eine Verbindlichkeitsposition, und ihre Veränderung steht in der Kapitalflussrechnung unter Finanzierung; ein Eigenkapitalkonto mit dieser Rolle bleibt im Eigenkapital. Einem Aufwandskonto, das nach einer Provision benannt ist, wird **Provisionen** vorgeschlagen, einem Verbindlichkeits- oder Eigenkapitalkonto, das nach einer Wandelanleihe, einem SAFE oder einer einfachen Vereinbarung benannt ist, **Wandelanleihen und SAFEs**, und einem Konto, das nach einem Gesellschafterdarlehen, einem Inhaberdarlehen oder einem Darlehen von einer Person benannt ist, **Finanzverbindlichkeiten**, auch wenn sein Name zusätzlich „payable“ enthält. Einem Aufwandskonto, das nach einem Auftragnehmer benannt ist, wird **Personal** vorgeschlagen.

Die Bilanz endet mit einer Kontrollzeile, Vermögenswerte abzüglich Verbindlichkeiten und Eigenkapital, und die Kapitalflussrechnung mit der Veränderung der liquiden Mittel abzüglich der Bewegung auf den Zahlungsmittelkonten. Beide sind null, wenn der Finanzbericht stimmt. Die Zusicherungen, die sie belegen, finden Sie unter [Sind die Zahlen verlässlich?](/de/guides/projects/data-foundation-proof/).

### Konzerninterne Eliminierungen

Konzerninterne Zeilen werden über das Partnerunternehmen abgeglichen. Verwendet wird der Partner auf der Zeile; hat eine Zeile keinen, wird der Partner ihres Kunden verwendet. Beide Seiten eines Paares werden eliminiert, und der Betrag, um den die beiden Seiten voneinander abweichen, wird auf eine Zeile für konzerninterne Differenzen gebucht. Jedes Paar erhält einen Grund:

| Grund | Bedeutung |
|---|---|
| **Abgeglichen** | Beide Seiten haben denselben Betrag gebucht. |
| **Nur eine Seite gebucht** | Eine Entität hat die Transaktion gebucht, ihr Partner nicht. |
| **Nicht eliminiert** | Eine Zeile des Paares hat keinen Wechselkurs, daher wird keine Seite eliminiert. |

Ein Paar wird anhand seines kumulierten Werts seit Jahresbeginn beurteilt. Die Intercompany-Prüfung wird gelb, wenn die Differenz eines Paares über der Projektvariable `group_amber` liegt (Standard `1`), und rot über `group_red` (Standard `1000`), was der **Toleranz für Intercompany** in **Projekteinstellungen** entspricht (wird nicht angezeigt, solange die Gruppe nur eine Gesellschaft hat). Zeilen ohne Partner oder mit einem Partner, der keine Entität ist, werden nicht eliminiert und bei dieser Prüfung gezählt. Eine Quelle, die Partner führt, neben einer, die keine führt, wird gelb angezeigt.

Die eigenen Eliminierungsentitäten einer Quelle bleiben außerhalb der Konzern-GuV, und die Konsolidierungsprüfung weist darauf hin.

In den drei Finanzberichten werden konzerninterne Forderungen und Verbindlichkeiten ebenso paarweise eliminiert wie konzerninterne Erträge und Aufwendungen. Der Betrag, um den die beiden Seiten eines Paares voneinander abweichen, steht auf der Position für konzerninterne Differenzen der Gewinn- und Verlustrechnung oder der Bilanz, sodass die Konzernbilanz trotzdem ausgeglichen ist, und seine Bewegung steht in der Kapitalflussrechnung auf der Position für die Veränderung konzerninterner Salden. Jede Eliminierungszeile führt beide Entitäten sowie das Land, die Region und die Division, die sie gemeinsam haben, sodass eine Division, ein Land oder eine Region nur die Paare eliminiert, deren beide Entitäten darin liegen, und der Konzern jedes Paar eliminiert.

### Mit Ihrem Konsolidierungssystem abstimmen

Fügen Sie die Ergebnisse, die Ihr Konsolidierungssystem ausweist, als Datei hinzu und markieren Sie beim Bestätigen der Zuordnung **Dies sind konsolidierte Ergebnisse oder Ihre berichtete GuV (OneStream, Anaplan, SAP Group Reporting, FCCS)**. Beantworten Sie **Welche Version der Zahlen ist das?** mit dem Namen des Systems. Die Tabelle **Abstimmung** zeigt dann für jede Entität und Position **unsere**, **berichtet** und **Differenz**, kumuliert seit Jahresbeginn. Eine Differenz erklärt sich meist durch die Zeilen **Eliminierungen**, **Konzerngesamt** und **Nicht zugeordnet** oder durch die Wechselkurse, die das System verwendet. Die Abstimmungsprüfung listet jede Position über `group_amber` auf.

### Wer es sehen kann

Konzernergebnisse folgen dem Zeilenzugriff des Projekts. Wenn der Zeilenzugriff die Konzernergebnisse sperrt, zeigt die Konsolidierungsprüfung Gelb. Eine Person, die nur einige Entitäten sieht, sieht deren Summen vor Eliminierung, und **Zusammenfassung** weist sie darauf hin: „Diese Zahlen umfassen nur die Gesellschaften, auf die Sie Zugriff haben, nicht das gesamte Unternehmen.“ Die Zeilen **Eliminierungen** und die konzerninternen Tabellen erfordern Zugriff auf jede Entität.

**Zeilen nach Entität einschränken** in **Gruppen- und Zeilenzugriff** beschränkt eine Gruppe, der Entitäten gewährt wurden, auf die Zeilen dieser Entitäten, in jeder Tabelle mit einer Entitätsspalte. Nur ein Architect sieht diese Option. Das Markieren oder Entfernen der Markierung von **Einschränken** gilt sofort und wird abgelehnt, solange der Zeilenzugriff für den Workspace deaktiviert ist. Wenn Sie die Markierung entfernen, während Gruppen Entitätsberechtigungen haben, wird zuerst **Entitätsberechtigungen entfernen?** gefragt; klicken Sie auf **Ausschalten**, um fortzufahren.

Wenn das Projekt über eine Spalte, die die Konzerntabellen nicht führen – etwa die Abteilung –, einschränkt, wer welche Zeilen sieht, bleiben die Konzernergebnisse für alle ausgeschaltet, und die Konsolidierungsprüfung zeigt **Group views are off**. Nur ein Architect kann dann in **Gruppen- und Zeilenzugriff** die Option **Alle im Projekt dürfen die Konzernergebnisse sehen** markieren und auf **Speichern** klicken; andere sehen das Kontrollkästchen nicht. Die Änderung gilt beim nächsten **Laden** oder **Änderungen anwenden**.

## Aktuell halten

Sobald ein Ladevorgang abgeschlossen ist und keine Frage wartet, die Zeilen zurückhält, ist der nächste Schritt auf **Zusammenfassung** die Schaltfläche **Halten Sie dies aktuell**, bis **Aktualisieren** in **Projekteinstellungen** auf **Täglich**, **Wöchentlich** oder **Monatlich** steht. Es gibt zwei Möglichkeiten, **Laden** einzuplanen:

- **Aktionen ▾ > Nächtlich aktualisieren** auf **Zusammenfassung** führt **Laden** jede Nacht um 02:00 UTC aus.
- Öffnen Sie **Aktionen ▾ > Projekteinstellungen…** auf **Zusammenfassung**. Wählen Sie unter **Aktualisieren** die Option **Täglich**, **Wöchentlich** oder **Monatlich** und legen Sie **Aktualisierungszeit (UTC)** fest, angegeben als Stunden und Minuten wie `02:00`. Bei **Wöchentlich** ist **Aktualisierungstag** 1 (Montag) bis 7 (Sonntag); bei **Monatlich** ist es der Tag des Monats. Klicken Sie auf **Speichern**. **Bei Bedarf** entfernt den Zeitplan.

Ein Zeitplan kann eingerichtet werden, sobald ein Ladevorgang mit einer Quelle ohne rote Prüfungen abgeschlossen ist; ein Projekt, das nur Beispieldaten enthält, kann daher nicht eingeplant werden. Wenn Sie nur einige Entitäten des Projekts sehen, richtet ein Architect ihn ein. Kann ein Zeitplan nicht eingerichtet werden, wird der Grund angezeigt. Solange **Aktualisieren** auf **Täglich**, **Wöchentlich** oder **Monatlich** steht, zeigt die Seite **Systeme**, wann die nächste Aktualisierung jedes Systems fällig ist; siehe [Wie aktuell jedes System ist](/de/guides/projects/data-foundation-proof/#wie-aktuell-jedes-system-ist). **Nächtlich aktualisieren** lässt **Aktualisieren** unverändert, sodass keine nächste Aktualisierung angezeigt wird und **Halten Sie dies aktuell** der nächste Schritt bleibt.

Der geplante Ladevorgang wird im Namen der Person ausgeführt, die ihn eingerichtet hat. Kann diese Person die Verbindung eines Systems nicht mehr verwenden, wird der Ladevorgang mit einer Warnung übersprungen, die die Person und die Verbindung nennt; richten Sie den Zeitplan erneut ein.

Eine Datei, die bei einem geplanten Ladevorgang fehlt oder leer ist, führt zu einer Warnung, die den Pfad nennt, nicht zu einem Fehler, und der Rest des Modells wird trotzdem geladen.

Öffnen Sie **Aktionen ▾ > Projekteinstellungen…** auf **Zusammenfassung**; **Geschäftsbezeichnungen** befindet sich in der Karte **Namen** von **Projekteinstellungen**.

2. Geben Sie den **Code** ein: `segment_1` bis `segment_10` für eine Kategorie, den Schlüssel der Position für eine GuV-Position, den Namen der Kennzahl, `table.column` für eine Spalte oder den Code einer Entität oder eines Kontos.
3. Geben Sie den **Name** ein, höchstens 60 Zeichen in einer Zeile.
4. Klicken Sie auf **Speichern**. Der Dialog schließt sich, sobald alles darin gespeichert ist; eine abgelehnte Bezeichnung wird unter dem Raster gemeldet, und der Dialog bleibt geöffnet.

Beim Speichern wird die gesamte Liste ersetzt. Eine Zeile mit leerem Namen entfernt diese Bezeichnung, und **Ausgewählte entfernen** entfernt die markierten Zeilen. Denselben Code zweimal zu benennen wird abgelehnt. ## Erlösklassen und Teamfunktionen

Erlösklassen sind die Arten von Erlösen, die Ihr Unternehmen verkauft, etwa SaaS oder BPO, und die Funktion eines Teams besagt, wofür dessen Kosten anfallen. Das Dashboard [CFM-Executive - Growth and efficiency](/de/guides/projects/data-foundation-dashboards/#wachstum-und-effizienz) liest beides.

**Erlösklassen** in den **Projekteinstellungen** listet die Klassen auf, jede mit einem Namen und einer Art: **Abonnement**, **Support und Wartung**, **Managed Service**, **Implementierung**, **Beratung und Professional Services** oder **Andere**. Die ersten drei Arten sind wiederkehrend. Ein Projekt beginnt mit einer Klasse jeder Art, nach ihr benannt. Öffnen Sie **Aktionen ▾ > Projekteinstellungen…** auf **Zusammenfassung**. Klicken Sie auf **Hinzufügen** für eine neue Klasse, benennen Sie eine Klasse um oder ändern Sie ihre Art, oder klicken Sie auf **Entfernen**, und klicken Sie dann auf **Speichern**.

- Jede Klasse braucht einen Namen mit höchstens 60 Zeichen, und zwei Klassen dürfen nicht denselben Namen haben. Ein Name darf kein einfaches Anführungszeichen, keinen Backslash und keine geschweiften Klammern enthalten, und „Shared“, „Not yet classed“ und „Intercompany removed“ sind für die Berichte reserviert.
- Das Umbenennen einer Klasse oder das Ändern ihrer Art behält jede mit ihr gegebene Antwort. Die Dashboards zeigen die Änderung nach dem nächsten **Laden** oder **Änderungen anwenden**.
- Das Entfernen einer Klasse fragt erneut nach jedem Konto und Produkt, das mit ihr beantwortet wurde.

**Fragen** erfragt die Klasse und die Funktion unter **Umsatzklassen der Konten**, **Umsatzklassen der Produkte** und **Funktionen der Teams**:

- **Welche Umsatzklasse hat das Konto …?** für jedes Erlös- und Umsatzkostenkonto, auf das das Hauptbuch bucht und das keine Klasse hat, eine Frage je Konto, nie eine für ein übergeordnetes Konto und seine Konten zusammen. Ein Umsatzkostenkonto kann auch **Von jeder Klasse gemeinsam getragen** sein: Seine Kosten werden nach dem Umsatzanteil jeder Klasse in den 12 Monaten bis zum jeweiligen Monat auf die Klassen verteilt.
- **Welche Umsatzklasse hat das Produkt …?** für jedes Produkt eines Vertrags, das keine Klasse hat. Die Klasse eines Produkts teilt den wiederkehrenden Umsatz nach Klasse auf; jede Vertragsposition zählt unabhängig von ihrer Klasse zum jährlich wiederkehrenden Umsatz.
- **Welche Funktion hat die Abteilung … von …?** für jede Abteilung, auf die das Hauptbuch bucht, oder **Welche Funktion hat das Profitcenter … von …?** für jedes Profitcenter, wenn sein System keine Abteilungen hat, etwa eine Klasse in QuickBooks Online. Die Antwort lautet **Umsatzkosten**, **Vertrieb und Marketing**, **Forschung und Entwicklung** oder **Allgemeine Verwaltung**, und die Teams jedes Systems werden gesondert gefragt.

Der Vorschlag stammt aus dem Namen: Einem Konto oder Produkt, das nach Abonnements, SaaS oder Wartung benannt ist, wird zum Beispiel eine Klasse dieser Art vorgeschlagen; ein Wort nach „non-“ zählt nicht, sodass „Non-recurring“ keine wiederkehrende Klasse vorschlägt. Einem Erlöskonto, dessen Name es keiner Klasse zuordnet, wird eine Klasse der Art **Andere** oder eine andere Klasse, die nicht wiederkehrend ist, vorgeschlagen und einem Umsatzkostenkonto **Von jeder Klasse gemeinsam getragen**. Ein Produkt erhält nur dann einen Vorschlag, wenn sein Name es zuordnet. Einem Team wird aus seinem Namen eine Funktion vorgeschlagen, etwa **Vertrieb und Marketing** für ein Vertriebs- oder Marketingteam, sonst **Allgemeine Verwaltung**.

Diese Fragen halten nichts zurück: Sie machen das Projekt nicht gelb und sind nie der nächste Schritt auf **Zusammenfassung**. Bis ein Konto beantwortet ist, ist sein Umsatz „Not yet classed“ und zählt nicht als wiederkehrend; ein noch nicht beantwortetes Produkt zählt trotzdem zum jährlich wiederkehrenden Umsatz, als „Not yet classed“. Das Dashboard nennt unter den Zahlen, die es betrifft, was noch nicht beantwortet ist.

## Eine Zahl erklären

**Diese Zahl erklären** zeigt, woraus sich eine Zahl zusammensetzt. Sobald ein Monat geladen ist, zeigt **Zusammenfassung** den Jahresüberschuss für das Jahr bis zum letzten vollständigen Monat, mit **Diese Zahl erklären** daneben. Dadurch wird **Explain: Net income** geöffnet, oben mit der Zahl für das Jahr bis zu diesem Monat, darunter mit dem, woraus sie sich zusammensetzt, jede Liste mit den größten Werten zuerst:

| Liste | Inhalt |
|---|---|
| **Positionen** | Die Positionen der Finanzberichte, die sich zur Zahl summieren. |
| **Entitäten** | Der Anteil jeder Entität. In einem Konzern sind die Eliminierungen eine davon. |
| **Konten** | Der Anteil jedes Kontos. |

Jede Liste zeigt die zehn größten und den Rest als einen Eintrag, etwa **Other accounts (12)**, sodass sich jede Liste zur Zahl summiert. Ein Name, der ein Link ist, öffnet seine eigene Erklärung, nur für diese Position, Entität oder dieses Konto. **Größte Dokumente** listet die zehn größten Hauptbuchdokumente hinter der Zahl mit **System**, **Entität**, **Dokument**, **Gebucht**, **Konto**, **Beschreibung** und **Betrag** auf, und **Alle Dokumente exportieren** lädt alle herunter. **Weave fragen, warum sich der Wert verändert hat** fragt Weave, warum sich die Zahl im Jahr bis zu diesem Monat verändert hat und welche Entitäten, Konten und Dokumente sie bewegt haben.

Das Fenster folgt Ihrem Zeilenzugriff: Sie können nur die Zahlen erklären, die Sie sehen. Eine Tabelle, die noch nicht vorhanden ist, führt zu einer Warnung, nicht zu einem Fehler. Eine Zahl, hinter der nichts steht, zeigt **Nichts zu erklären**.

## Umlageregeln

Umlagen verteilen gemeinsame Kosten wie Gemeinkosten auf Abteilungen, Produkte und Kunden. Das Modell hat zwei Stufen: **Stufe 1: Gemeinkosten auf Abteilungen** und **Stufe 2: Abteilungen auf Produkte und Kunden**. Klicken Sie in einem Projekt, das mit einer Lösung erstellt wurde, in der Gruppe **Data Foundation** der Leiste **Startseite** auf **Umlagen**. Dadurch wird **Umlageregeln** geöffnet, wo Sie sehen oder ändern, wie jede Stufe durchgeführt wird. Ohne Änderungen funktionieren sie wie vor der Einführung des Assistenten. Ein Leser kann die Regeln öffnen, aber nicht speichern.

Für jede Stufe stellt der Assistent vier Fragen:

| Schritt | Frage | Auswahl |
|---|---|---|
| **Pool** | Welche Kosten möchten Sie verteilen? | Die Kontenart und für Stufe 1 die Abteilung, die die Kosten trägt, oder **All departments**. |
| **Treiber** | Wonach möchten Sie sie verteilen? | **Statistic**, die Sie als Verteilungstreiber geladen haben, etwa Mitarbeiterzahl oder Quadratmeter, **Net sales amount**, **Sales quantity** oder **Spread evenly**. Verwenden Sie den Treiber aus **Same period** oder **Same period last year**. |
| **Ziel** | Wo landen sie? | Stufe 1: Abteilungen. Stufe 2: Produkte, Kunden oder beides. |
| **Methode** | Was passiert, wenn ein Treiber negativ ist? | **Ignore negative values** oder **Stop and tell me**. |

Unter den Schritten zeigt **Preview for** für einen Monat, angegeben als Jahr und Monat wie `2026-09`, was die Regeln – einschließlich noch nicht gespeicherter – bewirken würden: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Alles Nicht-Umgelegte sind Kosten, für die es keinen Treiber gab. Die Vorschau folgt Ihrem Zeilenzugriff.

Ein Abteilungs- oder Statistikname darf kein einfaches Anführungszeichen (`'`), keinen Backslash und keinen Zeilenumbruch enthalten, weil der Name in die Filter der Umlageschritte geschrieben wird. **Speichern** und eine Vorschau von Stufe 1 lehnen einen solchen Namen ab und nennen ihn.

Klicken Sie auf **Speichern**. Die Regeln werden beim nächsten **Laden** wirksam oder wenn Sie auf **Apply changes** klicken. Wenn Sie einen Umlageschritt von Hand bearbeitet haben, bleibt Ihre Änderung erhalten und wird nicht überschrieben; die Speicherung nennt ihn. Während ein Ladevorgang läuft, können Sie nicht speichern.

## Board Pack

Ein Board Pack schreibt Ihre Ergebnisse versandfertig in einen Ordner eines Dokumentenkontos. Klicken Sie auf der Seite **Berichte** in der Karte **Vorstandspaket** auf **Einstellungen für die Board-Unterlagen**, wählen Sie ein **Dokumentenkonto** und einen **Ordner**, etwa `/board-packs`, und klicken Sie auf **Speichern**. Jedes **Laden** erstellt dann das Pack, sodass die Dateien im Ordner so aktuell sind wie der letzte Ladevorgang. Jede Ausführung schreibt:

- Eine Excel-Arbeitsmappe, `Board pack.xlsx`, mit den Blättern **Profit and loss**, **Balance sheet** und **Cash flow**: jeder Monat und jede Position nach Entität, mit den Eliminierungen und der Konzernsumme. Ein Projekt mit einer einzigen Entität hat keine Eliminierungs- oder Konzernzeilen.
- Ein PDF des Dashboards **CFM-Finance - Statements**.

Sobald dieses Dashboard erstellt ist, öffnet **Board-Unterlagen öffnen** in derselben Karte es.

Klicken Sie auf **Jetzt ausführen**, um sofort ein Pack zu erstellen; seine Dateien erscheinen im Ordner, sobald es fertig ist. Der Dialog zeigt die letzte Ausführung und ihr Ergebnis sowie die nächste Ausführung. **Änderungen anwenden** erstellt kein Pack. Um eines nach Zeitplan zu erstellen, planen Sie **Laden** ein (siehe [Aktuell halten](#aktuell-halten)); bis dahin zeigt der Dialog **Noch nicht geplant. Jeder Ladevorgang erstellt das Vorstandspaket: Richten Sie die nächtliche Aktualisierung ein, damit es jede Nacht erstellt wird.** Einrichten kann dies nur, wer das Projekt ändern darf.

Ein Pack, das nicht vollständig erstellt werden kann, lässt den Ladevorgang nie fehlschlagen:

- Ist das Reporting für Ihren Workspace deaktiviert, besteht das Pack nur aus der Excel-Arbeitsmappe, und die Ausführung meldet **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- Hat ein von jemand anderem erstelltes Dashboard bereits die Adresse, die Data Foundation für das Dashboard der Finanzberichte benötigt, bleibt dieses Dashboard unverändert und das PDF wird nicht erstellt. Die Meldung nennt die Adresse; geben Sie dem anderen Dashboard in Superset eine andere Adresse und führen Sie dann **Laden** erneut aus.
- Schlägt ein Schritt des Packs fehl, zeigt die letzte Ausführung im Dialog **fehlgeschlagen**. Der Ladevorgang selbst war dennoch erfolgreich.

## Wiederherstellungspunkte

Ein Wiederherstellungspunkt wird zu Beginn jedes **Laden** oder **Apply changes** erstellt, unabhängig davon, wer ihn startet, einschließlich eines geplanten Ladevorgangs, sowie vor jeder Änderung an Zuordnungen oder Quellen. Er enthält die Tabellen des Modells, die Dimensionen und die Einstellungen, auf denen der nächste Ladevorgang aufbaut: Ihre Quellen, Dateien und Umlageregeln. Die letzten sieben für Ladevorgänge erstellten Punkte und die letzten fünf vor Änderungen erstellten Punkte bleiben erhalten, sodass Änderungen nie die für Ladevorgänge erstellten Punkte verdrängen. Ältere Punkte entfallen.

Um zurückzugehen, öffnen Sie **Aktionen ▾ > Wiederherstellen…** auf **Zusammenfassung**. Jeder Punkt zeigt, wann er erstellt wurde, und darunter, wie viele Tabellen seine Wiederherstellung zurückbringt, zum Beispiel **Puts back 12 tables.**, und in einem Hinweis, was er unverändert lässt. Wählen Sie einen Punkt und klicken Sie auf **Wiederherstellen**. **Wiederherstellen** wird angeboten, sobald ein Punkt existiert. Beim Wiederherstellen wird zuerst der aktuelle Zustand des Projekts als eigener Punkt festgehalten, sodass Sie erneut zurückgehen können. Anschließend werden die Tabellen, die Dimensionen und diese Einstellungen auf den früheren Stand zurückgesetzt, und der nächste Ladevorgang baut darauf auf. Eine Wiederherstellung auf die Quellen, die Sie bereits hatten, markiert diese nicht als geändert. Die Wiederherstellung auf einen Punkt, der vor dem Hinzufügen einer Konnektor- oder Dateiquelle erstellt wurde, entfernt die gelandeten Tabellen dieser Quelle, und eine Warnung nennt die Quelle. Wenn Sie die Wiederherstellung rückgängig machen, holt Laden die Tabellen einer Konnektorquelle erneut, und bei einer Dateiquelle bestätigen Sie die Datei erneut. Lassen sich die Tabellen einer Quelle nicht entfernen, weist eine Warnung darauf hin, dass sie im Ordner der Quelle bleiben, bis Sie sie von Hand löschen, und der Rest wird dennoch wiederhergestellt. Eine Ansicht, eine Dimension, die nicht gespeichert werden kann, oder eine Tabelle ohne gespeicherte Kopie wird in einer Warnung genannt, und der Rest wird wiederhergestellt. Ein bereits entfallener Wiederherstellungspunkt wird abgelehnt, und während ein Ladevorgang läuft, können Sie nicht wiederherstellen.

## Ein Projekt klonen

**Aktionen ▾ > Klonen…** auf **Zusammenfassung** kopiert das Projekt unter einem von Ihnen vergebenen Namen. Die Kopie behält die Vorlage, Ihre Änderungen am Modell sowie Ihre Kennzahlen und Analysepfade und lädt die Beispieldaten. Ihre Quellen sind nicht verbunden; verbinden Sie sie daher in der Kopie, bevor Sie laden. Sie können weiterarbeiten, während die Kopie erstellt wird, und **Projekt öffnen** bringt Sie zu ihr, sobald sie bereit ist.

## Als eigene Vorlage speichern

Speichern Sie die Einrichtung eines Projekts, um sie für den nächsten Kunden oder die nächste Entität wiederzuverwenden. Öffnen Sie **Aktionen ▾ > Als meine Vorlage speichern…** auf **Zusammenfassung**, wählen Sie das Dokumentenkonto und benennen Sie die Datei. Die Endung `.zip` wird ergänzt, wenn Sie sie weglassen. Das Überschreiben einer vorhandenen Datei wird abgelehnt; wählen Sie daher einen anderen Namen.

Die Datei enthält die Struktur des Projekts, Ihre Änderungen am Modell, Kennzahlen und Analysepfade, die Geschäftsbezeichnungen für Entitäten und Konten sowie die Zeilen der Konfigurationstabellen der Vorlage, etwa die Aktivitätszuordnung von [Cost to Serve](/de/guides/projects/cost-to-serve/) oder die Richtlinienbandbreiten von [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/). Nicht enthalten sind Verbindungen, Dateien, der nächtliche Zeitplan, Ausführungen, Wiederherstellungspunkte, das Board Pack und die Zugriffsberechtigungen.

Um sie zu verwenden, erstellen Sie ein Projekt, wählen Sie unter **Starten mit** die Option **Aus einer Vorlagendatei** und wählen Sie Dokumentenkonto und Pfad. Das neue Projekt ist privat, und jede Quelle wartet darauf, verbunden zu werden. Eine spätere Version der Vorlage führt ihre Änderungen um die von Ihnen bearbeiteten Schritte herum zusammen. Gibt es unter dem Pfad keine Datei, wird nichts erstellt und Sie erhalten eine Meldung. Jeder, der das Dokumentenkonto lesen kann, kann aus der Datei installieren. Um sie in einem anderen Workspace zu verwenden, laden Sie die Datei herunter und dort wieder hoch.

## Offene Fragen mit Ask klären

Nach einem Ladevorgang kann ein Projekt noch auf drei Arten von Angaben warten: Konten, die der Kontenplan ohne Typ lässt, Codes, die mehr als eine Quelle verwendet, und Spalten in Ihren Dateien, die keiner Zuordnung entsprechen. Bitten Sie den Assistenten, sie zu klären: Verwenden Sie in einem KI-Assistenten über MCP den Prompt **Resolve Data Foundation residue**. Er liest, was aussteht, und schlägt für jeden Punkt eine Antwort mit Begründung vor.

Der Assistent schreibt nichts. Weave-AI-Chat kann außerdem anzeigen, worauf ein Projekt wartet (siehe [Weave-AI-Chat](/de/guides/ai-assistant/weave-tab/#data-foundation)), und ein per MCP verbundener Agent kann die Fragen selbst lesen und beantworten (siehe [Data Foundation mit einem per MCP verbundenen KI-Agenten](/de/integrations/ai-coding-agents/data-foundation/)). Sie übernehmen seine Antworten dort, wo Sie auch selbst geantwortet hätten: Konten und Codes auf der Seite **Fragen** und Dateispalten in der Zuordnung der Datei. Er schlägt nie eine Entität vor. Eine Frage auf **Fragen** kann bereits einen eigenen Vorschlag von Weave enthalten; siehe [Die Data-Foundation-Seiten](#die-data-foundation-seiten).

## Das Projekt übergeben

Wenn das Projekt für jemand anderen eingerichtet wird, etwa für einen Kunden, schließen Sie mit diesen Schritten ab:

- **Aktuell halten.** Planen Sie **Laden** ein. Siehe [Aktuell halten](#aktuell-halten).
- **Teilen.** Geben Sie dem Team auf der Seite **Zugriff & Freigabe** des Projekts Zugriff. Siehe [Projektzugriff verwalten](/de/guides/projects/managing-projects/#projektzugriff-verwalten).
- **Einen Nachweis aufbewahren.** **Aktionen ▾ > Nachweispaket herunterladen** auf **Zusammenfassung** lädt eine Excel-Arbeitsmappe mit den Blättern **Status**, **Quellen**, **Abdeckung**, **Zuordnungen**, **Konsolidierung**, **Abstimmung** und **Letzter Ladevorgang** herunter: was geladen wurde und woher, wie Codes zugeordnet wurden, dass der Konzern abgestimmt ist und wie der letzte Ladevorgang verlief. Sie folgt dem Zeilenzugriff der Person, die sie herunterlädt, und jeder mit einer Rolle im Projekt kann sie herunterladen.
- **Übergeben.** Machen Sie den Eigentümer zum Architect des Projekts und entfernen Sie sich dann aus dessen Mitgliedern. Einige Entscheidungen trifft nur ein Architect, etwa allen die Konzernergebnisse sichtbar zu machen oder einem Projekt Data Foundation hinzuzufügen.

## Mit einer Vorlage auf dem Modell aufbauen

Eine Vorlage baut ihre Berichte und Modelle auf dem Common Finance Model auf, sodass sie unabhängig davon, welche ERPs es speisen, gleich funktionieren. Wenn Sie ein Projekt aus einer Vorlage wie **Enterprise Profitability** starten, erstellt sie:

- Die [Tabellen des Common Finance Model](#tabellen-des-common-finance-model), leer oder mit Beispieldaten gefüllt.
- Die Dimensionen **Entität**, **Konto**, **Abteilung**, **Kunde**, **Produkt**, **Segment 1** und **Segment 2**, aufgebaut aus diesen Tabellen. Siehe [Hierarchien](#hierarchien).
- Den Workflow **Laden** und die Workflows, die er ausführt, um Ihr ERP und Ihre Dateien zu lesen, zu überführen, die Bereitschaft zu prüfen und die Modelle der Vorlage aufzubauen.
- Die eigenen Berichte und Modelle der Vorlage. **Enterprise Profitability** fügt eine GuV-Tabelle mit Umsatz, Umsatzkosten, Bruttomarge, direkten und Gemeinkosten-Betriebsaufwendungen, Deckungsbeitrag und operativer Marge hinzu, dazu Margenbrücken im Vorjahres- und Budgetvergleich.
- Kennzahlen und einen Analysepfad, um Fragen zu den Ergebnissen zu stellen.

Unter **Starten mit** ist **Data Foundation** das Modell allein, mit seinen Berichten. Jede der drei Lösungen enthält Data Foundation, fügt eigene Modelle hinzu und zeigt **Umlagen** in der Leiste:

| Lösung | Fügt hinzu |
|---|---|
| **Enterprise Profitability** | Die Gewinn- und Verlustrechnung und Margenbrücken. |
| **Cost to Serve** | Die Kosten der Betreuung jedes Kunden und die Marge danach. Siehe [Cost to Serve](/de/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | Das Gewinnniveau jeder Entität im Vergleich zu Ihrer Richtlinienbandbreite sowie die Anpassung. Siehe [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/). |

**Aus einer Vorlagendatei** startet mit einem von Ihnen gespeicherten Projekt. Siehe [Als eigene Vorlage speichern](#als-eigene-vorlage-speichern).

Um sich umzusehen, bevor Sie Ihr eigenes ERP verbinden, markieren Sie beim Erstellen des Projekts **Mit Beispieldaten starten**. Das Projekt führt sofort einen ersten Ladevorgang aus, sodass **Zusammenfassung** ein vollständiges Beispiel zeigt, einschließlich einer Euro-Entität, die in US-Dollar umgerechnet wird. Wenn Sie Ihr eigenes ERP verbinden oder eigene Dateien hinzufügen, werden die Beispieldaten entfernt und Ihre Daten treten an ihre Stelle. Wird das Entfernen unterbrochen, schließt der nächste **Laden**-Vorgang es ab. Ein eigener Ordner namens `sample` wird nie entfernt; solange die Beispieldaten diesen Ordner belegen, werden die anderen Tabellen darin jedoch nicht gelesen, verschieben Sie sie daher in einen Ordner mit einem anderen Namen.

In der Gruppe **Data Foundation** der Leiste **Startseite** des Projekts verbinden, laden und prüfen Sie Ihre Daten. Welche Zeilen angezeigt werden, steht unter [Data Foundation erhalten](#data-foundation-erhalten).

| Seite | Inhalt |
|---|---|
| **Zusammenfassung** | Wo Data Foundation steht, ob die Zahlen verlässlich sind und was als Nächstes zu tun ist. Siehe unten. |
| **Systeme** | Jedes System, aus dem Sie berichten, sein Stand und wann es zuletzt geladen wurde, **System hinzufügen** und die Karte **Dateien**. Siehe [Ihr ERP verbinden](#ihr-erp-verbinden), [Systeme](#systeme) und [Dateien für Daten außerhalb Ihres ERP hinzufügen](#dateien-für-daten-außerhalb-ihres-erp-hinzufügen). |
| **Fragen** | Alles, was auf Ihre Antwort wartet. Siehe unten. |
| **Berichte** | Die Dashboards nach Persona, die sich jeweils in einer neuen Registerkarte öffnen, und die Karte **Vorstandspaket**. Siehe [Dashboards, Kennzahlen und Analysepfade](/de/guides/projects/data-foundation-dashboards/) und [Board Pack](#board-pack). |
| **Umlagen** | Öffnet in einem Projekt, das mit einer Lösung erstellt wurde, **Umlageregeln**. Siehe [Umlageregeln](#umlageregeln). |

**Zusammenfassung** liest sich von oben nach unten:

- Wo das Projekt steht, in einer Zeile, mit dem jeweils nächsten Schritt als Schaltfläche, etwa **Fügen Sie Ihr Finanzsystem hinzu**, **Laden**, **1 Frage beantworten**, **Halten Sie dies aktuell** oder **Berichte öffnen**, und die Zeile mit dem Jahresüberschuss und **Diese Zahl erklären**. Siehe [Eine Zahl erklären](#eine-zahl-erklären).
- In einem Projekt mit mehr als einer Entität **Der Konzern**: wie vollständig der Konzern ist, seine Berichtswährung und der Monat, in dem sein Geschäftsjahr beginnt, mit **Ändern**, um **Projekteinstellungen** zu öffnen.
- **Sind die Zahlen verlässlich?**, die fünf Zusicherungen; bei einem einzigen System **Your system**; falls vorhanden **Was sich geändert hat**; und **Monat abschließen**. Siehe [Data Foundation: Sind die Zahlen verlässlich?](/de/guides/projects/data-foundation-proof/).
- **Weave fragen** mit Fragen für den Einstieg.
- **Verlauf**: jede Antwort, jeder Abgleich, jeder Abschluss und jede Neuausweisung, mit der Person, die sie vorgenommen hat, dem Zeitpunkt und dem vorherigen Wert. Klicken Sie auf **Verlauf anzeigen**, um ihn aufzulisten, auf **Mehr anzeigen** für ältere Einträge und auf **Exportieren**, um ihn als Excel-Arbeitsmappe herunterzuladen.
- **Quellenabdeckung**, wo Sie festlegen, welche Quelle zählt, wenn zwei dieselben Monate liefern. Siehe [Festlegen, welche Quelle ab wann zählt](#festlegen-welche-quelle-ab-wann-zählt).

Wenn Ihnen der Zeilenzugriff nur einige Entitäten zeigt, zeigt **Zusammenfassung** den Hinweis **Diese Zahlen umfassen nur die Gesellschaften, auf die Sie Zugriff haben, nicht das gesamte Unternehmen.**

**Aktionen ▾** oben auf **Zusammenfassung** enthält **Projekteinstellungen…**, **Hierarchien…**, **Nächtlich aktualisieren**, **Nachweispaket herunterladen**, **Klonen…**, **Wiederherstellen…** und **Als meine Vorlage speichern…**. Siehe [Hierarchien](#hierarchien), [Aktuell halten](#aktuell-halten), [Das Projekt übergeben](#das-projekt-übergeben), [Ein Projekt klonen](#ein-projekt-klonen), [Wiederherstellungspunkte](#wiederherstellungspunkte) und [Als eigene Vorlage speichern](#als-eigene-vorlage-speichern). Das Dialogfeld **Projekteinstellungen** öffnet sich auch über **Ändern** auf der Karte **Der Konzern**, solange die Gruppe mehr als eine Gesellschaft hat. Nur wer das Projekt ändern darf, kann die Einträge verwenden, die es ändern.

**Fragen** listet alles auf, was auf Ihre Antwort wartet, nach Thema gruppiert, mit der Anzahl der Fragen je Thema. Wenn Sie ein System hinzufügen, beantworten Sie eine Frage pro Thema, etwa ob es dieselben Codes wie ein bereits verbundenes System verwendet, nicht eine pro Code. Eine Frage, die Zeilen aus den Zahlen zurückhält, nennt deren Anzahl und Betrag. **Weave suggests:** gibt die Antwort von Weave und die Belege dafür an: Klicken Sie auf **Diese Antwort verwenden**, oder wählen Sie in der Liste eine andere und klicken Sie auf **Antworten**. **Alle Vorschläge übernehmen** beantwortet jede Frage, die einen Vorschlag hat. Eine Antwort gilt beim nächsten **Laden** oder **Änderungen anwenden**. Die Zeile **Fragen** wird nur angezeigt, solange eine Frage wartet.

Eine Frage zu einer Erlösklasse oder zur Funktion eines Teams hält nichts zurück. Siehe [Erlösklassen und Teamfunktionen](#erlösklassen-und-teamfunktionen).

Wenn Sie Ihre Quellen ändern, zeigt eine Leiste über jeder Seite **Sie haben Ihre Quellen geändert. Klicken Sie auf „Änderungen anwenden“, um sie zu verwenden.** Sie enthält **Änderungen anzeigen** und **Änderungen anwenden** und ist die einzige Stelle, an der eine Änderung angewendet wird. Das Ergebnis eines **Laden** oder **Änderungen anwenden** wird über der jeweils geöffneten Seite angezeigt, sodass Sie es auf jeder Seite sehen.

Während ein Ladevorgang läuft, aktualisieren sich die Seiten selbst und lesen weiter, auch wenn ein Lesevorgang fehlschlägt. Kann der Status nicht gelesen werden, erscheint **Der Foundation-Status konnte nicht gelesen werden.** mit **Erneut versuchen**, das ihn neu liest; die Seiten versuchen es außerdem einmal selbst erneut, bevor sie die Meldung anzeigen, und die Meldung verschwindet, sobald der Server antwortet.

## Tabellen des Common Finance Model

Data Foundation überführt jede Quelle, ob ERP oder Datei, in dieselben Tabellen, sodass darauf aufbauende Berichte, Kennzahlen und Modelle unabhängig von der Quelle gleich funktionieren. Jede Zeile erfasst außerdem ihr Quellsystem und den Zeitpunkt des Lesens. Die Spalte **Dataset** enthält den Namen, den Sie beim Hinzufügen einer Datei wählen.

| Dataset | Tabelle | Inhalt |
|---|---|---|
| Entitäten | `cfm_entity` | Rechtliche Einheiten mit übergeordneter Entität, Landes- und Konzernwährung, Land, Region und Division. |
| Code-Zuordnung | `cfm_code_map` | Die Zuordnung von einem Code, wie eine Quelle ihn führt, etwa einem Entitäts-, Konto- oder Abteilungscode, zum kanonischen Code. Siehe [Entitätszuordnung](#entitätszuordnung) und [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| Wechselkurse | `cfm_fx_rate` | Monatliche Durchschnitts-, Stichtags- und historische Kurse je Währungspaar. Siehe [Wechselkurse](#wechselkurse). |
| Geschäftskalender | `cfm_fiscal_calendar` | Eine Zeile pro Geschäftsperiode einer Entität, mit Start- und Enddatum und der Angabe, ob sie abgeschlossen ist. |
| Kontenplan | `cfm_account` | Konten mit übergeordnetem Konto, Typ (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), Abschlussbestandteil, Normalsaldo, Kurstyp, Kontorolle und Erlösklasse. Die Rolle, etwa Zahlungsmittel, Forderung, Verbindlichkeit oder Gewinnrücklagen, ordnet das Konto seiner Position im Abschluss und in der Kapitalflussrechnung zu. |
| Abteilungen | `cfm_department` | Abteilungen und Kostenstellen mit übergeordneter Abteilung, Profitcenter und Funktion. |
| Profitcenter | `cfm_profit_center` | Profitcenter mit übergeordnetem Profitcenter und Funktion. |
| Produkte | `cfm_product` | Produktstammdaten mit übergeordnetem Produkt, Familie, Gruppe, Mengeneinheit, Standardkosten und Erlösklasse. |
| Kunden | `cfm_customer` | Kundenstammdaten mit übergeordnetem Kunden, Gruppe, Region und Land. Kundennamen werden nicht maskiert. |
| Segmentwerte | `cfm_segment` | Segmentwerte mit Name und übergeordnetem Wert. Siehe [Hierarchien](#hierarchien). |
| Hauptbuch | `cfm_gl_journal` | Journalzeilen in Transaktions-, Landes- und Berichtswährung. |
| Saldenliste | `cfm_trial_balance` | Soll, Haben und Saldo je Periode nach Entität, Konto und Abteilung, in Landes- und Berichtswährung. |
| Verkaufspositionen | `cfm_sales_line` | Fakturierte Verkaufspositionen mit Menge, Brutto-, Rabatt-, Netto- und Umsatzkostenbeträgen. |
| Pipeline | `cfm_opportunity` | Vertriebspipeline: eine Zeile pro Position einer Verkaufschance in jeder Phase, eine Kopie pro Monatsende. |
| Lagerbestände | `cfm_inventory_balance` | Lagerbestand am Periodenende nach Produkt und Lager. |
| Budget | `cfm_budget` | Budget und Prognose nach Szenario, Version, Konto und Abteilung. |
| CO-PA nach Bewertung | `cfm_copa` | SAP-Ergebnisrechnung (CO-PA) nach Entität, Periode, Konto, Produkt und Kunde, ein Satz Zeilen pro Bewertung (gesetzlich, Konzern oder Profitcenter), nie zusammengerechnet. Erlöse sind positiv, Kosten negativ. Von den Vorlagen liest nur [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/#co-pa-marge) sie. |
| Verteilungstreiber | `cfm_stat_driver` | Statistische Treiber wie Mitarbeiterzahl, Quadratmeter oder Stückzahlen. |

Das Modell enthält außerdem die Nebenbücher und ihre Stammdaten, befüllt von den Systemen, die sie führen:

| Tabelle | Inhalt |
|---|---|
| `cfm_site` | Standorte: Werk, Lagerort oder Büro, jeweils in einer Entität. |
| `cfm_supplier` | Lieferantenstammdaten. |
| `cfm_sales_rep` | Stammdaten der Vertriebsmitarbeiter. |
| `cfm_project` | Projektstammdaten. Eine Marketingkampagne ist ein Projekt. |
| `cfm_standard_cost` | Standardkosten pro Einheit nach Produkt, kalkulierender Entität und Periode. |
| `cfm_system_balance` | Der eigene Schlusssaldo jedes Systems nach Konto zu jedem Monatsende, gelesen aus seinem Saldenbericht, nie aus den Journalzeilen. |
| `cfm_supplier_invoice_line` | Positionen von Lieferantenrechnungen. |
| `cfm_purchase_order_line` | Bestellpositionen, eine Kopie pro Monatsende. |
| `cfm_open_item` | Offene Forderungen und Verbindlichkeiten, eine Kopie pro Monatsende. |
| `cfm_payment` | Erhaltene und geleistete Zahlungen. |
| `cfm_order_line` | Kundenauftragspositionen, eine Kopie pro Monatsende. |
| `cfm_asset` | Anlagenverzeichnis. |
| `cfm_asset_movement` | Anlagenbewegungen nach Buch und Periode: Zugang, Abschreibung, Abgang und Umbuchung. |
| `cfm_contract` | Verträge und Abonnements, eine Kopie pro Monatsende. Ein [Vertragsregister](#vertragsregister) wird in jedes Monatsende kopiert, über das jede Laufzeit läuft. |
| `cfm_deferred_revenue_movement` | Bewegungen abgegrenzter Erlöse nach Vertrag und Periode. |
| `cfm_bank_balance` | Bankkonten und ihre Buchsalden zum Monatsende. |
| `cfm_inventory_movement` | Lagerbewegungen: Zugänge, Abgänge, Produktion, Umlagerungen, Anpassungen und Abschreibungen. |

Bei einer Tabelle, die eine Kopie pro Monatsende führt, ersetzt jeder Ladevorgang die Kopie des offenen Monats. Die Belegtabellen haben eine Spalte `counts`: `1` für eine Zeile, die zählt, aus dem System, das für ihre Entität und ihren Monat zählt, und aus dem Buch, über das das Projekt berichtet, und `0` für eine Zeile, die aus einem anderen System oder Buch aufbewahrt wird. Berichte und Kennzahlen lesen nur die Zeilen, die zählen.

Ein Foundation-Projekt wird mit [Projektelementen](/de/guides/projects/data-model/) für die Spalten geliefert, die diese Tabellen gemeinsam haben: `entity`, `account`, `department`, `profit_center`, `product`, `customer`, `period`, `site`, `supplier`, `sales_rep` und `project`. Jedes enthält eine Beschreibung sowie, wo zutreffend, einen Typ und eine Dimension, sodass jede Tabelle mit einer dieser Spalten dieselbe Bedeutung zeigt. Data Foundation fügt jedes davon hinzu, das dem Projekt fehlt, und lässt eines, das Sie bearbeitet haben, unverändert. Das gilt für jede ERP- und Dateiquelle.

Perioden werden als `YYYY-MM` geschrieben, und Transaktionen werden nach Buchungsperiode zugeordnet. Das Budget ist optional: Ein ERP ohne Budgets lädt trotzdem alles andere.

Eine Saldenlistendatei kann Soll- und Habenspalten, eine Saldospalte oder beides enthalten. Gibt es nur Soll und Haben, ist der Saldo Soll minus Haben, und eine leere Seite zählt als null. Gibt es nur einen Saldo, wird ein positiver Saldo zum Soll und ein negativer Saldo zum Haben, als positiver Betrag. Eine Abteilungsspalte ist optional.

## Fehlerbehebung

| Symptom | Was zu tun ist |
|---|---|
| **Verbindung testen** meldet, dass das ERP die Anmeldedaten abgelehnt hat | Prüfen Sie die Anmeldedaten der Verbindung und ob sich der Integrationsbenutzer beim ERP anmelden kann. |
| **Verbindung testen** zeigt **Fehlende Berechtigung** für ein Dataset | Bitten Sie Ihren ERP-Administrator, die genannten Berechtigungen hinzuzufügen. Der [Verbindungsleitfaden](/de/guides/connections/) für Ihr ERP listet auf, was die Verbindung benötigt. |
| Eine ERP-Fehlermeldung ist kürzer als die des ERP selbst | PlaidCloud entfernt Anmeldedaten, Token und Schlüssel aus Anbieterfehlern, bevor sie angezeigt werden, daher fehlen einige Details. Führen Sie **Verbindung testen** aus, um zu sehen, welches Dataset betroffen ist. |
| **Every month loaded** schlägt für eine Periode fehl | Ein ERP-Lesevorgang für diese Periode ist fehlgeschlagen. Führen Sie **Laden** erneut aus; bereits geladene Perioden werden übersprungen. |
| **Every account known** schlägt fehl | Fügen Sie die fehlenden Konten dem Kontenplan im ERP oder in Ihrer Datei hinzu und führen Sie **Laden** erneut aus. |
| **Every amount has a rate** schlägt fehl | Für die Währung einer Entität gibt es für diese Periode keinen Kurs in die Berichtswährung, oder es wurde keine eindeutige Berichtswährung gefunden. Fügen Sie die Kurse einer Datei **Wechselkurse** hinzu, prüfen Sie, ob die Verbindung die Wechselkurse des ERP lesen kann, oder setzen Sie die Projektvariable `reporting_currency`. Führen Sie dann **Laden** erneut aus. |
| **Every amount has a rate** ist ein Warnhinweis | Bilanz-, Lagerbestands- oder Budgetzeilen haben für die Periode keinen Stichtags-, historischen oder Plankurs. Die Gewinn- und Verlustrechnung ist nicht betroffen. Fügen Sie die Kurse hinzu, einschließlich Plankursen für Budgetmonate, und führen Sie **Laden** erneut aus. |
| **Codes mapped** schlägt fehl | Öffnen Sie **Fragen** und beantworten Sie jede Frage. Die Antworten gelten beim nächsten **Laden** oder **Änderungen anwenden**. |
| **One source for each key** schlägt fehl | Wählen Sie unter **Quellenabdeckung** auf **Zusammenfassung** den Monat und die Quelle, klicken Sie auf **Auswahl speichern** und dann auf **Änderungen anwenden**. |
| Die Intercompany-Prüfung ist rot oder gelb | Prüfen Sie die Paare in **Konzerninterne Paare**. Buchen Sie die fehlende Seite, ergänzen Sie das Partnerunternehmen auf den Zeilen oder fügen Sie den fehlenden Kurs hinzu. |
| **Group views are off** | Bitten Sie einen Architect, unter **Gruppen- und Zeilenzugriff** in **Projekteinstellungen** die Option **Alle im Projekt dürfen die Konzernergebnisse sehen** zu markieren. |
| Ein geplanter Ladevorgang wurde übersprungen | Die Person, die den Zeitplan eingerichtet hat, kann die Verbindung eines Systems nicht mehr verwenden. Richten Sie den Zeitplan erneut ein. Siehe [Aktuell halten](#aktuell-halten). |
| **Every entity known** schlägt fehl | Fügen Sie die Entität den Entitätsstammdaten hinzu oder ordnen Sie ihren Code in einer Datei **Code-Zuordnung** einer vorhandenen Entität zu und führen Sie **Laden** erneut aus. |
