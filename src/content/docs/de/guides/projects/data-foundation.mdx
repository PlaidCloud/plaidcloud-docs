**Data Foundation** ist das Finanzdaten-Fundament für Ihre PlaidCloud-Projekte. Sein **Common Finance Model** führt ERP-Daten aus mehreren ERP-Systemen, und mehreren Instanzen jedes Systems, in einem einzigen Modell zusammen: ein Kontenplan, ein Satz Entitäten und eine Berichtswährung. Berichte, Kennzahlen und KI-Assistenten, die auf dem Modell aufbauen, lesen alle dieselben Zahlen, aus welchem ERP sie auch stammen.

Ihr ERP verbindet sich über seine PlaidCloud-Verbindung, sodass Hauptbuch, Saldenliste, Stammdaten und Budgets direkt aus der Quelle eintreffen, ohne dass Sie etwas exportieren müssen. Dateien ergänzen Daten, die ein System nicht enthält, etwa Wechselkurse, Verteilungstreiber oder ein Budget, das außerhalb des ERP geführt wird, und können die ERP-Zeilen ersetzen, die sie abdecken. **Laden** überführt jede Quelle in das Modell, rechnet sie in die Berichtswährung um und prüft, ob sie abgestimmt ist, alles auf der Registerkarte **Foundation** des Projekts. Wo Quellen denselben Code für Verschiedenes verwenden, legen Sie fest, ob sie dasselbe meinen, und eine Management-Konsolidierung erstellt die Konzern-Gewinn- und Verlustrechnung mit eliminierten Intercompany-Beträgen. Vorlagen wie **Enterprise Profitability** bauen ihre Berichte und Modelle darauf auf.

## ERP verbinden

Ihr ERP verbindet sich über seine PlaidCloud-Verbindung mit Data Foundation. Data Foundation liest Hauptbuch, Saldenliste, Stammdaten, Wechselkurse und Budgets direkt daraus und liest ausschließlich. Sie können eine vorhandene Verbindung auswählen oder auf der Registerkarte eine neue erstellen. Für jedes System gibt es eine Seite für den Administrator, der den Zugriff erteilt, aufgelistet unter [Welche Systeme das Modell speisen können](/de/guides/projects/data-foundation-getting-started/#welche-systeme-das-modell-speisen-können), und die [Data Foundation Coverage Matrix](/de/reference/data-foundation-coverage-matrix/) zeigt, welche Datensätze jedes System direkt liefert.

<Steps>

1. Öffnen Sie in Analyze **Projekte** und klicken Sie auf **Neues Projekt**. Geben Sie einen Namen ein und wählen Sie unter **Starten mit** eine Vorlage, etwa **Enterprise Profitability (Vorlage)**, statt **Leeres Projekt**. Klicken Sie auf **Erstellen**.

   Das Projekt öffnet sich auf seiner Registerkarte **Foundation**. Es ist privat für Sie, und Sie sind sein einziger Architect, bis Sie es teilen.

2. Wählen Sie auf der Registerkarte **Foundation** eine vorhandene Verbindung für Ihr ERP aus oder wählen Sie **Neue Verbindung erstellen**. Bei jeder vorhandenen Verbindung sind die Workflows aufgelistet, die sie bereits verwenden, oder es steht **Noch von keinem Workflow verwendet** da.

3. Geben Sie für eine neue Verbindung einen **Verbindungsname** ein, wählen Sie die **Umgebung** und füllen Sie die Anmeldedaten aus, die Ihre ERP-Verbindung verlangt.

   Haben Sie die Anmeldedaten noch nicht? Das Formular zeigt eine fertige Zugriffsanfrage für Ihren ERP-Administrator. Klicken Sie auf **Anfrage kopieren** oder **Anfrage per E-Mail senden**, senden Sie sie ab und tragen Sie die Werte ein, die Sie zurückbekommen.

4. Klicken Sie auf **Verbindung testen**. PlaidCloud meldet sich an und versucht, jeden Datensatz zu lesen, und listet dann jeden als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** auf. Fehlt etwas, nennt es die Berechtigungen, die Ihr ERP-Administrator hinzufügen soll.

5. Legen Sie **Monate Verlauf** fest: wie viele Monate zurück geladen werden, von 1 bis 120. Der Standard ist 24.

6. Markieren Sie bei einer vorhandenen Verbindung die zu ladenden Entitäten oder lassen Sie alle unmarkiert, um jede Entität zu laden. Inaktive und Eliminierungsentitäten bleiben ausgeblendet, bis Sie sie einblenden. Klicken Sie dann auf **Verbinden**.

7. Klicken Sie bei einer neuen Verbindung auf **Verbinden**, um sie zu erstellen. Markieren Sie dann die zu ladenden Entitäten und klicken Sie erneut auf **Verbinden**, um sie zu speichern. Bis dahin wird jede Entität geladen.

8. Um ein weiteres ERP-System oder eine weitere Instanz einzubinden, wiederholen Sie diese Schritte und aktivieren Sie **Add this as another source instead of replacing the current one**, bevor Sie auf **Verbinden** klicken. Ohne diese Option ersetzt die neue Verbindung die aktuelle Quelle.

</Steps>

Nach dem Verbinden nennt die Karte, welche Verbindung, Umgebung, Entitäten und wie viele Monate Verlauf das Projekt lädt.

Jeder Ladevorgang liest nur, was sich geändert hat: Offene Perioden und die zuletzt abgeschlossene Periode werden erneut gelesen, bereits geladene abgeschlossene Perioden bleiben erhalten. Wenn Sie **Monate Verlauf** erhöhen, werden nur die hinzugekommenen Monate gelesen. Ein geänderter Wechselkurs, eine geänderte Entitätszuordnung oder eine geänderte Berichtswährung führt dazu, dass die davon betroffenen Monate erneut gelesen werden.

## Quellen

Jedes ERP-System und jede Instanz, aus der das Projekt lädt, ist eine Quelle. Die Liste **Quellen** auf der Registerkarte **Foundation** zeigt für jede Quelle eine Zeile in der Reihenfolge, mit ihrem Namen, dem Zeitpunkt des letzten Ladevorgangs, der Anzahl der gelieferten Zeilen und den gelesenen Berichtsbüchern, zum Beispiel `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Eine Quelle, die noch nicht geladen wurde, zeigt **not loaded yet**. Dateien, die Sie bestätigen, sind ebenfalls Quellen.

Öffnen Sie **Erweitert** bei einer Quelle, um zu ändern, wie sie verwendet wird:

| Einstellung | Was sie bewirkt |
|---|---|
| **Name** | Die Bezeichnung, die Berichte, Zuordnungsfragen und Meldungen für die Quelle verwenden. |
| **Place in the order** | Welchen Rang die Quelle hat. Wenn zwei Quellen denselben Monat desselben Unternehmens abdecken, gewinnt die in der Reihenfolge höhere. |
| **Reporting books, separated by commas** | Die zu lesenden Rechnungslegungsbücher, bei einem System, das mehr als eines führt. **All reporting books** liest jedes Buch. |
| **Unternehmen**, **Von (2026-01)** und **Bis (2026-12)** | Die Monate, die diese Quelle für jedes Unternehmen liefert. Lassen Sie einen Monat leer, wenn es keine Grenze geben soll. Schreiben Sie Monate als Jahr und Monat, zum Beispiel `2026-03`. |

Klicken Sie auf **Speichern**, um Ihre Änderungen zu behalten. Um eine Quelle zu entfernen, klicken Sie auf **Remove this source** und bestätigen Sie mit **Entfernen**. Alles, was daraus geladen wurde, wird gelöscht, und Sie können sie später erneut verbinden.

Das Ändern von Quellen liest Ihr ERP nicht erneut. Die Karte **Letzter Ladevorgang** zeigt **Changes not applied yet**, bis Sie auf **Apply changes** klicken. Das führt einen Ladevorgang mit den bereits abgerufenen Daten aus: Er überführt die Quellen mit Ihrer neuen Reihenfolge, Ihren Zuordnungen, Namen und Dateien erneut in das Modell und baut das Modell neu auf. Klicken Sie auf **Laden**, wenn Sie zusätzlich aktuelle Daten aus den ERP-Systemen wollen.

## Dateien für Daten außerhalb Ihres ERP hinzufügen

Dateien ergänzen Ihre ERP-Verbindung um Daten, die ein System nicht enthält, etwa Wechselkurse, Verteilungstreiber, eine [Entitätszuordnung](#entitätszuordnung) oder ein Budget, das außerhalb des ERP geführt wird. Jede Datei gehört zu einem der Datensätze, die unter [Tabellen des Common Finance Model](#tabellen-des-common-finance-model) aufgelistet sind.

<Steps>

1. Wählen Sie unter **Dateien** das **Dokumentenkonto**, in dem die Datei gespeichert werden soll.

2. Legen Sie eine CSV- oder Excel-Datei auf **CSV- oder Excel-Datei hier ablegen** ab oder klicken Sie auf **Datei auswählen**. Die Datei wird in den Ordner `/foundation/` des Dokumentenkontos hochgeladen.

   Für eine Datei, die bereits im Dokumentenkonto liegt, geben Sie ihren **Dateipfad** ein, zum Beispiel `/foundation/budget.csv`, und klicken Sie auf **Datei hinzufügen**.

   Um jeden Monat eine neue Datei zu lesen, fügen Sie alle Dateien eines Ordners hinzu, deren Name passt: Geben Sie den Ordner ein und was die **File names that** enthalten, womit sie beginnen, womit sie enden, ob sie genau übereinstimmen oder einem Muster entsprechen, und klicken Sie auf **Add files**. Dateien in Ordnern innerhalb dieses Ordners werden nicht gelesen.

3. PlaidCloud liest die Datei und schlägt eine Zuordnung vor:

   - **Erkanntes Trennzeichen, Dezimaltrennzeichen und Datumsangaben.** Das Trennzeichen (Komma, Semikolon, Tabulator oder senkrechter Strich), das Dezimaltrennzeichen und das Datumsformat werden für Sie erkannt.
   - **Dataset**: die Tabelle des Common Finance Model, zu der die Datei gehört, ermittelt aus dem Dateinamen und den Spaltenüberschriften. Wenn die Zuordnung nicht eindeutig ist, wählen Sie sie aus der Liste.
   - **Dezimaltrennzeichen**: **Punkt (1,234.56)** oder **Komma (1.234,56)**.
   - **Datumsformat**: wird angezeigt, wenn die Datei Datumsangaben enthält. Ändern Sie es, wenn das erkannte Format falsch ist: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` oder `MM/DD/YYYY`.
   - Ein Raster aus **Spalte in Datei**, **Typ**, **Beispiele** und **Geht nach**. Ändern Sie **Geht nach**, um eine Spalte in ein anderes Feld zu leiten oder auf **Nicht laden** zu setzen.

4. Beantworten Sie die Fragen, die die Datei aufwirft, etwa **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** oder **Are revenues shown as negative numbers?** Jede wird nur gestellt, wenn die Datei es nicht schon sagt.

5. Prüfen Sie, wohin jede Spalte geht, und klicken Sie dann auf **Zuordnung bestätigen**.

</Steps>

Diese Optionen erscheinen bei einer Datei, wenn sie zutreffen:

| Option | Verwenden Sie sie, um |
|---|---|
| **Which source do these rows apply to?** | eine Code-Zuordnungsdatei auf eine Quelle zu beschränken. **Every source** wendet sie auf alle an. |
| **Where does this file come from?** | festzulegen, ob die Datei **This project's own codes** enthält oder aus einem **Another system** stammt, das Sie benennen, zum Beispiel `SAP Germany export`. Eine Datei aus einem anderen System wird wie eine ERP-Quelle auf gemeinsame Codes geprüft. |
| **Split … into … parts at each …** (unter **Erweitert**) | eine Spalte, die mehrere Werte enthält, etwa `100-200-300`, aufzuteilen und jeden Teil in ein eigenes Feld zu leiten. |
| **Which currency do you report in?** | die Berichtswährung festzulegen, wenn das Projekt noch keine hat. Schreiben Sie sie mit drei Buchstaben, zum Beispiel `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | die Ergebnisse Ihres Konsolidierungssystems zu laden, damit die Konzern-Gewinn- und Verlustrechnung [abgestimmt](#mit-ihrem-konsolidierungssystem-abstimmen) werden kann. |

Um eine Datei aus dem Projekt zu nehmen, klicken Sie unter **Dateien** neben ihr auf **Entfernen** oder in ihrer Zuordnung auf **Remove this file** und bestätigen Sie. Ihre Zahlen verschwinden aus Ihren Berichten, sobald Sie das nächste Mal auf **Apply changes** klicken.

Wenn PlaidCloud das Dataset, das Dezimaltrennzeichen oder die Reihenfolge der Datumsangaben nicht selbst bestimmen kann, zum Beispiel bei einer Datei, deren Datumsangaben als Tag/Monat oder Monat/Tag gelesen werden könnten, fordert es Sie auf, vor dem Bestätigen zu wählen. Das Hinzufügen einer zweiten Datei für dasselbe Dataset ersetzt die erste. Wenn die Spalten einer späteren Datei nicht zum Dataset passen, nennt der Ladevorgang die Datei und die Spalten und fordert Sie auf, die Datei oder ihre Spaltennamen zu korrigieren oder **Schema Mismatch** des Schritts auf `union` zu setzen.

Akzeptierte Dateien sind CSV-, TSV- und TXT-Textdateien, Excel-Dateien im Format `.xlsx` (gelesen wird das erste Blatt) und Parquet-Dateien.

<Aside type="note">
Eine fehlende oder leere Datei bricht einen Ladevorgang nie ab. Beim Hinzufügen heißt es, dass noch nichts zuzuordnen ist, und ein Ladevorgang endet mit einer Warnung, die den Pfad nennt, und lässt dieses Dataset leer. Fügen Sie die Datei erneut hinzu, sobald sie existiert.
</Aside>

## Daten laden

Klicken Sie auf der Karte **Laden** oder der Karte **Letzter Ladevorgang** auf **Laden**. Der Ladevorgang liest Ihr verbundenes ERP und Ihre bestätigten Dateien, überführt sie in das Common Finance Model, rechnet sie in die Berichtswährung um, führt die Bereitschaftsprüfungen aus und baut die Modelle der Vorlage neu auf.

- Pro Projekt läuft immer nur ein Ladevorgang. Ein zweites **Laden** oder **Apply changes** meldet, dass bereits ein Ladevorgang läuft, und solange einer läuft, können Sie keine Quellen ändern.
- Wenn andere Workflows dieselbe ERP-Verbindung verwenden, listet der erste Ladevorgang sie auf und bittet Sie um Bestätigung, weil ein Ladevorgang aus dem ERP liest und diese Workflows verlangsamen kann. Klicken Sie auf **Trotzdem laden**, um fortzufahren.
- Nach einem Upgrade von PlaidCloud aktualisiert das **Laden** eines Architect auch die generierten Workflows des Projekts und erstellt die Arbeitstabellen, die sie brauchen. Bis dahin zeigt die Statusseite einen gelben Eintrag, „The workflows were generated by an earlier release. An Architect's Load updates them.“, und das **Laden** eines Managers warnt, dass nur ein Architect sie aktualisieren kann.
- Ein fehlgeschlagener Ladevorgang wird rot angezeigt und versteckt sich nie hinter früheren Ergebnissen. Schlägt die Konsolidierung fehl, nennt der Status den Schritt, bei dem sie angehalten hat, statt alte Konzernergebnisse zu zeigen. Zeilen aus einem früheren Ladevorgang zeigen **Aus einem früheren Ladevorgang. Erneut laden.**, bis ein Ladevorgang gelingt.
- Wenn das Lesen einer Entität und Periode fehlschlägt, werden die übrigen trotzdem geladen. Führen Sie **Laden** erneut aus, um nur das Fehlgeschlagene abzurufen.

### Zurückgehaltene Zeilen

Wenn sich Quellen überschneiden, behält ein Ladevorgang von jeder Zahl eine Kopie und hält die anderen zurück, statt sie doppelt zu zählen. Zurückgehaltene Zeilen werden mit ihrer Quelle, ihrer Entität und dem Grund festgehalten, und der Ladevorgang endet mit einer Warnung, die die Anzahlen nennt, zum Beispiel `120 rows of NetSuite EU also provided by a source ranked ahead`. Die Gründe sind:

| Grund | Bedeutung |
|---|---|
| In einem anderen Rechnungslegungsbuch | Die Zeile gehört zu einem Berichtsbuch, das die Quelle nicht lesen soll. |
| Außerhalb der Perioden, die die Quelle liefert | Die Zeile liegt außerhalb der für das Unternehmen festgelegten Monate **Von** und **Bis**. |
| Auch von einer höher eingestuften Quelle geliefert | Eine in der Reihenfolge höhere Quelle deckt dasselbe Unternehmen und denselben Monat ab. |
| Auch in einer früheren Datei der Quelle | Eine frühere Datei derselben Quelle deckt den Monat bereits ab. |
| Durch eine Datei ersetzt | Eine Datei ersetzt die ERP-Zeilen für diese Entität und diesen Monat. |
| Trägt einen Code, den auch eine andere Quelle verwendet | Der Code braucht Ihre Antwort. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| Trägt einen Code, der zwei Codes zugeordnet ist | Die Code-Zuordnung gibt dem Code zwei Antworten. |

Statistische Konten wandern statt ins Hauptbuch in die Verteilungstreiber und werden als verschoben angezeigt, nicht als Problem.

### ERP-Daten und Dateien zusammen

Eine Datei ersetzt nur, was sie abdeckt, und die übrigen Zeilen aus Ihrem ERP bleiben bestehen.

- **Stammdatendateien** (Konten, Abteilungen, Kunden, Produkte und Segmentwerte) ersetzen die ERP-Zeilen mit demselben Code.
- **Bewegungsdatendateien** ersetzen die ERP-Zeilen für dieselbe Entität und denselben Monat. Hauptbuch- und Saldenlistendateien gleichen außerdem nach Ledger ab, Budgetdateien nach Szenario und Dateien mit statistischen Treibern nach Szenario und Treiber.

Deckt eine Datei später einen Monat nicht mehr ab, kehren die Daten des ERP für diesen Monat beim nächsten Ladevorgang zurück.

## Entitätszuordnung

Jede Quelle benennt ihre Entitäten mit eigenen Codes. Die **Entitätszuordnung** ordnet diese Codes den Entitäten in Ihrem Entitätsstamm zu, sodass die Zeilen aus jeder Quelle bei derselben Entität landen.

Um sie zu verwenden, fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Entitätszuordnung**:

| Spalte | Inhalt |
|---|---|
| `source_entity` | Der Code, wie die Quelle ihn führt, etwa ein Buchungskreis. |
| `entity` | Die Entität, zu der er gehört, wie der Entitätsstamm sie benennt. |

- Ein Code, der nicht in der Zuordnung steht, wird unverändert verwendet.
- Mehrere Codes können einer Entität zugeordnet werden. Ihre Zeilen werden zusammengefasst, und ein Monat gilt als abgeschlossen, sobald er für alle abgeschlossen ist.
- Codes in der Zuordnung gelten für jede Quelle, daher müssen die Entitätscodes jeder Quelle quellenübergreifend eindeutig sein.
- Eine Zeile einer **Entitäten**-Datei ersetzt die Entität des ERP mit demselben Entitätscode.

Die Prüfung **Nicht zugeordnete Entitäten** markiert jede Zeile, deren Entität weder im Entitätsstamm steht noch ihm durch die Zuordnung zugeordnet ist. Solange kein Entitätsstamm geladen ist, zeigt sie **– Nicht zutreffend**.

## Codes quellenübergreifend zuordnen

Zwei Quellen können denselben Code für Verschiedenes oder verschiedene Codes für dasselbe verwenden. Wenn ein Code in mehr als einer Quelle vorkommt, hält Data Foundation seine Zeilen zurück, bis Sie sagen, ob er überall dasselbe bedeutet, damit jeder Betrag nur einmal gezählt wird. Die Prüfung **Codes waiting for your answer** listet sie auf, die ersten 10 und dann „and K more“, und die Karte **What to do next** auf der Registerkarte **Foundation** hat eine Schaltfläche **Prüfen**.

**Prüfen** öffnet **Codes waiting for your answer**. Dort sind die Codes danach gruppiert, was sie sind: **Kontotypen**, **Unternehmen**, **Konten**, **Abteilungen**, **Profit-Center**, **Kunden**, **Produkte** und jede zusätzliche Kategorie. Für jeden Code wird angezeigt, wie ihn jede Quelle nennt, und ein Vorschlag:

- **Looks like the same thing**, wenn die Quellen dem Code denselben Namen geben.
- **Looks like different things**, wenn die Namen sich unterscheiden.
- **We can't tell. Please answer.**, wenn es keinen Anhaltspunkt gibt.

Beantworten Sie einen Code nach dem anderen mit **Yes, the same** oder **No, different**, oder beantworten Sie eine ganze Gruppe auf einmal mit **Accept all** (jeden Vorschlag übernehmen), **All the same** oder **All different**. Bei Konten können Sie auch eine ganze übergeordnete Gruppe des Kontenplans auf einmal beantworten. Wo eine Quelle keine Kontotypen führt, wählen Sie für eine Gruppe von Konten **Use this type**: **Umsatz**, **Cost of goods sold**, **Operating expenses**, **Non-operating income and expenses**, **Assets**, **Liabilities** oder **Equity**.

Zuordnungen werden je Quelle und Dimension gespeichert, sodass eine Antwort für die Abteilungen einer Quelle nie die Konten einer anderen Quelle ändert. Antworten werden laufend gespeichert, mit **Saved. Press Apply changes to use your answers.** Klicken Sie auf **Apply changes**, um sie zu verwenden.

Sie können die Zuordnungen auch in einer Datei bereitstellen. Fügen Sie eine Datei mit dem Dataset **Code map** hinzu und wählen Sie **Which source do these rows apply to?**, um sie auf eine Quelle zu beschränken.

## Wählen, welche Quelle ab wann zählt

Wenn zwei Quellen dieselben Monate liefern, fordert die Prüfung **Which source covers which months** Sie zu einer Auswahl auf. Klicken Sie in der Karte **What to do next** auf **Choose which source counts from when**, um **Which source counts from when** zu öffnen, das jede Überschneidung nach Unternehmen auflistet. Wählen Sie die Quelle, die zählt, geben Sie in **That month is** den Monat ein, ab dem sie zählt, zum Beispiel `2026-04`, und klicken Sie auf **Apply changes**. Die andere Quelle behält die früheren Monate.

Derselbe Dialog warnt, wenn zwei Quellen für eine Währung unterschiedliche Wechselkurse liefern; verwendet werden die Kurse der in der Reihenfolge höheren Quelle.

## Währungsumrechnung

Jeder Ladevorgang rechnet die Beträge von Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget aus ihrer lokalen Währung in eine Berichtswährung um. Berichte und Modelle lesen die umgerechneten Beträge, sodass Entitäten in verschiedenen Währungen, aus beliebigen Systemen, korrekt summiert werden.

### Die Berichtswährung

Um die Berichtswährung zu wählen, setzen Sie die Projektvariable `reporting_currency` auf einen Währungscode wie `USD`. Siehe [Projektvariablen verwalten](/de/guides/projects/managing-projects/#projektvariablen-verwalten). Die Vorlage legt sie leer an. Solange sie leer ist, verwendet jeder Ladevorgang das Erste der folgenden Elemente, das genau eine Währung benennt:

1. Die Konzernwährung der Entitäten.
2. Die lokale Währung der obersten Entitäten, derjenigen ohne übergeordnete Entität.
3. Die lokale Währung der Dateien.

Benennt keines davon genau eine Währung, zeigt **Währungsumrechnung** ein Problem, bis Sie `reporting_currency` festlegen.

Beträge, die bereits in der Berichtswährung vorliegen, bleiben unverändert, sodass ein Projekt, dessen Daten alle in einer Währung vorliegen, keine Kurse braucht.

Auch Umsatz-, Lagerbestands- und Budgetdateien können eine Währung enthalten. Ordnen Sie eine Spalte namens `Currency` oder `Local Currency` zu, dann wird sie automatisch erkannt, und die lokalen Beträge der Datei werden in die Berichtswährung umgerechnet. Ein Konzern- oder Berichtsbetrag, der bereits in der Datei steht, bleibt unverändert. Die Standardkosten eines Produkts werden nicht umgerechnet.

### Wechselkurse

Ein Kurs rechnet für einen Monat eine Einheit einer Währung in die Berichtswährung um: Der umgerechnete Betrag ist der lokale Betrag mal dem Kurs.

- **Aus Ihrem ERP** liest jeder Ladevorgang die Wechselkurse, die das ERP führt.
- **Aus einer Datei**: Fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Wechselkurse**. Ein Kurs in der Datei ersetzt den Kurs des ERP für dieselben Währungen und denselben Monat. Verwenden Sie eine Datei, um in einer Währung zu berichten, für die Ihre ERP-Systeme keine Kurse veröffentlichen, oder um geplante Kurse für Budgetmonate hinzuzufügen.

| Spalte | Inhalt |
|---|---|
| `from_currency` | Die Währung, aus der umgerechnet wird, zum Beispiel `EUR`. |
| `to_currency` | Die Berichtswährung, zum Beispiel `USD`. |
| `period` | Der Monat, als `YYYY-MM`. |
| `average_rate` | Der Durchschnittskurs des Monats. |
| `closing_rate` | Der Kurs am Monatsende. |
| `historical_rate` | Der historische Kurs, für das Eigenkapital und für Konten, die auf den historischen Kurs gesetzt sind. |

Verwendet werden nur Kurse in die Berichtswährung. Ein Kurs, der andersherum notiert ist, von der Berichtswährung in eine andere Währung, wird nicht invertiert.

### Welcher Kurs gilt

Jede Zeile wird aus ihrer eigenen Währung umgerechnet, sodass eine Zeile in einer anderen Währung als ihre Entität aus der Währung umgerechnet wird, in der sie vorliegt. Es gilt die erste Regel, die auf die Zeile passt:

| Zeile | Kurs |
|---|---|
| Statistische und nicht buchende Konten | Nicht umgerechnet. |
| Bereits in der Berichtswährung | Nicht umgerechnet. |
| Konto mit einem Kurstyp | Dieser Kurs: Durchschnitt, Stichtag oder historisch. Historisch fällt auf den Stichtagskurs zurück, wenn es keinen historischen Kurs gibt. Aus einem ERP ist der Kurstyp der eigene Kurstyp des Kontos. Ordnen Sie in einer Kontenplandatei eine Kurstyp-Spalte `fx_rate_type` mit `average`, `closing` oder `historical` zu. |
| Verkaufsposition | Der Durchschnittskurs der Periode. |
| Lagerbestand | Der Stichtagskurs der Periode. |
| Budgetzeile | Nach Konto, wie beim Hauptbuch: der Durchschnittskurs für Gewinn- und Verlustkonten und der Stichtagskurs für Bilanzkonten. |
| Gewinn- und Verlustkonto | Der Durchschnittskurs der Periode. |
| Eigenkapitalkonto | Der historische Kurs oder der Stichtagskurs, wenn es keinen historischen Kurs gibt. |
| Jedes andere Bilanzkonto | Der Stichtagskurs der Periode. |

Umgerechnete Beträge werden nicht gerundet, sodass die Summen nicht abweichen.

<Aside type="note">
Die Saldenliste enthält die Bewegungen jeder Periode, daher sind Bilanzbeträge die Bewegungen jedes Monats, umgerechnet zum Stichtagskurs dieses Monats. Es sind keine zum Periodenendkurs neu umgerechneten Bilanzen, und es gibt weder eine kumulierte Umrechnungsdifferenz noch eine Intercompany-Eliminierung. Verwenden Sie die umgerechneten Beträge für die Gewinn- und Verlustrechnung.
</Aside>

## Hierarchien

Jeder Ladevorgang baut die Dimensionen aus den Stammdaten jeder Quelle neu auf. Zu Beginn gibt es sieben Dimensionen und bis zu zehn zusätzliche Kategorien:

| Dimension | Aufgebaut aus |
|---|---|
| **Entität** | Entitäten und ihren übergeordneten Entitäten |
| **Konto** | Kontenplan und übergeordneten Konten |
| **Abteilung** | Abteilungen und ihren übergeordneten Abteilungen |
| **Kunde** | Kunden und ihren übergeordneten Kunden |
| **Produkt** | Produkten und ihren übergeordneten Produkten |
| **Segment 1** | Segmentwerten für `segment_1` |
| **Segment 2** | Segmentwerten für `segment_2` |
| **Segment 3** bis **Segment 10** | Segmentwerten für `segment_3` bis `segment_10`, wenn Ihre Quellen sie führen |

- Ein Datensatz ohne übergeordneten Datensatz oder einer, der sich selbst als übergeordneten Datensatz nennt, wird als Mitglied der obersten Ebene geladen.
- Weil jeder Ladevorgang die Hierarchien neu aufbaut, ändern Sie einen übergeordneten Datensatz im ERP oder in Ihrer Datei, nicht in der Dimension.
- Ein Problem in einer Hierarchie betrifft nur diese Dimension. Der Ladevorgang und die Modelle der Vorlage werden trotzdem abgeschlossen.
- Sie können jede zusätzliche Kategorie nach ihrem Inhalt umbenennen, zum Beispiel **Klasse** oder **Region**. Geben Sie unter **Rename extra categories** die Namen ein, die Ihre Berichte verwenden, und klicken Sie auf **Save names**. Namen bestehen aus Buchstaben, Ziffern, Leerzeichen, Punkten, Bindestrichen und Unterstrichen, bis zu 60 Zeichen.
- Jede Quelle gibt an, unter welchem Ihrer Kategorienamen jede ihrer eigenen zusätzlichen Kategorien läuft. Öffnen Sie **Erweitert** bei der Quelle, wählen Sie für jede den Namen oder wählen Sie **Leave out**, und klicken Sie auf **Speichern**. Quellen, die eine Kategorie unterschiedlich nennen, etwa `Class` und `Business area`, teilen sich dann einen Platz.

Um Segmenthierarchien aus einer Datei bereitzustellen, wählen Sie das Dataset **Segmentwerte**:

| Spalte | Inhalt |
|---|---|
| `segment` | Zu welchem Segment der Wert gehört: `segment_1` bis `segment_10`. |
| `segment_value` | Der Wert, wie Hauptbuch-, Umsatz- und Budgetzeilen ihn führen. |
| `segment_value_name` | Sein Name. |
| `parent_segment_value` | Sein übergeordneter Wert innerhalb desselben Segments. |

## Bereitschaftsprüfungen

Nach jedem Ladevorgang listet das Raster **Bereitschaft** jede Prüfung für jede Entität und Periode mit einem dieser Status auf:

| Status | Bedeutung |
|---|---|
| **● Bereit** | Die Prüfung wurde bestanden. |
| **▲ Aufmerksamkeit erforderlich** | Einen Blick wert, aber die Zahlen sind verwendbar. |
| **■ Problem** | Beheben Sie dies, bevor Sie sich auf die Ergebnisse verlassen. |
| **– Nicht zutreffend** | Für diese Prüfung gibt es noch keine Daten. |

Die Prüfungen sind:

| Prüfung | Was sie bestätigt |
|---|---|
| **Daten geladen** | Jede Geschäftsperiode hat Hauptbuchzeilen, und jedes Lesen aus dem ERP war erfolgreich. Eine abgeschlossene Periode ohne Zeilen ist ein Problem; eine offene Periode ohne Zeilen erfordert Aufmerksamkeit. |
| **Saldenliste stimmt mit Hauptbuch überein** | Die Saldenliste entspricht dem Hauptbuch für jede Entität, Periode und jedes Konto. Wo sowohl die Saldenliste als auch das Hauptbuch für ein Konto Abteilungen führen, stimmt sie auch jede Abteilung ab. |
| **Umsatz stimmt mit Hauptbuch überein** | Die Verkaufspositionen entsprechen den Umsatz- und COGS-Konten des Hauptbuchs für jede Periode. |
| **Unbekannte Produkte/Kunden** | Jede Verkaufsposition nennt ein Produkt und einen Kunden, die in den Produkt- und Kundenstammdaten existieren. |
| **Konten fehlen im Kontenplan** | Jede Hauptbuchzeile nennt ein Konto, das im Kontenplan steht. Zeilen mit einem unbekannten Konto bleiben in der Gewinn- und Verlustrechnung unberücksichtigt. Ein Konto mit Buchungen, aber ohne Kontotyp ist ebenfalls ein Problem, und eine Quelle, deren Kontenplan Umsatzkonten, aber kein Konto für Herstellungskosten der verkauften Waren typisiert, erfordert Aufmerksamkeit. |
| **Währungsumrechnung** | Jede Zeile von Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget hat einen Betrag in der Berichtswährung. Eine Gewinn- und Verlust- oder Umsatzzeile ohne Kurs ist ein Problem, weil die Gewinn- und Verlustrechnung umgerechnete Beträge liest. Eine Bilanz-, Lagerbestands- oder Budgetzeile ohne Kurs erfordert Aufmerksamkeit. Ein Budgetmonat ohne Kurs wird gelb angezeigt, laden Sie daher geplante Kurse für Budgetmonate. Siehe [Währungsumrechnung](#währungsumrechnung). |
| **Nicht zugeordnete Entitäten** | Jede Zeile von Hauptbuch, Saldenliste und Umsatz nennt eine Entität im Entitätsstamm, direkt oder über die Entitätszuordnung. Nicht zutreffend, bis ein Entitätsstamm geladen ist. Siehe [Entitätszuordnung](#entitätszuordnung). |

Ladevorgänge mit mehr als einer Quelle fügen diese Prüfungen hinzu:

| Prüfung | Was sie bestätigt |
|---|---|
| **Reporting book** | Für eine Quelle, die mehrere Rechnungslegungsbücher für eine Entität führt, wurde das Berichtsbuch gewählt. Bis Sie wählen, zählt nur das erste Buch. |
| **Codes waiting for your answer** | Jeder Code, den mehr als eine Quelle verwendet, wurde beantwortet. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| **Extra categories from your sources** | Jede zusätzliche Kategorie, die eine Quelle führt, hat einen Namen oder wurde ausgelassen. |
| **Which source covers which months** | Keine zwei Quellen liefern dieselben Monate eines Unternehmens, es sei denn, Sie haben gewählt, welche zählt. |
| **Account types and hierarchy** | Jeder übergeordnete Datensatz, den eine Dimension nennt, existiert, und kein Mitglied ist sein eigener übergeordneter Datensatz oder Vorfahre. Ein fehlender übergeordneter Datensatz setzt seine untergeordneten an die Spitze der Hierarchie, und eine Schleife verhindert, dass diese Hierarchie geladen wird. Die Summen bleiben unberührt. |
| **Geschäftskalender** | Die Geschäftsperioden jeder Entität sind Kalendermonate, und jeder Monat an Zeilen lässt sich einer Geschäftsperiode zuordnen. Es erfordert Aufmerksamkeit, wenn die Perioden einer Entität keine Kalendermonate sind (4-4-5, 13 Perioden) oder wenn die Zeilen eines Monats in mehr als einer Geschäftsperiode liegen könnten oder dem Geschäftskalender der Monat fehlt. |

Jede Zeile, die nicht bereit ist, sagt in der Spalte **Was zu tun ist**, was zu tun ist, etwa den Kontenplan zu laden, Wechselkurse zu laden oder **Laden** für eine Periode erneut auszuführen.

Das Raster zeigt außerdem zwei Einrichtungsprüfungen, die nur erscheinen, wenn sie Aufmerksamkeit erfordern:

| Prüfung | Wann sie erscheint |
|---|---|
| **Gemeinkostenumlage** | Nur eine der Projektvariablen `overhead_department` und `overhead_driver` ist gesetzt, oder kein Verteilungstreiber passt zu `overhead_driver`, sodass die Umlage nichts bewirken würde. Setzen Sie beide oder leeren Sie beide, um die Gemeinkostenumlage auszuschalten. |
| **Budgetvergleich** | Budgetzeilen sind geladen, aber keine liegt in der Version, die die Projektvariable `budget_version` nennt, sodass der Budgetvergleich leer wäre. |

## Management-Konsolidierung

Jeder Ladevorgang erstellt eine Management-Konsolidierung: die Konzern-Gewinn- und Verlustrechnung aller Entitäten des Konzerns, in der Berichtswährung, mit eliminierten Intercompany-Beträgen. Sie dient dem Management-Reporting. Ihr Konsolidierungssystem bleibt der Nachweis für den gesetzlichen Konzern; stimmen Sie unten damit ab.

<Aside type="note">
Die Management-Konsolidierung umfasst nur die Gewinn- und Verlustrechnung. Sie ist keine gesetzliche oder rechtliche Konsolidierung und hat weder eine konsolidierte Bilanz noch Umrechnungsdifferenzen, Geschäfts- oder Firmenwert oder Minderheitsanteile.
</Aside>

### Konzern auswählen

Öffnen Sie unter **Quellen** die Option **Gruppe**, um die Unternehmen im Konzern zu sehen. Ein Unternehmen, dessen Markierung Sie aufheben, bleibt einzeln in Ihren Berichten, wird aber aus der Konzernsumme ausgelassen. Klicken Sie auf **Save group**. Die Änderung gilt beim nächsten **Laden** oder **Apply changes**. Ein neues Unternehmen gehört zum Konzern, bis Sie es abwählen.

Das Geschäftsjahr des Konzerns beginnt in dem Monat, den die Projektvariable `group_fy_start_month` festlegt, das ist `1`, sofern Sie es nicht ändern.

### Was Sie bekommen

| Tabelle | Inhalt |
|---|---|
| **Group P&L** | Eine Zeile je Entität, Periode und Position (Umsatz, Herstellungskosten der verkauften Waren, Betriebsaufwand, nicht operativ, Intercompany-Differenz), in der Berichtswährung. Umsatz und Kosten tragen ihr natürliches Vorzeichen. |
| **Group P&L year to date** | Dasselbe, kumuliert im Jahr, bis zur zuletzt vollständig geladenen Periode des Konzerns. |
| **Intercompany pairs** | Eine Zeile je Paar von Entitäten, Konzern und Periode, mit dem Betrag jeder Seite und dem Restbetrag. |
| **Intercompany lines** | Die Hauptbuchzeilen hinter einer Konzernzahl oder einem Paar, mit dem Handelspartner. |
| **Abstimmung** | Die kumulierte Konzern-GuV im Vergleich zu Ihrem Konsolidierungssystem. |

In diesen Tabellen erscheinen drei Entitätsnamen:

| Entität | Bedeutung |
|---|---|
| **Eliminations** | Die Intercompany-Eliminierungen. Sie saldieren sich zu null, belassen Sie sie also für die Konzernzahlen und filtern Sie sie für die Summe der Entitäten vor der Eliminierung heraus. |
| **Group total** | Die Gesamtsumme des Konsolidierungssystems, in der Abstimmung. |
| **Unmapped** | Zeilen ohne Periode sowie Konten oder Entitäten Ihres Konsolidierungssystems, die dieses Projekt nicht hat. |

Die Kennzahlen **Consolidated income**, **Consolidated result** und **IC difference** sowie ein Analysepfad für jede Tabelle beantworten Fragen zum Konzern.

### Intercompany-Eliminierungen

Intercompany-Zeilen werden nach Handelspartner abgeglichen. Verwendet wird der Partner der Zeile; hat eine Zeile keinen, gilt der Partner ihres Kunden. Beide Seiten eines Paars werden eliminiert, und der Betrag, um den die beiden Seiten voneinander abweichen, wird auf eine Intercompany-Differenzzeile gebucht. Jedes Paar bekommt einen Grund:

| Grund | Bedeutung |
|---|---|
| **Abgeglichen** | Beide Seiten haben denselben Betrag gebucht. |
| **Only one side booked** | Eine Entität hat den Vorgang gebucht, ihr Partner nicht. |
| **Not eliminated** | Eine Zeile des Paars hat keinen Wechselkurs, daher wird keine Seite eliminiert. |

Ein Paar wird anhand seines Stands seit Jahresbeginn beurteilt. Die Zeile **Intercompany balances** wird gelb, wenn die Differenz eines Paars über der Projektvariable `group_amber` liegt (Standard `1`), und rot über `group_red` (Standard `1000`). Zeilen ohne Partner oder mit einem Partner, der keine Entität ist, werden nicht eliminiert und in dieser Zeile mitgezählt. Eine Quelle, die Partner führt, neben einer, die keine führt, wird gelb angezeigt.

Die eigenen Eliminierungsentitäten einer Quelle bleiben aus der Konzern-GuV heraus, und die Zeile **Konsolidierung** sagt das.

### Mit Ihrem Konsolidierungssystem abstimmen

Fügen Sie die Ergebnisse, die Ihr Konsolidierungssystem berichtet, als Datei hinzu und aktivieren Sie **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)**, wenn Sie ihre Zuordnung bestätigen. Beantworten Sie **Which version of the numbers is this?** mit dem Namen des Systems. Die Tabelle **Abstimmung** zeigt dann **ours**, **reported** und **Differenz** für jede Entität und Position, kumuliert im Jahr. Eine Differenz erklärt sich meist in den Zeilen **Eliminations**, **Group total** und **Unmapped** oder durch die Wechselkurse, die das System verwendet. Die Zeile **Reconciliation to the source** listet jede Position über `group_amber` auf.

### Wer es sehen kann

Konzernergebnisse folgen dem Zeilenzugriff des Projekts. Wenn der Zeilenzugriff die Konzernergebnisse verhindert, wird der Status gelb angezeigt. Wer nur einige Entitäten sieht, sieht die Summen dieser Entitäten vor der Eliminierung. Die Zeilen **Eliminations** und die Intercompany-Tabellen erfordern Zugriff auf jede Entität.

Wenn das Projekt einschränkt, wer welche Zeilen sieht, und zwar nach einer Spalte, die die Konzerntabellen nicht führen, etwa der Abteilung, bleiben die Konzernergebnisse für alle ausgeschaltet, und **Konsolidierung** zeigt **Group views are off**. Nur ein Architect kann dann unter **Gruppe** **Everyone on the project may see the group results** aktivieren. Die Änderung gilt beim nächsten **Laden** oder **Apply changes**.

## Aktuell halten

Nachdem ein Ladevorgang aus Ihrer ERP-Verbindung ohne Probleme erfolgreich war, erscheint **Nächtlich aktualisieren** auf der Karte **Letzter Ladevorgang**. Klicken Sie darauf, um **Laden** jede Nacht um 2:00 Uhr in Ihrer Zeitzone auszuführen. Die Karte zeigt dann **Nightly refresh: Every night at 2:00** und wer ihn eingerichtet hat.

Der nächtliche Ladevorgang läuft als die Person, die ihn eingerichtet hat. Kann diese Person die ERP-Verbindung nicht mehr verwenden, meldet das Raster, dass der nächtliche Ladevorgang übersprungen wird; richten Sie ihn erneut ein. Ein Projekt, das nur Beispieldaten enthält, lässt sich nicht planen.

Eine fehlende oder leere Datei bei einem nächtlichen Ladevorgang führt zu einer Warnung, die den Pfad nennt, nicht zu einem Fehler, und der Rest des Modells wird trotzdem geladen.

## Business Names

**Business names** auf der Registerkarte **Foundation** geben den Codes in Ihrem Modell die Namen, die Ihr Unternehmen verwendet. Berichte, Kennzahlen und der Assistent zeigen diese Namen, und ein gespeicherter Name gilt sofort. Spätere Ladevorgänge behalten ihn.

1. Klicken Sie auf **Add a name** und wählen Sie die **Art**: **Kategorie**, **P&L line**, **Metric** oder **Spalte**.
2. Geben Sie den **Code** ein: `segment_1` bis `segment_10` für eine Kategorie, den Schlüssel der Position für eine P&L line, den Namen der Kennzahl oder `table.column` für eine Spalte.
3. Geben Sie den **Name** ein, höchstens 60 Zeichen in einer Zeile.
4. Klicken Sie auf **Save names**.

Das Speichern ersetzt die ganze Liste. Eine Zeile mit leerem Namen entfernt diesen Namen, und **Ausgewählte entfernen** entfernt die Zeilen, die Sie markieren. Denselben Code zweimal zu benennen, wird abgelehnt. Business Names werden auch in die Beschreibung des Analysepfads geschrieben, damit der Assistent Ihre Wörter verwendet, und diese Beschreibung hat eine Längenbegrenzung: Würde ein Name sie zu lang machen, wird nichts gespeichert und Sie erhalten eine Meldung.

## Eine Zahl erklären

**Explain this number** zeigt, woraus sich eine Zahl der Gewinn- und Verlustrechnung zusammensetzt. Im Raster **Bereitschaft** hat eine Zeile für eine Entität und einen Monat **Explain this number**, das die operative Marge der Entität für diesen Monat öffnet. Das Fenster teilt die Zahl in Schichten auf, die sich zur Gesamtsumme oben addieren:

| Schicht | Inhalt |
|---|---|
| **From the general ledger** | Was das Hauptbuch auf die Position gebucht hat. |
| **Allocated in** | Kosten, die Ihre [Umlageregeln](#umlageregeln) dieser Entität zugewiesen haben. |
| **Allocated out** | Kosten, die diese Entität auf andere umgelegt hat. |
| **Eliminated in the group** | Intercompany-Beträge, die im Konzernergebnis eliminiert wurden. |

Jede Schicht hat einen Satz, der sagt, was sie ist, und ihre größten Quellbelege, mit Quellsystem, Beleg und Konto. Es werden nur Schichten angezeigt, die Zeilen haben. Das Fenster folgt Ihrem Zeilenzugriff: Sie erklären nur Zahlen, die Sie sehen können. Bei einer Zahl, hinter der nichts steht, erscheint **Nothing to explain**.

## Umlageregeln

Umlagen verteilen gemeinsame Kosten, etwa Gemeinkosten, auf Abteilungen, Produkte und Kunden. Das Modell hat zwei Stufen: **Stage 1: overhead to departments** und **Stage 2: departments to products and customers**. Öffnen Sie **Aktionen > Allocations...**, um zu sehen oder zu ändern, wie jede Stufe erfolgt. Ohne Änderungen arbeiten sie wie vor dem Assistenten. Ein Leser kann die Regeln öffnen, aber nicht speichern.

Für jede Stufe stellt der Assistent vier Fragen:

| Schritt | Frage | Auswahl |
|---|---|---|
| **Pool** | Welche Kosten wollen Sie verteilen? | Die Art des Kontos und, für Stufe 1, die Abteilung, die die Kosten trägt, oder **All departments**. |
| **Driver** | Wonach wollen Sie sie verteilen? | **Statistic**, die Sie als Verteilungstreiber geladen haben, etwa Headcount oder Quadratmeter, **Net sales amount**, **Sales quantity** oder **Spread evenly**. Verwenden Sie den Treiber von **Same period** oder **Same period last year**. |
| **Ziel** | Wo landen sie? | Stufe 1: Abteilungen. Stufe 2: Produkte, Kunden oder beides. |
| **Methode** | Was passiert, wenn ein Treiber negativ ist? | **Ignore negative values** oder **Stop and tell me**. |

Unter den Schritten zeigt **Preview for** für einen Monat, geschrieben als Jahr und Monat wie `2026-09`, was die Regeln, auch ungespeicherte, bewirken würden: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Alles Nicht-Umgelegte sind Kosten, für die kein Treiber vorhanden war. Die Vorschau folgt Ihrem Zeilenzugriff.

Klicken Sie auf **Speichern**. Die Regeln gelten ab dem nächsten **Laden** oder wenn Sie auf **Apply changes** klicken. Wenn Sie einen Umlageschritt von Hand bearbeitet haben, bleibt Ihre Änderung erhalten und wird nicht überschrieben, und beim Speichern wird sie genannt. Während ein Ladevorgang läuft, können Sie nicht speichern.

## Board Pack

Ein Board Pack schreibt Ihre Ergebnisse nach Zeitplan in einen Ordner eines Dokumentenkontos, versandfertig. Öffnen Sie **Aktionen > Board pack...**, wählen Sie ein **Dokumentenkonto** und einen **Ordner**, etwa `/board-packs`, und klicken Sie auf **Speichern**. Jede Ausführung schreibt:

- Eine Excel-Arbeitsmappe, `Board pack.xlsx`, mit der Gewinn- und Verlustrechnung nach Entität, einer Margenbrücke sowie den besten und schlechtesten Kunden.
- Ein PDF des Dashboards der Gewinn- und Verlustrechnung.

Hat das Projekt noch kein Dashboard, wird nur die Arbeitsmappe geschrieben, und die Ausführung nennt den Grund. Klicken Sie auf **Run now**, um sofort ein Pack zu erstellen; seine Dateien erscheinen im Ordner, sobald es fertig ist. Die Karte zeigt die letzte Ausführung und ihr Ergebnis sowie die nächste Ausführung. Das Pack wird vom Workflow **Board pack** des Projekts erstellt, den die nächtliche Aktualisierung nicht ausführt: Um es nach Zeitplan zu erstellen, planen Sie diesen Workflow mit dem [Ereignis-Scheduler](/de/administration/scheduled-events/event-scheduler/), zum Beispiel für einen Zeitpunkt nach dem Ende der nächtlichen Aktualisierung. Nur wer das Projekt ändern kann, richtet es ein.

## Wiederherstellungspunkte

Ein Wiederherstellungspunkt entsteht, wenn jedes **Laden** oder **Apply changes** beginnt, egal wer es startet, auch bei einem geplanten Ladevorgang, und vor jeder Änderung an Zuordnungen oder Quellen. Er enthält die Tabellen des Modells, die Dimensionen und die Einstellungen, aus denen der nächste Ladevorgang aufbaut: Ihre Quellen, Dateien und Umlageregeln. Die letzten sieben Punkte für Ladevorgänge und die letzten fünf vor Änderungen bleiben erhalten, sodass Änderungen die Punkte für Ladevorgänge nie verdrängen. Ältere Punkte fallen heraus.

Um zurückzugehen, öffnen Sie **Aktionen > Restore...**, wählen Sie einen Punkt und klicken Sie auf **Wiederherstellen**. **Wiederherstellen** steht zur Verfügung, sobald ein Punkt existiert. Beim Wiederherstellen wird zuerst das Projekt, wie es jetzt ist, als eigener Punkt festgehalten, sodass Sie erneut zurückgehen können. Danach werden die Tabellen, die Dimensionen und diese Einstellungen so zurückgesetzt, wie sie waren, und der nächste Ladevorgang baut darauf auf. Eine Tabelle ohne gespeicherte Kopie oder eine Engine, die keinen Verlauf halten kann, wird in einer Warnung genannt, und der Rest wird wiederhergestellt. Ein herausgefallener Wiederherstellungspunkt wird abgelehnt, und während ein Ladevorgang läuft, können Sie nicht wiederherstellen.

## Ein Projekt klonen

**Aktionen > Clone...** kopiert das Projekt unter einem von Ihnen vergebenen Namen. Die Kopie behält die Vorlage, Ihre Änderungen am Modell sowie Ihre Kennzahlen und Analysepfade und lädt die Beispieldaten. Ihre Quellen sind nicht verbunden, verbinden Sie sie also in der Kopie, bevor Sie laden. Sie können weiterarbeiten, während die Kopie erstellt wird, und **Projekt öffnen** bringt Sie dorthin, wenn sie fertig ist.

## Als eigene Vorlage speichern

Speichern Sie die Einrichtung eines Projekts, um sie für den nächsten Kunden oder die nächste Entität wiederzuverwenden. Öffnen Sie **Aktionen > Save as my template...**, wählen Sie das Dokumentenkonto und benennen Sie die Datei. Ein Name, der auf `.zip` endet, wird hinzugefügt, wenn Sie ihn weglassen. Das Speichern über eine vorhandene Datei wird abgelehnt, wählen Sie also einen anderen Namen.

Die Datei enthält die Struktur des Projekts, Ihre Änderungen am Modell, Kennzahlen und Analysepfade, die Business Names für Entitäten und Konten sowie die Zeilen der Konfigurationstabellen der Vorlage, etwa die Aktivitätszuordnung von [Cost to Serve](/de/guides/projects/cost-to-serve/) oder die Richtlinienbandbreiten von [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/). Sie lässt Verbindungen, Dateien, den nächtlichen Zeitplan, Ausführungen, Wiederherstellungspunkte, das Board Pack und die Zugriffsberechtigten aus.

Um sie zu verwenden, erstellen Sie ein Projekt, wählen Sie unter **Starten mit** die Option **From a template file...** und wählen Sie das Dokumentenkonto und den Pfad. Das neue Projekt ist privat für Sie, und alle Quellen warten darauf, verbunden zu werden. Eine spätere Version der Vorlage führt ihre Änderungen um die Schritte herum zusammen, die Sie bearbeitet haben. Gibt es am Pfad keine Datei, wird nichts erstellt und Sie erhalten eine Meldung. Jeder, der das Dokumentenkonto lesen kann, kann aus der Datei installieren. Um sie in einem anderen Workspace zu verwenden, laden Sie die Datei herunter und dort hoch.

## Offene Fragen mit Ask klären

Nach einem Ladevorgang kann ein Projekt noch auf drei Angaben warten: Konten, die der Kontenplan ohne Typ lässt, Codes, die mehr als eine Quelle verwendet, und Spalten in Ihren Dateien, die zu nichts passten. Bitten Sie den Assistenten, sie zu klären: Verwenden Sie von einem KI-Assistenten über MCP den Prompt **Resolve Data Foundation residue**. Er liest, was aussteht, und schlägt für jeden Punkt eine Antwort mit Begründung vor.

Der Assistent schreibt nichts. Sie übernehmen seine Antworten dort, wo Sie selbst geantwortet hätten: Konten und Codes unter **Codes waiting for your answer** und Dateispalten in der Zuordnung der Datei. Er schlägt nie eine Entität vor.

## Das Projekt übergeben

Die Checkliste **Einrichtung** hat nach **Hierarchien prüfen** vier abschließende Punkte:

- **Set up the nightly refresh** ist erledigt, sobald **Nächtlich aktualisieren** aktiviert ist.
- **Mit Ihrem Team teilen** ist erledigt, sobald jemand außer der Person, die das Projekt eingerichtet hat, Mitglied ist.
- **Download the evidence pack** ist erledigt, wenn Sie das Pack nach dem letzten erfolgreichen Ladevorgang herunterladen.
- **Hand the project over to its owner** ist erledigt, sobald es einen anderen Architect als die Person gibt, die es eingerichtet hat, und die Summen übereinstimmen. Solange es nicht erledigt ist, sagt die Checkliste, was zu tun ist: Machen Sie den Eigentümer des Kunden zu einem Architect dieses Projekts und entfernen Sie sich dann aus den Mitgliedern.

Die Checkliste nennt, wer das Projekt eingerichtet hat (**Set up by**).

## Mit einer Vorlage auf dem Modell aufbauen

Eine Vorlage baut ihre Berichte und Modelle auf dem Common Finance Model auf, sodass sie gleich funktionieren, welche ERP-Systeme es auch speisen. Wenn Sie ein Projekt aus einer Vorlage starten, etwa **Enterprise Profitability**, erstellt es:

- Die [Tabellen des Common Finance Model](#tabellen-des-common-finance-model), leer oder mit Beispieldaten gefüllt.
- Die Dimensionen **Entität**, **Konto**, **Abteilung**, **Kunde**, **Produkt**, **Segment 1** und **Segment 2**, aufgebaut aus diesen Tabellen. Siehe [Hierarchien](#hierarchien).
- Den Workflow **Laden** und die Workflows, die er ausführt, um Ihr ERP und Ihre Dateien zu lesen, sie in das Modell zu überführen, die Bereitschaft zu prüfen und die Modelle der Vorlage aufzubauen.
- Die eigenen Berichte und Modelle der Vorlage. **Enterprise Profitability** fügt eine Gewinn- und Verlusttabelle hinzu, mit Umsatz, COGS, Rohmarge, direktem und Gemeinkosten-Betriebsaufwand, Deckungsbeitrag und operativer Marge, sowie Margenbrücken im Jahresvergleich und gegenüber dem Budget.
- Kennzahlen und einen Analysepfad, um Fragen zu den Ergebnissen zu stellen.

Unter **Starten mit** stehen drei Vorlagen zur Verfügung, die jeweils auf demselben Modell aufbauen:

| Vorlage | Ergänzt |
|---|---|
| **Enterprise Profitability** | Die Gewinn- und Verlustrechnung und die Margenbrücken. |
| **Cost to Serve** | Die Kosten für die Bedienung jedes Kunden und die Marge danach. Siehe [Cost to Serve](/de/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | Das Gewinnniveau jeder Entität im Verhältnis zu Ihrer Richtlinienbandbreite und den True-up. Siehe [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/). |

**From a template file...** startet von einem Projekt, das Sie gespeichert haben. Siehe [Als eigene Vorlage speichern](#als-eigene-vorlage-speichern).

Um zu experimentieren, bevor Sie Ihr eigenes ERP verbinden, aktivieren Sie beim Erstellen des Projekts **Mit Beispieldaten starten**. Das Projekt führt sofort einen ersten Ladevorgang aus, sodass die Registerkarte **Foundation** ein vollständiges Beispiel zeigt, einschließlich einer Euro-Entität, die in US-Dollar umgerechnet wird. Wenn Sie Ihr eigenes ERP verbinden oder eigene Dateien hinzufügen, werden die Beispielzeilen gelöscht und Ihre Daten treten an ihre Stelle.

## Die Registerkarte Foundation

Auf der Registerkarte **Foundation** verbinden, laden und prüfen Sie Ihre Daten. Sie hat diese Bereiche, von oben nach unten:

| Bereich | Was er zeigt |
|---|---|
| **Letzter Ladevorgang** | Ob der letzte Ladevorgang erfolgreich war, fehlgeschlagen ist oder noch läuft, mit den Schaltflächen **Laden**, **Apply changes**, **Aktualisieren** und **Nächtlich aktualisieren**. |
| **What to do next** | Was Ihre Aufmerksamkeit braucht, das Wichtigste zuerst, jeweils mit einer Schaltfläche **Prüfen** oder **Choose which source counts from when**. |
| **Quellen** | Jede Quelle der Reihe nach, mit **Erweitert**, **Remove this source**, **Gruppe** und **Rename extra categories**. |
| **Einrichtung** | Die Einrichtungs-Checkliste: **Daten verbinden**, **Daten laden**, **Prüfen, ob die Summen übereinstimmen**, **Hierarchien prüfen**, **Set up the nightly refresh**, **Mit Ihrem Team teilen**, **Download the evidence pack** und **Hand the project over to its owner**. Der aktuelle Punkt ist fett. |
| **Business names** | Die Namen, die Ihr Unternehmen für Kategorien, GuV-Positionen, Kennzahlen und Spalten verwendet. Siehe [Business Names](#business-names). |
| **Dateien** | Jede Datei, die Sie hinzugefügt haben, ihr Dataset, etwa **Hauptbuch** oder **Wechselkurse**, und ob ihre Zuordnung **✓ Bestätigt** oder **○ Wartet auf Bestätigung** ist. |
| **Daten geladen** | Für jede Entität die erste und die letzte geladene Periode und wie viele Perioden bereit sind. |
| **Perioden** | Die Geschäftsperioden jeder Entität und ob jede **✓ Geschlossen** oder **○ Offen** ist. |
| **Bereitschaft** | Das Bereitschaftsraster: eine Zeile je Entität, Periode und Prüfung, mit ihrem Status und **Was zu tun ist**. |
| Verbindung | Verbinden Sie Ihr ERP, wählen Sie die Entitäten und wie viele Monate Verlauf geladen werden, oder fügen Sie eine weitere Quelle hinzu. |
| **Dateien** (hinzufügen) | Fügen Sie eine CSV-, TSV-, TXT-, Excel- oder Parquet-Datei hinzu und bestätigen Sie, wie ihre Spalten zugeordnet werden. |
| **Laden** | Starten Sie einen Ladevorgang. **Apply changes** führt einen aus, ohne aus den ERP-Systemen abzurufen. |

Während ein Ladevorgang läuft, aktualisiert sich die Registerkarte von selbst.

Die Einrichtungs-Checkliste verfolgt Ihren Fortschritt:

- **Daten verbinden** und **Daten laden** haken sich selbst ab, sobald eine Quelle angebunden und ein Ladevorgang erfolgreich ist.
- **Prüfen, ob die Summen übereinstimmen** hakt sich selbst ab, wenn die Abstimmungsprüfungen bestanden sind.
- **Hierarchien prüfen**: Klicken Sie auf **Dimensionen öffnen**, um die Hierarchien von Entität, Konto und Abteilung zu prüfen, und aktivieren Sie dann **Ich habe sie geprüft**. Diese bestätigen Sie selbst.
- **Set up the nightly refresh**, **Mit Ihrem Team teilen**, **Download the evidence pack** und **Hand the project over to its owner** schließen die Liste ab. Siehe [Das Projekt übergeben](#das-projekt-übergeben) und [Projektzugriff verwalten](/de/guides/projects/managing-projects/#projektzugriff-verwalten).

Das Menü **Aktionen** enthält **Allocations...**, **Board pack...**, **Clone...**, **Restore...** und **Save as my template...**. Siehe [Umlageregeln](#umlageregeln), [Board Pack](#board-pack), [Ein Projekt klonen](#ein-projekt-klonen), [Wiederherstellungspunkte](#wiederherstellungspunkte) und [Als eigene Vorlage speichern](#als-eigene-vorlage-speichern).

## Tabellen des Common Finance Model

Data Foundation überführt jede Quelle, ERP oder Datei, in dieselben fünfzehn Tabellen, sodass darauf aufbauende Berichte, Kennzahlen und Modelle unabhängig von der Quelle gleich funktionieren. Jede Zeile hält außerdem ihr Quellsystem fest und wann sie gelesen wurde. Die Spalte **Dataset** ist der Name, den Sie beim Hinzufügen einer Datei wählen.

| Dataset | Tabelle | Inhalt |
|---|---|---|
| Entitäten | `cfm_entity` | Rechtliche Entitäten mit übergeordneter Entität, lokaler Währung und Konzernwährung sowie Land. |
| Entitätszuordnung | `cfm_entity_map` | Entitätscodes der Quelle und die Entität, zu der jeder gehört. Siehe [Entitätszuordnung](#entitätszuordnung). |
| Wechselkurse | `cfm_fx_rate` | Monatliche Durchschnitts-, Stichtags- und historische Kurse je Währungspaar. Siehe [Wechselkurse](#wechselkurse). |
| Geschäftskalender | `cfm_fiscal_calendar` | Eine Zeile je Geschäftsperiode einer Entität, mit Start- und Enddatum und der Angabe, ob sie abgeschlossen ist. |
| Kontenplan | `cfm_account` | Konten mit übergeordnetem Konto, Typ (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), Rechenwerk, normalem Saldo und Kurstyp. |
| Abteilungen | `cfm_department` | Abteilungen und Kostenstellen mit übergeordneter Einheit und Profit-Center. |
| Produkte | `cfm_product` | Produktstamm mit übergeordnetem Produkt, Familie, Gruppe, Mengeneinheit und Standardkosten. |
| Kunden | `cfm_customer` | Kundenstamm mit übergeordnetem Kunden, Gruppe, Region und Land. Kundennamen werden nicht maskiert. |
| Segmentwerte | `cfm_segment` | Segmentwerte mit Name und übergeordnetem Wert. Siehe [Hierarchien](#hierarchien). |
| Hauptbuch | `cfm_gl_journal` | Journalzeilen in Transaktions-, lokaler und Berichtswährung. |
| Saldenliste | `cfm_trial_balance` | Soll, Haben und Saldo der Periode nach Entität, Konto und Abteilung, in lokaler Währung und Berichtswährung. |
| Verkaufspositionen | `cfm_sales_line` | Fakturierte Verkaufspositionen mit Menge, Brutto-, Rabatt-, Netto- und COGS-Beträgen. |
| Lagerbestände | `cfm_inventory_balance` | Lagerbestand am Periodenende nach Produkt und Lager. |
| Budget | `cfm_budget` | Budget und Forecast nach Szenario, Version, Konto und Abteilung. |
| Verteilungstreiber | `cfm_stat_driver` | Statistische Treiber wie Headcount, Quadratmeter oder Einheiten. |

Perioden werden als `YYYY-MM` geschrieben, und Transaktionen werden nach Buchungsperiode eingeordnet. Das Budget ist optional: Ein ERP ohne Budgets lädt trotzdem alles andere.

Eine Saldenlistendatei kann Soll- und Haben-Spalten, eine Saldospalte oder beides enthalten. Mit nur Soll und Haben ist der Saldo Soll minus Haben, und eine leere Seite zählt als null. Mit nur einem Saldo wird ein positiver Saldo zum Soll und ein negativer Saldo zum Haben, als positiver Betrag. Eine Abteilungsspalte ist optional.

## Fehlerbehebung

| Symptom | Was zu tun ist |
|---|---|
| **Verbindung testen** meldet, dass das ERP die Anmeldedaten abgelehnt hat | Prüfen Sie die Anmeldedaten der Verbindung und ob sich der Integrationsbenutzer am ERP anmelden kann. |
| **Verbindung testen** zeigt für ein Dataset **Fehlende Berechtigung** | Bitten Sie Ihren ERP-Administrator, die genannten Berechtigungen hinzuzufügen. Die [Verbindungsanleitung](/de/guides/connections/) für Ihr ERP listet auf, was die Verbindung braucht. |
| Eine ERP-Fehlermeldung ist kürzer als die des ERP selbst | PlaidCloud entfernt Anmeldedaten, Token und Schlüssel aus Fehlern von Anbietern, bevor es sie anzeigt, daher fehlen manche Details. Führen Sie **Verbindung testen** aus, um zu sehen, welches Dataset betroffen ist. |
| **Daten geladen** ist für eine Periode ein Problem | Das Lesen aus dem ERP für diese Periode ist fehlgeschlagen. Führen Sie **Laden** erneut aus; Perioden, die geladen wurden, werden übersprungen. |
| **Konten fehlen im Kontenplan** ist ein Problem | Fügen Sie die fehlenden Konten dem Kontenplan im ERP oder in Ihrer Datei hinzu und führen Sie **Laden** erneut aus. |
| **Währungsumrechnung** ist ein Problem | Die Währung einer Entität hat für diese Periode keinen Kurs in die Berichtswährung, oder es wurde keine einheitliche Berichtswährung gefunden. Fügen Sie die Kurse einer Datei **Wechselkurse** hinzu, prüfen Sie, ob die Verbindung die Wechselkurse des ERP lesen kann, oder setzen Sie die Projektvariable `reporting_currency`. Führen Sie dann **Laden** erneut aus. |
| **Währungsumrechnung** erfordert Aufmerksamkeit | Bilanz-, Lagerbestands- oder Budgetzeilen haben für die Periode keinen Stichtags-, historischen oder geplanten Kurs. Die Gewinn- und Verlustrechnung ist davon nicht betroffen. Fügen Sie die Kurse hinzu, einschließlich geplanter Kurse für Budgetmonate, und führen Sie **Laden** erneut aus. |
| **Codes waiting for your answer** erfordert Aufmerksamkeit | Klicken Sie auf **Prüfen**, beantworten Sie jeden Code und klicken Sie auf **Apply changes**. |
| **Which source covers which months** erfordert Aufmerksamkeit | Klicken Sie auf **Choose which source counts from when**, wählen Sie die Quelle und klicken Sie auf **Apply changes**. |
| **Intercompany balances** ist rot oder gelb | Prüfen Sie die Paare in **Intercompany pairs**. Buchen Sie die fehlende Seite, fügen Sie den Zeilen den Handelspartner hinzu oder ergänzen Sie den fehlenden Kurs. |
| **Group views are off** | Bitten Sie einen Architect, unter **Gruppe** **Everyone on the project may see the group results** zu aktivieren. |
| **Nicht zugeordnete Entitäten** ist ein Problem | Fügen Sie die Entität dem Entitätsstamm hinzu oder ordnen Sie ihren Code in der Datei **Entitätszuordnung** einer vorhandenen Entität zu und führen Sie **Laden** erneut aus. |
