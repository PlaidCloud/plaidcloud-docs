**Data Foundation** ist das Finanzdatenfundament für Ihre PlaidCloud-Projekte. Sein **Common Finance Model** führt ERP-Daten aus mehreren ERP-Systemen und mehreren Instanzen jedes Systems in einem einzigen Modell zusammen: ein Kontenplan, ein Satz Entitäten und eine Berichtswährung. Berichte, Kennzahlen und KI-Assistenten, die auf dem Modell aufbauen, lesen dieselben Zahlen, unabhängig davon, aus welchem ERP sie stammen.

Ihr ERP wird über seine PlaidCloud-Verbindung angebunden, sodass Hauptbuch, Saldenliste, Stammdaten und Budgets direkt aus der Quelle eintreffen, ohne dass Sie etwas exportieren müssen. Dateien ergänzen Daten, die ein System nicht enthält, etwa Wechselkurse, Verteilungstreiber oder ein Budget, das außerhalb des ERP geführt wird, und können die ERP-Zeilen ersetzen, die sie abdecken. **Laden** überführt jede Quelle in das Modell, rechnet sie in die Berichtswährung um und prüft, ob die Summen übereinstimmen, alles auf der Registerkarte **Foundation** des Projekts. Wo Quellen denselben Code für Unterschiedliches verwenden, legen Sie fest, ob sie dasselbe bedeuten, und eine Management-Konsolidierung erstellt die Konzern-Gewinn- und Verlustrechnung mit eliminierten Intercompany-Positionen. Vorlagen wie **Enterprise Profitability** bauen ihre Berichte und Modelle darauf auf.

## ERP verbinden

Ihr ERP wird über seine PlaidCloud-Verbindung mit Data Foundation verbunden. Data Foundation liest Hauptbuch, Saldenliste, Stammdaten, Wechselkurse und Budgets direkt daraus und liest ausschließlich. Sie können auf der Registerkarte eine vorhandene Verbindung auswählen oder eine neue erstellen. Für jedes System gibt es eine Seite für den Administrator, der den Zugriff gewährt. Sie sind unter [Welche Systeme das Modell speisen können](/de/guides/projects/data-foundation-getting-started/#welche-systeme-das-modell-speisen-können) aufgeführt, und die [Data-Foundation-Abdeckungsmatrix](/de/reference/data-foundation-coverage-matrix/) zeigt, welche Datasets jedes System direkt liefert.

<Steps>

1. Öffnen Sie in Analyze **Projekte** und klicken Sie auf **Neues Projekt**. Geben Sie einen Namen ein und wählen Sie unter **Starten mit** eine Vorlage, etwa **Enterprise Profitability (Vorlage)**, statt **Leeres Projekt**. Klicken Sie auf **Erstellen**.

   Das Projekt öffnet sich auf seiner Registerkarte **Foundation**. Es ist privat und gehört nur Ihnen, und Sie sind sein einziger Architect, bis Sie es teilen.

2. Wählen Sie auf der Registerkarte **Foundation** eine vorhandene Verbindung für Ihr ERP aus oder wählen Sie **Neue Verbindung erstellen**. Bei jeder vorhandenen Verbindung sind die Workflows aufgeführt, die sie bereits verwenden, oder es steht dort **Noch von keinem Workflow verwendet**.

3. Geben Sie für eine neue Verbindung einen **Verbindungsname** ein, wählen Sie die **Umgebung** und tragen Sie die Zugangsdaten ein, die Ihre ERP-Verbindung verlangt.

   Sie haben die Zugangsdaten noch nicht? Das Formular zeigt eine vorbereitete Zugriffsanfrage für Ihren ERP-Administrator. Klicken Sie auf **Anfrage kopieren** oder **Anfrage per E-Mail senden**, senden Sie sie ab und tragen Sie die Werte ein, die Sie zurückerhalten.

4. Klicken Sie auf **Verbindung testen**. PlaidCloud meldet sich an und versucht, jedes Dataset zu lesen. Anschließend wird jedes als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** aufgeführt. Fehlt etwas, nennt PlaidCloud die Berechtigungen, die Ihr ERP-Administrator hinzufügen soll.

5. Legen Sie **Monate Verlauf** fest: wie viele Monate rückwirkend geladen werden, von 1 bis 120. Der Standard ist 24.

6. Aktivieren Sie bei einer vorhandenen Verbindung die zu ladenden Entitäten oder lassen Sie alle deaktiviert, um jede Entität zu laden. Inaktive Entitäten und Eliminierungsentitäten bleiben ausgeblendet, bis Sie sich entscheiden, sie anzuzeigen. Klicken Sie dann auf **Verbinden**.

7. Klicken Sie bei einer neuen Verbindung auf **Verbinden**, um sie zu erstellen. Aktivieren Sie anschließend die zu ladenden Entitäten und klicken Sie erneut auf **Verbinden**, um sie zu speichern. Bis dahin wird jede Entität geladen.

8. Um ein weiteres ERP-System oder eine weitere Instanz einzubinden, wiederholen Sie diese Schritte und aktivieren Sie vor dem Klick auf **Verbinden** die Option **Add this as another source instead of replacing the current one**. Ohne sie ersetzt die neue Verbindung die aktuelle Quelle.

</Steps>

Nach dem Verbinden zeigt die Karte an, welche Verbindung, Umgebung, Entitäten und wie viele Monate Verlauf das Projekt lädt.

Jeder Ladevorgang liest nur, was sich geändert hat: Offene Perioden und die zuletzt abgeschlossene Periode werden erneut gelesen, bereits geladene abgeschlossene Perioden bleiben erhalten. Wenn Sie **Monate Verlauf** erhöhen, werden nur die hinzugekommenen Monate gelesen. Ein geänderter Wechselkurs, eine geänderte Entitätszuordnung oder eine geänderte Berichtswährung führt dazu, dass die betroffenen Monate erneut gelesen werden.

## Quellen

Jedes ERP-System und jede Instanz, aus denen das Projekt lädt, ist eine Quelle. Die Liste **Quellen** auf der Registerkarte **Foundation** zeigt für jede eine Zeile in Reihenfolge, mit ihrem Namen, dem Zeitpunkt des letzten Ladevorgangs, der Anzahl gelieferter Zeilen und den Berichtsbüchern, die sie liest, zum Beispiel `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Eine Quelle, die noch nicht geladen wurde, zeigt **not loaded yet**. Dateien, die Sie bestätigen, sind ebenfalls Quellen.

Öffnen Sie **Erweitert** bei einer Quelle, um zu ändern, wie sie verwendet wird:

| Einstellung | Funktion |
|---|---|
| **Name** | Die Bezeichnung, die Berichte, Zuordnungsfragen und Meldungen für die Quelle verwenden. |
| **Place in the order** | Der Rang der Quelle. Wenn zwei Quellen denselben Monat desselben Unternehmens abdecken, gewinnt die in der Reihenfolge höher stehende. |
| **Reporting books, separated by commas** | Die zu lesenden Buchführungsbücher bei einem System, das mehr als eines führt. **All reporting books** liest jedes Buch. |
| **Unternehmen**, **Von (2026-01)** und **Bis (2026-12)** | Die Monate, die diese Quelle für jedes Unternehmen liefert. Lassen Sie einen Monat leer, wenn es keine Grenze geben soll. Schreiben Sie Monate als Jahr und Monat, zum Beispiel `2026-03`. |

Klicken Sie auf **Speichern**, um Ihre Änderungen zu behalten. Um eine Quelle zu entfernen, klicken Sie auf **Remove this source** und bestätigen Sie mit **Entfernen**. Alles, was daraus geladen wurde, wird gelöscht, und Sie können die Quelle später erneut verbinden.

Das Ändern von Quellen liest Ihr ERP nicht erneut. Die Karte **Letzter Ladevorgang** zeigt **Changes not applied yet**, bis Sie auf **Apply changes** klicken. Das führt einen Ladevorgang aus den bereits abgerufenen Daten aus: Er überführt die Quellen mit Ihrer neuen Reihenfolge, Ihren Zuordnungen, Namen und Dateien erneut und baut das Modell neu auf. Klicken Sie auf **Laden**, wenn Sie zusätzlich frische Daten aus den ERPs wünschen.

## Dateien für Daten außerhalb Ihres ERP hinzufügen

Dateien ergänzen Ihre ERP-Verbindung um Daten, die ein System nicht enthält, etwa Wechselkurse, Verteilungstreiber, eine [Entitätszuordnung](#entitätszuordnung) oder ein Budget, das außerhalb des ERP geführt wird. Jede Datei gehört zu einem der Datasets, die unter [Tabellen des Common Finance Model](#tabellen-des-common-finance-model) aufgeführt sind.

<Steps>

1. Wählen Sie unter **Dateien** das **Dokumentenkonto** aus, in dem die Datei gespeichert werden soll.

2. Legen Sie eine CSV- oder Excel-Datei auf **CSV- oder Excel-Datei hier ablegen** ab oder klicken Sie auf **Datei auswählen**. Die Datei wird in den Ordner `/foundation/` des Dokumentenkontos hochgeladen.

   Geben Sie für eine Datei, die sich bereits im Dokumentenkonto befindet, ihren **Dateipfad** ein, zum Beispiel `/foundation/budget.csv`, und klicken Sie auf **Datei hinzufügen**.

   Um jeden Monat eine neue Datei zu lesen, fügen Sie jede Datei eines Ordners hinzu, deren Name passt: Geben Sie den Ordner an und legen Sie unter **File names that** fest, ob die Namen etwas enthalten, damit beginnen, damit enden, genau übereinstimmen oder einem Muster entsprechen, und klicken Sie auf **Add files**. Dateien in Ordnern darin werden nicht gelesen.

3. PlaidCloud liest die Datei und schlägt eine Zuordnung vor:

   - **Detected delimiter, decimal separator and dates.** Das Trennzeichen (Komma, Semikolon, Tabulator oder senkrechter Strich), das Dezimaltrennzeichen und das Datumsformat werden für Sie erkannt.
   - **Dataset**: die Tabelle des Common Finance Model, zu der die Datei gehört, abgeleitet aus Dateiname und Spaltenüberschriften. Wenn die Zuordnung nicht eindeutig ist, wählen Sie sie aus der Liste aus.
   - **Dezimaltrennzeichen**: **Punkt (1,234.56)** oder **Komma (1.234,56)**.
   - **Datumsformat**: wird angezeigt, wenn die Datei Datumswerte enthält. Ändern Sie es, wenn das erkannte Format falsch ist: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` oder `MM/DD/YYYY`.
   - Ein Raster aus **Spalte in Datei**, **Typ**, **Beispiele** und **Geht nach**. Ändern Sie **Geht nach**, um eine Spalte einem anderen Feld zuzuweisen oder auf **Nicht laden** zu setzen.

4. Beantworten Sie die Fragen, die die Datei aufwirft, etwa **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** oder **Are revenues shown as negative numbers?** Jede wird nur gestellt, wenn die Datei die Antwort nicht bereits enthält.

5. Prüfen Sie, wohin jede Spalte geht, und klicken Sie dann auf **Zuordnung bestätigen**. Während die Verarbeitung läuft, nennt der Hinweis unter der Schaltfläche den Grund für das Warten. In einem Projekt, das noch die Beispieldaten enthält, entfernt die erste Datei, die Sie bestätigen, auch das Beispiel, was einige Minuten dauern kann.

</Steps>

Diese Optionen erscheinen bei einer Datei, wenn sie zutreffen:

| Option | Verwendung |
|---|---|
| **Which source do these rows apply to?** | Eine Code-Zuordnungsdatei auf eine Quelle beschränken. **Every source** wendet sie auf alle an. |
| **Where does this file come from?** | Angeben, ob die Datei **This project's own codes** enthält oder aus **Another system** stammt, das Sie benennen, zum Beispiel `SAP Germany export`. Eine Datei aus einem anderen System wird wie eine ERP-Quelle auf gemeinsame Codes geprüft. |
| **Split … into … parts at each …** (unter **Erweitert**) | Eine Spalte aufteilen, die mehrere Werte enthält, etwa `100-200-300`, und jeden Teil einem eigenen Feld zuweisen. |
| **Which currency do you report in?** | Die Berichtswährung festlegen, wenn das Projekt noch keine hat. Schreiben Sie sie dreibuchstabig, zum Beispiel `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Die Ergebnisse Ihres Konsolidierungssystems laden, damit die Konzern-Gewinn- und Verlustrechnung [abgestimmt](#mit-ihrem-konsolidierungssystem-abstimmen) werden kann. |

Um eine Datei aus dem Projekt zu entfernen, klicken Sie unter **Dateien** neben ihr auf **Entfernen** oder in ihrer Zuordnung auf **Remove this file** und bestätigen Sie. Ihre Zahlen verschwinden aus Ihren Berichten, sobald Sie das nächste Mal auf **Apply changes** klicken.

Wenn PlaidCloud das Dataset, das Dezimaltrennzeichen oder die Datumsreihenfolge nicht selbst bestimmen kann, zum Beispiel bei einer Datei, deren Datumswerte als Tag/Monat oder Monat/Tag gelesen werden könnten, bittet es Sie, vor dem Bestätigen eine Auswahl zu treffen. Wenn Sie eine zweite Datei für dasselbe Dataset hinzufügen, ersetzt sie die erste. Wenn die Spalten einer späteren Datei nicht zum Dataset passen, nennt der Ladevorgang die Datei und die Spalten und fordert Sie auf, die Datei oder ihre Spaltennamen zu korrigieren oder **Schema Mismatch** des Schritts auf `union` zu setzen.

Akzeptiert werden Textdateien im Format CSV, TSV und TXT, Excel-Dateien im Format `.xlsx` (gelesen wird das erste Blatt) und Parquet-Dateien.

<Aside type="note">
Eine fehlende oder leere Datei stoppt einen Ladevorgang nie. Beim Hinzufügen erscheint der Hinweis, dass noch nichts zuzuordnen ist, und ein Ladevorgang endet mit einer Warnung, die den Pfad nennt, wobei das betreffende Dataset leer bleibt. Fügen Sie die Datei erneut hinzu, sobald sie vorhanden ist.
</Aside>

## Daten laden

Klicken Sie auf der Karte **Laden** oder der Karte **Letzter Ladevorgang** auf **Laden**. Der Ladevorgang liest Ihr verbundenes ERP und Ihre bestätigten Dateien, überführt sie in das Common Finance Model, rechnet sie in die Berichtswährung um, führt die Bereitschaftsprüfungen aus und baut die Modelle der Vorlage neu auf.

- Pro Projekt läuft immer nur ein Ladevorgang. Ein zweites **Laden** oder **Apply changes** meldet, dass bereits ein Ladevorgang läuft, und solange einer läuft, können Sie keine Quellen ändern.
- Wenn andere Workflows dieselbe ERP-Verbindung verwenden, listet der erste Ladevorgang sie auf und bittet Sie um Bestätigung, weil ein Ladevorgang aus dem ERP liest und diese Workflows verlangsamen kann. Klicken Sie auf **Trotzdem laden**, um fortzufahren.
- Nach einem Upgrade von PlaidCloud aktualisiert das **Laden** eines Architects auch die generierten Workflows des Projekts und erstellt alle Arbeitstabellen, die sie benötigen. Bis dahin führt die Statusseite einen gelben Eintrag auf: „The workflows were generated by an earlier release. An Architect's Load updates them.“, und das **Laden** eines Managers warnt, dass nur ein Architect sie aktualisieren kann.
- Beim Anwenden eines Updates bleiben Ihre eigenen Änderungen an den generierten Schritten erhalten. Wenn Sie einen Schritt geändert haben und das Update ihn ebenfalls geändert hat, bleibt Ihre Änderung erhalten, und die Statusseite vermerkt den Konflikt unter dem Schrittnamen. Ein Schritt, den Sie bearbeitet haben und den das Update nicht mehr generiert, bleibt erhalten, wird aber deaktiviert; löschen Sie ihn oder aktivieren Sie ihn wieder, wenn Sie ihn noch brauchen. Ein Schritt, den das Update ersetzt, wird genannt, und der frühere bleibt in seinen Schrittversionen erhalten.
- Wenn ein Update auf halbem Weg abgebrochen wurde oder noch läuft, weist die Statusseite darauf hin, und seine Schritte laufen möglicherweise in falscher Reihenfolge, bis es abgeschlossen ist. Drücken Sie als Architect erneut auf **Laden**, um es abzuschließen. Bricht es erneut ab, wenden Sie sich an den Support.
- Ein fehlgeschlagener Ladevorgang wird rot angezeigt und verbirgt sich nie hinter früheren Ergebnissen. Schlägt die Konsolidierung fehl, nennt der Status den Schritt, bei dem sie abgebrochen wurde, statt alte Konzernergebnisse anzuzeigen. Zeilen aus einem früheren Ladevorgang zeigen **Aus einem früheren Ladevorgang. Erneut laden.**, bis ein Ladevorgang erfolgreich ist.
- Wenn eine Entität und Periode nicht gelesen werden kann, wird der Rest dennoch geladen. Führen Sie **Laden** erneut aus, um nur das Fehlgeschlagene abzurufen.

### Zurückgehaltene Zeilen

Wenn sich Quellen überschneiden, behält ein Ladevorgang jeweils eine Kopie jeder Zahl und hält die anderen zurück, statt sie doppelt zu zählen. Zurückgehaltene Zeilen werden mit ihrer Quelle, Entität und dem Grund festgehalten, und der Ladevorgang endet mit einer Warnung, die die Anzahlen nennt, zum Beispiel `120 rows of NetSuite EU also provided by a source ranked ahead`. Die Gründe sind:

| Grund | Bedeutung |
|---|---|
| In another accounting book | Die Zeile gehört zu einem Berichtsbuch, das die Quelle nicht lesen soll. |
| Outside the periods the source provides | Die Zeile liegt außerhalb der Monate **Von** und **Bis**, die für das Unternehmen festgelegt sind. |
| Also provided by a source ranked ahead | Eine in der Reihenfolge höher stehende Quelle deckt dasselbe Unternehmen und denselben Monat ab. |
| Also in an earlier file of the source | Eine frühere Datei derselben Quelle deckt den Monat bereits ab. |
| Replaced by a file | Eine Datei ersetzt die ERP-Zeilen für diese Entität und diesen Monat. |
| Carrying a code another source also uses | Der Code benötigt Ihre Antwort. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| Carrying a code mapped to two codes | Die Code-Zuordnung gibt dem Code zwei Antworten. |

Statistische Konten wandern statt ins Hauptbuch zu den Verteilungstreibern und werden als verschoben angezeigt, nicht als Problem.

### ERP-Daten und Dateien zusammen

Eine Datei ersetzt nur das, was sie abdeckt, und die übrigen Zeilen aus Ihrem ERP bleiben bestehen.

- **Stammdatendateien** (Konten, Abteilungen, Kunden, Produkte und Segmentwerte) ersetzen die ERP-Zeilen mit demselben Code.
- **Bewegungsdatendateien** ersetzen die ERP-Zeilen für dieselbe Entität und denselben Monat. Hauptbuch- und Saldenlistendateien werden zusätzlich nach Ledger zugeordnet, Budgetdateien nach Szenario und Dateien mit statistischen Treibern nach Szenario und Treiber.

Wenn eine Datei später einen Monat nicht mehr abdeckt, kehren die Daten des ERP für diesen Monat beim nächsten Ladevorgang zurück.

## Entitätszuordnung

Jede Quelle benennt ihre Entitäten mit eigenen Codes. Die **Entitätszuordnung** ordnet diese Codes den Entitäten in Ihrem Entitätsstamm zu, sodass Zeilen aus jeder Quelle bei derselben Entität landen.

Um sie zu verwenden, fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Entitätszuordnung**:

| Spalte | Enthält |
|---|---|
| `source_entity` | Den Code, wie ihn die Quelle führt, etwa einen Buchungskreis. |
| `entity` | Die Entität, zu der er gehört, wie sie der Entitätsstamm benennt. |

- Ein Code, der nicht in der Zuordnung steht, wird unverändert verwendet.
- Mehrere Codes können einer Entität zugeordnet sein. Ihre Zeilen werden zusammengefasst, und ein Monat gilt als abgeschlossen, sobald er für alle abgeschlossen ist.
- Codes in der Zuordnung gelten für jede Quelle, daher müssen die Entitätscodes jeder Quelle quellenübergreifend eindeutig sein.
- Eine Zeile einer **Entitäten**-Datei ersetzt die Entität des ERP mit demselben Entitätscode.

Die Prüfung **Nicht zugeordnete Entitäten** meldet jede Zeile, deren Entität weder im Entitätsstamm steht noch durch die Zuordnung einer solchen zugewiesen ist. Solange kein Entitätsstamm geladen ist, zeigt sie **– Nicht zutreffend**.

## Codes quellenübergreifend zuordnen

Zwei Quellen können denselben Code für Unterschiedliches oder unterschiedliche Codes für dasselbe verwenden. Wenn ein Code in mehr als einer Quelle vorkommt, hält Data Foundation seine Zeilen zurück, bis Sie angeben, ob er überall dasselbe bedeutet, damit jeder Betrag nur einmal gezählt wird. Die Prüfung **Codes waiting for your answer** listet sie auf, die ersten 10 und dann „and K more“, und die Karte **What to do next** auf der Registerkarte **Foundation** hat eine Schaltfläche **Prüfen**.

**Prüfen** öffnet **Codes waiting for your answer**. Die Codes sind danach gruppiert, was sie sind: **Kontotypen**, **Unternehmen**, **Konten**, **Abteilungen**, **Profit-Center**, **Kunden**, **Produkte** und jede zusätzliche Kategorie. Für jeden Code wird angezeigt, wie ihn jede Quelle nennt, sowie ein Vorschlag:

- **Looks like the same thing**, wenn die Quellen dem Code denselben Namen geben.
- **Looks like different things**, wenn die Namen abweichen.
- **We can't tell. Please answer.**, wenn es keine Anhaltspunkte gibt.

Beantworten Sie jeweils einen Code mit **Yes, the same** oder **No, different**, oder beantworten Sie eine ganze Gruppe auf einmal mit **Accept all** (jeden Vorschlag übernehmen), **All the same** oder **All different**. Bei Konten können Sie auch eine ganze übergeordnete Gruppe des Kontenplans auf einmal beantworten. Wenn eine Quelle keine Kontotypen führt, wählen Sie für eine Kontengruppe **Use this type**: **Umsatz**, **Wareneinsatz**, **Betriebsaufwand**, **Neutrales Ergebnis**, **Aktiva**, **Verbindlichkeiten** oder **Eigenkapital**.

Zuordnungen werden pro Quelle und Dimension geführt, daher ändert eine Antwort für die Abteilungen einer Quelle nie die Konten einer anderen Quelle. Antworten werden laufend gespeichert, mit **Saved. Press Apply changes to use your answers.** Klicken Sie auf **Apply changes**, um sie zu verwenden.

Sie können die Zuordnungen auch in einer Datei liefern. Fügen Sie eine Datei mit dem Dataset **Code map** hinzu und wählen Sie **Which source do these rows apply to?**, um sie auf eine Quelle zu beschränken.

## Festlegen, welche Quelle ab wann zählt

Wenn zwei Quellen dieselben Monate liefern, bittet die Prüfung **Which source covers which months** Sie um eine Auswahl. Klicken Sie auf der Karte **What to do next** auf **Choose which source counts from when**, um **Which source counts from when** zu öffnen, das jede Überschneidung nach Unternehmen auflistet. Wählen Sie die Quelle, die zählt, geben Sie unter **That month is** den Monat ein, ab dem sie zählt, zum Beispiel `2026-04`, und klicken Sie auf **Apply changes**. Die andere Quelle behält die früheren Monate.

Derselbe Dialog warnt, wenn zwei Quellen für eine Währung unterschiedliche Wechselkurse liefern; verwendet werden die Kurse der in der Reihenfolge höher stehenden Quelle.

## Währungsumrechnung

Jeder Ladevorgang rechnet die Beträge aus Hauptbuch, Saldenliste, Verkauf, Lager und Budget aus ihrer Lokalwährung in eine Berichtswährung um. Berichte und Modelle lesen die umgerechneten Beträge, sodass Entitäten in unterschiedlichen Währungen, aus jedem System, korrekt summiert werden.

### Die Berichtswährung

Um die Berichtswährung festzulegen, setzen Sie die Projektvariable `reporting_currency` auf einen Währungscode wie `USD`. Siehe [Projektvariablen verwalten](/de/guides/projects/managing-projects/#projektvariablen-verwalten). Die Vorlage legt sie leer an. Solange sie leer ist, verwendet jeder Ladevorgang die erste der folgenden Angaben, die genau eine Währung benennt:

1. Die Konzernwährung der Entitäten.
2. Die Lokalwährung der Entitäten oberster Ebene, also derjenigen ohne übergeordnete Entität.
3. Die Lokalwährung der Dateien.

Benennt keine davon genau eine Währung, zeigt **Währungsumrechnung** ein Problem an, bis Sie `reporting_currency` festlegen.

Beträge, die bereits in der Berichtswährung vorliegen, bleiben unverändert, daher braucht ein Projekt, dessen Daten alle in einer Währung vorliegen, keine Kurse.

Auch Verkaufs-, Lager- und Budgetdateien können eine Währung enthalten. Ordnen Sie eine Spalte namens `Currency` oder `Local Currency` zu, und sie wird automatisch erkannt; die Lokalbeträge der Datei werden dann in die Berichtswährung umgerechnet. Ein Konzern- oder Berichtsbetrag, der bereits in der Datei steht, bleibt unverändert. Der Standardkostensatz von Produkten wird nicht umgerechnet.

### Wechselkurse

Ein Kurs rechnet eine Einheit einer Währung für einen Monat in die Berichtswährung um: Der umgerechnete Betrag ist der Lokalbetrag mal dem Kurs.

- **Aus Ihrem ERP** liest jeder Ladevorgang die Wechselkurse, die das ERP führt.
- **Aus einer Datei**: Fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Wechselkurse**. Ein Kurs in der Datei ersetzt den Kurs des ERP für dieselben Währungen und denselben Monat. Verwenden Sie eine Datei, um in einer Währung zu berichten, für die Ihre ERPs keine Kurse veröffentlichen, oder um Planungskurse für Budgetmonate zu ergänzen.

| Spalte | Enthält |
|---|---|
| `from_currency` | Die Währung, aus der umgerechnet wird, zum Beispiel `EUR`. |
| `to_currency` | Die Berichtswährung, zum Beispiel `USD`. |
| `period` | Den Monat im Format `YYYY-MM`. |
| `average_rate` | Den Durchschnittskurs für den Monat. |
| `closing_rate` | Den Kurs am Monatsende. |
| `historical_rate` | Den historischen Kurs, für Eigenkapital und für Konten, die auf den historischen Kurs eingestellt sind. |

Hat eine Währung keinen Kurs in die Berichtswährung, wird ihr Kurs in der Gegenrichtung, von der Berichtswährung in diese Währung, invertiert, wobei 12 Dezimalstellen erhalten bleiben. Fehlt auch dieser, wird ihr Kurs in eine andere Währung mit dem Kurs dieser anderen Währung in die Berichtswährung multipliziert.

### Welcher Kurs gilt

Jede Zeile wird aus ihrer eigenen Währung umgerechnet, sodass eine Zeile in einer anderen Währung als ihre Entität aus der Währung umgerechnet wird, in der sie vorliegt. Es gilt die erste Regel, die auf die Zeile zutrifft:

| Zeile | Kurs |
|---|---|
| Statistische und nicht buchende Konten | Nicht umgerechnet. |
| Bereits in der Berichtswährung | Nicht umgerechnet. |
| Konto mit Kurstyp | Dieser Kurs: Durchschnitt, Stichtag oder historisch. Historisch fällt auf den Stichtagskurs zurück, wenn kein historischer Kurs vorliegt. Aus einem ERP ist der Kurstyp der eigene Kurstyp des Kontos. Ordnen Sie in einer Kontenplandatei eine Kurstypspalte `fx_rate_type` mit `average`, `closing` oder `historical` zu. |
| Verkaufsposition | Der Durchschnittskurs der Periode. |
| Lagerbestand | Der Stichtagskurs der Periode. |
| Budgetzeile | Nach Konto, wie im Hauptbuch: der Durchschnittskurs für Konten der Gewinn- und Verlustrechnung und der Stichtagskurs für Bilanzkonten. |
| Konto der Gewinn- und Verlustrechnung | Der Durchschnittskurs der Periode. |
| Eigenkapitalkonto | Der historische Kurs oder der Stichtagskurs, wenn kein historischer Kurs vorliegt. |
| Jedes andere Bilanzkonto | Der Stichtagskurs der Periode. |

Umgerechnete Beträge werden nicht gerundet, sodass die Summen nicht abdriften.

<Aside type="note">
Die Saldenliste enthält die Bewegungen jeder Periode, daher sind Bilanzbeträge die Bewegungen jedes Monats, umgerechnet zum Stichtagskurs dieses Monats. Es ist keine zum Periodenendkurs neu umgerechnete Bilanz, und es gibt keine kumulierte Umrechnungsanpassung und keine Intercompany-Eliminierung. Verwenden Sie die umgerechneten Beträge für die Gewinn- und Verlustrechnung.
</Aside>

## Hierarchien

Jeder Ladevorgang baut die Dimensionen aus den Stammdaten jeder Quelle neu auf. Zu Beginn gibt es sieben Dimensionen und bis zu zehn zusätzliche Kategorien:

| Dimension | Aufgebaut aus |
|---|---|
| **Entität** | Entitäten und ihren übergeordneten Entitäten |
| **Konto** | Kontenplan und übergeordneten Konten |
| **Abteilung** | Abteilungen und ihren übergeordneten Abteilungen |
| **Kunde** | Kunden und ihren übergeordneten Kunden |
| **Produkt** | Produkten und ihren übergeordneten Produkten |
| **Segment 1** | Segmentwerten für `segment_1` |
| **Segment 2** | Segmentwerten für `segment_2` |
| **Segment 3** bis **Segment 10** | Segmentwerten für `segment_3` bis `segment_10`, sofern Ihre Quellen sie führen |

- Ein Datensatz ohne übergeordnetes Element oder einer, der sich selbst als übergeordnetes Element benennt, wird als Mitglied der obersten Ebene geladen.
- Da jeder Ladevorgang die Hierarchien neu aufbaut, ändern Sie ein übergeordnetes Element im ERP oder in Ihrer Datei, nicht in der Dimension.
- Ein Problem in einer Hierarchie betrifft nur diese Dimension. Der Ladevorgang und die Modelle der Vorlage werden dennoch abgeschlossen.
- Sie können jede zusätzliche Kategorie nach ihrem Inhalt umbenennen, zum Beispiel **Klasse** oder **Region**. Geben Sie unter **Rename extra categories** die Namen ein, die Ihre Berichte verwenden, und klicken Sie auf **Save names**. Namen bestehen aus Buchstaben, Zahlen, Leerzeichen, Punkten, Bindestrichen und Unterstrichen und sind bis zu 60 Zeichen lang.
- Jede Quelle legt fest, unter welchem Ihrer Kategorienamen jede ihrer eigenen zusätzlichen Kategorien eingeordnet wird. Öffnen Sie **Erweitert** bei der Quelle, wählen Sie für jede den Namen oder wählen Sie **Leave out**, und klicken Sie auf **Speichern**. Quellen, die eine Kategorie unterschiedlich nennen, etwa `Class` und `Business area`, teilen sich dann einen Platz.

Um Segmenthierarchien aus einer Datei zu liefern, wählen Sie das Dataset **Segmentwerte**:

| Spalte | Enthält |
|---|---|
| `segment` | Zu welchem Segment der Wert gehört: `segment_1` bis `segment_10`. |
| `segment_value` | Den Wert, wie ihn Hauptbuch-, Verkaufs- und Budgetzeilen führen. |
| `segment_value_name` | Seinen Namen. |
| `parent_segment_value` | Sein übergeordnetes Element innerhalb desselben Segments. |

## Bereitschaftsprüfungen

Nach jedem Ladevorgang listet das Raster **Bereitschaft** jede Prüfung für jede Entität und Periode mit einem dieser Status auf:

| Status | Bedeutung |
|---|---|
| **● Bereit** | Die Prüfung wurde bestanden. |
| **▲ Aufmerksamkeit erforderlich** | Einen Blick wert, aber die Zahlen sind verwendbar. |
| **■ Problem** | Beheben Sie dies, bevor Sie sich auf die Ergebnisse verlassen. |
| **– Nicht zutreffend** | Für diese Prüfung liegen noch keine Daten vor. |

Die Prüfungen sind:

| Prüfung | Was sie bestätigt |
|---|---|
| **Daten geladen** | Jede Geschäftsperiode hat Hauptbuchzeilen, und jeder ERP-Lesevorgang war erfolgreich. Eine abgeschlossene Periode ohne Zeilen ist ein Problem; eine offene Periode ohne Zeilen erfordert Aufmerksamkeit. |
| **Saldenliste stimmt mit Hauptbuch überein** | Die Saldenliste entspricht dem Hauptbuch für jede Entität, Periode und jedes Konto. Wenn sowohl die Saldenliste als auch das Hauptbuch bei einem Konto Abteilungen führen, wird auch jede Abteilung abgestimmt. |
| **Umsatz stimmt mit Hauptbuch überein** | Verkaufspositionen entsprechen den Umsatz- und Wareneinsatzkonten des Hauptbuchs für jede Periode. |
| **Unbekannte Produkte/Kunden** | Jede Verkaufsposition nennt ein Produkt und einen Kunden, die in den Produkt- und Kundenstammdaten vorhanden sind. |
| **Konten fehlen im Kontenplan** | Jede Hauptbuchzeile nennt ein Konto im Kontenplan. Zeilen mit einem unbekannten Konto bleiben in der Gewinn- und Verlustrechnung unberücksichtigt. Ein Konto mit Buchungen, aber ohne Kontotyp, ist ebenfalls ein Problem, und eine Quelle, deren Kontenplan Umsatzkonten, aber kein Wareneinsatzkonto typisiert, erfordert Aufmerksamkeit. |
| **Währungsumrechnung** | Jede Zeile aus Hauptbuch, Saldenliste, Verkauf, Lager und Budget hat einen Betrag in der Berichtswährung. Eine Zeile der Gewinn- und Verlustrechnung oder des Verkaufs ohne Kurs ist ein Problem, weil die Gewinn- und Verlustrechnung umgerechnete Beträge liest. Eine Bilanz-, Lager- oder Budgetzeile ohne Kurs erfordert Aufmerksamkeit. Ein Budgetmonat ohne Kurs wird gelb angezeigt, laden Sie daher Planungskurse für Budgetmonate. Siehe [Währungsumrechnung](#währungsumrechnung). |
| **Nicht zugeordnete Entitäten** | Jede Zeile aus Hauptbuch, Saldenliste und Verkauf nennt eine Entität im Entitätsstamm, direkt oder über die Entitätszuordnung. Nicht zutreffend, bis ein Entitätsstamm geladen ist. Siehe [Entitätszuordnung](#entitätszuordnung). |

Ladevorgänge mit mehr als einer Quelle ergänzen diese Prüfungen:

| Prüfung | Was sie bestätigt |
|---|---|
| **Reporting book** | Bei einer Quelle, die mehrere Buchführungsbücher für eine Entität führt, wurde das Berichtsbuch ausgewählt. Bis zur Auswahl zählt nur das erste Buch. |
| **Codes waiting for your answer** | Jeder Code, den mehr als eine Quelle verwendet, wurde beantwortet. Siehe [Codes quellenübergreifend zuordnen](#codes-quellenübergreifend-zuordnen). |
| **Extra categories from your sources** | Jede zusätzliche Kategorie einer Quelle hat einen Namen oder wurde ausgelassen. |
| **Which source covers which months** | Keine zwei Quellen liefern dieselben Monate eines Unternehmens, es sei denn, Sie haben festgelegt, welche zählt. |
| **Account types and hierarchy** | Jedes übergeordnete Element, das eine Dimension nennt, existiert, und kein Mitglied ist sein eigenes übergeordnetes Element oder sein eigener Vorfahre. Ein fehlendes übergeordnetes Element setzt seine untergeordneten Elemente an die Spitze der Hierarchie, und eine Schleife verhindert das Laden dieser Hierarchie. Die Summen bleiben unberührt. |
| **Geschäftskalender** | Die Geschäftsperioden jeder Entität sind Kalendermonate, und jeder Monat an Zeilen lässt sich in genau eine Geschäftsperiode einordnen. Sie erfordert Aufmerksamkeit, wenn die Perioden einer Entität keine Kalendermonate sind (4-4-5, 13 Perioden) oder wenn die Zeilen eines Monats in mehr als eine Geschäftsperiode fallen könnten oder dem Geschäftskalender der Monat fehlt. |

Jede Zeile, die nicht bereit ist, nennt in der Spalte **Was zu tun ist**, was zu tun ist, etwa den Kontenplan zu laden, Wechselkurse zu laden oder **Laden** für eine Periode erneut auszuführen.

Das Raster zeigt außerdem zwei Einrichtungsprüfungen, die nur erscheinen, wenn sie Aufmerksamkeit erfordern:

| Prüfung | Wann sie erscheint |
|---|---|
| **Gemeinkostenumlage** | Nur eine der Projektvariablen `overhead_department` und `overhead_driver` ist gesetzt, oder kein Verteilungstreiber passt zu `overhead_driver`, sodass die Umlage nichts bewirken würde. Setzen Sie beide oder löschen Sie beide, um die Gemeinkostenumlage auszuschalten. |
| **Budgetvergleich** | Budgetzeilen sind geladen, aber keine davon liegt in der Version, die die Projektvariable `budget_version` nennt, sodass der Budgetvergleich leer wäre. |

## Management-Konsolidierung

Jeder Ladevorgang erstellt eine Management-Konsolidierung: die Konzern-Gewinn- und Verlustrechnung jeder Entität im Konzern, in der Berichtswährung, mit eliminierten Intercompany-Positionen. Sie dient der Management-Berichterstattung. Ihr Konsolidierungssystem bleibt das führende System für den gesetzlichen Konzern; stimmen Sie wie unten beschrieben darauf ab.

<Aside type="note">
Die Management-Konsolidierung deckt nur die Gewinn- und Verlustrechnung ab. Sie ist keine gesetzliche oder rechtliche Konsolidierung und enthält keine konsolidierte Bilanz, keine Umrechnungsanpassung, keinen Goodwill und keine Minderheitsanteile.
</Aside>

### Den Konzern festlegen

Öffnen Sie unter **Quellen** die Option **Gruppe**, um die Unternehmen im Konzern zu sehen. Ein Unternehmen, dessen Auswahl Sie aufheben, bleibt einzeln in Ihren Berichten, wird aber aus der Konzernsumme ausgelassen. Klicken Sie auf **Save group**. Die Änderung wird beim nächsten **Laden** oder **Apply changes** wirksam. Ein neues Unternehmen gehört zum Konzern, bis Sie es abwählen.

Das Geschäftsjahr des Konzerns beginnt in dem Monat, den die Projektvariable `group_fy_start_month` festlegt, standardmäßig `1`, sofern Sie das nicht ändern.

### Was Sie erhalten

| Tabelle | Enthält |
|---|---|
| **Group P&L** | Eine Zeile je Entität, Periode und Position (Umsatz, Wareneinsatz, Betriebsaufwand, neutrales Ergebnis, Intercompany-Differenz) in der Berichtswährung. Umsatz und Kosten tragen ihr natürliches Vorzeichen. |
| **Group P&L year to date** | Dasselbe, kumuliert seit Jahresbeginn bis zur letzten vollständig geladenen Periode des Konzerns. |
| **Intercompany pairs** | Eine Zeile je Paar aus Entitäten, Konzern und Periode, mit dem Betrag jeder Seite und dem Rest. |
| **Intercompany lines** | Die Hauptbuchzeilen hinter einer Konzernzahl oder einem Paar, mit dem Handelspartner. |
| **Abstimmung** | Die Konzern-GuV seit Jahresbeginn im Vergleich zu Ihrem Konsolidierungssystem. |

In diesen Tabellen erscheinen drei Entitätsnamen:

| Entität | Bedeutung |
|---|---|
| **Eliminations** | Die Intercompany-Eliminierungen. Sie saldieren sich zu null, belassen Sie sie daher für die Konzernzahlen und filtern Sie sie für die Summe der Entitäten vor der Eliminierung heraus. |
| **Group total** | Die Summe des Konsolidierungssystems, in der Abstimmung. |
| **Unmapped** | Zeilen ohne Periode sowie Konten oder Entitäten Ihres Konsolidierungssystems, die dieses Projekt nicht hat. |

Die Kennzahlen **Consolidated income**, **Consolidated result** und **IC difference** sowie ein Analysepfad für jede Tabelle beantworten Fragen zum Konzern.

### Intercompany-Eliminierungen

Intercompany-Zeilen werden nach Handelspartner zugeordnet. Verwendet wird der Partner auf der Zeile; hat eine Zeile keinen, der Partner ihres Kunden. Beide Seiten eines Paares werden eliminiert, und der Betrag, um den die beiden Seiten voneinander abweichen, wird auf eine Intercompany-Differenzzeile gebucht. Jedes Paar erhält einen Grund:

| Grund | Bedeutung |
|---|---|
| **Matched** | Beide Seiten haben denselben Betrag gebucht. |
| **Only one side booked** | Eine Entität hat die Transaktion gebucht, ihr Partner nicht. |
| **Not eliminated** | Eine Zeile des Paares hat keinen Wechselkurs, daher wird keine Seite eliminiert. |

Ein Paar wird anhand seines Jahresverlaufs beurteilt. Die Zeile **Intercompany balances** wird gelb, wenn die Differenz eines Paares über der Projektvariable `group_amber` (Standard `1`) liegt, und rot über `group_red` (Standard `1000`). Zeilen ohne Partner oder mit einem Partner, der keine Entität ist, werden nicht eliminiert und in dieser Zeile gezählt. Eine Quelle, die Partner führt, neben einer, die keine führt, wird gelb angezeigt.

Die eigenen Eliminierungsentitäten einer Quelle bleiben aus der Konzern-GuV heraus, und die Zeile **Konsolidierung** weist darauf hin.

### Mit Ihrem Konsolidierungssystem abstimmen

Fügen Sie die Ergebnisse, die Ihr Konsolidierungssystem meldet, als Datei hinzu und aktivieren Sie beim Bestätigen ihrer Zuordnung **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)**. Beantworten Sie **Which version of the numbers is this?** mit dem Namen des Systems. Die Tabelle **Abstimmung** zeigt dann **ours**, **reported** und **Differenz** für jede Entität und Position seit Jahresbeginn. Eine Differenz erklärt sich meist in den Zeilen **Eliminations**, **Group total** und **Unmapped** oder durch die vom System verwendeten Wechselkurse. Die Zeile **Reconciliation to the source** listet jede Position über `group_amber` auf.

### Wer es sehen kann

Konzernergebnisse folgen dem Zeilenzugriff des Projekts. Wenn der Zeilenzugriff die Konzernergebnisse verhindert, wird der Status gelb angezeigt. Eine Person, die nur einige Entitäten sieht, sieht die Summen dieser Entitäten vor der Eliminierung. Die Zeilen **Eliminations** und die Intercompany-Tabellen erfordern Zugriff auf jede Entität.

Wenn das Projekt einschränkt, wer welche Zeilen sieht, und zwar anhand einer Spalte, die die Konzerntabellen nicht führen, etwa Abteilung, bleiben die Konzernergebnisse für alle ausgeschaltet, und **Konsolidierung** meldet **Group views are off**. Nur ein Architect kann dann unter **Gruppe** die Option **Everyone on the project may see the group results** aktivieren. Die Änderung wird beim nächsten **Laden** oder **Apply changes** wirksam.

## Aktuell halten

Nachdem ein Ladevorgang aus Ihrer ERP-Verbindung ohne Probleme erfolgreich war, erscheint auf der Karte **Letzter Ladevorgang** die Schaltfläche **Nächtlich aktualisieren**. Klicken Sie darauf, um **Laden** jede Nacht um 2:00 Uhr in Ihrer Zeitzone auszuführen. Die Karte zeigt dann **Nightly refresh: Every night at 2:00** und wer ihn eingerichtet hat.

Der nächtliche Ladevorgang läuft als die Person, die ihn eingerichtet hat. Wenn diese Person die ERP-Verbindung nicht mehr verwenden kann, meldet das Raster, dass der nächtliche Ladevorgang übersprungen wird; richten Sie ihn erneut ein. Ein Projekt, das nur Beispieldaten enthält, kann nicht per Zeitplan ausgeführt werden.

Eine Datei, die bei einem nächtlichen Ladevorgang fehlt oder leer ist, führt zu einer Warnung, die den Pfad nennt, nicht zu einem Fehler, und der Rest des Modells wird dennoch geladen.

## Business Names

**Business names** auf der Registerkarte **Foundation** geben den Codes in Ihrem Modell die Namen, die Ihr Unternehmen verwendet. Berichte, Kennzahlen und der Assistent zeigen diese Namen an, und ein gespeicherter Name gilt sofort. Spätere Ladevorgänge behalten ihn bei.

1. Klicken Sie auf **Add a name** und wählen Sie die **Art**: **Kategorie**, **GuV-Position**, **Kennzahl** oder **Spalte**.
2. Geben Sie den **Code** ein: `segment_1` bis `segment_10` für eine Kategorie, den Schlüssel der Position für eine GuV-Position, den Namen der Kennzahl oder `table.column` für eine Spalte.
3. Geben Sie den **Name** ein, höchstens 60 Zeichen in einer Zeile.
4. Klicken Sie auf **Save names**.

Das Speichern ersetzt die gesamte Liste. Eine Zeile mit leerem Namen entfernt diesen Namen, und **Ausgewählte entfernen** entfernt die Zeilen, die Sie aktivieren. Denselben Code zweimal zu benennen, wird abgelehnt. Business Names werden auch in die Beschreibung des Analysepfads geschrieben, damit der Assistent Ihre Begriffe verwendet, und diese Beschreibung hat eine Längenbegrenzung: Würde ein Name sie zu lang machen, wird nichts gespeichert, und Sie werden darauf hingewiesen.

## Eine Zahl erklären

**Explain this number** zeigt, woraus sich eine Zahl der Gewinn- und Verlustrechnung zusammensetzt. Im Raster **Bereitschaft** hat eine Zeile für eine Entität und einen Monat **Explain this number**, das die operative Marge der Entität für diesen Monat öffnet. Das Fenster teilt die Zahl in Schichten auf, die sich zur Summe oben addieren:

| Schicht | Enthält |
|---|---|
| **From the general ledger** | Was das Hauptbuch auf die Position gebucht hat. |
| **Allocated in** | Kosten, die Ihre [Umlageregeln](#umlageregeln) dieser Entität zugewiesen haben. |
| **Allocated out** | Kosten, die diese Entität anderen zugewiesen hat. |
| **Eliminated in the group** | Intercompany-Positionen, die im Konzernergebnis eliminiert wurden. |

Jede Schicht hat einen Satz, der sagt, was sie ist, und nennt ihre größten Quellbelege mit Quellsystem, Beleg und Konto. Es werden nur Schichten angezeigt, die Zeilen haben. Das Fenster folgt Ihrem Zeilenzugriff: Sie erklären nur die Zahlen, die Sie sehen können. Bei einer Zahl ohne Grundlage steht **Nothing to explain**.

## Umlageregeln

Umlagen verteilen gemeinsame Kosten, etwa Gemeinkosten, auf Abteilungen, Produkte und Kunden. Das Modell hat zwei Stufen: **Stage 1: overhead to departments** und **Stage 2: departments to products and customers**. Öffnen Sie **Aktionen > Umlagen...**, um zu sehen oder zu ändern, wie jede ausgeführt wird. Ohne Änderungen arbeiten sie so, wie sie vor dem Assistenten arbeiteten. Ein Leser kann die Regeln öffnen, aber nicht speichern.

Für jede Stufe stellt der Assistent vier Fragen:

| Schritt | Frage | Auswahl |
|---|---|---|
| **Pool** | Which costs do you want to spread? | Die Kontoart und für Stufe 1 die Abteilung, die die Kosten trägt, oder **All departments**. |
| **Treiber** | What do you want to spread them by? | **Statistic**, das Sie als Verteilungstreiber geladen haben, etwa Mitarbeiterzahl oder Quadratfuß, **Net sales amount**, **Sales quantity** oder **Spread evenly**. Verwenden Sie den Treiber von **Same period** oder **Same period last year**. |
| **Ziel** | Where do they land? | Stufe 1: Abteilungen. Stufe 2: Produkte, Kunden oder beides. |
| **Methode** | What happens when a driver is negative? | **Ignore negative values** oder **Stop and tell me**. |

Unter den Schritten zeigt **Preview for** für einen Monat, geschrieben als Jahr und Monat wie `2026-09`, was die Regeln bewirken würden, einschließlich nicht gespeicherter: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Alles Nichtumgelegte sind Kosten, für die kein Treiber vorhanden war. Die Vorschau folgt Ihrem Zeilenzugriff.

Klicken Sie auf **Speichern**. Die Regeln werden beim nächsten **Laden** wirksam oder wenn Sie auf **Apply changes** klicken. Wenn Sie einen Umlageschritt von Hand bearbeitet haben, bleibt Ihre Änderung erhalten und wird nicht überschrieben, und das Speichern nennt ihn. Während ein Ladevorgang läuft, können Sie nicht speichern.

## Board Pack

Ein Board Pack schreibt Ihre Ergebnisse in einen Ordner in einem Dokumentenkonto, versandfertig. Öffnen Sie **Aktionen > Board pack...**, wählen Sie ein **Dokumentenkonto** und einen **Ordner**, etwa `/board-packs`, und klicken Sie auf **Speichern**. Jedes **Laden** erstellt dann das Pack, sodass die Dateien im Ordner so aktuell sind wie der letzte Ladevorgang. Jede Ausführung schreibt:

- Eine Excel-Arbeitsmappe, `Board pack.xlsx`, mit der Gewinn- und Verlustrechnung nach Entität, einer Margenbrücke sowie den besten und schlechtesten Kunden.
- Ein PDF des Dashboards der Gewinn- und Verlustrechnung.

Klicken Sie auf **Run now**, um sofort ein Pack zu erstellen; seine Dateien erscheinen im Ordner, wenn es fertig ist. Der Dialog zeigt die letzte Ausführung und ihr Ergebnis sowie die nächste Ausführung. **Apply changes** erstellt kein Pack. Um jede Nacht eines zu erstellen, richten Sie die nächtliche Aktualisierung ein (siehe [Aktuell halten](#aktuell-halten)); bis dahin zeigt der Dialog **Not scheduled yet**. Nur wer das Projekt ändern kann, richtet sie ein.

Ein Pack, das nicht vollständig erstellt werden kann, lässt den Ladevorgang nie fehlschlagen:

- Wenn die Berichterstattung für Ihren Workspace ausgeschaltet ist, besteht das Pack nur aus der Excel-Arbeitsmappe, und die Ausführung meldet **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- Wenn ein Dashboard eines anderen Benutzers bereits die Adresse hat, die Data Foundation für das Dashboard der Gewinn- und Verlustrechnung benötigt, bleibt dieses Dashboard unverändert, und das PDF wird nicht erstellt. Die Meldung nennt die Adresse; geben Sie dem anderen Dashboard eine andere Adresse und führen Sie dann **Laden** erneut aus.
- Wenn ein Schritt des Packs fehlschlägt, zeigt die Liste **Status** eine gelbe Zeile **Board pack**, die den Schritt und den Grund nennt. Der Ladevorgang selbst war dennoch erfolgreich.

## Wiederherstellungspunkte

Ein Wiederherstellungspunkt wird erstellt, wenn jedes **Laden** oder **Apply changes** beginnt, unabhängig davon, wer es startet, einschließlich eines per Zeitplan ausgeführten Ladevorgangs, sowie vor jeder Änderung an Zuordnungen oder Quellen. Er enthält die Tabellen des Modells, die Dimensionen und die Einstellungen, aus denen der nächste Ladevorgang aufbaut: Ihre Quellen, Dateien und Umlageregeln. Die letzten sieben Punkte, die für Ladevorgänge erstellt wurden, und die letzten fünf, die vor Änderungen erstellt wurden, bleiben erhalten, sodass Änderungen die für Ladevorgänge erstellten Punkte nie verdrängen. Ältere Punkte fallen heraus.

Um zurückzugehen, öffnen Sie **Aktionen > Wiederherstellen...**. Jeder Punkt zeigt, wann er erstellt wurde, und darunter, wie viele Tabellen seine Wiederherstellung zurückbringt, zum Beispiel **Puts back 12 tables.**, sowie etwaige Warnungen. Wählen Sie einen Punkt und klicken Sie auf **Wiederherstellen**. **Wiederherstellen** wird angeboten, sobald ein Punkt existiert. Beim Wiederherstellen wird zuerst das Projekt in seinem jetzigen Zustand als eigener Punkt festgehalten, sodass Sie erneut zurückgehen können. Anschließend werden die Tabellen, die Dimensionen und diese Einstellungen so wiederhergestellt, wie sie waren, und der nächste Ladevorgang baut darauf auf. Das Wiederherstellen auf Quellen, die Sie bereits hatten, markiert diese nicht als geändert. Eine Ansicht, eine Dimension, die nicht gespeichert werden kann, oder eine Tabelle ohne gespeicherte Kopie wird in einer Warnung genannt, und der Rest wird wiederhergestellt. Ein Wiederherstellungspunkt, der herausgefallen ist, wird abgelehnt, und solange ein Ladevorgang läuft, können Sie nicht wiederherstellen.

## Ein Projekt klonen

**Aktionen > Klonen...** kopiert das Projekt unter einem Namen, den Sie angeben. Die Kopie behält die Vorlage, Ihre Änderungen am Modell sowie Ihre Kennzahlen und Analysepfade und lädt die Beispieldaten. Ihre Quellen sind nicht verbunden, verbinden Sie sie daher in der Kopie, bevor Sie laden. Sie können weiterarbeiten, während die Kopie erstellt wird, und **Projekt öffnen** führt Sie dorthin, wenn sie fertig ist.

## Als meine Vorlage speichern

Speichern Sie die Einrichtung eines Projekts, um sie für den nächsten Kunden oder die nächste Entität wiederzuverwenden. Öffnen Sie **Aktionen > Save as my template...**, wählen Sie das Dokumentenkonto und benennen Sie die Datei. Eine Endung `.zip` wird ergänzt, wenn Sie sie weglassen. Das Speichern über eine vorhandene Datei wird abgelehnt, wählen Sie daher einen anderen Namen.

Die Datei enthält die Struktur des Projekts, Ihre Änderungen am Modell, Kennzahlen und Analysepfade, die Business Names für Entitäten und Konten sowie die Zeilen der Konfigurationstabellen der Vorlage, etwa die Aktivitätszuordnung von [Cost to Serve](/de/guides/projects/cost-to-serve/) oder die Richtwertspannen von [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/). Nicht enthalten sind Verbindungen, Dateien, der nächtliche Zeitplan, Ausführungen, Wiederherstellungspunkte, das Board Pack und wer Zugriff hat.

Um sie zu verwenden, erstellen Sie ein Projekt, wählen Sie unter **Starten mit** die Option **From a template file...** und geben Sie das Dokumentenkonto und den Pfad an. Das neue Projekt ist privat und gehört Ihnen, wobei jede Quelle auf ihre Verbindung wartet. Eine spätere Version der Vorlage führt ihre Änderungen um die Schritte herum zusammen, die Sie bearbeitet haben. Gibt es am Pfad keine Datei, wird nichts erstellt, und Sie werden darauf hingewiesen. Jeder, der das Dokumentenkonto lesen kann, kann aus der Datei installieren. Um sie in einem anderen Workspace zu verwenden, laden Sie die Datei herunter und dort hoch.

## Offene Fragen mit Ask klären

Nach einem Ladevorgang kann ein Projekt noch auf Angaben zu drei Dingen warten: Konten, denen der Kontenplan keinen Typ zuweist, Codes, die mehr als eine Quelle verwendet, und Spalten in Ihren Dateien, die nichts zugeordnet wurden. Bitten Sie den Assistenten, sie zu klären: Verwenden Sie aus einem KI-Assistenten über MCP den Prompt **Resolve Data Foundation residue**. Er liest, was aussteht, und schlägt für jeden Punkt eine Antwort mit Begründung vor.

Der Assistent schreibt nichts. Sie wenden seine Antworten dort an, wo Sie selbst geantwortet hätten: Konten und Codes unter **Codes waiting for your answer** und Dateispalten in der Zuordnung der Datei. Er schlägt nie eine Entität vor.

## Das Projekt übergeben

Die Checkliste **Einrichtung** hat nach **Hierarchien prüfen** vier abschließende Punkte:

- **Set up the nightly refresh** ist erledigt, sobald **Nächtlich aktualisieren** aktiviert ist.
- **Mit Ihrem Team teilen** ist erledigt, sobald jemand außer der Person, die das Projekt eingerichtet hat, Mitglied ist.
- **Download the evidence pack** ist erledigt, wenn Sie das Pack nach dem letzten erfolgreichen Ladevorgang herunterladen.
- **Hand the project over to its owner** ist erledigt, sobald ein anderer Architect als die Person, die es eingerichtet hat, existiert und die Summen übereinstimmen. Solange es nicht erledigt ist, nennt die Checkliste, was zu tun ist: den Eigentümer des Kunden zum Architect dieses Projekts machen und sich dann aus seinen Mitgliedern entfernen.

Die Checkliste nennt, wer das Projekt eingerichtet hat (**Set up by**).

## Mit einer Vorlage auf dem Modell aufbauen

Eine Vorlage baut ihre Berichte und Modelle auf dem Common Finance Model auf, sodass sie unabhängig davon, welche ERPs es speisen, gleich funktionieren. Wenn Sie ein Projekt aus einer Vorlage starten, etwa **Enterprise Profitability**, werden erstellt:

- Die [Tabellen des Common Finance Model](#tabellen-des-common-finance-model), leer oder mit Beispieldaten gefüllt.
- Die Dimensionen **Entität**, **Konto**, **Abteilung**, **Kunde**, **Produkt**, **Segment 1** und **Segment 2**, aufgebaut aus diesen Tabellen. Siehe [Hierarchien](#hierarchien).
- Der Workflow **Laden** und die Workflows, die er ausführt, um Ihr ERP und Ihre Dateien zu lesen, sie zu überführen, die Bereitschaft zu prüfen und die Modelle der Vorlage aufzubauen.
- Die eigenen Berichte und Modelle der Vorlage. **Enterprise Profitability** ergänzt eine Tabelle der Gewinn- und Verlustrechnung mit Umsatz, Wareneinsatz, Bruttomarge, direkten und Gemeinkosten-Betriebsaufwendungen, Deckungsbeitrag und operativer Marge sowie Margenbrücken im Jahresvergleich und gegenüber dem Budget.
- Kennzahlen und einen Analysepfad, um Fragen zu den Ergebnissen zu stellen.

Unter **Starten mit** stehen drei Vorlagen zur Verfügung, die jeweils auf demselben Modell aufbauen:

| Vorlage | Ergänzt |
|---|---|
| **Enterprise Profitability** | Die Gewinn- und Verlustrechnung und Margenbrücken. |
| **Cost to Serve** | Die Kosten, die für die Betreuung jedes Kunden anfallen, und die Marge danach. Siehe [Cost to Serve](/de/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | Das Gewinnniveau jeder Entität gegenüber Ihrer Richtwertspanne und die Nachverrechnung. Siehe [Operational Transfer Pricing](/de/guides/projects/operational-transfer-pricing/). |

**From a template file...** startet von einem Projekt, das Sie gespeichert haben. Siehe [Als meine Vorlage speichern](#als-meine-vorlage-speichern).

Um zu erkunden, bevor Sie Ihr eigenes ERP verbinden, aktivieren Sie beim Erstellen des Projekts **Mit Beispieldaten starten**. Das Projekt führt sofort einen ersten Ladevorgang aus, sodass die Registerkarte **Foundation** ein vollständiges Beispiel zeigt, einschließlich einer in US-Dollar umgerechneten Euro-Entität. Wenn Sie Ihr eigenes ERP verbinden oder Ihre eigenen Dateien hinzufügen, wird das Beispiel entfernt, und Ihre Daten treten an seine Stelle. Wird das Entfernen unterbrochen, schließt das nächste **Laden** es ab. Ein eigener Ordner namens `sample` wird nie entfernt: Die Statusseite vermerkt, dass das Beispiel diesen Ordner belegt, sodass die anderen Tabellen darin nicht gelesen werden, und bittet Sie, sie in einen Ordner mit anderem Namen zu verschieben.

## Die Registerkarte Foundation

Auf der Registerkarte **Foundation** verbinden, laden und prüfen Sie Ihre Daten. Eine Leiste links listet vier Seiten auf:

| Seite | Was sie zeigt |
|---|---|
| **Status** | Den Zustand des Projekts: **Letzter Ladevorgang** mit den Schaltflächen **Laden**, **Apply changes**, **Aktualisieren** und **Nächtlich aktualisieren**, **What to do next**, die Checkliste **Einrichtung**, **Daten geladen**, **Perioden**, **Bereitschaft** und das Menü **Aktionen**. |
| **Answers needed** | Die Fragen, die auf Sie warten, etwa Codes, die mehr als eine Quelle verwendet und bei denen Sie angeben, ob sie dasselbe bedeuten. |
| **Source coverage** | Wo sich Quellen für eine Gesellschaft und einen Monat überschneiden oder Lücken lassen und welche Quelle ab wann zählt. |
| **Quellen** | Jede Quelle in Reihenfolge, mit **Erweitert**, **Remove this source**, **Gruppe** und **Rename extra categories**, sowie **Verbinden**, wo Sie ein ERP verbinden, die Entitäten und die Anzahl der zu ladenden Monate Verlauf auswählen oder eine Datei hinzufügen. |

Badges in der Leiste zählen, was Ihre Aufmerksamkeit erfordert: die offenen Fragen auf **Answers needed**, die Abdeckungsprobleme auf **Source coverage** und die Quellen auf **Quellen**. **Status** zeigt kein Badge. Das Ergebnis von **Laden** oder **Apply changes** und das Statusbanner erscheinen über der jeweils geöffneten Seite, sodass Sie sie auf jeder Seite sehen. Die Schaltflächen auf **Status**, die auf eine Frage oder ein Abdeckungsproblem verweisen, etwa **Prüfen**, führen Sie zur entsprechenden Seite. Wenn Sie **Answers needed** oder **Source coverage** schließen, kehren Sie zu **Status** zurück.

Die Checkliste **Einrichtung** umfasst: **Daten verbinden**, **Daten laden**, **Prüfen, ob die Summen übereinstimmen**, **Hierarchien prüfen**, **Set up the nightly refresh**, **Mit Ihrem Team teilen**, **Download the evidence pack** und **Hand the project over to its owner**. Der aktuelle Punkt ist fett dargestellt. Die Business Names, die von Ihnen hinzugefügten Dateien mit ihrem Zuordnungsstatus (**✓ Bestätigt** oder **○ Wartet auf Bestätigung**) sowie das Bereitschaftsraster mit einer Zeile je Entität, Periode und Prüfung samt **Was zu tun ist** befinden sich auf denselben Seiten. Siehe [Business Names](#business-names).

Während ein Ladevorgang läuft, aktualisiert sich die Registerkarte selbstständig und liest weiter, auch wenn ein Lesevorgang fehlschlägt. Kann der Status nicht gelesen werden, erscheint **Der Foundation-Status konnte nicht gelesen werden.** mit **Erneut versuchen**, was ihn neu liest; die Registerkarte versucht es außerdem einmal selbst, bevor sie die Meldung zeigt, und die Meldung verschwindet, sobald der Server antwortet.

Die Seite **Status** vermerkt außerdem:

- Ein Ordner unter `/sources/`, dessen Tabellen die benötigten Spalten fehlen, wird nicht als Quelle hinzugefügt. Ein Hinweis nennt jede ausgelassene Tabelle und die fehlende Spalte. Fügen Sie die Spalte hinzu und drücken Sie dann **Laden** oder **Apply changes**.
- Wenn ein Ladevorgang erfolgreich war, aber keine Hauptbuchzeilen zum Abgleich eingebracht hat, meldet eine gelbe Zeile **Model P&L ties to GL**, dass nichts abgestimmt wurde. **Prüfen, ob die Summen übereinstimmen** bleibt in der Einrichtungs-Checkliste ausstehend, nicht erledigt, bis etwas abgestimmt wurde. Fügen Sie eine Quelle mit Hauptbuchzeilen hinzu und drücken Sie dann **Laden**.

Die Einrichtungs-Checkliste verfolgt Ihren Fortschritt:

- **Daten verbinden** und **Daten laden** werden von selbst abgehakt, sobald eine Quelle angehängt und ein Ladevorgang erfolgreich ist.
- **Prüfen, ob die Summen übereinstimmen** wird von selbst abgehakt, wenn die Abstimmungsprüfungen bestanden sind.
- **Hierarchien prüfen**: Klicken Sie auf **Dimensionen öffnen**, um die Hierarchien für Entität, Konto und Abteilung zu prüfen, und aktivieren Sie dann **Ich habe sie geprüft**. Diesen Punkt bestätigen Sie selbst.
- **Set up the nightly refresh**, **Mit Ihrem Team teilen**, **Download the evidence pack** und **Hand the project over to its owner** schließen die Liste ab. Siehe [Das Projekt übergeben](#das-projekt-übergeben) und [Projektzugriff verwalten](/de/guides/projects/managing-projects/#projektzugriff-verwalten).

Das Menü **Aktionen** enthält **Umlagen...**, **Board pack...**, **Klonen...**, **Wiederherstellen...** und **Save as my template...**. Siehe [Umlageregeln](#umlageregeln), [Board Pack](#board-pack), [Ein Projekt klonen](#ein-projekt-klonen), [Wiederherstellungspunkte](#wiederherstellungspunkte) und [Als meine Vorlage speichern](#als-meine-vorlage-speichern).

## Tabellen des Common Finance Model

Data Foundation überführt jede Quelle, ERP oder Datei, in dieselben fünfzehn Tabellen, sodass Berichte, Kennzahlen und Modelle darauf unabhängig von der Quelle gleich funktionieren. Jede Zeile hält außerdem ihr Quellsystem und den Zeitpunkt des Lesens fest. Die Spalte **Dataset** ist der Name, den Sie beim Hinzufügen einer Datei wählen.

| Dataset | Tabelle | Enthält |
|---|---|---|
| Entitäten | `cfm_entity` | Rechtliche Einheiten mit übergeordneter Einheit, Lokal- und Konzernwährung und Land. |
| Entitätszuordnung | `cfm_entity_map` | Entitätscodes der Quellen und die Entität, zu der jeder gehört. Siehe [Entitätszuordnung](#entitätszuordnung). |
| Wechselkurse | `cfm_fx_rate` | Monatliche Durchschnitts-, Stichtags- und historische Kurse je Währungspaar. Siehe [Wechselkurse](#wechselkurse). |
| Geschäftskalender | `cfm_fiscal_calendar` | Eine Zeile je Geschäftsperiode einer Entität, mit Start- und Enddatum und der Angabe, ob sie abgeschlossen ist. |
| Kontenplan | `cfm_account` | Konten mit übergeordnetem Konto, Typ (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), Rechnung, normalem Saldo und Kurstyp. |
| Abteilungen | `cfm_department` | Abteilungen und Kostenstellen mit übergeordneter Einheit und Profitcenter. |
| Produkte | `cfm_product` | Produktstamm mit übergeordnetem Produkt, Familie, Gruppe, Mengeneinheit und Standardkosten. |
| Kunden | `cfm_customer` | Kundenstamm mit übergeordnetem Kunden, Gruppe, Region und Land. Kundennamen werden nicht maskiert. |
| Segmentwerte | `cfm_segment` | Segmentwerte mit Name und übergeordnetem Element. Siehe [Hierarchien](#hierarchien). |
| Hauptbuch | `cfm_gl_journal` | Journalzeilen in Transaktions-, Lokal- und Berichtswährung. |
| Saldenliste | `cfm_trial_balance` | Soll, Haben und Saldo der Periode nach Entität, Konto und Abteilung, in Lokal- und Berichtswährung. |
| Verkaufspositionen | `cfm_sales_line` | Fakturierte Verkaufspositionen mit Menge, Brutto-, Rabatt-, Netto- und Wareneinsatzbeträgen. |
| Lagerbestände | `cfm_inventory_balance` | Lagerbestand am Periodenende nach Produkt und Lager. |
| Budget | `cfm_budget` | Budget und Prognose nach Szenario, Version, Konto und Abteilung. |
| Verteilungstreiber | `cfm_stat_driver` | Statistische Treiber wie Mitarbeiterzahl, Quadratfuß oder Einheiten. |

Perioden werden als `YYYY-MM` geschrieben, und Transaktionen werden nach Buchungsperiode zugeordnet. Das Budget ist optional: Ein ERP ohne Budgets lädt dennoch alles andere.

Eine Saldenlistendatei kann Soll- und Haben-Spalten, eine Saldospalte oder beides enthalten. Mit nur Soll und Haben ist der Saldo Soll minus Haben, und eine leere Seite zählt als null. Mit nur einem Saldo wird ein positiver Saldo zum Soll und ein negativer Saldo zum Haben, als positiver Betrag. Eine Abteilungsspalte ist optional.

## Fehlerbehebung

| Symptom | Was zu tun ist |
|---|---|
| **Verbindung testen** meldet, dass das ERP die Zugangsdaten abgelehnt hat | Prüfen Sie die Zugangsdaten der Verbindung und ob sich der Integrationsbenutzer am ERP anmelden kann. |
| **Verbindung testen** zeigt für ein Dataset **Fehlende Berechtigung** | Bitten Sie Ihren ERP-Administrator, die genannten Berechtigungen hinzuzufügen. Die [Verbindungsanleitung](/de/guides/connections/) für Ihr ERP nennt, was die Verbindung benötigt. |
| Eine ERP-Fehlermeldung ist kürzer als die des ERP selbst | PlaidCloud entfernt Zugangsdaten, Token und Schlüssel aus Fehlern des Anbieters, bevor es sie anzeigt, sodass manche Details fehlen. Führen Sie **Verbindung testen** aus, um zu sehen, welches Dataset betroffen ist. |
| **Daten geladen** ist für eine Periode ein Problem | Ein ERP-Lesevorgang für diese Periode ist fehlgeschlagen. Führen Sie **Laden** erneut aus; bereits geladene Perioden werden übersprungen. |
| **Konten fehlen im Kontenplan** ist ein Problem | Fügen Sie die fehlenden Konten dem Kontenplan im ERP oder in Ihrer Datei hinzu und führen Sie **Laden** erneut aus. |
| **Währungsumrechnung** ist ein Problem | Für die Währung einer Entität gibt es für diese Periode keinen Kurs in die Berichtswährung, oder es wurde keine einzelne Berichtswährung gefunden. Fügen Sie die Kurse in einer Datei **Wechselkurse** hinzu, prüfen Sie, ob die Verbindung die Wechselkurse des ERP lesen kann, oder setzen Sie die Projektvariable `reporting_currency`. Führen Sie dann **Laden** erneut aus. |
| **Währungsumrechnung** erfordert Aufmerksamkeit | Bilanz-, Lager- oder Budgetzeilen haben für die Periode keinen Stichtags-, historischen oder Planungskurs. Die Gewinn- und Verlustrechnung ist nicht betroffen. Fügen Sie die Kurse hinzu, einschließlich Planungskursen für Budgetmonate, und führen Sie **Laden** erneut aus. |
| **Codes waiting for your answer** erfordert Aufmerksamkeit | Klicken Sie auf **Prüfen**, beantworten Sie jeden Code und klicken Sie auf **Apply changes**. |
| **Which source covers which months** erfordert Aufmerksamkeit | Klicken Sie auf **Choose which source counts from when**, wählen Sie die Quelle und klicken Sie auf **Apply changes**. |
| **Intercompany balances** ist rot oder gelb | Prüfen Sie die Paare in **Intercompany pairs**. Buchen Sie die fehlende Seite, ergänzen Sie den Handelspartner in den Zeilen oder fügen Sie den fehlenden Kurs hinzu. |
| **Group views are off** | Bitten Sie einen Architect, unter **Gruppe** die Option **Everyone on the project may see the group results** zu aktivieren. |
| **Nicht zugeordnete Entitäten** ist ein Problem | Fügen Sie die Entität dem Entitätsstamm hinzu oder ordnen Sie ihren Code in der Datei **Entitätszuordnung** einer vorhandenen Entität zu und führen Sie **Laden** erneut aus. |
