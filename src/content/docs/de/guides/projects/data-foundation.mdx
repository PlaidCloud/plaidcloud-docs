**Data Foundation** ist das Finanzdatenfundament für Ihre PlaidCloud-Projekte. Das **Common Finance Model** führt ERP-Daten aus mehreren ERP-Systemen und jeweils mehreren Instanzen in einem einzigen Modell zusammen: ein Kontenplan, eine Menge von Entitäten und eine Berichtswährung. Berichte, Kennzahlen und KI-Assistenten, die auf dem Modell aufbauen, lesen alle dieselben Zahlen, aus welchem ERP sie auch stammen.

Ihr ERP wird über seine PlaidCloud-Verbindung angebunden, sodass Hauptbuch, Saldenliste, Stammdaten und Budgets direkt aus der Quelle eintreffen und nichts exportiert werden muss. Dateien ergänzen Daten, die ein System nicht enthält, etwa Wechselkurse, Verteilungstreiber oder ein außerhalb des ERP geführtes Budget, und können die ERP-Zeilen ersetzen, die sie abdecken. **Laden** überführt jede Quelle in das Modell, rechnet sie in die Berichtswährung um und prüft, ob alles übereinstimmt – alles auf der Registerkarte **Foundation** des Projekts. Vorlagen wie **Enterprise Profitability** bauen ihre Berichte und Modelle darauf auf.

## ERP verbinden

Ihr ERP wird über seine PlaidCloud-Verbindung an Data Foundation angebunden. Data Foundation liest Hauptbuch, Saldenliste, Stammdaten, Wechselkurse und Budgets direkt daraus und liest ausschließlich. Sie können eine vorhandene Verbindung auswählen oder auf der Registerkarte eine erstellen; die [Verbindungsanleitungen](/de/guides/connections/) behandeln die Zugriffseinrichtung für jedes ERP.

<Steps>

1. Öffnen Sie in Analyze **Projekte** und klicken Sie auf **Neues Projekt**. Geben Sie einen Namen ein und wählen Sie unter **Starten mit** statt **Leeres Projekt** eine Vorlage, zum Beispiel **Enterprise Profitability (Vorlage)**. Klicken Sie auf **Erstellen**.

   Das Projekt öffnet sich auf seiner Registerkarte **Foundation**. Es ist privat für Sie, und Sie sind sein einziger Architect, bis Sie es freigeben.

2. Wählen Sie auf der Registerkarte **Foundation** eine vorhandene Verbindung für Ihr ERP aus oder wählen Sie **Neue Verbindung erstellen**. Jede vorhandene Verbindung listet die Workflows auf, die sie bereits verwenden, oder meldet **Noch von keinem Workflow verwendet**.

3. Geben Sie für eine neue Verbindung einen **Verbindungsname** ein, wählen Sie die **Umgebung** und tragen Sie die Zugangsdaten ein, die Ihre ERP-Verbindung verlangt.

   Sie haben die Zugangsdaten noch nicht? Das Formular zeigt eine vorgefertigte Zugriffsanfrage für Ihren ERP-Administrator. Klicken Sie auf **Anfrage kopieren** oder **Anfrage per E-Mail senden**, schicken Sie sie ab und tragen Sie die Werte ein, die Sie zurückerhalten.

4. Klicken Sie auf **Verbindung testen**. PlaidCloud meldet sich an und versucht, jedes Dataset zu lesen, und listet dann jedes als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** auf. Fehlt etwas, nennt es die Berechtigungen, die Ihr ERP-Administrator hinzufügen soll.

5. Legen Sie **Monate Verlauf** fest: wie viele Monate zurück geladen werden, von 1 bis 120. Der Standard ist 24.

6. Markieren Sie bei einer vorhandenen Verbindung die zu ladenden Entitäten oder lassen Sie alle unmarkiert, um jede Entität zu laden. Inaktive Entitäten und Eliminierungsentitäten bleiben ausgeblendet, bis Sie sich dafür entscheiden, sie anzuzeigen. Klicken Sie dann auf **Verbinden**.

7. Klicken Sie bei einer neuen Verbindung auf **Verbinden**, um sie zu erstellen. Markieren Sie dann die zu ladenden Entitäten und klicken Sie erneut auf **Verbinden**, um sie zu speichern. Bis Sie das tun, wird jede Entität geladen.

</Steps>

Nach der Verbindung zeigt die Karte an, welche Verbindung, Umgebung, Entitäten und wie viele Monate Verlauf das Projekt lädt.

Jeder Ladevorgang liest nur, was sich geändert hat: Offene Perioden und die zuletzt abgeschlossene Periode werden erneut gelesen, bereits geladene abgeschlossene Perioden bleiben erhalten. Wenn Sie **Monate Verlauf** erhöhen, werden nur die hinzugekommenen Monate gelesen. Ein geänderter Wechselkurs, eine geänderte Entitätszuordnung oder eine geänderte Berichtswährung liest die davon betroffenen Monate erneut.

## Dateien für Daten außerhalb Ihres ERP hinzufügen

Dateien ergänzen Ihre ERP-Verbindung um Daten, die ein System nicht enthält, etwa Wechselkurse, Verteilungstreiber, eine [Entitätszuordnung](#entitätszuordnung) oder ein außerhalb des ERP geführtes Budget. Jede Datei gehört zu einem der Datasets, die unter [Tabellen des Common Finance Model](#tabellen-des-common-finance-model) aufgeführt sind.

<Steps>

1. Wählen Sie unter **Dateien** das **Dokumentenkonto** aus, in dem die Datei gespeichert werden soll.

2. Legen Sie eine CSV- oder Excel-Datei auf **CSV- oder Excel-Datei hier ablegen** ab oder klicken Sie auf **Datei auswählen**. Die Datei wird in den Ordner `/foundation/` des Dokumentenkontos hochgeladen.

   Geben Sie für eine Datei, die sich bereits im Dokumentenkonto befindet, ihren **Dateipfad** ein, zum Beispiel `/foundation/budget.csv`, und klicken Sie auf **Datei hinzufügen**.

3. PlaidCloud liest die Datei und schlägt eine Zuordnung vor:

   - **Erkanntes Trennzeichen, Dezimaltrennzeichen und Datumsangaben.** Das Trennzeichen (Komma, Semikolon, Tabulator oder senkrechter Strich), das Dezimaltrennzeichen und das Datumsformat werden automatisch erkannt.
   - **Dataset**: die Tabelle des Common Finance Model, zu der die Datei gehört, abgeleitet aus Dateiname und Spaltenüberschriften. Ist die Zuordnung nicht eindeutig, wählen Sie sie aus der Liste aus.
   - **Dezimaltrennzeichen**: **Punkt (1,234.56)** oder **Komma (1.234,56)**.
   - **Datumsformat**: wird angezeigt, wenn die Datei Datumsangaben enthält. Ändern Sie es, wenn das erkannte Format falsch ist: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` oder `MM/DD/YYYY`.
   - Ein Raster mit **Spalte in Datei**, **Typ**, **Beispiele** und **Geht nach**. Ändern Sie **Geht nach**, um eine Spalte einem anderen Feld zuzuweisen oder auf **Nicht laden** zu setzen.

4. Prüfen Sie, wohin jede Spalte geht, und klicken Sie dann auf **Zuordnung bestätigen**.

</Steps>

Kann PlaidCloud das Dataset, das Dezimaltrennzeichen oder die Datumsreihenfolge nicht selbst bestimmen, zum Beispiel bei einer Datei, deren Datumsangaben als Tag/Monat oder Monat/Tag gelesen werden könnten, bittet es Sie vor der Bestätigung um eine Auswahl. Wenn Sie eine zweite Datei für dasselbe Dataset hinzufügen, ersetzt sie die erste.

Akzeptiert werden Textdateien im Format CSV, TSV und TXT, Excel-Dateien im Format `.xlsx` (gelesen wird das erste Blatt) und Parquet-Dateien.

<Aside type="note">
Eine fehlende oder leere Datei stoppt einen Ladevorgang nie. Beim Hinzufügen erfahren Sie, dass noch nichts zuzuordnen ist, und ein Ladevorgang endet mit einer Warnung, die den Pfad nennt, und lässt dieses Dataset leer. Fügen Sie die Datei erneut hinzu, sobald sie existiert.
</Aside>

## Daten laden

Klicken Sie auf der Karte **Laden** oder der Karte **Letzter Ladevorgang** auf **Laden**. Der Ladevorgang liest Ihr verbundenes ERP und Ihre bestätigten Dateien, überführt sie in das Common Finance Model, rechnet sie in die Berichtswährung um, führt die Bereitschaftsprüfungen aus und baut die Modelle der Vorlage neu auf.

- Pro Projekt läuft immer nur ein Ladevorgang. Ein zweites **Laden** meldet, dass bereits ein Ladevorgang läuft.
- Wenn andere Workflows dieselbe ERP-Verbindung verwenden, listet der erste Ladevorgang sie auf und bittet um Bestätigung, weil ein Ladevorgang aus dem ERP liest und diese Workflows verlangsamen kann. Klicken Sie auf **Trotzdem laden**, um fortzufahren.
- Ein fehlgeschlagener Ladevorgang wird rot angezeigt und verschwindet nie hinter früheren Ergebnissen. Zeilen aus einem früheren Ladevorgang zeigen **Aus einem früheren Ladevorgang. Erneut laden.**, bis ein Ladevorgang erfolgreich ist.
- Schlägt das Lesen einer Entität und Periode fehl, werden die übrigen trotzdem geladen. Führen Sie **Laden** erneut aus, um nur das nachzuladen, was fehlgeschlagen ist.

### ERP-Daten und Dateien zusammen

Eine Datei ersetzt nur, was sie abdeckt, und die übrigen Zeilen aus Ihrem ERP bleiben erhalten.

- **Stammdatendateien** (Konten, Abteilungen, Kunden, Produkte und Segmentwerte) ersetzen die ERP-Zeilen mit demselben Code.
- **Bewegungsdatendateien** ersetzen die ERP-Zeilen für dieselbe Entität und denselben Monat. Hauptbuch- und Saldenlistendateien werden außerdem nach Ledger abgeglichen, Budgetdateien nach Szenario und Dateien mit statistischen Treibern nach Szenario und Treiber.

Deckt eine Datei später einen Monat nicht mehr ab, kehren die Daten des ERP für diesen Monat beim nächsten Ladevorgang zurück.

## Entitätszuordnung

Jede Quelle benennt ihre Entitäten mit eigenen Codes. Die **Entitätszuordnung** ordnet diese Codes den Entitäten in Ihrem Entitätsstamm zu, sodass Zeilen aus jeder Quelle bei derselben Entität landen.

Um eine zu verwenden, fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Entitätszuordnung**:

| Spalte | Enthält |
|---|---|
| `source_entity` | Den Code, wie ihn die Quelle führt, etwa einen Buchungskreis. |
| `entity` | Die Entität, zu der er gehört, so wie der Entitätsstamm sie benennt. |

- Ein Code, der nicht in der Zuordnung enthalten ist, wird unverändert verwendet.
- Mehrere Codes können einer Entität zugeordnet werden. Ihre Zeilen werden zusammengefasst, und ein Monat gilt als abgeschlossen, sobald er für alle abgeschlossen ist.
- Codes in der Zuordnung gelten für jede Quelle, daher müssen die Entitätscodes jeder Quelle quellenübergreifend eindeutig sein.
- Eine Zeile in einer Datei **Entitäten** ersetzt die Entität des ERP mit demselben Entitätscode.

Die Prüfung **Nicht zugeordnete Entitäten** markiert jede Zeile, deren Entität weder im Entitätsstamm enthalten noch durch die Zuordnung einer solchen zugeordnet ist. Solange kein Entitätsstamm geladen ist, zeigt sie **– Nicht zutreffend**.

## Währungsumrechnung

Jeder Ladevorgang rechnet die Beträge von Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget aus ihrer lokalen Währung in eine Berichtswährung um. Berichte und Modelle lesen die umgerechneten Beträge, sodass Entitäten in unterschiedlichen Währungen aus beliebigen Systemen korrekt summiert werden.

### Die Berichtswährung

Um die Berichtswährung festzulegen, setzen Sie die Projektvariable `reporting_currency` auf einen Währungscode wie `USD`. Siehe [Projektvariablen verwalten](/de/guides/projects/managing-projects/#projektvariablen-verwalten). Die Vorlage legt sie leer an. Solange sie leer ist, verwendet jeder Ladevorgang die erste der folgenden Angaben, die genau eine Währung benennt:

1. Die Konzernwährung der Entitäten.
2. Die lokale Währung der Entitäten der obersten Ebene, also derer ohne übergeordnete Entität.
3. Die lokale Währung der Dateien.

Benennt keine davon genau eine Währung, zeigt **Währungsumrechnung** ein Problem an, bis Sie `reporting_currency` festlegen.

Beträge, die bereits in der Berichtswährung vorliegen, bleiben unverändert, sodass ein Projekt, dessen Daten alle in einer Währung vorliegen, keine Kurse benötigt.

Auch Umsatz-, Lagerbestands- und Budgetdateien können eine Währung enthalten. Ordnen Sie eine Spalte namens `Currency` oder `Local Currency` zu, dann wird sie automatisch erkannt, und die lokalen Beträge der Datei werden in die Berichtswährung umgerechnet. Ein Konzern- oder Berichtsbetrag, der bereits in der Datei steht, bleibt unverändert. Die Standardkosten eines Produkts werden nicht umgerechnet.

### Wechselkurse

Ein Kurs rechnet für einen Monat eine Einheit einer Währung in die Berichtswährung um: Der umgerechnete Betrag ist der lokale Betrag mal dem Kurs.

- **Aus Ihrem ERP** liest jeder Ladevorgang die Wechselkurse, die das ERP enthält.
- **Aus einer Datei**: Fügen Sie eine CSV- oder Excel-Datei hinzu und wählen Sie das Dataset **Wechselkurse**. Ein Kurs in der Datei ersetzt den Kurs des ERP für dieselben Währungen und denselben Monat. Verwenden Sie eine Datei, um in einer Währung zu berichten, für die Ihre ERP-Systeme keine Kurse bereitstellen, oder um Planungskurse für Budgetmonate hinzuzufügen.

| Spalte | Enthält |
|---|---|
| `from_currency` | Die Ausgangswährung der Umrechnung, zum Beispiel `EUR`. |
| `to_currency` | Die Berichtswährung, zum Beispiel `USD`. |
| `period` | Den Monat im Format `YYYY-MM`. |
| `average_rate` | Den Durchschnittskurs des Monats. |
| `closing_rate` | Den Kurs am Monatsende. |
| `historical_rate` | Den historischen Kurs für das Eigenkapital und für Konten, die auf den historischen Kurs eingestellt sind. |

Es werden nur Kurse in die Berichtswährung verwendet. Ein Kurs, der in die andere Richtung notiert ist, also von der Berichtswährung in eine andere Währung, wird nicht invertiert.

### Welcher Kurs gilt

Jede Zeile wird aus ihrer eigenen Währung umgerechnet; eine Zeile in einer anderen Währung als ihre Entität wird also aus der Währung umgerechnet, in der sie vorliegt. Es gilt die erste Regel, die auf die Zeile passt:

| Zeile | Kurs |
|---|---|
| Statistische und nicht buchende Konten | Nicht umgerechnet. |
| Bereits in der Berichtswährung | Nicht umgerechnet. |
| Konto mit Kurstyp | Dieser Kurs: Durchschnitts-, Stichtags- oder historischer Kurs. Der historische Kurs fällt auf den Stichtagskurs zurück, wenn kein historischer Kurs vorhanden ist. Aus einem ERP ist der Kurstyp der eigene Kurstyp des Kontos. Ordnen Sie in einer Kontenplandatei eine Kurstyp-Spalte `fx_rate_type` mit `average`, `closing` oder `historical` zu. |
| Verkaufsposition | Der Durchschnittskurs der Periode. |
| Lagerbestand | Der Stichtagskurs der Periode. |
| Budgetzeile | Nach Konto, wie beim Hauptbuch: der Durchschnittskurs für GuV-Konten und der Stichtagskurs für Bilanzkonten. |
| GuV-Konto | Der Durchschnittskurs der Periode. |
| Eigenkapitalkonto | Der historische Kurs oder der Stichtagskurs, wenn kein historischer Kurs vorhanden ist. |
| Jedes andere Bilanzkonto | Der Stichtagskurs der Periode. |

Umgerechnete Beträge werden nicht gerundet, sodass sich die Summen nicht verschieben.

<Aside type="note">
Die Saldenliste enthält die Bewegungen jeder Periode, daher sind Bilanzbeträge die Bewegungen jedes Monats, umgerechnet zum Stichtagskurs dieses Monats. Es handelt sich nicht um eine zum Periodenendkurs neu umgerechnete Bilanz, und es gibt weder eine kumulierte Umrechnungsanpassung noch eine Eliminierung konzerninterner Posten. Verwenden Sie die umgerechneten Beträge für die Gewinn- und Verlustrechnung.
</Aside>

## Hierarchien

Jeder Ladevorgang baut sieben Dimensionen aus den Stammdaten jeder Quelle neu auf:

| Dimension | Aufgebaut aus |
|---|---|
| **Entität** | Entitäten und ihren übergeordneten Entitäten |
| **Konto** | Kontenplan und übergeordneten Konten |
| **Abteilung** | Abteilungen und ihren übergeordneten Abteilungen |
| **Kunde** | Kunden und ihren übergeordneten Kunden |
| **Produkt** | Produkten und ihren übergeordneten Produkten |
| **Segment 1** | Segmentwerten für `segment_1` |
| **Segment 2** | Segmentwerten für `segment_2` |

- Ein Datensatz ohne übergeordnetes Element oder einer, der sich selbst als übergeordnetes Element nennt, wird als Member der obersten Ebene geladen.
- Da jeder Ladevorgang die Hierarchien neu aufbaut, ändern Sie ein übergeordnetes Element im ERP oder in Ihrer Datei, nicht in der Dimension.
- Ein Problem in einer Hierarchie betrifft nur diese Dimension. Der Ladevorgang und die Modelle der Vorlage werden trotzdem abgeschlossen.
- Sie können **Segment 1** und **Segment 2** nach dem benennen, was sie enthalten, zum Beispiel **Klasse** und **Standort**.

Um Segmenthierarchien aus einer Datei bereitzustellen, wählen Sie das Dataset **Segmentwerte**:

| Spalte | Enthält |
|---|---|
| `segment` | Zu welchem Segment der Wert gehört: `segment_1` bis `segment_5`. **Segment 1** und **Segment 2** haben Dimensionen. |
| `segment_value` | Den Wert, wie ihn die Hauptbuch-, Verkaufs- und Budgetzeilen führen. |
| `segment_value_name` | Seinen Namen. |
| `parent_segment_value` | Sein übergeordnetes Element innerhalb desselben Segments. |

## Bereitschaftsprüfungen

Nach jedem Ladevorgang listet das Raster **Bereitschaft** jede Prüfung für jede Entität und Periode auf, mit einem der folgenden Status:

| Status | Bedeutung |
|---|---|
| **● Bereit** | Die Prüfung wurde bestanden. |
| **▲ Aufmerksamkeit erforderlich** | Einen Blick wert, aber die Zahlen sind verwendbar. |
| **■ Problem** | Beheben Sie dies, bevor Sie sich auf die Ergebnisse verlassen. |
| **– Nicht zutreffend** | Für diese Prüfung liegen noch keine Daten vor. |

Die Prüfungen sind:

| Prüfung | Was sie bestätigt |
|---|---|
| **Daten geladen** | Jede Geschäftsperiode hat Hauptbuchzeilen, und jeder ERP-Lesezugriff war erfolgreich. Eine abgeschlossene Periode ohne Zeilen ist ein Problem; bei einer offenen Periode ohne Zeilen ist Aufmerksamkeit erforderlich. |
| **Saldenliste stimmt mit Hauptbuch überein** | Die Saldenliste entspricht dem Hauptbuch für jede Entität, Periode und jedes Konto. Wenn sowohl die Saldenliste als auch das Hauptbuch für ein Konto Abteilungen enthalten, wird zusätzlich jede Abteilung abgestimmt. |
| **Umsatz stimmt mit Hauptbuch überein** | Die Verkaufszeilen entsprechen den Hauptbuchkonten für Umsatz und Herstellkosten (COGS) je Periode. |
| **Unbekannte Produkte/Kunden** | Jede Verkaufszeile nennt ein Produkt und einen Kunden, die im Produkt- und im Kundenstamm vorhanden sind. |
| **Konten fehlen im Kontenplan** | Jede Hauptbuchzeile nennt ein Konto im Kontenplan. Zeilen mit unbekanntem Konto werden aus der Gewinn- und Verlustrechnung ausgelassen. |
| **Währungsumrechnung** | Jede Zeile von Hauptbuch, Saldenliste, Umsatz, Lagerbestand und Budget hat einen Betrag in der Berichtswährung. Eine GuV- oder Umsatzzeile ohne Kurs ist ein Problem, weil die Gewinn- und Verlustrechnung umgerechnete Beträge liest. Bei einer Bilanz-, Lagerbestands- oder Budgetzeile ohne Kurs ist Aufmerksamkeit erforderlich. Ein Budgetmonat ohne Kurs wird gelb angezeigt, laden Sie daher Planungskurse für Budgetmonate. Siehe [Währungsumrechnung](#währungsumrechnung). |
| **Nicht zugeordnete Entitäten** | Jede Hauptbuch-, Saldenlisten- und Verkaufszeile nennt eine Entität im Entitätsstamm, direkt oder über die Entitätszuordnung. Nicht zutreffend, bis ein Entitätsstamm geladen ist. Siehe [Entitätszuordnung](#entitätszuordnung). |

Jede Zeile, die nicht bereit ist, nennt in der Spalte **Was zu tun ist**, was zu tun ist, etwa den Kontenplan zu laden, Wechselkurse zu laden oder **Laden** für eine Periode erneut auszuführen.

Das Raster zeigt außerdem zwei Einrichtungsprüfungen, die nur erscheinen, wenn Aufmerksamkeit erforderlich ist:

| Prüfung | Wann sie erscheint |
|---|---|
| **Gemeinkostenumlage** | Nur eine der Projektvariablen `overhead_department` und `overhead_driver` ist gesetzt, oder kein Verteilungstreiber passt zu `overhead_driver`, sodass die Umlage nichts bewirken würde. Setzen Sie beide oder löschen Sie beide, um die Gemeinkostenumlage auszuschalten. |
| **Budgetvergleich** | Budgetzeilen sind geladen, aber keine davon liegt in der Version, die die Projektvariable `budget_version` benennt, sodass der Budgetvergleich leer wäre. |

## Aktuell halten

Nachdem ein Ladevorgang aus Ihrer ERP-Verbindung ohne Probleme erfolgreich war, erscheint auf der Karte **Letzter Ladevorgang** die Option **Nächtlich aktualisieren**. Klicken Sie darauf, um **Laden** jede Nacht um 2:00 Uhr in Ihrer Zeitzone auszuführen. Die Karte zeigt dann **Nightly refresh: Every night at 2:00** und wer die Aktualisierung eingerichtet hat.

Der nächtliche Ladevorgang läuft als die Person, die ihn eingerichtet hat. Kann diese Person die ERP-Verbindung nicht mehr verwenden, meldet das Raster, dass der nächtliche Ladevorgang übersprungen wird; richten Sie ihn erneut ein. Ein Projekt, das nur Beispieldaten enthält, kann nicht geplant werden.

Eine Datei, die bei einem nächtlichen Ladevorgang fehlt oder leer ist, führt zu einer Warnung, die den Pfad nennt, und nicht zu einem Fehler, und der Rest des Modells wird trotzdem geladen.

## Mit einer Vorlage auf dem Modell aufbauen

Eine Vorlage baut ihre Berichte und Modelle auf dem Common Finance Model auf, sodass sie unabhängig davon, welche ERP-Systeme es speisen, gleich funktionieren. Wenn Sie ein Projekt aus einer Vorlage starten, zum Beispiel **Enterprise Profitability**, erstellt sie:

- Die [Tabellen des Common Finance Model](#tabellen-des-common-finance-model), leer oder mit Beispieldaten gefüllt.
- Die Dimensionen **Entität**, **Konto**, **Abteilung**, **Kunde**, **Produkt**, **Segment 1** und **Segment 2**, aufgebaut aus diesen Tabellen. Siehe [Hierarchien](#hierarchien).
- Den Workflow **Laden** und die Workflows, die er ausführt, um Ihr ERP und Ihre Dateien zu lesen, zu überführen, die Bereitschaft zu prüfen und die Modelle der Vorlage aufzubauen.
- Die eigenen Berichte und Modelle der Vorlage. **Enterprise Profitability** ergänzt eine Tabelle der Gewinn- und Verlustrechnung mit Umsatz, Herstellkosten (COGS), Bruttomarge, direkten und Gemeinkosten-Betriebsausgaben, Deckungsbeitrag und Betriebsmarge sowie Margenbrücken im Jahresvergleich und gegenüber dem Budget.
- Kennzahlen und einen Analysepfad, um Fragen zu den Ergebnissen zu stellen.

Um sich umzusehen, bevor Sie Ihr eigenes ERP verbinden, markieren Sie beim Erstellen des Projekts **Mit Beispieldaten starten**. Das Projekt führt sofort einen ersten Ladevorgang aus, sodass die Registerkarte **Foundation** ein vollständiges Beispiel zeigt, einschließlich einer Euro-Entität, die in US-Dollar umgerechnet wird. Wenn Sie Ihr eigenes ERP verbinden oder eigene Dateien hinzufügen, werden die Beispielzeilen gelöscht und Ihre Daten treten an ihre Stelle.

## Die Registerkarte Foundation

Auf der Registerkarte **Foundation** verbinden, laden und prüfen Sie Ihre Daten. Sie hat von oben nach unten folgende Abschnitte:

| Abschnitt | Was er zeigt |
|---|---|
| **Letzter Ladevorgang** | Ob der letzte Ladevorgang erfolgreich war, fehlgeschlagen ist oder noch läuft, mit den Schaltflächen **Laden**, **Aktualisieren** und **Nächtlich aktualisieren**. |
| **Einrichtung** | Die Einrichtungs-Checkliste: **Daten verbinden**, **Daten laden**, **Prüfen, ob die Summen übereinstimmen**, **Hierarchien prüfen** und **Mit Ihrem Team teilen**. Der aktuelle Punkt ist fett dargestellt. |
| **Dateien** | Jede hinzugefügte Datei, ihr Dataset, etwa **Hauptbuch** oder **Wechselkurse**, und ob ihre Zuordnung **✓ Bestätigt** oder **○ Wartet auf Bestätigung** ist. |
| **Daten geladen** | Für jede Entität die erste und die letzte geladene Periode und wie viele Perioden bereit sind. |
| **Perioden** | Die Geschäftsperioden jeder Entität und ob jede **✓ Geschlossen** oder **○ Offen** ist. |
| **Bereitschaft** | Das Bereitschaftsraster: eine Zeile pro Entität, Periode und Prüfung, mit ihrem Status und **Was zu tun ist**. |
| Verbindung | Verbinden Sie Ihr ERP und wählen Sie die Entitäten und wie viele Monate Verlauf geladen werden. |
| **Dateien** (hinzufügen) | Fügen Sie eine CSV-, TSV-, TXT-, Excel- oder Parquet-Datei hinzu und bestätigen Sie, wie ihre Spalten zugeordnet werden. |
| **Laden** | Einen Ladevorgang starten. |

Während ein Ladevorgang läuft, aktualisiert sich die Registerkarte von selbst.

Die Einrichtungs-Checkliste verfolgt Ihren Fortschritt:

- **Daten verbinden** und **Daten laden** werden von selbst abgehakt, sobald eine Quelle angebunden und ein Ladevorgang erfolgreich ist.
- **Prüfen, ob die Summen übereinstimmen** wird von selbst abgehakt, wenn die Abstimmungsprüfungen bestanden sind.
- **Hierarchien prüfen**: Klicken Sie auf **Dimensionen öffnen**, um die Hierarchien Entität, Konto und Abteilung zu prüfen, und markieren Sie dann **Ich habe sie geprüft**. Diesen Punkt bestätigen Sie selbst.
- **Mit Ihrem Team teilen**: Geben Sie das Projekt frei, wenn es bereit ist. Siehe [Projektzugriff verwalten](/de/guides/projects/managing-projects/#projektzugriff-verwalten).

## Tabellen des Common Finance Model

Data Foundation überführt jede Quelle, ERP oder Datei, in dieselben fünfzehn Tabellen, sodass darauf aufbauende Berichte, Kennzahlen und Modelle unabhängig von der Quelle gleich funktionieren. Jede Zeile hält außerdem ihr Quellsystem und den Zeitpunkt des Lesens fest. Die Spalte **Dataset** ist der Name, den Sie beim Hinzufügen einer Datei wählen.

| Dataset | Tabelle | Enthält |
|---|---|---|
| Entitäten | `cfm_entity` | Rechtliche Einheiten mit übergeordneter Einheit, lokaler und Konzernwährung sowie Land. |
| Entitätszuordnung | `cfm_entity_map` | Entitätscodes der Quellen und die Entität, zu der jeder gehört. Siehe [Entitätszuordnung](#entitätszuordnung). |
| Wechselkurse | `cfm_fx_rate` | Monatliche Durchschnitts-, Stichtags- und historische Kurse je Währungspaar. Siehe [Wechselkurse](#wechselkurse). |
| Geschäftskalender | `cfm_fiscal_calendar` | Eine Zeile pro Geschäftsperiode einer Entität, mit Start- und Enddatum und der Angabe, ob sie abgeschlossen ist. |
| Kontenplan | `cfm_account` | Konten mit übergeordnetem Konto, Typ (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), Rechenwerk, normalem Saldo und Kurstyp. |
| Abteilungen | `cfm_department` | Abteilungen und Kostenstellen mit übergeordneter Einheit und Profitcenter. |
| Produkte | `cfm_product` | Produktstamm mit übergeordnetem Produkt, Familie, Gruppe, Mengeneinheit und Standardkosten. |
| Kunden | `cfm_customer` | Kundenstamm mit übergeordnetem Kunden, Gruppe, Region und Land. Kundennamen werden nicht maskiert. |
| Segmentwerte | `cfm_segment` | Segmentwerte mit Name und übergeordnetem Element. Siehe [Hierarchien](#hierarchien). |
| Hauptbuch | `cfm_gl_journal` | Journalzeilen in Transaktions-, lokaler und Berichtswährung. |
| Saldenliste | `cfm_trial_balance` | Soll, Haben und Saldo der Periode je Entität, Konto und Abteilung, in lokaler und Berichtswährung. |
| Verkaufspositionen | `cfm_sales_line` | Fakturierte Verkaufszeilen mit Menge, Brutto-, Rabatt-, Netto- und Herstellkostenbeträgen (COGS). |
| Lagerbestände | `cfm_inventory_balance` | Lagerbestand am Periodenende je Produkt und Lager. |
| Budget | `cfm_budget` | Budget und Forecast je Szenario, Version, Konto und Abteilung. |
| Verteilungstreiber | `cfm_stat_driver` | Statistische Treiber wie Mitarbeiterzahl, Quadratfuß oder Stückzahlen. |

Perioden werden als `YYYY-MM` geschrieben, und Transaktionen werden nach Buchungsperiode zugeordnet. Das Budget ist optional: Ein ERP ohne Budgets lädt trotzdem alles andere.

Eine Saldenlistendatei kann Soll- und Haben-Spalten, eine Saldo-Spalte oder beides enthalten. Mit nur Soll und Haben ergibt sich der Saldo aus Soll minus Haben, wobei eine leere Seite als null zählt. Mit nur einem Saldo wird ein positiver Saldo zum Soll und ein negativer Saldo zum Haben, jeweils als positiver Betrag. Eine Abteilungsspalte ist optional.

## Fehlerbehebung

| Symptom | Was zu tun ist |
|---|---|
| **Verbindung testen** meldet, dass das ERP die Zugangsdaten abgelehnt hat | Prüfen Sie die Zugangsdaten der Verbindung und ob sich der Integrationsbenutzer beim ERP anmelden kann. |
| **Verbindung testen** zeigt für ein Dataset **Fehlende Berechtigung** | Bitten Sie Ihren ERP-Administrator, die genannten Berechtigungen hinzuzufügen. Die [Verbindungsanleitung](/de/guides/connections/) für Ihr ERP listet auf, was die Verbindung benötigt. |
| Eine ERP-Fehlermeldung ist kürzer als die des ERP selbst | PlaidCloud entfernt Zugangsdaten, Tokens und Schlüssel aus Fehlermeldungen des Anbieters, bevor es sie anzeigt, sodass manche Details fehlen. Führen Sie **Verbindung testen** aus, um zu sehen, welches Dataset betroffen ist. |
| **Daten geladen** ist für eine Periode ein Problem | Ein ERP-Lesezugriff für diese Periode ist fehlgeschlagen. Führen Sie **Laden** erneut aus; bereits geladene Perioden werden übersprungen. |
| **Konten fehlen im Kontenplan** ist ein Problem | Fügen Sie die fehlenden Konten im ERP oder in Ihrer Datei zum Kontenplan hinzu und führen Sie **Laden** erneut aus. |
| **Währungsumrechnung** ist ein Problem | Für die Währung einer Entität gibt es für diese Periode keinen Kurs in die Berichtswährung, oder es wurde keine eindeutige Berichtswährung gefunden. Fügen Sie die Kurse in einer Datei **Wechselkurse** hinzu, prüfen Sie, ob die Verbindung die Wechselkurse des ERP lesen kann, oder setzen Sie die Projektvariable `reporting_currency`. Führen Sie dann **Laden** erneut aus. |
| **Währungsumrechnung** erfordert Aufmerksamkeit | Für Bilanz-, Lagerbestands- oder Budgetzeilen gibt es für die Periode keinen Stichtags-, historischen oder Planungskurs. Die Gewinn- und Verlustrechnung ist nicht betroffen. Fügen Sie die Kurse hinzu, einschließlich Planungskursen für Budgetmonate, und führen Sie **Laden** erneut aus. |
| **Nicht zugeordnete Entitäten** ist ein Problem | Fügen Sie die Entität zum Entitätsstamm hinzu oder ordnen Sie ihren Code in der Datei **Entitätszuordnung** einer vorhandenen Entität zu und führen Sie **Laden** erneut aus. |
