Dimensionen in PlaidCloud sind **Hierarchien** – Baumstrukturen, die zum Beispiel Kostenstellen, Produkte, Konten, Geografie oder Zeiträume ordnen. Sie bilden das Gerüst, mit dem Umlagen, Dashboards und Berichte Daten aufteilen und aggregieren.

Eine Dimension kann mehr als nur Eltern-Kind-Beziehungen enthalten. Jeder Knoten kann Eigenschaften, Aliase und Werte tragen – eine Kostenstellenhierarchie kann Ihnen also auch sagen, in welcher Währung jede Kostenstelle berichtet, zu welcher Geschäftseinheit sie in einer alternativen Ansicht aggregiert wird und wie hoch ihr Betriebsbudget ist.

Dimensionen werden auf der Registerkarte **Dimensionen** in jedem Projekt verwaltet.

## Haupthierarchie

Jede Dimension hat eine **Haupt**hierarchie. Die Haupthierarchie definiert die vollständige Menge der Blattmitglieder – jeder Blattknoten irgendwo in der Dimension muss hier vorkommen.

Betrachten Sie die Haupthierarchie als den kanonischen Baum, der die einzige Wahrheit darstellt. Alles in der Dimension ist Mitglied der Haupthierarchie; es geht lediglich darum, *wo* im Baum es sich befindet.

## Alternative (Attribut-)Hierarchien

Alternativhierarchien sind andere Ansichten der Blätter der Haupthierarchie. Sie können eine Teilmenge von Blättern auswählen, sie anders gruppieren oder völlig andere Aggregationen verwenden.

Zwei häufige Muster:

- **Teilmengenansicht** – Ziehen Sie eine bestimmte Menge von Blättern in einen fokussierten Baum für einen bestimmten Bericht oder eine bestimmte Umlage. Die Alternative übernimmt alle Änderungen an ihren Mitgliedern aus der Hauptansicht.
- **Andere Aggregation** – dieselben Blätter, andere Eltern. Beispiel: Die Haupthierarchie ordnet Kostenstellen nach Abteilung; eine Alternative ordnet dieselben Kostenstellen nach Geografie.

## Dimensionen verwalten

<Aside type="caution">
**Eine Dimension, die bestimmt, wer welche Zeilen sieht, kann nur von einem Projekt-Architect geändert werden.** In einem Projekt, das Zeilen mit [Zeilenzugriff](/de/administration/access/managing-security-groups-and-assignments/#gewährungen-für-dimensionen) einschränkt, kann eine Dimension, aus der eine eingeschränkte Spalte ihre Werte bezieht, nur von einem Projekt-Architect, einem Mandantenadministrator oder den eigenen Workflows des Projekts geändert werden – das betrifft das Hinzufügen, Verschieben, Umbenennen, Kopieren, Leeren, Laden oder Wiederherstellen ihrer Knoten sowie das Erstellen, Kopieren, Umbenennen oder Löschen der Dimension selbst. Alle anderen erfahren, wen sie fragen können. Andere Dimensionen und jede Dimension in einem Projekt, das keine Zeilen einschränkt, funktionieren wie unten beschrieben.
</Aside>

### Erstellen

Wählen Sie in der Symbolleiste über die Schaltfläche **Neu** die Option **Neue Dimension**. Geben Sie einen Namen, ein Verzeichnis (für die ordnerartige Organisation) und eine beschreibende Notiz ein.

Klicken Sie auf **Erstellen** – die Dimension steht sofort bereit. Sie können eine Dimension auch in einem Workflow mit dem Schritt [Dimension Create](/de/reference/workflow-steps/dimensions/dimension-create/) erstellen.

### Eine Umlagedimension erstellen

Eine **Umlagedimension** (auch **Zuweisungsdimension** genannt) ist die spezielle Dimension, die ein [Umlage](/de/guides/allocations/setup/configure-an-allocation/)-Schritt liest, um zu entscheiden, wie jeder Quelldatensatz auf seine Ziele verteilt wird. Statt eine Dimension Knoten für Knoten aufzubauen, erstellen Sie mit dem geführten Assistenten in einem Durchgang eine Ausgangsdimension.

Wenn Ihr Workspace die Funktion aktiviert hat und Sie die Berechtigung zum Erstellen von Dimensionen besitzen, öffnen Sie das Menü **Neu** und wählen Sie **Neue Umlagedimension** (mit einem Teilungssymbol gekennzeichnet). Der Assistent öffnet sich beim ersten von vier Schritten:

1. **Name und Tabellen** – Geben Sie der Dimension einen Namen und wählen Sie dann die **Quelltabelle (Werte)**, deren Zeilen Ihre Regeln filtern, und die **Treibertabelle**, anhand der der Betrag verteilt wird.
2. **Regelfilter** – Markieren Sie die Quellspalten, die als Regelfilter dienen. Eine Spalte, die bereits eine Dimensionsbeziehung hat, wird unverändert übernommen; bei einer Spalte ohne Beziehung können Sie eine Dimension zuordnen, damit ihre Werte zu Mitgliedern aufgelöst werden.
3. **Treiber und Ziele** – Legen Sie die Spalten **Treibername** und **Treiberwert** in der Treibertabelle fest und markieren Sie die **Zielspalten**, auf die der Betrag verteilt wird.
4. **Regeln** – Füllen Sie ein flaches Raster mit Regeln. Jede Regel besteht aus einer Menge von Quellfilterwerten und dem benannten Treiber, der für diese Kombination verwendet wird.

Klicken Sie auf **Fertig stellen**, und PlaidCloud erstellt die gesamte Dimension in einem Schritt. Sie erscheint in der Dimensionsstruktur mit einem **Teilungssymbol**, das sie als Umlagedimension und nicht als gewöhnliche Hierarchie kennzeichnet.

Die Dimension wird unabhängig von jeder Umlage erstellt, sodass eine einzige Umlagedimension mehrere Schritte bedienen kann. Um sie zu verwenden, verweisen Sie mit einem Umlageschritt auf sie – siehe [Eine Umlage konfigurieren](/de/guides/allocations/setup/configure-an-allocation/).

### Löschen

Wählen Sie die Dimension aus, öffnen Sie das Menü **Aktionen** und wählen Sie **Dimension löschen**. Dadurch werden die Dimension und alle zugrunde liegenden Daten entfernt.

Sie können auch aus einem Workflow heraus mit dem Schritt [Dimension Delete](/de/reference/workflow-steps/dimensions/dimension-delete/) löschen.

Wenn Sie die Dimension behalten, aber ihren Inhalt zurücksetzen möchten (alle Struktur, Werte, Aliase, Eigenschaften und Alternativhierarchien leeren), verwenden Sie statt des Löschens den Schritt [Dimension Clear](/de/reference/workflow-steps/dimensions/dimension-clear/).

### Kopieren

Wählen Sie die Dimension aus, öffnen Sie **Aktionen** und wählen Sie **Dimension kopieren**. Geben Sie einen Namen für die Kopie an und klicken Sie auf **Kopie erstellen**. Die Kopie enthält Werte, Aliase, Eigenschaften und alle Alternativhierarchien.

### Sortieren

Im Dimensionsverwaltungsbereich können Sie Mitglieder nach oben und unten verschieben und Eltern direkt ändern. Bei großen Hierarchien wird das von Hand mühsam – verwenden Sie den Workflow-Schritt [Dimension Sort](/de/reference/workflow-steps/dimensions/dimension-sort/), um programmgesteuert zu sortieren. Das spart nach Datenladevorgängen oder größeren Umstrukturierungen viel Zeit.

## Dimensionen laden

Eine Dimension zu laden bedeutet, tabellarische Quelldaten in eine hierarchische Struktur umzuwandeln. PlaidCloud unterstützt zwei Datenformen für Ladevorgänge:

- **Eltern-Kind** – Zwei Spalten: eine für das Elternelement, eine für das Kind. Jede Zeile definiert eine Kante im Baum. Das funktioniert für beliebig tiefe, unregelmäßige Hierarchien.
- **Ebenen** – Eine Spalte pro Ebene. Zeile für Zeile gibt jede Spalte das Elternelement auf dieser Ebene an. Am besten geeignet für regelmäßige Hierarchien mit vorhersehbarer Tiefe (z. B. Land → Region → Stadt).

Ladevorgänge können neben der Struktur auch Werte, Aliase und Eigenschaften enthalten. Alle Optionen finden Sie beim Workflow-Schritt [Dimension Load](/de/reference/workflow-steps/dimensions/dimension-load/).

## Knoteneigenschaften

Schalten Sie in der Hierarchie-Symbolleiste **Eigenschaften** ein, um für jede in der Dimension definierte Eigenschaft eine Spalte anzuzeigen – die Währung einer Kostenstelle, die Geschäftseinheit eines Kontos, die Kategorie eines Produkts.

### Eine Eigenschaft hinzufügen oder bearbeiten

1. Klicken Sie in der Symbolleiste auf **Neue Eigenschaft**
2. Geben Sie im Fenster **Eigenschaftskonfiguration** einen **Eigenschaftsnamen** ein, wählen Sie die **Eigenschaftsanzeige** (**Text** oder **Tag**) und einen **Editortyp** – das Steuerelement, das die Eigenschaft für die Dateneingabe verwendet, darunter **Auswahl (Dimension)**, **Auswahl (Fest)**, **Auswahl (Tabelle)**, **Kontrollkästchen**, **Drehfeld**, **Datumsauswahl** und **Numerisch**
3. Wenn der Editortyp weitere Einrichtung erfordert, erscheint ein Abschnitt **Konfiguration** mit einer Schaltfläche **Konfiguration bearbeiten**
4. Klicken Sie zum Speichern auf **Erstellen** (bzw. **Aktualisieren** beim Bearbeiten)

Um die Einrichtung einer vorhandenen Eigenschaft zu ändern, wählen Sie ihre Spalte aus und wählen Sie in der Symbolleiste **Eigenschaftskonfiguration bearbeiten**. **Eigenschaft löschen** entfernt eine Eigenschaft vollständig; **Eigenschaft leeren** leert den ausgewählten Eintrag, und **Alle Einträge für Eigenschaft leeren** leert sie über alle Knoten hinweg.

### Eigenschaften vom Typ Dimension und die Mitgliederauswahl

Wenn Sie den **Editortyp** einer Eigenschaft auf **Auswahl (Dimension)** setzen, wird sie zu einer Nachschlageeigenschaft auf die Hierarchie einer anderen Dimension (oder derselben Dimension) – zum Beispiel eine Eigenschaft „Region“ einer Kostenstelle, die auf eine Dimension Geografie verweist. Ein Klick auf **Konfiguration bearbeiten** öffnet das Fenster **Dimensionskonfiguration**:

- **Dimension** und **Hierarchie** – die Dimension und die Hierarchie, aus der die Eigenschaft Mitglieder auswählt. Wählen Sie bei Hierarchie **Nicht angegeben**, damit die Auswahl jede Hierarchie der Dimension anzeigt.
- **Startknoten (optional)** – beschränken Sie die Auswahl auf einen Teilbaum statt auf die gesamte Hierarchie.
- **Mehrfachauswahl zulassen** – erlaubt es, dass ein einzelner Eigenschaftswert mehr als ein Mitglied enthält. Die Option ist standardmäßig aktiviert; deaktivieren Sie sie, um die Eigenschaft auf ein einzelnes Mitglied zu beschränken.
- **Sonderfälle** – bietet **Quelle** und **Aktuell**, zusätzliche auswählbare Einträge neben den tatsächlichen Mitgliedern der Hierarchie.

**Speichern** erfordert, dass eine Dimension ausgewählt wurde. Die Hierarchie kann auf **Nicht angegeben** bleiben, was eine Auswahl und kein leeres Feld ist.

Sobald eine Eigenschaft so konfiguriert ist, doppelklicken Sie im Raster auf eine ihrer Zellen, um die Mitgliederauswahl zu öffnen – dieselbe baumartige Auswahl erscheint auch bei einer Spalte, die einer Dimension zugeordnet ist, in einem [Dateneditor](/de/guides/projects/managing-data-editors/)-Raster. Sie öffnet sich beim ersten Doppelklick, unabhängig davon, ob die Zelle bereits einen Wert hat.

- **Alle erweitern** / **Alle reduzieren** – öffnet oder schließt jeden Zweig des Baums.
- Klicken Sie auf ein Mitglied (oder, bei aktivierter Mehrfachauswahl, auf mehrere Mitglieder), um es auszuwählen.
- **Übernehmen** setzt die Eigenschaft auf Ihre aktuelle Auswahl.
- **Leeren** entfernt den aktuellen Wert der Eigenschaft.
- **Abbrechen** schließt die Auswahl, ohne etwas zu ändern.

<Aside type="note">Wenn beim Öffnen der Auswahl im Raster mehrere Zeilen ausgewählt sind, setzt **Übernehmen** den Wert in allen ausgewählten Zeilen, nicht nur in der, auf die Sie doppelgeklickt haben – das ist beabsichtigt, um viele Zeilen gleichzeitig zu bearbeiten.</Aside>

## Vererbung von Dimensionseigenschaften

Eine Dimension kann so konfiguriert werden, dass Kinder Eigenschaftswerte von ihren Vorfahren erben. Um dies zu aktivieren, klicken Sie auf die Dropdown-Liste neben **Eigenschaften** und wählen Sie **Geerbte Eigenschaften**.

Hinweise zum Verhalten der Vererbung:

- Die Vererbung gilt für **alle** Eigenschaften der Dimension – Sie können sie nicht für eine Eigenschaft aktivieren und für andere nicht.
- Wenn Sie eine Eigenschaft bei einem Kind setzen und diesen Wert später löschen, kehrt das Kind zum Wert seines Elternelements zurück. Kinder können keine leere Eigenschaft haben, wenn das Elternelement einen Wert hat.
- Das Setzen einer Eigenschaft an einem Knoten wird an seine Nachkommen weitergegeben und überschreibt deren geerbten Wert, bis sie ausdrücklich gesetzt werden.
- Die Vererbung durchläuft den Baum bis hinunter zu den Blattknoten.

## Knoten in einer Hierarchie finden

Eine große Dimension kann Tausende von Mitgliedern umfassen, daher hat das Hierarchiefenster zwei Möglichkeiten, einzugrenzen, was das Raster zeigt. Beide blenden nicht passende Knoten aus, statt sie nur hervorzuheben, und beide lassen die Vorfahren eines passenden Knotens sichtbar, sodass Sie weiterhin sehen, wo er im Baum liegt.

### Das Filterfeld

Das Feld **Filter:** am unteren Rand des Fensters filtert während der Eingabe. Es findet Übereinstimmungen mit jedem Teil des Textes, ohne Beachtung der Groß- und Kleinschreibung, und durchsucht:

- den Namen des Knotens in der Hierarchie und
- jede Spalte **Alternativen**, **Aliase**, **Eigenschaften** und **Werte**, die Sie gerade anzeigen.

Da nur die angezeigten Spalten durchsucht werden, dienen die Umschalter der Symbolleiste zugleich als Suchbereich – schalten Sie **Eigenschaften** ein, um einen Knoten anhand eines Kontocodes zu finden, der in einer seiner Eigenschaften steht, und schalten Sie sie wieder aus, um nur Namen zu durchsuchen. Eine als Tags angezeigte Eigenschaft wird bei jedem einzelnen Tag gefunden.

Die Schaltflächen neben dem Feld legen fest, auf welchen Bereich der Filter angewendet wird: **Beide**, **Haupthierarchie** oder **Alternativhierarchie**. Die Trichter-Schaltfläche löscht den Filter und stellt den vollständigen Baum wieder her.

<Aside type="note">Das Feld Filter durchsucht den auf jedem Knoten gespeicherten Wert. Bei aktivierten **Geerbten Eigenschaften** wird ein Knoten, der einen von einem Vorfahren geerbten Wert anzeigt, über diesen Wert nicht gefunden – nur der Vorfahr, bei dem der Wert tatsächlich gesetzt ist.</Aside>

### Erweiterte Filter

Während das Feld Filter alle angezeigten Spalten gleichzeitig durchsucht, erstellt **Erweitert** in der Hierarchie-Symbolleiste präzise Kriterien pro Spalte. Es öffnet das Fenster **Erweiterte Dimensionsfilter konfigurieren**, in dem jede Zeile ein Kriterium ist:

1. Klicken Sie auf **Zeile hinzufügen**
2. Wählen Sie eine **Spalte** – eine beliebige Eigenschafts- oder Aggregationsspalte der Dimension
3. Wählen Sie eine **Bedingung**. Eine Eigenschaft enthält Text und bietet daher `=`, `!=` und `contains`; eine Aggregation enthält Zahlen und bietet daher `=`, `!=`, `<`, `>`, `<=` und `>=`
4. Geben Sie entweder einen **Wert** zum Vergleichen ein oder wählen Sie unter **Vergleichen mit** eine andere Spalte, um die beiden Spalten miteinander zu vergleichen – das eine oder das andere, nicht beides. **Vergleichen mit** listet die anderen Spalten auf, die dieselbe Art von Wert enthalten, da der Vergleich einer Zahl mit Text in keinem Fall eine Antwort liefert
5. Klicken Sie zum Anwenden auf **Aktualisieren**

**Zeile löschen** entfernt die ausgewählten Zeilen, und **Leeren** leert die gesamte Liste. Fügen Sie mehrere Zeilen hinzu, um weiter einzugrenzen: Ein Knoten muss jede Zeile erfüllen sowie auch den Text im Feld Filter. **Aktualisieren** bleibt deaktiviert, bis jede Zeile vollständig ist, sodass ein halb fertiges Kriterium nie stillschweigend ändert, was Sie sehen.

Erweiterte Kriterien gelten für die Haupthierarchie. Das Feld Filter gilt weiterhin für den Bereich, den die Schaltflächen daneben auswählen.

Textbedingungen ignorieren die Groß- und Kleinschreibung, genau wie das Feld Filter. `=` stimmt mit dem gesamten Wert überein; verwenden Sie daher `contains`, um einen Code zu finden, der in einem längeren Eigenschaftswert oder in einem Tag einer Eigenschaft mit mehreren Tags steht.
