Dimensionen in PlaidCloud sind **Hierarchien** – Baumstrukturen, die zum Beispiel Kostenstellen, Produkte, Konten, Geografie oder Zeiträume ordnen. Sie sind das Gerüst, mit dem Umlagen, Dashboards und Berichte Daten aufteilen und aggregieren.

Eine Dimension kann mehr als nur Eltern-Kind-Beziehungen enthalten. Jeder Knoten kann Eigenschaften, Aliase und Werte tragen – so kann eine Kostenstellenhierarchie auch angeben, in welcher Währung jede Stelle berichtet, zu welcher Geschäftseinheit sie in einer alternativen Ansicht aggregiert wird und wie hoch ihr Betriebsbudget ist.

Dimensionen werden auf der Registerkarte **Dimensionen** in jedem Projekt verwaltet.

## Haupthierarchie

Jede Dimension hat eine **Haupt**hierarchie. Die Haupthierarchie definiert die vollständige Menge der Blattmitglieder – jeder Blattknoten irgendwo in der Dimension muss hier vorkommen.

Betrachten Sie die Haupthierarchie als den kanonischen Baum, der die einzige Wahrheit darstellt. Alles in der Dimension ist ein Mitglied der Haupthierarchie; die Frage ist nur, *wo* im Baum es sich befindet.

## Alternativhierarchien (Attributhierarchien)

Alternativhierarchien sind andere Sichten auf die Blätter der Haupthierarchie. Sie können eine Teilmenge von Blättern auswählen, sie anders gruppieren oder völlig andere Aggregationen verwenden.

Zwei häufige Muster:

- **Teilmengenansicht** – Sie ziehen eine bestimmte Menge von Blättern in einen fokussierten Baum für einen bestimmten Bericht oder eine bestimmte Umlage. Die Alternative übernimmt alle Änderungen an ihren Mitgliedern aus der Haupthierarchie.
- **Andere Aggregation** – dieselben Blätter, andere Eltern. Zum Beispiel: Die Haupthierarchie ordnet Kostenstellen nach Abteilung; eine Alternative ordnet dieselben Kostenstellen nach Geografie.

<Aside>Elemente in der Haupthierarchie tragen Attributbezeichnungen, die zeigen, zu welchen Alternativhierarchien sie ebenfalls gehören.</Aside>

## Dimensionen verwalten

<Aside type="caution">
**Eine Dimension, die entscheidet, wer welche Zeilen sieht, kann nur von einem Projekt-Architect geändert werden.** In einem Projekt, das Zeilen mit [Zeilenzugriff](/de/administration/access/managing-security-groups-and-assignments/#dimensionsgewährungen) einschränkt, kann eine Dimension, aus der eine eingeschränkte Spalte ihre Werte bezieht, nur von einem Projekt-Architect, einem Mandantenadministrator oder den eigenen Workflows des Projekts geändert werden – das umfasst das Hinzufügen, Verschieben, Umbenennen, Kopieren, Leeren, Laden oder Wiederherstellen ihrer Knoten sowie das Erstellen, Kopieren, Umbenennen oder Löschen der Dimension selbst. Allen anderen wird gesagt, wen sie fragen sollen. Andere Dimensionen und jede Dimension in einem Projekt, das keine Zeilen einschränkt, funktionieren wie unten beschrieben.
</Aside>

### Erstellen

Wählen Sie über die Schaltfläche **Neu** in der Symbolleiste **Neue Dimension** aus. Geben Sie einen Namen, ein Verzeichnis (für die ordnerartige Organisation) und eine beschreibende Notiz ein.

Klicken Sie auf **Erstellen** – die Dimension ist sofort bereit. Sie können eine Dimension auch aus einem Workflow mit dem [Dimension Create](/de/reference/workflow-steps/dimensions/dimension-create/)-Schritt erstellen.

### Eine Umlagedimension erstellen

Eine **Umlagedimension** (auch **Zuweisungsdimension** genannt) ist die spezielle Dimension, die ein [Umlage](/de/guides/allocations/setup/configure-an-allocation/)-Schritt liest, um zu entscheiden, wie jeder Quelldatensatz auf seine Ziele verteilt wird. Anstatt eine solche Dimension Knoten für Knoten aufzubauen, erstellen Sie mit dem geführten Assistenten in einem Durchgang eine Ausgangsdimension.

Wenn für Ihren Workspace die Funktion aktiviert ist und Sie die Berechtigung zum Erstellen von Dimensionen haben, öffnen Sie das Menü **Neu** und wählen Sie **Neue Umlagedimension** (mit einem Symbol für Verzweigung gekennzeichnet). Der Assistent öffnet sich beim ersten von vier Schritten:

1. **Name and tables** – Geben Sie der Dimension einen Namen und wählen Sie dann die **Quelltabelle (Werte)**, deren Zeilen Ihre Regeln filtern, und die **Treibertabelle**, anhand derer der Betrag verteilt wird.
2. **Rule filters** – Aktivieren Sie die Quellspalten, die als Regelfilter dienen. Eine Spalte, die bereits eine Dimensionsbeziehung hat, wird unverändert übernommen; bei einer, die keine hat, können Sie eine Dimension zuordnen, damit ihre Werte zu Mitgliedern aufgelöst werden.
3. **Driver and targets** – Bestimmen Sie in der Treibertabelle die Spalten für **Treibername** und **Treiberwert** und aktivieren Sie die **Zielspalten**, auf die der Betrag verteilt wird.
4. **Rules** – Füllen Sie ein flaches Raster von Regeln aus. Jede Regel ist eine Menge von Quellfilterwerten plus der benannte Treiber, der für diese Kombination verwendet wird.

Klicken Sie auf **Finish**, und PlaidCloud erstellt die gesamte Dimension in einem Schritt. Sie erscheint im Dimensionsbaum mit einem **Symbol für Verzweigung** und ist damit als Umlagedimension statt als gewöhnliche Hierarchie gekennzeichnet.

Die Dimension wird unabhängig von jeder Umlage erstellt, sodass eine einzige Umlagedimension mehrere Schritte bedienen kann. Um sie zu verwenden, verweisen Sie einen Umlageschritt auf sie – siehe [Eine Umlage konfigurieren](/de/guides/allocations/setup/configure-an-allocation/).

### Löschen

Wählen Sie die Dimension aus, öffnen Sie das Menü **Aktionen** und wählen Sie **Dimension löschen**. Dadurch werden die Dimension und alle zugrunde liegenden Daten entfernt.

Sie können auch aus einem Workflow mit dem [Dimension Delete](/de/reference/workflow-steps/dimensions/dimension-delete/)-Schritt löschen.

Wenn Sie die Dimension behalten, aber ihren Inhalt zurücksetzen möchten (alle Struktur, Werte, Aliase, Eigenschaften und Alternativhierarchien leeren), verwenden Sie den [Dimension Clear](/de/reference/workflow-steps/dimensions/dimension-clear/)-Schritt anstelle des Löschens.

### Kopieren

Wählen Sie die Dimension aus, öffnen Sie **Aktionen** und wählen Sie **Dimension kopieren**. Geben Sie einen Namen für die Kopie an und klicken Sie auf **Kopie erstellen**. Die Kopie enthält Werte, Aliase, Eigenschaften und alle Alternativhierarchien.

### Sortieren

Im Verwaltungsbereich der Dimension können Sie Mitglieder nach oben und unten verschieben und Eltern direkt ändern. Bei großen Hierarchien wird das von Hand mühsam – verwenden Sie den [Dimension Sort](/de/reference/workflow-steps/dimensions/dimension-sort/)-Schritt, um programmgesteuert zu sortieren. Das spart nach Datenladevorgängen oder größeren Umstrukturierungen viel Zeit.

## Dimensionen laden

Das Laden einer Dimension bedeutet, tabellarische Quelldaten in eine hierarchische Struktur umzuwandeln. PlaidCloud unterstützt zwei Datenformen für Ladevorgänge:

- **Eltern-Kind** – Zwei Spalten: eine für den Eltern-, eine für den Kindknoten. Jede Zeile definiert eine Kante im Baum. Das funktioniert für beliebig tiefe, unregelmäßige Hierarchien.
- **Ebenen** – Eine Spalte pro Ebene. Zeile für Zeile gibt jede Spalte den Elternknoten auf dieser Ebene an. Am besten für regelmäßige Hierarchien mit vorhersehbarer Tiefe (z. B. Land → Region → Stadt).

Ladevorgänge können neben der Struktur auch Werte, Aliase und Eigenschaften enthalten. Alle Optionen finden Sie beim [Dimension Load](/de/reference/workflow-steps/dimensions/dimension-load/)-Schritt.

## Knoteneigenschaften

Schalten Sie in der Symbolleiste der Hierarchie **Eigenschaften** ein, um für jede in der Dimension definierte Eigenschaft eine Spalte anzuzeigen – die Währung einer Kostenstelle, die Geschäftseinheit eines Kontos, die Kategorie eines Produkts.

### Eine Eigenschaft hinzufügen oder bearbeiten

1. Klicken Sie in der Symbolleiste auf **Neue Eigenschaft**.
2. Geben Sie im Fenster **Eigenschaftskonfiguration** einen **Eigenschaftsnamen** ein, wählen Sie die **Eigenschaftsanzeige** (**Text** oder **Tag**) und einen **Editortyp** – das Steuerelement, das die Eigenschaft für die Dateneingabe verwendet, darunter **Auswahl (Dimension)**, **Auswahl (Fest)**, **Auswahl (Tabelle)**, **Kontrollkästchen**, **Drehfeld**, **Datumsauswahl** und **Numerisch**.
3. Wenn der Editortyp weitere Einrichtung benötigt, erscheint ein Bereich **Konfiguration** mit einer Schaltfläche **Konfiguration bearbeiten**.
4. Klicken Sie zum Speichern auf **Erstellen** (oder beim Bearbeiten auf **Aktualisieren**).

Um die Einrichtung einer vorhandenen Eigenschaft zu ändern, wählen Sie ihre Spalte aus und wählen Sie in der Symbolleiste **Eigenschaftskonfiguration bearbeiten**. **Eigenschaft löschen** entfernt eine Eigenschaft vollständig; **Eigenschaft leeren** leert den ausgewählten Eintrag, und **Alle Einträge für Eigenschaft leeren** leert ihn über alle Knoten hinweg.

### Eigenschaften vom Typ Dimension und die Mitgliederauswahl

Wenn Sie den **Editortyp** einer Eigenschaft auf **Auswahl (Dimension)** setzen, wird sie zu einem Nachschlagen in der Hierarchie einer anderen Dimension (oder derselben Dimension) – zum Beispiel die Eigenschaft „Region“ einer Kostenstelle, die auf eine Dimension Geografie verweist. Ein Klick auf **Konfiguration bearbeiten** öffnet das Fenster **Dimensionskonfiguration**:

- **Dimension** und **Hierarchie** – die Dimension und die Hierarchie, aus der die Eigenschaft Mitglieder auswählt. Wählen Sie bei Hierarchie **Nicht angegeben**, damit die Auswahl jede Hierarchie der Dimension zeigt.
- **Startknoten (optional)** – beschränkt die Auswahl auf einen Teilbaum statt auf die gesamte Hierarchie.
- **Mehrfachauswahl zulassen** – lässt einen einzelnen Eigenschaftswert mehr als ein Mitglied enthalten. Standardmäßig ist es aktiviert; deaktivieren Sie es, um die Eigenschaft auf ein einzelnes Mitglied zu beschränken.
- **Sonderfälle** – bietet **Quelle** und **Aktuell**, zusätzliche auswählbare Einträge neben den tatsächlichen Mitgliedern der Hierarchie.

**Speichern** erfordert, dass eine Dimension ausgewählt ist. Die Hierarchie kann auf **Nicht angegeben** bleiben, was eine Auswahl und kein leerer Wert ist.

Sobald eine Eigenschaft auf diese Weise konfiguriert ist, doppelklicken Sie im Raster auf eine ihrer Zellen, um die Mitgliederauswahl zu öffnen – dieselbe baumartige Auswahl erscheint auch für eine Dimensionen zugeordnete Spalte in einem Raster des [Dateneditors](/de/guides/projects/managing-data-editors/). Sie öffnet sich beim ersten Doppelklick, unabhängig davon, ob die Zelle bereits einen Wert hat.

- **Alle erweitern** / **Alle reduzieren** – öffnet oder schließt jeden Zweig des Baums.
- Klicken Sie auf ein Mitglied (oder, bei aktivierter Mehrfachauswahl, auf mehrere Mitglieder), um es auszuwählen.
- **Übernehmen** setzt die Eigenschaft auf Ihre aktuelle Auswahl.
- **Leeren** entfernt den aktuellen Wert der Eigenschaft.
- **Abbrechen** schließt die Auswahl, ohne etwas zu ändern.

<Aside type="note">Wenn beim Öffnen der Auswahl mehrere Zeilen im Raster ausgewählt sind, setzt **Übernehmen** den Wert in allen ausgewählten Zeilen, nicht nur in der, auf die Sie doppelgeklickt haben – das ist beabsichtigt, um viele Zeilen auf einmal zu bearbeiten.</Aside>

## Vererbung von Dimensionseigenschaften

Eine Dimension kann so konfiguriert werden, dass untergeordnete Knoten Eigenschaftswerte von ihren Vorfahren erben. Um dies zu aktivieren, klicken Sie auf das Dropdown neben **Eigenschaften** und wählen Sie **Geerbte Eigenschaften**.

Hinweise zum Verhalten der Vererbung:

- Die Vererbung gilt für **alle** Eigenschaften der Dimension – Sie können sie nicht für eine Eigenschaft aktivieren und für andere nicht.
- Wenn Sie eine Eigenschaft an einem untergeordneten Knoten setzen und diesen Wert später löschen, kehrt der Knoten zum Wert seines Elternknotens zurück. Untergeordnete Knoten können keine leere Eigenschaft haben, wenn der Elternknoten einen Wert hat.
- Das Setzen einer Eigenschaft an einem Knoten wirkt sich auf seine Nachfahren aus und überschreibt deren geerbten Wert, bis sie ausdrücklich gesetzt werden.
- Die Vererbung läuft den Baum bis zu den Blattknoten hinunter.

## Knoten in einer Hierarchie finden

Eine große Dimension kann Tausende von Mitgliedern umfassen, daher bietet das Hierarchiefenster zwei Möglichkeiten, einzugrenzen, was das Raster zeigt. Beide blenden nicht passende Knoten aus, anstatt sie nur hervorzuheben, und beide lassen die Vorfahren eines passenden Knotens sichtbar, damit Sie weiterhin sehen, wo er im Baum sitzt.

### Das Filterfeld

Das Feld **Filter** am unteren Rand des Hauptbereichs filtert während der Eingabe. Drücken Sie **/** oder Strg/Cmd+F, um dorthin zu springen. Es sucht in beliebigen Teilen des Textes ohne Beachtung der Groß- und Kleinschreibung und durchsucht:

- den Namen des Knotens in der Hierarchie und
- jede Spalte **Alternativen**, **Aliase**, **Eigenschaften** und **Werte**, die Sie aktuell anzeigen.

Da nur die Spalten auf dem Bildschirm durchsucht werden, bestimmen die Spaltenoptionen im Menü **Ansicht** zugleich den Suchumfang – schalten Sie **Eigenschaften** ein, um einen Knoten über einen in einer seiner Eigenschaften gespeicherten Kontocode zu finden, und schalten Sie sie wieder aus, um nur Namen zu durchsuchen. Eine Eigenschaft, die als Tags angezeigt wird, findet bei jedem einzelnen Tag eine Übereinstimmung.

Der Umschalter **Main | Both | Alternate** neben dem Feld legt fest, auf welchen Baum sich der Filter bezieht. Er ist ausgeblendet, wenn der Bereich für Alternativen ausgeblendet ist; zeigen Sie den Bereich mit **Alternativhierarchie anzeigen** im Menü **Ansicht** an. Die Trichter-Schaltfläche löscht den Filter und stellt den vollständigen Baum wieder her.

<Aside type="note">Das Filterfeld durchsucht den an jedem Knoten gespeicherten Wert. Wenn **Geerbte Eigenschaften** eingeschaltet ist, wird ein Knoten, der einen von einem Vorfahren geerbten Wert anzeigt, von diesem Wert nicht gefunden – nur der Vorfahr, an dem der Wert tatsächlich gesetzt ist.</Aside>

### Erweiterte Filter

Während das Filterfeld alle angezeigten Spalten gleichzeitig durchsucht, erstellt **Erweitert** in der Symbolleiste der Hierarchie präzise Kriterien pro Spalte. Es öffnet das Fenster **Erweiterte Dimensionsfilter konfigurieren**, in dem jede Zeile ein Kriterium ist:

1. Klicken Sie auf **Zeile hinzufügen**.
2. Wählen Sie eine **Spalte** – eine beliebige Eigenschaft oder Aggregationsspalte der Dimension.
3. Wählen Sie eine **Bedingung**. Eine Eigenschaft enthält Text und bietet daher `=`, `!=` und `contains`; eine Aggregation enthält Zahlen und bietet daher `=`, `!=`, `<`, `>`, `<=` und `>=`.
4. Geben Sie entweder einen **Wert** zum Vergleichen ein oder wählen Sie unter **Vergleichen mit** eine andere Spalte, um die beiden Spalten miteinander zu vergleichen – das eine oder das andere, nicht beides. **Vergleichen mit** listet die anderen Spalten auf, die dieselbe Art von Wert enthalten, da der Vergleich einer Zahl mit Text in keinem Fall etwas ergibt.
5. Klicken Sie auf **Aktualisieren**, um den Filter anzuwenden.

**Zeile löschen** entfernt die ausgewählten Zeilen, und **Leeren** leert die gesamte Liste. Fügen Sie mehrere Zeilen hinzu, um weiter einzugrenzen: Ein Knoten muss jede Zeile erfüllen, und auch den Text im Filterfeld. **Aktualisieren** bleibt deaktiviert, bis jede Zeile vollständig ist, sodass ein halb fertiges Kriterium nie stillschweigend ändert, was Sie sehen.

Erweiterte Kriterien gelten für die Haupthierarchie. Das Filterfeld gilt weiterhin für den Bereich, den die Schaltflächen daneben auswählen.

Textbedingungen ignorieren die Groß- und Kleinschreibung, ebenso wie das Filterfeld. `=` stimmt mit dem gesamten Wert überein; verwenden Sie daher `contains`, um einen Code zu finden, der in einem längeren Eigenschaftswert oder in einem Tag einer Eigenschaft mit mehreren Tags steht.
