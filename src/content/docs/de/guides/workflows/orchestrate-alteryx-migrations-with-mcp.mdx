Der MCP-Server von PlaidCloud ermöglicht es einem KI-Agenten, eine Migration über viele Alteryx-Workflows hinweg zu koordinieren. Der Agent kann helfen, Dateien in Document bereitzustellen und zu organisieren, Workflow-Pakete zu inventarisieren, den Alteryx-Konverter aufzurufen, erzeugte Workflows zu organisieren, Validierungs-Workflows auszuführen und den Fortschritt für das Migrationsteam zusammenzufassen.

<Aside type="note">
  MCP eignet sich ideal für die Koordination im Portfolio-Maßstab. Die Konvertierung selbst übernimmt weiterhin der PlaidCloud-Importer; der Agent hilft, die Arbeit zu planen, zu sequenzieren, auszuführen und zusammenzufassen.
</Aside>

## Wann MCP verwenden

Verwenden Sie die MCP-Orchestrierung, wenn Sie viele Workflows migrieren oder wenn ein KI-Agent bei wiederholbaren Migrationsaufgaben helfen soll:

- Alteryx-Dateien inventarisieren, die in Document bereitgestellt sind.
- Migrationsdateien über Document-Tools hochladen, kopieren, verschieben, umbenennen und organisieren.
- Mit einem verbundenen gemeinsamen Speicherkonto arbeiten, etwa OneDrive, Google Drive, SharePoint, S3, Azure Blob oder SFTP.
- Workflows, Apps und Makros zu Migrationsbatches gruppieren.
- Jede Datei `.yxmd`, `.yxwz` oder `.yxmc` in PlaidCloud konvertieren.
- Konvertierungsergebnisse im gesamten Portfolio nachverfolgen.
- Konvertierte Workflows oder Validierungs-Workflows ausführen.
- Eine Migrationszusammenfassung zur Prüfung erstellen.

Für einen einzelnen Workflow ist das Importformular oft der schnellste Weg. Für ein Portfolio gibt MCP dem Agenten eine strukturierte Möglichkeit, dieselben PlaidCloud-Funktionen wiederholt zu koordinieren.

## Was der Agent aufrufen kann

Der MCP-Tool-Katalog enthält ein Alteryx-Konvertierungstool namens `alteryx_convert`. Es erstellt PlaidCloud-Workflows aus Alteryx-Dateien, die in Document gespeichert sind.

Der Konvertierungsaufruf enthält:

- Quell-Dokumentenkonto und Pfad der Alteryx-Datei.
- Ziel-Projekt in PlaidCloud.
- Ziel-Dokumentenkonto und Pfad für Konvertierungsartefakte.
- Optionale Präfixe für Workflows, Schritte und Tabellen. Das Tabellenpräfix ist standardmäßig der eigene Name des Workflows; dadurch kommen sich zwei Konvertierungen in einem Projekt bei den Tabellen nicht ins Gehege. Übergeben Sie ein leeres Präfix, um die reinen Namen zu erhalten.
- Workflow-Typ, standardmäßig erweiterte Workflows.

Der Agent kann dies mit den üblichen MCP-Tools für Projekte, Workflows, Document, Workflow-Ausführungen und Tabellen kombinieren, um die gesamte Migration zu steuern.

## Dateien mit dem Agenten vorbereiten

Ein über MCP verbundener Agent kann bei der Dateivorbereitung rund um die Konvertierung helfen:

- Dateien `.yxmd`, `.yxwz` und `.yxmc` in Document finden.
- Wahrscheinliche Eingabedateien, Makrodateien, Berichtsressourcen, räumliche Begleitdateien und erwartete Ausgaben identifizieren.
- Eine saubere Ordnerstruktur für die Migration anlegen.
- Dateien in diese Struktur kopieren, verschieben oder umbenennen.
- Zusammengehörige Workflow-, Makro-, Daten-, räumliche, Berichts- und Validierungsdateien zusammenhalten.
- Das Paket vor der Konvertierung zusammenfassen.

Das ist nützlich, wenn ein Migrationspaket viele Ordner enthält oder Teams vor Beginn der Konvertierung ein wiederholbares Inventar vom Agenten erstellen lassen möchten.

## Gemeinsamen Speicher ohne Hochladen nutzen

Sie müssen Dateien vor der Migration nicht in einen neuen, von PlaidCloud verwalteten Ordner hochladen. PlaidCloud Document kann sich direkt mit gemeinsamem Speicher verbinden, der das Alteryx-Migrationspaket bereits enthält.

Gängige Optionen sind:

- [Google Drive](/de/guides/documents/adding-accounts/add-google-drive-account/)
- [OneDrive oder SharePoint](/de/guides/documents/adding-accounts/add-onedrive-account/)
- [AWS S3](/de/guides/documents/adding-accounts/add-aws-s3-account/)
- [Azure Blob Storage](/de/guides/documents/adding-accounts/add-azure-blob-storage-account/)
- [SFTP](/de/guides/documents/adding-accounts/add-sftp-account/)

Nachdem das Dokumentenkonto verbunden ist, kann der Agent mit diesem Dokumentenkonto und Pfad arbeiten. So bleibt die Migration nah am vorhandenen gemeinsamen Speicher des Kunden, und ein separater Upload-Schritt kann entfallen.

## Dateien in Document bereitstellen oder auswählen

Bevor Sie einen Agenten bitten, die Migration zu orchestrieren, wählen Sie einen dieser Wege:

- Einen vorhandenen gemeinsamen Speicherort als Dokumentenkonto verbinden.
- Workflow-Pakete in ein Dokumentenkonto hochladen.
- Den Agenten bitten, Dateien zu organisieren, die bereits in Document verfügbar sind.

Bestätigen Sie dann:

1. Workflows, Apps, Makros, Eingabedateien, räumliche Begleitdateien, Berichte und erwartete Ausgaben sind über Document verfügbar.
2. Das Zielprojekt ist ausgewählt.
3. Der Document-Pfad für Abhängigkeiten und Artefakte der konvertierten Workflows ist ausgewählt.
4. Der Agent hat die Berechtigung, die relevanten MCP-Tools für Document und Workflows zu verwenden.

Der Agent kann dann beim Aufruf des Konverters stabile Document-Pfade verwenden.

## Vorgeschlagener Agent-Prompt

Verwenden Sie mit einem über MCP verbundenen Agenten einen Prompt wie diesen:

```text
In PlaidCloud, migrate the Alteryx workflows in the connected Document account
"Migration Share" under /q4-alteryx-package into the project "Q4 Migration".

First inventory the .yxmd, .yxwz, and .yxmc files. Organize the package by
workflow, macro, input, spatial, report, and expected-output files. Group macros
with the workflows that call them. Then convert the workflows as Advanced
workflows using the Document output path /q4-alteryx-converted. Prefix created
workflows with "Q4 - ". After each conversion, summarize the generated workflow,
macros, readiness notes, and next validation step. Ask before making mutating calls.
```

Passen Sie Projektnamen, Quellpfad, Zielpfad und Präfix an Ihren Migrationsbatch an.

## Empfohlener Orchestrierungsablauf

Bitten Sie den Agenten bei Portfolio-Migrationen, diesen Ablauf einzuhalten:

1. Das Dokumentenkonto verbinden oder auswählen, das das Migrationspaket enthält.
2. Den Quell-Document-Ordner inventarisieren.
3. Dateien `.yxmd`, `.yxwz` und `.yxmc` identifizieren.
4. Dateien in Gruppen für Workflow, Makro, Eingabe, räumlich, Bericht und erwartete Ausgabe organisieren.
5. Zusammengehörige Workflows und Makros gruppieren.
6. Zielprojekt und Document-Ausgabepfad bestätigen.
7. Makros und Workflows in erweiterte Workflows konvertieren.
8. Die erzeugten Workflows öffnen oder beschreiben.
9. Strukturelle Validierung ausführen.
10. Validierung der Ausgabeparität ausführen, wo erwartete Ausgaben verfügbar sind.
11. Konvertierte Workflows, erzeugte Makros, Artefakte und den Validierungsstatus zusammenfassen.

So erhält das Migrationsteam einen Fortschrittsbericht über das gesamte Portfolio und nutzt dennoch für jede Konvertierung den nativen Importer von PlaidCloud.

## Verändernde Aufrufe prüfen

Die meisten MCP-Clients zeigen Tool-Aufrufe an, bevor sie ausgeführt werden. Prüfen Sie Konvertierungs- und Workflow-Ausführungsaufrufe vor der Freigabe, besonders in Produktionsprojekten.

Verwenden Sie für Staging-Migrationen ein eigenes Migrationsprojekt und einen eigenen Document-Ordner. Übernehmen Sie die konvertierten Workflows nach der Validierung in das Produktionsprojekt.

## Ergebnisse nachverfolgen

Bitten Sie den Agenten, eine Migrationstabelle zu erstellen mit:

- Alteryx-Quelldatei.
- Erzeugtem PlaidCloud-Workflow.
- Erzeugten Makro-Workflows.
- Konvertierungsstatus.
- Validierungsstufe.
- Document-Ausgabepfad.
- Hinweisen für die Nachverfolgung.

Diese Zusammenfassung ist nützlich für die Projektberichterstattung, die Übergabe und die Prüfung der Produktionsbereitschaft.
