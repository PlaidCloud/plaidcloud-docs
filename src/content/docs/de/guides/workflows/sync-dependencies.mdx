In einem erweiterten Workflow bestimmen die Konnektoren auf der Arbeitsfläche die Reihenfolge, in der Schritte ausgeführt werden. Ein Schritt, der eine Tabelle liest, sollte nach dem Schritt ausgeführt werden, der sie schreibt, doch nichts zwingt Sie, diesen Konnektor zu zeichnen. Ohne ihn können die beiden Schritte gleichzeitig laufen, und der zweite Schritt liest die Tabelle möglicherweise, bevor der erste sie fertig geschrieben hat. Das kommt häufig in Workflows vor, die konvertiert, kopiert oder aus anderen Workflows zusammengestellt wurden.

**Abhängigkeiten synchronisieren** findet diese Schritte, indem es liest, welche Tabellen jeder Schritt liest und schreibt, und schlägt die Konnektoren vor, die sie in die richtige Reihenfolge bringen. Sie prüfen jeden Vorschlag, und nichts ändert sich, bis Sie **Verbindungen hinzufügen** wählen.

Abhängigkeiten synchronisieren fügt nur Konnektoren hinzu. Es entfernt oder verschiebt nie einen Konnektor und ändert nie einen Schritt.

## Die vorgeschlagenen Konnektoren prüfen

1. Öffnen Sie den Workflow auf der [Arbeitsfläche für erweiterte Workflows](/de/guides/workflows/advanced-workflows/).
2. Wählen Sie in der Symbolleiste neben **Prüfen** die Option **Abhängigkeiten synchronisieren**. Hat Weave bereits Vorschläge, weist ein Banner unter der Symbolleiste darauf hin, zum Beispiel *Weave schlägt 3 Konnektoren vor, damit jeder Schritt nach dem Schritt ausgeführt wird, der eine von ihm gelesene Tabelle schreibt.* Wählen Sie im Banner **Prüfen…**, um dasselbe Fenster zu öffnen.
3. Das Fenster **Abhängigkeiten synchronisieren** listet pro Zeile einen Vorschlag auf, etwa *„Load Sales“ vor „Report“ ausführen, der „sales“ liest*. Jede Zeile hat ein Kontrollkästchen.
4. Aktivieren Sie die gewünschten Konnektoren und deaktivieren Sie die, die Sie nicht möchten.
5. Wählen Sie **Verbindungen hinzufügen**.

Die Konnektoren erscheinen sofort auf der Arbeitsfläche. **Rückgängig** entfernt sie alle in einem Schritt, und **Wiederholen** stellt sie wieder her.

Die Schaltfläche **Abhängigkeiten synchronisieren** sehen Sie, wenn Sie den Workflow bearbeiten und seine Tabellen lesen können.

## Welche Vorschläge aktiviert sind

Ein Vorschlag ist aktiviert, wenn beide Schritte **Tabelle: Extrahieren**, **Tabelle: Kopieren**, **Tabelle: Melt (Spalten in Zeilen)**, **Tabelle: Pivot (Zeilen in Spalten)** oder **Tabelle: Merkmale erstellen** sind. Diese lesen eine Tabelle und ersetzen bei jeder Ausführung ihr Ziel, sodass die Reihenfolge eindeutig ist.

Jeder andere Vorschlag wird aufgelistet, aber nicht aktiviert. Dabei handelt es sich um einen Schritt, der anfügt (**Tabelle: Anfügen**), importiert, verknüpft oder nachschlägt, oder der mehrere Tabellen liest, etwa **SQL extrahieren**. Aktivieren Sie einen solchen Vorschlag, wenn dieser Schritt auf den anderen warten soll.

<Aside type="tip">Lesen Sie jede Zeile, bevor Sie sie hinzufügen. Manchmal soll ein Schritt lesen, was ein anderer Schritt bei der *vorherigen* Ausführung geschrieben hat. Lassen Sie diesen Vorschlag deaktiviert.</Aside>

## Was das Fenster Ihnen außerdem mitteilt

- **Schritte, die bereits in der falschen Reihenfolge stehen.** Wenn ein Konnektor bereits dafür sorgt, dass ein Schritt *vor* dem Schritt läuft, der eine von ihm gelesene Tabelle schreibt, nennt das Fenster die Anzahl. Abhängigkeiten synchronisieren ordnet keine Schritte um; prüfen Sie diese Konnektoren auf der Arbeitsfläche.
- **Schritte, die Sie nicht öffnen können.** Ein Vorschlag, der einen Schritt betrifft, den Ihre Rolle ausblendet, wird gezählt, aber nicht aufgelistet.
- **Ein Workflow, den Weave nicht prüfen kann.** Führt ein Schritt einen anderen Workflow aus, verwendet er Tabellen, denen Weave nicht folgen kann, oder bilden die Konnektoren eine Schleife, teilt das Fenster mit, dass Weave die Schrittreihenfolge des Workflows nicht prüfen kann, und schlägt nichts vor.
- **Nichts hinzuzufügen.** Wenn bereits jeder Schritt nach den Schritten läuft, die die von ihm gelesenen Tabellen schreiben, teilt das Fenster das mit.

## Was Weave nicht prüft

Weave schlägt nur dann einen Konnektor vor, wenn die Reihenfolge sicher ist. Folgendes beurteilt es nicht:

- Eine Tabelle, die von mehr als einem Schritt im Workflow oder auch von einem anderen Workflow geschrieben wird, da ein Schritt möglicherweise die Ausgabe des anderen Workflows lesen soll. Ein Schritt, der eine Tabelle sowohl liest als auch schreibt, die ein anderer Schritt ebenfalls schreibt, zählt genauso.
- Eine Tabelle, die ein Schritt per Variable auswählt, ein Name, den mehrere Tabellen teilen, eine Ansicht oder eine Tabelle aus einem anderen Projekt.
- Eine Tabelle, die ein Schritt im Workflow leert, aus der er Zeilen löscht oder die er verwirft, da das Leeren einer Tabelle vor dem Laden eine bewusste Reihenfolge ist.
- Schritte innerhalb eines [Ausführungscontainers](/de/guides/workflows/advanced-workflows/#ausführungscontainer).
- Deaktivierte Schritte und Schritte in einem deaktivierten Container. Ein Konnektorpfad durch einen deaktivierten Schritt zählt weiterhin, weil der Workflow direkt durch ihn hindurchläuft.

Weave prüft die Reihenfolge, in der Schritte ausgeführt werden, nicht die Daten, die sie erzeugen.

## Wenn sich der Workflow während Ihrer Prüfung ändert

Ändert jemand den Workflow, während das Fenster geöffnet ist, oder trifft ein Vorschlag nicht mehr zu, erscheint beim Wählen von **Verbindungen hinzufügen** der Hinweis **Workflow geändert**, und die Arbeitsfläche wird neu geladen. Wählen Sie erneut **Abhängigkeiten synchronisieren**, um zu sehen, was Weave jetzt vorschlägt.

Entsperren Sie einen gesperrten Workflow, bevor Sie Konnektoren hinzufügen oder rückgängig machen.

## Weave findet diese von selbst

Sie müssen die Arbeitsfläche nicht öffnen, um diese Schritte zu finden. Weave prüft jeden erweiterten Workflow im Hintergrund, auch solche, die nie ausgeführt wurden, und meldet **Steps that can run before the table they read is written** auf der Registerkarte **Weave**. Fehlt ein Konnektor, öffnet **Beheben** bei diesem Befund dieses Fenster auf der Arbeitsfläche des Workflows. Siehe [Weave-Befunde](/de/guides/ai-assistant/weave-findings/#was-weave-heute-prüft).
