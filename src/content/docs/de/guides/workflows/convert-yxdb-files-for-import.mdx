Alteryx schreibt `.yxdb`-Dateien in zwei Formaten. Das klassische Format (von der ursprünglichen Engine geschrieben) ist gut dokumentiert, und PlaidCloud importiert es direkt. Die AMP-Engine schreibt eine neuere Variante – der Dateikopf lautet `Alteryx e2 Database file` –, deren Spezifikation proprietär und unveröffentlicht ist, sodass kein Werkzeug außerhalb von Alteryx sie lesen kann, auch PlaidCloud nicht.

Während einer Migration steht Ihnen noch lizenziertes Alteryx Designer zur Verfügung, und Designer liest beide Formate. Nutzen Sie es einmal, bevor Sie es außer Betrieb nehmen, um Dateien im AMP-Format in ein portables Format umzuschreiben.

<Aside type="note">
  Klassische `.yxdb`-Dateien lassen sich direkt in PlaidCloud importieren – eine Konvertierung ist nicht nötig. Wenn ein Import bei einer `.yxdb` mit einem Fehler wegen nicht lesbarer Datei fehlschlägt, ist eine Datei im AMP-Format die wahrscheinlichste Ursache.
</Aside>

## Dateien im AMP-Format erkennen

- Der Workflow, der die Datei erzeugt hat, lief mit aktivierter AMP-Engine.
- PlaidCloud meldet die Datei beim Import als nicht lesbar, während andere `.yxdb`-Dateien aus demselben Paket problemlos importiert werden.
- Die ersten Bytes der Datei lauten `Alteryx e2 Database file` statt `Alteryx Database File` (in jedem Text- oder Hex-Editor sichtbar).

## Option A: Dateien einzeln in Designer neu speichern

Bei einer Handvoll Dateien speichern Sie jede einzeln aus Designer neu:

1. Fügen Sie in Alteryx Designer ein Werkzeug **Input Data** hinzu und wählen Sie die `.yxdb`-Datei aus.
2. Verbinden Sie ein Werkzeug **Output Data** und wählen Sie einen neuen `.yxdb`-Pfad.
3. Aktivieren Sie in den Optionen des Werkzeugs „Output Data“ die Option, die Datei **kompatibel mit Designer 18.1 und älter** zu speichern. Das erzwingt das klassische Format.
4. Führen Sie den Workflow aus und importieren Sie dann die neue Datei in PlaidCloud.

Das Schreiben in eine CSV-Datei statt in eine `.yxdb` in Schritt 2 funktioniert ebenfalls und überspringt die Kompatibilitätsoption.

## Option B: Einen Ordner mit dem herunterladbaren Workflow stapelweise konvertieren

Laden Sie bei vielen Dateien den vorgefertigten Workflow herunter und führen Sie ihn in Designer aus:

<a href="/downloads/convert_yxdb_folder.yxmd" download>convert_yxdb_folder.yxmd herunterladen</a>

Er verkettet ein Werkzeug **Directory**, ein Werkzeug **Dynamic Input** und ein Werkzeug **Output Data**, sodass jede `.yxdb` in einem Ordner – klassisch oder AMP – als CSV-Datei mit dem Namen `converted_<original name>.csv` neu geschrieben wird. CSV ist portabel, und PlaidCloud importiert es verlustfrei.

1. Öffnen Sie `convert_yxdb_folder.yxmd` in Alteryx Designer.
2. Legen Sie im Werkzeug **Directory** den Ordner fest, der Ihre `.yxdb`-Dateien enthält.
3. Richten Sie im Werkzeug **Dynamic Input** die Input Data Source Template auf eine beliebige `.yxdb`-Datei in diesem Ordner.
4. Legen Sie im Werkzeug **Output Data** den Ausgabeordner fest.
5. Führen Sie den Workflow aus, laden Sie dann die CSV-Dateien in das Dokumentenkonto hoch und importieren Sie sie.

<Aside type="caution">
  Das Werkzeug Dynamic Input setzt voraus, dass alle Dateien eines Stapels dasselbe Feldlayout wie die Vorlagendatei haben. Dateien mit abweichendem Layout werden mit einer Warnung übersprungen – der Ergebnisbereich von Designer nennt jede übersprungene Datei. Gruppieren Sie abweichende Dateien in einem eigenen Ordner mit eigener Vorlage und führen Sie den Workflow erneut aus, oder speichern Sie Nachzügler einzeln mit Option A neu.
</Aside>

Beim Konvertieren in CSV gehen `.yxdb`-spezifische Typangaben verloren (alles kommt als Text an und wird beim Import neu typisiert). Prüfen Sie daher importierte Tabellen stichprobenartig auf Spaltentypen – insbesondere Datumsangaben und Dezimalzahlen mit hoher Genauigkeit.
