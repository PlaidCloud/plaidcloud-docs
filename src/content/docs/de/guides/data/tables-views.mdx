Tabellarische Daten und Informationen werden in PlaidCloud in Greenplum-Data-Warehouses gespeichert.  Das bietet enorme
Skalierbarkeit und Leistung und nutzt dabei bewährte, ausgereifte Technologie, um das Risiko von Datenverlust
oder Datenbeschädigung zu minimieren.

Außerdem ermöglicht ein Data Warehouse mit einer gängigen Syntax Drittanbieter-Werkzeugen, sich direkt zu verbinden
und Daten zu erkunden.  Damit ist das Datenökosystem von PlaidCloud offen und erkundbar und gewährleistet
zugleich branchenführende Sicherheit und Zugriffskontrollen.

## Tabellen

Tabellen enthalten in PlaidCloud die physischen tabellarischen Daten.  Einzelne Tabellen können bei Bedarf viele Terabyte an Daten aufnehmen.  Die Daten werden auf vielen
physischen Servern gespeichert und automatisch gespiegelt, um Datenintegrität und hohe Verfügbarkeit sicherzustellen.

Tabellen bestehen aus Spalten verschiedener Datentypen.  Ein geeigneter Datentyp kann die Leistung und insbesondere die Speichergröße Ihrer Daten verbessern.
PlaidCloud kann die Daten auch besser komprimieren, wenn sie den am besten geeigneten Datentyp verwenden.  Dieser wird meist von PlaidCloud erraten,
Sie können die Datentypen aber auch über die Spalten-Mapper in Workflow-Schritten ändern.

Sie können Tabellen anhand des Workflows, der sie verwendet, anhand eines Spaltennamens oder anhand eines enthaltenen Werts finden und sehen, wann eine Tabelle zuletzt gelesen wurde. Siehe [Tabellen und Ansichten verwalten](/de/guides/projects/managing-tables-and-views/#tabellen-finden).

## Ansichten

Ansichten verhalten sich genau wie Tabellen, enthalten aber keine physischen Daten.  Sie sind logische Darstellungen von Tabellen, die über eine Abfrage abgeleitet werden.  Mit Ansichten können Sie Speicherplatz sparen.

Für die Verwendung von Ansichten gelten allerdings einige Einschränkungen.  Beachten Sie Folgendes:

 * Leistung beim Stapeln von Ansichten – Das Stapeln von Ansichten (eine Ansicht auf einer Ansicht auf einer Ansicht usw.) kann bei sehr großen Tabellen oder komplexen Berechnungen die Leistung beeinträchtigen.  Möglicherweise sind Zwischentabellen nötig, um die Leistung zu verbessern.
 * Dashboard-Leistung – Eine Ansicht lässt sich zwar problemlos für die Verwendung in Dashboards veröffentlichen, bei sehr großen Tabellen sollten Sie für die beste Benutzererfahrung aber eher eine Tabelle als eine Ansicht veröffentlichen.
 * Dynamische Daten – Die Daten in einer Ansicht ändern sich, wenn sich die Daten der zugrunde liegenden referenzierten Tabelle ändern.  Das kann ein Vorteil sein (alles wird automatisch aktualisiert) oder ein unerwartetes Problem, wenn eine statische Datenmenge gewünscht war.

<Aside>Ansichten können Workflows beschleunigen, da zur Laufzeit des Workflows keine Datenverschiebung nötig ist.</Aside>

<Aside>Da Ansichten keine Daten enthalten, fällt Ihnen auf, dass sie nicht als Ziel für Importe verwendet werden können. In diesem Fall muss eine Tabelle verwendet werden.</Aside>
