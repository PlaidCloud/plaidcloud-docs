Jedes Mal, wenn eine Tabelle geschrieben wird, bewahrt das Lakehouse von PlaidCloud einen **Snapshot** der Tabelle zu diesem Zeitpunkt auf – eine konsistente Kopie der Daten zu einem bestimmten Zeitpunkt. Mit Snapshots können Sie nachsehen, was eine Tabelle früher enthielt, einen fehlerhaften Ladevorgang rückgängig machen und nachvollziehen, wie sich eine Tabelle im Lauf der Zeit verändert hat. Wie weit Sie zurückgehen können, bestimmt die Time-Travel-Einstellung der Tabelle: standardmäßig 1 Tag und bis zu 90 Tage für den Projektstandard oder eine Tabelle, die den Zeitraum verlängert. Siehe [Speicher verwalten](/de/guides/projects/managing-storage/).

Um eine Tabelle per SQL so zu lesen, wie sie zum Zeitpunkt eines Snapshots war, kopieren Sie eine Abfrage mit `FOR VERSION AS OF` aus den Details der Tabelle im [Lakehouse-Fenster](/de/guides/data/lakehouse-window/#eine-time-travel-abfrage-kopieren).

Im Bereich Snapshots können Sie diesen Verlauf durchsuchen, jeden Snapshot schreibgeschützt im Tabellen-Explorer öffnen und die Tabelle auf einen früheren Snapshot zurücksetzen oder daraus wiederherstellen.

## Den Bereich Snapshots öffnen

Klicken Sie in der Liste **Tabellen** des Projekts in der Zeile einer Tabelle auf die Schaltfläche für Snapshots/Flashback. Der Bereich **Snapshots** öffnet sich und listet die Snapshots der Tabelle auf, die neuesten zuerst:

- **Wann** – Datum und Uhrzeit, zu denen der Snapshot erstellt wurde.
- **Zeilen** – die Zeilenanzahl der Tabelle zum Zeitpunkt dieses Snapshots.
- **Δ Zeilen** – die Veränderung der Zeilenanzahl gegenüber dem vorherigen Snapshot, sodass Sie sehen, was jeder Schreibvorgang hinzugefügt oder entfernt hat.
- **Größe** – die komprimierte Speichergröße des Snapshots.
- **Bezeichnung** – ein Name für Snapshots, die Sie benannt oder fixiert haben.
- **Gehalten** – eine Markierung für Snapshots, die gehalten werden (über das normale Aufbewahrungsfenster hinaus aufbewahrt).

## Die Daten zum Stand eines Snapshots anzeigen

Es gibt zwei Möglichkeiten, die Daten einer Tabelle zu einem früheren Zeitpunkt anzuzeigen. Beide öffnen den Tabellen-Explorer in einer **schreibgeschützten historischen Ansicht** mit einem Banner, das anzeigt, welchen Snapshot Sie gerade betrachten, und einer Schaltfläche **Zurück zu aktuellen Daten**.

1. **Über den Bereich Snapshots** – wählen Sie einen Snapshot aus und klicken Sie auf **Ansicht beim Snapshot**.
2. **Über den Tabellen-Explorer** – verwenden Sie die Dropdown-Liste **As of** in der Symbolleiste. Sie listet die letzten Snapshots der Tabelle danach auf, was sie geschrieben hat, etwa *after Month-End Close ran*, und wann; wählen Sie einen aus, um die Ansicht umzuschalten, oder wählen Sie **Aktuell (Live-Daten)**, um zu den Live-Daten zurückzukehren.

Klicken Sie in der historischen Ansicht auf **Compare with now**, um zu sehen, wie viele Zeilen sich seitdem geändert haben, hinzugefügt oder entfernt wurden, wobei die abweichenden Zeilen im Raster markiert sind. Siehe [Eine Tabelle zum Stand einer früheren Ausführung](/de/guides/ai-assistant/weave-numbers/#eine-tabelle-zum-stand-einer-früheren-ausführung).

<Aside>Die historische Ansicht ist schreibgeschützt – sie ist ein Blick in die Vergangenheit, keine bearbeitbare Kopie. Verwenden Sie **Zurücksetzen** oder **Wiederherstellen** (siehe unten), wenn Sie alte Daten wieder in eine Tabelle übernehmen möchten.</Aside>

## Einen Snapshot zurücksetzen oder wiederherstellen

Wählen Sie einen Snapshot aus und klicken Sie auf **Zurücksetzen / Wiederherstellen**. Der Dialog bietet zwei Möglichkeiten:

- **Diese Tabelle direkt zurücksetzen** (Standard) – ersetzt die aktuellen Daten der Tabelle durch den Snapshot. Da dies destruktiv ist, geben Sie zur Bestätigung den Namen der Tabelle ein. Bevor die Daten ersetzt werden, erfasst PlaidCloud automatisch einen **Sicherheits-Snapshot vor dem Zurücksetzen** des aktuellen Zustands (bei Speicher-Engines, die das Fixieren unterstützen), sodass Sie jederzeit zum vorherigen Stand zurückkehren können. Wenn sich in einem Databend-Lakehouse die Spalten der Tabelle seit dem Snapshot geändert haben, wird ein direktes Zurücksetzen abgelehnt und die geänderten Spalten werden genannt – stellen Sie stattdessen in eine neue Tabelle wieder her.
- **Momentaufnahme in eine neue Tabelle wiederherstellen** – lässt die ursprüngliche Tabelle unverändert und erstellt im Projekt eine neue Tabelle (Sie geben ihr einen Namen und einen Ordner), die aus dem Snapshot befüllt wird und dieselben Spalten wie die Quelle hat. Über den KI-Assistenten oder MCP erhält eine Wiederherstellung ohne angegebenen Namen einen Namen auf Basis der Quelltabelle, zum Beispiel `Sales (restored 3f2a9c1d)`.

<Aside type="caution">Das direkte Zurücksetzen überschreibt die aktuellen Daten der Tabelle. Die eingegebene Bestätigung und der automatische Sicherheits-Snapshot vor dem Zurücksetzen dienen Ihrem Schutz – lesen Sie den Dialog, bevor Sie bestätigen. Das Zurücksetzen ist gesperrt, solange das Projekt gesperrt ist.</Aside>

<Aside>Über die REST-API oder MCP stellen Sie einen Snapshot direkt wieder her, indem Sie die Zieltabelle weglassen oder die Tabelle selbst angeben. Eine direkte Wiederherstellung erhält dort denselben Schutz wie das Zurücksetzen im Dialog: einen Sicherheits-Snapshot vor dem Zurücksetzen, sofern die Speicher-Engine dies unterstützt, und einen Audit-Eintrag. Damit sie abgelehnt wird, falls die Tabelle seit dem Auflisten ihrer Snapshots geschrieben wurde, übergeben Sie den neuesten Snapshot, den Sie gesehen haben, als `expected_current_snapshot_id`.</Aside>

<Aside>Wenn eine Wiederherstellung in eine neue Tabelle fehlschlägt – zum Beispiel, weil der Snapshot abgelaufen ist –, wird dem Projekt keine neue Tabelle hinzugefügt.</Aside>

## Benennen, Fixieren und Aufbewahrung

Snapshots laufen bei der nächtlichen Bereinigung gemäß der Time-Travel-Einstellung der Tabelle ab (standardmäßig 1 Tag, bis zu 90 Tage). Zurücksetzen und Wiederherstellen funktionieren bis zum ältesten wiederherstellbaren Zeitpunkt, der für die Tabelle angezeigt wird. Um einen Snapshot länger aufzubewahren:

- **Snapshot erstellen** erstellt bei Bedarf einen gehaltenen Snapshot der aktuellen Daten – nützlich vor einem riskanten Neuladen (zum Beispiel „vor dem Neuladen von Q2“).
- **Halten** fixiert den ausgewählten Snapshot; **Freigeben** hebt das Halten auf und gibt ihn in den normalen Lebenszyklus zurück.

<Aside type="caution">Das Halten bewahrt mehr als nur den einen Snapshot auf – es bewahrt den gehaltenen Snapshot *und* jeden danach geschriebenen Snapshot auf, sodass der Speicherbedarf wächst, bis Sie das Halten aufheben. Wird eine Tabelle vollständig ersetzt (ein Upsert oder ein SCD-2-Ersetzen), beginnt ein völlig neuer Snapshot-Verlauf, und jedes Halten im alten Verlauf geht damit verloren.</Aside>

Wenn Sie über die REST-API alle Tabellen eines Projekts auf einmal wiederherstellen, wird jede Tabelle auf ihren neuesten gehaltenen Snapshot wiederhergestellt, und Tabellen ohne gehaltenen Snapshot bleiben unverändert. Ein Sicherheits-Snapshot vor dem Zurücksetzen gilt nicht als gehalten, auch wenn der Bereich Snapshots ihn möglicherweise als gehalten markiert, es sei denn, Sie halten diesen Snapshot zusätzlich selbst, zum Beispiel mit **Halten**. Snapshot-Namen, die mit `pre-revert_` beginnen, sind für Sicherheits-Snapshots reserviert. Wenn eine Tabelle nicht wiederhergestellt werden kann, werden die anderen trotzdem wiederhergestellt, und die Anfrage schlägt fehl und nennt jede Tabelle, die nicht wiederhergestellt wurde, sowie den Grund.

<Aside>Das Benennen eines bei Bedarf erstellten Snapshots ist für Lakehouse-Tabellen (StarRocks) verfügbar. Das Halten und Freigeben eines Snapshots funktioniert jetzt auch für Databend-basierte Tabellen; Snapshots werden dort auch ohne Halten für das Aufbewahrungsfenster aufbewahrt.</Aside>

## Prüfprotokoll

Direkte Zurücksetzungen, ob über den Dialog, die REST-API oder einen KI-Assistenten, werden im Audit-Protokoll des Lakehouse erfasst, einschließlich der Person, die das Zurücksetzen durchgeführt hat, des Zeitpunkts, des Snapshots, auf den zurückgesetzt wurde, und des aufbewahrten Sicherheits-Snapshots – sodass Tabellenänderungen über diese Funktion nachvollziehbar sind.
