Jedes Mal, wenn eine Tabelle geschrieben wird, behält das Lakehouse von PlaidCloud einen **Snapshot** der Tabelle zu diesem Zeitpunkt – eine konsistente Kopie der Daten zu einem bestimmten Zeitpunkt. Mit Snapshots können Sie nachsehen, was eine Tabelle früher enthielt, sich von einem fehlerhaften Ladevorgang erholen und nachvollziehen, wie sich eine Tabelle im Lauf der Zeit verändert hat. Wie weit Sie zurückgehen können, bestimmt die Time-Travel-Einstellung der Tabelle: standardmäßig 1 Tag und bis zu 90 Tage für den Projektstandard oder eine Tabelle, die ihn verlängert. Siehe [Speicher verwalten](/de/guides/projects/managing-storage/).

Im Bereich „Snapshots“ können Sie diesen Verlauf durchsuchen, jeden Snapshot schreibgeschützt im Tabellen-Explorer öffnen und die Tabelle auf einen früheren Snapshot zurücksetzen oder wiederherstellen.

## Den Snapshots-Bereich öffnen

Klicken Sie in der Liste **Tabellen** des Projekts in der Zeile einer Tabelle auf die Snapshot-/Flashback-Schaltfläche. Der Bereich **Snapshots** öffnet sich und listet die Snapshots der Tabelle mit den neuesten zuerst auf:

- **Wann** – Datum und Uhrzeit, zu denen der Snapshot erstellt wurde.
- **Zeilen** – die Zeilenanzahl der Tabelle bei diesem Snapshot.
- **Δ Zeilen** – die Änderung der Zeilenanzahl gegenüber dem vorherigen Snapshot, sodass Sie sehen können, was jeder Schreibvorgang hinzugefügt oder entfernt hat.
- **Größe** – die komprimierte Speichergröße des Snapshots.
- **Bezeichnung** – ein Name für Snapshots, die Sie benannt oder angeheftet haben.
- **Gehalten** – eine Markierung für Snapshots, die gehalten werden (über das normale Aufbewahrungsfenster hinaus aufbewahrt).

## Die Daten zum Stand eines Snapshots anzeigen

Es gibt zwei Möglichkeiten, die Daten einer Tabelle zu einem früheren Zeitpunkt anzuzeigen. Beide öffnen den Tabellen-Explorer in einer **schreibgeschützten historischen Ansicht** mit einem Banner, das zeigt, welchen Snapshot Sie ansehen, und einer Schaltfläche **Zurück zu aktuellen Daten**.

1. **Im Snapshots-Bereich** – wählen Sie einen Snapshot aus und klicken Sie auf **Ansicht beim Snapshot**.
2. **Im Tabellen-Explorer** – verwenden Sie das Dropdown **As of** in der Symbolleiste. Es listet die letzten Snapshots der Tabelle auf; wählen Sie einen aus, um die Ansicht umzuschalten, oder wählen Sie **Aktuell (Live-Daten)**, um zu den Live-Daten zurückzukehren.

<Aside>Die historische Ansicht ist schreibgeschützt – sie ist ein Fenster in die Vergangenheit, keine bearbeitbare Kopie. Verwenden Sie **Zurücksetzen** oder **Wiederherstellen** (siehe unten), wenn Sie alte Daten in eine Tabelle zurückholen möchten.</Aside>

## Einen Snapshot zurücksetzen oder wiederherstellen

Wählen Sie einen Snapshot aus und klicken Sie auf **Zurücksetzen / Wiederherstellen**. Der Dialog bietet zwei Optionen:

- **Revert this table in place** (Standard) – ersetzt die aktuellen Daten der Tabelle durch den Snapshot. Da dies destruktiv ist, geben Sie zur Bestätigung den Namen der Tabelle ein. Bevor die Daten ersetzt werden, erfasst PlaidCloud automatisch einen **Sicherheits-Snapshot vor dem Zurücksetzen** vom aktuellen Zustand (bei Speicher-Engines, die Anheften unterstützen), sodass Sie jederzeit zum vorherigen Stand zurückkehren können. In einem Databend-Lakehouse wird ein Zurücksetzen an Ort und Stelle abgelehnt, wenn sich die Spalten der Tabelle seit dem Snapshot geändert haben; die geänderten Spalten werden dabei genannt – stellen Sie stattdessen in eine neue Tabelle wieder her.
- **Momentaufnahme in eine neue Tabelle wiederherstellen** – lässt die ursprüngliche Tabelle unberührt und erstellt im Projekt eine neue Tabelle (Sie geben ihr einen Namen und einen Ordner), die aus dem Snapshot befüllt wird und dieselben Spalten wie die Quelle hat. Über den KI-Assistenten oder MCP erhält eine Wiederherstellung ohne angegebenen Namen einen Namen auf Basis der Quelltabelle, zum Beispiel `Sales (restored 3f2a9c1d)`.

<Aside type="caution">Das Zurücksetzen an Ort und Stelle überschreibt die aktuellen Daten der Tabelle. Die eingegebene Bestätigung und der automatische Sicherheits-Snapshot vor dem Zurücksetzen schützen Sie – lesen Sie den Dialog, bevor Sie bestätigen. Das Zurücksetzen ist blockiert, solange das Projekt gesperrt ist.</Aside>

<Aside>Über die REST-API oder MCP stellen Sie einen Snapshot an Ort und Stelle wieder her, indem Sie die Zieltabelle weglassen oder die Tabelle selbst angeben. Eine Wiederherstellung an Ort und Stelle erhält dort denselben Schutz wie das Zurücksetzen im Dialog: einen Sicherheits-Snapshot vor dem Zurücksetzen, sofern die Speicher-Engine einen unterstützt, und einen Audit-Eintrag. Damit sie abgelehnt wird, wenn die Tabelle seit dem Auflisten ihrer Snapshots geschrieben wurde, übergeben Sie den neuesten Snapshot, den Sie gesehen haben, als `expected_current_snapshot_id`.</Aside>

<Aside>Schlägt die Wiederherstellung in eine neue Tabelle fehl – zum Beispiel weil der Snapshot abgelaufen ist –, wird dem Projekt keine neue Tabelle hinzugefügt.</Aside>

## Benennen, Anheften und Aufbewahrung

Snapshots laufen bei der nächtlichen Bereinigung entsprechend der Time-Travel-Einstellung der Tabelle ab (standardmäßig 1 Tag, bis zu 90 Tage). Zurücksetzen oder Wiederherstellen funktioniert bis zum ältesten wiederherstellbaren Zeitpunkt, der für die Tabelle angezeigt wird. Um einen länger aufzubewahren:

- **Snapshot erstellen** erstellt auf Anforderung einen gehaltenen Snapshot der aktuellen Daten – nützlich vor einem riskanten erneuten Laden (zum Beispiel „vor dem Neuladen von Q2“).
- **Halten** heftet den ausgewählten Snapshot an; **Freigeben** hebt das Halten auf und überführt ihn zurück in den normalen Lebenszyklus.

<Aside type="caution">Ein Halten bewahrt mehr als nur den einen Snapshot – es bewahrt den gehaltenen Snapshot *und* jeden danach geschriebenen Snapshot, sodass der Speicherbedarf weiter wächst, bis Sie das Halten freigeben. Das vollständige Ersetzen einer Tabelle (ein Upsert oder ein SCD-2-Replace) beginnt einen völlig neuen Snapshot-Verlauf, und jedes Halten auf den alten geht damit verloren.</Aside>

Wird jede Tabelle eines Projekts auf einmal über die REST-API wiederhergestellt, wird jede Tabelle auf ihren jüngsten gehaltenen Snapshot wiederhergestellt, und Tabellen ohne Halten bleiben unverändert. Ein Sicherheits-Snapshot vor dem Zurücksetzen zählt nicht als Halten, auch wenn der Snapshots-Bereich ihn möglicherweise als gehalten markiert, es sei denn, Sie halten diesen Snapshot selbst, zum Beispiel mit **Halten**. Snapshot-Namen, die mit `pre-revert_` beginnen, sind für Sicherheits-Snapshots reserviert. Kann eine Tabelle nicht wiederhergestellt werden, werden die anderen trotzdem wiederhergestellt, und die Anfrage schlägt fehl und nennt jede nicht wiederhergestellte Tabelle samt Grund.

<Aside>Das Benennen eines Snapshots auf Anforderung ist für Lakehouse-Tabellen (StarRocks) verfügbar. Das Halten und Freigeben eines Snapshots funktioniert jetzt auch bei Databend-basierten Tabellen; Snapshots werden dort auch ohne Halten weiterhin für das Aufbewahrungsfenster aufbewahrt.</Aside>

## Überwachung

Das Zurücksetzen an Ort und Stelle – ob über den Dialog, die REST-API oder einen KI-Assistenten – wird im Audit-Protokoll des Lakehouse aufgezeichnet, einschließlich wer das Zurücksetzen durchgeführt hat, wann, auf welchen Snapshot zurückgesetzt wurde und welcher Sicherheits-Snapshot aufbewahrt wurde – sodass Tabellenänderungen über diese Funktion nachvollziehbar sind.
