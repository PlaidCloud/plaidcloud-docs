Ein Repository enthält die Dateien, Branches und den Verlauf eines Projekts. Diese Anleitung zeigt, wie Sie ein Repository erstellen und von Ihrem Computer aus eine Verbindung dazu herstellen.

## Repository erstellen

1. Öffnen Sie **Git** in Ihrem Workspace.
2. Wählen Sie oben rechts das Menü **+** und dann **New Repository**.
3. Geben Sie einen Namen und optional eine kurze Beschreibung ein.
4. Legen Sie die Sichtbarkeit fest. Neue Repositories sind standardmäßig **Privat** – nur Mitglieder, denen Sie Zugriff gewähren, können sie sehen.
5. Wählen Sie optional **Initialize Repository**, um eine README-Datei, eine `.gitignore`-Datei und eine Lizenz hinzuzufügen.
6. Wählen Sie **Create Repository**.

Contributors können Repositories nicht direkt in der Git-Organisation des Workspace erstellen; Repositories werden über PlaidCloud erstellt.

## Persönliches Zugriffstoken erzeugen

Da Sie sich über PlaidCloud anmelden, hat Ihr Konto kein separates Git-Passwort. Um per HTTPS über die Befehlszeile zu klonen oder zu pushen, erstellen Sie ein persönliches Zugriffstoken und verwenden es anstelle eines Passworts.

1. Wählen Sie oben rechts Ihren Avatar und dann **Einstellungen**. Die Einrichtungskarte auf der Registerkarte **Git** verlinkt ebenfalls direkt auf diese Seite.
2. Öffnen Sie die Registerkarte **Anwendungen**.
3. Geben Sie unter **Zugriffstoken verwalten** einen Namen ein, der beschreibt, wo Sie das Token verwenden (zum Beispiel `laptop`).
4. Wählen Sie die Berechtigung **write:repository**, damit das Token klonen und pushen kann.
5. Wählen Sie **Generate Token**.
6. Kopieren Sie das Token und bewahren Sie es sicher auf. Sie können es danach nicht mehr einsehen.

<Aside type="caution">Behandeln Sie das Token wie ein Passwort – jeder, der es besitzt, kann in Git in Ihrem Namen handeln. Erzeugen Sie für jeden Rechner ein eigenes Token, damit Sie eines widerrufen können, ohne die anderen zu beeinträchtigen.</Aside>

## Repository klonen

1. Öffnen Sie **Git** in Ihrem Workspace und wählen Sie die Kopierschaltfläche neben der Clone-Adresse des Repositorys (wählen Sie **How to clone** für die Einrichtungsschritte). Sie können auch im Repository **Code** wählen und die **HTTPS**-URL kopieren.
2. Führen Sie in einem Terminal `git clone` mit dieser URL aus:

   ```bash
   git clone <clone URL>
   ```

3. Wenn Git nach einem Passwort fragt, fügen Sie das **Zugriffstoken** ein. Verwenden Sie den Benutzernamen, der bereits in der URL steht.
4. Legen Sie den Namen und die E-Mail-Adresse fest, die Git in Ihren Commits speichert, mit den Werten, die die Einrichtungskarte anzeigt:

   ```bash
   git config --global user.name "Your Name"
   git config --global user.email "you@example.com"
   ```

Zum Pushen benötigen Sie Contributor- oder Administrator-Zugriff; als Viewer können Sie lesen, aber nicht pushen. Siehe [Zugriffsstufen](/de/guides/git/#zugriffsstufen).

<Aside>Damit Sie das Token nicht bei jedem Push erneut eingeben müssen, können Sie es vom Git-Credential-Helper Ihres Betriebssystems speichern lassen, zum Beispiel mit `git config --global credential.helper osxkeychain` unter macOS.</Aside>

## Änderungen committen und pushen

Gehen Sie in einem geklonten Repository wie folgt vor:

1. Stagen Sie Ihre Änderungen: `git add .`
2. Halten Sie sie mit einer Nachricht fest: `git commit -m "Describe what changed"`
3. Senden Sie sie an PlaidCloud Git: `git push`

Ihre Commits erscheinen in den Ansichten **Commits** und **Aktivität** des Repositorys sowie in jedem Branch oder Pull Request, der sie enthält.

## Zugriff und Sichtbarkeit verwalten

Öffnen Sie die Registerkarte **Einstellungen** eines Repositorys, um es umzubenennen, seine Sichtbarkeit zu ändern oder das Eigentum zu übertragen. Damit andere Mitglieder mitarbeiten können, verwenden Sie **Einstellungen → Collaborators** und fügen Sie sie per Benutzernamen mit der Rolle **Lesen**, **Schreiben** oder **Administrator** hinzu.

<Aside>Der Repository-Zugriff folgt außerdem Ihrer Workspace-Mitgliedschaft und Ihren Sicherheitsgruppen. Unter [Zugriffsverwaltung](/de/administration/access/) erfahren Sie, wie diese bestimmen, wer ein Repository sehen und bearbeiten darf.</Aside>
