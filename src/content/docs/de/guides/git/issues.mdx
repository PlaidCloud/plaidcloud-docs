Issues geben Ihrem Team einen gemeinsamen Ort, um Fehler zu verfolgen, Funktionen zu planen und alles festzuhalten, was Aufmerksamkeit braucht – direkt verknüpft mit dem Code in Ihrem Repository.

## Issue erstellen

1. Öffnen Sie Ihr Repository und wählen Sie die Registerkarte **Issues**.
2. Wählen Sie **New Issue**.
3. Geben Sie einen prägnanten **Titel** ein, der das Problem oder die Aufgabe beschreibt.
4. Verfassen Sie eine **Beschreibung** in Markdown – fügen Sie bei Bedarf Schritte zur Reproduktion, Akzeptanzkriterien, Screenshots oder Codeblöcke hinzu.
5. Wählen Sie **Submit New Issue**, um es zu veröffentlichen.

<Aside>Ein Repository kann unter **Einstellungen → Issue Templates** wiederverwendbare Issue-Vorlagen definieren. Sind Vorlagen konfiguriert, erscheint beim Öffnen eines neuen Issues eine Auswahl, sodass Mitwirkende mit einem einheitlichen Formular statt mit einer leeren Seite beginnen.</Aside>

## Mit Bezeichnungen und Meilensteinen organisieren

**Bezeichnungen** kategorisieren und priorisieren Issues. Wenden Sie beim Anzeigen eines Issues eine oder mehrere Bezeichnungen über die rechte Seitenleiste an oder direkt in der Issue-Liste über den Filter **Bezeichnung**. Üblich sind Typbezeichnungen (`bug`, `enhancement`) neben Prioritätsbezeichnungen (`high`, `low`), aber Sie können unter **Issues → Labels** beliebige Bezeichnungen erstellen, die zu Ihrem Workflow passen.

**Meilensteine** fassen Issues zu einem gemeinsamen Ziel zusammen – einem Release-Termin, einem Sprint oder einem Funktionsziel. Erstellen Sie Meilensteine unter **Issues → Milestones** und weisen Sie ein Issue dann in dessen Seitenleiste einem Meilenstein zu. Die Meilensteinansicht zeigt den Fortschritt, wenn Issues geschlossen werden.

## Zuweisen und diskutieren

- **Zuständige** – verwenden Sie das Feld **Zuständige** in der Seitenleiste, um festzulegen, wer verantwortlich ist. Jedes Workspace-Mitglied mit Repository-Zugriff kann zugewiesen werden.
- **Kommentare** – fügen Sie im Kommentarverlauf unter der Issue-Beschreibung Kontext, Entscheidungen oder Statusaktualisierungen hinzu.
- **@-Erwähnungen** – geben Sie an beliebiger Stelle in einem Kommentar oder einer Beschreibung `@username` ein, um diese Person direkt zu benachrichtigen.
- **Reaktionen** – verwenden Sie Emoji-Reaktionen auf Kommentare, um einen Punkt zu bestätigen, ohne zu antworten.

## Issues mit Code verknüpfen

Das Referenzieren von Issues in Commits und Pull Requests hält Ihren Verlauf nachvollziehbar.

- **Per Nummer referenzieren** – geben Sie `#12` in eine Commit-Nachricht, eine Pull-Request-Beschreibung oder einen Kommentar ein, um einen anklickbaren Link zu Issue 12 im selben Repository zu erzeugen.
- **Automatisches Schließen beim Mergen** – nehmen Sie ein Schlüsselwort zum Schließen in die Pull-Request-Beschreibung auf (zum Beispiel `Closes #12`, `Fixes #34` oder `Resolves #56`). Wenn der Pull Request in den Standard-Branch gemergt wird, werden die referenzierten Issues automatisch geschlossen.
- **Querverweise auf andere Issues** – verwenden Sie `#number` in jedem Issue-Kommentar, um verwandte Issues zu verknüpfen. Jedes referenzierte Issue zeigt einen Rückverweis, sodass die Verbindung von beiden Seiten sichtbar ist.

## Issues finden

Die Issue-Liste unterstützt mehrere Filter, die Sie kombinieren können:

| Filter | Funktion |
|---|---|
| **Zustand** | Offene oder geschlossene Issues anzeigen |
| **Bezeichnung** | Auf eine oder mehrere Bezeichnungen eingrenzen |
| **Meilenstein** | Einem Meilenstein zugewiesene Issues anzeigen |
| **Zuständige** | Einer bestimmten Person zugewiesene Issues anzeigen |
| **Autor** | Von einer bestimmten Person eröffnete Issues anzeigen |

Wählen Sie in der Filterleiste über der Issue-Liste die passende Spalte aus, um jeden Filter anzuwenden. Informationen zur Stichwortsuche in Issue-Titeln und -Texten finden Sie unter [Code durchsuchen](/de/guides/git/searching-code/).
