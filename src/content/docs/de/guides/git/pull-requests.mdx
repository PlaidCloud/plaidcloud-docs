## Branch erstellen

Arbeiten Sie in einem neuen Branch, damit Ihre Änderungen vom Standard-Branch getrennt bleiben, bis sie bereit sind.

**In der Benutzeroberfläche:**

1. Öffnen Sie Ihr Repository und wählen Sie die Branch-Auswahl oben links (sie zeigt den Namen des aktuellen Branches).
2. Geben Sie im Suchfeld einen neuen Branch-Namen ein und wählen Sie **Create Branch**.

**Lokal:**

1. Erstellen Sie den Branch und wechseln Sie dorthin: `git checkout -b feature-x`
2. Nehmen Sie Ihre Änderungen vor und stagen und committen Sie sie dann: `git add .` und anschließend `git commit -m "Describe what changed"`
3. Pushen Sie den Branch zu PlaidCloud Git: `git push -u origin feature-x`

## Pull Request öffnen

1. Öffnen Sie Ihr Repository, wählen Sie die Registerkarte **Pull Requests** und dann **New Pull Request**.
2. Setzen Sie den Branch **Vergleichen** auf Ihren Feature-Branch und den Branch **Basis** auf das Ziel (in der Regel `main` oder `master`).
3. Schreiben Sie einen aussagekräftigen Titel und eine Beschreibung, die erklärt, was sich geändert hat und warum.
4. Um verwandte Issues zu verknüpfen, fügen Sie in der Beschreibung ein Schlüsselwort zum Schließen hinzu – zum Beispiel `Closes #12` –, damit das Issue automatisch geschlossen wird, wenn der Pull Request gemergt wird.
5. Weisen Sie bei Bedarf Reviewer zu und wählen Sie dann **Create Pull Request**.

## Änderungen prüfen

Reviewer arbeiten den Pull Request durch, ohne etwas zu mergen:

1. Öffnen Sie den Pull Request und wählen Sie **Files Changed**, um den Diff zu lesen.
2. Wählen Sie eine beliebige Zeile im Diff, um einen Inline-Kommentar zu dieser konkreten Änderung zu hinterlassen.
3. Geben Sie zum Abschluss ein Gesamturteil ab: **Genehmigen**, um zuzustimmen, oder **Request Changes**, um zuerst Überarbeitungen anzufordern.
4. Der Autor pusht weitere Commits in denselben Branch, um das Feedback zu berücksichtigen – der Pull Request wird automatisch aktualisiert, ein neuer muss nicht geöffnet werden.
5. Reviewer markieren einzelne Kommentarverläufe als gelöst, sobald jedes Anliegen behoben ist.

<Aside>Ein Repository-Administrator kann für den Standard-Branch einen Branch-Schutz aktivieren, der vor dem Mergen eines Pull Requests eine Mindestanzahl an Genehmigungen verlangt.</Aside>

## Mergen

Sobald der Pull Request genehmigt ist:

1. Wählen Sie im Dropdown neben der Schaltfläche **Merge** eine Merge-Methode:
   - **Create a merge commit** – bewahrt den vollständigen Branch-Verlauf mit einem Merge-Commit.
   - **Squash and merge** – fasst alle Commits des Branches zu einem einzigen Commit im Ziel-Branch zusammen.
   - **Rebase and merge** – spielt die Commits des Branches ohne Merge-Commit auf den Ziel-Branch ab.
2. Wählen Sie **Merge**, um den Vorgang abzuschließen.
3. Wählen Sie optional **Delete Branch**, um den Feature-Branch aufzuräumen, sobald er nicht mehr benötigt wird.
