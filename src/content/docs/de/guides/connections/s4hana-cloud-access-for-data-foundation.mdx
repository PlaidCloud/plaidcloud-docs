[Data Foundation](/de/guides/projects/data-foundation/) führt die Daten aller ERP-Systeme und Instanzen, die Sie verbinden, in einem Common Finance Model zusammen, und SAP S/4HANA Cloud ist eines der ERP-Systeme, die es direkt liest. Die Verbindung liest die freigegebenen OData-Dienste des Mandanten mit OAuth-2.0-Client-Anmeldedaten; ein Agent ist nicht beteiligt. Diese Seite richtet sich an den S/4HANA-Cloud-Administrator, der das einrichtet, und an den PlaidCloud-Benutzer, der ihn darum bittet.

PlaidCloud liest Daten ausschließlich. Niemand sendet ein Kennwort oder ein Client-Secret per E-Mail.

## Zugriffsanfrage senden

Wählen Sie auf der Seite **Systeme** des Projekts, unter **Data Foundation** in **Startseite**, unter **System hinzufügen** im Feld **System** Ihr System aus und klicken Sie auf **Noch keinen Zugang?**. Das System wartet dann auf den Zugang, und es wird eine Anfrage angezeigt, die alle Systeme des Projekts abdeckt. Klicken Sie auf **Anfrage kopieren**, um sie in Ihre eigene Nachricht einzufügen, oder auf **Anfrage per E-Mail senden**, um sie in Ihrem E-Mail-Programm mit dem Betreff „Zugang zu PlaidCloud“ zu öffnen.

## Was der S/4HANA-Cloud-Administrator einrichtet

<Steps>

1. **Erstellen Sie einen Kommunikationsbenutzer** für PlaidCloud in der App **Maintain Communication Users**. Seine Authentifizierungsmethode ist OAuth 2.0 oder Benutzername und Kennwort, je nach Anforderung Ihrer Systemlandschaft.

2. **Erstellen Sie ein Kommunikationssystem** für PlaidCloud in der App **Communication Systems**, mit diesem Benutzer für die eingehende Kommunikation und OAuth-2.0-Client-Anmeldedaten.

3. **Erstellen Sie für jedes der folgenden Szenarien eine Kommunikationsvereinbarung** in der App **Communication Arrangements**, jeweils für das System aus Schritt 2. Zusammen stellen sie die OData-Dienste bereit, die PlaidCloud liest:

   | Szenario | Dienst |
   |---|---|
   | Company Code | `API_COMPANYCODE_SRV` |
   | G/L Account in Chart of Accounts | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
   | Cost Center | `API_COSTCENTER_SRV` |
   | Business Partner and Customer | `API_BUSINESS_PARTNER` |
   | Product | `API_PRODUCT_SRV` |
   | Fiscal Year Variant Periods | `API_FISCALYEARPERIODFORVARIANT_SRV` |
   | Exchange Rates | `API_EXCHANGERATE_SRV` |
   | Journal Entry Item | `API_JOURNALENTRYITEMBASIC_SRV` (das Journal und der Saldovortrag) |
   | Billing Document | `API_BILLING_DOCUMENT_SRV` (optional: ergänzt fakturierte Umsätze, Belege und Positionen) |

   Richten Sie für die optionalen Datasets außerdem die Szenarien ein, die diese Dienste bereitstellen:

   | Dienst | Ergänzt |
   |---|---|
   | `API_JOURNALENTRY_SRV` | Wer jedes Journal erfasst hat, wann, und welches Journal es storniert |
   | `API_BUSINESS_PARTNER` (`A_Supplier`) | Lieferanten |
   | `API_PLANT_SRV` | Werke, gelesen als Standorte, und die Werke der Lagerbestände |
   | `API_PROFITCENTER_SRV` | Profitcenter |
   | `API_SUPPLIERINVOICE_PROCESS_SRV` | Lieferantenrechnungspositionen |
   | `API_OPLACCTGDOCITEMCUBE_SRV` | Offene Posten und Zahlungen sowie die Fälligkeitsdaten von Lieferantenrechnungen |
   | `API_FINPLANNINGDATA_SRV` | Budgets |
   | `API_MATERIAL_STOCK_SRV` | Lagerbestände |

   Geben Sie dem Kommunikationsbenutzer Zugriff auf jeden Buchungskreis, über den Sie berichten.

</Steps>

## Was zurückzusenden ist

| Der Administrator sendet | Eingabe in PlaidCloud als |
|---|---|
| Den Host der API des Mandanten, zum Beispiel `https://my300000-api.s4hana.cloud.sap` | **API-Host-URL** |
| Die Token-URL: die eigene des Mandanten (`/sap/bc/sec/oauth2/token`) oder die Ihres XSUAA-Autorisierungsservers, falls Ihre Systemlandschaft einen verwendet | **OAuth2-Token-URL** |
| Die Client-ID | **Client-ID** |
| Das Client-Secret über das sichere Verbindungsformular | **Client-Secret**, das Ihr Team selbst eingibt |
| Ob **Carry Forward Balances** für jedes zu ladende Geschäftsjahr ausgeführt wurde | Nichts einzugeben. Die Eröffnungssalden werden daraus gelesen. |

<Aside type="caution">
Senden Sie das Client-Secret nie per E-Mail. **Client-Secret** ist ein Geheimnis: Es wird in der Verbindung gespeichert und nie wieder angezeigt.
</Aside>

## Zugriff prüfen

Klicken Sie danach in PlaidCloud, sobald das System hinzugefügt ist, in seiner Zeile auf der Seite **Systeme** auf **Verbindung testen**. Der Test liest die erforderlichen Datasets und zeigt jedes als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** an. Die optionalen sind nicht Teil des Tests: Verweigert S/4HANA Cloud eines davon, nennen die Bereitschaftsprüfungen auf dem Dashboard **CFM-Accounting - Close and assurance** nach dem nächsten Laden den Dienst, der der Kommunikationsvereinbarung hinzuzufügen ist.

| Dataset | Erforderlicher Dienst |
|---|---|
| Entitäten | `API_COMPANYCODE_SRV` |
| Kontenplan | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
| Abteilungen | `API_COSTCENTER_SRV` |
| Kunden | `API_BUSINESS_PARTNER` |
| Produkte | `API_PRODUCT_SRV` |
| Wechselkurse | `API_EXCHANGERATE_SRV` |
| Geschäftskalender | `API_FISCALYEARPERIODFORVARIANT_SRV` |
| Hauptbuch | `API_JOURNALENTRYITEMBASIC_SRV` |
| Saldenliste | `API_JOURNALENTRYITEMBASIC_SRV` |
| Verkaufspositionen | `API_BILLING_DOCUMENT_SRV` (optional) |

Zeigt ein Dataset **Fehlende Berechtigung**, bitten Sie den Administrator, die Kommunikationsvereinbarung für den zugehörigen Dienst hinzuzufügen, und testen Sie erneut. Verkaufspositionen, Budget, Lagerbestände, Lieferanten, Standorte, Profitcenter, Lieferantenrechnungspositionen, offene Posten und Zahlungen sind optional: Ein Mandant, der eines davon nicht enthält, lädt trotzdem alles andere. Offene Posten oder Zahlungen eines Monats, die nicht gelesen werden können, und Lieferantenrechnungspositionen eines Monats, deren Lesen fehlschlägt, behalten die Zeilen, die sie bereits hatten, und werden beim nächsten Laden erneut gelesen.

Die Dienste melden keinen Periodenstatus und keinen eigenen Monatsendsaldo, daher ist jede Periode offen, und das Hauptbuch wird mit seiner eigenen Saldenliste verglichen.
