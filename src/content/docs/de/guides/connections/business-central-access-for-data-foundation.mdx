[Data Foundation](/de/guides/projects/data-foundation/) führt die Daten aller ERP-Systeme und Instanzen, die Sie verbinden, in einem Common Finance Model zusammen, und Microsoft Dynamics 365 Business Central ist eines der ERP-Systeme, die es direkt liest. Die Verbindung nutzt eine Microsoft-Entra-ID-Anwendung mit Client-Anmeldedaten, einen schreibgeschützten Berechtigungssatz und einige als Webdienste veröffentlichte Seiten. Diese Seite richtet sich an den Business-Central-Administrator, der das einrichtet, und an den PlaidCloud-Benutzer, der ihn darum bittet.

PlaidCloud liest Daten ausschließlich. Niemand sendet ein Client-Secret per E-Mail.

## Zugriffsanfrage senden

Wählen Sie auf der Registerkarte **Foundation** des Projekts unter **Business-Central-Verbindung** die Option **Neue Verbindung erstellen**. Das Formular zeigt die vollständige Anfrage. Klicken Sie auf **Anfrage kopieren**, um sie in Ihre eigene Nachricht einzufügen, oder auf **Anfrage per E-Mail senden**, um sie in Ihrem E-Mail-Programm mit dem Betreff „Read-only Business Central access for PlaidCloud (Microsoft Entra ID, client credentials)“ zu öffnen.

## Was der Business-Central-Administrator einrichtet

<Steps>

1. **Registrieren Sie eine App in Microsoft Entra ID.** Fügen Sie unter **App registrations > New registration** ein Client-Secret hinzu und notieren Sie die Verzeichnis-ID (Mandanten-ID), die Anwendungs-ID (Client-ID) und das Secret.

2. **Fügen Sie die App in Business Central hinzu.** Öffnen Sie **Microsoft Entra Applications**, fügen Sie die Anwendung hinzu, setzen Sie ihren Status auf **Aktiviert** und weisen Sie ihr für jedes Unternehmen, über das Sie berichten, die Berechtigungssätze **D365 READ** und **D365 BASIC** zu. Weisen Sie keinen Berechtigungssatz mit Schreibzugriff zu.

3. **Veröffentlichen Sie Seiten als Webdienste.** Veröffentlichen Sie unter **Search > Web Services > New** diese Seiten mit genau diesen Dienstnamen und aktiviertem Kontrollkästchen **Published**. Die Standard-API enthält ihre Felder nicht:

   | Seite | Dienstname | Hinweise |
   |---|---|---|
   | 20 G/L Entries | `GLEntries` | |
   | 16 Chart of Accounts | `GLAccounts` | |
   | 100 Accounting Periods | `AccountingPeriods` | |
   | 537 Dimension Values | `DimensionValues` | |
   | 240 Business Units | `BusinessUnits` | |
   | 605 IC Partner List | `ICPartners` | |
   | 5802 Value Entries | `ValueEntries` | Herstellungskosten der verkauften Waren; optional |
   | 120 G/L Budget Entries | `GLBudgetEntries` | Budgets; optional |
   | Statistical Ledger Entries | `StatisticalLedgerEntries` | Statistische Treiber; optional |
   | 118 General Ledger Setup | `GeneralLedgerSetup` | Shortcut-Dimensionen 3 bis 8; optional |
   | 479 Dimension Set Entries | `DimensionSetEntries` | Shortcut-Dimensionen 3 bis 8; optional |

4. **Teilen Sie dem PlaidCloud-Benutzer zwei Entscheidungen mit:** den Quellcode, unter dem Ihre Prüfungsanpassungen gebucht werden (PlaidCloud geht von `ADJUSTMENT` aus), und welche Dimension Ihre Abteilung ist (PlaidCloud geht von der globalen Dimension 1 mit dem Namen `DEPARTMENT` aus).

</Steps>

## Was zurückzusenden ist

| Der Administrator sendet | Eingabe in PlaidCloud als |
|---|---|
| Die Verzeichnis-ID (Mandanten-ID) | **Verzeichnis-ID (Mandanten-ID)** |
| Den Umgebungsnamen, zum Beispiel `production` | **Umgebungsname** |
| Die Anwendungs-ID (Client-ID) | **Anwendungs-ID (Client-ID)** |
| Das Client-Secret | **Client-Secret**, über das Formular eingegeben, nicht per E-Mail |
| Den Namen der Dimension, die Ihre Abteilung ist | Die Systemeinstellung `department_dimension` |
| Die Unternehmen, die PlaidCloud lesen darf | In PlaidCloud unter **Unternehmen** ausgewählt (mindestens eines) |

Unternehmen, die Konsolidierungsunternehmen sind, kommen in die Systemeinstellung `consolidation_companies`, damit ihre Buchungen nicht als Aktivität eines Unternehmens gezählt werden. Wechselkurse stammen aus einem Unternehmen: Nennen Sie es in der Systemeinstellung `rate_company`, andernfalls verwendet PlaidCloud das erste Unternehmen.

## Zugriff prüfen

Geben Sie in PlaidCloud die Werte ein und klicken Sie auf **Verbindung testen**. Jedes Dataset wird als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** angezeigt:

| Dataset | Was es benötigt |
|---|---|
| Entitäten, Kontenplan, Kunden, Produkte, Wechselkurse, Saldenliste | API-Zugriff (Berechtigungssatz D365 READ) |
| Geschäftskalender | Den Webdienst `AccountingPeriods` |
| Abteilungen | Den Webdienst `DimensionValues` |
| Hauptbuch | Den Webdienst `GLEntries` |
| Verkaufspositionen, Budget, Verteilungstreiber | Optional |

Fehlt ein Dataset, nennt der Test die Berechtigung oder den Webdienst, die hinzuzufügen sind. Bitten Sie den Administrator, sie hinzuzufügen, und testen Sie erneut. Verkaufspositionen, Budget und Verteilungstreiber sind optional: Eine Umgebung, die sie nicht verwendet, lädt trotzdem alles andere.
