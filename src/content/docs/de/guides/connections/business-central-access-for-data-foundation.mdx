[Data Foundation](/de/guides/projects/data-foundation/) führt die Daten aus jedem ERP-System und jeder Instanz, die Sie verbinden, in einem Common Finance Model zusammen. Microsoft Dynamics 365 Business Central gehört zu den ERP-Systemen, die direkt gelesen werden. Die Verbindung nutzt eine Microsoft-Entra-ID-Anwendung mit Client-Anmeldeinformationen, einen schreibgeschützten Berechtigungssatz und einige als Webdienste veröffentlichte Seitenobjekte. Diese Seite richtet sich an den Business-Central-Administrator, der das einrichtet, und an den PlaidCloud-Benutzer, der ihn darum bittet.

PlaidCloud liest Daten ausschließlich. Ein Client-Secret wird nie per E-Mail verschickt.

## Zugriffsanfrage senden

Wählen Sie auf der Seite **Systeme** des Projekts, unter **Data Foundation** in **Startseite**, unter **System hinzufügen** im Feld **System** Ihr System aus und klicken Sie auf **Noch keinen Zugang?**. Das System wartet dann auf den Zugang, und es wird eine Anfrage angezeigt, die alle Systeme des Projekts abdeckt. Klicken Sie auf **Anfrage kopieren**, um sie in Ihre eigene Nachricht einzufügen, oder auf **Anfrage per E-Mail senden**, um sie in Ihrem E-Mail-Programm mit dem Betreff „Zugang zu PlaidCloud“ zu öffnen.

## Was der Business-Central-Administrator einrichtet

<Steps>

1. **Registrieren Sie eine App in Microsoft Entra ID.** Fügen Sie unter **App registrations > New registration** ein Client-Secret hinzu und notieren Sie die Verzeichnis-ID (Mandant), die Anwendungs-ID (Client) und das Secret.

2. **Fügen Sie die App in Business Central hinzu.** Öffnen Sie **Microsoft Entra Applications**, fügen Sie die Anwendung hinzu, setzen Sie ihren Status auf **Aktiviert** und weisen Sie ihr für jedes Unternehmen, über das Sie berichten, ausschließlich den Berechtigungssatz **D365 READ** zu. Er liest jede der unten aufgeführten Seiten. Weisen Sie ihr weder **D365 BASIC** noch einen anderen Berechtigungssatz zu, der schreiben kann.

3. **Veröffentlichen Sie Seitenobjekte als Webdienste.** Veröffentlichen Sie unter **Search > Web Services > New** diese Seitenobjekte mit genau diesen Dienstnamen und aktiviertem Kontrollkästchen **Published**. Die Standard-API enthält ihre Felder nicht:

   | Seite | Dienstname | Hinweise |
   |---|---|---|
   | 20 G/L Entries | `GLEntries` | |
   | 16 Chart of Accounts | `GLAccounts` | |
   | 100 Accounting Periods | `AccountingPeriods` | |
   | 537 Dimension Values | `DimensionValues` | |
   | 240 Business Units | `BusinessUnits` | |
   | 605 IC Partner List | `ICPartners` | |
   | 5802 Value Entries | `ValueEntries` | Herstellkosten der verkauften Waren und Bestandssalden; optional |
   | 120 G/L Budget Entries | `GLBudgetEntries` | Budgets; optional |
   | Statistical Ledger Entries | `StatisticalLedgerEntries` | Statistische Treiber; optional |
   | 118 General Ledger Setup | `GeneralLedgerSetup` | Shortcut-Dimensionen 3 bis 8; optional |
   | 479 Dimension Set Entries | `DimensionSetEntries` | Shortcut-Dimensionen 3 bis 8; optional |
   | 573 Detailed Cust. Ledg. Entries | `DetailedCustLedgEntries` | Offene Posten und Zahlungen; optional |
   | 574 Detailed Vendor Ledg. Entries | `DetailedVendorLedgEntries` | Offene Posten und Zahlungen; optional |
   | 371 Bank Account List | `BankAccounts` | Banksalden; optional |
   | 277 Bank Account Posting Groups | `BankAccountPostingGroups` | Banksalden; optional |
   | Inventory Posting Setup (nach der zugehörigen Seite suchen) | `InventoryPostingSetup` | Das Konto der Einkaufspositionen eines Artikels; optional |

4. **Teilen Sie dem PlaidCloud-Benutzer drei Festlegungen mit:** den Quellcode, unter dem Ihre Prüfungsanpassungen gebucht werden (PlaidCloud geht von `ADJUSTMENT` aus), welche Dimension Ihre Abteilung ist (PlaidCloud geht von Global Dimension 1 mit dem Namen `DEPARTMENT` aus) und welche Ihr Profitcenter ist (PlaidCloud geht von Global Dimension 2 mit dem Namen `PROFITCENTER` aus). Ein Standort ist ein Lagerort in Business Central.

</Steps>

## Was Sie zurückschicken

| Der Administrator schickt | Eingabe in PlaidCloud als |
|---|---|
| Die Verzeichnis-ID (Mandant) | **Azure-AD-Mandanten-ID** |
| Die Anwendungs-ID (Client) | **Client-ID** |
| Das Client-Secret | **Client-Secret**, im Verbindungseditor eingegeben, nicht per E-Mail |
| Den Namen der Umgebung, zum Beispiel `production` | **Umgebung** |
| Die ID eines Unternehmens | **Unternehmens-ID**: Die Verbindung benötigt eine, und Data Foundation liest die unter **Gesellschaften** ausgewählten Unternehmen |
| Den Namen der Dimension, die Ihre Abteilung ist | Die Systemeinstellung **Department dimension** |
| Den Namen der Dimension, die Ihr Profitcenter ist | Die Systemeinstellung **Profit centre dimension** |
| Den Quellcode, unter dem Ihre Prüfungsanpassungen gebucht werden | Die Systemeinstellung **Audit adjustment source code** |
| Die Unternehmen, die PlaidCloud lesen darf | Unter **Optionen**, **Gesellschaften**: Aktivieren Sie sie, oder keines für alle Unternehmen |

Unternehmen, die Konsolidierungsunternehmen sind, tragen Sie in der Systemeinstellung **Consolidation companies** ein, damit ihre Buchungen nicht als Aktivität eines Unternehmens zählen. Die Wechselkurse stammen aus einem Unternehmen: Nennen Sie es in der Systemeinstellung **Exchange rate company**, andernfalls verwendet PlaidCloud das erste Unternehmen.

## Zugriff prüfen

Klicken Sie danach in PlaidCloud, sobald das System hinzugefügt ist, in seiner Zeile auf der Seite **Systeme** auf **Verbindung testen**. Jedes Dataset wird als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** angezeigt:

| Dataset | Was es benötigt |
|---|---|
| Entitäten, Kontenplan, Kunden, Produkte, Wechselkurse, Saldenliste | API-Zugriff (Berechtigungssatz D365 READ) |
| Geschäftskalender | Der Webdienst `AccountingPeriods` |
| Abteilungen | Der Webdienst `DimensionValues` |
| Hauptbuch | Der Webdienst `GLEntries` |
| Jedes andere Dataset | Optional, nicht Teil des Tests |

Fehlt ein Dataset, nennt der Test die Berechtigung oder den Webdienst, der hinzuzufügen ist. Bitten Sie den Administrator, ihn hinzuzufügen, und testen Sie erneut.

Die optionalen Datasets sind Standorte, Profitcenter, Lieferanten, der Monatsendsaldo, Banksalden, Bestandssalden, Verkaufspositionen, Lieferantenrechnungspositionen, offene Posten, Zahlungen, Budgets und Verteilungstreiber. Eine Umgebung, die eines davon nicht nutzt, lädt trotzdem alles andere, und nach dem nächsten Laden nennen die Bereitschaftsprüfungen auf dem Dashboard **CFM-Accounting - Close and assurance** jede Seite, die Business Central verweigert. Der Monatsendsaldo ist die Saldenliste zu jedem Monatsende; Banksalden sind dieser Saldo für die Konten, auf die Ihre Bankkonten buchen. Verweigert Business Central einen Lesezugriff, aus dem der Monatsendsaldo, die Banksalden, der Bestand, die Verkaufspositionen, die Lieferantenrechnungspositionen, die offenen Posten oder die Zahlungen eines Monats aufgebaut werden, behält dieser Monat die Zeilen, die er bereits hatte, und wird beim nächsten Laden erneut gelesen.
