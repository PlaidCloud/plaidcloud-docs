Eine **Verbindung** ist eine gespeicherte Konfiguration, mit der PlaidCloud ein externes System erreicht — eine Datenbank, einen Data Lake, ein ERP, eine REST-API, einen Cloud-Dienst oder einen Git-Anbieter. Workflow-Schritte verweisen über den Namen auf die Verbindung, sodass Endpunktdetails und Anmeldedaten an einer Stelle liegen und in jedem Schritt und Projekt wiederverwendet werden, die sie brauchen.

Verbindungen werden unter **Tools > Connections** verwaltet.

## Verbindung erstellen

1. Öffnen Sie **Tools > Connections**
2. Klicken Sie in der Symbolleiste auf `New Connection` und wählen Sie im Menü das System, mit dem Sie sich verbinden möchten
3. Füllen Sie das Verbindungsformular aus (die Registerkarten und Felder variieren je nach Typ — siehe [Verbindungsformular](#verbindungsformular) weiter unten)
4. Klicken Sie zum Speichern auf `Create`

Die neue Verbindung erscheint in der Liste, mit Ihnen als Eigentümer.

<Aside type="note">Die Liste der Verbindungstypen und die Felder, die jeder benötigt, sind in der [Connector-Referenz](/de/reference/connectors/) katalogisiert. Für einen Dienst ohne eigenen Connector verwenden Sie die [generische REST-Verbindung](/de/reference/connectors/rest/generic-rest/).</Aside>

## Verbindungsformular

Die meisten Verbindungen öffnen ein Formular mit mehreren Registerkarten. Die genauen Registerkarten hängen vom Typ ab, häufig sehen Sie jedoch:

- **Verbindungskonfiguration** (bei REST **Verbindungsdetails**) — den Verbindungsnamen `Name`, ein optionales `Memo`, Host/Port/Datenbank (bei REST Host/Authentifizierungstyp), den Schalter `Usage` (`Active`) und das `Security Model`. Bei einer Datenbankverbindung stehen die Anmeldedaten hier in der Gruppe **Authentifizierungsdaten**; bei einer REST-Verbindung haben sie eine eigene Registerkarte **Authentifizierung**.
- **SSL-Konfiguration** — `Use SSL` sowie den SSL-Modus und optionale Client-/Root-Zertifikate für eine verschlüsselte Verbindung.
- **SSH-Konfiguration** — `Use SSH` sowie Bastion-Host, Port, Benutzer und Schlüssel, um die Verbindung über einen SSH-Jump-Host zu tunneln.

Kennwort-, Token- und andere Anmeldedatenfelder sind nur schreibbar: Sie erscheinen leer, wenn Sie eine gespeicherte Verbindung erneut öffnen, und lassen Sie sie beim Speichern leer, bleibt das gespeicherte Geheimnis erhalten. Geben Sie einen Wert nur erneut ein, wenn Sie ihn ändern möchten. Das gilt für den API-Schlüssel, das OAuth-Client-Secret und das OAuth-Refresh-Token einer REST-Verbindung. Mehrzeilige Anmeldedaten — ein privates NetSuite-Zertifikat, ein Anaplan-Zertifikat samt privatem Schlüssel, ein Postman-API-Schlüssel, eine eingehende Webhook-URL von Slack oder Teams — sind auf dieselbe Weise nur schreibbar und werden beim Eingeben oder Einfügen maskiert. Ein Ersatzwert, der nur aus Leerzeichen besteht, wird abgelehnt, statt die gespeicherten Anmeldedaten zu überschreiben; leeren Sie das Feld, um den gespeicherten Wert zu behalten. Auch der SSL-Client-Schlüssel und der private SSH-Schlüssel einer SQL- oder Git-Verbindung sind nur schreibbar, bleiben aber sichtbar, während Sie sie eingeben. Jedes andere Feld zeigt überall dort, wo die Verbindung angezeigt wird, seinen tatsächlich gespeicherten Wert, im Editor und über die API, auch Felder, die dem Namen nach sensibel wirken (das Schreibschutz-Kennzeichen einer Datenbank, eine Kontokennung, ein Schema, ein Hostname) — maskiert oder ausgeblendet werden nur tatsächliche Anmeldedaten.

Über die REST-API und MCP folgt ein Anmeldedatenfeld derselben Regel wie der Editor: Senden Sie eine leere Zeichenfolge, behält PlaidCloud den gespeicherten Wert; senden Sie `null`, um ihn zu löschen. Jedes Feld ohne Anmeldedaten wird weiterhin geleert, wenn Sie es leer senden.

Pflichtfelder werden beim Speichern validiert; fehlt etwas, wechselt das Formular zu der Registerkarte mit dem ersten ungültigen Feld und markiert es.

## Sicherheitsmodell

Das `Security Model` einer Verbindung steuert, wer im Workspace sie verwenden kann:

| Option | Wer die Verbindung verwenden kann |
|---|---|
| Privat (nur Eigentümer) | Nur die Eigentümer. |
| Nur bestimmte Mitglieder | Eigentümer plus eine ausdrückliche Liste von Mitgliedern. |
| Nur bestimmte Sicherheitsgruppen | Eigentümer plus Mitglieder benannter Sicherheitsgruppen. |
| Alle Arbeitsbereichsmitglieder | Alle im Workspace. |

Wenn Sie `Specific Members Only` oder `Specific Security Groups Only` wählen, erteilen Sie den Zugriff über das Menü `Actions` der Liste — `Members` für `Specific Members Only` oder `Groups` für `Specific Security Groups Only` sowie `Agents` und `Owners` öffnen jeweils eine Dual-Listen-Auswahl zum Hinzufügen und Entfernen von Zugriff. Nur ein Eigentümer der Verbindung oder ein Workspace-Administrator kann dort den Zugriff ändern. Alle anderen, die Verbindungen bearbeiten dürfen, können sie öffnen, um zu sehen, wer Zugriff hat, ohne ihn zu ändern. Ein Workspace-Administrator kann den Zugriff auf eine Verbindung ändern, die ihm nicht gehört, um sie weiterzugeben, wenn ihre Eigentümer ausgeschieden sind.

## Umgebungen

Eine Verbindung kann pro **Umgebung** eine andere Konfiguration enthalten (zum Beispiel einen Entwicklungs-Host und einen Produktions-Host unter einem Verbindungsnamen). Die Umgebungsauswahl in der Symbolleiste bestimmt, die Konfiguration welcher Umgebung Sie ansehen und bearbeiten.

- `New Environment` — eine Verbindungsumgebung hinzufügen
- `Edit Environment` — die ausgewählte Umgebung umbenennen
- `Delete Environment` — die ausgewählte Umgebung entfernen

Die Spalte `Available` in der Liste zeigt, ob die ausgewählte Verbindung für die gewählte Umgebung konfiguriert ist.

<Aside type="note">Beim Speichern wird eine Konfiguration in die gespeicherte für diese Umgebung zusammengeführt, sodass leere, nur schreibbare Geheimnisse nie mit leeren Werten überschrieben werden.</Aside>

Umgebungen werden mit PlaidLink-Agents geteilt, sodass die Umgebung eines Projekts sowohl den Agent umschalten kann, der seine Remote-Schritte ausführt, als auch die Verbindungen, die es liest. Siehe [Agent-Umgebungen](/de/reference/cli/plaidlink/agents/#agent-umgebungen).

## Verbindung bearbeiten

1. Wählen Sie die Verbindung in der Liste aus
2. Klicken Sie in der Symbolleiste auf `Edit` (oder klicken Sie mit der rechten Maustaste auf die Zeile)
3. Ändern Sie die Felder und klicken Sie auf `Update`

## Verbindung testen

Wie Sie testen, hängt vom Typ ab:

- **Datenbankverbindungen** — Databricks, Snowflake, PostgreSQL und Redshift — haben im Editor eine Schaltfläche **Verbindung testen**. Sie öffnet die Verbindung mit den eingegebenen Anmeldedaten und meldet den Erfolg (mit der erreichten Serverversion) oder den Grund des Fehlschlags, ohne den Editor zu schließen, sodass Sie direkt korrigieren und es erneut versuchen können.
- Datenbankverbindungen mit SSH bieten auf der Registerkarte `SSH Config` außerdem einen Test für den SSH-Tunnel.
- Die [generische REST-Verbindung](/de/reference/connectors/rest/generic-rest/) hat eine Registerkarte `Testing`, die über die gespeicherte Verbindung eine Ad-hoc-Anfrage sendet.

Speichern Sie die Verbindung vor dem Testen — Tests laufen gegen die gespeicherte Konfiguration.

<Aside type="note">**Verbindung testen** erscheint bei einer Verbindungsart, sobald ihr Editor es anbietet — derzeit die oben genannten Datenbanktypen sowie [TM1](/de/guides/connections/tm1/), [Oracle Essbase](/de/guides/connections/essbase/), [HFM/FCCS](/de/guides/connections/hfm-fccs/), Salesforce und Anaplan. Andere REST-Verbindungen, etwa NetSuite, bieten es noch nicht — prüfen Sie diese per Smoke-Test, indem Sie aus einem Workflow-Schritt eine kleine Anfrage senden (zu NetSuite siehe [Mit NetSuite verbinden](/de/guides/connections/netsuite/#die-verbindung-per-smoke-test-prüfen)).</Aside>

## Klonen, Löschen und Verwendung nachverfolgen

- **Klonen** — die Konfiguration einer Verbindung als Grundlage für eine neue duplizieren. Siehe [Verbindung klonen](/de/guides/connections/clone-connection/).
- **Löschen** — die ausgewählte Verbindung über die Symbolleiste entfernen (Sie werden um Bestätigung gebeten).
- **Verwendungsnachweis…** — die Workflow-Schritte auflisten, die auf die Verbindung verweisen, damit Sie die Auswirkungen sehen, bevor Sie sie bearbeiten oder löschen.

<Aside type="caution">`Edit`, `Clone` und `Delete` stehen nur für Verbindungen zur Verfügung, die Ihnen gehören. Sind diese Aktionen für die ausgewählte Zeile ausgegraut, sind Sie kein Eigentümer — bitten Sie einen Eigentümer, die Änderung vorzunehmen oder Sie über `Owners` hinzuzufügen.</Aside>
