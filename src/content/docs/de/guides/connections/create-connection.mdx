Eine **Verbindung** ist eine gespeicherte Konfiguration, mit der PlaidCloud ein externes System erreicht – eine Datenbank, einen Data Lake, ein ERP, eine REST-API, einen Cloud-Dienst oder einen Git-Anbieter. Workflow-Schritte verweisen über den Namen auf die Verbindung, sodass Endpunktdetails und Zugangsdaten an einer Stelle liegen und in jedem Schritt und Projekt, das sie benötigt, wiederverwendet werden.

Verbindungen werden unter **Tools > Connections** verwaltet.

## Eine Verbindung erstellen

1. Öffnen Sie **Tools > Connections**
2. Klicken Sie in der Symbolleiste auf `New Connection` und wählen Sie im Menü das System aus, mit dem Sie sich verbinden möchten
3. Füllen Sie das Verbindungsformular aus (die Registerkarten und Felder variieren je nach Typ – siehe [Verbindungsformular](#verbindungsformular) unten)
4. Klicken Sie zum Speichern auf `Create`

Die neue Verbindung erscheint in der Liste, mit Ihnen als Eigentümer.

Acumatica-, Bill.com-, Dynamics-, Eclipse-, HFM/FCCS-, NetSuite-, Workday- und Workday-Financials-Verbindungen werden als REST-Verbindungen gespeichert, daher zeigt die Spalte **Typ** in der Liste für sie **REST** an. Jede öffnet sich in einem eigenen Formular zum Erstellen, Bearbeiten und Auswählen in Schritten. Header, Authentifizierung und Paginierung finden Sie unter **Edit REST settings** (siehe [Eine Verbindung bearbeiten](#eine-verbindung-bearbeiten)).

<Aside type="note">Die Liste der Verbindungstypen und die Felder, die jeder benötigt, sind in der [Connectors-Referenz](/de/reference/connectors/) katalogisiert. Verwenden Sie für einen Dienst ohne dedizierten Connector die [generische REST-Verbindung](/de/reference/connectors/rest/generic-rest/).</Aside>

## Verbindungsformular

Die meisten Verbindungen öffnen ein Formular mit mehreren Registerkarten. Die genauen Registerkarten hängen vom Typ ab, häufig sehen Sie jedoch:

- **Verbindungskonfiguration** (bei REST **Verbindungsdetails**) – den Verbindungsnamen `Name`, ein optionales `Memo`, Host/Port/Datenbank (bzw. Host/Authentifizierungstyp bei REST), den Schalter `Usage` (`Active`) und das `Security Model`. Bei einer Datenbankverbindung stehen die Zugangsdaten hier in einer Gruppe **Authentifizierungsdaten**; bei einer REST-Verbindung haben sie eine eigene Registerkarte **Authentifizierung**.
- **SSL-Konfiguration** – `Use SSL` sowie den SSL-Modus und optionale Client-/Stammzertifikate für eine verschlüsselte Verbindung.
- **SSH-Konfiguration** – `Use SSH` sowie Bastion-Host, Port, Benutzer und Schlüssel, um die Verbindung über einen SSH-Jump-Host zu tunneln.

Felder für Passwörter, Token und andere Zugangsdaten sind nur schreibbar: Sie erscheinen leer, wenn Sie eine gespeicherte Verbindung erneut öffnen, und wenn Sie sie beim Speichern leer lassen, bleibt das gespeicherte Geheimnis erhalten. Geben Sie einen Wert nur erneut ein, wenn Sie ihn ändern möchten. Das gilt für den API-Schlüssel, das OAuth-Client-Secret und das OAuth-Refresh-Token einer REST-Verbindung. Mehrzeilige Zugangsdaten – ein privates NetSuite-Zertifikat, ein Anaplan-Zertifikat und privater Schlüssel, ein Postman-API-Schlüssel, eine eingehende Webhook-URL von Slack oder Teams – sind auf dieselbe Weise nur schreibbar und werden beim Tippen oder Einfügen maskiert. Ein Ersatzwert, der nur aus Leerzeichen besteht, wird abgelehnt, statt über die gespeicherten Zugangsdaten geschrieben zu werden; leeren Sie das Feld, um den gespeicherten Wert beizubehalten. Der SSL-Clientschlüssel und der private SSH-Schlüssel einer SQL- oder Git-Verbindung sind ebenfalls nur schreibbar, bleiben aber sichtbar, während Sie sie eingeben. Jedes andere Feld zeigt überall dort, wo die Verbindung angezeigt wird, seinen tatsächlich gespeicherten Wert, im Editor und über die API, auch Felder, die dem Namen nach sensibel wirken (das Nur-Lese-Kennzeichen einer Datenbank, eine Kontokennung, ein Schema, ein Hostname) – maskiert oder verborgen wird immer nur echte Zugangsdaten.

Über die REST-API und MCP folgt ein Zugangsdatenfeld derselben Regel wie im Editor: Senden Sie eine leere Zeichenfolge, behält PlaidCloud den gespeicherten Wert bei; senden Sie `null`, um ihn zu löschen. Jedes Feld, das keine Zugangsdaten enthält, wird weiterhin geleert, wenn Sie es leer senden.

Pflichtfelder werden beim Speichern geprüft; fehlt etwas, wechselt das Formular zu der Registerkarte mit dem ersten ungültigen Feld und kennzeichnet es.

## Sicherheitsmodell

Das `Security Model` einer Verbindung steuert, wer im Workspace sie verwenden darf:

| Option | Wer die Verbindung verwenden darf |
|---|---|
| Privat (nur Eigentümer) | Nur die Eigentümer. |
| Nur bestimmte Mitglieder | Eigentümer sowie eine ausdrückliche Liste von Mitgliedern. |
| Nur bestimmte Sicherheitsgruppen | Eigentümer sowie Mitglieder benannter Sicherheitsgruppen. |
| Alle Arbeitsbereichsmitglieder | Alle im Workspace. |

Wenn Sie `Specific Members Only` oder `Specific Security Groups Only` wählen, erteilen Sie den Zugriff über das Menü `Actions` der Liste – `Members` für `Specific Members Only` oder `Groups` für `Specific Security Groups Only`, dazu `Agents` und `Owners`, öffnen jeweils eine filterbare Checkliste, in der Sie aktivieren, wer Zugriff hat (siehe [Zuweisen mit der Auswahl](/de/administration/access/managing-security-groups-and-assignments/#zuweisen-mit-der-auswahl)). Nur ein Eigentümer der Verbindung oder ein Workspace-Administrator kann dort den Zugriff ändern. Alle anderen, die Verbindungen bearbeiten können, können sie öffnen, um zu sehen, wer Zugriff hat, in einer schreibgeschützten Liste der bereits zugewiesenen Personen. Ein Workspace-Administrator kann den Zugriff auf eine Verbindung ändern, deren Eigentümer er nicht ist, um sie weiterzugeben, wenn ihre Eigentümer das Unternehmen verlassen haben.

## Wer die Zugangsdaten einer Verbindung sieht

Jeder, der eine Verbindung verwenden darf, kann sie öffnen und ihre Einstellungen sehen sowie die Repositories, Branches und Dateien einer Git-Verbindung durchsuchen. Die Passwörter, Token und Schlüssel einer Verbindung werden nur an Mitglieder zurückgegeben, die Verbindungen oder Workflows bearbeiten dürfen. Über die REST-API und MCP erhalten alle anderen sie maskiert.

Wenn Sie eine Git-Verbindung mit einer anderen Server-URL als der gespeicherten durchsuchen, geben Sie ein Token für diesen Server ein.

## Umgebungen

Eine Verbindung kann pro **Umgebung** eine andere Konfiguration enthalten (zum Beispiel einen Entwicklungs-Host und einen Produktions-Host unter einem Verbindungsnamen). Die Umgebungsauswahl in der Symbolleiste bestimmt, die Konfiguration welcher Umgebung Sie anzeigen und bearbeiten.

- `New Environment` – eine Verbindungsumgebung hinzufügen
- `Edit Environment` – die ausgewählte Umgebung umbenennen
- `Delete Environment` – die ausgewählte Umgebung entfernen, sobald kein Projekt sie verwendet, kein Schritt sie als [feste Umgebung](/de/guides/projects/managing-projects/#einen-schritt-auf-eine-umgebung-festlegen) hat und kein Agent sie bedient. Andernfalls nennt die Meldung, was sie noch verwendet. Die Standardumgebung kann nicht gelöscht werden.

Die Spalte `Available` in der Liste zeigt, ob die ausgewählte Verbindung für die gewählte Umgebung konfiguriert ist.

<Aside type="note">Beim Speichern wird eine Konfiguration in die gespeicherte Konfiguration dieser Umgebung eingemischt, sodass leere, nur schreibbare Geheimnisse nie mit leeren Werten überschrieben werden.</Aside>

Umgebungen werden mit PlaidLink-Agenten geteilt, sodass die Umgebung eines Projekts den Agenten umschalten kann, der seine Remote-Schritte ausführt, sowie die Verbindungen, die es liest. Siehe [Agent-Umgebungen](/de/reference/cli/plaidlink/agents/#agent-umgebungen).

## Eine Verbindung bearbeiten

1. Wählen Sie die Verbindung in der Liste aus
2. Klicken Sie in der Symbolleiste auf `Edit` (oder klicken Sie mit der rechten Maustaste auf die Zeile)
3. Ändern Sie die Felder und klicken Sie auf `Update`

Bei einer Acumatica-, Bill.com-, Dynamics-, Eclipse-, HFM/FCCS-, NetSuite-, Workday- oder Workday-Financials-Verbindung öffnet `Edit` das eigene Formular des jeweiligen Dienstes. Um die Header, die Authentifizierung oder die Paginierung der zugrunde liegenden REST-Verbindung zu ändern, wählen Sie die Verbindung aus und wählen Sie im Menü **Verbindungen** die Option `Edit REST settings`, oder klicken Sie mit der rechten Maustaste auf die Zeile.

## Eine Verbindung testen

Wie Sie testen, hängt vom Typ ab:

- **Datenbankverbindungen** – Databricks, Snowflake, PostgreSQL und Redshift – haben im Editor eine Schaltfläche **Verbindung testen**. Sie öffnet die Verbindung mit den eingegebenen Zugangsdaten und meldet den Erfolg (mit der erreichten Serverversion) oder den Grund des Fehlschlags, ohne den Editor zu schließen, sodass Sie direkt korrigieren und es erneut versuchen können.
- Datenbankverbindungen mit SSH bieten außerdem einen Test für den SSH-Tunnel auf der Registerkarte `SSH Config`.
- Die [generische REST-Verbindung](/de/reference/connectors/rest/generic-rest/) hat eine Registerkarte `Testing`, die eine Ad-hoc-Anfrage über die gespeicherte Verbindung sendet.

Speichern Sie die Verbindung vor dem Testen – Tests laufen gegen die gespeicherte Konfiguration.

<Aside type="note">**Verbindung testen** erscheint bei einer Verbindungsart, sobald ihr Editor es anbietet – derzeit die oben genannten Datenbanktypen sowie [TM1](/de/guides/connections/tm1/), [Oracle Essbase](/de/guides/connections/essbase/), [HFM/FCCS](/de/guides/connections/hfm-fccs/), [NetSuite](/de/guides/connections/netsuite/), Salesforce und Anaplan. Testen Sie andere REST-Verbindungen per Smoke-Test, indem Sie eine kleine Anfrage aus einem Workflow-Schritt senden.</Aside>

## Adressen, die eine Verbindung nicht erreichen kann

Eine Verbindung kann nicht auf eine Loopback-, Link-Local- oder Cloud-Metadaten-Adresse zeigen. PlaidCloud prüft die Adresse, in die ein Hostname aufgelöst wird, wenn Sie die Verbindung testen und wenn ein Schritt sie verwendet, und eine Adresse, die nicht zulässig ist, schlägt mit einem Fehler fehl, der den Host und die Adresse nennt, in die er aufgelöst wurde. Adressen in Ihrem privaten Netzwerk sind davon nicht betroffen.

## Klonen, Löschen und Verwendung nachverfolgen

- **Klonen** – die Konfiguration einer Verbindung als Grundlage für eine neue duplizieren. Siehe [Eine Verbindung klonen](/de/guides/connections/clone-connection/).
- **Löschen** – die ausgewählte Verbindung über die Symbolleiste entfernen (Sie werden um Bestätigung gebeten).
- **Verwendungsnachweis…** – die Workflow-Schritte auflisten, die auf die Verbindung verweisen, damit Sie die Auswirkungen sehen, bevor Sie sie bearbeiten oder löschen.

<Aside type="caution">`Edit`, `Clone` und `Delete` sind nur für Verbindungen verfügbar, deren Eigentümer Sie sind. Wenn diese Aktionen für die ausgewählte Zeile ausgegraut sind, sind Sie kein Eigentümer – bitten Sie einen Eigentümer, die Änderung vorzunehmen oder Sie über `Owners` hinzuzufügen.</Aside>

Dasselbe gilt über die REST-API, JSON-RPC und den KI-Assistenten bzw. MCP: Um die Einstellungen einer Verbindung zu ändern, müssen Sie einer ihrer Eigentümer sein, oder bei einer Verbindung ohne Eigentümer ein Workspace-Administrator. Das Aktivieren, Deaktivieren, Sperren und Entsperren einer Verbindung erfordert einen Eigentümer oder einen Workspace-Administrator. Eine Anfrage, die mehrere Verbindungen nennt, wird nur angewendet, wenn Sie jede davon ändern dürfen.
