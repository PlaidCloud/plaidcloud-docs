Verbinden Sie PlaidCloud mit **Anaplan**, damit ein Workflow eine gespeicherte Ansicht über den Large-Volume-Leseweg von Anaplan lesen, eine bereits vorhandene Exportaktion ausführen oder eine oder mehrere Anaplan-Listen in eine PlaidCloud-Dimension einlesen kann. Die Verbindung greift **Cloud-direkt** auf die Integration API von Anaplan zu – für diese Schritte gibt es keinen Weg über einen lokalen Agent. Diese Anleitung behandelt die Verbindung, die Authentifizierung, eine kurze Einführung in jeden der drei Leseschritte und Hinweise zu Zeitplänen.

<Aside type="note">
Dieser Konnektor ist rein lesend. Es wird nie etwas nach Anaplan zurückgeschrieben – es gibt weder einen Rückschreibe-Schritt noch einen Modus für teilweises Übernehmen.
</Aside>

## Voraussetzungen

Von Ihrem Anaplan Workspace Administrator benötigen Sie:

- Entweder einen Anaplan-**Benutzernamen und ein Passwort** oder ein **CA-Zertifikat samt privatem Schlüssel**, das Ihr Workspace Administrator einem Anaplan-Benutzer zugeordnet hat – mit Lesezugriff auf den Workspace und die Modelle, die Ihre Workflows lesen werden. Siehe [Authentifizierung](#authentifizierung) weiter unten.
- Die **Workspace-ID** und die **Modell-ID** der Modelle, aus denen Sie lesen, sichtbar in den Modelleinstellungen von Anaplan. Beide lassen sich nach dem Erstellen der Verbindung auch live über die Verbindung ermitteln.
- Für **Anaplan: Ansicht lesen** – eine **gespeicherte Ansicht**, die genau den gewünschten Ausschnitt aus Zeilen, Spalten und Filtern enthält. Siehe [Anaplan: Ansicht lesen](#anaplan-ansicht-lesen) weiter unten.
- Für **Anaplan: Export lesen** – eine **bereits vorhandene Exportaktion** im Modell.
- Für **Anaplan: Liste lesen** – die Anaplan-**Listen**, aus denen die Hierarchie besteht, die Sie lesen möchten.

## Authentifizierung

Die Verbindung hat einen **Authentifizierungsmodus**: **Einfach** (Standard) oder **Zertifikat**. Eine bestehende Verbindung funktioniert unverändert als Einfach weiter.

- **Einfach** meldet sich mit einem Anaplan-Benutzernamen und einem Passwort an.
- **Zertifikat** meldet sich mit einem von einer CA ausgestellten Zertifikat und dessen privatem Schlüssel an, beide als PEM-Text eingefügt. Der private Schlüssel muss **RSA und unverschlüsselt** sein, und das Zertifikat muss dasjenige sein, das Ihr Anaplan Workspace Administrator Ihrem Anaplan-Benutzer zugeordnet hat – ausgestellt von einer CA, der Anaplan für Ihren Tenant vertraut. PlaidCloud signiert eine zufällige Challenge mit dem Schlüssel und tauscht sie gemäß dem Zertifikatsauthentifizierungs-Ablauf von Anaplan gegen ein Anaplan-Token ein; nach dem Einfügen von Zertifikat und Schlüssel ist nichts weiter zu tun, und die Token-Erneuerung funktioniert wie im Modus Einfach. Beide Felder maskieren, was Sie einfügen, beide Geheimnisse werden wie ein Passwort im Modus Einfach verschlüsselt gespeichert, und beim Wechsel des Modus werden nie die Zugangsdaten des jeweils anderen Modus gesendet – wenn Sie eine bestehende Verbindung von Einfach auf Zertifikat umstellen, müssen Sie Zertifikat und Schlüssel einfügen, da sie nicht übernommen werden.

Die Multi-Faktor-Authentifizierung von Anaplan gilt für Benutzer, die sich mit E-Mail und Passwort anmelden. Die Zertifikatsauthentifizierung ist die passwortlose Option für eine automatisierte, nach Zeitplan laufende Verbindung.

Der Modus Zertifikat bricht ab, bevor Anaplan kontaktiert wird, wenn der eingefügte Schlüssel oder das Zertifikat nicht gelesen werden kann, der Schlüssel verschlüsselt oder nicht RSA ist oder der Schlüssel nicht zum Zertifikat passt. Lehnt Anaplan selbst das Zertifikat ab, nennt die Fehlermeldung, ob es abgelaufen ist; übliche Ursachen sind ein Zertifikat, das keinem Anaplan-Benutzer zugeordnet ist, oder eine CA, der für Ihren Tenant nicht vertraut wird.

## Verbindung erstellen

<Steps>

1. Öffnen Sie **Tools > Connections** und klicken Sie auf `New Connection`.

2. Wählen Sie im Menü **Anaplan** aus.

3. Füllen Sie die Felder aus:

   | Feld | Wert |
   |---|---|
   | Name | Ein sprechender Name, zum Beispiel `Anaplan Prod`. |
   | API-Host | Optional. Leer lassen für den Standardwert von Anaplan, `https://api.anaplan.com`. |
   | Authentifizierungshost | Optional. Leer lassen für den Standardwert von Anaplan, `https://auth.anaplan.com`. |
   | Authentifizierungsmodus | **Einfach** (Standard) oder **Zertifikat**. Siehe [Authentifizierung](#authentifizierung) oben. |
   | Benutzername | Der Benutzername des Anaplan-Kontos. Nur im Modus Einfach. |
   | Passwort | Das Passwort des Anaplan-Kontos. Nur im Modus Einfach. |
   | CA-Zertifikat | PEM-Text des in Anaplan registrierten X.509-Zertifikats. Nur im Modus Zertifikat. |
   | Privater Schlüssel | PEM-Text des privaten RSA-Schlüssels des Zertifikats, unverschlüsselt. Nur im Modus Zertifikat. |
   | Standard-Arbeitsbereichs-ID | Optional. Eine Vorbelegung für das Feld Workspace eines Leseschritts. |
   | Standard-Modell-ID | Optional. Eine Vorbelegung für das Feld Model eines Leseschritts. |
   | Timeout (Sekunden) | Standardmäßig 30. |

4. Klicken Sie auf `Test Connection`. Ein erfolgreicher Test meldet die E-Mail-Adresse des Anaplan-Kontos, zu dem die Zugangsdaten gehören.

5. Klicken Sie auf `Create`.

</Steps>

## Anaplan: Ansicht lesen

Fügen Sie einen Schritt **Anaplan: Ansicht lesen** hinzu, um eine gespeicherte Ansicht über den Large-Volume-Leseweg von Anaplan zu lesen. **Die Ansicht wird genau so gelesen, wie sie in Anaplan gespeichert wurde – dieser Schritt bietet keine Auswahl von Zeilen, Spalten oder Seiten.** Um einen anderen Ausschnitt zu lesen, erstellen Sie in Anaplan eine andere gespeicherte Ansicht; ein Boolesches Line Item zusammen mit einer gespeicherten Ansicht ist dort der übliche Weg zum Filtern. Eine Datenspalte erhält ihren deklarierten Anaplan-Typ nur dann, wenn die Ansicht die **Line Items auf der Spaltenachse** hat; sind die Line Items auf den Zeilen (ein üblicher GuV-Aufbau) oder fehlen sie in der Ansicht, landet jede Spalte stattdessen als Text, und der Schritt weist darauf hin. Eine Ansicht, deren Filter nichts findet, landet als leere Tabelle mit einer Warnung. Ein Zahlenwert, den der Schritt nicht eindeutig lesen kann – meist einer, der ebenso gut eine einfache Dezimalzahl oder eine Darstellung im europäischen Format sein könnte –, wird abgelehnt statt geraten, es sei denn, ein anderer Wert derselben Spalte entscheidet, welche Lesart richtig ist; ein Wert, der sich lesen lässt, landet in voller Genauigkeit ohne Rundungsfehler. Das vollständige Feld- und Verhaltensreferenz finden Sie unter [Anaplan: Ansicht lesen](/de/reference/workflow-steps/anaplan/anaplan-read-view/).

## Anaplan: Export lesen

Fügen Sie einen Schritt **Anaplan: Export lesen** hinzu, um eine **bereits vorhandene** Anaplan-Exportaktion auszuführen und die erzeugte Datei zu laden. Die API kann keine Exportaktion anlegen – erstellen oder bearbeiten Sie sie zuerst in Anaplan –, und der Schritt kann die Ausgabe nicht einschränken: Es landet genau das, was die Aktion in Anaplan zu exportieren konfiguriert ist. **Jede Spalte landet als Text.** Zahlen werden im US-Format angefordert; eine Spalte, die dennoch mit Tausendertrennzeichen zurückkommt, landet unverändert als Text mit einer benannten Warnung, statt die Ausführung scheitern zu lassen. Der Schritt bricht ab, statt eine Tabelle zu laden, wenn der Export fehlschlägt, abgebrochen wird, keine Daten liefert, nach Ablauf des Abfragebudgets des Schritts noch läuft oder eine Datei erzeugt, die sich nicht dem Export zuordnen lässt oder deren Zeilenanzahl von dem abweicht, was Anaplan selbst meldet. Die vollständige Referenz finden Sie unter [Anaplan: Export lesen](/de/reference/workflow-steps/anaplan/anaplan-read-export/).

## Anaplan: Liste lesen

Fügen Sie einen Schritt **Anaplan: Liste lesen** hinzu, um eine oder mehrere Anaplan-Listen in eine PlaidCloud-Dimension einzulesen. **Ein Schritt liest eine ganze zusammengesetzte Hierarchie** – nennen Sie alle Listen, über die sie sich erstreckt, beginnend mit der Wurzel (zum Beispiel Region, dann Land, dann Filiale), statt sie auf mehrere Schritte aufzuteilen; die Staging-Tabelle wird bei jeder Ausführung ersetzt, sodass mehrere Schritte, die auf dieselbe Staging-Tabelle zeigen, jeweils die Zeilen des vorherigen löschen würden. Jede Kante wird mit einem einfachen `+` aufsummiert, da Anaplan-Listenhierarchien keine Gewichtung oder kein Vorzeichen pro Kante enthalten, das gelesen werden könnte. Die Zugriffssteuerung und die Teilmengenzugehörigkeit von Anaplan-Listen werden nicht importiert – sie sind Metadaten, keine Dimensionsdaten. Doppelte Knoten-IDs, eine nicht auflösbare Elternreferenz, widersprüchliche Elternreferenzen und ein Eigenschaftsname, der mit importierten Metadaten kollidiert, werden alle abgelehnt, bevor etwas landet. Die vollständige Referenz finden Sie unter [Anaplan: Liste lesen](/de/reference/workflow-steps/anaplan/anaplan-read-list/).

## Anaplan als Quelle für Data Foundation

[Data Foundation](/de/guides/projects/data-foundation/) kann den in Anaplan gehaltenen Plan – ein Budget, eine Prognose oder die Ergebnisse eines Konsolidierungsmodells – in sein Common Finance Model einlesen. Es holt den Plan herein, nie das Hauptbuch, und liest nur.

Data Foundation führt eine Exportaktion des Modells so aus, wie sie gespeichert ist; Ihr Anaplan-Administrator erstellt diesen Export daher zuerst. Die Registerkarte **Foundation** formuliert die Anforderung für ihn. Der Export muss ein flaches Raster mit einer Zeile je Entität, Periode, Konto und Abteilung sein, mit genau diesen Spaltenüberschriften:

| Spalte | Enthält |
|---|---|
| `Entity` | Den Entitätscode. |
| `Period` | Den Monat im Format `YYYY-MM`. |
| `Account` | Den Kontocode. |
| `Department` | Den Abteilungscode, leer, wenn der Plan keine hat. |
| `Currency` | Die Währung des Betrags. |
| `Amount` | Eine einfache Zahl ohne Tausendertrennzeichen, mit dem Vorzeichen, in dem der Plan geführt wird (Erlöse positiv). |

Fügen Sie die Verbindung dann wie jede andere auf der Registerkarte **Foundation** als Quelle hinzu (siehe [ERP verbinden](/de/guides/projects/data-foundation/#erp-verbinden)) und wählen Sie:

| Einstellung | Bedeutung |
|---|---|
| Export | Die ID der auszuführenden Exportaktion. |
| Szenario | **Budget** (Standard), **Prognose** oder **Konsolidiert**, für die Ergebnisse eines Konsolidierungsmodells, mit denen die Konzern-Gewinn- und Verlustrechnung abgestimmt wird. |
| Version | Eine Bezeichnung, die jeder Zeile aufgeprägt wird. Standardmäßig `Anaplan`. |
| Entitäten | Die Entitäten des Exports, die behalten werden. Anaplan listet keine zur Auswahl auf, geben Sie sie daher ein; leer behält jede Entität. |

Beträge werden unverändert im natürlichen Vorzeichen gelesen. Eine Spalte, die weiterhin mit Tausendertrennzeichen gruppiert zurückkommt, wird markiert statt geraten, wie bei [Anaplan: Export lesen](/de/reference/workflow-steps/anaplan/anaplan-read-export/).

## Hinweise zu Zeitplänen

Das Anfragenbudget von Anaplan wird **tenantweit geteilt** – über jede Integration Ihrer Organisation gegen diesen Anaplan-Tenant, nicht nur über PlaidCloud –, und PlaidCloud koordiniert keine Zeitpläne über gleichzeitige Ausführungen hinweg. Mehrere Anaplan-Schritte, die in derselben Cron-Minute laufen, können dieses Budget erschöpfen, bevor einer von ihnen fertig ist. **Staffeln Sie die Zeitpläne Ihrer Anaplan-Workflows**, statt sie alle gleichzeitig auszuführen.
