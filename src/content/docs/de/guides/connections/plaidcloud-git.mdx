Eine **PlaidCloud-Git-Verbindung** richtet einen Workflow – oder den Build einer Server-Panel-App – auf ein Repository auf dem eigenen verwalteten Git-Server Ihres Workspace. Da dieser Git-Server für Sie unter `git.<your-workspace>.plaid.cloud` gehostet wird und Sie bereits über Ihre normale PlaidCloud-Anmeldung angemeldet sind, ist das Verbindungsformular deutlich einfacher als das eines externen Git-Anbieters: Es gibt keine Server-URL einzugeben und keinen Benutzernamen, kein Token und keinen SSH-Schlüssel zu verwalten.

<Aside type="note">Für eine PlaidCloud-Git-Verbindung geben Sie nie eine Server-URL oder Anmeldedaten ein. Der Git-Server Ihres Workspace und Ihr Zugriff darauf werden automatisch über Ihre PlaidCloud-Anmeldung (einschließlich SSO) abgewickelt – es gibt also keine Token zu erzeugen, zu speichern oder zu rotieren.</Aside>

## Wann Sie sie verwenden

Greifen Sie zu einer PlaidCloud-Git-Verbindung, wenn das Repository, aus dem Sie lesen möchten, in [PlaidCloud Git](/de/guides/git/) liegt – dem integrierten Git-Dienst Ihres Workspace – statt bei einem externen Host. Der häufigste Einsatz ist die Automatisierung von Builds von **Server-Panel-Apps** oder **Dash-Apps** aus einem verwalteten Repository, sodass ein Push auf einen Branch die App neu erstellt und erneut bereitstellt, ohne dass ein externes GitHub-Konto oder ein persönliches Zugriffstoken im Spiel ist.

Für ein Repository, das bei einem externen Dienst gehostet wird – GitHub, GitLab, Bitbucket, Forgejo oder Gitea –, verwenden Sie stattdessen eine [externe Git-Verbindung](/de/reference/connectors/git/). Diese behalten das vollständige Formular mit einer **Server-URL**, Benutzer-/Token- oder SSO-Authentifizierung sowie den Registerkarten **SSL** und **SSH**.

## Eine PlaidCloud-Git-Verbindung erstellen

1. Öffnen Sie **Tools > Connections**
2. Klicken Sie auf `New Connection` und wählen Sie im Menü **PlaidCloud Git**
3. Füllen Sie das vereinfachte Formular aus:
   - **Kontoname** – ein Anzeigename für die Verbindung
   - **Notiz** – ein optionaler Hinweis, wofür die Verbindung gedacht ist
   - **Repository** – klicken Sie auf `Refresh`, um die Repositories aufzulisten, die Ihr Workspace erreichen kann, und wählen Sie dann eines (zum Beispiel Ihr Repository `udfs` oder `apps`). Sie wählen aus der Liste, statt den Pfad einzutippen.
   - **Standardbranch** – wählen Sie aus der Liste der Branches im ausgewählten Repository den Branch, der standardmäßig gelesen wird
   - **Startpfad** – durchsuchen Sie optional das Repository und wählen Sie einen Ordner, um jede Dateisuche auf einen Unterordner zu beschränken; lassen Sie ihn leer, um das gesamte Repository zu verwenden
4. Legen Sie die **Verwendung** fest – `Active`, um die Verbindung zu aktivieren, und `Read Only`, wenn die Verbindung nie schreiben soll
5. Legen Sie das **Sicherheitsmodell** fest – wer im Workspace die Verbindung verwenden darf
6. Klicken Sie zum Speichern auf `Create`

Das ist das gesamte Formular. Anders als bei einem externen Git-Anbieter gibt es keine Server-URL, keine Registerkarte für die Authentifizierung und keine SSL- oder SSH-Konfiguration – all das wird für Sie erledigt.

<Aside type="note">Repository, Standardbranch und Startpfad werden aus Live-Listen gewählt – wählen Sie zuerst ein Repository, dann seinen Branch und navigieren Sie dann zu einem Ordner –, sodass nichts falsch eingetippt werden kann. Jede Liste wird mit dem eigenen Zugriff der Verbindung gelesen, sodass sie bei einer PlaidCloud-Git-Verbindung sofort gefüllt wird, ohne dass Anmeldedaten einzugeben sind.</Aside>

## Sicherheitsmodell

Das `Security Model` steuert, wer im Workspace die Verbindung verwenden kann:

| Option | Wer die Verbindung verwenden kann |
|---|---|
| Privat (nur Eigentümer) | Nur die Eigentümer. |
| Nur bestimmte Mitglieder | Eigentümer plus eine ausdrückliche Liste von Mitgliedern. |
| Nur bestimmte Sicherheitsgruppen | Eigentümer plus Mitglieder benannter Sicherheitsgruppen. |
| Alle Arbeitsbereichsmitglieder | Alle im Workspace. |

Für `Specific Members Only` oder `Specific Security Groups Only` erteilen Sie den Zugriff nach dem Speichern über das Menü `Actions` der Liste. Die gemeinsamen Verbindungsmechanismen finden Sie unter [Verbindung erstellen und verwalten](/de/guides/connections/create-connection/#sicherheitsmodell).

## Panel-App- und Dash-App-Builds aus verwaltetem Git automatisieren

Eine [Server-Panel-App](/de/guides/panel-apps/creating/) oder eine [Dash-App](/de/guides/dash-apps/) wird aus einem Git-Branch erstellt und bei jedem Push auf diesen Branch automatisch neu erstellt. Wenn Sie sie auf eine PlaidCloud-Git-Verbindung richten, bleibt der gesamte Kreislauf in Ihrem Workspace – ohne externen Host und ohne persönliches Zugriffstoken, das gültig gehalten werden muss.

1. Pushen Sie Ihre App in ein Repository auf dem PlaidCloud-Git-Server Ihres Workspace – eine `.py`-Datei als Einstiegspunkt (bei Panel ruft sie `.servable()` auf; bei Dash stellt sie `server = app.server` bereit) und eine optionale `requirements.txt` im Repository-Stammverzeichnis oder neben Ihrem Einstiegspunkt. Das Repository-Layout finden Sie unter [Eine Panel-App erstellen](/de/guides/panel-apps/creating/#ihr-app-repository-vorbereiten) oder [Eine Dash-App aus PlaidCloud Git bereitstellen](/de/guides/dash-apps/deploy-from-git/).
2. Erstellen Sie nach den obigen Schritten eine PlaidCloud-Git-Verbindung, deren **Repository** dieses Repository ist.
3. Klicken Sie unter **Meine Panel-Apps** auf **Neue Server-App** oder **Neue Dash-App** und gehen Sie unter **Git-Verbindung und Veröffentlichungsüberwachung** wie folgt vor:
   - **Git-Verbindung** – wählen Sie die soeben erstellte PlaidCloud-Git-Verbindung
   - **Branch** – der Branch, aus dem erstellt wird; Pushes darauf erstellen die App neu und stellen sie erneut bereit
   - **Einstiegspunkt** – die `.py`-Datei, die die App ausliefern soll
4. Schließen Sie den Veröffentlichungsdialog ab und klicken Sie auf **Veröffentlichen**.

Von da an erstellt jeder Push auf diesen Branch auf Ihrem verwalteten Git-Server die App neu – ein durchgängig automatisierter Build, der PlaidCloud nie verlässt.
