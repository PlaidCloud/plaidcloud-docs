[Data Foundation](/de/guides/projects/data-foundation/) führt Daten aus jedem ERP-System und jeder Instanz, die Sie verbinden, in einem Common Finance Model zusammen, und NetSuite ist eines der ERPs, die es direkt liest. Die NetSuite-Verbindung nutzt OAuth-2.0-Maschine-zu-Maschine-Zugriff: eine schreibgeschützte Rolle, einen Integrationsdatensatz mit dem Client-Credentials-Grant und ein Zertifikat. Diese Seite richtet sich an den NetSuite-Administrator, der das einrichtet, und an den PlaidCloud-Benutzer, der ihn darum bittet.

PlaidCloud liest nur Daten. Niemand sendet ein Passwort, ein Token-Secret oder einen privaten Schlüssel per E-Mail.

## Vorab: Das Zertifikat erstellen

Das Team des PlaidCloud-Benutzers erstellt ein RSA-Schlüsselpaar und behält den privaten Schlüssel. Nur das öffentliche Zertifikat geht an NetSuite. Zum Beispiel mit OpenSSL:

```bash
openssl req -new -x509 -newkey rsa:3072 -nodes -days 730 \
    -keyout plaidcloud_netsuite.pem \
    -out plaidcloud_netsuite_public.pem \
    -subj "/CN=PlaidCloud"
```

Hängen Sie `plaidcloud_netsuite_public.pem` an die Anfrage an, die Sie dem Administrator senden. Bewahren Sie `plaidcloud_netsuite.pem` für das Feld **Privates NetSuite-Zertifikat** in PlaidCloud auf.

## Die Zugriffsanfrage senden

Wählen Sie auf der Seite **Systeme** des Projekts, unter **Data Foundation** in **Startseite**, unter **System hinzufügen** im Feld **System** Ihr System aus und klicken Sie auf **Noch keinen Zugang?**. Das System wartet dann auf den Zugang, und es wird eine Anfrage angezeigt, die alle Systeme des Projekts abdeckt. Klicken Sie auf **Anfrage kopieren**, um sie in Ihre eigene Nachricht einzufügen, oder auf **Anfrage per E-Mail senden**, um sie in Ihrem E-Mail-Programm mit dem Betreff „Zugang zu PlaidCloud“ zu öffnen. Hängen Sie das öffentliche Zertifikat an.

## Was der NetSuite-Administrator einrichtet

<Steps>

1. **Funktionen aktivieren.** Aktivieren Sie unter **Setup > Company > Enable Features > SuiteCloud**:

   - REST Web Services
   - OAuth 2.0
   - SuiteAnalytics Workbook (erforderlich für SuiteQL)

2. **Erstellen Sie eine schreibgeschützte Rolle**, zum Beispiel „PlaidCloud Read Only“, mit diesen Berechtigungen:

   | Berechtigung | Stufe |
   |---|---|
   | Setup: REST Web Services | Full |
   | Setup: Log in using OAuth 2.0 Access Tokens | Full |
   | Transactions: Invoice, Cash Sale and Credit Memo | View |
   | Lists: Items and Locations | View |
   | Transactions: Budget | View |
   | Reports: General Ledger | View |
   | Setup: Accounting Periods | View |
   | Lists: Subsidiaries | View |
   | Lists: Accounts | View |
   | Lists: Departments | View |
   | Lists: Classes | View |
   | Lists: Locations | View |
   | Lists: Customers | View |
   | Lists: Currency | View |
   | Lists: Consolidated Exchange Rates | View |
   | Lists: Custom Record Entries, wenn Sie benutzerdefinierte Segmente verwenden | View |
   | Lists: Vendors, für Lieferanten | View |
   | Lists: Employees, für Vertriebsmitarbeiter | View |
   | Transactions: Bills, für Lieferantenrechnungspositionen, offene Posten und Zahlungen | View |
   | Transactions: Customer Payment and Pay Bills, für offene Posten und Zahlungen | View |
   | Transactions: Find Transaction, dafür, was jede Zahlung ausgeglichen hat | View |

   Die letzten sechs sind optional. Geben Sie der Rolle Zugriff auf jede Tochtergesellschaft, über die PlaidCloud berichtet.

3. **Erstellen Sie einen Integrationsdatensatz.** Unter **Setup > Integration > Manage Integrations > New**:

   - **Name:** PlaidCloud
   - **Authentifizierung:** Aktivieren Sie nur **Client Credentials (Machine to Machine) Grant** – keine tokenbasierte Authentifizierung und kein Authorization-Code-Grant.
   - **Scopes:** REST Web Services und RESTlets.

   Speichern Sie ihn und kopieren Sie die **Client-ID**. NetSuite zeigt sie einmalig auf der Bestätigungsseite an.

4. **Ordnen Sie das Zertifikat zu.** Unter **Setup > Integration > OAuth 2.0 Client Credentials (M2M) Setup > Create New**:

   - **Entität:** der Benutzer, als der PlaidCloud handelt.
   - **Rolle:** die Rolle aus Schritt 2.
   - **Anwendung:** PlaidCloud, die Integration aus Schritt 3.
   - **Zertifikat:** das öffentliche Zertifikat, das der Anfrage beigefügt war.

   Speichern Sie es und kopieren Sie die **Zertifikats-ID**.

</Steps>

## Was zurückgesendet wird

| Der Administrator sendet | Gespeichert in der NetSuite-Verbindung als |
|---|---|
| Die **Konto-ID** aus **Setup > Company > Company Information** – zum Beispiel `1234567` oder `1234567_SB1` für eine Sandbox | **NetSuite-Konto-ID** |
| Die **Client-ID** aus Schritt 3 | **Client-ID** |
| Die **Zertifikats-ID** aus Schritt 4 | **Zertifikats-ID** |
| Die Tochtergesellschaften, die PlaidCloud lesen darf | Beim Hinzufügen des Systems unter **Optionen**, **Gesellschaften**: Aktivieren Sie sie, oder keine für jede aktive Tochtergesellschaft, die keine Eliminierungsgesellschaft ist |

Der private Schlüssel, der zum Zertifikat gehört, bleibt beim Team des PlaidCloud-Benutzers. Es gibt ihn selbst im Feld **Privates NetSuite-Zertifikat** der Verbindung ein.

<Aside type="caution">
Geben Sie die Konto-ID genau so ein, wie NetSuite sie anzeigt, einschließlich des Suffixes `_SB1` für eine Sandbox. PlaidCloud leitet daraus die NetSuite-Adresse ab.
</Aside>

## Den Zugriff prüfen

Klicken Sie danach in PlaidCloud, sobald das System hinzugefügt ist, in seiner Zeile auf der Seite **Systeme** auf **Verbindung testen**. Jedes Dataset wird als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** angezeigt:

| Dataset | Erforderliche Berechtigung |
|---|---|
| Verkaufspositionen | Transactions: Invoice, Cash Sale and Credit Memo (View) |
| Lagerbestände | Lists: Items and Locations (View) |
| Budgets | Transactions: Budget (View) |
| Statistische Konten | Reports: General Ledger (View) |
| Buchungsperioden | Setup: Accounting Periods (View) |
| Tochtergesellschaften | Lists: Subsidiaries (View) |
| Wechselkurse | Lists: Consolidated Exchange Rates (View) |
| Klassen | Lists: Classes (View) |
| Standorte | Lists: Locations (View) |

Fehlt ein Dataset, nennt der Test die hinzuzufügenden Berechtigungen. Bitten Sie den Administrator, sie der Rolle hinzuzufügen, und testen Sie erneut. Budgets sind optional: Ein NetSuite-Konto, das keine Budgets verwendet, lädt trotzdem alles andere. Auch Wechselkurse, Klassen und Standorte stoppen ein Laden nicht: Verweigert NetSuite eines davon, wird nichts davon geladen, und die Bereitschaftsprüfungen nennen die hinzuzufügende Berechtigung. Ohne Wechselkurse stellen Sie die Kurse stattdessen in einer Datei **Wechselkurse** bereit.

Der Test liest weder Lieferanten noch Vertriebsmitarbeiter, Lieferantenrechnungspositionen, Banksalden, offene Posten oder Zahlungen. Sie sind optional: Verweigert NetSuite eines davon, nennen die Bereitschaftsprüfungen auf dem Dashboard **CFM-Accounting - Close and assurance** nach dem nächsten Laden die hinzuzufügende Berechtigung, und der Rest wird geladen. Klassen werden als Profitcenter geladen und Standorte als Sites. Budgets, Lieferantenrechnungen, Banksalden, offene Posten oder Zahlungen eines Monats, die NetSuite verweigert, behalten die Zeilen, die sie bereits hatten, und werden beim nächsten Laden erneut gelesen. NetSuite hat keinen eigenen Monatsendsaldo, den Data Foundation liest, daher wird sein Hauptbuch mit seiner eigenen Saldenliste verglichen.
