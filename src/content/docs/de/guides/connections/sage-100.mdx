Sage 100 ist auf Ihren eigenen Servern installiert und hat keine Web-API. PlaidCloud erreicht es daher über einen [PlaidLink](/de/reference/cli/plaidlink/)-Agent, der auf einem Windows-Computer in Ihrem Netzwerk läuft. [Data Foundation](/de/guides/projects/data-foundation/) liest über diesen Agent den Kontenplan, den Geschäftskalender, die Journale und die Periodensalden eines Sage-100-Unternehmens, wie bei jedem anderen ERP-System, das es anbindet. Ein Workflow kann außerdem Journalbuchungen des Hauptbuchs und manuelle Schecks der Kreditorenbuchhaltung in das Unternehmen zurückbuchen.

Diese Seite beschreibt, was der Sage-100-Administrator einrichtet, wie Sie das Unternehmen verbinden, was Data Foundation liest und wie sich das Buchen verhält.

## Was der Sage-100-Administrator einrichtet

Alles Folgende geschieht auf dem einen Computer, auf dem der PlaidLink-Agent läuft.

<Steps>

1. **Installieren und registrieren Sie PlaidLink** auf dem Computer, verwenden Sie PlaidLink 1.2.36 oder höher und führen Sie den Agent unter einem eigenen Windows-Konto aus, nicht unter einem Systemkonto (LocalSystem, LocalService oder NetworkService). Mit einem eigenen Konto kann PlaidLink eine hängende Sage-100-Sitzung beenden; unter einem Systemkonto ist das nicht möglich.

2. **Installieren Sie den 64-Bit-ODBC-Treiber von Sage und legen Sie ein 64-Bit-System-DSN an.** Der Agent ist ein 64-Bit-Programm und kann keinen 32-Bit-Treiber und keine 32-Bit-Datenquelle verwenden. Die Datenquelle heißt meist `SOTAMAS90` und wird mit Sage 100 Standard und Advanced geliefert. Sage 100 Premium liest aus SQL Server und benötigt stattdessen den Microsoft ODBC Driver for SQL Server. Prüfen Sie, ob Ihre Sage-100-Lizenz den ODBC-Treiber und den Arbeitsplatz abdeckt.

3. **Legen Sie einen Sage-Benutzer für PlaidCloud an** und weisen Sie ihm in der Rollenpflege diese Aufgaben zu.

   | Zweck | Aufgaben |
   |---|---|
   | Lesen | General Ledger: Chart of Accounts, Account Inquiry, Journal Entry inquiry, Fiscal Year and Period inquiry. Library Master: Company Maintenance inquiry. |
   | Buchen, mit dem Recht, Einträge hinzuzufügen und nicht nur anzusehen | General Ledger: Journal Entry. Accounts Payable: Manual Check Entry. |

   Für Premium geben Sie dem Benutzer außerdem Lesezugriff auf die Sage-100-Datenbank in SQL Server.

4. **Installieren Sie Sage 100 auf demselben Computer als Arbeitsplatz.** Die Datenquelle benötigt ihn, um die Unternehmensdateien zu öffnen, und das Buchen läuft über das Business Object Interface (BOI) von Sage, das die Arbeitsplatzinstallation bereitstellt. Das Buchen belegt während der Ausführung eine Sage-100-Arbeitsplatzlizenz. Notieren Sie den Ordner, in dem Sage 100 installiert ist, und die Währung, in der das Unternehmen bucht.

5. **Stellen Sie PlaidCloud ein Testunternehmen** oder eine Kopie des Unternehmens bereit, mit dem zuerst die Verbindung hergestellt wird.

6. **Erlauben Sie den PlaidLink-Agent in Ihrem Virenschutz und in Windows SmartScreen**, damit die erste Installation nicht blockiert wird.

</Steps>

Eine Standard- oder Advanced-Datenquelle meldet sich an einem Unternehmen an. Eine Premium-Verbindung benennt ein Unternehmen in einer Datenbank. Verbinden Sie jedes Unternehmen einzeln.

<Aside type="caution">
Senden Sie das Sage-Passwort niemals per E-Mail. **Sage password** ist ein Geheimnis: Es wird in der Verbindung gespeichert und nie wieder angezeigt.
</Aside>

### Die Zugriffsanfrage senden

Wählen Sie auf der Registerkarte **Foundation** des Projekts unter **System verbinden** die Option **Sage 100 — on-premises** und dann **Neue Verbindung erstellen**. Das Formular zeigt diese Anfrage vollständig, einen Link **PlaidLink einrichten**, **Anfrage kopieren**, um sie in Ihre eigene Nachricht einzufügen, und **Anfrage per E-Mail senden**, um sie in Ihrem E-Mail-Programm mit dem Betreff "Sage 100 access for PlaidCloud" zu öffnen.

## Das Unternehmen verbinden

Öffnen Sie auf der Registerkarte **Foundation** den Bereich **Quellen**, wählen Sie unter **System verbinden** die Option **Sage 100 — on-premises** (**Weiteres System verbinden**, sobald das Projekt eine Quelle hat) und dann **Neue Verbindung erstellen**. Geben Sie einen **Verbindungsname** ein, wählen Sie die **Umgebung** und füllen Sie diese Einstellungen aus:

| Einstellung | Was einzugeben ist |
|---|---|
| **Sage 100 edition** | Premium, Standard oder Advanced. |
| **Company code** | Der Code des Sage-100-Unternehmens, 1 bis 10 Buchstaben und Ziffern. |
| **Company currency** | Der dreistellige Code der Währung, in der das Unternehmen bucht, zum Beispiel `USD`. Erforderlich: PlaidCloud nimmt nie eine Währung an. |
| **Sage user** | Der Sage-Benutzer, den Sie für PlaidCloud angelegt haben. |
| **Sage password** | Das Passwort dieses Benutzers. |
| **Sage 100 install folder on the agent machine** | Der Ordner, in dem Sage 100 installiert ist. Das Buchen benötigt ihn, das Lesen nicht. |
| **Accounts Payable division** | Die Division, in die manuelle Schecks gebucht werden. Standard ist `00`. |
| **SQL Server (Premium)** und **SQL Server database (Premium)** | Für Premium: der SQL Server und die Datenbank der Sage-100-Installation. |
| **ODBC data source (Standard and Advanced)** | Für Standard und Advanced: das System-DSN auf dem Computer des Agents. Standard ist `SOTAMAS90`. |

Wählen Sie unter **Systemeinstellungen** in **PlaidLink agent** den PlaidLink-Agent und setzen Sie dort **Company currency** auf denselben Code. Zeilen werden in dieser Währung geladen, und sie ist `USD`, bis Sie sie ändern. **Document account for the agent's reads** nimmt die Dateien auf, die der Agent beim Lesen schreibt, und ist standardmäßig das des Projekts. **Account mask** ist das Kontoformat von Sage 100, in dem `#` ein Zeichen und alles andere ein Trennzeichen ist: `####-###` ist ein vierstelliges Hauptkonto, ein Trennzeichen und eine dreistellige Abteilung. Sie ist `####`, bis Sie sie ändern.

Klicken Sie auf **Verbindung testen**. Für Sage 100 prüft das, ob die Verbindung alle benötigten Werte hat, und es meldet sich nicht bei Sage 100 an: Der Agent liest die Tabellen, wenn Sie auf **Laden** klicken. Legen Sie dann **Monate Verlauf** fest und fügen Sie das System hinzu, wie unter [Ihr ERP verbinden](/de/guides/projects/data-foundation/#ihr-erp-verbinden) beschrieben. Das eine Unternehmen ist die einzige Entität, die die Verbindung anbietet.

## Was Data Foundation liest

| Datensatz | Aus Sage 100 gelesen |
|---|---|
| Entitäten | Das Unternehmen. |
| Geschäftskalender | Die Geschäftsjahre und ihre Perioden, bis zu 13 pro Jahr. Eine Periode, deren Enddatum dem der vorherigen entspricht, ist eine Anpassungsperiode. |
| Kontenplan | Die Konten des Hauptbuchs, nach der Kontomaske in Segmente aufgeteilt. |
| Abteilungen | Das Abteilungssegment des Kontos, wenn die Maske eines hat. |
| Hauptbuch | Die Buchungsdetails des Hauptbuchs, nach Geschäftsjahr und Periode. |
| Saldenliste | Der Verlauf der Periodenbuchungen: Soll und Haben jedes Kontos pro Periode, mit einem Eröffnungssaldo für die erste gelesene Periode. |

Sage 100 liefert keine Produkte, Kunden, Verkaufspositionen, Wechselkurse oder andere Datensätze: Fügen Sie diese als Dateien hinzu. Es führt seine Bücher in einer Währung, daher gibt es keine Kurse zu lesen. Siehe die [Data-Foundation-Abdeckungsmatrix](/de/reference/data-foundation-coverage-matrix/).

Eine Tabelle, die der Agent nicht lesen kann oder die keine Zeilen hat, ist eine Warnung und kein Fehler: Was ein früherer Ladevorgang daraus geladen hat, bleibt unverändert, die Datensätze, die geladen werden können, werden geladen, und **Bereitschaft** nennt die Tabelle.

## In Sage 100 buchen

Der Schritt **Belege buchen** bucht in eine Sage-100-Verbindung aus derselben Tabelle mit Belegen wie bei jedem anderen ERP und mit denselben [Buchungsmodi](/de/guides/workflows/run-a-workflow/#einen-buchungsmodus-wählen): **Simulieren** erstellt und prüft jeden Beleg, ohne Sage 100 zu kontaktieren. Ein System bucht nur dann Live, wenn die Ausführung Live ist und das Projekt für heute die Schreibautorisierung dafür besitzt. Unter [Buchungsregister prüfen](/de/guides/connections/posting-register/) verfolgen Sie Buchungen, und unter [ERP-Buchungsverlauf prüfen](/de/guides/connections/erp-post-history/) finden Sie das Hauptbuch dahinter.

Sage 100 nimmt zwei Arten von Belegen entgegen:

| Beleg | Was gebucht wird | Was er benötigt |
|---|---|---|
| `journal` | Eine Journalbuchung des Hauptbuchs. | Ein Buchungsdatum und ein Konto in jeder Zeile. Die Zeilen müssen auf den Cent ausgeglichen sein, und die Referenz, die zur Beschreibung des Journals wird, hat höchstens 30 Zeichen. |
| `payment` | Ein manueller Scheck der Kreditorenbuchhaltung, der eine außerhalb von Sage 100 geleistete Zahlung gegen die offenen Rechnungen des Lieferanten erfasst. | Ein Buchungsdatum, ein Lieferant über alle Zeilen, eine `invoice_no` und ein positiver Betrag in jeder Zeile, ein Bankcode und eine Referenz mit höchstens 7 Zeichen, die zur Schecknummer wird. Der Bankcode ist eine Spalte `bank_code` oder ein erforderlicher Wert, der im Sage-100-System gespeichert ist. |

Bevor etwas gesendet wird, wird ein Beleg mit Angabe des Grundes angehalten, wenn:

- seine Zeilen in einer anderen Währung als der **Company currency** der Verbindung vorliegen;
- seine Spalte `company` ein anderes Unternehmen als den **Company code** der Verbindung benennt;
- ein Journal in eine Periode datiert ist, die Sage 100 abgeschlossen hat, oder eine Zahlung eine Rechnung begleicht, die für diesen Betrag nicht offen ist, sofern der Agent das feststellen kann (diese beiden Prüfungen laufen nur bei Live-Buchungen);

Jeder Beleg wird in Sage 100 in einem Batch erfasst, und PlaidCloud liest ihn zurück, bevor er als gebucht gilt. Das sehen Sie:

- **Gebucht** nur, wenn das Zurücklesen den Beleg in den gebuchten Tabellen von Sage 100 findet.
- **Wartend**, mit der Meldung "Entered in Sage, batch *n*", wenn der Beleg im Batch liegt und auf das Update von Sage 100 wartet. Solange der Agent online ist, fragt PlaidCloud Sage 100 etwa jede Stunde erneut nach jedem solchen Beleg und erfasst ihn als gebucht, sobald er erscheint. Ein Beleg, der nach 7 Tagen noch erfasst ist, wird unbestätigt.
- **Unbestätigt**, wenn PlaidCloud nicht feststellen kann, ob Sage 100 ihn enthält. Er wird nie auf Verdacht erneut gesendet, prüfen Sie also Sage 100, bevor Sie ihn auflösen.
- **Nicht gebucht**, wenn Sage 100 den Beleg ablehnt oder der Agent ihn nie angenommen hat, zum Beispiel weil er offline ist. Ein abgelehnter Beleg kann nach der Korrektur erneut gesendet werden.

Ein gebuchter Beleg wird nie zweimal gebucht: Wird derselbe Beleg erneut ausgeführt, wird er an seiner Referenz erkannt.

<Aside type="note">
PlaidLink öffnet pro Agent nur eine Sage-100-Sitzung gleichzeitig, daher laufen Buchungen eines Agents nacheinander. Eine Buchung wartet bis zu eine Minute auf die Sitzung, bevor sie als nicht verfügbar abgelehnt wird. Das Stornieren einer Buchung ist für Sage 100 nicht verfügbar.
</Aside>
