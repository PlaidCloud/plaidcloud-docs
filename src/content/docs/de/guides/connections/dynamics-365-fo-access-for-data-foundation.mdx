[Data Foundation](/de/guides/projects/data-foundation/) führt die Daten aller ERP-Systeme und Instanzen, die Sie verbinden, in einem Common Finance Model zusammen, und Dynamics 365 Finance and Operations ist eines der ERP-Systeme, die es direkt liest. Die Verbindung nutzt für die Stammdaten eine Microsoft-Entra-ID-Anwendung mit Client-Secret und für das Hauptbuchjournal, die Nebenbücher und die Banksalden Ihren Fabric-(Synapse-)Link-SQL-Endpunkt. Diese Seite richtet sich an den Dynamics-365-Administrator, der das einrichtet, und an den PlaidCloud-Benutzer, der ihn darum bittet.

PlaidCloud liest Daten ausschließlich. Niemand sendet ein Client-Secret oder ein SQL-Kennwort per E-Mail.

## Zugriffsanfrage senden

Wählen Sie auf der Seite **Systeme** des Projekts, unter **Data Foundation** in **Startseite**, unter **System hinzufügen** im Feld **System** Ihr System aus und klicken Sie auf **Noch keinen Zugang?**. Das System wartet dann auf den Zugang, und es wird eine Anfrage angezeigt, die alle Systeme des Projekts abdeckt. Klicken Sie auf **Anfrage kopieren**, um sie in Ihre eigene Nachricht einzufügen, oder auf **Anfrage per E-Mail senden**, um sie in Ihrem E-Mail-Programm mit dem Betreff „Zugang zu PlaidCloud“ zu öffnen.

## Was der Dynamics-365-Administrator einrichtet

<Steps>

1. **Registrieren Sie für PlaidCloud eine Anwendung in Microsoft Entra ID** mit einem Client-Secret. Notieren Sie die Anwendungs-ID (Client-ID), die Verzeichnis-ID (Mandanten-ID) und das Secret.

2. **Ordnen Sie die Anwendung einem Benutzer zu.** Fügen Sie in Dynamics 365 unter **System administration > Setup > Microsoft Entra ID applications** die Client-ID hinzu und ordnen Sie sie einem Benutzer zu, dessen Rolle für jede zu ladende juristische Person Folgendes anzeigen darf:

   - Hauptbuch: juristische Personen, Geschäftskalender, Hauptkonten, Werte der Finanzdimensionen, Wechselkurse
   - Debitorenbuchhaltung: Kunden und Kundenrechnungspositionen
   - Kreditorenbuchhaltung: Lieferanten (optional)
   - Produktinformationsverwaltung: freigegebene Produkte
   - Lagerverwaltung: Bestand und Lagertransaktionen (optional)
   - Budgetierung: Budgetregistereinträge (optional)

3. **Richten Sie Fabric Link für das Hauptbuchjournal ein.** Journalzeilen werden aus Ihrem Fabric-(Synapse-)Link-SQL-Endpunkt gelesen, nicht aus dem OData-Dienst. Stellen Sie sicher, dass Fabric Link für diese Tabellen aktiviert ist, und erstellen Sie auf diesem Endpunkt ein schreibgeschütztes SQL-Login für PlaidCloud:

   - `generaljournalaccountentry`
   - `generaljournalentry`
   - `fiscalcalendarperiod`
   - `dimensionattributelevelvalue`, mit einer Zeile je Dimensionswert jeder Finanzdimensionskombination und dem Namen der zugehörigen Dimension
   - für offene Posten und Zahlungen (optional): `custtrans`, `vendtrans`, `custsettlement`, `vendsettlement`
   - für Lieferantenrechnungspositionen (optional): `vendinvoicetrans`, `vendinvoicejour`
   - für Banksalden (optional): `bankaccounttrans`, `bankaccounttable`

   Standorte und Profitcenter sind die Werte der Finanzdimensionen `Site` und `BusinessUnit`.

</Steps>

## Was zurückzusenden ist

| Der Administrator sendet | Eingabe in PlaidCloud als |
|---|---|
| Die Umgebungs-URL, `https://<name>.operations.dynamics.com` | **Umgebungs-URL** |
| Die Verzeichnis-ID (Mandanten-ID) | **Azure-AD-Mandanten-ID** |
| Die Anwendungs-ID (Client-ID) | **Client-ID** |
| Die `dataAreaId` einer juristischen Person | **Rechtseinheit / Unternehmen (dataAreaId)**: Die Verbindung benötigt eine, und Data Foundation liest die unter **Gesellschaften** ausgewählten juristischen Personen |
| Den Fabric-Link-SQL-Endpunkt, die Datenbank und das Login | Eine separate SQL-Verbindung in PlaidCloud, deren Verbindungs-ID in die Systemeinstellung **Fabric Link SQL connection (its connection ID)** kommt |
| Die Hauptkontenkategorien Ihrer Konten für die Herstellungskosten der verkauften Waren (PlaidCloud geht von `COGS` aus) | Die Systemeinstellung **Cost of goods sold main account categories** |
| Die Hauptkontenkategorien der nicht betrieblichen Konten: Zinsen, Ertragsteuern, Fremdwährungsgewinne und -verluste, sonstige Erträge | Die Systemeinstellung **Non-operating main account categories** |
| Die Finanzdimension, die den Intercompany-Partner einer Zeile benennt (PlaidCloud geht von `IntercompanyPartner` aus) | Die Systemeinstellung **Intercompany partner dimension** |
| Die juristischen Personen, die PlaidCloud lesen darf | Unter **Optionen**, **Gesellschaften**: Aktivieren Sie sie, oder keine für alle |

Das Client-Secret und das Kennwort des SQL-Logins werden nie per E-Mail gesendet. Das Team des PlaidCloud-Benutzers fügt das **Client-Secret** selbst in PlaidCloud ein, und die SQL-Verbindung enthält das SQL-Login. Juristische Personen, die Konsolidierungseinheiten sind, kommen in die Systemeinstellung **Consolidation legal entities**, damit ihre Buchungen nicht als Aktivität eines Unternehmens gezählt werden.

## Zugriff prüfen

Klicken Sie danach in PlaidCloud, sobald das System hinzugefügt ist, in seiner Zeile auf der Seite **Systeme** auf **Verbindung testen**. Jedes Dataset wird als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** angezeigt:

| Dataset | Erforderliche Berechtigung |
|---|---|
| Entitäten | Hauptbuch: juristische Personen anzeigen |
| Geschäftskalender | Hauptbuch: Geschäftskalender anzeigen |
| Kontenplan | Hauptbuch: Hauptkonten anzeigen |
| Abteilungen | Hauptbuch: Werte der Finanzdimensionen anzeigen |
| Kunden | Debitorenbuchhaltung: Kunden anzeigen |
| Produkte | Produktinformationsverwaltung: freigegebene Produkte anzeigen |
| Wechselkurse | Hauptbuch: Wechselkurse anzeigen |
| Saldenliste, Hauptbuch | Das Hauptbuch anzeigen (das Journal, über Fabric Link) |
| Jedes andere Dataset | Optional, nicht Teil des Tests |

Fehlt ein Dataset, nennt der Test die Berechtigung, die hinzuzufügen ist. Bitten Sie den Administrator, sie der Rolle hinzuzufügen, und testen Sie erneut.

Die optionalen Datasets sind Standorte, Profitcenter, Lieferanten, Verkaufspositionen, Lagerbestände, Budgets, Banksalden, Lieferantenrechnungspositionen, offene Posten und Zahlungen. Eine Umgebung, die eines davon nicht enthält, lädt trotzdem alles andere. Banksalden, Lieferantenrechnungspositionen, offene Posten oder Zahlungen eines Monats, die nicht aus Fabric Link gelesen werden können, behalten die Zeilen, die sie bereits hatten, und werden beim nächsten Laden erneut gelesen.

Dynamics 365 hat kein Saldenobjekt, das die Verbindung lesen kann, daher wird kein Monatsendsaldo geladen: Das Hauptbuch wird mit seiner eigenen Saldenliste verglichen.
