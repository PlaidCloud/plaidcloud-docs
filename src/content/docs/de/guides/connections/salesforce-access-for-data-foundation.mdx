[Data Foundation](/de/guides/projects/data-foundation/) führt die Daten aller Systeme, die Sie verbinden, in beliebig vielen Instanzen in einem Common Finance Model zusammen. Salesforce ist eines der Systeme, die es direkt liest. Salesforce ist eine CRM-Quelle, kein Hauptbuch: Es liefert Kunden, Produkte, die Vertriebspipeline, Vertriebsmitarbeiter, Kampagnen, seine Geschäftsmonate und Aufträge, nie Hauptbuchbuchungen. Diese Seite richtet sich an den Salesforce-Administrator, der den Zugriff einrichtet, und an den PlaidCloud-Benutzer, der ihn darum bittet.

PlaidCloud liest Daten ausschließlich. Niemand sendet ein Kennwort oder ein Sicherheitstoken per E-Mail.

## Zugriffsanfrage senden

Wählen Sie auf der Seite **Systeme** des Projekts, unter **Data Foundation** in **Startseite**, unter **System hinzufügen** im Feld **System** Ihr System aus und klicken Sie auf **Noch keinen Zugang?**. Das System wartet dann auf den Zugang, und es wird eine Anfrage angezeigt, die alle Systeme des Projekts abdeckt. Klicken Sie auf **Anfrage kopieren**, um sie in Ihre eigene Nachricht einzufügen, oder auf **Anfrage per E-Mail senden**, um sie in Ihrem E-Mail-Programm mit dem Betreff „Zugang zu PlaidCloud“ zu öffnen.

## Was der Salesforce-Administrator einrichtet

<Steps>

1. **Erstellen Sie eine External Client App** unter **Setup > Apps > External Client Apps > New** oder eine Connected App, falls Ihre Org noch welche hat:

   - Aktivieren Sie die OAuth-Einstellungen und setzen Sie nur das Häkchen bei **Enable Client Credentials Flow** (kein Authorization-Code- und kein Kennwort-Flow).
   - **OAuth-Bereich:** Manage user data via APIs (`api`).
   - **Run As:** ein dedizierter Integrationsbenutzer (Schritt 2).

2. **Geben Sie dem Integrationsbenutzer ein Profil oder einen Berechtigungssatz** mit:

   - API Enabled
   - Lesezugriff auf Account (einschließlich des Felds Account Number), Product2, Opportunity, OpportunityLineItem und Organization (für die Standardwährung)
   - Lesezugriff auf User (Vertriebsmitarbeiter), Campaign (Kampagnen, gelesen als Projekte), FiscalYearSettings und Period (die Geschäftsmonate), OpportunityHistory und OpportunityStage (die Pipeline, wie sie zu jedem Monatsende stand) sowie Order und OrderItem (Aufträge, bei aktivierten Orders), wenn Sie sie im Modell haben möchten
   - View All Data oder Freigaben, mit denen er jede Opportunity sieht, über die Sie berichten

   Salesforce beschränkt jede Zeile und jedes Feld, das PlaidCloud lesen kann, auf das, was dieser Benutzer sehen kann.

3. **Kopieren Sie den Consumer Key (Client-ID) und das Consumer Secret** aus der App sowie die My-Domain-URL der Org, zum Beispiel `https://yourcompany.my.salesforce.com`.

</Steps>

## Was zurückzusenden ist

| Der Administrator sendet | Eingabe in PlaidCloud als |
|---|---|
| Die My-Domain-URL | **My Domain**: nur der Domänenname, zum Beispiel `yourcompany`; `.my.salesforce.com` wird für Sie ergänzt |
| Die Client-ID (Consumer Key) | **Client-ID** |
| Das Client-Secret (Consumer Secret), über das sichere Verbindungsformular, nicht per E-Mail | **Client-Secret** |

Geben Sie unter **Optionen**, **Gesellschaften** die eine Entität ein, zu der die Pipeline der Salesforce-Org gehört: Eine Org hat keine Entitäten, die sich auflisten ließen. Eine Org ist eine Entität, zwei Orgs sind also zwei Verbindungen.

## Zugriff prüfen

Klicken Sie danach in PlaidCloud, sobald das System hinzugefügt ist, in seiner Zeile auf der Seite **Systeme** auf **Verbindung testen**. Jedes Dataset wird als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** angezeigt:

| Dataset | Was es in Salesforce liest |
|---|---|
| Kunden | Account |
| Produkte | Product2 |
| Pipeline | Opportunity und OpportunityLineItem, mit den Kontonummern |
| Die Standardwährung der Org | Organization |

Alle sind optional. Zeigt eines **Fehlende Berechtigung**, bitten Sie den Administrator, dem Integrationsbenutzer den Lesezugriff auf dieses Objekt hinzuzufügen, und testen Sie erneut.

Die anderen Datasets, ebenfalls alle optional, liest der Test nicht:

| Dataset | Was es in Salesforce liest |
|---|---|
| Vertriebsmitarbeiter | User |
| Projekte | Campaign |
| Geschäftskalender | FiscalYearSettings und Period, nur die Monate |
| Pipeline, wie sie zu jedem vergangenen Monatsende stand | OpportunityHistory und OpportunityStage |
| Kundenaufträge | Order und OrderItem |

Verweigert Salesforce eines davon, nennen die Bereitschaftsprüfungen auf dem Dashboard **CFM-Accounting - Close and assurance** nach dem nächsten Laden die Objekte, auf die der Integrationsbenutzer Lesezugriff erhalten muss. Pipeline oder Aufträge eines Monats, die nicht gelesen werden können, behalten die Zeilen, die sie bereits hatten.

Pipeline-Beträge stehen in der Währung der Opportunity. Eine Org mit nur einer Währung hat kein solches Feld, daher verwendet PlaidCloud die Standardwährung der Org aus Organization und andernfalls die Währung der Entität.
