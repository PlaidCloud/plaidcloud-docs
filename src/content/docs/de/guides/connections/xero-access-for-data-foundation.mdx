[Data Foundation](/de/guides/projects/data-foundation/) führt die Daten aller ERP- und Buchhaltungssysteme, die Sie verbinden, in beliebig vielen Instanzen in einem Common Finance Model zusammen. Xero ist eines der Systeme, die es direkt liest, eine Xero-Organisation je Verbindung. Diese Seite richtet sich an den Xero-Administrator, der den Zugriff einrichtet, und an den PlaidCloud-Benutzer, der ihn darum bittet.

PlaidCloud liest Daten ausschließlich. Niemand sendet ein Kennwort per E-Mail.

## Zugriffsanfrage senden

Wählen Sie auf der Registerkarte **Foundation** des Projekts die Option **Neue Verbindung erstellen** und dann **Xero**. Das Formular zeigt die vollständige Anfrage. Klicken Sie auf **Anfrage kopieren**, um sie in Ihre eigene Nachricht einzufügen, oder auf **Anfrage per E-Mail senden**, um sie in Ihrem E-Mail-Programm mit dem Betreff „Read-only Xero access for PlaidCloud“ zu öffnen.

## Was der Xero-Administrator einrichtet

<Steps>

1. **Autorisieren Sie die Xero-App von PlaidCloud** für jede Organisation, über die Sie berichten, angemeldet als Benutzer mit der Rolle Standard oder Advanced. Die App fragt nur Lesezugriff an:

   | Bereich | Was er abdeckt |
   |---|---|
   | `accounting.settings.read` | Organisation, Kontenplan, Tracking-Kategorien, Artikel |
   | `accounting.contacts.read` | Kunden |
   | `accounting.transactions.read` | Verkaufsrechnungen und Gutschriften |
   | `accounting.journals.read` | Das Hauptbuch: jedes gebuchte Journal |
   | `accounting.reports.read` | Die Saldenliste, für Eröffnungssalden |

   Ohne `accounting.journals.read` kann das Hauptbuch nicht geladen werden. Kontenplan, Abteilungen, Kunden und Produkte werden trotzdem geladen.

2. **Richten Sie die Tracking-Kategorien ein, die PlaidCloud liest**, mit diesen Namen:

   - **Department:** eine Option je Abteilung, benannt so, wie ihr Code erscheinen soll.
   - **Intercompany:** eine Option je Konzerngesellschaft, benannt nach dem Entitätscode dieser Gesellschaft, auf den Zeilen von Intercompany-Journalen. Benennen Sie Intercompany-Konten so, dass „Intercompany“ Teil des Kontonamens ist.

</Steps>

## Was zurückzusenden ist

| Der Administrator sendet | Eingabe in PlaidCloud als |
|---|---|
| Die Mandanten-ID der Organisation (Xero listet sie unter der Verbindung oder unter `GET /connections`) | **Organisations-ID (Mandanten-ID)** |
| Die Bestätigung, dass das Geschäftsjahresende und das Sperrdatum für Perioden der Organisation festgelegt sind | Nichts einzugeben: PlaidCloud liest beides aus Xero |

Der PlaidCloud-Benutzer fügt das **Refresh-Token** selbst ein; es ist ein Geheimnis und wird nie per E-Mail gesendet. Er wählt auch die **Organisation** aus, als die die Verbindung geladen wird.

Unter **Systemeinstellungen** benennt **Konto für Gewinnrücklagen** das Eigenkapitalkonto, in das die Eröffnungs-Gewinn- und Verlustrechnung übergeht, wenn die Kontennamen das nicht bereits aussagen. Es ist optional.

## Zugriff prüfen

Klicken Sie in PlaidCloud auf **Verbindung testen**. Jedes Dataset wird als **Lesbar**, **Fehlende Berechtigung** oder **Fehler** angezeigt:

| Dataset | Erforderlicher Bereich |
|---|---|
| Entitäten | `accounting.settings.read` |
| Kontenplan | `accounting.settings.read` |
| Abteilungen | `accounting.settings.read` (die Tracking-Kategorie Department) |
| Produkte | `accounting.settings.read` |
| Geschäftskalender | `accounting.settings.read` |
| Kunden | `accounting.contacts.read` |
| Hauptbuch | `accounting.journals.read` |
| Saldenliste | `accounting.reports.read` |
| Verkaufspositionen (optional) | `accounting.transactions.read` |
| Budget (optional) | `accounting.reports.read` |

Zeigt ein Dataset **Fehlende Berechtigung**, nennt der Test den Bereich, der zu erteilen ist. Autorisieren Sie die App mit diesem Bereich erneut und testen Sie erneut. Eine Xero-Organisation ohne Verkaufsrechnungen oder Budgets lädt trotzdem alles andere.

Wechselkurse sind nicht Teil dieses Zugriffs: Xero veröffentlicht sie nicht. Stellen Sie sie stattdessen in einer Datei **Currency rates** bereit.
