## Beschreibung

Workspace-Administratoren legen fest, welche KI-Funktionen von Weave der Workspace nutzt. Jede Funktion lässt sich einzeln für alle im Workspace ausschalten. Jede Funktion ist eingeschaltet, bis ein Administrator sie ausschaltet.

Die Prüfungen und Befunde von Weave verwenden keine KI und bleiben daher unabhängig von Ihrer Auswahl hier eingeschaltet.

## Eine Funktion ein- oder ausschalten

1. Klicken Sie in der Kopfzeile auf die Schaltfläche **Weave**.
2. Wählen Sie am Ende des Menüs **KI-Funktionen…**.
3. Entfernen Sie das Häkchen neben jeder Funktion, die Sie ausschalten möchten, oder setzen Sie es, um sie wieder einzuschalten.
4. Klicken Sie auf **Speichern**.

Die Änderung gilt für die nächste KI-Anfrage, die jemand im Workspace stellt. Niemand muss sich abmelden.

**KI-Funktionen…** erscheint nur für Workspace-Administratoren. Wer sonst versucht, die Funktionen über die API zu ändern, erhält die Meldung *Only workspace administrators can turn AI features on or off.*

## Die Funktionen

| Funktion | Was sie umfasst | Wenn ausgeschaltet |
|---|---|---|
| **Weave-Chat** | Der Chat auf der Registerkarte **Weave** eines Projekts, **Assistenten fragen** unter **Hilfe & Support** und Weave in der [PlaidCloud-Mobil-App](/de/guides/mobile-app/weave-on-mobile/). | Der **Chat** auf der Registerkarte **Weave** meldet, dass der Administrator ihn ausgeschaltet hat, **Hilfe & Support** hat keine Registerkarte **Assistenten fragen**, und eine in der Mobil-App gestellte Frage wird abgelehnt. |
| **Behebungsassistent** | **Beheben** bei den Befunden von Weave und die Registerkarte **Weave AI** bei einem Protokolleintrag. | Befunde bieten kein **Beheben** an, außer bei einem fehlenden Konnektor unter **Steps that can run before the table they read is written**; dessen **Beheben** öffnet [Abhängigkeiten synchronisieren](/de/guides/workflows/sync-dependencies/) statt des Assistenten. Die Registerkarte **Weave AI** ist nicht verfügbar. |
| **Import- und Exportassistenten** | Der Weave-Chat, der für Sie einen Dateiimport, einen Importschritt oder einen Exportschritt einrichtet. | Der Weave-Chat kann diese nicht einrichten. |
| **Ausdrucksassistent** | Der Assistent im Ausdruckseditor. | Der Ausdruckseditor hat keinen Assistenten. |
| **SQL aus einer Beschreibung** | [Generate SQL with AI](/de/guides/ai-assistant/generate-sql-extract/) beim Schritt **SQL extrahieren**. | Der Schritt hat keinen Bereich **Generate SQL with AI**. Sie können das SQL weiterhin selbst schreiben. |
| **Zusammenfassung der Workflow-Prüfung** | Die von der KI geschriebene Zusammenfassung über der **Prüfen**-Funktion eines Workflows. | **Prüfen** zeigt seine Befunde ohne die Zusammenfassung. |
| **Startdiagramm** | Die KI wählt das erste Diagramm für eine hineingezogene Datei. | Stattdessen wählt eine Regel das Diagramm. |

Wer bei der Änderung bereits angemeldet war, sieht die Funktion weiterhin, bis PlaidCloud neu geladen wird, aber Weave verwendet dafür keine KI mehr. Der Chat, der Behebungs- und der Ausdrucksassistent sowie SQL aus einer Beschreibung weisen darauf hin, zum Beispiel mit *Your workspace administrator has turned off the fix assistant.*

<Aside type="note">
Diese Schalter betreffen die KI, die PlaidCloud bereitstellt. KI-Schritte in Ihren Workflows verwenden Ihre eigene KI-Verbindung, und KI-Werkzeuge, die Sie über [MCP](/de/integrations/ai-coding-agents/) anbinden, verwenden ihr eigenes Modell; keines von beiden ist betroffen.
</Aside>

## Änderungsprotokoll

Jede ein- oder ausgeschaltete Funktion wird im Sicherheitsprotokoll des Workspaces festgehalten, mit der Angabe, wer sie wann geändert hat, zum Beispiel *Turned off the fix assistant.*

## Über die API

`GET /rest/v1/analyze/ai/features` liefert jede Funktion und ob sie eingeschaltet ist, als `{"features": [{"feature": "chat", "on": true}, …]}`. Die Funktionsnamen lauten `chat`, `fix`, `import_export`, `expression`, `sql_extract`, `review_summary` und `starter_chart`.

`PUT /rest/v1/analyze/ai/features` mit `{"off": ["fix"], "on": ["chat"]}` schaltet die Funktionen in `off` aus und die in `on` ein. Eine Funktion, die in keiner der beiden Listen steht, bleibt unverändert, sodass zwei Administratoren, die unterschiedliche Funktionen ändern, sich nicht gegenseitig rückgängig machen. Die Antwort entspricht der des `GET`. Nur ein Workspace-Administrator kann ihn aufrufen, und ein Name, der keine Funktion ist, oder einer, der in beiden Listen steht, wird abgelehnt.
