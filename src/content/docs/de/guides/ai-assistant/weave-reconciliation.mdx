## Beschreibung

Vor dem Abschluss müssen Sie wissen, dass ein Satz von Zahlen mit einem anderen übereinstimmt:
das Hauptbuch mit der Saldenliste, ein Quellsystem mit seiner Ladung, die Schlusssalden dieses
Monats mit den Eröffnungssalden des nächsten. Eine **Abstimmung**
benennt die beiden Seiten und wie ihre Zeilen einander zugeordnet werden, und Weave antwortet auf eine von drei
Arten:

> Ist-Werte Hauptbuch stimmt mit Saldenliste überein: Alle 1.204 Konten stimmen exakt überein. Beide
> ergeben in Summe 12.345.678,90.

> Ist-Werte Hauptbuch stimmt nicht mit Saldenliste überein: 3 von 1.204 Konten weichen ab, insgesamt um
> 4.210,00 ohne Berücksichtigung des Vorzeichens. Saldiert liegt Ist-Werte Hauptbuch 3.900,00 höher. Die
> größte Abweichung betrifft 4000, mit 3.900,00 Unterschied (Ist-Werte Hauptbuch 1.000.000,00, Saldenliste
> 996.100,00).

> Weave konnte nicht prüfen, ob Ist-Werte Hauptbuch mit Saldenliste übereinstimmt: Keine der beiden Seiten
> hat Zeilen, die den Filtern dieser Abstimmung entsprechen. Wenn diese Daten noch nicht
> geladen wurden, laden Sie sie und prüfen Sie erneut.

Weave sagt nie, dass eine Abstimmung übereinstimmt, wenn es nicht beide Seiten vollständig
lesen konnte. Der Vergleich ist eine Abfrage auf Ihren Daten; es ist keine KI beteiligt.

## Eine Abstimmung anlegen

Nur ein Architect des Projekts kann eine Abstimmung anlegen, bearbeiten oder löschen, und das
Projekt muss entsperrt sein.

1. Öffnen Sie die Registerkarte **Weave** des Projekts und klicken Sie in der Leiste **Monitor** unter **Close checks** auf **Abstimmungen**.
2. Klicken Sie auf **Neu**.
3. Geben Sie unter **Name** einen Namen ein, und geben Sie unter **Zeilen heißen** an, was eine verglichene Zeile
   ist, im Plural – „Konten“ oder „Kombinationen aus Konto und Kostenstelle“. Weave
   verwendet das in jedem Satz; wenn Sie das Feld leer lassen, sagt es „Elemente“.
4. Geben Sie unter **Erste Seite** und **Zweite Seite** jeder Seite eine **Bezeichnung** – den
   Namen, den Weave für sie verwendet, etwa „Ist-Werte Hauptbuch“ – und wählen Sie ihre **Tabelle**. Wählen Sie unter
   **Kennzahl**, wie sich ihre Zeilen summieren – **Summe von**, **Anzahl von**, **Eindeutige Anzahl von**,
   **Minimum**, **Maximum** oder **Durchschnitt von** – und die Spalte.
5. Fügen Sie einer der Seiten **Filter** hinzu, um nur einen Teil ihrer Zeilen zu lesen. Trennen Sie mehrere
   Werte durch Kommas. Um zwei Perioden einer Tabelle zu vergleichen, wählen Sie auf beiden Seiten dieselbe Tabelle
   und filtern Sie jede Seite auf ihre Periode; fügen Sie die Periodenspalte nicht
   unter **Abgleichen nach** hinzu, sonst wird keine Zeile zugeordnet.
6. Fügen Sie unter **Abgleichen nach** eine Zeile pro Schlüsselspalte hinzu. Jede Zeile ordnet eine Spalte der
   ersten Seite einer Spalte der zweiten zu, sodass `account` mit `acct` abgeglichen werden kann. Geben Sie
   der Zeile eine Überschrift, etwa „Konto“; sie wird zur Überschrift dieser Spalte in der Liste der
   Abweichungen. Ohne Schlüssel wird jede Seite als einzelne Zahl verglichen – bei einer Summe oder Anzahl
ihre Gesamtsumme.
7. Legen Sie optional eine **Toleranz pro Zeile** fest: wie weit die beiden Werte einer Zeile auseinanderliegen
   dürfen und trotzdem übereinstimmen, in den Einheiten der Kennzahl selbst, etwa `0.01`. Es ist kein
   Prozentsatz. Lassen Sie den Wert auf 0, damit jede Zeile exakt übereinstimmen muss.
8. Wählen Sie optional einen **Workflow**, um die Abstimmung in die Bereitschafts-Checkliste dieses Workflows
   für den Abschluss aufzunehmen. Siehe [In der Bereitschafts-Checkliste](#in-der-bereitschafts-checkliste).
9. Klicken Sie auf **Entwurf speichern**.

Weave lehnt eine Abstimmung ab, die es nicht fair vergleichen könnte, und nennt den Grund:

- Die beiden Seiten brauchen dieselbe Anzahl von Schlüsseln, bis zu 8, und unterschiedliche Bezeichnungen, und
  sie dürfen abgesehen von ihren Bezeichnungen nicht identisch sein.
- Einander zugeordnete Schlüsselspalten müssen dieselbe Art von Wert enthalten – Zahlen, Text, Datumsangaben,
  Datums- und Uhrzeitangaben oder Wahr/Falsch. Spalten mit Gleitkommazahlen (Typen wie `float` oder
  `double`) können keine Schlüssel sein, und ein Schlüssel kann keine Spalte namens `value` oder `rows` sein.
- Eine Kennzahl muss eine Zahlenspalte sein, außer sie zählt.
- Ein Durchschnitt oder eine Summe, ein Minimum oder Maximum einer Spalte mit Gleitkommazahlen
  braucht eine Toleranz über 0, weil solche Werte selten exakt übereinstimmen.
- Jede Tabelle und Spalte, die sie nennt, muss im Projekt sein, und der Workflow, mit dem sie
  verknüpft ist, ebenfalls.
- Speichern ohne Änderungen wird abgelehnt.

Die beiden Seiten können unterschiedliche Kennzahlen verwenden, etwa eine Summe auf der einen und eine Anzahl
auf der anderen Seite. Fehlende Zeilen zählen nur dann als 0, wenn beide Seiten **Summe von** oder
**Anzahl von** verwenden; siehe [Das Ergebnis lesen](#das-ergebnis-lesen).

## Genehmigung

Eine Abstimmung kann einen Workflow als abschlussbereit kennzeichnen, deshalb braucht es zwei Personen.
Was Sie speichern, ist ein Entwurf. Ein anderer Architect wählt ihn aus und klickt auf **Genehmigen**,
und ab dann ist diese Version diejenige, die Leser und die Bereitschafts-Checkliste
ausführen. Sie können keine Version genehmigen, die Sie zuletzt bearbeitet haben, daher braucht ein Projekt
einen zweiten Architect, um eine Abstimmung in Gebrauch zu nehmen. Die Genehmigung prüft die Tabellen
erneut und wird abgelehnt, wenn sich der Entwurf geändert hat, seit die genehmigende Person ihn gelesen hat.

Das Bearbeiten einer genehmigten Abstimmung speichert einen neuen Entwurf, und die genehmigte Version
bleibt in Gebrauch, bis der neue genehmigt ist. Wenn ein neuerer Entwurf wartet, gibt das
Ergebnis das an. Architects können auf **Entwurf prüfen** klicken, um die Arbeitsversion
vor ihrer Genehmigung auszuführen.

<Aside type="caution">
Zum Löschen einer Abstimmung genügt ein Architect. Das ist die einzige Möglichkeit, wie eine einzelne Person
eine nicht übereinstimmende Abstimmung aus der Bereitschafts-Checkliste entfernen kann: Ihre Zeile
verschwindet mit ihr, und der Workflow kann dann **Bereit** lauten.
</Aside>

## Das Ergebnis lesen

Wählen Sie eine Abstimmung aus, um sie auszuführen. Klicken Sie auf **Erneut prüfen**, um sie auszuführen, nachdem sich die Daten
geändert haben.

Wenn sie nicht übereinstimmt, werden die abweichenden Zeilen unter dem Satz aufgeführt, die
größte zuerst, bis zu 50 davon. Jede zeigt ihre Schlüssel, die Werte beider Seiten und
die erste Seite abzüglich der zweiten. Eine Zeile, die nur auf einer Seite gefunden wurde, zeigt **keine Zeilen**
für die andere Seite, nie 0, und eine Zeile mit leerem Wert zeigt **kein Wert**.
Wenn mehr Zeilen abweichen als angezeigt werden, gibt eine Beschriftung an, wie viele ausgelassen wurden und
um wie viel sie zusammen abweichen; fügen Sie Filter hinzu, um weniger Zeilen auf einmal zu betrachten.

- **Toleranz.** Eine Zeile stimmt überein, wenn ihre beiden Werte nicht weiter auseinanderliegen als die
  Toleranz. Diese kleinen Abweichungen summieren sich dennoch, sodass eine Abstimmung Zeile für Zeile
  übereinstimmen kann, während ihre Summen abweichen, und der Satz sagt das dann:

  > Ist-Werte Hauptbuch stimmt mit Saldenliste überein: Jedes der 1.204 Konten liegt innerhalb
  > seiner Toleranz von 0,01. Über alle Konten saldieren sich diese kleinen Abweichungen auf 0,37:
  > Ist-Werte Hauptbuch ergibt in Summe 12.345.679,27 und Saldenliste 12.345.678,90, daher liegt
  > Ist-Werte Hauptbuch 0,37 höher.

- **Fehlende Zeilen.** Wenn beide Seiten **Summe von** oder **Anzahl von** verwenden, zählt eine Zeile, die nur
  eine Seite hat, auf der anderen Seite als 0, sodass eine Zeile mit 0 auf der einen Seite, die auf der
  anderen fehlt, übereinstimmt. Eine Seite ganz ohne Zeilen, während die andere welche hat,
  ist immer eine Abweichung.
- **Andere Kennzahlen.** Bei einer eindeutigen Anzahl, einem Minimum, einem Maximum oder einem
  Durchschnitt ist eine Zeile, die einer Seite fehlt, eine Abweichung, und es wird keine Summe angegeben,
  da sich diese Werte nicht addieren lassen.

Weave meldet **Nicht prüfbar**, wenn es die beiden Seiten nicht vollständig vergleichen kann,
und nennt den Grund, unter anderem wenn:

- Ihre Rolle keine Tabellendaten lesen kann oder eine der Tabellen, die eine Seite liest, nicht sehen kann;
- der Zeilenzugriff Sie nur einen Teil der Zeilen einer Seite sehen lässt – eine Übereinstimmung bei einem Teil der Daten
  ist keine Übereinstimmung;
- eine Tabelle oder Spalte, die die Abstimmung verwendet, entfernt oder umbenannt wurde, eine
  Schlüsselspalte jetzt eine andere Art von Wert enthält oder eine Kennzahlspalte keine Zahlen mehr
  enthält oder jetzt eine Toleranz braucht, die sie nicht hat;
- ein Nachschlagen in einer Seite jetzt für manche Einträge mehr als eine Zeile findet;
- keine der beiden Seiten Zeilen hat, die ihren Filtern entsprechen, oder keine für irgendeine
  Zeile einen Wert hat;
- die Abstimmung noch nicht genehmigt wurde;
- sie gerade nicht ausgeführt werden konnte, etwa wenn das Warehouse nur langsam antwortet.

<Aside type="note">
**Stimmt überein** bedeutet, dass die beiden Seiten Zeile für Zeile innerhalb der Toleranz übereinstimmen, für die
festgelegten Filter. Es sagt nichts darüber aus, ob eine der Seiten für sich genommen richtig ist.
</Aside>

## In der Bereitschafts-Checkliste

Eine mit einem Workflow verknüpfte Abstimmung erscheint beim Element dieses Workflows in jeder
[Bereitschaftsgruppe](/de/guides/ai-assistant/weave-readiness/), die den
Workflow enthält, als Zeile **Reconciliations tie out**, mit dem eigenen Satz jeder Abstimmung
und **Abstimmung öffnen**. Eine Abstimmung, die nicht übereinstimmt, macht
den Workflow **Nicht bereit**. Eine, die Weave nicht prüfen konnte oder die noch nicht
genehmigt wurde, macht ihn **Nicht prüfbar**, es sei denn, eine andere Zeile macht ihn bereits
**Nicht bereit**.

Die Checkliste führt jeweils die genehmigte Version aus, als die Person, die prüft,
daher spiegelt ihre Antwort die Zeilen wider, die diese Person sehen kann. Sie führt bis zu 25 pro
Checkliste aus und gibt ihnen zusammen eine Minute; alle darüber hinaus melden das, statt
ausgeführt zu werden, und zählen als **Nicht prüfbar**. Wenn Weave eine Gruppe vor ihrer
Fälligkeitszeit prüft, führt es sie als Eigentümer der Gruppe aus und liest Tabellen nur, wenn der Eigentümer
das beim letzten Speichern der Gruppe konnte.

## Wer was sehen kann

Alle, die die Registerkarte „Weave“ des Projekts öffnen können, können seine genehmigten
Abstimmungen auflisten. Zum Ausführen einer Abstimmung ist zusätzlich eine Rolle nötig, die Tabellendaten lesen kann. Ein Leser,
der kein Architect ist, sieht den Namen und die Seitenbezeichnungen jeder Abstimmung, nie ihre
Tabellen, Spalten oder Filter, und die Gründe, die Weave ihm nennt, nennen nur die
Seiten.

## Über die API

Abstimmungen sind über die Plattform-API verfügbar:
`GET /analyze/weave/reconciliations` listet die Abstimmungen eines Projekts auf, und
`GET`, `POST`, `PUT` und `DELETE` auf `/analyze/weave/reconciliation` lesen, erstellen,
ersetzen und löschen eine. `POST /analyze/weave/reconciliation/approve` genehmigt einen
Entwurf: Senden Sie `digest`, gesetzt auf den `content_digest`, den Sie mit ihm gelesen haben; das
identifiziert genau die Version, die Sie geprüft haben. `GET /analyze/weave/reconciliation/run` führt eine aus.

Eine Seite kann auch in anderen Tabellen nachschlagen – ein Join von der Tabelle der Seite zu einer
Nachschlagetabelle, der für jede Zeile der Seite höchstens eine Zeile finden darf. Nachschlagen und
die Kennzahl **Gewichteter Durchschnitt von**, die wie ein Durchschnitt eine Toleranz über 0 braucht,
lassen sich nur über die API festlegen; das Formular behält sie beim Bearbeiten bei.

Über MCP verbundene KI-Agenten können Abstimmungen mit
`reconciliation_find` und `reconciliation_run` finden und ausführen. Ein Architect, der mit seiner
eigenen Anmeldung verbunden ist, kann mit `reconciliation_upsert` auch einen Entwurf speichern; eine KI, die im
Auftrag einer Person handelt, etwa eine Agent-Sitzung, Microsoft 365 Copilot oder der In-App-Chat,
kann das nicht. Kein MCP-Tool genehmigt eine Abstimmung.
