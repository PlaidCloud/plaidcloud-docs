## Beschreibung

Vor dem Abschluss müssen Sie wissen, dass ein Zahlenwerk mit einem anderen übereinstimmt: das Hauptbuch mit der Saldenliste, ein Quellsystem mit seinem Ladevorgang, die Schlusssalden dieses Monats mit den Eröffnungssalden des nächsten. Eine **Abstimmung** benennt die beiden Seiten und wie ihre Zeilen einander zugeordnet werden, und Weave antwortet auf eine von drei Arten:

> Ist-Werte Hauptbuch stimmt mit Saldenliste überein: Alle 1.204 Konten stimmen exakt überein. Beide ergeben in Summe 12.345.678,90.

> Ist-Werte Hauptbuch stimmt nicht mit Saldenliste überein: 3 von 1.204 Konten weichen ab, insgesamt um 4.210,00 ohne Berücksichtigung des Vorzeichens. Saldiert liegt Ist-Werte Hauptbuch um 3.900,00 höher. Die größte Abweichung hat 4000 mit 3.900,00 (Ist-Werte Hauptbuch 1.000.000,00, Saldenliste 996.100,00).

> Weave konnte nicht prüfen, ob Ist-Werte Hauptbuch mit Saldenliste übereinstimmt: Keine der beiden Seiten hat Zeilen, die den Filtern dieser Abstimmung entsprechen. Wenn diese Daten noch nicht geladen wurden, laden Sie sie und prüfen Sie erneut.

Weave sagt nie, dass eine Abstimmung übereinstimmt, wenn es nicht beide Seiten vollständig lesen konnte. Der Vergleich ist eine Abfrage auf Ihren Daten; es ist keine KI beteiligt.

## Eine Abstimmung erstellen

Nur ein Architect des Projekts kann eine Abstimmung erstellen, bearbeiten oder löschen, und das Projekt muss entsperrt sein.

1. Öffnen Sie die Registerkarte **Weave** des Projekts und klicken Sie in der Symbolleiste auf **Abstimmungen**.
2. Klicken Sie auf **Neu**.
3. Geben Sie einen **Name** an und legen Sie unter **Zeilen heißen** fest, was eine verglichene Zeile ist, im Plural — „Konten“ oder „Paare aus Konto und Kostenstelle“. Weave verwendet das in jedem Satz; wenn Sie das Feld leer lassen, sagt es „Elemente“.
4. Geben Sie unter **Erste Seite** und **Zweite Seite** jeder Seite eine **Bezeichnung** — den Namen, den Weave für sie verwendet, etwa „Ist-Werte Hauptbuch“ — und wählen Sie ihre **Tabelle**. Wählen Sie unter **Kennzahl**, wie sich ihre Zeilen aufsummieren — **Summe von**, **Anzahl von**, **Eindeutige Anzahl von**, **Kleinster Wert**, **Größter Wert** oder **Durchschnitt von** — und die Spalte.
5. Fügen Sie einer der beiden Seiten **Filter** hinzu, um nur einen Teil ihrer Zeilen zu lesen. Trennen Sie mehrere Werte durch Kommas. Um zwei Perioden einer Tabelle zu vergleichen, wählen Sie auf beiden Seiten dieselbe Tabelle und filtern Sie jede Seite auf ihre Periode; fügen Sie die Periodenspalte nicht unter **Abgleichen nach** hinzu, sonst stimmen keine Zeilen überein.
6. Fügen Sie unter **Abgleichen nach** pro Schlüsselspalte eine Zeile hinzu. Jede Zeile ordnet eine Spalte der ersten Seite einer Spalte der zweiten Seite zu, sodass `account` mit `acct` abgeglichen werden kann. Geben Sie der Zeile eine Überschrift, etwa „Konto“; sie steht über dieser Spalte in der Liste der Abweichungen. Ohne Schlüssel wird jede Seite als einzelner Wert verglichen — als ihre Summe bzw. bei einer Anzahl als ihre Anzahl.
7. Legen Sie optional eine **Toleranz pro Zeile** fest: wie weit die beiden Werte einer Zeile auseinanderliegen dürfen und trotzdem übereinstimmen, in den Einheiten der Kennzahl, etwa `0.01`. Es ist keine Prozentangabe. Bei 0 muss jede Zeile exakt übereinstimmen.
8. Wählen Sie optional einen **Workflow**, um die Abstimmung in die Bereitschafts-Checkliste für den Abschluss dieses Workflows aufzunehmen. Siehe [In der Bereitschafts-Checkliste](#in-der-bereitschafts-checkliste).
9. Klicken Sie auf **Entwurf speichern**.

Weave lehnt eine Abstimmung ab, die es nicht fair vergleichen konnte, und nennt den Grund:

- Die beiden Seiten brauchen gleich viele Schlüssel, bis zu 8, und unterschiedliche Bezeichnungen, und sie dürfen sich nicht nur in ihren Bezeichnungen unterscheiden.
- Gepaarte Schlüsselspalten müssen dieselbe Art von Wert enthalten — Zahlen, Text, Datumsangaben, Datums- und Zeitangaben oder Wahr/Falsch. Spalten mit Gleitkommazahlen (Typen wie `float` oder `double`) können keine Schlüssel sein, und ein Schlüssel kann keine Spalte mit dem Namen `value` oder `rows` sein.
- Eine Kennzahl muss eine Zahlenspalte sein, es sei denn, sie zählt.
- Ein Durchschnitt oder eine Summe, ein kleinster oder größter Wert einer Spalte mit Gleitkommazahlen braucht eine Toleranz über 0, weil solche Werte selten exakt übereinstimmen.
- Jede genannte Tabelle und Spalte muss im Projekt sein, und auch der verknüpfte Workflow muss im Projekt sein.
- Ein Speichern ohne Änderung wird abgelehnt.

Die beiden Seiten können unterschiedliche Kennzahlen verwenden, etwa eine Summe auf der einen und eine Anzahl auf der anderen Seite. Fehlende Zeilen zählen nur dann als 0, wenn beide Seiten **Summe von** oder **Anzahl von** verwenden; siehe [Das Ergebnis lesen](#das-ergebnis-lesen).

## Genehmigung

Eine Abstimmung kann einen Workflow als abschlussbereit kennzeichnen, deshalb braucht sie zwei Personen. Was Sie speichern, ist ein Entwurf. Ein anderer Architect wählt ihn aus und klickt auf **Genehmigen**; ab dann ist diese Version diejenige, die Leser und die Bereitschafts-Checkliste ausführen. Sie können keine Version genehmigen, die Sie zuletzt bearbeitet haben, daher braucht ein Projekt einen zweiten Architect, um eine Abstimmung in Gebrauch zu nehmen. Die Genehmigung prüft die Tabellen erneut und wird abgelehnt, wenn sich der Entwurf geändert hat, seit der Genehmigende ihn gelesen hat.

Das Bearbeiten einer genehmigten Abstimmung speichert einen neuen Entwurf, und die genehmigte Version bleibt in Gebrauch, bis die neue genehmigt ist. Wartet ein neuerer Entwurf, weist das Ergebnis darauf hin. Architects können auf **Entwurf prüfen** klicken, um die Arbeitsversion vor der Genehmigung auszuführen.

<Aside type="caution">
Zum Löschen einer Abstimmung genügt ein Architect. Das ist die einzige Möglichkeit, wie eine einzelne Person eine Abstimmung, die nicht abstimmt, aus der Bereitschafts-Checkliste entfernen kann: Ihre Zeile verschwindet mit ihr, und der Workflow kann dann **Bereit** anzeigen.
</Aside>

## Das Ergebnis lesen

Wählen Sie eine Abstimmung aus, um sie auszuführen. Klicken Sie auf **Erneut prüfen**, um sie nach einer Datenänderung erneut auszuführen.

Wenn sie nicht abstimmt, werden die abweichenden Zeilen unter dem Satz aufgelistet, die größte zuerst, mit bis zu 50 angezeigten Zeilen. Jede zeigt ihre Schlüssel, die Werte beider Seiten und die erste Seite abzüglich der zweiten. Eine Zeile, die nur auf einer Seite vorkommt, zeigt für die andere Seite **keine Zeilen**, nie 0, und eine Zeile mit leerem Wert zeigt **kein Wert**. Weichen mehr Zeilen ab, als angezeigt werden, nennt eine Bildunterschrift, wie viele ausgelassen sind und um wie viel sie zusammen abweichen; fügen Sie Filter hinzu, um jeweils weniger Zeilen zu betrachten.

- **Toleranz.** Eine Zeile stimmt überein, wenn ihre beiden Werte nicht weiter auseinanderliegen als die Toleranz. Diese kleinen Abweichungen summieren sich dennoch, sodass eine Abstimmung zeilenweise übereinstimmen kann, während ihre Summen abweichen; der Satz sagt das dann auch:

  > Ist-Werte Hauptbuch stimmt mit Saldenliste überein: Jedes der 1.204 Konten liegt innerhalb seiner Toleranz von 0,01. Über alle Konten saldieren sich diese kleinen Abweichungen auf 0,37: Ist-Werte Hauptbuch ergibt in Summe 12.345.679,27 und Saldenliste 12.345.678,90, sodass Ist-Werte Hauptbuch um 0,37 höher liegt.

- **Fehlende Zeilen.** Wenn beide Seiten **Summe von** oder **Anzahl von** verwenden, zählt eine Zeile, die nur eine Seite hat, auf der anderen Seite als 0; eine Zeile mit 0 auf der einen Seite, die auf der anderen fehlt, stimmt also überein. Eine Seite ganz ohne Zeilen, während die andere welche hat, ist immer eine Abweichung.
- **Andere Kennzahlen.** Bei einer eindeutigen Anzahl, dem kleinsten oder größten Wert oder einem Durchschnitt ist eine Zeile, die einer Seite fehlt, eine Abweichung, und es wird keine Summe angegeben, da sich diese Werte nicht aufsummieren.

Weave sagt, dass es **nicht prüfen konnte**, wenn es die beiden Seiten nicht vollständig vergleichen kann, und nennt den Grund, unter anderem wenn:

- Ihre Rolle keine Tabellendaten lesen oder eine der von einer Seite gelesenen Tabellen nicht sehen kann;
- Zeilenzugriff Ihnen nur einen Teil der Zeilen einer Seite zeigt — eine Übereinstimmung auf einem Teil der Daten ist keine Übereinstimmung;
- eine von der Abstimmung verwendete Tabelle oder Spalte entfernt oder umbenannt wurde, eine Schlüsselspalte jetzt eine andere Art von Wert enthält oder eine Kennzahlspalte keine Zahlen mehr enthält oder jetzt eine Toleranz braucht, die sie nicht hat;
- eine Nachschlageverknüpfung in einer Seite für einige Einträge jetzt mehr als eine Zeile findet;
- keine der beiden Seiten Zeilen hat, die ihren Filtern entsprechen, oder keine für irgendeine Zeile einen Wert hat;
- die Abstimmung noch nicht genehmigt wurde;
- sie gerade nicht ausgeführt werden konnte, etwa weil das Warehouse langsam antwortet.

<Aside type="note">
**Stimmt ab** bedeutet, dass die beiden Seiten für die festgelegten Filter zeilenweise innerhalb der Toleranz übereinstimmen. Es sagt nichts darüber aus, ob eine der beiden Seiten für sich genommen korrekt ist.
</Aside>

## In der Bereitschafts-Checkliste

Eine mit einem Workflow verknüpfte Abstimmung erscheint beim Eintrag dieses Workflows in jeder [Bereitschaftsgruppe](/de/guides/ai-assistant/weave-readiness/), die den Workflow enthält, als Zeile **Reconciliations tie out**, mit dem eigenen Satz jeder Abstimmung und **Abstimmung öffnen**. Eine Abstimmung, die nicht abstimmt, lässt den Workflow **Nicht bereit** sein. Eine, die Weave nicht prüfen konnte oder die nicht genehmigt wurde, macht ihn **Nicht prüfbar**, sofern nicht bereits eine andere Zeile ihn **Nicht bereit** macht.

Die Checkliste führt die genehmigte Version jeder Abstimmung aus, als die Person, die prüft, sodass ihre Antwort die Zeilen widerspiegelt, die diese Person sehen kann. Sie führt pro Checkliste bis zu 25 aus und gibt ihnen zusammen eine Minute; alle darüber hinaus sagen das, statt ausgeführt zu werden, und zählen als **Nicht prüfbar**. Wenn Weave eine Gruppe vor ihrer Fälligkeitszeit prüft, führt es sie als Zuständiger der Gruppe aus und liest Tabellen nur, wenn der Zuständige das beim letzten Speichern der Gruppe konnte.

## Wer was sehen kann

Jeder, der die Weave-Registerkarte des Projekts öffnen kann, kann dessen genehmigte Abstimmungen auflisten. Zum Ausführen einer Abstimmung ist außerdem eine Rolle nötig, die Tabellendaten lesen kann. Ein Leser, der kein Architect ist, sieht Name und Seitenbezeichnungen jeder Abstimmung, nie deren Tabellen, Spalten oder Filter, und die Gründe, die Weave ihm nennt, benennen nur die Seiten.

## Über die API

Abstimmungen sind über die Plattform-API verfügbar: `GET /analyze/weave/reconciliations` listet die Abstimmungen eines Projekts auf, und `GET`, `POST`, `PUT` und `DELETE` auf `/analyze/weave/reconciliation` lesen, erstellen, ersetzen und löschen eine Abstimmung. `POST /analyze/weave/reconciliation/approve` genehmigt einen Entwurf: Senden Sie `digest`, gesetzt auf den `content_digest`, den Sie dabei gelesen haben und der genau die von Ihnen geprüfte Version identifiziert. `GET /analyze/weave/reconciliation/run` führt eine aus.

Eine Seite kann auch andere Tabellen nachschlagen — eine Verknüpfung von der Tabelle der Seite zu einer Nachschlagetabelle, die für jede Zeile der Seite höchstens eine Zeile finden darf. Nachschlageverknüpfungen und die Kennzahl **Gewichteter Durchschnitt von**, die wie ein Durchschnitt eine Toleranz über 0 braucht, lassen sich nur über die API festlegen; das Formular behält sie beim Bearbeiten bei.

KI-Agenten, die über MCP verbunden sind, können Abstimmungen mit `reconciliation_find` und `reconciliation_run` finden und ausführen. Ein Architect, der mit der eigenen Anmeldung verbunden ist, kann außerdem mit `reconciliation_upsert` einen Entwurf speichern; eine KI, die im Auftrag von jemandem handelt, etwa eine Agent-Sitzung, Microsoft 365 Copilot oder der Chat in der App, kann das nicht. Kein MCP-Tool genehmigt eine Abstimmung.
