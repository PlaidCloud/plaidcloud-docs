## Beschreibung

Der Workflow-Schritt **SQL extrahieren** führt ein schreibgeschütztes `SELECT` auf den Daten Ihres Projekts aus und schreibt das Ergebnis in eine neue Tabelle. Eine solche Abfrage von Hand zu schreiben, setzt voraus, dass Sie die Quelltabellen, ihre Spalten und das SQL zum Formen der Daten kennen.

Der Schritt-Editor kann die Abfrage für Sie schreiben. Beschreiben Sie die gewünschte Ausgabe in einfacher Sprache, und der KI-Assistent erstellt das `SELECT` – und wenn Sie ihm nicht sagen, aus welchen Tabellen gelesen werden soll, untersucht er die Tabellen des Projekts und wählt die relevanten selbst aus. Das generierte SQL und die erkannten Spalten werden zur Prüfung angezeigt und bleiben vor dem Speichern des Schritts vollständig bearbeitbar.

<Aside type="note">
Hierfür wird dasselbe integrierte Modell verwendet wie für den KI-Assistenten – es ist **nichts einzurichten**. Sie müssen dafür keinen Agenten und keine LLM-Verbindung pro Workspace konfigurieren.
</Aside>

## Den Schritt öffnen

Klicken Sie in der Ansicht **Schritte** eines Workflows auf **Schritt erstellen** und wählen Sie entweder:

- **Tables → Extract SQL** oder
- **AI → SQL Extract (AI Assisted)**

Beide öffnen denselben Schritt-Editor für SQL-Extract, der oben auf der Seite „Extraktionsparameter" nun einen Bereich **Generate SQL with AI** enthält.

## Die Abfrage generieren

1. **(Optional) Quelltabellen wählen.** Wählen Sie in der Liste **Quelltabellen** eine oder mehrere Tabellen aus, aus denen die Abfrage lesen soll. Lassen Sie die Liste leer, damit der Assistent das Projekt untersucht und die relevanten Tabellen für Sie auswählt.
2. **Beschreiben, was Sie möchten.** Schreiben Sie im Feld **Beschreiben** das Ergebnis in einfacher Sprache – zum Beispiel *„classify each ledger account into an activity pool based on its account number range"*.
3. **Auf „SQL generieren" klicken.** Der Assistent schreibt ein einzelnes schreibgeschütztes `SELECT`, validiert es durch Ausführen und füllt:
   - den Editor **SQL-Select-Abfrage** mit der generierten Anweisung und
   - die Zuordnungsseite **Tabellendatenauswahl** mit den erkannten Spalten.

   Wenn Sie die Quellliste leer gelassen haben, werden die vom Assistenten gewählten Tabellen in der Liste ausgewählt, sodass Sie sehen, was er verwendet hat, und es anpassen können.

## Prüfen und speichern

Das generierte SQL ist ein Ausgangspunkt, keine Blackbox:

- **Bearbeiten Sie es frei.** Der SQL-Editor ist vollständig bearbeitbar – verfeinern Sie die Abfrage, fügen Sie einen Join hinzu oder ändern Sie die Spaltenliste, bevor Sie speichern. (Um mehrere Tabellen zu verknüpfen, können Sie mehrere Quelltabellen auswählen oder einfach die generierte Abfrage bearbeiten.)
- **Wählen Sie eine Zieltabelle aus.** Wählen oder benennen Sie die **Zieltabelle**, in die der Schritt sein Ergebnis schreibt.
- **Speichern Sie den Schritt.** Er wird als gewöhnlicher SQL-Extract-Schritt gespeichert und läuft wie jeder andere als Teil des Workflows.

<Aside type="tip">
Gibt der Assistent eine Abfrage zurück, die nicht läuft, zeigt der Editor das SQL zusammen mit dem Fehler an, sodass Sie es korrigieren oder Ihre Beschreibung anpassen und erneut generieren können.
</Aside>

## Hinweise und Einschränkungen

- Der Assistent schreibt nur **schreibgeschützte** `SELECT`-Anweisungen; er erzeugt nie `INSERT`, `UPDATE`, `DELETE` oder anderes datenänderndes SQL.
- Die Generierung **erstellt oder führt den Schritt nicht aus** – sie entwirft nur die Abfrage und zeigt die Spalten in der Vorschau. Der Schritt wird beim Speichern erstellt und läuft, wenn der Workflow läuft.
- Die generierte Abfrage liest mit den **Anzeigenamen** Ihrer Tabellen – jede Tabelle wird oben in der Abfrage einmal unter ihrem Namen gebunden (sodass Spalten, Joins und Filter mit einfachen Namen statt mit internen `analyzetable_…`-IDs lesbar sind). Die echten Bezeichner werden beim Speichern automatisch wiederhergestellt, sodass die Abfrage unverändert läuft. Eine Tabelle, deren Name nicht eindeutig ist, behält ihren Bezeichner.
