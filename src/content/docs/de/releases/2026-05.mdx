## Hinzugefügt

- **Persönliches Temp-Laufwerk** – jedes Workspace-Mitglied erhält jetzt einen privaten, benutzerbezogenen Arbeitsbereich, der von verwaltetem Cloud-Speicher getragen wird. Auf Chart-Ebene standardmäßig aktiviert; für die Nutzung ist keine Aktion eines Administrators erforderlich.
- **Self-Service-Registrierung über Stripe** – neue Konten können sich jetzt direkt über plaidcloud.com registrieren, ohne Kontakt zum Vertrieb. Der Registrierungsablauf ist für die Bereitstellung von Tenants an die Control Plane angebunden.
- **MCP-Integrationsendpunkte** – die Routen `/mcp` und `/.well-known/oauth-*` werden jetzt an den PlaidCloud-RPC-Server geleitet. Damit können KI-Coding-Agenten (Claude Code, Cursor, Copilot, ChatGPT, Gemini) über das Model Context Protocol eine Verbindung herstellen. Siehe [KI-Coding-Agenten](/de/integrations/ai-coding-agents/).
- **Werkzeuge für die Migration zu Lakehouse v2** – der Migrator-Dienst, der Workspaces von Lakehouse v1 (Databend) zu Lakehouse v2 (StarRocks) verschiebt, ist jetzt flottenweit bereitgestellt, als Vorbereitung auf gestaffelte Tenant-Migrationen.

## Geändert

- **App-Oberfläche auf qooxdoo vereinheitlicht** – `app.<your-domain>` liefert jetzt direkt den qooxdoo-Client aus. Das ältere cp-frontend ist veraltet; Benutzer mit Lesezeichen auf alte Pfade werden transparent weitergeleitet.
- **Alte URLs werden automatisch weitergeleitet** – Aufrufe von `/signin` und verwandten älteren Pfaden werden jetzt per 301 auf die neue `/client/`-Oberfläche weitergeleitet. Aktualisieren Sie Ihre Lesezeichen nach Belieben; alte Links funktionieren weiterhin.
- **Workflow-Ausführungsverlauf** – pro Tenant werden jetzt zusätzliche Metadaten zum Ausführungsverlauf erfasst, die mehr Details in den Workflow-Protokollen sichtbar machen.

## Sicherheit

- **WAF ersetzt** – die Web Application Firewall am Perimeter wurde durch eine aktiver gepflegte Alternative ersetzt, ohne Änderung des zugelassenen Datenverkehrs.
