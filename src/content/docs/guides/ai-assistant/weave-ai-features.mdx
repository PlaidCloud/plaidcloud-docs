## Description

Workspace administrators decide which of Weave's AI features the workspace uses.
Each feature can be turned off on its own, for everyone in the workspace. Every
feature is on until an administrator turns it off.

Weave's checks and findings use no AI, so they stay on whatever you choose here.

## Turn a Feature On or Off

1. Click the **Weave** button in the header.
2. Choose **AI Features…** at the end of its menu.
3. Clear the box beside each feature to turn off, or tick it to turn it back on.
4. Click **Save**.

The change applies to the next AI request anyone in the workspace makes. Nobody
has to sign out.

**AI Features…** appears only for workspace administrators. Anyone else who tries
to change the features through the API is told *Only workspace administrators
can turn AI features on or off.*

## The Features

| Feature | What it covers | With it off |
|---|---|---|
| **Weave chat** | The chat on a project's **Weave** tab, **Ask the Assistant** in **Help & Support**, and Weave in the [PlaidCloud mobile app](/guides/mobile-app/weave-on-mobile/). | The **Weave** tab's **Chat** says the administrator has turned it off, **Help & Support** has no **Ask the Assistant** tab, and a question asked in the mobile app is refused. |
| **Fix assistant** | **Fix** on Weave's findings, and the **Weave AI** tab on a log entry. | Findings offer no **Fix**, and the **Weave AI** tab is unavailable. |
| **Import and export assistants** | Weave chat setting up a file import, an import step or an export step for you. | Weave chat can't set these up. |
| **Expression assistant** | The assistant in the expression editor. | The expression editor has no assistant. |
| **SQL from a description** | [Generate SQL with AI](/guides/ai-assistant/generate-sql-extract/) on the **Extract SQL** step. | The step has no **Generate SQL with AI** section. You can still write the SQL yourself. |
| **Workflow review summary** | The summary written by AI above a workflow's **Check**. | **Check** shows its findings without the summary. |
| **Starter chart** | AI choosing the first chart for a file you drop in. | A rule chooses the chart instead. |

Someone who was already signed in when you made the change still sees the
feature until they reload PlaidCloud, but Weave no longer uses AI for it. The
chat, the fix and expression assistants, and SQL from a description say so, for
example *Your workspace administrator has turned off the fix assistant.*

<Aside type="note">
These switches cover the AI that PlaidCloud provides. AI steps in your workflows
use your own AI connection, and AI tools you connect over
[MCP](/integrations/ai-coding-agents/) use their own model, so neither is
affected.
</Aside>

## Record of Changes

Each feature turned on or off is recorded in the workspace's Security Log, with who
changed it and when, for example *Turned off the fix assistant.*

## Through the API

`GET /rest/v1/analyze/ai/features` returns each feature and whether it is on, as
`{"features": [{"feature": "chat", "on": true}, …]}`. The feature names are
`chat`, `fix`, `import_export`, `expression`, `sql_extract`, `review_summary` and
`starter_chart`.

`PUT /rest/v1/analyze/ai/features` with `{"off": ["fix"], "on": ["chat"]}` turns
off the features in `off` and on those in `on`. A feature in neither list stays as
it is, so two administrators changing different features don't undo each other.
It answers as the `GET` does. Only a workspace administrator can call it, and a
name that isn't a feature, or one in both lists, is refused.
