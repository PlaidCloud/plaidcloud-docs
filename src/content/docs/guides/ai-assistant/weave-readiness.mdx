## Description

On the days that matter most — month-end, a forecast submission, a board pack —
the question is not "what has Weave noticed?" but "are we ready?". A **readiness
set** names the workflows a deadline depends on, and **Check** answers that
question for all of them at once, in one checklist that opens with its own
count:

> 11 of 13 ready; 1 not ready; 1 couldn't check.

Each workflow in the set is one item. It is **Ready** only when every check Weave
could run on it passed. It is **Not ready** when one of them found a problem, and
the problem is listed beneath it with the same **Fix**, **Go To** and **How Weave
knows** buttons as the Weave tab. It is **Couldn't check** when Weave had no way
to judge part of it, and the reason is written out. Nothing Weave did not judge
is ever shown as ready.

The checks are the rules Weave already runs — no AI is involved — so a checklist
costs nothing however often you ask for it. For what those rules read and what
their answers mean, see [What Weave Checks](/guides/ai-assistant/weave-findings/).

## Make a Readiness Set

1. Open the project's **Weave** tab and click **Readiness** in its toolbar.
2. Click **New**. Give the set a name, such as "Month-end close", and move the
   workflows it depends on from **Workflows in the project** to **Workflows in
   this set**.
3. Optionally tick **Has a due time** and say when the set is due, as a cron
   expression with the UTC offset it is written in — the same form a scheduled
   event uses. `0 9 5 * *` with **UTC +0** is 09:00 UTC on the 5th of every
   month; `0 8 * * 1` is 08:00 every Monday.
4. Say how many hours before the due time Weave should tell the set's owner, from
   1 to 168. The default is 24.
5. Click **Save**.

A set belongs to the project and everyone who can open the project's Weave tab
can check it. Making, editing or deleting a set needs write access to the
project, and every workflow in a set must be one in that project. A set is not
copied when its project is copied.

## Read the Checklist

Select a set on the left. Weave reads the whole project — the same read the Weave
tab makes — and judges each workflow in the set. Click **Check Again** after you
have fixed something.

Each item shows the workflow's name, its verdict, and one line per check that
applies to it:

| Line | What Weave compares | When it says "couldn't check" |
|------|---------------------|-------------------------------|
| **Inputs are fresh** | Every table the workflow reads, against the schedule or the freshness threshold of the workflows that write it. | Your role can't read tables; a table it reads is hidden from you; a table it reads has neither a scheduled writer nor a freshness threshold, so nothing says when it should have been written. |
| **Last run succeeded** | The workflow's most recent run. | It has no runs on record, or its run history couldn't be read. |
| **Last run looked usual** | How long the last run took, and how many rows its steps wrote, how many empty values they left and how their values spread, against the earlier runs. | The last run failed or didn't complete, so there is nothing usual to compare; a step has too few earlier runs; your row access hides run sizes. |
| **Inputs unchanged since it last ran** | Whether a table it reads was written to by another workflow after it last read it. | Your role can't read tables, or the workflow has no runs to compare against. |
| **Schedule is healthy** | Its scheduled events: valid timetables, in step with the scheduler, no due run missed, no due time lost to a run still going. | The scheduler couldn't be read. |

A workflow with no scheduled events has no **Schedule is healthy** line, and the
item says it is not scheduled. That is a fact about the workflow, not something
Weave failed to check.

A workflow that has been deleted from the project since the set was made, or
that your role can't see, is still counted. It appears as **Couldn't check** with
the reason, so the count never quietly shrinks.

<Aside type="note">
**Ready** means every check Weave could run passed. It is not a statement that
the workflow's figures are right, that its dashboards are current, or that
anything outside the project is in order. The lines name exactly what was
compared, and **How Weave knows** on a finding names what the check leaves out.
</Aside>

## Be Told Before the Due Time

For a set with a due time, Weave runs the check on its own as the due time
approaches and tells the set's owner — whoever created it — once per due time,
as an in-app message:

> "Month-end close" is due in 3 days (31 Oct 17:00 UTC): 11 of its 13 workflows
> ready, 1 not ready, 1 Weave couldn't check.

Click **Open Weave** on the message to open the project's Weave tab and the
checklist for that set. The message carries counts only; the names and the
reasons are in the checklist. If the owner can no longer open the project,
nothing is sent.

Weave checks on the hour, so a set whose notice is 24 hours is told within the
hour after it comes 24 hours from due. The check runs as the owner, and it reads
tables only if the person who last saved the set could read tables: a set saved
by someone without table access reports its table lines as unchecked until
someone with table access saves it again.

## Through the API

Readiness sets are available through the platform API under
`/analyze/weave/readiness`: `GET /sets` lists a project's sets, `GET /set`,
`POST /set`, `PUT /set` and `DELETE /set` read, create, replace and delete one,
and `GET /check` returns the checklist as the window shows it, with each line's
findings.
