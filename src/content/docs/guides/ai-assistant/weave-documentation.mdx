## Description

Select a table, step or workflow in a project and its details panel opens. At
the bottom, a **Documentation** section shows a page Weave writes about it from
the project's saved settings:

- for a table, the steps that write and read it, and its columns;
- for a step, what it does and where it runs;
- for a workflow, its steps in order and the tables it reads and writes.

The page is written each time you select the item, from the settings as they
are saved at that moment, so it never goes out of date and there is nothing to
refresh by hand. No AI is involved, so it works when no AI provider is
available. After a save in the same details panel, such as a new description,
the page is written again.

The AI assistant in a project, and AI assistants connected over MCP, can read
the same page. See [For AI Assistants](#for-ai-assistants).

## A Table's Page

- **The description** — the table's **Memo**, shown as a quote. PlaidCloud
  sets the memo *Created dynamically* on a table a step creates; that one is not
  shown, since it says nothing about the table.
- **Written by** and **Read by** — each step, by name, with its step type and
  the workflows it is in. *(disabled)* follows a workflow where the step is
  disabled, and *not in any workflow* marks a step that isn't in one. A step
  whose table name holds a variable that may or may not name this table is
  listed with *depending on the values of its variables*. A Table: Clear, Table:
  Drop or Table: In-Place Delete step counts as writing the table it changes, and
  a step that reads a table and writes it back is listed under both.
- **No step in this project reads this table.** means no step in this project
  lists it as a source. The page does not check dashboards, exports, other
  projects or anything outside the project's steps.
- **Columns** — each column and its type, with its description from **Column
  Properties** where one is set.

## A Step's Page

**What it does** gives one sentence for each thing the step does:

| Step | The page says |
| --- | --- |
| Allocation: Split | Which value it splits from which table, across which columns, using which driver column, and how each share is worked out — for example, "Each `product`'s share is its `weight` divided by the total `weight` for the same `cost_center`, `year` and `month`." Columns are named as the source and driver tables name them. A filter on the step's source or driver is noted, and the tables it writes are named. |
| Allocation: Split using Dimension | Which value it splits from which table and which driver column it uses, and every table it writes, including its mapping, path and summary tables. |
| Import | The file or files it imports and the table it imports into. |
| Export | The table it exports and the file it writes. |
| Extract: SQL with no listed sources | That it runs a SQL query, and the table it writes. |
| Table: Clear, Table: Drop, Table: In-Place Delete | That it clears, drops or deletes rows from its table. |
| A step that runs another workflow | The workflow it runs and how: when its conditions are met, in a loop, as a macro, or by including it. A workflow chosen by a variable is shown as the name the step gives. Any table the step itself reads, such as the table a loop steps through, is listed too. |
| Any other step | The tables it reads and the tables it writes. |

The page then says where the step runs — *It is step 3 in* followed by the
workflow, numbered as in the workflow's steps list — or that it isn't in any
workflow.

A table the step names through a variable is shown by its name, followed by
*(named by a variable)*.

## A Workflow's Page

- **Steps** — numbered as in the workflow's steps list, with each step's type
  and the table it writes, or the workflow it runs. Steps of a workflow it
  includes are listed in place, as the steps list shows them.
- **Reads from outside this workflow** — tables a step reads before any step in
  this workflow writes them.
- **Writes** — tables the workflow's steps write.

Disabled steps are listed in **Steps** but left out of the two lists, and the
page says so. The tables used by a workflow that one of its steps runs are on
that workflow's own page.

## What Your Role Hides

A table, step or workflow can be hidden from the Manager or Explorer role. A
page never names one your role hides:

- A step you can't open is counted — for example, *2 more steps you can't open*
  — and keeps its number in a workflow's steps list.
- A table, step or workflow you can't open reads the same as one that no longer
  exists — for example, *a table you can't open or that no longer exists* — so
  a page can't be used to find out whether something hidden exists. The steps
  left out of a workflow's lists this way are noted, since a table one of them
  writes may then be listed as read from outside. A table a
  step names that you can't open, or that doesn't exist, is shown by the name
  the step gives it, followed by *(not a table you can open)*, and a workflow
  likewise by *(not a workflow you can open)*.
- Asking for the page of an item your role hides answers as if it isn't there.

An Architect can open everything, so an Architect's pages say *a deleted
table*, *(table not found)*, *A deleted step* or *(workflow not found)* instead.

## What It Doesn't Cover

- **Row counts, sizes and update times.**
- **Tables a step reaches only through its SQL text or an expression.** The
  page lists the tables a step names in its settings.
- **Unsaved edits.** The page describes the saved settings.

<Aside type="note">
The page doesn't interpret your data or judge whether a step is right. It
states what the saved settings say, in plain language.
</Aside>

## For AI Assistants

- **The AI assistant in PlaidCloud** can read a table's, step's or workflow's
  page when you ask about it in a conversation opened on a project, and answer
  from what the page says. See [Using the AI
  Assistant](/guides/ai-assistant/using-ai-assistant/).
- **AI assistants connected over MCP** can read the same page with the
  `doc_describe` tool, given the project, whether the item is a table, step or
  workflow, and its id. It needs read access to steps, workflows and tables,
  and follows the same rules for what your role hides. See [AI Agents
  (MCP)](/integrations/ai-coding-agents/).
