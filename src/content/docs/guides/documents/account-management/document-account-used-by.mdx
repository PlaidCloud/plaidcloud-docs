Before you retire, replace or rebuild a document account, find everything that uses it, then move those uses to another account.

## See Where an Account Is Used

1. Select `Document > Manage Accounts`.
2. Select the **Used By** icon on the account's row.

**Where Used** lists each use with its project, type, name and how the account is used:

| Column | Values |
| --- | --- |
| Type | Step, Workflow, or Project default |
| Used | Directly; Container condition; Project default; or Variable (may be used) |

Steps and workflows your role can't see are counted but not named. The list is gathered a project at a time and says when it may be incomplete or which projects were never scanned.

App Runner manifests and project tile images are not scanned. A use that comes from a variable is listed, and you update that variable by hand.

## Re-Point an Account

1. In **Where Used**, select **Re-point...**.
2. Choose the account to switch to, then select **Preview**.
3. Review the uses. Nothing has changed yet. Clear any you want to leave alone.
4. Select **Re-point** and confirm.

Each use then shows its result: **Changed**, **Changed since the preview**, **Not allowed**, **Project is locked**, **No longer exists** or **Refused**. A use that fails doesn't stop the others. Changing a project default requires an Architect or workspace administrator.

Variable uses are never changed. The preview names each variable and the step to update by hand.

<Aside type="caution">If you re-point to a Personal Temp Drive, workflows run as the project, which cannot open that drive, and the re-pointed steps fail when they run. PlaidCloud warns you for each affected project.</Aside>

## Using an AI Assistant

* The AI assistant in a project can propose a re-point. It shows the changes on an approval card and applies them only after you approve.
* Over MCP, `document_account_describe(include=['used_by'])` lists the uses and `document_account_repoint` previews and applies a re-point.
