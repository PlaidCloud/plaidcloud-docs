[Data Foundation](/guides/projects/data-foundation/) brings data from every ERP system and instance you connect into one Common Finance Model, and Sage Intacct is one of the ERPs it reads directly. The connection uses Intacct Web Services: a sender authorization for PlaidCloud and a read-only Web Services user. This page is for the Sage Intacct administrator who sets that up, and for the PlaidCloud user who asks them to.

PlaidCloud only reads data. Nobody sends a password by email.

## Send the Access Request

On the project's **Systems** page, under **Data Foundation** in **Home**, choose your system in **System** under **Add a system** and click **Don't have access yet?**. The system waits for access, and one request covering the project's systems is shown. Click **Copy request** to paste it into your own message, or **Email request** to open it in your mail program with the subject "Access for PlaidCloud."

## What the Sage Intacct Administrator Sets Up

<Steps>

1. **Authorize PlaidCloud as a Web Services sender.** Under **Company > Admin > Web Services authorizations**, add the Sender ID PlaidCloud gave you. Send back the Sender ID and the Sender password Sage issued for it.

2. **Create a Web Services user.** Under **Company > Admin > Users**, create a user of type "Business" with the "Web services only" option, and a role with **View** permission on:

   | Area | Objects |
   |---|---|
   | General Ledger | Accounts, Statistical accounts, Journal entries (all journals, including adjustment journals), Account balances, Reporting periods, Exchange rates, Budgets |
   | Company | Entities (locations), Departments, Classes, Projects |
   | Accounts Receivable | Customers, Invoices, Adjustments, Payments |
   | Accounts Payable | Vendors, Bills, Adjustments, Payments |
   | Cash Management | Checking accounts |
   | Inventory Control | Items |
   | Order Entry | Transactions (sales invoices, and the credit memos and returns that take them back), if you want sales |

   Give the user access to the top level of the company and to every entity PlaidCloud reports on. If your credit memo and return transaction definitions aren't named Sales Credit Memo and Sales Return, tell the PlaidCloud user their names.

3. **Allow the user's IP address** if your company restricts Web Services by IP.

</Steps>

## What to Send Back

| The administrator sends | Entered in PlaidCloud as |
|---|---|
| The company ID | **Company ID** |
| The Web Services user ID | **Web Service User Username** |
| The Sender ID | **Client ID** |
| The Sender password | **Client Secret** |
| The names of your credit memo and return transaction definitions, if not the defaults | The **Credit memo and return document types** system setting (defaults: Sales Credit Memo, Sales Return) |
| The entities PlaidCloud may read | Under **Options**, **Companies**: tick them, or none for all of them |

Passwords go through your password manager, never by email. The PlaidCloud user's team enters the Sender password as the **Client Secret** themselves. Entities that are your company's own eliminations go under the **Elimination entities** system setting.

## Check the Access

Back in PlaidCloud, once the system is added, click **Test connection** on its row on the **Systems** page. It reads the required datasets and shows each as **Readable**, **Missing permission** or **Error**. The optional ones, marked below, aren't part of the test: if Sage Intacct refuses one, after the next load the readiness checks, on the **CFM-Accounting - Close and assurance** dashboard, name the object to grant.

| Dataset | Permission it needs |
|---|---|
| Entities | Company: Entities (View) |
| Chart of accounts | General Ledger: Accounts and Statistical accounts (View) |
| Departments | Company: Departments (View) |
| Customers | Accounts Receivable: Customers (View) |
| Products | Inventory Control: Items (View) |
| Currency rates | General Ledger: Exchange rates (View) |
| Fiscal calendar | General Ledger: Reporting periods (View) |
| Trial balance | General Ledger: Account balances (View) |
| General ledger | General Ledger: Journal entries (View) |
| Month-end balance (optional) | General Ledger: Account balances (View) |
| Bank balances (optional) | Cash Management: Checking accounts (View), with the month-end balance |
| Sites (optional) | Company: Entities (locations) (View) |
| Profit centers (optional) | Company: Classes (View) |
| Projects (optional) | Company: Projects (View) |
| Suppliers (optional) | Accounts Payable: Vendors (View) |
| Sales lines (optional) | Order Entry: Transactions (View) |
| Supplier invoice lines (optional) | Accounts Payable: Bills and Adjustments (View) |
| Open items and Payments (optional) | Accounts Receivable: Invoices, Adjustments and Payments, and Accounts Payable: Bills, Adjustments and Payments (View) |
| Budget (optional) | General Ledger: Budgets (View) |
| Allocation drivers (optional) | General Ledger: Account balances (View) |

When a dataset is missing, the test names the permission to add. Ask the administrator to add it to the role and test again. A company that doesn't use an optional dataset still loads everything else. When Sage Intacct refuses a read that a month's supplier invoices, open items or payments are built from, that month keeps the rows it already had and is read again at the next load.

Who entered a journal, when, who approved it and what it reverses are read from the journal's batch. A role that can't read the batch leaves them empty.
