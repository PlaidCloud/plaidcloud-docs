[Data Foundation](/guides/projects/data-foundation/) brings data from every ERP system and instance you connect into one Common Finance Model, and Dynamics 365 Finance and Operations is one of the ERPs it reads directly. The connection uses a Microsoft Entra ID application with a client secret for the master data, and your Fabric (Synapse) Link SQL endpoint for the general journal, the sub-ledgers and bank balances. This page is for the Dynamics 365 administrator who sets that up, and for the PlaidCloud user who asks them to.

PlaidCloud only reads data. Nobody sends a client secret or a SQL password by email.

## Send the Access Request

On the project's **Systems** page, under **Data Foundation** in **Home**, choose your system in **System** under **Add a system** and click **Don't have access yet?**. The system waits for access, and one request covering the project's systems is shown. Click **Copy request** to paste it into your own message, or **Email request** to open it in your mail program with the subject "Access for PlaidCloud."

## What the Dynamics 365 Administrator Sets Up

<Steps>

1. **Register an application in Microsoft Entra ID** for PlaidCloud, with a client secret. Note its Application (client) ID, the Directory (tenant) ID and the secret.

2. **Map the application to a user.** In Dynamics 365, under **System administration > Setup > Microsoft Entra ID applications**, add the client ID and map it to a user with a role that can view, for every legal entity you want to load:

   - General ledger: legal entities, fiscal calendars, main accounts, financial dimension values, exchange rates
   - Accounts receivable: customers and customer invoice lines
   - Accounts payable: vendors (optional)
   - Product information management: released products
   - Inventory management: on-hand and inventory transactions (optional)
   - Budgeting: budget register entries (optional)

3. **Set up Fabric Link for the general journal.** General journal lines are read from your Fabric (Synapse) Link SQL endpoint, not from the OData service. Confirm that Fabric Link is on for these tables, and create a read-only SQL login for PlaidCloud on that endpoint:

   - `generaljournalaccountentry`
   - `generaljournalentry`
   - `fiscalcalendarperiod`
   - `dimensionattributelevelvalue`, with one row per dimension value of each financial dimension combination and the name of its dimension
   - for open items and payments (optional): `custtrans`, `vendtrans`, `custsettlement`, `vendsettlement`
   - for supplier invoice lines (optional): `vendinvoicetrans`, `vendinvoicejour`
   - for bank balances (optional): `bankaccounttrans`, `bankaccounttable`

   Sites and profit centers are the values of the `Site` and `BusinessUnit` financial dimensions.

</Steps>

## What to Send Back

| The administrator sends | Entered in PlaidCloud as |
|---|---|
| The Environment URL, `https://<name>.operations.dynamics.com` | **Environment URL** |
| The Directory (tenant) ID | **Azure AD Tenant ID** |
| The Application (client) ID | **Client ID** |
| The `dataAreaId` of one legal entity | **Legal Entity / Company (dataAreaId)**: the connection needs one, and Data Foundation reads the legal entities chosen under **Companies** |
| The Fabric Link SQL endpoint, database and login | A separate SQL connection in PlaidCloud, whose connection ID goes in the **Fabric Link SQL connection (its connection ID)** system setting |
| The main account categories of your cost of goods sold accounts (PlaidCloud assumes `COGS`) | The **Cost of goods sold main account categories** system setting |
| The main account categories of the accounts that are not operating: interest, income tax, foreign exchange gains and losses, other income | The **Non-operating main account categories** system setting |
| The financial dimension that names a line's intercompany partner (PlaidCloud assumes `IntercompanyPartner`) | The **Intercompany partner dimension** system setting |
| The legal entities PlaidCloud may read | Under **Options**, **Companies**: tick them, or none for all of them |

The client secret and the SQL login's password never go by email. The PlaidCloud user's team pastes the **Client Secret** into PlaidCloud themselves, and the SQL connection holds the SQL login. Legal entities that are consolidation entities go under the **Consolidation legal entities** system setting, so their postings aren't counted as a company's activity.

## Check the Access

Back in PlaidCloud, once the system is added, click **Test connection** on its row on the **Systems** page. Each dataset shows as **Readable**, **Missing permission** or **Error**:

| Dataset | Permission it needs |
|---|---|
| Entities | General ledger: View legal entities |
| Fiscal calendar | General ledger: View fiscal calendars |
| Chart of accounts | General ledger: View main accounts |
| Departments | General ledger: View financial dimension values |
| Customers | Accounts receivable: View customers |
| Products | Product information management: View released products |
| Currency rates | General ledger: View exchange rates |
| Trial balance, General ledger | View the general ledger (the journal, through Fabric Link) |
| Every other dataset | Optional, not part of the test |

When a dataset is missing, the test names the permission to add. Ask the administrator to add it to the role and test again.

The optional datasets are sites, profit centers, suppliers, sales lines, inventory balances, budgets, bank balances, supplier invoice lines, open items and payments. An environment that doesn't hold one still loads everything else. A month's bank balances, supplier invoice lines, open items or payments that can't be read from Fabric Link keep the rows they already had and are read again at the next load.

Dynamics 365 has no balance object the connection can read, so no month-end balance loads: the ledger is compared with its own trial balance.
