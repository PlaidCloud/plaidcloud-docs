[Data Foundation](/guides/projects/data-foundation/) brings data from every system you connect, in as many instances as you have, into one Common Finance Model. Salesforce is one of the systems it reads directly. Salesforce is a CRM source, not a ledger: it supplies customers, products, the sales pipeline, sales reps, campaigns, its fiscal months and orders, never general ledger entries. This page is for the Salesforce administrator who sets up the access, and for the PlaidCloud user who asks them to.

PlaidCloud only reads data. Nobody sends a password or a security token by email.

## Send the Access Request

On the project's **Systems** page, under **Data Foundation** in **Home**, choose your system in **System** under **Add a system** and click **Don't have access yet?**. The system waits for access, and one request covering the project's systems is shown. Click **Copy request** to paste it into your own message, or **Email request** to open it in your mail program with the subject "Access for PlaidCloud."

## What the Salesforce Administrator Sets Up

<Steps>

1. **Create an External Client App** under **Setup > Apps > External Client Apps > New**, or a Connected App if your org still has them:

   - Enable OAuth settings, and tick **Enable Client Credentials Flow** only (no authorization code or password flow).
   - **OAuth scope:** Manage user data via APIs (`api`).
   - **Run As:** a dedicated integration user (step 2).

2. **Give the integration user a profile or permission set** with:

   - API Enabled
   - Read on Account (including the Account Number field), Product2, Opportunity, OpportunityLineItem and Organization (for the default currency)
   - Read on User (sales reps), Campaign (campaigns, read as projects), FiscalYearSettings and Period (the fiscal months), OpportunityHistory and OpportunityStage (the pipeline as it stood at each month end), and Order and OrderItem (orders, with Orders enabled), if you want them in the model
   - View All Data, or sharing that lets it see every opportunity you report on

   Salesforce limits every row and field PlaidCloud can read to what this user can see.

3. **Copy the Consumer Key (client ID) and Consumer Secret** from the app, and the org's My Domain URL, for example `https://yourcompany.my.salesforce.com`.

</Steps>

## What to Send Back

| The administrator sends | Entered in PlaidCloud as |
|---|---|
| The My Domain URL | **My Domain**: the domain name only, such as `yourcompany`; `.my.salesforce.com` is added for you |
| The Client ID (Consumer Key) | **Client ID** |
| The Client secret (Consumer Secret), through the secure connection form, not by email | **Client Secret** |

Under **Options**, **Companies**, enter the one entity the Salesforce org's pipeline belongs to: an org has no entities to list. One org is one entity, so two orgs are two connections.

## Check the Access

Back in PlaidCloud, once the system is added, click **Test connection** on its row on the **Systems** page. Each dataset shows as **Readable**, **Missing permission** or **Error**:

| Dataset | What it reads in Salesforce |
|---|---|
| Customers | Account |
| Products | Product2 |
| Pipeline | Opportunity and OpportunityLineItem, with the account numbers |
| The org's default currency | Organization |

All of them are optional. When one shows **Missing permission**, ask the administrator to add the read access on that object to the integration user and test again.

The test doesn't read the other datasets, all optional too:

| Dataset | What it reads in Salesforce |
|---|---|
| Sales reps | User |
| Projects | Campaign |
| Fiscal calendar | FiscalYearSettings and Period, the months only |
| Pipeline, as it stood at each past month end | OpportunityHistory and OpportunityStage |
| Sales orders | Order and OrderItem |

If Salesforce refuses one, after the next load the readiness checks, on the **CFM-Accounting - Close and assurance** dashboard, name the objects to give the integration user Read on. A month's pipeline or orders that can't be read keep the rows they already had.

Pipeline amounts are in the opportunity's currency. An org that uses one currency has no such field, so PlaidCloud uses the org's default currency from Organization, and otherwise the entity's currency.
