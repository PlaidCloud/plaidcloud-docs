[Data Foundation](/guides/projects/data-foundation/) brings data from every ERP and accounting system you connect, in as many instances as you have, into one Common Finance Model. Xero is one of the systems it reads directly, one Xero organisation per connection. This page is for the Xero administrator who sets up the access, and for the PlaidCloud user who asks them to.

PlaidCloud only reads data. Nobody sends a password by email.

## Send the Access Request

On the project's **Systems** page, under **Data Foundation** in **Home**, choose your system in **System** under **Add a system** and click **Don't have access yet?**. The system waits for access, and one request covering the project's systems is shown. Click **Copy request** to paste it into your own message, or **Email request** to open it in your mail program with the subject "Access for PlaidCloud."

## What the Xero Administrator Sets Up

<Steps>

1. **Authorise PlaidCloud's Xero app** for each organisation you report on, signed in as a user with the Standard or Advanced role. When the PlaidCloud user clicks **Connect to Xero**, Xero's consent screen asks for these scopes:

   | Scope | What Data Foundation reads with it |
   |---|---|
   | `offline_access` | Nothing: it keeps the connection signed in between loads |
   | `accounting.settings` | Organisation, chart of accounts, tracking categories, items |
   | `accounting.contacts` | Customers and suppliers |
   | `accounting.transactions` | Sales invoices and credit notes, bills and supplier credit notes, spend money transactions, payments, overpayments and prepayments |
   | `accounting.reports.read` | The trial balance, for opening balances and each month-end balance, and budgets |

   Data Foundation only reads, though `accounting.settings`, `accounting.contacts` and `accounting.transactions` also allow changes. The general ledger is read from Xero's journals, which need `accounting.journals.read`, and the consent screen doesn't ask for it. Without it the general ledger can't load. The chart of accounts, departments, customers and products still do.

2. **Set up the tracking categories PlaidCloud reads**, by these names:

   - **Department:** one option per department, named as you want its code to appear.
   - **Site** and **Profit centre** (optional): one option per site or profit center, if you track them.
   - **Intercompany:** one option per group company, named by that company's entity code, on the lines of intercompany journals. Name intercompany accounts so that "Intercompany" is part of the account name.

</Steps>

## What to Send Back

| The administrator sends | Entered in PlaidCloud as |
|---|---|
| Confirmation that the organisation's financial year end and period lock date are set | Nothing to enter: PlaidCloud reads both from Xero |

There is no ID, token or password to send. On the project's **Systems** page, the PlaidCloud user chooses Xero in **System** under **Add a system** and clicks **Connect to Xero**, and the Xero user signs in and approves the app. The connection loads one organisation, chosen in its **Organisation** field.

Under **System settings**, **Retained earnings account** names the Equity account the opening profit and loss rolls into, when the account names don't already say. It's optional.

## Check the Access

Back in PlaidCloud, once the system is added, click **Test connection** on its row on the **Systems** page. It reads the required datasets (entities, chart of accounts, fiscal calendar, general ledger and trial balance) and shows each as **Readable**, **Missing permission** or **Error**. The optional ones aren't part of the test: if Xero refuses one, the readiness checks name it after the next load.

| Dataset | Scope it needs |
|---|---|
| Entities | `accounting.settings.read` |
| Chart of accounts | `accounting.settings.read` |
| Fiscal calendar | `accounting.settings.read` |
| General ledger | `accounting.journals.read` |
| Trial balance | `accounting.reports.read` |
| Departments (optional) | `accounting.settings.read` (the Department tracking category) |
| Sites and Profit centers (optional) | `accounting.settings.read` (the Site and Profit centre tracking categories) |
| Products (optional) | `accounting.settings.read` |
| Customers and Suppliers (optional) | `accounting.contacts.read` |
| Month-end balance and Bank balances (optional) | `accounting.reports.read` (the trial balance at each month end) |
| Sales lines (optional) | `accounting.transactions.read` |
| Supplier invoice lines (optional) | `accounting.transactions.read` (bills, supplier credit notes and spend money transactions) |
| Open items and Payments (optional) | `accounting.transactions.read` |
| Budget (optional) | `accounting.reports.read` |

When a dataset shows **Missing permission**, the test names the scope to grant. Re-authorise the app with it and test again. A Xero organisation without sales invoices or budgets still loads everything else. When Xero refuses a read that a month's balances, sales, bills, open items or payments are built from, that month keeps the rows it already had and is read again at the next load.

Currency rates are not part of this access: Xero doesn't publish them. Supply them in a **Currency rates** file instead.
