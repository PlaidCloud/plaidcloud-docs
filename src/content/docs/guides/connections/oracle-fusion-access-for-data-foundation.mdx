[Data Foundation](/guides/projects/data-foundation/) brings data from every ERP system and instance you connect into one Common Finance Model, and Oracle Fusion Cloud ERP is one of the ERPs it reads directly. The Oracle Fusion connection uses OAuth 2.0 client credentials, a read-only integration user, and a small set of BI Publisher reports. This page is for the Oracle Fusion administrator who sets that up, and for the PlaidCloud user who asks them to.

PlaidCloud only reads data. Nobody sends a password or a client secret by email.

## Send the Access Request

On the project's **Systems** page, under **Data Foundation** in **Home**, choose your system in **System** under **Add a system** and click **Don't have access yet?**. The system waits for access, and one request covering the project's systems is shown. Click **Copy request** to paste it into your own message, or **Email request** to open it in your mail program with the subject "Access for PlaidCloud."

## What the Oracle Fusion Administrator Sets Up

<Steps>

1. **Create an integration user** and give it a custom job role that can only view, for every ledger you report on. Don't use a role that can enter, post or approve anything, such as General Accountant. The role needs:

   - General Ledger: ledgers, accounting calendars and period statuses, journal batches, journals and account balances (inquiry privileges, with data access to those ledgers)
   - Currency conversion rates (daily rates)
   - Key flexfield segment labels, value sets and their account hierarchy (trees)
   - Receivables and Payables: invoices, receipts, payments and their distributions, and customer accounts and suppliers
   - Cash Management bank accounts
   - Inventory items and on-hand quantities
   - For each optional report you deploy, the matching view-only access: Purchasing (View Purchase Order, `PO_VIEW_PURCHASE_ORDER_PRIV`, and receipt inquiry, with data access to the procurement business units), Fixed Assets (asset inquiry, with data access to the corporate and tax asset books), Cost Management (Review Item Costs, with data access to the cost organizations) and Budgets (General Ledger budget balance inquiry)
   - Run access to the BI Publisher reports in step 3 and the ERP Integration Service (ESS jobs)

2. **Register a confidential application** in the identity domain (IAM) with the client credentials grant and the scope of the Fusion Applications REST API. Copy its client ID and secret.

3. **Deploy the BI Publisher reports** under `/Custom/PlaidCloud/DataFoundation`. Each one runs as an ESS job, with the report name as the job definition, and returns a CSV with the columns listed in the request. The first six are required: the ledger is built from them. The others are optional: without one, the data it carries stays empty and nothing else is affected.

   | Report | What it returns |
   |---|---|
   | `PlaidCloudKeyFlexLabels` | One row per segment of each General Ledger chart of accounts: its position, its label and its value set |
   | `PlaidCloudSegmentValues` | Every value of those value sets, with the natural account type and the value hierarchy |
   | `PlaidCloudCalendar` | The accounting periods of every ledger, with the ledger's period-average and period-end rate types |
   | `PlaidCloudCodeCombinations` | The code combinations and their segments |
   | `PlaidCloudBalances` | The balances of every ledger in every period, adjusting periods included: the opening balances and the month-end balance the ledger is compared with |
   | `PlaidCloudJournalLines` | The journal lines, read one ledger, period and balancing segment value at a time, with who entered and approved each journal, when, and the journal it reverses |
   | `PlaidCloudCustomers` | The customer accounts and their party names (optional) |
   | `PlaidCloudItems` | The items of the master inventory organization (optional) |
   | `PlaidCloudSalesLines` | One row per Receivables invoice line (optional) |
   | `PlaidCloudSites` | The values of the `GL_SITE` segment (optional) |
   | `PlaidCloudSuppliers` | The suppliers (optional) |
   | `PlaidCloudArDocuments`, `PlaidCloudReceipts` | Receivables transactions and what was applied to them, for open items and payments (optional) |
   | `PlaidCloudApInvoices`, `PlaidCloudApPayments` | Payables invoices and what was applied to them, for open items and payments (optional) |
   | `PlaidCloudApInvoiceLines` | One row per Payables invoice line (optional) |
   | `PlaidCloudBankBalances` | Each bank account's own balance at every month end (optional) |
   | `PlaidCloudInventory` | The on-hand quantity and value of every item and subinventory at every month end (optional) |
   | `PlaidCloudBudget` | The approved budget by month (optional) |
   | `PlaidCloudPurchaseOrders`, `PlaidCloudPurchaseOrderEvents` | Purchase order lines, and their receipts and matched invoices (optional) |
   | `PlaidCloudAssets`, `PlaidCloudAssetMovements` | The asset register of the corporate book, and each asset's movements in the corporate and tax books (optional) |
   | `PlaidCloudStandardCosts` | Each item's standard cost per month (optional) |

   The exact columns of each report are in the access request text. Give the report names exactly as shown. If you deployed `PlaidCloudBalances` or `PlaidCloudApInvoices` for an earlier version, extend them as the request describes: `PlaidCloudBalances` must now return every period with its activity.

</Steps>

## What to Send Back

| The administrator sends | Entered in PlaidCloud as |
|---|---|
| The host of your Fusion Applications URL, without `https://` | **Pod Host** |
| The token URL of the identity domain | **Identity Domain Token URL** |
| The scope of the REST API application | **Scope** |
| The client ID from step 2 | **Client ID** |
| The client secret from step 2 | **Client Secret** |
| The balancing segment values PlaidCloud may read | Under **Options**, **Companies**, which Fusion can't list: enter the values, separated by commas, or leave it empty to load every one |

The request's closing list asks for these values together. Share the client secret through your password manager, not by email. The PlaidCloud user's team pastes it into PlaidCloud themselves.

## Check the Access

Back in PlaidCloud, once the system is added, click **Test connection** on its row on the **Systems** page. It reads one object for each required dataset and shows each dataset as **Readable**, **Missing permission** or **Error**. The reports themselves run at the first load, and the optional ones aren't part of the test: one that is missing, or that the user may not run, is named at the next load.

| Dataset | The test reads |
|---|---|
| Entities, Fiscal calendar, Chart of accounts, Departments, Trial balance | The ledgers |
| Currency rates | Daily conversion rates |
| General ledger | Journal batches |

When a dataset is missing, the test says which permission to add. Ask the administrator to add it to the job role and test again. A Fusion pod without an optional report still loads everything else: customers, products, sites and suppliers load empty, and any other dataset keeps what an earlier load landed until the report can be read again.

Oracle Fusion has no profit center list that Data Foundation reads. A journal line's profit center is its chart's management segment.
