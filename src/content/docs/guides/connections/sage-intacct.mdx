Connect PlaidCloud to Sage Intacct and pull financial and accounting data. This guide takes you from Web Services credentials to a working pull. For the field reference, see the [Sage Intacct REST Connector](/reference/connectors/rest/sage-intacct/).

## Prerequisites

You need, in Sage Intacct:

- **Web Services** enabled for your company — the **sender id** and **sender password** are provisioned by Sage support.
- A **Web Services user** for PlaidCloud, with permissions on **every** object your queries will read.
- Your **company id**, and the **entity** if you run a multi-entity tenant.

Record the company id, user id, user password, sender id, and sender password before you start.

<Aside type="caution">The sender credentials and the user credentials are separate. The sender id/password authenticate the application to Sage; the user id/password authenticate the login within your company. Both are required, and both are secrets.</Aside>

## Create the Connection

<Steps>

1. Open **Tools > Connections** and click `New Connection`.

2. Choose **Sage Intacct** from the menu (not the generic **REST** type).

3. Fill in the fields:

   | Field | Value |
   |---|---|
   | Name | A friendly name, e.g. `Intacct Prod`. |
   | Company ID | The Intacct company you're connecting to. |
   | User ID / User Password | The Web Services user login. |
   | Sender ID / Sender Password | The Web Services sender credentials from Sage. |
   | Entity | Optional — for a multi-entity tenant. |

4. Click `Create`.

</Steps>

## Smoke-Test the Connection

Confirm the credentials work before building on them.

<Steps>

1. Add a [REST Request step](/guides/workflows/rest-request-step/) to a workflow and set **Connection** to your Sage Intacct connection.

2. Point it at a small, bounded read against an object your user can see.

3. Click **Send Test Request**.

</Steps>

<Aside type="caution">
Use **Send Test Request**, not the Preview tab. A green result means the sender and user credentials both authenticated. If it errors, the message carries Sage's own detail — usually a permission gap on the Web Services user or a bad sender credential.
</Aside>

<Aside type="note">
Sage Intacct requests are **single-request — there is no pagination** to configure. Leave the Pagination controls alone.
</Aside>

## Pull Data

For routine pulls, Sage Intacct has dedicated import steps that map straight to Intacct objects:

- [Import Sage AP](/reference/workflow-steps/import/import-sage-ap/) — AP bill headers
- [Import Sage AP Lines](/reference/workflow-steps/import/import-sage-ap-lines/) — AP bill line detail
- [Import Sage Intacct Query](/reference/workflow-steps/import/import-intacct-query/) — a query against any Intacct object

Pick the step, choose your Sage Intacct connection, set the object or query, and run it. As with any import, define amount and date columns with their real types so they arrive typed rather than as text.

## Verify and Schedule

<Steps>

1. Run the step and check the target table — row counts and column types.

2. For an ongoing feed, [schedule the workflow](/get-started/tutorials/schedule-a-workflow/).

</Steps>

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Authentication failure | A wrong sender credential (provisioned by Sage) or a wrong user login. |
| Permission / object-not-found error | The Web Services user lacks permission on the object being read. |
| Empty result for a multi-entity tenant | The wrong **Entity**, or none set when one is required. |
