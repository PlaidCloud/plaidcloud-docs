[Data Foundation](/guides/projects/data-foundation/) brings data from every ERP system and instance you connect into one Common Finance Model, and SAP S/4HANA Cloud is one of the ERPs it reads directly. The connection reads the tenant's released OData services with OAuth 2.0 client credentials; no agent is involved. This page is for the S/4HANA Cloud administrator who sets that up, and for the PlaidCloud user who asks them to.

PlaidCloud only reads data. Nobody sends a password or a client secret by email.

## Send the Access Request

On the project's **Systems** page, under **Data Foundation** in **Home**, choose your system in **System** under **Add a system** and click **Don't have access yet?**. The system waits for access, and one request covering the project's systems is shown. Click **Copy request** to paste it into your own message, or **Email request** to open it in your mail program with the subject "Access for PlaidCloud."

## What the S/4HANA Cloud Administrator Sets Up

<Steps>

1. **Create a communication user** for PlaidCloud, in the app **Maintain Communication Users**. Its authentication method is OAuth 2.0 or user name and password, as your landscape requires.

2. **Create a communication system** for PlaidCloud, in the app **Communication Systems**, with that user for inbound communication and OAuth 2.0 client credentials.

3. **Create a communication arrangement** for each scenario below, in the app **Communication Arrangements**, all for the system from step 2. Together they expose the OData services PlaidCloud reads:

   | Scenario | Service |
   |---|---|
   | Company Code | `API_COMPANYCODE_SRV` |
   | G/L Account in Chart of Accounts | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
   | Cost Center | `API_COSTCENTER_SRV` |
   | Business Partner and Customer | `API_BUSINESS_PARTNER` |
   | Product | `API_PRODUCT_SRV` |
   | Fiscal Year Variant Periods | `API_FISCALYEARPERIODFORVARIANT_SRV` |
   | Exchange Rates | `API_EXCHANGERATE_SRV` |
   | Journal Entry Item | `API_JOURNALENTRYITEMBASIC_SRV` (the journal and the balance carried forward) |
   | Billing Document | `API_BILLING_DOCUMENT_SRV` (optional: it adds invoiced sales, documents and items) |

   For the optional datasets, also arrange the scenarios that expose these services:

   | Service | Adds |
   |---|---|
   | `API_JOURNALENTRY_SRV` | Who entered each journal, when, and the journal it reverses |
   | `API_BUSINESS_PARTNER` (`A_Supplier`) | Suppliers |
   | `API_PLANT_SRV` | Plants, read as sites, and the plants of inventory balances |
   | `API_PROFITCENTER_SRV` | Profit centers |
   | `API_SUPPLIERINVOICE_PROCESS_SRV` | Supplier invoice lines |
   | `API_OPLACCTGDOCITEMCUBE_SRV` | Open items and payments, and the due dates of supplier invoices |
   | `API_FINPLANNINGDATA_SRV` | Budgets |
   | `API_MATERIAL_STOCK_SRV` | Inventory balances |

   Give the communication user access to every company code you report on.

</Steps>

## What to Send Back

| The administrator sends | Entered in PlaidCloud as |
|---|---|
| The host of the tenant's API, for example `https://my300000-api.s4hana.cloud.sap` | **API Host URL** |
| The token URL: the tenant's own (`/sap/bc/sec/oauth2/token`), or your XSUAA authorization server's if your landscape uses one | **OAuth2 Token URL** |
| The client ID | **Client ID** |
| The client secret, through the secure connection form | **Client Secret**, which your team enters itself |
| Whether **Carry Forward Balances** has run for each fiscal year you load | Nothing to enter. The opening balances are read from it. |

<Aside type="caution">
Never email the client secret. **Client Secret** is a secret: it is stored on the connection and never shown again.
</Aside>

## Check the Access

Back in PlaidCloud, once the system is added, click **Test connection** on its row on the **Systems** page. It reads the required datasets and shows each as **Readable**, **Missing permission** or **Error**. The optional ones aren't part of the test: if S/4HANA Cloud refuses one, after the next load the readiness checks, on the **CFM-Accounting - Close and assurance** dashboard, name the service to add to the communication arrangement.

| Dataset | Service it needs |
|---|---|
| Entities | `API_COMPANYCODE_SRV` |
| Chart of accounts | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
| Departments | `API_COSTCENTER_SRV` |
| Customers | `API_BUSINESS_PARTNER` |
| Products | `API_PRODUCT_SRV` |
| Currency rates | `API_EXCHANGERATE_SRV` |
| Fiscal calendar | `API_FISCALYEARPERIODFORVARIANT_SRV` |
| General ledger | `API_JOURNALENTRYITEMBASIC_SRV` |
| Trial balance | `API_JOURNALENTRYITEMBASIC_SRV` |
| Sales lines | `API_BILLING_DOCUMENT_SRV` (optional) |

When a dataset shows **Missing permission**, ask the administrator to add the communication arrangement for its service and test again. Sales lines, budget, inventory balances, suppliers, sites, profit centers, supplier invoice lines, open items and payments are optional: a tenant that doesn't hold one still loads everything else. A month's open items or payments that can't be read, and a month's supplier invoice lines whose read fails, keep the rows they already had and are read again at the next load.

The services report no period status and no month-end balance of their own, so every period is open and the ledger is compared with its own trial balance.
