Every Data Foundation project comes with eighteen dashboards, a set of metrics and an analysis path for each subject. They all read the same report views, which every **Load** fills from the [Common Finance Model](/guides/projects/data-foundation/), so a dashboard, a metric and an answer from Weave never disagree. This holds for a project made from any Data Foundation template, such as [Cost to Serve](/guides/projects/cost-to-serve/) or [Operational Transfer Pricing](/guides/projects/operational-transfer-pricing/). To check that the numbers behind them can be trusted, see [Data Foundation: Can the Numbers Be Trusted?](/guides/projects/data-foundation-proof/).

## The Reports Page

**Reports**, under **Data Foundation** in the project home, lists the dashboards by persona: **Accounting**, **Executive**, **Finance**, **Marketing**, **Operations** and **Sales**. Click a dashboard's name to open it in a new browser tab. It opens in standard Superset, and no filter is carried from the project. As the page says, you see them if you have access to the project.

A dashboard with no data yet is listed by name, dimmed, under a line such as "3 reports have no data yet", with what would fill it: "Fills when a system with pipeline data finishes its load." or, for a dashboard that reads no particular subject, "Fills when your systems finish their first load."

The **Board pack** card at the bottom has **Open the board pack** once the pack's dashboard is built, and **Board pack settings**, available with edit access to the project, which opens the settings described in [Board Pack](/guides/projects/data-foundation/#board-pack).

## When the Dashboards Are Built

Installing Data Foundation creates the report views, and its message says how many report views and dashboards it installed and what to do next. The dashboards themselves are built at the end of every **Load** and **Apply changes**, by its **Make the dashboards** step, from what that run wrote. A project installed with the sample data shows the sample once its first load ends.

Each later run rebuilds the dashboards in place, so their links stay the same and data that arrives later fills in. Data Foundation rebuilds a dashboard on every Load, edits included, so copy a dashboard in Superset to keep changes of your own. The context line at the top of each dashboard says the same.

Missing data is never an error:

- A chart or tile with no data is left out and its row closes up. A tile without data can give its place to another one, such as **Owed by customers** in place of **Net debt** when no account is marked as borrowings.
- A tab whose charts all have no data is left out. A dashboard whose **Overview** has nothing to show is not built, and **Reports** lists it as having no data yet.
- The run finishes with a warning that names the dashboard and the tab left out, such as "CFM-Sales - Pipeline: the Deals closing tab is left out, as its charts have no data yet."
- If reporting is turned off for your workspace, no dashboards are made, and the warning says so.
- If a dashboard someone else made already has the address a Data Foundation dashboard needs, that dashboard is left as it is, and the warning names the address. Give the other dashboard another address in Superset.

## Who Sees Them

A dashboard takes the project's [default audience for new dashboards](/guides/dashboards/control-who-can-see-a-dashboard/#default-audience-for-new-dashboards) when it is first built. Later rebuilds keep whatever audience it has then.

The dashboards are built from every row of the project, never from the rows one person can see. Each person who opens a dashboard sees only the rows their [row access](/administration/access/managing-security-groups-and-assignments/#managing-row-access) allows. When someone whose row access narrows what they see starts a rebuild, the dashboards are left as the last Load built them, and the message says that the next Load rebuilds them.

On a project that [restricts rows](/administration/access/managing-security-groups-and-assignments/#managing-row-access), the report views are tables, so row access filters them in dashboards as it does any published table. Every **Load** and **Apply changes** checks each report again:

- A report built from Data Foundation tables that carry a restricted column it doesn't carry itself is not published for reporting, because its rows couldn't be limited to what each member may see. If it was published, it is unpublished, even on a locked project. The charts that read it are left out, and the warning names the dashboard, the report and the column.
- A report that is still a view, such as one made before the project restricted rows, is turned into a table. Its charts are left out of that run as not built yet, and the next **Load** or **Apply changes** builds them. On a locked project it is left out instead, and unpublished if it was published; the warning says to unlock the project and Load again.

Every dashboard is titled **CFM-*persona* - *report***. It opens on **Overview** and ends with **Detail**, which lists the rows behind the figures. The tabs in between answer the questions below.

### Growth and Efficiency

**CFM-Executive - Growth and efficiency** shows the figures a subscription or software business reports to its board and investors. Its Overview tiles are **Annual recurring revenue**, **Net revenue retention at this month's rates**, **Net new recurring revenue, last 12 months** and **Months of cash at the last 12 months' burn**. Below them are annual recurring revenue by revenue class, how it changed in the last 12 months, and a year-by-year table of actual and forecast years.

- Annual recurring revenue comes from contracts. It is the annual value of the active contracts and subscriptions at the end of the month chosen, read from the contracts table, for example a [contracts file](/guides/projects/data-foundation/#contract-registers). Contracts from a [contract register](/guides/projects/data-foundation/#contract-registers) count from their start date. Until contracts are loaded, each figure that needs them reads "Needs contracts: load your contracts or subscriptions," and the charts of annual recurring revenue give way to revenue in the ledger by class each month.
- Revenue classes split recurring revenue, and revenue and margin in the ledger, into your company's own kinds of revenue. See [Revenue Classes and Team Functions](/guides/projects/data-foundation/#revenue-classes-and-team-functions). Every contract line counts in annual recurring revenue whatever its class. Revenue in the ledger counts as recurring when its account's class is of a recurring kind.
- The 12-month bridge goes from 12 months ago to the month chosen by customer within each entity. "New" customers had no recurring revenue 12 months ago and "Lost" ones have none now; "Grew" and "Shrank" are the rest, by the customer's total over every class. "Exchange rates" restates 12 months ago at this month's closing rates, and "Month chosen" is where the bridge ends. Until 13 months of contracts are loaded, every customer is new.
- Retention comes from the same bridge, at this month's rates. Net revenue retention is what the customers of 12 months ago have now over what they had then. **Gross revenue retention** leaves out their growth, so it is never above 100%, and a customer moving value between classes has not fallen. On **CFM-Sales - Orders and contracts**, **Recurring revenue kept from a year ago**, the **Net revenue retention** metric, keeps each year at its own rates instead.
- The **Efficiency** tab measures against sales and marketing spend: the operating cost of teams whose function is **Sales and marketing**, plus marketing and commissions accounts anywhere. **Cost to win a new customer** is the last 12 months' spend over the new customers in them. **Lifetime value for each 1 spent winning a customer** caps a customer's lifetime at 5 years. **Net new recurring revenue for each 1 spent on sales and marketing the year before** compares the last 12 months' growth with the spend of the 12 months before them, and **Cash burned for each 1 of net new recurring revenue** compares net burn with that growth.
- Net burn is operating plus investing cash flow, leaving out money raised or repaid and exchange rates. **Months of cash at the last 12 months' burn** is the cash at the month end over the average monthly net burn of the last 12 months, a past rate, not a forecast. With no account marked as cash, it reads "Needs account roles: which accounts hold cash"; when the last 12 months burned no cash, it reads "Not burning cash" with the cash at the month end.
- The **Margin by class** tab gives each class its revenue less its cost of revenue. A cost-of-revenue account shared by every class is spread by each class's share of revenue over the 12 months to each month. **Gross margin %, year to date** is the profit and loss's own, and the tab's other revenue figures are before intercompany eliminations.
- The year-by-year table shows complete years, the current year, to date or with the latest forecast's remaining months, and the latest forecast's later years. Growth compares full years only.
- Revenue for each person employed is shown when the allocation drivers carry a headcount.

A figure with a gap keeps its value, with up to two lines under it naming the gap and its size, such as months of the last 12 not loaded, revenue with no revenue class yet, operating cost with no team, or entities with no contracts or no cash account. Customers whose currency has no closing rate for the month chosen or 12 months before, and entities whose contracts are not loaded for the month, are left out of the bridge and retention. The dashboard has no profit center filter, as recurring revenue, retention and the bridge are by entity and customer.

## Reading a Dashboard

**The context line.** Each tab opens with a line that says what the figures cover. See [On the Dashboards](/guides/projects/data-foundation-proof/#on-the-dashboards). On **Overview** it adds **Right-click any chart to break it down or see its rows**. Without a budget it says **No budget loaded; comparing with last year**, and the chart titles compare with last year instead of budget.

**Filters.** **Period** is always there. **Region**, **Country**, **Division** and **Entity** are added when the project has two or more of them, and each lists only the values within the ones chosen before it. **Profit centre** is added when the data carries two or more. A dashboard's own filters follow. Filters that don't fit the bar are under **More filters**. **Period** opens on the last month closed for every entity. **CFM-Accounting - Close and assurance**, **CFM-Accounting - Intercompany** and **CFM-Sales - Pipeline** open on the current month: the first month not yet closed. With no month closed, **Period** opens on the latest month.

**CFM-Executive - Growth and efficiency** has no profit center filter. See [Growth and Efficiency](#growth-and-efficiency).

**Tiles.** A tile shows the figure, its change and its trend over the twelve months to the month chosen, with two comparisons: against budget and against last year, or, where the figure has no budget, against last month and against last year. A figure with no month of its own shows its value without the trend. A tile that another tab explains ends with **Why ›**, which opens that tab. Every variance is shown so that a positive figure is good, whichever way the measure runs, and the tile's arrow and color follow. A margin's variance is in points.

**See also.** Every tab but **Overview** ends with a **See also** line that links the dashboards related to it.

**Units.** Chart titles name the unit. The **Display unit** project setting is **Automatic**, **Whole units**, **Thousands** or **Millions**. **Automatic** uses whole units for a single company with less than 10 million of revenue in its largest fiscal year; otherwise thousands, or millions from 1 billion of revenue. Amounts per unit, such as an average price, are never scaled. A changed setting shows when the dashboards are next built.

**Your system's words.** A project with one QuickBooks Online system reads in its words: **Class** in place of **Profit centre**, **Location** in place of site and **Category** in place of product family.

## Copies of a Project

A project made with [Clone](/guides/projects/data-foundation/#clone-a-project) has no dashboards of its own. It shares the original's set, and those dashboards keep reading the original. Its **Reports** page says **This project is a copy**, with **Open the reporting project** and two choices:

- **Make this the reporting project** points the set's dashboards at this project, so their charts, links, favorites and schedules carry on. Each dashboard takes this project's default audience, unless an owner chose its audience or someone co-owns it. You need edit access to this project and to the one the dashboards read before. A chart whose data this project lacks shows nothing here, and the message names the dashboard and tabs. On a project that has never loaded, the message is "This project has no reporting database yet. Run Load first."
- **Give this copy its own dashboards** asks you to confirm, "This copy gets its own set of dashboards, as a separate business would. Use this only when the copy has become one." Click **Give dashboards** to go ahead.

Both need edit access to the project, and both rebuild the dashboards straight away.

## Metrics

Every project gets the metrics its dashboards show. Most are a [metric definition](/integrations/ai-coding-agents/metric-definitions/) that Weave answers with, defined once for both, so Weave and the dashboards agree. On **CFM-Executive - Growth and efficiency**, Weave answers the headline figures, such as annual recurring revenue, net and gross revenue retention, net new recurring revenue, net burn and months of cash; its other figures, such as cost to win a new customer, lifetime value and the splits by class and function, are on the dashboard only. A metric is named by its title, such as **Revenue** or **Working capital**, or, where two share a title, the title and its subject, as *title* - *subject*. Where two of the same subject share a title, it is *title* (*metric name*).

Metrics are made when Data Foundation is installed and at the end of every **Load** by its **Make the metrics** step. A metric is made once the report view it reads is built. A metric the project already has by that name is left as it is, so your edits to it stay. A metric that can't be made is named in the run's warnings, with why; the dashboards still show it.

## Analysis Paths

Installing Data Foundation makes one [analysis path](/integrations/ai-coding-agents/analysis-paths/) per subject, named after the project: *project name* - *subject*. The subjects are **Finance**, **Journals**, **Trial balance**, **Drivers**, **Sales**, **Pipeline**, **Orders**, **Contracts**, **Purchasing**, **Receivables and payables**, **Intercompany**, **Inventory**, **Assets**, **Cash** and **Close and assurance**. When another analysis path already uses the project's name, the paths take the name with a number, such as `Northwind (2) - Finance`.

Each path reads the subject's report view and describes every report view of the subject, so Weave knows what each holds. Your [business names](/guides/projects/data-foundation/#business-names) are written into the description of the project's own analysis path. A path of the same name that belongs to another project is left as it is, with a warning.

## Report Views

The report views are tables and views named `cfm_rv_...` at the top of the project, such as `cfm_rv_finance_month` and `cfm_rv_sales_window`. The project's **Reports** workflow fills them in every **Load**, after **Consolidate**. Every dashboard, metric and analysis path reads them, and you can query them like any other table in the project. A view whose data isn't there yet is created empty and fills once its data arrives.
