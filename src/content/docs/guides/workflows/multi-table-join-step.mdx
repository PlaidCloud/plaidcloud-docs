## Description

The **Multi-Table Join** step joins many tables in a single operation. Instead of chaining a series of two-table joins — where you lose the big picture and repeat the same output mapping — you lay every table out on a visual **join-graph designer**, draw the joins between their columns, and produce one result table.

It's built for the common shape of analytics joins: one fact table joined to several dimension or lookup tables. You can join up to 32 tables at once.

<Aside type="note">This step replaces the pattern of chaining several Inner Join / Outer Join steps. One step, one diagram, one output mapping — and a single shared view of how the tables fit together.</Aside>

## Add a Multi-Table Join

Add it like any other step and choose **Multi-Table Join** (under the **Tables** group of the step menu, or drag it from the palette on the [Advanced workflow canvas](/guides/workflows/advanced-workflows/)). The step's config opens with the join-graph designer on its **Tables** tab.

## Design the Join

### Add Tables

Choose **Add Table** to place a source table on the canvas. Each table shows as a card listing its columns. Repeat for every table you want to join.

### Draw Joins

Drag from a column on one table to the matching column on another to create a **join** (an edge) between them. Select an edge to open the condition editor on the right, where you set:

- **Join type** — `INNER` (keep rows that match in both), `LEFT` (keep all rows from the left table), `FULL` (keep all rows from both), or `CROSS` (every combination — no conditions).
- **Join conditions** — one or more comparisons between the two tables' columns. Combine multiple conditions with **AND** / **OR**, and use the full set of operators (`=`, `<>`, `<`, `<=`, `>`, `>=`, `BETWEEN`, `IS NULL`, `IS NOT NULL`, `IN`, `NOT IN`, `LIKE`, `NOT LIKE`).

The designer keeps the join graph as a tree — each table connects into the result through exactly one join, so there are no cycles or ambiguous paths. To remove a join, select the edge and choose **Delete edge**.

### Organize the Canvas

- **Tidy Layout** auto-arranges the tables and joins for readability.
- **Fit to View** zooms and pans so the whole graph is visible; you can also pan and zoom manually.
- **Filter…** narrows the columns shown on the cards when a table has many columns.
- **Undo** / **Redo** step backward and forward through your edits, and **History** shows the timeline of changes.
- **Export** downloads the join diagram as an SVG image — handy for documentation or review.

## Choose Output Columns

Map the columns you want in the result table — pick from any of the joined tables, rename them, set their data type, and apply an aggregation where needed. You can also apply a filter to the joined result before it's written.

## Validation

PlaidCloud validates the join as you build it and again when the step runs. If something is wrong — an unsupported configuration, a cycle, or a column that no longer exists — the step reports the problem and the designer highlights the offending table or join with a message. Use **Jump to issue** to navigate straight to it.

<Aside type="tip">A `CROSS` join produces every combination of rows and has no conditions. On large tables this can be very expensive — use it deliberately.</Aside>

## Run the Step

The Multi-Table Join runs like any other step. It executes all the joins in one operation and writes the mapped columns to the target table.
