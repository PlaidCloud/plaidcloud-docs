**Home** is the first tab in PlaidCloud and, by default, the tab you land on when you sign in. It shows a board of tiles — up to twenty — covering the things you most likely came here to open: the projects your workspace actually works in, the dashboards and panel apps you can reach, and anything that broke overnight.

Every tile is clickable. Clicking one takes you straight to the thing it describes, switching tabs for you where it needs to.

## What's on the Board

Tiles appear in a fixed priority order, so the urgent things are always at the top left.

### Workflow Failures

A red-bordered tile appears for each workflow whose **most recent run failed**. This is the one to look at first — it's how you find out that last night's scheduled run didn't finish.

Each failure tile shows:

- The workflow name, with the project it belongs to underneath
- **Failed step** — the step that actually broke the run
- The error message the step reported
- **Failed** *(when)* — how long ago the run ended

Clicking the tile switches to the **Analyze** tab and opens the workflow at the failed step, so you can inspect and fix it without hunting for it.

<Aside type="note">
A failure tile disappears on its own once the workflow runs cleanly again — you don't need to clear it. If the workflow is re-run while you're looking at the board, the tile vanishes there and then; otherwise it's gone next time the board loads. Only the *latest* run counts, so a workflow that failed at 2am and succeeded on a re-run at 7am is not shown.
</Aside>

If you want a tile gone before the underlying problem is fixed — say you already know about it and don't want it taking up space — click the **✕** in its top-right corner. That dismissal is remembered, so the same failed run won't come back on the next refresh.

### Projects

Project tiles show the projects your workspace has used most over the last 60 days, most-used first. "Used" here means workflow runs, so the projects with the most activity rise to the top.

Each project tile shows:

- **Runs** — how many workflow runs the project has had in the window
- **Last run** — when the most recent one started

A project with no runs in the window shows **Last edited** instead, so newly created or quiet projects still tell you something useful.

Clicking a project tile switches to the **Analyze** tab and opens that project.

### Dashboards

Dashboard tiles cover the dashboards you have access to, with the dashboard's memo underneath the name and **Updated** *(when)* along the bottom. Clicking one opens the dashboard in a new browser tab.

### Panel Apps

Panel app tiles show the Panel apps available to you. Server-backed apps are labelled **Panel App (Server)**; browser-based ones are labelled **Panel App**. Clicking one opens the app in a new browser tab.

A server app that is still building shows **Not ready yet** and is greyed out — it stays on the board so you know it exists, but there's nothing to open until its build finishes.

## Refreshing

The board refreshes itself when you come back to the Home tab after being away for a couple of minutes. To force it, click **Refresh** in the top-right of the tab.

Workflow failures are the exception — those update live. You don't need to refresh to see a failure clear.

## Starting Somewhere Else

If you'd rather land on your usual working tab instead of Home:

1. Click your avatar in the top-right corner
2. Open **Options**
3. Untick **Start on Home**

PlaidCloud will then open on the first app tab you're entitled to. The Home tab stays in the tab bar either way — this only changes where you land at sign-in.

<Aside>
Opening PlaidCloud from a direct link to a specific table, step, or workflow always takes you to that item, regardless of this setting.
</Aside>

## When the Board Is Empty

If you see **Nothing to show yet**, there's nothing the board can offer you — no projects with recent activity, no dashboards, and no panel apps you can open. This is normal in a brand-new workspace. Create a project or ask an administrator about your access, and the tiles will fill in.

## What You See Depends on Your Access

The board only ever shows things you already have permission to open. Project tiles are limited to projects you can read, and the dashboard and panel-app tiles only appear if you have access to those areas. Two people in the same workspace can see different boards.
