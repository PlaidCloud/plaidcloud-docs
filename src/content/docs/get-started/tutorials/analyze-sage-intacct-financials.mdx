## Prerequisites

- A PlaidCloud workspace and a project to work in ([start a trial](https://app.plaidcloud.com) if you need one).
- **A working Sage Intacct connection.** Follow [Connect to Sage Intacct](/guides/connections/sage-intacct/) first — you need Web Services enabled, a Web Services user with permission on the objects you'll read, your company id, and the sender/user credentials. Confirm the connection works before you start here.
- Know your **operating entities** (the entity ids you report on) and roughly which **account-number range** holds your P&L accounts (revenue and expense). The examples below use `201` and `301` for entities and `4010`–`9999` for the P&L range — substitute your own.

<Aside type="note">
Everything after the pull is point-and-click — no SQL, no code. The one Intacct-specific piece is the **Import Sage** step, which reads Intacct's *account balances by dimension* for a date and account range. It returns one row per account per dimension combination, with an opening, period, and ending balance on each.
</Aside>

## Step 1: Create a Workflow

The workflow is the pipeline that pulls and shapes the data.

<Steps>

1. Open your project and switch to the **Workflows** tab.
2. Click **New Workflow**, name it something like `Intacct Financials`, and open it.

</Steps>

## Step 2: Pull the Trial Balance

The [Import Sage step](/reference/workflow-steps/import/import-sage/) pulls account balances for a date range and an account range, carrying the dimensions you choose onto every row — that's your trial balance.

<Steps>

1. Add an **Import Sage** step.

2. On its configuration, set:

   | Field | Value |
   |---|---|
   | **Connection** | your Sage Intacct connection |
   | **Company** | the Intacct company to read from |
   | **Start date** / **End date** | the period you're closing — e.g. the first and last day of the month |
   | **Start account** / **End account** | your P&L range, e.g. `4010` to `9999` |
   | **Entities** | your operating entities, e.g. `201`, `301` |
   | **Dimensions** | switch on the ones you report by — commonly **Location**, **Department**, **Employee**, and **Class** |

3. Set the **Target** to a new table named `intacct_trial_balance`.

4. Run the step. You now have one row per account per dimension combination, with `startbalance`, `periodbalance`, and `endbalance` columns plus an id/name pair for each dimension you enabled (e.g. `departmentid` / `departmentname`, `locationname`).

</Steps>

<Aside type="caution">
Intacct returns every column as **text**, and Sage pulls are **single-request** (no pagination) — account-balance results are small, so that's fine here, but don't use this step for high-volume line-item detail. You'll set the real column types in the next step, where they matter.
</Aside>

<Aside type="note">
Both **Start date** and **End date** must be set — a lone start or end date is ignored. If you enabled a dimension whose id and name you don't need, you can drop the extra column in the next step. (The **Warehouse** dimension checkbox has no effect; use **Custom dimensions** if you need warehouse on the output.)
</Aside>

## Step 3: Shape the Balances Into a P&L

Now the analysis, done with a single point-and-click transform — no SQL. Your P&L range rolls up into a few statement lines, per department, with the sign flipped so revenue reads positive. A [Table Extract step](/reference/workflow-steps/tables/table-extract/) does all of it on its **Table Data Selection** and **Data Filters** tabs.

<Steps>

1. Add a **Table Extract** step. Set its **Source** to `intacct_trial_balance` and its **Target** to a new table, `intacct_pnl`.

2. On the **Table Data Selection** tab, click **Summarize** to turn on aggregation, then set up three target columns:

   - **`departmentname`** — mapped straight from the source. Type **Text**, summarize **Group By**.
   - **`pnl_line`** — an **expression** (below) that turns the account number into a report line. Type **Text**, summarize **Group By**.
   - **`amount`** — an **expression** `func.to_float64(intacct_trial_balance.endbalance) * -1`, which converts the text balance to a number and flips the sign. Type **Currency**, summarize **Sum**.

   Setting the `amount` target column's **Type** to **Currency** is what lets the text balance add up. For `pnl_line`, double-click its **expression** cell and enter (point-and-click the columns and the `case` function from the **Conditions** group):

   ```python
   case(
       (func.to_float64(intacct_trial_balance.glaccountno) < 5000, '1 - Revenue'),
       (func.to_float64(intacct_trial_balance.glaccountno) < 6000, '2 - Cost of Goods Sold'),
       else_='3 - Operating Expenses',
   )
   ```

3. Run the step.

</Steps>

The `* -1` is the one accounting move: Intacct carries revenue as a credit (negative) and expenses as a debit (positive), so negating the ending balance makes **revenue read positive and costs negative** — each department's lines then *add up to net income*. Adjust the account-number cutoffs in the `case()` to match your chart of accounts. Expressions use PlaidCloud's point-and-click editor — see [Advanced Data Mapper Usage](/reference/workflow-steps/common/advanced-data-mapper-usage/) and the [expression reference](/reference/expressions/).

<Aside type="tip">
Want a company-wide P&L instead of by-department? Drop `departmentname` from the target columns and keep only `pnl_line` (Group By) and `amount` (Sum).
</Aside>

## Step 4: Read It Like a Finance Person

Open the `intacct_pnl` table. For each department you have three numbers:

| departmentname | pnl_line | amount |
|---|---|---|
| Operations | 1 - Revenue | 486,200.00 |
| Operations | 2 - Cost of Goods Sold | -190,540.00 |
| Operations | 3 - Operating Expenses | -212,880.00 |

Read straight off it:

- **Gross profit** = Revenue + Cost of Goods Sold (COGS is already negative) → `486,200 − 190,540 = 295,660`.
- **Net income** = the three lines summed → `82,780`.
- **Gross margin %** = gross profit ÷ revenue → ~61%.

The first thing to do is **tie it out**: run Intacct's own P&L (Financial Reports) for the same period and entities, and confirm revenue and net income match. If they don't, it's almost always a scope difference — an entity you didn't include, an account range that clips part of the P&L, or a period misalignment. Trust the pipeline only once it ties.

<Aside type="tip">
Want the classic period-across-the-top layout? Add a [Table Pivot step](/reference/workflow-steps/tables/table-pivot/) reading `intacct_pnl`: pivot the period into columns, keep `pnl_line` as the row, and sum `amount`. To get a period column in the first place, add `end_date` as a **Group By** column in Step 3. That gives you month-over-month at a glance, no SQL.
</Aside>

## Step 5: Put It on a Dashboard

Numbers in a table are fine; a chart is what you send to the CFO. [Publish](/get-started/tutorials/load-and-transform-data/#step-7-publish-the-result) `intacct_pnl`, then follow [Build a Dashboard](/get-started/tutorials/build-a-dashboard/) to add:

- a **bar chart** of net income (or revenue) by `departmentname`, and
- a **bar** of each `pnl_line` so the revenue / COGS / opex mix is visible at a glance.

That's a live Sage Intacct financial dashboard — no export, refreshed whenever the workflow runs.

## Step 6: Schedule the Refresh

<Steps>

1. Run the whole workflow once, top to bottom, to confirm every step is green.
2. [Schedule the workflow](/get-started/tutorials/schedule-a-workflow/) — monthly on a close cadence, or weekly if you want the numbers fresh through the month.

</Steps>

Because the pull is a full-table replace, each run re-reads the balances for the date and account range you set — keep those to the window you need (the current period, your P&L accounts) rather than all of history.

<Aside type="note">
**Statistical accounts** (headcount, square footage, units) live in Intacct's *statistical* books, which the Import Sage step doesn't reach from the UI. Pulling them — to build per-head or per-unit metrics alongside this P&L — uses the same account-balances API in statistical mode, driven by a small reusable [user-defined function](/get-started/tutorials/reuse-variables-macros-udfs/). It's an advanced follow-up to this tutorial, not part of the day-one path.
</Aside>
