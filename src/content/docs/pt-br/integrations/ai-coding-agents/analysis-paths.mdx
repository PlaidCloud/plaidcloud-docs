Um **caminho de análise** é um nome amigável para uma tabela que você analisa com frequência — como *"Resultados operacionais"* ou *"a DRE"*. Registre-o uma vez e, a partir daí, você (e seu assistente de IA conectado) poderá fazer perguntas sobre ele por esse nome, sem repetir a cada vez qual projeto e qual tabela você quer dizer.

Escolha um como **padrão** do espaço de trabalho, e perguntas simples como *"por que isso subiu no último trimestre?"* simplesmente funcionam — o assistente já sabe a que "isso" se refere.

<Aside>
Os caminhos de análise são uma facilidade compartilhada do espaço de trabalho: um administrador os configura e, depois, **qualquer pessoa** no espaço de trabalho pode usá-los em suas perguntas — pelo [Microsoft 365 Copilot](/pt-br/integrations/microsoft-365-copilot/) ou por um agente de programação conectado via [MCP](../getting-started/). Toda pergunta continua sendo executada sob as permissões de cada pessoa.
</Aside>

## Por que usá-los

Sem um caminho de análise, toda pergunta precisa especificar exatamente onde os dados estão — o projeto *e* a tabela —, o que fica cansativo rapidamente e é fácil de errar. Com um, você fala sobre seus dados do jeito que realmente pensa neles:

- **Pergunte pelo nome.** *"Resuma os Resultados operacionais."* em vez de *"resuma a tabela `ops_summary_v3` no projeto `Enterprise Profitability`."*
- **Defina um padrão.** Marque a tabela que você mais usa como padrão e dispense o nome por completo — *"o que mudou desde o mês passado?"* cai automaticamente nos dados certos.
- **Mantenha todos consistentes.** Quando a equipe inteira se refere à *"DRE"*, todos chegam à mesma tabela — sem adivinhação, sem cópias desatualizadas.

## Registrar um caminho de análise

Se você é administrador do espaço de trabalho, não precisa de um formulário nem de uma tela de configurações — basta pedir ao seu assistente de IA conectado, em linguagem natural, que registre o caminho para você:

> *"Registre um caminho de análise chamado **Resultados operacionais** que aponte para a tabela `ops_summary` no projeto **Enterprise Profitability**."*

O assistente confirma o caminho e ele fica pronto para uso imediatamente. Você pode registrar quantos quiser — um por tabela que você analisa regularmente.

<Aside type="tip">
Escolha nomes do jeito que sua equipe fala: *"Resultados operacionais", "o Forecast", "Quadro de pessoal".* Quanto mais amigável o nome, mais naturais ficam as suas perguntas.
</Aside>

## Definir um caminho padrão

Como administrador, marque um caminho como **padrão** para que as perguntas que não indicam uma tabela caiam nele automaticamente:

> *"Torne **Resultados operacionais** o caminho de análise padrão."*

A partir daí, *"quais foram as maiores variações neste trimestre?"* ou *"por que o total caiu?"* são executadas nessa tabela sem nada mais a especificar. Há um único padrão para todo o espaço de trabalho, de modo que as perguntas sem alvo de todos se resolvem para a mesma tabela. Definir um novo padrão simplesmente passa a coroa adiante — só existe um por vez, e o assistente informa qual é.

## Como tornar um caminho útil para assistentes de IA

Um nome e uma tabela dizem a um assistente *onde* estão os dados. Não dizem o que os dados *significam*: quais filtros sempre se aplicam, como funciona o seu ano fiscal, a que se referem as palavras da sua equipe. Sem isso, o assistente adivinha, e uma resposta errada dada com confiança é pior do que uma resposta lenta. Esta seção trata dos dois lugares onde você coloca esse conhecimento e do motivo pelo qual ambos importam.

Neste guia, **assistentes de IA** significa qualquer LLM conectado por meio do MCP do PlaidCloud (Claude, Microsoft Copilot, ChatGPT e outros), mais a IA integrada do PlaidCloud.

<Aside type="tip" title="A Orientação do prompt decide a qualidade das respostas">
Um caminho com boa Orientação do prompt e memorandos de coluna em sua tabela recebe respostas corretas e consistentes de todos os assistentes. Um caminho sem nenhum dos dois recebe o que o assistente inferir a partir dos nomes das colunas. Dez minutos dedicados a essas duas coisas são a configuração de maior valor que você pode fazer para um caminho.
</Aside>

### Adicionar Orientação do prompt

Cada caminho de análise tem uma **Orientação do prompt**: texto livre, escrito por você, que diz aos assistentes como usar o caminho. Escreva uma diretriz por linha.

Para adicioná-la, abra o menu **Ferramentas** e escolha **Caminhos de análise**, depois selecione um caminho e escolha **Editar** (ou escolha **Novo** para criar um). O campo **Orientação do prompt** vem depois de **Tabela**, logo antes de **Definir como padrão do espaço de trabalho**. Um assistente conectado com permissão para gerenciar caminhos de análise também pode defini-la. Quem chama via MCP e API vê esse campo como `description`, por exemplo: *"Defina a description do caminho Resultados operacionais como …"*

Os assistentes usam a Orientação do prompt de duas formas:

1. **Para escolher o caminho.** Quando uma pergunta não nomeia um caminho, o assistente a compara com o nome e a Orientação do prompt de cada caminho e escolhe a melhor correspondência.
2. **Como orientação permanente.** Depois de escolher um caminho, o assistente aplica a Orientação do prompt a toda consulta feita nesse caminho: os filtros a incluir, a terminologia a traduzir. Para um assistente conectado via MCP, os próprios números de negócio vêm das [definições de métricas](../metric-definitions/) do projeto, não da orientação.

A Orientação do prompt é armazenada com o caminho e fica visível para todos no espaço de trabalho que podem ver os caminhos de análise. Ela chega aos assistentes que trabalham via MCP e à IA integrada do PlaidCloud. Não é repassada à assistência de IA dentro da etapa de LLM de um fluxo de trabalho.

### O que escrever

Inclua o que um analista novo precisaria ouvir no primeiro dia com esta tabela. Dê a cada diretriz sua própria linha.

| Escreva isto | Exemplo |
|---|---|
| **As perguntas que o caminho responde e as que não responde.** | *"Resultados operacionais mensais por unidade de negócio. Use para perguntas sobre receita, custo e EBITDA. Não use para quadro de pessoal nem previsões; use o caminho Forecast."* |
| **Qual métrica uma palavra de negócio designa**, para assistentes conectados via MCP. | *"'Receita' é a métrica Receita líquida. `billed_amount` é faturamento, não receita."* |
| **Filtros que sempre se aplicam.** | *"Sempre exclua `scenario = 'Budget'`, a menos que perguntem sobre orçamento. As linhas intercompany têm `entity_type = 'IC'`; deixe-as fora dos totais."* |
| **Convenções de sinal, calendário e granularidade.** | *"Os custos são armazenados como negativos. O ano fiscal começa em julho, portanto o FY26 vai de jul de 2025 a jun de 2026. Uma linha por unidade de negócio por mês."* |
| **Termos de negócio mapeados para os dados.** | *"'O Meio-Oeste' significa `region IN ('IL','IN','OH','MI')`. 'Produtos principais' significa `product_tier = 'A'`."* |

Seja breve e específico. Uma diretriz por linha é melhor que um parágrafo, e o limite é de **1.000 caracteres**. Os espaços no início e no fim são removidos.

<Aside>
Para um assistente conectado via MCP, a forma como um número de negócio é calculado — qual coluna, somada de que maneira, sobre quais linhas — pertence a uma [definição de métrica](../metric-definitions/), não à Orientação do prompt. A orientação diz quais filtros e termos se aplicam ao caminho; uma métrica diz o que é o número.
</Aside>

### O que não escrever

- **O que os assistentes já veem.** Tipos de coluna, chaves e contagens de linhas são retornados junto com a tabela. Repeti-los gasta seus 1.000 caracteres.
- **O que uma coluna significa.** Coloque isso em um [memorando de coluna](#adicionar-memorandos-de-coluna), para que fique com a coluna, onde quer que a tabela seja usada. A Orientação do prompt serve para dizer como usar o caminho como um todo.
- **Qualquer coisa confidencial.** A Orientação do prompt é visível em todo o espaço de trabalho, não apenas para quem tem acesso ao projeto da tabela. Não inclua senhas ou chaves, dados pessoais, nem números e comentários que você não mostraria a todos os membros do espaço de trabalho.

### Orientação do prompt boa e fraca

Os dois exemplos abaixo são para o mesmo caminho, e a mesma pergunta é feita: *"Qual foi o EBITDA do Meio-Oeste no ano passado?"*

| | Orientação fraca | Orientação boa |
|---|---|---|
| **Texto** | *"Dados operacionais."* | *"Resultados operacionais mensais por unidade de negócio.*<br />*EBITDA = `ebitda_adj`; ignore `ebitda`.*<br />*Exclua `scenario = 'Budget'` e as linhas intercompany (`entity_type = 'IC'`).*<br />*O ano fiscal começa em julho.*<br />*Meio-Oeste = IL, IN, OH, MI."* |
| **O que o assistente faz** | Escolhe a coluna simples `ebitda`, inclui linhas de orçamento e intercompany e interpreta "ano passado" como o ano civil. | Usa `ebitda_adj`, deixa de fora as linhas de orçamento e intercompany, usa o último ano fiscal concluído e filtra pelos quatro estados do Meio-Oeste. |
| **A resposta** | Um número plausível, errado e diferente do que a equipe financeira apresenta. | O número que a equipe financeira reporta. |

A orientação fraca não é falsa. Ela apenas deixa cada decisão para o palpite do assistente.

### Adicionar memorandos de coluna

A Orientação do prompt cobre o caminho como um todo. Um **memorando de coluna** explica uma coluna, e é assim que os assistentes aprendem o que uma coluna realmente contém. **Quando o propósito de uma coluna não está claro pelo nome, um memorando faz a diferença entre a coluna certa e uma errada que parece plausível.**

Os memorandos da tabela do caminho são retornados aos assistentes de IA junto com a lista de colunas, em `table_describe` com `include=['columns']`, como `memo` em cada coluna que tiver um. As colunas sem memorando são retornadas como antes. Os mesmos memorandos chegam à assistência de IA na etapa de LLM de um fluxo de trabalho, para as tabelas que ela usa.

#### Quando um memorando é necessário

| Adicione um memorando para | Exemplo de memorando |
|---|---|
| **Códigos e abreviações** | `seg_cd`: *"Código do segmento de cliente: E = Enterprise, M = Médias empresas, S = Pequenas empresas."* |
| **Medidas parecidas** | `ebitda_adj`: *"EBITDA depois de removidos os itens pontuais. Use este para relatórios; `ebitda` não é ajustado."* |
| **Flags** | `is_ic`: *"1 se a linha for uma transação intercompany. Exclua dos totais consolidados."* |
| **Unidades ou moeda** | `amt_local`: *"Valor na moeda local da entidade, em milhares."* |
| **Valores derivados ou alocados** | `alloc_cost`: *"Custo compartilhado alocado a esta unidade por quadro de pessoal. Não incorrido diretamente."* |

Pule as colunas cujos nomes já dizem tudo, como `invoice_date` ou `customer_name`. Um memorando que repete o nome não acrescenta nada.

#### Como adicionar um memorando

1. Abra a tabela do caminho no [Explorador de tabelas](/pt-br/guides/data/table-explorer/).
2. Na barra de ferramentas, ative **Propriedades da coluna**.
3. Selecione a coluna na lista de colunas.
4. Digite o texto em **Memorando**.

Um memorando definido na tabela vale onde quer que a tabela seja usada, incluindo todo caminho de análise que aponte para ela.

#### Orientação do prompt ou memorando

Coloque cada fato em um só lugar.

| | Orientação do prompt | Memorando de coluna |
|---|---|---|
| **Abrange** | Como usar o caminho como um todo | O que uma coluna significa |
| **Conteúdo típico** | Perguntas que ele responde, filtros permanentes, calendário fiscal, termos de negócio | Códigos, unidades, flags, qual das medidas parecidas usar |
| **Exemplo** | *"Exclua as linhas intercompany dos totais."* | `is_ic`: *"1 se a linha for intercompany."* |

Aqui, o memorando diz o que `is_ic` significa, e a Orientação do prompt diz o que fazer com ele.

## Como usá-los

Depois que seus caminhos estiverem registrados, basta perguntar:

<Steps>

1. **Pelo nome** — *"Mostre-me as primeiras linhas dos Resultados operacionais."*

2. **Pelo padrão** — *"O que mudou em relação ao último trimestre?"* (sem nomear tabela — usa o caminho padrão do espaço de trabalho).

3. **Alterne à vontade** — *"Agora faça o mesmo para o Forecast."* O assistente acompanha, de caminho em caminho.

</Steps>

Isso combina naturalmente com perguntas sobre alocação — veja [Rastreamento de alocações](../tracing-allocations/) — para que você vá de *"por que os Resultados operacionais se moveram?"* direto para as contas e os direcionadores por trás disso.

## Como usá-los pelo MCP

Quando um assistente conectado via [MCP](../getting-started/) passa um caminho de análise a uma ferramenta, ele pode usar o **nome** do caminho (sem diferenciar maiúsculas de minúsculas) ou o seu **id**. Um caminho atualizado com um id que não existe é recusado; para criar um novo caminho, omita o id.

`query_data_read` aceita `analysis_path` no lugar de um projeto e uma tabela para `table`, `json_paths`, `dimension_value`, `column_values` e `aggregate`.

**Pré-visualize apenas algumas colunas.** Passe `columns=[...]` para `query_data_read(action='table')` para retornar somente as colunas que você nomear. As regras de acesso às linhas continuam valendo integralmente. Não pode ser combinado com `version_id`.

**Obtenha um total filtrado em uma única chamada.** Peça a `column_values` a medida e filtre pela coluna que lhe interessa:

```
query_data_read(
  action='column_values',
  project_id=<project>,
  table_id=<table>,
  dimension_column_name=<filter column>,
  value_column_name=<measure>,
  filters={<filter column>: <value>}
)
```

Ele retorna uma linha para esse valor. Quando o nome de uma coluna está escrito errado, o erro lista até cinco correspondências próximas para que o assistente possa corrigir e tentar de novo.

**Totalize ou detalhe em uma única chamada.** Use `action='aggregate'` para agrupar por uma ou mais colunas e totalizar, calcular a média ou contar medidas no servidor, em vez de ler linhas:

```
query_data_read(
  action='aggregate',
  project_id=<project>,
  table_id=<table>,
  group_by=['Product'],
  measures=[{'column': 'Revenue', 'agg': 'sum'}, {'column': 'Volume'}],
  filters={'Fiscal Year': 2027},
  order_by='Revenue',
  limit=10
)
```

`measures` aceita `agg` com `sum` (o padrão), `avg`, `min`, `max` ou `count`; `count` também aceita `'*'`. Um valor de `filters` pode ser uma lista para corresponder a qualquer um de vários valores. `limit` tem padrão 50 e no máximo 500. `order_by` nomeia uma medida ou uma coluna de agrupamento; as medidas são ordenadas da maior para a menor. A resposta tem `rows`, `total_groups` e `truncated`, que é verdadeiro quando existem mais grupos do que `limit` retornou. As regras de acesso às linhas se aplicam antes de os totais serem calculados.

## Quem pode configurá-los

Configurar caminhos de análise — registrá-los e escolher o padrão — é uma ação de **administrador**, para que os nomes compartilhados permaneçam limpos e confiáveis para todos. Depois que existem, todo membro do espaço de trabalho pode usá-los em suas perguntas, vendo ainda apenas os dados que suas próprias permissões permitem.
