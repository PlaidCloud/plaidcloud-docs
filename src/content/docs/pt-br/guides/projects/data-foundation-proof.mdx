Cada **Carregar** e cada **Aplicar alterações** termina verificando os valores que gravou. A página **Resumo**, em **Data Foundation** na página inicial do projeto, mostra o resultado: a situação do projeto em uma linha, cinco garantias, o quão atualizado está cada sistema e os meses que você fechou. Esta página explica o que cada item informa e o que fazer quando ele não está verde. Para configurar o projeto, consulte [Primeiros passos com o Data Foundation](/pt-br/guides/projects/data-foundation-getting-started/).

## A situação do projeto

A primeira linha de **Resumo** informa a situação do projeto:

| Linha | Significado |
|---|---|
| "Equilibrado até setembro de 2026" | Todas as garantias aplicáveis estão verdes, até esse mês. |
| "2 de 5 verificações precisam de atenção até setembro de 2026" | Esse número de garantias está vermelho. |
| "Nenhum sistema financeiro ainda" | Nenhum sistema foi adicionado. |
| "Ainda não carregado" | Nenhum mês foi carregado. |
| "Carregado até setembro de 2026; não foi possível ler as verificações agora" | Os dados estão carregados até esse mês, mas não foi possível ler as garantias quando a página as solicitou. |
| "Carregando NetSuite" | Uma execução está em andamento. |

O mês é o mais recente que está completo. Para um grupo, é o último mês que todas as entidades carregaram, e o cartão **O grupo** informa o quão completo o grupo está, por exemplo: "38 de 41 entidades carregadas. Completo até setembro de 2026; em outubro faltam SAP ECC." Uma entidade que ainda não carregou o mês seguinte mantém os valores do grupo no mês anterior, e a linha cita o sistema de onde ela vem.

## As cinco garantias

O cartão **Os números são confiáveis?** em **Resumo** lista cinco garantias, cada uma verificada para cada sistema, entidade e mês:

| Garantia | O que ela informa |
|---|---|
| **Equilibrado com cada sistema** | O saldo final de cada conta é igual ao saldo que o próprio sistema informa. Quando um sistema não informa um saldo separado, o razão dele é comparado com o próprio balancete, mês a mês, e a linha diz **O razão coincide com o próprio balancete**. |
| **Nada se perdeu no caminho** | Cada linha que cada sistema entregou é contabilizada, mantida (pertence a outro sistema ou livro) ou retida à espera de uma resposta. |
| **A contabilidade de cada entidade está equilibrada** | Os lançamentos de cada entidade em um mês somam zero, na moeda dela: débitos iguais a créditos. |
| **O grupo fecha** | Cada par intercompanhia concorda dentro da **Tolerância entre empresas**, em cobranças e em saldos, todo mês; cada entidade tem suas taxas de câmbio; e o balanço patrimonial de cada entidade fecha na moeda de relatório. |
| **O fluxo de caixa está consistente** | A variação do caixa na demonstração dos fluxos de caixa é igual à movimentação das contas de caixa, para cada entidade e para o grupo. |

Cada garantia mostra um destes estados:

| Mostra | Significado |
|---|---|
| **Verde** | Ela foi aprovada, e a linha abaixo informa o que foi comparado. |
| **Vermelho** | Pelo menos um sistema, entidade ou mês falha. O número ao lado indica quantos itens falham. |
| **Não aplicável** | Nada pôde ser verificado, por exemplo, um mês sem saldo nem balancete para comparar. A linha abaixo informa o motivo. |
| **Ainda não verificado** | Nenhuma carga executou a garantia. |

Uma empresa com uma só entidade não vê **O grupo fecha**. Um mês em que uma entidade não tem taxa de câmbio deixa essa entidade fora dos valores do grupo, por isso o fluxo de caixa dela não é avaliado nesse mês.

### Quando uma garantia está vermelha

Uma garantia vermelha lista o que falha: até os 20 itens mais recentes, em ordem de mês. Um item das três primeiras cita o sistema, a entidade, o mês, a conta e o valor. Um item das duas últimas é uma frase, como "Sem taxa EUR para outubro de 2026: Paris SA fica de fora dos valores do grupo nesse mês". Os valores estão na moeda de relatório.

| Garantia | O que fazer |
|---|---|
| **Equilibrado com cada sistema** | Compare a conta no relatório de saldos do próprio sistema, ou no balancete dele, com as linhas do razão e depois execute **Carregar** novamente. |
| **Nada se perdeu no caminho** | Responda às perguntas pendentes na página **Perguntas**, para que as linhas retidas sejam contabilizadas. |
| **A contabilidade de cada entidade está equilibrada** | Carregue o mês novamente ou corrija o lançamento no sistema. |
| **O grupo fecha** | Para um par com diferença, registre o lado que falta ou corrija o valor na entidade que diverge. Para uma taxa ausente, carregue a taxa dessa moeda para o mês. Para um balanço patrimonial que não fecha, verifique as eliminações e a conversão das linhas da demonstração. |
| **O fluxo de caixa está consistente** | Atribua uma função de conta à conta do balanço patrimonial que não tem linha de fluxo de caixa. |

**Perguntar ao Weave por quê**, ao lado de uma garantia vermelha, pergunta ao Weave por que ela está vermelha e quem precisa corrigi-la.

A **Tolerância entre empresas**, na moeda de relatório, é uma configuração do projeto com padrão de 1000. É o mesmo valor de `group_red` em [Eliminações intercompanhia](/pt-br/guides/projects/data-foundation/#eliminações-intercompanhia).

As [Verificações de prontidão](/pt-br/guides/projects/data-foundation/#verificações-de-prontidão) continuam sendo o detalhamento sob as cinco garantias. No painel **CFM-Accounting - Close and assurance**, **Every check, by system, month chosen** agrupa as verificações sob a garantia que cada uma comprova.

## O quão atualizado está cada sistema

A página **Sistemas** mostra, para cada sistema, quando ele foi carregado pela última vez e, se a última carga falhou, a última carga bem-sucedida. Quando a configuração **Atualizar** do projeto é **Diário**, **Semanal** ou **Mensal**, ela também mostra **Próxima atualização** com o horário previsto da próxima carga. Um sistema fica em atraso um dia depois do horário previsto, e a linha dele passa a dizer **Atualização em atraso desde** esse horário, em vermelho. Com um só sistema, a linha dele fica em **Resumo**, em **Seu sistema**, marcada como **Em atraso** quando for o caso. Com **Atualizar** definido como **Sob demanda**, um sistema nunca fica em atraso.

Um sistema cuja carga falhou mostra **Falhou** e informa o que fazer, por exemplo, abrir a conexão dele ou conectar novamente quando o acesso tiver expirado.

## Fechar um mês

Fechar um mês fixa os valores dele: as cargas posteriores continuam lendo o sistema, mas não alteram mais um mês fechado. Em **Resumo**, o cartão **Fechar um mês** mostra **Fechado até** com o último mês até o qual todas as entidades estão fechadas, ou **Nenhum mês foi fechado ainda.**

Para fechar:

1. Em **Fechar até**, escolha o mês. A lista começa no mês seguinte ao último fechado ou, quando nenhum estiver fechado, no mês passado.
2. Clique em **Fechar**.

Todas as entidades que você pode ver são fechadas até esse mês, e **Histórico** registra quem fechou e quando. Fechar exige um Gerente ou Arquiteto do projeto.

Quando o próprio calendário fiscal de um sistema mostra um mês fechado para todas as entidades que ele contém e o mês ainda não está fechado aqui, o cartão o oferece, por exemplo, "NetSuite mostra setembro de 2026 como fechado. Fechá-lo aqui?". Clique em **Fechar aqui** para fechá-lo.

### Quando um sistema altera um mês fechado

Se um sistema informar depois um valor diferente para um mês fechado, o mês fechado mantém o valor dele, e o cartão **O que mudou** em **Resumo** mostra a diferença, citando o sistema, a entidade, o mês, a conta e o valor da alteração. O projeto fica âmbar enquanto houver uma alteração pendente.

Clique em **Aceitar a alteração** para adotar os novos valores do sistema para esse mês. Isso executa **Aplicar alterações**, que reapresenta o mês, e **Histórico** registra uma **Reapresentação** com o valor de cada conta antes e depois. Aceitar uma alteração exige um Gerente ou Arquiteto que possa usar a conexão de todos os sistemas.

A configuração de projeto **Dia-alvo de fechamento**, cinco dias após o fim do mês, a menos que você a altere, é o dia em que o painel **CFM-Accounting - Close and assurance** considera um mês fechado no prazo em **Entities closed by the target day**.

## Nos painéis

Cada guia de painel do Data Foundation começa com uma linha de contexto que informa o que você está vendo: o mês, a entidade, o sistema, se ele está carregado e fechado, quantas garantias foram aprovadas, e a moeda e a unidade.

## Notificações

As pessoas que usam o aplicativo móvel do PlaidCloud recebem duas notificações, apenas com contagens, sobre projetos do Data Foundation. Nenhuma delas cita o projeto.

- **Quando uma carga altera o estado do projeto.** Quando um **Carregar** ou **Aplicar alterações** termina e o projeto fica vermelho, âmbar ou verde, quem o iniciou recebe "Um projeto do Data Foundation precisa da sua atenção." ou "Um projeto do Data Foundation está pronto." Para uma carga agendada, é quem salvou o agendamento pela última vez.
- **O resumo diário.** Uma vez por dia, cada Arquiteto e Gerente de um projeto recebe uma notificação, "2 projetos do Data Foundation precisam da sua atenção.", que conta os projetos que, desde o último resumo, ficaram âmbar ou vermelhos, cuja última carga aplicou códigos que nenhuma carga anterior tinha visto ou cuja carga falhou nas últimas 24 horas. Em um projeto aberto a todos os membros, só a pessoa que salvou o projeto pela última vez a recebe. Um projeto que ainda está carregando é contado no dia seguinte.

Um projeto fica vermelho quando a última execução falhou ou uma garantia está vermelha; âmbar enquanto houver uma pergunta ou uma alteração após o fechamento pendente, ou quando a última carga terminou com um aviso; e verde nos demais casos. A cor é avaliada sobre o projeto inteiro, não sobre as linhas que uma pessoa pode ver.
