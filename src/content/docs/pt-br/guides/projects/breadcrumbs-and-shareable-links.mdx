As janelas do Analyze se abrem umas sobre as outras — um fluxo de trabalho dentro de um projeto, uma etapa dentro desse fluxo de trabalho, uma tabela que você abriu para conferir um resultado. Dois recursos facilitam ver onde você está e voltar: um **breadcrumb** no título de cada janela e uma **URL que acompanha o que você está vendo**, de modo que qualquer visualização pode ser salva nos favoritos ou colada para um colega.

## O breadcrumb

As janelas que pertencem a um projeto mostram sua hierarquia como título, na barra de título da janela:

```
My Project › Workflow › Nightly Load
```

Cada parte é chamada de segmento, e eles são lidos da esquerda para a direita, do contêiner mais externo para dentro:

1. **O projeto** — o projeto que contém o que você está vendo.
2. **O tipo de objeto** — Fluxo de trabalho, Tabela, Etapa, Dimensão ou Editor de dados.
3. **O próprio objeto** — o fluxo de trabalho, a tabela, a etapa etc. atual. Este último segmento é onde você já está, portanto não é clicável.

### Navegar com ele

Selecione qualquer um dos dois primeiros segmentos para subir um nível:

| Segmento | Dica de ferramenta | O que faz |
|---|---|---|
| O nome do projeto | Abrir projeto | Abre esse projeto ou o traz para a frente se já estiver aberto |
| Fluxo de trabalho | Mostrar todos os fluxos de trabalho | Abre o projeto na lista de Fluxos de trabalho |
| Tabela | Mostrar todas as tabelas | Abre o projeto na lista de Tabelas |
| Etapa | Mostrar todas as etapas | Abre o projeto na lista de Etapas |
| Dimensão | Mostrar todas as dimensões | Abre o projeto na lista de Dimensões |
| Editor de dados | Mostrar todos os editores de dados | Abre o projeto na lista de Editores de dados |

O segmento de tipo é a maneira rápida de chegar a um item irmão: a partir de um fluxo de trabalho, um clique leva você à lista completa de fluxos de trabalho do mesmo projeto, pronta para abrir outro.

<Aside type="note">
A janela de onde você veio permanece aberta. Navegar com um breadcrumb traz o projeto para a frente — ele não fecha o que você estava vendo, e você pode voltar a isso pela barra de guias na parte inferior da tela.
</Aside>

### Onde os breadcrumbs aparecem

- Janelas de **Fluxo de trabalho** — a grade de etapas de um fluxo de trabalho padrão
- **Designer visual de fluxo de trabalho** — a visão em tela de um fluxo de trabalho avançado
- **Explorador de tabelas**
- Janelas de **Etapa** abertas isoladamente
- Janelas de hierarquia de **Dimensão**
- Janelas de **Editor de dados**

Uma etapa pode pertencer a mais de um fluxo de trabalho, portanto o breadcrumb de uma etapa mostra `Project › Step › name` em vez de nomear um único fluxo de trabalho proprietário.

### Acesso por teclado e leitor de tela

Os segmentos clicáveis são controles comuns: **Tabulação** move o foco para eles e **Enter** ou **Espaço** ativa o que está com foco, de modo que você nunca precisa do mouse para subir na hierarquia. Cada um é anunciado como botão, o segmento final é anunciado como a página atual, e os separadores `›` são ignorados em vez de lidos em voz alta.

### Sair de um Editor de dados com alterações não salvas

O Editor de dados é a única janela que pergunta antes de um breadcrumb levar você embora. Se você tem edições em andamento, selecionar um segmento mostra o aviso **Alterações não salvas** — *Fechar o editor de dados sem salvar as alterações?* — com **Fechar editor** para sair mesmo assim. Cancele o aviso e você permanece no editor com suas alterações intactas.

É o mesmo aviso que o botão **Fechar** do próprio editor mostra, portanto não existe caminho para sair de um Editor de dados que descarte o trabalho sem perguntar.

## Links compartilháveis

A barra de endereços sempre nomeia a janela que está na frente. Abra um fluxo de trabalho e a URL passa a ser o link desse fluxo de trabalho; abra uma tabela e ela passa a ser o link da tabela. Esse link é a unidade que você compartilha.

**Para compartilhar o que você está vendo**, copie a URL da barra de endereços do navegador e envie. Qualquer pessoa com acesso a esse projeto abre a mesma visualização. Salve nos favoritos e ele continuará funcionando depois.

### O que acontece quando alguém abre o link

Abrir ou atualizar um link restaura o **contexto pai**, e não apenas a janela. Um link para um fluxo de trabalho reabre também o projeto dele, de modo que você chega com o projeto disponível na barra de guias, em vez de uma única janela solta — o mesmo lugar a que você chegaria navegando até lá por conta própria.

### Formatos de link

Os links começam pelo projeto: primeiro o projeto, depois o objeto dentro dele, separados por `~`.

```
#p~my-project                        a project
#p~my-project~w~<workflow>           a standard workflow
#p~my-project~c~<workflow>           a workflow in the Visual Workflow Designer
#p~my-project~w~<workflow>~s~<step>  a step within a workflow
#p~my-project~t~<table>              a table in the Table Explorer
#p~my-project~d~<dimension>          a dimension hierarchy
#p~my-project~e~<editor>             a Data Editor
#home                                the Home landing page
```

Quando um projeto tem um nome de esquema, o link o usa (`my-project` acima), o que torna o link legível e estável. Caso contrário, o identificador do projeto é usado. As duas formas abrem o mesmo projeto.

<Aside type="note">
Os links criados antes do formato com o projeto primeiro continuam funcionando. Os links mais antigos no estilo `?p=…&t=…` continuam abrindo a visualização correta, e a barra de endereços se atualiza sozinha para o formato atual na sua primeira navegação.
</Aside>

### Quando um link não pode ser aberto

Se o objeto de um link foi excluído desde então, ou se você não tem acesso ao projeto dele, o link abre o aplicativo sem essa visualização, em vez de falhar. Fechar uma janela cujo link está na barra de endereços devolve a URL ao projeto proprietário, de modo que a barra de endereços nunca aponta para algo que não está mais aberto.
