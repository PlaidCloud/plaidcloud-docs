Todo projeto do Data Foundation vem com dezoito painéis, um conjunto de métricas e um caminho de análise para cada assunto. Todos leem as mesmas visões de relatório, que cada **Carregar** preenche a partir do [Common Finance Model](/pt-br/guides/projects/data-foundation/), de modo que um painel, uma métrica e uma resposta do Weave nunca divergem. Isso vale para um projeto criado a partir de qualquer modelo do Data Foundation, como [Cost to Serve](/pt-br/guides/projects/cost-to-serve/) ou [Operational Transfer Pricing](/pt-br/guides/projects/operational-transfer-pricing/). Para verificar se os números por trás deles são confiáveis, consulte [Data Foundation: os números são confiáveis?](/pt-br/guides/projects/data-foundation-proof/).

## A página Relatórios

**Relatórios**, em **Data Foundation** no início do projeto, lista os painéis por perfil: **Contabilidade**, **Executivo**, **Finanças**, **Marketing**, **Operações** e **Vendas**. Clique no nome de um painel para abri-lo em uma nova guia do navegador. Ele abre no Superset padrão, e nenhum filtro é levado do projeto. Como a página informa, você os vê se tiver acesso ao projeto.

Um painel ainda sem dados é listado pelo nome, esmaecido, sob uma linha como "3 reports have no data yet", com o que o preencheria: "Fills when a system with pipeline data finishes its load." ou, para um painel que não lê nenhum assunto específico, "Fills when your systems finish their first load."

O cartão **Pacote do conselho** na parte inferior tem **Abrir o pacote para a diretoria** assim que o painel do pacote é criado, e **Configurações do pacote para a diretoria**, disponível com acesso de edição ao projeto, que abre as configurações descritas em [Pacote para a diretoria](/pt-br/guides/projects/data-foundation/#pacote-para-a-diretoria).

## Quando os painéis são criados

Instalar o Data Foundation cria as visões de relatório, e a mensagem da instalação informa quantas visões de relatório e quantos painéis foram instalados e o que fazer em seguida. Os próprios painéis são criados ao fim de cada **Carregar** e **Aplicar alterações**, pela etapa **Make the dashboards**, a partir do que essa execução gravou. Um projeto instalado com os dados de exemplo mostra o exemplo assim que a primeira carga termina.

Cada execução posterior recria os painéis no mesmo lugar, então os links deles continuam os mesmos e os dados que chegam depois são preenchidos. O Data Foundation recria um painel a cada Carregar, inclusive as edições, então copie um painel no Superset para manter alterações suas. A linha de contexto no topo de cada painel diz o mesmo.

A falta de dados nunca é um erro:

- Um gráfico ou bloco sem dados é omitido, e a linha dele se fecha. Um bloco sem dados pode ceder o lugar a outro, como **Owed by customers** no lugar de **Net debt** quando nenhuma conta está marcada como empréstimos.
- Uma guia cujos gráficos não têm dados é omitida. Um painel cuja **Overview** não tem nada a mostrar não é criado, e **Relatórios** o lista como ainda sem dados.
- A execução termina com um aviso que indica o painel e a guia omitida, como "CFM-Sales - Pipeline: the Deals closing tab is left out, as its charts have no data yet."
- Se os relatórios estiverem desativados no seu espaço de trabalho, nenhum painel é criado, e o aviso informa isso.
- Se um painel criado por outra pessoa já tiver o endereço de que um painel do Data Foundation precisa, esse painel é deixado como está, e o aviso indica o endereço. Dê outro endereço ao outro painel no Superset.

## Quem os vê

Um painel recebe o [público padrão para novos painéis](/pt-br/guides/dashboards/control-who-can-see-a-dashboard/#público-padrão-para-novos-painéis) do projeto quando é criado pela primeira vez. As recriações posteriores mantêm o público que ele tiver nesse momento.

Os painéis são criados a partir de todas as linhas do projeto, nunca das linhas que uma pessoa consegue ver. Cada pessoa que abre um painel vê apenas as linhas que o seu [acesso a linhas](/pt-br/administration/access/managing-security-groups-and-assignments/#gerenciar-o-acesso-a-linhas) permite. Quando alguém cujo acesso a linhas restringe o que vê inicia uma recriação, os painéis são deixados como o último Carregar os criou, e a mensagem informa que o próximo Carregar os recria.

## Os dezoito painéis

Todo painel tem o título **CFM-*perfil* - *relatório***. Ele abre em **Overview** e termina com **Detail**, que lista as linhas por trás dos números. As guias intermediárias respondem às perguntas abaixo.

|---|---|---|
| **CFM-Accounting - Assets** | **Roll-forward**, **Bought and sold** | Contabilidade |
| **CFM-Accounting - Close and assurance** | **What needs fixing**, **Is the month closed**. Consulte [Data Foundation: os números são confiáveis?](/pt-br/guides/projects/data-foundation-proof/) | Contabilidade |
| **CFM-Accounting - Intercompany** | **Which pairs do not agree**, **What has no partner** | Contabilidade |
| **CFM-Accounting - Journals** | **What was posted by hand**, **Journals to check** | Contabilidade |
| **CFM-Accounting - Receivables and payables** | **Who owes us**, **Who we pay** | Contabilidade |
| **CFM-Executive - Growth and efficiency** | **Recurring revenue**, **Margin by class**, **Efficiency**. Consulte [Crescimento e eficiência](#crescimento-e-eficiência). | Executivo |
| **CFM-Executive - Summary** | **Where the cash is**, **Sales and what is coming** | Executivo |
| **CFM-Finance - Operating expense** | **Which costs**, **Which departments**, **Which entities** | Finanças |
| **CFM-Finance - Performance against plan** | **What caused the gap**, **Who is over budget**, **Where the year lands** | Finanças |
| **CFM-Finance - Statements** | **What we own and owe**, **Where the cash went**, **Each unit's share**. O PDF do pacote para a diretoria imprime este painel. | Finanças |

Os blocos da **Overview** do **CFM-Executive - Summary** são **Revenue, year to date**, **Gross margin %, year to date**, **EBITDA, year to date** e **Cash at month end**.

### Crescimento e eficiência

O **CFM-Executive - Growth and efficiency** mostra os números que uma empresa de assinaturas ou de software apresenta à diretoria e aos investidores. Os blocos da Overview são **Annual recurring revenue**, **Net revenue retention at this month's rates**, **Net new recurring revenue, last 12 months** e **Months of cash at the last 12 months' burn**. Abaixo deles estão a receita recorrente anual por classe de receita, como ela mudou nos últimos 12 meses e uma tabela ano a ano com os anos realizados e previstos.

- A receita recorrente anual vem dos contratos. É o valor anual dos contratos e das assinaturas ativos no fim do mês escolhido, lido da tabela de contratos, por exemplo de um [arquivo de contratos](/pt-br/guides/projects/data-foundation/#registros-de-contratos). Os contratos assinados contam a partir da data de início. Enquanto os contratos não são carregados, cada número que depende deles mostra "Needs contracts: load your contracts or subscriptions", e os gráficos de receita recorrente anual dão lugar à receita do razão por classe em cada mês.
- As classes de receita dividem a receita recorrente, e a receita e a margem do razão, nos tipos de receita da sua própria empresa. Consulte [Classes de receita e funções das equipes](/pt-br/guides/projects/data-foundation/#classes-de-receita-e-funções-das-equipes). Toda linha de contrato conta na receita recorrente anual, qualquer que seja a classe. A receita do razão conta como recorrente quando a classe da conta dela é de um tipo recorrente.
- A ponte de 12 meses vai de 12 meses atrás até o mês escolhido, por cliente dentro de cada entidade. Os clientes "New" não tinham receita recorrente 12 meses atrás e os "Lost" não têm agora; "Grew" e "Shrank" são os demais, pelo total do cliente em todas as classes. "Exchange rates" reapresenta o valor de 12 meses atrás às taxas de fechamento deste mês, e "Month chosen" é onde a ponte termina. Enquanto não há 13 meses de contratos carregados, todo cliente é novo.
- A retenção vem da mesma ponte, às taxas deste mês. A retenção líquida de receita é o que os clientes de 12 meses atrás têm agora em relação ao que tinham então. A **Gross revenue retention** exclui o crescimento deles, então nunca passa de 100%, e um cliente que move valor entre classes não caiu. No **CFM-Sales - Orders and contracts**, a métrica **Net revenue retention** de **Recurring revenue kept from a year ago** mantém cada ano às taxas dele.
- A guia **Efficiency** mede em relação ao gasto com vendas e marketing: o custo operacional das equipes cuja função é **Vendas e marketing**, mais as contas de marketing e de comissões em qualquer lugar. O **Cost to win a new customer** é o gasto dos últimos 12 meses dividido pelos novos clientes desse período. O **Lifetime value for each 1 spent winning a customer** limita o tempo de vida de um cliente a 5 anos. O **Net new recurring revenue for each 1 spent on sales and marketing the year before** compara o crescimento dos últimos 12 meses com o gasto dos 12 meses anteriores a eles, e o **Cash burned for each 1 of net new recurring revenue** compara a queima líquida com esse crescimento.
- A queima líquida é o fluxo de caixa operacional mais o de investimento, sem o dinheiro captado ou pago e sem as taxas de câmbio. O **Months of cash at the last 12 months' burn** é o caixa do fim do mês dividido pela queima líquida mensal média dos últimos 12 meses, uma taxa passada, não uma previsão. Sem nenhuma conta marcada como caixa, mostra "Needs account roles: which accounts hold cash"; quando os últimos 12 meses não queimaram caixa, mostra "Not burning cash" com o caixa do fim do mês.
- A guia **Margin by class** dá a cada classe a receita menos o custo da receita. Uma conta de custo da receita compartilhada por todas as classes é distribuída pela participação de cada classe na receita dos 12 meses até cada mês. O **Gross margin %, year to date** é o da própria demonstração do resultado, e os demais números de receita da guia são anteriores às eliminações entre empresas.
- A tabela ano a ano mostra os anos completos, o ano atual, até a data ou com os meses restantes da última previsão, e os anos posteriores da última previsão. O crescimento compara apenas anos completos.
- A receita por pessoa empregada é mostrada quando os direcionadores de alocação trazem um número de funcionários.

Um número com lacuna mantém o valor, com até duas linhas abaixo dele que nomeiam a lacuna e o tamanho dela, como meses dos últimos 12 não carregados, receita ainda sem classe de receita, custo operacional sem equipe, ou entidades sem contratos ou sem conta de caixa. Os clientes cuja moeda não tem taxa de fechamento para o mês escolhido ou para 12 meses atrás, e as entidades cujos contratos não estão carregados para o mês, ficam fora da ponte e da retenção. O painel não tem filtro de centro de lucro, pois a receita recorrente, a retenção e a ponte são por entidade e por cliente.

## Como ler um painel

**A linha de contexto.** Cada guia começa com uma linha que diz o que os números abrangem. Consulte [Nos painéis](/pt-br/guides/projects/data-foundation-proof/#nos-painéis). Na **Overview**, ela acrescenta **Right-click any chart to break it down or see its rows**. Sem orçamento, ela diz **No budget loaded; comparing with last year**, e os títulos dos gráficos comparam com o ano anterior em vez do orçamento.

**Filtros.** **Period** está sempre presente. **Region**, **Country**, **Division** e **Entity** são acrescentados quando o projeto tem dois ou mais deles, e cada um lista apenas os valores dentro dos escolhidos antes dele. **Profit centre** é acrescentado quando os dados trazem dois ou mais. Em seguida vêm os filtros próprios do painel. Os filtros que não cabem na barra ficam em **More filters**. **Period** abre no último mês fechado para todas as entidades. **CFM-Accounting - Close and assurance**, **CFM-Accounting - Intercompany** e **CFM-Sales - Pipeline** abrem no mês atual: o primeiro mês ainda não fechado. Sem nenhum mês fechado, **Period** abre no mês mais recente.

O **CFM-Executive - Growth and efficiency** não tem filtro de centro de lucro. Consulte [Crescimento e eficiência](#crescimento-e-eficiência).

**Blocos.** Um bloco mostra o número, a variação dele e a tendência nos doze meses até o mês escolhido, com duas comparações: com o orçamento e com o ano anterior ou, quando o número não tem orçamento, com o mês anterior e com o ano anterior. Um número sem um mês próprio mostra o valor sem a tendência. Um bloco que outra guia explica termina com **Why ›**, que abre essa guia. Toda variação é mostrada de modo que um número positivo seja bom, seja qual for o sentido da medida, e a seta e a cor do bloco acompanham isso. A variação de uma margem é dada em pontos.

**See also.** Toda guia, exceto a **Overview**, termina com uma linha **See also** que leva aos painéis relacionados a ela.

**Unidades.** Os títulos dos gráficos indicam a unidade. A configuração de projeto **Unidade de exibição** é **Automático**, **Unidades inteiras**, **Milhares** ou **Milhões**. **Automático** usa unidades inteiras para uma única empresa com menos de 10 milhões de receita no seu maior ano fiscal; caso contrário, milhares, ou milhões a partir de 1 bilhão de receita. Valores por unidade, como um preço médio, nunca são escalados. Uma configuração alterada aparece na próxima vez que os painéis forem criados.

**As palavras do seu sistema.** Um projeto com um único sistema QuickBooks Online usa as palavras dele: **Class** no lugar de **Profit centre**, **Location** no lugar de site e **Category** no lugar de família de produtos.

## Cópias de um projeto

Um projeto criado com [Clonar](/pt-br/guides/projects/data-foundation/#clonar-um-projeto) não tem painéis próprios. Ele compartilha o conjunto do original, e esses painéis continuam lendo o original. A página **Relatórios** dele diz **Este projeto é uma cópia**, com **Abrir o projeto de relatórios** e duas opções:

- **Definir como projeto de relatórios** aponta os painéis do conjunto para este projeto, de modo que os gráficos, os links, os favoritos e os agendamentos deles continuam. Cada painel recebe o público padrão deste projeto, a menos que um proprietário tenha escolhido o público dele ou que alguém seja coproprietário dele. Você precisa de acesso de edição a este projeto e àquele que os painéis liam antes. Um gráfico cujos dados este projeto não tem não mostra nada aqui, e a mensagem indica o painel e as guias. Em um projeto que nunca carregou, a mensagem é "This project has no reporting database yet. Run Load first."
- **Atribuir painéis próprios a esta cópia** pede que você confirme: "This copy gets its own set of dashboards, as a separate business would. Use this only when the copy has become one." Clique em **Atribuir painéis** para prosseguir.

Ambas exigem acesso de edição ao projeto, e ambas recriam os painéis imediatamente.

## Métricas

Todo projeto recebe as métricas que os painéis dele mostram. A maioria é uma [definição de métrica](/pt-br/integrations/ai-coding-agents/metric-definitions/) com que o Weave responde, definida uma única vez para ambos, de modo que o Weave e os painéis concordam. No **CFM-Executive - Growth and efficiency**, o Weave responde com os números principais, como receita recorrente anual, retenção de receita líquida e bruta, nova receita recorrente líquida, queima líquida de caixa e meses de caixa; os demais números, como o custo para conquistar um cliente, o valor do tempo de vida e as divisões por classe e por função, ficam só no painel. Uma métrica é nomeada pelo título, como **Revenue** ou **Working capital**, ou, quando duas compartilham um título, pelo título e pelo assunto dela, como *título* - *assunto*. Quando duas do mesmo assunto compartilham um título, ela é *título* (*nome da métrica*).

As métricas são criadas quando o Data Foundation é instalado e ao fim de cada **Carregar**, pela etapa **Make the metrics**. Uma métrica é criada assim que a visão de relatório que ela lê é criada. Uma métrica que o projeto já tem com esse nome é deixada como está, então as suas edições nela permanecem. Uma métrica que não pode ser criada é indicada nos avisos da execução, com o motivo; os painéis ainda a mostram.

## Caminhos de análise

Instalar o Data Foundation cria um [caminho de análise](/pt-br/integrations/ai-coding-agents/analysis-paths/) por assunto, nomeado a partir do projeto: *nome do projeto* - *assunto*. Os assuntos são **Finance**, **Journals**, **Trial balance**, **Drivers**, **Sales**, **Pipeline**, **Orders**, **Contracts**, **Purchasing**, **Receivables and payables**, **Intercompany**, **Inventory**, **Assets**, **Cash** e **Close and assurance**. Quando outro caminho de análise já usa o nome do projeto, os caminhos recebem o nome com um número, como `Northwind (2) - Finance`.

Cada caminho lê a visão de relatório do assunto e descreve todas as visões de relatório do assunto, para que o Weave saiba o que cada uma contém. Os seus [nomes de negócio](/pt-br/guides/projects/data-foundation/#nomes-de-negócio) são gravados na descrição do caminho de análise do próprio projeto. Um caminho com o mesmo nome que pertence a outro projeto é deixado como está, com um aviso.

## Visões de relatório

As visões de relatório são tabelas e visões chamadas `cfm_rv_...` no nível superior do projeto, como `cfm_rv_finance_month` e `cfm_rv_sales_window`. O fluxo de trabalho **Reports** do projeto as preenche a cada **Carregar**, após **Consolidate**. Todo painel, métrica e caminho de análise as lê, e você pode consultá-las como qualquer outra tabela do projeto. Uma visão cujos dados ainda não estão lá é criada vazia e é preenchida assim que os dados chegam.
