**Exportar para formato portátil** empacota os fluxos de trabalho de um projeto como um programa Python autocontido que é executado no [DuckDB](https://duckdb.org) sem nenhuma conexão com o PlaidCloud. Ele produz uma cópia portátil da lógica e dos dados do projeto que é executada offline, por conta própria.

É uma exportação unidirecional. O pacote gerado é um instantâneo de um momento específico; ele não sincroniza de volta, e exportar novamente após alterações produz um pacote novo.

<Aside type="caution" title="Fidelidade em regime de melhor esforço">
A exportação reproduz exatamente as etapas de transformação baseadas em SQL. Operações proprietárias e com efeitos colaterais — alocações, cargas de dimensão, notificações, etapas de documentos e relatórios, scripts — são exportadas como **stubs**: a configuração original delas é preservada e, quando a tabela de saída foi materializada, seus dados são incluídos como um instantâneo, mas a etapa em si não é executada novamente. A fidelidade de cada etapa é registrada em `COVERAGE.md` dentro do pacote. Para resultados garantidos e totalmente recalculados, execute o projeto no PlaidCloud.
</Aside>

## Exportar um projeto

1. Abra o **Analyze** e selecione a guia **Projetos**.
2. Selecione um único projeto.
3. Abra o menu **Ações** (ou clique com o botão direito no projeto) e escolha **Exportar para formato portátil** — ele fica ao lado de **Export Project**.
4. Na caixa de diálogo:
   - **Conta de documentos** — a conta de documentos na qual o pacote é gravado.
   - **Caminho da pasta** — a pasta dentro dessa conta, por exemplo `/exports`.
   - **Include data** — quando marcada (o padrão), as tabelas de origem e de instantâneo são incluídas como Parquet, para que o pacote seja executado sem nenhum dado externo. Desmarque para enviar apenas o código e os contratos de esquema, que você mesmo preenche depois.
5. Clique em **Exportar**. Quando terminar, uma mensagem confirma onde o pacote foi gravado e quantas tabelas foram capturadas em instantâneo.

A ação exige acesso ao projeto e à leitura de suas tabelas — o mesmo nível de acesso necessário hoje para exportar dados de tabela.

## O que há no pacote

A exportação é um `.zip` que contém:

- `pipeline_<workflow>.py` — um script por fluxo de trabalho, com as etapas na ordem de execução.
- `config.py` — a seleção do mecanismo (DuckDB por padrão) e o nome do esquema do projeto.
- `_runtime.py` — uma pequena camada de compatibilidade do mecanismo; a única dependência além do DuckDB.
- `stubs.py` — funções sem operação para operações não portáteis, cada uma com a configuração original da etapa.
- `data/` — instantâneos Parquet das tabelas de origem e congeladas (quando **Include data** estava marcada).
- `requirements.txt` — as dependências Python (apenas `duckdb`).
- `README.md`, `COVERAGE.md`, `RUN_ORDER.md` — como executar, a fidelidade de cada etapa e a ordem em que os scripts de fluxo de trabalho devem ser executados.

## Executar o pacote

1. Descompacte o pacote e crie um ambiente Python:

   ```bash
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. Execute cada script de fluxo de trabalho, na ordem listada em `RUN_ORDER.md`:

   ```bash
   python pipeline_<workflow>.py
   ```

Cada script cria suas tabelas em um banco de dados DuckDB local (`export.duckdb` por padrão). As etapas de transformação SQL são recalculadas ao vivo; as etapas com stub exibem um aviso e deixam a saída capturada em instantâneo no lugar. Para apontar o pacote para o seu próprio data warehouse em vez do DuckDB, defina `ENGINE` em `config.py`.
