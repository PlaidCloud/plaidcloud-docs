O **Data Foundation** é a base de dados financeiros dos seus projetos PlaidCloud. O **Common Finance Model** dele reúne dados de vários sistemas ERP, e de várias instâncias de cada um, em um único modelo: um plano de contas, um conjunto de entidades e uma moeda de relatório. Relatórios, métricas e assistentes de IA criados sobre o modelo leem os mesmos números, seja qual for o ERP de origem.

Seu ERP se conecta pela conexão do PlaidCloud, então o razão geral, o balancete, os dados mestres e os orçamentos chegam diretamente da origem, sem nada para exportar. Arquivos acrescentam dados que um sistema não tem, como taxas de câmbio, direcionadores de alocação ou um orçamento mantido fora do ERP, e podem substituir as linhas do ERP que cobrem. **Carregar** padroniza cada origem no modelo, converte para a moeda de relatório e verifica se os totais batem, tudo no grupo **Data Foundation** da barra lateral **Início** do projeto. Quando você adiciona um segundo sistema, responde a uma pergunta por assunto, como se ele usa os mesmos códigos de conta de um sistema já conectado, e uma consolidação gerencial monta a demonstração do resultado do grupo com as operações intercompanhia eliminadas. Você pode adicionar o Data Foundation a qualquer projeto, e soluções, como o **Enterprise Profitability**, criam seus relatórios e modelos sobre ele.

## Obter o Data Foundation

Você pode começar um projeto com o Data Foundation ou adicioná-lo a um projeto que já tem.

- **Um projeto novo.** No Analyze, abra **Projetos** e clique em **Novo projeto**. **Começar de** lista **Blank**, **Data Foundation**, **Enterprise Profitability**, **Cost to Serve**, **Operational Transfer Pricing** e **A partir de um arquivo de modelo**, com uma linha abaixo da lista que informa o que a escolha oferece. **Data Foundation** é o modelo sozinho, com seus relatórios. Cada uma das três soluções inclui o Data Foundation e acrescenta seus próprios modelos. Para ver um exemplo completo antes de conectar qualquer coisa, marque **Começar com dados de exemplo**. Clique em **Criar**. O projeto é privado para você, e você é o único Arquiteto dele, até compartilhá-lo.
- **Seu primeiro acesso.** Se você pode criar projetos, a tela de boas-vindas do seu primeiro acesso oferece **Conecte seu sistema financeiro**. Isso cria um projeto do Data Foundation, dá um nome a ele para você e o abre enquanto ele é criado.
- **Um projeto que você já tem.** Abra **Início** no projeto. Sob o título **Data Foundation** da barra lateral, a linha **Data Foundation** explica o que ele é, e um Arquiteto do projeto vê **Adicionar Data Foundation**. A criação é executada em segundo plano, e a página mostra **Adicionando o Data Foundation. Isso leva alguns minutos.** Seus próprios fluxos de trabalho, tabelas e outros trabalhos permanecem como estão. Se o projeto já tiver uma tabela no lugar em que o modelo mantém uma, nada é instalado e a mensagem cita a tabela.

**Início** é a primeira guia de todo projeto. Quando um projeto tem o Data Foundation, o grupo **Data Foundation** da barra lateral contém estas linhas, cada uma com seu próprio link:

| Linha | Quando aparece |
|---|---|
| **Resumo** | Sempre. Um projeto com Data Foundation e ainda sem nenhum sistema abre nela. |
| **Sistemas** | Quando o projeto tem dois ou mais sistemas, quando um sistema está aguardando acesso ou quando a próxima etapa em **Resumo** é adicionar, conectar ou manter um sistema atualizado. |
| **Perguntas** | Enquanto houver uma pergunta aguardando sua resposta, com a quantidade indicada em um selo. |
| **Relatórios** | Sempre. |
| **Alocações** | Em um projeto criado com uma solução. |

## Conectar seu ERP

Seu sistema financeiro se conecta ao Data Foundation pela conexão do PlaidCloud. O Data Foundation lê diretamente dele o razão geral, o balancete, os dados mestres, as taxas de câmbio, os orçamentos e, quando o sistema os contém, os razões auxiliares, os saldos de fim de mês e os saldos bancários, e apenas lê. As credenciais só são digitadas no editor de conexões padrão. Cada sistema tem uma página para o administrador que concede o acesso, listada em [Quais sistemas podem alimentar o modelo](/pt-br/guides/projects/data-foundation-getting-started/#quais-sistemas-podem-alimentar-o-modelo), e a [Matriz de cobertura do Data Foundation](/pt-br/reference/data-foundation-coverage-matrix/) mostra quais datasets cada sistema fornece diretamente.

<Steps>

1. Em **Resumo**, clique em **Adicione seu sistema financeiro**. Isso abre **Sistemas**.

2. Em **Adicionar um sistema**, escolha seu sistema em **Sistema**. O que vem a seguir depende de como o sistema faz login:

   - **QuickBooks Online e Xero** fazem login quando você aprova o acesso na janela do próprio sistema. Clique em **Connect to** e no nome do sistema. O PlaidCloud cria a conexão para o ambiente do projeto e abre a janela de aprovação. Depois que você aprova, o sistema é adicionado e começa a carregar. Se o navegador bloquear a janela, permita pop-ups para o site e tente novamente.
   - **Um sistema em que você faz login com credenciais** lista em **Conexão** as conexões desse tipo que você pode usar, com a primeira selecionada, e **Nova conexão**. Escolha uma e clique em **Adicionar sistema**. **Nova conexão** abre o editor de conexões padrão com o ambiente do projeto já preenchido, e o sistema é adicionado quando você salva a conexão.
   - **SAP S/4HANA, SAP ECC, Oracle E-Business Suite e Sage 100** são acessados por meio de um agente PlaidLink na sua rede. Configure o agente primeiro e depois escolha a conexão dele como em qualquer sistema que faz login com credenciais.

3. Para mudar o que é carregado antes de adicionar o sistema, abra **Opções**. **Empresas** lista as empresas do sistema: marque as que devem ser carregadas ou nenhuma para carregar todas. Um sistema que não lista as empresas pede que você as digite. **Meses de histórico** é quantos meses para trás carregar, de 1 a 120. Alguns sistemas também têm **Configurações do sistema**, e um sistema com uma configuração indispensável abre **Opções** e a solicita. Sem **Opções**, todas as empresas ativas e 24 meses de histórico são carregados.

4. Um sistema adicionado com a respectiva conexão começa a carregar imediatamente. Se outros fluxos de trabalho usam a mesma conexão, o PlaidCloud primeiro pergunta **Carregar de uma conexão compartilhada?** e os cita, porque a carga lê da conexão e pode deixar esses fluxos de trabalho mais lentos. Clique em **Carregar mesmo assim** para continuar.

</Steps>

Ainda não tem acesso? Escolha o sistema e clique em **Ainda não tem acesso?**. O sistema é adicionado como **Aguardando acesso**, e uma única solicitação que abrange todos os sistemas em espera é exibida, pronta para ser enviada com **Copiar solicitação** ou **Enviar solicitação por e-mail**. Quando o acesso chegar, adicione o sistema com a respectiva conexão em **Adicionar um sistema**. Para QuickBooks Online e Xero, clique em **Conectar** na linha do sistema.

Para trazer outro sistema ou outra instância, adicione-o da mesma forma. Adicionar um sistema sempre mantém os outros como estão, de modo que vários sistemas e instâncias alimentam o mesmo modelo consolidado. Quando você adiciona um segundo sistema, o Data Foundation faz uma pergunta por assunto em vez de uma por código. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens).

Cada carga lê apenas o que mudou: os períodos abertos e o último período fechado são lidos novamente, e os períodos fechados já carregados são mantidos. Aumentar **Meses de histórico** lê apenas os meses acrescentados. Uma alteração em uma taxa de câmbio, no mapeamento de entidades ou na moeda de relatório lê novamente os meses afetados.

## Sistemas

Cada sistema e instância de onde o projeto carrega dados é uma origem, e os arquivos que você confirma também são origens. A linha **Sistemas** da barra lateral e, com ela, a página, seus botões e seu cartão **Arquivos** aparecem quando o projeto tem dois ou mais sistemas, quando um sistema está aguardando acesso ou quando a próxima etapa em **Resumo** é adicionar, conectar ou manter um sistema atualizado. Com um só sistema, carregado e mantido atualizado, **Resumo** o mostra em **Seu sistema**. A página **Sistemas** lista todos os sistemas, com **Sistema**, **Status** e **Última carga**. **Status** é **Aguardando acesso**, **Conectado**, **Carregando**, **Carregado** ou **Falhou**. **Última carga** informa quando o sistema foi carregado pela última vez, ou **Ainda não carregado**, e, quando o projeto é atualizado por agendamento, quando a próxima atualização está prevista ou desde quando ela está em atraso. Abaixo de um sistema que falhou, a linha dele informa o motivo.

Cada linha tem o botão adequado à situação do sistema:

| Botão | Quando aparece |
|---|---|
| **Carregar** | O sistema está conectado ou carregado. Ele lê apenas esse sistema e depois reconstrói o modelo com os dados de todos os sistemas. Um sistema com falha o oferece ao lado da correção. |
| **Abrir conexão** | O sistema não foi carregado. Abra a conexão dele para ver o motivo e corrigi-lo. |
| **Reconectar** | O login no QuickBooks Online ou no Xero expirou. |
| **Conectar** | O QuickBooks Online ou o Xero está aguardando acesso. |
| **Solicitar acesso** | Um sistema que faz login com credenciais está aguardando acesso. Ele mostra novamente a solicitação a enviar. |

Ao lado dele, **Testar conexão** faz login e tenta ler cada dataset; depois, lista cada um como **Legível**, **Permissão ausente** ou **Erro** e informa as permissões que você deve pedir ao administrador do sistema. **Remover** retira um sistema do projeto depois que você confirma **Remover este sistema?**. Tudo o que foi carregado dele é excluído, e você pode conectá-lo novamente mais tarde.

Clique em **Editar** em um sistema para mudar como ele é usado e depois clique em **Salvar**:

| Configuração | O que faz |
|---|---|
| **Nome** | O rótulo que relatórios, perguntas e mensagens usam para o sistema. |
| **Livros contábeis de relatório, separados por vírgulas** | Os livros contábeis a ler, para um sistema que mantém mais de um. **All reporting books** lê todos os livros. |
| **Meses que esta fonte fornece** | Para cada **Empresa**, os meses de **De (2026-01)** a **Até (2026-12)** que o sistema fornece. Deixe um mês vazio para não haver limite. Escreva os meses como ano e mês, por exemplo `2026-03`. |
| **Categorias adicionais nesta fonte** | Para cada categoria adicional que o sistema contém, o **Nome** dela e onde ela é **Exibido em**, ou **Deixar de fora**. |
| **Empresas** e **Meses de histórico** | Quais empresas o sistema carrega e quantos meses para trás. |

Adicionar empresas, ou não marcar nenhuma, salva imediatamente. Deixar uma empresa de fora pede primeiro que você confirme **Carregar menos empresas?**, porque salvar apaga na hora tudo o que foi carregado daquele sistema, e o próximo **Carregar** obtém novamente as empresas marcadas.

Quando dois sistemas fornecem o mesmo mês para a mesma empresa, vale o que estiver listado mais acima até você escolher qual vale a partir de quando. Consulte [Escolher qual origem vale a partir de quando](#escolher-qual-origem-vale-a-partir-de-quando).

Alterar as origens não lê o ERP novamente. A barra acima de todas as páginas mostra **Você alterou suas origens. Clique em Aplicar alterações para usá-las.** até você clicar em **Aplicar alterações**, que executa uma carga com os dados já obtidos: padroniza novamente as origens com os novos mapeamentos, nomes e arquivos e reconstrói o modelo. Clique em **Carregar** quando também quiser dados novos dos seus sistemas.

## Adicionar arquivos com dados de fora do ERP

Os arquivos complementam a conexão do ERP com dados que um sistema não tem, como taxas de câmbio, direcionadores de alocação, um [Mapa de códigos](#mapeamento-de-entidades) de códigos de entidade ou um orçamento mantido fora do ERP. Cada arquivo pertence a um dos datasets listados em [Tabelas do Common Finance Model](#tabelas-do-common-finance-model).

<Steps>

1. No cartão **Arquivos**, abaixo dos sistemas em **Sistemas**, escolha a **Conta de documentos** onde o arquivo será armazenado.

2. Solte um arquivo CSV ou Excel em **Solte aqui um arquivo CSV ou Excel** ou clique em **Escolher um arquivo**. O arquivo é enviado para a pasta `/foundation/` da conta de documentos.

   Para um arquivo que já está na conta de documentos, abra **Mais formas de adicionar arquivos** e, em **Adicionar um arquivo que já está na conta de documentos**, digite o caminho dele, por exemplo `/foundation/budget.csv`, e clique em **Adicionar arquivo**.

   Para ler um arquivo novo todo mês, use **Adicionar todos os arquivos correspondentes de uma pasta**: digite a pasta, escolha se os nomes dos arquivos **contém**, **começa com**, **termina com**, **é exatamente** ou **corresponde a (\* representa qualquer coisa)** o que você digitar e clique em **Adicionar arquivos**. Arquivos em pastas dentro dela não são lidos.

3. O PlaidCloud lê o arquivo e propõe um mapeamento:

   - **Delimitador, separador decimal e datas detectados.** O delimitador (vírgula, ponto e vírgula, tabulação ou barra vertical), o separador decimal e o formato de data são detectados para você.
   - **Dataset**: a tabela do Common Finance Model à qual o arquivo pertence, identificada pelo nome do arquivo e pelos cabeçalhos das colunas. Quando a correspondência não está clara, escolha-a na lista.
   - **Separador decimal**: **Ponto (1,234.56)** ou **Vírgula (1.234,56)**.
   - **Formato de data**: exibido quando o arquivo tem datas. Altere-o se o formato detectado estiver errado: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Uma grade com **Coluna no arquivo**, **Tipo**, **Exemplos** e **Vai para**. Altere **Vai para** para enviar uma coluna a outro campo ou para **Não carregar**.

4. Responda às perguntas que o arquivo levantar, como **Para qual empresa é este arquivo?**, **Em que moeda estão os valores?**, **Esses valores são acumulados do ano ou do mês?**, **Os valores estão em milhares ou em milhões?**, **As receitas são mostradas como números negativos?** ou, para um arquivo de contratos, **Cada linha é um período de contrato?** (consulte [Registros de contratos](#registros-de-contratos)). Cada uma só é feita quando o arquivo ainda não informa isso, exceto **Cada linha é um período de contrato?**, que todo arquivo proposto como de contratos faz.

5. Verifique para onde vai cada coluna e clique em **Confirmar mapeamento**. Enquanto isso é processado, a nota abaixo do botão explica o motivo da espera. Em um projeto que ainda tem os dados de exemplo, o primeiro arquivo que você confirma também remove o exemplo, o que pode levar alguns minutos.

</Steps>

Estas opções aparecem em um arquivo quando se aplicam:

| Opção | Use para |
|---|---|
| **Which source do these rows apply to?** | Limitar um arquivo de mapa de códigos a uma origem. **Every source** o aplica a todas elas. |
| **Where does this file come from?** | Informar se o arquivo contém **This project's own codes** ou vem de **Another system**, ao qual você dá um nome, por exemplo `SAP Germany export`. Um arquivo de outro sistema é verificado quanto a códigos compartilhados, como uma origem ERP. |
| **Split … into … parts at each …** (em **Avançado**) | Dividir uma coluna que contém vários valores, como `100-200-300`, e enviar cada parte para o próprio campo. |
| **Which currency do you report in?** | Definir a moeda de relatório quando o projeto ainda não tem uma. Escreva-a com três letras, por exemplo `USD`. |
| **São resultados consolidados ou sua DRE reportada (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Carregar os resultados do seu sistema de consolidação para que a demonstração do resultado do grupo possa ser [reconciliada](#reconciliar-com-o-seu-sistema-de-consolidação). |

Para retirar um arquivo do projeto, clique em **Remover** ao lado dele em **Arquivos**, ou em **Remove this file** no mapeamento dele, e confirme. Os valores dele saem dos seus relatórios na próxima vez que você clicar em **Apply changes**.

Quando o PlaidCloud não consegue decidir sozinho o dataset, o separador decimal ou a ordem das datas, por exemplo em um arquivo cujas datas podem ser lidas como dia/mês ou mês/dia, ele pede que você escolha antes de confirmar. Adicionar um segundo arquivo para o mesmo dataset substitui o primeiro. Se as colunas de um arquivo posterior não corresponderem ao dataset, a carga informa o arquivo e as colunas e pede que você corrija o arquivo ou os nomes das colunas, ou defina o **Schema Mismatch** da etapa como `union`.

Os arquivos aceitos são arquivos de texto CSV, TSV e TXT, arquivos Excel `.xlsx` (lidos a partir da primeira planilha) e arquivos Parquet.

<Aside type="note">
Um arquivo ausente ou vazio nunca interrompe uma carga. Ao adicioná-lo, você é avisado de que ainda não há nada para mapear, e a carga termina com um aviso que informa o caminho. O dataset mantém as linhas que o arquivo lhe deu por último, se houver. Adicione o arquivo novamente quando ele existir.
</Aside>

### Registros de contratos

Um arquivo de contratos pode ser um registro de períodos de contrato ou os contratos em um fim de mês, por isso confirmar um pergunta **Cada linha é um período de contrato?**. A resposta proposta é **Sim, cada linha é um período de contrato** quando o arquivo tem uma data de início e nenhuma coluna de fim de mês. Um arquivo que você já confirmou mantém a resposta quando é adicionado novamente.

- **Sim, cada linha é um período de contrato**: cada linha é um período de um contrato, com a data de início, a data de término e o valor anual. Cada carga copia cada linha para todo fim de mês entre a data de início e a data de término, ou adiante enquanto a data de término estiver em branco, até o mês da carga ou o último mês do calendário da entidade, se for anterior. Um contrato assinado que começa depois conta a partir do início. Toda cópia é `Active`, exceto a cópia do mês da carga, que mantém o status da própria linha. Uma linha sem número de linha é numerada dentro do contrato dela.
- **Não, o arquivo contém os contratos no fim de um mês**: o arquivo é a cópia dos contratos de um fim de mês, como qualquer outro arquivo de contratos.

Uma linha sem data de início, uma linha cujo status diz que terminou mas que não tem data de término e uma linha que termina antes do último dia do primeiro mês dela não são períodos de contrato, e por isso são retidas. Consulte [Linhas retidas](#linhas-retidas). Os códigos de cliente e de produto de um registro são adicionados aos clientes e aos produtos, nomeados pelo código, a menos que outra origem dê um nome ao mesmo código. Os códigos de entidade dele só são adicionados quando nenhuma outra origem nomeia entidades.

## Carregar seus dados

Uma carga lê os sistemas conectados e os arquivos confirmados, padroniza-os no Common Finance Model, converte-os para a moeda de relatório, executa as verificações de prontidão e reconstrói os modelos. Um sistema adicionado com a respectiva conexão inicia sozinho a primeira carga. Antes de qualquer carga, **Carregar** também é a próxima etapa em **Resumo**. Depois disso, **Carregar** na linha de um sistema em **Sistemas** lê apenas esse sistema e depois padroniza, reconstrói e consolida com os dados de todos os sistemas, de modo que adicionar um sistema nunca lê os outros novamente. Enquanto a carga é executada, **Resumo** informa o que está sendo carregado.

- Apenas uma carga é executada por projeto de cada vez. Um segundo **Carregar** ou **Apply changes** avisa que já há uma carga em execução, e você não pode alterar as origens enquanto ela é executada.
- Se outros fluxos de trabalho usam a mesma conexão, a primeira carga os lista e pede que você confirme, porque uma carga lê do sistema e pode deixar esses fluxos de trabalho mais lentos. Clique em **Carregar mesmo assim** para continuar.
- Depois de uma atualização do PlaidCloud, o **Carregar** ou **Aplicar alterações** de um Arquiteto também atualiza os fluxos de trabalho gerados do projeto, criando as tabelas de trabalho de que precisarem. Quando há uma versão mais recente do modelo disponível, a barra acima de todas as páginas do Data Foundation mostra **Update available** e informa que o **Carregar** ou **Aplicar alterações** de um Arquiteto a instala. O **Carregar** de um Gerente avisa que apenas um Arquiteto pode atualizá-los.
- Aplicar uma atualização mantém as suas próprias edições nas etapas geradas. Se você alterou uma etapa e a atualização também a alterou, sua edição é mantida. Uma etapa que você editou e que a atualização não gera mais é mantida, mas desativada; exclua-a ou reative-a se ainda precisar dela. Uma etapa que a atualização substitui é indicada pelo nome, e a anterior permanece nas versões da etapa.
- Se uma atualização parou no meio do caminho, as etapas podem ser executadas fora de ordem até ela terminar. Pressione **Carregar** novamente como Arquiteto para concluí-la. Se ela parar de novo, entre em contato com o suporte.
- Um sistema que não é carregado mostra **Falhou** em **Sistemas**, com o motivo e a correção. Quando a última carga termina com um aviso, **Resumo** mostra **The last Load ended with a warning:** seguido do aviso.
- Se a leitura de uma entidade e período falhar, o restante ainda é carregado. Execute **Carregar** novamente para buscar apenas o que falhou.
- Se um dataset de uma origem falhar na leitura, o restante da origem ainda é carregado, esse dataset mantém as linhas que tinha, e o sistema mostra **Falhou** em **Sistemas** até que uma carga o leia.

### Linhas retidas

Quando as origens se sobrepõem, a carga conta cada valor uma só vez. As linhas que ela não conta são mantidas ou retidas.

As linhas mantidas permanecem no projeto, marcadas como não contadas, para que nada do que um sistema contém se perca e nada seja contado duas vezes. Uma linha é mantida quando está:

- em outro livro contábil, como um livro local ou fiscal, que a origem não está configurada para ler;
- fora dos meses **De** e **Até** definidos para a empresa dela;
- em uma empresa e um mês que outra origem conta, por exemplo o sistema de onde uma entidade foi transferida;
- substituída por um arquivo para aquela entidade e mês.

As linhas retidas são registradas com a origem, a entidade e o motivo, e a carga termina com um aviso que informa as quantidades, por exemplo `120 rows of NetSuite EU carrying a code another source also uses`. Os motivos são:

| Motivo | Significado |
|---|---|
| Também em um arquivo anterior da origem | Um arquivo anterior da mesma origem já cobre o mês. |
| Um saldo de abertura posterior | O saldo de abertura mais antigo da entidade e a movimentação desde então já são contados. |
| Com um código que outra origem também usa | O código precisa da sua resposta. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| Com um código mapeado para dois códigos | O mapa de códigos dá duas respostas para o código. |
| Com um código que o próprio cadastro não tem | A lista de contas, produtos ou clientes do próprio sistema não tem o código. |
| Totais de relatório ou linhas em branco | As linhas de total ou em branco de um arquivo. |
| Sem data de início, terminada sem data de término, ou terminando antes do último dia do primeiro mês, portanto não é um período de contrato | Uma linha de um registro de contratos que não é um período de contrato. Consulte [Registros de contratos](#registros-de-contratos). |

As contas estatísticas vão para os direcionadores de alocação, e não para o razão, e aparecem como movidas, não como um problema.

### Dados do ERP e arquivos juntos

Um arquivo substitui apenas o que cobre, e as demais linhas do ERP permanecem.

- **Arquivos mestres** (contas, departamentos, clientes, produtos e valores de segmento) substituem as linhas do ERP com o mesmo código.
- **Arquivos de transações** substituem as linhas do ERP para a mesma entidade e mês. Arquivos de razão geral e de balancete também correspondem por razão, arquivos de orçamento por cenário, e arquivos de direcionadores estatísticos por cenário e direcionador.

Se um arquivo deixar de cobrir um mês, os dados do ERP para esse mês voltam na próxima carga.

## Mapeamento de entidades

Cada origem identifica as entidades com os próprios códigos. Um arquivo **Mapa de códigos** associa esses códigos às entidades do seu cadastro de entidades, para que as linhas de todas as origens caiam na mesma entidade.

Para usá-lo, adicione um arquivo CSV ou Excel e escolha o dataset **Mapa de códigos**:

| Coluna | Contém |
|---|---|
| `source_code` | O código como a origem o registra, como um código de empresa. Uma coluna chamada `source_entity` também é associada a ele. |
| `code` | A entidade à qual pertence, com o nome usado no cadastro de entidades. Uma coluna chamada `entity` também é associada a ela. |

Cada linha mapeia um código de entidade, a menos que o arquivo tenha uma coluna `dimension` que indique outra coisa. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens).

- Um código que não está no mapa de códigos é usado como está.
- Vários códigos podem ser mapeados para uma entidade. As linhas deles são combinadas, e um mês conta como fechado quando estiver fechado para todos eles.
- As linhas do arquivo se aplicam a todas as origens, a menos que você escolha uma em **A qual fonte estas linhas se aplicam?**; portanto, limite o arquivo a uma origem quando duas origens usarem o mesmo código para entidades diferentes.
- Uma linha de arquivo de **Entidades** substitui a entidade do ERP com o mesmo código de entidade.

A verificação **Every entity known** sinaliza qualquer linha cuja entidade não esteja no cadastro de entidades nem mapeada para uma pelo mapa de códigos. Ela não se aplica até que um cadastro de entidades seja carregado.

## Mapear códigos entre origens

Dois sistemas podem usar o mesmo código para coisas diferentes, ou códigos diferentes para a mesma coisa. Quando você adiciona um sistema cujos códigos se sobrepõem aos de um sistema já conectado, o Data Foundation faz uma pergunta por assunto em vez de uma por código, por exemplo **Does SAP ECC use the same account codes as NetSuite?** Ele pergunta isso para contas, departamentos, centros de lucro, locais, produtos, clientes e cada categoria adicional.

Cada pergunta fica aguardando na página **Perguntas** com a resposta sugerida pelo Weave e as evidências que a sustentam, como quantos dos códigos compartilhados têm o mesmo nome, e informa quantas linhas ficam retidas até você responder. Responda **Same codes as** o outro sistema ou **Different codes from** ele.

- Até você responder, as linhas com os códigos compartilhados ficam retidas, para que cada valor seja contado uma só vez.
- Depois que você responde que um sistema usa os mesmos códigos, um código que aparecer depois como novo nele é considerado do outro sistema, sem nova pergunta.
- Os mapeamentos são mantidos por sistema e dimensão, então uma resposta sobre os departamentos de um sistema nunca altera as contas de outro.
- Uma resposta é aplicada no próximo **Carregar** ou **Aplicar alterações**, e **Histórico** em **Resumo** registra quem a deu, quando e o valor anterior.

Você também pode fornecer os mapeamentos em um arquivo. Adicione um arquivo com o dataset **Code map** e escolha **Which source do these rows apply to?** para limitá-lo a uma origem.

## Escolher qual origem vale a partir de quando

Quando uma entidade passa de um sistema para outro, os dois sistemas a contêm. **Perguntas** pergunta **From which month does** o novo sistema **count for** a entidade e sugere o mês seguinte ao último mês do razão do sistema anterior. O sistema anterior fica com os meses anteriores.

O cartão **Cobertura de fontes** em **Resumo** lista quaisquer outros meses que duas origens fornecem. Em **Problemas**, para duas origens que se sobrepõem em uma empresa, digite o mês em **Esse mês é**, por exemplo `2026-04`, escolha a origem em **Qual origem conta a partir desse mês?**, clique em **Salvar escolha** e depois clique em **Aplicar alterações** na barra acima da página. Até você escolher, apenas a primeira das duas é contada, e a outra origem fica com os meses anteriores ao que você digitar. **Requer atenção** explica as sobreposições contadas conforme descrito, como duas origens que fornecem taxas de câmbio diferentes para uma empresa, e informa de quem são as taxas usadas.

## Conversão de moedas

Cada carga converte os valores de razão geral, balancete, vendas, estoque, orçamento e razões auxiliares da moeda local para uma única moeda de relatório. Relatórios e modelos leem os valores convertidos, então entidades em moedas diferentes, de qualquer sistema, somam corretamente.

### A moeda de relatório

Para escolher a moeda de relatório, defina a variável de projeto `reporting_currency` com um código de moeda, como `USD`. Consulte [Gerenciar variáveis do projeto](/pt-br/guides/projects/managing-projects/#gerenciar-variáveis-do-projeto). Você pode, em vez disso, abrir **Ações ▾ > Configurações do projeto…** em **Resumo** e digitar o código em **Moeda de relatório**. O modelo a cria em branco. Enquanto ela estiver em branco, cada carga usa a primeira destas opções que indicar exatamente uma moeda:

1. A moeda do grupo das entidades.
2. A moeda local das entidades de nível superior, as que não têm pai.
3. A moeda local dos arquivos.

Se nenhuma delas indicar exatamente uma moeda, defina `reporting_currency` você mesmo.

Valores que já estão na moeda de relatório permanecem como estão, então um projeto cujos dados estão todos em uma moeda não precisa de taxas.

Arquivos de vendas, estoque e orçamento também podem ter uma moeda. Mapeie uma coluna chamada `Currency` ou `Local Currency` e ela será identificada automaticamente, e os valores locais do arquivo serão convertidos para a moeda de relatório. Um valor de grupo ou de relatório que já esteja no arquivo é mantido como está. O custo-padrão do cadastro de produtos já está na moeda do grupo e não é convertido.

### Taxas de câmbio

Uma taxa converte uma unidade de uma moeda para a moeda de relatório em um mês: o valor convertido é o valor local multiplicado pela taxa.

- **Do seu ERP**, cada carga lê as taxas de câmbio que o ERP mantém.
- **De um arquivo**, adicione um arquivo CSV ou Excel e escolha o dataset **Taxas de câmbio**. Uma taxa no arquivo substitui a taxa do ERP para as mesmas moedas e mês. Use um arquivo para gerar relatórios em uma moeda para a qual seus ERPs não publicam taxas, ou para acrescentar taxas planejadas para os meses do orçamento.

| Coluna | Contém |
|---|---|
| `from_currency` | A moeda de origem da conversão, por exemplo `EUR`. |
| `to_currency` | A moeda de relatório, por exemplo `USD`. |
| `period` | O mês, no formato `YYYY-MM`. |
| `average_rate` | A taxa média do mês. |
| `closing_rate` | A taxa no fim do mês. |
| `historical_rate` | A taxa histórica, para o patrimônio líquido e para contas configuradas com a taxa histórica. |

Quando uma moeda não tem taxa para a moeda de relatório, a taxa no sentido inverso, da moeda de relatório para ela, é invertida, com 12 casas decimais. Se isso não for possível, a taxa dela para outra moeda é multiplicada pela taxa dessa moeda para a moeda de relatório.

### Qual taxa se aplica

Cada linha é convertida a partir da própria moeda, então uma linha em uma moeda diferente da moeda da entidade é convertida a partir da moeda em que está. Aplica-se a primeira regra que se encaixa na linha:

| Linha | Taxa |
|---|---|
| Contas estatísticas e contas sem lançamento | Não convertidas. |
| Já na moeda de relatório | Não convertida. |
| Conta com um tipo de taxa | Essa taxa: média, de fechamento ou histórica. A histórica recorre à de fechamento quando não há taxa histórica. Em um ERP, o tipo de taxa é o próprio tipo de taxa da conta. Em um arquivo de plano de contas, mapeie uma coluna de tipo de taxa para `fx_rate_type` com `average`, `closing` ou `historical`. |
| Linha de vendas | A taxa média do período. |
| Saldo de estoque | A taxa de fechamento do período. |
| Fatura de fornecedor, pedido de compra, pagamento, pedido de venda, movimentação de ativo, movimentação de receita diferida, movimentação de estoque ou custo-padrão | A taxa média do período. |
| Conta a receber ou a pagar em aberto, valor em aberto de um pedido de venda, valor de um contrato ou saldo bancário | A taxa de fechamento do fim do mês em que está registrado. |
| Linha de orçamento | Por conta, como o razão geral: a taxa média para contas de resultado e a taxa de fechamento para contas patrimoniais. |
| Conta de resultado | A taxa média do período. |
| Conta de patrimônio líquido | A taxa histórica, ou a taxa de fechamento quando não há taxa histórica. |
| Qualquer outra conta patrimonial | A taxa de fechamento do período. |

Os valores convertidos não são arredondados, então os totais não se desviam.

As visões de pipeline `cfm_rv_pipeline_month`, `cfm_rv_won_booked` e `cfm_rv_campaign_window` convertem os valores ganhos, perdidos e criados das oportunidades pela taxa média do mês em que o negócio foi fechado ou criado. O pipeline em aberto de um mês usa a taxa de fechamento daquele mês ou, enquanto a taxa do próprio mês ainda não estiver carregada, a taxa de fechamento mais recente carregada para a moeda.

<Aside type="note">
O valor ganho, perdido ou criado de um negócio em moeda estrangeira fica de fora quando a moeda dele não tem taxa média para aquele mês, em vez de ser mostrado por outra taxa. O negócio continua sendo contado. O valor de um negócio ganho em moeda estrangeira fica fora de `cfm_rv_pipeline_month`, `cfm_rv_won_booked` e `cfm_rv_campaign_window` até que a taxa média do mês dele seja carregada, então os ganhos em moeda estrangeira do mês atual ficam faltando nos valores ganhos até lá. Adicione a taxa a um arquivo **Taxas de câmbio** ou verifique se a conexão consegue ler as taxas de câmbio do ERP e, em seguida, execute **Carregar** novamente.
</Aside>

<Aside type="note">
O razão geral e o balancete contêm as movimentações de cada período, então os valores patrimoniais deles são as movimentações de cada mês convertidas pela taxa daquele mês. O balanço patrimonial consolidado, por sua vez, converte saldos, pela taxa de fechamento do mês exibido, com a diferença em uma linha de diferença de conversão no patrimônio líquido. Consulte [Consolidação gerencial](#consolidação-gerencial).
</Aside>

## Hierarquias

Cada carga reconstrói as dimensões a partir dos dados mestres de todas as origens. Há sete dimensões de início e até dez categorias extras:

| Dimensão | Criada a partir de |
|---|---|
| **Entidade** | Entidades e seus pais |
| **Conta** | Plano de contas e contas pai |
| **Departamento** | Departamentos e seus pais |
| **Cliente** | Clientes e seus clientes pai |
| **Produto** | Produtos e seus produtos pai |
| **Segmento 1** | Valores de segmento para `segment_1` |
| **Segmento 2** | Valores de segmento para `segment_2` |
| **Segmento 3** a **Segmento 10** | Valores de segmento para `segment_3` a `segment_10`, quando suas origens os têm |

- Um registro sem pai, ou que indica a si mesmo como pai, é carregado como membro de nível superior.
- Como cada carga reconstrói as hierarquias, altere um pai no ERP ou no seu arquivo, não na dimensão.
- Um problema em uma hierarquia afeta apenas aquela dimensão. A carga e os modelos do modelo de projeto ainda são concluídos.
- Você pode renomear cada categoria adicional conforme o que ela contém, por exemplo **Classe** ou **Região**. Abra **Ações ▾ > Configurações do projeto…** em **Resumo**, digite os nomes que seus relatórios usam em **Nomes** em **Configurações do projeto** e clique em **Salvar**. Os nomes usam letras, números, espaços, pontos, hifens e sublinhados, com até 60 caracteres.
- Cada origem informa em qual dos seus nomes de categoria entra cada uma das categorias adicionais dela. Em **Sistemas**, clique em **Editar** na origem, escolha o nome para cada uma em **Categorias adicionais nesta fonte**, ou escolha **Deixar de fora**, e clique em **Salvar**. Origens que chamam uma categoria por nomes diferentes, como `Class` e `Business area`, passam a compartilhar uma posição.

Para fornecer hierarquias de segmento a partir de um arquivo, escolha o dataset **Valores de segmento**:

| Coluna | Contém |
|---|---|
| `segment` | O segmento ao qual o valor pertence: `segment_1` a `segment_10`. |
| `segment_value` | O valor, como as linhas de razão geral, vendas e orçamento o registram. |
| `segment_value_name` | O nome dele. |
| `parent_segment_value` | O pai dele dentro do mesmo segmento. |

## Verificações de prontidão

Estas verificações são o detalhamento das cinco garantias em **Resumo**; consulte [Os números são confiáveis?](/pt-br/guides/projects/data-foundation-proof/).

Cada **Carregar** e cada **Aplicar alterações** as executa para cada entidade e período, e cada verificação conta em uma das cinco garantias. Uma verificação que falha fica vermelha. Um alerta fica âmbar: algo a examinar que não compromete os valores. No painel **CFM-Accounting - Close and assurance**, a guia **What needs fixing** mostra **Every check, by system, month chosen**, com o número de itens vermelhos de cada verificação para cada sistema, em que zero significa nada a corrigir. A tabela de itens a corrigir do mês escolhido, do maior para o menor, cita cada item vermelho e informa o que fazer, como carregar o plano de contas, carregar taxas de câmbio ou executar **Carregar** novamente. Consulte [Painéis, métricas e caminhos de análise](/pt-br/guides/projects/data-foundation-dashboards/).

As principais verificações são:

| Verificação | Em | O que confirma |
|---|---|---|
| **Every month loaded** | **Nada se perdeu no caminho** | Todo período fiscal tem linhas de razão geral, e todas as leituras do ERP foram bem-sucedidas. Um período fechado sem linhas falha; um período aberto sem nenhuma é um alerta. |
| **Trial balance equals the ledger** | **Equilibrado com cada sistema** | O balancete é igual ao razão geral para cada entidade, período e conta. Quando tanto o balancete quanto o razão geral têm departamentos para uma conta, os totais também batem por departamento. |
| **Sales equal the ledger** | **Nada se perdeu no caminho** | As linhas de vendas são iguais às contas de receita e de CMV do razão geral em cada período. |
| **Every product and customer of a sale known** | **Nada se perdeu no caminho** | Toda linha de vendas indica um produto e um cliente que existem nos cadastros de produtos e de clientes. |
| **Every account known** e **Every account typed** | **Nada se perdeu no caminho** | Toda linha de razão geral indica uma conta do plano de contas. Linhas com uma conta desconhecida ficam de fora da demonstração do resultado. Uma conta com lançamentos, mas sem tipo de conta, também falha, e uma origem cujo plano classifica contas de receita, mas nenhuma conta de custo das mercadorias vendidas, é um alerta. |
| **Every amount has a rate** | **O grupo fecha** | Toda linha de razão geral, balancete, vendas, estoque e orçamento tem um valor na moeda de relatório. Uma linha de resultado ou de vendas sem taxa falha, porque a demonstração do resultado lê valores convertidos. Uma linha patrimonial, de estoque ou de orçamento sem taxa é um alerta; por isso, carregue taxas planejadas para os meses do orçamento. Consulte [Conversão de moedas](#conversão-de-moedas). |
| **Every entity known** | **Nada se perdeu no caminho** | Toda linha de razão geral, balancete e vendas indica uma entidade do cadastro de entidades, diretamente ou mapeada para uma em um arquivo **Mapa de códigos**. Não se aplica até que um cadastro de entidades seja carregado. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |

Estas verificações só são levantadas quando requerem atenção, todas em **Nada se perdeu no caminho**:

| Verificação | O que confirma |
|---|---|
| **Reporting book chosen** | Uma origem que tem vários livros contábeis para uma entidade teve o livro de relatório escolhido. Até você escolher, apenas o primeiro livro conta. |
| **Codes mapped** | Todo código usado por mais de uma origem foi respondido. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| **One source for each key** | Duas origens nunca fornecem os mesmos meses de uma empresa, a menos que você tenha escolhido qual vale. |
| **Hierarchies complete** | Todo pai indicado por uma dimensão existe, e nenhum membro é o próprio pai ou ancestral. Um pai ausente coloca os filhos dele no topo da hierarquia, e um ciclo impede o carregamento daquela hierarquia. Os totais não são afetados. |
| **Months placed in the fiscal calendar** | Os períodos fiscais de cada entidade são meses do calendário, e cada mês de linhas pode ser colocado em um período fiscal. É um alerta quando os períodos de uma entidade não são meses do calendário (4-4-5, 13 períodos), ou quando as linhas de um mês podem estar em mais de um período fiscal ou o calendário fiscal não tem o mês. |

Duas verificações de configuração só são levantadas quando requerem atenção. Uma é levantada quando apenas uma das variáveis de projeto `overhead_department` e `overhead_driver` está definida, ou nenhum direcionador de alocação corresponde a `overhead_driver`, de modo que a alocação de custos indiretos não faria nada: defina as duas ou limpe as duas para desativar a alocação de custos indiretos. A outra é levantada quando há linhas de orçamento carregadas, mas nenhuma está na **Versão do orçamento** das configurações do projeto (a variável de projeto `budget_version`), de modo que a comparação com o orçamento ficaria vazia.

## Consolidação gerencial

Cada carga monta uma consolidação gerencial: a demonstração do resultado, o balanço patrimonial e o fluxo de caixa de todas as entidades do grupo, na moeda de relatório, com as operações intercompanhia eliminadas. Ela se destina a relatórios gerenciais. Seu sistema de consolidação continua sendo o registro oficial do grupo para fins societários; faça a reconciliação com ele conforme descrito abaixo.

Onde quer que os valores consolidados apareçam, eles levam o rótulo **Management consolidation**: ao lado da primeira linha de **Resumo**, na linha de contexto no topo de cada painel e na coluna **Basis** do pacote para a diretoria, cuja coluna **Basis note** diz "Entities combined, intercompany eliminated, translated to the reporting currency. Not a statutory consolidation." Um projeto com uma só entidade não mostra rótulo.

<Aside type="note">
A consolidação gerencial não é uma consolidação societária ou legal. Ela não elimina investimentos contra o patrimônio líquido e não tem ágio nem participação de não controladores.
</Aside>

### Escolher o grupo

Em **Resumo**, o cartão **O grupo** mostra a moeda de relatório. Clique em **Alterar**, ou abra **Ações ▾ > Configurações do projeto…** em **Resumo**, para abrir **Configurações do projeto**, onde **Acesso por grupo e linha** lista as **Empresas do grupo**. Uma empresa que você desmarcar continua nos seus relatórios individualmente, mas fica de fora do total do grupo. Clique em **Salvar**. A alteração se aplica no próximo **Carregar** ou **Aplicar alterações**. Uma empresa nova fica no grupo até você desmarcá-la.

O exercício fiscal do grupo começa no mês definido pela variável de projeto `group_fy_start_month`. Enquanto ela estiver em branco, o que acontece a menos que você a defina, o exercício fiscal do grupo começa no mês em que começa o exercício fiscal da entidade de nível superior, a única entidade sem pai, ou em janeiro quando a entidade de nível superior não tem calendário fiscal. Quando mais de uma entidade não tem pai, ou a entidade de nível superior é um nó de hierarquia sem calendário fiscal próprio, ele começa em janeiro e a consolidação aparece em âmbar até você definir o mês.

### O que você obtém

| Tabela | Contém |
|---|---|
| **DRE do grupo** | Uma linha por entidade, período e linha de resultado (receita, custo das mercadorias vendidas, despesas operacionais, não operacional, diferença intercompanhia), na moeda de relatório. Receitas e custos mantêm o sinal natural. |
| **DRE do grupo acumulada no ano** | O mesmo, acumulado no ano, até o último período totalmente carregado do grupo. |
| `group_statements` | A demonstração do resultado, o balanço patrimonial e o fluxo de caixa como exibidos, linha a linha, com todos os subtotais e totais, para cada entidade, as eliminações e o grupo, na moeda de relatório. Receitas, ativos e entradas de caixa são positivos. Cada linha tem o valor do mês e o acumulado do exercício fiscal do grupo até esse mês; uma linha do balanço patrimonial tem o saldo do mês. |
| `group_result` | As mesmas três demonstrações por entidade, linha, conta e mês, em todos os livros de relatório, na moeda de relatório e, para uma entidade em outra moeda, também na moeda dela. Os valores são positivos a débito, como no razão geral. |
| **Pares intercompanhia** | Uma linha por par de entidades, grupo e período, com o valor de cada lado e o resíduo. |
| **Linhas intercompanhia** | As linhas do razão por trás de um valor do grupo ou de um par, com o parceiro comercial. |
| **Reconciliação** | A DRE do grupo acumulada no ano comparada com o seu sistema de consolidação. |

Três nomes de entidade aparecem nestas tabelas:

| Entidade | Significado |
|---|---|
| **Eliminations** | As eliminações intercompanhia. Elas se anulam, então mantenha-as para os valores do grupo e filtre-as para obter a soma das entidades antes da eliminação. |
| **Group total** | O total do sistema de consolidação, na reconciliação. |
| **Unmapped** | Linhas sem período, e contas ou entidades do seu sistema de consolidação que este projeto não tem. |

As métricas **Consolidated income**, **Consolidated result** e **IC difference** leem a **DRE do grupo**. Elas e um caminho de análise para cada uma das tabelas **DRE do grupo**, intercompanhia e de reconciliação respondem a perguntas sobre o grupo. O painel **CFM-Finance - Statements** e o pacote para a diretoria mostram as três demonstrações.

#### As três demonstrações

- **Demonstração do resultado**: cada mês pela taxa média daquele mês.
- **Balanço patrimonial**: o saldo de cada conta é o saldo de abertura mais a movimentação até o mês. Os saldos ficam pela taxa de fechamento do mês exibido, e o patrimônio líquido pela taxa histórica, ou pelo tipo de taxa da própria conta quando ela tem um. Uma conta de patrimônio líquido sem taxa histórica fica pela taxa de fechamento. O resultado de exercícios fiscais anteriores fica em lucros acumulados, e o deste ano em lucros do exercício corrente, cada um pelas taxas médias dos próprios meses.
- A diferença de conversão é uma linha no patrimônio líquido para cada entidade, calculada como o patrimônio líquido e o resultado dela pela taxa de fechamento menos o valor convertido. É o que faz um balanço patrimonial convertido fechar, nunca um valor de ajuste. Quando uma entidade em outra moeda não tem taxa de fechamento para um mês, o balanço patrimonial dela não é convertido nesse mês e não fecha, e a consolidação aparece em âmbar, citando a entidade e o mês. Carregue a taxa e depois execute **Aplicar alterações**.
- **Fluxo de caixa**: calculado a partir da movimentação de cada conta do balanço patrimonial no mês, pela função da conta, à taxa média do mês. Uma linha de efeito das taxas de câmbio contém a parte da variação do caixa, a taxas de fechamento, que decorre da variação das taxas. Uma conta do balanço patrimonial sem função fica na linha de outras variações.
- As **Funções das contas** respondidas em **Perguntas** posicionam as contas nas linhas. **Comissões** é uma linha própria das despesas operacionais. **Notas conversíveis e SAFEs** é uma linha do passivo, e a variação dela fica em financiamento no fluxo de caixa; uma conta do patrimônio líquido com essa função permanece no patrimônio líquido. Uma conta de despesa com nome de comissão recebe a sugestão **Comissões**; uma conta do passivo ou do patrimônio líquido com nome de nota conversível, de SAFE ou de um simple agreement, **Notas conversíveis e SAFEs**; e uma conta com nome de empréstimo de acionista, empréstimo de sócio ou empréstimo de uma pessoa, **Empréstimos**, mesmo quando o nome dela também diz a pagar. Uma conta de despesa com nome de prestador de serviços recebe a sugestão **Pessoal**.

O balanço patrimonial termina com uma linha de verificação, ativos menos passivos e patrimônio líquido, e o fluxo de caixa com a variação do caixa menos a movimentação das contas de caixa. As duas são zero quando a demonstração está correta. Consulte [Os números são confiáveis?](/pt-br/guides/projects/data-foundation-proof/) para ver as garantias que as comprovam.

### Eliminações intercompanhia

As linhas intercompanhia são correspondidas pelo parceiro comercial. É usado o parceiro da linha; quando a linha não tem um, é usado o parceiro do cliente dela. Os dois lados de um par são eliminados, e o valor pelo qual os dois lados não batem é lançado em uma linha de diferença intercompanhia. Cada par recebe um motivo:

| Motivo | Significado |
|---|---|
| **Correspondente** | Os dois lados lançaram o mesmo valor. |
| **Apenas um lado lançou** | Uma entidade lançou a transação e o parceiro dela não. |
| **Não eliminado** | Uma linha do par não tem taxa de câmbio, então nenhum dos lados é eliminado. |

Um par é avaliado pelo acumulado no ano. A verificação intercompanhia fica âmbar quando a diferença de um par passa da variável de projeto `group_amber` (padrão `1`) e vermelha acima de `group_red` (padrão `1000`), que é a **Tolerância entre empresas** em **Configurações do projeto** (não é exibida enquanto o grupo tiver só uma empresa). Linhas sem parceiro, ou com um parceiro que não é uma entidade, não são eliminadas e são contadas nessa verificação. Uma origem que tem parceiros ao lado de outra que não tem aparece em âmbar.

As entidades de eliminação da própria origem ficam fora da DRE do grupo, e a verificação de consolidação informa isso.

Nas três demonstrações, as contas a receber e a pagar intercompanhia são eliminadas por par, assim como as receitas e os custos intercompanhia. O valor pelo qual os dois lados de um par não batem fica na linha de diferença intercompanhia da demonstração do resultado ou do balanço patrimonial, para que o balanço patrimonial do grupo continue fechando, e a movimentação dele fica na linha de variação dos saldos intercompanhia do fluxo de caixa. Cada linha de eliminação traz as duas entidades e o país, a região e a divisão que elas compartilham, de modo que uma divisão, um país ou uma região elimina apenas os pares cujas duas entidades estão dentro dela, e o grupo elimina todos os pares.

### Reconciliar com o seu sistema de consolidação

Adicione como arquivo os resultados que o seu sistema de consolidação informa e marque **São resultados consolidados ou sua DRE reportada (OneStream, Anaplan, SAP Group Reporting, FCCS)** ao confirmar o mapeamento. Responda a **Qual versão dos números é esta?** com o nome do sistema. A tabela **Reconciliação** passa então a mostrar **nosso**, **reportado** e **diferença** para cada entidade e linha, no acumulado do ano. Uma diferença normalmente é explicada nas linhas **Eliminations**, **Group total** e **Unmapped**, ou pelas taxas de câmbio que o sistema usa. A verificação de reconciliação lista cada linha acima de `group_amber`.

### Quem pode ver

Os resultados do grupo seguem o acesso às linhas do projeto. Quando o acesso às linhas bloqueia os resultados do grupo, a verificação de consolidação aparece em âmbar. Uma pessoa que vê apenas algumas entidades vê as somas dessas entidades antes da eliminação, e **Resumo** informa isso a ela: "Estes números abrangem apenas as entidades às quais você tem acesso, não a empresa inteira." As linhas **Eliminations** e as tabelas intercompanhia exigem acesso a todas as entidades.

**Restringir linhas por entidade**, em **Acesso por grupo e linha**, limita um grupo com permissão para determinadas entidades às linhas dessas entidades, em todas as tabelas com uma coluna de entidade. Só um Arquiteto vê essa opção. Marcar ou desmarcar **Restringir** se aplica na hora e é recusado enquanto o acesso às linhas estiver desativado para o espaço de trabalho. Desmarcá-la enquanto houver grupos com permissões de entidade pergunta primeiro **Remover as permissões de entidade?**; clique em **Desativar** para continuar.

Se o projeto limita quem vê quais linhas por uma coluna que as tabelas do grupo não têm, como departamento, os resultados do grupo ficam desativados para todos e a verificação de consolidação mostra **Group views are off**. Nesse caso, apenas um Arquiteto pode marcar **Todas as pessoas do projeto podem ver os resultados do grupo** em **Acesso por grupo e linha** e clicar em **Salvar**; os demais não veem a caixa. A alteração se aplica no próximo **Carregar** ou **Aplicar alterações**.

## Manter atualizado

Quando uma carga termina e nenhuma pergunta que retém linhas está pendente, a próxima etapa em **Resumo** é **Manter atualizado** até que **Atualizar**, em **Configurações do projeto**, seja **Diário**, **Semanal** ou **Mensal**. Há duas formas de agendar o **Carregar**:

- **Ações ▾ > Atualizar toda noite**, em **Resumo**, executa **Carregar** todas as noites às 02:00 UTC.
- Abra **Ações ▾ > Configurações do projeto…** em **Resumo**. Em **Atualizar**, escolha **Diário**, **Semanal** ou **Mensal** e defina **Horário da atualização (UTC)**, escrito como horas e minutos, como `02:00`. Para **Semanal**, **Dia da atualização** vai de 1 (segunda-feira) a 7 (domingo); para **Mensal**, é o dia do mês. Clique em **Salvar**. **Sob demanda** remove o agendamento.

Um agendamento pode ser configurado depois que uma carga com uma origem termina sem verificações vermelhas; por isso, um projeto que tem apenas dados de exemplo não pode ser agendado. Se você vê apenas algumas das entidades do projeto, um Arquiteto o configura. Quando um agendamento não pode ser configurado, o motivo é exibido. Enquanto **Atualizar** for **Diário**, **Semanal** ou **Mensal**, a página **Sistemas** mostra quando está prevista a próxima atualização de cada sistema; consulte [O quão atualizado está cada sistema](/pt-br/guides/projects/data-foundation-proof/#o-quão-atualizado-está-cada-sistema). **Atualizar toda noite** mantém **Atualizar** como está, então nenhuma próxima atualização é exibida e **Manter atualizado** continua sendo a próxima etapa.

A carga agendada é executada como a pessoa que a configurou. Se essa pessoa não puder mais usar a conexão de um sistema, a carga é ignorada com um aviso que cita a pessoa e a conexão; configure o agendamento novamente.

Um arquivo ausente ou vazio em uma carga agendada termina com um aviso que informa o caminho, não com um erro, e o restante do modelo ainda é carregado.

## Nomes de negócio

Os **Nomes de negócio** dão aos códigos do seu modelo os nomes que a sua empresa usa. Relatórios, métricas e o Ask mostram esses nomes, e um nome salvo se aplica imediatamente. As cargas posteriores o mantêm. Abra **Ações ▾ > Configurações do projeto…** em **Resumo**; **Nomes de negócio** fica no cartão **Nomes** de **Configurações do projeto**.

1. Clique em **Adicionar um nome** e escolha o **Tipo**: **Categoria**, **Linha da DRE**, **Métrica**, **Coluna**, **Entidade** ou **Conta**.
2. Digite o **Código**: `segment_1` a `segment_10` para uma categoria, a chave da linha para uma linha da DRE, o nome da métrica, `table.column` para uma coluna, ou o código de uma entidade ou conta.
3. Digite o **Nome**, com no máximo 60 caracteres em uma linha.
4. Clique em **Salvar**. A caixa de diálogo fecha quando tudo nela está salvo; um nome recusado é informado abaixo da grade, e a caixa de diálogo permanece aberta.

Salvar substitui a lista inteira. Uma linha com nome vazio remove aquele nome, e **Remover selecionados** remove as linhas que você marcar. Nomear o mesmo código duas vezes é recusado. Os nomes de negócio também são gravados na descrição do caminho de análise para que o assistente use as suas palavras, e essa descrição tem um limite de tamanho: se um nome a deixar longa demais, nada é salvo e você é avisado.

## Classes de receita e funções das equipes

As classes de receita são os tipos de receita que a sua empresa vende, como SaaS ou BPO, e a função de uma equipe diz para que serve o custo dela. O painel [CFM-Executive - Growth and efficiency](/pt-br/guides/projects/data-foundation-dashboards/#crescimento-e-eficiência) lê ambas.

**Classes de receita** em **Configurações do projeto** lista as classes, cada uma com um nome e um tipo: **Assinatura**, **Suporte e manutenção**, **Serviço gerenciado**, **Implementação**, **Consultoria e serviços profissionais** ou **Outro**. Os três primeiros tipos são recorrentes. Um projeto começa com uma classe de cada tipo, com o nome dele. Abra **Ações ▾ > Configurações do projeto…** em **Resumo**. Clique em **Adicionar** para uma nova classe, renomeie uma classe ou mude o tipo dela, ou clique em **Remover**, e depois clique em **Salvar**.

- Toda classe precisa de um nome, com no máximo 60 caracteres, e duas classes não podem ter o mesmo nome. Um nome não pode conter aspas simples, barra invertida nem chaves, e "Shared", "Not yet classed" e "Intercompany removed" são reservados para os relatórios.
- Renomear uma classe ou mudar o tipo dela mantém todas as respostas dadas com ela. Os painéis mostram a alteração após o próximo **Carregar** ou **Aplicar alterações**.
- Remover uma classe pergunta de novo sobre cada conta e cada produto respondido com ela.

**Perguntas** pergunta sobre a classe e a função em **Classes de receita das contas**, **Classes de receita dos produtos** e **Funções das equipes**:

- **Qual é a classe de receita da conta …?** para cada conta de receita e de custo da receita em que o razão lança e que não tem classe, uma pergunta por conta, nunca uma para uma conta pai e as contas dela em conjunto. Uma conta de custo da receita também pode ser **Compartilhado por todas as classes**: o custo dela é distribuído pelas classes conforme a participação de cada classe na receita dos 12 meses até cada mês.
- **Qual é a classe de receita do produto …?** para cada produto de um contrato que não tem classe. A classe de um produto divide a receita recorrente por classe; toda linha de contrato conta na receita recorrente anual, qualquer que seja a classe.
- **Qual é a função do departamento … de …?** para cada departamento em que o razão lança, ou **Qual é a função do centro de lucro … de …?** para cada centro de lucro quando o sistema dele não tem departamentos, como uma Class do QuickBooks Online. A resposta é **Custo da receita**, **Vendas e marketing**, **Pesquisa e desenvolvimento** ou **Geral e administrativo**, e as equipes de cada sistema são perguntadas separadamente.

A sugestão vem do nome: uma conta ou um produto com nome de assinaturas, SaaS ou manutenção, por exemplo, recebe a sugestão de uma classe desse tipo; uma palavra depois de "non-" não conta, então "Non-recurring" não sugere nenhuma classe recorrente. Uma conta de receita cujo nome não a coloca em nenhuma classe recebe a sugestão de uma classe do tipo **Outro**, ou de outra classe que não é recorrente, e uma conta de custo da receita, **Compartilhado por todas as classes**. Um produto só recebe sugestão quando o nome dele o coloca em uma classe. Uma equipe recebe a sugestão de uma função pelo nome, como **Vendas e marketing** para uma equipe de vendas ou de marketing, ou então **Geral e administrativo**.

Essas perguntas não retêm nada: não deixam o projeto âmbar e nunca são a próxima etapa em **Resumo**. Enquanto uma conta não é respondida, a receita dela é "Not yet classed" e não conta como recorrente; um produto ainda não respondido continua contando na receita recorrente anual, como "Not yet classed". O painel nomeia o que ainda não foi respondido abaixo dos números que isso afeta.

## Explicar um número

**Explicar este número** mostra o que compõe um valor. Depois que um mês é carregado, **Resumo** mostra o lucro líquido do ano até o último mês completo, com **Explicar este número** ao lado. Isso abre **Explain: Net income**, com o valor do ano até esse mês no topo e, em seguida, o que o compõe, cada lista do maior para o menor:

| Lista | O que contém |
|---|---|
| **Linhas** | As linhas da demonstração que somam o valor. |
| **Entidades** | A parcela de cada entidade. Em um grupo, as eliminações são uma delas. |
| **Contas** | A parcela de cada conta. |

Cada lista mostra os dez maiores e o restante como um único item, como **Other accounts (12)**, de modo que toda lista soma o valor. Um nome que é um link abre a própria explicação, apenas para aquela linha, entidade ou conta. **Maiores documentos** lista os dez maiores documentos do razão por trás do valor, com **Sistema**, **Entidade**, **Documento**, **Lançado**, **Conta**, **Descrição** e **Valor**, e **Exportar todos os documentos** baixa todos eles. **Perguntar ao Weave por que mudou** pergunta ao Weave por que o valor mudou no ano até esse mês e quais entidades, contas e documentos o movimentaram.

A janela segue o seu acesso às linhas: você só explica os valores que pode ver. Uma tabela que ainda não existe gera um aviso, não um erro. Um número sem nada por trás mostra **Nada a explicar**.

## Regras de alocação

As alocações distribuem custos compartilhados, como custos indiretos, para departamentos, produtos e clientes. O modelo tem duas fases: **Etapa 1: despesas gerais para departamentos** e **Etapa 2: departamentos para produtos e clientes**. Em um projeto criado com uma solução, clique em **Alocações** no grupo **Data Foundation** da barra lateral **Início**. Isso abre **Regras de alocação**, onde você vê ou altera como cada uma é feita. Sem alterações, elas funcionam como antes de o assistente existir. Um leitor pode abrir as regras, mas não salvá-las.

Para cada fase, o assistente faz quatro perguntas:

| Etapa | Pergunta | Opções |
|---|---|---|
| **Conjunto** | Quais custos você quer distribuir? | O tipo de conta e, na fase 1, o departamento que contém o custo, ou **All departments**. |
| **Direcionador** | Por qual critério você quer distribuí-los? | **Statistic** que você carregou como direcionadores de alocação, como número de funcionários ou metros quadrados, **Net sales amount**, **Sales quantity** ou **Spread evenly**. Use o direcionador de **Same period** ou **Same period last year**. |
| **Destino** | Para onde eles vão? | Fase 1: departamentos. Fase 2: produtos, clientes ou ambos. |
| **Método** | O que acontece quando um direcionador é negativo? | **Ignore negative values** ou **Stop and tell me**. |

Abaixo das etapas, **Preview for** um mês, escrito como ano e mês, por exemplo `2026-09`, mostra o que as regras, inclusive as que você ainda não salvou, fariam: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Qualquer valor não alocado é custo que não teve direcionador para recebê-lo. A pré-visualização segue o seu acesso às linhas.

Um nome de departamento ou de estatística não pode conter aspas simples (`'`), barra invertida nem quebra de linha, porque o nome é escrito nos filtros das etapas de alocação. **Salvar** e uma prévia do estágio 1 recusam um nome assim e o informam.

Clique em **Salvar**. As regras entram em vigor no próximo **Carregar** ou quando você clicar em **Apply changes**. Se você editou uma etapa de alocação manualmente, sua edição é mantida, não sobrescrita, e o salvamento a indica pelo nome. Não é possível salvar enquanto uma carga está em execução.

## Pacote para a diretoria

Um pacote para a diretoria grava seus resultados em uma pasta de uma conta de documentos, pronto para enviar. Na página **Relatórios**, clique em **Configurações do pacote para a diretoria** no cartão **Pacote do conselho**, escolha uma **Conta de documentos** e uma **Pasta**, como `/board-packs`, e clique em **Salvar**. A partir daí, cada **Carregar** gera o pacote, então os arquivos da pasta estão tão atualizados quanto a última carga. Cada execução grava:

- Uma pasta de trabalho do Excel, `Board pack.xlsx`, com as planilhas **Profit and loss**, **Balance sheet** e **Cash flow**: cada mês e cada linha por entidade, com as eliminações e o total do grupo. Um projeto com uma só entidade não tem linhas de eliminações nem do grupo.
- Um PDF do painel **CFM-Finance - Statements**.

Quando esse painel estiver criado, **Abrir o pacote para a diretoria** no mesmo cartão o abre.

Clique em **Executar agora** para gerar um pacote imediatamente; os arquivos dele aparecem na pasta quando termina. A caixa de diálogo mostra a última execução e o resultado dela, e a próxima execução. **Aplicar alterações** não gera um pacote. Para gerar um pacote por agendamento, agende o **Carregar** (consulte [Manter atualizado](#manter-atualizado)); até lá, a caixa de diálogo mostra **Ainda não agendado. Cada carregamento gera o pacote do conselho: configure a atualização noturna para gerá-lo todas as noites.** Apenas quem pode alterar o projeto pode configurá-lo.

Um pacote que não pode ser gerado por completo nunca faz a carga falhar:

- Se os relatórios estiverem desativados no seu espaço de trabalho, o pacote contém apenas a pasta de trabalho do Excel, e a execução mostra **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- Se um painel criado por outra pessoa já tiver o endereço de que o Data Foundation precisa para o painel das demonstrações, esse painel é mantido como está e o PDF não é gerado. A mensagem informa o endereço; dê outro endereço ao outro painel no Superset e execute **Carregar** novamente.
- Se alguma etapa do pacote falhar, a última execução na caixa de diálogo mostra **falhou**. A carga em si foi bem-sucedida.

## Pontos de restauração

Um ponto de restauração é criado no início de cada **Carregar** ou **Apply changes**, seja quem for que o inicie, inclusive uma carga agendada, e antes de cada alteração em mapeamentos ou origens. Ele contém as tabelas do modelo, as dimensões e as configurações a partir das quais a próxima carga é feita: suas origens, arquivos e regras de alocação. São mantidos os últimos sete pontos criados para cargas e os últimos cinco criados antes de alterações, então as alterações nunca descartam os pontos criados para cargas. Os pontos mais antigos são descartados.

Para voltar, abra **Ações ▾ > Restaurar…** em **Resumo**. Cada ponto mostra quando foi criado e, abaixo, quantas tabelas a restauração traz de volta, por exemplo **Puts back 12 tables.** e, em uma nota, o que ela mantém como está. Escolha um ponto e clique em **Restaurar**. **Restaurar** fica disponível quando existe um ponto. A restauração primeiro registra o projeto como está agora em um ponto próprio, para que você possa voltar novamente. Depois, ela devolve as tabelas, as dimensões e essas configurações ao estado anterior, e a próxima carga parte delas. Restaurar para as origens que você já tinha não as marca como alteradas. Restaurar para um ponto criado antes de uma origem de conector ou de arquivo ser adicionada remove as tabelas que essa origem carregou, e um aviso informa a origem. Se você desfizer a restauração, o Carregar traz de novo as tabelas de uma origem de conector e, no caso de uma origem de arquivo, você confirma o arquivo novamente. Se não for possível remover as tabelas de uma origem, um aviso informa que elas permanecem na pasta da origem até você excluí-las manualmente, e o restante é restaurado mesmo assim. Uma visão, uma dimensão que não pode ser salva ou uma tabela sem cópia salva é indicada em um aviso, e o restante é restaurado. Um ponto de restauração já descartado é recusado, e não é possível restaurar enquanto uma carga está em execução.

## Clonar um projeto

**Ações ▾ > Clonar…**, em **Resumo**, copia o projeto com um nome que você informa. A cópia mantém o modelo de projeto, suas edições no modelo e suas métricas e caminhos de análise, e carrega os dados de exemplo. As origens dela não ficam conectadas, então conecte-as na cópia antes de carregar. Você pode continuar trabalhando enquanto a cópia é feita, e **Abrir projeto** leva você até ela quando estiver pronta.

## Salvar como meu modelo

Salve a configuração de um projeto para reutilizá-la com o próximo cliente ou entidade. Abra **Ações ▾ > Salvar como meu modelo…** em **Resumo**, escolha a conta de documentos e dê um nome ao arquivo. Se você não incluir `.zip` no final do nome, ele é acrescentado. Salvar sobre um arquivo existente é recusado, então escolha outro nome.

O arquivo contém a estrutura do projeto, suas edições no modelo, métricas e caminhos de análise, os nomes de negócio de entidades e contas, e as linhas das tabelas de configuração do modelo de projeto, como o mapa de atividades do [Cost to Serve](/pt-br/guides/projects/cost-to-serve/) ou as faixas da política do [Operational Transfer Pricing](/pt-br/guides/projects/operational-transfer-pricing/). Ele deixa de fora conexões, arquivos, o agendamento noturno, execuções, pontos de restauração, o pacote para a diretoria e quem tem acesso.

Para usá-lo, crie um projeto, escolha **A partir de um arquivo de modelo** em **Começar de** e selecione a conta de documentos e o caminho. O novo projeto é privado para você, com todas as origens aguardando conexão. Uma versão posterior do modelo mescla as alterações dela ao redor das etapas que você editou. Se não houver arquivo no caminho, nada é criado e você é avisado. Qualquer pessoa que possa ler a conta de documentos pode instalar a partir do arquivo. Para usá-lo em outro espaço de trabalho, baixe o arquivo e envie-o lá.

## Resolver perguntas em aberto com o Ask

Depois de uma carga, um projeto ainda pode estar aguardando três informações: contas que o plano deixa sem tipo, códigos usados por mais de uma origem e colunas dos seus arquivos que não corresponderam a nada. Peça ao assistente para resolvê-las: em um assistente de IA via MCP, use o prompt **Resolve Data Foundation residue**. Ele lê o que está pendente e propõe uma resposta para cada item, com um motivo.

O assistente não grava nada. O chat do Weave AI também pode informar o que um projeto está aguardando (consulte [Chat do Weave AI](/pt-br/guides/ai-assistant/weave-tab/#data-foundation)), e um agente conectado por MCP pode ler e responder às perguntas por conta própria (consulte [Data Foundation com um agente de IA conectado por MCP](/pt-br/integrations/ai-coding-agents/data-foundation/)). Você aplica as respostas dele onde você mesmo teria respondido: contas e códigos na página **Perguntas**, e colunas de arquivo no mapeamento do arquivo. Ele nunca propõe uma entidade. Uma pergunta em **Perguntas** já pode trazer a sugestão do próprio Weave; consulte [As páginas do Data Foundation](#as-páginas-do-data-foundation).

## Entregar o projeto

Quando o projeto é configurado para outra pessoa, como um cliente, termine com estas etapas:

- **Mantenha-o atualizado.** Agende o **Carregar**. Consulte [Manter atualizado](#manter-atualizado).
- **Compartilhe-o.** Dê acesso à equipe na página **Acesso e compartilhamento** do projeto. Consulte [Gerenciar o acesso ao projeto](/pt-br/guides/projects/managing-projects/#gerenciar-o-acesso-ao-projeto).
- **Guarde um registro.** **Ações ▾ > Baixar o pacote de evidências**, em **Resumo**, baixa uma pasta de trabalho do Excel com as planilhas **Status**, **Sources**, **Coverage**, **Mappings**, **Consolidation**, **Reconcile** e **Last load**: o que foi carregado e de onde, como os códigos foram mapeados, que o grupo bate e como foi a última carga. Ela segue o acesso às linhas de quem a baixa, e qualquer pessoa com uma função no projeto pode baixá-la.
- **Entregue-o.** Torne o proprietário um Arquiteto do projeto e depois remova-se dos membros. Algumas escolhas cabem apenas a um Arquiteto, como permitir que todos vejam os resultados do grupo ou adicionar o Data Foundation a um projeto.

## Construir sobre o modelo com um modelo de projeto

Um modelo de projeto cria seus relatórios e modelos sobre o Common Finance Model, então eles funcionam da mesma forma, sejam quais forem os ERPs que o alimentam. Quando você inicia um projeto a partir de um modelo, como o **Enterprise Profitability**, ele cria:

- As [tabelas do Common Finance Model](#tabelas-do-common-finance-model), vazias ou preenchidas com dados de exemplo.
- As dimensões **Entidade**, **Conta**, **Departamento**, **Cliente**, **Produto**, **Segmento 1** e **Segmento 2**, criadas a partir dessas tabelas. Consulte [Hierarquias](#hierarquias).
- O fluxo de trabalho **Carregar** e os fluxos de trabalho que ele executa para ler o ERP e os arquivos, padronizá-los, verificar a prontidão e montar os modelos do modelo de projeto.
- Os relatórios e modelos próprios do modelo de projeto. O **Enterprise Profitability** acrescenta uma tabela de demonstração do resultado com receita, CMV, margem bruta, despesas operacionais diretas e indiretas, margem de contribuição e margem operacional, além de pontes de margem ano contra ano e contra o orçamento.
- Métricas e um caminho de análise para fazer perguntas sobre os resultados.

Em **Começar de**, **Data Foundation** é o modelo sozinho, com seus relatórios. Cada uma das três soluções inclui o Data Foundation, acrescenta seus próprios modelos e mostra **Alocações** na barra lateral:

| Solução | Acrescenta |
|---|---|
| **Enterprise Profitability** | A demonstração do resultado e as pontes de margem. |
| **Cost to Serve** | O custo de atender cada cliente e a margem depois dele. Consulte [Cost to Serve](/pt-br/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | O nível de lucro de cada entidade comparado com a faixa da sua política, e o ajuste (true-up). Consulte [Operational Transfer Pricing](/pt-br/guides/projects/operational-transfer-pricing/). |

**A partir de um arquivo de modelo** começa a partir de um projeto que você salvou. Consulte [Salvar como meu modelo](#salvar-como-meu-modelo).

Para explorar antes de conectar o seu próprio ERP, marque **Começar com dados de exemplo** ao criar o projeto. O projeto executa uma primeira carga imediatamente, então **Resumo** mostra um exemplo completo, incluindo uma entidade em euros convertida para dólares americanos. Quando você conecta o seu próprio ERP ou adiciona os seus próprios arquivos, o exemplo é removido e os seus dados ocupam o lugar dele. Se a remoção for interrompida, o próximo **Carregar** a conclui. Uma pasta sua chamada `sample` nunca é removida, mas, enquanto o exemplo ocupar essa pasta, as outras tabelas dela não são lidas; por isso, mova-as para uma pasta com outro nome.

O grupo **Data Foundation** da barra lateral **Início** do projeto é onde você conecta, carrega e verifica seus dados. As linhas exibidas estão descritas em [Obter o Data Foundation](#obter-o-data-foundation).

| Página | O que mostra |
|---|---|
| **Resumo** | A situação do Data Foundation, se os números são confiáveis e o que fazer a seguir. Veja abaixo. |

Consulte [Conectar seu ERP](#conectar-seu-erp), [Sistemas](#sistemas) e [Adicionar arquivos com dados de fora do ERP](#adicionar-arquivos-com-dados-de-fora-do-erp). |
| **Perguntas** | Tudo o que aguarda sua resposta. Veja abaixo. |
| **Relatórios** | Os painéis por perfil, cada um abrindo em uma nova guia, e o cartão **Pacote do conselho**. Consulte [Painéis, métricas e caminhos de análise](/pt-br/guides/projects/data-foundation-dashboards/) e [Pacote para a diretoria](#pacote-para-a-diretoria). |
| **Alocações** | Em um projeto criado com uma solução, abre **Regras de alocação**. Consulte [Regras de alocação](#regras-de-alocação). |

**Resumo** mostra, de cima para baixo:

- A situação do projeto em uma linha, com a próxima etapa como um botão, como **Adicione seu sistema financeiro**, **Carregar**, **Responder 1 pergunta**, **Manter atualizado** ou **Abrir os relatórios**, e a linha do lucro líquido com **Explicar este número**. Consulte [Explicar um número](#explicar-um-número).
- Em um projeto com mais de uma entidade, **O grupo**: o quão completo o grupo está, a moeda de relatório dele e o mês em que começa o exercício financeiro, com **Alterar** para abrir **Configurações do projeto**.
- **Os números são confiáveis?**, as cinco garantias; com um único sistema, **Seu sistema**; quando houver, **O que mudou**; e **Fechar um mês**. Consulte [Data Foundation: os números são confiáveis?](/pt-br/guides/projects/data-foundation-proof/).
- **Perguntar ao Weave**, com perguntas para começar.
- **Histórico**: cada resposta, correspondência, fechamento e reapresentação, com quem a fez, quando e o valor anterior. Clique em **Mostrar histórico** para listá-lo, em **Mostrar mais** para ver entradas mais antigas e em **Exportar** para baixá-lo como uma pasta de trabalho do Excel.
- **Cobertura de fontes**, onde você escolhe qual origem vale quando duas fornecem os mesmos meses. Consulte [Escolher qual origem vale a partir de quando](#escolher-qual-origem-vale-a-partir-de-quando).

Se o acesso às linhas mostrar apenas algumas entidades para você, **Resumo** mostra **Estes números abrangem apenas as entidades às quais você tem acesso, não a empresa inteira.**

**Ações ▾**, no topo de **Resumo**, contém **Configurações do projeto…**, **Hierarquias…**, **Atualizar toda noite**, **Baixar o pacote de evidências**, **Clonar…**, **Restaurar…** e **Salvar como meu modelo…**. Consulte [Hierarquias](#hierarquias), [Manter atualizado](#manter-atualizado), [Entregar o projeto](#entregar-o-projeto), [Clonar um projeto](#clonar-um-projeto), [Pontos de restauração](#pontos-de-restauração) e [Salvar como meu modelo](#salvar-como-meu-modelo). A caixa de diálogo **Configurações do projeto** também abre com **Alterar** no cartão **O grupo** enquanto o grupo tiver mais de uma empresa. Apenas quem pode alterar o projeto pode usar as opções que o alteram.

**Perguntas** lista tudo o que aguarda sua resposta, agrupado por assunto, com quantas perguntas cada assunto tem. Quando você adiciona um sistema, responde a uma pergunta por assunto, como se ele usa os mesmos códigos de um sistema já conectado, e não a uma por código. Uma pergunta que retém linhas dos valores informa quantas são e o valor delas. **Weave suggests:** traz a resposta do Weave e as evidências que a sustentam: clique em **Usar esta resposta** ou escolha outra na lista e clique em **Responder**. **Aceitar todas as sugeridas** responde a todas as perguntas que têm uma sugestão. Uma resposta é aplicada no próximo **Carregar** ou **Aplicar alterações**. A linha **Perguntas** aparece apenas enquanto houver uma pergunta pendente.

Uma pergunta sobre uma classe de receita ou sobre a função de uma equipe não retém nada. Consulte [Classes de receita e funções das equipes](#classes-de-receita-e-funções-das-equipes).

Quando você altera as origens, uma barra acima de todas as páginas mostra **Você alterou suas origens. Clique em Aplicar alterações para usá-las.** Ela tem **Mostrar o que mudou** e **Aplicar alterações** e é o único lugar para aplicar uma alteração. O resultado de um **Carregar** ou **Aplicar alterações** aparece acima da página que estiver aberta, então você o vê em todas as páginas.

Enquanto uma carga é executada, as páginas se atualizam sozinhas e continuam lendo mesmo que uma leitura falhe. Se não for possível ler o status, aparece **Não foi possível ler o status do Foundation.** com **Tentar novamente**, que lê o status de novo; as páginas também tentam novamente uma vez por conta própria antes de mostrar a mensagem, e a mensagem desaparece quando o servidor responde.

## Tabelas do Common Finance Model

O Data Foundation padroniza cada origem, seja ERP ou arquivo, nas mesmas tabelas, para que relatórios, métricas e modelos criados sobre elas funcionem da mesma forma, seja qual for a origem. Cada linha também registra o sistema de origem e quando foi lida. A coluna **Dataset** é o nome que você escolhe ao adicionar um arquivo.

| Dataset | Tabela | Contém |
|---|---|---|
| Entidades | `cfm_entity` | Entidades legais com pai, moeda local e do grupo, país, região e divisão. |
| Mapa de códigos | `cfm_code_map` | O mapeamento de um código como a origem o registra, como um código de entidade, conta ou departamento, para o código canônico. Consulte [Mapeamento de entidades](#mapeamento-de-entidades) e [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| Taxas de câmbio | `cfm_fx_rate` | Taxas mensais médias, de fechamento e históricas por par de moedas. Consulte [Taxas de câmbio](#taxas-de-câmbio). |
| Calendário fiscal | `cfm_fiscal_calendar` | Uma linha por período fiscal de cada entidade, com datas de início e fim e se está fechado. |
| Plano de contas | `cfm_account` | Contas com pai, tipo (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), demonstrativo, saldo normal, tipo de taxa, função da conta e classe de receita. A função, como caixa, contas a receber, contas a pagar ou lucros acumulados, posiciona a conta na linha da demonstração e do fluxo de caixa. |
| Departamentos | `cfm_department` | Departamentos e centros de custo com pai, centro de lucro e função. |
| Centros de lucro | `cfm_profit_center` | Centros de lucro com pai e função. |
| Produtos | `cfm_product` | Cadastro de produtos com pai, família, grupo, unidade de medida, custo-padrão e classe de receita. |
| Clientes | `cfm_customer` | Cadastro de clientes com pai, grupo, região e país. Os nomes dos clientes não são mascarados. |
| Valores de segmento | `cfm_segment` | Valores de segmento com nome e pai. Consulte [Hierarquias](#hierarquias). |
| Razão geral | `cfm_gl_journal` | Linhas de lançamento na moeda da transação, na moeda local e na moeda de relatório. |
| Balancete | `cfm_trial_balance` | Débitos, créditos e saldo líquido do período por entidade, conta e departamento, na moeda local e na moeda de relatório. |
| Linhas de vendas | `cfm_sales_line` | Linhas de vendas faturadas com quantidade e valores bruto, de desconto, líquido e de CMV. |
| Pipeline | `cfm_opportunity` | Pipeline de vendas: uma linha por linha de oportunidade, em qualquer estágio, uma cópia por fim de mês. |
| Saldos de estoque | `cfm_inventory_balance` | Estoque de fim de período por produto e depósito. |
| Orçamento | `cfm_budget` | Orçamento e previsão por cenário, versão, conta e departamento. |
| CO-PA por avaliação | `cfm_copa` | Análise de rentabilidade do SAP (CO-PA) por entidade, período, conta, produto e cliente, um conjunto de linhas por avaliação (legal, de grupo ou de centro de lucro), nunca somadas. A receita é positiva e os custos, negativos. Dos modelos de projeto, apenas o [Operational Transfer Pricing](/pt-br/guides/projects/operational-transfer-pricing/#margem-co-pa) a lê. |
| Direcionadores de alocação | `cfm_stat_driver` | Direcionadores estatísticos, como número de funcionários, metros quadrados ou unidades. |

O modelo também contém os razões auxiliares e os respectivos cadastros, preenchidos pelos sistemas que os têm:

| Tabela | Contém |
|---|---|
| `cfm_site` | Locais: fábrica, local de depósito ou escritório, cada um em uma entidade. |
| `cfm_supplier` | Cadastro de fornecedores. |
| `cfm_sales_rep` | Cadastro de representantes de vendas. |
| `cfm_project` | Cadastro de projetos. Uma campanha de marketing é um projeto. |
| `cfm_standard_cost` | Custo-padrão por unidade, por produto, entidade de custeio e período. |
| `cfm_system_balance` | O próprio saldo final de cada sistema por conta em cada fim de mês, lido do relatório de saldos dele, nunca das linhas de lançamento. |
| `cfm_supplier_invoice_line` | Linhas de faturas de fornecedores. |
| `cfm_purchase_order_line` | Linhas de pedidos de compra, uma cópia por fim de mês. |
| `cfm_open_item` | Contas a receber e a pagar em aberto, uma cópia por fim de mês. |
| `cfm_payment` | Pagamentos recebidos e efetuados. |
| `cfm_order_line` | Linhas de pedidos de venda, uma cópia por fim de mês. |
| `cfm_asset` | Registro do ativo imobilizado. |
| `cfm_asset_movement` | Movimentações de ativos por livro e período: adição, depreciação, baixa e transferência. |
| `cfm_contract` | Contratos e assinaturas, uma cópia por fim de mês. Um [registro de contratos](#registros-de-contratos) é copiado para todo fim de mês que cada período abrange. |
| `cfm_deferred_revenue_movement` | Movimentações de receita diferida por contrato e período. |
| `cfm_bank_balance` | Contas bancárias e os respectivos saldos contábeis de fim de mês. |
| `cfm_inventory_movement` | Movimentações de estoque: entradas, saídas, produção, transferências, ajustes e baixas. |

Em uma tabela mantida com uma cópia por fim de mês, a cópia do mês aberto é substituída a cada carga. As tabelas de documentos têm uma coluna `counts`: `1` para uma linha que conta, vinda do sistema que vale para a entidade e o mês dela e do livro que o projeto reporta, e `0` para uma linha mantida de outro sistema ou livro. Relatórios e métricas leem apenas as linhas que contam.

Um projeto do Data Foundation vem com [elementos de projeto](/pt-br/guides/projects/data-model/) para as colunas que essas tabelas compartilham: `entity`, `account`, `department`, `profit_center`, `product`, `customer`, `period`, `site`, `supplier`, `sales_rep` e `project`. Cada um tem uma descrição e, quando se aplica, um tipo e uma dimensão, de modo que toda tabela que tenha uma dessas colunas mostre o mesmo significado. O Data Foundation adiciona qualquer um deles que o projeto não tenha e deixa como está o que você editou. Isso vale para todo ERP e origem de arquivo.

Os períodos são escritos como `YYYY-MM`, e as transações são posicionadas pelo período de lançamento. O orçamento é opcional: um ERP sem orçamentos ainda carrega todo o restante.

Um arquivo de balancete pode ter colunas de débito e crédito, uma coluna de saldo líquido, ou ambas. Com apenas débito e crédito, o saldo líquido é o débito menos o crédito, e um lado em branco conta como zero. Com apenas o saldo líquido, um valor positivo se torna débito e um valor negativo se torna crédito, como valor positivo. Uma coluna de departamento é opcional.

## Solução de problemas

| Sintoma | O que fazer |
|---|---|
| **Testar conexão** informa que o ERP recusou as credenciais | Verifique as credenciais da conexão e se o usuário de integração consegue fazer login no ERP. |
| **Testar conexão** mostra **Permissão ausente** para um dataset | Peça ao administrador do ERP que adicione as permissões indicadas. O [guia de conexão](/pt-br/guides/connections/) do seu ERP lista o que a conexão precisa. |
| Uma mensagem de erro do ERP é mais curta do que a do próprio ERP | O PlaidCloud remove credenciais, tokens e chaves dos erros do provedor antes de exibi-los, então alguns detalhes ficam de fora. Execute **Testar conexão** para ver qual dataset é afetado. |
| **Every month loaded** falha para um período | Uma leitura do ERP para aquele período falhou. Execute **Carregar** novamente; os períodos já carregados são ignorados. |
| **Every account known** falha | Adicione as contas que faltam ao plano de contas no ERP ou no seu arquivo e execute **Carregar** novamente. |
| **Every amount has a rate** falha | A moeda de uma entidade não tem taxa para a moeda de relatório naquele período, ou não foi encontrada uma única moeda de relatório. Adicione as taxas a um arquivo de **Taxas de câmbio**, verifique se a conexão consegue ler as taxas de câmbio do ERP ou defina a variável de projeto `reporting_currency`. Depois, execute **Carregar** novamente. |
| **Every amount has a rate** é um alerta | Linhas patrimoniais, de estoque ou de orçamento não têm taxa de fechamento, histórica ou planejada para o período. A demonstração do resultado não é afetada. Adicione as taxas, incluindo taxas planejadas para os meses do orçamento, e execute **Carregar** novamente. |
| **Codes mapped** falha | Abra **Perguntas** e responda a cada pergunta. As respostas são aplicadas no próximo **Carregar** ou **Aplicar alterações**. |
| **One source for each key** falha | Em **Cobertura de fontes**, em **Resumo**, escolha o mês e a origem, clique em **Salvar escolha** e clique em **Aplicar alterações**. |
| A verificação intercompanhia está vermelha ou âmbar | Verifique os pares em **Pares intercompanhia**. Lance o lado que falta, adicione o parceiro comercial às linhas ou adicione a taxa que falta. |
| **Group views are off** | Peça a um Arquiteto que marque **Todas as pessoas do projeto podem ver os resultados do grupo** em **Acesso por grupo e linha**, em **Configurações do projeto**. |
| Uma carga agendada foi ignorada | A pessoa que configurou o agendamento não pode mais usar a conexão de um sistema. Configure o agendamento novamente. Consulte [Manter atualizado](#manter-atualizado). |
| **Every entity known** falha | Adicione a entidade ao cadastro de entidades, ou mapeie o código dela para uma entidade existente em um arquivo **Mapa de códigos**, e execute **Carregar** novamente. |
