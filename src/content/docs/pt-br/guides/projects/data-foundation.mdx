O **Data Foundation** é a base de dados financeiros dos seus projetos do PlaidCloud. O **Common Finance Model** reúne em um único modelo os dados de vários sistemas ERP, e de várias instâncias de cada um: um plano de contas, um conjunto de entidades e uma moeda de relatório. Relatórios, métricas e assistentes de IA criados sobre o modelo leem os mesmos números, seja qual for o ERP de origem.

Seu ERP se conecta por meio da conexão do PlaidCloud, então o razão geral, o balancete, os dados mestres e os orçamentos chegam direto da origem, sem nada para exportar. Os arquivos acrescentam dados que um sistema não guarda, como taxas de câmbio, direcionadores de alocação ou um orçamento mantido fora do ERP, e podem substituir as linhas do ERP que cobrem. **Carregar** adapta cada origem ao modelo, converte para a moeda de relatório e verifica se os totais batem, tudo na guia **Foundation** do projeto. Quando origens usam o mesmo código para coisas diferentes, você informa se significam a mesma coisa, e uma consolidação gerencial monta a demonstração do resultado do grupo com as operações entre empresas do grupo eliminadas. Modelos, como o **Enterprise Profitability**, criam seus relatórios e modelos sobre essa base.

## Conecte seu ERP

Seu ERP se conecta ao Data Foundation por meio da conexão do PlaidCloud. O Data Foundation lê o razão geral, o balancete, os dados mestres, as taxas de câmbio e os orçamentos diretamente dela, e apenas lê. Você pode escolher uma conexão existente ou criar uma na guia. Cada sistema tem uma página para o administrador que concede o acesso, listada em [Quais sistemas podem alimentar o modelo](/pt-br/guides/projects/data-foundation-getting-started/#quais-sistemas-podem-alimentar-o-modelo), e a [Matriz de cobertura do Data Foundation](/pt-br/reference/data-foundation-coverage-matrix/) mostra quais datasets cada sistema fornece diretamente.

<Steps>

1. No Analyze, abra **Projetos** e clique em **Novo projeto**. Informe um nome e, em **Começar de**, escolha um modelo, como **Enterprise Profitability (modelo)**, em vez de **Projeto em branco**. Clique em **Criar**.

   O projeto abre na guia **Foundation**. Ele é privado para você, e você é o único Arquiteto dele, até compartilhá-lo.

2. Na guia **Foundation**, escolha uma conexão existente para o seu ERP ou selecione **Criar uma nova conexão**. Cada conexão existente lista os fluxos de trabalho que já a usam ou informa **Ainda não usado por nenhum workflow**.

3. Para uma nova conexão, informe um **Nome da conexão**, escolha o **Ambiente** e preencha as credenciais que a conexão do seu ERP solicita.

   Ainda não tem as credenciais? O formulário mostra uma solicitação de acesso pronta para o administrador do seu ERP. Clique em **Copiar solicitação** ou **Enviar solicitação por e-mail**, envie e informe os valores que ele devolver.

4. Clique em **Testar conexão**. O PlaidCloud faz login e tenta ler cada dataset, depois lista cada um como **Legível**, **Permissão ausente** ou **Erro**. Quando falta algo, ele informa as permissões que você deve pedir ao administrador do ERP para adicionar.

5. Defina **Meses de histórico**: quantos meses para trás carregar, de 1 a 120. O padrão é 24.

6. Para uma conexão existente, marque as entidades a carregar ou deixe todas desmarcadas para carregar todas as entidades. Entidades inativas e de eliminação ficam ocultas até você optar por exibi-las. Depois clique em **Conectar**.

7. Para uma nova conexão, clique em **Conectar** para criá-la. Depois marque as entidades a carregar e clique em **Conectar** de novo para salvá-las. Até você fazer isso, todas as entidades são carregadas.

8. Para trazer outro sistema ERP ou outra instância, repita estas etapas e marque **Add this as another source instead of replacing the current one** antes de clicar em **Conectar**. Sem isso, a nova conexão substitui a origem atual.

</Steps>

Depois de conectado, o cartão informa qual conexão, ambiente, entidades e meses de histórico o projeto carrega.

Cada carga lê apenas o que mudou: os períodos abertos e o último período fechado são lidos de novo, e os períodos fechados já carregados são mantidos. Aumentar **Meses de histórico** lê apenas os meses acrescentados. Uma taxa de câmbio, um mapeamento de entidades ou uma moeda de relatório alterados leem de novo os meses que afetam.

## Origens

Cada sistema ERP e cada instância de que o projeto carrega dados é uma origem. A lista **Origens** na guia **Foundation** mostra uma linha para cada uma, em ordem, com seu nome, quando foi carregada pela última vez e quantas linhas forneceu, além dos livros de relatório que ela lê, por exemplo `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Uma origem que ainda não foi carregada mostra **not loaded yet**. Os arquivos que você confirma também são origens.

Abra **Avançado** em uma origem para alterar como ela é usada:

| Configuração | O que faz |
|---|---|
| **Nome** | O rótulo que relatórios, perguntas de mapeamento e mensagens usam para a origem. |
| **Place in the order** | A posição da origem. Quando duas origens cobrem o mesmo mês da mesma empresa, vale a que está mais acima na ordem. |
| **Reporting books, separated by commas** | Os livros contábeis a ler, para um sistema que mantém mais de um. **All reporting books** lê todos os livros. |
| **Empresa**, **De (2026-01)** e **Até (2026-12)** | Os meses que esta origem fornece para cada empresa. Deixe um mês vazio para não ter limite. Escreva os meses como ano e mês, por exemplo `2026-03`. |

Clique em **Salvar** para manter suas alterações. Para descartar uma origem, clique em **Remove this source** e confirme **Remover**. Tudo o que foi carregado dela é excluído, e você pode conectá-la de novo depois.

Alterar origens não lê seu ERP de novo. O cartão **Última carga** mostra **Changes not applied yet** até você clicar em **Apply changes**, que executa uma carga a partir dos dados já obtidos: ela adapta as origens de novo com a nova ordem, os novos mapeamentos, nomes e arquivos, e reconstrói o modelo. Clique em **Carregar** quando também quiser dados novos dos ERPs.

## Adicione arquivos para dados fora do seu ERP

Os arquivos complementam a conexão do seu ERP com dados que um sistema não guarda, como taxas de câmbio, direcionadores de alocação, um [Mapeamento de entidades](#mapeamento-de-entidades) ou um orçamento mantido fora do ERP. Cada arquivo pertence a um dos datasets listados em [Tabelas do Common Finance Model](#tabelas-do-common-finance-model).

<Steps>

1. Em **Arquivos**, escolha a **Conta de documentos** em que o arquivo será armazenado.

2. Solte um arquivo CSV ou Excel em **Solte aqui um arquivo CSV ou Excel** ou clique em **Escolher um arquivo**. O arquivo é enviado para a pasta `/foundation/` da conta de documentos.

   Para um arquivo que já está na conta de documentos, informe o **Caminho do arquivo**, por exemplo `/foundation/budget.csv`, e clique em **Adicionar arquivo**.

   Para ler um novo arquivo todo mês, adicione todos os arquivos de uma pasta cujo nome corresponda: informe a pasta e o que os **File names that** contêm, começam com, terminam com, correspondem exatamente a ou correspondem como padrão, e clique em **Add files**. Arquivos em pastas dentro dela não são lidos.

3. O PlaidCloud lê o arquivo e propõe um mapeamento:

   - **Detected delimiter, decimal separator and dates.** O delimitador (vírgula, ponto e vírgula, tabulação ou barra vertical), o separador decimal e o formato de data são detectados para você.
   - **Dataset**: a tabela do Common Finance Model à qual o arquivo pertence, identificada pelo nome do arquivo e pelos títulos das colunas. Quando a correspondência não é clara, escolha-a na lista.
   - **Separador decimal**: **Ponto (1,234.56)** ou **Vírgula (1.234,56)**.
   - **Formato de data**: exibido quando o arquivo tem datas. Altere-o se o formato detectado estiver errado: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Uma grade com **Coluna no arquivo**, **Tipo**, **Exemplos** e **Vai para**. Altere **Vai para** para enviar uma coluna a outro campo ou para **Não carregar**.

4. Responda às perguntas que o arquivo levanta, como **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** ou **Are revenues shown as negative numbers?** Cada uma só é feita quando o arquivo ainda não informa a resposta.

5. Confira para onde vai cada coluna e clique em **Confirmar mapeamento**.

</Steps>

Estas opções aparecem em um arquivo quando se aplicam:

| Opção | Use para |
|---|---|
| **Which source do these rows apply to?** | Limitar um arquivo de mapeamento de códigos a uma origem. **Every source** o aplica a todas. |
| **Where does this file come from?** | Informar se o arquivo contém **This project's own codes** ou vem de **Another system**, que você nomeia, por exemplo `SAP Germany export`. Um arquivo de outro sistema é verificado quanto a códigos compartilhados como uma origem de ERP. |
| **Split … into … parts at each …** (em **Avançado**) | Dividir uma coluna que contém vários valores, como `100-200-300`, e enviar cada parte para seu próprio campo. |
| **Which currency do you report in?** | Definir a moeda de relatório quando o projeto ainda não tem uma. Escreva-a com três letras, por exemplo `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Carregar os resultados do seu sistema de consolidação para que a demonstração do resultado do grupo possa ser [reconciliada](#reconcilie-com-seu-sistema-de-consolidação). |

Para retirar um arquivo do projeto, clique em **Remover** ao lado dele em **Arquivos**, ou em **Remove this file** no mapeamento dele, e confirme. Os valores dele saem dos seus relatórios na próxima vez que você clicar em **Apply changes**.

Quando o PlaidCloud não consegue decidir sozinho o dataset, o separador decimal ou a ordem das datas, por exemplo um arquivo cujas datas podem ser lidas como dia/mês ou mês/dia, ele pede que você escolha antes de confirmar. Adicionar um segundo arquivo para o mesmo dataset substitui o primeiro. Se as colunas de um arquivo posterior não corresponderem ao dataset, a carga nomeia o arquivo e as colunas e orienta você a corrigir o arquivo ou os nomes das colunas, ou a definir **Schema Mismatch** da etapa como `union`.

Os arquivos aceitos são arquivos de texto CSV, TSV e TXT, arquivos Excel `.xlsx` (lidos a partir da primeira planilha) e arquivos Parquet.

<Aside type="note">
Um arquivo ausente ou vazio nunca interrompe uma carga. Ao adicioná-lo, o sistema informa que ainda não há nada para mapear, e a carga termina com um aviso que nomeia o caminho, deixando esse dataset vazio. Adicione o arquivo de novo quando ele existir.
</Aside>

## Carregue seus dados

Clique em **Carregar** no cartão **Carregar** ou no cartão **Última carga**. A carga lê o ERP conectado e os arquivos confirmados, adapta tudo ao Common Finance Model, converte para a moeda de relatório, executa as verificações de prontidão e reconstrói os modelos do modelo de projeto.

- Apenas uma carga é executada por vez em um projeto. Um segundo **Carregar** ou **Apply changes** informa que já há uma carga em execução, e você não pode alterar origens enquanto uma é executada.
- Se outros fluxos de trabalho usam a mesma conexão de ERP, a primeira carga os lista e pede que você confirme, porque uma carga lê do ERP e pode deixar esses fluxos de trabalho mais lentos. Clique em **Carregar mesmo assim** para prosseguir.
- Depois que o PlaidCloud é atualizado, o **Carregar** de um Arquiteto também atualiza os fluxos de trabalho gerados do projeto, criando as tabelas de trabalho de que eles precisam. Até lá, a página de status lista um item âmbar, "The workflows were generated by an earlier release. An Architect's Load updates them.", e o **Carregar** de um Gerente avisa que somente um Arquiteto pode atualizá-los.
- Uma carga com falha aparece em vermelho e nunca se esconde atrás de resultados anteriores. Se a consolidação falhar, o status nomeia a etapa em que ela parou em vez de mostrar resultados antigos do grupo. As linhas de uma carga anterior mostram **De uma carga anterior. Carregue novamente.** até que uma carga seja bem-sucedida.
- Se uma entidade e um período não puderem ser lidos, o restante ainda é carregado. Execute **Carregar** de novo para buscar apenas o que falhou.

### Linhas retidas

Quando as origens se sobrepõem, a carga mantém uma cópia de cada valor e retém as outras em vez de contá-las duas vezes. As linhas retidas são registradas com a origem, a entidade e o motivo, e a carga termina com um aviso que informa as contagens, por exemplo `120 rows of NetSuite EU also provided by a source ranked ahead`. Os motivos são:

| Motivo | Significado |
|---|---|
| Em outro livro contábil | A linha pertence a um livro de relatório que a origem não está configurada para ler. |
| Fora dos períodos que a origem fornece | A linha está fora dos meses **De** e **Até** definidos para a empresa. |
| Também fornecida por uma origem em posição superior | Uma origem mais acima na ordem cobre a mesma empresa e o mesmo mês. |
| Também em um arquivo anterior da origem | Um arquivo anterior da mesma origem já cobre o mês. |
| Substituída por um arquivo | Um arquivo substitui as linhas do ERP para essa entidade e esse mês. |
| Com um código que outra origem também usa | O código precisa da sua resposta. Veja [Mapeie códigos entre origens](#mapeie-códigos-entre-origens). |
| Com um código mapeado para dois códigos | O mapeamento de códigos dá duas respostas para o código. |

As contas estatísticas passam para os direcionadores de alocação em vez do razão, e aparecem como movidas, não como um problema.

### Dados do ERP e arquivos em conjunto

Um arquivo substitui apenas o que cobre, e as demais linhas do seu ERP permanecem.

- **Arquivos mestres** (contas, departamentos, clientes, produtos e Valores de segmento) substituem as linhas do ERP com o mesmo código.
- **Arquivos de transações** substituem as linhas do ERP da mesma entidade e do mesmo mês. Os arquivos de razão geral e de balancete também correspondem por razão, os arquivos de orçamento por cenário e os arquivos de direcionadores estatísticos por cenário e direcionador.

Se um arquivo deixar de cobrir um mês, os dados do ERP desse mês voltam na próxima carga.

## Mapeamento de entidades

Cada origem nomeia suas entidades com seus próprios códigos. O **Mapeamento de entidades** associa esses códigos às entidades do seu cadastro mestre de entidades, para que as linhas de todas as origens cheguem à mesma entidade.

Para usar um, adicione um arquivo CSV ou Excel e escolha o dataset **Mapeamento de entidades**:

| Coluna | Contém |
|---|---|
| `source_entity` | O código como a origem o carrega, como um código de empresa. |
| `entity` | A entidade a que ele pertence, como o cadastro mestre de entidades a nomeia. |

- Um código que não está no mapeamento é usado como está.
- Vários códigos podem ser mapeados para uma entidade. As linhas deles são combinadas, e um mês conta como fechado quando está fechado para todos eles.
- Os códigos do mapeamento valem para todas as origens, então os códigos de entidade de cada origem devem ser exclusivos entre as origens.
- Uma linha do arquivo **Entidades** substitui a entidade do ERP com o mesmo código de entidade.

A verificação **Entidades não mapeadas** sinaliza qualquer linha cuja entidade não está no cadastro mestre de entidades nem é mapeada para uma pelo mapeamento de entidades. Enquanto nenhum cadastro mestre de entidades for carregado, ela mostra **– Não se aplica**.

## Mapeie códigos entre origens

Duas origens podem usar o mesmo código para coisas diferentes, ou códigos diferentes para a mesma coisa. Quando um código aparece em mais de uma origem, o Data Foundation retém as linhas dele até você dizer se ele significa a mesma coisa em todos os lugares, para que cada valor seja contado uma vez. A verificação **Codes waiting for your answer** os lista, os 10 primeiros e depois "e mais K", e o cartão **What to do next** na guia **Foundation** tem um botão **Revisar**.

**Revisar** abre **Codes waiting for your answer**. Ele agrupa os códigos pelo que são: **Account types**, **Companies**, **Accounts**, **Departments**, **Profit centers**, **Customers**, **Products** e cada categoria extra. Para cada código, mostra como cada origem o chama e uma sugestão:

- **Looks like the same thing** quando as origens dão o mesmo nome ao código.
- **Looks like different things** quando os nomes diferem.
- **We can't tell. Please answer.** quando não há nada em que se basear.

Responda um código por vez com **Yes, the same** ou **No, different**, ou responda um grupo inteiro de uma vez com **Accept all** (aceitar todas as sugestões), **All the same** ou **All different**. Para contas, você também pode responder de uma vez um grupo pai inteiro do plano de contas. Quando uma origem não traz tipos de conta, escolha **Use this type** para um grupo de contas: **Revenue**, **Cost of goods sold**, **Operating expenses**, **Non-operating income and expenses**, **Assets**, **Liabilities** ou **Equity**.

Os mapeamentos são mantidos por origem e dimensão, então uma resposta para os departamentos de uma origem nunca altera as contas de outra. As respostas são salvas conforme você avança, com **Saved. Press Apply changes to use your answers.** Clique em **Apply changes** para usá-las.

Você também pode fornecer os mapeamentos em um arquivo. Adicione um arquivo com o dataset **Code map** e escolha **Which source do these rows apply to?** para limitá-lo a uma origem.

## Escolha qual origem vale a partir de quando

Quando duas origens fornecem os mesmos meses, a verificação **Which source covers which months** pede que você escolha. Clique em **Choose which source counts from when** no cartão **What to do next** para abrir **Which source counts from when**, que lista cada sobreposição por empresa. Escolha a origem que vale, informe o mês a partir do qual ela vale em **That month is**, por exemplo `2026-04`, e clique em **Apply changes**. A outra origem mantém os meses anteriores.

A mesma caixa de diálogo avisa quando duas origens dão taxas de câmbio diferentes para uma moeda; são usadas as taxas da origem mais acima na ordem.

## Conversão de moedas

Cada carga converte os valores do razão geral, do balancete, das vendas, do estoque e do orçamento da moeda local para uma única moeda de relatório. Relatórios e modelos leem os valores convertidos, então entidades em moedas diferentes, de qualquer sistema, somam corretamente.

### A moeda de relatório

Para escolher a moeda de relatório, defina a variável do projeto `reporting_currency` com um código de moeda, como `USD`. Veja [Gerenciar variáveis do projeto](/pt-br/guides/projects/managing-projects/#gerenciar-variáveis-do-projeto). O modelo a cria em branco. Enquanto estiver em branco, cada carga usa o primeiro destes critérios que nomeie exatamente uma moeda:

1. A moeda do grupo das entidades.
2. A moeda local das entidades de nível superior, as que não têm pai.
3. A moeda local dos arquivos.

Se nenhum deles nomear exatamente uma moeda, **Conversão de moedas** mostra um problema até você definir `reporting_currency`.

Os valores que já estão na moeda de relatório permanecem como estão, então um projeto cujos dados estão todos em uma única moeda não precisa de taxas.

Os arquivos de vendas, estoque e orçamento também podem trazer uma moeda. Mapeie uma coluna chamada `Currency` ou `Local Currency` e ela é reconhecida automaticamente, e os valores locais do arquivo são convertidos para a moeda de relatório. Um valor de grupo ou de relatório que já esteja no arquivo é mantido como está. O custo padrão do produto não é convertido.

### Taxas de câmbio

Uma taxa converte uma unidade de uma moeda para a moeda de relatório em um mês: o valor convertido é o valor local multiplicado pela taxa.

- **Do seu ERP**, cada carga lê as taxas de câmbio que o ERP guarda.
- **De um arquivo**, adicione um arquivo CSV ou Excel e escolha o dataset **Taxas de câmbio**. Uma taxa do arquivo substitui a taxa do ERP para as mesmas moedas e o mesmo mês. Use um arquivo para relatar em uma moeda para a qual seus ERPs não publicam taxas, ou para acrescentar taxas planejadas para os meses do orçamento.

| Coluna | Contém |
|---|---|
| `from_currency` | A moeda de origem da conversão, por exemplo `EUR`. |
| `to_currency` | A moeda de relatório, por exemplo `USD`. |
| `period` | O mês, como `YYYY-MM`. |
| `average_rate` | A taxa média do mês. |
| `closing_rate` | A taxa no fim do mês. |
| `historical_rate` | A taxa histórica, para o patrimônio líquido e para contas definidas com a taxa histórica. |

Somente as taxas para a moeda de relatório são usadas. Uma taxa cotada no sentido inverso, da moeda de relatório para outra moeda, não é invertida.

### Qual taxa se aplica

Cada linha é convertida a partir da própria moeda, então uma linha em uma moeda diferente da de sua entidade é convertida a partir da moeda em que está. A primeira regra que se ajusta à linha é a que vale:

| Linha | Taxa |
|---|---|
| Contas estatísticas e que não recebem lançamentos | Não convertida. |
| Já na moeda de relatório | Não convertida. |
| Conta com um tipo de taxa | Essa taxa: média, de fechamento ou histórica. A histórica recorre à de fechamento quando não há taxa histórica. Em um ERP, o tipo de taxa é o tipo de taxa da própria conta. Em um arquivo de plano de contas, mapeie uma coluna de tipo de taxa para `fx_rate_type` com `average`, `closing` ou `historical`. |
| Linha de vendas | A taxa média do período. |
| Saldo de estoque | A taxa de fechamento do período. |
| Linha de orçamento | Por conta, como o razão geral: a taxa média para contas da demonstração do resultado e a taxa de fechamento para contas do balanço patrimonial. |
| Conta da demonstração do resultado | A taxa média do período. |
| Conta de patrimônio líquido | A taxa histórica, ou a taxa de fechamento quando não há taxa histórica. |
| Qualquer outra conta do balanço patrimonial | A taxa de fechamento do período. |

Os valores convertidos não são arredondados, então os totais não se desviam.

<Aside type="note">
O balancete contém as movimentações de cada período, então os valores do balanço patrimonial são as movimentações de cada mês convertidas à taxa de fechamento desse mês. Eles não são um balanço patrimonial reconvertido à taxa do fim do período, e não há ajuste cumulativo de conversão nem eliminação entre empresas do grupo. Use os valores convertidos para a demonstração do resultado.
</Aside>

## Hierarquias

Cada carga reconstrói as dimensões a partir dos dados mestres de todas as origens. Há sete dimensões para começar e até dez categorias extras:

| Dimensão | Construída a partir de |
|---|---|
| **Entidade** | Entidades e seus pais |
| **Conta** | Plano de contas e contas pai |
| **Departamento** | Departamentos e seus pais |
| **Cliente** | Clientes e seus clientes pai |
| **Produto** | Produtos e seus produtos pai |
| **Segmento 1** | Valores de segmento para `segment_1` |
| **Segmento 2** | Valores de segmento para `segment_2` |
| **Segmento 3** a **Segmento 10** | Valores de segmento para `segment_3` a `segment_10`, quando suas origens os trazem |

- Um registro sem pai, ou que nomeia a si mesmo como pai, é carregado como membro de nível superior.
- Como cada carga reconstrói as hierarquias, altere um pai no ERP ou no seu arquivo, não na dimensão.
- Um problema em uma hierarquia afeta apenas essa dimensão. A carga e os modelos do modelo de projeto ainda são concluídos.
- Você pode renomear cada categoria extra para o que ela contém, por exemplo **Classe** ou **Região**. Em **Rename extra categories**, informe os nomes que seus relatórios usam e clique em **Save names**. Os nomes usam letras, números, espaços, pontos, hifens e sublinhados, com até 60 caracteres.
- Cada origem informa sob qual dos seus nomes de categoria cada uma de suas categorias extras entra. Abra **Avançado** na origem, escolha o nome de cada uma, ou escolha **Leave out**, e clique em **Salvar**. Origens que chamam uma categoria por nomes diferentes, como `Class` e `Business area`, passam então a compartilhar um mesmo espaço.

Para fornecer hierarquias de segmento a partir de um arquivo, escolha o dataset **Valores de segmento**:

| Coluna | Contém |
|---|---|
| `segment` | A que segmento o valor pertence: `segment_1` a `segment_10`. |
| `segment_value` | O valor, como as linhas do razão geral, das vendas e do orçamento o carregam. |
| `segment_value_name` | O nome dele. |
| `parent_segment_value` | O pai dele dentro do mesmo segmento. |

## Verificações de prontidão

Depois de cada carga, a grade **Prontidão** lista todas as verificações de todas as entidades e períodos, com um destes status:

| Status | Significado |
|---|---|
| **● Pronto** | A verificação passou. |
| **▲ Requer atenção** | Vale uma olhada, mas os números são utilizáveis. |
| **■ Problema** | Corrija antes de confiar nos resultados. |
| **– Não se aplica** | Ainda não há dados para esta verificação. |

As verificações são:

| Verificação | O que confirma |
|---|---|
| **Dados carregados** | Todo período fiscal tem linhas do razão geral, e toda leitura do ERP foi bem-sucedida. Um período fechado sem linhas é um problema; um período aberto sem linhas requer atenção. |
| **Balancete bate com o razão geral** | O balancete é igual ao razão geral para cada entidade, período e conta. Quando o balancete e o razão geral trazem departamentos para uma conta, ele também confere cada departamento. |
| **Vendas batem com o razão geral** | As linhas de vendas são iguais às contas de receita e de CPV do razão geral em cada período. |
| **Produtos/clientes desconhecidos** | Toda linha de vendas nomeia um produto e um cliente que existem nos cadastros mestres de produtos e clientes. |
| **Contas ausentes do plano de contas** | Toda linha do razão geral nomeia uma conta do plano de contas. As linhas com conta desconhecida ficam fora da demonstração do resultado. Uma conta com lançamentos, mas sem tipo de conta, também é um problema, e uma origem cujo plano de contas tipifica contas de Receita mas nenhuma conta de custo dos produtos vendidos requer atenção. |
| **Conversão de moedas** | Toda linha do razão geral, do balancete, das vendas, do estoque e do orçamento tem um valor na moeda de relatório. Uma linha da demonstração do resultado ou de vendas sem taxa é um problema, porque a demonstração do resultado lê os valores convertidos. Uma linha do balanço patrimonial, do estoque ou do orçamento sem taxa requer atenção. Um mês de orçamento sem taxa ainda aparece em âmbar, então carregue taxas planejadas para os meses do orçamento. Veja [Conversão de moedas](#conversão-de-moedas). |
| **Entidades não mapeadas** | Toda linha do razão geral, do balancete e de vendas nomeia uma entidade do cadastro mestre de entidades, diretamente ou pelo mapeamento de entidades. Não se aplica até que um cadastro mestre de entidades seja carregado. Veja [Mapeamento de entidades](#mapeamento-de-entidades). |

As cargas com mais de uma origem acrescentam estas verificações:

| Verificação | O que confirma |
|---|---|
| **Reporting book** | Uma origem que traz vários livros contábeis para uma entidade teve seu livro de relatório escolhido. Até você escolher, apenas o primeiro livro conta. |
| **Codes waiting for your answer** | Todo código usado por mais de uma origem foi respondido. Veja [Mapeie códigos entre origens](#mapeie-códigos-entre-origens). |
| **Extra categories from your sources** | Toda categoria extra que uma origem traz tem um nome ou foi deixada de fora. |
| **Which source covers which months** | Nenhuma origem fornece os mesmos meses de uma empresa que outra, a menos que você tenha escolhido qual vale. |
| **Account types and hierarchy** | Todo pai que uma dimensão nomeia existe, e nenhum membro é pai ou ancestral de si mesmo. Um pai ausente coloca seus filhos no topo da hierarquia, e um ciclo impede o carregamento dessa hierarquia. Os totais não são afetados. |
| **Calendário fiscal** | Os períodos fiscais de cada entidade são meses do calendário, e cada mês de linhas pode ser colocado em um período fiscal. Requer atenção quando os períodos de uma entidade não são meses do calendário (4-4-5, 13 períodos), ou quando as linhas de um mês podem estar em mais de um período fiscal ou o calendário fiscal não tem o mês. |

Cada linha que não está pronta diz o que fazer na coluna **O que fazer**, como carregar o plano de contas, carregar taxas de câmbio ou executar **Carregar** de novo para um período.

A grade também mostra duas verificações de configuração, que só aparecem quando precisam de atenção:

| Verificação | Quando aparece |
|---|---|
| **Alocação de custos indiretos** | Apenas uma das variáveis do projeto `overhead_department` e `overhead_driver` está definida, ou nenhum direcionador de alocação corresponde a `overhead_driver`, então a alocação não faria nada. Defina as duas ou limpe as duas para desativar a alocação de custos indiretos. |
| **Comparação com o orçamento** | Há linhas de orçamento carregadas, mas nenhuma está na versão que a variável do projeto `budget_version` nomeia, então a comparação com o orçamento ficaria vazia. |

## Consolidação gerencial

Cada carga constrói uma consolidação gerencial: a demonstração do resultado do grupo com todas as entidades do grupo, na moeda de relatório, com as operações entre empresas do grupo eliminadas. Ela serve para a elaboração de relatórios gerenciais. Seu sistema de consolidação continua sendo o registro oficial do grupo para fins estatutários; reconcilie com ele conforme descrito abaixo.

<Aside type="note">
A consolidação gerencial abrange apenas a demonstração do resultado. Ela não é uma consolidação estatutária ou legal e não tem balanço patrimonial consolidado, ajuste de conversão, ágio nem participação de minoritários.
</Aside>

### Escolha o grupo

Em **Origens**, abra **Grupo** para ver as empresas do grupo. Uma empresa que você desmarca continua nos seus relatórios por conta própria, mas fica fora do total do grupo. Clique em **Save group**. A alteração se aplica na próxima **Carregar** ou **Apply changes**. Uma nova empresa fica no grupo até você desmarcá-la.

O ano fiscal do grupo começa no mês definido pela variável do projeto `group_fy_start_month`, que é `1` a menos que você a altere.

### O que você obtém

| Tabela | Contém |
|---|---|
| **Group P&L** | Uma linha por entidade, período e linha (receita, custo dos produtos vendidos, despesas operacionais, não operacional, diferença entre empresas do grupo), na moeda de relatório. Receita e custos mantêm o sinal natural. |
| **Group P&L year to date** | O mesmo, acumulado no ano, até o último período totalmente carregado do grupo. |
| **Intercompany pairs** | Uma linha por par de entidades, grupo e período, com o valor de cada lado e o resíduo. |
| **Intercompany lines** | As linhas do razão por trás de um valor do grupo ou de um par, com o parceiro comercial. |
| **Reconciliação** | A demonstração do resultado do grupo acumulada no ano em comparação com seu sistema de consolidação. |

Três nomes de entidade aparecem nessas tabelas:

| Entidade | Significado |
|---|---|
| **Eliminations** | As eliminações entre empresas do grupo. Elas somam zero, então deixe-as incluídas para os valores do grupo e filtre-as para obter a soma das entidades antes da eliminação. |
| **Group total** | O total do sistema de consolidação, na reconciliação. |
| **Unmapped** | Linhas sem período, e contas ou entidades do seu sistema de consolidação que este projeto não tem. |

As métricas **Consolidated income**, **Consolidated result** e **IC difference**, e um caminho de análise para cada tabela, respondem a perguntas sobre o grupo.

### Eliminações entre empresas do grupo

As linhas entre empresas do grupo são pareadas por parceiro comercial. Usa-se o parceiro da linha; quando a linha não tem um, usa-se o parceiro do cliente dela. Os dois lados de um par são eliminados, e o valor pelo qual os dois lados não coincidem é lançado em uma linha de diferença entre empresas do grupo. Cada par recebe um motivo:

| Motivo | Significado |
|---|---|
| **Matched** | Os dois lados lançaram o mesmo valor. |
| **Only one side booked** | Uma entidade lançou a transação e seu parceiro não. |
| **Not eliminated** | Uma linha do par não tem taxa de câmbio, então nenhum dos lados é eliminado. |

Um par é avaliado pelo acumulado no ano. A linha **Intercompany balances** fica âmbar quando a diferença de um par supera a variável do projeto `group_amber` (padrão `1`) e vermelha quando supera `group_red` (padrão `1000`). As linhas sem parceiro, ou com um parceiro que não é uma entidade, não são eliminadas e são contadas nessa linha. Uma origem que traz parceiros ao lado de uma que não traz aparece em âmbar.

As entidades de eliminação da própria origem ficam fora da demonstração do resultado do grupo, e a linha **Consolidação** informa isso.

### Reconcilie com seu sistema de consolidação

Adicione como arquivo os resultados que seu sistema de consolidação relata e marque **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** ao confirmar o mapeamento dele. Responda **Which version of the numbers is this?** com o nome do sistema. A tabela **Reconciliação** passa então a mostrar **ours**, **reported** e **diferença** para cada entidade e linha, acumulados no ano. Uma diferença costuma ser explicada nas linhas **Eliminations**, **Group total** e **Unmapped**, ou pelas taxas de câmbio que o sistema usa. A linha **Reconciliation to the source** lista todas as linhas acima de `group_amber`.

### Quem pode ver

Os resultados do grupo seguem o acesso a linhas do projeto. Quando o acesso a linhas impede os resultados do grupo, o status aparece em âmbar. Uma pessoa que vê apenas algumas entidades vê as somas dessas entidades antes da eliminação. As linhas **Eliminations** e as tabelas entre empresas do grupo exigem acesso a todas as entidades.

Se o projeto limita quem vê quais linhas por uma coluna que as tabelas do grupo não trazem, como o departamento, os resultados do grupo ficam desativados para todos e **Consolidação** informa **Group views are off**. Somente um Arquiteto pode então marcar **Everyone on the project may see the group results** em **Grupo**. A alteração se aplica na próxima **Carregar** ou **Apply changes**.

## Mantenha atualizado

Depois que uma carga da sua conexão de ERP é bem-sucedida e sem problemas, **Atualizar toda noite** aparece no cartão **Última carga**. Clique nele para executar **Carregar** toda noite às 2:00 no seu fuso horário. O cartão passa então a mostrar **Nightly refresh: Every night at 2:00** e quem o configurou.

A carga noturna é executada como a pessoa que a configurou. Se essa pessoa não puder mais usar a conexão de ERP, a grade informa que a carga noturna foi ignorada; configure-a de novo. Um projeto que tem apenas dados de exemplo não pode ser agendado.

Um arquivo ausente ou vazio em uma carga noturna termina com um aviso que nomeia o caminho, não com um erro, e o restante do modelo ainda é carregado.

## Nomes de negócio

**Business names** na guia **Foundation** dão aos códigos do seu modelo os nomes que sua empresa usa. Relatórios, métricas e o assistente mostram esses nomes, e um nome salvo se aplica de imediato. As cargas seguintes o mantêm.

1. Clique em **Add a name** e escolha o **Tipo**: **Category**, **P&L line**, **Metric** ou **Column**.
2. Informe o **Código**: `segment_1` a `segment_10` para uma categoria, a chave da linha para uma linha da demonstração do resultado, o nome da métrica, ou `table.column` para uma coluna.
3. Informe o **Nome**, com no máximo 60 caracteres em uma linha.
4. Clique em **Save names**.

Salvar substitui a lista inteira. Uma linha com o nome vazio remove esse nome, e **Remover selecionados** remove as linhas que você marcar. Nomear o mesmo código duas vezes é recusado. Os nomes de negócio também são gravados na descrição do caminho de análise para que o assistente use as suas palavras, e essa descrição tem um limite de tamanho: se um nome a deixar longa demais, nada é salvo e você é avisado.

## Explique um número

**Explain this number** mostra o que compõe um valor da demonstração do resultado. Na grade **Prontidão**, uma linha de uma entidade e um mês tem **Explain this number**, que abre a margem operacional da entidade nesse mês. A janela divide o número em camadas que somam o total no topo:

| Camada | O que contém |
|---|---|
| **From the general ledger** | O que o razão lançou na linha. |
| **Allocated in** | Custo distribuído a esta entidade pelas suas [regras de alocação](#regras-de-alocação). |
| **Allocated out** | Custo que esta entidade distribuiu a outras. |
| **Eliminated in the group** | Operações entre empresas do grupo que foram eliminadas no resultado do grupo. |

Cada camada tem uma frase que diz o que ela é e seus maiores documentos de origem, com o sistema de origem, o documento e a conta. Só aparecem as camadas que têm linhas. A janela segue o seu acesso a linhas: você explica apenas os valores que pode ver. Um número sem nada por trás informa **Nothing to explain**.

## Regras de alocação

As alocações distribuem custos compartilhados, como custos indiretos, para departamentos, produtos e clientes. O modelo tem dois estágios: **Stage 1: overhead to departments** e **Stage 2: departments to products and customers**. Abra **Ações > Alocações...** para ver ou alterar como cada um é feito. Sem alterações, eles funcionam como funcionavam antes de o assistente existir. Um leitor pode abrir as regras, mas não salvá-las.

Para cada estágio, o assistente faz quatro perguntas:

| Etapa | Pergunta | Opções |
|---|---|---|
| **Pool** | Quais custos você quer distribuir? | O tipo de conta e, no estágio 1, o departamento que mantém o custo, ou **All departments**. |
| **Driver** | Por qual critério você quer distribuí-los? | **Statistic** que você carregou como direcionadores de alocação, como número de funcionários ou metros quadrados, **Net sales amount**, **Sales quantity** ou **Spread evenly**. Use o direcionador do **Same period** ou do **Same period last year**. |
| **Target** | Onde eles vão parar? | Estágio 1: departamentos. Estágio 2: produtos, clientes ou ambos. |
| **Method** | O que acontece quando um direcionador é negativo? | **Ignore negative values** ou **Stop and tell me**. |

Abaixo das etapas, **Preview for** um mês, escrito como ano e mês, como `2026-09`, mostra o que as regras, inclusive as que você ainda não salvou, fariam: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Qualquer valor não alocado é custo para o qual não havia direcionador. A pré-visualização segue o seu acesso a linhas.

Clique em **Salvar**. As regras entram em vigor na próxima **Carregar**, ou quando você clica em **Apply changes**. Se você editou uma etapa de alocação manualmente, sua edição é mantida, não sobrescrita, e o salvamento a nomeia. Você não pode salvar enquanto uma carga está em execução.

## Board pack

Um board pack grava seus resultados em uma pasta de uma conta de documentos, em um agendamento, pronto para enviar. Abra **Ações > Board pack...**, escolha uma **Conta de documentos** e uma **Pasta**, como `/board-packs`, e clique em **Salvar**. Cada execução grava:

- Uma pasta de trabalho do Excel, `Board pack.xlsx`, com a demonstração do resultado por entidade, uma ponte de margem e os melhores e piores clientes.
- Um PDF do painel da demonstração do resultado.

Se o projeto ainda não tem um painel, a pasta de trabalho é gravada sozinha e a execução informa o motivo. Clique em **Run now** para gerar um pack imediatamente; os arquivos dele aparecem na pasta quando termina. O cartão mostra a última execução e seu resultado, e a próxima execução. O pack é gerado pelo fluxo de trabalho **Board pack** do projeto, que a atualização noturna não executa: para gerá-lo em um agendamento, agende esse fluxo de trabalho com o [agendador de eventos](/pt-br/administration/scheduled-events/event-scheduler/), por exemplo para um horário posterior ao término da atualização noturna. Somente quem pode alterar o projeto o configura.

## Pontos de restauração

Um ponto de restauração é criado quando cada **Carregar** ou **Apply changes** começa, seja quem for que o inicie, inclusive uma carga agendada, e antes de cada alteração de mapeamentos ou origens. Ele guarda as tabelas do modelo, as dimensões e as configurações a partir das quais a próxima carga é construída: suas origens, arquivos e regras de alocação. São mantidos os últimos sete pontos criados para cargas e os últimos cinco criados antes de alterações, então as alterações nunca expulsam os pontos criados para cargas. Os pontos mais antigos são descartados.

Para voltar atrás, abra **Ações > Restaurar...**, escolha um ponto e clique em **Restaurar**. **Restaurar** é oferecido quando existe um ponto. Restaurar primeiro registra o projeto como ele está agora como um ponto próprio, para que você possa voltar de novo. Em seguida, devolve as tabelas, as dimensões e essas configurações ao que eram, e a próxima carga é construída a partir delas. Uma tabela sem cópia salva, ou um mecanismo que não pode guardar histórico, é nomeada em um aviso e o restante é restaurado. Um ponto de restauração que já foi descartado é recusado, e você não pode restaurar enquanto uma carga está em execução.

## Clone um projeto

**Ações > Clonar...** copia o projeto com um nome que você informa. A cópia mantém o modelo, suas edições no modelo e suas métricas e caminhos de análise, e carrega os dados de exemplo. As origens dela não ficam conectadas, então conecte-as na cópia antes de carregar. Você pode continuar trabalhando enquanto a cópia é feita, e **Abrir projeto** leva você até ela quando estiver pronta.

## Salvar como meu modelo

Salve a configuração de um projeto para reutilizá-la no próximo cliente ou na próxima entidade. Abra **Ações > Save as my template...**, escolha a conta de documentos e dê um nome ao arquivo. Um nome terminado em `.zip` é acrescentado se você o omitir. Salvar sobre um arquivo existente é recusado, então escolha outro nome.

O arquivo guarda a estrutura do projeto, suas edições no modelo, as métricas e os caminhos de análise, os nomes de negócio para entidades e contas, e as linhas das tabelas de configuração do modelo, como o mapa de atividades do [Cost to Serve](/pt-br/guides/projects/cost-to-serve/) ou as faixas de política do [Operational Transfer Pricing](/pt-br/guides/projects/operational-transfer-pricing/). Ele deixa de fora conexões, arquivos, o agendamento noturno, execuções, pontos de restauração, o board pack e quem tem acesso.

Para usá-lo, crie um projeto, escolha **From a template file...** em **Começar de** e indique a conta de documentos e o caminho. O novo projeto é privado para você, com todas as origens esperando para serem conectadas. Uma versão posterior do modelo mescla as alterações dela em torno das etapas que você editou. Se não houver arquivo no caminho, nada é criado e você é avisado. Qualquer pessoa que possa ler a conta de documentos pode instalar a partir do arquivo. Para usá-lo em outro espaço de trabalho, baixe o arquivo e envie-o para lá.

## Resolva perguntas em aberto com o Ask

Depois de uma carga, um projeto ainda pode estar esperando que você informe três coisas: contas que o plano de contas deixa sem tipo, códigos que mais de uma origem usa e colunas dos seus arquivos que não corresponderam a nada. Peça ao assistente que as resolva: em um assistente de IA via MCP, use o prompt **Resolve Data Foundation residue**. Ele lê o que está pendente e propõe uma resposta para cada item, com um motivo.

O assistente não grava nada. Você aplica as respostas dele onde você mesmo as teria dado: contas e códigos em **Codes waiting for your answer**, e colunas de arquivos no mapeamento do arquivo. Ele nunca propõe uma entidade.

## Entregue o projeto

A lista **Configuração** tem quatro itens finais depois de **Revise suas hierarquias**:

- **Set up the nightly refresh** é concluído quando **Atualizar toda noite** está ativado.
- **Compartilhe com sua equipe** é concluído quando alguém além da pessoa que configurou o projeto é membro.
- **Download the evidence pack** é concluído quando você baixa o pack depois da última carga bem-sucedida.
- **Hand the project over to its owner** é concluído quando existe um Arquiteto além da pessoa que o configurou e os totais batem. Enquanto não é concluído, a lista informa o que fazer: tornar o proprietário do cliente um Arquiteto deste projeto e depois remover você mesmo dos membros.

A lista informa quem configurou o projeto (**Set up by**).

## Crie sobre o modelo com um modelo de projeto

Um modelo de projeto cria seus relatórios e modelos sobre o Common Finance Model, então eles funcionam do mesmo jeito seja qual for o ERP que o alimenta. Quando você inicia um projeto a partir de um modelo, como o **Enterprise Profitability**, ele cria:

- As [tabelas do Common Finance Model](#tabelas-do-common-finance-model), vazias ou preenchidas com dados de exemplo.
- As dimensões **Entidade**, **Conta**, **Departamento**, **Cliente**, **Produto**, **Segmento 1** e **Segmento 2** construídas a partir dessas tabelas. Veja [Hierarquias](#hierarquias).
- O fluxo de trabalho **Carregar** e os fluxos de trabalho que ele executa para ler seu ERP e seus arquivos, adaptá-los, verificar a prontidão e construir os modelos do modelo de projeto.
- Os relatórios e modelos do próprio modelo de projeto. O **Enterprise Profitability** acrescenta uma tabela de demonstração do resultado com receita, CPV, margem bruta, despesas operacionais diretas e indiretas, contribuição e margem operacional, além de pontes de margem ano a ano e em relação ao orçamento.
- Métricas e um caminho de análise para fazer perguntas sobre os resultados.

Três modelos estão disponíveis em **Começar de**, cada um construído sobre o mesmo modelo:

| Modelo | Acrescenta |
|---|---|
| **Enterprise Profitability** | A demonstração do resultado e as pontes de margem. |
| **Cost to Serve** | O custo de atender cada cliente e a margem depois dele. Veja [Cost to Serve](/pt-br/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | O nível de lucro de cada entidade em relação à sua faixa de política e o ajuste final. Veja [Operational Transfer Pricing](/pt-br/guides/projects/operational-transfer-pricing/). |

**From a template file...** começa a partir de um projeto que você salvou. Veja [Salvar como meu modelo](#salvar-como-meu-modelo).

Para explorar antes de conectar seu próprio ERP, marque **Começar com dados de exemplo** ao criar o projeto. O projeto executa uma primeira carga imediatamente, então a guia **Foundation** mostra um exemplo completo, incluindo uma entidade em euros convertida para dólares americanos. Quando você conecta seu próprio ERP ou adiciona seus próprios arquivos, as linhas de exemplo são apagadas e seus dados tomam o lugar delas.

## Tabelas do Common Finance Model

O Data Foundation adapta cada origem, ERP ou arquivo, às mesmas quinze tabelas, então relatórios, métricas e modelos construídos sobre elas funcionam do mesmo jeito seja qual for a origem. Cada linha também registra seu sistema de origem e quando foi lida. A coluna **Dataset** é o nome que você escolhe ao adicionar um arquivo.

| Dataset | Tabela | Contém |
|---|---|---|
| Entidades | `cfm_entity` | Entidades legais com pai, moeda local e do grupo, e país. |
| Mapeamento de entidades | `cfm_entity_map` | Códigos de entidade da origem e a entidade a que cada um pertence. Veja [Mapeamento de entidades](#mapeamento-de-entidades). |
| Taxas de câmbio | `cfm_fx_rate` | Taxas mensais média, de fechamento e histórica por par de moedas. Veja [Taxas de câmbio](#taxas-de-câmbio). |
| Calendário fiscal | `cfm_fiscal_calendar` | Uma linha por período fiscal de entidade, com datas de início e fim e se está fechado. |
| Plano de contas | `cfm_account` | Contas com pai, tipo (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), demonstração, saldo normal e tipo de taxa. |
| Departamentos | `cfm_department` | Departamentos e centros de custo com pai e centro de lucro. |
| Produtos | `cfm_product` | Cadastro mestre de produtos com pai, família, grupo, unidade de medida e custo padrão. |
| Clientes | `cfm_customer` | Cadastro mestre de clientes com pai, grupo, região e país. Os nomes dos clientes não são mascarados. |
| Valores de segmento | `cfm_segment` | Valores de segmento com nome e pai. Veja [Hierarquias](#hierarquias). |
| Razão geral | `cfm_gl_journal` | Linhas de lançamento na moeda da transação, local e de relatório. |
| Balancete | `cfm_trial_balance` | Débitos, créditos e líquido do período por entidade, conta e departamento, em moeda local e de relatório. |
| Linhas de vendas | `cfm_sales_line` | Linhas de vendas faturadas com quantidade, valores bruto, de desconto, líquido e de CPV. |
| Saldos de estoque | `cfm_inventory_balance` | Estoque no fim do período por produto e depósito. |
| Orçamento | `cfm_budget` | Orçamento e previsão por cenário, versão, conta e departamento. |
| Direcionadores de alocação | `cfm_stat_driver` | Direcionadores estatísticos, como número de funcionários, metros quadrados ou unidades. |

Os períodos são escritos como `YYYY-MM`, e as transações são colocadas pelo período de lançamento. O orçamento é opcional: um ERP sem orçamentos ainda carrega todo o resto.

Um arquivo de balancete pode trazer colunas de débito e crédito, uma coluna de líquido, ou ambas. Com apenas débito e crédito, o líquido é débito menos crédito, e um lado em branco conta como zero. Com apenas um líquido, um líquido positivo vira o débito e um líquido negativo vira o crédito, como valor positivo. Uma coluna de departamento é opcional.

## Solução de problemas

| Sintoma | O que fazer |
|---|---|
| **Testar conexão** diz que o ERP recusou as credenciais | Verifique as credenciais da conexão e se o usuário de integração consegue fazer login no ERP. |
| **Testar conexão** mostra **Permissão ausente** para um dataset | Peça ao administrador do ERP que adicione as permissões que ela nomeia. O [guia de conexão](/pt-br/guides/connections/) do seu ERP lista o que a conexão precisa. |
| Uma mensagem de erro do ERP é mais curta que a do próprio ERP | O PlaidCloud remove credenciais, tokens e chaves dos erros do provedor antes de exibi-los, então algum detalhe é omitido. Execute **Testar conexão** para ver qual dataset é afetado. |
| **Dados carregados** é um problema em um período | Uma leitura do ERP para esse período falhou. Execute **Carregar** de novo; os períodos que foram carregados são ignorados. |
| **Contas ausentes do plano de contas** é um problema | Adicione as contas ausentes ao plano de contas no ERP ou no seu arquivo e execute **Carregar** de novo. |
| **Conversão de moedas** é um problema | A moeda de uma entidade não tem taxa para a moeda de relatório nesse período, ou nenhuma moeda de relatório única foi encontrada. Adicione as taxas a um arquivo **Taxas de câmbio**, verifique se a conexão consegue ler as taxas de câmbio do ERP, ou defina a variável do projeto `reporting_currency`. Depois execute **Carregar** de novo. |
| **Conversão de moedas** requer atenção | Linhas do balanço patrimonial, do estoque ou do orçamento não têm taxa de fechamento, histórica ou planejada para o período. A demonstração do resultado não é afetada. Adicione as taxas, inclusive as taxas planejadas para os meses do orçamento, e execute **Carregar** de novo. |
| **Codes waiting for your answer** requer atenção | Clique em **Revisar**, responda a cada código e clique em **Apply changes**. |
| **Which source covers which months** requer atenção | Clique em **Choose which source counts from when**, escolha a origem e clique em **Apply changes**. |
| **Intercompany balances** está vermelho ou âmbar | Verifique os pares em **Intercompany pairs**. Lance o lado que falta, adicione o parceiro comercial às linhas ou adicione a taxa que falta. |
| **Group views are off** | Peça a um Arquiteto que marque **Everyone on the project may see the group results** em **Grupo**. |
| **Entidades não mapeadas** é um problema | Adicione a entidade ao cadastro mestre de entidades, ou mapeie o código dela para uma entidade existente no arquivo **Mapeamento de entidades**, e execute **Carregar** de novo. |
