O **Data Foundation** é a base de dados financeiros dos seus projetos PlaidCloud. O **Common Finance Model** dele reúne dados de vários sistemas ERP, e de várias instâncias de cada um, em um único modelo: um plano de contas, um conjunto de entidades e uma moeda de relatório. Relatórios, métricas e assistentes de IA criados sobre o modelo leem os mesmos números, seja qual for o ERP de origem.

Seu ERP se conecta pela conexão do PlaidCloud, então o razão geral, o balancete, os dados mestres e os orçamentos chegam diretamente da origem, sem nada para exportar. Arquivos acrescentam dados que um sistema não tem, como taxas de câmbio, direcionadores de alocação ou um orçamento mantido fora do ERP, e podem substituir as linhas do ERP que cobrem. **Carregar** padroniza cada origem no modelo, converte para a moeda de relatório e verifica se os totais batem, tudo na guia **Foundation** do projeto. Quando as origens usam o mesmo código para coisas diferentes, você informa se significam a mesma coisa, e uma consolidação gerencial monta a demonstração do resultado do grupo com as operações intercompanhia eliminadas. Modelos, como o **Enterprise Profitability**, criam seus relatórios e modelos sobre ele.

## Conectar seu ERP

Seu ERP se conecta ao Data Foundation pela conexão do PlaidCloud. O Data Foundation lê o razão geral, o balancete, os dados mestres, as taxas de câmbio e os orçamentos diretamente dele, e apenas lê. Você pode escolher uma conexão existente ou criar uma na guia. Cada sistema tem uma página para o administrador que concede o acesso, listada em [Quais sistemas podem alimentar o modelo](/pt-br/guides/projects/data-foundation-getting-started/#quais-sistemas-podem-alimentar-o-modelo), e a [Matriz de cobertura do Data Foundation](/pt-br/reference/data-foundation-coverage-matrix/) mostra quais datasets cada sistema fornece diretamente.

<Steps>

1. No Analyze, abra **Projetos** e clique em **Novo projeto**. Digite um nome e, em **Começar de**, escolha um modelo, como **Enterprise Profitability (modelo)**, em vez de **Projeto em branco**. Clique em **Criar**.

   O projeto abre na guia **Foundation**. Ele é privado para você, e você é o único Arquiteto dele, até compartilhá-lo.

2. Na guia **Foundation**, abra **Origens** e, em **Connect a system**, escolha o tipo de sistema no bloco correspondente. Em seguida, escolha uma conexão existente para ele ou escolha **Criar uma nova conexão**. Cada conexão existente lista os fluxos de trabalho que já a usam ou mostra **Ainda não usado por nenhum workflow**, e uma conexão que já é uma origem aparece como **already a source** e não pode ser escolhida novamente.

3. Para uma nova conexão, digite um **Nome da conexão**, escolha o **Ambiente** e preencha as credenciais que a conexão do seu ERP pede.

   Ainda não tem as credenciais? O formulário mostra uma solicitação de acesso pronta para o administrador do seu ERP. Clique em **Copiar solicitação** ou **Enviar solicitação por e-mail**, envie-a e digite os valores que ele devolver.

4. Clique em **Testar conexão**. O PlaidCloud faz login e tenta ler cada dataset; depois, lista cada um como **Legível**, **Permissão ausente** ou **Erro**. Quando falta algo, ele informa as permissões que você deve pedir ao administrador do ERP.

5. Defina **Meses de histórico**: quantos meses para trás carregar, de 1 a 120. O padrão é 24.

6. Para uma conexão existente, marque as entidades a carregar ou deixe todas desmarcadas para carregar todas as entidades. Entidades inativas e de eliminação ficam ocultas até você optar por exibi-las. Depois, clique em **Conectar**.

7. Para uma nova conexão, clique em **Conectar** para criá-la. Depois, marque as entidades a carregar e clique em **Conectar** novamente para salvá-las. Até fazer isso, todas as entidades são carregadas.

8. Para trazer outro sistema ERP ou outra instância, abra **Connect another system** e repita estas etapas. Conectar sempre adiciona uma origem e mantém as existentes como estão, de modo que vários sistemas ERP e instâncias podem alimentar o mesmo modelo consolidado.

</Steps>

Depois de conectado, o cartão informa qual conexão, ambiente, entidades e meses de histórico o projeto carrega.

Cada carga lê apenas o que mudou: os períodos abertos e o último período fechado são lidos novamente, e os períodos fechados já carregados são mantidos. Aumentar **Meses de histórico** lê apenas os meses acrescentados. Uma alteração em uma taxa de câmbio, no mapeamento de entidades ou na moeda de relatório lê novamente os meses afetados.

## Origens

Cada sistema ERP e instância de onde o projeto carrega dados é uma origem. A lista **Load order** na página **Origens** da guia **Foundation** mostra uma linha para cada uma, em ordem, com o nome e o sistema, **Empresas**, **Última carga**, **Linhas** e **Status**. **Empresas** mostra **Todos** ou quantas estão selecionadas. Uma origem que ainda não foi carregada mostra **Not loaded yet**. Os arquivos que você confirma também são origens.

Clique em **Editar** em uma origem para mudar como ela é usada:

| Configuração | O que faz |
|---|---|
| **Nome** | O rótulo que relatórios, perguntas de mapeamento e mensagens usam para a origem. |
| **Posição na ordem** | A posição da origem. Quando duas origens cobrem o mesmo mês da mesma empresa, vence a que estiver mais acima na ordem. |
| **Livros contábeis de relatório, separados por vírgulas** | Os livros contábeis a ler, para um sistema que mantém mais de um. **All reporting books** lê todos os livros. |
| **Empresas** | Para uma origem de sistema, quais das empresas dela (subsidiárias) a origem carrega. A lista é lida do sistema quando você abre o painel pela primeira vez e mostra as empresas que a origem carrega agora. Marque as que devem ser carregadas ou não marque nenhuma para carregar todas. Se o sistema não listar as empresas, digite os nomes delas separados por vírgulas. |
| **Empresa**, **De (2026-01)** e **Até (2026-12)** | Os meses que esta origem fornece para cada empresa. Deixe um mês vazio para não haver limite. Escreva os meses como ano e mês, por exemplo `2026-03`. |

Clique em **Salvar** para manter as alterações. Adicionar empresas, ou não marcar nenhuma, salva imediatamente. Deixar uma empresa de fora pede primeiro que você confirme **Load fewer companies?**, porque salvar apaga na hora tudo o que foi carregado daquela origem, e o próximo **Carregar** obtém novamente as empresas marcadas. Se a conexão da origem agora lê uma conta diferente daquela para a qual a origem foi configurada, o salvamento é recusado com uma mensagem informando isso, de modo que uma alteração nunca substitui outra origem. Nesse caso, reconecte essa conta como uma origem própria. Para descartar uma origem, clique em **Remove this source** e confirme em **Remover**. Tudo o que foi carregado dela é excluído, e você pode conectá-la novamente mais tarde.

Alterar as origens não lê o ERP novamente. O cartão **Última carga** mostra **Changes not applied yet** até você clicar em **Apply changes**, que executa uma carga com os dados já obtidos: padroniza novamente as origens com a nova ordem, mapeamentos, nomes e arquivos e reconstrói o modelo. Clique em **Carregar** quando também quiser dados novos dos ERPs.

## Adicionar arquivos com dados de fora do ERP

Os arquivos complementam a conexão do ERP com dados que um sistema não tem, como taxas de câmbio, direcionadores de alocação, um [Mapeamento de entidades](#mapeamento-de-entidades) ou um orçamento mantido fora do ERP. Cada arquivo pertence a um dos datasets listados em [Tabelas do Common Finance Model](#tabelas-do-common-finance-model).

<Steps>

1. Em **Arquivos**, escolha a **Conta de documentos** onde o arquivo será armazenado.

2. Solte um arquivo CSV ou Excel em **Solte aqui um arquivo CSV ou Excel** ou clique em **Escolher um arquivo**. O arquivo é enviado para a pasta `/foundation/` da conta de documentos.

   Para um arquivo que já está na conta de documentos, digite o **Caminho do arquivo**, por exemplo `/foundation/budget.csv`, e clique em **Adicionar arquivo**.

   Para ler um arquivo novo todo mês, adicione todos os arquivos de uma pasta cujo nome corresponda: digite a pasta e o que os **File names that** contêm, começam com, terminam com, correspondem exatamente ou correspondem como padrão, e clique em **Add files**. Arquivos em pastas dentro dela não são lidos.

3. O PlaidCloud lê o arquivo e propõe um mapeamento:

   - **Delimitador, separador decimal e datas detectados.** O delimitador (vírgula, ponto e vírgula, tabulação ou barra vertical), o separador decimal e o formato de data são detectados para você.
   - **Dataset**: a tabela do Common Finance Model à qual o arquivo pertence, identificada pelo nome do arquivo e pelos cabeçalhos das colunas. Quando a correspondência não está clara, escolha-a na lista.
   - **Separador decimal**: **Ponto (1,234.56)** ou **Vírgula (1.234,56)**.
   - **Formato de data**: exibido quando o arquivo tem datas. Altere-o se o formato detectado estiver errado: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Uma grade com **Coluna no arquivo**, **Tipo**, **Exemplos** e **Vai para**. Altere **Vai para** para enviar uma coluna a outro campo ou para **Não carregar**.

4. Responda às perguntas que o arquivo levantar, como **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** ou **Are revenues shown as negative numbers?** Cada uma só é feita quando o arquivo ainda não informa isso.

5. Verifique para onde vai cada coluna e clique em **Confirmar mapeamento**. Enquanto isso é processado, a nota abaixo do botão explica o motivo da espera. Em um projeto que ainda tem os dados de exemplo, o primeiro arquivo que você confirma também remove o exemplo, o que pode levar alguns minutos.

</Steps>

Estas opções aparecem em um arquivo quando se aplicam:

| Opção | Use para |
|---|---|
| **Which source do these rows apply to?** | Limitar um arquivo de mapa de códigos a uma origem. **Every source** o aplica a todas elas. |
| **Where does this file come from?** | Informar se o arquivo contém **This project's own codes** ou vem de **Another system**, ao qual você dá um nome, por exemplo `SAP Germany export`. Um arquivo de outro sistema é verificado quanto a códigos compartilhados, como uma origem ERP. |
| **Split … into … parts at each …** (em **Avançado**) | Dividir uma coluna que contém vários valores, como `100-200-300`, e enviar cada parte para o próprio campo. |
| **Which currency do you report in?** | Definir a moeda de relatório quando o projeto ainda não tem uma. Escreva-a com três letras, por exemplo `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Carregar os resultados do seu sistema de consolidação para que a demonstração do resultado do grupo possa ser [reconciliada](#reconciliar-com-o-seu-sistema-de-consolidação). |

Para retirar um arquivo do projeto, clique em **Remover** ao lado dele em **Arquivos**, ou em **Remove this file** no mapeamento dele, e confirme. Os valores dele saem dos seus relatórios na próxima vez que você clicar em **Apply changes**.

Quando o PlaidCloud não consegue decidir sozinho o dataset, o separador decimal ou a ordem das datas, por exemplo em um arquivo cujas datas podem ser lidas como dia/mês ou mês/dia, ele pede que você escolha antes de confirmar. Adicionar um segundo arquivo para o mesmo dataset substitui o primeiro. Se as colunas de um arquivo posterior não corresponderem ao dataset, a carga informa o arquivo e as colunas e pede que você corrija o arquivo ou os nomes das colunas, ou defina o **Schema Mismatch** da etapa como `union`.

Os arquivos aceitos são arquivos de texto CSV, TSV e TXT, arquivos Excel `.xlsx` (lidos a partir da primeira planilha) e arquivos Parquet.

<Aside type="note">
Um arquivo ausente ou vazio nunca interrompe uma carga. Ao adicioná-lo, você é avisado de que ainda não há nada para mapear, e a carga termina com um aviso que informa o caminho, deixando aquele dataset vazio. Adicione o arquivo novamente quando ele existir.
</Aside>

## Carregar seus dados

Clique em **Carregar** no cartão **Carregar** ou no cartão **Última carga**. A carga lê o ERP conectado e os arquivos confirmados, padroniza-os no Common Finance Model, converte-os para a moeda de relatório, executa as verificações de prontidão e reconstrói os modelos do modelo de projeto.

- Apenas uma carga é executada por projeto de cada vez. Um segundo **Carregar** ou **Apply changes** avisa que já há uma carga em execução, e você não pode alterar as origens enquanto ela é executada.
- Se outros fluxos de trabalho usam a mesma conexão de ERP, a primeira carga os lista e pede que você confirme, porque uma carga lê do ERP e pode deixar esses fluxos de trabalho mais lentos. Clique em **Carregar mesmo assim** para continuar.
- Depois de uma atualização do PlaidCloud, o **Carregar** de um Arquiteto também atualiza os fluxos de trabalho gerados do projeto, criando as tabelas de trabalho de que precisarem. Até lá, a página de status lista um item âmbar, "The workflows were generated by an earlier release. An Architect's Load updates them.", e o **Carregar** de um Gerente avisa que apenas um Arquiteto pode atualizá-los.
- Aplicar uma atualização mantém as suas próprias edições nas etapas geradas. Se você alterou uma etapa e a atualização também a alterou, sua edição é mantida e a página de status registra o conflito pelo nome da etapa. Uma etapa que você editou e que a atualização não gera mais é mantida, mas desativada; exclua-a ou reative-a se ainda precisar dela. Uma etapa que a atualização substitui é indicada pelo nome, e a anterior permanece nas versões da etapa.
- Se uma atualização parou no meio do caminho, ou ainda está em execução, a página de status informa isso, e as etapas podem ser executadas fora de ordem até ela terminar. Pressione **Carregar** novamente como Arquiteto para concluí-la. Se ela parar de novo, entre em contato com o suporte.
- Uma carga com falha aparece em vermelho e nunca fica escondida atrás de resultados anteriores. Se a consolidação falhar, o status informa a etapa em que parou, em vez de mostrar resultados antigos do grupo. Linhas de uma carga anterior mostram **De uma carga anterior. Carregue novamente.** até que uma carga seja bem-sucedida.
- Se a leitura de uma entidade e período falhar, o restante ainda é carregado. Execute **Carregar** novamente para buscar apenas o que falhou.

### Linhas retidas

Quando as origens se sobrepõem, a carga mantém uma cópia de cada valor e retém as outras, em vez de contá-las duas vezes. As linhas retidas são registradas com a origem, a entidade e o motivo, e a carga termina com um aviso que informa as quantidades, por exemplo `120 rows of NetSuite EU also provided by a source ranked ahead`. Os motivos são:

| Motivo | Significado |
|---|---|
| Em outro livro contábil | A linha pertence a um livro contábil de relatório que a origem não está configurada para ler. |
| Fora dos períodos que a origem fornece | A linha está fora dos meses **De** e **Até** definidos para a empresa. |
| Também fornecida por uma origem mais bem posicionada | Uma origem mais acima na ordem cobre a mesma empresa e o mesmo mês. |
| Também em um arquivo anterior da origem | Um arquivo anterior da mesma origem já cobre o mês. |
| Substituída por um arquivo | Um arquivo substitui as linhas do ERP para aquela entidade e mês. |
| Com um código que outra origem também usa | O código precisa da sua resposta. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| Com um código mapeado para dois códigos | O mapa de códigos dá duas respostas para o código. |

As contas estatísticas vão para os direcionadores de alocação, e não para o razão, e aparecem como movidas, não como um problema.

### Dados do ERP e arquivos juntos

Um arquivo substitui apenas o que cobre, e as demais linhas do ERP permanecem.

- **Arquivos mestres** (contas, departamentos, clientes, produtos e valores de segmento) substituem as linhas do ERP com o mesmo código.
- **Arquivos de transações** substituem as linhas do ERP para a mesma entidade e mês. Arquivos de razão geral e de balancete também correspondem por razão, arquivos de orçamento por cenário, e arquivos de direcionadores estatísticos por cenário e direcionador.

Se um arquivo deixar de cobrir um mês, os dados do ERP para esse mês voltam na próxima carga.

## Mapeamento de entidades

Cada origem identifica as entidades com os próprios códigos. O **Mapeamento de entidades** associa esses códigos às entidades do seu cadastro de entidades, para que as linhas de todas as origens caiam na mesma entidade.

Para usá-lo, adicione um arquivo CSV ou Excel e escolha o dataset **Mapeamento de entidades**:

| Coluna | Contém |
|---|---|
| `source_entity` | O código como a origem o registra, como um código de empresa. |
| `entity` | A entidade à qual pertence, com o nome usado no cadastro de entidades. |

- Um código que não está no mapeamento é usado como está.
- Vários códigos podem ser mapeados para uma entidade. As linhas deles são combinadas, e um mês conta como fechado quando estiver fechado para todos eles.
- Os códigos do mapeamento se aplicam a todas as origens, então os códigos de entidade de cada origem precisam ser exclusivos entre as origens.
- Uma linha de arquivo de **Entidades** substitui a entidade do ERP com o mesmo código de entidade.

A verificação **Entidades não mapeadas** sinaliza qualquer linha cuja entidade não esteja no cadastro de entidades nem mapeada para uma pelo mapeamento. Até que um cadastro de entidades seja carregado, ela mostra **– Não se aplica**.

## Mapear códigos entre origens

Duas origens podem usar o mesmo código para coisas diferentes, ou códigos diferentes para a mesma coisa. Quando um código aparece em mais de uma origem, o Data Foundation retém as linhas dele até você dizer se ele significa a mesma coisa em todas, para que cada valor seja contado uma só vez. A verificação **Códigos aguardando sua resposta** os lista, os 10 primeiros e depois "and K more", e o cartão **What to do next** na guia **Foundation** tem um botão **Revisar**.

**Revisar** abre **Códigos aguardando sua resposta**. Ele agrupa os códigos pelo que são: **Tipos de conta**, **Empresas**, **Contas**, **Departamentos**, **Centros de lucro**, **Clientes**, **Produtos** e cada categoria extra. Para cada código, mostra como cada origem o chama e uma sugestão:

- **Looks like the same thing** quando as origens dão ao código o mesmo nome.
- **Looks like different things** quando os nomes diferem.
- **We can't tell. Please answer.** quando não há nada em que se basear.

Responda um código de cada vez com **Yes, the same** ou **No, different**, ou responda um grupo inteiro de uma vez com **Accept all** (aceitar todas as sugestões), **All the same** ou **All different**. Para contas, você também pode responder de uma vez um grupo pai inteiro do plano. Quando uma origem não tem tipos de conta, escolha **Use this type** para um grupo de contas: **Receita**, **Custo das mercadorias vendidas**, **Despesas operacionais**, **Receitas e despesas não operacionais**, **Ativos**, **Passivos** ou **Patrimônio líquido**.

Os mapeamentos são mantidos por origem e dimensão, então uma resposta sobre os departamentos de uma origem nunca altera as contas de outra. As respostas são salvas à medida que você avança, com **Saved. Press Apply changes to use your answers.** Clique em **Apply changes** para usá-las.

Você também pode fornecer os mapeamentos em um arquivo. Adicione um arquivo com o dataset **Code map** e escolha **Which source do these rows apply to?** para limitá-lo a uma origem.

## Escolher qual origem vale a partir de quando

Quando duas origens fornecem os mesmos meses, a verificação **Qual origem cobre quais meses** pede que você escolha. Clique em **Choose which source counts from when** no cartão **What to do next** para abrir **Which source counts from when**, que lista cada sobreposição por empresa. Escolha a origem que vale, digite o mês a partir do qual ela vale em **That month is**, por exemplo `2026-04`, e clique em **Apply changes**. A outra origem fica com os meses anteriores.

A mesma caixa de diálogo avisa quando duas origens fornecem taxas de câmbio diferentes para uma moeda; são usadas as taxas da origem mais acima na ordem.

## Conversão de moedas

Cada carga converte os valores de razão geral, balancete, vendas, estoque e orçamento da moeda local para uma única moeda de relatório. Relatórios e modelos leem os valores convertidos, então entidades em moedas diferentes, de qualquer sistema, somam corretamente.

### A moeda de relatório

Para escolher a moeda de relatório, defina a variável de projeto `reporting_currency` com um código de moeda, como `USD`. Consulte [Gerenciar variáveis do projeto](/pt-br/guides/projects/managing-projects/#gerenciar-as-variáveis-do-projeto). O modelo a cria em branco. Enquanto ela estiver em branco, cada carga usa a primeira destas opções que indicar exatamente uma moeda:

1. A moeda do grupo das entidades.
2. A moeda local das entidades de nível superior, as que não têm pai.
3. A moeda local dos arquivos.

Se nenhuma delas indicar exatamente uma moeda, **Conversão de moedas** mostra um problema até você definir `reporting_currency`.

Valores que já estão na moeda de relatório permanecem como estão, então um projeto cujos dados estão todos em uma moeda não precisa de taxas.

Arquivos de vendas, estoque e orçamento também podem ter uma moeda. Mapeie uma coluna chamada `Currency` ou `Local Currency` e ela será identificada automaticamente, e os valores locais do arquivo serão convertidos para a moeda de relatório. Um valor de grupo ou de relatório que já esteja no arquivo é mantido como está. O custo-padrão dos produtos não é convertido.

### Taxas de câmbio

Uma taxa converte uma unidade de uma moeda para a moeda de relatório em um mês: o valor convertido é o valor local multiplicado pela taxa.

- **Do seu ERP**, cada carga lê as taxas de câmbio que o ERP mantém.
- **De um arquivo**, adicione um arquivo CSV ou Excel e escolha o dataset **Taxas de câmbio**. Uma taxa no arquivo substitui a taxa do ERP para as mesmas moedas e mês. Use um arquivo para gerar relatórios em uma moeda para a qual seus ERPs não publicam taxas, ou para acrescentar taxas planejadas para os meses do orçamento.

| Coluna | Contém |
|---|---|
| `from_currency` | A moeda de origem da conversão, por exemplo `EUR`. |
| `to_currency` | A moeda de relatório, por exemplo `USD`. |
| `period` | O mês, no formato `YYYY-MM`. |
| `average_rate` | A taxa média do mês. |
| `closing_rate` | A taxa no fim do mês. |
| `historical_rate` | A taxa histórica, para o patrimônio líquido e para contas configuradas com a taxa histórica. |

Quando uma moeda não tem taxa para a moeda de relatório, a taxa no sentido inverso, da moeda de relatório para ela, é invertida, com 12 casas decimais. Se isso não for possível, a taxa dela para outra moeda é multiplicada pela taxa dessa moeda para a moeda de relatório.

### Qual taxa se aplica

Cada linha é convertida a partir da própria moeda, então uma linha em uma moeda diferente da moeda da entidade é convertida a partir da moeda em que está. Aplica-se a primeira regra que se encaixa na linha:

| Linha | Taxa |
|---|---|
| Contas estatísticas e contas sem lançamento | Não convertidas. |
| Já na moeda de relatório | Não convertida. |
| Conta com um tipo de taxa | Essa taxa: média, de fechamento ou histórica. A histórica recorre à de fechamento quando não há taxa histórica. Em um ERP, o tipo de taxa é o próprio tipo de taxa da conta. Em um arquivo de plano de contas, mapeie uma coluna de tipo de taxa para `fx_rate_type` com `average`, `closing` ou `historical`. |
| Linha de vendas | A taxa média do período. |
| Saldo de estoque | A taxa de fechamento do período. |
| Linha de orçamento | Por conta, como o razão geral: a taxa média para contas de resultado e a taxa de fechamento para contas patrimoniais. |
| Conta de resultado | A taxa média do período. |
| Conta de patrimônio líquido | A taxa histórica, ou a taxa de fechamento quando não há taxa histórica. |
| Qualquer outra conta patrimonial | A taxa de fechamento do período. |

Os valores convertidos não são arredondados, então os totais não se desviam.

<Aside type="note">
O balancete contém as movimentações de cada período, então os valores patrimoniais são as movimentações de cada mês convertidas pela taxa de fechamento daquele mês. Eles não são um balanço patrimonial reconvertido pela taxa de fim de período, e não há ajuste acumulado de conversão nem eliminação intercompanhia. Use os valores convertidos para a demonstração do resultado.
</Aside>

## Hierarquias

Cada carga reconstrói as dimensões a partir dos dados mestres de todas as origens. Há sete dimensões de início e até dez categorias extras:

| Dimensão | Criada a partir de |
|---|---|
| **Entidade** | Entidades e seus pais |
| **Conta** | Plano de contas e contas pai |
| **Departamento** | Departamentos e seus pais |
| **Cliente** | Clientes e seus clientes pai |
| **Produto** | Produtos e seus produtos pai |
| **Segmento 1** | Valores de segmento para `segment_1` |
| **Segmento 2** | Valores de segmento para `segment_2` |
| **Segmento 3** a **Segmento 10** | Valores de segmento para `segment_3` a `segment_10`, quando suas origens os têm |

- Um registro sem pai, ou que indica a si mesmo como pai, é carregado como membro de nível superior.
- Como cada carga reconstrói as hierarquias, altere um pai no ERP ou no seu arquivo, não na dimensão.
- Um problema em uma hierarquia afeta apenas aquela dimensão. A carga e os modelos do modelo de projeto ainda são concluídos.
- Você pode renomear cada categoria extra conforme o que ela contém, por exemplo **Classe** ou **Região**. Em **Rename extra categories**, digite os nomes que seus relatórios usam e clique em **Save names**. Os nomes usam letras, números, espaços, pontos, hifens e sublinhados, com até 60 caracteres.
- Cada origem informa em qual dos seus nomes de categoria entra cada uma das categorias extras dela. Clique em **Editar** na origem, escolha o nome para cada uma, ou escolha **Leave out**, e clique em **Salvar**. Origens que chamam uma categoria por nomes diferentes, como `Class` e `Business area`, passam a compartilhar uma posição.

Para fornecer hierarquias de segmento a partir de um arquivo, escolha o dataset **Valores de segmento**:

| Coluna | Contém |
|---|---|
| `segment` | O segmento ao qual o valor pertence: `segment_1` a `segment_10`. |
| `segment_value` | O valor, como as linhas de razão geral, vendas e orçamento o registram. |
| `segment_value_name` | O nome dele. |
| `parent_segment_value` | O pai dele dentro do mesmo segmento. |

## Verificações de prontidão

Depois de cada carga, a grade **Prontidão** lista todas as verificações para cada entidade e período, com um destes status:

| Status | Significado |
|---|---|
| **● Pronto** | A verificação foi aprovada. |
| **▲ Requer atenção** | Vale a pena conferir, mas os números podem ser usados. |
| **■ Problema** | Corrija isto antes de confiar nos resultados. |
| **– Não se aplica** | Ainda não há dados para esta verificação. |

As verificações são:

| Verificação | O que confirma |
|---|---|
| **Dados carregados** | Todo período fiscal tem linhas de razão geral, e todas as leituras do ERP foram bem-sucedidas. Um período fechado sem linhas é um problema; um período aberto sem nenhuma requer atenção. |
| **Balancete bate com o razão geral** | O balancete é igual ao razão geral para cada entidade, período e conta. Quando tanto o balancete quanto o razão geral têm departamentos para uma conta, os totais também batem por departamento. |
| **Vendas batem com o razão geral** | As linhas de vendas são iguais às contas de receita e de CMV do razão geral em cada período. |
| **Produtos/clientes desconhecidos** | Toda linha de vendas indica um produto e um cliente que existem nos cadastros de produtos e de clientes. |
| **Contas ausentes do plano de contas** | Toda linha de razão geral indica uma conta do plano de contas. Linhas com uma conta desconhecida ficam de fora da demonstração do resultado. Uma conta com lançamentos, mas sem tipo de conta, também é um problema, e uma origem cujo plano classifica contas de receita, mas nenhuma conta de custo das mercadorias vendidas, requer atenção. |
| **Conversão de moedas** | Toda linha de razão geral, balancete, vendas, estoque e orçamento tem um valor na moeda de relatório. Uma linha de resultado ou de vendas sem taxa é um problema, porque a demonstração do resultado lê valores convertidos. Uma linha patrimonial, de estoque ou de orçamento sem taxa requer atenção. Um mês de orçamento ainda sem taxa aparece em âmbar, então carregue taxas planejadas para os meses do orçamento. Consulte [Conversão de moedas](#conversão-de-moedas). |
| **Entidades não mapeadas** | Toda linha de razão geral, balancete e vendas indica uma entidade do cadastro de entidades, diretamente ou pelo mapeamento de entidades. Não se aplica até que um cadastro de entidades seja carregado. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |

Cargas com mais de uma origem acrescentam estas verificações:

| Verificação | O que confirma |
|---|---|
| **Livro contábil de relatório** | Uma origem que tem vários livros contábeis para uma entidade teve o livro de relatório escolhido. Até você escolher, apenas o primeiro livro conta. |
| **Códigos aguardando sua resposta** | Todo código usado por mais de uma origem foi respondido. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| **Categorias extras das suas origens** | Toda categoria extra que uma origem tem recebeu um nome ou foi deixada de fora. |
| **Qual origem cobre quais meses** | Duas origens nunca fornecem os mesmos meses de uma empresa, a menos que você tenha escolhido qual vale. |
| **Tipos de conta e hierarquia** | Todo pai indicado por uma dimensão existe, e nenhum membro é o próprio pai ou ancestral. Um pai ausente coloca os filhos dele no topo da hierarquia, e um ciclo impede o carregamento daquela hierarquia. Os totais não são afetados. |
| **Calendário fiscal** | Os períodos fiscais de cada entidade são meses do calendário, e cada mês de linhas pode ser colocado em um período fiscal. Requer atenção quando os períodos de uma entidade não são meses do calendário (4-4-5, 13 períodos), ou quando as linhas de um mês podem estar em mais de um período fiscal ou o calendário fiscal não tem o mês. |

Cada linha que não está pronta informa o que fazer na coluna **O que fazer**, como carregar o plano de contas, carregar taxas de câmbio ou executar **Carregar** novamente para um período.

A grade também mostra duas verificações de configuração, que aparecem apenas quando requerem atenção:

| Verificação | Quando aparece |
|---|---|
| **Alocação de custos indiretos** | Apenas uma das variáveis de projeto `overhead_department` e `overhead_driver` está definida, ou nenhum direcionador de alocação corresponde a `overhead_driver`, então a alocação não faria nada. Defina as duas ou limpe as duas para desativar a alocação de custos indiretos. |
| **Comparação com o orçamento** | Há linhas de orçamento carregadas, mas nenhuma está na versão indicada pela variável de projeto `budget_version`, então a comparação com o orçamento ficaria vazia. |

## Consolidação gerencial

Cada carga monta uma consolidação gerencial: a demonstração do resultado do grupo com todas as entidades do grupo, na moeda de relatório, com as operações intercompanhia eliminadas. Ela se destina a relatórios gerenciais. Seu sistema de consolidação continua sendo o registro oficial do grupo para fins societários; faça a reconciliação com ele conforme descrito abaixo.

<Aside type="note">
A consolidação gerencial cobre apenas a demonstração do resultado. Ela não é uma consolidação societária ou legal, e não tem balanço patrimonial consolidado, ajuste de conversão, ágio nem participação de não controladores.
</Aside>

### Escolher o grupo

Em **Origens**, abra **Grupo** para ver as empresas do grupo. Uma empresa que você desmarcar continua nos seus relatórios individualmente, mas fica de fora do total do grupo. Clique em **Save group**. A alteração se aplica no próximo **Carregar** ou **Apply changes**. Uma empresa nova fica no grupo até você desmarcá-la.

O exercício fiscal do grupo começa no mês definido pela variável de projeto `group_fy_start_month`, que é `1`, a menos que você a altere.

### O que você obtém

| Tabela | Contém |
|---|---|
| **DRE do grupo** | Uma linha por entidade, período e linha de resultado (receita, custo das mercadorias vendidas, despesas operacionais, não operacional, diferença intercompanhia), na moeda de relatório. Receitas e custos mantêm o sinal natural. |
| **DRE do grupo acumulada no ano** | O mesmo, acumulado no ano, até o último período totalmente carregado do grupo. |
| **Pares intercompanhia** | Uma linha por par de entidades, grupo e período, com o valor de cada lado e o resíduo. |
| **Linhas intercompanhia** | As linhas do razão por trás de um valor do grupo ou de um par, com o parceiro comercial. |
| **Reconciliação** | A DRE do grupo acumulada no ano comparada com o seu sistema de consolidação. |

Três nomes de entidade aparecem nestas tabelas:

| Entidade | Significado |
|---|---|
| **Eliminations** | As eliminações intercompanhia. Elas se anulam, então mantenha-as para os valores do grupo e filtre-as para obter a soma das entidades antes da eliminação. |
| **Group total** | O total do sistema de consolidação, na reconciliação. |
| **Unmapped** | Linhas sem período, e contas ou entidades do seu sistema de consolidação que este projeto não tem. |

As métricas **Consolidated income**, **Consolidated result** e **IC difference**, e um caminho de análise para cada tabela, respondem a perguntas sobre o grupo.

### Eliminações intercompanhia

As linhas intercompanhia são correspondidas pelo parceiro comercial. É usado o parceiro da linha; quando a linha não tem um, é usado o parceiro do cliente dela. Os dois lados de um par são eliminados, e o valor pelo qual os dois lados não batem é lançado em uma linha de diferença intercompanhia. Cada par recebe um motivo:

| Motivo | Significado |
|---|---|
| **Correspondente** | Os dois lados lançaram o mesmo valor. |
| **Apenas um lado lançou** | Uma entidade lançou a transação e o parceiro dela não. |
| **Não eliminado** | Uma linha do par não tem taxa de câmbio, então nenhum dos lados é eliminado. |

Um par é avaliado pelo acumulado no ano. A linha **Intercompany balances** fica âmbar quando a diferença de um par passa da variável de projeto `group_amber` (padrão `1`) e vermelha acima de `group_red` (padrão `1000`). Linhas sem parceiro, ou com um parceiro que não é uma entidade, não são eliminadas e são contadas nessa linha. Uma origem que tem parceiros ao lado de outra que não tem aparece em âmbar.

As entidades de eliminação da própria origem ficam fora da DRE do grupo, e a linha **Consolidação** informa isso.

### Reconciliar com o seu sistema de consolidação

Adicione como arquivo os resultados que o seu sistema de consolidação informa e marque **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** ao confirmar o mapeamento. Responda a **Which version of the numbers is this?** com o nome do sistema. A tabela **Reconciliação** passa então a mostrar **nosso**, **reportado** e **diferença** para cada entidade e linha, no acumulado do ano. Uma diferença normalmente é explicada nas linhas **Eliminations**, **Group total** e **Unmapped**, ou pelas taxas de câmbio que o sistema usa. A linha **Reconciliation to the source** lista cada linha acima de `group_amber`.

### Quem pode ver

Os resultados do grupo seguem o acesso às linhas do projeto. Quando o acesso às linhas bloqueia os resultados do grupo, o status aparece em âmbar. Uma pessoa que vê apenas algumas entidades vê as somas dessas entidades antes da eliminação. As linhas **Eliminations** e as tabelas intercompanhia exigem acesso a todas as entidades.

Se o projeto limita quem vê quais linhas por uma coluna que as tabelas do grupo não têm, como departamento, os resultados do grupo ficam desativados para todos e **Consolidação** mostra **Group views are off**. Nesse caso, apenas um Arquiteto pode marcar **Everyone on the project may see the group results** em **Grupo**. A alteração se aplica no próximo **Carregar** ou **Apply changes**.

## Manter atualizado

Depois que uma carga da conexão do ERP é bem-sucedida sem problemas, **Atualizar toda noite** aparece no cartão **Última carga**. Clique nele para executar **Carregar** todas as noites às 2:00 no seu fuso horário. O cartão passa a mostrar **Nightly refresh: Every night at 2:00** e quem o configurou.

A carga noturna é executada como a pessoa que a configurou. Se essa pessoa não puder mais usar a conexão do ERP, a grade informa que a carga noturna foi ignorada; configure-a novamente. Um projeto que tem apenas dados de exemplo não pode ser agendado.

Um arquivo ausente ou vazio em uma carga noturna termina com um aviso que informa o caminho, não com um erro, e o restante do modelo ainda é carregado.

## Nomes de negócio

**Business names**, em **Names** na página **Origens** da guia **Foundation**, dão aos códigos do seu modelo os nomes que a sua empresa usa. Relatórios, métricas e o assistente mostram esses nomes, e um nome salvo se aplica imediatamente. As cargas posteriores o mantêm.

1. Clique em **Add a name** e escolha o **Tipo**: **Categoria**, **Linha da DRE**, **Métrica** ou **Coluna**.
2. Digite o **Código**: `segment_1` a `segment_10` para uma categoria, a chave da linha para uma linha da DRE, o nome da métrica, ou `table.column` para uma coluna.
3. Digite o **Nome**, com no máximo 60 caracteres em uma linha.
4. Clique em **Save names**.

Salvar substitui a lista inteira. Uma linha com nome vazio remove aquele nome, e **Remover selecionados** remove as linhas que você marcar. Nomear o mesmo código duas vezes é recusado. Os nomes de negócio também são gravados na descrição do caminho de análise para que o assistente use as suas palavras, e essa descrição tem um limite de tamanho: se um nome a deixar longa demais, nada é salvo e você é avisado.

## Explicar um número

**Explain this number** mostra o que compõe um valor da demonstração do resultado. Na grade **Prontidão**, uma linha de uma entidade e mês tem **Explain this number**, que abre a margem operacional da entidade naquele mês. A janela divide o número em camadas que somam o total mostrado no topo:

| Camada | O que contém |
|---|---|
| **From the general ledger** | O que o razão lançou na linha. |
| **Allocated in** | Custo distribuído para esta entidade pelas suas [regras de alocação](#regras-de-alocação). |
| **Allocated out** | Custo que esta entidade distribuiu para outras. |
| **Eliminated in the group** | Operações intercompanhia eliminadas no resultado do grupo. |

Cada camada tem uma frase que diz o que ela é e quais são os maiores documentos de origem, com o sistema de origem, o documento e a conta. Apenas as camadas que têm linhas são mostradas. A janela segue o seu acesso às linhas: você só explica os valores que pode ver. Um número sem nada por trás mostra **Nothing to explain**.

## Regras de alocação

As alocações distribuem custos compartilhados, como custos indiretos, para departamentos, produtos e clientes. O modelo tem duas fases: **Stage 1: overhead to departments** e **Stage 2: departments to products and customers**. Abra **Ações > Alocações...** para ver ou alterar como cada uma é feita. Sem alterações, elas funcionam como antes de o assistente existir. Um leitor pode abrir as regras, mas não salvá-las.

Para cada fase, o assistente faz quatro perguntas:

| Etapa | Pergunta | Opções |
|---|---|---|
| **Conjunto** | Quais custos você quer distribuir? | O tipo de conta e, na fase 1, o departamento que contém o custo, ou **All departments**. |
| **Direcionador** | Por qual critério você quer distribuí-los? | **Statistic** que você carregou como direcionadores de alocação, como número de funcionários ou metros quadrados, **Net sales amount**, **Sales quantity** ou **Spread evenly**. Use o direcionador de **Same period** ou **Same period last year**. |
| **Destino** | Para onde eles vão? | Fase 1: departamentos. Fase 2: produtos, clientes ou ambos. |
| **Método** | O que acontece quando um direcionador é negativo? | **Ignore negative values** ou **Stop and tell me**. |

Abaixo das etapas, **Preview for** um mês, escrito como ano e mês, por exemplo `2026-09`, mostra o que as regras, inclusive as que você ainda não salvou, fariam: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Qualquer valor não alocado é custo que não teve direcionador para recebê-lo. A pré-visualização segue o seu acesso às linhas.

Clique em **Salvar**. As regras entram em vigor no próximo **Carregar** ou quando você clicar em **Apply changes**. Se você editou uma etapa de alocação manualmente, sua edição é mantida, não sobrescrita, e o salvamento a indica pelo nome. Não é possível salvar enquanto uma carga está em execução.

## Pacote para a diretoria

Um pacote para a diretoria grava seus resultados em uma pasta de uma conta de documentos, pronto para enviar. Abra **Ações > Pacote para a diretoria...**, escolha uma **Conta de documentos** e uma **Pasta**, como `/board-packs`, e clique em **Salvar**. A partir daí, cada **Carregar** gera o pacote, então os arquivos da pasta estão tão atualizados quanto a última carga. Cada execução grava:

- Uma pasta de trabalho do Excel, `Board pack.xlsx`, com a demonstração do resultado por entidade, uma ponte de margem e os principais e piores clientes.
- Um PDF do painel da demonstração do resultado.

Clique em **Run now** para gerar um pacote imediatamente; os arquivos dele aparecem na pasta quando termina. A caixa de diálogo mostra a última execução e o resultado dela, e a próxima execução. **Apply changes** não gera um pacote. Para gerar um todas as noites, configure a atualização noturna (consulte [Manter atualizado](#manter-atualizado)); até lá, a caixa de diálogo mostra **Not scheduled yet**. Apenas quem pode alterar o projeto pode configurá-lo.

Um pacote que não pode ser gerado por completo nunca faz a carga falhar:

- Se os relatórios estiverem desativados no seu espaço de trabalho, o pacote contém apenas a pasta de trabalho do Excel, e a execução mostra **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- Se um painel criado por outra pessoa já tiver o endereço de que o Data Foundation precisa para o painel da demonstração do resultado, esse painel é mantido como está e o PDF não é gerado. A mensagem informa o endereço; dê outro endereço ao outro painel e execute **Carregar** novamente.
- Se alguma etapa do pacote falhar, a lista **Status** mostra uma linha âmbar **Pacote para a diretoria** que indica a etapa e o motivo. A carga em si foi bem-sucedida.

## Pontos de restauração

Um ponto de restauração é criado no início de cada **Carregar** ou **Apply changes**, seja quem for que o inicie, inclusive uma carga agendada, e antes de cada alteração em mapeamentos ou origens. Ele contém as tabelas do modelo, as dimensões e as configurações a partir das quais a próxima carga é feita: suas origens, arquivos e regras de alocação. São mantidos os últimos sete pontos criados para cargas e os últimos cinco criados antes de alterações, então as alterações nunca descartam os pontos criados para cargas. Os pontos mais antigos são descartados.

Para voltar, abra **Ações > Restaurar...**. Cada ponto mostra quando foi criado e, abaixo, quantas tabelas a restauração traz de volta, por exemplo **Puts back 12 tables.**, além de eventuais avisos. Escolha um ponto e clique em **Restaurar**. **Restaurar** fica disponível quando existe um ponto. A restauração primeiro registra o projeto como está agora em um ponto próprio, para que você possa voltar novamente. Depois, ela devolve as tabelas, as dimensões e essas configurações ao estado anterior, e a próxima carga parte delas. Restaurar para as origens que você já tinha não as marca como alteradas. Uma visão, uma dimensão que não pode ser salva ou uma tabela sem cópia salva é indicada em um aviso, e o restante é restaurado. Um ponto de restauração já descartado é recusado, e não é possível restaurar enquanto uma carga está em execução.

## Clonar um projeto

**Ações > Clonar...** copia o projeto com um nome que você informa. A cópia mantém o modelo de projeto, suas edições no modelo e suas métricas e caminhos de análise, e carrega os dados de exemplo. As origens dela não ficam conectadas, então conecte-as na cópia antes de carregar. Você pode continuar trabalhando enquanto a cópia é feita, e **Abrir projeto** leva você até ela quando estiver pronta.

## Salvar como meu modelo

Salve a configuração de um projeto para reutilizá-la com o próximo cliente ou entidade. Abra **Ações > Salvar como meu modelo...**, escolha a conta de documentos e dê um nome ao arquivo. Se você não incluir `.zip` no final do nome, ele é acrescentado. Salvar sobre um arquivo existente é recusado, então escolha outro nome.

O arquivo contém a estrutura do projeto, suas edições no modelo, métricas e caminhos de análise, os nomes de negócio de entidades e contas, e as linhas das tabelas de configuração do modelo de projeto, como o mapa de atividades do [Cost to Serve](/pt-br/guides/projects/cost-to-serve/) ou as faixas da política do [Operational Transfer Pricing](/pt-br/guides/projects/operational-transfer-pricing/). Ele deixa de fora conexões, arquivos, o agendamento noturno, execuções, pontos de restauração, o pacote para a diretoria e quem tem acesso.

Para usá-lo, crie um projeto, escolha **From a template file...** em **Começar de** e selecione a conta de documentos e o caminho. O novo projeto é privado para você, com todas as origens aguardando conexão. Uma versão posterior do modelo mescla as alterações dela ao redor das etapas que você editou. Se não houver arquivo no caminho, nada é criado e você é avisado. Qualquer pessoa que possa ler a conta de documentos pode instalar a partir do arquivo. Para usá-lo em outro espaço de trabalho, baixe o arquivo e envie-o lá.

## Resolver perguntas em aberto com o Ask

Depois de uma carga, um projeto ainda pode estar aguardando três informações: contas que o plano deixa sem tipo, códigos usados por mais de uma origem e colunas dos seus arquivos que não corresponderam a nada. Peça ao assistente para resolvê-las: em um assistente de IA via MCP, use o prompt **Resolve Data Foundation residue**. Ele lê o que está pendente e propõe uma resposta para cada item, com um motivo.

O assistente não grava nada. Você aplica as respostas dele onde você mesmo teria respondido: contas e códigos em **Códigos aguardando sua resposta**, e colunas de arquivo no mapeamento do arquivo. Ele nunca propõe uma entidade.

## Entregar o projeto

A lista de verificação **Configuração** tem quatro itens finais depois de **Revise suas hierarquias**:

- **Configure a atualização noturna** é concluído quando **Atualizar toda noite** está ativado.
- **Compartilhe com sua equipe** é concluído quando alguém além da pessoa que configurou o projeto é membro dele.
- **Baixe o pacote de evidências** é concluído quando você baixa o pacote depois da última carga bem-sucedida.
- **Entregue o projeto ao proprietário** é concluído quando existe um Arquiteto diferente da pessoa que o configurou e os totais batem. Enquanto não estiver concluído, a lista de verificação diz o que fazer: torne o proprietário do cliente um Arquiteto deste projeto e depois remova-se dos membros.

A lista de verificação informa quem configurou o projeto (**Set up by**).

## Construir sobre o modelo com um modelo de projeto

Um modelo de projeto cria seus relatórios e modelos sobre o Common Finance Model, então eles funcionam da mesma forma, sejam quais forem os ERPs que o alimentam. Quando você inicia um projeto a partir de um modelo, como o **Enterprise Profitability**, ele cria:

- As [tabelas do Common Finance Model](#tabelas-do-common-finance-model), vazias ou preenchidas com dados de exemplo.
- As dimensões **Entidade**, **Conta**, **Departamento**, **Cliente**, **Produto**, **Segmento 1** e **Segmento 2**, criadas a partir dessas tabelas. Consulte [Hierarquias](#hierarquias).
- O fluxo de trabalho **Carregar** e os fluxos de trabalho que ele executa para ler o ERP e os arquivos, padronizá-los, verificar a prontidão e montar os modelos do modelo de projeto.
- Os relatórios e modelos próprios do modelo de projeto. O **Enterprise Profitability** acrescenta uma tabela de demonstração do resultado com receita, CMV, margem bruta, despesas operacionais diretas e indiretas, margem de contribuição e margem operacional, além de pontes de margem ano contra ano e contra o orçamento.
- Métricas e um caminho de análise para fazer perguntas sobre os resultados.

Três modelos estão disponíveis em **Começar de**, cada um construído sobre o mesmo modelo:

| Modelo | Acrescenta |
|---|---|
| **Enterprise Profitability** | A demonstração do resultado e as pontes de margem. |
| **Cost to Serve** | O custo de atender cada cliente e a margem depois dele. Consulte [Cost to Serve](/pt-br/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | O nível de lucro de cada entidade comparado com a faixa da sua política, e o ajuste (true-up). Consulte [Operational Transfer Pricing](/pt-br/guides/projects/operational-transfer-pricing/). |

**From a template file...** começa a partir de um projeto que você salvou. Consulte [Salvar como meu modelo](#salvar-como-meu-modelo).

Para explorar antes de conectar o seu próprio ERP, marque **Começar com dados de exemplo** ao criar o projeto. O projeto executa uma primeira carga imediatamente, então a guia **Foundation** mostra um exemplo completo, incluindo uma entidade em euros convertida para dólares americanos. Quando você conecta o seu próprio ERP ou adiciona os seus próprios arquivos, o exemplo é removido e os seus dados ocupam o lugar dele. Se a remoção for interrompida, o próximo **Carregar** a conclui. Uma pasta sua chamada `sample` nunca é removida: a página de status informa que o exemplo ocupa essa pasta, de modo que as outras tabelas dela não são lidas, e pede que você as mova para uma pasta com outro nome.

## A guia Foundation

A guia **Foundation** é onde você conecta, carrega e verifica seus dados. Uma barra à esquerda lista quatro páginas:

| Página | O que mostra |
|---|---|
| **Status** | O estado do projeto: **Última carga** com os botões **Carregar**, **Apply changes**, **Atualizar** e **Atualizar toda noite**, **What to do next**, a lista de verificação **Configuração**, **Dados carregados**, **Períodos**, **Prontidão** e o menu **Ações**. |
| **Respostas necessárias** | As perguntas que aguardam você, como códigos usados por mais de uma origem, em que você diz se significam a mesma coisa. |
| **Cobertura das origens** | Onde as origens se sobrepõem ou deixam lacunas para uma empresa e mês, e qual origem vale a partir de quando. |
| **Origens** | Cada origem em **Load order**, com **Editar** e **Remove this source**, os cartões **Grupo** e **Names**, e **Connect a system** (ou **Connect another system**), onde você escolhe um tipo de sistema, escolhe a conexão dele, as empresas e quantos meses de histórico carregar, ou adiciona um arquivo. Os arquivos que você adicionou ficam no cartão **Arquivos**. |

Os indicadores na barra contam o que requer atenção: as perguntas em aberto em **Respostas necessárias**, os problemas de cobertura em **Cobertura das origens** e as origens em **Origens**. **Status** não mostra indicador. O resultado de um **Carregar** ou **Apply changes** e a faixa de status aparecem acima da página que estiver aberta, então você os vê em todas as páginas. Os botões em **Status** que apontam para uma pergunta ou um problema de cobertura, como **Revisar**, levam você até aquela página. Fechar **Respostas necessárias** ou **Cobertura das origens** leva você de volta a **Status**.

Quando você altera as origens, uma barra acima de todas as páginas mostra **You have changed your sources. Press Apply changes to use them.** Ela tem **Show what changed** e **Apply changes** e é o único lugar para aplicar uma alteração. Quando não há nada aguardando aplicação, **Carregar** é o botão principal em **Status**. Em **Status**, **What to do next** lista primeiro os problemas e depois os itens que requerem atenção, numerados ao longo dos dois grupos. Em **Respostas necessárias**, **Answer all** oferece **Accept suggestions**, **All the same** e **All different**. Em **Cobertura das origens**, **Save choice** mantém qual origem vale a partir de quando.

A lista de verificação **Configuração** é: **Conectar seus dados**, **Carregue seus dados**, **Verificar se os totais batem**, **Revise suas hierarquias**, **Configure a atualização noturna**, **Compartilhe com sua equipe**, **Baixe o pacote de evidências** e **Entregue o projeto ao proprietário**. O item atual fica em negrito. Os nomes de negócio, os arquivos que você adicionou e o estado do mapeamento deles (**✓ Confirmado** ou **○ Aguardando confirmação**), e a grade de prontidão com uma linha por entidade, período e verificação e o respectivo **O que fazer**, ficam nas mesmas páginas. Consulte [Nomes de negócio](#nomes-de-negócio).

Enquanto uma carga é executada, a guia se atualiza sozinha e continua lendo mesmo que uma leitura falhe. Se não for possível ler o status, aparece **Não foi possível ler o status do Foundation.** com **Tentar novamente**, que lê o status de novo; a guia também tenta novamente uma vez por conta própria antes de mostrar a mensagem, e a mensagem desaparece quando o servidor responde.

A página **Status** também informa:

- Uma pasta em `/sources/` cujas tabelas não têm as colunas necessárias não é adicionada como origem. Uma nota indica cada tabela deixada de fora e a coluna que falta. Adicione a coluna e pressione **Carregar** ou **Apply changes**.
- Se uma carga foi bem-sucedida, mas não trouxe linhas de razão para comparar, uma linha âmbar **Model P&L ties to GL** informa que nada foi conciliado. **Verificar se os totais batem** fica pendente na lista de verificação de configuração, e não concluído, até que algo tenha sido conciliado. Adicione uma origem com linhas de razão e pressione **Carregar**.

A lista de verificação de configuração acompanha o seu progresso:

- **Conectar seus dados** e **Carregue seus dados** são marcados automaticamente quando uma origem é anexada e uma carga é bem-sucedida.
- **Verificar se os totais batem** é marcado automaticamente quando as verificações de conciliação são aprovadas.
- **Revise suas hierarquias**: clique em **Abrir dimensões** para revisar as hierarquias de entidade, conta e departamento e depois marque **Eu já revisei**. Você mesmo confirma este item.
- **Configure a atualização noturna**, **Compartilhe com sua equipe**, **Baixe o pacote de evidências** e **Entregue o projeto ao proprietário** encerram a lista. Consulte [Entregar o projeto](#entregar-o-projeto) e [Gerenciar o acesso ao projeto](/pt-br/guides/projects/managing-projects/#gerenciar-o-acesso-ao-projeto).

O menu **Ações** contém **Alocações...**, **Pacote para a diretoria...**, **Clonar...**, **Restaurar...** e **Salvar como meu modelo...**. Consulte [Regras de alocação](#regras-de-alocação), [Pacote para a diretoria](#pacote-para-a-diretoria), [Clonar um projeto](#clonar-um-projeto), [Pontos de restauração](#pontos-de-restauração) e [Salvar como meu modelo](#salvar-como-meu-modelo).

## Tabelas do Common Finance Model

O Data Foundation padroniza cada origem, seja ERP ou arquivo, nas mesmas quinze tabelas, para que relatórios, métricas e modelos criados sobre elas funcionem da mesma forma, seja qual for a origem. Cada linha também registra o sistema de origem e quando foi lida. A coluna **Dataset** é o nome que você escolhe ao adicionar um arquivo.

| Dataset | Tabela | Contém |
|---|---|---|
| Entidades | `cfm_entity` | Entidades legais com pai, moeda local e do grupo, e país. |
| Mapeamento de entidades | `cfm_entity_map` | Códigos de entidade da origem e a entidade à qual cada um pertence. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |
| Taxas de câmbio | `cfm_fx_rate` | Taxas mensais médias, de fechamento e históricas por par de moedas. Consulte [Taxas de câmbio](#taxas-de-câmbio). |
| Calendário fiscal | `cfm_fiscal_calendar` | Uma linha por período fiscal de cada entidade, com datas de início e fim e se está fechado. |
| Plano de contas | `cfm_account` | Contas com pai, tipo (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), demonstrativo, saldo normal e tipo de taxa. |
| Departamentos | `cfm_department` | Departamentos e centros de custo com pai e centro de lucro. |
| Produtos | `cfm_product` | Cadastro de produtos com pai, família, grupo, unidade de medida e custo-padrão. |
| Clientes | `cfm_customer` | Cadastro de clientes com pai, grupo, região e país. Os nomes dos clientes não são mascarados. |
| Valores de segmento | `cfm_segment` | Valores de segmento com nome e pai. Consulte [Hierarquias](#hierarquias). |
| Razão geral | `cfm_gl_journal` | Linhas de lançamento na moeda da transação, na moeda local e na moeda de relatório. |
| Balancete | `cfm_trial_balance` | Débitos, créditos e saldo líquido do período por entidade, conta e departamento, na moeda local e na moeda de relatório. |
| Linhas de vendas | `cfm_sales_line` | Linhas de vendas faturadas com quantidade e valores bruto, de desconto, líquido e de CMV. |
| Saldos de estoque | `cfm_inventory_balance` | Estoque de fim de período por produto e depósito. |
| Orçamento | `cfm_budget` | Orçamento e previsão por cenário, versão, conta e departamento. |
| Direcionadores de alocação | `cfm_stat_driver` | Direcionadores estatísticos, como número de funcionários, metros quadrados ou unidades. |

Os períodos são escritos como `YYYY-MM`, e as transações são posicionadas pelo período de lançamento. O orçamento é opcional: um ERP sem orçamentos ainda carrega todo o restante.

Um arquivo de balancete pode ter colunas de débito e crédito, uma coluna de saldo líquido, ou ambas. Com apenas débito e crédito, o saldo líquido é o débito menos o crédito, e um lado em branco conta como zero. Com apenas o saldo líquido, um valor positivo se torna débito e um valor negativo se torna crédito, como valor positivo. Uma coluna de departamento é opcional.

## Solução de problemas

| Sintoma | O que fazer |
|---|---|
| **Testar conexão** informa que o ERP recusou as credenciais | Verifique as credenciais da conexão e se o usuário de integração consegue fazer login no ERP. |
| **Testar conexão** mostra **Permissão ausente** para um dataset | Peça ao administrador do ERP que adicione as permissões indicadas. O [guia de conexão](/pt-br/guides/connections/) do seu ERP lista o que a conexão precisa. |
| Uma mensagem de erro do ERP é mais curta do que a do próprio ERP | O PlaidCloud remove credenciais, tokens e chaves dos erros do provedor antes de exibi-los, então alguns detalhes ficam de fora. Execute **Testar conexão** para ver qual dataset é afetado. |
| **Dados carregados** é um problema para um período | Uma leitura do ERP para aquele período falhou. Execute **Carregar** novamente; os períodos já carregados são ignorados. |
| **Contas ausentes do plano de contas** é um problema | Adicione as contas que faltam ao plano de contas no ERP ou no seu arquivo e execute **Carregar** novamente. |
| **Conversão de moedas** é um problema | A moeda de uma entidade não tem taxa para a moeda de relatório naquele período, ou não foi encontrada uma única moeda de relatório. Adicione as taxas a um arquivo de **Taxas de câmbio**, verifique se a conexão consegue ler as taxas de câmbio do ERP ou defina a variável de projeto `reporting_currency`. Depois, execute **Carregar** novamente. |
| **Conversão de moedas** requer atenção | Linhas patrimoniais, de estoque ou de orçamento não têm taxa de fechamento, histórica ou planejada para o período. A demonstração do resultado não é afetada. Adicione as taxas, incluindo taxas planejadas para os meses do orçamento, e execute **Carregar** novamente. |
| **Códigos aguardando sua resposta** requer atenção | Clique em **Revisar**, responda a cada código e clique em **Apply changes**. |
| **Qual origem cobre quais meses** requer atenção | Clique em **Choose which source counts from when**, escolha a origem e clique em **Apply changes**. |
| **Intercompany balances** está vermelho ou âmbar | Verifique os pares em **Pares intercompanhia**. Lance o lado que falta, adicione o parceiro comercial às linhas ou adicione a taxa que falta. |
| **Group views are off** | Peça a um Arquiteto que marque **Everyone on the project may see the group results** em **Grupo**. |
| **Entidades não mapeadas** é um problema | Adicione a entidade ao cadastro de entidades, ou mapeie o código dela para uma entidade existente no arquivo de **Mapeamento de entidades**, e execute **Carregar** novamente. |
