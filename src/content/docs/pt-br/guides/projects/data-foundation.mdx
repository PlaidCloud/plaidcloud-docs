O **Data Foundation** é a base de dados financeiros dos seus projetos do PlaidCloud. Seu **Common Finance Model** reúne dados de ERP de vários sistemas de ERP, e de várias instâncias de cada um, em um único modelo: um plano de contas, um conjunto de entidades e uma moeda de relatório. Relatórios, métricas e assistentes de IA criados sobre o modelo leem os mesmos números, seja qual for o ERP de origem.

Seu ERP se conecta pela conexão dele no PlaidCloud, de modo que o razão geral, o balancete, os dados mestres e os orçamentos chegam diretamente da origem, sem nada para exportar. Os arquivos acrescentam dados que um sistema não contém, como taxas de câmbio, direcionadores de alocação ou um orçamento mantido fora do ERP, e podem substituir as linhas do ERP que cobrem. **Carregar** adapta cada origem ao modelo, converte-a para a moeda de relatório e verifica se os totais batem, tudo a partir da guia **Foundation** do projeto. Quando as origens usam o mesmo código para coisas diferentes, você diz se elas significam a mesma coisa, e uma consolidação gerencial constrói a demonstração do resultado do grupo com as transações entre empresas do grupo eliminadas. Os modelos, como o **Enterprise Profitability**, constroem seus relatórios e modelos de cálculo sobre ele.

## Conecte seu ERP

Seu ERP se conecta ao Data Foundation pela conexão dele no PlaidCloud. O Data Foundation lê diretamente dela o razão geral, o balancete, os dados mestres, as taxas de câmbio e os orçamentos, e só faz leitura. Você pode escolher uma conexão existente ou criar uma na guia; os [guias de conexão](/pt-br/guides/connections/) abordam a configuração de acesso de cada ERP.

<Steps>

1. No Analyze, abra **Projetos** e clique em **Novo projeto**. Digite um nome e, em **Começar de**, escolha um modelo, como **Enterprise Profitability (modelo)**, em vez de **Projeto em branco**. Clique em **Criar**.

   O projeto abre na guia **Foundation**. Ele é privado para você, e você é o único Arquiteto dele, até compartilhá-lo.

2. Na guia **Foundation**, escolha uma conexão existente para o seu ERP ou selecione **Criar uma nova conexão**. Cada conexão existente lista os fluxos de trabalho que já a usam, ou informa **Ainda não usado por nenhum workflow**.

3. Para uma nova conexão, digite um **Nome da conexão**, escolha o **Ambiente** e preencha as credenciais que a conexão do seu ERP solicita.

   Ainda não tem as credenciais? O formulário mostra uma solicitação de acesso pronta para o administrador do seu ERP. Clique em **Copiar solicitação** ou **Enviar solicitação por e-mail**, envie-a e digite os valores que ele devolver.

4. Clique em **Testar conexão**. O PlaidCloud faz login e tenta ler cada dataset, depois lista cada um como **Legível**, **Permissão ausente** ou **Erro**. Quando algo está faltando, ele indica as permissões que você deve pedir ao administrador do ERP para adicionar.

5. Defina **Meses de histórico**: quantos meses para trás carregar, de 1 a 120. O padrão é 24.

6. Para uma conexão existente, marque as entidades a carregar ou deixe todas desmarcadas para carregar todas as entidades. As entidades inativas e de eliminação ficam ocultas até você optar por mostrá-las. Depois clique em **Conectar**.

7. Para uma nova conexão, clique em **Conectar** para criá-la. Depois marque as entidades a carregar e clique em **Conectar** novamente para salvá-las. Até você fazer isso, todas as entidades são carregadas.

8. Para trazer outro sistema de ERP ou outra instância, repita estas etapas e marque **Add this as another source instead of replacing the current one** antes de clicar em **Conectar**. Sem isso, a nova conexão substitui a origem atual.

</Steps>

Depois de conectado, o cartão informa qual conexão, ambiente, entidades e meses de histórico o projeto carrega.

Cada carga lê apenas o que mudou: os períodos abertos e o último período fechado são lidos novamente, e os períodos fechados já carregados são mantidos. Aumentar **Meses de histórico** lê apenas os meses acrescentados. Uma taxa de câmbio, um mapeamento de entidades ou uma moeda de relatório alterados leem novamente os meses que afetam.

## Origens

Cada sistema e instância de ERP de que o projeto carrega dados é uma origem. A lista **Origens** na guia **Foundation** mostra uma linha para cada uma, em ordem, com seu nome, quando foi carregada pela última vez e quantas linhas forneceu, e os livros de relatório que ela lê, por exemplo `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Uma origem que ainda não foi carregada informa **not loaded yet**. Os arquivos que você confirma também são origens.

Abra **Avançado** em uma origem para mudar como ela é usada:

| Configuração | O que ela faz |
|---|---|
| **Nome** | O rótulo que os relatórios, as perguntas de mapeamento e as mensagens usam para a origem. |
| **Place in the order** | Onde a origem se classifica. Quando duas origens cobrem o mesmo mês da mesma empresa, a que está mais acima na ordem prevalece. |
| **Reporting books, separated by commas** | Os livros contábeis a ler, para um sistema que mantém mais de um. **All reporting books** lê todos os livros. |
| **Empresa**, **De (2026-01)** e **Até (2026-12)** | Os meses que esta origem fornece para cada empresa. Deixe um mês vazio para não ter limite. Escreva os meses como ano e mês, por exemplo `2026-03`. |

Clique em **Salvar** para manter suas alterações. Para descartar uma origem, clique em **Remove this source** e confirme **Remover**. Tudo o que foi carregado dela é excluído, e você pode conectá-la novamente depois.

Alterar origens não lê o seu ERP novamente. O cartão **Última carga** informa **Changes not applied yet** até você clicar em **Apply changes**, que executa uma carga a partir dos dados já extraídos: ele adapta as origens novamente com a nova ordem, os mapeamentos, os nomes e os arquivos, e reconstrói o modelo. Clique em **Carregar** quando também quiser dados novos dos ERPs.

## Adicione arquivos para dados fora do seu ERP

Os arquivos complementam a conexão do seu ERP com dados que um sistema não contém, como taxas de câmbio, direcionadores de alocação, um [Mapeamento de entidades](#mapeamento-de-entidades) ou um orçamento mantido fora do ERP. Cada arquivo pertence a um dos datasets listados em [Tabelas do Common Finance Model](#tabelas-do-common-finance-model).

<Steps>

1. Em **Arquivos**, escolha a **Conta de documentos** em que o arquivo será armazenado.

2. Solte um arquivo CSV ou Excel em **Solte aqui um arquivo CSV ou Excel**, ou clique em **Escolher um arquivo**. O arquivo é enviado para a pasta `/foundation/` da conta de documentos.

   Para um arquivo que já está na conta de documentos, digite o **Caminho do arquivo**, por exemplo `/foundation/budget.csv`, e clique em **Adicionar arquivo**.

   Para ler um arquivo novo todo mês, adicione todos os arquivos de uma pasta cujo nome corresponda: digite a pasta e o que **File names that** contenham, comecem com, terminem com, correspondam exatamente ou correspondam como padrão, e clique em **Add files**. Os arquivos em pastas dentro dela não são lidos.

3. O PlaidCloud lê o arquivo e propõe um mapeamento:

   - **Delimitador, separador decimal e datas detectados.** O delimitador (vírgula, ponto e vírgula, tabulação ou barra vertical), o separador decimal e o formato de data são detectados para você.
   - **Dataset**: a tabela do Common Finance Model à qual o arquivo pertence, identificada pelo nome do arquivo e pelos títulos das colunas. Quando a correspondência não é clara, escolha-a na lista.
   - **Separador decimal**: **Ponto (1,234.56)** ou **Vírgula (1.234,56)**.
   - **Formato de data**: exibido quando o arquivo tem datas. Altere-o se o formato detectado estiver errado: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Uma grade com **Coluna no arquivo**, **Tipo**, **Exemplos** e **Vai para**. Altere **Vai para** para enviar uma coluna a um campo diferente ou para **Não carregar**.

4. Responda às perguntas que o arquivo levanta, como **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** ou **Are revenues shown as negative numbers?** Cada uma é feita somente quando o arquivo ainda não responde.

5. Confira para onde cada coluna vai e clique em **Confirmar mapeamento**.

</Steps>

Estas opções aparecem em um arquivo quando se aplicam:

| Opção | Use para |
|---|---|
| **Which source do these rows apply to?** | Limitar um arquivo de mapa de códigos a uma origem. **Every source** o aplica a todas elas. |
| **Where does this file come from?** | Informar se o arquivo contém **This project's own codes** ou vem de **Another system**, que você nomeia, por exemplo `SAP Germany export`. Um arquivo de outro sistema é verificado quanto a códigos compartilhados como uma origem de ERP. |
| **Split … into … parts at each …** (em **Avançado**) | Dividir uma coluna que contém vários valores, como `100-200-300`, e enviar cada parte para o seu próprio campo. |
| **Which currency do you report in?** | Definir a moeda de relatório quando o projeto ainda não tem uma. Escreva-a com três letras, por exemplo `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Carregar os resultados do seu sistema de consolidação para que a demonstração do resultado do grupo possa ser [reconciliada](#reconcilie-com-o-seu-sistema-de-consolidação). |

Para retirar um arquivo do projeto, clique em **Remover** ao lado dele em **Arquivos**, ou em **Remove this file** no mapeamento dele, e confirme. Os valores dele saem dos seus relatórios na próxima vez que você clicar em **Apply changes**.

Quando o PlaidCloud não consegue decidir sozinho o dataset, o separador decimal ou a ordem das datas, por exemplo um arquivo cujas datas poderiam ser lidas como dia/mês ou mês/dia, ele pede que você escolha antes de confirmar. Adicionar um segundo arquivo para o mesmo dataset substitui o primeiro. Se as colunas de um arquivo posterior não corresponderem ao dataset, a carga informa o arquivo e as colunas e orienta você a corrigir o arquivo ou os nomes das colunas, ou a definir **Schema Mismatch** da etapa como `union`.

Os arquivos aceitos são arquivos de texto CSV, TSV e TXT, arquivos Excel `.xlsx` (lidos a partir da primeira planilha) e arquivos Parquet.

<Aside type="note">
Um arquivo ausente ou vazio nunca interrompe uma carga. Ao adicioná-lo, é informado que ainda não há nada para mapear, e uma carga termina com um aviso que indica o caminho, deixando esse dataset vazio. Adicione o arquivo novamente quando ele existir.
</Aside>

## Carregue seus dados

Clique em **Carregar** no cartão **Carregar** ou no cartão **Última carga**. A carga lê o seu ERP conectado e os seus arquivos confirmados, adapta-os ao Common Finance Model, converte-os para a moeda de relatório, executa as verificações de prontidão e reconstrói os modelos de cálculo do modelo.

- Apenas uma carga é executada por vez para um projeto. Um segundo **Carregar** ou **Apply changes** informa que uma carga já está em execução, e você não pode alterar as origens enquanto uma está em execução.
- Se outros fluxos de trabalho usam a mesma conexão de ERP, a primeira carga os lista e pede que você confirme, porque uma carga lê do ERP e pode deixar esses fluxos de trabalho mais lentos. Clique em **Carregar mesmo assim** para prosseguir.
- Depois que o PlaidCloud é atualizado, o **Carregar** de um Arquiteto também atualiza os fluxos de trabalho gerados do projeto, criando as tabelas de trabalho de que precisam. Até lá, o cartão **Última carga** informa **Changes not applied yet**, e o **Carregar** de um Gerente avisa que o **Carregar** de um Arquiteto os atualiza.
- Uma carga com falha aparece em vermelho e nunca se esconde atrás de resultados anteriores. Se a consolidação falhar, o status informa a etapa em que ela parou, em vez de mostrar resultados antigos do grupo. As linhas de uma carga anterior mostram **De uma carga anterior. Carregue novamente.** até que uma carga seja bem-sucedida.
- Se uma entidade e um período falham na leitura, o restante ainda é carregado. Execute **Carregar** novamente para buscar apenas o que falhou.

### Linhas retidas

Quando as origens se sobrepõem, uma carga mantém uma cópia de cada valor e retém as outras em vez de contá-las duas vezes. As linhas retidas são registradas com a origem, a entidade e o motivo, e a carga termina com um aviso que indica as contagens, por exemplo `120 rows of NetSuite EU also provided by a source ranked ahead`. Os motivos são:

| Motivo | Significado |
|---|---|
| Em outro livro contábil | A linha pertence a um livro de relatório que a origem não está configurada para ler. |
| Fora dos períodos que a origem fornece | A linha cai fora dos meses **De** e **Até** definidos para a empresa. |
| Também fornecida por uma origem mais bem classificada | Uma origem mais acima na ordem cobre a mesma empresa e o mesmo mês. |
| Também em um arquivo anterior da origem | Um arquivo anterior da mesma origem já cobre o mês. |
| Substituída por um arquivo | Um arquivo substitui as linhas do ERP para essa entidade e esse mês. |
| Com um código que outra origem também usa | O código precisa da sua resposta. Consulte [Mapeie códigos entre origens](#mapeie-códigos-entre-origens). |
| Com um código mapeado para dois códigos | O mapa de códigos dá duas respostas ao código. |

As contas estatísticas vão para os direcionadores de alocação em vez do razão, e aparecem como movidas, não como um problema.

### Dados do ERP e arquivos juntos

Um arquivo substitui somente o que ele cobre, e as outras linhas do seu ERP permanecem.

- Os **arquivos mestres** (contas, departamentos, clientes, produtos e **Valores de segmento**) substituem as linhas do ERP com o mesmo código.
- Os **arquivos de transações** substituem as linhas do ERP para a mesma entidade e o mesmo mês. Os arquivos de razão geral e de balancete também correspondem por razão, os de orçamento por cenário, e os de direcionadores estatísticos por cenário e direcionador.

Se um arquivo deixar de cobrir um mês mais tarde, os dados do ERP para esse mês voltam na próxima carga.

## Mapeamento de entidades

Cada origem nomeia suas entidades com seus próprios códigos. O **Mapeamento de entidades** associa esses códigos às entidades do seu cadastro mestre de entidades, de modo que as linhas de todas as origens caiam na mesma entidade.

Para usá-lo, adicione um arquivo CSV ou Excel e escolha o dataset **Mapeamento de entidades**:

| Coluna | Contém |
|---|---|
| `source_entity` | O código como a origem o carrega, como um código de empresa. |
| `entity` | A entidade à qual ele pertence, como o cadastro mestre de entidades a nomeia. |

- Um código que não está no mapeamento é usado como está.
- Vários códigos podem ser mapeados para uma entidade. Suas linhas são combinadas, e um mês conta como fechado quando está fechado para todos eles.
- Os códigos no mapeamento se aplicam a todas as origens, portanto os códigos de entidade de cada origem devem ser exclusivos entre as origens.
- Uma linha de arquivo **Entidades** substitui a entidade do ERP com o mesmo código de entidade.

A verificação **Entidades não mapeadas** sinaliza qualquer linha cuja entidade não está no cadastro mestre de entidades nem é mapeada para uma pelo mapeamento. Até que um cadastro mestre de entidades seja carregado, ela mostra **– Não se aplica**.

## Mapeie códigos entre origens

Duas origens podem usar o mesmo código para coisas diferentes, ou códigos diferentes para a mesma coisa. Quando um código aparece em mais de uma origem, o Data Foundation retém as linhas dele até você dizer se ele significa a mesma coisa em todos os lugares, de modo que cada valor seja contado uma vez. A verificação **Codes waiting for your answer** lista os 10 primeiros e depois "e mais K", e o cartão **What to do next** na guia **Foundation** tem um botão **Revisar**.

**Revisar** abre **Codes waiting for your answer**. Ele agrupa os códigos pelo que são: **Tipos de conta**, **Empresas**, **Contas**, **Departamentos**, **Centros de lucro**, **Clientes**, **Produtos** e cada categoria extra. Para cada código, mostra como cada origem o chama e uma sugestão:

- **Looks like the same thing** quando as origens dão o mesmo nome ao código.
- **Looks like different things** quando os nomes diferem.
- **We can't tell. Please answer.** quando não há nada em que se basear.

Responda um código por vez com **Yes, the same** ou **No, different**, ou responda um grupo inteiro de uma só vez com **Accept all** (aceitar todas as sugestões), **All the same** ou **All different**. Para contas, você também pode responder um grupo pai inteiro do plano de contas de uma vez. Quando uma origem não traz tipos de conta, escolha **Use this type** para um grupo de contas: **Receita**, **Custo dos produtos vendidos**, **Despesas operacionais**, **Receitas e despesas não operacionais**, **Ativos**, **Passivos** ou **Patrimônio líquido**.

Os mapeamentos são mantidos por origem e dimensão, portanto uma resposta para os departamentos de uma origem nunca altera as contas de outra origem. As respostas são salvas à medida que você avança, com **Saved. Press Apply changes to use your answers.** Clique em **Apply changes** para usá-las.

Você também pode fornecer os mapeamentos em um arquivo. Adicione um arquivo com o dataset **Code map** e escolha **Which source do these rows apply to?** para limitá-lo a uma origem.

## Escolha qual origem conta a partir de quando

Quando duas origens fornecem os mesmos meses, a verificação **Which source covers which months** pede que você escolha. Clique em **Choose which source counts from when** no cartão **What to do next** para abrir **Which source counts from when**, que lista cada sobreposição por empresa. Escolha a origem que conta, digite o mês a partir do qual ela conta em **That month is**, por exemplo `2026-04`, e clique em **Apply changes**. A outra origem mantém os meses anteriores.

A mesma caixa de diálogo avisa quando duas origens dão taxas de câmbio diferentes para uma moeda; as taxas da origem mais acima na ordem são usadas.

## Conversão de moedas

Cada carga converte os valores de razão geral, balancete, vendas, estoque e orçamento da moeda local para uma única moeda de relatório. Os relatórios e modelos leem os valores convertidos, de modo que entidades em moedas diferentes, de qualquer sistema, somem corretamente.

### A moeda de relatório

Para escolher a moeda de relatório, defina a variável de projeto `reporting_currency` com um código de moeda, como `USD`. Consulte [Gerenciar variáveis do projeto](/pt-br/guides/projects/managing-projects/#gerenciar-variáveis-do-projeto). O modelo a cria em branco. Enquanto ela estiver em branco, cada carga usa o primeiro destes que indicar exatamente uma moeda:

1. A moeda do grupo das entidades.
2. A moeda local das entidades de nível superior, as que não têm pai.
3. A moeda local dos arquivos.

Se nenhum deles indicar exatamente uma moeda, **Conversão de moedas** mostra um problema até você definir `reporting_currency`.

Os valores que já estão na moeda de relatório permanecem como estão, portanto um projeto cujos dados estão todos em uma moeda não precisa de taxas.

Os arquivos de vendas, estoque e orçamento também podem trazer uma moeda. Mapeie uma coluna chamada `Currency` ou `Local Currency` e ela é identificada automaticamente, e os valores locais do arquivo são convertidos para a moeda de relatório. Um valor de grupo ou de relatório que já esteja no arquivo é mantido como está. O custo padrão do produto não é convertido.

### Taxas de câmbio

Uma taxa converte uma unidade de uma moeda para a moeda de relatório em um mês: o valor convertido é o valor local multiplicado pela taxa.

- **A partir do seu ERP**, cada carga lê as taxas de câmbio que o ERP mantém.
- **A partir de um arquivo**, adicione um arquivo CSV ou Excel e escolha o dataset **Taxas de câmbio**. Uma taxa no arquivo substitui a taxa do ERP para as mesmas moedas e o mesmo mês. Use um arquivo para reportar em uma moeda para a qual seus ERPs não publicam taxas, ou para adicionar taxas planejadas para os meses de orçamento.

| Coluna | Contém |
|---|---|
| `from_currency` | A moeda de origem da conversão, por exemplo `EUR`. |
| `to_currency` | A moeda de relatório, por exemplo `USD`. |
| `period` | O mês, como `YYYY-MM`. |
| `average_rate` | A taxa média do mês. |
| `closing_rate` | A taxa no fim do mês. |
| `historical_rate` | A taxa histórica, para o patrimônio líquido e para as contas definidas com a taxa histórica. |

Somente as taxas para a moeda de relatório são usadas. Uma taxa cotada no sentido inverso, da moeda de relatório para outra moeda, não é invertida.

### Qual taxa se aplica

Cada linha é convertida a partir da própria moeda, portanto uma linha em uma moeda diferente da de sua entidade é convertida a partir da moeda em que está. A primeira regra que se aplica à linha prevalece:

| Linha | Taxa |
|---|---|
| Contas estatísticas e que não recebem lançamentos | Não convertidas. |
| Já na moeda de relatório | Não convertida. |
| Conta com um tipo de taxa | Essa taxa: média, de fechamento ou histórica. A histórica recorre à de fechamento quando não há taxa histórica. Em um ERP, o tipo de taxa é o tipo de taxa da própria conta. Em um arquivo de plano de contas, mapeie uma coluna de tipo de taxa para `fx_rate_type` com `average`, `closing` ou `historical`. |
| Linha de vendas | A taxa média do período. |
| Saldo de estoque | A taxa de fechamento do período. |
| Linha de orçamento | Por conta, como o razão geral: a taxa média para as contas da demonstração do resultado e a taxa de fechamento para as contas do balanço patrimonial. |
| Conta da demonstração do resultado | A taxa média do período. |
| Conta de patrimônio líquido | A taxa histórica, ou a taxa de fechamento quando não há taxa histórica. |
| Qualquer outra conta do balanço patrimonial | A taxa de fechamento do período. |

Os valores convertidos não são arredondados, portanto os totais não se desviam.

<Aside type="note">
O balancete contém as movimentações de cada período, portanto os valores do balanço patrimonial são as movimentações de cada mês convertidas pela taxa de fechamento desse mês. Eles não são um balanço patrimonial reconvertido pela taxa do fim do período, e não há ajuste de conversão acumulado nem eliminação de transações entre empresas do grupo. Use os valores convertidos para a demonstração do resultado.
</Aside>

## Hierarquias

Cada carga reconstrói as dimensões a partir dos dados mestres de cada origem. Há sete dimensões para começar, e até dez categorias extras:

| Dimensão | Construída a partir de |
|---|---|
| **Entidade** | Entidades e seus pais |
| **Conta** | Plano de contas e contas pai |
| **Departamento** | Departamentos e seus pais |
| **Cliente** | Clientes e seus clientes pai |
| **Produto** | Produtos e seus produtos pai |
| **Segmento 1** | Valores de segmento para `segment_1` |
| **Segmento 2** | Valores de segmento para `segment_2` |
| **Segmento 3** a **Segmento 10** | Valores de segmento de `segment_3` a `segment_10`, quando suas origens os trazem |

- Um registro sem pai, ou que se nomeia como o próprio pai, é carregado como membro de nível superior.
- Como cada carga reconstrói as hierarquias, altere um pai no ERP ou no seu arquivo, não na dimensão.
- Um problema em uma hierarquia afeta apenas essa dimensão. A carga e os modelos de cálculo do modelo ainda são concluídos.
- Você pode renomear cada categoria extra para o que ela contém, por exemplo **Classe** ou **Região**. Em **Rename extra categories**, digite os nomes que seus relatórios usam e clique em **Save names**. Os nomes usam letras, números, espaços, pontos, hifens e sublinhados, com até 60 caracteres.
- Cada origem diz sob qual dos seus nomes de categoria cada uma das suas próprias categorias extras se enquadra. Abra **Avançado** na origem, escolha o nome de cada uma, ou escolha **Leave out**, e clique em **Salvar**. As origens que chamam uma categoria por nomes diferentes, como `Class` e `Business area`, passam então a compartilhar uma posição.

Para fornecer hierarquias de segmento a partir de um arquivo, escolha o dataset **Valores de segmento**:

| Coluna | Contém |
|---|---|
| `segment` | A qual segmento o valor pertence: de `segment_1` a `segment_10`. |
| `segment_value` | O valor, como as linhas de razão geral, vendas e orçamento o trazem. |
| `segment_value_name` | O nome dele. |
| `parent_segment_value` | O pai dele dentro do mesmo segmento. |

## Verificações de prontidão

Após cada carga, a grade **Prontidão** lista cada verificação para cada entidade e período, com um destes status:

| Status | Significado |
|---|---|
| **● Pronto** | A verificação passou. |
| **▲ Requer atenção** | Vale uma olhada, mas os números são utilizáveis. |
| **■ Problema** | Corrija antes de confiar nos resultados. |
| **– Não se aplica** | Ainda não há dados para esta verificação. |

As verificações são:

| Verificação | O que ela confirma |
|---|---|
| **Dados carregados** | Todo período fiscal tem linhas de razão geral, e toda leitura do ERP foi bem-sucedida. Um período fechado sem linhas é um problema; um período aberto sem elas requer atenção. |
| **Balancete bate com o razão geral** | O balancete é igual ao razão geral para cada entidade, período e conta. Quando o balancete e o razão geral trazem departamentos para uma conta, ela também verifica cada departamento. |
| **Vendas batem com o razão geral** | As linhas de vendas são iguais às contas de receita e de custo dos produtos vendidos do razão geral para cada período. |
| **Produtos/clientes desconhecidos** | Toda linha de vendas indica um produto e um cliente que existem nos cadastros mestres de produtos e clientes. |
| **Contas ausentes do plano de contas** | Toda linha do razão geral indica uma conta do plano de contas. As linhas com uma conta desconhecida ficam de fora da demonstração do resultado. Uma conta com lançamentos mas sem tipo de conta também é um problema, e uma origem cujo plano de contas tipifica contas de receita mas nenhuma de custo das mercadorias vendidas precisa de atenção. |
| **Conversão de moedas** | Toda linha de razão geral, balancete, vendas, estoque e orçamento tem um valor na moeda de relatório. Uma linha da demonstração do resultado ou de vendas sem taxa é um problema, porque a demonstração do resultado lê valores convertidos. Uma linha de balanço patrimonial, estoque ou orçamento sem taxa requer atenção. Um mês de orçamento ainda sem taxa aparece em âmbar, portanto carregue taxas planejadas para os meses de orçamento. Consulte [Conversão de moedas](#conversão-de-moedas). |
| **Entidades não mapeadas** | Toda linha de razão geral, balancete e vendas indica uma entidade do cadastro mestre de entidades, diretamente ou pelo mapeamento de entidades. Não se aplica até que um cadastro mestre de entidades seja carregado. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |

As cargas com mais de uma origem acrescentam estas verificações:

| Verificação | O que ela confirma |
|---|---|
| **Reporting book** | Uma origem que mantém vários livros contábeis para uma entidade teve seu livro de relatório escolhido. Até você escolher, só o primeiro livro conta. |
| **Codes waiting for your answer** | Todo código usado por mais de uma origem foi respondido. Consulte [Mapeie códigos entre origens](#mapeie-códigos-entre-origens). |
| **Extra categories from your sources** | Toda categoria extra que uma origem traz tem um nome ou foi deixada de fora. |
| **Which source covers which months** | Duas origens não fornecem os mesmos meses de uma empresa, a menos que você tenha escolhido qual conta. |
| **Account types and hierarchy** | Todo pai que uma dimensão nomeia existe, e nenhum membro é seu próprio pai nem seu próprio ancestral. Um pai ausente coloca seus filhos no topo da hierarquia, e um laço impede o carregamento dessa hierarquia. Os totais não são afetados. |
| **Calendário fiscal** | Os períodos fiscais de cada entidade são meses do calendário, e todas as linhas de um mês podem ser colocadas em um único período fiscal. Precisa de atenção quando os períodos de uma entidade não são meses do calendário (4-4-5, 13 períodos), ou quando as linhas de um mês podem estar em mais de um período fiscal ou o calendário fiscal não tem o mês. |

Cada linha que não está pronta diz o que fazer na coluna **O que fazer**, como carregar o plano de contas, carregar taxas de câmbio ou executar **Carregar** novamente para um período.

A grade também mostra duas verificações de configuração, que aparecem somente quando precisam de atenção:

| Verificação | Quando aparece |
|---|---|
| **Alocação de custos indiretos** | Apenas uma das variáveis de projeto `overhead_department` e `overhead_driver` está definida, ou nenhum direcionador de alocação corresponde a `overhead_driver`, de modo que a alocação não faria nada. Defina as duas, ou limpe as duas para desativar a alocação de custos indiretos. |
| **Comparação com o orçamento** | As linhas de orçamento estão carregadas, mas nenhuma está na versão que a variável de projeto `budget_version` indica, de modo que a comparação com o orçamento ficaria vazia. |

## Consolidação gerencial

Cada carga constrói uma consolidação gerencial: a demonstração do resultado do grupo de todas as entidades do grupo, na moeda de relatório, com as transações entre empresas do grupo eliminadas. Ela serve para relatórios gerenciais. Seu sistema de consolidação continua sendo o registro do grupo societário; reconcilie com ele abaixo.

<Aside type="note">
A consolidação gerencial cobre apenas a demonstração do resultado. Ela não é uma consolidação societária ou legal e não tem balanço patrimonial consolidado, ajuste de conversão, ágio nem participação de minoritários.
</Aside>

### Escolha o grupo

Em **Origens**, abra **Grupo** para ver as empresas do grupo. Uma empresa que você desmarcar continua nos seus relatórios por conta própria, mas fica fora do total do grupo. Clique em **Save group**. A alteração se aplica na próxima vez que você usar **Carregar** ou **Apply changes**. Uma nova empresa fica no grupo até você desmarcá-la.

O ano fiscal do grupo começa no mês definido pela variável de projeto `group_fy_start_month`, que é `1`, a menos que você a altere.

### O que você obtém

| Tabela | Contém |
|---|---|
| **Group P&L** | Uma linha por entidade, período e item (receita, custo dos produtos vendidos, despesas operacionais, não operacional, diferença entre empresas do grupo), na moeda de relatório. Receitas e custos mantêm seu sinal natural. |
| **Group P&L year to date** | O mesmo, acumulado no ano, até o último período totalmente carregado do grupo. |
| **Intercompany pairs** | Uma linha por par de entidades, grupo e período, com o valor de cada lado e o resíduo. |
| **Intercompany lines** | As linhas do razão por trás de um valor do grupo ou de um par, com o parceiro comercial. |
| **Reconciliação** | A demonstração do resultado do grupo acumulada no ano em comparação com o seu sistema de consolidação. |

Três nomes de entidade aparecem nessas tabelas:

| Entidade | Significado |
|---|---|
| **Eliminations** | As eliminações entre empresas do grupo. Elas somam zero, portanto mantenha-as para os valores do grupo e filtre-as para a soma das entidades antes da eliminação. |
| **Group total** | O total do sistema de consolidação, na reconciliação. |
| **Unmapped** | Linhas sem período, e contas ou entidades do seu sistema de consolidação que este projeto não tem. |

As métricas **Consolidated income**, **Consolidated result** e **IC difference**, e um caminho de análise para cada tabela, respondem a perguntas sobre o grupo.

### Eliminações entre empresas do grupo

As linhas entre empresas do grupo são pareadas por parceiro comercial. O parceiro da linha é usado; quando uma linha não tem, usa-se o parceiro do cliente dela. Os dois lados de um par são eliminados, e o valor pelo qual os dois lados não coincidem é lançado em uma linha de diferença entre empresas do grupo. Cada par recebe um motivo:

| Motivo | Significado |
|---|---|
| **Correspondente** | Os dois lados lançaram o mesmo valor. |
| **Only one side booked** | Uma entidade lançou a transação e o parceiro dela não. |
| **Not eliminated** | Uma linha do par não tem taxa de câmbio, portanto nenhum dos lados é eliminado. |

Um par é avaliado no acumulado do ano. A linha **Intercompany balances** fica âmbar quando a diferença de um par ultrapassa a variável de projeto `group_amber` (padrão `1`) e vermelha acima de `group_red` (padrão `1000`). As linhas sem parceiro, ou com um parceiro que não é uma entidade, não são eliminadas e são contadas nessa linha. Uma origem que traz parceiros ao lado de outra que não traz aparece em âmbar.

As próprias entidades de eliminação de uma origem ficam fora da demonstração do resultado do grupo, e a linha **Consolidação** informa isso.

### Reconcilie com o seu sistema de consolidação

Adicione como arquivo os resultados que o seu sistema de consolidação informa e marque **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** ao confirmar o mapeamento dele. Responda **Which version of the numbers is this?** com o nome do sistema. A tabela **Reconciliação** mostra então **ours**, **reported** e **diferença** para cada entidade e item, acumulados no ano. Uma diferença geralmente é explicada nas linhas **Eliminations**, **Group total** e **Unmapped**, ou pelas taxas de câmbio que o sistema usa. A linha **Reconciliation to the source** lista todos os itens acima de `group_amber`.

### Quem pode ver

Os resultados do grupo seguem o acesso por linhas do projeto. Quando o acesso por linhas impede os resultados do grupo, o status aparece em âmbar. Uma pessoa que vê apenas algumas entidades vê as somas dessas entidades antes da eliminação. As linhas **Eliminations** e as tabelas entre empresas do grupo exigem acesso a todas as entidades.

Se o projeto limita quem vê quais linhas por uma coluna que as tabelas do grupo não trazem, como departamento, os resultados do grupo permanecem desativados para todos e **Consolidação** informa **Group views are off**. Então só um Arquiteto pode marcar **Everyone on the project may see the group results** em **Grupo**. A alteração se aplica na próxima vez que você usar **Carregar** ou **Apply changes**.

## Mantenha atualizado

Depois que uma carga da sua conexão de ERP é bem-sucedida sem problemas, **Atualizar toda noite** aparece no cartão **Última carga**. Clique nele para executar **Carregar** toda noite às 2h no seu fuso horário. O cartão passa então a mostrar **Nightly refresh: Every night at 2:00** e quem o configurou.

A carga noturna é executada como a pessoa que a configurou. Se essa pessoa não puder mais usar a conexão de ERP, a grade informa que a carga noturna foi ignorada; configure-a novamente. Um projeto que tem apenas dados de exemplo não pode ser agendado.

Um arquivo ausente ou vazio em uma carga noturna termina com um aviso que indica o caminho, não com um erro, e o restante do modelo ainda é carregado.

## Construa sobre o Common Finance Model com um modelo

Um modelo constrói seus relatórios e modelos de cálculo sobre o Common Finance Model, de modo que funcionem da mesma forma, sejam quais forem os ERPs que o alimentam. Quando você inicia um projeto a partir de um modelo, como o **Enterprise Profitability**, ele cria:

- As [tabelas do Common Finance Model](#tabelas-do-common-finance-model), vazias ou preenchidas com dados de exemplo.
- As dimensões **Entidade**, **Conta**, **Departamento**, **Cliente**, **Produto**, **Segmento 1** e **Segmento 2** construídas a partir dessas tabelas. Consulte [Hierarquias](#hierarquias).
- O fluxo de trabalho **Carregar** e os fluxos de trabalho que ele executa para ler o seu ERP e os seus arquivos, adaptá-los, verificar a prontidão e construir os modelos de cálculo do modelo.
- Os próprios relatórios e modelos de cálculo do modelo. O **Enterprise Profitability** adiciona uma tabela de demonstração do resultado com receita, custo dos produtos vendidos, margem bruta, despesas operacionais diretas e indiretas, contribuição e margem operacional, além de pontes de margem ano a ano e em relação ao orçamento.
- Métricas e um caminho de análise para fazer perguntas sobre os resultados.

Para explorar antes de conectar o seu próprio ERP, marque **Começar com dados de exemplo** ao criar o projeto. O projeto executa uma primeira carga imediatamente, de modo que a guia **Foundation** mostra um exemplo completo, incluindo uma entidade em euros convertida para dólares americanos. Quando você conecta o seu próprio ERP ou adiciona os seus próprios arquivos, as linhas de exemplo são apagadas e os seus dados tomam o lugar delas.

## Tabelas do Common Finance Model

O Data Foundation adapta cada origem, ERP ou arquivo, às mesmas quinze tabelas, de modo que relatórios, métricas e modelos de cálculo construídos sobre elas funcionam da mesma forma, seja qual for a origem. Cada linha também registra seu sistema de origem e quando foi lida. A coluna **Dataset** é o nome que você escolhe ao adicionar um arquivo.

| Dataset | Tabela | Contém |
|---|---|---|
| Entidades | `cfm_entity` | Entidades legais com pai, moeda local e do grupo, e país. |
| Mapeamento de entidades | `cfm_entity_map` | Códigos de entidade da origem e a entidade a que cada um pertence. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |
| Taxas de câmbio | `cfm_fx_rate` | Taxas médias, de fechamento e históricas mensais por par de moedas. Consulte [Taxas de câmbio](#taxas-de-câmbio). |
| Calendário fiscal | `cfm_fiscal_calendar` | Uma linha por período fiscal da entidade, com datas de início e fim e se está fechado. |
| Plano de contas | `cfm_account` | Contas com pai, tipo (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), demonstração, saldo normal e tipo de taxa. |
| Departamentos | `cfm_department` | Departamentos e centros de custo com pai e centro de lucro. |
| Produtos | `cfm_product` | Cadastro mestre de produtos com pai, família, grupo, unidade de medida e custo padrão. |
| Clientes | `cfm_customer` | Cadastro mestre de clientes com pai, grupo, região e país. Os nomes dos clientes não são mascarados. |
| Valores de segmento | `cfm_segment` | Valores de segmento com nome e pai. Consulte [Hierarquias](#hierarquias). |
| Razão geral | `cfm_gl_journal` | Linhas de lançamento na moeda da transação, local e de relatório. |
| Balancete | `cfm_trial_balance` | Débitos, créditos e líquido do período por entidade, conta e departamento, em moeda local e de relatório. |
| Linhas de vendas | `cfm_sales_line` | Linhas de vendas faturadas com quantidade e valores bruto, de desconto, líquido e de custo dos produtos vendidos. |
| Saldos de estoque | `cfm_inventory_balance` | Estoque no fim do período por produto e depósito. |
| Orçamento | `cfm_budget` | Orçamento e previsão por cenário, versão, conta e departamento. |
| Direcionadores de alocação | `cfm_stat_driver` | Direcionadores estatísticos, como número de funcionários, área em metros quadrados ou unidades. |

Os períodos são escritos como `YYYY-MM`, e as transações são alocadas pelo período de lançamento. O orçamento é opcional: um ERP sem orçamentos ainda carrega todo o resto.

Um arquivo de balancete pode trazer colunas de débito e crédito, uma coluna de líquido, ou ambas. Com apenas débito e crédito, o líquido é débito menos crédito, e um lado em branco conta como zero. Com apenas o líquido, um líquido positivo se torna o débito e um líquido negativo se torna o crédito, como um valor positivo. Uma coluna de departamento é opcional.

## Solução de problemas

| Sintoma | O que fazer |
|---|---|
| **Testar conexão** informa que o ERP recusou as credenciais | Verifique as credenciais da conexão e se o usuário da integração consegue entrar no ERP. |
| **Testar conexão** mostra **Permissão ausente** para um dataset | Peça ao administrador do seu ERP para adicionar as permissões que ele indica. O [guia de conexão](/pt-br/guides/connections/) do seu ERP lista o que a conexão precisa. |
| Uma mensagem de erro do ERP é mais curta que a do próprio ERP | O PlaidCloud remove credenciais, tokens e chaves dos erros do provedor antes de exibi-los, portanto alguns detalhes ficam de fora. Execute **Testar conexão** para ver qual dataset é afetado. |
| **Dados carregados** é um problema em um período | Uma leitura do ERP para esse período falhou. Execute **Carregar** novamente; os períodos que foram carregados são ignorados. |
| **Contas ausentes do plano de contas** é um problema | Adicione as contas ausentes ao plano de contas no ERP ou no seu arquivo e execute **Carregar** novamente. |
| **Conversão de moedas** é um problema | A moeda de uma entidade não tem taxa para a moeda de relatório nesse período, ou nenhuma moeda de relatório única foi encontrada. Adicione as taxas a um arquivo de **Taxas de câmbio**, verifique se a conexão consegue ler as taxas de câmbio do ERP ou defina a variável de projeto `reporting_currency`. Depois execute **Carregar** novamente. |
| **Conversão de moedas** requer atenção | As linhas de balanço patrimonial, estoque ou orçamento não têm taxa de fechamento, histórica ou planejada para o período. A demonstração do resultado não é afetada. Adicione as taxas, inclusive taxas planejadas para os meses de orçamento, e execute **Carregar** novamente. |
| **Codes waiting for your answer** requer atenção | Clique em **Revisar**, responda a cada código e clique em **Apply changes**. |
| **Which source covers which months** requer atenção | Clique em **Choose which source counts from when**, escolha a origem e clique em **Apply changes**. |
| **Intercompany balances** está vermelho ou âmbar | Verifique os pares em **Intercompany pairs**. Lance o lado ausente, adicione o parceiro comercial às linhas ou adicione a taxa ausente. |
| **Group views are off** | Peça a um Arquiteto para marcar **Everyone on the project may see the group results** em **Grupo**. |
| **Entidades não mapeadas** é um problema | Adicione a entidade ao cadastro mestre de entidades, ou mapeie o código dela para uma entidade existente no arquivo de **Mapeamento de entidades**, e execute **Carregar** novamente. |
