## Descrição

A etapa **Extrair SQL** de fluxo de trabalho executa um `SELECT` somente leitura nos dados do seu projeto
e grava o resultado em uma nova tabela. Escrever essa consulta à mão exige
conhecer as tabelas de origem, as colunas delas e o SQL para modelá-las.

O editor de etapas pode escrever a consulta para você. Descreva a saída que você quer em
linguagem natural e o AI Assistant produz o `SELECT`; e, se você não disser
de quais tabelas ler, ele examina as tabelas do projeto e escolhe as
relevantes sozinho. O SQL gerado e as colunas detectadas são mostrados para
revisão e continuam totalmente editáveis antes de você salvar a etapa.

<Aside type="note">
Isto usa o mesmo modelo integrado que o AI Assistant usa, portanto **não há nada para
configurar**. Você não precisa configurar um agente de IA por espaço de trabalho nem uma conexão de LLM
para isso.
</Aside>

## Abrindo a etapa

Na visualização **Etapas** de um fluxo de trabalho, clique em **Criar etapa** e escolha:

- **Tables → Extrair SQL**, ou
- **AI → SQL Extract (AI Assisted)**

Ambas abrem o mesmo editor da etapa Extrair SQL, que agora inclui um painel **Generate SQL
with AI** no topo da página Parâmetros de extração de SQL.

## Gerando a consulta

1. **(Opcional) Escolha as tabelas de origem.** Na lista **Tabelas de origem**, selecione uma
   ou mais tabelas das quais a consulta deve ler. Deixe a lista vazia para que o
   Assistant examine o projeto e escolha as tabelas relevantes por você.
2. **Descreva o que você quer.** Na caixa **Descrever**, escreva o resultado em linguagem
   natural, por exemplo: *"classifique cada conta do razão em um pool de atividades
   com base na faixa do número da conta"*.
3. **Clique em Gerar SQL.** O Assistant escreve um único `SELECT` somente leitura,
   valida-o executando-o e preenche:
   - o editor **Consulta SQL SELECT** com a instrução gerada, e
   - a página de mapeamento **Seleção de dados da tabela** com as colunas detectadas.

   Se você deixou a lista de origens vazia, as tabelas que o Assistant escolheu são
   selecionadas de volta na lista para que você veja o que ele usou e ajuste.

## Revisando e salvando

O SQL gerado é um ponto de partida, não uma caixa-preta:

- **Edite à vontade.** O editor de SQL é totalmente editável: refine a consulta, adicione uma
  junção ou altere a lista de colunas antes de salvar. (Para unir várias tabelas, você pode
  selecionar várias tabelas de origem ou simplesmente editar a consulta gerada.)
- **Escolha uma tabela de destino.** Escolha ou nomeie a **Tabela de destino** em que a etapa grava
  o resultado.
- **Salve a etapa.** Ela é salva como uma etapa Extrair SQL comum e é executada como parte
  do fluxo de trabalho, como qualquer outra.

<Aside type="tip">
Se o Assistant devolver uma consulta que não executa, o editor ainda mostra o SQL
junto com o erro para que você o corrija, ou ajuste a sua descrição e
gere novamente.
</Aside>

## Observações e limites

- O Assistant escreve apenas instruções `SELECT` **somente leitura**; ele nunca produz
  `INSERT`, `UPDATE`, `DELETE` nem outro SQL que altere dados.
- A geração **não cria nem executa** a etapa: ela apenas redige a consulta e
  pré-visualiza as colunas. A etapa é criada quando você a salva e é executada quando o
  fluxo de trabalho é executado.
- A consulta gerada lê pelos **nomes de exibição** das suas tabelas: cada tabela é
  vinculada uma vez no topo da consulta com o seu nome (assim, colunas, junções e
  filtros usam nomes simples em vez de ids internos `analyzetable_…`).
  Os identificadores reais são restaurados automaticamente quando você salva, então a consulta
  executa sem alterações. Uma tabela cujo nome não é exclusivo mantém o seu identificador.
