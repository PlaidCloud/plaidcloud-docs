## Descrição

Selecione uma etapa ou um fluxo de trabalho em um projeto e o painel de detalhes dele é aberto. Na parte inferior, uma seção **Documentação** mostra uma página que o Weave escreve sobre o item a partir das configurações salvas do projeto. O painel de detalhes de uma tabela mostra, em vez disso, as **Colunas**, com o tipo e a descrição de cada coluna; a página abaixo descreve o que o Weave e os assistentes de IA leem sobre uma tabela:

- para uma tabela, as etapas que gravam e leem a tabela, e as colunas dela;
- para uma etapa, o que ela faz e onde é executada;
- para um fluxo de trabalho, as etapas em ordem e as tabelas que ele lê e grava.

A página é escrita sempre que você seleciona o item, a partir das configurações como estão salvas naquele momento, portanto nunca fica desatualizada e não há nada para atualizar manualmente. Nenhuma IA é usada, então ela funciona mesmo quando nenhum provedor de IA está disponível. Depois de salvar no mesmo painel de detalhes, por exemplo uma nova descrição, a página é escrita novamente.

O Weave AI, o chat na guia **Weave** de um projeto, e os assistentes de IA conectados via MCP podem ler a mesma página. Consulte [Para assistentes de IA](#para-assistentes-de-ia).

## A página de uma tabela

- **A descrição** — o **Memorando** da tabela, exibido como citação. O PlaidCloud define o memorando *Created dynamically* em uma tabela criada por uma etapa; esse não é exibido, pois não diz nada sobre a tabela.
- **Gravada por** e **Lida por** — cada etapa, pelo nome, com o tipo de etapa e os fluxos de trabalho em que ela está. *(desativada)* acompanha um fluxo de trabalho em que a etapa está desativada, e *fora de qualquer fluxo de trabalho* indica uma etapa que não está em nenhum. Uma etapa cujo nome de tabela contém uma variável que pode ou não indicar esta tabela é listada com *dependendo dos valores de suas variáveis*. Uma etapa que informa apenas um nome compartilhado por várias tabelas é listada com, por exemplo, *a menos que se refira a outra das 2 tabelas com este nome*, contando apenas as tabelas que você pode abrir. Uma etapa Tabela: Limpar, Tabela: Descartar ou Tabela: Exclusão no local conta como gravação na tabela que altera, e uma etapa que lê uma tabela e a grava de volta é listada nas duas.
- **Nenhuma etapa neste projeto lê esta tabela.** significa que nenhuma etapa neste projeto a lista como origem. A página não verifica painéis, exportações, outros projetos nem nada fora das etapas do projeto.
- **Colunas** — cada coluna e o tipo dela, com a descrição de **Propriedades da coluna** quando houver uma definida.

## A página de uma etapa

**O que ela faz** traz uma frase para cada coisa que a etapa faz:

| Etapa | O que a página diz |
| --- | --- |
| Allocation: Split | Qual valor ela divide, de qual tabela, entre quais colunas, usando qual coluna de direcionador, e como cada parcela é calculada — por exemplo, "A parcela de cada `product` é o `weight` dele dividido pelo `weight` total do mesmo `cost_center`, `year` e `month`." As colunas são nomeadas como as tabelas de origem e de direcionador as nomeiam. Um filtro na origem ou no direcionador da etapa é indicado, e as tabelas que ela grava são nomeadas. |
| Alocação: Dividir usando dimensão | Qual valor ela divide, de qual tabela e qual coluna de direcionador ela usa, e todas as tabelas que ela grava, incluindo as tabelas de mapeamento, de caminho e de resumo. |
| Importação | O arquivo ou arquivos que ela importa e a tabela para a qual importa. |
| Exportação | A tabela que ela exporta e o arquivo que grava. |
| Extract: SQL sem origens listadas | Que ela executa uma consulta SQL, e a tabela que grava. |
| Tabela: Limpar, Tabela: Descartar, Tabela: Exclusão no local | Que ela limpa, descarta ou exclui linhas de sua tabela ou, quando escolhe tabelas por pesquisa ou pasta, que atua sobre as tabelas escolhidas por essa configuração. |
| Importar tabela de projeto externa | Que ela copia uma tabela de outro projeto para uma tabela deste. |
| Uma etapa que executa outro fluxo de trabalho | O fluxo de trabalho que ela executa e como: quando as condições dela são atendidas, em um loop, como macro (uma vez para cada linha da tabela de origem, ou em execução simultânea) ou por inclusão. Um fluxo de trabalho escolhido por uma variável é exibido com o nome que a etapa informa, e um de outro projeto é descrito como tal. Qualquer tabela que a própria etapa lê, como a tabela que um loop percorre, também é listada. |
| Qualquer outra etapa | As tabelas que ela lê e as tabelas que ela grava. |

A página então informa onde a etapa é executada — *É a etapa 3 em* seguido do fluxo de trabalho, numerada como na lista de etapas do fluxo de trabalho — ou que ela não está em nenhum fluxo de trabalho.

Uma tabela que a etapa nomeia por meio de uma variável é exibida pelo nome, seguido de *(nomeada por uma variável)*.

## A página de um fluxo de trabalho

- **Etapas** — numeradas como na lista de etapas do fluxo de trabalho, com o tipo de cada etapa e a tabela que ela grava, ou o fluxo de trabalho que ela executa. As etapas de um fluxo de trabalho que ele inclui são listadas no lugar, como a lista de etapas as mostra.
- **Lê de fora deste fluxo de trabalho** — tabelas que uma etapa lê antes de qualquer etapa deste fluxo de trabalho gravá-las.
- **Grava** — tabelas que as etapas do fluxo de trabalho gravam.

As etapas desativadas são listadas em **Etapas**, mas ficam de fora das duas listas. A página informa isso, pois uma tabela gravada por uma etapa desativada pode então ser listada como lida de fora. As tabelas usadas por um fluxo de trabalho que uma de suas etapas executa estão na página desse próprio fluxo de trabalho.

## Um pacote de transição para o projeto inteiro

Para transferir um projeto, por exemplo a um cliente no fim de um contrato, baixe todas as páginas de uma só vez. Na janela **Projetos**, selecione um projeto e escolha **Baixar pacote de transição** no menu **Ações** ou no menu de clique com o botão direito. Você precisa de acesso de leitura ao projeto, às etapas, aos fluxos de trabalho e às tabelas dele.

O pacote é um único arquivo Markdown, com o nome do projeto — por exemplo *Month End handover.md* — e escrito a partir das configurações salvas no momento em que você o baixa. Ele começa com a descrição do projeto e uma contagem do que o projeto contém, e depois tem quatro seções:

- **Fluxos de trabalho** — a página de cada fluxo de trabalho. Os fluxos de trabalho que nenhum outro fluxo de trabalho executa vêm primeiro, por nome, e cada um é seguido dos fluxos de trabalho que ele executa, na ordem em que os executa. Um fluxo de trabalho executado a partir de dois lugares é listado uma vez.
- **Tabelas** — a página de cada tabela, como acima, incluindo as colunas e as descrições delas.
- **Métricas** — a versão atual de cada definição de métrica, em frases simples: o que ela mede, de qual tabela, as tabelas que ela une, as linhas que usa, as linhas reais e de orçamento, os períodos e pelo que ela pode ser detalhada. Uma métrica construída a partir de outras diz como, por exemplo *Receita dividida por Pedidos*. Consulte [Definições de métricas](/pt-br/integrations/ai-coding-agents/metric-definitions/).
- **Modelos de alocação** — cada cadeia de etapas de alocação que alimentam umas às outras, com a etapa ou etapas em que ela termina e a divisão de cada etapa, na ordem de execução. Uma etapa que não é executada em nenhum fluxo de trabalho fica de fora. Um modelo recebe o nome do seu fluxo de trabalho, ou da pasta que seus fluxos de trabalho compartilham. Quando não há esse nome, quando ele o compartilha com outro modelo, ou quando o obtém de algo que o seu perfil oculta, ele recebe como título o de uma de suas etapas. Um modelo de alocação não tem página própria fora do pacote.

O pacote segue as mesmas regras de uma página individual para o que o seu perfil oculta. Um fluxo de trabalho, tabela ou modelo de alocação que você não pode abrir é deixado de fora e contado no início, por exemplo *Deixa de fora 2 fluxos de trabalho e 5 tabelas que você não pode abrir.* Uma etapa que você não pode abrir nunca é nomeada, como em uma página individual.

## O que o seu perfil oculta

Uma tabela, etapa ou fluxo de trabalho pode ser ocultado dos perfis Gerente ou Explorador. Uma página nunca nomeia um item que o seu perfil oculta:

- Uma etapa que você não pode abrir é contada — por exemplo, *mais 2 etapas que você não pode abrir* — e mantém o número dela na lista de etapas de um fluxo de trabalho.
- Uma tabela, etapa ou fluxo de trabalho que você não pode abrir aparece da mesma forma que um que não existe mais — por exemplo, *uma tabela que você não pode abrir ou que não existe mais* — de modo que uma página não pode ser usada para descobrir se algo oculto existe. As etapas deixadas de fora das listas de um fluxo de trabalho dessa forma são indicadas, pois uma tabela gravada por uma delas pode então ser listada como lida de fora. Uma tabela nomeada por uma etapa que você não pode abrir, ou que não existe, é exibida pelo nome que a etapa lhe dá, seguido de *(não é uma tabela que você pode abrir)*, e um fluxo de trabalho da mesma forma, por *(não é um fluxo de trabalho que você pode abrir)*.
- Pedir a página de um item que o seu perfil oculta resulta em uma resposta como se ele não existisse.

Um Arquiteto pode abrir tudo, então as páginas de um Arquiteto dizem *uma tabela excluída*, *(tabela não encontrada)*, *Uma etapa excluída* ou *(fluxo de trabalho não encontrado)*.

## O que ela não cobre

- **Contagens de linhas, tamanhos e horários de atualização.**
- **Tabelas que uma etapa alcança apenas por meio do texto SQL ou de uma expressão.** A página lista as tabelas que uma etapa nomeia em suas configurações.
- **Edições não salvas.** A página descreve as configurações salvas.

<Aside type="note">
A página não interpreta seus dados nem julga se uma etapa está correta. Ela
informa o que as configurações salvas dizem, em linguagem simples.
</Aside>

## Para assistentes de IA

- O **Weave AI** pode ler a página de uma tabela, etapa ou fluxo de trabalho quando você pergunta sobre ela em uma conversa aberta em um projeto, e responder com base no que a página diz. Consulte [Chat do Weave AI](/pt-br/guides/ai-assistant/weave-tab/#chat-do-weave-ai).
- Os **assistentes de IA conectados via MCP** podem ler a mesma página com a ferramenta `doc_describe`, informando o projeto, se o item é uma tabela, etapa ou fluxo de trabalho, e o id dele. Isso exige acesso de leitura a etapas, fluxos de trabalho e tabelas, e segue as mesmas regras para o que o seu perfil oculta. Consulte [Agentes de IA (MCP)](/pt-br/integrations/ai-coding-agents/).
