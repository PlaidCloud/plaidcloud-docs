Toda vez que uma tabela é gravada, o lakehouse do PlaidCloud mantém um **instantâneo** da tabela naquele momento — uma cópia consistente dos dados em um ponto no tempo. Os instantâneos permitem olhar para trás e ver o que uma tabela continha antes, se recuperar de uma carga ruim e auditar como uma tabela mudou ao longo do tempo. Até onde você pode voltar é definido pela configuração de viagem no tempo da tabela: 1 dia por padrão e até 90 dias para o padrão do projeto ou para uma tabela que o aumente. Consulte [Gerenciando o armazenamento](/pt-br/guides/projects/managing-storage/).

O painel Instantâneos permite navegar por esse histórico, abrir qualquer instantâneo somente para leitura no Explorador de tabelas e reverter ou restaurar a tabela para um instantâneo anterior.

## Abrindo o painel Instantâneos

Na lista **Tabelas** do projeto, clique no botão de instantâneo/flashback na linha de uma tabela. O painel **Instantâneos** é aberto e lista os instantâneos da tabela, do mais recente para o mais antigo:

- **Quando** — a data e a hora em que o instantâneo foi feito.
- **Linhas** — a contagem de linhas da tabela nesse instantâneo.
- **Δ Linhas** — a variação na contagem de linhas em relação ao instantâneo anterior, para que você veja o que cada gravação adicionou ou removeu.
- **Tamanho** — o tamanho de armazenamento compactado do instantâneo.
- **Rótulo** — um nome, para os instantâneos que você nomeou ou fixou.
- **Retido** — um marcador de fixação para os instantâneos que estão retidos (mantidos além da janela normal de retenção).

## Vendo os dados em um instantâneo

Há duas maneiras de ver os dados de uma tabela em um ponto anterior no tempo. Ambas abrem o Explorador de tabelas em uma **visão histórica somente leitura**, com um banner que mostra qual instantâneo você está vendo e um botão **Voltar aos dados atuais**.

1. **No painel Instantâneos** — selecione um instantâneo e clique em **Ver no instantâneo**.
2. **No Explorador de tabelas** — use a lista suspensa **As of** na barra de ferramentas. Ela lista os instantâneos recentes da tabela; escolha um para alternar a visão ou escolha **Atual (dados ativos)** para voltar aos dados ativos.

<Aside>A visão histórica é somente leitura — é uma janela para o passado, não uma cópia editável. Use **Reverter** ou **Restaurar** (abaixo) se quiser trazer dados antigos de volta para uma tabela.</Aside>

## Revertendo ou restaurando um instantâneo

Selecione um instantâneo e clique em **Reverter / Restaurar**. A caixa de diálogo oferece duas opções:

- **Revert this table in place** (padrão) — substitui os dados atuais da tabela pelo instantâneo. Como isso é destrutivo, você digita o nome da tabela para confirmar. Antes de os dados serem substituídos, o PlaidCloud captura automaticamente um **instantâneo de segurança pré-reversão** do estado atual (em mecanismos de armazenamento que oferecem suporte à fixação), para que você sempre possa voltar ao ponto em que estava. Em um lakehouse Databend, se as colunas da tabela mudaram desde o instantâneo, a reversão no local é recusada, informando as colunas que mudaram — restaure em uma nova tabela.
- **Restaurar o instantâneo em uma nova tabela** — deixa a tabela original intacta e cria uma nova tabela no projeto (você informa um nome e uma pasta), preenchida a partir do instantâneo, com as mesmas colunas da origem. Pelo assistente de IA ou pelo MCP, uma restauração sem nome informado recebe um nome baseado na tabela de origem, por exemplo `Sales (restored 3f2a9c1d)`.

<Aside type="caution">Reverter no local sobrescreve os dados atuais da tabela. A confirmação digitada e o instantâneo de segurança pré-reversão automático existem para proteger você — leia a caixa de diálogo antes de confirmar. A reversão é bloqueada enquanto o projeto estiver bloqueado.</Aside>

<Aside>Pela API REST ou pelo MCP, restaure um instantâneo no local omitindo a tabela de destino ou informando a própria tabela. Uma restauração no local ali recebe a mesma proteção da reversão da caixa de diálogo: um instantâneo de segurança pré-reversão, quando o mecanismo de armazenamento oferece suporte a ele, e um registro de auditoria. Para que ela seja recusada se a tabela tiver sido gravada desde que você listou seus instantâneos, informe o instantâneo mais recente que você viu como `expected_current_snapshot_id`.</Aside>

<Aside>Se uma restauração em uma nova tabela falhar — por exemplo, porque o instantâneo expirou — nenhuma nova tabela é adicionada ao projeto.</Aside>

## Nomeação, fixação e retenção

Os instantâneos expiram conforme a configuração de viagem no tempo da tabela (1 dia por padrão, até 90 dias) na limpeza noturna. Reverter ou restaurar funciona até o ponto restaurável mais antigo exibido para a tabela. Para manter um por mais tempo:

- **Criar instantâneo** faz um instantâneo retido dos dados atuais sob demanda — útil antes de uma recarga arriscada (por exemplo, "antes da recarga do T2").
- **Retenção** fixa o instantâneo selecionado; **Liberar** remove a retenção e o devolve ao ciclo de vida normal.

<Aside type="caution">Uma retenção mantém mais do que um instantâneo — ela mantém o instantâneo retido *e* todos os instantâneos gravados depois dele, de modo que o armazenamento continua crescendo até você liberar a retenção. Substituir uma tabela por completo (um upsert ou uma substituição SCD-2) inicia um histórico de instantâneos totalmente novo, e qualquer retenção no antigo é perdida junto com ele.</Aside>

Restaurar todas as tabelas de um projeto de uma só vez, pela API REST, restaura cada tabela para o seu instantâneo retido mais recente e deixa como estão as tabelas sem retenção. Um instantâneo de segurança pré-reversão não conta como uma retenção, embora o painel Instantâneos possa marcá-lo como retido, a menos que você também retenha esse instantâneo, por exemplo com **Retenção**. Os nomes de instantâneo que começam com `pre-revert_` são reservados para instantâneos de segurança. Se alguma tabela não puder ser restaurada, as outras ainda são restauradas, e a solicitação falha informando cada tabela que não foi restaurada e o motivo.

<Aside>Nomear um instantâneo sob demanda está disponível em tabelas do Lakehouse (StarRocks). Reter e liberar um instantâneo agora também funciona em tabelas baseadas em Databend; ali, os instantâneos ainda são mantidos durante a janela de retenção mesmo sem uma retenção.</Aside>

## Auditoria

As reversões no local, seja pela caixa de diálogo, pela API REST ou por um assistente de IA, são registradas no log de auditoria do lakehouse, incluindo quem realizou a reversão, quando, o instantâneo para o qual se reverteu e o instantâneo de segurança que foi mantido — assim, as alterações de tabela feitas por meio deste recurso são rastreáveis.
