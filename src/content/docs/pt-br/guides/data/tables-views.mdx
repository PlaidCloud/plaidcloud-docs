Os dados e as informações tabulares no PlaidCloud são armazenados em data warehouses Greenplum.  Isso oferece enorme
escalabilidade e desempenho, usando uma tecnologia bem conhecida e madura para minimizar o risco de perda ou corrupção 
de dados.

Além disso, o uso de um data warehouse que opera com uma sintaxe comum permite que ferramentas de terceiros se conectem
e explorem os dados diretamente.  Na prática, isso torna o ecossistema de dados do PlaidCloud aberto e explorável, ao mesmo tempo 
que garante segurança e controles de acesso líderes do setor.

## Tabelas

As tabelas guardam os dados tabulares físicos em todo o PlaidCloud.  Cada tabela pode guardar muitos terabytes de dados, se necessário.  Os dados são armazenados em vários
servidores físicos e espelhados automaticamente para garantir a integridade dos dados e a alta disponibilidade.

As tabelas são compostas por colunas de vários tipos de dados.  Usar um tipo de dados adequado pode ajudar no desempenho e, especialmente, no tamanho de armazenamento dos seus dados.
O PlaidCloud consegue compactar melhor os dados se eles usarem o tipo de dados mais adequado. Isso costuma ser deduzido pelo PlaidCloud, mas
também é possível alterar os tipos de dados usando os mapeadores de colunas nas etapas de fluxo de trabalho.

Você pode encontrar tabelas pelo fluxo de trabalho que as usa, por um nome de coluna ou por um valor que elas contêm, e ver quando uma tabela foi lida pela última vez. Consulte [Gerenciando tabelas e visões](/pt-br/guides/projects/managing-tables-and-views/#encontrar-tabelas).

## Visões

As visões funcionam como tabelas, mas não guardam nenhum dado físico.  São representações lógicas de tabelas derivadas por meio de uma consulta.  O uso de visões pode economizar armazenamento.

No entanto, há algumas limitações no uso de visões.  Esteja ciente do seguinte:

 * Desempenho do empilhamento de visões - O empilhamento de visões (uma visão de uma visão de uma visão... etc.) pode afetar o desempenho em tabelas muito grandes ou cálculos complexos.  Pode ser necessário criar tabelas intermediárias para melhorar o desempenho.
 * Desempenho em painéis - Embora não haja problema em publicar uma visão para uso em painéis, para tabelas muito grandes talvez seja melhor publicar uma tabela em vez de uma visão, para uma experiência ideal do usuário.
 * Dados dinâmicos - Os dados de uma visão mudam quando os dados da tabela subjacente referenciada mudam.  Isso pode ser um benefício (tudo é atualizado automaticamente) ou uma dor de cabeça inesperada, se a intenção era ter um conjunto de dados estático.

<Aside>O uso de visões pode ajudar a acelerar os fluxos de trabalho, pois nenhuma movimentação de dados é necessária no momento da execução do fluxo de trabalho.</Aside>

<Aside>Como as visões não contêm dados, você perceberá que elas não podem ser usadas como destino de importações. Nesse caso, é preciso usar uma tabela.</Aside>
