## Descrição


Os painéis oferecem suporte a uma ampla variedade de casos de uso, de relatórios estáticos a análises dinâmicas. Eles atendem a necessidades complexas de relatórios e, ao mesmo tempo, oferecem uma interface intuitiva de apontar e clicar. Pode haver momentos em que você encontre problemas. Um membro da equipe de suporte do PlaidCloud está sempre disponível para ajudar, mas também reunimos abaixo algumas dicas caso você enfrente um problema semelhante.



## **Perguntas e respostas comuns sobre painéis**



### Navegador preferido


Devido ao uso frequente de cache, o Google Chrome costuma ser o melhor navegador para usar com os painéis. Se você estiver usando outro navegador e tiver um problema, sugerimos primeiro limpar o cache e os cookies para ver se isso resolve. Se não resolver, sugerimos mudar para o Google Chrome e verificar se o problema se repete.



### Atraso de sincronização


* *Problema:* Depois de cancelar a publicação e publicar tabelas na área de Painéis, os dados parecem não estar sincronizando corretamente.
* *Soluções:* Republicar uma tabela limpa os resultados em cache de todos os gráficos que a leem, de modo que um painel aberto após a execução do fluxo de trabalho mostra os novos dados sem atualização manual. Se isso não acontecer, verifique se a execução terminou e se republicou a tabela esperada. Consulte [Cache de painéis](/pt-br/guides/dashboards/dashboard-caching/).

### Erro de sincronização de tabela


* *Problema:* Depois de recriar uma tabela usando o mesmo nome publicado de uma tabela anterior, a tabela não sincroniza, mesmo depois de atualizar o painel, publicar, cancelar a publicação e republicar a tabela.
* *Soluções:* Republique a tabela com um nome diferente. O modelo de dados do painel não permite tabelas duplicadas, nem tabelas com o mesmo nome publicado e o mesmo ID de projeto.

### Aviso de cache


* *Problema:* Apareceu um aviso no canto superior direito dizendo “Loaded data cached **3 hours ago**. Click to force-refresh.”
* *Soluções:* Clique no aviso para forçar a atualização do cache. Você também pode clicar no menu suspenso ao lado de “Edit dashboard” e selecionar “Force refresh dashboard”. Qualquer uma dessas opções atualiza dentro do sistema e é preferível a atualizar o próprio navegador. Por quanto tempo um resultado é mantido é configurável — consulte [Cache de painéis](/pt-br/guides/dashboards/dashboard-caching/).

### Aviso de permissão


* *Problema:* Meu painel publicado está exibindo o mesmo erro em cada seção em que os dados deveriam aparecer: “This endpoint requires the datasource… permission”
* *Soluções:* Verifique se as fontes de dados não estão antigas. Muito provavelmente, os gráficos estão obtendo dados de material desatualizado. Se isso acontecer, atualize os gráficos com novas fontes de dados.
* *Problema:* Estou recebendo o mesmo aviso de permissão acima, mas meu colega consegue ver os dados do gráfico.
* *Soluções:* Se o problema é que uma pessoa consegue ver os dados nos gráficos e outra não, a segunda pessoa pode precisar receber permissão de alguém da categoria autorizada. Para isso:


	1. Vá para Charts
	2. Selecione o segundo ícone pequeno de lápis e papel ao lado do gráfico ao qual você quer conceder acesso
	3. Clique em Edit Table
	4. Clique em Detail
	5. Clique em Owners, adicione o nome da pessoa a quem você quer conceder acesso e salve.

<Aside>Como prática recomendada, sempre que você criar e salvar um novo gráfico, adicione todas as pessoas aplicáveis à seção Owners nesse momento. Caso contrário, você precisará voltar para editar e adicionar proprietários sempre que alguém novo precisar de acesso.</Aside>


### Salvar filtros modificados no painel


* *Problema:* Modifiquei filtros no meu modelo de rascunho e quero salvá-los no meu painel. Os filtros não estão na lista. No meu modelo de rascunho, um aviso dizia: “There is no chart definition associated with this component, could it have been deleted? Delete this container and save to remove this message.”
* *Soluções:* Vá para “Edit Chart”. Lá, verifique se a seção “Dashboards” está preenchida com o painel correto. Se estiver em branco, adicione o nome correto do painel.

### Formatação de números: falhas


* *Problema:* A formatação dos meus números está quebrada e fora de ordem.
* *Soluções:* O motivo mais provável dessa falha é o uso de nulos em uma coluna numérica. Usando um filtro, elimine todas as colunas numéricas nulas. Tente executar novamente. Se isso não funcionar, consulte o material disponível aqui: http://bl.ocks.org/zanarmstrong/05c1e95bf7aa16c4768e ou aqui: https://github.com/apache-superset/superset-ui/issues. Por fim, sinta-se sempre à vontade para entrar em contato com um membro da equipe de suporte do PlaidCloud. Este problema é conhecido e uma solução mais permanente está em desenvolvimento.

### Formatação de números


Para arredondar números para o inteiro mais próximo:


1. *Não use:* ,.0f
2. *Use em vez disso:* ,d ou $,d para dólares

### Importar um painel existente


* *Problema:* Estou importando um painel existente e recebo um erro na minha exportação.
* *Soluções:* Primeiro, verifique o arquivo. Painéis e conjuntos de dados são importados a partir do arquivo ZIP gerado por **Exportar**. Um arquivo de exportação JSON ou YAML mais antigo é recusado; portanto, exporte o painel novamente e importe o novo arquivo ZIP.
* Em seguida, verifique se o painel tem um “Slug”. Para isso, abra Edit Dashboard; a segunda seção se chama Slug. Se essa seção estiver vazia ou disser “null”, o problema não é esse. Caso contrário, o slug precisa ser exclusivo: altere-o para algo que nenhum outro painel use, exporte novamente e importe o novo arquivo.
