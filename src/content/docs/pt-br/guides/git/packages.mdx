O PlaidCloud Git inclui um registro de pacotes integrado para artefatos distribuíveis e o Git Large File Storage (LFS) para arquivos binários grandes dentro dos seus repositórios.

## Sobre o registro de pacotes

O registro de pacotes é por proprietário e oferece suporte a uma ampla variedade de formatos de ecossistema: npm, PyPI, Maven, NuGet, RubyGems, imagens de contêiner e outros. Os pacotes são privados para o seu espaço de trabalho e acessíveis apenas por membros autenticados.

Cada tipo de pacote tem seu próprio endpoint em:

```
https://git.example.plaidcloud.com/api/packages/you/<type>
```

em que `<type>` é o identificador do ecossistema (por exemplo, `npm`, `pypi` ou `maven`).

## Autenticar no registro

As operações do gerenciador de pacotes usam seu nome de usuário do PlaidCloud Git e um token de acesso pessoal como senha. Consulte [Repositórios](/pt-br/guides/git/repositories/) para saber como criar um token.

## Publicar um pacote

As etapas variam conforme o ecossistema, mas o padrão é o mesmo: aponte seu gerenciador de pacotes para a URL do registro e execute o comando de publicação padrão dele.

Para o npm, adicione um `.npmrc` ao seu projeto para delimitar os pacotes ao registro:

```ini
@you:registry=https://git.example.plaidcloud.com/api/packages/you/npm/
//git.example.plaidcloud.com/api/packages/you/npm/:_authToken=YOUR_TOKEN
```

Depois, publique normalmente:

```bash
npm publish
```

Para PyPI, Maven, NuGet e outros ecossistemas, configure a definição de repositório ou de origem da ferramenta com a URL de registro correspondente e use o comando de publicação padrão dela (por exemplo, `twine upload`, `mvn deploy` ou `dotnet nuget push`).

## Instalar um pacote

Aponte seu gerenciador de pacotes para a mesma URL do registro e instale normalmente. Com o `.npmrc` acima configurado:

```bash
npm install @you/my-package
```

Para outros ecossistemas, adicione o registro como uma origem adicional na configuração da ferramenta e use o comando de instalação padrão dela.

## Arquivos grandes com o Git LFS

O Git LFS mantém seu repositório rápido substituindo, no histórico, arquivos grandes ou binários por ponteiros leves e armazenando os dados do arquivo separadamente. O LFS está habilitado em todos os repositórios do PlaidCloud Git.

1. Instale o cliente LFS uma vez na sua máquina:

   ```bash
   git lfs install
   ```

2. Informe ao LFS quais padrões de arquivo acompanhar, de dentro do seu repositório:

   ```bash
   git lfs track "*.parquet"
   ```

   Isso cria ou atualiza o `.gitattributes`. Faça commit desse arquivo:

   ```bash
   git add .gitattributes
   git commit -m "Track Parquet files with LFS"
   ```

3. Adicione e envie normalmente — os arquivos correspondentes são enviados ao LFS automaticamente:

   ```bash
   git add data/large-dataset.parquet
   git commit -m "Add dataset"
   git push origin main
   ```

<Aside type="tip">O Git LFS é para arquivos grandes que ficam no histórico de um repositório e são obtidos com `git clone` ou `git pull`. O registro de pacotes é para artefatos versionados e distribuíveis que os consumidores instalam com um gerenciador de pacotes. Se os colegas de equipe vão usar `npm install` ou `pip install`, use o registro; se precisarem dele como parte de um checkout, use o LFS.</Aside>
