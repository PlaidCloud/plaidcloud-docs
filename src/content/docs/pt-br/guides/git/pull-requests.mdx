## Criar um branch

Trabalhe em um novo branch para que suas alterações fiquem separadas do branch padrão até estarem prontas.

**Na interface:**

1. Abra o repositório e selecione o seletor de branch perto do canto superior esquerdo (ele mostra o nome do branch atual).
2. Digite um novo nome de branch na caixa de pesquisa e selecione **Create Branch**.

**Localmente:**

1. Crie o branch e mude para ele: `git checkout -b feature-x`
2. Faça suas alterações e depois adicione-as à área de preparação e faça commit: `git add .` e depois `git commit -m "Describe what changed"`
3. Envie o branch ao PlaidCloud Git: `git push -u origin feature-x`

## Abrir um pull request

1. Abra o repositório, selecione a guia **Pull Requests** e depois **New Pull Request**.
2. Defina o branch **Comparar** como seu branch de recurso e o branch **Base** como o de destino (geralmente `main` ou `master`).
3. Escreva um título claro e uma descrição que explique o que mudou e por quê.
4. Para vincular issues relacionadas, adicione uma palavra-chave de fechamento na descrição, por exemplo `Closes #12`, para que a issue seja fechada automaticamente quando o pull request for mesclado.
5. Atribua revisores, se necessário, e depois selecione **Create Pull Request**.

## Revisar alterações

Os revisores trabalham no pull request sem mesclar nada:

1. Abra o pull request e selecione **Files Changed** para ler o diff.
2. Selecione qualquer linha do diff para deixar um comentário em linha sobre aquela alteração específica.
3. Ao terminar, envie um veredito geral: **Aprovar** para dar o aval ou **Request Changes** para pedir revisões antes.
4. O autor envia mais commits para o mesmo branch para tratar o feedback; o pull request é atualizado automaticamente, sem necessidade de abrir um novo.
5. Os revisores marcam threads de comentários individuais como resolvidos depois que cada ponto é tratado.

<Aside>Um administrador do repositório pode habilitar a proteção de branch no branch padrão para exigir um número mínimo de aprovações antes que um pull request possa ser mesclado.</Aside>

## Mesclar

Depois que o pull request for aprovado:

1. Escolha um método de mesclagem na lista suspensa ao lado do botão **Merge**:
   - **Create a merge commit:** preserva o histórico completo do branch com um commit de mesclagem.
   - **Squash and merge:** combina todos os commits do branch em um único commit no branch de destino.
   - **Rebase and merge:** reaplica os commits do branch sobre o branch de destino sem um commit de mesclagem.
2. Selecione **Merge** para concluir.
3. Opcionalmente, selecione **Delete Branch** para limpar o branch de recurso quando ele não for mais necessário.
