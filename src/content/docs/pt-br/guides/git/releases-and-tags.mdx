Uma tag marca um commit como significativo, normalmente uma versão como `v1.2.0`. Um release se baseia em uma tag ao adicionar notas legíveis e anexos de arquivo opcionais, para que os usuários possam navegar e baixar versões específicas pela interface web.

## Criar uma tag

Você pode criar uma tag pela interface ou pelo seu clone local.

**Pela interface:**

1. Abra o repositório e selecione **Releases** e depois **Tags**.
2. Selecione **Create Tag**.
3. Informe um nome de tag (por exemplo, `v1.2.0`), escolha o branch ou commit de destino e selecione **Create Tag**.

**Pela linha de comando:**

```bash
git tag v1.2.0
git push origin v1.2.0
```

Para marcar um commit específico do passado, informe o ID do commit em vez de depender de `HEAD`:

```bash
git tag v1.2.0 abc1234
git push origin v1.2.0
```

## Publicar um release

1. Abra o repositório e selecione **Releases**.
2. Selecione **New Release**.
3. No campo **Tag Name**, escolha uma tag existente ou digite um novo nome para criar uma na ponta atual do branch padrão.
4. Informe um **Release Title** e escreva as notas do release no corpo em Markdown; changelogs, instruções de atualização e problemas conhecidos pertencem a este espaço.
5. Selecione **This is a pre-release** se a versão não estiver pronta para uso geral ou **Salvar rascunho** para terminar depois sem publicar.
6. Selecione **Publish Release** quando estiver pronto.

<Aside>Os releases em rascunho ficam visíveis apenas para membros do repositório com acesso de gravação. Um pré-release fica visível para todos com acesso, mas é excluído da designação "Latest" na visão geral do repositório.</Aside>

## Anexar arquivos

Os arquivos carregados aparecem na página do release como links de download nomeados, ao lado do arquivo de origem gerado automaticamente.

1. No formulário de novo release ou de edição, acesse a seção **Attach Files**.
2. Arraste arquivos para a área de upload ou selecione-a para navegar; binários compilados, arquivos compactados, checksums e assinaturas são escolhas comuns.
3. Repita para cada arquivo e depois publique ou atualize o release.

Mantenha cada arquivo com um tamanho razoável para que os downloads continuem rápidos para a sua equipe.

<Aside type="tip">Para pacotes instaláveis, como módulos npm, imagens de contêiner, wheels do PyPI e similares, o [registro de pacotes](/pt-br/guides/git/packages/) é mais adequado do que anexos de release. Ele entende resolução de versões, metadados de dependências e ferramentas de cliente (`npm`, `pip`, `docker pull`) de maneiras que um simples download de arquivo não entende.</Aside>

## Visualizar e baixar releases

1. Selecione **Releases** para ver a lista completa, do mais recente para o mais antigo.
2. O último release que não é pré-release é destacado com um selo **Latest**.
3. Cada entrada mostra o nome da tag, o título do release, as notas e links para:
   - **Source code:** arquivos `zip` e `tar.gz` gerados automaticamente do commit marcado.
   - **Assets:** quaisquer arquivos que você anexou ao publicar o release.
4. Selecione o link de um arquivo para baixá-lo diretamente ou copie a URL para compartilhá-lo.

Para comparar dois releases, abra os nomes das tags como uma URL de comparação:

```bash
https://git.example.plaidcloud.com/you/my-repo/compare/v1.1.0...v1.2.0
```
