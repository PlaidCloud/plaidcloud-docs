As issues dão à sua equipe um lugar compartilhado para acompanhar bugs, planejar recursos e registrar qualquer coisa que precise de atenção, tudo vinculado diretamente ao código do seu repositório.

## Criar uma issue

1. Abra o repositório e selecione a guia **Issues**.
2. Selecione **New Issue**.
3. Informe um **Título** conciso que descreva o problema ou a tarefa.
4. Escreva uma **Descrição** em Markdown, incluindo etapas de reprodução, critérios de aceitação, capturas de tela ou blocos de código, conforme necessário.
5. Selecione **Submit New Issue** para publicá-la.

<Aside>Um repositório pode definir modelos de issue reutilizáveis em **Settings → Issue Templates**. Quando há modelos configurados, ao abrir uma nova issue é exibido um seletor, para que os colaboradores comecem com um formulário consistente em vez de uma página em branco.</Aside>

## Organizar com rótulos e marcos

Os **Rótulos** categorizam e priorizam issues. Aplique um ou mais rótulos pela barra lateral direita ao visualizar uma issue, ou diretamente pela lista de issues usando o filtro **Rótulo**. As convenções comuns são rótulos de tipo (`bug`, `enhancement`) junto com rótulos de prioridade (`high`, `low`), mas você pode criar os rótulos que se adaptarem ao seu fluxo de trabalho em **Issues → Rótulos**.

Os **Marcos** agrupam issues em direção a uma meta compartilhada, como uma data de release, um sprint ou um objetivo de recurso. Crie marcos em **Issues → Milestones** e depois atribua uma issue a um marco pela barra lateral dela. A visão do marco mostra o progresso à medida que as issues são fechadas.

## Atribuir e discutir

- **Responsáveis:** use o campo **Assignees** na barra lateral para indicar quem é responsável. Qualquer membro do espaço de trabalho com acesso ao repositório pode ser atribuído.
- **Comentários:** adicione contexto, decisões ou atualizações de status no thread de comentários abaixo da descrição da issue.
- **@menções:** digite `@username` em qualquer lugar de um comentário ou de uma descrição para notificar diretamente essa pessoa.
- **Reações:** use reações com emoji nos comentários para reconhecer um ponto sem adicionar uma resposta.

## Vincular issues ao código

Referenciar issues em commits e pull requests mantém seu histórico rastreável.

- **Referência por número:** digite `#12` em uma mensagem de commit, na descrição de um pull request ou em um comentário para criar um link clicável para a issue 12 no mesmo repositório.
- **Fechamento automático na mesclagem:** inclua uma palavra-chave de fechamento na descrição de um pull request (por exemplo, `Closes #12`, `Fixes #34` ou `Resolves #56`). Quando o pull request é mesclado no branch padrão, as issues referenciadas são fechadas automaticamente.
- **Referência cruzada a outras issues:** use `#number` livremente em qualquer comentário de issue para vincular issues relacionadas; cada issue referenciada exibe um link de volta, de modo que a conexão fica visível dos dois lados.

## Encontrar issues

A lista de issues oferece vários filtros que você pode combinar:

| Filtro | O que faz |
|---|---|
| **Estado** | Mostra issues abertas ou fechadas |
| **Rótulo** | Restringe a um ou mais rótulos |
| **Marco** | Mostra as issues atribuídas a um marco |
| **Responsável** | Mostra as issues atribuídas a uma pessoa específica |
| **Autor** | Mostra as issues abertas por uma pessoa específica |

Selecione a coluna correspondente na barra de filtros acima da lista de issues para aplicar cada filtro. Para pesquisar por palavras-chave nos títulos e nos corpos das issues, consulte [Pesquisar código](/pt-br/guides/git/searching-code/).
