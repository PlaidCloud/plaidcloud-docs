Um **sistema** é uma conexão ERP em um ambiente. A etapa **Lançar documentos**, um lançamento a partir de um arquivo e toda outra forma de lançar (consulte [Lançar documentos em sistemas ERP](/pt-br/guides/connections/post-documents/)) enviam cada documento a um sistema, e o sistema decide como o documento é montado, verificado e enviado. Toda conexão ERP que você pode ver aparece por conta própria como um sistema — cinco conexões SAP são cinco sistemas, na nuvem e locais lado a lado — e a mesma conexão em um [ambiente](/pt-br/guides/connections/create-connection/#ambientes) de sandbox e em um de produção são dois sistemas, cada um com suas próprias configurações.

Você configura os sistemas uma vez por ambiente. Todo projeto nesse ambiente compartilha a grade de qual entidade lança onde e as configurações de cada sistema. Somente Entrar em produção é feito por projeto.

## Abrir Sistemas

Abra o [Registro de lançamentos](/pt-br/guides/connections/posting-register/) e escolha **Sistemas** em **Configurações** na barra lateral. O cabeçalho tem:

- Um seletor de ambiente: o ambiente cujos sistemas são listados.
- Um seletor de projeto, que começa em **Sem projeto**. Escolha um projeto para ver se cada sistema está Ao vivo nele e para entrar em produção.
- **Ações**, com **Entrar em produção neste projeto…** (exibido para um arquiteto do projeto), **Copiar para outro ambiente…** (exibido para um administrador do workspace), **Sugerir qual entidade lança onde…** e **Histórico de alterações**.

A página mostra dois cartões: **Sistemas · *ambiente*** e **Qual entidade lança onde**. Sem nenhuma conexão ERP no ambiente, a página diz **Nenhum sistema para lançar**: adicione uma conexão a um sistema ERP em Conexões e ela aparece aqui.

## A lista de sistemas

Cada sistema é uma linha: seu nome, seu tipo de ERP e um conjunto de selos.

| Selo | O que diz |
|---|---|
| **Nuvem** | Um sistema na nuvem. |
| **Local · agente online** | Um sistema local cujo agente entrou em contato nos últimos cinco minutos. |
| **Local · agente offline desde *hora*** / **Local · agente não conectado** | O agente não está online, ou nenhum agente atende este ambiente. |
| **Pode lançar** | O sistema pode receber lançamentos. |
| **Não verificado** | Um sistema local cujo agente não está online. |
| **Ao vivo** / **Simular** | Exibido somente com um projeto escolhido: se este sistema lança de verdade nesse projeto. |
| **Desativado** | O sistema não recebe novos lançamentos. Exibido no lugar de Ao vivo ou Simular. |

Uma linha também pode ter dois botões:

- **Reconectar** — exibido quando o agente de um sistema local não está online. Ele abre a conexão para que você entre novamente.
- **Entrar em produção ›** — exibido para um arquiteto do projeto, com um projeto escolhido, em um sistema que não está Desativado, pode receber lançamentos e ainda está em Simular. Consulte [Entrar em produção](#entrar-em-produção).

### O que uma linha abre

Abra uma linha com a seta no lado esquerdo dela. Ela mostra três itens e uma linha de links.

**O que falta** é a lista de verificação do que separa o sistema do lançamento, cada item com quem o faz. Um item concluído é marcado e sinalizado como concluído.

| Item | Quem | Concluído quando |
|---|---|---|
| Conta de serviço e suas permissões | **TI** | Sempre concluído por enquanto; nada a configurar. |
| Agente instalado e online (somente local) | **TI** | O agente está online. |
| Uma entidade lança neste sistema | **Administrador do workspace** | Uma linha de [Qual entidade lança onde](#qual-entidade-lança-onde) nomeia este sistema. |
| Entrar em produção | **Arquiteto do projeto** | O sistema está Ao vivo no projeto escolhido. |

**O que ele pode fazer** é uma linha, como "Aceita lançamentos contábeis, faturas de clientes · estorna lançamentos contábeis · respostas na própria chamada". Ela lista os tipos de documento que o sistema aceita, os que ele consegue estornar e se a resposta dele chega como **respostas na própria chamada** ou **respostas depois**. A lista completa de cada sistema está abaixo, em [O que cada sistema pode fazer](#o-que-cada-sistema-pode-fazer).

**Cópia das suas listas** mostra a idade da cópia que o sistema tem de suas contas, empresas e períodos, com **Atualizar agora** e **Ver a cópia**. Consulte [A cópia das listas de um sistema](#a-cópia-das-listas-de-um-sistema).

Os links abaixo deles são **Para TI**, **Configurações…**, **Marcar como Desativado** (ou **Reativar de Desativado**) e **Histórico**, que abre o [Histórico de alterações](#histórico-de-alterações) somente deste sistema.

## As configurações existentes

Toda configuração tem um valor inicial, e a maioria dos projetos nunca altera nenhuma.

| Configuração | Onde | Quem altera | Valor inicial |
|---|---|---|---|
| Qual entidade lança onde | [Sistemas](#qual-entidade-lança-onde), uma vez por ambiente | Um administrador do workspace | Nenhuma linha. Sem linhas, o único sistema que não está Desativado listado em **Sistemas** recebe todas as entidades. |
| Desativado | A linha de um sistema | Um administrador do workspace | Não desativado |
| Simular ou Ao vivo | [Entrar em produção](#entrar-em-produção), por sistema, por projeto | O arquiteto do projeto | Simular |
| **Valores necessários sempre** | As [Configurações](#configurações-do-sistema) de um sistema | Um administrador do workspace | Nenhum |
| **Correspondências de código** (incluindo a correspondência de entidade) | As [Configurações](#configurações-do-sistema) de um sistema | Um administrador do workspace | Nenhuma |
| **A função própria do cliente** (SAP local) | As [Configurações](#configurações-do-sistema) de um sistema | Um administrador do workspace | Nenhuma, ou a função que uma etapa convertida traz |
| Regras de retenção | [Regras de retenção](#regras-de-retenção), por sistema | Um administrador do registro (`erp.register.admin`) | Nada é retido |
| **Reter para uma pessoa** | A etapa, em **Mais ▸** | Quem criou a etapa | Nada é retido |
| **Quem é avisado** | A etapa, em **Mais ▸** | Quem criou a etapa | **Quem iniciou a execução** |
| **Conta de arredondamento e limite** | A etapa, em **Mais ▸** | Quem criou a etapa | Sem arredondamento |
| **Quando um documento lançado volta alterado** | A etapa, em **Mais ▸** | Quem criou a etapa | **Perguntar (valor inicial). Vai para Requer atenção com duas opções.** |

As quatro configurações da etapa são descritas junto com a etapa em [Lançar documentos em sistemas ERP](/pt-br/guides/connections/post-documents/); a retenção de uma etapa é descrita [abaixo](#a-retenção-própria-de-uma-etapa).

## Configurações do sistema

Escolha **Configurações…** em uma linha aberta. A caixa de diálogo, **Configurações: *sistema***, só pode ser editada por um administrador do workspace; qualquer outra pessoa vê **Somente um administrador do workspace pode alterar estas configurações.** **Salvar** substitui todas as configurações do sistema, e cada alteração é registrada no [Histórico de alterações](#histórico-de-alterações).

**Valores necessários sempre** são valores adicionados a todo documento enviado a este sistema, como pares **Valor** e **Definir como**. Um sistema lê pelo nome os que ele precisa, e uma coluna do próprio documento com o mesmo significado prevalece sobre o valor do sistema:

| Sistema | Valor | Usado para |
|---|---|---|
| Sage Intacct | `gl_journal_id` | O diário no qual um lançamento contábil é lançado, quando o documento não tem `journal_type`. |
| Sage 100 | `bank_code` | A conta bancária contra a qual um pagamento é emitido, quando o documento não tem `bank_code`. |

**Correspondências de código** dizem onde um código daqui é outro código no sistema: uma **Dimensão**, **Nosso código** e **Código no sistema**. Use a dimensão `entity` para uma entidade cuja empresa no sistema tem outro código, e `account` para uma conta. As [verificações](#verificações-em-relação-às-listas) buscam um código nas listas do sistema por meio da sua correspondência, ou como estão escritos quando não há uma, e uma correspondência de entidade também permite que a grade [sugira](#linhas-sugeridas) este sistema para essa entidade.

**A função própria do cliente** aparece somente para o SAP local. Informe a função de cada **Tipo de documento**. As configurações nomeiam apenas a função: a correspondência de campos de cada função — qual campo do SAP recebe qual coluna — fica no sistema como está, e uma função trazida por uma etapa de lançamento SAP convertida mantém a correspondência de campos que a etapa tinha. Consulte [SAP local](#sap-local).

## Qual entidade lança onde

O segundo cartão é a grade de qual entidade lança em qual sistema, a partir de qual data, definida uma vez por ambiente e compartilhada por todos os projetos nele. Cada linha é uma entidade, **→**, um sistema e um campo opcional **De (AAAA-MM-DD)**.

1. Escolha **Adicionar uma linha**, digite a entidade e escolha um sistema em **Escolha um sistema**. Somente sistemas que não estão Desativados são oferecidos.
2. Deixe **De (AAAA-MM-DD)** em branco para "desde o início", ou informe a data em que a entidade começa a lançar nesse sistema. Para mover uma entidade para outro sistema no meio do ano, mantenha a primeira linha dela e adicione uma segunda linha para o novo sistema a partir da data da mudança, por exemplo `2026-07-01`.
3. Escolha **Salvar**. Uma data que não esteja nesse formato é recusada com **Uma data tem o formato 2026-07-01.**

Editar a grade exige um administrador do workspace; qualquer outra pessoa a vê somente para leitura. Uma entidade já salva não pode ser renomeada: remova a linha dela com a cruz no final e adicione outra. As entidades que documentos citaram mas que nenhuma linha nomeia ainda são listadas sem sistema escolhido; se não houver nenhuma, o cartão diz **Ainda não há entidades. São as que aparecem nas tabelas que você lança. Adicione uma linha para nomear uma.**

### Como um documento encontra seu sistema

Um documento é lançado pelos sistemas do ambiente do seu projeto.

- O sistema dele é a linha mais recente da entidade cuja data **De** é igual ou anterior à data de lançamento do documento (hoje, quando ele não tem uma).
- Quando a grade do ambiente não tem nenhuma linha e apenas um sistema que não está Desativado está listado em **Sistemas**, esse sistema recebe todos os documentos.
- Um documento cuja entidade nenhuma linha cobre nessa data não é lançado e informa que não há sistema para a entidade dele.
- Um documento cuja linha nomeia um sistema Desativado não é lançado e informa que o sistema está desativado.

### Linhas sugeridas

Para uma entidade que nenhuma linha nomeia ainda, a grade sugere um sistema quando exatamente um sistema do ambiente que não está Desativado nomeia essa entidade — por meio de uma [correspondência de código](#configurações-do-sistema) `entity` ou na própria cópia da sua lista de empresas. A linha mostra **Sugerido** e continua somente para leitura até que você escolha **Aceitar**; somente as linhas aceitas são salvas.

**Sugerir qual entidade lança onde…** em **Ações** é a sugestão do Weave a partir do Data Foundation: com um projeto escolhido, ele preenche cada entidade que o Data Foundation do projeto carregou com a conexão da qual a carregou. Nada é calculado por um modelo e nada é salvo: as linhas são preenchidas, uma mensagem informa quantas e você lê cada uma e escolhe **Salvar**. Sem nada carregado, ele diz **Ainda sem sugestões.**

### Linhas que você não pode alterar aqui

- Uma linha cujo sistema está Desativado é exibida somente para leitura com **Desativado**. Salvar a grade a mantém.
- Uma linha cujo sistema você não pode ver é exibida somente para leitura com **Não está nesta lista**. Salvar a grade a remove, então **Salvar** primeiro pede que você confirme em **Salvar roteamento**.

## Entrar em produção

Nada é lançado de verdade até que alguém entre em produção de propósito. Entrar em produção é por sistema e por projeto: em um projeto, alguns sistemas podem estar Ao vivo enquanto outros ainda estão em Simular. Um projeto novo, copiado ou de avaliação começa em Simular em todos os sistemas até que alguém entre em produção nele.

1. Escolha o projeto no seletor de projeto do cabeçalho.
2. Escolha **Entrar em produção ›** na linha de um sistema, ou **Entrar em produção neste projeto…** em **Ações** para todos os sistemas que podem receber lançamentos e ainda não estão Ao vivo. Sem um projeto escolhido, você é avisado: **Escolha um projeto para entrar em produção.**
3. A caixa de diálogo **Entrar em produção** primeiro verifica o que mudaria, sem alterar nada, e mostra:
   - **Estes passam a Ao vivo**: os sistemas que vão lançar de verdade.
   - **O modo de lançamento do projeto passa a Em produção, então todo sistema em produção lança de verdade.** — exibido quando o próprio projeto ainda não está no modo Ao vivo.
   - **Já estão Ao vivo**: os sistemas que já estão.
   - ***sistema* não pode entrar Ao vivo:** com o motivo: o sistema está Desativado, o projeto está bloqueado, você não tem acesso de gravação a essa conexão, ou não é um sistema no qual você pode lançar.
4. Escolha **Entrar em produção**. Ele só fica habilitado quando pelo menos um sistema passaria a Ao vivo.

Entrar em produção grava a autorização do projeto para esses sistemas nesse ambiente e define o modo de lançamento do projeto como Ao vivo quando ele não estava. Cada sistema que entra em produção é registrado no [Histórico de alterações](#histórico-de-alterações). Entrar em produção nunca é copiado para outro ambiente ou projeto.

Entrar em produção exige o arquiteto do projeto, em um projeto que não está bloqueado, com o seu próprio acesso de gravação a cada conexão. A mesma verificação vale pela API REST (`POST /erp/go-live`) e pela ferramenta MCP `erp_go_live`, que também recusa um token de IA delegado: uma pessoa entra em produção, nunca um agente atuando por ela. Ambas apenas informam o que mudaria, a menos que `dry_run` seja definido como false.

## Desativar um sistema

Escolha **Marcar como Desativado** em uma linha aberta e confirme com **Aposentar**: o sistema deixa de ser oferecido para lançamento até ser reativado. As linhas dele na grade são mantidas, e os documentos roteados para ele não são lançados. **Reativar de Desativado** reverte isso. Ambos exigem um administrador do workspace e são registrados no [Histórico de alterações](#histórico-de-alterações).

## Para TI

**Para TI** abre **Para TI: *sistema***, o que o produto faz neste sistema para que possa ser permitido e auditado:

- **Entra como** — a conta com a qual a conexão entra.
- **Tamanho do lote** — o tamanho do lote que as configurações do sistema definem, ou **Não definido**.
- **Agente** e **Versão do agente** — para um sistema local.
- **Como chamamos** — cada função ou serviço que o produto chama pelo nome, com a data do último uso. Para o SAP local, são as funções definidas em [Configurações](#configurações-do-sistema). Antes de qualquer lançamento ou teste, ele diz **Nada ainda. Aparece aqui depois que este sistema receber um lançamento ou um teste.**

Quando o login expirou, a caixa de diálogo informa isso e oferece **Reconectar**.

## Copiar para outro ambiente

Configure uma sandbox uma vez e copie-a para a produção em vez de digitar tudo de novo. Escolha **Copiar para outro ambiente…** em **Ações** (somente um administrador do workspace).

1. Escolha o ambiente em **Copiar para**.
2. Todos os sistemas deste ambiente são listados e marcados quando a mesma conexão é um sistema no outro ambiente; um que não é aparece como ***sistema* (não está neste ambiente)** e não pode ser marcado.
3. Escolha **Copiar** e confirme.

Para cada sistema marcado, a cópia substitui as configurações, as correspondências de código e as funções SAP desse sistema no outro ambiente por estas, e adiciona as linhas da grade que o nomeiam e que o outro ambiente não tem (a mesma entidade a partir da mesma data). As linhas que já existem são mantidas como estão. O resultado informa quantas linhas da grade e as configurações de quantos sistemas foram copiadas. Entrar em produção não é copiado: todo projeto do outro ambiente continua em Simular até que alguém entre em produção lá.

## A cópia das listas de um sistema

As verificações comparam os documentos com as **Contas**, **Empresas** e **Períodos** do próprio sistema. O PlaidCloud mantém uma cópia de cada uma, lida do próprio sistema:

- **No início de toda execução Ao vivo em um sistema Ao vivo**, a partir do sistema, com até 60 segundos para a leitura inteira. Somente a leitura dessa execução pode barrar um documento.
- **Em Atualizar agora**, em uma linha aberta. Atualizar contata o seu sistema ERP como o lançamento faz, então exige um administrador do workspace e o seu próprio acesso de gravação a essa conexão. Ele informa quantas contas, empresas e períodos leu e quanto tempo a leitura levou. Uma cópia atualizada serve para visualização: ela não alimenta uma verificação.

Cada lista mostra sua idade na linha — como "Contas lidas há 3 horas", "Períodos parciais, lidos há 2 dias" ou "Empresas ainda não lidas" — ou informa que não pôde ser lida e por quê. Uma cópia que foi interrompida ou voltou vazia não substitui a anterior.

**Ver a cópia** abre **Cópia das listas**, uma lista por vez (**Contas**, **Empresas** ou **Períodos**), com **Código**, **Nome**, **Bloqueado**, **Status no sistema**, **De** e **Até**. Ela mostra até as primeiras 5.000 linhas. Códigos de imposto, clientes e fornecedores não são copiados; ficam a cargo do sistema.

Uma execução em Simular não lê nada do sistema, então em Simular essas verificações não são executadas e o sistema decide quando você entrar em produção.

## Verificações em relação às listas

No início de uma execução Ao vivo em um sistema Ao vivo, cada documento é verificado em relação às listas que essa execução leu. Uma verificação cuja lista não pôde ser lida, voltou parcial ou vazia, ou não terminou a tempo não é realizada — nunca é aprovada, nunca barra — e o sistema decide. A página da execução mostra quais verificações foram executadas em cada documento.

- **Period open** (Período aberto). O período do documento é encontrado pelo código do período, ou então pelos períodos em que a data de lançamento dele se enquadra. Ele só é barrado quando todos os períodos que o contêm estão fechados para lançamento no sistema — um período de ajuste que se sobrepõe ao mês dele mantém a data aberta. Um período cujo status o sistema informa em palavras que o PlaidCloud não conhece não é verificado.
- **A entidade é uma empresa.** Quando a lista de empresas foi lida, a entidade do documento — por meio da correspondência de código `entity`, se houver uma, ou como está escrita — deve ser uma das empresas do sistema.
- **As contas existem.** Quando a lista de contas foi lida, a conta de cada linha — por meio da correspondência de código `account`, se houver uma, ou como está escrita — deve estar no sistema e não bloqueada para lançamento. Códigos numéricos correspondem independentemente dos zeros à esquerda, então `6100` encontra `0000006100`.

Um documento barrado fica como Não lançado com o motivo, como "Linha 3: a conta 6100 não está em *sistema*". As listas que cada sistema ERP oferece estão na tabela abaixo.

## Regras de retenção

Nada é retido até que uma regra determine. Um documento que uma regra retém aguarda como Requer aprovação até que uma pessoa o aprove em [Aprovações](/pt-br/guides/connections/posting-register/); todo o resto que passa nas verificações é enviado sem isso. Escolha **Regras de retenção** em **Configurações** na barra lateral.

A lista tem **Nome**, **Aplica-se a**, **Reter quando**, **Aprovado por** e **Por**. Sem regras, ela diz **Nada está retido**. Qualquer pessoa com `erp.register.view` pode ler as regras; adicionar, editar e excluir exigem um administrador do registro (`erp.register.admin`), que vê **Nova regra**, **Editar** e **Excluir** na barra de ferramentas. Excluir uma regra faz com que ela deixe de reter qualquer coisa nova; os documentos que já estão aguardando continuam aguardando até que alguém decida. Toda alteração é registrada no [Histórico de alterações](#histórico-de-alterações).

### As condições de uma regra

**Nova regra** abre **Nova regra de retenção**:

1. Dê um **Nome** à regra, por exemplo "Lançamentos contábeis acima de 250.000".
2. Escolha o sistema em **Aplica-se a**. São oferecidos os sistemas de todos os ambientes que você pode ver.
3. Marque o que retém um documento em **Reter quando**. Todas as condições marcadas devem valer; sem nenhuma marcada, nada é retido.
   - **O valor é maior que** um número, **na moeda própria da entidade**: o tamanho do documento é a soma dos débitos com os valores locais positivos, ou os valores da transação quando a tabela não informa valores locais.
   - **Foi lançado a partir de um arquivo**.
   - **É um(a)** **estorno**, **crédito** ou **correção** — marque qualquer um dos três.
   - **Está marcado como incomum** — consulte [Marcado como incomum](#marcado-como-incomum).
   - **Sempre, por exemplo durante o fechamento** — retém todos os documentos do sistema; desativa as outras condições.
4. Escolha quem aprova em **Aprovado por**: **Os aprovadores do registro** ou **Pessoas nomeadas** — marque as pessoas e, opcionalmente, as entidades para as quais elas aprovam, separadas por vírgulas (em branco significa todas as entidades).
5. Escolha **Salvar**. Ele fica habilitado quando a regra tem um nome, um sistema, pelo menos uma condição, um valor que seja um número e, para pessoas nomeadas, pelo menos uma pessoa.

Um documento retido retém todos os outros documentos do seu conjunto, então um conjunto é aprovado e lançado como um só.

### Quem pode aprovar

Um aprovador precisa de `erp.register.approve` e da sua própria concessão na conexão do documento. Quando a regra nomeia pessoas, somente essas pessoas aprovam — e somente para as entidades que ela lista, se listar alguma. Ninguém aprova um documento que enviou: nem a pessoa que iniciou a execução, nem a pessoa cujo **Lançar estes** o enviou.

Uma aprovação dada enquanto o documento foi enviado em Simular não vale para um envio Ao vivo: quando o mesmo documento é enviado depois Ao vivo, ele é retido novamente para uma nova decisão.

Se o seu workspace exige separação de funções para lançamentos, um estorno, crédito ou correção que ela cobre também é retido para uma segunda pessoa, mesmo sem nenhuma regra.

### A retenção própria de uma etapa

Uma etapa **Lançar documentos** pode reter mais do que os sistemas retêm, em **Mais ▸** → **Reter para uma pessoa**. Suas condições são **O valor é superior a**, **Foi lançado a partir de um arquivo**, **É um estorno, crédito ou correção**, **Está marcado como incomum** e **Sempre**, combinadas da mesma forma; sem nada marcado, nada mais é retido. A retenção de uma etapa apenas se soma às regras do sistema — ela não pode liberar o que uma regra do sistema retém — e seus documentos são aprovados pelos aprovadores do registro. Aprovadores nomeados são definidos em uma regra do sistema.

Alterar a retenção de uma etapa pela API REST (`PUT /erp/steps/{step_id}/holds`) ou pela ferramenta MCP `erp_hold_upsert` exige `analyze.step.write` e a função de Arquiteto ou Gerente do projeto em um projeto que não está bloqueado.

### Marcado como incomum

Um documento é marcado como incomum quando, em comparação com o que a entidade dele lançou antes:

- o valor dele é mais de dez vezes maior ou menor que o do último lançamento da mesma referência;
- ele usa uma conta, cliente, fornecedor ou parceiro comercial que a entidade dele não usou nos últimos 500 documentos; ou
- a data de lançamento dele está fora do seu período.

Cada marcação registra a frase que diz por quê, como "A data de lançamento 2026-08-02 está fora do período 2026-07." A marcação é calculada a partir dos documentos anteriores da entidade; nenhum modelo de IA é chamado. Uma entidade sem documentos anteriores nunca é marcada.

## O que cada sistema pode fazer

Todo sistema abaixo pode ser executado em Simular, que monta e verifica cada documento e não envia nada. Um documento de um tipo que o sistema dele não aceita fica como Não lançado; ele não é convertido em outro tipo.

Uma resposta **na chamada** volta quando o documento é enviado. Uma resposta **depois** chega após o envio, e o documento fica Aguardando até que ela chegue; um documento cuja resposta nunca se resolve fica Não confirmado, e você o resolve a partir do [Registro de lançamentos](/pt-br/guides/connections/posting-register/).

### SAP local

O SAP local lança por meio do agente, chamando a função própria do cliente para cada tipo de documento — definida em [**A função própria do cliente**](#configurações-do-sistema). Um documento cujo tipo não tem função, ou cuja correspondência de campos da função não tem nenhum campo para a referência do documento, fica como Não lançado. Converter uma etapa de lançamento SAP existente traz a função e a correspondência de campos dela para o sistema, quando o sistema ainda não tem uma função para esse tipo de documento; consulte [Lançar documentos em sistemas ERP](/pt-br/guides/connections/post-documents/).

- **Simular** monta a mesma solicitação e para antes do agente: nada chega ao SAP.
- **Ao vivo** entrega os documentos ao agente que atende o ambiente do sistema. O agente grava as respostas do SAP em um relatório na conta de documentos padrão do projeto (em `/erp_posting/sap`), e cada documento continua Aguardando até que esse relatório seja lido. Um projeto sem conta de documentos padrão não pode lançar no SAP Ao vivo, e seus documentos ficam como Não lançados com esse motivo.
- **Quando o agente está offline**, nada é enviado: os documentos ficam como Não lançados, informando que o agente estava offline, e podem ser tentados novamente quando ele voltar. Quando o agente não aceita os documentos em cerca de 18 segundos, eles são recolhidos sem envio e ficam como Não lançados da mesma forma.
- Um documento que o relatório do SAP deixa indefinido fica como Não confirmado. Resolva-o a partir do Registro de lançamentos.

### Sage 100

O Sage 100 é local e não tem API de rede: os documentos chegam a ele por meio do agente, que executa a Business Object Interface da Sage.

- **Uma empresa por conexão.** A conexão nomeia a empresa Sage e a moeda dela. Um documento de outra empresa, ou com uma linha em outra moeda, não é enviado.
- **Lançamentos contábeis** são lançados como lançamentos de diário do razão. A referência de um lançamento é a descrição dele no Sage, então pode ter no máximo 30 caracteres.
- **Pagamentos** são lançados como cheques manuais de contas a pagar para pagamentos feitos fora do Sage: um fornecedor por pagamento, a referência como número do cheque (no máximo 7 caracteres), um `bank_code` (do documento ou dos [valores necessários sempre](#configurações-do-sistema) do sistema) e cada linha nomeando a fatura que ela paga com um valor positivo.
- **Em uma execução Ao vivo**, o agente consulta o Sage primeiro: um lançamento contábil com data em um período que o Sage fechou é barrado, assim como um pagamento de uma fatura que o Sage não mantém em aberto.
- **Após o envio**, um documento só fica Lançado quando as tabelas de lançamentos do Sage o mostram. Um documento inserido em um lote do Sage mas ainda não atualizado continua Aguardando; uma varredura em segundo plano consulta o agente novamente, no máximo uma vez por hora, e um que ainda esteja aguardando após sete dias passa a Não confirmado.

## Histórico de alterações

Toda alteração em um sistema é registrada com quem a fez e quando: **Configurações do sistema**, **Desativado**, **Função SAP**, **Correspondência de código**, **Qual entidade lança onde**, **Regra de retenção**, **Entrar em produção** e **Cópia de listas** (cada leitura das listas de um sistema). Escolha **Histórico de alterações** em **Configurações** na barra lateral ou no menu **Ações**, ou **Histórico** na linha de um sistema para ver somente esse sistema. A lista tem **Quando**, **Por**, **O quê**, **Sistema**, **Qual**, **De** e **Até**.

Você vê as alterações nos sistemas nos quais tem uma concessão; uma entrada em produção apenas para projetos que você alcança, e a retenção de uma etapa apenas em projetos que você alcança.

## Quem pode fazer o quê

Toda regra abaixo é verificada pelo servidor, da mesma forma para o aplicativo, a API REST e as ferramentas MCP, a menos que a linha diga o contrário.

| Para | Você precisa de |
|---|---|
| Ver Sistemas, as configurações de um sistema, a grade e a cópia das listas | `analyze.connection.read`, e somente as conexões que você pode ver |
| Alterar configurações, desativar um sistema, salvar a grade, copiar para outro ambiente | Um administrador do workspace |
| Atualizar as listas de um sistema | Um administrador do workspace na página Sistemas, ou `analyze.connection.read` pela API REST e pela ferramenta MCP `erp_system_lists`; de qualquer forma, o seu próprio acesso de gravação a essa conexão |
| Entrar em produção | O arquiteto do projeto em um projeto que não está bloqueado, com o seu próprio acesso de gravação a cada conexão; uma pessoa, nunca um token de IA delegado |
| Ler regras de retenção | `erp.register.view` |
| Adicionar, alterar ou excluir a regra de retenção de um sistema | Um administrador do registro (`erp.register.admin`) |
| Alterar a retenção própria de uma etapa | `analyze.step.write` e a função de Arquiteto ou Gerente do projeto em um projeto que não está bloqueado |
| Aprovar um documento retido | `erp.register.approve` e a sua própria concessão na conexão do documento; nomeado na regra quando ela nomeia pessoas; nunca o seu próprio envio |
