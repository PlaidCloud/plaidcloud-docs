O [Data Foundation](/pt-br/guides/projects/data-foundation/) reúne os dados de todos os sistemas ERP e instâncias que você conecta em um único Common Finance Model, e o Microsoft Dynamics 365 Business Central é um dos ERPs que ele lê diretamente. A conexão usa um aplicativo do Microsoft Entra ID com credenciais de cliente, um conjunto de permissões somente leitura e alguns objetos de página publicados como serviços web. Esta página é destinada ao administrador do Business Central que faz essa configuração e ao usuário do PlaidCloud que solicita isso a ele.

O PlaidCloud apenas lê dados. Ninguém envia um segredo do cliente por e-mail.

## Enviar a solicitação de acesso

Na página **Sistemas** do projeto, em **Data Foundation**, no **Início**, escolha seu sistema em **Sistema**, em **Adicionar um sistema**, e clique em **Ainda não tem acesso?**. O sistema fica aguardando acesso, e é exibida uma única solicitação que abrange os sistemas do projeto. Clique em **Copiar solicitação** para colá-la em sua própria mensagem ou em **Enviar solicitação por e-mail** para abri-la em seu programa de e-mail, com o assunto "Acesso ao PlaidCloud."

## O que o administrador do Business Central configura

<Steps>

1. **Registre um aplicativo no Microsoft Entra ID.** Em **App registrations > New registration**, adicione um segredo do cliente e anote o ID do diretório (tenant), o ID do aplicativo (cliente) e o segredo.

2. **Adicione o aplicativo no Business Central.** Abra **Microsoft Entra Applications**, adicione o aplicativo, defina seu estado como **Ativado** e atribua a ele apenas o conjunto de permissões **D365 READ**, para cada empresa sobre a qual você gera relatórios. Ele lê todas as páginas abaixo. Não atribua a ele o **D365 BASIC** nem qualquer outro conjunto de permissões que possa gravar.

3. **Publique objetos de página como serviços web.** Em **Search > Web Services > New**, publique estes objetos de página exatamente com estes nomes de serviço e com **Published** marcado. A API padrão não inclui os campos deles:

   | Página | Nome do serviço | Observações |
   |---|---|---|
   | 20 G/L Entries | `GLEntries` | |
   | 16 Chart of Accounts | `GLAccounts` | |
   | 100 Accounting Periods | `AccountingPeriods` | |
   | 537 Dimension Values | `DimensionValues` | |
   | 240 Business Units | `BusinessUnits` | |
   | 605 IC Partner List | `ICPartners` | |
   | 5802 Value Entries | `ValueEntries` | Custo dos produtos vendidos e saldos de estoque; opcional |
   | 120 G/L Budget Entries | `GLBudgetEntries` | Orçamentos; opcional |
   | Statistical Ledger Entries | `StatisticalLedgerEntries` | Direcionadores estatísticos; opcional |
   | 118 General Ledger Setup | `GeneralLedgerSetup` | Dimensões de atalho 3 a 8; opcional |
   | 479 Dimension Set Entries | `DimensionSetEntries` | Dimensões de atalho 3 a 8; opcional |
   | 573 Detailed Cust. Ledg. Entries | `DetailedCustLedgEntries` | Itens em aberto e pagamentos; opcional |
   | 574 Detailed Vendor Ledg. Entries | `DetailedVendorLedgEntries` | Itens em aberto e pagamentos; opcional |
   | 371 Bank Account List | `BankAccounts` | Saldos bancários; opcional |
   | 277 Bank Account Posting Groups | `BankAccountPostingGroups` | Saldos bancários; opcional |
   | Inventory Posting Setup (pesquise a página dela) | `InventoryPostingSetup` | A conta das linhas de compra de um item; opcional |

4. **Informe ao usuário do PlaidCloud três escolhas:** o código de origem sob o qual seus ajustes de auditoria são lançados (o PlaidCloud presume `ADJUSTMENT`), qual dimensão representa seu departamento (o PlaidCloud presume a Global Dimension 1, chamada `DEPARTMENT`) e qual representa seu centro de lucro (o PlaidCloud presume a Global Dimension 2, chamada `PROFITCENTER`). Um site é um local do Business Central.

</Steps>

## O que enviar de volta

| O administrador envia | Informado no PlaidCloud como |
|---|---|
| O ID do diretório (tenant) | **ID do tenant do Azure AD** |
| O ID do aplicativo (cliente) | **ID do cliente** |
| O segredo do cliente | **Segredo do cliente**, informado no editor de conexões, não por e-mail |
| O nome do ambiente, por exemplo `production` | **Ambiente** |
| O ID de uma empresa | **ID da empresa**: a conexão precisa de um, e o Data Foundation lê as empresas escolhidas em **Empresas** |
| O nome da dimensão que representa seu departamento | A configuração de sistema **Department dimension** |
| O nome da dimensão que representa seu centro de lucro | A configuração de sistema **Profit centre dimension** |
| O código de origem sob o qual seus ajustes de auditoria são lançados | A configuração de sistema **Audit adjustment source code** |
| As empresas que o PlaidCloud pode ler | Em **Opções**, **Empresas**: marque-as, ou nenhuma para todas as empresas |

As empresas de consolidação entram na configuração de sistema **Consolidation companies**, para que seus lançamentos não sejam contados como atividade de uma empresa. As taxas de câmbio vêm de uma única empresa. Indique-a na configuração de sistema **Exchange rate company**; caso contrário, o PlaidCloud usa a primeira empresa.

## Verificar o acesso

De volta ao PlaidCloud, depois de adicionar o sistema, clique em **Testar conexão** na linha dele na página **Sistemas**. Cada conjunto de dados aparece como **Legível**, **Permissão ausente** ou **Erro**:

| Conjunto de dados | O que ele exige |
|---|---|
| Entidades, Plano de contas, Clientes, Produtos, Taxas de câmbio, Balancete | Acesso à API (conjunto de permissões D365 READ) |
| Calendário fiscal | O serviço web `AccountingPeriods` |
| Departamentos | O serviço web `DimensionValues` |
| Razão geral | O serviço web `GLEntries` |
| Todos os outros conjuntos de dados | Opcionais, não fazem parte do teste |

Quando falta um conjunto de dados, o teste informa qual permissão ou serviço web adicionar. Peça ao administrador que o adicione e teste novamente.

Os conjuntos de dados opcionais são sites, centros de lucro, fornecedores, o saldo de fim de mês, saldos bancários, saldos de estoque, linhas de vendas, linhas de faturas de fornecedor, itens em aberto, pagamentos, orçamentos e direcionadores de alocação. Um ambiente que não usa um deles ainda carrega todo o restante e, após a próxima carga, as verificações de prontidão, no painel **CFM-Accounting - Close and assurance**, indicam qualquer página que o Business Central recuse. O saldo de fim de mês é o balancete no fim de cada mês; os saldos bancários são esse saldo para as contas nas quais suas contas bancárias lançam. Quando o Business Central recusa uma leitura a partir da qual são montados o saldo de fim de mês, os saldos bancários, o estoque, as linhas de vendas, as linhas de faturas de fornecedor, os itens em aberto ou os pagamentos de um mês, esse mês mantém as linhas que já tinha e é lido novamente na próxima carga.
