O [Data Foundation](/pt-br/guides/projects/data-foundation/) reúne os dados de todos os sistemas e instâncias de ERP que você conecta em um único Common Finance Model, e o Dynamics 365 Finance and Operations é um dos ERPs que ele lê diretamente. A conexão usa um aplicativo do Microsoft Entra ID com um segredo do cliente para os dados mestres e o endpoint SQL do Fabric (Synapse) Link para o diário geral. Esta página é para o administrador do Dynamics 365 que faz essa configuração e para o usuário do PlaidCloud que a solicita a ele.

O PlaidCloud apenas lê dados. Ninguém envia um segredo do cliente ou uma senha SQL por e-mail.

## Enviar a solicitação de acesso

Na guia **Foundation** do projeto, escolha **Criar uma nova conexão** em **Dynamics 365 Finance and Operations connection**. O formulário mostra a solicitação completa. Clique em **Copiar solicitação** para colá-la na sua própria mensagem ou em **Enviar solicitação por e-mail** para abri-la no seu programa de e-mail com o assunto "Read-only Dynamics 365 Finance and Operations access for PlaidCloud."

## O que o administrador do Dynamics 365 configura

<Steps>

1. **Registrar um aplicativo no Microsoft Entra ID** para o PlaidCloud, com um segredo do cliente. Anote o ID do aplicativo (cliente), o ID do diretório (tenant) e o segredo.

2. **Mapear o aplicativo para um usuário.** No Dynamics 365, em **System administration > Setup > Microsoft Entra ID applications**, adicione o ID do cliente e mapeie-o para um usuário com uma função que possa visualizar, para cada entidade legal que você quer carregar:

   - Razão geral: entidades legais, calendários fiscais, contas principais, valores de dimensões financeiras, taxas de câmbio
   - Contas a receber: clientes e linhas de fatura de cliente
   - Gerenciamento de informações do produto: produtos liberados
   - Gerenciamento de estoque: saldos em estoque e transações de estoque (opcional)
   - Orçamento: lançamentos do registro de orçamento (opcional)

3. **Configurar o Fabric Link para o diário geral.** As linhas do diário geral são lidas do endpoint SQL do Fabric (Synapse) Link, não do serviço OData. Confirme que o Fabric Link está ativo para estas tabelas e crie, nesse endpoint, um login SQL somente leitura para o PlaidCloud:

   - `generaljournalaccountentry`
   - `generaljournalentry`
   - `fiscalcalendarperiod`
   - `dimensionattributelevelvalue`, com uma linha para cada valor de dimensão de cada combinação de dimensões financeiras e o nome da respectiva dimensão

</Steps>

## O que devolver

| O administrador envia | Informado no PlaidCloud como |
|---|---|
| O URL do ambiente, `https://<name>.operations.dynamics.com` | **URL do ambiente** |
| O ID do diretório (tenant) | **ID do diretório (tenant)** |
| O ID do aplicativo (cliente) | **ID do aplicativo (cliente)** |
| O endpoint SQL, o banco de dados e o login do Fabric Link | Uma conexão SQL separada no PlaidCloud, escolhida na configuração de sistema `fabric_connection_id` |
| As categorias de conta principal das suas contas de custo das mercadorias vendidas (o PlaidCloud presume `COGS`) | A configuração de sistema `cogs_categories` |
| As categorias de conta principal das contas que não são operacionais: juros, imposto de renda, ganhos e perdas cambiais, outras receitas | A configuração de sistema `non_operating_categories` |
| A dimensão financeira que nomeia o parceiro intercompanhia de uma linha (o PlaidCloud presume `IntercompanyPartner`) | A configuração de sistema `ic_partner_dimension` |
| As entidades legais que o PlaidCloud pode ler | Escolhidas em **Entidades legais** no PlaidCloud |

O segredo do cliente e a senha do login SQL nunca vão por e-mail. A equipe do usuário do PlaidCloud cola o **Segredo do cliente** no PlaidCloud por conta própria, e a conexão SQL guarda o login SQL. As entidades legais que são entidades de consolidação vão na configuração de sistema `consolidation_companies`, para que os lançamentos delas não sejam contados como atividade de uma empresa.

## Verificar o acesso

De volta ao PlaidCloud, informe os valores e clique em **Testar conexão**. Cada conjunto de dados aparece como **Legível**, **Permissão ausente** ou **Erro**:

| Conjunto de dados | Permissão que ele exige |
|---|---|
| Entidades | Razão geral: visualizar entidades legais |
| Calendário fiscal | Razão geral: visualizar calendários fiscais |
| Plano de contas | Razão geral: visualizar contas principais |
| Departamentos | Razão geral: visualizar valores de dimensões financeiras |
| Clientes | Contas a receber: visualizar clientes |
| Produtos | Gerenciamento de informações do produto: visualizar produtos liberados |
| Taxas de câmbio | Razão geral: visualizar taxas de câmbio |
| Balancete, Razão geral | Visualizar o razão geral (o diário, pelo Fabric Link) |
| Linhas de vendas, Saldos de estoque, Orçamento | Opcional |

Quando falta um conjunto de dados, o teste informa a permissão a adicionar. Peça ao administrador que a adicione à função e teste novamente. Linhas de vendas, Saldos de estoque e Orçamento são opcionais: um ambiente que não os contém ainda carrega todo o resto.
