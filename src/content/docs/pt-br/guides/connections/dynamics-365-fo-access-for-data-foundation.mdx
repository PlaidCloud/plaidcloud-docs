O [Data Foundation](/pt-br/guides/projects/data-foundation/) reúne os dados de todos os sistemas e instâncias de ERP que você conecta em um único Common Finance Model, e o Dynamics 365 Finance and Operations é um dos ERPs que ele lê diretamente. A conexão usa um aplicativo do Microsoft Entra ID com um segredo do cliente para os dados mestres e o endpoint SQL do Fabric (Synapse) Link para o diário geral, os subrazões e os saldos bancários. Esta página é para o administrador do Dynamics 365 que faz essa configuração e para o usuário do PlaidCloud que a solicita a ele.

O PlaidCloud apenas lê dados. Ninguém envia um segredo do cliente ou uma senha SQL por e-mail.

## Enviar a solicitação de acesso

Na página **Sistemas** do projeto, em **Data Foundation**, no **Início**, escolha seu sistema em **Sistema**, em **Adicionar um sistema**, e clique em **Ainda não tem acesso?**. O sistema fica aguardando acesso, e é exibida uma única solicitação que abrange os sistemas do projeto. Clique em **Copiar solicitação** para colá-la na sua própria mensagem ou em **Enviar solicitação por e-mail** para abri-la no seu programa de e-mail com o assunto "Acesso ao PlaidCloud."

## O que o administrador do Dynamics 365 configura

<Steps>

1. **Registrar um aplicativo no Microsoft Entra ID** para o PlaidCloud, com um segredo do cliente. Anote o ID do aplicativo (cliente), o ID do diretório (tenant) e o segredo.

2. **Mapear o aplicativo para um usuário.** No Dynamics 365, em **System administration > Setup > Microsoft Entra ID applications**, adicione o ID do cliente e mapeie-o para um usuário com uma função que possa visualizar, para cada entidade legal que você quer carregar:

   - Razão geral: entidades legais, calendários fiscais, contas principais, valores de dimensões financeiras, taxas de câmbio
   - Contas a receber: clientes e linhas de fatura de cliente
   - Contas a pagar: fornecedores (opcional)
   - Gerenciamento de informações do produto: produtos liberados
   - Gerenciamento de estoque: saldos em estoque e transações de estoque (opcional)
   - Orçamento: lançamentos do registro de orçamento (opcional)

3. **Configurar o Fabric Link para o diário geral.** As linhas do diário geral são lidas do endpoint SQL do Fabric (Synapse) Link, não do serviço OData. Confirme que o Fabric Link está ativo para estas tabelas e crie, nesse endpoint, um login SQL somente leitura para o PlaidCloud:

   - `generaljournalaccountentry`
   - `generaljournalentry`
   - `fiscalcalendarperiod`
   - `dimensionattributelevelvalue`, com uma linha para cada valor de dimensão de cada combinação de dimensões financeiras e o nome da respectiva dimensão
   - para itens em aberto e pagamentos (opcional): `custtrans`, `vendtrans`, `custsettlement`, `vendsettlement`
   - para linhas de faturas de fornecedor (opcional): `vendinvoicetrans`, `vendinvoicejour`
   - para saldos bancários (opcional): `bankaccounttrans`, `bankaccounttable`

   Sites e centros de lucro são os valores das dimensões financeiras `Site` e `BusinessUnit`.

</Steps>

## O que devolver

| O administrador envia | Informado no PlaidCloud como |
|---|---|
| O URL do ambiente, `https://<name>.operations.dynamics.com` | **URL do ambiente** |
| O ID do diretório (tenant) | **ID do tenant do Azure AD** |
| O ID do aplicativo (cliente) | **ID do cliente** |
| O `dataAreaId` de uma entidade legal | **Entidade legal / Empresa (dataAreaId)**: a conexão precisa de um, e o Data Foundation lê as entidades legais escolhidas em **Empresas** |
| O endpoint SQL, o banco de dados e o login do Fabric Link | Uma conexão SQL separada no PlaidCloud, cujo ID de conexão vai na configuração de sistema **Fabric Link SQL connection (its connection ID)** |
| As categorias de conta principal das suas contas de custo das mercadorias vendidas (o PlaidCloud presume `COGS`) | A configuração de sistema **Cost of goods sold main account categories** |
| As categorias de conta principal das contas que não são operacionais: juros, imposto de renda, ganhos e perdas cambiais, outras receitas | A configuração de sistema **Non-operating main account categories** |
| A dimensão financeira que nomeia o parceiro intercompanhia de uma linha (o PlaidCloud presume `IntercompanyPartner`) | A configuração de sistema **Intercompany partner dimension** |
| As entidades legais que o PlaidCloud pode ler | Em **Opções**, **Empresas**: marque-as, ou nenhuma para todas elas |

O segredo do cliente e a senha do login SQL nunca vão por e-mail. A equipe do usuário do PlaidCloud cola o **Segredo do cliente** no PlaidCloud por conta própria, e a conexão SQL guarda o login SQL. As entidades legais que são entidades de consolidação vão na configuração de sistema **Consolidation legal entities**, para que os lançamentos delas não sejam contados como atividade de uma empresa.

## Verificar o acesso

De volta ao PlaidCloud, depois de adicionar o sistema, clique em **Testar conexão** na linha dele na página **Sistemas**. Cada conjunto de dados aparece como **Legível**, **Permissão ausente** ou **Erro**:

| Conjunto de dados | Permissão que ele exige |
|---|---|
| Entidades | Razão geral: visualizar entidades legais |
| Calendário fiscal | Razão geral: visualizar calendários fiscais |
| Plano de contas | Razão geral: visualizar contas principais |
| Departamentos | Razão geral: visualizar valores de dimensões financeiras |
| Clientes | Contas a receber: visualizar clientes |
| Produtos | Gerenciamento de informações do produto: visualizar produtos liberados |
| Taxas de câmbio | Razão geral: visualizar taxas de câmbio |
| Balancete, Razão geral | Visualizar o razão geral (o diário, pelo Fabric Link) |
| Todos os outros conjuntos de dados | Opcionais, não fazem parte do teste |

Quando falta um conjunto de dados, o teste informa a permissão a adicionar. Peça ao administrador que a adicione à função e teste novamente.

Os conjuntos de dados opcionais são sites, centros de lucro, fornecedores, linhas de vendas, saldos de estoque, orçamentos, saldos bancários, linhas de faturas de fornecedor, itens em aberto e pagamentos. Um ambiente que não contém um deles ainda carrega todo o resto. Os saldos bancários, as linhas de faturas de fornecedor, os itens em aberto ou os pagamentos de um mês que não puderem ser lidos do Fabric Link mantêm as linhas que já tinham e são lidos novamente na próxima carga.

O Dynamics 365 não tem um objeto de saldo que a conexão possa ler, então nenhum saldo de fim de mês é carregado: o razão é comparado com o próprio balancete.
