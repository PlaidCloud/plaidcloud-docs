O [Data Foundation](/pt-br/guides/projects/data-foundation/) reúne os dados de todos os sistemas ERP e instâncias que você conecta em um único Common Finance Model. O Workday é um dos sistemas que ele lê diretamente. O Workday não tem um serviço web para linhas de lançamento contábil ou saldos, por isso esta página é destinada ao administrador do Workday que cria os relatórios lidos pelo Data Foundation e ao usuário do PlaidCloud que solicita isso a ele.

O PlaidCloud apenas lê dados. Ninguém envia uma senha por e-mail.

## Enviar a solicitação de acesso

Na guia **Foundation** do projeto, escolha **Criar uma nova conexão** e selecione **Workday**. O formulário mostra a especificação dos relatórios. Clique em **Copiar solicitação** para colá-la em sua própria mensagem ou em **Enviar solicitação por e-mail** para abri-la em seu programa de e-mail.

## O que o administrador do Workday configura

<Steps>

1. **Crie dez relatórios personalizados (RaaS)**, quatro deles opcionais, e compartilhe-os com o usuário do sistema de integração. Use exatamente os nomes de coluna indicados: o Data Foundation faz o mapeamento por nome, portanto uma coluna renomeada não pode ser lida. Toda coluna de código contém o Reference ID do objeto, e não um descritor como "C100 Acme US". O formato de saída de todos os relatórios é JSON.

2. **Conceda os serviços web do Financial_Management** `Get_Workday_Companies` e `Get_Currency_Conversion_Rates` ao mesmo usuário.

3. **Envie as URLs dos relatórios** e os dados do usuário do sistema de integração.

</Steps>

| Relatório | Obrigatório | Conteúdo |
|---|---|---|
| Linhas de lançamento | Sim | Uma linha por linha de lançamento contábil registrada. Prompts: Company (a empresa da linha, como um Reference ID) e Period (o Reference ID do período fiscal). Inclui as worktags Region, Fund, Program e Project, a afiliada intercompany, os valores na moeda da transação e na moeda do razão, e o livro |
| Saldos iniciais | Sim | Uma linha por empresa, período fiscal e conta do razão: o saldo no início do período. Somente contas de Ativo, Passivo e Patrimônio líquido são carregadas |
| Contas do razão | Sim | Conta, nome, tipo, indicador intercompany, categoria opcional e conta pai |
| Centros de custo | Sim | Centro de custo, nome e pai |
| Períodos fiscais | Sim | Uma linha por empresa e período fiscal, inclusive períodos de ajuste, com início, fim e status |
| Quadro de funcionários | Opcional | Funcionários ativos no fim de cada período, por centro de custo, com FTE |
| Valores de worktag | Opcional | Uma linha por valor de Region, Fund, Program e Project, com o pai |
| Clientes | Opcional | Cliente, nome, pai, categoria, região e país |
| Itens de venda | Opcional | Item, nome, pai, grupo e unidade de medida |
| Linhas de fatura de venda | Opcional | Uma linha por linha de fatura de cliente, com quantidade e valores bruto, de desconto, líquido e de custo |

A lista completa de colunas de cada relatório está na especificação da guia Foundation. Algumas regras se aplicam ao que os relatórios retornam:

- Somente linhas de lançamento contábil Posted são carregadas, e somente do razão Actuals. Os razões Commitment e Obligation não são carregados.
- Um Book_Code em branco indica o livro principal. Uma linha em branco conta em todos os livros da sua empresa e período, e uma linha com Book_Code pertence somente a esse livro.
- A empresa da linha prevalece sobre a do lançamento.
- Ledger_Account_Type_ID é Revenue, COGS, Opex, NonOperating, Asset, Liability ou Equity. O Workday tem um único tipo Expense, que é carregado como Opex. Para separar o custo dos produtos vendidos ou as despesas não operacionais, imprima um campo calculado que retorne COGS ou NonOperating. Uma conta sem tipo não é carregada na demonstração do resultado.
- Faturas Draft, In Progress, Canceled e Denied não são carregadas.
- Os orçamentos são carregados de arquivos. O Adaptive Planning não está conectado.

## O que enviar de volta

| O administrador envia | Informado no PlaidCloud como |
|---|---|
| O host do Workday | **Host do Workday** |
| O nome do tenant | **Tenant** |
| O nome do usuário do sistema de integração | **Usuário do sistema de integração** |
| A URL de cada relatório obrigatório | **Journal Lines report URL**, **Beginning Balances report URL**, **Ledger Accounts report URL**, **Cost Centers report URL**, **Fiscal Periods report URL** |
| A URL de cada relatório opcional que você criou | **Headcount report URL (optional)**, **Worktag Values report URL (optional)**, **Customers report URL (optional)**, **Sales Items report URL (optional)**, **Sales Invoice Lines report URL (optional)** |
| Os Reference IDs das empresas que o PlaidCloud pode ler | Escolhidas em **Companies**. Deixe em branco para carregar todas as empresas |

O usuário do PlaidCloud cola ele mesmo a **Senha** do usuário do sistema de integração. Ela é um segredo e nunca é enviada por e-mail.

Em **System settings**, **Retained earnings account** indica a conta de Patrimônio líquido para a qual a demonstração do resultado de abertura é transferida, quando os nomes das contas ainda não deixam isso claro. É opcional.

<Aside type="note">
O tipo Expense único do Workday é carregado como Opex, e a verificação de prontidão do Data Foundation sinaliza isso. Se as suas contas de custo dos produtos vendidos ou não operacionais precisarem ser diferenciadas, use o campo calculado descrito acima.
</Aside>

## Verificar o acesso

De volta ao PlaidCloud, clique em **Testar conexão**. Cada conjunto de dados aparece como **Legível**, **Permissão ausente** ou **Erro**:

| Conjunto de dados | Origem |
|---|---|
| Entidades | `Get_Workday_Companies` |
| Plano de contas | O relatório Contas do razão |
| Departamentos | O relatório Centros de custo |
| Calendário fiscal | O relatório Períodos fiscais |
| Taxas de câmbio | `Get_Currency_Conversion_Rates` |
| Balancete | O relatório Saldos iniciais |
| Razão geral | O relatório Linhas de lançamento |
| Direcionadores de alocação (opcional) | O relatório Quadro de funcionários |
| Valores de segmento (opcional) | O relatório Valores de worktag |
| Clientes (opcional) | O relatório Clientes |
| Produtos (opcional) | O relatório Itens de venda |
| Linhas de vendas (opcional) | O relatório Linhas de fatura de venda |

Quando um conjunto de dados mostra **Permissão ausente**, o teste informa o nome do relatório ou do serviço web. Peça ao administrador que o compartilhe com o usuário do sistema de integração e teste novamente. Um tenant sem os relatórios opcionais ainda carrega todo o restante.
