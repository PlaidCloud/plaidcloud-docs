O [Data Foundation](/pt-br/guides/projects/data-foundation/) reúne os dados de todos os sistemas e instâncias de ERP que você conecta em um único Common Finance Model. O Workday é um dos sistemas que ele lê diretamente. O Workday não tem web service para linhas de lançamento nem para saldos, então esta página é para o administrador do Workday que cria os relatórios lidos e para o usuário do PlaidCloud que os solicita a ele.

O PlaidCloud apenas lê dados. Ninguém envia uma senha por e-mail.

## Enviar a solicitação de acesso

Na guia **Foundation** do projeto, escolha **Criar uma nova conexão** e selecione **Workday**. O formulário mostra a especificação dos relatórios. Clique em **Copiar solicitação** para colá-la na sua própria mensagem ou em **Enviar solicitação por e-mail** para abri-la no seu programa de e-mail.

## O que o administrador do Workday configura

<Steps>

1. **Criar dez relatórios personalizados (RaaS)**, quatro deles opcionais, e compartilhá-los com o usuário do sistema de integração. Use os nomes das colunas exatamente como estão: o Data Foundation faz o mapeamento pelo nome, então uma coluna renomeada não pode ser lida. Toda coluna de código é o Reference ID do objeto, não um descritor como "C100 Acme US". O formato de saída de todos os relatórios é JSON.

2. **Conceder os web services do Financial_Management** `Get_Workday_Companies` e `Get_Currency_Conversion_Rates` ao mesmo usuário.

3. **Enviar os URLs dos relatórios** e os dados do usuário do sistema de integração.

</Steps>

| Relatório | Obrigatório | Conteúdo |
|---|---|---|
| Linhas de lançamento | Sim | Uma linha por linha de lançamento contábil registrada. Prompts: Company (a empresa da linha, como Reference ID) e Period (o Reference ID do período fiscal). Inclui os worktags Region, Fund, Program e Project, o afiliado intercompanhia, os valores na moeda da transação e na moeda do razão, e o livro |
| Saldos iniciais | Sim | Uma linha por empresa, período fiscal e conta do razão: o saldo no início do período. Somente as contas de ativo, passivo e patrimônio líquido são carregadas |
| Contas do razão | Sim | Conta, nome, tipo, indicador intercompanhia, categoria opcional e conta pai |
| Centros de custo | Sim | Centro de custo, nome e pai |
| Períodos fiscais | Sim | Uma linha por empresa e período fiscal, inclusive os períodos de ajuste, com início, fim e status |
| Quadro de funcionários | Opcional | Trabalhadores ativos no fim de cada período, por centro de custo, com FTE |
| Valores de worktag | Opcional | Uma linha por valor de Region, Fund, Program e Project, com o pai |
| Clientes | Opcional | Cliente, nome, pai, categoria, região e país |
| Itens de venda | Opcional | Item, nome, pai, grupo e unidade de medida |
| Linhas de fatura de venda | Opcional | Uma linha por linha de fatura de cliente, com quantidade e valores bruto, de desconto, líquido e de custo |

A lista completa de colunas de cada relatório está na especificação da guia Foundation. Algumas regras se aplicam ao que os relatórios retornam:

- Somente as linhas de lançamento Posted são carregadas, e somente o razão Actuals. Os razões Commitment e Obligation não são.
- Um Book_Code em branco é o livro primário. Uma linha em branco conta em todos os livros da empresa e do período dela, e uma linha com um Book_Code pertence somente a esse livro.
- A empresa da linha prevalece sobre a do lançamento.
- Ledger_Account_Type_ID é Revenue, COGS, Opex, NonOperating, Asset, Liability ou Equity. O Workday tem um único tipo Expense, que é carregado como Opex. Para separar o custo das mercadorias vendidas ou a despesa não operacional, imprima um campo calculado que retorne COGS ou NonOperating. Uma conta sem tipo não é carregada na demonstração do resultado.
- As faturas nos status Draft, In Progress, Canceled e Denied não são carregadas.
- Os orçamentos são carregados de arquivos. O Adaptive Planning não está conectado.

## O que devolver

| O administrador envia | Informado no PlaidCloud como |
|---|---|
| O host do Workday | **Host do Workday** |
| O nome do tenant | **Tenant** |
| O nome do usuário do sistema de integração | **Usuário do sistema de integração** |
| O URL de cada relatório obrigatório | **URL do relatório de linhas de lançamento**, **URL do relatório de saldos iniciais**, **URL do relatório de contas do razão**, **URL do relatório de centros de custo**, **URL do relatório de períodos fiscais** |
| O URL de cada relatório opcional que você criou | **URL do relatório de quadro de funcionários (opcional)**, **URL do relatório de valores de worktag (opcional)**, **URL do relatório de clientes (opcional)**, **URL do relatório de itens de venda (opcional)**, **URL do relatório de linhas de fatura de venda (opcional)** |
| Os Reference IDs das empresas que o PlaidCloud pode ler | Escolhidos em **Empresas**. Deixe em branco para carregar todas as empresas |

O usuário do PlaidCloud cola por conta própria a **Senha** do usuário do sistema de integração; ela é um segredo e nunca é enviada por e-mail.

Em **Configurações do sistema**, **Conta de lucros acumulados** indica a conta de Patrimônio líquido para a qual a demonstração do resultado de abertura é transferida, quando os nomes das contas ainda não deixam isso claro. É opcional.

<Aside type="note">
O tipo Expense único do Workday é carregado como Opex, e a verificação de prontidão do Data Foundation o sinaliza. Se as suas contas de custo das mercadorias vendidas ou não operacionais precisam ser distinguidas, use o campo calculado descrito acima.
</Aside>

## Verificar o acesso

De volta ao PlaidCloud, clique em **Testar conexão**. Cada conjunto de dados aparece como **Legível**, **Permissão ausente** ou **Erro**:

| Conjunto de dados | Vem de |
|---|---|
| Entidades | `Get_Workday_Companies` |
| Plano de contas | O relatório de contas do razão |
| Departamentos | O relatório de centros de custo |
| Calendário fiscal | O relatório de períodos fiscais |
| Taxas de câmbio | `Get_Currency_Conversion_Rates` |
| Balancete | O relatório de saldos iniciais |
| Razão geral | O relatório de linhas de lançamento |
| Direcionadores de alocação (opcional) | O relatório de quadro de funcionários |
| Valores de segmento (opcional) | O relatório de valores de worktag |
| Clientes (opcional) | O relatório de clientes |
| Produtos (opcional) | O relatório de itens de venda |
| Linhas de vendas (opcional) | O relatório de linhas de fatura de venda |

Quando um conjunto de dados mostra **Permissão ausente**, o teste informa o relatório ou web service. Peça ao administrador que o compartilhe com o usuário do sistema de integração e teste novamente. Um tenant sem os relatórios opcionais ainda carrega todo o resto.
