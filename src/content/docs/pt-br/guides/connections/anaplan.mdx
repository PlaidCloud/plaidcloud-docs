Conecte o PlaidCloud ao **Anaplan** para que um fluxo de trabalho possa ler uma visão salva pelo caminho de solicitação de leitura de grande volume do Anaplan, executar uma ação de exportação já existente ou ler uma ou mais listas do Anaplan em uma dimensão do PlaidCloud. A conexão acessa a própria Integration API do Anaplan **direto na nuvem** — essas etapas não têm caminho por agente local. Este guia aborda a conexão, a autenticação, uma breve introdução a cada uma das três etapas de leitura e as considerações sobre agendamento.

<Aside type="note">
Este conector é somente leitura. Nada é gravado de volta no Anaplan — não há etapa de gravação de retorno nem modo de aplicação parcial.
</Aside>

## Pré-requisitos

Você precisa destes itens, fornecidos pelo administrador do espaço de trabalho do Anaplan:

- Um **nome de usuário e uma senha** do Anaplan, ou um **certificado de CA e a respectiva chave privada** registrados em um usuário do Anaplan pelo administrador do espaço de trabalho — com acesso de leitura ao espaço de trabalho e aos modelos que seus fluxos de trabalho vão ler. Consulte [Autenticação](#autenticação) abaixo.
- O **ID do espaço de trabalho** e o **ID do modelo** dos modelos de onde você vai ler, visíveis nas configurações do modelo no próprio Anaplan. Ambos também podem ser descobertos em tempo real pela conexão depois que ela é criada.
- Para **Anaplan: Ler visão** — uma **visão salva**, criada exatamente com o recorte de linhas, colunas e filtros que você quer. Consulte [Anaplan: Ler visão](#anaplan-ler-visão) abaixo.
- Para **Anaplan: Ler exportação** — uma **ação de exportação que já exista** no modelo.
- Para **Anaplan: Ler lista** — as **listas** do Anaplan que compõem a hierarquia que você quer ler.

## Autenticação

A conexão tem um **Modo de autenticação**: **Básica** (o padrão) ou **Certificado**. Uma conexão existente continua funcionando sem alterações como Básica.

- **Básica** entra com um nome de usuário e uma senha do Anaplan.
- **Certificado** entra com um certificado emitido por uma CA e a respectiva chave privada, ambos colados como texto PEM. A chave privada deve ser **RSA e não criptografada**, e o certificado deve ser aquele que o administrador do espaço de trabalho do Anaplan registrou no seu usuário do Anaplan — emitido por uma CA em que o Anaplan confie para o seu tenant. O PlaidCloud assina um desafio aleatório com a chave e o troca por um token do Anaplan, seguindo o próprio fluxo de autenticação por certificado do Anaplan; não há mais nada a fazer depois que o certificado e a chave são colados, e a renovação do token funciona como no modo Básica. Os dois campos mascaram o que você cola, e ambos os segredos são armazenados criptografados, como uma senha do modo Básica. Alternar entre os modos nunca envia as credenciais do outro modo — se você mudar uma conexão existente de Básica para Certificado, precisará colar o certificado e a chave, pois eles não são transferidos.

A autenticação multifator do Anaplan se aplica a usuários que entram com e-mail e senha. A autenticação por certificado é a opção sem senha para uma conexão automatizada e agendada.

O modo Certificado recusa a operação antes de contatar o Anaplan se a chave ou o certificado colado não puder ser lido, se a chave estiver criptografada ou não for RSA, ou se a chave não corresponder ao certificado. Se o próprio Anaplan rejeitar o certificado, o erro informa se ele expirou; as causas mais comuns são um certificado que não está registrado em um usuário do Anaplan ou uma CA em que o seu tenant não confia.

## Criar a conexão

<Steps>

1. Abra **Tools > Connections** e clique em `New Connection`.

2. Escolha **Anaplan** no menu.

3. Preencha os campos:

   | Campo | Valor |
   |---|---|
   | Nome | Um nome amigável, por exemplo `Anaplan Prod`. |
   | Host da API | Opcional. Deixe em branco para usar o padrão do Anaplan, `https://api.anaplan.com`. |
   | Host de autenticação | Opcional. Deixe em branco para usar o padrão do Anaplan, `https://auth.anaplan.com`. |
   | Modo de autenticação | **Básica** (padrão) ou **Certificado**. Consulte [Autenticação](#autenticação) acima. |
   | Nome de usuário | O nome de usuário da conta do Anaplan. Somente no modo Básica. |
   | Senha | A senha da conta do Anaplan. Somente no modo Básica. |
   | Certificado de CA | Texto PEM do certificado X.509 registrado no Anaplan. Somente no modo Certificado. |
   | Chave privada | Texto PEM da chave privada RSA do certificado, sem criptografia. Somente no modo Certificado. |
   | ID do espaço de trabalho padrão | Opcional. Um preenchimento prévio de conveniência para o campo Workspace de uma etapa de leitura. |
   | ID do modelo padrão | Opcional. Um preenchimento prévio de conveniência para o campo Model de uma etapa de leitura. |
   | Tempo limite (segundos) | O padrão é 30. |

4. Clique em `Test Connection`. Um teste bem-sucedido informa o e-mail da conta do Anaplan à qual as credenciais correspondem.

5. Clique em `Create`.

</Steps>

## Anaplan: Ler visão

Adicione uma etapa **Anaplan: Ler visão** para ler uma visão salva pelo caminho de solicitação de leitura de grande volume do Anaplan. **A visão é lida exatamente como foi salva no Anaplan — esta etapa não tem seleção de linhas, colunas ou páginas.** Para ler um recorte diferente, crie outra visão salva no Anaplan; um item de linha booleano combinado com uma visão salva é a forma usual de filtrar ali. Uma coluna de dados chega com o tipo declarado no Anaplan somente quando a visão coloca os **itens de linha no eixo das colunas**; com os itens de linha nas linhas (um layout comum de DRE) ou ausentes da visão, todas as colunas chegam como texto, e a etapa avisa isso. Uma visão cujo filtro não corresponde a nada gera uma tabela vazia com um aviso. Um valor numérico que a etapa não consegue ler sem ambiguidade — na maioria das vezes um que pode ser igualmente um decimal simples ou uma representação no estilo europeu — é recusado em vez de adivinhado, a menos que outro valor da mesma coluna esclareça qual leitura é a correta; um valor que é interpretado com sucesso chega com a precisão total, sem erro de arredondamento. Consulte [Anaplan: Ler visão](/pt-br/reference/workflow-steps/anaplan/anaplan-read-view/) para a referência completa de campos e comportamento.

## Anaplan: Ler exportação

Adicione uma etapa **Anaplan: Ler exportação** para executar uma ação de exportação **já existente** do Anaplan e carregar o arquivo que ela produz. A API não consegue criar uma ação de exportação — crie ou edite-a antes no Anaplan — e a etapa não consegue restringir o que ela emite: o que a ação estiver configurada para exportar no Anaplan é exatamente o que chega. **Todas as colunas chegam como texto.** Os números são solicitados com a formatação dos EUA; uma coluna que ainda assim volta com separadores de milhares chega sem alterações, como texto, com um aviso nomeado, em vez de fazer a execução falhar. A etapa para, sem carregar uma tabela, quando a exportação falha, é cancelada, não produz dados, ainda está em execução quando o orçamento de consultas da etapa se esgota, ou produz um arquivo que não pode ser associado à exportação ou cuja contagem de linhas diverge da que o próprio Anaplan informa. Consulte [Anaplan: Ler exportação](/pt-br/reference/workflow-steps/anaplan/anaplan-read-export/) para a referência completa.

## Anaplan: Ler lista

Adicione uma etapa **Anaplan: Ler lista** para ler uma ou mais listas do Anaplan em uma dimensão do PlaidCloud. **Uma etapa lê uma hierarquia composta inteira** — nomeie todas as listas que ela abrange, começando pela raiz (por exemplo, Região, depois País, depois Loja), em vez de dividi-la entre várias etapas; a tabela de preparação é substituída a cada execução, de modo que várias etapas apontadas para a mesma tabela de preparação apagariam, cada uma, as linhas da anterior. Toda aresta é consolidada com um simples `+`, pois as hierarquias de listas do Anaplan não têm peso nem sinal por aresta para serem lidos. Os controles de acesso às listas e a participação em subconjuntos do Anaplan não são importados — são metadados, não dados de dimensão. IDs de nó duplicados, uma referência de pai que não pode ser resolvida, referências de pai conflitantes e um nome de propriedade que colide com os metadados importados são recusados antes que qualquer coisa seja carregada. Consulte [Anaplan: Ler lista](/pt-br/reference/workflow-steps/anaplan/anaplan-read-list/) para a referência completa.

## Anaplan como origem do Data Foundation

O [Data Foundation](/pt-br/guides/projects/data-foundation/) pode ler no Common Finance Model o plano que o Anaplan mantém: um orçamento, uma previsão ou os resultados de um modelo de consolidação. Ele traz o plano, nunca o razão, e apenas lê.

O Data Foundation executa uma ação de exportação do modelo como ele está salvo, então o administrador do Anaplan precisa criar essa exportação antes. A guia **Foundation** redige a solicitação para ele. A exportação deve ser uma grade plana com uma linha para cada entidade, período, conta e departamento, e com estes cabeçalhos de coluna exatamente:

| Coluna | Contém |
|---|---|
| `Entity` | O código da entidade. |
| `Period` | O mês, no formato `YYYY-MM`. |
| `Account` | O código da conta. |
| `Department` | O código do departamento, em branco quando o plano não tem um. |
| `Currency` | A moeda do valor. |
| `Amount` | Um número simples, sem separador de milhares, no sinal em que o plano é mantido (receita positiva). |

Em seguida, adicione a conexão como origem na guia **Foundation**, como em qualquer outra (consulte [Conecte seu ERP](/pt-br/guides/projects/data-foundation/#conectar-seu-erp)). Uma nova conexão pede o **Nome de usuário**, a **Senha**, o **ID do espaço de trabalho** e o **ID do modelo**. O Anaplan não lista entidades para marcar, então o formulário pede uma: informe em **Nome** a entidade da exportação a manter ou deixe em branco para manter todas as entidades. Depois preencha as **Configurações do sistema**, que aparecem com estes nomes:

| Configuração | O que significa |
|---|---|
| `export` | O ID da ação de exportação a executar. |
| `scenario` | `Budget` (o padrão), `Forecast` ou `Consolidated`, para os resultados de um modelo de consolidação com os quais a demonstração do resultado (DRE) do grupo é conciliada. |
| `version` | Um rótulo aplicado a todas as linhas. O padrão é `Anaplan`. |

Os valores são lidos como estão, no sinal natural. Uma coluna que volta ainda agrupada com separadores de milhares é sinalizada, não adivinhada, como em [Anaplan: Ler exportação](/pt-br/reference/workflow-steps/anaplan/anaplan-read-export/).

## Considerações sobre agendamento

O orçamento de taxa de solicitações do Anaplan é **compartilhado em todo o tenant** — entre todas as integrações que a sua organização executa contra esse tenant do Anaplan, não apenas as do PlaidCloud — e o PlaidCloud não coordena os agendamentos entre execuções simultâneas. Várias etapas do Anaplan que caem no mesmo minuto do cron podem esgotar esse orçamento antes que qualquer uma delas termine. **Escalone os agendamentos dos seus fluxos de trabalho do Anaplan** em vez de executá-los todos ao mesmo tempo.
