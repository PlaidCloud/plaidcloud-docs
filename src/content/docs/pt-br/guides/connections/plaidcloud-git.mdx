Uma **conexão PlaidCloud Git** aponta um fluxo de trabalho, ou a compilação de um aplicativo Panel de servidor, para um repositório no servidor Git gerenciado do seu espaço de trabalho. Como esse servidor Git é hospedado para você em `git.<your-workspace>.plaid.cloud` e você já está autenticado pelo login normal do PlaidCloud, o formulário da conexão é bem mais simples que o de um provedor Git externo: não há URL de servidor para informar nem nome de usuário, token ou chave SSH para gerenciar.

<Aside type="note">Você nunca informa uma URL de servidor nem credenciais em uma conexão PlaidCloud Git. O servidor Git do seu espaço de trabalho e o seu acesso a ele são tratados automaticamente a partir do seu login no PlaidCloud (inclusive SSO), portanto não há tokens para gerar, armazenar ou girar.</Aside>

## Quando usar

Use uma conexão PlaidCloud Git sempre que o repositório de onde você quer ler estiver no [PlaidCloud Git](/pt-br/guides/git/), o serviço Git integrado do seu espaço de trabalho, e não em um host externo. O uso mais comum é automatizar as compilações de aplicativos **Panel de servidor** ou **Dash** a partir de um repositório gerenciado, de modo que um push em um branch recompile e reimplante o aplicativo sem depender de uma conta externa do GitHub nem de um token de acesso pessoal.

Para um repositório hospedado em um serviço externo (GitHub, GitLab, Bitbucket, Forgejo ou Gitea), use uma [conexão Git externa](/pt-br/reference/connectors/git/). Essas conexões mantêm o formulário completo, com **URL do servidor**, autenticação por usuário/token ou SSO e as guias **SSL** e **SSH**.

## Criar uma conexão PlaidCloud Git

1. Abra **Tools > Connections**
2. Clique em `New Connection` e escolha **PlaidCloud Git** no menu
3. Preencha o formulário simplificado:
   - **Nome da conta**: um nome de exibição para a conexão
   - **Memorando**: uma observação opcional sobre a finalidade da conexão
   - **Repositório**: clique em `Refresh` para listar os repositórios que o seu espaço de trabalho consegue acessar e escolha um (por exemplo, o repositório `udfs` ou `apps`). Você escolhe na lista em vez de digitar o caminho.
   - **Branch padrão**: escolha o branch de leitura padrão na lista de branches do repositório selecionado
   - **Caminho inicial**: opcionalmente, navegue pelo repositório e escolha uma pasta para limitar todas as buscas de arquivos a uma subpasta; deixe em branco para usar o repositório inteiro
4. Defina **Uso**: `Active` para habilitar a conexão e `Read Only` se a conexão nunca deve gravar
5. Defina o **Modelo de segurança**: quem no espaço de trabalho pode usar a conexão
6. Clique em `Create` para salvar

Esse é o formulário inteiro. Diferente de um provedor Git externo, não há URL do servidor, guia de autenticação nem configuração de SSL ou SSH: tudo isso é tratado para você.

<Aside type="note">O repositório, o branch padrão e o caminho inicial são escolhidos em listas dinâmicas (escolha primeiro um repositório, depois o branch e, por fim, navegue até uma pasta), então não há nada para digitar errado. Cada lista é lida com o acesso da própria conexão, portanto, em uma conexão PlaidCloud Git, elas são preenchidas imediatamente, sem credenciais para informar.</Aside>

## Modelo de segurança

O `Security Model` controla quem no espaço de trabalho pode usar a conexão:

| Opção | Quem pode usar a conexão |
|---|---|
| Privado (somente proprietários) | Somente os proprietários. |
| Somente membros específicos | Os proprietários e uma lista explícita de membros. |
| Somente grupos de segurança específicos | Os proprietários e os membros de grupos de segurança indicados. |
| Todos os membros do espaço de trabalho | Todos no espaço de trabalho. |

Para `Specific Members Only` ou `Specific Security Groups Only`, conceda o acesso pelo menu `Actions` da lista depois de salvar. Consulte [Criar e gerenciar uma conexão](/pt-br/guides/connections/create-connection/#modelo-de-segurança) para ver os mecanismos de conexão compartilhados.

## Quem pode ver os repositórios

Todo repositório que o PlaidCloud cria para você pode ser lido por todos os membros do seu espaço de trabalho que estiverem autenticados. Isso inclui os repositórios por trás dos seus aplicativos Panel e Dash e os repositórios integrados `apps` e `udfs`. Ninguém que não esteja autenticado pode lê-los.

Por isso, os membros podem abrir e republicar aplicativos e escolher um repositório para uma conexão PlaidCloud Git sem nenhuma configuração por repositório.

### Avançado: repositórios privados

Um administrador do Git pode tornar um repositório privado na interface do Git. Um repositório privado deixa de ser visível para todos os membros, portanto:

- Ele não aparece na lista **Repositório** das conexões PlaidCloud Git.
- O código de UDF baseado em Git não pode ser lido dele, então uma UDF baseada em Git armazenada em um repositório privado não será executada.
- Os membros não podem publicar um aplicativo a partir dele.

Para usar um repositório privado como origem, crie uma [conexão Git externa](/pt-br/reference/connectors/git/) com o próprio token de acesso.

## Automatizar compilações de aplicativos Panel e Dash a partir do Git gerenciado

Um [aplicativo Panel de servidor](/pt-br/guides/panel-apps/creating/) ou um [aplicativo Dash](/pt-br/guides/dash-apps/) é compilado a partir de um branch do Git e recompilado automaticamente a cada push nesse branch. Apontá-lo para uma conexão PlaidCloud Git mantém todo o ciclo dentro do seu espaço de trabalho, sem host externo e sem token de acesso pessoal para manter ativo.

1. Envie seu aplicativo por push para um repositório no servidor PlaidCloud Git do seu espaço de trabalho: um arquivo `.py` de ponto de entrada (no Panel, ele chama `.servable()`; no Dash, expõe `server = app.server`) e um `requirements.txt` opcional na raiz do repositório ou ao lado do ponto de entrada. Consulte [Criar um aplicativo Panel](/pt-br/guides/panel-apps/creating/#prepare-o-repositório-do-aplicativo) ou [Implantar um aplicativo Dash a partir do PlaidCloud Git](/pt-br/guides/dash-apps/deploy-from-git/) para ver a estrutura do repositório.
2. Crie uma conexão PlaidCloud Git cujo **Repositório** seja esse repositório, seguindo as etapas acima.
3. Em **Aplicativos**, escolha **Novo app** > **Baseado em servidor** ou **App Dash** e, em **Conexão Git e monitor de publicação**:
   - **Conexão Git**: escolha a conexão PlaidCloud Git que você acabou de criar
   - **Branch**: o branch de onde compilar; os pushes nele recompilam e reimplantam o aplicativo
   - **Ponto de entrada**: o arquivo `.py` que o aplicativo deve servir
4. Conclua a caixa de diálogo de publicação e clique em **Publicar**.

A partir daí, cada push nesse branch do seu servidor Git gerenciado recompila o aplicativo, em uma compilação automatizada de ponta a ponta que nunca sai do PlaidCloud.
