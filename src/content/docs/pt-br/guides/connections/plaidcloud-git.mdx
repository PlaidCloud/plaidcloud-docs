Uma **conexão PlaidCloud Git** aponta um fluxo de trabalho — ou a compilação de um aplicativo Panel de servidor — para um repositório no servidor Git gerenciado do seu próprio espaço de trabalho. Como esse servidor Git é hospedado para você em `git.<your-workspace>.plaid.cloud` e você já está conectado pelo seu login normal do PlaidCloud, o formulário da conexão é bem mais simples que o de um provedor Git externo: não há URL de servidor para informar nem nome de usuário, token ou chave SSH para gerenciar.

<Aside type="note">Você nunca informa uma URL de servidor nem credenciais em uma conexão PlaidCloud Git. O servidor Git do seu espaço de trabalho e o seu acesso a ele são tratados automaticamente a partir do seu login no PlaidCloud (incluindo SSO) — portanto não há tokens para gerar, armazenar ou rotacionar.</Aside>

## Quando usar

Use uma conexão PlaidCloud Git sempre que o repositório que você quer ler estiver no [PlaidCloud Git](/pt-br/guides/git/) — o serviço Git integrado do seu espaço de trabalho — e não em um host externo. O uso mais comum é automatizar as compilações de **aplicativos Panel de servidor** ou **aplicativos Dash** a partir de um repositório gerenciado, de modo que um push em um branch recompile e reimplante o aplicativo sem uma conta externa do GitHub nem um token de acesso pessoal no processo.

Para um repositório hospedado em um serviço externo — GitHub, GitLab, Bitbucket, Forgejo ou Gitea —, use, em vez disso, uma [conexão Git externa](/pt-br/reference/connectors/git/). Essas conexões mantêm o formulário completo, com uma **URL do servidor**, autenticação por usuário/token ou SSO e as guias **SSL** e **SSH**.

## Criar uma conexão PlaidCloud Git

1. Abra **Tools > Connections**
2. Clique em `New Connection` e escolha **PlaidCloud Git** no menu
3. Preencha o formulário simplificado:
   - **Nome da conta** — um nome de exibição para a conexão
   - **Memorando** — uma observação opcional sobre a finalidade da conexão
   - **Repositório** — clique em `Refresh` para listar os repositórios que o seu espaço de trabalho consegue alcançar e escolha um (por exemplo, o seu repositório `udfs` ou `apps`). Você escolhe na lista em vez de digitar o caminho.
   - **Branch padrão** — escolha o branch a ser lido por padrão na lista de branches do repositório selecionado
   - **Caminho inicial** — opcionalmente, navegue pelo repositório e escolha uma pasta para limitar toda busca de arquivos a uma subpasta; deixe sem definir para usar o repositório inteiro
4. Defina **Uso** — `Active` para ativar a conexão e `Read Only` se a conexão nunca deve gravar
5. Defina o **Modelo de segurança** — quem no espaço de trabalho pode usar a conexão
6. Clique em `Create` para salvar

Esse é o formulário inteiro. Diferentemente de um provedor Git externo, não há URL do servidor, guia de autenticação nem configuração de SSL ou SSH — tudo isso é tratado para você.

<Aside type="note">O repositório, o branch padrão e o caminho inicial são escolhidos em listas em tempo real — escolha primeiro um repositório, depois o branch e, por fim, navegue até uma pasta —, portanto não há nada para digitar errado. Cada lista é lida com o acesso da própria conexão, de modo que, em uma conexão PlaidCloud Git, elas são preenchidas imediatamente, sem credenciais para informar.</Aside>

## Modelo de segurança

O `Security Model` controla quem no espaço de trabalho pode usar a conexão:

| Opção | Quem pode usar a conexão |
|---|---|
| Privado (somente proprietários) | Apenas os proprietários. |
| Somente membros específicos | Os proprietários e uma lista explícita de membros. |
| Somente grupos de segurança específicos | Os proprietários e os membros de grupos de segurança nomeados. |
| Todos os membros do espaço de trabalho | Todos os usuários do espaço de trabalho. |

Para `Specific Members Only` ou `Specific Security Groups Only`, conceda o acesso pelo menu `Actions` da lista depois de salvar. Consulte [Criar e gerenciar uma conexão](/pt-br/guides/connections/create-connection/#modelo-de-segurança) para a mecânica compartilhada das conexões.

## Automatizar compilações de aplicativos Panel e Dash a partir do Git gerenciado

Um [aplicativo Panel de servidor](/pt-br/guides/panel-apps/creating/) ou um [aplicativo Dash](/pt-br/guides/dash-apps/) é compilado a partir de um branch do Git e recompilado automaticamente a cada push nesse branch. Apontá-lo para uma conexão PlaidCloud Git mantém todo o ciclo dentro do seu espaço de trabalho — sem host externo e sem um token de acesso pessoal para manter ativo.

1. Envie seu aplicativo para um repositório no servidor PlaidCloud Git do seu espaço de trabalho — um arquivo `.py` de ponto de entrada (o do Panel chama `.servable()`; o do Dash expõe `server = app.server`) e um `requirements.txt` opcional na raiz do repositório ou ao lado do ponto de entrada. Consulte [Criar um aplicativo Panel](/pt-br/guides/panel-apps/creating/#prepare-o-repositório-do-seu-aplicativo) ou [Implantar um aplicativo Dash a partir do PlaidCloud Git](/pt-br/guides/dash-apps/deploy-from-git/) para o layout do repositório.
2. Crie uma conexão PlaidCloud Git cujo **Repositório** seja esse repositório, seguindo as etapas acima.
3. Em **Meus aplicativos Panel**, clique em **Novo aplicativo de servidor** ou **Novo aplicativo Dash** e, em **Conexão Git e monitor de publicação**:
   - **Conexão Git** — escolha a conexão PlaidCloud Git que você acabou de criar
   - **Branch** — o branch a partir do qual compilar; os pushes nele recompilam e reimplantam o aplicativo
   - **Ponto de entrada** — o arquivo `.py` que o aplicativo deve servir
4. Conclua a caixa de diálogo de publicação e clique em **Publicar**.

A partir daí, cada push nesse branch no seu servidor Git gerenciado recompila o aplicativo — uma compilação automatizada de ponta a ponta que nunca sai do PlaidCloud.
