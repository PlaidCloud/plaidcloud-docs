O [Data Foundation](/pt-br/guides/projects/data-foundation/) reúne os dados de todos os sistemas e instâncias de ERP que você conecta em um único Common Finance Model, e o SAP S/4HANA Cloud é um dos ERPs que ele lê diretamente. A conexão lê os serviços OData liberados do tenant com credenciais de cliente OAuth 2.0; nenhum agente está envolvido. Esta página é para o administrador do S/4HANA Cloud que faz essa configuração e para o usuário do PlaidCloud que a solicita a ele.

O PlaidCloud apenas lê dados. Ninguém envia uma senha ou um segredo do cliente por e-mail.

## Enviar a solicitação de acesso

Na página **Sistemas** do projeto, em **Data Foundation**, no **Início**, escolha seu sistema em **Sistema**, em **Adicionar um sistema**, e clique em **Ainda não tem acesso?**. O sistema fica aguardando acesso, e é exibida uma única solicitação que abrange os sistemas do projeto. Clique em **Copiar solicitação** para colá-la na sua própria mensagem ou em **Enviar solicitação por e-mail** para abri-la no seu programa de e-mail com o assunto "Acesso ao PlaidCloud."

## O que o administrador do S/4HANA Cloud configura

<Steps>

1. **Criar um usuário de comunicação** para o PlaidCloud, no aplicativo **Maintain Communication Users**. O método de autenticação dele é OAuth 2.0 ou nome de usuário e senha, conforme o seu ambiente exigir.

2. **Criar um sistema de comunicação** para o PlaidCloud, no aplicativo **Communication Systems**, com esse usuário para comunicação de entrada e com credenciais de cliente OAuth 2.0.

3. **Criar um acordo de comunicação** para cada cenário abaixo, no aplicativo **Communication Arrangements**, todos para o sistema da etapa 2. Juntos, eles expõem os serviços OData que o PlaidCloud lê:

   | Cenário | Serviço |
   |---|---|
   | Código da empresa | `API_COMPANYCODE_SRV` |
   | Conta do razão no plano de contas | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
   | Centro de custo | `API_COSTCENTER_SRV` |
   | Parceiro de negócios e cliente | `API_BUSINESS_PARTNER` |
   | Produto | `API_PRODUCT_SRV` |
   | Períodos da variante de ano fiscal | `API_FISCALYEARPERIODFORVARIANT_SRV` |
   | Taxas de câmbio | `API_EXCHANGERATE_SRV` |
   | Item de lançamento contábil | `API_JOURNALENTRYITEMBASIC_SRV` (o diário e o saldo transportado) |
   | Documento de faturamento | `API_BILLING_DOCUMENT_SRV` (opcional: acrescenta vendas faturadas, documentos e itens) |

   Para os conjuntos de dados opcionais, crie também os acordos para os cenários que expõem estes serviços:

   | Serviço | Acrescenta |
   |---|---|
   | `API_JOURNALENTRY_SRV` | Quem inseriu cada lançamento, quando, e o lançamento que ele estorna |
   | `API_BUSINESS_PARTNER` (`A_Supplier`) | Fornecedores |
   | `API_PLANT_SRV` | Centros, lidos como sites, e os centros dos saldos de estoque |
   | `API_PROFITCENTER_SRV` | Centros de lucro |
   | `API_SUPPLIERINVOICE_PROCESS_SRV` | Linhas de faturas de fornecedor |
   | `API_OPLACCTGDOCITEMCUBE_SRV` | Itens em aberto e pagamentos, e as datas de vencimento das faturas de fornecedor |
   | `API_FINPLANNINGDATA_SRV` | Orçamentos |
   | `API_MATERIAL_STOCK_SRV` | Saldos de estoque |

   Dê ao usuário de comunicação acesso a todos os códigos de empresa sobre os quais você gera relatórios.

</Steps>

## O que devolver

| O administrador envia | Informado no PlaidCloud como |
|---|---|
| O host da API do tenant, por exemplo `https://my300000-api.s4hana.cloud.sap` | **URL do host da API** |
| O URL do token: o do próprio tenant (`/sap/bc/sec/oauth2/token`) ou o do seu servidor de autorização XSUAA, se o seu ambiente usar um | **URL do token OAuth2** |
| O ID do cliente | **ID do cliente** |
| O segredo do cliente, pelo formulário de conexão seguro | **Segredo do cliente**, que a sua equipe informa por conta própria |
| Se o **Carry Forward Balances** foi executado para cada ano fiscal que você carrega | Nada a informar. Os saldos de abertura são lidos dele. |

<Aside type="caution">
Nunca envie o segredo do cliente por e-mail. O **Segredo do cliente** é um segredo: ele é armazenado na conexão e nunca mais exibido.
</Aside>

## Verificar o acesso

De volta ao PlaidCloud, depois de adicionar o sistema, clique em **Testar conexão** na linha dele na página **Sistemas**. Ele lê os conjuntos de dados obrigatórios e mostra cada um como **Legível**, **Permissão ausente** ou **Erro**. Os opcionais não fazem parte do teste: se o S/4HANA Cloud recusar algum, após a próxima carga as verificações de prontidão, no painel **CFM-Accounting - Close and assurance**, indicam o serviço a adicionar ao acordo de comunicação.

| Conjunto de dados | Serviço que ele exige |
|---|---|
| Entidades | `API_COMPANYCODE_SRV` |
| Plano de contas | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
| Departamentos | `API_COSTCENTER_SRV` |
| Clientes | `API_BUSINESS_PARTNER` |
| Produtos | `API_PRODUCT_SRV` |
| Taxas de câmbio | `API_EXCHANGERATE_SRV` |
| Calendário fiscal | `API_FISCALYEARPERIODFORVARIANT_SRV` |
| Razão geral | `API_JOURNALENTRYITEMBASIC_SRV` |
| Balancete | `API_JOURNALENTRYITEMBASIC_SRV` |
| Linhas de vendas | `API_BILLING_DOCUMENT_SRV` (opcional) |

Quando um conjunto de dados mostra **Permissão ausente**, peça ao administrador que adicione o acordo de comunicação do serviço correspondente e teste novamente. Linhas de vendas, orçamento, saldos de estoque, fornecedores, sites, centros de lucro, linhas de faturas de fornecedor, itens em aberto e pagamentos são opcionais: um tenant que não contém algum deles ainda carrega todo o resto. Os itens em aberto ou os pagamentos de um mês que não puderem ser lidos, e as linhas de faturas de fornecedor de um mês cuja leitura falhar, mantêm as linhas que já tinham e são lidos novamente na próxima carga.

Os serviços não informam status de período nem saldo de fim de mês próprios, então todos os períodos ficam abertos e o razão é comparado com o próprio balancete.
