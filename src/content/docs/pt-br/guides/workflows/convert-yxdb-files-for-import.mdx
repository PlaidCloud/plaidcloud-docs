O Alteryx grava arquivos `.yxdb` em dois formatos. O formato clássico (gravado pelo mecanismo original) é bem conhecido, e o PlaidCloud o importa diretamente. O mecanismo AMP grava uma variante mais nova — o cabeçalho do arquivo contém `Alteryx e2 Database file` — cuja especificação é proprietária e não publicada, de modo que nenhuma ferramenta fora do Alteryx consegue lê-la, incluindo o PlaidCloud.

Durante uma migração, você ainda tem o Alteryx Designer licenciado, e o Designer lê os dois formatos. Use-o uma vez, antes de desativá-lo, para reescrever os arquivos em formato AMP em algo portátil.

<Aside type="note">
  Os arquivos `.yxdb` clássicos são importados diretamente para o PlaidCloud — não é necessária conversão. Se uma importação falhar com um erro de arquivo ilegível em um `.yxdb`, a causa mais provável é um arquivo em formato AMP.
</Aside>

## Identificar arquivos em formato AMP

- O fluxo de trabalho que gerou o arquivo foi executado com o mecanismo AMP ativado.
- O PlaidCloud informa que o arquivo está ilegível durante a importação, enquanto outros arquivos `.yxdb` do mesmo pacote são importados normalmente.
- Os primeiros bytes do arquivo contêm `Alteryx e2 Database file` em vez de `Alteryx Database File` (visível em qualquer editor de texto ou hexadecimal).

## Opção A: salvar novamente os arquivos individualmente no Designer

Para poucos arquivos, salve cada um novamente a partir do Designer:

1. No Alteryx Designer, adicione uma ferramenta **Input Data** e selecione o arquivo `.yxdb`.
2. Conecte uma ferramenta **Output Data** e escolha um novo caminho `.yxdb`.
3. Nas opções da ferramenta Output Data, ative a opção de salvar o arquivo **compatível com o Designer 18.1 e anteriores**. Isso força o formato clássico.
4. Execute o fluxo de trabalho e depois importe o novo arquivo para o PlaidCloud.

Gravar em CSV em vez de `.yxdb` na etapa 2 também funciona e dispensa a opção de compatibilidade.

## Opção B: converter uma pasta em lote com o fluxo de trabalho para download

Para muitos arquivos, baixe o fluxo de trabalho pronto e execute-o no Designer:

<a href="/downloads/convert_yxdb_folder.yxmd" download>Baixar convert_yxdb_folder.yxmd</a>

Ele encadeia uma ferramenta **Directory**, uma ferramenta **Dynamic Input** e uma ferramenta **Output Data** para que todo `.yxdb` de uma pasta — clássico ou AMP — seja reescrito como um arquivo CSV chamado `converted_<original name>.csv`. O CSV é portátil e o PlaidCloud o importa sem perdas.

1. Abra `convert_yxdb_folder.yxmd` no Alteryx Designer.
2. Na ferramenta **Directory**, defina a pasta que contém seus arquivos `.yxdb`.
3. Na ferramenta **Dynamic Input**, aponte o modelo de origem dos dados de entrada para qualquer arquivo `.yxdb` dessa pasta.
4. Na ferramenta **Output Data**, defina a pasta de saída.
5. Execute o fluxo de trabalho e depois envie os CSVs para Documentos e importe-os.

<Aside type="caution">
  A ferramenta Dynamic Input exige que todos os arquivos de um lote tenham o mesmo layout de campos do arquivo de modelo. Arquivos com layout diferente são ignorados com um aviso — o painel de resultados do Designer nomeia cada arquivo ignorado. Agrupe os arquivos diferentes em uma pasta própria, com um modelo próprio, e execute novamente, ou salve novamente os arquivos restantes individualmente usando a Opção A.
</Aside>

Os arquivos convertidos para CSV perdem a tipagem específica do `.yxdb` (tudo chega como texto e é tipado novamente na importação), portanto verifique por amostragem os tipos de coluna das tabelas importadas — especialmente datas e decimais de alta precisão.
