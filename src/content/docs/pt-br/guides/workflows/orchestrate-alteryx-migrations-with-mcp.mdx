O servidor MCP do PlaidCloud permite que um agente de IA coordene uma migração de muitos fluxos de trabalho do Alteryx. O agente pode ajudar a preparar e organizar arquivos no Document, inventariar pacotes de fluxos de trabalho, chamar o conversor do Alteryx, organizar os fluxos de trabalho gerados, executar fluxos de trabalho de validação e resumir o progresso para a equipe de migração.

<Aside type="note">
  O MCP é ideal para a coordenação em escala de portfólio. O importador do PlaidCloud continua realizando a conversão; o agente ajuda a planejar, sequenciar, executar e resumir o trabalho.
</Aside>

## Quando usar o MCP

Use a orquestração por MCP quando estiver migrando muitos fluxos de trabalho ou quando quiser que um agente de IA ajude em tarefas de migração repetíveis:

- Inventariar os arquivos do Alteryx preparados no Document.
- Carregar, copiar, mover, renomear e organizar arquivos de migração por meio das ferramentas do Document.
- Trabalhar a partir de uma conta de armazenamento compartilhado conectada, como OneDrive, Google Drive, SharePoint, S3, Azure Blob ou SFTP.
- Agrupar fluxos de trabalho, aplicativos e macros em lotes de migração.
- Converter cada arquivo `.yxmd`, `.yxwz` ou `.yxmc` para o PlaidCloud.
- Acompanhar os resultados da conversão em todo o portfólio.
- Executar fluxos de trabalho convertidos ou fluxos de trabalho de validação.
- Produzir um resumo da migração para revisão.

Para um único fluxo de trabalho, o formulário de importação costuma ser o caminho mais rápido. Para um portfólio, o MCP dá ao agente uma forma estruturada de coordenar repetidamente os mesmos recursos do PlaidCloud.

## O que o agente pode chamar

O catálogo de ferramentas do MCP inclui uma ferramenta de conversão do Alteryx chamada `alteryx_convert`. Ela cria fluxos de trabalho do PlaidCloud a partir de arquivos do Alteryx armazenados no Document.

A chamada de conversão inclui:

- A conta de documentos e o caminho de origem do arquivo do Alteryx.
- O projeto de destino do PlaidCloud.
- A conta de documentos e o caminho de destino para os artefatos da conversão.
- Prefixos opcionais de fluxo de trabalho, etapa e tabela. O prefixo de tabela usa por padrão o próprio nome do fluxo de trabalho, o que evita que duas conversões no mesmo projeto usem as mesmas tabelas; informe um prefixo vazio para obter os nomes sem prefixo.
- O tipo de fluxo de trabalho, com fluxos de trabalho avançados como padrão.

O agente pode combinar isso com as ferramentas normais do MCP de projeto, fluxo de trabalho, Document, execução de fluxo de trabalho e tabela para gerenciar a migração como um todo.

## Preparar arquivos com o agente

Um agente conectado por MCP pode ajudar no trabalho de preparação de arquivos em torno da conversão:

- Encontrar arquivos `.yxmd`, `.yxwz` e `.yxmc` no Document.
- Identificar prováveis arquivos de entrada, arquivos de macro, ativos de relatório, arquivos auxiliares espaciais e saídas esperadas.
- Criar uma estrutura de pastas de migração organizada.
- Copiar, mover ou renomear arquivos para essa estrutura.
- Manter juntos os arquivos relacionados de fluxo de trabalho, macro, dados, espaciais, relatório e validação.
- Resumir o pacote antes da conversão.

Isso é útil quando um pacote de migração contém muitas pastas ou quando as equipes querem que o agente produza um inventário repetível antes de a conversão começar.

## Usar armazenamento compartilhado sem carregar arquivos

Você não precisa carregar arquivos em uma nova pasta do PlaidCloud antes da migração. O Document do PlaidCloud pode se conectar diretamente a um armazenamento compartilhado que já contém o pacote de migração do Alteryx.

As opções mais comuns incluem:

- [Google Drive](/pt-br/guides/documents/adding-accounts/add-google-drive-account/)
- [OneDrive ou SharePoint](/pt-br/guides/documents/adding-accounts/add-onedrive-account/)
- [AWS S3](/pt-br/guides/documents/adding-accounts/add-aws-s3-account/)
- [Azure Blob Storage](/pt-br/guides/documents/adding-accounts/add-azure-blob-storage-account/)
- [SFTP](/pt-br/guides/documents/adding-accounts/add-sftp-account/)

Depois que a conta de documentos estiver conectada, o agente pode trabalhar a partir dessa conta de documentos e caminho. Isso mantém a migração próxima ao armazenamento compartilhado já existente do cliente e pode eliminar uma etapa separada de carregamento.

## Preparar ou selecionar arquivos no Document

Antes de pedir a um agente que orquestre a migração, escolha um destes caminhos:

- Conectar um local de armazenamento compartilhado existente como uma conta de documentos.
- Carregar pacotes de fluxos de trabalho em uma conta de documentos.
- Pedir ao agente que organize os arquivos já disponíveis no Document.

Em seguida, confirme:

1. Fluxos de trabalho, aplicativos, macros, arquivos de entrada, arquivos auxiliares espaciais, relatórios e saídas esperadas estão disponíveis por meio do Document.
2. O projeto de destino está selecionado.
3. O caminho do Document para as dependências e os artefatos dos fluxos de trabalho convertidos está selecionado.
4. O agente tem permissão para usar as ferramentas relevantes do MCP de Document e de fluxo de trabalho.

O agente pode então referenciar caminhos estáveis do Document ao chamar o conversor.

## Prompt sugerido para o agente

Use um prompt como este com um agente conectado por MCP:

```text
In PlaidCloud, migrate the Alteryx workflows in the connected Document account
"Migration Share" under /q4-alteryx-package into the project "Q4 Migration".

First inventory the .yxmd, .yxwz, and .yxmc files. Organize the package by
workflow, macro, input, spatial, report, and expected-output files. Group macros
with the workflows that call them. Then convert the workflows as Advanced
workflows using the Document output path /q4-alteryx-converted. Prefix created
workflows with "Q4 - ". After each conversion, summarize the generated workflow,
macros, readiness notes, and next validation step. Ask before making mutating calls.
```

Ajuste o nome do projeto, o caminho de origem, o caminho de destino e o prefixo para o seu lote de migração.

## Fluxo de orquestração recomendado

Para migrações de portfólio, peça ao agente que siga este fluxo:

1. Conecte ou selecione a conta de documentos que contém o pacote de migração.
2. Inventarie a pasta de origem do Document.
3. Identifique os arquivos `.yxmd`, `.yxwz` e `.yxmc`.
4. Organize os arquivos em grupos de fluxo de trabalho, macro, entrada, espacial, relatório e saída esperada.
5. Agrupe os fluxos de trabalho e as macros relacionados.
6. Confirme o projeto de destino e o caminho de saída do Document.
7. Converta macros e fluxos de trabalho em fluxos de trabalho avançados.
8. Abra ou descreva os fluxos de trabalho gerados.
9. Execute a validação estrutural.
10. Execute a validação de paridade de saída quando houver saídas esperadas disponíveis.
11. Resuma os fluxos de trabalho convertidos, as macros geradas, os artefatos e o status da validação.

Isso dá à equipe de migração um único relatório de progresso para todo o portfólio, ao mesmo tempo em que usa o importador nativo do PlaidCloud em cada conversão.

## Revisar chamadas que alteram dados

A maioria dos clientes MCP mostra as chamadas de ferramenta antes de executá-las. Revise as chamadas de conversão e de execução de fluxo de trabalho antes de aprová-las, especialmente em projetos de produção.

Para migrações em ambiente de teste, use um projeto de migração e uma pasta do Document dedicados. Após a validação, promova os fluxos de trabalho convertidos para o projeto de produção.

## Acompanhar os resultados

Peça ao agente que produza uma tabela de migração com:

- O arquivo de origem do Alteryx.
- O fluxo de trabalho do PlaidCloud gerado.
- Os fluxos de trabalho de macro gerados.
- O status da conversão.
- O nível de validação.
- O caminho de saída no Document.
- Observações para acompanhamento.

Esse resumo é útil para relatórios do projeto, transferência de responsabilidade e revisão de prontidão para produção.
