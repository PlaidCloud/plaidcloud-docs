Use esta lista de verificação antes de importar fluxos de trabalho do Alteryx para o PlaidCloud. Um pacote completo ajuda o PlaidCloud a criar fluxos de trabalho avançados, fluxos de trabalho de macro, dependências baseadas em documentos e entradas de execução controladas com o mínimo de ajustes posteriores.

<Aside type="note">
  Para portfólios grandes, execute esta lista de verificação uma vez para o portfólio e novamente para cada família de fluxos de trabalho de alta prioridade.
</Aside>

## Reunir os arquivos de fluxo de trabalho

Reúna todos os arquivos de fluxo de trabalho que fazem parte da migração:

1. Fluxos de trabalho padrão: `.yxmd`.
2. Aplicativos analíticos: `.yxwz`.
3. Macros: `.yxmc`.
4. Macros aninhadas ou compartilhadas referenciadas por outros fluxos de trabalho.
5. Versões de fluxos de trabalho que ainda são usadas em produção.

Mantenha juntos os fluxos de trabalho e as macros relacionados quando eles chamarem uns aos outros. O PlaidCloud usa essas relações para gerar fluxos de trabalho de macro e conectar as portas de entrada e saída das macros.

## Reunir as dependências de dados

Empacote os arquivos que os fluxos de trabalho leem, gravam ou inspecionam:

- Arquivos CSV, TSV, de largura fixa, JSON, XML, Excel, Access, YXDB e de extração de banco de dados.
- Pastas usadas pelas ferramentas Directory ou Dynamic Input.
- Arquivos de saída esperados para validação.
- Ativos de relatório, como imagens, PDFs, modelos e camadas de mapa.
- Tabelas de consulta e tabelas de regras usadas em junções, fórmulas, substituições e correspondências.

Se um fluxo de trabalho fizer referência a um caminho local da área de trabalho, inclua esse arquivo ou pasta no pacote de importação e escolha o caminho de documentos onde o PlaidCloud deve armazená-lo.

## Reunir os arquivos auxiliares espaciais

Formatos de arquivo espacial costumam exigir que vários arquivos permaneçam juntos. Inclua todos os arquivos auxiliares na mesma pasta:

- Grupos de shapefile, como `.shp`, `.shx`, `.dbf` e `.prj`.
- Grupos do MapInfo, como `.tab`, `.map`, `.id` e `.dat`.
- KML, GeoJSON e outros arquivos espaciais independentes.
- Arquivos de projeção ou de sistema de referência de coordenadas usados pelo fluxo de trabalho.

A ausência de arquivos auxiliares é uma causa comum de diferenças na validação espacial.

## Registrar as entradas de execução

Para aplicativos analíticos, registre os valores que os usuários normalmente informam:

1. Entradas de texto, numéricas, de data, de arquivo e de pasta.
2. Seleções em listas suspensas, botões de opção, caixas de seleção, listas e árvores.
3. Padrões usados em execuções agendadas ou repetíveis.
4. Valores que disparam condições, avisos ou erros.

O PlaidCloud converte essas entradas em variáveis de fluxo de trabalho controladas.

## Escolher o local de destino

Antes da importação, decida:

1. O projeto de destino no PlaidCloud.
2. A conta de documentos de destino.
3. A pasta de documentos de destino para os arquivos importados.
4. A convenção de nomenclatura dos fluxos de trabalho e macros convertidos.
5. Se a primeira importação será de teste (staging) ou de produção.

Em migrações de portfólio, use uma pasta de migração dedicada em Documentos para que as dependências continuem fáceis de auditar.

## Escolher as evidências de validação

Para cada fluxo de trabalho, escolha o nível de validação:

- A validação estrutural confirma que o fluxo de trabalho é convertido em um DAG executável do PlaidCloud.
- A validação de paridade de saída compara esquema, contagem de linhas e valores das linhas com saídas confiáveis do Alteryx.
- A validação de artefatos revisa relatórios, PDFs, imagens, gráficos, mapas ou saídas de modelos.

Armazene as saídas esperadas junto com o pacote de migração sempre que a paridade de saída for necessária.

## Lista de verificação de prontidão para importação

Antes de importar, confirme:

- Os arquivos de fluxo de trabalho, aplicativo e macro estão presentes.
- As macros referenciadas estão presentes.
- Os arquivos e pastas de entrada estão presentes.
- Os arquivos auxiliares espaciais estão agrupados.
- As saídas esperadas estão disponíveis quando a validação de paridade faz parte do plano de migração.
- Os valores das entradas de execução são conhecidos para os aplicativos analíticos.
- O projeto de destino e o caminho de documentos estão selecionados.
- As credenciais ou conexões externas necessárias ao fluxo de trabalho estão disponíveis no PlaidCloud.
