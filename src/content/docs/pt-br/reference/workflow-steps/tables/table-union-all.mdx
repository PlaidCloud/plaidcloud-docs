## Descrição


Use para combinar várias tabelas de dados com a mesma estrutura de colunas em uma única tabela de dados. Por exemplo, dados de séries temporais são candidatos ideais para esta transformação. O resultado reúne todos os registros das tabelas combinadas.

<Aside>**Union All** não remove duplicatas. Se você quiser remover registros duplicados, use **Union Distinct**.</Aside>

## Origens


A seção **Origens** reúne todas as tabelas de dados a serem anexadas. Normalmente, todas as tabelas de dados têm a mesma estrutura de colunas (ou uma semelhante). Há dois botões para adicionar uma tabela de dados à lista:


* **Inserir linha**
* **Anexar linha**

Além disso, clicar com o botão direito na janela **Selecionar origem para editar** exibe as mesmas opções. Clicar com o botão direito em uma tabela já adicionada também exibe a opção **Excluir**.


Para executar a transformação corretamente, é necessário haver uma entrada na seção **Origens** para cada tabela de dados de origem a ser anexada. Essas entradas são listadas na ordem em que serão anexadas. Para ajustar a ordem, clique com o botão direito em uma tabela para exibir as seguintes opções:


* **Mover para baixo** (se aplicável)
* **Mover para o final** (se aplicável)
* **Mover para cima** (se aplicável)
* **Mover para o início** (se aplicável)

Por padrão, cada origem se chama *New Frame*, mas recomendamos que o modelador dê nomes descritivos, clicando duas vezes no nome e renomeando-o.


<Aside>É importante lembrar que o texto exibido **não** tem relação com o nome da tabela de dados de origem. Recomendamos que o modelador use um nome descritivo, muitas vezes igual ao da tabela de dados de origem, mas tenha em mente que não há nenhum vínculo entre os nomes.</Aside>


## Tabela de destino


Por padrão, a **Tabela de destino** fica em branco. Antes de nomeá-la, observe que as tabelas de dados devem seguir as convenções de nomenclatura do Linux. Por isso, recomendamos que os nomes tenham apenas caracteres alfanuméricos. O Analyze remove automaticamente do nome os caracteres inválidos. Além disso, ele limita o tamanho a 256 caracteres, então seja conciso!

## Correspondência de colunas

**Corresponder colunas por**, em **Tabela de destino**, escolhe como as origens são alinhadas:

* **Nome** (padrão) — as colunas de cada origem são associadas às da primeira origem pelo nome.
* **Posição** — as origens são empilhadas em ordem, como faz o `union` do Spark. O resultado usa os nomes de coluna da primeira origem, e todas as origens precisam ter o mesmo número de colunas. O mapeamento de colunas de cada origem não é usado, portanto a guia **Seleção de dados da tabela** fica desativada.

Com **Posição**, cada coluna assume um tipo que todas as origens comportam: dois tipos numéricos tornam-se o mais amplo, uma data e um carimbo de data/hora tornam-se um carimbo de data/hora, e as demais combinações tornam-se texto. Uma coluna booleana ou binária combinada com outro tipo não tem tipo comum e faz a etapa falhar, assim como origens com números de colunas diferentes.

Se todas as tabelas de origem estiverem ausentes, a etapa termina com um aviso em vez de falhar, em qualquer um dos modos.

## O que é verificado ao salvar

Toda origem deve produzir as mesmas colunas da primeira origem: os mesmos nomes de coluna e, quando ambas declaram um, o mesmo tipo. A tabela de destino é construída a partir das colunas da primeira origem. Uma origem pode listar suas colunas em outra ordem, porque elas são associadas pelo nome. Salvar uma etapa cujas origens diferem é recusado, com a indicação de cada diferença: *Source 'east' must produce the same columns as 'west': missing region; not in 'west': area.*

Ao salvar, também é preenchido o mapeamento de cada origem que tem uma tabela de origem, mas não tem colunas de origem ou de destino, a partir dessa tabela, como faria **Preencher ambas as tabelas de mapeamento**.
