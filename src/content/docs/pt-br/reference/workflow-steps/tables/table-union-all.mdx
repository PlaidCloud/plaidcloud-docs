## Descrição


Use para combinar várias tabelas de dados com a mesma estrutura de colunas em uma única tabela de dados. Por exemplo, dados de série temporal são candidatos ideais para esta transformação. O resultado são todos os registros das tabelas combinadas.

<Aside>O **Union All** não remove duplicatas. Se você quiser remover registros duplicados, use **Union Distinct**.</Aside>

## Origens


A seção **Origens** funciona como uma coleção de todas as tabelas de dados a anexar umas às outras. Normalmente, todas as tabelas de dados têm a mesma estrutura de colunas (ou semelhante). Há dois botões disponíveis para adicionar uma tabela de dados à lista:


* **Inserir linha**
* **Anexar linha**

Além disso, clicar com o botão direito na janela **Selecionar origem para editar** exibe as mesmas opções. Clicar com o botão direito em uma tabela já adicionada também exibe a opção **Excluir**.


Para executar a transformação corretamente, é preciso haver uma entrada na seção **Origens** para cada tabela de dados de origem a anexar. Essas entradas são listadas na ordem em que serão anexadas. Para ajustar a ordem, clicar com o botão direito em uma tabela exibe as seguintes opções:


* **Mover para baixo** (se aplicável)
* **Mover para o final** (se aplicável)
* **Mover para cima** (se aplicável)
* **Mover para o início** (se aplicável)

Por padrão, cada origem recebe o nome *New Frame*, mas o modelador é incentivado a fornecer nomes descritivos clicando duas vezes no nome e renomeando-o de acordo.


<Aside>É importante lembrar que o texto exibido **não** está relacionado ao nome da tabela de dados de origem. Recomendamos que o modelador forneça um nome descritivo, muitas vezes o mesmo da tabela de dados de origem, mas lembre-se de que não há nenhum vínculo entre os nomes.</Aside>


## Tabela de destino


Por padrão, a **Tabela de destino** fica em branco. Antes de dar um nome, observe que as tabelas de dados devem seguir as convenções de nomenclatura do Linux. Por isso, recomendamos que os nomes consistam apenas em caracteres alfanuméricos. O Analyze remove automaticamente do nome quaisquer caracteres inválidos. Além disso, ele limita o tamanho a 256 caracteres, então seja conciso!

## Correspondência de colunas

**Corresponder colunas por**, em **Tabela de destino**, escolhe como as origens se alinham:

* **Nome** (padrão): as colunas de cada origem são correspondidas às da primeira origem pelo nome.
* **Posição**: as origens são empilhadas em ordem, como faz o `union` do Spark. O resultado usa os nomes de coluna da primeira origem, e toda origem precisa ter o mesmo número de colunas. O mapeamento de colunas de cada origem não é usado, então a guia **Colunas** dela fica desativada.

Com **Posição**, cada coluna assume um tipo que todas as origens comportam: dois tipos numéricos se tornam o mais amplo, uma data e um carimbo de data/hora se tornam um carimbo de data/hora, e as demais combinações se tornam texto. Uma coluna booleana ou binária combinada com outro tipo não tem tipo comum e faz a etapa falhar, assim como origens com números diferentes de colunas.

Se todas as tabelas de origem estiverem ausentes, a etapa termina com um aviso em vez de falhar, em qualquer um dos modos.

## O que é verificado ao salvar

Toda origem deve produzir as mesmas colunas que a primeira origem: os mesmos nomes de coluna e, quando ambas declaram um, o mesmo tipo. A tabela de destino é construída a partir das colunas da primeira origem. Uma origem pode listar suas colunas em uma ordem diferente, porque elas são correspondidas pelo nome. Salvar uma etapa cujas origens diferem é recusado, nomeando cada diferença: *A origem 'east' deve produzir as mesmas colunas que 'west': falta region; não está em 'west': area.*

Salvar também preenche, a partir da tabela dela, o mapeamento de cada origem que tem uma tabela de origem, mas não tem colunas de origem ou de destino, como faria **Preencher ambas as tabelas de mapeamento**.
