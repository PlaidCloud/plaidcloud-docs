## Descrição

A etapa **Tabela: Função de texto** aplica uma função de texto às colunas de cada linha que a função lê e grava o resultado em uma nova coluna de uma cópia da tabela de origem. Um NULL em qualquer coluna lida pela função resulta em NULL.

## Origem e opções

- **Tabela de origem** e **Tabela de saída** — a tabela a ser lida e a tabela a ser gravada.
- **Função** — a função a aplicar. O formulário oferece as funções das duas tabelas abaixo e mostra um campo de coluna, rotulado conforme sua função, para cada argumento que a função selecionada lê.
- **Colunas de argumento** — as colunas que a função lê, na ordem em que a tabela as lista. Todas são obrigatórias.
- **Coluna de saída** — o nome da coluna adicionada à cópia da origem.

| Função | Argumentos | Resultado |
| --- | --- | --- |
| `levenshtein` | Primeira coluna, Segunda coluna | Distância de edição que diferencia maiúsculas e minúsculas, como número inteiro |
| `soundex` | Texto | Texto |
| `json_format` | JSON | Texto JSON formatado para leitura |
| `json_field` | JSON, Caminho | Texto |
| `json_set_text`, `json_set_number`, `json_set_boolean` | JSON, Caminho, Valor | Texto JSON com o valor definido |
| `regex_match` | Texto, Padrão, Diferenciar maiúsculas e minúsculas | Verdadeiro ou falso |
| `regex_search` | Texto, Padrão, Ocorrência, Diferenciar maiúsculas e minúsculas | Posição, como número inteiro |
| `regex_extract` | Texto, Padrão, Ocorrência, Diferenciar maiúsculas e minúsculas | Texto |
| `regex_replace` | Texto, Padrão, Substituição, Diferenciar maiúsculas e minúsculas | Texto |
| `to_text_number` | Número, Padrão | Texto: o número escrito com um padrão no estilo DecimalFormat |
| `to_text_datetime` | Data/hora, Padrão | Texto: a data escrita com um padrão de data e hora |
| `parse_date` | Texto, Padrão | O texto lido como data |
| `parse_datetime` | Texto, Padrão | O texto lido como data e hora |

Uma análise do Savant convertida pode conter qualquer uma dessas funções, e elas são executadas da mesma forma. Uma função que o formulário não oferece mostra as colunas armazenadas e é mantida exatamente como foi salva.

### Mais funções

A lista **Função** também oferece estas funções. Fluxos de trabalho do KNIME convertidos também as usam.

| Função | Argumentos | Resultado |
| --- | --- | --- |
| `damerau_levenshtein`, `hamming`, `lcs` | Primeira coluna, Segunda coluna | A distância de edição correspondente, como número inteiro |
| `jaro`, `jaro_winkler` | Primeira coluna, Segunda coluna | 1 menos a similaridade, 0 para textos iguais |
| `ngram_distance` | Primeira coluna, Segunda coluna | 1 menos o coeficiente de Dice dos bigramas de caracteres |
| `jaccard_tokens`, `dice_tokens`, `cosine_tokens` | Primeira coluna, Segunda coluna | 1 menos a similaridade de conjuntos das palavras dos dois textos, 1 quando qualquer um deles não tem palavras |
| `java_compare` | Primeira coluna, Segunda coluna | A diferença dos primeiros caracteres distintos, como o `compareTo` do Java a fornece, como número inteiro |
| `java_regex` | Texto, Padrão, Substituição *(somente no modo replace)* | Uma expressão regular Java lida de uma coluna: verdadeiro ou falso nos modos `matches` e `find`, texto em `extract` e `replace` |
| `knime_count` | Texto, Texto de pesquisa | Quantas vezes o texto de pesquisa ocorre, como número inteiro |
| `knime_binomial`, `long_pow` | Dois números | O coeficiente binomial, ou a potência inteira, em aritmética de 64 bits com estouro cíclico |
| `encode`, `decode` | Texto | O texto como bytes base64 em um conjunto de caracteres, e o inverso |
| `url_encode` | Texto | O texto codificado com porcentagem como valor de formulário, com o espaço escrito como `+` |
| `list_sort_numeric` | Texto | Uma lista mantida como texto separado, ordenada por valor numérico |
| `geojson_to_wkt` | JSON, Caminho | A geometria GeoJSON em um caminho como `$.a[0]`, ou `$` para o próprio texto, como WKT |
| `json_patch_apply` | JSON | O documento com um JSON Patch ou Merge Patch aplicado |
| `json_diff` | Primeiro JSON, Segundo JSON | O JSON Patch que transforma o primeiro documento no segundo |
| `json_schema_check` | JSON | Os erros que o documento tem em relação a um Esquema JSON, como JSON; NULL quando não há nenhum |
| `json_normalize` | JSON | O documento como texto JSON normalizado |
| `json_to_xml`, `xml_to_json` | Documento | O documento convertido para XML ou para JSON |
| `xml_well_formed` | XML | O texto quando é um XML bem formado; caso contrário, NULL |
| `xslt` | XML, Folha de estilo | O documento transformado pela folha de estilo XSLT |
| `message_text`, `message_tool_calls` | JSON | O texto de uma mensagem de IA, ou suas chamadas de ferramenta como JSON |

Defina as opções de uma função em `function_options`:

- `java_regex` — `mode`: `matches` (padrão, o texto inteiro), `find` (em qualquer parte), `extract` (grupo `group` da primeira correspondência, padrão 0) ou `replace` (todas as correspondências); `flags` `i` ignora maiúsculas e minúsculas.
- `knime_count` — `modifiers`: `i` ignora maiúsculas e minúsculas, `w` conta palavras inteiras entre espaços em branco.
- `encode` e `decode` — `charset`, um nome de conjunto de caracteres Java; o padrão é UTF-8.
- `json_patch_apply` — `patch`, a matriz JSON Patch ou o objeto Merge Patch; `merge` é verdadeiro para um Merge Patch; `keep` mantém o documento quando um teste do patch falha.
- `json_schema_check` — `schema`; `fail` interrompe a etapa no primeiro erro em vez de retorná-lo.
- `json_normalize` — `comments` permite comentários `/* */` e `//`; `fail` (padrão verdadeiro) interrompe a etapa diante de um texto que não é JSON, e falso resulta em NULL.
- `json_to_xml` — `root`, `item`, `typed`, `parent_keys`, `namespace`, `text_key` e `text_key_enabled`. `xml_to_json` — `text_key`, `comments` e `pis`.
- `list_sort_numeric` — `separator`; `empty`, o texto gravado para uma lista sem elementos; e `missing`, o texto de um elemento ausente, ordenado por último.

Por padrão, a etapa lê todas as colunas da origem e grava todas as colunas da origem seguidas da coluna de saída. Defina `source_columns` para ler apenas algumas colunas e `target_columns` (cada uma `{source, target, dtype}`) para escolher e ordenar as colunas gravadas. Uma coluna de destino com o mesmo nome da coluna de saída toma o lugar dela, com o tipo de dados indicado.
