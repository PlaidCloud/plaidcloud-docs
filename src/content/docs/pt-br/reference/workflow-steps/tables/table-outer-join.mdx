## Descrição


Use para executar uma junção externa em 2 tabelas de dados, combinando-as em uma única tabela de dados com base nas chaves de junção especificadas. O controle **Tipo de junção** seleciona quais linhas sem correspondência manter: uma junção **à esquerda**, **à direita** ou **externa completa**. O padrão é uma junção à esquerda (todas as linhas da Tabela A, com as colunas da Tabela B preenchidas onde as chaves correspondem).


Para mais detalhes sobre a metodologia da junção externa, veja aqui: [Wikipedia SQL Join](http://en.wikipedia.org/wiki/Join_%28SQL%29)

## Colunas nomeadas durante a execução

Selecione **Levar também colunas nomeadas durante a execução** para passar adiante, sem alteração, todas as colunas de origem que a etapa não lista, como a tabela as tem quando a etapa é executada. Use-o quando uma etapa anterior cria colunas cujos nomes dependem dos dados, como um pivô, de modo que você não pode listá-las ao construir a etapa. Deixe desativado para gravar apenas as colunas que você lista.

### Tipo de junção

Escolha como as linhas sem correspondência são mantidas:

- **Junção à esquerda**: mantém todas as linhas da Tabela A; as colunas da Tabela B são preenchidas apenas onde as chaves de junção correspondem. Este é o padrão.
- **Junção à direita**: mantém todas as linhas da Tabela B; as colunas da Tabela A são preenchidas apenas onde as chaves de junção correspondem.
- **Junção externa completa**: mantém todas as linhas de ambas as tabelas, tenham ou não correspondência do outro lado.

## Exemplos


### Unir fabricantes de automóveis com modelos


Neste exemplo, considere as seguintes tabelas de dados de origem. A primeira é uma lista de fabricantes de automóveis.




| Mfg_ID | Manufacturer |
|--------|--------------|
|    1   | Aston Martin |
|    2   | Porsche      |
|    3   | Lamborghini  |
|    4   | Ferrari      |
|    5   | Koenigsegg   |


A seguir, uma lista de modelos de automóveis com um ID de fabricante. Observe que vários modelos não têm fabricante.




| ModelName          | Mfg_ID |
|--------------------|--------|
| Aventador          |    3   |
| Countach           |    3   |
| DBS                |    1   |
| Enzo               |    4   |
| One-77             |    1   |
| Optimus Prime      |        |
| Batmobile          |        |
| Agera              |    5   |
| Lightning McQueen  |        |

Para obter uma lista de modelos por fabricante, faz sentido unir por *Mfg_ID*. Ao aproveitar os conceitos de junção externa, a saída também poderá mostrar os itens que não têm nenhuma correspondência.



Primeiro, especifique os parâmetros da **Seleção de dados da Tabela 1**. A tabela de dados de origem é selecionada e todas as colunas são listadas.



Em seguida, especifique os parâmetros da **Seleção de dados da Tabela 2.** Mais uma vez, a tabela de dados de origem é selecionada e todas as colunas são listadas.



Por fim, as condições de junção são definidas na guia **Saída**. Usando o botão **Detectar**, o Analyze identifica corretamente a coluna *Mfg_ID* a ser usada como **Chave de junção**. Como este exemplo mantém as linhas sem correspondência de ambas as tabelas, defina o **Tipo de junção** como **Junção externa completa**. Por último, as 


**Colunas de saída de destino** são especificadas automaticamente com o botão **Propagar**. Isso inclui efetivamente todas as colunas de todas as tabelas, com as colunas de junção, obviamente, incluídas uma única vez. Observe que as colunas são ordenadas alfabeticamente, primeiro por *Manufacturer* e depois por *ModelName*.



Como esperado, a saída final inclui todas as linhas de ambas as tabelas, tenham ou não correspondência nas duas. Assim, desta vez a *Porsche* de fato aparece, apesar de não ter modelos. Além disso, *Batmobile*, *Lightning McQueen* e *Optimus Prime* são incluídos nos resultados mesmo que nenhum deles tenha fabricante. Afinal, quem consegue dizer ‘não’ a eles?
