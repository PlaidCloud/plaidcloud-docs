## Descrição


Use esta etapa para executar uma junção externa em 2 tabelas de dados, combinando-as em uma única tabela de dados com base nas chaves de junção especificadas. O controle **Tipo de junção** seleciona quais linhas sem correspondência manter — uma **Junção à esquerda**, uma **Junção à direita** ou uma **Junção externa completa**. O padrão é a junção à esquerda (todas as linhas da Tabela A, com as colunas da Tabela B preenchidas onde as chaves correspondem).


Para mais detalhes sobre a metodologia da junção externa, consulte: [Wikipedia SQL Join](http://en.wikipedia.org/wiki/Join_%28SQL%29)

## Colunas nomeadas durante a execução

Marque **Levar também colunas nomeadas durante a execução** para passar sem alteração todas as colunas de origem que a etapa não lista, como a tabela as tem quando a etapa é executada. Use essa opção quando uma etapa anterior cria colunas cujos nomes dependem dos dados, como em um pivô, e por isso você não pode listá-las ao criar a etapa. Deixe-a desmarcada para gravar somente as colunas que você listar.

### Tipo de junção

Escolha como as linhas sem correspondência são mantidas:

- **Junção à esquerda** — mantém todas as linhas da Tabela A; as colunas da Tabela B são preenchidas somente onde as chaves de junção correspondem. Este é o padrão.
- **Junção à direita** — mantém todas as linhas da Tabela B; as colunas da Tabela A são preenchidas somente onde as chaves de junção correspondem.
- **Junção externa completa** — mantém todas as linhas das duas tabelas, tenham ou não correspondência do outro lado.

## Exemplos


### Junção de fabricantes de automóveis com modelos


Neste exemplo, considere as tabelas de dados de origem a seguir. A primeira é uma lista de fabricantes de automóveis.




| Mfg_ID | Manufacturer |
|--------|--------------|
|    1   | Aston Martin |
|    2   | Porsche      |
|    3   | Lamborghini  |
|    4   | Ferrari      |
|    5   | Koenigsegg   |


A seguir, há uma lista de modelos de automóveis com um ID de fabricante. Observe que vários modelos não têm fabricante.




| ModelName          | Mfg_ID |
|--------------------|--------|
| Aventador          |    3   |
| Countach           |    3   |
| DBS                |    1   |
| Enzo               |    4   |
| One-77             |    1   |
| Optimus Prime      |        |
| Batmobile          |        |
| Agera              |    5   |
| Lightning McQueen  |        |

Para obter uma lista de modelos por fabricante, faz sentido juntar por *Mfg_ID*. Ao aproveitar os conceitos de junção externa, a saída também poderá mostrar os itens que não têm nenhuma correspondência.



Primeiro, especifique os parâmetros de **Table 1 Data Selection**. A tabela de dados de origem é selecionada e todas as colunas são listadas.



Em seguida, especifique os parâmetros de **Table 2 Data Selection.** Mais uma vez, a tabela de dados de origem é selecionada e todas as colunas são listadas.



Por fim, as condições de junção são definidas na guia **Table Output**. Usando o botão **Detectar**, o Analyze identifica corretamente a coluna *Mfg_ID* a ser usada como **Join Key**. Como este exemplo mantém as linhas sem correspondência das duas tabelas, defina o **Tipo de junção** como **Junção externa completa**. Por último, as 


**Colunas de saída de destino** são especificadas automaticamente com o botão **Propagar**. Isso inclui, na prática, todas as colunas de todas as tabelas, com as colunas de junção, obviamente, incluídas uma única vez. Observe que as colunas são ordenadas alfabeticamente, primeiro por *Manufacturer* e depois por *ModelName*.



Como esperado, a saída final inclui todas as linhas das duas tabelas, tenham ou não correspondência nas duas. Por isso, desta vez *Porsche* aparece, mesmo sem ter modelos. Além disso, *Batmobile*, *Lightning McQueen* e *Optimus Prime* são incluídos nos resultados, embora nenhum deles tenha fabricante. Afinal, quem consegue dizer “não” a eles?
