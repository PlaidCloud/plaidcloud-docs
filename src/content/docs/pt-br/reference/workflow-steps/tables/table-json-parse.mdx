## Descrição

Lê uma coluna com texto JSON e a expande em linhas de saída — uma para cada valor encontrado no documento. É a contrapartida de [Análise de XML](/pt-br/reference/workflow-steps/tables/table-xml-parse/) e o equivalente do PlaidCloud à ferramenta *JSON Parse* do Alteryx.

Use-a quando um sistema anterior entrega um payload JSON em uma única coluna e você precisa do conteúdo dele como linhas e colunas comuns.

## Itens de configuração exclusivos

### Campo JSON

A coluna com o texto JSON a ser analisado.

### Formato da saída

- **Name and value only** (padrão) — cada linha de saída traz `JSON_Name` e `JSON_ValueString`. É a opção mais simples e basta quando tudo o que vem depois trata os valores como texto.
- **Typed values** — desative a opção de campo único para adicionar as colunas de valor específicas de cada tipo, de modo que números e booleanos cheguem como números e booleanos, e não como strings.

### Levar as colunas de entrada

Desativado por padrão. Ative para repetir as demais colunas do registro de entrada em cada linha de valor, de modo que os valores analisados permaneçam associados ao registro de origem sem uma etapa de junção separada.

### Outros layouts

**Saída** (`json_layout`) escolhe um formato de saída diferente. Cada um deles mantém uma linha para cada linha de entrada:

- **Largo: uma coluna por caminho de chave** (`wide`) — as colunas de entrada, menos o campo JSON, a menos que ele seja incluído, mais uma coluna de texto para cada caminho de chave com pontos, NULL onde um documento não o tem.
- **Uma coluna por consulta JSONPath** (`paths`) — as colunas de entrada mais uma coluna para cada consulta JSONPath. Liste as consultas em **Consultas JSONPath** (`json_paths`), cada uma com as configurações **Coluna**, **JSONPath**, **Tipo** e **Várias correspondências** (`target`, `path`, `dtype`, `multi`): `path` é um JSONPath (nomes, índices, curingas, varredura profunda, fatias, uniões e filtros), `dtype` é `text`, `integer`, `bigint`, `double`, `boolean` ou `json`, e `multi` fica vazio para a primeira correspondência (NULL quando não há nenhuma), `list` para todas as correspondências como um valor de lista, ou `paths` para os caminhos que correspondem. Em vez da lista, **Consultas de uma tabela** (`json_dictionary`) lê as consultas das linhas de uma tabela: `{source, path, type, output}` nomeiam a tabela e as colunas dela que contêm cada caminho, tipo e nome de coluna de saída.
- **Colunas como o KNIME JSON to Table as cria** (`table`) — as colunas de entrada mais as colunas que o nó JSON to Table do KNIME cria a partir dos documentos. As opções de **JSON para tabela** (`json_table`) a controlam, começando por **Nomear as colunas pelo caminho JSON** (`paths`), **Separador de caminho** (`separator`, padrão `.`) para unir os segmentos do caminho, **Matrizes** (`arrays`) como `GenerateCollectionCells`, `GenerateColumns` ou `KeepAllArrayAsJsonArray`, **Níveis a expandir** (`levels`, 0 para todos) e **Omitir os objetos que foram expandidos** (`omit_objects`, padrão true) para deixar de fora os valores de objeto.

Com o layout JSONPath ou JSON para tabela, ative **Omitir o campo JSON da saída** (`json_remove_source`) para remover o campo JSON do resultado.
