## Descrição

Executa uma operação versionada de paridade com o Alteryx como um job gerenciado. É o veículo de uso geral para [conversões do Alteryx](/pt-br/guides/workflows/migrate-alteryx-workflows/) cujo trabalho precisa de bibliotecas Python — Shapely, scikit-learn, NLTK, Tesseract, reportlab — em vez de SQL de banco de dados.

A maioria das operações convertidas agora tem seu próprio tipo de etapa de primeira classe, mais fácil de ler e editar. Esta etapa continua existindo para as operações que não têm, e é o que esses tipos de etapa iniciam por baixo dos panos.

<Aside type="note" title="Normalmente não é criada manualmente">
  A conversão gera esta etapa onde ela é necessária. Você a adicionaria manualmente
  apenas para executar uma operação de paridade que não tem um tipo de etapa próprio — por exemplo,
  [Spatial Info (etapa)](/pt-br/reference/workflow-steps/spatial/spatial-info/).
</Aside>

## Configuração

### Executor

- **Operação** — a operação de paridade a executar.
- **Versão do contrato** — o contrato do executor sob o qual a operação é executada. O padrão é `v1`.

### Entradas e saídas

- **Origem** / **Tabela de destino** — as tabelas primárias de entrada e de saída.
- **Tabelas de entrada** / **Tabelas de saída** — tabelas adicionais para operações que recebem ou produzem mais de uma.
- **Artefatos de entrada** / **Artefatos de saída** — entradas e saídas que não são tabelas, como imagens renderizadas.

### Recursos

Desativado por padrão; nesse caso, o job recebe os recursos padrão. Ative o gerenciamento avançado de recursos para definir **CPU** e **Memória** explicitamente — vale a pena quando uma operação trata geometrias excepcionalmente grandes ou treinamento de modelos e a alocação padrão não é suficiente.
