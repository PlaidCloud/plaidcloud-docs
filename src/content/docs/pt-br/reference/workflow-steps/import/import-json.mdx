## Descrição

Importe arquivos de texto JSON do PlaidCloud Document.

Para mais detalhes sobre arquivos JSON, consulte o site oficial do JSON: http://json.org/.

Os arquivos JSON *não* mantêm a ordem das colunas. A ordem das colunas no arquivo de origem não reflete necessariamente a ordem das colunas na tabela de dados importada.

As importações de JSON são transmitidas por armazenamento temporário em vez de carregar o documento inteiro na memória, de modo que arquivos muito grandes são importados sem esgotar a memória. As colunas que aparecem pela primeira vez no fim de um documento grande são incluídas na tabela importada. Objetos e arrays aninhados são importados como texto JSON compacto padrão, de modo que as etapas seguintes possam analisá-los com qualquer ferramenta JSON.

## Itens de configuração exclusivos

### Orientação dos dados JSON

Considere o seguinte conjunto de dados:

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

Os arquivos JSON podem ser importados em um de três formatos de dados:

* Records: os dados são armazenados em conjuntos de dicionários Python, com cada linha armazenada no formato \{Column -> Value, …}. Por exemplo:


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index: os dados são armazenados em conjuntos de dicionários Python aninhados, com cada linha armazenada no formato \{Index -> \{Column -> Value, …},…}. Por exemplo:


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split: os dados são armazenados em um único conjunto de dicionário Python, com os valores armazenados em listas. Por exemplo:


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

Além dos formatos acima, o JSON delimitado por nova linha (NDJSON) é aceito: um objeto JSON independente por linha, sem array envolvente. Por exemplo:

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### Documento inteiro

Para manter o JSON de cada arquivo intacto, selecione **Importar cada arquivo como uma linha com todo o documento JSON** (`whole_document`) em **Mais opções de JSON**. Cada arquivo é então importado como uma linha que contém todo o seu documento JSON, com os números mantidos como foram escritos.

### Datas e carimbos de data/hora

Um campo é importado como datas ou carimbos de data/hora quando todos os seus valores têm o mesmo destes formatos:

| Formato | Datas | Carimbos de data/hora |
| --- | --- | --- |
| ISO 8601 | `2026-01-23` | `2026-01-23T23:14:00` |
| Mês primeiro | `01-23-2026` ou `01-23-26` | `01-23-2026 11:14:00 PM`, com hora no formato de 12 horas |
| Dia primeiro | `23-01-2026` ou `23-01-26` | `23-01-2026 23:14:00`, com hora no formato de 24 horas |
| Ano de dois dígitos primeiro | `99-01-23` | `99-01-23 23:14:00`, com hora no formato de 24 horas |

Todos os valores de um campo são lidos da mesma forma, qualquer que seja a ordem das linhas. Um campo em qualquer outro formato, como `01/23/2026` ou `01-23-2026 23:14:00`, é importado como texto. O mesmo acontece com um campo cujos valores misturam formatos, embora algumas misturas de anos de dois e de quatro dígitos, como `01-23-2026` e `01-24-26`, interrompam a importação com um erro que nomeia o campo.

#### Quando um valor se encaixa em mais de um formato

`01-03-2026` pode ser 3 de janeiro ou 1º de março, e `23-01-26` pode ser 23 de janeiro de 2026 ou, lido com o ano primeiro, 26 de janeiro de 2023. Quando todos os valores de um campo se encaixam em mais de um dos formatos acima, o **Formato de data** da etapa decide pela ordem de dia, mês e ano:

* Uma opção que começa com Mês e dia lê o mês primeiro: `01-03-2026` como 3 de janeiro.
* Uma opção que começa com Dia e mês ou Abreviado lê o dia primeiro: `01-03-2026` como 1º de março, e `23-01-26` como 23 de janeiro de 2026.
* Com qualquer outro Formato de data, a importação é interrompida com um erro que nomeia o campo e as opções que resolveriam o caso.

Essas opções também leem um carimbo de data/hora no outro relógio quando o dia e o mês de todos os valores são 12 ou menos: uma opção Mês e dia lê `01-03-2026 23:14:00` como 3 de janeiro, e uma opção Dia e mês ou Abreviado lê `01-03-2026 11:14:00 PM` como 1º de março. Qualquer outro Formato de data os lê como na tabela, dia primeiro com hora de 24 horas e mês primeiro com hora de 12 horas.

Nenhuma opção de Formato de data lê o ano de dois dígitos primeiro, de modo que um campo como `26-01-23` é importado com o ano primeiro somente quando seus valores não podem ser lidos de outra forma, como em `99-01-23`. Escrita com um ano de quatro dígitos, como `2026-01-23`, essa data é importada como ISO 8601.

Um arquivo que também contém um carimbo de data/hora dentro de um objeto ou array aninhado é a exceção: nenhuma das verificações acima se aplica a ele, e um valor que se encaixa em mais de um formato pode ser lido de forma diferente de uma linha para outra.
