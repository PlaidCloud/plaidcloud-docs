## Descrição


Importa o resultado de uma consulta SQL em um banco de dados externo para uma tabela de projeto do PlaidCloud. A consulta é executada no banco de dados remoto; somente o conjunto de resultados é trazido para o PlaidCloud.

Difere de [Importar tabelas de banco de dados externo](/pt-br/reference/workflow-steps/import/import-external-database-tables/) porque você mesmo escreve o SQL, o que é útil para junções, filtros ou agregações complexas que você quer que o banco de dados de origem realize antes de os dados chegarem ao PlaidCloud.

### Detecção do tipo de coluna
As importações de SQL têm a opção de tentar detectar o tipo de dados durante o carregamento ou de definir todas as colunas com o tipo Texto. Definir os tipos de dados dinamicamente pode ser mais rápido se os dados estiverem limpos, mas pode causar problemas em algumas circunstâncias.

Por exemplo, se a maior parte dos dados parecer numérica, mas também houver algum texto, a importação pode tentar defini-la como numérica, causando problemas de carregamento por tipos de dados incompatíveis. Ou pode haver problemas se houver um código de produto numérico de 16 dígitos, por exemplo. Ele cortaria os zeros à esquerda, resultando em um número em vez de um código de 16 dígitos.

Definir todos os dados como texto, porém, exige uma etapa Extract posterior para converter os tipos de dados que não deveriam ser texto para o tipo apropriado, como datas ou valores numéricos.

## Solução de problemas

| Sintoma | Causa provável |
| --- | --- |
| A etapa levou visivelmente mais tempo que o normal, até cerca de meia hora a mais, sem que nada mais mudasse na sua consulta, conexão ou volume de dados | O worker em segundo plano que executava a importação foi interrompido no meio do caminho (uma reinicialização ou remoção do lado da plataforma, não algo no seu fluxo de trabalho), e a plataforma tentou novamente a importação da tabela para você. A nova tentativa só começa quando a interrupção é detectada, o que explica o tempo extra. |
| A etapa ainda terminou com sucesso depois desse atraso | A nova tentativa substitui totalmente o conteúdo da tabela, então o resultado é o mesmo de uma única execução limpa; não há mais nada a verificar ou refazer. |
| A etapa falha com "has already been attempted and cannot be safely re-run" | Em uma etapa Importar SQL, essa recusa não ocorre mais: uma interrupção no meio da execução é tentada novamente. Você ainda a verá, por projeto, ao [restaurar um arquivo de projeto](/pt-br/guides/projects/archive-a-project/#restaurar-um-arquivo) ou [carregar uma dimensão](/pt-br/reference/workflow-steps/dimensions/dimension-load/), em que executar de novo criaria uma duplicata em vez de substituir algo. Abra um chamado de suporte se você a vir em uma própria etapa Importar SQL.
