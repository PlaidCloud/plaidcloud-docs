## Descrição

Lê um arquivo de banco de dados Microsoft Access de uma conta de documentos e importa suas tabelas — uma tabela de projeto para cada tabela do Access, nomeada com um prefixo que você escolhe.

Como um arquivo Access contém várias tabelas, esta etapa importa o arquivo como um todo, em vez de mapear as colunas de uma única tabela.

## Itens de configuração exclusivos

### Origem

O arquivo de banco de dados Access em uma conta de documentos. O seletor de arquivos também permite correspondência por pesquisa, em vez de um caminho exato, com uma opção recursiva e uma regra para conciliar diferenças de esquema entre os arquivos correspondentes.

### Destino

**Prefixo da tabela** — adicionado no início do nome de cada tabela importada, para que as tabelas de um arquivo permaneçam agrupadas e não colidam com as de outra importação.

### Ignorar se não houver alterações

Ativado por padrão. Uma execução de fluxo de trabalho ignora totalmente a importação — inclusive o download — quando o arquivo de origem não mudou desde a última execução e as tabelas de destino ainda contêm as linhas que ela carregou. Uma tabela que foi esvaziada é importada novamente.

## Quando o arquivo não pode ser lido

A etapa falha, informando o arquivo e a tabela que não conseguiu ler, em vez de terminar e deixar uma tabela vazia para trás. Isso acontece quando o arquivo não lista nenhuma tabela que o PlaidCloud consiga ler, quando uma tabela é nomeada mas suas colunas não podem ser descritas, ou quando a leitura das linhas de uma tabela falha — um arquivo gravado por uma versão do Access mais nova do que o leitor entende é a causa mais comum. Converta ou exporte o arquivo novamente a partir do Access e execute a importação outra vez.

Um arquivo cujas tabelas estão todas realmente vazias é importado com sucesso e emite um aviso informando que nenhum registro foi carregado.
