## Descrição

Importe arquivos de texto delimitado do PlaidCloud Document. Isso inclui, entre outros, os seguintes tipos de delimitador:
* vírgula (, )
* barra vertical (|)
* ponto e vírgula (; )
* tabulação
* espaço ( )
* arroba (@)
* til (~)
* dois-pontos (:)

### Inspecionar arquivo de origem selecionado

Ao pressionar o botão *Detectar configurações do arquivo de origem*, o PlaidCloud abre o arquivo e o inspeciona para tentar determinar o formato dos dados.  Verifique sempre
as configurações detectadas para confirmar que parecem corretas.

<Aside>Se um diretório de arquivos for selecionado para importação ou se a pesquisa for usada, o primeiro arquivo encontrado será usado na detecção</Aside>

Uma etapa cujo arquivo não retorna nenhuma coluna não pode ser salva: o salvamento é interrompido com **Nenhuma coluna detectada**. Quando o PlaidCloud não consegue ler o arquivo, a mensagem informa o motivo, por exemplo, uma extensão incomum para um arquivo delimitado ou um caminho de arquivo que usa uma variável de fluxo de trabalho não definida. Caso contrário, verifique se o delimitador e os caracteres de aspas e de escape correspondem ao arquivo, se ele é um arquivo de texto delimitado e se não está vazio.

### Formato dos dados

#### Delimitador
Como mencionado acima, **Inspecionar origem** tenta determinar o delimitador no arquivo de origem. Se você preferir outro delimitador, use esta
seção para especificá-lo. Os usuários podem escolher em uma lista de delimitadores padrão. Uma etapa sem delimitador definido usa vírgula.
* vírgula (, )
* barra vertical (|)
* ponto e vírgula (; )
* tabulação
* espaço ( )
* arroba (@)
* til (~)
* dois-pontos (:)

#### Tipo de cabeçalho

Como os arquivos CSV podem ou não conter cabeçalhos, o PlaidCloud oferece uma forma de usar os cabeçalhos, ignorá-los ou usar a ordem das colunas para determinar o alinhamento delas.
* **Sem cabeçalho**: o arquivo CSV não contém cabeçalho.  Use a lista de origem no *Data Mapper* para determinar o alinhamento das colunas
* **Com cabeçalho - usar cabeçalho e substituir lista de campos**: o arquivo CSV tem um cabeçalho.  Use os nomes de cabeçalho especificados e ignore a lista de origem no *Data Mapper*.
* **Com cabeçalho - ignorar cabeçalho e usar a lista de campos**: o arquivo CSV tem um cabeçalho, mas ele deve ser ignorado.  Use os nomes de cabeçalho especificados pela lista de origem no *Data Mapper*.

**Tipo de cabeçalho** é armazenado em `header_treatment` como `use` ou `skip` para as duas opções de cabeçalho. O Importar Excel também aceita `dynamic`.

#### Formato de data

Esta configuração é útil quando as datas contidas no arquivo CSV não são facilmente reconhecidas como datas e horas.  O processo de importação tenta converter as datas, mas um pouco de informação extra
pode ajudar nessa conversão.

Um valor que o warehouse não consegue ler com o formato informado é armazenado como vazio, sem interromper a importação; assim, um formato que não corresponde ao arquivo
produz uma coluna de datas vazias e uma importação que ainda informa sucesso. Depois de alterar esta configuração, confira a coluna importada antes de confiar no resultado.

<Aside type="caution" title="Colunas Hora no Lakehouse v2">
Uma coluna cujo tipo de dados é **Hora** é importada como vazia no Lakehouse v2, qualquer que seja o formato de data informado. A função do warehouse usada para interpretá-la não consegue
produzir um valor de hora do dia isolado. Importe a coluna como **Carimbo de data/hora** e leia a hora a partir dele, ou importe-a como **Texto**. As colunas **Data** e **Carimbo de data/hora**
não são afetadas.
</Aside>

### Caracteres especiais

As entradas de caracteres especiais controlam como o PlaidCloud trata a presença de determinados caracteres e o que eles significam no processamento do CSV
 * **Caractere de aspas**: é o caractere usado para indicar um conjunto de texto delimitado que deve ser processado como um único campo. Quando não definido, é aspas duplas (`"`).
 * **Caractere de escape**: é o caractere usado para indicar que o caractere seguinte deve ser processado como está, sem ser interpretado como caractere especial.  Útil quando um campo pode conter o delimitador. Quando não definido, é a barra invertida (`\`).
 * **Caractere nulo**: como os arquivos CSV não têm tipos de dados, este caractere permite indicar que o valor deve ser NULL, e não uma string vazia ou 0.
 * **Campos vazios**: um campo vazio é carregado como NULL em todos os lakehouses, tanto em colunas de texto quanto numéricas; portanto, um número em branco é NULL, e não 0. Uma célula que contém apenas espaços é carregada como está.
 * **Negativos à direita**: alguns sistemas de origem geram números negativos com o símbolo de negativo no final, em vez de no início.  Esta configuração processa esses valores como números negativos.

### Seleção de linhas

Para arquivos de entrada com registros estranhos, defina **Ignorar linhas** como o número de linhas a ignorar antes de processar os dados.  Isso é útil se os arquivos contêm blocos de cabeçalho que precisam ser ignorados antes de chegar aos dados tabulares.

As linhas ignoradas incluem linhas em branco. Com um **Tipo de cabeçalho** igual a **Com cabeçalho - usar cabeçalho e substituir lista de campos**, o cabeçalho é lido da primeira linha após as linhas ignoradas, de modo que os dados são mapeados para as colunas de destino pelo nome do cabeçalho. Um arquivo que contém apenas as linhas ignoradas e um cabeçalho, sem linhas de dados, não importa nada, e a etapa ainda assim é concluída.

#### Exemplo: exportação de lista do SAP

Uma exportação de lista do SAP, como KE24, KSB1 ou FAGLL03, começa com um bloco de seleção, muitas vezes com linhas em branco, antes do cabeçalho das colunas:

```text
Line Item Journal Entries
Company Code: 1000
Posting Date: 2026-09-01 to 2026-09-30

Company Code|Document Number|Posting Date|Amount
1000|100004512|2026-09-03|1,500.00
```

O cabeçalho está na linha 5, portanto há quatro linhas antes dele. Defina **Ignorar linhas** como `4` e **Tipo de cabeçalho** como **Com cabeçalho - usar cabeçalho e substituir lista de campos**. A importação lê `Company Code`, `Document Number`, `Posting Date` e `Amount` como nomes de coluna, e a primeira linha de dados é a linha seguinte ao cabeçalho.

Selecione **Keep Quoted Empty Fields ("") As Empty String** para carregar um campo vazio entre aspas como string vazia, em vez de NULL.

### Configurações adicionais

**Mais opções de CSV** contém estes campos:

* **Codificação** (`encoding`) — o codec Python com o qual o arquivo é lido, em vez de detectá-lo. Bytes que não podem ser decodificados são lidos como U+FFFD.
* **Delimitadores** (`delimiters`) — uma matriz JSON com todos os textos que separam colunas, em vez de um único delimitador. Cada um pode ter vários caracteres. Selecione **Vários delimitadores seguidos contam como um** (`combine_delimiters`) para contar vários delimitadores seguidos como um só.
* **Delimitador de linha** (`row_delimiter`) — o texto que encerra uma linha quando está fora de aspas; uma quebra de linha em outro lugar passa a fazer parte do valor. Se ficar em branco, qualquer quebra de linha encerra uma linha.
* **Prefixo de linha de comentário** (`comment`) — as linhas que começam com este texto não são importadas. **Comentários** (`comments`) lista comentários como pares **Começa com** e **Termina com**, que são removidos onde quer que estejam fora de aspas; sem **Termina com**, um comentário vai até o fim da linha.
* **Continuação de linha** (`line_continuation`) — este texto antes de uma quebra de linha une a linha à seguinte.
* **Aspa de fechamento** (`quote_end`) — a aspa que encerra um valor entre aspas, quando difere de **Caractere de aspas**. Selecione **Um valor entre aspas mantém as aspas** (`keep_quotes`) para manter as aspas de um valor entre aspas.
* **Importar uma linha vazia como uma linha de valores vazios** (`keep_blank_lines`) — uma linha vazia é importada como uma linha de valores vazios, em vez de ser omitida.
