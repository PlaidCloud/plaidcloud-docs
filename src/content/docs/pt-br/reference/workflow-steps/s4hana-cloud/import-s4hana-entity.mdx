## Descrição

Importa uma entidade do SAP S/4HANA Cloud para uma tabela de projeto por meio da sua [conexão do S/4HANA Cloud](/pt-br/guides/connections/s4hana-cloud/). Escolha a conexão, o tipo de entidade e os filtros desejados; a etapa busca os registros correspondentes e os grava, sem precisar escrever consultas OData.

Esta é uma etapa genérica pronta — um tipo de etapa cobre duas entidades: um cubo agregado `trial_balance` para relatórios de fim de período e `journal_entry_items`, em nível de item de linha, para transações lançadas detalhadas.

## Configuração

| Campo | Obrigatório | Observações |
|---|---|---|
| S/4HANA Connection | Sim | A conexão do S/4HANA Cloud usada para a leitura. |
| Tabela de destino | Sim | A tabela do projeto em que os resultados são gravados. Ela é totalmente sobrescrita a cada execução. |
| Tipo de entidade | Sim | Qual entidade importar. O padrão é `trial_balance`. Uma entre `trial_balance` e `journal_entry_items`. |
| Filtros | Não | Filtros de intervalo e de igualdade convertidos no `$filter` OData da solicitação. Cada entidade restringe os filtros aos campos que o S/4HANA consegue avaliar no servidor — um campo sem suporte é rejeitado, não descartado silenciosamente. |

### Entidades e Campos Filtráveis

| Tipo de entidade | O que importa | Serviço OData | Campos filtráveis |
|---|---|---|---|
| `trial_balance` | Saldos agregados de contas do razão geral no fim do período | `API_OPLACCTGDOCITEMCUBE_SRV` | `CompanyCode`, `GLAccount`, `CostCenter`, `ProfitCenter`, `FiscalYear` (intervalo), `FiscalPeriod` (intervalo), `Ledger` |
| `journal_entry_items` | Itens de linha de lançamentos contábeis efetivados | `API_JOURNALENTRYITEMBASIC_SRV` | `CompanyCode`, `GLAccount`, `CostCenter`, `ProfitCenter`, `PostingDate` (intervalo), `FiscalYear` (intervalo), `FiscalPeriod` (intervalo), `Ledger` |

<Aside type="note">
`PostingDate`, `FiscalYear` e `FiscalPeriod` aceitam filtros de **intervalo** (limites no estilo `ge`/`le`) — a principal forma de delimitar uma importação de `journal_entry_items`, já que uma importação sem limites do detalhe de itens de linha pode ser muito grande. Defina pelo menos um limite em uma entidade grande antes de executar com dados de produção.
</Aside>

<Aside type="caution">
`CostCenter` e `ProfitCenter` só podem ser filtrados quando o seu Communication Scenario os expõe. Uma dimensão que não faz parte desse cenário é rejeitada como filtro sem suporte, em vez de ser ignorada silenciosamente.
</Aside>
