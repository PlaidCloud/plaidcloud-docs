## Descrição

Importa um objeto do Sage Intacct para uma tabela de projeto por meio da sua [conexão Sage Intacct](/pt-br/guides/connections/sage-intacct/), usando as operações `readByQuery`/`readMore` do XML Gateway do Intacct para percorrer automaticamente todo o conjunto de resultados. Escolha a conexão, o objeto e os filtros desejados; a etapa busca os registros correspondentes e os grava, sem paginação manual para gerenciar.

Esta é uma etapa genérica pronta — um tipo de etapa cobre sete objetos, do detalhe de transações e saldos do razão geral (`GLDETAIL`, `GLACCOUNTBALANCE`, `GLENTRY`) aos cadastros mestres de dimensões (`LOCATION`, `DEPARTMENT`, `CLASS`) e documentos de pedidos (`SODOCUMENT`).

<Aside type="note">
Esta etapa é diferente de [Import Sage Intacct Query](/pt-br/reference/workflow-steps/sage-intacct/import-intacct-query/), que atende **qualquer** objeto do Intacct com um seletor de campos de uso geral. `Import Intacct Entity` é a etapa de catálogo nativo especificamente para estes sete objetos, com uma lista curada de filtros permitidos por objeto e paginação `readMore` automática para grandes conjuntos de resultados (o detalhe do razão geral, em particular, pode ultrapassar com folga uma única página da API do Intacct).
</Aside>

## Configuração

| Campo | Obrigatório | Observações |
|---|---|---|
| Conexão Sage | Sim | A conexão Sage Intacct usada para a leitura. |
| Tabela de destino | Sim | A tabela do projeto em que os resultados são gravados. Ela é totalmente sobrescrita a cada execução. |
| Object | Sim | Qual objeto do Intacct importar. Um entre `GLDETAIL`, `GLACCOUNTBALANCE`, `GLENTRY`, `LOCATION`, `DEPARTMENT`, `CLASS`, `SODOCUMENT`. |
| Filters | Não | Uma matriz de cláusulas `{field, operator, value}`. Os operadores incluem `eq`, `ne`, `gt`, `ge`, `lt`, `le`. Um intervalo é expresso como duas cláusulas no mesmo campo — uma `ge` e uma `le`. Cada objeto restringe os filtros à sua própria lista permitida de campos e operadores; uma combinação de campo ou operador sem suporte é rejeitada, não descartada silenciosamente. |

### Objetos e Filtros de Intervalo Típicos

| Objeto | O que importa | Filtros de intervalo comuns |
|---|---|---|
| `GLDETAIL` | Detalhe das linhas de transações do razão geral | data de lançamento (`ge`/`le`), valor (`ge`/`le`) |
| `GLACCOUNTBALANCE` | Saldos de contas por período | data de fim do período (`ge`/`le`) |
| `GLENTRY` | Linhas de lançamentos contábeis efetivados | data de lançamento (`ge`/`le`) |
| `LOCATION` | Cadastro mestre da dimensão de localização | — (somente filtros de igualdade) |
| `DEPARTMENT` | Cadastro mestre da dimensão de departamento | — (somente filtros de igualdade) |
| `CLASS` | Cadastro mestre da dimensão de classe | — (somente filtros de igualdade) |
| `SODOCUMENT` | Documentos de pedidos de venda | data do documento (`ge`/`le`) |

## Como a Paginação Funciona

O XML Gateway do Intacct retorna os resultados uma página por vez. Esta etapa emite a chamada inicial `readByQuery` e, em seguida, faz chamadas `readMore` usando o ID do conjunto de resultados retornado pelo Intacct, até que todas as páginas tenham sido lidas — assim, uma importação de `GLDETAIL` com dezenas de milhares de linhas é concluída em uma única execução da etapa, sem que você precise ajustar o tamanho da página.

<Aside type="caution">
Uma importação muito ampla e sem filtros de `GLDETAIL` ou `GLENTRY` ainda pode levar muito tempo para ser paginada por completo. Delimite uma importação grande com um intervalo de datas de lançamento em vez de depender apenas da paginação para torná-la rápida.
</Aside>
