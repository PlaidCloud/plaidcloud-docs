## Descrição


Exporte uma tabela de dados do Analyze para o PlaidCloud Document como um arquivo do Microsoft Excel. O PlaidCloud Analyze oferece suporte a versões modernas do Microsoft Excel (2007-2016) e também a versões legadas (2000/2003).



## Parâmetros de exportação

<SnippetCommonExportFileSelection />



### Nome da aba de destino
Especifique o nome da aba de destino. O padrão é ***Sheet1***


### Dividir

**Dividir** separa uma tabela em várias saídas de acordo com os valores de uma coluna:

* **Sem divisão** (padrão) — uma pasta de trabalho com a tabela na aba **Nome da aba de destino**.
* **Arquivos separados** — uma pasta de trabalho para cada valor distinto da coluna, com as linhas desse valor.
* **Planilhas separadas** — uma pasta de trabalho com uma aba para cada valor distinto, nomeada com o valor. **Nome da aba de destino** não é usado.

Defina **Dividir por coluna** como a coluna usada na divisão; ela deve ser uma coluna que a exportação grava. **Nomear cada arquivo por** define como Arquivos separados nomeia cada pasta de trabalho: **Sufixo do nome do arquivo** ou **Prefixo do nome do arquivo** adiciona o valor ao nome do arquivo, e **Nome do arquivo** usa o valor como o nome inteiro. Selecione **Manter a coluna de divisão na saída** para gravar também a coluna de divisão em cada saída.

Linhas cujo valor está em branco não são gravadas, e a etapa termina com um aviso. Planilhas separadas é interrompida, informando os valores, quando dois valores resultam no mesmo nome de aba.

### Selecionar a compactação do arquivo

Todos os arquivos exportados não são compactados, mas as seguintes opções de compactação estão disponíveis:

* Sem compactação
* Zip
* GZip
* BZip2

### Gravar o cabeçalho na primeira linha
Se esta caixa de seleção estiver marcada, os cabeçalhos da tabela serão exportados para a primeira linha. Se não estiver, o arquivo exportado não terá cabeçalhos.

### Se o arquivo existir

Em **Mais opções do Excel**, **Um arquivo que já existe** (`if_exists`) define o que acontece quando a pasta de trabalho já existe: `replace` (padrão) grava uma nova pasta de trabalho, `append` grava as linhas abaixo da última linha usada da aba, começando na coluna A, e `fail` interrompe a etapa sem gravar nada. Um append baixa a pasta de trabalho, adiciona as linhas e a envia novamente; por isso, quando duas execuções fazem append no mesmo arquivo ao mesmo tempo, vale a última a terminar. Selecione **Escrever o cabeçalho novamente abaixo das linhas existentes** (`header_on_append`) para gravar a linha de cabeçalho novamente abaixo das linhas já existentes.

### Configurações adicionais

**Mais opções do Excel** também contém estes campos:

* **Ordenar linhas por** (`sort_columns`) — ordena as linhas gravadas por estas colunas de origem, começando pela primeira chave, cada uma com as configurações **Coluna**, **Crescente** e **Nulos**. Uma coluna-chave não precisa ser gravada. **Nulos** assume o padrão primeiro em ordem crescente e último em ordem decrescente. Não é usado com **Resumir** ou **Distintos**.
* **Células ausentes como** (`null_as`) — texto gravado em cada célula ausente, inclusive nas colunas numéricas.
* **Uma planilha existente** (`if_sheet_exists`) — com **Escrever na pasta de trabalho existente, mantendo a formatação** (`preserve_format`) selecionado e uma pasta de trabalho que já tem a aba: **Falhar a etapa** (`fail`) interrompe a etapa e **Deixar como está** (`skip`) deixa essa aba como está. Por padrão, **Escrever os dados nela** grava os dados na aba.

## Limites de tamanho

Uma planilha do Excel comporta no máximo 1.048.576 linhas (a linha de cabeçalho conta
nesse total) e 16.384 colunas. Uma etapa que produziria mais que isso é interrompida
imediatamente e informa o motivo, em vez de gastar a exportação produzindo um arquivo
que o Excel se recusaria a abrir.

Exportações muito grandes também podem exceder o que o próprio formato de arquivo permite,
mesmo quando as contagens de linhas e colunas estão dentro do limite. Se isso acontecer, a etapa
informa que os dados da planilha são grandes demais.

Para dados acima desses tamanhos, exporte para CSV ou Parquet — nenhum dos dois tem limite
de linhas, e ambos são bem mais rápidos de gerar e menores para armazenar.
