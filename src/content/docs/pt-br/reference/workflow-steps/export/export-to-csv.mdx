## Descrição



Grava uma tabela de projeto do PlaidCloud em uma conta de documentos como um arquivo CSV (valores separados por vírgula). É o formato de exportação mais comum, aceito por praticamente todos os sistemas posteriores, ferramentas de planilha e plataformas de BI.

Configurável: delimitador (vírgula, tabulação, barra vertical, personalizado), comportamento de aspas, linha de cabeçalho e codificação.

### Selecionando a compactação do arquivo

Todos os arquivos exportados são não compactados, mas as seguintes opções de compactação estão disponíveis:

* Sem compactação
* Zip
* GZip
* BZip2



### Formato dos dados

![Formato de dados do Exportar CSV](/images/export_file_csv_data_format.png)



#### Delimitador
A transformação Exportar CSV é usada para exportar tabelas de dados para arquivos de texto delimitados salvos no PlaidCloud Document. Isso inclui, entre outros, os seguintes tipos de delimitador:


* CSV do Excel (separado por vírgula)
* TSV do Excel (separado por tabulação)
* Separador definido pelo usuário –>


	+ vírgula (,)
	+ barra vertical (|)
	+ ponto e vírgula (;)
	+ tabulação
	+ espaço ( )
	+ outro/personalizado (til, hífen etc.)

Para especificar um delimitador personalizado, selecione **Separador definido pelo usuário –>** e depois **Outro –>**, e digite o delimitador personalizado na caixa de texto.


#### Caracteres especiais

A seção **Caracteres especiais** permite especificar como tratar dados com aspas e caracteres de escape. Escolha entre as seguintes configurações:

* Caracteres especiais (QUOTE_MINIMAL): coloca entre aspas os campos com caracteres especiais (qualquer coisa que confundiria um analisador configurado com o mesmo dialeto e as mesmas opções). Esta é a configuração padrão.
* Todos (QUOTE_ALL): coloca tudo entre aspas, independentemente do tipo.
* Não numéricos (QUOTE_NONNUMERIC): coloca entre aspas todos os campos que não são inteiros nem números de ponto flutuante. Quando usado com o leitor, os campos de entrada sem aspas são convertidos em números de ponto flutuante.
* Nenhum (QUOTE_NONE): não coloca nada entre aspas na saída. Os caracteres de aspas são incluídos na saída com o caractere de escape fornecido pelo usuário. Observe que apenas um único caractere de escape pode ser fornecido.

Por padrão, uma aspa dentro de um campo entre aspas é gravada em dobro (`""`). Ative `escape_quotes` para gravá-la com o caractere de escape, como o Spark faz: com `\` como caractere de escape, o campo `say "hi"` é gravado como `"say \"hi\""`. A configuração vem desativada por padrão, portanto as exportações existentes não mudam. 

Por padrão, um valor que contém o caractere de aspas é colocado entre aspas só por esse motivo. Desmarque **Colocar entre aspas os valores que contêm o caractere de aspas** para gravar esse valor sem aspas ao redor, como o Spark faz com `escapeQuotes` desativado; um valor que contém o delimitador ou uma quebra de linha continua entre aspas. A caixa de seleção vem marcada por padrão. Desmarcada, o arquivo é gravado pelo PlaidCloud e não pelo warehouse.

Deixe o **Caractere de aspas** vazio para gravar cada valor exatamente como está: nada é colocado entre aspas e nada recebe escape. Um valor que contém o delimitador ou uma quebra de linha passa então a ser lido como mais campos, portanto escolha um delimitador que seus dados não contenham.

#### Escrever o cabeçalho na primeira linha
Se esta caixa de seleção estiver marcada, os cabeçalhos da tabela são exportados na primeira linha. Se não estiver, o arquivo exportado não terá cabeçalhos.

#### Incluir tipos de dados nos cabeçalhos
Se esta caixa de seleção estiver marcada, os cabeçalhos do arquivo exportado conterão o tipo de dados da coluna.

#### Fins de linha do Windows

Por fim, a caixa de seleção **Usar fins de linha compatíveis com o Windows** vem marcada por padrão para garantir a compatibilidade com sistemas Windows. É recomendável deixar esta configuração ativada, a menos que você trabalhe em um ambiente exclusivamente Unix.




### Se o arquivo existir

Em **Mais opções de CSV**, **Um arquivo que já existe** (`if_exists`) decide o que acontece quando o arquivo já está lá: `replace` (padrão) grava um novo arquivo, `append` adiciona as linhas ao final do arquivo existente sem linha de cabeçalho e `fail` interrompe a etapa, sem gravar nada. Um append baixa o arquivo, adiciona as linhas e o envia novamente, portanto, quando duas execuções fazem append no mesmo arquivo ao mesmo tempo, vale a última a terminar. Com `append`, marque **Escrever o cabeçalho novamente abaixo das linhas existentes** (`header_on_append`) para gravar a linha de cabeçalho novamente abaixo das linhas já existentes.

### Configurações adicionais

**Mais opções de CSV** também contém estes campos:

* **Ordenar linhas por** (`sort_columns`) — ordena as linhas gravadas por estas colunas de origem, a primeira chave primeiro, cada uma com uma configuração de **Coluna**, **Crescente** e **Nulos**. Uma coluna de chave não precisa ser gravada. **Nulos** assume por padrão primeiro em ordem crescente e por último em ordem decrescente. Não é usada com **Resumir** ou **Distintos**.
* **Fim de linha** (`line_ending`) — o fim de linha de todas as linhas, `\n`, `\r\n` ou `\r`, no lugar de **Usar fins de linha compatíveis com o Windows**.
* **Colocar entre aspas** (`quote_mode`) — quais valores recebem aspas: **Nunca**, **Sempre**, **Todos os valores exceto números e booleanos** ou **Um valor que contém o delimitador**. Por padrão, um valor recebe aspas quando necessário.
* **Aspa de fechamento** (`quote_end`) — a aspa de fechamento, quando difere da aspa de abertura.
* **Aspa de fechamento dentro de um valor** (`quote_replacement`) — gravada no lugar de uma aspa de fechamento dentro de um valor entre aspas. Se vazia, a aspa é duplicada.
* **Delimitador dentro de um valor** (`delimiter_replacement`) — com **Colocar entre aspas** definido como **Nunca**, gravado no lugar do delimitador dentro de um valor.
* **Iniciar o arquivo com uma marca de ordem de bytes** (`write_bom`) — inicia o arquivo com uma marca de ordem de bytes.
* **Separador decimal** (`decimal_separator`) — o caractere gravado para a vírgula decimal de um número.
* **Linhas antes do cabeçalho** (`comment_lines`) — uma matriz JSON de linhas gravadas como estão antes do cabeçalho.
* **Gravar números decimais como o Java** (`scientific_numbers`) — grava um número decimal em notação científica a partir de 10 milhões e abaixo de 0,001, como `1.0E10`.
* **Escrever cada nome de arquivo como indicado, sem adicionar .csv ou .tsv** (`keep_file_extension`) — grava cada nome de arquivo exatamente como indicado.
* **Com gzip, salvar o arquivo com o nome indicado, sem adicionar .gz** (`exact_file_name`) — com compactação gzip, salva o arquivo com o nome indicado.
