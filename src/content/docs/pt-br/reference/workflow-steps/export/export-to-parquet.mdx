## Descrição

Grava uma tabela de projeto em uma conta de documentos como um arquivo [Apache Parquet](https://parquet.apache.org/). O Parquet armazena os dados por coluna, e não por linha; por isso compacta muito melhor que o CSV em tabelas largas e permite que um leitor downstream carregue apenas as colunas de que precisa.

Em geral, é a escolha certa para entregar tabelas grandes a uma plataforma de dados em nuvem ou a um fluxo de trabalho de ciência de dados. Os tipos — inteiros, decimais, datas e carimbos de data/hora — são preservados, e uma coluna de números inteiros continua sendo uma coluna de inteiros mesmo quando alguns de seus valores estão em branco. Use-a em conjunto com [Importar Parquet](/pt-br/reference/workflow-steps/import/import-parquet/).

## Itens de configuração exclusivos

### Compactação

O Parquet compacta por bloco de coluna:

* **Snappy** — leitura mais rápida, tamanho de arquivo moderado
* **Zstandard** — arquivos menores, exige um leitor com Zstandard 0.8 ou posterior

### Prefixo do arquivo de destino

Quando a etapa exporta uma tabela para um único arquivo e o valor já termina em `.parquet`, como `Loadfile1.parquet`, o arquivo é gravado exatamente com esse nome. Caso contrário, o valor é um prefixo: cada tabela é gravada como `<prefix><table name>.parquet`.

### Um arquivo por tabela

As exportações em Parquet gravam um arquivo para cada tabela. Escolher gravar vários arquivos é recusado, com uma mensagem informando isso; desmarque essa opção para executar a exportação.

### Se o arquivo existir

**Um arquivo que já existe** (`if_exists`), em **Se o arquivo existir**, na página **Parâmetros do arquivo**:

* **Sobrescrevê-lo** (`overwrite`, padrão) substitui um arquivo que já existe.
* **Fazer a etapa falhar sem gravar nada** (`fail`) interrompe a etapa, sem gravar nada, quando um arquivo que ela gravaria já existe.
