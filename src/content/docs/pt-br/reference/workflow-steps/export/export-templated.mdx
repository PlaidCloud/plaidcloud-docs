## Descrição

Renderiza tabelas de projeto por meio de um modelo para produzir um documento estruturado, em vez do despejo bruto de colunas que as outras etapas de exportação gravam. Use-a quando o sistema receptor exigir um formato XML específico, ou outro formato de texto, em vez de uma tabela.

## Itens de configuração exclusivos

### Modelo de origem

O modelo Jinja a partir do qual a saída é renderizada. Consulte [O que um modelo pode usar](#o-que-um-modelo-pode-usar).

### Saída de destino

A conta de documentos, a pasta e o nome do arquivo do resultado renderizado. O modelo decide o que o arquivo contém; um nome de arquivo sem extensão recebe `.xml`.

**Usar DataFrames do Pandas para os dados da tabela** muda a forma como as linhas de cada origem chegam ao modelo. Consulte [Linhas de origem como tabela](#linhas-de-origem-como-tabela).

### Tabela de origem

Indique as tabelas explicitamente ou encontre-as por caminho e uma regra de pesquisa: exata, começa com, termina com, contém ou glob.

## O que um modelo pode usar

O modelo é renderizado em um sandbox: ele lê os dados que a etapa fornece e nada mais.

- **Cada origem, pelo seu Nome.** Toda tabela de origem que você lista fica disponível ao modelo pelo **Nome** que você der a ela, portanto use um nome que funcione como variável, como `invoices`.
- **As variáveis do fluxo de trabalho**, como `variable`, por exemplo `{{ variable.region }}`.

```jinja
<Invoices>
{% for row in invoices %}
  <Invoice id="{{ row.invoice_id }}" amount="{{ row.amount }}" />
{% endfor %}
</Invoices>
```

### Linhas de origem como lista

Com **Usar DataFrames do Pandas para os dados da tabela** desativado, uma origem é uma lista somente leitura de linhas. Percorra-a em um laço ou use `|length`, `keys()`, `first()`, `one()`, `all()`, `scalar()`, `scalars()`, `mappings()`, `fetchmany(n)` e `columns('a', 'b')`. Leia um valor de uma linha como `row.amount`, `row['amount']` ou `row[0]`; `row._mapping`, `row._asdict()` e `row._fields` também funcionam. As linhas de `columns('a', 'b')` aceitam `row.amount` ou `row[0]`, não `row['amount']`.

### Linhas de origem como tabela

Com **Usar DataFrames do Pandas para os dados da tabela** ativado, uma origem é uma tabela somente leitura. Percorrê-la em um laço fornece cada linha como um dicionário, então `row.amount` e `row['amount']` funcionam. Você também pode usar:

- `columns`, `empty`, `shape`, `values` e `index`
- `head(n)` e `tail(n)`
- `itertuples()`, que coloca a posição da linha primeiro como `Index`, então `r[1]` é a primeira coluna; `itertuples(index=False)` a omite
- `iterrows()`, que fornece a posição da linha e a linha
- `invoices['amount']`, os valores de uma coluna, com `sum()`, `min()`, `max()`, `mean()`, `unique()` e `tolist()`; `sum`, `min`, `max` e `mean` ignoram nulos

Outros métodos do pandas, como `loc` e `groupby`, não estão disponíveis. Dê forma aos dados em uma etapa anterior e exporte o resultado.

### O que um modelo não pode fazer

- Chamar um método cujo nome comece com `to_`, em qualquer valor: `to_csv` e `to_json`, e também os inofensivos, como `to_pydatetime`.
- Ler um atributo cujo nome comece com sublinhado, exceto `_mapping`, `_asdict` e `_fields` de uma linha.
- Gravar ou abrir arquivos.

Uma chamada `to_` ou uma operação com arquivo faz a etapa falhar. Um atributo com sublinhado diferente desses três simplesmente é renderizado como nada.
