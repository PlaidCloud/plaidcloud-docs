## Descrição


Exporte uma tabela de dados do Analyze para o PlaidCloud Document como um arquivo JSON. Há várias opções (mostradas abaixo) para a orientação dos dados.



Para saber mais sobre arquivos JSON, consulte o site oficial do JSON: http://json.org/.


<Aside>Arquivos JSON *não* mantêm a ordem das colunas. A ordem das colunas na tabela de dados de origem não é necessariamente a mesma do arquivo exportado.</Aside>

### Orientação do JSON


Considere o seguinte conjunto de dados:




| ID |  Name  | Gender | State |
|----|--------|--------|-------|
| 1  | Jack   |   M    |   MO  |
| 2  | Jill   |   F    |   MO  |
| 3  | George |   M    |   VA  |
| 4  | Abe    |   M    |   KY  |

Arquivos JSON podem ser exportados em um dos quatro formatos de dados:


* Records: os dados são armazenados em dicionários Python, com cada linha no formato \{Coluna -> Valor, …}. Por exemplo: **[\{“ID”:1,”Name”:”Jack”,”Gender”:”M”,”State”:”MO”},\{“ID”:2,”Name”:”Jill”,”Gender”:”F”,”State”:”MO”},\{“ID”:3,”Name”:”George”,”Gender”:”M”,”State”:”VA”},\{“ID”:4,”Name”:”Abe”,”Gender”:”M”,”State”:”KY”}]**
* Index: os dados são armazenados em dicionários Python aninhados, com cada linha no formato \{Índice -> \{Coluna -> Valor, …},…}. Por exemplo: **\{“0”:\{“ID”:1,”Name”:”Jack”,”Gender”:”M”,”State”:”MO”},”1”:\{“ID”:2,”Name”:”Jill”,”Gender”:”F”,”State”:”MO”},”2”:\{“ID”:3,”Name”:”George”,”Gender”:”M”,”State”:”VA”},”3”:\{“ID”:4,”Name”:”Abe”,”Gender”:”M”,”State”:”KY”}}**
* Split: os dados são armazenados em um único dicionário Python, com os valores em listas. Por exemplo: **\{“columns”:[“ID”,”Name”,”Gender”,”State”],”index”:[0,1,2,3],”data”:[[1,”Jack”,”M”,”MO”],[2,”Jill”,”F”,”MO”],[3,”George”,”M”,”VA”],[4,”Abe”,”M”,”KY”]]}**
* Values: os dados são armazenados em várias listas Python. Por exemplo: **[[1,”Jack”,”M”,”MO”],[2,”Jill”,”F”,”MO”],[3,”George”,”M”,”VA”],[4,”Abe”,”M”,”KY”]]**


### Tratamento de datas


Especifique o **Formato de data** usando o menu suspenso. Escolha entre os seguintes formatos:


* **Epoch (Unix Timestamp – Seconds since 1/1/1970)**
* **ISO 8601 Format (YYYY-MM-DD HH:MM:SS with timeproject offset)**

Especifique a **Unidade de data** usando o menu suspenso. Escolha entre os seguintes formatos, listados em ordem crescente de precisão:


* **Segundos (s)**
* **Milissegundos (ms)**
* **Microssegundos (us)**
* **Nanossegundos (ns)**

### Forçar ASCII


Marque esta caixa de seleção para garantir que todas as strings sejam codificadas em ASCII válido. Ela vem habilitada por padrão.



### Tipo de arquivo de saída


Todos os arquivos exportados não são compactados, mas as seguintes opções de compactação estão disponíveis:


* Zip
* GZip
* BZip2


### Configurações adicionais

* **Um arquivo que já existe** (`if_exists`), em **Se o arquivo existir** — **Sobrescrevê-lo** (`overwrite`, padrão) substitui um arquivo que já existe; **Fazer a etapa falhar sem gravar nada** (`fail`) interrompe a etapa, sem gravar nada, quando um arquivo que ela gravaria já existe.
* **Ordenar linhas por** (`sort_columns`), em **Ordem das linhas** — ordena as linhas gravadas por estas colunas de origem, começando pela primeira chave, cada uma com as configurações **Coluna**, **Crescente** e **Nulos**. Uma coluna-chave não precisa ser gravada. **Nulos** assume o padrão primeiro em ordem crescente e último em ordem decrescente. Não é usado com **Resumir** ou **Distintos**.
