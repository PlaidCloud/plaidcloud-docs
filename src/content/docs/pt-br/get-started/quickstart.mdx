## O que você vai criar

Um pequeno fluxo de trabalho que:

1. Importa um CSV para uma tabela de projeto
2. Filtra e transforma os dados com algumas etapas
3. Publica o resultado para que outras ferramentas possam consumi-lo

<Aside>
Este passo a passo é propositalmente leve: é um tour pelas peças principais, não um aprofundamento. Quando terminar, a página [Conceitos](/pt-br/get-started/concepts/) explica *por que* as coisas são organizadas dessa forma, e a seção [Guias](/pt-br/guides/) aborda cada tarefa em detalhes.
</Aside>

## Comece com o projeto de exemplo

Se você prefere ver um resultado pronto antes de criar o seu, use o atalho. Em um espaço de trabalho novo, aparece um botão **Carregar exemplo**. Se o seu espaço de trabalho oferecer mais de um exemplo guiado, você primeiro escolhe qual carregar em uma lista curta:

- **Retail Sales Analysis** — varejo e vendas
- **Campaign Performance by Channel** — marketing
- **Inventory Status Report** — cadeia de suprimentos e operações
- **Budget vs Actual by Department** — finanças

Cada um é um conjunto de dados pequeno e realista, criado inteiramente com as etapas de transformação low-code do PlaidCloud, sem SQL escrito à mão, para que você possa abrir o fluxo de trabalho pronto depois e ver exatamente como ele funciona. Escolha um (ou, se houver apenas um exemplo disponível, o PlaidCloud o carrega diretamente), e o PlaidCloud cria o projeto e executa o fluxo de trabalho, mostrando cada fase à medida que avança — **Importing** de um arquivo, **Cleaning**, ramificação em alguns resumos paralelos e, por fim, combinação deles em uma única tabela de resultado — antes de abrir o resultado para você. Quando a execução termina, o PlaidCloud também publica a tabela de resultado para geração de relatórios e cria um painel a partir dela automaticamente: um resumo de KPIs, uma tendência ao longo do tempo, um detalhamento pela categoria principal do exemplo e, nos exemplos de varejo e de estoque, um detalhamento por estado dos EUA. A primeira execução leva cerca de um minuto enquanto o data warehouse é aquecido; todas as seguintes são quase instantâneas, e a tela avisa isso para que a espera não seja uma surpresa. Você chega a um primeiro resultado real e a um painel pronto em poucos minutos, sem construir nada, e cada peça criada é sua para abrir, alterar e executar novamente. Se o carregamento ou a execução do exemplo encontrar um problema, o PlaidCloud avisa você e oferece tentar novamente.

O projeto de exemplo, o fluxo de trabalho e cada painel que ele cria são compartilhados com todo o espaço de trabalho no momento em que são criados: um colega com acesso de Visualizador vê o mesmo exemplo pronto que você, sem nenhuma etapa de compartilhamento separada.

Toda tela vazia também orienta você para a próxima etapa, em vez de deixá-lo diante de uma grade em branco. **Projetos**, **Fluxos de trabalho**, **Tabelas**, **Conexões** e **Painéis** recebem você com uma breve explicação e uma ação principal — **Novo projeto**, **Novo fluxo de trabalho**, **Importar pacote de tabelas** e assim por diante — para que sempre haja um caminho óbvio a seguir. Um link **Precisa de ajuda?** nessas telas e no painel de boas-vindas leva você direto ao suporte se tiver dificuldades. Se você foi adicionado a um espaço de trabalho como Visualizador, essas telas explicam o que você está vendo sem oferecer ações que você não pode executar. E se um Visualizador chega a um espaço de trabalho que ainda não tem conteúdo visível, uma tela de boas-vindas apresenta uma breve introdução prática, um tour guiado pelo aplicativo e acesso rápido à ajuda, para que sempre haja um próximo passo.

Essa primeira execução guiada aparece em todo espaço de trabalho novo, em todos os planos. Se você já conhece o aplicativo, escolha **Dispensar** no painel de boas-vindas — uma confirmação rápida lembra que a orientação continua disponível — e ele sai do caminho. Para trazê-lo de volta a qualquer momento, abra o menu do usuário no canto superior direito e escolha **Reiniciar introdução**.

## Comece com seu próprio CSV

Para começar com seus próprios dados em vez de um exemplo, escolha **Traga seus próprios dados**. A opção fica ao lado de **Carregar exemplo** em uma tela **Projetos** vazia, e a Home também a oferece. Você precisa de permissão para criar projetos e tabelas e para gravar no armazenamento de documentos para vê-la. Quando você já tiver projetos, **Novo** > **Projeto a partir de arquivo CSV** na tela **Projetos** abre a mesma janela e, para adicionar um CSV a um projeto que você já tem, consulte [Importar um arquivo CSV](/pt-br/guides/projects/managing-tables-and-views/#importar-um-arquivo-csv).

Solte um arquivo CSV na caixa ou escolha **Escolher um arquivo CSV** para selecionar um; somente arquivos terminados em `.csv` são aceitos. O PlaidCloud envia o arquivo para o seu **Personal Temp Drive** ou, se você não tiver um, para o **Temp Drive** do espaço de trabalho, cria um projeto com o nome do arquivo, importa-o para uma tabela com o nome do arquivo — `Sales Data.csv` vira o projeto **Sales Data** com a tabela `sales_data` — e abre a lista de **Tabelas** do novo projeto. Um painel **Próximo passo sugerido** é aberto e, depois que o PlaidCloud faz uma primeira análise da tabela, ele passa a ser **Seus dados em resumo**, mostrando quantas linhas a tabela tem e, para as seis primeiras colunas, o tipo de cada coluna, a parcela de seus valores que estão vazios e quantos valores distintos ela contém.

Abaixo há um gráfico de barras inicial. Suas barras são os valores de uma coluna com uma lista curta de valores repetidos, como uma região, e cada barra soma ou calcula a média de uma coluna numérica para esse valor, ou conta suas linhas. Quando há mais de um gráfico sensato a desenhar, a IA do PlaidCloud escolhe um e lhe dá um título; ela vê apenas os nomes, tipos e contagens das colunas, nunca um valor do seu arquivo. Se nenhuma coluna tiver uma lista curta de valores repetidos, o painel informa que não há gráfico inicial.

Quando os relatórios estão ativados e você tem permissão para publicar tabelas, o PlaidCloud também publica a tabela para geração de relatórios e cria um painel inicial a partir do gráfico, e **Abrir painel** o abre em uma nova guia. Os gráficos do painel recebem o nome das colunas que exibem, como "Total revenue by region"; o título da IA aparece apenas no gráfico do painel de passo sugerido. Como qualquer painel novo, ele começa visível para todos no projeto; consulte [Controlar quem pode ver um painel](/pt-br/guides/dashboards/control-who-can-see-a-dashboard/) para alterar isso.

O painel também oferece **Limpar estes dados** ou **Resumir estes dados**, cada um abrindo uma etapa pronta para revisão, ou **Agora não** para ignorar.

Se a importação falhar, o PlaidCloud remove o projeto que acabou de criar e informa o que deu errado. O PlaidCloud exclui o arquivo enviado do drive temporário assim que a importação termina, com ou sem sucesso; se isso não acontecer, o drive temporário o exclui após um dia. Se o espaço de trabalho não tiver um drive temporário, a janela informa que não há onde armazenar seu arquivo, e um administrador do espaço de trabalho precisa entrar em contato com o suporte.

## Acompanhe seu progresso na Home

Quando você está dentro de um espaço de trabalho, a Home mostra um cartão **Primeiros passos** que acompanha sua configuração etapa por etapa, com um medidor de progresso ("N de M") integrado. O que você vê depende da sua função: administradores têm cinco etapas — experimentar o exemplo, conectar seus dados, criar seu primeiro fluxo de trabalho, publicar um painel e convidar sua equipe; construtores têm três — experimentar o exemplo, criar seu primeiro fluxo de trabalho e publicar um painel; visualizadores não veem o cartão.

O cartão sempre apresenta como ação principal o que você ainda não fez, e cada uma das outras etapas restantes é uma linha clicável que leva você direto até ela. Uma etapa concluída é marcada definitivamente — nunca é desmarcada — e as etapas concluídas são recolhidas para que o cartão fique focado no que falta.

<Aside>
"Publicar um painel" só conta um painel que você mesmo publicou — se um colega publicar um, sua caixa não é marcada.
</Aside>

Se você prefere não ver o cartão, escolha **Ocultar** e ele é recolhido em um pequeno botão "Primeiros passos · N/M" na barra de ferramentas; clique nesse botão a qualquer momento para trazer o cartão completo de volta. **Reiniciar introdução** no menu do usuário também o traz de volta. Para desativar a introdução por completo, use **Dispensar a introdução?**; ela permanece desativada até você escolher **Reiniciar introdução**.

Conclua todas as etapas e o cartão se aposenta sozinho: ele desaparece da Home e uma única mensagem de comemoração "Tudo pronto" recebe você — uma vez por espaço de trabalho, não importa quantos dispositivos ou navegadores você use para chegar lá.

Seu progresso, o estado oculto ou visível do cartão, os tours, as dicas e tudo o que você dispensou na Home acompanham a sua conta, e não o seu navegador. Entre de um novo dispositivo, de outro navegador ou de uma janela anônima e você continua de onde parou, em vez de recomeçar.

O restante deste início rápido cria o mesmo tipo de fluxo de trabalho manualmente, para que você veja cada peça em funcionamento.

## 1. Abra um projeto

Depois de entrar, você chega ao seu espaço de trabalho. Abra a guia **Projetos** e crie um novo projeto — dê a ele um nome descritivo, como "Quickstart". Um projeto é onde seus dados, fluxos de trabalho e dimensões ficam juntos.

Consulte [Gerenciamento de projetos](/pt-br/guides/projects/managing-projects/) para saber mais sobre o ciclo de vida de um projeto.

## 2. Importe um CSV

Dentro do projeto, abra a guia **Fluxos de trabalho** e crie um novo fluxo de trabalho. Adicione uma etapa **Importar → CSV**. Envie um pequeno CSV do seu computador ou aponte para um CSV em um repositório de documentos conectado.

Execute essa etapa. O CSV chega como uma tabela no seu projeto. Abra a guia **Tabelas** para vê-la.

Referência: [Etapa Import CSV](/pt-br/reference/workflow-steps/import/import-csv/) · Guia: [Onde ficam os fluxos de trabalho?](/pt-br/guides/workflows/where-are-workflows/)

## 3. Adicione uma etapa de transformação

De volta ao fluxo de trabalho, adicione uma etapa **Tabelas → Table Lookup** (ou qualquer uma das etapas de tabela). Configure a origem e o destino, escolha quais colunas manter e aplique um filtro simples.

Ao executar a etapa, a saída é uma nova tabela que você pode visualizar.

Referência: [Etapas de fluxo de trabalho](/pt-br/reference/workflow-steps/)

## 4. Publique o resultado

Adicione uma etapa final **Publicar** (em **Dados → Publicar**) para que a tabela fique disponível para painéis, ferramentas de BI ou consumidores externos.

Guia: [Publicação de dados](/pt-br/guides/data/publish/)

## 5. Execute o fluxo de trabalho inteiro

Clique em **Executar** no fluxo de trabalho. Acompanhe o log à medida que cada etapa é executada. Se algo der erro, o guia [Gerenciamento de erros de etapas](/pt-br/guides/workflows/managing-step-errors/) aborda a depuração.

- **Crie algo real** — os [Tutoriais](/pt-br/get-started/tutorials/) percorrem cenários completos (carregar e transformar dados, criar uma alocação, publicar um painel).
- **Navegue por tarefa** — os [Guias](/pt-br/guides/) abordam tarefas específicas que você talvez queira realizar.
- **Consulte algo** — a [Referência](/pt-br/reference/) tem todas as etapas de fluxo de trabalho, expressões e conectores.
