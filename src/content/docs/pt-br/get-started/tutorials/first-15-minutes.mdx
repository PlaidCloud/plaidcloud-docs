*~15 minutos · entre, oriente-se, execute seu primeiro exemplo*

Esta é a sessão que todos os outros tutoriais pressupõem que você já teve. Você vai entrar, aprender onde ficam os projetos, fluxos de trabalho, dados e painéis e, em seguida, abrir um fluxo de trabalho pronto, executá-lo e ver um resultado sair do outro lado. Nada de construir do zero ainda — isso é o [Início rápido](/pt-br/get-started/quickstart/), que esta página complementa. Pense nisto como o mapa antes da viagem.

> **Você vai precisar de um espaço de trabalho.** Se não tiver um, [inicie uma avaliação gratuita](https://app.plaidcloud.com) — ela provisiona um espaço de trabalho em poucos minutos. Tudo o que vem a seguir acontece dentro dele.

## Como o PlaidCloud é organizado

Três palavras explicam quase tudo o que você verá. Sua conta vive em uma **organização** (o limite de cobrança e de identidade). Dentro dela há um ou mais **espaços de trabalho** — ambientes isolados onde o trabalho realmente acontece. Dentro de um espaço de trabalho ficam os **projetos**, e cada projeto é dono de suas próprias tabelas, fluxos de trabalho, dimensões e histórico. Os projetos não compartilham estado entre si.

O modelo de dados completo — conexões, visões, dimensões, alocações — está descrito em [Conceitos](/pt-br/get-started/concepts/). Você não precisa de tudo hoje; as três palavras acima bastam para se orientar.

## Etapa 1: entre e conheça o Iniciador

Abra a URL do seu espaço de trabalho (algo como `https://acme.plaid.cloud`) e entre — a URL exata está no seu e-mail de boas-vindas ou de avaliação e também na página da sua organização. A primeira coisa que você vê é o **Iniciador** — uma página única de blocos que reúne o que você mais usa para que você retome de onde parou. A partir daqui, **Analisar** é a área do aplicativo onde ficam seus projetos, fluxos de trabalho, tabelas e painéis; você passará a maior parte desta sessão nela.

O Iniciador é organizado em três faixas, de cima para baixo. Uma faixa só aparece quando tem algo a mostrar:

| Faixa | O que ela contém |
|---|---|
| **Requer atenção** | Fluxos de trabalho cuja execução mais recente falhou — os problemas aparecem assim que você chega |
| **Pinned** | Tudo o que você marcou com estrela como favorito, na ordem em que fixou |
| **Recentes** | Projetos, painéis e aplicativos Panel que você abriu ou editou recentemente |

Em um espaço de trabalho novo, essas faixas ficam quase vazias — isso é esperado. Conforme você trabalha, elas se preenchem. Os detalhes completos estão no [guia do Iniciador](/pt-br/guides/launcher/).

> **Dois atalhos que valem a pena aprender agora.** Pressione **Ctrl/Cmd-K** em qualquer tela para abrir a paleta de comandos: ela lista o que você abriu por último e as ações disponíveis e, conforme você digita, pesquisa também projetos, fluxos de trabalho, tabelas, painéis e aplicativos Panel. Clique na **estrela** de qualquer cartão para fixá-lo na faixa **Pinned**, para que ele nunca saia do seu alcance.

## Etapa 2: oriente-se — onde as coisas ficam

Tudo no PlaidCloud vive dentro de um projeto, e um projeto apresenta seu conteúdo em guias. Você vai voltar a elas o tempo todo:

| Onde | O que você encontra |
|---|---|
| **Projetos** | Todos os projetos do espaço de trabalho; abra um para trabalhar dentro dele |
| **Fluxos de trabalho** | Os pipelines que importam, transformam e publicam dados |
| **Tabelas** | Os dados estruturados — linhas e colunas — que os fluxos de trabalho leem e gravam |
| **Painéis** | Visões interativas publicadas, construídas a partir de tabelas |
| **AI Assistant** | Um chat no escopo do projeto para fazer perguntas sobre seus dados e fluxos de trabalho |

O modelo mental para levar adiante: um **fluxo de trabalho** é uma sequência de **etapas**; cada etapa lê de uma ou mais **tabelas** de origem e grava em uma tabela de destino — deixando os originais intactos. Um **painel** lê as tabelas que um fluxo de trabalho publica. Esse é o ciclo que você verá repetidas vezes.

## Etapa 3: abra um exemplo pronto

Em vez de construir qualquer coisa agora, abra algo que já funciona e veja-o em ação.

1. No **Iniciador** ou em **Analisar → Projetos**, abra um projeto. Se o seu espaço de trabalho de avaliação veio com um projeto de exemplo, abra esse — se a guia **Projetos** estiver vazia, nenhum foi incluído; então percorra o [Início rápido](/pt-br/get-started/quickstart/) uma vez para criar um pequeno projeto e fluxo de trabalho e depois volte aqui. O restante desta página funciona do mesmo jeito nos dois casos.
2. Vá para a guia **Fluxos de trabalho** dentro do projeto.
3. Clique duas vezes em um fluxo de trabalho para abrir o **Workflow Explorer**. Você verá as etapas dispostas em ordem — importações à esquerda, transformações e publicações fluindo para a direita.
4. Clique em uma única etapa para ver como ela está configurada: a tabela de origem, a tabela de destino e as opções. Você não precisa alterar nada — está lendo, não editando.

> **Ler antes de executar é um bom hábito.** Dar uma olhada nas etapas de um fluxo de trabalho antes de executá-lo mostra quais tabelas ele vai tocar e o que vai produzir — assim o resultado não será uma surpresa.

## Etapa 4: execute e veja um resultado

Agora faça com que ele faça alguma coisa.

1. No Workflow Explorer, clique em **Executar** para o fluxo de trabalho inteiro (não apenas uma etapa).
2. Acompanhe o **log** enquanto cada etapa é executada em ordem. Cada linha informa qual etapa foi executada e se teve sucesso.
3. Quando a execução terminar, vá para a guia **Tabelas**. A tabela de saída do fluxo de trabalho está lá — entre nela e você deve ver linhas preenchendo a grade: as linhas e colunas reais que o fluxo de trabalho acabou de produzir. Linhas nessa tabela são o seu sinal visível de sucesso.

Essa tabela é o seu resultado: dados reais que um fluxo de trabalho acabou de criar a partir das origens. Se o fluxo de trabalho terminou com uma etapa de publicação, essa saída agora também está acessível a [painéis](/pt-br/guides/dashboards/) e outros consumidores.

> **Se uma etapa ficar vermelha, tudo bem por enquanto.** Uma execução com falha também aparece na faixa **Requer atenção** do Iniciador. Quando estiver pronto para corrigir uma, o tutorial [Corrija um fluxo de trabalho com o assistente de IA](/pt-br/get-started/tutorials/fix-a-workflow-with-ai/) mostra como diagnosticar e reparar uma falha — você não precisa resolver isso nesta sessão.

## Etapa 5: faça uma pergunta (opcional)

Todo projeto tem um **AI Assistant** integrado — um chat no escopo dos dados e fluxos de trabalho daquele projeto. Abra-o e pergunte algo simples, como *quais tabelas existem neste projeto?* ou *o que aquele último fluxo de trabalho produziu?* É a forma mais rápida de se localizar em um projeto desconhecido, e as conversas persistem por projeto, então você pode retomar uma discussão depois.

## Você tem o mapa

Em quinze minutos, você fez o que todo tutorial posterior considera dado: entrou, encontrou o caminho pelo Iniciador e pelas guias de um projeto e executou um fluxo de trabalho do início até um resultado pronto. A partir daqui, cada tutorial se apoia exatamente nesse ciclo — conectar dados, moldá-los, modelá-los, exibi-los.
