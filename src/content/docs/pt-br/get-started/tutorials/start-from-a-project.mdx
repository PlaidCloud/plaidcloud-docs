*~15 minutos · copie ou importe um projeto e depois faça dele o seu*

A vitória mais rápida no primeiro dia do PlaidCloud não é construir do zero, e sim começar de algo que já funciona. Escolha um projeto que já importa dados, os transforma e produz um resultado, obtenha sua própria cópia dele e altere as partes que são suas.

Não há uma galeria de modelos para navegar. Em vez disso, você tem duas formas concretas de começar a partir de um projeto que funciona:

- **Copiar um projeto** que já existe no seu espaço de trabalho para um projeto totalmente novo e seu: [Copiar um projeto](/pt-br/guides/projects/managing-projects/#copiar-um-projeto).
- **Executar um pacote portátil**: um projeto que alguém exportou como um pacote autocontido em [formato portátil](/pt-br/guides/projects/export-to-portable-format/), que é executado por conta própria fora do PlaidCloud.

Qual das duas você quer depende de onde você pretende chegar.

| Você quer… | Use | Resultado |
|---|---|---|
| Construir sobre um projeto dentro do PlaidCloud e continuar iterando | **Copiar projeto** | Um novo projeto seu, pronto para editar e executar |
| Executar a lógica de um projeto offline ou entregá-lo a alguém sem login no PlaidCloud | **Exportar para formato portátil** | Um pacote independente de Python + DuckDB |

## Pré-requisitos

- Um espaço de trabalho do PlaidCloud ([inicie um teste gratuito](https://app.plaidcloud.com) se você não tiver um).
- Para o **Caminho A**: um projeto existente que você consiga ver na guia **Projetos**, seja um dos seus, um exemplo compartilhado ou qualquer um ao qual um colega tenha dado acesso a você.
- Para o **Caminho B**: um `.zip` em formato portátil que alguém exportou, ou um projeto seu para exportar.

> **Não tem certeza do que é um projeto?** Um projeto é a unidade de trabalho no PlaidCloud: ele tem seus próprios dados, fluxos de trabalho, dimensões e histórico, e não compartilha estado com nenhum outro projeto. Leia primeiro [Projetos](/pt-br/guides/projects/) se isso for novidade para você.

## Caminho A: copie um projeto existente

A cópia cria uma duplicata completa e editável, de tudo ou apenas das partes que você escolher, em um projeto totalmente novo que é inteiramente seu.

1. Abra **Analisar** e selecione a guia **Projetos**.
2. Selecione o projeto a partir do qual você quer começar.
3. Clique no botão **Ações** e escolha **Copiar projeto**.
4. Escolha **um novo projeto** como destino. Dê a ele um nome e um **ID**.
5. Deixe a árvore de seleção totalmente marcada para trazer o projeto inteiro e clique em **Copiar projeto**.

> **O ID é permanente.** O ID que você dá ao novo projeto se torna o nome do esquema dele e não pode ser alterado depois. Escolha algo com que você fique satisfeito: o nome pode ser alterado a qualquer momento, o ID não.

A cópia é executada em segundo plano; você é notificado quando ela termina. Consulte [Copiar um projeto](/pt-br/guides/projects/managing-projects/#copiar-um-projeto) para ver a caixa de diálogo completa.

### Traga apenas as partes que você quer

Você não precisa copiar tudo. A árvore de seleção lista o que o projeto contém por tipo (fluxos de trabalho, etapas, tabelas, dimensões, editores de dados, funções definidas pelo usuário) e você pode marcar somente as partes que quiser. Tudo o que você marcar traz consigo as dependências automaticamente: as tabelas que uma etapa lê e grava, as dimensões com as quais ela carrega, as funções que ela chama e qualquer subfluxo de trabalho que ela invoque. Você nunca precisa descobrir essas dependências por conta própria.

> **Mantenha as referências apontando para a sua cópia.** Deixe **Atualizar referências** ativado (o padrão). Ele reescreve as etapas copiadas para que apontem para as tabelas e os objetos do seu novo projeto, e não de volta para o original, o que quase sempre é o que você quer. Desative-o somente se quiser deliberadamente que a cópia continue lendo os objetos do projeto de origem.

## Caminho B: comece a partir de um pacote portátil

Um pacote portátil é um projeto empacotado como um programa Python autocontido que é executado no [DuckDB](https://duckdb.org) sem nenhuma conexão com o PlaidCloud. É a forma de começar a partir de um projeto que funciona quando você quer que ele seja executado *fora da plataforma*: no seu notebook, em um job de CI ou nas mãos de alguém que não tem login no PlaidCloud.

Se um colega já lhe deu um pacote, pule para [Execute-o](#execute-o). Para criar um você mesmo:

1. Abra **Analisar** e selecione a guia **Projetos**.
2. Selecione um único projeto.
3. Abra o menu **Ações** e escolha **Exportar para formato portátil**.
4. Defina a **Conta de documentos** e o **Caminho da pasta** nos quais o pacote será gravado, deixe **Include data** marcado para que ele seja executado sem nenhuma origem externa e clique em **Exportar**.

O resultado é um `.zip` contendo um script Python por fluxo de trabalho, os instantâneos de dados em Parquet, um `requirements.txt` listando os pacotes Python de que os scripts precisam e um `README.md`, um `COVERAGE.md` e um `RUN_ORDER.md`. Consulte [Exportar para formato portátil](/pt-br/guides/projects/export-to-portable-format/) para saber o que é cada arquivo.

> **Um pacote portátil é um instantâneo de mão única, e não uma reimportação.** Ele é executado *fora* do PlaidCloud e não sincroniza de volta: as alterações que você faz no pacote não retornam ao projeto, e exportar novamente depois de editar produz um pacote novo. Para continuar trabalhando dentro do PlaidCloud, use o **Caminho A**. Para continuar iterando no PlaidCloud *e* distribuir uma cópia executável, faça os dois.

> **A fidelidade é de melhor esforço.** As etapas de transformação SQL são reproduzidas exatamente. As etapas proprietárias e com efeitos colaterais (alocações, cargas de dimensão, notificações, etapas de documentos e relatórios, scripts) são exportadas como stubs que não são reexecutados; em vez disso, sua última saída materializada é incluída como instantâneo. A fidelidade de cada etapa é registrada em `COVERAGE.md`. Para resultados totalmente recalculados, execute o projeto no PlaidCloud.

### Execute-o

Descompacte o pacote, crie um ambiente Python e execute cada script de fluxo de trabalho na ordem que `RUN_ORDER.md` lista:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python pipeline_<workflow>.py
```

Cada script cria suas tabelas em um banco de dados DuckDB local. As etapas SQL são recalculadas ao vivo; as etapas com stub mantêm no lugar sua saída em instantâneo.

## Faça dele o seu

Seja qual for a forma como você começou, a cópia agora é sua para alterar; é aqui que a vitória do primeiro dia compensa. Alguns primeiros passos:

| Faça isto | Onde |
|---|---|
| Aponte as importações para *os seus* dados em vez dos do exemplo | As etapas de importação de cada fluxo de trabalho; consulte [Carregar, transformar e publicar dados](/pt-br/get-started/tutorials/load-and-transform-data/) |
| Renomeie o projeto ou ajuste quem pode abri-lo | [Gerenciamento de projetos](/pt-br/guides/projects/managing-projects/) → Controle de acesso |
| Defina variáveis de projeto para valores que se repetem entre fluxos de trabalho | [Gerenciamento de variáveis do projeto](/pt-br/guides/projects/managing-projects/#gerenciar-variáveis-do-projeto) |
| Confirme que tudo ainda é executado de ponta a ponta | Clique em **Executar** em cada fluxo de trabalho e acompanhe o log |

Como toda alteração é rastreada, você pode experimentar livremente: o [rastreamento automático de alterações](/pt-br/guides/projects/managing-projects/#histórico-de-versões) permite recuperar qualquer estado anterior a um ponto no tempo se uma edição der errado.
