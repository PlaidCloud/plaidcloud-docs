*~30 minutos · uma verificação de prontidão, uma importação, uma execução validada*

Leve um fluxo de trabalho do Alteryx para o PlaidCloud de ponta a ponta: verifique se ele está pronto, importe e converta, veja o que foi convertido sem problemas e o que merece atenção, e execute-o. Esta é uma primeira migração pensada para gerar confiança, não um tour completo. Escolha um fluxo de trabalho que você conheça bem e, de preferência, para o qual você tenha uma saída conhecida e correta, para poder confirmar que a execução convertida está certa.

O importador do PlaidCloud preserva o grafo do fluxo de trabalho, carrega os arquivos referenciados nos documentos, gera fluxos de trabalho de macro e mapeia cada ferramenta do Alteryx para uma etapa nativa do fluxo de trabalho ou para um executor gerenciado. A maior parte de um fluxo de trabalho é convertida com pouco esforço manual, e a parte honesta deste tutorial é o restante: algumas ferramentas exigem atenção, e o PlaidCloud diz exatamente quais são, para você ir direto a elas.

## Pré-requisitos

- Um espaço de trabalho do PlaidCloud e um projeto no qual importar. Use um projeto de migração dedicado para que as dependências continuem fáceis de auditar.
- Um arquivo de fluxo de trabalho do Alteryx: `.yxmd` (fluxo de trabalho), `.yxwz` (aplicativo analítico) ou `.yxmc` (macro).
- Os arquivos que esse fluxo de trabalho lê durante a execução, mantidos junto com ele.
- Uma conta de documentos e uma pasta nas quais o PlaidCloud possa armazenar os arquivos importados.

## Etapa 1: verifique a prontidão

Uma importação limpa começa com um pacote completo. Reúna tudo em que o fluxo de trabalho toca antes de abrir o importador:

1. O próprio arquivo do fluxo de trabalho, mais todas as macros que ele chama, inclusive macros aninhadas, como arquivos `.yxmc`.
2. Arquivos de dados de entrada: CSV, TSV, Excel, Access, YXDB, XML, JSON e extrações de bancos de dados.
3. Arquivos auxiliares espaciais mantidos na mesma pasta: grupos de shapefile (`.shp`, `.shx`, `.dbf`, `.prj`), grupos do MapInfo (`.tab`, `.map`, `.id`, `.dat`) e quaisquer arquivos de projeção. Arquivos auxiliares ausentes são uma fonte comum de diferenças espaciais.
4. Ativos de relatório que o fluxo de trabalho referencia: imagens, PDFs, modelos e camadas de mapa.
5. Para um aplicativo analítico, os valores que os usuários normalmente informam: texto, números, datas, seleções de arquivos e pastas e seleções em listas suspensas ou caixas de seleção. Eles se tornam variáveis do fluxo de trabalho que você definirá antes de uma execução.

Em seguida, decida duas coisas: a pasta de documentos que guardará os arquivos carregados e se você vai validar este fluxo de trabalho estruturalmente (ele converte e executa?) ou em relação a saídas conhecidas e corretas (ele produz os mesmos resultados?).

> **Leve a saída conhecida e correta.** Se você tiver um resultado confiável da execução no Alteryx, mantenha-o junto com o pacote. É ele que transforma "executou" em "está correto" na Etapa 4.

A [lista de verificação de prontidão para migração do Alteryx](/pt-br/guides/workflows/alteryx-migration-readiness-checklist/) é a versão completa desta etapa, para quando você passar de um fluxo de trabalho para um portfólio.

## Etapa 2: importe e converta

1. Abra seu projeto de destino no PlaidCloud.
2. Abra **Tools → Importar fluxo de trabalho do Alteryx**.
3. Escolha o projeto de destino e selecione seu arquivo `.yxmd`, `.yxwz` ou `.yxmc`.
4. Opcionalmente, defina prefixos para os nomes de fluxo de trabalho, etapa e tabela. Os nomes de tabela já recebem como prefixo o nome do próprio fluxo de trabalho, então um único fluxo de trabalho não precisa de prefixo próprio.
5. Escolha a conta de documentos e a pasta para os arquivos importados.
6. Adicione quaisquer arquivos ou pastas referenciados de que o fluxo de trabalho precise durante a execução.
7. Inicie a importação.

Quando a importação termina, a janela substitui o formulário por um **relatório de conversão**: quantas etapas foram mapeadas com alta confiança, quantas precisam de revisão e, quando houver alguma, uma tabela com cada etapa de menor confiança, sua operação, sua confiança e observações. Esse relatório é o coração da migração. Toda etapa sinalizada também carrega a mesma observação no memorando da etapa na tela, para que você possa ir direto a ela.

O PlaidCloud armazena as dependências importadas na pasta de documentos que você escolheu e aponta as etapas convertidas para esses caminhos, de modo que o fluxo de trabalho seja executado de forma repetível, sem depender de um sistema de arquivos de desktop.

> **Comentários e contêineres também vêm junto.** As caixas de comentário chegam como notas e caixas de destaque, e os Tool Containers viram grupos: eles explicam o fluxo de trabalho exatamente como no Alteryx e não acrescentam trabalho de execução. A barreira de um **Control Container** também é preservada: suas etapas são importadas já configuradas para executar somente quando os dados controlados tiverem linhas.

## Etapa 3: revise o que foi convertido e o que precisa de atenção

Abra o fluxo de trabalho avançado gerado e percorra o relatório de conversão de cima para baixo. A maioria das etapas é convertida com alta confiança e não exige nada de você. As sinalizadas são onde uma primeira migração conquista confiança: leia cada observação e decida.

Este é o formato real de uma conversão parcial e o que cada caso significa:

| O que você vê | O que significa | O que fazer |
|---|---|---|
| Etapa de alta confiança | Mapeada sem problemas para uma etapa nativa ou um executor | Nada; faça uma verificação por amostragem se quiser |
| Etapa sinalizada para revisão | Convertida, mas com uma ressalva que vale confirmar | Leia a observação; verifique o resultado em relação ao esperado |
| Etapa marcada como não convertida | O importador se recusou a converter em vez de adivinhar errado | Corrija a causa no Alteryx e importe novamente, ou crie a etapa manualmente |
| Uma referência a uma tabela que ainda não existe | Um conjunto de dados Calgary ou criado externamente que o fluxo de trabalho não gerou | Carregue a tabela indicada antes de executar |

Alguns sinalizadores que você provavelmente encontrará em uma primeira migração:

- **Amostragem aleatória** (Create Samples, Random % Sample) mantém exatamente os tamanhos e as proporções, mas o PlaidCloud sorteia seus próprios registros; valide por contagens e proporções, e não por quais linhas foram selecionadas.
- **Modelos XGBoost** são convertidos em um classificador de gradient boosting do scikit-learn; espere equivalência estatística, e não valores idênticos, e confira as observações da etapa.
- **Uma etapa não convertida falha de propósito** quando o fluxo de trabalho chega a ela, de modo que uma conversão com uma barreira não resolvida ou uma tabela ausente não possa ser executada como se nada estivesse errado. Essa franqueza é deliberada: é o importador se recusando a apresentar um número errado como certo.

> **Uma execução bem-sucedida não é automaticamente uma execução correta.** O relatório diz onde olhar; a validação na próxima etapa diz se você deve confiar nos números. Não a pule em um fluxo de trabalho cuja saída alguém usa.

Para ver o catálogo completo de como cada família de ferramentas é convertida, consulte a [matriz de conversão do Alteryx](/pt-br/reference/alteryx-conversion-matrix/).

## Etapa 4: defina variáveis, execute e valide

1. Na tela do fluxo de trabalho convertido, revise as etapas e ramificações geradas.
2. Defina as **Variáveis do fluxo de trabalho**: elas são as perguntas do seu aplicativo convertido e os parâmetros de execução. Aponte as variáveis de arquivo e de pasta para os caminhos de documentos da Etapa 2 e use os mesmos valores que você usou na execução no Alteryx.
3. Clique em **Executar** no fluxo de trabalho (e não em uma única etapa) e acompanhe o log enquanto cada etapa é executada em ordem.
4. Revise o histórico de execuções, as saídas das etapas e quaisquer observações de prontidão.

Em seguida, valide no nível que você escolheu na Etapa 1:

- **Estrutural**: o fluxo de trabalho abriu, o grafo tem as ramificações e macros esperadas, as entradas foram carregadas, as variáveis apareceram e a execução foi concluída. Suficiente para prontidão e inventário.
- **Paridade de saída**: compare esquema, contagem de linhas e valores das linhas com a sua saída confiável do Alteryx. A ordem das linhas é ignorada, a menos que o fluxo de trabalho ordene explicitamente. Verifique também o tratamento de nulos, a precisão numérica, as datas e a geometria, quando aplicável.

Se uma comparação divergir, investigue as causas nesta ordem: arquivos de entrada ausentes ou diferentes, valores de variáveis diferentes, instantâneos de origem diferentes, depois diferenças de nulos, datas, arredondamento ou ordenação, e por fim referência espacial ou formato de geometria. Corrija a causa, execute novamente e compare outra vez. O [guia de validação](/pt-br/guides/workflows/validate-converted-alteryx-workflows/) tem a lista de verificação completa.

> **Importar novamente é seguro.** Corrigir um pacote e importá-lo de novo cria um conjunto próprio de tabelas, em vez de sobrescrever a primeira importação; exclua o fluxo de trabalho anterior e suas tabelas quando estiver satisfeito com o novo.

## Você migrou um fluxo de trabalho

Você levou um fluxo de trabalho do Alteryx de uma verificação de prontidão até uma execução validada no PlaidCloud e, tão importante quanto, agora sabe ler o relatório de conversão para distinguir o que foi convertido sem problemas do que merece uma olhada. Esse é o ciclo completo. Repita-o para cada fluxo de trabalho e, para um portfólio maior, migre em lotes para um projeto dedicado.
