*~20 minutos · uma etapa com falha, um diagnóstico de IA, uma correção aplicada*

Você executa um fluxo de trabalho, uma etapa fica vermelha e o texto do erro sozinho não diz o que mudar. Este tutorial percorre exatamente esse momento: você abre o **AI Assistant** integrado do PlaidCloud, deixa que ele diagnostique a etapa com falha usando seus dados reais, aprova a correção proposta e executa novamente para confirmar. Depois, você usa o mesmo assistente para escrever uma etapa Extrair SQL a partir de uma descrição em linguagem natural.

Este é o AI Assistant dentro do produto, que ajuda a construir e corrigir fluxos de trabalho. Ele **não** é a mesma coisa que conectar um agente externo de programação com IA (Claude Code, Cursor, MCP) ao seu tenant — esse caminho complementar está em [Conecte um agente de programação com IA](/pt-br/get-started/tutorials/mcp-with-ai-agent/).

## O que você vai fazer

| Fase | O que você vai usar |
|---|---|
| Ver a etapa falhar e ler o erro | A guia **Log** do projeto |
| Diagnosticar e corrigir a etapa com falha | O assistente de correção, na guia **AI Assistant** da entrada de log |
| Confirmar a correção | Diga sim quando o assistente oferecer para executar a etapa novamente |
| Adicionar uma nova consulta sem escrever SQL | **Generate SQL with AI** em uma etapa Extrair SQL |

## Pré-requisitos

- Um espaço de trabalho do PlaidCloud ([inicie uma avaliação gratuita](https://app.plaidcloud.com) se não tiver um) e um projeto que você possa editar.
- Um fluxo de trabalho com pelo menos uma etapa — de preferência uma que falhe, ou que você consiga fazer falhar (um nome de coluna digitado errado em uma transformação basta para reproduzir o cenário).

> **O assistente corrige com as suas permissões.** Ele só pode alterar uma etapa que você mesmo já poderia editar, e toda alteração que ele faz pode ser revertida executando-a novamente ou editando a etapa diretamente. Consulte [Correção de erros de fluxo de trabalho com IA](/pt-br/guides/ai-assistant/fixing-workflow-errors/).

## Etapa 1: execute o fluxo de trabalho e encontre o erro

Quando uma etapa falha, um indicador de erro aparece no fluxo de trabalho e na etapa que falhou, e a falha é gravada no log do fluxo de trabalho.

1. Abra seu projeto e execute o fluxo de trabalho (ou a única etapa que você está testando).
2. Vá para a guia **Log** do projeto. O log lista os eventos conforme as etapas são executadas — incluindo avisos e erros.
3. Na lista de log, selecione a entrada da etapa que falhou. A mensagem completa — incluindo qualquer traceback — abre no painel à direita, na guia **Mensagem de log**.

> **Não tem um fluxo de trabalho quebrado à mão? Crie um em 30 segundos.** Em qualquer etapa de transformação, edite a expressão de uma coluna para fazer referência a uma coluna que não existe — troque `net_amount` por `net_amnt`, por exemplo — e salve. Execute a etapa e ela falha com um erro no log dizendo que a coluna `net_amnt` não existe. Essa é uma configuração incorreta genuína, que o assistente de correção foi feito para detectar, então é uma forma limpa de acompanhar este tutorial do início ao fim.

Para saber mais sobre como os erros aparecem e as opções para tratá-los, consulte [Gerenciamento de erros de etapa](/pt-br/guides/workflows/managing-step-errors/) e [Visualizar o log do fluxo de trabalho](/pt-br/guides/workflows/viewing-workflow-log/).

## Etapa 2: abra o assistente de correção

O assistente de correção fica bem ao lado do erro bruto, já apontado para a etapa que falhou.

1. Com a entrada de log com falha selecionada, localize o painel à direita que mostra **Mensagem de log**.
2. Mude esse painel para a guia **AI Assistant**.

O chat do **AI Assistant** abre já apontado para o fluxo de trabalho e a etapa de onde veio a entrada de log selecionada, então você não precisa dizer qual etapa falhou. Você pode ler o erro bruto em **Mensagem de log** e conversar com o assistente em **AI Assistant**, lado a lado.

Na maioria dos erros, ele começa a diagnosticar imediatamente. Em alguns casos comuns, como uma expressão que cita uma coluna inexistente, a primeira resposta é, em vez disso, uma breve explicação que o PlaidCloud já tem para esse tipo de erro: o que costuma causá-lo, quais palavras da mensagem de erro observar e como corrigi-lo. Essa explicação não examina a sua etapa. Responda — por exemplo, *"Verifique esta etapa e corrija"* — e o assistente assume a partir daí. Consulte [Erros comuns](/pt-br/guides/ai-assistant/fixing-workflow-errors/#erros-comuns).

## Etapa 3: deixe-o diagnosticar e propor uma correção

O assistente trabalha em uma ordem fixa, e nada é salvo até que você diga:

1. **Diagnostica** — ele lê a configuração da etapa com falha e as tabelas e colunas que ela toca, verificando suas afirmações em relação aos seus dados em vez de adivinhar apenas pelo texto do erro.
2. **Propõe** — se encontrar uma configuração incorreta genuína, mostra a configuração corrigida da etapa e explica com clareza o que mudou e por quê. Nada é gravado neste ponto.
3. **Você aprova** — ele espera pela sua autorização explícita. Uma resposta ambígua não é tomada como aprovação.
4. **Aplica** — depois que você aprova, ele grava a configuração corrigida na etapa, pelo mesmo caminho que o editor de etapas usa.
5. **Oferece uma nova execução** — ele pergunta se deve executar a etapa novamente agora. Diga sim e ele executa a etapa e informa se a correção funcionou.

Leia a alteração proposta antes de aprovar. O assistente repara a configuração da única etapa de onde veio o erro — por exemplo, um nome de coluna ou de função digitado errado, uma expressão inválida, um tipo de dado ou conversão incorreto, ou SQL malformado — e altera o mínimo necessário para corrigir o erro.

> **Ele é honesto sobre o que não consegue corrigir.** A única alavanca dele é a configuração dessa etapa. Ele não cria, exclui nem reordena etapas, não edita outra etapa e não altera seus dados. Muitas falhas não são problemas de configuração — dados de origem ausentes ou malformados, uma etapa anterior que falhou primeiro, um erro transitório ou de infraestrutura, um problema de permissões ou uma lógica quebrada dentro de uma transformação ou UDF. Para esses casos, ele explica o que encontrou e indica onde está a correção de verdade, em vez de forçar uma edição para parecer uma solução.

## Etapa 4: aprove e execute novamente

1. Quando a configuração proposta parecer correta, confirme a alteração explicitamente. O assistente a aplica à etapa.
2. Quando o assistente perguntar se deve executar a etapa novamente, diga sim. Ele executa a etapa e informa se teve sucesso ou se falhou de novo. Você também pode executar a etapa, ou o fluxo de trabalho, por conta própria.

Se o assistente disse que a causa está fora da configuração da etapa — dados incorretos, uma falha anterior, um problema de permissões — essa é a resposta. Corrija onde o problema realmente está, em vez de pedir ao assistente que edite a etapa mesmo assim.

> **Avisos costumam ser inofensivos.** Se a entrada de log for um aviso e não uma falha grave, o assistente muitas vezes dirá que nenhuma alteração é necessária, em vez de inventar uma edição. Esse é um resultado válido, não um beco sem saída.

## Etapa 5: gere uma etapa Extrair SQL com IA

Agora use o mesmo assistente para adicionar trabalho novo, e não apenas repará-lo. A etapa **Extrair SQL** executa um `SELECT` somente leitura e grava o resultado em uma nova tabela — e o editor de etapas pode escrever essa consulta para você.

1. Na visão **Etapas** do fluxo de trabalho, clique em **Criar etapa** e escolha **Tabelas → Extrair SQL** ou **AI → SQL Extract (AI Assisted)**. Ambos abrem o mesmo editor, que inclui um painel **Generate SQL with AI** no topo da página Parâmetros de extração de SQL.
2. **(Opcional) Escolha as tabelas de origem.** Na lista **Tabelas de origem**, selecione uma ou mais tabelas das quais a consulta deve ler. Deixe vazia para que o assistente examine o projeto e escolha por conta própria as tabelas relevantes.
3. **Descreva o que você quer.** Na caixa **Descrever**, escreva o resultado em linguagem natural — por exemplo, *"classifique cada conta contábil em um conjunto de atividades com base no intervalo do número da conta"*.
4. **Clique em Gerar SQL.** O assistente escreve um único `SELECT` somente leitura, valida-o executando-o e preenche o editor **Consulta SQL SELECT** e a página de mapeamento **Seleção de dados da tabela** com as colunas detectadas. Se você deixou a lista de origem vazia, as tabelas que ele escolheu são selecionadas de volta na lista para que você veja o que foi usado.

> **Não há nada a configurar.** Isso usa o mesmo modelo integrado que o AI Assistant usa — você não precisa configurar um agente de IA ou uma conexão de LLM por espaço de trabalho para isso.

## Etapa 6: revise e salve a etapa

O SQL gerado é um ponto de partida, não uma caixa-preta.

1. **Edite à vontade.** O editor de SQL é totalmente editável — refine a consulta, adicione uma junção ou altere a lista de colunas antes de salvar.
2. **Escolha uma tabela de destino.** Escolha ou dê um nome à **Tabela de destino** em que a etapa grava o resultado.
3. **Salve a etapa.** Ela é salva como uma etapa Extrair SQL comum e é executada como parte do fluxo de trabalho, como qualquer outra.

O assistente só escreve instruções `SELECT` somente leitura — nunca `INSERT`, `UPDATE`, `DELETE` ou outro SQL que altere dados. A geração apenas cria rascunhos e pré-visualizações; a etapa é criada quando você a salva e é executada quando o fluxo de trabalho é executado. Se uma consulta gerada não executar, o editor mostra o SQL junto com o erro para que você o corrija — ou ajuste a descrição e gere novamente. Todos os detalhes em [Geração de etapas Extrair SQL com IA](/pt-br/guides/ai-assistant/generate-sql-extract/).

**Esse é o auxílio.** Você diagnosticou uma etapa com falha usando dados reais, aprovou e aplicou a correção da IA, confirmou com uma nova execução e gerou uma etapa Extrair SQL funcional a partir de uma frase em linguagem natural — o mesmo assistente consertando o que está quebrado e construindo o que é novo.
