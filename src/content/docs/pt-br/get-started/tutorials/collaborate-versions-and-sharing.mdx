*~25 minutos · um histórico de versões, uma comparação, um link compartilhado*

Quando várias pessoas trabalham no mesmo projeto, as perguntas que importam no primeiro dia são sempre as mesmas: *O que mudou? Posso recuperar um estado anterior? Como levo uma alteração de um projeto para outro? Como envio um colega direto para o que estou vendo?* O PlaidCloud responde às quatro já de fábrica — o trabalho é **versionado, comparável e compartilhável**, e este tutorial mostra cada um desses pontos.

A mensagem para levar: nada se perde. Toda alteração é registrada, quaisquer dois projetos podem ser comparados e toda tela tem um link.

## O que você vai fazer

1. Ver o histórico automático de alterações de um projeto e ler o log dele.
2. Comparar dois projetos e entender o que uma mesclagem faz.
3. Organizar o trabalho com rótulos para encontrá-lo novamente.
4. Copiar um link direto que leva um colega a um lugar exato.

## Pré-requisitos

- Um espaço de trabalho do PlaidCloud e um projeto que você possa abrir.
- Um segundo projeto — uma cópia ou um equivalente de QA/produção — se você quiser testar a comparação com conteúdo real. Um [projeto copiado](/pt-br/guides/projects/managing-projects/#copiar-um-projeto) funciona bem.

## Parte 1: o trabalho é versionado

Tudo o que você constrói em um projeto é registrado para você — não é preciso ativar isso.

> **Nada se perde.** Todas as alterações em um projeto — fluxos de trabalho, editores de dados, hierarquias, estruturas de tabelas e funções definidas pelo usuário — são registradas e permitem a **recuperação até um ponto no tempo** do estado. Isso significa que uma alteração acidental pode ser recuperada e qualquer ponto anterior pode ser copiado para comparação.

Além desse registro automático, projetos e seus elementos oferecem suporte a **versionamento**: criar uma versão é fácil, e você pode **mesclar alterações de uma versão em outra**. É uma maneira simples de manter instantâneos ou de desenvolver em uma versão e mesclar essas alterações na versão que não é de desenvolvimento quando estiver pronto.

### Leia o log do projeto

O log do projeto consolida cada log de fluxo de trabalho individual em uma única visão abrangente da atividade do projeto — membros atribuídos, fluxos de trabalho executados e mais.

1. Abra **Analisar**.
2. Selecione **Projetos**.
3. Abra a guia **Log** (o log do projeto).

Para restringir um log movimentado, use o controle de filtro ao lado das mensagens de log e escolha suas diretrizes de filtro. Para ler uma entrada por completo, clique nela com o botão direito e veja a caixa **Mensagem de log**.

> **Limpar o log também exclui os sublogs.** O botão **Limpar log** remove o log do projeto *e* o sublog de cada fluxo de trabalho abaixo dele. Limpe-o somente quando você realmente quiser se livrar desse histórico.

## Parte 2: compare dois projetos

A comparação permite ver exatamente o que difere entre dois projetos e, nas partes que podem ser copiadas com segurança, mesclar alterações selecionadas de um no outro. Ela atende a duas situações do dia a dia: **promover alterações entre ambientes** (um projeto de QA para o equivalente de produção) e **revisar em relação a uma cópia anterior** (um clone mês a mês, para ver o que mudou).

Você mantém o controle o tempo todo — nada é gravado até que você selecione itens específicos e os aplique, e é possível validar antes com uma simulação.

### Abra uma comparação

1. Abra **Analisar** e selecione **Projetos**.
2. Clique com o botão direito no projeto de que você quer partir (ou use o menu de ações dele) e escolha **Comparar com...**.
3. O projeto de que você partiu é preenchido como **Origem**. Escolha o **Destino** na lista suspensa.
4. Clique em **Comparar**.

Os dois projetos devem estar no mesmo espaço de trabalho. Use **Trocar** para inverter Origem e Destino antes de comparar — a direção importa, porque uma mesclagem copia *da* Origem *para o* Destino.

### Leia a comparação

O lado esquerdo agrupa cada diferença em sua categoria — **Fluxos de trabalho** (com **Etapas** aninhadas), **Variáveis**, **Dimensões**, **Editores**, **UDFs**, **Visões** e **Tabelas**. Cada item recebe um selo com seu status:

| Selo | Significado |
|---|---|
| **Adicionado** | Está na Origem, mas não no Destino — seria criado no Destino |
| **Modificado** | Está em ambos, mas a configuração difere |
| **Excluído** | Está no Destino, mas não na Origem |
| **Inalterado** | Idêntico nos dois lados (oculto por padrão) |

Selecione um item alterado para ver uma tabela **Campo / Origem / Destino** à direita, com a **Diferença de configuração** completa abaixo dela. Filtre por nome ou caminho, ou alterne as caixas de seleção de status, para focar em uma lista longa.

### Entenda o que a mesclagem faz

Nem toda diferença pode ser copiada com segurança, então a comparação rotula cada item:

- **Fluxos de trabalho, Etapas e Variáveis** podem ser mesclados.
- **Dimensões, Editores, UDFs, Visões e Tabelas** são **somente para visualização** — revise-os aqui, mas copie-os com as ferramentas dedicadas a cada um.

Para mesclar, selecione os itens que podem ser mesclados, clique em **Simulação** para validar sem gravar e depois em **Aplicar** e confirme. Os itens mesclados mantêm sua identidade no Destino, então você pode comparar novamente mais tarde e mesclar outras alterações sem criar duplicatas.

> **Uma mesclagem altera o Destino.** Revise a diferença, faça uma simulação e confirme que Origem e Destino estão na ordem certa antes de aplicar. Se outra pessoa editou o Destino depois que você carregou a comparação, a mesclagem para em vez de sobrescrever o trabalho dela — atualize e aplique novamente.

Para promover Dev → QA → Produção entre projetos copiados uns dos outros, veja [Ressincronizando a partir do projeto do qual você copiou](/pt-br/guides/projects/compare-and-merge-projects/#ressincronizar-a-partir-do-projeto-que-você-copiou), que emparelha os itens pela linhagem de cópia em vez de pelo nome.

## Parte 3: organize com rótulos

**Rótulos** são tags livres que você anexa a objetos — o próprio projeto, seus fluxos de trabalho, etapas, tabelas, dimensões, editores de dados e UDFs. Use-os para agrupar itens relacionados pelo que importa para você (uma fase do trabalho, um sistema de origem, um responsável, uma versão) e encontrá-los rapidamente depois.

Todo objeto que pode receber tags tem uma caixa **Rótulos** em seu painel de detalhes:

1. Clique em qualquer ponto da caixa **Rótulos** para posicionar o cursor.
2. Digite o texto do rótulo.
3. Pressione **Enter** (ou digite uma vírgula) para adicioná-lo.

Remova um rótulo com o **×** no respectivo chip ou pressione **Backspace** com o campo de entrada vazio para remover o último.

> **Os rótulos são armazenados em minúsculas.** O PlaidCloud converte cada rótulo para minúsculas automaticamente e recusa duplicatas no mesmo objeto. Mantenha seu conjunto consistente e ele se torna uma maneira leve de fatiar um projeto grande.

Para encontrar itens marcados, digite o rótulo na caixa de filtro de uma lista de projetos — a busca compara o texto do rótulo junto com o nome do item.

## Parte 4: compartilhe um link direto

O PlaidCloud mantém a barra de endereços em sincronia com o que você tem aberto. Abra um fluxo de trabalho, uma tabela ou uma dimensão, e a URL se torna um **link direto** para ele. Não há um botão de compartilhar separado — a barra de endereços *é* o link.

1. Abra o objeto que você quer compartilhar.
2. Copie a URL inteira da barra de endereços do navegador.
3. Envie-a — quem a abrir chega à mesma tela.

Os links começam pelo projeto: o projeto vem primeiro, depois o objeto dentro dele, separados por `~`.

| Tela | O link termina com |
|---|---|
| Projeto | `#p~<project>` |
| Fluxo de trabalho (grade de Etapas) | `#p~<project>~w~<workflow>` |
| Fluxo de trabalho (tela do Designer visual de fluxo de trabalho) | `#p~<project>~c~<workflow>` |
| Uma etapa dentro de um fluxo de trabalho | `…~w~<workflow>~s~<step>` |
| Explorador de tabelas | `#p~<project>~t~<table>` |
| Hierarquia da dimensão | `#p~<project>~d~<dimension>` |
| Editor de dados | `#p~<project>~e~<editor>` |

Abrir um link restaura o **contexto pai**, não apenas a janela em questão: um link para um fluxo de trabalho reabre também o projeto dele, de modo que a pessoa chega com o projeto ao redor na barra de guias. Um link de etapa chega a selecionar a etapa para ela.

> **Um link carrega a *localização*, não a permissão.** Quem o abre ainda precisa de acesso ao projeto. Quem não tiver acesso não verá o objeto — portanto, compartilhar um link é seguro. Controle quem pode ver o quê em [Controle o acesso aos dados](/pt-br/get-started/tutorials/control-data-access/).

Links mais antigos no estilo `#te?p=…&t=…` ainda funcionam e se reescrevem silenciosamente para a forma atual, mais legível, na primeira navegação.

**Nada se perde — e agora você pode mostrar isso.** Você leu o histórico de um projeto, comparou dois projetos e mesclou com segurança em uma direção, organizou o trabalho com rótulos para encontrá-lo novamente e entregou a um colega um link direto que o leva exatamente onde você está.
