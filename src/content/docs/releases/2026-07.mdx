## Added

- **A new Launcher.** Signing in now opens on the Launcher: one page of tiles gathering your recent projects, dashboards and panel apps, whatever you've pinned, and any workflow whose last run failed — laid out in three lanes you can act on directly: open a tile, run a workflow, jump to a failed run, or dismiss it. Pin anything from the Launcher or from the lists and document browser where you already work — projects, workflows, tables, dimensions, data editors, dashboards, panel apps, and documents by file or folder. Project tiles summarise the project (workflow runs, workflows, tables, records) and carry a faded background image you can set per project under **Launcher Tile Image** on the project's Home tab. Switch between tiles and a dense list, hide the types you don't want to see, and press **Ctrl/Cmd-K** to search projects, workflows, tables, dashboards and panel apps as you type. See [The Launcher](/guides/launcher/).

- **Paste a collection or spec into a REST Request step.** The Postman, OpenAPI/Swagger, and HAR sources each gained a **Paste…** button beside the file picker, so you can supply the content directly instead of saving it to Document first. See [REST Request Step](/guides/workflows/rest-request-step/#paste-a-collection-or-spec-instead-of-picking-a-file).

- **Attach an API definition to a REST connection.** Generic REST and MuleSoft connections can now carry their own OpenAPI 3.x or Swagger 2.0 definition — a published address, or a specification file kept in Document. Set it once on the connection under **API Definition**, then any REST Request step using that connection can set **Endpoint Source** to **From the connection's API definition** and list the API's endpoints, with methods, parameters, and bodies filled in, without restating the definition on every step. See [Generic REST Connection](/reference/connectors/rest/generic-rest/#api-definition) and [REST Request Step](/guides/workflows/rest-request-step/#reuse-a-connections-api-definition).

- **MuleSoft is available as a connection type.** Add a MuleSoft Anypoint gateway from the New Connection menu and configure it like any other REST connection — your own gateway address and whichever authentication it expects. See [MuleSoft REST Connector](/reference/connectors/rest/mulesoft/).

- **PlaidCloud Git connections.** Connect to your workspace's own managed Git server with a simplified form — just an account name, memo, repository path, default branch, and optional start path — with no server URL, username, token, or SSH key to enter, because your Git server and your access to it come from your normal PlaidCloud sign-in. Point a Server Panel app's build at a PlaidCloud Git connection to automate builds entirely inside your workspace, without an external GitHub account or access token. External Git providers (GitHub, GitLab, Bitbucket, Forgejo, Gitea) keep their full connection form. See [PlaidCloud Git Connection](/guides/connections/plaidcloud-git/).

- **Currency — a column data type built for money.** Every column data-type list — step output column mappings, the data mapper grid, a table's Column Properties, and MCP/AI tooling — now offers **Currency**: an exact fixed-point type with 18 digits of precision and 4 decimal places (roughly ±100 trillion, exact to 1/10,000). It stores money in half the in-memory width of Numeric, so money-heavy dashboards and workflow steps scan about half the data and run faster; Numeric stays the high-precision default (38 digits, 10 decimal places). Currency is always your explicit choice — imports, type detection, SQL results, and derived columns still default to Numeric — and once set on a column it is remembered through reads, downstream steps, and table rebuilds. Aggregations of Currency return Numeric. The option appears once the platform update is live on your workspace. See [Currency Data Type](/guides/data/currency-data-type/).

- **Skip re-importing unchanged source files** — file-import steps (CSV, Excel, Fixed Width, JSON, Avro, Parquet, Alteryx yxdb, dbf, XML, Access) have a new **Skip re-import if source files unchanged** option. Turn it on and a workflow run skips the whole download, conversion, and table rebuild when the source files and the step's settings have not changed since the last successful run — so a scheduled reload no longer repeats the work. **On by default** — untick the option on a step to always re-import; the change is detected from each file's size and modified time, plus a content hash where the source provides one. Manual, one-off imports always run. See [Import CSV](/reference/workflow-steps/import/import-csv/).

- **Machine learning in workflows — ML: Train Model and ML: Score steps.** Train a model on any table — choose from seven algorithms including linear and logistic regression, decision trees, random forests, and gradient boosting — and score data with it, appending a prediction column, entirely inside a workflow. The trained model flows through the workflow like any other table, with its algorithm, settings, features, and training metrics recorded alongside, and mistyped algorithms or settings are caught when you save the step. Alteryx Assisted Modeling pipelines also convert to these native ML steps on import, with XGBoost models carrying a documented approximation note. See [ML: Train Model](/reference/workflow-steps/machine-learning/ml-train/), [ML: Score](/reference/workflow-steps/machine-learning/ml-score/), and [Machine Learning Conversions](/guides/workflows/migrate-alteryx-workflows/#machine-learning-assisted-modeling-conversions).

- **PlaidCloud Managed Bucket document accounts.** Add fully managed file storage to Document in a single step — no cloud project, credentials, region, or storage tier to set up or tune. Available on the Business and Enterprise plans. See [Add a PlaidCloud Managed Bucket Account](/guides/documents/adding-accounts/add-managed-bucket-account/).

- **Connect a OneDrive or SharePoint site with least-privilege access.** Add a OneDrive for Business or SharePoint site as a Document account that can reach only the sites your Microsoft administrator has explicitly granted — Microsoft's Sites.Selected model — rather than your whole Microsoft 365 tenant. Choose OneDrive as the account's service, enter your app registration's Client ID, secret, and tenant ID, paste a granted site's URL, and pick one of its document libraries as the starting folder. Sites you don't grant — payroll, HR, and the like — stay completely out of reach. See [Add OneDrive / SharePoint Account](/guides/documents/adding-accounts/add-onedrive-account/).

- **A more capable REST Request step.** REST Request can now fan a call out over the rows of a driver table — one request per row, with an optional row filter — carrying key columns onto the results, with a concurrency limit, a request-rate cap, an opt-in idempotency key for safe re-runs, a continue-on-error option, and clear per-row failure reporting. New authoring aids make requests easier to build and verify: import from a curl command, insert and highlight variable tokens (including a driver table's columns), test the first fan-out row, preview the resolved request and its pagination before running, restore unsaved drafts, edit the selected connection in place, and confirm before saving a request you haven't successfully tested. See [REST Request Step](/guides/workflows/rest-request-step/).

- **An expanded Help & Support experience.** Attach screenshots and files to tickets and replies (images show inline), work tickets from a sorted, filterable support console (reply, add internal notes, claim, set priority, and escalate to PlaidCloud), route new-ticket alerts to a Slack, Teams, or email channel, email the ticket owner when a ticket gets a reply, and auto-escalate tickets left unanswered too long. See [Getting Help](/guides/support/getting-help/), [The Support Console](/guides/support/support-console/), and [Managing Support](/guides/support/managing-support/).

- **Analysis paths for AI questions.** Give the tables you analyze most a friendly name, and set one as your default, so you and your AI assistant can ask about "the Operations Results" — or just "what changed last quarter?" — without naming the project and table every time. Works across Microsoft 365 Copilot and any MCP-connected agent. See [Analysis Paths](/integrations/ai-coding-agents/analysis-paths/).

- **Smarter, more honest AI allocation cost-tracing.** When you ask an MCP-connected AI agent why an allocation result changed, the answer now carries a plain-language confidence level and caveats — flagging when a cause is a mix of overlapping factors, when it depends on current hierarchy or driver weights, or when part of the change may just be an unfinished data load, and these trust signals travel with the answer even when a follow-up agent summarizes it. Administrators can also turn on an optional check that lowers confidence and flags an answer when the pool or driver data behind it hasn't been reloaded recently. For a result built from several allocation branches, the confidence now weighs each branch by how much of the change it accounts for, so one small, shaky branch doesn't drag down an otherwise-clean answer. You can also ask driver-reweight what-if questions ("what if this cost centre's headcount doubled?"), and the full root-cause analysis can now be driven over the REST API, not only through an AI agent. See [Tracing Allocations with an MCP-Connected AI Agent](/integrations/ai-coding-agents/tracing-allocations/).

- **A written trace summary you can trust — and your AI can check.** When you ask an MCP-connected AI agent why an allocation result changed, it can now return a plain-language **summary built directly from the analysis**: it states the confidence level, carries every caveat, and cites no figure that didn't come from a real query. A companion **faithfulness check** lets the agent confirm its own reworded version kept the confidence and every caveat and invented nothing — so the narrative is *provably* faithful, not just fluent. Each summary also suggests the natural next question — scope to a single member, break the change down by a dimension, or point at a specific producing step when a result table is built by more than one — so you can drill in without knowing the exact wording. See [Answers You Can Trust](/integrations/ai-coding-agents/honest-answers/).

- **Preview step data in the Visual Workflow Designer.** See a step's output in place, without opening a new window — dock a preview of the first 100 rows, with typed columns, row and column counts, and a selector for multi-output steps, at the bottom of the canvas. Clicking another step retargets the preview, it refreshes when a run finishes, and you can open the full Table Explorer in one click. See [Preview Step Data](/guides/workflows/preview-step-data/).

- **Lock a Panel app against accidental changes.** A lock icon on each row of My Panel Apps protects an app the way the existing workflow and step locks do: while locked, editing, removing, and rebuilding it refuse to run — and a git push to a server app's branch no longer rebuilds it — while opening the app, its logs, and its usage metrics keep working. It's a guard against accidents, not a security control: anyone who can edit panel apps can unlock them. See [Locking an App](/guides/panel-apps/using/#locking-an-app).

- **Workflow steps are auto-numbered.** Every step now carries a number — a badge on the visual canvas, the leading column of the steps grid, and the same "Step 7" in run logs, workflow documentation reports, and AI assistant listings — so you can point a teammate or an AI agent at "step 7" instead of describing a step by name in a tangled imported workflow. Numbers follow the flow (a step always numbers after the steps it feeds from), canvas position breaks ties left-to-right then top-to-bottom, and everyone's canvas renumbers live as the workflow is edited, with a brief highlight on steps whose number changed. Right-click a step (or click its badge) to copy a ready-to-paste reference like "Step 7 — Clean Customer Names". See [Step Numbers](/guides/workflows/step-numbers/).

- **Two new workflow steps — Directory Listing and Row Count Assert.** Directory Listing writes a table of the files in a document directory (with an optional file pattern and a subdirectory option) so downstream steps can act on whatever files are present. Row Count Assert is a data-quality gate that fails the workflow when two tables have different row counts. See [Directory Listing](/reference/workflow-steps/document/directory-listing/) and [Row Count Assert](/reference/workflow-steps/workflow-control/row-count-assert/).

- **Jump to a workflow's logs from the Visual Workflow Designer.** A **View Logs** button on the canvas toolbar opens the project Log view already filtered to the workflow you have open — the same full run log you'd otherwise reach from the Project area. See [Advanced Workflows](/guides/workflows/advanced-workflows/#view-logs).

## Changed

- **Table Update writes to a target table instead of changing its source.** The step formerly known as **Table In-Place Update** is now **Table Update**, and it is back in the New Step menu. It reads the source, updates the rows matching your filter, and writes every row — changed and unchanged alike — to a target table you choose, leaving the source intact for comparison. The target's columns always mirror the source's, including any column added upstream after the step was last opened. Because the update no longer happens in place, it runs on every warehouse, including those that don't allow a table to be changed in place. A view is a valid target. Steps saved before this change need a target table selected before they will run, and any step that read the source expecting the updated rows must be pointed at the new target. See [Table Update](/reference/workflow-steps/tables/table-update/).

- **Multi-Table Join accepts dynamic source and target tables.** Tick **Dynamic** on a table picker and give a table name or a project path instead of choosing from the list — either may carry `{variable}` tokens resolved when the workflow runs, so a join can write to `/03 Results/FACT_GL_{year}` and pick up a different table each period. The target is created if it does not exist. This is how every other step's tables already worked; Multi-Table Join previously required a table picked from the list and could not be saved otherwise. A dynamic source's columns can't be read at design time, so you enter them by hand in the side panel. See [Multi-Table Join Step](/guides/workflows/multi-table-join-step/).

- **Multi-Table Join output columns can hold an expression or a constant.** An output column now takes its value from exactly one of three places — a source column (with the canvas alias that owns it), a **Constant**, or an **Expression**. **Add expression column** appends a row and opens the full expression editor with every table on the canvas in its column browser, so a value can span several joined tables. The **Post-Join Filter** is that same editor rather than a plain text box, and lists the output columns you can reference as `result.column_name`. The editor drops to three tabs: the internal-only **Advanced (server-set)** tab is gone, and those settings are still kept when you save. See [Multi-Table Join Step](/guides/workflows/multi-table-join-step/).

- **File imports handle large files and keep source data types.** Imports of Excel, JSON, Parquet, Alteryx yxdb, dBASE, and fixed-width files no longer load the whole file into memory, so large files that previously failed with out-of-memory errors now import — the practical limit is disk space, not memory. The source's data types — decimals, dates, and timestamps — are now carried through to the target table instead of round-tripping through text, and Parquet timestamp columns keep their full time-of-day precision (previously truncated to the date). Deliberately unchanged: blank numeric cells still load as 0, and the file name, path, worksheet name, row number, and last-modified columns behave exactly as before, with row numbers counted per source file. See [Import Excel](/reference/workflow-steps/import/import-excel/), [Import JSON](/reference/workflow-steps/import/import-json/), and [Import Parquet](/reference/workflow-steps/import/import-parquet/).

- **JSON imports accept newline-delimited files and produce standard JSON text.** The Import JSON step now accepts newline-delimited JSON (NDJSON) — one object per line — in addition to JSON arrays, and nested objects and arrays now land in the table as standard compact JSON text rather than Python-styled notation, so downstream steps can parse them with any JSON tooling. See [Import JSON](/reference/workflow-steps/import/import-json/).

- **Pick the repository, branch, and folder for a Git connection.** The Git connection form no longer asks you to type a repository path, branch name, or start path — you choose them from live lists. Enter the server and credentials (nothing to enter for a PlaidCloud Git connection), click Refresh to list the repositories the connection can reach, pick one to load its branches, then browse its folders to set an optional start path — so a mistyped name can't quietly break the connection. Editing an existing connection browses without re-entering the stored password. Applies to PlaidCloud Git and every external provider (GitHub, GitLab, Bitbucket, Forgejo, Gitea). See [PlaidCloud Git Connection](/guides/connections/plaidcloud-git/).

- **AI cost-tracing is more accurate and harder to mislead.** What-if estimates are now real per-target numbers that add up across a fan-out, rather than upper bounds, and can be scoped to a single target — and pointed at a driver or basis table instead of the input pool, the agent declines the estimate and explains why. Driver-reweight what-ifs are exact: they move only the amount the driver actually splits and leave any pass-through cost untouched. The agent now recognizes and lowers its confidence on misleading shapes — a total whose large ups and downs offset to a small net change, or a change that is mostly pass-through rather than driver-governed — naming how much the driver-controlled amount actually moved and no longer overstating a single "dominant factor" when the split is unreliable. It also explains dimension-hierarchy allocations instead of leaving them unattributed. Data-freshness checks now cover the driver and basis tables, results produced by more than one allocation step can be traced by picking the step — or automatically when a filter narrows to rows only one step produced — and a year-over-year comparison with no prior-year data now says so rather than calling the change "normal". See [Tracing Allocations with an MCP-Connected AI Agent](/integrations/ai-coding-agents/tracing-allocations/).

- **Alteryx import ends on a conversion report.** Importing an Alteryx workflow now summarizes how many steps mapped with high confidence and how many need review, and lists the lower-confidence steps with notes so you can check them before running; each imported step also carries its confidence as a memo on the canvas. Packaged report macros now import as hand-editable Report steps, and a new guide plus a downloadable workflow batch-convert AMP-format `.yxdb` files to CSV so their data imports losslessly. See [Migrate Alteryx Workflows](/guides/workflows/migrate-alteryx-workflows/) and [Convert .yxdb Files for Import](/guides/workflows/convert-yxdb-files-for-import/).

- **External Tables: refresh a single table's columns from the source.** On the Import and Export External Tables steps, the per-table **Inspect Source** button now reads the selected table's current columns straight from the connected database and updates just that table's mapping in place — handy when a source table's columns have changed since you built the step, without re-running discovery over the whole connection. See [Import External Database Tables](/reference/workflow-steps/import/import-external-database-tables/).
- **Presence in the Visual Workflow Designer now shows real avatars.** When several people have the same Advanced workflow open, the toolbar's presence row now shows each person by their gravatar (or their initials if they have none), and a person appears once no matter how many browser tabs they have it open in. See [Advanced Workflows](/guides/workflows/advanced-workflows/#whos-here).

- **Opening a Server Panel app now shows real progress.** The waking screen used to show one message for the whole start-up and then a generic timeout, so an app that could not start at all looked identical to one that was simply slow. It now reports the actual stage — starting, preparing, loading — reports a genuine failure within seconds along with the underlying reason, and sends you straight through when the app is already warm. An app that starts but fails while loading (for example a missing package) is reported as failed with its error, instead of serving a blank page. See [Creating a Panel App](/guides/panel-apps/creating/).

## Fixed

- **Exporting a project no longer fails because of one unreadable table.** If a table listed in the project has no data behind it, the export used to abandon the whole archive and leave no file at all. It now archives everything else, leaves that table's data out, and finishes with a message naming the tables it skipped — and the archive records them, so a restore lists them rather than presenting them as complete. The export window also names the project it is archiving. See [Archive a Project](/guides/projects/archive-a-project/).

- **Table Update no longer discards Set Null when you save.** Its column mapper listed the columns you were updating under a **Source Column** heading, left **Target Column** empty, and offered no **Set Null** control at all — and saving the step silently dropped Set Null from every column that had it, so the step stopped clearing those values. The mapper now shows an **Update Column** heading alongside Constant, Expression, and Set Null, and keeps all four. If a step of yours cleared a column before, check that Set Null is still ticked. See [Table Update](/reference/workflow-steps/tables/table-update/).

- **Table Upsert works over the API on StarRocks workspaces.** The merge those workspaces use was reachable from the workflow engine but not from the REST API, which still required statements that path does not use, so an upsert could not be driven over the API there at all. See [Table Upsert](/reference/workflow-steps/tables/table-upsert/).

- **A Table Upsert inside a macro now stops instead of writing to the wrong table.** On StarRocks workspaces it merged into the project's own table rather than the macro's copy, silently. It now reports a clear error, and macro upserts on those workspaces stay unavailable until the underlying limitation is lifted. See [Table Upsert](/reference/workflow-steps/tables/table-upsert/).

- **Saving a Multi-Table Join step reports what needs fixing.** A save with anything left to resolve failed with an internal error instead of telling you what was wrong. It now switches to the tab holding the first problem and lists every issue, and each tab carries a badge with its count. The **Pick from canvas…** picker no longer opens behind the step form where it could not be reached. See [Multi-Table Join Step](/guides/workflows/multi-table-join-step/).

- **Dynamic Excel imports work again.** An Excel import configured to discover its columns from the worksheet, rather than from a saved column mapping, failed on every run. It now imports as configured. See [Import Excel](/reference/workflow-steps/import/import-excel/).

- **An empty worksheet no longer fails a multi-worksheet Excel import.** When an Excel import covers several worksheets and one of them is empty, the import now loads zero rows from that worksheet and carries on, instead of failing the whole step. See [Import Excel](/reference/workflow-steps/import/import-excel/).

- **JSON imports no longer drop columns that appear late in a large document.** A column whose first value appeared deep into a large JSON file could be silently missing from the imported table. Every column in the document is now included. See [Import JSON](/reference/workflow-steps/import/import-json/).

- **REST connections using Basic, API Key, or Bearer Token authentication now actually authenticate.** Only OAuth 2.0 credentials were ever sent, so a connection configured with any of the other three failed against APIs that check authentication. All four now work as configured. If you worked around this by putting the credential into **Default Headers** by hand, the connection's own authentication now takes precedence and that row can be removed. See [Generic REST Connection](/reference/connectors/rest/generic-rest/#authentication).

- **Listing endpoints from a Postman collection or API specification works again.** In the REST Request step, **Load Catalog** reported an error for every source — Postman collections and OpenAPI/Swagger specifications, whether picked from your documents or fetched from an address. It lists endpoints again, and tells you to pick a file or address first if you haven't chosen one yet. See [REST Request Step](/guides/workflows/rest-request-step/).

- **A REST connection's default headers are now actually sent.** Headers set under **Default Headers** on a REST connection were shown in a step's request preview but left off the real request. They are now sent with every request through that connection, including each page of a paginated read and each request in a per-row fan-out. A header set on an individual step still takes precedence over one of the same name on the connection. If you have a connection with default headers configured, check they are what you want to send. See [Generic REST Connection](/reference/connectors/rest/generic-rest/#default-headers).

- **Pushing to a Server Panel app's repository now rebuilds the app.** Publishing a Server Panel app from a PlaidCloud Git or GitHub connection always worked, but pushes to the connection's branch afterwards were not picked up — the app kept serving the version it was first built from until someone republished it by hand. Pushes now rebuild and redeploy automatically, as described in [Deploy a Panel App from Git](/guides/panel-apps/deploy-from-git/). A locked app still skips the rebuild until you unlock it. No change is needed to existing apps or connections.

- **Renaming a step's run conditions works again.** When you set conditions that must be met before a step runs, you can now rename each condition — edit the new **Name** field in the Configuration panel, or double-click the condition in the list. Right-click a condition for **Rename** and **Delete** as well. See [Run Conditions on a Step](/guides/workflows/step-conditions/).

- **Clearer error when an import can't read any columns.** When you set up or auto-create a CSV or text import and PlaidCloud can't read any columns from the source file — for example some Microsoft Access text exports, or a file whose delimiter or quoting doesn't match — it now tells you right away, as you save or create the import, instead of letting the step run and fail later with a confusing message. Adjust the delimiter, quote, and escape settings or fix the file, then try again. See [Import CSV](/reference/workflow-steps/import/import-csv/).

- **Managed bucket name collisions now explain themselves.** Creating a PlaidCloud Managed Bucket document account with a bucket name that's already in use previously failed with a generic "Internal server error". The Bucket Name field now flags the collision directly and explains that bucket names are globally unique, with guidance on picking a more specific name — for example, adding your company as a prefix. See [Add a PlaidCloud Managed Bucket Account](/guides/documents/adding-accounts/add-managed-bucket-account/).

- **OneDrive and SharePoint document accounts — browsing and download fixes.** Opening a configured OneDrive or SharePoint document account now reliably lists its folders and files instead of failing with an error, and downloading a file works even when your Microsoft administrator has turned off link sharing for the site. Downloads no longer depend on creating a shareable link, so a file in a locked-down site still opens instead of erroring. See [Add OneDrive / SharePoint Account](/guides/documents/adding-accounts/add-onedrive-account/).

- **Deleting a table an import reads from now warns you.** When you delete a table that an **Import: External Project Table** step reads from, PlaidCloud now recognizes it as in use and makes you confirm a force-deletion — ticking **Force the delete of the table?** — instead of offering a plain delete, so a table another project depends on can't be removed by accident. This includes references from a step in a *different* project that shares this project's data; those are shown in the confirmation without the other project's step details (you may not have access to it). See [Import Project Table](/reference/workflow-steps/import/import-project-table/).

- **Join steps — Output Columns fixes.** For Inner, Outer, Anti, and Cross Join, the Output Columns tab now lists only the columns you mapped from the two sources and drops stale rows when you remove a mapped source column; the column-mapper toolbar and multi-row selection are back; and Summarize is now a toggle that's off by default, so a join no longer forces its output to be grouped — and when you turn it on, new columns default to an aggregation based on their data type, which you can override per column. Multi-Table Join output columns now follow renames and removals in the join-graph designer. See [Table Inner Join](/reference/workflow-steps/tables/table-inner-join/) and [Multi-Table Join Step](/guides/workflows/multi-table-join-step/).

- **REST Request reliability fixes.** Variables now substitute reliably in JSON request bodies, per-request timeout and retry settings are honored (retries limited to idempotent methods, so a POST/PUT/PATCH is never re-sent), rate-limited responses are retried with backoff, and request credentials are masked in any captured raw JSON. A test request now shows the response status code even on success, and a single-object response imports as one row. Sensor- and webhook-triggered workflows can also read the trigger's metadata and inbound payload as variables. See [REST Request Step](/guides/workflows/rest-request-step/).

- **AI cost-tracing fixes.** Cost-tracing now handles model column names that contain spaces or symbols, resolves tables given by their friendly name, works on results from model-run steps and project copies, and works across all workspace types. Anomaly detection now flags unusually large swings and keeps quarter-labeled periods in real-time order across a year boundary, and two mislabeling bugs — a "from zero" jump when the weighting basis started empty, and a wrong-signed percentage change when the prior value was negative — are corrected.

- **Import/Export Project Table warns on an empty source.** When an Import Project Table or Export Project Table step copies from a source table that has no rows, it now finishes with a warning saying the source was empty — so an unexpectedly empty result is easy to spot rather than the step appearing to succeed silently. Most often it means the source project's data had not been built yet when the step ran. See [Import Project Table](/reference/workflow-steps/import/import-project-table/) and [Export to External Project Table](/reference/workflow-steps/export/export-project-table/).

- **Create and Open now opens the right view for a DAG workflow.** Using **Create and Open Config** on a new Advanced (DAG) workflow opened the classic steps grid instead of the Visual Workflow Designer canvas. It now opens the canvas, matching what you get by double-clicking the workflow. See [Advanced Workflows](/guides/workflows/advanced-workflows/).

- **Panel app dependencies can live next to the app.** A server-side Panel app built from a Git repository now installs a `requirements.txt` kept beside its entry point, not only one at the repository root — so an app stored in a subfolder of a shared repository can declare its own packages (for example `plotly`, `holoviews`, or `hvplot`) and no longer renders blank from a missing library. See [Creating a Panel App](/guides/panel-apps/creating/#add-dependencies).

- **Moving large or many documents between folders.** Moving several files at once — or a single large file — from one Document folder to another now works reliably. Moves run one at a time so the file list stays consistent, and a large move is given the time it needs to finish instead of being cut off partway.

- **The AI assistant no longer refuses expressions that reference underscore-named columns.** An expression referencing a column whose name starts with an underscore (for example `_MajorAccountFlag`) is now accepted. And when an expression tests a column with `is`, `is not`, or `not` — which on a column never matches any row, or errors, rather than doing what it looks like — the assistant steers you to the operator that works (`is_(None)` for a null test, `!=`, `~`) instead of a plain rejection.

- **The AI assistant no longer refuses valid functions.** Real functions that weren't in the expression picker's list — `rtrim`, `ltrim`, `to_char`, `substring`, and many more — were rejected as unknown, and writing any function name in capitals (`func.SUM`) was rejected even when the lowercase form was accepted. The assistant now checks names against your workspace's own function list as well as the picker's, and does so case-insensitively.

- **Panel apps no longer render with invisible text.** A platform-wide theme default was applied to every Panel app, including apps that don't use a matching page template. On those apps it painted the text white on a white page — the app looked blank, with nothing in the logs to explain it. Apps now keep their own look unless they opt into a themed template. Existing apps pick this up the next time they're rebuilt or republished.

- **The waking screen no longer changes how a Panel app looks.** While a Server Panel app was starting, the screen behind it set its own background and light/dark colors, and the app inherited them with no way to override — so an app could render on the wrong canvas color and follow your operating system's light/dark preference instead of its own. The screen is now fully removed once the app is up. It also drops nothing from the address you opened: query parameters an app reads, `?theme=dark` among them, now reach the app.

- **Expanding an archive keeps its folder structure.** Unpacking a `.zip` or `.tar.gz` into Document flattened everything into the destination folder — an archive containing `data/master/accounts.csv` produced a bare `accounts.csv`, so files with the same name in different folders collided. Nested archives now unpack with their folders intact. Flat archives and single-file `.gz`/`.bz2` are unchanged. On SFTP document accounts the destination folders must already exist, so expand a nested archive to a path you have already created there.

- **A bad schedule no longer breaks the Event Scheduler.** One scheduled event with an unusable recurrence — an impossible date such as the 31st of a 30-day month, or a malformed entry — made the workspace-wide Event Scheduler list and the schedule calendar fail with an internal server error, and could stop a project opening. A schedule that can't be read now simply shows a blank next run, and everything else on the screen loads normally. See [Event Scheduler](/administration/scheduled-events/event-scheduler/).

- **Workflow failures now say what actually went wrong.** When a workflow step failed inside a background job, the run log and the notification email showed only a generic message for the operation — "Exception importing directly from remote sql" — while the real cause, such as an expired password on the source system, appeared nowhere you could reach. The underlying failure is now carried through to the log and the email. When many tables fail on one shared cause it's reported once rather than per table, and credentials are stripped from the message.

- **REST requests to a different host no longer send the connection's credentials.** When a REST Request step used a full address rather than a path — including the paging links many APIs return — two things went wrong: the address was joined onto the connection's host and the request failed outright, and the connection's authentication and default headers were attached regardless of where the request was going. Full addresses are now used as given, and credentials and default headers are withheld unless the address points back at the connection's own host — so paging still works while a third-party address never receives your credentials. See [REST Request Step](/guides/workflows/rest-request-step/).

- **Editing a Basic-auth REST connection no longer loses its password.** Saving a change to a REST connection that used Basic authentication, without retyping the password, discarded the stored secret. Stored passwords are now preserved for all four authentication types. Two request-preview mismatches are also fixed: a header set in different letter cases on the step is folded the same way the real request folds it, and an empty header value is now sent empty instead of as the literal text "None". See [Generic REST Connection](/reference/connectors/rest/generic-rest/#authentication).

- **Combining tables keeps each column's dimension and formatting.** When a Union, Union All, Allocation, or multi-table Join merges several sources into one output column, the column's dimension, memo, and format settings were resolved from whichever source happened to sort last. A source that said nothing about a dimension could suppress one that named it, so a column stayed unassociated across rebuilds while a similar column recovered. Now a source that names a dimension wins over one that is silent, a passed-through column takes precedence over a renamed one, and a genuine disagreement between sources is reported in the step log instead of being resolved silently. Renaming an aggregated column — `SUM(amount)` to `total_amount` — also no longer copies the source column's dimension onto the total, which never identified a member of it. See [Table Union All](/reference/workflow-steps/tables/table-union-all/) and [Table Union Distinct](/reference/workflow-steps/tables/table-union-distinct/).

- **Table Melt honors the column mapping you authored.** Columns you deliberately left out of a melt's mapping were added back into the step behind the scenes, which on an aggregating step made the whole step fail. A mapping that names its value columns is now used exactly as written. See [Table Melt](/reference/workflow-steps/tables/table-melt/).

- **Copying a table from another project works again.** The step that copies a table between projects called an operation that no longer exists, so every run failed on the server. It now uses the same mechanism as the Import Project Table step, and reports a warning rather than failing when the source is empty. See [Import Project Table](/reference/workflow-steps/import/import-project-table/).

- **Row Count Assert works inside a macro.** A Row Count Assert step nested in a Macro Run or Macro Concurrent step failed with a server-side error; only top-level runs worked, which is why it went unnoticed. It now runs correctly at any nesting level. See [Row Count Assert](/reference/workflow-steps/workflow-control/row-count-assert/).

## Removed

- **Retired legacy import and export steps** — the SAS7BDAT import, HTML import, and HTML export steps have been removed. Use the current import and export steps for these formats instead.

- **Retired the X12 EDI import step** — the step type has been removed. It was never functional: every X12 EDI import failed on run. If you need EDI data in PlaidCloud, convert it to a supported format such as CSV or JSON and import that.

- **Retired the in-app Reset Password option** — the **Reset Password** item has been removed from the account (avatar) menu. To reset your password, use the **Forgot Password?** link on the sign-in page.

## Security

- **Security assignment changes now take effect immediately.** Editing a security group's scopes or members, deleting a group, changing a member's security groups, or activating and deactivating a member all applied on a delay — up to half a minute for most permissions, and for access to your workspace's Git server not until that person next signed in, which for someone whose access was revoked could be never. Every one of those changes is now applied the moment you save it, across the whole platform. Nothing to configure; review any access you previously granted or revoked and expect it to be accurate now. See [Managing Security Groups and Assignments](/administration/access/managing-security-groups-and-assignments/).
