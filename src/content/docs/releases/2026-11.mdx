## Added

- **PlaidXL builds, drills, explains and plans in Excel.** The **PlaidCloud** ribbon tab is grouped into **Connect**, **Insert**, **Refresh**, **Drill**, **Write** and **Share**, the common commands are also on a **PlaidXL** right-click menu and a **PlaidXL Cell** tab, and the main commands have keyboard shortcuts you can change, which don't fire while you type in a field. A command that fails says which one and why. A command run before you sign in opens the sign-in and runs once you're in, a sign-in works for one workspace so switching workspaces asks you to sign in to the new one (and switching back doesn't), and with a Microsoft Entra work account in Office, PlaidXL finds your workspace for you. See the [PlaidXL reference](/reference/cli/plaidxl/).
  - **Build a report in a few clicks.** The **Report** tab lays out a live report from a table, with a dimension drilled down the rows and another across the columns, and a `CELL` value at every intersection. **Build my first report** makes a sample from your own data. As you drill, a report inserts and removes whole rows and columns, and values you've typed, notes and formats stay with their row. See [Build a Report](/reference/cli/plaidxl/build-a-report/).
  - **Drill from any cell.** **Drill down**, **Drill up**, **Keep only** and **Remove only** turn a node into a live `DRILL` formula and edit it for you, from a node, a dimension heading or a report value. **Custom drill** previews the rows before you insert them, and the member picker inserts members or adds a dropdown of a node's children to cells. `DRILL` takes nodes to exclude or open, and can run across a row. See [Drill, Pick Members and Explain Numbers](/reference/cli/plaidxl/drill/).
  - **Explain a number.** **Explain this number** shows what a value calculates, whether it matches PlaidCloud now, and the table and workflow step it comes from. **Show detail rows** puts the rows behind a value on a sheet of their own, with a check that they add up.
  - **Governed metrics in Excel.** `PLAIDXL.METRIC` and `PLAIDXL.METRIC_BREAKDOWN` return a business metric as dashboards show it, and a `CELL` or `CELLS` with nothing to aggregate shows `0` for a sum and otherwise `#VALUE!` with the reason (blank in a `CELLS` spill), and **Metric...** lists your project's metrics with their current values. See [Metrics](/reference/cli/plaidxl/functions/#metrics).
  - **Plan by typing into a report.** Type a number over a `CELL` value and it's written to PlaidCloud: spread in proportion, equally or in the shape of another member, adjusted by an amount or a percentage, with held cells left alone. Mean, median, minimum, maximum, standard deviation and variance cells take typed values too, and a typed value follows its cell when rows or columns are inserted or deleted (values in deleted cells are reported). **Undo last write** reverses typed values and saves, newest first, and only the person and workspace that made a write can undo it. Undoing a sum, or a mean typed into an empty cell, keeps what has been written into the same cells since, and a write that was interrupted before it finished can't be undone. See [Type Values Into PlaidCloud](/reference/cli/plaidxl/write-values/).
  - **Refresh just what you need.** Refresh a sheet, a selection or every table, with each table's progress and **Cancel** in the task pane, or recalculate only the PlaidXL formulas. Retrieved tables arrive as Excel Tables formatted by data type, keep your own columns and number formats when they refresh, and refresh in their own place. A retrieve or refresh never overwrites other cells or overlaps another Excel Table, and whole-number IDs too large for Excel and dates before 1900 arrive as text. Retrieving a table again doesn't add it to the refresh list twice, **Stop refreshing** takes one off, and dimensions refresh with your tables. See [Refresh All Tables](/reference/cli/plaidxl/retrieve/#refresh-all-tables).
  - **Save writes straight away and can be undone.** **Save to PlaidCloud** writes without a confirmation, says what it did, and offers **Undo**. A sheet retrieved with a filter, a detail-rows sheet, or someone whose access covers only some rows replaces only those rows, so other people's rows are kept. A drill-through sheet whose members changed since you retrieved it isn't saved, and a save that fails names the restore point so the table can be put back. See [Save a Table to PlaidCloud](/reference/cli/plaidxl/retrieve/#save-a-table-to-plaidcloud).
  - **Ask Weave in Excel.** On the **Weave** tab, ask in plain words for a report, a formula, a drill or a table, or choose **Ask Weave about this cell**. Weave reads PlaidCloud as you and changes only the workbook, asks before replacing anything you've entered, never writes a formula that reaches outside the workbook, and each change can be reverted until you reload the pane. See [Ask Weave in Excel](/reference/cli/plaidxl/weave/).
  - **Share a values-only copy of one sheet or the whole workbook.** **Convert to values** converts a whole workbook, one sheet, or values with no way back (which asks first), changes only PlaidXL formulas and their spills, leaves formulas still calculating for a second try, and **Restore PlaidXL formulas** still works after you rename a sheet.
- **Preview on step forms.** Import: SQL, Execute: SQL, Extract: SQL, Export: SQL and Salesforce Query show up to 100 rows without running the step, and the Anaplan view and list reads show the columns and types they would produce. Click **Preview** on the **Source** tab. Variables are filled in as the run would fill them, but variable formats such as `{x:>9}` aren't supported. Preview only runs standard SQL functions; otherwise it tells you to run the step. It isn't available on locked projects, or for the Agent-based Execute SQL step. See [Import SQL](/reference/workflow-steps/import/import-sql/) and [Extract SQL](/reference/workflow-steps/tables/table-extract-sql/).
- **Usage Reports show what changed, narrow to a group, and flow into workflows.** **Overview** adds trend arrows against the previous period and a **Highlights** list that points to inactive members and to dashboards and apps nobody opened. Deactivated members aren't counted or listed as inactive. **Group** limits **Overview**, **Content** and the inactive list to one security group's members, and the date range adds **Previous month** and **This month** and is shared by every tab and remembered with your account. Every figure now has an explanation, tables use plain names such as **Members** and **Area**, rows open with Enter, loading and errors are clearer, and the last **Funnel** step shows how many members completed it. The new **Get Workspace Usage** step writes daily or monthly usage totals into a table on a schedule, with no member names, and each run, like **Get Workspace Members**, is recorded in the Security Log. See [Usage Reports](/administration/access/usage-reports/) and [Get Workspace Usage](/reference/workflow-steps/general/get-workspace-usage/).
- **AI assistants can unpublish a table and set a project's default dashboard audience.** `publish_manage` unpublishes a table along with its published view and any dashboard dataset no chart uses; a dataset a chart still uses stays, and so do the view and dataset when a report view is built on the published view, while the table still unpublishes. `project_upsert` sets `dashboard_default_audience`, the groups that new dashboards in the project are shared with, and `[]` clears it. See [Unpublish](/guides/data/publish/#unpublish-through-the-ai-assistant-or-mcp) and [Set the Default Audience Through the AI Assistant or MCP](/guides/dashboards/control-who-can-see-a-dashboard/#set-the-default-audience-through-the-ai-assistant-or-mcp).

- **A Git app lists your repositories and tells you what you can do.** **Git** in the app list shows your role (**Administrator**, **Contributor** or **Viewer**) and the workspace's repositories, each with its description, last-updated date, a clone address with a copy button, and **Open**. A **Set up Git on your computer** card walks through installing Git, creating a token and cloning, and **How to clone** reopens it. **View all in Git** opens the full Git interface and **Manage who can push** opens group management. Access is **Viewer**, **Contributor** (push app code to `apps`) or **Administrator** (push everywhere, including `udfs`), and a Viewer sees up to three workspace administrators to ask. The new **Git Contributors** group grants Contributor and can be a default group, so new members get it automatically; **Git Administration** grants Admin. A member's **Git** tab shows their Git username, level and the group that grants it. A member's Git account follows their membership: deactivating or removing a member blocks their Git account within about an hour, tokens and SSH keys included, and reactivating them unblocks it, with their repositories and history kept. Signing in to Git with single sign-on opens the member's own account. Contributors don't create repositories directly in the workspace's Git organization; repositories are created through PlaidCloud. App windows show a **Repository** section and UDFs have **Open**, and Git has a **← Back to** your workspace link. Every repository the platform creates, including app repositories and the built-in `apps` and `udfs` repositories, is readable by every signed-in member of the workspace, so members can open and republish apps without per-repository setup. A Git administrator can still make a repository private, which hides it from repository pickers and stops members publishing from it or running Git-backed UDF code stored in it. See [PlaidCloud Git](/guides/git/#open-git) and [Who can see repositories](/guides/connections/plaidcloud-git/#who-can-see-repositories).
- **Cost to Serve and Operational Transfer Pricing templates build on the Common Finance Model.** Start a project from **Cost to Serve** to spread operating expense to customers by the activity and driver you set for each department, and see each customer's margin after the cost of serving them, tied back to the ledger. Start from **Operational Transfer Pricing** to test each entity's profit level (return on sales, net cost plus or resale minus) against your policy ranges, with the true-up that brings an out-of-range entity back to target. Return on sales is EBIT divided by tested-party sales. See [Cost to Serve](/guides/projects/cost-to-serve/) and [Operational Transfer Pricing](/guides/projects/operational-transfer-pricing/).
- **OneStream and Anaplan feed Data Foundation, and OneStream has a read step.** Data Foundation reads OneStream consolidated results through a data adapter your OneStream administrator builds, and an Anaplan plan through an export action, and reconciles the group profit and loss to them. The new **OneStream: Read Adapter** step reads an adapter, one call for each consolidation member, into a table in any workflow. See [OneStream for Data Foundation](/guides/connections/onestream-for-data-foundation/), [Anaplan as a Data Foundation Source](/guides/connections/anaplan/#anaplan-as-a-data-foundation-source) and [OneStream: Read Adapter](/reference/workflow-steps/onestream/onestream-read-adapter/).
- **Choose how Data Foundation spreads shared costs.** **Actions > Allocations...** walks through which costs to spread, what to spread them by, where they land and what happens to a negative driver, for overhead to departments and for departments to products and customers, with a preview of one month that shows what is pooled, allocated and left unallocated. Rules you edit by hand are kept. See [Allocation Rules](/guides/projects/data-foundation/#allocation-rules).
- **Explain a number and name things your way in Data Foundation.** **Explain this number** splits a profit and loss figure into what the ledger holds, what was allocated in and out, and what was eliminated in the group, with the largest source documents, under your own row access. **Business names** give categories, P&L lines, metrics and columns the names your business uses, in reports, metrics and the assistant. See [Explain a Number](/guides/projects/data-foundation/#explain-a-number) and [Business Names](/guides/projects/data-foundation/#business-names).
- **Data Foundation writes a board pack with every load and lets you go back.** Every **Load** writes an Excel workbook and a PDF of the profit and loss dashboard to a folder of a document account; with reporting off the pack is the workbook alone, and the dialog says so. A restore point is made as each load starts and before each change to mappings or sources, and **Actions > Restore...** shows how many tables each one puts back and puts the project, dimensions included, back. The **Foundation** tab is clearer about what is happening: it shows an update that is still running or stopped part way, says why a folder of tables isn't a source, keeps **Check that totals tie out** pending until something has tied out, and recovers when a status read fails. Applying an update keeps your own edits to generated steps and notes any conflict. See [Board Pack](/guides/projects/data-foundation/#board-pack) and [Restore Points](/guides/projects/data-foundation/#restore-points).
- **Clone a Data Foundation project, or save one as a template.** **Actions > Clone...** copies a project with your model edits, metrics and analysis paths. **Save as my template...** saves a setup to a document account, and **From a template file...** starts a new private project from it, with its sources waiting to be connected. See [Clone a Project](/guides/projects/data-foundation/#clone-a-project) and [Save as My Template](/guides/projects/data-foundation/#save-as-my-template).
- **Data Foundation's setup checklist runs through handover, and the assistant can resolve what's left.** The checklist adds the nightly refresh, the evidence pack and handing the project to its owner, and says who set the project up. Ask the assistant to propose answers for accounts without a type, codes several sources use and file columns that matched nothing; it writes nothing, and you apply the answers. See [Get Started With Data Foundation](/guides/projects/data-foundation-getting-started/) and [Resolve Open Questions With Ask](/guides/projects/data-foundation/#resolve-open-questions-with-ask).

- **Voice in Weave on mobile takes one tap.** Tap the microphone, ask your question, and Weave sends it once you stop talking. Tap the microphone again to stop early, and it turns off by itself if nothing is heard. If you leave the **Weave** tab or background the app mid-sentence, your words stay in the question box unsent so you can review them. Run, Pause, Stop and Resume ignore an accidental double tap on their confirmation. Requires app version 1.3.0 or later. See [Use Your Voice](/guides/mobile-app/weave-on-mobile/#use-your-voice).

## Changed

- **PlaidCloud's web app and Python client library use the REST API, and JSON-RPC is deprecated.** The web app sends its requests to the REST API. With `plaidcloud-rpc` 1.25.0 or later, `SimpleRPC` calls go to the REST API with no change to your code; a call the REST API doesn't cover yet, or a workspace still on an older release, uses JSON-RPC as before. JSON-RPC will be removed in a later release, so upgrade your scripts and notebooks to `plaidcloud-rpc` 1.25.0 or later and write new integrations against the REST API. See [Command Line](/reference/cli/jupyter/command-line/).
- **Step forms follow one layout.** Tabs have standard names in a standard order: General, Settings, Source, Columns, Filters, Output and Advanced, with Header columns and Line columns on ERP posting forms. Required fields are marked with *, and a form only blocks saving for what the step needs.
- **Copy Project chooses table data and dimension members separately, copies data faster, and keeps a private copy's ERP write authorizations.** Under **Data to copy**, choose **Table data** — **No table data** (the default), **Full** or **Sample** — and, separately, **Copy dimension members**, which is on by default, so a copy without table rows still arrives with populated dimensions and is quick to make. **Full** and **Sample** copies copy several tables at once, so projects with many tables finish faster. **Copy Results** lists each dimension's outcome alongside the tables, and **Retry failed items** retries failed tables and dimensions together. A new copy made with data is private to you and keeps the source's ERP write authorizations that you could grant yourself; if the source posts Live, the copy arrives in Simulate, so nothing reaches the ERP until you switch it to Live. The REST API and the `project_copy` MCP tool take `dimension_members` too. See [Choosing How Much Data to Copy](/guides/projects/managing-projects/#choosing-how-much-data-to-copy) and [ERP Write Authorizations in the Copy](/guides/projects/managing-projects/#erp-write-authorizations-in-the-copy).
- **A table's details panel shows the steps that use it sooner.** Selecting another table clears the previous table's steps straight away, and steps in other projects that share this project's data are added a moment after the rest instead of holding up the whole panel. See [See Where a Table Is Used](/guides/projects/managing-tables-and-views/#see-where-a-table-is-used).
- **The row action menu (⋯) is at the left edge of every grid row.**
- **App tab icons are one consistent set**, in light and dark.
- **Saved ERP write steps with no validate setting open as validate-only.** This covers SAP Post, SAP Attach, NetSuite Post, Oracle EBS GL and AP Post, and Xero export. Steps explicitly set to run live stay live.
- **Long-running jobs show progress the same way everywhere.**
- **Stopping a workflow stops everything it started, and a run or step that can't finish fails instead of hanging.** Stop cancels import and dimension steps that were still queued, so later imports and dimension loads in the workspace start normally, and it also stops the workflow's queued or running connector (Singer) syncs. If a step's job can't start, the step fails with the reason instead of waiting forever: no worker starts it within about 40 minutes, a worker started it and then went away, its pod is stuck Pending for about 20 minutes, its image can't be pulled for about 5 minutes, or no pod is created for about 20 minutes. A connector sync that no runner picks up within about 30 minutes fails with a message naming the sync. While a step waits for a worker, its status message reads "Waiting for a worker…" with the minutes so far, and clears once the work starts. Stopping a macro stops every running copy of it, while stopping one copy, or a **Macro Concurrent** step giving up on a copy that stopped responding, leaves the workflow that called it running. A macro running only inside other workflows shows as **Running** in the workflow list, with **Stop** available and each step's status, start and end time from its latest run. A run whose server is lost ends as failed, and one still running after 12 hours fails with "Run failed: still running at the 12-hour limit. Re-run the workflow." See [Run a Workflow](/guides/workflows/run-a-workflow/#steps-that-never-start).
- **Resume, run history and run status match what actually ran.** Resuming a parent workflow runs everything a child workflow had left, even after you re-ran one of the child's steps on its own, and each call of a child workflow within one run has its own run-history entry. A step that restarts because its server stopped says so in its log, and `workflow_run_status` and the REST API's run outcome list the steps that failed but continued, in `continued_step_ids` and `continued_step_count`, instead of reporting the run as clean. See [Pause, Stop, and Resume](/guides/workflows/run-a-workflow/#pause-stop-and-resume) and [Continue on Error](/guides/workflows/continue-on-error/).
- **Step errors show their own message.** An error PlaidCloud didn't anticipate reads "The step stopped on an unexpected error (*type*): *message*". The **Needs attention** cards on the Launcher show the error in one line and leave out runs of workflows that have since been deleted. See [Managing Step Errors](/guides/workflows/managing-step-errors/).
- **An ERP extract that doesn't finish fails its step, and Resume continues it.** When **SAP: Ad-Hoc Extract** pauses at its row or time limit or its agent doesn't reply in time, or a Salesforce, Oracle Fusion bulk or HFM/FCCS export job is still running when the step stops waiting, the step fails so the steps after it don't run on a partial table. Resume the workflow or re-run the step and the extract continues from where it stopped, on the same job. See [Run Limits](/guides/connections/sap-adhoc-extract/#run-limits) and [Salesforce: Query Object](/reference/workflow-steps/salesforce/query-salesforce-object/#when-a-run-does-not-finish).
- **Cancelling an export stops its query in the warehouse.** When an export or download is cancelled, including by stopping its workflow, the query reading its data stops too on Lakehouse v2, Snowflake, Databricks, PostgreSQL and Greenplum, and an export to a remote database stops reading its source, instead of running on to the end.
- **REST, Import REST and Import Postman steps are converted to REST Request when your workspace upgrades.** A step that can't be converted cleanly stays as it was. See [REST Request Step](/guides/workflows/rest-request-step/).
- **Project Architects see all rows of row-restricted tables in dashboards**, matching what they see in Analyze. Taking away Architect access takes effect in dashboards immediately — whether you change someone's role, remove them or their group from the project, change the project's access type, restore an earlier project version, or delete a security group. See [Managing Row Access](/administration/access/managing-security-groups-and-assignments/#managing-row-access).
- **Members limited by Row Access can run their own SQL queries and export the results.** On a project with Row Access, a member who isn't an Architect gets exactly the rows their grants allow from their own queries on query screens, and can export them to CSV, Excel or JSON, with the **Rows limited by your access** notice; before, these were refused. A grant value containing a percent sign (`%`) now returns its rows on query screens, and downloading such a query as CSV works. Their own free-form SQL on Snowflake or Databricks, exports of their own SQL from Postgres-family warehouses, and reading a governed table as of a snapshot are still refused, and a view must keep the governed column under its original name to be filtered. See [Row Access and Queries You Write Yourself](/administration/access/managing-security-groups-and-assignments/#row-access-and-queries-you-write-yourself).
- **A dashboard link opened after your session has expired takes you to that dashboard once you sign in.** See [Using Dashboards](/guides/dashboards/using-dashboards/).
- **MCP tools refuse a field they don't recognise** and name it in the error, instead of ignoring it. `workflow_upsert` takes `memo` and accepts `description` as another name for it. See [Unknown Fields Are Refused](/integrations/ai-coding-agents/getting-started/#unknown-fields-are-refused).
- **On Lakehouse v2, the lakehouse writes Parquet exports to Google Cloud Storage itself.** An export to a Google Cloud Storage document account goes straight into the account's bucket, written with the account's own credentials, instead of every row passing through PlaidCloud first. Exports to Amazon S3 and Azure Blob Storage accounts work as before. See [Export to Parquet](/reference/workflow-steps/export/export-to-parquet/).
- **Slack, Microsoft Teams and Web Hook steps say why a message wasn't sent.** The step's error names the server it tried to reach and, for Slack and Teams, the connection, and says what went wrong: for example, Slack no longer recognises the webhook, the channel can't be posted to, the server can't be found or doesn't answer within 60 seconds, or the connection has been deleted. A Slack or Teams webhook URL is never shown, because anyone who has it can post as your integration. See [Notify via Slack](/reference/workflow-steps/notifications/notify-via-slack/).
- **Access tokens for a project's service account last at least 24 hours.** Workflow jobs that run as the project, such as UDF steps, get tokens that last 24 hours. A shorter lifetime is raised when your workspace upgrades, and a longer one you set is kept.
- **A workspace's organization, owner, data center, release and version are set by PlaidCloud.** In the control plane, these fields are read-only when you edit a workspace, and a workspace you create is owned by you and placed on the default data center and release channel. Use **Set Version** to change versions, and ask PlaidCloud Support to move a workspace, change its owner or channel, or pin it. See [Workspace Configuration](/administration/control-plane/workspace-configuration/#primary-settings).

## Fixed

- **Invalid project settings are reported with a clear message.** An unknown environment or document account, a slug that is taken or reserved, or an invalid storage type or posting mode now returns a message naming the problem instead of a generic server error. Through the REST API this is a 400 rather than a 500, and through the AI assistant or MCP it is an invalid-argument error.
- **The REST API's dimension values request works.** `POST /rest/v1/analyze/query/retrieve-dimension-values` was answered as a grid request and refused as invalid. It now returns one aggregated value for each column in `value_columns`, and a grid, one value for each pair of a row filter and a column filter, has its own `POST /rest/v1/analyze/query/retrieve-dimension-cells`.
- **Slow table reads and file handling no longer hold up other requests.** Reading a table's columns from the warehouse, registering a Data Foundation file, exporting to Excel, reading a REST or SOAP import's response, finding where a document account is used, and checking a Panel app's code or logo could each pause every other request the same server was handling until it finished. They now run alongside those requests.
- **The project and workflow variable dialogs scroll.** On a small screen or low resolution the add and edit dialog was taller than the window, so the **Create** and **Update** buttons could be out of reach. The form now scrolls and the buttons stay at the bottom.
- **Files over 256 MiB in an Azure Blob Storage document account can be copied, moved and renamed.** Each of these used to fail on a file that size, and so did moving or renaming a folder holding one.
- **On Lakehouse v2, a table's row count reflects what was just written to it.** A step or import that wrote a table could record the row count from before the write, so a table just loaded showed 0 rows and an import could report 0 rows imported. The count is now read once the new rows are visible everywhere, so the steps after it read them too. Switching a table to another branch, or merging a branch into it, also updates its row and column counts.
- **Weave's empty-values check compares each run with what earlier runs really left.** A step's empty values were often counted just after the step emptied its table to refill it, so its earlier runs looked as if they had none, and a column that had always been partly empty was reported as if it had only just become so. Each run is now counted as the step left its table. Counts recorded before can't be told apart from good ones, so they aren't used: each step's empty-values check starts its history again, and is reported as unchecked until five runs have been counted. The rows and spread-of-values checks also no longer credit a step with a write another step makes to the same table more than two seconds after it finishes. See [What Weave Checks](/guides/ai-assistant/weave-findings/).
- **Data Foundation keeps the precision of inverted exchange rates and decimal thresholds.** A rate PlaidCloud turns around, because your rates are quoted from the reporting currency into another currency, could be rounded to six decimal places, which left amounts in a currency with a small rate, such as the Indonesian rupiah, around 1% off. Inverted rates now keep 12 decimal places. A `group_amber` or `group_red` threshold with decimals, such as `0.5`, was rounded to a whole number. Your next Load uses the precise values. See [Exchange Rates](/guides/projects/data-foundation/#exchange-rates).
- **Alerts and digests stop for a deactivated member.** A Panel app alert or digest whose owner was deactivated kept checking and sending. It now pauses while they're deactivated and resumes if they're reactivated. See [Alerts and Digests](/guides/panel-apps/alerts-and-digests/).
- **Asking the REST API for a deleted connection returns 404.** Requesting a connection that has been deleted, or an ID that doesn't exist, answered with a generic server error (500). It now returns 404 with a message naming the connection ID.

## Security

- **Password sign-ins need an authenticator app, and passwords are stronger.** A member who signs in with a PlaidCloud password is asked to set up an authenticator app at their next sign-in, and enters its code each time after that. Single sign-on, Google, Microsoft and GitHub sign-in, API tokens and service accounts are unchanged. A new password needs at least 12 characters and can't be your username or one of your last six passwords, and after repeated failed sign-in attempts the account is locked for a short time. A stricter rule your workspace already had is kept. See [Member Authentication](/administration/access/member-authentication/).
- **Connections point at public and private-network addresses.** A connection can't point at a loopback, link-local or cloud metadata address, and the error names the host and the address it resolved to. Addresses on your private network are unaffected. See [Addresses a Connection Can't Reach](/guides/connections/create-connection/#addresses-a-connection-cant-reach).
- **Saved connection credentials are shown only to members who can edit connections or workflows.** Through the REST API and MCP, a saved connection's passwords, tokens and keys are masked for other members, who can still open and browse it. See [Who Sees a Connection's Credentials](/guides/connections/create-connection/#who-sees-a-connections-credentials).
- **App builds run without access to your workspace's Git credentials.**
- **Proxy download links are valid for one hour.** With **Use PlaidCloud Proxy Download** on, open the download again for a new link when one has expired. See [Services](/administration/control-plane/workspace-configuration/#services).
- **Adding people to security groups follows the permissions you hold.** You can add a member to a security group, choose a member's groups or invite an Architect when you hold every permission the group grants. Workspace admins are not limited. See [Managing Security Groups](/administration/access/managing-security-groups-and-assignments/#managing-security-groups).
- **A connection's owners, or a workspace administrator, change its settings and switch it on or off.** Changing a connection's settings through the REST API, JSON-RPC and the AI assistant or MCP takes one of its owners, or a workspace administrator for a connection with no owner. Enabling, disabling, locking and unlocking a connection take an owner or a workspace administrator, and a request naming several connections applies only when you can change all of them. Only a workspace administrator can choose the workspace's default AI connection, and a connection a member owns is the default only when no connection owned by an administrator, or with no owner, could be. See [Edit a Connection](/guides/connections/create-connection/#edit-a-connection) and [LLM Providers](/integrations/ai-architecture/llm-providers/#what-the-connection-holds).
- **Saving Row Access keeps a granted value that its source doesn't have.** A value a security group was granted stays in the grid, marked, when the table has no rows with it, the dimension doesn't have the member, or the list doesn't have it. **Save** asks whether to keep each such value or remove it. See [The Row Access Grid](/administration/access/managing-security-groups-and-assignments/#the-row-access-grid).
- **Only an account's owners can restore its earlier versions.** Restoring a document account to an earlier version, holding or releasing a version, and taking a backup take one of the account's owners, and none of them is available on a system-managed account. Seeing an account's version history needs access to the account.
- **`query_run` runs read-only statements.** The `query_run` tool that the AI assistant and MCP clients use accepts one SELECT or WITH statement, an EXPLAIN of one, or a SHOW; any other statement is not run. To change data, use `query_transform`. The SQL in an MCP table export follows the same rule. Through the REST and JSON-RPC APIs, it also applies to running a query, building column facets, downloading a query as CSV, exporting a query to a remote database and exporting table data with your own query, for members who can't change project data; a refused query returns 403. Explain Analyze runs the query to measure it, so in the query log and the lakehouse it accepts only a query that reads, and on a project with row access only a project Architect can run it from the query log.
- **DataFrame writes, record saves and clears into a row-restricted table change only the rows you can see.** When Row Access limits your rows, writing a DataFrame to a restricted table or clearing it with the Python client, or saving records to it or clearing it through the REST API, changes only your own rows, and a load carrying a row outside your access is refused before anything changes, naming the values it found. Project Architects, members who see every row, and workflow runs write the whole table. Each of these writes that a person makes, to any table, is recorded in the Security Log. See [Loading Data Into a Restricted Table](/administration/access/managing-security-groups-and-assignments/#loading-data-into-a-restricted-table).
- **Imports, copies, restores and deletes on a row-restricted table need every row to be visible to you.** When Row Access limits your rows, importing a file into a restricted table, copying a table into it from another project, switching or merging its branch, restoring it, deleting it, bringing it back after it was deleted, or any other action that replaces the whole table runs only when you can see every row of the table; otherwise it is refused and nothing changes. Saving a table's rows through the REST API changes only your own rows, as the other loads do. Project Architects, members who see every row, and workflow runs are unaffected, and these actions are recorded in the Security Log too. See [Loading Data Into a Restricted Table](/administration/access/managing-security-groups-and-assignments/#loading-data-into-a-restricted-table).
