## Added

- **PlaidXL builds, drills, explains and plans in Excel.** The **PlaidCloud** ribbon tab is grouped into **Connect**, **Insert**, **Refresh**, **Drill**, **Write** and **Share**, the common commands are also on a **PlaidXL** right-click menu and a **PlaidXL Cell** tab, and the main commands have keyboard shortcuts you can change. A command run before you sign in opens the sign-in and runs once you're in, and with a Microsoft Entra work account in Office, PlaidXL finds your workspace for you. See the [PlaidXL reference](/reference/cli/plaidxl/).
  - **Build a report in a few clicks.** The **Report** tab lays out a live report from a table, with a dimension drilled down the rows and another across the columns, and a `CELL` value at every intersection. **Build my first report** makes a sample from your own data. As you drill, a report inserts and removes whole rows and columns, and values you've typed, notes and formats stay with their row. See [Build a Report](/reference/cli/plaidxl/build-a-report/).
  - **Drill from any cell.** **Drill down**, **Drill up**, **Keep only** and **Remove only** turn a node into a live `DRILL` formula and edit it for you, from a node, a dimension heading or a report value. **Custom drill** previews the rows before you insert them, and the member picker inserts members or adds a dropdown of a node's children to cells. `DRILL` takes nodes to exclude or open, and can run across a row. See [Drill, Pick Members and Explain Numbers](/reference/cli/plaidxl/drill/).
  - **Explain a number.** **Explain this number** shows what a value calculates, whether it matches PlaidCloud now, and the table and workflow step it comes from. **Show detail rows** puts the rows behind a value on a sheet of their own, with a check that they add up.
  - **Governed metrics in Excel.** `PLAIDXL.METRIC` and `PLAIDXL.METRIC_BREAKDOWN` return a business metric as dashboards show it, and **Metric...** lists your project's metrics with their current values. See [Metrics](/reference/cli/plaidxl/functions/#metrics).
  - **Plan by typing into a report.** Type a number over a `CELL` value and it's written to PlaidCloud: spread in proportion, equally or in the shape of another member, adjusted by an amount or a percentage, with held cells left alone. Mean, median, minimum, maximum, standard deviation and variance cells take typed values too. **Undo last write** reverses typed values and saves, newest first. See [Type Values Into PlaidCloud](/reference/cli/plaidxl/write-values/).
  - **Refresh just what you need.** Refresh a sheet, a selection or every table, with each table's progress and **Cancel** in the task pane, or recalculate only the PlaidXL formulas. Retrieved tables arrive as Excel Tables formatted by data type, keep your own columns and number formats when they refresh, and refresh in their own place. Retrieving a table again doesn't add it to the refresh list twice, **Stop refreshing** takes one off, and dimensions refresh with your tables. See [Refresh All Tables](/reference/cli/plaidxl/retrieve/#refresh-all-tables).
  - **Save writes straight away and can be undone.** **Save to PlaidCloud** writes without a confirmation, says what it did, and offers **Undo**. A sheet retrieved with a filter, a detail-rows sheet, or someone whose access covers only some rows replaces only those rows, so other people's rows are kept. See [Save a Table to PlaidCloud](/reference/cli/plaidxl/retrieve/#save-a-table-to-plaidcloud).
  - **Ask Weave in Excel.** On the **Weave** tab, ask in plain words for a report, a formula, a drill or a table, or choose **Ask Weave about this cell**. Weave reads PlaidCloud as you and changes only the workbook, asks before replacing anything you've entered, and each change can be reverted until you reload the pane. See [Ask Weave in Excel](/reference/cli/plaidxl/weave/).
  - **Share a values-only copy of one sheet or the whole workbook.** **Convert to values** converts a whole workbook, one sheet, or values with no way back, and **Restore PlaidXL formulas** still works after you rename a sheet.
- **Preview on step forms.** Import: SQL, Execute: SQL, Extract: SQL, Export: SQL and Salesforce Query show up to 100 rows without running the step, and the Anaplan view and list reads show the columns and types they would produce. Click **Preview** on the **Source** tab. Variables are filled in as the run would fill them, but variable formats such as `{x:>9}` aren't supported. Preview only runs standard SQL functions; otherwise it tells you to run the step. It isn't available on locked projects, or for the Agent-based Execute SQL step. See [Import SQL](/reference/workflow-steps/import/import-sql/) and [Extract SQL](/reference/workflow-steps/tables/table-extract-sql/).
- **AI assistants can unpublish a table and set a project's default dashboard audience.** `publish_manage` unpublishes a table along with its published view and any dashboard dataset no chart uses; a dataset a chart still uses stays, and so do the view and dataset when a report view is built on the published view, while the table still unpublishes. `project_upsert` sets `dashboard_default_audience`, the groups that new dashboards in the project are shared with, and `[]` clears it. See [Unpublish](/guides/data/publish/#unpublish-through-the-ai-assistant-or-mcp) and [Set the Default Audience Through the AI Assistant or MCP](/guides/dashboards/control-who-can-see-a-dashboard/#set-the-default-audience-through-the-ai-assistant-or-mcp).

- **Voice in Weave on mobile takes one tap.** Tap the microphone, ask your question, and Weave sends it once you stop talking. Tap the microphone again to stop early, and it turns off by itself if nothing is heard. If you leave the **Weave** tab or background the app mid-sentence, your words stay in the question box unsent so you can review them. Run, Pause, Stop and Resume ignore an accidental double tap on their confirmation. Requires app version 1.3.0 or later. See [Use Your Voice](/guides/mobile-app/weave-on-mobile/#use-your-voice).

## Changed

- **Step forms follow one layout.** Tabs have standard names in a standard order: General, Settings, Source, Columns, Filters, Output and Advanced, with Header columns and Line columns on ERP posting forms. Required fields are marked with *, and a form only blocks saving for what the step needs.
- **Copy Project chooses table data and dimension members separately, copies data faster, and keeps a private copy's ERP write authorizations.** Under **Data to copy**, choose **Table data** — **No table data** (the default), **Full** or **Sample** — and, separately, **Copy dimension members**, which is on by default, so a copy without table rows still arrives with populated dimensions and is quick to make. **Full** and **Sample** copies copy several tables at once, so projects with many tables finish faster. **Copy Results** lists each dimension's outcome alongside the tables, and **Retry failed items** retries failed tables and dimensions together. A new copy made with data is private to you and keeps the source's ERP write authorizations that you could grant yourself; if the source posts Live, the copy arrives in Simulate, so nothing reaches the ERP until you switch it to Live. The REST API and the `project_copy` MCP tool take `dimension_members` too. See [Choosing How Much Data to Copy](/guides/projects/managing-projects/#choosing-how-much-data-to-copy) and [ERP Write Authorizations in the Copy](/guides/projects/managing-projects/#erp-write-authorizations-in-the-copy).
- **The row action menu (⋯) is at the left edge of every grid row.**
- **Saved ERP write steps with no validate setting open as validate-only.** This covers SAP Post, SAP Attach, NetSuite Post, Oracle EBS GL and AP Post, and Xero export. Steps explicitly set to run live stay live.
- **Long-running jobs show progress the same way everywhere.**
- **Stopping a workflow stops everything it started, and a step that can't start fails instead of hanging.** Stop cancels import and dimension steps that were still queued, so later imports and dimension loads in the workspace start normally, and it also stops the workflow's queued or running connector (Singer) syncs. If a step's job can't start, the step fails with the reason instead of waiting forever: no worker starts it within about 40 minutes, a worker started it and then went away, its pod is stuck Pending for about 20 minutes, its image can't be pulled for about 5 minutes, or no pod is created for about 20 minutes. A connector sync that no runner picks up within about 30 minutes fails with a message naming the sync. While a step waits for a worker, its status message reads "Waiting for a worker…" with the minutes so far, and clears once the work starts. See [Run a Workflow](/guides/workflows/run-a-workflow/#steps-that-never-start).
- **REST, Import REST and Import Postman steps are converted to REST Request when your workspace upgrades.** A step that can't be converted cleanly stays as it was. See [REST Request Step](/guides/workflows/rest-request-step/).
- **Project Architects see all rows of row-restricted tables in dashboards**, matching what they see in Analyze. Taking away Architect access takes effect in dashboards immediately — whether you change someone's role, remove them or their group from the project, change the project's access type, restore an earlier project version, or delete a security group. A former Architect no longer sees every row of row-restricted data. See [Managing Row Access](/administration/access/managing-security-groups-and-assignments/#managing-row-access).
- **A dashboard link opened after your session has expired takes you to that dashboard once you sign in.** See [Using Dashboards](/guides/dashboards/using-dashboards/).
- **MCP tools refuse a field they don't recognise** and name it in the error, instead of ignoring it. `workflow_upsert` takes `memo` and accepts `description` as another name for it. See [Unknown Fields Are Refused](/integrations/ai-coding-agents/getting-started/#unknown-fields-are-refused).
- **On Lakehouse v2, the lakehouse writes Parquet exports to Google Cloud Storage itself.** An export to a Google Cloud Storage document account goes straight into the account's bucket, written with the account's own credentials, instead of every row passing through PlaidCloud first. Exports to Amazon S3 and Azure Blob Storage accounts work as before. See [Export to Parquet](/reference/workflow-steps/export/export-to-parquet/).
- **Slack, Microsoft Teams and Web Hook steps say why a message wasn't sent.** The step's error names the server it tried to reach and, for Slack and Teams, the connection, and says what went wrong: for example, Slack no longer recognises the webhook, the channel can't be posted to, the server can't be found or doesn't answer within 60 seconds, or the connection has been deleted. A Slack or Teams webhook URL is never shown, because anyone who has it can post as your integration. See [Notify via Slack](/reference/workflow-steps/notifications/notify-via-slack/).

## Fixed

- **Invalid project settings are reported with a clear message.** An unknown environment or document account, a slug that is taken or reserved, or an invalid storage type or posting mode now returns a message naming the problem instead of a generic server error. Through the REST API this is a 400 rather than a 500, and through the AI assistant or MCP it is an invalid-argument error.
- **The REST API's dimension values request works.** `POST /rest/v1/analyze/query/retrieve-dimension-values` was answered as a grid request and refused as invalid. It now returns one aggregated value for each column in `value_columns`, and a grid, one value for each pair of a row filter and a column filter, has its own `POST /rest/v1/analyze/query/retrieve-dimension-cells`.
- **Slow table reads and file handling no longer hold up other requests.** Reading a table's columns from the warehouse, registering a Data Foundation file, exporting to Excel, reading a REST or SOAP import's response, finding where a document account is used, and checking a Panel app's code or logo could each pause every other request the same server was handling until it finished. They now run alongside those requests.
- **The project and workflow variable dialogs scroll.** On a small screen or low resolution the add and edit dialog was taller than the window, so the **Create** and **Update** buttons could be out of reach. The form now scrolls and the buttons stay at the bottom.
- **Files over 256 MiB in an Azure Blob Storage document account can be copied, moved and renamed.** Each of these used to fail on a file that size, and so did moving or renaming a folder holding one.
- **On Lakehouse v2, a table's row count reflects what was just written to it.** A step or import that wrote a table could record the row count from before the write, so a table just loaded showed 0 rows and an import could report 0 rows imported. The count is now read once the new rows are visible everywhere, so the steps after it read them too. Switching a table to another branch, or merging a branch into it, also updates its row and column counts.
- **Weave's empty-values check compares each run with what earlier runs really left.** A step's empty values were often counted just after the step emptied its table to refill it, so its earlier runs looked as if they had none, and a column that had always been partly empty was reported as if it had only just become so. Each run is now counted as the step left its table. Counts recorded before can't be told apart from good ones, so they aren't used: each step's empty-values check starts its history again, and is reported as unchecked until five runs have been counted. The rows and spread-of-values checks also no longer credit a step with a write another step makes to the same table more than two seconds after it finishes. See [What Weave Checks](/guides/ai-assistant/weave-findings/).
- **Asking the REST API for a deleted connection returns 404.** Requesting a connection that has been deleted, or an ID that doesn't exist, answered with a generic server error (500). It now returns 404 with a message naming the connection ID.

## Security

- **Only an account's owners can restore its earlier versions.** Restoring a document account to an earlier version, holding or releasing a version, and taking a backup now need you to be one of the account's owners, and none of them is available on a system-managed account. Seeing an account's version history needs access to the account.
