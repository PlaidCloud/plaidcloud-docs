## Added

- **A Trust Center in the control plane gives your security team PlaidCloud's security documents.** Admin and Security users open **Trust Center** for their organization, download public documents such as the subprocessor list and DPA right away, and sign the security-documentation NDA once for the organization to unlock restricted documents such as the SOC 2 Type II report. Other Admin and Security users see who signed and when. An organization whose contract already includes an NDA can have it marked on file so documents unlock without signing. Restricted downloads are watermarked and recorded, and a new NDA version needs accepting again. Admin and Security users can also opt in, per organization, to a daily email summarizing new or updated documents and new NDA versions; it never contains the documents themselves. See [Trust Center](/administration/control-plane/trust-center/).
- **PlaidXL builds, drills, explains and plans in Excel.** The **PlaidCloud** ribbon tab is grouped into **Connect**, **Insert**, **Refresh**, **Drill**, **Write** and **Share**, the common commands are also on a **PlaidXL** right-click menu and a **PlaidXL Cell** tab, and the main commands have keyboard shortcuts you can change, which don't fire while you type in a field. A command that fails says which one and why. A command run before you sign in opens the sign-in and runs once you're in, a sign-in works for one workspace so switching workspaces asks you to sign in to the new one (and switching back doesn't), and with a Microsoft Entra work account in Office, PlaidXL finds your workspace for you. See the [PlaidXL reference](/reference/cli/plaidxl/).
  - **Build a report in a few clicks.** The **Report** tab lays out a live report from a table, with a dimension drilled down the rows and another across the columns, and a `CELL` value at every intersection. **Build my first report** makes a sample from your own data. As you drill, a report inserts and removes whole rows and columns, and values you've typed, notes and formats stay with their row. See [Build a Report](/reference/cli/plaidxl/build-a-report/).
  - **Drill from any cell.** **Drill down**, **Drill up**, **Keep only** and **Remove only** turn a node into a live `DRILL` formula and edit it for you, from a node, a dimension heading or a report value. **Custom drill** previews the rows before you insert them, and the member picker inserts members or adds a dropdown of a node's children to cells. `DRILL` takes nodes to exclude or open, and can run across a row. See [Drill, Pick Members and Explain Numbers](/reference/cli/plaidxl/drill/).
  - **Explain a number.** **Explain this number** shows what a value calculates, whether it matches PlaidCloud now, and the table and workflow step it comes from. **Show detail rows** puts the rows behind a value on a sheet of their own, with a check that they add up.
  - **Governed metrics in Excel.** `PLAIDXL.METRIC` and `PLAIDXL.METRIC_BREAKDOWN` return a business metric as dashboards show it, and a `CELL` or `CELLS` with nothing to aggregate shows `0` for a sum and otherwise `#VALUE!` with the reason (blank in a `CELLS` spill), and **Metric...** lists your project's metrics with their current values. A metric can filter on more than one alternate hierarchy and mix an alternate-hierarchy member with members of other dimensions. See [Metrics](/reference/cli/plaidxl/functions/#metrics).
  - **Plan by typing into a report.** Type a number over a `CELL` value and it's written to PlaidCloud: spread in proportion, equally or in the shape of another member, adjusted by an amount or a percentage, with held cells left alone. Mean, median, minimum, maximum, standard deviation and variance cells take typed values too, and a typed value follows its cell when rows or columns are inserted or deleted (values in deleted cells are reported). **Undo last write** reverses typed values and saves, newest first, and only the person and workspace that made a write can undo it. Undoing a sum, or a mean typed into an empty cell, keeps what has been written into the same cells since, and a write that was interrupted before it finished can't be undone. See [Type Values Into PlaidCloud](/reference/cli/plaidxl/write-values/).
  - **Refresh just what you need.** Refresh a sheet, a selection or every table, with each table's progress and **Cancel** in the task pane, or recalculate only the PlaidXL formulas. Large tables retrieve much faster in Excel on the web and in current desktop Excel (a 143,000-row, 77-column table takes about a minute instead of over ten; older Excel versions work as before), and text longer than an Excel cell holds is flagged and kept from being saved cut. Retrieved tables arrive as Excel Tables formatted by data type, keep your own columns and number formats when they refresh, and refresh in their own place. A retrieve or refresh never overwrites other cells or overlaps another Excel Table, and whole-number IDs too large for Excel and dates before 1900 arrive as text. Retrieving a table again doesn't add it to the refresh list twice, **Stop refreshing** takes one off, and dimensions refresh with your tables. See [Refresh All Tables](/reference/cli/plaidxl/retrieve/#refresh-all-tables).
  - **Save writes straight away and can be undone.** **Save to PlaidCloud** writes without a confirmation, says what it did, and offers **Undo**, which works for up to 7 days after each save on Lakehouse tables. A sheet retrieved with a filter, a detail-rows sheet, or someone whose access covers only some rows replaces only those rows, so other people's rows are kept. A drill-through sheet whose members changed since you retrieved it isn't saved, and a save that fails names the restore point so the table can be put back. See [Save a Table to PlaidCloud](/reference/cli/plaidxl/retrieve/#save-a-table-to-plaidcloud).
  - **Ask Weave in Excel.** On the **Weave** tab, ask in plain words for a report, a formula, a drill or a table, or choose **Ask Weave about this cell**. Weave reads PlaidCloud as you and changes only the workbook, asks before replacing anything you've entered, never writes a formula that reaches outside the workbook, and each change can be reverted until you reload the pane. See [Ask Weave in Excel](/reference/cli/plaidxl/weave/).
  - **Share a values-only copy of one sheet or the whole workbook.** **Convert to values** converts a whole workbook, one sheet, or values with no way back (which asks first), changes only PlaidXL formulas and their spills, leaves formulas still calculating for a second try, and **Restore PlaidXL formulas** still works after you rename a sheet.
  - **The task pane has a new look.** It matches the PlaidCloud web app, with brand blue, rail-style tabs and lists, and tables, dimensions, projects and columns in bounded scrolling cards. Keyboard focus shows a clear ring, and the pane follows your light or dark Office theme. The tabs sit three across and two down in a narrow pane and in one row from 560 pixels wide. See [Light and Dark Theme](/reference/cli/plaidxl/connect/#light-and-dark-theme).
  - **Numbers in the pane follow Excel's display language.** Row and column counts and the refresh, recalculation, Explain, Formulas, Report and planning messages show numbers the way your Excel does, so German Excel shows 4.812.233. Values written to cells don't change.
  - **A sheet's tab turns yellow while it refreshes.** During **Refresh All Tables**, whether from the pane, the ribbon or Weave, each sheet's tab is yellow while that sheet refreshes, then returns to its previous colour, including your own, when it finishes, fails or is cancelled. If you save and close the workbook part-way, the tabs are put back the next time PlaidXL starts in it. See [Refresh All Tables](/reference/cli/plaidxl/retrieve/#refresh-all-tables).
- **Google Drive document accounts work in workflows.** A Google Drive account, set up with a Google Cloud service account whose key JSON you enter as the account's private key, can list, import, export, copy, move, rename and delete files and create folders from a workflow. Its top-level locations are the folders shared with the service account and the Shared Drives it belongs to, and a Google Sheet reads as an `.xlsx` export. A folder in someone's My Drive accepts overwrites of existing files but not new ones, so create the file first or use a Shared Drive. A missing folder lists as empty, and throttling and temporary Google errors are retried automatically. See [Add Google Drive Account](/guides/documents/adding-accounts/add-google-drive-account/#using-the-account-in-workflows).
- **Sage 100 connects on-premises, for Data Foundation and for posting.** Through a PlaidLink agent on a Windows computer in your network, Data Foundation reads a Sage 100 company's chart of accounts, fiscal calendar, journals and period balances, in the Premium, Standard and Advanced editions, one company per connection. A workflow can also post General Ledger journals and Accounts Payable manual checks to it. A document counts as posted only when PlaidCloud reads it back from Sage 100, shows as waiting while it sits in a Sage 100 batch, and is never re-sent when PlaidCloud can't tell whether Sage 100 holds it. The agent needs PlaidLink 1.2.36 or later. See [Sage 100 (On-Premises)](/guides/connections/sage-100/).
- **`{date_iso}` gives the run's time in ISO 8601.** It holds the current UTC time as `2026-11-12T22:49:56+00:00`, so an expression can take its first 7 or 10 characters for the month or the day. It works wherever `{date}`, the long form, does: step settings and expressions, notification email templates including their preview and **Send Test to Me**, and Forecast, Parity and Solver steps. See [Built-in Variables](/guides/workflows/manage-workflow-variables/#built-in-variables).
- **Post documents to any ERP from one step, with one record of every posting.** The **Post Documents** step posts the documents in a table to the system each entity posts to, so one step can post to several ERP systems and several instances of the same ERP. A journal in the Data Foundation's shape posts with nothing to match; an invoiced sales-line table posts once you add `account` and `document_type`. Every posting is recorded the same way whichever system it went to, with checks before anything is sent, and each run has its own page. A column named for a posting field that isn't read as that field, because it means something else in a model table or another column is mapped to that field, isn't posted, and the step warns, naming it, so you can map it in the columns. See [Post Documents to ERP Systems](/guides/connections/post-documents/).
  - **Simulate first, then Live.** A run and each system are set to **Simulate** or **Live**; a simulated document reads **Would post** and nothing is sent. Five checks stop a document before it is sent, including **Balanced** and **Sets agree**, with a rounding account and limit. On the workflow canvas, the **Simulate** button is now **Test run**: it still walks the workflow without running any step, and is separate from the Simulate posting mode.
  - **Runs have a page.** The run page shows each document, why one was stopped, and lets you **Stop run**, **Post these** and **Check in the system**. A step's Live run lists what the step posted before and did not produce this time, and **Reverse these** reverses it. **Post from a file…** in the Posting Register posts a spreadsheet with no workflow, and **Post again** on a file run's page posts it again with a new date, once (starting in Simulate) or every month; both are also available through the REST API and MCP, and documents posted before PlaidCloud can be recorded as already posted. You can also post from an allocation, and **Convert to Post documents…** turns an SAP posting step into the new step. Posting over REST or MCP and starting a file post take the Architect or Manager role on a project that isn't locked.
  - **Systems, routing and Go live.** Each system has its settings, including a fixed value for a column a table lacks, and the entities that post to it from a date, **Go live ›** on a system's row or **Go live in this project…** in **Actions** uses the existing write authorization and project mode, a system can be copied to another environment, and **Refresh now** re-reads a system's lists of accounts, companies and periods into a copy you can view. The period-open, existence and code-match checks use only the lists a Live run reads from a Live system as it starts; a check whose list was not read in that run reads "not checked". See [Set Up ERP Systems for Posting](/guides/connections/erp-systems/).
  - **Hold rules send risky documents to a person.** A hold rule or a step's own hold sends a document to the **Approvals** inbox, large documents can be flagged as unusual, and an approval covers one action. A reversal, credit or correction is also held for a second person.
  - **Supported systems.** The per-system tables list what each ERP can do, including NetSuite invoices, credit memos on QuickBooks, Xero and Acumatica, and SAP through the agent (when the agent is offline, nothing is sent, and the documents can be retried once it is back).
  - **The Posting Register is rebuilt around postings.** Its rail groups **Needs attention**, **Postings** and **Runs**; **Approvals**, **Delegations** and **My watches**; and **Systems**, **Hold rules**, **History of changes**, **Exports & alerts** and **Retention**. Every posting reads as one of seven states, and its drawer shows the reasons, lines, versions and links into the system, with **Reverse…**, **Credit…** and **Correct…**, **Retry**, comments and a watch, and **Postings** answers a question in your own words with **Ask**. **Home** shows a **Posting Register** card while anything needs you, the command palette lists **Needs attention** and **Approvals** and finds a posting by its ledger id with **Find posting**, and in the register Ctrl+K (Cmd+K on a Mac) opens that command palette rather than a list of its own. An **Unconfirmed** posting is settled with **Say whether it posted**, or from the system's own stored report for SAP, and a ledger entry that **Needs a look**, or is **Rejected** though its system holds it, is settled with **Resolve…** over the REST API, asking the system what it holds where it can. The earlier Register screens (list, roll-up, reconcile, trends, lineage, simulated postings, exception queue and assist) and saved views are replaced by these. See [Review the Posting Register](/guides/connections/posting-register/).
- **Run Insight shows where a workflow run's time went.** Click **History** on the canvas, choose **Run insight** from the **Actions** menu on the **Workflows** tab, choose **Open latest run** on a workflow card on Home, or click **Open the run** on a Weave message about a slow run. A headline says what happened, **What needs attention** lists failures first, then time beyond the usual, then waiting, and **Flow**, **Timeline** and **Table** views show the run block by block. Each step is judged against its own recent runs, and **Compare to** can add the previous run or one you choose. A live run updates on its own. AI assistants get the same profile through `workflow_describe` with `include=['run_insight']`, and the REST API through `GET /rest/v1/analyze/workflow/run-insight`. See [Run Insight](/guides/workflows/run-a-workflow/#run-insight).

The new **Data model** page on Project home lists the elements, shows the tables that share each as a graph or a matrix, flags tables whose type differs, and suggests names worth making elements. The graph zooms with the mouse wheel or the zoom buttons, has **Fit**, **1:1** and a minimap, and exports to PDF or PNG. ## Fixed

- **Restoring a Data Foundation project to a point before a source was added removes that source's landed tables.** They stayed behind. A warning now names the source, and says to confirm the file again if you undo the restore, or that Load pulls the tables again. If they can't be removed, the warning says where they stay, and the rest is still restored. See [Restore Points](/guides/projects/data-foundation/#restore-points).
- **A restore point that rolls off no longer releases a hold you set yourself.** On Lakehouse tables, restore points now hold their snapshots separately from yours, and a project restore uses only your holds.
- **Running a recipe or asking @Weave in a comment counts toward the limit on Weave tasks.** Each person can have only so many running at once, and Weave says when you are at the limit; the comment is still saved. See [When Weave Is Busy](/guides/ai-assistant/weave-team/#when-weave-is-busy).
- **A failed workflow's card on Home shows its error on the card's tint.** A white band no longer covers the tinted card behind the error message.
- **Tidy all keeps steps inside the groups of converted workflows.** In a workflow converted with groups nested inside other groups, **Tidy all** pulled steps out of their groups. It no longer does. Workflows converted earlier are fixed as each workspace is upgraded: in most of them, the nested groups are separated, keeping their names and layout. See [Containers](/guides/workflows/advanced-workflows/#containers).
- **Invalid project settings are reported with a clear message.** An unknown environment or document account, a slug that is taken or reserved, or an invalid storage type or posting mode now returns a message naming the problem instead of a generic server error. Through the REST API this is a 400 rather than a 500, and through the AI assistant or MCP it is an invalid-argument error.
- **The REST API's dimension values request works.** `POST /rest/v1/analyze/query/retrieve-dimension-values` was answered as a grid request and refused as invalid. It now returns one aggregated value for each column in `value_columns`, and a grid, one value for each pair of a row filter and a column filter, has its own `POST /rest/v1/analyze/query/retrieve-dimension-cells`.
- **Slow table reads and file handling no longer hold up other requests.** Reading a table's columns from the warehouse, registering a Data Foundation file, exporting to Excel, reading a REST or SOAP import's response, finding where a document account is used, and checking a Panel app's code or logo could each pause every other request the same server was handling until it finished. They now run alongside those requests.
- **The project and workflow variable dialogs scroll.** On a small screen or low resolution the add and edit dialog was taller than the window, so the **Create** and **Update** buttons could be out of reach. The form now scrolls and the buttons stay at the bottom.
- **Files over 256 MiB in an Azure Blob Storage document account can be copied, moved and renamed.** Each of these used to fail on a file that size, and so did moving or renaming a folder holding one.
- **On Lakehouse v2, a table's row count reflects what was just written to it.** A step or import that wrote a table could record the row count from before the write, so a table just loaded showed 0 rows and an import could report 0 rows imported. The count is now read once the new rows are visible everywhere, so the steps after it read them too. Switching a table to another branch, or merging a branch into it, also updates its row and column counts.
- **Weave's empty-values check compares each run with what earlier runs really left.** A step's empty values were often counted just after the step emptied its table to refill it, so its earlier runs looked as if they had none, and a column that had always been partly empty was reported as if it had only just become so. Each run is now counted as the step left its table. Counts recorded before can't be told apart from good ones, so they aren't used: each step's empty-values check starts its history again, and is reported as unchecked until five runs have been counted. The rows and spread-of-values checks also no longer credit a step with a write another step makes to the same table more than two seconds after it finishes. See [What Weave Checks](/guides/ai-assistant/weave-findings/).
- **Data Foundation keeps the precision of inverted exchange rates and decimal thresholds.** A rate PlaidCloud turns around, because your rates are quoted from the reporting currency into another currency, could be rounded to six decimal places, which left amounts in a currency with a small rate, such as the Indonesian rupiah, around 1% off. Inverted rates now keep 12 decimal places. A `group_amber` or `group_red` threshold with decimals, such as `0.5`, was rounded to a whole number. Your next Load uses the precise values. See [Exchange Rates](/guides/projects/data-foundation/#exchange-rates).
- **Alerts and digests stop for a deactivated member.** A Panel app alert or digest whose owner was deactivated kept checking and sending. It now pauses while they're deactivated and resumes if they're reactivated. See [Alerts and Digests](/guides/panel-apps/alerts-and-digests/).
- **Asking the REST API for a deleted connection returns 404.** Requesting a connection that has been deleted, or an ID that doesn't exist, answered with a generic server error (500). It now returns 404 with a message naming the connection ID.
- **Templated table exports work through the AI assistant and MCP.** The `templated` format of `table_data_export` failed whenever it was given a table. It now exports the table through your template, limited to the rows you can read. In the template, a table's rows are named by its table ID with each `-` written as `_`.
- **Amazon S3 and S3-compatible document accounts keep their Region.** Saving one of these accounts discarded the **Region** you entered, so the field was blank the next time you opened the account. The Region is now saved. On an account saved before this fix, enter the Region again and save. See [Add AWS S3 Account](/guides/documents/adding-accounts/add-aws-s3-account/).
- **A plain ASCII file with a few Windows characters is read exactly.** A file that was ASCII apart from a few Windows dashes, curly quotes or accented letters could fail the encoding conversion steps with "reads as neither UTF-8 nor ascii", fail or be read in the wrong encoding when added to Data Foundation, or be imported by **Import: CSV** with � in place of those characters or in the wrong encoding. The encoding conversion steps and **Import: CSV**, when its **Encoding** is left blank, now read the characters as written, and so does Data Foundation when one of them is in the file's first 4 MB. An import whose encoding can't be worked out now stops with an error naming the file, instead of importing � in place of characters. See [Convert Document Encoding to UTF-8](/reference/workflow-steps/document/convert-document-encoding-to-utf-8/#how-it-works).
- **Converting a folder's encoding no longer overwrites a file with another of the same name.** Two files bound for the same place in the destination — two files of the same name from different subfolders, say — left only the last one written. The step now stops before writing the second, names both files and where they would go, and says when ticking **Keep Subfolders** would keep them apart.
- **Clearing Replace characters in Document: Convert File to ASCII Encoding takes effect.** A step saved with **Replace characters the target encoding cannot hold with ?** ticked stayed that way after the box was cleared and the step saved again. Clearing it now turns replacement off.
- **The AI assistant and JSON-RPC no longer name the steps that use a table your role hides.** Asked where such a table is used, they named each step your role can see that reads or writes it, with its settings and workflow. They now say that steps use the table without naming them, the same as the project's table references. See [What Your Role Hides](/guides/ai-assistant/weave-tab/#what-your-role-hides).
- **The default AI connection you choose stays the default.** Marking an AI connection as the workspace default appeared to succeed but was never saved, so agents and steps that rely on the default kept using whichever connection was updated most recently. Your choice is now saved. See [LLM Providers](/integrations/ai-architecture/llm-providers/#what-the-connection-holds).
- **Right-clicking a conversation in Weave's history no longer opens Rename on top of Delete Thread.** **Rename** is now on the chat's tab: right-click the tab, which until now offered nothing. See [The Tabs in the Weave Tab](/guides/ai-assistant/weave-tab/#the-tabs-in-the-weave-tab).
- **Weave no longer stops with a generic error on a question that needs many lookups.** When answering a question or diagnosing a failed step took more than about a dozen lookups, Weave ended with *An internal error occurred. Please try again.* and dropped any fix it had already prepared. It now has room for twice as many. If it still runs out, it shows what it found and any fix it prepared, and says it stopped early.
- **A blank Memo no longer stops you saving.** Creating or saving a project, dimension, table, warehouse, editor, scheduled workflow event or distribution list with the **Memo** box left empty failed with "Memo: Input should be a valid string". A blank memo is now accepted.
- **An expression that gives several values where one is expected is refused, and a Table Extract or Table Union All step keeps its target table's data.** The usual cause is a trailing comma, as in `table.amount,`, or a comparison with several values, such as `table.region == ('EU', 'US')`. On Databend the step failed, and a Table Extract or Table Union All step had already emptied its target table by then. Some other warehouses ran such an expression, but not always as written, so a step that has been running without errors may now be refused. The step form refuses the expression when you save the step, and the message shows what to change. See [Several Values Where One Is Expected](/reference/workflow-steps/common/advanced-data-mapper-usage/#several-values-where-one-is-expected).
- **A step that names an output column twice stops before emptying its target.** In Table Lookup, Table Extract or a join, two **Target Output Columns** with the same name made the step empty its target table and then fail with an unclear error. The step now stops first, with a message naming the repeated column, so you can give each output column its own name. Extract SQL, which writes columns in the order your query returns them, is unchanged. See [Table Lookup](/reference/workflow-steps/tables/table-lookup/).
- **A union source saved without its source columns says what's missing.** A Table Union All or Table Union Distinct source saved through the REST API, JSON-RPC, or the AI assistant or MCP with no list of source columns failed when the step ran, with an unexpected error naming an internal setting. Saving one is now refused, naming the source, and a step that reads one saved before stops before it writes anything, naming the source. A converted Table Union All that takes every column from its tables, or stacks them by position, needs no list and isn't refused for having none.
- **A column's constant can be a number, `0` or `false`.** A step whose output column had a number as its constant failed with an unexpected error. A constant of `0` or `false` was treated as no constant at all, so the column took its expression or source column instead, or the step failed because the column had nothing to read. These constants are now written to every row, converted to the column's data type, and the AI assistant can propose a step with one.
- **Converted Alteryx Data Cleansing tools remove null rows.** A Data Cleansing or Data Cleanse Pro tool with **Remove Null Rows** ticked was flagged for review in the conversion report, and its converted step kept every row. The step now removes each row that is null in every column, as Alteryx does. A row holding an empty text value is kept. Data Cleanse Pro checks each row after its other options, so a row whose nulls it replaces with blanks is kept too. **Remove Null Columns** is still flagged for review. Import the workflow again to pick this up.
- **Email notifications and exports with no columns listed include every column.** A Notify Via Email frame with no columns chosen, or an export step with no target columns mapped, used to fail the run. Both now include every column of their table, so check the Data Mapper before you export to an external destination. See [Export Steps](/reference/workflow-steps/export/#columns-written). In a template body, `{variable}` placeholders in the subject are filled in for scheduled sends, preview and **Send Test to Me**.
- **Five export steps and Run SAP PCM Hyper Loader warn instead of failing when the source is missing, empty or has no columns.** Export MongoDB, Export External Database Tables, Tableau Hyper Export, Spatial File Export, Export to Excel Sheets and Run SAP PCM Hyper Loader failed, or finished without saying that nothing was written. They now succeed and log a warning that names the source or target. Export MongoDB writes nothing to the collection for a missing table, and when the table has no rows and **Delete every document in the collection before writing** is on, empties the collection and says so. Export External Database Tables skips a target whose source is missing or has no columns, and that target table keeps its previous rows. Tableau Hyper Export and Spatial File Export write no file for a missing or column-less source, and warn when the source has no rows. Export to Excel Sheets writes no workbook when no sheet has anything to write and there is no template or workbook to seed from. Run SAP PCM Hyper Loader skips such a source and loads the rest, and when none has anything to load, it logs that nothing was loaded. See [Export MongoDB](/reference/workflow-steps/export/export-mongodb/) and [Export External Database Tables](/reference/workflow-steps/export/export-external-tables/).
- **Expression validation accepts the functions a run accepts.** Valid expressions that call functions such as `int(...)` were refused when you checked them.
- **Loading a dimension from a table works on projects with Row Access.** On a project that restricts rows, the load failed, so Data Foundation's hierarchies weren't rebuilt. Project Architects and workflow runs now load it. Anyone whose Row Access limits what they can read of the source table is told to ask a project Architect or to load it from a workflow, because everyone in the project sees the members a load makes. See [Loading Data Into a Restricted Table](/administration/access/managing-security-groups-and-assignments/#loading-data-into-a-restricted-table).
- **Data Foundation loads, and makes the Pipeline dashboard, on projects with Row Access.** On a project that restricts rows, **Load** and **Apply changes** could stop while building the pipeline by stage, and the **Pipeline** dashboard wasn't made, because its table couldn't be published for reporting.
- **Data Foundation dashboards open on the month the Period filter shows.** The filter showed the month chosen, but the charts that read one month added up every month until you applied the filter.
- **Data Foundation dashboard tiles and context lines show in full.** Their last lines could be cut off.
- **An empty file ends a Data Foundation load with a warning that names it.** A file with no rows after its header loaded nothing new without saying so. The dataset keeps the rows the file last gave it.
- **Headcount and units produced count allocation driver rows with no scenario, whatever the case of the driver's name.** A driver row with no scenario now counts as actual, and a driver named `Headcount` counts as `headcount`.
- **Salesforce, SAP, Oracle E-Business Suite and Oracle Fusion sources load their data into Data Foundation.** Reading them during **Load** failed, although the load itself finished.
- **Accented and other non-English characters read from Salesforce come through intact.** Names such as Hernández came out garbled from the **Salesforce: Query Object** step and from Data Foundation's Salesforce sources.
- **Key marks on the Data model graph no longer run together.** When several tables were keyed on the same element, the **1** marking each table's key was drawn where their lines left the element, so the marks ran together, as in "11". Each **1** is now drawn at the table end of its line, just left of the table card. See [Read the Data Model](/guides/projects/data-model/#read-the-data-model).
- **Making a warehouse the default says the switch is still under way, and the warehouse dialog no longer raises a false error.** **Make default** in **Manage warehouses** said the warehouse was the default at once, although the workspace takes a few minutes to switch to it. It now says so. On beta workspaces, switching between **Snowflake** and **Databricks** in the warehouse dialog also no longer shows an error message asking you to tell the dev team.
- **A server or Dash app opened from a shared or older link shows the loading screen.** A server or Dash app opened from any link other than the one you launched it from, such as an address-bar link copied after launch, an older `/serve/panel/` link from a digest email, a Slack or Microsoft Teams alert or digest card, or the REST API's `location` field, or a Studio preview link, showed a blank tab while a sleeping app woke. It now shows the loading screen, and the link's page, query and `#` section carry through to the app. Signed out, a link opened in a browser tab takes you through sign-in first and then to the loading screen or the app; the `#` section may be lost if you have to sign in. An app embedded in another page still shows an error when you're signed out.
- **An item's version history lists only its own versions.** The versions of a step, user-defined function, dimension, document account or saved layout could include those of another of the same kind whose ID starts with the same characters, such as a step `load` and a step `load_2`. Each now lists only its own.
- **Agent Remote Export: SQL loads the table you choose.** A step created, copied or switched to **Export to Analyze Table** in the step form wrote its result to a file in its **Target Directory** instead, so its **Target Table** was never loaded. The choice is now saved. Such a step now opens on **Export to File**, because that is what it has been running: choose **Export to Analyze Table** and save it again.
- **A failed Table Project to Project Copy keeps its target table's data.** With **Append to Existing Data** unticked, the step emptied the target table before copying into it, so a copy that then failed left the target empty. A copy that fails now leaves the target table's rows and columns as they were. See [Table Project to Project Copy](/reference/workflow-steps/tables/frame-project-copy/).
- **On Lakehouse v2, Restore Tables reads an archive from an Amazon S3 bucket in any AWS Region.** A restore from a bucket outside `us-east-1` failed. See [Restore Tables](/reference/workflow-steps/import/restore-tables/).
- **On Databend, a preview or what-if that runs out of time no longer keeps your warehouse busy.** When a step's **Preview** took longer than 30 seconds, or Weave ran out of time while carrying a scenario into later steps, PlaidCloud stopped waiting, but the query went on running in your warehouse until it finished, and trying again started another. The warehouse now stops the query too, and a preview it stops says it took longer than 30 seconds. See [Carry a Scenario into Later Steps](/guides/allocations/results/driver-what-if/#carry-a-scenario-into-later-steps).
- **Removing a member keeps their account and history.** Deleting a member deleted their account. **Remove from workspace…** now stops the member signing in and takes away their access, and keeps the account and its history, with the member listed as **Inactive**. **Erase permanently…**, for workspace administrators, also deletes the account and the member's usage data. See [Editing and Deleting a Member](/administration/access/member-management/#editing-and-deleting-a-member).
- **Export to Excel keeps the other sheets of an existing workbook.** An export that replaced an existing workbook lost every sheet the step didn't write. The step now writes only its own sheets and keeps the rest, unless the file isn't a readable workbook. See [If the File Exists](/reference/workflow-steps/export/export-to-excel/#if-the-file-exists).
- **A step whose columns set an aggregation summarizes when its settings don't say otherwise.** A step written through the REST API or MCP, such as a join or lookup, with an aggregation on its columns but no **Summarize** setting returned ungrouped rows. It now summarizes; a step with **Summarize** turned off still doesn't.
- **A step stays in run history when recording it fails at first.** If writing a step's run to run history failed, for example because the warehouse connection reset, the step was missing from run history and from Weave's alerts about the run. PlaidCloud now tries the write again.
- **A posting that gets a server error from its ERP needs a look instead of being rejected.** When Acumatica, Business Central, NetSuite, Oracle Fusion, QuickBooks Online, Sage Intacct or Xero answered a posting with a server error, it was recorded as rejected although the document might exist, so retrying it could post it twice. It is now **Unconfirmed** (**Needs a look** when you open it by its ledger id), so it isn't sent again before someone checks, and you can settle it with **Resolve…**. See [Resolve a Ledger Entry](/guides/connections/posting-register/#resolve-a-ledger-entry).
- **A filter that matches nothing no longer looks like an empty list.** In Projects, Workflows, Steps, Tables, Dimensions, Data Editors and user-defined functions, a filter left with no matches, for example after you deleted the only matching item or refreshed the list, showed "No projects yet" or its equivalent and hid the filter box, so only reloading the page got you out. The list now says no results match your filter and offers **Clear filters**.
- **Databricks lakehouses load CSV imports, run steps with literal values and publish tables for dashboards.** On a Databricks lakehouse, importing a CSV file failed with a schema mismatch, and a column named like `Unit Price` couldn't be created, whether in a lakehouse table or in a table an export creates on a Databricks connection. Imported and cast numbers lost their decimals, so 10.5 loaded as 11 and values of more than ten digits loaded empty. A step whose filter or expression held a literal value, such as a Table Extract step filtered on `id > 2`, failed with an unbound parameter. A `%` in stored values, filters, column names and aliases, and view definitions also reached Databricks doubled, and tables couldn't be published for dashboards. All of these now work. Tables PlaidCloud creates on Databricks now use Delta column mapping, so a tool that reads them directly must support it.
- **A dropped connection no longer sends an action again.** When the connection dropped while PlaidCloud was waiting for a reply, it resent some requests up to three more times, even though the server may already have carried them out, so the same action, such as a workflow run, a copy or an email, could happen twice. They are now sent once. If your connection drops, you may see an error instead; check whether the action went through before trying again.

## Security

- **Weave no longer sends your name and email address to its AI provider at the start of each conversation.** It never used them.
- **Weave sends its AI provider at most 500 rows from any one query.** That covers the queries Weave writes and the metrics it runs, which before could send it every row they returned. When a metric returns more than 500 rows, its card in the conversation says so. See [How Weave Uses Your Data](/guides/ai-assistant/weave-data-use/).
- **Password sign-ins need an authenticator app, and passwords are stronger.** A member who signs in with a PlaidCloud password is asked to set up an authenticator app at their next sign-in, and enters its code each time after that. Single sign-on, Google, Microsoft and GitHub sign-in, API tokens and service accounts are unchanged. A new password needs at least 12 characters and can't be your username or one of your last six passwords, and after repeated failed sign-in attempts the account is locked for a short time. A stricter rule your workspace already had is kept. See [Member Authentication](/administration/access/member-authentication/).
- **Connections point at public and private-network addresses.** A connection can't point at a loopback, link-local or cloud metadata address, and the error names the host and the address it resolved to. Addresses on your private network are unaffected. See [Addresses a Connection Can't Reach](/guides/connections/create-connection/#addresses-a-connection-cant-reach).
- **Saved connection credentials are never shown to a person.** Through the REST API and MCP, a saved connection's passwords, tokens and keys are masked for everyone, whatever their permissions, though members can still open and browse it. Only service accounts receive them, such as PlaidLink agents and a project's own service account, never a person's sign-in. Changing where a connection sends its credentials, such as its host, needs them entered again, and a project's own database password is shown only to its Architects. See [Who Sees a Connection's Credentials](/guides/connections/create-connection/#who-sees-a-connections-credentials).
- **A connection's credentials don't follow a redirect to another origin.** A standard `Authorization` header is left off a request redirected to a different scheme, host or port, and a request that carries credentials any other way, such as an API key header, stops instead of following. HFM/FCCS connections don't follow redirects at all. See [Generic REST Connection](/reference/connectors/rest/generic-rest/).
- **Unrestricted Google, Microsoft and GitHub sign-in no longer create accounts in your workspace.** Google sign-in that isn't limited to your own Google Workspace domain, Microsoft sign-in that isn't limited to your own organization's directory, and GitHub sign-in only sign in people who already have an account in the workspace, such as members you invited. See [Existing Accounts and Email Verification](/administration/control-plane/workspace-configuration/#existing-accounts-and-email-verification).
- **A restricted dashboard reaches only members who can access its data.** A dashboard limited to security groups is listed and opens for a member of those groups only when at least one of its datasets is in a project they can access, or it has none. A dashboard's datasets and charts leave out those in projects you can't access. See [Which Dashboards You See](/guides/dashboards/using-dashboards/#which-dashboards-you-see).
- **App builds run without access to your workspace's Git credentials.**
- **Approving a Weave change takes the permission the change needs.** Approving a card or a plan applies a change only when you hold the permission it needs, such as changing steps, running workflows or changing Panel apps. Otherwise Weave says it can't apply it. See [Approve a Change](/guides/ai-assistant/weave-dock/#approve-a-change).
- **Posting needs the Architect or Manager role on a project that isn't locked.** Posting documents over REST or MCP, starting a file post, and sending a post to a PlaidLink agent for SAP, Oracle E-Business Suite or Sage 100 from a project you belong to are refused for an Explorer and on a locked project. See [Who Can Do What](/guides/connections/post-documents/#who-can-do-what).
- **A security group can't grant the MFA exemption.** It is set on the member. See [Password Sign-In Requires an Authenticator App](/administration/access/member-authentication/#password-sign-in-requires-an-authenticator-app).
- **Record as already posted no longer settles a document in a project you can't see.** It lists the document as *This document belongs to a project you cannot see.*
- **Cloning a Data Foundation project stages its archive where only workspace admins can reach it,** not in a temporary account every member can browse.
- **The Registered Systems list no longer shows client secrets.** An OAuth client's owner reads its secret in the client's configuration dialog, opened with the gear on its row.
- **An agent's private key is shown only to members who can edit agents.** The key no longer appears in agent lists or details through the REST API and MCP, and the Agent form shows the **Private Key** and **View RPC Config** only to members who can edit agents. Service accounts, project and agent tokens, and AI-delegated tokens can't retrieve the key or an RPC config. Credentials in an agent's configuration, such as a password, are masked in agent lists and details through the REST API and MCP. Running agents are unaffected, and the public key is still shown. See [Obtaining Agent Credentials](/reference/cli/plaidlink/agents/#obtaining-agent-credentials).
- **Proxy download links are valid for one hour.** With **Use PlaidCloud Proxy Download** on, open the download again for a new link when one has expired. See [Services](/administration/control-plane/workspace-configuration/#services).
- **Adding people to security groups follows the permissions you hold.** You can add a member to a security group, choose a member's groups or invite an Architect when you hold every permission the group grants. Workspace admins are not limited. See [Managing Security Groups](/administration/access/managing-security-groups-and-assignments/#managing-security-groups).
- **A connection's owners, or a workspace administrator, change its settings and switch it on or off.** Changing a connection's settings through the REST API, JSON-RPC and the AI assistant or MCP takes one of its owners, or a workspace administrator for a connection with no owner. Enabling, disabling, locking and unlocking a connection take an owner or a workspace administrator, and a request naming several connections applies only when you can change all of them. Only a workspace administrator can choose the workspace's default AI connection, and a connection a member owns is the default only when no connection owned by an administrator, or with no owner, could be. See [Edit a Connection](/guides/connections/create-connection/#edit-a-connection) and [LLM Providers](/integrations/ai-architecture/llm-providers/#what-the-connection-holds).
- **Saved layout version history covers only layouts you can use.** Through the REST API, JSON-RPC and MCP, a table's saved-layout versions are listed, restored, held, released and backed up only for layouts you own, layouts shared with you and global layouts. Any other layout is reported as unknown. Restoring a version brings back the layout's columns and filters and keeps its owner and who it's shared with. Restoring every saved layout on a table takes a workspace admin. When its owner deletes a saved layout, its version history is deleted with it, held versions included. A layout version is restored in place: leave the target out, or name the same layout. See [Version History](/guides/projects/managing-projects/#version-history).
- **Row Access applies to everything a member does with a restricted table.** Members see and change only the rows their grants allow, in dashboards, in their own SQL, and in loads.
  - **Project Architects see all rows of row-restricted tables in dashboards**, matching what they see in Analyze. Taking away Architect access takes effect in dashboards immediately — whether you change someone's role, remove them or their group from the project, change the project's access type, restore an earlier project version, or delete a security group. See [Managing Row Access](/administration/access/managing-security-groups-and-assignments/#managing-row-access).
  - **Members limited by Row Access can run their own SQL queries and export the results.** On a project with Row Access, a member who isn't an Architect gets exactly the rows their grants allow from their own queries on query screens, and can export them to CSV, Excel or JSON, with the **Rows limited by your access** notice; before, these were refused. A grant value containing a percent sign (`%`) now returns its rows on query screens, and downloading such a query as CSV works. Their own free-form SQL on Snowflake or Databricks, exports of their own SQL from Postgres-family warehouses, and reading a governed table as of a snapshot are still refused, and a view must keep the governed column under its original name to be filtered. See [Row Access and Queries You Write Yourself](/administration/access/managing-security-groups-and-assignments/#row-access-and-queries-you-write-yourself).
  - **Saving Row Access keeps a granted value that its source doesn't have.** A value a security group was granted stays in the grid, marked, when the table has no rows with it, the dimension doesn't have the member, or the list doesn't have it. **Save** asks whether to keep each such value or remove it. See [The Row Access Grid](/administration/access/managing-security-groups-and-assignments/#the-row-access-grid).
  - **DataFrame writes, record saves and clears into a row-restricted table change only the rows you can see.** When Row Access limits your rows, writing a DataFrame to a restricted table or clearing it with the Python client, or saving records to it or clearing it through the REST API, changes only your own rows, and a load carrying a row outside your access is refused before anything changes, naming the values it found. Project Architects, members who see every row, and workflow runs write the whole table. Each of these writes that a person makes, to any table, is recorded in the Security Log. See [Loading Data Into a Restricted Table](/administration/access/managing-security-groups-and-assignments/#loading-data-into-a-restricted-table).
  - **Imports, copies, restores and deletes on a row-restricted table need every row to be visible to you.** When Row Access limits your rows, importing a file into a restricted table, copying a table into it from another project, switching or merging its branch, restoring it, deleting it, bringing it back after it was deleted, or any other action that replaces the whole table runs only when you can see every row of the table; otherwise it is refused and nothing changes. Saving a table's rows through the REST API changes only your own rows, as the other loads do. Project Architects, members who see every row, and workflow runs are unaffected, and these actions are recorded in the Security Log too. See [Loading Data Into a Restricted Table](/administration/access/managing-security-groups-and-assignments/#loading-data-into-a-restricted-table).
  - **ERP post steps run on projects with Row Access.** A step that posts to an ERP, such as Workday, runs on a row-restricted project, and snapshot, branch and optimization-candidate listings work there too.
- **Only an account's owners can restore its earlier versions.** Restoring a document account to an earlier version, holding or releasing a version, and taking a backup take one of the account's owners, and none of them is available on a system-managed account. Seeing an account's version history needs access to the account.
- **`query_run` runs read-only statements.** The `query_run` tool that the AI assistant and MCP clients use accepts one SELECT or WITH statement, an EXPLAIN of one, or a SHOW; any other statement is not run. To change data, use `query_transform`. The SQL in an MCP table export follows the same rule. Through the REST and JSON-RPC APIs, it also applies to running a query, building column facets, downloading a query as CSV, exporting a query to a remote database and exporting table data with your own query, for members who can't change project data; a refused query returns 403. Explain Analyze runs the query to measure it, so in the query log and the lakehouse it accepts only a query that reads, and on a project with row access only a project Architect can run it from the query log.
- **Table Explorer filters, queries sent to PlaidCloud and the query that finds a Table Extract step's Dynamic Columns can't call functions that run SQL or read the server's files.** A call to one, such as `query_to_xml`, `dblink` or `pg_read_file`, is refused, and the error names the function. In the same places, `.op()` accepts only an operator and a `literal_column` can't use Unicode-escaped quoting. The Dynamic Columns query carries the step's filter and the expressions that read the column names from the source, so one that breaks a rule fails the step when it runs. See [Functions and Operators That Are Refused](/reference/workflow-steps/common/advanced-data-mapper-usage/#functions-and-operators-that-are-refused).
- **Data Foundation allocation rules refuse a department or statistic name that contains a single quote, a backslash or a line break.** The name is written into the allocation steps' filters, so **Save** and a preview of stage 1 refuse it and name the value. See [Allocation Rules](/guides/projects/data-foundation/#allocation-rules).
- **Entries in the activity panel can't be made up through the API.** `POST /rest/v1/analyze/workflow/update-stream`, and its JSON-RPC equivalent, accept only the start or skip of a scheduled run, in a project you can open, with nothing but its project, workflow and run IDs. Every other entry, and the names shown in each one, come from PlaidCloud itself.
- **Read-only queries and Row Access refuse a query the warehouse could read in more than one way.** A query run read-only, or with Row Access applied, is now checked under each way the warehouse might read its comments and quoted text, and is refused, with a message saying why, when any of them reads it differently. Until now, a query could hide a second statement, or a table read without its filter, in text the check took for a comment or a string. A backslash in quoted text, or a `/*` inside a comment, can now cause a refusal; write a quote inside text as two quotes (`''`).
- **An expression can't read a restricted table around its Row Access filter.** Expressions and filters in Table Explorer, in Weave's **Why this number**, in **Check Keys** on a join or lookup step, and in a table read through the JSON-RPC `read_frame` call read only the rows your grants allow, including in any subquery they build. One that reaches the table's data any other way is refused.
- **After you sign in, PlaidCloud returns you only to its own pages.** A sign-in link written to send you to another site afterwards now takes you to PlaidCloud instead.
