## Added

- **A Trust Center in the control plane gives your security team PlaidCloud's security documents.** Admin and Security users open **Trust Center** for their organization, download public documents such as the subprocessor list and DPA right away, and sign the security-documentation NDA once for the organization to unlock restricted documents such as the SOC 2 Type II report. Other Admin and Security users see who signed and when. An organization whose contract already includes an NDA can have it marked on file so documents unlock without signing. Restricted downloads are watermarked and recorded, and a new NDA version needs accepting again. Admin and Security users can also opt in, per organization, to a daily email summarizing new or updated documents and new NDA versions; it never contains the documents themselves. See [Trust Center](/administration/control-plane/trust-center/).
- **PlaidXL builds, drills, explains and plans in Excel.** The **PlaidCloud** ribbon tab is grouped into **Connect**, **Insert**, **Refresh**, **Drill**, **Write** and **Share**, the common commands are also on a **PlaidXL** right-click menu and a **PlaidXL Cell** tab, and the main commands have keyboard shortcuts you can change, which don't fire while you type in a field. A command that fails says which one and why. A command run before you sign in opens the sign-in and runs once you're in, a sign-in works for one workspace so switching workspaces asks you to sign in to the new one (and switching back doesn't), and with a Microsoft Entra work account in Office, PlaidXL finds your workspace for you. See the [PlaidXL reference](/reference/cli/plaidxl/).
  - **Build a report in a few clicks.** The **Report** tab lays out a live report from a table, with a dimension drilled down the rows and another across the columns, and a `CELL` value at every intersection. **Build my first report** makes a sample from your own data. As you drill, a report inserts and removes whole rows and columns, and values you've typed, notes and formats stay with their row. See [Build a Report](/reference/cli/plaidxl/build-a-report/).
  - **Drill from any cell.** **Drill down**, **Drill up**, **Keep only** and **Remove only** turn a node into a live `DRILL` formula and edit it for you, from a node, a dimension heading or a report value. **Custom drill** previews the rows before you insert them, and the member picker inserts members or adds a dropdown of a node's children to cells. `DRILL` takes nodes to exclude or open, and can run across a row. See [Drill, Pick Members and Explain Numbers](/reference/cli/plaidxl/drill/).
  - **Explain a number.** **Explain this number** shows what a value calculates, whether it matches PlaidCloud now, and the table and workflow step it comes from. **Show detail rows** puts the rows behind a value on a sheet of their own, with a check that they add up.
  - **Governed metrics in Excel.** `PLAIDXL.METRIC` and `PLAIDXL.METRIC_BREAKDOWN` return a business metric as dashboards show it, and a `CELL` or `CELLS` with nothing to aggregate shows `0` for a sum and otherwise `#VALUE!` with the reason (blank in a `CELLS` spill), and **Metric...** lists your project's metrics with their current values. A metric can filter on more than one alternate hierarchy and mix an alternate-hierarchy member with members of other dimensions. See [Metrics](/reference/cli/plaidxl/functions/#metrics).
  - **Plan by typing into a report.** Type a number over a `CELL` value and it's written to PlaidCloud: spread in proportion, equally or in the shape of another member, adjusted by an amount or a percentage, with held cells left alone. Mean, median, minimum, maximum, standard deviation and variance cells take typed values too, and a typed value follows its cell when rows or columns are inserted or deleted (values in deleted cells are reported). **Undo last write** reverses typed values and saves, newest first, and only the person and workspace that made a write can undo it. Undoing a sum, or a mean typed into an empty cell, keeps what has been written into the same cells since, and a write that was interrupted before it finished can't be undone. See [Type Values Into PlaidCloud](/reference/cli/plaidxl/write-values/).
  - **Refresh just what you need.** Refresh a sheet, a selection or every table, with each table's progress and **Cancel** in the task pane, or recalculate only the PlaidXL formulas. Large tables retrieve much faster in Excel on the web and in current desktop Excel (a 143,000-row, 77-column table takes about a minute instead of over ten; older Excel versions work as before), and text longer than an Excel cell holds is flagged and kept from being saved cut. Retrieved tables arrive as Excel Tables formatted by data type, keep your own columns and number formats when they refresh, and refresh in their own place. A retrieve or refresh never overwrites other cells or overlaps another Excel Table, and whole-number IDs too large for Excel and dates before 1900 arrive as text. Retrieving a table again doesn't add it to the refresh list twice, **Stop refreshing** takes one off, and dimensions refresh with your tables. See [Refresh All Tables](/reference/cli/plaidxl/retrieve/#refresh-all-tables).
  - **Save writes straight away and can be undone.** **Save to PlaidCloud** writes without a confirmation, says what it did, and offers **Undo**, which works for up to 7 days after each save on Lakehouse tables. A sheet retrieved with a filter, a detail-rows sheet, or someone whose access covers only some rows replaces only those rows, so other people's rows are kept. A drill-through sheet whose members changed since you retrieved it isn't saved, and a save that fails names the restore point so the table can be put back. See [Save a Table to PlaidCloud](/reference/cli/plaidxl/retrieve/#save-a-table-to-plaidcloud).
  - **Ask Weave in Excel.** On the **Weave** tab, ask in plain words for a report, a formula, a drill or a table, or choose **Ask Weave about this cell**. Weave reads PlaidCloud as you and changes only the workbook, asks before replacing anything you've entered, never writes a formula that reaches outside the workbook, and each change can be reverted until you reload the pane. See [Ask Weave in Excel](/reference/cli/plaidxl/weave/).
  - **Share a values-only copy of one sheet or the whole workbook.** **Convert to values** converts a whole workbook, one sheet, or values with no way back (which asks first), changes only PlaidXL formulas and their spills, leaves formulas still calculating for a second try, and **Restore PlaidXL formulas** still works after you rename a sheet.
  - **The task pane has a new look.** It matches the PlaidCloud web app, with brand blue, rail-style tabs and lists, and tables, dimensions, projects and columns in bounded scrolling cards. Keyboard focus shows a clear ring, and the pane follows your light or dark Office theme. The tabs sit three across and two down in a narrow pane and in one row from 560 pixels wide. See [Light and Dark Theme](/reference/cli/plaidxl/connect/#light-and-dark-theme).
  - **Numbers in the pane follow Excel's display language.** Row and column counts and the refresh, recalculation, Explain, Formulas, Report and planning messages show numbers the way your Excel does, so German Excel shows 4.812.233. Values written to cells don't change.
  - **A sheet's tab turns yellow while it refreshes.** During **Refresh All Tables**, whether from the pane, the ribbon or Weave, each sheet's tab is yellow while that sheet refreshes, then returns to its previous colour, including your own, when it finishes, fails or is cancelled. If you save and close the workbook part-way, the tabs are put back the next time PlaidXL starts in it. See [Refresh All Tables](/reference/cli/plaidxl/retrieve/#refresh-all-tables).

See [Review the Posting Register](/guides/connections/posting-register/).

## Fixed

- **Invalid project settings are reported with a clear message.** An unknown environment or document account, a slug that is taken or reserved, or an invalid storage type or posting mode now returns a message naming the problem instead of a generic server error. Through the REST API this is a 400 rather than a 500, and through the AI assistant or MCP it is an invalid-argument error.
- **The REST API's dimension values request works.** `POST /rest/v1/analyze/query/retrieve-dimension-values` was answered as a grid request and refused as invalid. It now returns one aggregated value for each column in `value_columns`, and a grid, one value for each pair of a row filter and a column filter, has its own `POST /rest/v1/analyze/query/retrieve-dimension-cells`.
- **Slow table reads and file handling no longer hold up other requests.** Reading a table's columns from the warehouse, registering a Data Foundation file, exporting to Excel, reading a REST or SOAP import's response, finding where a document account is used, and checking a Panel app's code or logo could each pause every other request the same server was handling until it finished. They now run alongside those requests.
- **The project and workflow variable dialogs scroll.** On a small screen or low resolution the add and edit dialog was taller than the window, so the **Create** and **Update** buttons could be out of reach. The form now scrolls and the buttons stay at the bottom.
- **Files over 256 MiB in an Azure Blob Storage document account can be copied, moved and renamed.** Each of these used to fail on a file that size, and so did moving or renaming a folder holding one.
- **On Lakehouse v2, a table's row count reflects what was just written to it.** A step or import that wrote a table could record the row count from before the write, so a table just loaded showed 0 rows and an import could report 0 rows imported. The count is now read once the new rows are visible everywhere, so the steps after it read them too. Switching a table to another branch, or merging a branch into it, also updates its row and column counts.
- **Weave's empty-values check compares each run with what earlier runs really left.** A step's empty values were often counted just after the step emptied its table to refill it, so its earlier runs looked as if they had none, and a column that had always been partly empty was reported as if it had only just become so. Each run is now counted as the step left its table. Counts recorded before can't be told apart from good ones, so they aren't used: each step's empty-values check starts its history again, and is reported as unchecked until five runs have been counted. The rows and spread-of-values checks also no longer credit a step with a write another step makes to the same table more than two seconds after it finishes. See [What Weave Checks](/guides/ai-assistant/weave-findings/).
- **Data Foundation keeps the precision of inverted exchange rates and decimal thresholds.** A rate PlaidCloud turns around, because your rates are quoted from the reporting currency into another currency, could be rounded to six decimal places, which left amounts in a currency with a small rate, such as the Indonesian rupiah, around 1% off. Inverted rates now keep 12 decimal places. A `group_amber` or `group_red` threshold with decimals, such as `0.5`, was rounded to a whole number. Your next Load uses the precise values. See [Exchange Rates](/guides/projects/data-foundation/#exchange-rates).
- **Alerts and digests stop for a deactivated member.** A Panel app alert or digest whose owner was deactivated kept checking and sending. It now pauses while they're deactivated and resumes if they're reactivated. See [Alerts and Digests](/guides/panel-apps/alerts-and-digests/).
- **Asking the REST API for a deleted connection returns 404.** Requesting a connection that has been deleted, or an ID that doesn't exist, answered with a generic server error (500). It now returns 404 with a message naming the connection ID.
- **Templated table exports work through the AI assistant and MCP.** The `templated` format of `table_data_export` failed whenever it was given a table. It now exports the table through your template, limited to the rows you can read. In the template, a table's rows are named by its table ID with each `-` written as `_`.
- **Amazon S3 and S3-compatible document accounts keep their Region.** Saving one of these accounts discarded the **Region** you entered, so the field was blank the next time you opened the account. The Region is now saved. On an account saved before this fix, enter the Region again and save. See [Add AWS S3 Account](/guides/documents/adding-accounts/add-aws-s3-account/).
- **Converting a folder's encoding no longer overwrites a file with another of the same name.** Two files bound for the same place in the destination — two files of the same name from different subfolders, say — left only the last one written. The step now stops before writing the second, names both files and where they would go, and says when ticking **Keep Subfolders** would keep them apart.
- **Clearing Replace characters in Document: Convert File to ASCII Encoding takes effect.** A step saved with **Replace characters the target encoding cannot hold with ?** ticked stayed that way after the box was cleared and the step saved again. Clearing it now turns replacement off.
- **The AI assistant and JSON-RPC no longer name the steps that use a table your role hides.** Asked where such a table is used, they named each step your role can see that reads or writes it, with its settings and workflow. They now say that steps use the table without naming them, the same as the project's table references. See [What Your Role Hides](/guides/ai-assistant/weave-tab/#what-your-role-hides).
- **The default AI connection you choose stays the default.** Marking an AI connection as the workspace default appeared to succeed but was never saved, so agents and steps that rely on the default kept using whichever connection was updated most recently. Your choice is now saved. See [LLM Providers](/integrations/ai-architecture/llm-providers/#what-the-connection-holds).
- **Right-clicking a conversation in Weave's history no longer opens Rename on top of Delete Thread.** **Rename** is now on the chat's tab: right-click the tab, which until now offered nothing. See [The Tabs in the Weave Tab](/guides/ai-assistant/weave-tab/#the-tabs-in-the-weave-tab).
- **A blank Memo no longer stops you saving.** Creating or saving a project, dimension, table, warehouse, editor, scheduled workflow event or distribution list with the **Memo** box left empty failed with "Memo: Input should be a valid string". A blank memo is now accepted.
- **An expression that gives several values where one is expected is refused, and a Table Extract or Table Union All step keeps its target table's data.** The usual cause is a trailing comma, as in `table.amount,`, or a comparison with several values, such as `table.region == ('EU', 'US')`. On Databend the step failed, and a Table Extract or Table Union All step had already emptied its target table by then. Some other warehouses ran such an expression, but not always as written, so a step that has been running without errors may now be refused. The step form refuses the expression when you save the step, and the message shows what to change. See [Several Values Where One Is Expected](/reference/workflow-steps/common/advanced-data-mapper-usage/#several-values-where-one-is-expected).
- **A step that names an output column twice stops before emptying its target.** In Table Lookup, Table Extract or a join, two **Target Output Columns** with the same name made the step empty its target table and then fail with an unclear error. The step now stops first, with a message naming the repeated column, so you can give each output column its own name. Extract SQL, which writes columns in the order your query returns them, is unchanged. See [Table Lookup](/reference/workflow-steps/tables/table-lookup/).
- **A union source saved without its source columns says what's missing.** A Table Union All or Table Union Distinct source saved through the REST API, JSON-RPC, or the AI assistant or MCP with no list of source columns failed when the step ran, with an unexpected error naming an internal setting. Saving one is now refused, naming the source, and a step that reads one saved before stops before it writes anything, naming the source. A converted Table Union All that takes every column from its tables, or stacks them by position, needs no list and isn't refused for having none.
- **A column's constant can be a number, `0` or `false`.** A step whose output column had a number as its constant failed with an unexpected error. A constant of `0` or `false` was treated as no constant at all, so the column took its expression or source column instead, or the step failed because the column had nothing to read. These constants are now written to every row, converted to the column's data type, and the AI assistant can propose a step with one.
- **Converted Alteryx Data Cleansing tools remove null rows.** A Data Cleansing or Data Cleanse Pro tool with **Remove Null Rows** ticked was flagged for review in the conversion report, and its converted step kept every row. The step now removes each row that is null in every column, as Alteryx does. A row holding an empty text value is kept. Data Cleanse Pro checks each row after its other options, so a row whose nulls it replaces with blanks is kept too. **Remove Null Columns** is still flagged for review. Import the workflow again to pick this up.

Project Architects, members who see every row, and workflow runs are unaffected, and these actions are recorded in the Security Log too. See [Loading Data Into a Restricted Table](/administration/access/managing-security-groups-and-assignments/#loading-data-into-a-restricted-table).
- **Only an account's owners can restore its earlier versions.** Restoring a document account to an earlier version, holding or releasing a version, and taking a backup take one of the account's owners, and none of them is available on a system-managed account. Seeing an account's version history needs access to the account.
- **`query_run` runs read-only statements.** The `query_run` tool that the AI assistant and MCP clients use accepts one SELECT or WITH statement, an EXPLAIN of one, or a SHOW; any other statement is not run. To change data, use `query_transform`. The SQL in an MCP table export follows the same rule. Through the REST and JSON-RPC APIs, it also applies to running a query, building column facets, downloading a query as CSV, exporting a query to a remote database and exporting table data with your own query, for members who can't change project data; a refused query returns 403. Explain Analyze runs the query to measure it, so in the query log and the lakehouse it accepts only a query that reads, and on a project with row access only a project Architect can run it from the query log.
- **Table Explorer filters, queries sent to PlaidCloud and the query that finds a Table Extract step's Dynamic Columns can't call functions that run SQL or read the server's files.** A call to one, such as `query_to_xml`, `dblink` or `pg_read_file`, is refused, and the error names the function. In the same places, `.op()` accepts only an operator and a `literal_column` can't use Unicode-escaped quoting. The Dynamic Columns query carries the step's filter and the expressions that read the column names from the source, so one that breaks a rule fails the step when it runs. See [Functions and Operators That Are Refused](/reference/workflow-steps/common/advanced-data-mapper-usage/#functions-and-operators-that-are-refused).
- **Data Foundation allocation rules refuse a department or statistic name that contains a single quote, a backslash or a line break.** The name is written into the allocation steps' filters, so **Save** and a preview of stage 1 refuse it and name the value. See [Allocation Rules](/guides/projects/data-foundation/#allocation-rules).
