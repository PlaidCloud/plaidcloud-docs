Arrow Flight SQL takes a SQL statement and streams back its result as Arrow. It suits Python data tools, SQL clients such as DBeaver, and Tableau Desktop. You send one read-only statement over the project's tables, and PlaidCloud filters every table it reads to the rows the client's owner may see before it runs. Before you connect, create a BI feed client and add it to the project; see [Connect BI Tools](/integrations/bi-tools/).

## Connection Details

| Setting | Value |
| --- | --- |
| Endpoint | `grpc+tls://flightsql.<workspace host>:443` |
| JDBC URL | `jdbc:arrow-flight-sql://flightsql.<workspace host>:443/?useEncryption=true&project_id=<project id>` |
| User name | The client ID |
| Password | The client secret |
| Project | `project_id`: part of the JDBC URL, or the ADBC option `adbc.flight.sql.rpc.call_header.project_id` |

The project's **JDBC URL** is on the **BI feed clients** card of its **Access & sharing** page, ready to copy. The connection is always encrypted, on port 443.

A connection reads one project. To read another, connect again with that project's ID.

## Python

Install the ADBC Flight SQL driver with `pip install adbc-driver-flightsql pyarrow`, then connect with the client's ID and secret, here read from environment variables:

```python
import os

import adbc_driver_flightsql.dbapi as flightsql

with flightsql.connect(
    "grpc+tls://flightsql.<workspace host>:443",
    db_kwargs={
        "username": os.environ["PLAIDCLOUD_CLIENT_ID"],
        "password": os.environ["PLAIDCLOUD_CLIENT_SECRET"],
        "adbc.flight.sql.rpc.call_header.project_id": "<project id>",
    },
    autocommit=True,
) as connection, connection.cursor() as cursor:
    cursor.execute(
        'SELECT region, SUM(amount) AS total FROM "Sales" WHERE fiscal_year = ? GROUP BY region',
        parameters=(2024,),
    )
    sales = cursor.fetch_arrow_table()
```

The feed runs no transactions, so connect with `autocommit=True`. `sales` is an Arrow table:

- **pandas:** `sales.to_pandas()`
- **polars:** `polars.from_arrow(sales)`
- **DuckDB:** query it by its name, as in `duckdb.sql("SELECT * FROM sales")`

For a large result, `cursor.fetch_record_batch()` reads it a batch at a time instead of all at once.

## DBeaver

DBeaver doesn't include the Apache Arrow Flight SQL driver, so add it once:

1. Choose **Database** > **Driver Manager** > **New**.
2. Name the driver, for example `Arrow Flight SQL`, and set **Class Name** to `org.apache.arrow.driver.jdbc.ArrowFlightJdbcDriver`.
3. On **Libraries**, choose **Add Artifact** and enter `org.apache.arrow:flight-sql-jdbc-driver`, or choose **Add File** and pick the driver's `.jar` file. Choose **OK**.

Then connect:

1. Choose **Database** > **New Database Connection** and pick the driver you added.
2. Connect by **URL**: paste the project's **JDBC URL**, then enter the client ID as the user name and the secret as the password.
3. Choose **Finish**. The project's tables are in the `plaid` schema.

In your own Java program, start Java with `--add-opens=java.base/java.nio=ALL-UNNAMED`. Without it, the driver connects and runs plain statements, but a statement with `?` parameters fails with `sun.misc.Unsafe or java.nio.DirectByteBuffer.<init>(long, int) not available`. DBeaver already starts with that option.

## Tableau Desktop and Tableau Server

1. Download the Apache Arrow Flight SQL JDBC driver (`flight-sql-jdbc-driver`, a `.jar` file) and put it in Tableau's drivers folder: `C:\Program Files\Tableau\Drivers` on Windows, or `~/Library/Tableau/Drivers` on a Mac. Then restart Tableau.
2. Under **Connect**, choose **To a Server** > **Other Databases (JDBC)**.
3. Enter the project's **JDBC URL** as the **URL**, choose **PostgreSQL** as the **Dialect**, enter the client ID and secret as **Username** and **Password**, and choose **Sign In**.
4. The project's tables are in the `plaid` schema.

To refresh a published workbook or data source, Tableau Server needs the same driver installed in its own drivers folder.

## The SQL You Can Send

The feed reads PostgreSQL-style SQL and accepts one read-only statement at a time:

- **One statement:** a `SELECT`, a `WITH … SELECT`, or a `UNION`, `INTERSECT` or `EXCEPT` of them. A recursive `WITH` is refused.
- **The project's tables, by name:** write a table's name on its own, or in the `plaid` schema, as in `plaid."Sales"`. Any other schema or catalog is refused.
- **Quoting:** a name without quotes matches whatever its case, as `sales` matches `Sales`. A quoted name must match exactly; quote a name with spaces or punctuation, as in `"Sales 2024"` or `"Cost Center Name"`.
- **The usual clauses:** joins, subqueries, `GROUP BY`, `HAVING`, `ORDER BY`, `LIMIT`, `OFFSET`, `FETCH`, `DISTINCT`, `CASE`, `CAST` and window functions.
- **Functions:** the common text, number, date, aggregate and window functions, including `UPPER`, `LOWER`, `TRIM`, `SUBSTRING`, `REPLACE`, `CONCAT`, `ROUND`, `ABS`, `COALESCE`, `NULLIF`, `EXTRACT`, `DATE_TRUNC`, `CURRENT_DATE`, `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, `ROW_NUMBER`, `RANK`, `LAG` and `LEAD`.
- **Parameters:** `?` markers, each given a number, text, true or false, a date, a timestamp, or NULL.
- **Length:** up to 65,536 characters, with its parameters written in.

Empty values sort the way the project's warehouse sorts them. Write `NULLS FIRST` or `NULLS LAST` when the order matters.

Quote a column named like a word a warehouse knows about the session or the clock, as in `"user"` or `"current_date"`. Without quotes, the word may not read your column: the feed may refuse it, or the warehouse may read the session's own value, as `current_date` reads today's date. `user`, `system_user`, `current_role`, `current_database`, `sysdate` and `systimestamp` are always refused without quotes, with a message asking you to quote them.

The feed refuses anything that writes or locks (`INSERT`, `UPDATE`, `DELETE`, `MERGE`, `SELECT … INTO`), `VALUES`, `UNNEST`, `LATERAL`, reading files, time travel, `TABLESAMPLE`, `PIVOT`, a `NATURAL` join (name its columns with `USING` or `ON` instead), a `SELECT` list item that reads another item's alias, as the second `x` does in `SELECT a AS x, x FROM t`, and any function outside its list. A refusal starts with "Nothing was run:" and names what it refused, so you can rewrite that part.

<Aside type="note">
Every table a statement reads, whether directly, in a join, a subquery or a `WITH`, is filtered to the rows the client's owner may read before the rest of the statement sees it.
</Aside>

## What Clients See

- **Schema:** one schema, `plaid`, with no catalog.
- **Tables:** the project's tables shown to the client's role, by their names in the project. Two names that differ only in case each get an underscore and a short code made from their table. Views aren't included.
- **Columns:** by their names in the project, spaces included, as in `"FULL YEAR"` or `"Cost Center Name"`. This differs from OData, which shows `FULL_YEAR`.
- **Keys:** a table's update keys are its primary key, and a table with none has no primary key. Tables have no foreign keys.

Timestamps arrive in UTC.

## Limits and Messages

There's no row cap: a result streams until it ends. Sign-in messages are listed in [Connect BI Tools](/integrations/bi-tools/#when-a-tool-cant-sign-in-or-sees-no-tables). These are particular to Flight SQL:

| Message | What to do |
| --- | --- |
| Name the project to read with the project_id connection property … | Add `project_id` to the JDBC URL, or set the ADBC option `adbc.flight.sql.rpc.call_header.project_id`. |
| This session reads another project. Connect again to read this one. | A connection reads one project. Open another connection for the other project. |
| This session has ended. Connect again. | A connection's session ends after 8 hours unused, and 24 hours after it began. Connect again. |
| This client was disabled or its secret has changed since this session began. Connect again. | Connect again with the current secret. If the client was disabled, enable it first. A deleted client, or one whose owner's account is disabled, can't connect. |
| The statement ran past the gateway's 3,600-second limit and was stopped. | One statement can run for an hour at most. Filter or aggregate it to return less. |
| Nothing was run: … | The statement holds something the feed doesn't accept; see [The SQL You Can Send](#the-sql-you-can-send). |
| The warehouse could not run the statement: … | The project's warehouse refused the statement, for the reason given. |
