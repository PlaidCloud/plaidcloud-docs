Power BI, Excel, Tableau, Python, DBeaver and other tools can read a project's tables directly through PlaidCloud's BI feed. The feed is read-only and offers two ways in:

- **OData**, a feed that Power BI, Excel and Tableau read with the OData connector they already have.
- **Arrow Flight SQL**, which takes your own SQL statement and returns the result as Arrow, for Python, DBeaver and Tableau Desktop.

Each tool signs in with a BI feed client, a client ID and secret that you create and add to a project. The client reads the project as you, its owner, may read it.

## Which Connection Should I Use?

| Tool | Connect with |
| --- | --- |
| Power BI Desktop | [OData](/integrations/bi-tools/odata/#power-bi-desktop) |
| Power BI Service | [OData](/integrations/bi-tools/odata/#power-bi-service) |
| Excel | [OData](/integrations/bi-tools/odata/#excel) |
| Tableau Cloud | [OData](/integrations/bi-tools/odata/#tableau) |
| Tableau Desktop and Tableau Server | [Flight SQL](/integrations/bi-tools/flight-sql/#tableau-desktop-and-tableau-server), through the Arrow Flight SQL JDBC driver, or [OData](/integrations/bi-tools/odata/#tableau) |
| Python, with pandas, polars or DuckDB | [Flight SQL](/integrations/bi-tools/flight-sql/#python), through ADBC |
| DBeaver | [Flight SQL](/integrations/bi-tools/flight-sql/#dbeaver) |

Both read the same tables, with the same Row Access, using the same client. OData returns at most 1,000,000 rows to one request. On Lakehouse v2 a larger table can be [served in pages](/integrations/bi-tools/odata/#tables-served-in-pages); otherwise it is read with a filter or with incremental refresh. Flight SQL has no row cap.

OData and Flight SQL name tables and columns differently. OData turns spaces and punctuation in a name into underscores, so a column `FULL YEAR` is `FULL_YEAR`. Flight SQL keeps the name the project gives it, so in SQL you quote it: `"FULL YEAR"`.

## Turn on External Access

The BI feed is available only when the workspace has external database access on. PlaidCloud sets it for you, with the address ranges allowed to connect: contact PlaidCloud support to turn it on or to change the ranges. See [Workspace Configuration](/administration/control-plane/workspace-configuration/#lakehouse).

The allowed address ranges decide which addresses can reach the BI feed:

- Ask for the ranges your tools connect from, such as your offices or VPN, in CIDR form.
- A service that refreshes in the cloud, such as Tableau Cloud, connects from its own addresses, which must be allowed too.
- With no ranges set, the feed accepts connections from any address, protected by the client's secret alone.
- Denied address ranges don't apply to the BI feed.

<Aside type="note">
Power BI Service refreshes from Microsoft's shared cloud addresses, which are too many to list. To refresh from Power BI Service, ask PlaidCloud support to set no ranges, so that the feed accepts every address and the client's secret alone protects it.
</Aside>

## Create a BI Feed Client

1. In Analyze, open **Tools** and choose **Registered Systems (oAuth Clients)**.
2. Choose **Register a New System (oAuth Client)**.
3. Enter a **Name**, and under **Type** choose **BI / external data feed**.
4. Choose **Create**.
5. The **BI feed client secret** window shows the **Client ID** and **Client secret**. Copy both now: the secret is not shown again.

The same window shows the feed's addresses, with a placeholder where a project's ID goes. Each project's **Access & sharing** page shows that project's own addresses, ready to copy.

In **Registered Systems (oAuth Clients)**, a BI feed client shows **BI / external data feed** in the **Type** column. Unlike an API client, it has no configuration to copy, and its secret can't be read again. If the secret is lost or may have been seen by someone else, choose **Regenerate secret** on the client's row, then **Regenerate**. The new secret is shown once, as at creation, and the old one stops working at once, so every tool that uses it fails until you give it the new one.

To stop a client reading anything, edit it and clear **Enabled**, or delete it.

## Add the Client to a Project

A new client reads nothing until you add it to a project.

1. Open the project's [Home](/guides/projects/project-home/#access--sharing) and choose **Access & sharing**.
2. On the **BI feed clients** card, choose **Add client ›**.
3. Choose the **BI feed client** and its **Role**: **Explorer** or **Manager**.
4. Choose **Add**.

<Aside type="caution" title="A Client Sees Only the Tables Shown to Its Role">
A Manager client sees a table only when the table's **Manager** box is ticked, and an Explorer client only when its **Explorer** box is ticked. No client reads a table with both boxes clear, so on a project where every table has both clear, the tool signs in but lists no tables. An Architect ticks the boxes on the project's **Tables** tab; see [Mark Table for Viewing Roles](/guides/projects/managing-tables-and-views/#mark-table-for-viewing-roles).
</Aside>

A client can't be an Architect. An Architect sees every table, whatever its boxes, so the client's role and that role's box on each table are how you choose which tables go into the feed.

To add a client you need to be able to change the project's access, as its Architect or a workspace admin does, and you can add only clients you own. If you have none, the window says so and offers **Open Registered Systems**. When you can't add a client, the card says why.

The card lists the clients that read the project, each with its role: all of them for the project's Architect or a workspace admin, and only your own for anyone else. It also shows the project's **Feed URL**, for OData, and **JDBC URL**, for Flight SQL. **Remove** on a client's row takes it off the project. The project's Architect or a workspace admin can remove any client, and an owner can remove their own.

## What a Client Reads

A BI feed client reads as its owner, the person who created it:

- **Tables:** the project's tables shown to its role, as [above](#add-the-client-to-a-project). Views aren't included.
- **Rows:** only the rows the owner's [Row Access](/administration/access/managing-security-groups-and-assignments/#managing-row-access) allows. This holds even when the owner is the project's Architect: through the feed, the owner's security groups decide the rows.
- **While the owner can:** the owner must still be able to open the project and read its tables. If they lose access to the project, or their account is disabled, the client stops working within a minute.
- **Read-only:** nothing a client sends can change data.

<Aside type="caution">
Anyone with the client ID and secret reads the project as the owner. Treat the secret as a password: keep it in the tool's own credential settings, and regenerate it if it may have been seen by someone else. The secret works only with the BI feed: the REST API, JSON-RPC and the MCP server refuse it.
</Aside>

## Connection Details

Copy the addresses from the project's **BI feed clients** card rather than typing them. In the table, `<workspace host>` is the address you open PlaidCloud at.

| | OData | Flight SQL |
| --- | --- | --- |
| Address | `https://odata.<workspace host>/v1/projects/<project id>/` | `grpc+tls://flightsql.<workspace host>:443` |
| JDBC URL | | `jdbc:arrow-flight-sql://flightsql.<workspace host>:443/?useEncryption=true&project_id=<project id>` |
| User name | The client ID | The client ID |
| Password | The client secret | The client secret |
| Project | Part of the address | The `project_id` connection property |

## When a Tool Can't Sign In or Sees No Tables

If the tool can't reach the feed at all, ask PlaidCloud support to check that the workspace has external database access on and allows the address the tool connects from. Once it connects, these messages say what's wrong:

| What the tool shows | What to do |
| --- | --- |
| It signs in, but lists no tables. | The client sees only the tables shown to its role. Tick the **Manager** or **Explorer** box, whichever is the client's role, on each table it should read; see [Add the Client to a Project](#add-the-client-to-a-project). |
| Sign in with the client id and secret of a BI feed client. | The tool sent no user name and password. Choose basic (user name and password) authentication. |
| The client id or secret is wrong, or the client is not a BI feed client. | Check the client ID and secret. The same message answers a client that was disabled or deleted, an API client, and a client whose owner's account is disabled. |
| This client may not read this project. | Add the client to the project on **Access & sharing**. If it is there, its owner may no longer be able to open the project. |
| Too many requests. Try again later. (OData)<br />Too many attempts. Try again in … seconds. (Flight SQL) | Too many sign-in attempts came from one address in a short time. Wait, then try again with the right secret. |
| PlaidCloud could not check these credentials just now. Try again shortly. | A passing problem on PlaidCloud's side. Try again. |
| The gateway is busy. Try again shortly. (OData)<br />The gateway is busy. Try again in 30 seconds. (Flight SQL) | The feed is serving as many reads as it can at once. Try again. |
