**Devise** est un type de données de colonne conçu pour les montants monétaires. Il apparaît à côté des types familiers (Numérique, Entier, Texte et les autres) dans toutes les listes de types de données, et il stocke les montants sous forme de décimaux exacts à virgule fixe : 18 chiffres de précision avec 4 décimales. Cela représente environ ±100 000 milliards, avec une exactitude au dix-millième d'unité et sans arrondi en virgule flottante.

L'avantage est la vitesse. Une colonne Devise occupe la moitié de la largeur en mémoire d'une colonne Numérique ; les tableaux de bord et les étapes de workflow qui parcourent des tables remplies de montants lisent donc environ deux fois moins de données et se terminent plus vite. Numérique reste le type par défaut à haute précision (38 chiffres de précision, 10 décimales) ; Devise est le type plus léger que vous choisissez partout où les valeurs sont des montants monétaires.

<Aside>
Devise est déployé avec la version actuelle de la plateforme. L'option apparaît dans vos listes de types de données dès que la mise à jour est active sur votre espace de travail.
</Aside>


## Quand utiliser Devise

Choisissez Devise pour les colonnes qui contiennent des montants monétaires : coût, chiffre d'affaires, prix, marge, dépenses, montants alloués. Ce sont les colonnes qui dominent les modèles de rentabilité et les modèles financiers ; les retyper est donc généralement le gain le plus important pour les tableaux de bord et les workflows qui parcourent beaucoup de données.

Conservez Numérique lorsque :

* Les valeurs pourraient dépasser environ ±100 000 milliards, ou nécessitent plus de 4 décimales (taux de change, taux unitaires, pourcentages et facteurs d'allocation, par exemple)
* La colonne mêle des montants monétaires à d'autres mesures, ou vous ne savez pas avec certitude ce qu'elle contiendra

<Aside type="note" title="Remarque">
Chaque valeur Devise doit tenir dans 18 chiffres de précision avec 4 décimales, soit environ ±100 000 milliards avec 4 décimales. Si une colonne nécessite plus d'échelle ou de précision, utilisez Numérique.
</Aside>


## Où le définir

Devise est disponible partout où vous choisissez le type de données d'une colonne.

### Dans le mappage des colonnes d'une étape de workflow

Dans le mappage des colonnes de sortie de n'importe quelle étape (la grille du Data Mapper), choisissez **Devise** dans la liste déroulante des types de données de la colonne, comme vous choisiriez Numérique ou Texte. L'étape écrit cette colonne en Devise à partir de l'exécution suivante.

### Dans les propriétés de colonne d'une table

Ouvrez les **Propriétés de la colonne** d'une table et utilisez le contrôle **Type de données** pour faire passer une colonne de **Numérique** à **Devise**, ou inversement. La modification prend effet la prochaine fois que la table est reconstruite, par exemple lors de la prochaine exécution de l'étape de workflow qui la produit.

### Avec un assistant IA ou un outillage MCP

Les agents connectés via [MCP](/fr/integrations/ai-coding-agents/getting-started/) peuvent aussi définir le type : la valeur du type de données est `currency` partout où un type de colonne est demandé, que ce soit pour créer une colonne, définir une table ou configurer une étape. Demander à votre assistant de *« passer les colonnes de montants en devise »* est souvent le moyen le plus rapide de retyper une table large.


## Comportement du type Devise

Quelques règles rendent Devise prévisible sur toute la plateforme :

* **Devise est toujours votre choix explicite.** Les imports, la détection automatique des types, les résultats SQL et les colonnes dérivées (sommes, expressions, sorties d'allocation) prennent toujours Numérique par défaut. Si vous voulez Devise sur un résultat, retypez vous-même cette colonne de sortie.
* **Une fois défini, il est mémorisé.** Une colonne déclarée Devise reste Devise à travers les lectures, les étapes en aval et les reconstructions de table. Lorsqu'une étape en aval renseigne son mappage de colonnes à partir de la table, le type Devise est automatiquement repris dans la configuration de l'étape.
* **Les agrégations renvoient Numérique.** Une SUM ou une autre agrégation d'une colonne Devise produit un résultat Numérique ; repassez la colonne de sortie en Devise si vous voulez stocker l'agrégat sous ce type.
* **Les cellules vides s'importent comme 0.** Dans les imports de fichiers, une cellule vide dans une colonne Devise se charge comme 0, exactement comme pour Numérique.

<Aside type="caution" title="Attention">
Pour les étapes où vous écrivez du SQL brut, le bouton **Renseigner** déduit les colonnes de sortie du résultat de la requête, et les résultats de requête reviennent toujours en Numérique. Passez les colonnes monétaires en Devise après avoir exécuté Renseigner, et prévoyez de les redéfinir si vous le relancez.
</Aside>
