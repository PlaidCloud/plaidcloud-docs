Comme les pipelines de données peuvent générer de nombreuses tables et vues intermédiaires, utiles pour la validation et les contrôles de processus mais inadaptées au reporting des résultats finaux, 
PlaidCloud fournit un processus `Publish` pour réduire le bruit lors de la création de tableaux de bord ou de la récupération de données dans PlaidXL. Le processus `Publish` permet de préciser 
quelles tables et vues sont définitives et fiables pour le reporting.

## Publier

Depuis l'onglet `Tables` de la configuration d'un projet PlaidCloud, repérez la table que vous souhaitez publier pour l'utiliser dans les tableaux de bord et PlaidXL. Faites un clic droit sur 
l'enregistrement de la table et sélectionnez `Set Published Table Reporting Name` dans le menu.

Une boîte de dialogue s'ouvre, dans laquelle vous pouvez indiquer un nom publié unique. Ce nom n'a pas besoin d'être identique au nom de la table ou de la vue. Pouvoir utiliser un nom différent 
est souvent utile lorsque vous référencez des sources de données dans les tableaux de bord et PlaidXL, car cela permet de proposer un nom plus convivial aux utilisateurs.

Une fois la table ou la vue publiée, son nom publié apparaît dans la colonne `Published As` de la vue `Tables`.

Lorsque vous sélectionnez la table, le nom s'affiche aussi dans le champ en lecture seule **Publié sous** du panneau **Détails de la table**, sous **ID de la table**. Le champ indique « Non publié » pour une table qui n'est pas publiée. Utilisez le bouton de copie situé à côté du champ pour copier le nom, et survolez le champ pour voir le nom complet lorsqu'il est trop long pour s'afficher en entier.

<Aside>Les noms publiés sont soumis à certaines restrictions. Ils peuvent comporter au maximum 63 caractères, et certains caractères spéciaux sont interdits. Cela est nécessaire pour garantir une compatibilité maximale avec les systèmes, outils et processus extérieurs à PlaidCloud.</Aside>

<Aside type="caution">
**Accès aux lignes.** Publier une table qui comporte une colonne restreinte par l'[accès aux lignes](/fr/administration/access/managing-security-groups-and-assignments/#gérer-laccès-aux-lignes) configure le filtre de tableau de bord de cette table dans la même opération. Les tableaux de bord lisent une table via sa vue de reporting publiée ; PlaidCloud enregistre donc le filtre de chaque groupe avant la fin de la publication. S'il n'y parvient pas, la publication est refusée avec le motif, et tout ce que cette tentative a créé est annulé — une table restreinte n'est jamais laissée sans filtre dans les tableaux de bord. Sur un projet qui restreint des lignes, une *vue* ne peut pas être publiée, car la requête d'une vue peut renommer ou dériver la colonne restreinte ; publiez plutôt la table qu'elle lit. Consultez [Un nom de colonne, toutes les tables](/fr/administration/access/managing-security-groups-and-assignments/#un-nom-de-colonne-toutes-les-tables).
</Aside>

## Examiner les performances d'une table publiée

Les performances des tables publiées constituent la phase 1 du pilote automatique de performance des tables de PlaidCloud. Cette fonctionnalité surveille la façon dont les utilisateurs se servent des tables publiées et vous fournit une recommandation ; elle ne modifie pas encore une table automatiquement. Ouvrez **Table Optimizer**, sélectionnez une table publiée, puis choisissez **Performances de la table publiée** pour afficher l'examen.

L'examen indique si PlaidCloud dispose d'une activité récente suffisante pour proposer des recommandations, notamment les requêtes directes répétées et l'utilisation par les tableaux de bord. Lorsqu'un schéma utile se dégage, il identifie les colonnes à envisager pour une future amélioration de la disposition. Il indique aussi clairement lorsqu'aucune modification n'est nécessaire ou lorsqu'il lui faut davantage d'activité récente avant de conclure.

Cette version de la phase 1 est passive : elle fournit uniquement des recommandations. Si vous décidez qu'une amélioration en vaut la peine, planifiez-la et appliquez-la dans le cadre de votre processus de changement habituel. Une future version de la phase 2 est prévue pour utiliser ces constats et les mêmes contrôles de sécurité afin d'appliquer automatiquement les optimisations prises en charge.

Les recommandations dépendent de la plateforme de données et de l'activité actuelle disponible pour cette table publiée. Lorsque PlaidCloud ne peut pas effectuer d'évaluation fiable, l'examen explique la limite au lieu de présenter une suggestion comme certaine.

## Annuler la publication

Annuler la publication d'une table ou d'une vue est similaire au processus de publication. Depuis l'onglet `Tables` de la configuration d'un projet PlaidCloud, repérez la table que vous souhaitez 
publier pour l'utiliser dans les tableaux de bord et PlaidXL. Faites un clic droit sur l'enregistrement de la table et sélectionnez `Set Published Table Reporting Name` dans le menu.

Lorsque la boîte de dialogue de définition du nom publié s'affiche, sélectionnez le bouton `Unpublish`. La table ne sera alors plus utilisable dans les tableaux de bord et PlaidXL.

Le nom publié n'apparaîtra plus dans la colonne `Published As`.

### Annuler la publication par l'assistant IA ou MCP

`publish_manage` annule la publication d'une table avec `target='table'` et `action='unpublish'`, à partir de `project_id`, de `table_id` et du `name` publié de la table. Un nom sous lequel la table n'est pas publiée est refusé.

- **La vue publiée et les jeux de données inutilisés sont supprimés aussi.** Annuler la publication d'une table supprime également sa vue publiée et tout jeu de données de tableau de bord qu'aucun graphique n'utilise. Si un graphique utilise encore le jeu de données, celui-ci est conservé.
- **Une vue de rapport construite sur la vue publiée la conserve.** La publication de la table est tout de même annulée, mais la vue publiée et son jeu de données restent, car la vue de rapport en dépend.
- **Répéter l'opération ne change rien.** Annuler la publication d'une table qui n'est déjà plus publiée réussit sans rien modifier.


## Renommer 

Renommer une table ou une vue est similaire au processus de publication. Depuis l'onglet `Tables` de la configuration d'un projet PlaidCloud, repérez la table que vous souhaitez 
publier pour l'utiliser dans les tableaux de bord et PlaidXL. Faites un clic droit sur l'enregistrement de la table et sélectionnez `Set Published Table Reporting Name` dans le menu.

Lorsque la boîte de dialogue s'affiche, remplacez le nom publié par le nouveau nom souhaité. Appuyez sur le bouton `Publish` pour mettre à jour le nom.

Le nom mis à jour apparaîtra désormais dans la colonne `Published As`, ainsi que dans les tableaux de bord et PlaidXL.
