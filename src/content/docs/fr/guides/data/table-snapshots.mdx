Chaque fois qu'une table est écrite, le lakehouse de PlaidCloud conserve un **instantané** de la table à ce moment : une copie cohérente des données à un instant donné. Les instantanés vous permettent de consulter le contenu antérieur d'une table, de vous rétablir après un mauvais chargement et d'auditer l'évolution d'une table dans le temps. La profondeur de retour en arrière dépend du paramètre de voyage dans le temps de la table : 1 jour par défaut, et jusqu'à 90 jours pour le paramètre par défaut du projet ou pour une table qui l'allonge. Voir [Gérer le stockage](/fr/guides/projects/managing-storage/).

Le panneau Instantanés vous permet de parcourir cet historique, d'ouvrir n'importe quel instantané en lecture seule dans l'explorateur de tables, et de rétablir ou de restaurer la table à un instantané antérieur.

## Ouvrir le panneau Instantanés

Dans la liste **Tables** du projet, cliquez sur le bouton d'instantané/flashback situé sur la ligne d'une table. Le panneau **Instantanés** s'ouvre et répertorie les instantanés de la table, du plus récent au plus ancien :

- **Quand** : la date et l'heure de prise de l'instantané.
- **Lignes** : le nombre de lignes de la table à cet instantané.
- **Δ lignes** : la variation du nombre de lignes par rapport à l'instantané précédent, pour voir ce que chaque écriture a ajouté ou supprimé.
- **Taille** : la taille de stockage compressée de l'instantané.
- **Libellé** : un nom, pour les instantanés que vous avez nommés ou épinglés.
- **Retenu** : un marqueur d'épingle pour les instantanés retenus (conservés au-delà de la fenêtre de rétention normale).

## Afficher les données à la date d'un instantané

Il existe deux façons d'afficher les données d'une table à un moment antérieur. Les deux ouvrent l'explorateur de tables dans une **vue historique en lecture seule**, avec une bannière indiquant l'instantané affiché et un bouton **Revenir aux données actuelles**.

1. **Depuis le panneau Instantanés** : sélectionnez un instantané et cliquez sur **Afficher à l'instantané**.
2. **Depuis l'explorateur de tables** : utilisez la liste déroulante **As of** de la barre d'outils. Elle répertorie les instantanés récents de la table ; choisissez-en un pour changer d'affichage, ou choisissez **Actuel (données en direct)** pour revenir aux données en direct.

<Aside>La vue historique est en lecture seule : c'est une fenêtre sur le passé, pas une copie modifiable. Utilisez **Rétablir** ou **Restaurer** (ci-dessous) si vous voulez ramener d'anciennes données dans une table.</Aside>

## Rétablir ou restaurer un instantané

Sélectionnez un instantané et cliquez sur **Rétablir / Restaurer**. La boîte de dialogue propose deux choix :

- **Rétablir cette table sur place** (par défaut) : remplace les données actuelles de la table par l'instantané. Comme cette opération est destructrice, vous saisissez le nom de la table pour confirmer. Avant le remplacement des données, PlaidCloud capture automatiquement un **instantané de sécurité préalable au rétablissement** de l'état actuel (sur les moteurs de stockage qui prennent en charge l'épinglage), afin que vous puissiez toujours revenir à votre point de départ. Sur un lakehouse Databend, si les colonnes de la table ont changé depuis l'instantané, un rétablissement sur place est refusé, avec le nom des colonnes modifiées ; restaurez alors dans une nouvelle table.
- **Restaurer l'instantané dans une nouvelle table** : laisse la table d'origine intacte et crée dans le projet une nouvelle table (vous lui donnez un nom et un dossier) alimentée à partir de l'instantané, avec les mêmes colonnes que la source. Via l'assistant IA ou MCP, une restauration sans nom prend un nom basé sur la table source, par exemple `Sales (restored 3f2a9c1d)`.

<Aside type="caution">Le rétablissement sur place écrase les données actuelles de la table. La confirmation par saisie et l'instantané de sécurité automatique préalable au rétablissement sont là pour vous protéger : lisez la boîte de dialogue avant de confirmer. Le rétablissement est bloqué tant que le projet est verrouillé.</Aside>

<Aside>Via l'API REST ou MCP, restaurez un instantané sur place en omettant la table cible, ou en nommant la table elle-même. Une restauration sur place y bénéficie de la même protection que le rétablissement de la boîte de dialogue : un instantané de sécurité préalable au rétablissement lorsque le moteur de stockage en prend un en charge, et un enregistrement d'audit. Pour qu'elle soit refusée si la table a été écrite depuis que vous avez répertorié ses instantanés, transmettez le dernier instantané que vous avez vu dans `expected_current_snapshot_id`.</Aside>

<Aside>Si une restauration dans une nouvelle table échoue (par exemple parce que l'instantané a expiré), aucune nouvelle table n'est ajoutée au projet.</Aside>

## Nommer, épingler et conserver

Les instantanés expirent selon le paramètre de voyage dans le temps de la table (1 jour par défaut, jusqu'à 90 jours) lors du nettoyage nocturne. Le rétablissement ou la restauration fonctionne jusqu'au plus ancien point restaurable affiché pour la table. Pour en conserver un plus longtemps :

- **Créer un instantané** prend à la demande un instantané retenu des données actuelles, utile avant un rechargement risqué (par exemple « avant le rechargement du T2 »).
- **Rétention** épingle l'instantané sélectionné ; **Libérer** supprime la rétention et le remet dans le cycle de vie normal.

<Aside type="caution">Une rétention conserve plus que l'instantané seul : elle conserve l'instantané retenu *et* tous les instantanés écrits après lui, de sorte que le stockage continue de croître tant que vous n'avez pas libéré la rétention. Remplacer entièrement une table (un upsert ou un remplacement SCD-2) démarre un tout nouvel historique d'instantanés, et toute rétention sur l'ancien est perdue avec lui.</Aside>

La restauration de toutes les tables d'un projet en une seule fois, via l'API REST, restaure chaque table à son instantané retenu le plus récent et laisse en l'état les tables sans rétention. Un instantané de sécurité préalable au rétablissement ne compte pas comme une rétention, bien que le panneau Instantanés puisse le marquer comme retenu, sauf si vous le retenez vous-même, par exemple avec **Rétention**. Les noms d'instantanés commençant par `pre-revert_` sont réservés aux instantanés de sécurité. Si une table ne peut pas être restaurée, les autres le sont quand même, et la requête échoue en nommant chaque table non restaurée et la raison.

<Aside>La possibilité de nommer un instantané à la demande est disponible sur les tables Lakehouse (StarRocks). La rétention et la libération d'un instantané fonctionnent désormais aussi sur les tables adossées à Databend ; les instantanés y sont toujours conservés pendant la fenêtre de rétention, même sans rétention.</Aside>

## Audit

Les rétablissements sur place, qu'ils proviennent de la boîte de dialogue, de l'API REST ou d'un assistant IA, sont consignés dans le journal d'audit du lakehouse, avec l'auteur du rétablissement, le moment, l'instantané vers lequel il a eu lieu et l'instantané de sécurité conservé ; les modifications de table effectuées via cette fonction sont ainsi traçables.
