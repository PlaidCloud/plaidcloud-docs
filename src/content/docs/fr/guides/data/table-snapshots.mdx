Chaque fois qu'une table est écrite, le lakehouse de PlaidCloud conserve un **instantané** de la table à ce moment-là — une copie cohérente des données à un instant donné. Les instantanés vous permettent de consulter ce que contenait une table auparavant, de récupérer après un chargement erroné et d'auditer l'évolution d'une table au fil du temps. La profondeur de l'historique accessible dépend du paramètre de voyage dans le temps de la table : 1 jour par défaut, et jusqu'à 90 jours pour la valeur par défaut du projet ou pour une table qui l'allonge. Consultez [Gérer le stockage](/fr/guides/projects/managing-storage/).

Pour lire en SQL une table telle qu'elle était lors d'un instantané, copiez une requête `FOR VERSION AS OF` depuis le détail de la table dans la [fenêtre Lakehouse](/fr/guides/data/lakehouse-window/#copier-une-requête-de-voyage-dans-le-temps).

Le panneau Instantanés vous permet de parcourir cet historique, d'ouvrir n'importe quel instantané en lecture seule dans l'Explorateur de tables, et de rétablir ou de restaurer la table à un instantané antérieur.

## Ouvrir le panneau Instantanés

Dans la liste **Tables** du projet, cliquez sur le bouton d'instantané/de retour arrière dans la ligne d'une table. Le panneau **Instantanés** s'ouvre et liste les instantanés de la table, du plus récent au plus ancien :

- **Quand** — la date et l'heure de prise de l'instantané.
- **Lignes** — le nombre de lignes de la table lors de cet instantané.
- **Δ lignes** — la variation du nombre de lignes par rapport à l'instantané précédent, pour voir ce que chaque écriture a ajouté ou supprimé.
- **Taille** — la taille de stockage compressée de l'instantané.
- **Libellé** — un nom, pour les instantanés que vous avez nommés ou épinglés.
- **Retenu** — un marqueur d'épinglage pour les instantanés retenus (conservés au-delà de la période de rétention normale).

## Afficher les données telles qu'elles étaient lors d'un instantané

Il existe deux façons d'afficher les données d'une table à un moment antérieur. Les deux ouvrent l'Explorateur de tables dans une **vue historique en lecture seule**, avec un bandeau indiquant l'instantané affiché et un bouton **Revenir aux données actuelles**.

1. **Depuis le panneau Instantanés** — sélectionnez un instantané et cliquez sur **Afficher à l'instantané**.
2. **Depuis l'Explorateur de tables** — utilisez la liste déroulante **As of** de la barre d'outils. Elle liste les instantanés récents de la table selon ce qui les a écrits, par exemple *after Month-End Close ran*, et leur date ; choisissez-en un pour changer de vue, ou choisissez **Actuel (données en direct)** pour revenir aux données en direct.

Dans la vue historique, cliquez sur **Compare with now** pour voir combien de lignes ont été modifiées, ajoutées ou supprimées depuis, les lignes qui diffèrent étant marquées dans la grille. Consultez [Une table lors d'une exécution antérieure](/fr/guides/ai-assistant/weave-numbers/#une-table-lors-dune-exécution-antérieure).

<Aside>La vue historique est en lecture seule — c'est une fenêtre sur le passé, pas une copie modifiable. Utilisez **Rétablir** ou **Restaurer** (ci-dessous) si vous voulez ramener d'anciennes données dans une table.</Aside>

## Rétablir ou restaurer un instantané

Sélectionnez un instantané et cliquez sur **Rétablir / Restaurer**. La boîte de dialogue propose deux choix :

- **Rétablir cette table sur place** (par défaut) — remplace les données actuelles de la table par l'instantané. Comme cette opération est destructrice, vous saisissez le nom de la table pour confirmer. Avant le remplacement des données, PlaidCloud capture automatiquement un **instantané de sécurité préalable au rétablissement** de l'état actuel (sur les moteurs de stockage qui prennent en charge l'épinglage) ; vous pouvez donc toujours revenir à votre point de départ. Sur un lakehouse Databend, si les colonnes de la table ont changé depuis l'instantané, un rétablissement sur place est refusé, avec le nom des colonnes modifiées — restaurez plutôt dans une nouvelle table.
- **Restaurer l'instantané dans une nouvelle table** — laisse la table d'origine intacte et crée dans le projet une nouvelle table (dont vous indiquez le nom et le dossier) alimentée à partir de l'instantané, avec les mêmes colonnes que la source. Via l'assistant IA ou MCP, une restauration sans nom indiqué en prend un fondé sur la table source, par exemple `Sales (restored 3f2a9c1d)`.

<Aside type="caution">Un rétablissement sur place écrase les données actuelles de la table. La confirmation saisie et l'instantané de sécurité automatique préalable au rétablissement sont là pour vous protéger — lisez la boîte de dialogue avant de confirmer. Le rétablissement est bloqué tant que le projet est verrouillé.</Aside>

<Aside>Via l'API REST ou MCP, restaurez un instantané sur place en omettant la table cible ou en indiquant la table elle-même. Une restauration sur place bénéficie alors de la même protection que le rétablissement de la boîte de dialogue : un instantané de sécurité préalable au rétablissement lorsque le moteur de stockage le permet, et un enregistrement d'audit. Pour qu'elle soit refusée si la table a été écrite depuis que vous avez listé ses instantanés, transmettez le plus récent instantané que vous avez vu dans `expected_current_snapshot_id`.</Aside>

<Aside>Si une restauration dans une nouvelle table échoue — par exemple parce que l'instantané a expiré —, aucune nouvelle table n'est ajoutée au projet.</Aside>

## Nommage, épinglage et rétention

Les instantanés expirent selon le paramètre de voyage dans le temps de la table (1 jour par défaut, jusqu'à 90 jours) lors du nettoyage nocturne. Le rétablissement ou la restauration fonctionne jusqu'au point restaurable le plus ancien affiché pour la table. Pour en conserver un plus longtemps :

- **Créer un instantané** prend à la demande un instantané retenu des données actuelles — utile avant un rechargement risqué (par exemple, « avant le rechargement du T2 »).
- **Rétention** épingle l'instantané sélectionné ; **Libérer** lève la rétention et le renvoie au cycle de vie normal.

<Aside type="caution">Une rétention conserve plus que le seul instantané concerné — elle conserve l'instantané retenu *et* tous les instantanés écrits après lui ; le stockage continue donc de croître jusqu'à ce que vous leviez la rétention. Remplacer entièrement une table (un upsert ou un remplacement SCD-2) démarre un tout nouvel historique d'instantanés, et toute rétention sur l'ancien est perdue avec lui.</Aside>

Restaurer toutes les tables d'un projet à la fois, via l'API REST, restaure chaque table à son instantané retenu le plus récent et laisse en l'état les tables sans rétention. Un instantané de sécurité préalable au rétablissement ne compte pas comme une rétention, même si le panneau Instantanés peut le marquer comme retenu, sauf si vous retenez aussi vous-même cet instantané, par exemple avec **Rétention**. Les noms d'instantanés commençant par `pre-revert_` sont réservés aux instantanés de sécurité. Si une table ne peut pas être restaurée, les autres le sont quand même, et la requête échoue en nommant chaque table non restaurée et la raison.

<Aside>Le nommage d'un instantané à la demande est disponible sur les tables Lakehouse (StarRocks). La rétention et la libération d'un instantané fonctionnent désormais aussi sur les tables reposant sur Databend ; les instantanés y sont toujours conservés pendant la période de rétention, même sans rétention explicite.</Aside>

## Audit

Les rétablissements sur place, qu'ils proviennent de la boîte de dialogue, de l'API REST ou d'un assistant IA, sont enregistrés dans le journal d'audit du lakehouse, y compris l'auteur du rétablissement, sa date, l'instantané rétabli et l'instantané de sécurité conservé — les modifications de tables effectuées via cette fonctionnalité sont donc traçables.
