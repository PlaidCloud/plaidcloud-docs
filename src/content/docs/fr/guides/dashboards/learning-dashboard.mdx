## Description


Les tableaux de bord prennent en charge un large éventail de cas d'usage, du reporting statique à l'analyse dynamique. Ils répondent à des besoins de reporting complexes tout en offrant une interface intuitive de type pointer-cliquer. Il peut arriver que vous rencontriez des difficultés. Un membre de l'équipe de support PlaidCloud est toujours disponible pour vous aider, mais nous avons aussi rassemblé ci-dessous quelques conseils au cas où vous rencontreriez un problème similaire.



## **Questions et réponses courantes sur les tableaux de bord**



### Navigateur recommandé


En raison d'une mise en cache fréquente, Google Chrome est généralement le meilleur navigateur à utiliser avec les tableaux de bord. Si vous utilisez un autre navigateur et rencontrez un problème, nous vous suggérons d'abord de vider le cache et les cookies pour voir si cela résout le problème. Sinon, nous vous suggérons de passer à Google Chrome et de vérifier si le problème se reproduit.



### Délai de synchronisation


* *Problème :* Après avoir dépublié puis publié des tables dans la zone Tableaux de bord, les données ne semblent pas se synchroniser correctement.
* *Solutions :* Republier une table vide les résultats en cache de chaque graphique qui la lit ; un tableau de bord ouvert après l'exécution du workflow affiche donc les nouvelles données sans actualisation manuelle. Si ce n'est pas le cas, vérifiez que l'exécution s'est terminée et qu'elle a republié la table attendue. Consultez [Mise en cache des tableaux de bord](/fr/guides/dashboards/dashboard-caching/).

### Erreur de synchronisation de table


* *Problème :* Après avoir recréé une table avec le même nom publié qu'une table précédente, la table ne se synchronise pas, même après avoir actualisé le tableau de bord, publié, dépublié et republié la table.
* *Solutions :* Republiez la table sous un autre nom. Le modèle de données des tableaux de bord n'autorise pas les tables en double, ni les tables ayant le même nom publié et le même ID de projet.

### Avertissement de cache


* *Problème :* Un avertissement est apparu en haut à droite : « Loaded data cached **3 hours ago**. Click to force-refresh. »
* *Solutions :* Cliquez sur l'avertissement pour forcer l'actualisation du cache. Vous pouvez aussi cliquer sur le menu déroulant à côté de « Edit dashboard » et y sélectionner « Force refresh dashboard ». L'une ou l'autre de ces options actualise au sein du système et est préférable à l'actualisation du navigateur web lui-même. La durée pendant laquelle un résultat est conservé est configurable ; consultez [Mise en cache des tableaux de bord](/fr/guides/dashboards/dashboard-caching/).

### Avertissement d'autorisation


* *Problème :* Mon tableau de bord publié affiche la même erreur dans chaque section où des données devraient apparaître : « This endpoint requires the datasource… permission »
* *Solutions :* Vérifiez que les sources de données ne sont pas anciennes. Il est probable que les graphiques puisent dans des éléments obsolètes. Dans ce cas, mettez à jour les graphiques avec de nouvelles sources de données.
* *Problème :* J'obtiens le même avertissement d'autorisation que ci-dessus, mais mon collègue peut voir les données du graphique.
* *Solutions :* Si le problème est qu'une personne peut voir les données des graphiques et qu'une autre ne le peut pas, la seconde personne peut avoir besoin qu'une autorisation lui soit accordée par quelqu'un de la catégorie autorisée. Pour ce faire :


	1. Accédez à Charts
	2. Sélectionnez la deuxième petite icône représentant un crayon et une feuille à côté du graphique auquel vous voulez accorder l'accès
	3. Cliquez sur Edit Table
	4. Cliquez sur Detail
	5. Cliquez sur Owners, ajoutez le nom de la personne à qui vous voulez accorder l'accès, puis enregistrez.

<Aside>Bonne pratique : chaque fois que vous créez et enregistrez un nouveau graphique, ajoutez à ce moment-là toutes les personnes concernées à la section Owners. Sinon, vous devrez revenir modifier et ajouter des propriétaires chaque fois qu'une nouvelle personne a besoin d'un accès.</Aside>


### Enregistrer les filtres modifiés dans le tableau de bord


* *Problème :* J'ai modifié des filtres dans mon modèle brouillon et je veux les enregistrer dans mon tableau de bord. Les filtres ne figurent pas dans la liste. Dans mon modèle brouillon, un avertissement indiquait : « There is no chart definition associated with this component, could it have been deleted? Delete this container and save to remove this message. »
* *Solutions :* Accédez à « Edit Chart ». À partir de là, vérifiez que la section « Dashboards » contient le bon tableau de bord. Si elle est vide, ajoutez le nom du bon tableau de bord.

### Mise en forme des nombres : ruptures


* *Problème :* La mise en forme de mes nombres est cassée et désordonnée.
* *Solutions :* La cause la plus probable de cette rupture est la présence de valeurs nulles dans une colonne numérique. À l'aide d'un filtre, éliminez toutes les valeurs nulles des colonnes numériques. Essayez de relancer. Si cela ne fonctionne pas, consultez les informations fournies ici : http://bl.ocks.org/zanarmstrong/05c1e95bf7aa16c4768e ou ici : https://github.com/apache-superset/superset-ui/issues. Enfin, n'hésitez jamais à contacter un membre de l'équipe de support PlaidCloud. Ce problème est connu et une solution plus pérenne est en cours de développement.

### Mise en forme des nombres


Pour arrondir les nombres à l'entier le plus proche :


1. *À ne pas utiliser :* ,.0f
2. *À utiliser à la place :* ,d ou $,d pour les dollars

### Importer un tableau de bord existant


* *Problème :* J'importe un tableau de bord existant et j'obtiens une erreur sur mon export.
* *Solutions :* Commencez par vérifier le fichier. Les tableaux de bord et les jeux de données s'importent à partir du fichier ZIP que produit **Exporter**. Un ancien fichier d'export JSON ou YAML est refusé ; exportez donc de nouveau le tableau de bord et importez le nouveau fichier ZIP.
* Vérifiez ensuite si le tableau de bord possède un « Slug ». Pour cela, ouvrez Edit Dashboard : la deuxième section s'intitule Slug. Si cette section est vide ou indique « null », ce n'est pas la cause du problème. Sinon, le slug doit être unique : remplacez-le par une valeur qu'aucun autre tableau de bord n'utilise, exportez de nouveau, puis importez le nouveau fichier.
