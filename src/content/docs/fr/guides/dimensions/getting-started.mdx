Les dimensions sont les hiérarchies de PlaidCloud — les arbres que vous utilisez pour organiser les centres de coûts, les produits, les comptes, la géographie, les périodes ou toute autre structure consolidée. Elles constituent le fondement sur lequel reposent les allocations, les tableaux de bord et les rapports.

## Quand utiliser une dimension

Recourez à une dimension lorsque vous devez :

- Consolider des valeurs des feuilles vers les parents (additionner les coûts par service, puis par région, puis pour l'entreprise)
- Allouer d'un ensemble de lignes à un autre à partir d'une hiérarchie partagée (répartir le coût informatique entre les unités opérationnelles)
- Découper un tableau de bord selon une structure plus profonde qu'une simple liste (explorer du continent au pays puis à la ville)
- Appliquer la même logique de regroupement à plusieurs endroits — définissez l'arbre une fois, référencez-le partout

Si vos données sont déjà à plat et à une seule dimension, vous n'avez pas besoin d'une dimension. Une table ordinaire suffit.

## Comment les dimensions sont structurées

Chaque dimension possède une **hiérarchie principale** — l'arbre canonique dans lequel chaque feuille est enregistrée exactement une fois. Par-dessus, vous pouvez superposer des **hiérarchies alternatives** qui reconsolident les mêmes feuilles sous des parents différents (par exemple, l'arbre principal regroupe les centres de coûts par service, une alternative les regroupe par région).

Chaque nœud de l'arbre peut porter des propriétés, des alias et des valeurs ; une hiérarchie est donc plus qu'un arbre de noms — c'est une structure dotée de métadonnées auxquelles les allocations et les rapports peuvent se référer.

Pour les mécanismes de création, de copie, de tri et de gestion des dimensions, consultez [Utiliser les dimensions (hiérarchies)](/fr/guides/dimensions/dimensions/).

## Comment les dimensions sont chargées

Les dimensions sont généralement alimentées à partir d'une table source via un workflow :

- **Format parent-enfant** — deux colonnes (parent, enfant), une arête par ligne
- **Format par niveaux** — une colonne par niveau de la hiérarchie, un chemin complet par ligne

Consultez [Charger et décharger des dimensions](/fr/guides/dimensions/loading-unloading/) pour le processus de chargement, et l'étape de workflow [Dimension Load](/fr/reference/workflow-steps/dimensions/dimension-load/) pour l'ensemble des options.
