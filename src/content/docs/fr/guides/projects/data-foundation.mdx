**Data Foundation** est le socle de données financières de vos projets PlaidCloud. Son **Common Finance Model** réunit les données ERP de plusieurs systèmes ERP, et de plusieurs instances de chacun, dans un seul modèle : un seul plan comptable, un seul ensemble d'entités et une seule devise de reporting. Les rapports, les métriques et les assistants IA construits sur le modèle lisent tous les mêmes chiffres, quel que soit l'ERP d'origine.

Votre ERP se connecte par sa connexion PlaidCloud : le grand livre, la balance de vérification, les données de base et les budgets arrivent donc directement de la source, sans rien à exporter. Les fichiers ajoutent les données qu'un système ne détient pas, comme les taux de change, les inducteurs d'allocation ou un budget tenu en dehors de l'ERP, et peuvent remplacer les lignes ERP qu'ils couvrent. **Charger** harmonise chaque source dans le modèle, la convertit dans la devise de reporting et vérifie la concordance des totaux, le tout depuis l'onglet **Foundation** du projet. Lorsque des sources utilisent le même code pour des choses différentes, vous indiquez si elles désignent la même chose, et une consolidation de gestion construit le compte de résultat du groupe avec les opérations intersociétés éliminées. Les modèles, tels que **Rentabilité de l'entreprise**, construisent leurs rapports et leurs modèles par-dessus.

## Connecter votre ERP

Votre ERP se connecte à Data Foundation par sa connexion PlaidCloud. Data Foundation lit directement à partir de celle-ci le grand livre, la balance de vérification, les données de base, les taux de change et les budgets, et ne fait que lire. Vous pouvez choisir une connexion existante ou en créer une dans l'onglet ; les [guides de connexion](/fr/guides/connections/) couvrent la configuration de l'accès de chaque ERP.

<Steps>

1. Dans Analyze, ouvrez **Projets** et cliquez sur **Nouveau projet**. Saisissez un nom et, sous **Partir de**, choisissez un modèle, tel que **Rentabilité de l'entreprise (modèle)**, au lieu de **Projet vierge**. Cliquez sur **Créer**.

   Le projet s'ouvre sur son onglet **Foundation**. Il est privé et vous en êtes le seul Architecte, jusqu'à ce que vous le partagiez.

2. Dans l'onglet **Foundation**, choisissez une connexion existante pour votre ERP, ou **Créer une nouvelle connexion**. Chaque connexion existante liste les workflows qui l'utilisent déjà, ou indique **Pas encore utilisé par un workflow**.

3. Pour une nouvelle connexion, saisissez un **Nom de la connexion**, choisissez l'**Environnement** et renseignez les identifiants que demande la connexion à votre ERP.

   Vous n'avez pas encore les identifiants ? Le formulaire affiche une demande d'accès prête à l'emploi pour votre administrateur ERP. Cliquez sur **Copier la demande** ou **Envoyer la demande par e-mail**, envoyez-la et saisissez les valeurs qu'il vous renvoie.

4. Cliquez sur **Tester la connexion**. PlaidCloud se connecte et essaie de lire chaque jeu de données, puis indique pour chacun **Lisible**, **Autorisation manquante** ou **Erreur**. Lorsqu'un élément manque, il nomme les autorisations à demander à votre administrateur ERP d'ajouter.

5. Définissez **Mois d'historique** : le nombre de mois à charger en remontant dans le temps, de 1 à 120. La valeur par défaut est 24.

6. Pour une connexion existante, cochez les entités à charger, ou laissez-les toutes décochées pour charger toutes les entités. Les entités inactives et d'élimination restent masquées tant que vous ne choisissez pas de les afficher. Cliquez ensuite sur **Connecter**.

7. Pour une nouvelle connexion, cliquez sur **Connecter** pour la créer. Cochez ensuite les entités à charger et cliquez de nouveau sur **Connecter** pour les enregistrer. Tant que vous ne l'avez pas fait, toutes les entités sont chargées.

8. Pour ajouter un autre système ERP ou une autre instance, répétez ces étapes et cochez **Ajouter comme source supplémentaire au lieu de remplacer la source actuelle** avant de cliquer sur **Connecter**. Sans cette option, la nouvelle connexion remplace la source actuelle.

</Steps>

Une fois la connexion établie, la carte indique la connexion, l'environnement, les entités et les mois d'historique que charge le projet.

Chaque chargement ne lit que ce qui a changé : les périodes ouvertes et la dernière période clôturée sont relues, et les périodes clôturées déjà chargées sont conservées. Augmenter **Mois d'historique** ne lit que les mois ajoutés. Un taux de change, une correspondance des entités ou une devise de reporting modifiés font relire les mois qu'ils concernent.

## Sources

Chaque système et chaque instance ERP à partir desquels le projet charge des données est une source. La liste **Sources** de l'onglet **Foundation** affiche une ligne pour chacune, dans l'ordre, avec son nom, la date de son dernier chargement, le nombre de lignes fournies et les livres de reporting lus, par exemple `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Une source qui n'a pas encore été chargée indique **pas encore chargé**. Les fichiers que vous confirmez sont aussi des sources.

Ouvrez **Avancé** sur une source pour modifier la façon dont elle est utilisée :

| Paramètre | Fonction |
|---|---|
| **Nom** | Le libellé que les rapports, les questions de correspondance et les messages utilisent pour la source. |
| **Rang dans l'ordre** | Le rang de la source. Lorsque deux sources couvrent le même mois de la même société, celle qui est plus haut dans l'ordre l'emporte. |
| **Livres de reporting, séparés par des virgules** | Les livres comptables à lire, pour un système qui en tient plusieurs. **Tous les livres de reporting** lit chaque livre. |
| **Société**, **De (2026-01)** et **À (2026-12)** | Les mois que cette source fournit pour chaque société. Laissez un mois vide pour ne fixer aucune limite. Écrivez les mois sous la forme année et mois, par exemple `2026-03`. |

Cliquez sur **Enregistrer** pour conserver vos modifications. Pour retirer une source, cliquez sur **Supprimer cette source** et confirmez avec **Supprimer**. Tout ce qui en a été chargé est supprimé, et vous pouvez la reconnecter plus tard.

Modifier les sources ne relit pas votre ERP. La carte **Dernier chargement** indique **Modifications pas encore appliquées** tant que vous n'avez pas cliqué sur **Appliquer les modifications**, qui lance un chargement à partir des données déjà récupérées : il harmonise de nouveau les sources avec votre nouvel ordre, vos correspondances, vos noms et vos fichiers, puis reconstruit le modèle. Cliquez sur **Charger** lorsque vous voulez aussi des données fraîches issues des ERP.

## Ajouter des fichiers pour les données extérieures à votre ERP

Les fichiers complètent votre connexion ERP avec des données qu'un système ne détient pas, comme les taux de change, les inducteurs d'allocation, une [Correspondance des entités](#correspondance-des-entités) ou un budget tenu en dehors de l'ERP. Chaque fichier appartient à l'un des jeux de données listés sous [Tables du Common Finance Model](#tables-du-common-finance-model).

<Steps>

1. Sous **Fichiers**, choisissez le **Compte de documents** où stocker le fichier.

2. Déposez un fichier CSV ou Excel sur **Déposez un fichier CSV ou Excel ici**, ou cliquez sur **Choisir un fichier**. Le fichier est téléversé dans le dossier `/foundation/` du compte de documents.

   Pour un fichier qui se trouve déjà dans le compte de documents, saisissez son **Chemin du fichier**, par exemple `/foundation/budget.csv`, et cliquez sur **Ajouter un fichier**.

   Pour lire chaque mois un nouveau fichier, ajoutez tous les fichiers d'un dossier dont le nom correspond : saisissez le dossier et ce que **Les noms de fichier** contiennent, commencent par, terminent par, correspondent exactement à ou correspondent comme motif, puis cliquez sur **Ajouter des fichiers**. Les fichiers situés dans des dossiers imbriqués ne sont pas lus.

3. PlaidCloud lit le fichier et propose une correspondance :

   - **Séparateur, séparateur décimal et dates détectés.** Le séparateur (virgule, point-virgule, tabulation ou barre verticale), le séparateur décimal et le format de date sont détectés pour vous.
   - **Jeu de données** : la table du Common Finance Model à laquelle appartient le fichier, déterminée d'après le nom du fichier et les en-têtes de colonnes. Lorsque la correspondance n'est pas claire, choisissez-la dans la liste.
   - **Séparateur décimal** : **Point (1,234.56)** ou **Virgule (1.234,56)**.
   - **Format de date** : affiché lorsque le fichier contient des dates. Modifiez-le si le format détecté est incorrect : `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Une grille **Colonne du fichier**, **Type**, **Exemples** et **Destination**. Modifiez **Destination** pour envoyer une colonne vers un autre champ, ou vers **Ne pas charger**.

4. Répondez aux questions que soulève le fichier, telles que **À quelle société ce fichier se rapporte-t-il ?**, **Dans quelle devise sont les montants ?**, **Ces montants sont-ils cumulés depuis le début de l'exercice ou pour le mois ?**, **Les montants sont-ils exprimés en milliers ou en millions ?** ou **Les chiffres d'affaires sont-ils affichés sous forme de nombres négatifs ?** Chacune n'est posée que si le fichier ne répond pas déjà.

5. Vérifiez la destination de chaque colonne, puis cliquez sur **Confirmer la correspondance**.

</Steps>

Ces options apparaissent sur un fichier lorsqu'elles s'appliquent :

| Option | Utilisez-la pour |
|---|---|
| **À quelle source ces lignes s'appliquent-elles ?** | Limiter un fichier de correspondance des codes à une seule source. **Toutes les sources** l'applique à toutes. |
| **D'où provient ce fichier ?** | Indiquer si le fichier contient **Les codes propres à ce projet** ou provient d'**Un autre système**, que vous nommez, par exemple `SAP Germany export`. Un fichier issu d'un autre système est contrôlé pour les codes partagés comme une source ERP. |
| **Fractionner … en … parties à chaque …** (sous **Avancé**) | Fractionner une colonne qui contient plusieurs valeurs, comme `100-200-300`, et envoyer chaque partie vers son propre champ. |
| **Dans quelle devise établissez-vous vos rapports ?** | Définir la devise de reporting lorsque le projet n'en a pas encore. Écrivez-la en trois lettres, par exemple `USD`. |
| **Il s'agit de résultats consolidés (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Charger les résultats de votre système de consolidation afin que le compte de résultat du groupe puisse être [rapproché](#rapprocher-avec-votre-système-de-consolidation). |

Pour retirer un fichier du projet, cliquez sur **Supprimer** à côté de lui sous **Fichiers**, ou sur **Supprimer ce fichier** dans sa correspondance, et confirmez. Ses chiffres quittent vos rapports la prochaine fois que vous cliquez sur **Appliquer les modifications**.

Lorsque PlaidCloud ne parvient pas à déterminer seul le jeu de données, le séparateur décimal ou l'ordre des dates, par exemple pour un fichier dont les dates peuvent se lire jour/mois ou mois/jour, il vous demande de choisir avant que vous ne confirmiez. Ajouter un second fichier pour le même jeu de données remplace le premier. Si les colonnes d'un fichier ultérieur ne correspondent pas au jeu de données, le chargement nomme le fichier et les colonnes et vous invite à corriger le fichier ou le nom de ses colonnes, ou à définir le paramètre **Incohérence de schéma** de l'étape sur `union`.

Les fichiers acceptés sont les fichiers texte CSV, TSV et TXT, les fichiers Excel `.xlsx` (lus à partir de la première feuille) et les fichiers Parquet.

<Aside type="note">
Un fichier absent ou vide n'arrête jamais un chargement. L'ajouter indique qu'il n'y a encore rien à faire correspondre, et un chargement se termine par un avertissement qui nomme le chemin, en laissant ce jeu de données vide. Ajoutez de nouveau le fichier une fois qu'il existe.
</Aside>

## Charger vos données

Cliquez sur **Charger** dans la carte **Charger** ou dans la carte **Dernier chargement**. Le chargement lit votre ERP connecté et vos fichiers confirmés, les harmonise dans le Common Finance Model, les convertit dans la devise de reporting, exécute les contrôles de préparation et reconstruit les modèles du modèle de projet.

- Un seul chargement s'exécute à la fois pour un projet. Un deuxième **Charger** ou **Appliquer les modifications** indique qu'un chargement est déjà en cours, et vous ne pouvez pas modifier les sources pendant qu'un chargement s'exécute.
- Si d'autres workflows utilisent la même connexion ERP, le premier chargement les liste et vous demande de confirmer, car un chargement lit l'ERP et peut ralentir ces workflows. Cliquez sur **Charger quand même** pour continuer.
- Après une mise à niveau de PlaidCloud, le **Charger** d'un Architecte met aussi à jour les workflows générés du projet, en créant les tables de travail dont ils ont besoin. D'ici là, la page d'état affiche un élément orange, « Les workflows ont été générés par une version antérieure. Le chargement d'un Architecte les met à jour. », et le **Charger** d'un Gestionnaire avertit que seul un Architecte peut les mettre à jour.
- Un chargement en échec s'affiche en rouge et ne se cache jamais derrière des résultats antérieurs. Si la consolidation échoue, l'état nomme l'étape à laquelle elle s'est arrêtée au lieu d'afficher d'anciens résultats de groupe. Les lignes d'un chargement antérieur affichent **Issu d'un chargement précédent. Rechargez.** tant qu'un chargement n'a pas réussi.
- Si la lecture d'une entité et d'une période échoue, le reste se charge quand même. Exécutez de nouveau **Charger** pour ne récupérer que ce qui a échoué.

### Lignes retenues

Lorsque des sources se chevauchent, un chargement conserve une seule copie de chaque chiffre et retient les autres au lieu de les compter deux fois. Les lignes retenues sont enregistrées avec leur source, leur entité et le motif, et le chargement se termine par un avertissement qui nomme les nombres, par exemple `120 rows of NetSuite EU also provided by a source ranked ahead`. Les motifs sont les suivants :

| Motif | Signification |
|---|---|
| Dans un autre livre comptable | La ligne appartient à un livre de reporting que la source n'est pas configurée pour lire. |
| En dehors des périodes fournies par la source | La ligne tombe en dehors des mois **De** et **À** définis pour la société. |
| Également fourni par une source mieux classée | Une source plus haut dans l'ordre couvre la même société et le même mois. |
| Également dans un fichier antérieur de la source | Un fichier antérieur de la même source couvre déjà le mois. |
| Remplacé par un fichier | Un fichier remplace les lignes ERP de cette entité et de ce mois. |
| Porteur d'un code qu'une autre source utilise aussi | Le code attend votre réponse. Voir [Faire correspondre les codes entre les sources](#faire-correspondre-les-codes-entre-les-sources). |
| Porteur d'un code mappé à deux codes | La table de correspondance des codes donne deux réponses au code. |

Les comptes statistiques passent aux inducteurs d'allocation au lieu du grand livre, et s'affichent comme déplacés, et non comme un problème.

### Données ERP et fichiers ensemble

Un fichier ne remplace que ce qu'il couvre, et les autres lignes de votre ERP restent.

- Les **fichiers de données de base** (comptes, départements, clients, produits et valeurs de segment) remplacent les lignes ERP ayant le même code.
- Les **fichiers de transactions** remplacent les lignes ERP de la même entité et du même mois. Les fichiers de grand livre et de balance de vérification correspondent aussi par registre comptable, les fichiers de budget par scénario, et les fichiers d'inducteurs statistiques par scénario et inducteur.

Si un fichier cesse ensuite de couvrir un mois, les données de l'ERP pour ce mois reviennent au chargement suivant.

## Correspondance des entités

Chaque source nomme ses entités avec ses propres codes. La **Correspondance des entités** associe ces codes aux entités de votre référentiel d'entités, de sorte que les lignes de toutes les sources arrivent sur la même entité.

Pour en utiliser une, ajoutez un fichier CSV ou Excel et choisissez le jeu de données **Correspondance des entités** :

| Colonne | Contenu |
|---|---|
| `source_entity` | Le code tel que la source le porte, comme un code de société. |
| `entity` | L'entité à laquelle il appartient, telle que la nomme le référentiel d'entités. |

- Un code absent de la correspondance est utilisé tel quel.
- Plusieurs codes peuvent correspondre à une même entité. Leurs lignes sont combinées, et un mois est considéré comme clôturé une fois qu'il l'est pour tous.
- Les codes de la correspondance s'appliquent à toutes les sources ; les codes d'entité de chaque source doivent donc être uniques d'une source à l'autre.
- Une ligne d'un fichier **Entités** remplace l'entité de l'ERP ayant le même code d'entité.

Le contrôle **Entités non mappées** signale toute ligne dont l'entité ne figure ni dans le référentiel d'entités ni dans la correspondance. Tant qu'aucun référentiel d'entités n'est chargé, il affiche **– Sans objet**.

## Faire correspondre les codes entre les sources

Deux sources peuvent utiliser le même code pour des choses différentes, ou des codes différents pour la même chose. Lorsqu'un code apparaît dans plusieurs sources, Data Foundation retient ses lignes jusqu'à ce que vous indiquiez s'il signifie partout la même chose, afin que chaque montant ne soit compté qu'une fois. Le contrôle **Codes en attente de votre réponse** les liste, les 10 premiers puis « et K autres », et la carte **Que faire ensuite** de l'onglet **Foundation** comporte un bouton **Examiner**.

**Examiner** ouvre **Codes en attente de votre réponse**. Il regroupe les codes selon leur nature : **Types de compte**, **Sociétés**, **Comptes**, **Départements**, **Centres de profit**, **Clients**, **Produits** et chaque catégorie supplémentaire. Pour chaque code, il montre comment chaque source l'appelle et une suggestion :

- **Semble identique** lorsque les sources donnent le même nom au code.
- **Semble différent** lorsque les noms diffèrent.
- **Impossible de trancher. Répondez, s'il vous plaît.** lorsqu'il n'y a rien sur quoi s'appuyer.

Répondez code par code avec **Oui, identique** ou **Non, différent**, ou répondez à tout un groupe d'un coup avec **Tout accepter** (retenir chaque suggestion), **Tous identiques** ou **Tous différents**. Pour les comptes, vous pouvez aussi répondre à tout un groupe parent du plan comptable d'un coup. Lorsqu'une source ne porte pas de types de compte, choisissez **Utiliser ce type** pour un groupe de comptes : **Chiffre d'affaires**, **Coût des marchandises vendues**, **Charges d'exploitation**, **Produits et charges hors exploitation**, **Actifs**, **Passifs** ou **Capitaux propres**.

Les correspondances sont conservées pour chaque source et chaque dimension : une réponse donnée pour les départements d'une source ne modifie donc jamais les comptes d'une autre. Les réponses sont enregistrées au fur et à mesure, avec **Enregistré. Appuyez sur Appliquer les modifications pour utiliser vos réponses.** Cliquez sur **Appliquer les modifications** pour les utiliser.

Vous pouvez aussi fournir les correspondances dans un fichier. Ajoutez un fichier avec le jeu de données **Correspondance des codes**, et choisissez **À quelle source ces lignes s'appliquent-elles ?** pour le limiter à une seule source.

## Choisir à partir de quand chaque source compte

Lorsque deux sources fournissent les mêmes mois, le contrôle **Quelle source couvre quels mois** vous demande de choisir. Cliquez sur **Choisir à partir de quand chaque source compte** dans la carte **Que faire ensuite** pour ouvrir **À partir de quand chaque source compte**, qui liste chaque chevauchement par société. Choisissez la source qui compte, saisissez le mois à partir duquel elle compte dans **Ce mois est**, par exemple `2026-04`, et cliquez sur **Appliquer les modifications**. L'autre source conserve les mois antérieurs.

La même boîte de dialogue avertit lorsque deux sources donnent des taux de change différents pour une devise ; les taux de la source plus haut dans l'ordre sont utilisés.

## Conversion de devises

Chaque chargement convertit les montants du grand livre, de la balance de vérification, des ventes, des stocks et du budget de leur devise locale vers une seule devise de reporting. Les rapports et les modèles lisent les montants convertis ; les entités dans des devises différentes, issues de n'importe quel système, totalisent donc correctement.

### La devise de reporting

Pour choisir la devise de reporting, définissez la variable de projet `reporting_currency` sur un code de devise tel que `USD`. Voir [Gérer les variables de projet](/fr/guides/projects/managing-projects/#gestion-des-variables-du-projet). Le modèle de projet la crée vide. Tant qu'elle est vide, chaque chargement utilise la première des valeurs suivantes qui désigne exactement une devise :

1. La devise du groupe des entités.
2. La devise locale des entités de premier niveau, celles qui n'ont pas de parent.
3. La devise locale des fichiers.

Si aucune ne désigne exactement une devise, **Conversion de devises** affiche un problème tant que vous n'avez pas défini `reporting_currency`.

Les montants déjà dans la devise de reporting restent tels quels ; un projet dont toutes les données sont dans une seule devise n'a donc besoin d'aucun taux.

Les fichiers de ventes, de stocks et de budget peuvent aussi porter une devise. Faites correspondre une colonne nommée `Currency` ou `Local Currency` et elle est prise en compte automatiquement, et les montants locaux du fichier sont convertis dans la devise de reporting. Un montant de groupe ou de reporting déjà présent dans le fichier est conservé tel quel. Le coût standard des produits n'est pas converti.

### Taux de change

Un taux convertit une unité d'une devise dans la devise de reporting pour un mois : le montant converti est le montant local multiplié par le taux.

- **À partir de votre ERP**, chaque chargement lit les taux de change que détient l'ERP.
- **À partir d'un fichier**, ajoutez un fichier CSV ou Excel et choisissez le jeu de données **Taux de change**. Un taux du fichier remplace le taux de l'ERP pour les mêmes devises et le même mois. Utilisez un fichier pour établir vos rapports dans une devise pour laquelle vos ERP ne publient pas de taux, ou pour ajouter des taux prévisionnels pour les mois budgétés.

| Colonne | Contenu |
|---|---|
| `from_currency` | La devise de départ de la conversion, par exemple `EUR`. |
| `to_currency` | La devise de reporting, par exemple `USD`. |
| `period` | Le mois, au format `YYYY-MM`. |
| `average_rate` | Le taux moyen du mois. |
| `closing_rate` | Le taux de fin de mois. |
| `historical_rate` | Le taux historique, pour les capitaux propres et pour les comptes définis au taux historique. |

Seuls les taux vers la devise de reporting sont utilisés. Un taux coté dans l'autre sens, de la devise de reporting vers une autre devise, n'est pas inversé.

### Quel taux s'applique

Chaque ligne est convertie à partir de sa propre devise ; une ligne dans une devise différente de celle de son entité est donc convertie à partir de la devise dans laquelle elle est exprimée. La première règle qui correspond à la ligne s'applique :

| Ligne | Taux |
|---|---|
| Comptes statistiques et comptes sans écritures | Non converti. |
| Déjà dans la devise de reporting | Non converti. |
| Compte avec un type de taux | Ce taux : moyen, de clôture ou historique. Le taux historique se rabat sur le taux de clôture lorsqu'il n'existe pas de taux historique. À partir d'un ERP, le type de taux est celui propre au compte. Dans un fichier de plan comptable, faites correspondre une colonne de type de taux à `fx_rate_type` avec `average`, `closing` ou `historical`. |
| Ligne de vente | Le taux moyen de la période. |
| Solde de stock | Le taux de clôture de la période. |
| Ligne de budget | Par compte, comme le grand livre : le taux moyen pour les comptes de compte de résultat et le taux de clôture pour les comptes de bilan. |
| Compte de compte de résultat | Le taux moyen de la période. |
| Compte de capitaux propres | Le taux historique, ou le taux de clôture lorsqu'il n'y a pas de taux historique. |
| Tout autre compte de bilan | Le taux de clôture de la période. |

Les montants convertis ne sont pas arrondis, de sorte que les totaux ne dérivent pas.

<Aside type="note">
La balance de vérification contient les mouvements de chaque période ; les montants de bilan sont donc les mouvements de chaque mois convertis au taux de clôture de ce mois. Ce n'est pas un bilan reconverti au taux de fin de période, et il n'y a ni écart de conversion cumulé ni élimination intersociétés. Utilisez les montants convertis pour le compte de résultat.
</Aside>

## Hiérarchies

Chaque chargement reconstruit les dimensions à partir des données de base de chaque source. Il y a sept dimensions au départ, et jusqu'à dix catégories supplémentaires :

| Dimension | Construite à partir de |
|---|---|
| **Entité** | Les entités et leurs parents |
| **Compte** | Le plan comptable et les comptes parents |
| **Département** | Les départements et leurs parents |
| **Client** | Les clients et leurs clients parents |
| **Produit** | Les produits et leurs produits parents |
| **Segment 1** | Les valeurs de segment pour `segment_1` |
| **Segment 2** | Les valeurs de segment pour `segment_2` |
| **Segment 3** à **Segment 10** | Les valeurs de segment pour `segment_3` à `segment_10`, lorsque vos sources les portent |

- Un enregistrement sans parent, ou qui se désigne lui-même comme son parent, est chargé comme membre de premier niveau.
- Comme chaque chargement reconstruit les hiérarchies, modifiez un parent dans l'ERP ou dans votre fichier, et non dans la dimension.
- Un problème dans une hiérarchie n'affecte que cette dimension. Le chargement et les modèles du modèle de projet se terminent quand même.
- Vous pouvez renommer chaque catégorie supplémentaire selon ce qu'elle contient, par exemple **Classe** ou **Région**. Sous **Renommer les catégories supplémentaires**, saisissez les noms que vos rapports utilisent et cliquez sur **Enregistrer les noms**. Les noms comportent des lettres, des chiffres, des espaces, des points, des tirets et des traits de soulignement, jusqu'à 60 caractères.
- Chaque source indique sous quel nom, parmi les noms de vos catégories, chacune de ses propres catégories supplémentaires se range. Ouvrez **Avancé** sur la source, choisissez le nom de chacune, ou choisissez **Laisser de côté**, et cliquez sur **Enregistrer**. Les sources qui désignent une catégorie par des noms différents, comme `Class` et `Business area`, partagent alors un seul emplacement.

Pour fournir les hiérarchies de segments à partir d'un fichier, choisissez le jeu de données **Valeurs de segment** :

| Colonne | Contenu |
|---|---|
| `segment` | Le segment auquel appartient la valeur : `segment_1` à `segment_10`. |
| `segment_value` | La valeur, telle que la portent les lignes du grand livre, des ventes et du budget. |
| `segment_value_name` | Son nom. |
| `parent_segment_value` | Son parent au sein du même segment. |

## Contrôles de préparation

Après chaque chargement, la grille **Préparation** liste chaque contrôle pour chaque entité et chaque période, avec l'un de ces états :

| État | Signification |
|---|---|
| **● Prêt** | Le contrôle a réussi. |
| **▲ À examiner** | Mérite un coup d'œil, mais les chiffres sont utilisables. |
| **■ Problème** | Corrigez ceci avant de vous fier aux résultats. |
| **– Sans objet** | Il n'y a pas encore de données pour ce contrôle. |

Les contrôles sont les suivants :

| Contrôle | Ce qu'il confirme |
|---|---|
| **Données chargées** | Chaque période fiscale comporte des lignes de grand livre, et chaque lecture de l'ERP a réussi. Une période clôturée sans ligne est un problème ; une période ouverte sans ligne est à examiner. |
| **La balance de vérification concorde avec le grand livre** | La balance de vérification est égale au grand livre pour chaque entité, période et compte. Lorsque la balance de vérification et le grand livre portent tous deux des départements pour un compte, la concordance est aussi vérifiée pour chaque département. |
| **Les ventes concordent avec le grand livre** | Les lignes de vente sont égales aux comptes de chiffre d'affaires et de CMV du grand livre pour chaque période. |
| **Produits/clients inconnus** | Chaque ligne de vente nomme un produit et un client qui existent dans les référentiels de produits et de clients. |
| **Comptes absents du plan comptable** | Chaque ligne du grand livre nomme un compte du plan comptable. Les lignes dont le compte est inconnu sont exclues du compte de résultat. Un compte avec des écritures mais sans type de compte est aussi un problème, et une source dont le plan type des comptes de chiffre d'affaires mais aucun compte de coût des marchandises vendues est à examiner. |
| **Conversion de devises** | Chaque ligne du grand livre, de la balance de vérification, des ventes, des stocks et du budget a un montant dans la devise de reporting. Une ligne de compte de résultat ou de ventes sans taux est un problème, car le compte de résultat lit les montants convertis. Une ligne de bilan, de stock ou de budget sans taux est à examiner. Un mois de budget sans taux apparaît en orange ; chargez donc des taux prévisionnels pour les mois budgétés. Voir [Conversion de devises](#conversion-de-devises). |
| **Entités non mappées** | Chaque ligne du grand livre, de la balance de vérification et des ventes nomme une entité du référentiel d'entités, directement ou par la correspondance des entités. Sans objet tant qu'aucun référentiel d'entités n'est chargé. Voir [Correspondance des entités](#correspondance-des-entités). |

Les chargements avec plus d'une source ajoutent ces contrôles :

| Contrôle | Ce qu'il confirme |
|---|---|
| **Livre de reporting** | Une source qui porte plusieurs livres comptables pour une entité s'est vu attribuer un livre de reporting choisi. Tant que vous ne choisissez pas, seul le premier livre compte. |
| **Codes en attente de votre réponse** | Chaque code utilisé par plusieurs sources a reçu une réponse. Voir [Faire correspondre les codes entre les sources](#faire-correspondre-les-codes-entre-les-sources). |
| **Catégories supplémentaires de vos sources** | Chaque catégorie supplémentaire qu'une source porte a un nom ou a été laissée de côté. |
| **Quelle source couvre quels mois** | Deux sources ne fournissent pas les mêmes mois d'une société, sauf si vous avez choisi laquelle compte. |
| **Types de compte et hiérarchie** | Chaque parent qu'une dimension nomme existe, et aucun membre n'est son propre parent ni son propre ancêtre. Un parent manquant place ses enfants au sommet de la hiérarchie, et une boucle empêche cette hiérarchie de se charger. Les totaux ne sont pas affectés. |
| **Calendrier fiscal** | Les périodes fiscales de chaque entité sont des mois civils, et chaque mois de lignes peut être placé dans une seule période fiscale. Il est à examiner lorsque les périodes d'une entité ne sont pas des mois civils (4-4-5, 13 périodes), ou lorsque les lignes d'un mois pourraient appartenir à plusieurs périodes fiscales ou que le calendrier fiscal ne contient pas le mois. |

Chaque ligne qui n'est pas prête indique quoi faire dans la colonne **Que faire**, par exemple charger le plan comptable, charger les taux de change ou exécuter de nouveau **Charger** pour une période.

La grille affiche aussi deux contrôles de configuration, qui n'apparaissent que lorsqu'ils sont à examiner :

| Contrôle | Quand il apparaît |
|---|---|
| **Répartition des frais généraux** | Une seule des variables de projet `overhead_department` et `overhead_driver` est définie, ou aucun inducteur d'allocation ne correspond à `overhead_driver`, de sorte que l'allocation ne ferait rien. Définissez les deux, ou videz les deux pour désactiver la répartition des frais généraux. |
| **Comparaison budgétaire** | Des lignes de budget sont chargées, mais aucune ne se trouve dans la version que nomme la variable de projet `budget_version`, de sorte que la comparaison budgétaire serait vide. |

## Consolidation de gestion

Chaque chargement construit une consolidation de gestion : le compte de résultat du groupe de toutes les entités du groupe, dans la devise de reporting, avec les opérations intersociétés éliminées. Elle sert au reporting de gestion. Votre système de consolidation reste la référence pour le groupe statutaire ; effectuez le rapprochement avec lui ci-dessous.

<Aside type="note">
La consolidation de gestion ne couvre que le compte de résultat. Ce n'est pas une consolidation statutaire ou légale, et elle ne comporte ni bilan consolidé, ni écart de conversion, ni écart d'acquisition, ni intérêts minoritaires.
</Aside>

### Choisir le groupe

Sous **Sources**, ouvrez **Groupe** pour voir les sociétés du groupe. Une société que vous décochez reste dans vos rapports à titre individuel, mais est exclue du total du groupe. Cliquez sur **Enregistrer le groupe**. La modification s'applique au prochain **Charger** ou **Appliquer les modifications**. Une nouvelle société fait partie du groupe tant que vous ne la décochez pas.

L'exercice fiscal du groupe commence le mois défini par la variable de projet `group_fy_start_month`, qui vaut `1` sauf modification.

### Ce que vous obtenez

| Table | Contenu |
|---|---|
| **Compte de résultat du groupe** | Une ligne par entité, période et poste (chiffre d'affaires, coût des marchandises vendues, charges d'exploitation, hors exploitation, écart intersociétés), dans la devise de reporting. Le chiffre d'affaires et les coûts portent leur signe naturel. |
| **Compte de résultat du groupe, cumul depuis le début de l'exercice** | La même chose, cumulée depuis le début de l'exercice, jusqu'à la dernière période du groupe entièrement chargée. |
| **Paires intersociétés** | Une ligne par paire d'entités, groupe et période, avec le montant de chaque côté et le résiduel. |
| **Lignes intersociétés** | Les lignes de grand livre derrière un chiffre du groupe ou une paire, avec le partenaire commercial. |
| **Rapprochement** | Le compte de résultat du groupe cumulé depuis le début de l'exercice face à votre système de consolidation. |

Trois noms d'entité apparaissent dans ces tables :

| Entité | Signification |
|---|---|
| **Éliminations** | Les éliminations intersociétés. Elles s'annulent à zéro : laissez-les pour les chiffres du groupe et filtrez-les pour obtenir la somme des entités avant élimination. |
| **Total du groupe** | Le total du système de consolidation, dans le rapprochement. |
| **Non mappé** | Les lignes sans période, et les comptes ou entités de votre système de consolidation que ce projet n'a pas. |

Les métriques **Produits consolidés**, **Résultat consolidé** et **Écart intersociétés**, ainsi qu'un chemin d'analyse pour chaque table, répondent aux questions sur le groupe.

### Éliminations intersociétés

Les lignes intersociétés sont appariées par partenaire commercial. Le partenaire de la ligne est utilisé ; lorsqu'une ligne n'en a pas, c'est celui de son client. Les deux côtés d'une paire sont éliminés, et le montant sur lequel les deux côtés ne concordent pas est comptabilisé sur une ligne d'écart intersociétés. Chaque paire reçoit un motif :

| Motif | Signification |
|---|---|
| **Correspondant** | Les deux côtés ont comptabilisé le même montant. |
| **Un seul côté comptabilisé** | Une entité a comptabilisé la transaction et son partenaire ne l'a pas fait. |
| **Non éliminé** | Une ligne de la paire n'a pas de taux de change ; aucun des deux côtés n'est donc éliminé. |

Une paire est jugée sur son cumul depuis le début de l'exercice. La ligne **Soldes intersociétés** passe à l'orange lorsque l'écart d'une paire dépasse la variable de projet `group_amber` (`1` par défaut) et au rouge au-delà de `group_red` (`1000` par défaut). Les lignes sans partenaire, ou dont le partenaire n'est pas une entité, ne sont pas éliminées et sont comptées sur cette ligne. Une source qui porte des partenaires à côté d'une qui n'en porte pas s'affiche en orange.

Les entités d'élimination propres à une source restent hors du compte de résultat du groupe, et la ligne **Consolidation** l'indique.

### Rapprocher avec votre système de consolidation

Ajoutez sous forme de fichier les résultats que rapporte votre système de consolidation, et cochez **Il s'agit de résultats consolidés (OneStream, Anaplan, SAP Group Reporting, FCCS)** lorsque vous confirmez sa correspondance. Répondez à **De quelle version des chiffres s'agit-il ?** avec le nom du système. La table **Rapprochement** affiche alors **nos chiffres**, **rapporté** et **écart** pour chaque entité et chaque poste, cumulés depuis le début de l'exercice. Un écart s'explique généralement par les lignes **Éliminations**, **Total du groupe** et **Non mappé**, ou par les taux de change que le système utilise. La ligne **Rapprochement avec la source** liste chaque poste au-delà de `group_amber`.

### Qui peut le voir

Les résultats du groupe suivent l'accès aux lignes du projet. Lorsque l'accès aux lignes bloque les résultats du groupe, l'état s'affiche en orange. Une personne qui ne voit que certaines entités voit la somme de ces entités avant élimination. Les lignes **Éliminations** et les tables intersociétés exigent l'accès à toutes les entités.

Si le projet limite qui voit quelles lignes selon une colonne que les tables du groupe ne portent pas, comme le département, les résultats du groupe restent désactivés pour tout le monde et **Consolidation** indique **Les vues du groupe sont désactivées**. Seul un Architecte peut alors cocher **Tous les membres du projet peuvent voir les résultats du groupe** sous **Groupe**. La modification s'applique au prochain **Charger** ou **Appliquer les modifications**.

## Garder les données à jour

Une fois qu'un chargement depuis votre connexion ERP a réussi sans problème, **Actualiser chaque nuit** apparaît dans la carte **Dernier chargement**. Cliquez dessus pour exécuter **Charger** chaque nuit à 2 h 00 dans votre fuseau horaire. La carte affiche alors **Actualisation nocturne : chaque nuit à 2 h 00** et la personne qui l'a configurée.

Le chargement nocturne s'exécute au nom de la personne qui l'a configuré. Si cette personne ne peut plus utiliser la connexion ERP, la grille indique que le chargement nocturne est ignoré ; configurez-le de nouveau. Un projet qui ne contient que des données d'exemple ne peut pas être planifié.

Un fichier absent ou vide lors d'un chargement nocturne se termine par un avertissement qui nomme le chemin, et non par une erreur, et le reste du modèle est quand même chargé.

## Noms métier

**Noms métier** dans l'onglet **Foundation** donne aux codes de votre modèle les noms que votre entreprise utilise. Les rapports, les métriques et l'assistant affichent ces noms, et un nom que vous enregistrez s'applique immédiatement. Les chargements suivants le conservent.

1. Cliquez sur **Ajouter un nom** et choisissez le **Genre** : **Catégorie**, **Ligne de compte de résultat**, **Métrique** ou **Colonne**.
2. Saisissez le **Code** : `segment_1` à `segment_10` pour une catégorie, la clé du poste pour une ligne de compte de résultat, le nom de la métrique, ou `table.column` pour une colonne.
3. Saisissez le **Nom**, d'au plus 60 caractères sur une seule ligne.
4. Cliquez sur **Enregistrer les noms**.

L'enregistrement remplace toute la liste. Une ligne dont le nom est vide supprime ce nom, et **Supprimer la sélection** supprime les lignes que vous cochez. Nommer deux fois le même code est refusé. Les noms métier sont aussi écrits dans la description du chemin d'analyse afin que l'assistant emploie vos mots, et cette description a une limite de longueur : si un nom la rendait trop longue, rien n'est enregistré et vous en êtes informé.

## Expliquer un chiffre

**Expliquer ce chiffre** montre ce qui compose un chiffre du compte de résultat. Dans la grille **Préparation**, une ligne pour une entité et un mois comporte **Expliquer ce chiffre**, qui ouvre la marge d'exploitation de l'entité pour ce mois. La fenêtre décompose le chiffre en couches dont la somme donne le total en haut :

| Couche | Contenu |
|---|---|
| **Issu du grand livre** | Ce que le grand livre a comptabilisé sur le poste. |
| **Alloué en entrée** | Le coût réparti vers cette entité par vos [règles d'allocation](#règles-dallocation). |
| **Alloué en sortie** | Le coût que cette entité a réparti vers d'autres. |
| **Éliminé dans le groupe** | Les opérations intersociétés éliminées dans le résultat du groupe. |

Chaque couche comporte une phrase qui dit ce qu'elle est et ses principaux documents sources, avec leur système source, leur document et leur compte. Seules les couches qui ont des lignes sont affichées. La fenêtre suit votre accès aux lignes : vous n'expliquez que les chiffres que vous pouvez voir. Un chiffre sans rien derrière indique **Rien à expliquer**.

## Règles d'allocation

Les allocations répartissent les coûts partagés, comme les frais généraux, entre les départements, les produits et les clients. Le modèle comporte deux phases : **Phase 1 : frais généraux vers les départements** et **Phase 2 : départements vers produits et clients**. Ouvrez **Actions > Allocations...** pour voir ou modifier la façon dont chacune est réalisée. Sans modification, elles fonctionnent comme avant l'existence de l'assistant. Un lecteur peut ouvrir les règles, mais pas les enregistrer.

Pour chaque phase, l'assistant pose quatre questions :

| Étape | Question | Choix |
|---|---|---|
| **Regroupement** | Quels coûts voulez-vous répartir ? | Le type de compte et, pour la phase 1, le département qui porte le coût, ou **Tous les départements**. |
| **Inducteur** | Selon quoi voulez-vous les répartir ? | **Statistique** que vous avez chargée comme inducteurs d'allocation, comme l'effectif ou la surface en pieds carrés, **Montant net des ventes**, **Quantité vendue** ou **Répartir uniformément**. Utilisez l'inducteur de la **Même période** ou de la **Même période de l'année précédente**. |
| **Cible** | Où atterrissent-ils ? | Phase 1 : départements. Phase 2 : produits, clients, ou les deux. |
| **Méthode** | Que se passe-t-il lorsqu'un inducteur est négatif ? | **Ignorer les valeurs négatives** ou **S'arrêter et me prévenir**. |

Sous les étapes, **Aperçu pour** un mois, écrit sous la forme année et mois comme `2026-09`, montre ce que feraient les règles, y compris celles que vous n'avez pas enregistrées : `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Tout ce qui est non alloué est un coût pour lequel aucun inducteur n'a pu le prendre en charge. L'aperçu suit votre accès aux lignes.

Cliquez sur **Enregistrer**. Les règles prennent effet au prochain **Charger**, ou lorsque vous cliquez sur **Appliquer les modifications**. Si vous avez modifié une étape d'allocation à la main, votre modification est conservée, et non écrasée, et l'enregistrement la nomme. Vous ne pouvez pas enregistrer pendant qu'un chargement s'exécute.

## Dossier du conseil

Un dossier du conseil écrit vos résultats selon une planification dans un dossier d'un compte de documents, prêt à être envoyé. Ouvrez **Actions > Dossier du conseil...**, choisissez un **Compte de documents** et un **Dossier**, comme `/board-packs`, et cliquez sur **Enregistrer**. Chaque exécution écrit :

- Un classeur Excel, `Board pack.xlsx`, avec le compte de résultat par entité, une passerelle de marge, ainsi que les meilleurs et les moins bons clients.
- Un PDF du tableau de bord du compte de résultat.

Si le projet n'a pas encore de tableau de bord, le classeur est écrit seul et l'exécution vous en indique la raison. Cliquez sur **Exécuter maintenant** pour produire un dossier immédiatement ; ses fichiers apparaissent dans le dossier à la fin. La carte affiche la dernière exécution et son résultat, ainsi que la prochaine exécution. Le dossier s'exécute avec l'actualisation nocturne dès que celle-ci est configurée. Seule une personne qui peut modifier le projet le configure.

## Points de restauration

Un point de restauration est créé avant chaque chargement, et avant chaque modification des correspondances ou des sources. Il contient les tables du modèle, les dimensions et les paramètres à partir desquels le chargement suivant construit : vos sources, vos fichiers et vos règles d'allocation. Les points récents sont conservés ; les plus anciens disparaissent, et les modifications ne font jamais disparaître les points pris avant les chargements.

Pour revenir en arrière, ouvrez **Actions > Restaurer...**, choisissez un point et cliquez sur **Restaurer**. **Restaurer** est proposé dès qu'un point existe. La restauration remet les tables, les dimensions et ces paramètres comme ils étaient, et le chargement suivant construit à partir d'eux. Une table sans copie enregistrée, ou un moteur qui ne peut pas conserver d'historique, est nommé dans un avertissement et le reste est restauré. Un point de restauration qui a disparu est refusé, et vous ne pouvez pas restaurer pendant qu'un chargement s'exécute.

## Cloner un projet

**Actions > Cloner...** copie le projet sous le nom que vous donnez. La copie conserve le modèle de projet, vos modifications du modèle, ainsi que vos métriques et vos chemins d'analyse, et charge les données d'exemple. Ses sources ne sont pas connectées : connectez-les donc dans la copie avant de charger. Vous pouvez continuer à travailler pendant la création de la copie, et **Ouvrir le projet** vous y conduit lorsqu'elle est prête.

## Enregistrer comme mon modèle

Enregistrez la configuration d'un projet pour la réutiliser pour le client ou l'entité suivant. Ouvrez **Actions > Enregistrer comme mon modèle...**, choisissez le compte de documents et nommez le fichier. Un nom se terminant par `.zip` est ajouté si vous l'omettez. Enregistrer par-dessus un fichier existant est refusé ; choisissez donc un autre nom.

Le fichier contient la structure du projet, vos modifications du modèle, les métriques et les chemins d'analyse, les noms métier des entités et des comptes, ainsi que les lignes des tables de configuration du modèle de projet, telles que la table de correspondance des activités de [Coût de service](/fr/guides/projects/cost-to-serve/) ou les fourchettes de politique de [Prix de transfert opérationnels](/fr/guides/projects/operational-transfer-pricing/). Il exclut les connexions, les fichiers, la planification nocturne, les exécutions, les points de restauration, le dossier du conseil et la liste des personnes ayant accès.

Pour l'utiliser, créez un projet, choisissez **À partir d'un fichier de modèle...** sous **Partir de**, puis indiquez le compte de documents et le chemin. Le nouveau projet est privé et vous appartient, avec chaque source en attente de connexion. Une version ultérieure du modèle de projet fusionne ses modifications autour des étapes que vous avez modifiées. S'il n'y a pas de fichier au chemin indiqué, rien n'est créé et vous en êtes informé. Toute personne qui peut lire le compte de documents peut installer à partir du fichier. Pour l'utiliser dans un autre espace de travail, téléchargez le fichier et téléversez-le là-bas.

## Résoudre les questions ouvertes avec Ask

Après un chargement, un projet peut encore attendre qu'on lui indique trois choses : les comptes que le plan laisse sans type, les codes que plusieurs sources utilisent, et les colonnes de vos fichiers qui n'ont rien trouvé à quoi correspondre. Demandez à l'assistant de les résoudre : depuis un assistant IA via MCP, utilisez le prompt **Resolve Data Foundation residue**. Il lit ce qui est en attente et propose une réponse pour chaque élément, avec une raison.

L'assistant n'écrit rien. Vous appliquez ses réponses là où vous auriez répondu vous-même : les comptes et les codes sous **Codes en attente de votre réponse**, et les colonnes de fichier dans la correspondance du fichier. Il ne propose jamais d'entité.

## Transmettre le projet

La liste de contrôle **Configuration** comporte quatre éléments de clôture après **Vérifier vos hiérarchies** :

- **Configurer l'actualisation nocturne** est fait dès que **Actualiser chaque nuit** est activé.
- **Partager avec votre équipe** est fait dès que quelqu'un d'autre que la personne qui a configuré le projet en est membre.
- **Télécharger le dossier de preuves** est fait lorsque vous téléchargez le dossier après le dernier chargement réussi.
- **Transmettre le projet à son propriétaire** est fait dès qu'il existe un Architecte autre que la personne qui l'a configuré et que les totaux concordent. Tant que ce n'est pas fait, la liste de contrôle indique quoi faire : faire du propriétaire du client un Architecte de ce projet, puis vous retirer de ses membres.

La liste de contrôle indique qui a configuré le projet (**Configuré par**).

## Construire sur le modèle avec un modèle de projet

Un modèle de projet construit ses rapports et ses modèles sur le Common Finance Model, de sorte qu'ils fonctionnent de la même façon quels que soient les ERP qui l'alimentent. Lorsque vous démarrez un projet à partir d'un modèle de projet, tel que **Rentabilité de l'entreprise**, il crée :

- Les [tables du Common Finance Model](#tables-du-common-finance-model), vides ou remplies de données d'exemple.
- Les dimensions **Entité**, **Compte**, **Département**, **Client**, **Produit**, **Segment 1** et **Segment 2** construites à partir de ces tables. Voir [Hiérarchies](#hiérarchies).
- Le workflow **Charger** et les workflows qu'il exécute pour lire votre ERP et vos fichiers, les harmoniser, contrôler la préparation et construire les modèles du modèle de projet.
- Les rapports et modèles propres au modèle de projet. **Rentabilité de l'entreprise** ajoute une table de compte de résultat avec le chiffre d'affaires, le CMV, la marge brute, les charges d'exploitation directes et indirectes, la contribution et la marge d'exploitation, ainsi que des passerelles de marge d'une année sur l'autre et par rapport au budget.
- Des métriques et un chemin d'analyse pour poser des questions sur les résultats.

Trois modèles de projet sont proposés sous **Partir de**, chacun construit sur le même modèle :

| Modèle de projet | Ajoute |
|---|---|
| **Rentabilité de l'entreprise** | Le compte de résultat et les passerelles de marge. |
| **Coût de service** | Le coût de service de chaque client, et la marge après celui-ci. Voir [Coût de service](/fr/guides/projects/cost-to-serve/). |
| **Prix de transfert opérationnels** | Le niveau de profit de chaque entité par rapport à votre fourchette de politique, et la régularisation. Voir [Prix de transfert opérationnels](/fr/guides/projects/operational-transfer-pricing/). |

**À partir d'un fichier de modèle...** démarre à partir d'un projet que vous avez enregistré. Voir [Enregistrer comme mon modèle](#enregistrer-comme-mon-modèle).

Pour explorer avant de connecter votre propre ERP, cochez **Commencer avec des données d'exemple** lorsque vous créez le projet. Le projet exécute immédiatement un premier chargement, de sorte que l'onglet **Foundation** affiche un exemple complet, y compris une entité en euros convertie en dollars américains. Lorsque vous connectez votre propre ERP ou ajoutez vos propres fichiers, les lignes d'exemple sont effacées et vos données prennent leur place.

## L'onglet Foundation

L'onglet **Foundation** est l'endroit où vous connectez, chargez et contrôlez vos données. Il comporte les sections suivantes, de haut en bas :

| Section | Ce qu'elle affiche |
|---|---|
| **Dernier chargement** | Si le dernier chargement a réussi, échoué ou est encore en cours, avec les boutons **Charger**, **Appliquer les modifications**, **Actualiser** et **Actualiser chaque nuit**. |
| **Que faire ensuite** | Ce qui nécessite votre attention, le plus important en premier, avec pour chaque élément un bouton **Examiner** ou **Choisir à partir de quand chaque source compte**. |
| **Sources** | Chaque source dans l'ordre, avec **Avancé**, **Supprimer cette source**, **Groupe** et **Renommer les catégories supplémentaires**. |
| **Configuration** | La liste de contrôle de configuration : **Connecter vos données**, **Charger vos données**, **Vérifier la concordance des totaux**, **Vérifier vos hiérarchies**, **Configurer l'actualisation nocturne**, **Partager avec votre équipe**, **Télécharger le dossier de preuves** et **Transmettre le projet à son propriétaire**. L'élément en cours est en gras. |
| **Noms métier** | Les noms que votre entreprise utilise pour les catégories, les postes de compte de résultat, les métriques et les colonnes. Voir [Noms métier](#noms-métier). |
| **Fichiers** | Chaque fichier ajouté, son jeu de données, comme **Grand livre** ou **Taux de change**, et si sa correspondance est **✓ Confirmé** ou **○ En attente de confirmation**. |
| **Données chargées** | Pour chaque entité, la première et la dernière période chargées et le nombre de périodes prêtes. |
| **Périodes** | Les périodes fiscales de chaque entité et si chacune est **✓ Clos** ou **○ Ouvert**. |
| **Préparation** | La grille de préparation : une ligne par entité, période et contrôle, avec son état et **Que faire**. |
| Connexion | Connecter votre ERP, choisir les entités et le nombre de mois d'historique à charger, ou ajouter une autre source. |
| **Fichiers** (ajout) | Ajouter un fichier CSV, TSV, TXT, Excel ou Parquet et confirmer la correspondance de ses colonnes. |
| **Charger** | Lancer un chargement. **Appliquer les modifications** en exécute un sans relire les ERP. |

Pendant qu'un chargement s'exécute, l'onglet s'actualise de lui-même.

La liste de contrôle de configuration suit votre progression :

- **Connecter vos données** et **Charger vos données** se cochent d'elles-mêmes dès qu'une source est rattachée et qu'un chargement réussit.
- **Vérifier la concordance des totaux** se coche de lui-même lorsque les contrôles de concordance réussissent.
- **Vérifier vos hiérarchies** : cliquez sur **Ouvrir les dimensions** pour examiner les hiérarchies Entité, Compte et Département, puis cochez **Je les ai examinés**. Celui-ci, vous le confirmez vous-même.
- **Configurer l'actualisation nocturne**, **Partager avec votre équipe**, **Télécharger le dossier de preuves** et **Transmettre le projet à son propriétaire** closent la liste. Voir [Transmettre le projet](#transmettre-le-projet) et [Gérer l'accès au projet](/fr/guides/projects/managing-projects/#gestion-de-laccès-aux-projets).

Le menu **Actions** contient **Allocations...**, **Dossier du conseil...**, **Cloner...**, **Restaurer...** et **Enregistrer comme mon modèle...**. Voir [Règles d'allocation](#règles-dallocation), [Dossier du conseil](#dossier-du-conseil), [Cloner un projet](#cloner-un-projet), [Points de restauration](#points-de-restauration) et [Enregistrer comme mon modèle](#enregistrer-comme-mon-modèle).

## Tables du Common Finance Model

Data Foundation harmonise chaque source, ERP ou fichier, dans les mêmes quinze tables, de sorte que les rapports, les métriques et les modèles construits dessus fonctionnent de la même façon quelle que soit la source. Chaque ligne enregistre aussi son système source et la date de sa lecture. La colonne **Jeu de données** est le nom que vous choisissez lorsque vous ajoutez un fichier.

| Jeu de données | Table | Contenu |
|---|---|---|
| Entités | `cfm_entity` | Entités juridiques avec parent, devise locale et devise du groupe, et pays. |
| Correspondance des entités | `cfm_entity_map` | Codes d'entité source et entité à laquelle chacun appartient. Voir [Correspondance des entités](#correspondance-des-entités). |
| Taux de change | `cfm_fx_rate` | Taux mensuels moyens, de clôture et historiques par paire de devises. Voir [Taux de change](#taux-de-change). |
| Calendrier fiscal | `cfm_fiscal_calendar` | Une ligne par période fiscale d'entité, avec les dates de début et de fin et l'indication si elle est clôturée. |
| Plan comptable | `cfm_account` | Comptes avec parent, type (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), état, solde normal et type de taux. |
| Départements | `cfm_department` | Départements et centres de coûts avec parent et centre de profit. |
| Produits | `cfm_product` | Référentiel de produits avec parent, famille, groupe, unité de mesure et coût standard. |
| Clients | `cfm_customer` | Référentiel de clients avec parent, groupe, région et pays. Les noms des clients ne sont pas masqués. |
| Valeurs de segment | `cfm_segment` | Valeurs de segment avec nom et parent. Voir [Hiérarchies](#hiérarchies). |
| Grand livre | `cfm_gl_journal` | Lignes de journal en devise de transaction, locale et de reporting. |
| Balance de vérification | `cfm_trial_balance` | Débits, crédits et net de la période par entité, compte et département, en devise locale et de reporting. |
| Lignes de vente | `cfm_sales_line` | Lignes de vente facturées avec quantité, montants bruts, remise, net et CMV. |
| Soldes de stock | `cfm_inventory_balance` | Stock de fin de période par produit et entrepôt. |
| Budget | `cfm_budget` | Budget et prévision par scénario, version, compte et département. |
| Inducteurs d'allocation | `cfm_stat_driver` | Inducteurs statistiques tels que l'effectif, la surface en pieds carrés ou les unités. |

Les périodes s'écrivent `YYYY-MM`, et les transactions sont placées selon la période de comptabilisation. Le budget est facultatif : un ERP sans budget charge quand même tout le reste.

Un fichier de balance de vérification peut porter des colonnes de débit et de crédit, une colonne de net, ou les deux. Avec seulement le débit et le crédit, le net est le débit moins le crédit, et un côté vide compte pour zéro. Avec seulement un net, un net positif devient le débit et un net négatif devient le crédit, en montant positif. Une colonne de département est facultative.

## Dépannage

| Symptôme | Que faire |
|---|---|
| **Tester la connexion** indique que l'ERP a refusé les identifiants | Vérifiez les identifiants de la connexion et que l'utilisateur d'intégration peut se connecter à l'ERP. |
| **Tester la connexion** affiche **Autorisation manquante** pour un jeu de données | Demandez à votre administrateur ERP d'ajouter les autorisations nommées. Le [guide de connexion](/fr/guides/connections/) de votre ERP liste ce dont la connexion a besoin. |
| Un message d'erreur de l'ERP est plus court que celui de l'ERP lui-même | PlaidCloud retire les identifiants, les jetons et les clés des erreurs des fournisseurs avant de les afficher ; certains détails sont donc omis. Exécutez **Tester la connexion** pour voir quel jeu de données est concerné. |
| **Données chargées** est un problème pour une période | Une lecture de l'ERP pour cette période a échoué. Exécutez de nouveau **Charger** ; les périodes déjà chargées sont ignorées. |
| **Comptes absents du plan comptable** est un problème | Ajoutez les comptes manquants au plan comptable dans l'ERP ou dans votre fichier, et exécutez de nouveau **Charger**. |
| **Conversion de devises** est un problème | La devise d'une entité n'a pas de taux vers la devise de reporting pour cette période, ou aucune devise de reporting unique n'a été trouvée. Ajoutez les taux dans un fichier **Taux de change**, vérifiez que la connexion peut lire les taux de change de l'ERP, ou définissez la variable de projet `reporting_currency`. Puis exécutez de nouveau **Charger**. |
| **Conversion de devises** est à examiner | Des lignes de bilan, de stock ou de budget n'ont pas de taux de clôture, historique ou prévisionnel pour la période. Le compte de résultat n'est pas affecté. Ajoutez les taux, y compris les taux prévisionnels pour les mois budgétés, et exécutez de nouveau **Charger**. |
| **Codes en attente de votre réponse** est à examiner | Cliquez sur **Examiner**, répondez pour chaque code et cliquez sur **Appliquer les modifications**. |
| **Quelle source couvre quels mois** est à examiner | Cliquez sur **Choisir à partir de quand chaque source compte**, choisissez la source et cliquez sur **Appliquer les modifications**. |
| **Soldes intersociétés** est rouge ou orange | Vérifiez les paires dans **Paires intersociétés**. Comptabilisez le côté manquant, ajoutez le partenaire commercial aux lignes, ou ajoutez le taux manquant. |
| **Les vues du groupe sont désactivées** | Demandez à un Architecte de cocher **Tous les membres du projet peuvent voir les résultats du groupe** sous **Groupe**. |
| **Entités non mappées** est un problème | Ajoutez l'entité au référentiel d'entités, ou associez son code à une entité existante dans le fichier **Correspondance des entités**, et exécutez de nouveau **Charger**. |
