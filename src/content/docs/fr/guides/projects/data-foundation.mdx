**Data Foundation** est le socle de données financières de vos projets PlaidCloud. Son **Common Finance Model** rassemble les données de plusieurs systèmes ERP, et de plusieurs instances de chacun, dans un seul modèle : un seul plan comptable, un seul ensemble d'entités et une seule devise de reporting. Les rapports, métriques et assistants IA construits sur le modèle lisent tous les mêmes chiffres, quel que soit l'ERP d'où ils proviennent.

Votre ERP se connecte via sa connexion PlaidCloud : le grand livre, la balance générale, les données de base et les budgets arrivent donc directement de la source, sans rien à exporter. Les fichiers ajoutent les données qu'un système ne contient pas, comme les taux de change, les inducteurs d'allocation ou un budget tenu en dehors de l'ERP, et peuvent remplacer les lignes de l'ERP qu'ils couvrent. **Charger** conforme chaque source au modèle, la convertit dans la devise de reporting et vérifie sa concordance, le tout depuis l'onglet **Foundation** du projet. Lorsque des sources utilisent le même code pour des choses différentes, vous indiquez s'ils désignent la même chose, et une consolidation de gestion construit le compte de résultat du groupe en éliminant l'intragroupe. Les modèles, comme **Rentabilité de l'entreprise**, construisent leurs rapports et leurs modèles de calcul par-dessus.

## Connecter votre ERP

Votre ERP se connecte à Data Foundation via sa connexion PlaidCloud. Data Foundation y lit directement le grand livre, la balance générale, les données de base, les taux de change et les budgets, et se contente toujours de lire. Vous pouvez choisir une connexion existante ou en créer une dans l'onglet. Chaque système dispose d'une page destinée à l'administrateur qui accorde l'accès, répertoriée dans [Quels systèmes peuvent alimenter le modèle](/fr/guides/projects/data-foundation-getting-started/#les-systèmes-qui-peuvent-alimenter-le-modèle), et la [matrice de couverture de Data Foundation](/fr/reference/data-foundation-coverage-matrix/) indique quels jeux de données chaque système fournit directement.

<Steps>

1. Dans Analyze, ouvrez **Projets** et cliquez sur **Nouveau projet**. Saisissez un nom et, sous **Partir de**, choisissez un modèle, comme **Rentabilité de l'entreprise (modèle)**, plutôt que **Projet vierge**. Cliquez sur **Créer**.

   Le projet s'ouvre sur son onglet **Foundation**. Il vous est privé, et vous en êtes le seul Architecte, jusqu'à ce que vous le partagiez.

2. Dans l'onglet **Foundation**, ouvrez **Sources** et, dans **Connect a system**, choisissez votre type de système à partir de sa vignette. Choisissez ensuite une connexion existante pour ce système, ou choisissez **Créer une nouvelle connexion**. Chaque connexion existante répertorie les workflows qui l'utilisent déjà, ou indique **Pas encore utilisé par un workflow**, et une connexion qui est déjà une source est signalée par **already a source** et ne peut pas être choisie de nouveau.

3. Pour une nouvelle connexion, saisissez un **Nom de la connexion**, choisissez l'**Environnement** et renseignez les identifiants que demande votre connexion ERP.

   Vous n'avez pas encore les identifiants ? Le formulaire affiche une demande d'accès prête à l'emploi pour votre administrateur ERP. Cliquez sur **Copier la demande** ou **Envoyer la demande par e-mail**, envoyez-la, puis saisissez les valeurs qu'il vous renvoie.

4. Cliquez sur **Tester la connexion**. PlaidCloud se connecte et tente de lire chaque jeu de données, puis indique pour chacun **Lisible**, **Autorisation manquante** ou **Erreur**. Lorsqu'il manque quelque chose, il nomme les autorisations à demander à votre administrateur ERP.

5. Définissez **Mois d'historique** : le nombre de mois à charger dans le passé, de 1 à 120. La valeur par défaut est 24.

6. Pour une connexion existante, cochez les entités à charger, ou laissez-les toutes décochées pour charger toutes les entités. Les entités inactives et d'élimination restent masquées jusqu'à ce que vous choisissiez de les afficher. Cliquez ensuite sur **Connecter**.

7. Pour une nouvelle connexion, cliquez sur **Connecter** pour la créer. Cochez ensuite les entités à charger et cliquez de nouveau sur **Connecter** pour les enregistrer. Tant que vous ne l'avez pas fait, toutes les entités sont chargées.

8. Pour ajouter un autre système ERP ou une autre instance, ouvrez **Connect another system** et répétez ces étapes. Une connexion ajoute toujours une source et laisse les sources existantes telles quelles : plusieurs systèmes ERP et instances peuvent ainsi alimenter le même modèle consolidé.

</Steps>

Une fois la connexion établie, la carte indique la connexion, l'environnement, les entités et les mois d'historique que charge le projet.

Chaque chargement ne lit que ce qui a changé : les périodes ouvertes et la dernière période clôturée sont relues, et les périodes clôturées déjà chargées sont conservées. Augmenter **Mois d'historique** ne lit que les mois ajoutés. Un taux de change, une correspondance des entités ou une devise de reporting modifiés font relire les mois concernés.

## Sources

Chaque système ERP et chaque instance à partir desquels le projet charge des données constituent une source. La liste **Load order** de la page **Sources** de l'onglet **Foundation** affiche une ligne pour chacune, dans l'ordre, avec son nom et son système, ses **Sociétés**, **Dernier chargement**, **Lignes** et **Statut**. **Sociétés** indique **Tous** ou le nombre de sociétés sélectionnées. Une source qui n'a pas encore été chargée indique **Not loaded yet**. Les fichiers que vous confirmez sont aussi des sources.

Cliquez sur **Modifier** sur une source pour changer la façon dont elle est utilisée :

| Paramètre | Rôle |
|---|---|
| **Nom** | Le libellé qu'utilisent pour la source les rapports, les questions de correspondance et les messages. |
| **Place dans l'ordre** | Le rang de la source. Lorsque deux sources couvrent le même mois de la même société, celle qui est placée le plus haut dans l'ordre l'emporte. |
| **Livres de reporting, séparés par des virgules** | Les livres comptables à lire, pour un système qui en tient plusieurs. **Tous les livres de reporting** lit tous les livres. |
| **Sociétés** | Pour une source système, celles de ses sociétés (filiales) que charge la source. La liste est lue dans le système lorsque vous ouvrez le panneau pour la première fois et affiche les sociétés que charge actuellement la source. Cochez celles à charger, ou n'en cochez aucune pour toutes les charger. Si le système ne répertorie pas ses sociétés, saisissez leurs noms séparés par des virgules. |
| **Société**, **De (2026-01)** et **À (2026-12)** | Les mois que cette source fournit pour chaque société. Laissez un mois vide pour ne fixer aucune limite. Écrivez les mois sous la forme année et mois, par exemple `2026-03`. |

Cliquez sur **Enregistrer** pour conserver vos modifications. Ajouter des sociétés, ou n'en cocher aucune, enregistre immédiatement. Exclure une société vous demande d'abord de confirmer **Load fewer companies?**, car l'enregistrement efface immédiatement tout ce qui a été chargé depuis cette source, et le prochain **Charger** récupère de nouveau les sociétés cochées. Si la connexion de la source lit désormais un compte différent de celui pour lequel la source a été configurée, l'enregistrement est refusé avec un message qui l'indique : une modification ne peut ainsi jamais remplacer une autre source. Reconnectez plutôt ce compte comme une source à part entière. Pour retirer une source, cliquez sur **Remove this source** et confirmez par **Supprimer**. Tout ce qui a été chargé depuis cette source est supprimé, et vous pourrez la reconnecter plus tard.

Modifier les sources ne relit pas votre ERP. La barre au-dessus de chaque page indique **You have changed your sources. Press Apply changes to use them.** jusqu'à ce que vous cliquiez sur **Apply changes**, qui exécute un chargement à partir des données déjà récupérées : il conforme de nouveau les sources avec votre nouvel ordre, vos correspondances, vos noms et vos fichiers, et reconstruit le modèle. Cliquez sur **Charger** lorsque vous voulez aussi des données fraîches issues des ERP.

## Ajouter des fichiers pour les données hors de votre ERP

Les fichiers complètent votre connexion ERP avec des données qu'un système ne contient pas, comme les taux de change, les inducteurs d'allocation, une [correspondance des entités](#correspondance-des-entités) ou un budget tenu en dehors de l'ERP. Chaque fichier appartient à l'un des jeux de données répertoriés sous [Tables du Common Finance Model](#tables-du-common-finance-model).

<Steps>

1. Sous **Fichiers**, choisissez le **Compte de documents** dans lequel stocker le fichier.

2. Déposez un fichier CSV ou Excel sur **Déposez un fichier CSV ou Excel ici**, ou cliquez sur **Choisir un fichier**. Le fichier est téléversé dans le dossier `/foundation/` du compte de documents.

   Pour un fichier qui se trouve déjà dans le compte de documents, saisissez son **Chemin du fichier**, par exemple `/foundation/budget.csv`, et cliquez sur **Ajouter un fichier**.

   Pour lire un nouveau fichier chaque mois, ajoutez tous les fichiers d'un dossier dont le nom correspond : saisissez le dossier et ce que les **File names that** contiennent, ce par quoi ils commencent ou se terminent, ce à quoi ils correspondent exactement ou selon un motif, puis cliquez sur **Ajouter des fichiers**. Les fichiers des sous-dossiers ne sont pas lus.

3. PlaidCloud lit le fichier et propose une correspondance :

   - **Délimiteur, séparateur décimal et dates détectés.** Le délimiteur (virgule, point-virgule, tabulation ou barre verticale), le séparateur décimal et le format de date sont détectés pour vous.
   - **Jeu de données** : la table du Common Finance Model à laquelle appartient le fichier, déterminée à partir du nom du fichier et des en-têtes de colonnes. Lorsque la correspondance n'est pas évidente, choisissez-la dans la liste.
   - **Séparateur décimal** : **Point (1,234.56)** ou **Virgule (1.234,56)**.
   - **Format de date** : affiché lorsque le fichier contient des dates. Modifiez-le si le format détecté est incorrect : `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Une grille **Colonne du fichier**, **Type**, **Exemples** et **Destination**. Modifiez **Destination** pour envoyer une colonne vers un autre champ, ou vers **Ne pas charger**.

4. Répondez aux questions que soulève le fichier, comme **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** ou **Are revenues shown as negative numbers?** Chacune n'est posée que lorsque le fichier ne donne pas déjà la réponse.

5. Vérifiez la destination de chaque colonne, puis cliquez sur **Confirmer la correspondance**. Pendant le traitement, la note sous le bouton explique ce qui est attendu. Dans un projet qui contient encore les données d'exemple, le premier fichier que vous confirmez supprime aussi l'exemple, ce qui peut prendre quelques minutes.

</Steps>

Ces options apparaissent sur un fichier lorsqu'elles s'appliquent :

| Option | Utilisation |
|---|---|
| **Which source do these rows apply to?** | Limiter un fichier de correspondance de codes à une seule source. **Every source** l'applique à toutes. |
| **Where does this file come from?** | Indiquer si le fichier contient **This project's own codes** ou provient d'**Another system**, que vous nommez, par exemple `SAP Germany export`. Un fichier provenant d'un autre système est contrôlé pour détecter les codes partagés, comme une source ERP. |
| **Split … into … parts at each …** (sous **Avancé**) | Scinder une colonne qui contient plusieurs valeurs, comme `100-200-300`, et envoyer chaque partie vers son propre champ. |
| **Which currency do you report in?** | Définir la devise de reporting lorsque le projet n'en a pas encore. Écrivez-la en trois lettres, par exemple `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Charger les résultats de votre système de consolidation afin de pouvoir [rapprocher](#rapprocher-avec-votre-système-de-consolidation) le compte de résultat du groupe. |

Pour retirer un fichier du projet, cliquez sur **Supprimer** à côté de celui-ci sous **Fichiers**, ou sur **Remove this file** dans sa correspondance, puis confirmez. Ses chiffres disparaissent de vos rapports la prochaine fois que vous cliquez sur **Apply changes**.

Lorsque PlaidCloud ne peut pas déterminer seul le jeu de données, le séparateur décimal ou l'ordre des dates, par exemple pour un fichier dont les dates peuvent se lire jour/mois ou mois/jour, il vous demande de choisir avant de confirmer. Ajouter un second fichier pour le même jeu de données remplace le premier. Si les colonnes d'un fichier ultérieur ne correspondent pas au jeu de données, le chargement nomme le fichier et les colonnes et vous invite à corriger le fichier ou ses noms de colonnes, ou à définir le **Schema Mismatch** de l'étape sur `union`.

Les fichiers acceptés sont les fichiers texte CSV, TSV et TXT, les fichiers Excel `.xlsx` (lus à partir de la première feuille) et les fichiers Parquet.

<Aside type="note">
Un fichier manquant ou vide n'interrompt jamais un chargement. Lorsque vous l'ajoutez, il est indiqué qu'il n'y a encore rien à mettre en correspondance, et un chargement se termine par un avertissement qui nomme le chemin, en laissant ce jeu de données vide. Ajoutez de nouveau le fichier une fois qu'il existe.
</Aside>

## Charger vos données

Cliquez sur **Charger** dans **Statut**. Le chargement lit votre ERP connecté et vos fichiers confirmés, les conforme au Common Finance Model, les convertit dans la devise de reporting, exécute les contrôles de préparation et reconstruit les modèles de calcul du modèle de projet.

- Un seul chargement s'exécute à la fois pour un projet. Un second **Charger** ou **Apply changes** indique qu'un chargement est déjà en cours, et vous ne pouvez pas modifier les sources pendant qu'il s'exécute.
- Si d'autres workflows utilisent la même connexion ERP, le premier chargement les répertorie et vous demande de confirmer, car un chargement lit l'ERP et peut ralentir ces workflows. Cliquez sur **Charger quand même** pour continuer.
- Après une mise à niveau de PlaidCloud, le **Charger** d'un Architecte met aussi à jour les workflows générés du projet, en créant les tables de travail dont ils ont besoin. D'ici là, la page de statut affiche un élément orange, « The workflows were generated by an earlier release. An Architect's Load updates them. », et le **Charger** d'un Gestionnaire avertit que seul un Architecte peut les mettre à jour.
- L'application d'une mise à jour conserve vos propres modifications des étapes générées. Si vous avez modifié une étape et que la mise à jour l'a modifiée aussi, votre modification est conservée et la page de statut signale le conflit par nom d'étape. Une étape que vous avez modifiée et que la mise à jour ne génère plus est conservée mais désactivée ; supprimez-la, ou réactivez-la si vous en avez encore besoin. Une étape que la mise à jour remplace est nommée, et l'ancienne reste dans ses versions d'étape.
- Si une mise à jour s'est arrêtée en cours de route, ou est encore en cours, la page de statut l'indique, et ses étapes peuvent s'exécuter dans le désordre jusqu'à ce qu'elle se termine. Appuyez de nouveau sur **Charger** en tant qu'Architecte pour la terminer. Si elle s'arrête de nouveau, contactez le support.
- Un chargement en échec s'affiche en rouge et ne se cache jamais derrière des résultats antérieurs. Si la consolidation échoue, le statut nomme l'étape à laquelle elle s'est arrêtée au lieu d'afficher d'anciens résultats de groupe. Les lignes issues d'un chargement antérieur affichent **Issu d'un chargement précédent. Rechargez.** jusqu'à ce qu'un chargement réussisse.
- Si la lecture d'une entité et d'une période échoue, le reste est quand même chargé. Exécutez de nouveau **Charger** pour ne récupérer que ce qui a échoué.

### Lignes retenues

Lorsque des sources se chevauchent, un chargement conserve un seul exemplaire de chaque chiffre et retient les autres au lieu de les compter deux fois. Les lignes retenues sont enregistrées avec leur source, leur entité et le motif, et le chargement se termine par un avertissement qui indique les nombres, par exemple `120 rows of NetSuite EU also provided by a source ranked ahead`. Les motifs sont les suivants :

| Motif | Signification |
|---|---|
| Dans un autre livre comptable | La ligne appartient à un livre de reporting que la source n'est pas configurée pour lire. |
| En dehors des périodes fournies par la source | La ligne se situe en dehors des mois **De** et **À** définis pour la société. |
| Également fournie par une source mieux classée | Une source placée plus haut dans l'ordre couvre la même société et le même mois. |
| Également dans un fichier antérieur de la source | Un fichier antérieur de la même source couvre déjà le mois. |
| Remplacée par un fichier | Un fichier remplace les lignes de l'ERP pour cette entité et ce mois. |
| Porte un code qu'une autre source utilise aussi | Le code attend votre réponse. Consultez [Mettre en correspondance les codes entre les sources](#mettre-en-correspondance-les-codes-entre-les-sources). |
| Porte un code mis en correspondance avec deux codes | La correspondance de codes donne deux réponses pour ce code. |

Les comptes statistiques sont transférés vers les inducteurs d'allocation au lieu du grand livre, et apparaissent comme transférés, et non comme un problème.

### Données ERP et fichiers ensemble

Un fichier ne remplace que ce qu'il couvre, et les autres lignes de votre ERP sont conservées.

- Les **fichiers de données de base** (comptes, départements, clients, produits et valeurs de segment) remplacent les lignes de l'ERP portant le même code.
- Les **fichiers de transactions** remplacent les lignes de l'ERP pour la même entité et le même mois. Les fichiers de grand livre et de balance générale correspondent aussi par livre, les fichiers de budget par scénario, et les fichiers d'inducteurs statistiques par scénario et par inducteur.

Si un fichier cesse ensuite de couvrir un mois, les données de l'ERP pour ce mois reviennent lors du chargement suivant.

## Correspondance des entités

Chaque source nomme ses entités avec ses propres codes. La **Correspondance des entités** fait correspondre ces codes aux entités de votre référentiel d'entités, afin que les lignes de chaque source aboutissent sur la même entité.

Pour en utiliser une, ajoutez un fichier CSV ou Excel et choisissez le jeu de données **Correspondance des entités** :

| Colonne | Contenu |
|---|---|
| `source_entity` | Le code tel que la source le porte, comme un code société. |
| `entity` | L'entité à laquelle il appartient, telle que la nomme le référentiel d'entités. |

- Un code absent de la correspondance est utilisé tel quel.
- Plusieurs codes peuvent correspondre à une même entité. Leurs lignes sont combinées, et un mois est considéré comme clôturé dès qu'il est clôturé pour tous ces codes.
- Les codes de la correspondance s'appliquent à toutes les sources : les codes d'entité de chaque source doivent donc être uniques entre les sources.
- Une ligne d'un fichier **Entités** remplace l'entité de l'ERP portant le même code d'entité.

Le contrôle **Entités non mappées** signale toute ligne dont l'entité ne figure pas dans le référentiel d'entités et n'est pas mise en correspondance avec l'une d'elles par la correspondance des entités. Tant qu'aucun référentiel d'entités n'est chargé, il affiche **– Sans objet**.

## Mettre en correspondance les codes entre les sources

Deux sources peuvent utiliser le même code pour des choses différentes, ou des codes différents pour la même chose. Lorsqu'un code apparaît dans plusieurs sources, Data Foundation retient ses lignes jusqu'à ce que vous indiquiez s'il a le même sens partout, afin que chaque montant ne soit compté qu'une fois. Le contrôle **Codes en attente de votre réponse** les répertorie, les 10 premiers puis « and K more », et **Answer codes ›** dans la liste **What to do next** de **Statut** les ouvre.

**Answer codes ›** ouvre **Réponses requises**, qui répertorie les **Codes en attente de votre réponse**. Les codes y sont regroupés selon leur nature : **Types de compte**, **Sociétés**, **Comptes**, **Départements**, **Centres de profit**, **Clients**, **Produits** et chaque catégorie supplémentaire. Pour chaque code, l'écran indique comment chaque source l'appelle et propose une suggestion :

- **Looks like the same thing** lorsque les sources donnent le même nom au code.
- **Looks like different things** lorsque les noms diffèrent.
- **We can't tell. Please answer.** lorsqu'il n'y a aucun indice.

Répondez code par code avec **Yes, the same** ou **No, different**, ou répondez pour tout un groupe à la fois avec **Accept all** (accepter toutes les suggestions), **All the same** ou **All different**. Pour les comptes, vous pouvez aussi répondre pour tout un groupe parent du plan comptable à la fois. Lorsqu'une source ne porte aucun type de compte, choisissez **Use this type** pour un groupe de comptes : **Chiffre d'affaires**, **Coût des ventes**, **Charges d'exploitation**, **Produits et charges hors exploitation**, **Actifs**, **Passifs** ou **Capitaux propres**.

Les correspondances sont conservées pour chaque source et chaque dimension : une réponse donnée pour les départements d'une source ne modifie donc jamais les comptes d'une autre source. Les réponses sont enregistrées au fur et à mesure, avec **Saved. Press Apply changes to use your answers.** Cliquez sur **Apply changes** pour les utiliser.

Vous pouvez aussi fournir les correspondances dans un fichier. Ajoutez un fichier avec le jeu de données **Code map**, et choisissez **Which source do these rows apply to?** pour le limiter à une seule source.

## Choisir quelle source compte à partir de quand

Lorsque deux sources fournissent les mêmes mois, le contrôle **Quelle source couvre quels mois** vous demande de choisir. Cliquez sur **Choose sources ›** dans la liste **What to do next** de **Statut** pour ouvrir **Couverture des sources**, qui répertorie chaque chevauchement par société. Choisissez la source qui compte, saisissez dans **That month is** le mois à partir duquel elle compte, par exemple `2026-04`, cliquez sur **Save choice**, puis sur **Apply changes** dans la barre au-dessus de la page. L'autre source conserve les mois antérieurs.

La même boîte de dialogue avertit lorsque deux sources donnent des taux de change différents pour une devise ; ce sont les taux de la source placée le plus haut dans l'ordre qui sont utilisés.

## Conversion de devises

Chaque chargement convertit les montants du grand livre, de la balance générale, des ventes, des stocks et des budgets de leur devise locale vers une seule devise de reporting. Les rapports et les modèles de calcul lisent les montants convertis : les entités dans des devises différentes, quel que soit leur système, se totalisent donc correctement.

### La devise de reporting

Pour choisir la devise de reporting, définissez la variable de projet `reporting_currency` sur un code de devise comme `USD`. Consultez [Gérer les variables du projet](/fr/guides/projects/managing-projects/#gérer-les-variables-du-projet). Le modèle la crée vide. Tant qu'elle est vide, chaque chargement utilise le premier des éléments suivants qui désigne exactement une devise :

1. La devise de groupe des entités.
2. La devise locale des entités de premier niveau, celles qui n'ont pas de parent.
3. La devise locale des fichiers.

Si aucun d'eux ne désigne exactement une devise, **Conversion de devises** affiche un problème jusqu'à ce que vous définissiez `reporting_currency`.

Les montants déjà exprimés dans la devise de reporting restent tels quels : un projet dont toutes les données sont dans une seule devise n'a donc besoin d'aucun taux.

Les fichiers de ventes, de stocks et de budget peuvent aussi porter une devise. Mettez en correspondance une colonne nommée `Currency` ou `Local Currency` : elle est prise en compte automatiquement, et les montants locaux du fichier sont convertis dans la devise de reporting. Un montant de groupe ou de reporting déjà présent dans le fichier est conservé tel quel. Le coût standard des produits n'est pas converti.

### Taux de change

Un taux convertit une unité d'une devise dans la devise de reporting pour un mois : le montant converti est égal au montant local multiplié par le taux.

- **Depuis votre ERP**, chaque chargement lit les taux de change que contient l'ERP.
- **Depuis un fichier**, ajoutez un fichier CSV ou Excel et choisissez le jeu de données **Taux de change**. Un taux du fichier remplace le taux de l'ERP pour les mêmes devises et le même mois. Utilisez un fichier pour établir vos rapports dans une devise pour laquelle vos ERP ne publient pas de taux, ou pour ajouter des taux prévisionnels pour les mois budgétaires.

| Colonne | Contenu |
|---|---|
| `from_currency` | La devise à convertir, par exemple `EUR`. |
| `to_currency` | La devise de reporting, par exemple `USD`. |
| `period` | Le mois, au format `YYYY-MM`. |
| `average_rate` | Le taux moyen du mois. |
| `closing_rate` | Le taux en fin de mois. |
| `historical_rate` | Le taux historique, pour les capitaux propres et pour les comptes définis au taux historique. |

Lorsqu'une devise n'a pas de taux vers la devise de reporting, son taux dans l'autre sens, de la devise de reporting vers elle, est inversé, avec 12 décimales. À défaut, son taux vers une autre devise est multiplié par le taux de cette devise vers la devise de reporting.

### Quel taux s'applique

Chaque ligne est convertie à partir de sa propre devise : une ligne dans une devise différente de celle de son entité est convertie à partir de la devise dans laquelle elle est exprimée. La première règle qui correspond à la ligne s'applique :

| Ligne | Taux |
|---|---|
| Comptes statistiques et comptes sans écriture | Non convertis. |
| Déjà dans la devise de reporting | Non convertie. |
| Compte avec un type de taux | Ce taux : moyen, de clôture ou historique. Le taux historique se replie sur le taux de clôture en l'absence de taux historique. Depuis un ERP, le type de taux est celui du compte lui-même. Dans un fichier de plan comptable, mettez en correspondance une colonne de type de taux avec `fx_rate_type` avec `average`, `closing` ou `historical`. |
| Ligne de vente | Le taux moyen de la période. |
| Solde de stock | Le taux de clôture de la période. |
| Ligne de budget | Selon le compte, comme pour le grand livre : le taux moyen pour les comptes de résultat et le taux de clôture pour les comptes de bilan. |
| Compte de résultat | Le taux moyen de la période. |
| Compte de capitaux propres | Le taux historique, ou le taux de clôture en l'absence de taux historique. |
| Tout autre compte de bilan | Le taux de clôture de la période. |

Les montants convertis ne sont pas arrondis, afin que les totaux ne dérivent pas.

<Aside type="note">
La balance générale contient les mouvements de chaque période : les montants de bilan sont donc les mouvements de chaque mois convertis au taux de clôture de ce mois. Il ne s'agit pas d'un bilan reconverti au taux de fin de période, et il n'y a ni écart de conversion cumulé ni élimination intragroupe. Utilisez les montants convertis pour le compte de résultat.
</Aside>

## Hiérarchies

Chaque chargement reconstruit les dimensions à partir des données de base de toutes les sources. Il existe sept dimensions au départ, et jusqu'à dix catégories supplémentaires :

| Dimension | Construite à partir de |
|---|---|
| **Entité** | Les entités et leurs parents |
| **Compte** | Le plan comptable et les comptes parents |
| **Département** | Les départements et leurs parents |
| **Client** | Les clients et leurs clients parents |
| **Produit** | Les produits et leurs produits parents |
| **Segment 1** | Les valeurs de segment de `segment_1` |
| **Segment 2** | Les valeurs de segment de `segment_2` |
| **Segment 3** à **Segment 10** | Les valeurs de segment de `segment_3` à `segment_10`, lorsque vos sources les portent |

- Un enregistrement sans parent, ou qui se désigne lui-même comme parent, est chargé comme membre de premier niveau.
- Comme chaque chargement reconstruit les hiérarchies, modifiez un parent dans l'ERP ou dans votre fichier, et non dans la dimension.
- Un problème dans une hiérarchie n'affecte que cette dimension. Le chargement et les modèles de calcul du modèle de projet se terminent quand même.
- Vous pouvez renommer chaque catégorie supplémentaire selon ce qu'elle contient, par exemple **Classe** ou **Région**. Sous **Names** sur la page **Sources**, saisissez les noms qu'utilisent vos rapports et cliquez sur **Save names**. Les noms peuvent comporter des lettres, des chiffres, des espaces, des points, des tirets et des traits de soulignement, jusqu'à 60 caractères.
- Chaque source indique sous lequel de vos noms de catégorie se range chacune de ses propres catégories supplémentaires. Cliquez sur **Modifier** sur la source, choisissez le nom pour chacune, ou choisissez **Leave out**, puis cliquez sur **Enregistrer**. Les sources qui appellent une catégorie par des noms différents, comme `Class` et `Business area`, partagent alors un même emplacement.

Pour fournir des hiérarchies de segments à partir d'un fichier, choisissez le jeu de données **Valeurs de segment** :

| Colonne | Contenu |
|---|---|
| `segment` | Le segment auquel appartient la valeur : `segment_1` à `segment_10`. |
| `segment_value` | La valeur, telle que la portent les lignes du grand livre, des ventes et du budget. |
| `segment_value_name` | Son nom. |
| `parent_segment_value` | Son parent au sein du même segment. |

## Contrôles de préparation

Après chaque chargement, la grille **Préparation** répertorie chaque contrôle pour chaque entité et chaque période, avec l'un des statuts suivants :

| Statut | Signification |
|---|---|
| **● Prêt** | Le contrôle a réussi. |
| **▲ À examiner** | Mérite un coup d'œil, mais les chiffres sont utilisables. |
| **■ Problème** | Corrigez ce point avant de vous fier aux résultats. |
| **– Sans objet** | Il n'y a pas encore de données pour ce contrôle. |

Les contrôles sont les suivants :

| Contrôle | Ce qu'il confirme |
|---|---|
| **Données chargées** | Chaque période fiscale comporte des lignes de grand livre, et chaque lecture de l'ERP a réussi. Une période clôturée sans aucune ligne est un problème ; une période ouverte sans aucune ligne est à examiner. |
| **La balance de vérification concorde avec le grand livre** | La balance générale est égale au grand livre pour chaque entité, période et compte. Lorsque la balance générale et le grand livre portent tous deux des départements pour un compte, la concordance est aussi vérifiée pour chaque département. |
| **Les ventes concordent avec le grand livre** | Les lignes de vente sont égales aux comptes de chiffre d'affaires et de coût des ventes du grand livre pour chaque période. |
| **Produits/clients inconnus** | Chaque ligne de vente nomme un produit et un client qui existent dans les référentiels de produits et de clients. |
| **Comptes absents du plan comptable** | Chaque ligne du grand livre nomme un compte du plan comptable. Les lignes dont le compte est inconnu sont exclues du compte de résultat. Un compte avec des écritures mais sans type de compte est aussi un problème, et une source dont le plan comptable type des comptes de chiffre d'affaires mais aucun compte de coût des ventes est à examiner. |
| **Conversion de devises** | Chaque ligne du grand livre, de la balance générale, des ventes, des stocks et du budget comporte un montant dans la devise de reporting. Une ligne de compte de résultat ou de vente sans taux est un problème, car le compte de résultat lit les montants convertis. Une ligne de bilan, de stock ou de budget sans taux est à examiner. Un mois budgétaire qui n'a pas encore de taux s'affiche en orange : chargez donc des taux prévisionnels pour les mois budgétaires. Consultez [Conversion de devises](#conversion-de-devises). |
| **Entités non mappées** | Chaque ligne du grand livre, de la balance générale et des ventes nomme une entité du référentiel d'entités, directement ou via la correspondance des entités. Sans objet tant qu'aucun référentiel d'entités n'est chargé. Consultez [Correspondance des entités](#correspondance-des-entités). |

Les chargements comportant plusieurs sources ajoutent ces contrôles :

| Contrôle | Ce qu'il confirme |
|---|---|
| **Livre de reporting** | Une source qui porte plusieurs livres comptables pour une entité a vu son livre de reporting choisi. Tant que vous n'avez pas choisi, seul le premier livre compte. |
| **Codes en attente de votre réponse** | Chaque code utilisé par plusieurs sources a reçu une réponse. Consultez [Mettre en correspondance les codes entre les sources](#mettre-en-correspondance-les-codes-entre-les-sources). |
| **Catégories supplémentaires de vos sources** | Chaque catégorie supplémentaire que porte une source a un nom ou a été exclue. |
| **Quelle source couvre quels mois** | Deux sources ne fournissent jamais les mêmes mois d'une société, sauf si vous avez choisi laquelle compte. |
| **Types de compte et hiérarchie** | Chaque parent nommé par une dimension existe, et aucun membre n'est son propre parent ou ancêtre. Un parent manquant place ses enfants au sommet de la hiérarchie, et une boucle empêche le chargement de cette hiérarchie. Les totaux ne sont pas affectés. |
| **Calendrier fiscal** | Les périodes fiscales de chaque entité sont des mois civils, et chaque mois de lignes peut être placé dans une seule période fiscale. Ce contrôle est à examiner lorsque les périodes d'une entité ne sont pas des mois civils (4-4-5, 13 périodes), ou lorsque les lignes d'un mois pourraient appartenir à plusieurs périodes fiscales ou que le calendrier fiscal ne comporte pas ce mois. |

Chaque ligne qui n'est pas prête indique quoi faire dans la colonne **Que faire**, par exemple charger le plan comptable, charger des taux de change ou exécuter de nouveau **Charger** pour une période.

La grille affiche aussi deux contrôles de configuration, qui n'apparaissent que lorsqu'ils sont à examiner :

| Contrôle | Quand il apparaît |
|---|---|
| **Répartition des frais généraux** | Une seule des variables de projet `overhead_department` et `overhead_driver` est définie, ou aucun inducteur d'allocation ne correspond à `overhead_driver` : l'allocation n'aurait donc aucun effet. Définissez les deux, ou effacez les deux pour désactiver la répartition des frais généraux. |
| **Comparaison budgétaire** | Des lignes de budget sont chargées, mais aucune ne se trouve dans la version que nomme la variable de projet `budget_version` : la comparaison budgétaire serait donc vide. |

## Consolidation de gestion

Chaque chargement construit une consolidation de gestion : le compte de résultat du groupe pour toutes les entités du groupe, dans la devise de reporting, après élimination de l'intragroupe. Elle est destinée au reporting de gestion. Votre système de consolidation reste la référence pour le groupe statutaire ; effectuez le rapprochement avec celui-ci comme décrit ci-dessous.

<Aside type="note">
La consolidation de gestion ne couvre que le compte de résultat. Il ne s'agit pas d'une consolidation statutaire ou légale, et elle ne comporte ni bilan consolidé, ni écart de conversion, ni écart d'acquisition, ni intérêts minoritaires.
</Aside>

### Choisir le groupe

Sur la page **Sources**, ouvrez **Group and row access** pour voir les sociétés du groupe. Une société que vous décochez reste dans vos rapports à titre individuel, mais est exclue du total du groupe. Cliquez sur **Save group**. La modification s'applique au prochain **Charger** ou **Apply changes**. Une nouvelle société fait partie du groupe jusqu'à ce que vous la décochiez.

L'exercice fiscal du groupe commence au mois défini par la variable de projet `group_fy_start_month`, qui vaut `1` sauf si vous la modifiez.

### Ce que vous obtenez

| Table | Contenu |
|---|---|
| **Compte de résultat du groupe** | Une ligne par entité, période et rubrique (chiffre d'affaires, coût des ventes, charges d'exploitation, hors exploitation, écart intragroupe), dans la devise de reporting. Le chiffre d'affaires et les coûts portent leur signe naturel. |
| **Compte de résultat du groupe en cumul annuel** | La même chose, en cumul depuis le début de l'exercice, jusqu'à la dernière période entièrement chargée du groupe. |
| **Paires intragroupe** | Une ligne par paire d'entités, groupe et période, avec le montant de chaque partie et le résidu. |
| **Lignes intragroupe** | Les lignes du grand livre derrière un chiffre du groupe ou une paire, avec le partenaire commercial. |
| **Rapprochement** | Le compte de résultat du groupe en cumul annuel comparé à votre système de consolidation. |

Trois noms d'entité apparaissent dans ces tables :

| Entité | Signification |
|---|---|
| **Éliminations** | Les éliminations intragroupe. Leur solde net est nul : laissez-les donc pour les chiffres du groupe et excluez-les par filtre pour obtenir la somme des entités avant élimination. |
| **Total groupe** | Le total du système de consolidation, dans le rapprochement. |
| **Non mappé** | Les lignes sans période, ainsi que les comptes ou entités de votre système de consolidation que ce projet ne comporte pas. |

Les métriques **Consolidated income**, **Consolidated result** et **IC difference**, ainsi qu'un chemin d'analyse pour chaque table, répondent aux questions sur le groupe.

### Éliminations intragroupe

Les lignes intragroupe sont rapprochées par partenaire commercial. C'est le partenaire indiqué sur la ligne qui est utilisé ; lorsqu'une ligne n'en a pas, c'est celui de son client. Les deux parties d'une paire sont éliminées, et le montant de l'écart entre les deux parties est comptabilisé sur une ligne d'écart intragroupe. Chaque paire reçoit un motif :

| Motif | Signification |
|---|---|
| **Correspondant** | Les deux parties ont comptabilisé le même montant. |
| **Une seule partie a comptabilisé** | Une entité a comptabilisé la transaction et son partenaire ne l'a pas fait. |
| **Non éliminé** | Une ligne de la paire n'a pas de taux de change : aucune des deux parties n'est donc éliminée. |

Une paire est évaluée sur son cumul annuel. La ligne **Intercompany balances** passe à l'orange lorsque l'écart d'une paire dépasse la variable de projet `group_amber` (`1` par défaut) et au rouge au-delà de `group_red` (`1000` par défaut). Les lignes sans partenaire, ou dont le partenaire n'est pas une entité, ne sont pas éliminées et sont comptées sur cette ligne. Une source qui porte des partenaires à côté d'une source qui n'en porte pas s'affiche en orange.

Les entités d'élimination propres à une source restent en dehors du compte de résultat du groupe, et la ligne **Consolidation** l'indique.

### Rapprocher avec votre système de consolidation

Ajoutez sous forme de fichier les résultats que publie votre système de consolidation, et cochez **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** lorsque vous confirmez sa correspondance. Répondez à **Which version of the numbers is this?** par le nom du système. La table **Rapprochement** affiche alors **nôtre**, **déclaré** et **écart** pour chaque entité et chaque rubrique, en cumul annuel. Un écart s'explique généralement par les lignes **Éliminations**, **Total groupe** et **Non mappé**, ou par les taux de change qu'utilise le système. La ligne **Reconciliation to the source** répertorie chaque rubrique au-delà de `group_amber`.

### Qui peut le voir

Les résultats du groupe suivent l'accès aux lignes du projet. Lorsque l'accès aux lignes bloque les résultats du groupe, le statut s'affiche en orange. Une personne qui ne voit que certaines entités voit les sommes de ces entités avant élimination. Les lignes **Éliminations** et les tables intragroupe nécessitent l'accès à toutes les entités.

Si le projet limite qui voit quelles lignes au moyen d'une colonne que les tables du groupe ne portent pas, comme le département, les résultats du groupe restent désactivés pour tout le monde et **Consolidation** indique **Group views are off**. Seul un Architecte peut alors cocher **Everyone on the project may see the group results** sous **Groupe**. La modification s'applique au prochain **Charger** ou **Apply changes**.

## Garder les données à jour

Lorsqu'un chargement depuis votre connexion ERP réussit sans aucun problème, **Actualiser chaque nuit** apparaît dans **Statut**. Cliquez dessus pour exécuter **Charger** chaque nuit à 2 h 00 dans votre fuseau horaire. **Statut** affiche alors **Nightly refresh: Every night at 2:00** ainsi que la personne qui l'a configuré.

Le chargement nocturne s'exécute sous l'identité de la personne qui l'a configuré. Si cette personne ne peut plus utiliser la connexion ERP, la grille indique que le chargement nocturne est ignoré ; configurez-le de nouveau. Un projet qui ne contient que des données d'exemple ne peut pas être planifié.

Un fichier manquant ou vide lors d'un chargement nocturne se termine par un avertissement qui nomme le chemin, et non par une erreur, et le reste du modèle est quand même chargé.

## Noms métier

Les **Business names**, sous **Names** dans la page **Sources** de l'onglet **Foundation**, donnent aux codes de votre modèle les noms qu'utilise votre entreprise. Les rapports, les métriques et l'assistant affichent ces noms, et un nom que vous enregistrez s'applique immédiatement. Les chargements ultérieurs le conservent.

1. Cliquez sur **Add a name** et choisissez le **Genre** : **Catégorie**, **Ligne du compte de résultat**, **Métrique** ou **Colonne**.
2. Saisissez le **Code** : `segment_1` à `segment_10` pour une catégorie, la clé de la ligne pour une ligne du compte de résultat, le nom de la métrique, ou `table.column` pour une colonne.
3. Saisissez le **Nom**, 60 caractères au maximum sur une seule ligne.
4. Cliquez sur **Save names**.

L'enregistrement remplace toute la liste. Une ligne dont le nom est vide supprime ce nom, et **Supprimer la sélection** supprime les lignes que vous cochez. Nommer deux fois le même code est refusé. Les noms métier sont aussi écrits dans la description du chemin d'analyse afin que l'assistant utilise vos termes, et cette description a une longueur limitée : si un nom la rendait trop longue, rien n'est enregistré et vous en êtes informé.

## Expliquer un chiffre

**Explain this number** montre ce qui compose un chiffre du compte de résultat. Dans la grille **Préparation**, une ligne pour une entité et un mois comporte **Explain this number**, qui ouvre la marge d'exploitation de l'entité pour ce mois. La fenêtre décompose le chiffre en couches dont la somme donne le total affiché en haut :

| Couche | Contenu |
|---|---|
| **From the general ledger** | Ce que le grand livre a comptabilisé sur la ligne. |
| **Allocated in** | Le coût réparti sur cette entité par vos [règles d'allocation](#règles-dallocation). |
| **Allocated out** | Le coût que cette entité a réparti sur d'autres. |
| **Eliminated in the group** | L'intragroupe éliminé dans le résultat du groupe. |

Chaque couche comporte une phrase qui indique ce qu'elle est et ses principaux documents sources, avec leur système source, leur document et leur compte. Seules les couches qui comportent des lignes sont affichées. La fenêtre suit votre accès aux lignes : vous n'expliquez que les chiffres que vous pouvez voir. Un chiffre derrière lequel il n'y a rien indique **Nothing to explain**.

## Règles d'allocation

Les allocations répartissent les coûts partagés, comme les frais généraux, sur les départements, les produits et les clients. Le modèle comporte deux phases : **Stage 1: overhead to departments** et **Stage 2: departments to products and customers**. Ouvrez **Actions > Allocations...** pour voir ou modifier la façon dont chacune est effectuée. Sans modification, elles fonctionnent comme avant l'existence de l'assistant. Un lecteur peut ouvrir les règles, mais pas les enregistrer.

Pour chaque phase, l'assistant pose quatre questions :

| Étape | Question | Choix |
|---|---|---|
| **Pool de coûts** | Quels coûts voulez-vous répartir ? | Le type de compte et, pour la phase 1, le département qui porte le coût, ou **All departments**. |
| **Inducteur** | Selon quoi voulez-vous les répartir ? | Une **Statistic** que vous avez chargée comme inducteur d'allocation, comme l'effectif ou la surface, **Net sales amount**, **Sales quantity** ou **Spread evenly**. Utilisez l'inducteur de **Same period** ou de **Same period last year**. |
| **Cible** | Où aboutissent-ils ? | Phase 1 : les départements. Phase 2 : les produits, les clients ou les deux. |
| **Méthode** | Que se passe-t-il lorsqu'un inducteur est négatif ? | **Ignore negative values** ou **Stop and tell me**. |

Sous les étapes, **Preview for** un mois, écrit sous la forme année et mois comme `2026-09`, montre ce que feraient les règles, y compris celles que vous n'avez pas enregistrées : `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Tout montant non alloué est un coût qui n'avait aucun inducteur pour le prendre en charge. L'aperçu suit votre accès aux lignes.

Un nom de département ou de statistique ne peut contenir ni apostrophe (`'`), ni barre oblique inverse, ni saut de ligne, car le nom est écrit dans les filtres des étapes d'allocation. **Enregistrer** et un aperçu de la phase 1 refusent un tel nom et l'indiquent.

Cliquez sur **Enregistrer**. Les règles prennent effet au prochain **Charger**, ou lorsque vous cliquez sur **Apply changes**. Si vous avez modifié une étape d'allocation à la main, votre modification est conservée, et non écrasée, et l'enregistrement la nomme. Vous ne pouvez pas enregistrer pendant qu'un chargement s'exécute.

## Dossier du conseil

Un dossier du conseil écrit vos résultats dans un dossier d'un compte de documents, prêts à être envoyés. Ouvrez **Actions > Board pack...**, choisissez un **Compte de documents** et un **Dossier**, comme `/board-packs`, puis cliquez sur **Enregistrer**. Chaque **Charger** produit alors le dossier du conseil : les fichiers du dossier sont donc aussi à jour que le dernier chargement. Chaque exécution écrit :

- Un classeur Excel, `Board pack.xlsx`, avec le compte de résultat par entité, un pont de marge, ainsi que les meilleurs et les moins bons clients.
- Un PDF du tableau de bord du compte de résultat.

Cliquez sur **Run now** pour produire immédiatement un dossier du conseil ; ses fichiers apparaissent dans le dossier lorsqu'il est terminé. La boîte de dialogue affiche la dernière exécution et son résultat, ainsi que la prochaine exécution. **Apply changes** ne produit pas de dossier du conseil. Pour en produire un chaque nuit, configurez l'actualisation nocturne (consultez [Garder les données à jour](#garder-les-données-à-jour)) ; d'ici là, la boîte de dialogue indique **Not scheduled yet**. Seule une personne qui peut modifier le projet peut la configurer.

Un dossier du conseil qui ne peut pas être produit en entier ne fait jamais échouer le chargement :

- Si le reporting est désactivé pour votre espace de travail, le dossier du conseil se limite au classeur Excel, et l'exécution indique **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- Si un tableau de bord créé par quelqu'un d'autre utilise déjà l'adresse dont Data Foundation a besoin pour le tableau de bord du compte de résultat, ce tableau de bord est laissé tel quel et le PDF n'est pas produit. Le message nomme l'adresse ; donnez une autre adresse à l'autre tableau de bord, puis exécutez de nouveau **Charger**.
- Si une étape du dossier du conseil échoue, la liste **Statut** affiche une ligne **Board pack** orange qui nomme l'étape et la raison. Le chargement lui-même a quand même réussi.

## Points de restauration

Un point de restauration est créé au démarrage de chaque **Charger** ou **Apply changes**, quelle que soit la personne qui le lance, y compris pour un chargement planifié, et avant chaque modification des correspondances ou des sources. Il contient les tables du modèle, les dimensions et les paramètres à partir desquels le prochain chargement est construit : vos sources, vos fichiers et vos règles d'allocation. Les sept derniers points créés pour des chargements et les cinq derniers créés avant des modifications sont conservés : les modifications n'évincent donc jamais les points créés pour des chargements. Les points plus anciens sont supprimés au fur et à mesure.

Pour revenir en arrière, ouvrez **Actions > Restaurer...**. Chaque point indique quand il a été créé et, en dessous, combien de tables sa restauration rétablit, par exemple **Puts back 12 tables.**, ainsi que les éventuels avertissements. Choisissez un point et cliquez sur **Restaurer**. **Restaurer** est proposé dès qu'un point existe. La restauration enregistre d'abord le projet dans son état actuel comme un point à part entière, afin que vous puissiez revenir de nouveau en arrière. Elle rétablit ensuite les tables, les dimensions et ces paramètres tels qu'ils étaient, et le prochain chargement est construit à partir d'eux. Restaurer les sources que vous aviez déjà ne les marque pas comme modifiées. Une vue, une dimension qui ne peut pas être enregistrée ou une table sans copie enregistrée est nommée dans un avertissement, et le reste est restauré. Un point de restauration supprimé est refusé, et vous ne pouvez pas restaurer pendant qu'un chargement s'exécute.

## Cloner un projet

**Actions > Cloner...** copie le projet sous le nom que vous indiquez. La copie conserve le modèle de projet, vos modifications du modèle, ainsi que vos métriques et vos chemins d'analyse, et charge les données d'exemple. Ses sources ne sont pas connectées : connectez-les donc dans la copie avant de charger. Vous pouvez continuer à travailler pendant la création de la copie, et **Ouvrir le projet** vous y amène lorsqu'elle est prête.

## Enregistrer comme mon modèle

Enregistrez la configuration d'un projet pour la réutiliser pour le client ou l'entité suivants. Ouvrez **Actions > Save as my template...**, choisissez le compte de documents et nommez le fichier. L'extension `.zip` est ajoutée si vous l'omettez. L'enregistrement par-dessus un fichier existant est refusé : choisissez donc un autre nom.

Le fichier contient la structure du projet, vos modifications du modèle, les métriques et les chemins d'analyse, les noms métier des entités et des comptes, ainsi que les lignes des tables de configuration du modèle de projet, comme la table de correspondance des activités de [Coût de service](/fr/guides/projects/cost-to-serve/) ou les fourchettes de politique de [Prix de transfert opérationnels](/fr/guides/projects/operational-transfer-pricing/). Il exclut les connexions, les fichiers, la planification nocturne, les exécutions, les points de restauration, le dossier du conseil et les accès.

Pour l'utiliser, créez un projet, choisissez **From a template file...** sous **Partir de**, puis sélectionnez le compte de documents et le chemin. Le nouveau projet vous est privé, et chaque source attend d'être connectée. Une version ultérieure du modèle fusionne ensuite ses modifications autour des étapes que vous avez modifiées. S'il n'y a aucun fichier au chemin indiqué, rien n'est créé et vous en êtes informé. Toute personne qui peut lire le compte de documents peut effectuer l'installation à partir du fichier. Pour l'utiliser dans un autre espace de travail, téléchargez le fichier et téléversez-le dans cet espace.

## Résoudre les questions en suspens avec Ask

Après un chargement, un projet peut encore attendre trois informations : les comptes que le plan comptable laisse sans type, les codes qu'utilisent plusieurs sources et les colonnes de vos fichiers qui ne correspondent à rien. Demandez à l'assistant de les résoudre : depuis un assistant IA via MCP, utilisez le prompt **Resolve Data Foundation residue**. Il lit ce qui est en attente et propose une réponse pour chaque élément, avec une justification.

L'assistant n'écrit rien. Vous appliquez ses réponses là où vous auriez répondu vous-même : les comptes et les codes sous **Codes en attente de votre réponse**, et les colonnes de fichier dans la correspondance du fichier. Il ne propose jamais d'entité.

## Transmettre le projet

La liste de contrôle **Configuration** comporte quatre éléments de clôture après **Vérifier vos hiérarchies** :

- **Configurer l'actualisation nocturne** est terminé dès que **Actualiser chaque nuit** est activé.
- **Partager avec votre équipe** est terminé dès qu'une personne autre que celle qui a configuré le projet en est membre.
- **Télécharger le dossier de preuves** est terminé lorsque vous téléchargez le dossier de preuves après le dernier chargement réussi.
- **Confier le projet à son propriétaire** est terminé dès qu'il existe un Architecte autre que la personne qui a configuré le projet et que les totaux concordent. Tant que ce n'est pas le cas, la liste de contrôle indique quoi faire : faites du propriétaire côté client un Architecte de ce projet, puis retirez-vous de ses membres.

La liste de contrôle indique qui a configuré le projet (**Set up by**).

## Construire sur le modèle avec un modèle de projet

Un modèle de projet construit ses rapports et ses modèles de calcul sur le Common Finance Model : ils fonctionnent donc de la même façon, quels que soient les ERP qui l'alimentent. Lorsque vous créez un projet à partir d'un modèle de projet, comme **Rentabilité de l'entreprise**, il crée :

- Les [tables du Common Finance Model](#tables-du-common-finance-model), vides ou remplies de données d'exemple.
- Les dimensions **Entité**, **Compte**, **Département**, **Client**, **Produit**, **Segment 1** et **Segment 2**, construites à partir de ces tables. Consultez [Hiérarchies](#hiérarchies).
- Le workflow **Charger** et les workflows qu'il exécute pour lire votre ERP et vos fichiers, les conformer, contrôler la préparation et construire les modèles de calcul du modèle de projet.
- Les rapports et modèles de calcul propres au modèle de projet. **Rentabilité de l'entreprise** ajoute une table de compte de résultat avec le chiffre d'affaires, le coût des ventes, la marge brute, les charges d'exploitation directes et de frais généraux, la contribution et la marge d'exploitation, ainsi que des ponts de marge d'une année sur l'autre et par rapport au budget.
- Des métriques et un chemin d'analyse pour poser des questions sur les résultats.

Trois modèles de projet sont disponibles sous **Partir de**, chacun construit sur le même modèle :

| Modèle de projet | Ajoute |
|---|---|
| **Rentabilité de l'entreprise** | Le compte de résultat et les ponts de marge. |
| **Coût de service** | Le coût de service de chaque client, et la marge après ce coût. Consultez [Coût de service](/fr/guides/projects/cost-to-serve/). |
| **Prix de transfert opérationnels** | Le niveau de profit de chaque entité par rapport à la fourchette de votre politique, et l'ajustement. Consultez [Prix de transfert opérationnels](/fr/guides/projects/operational-transfer-pricing/). |

**From a template file...** part d'un projet que vous avez enregistré. Consultez [Enregistrer comme mon modèle](#enregistrer-comme-mon-modèle).

Pour explorer avant de connecter votre propre ERP, cochez **Commencer avec des données d'exemple** lorsque vous créez le projet. Le projet exécute immédiatement un premier chargement : l'onglet **Foundation** affiche donc un exemple complet, y compris une entité en euros convertie en dollars américains. Lorsque vous connectez votre propre ERP ou ajoutez vos propres fichiers, l'exemple est supprimé et vos données prennent sa place. Si la suppression est interrompue, le prochain **Charger** la termine. Un dossier personnel nommé `sample` n'est jamais supprimé : la page de statut signale que l'exemple occupe ce dossier, que les autres tables qu'il contient ne sont donc pas lues, et vous invite à les déplacer dans un dossier portant un autre nom.

## L'onglet Foundation

L'onglet **Foundation** est l'endroit où vous connectez, chargez et contrôlez vos données. Un rail à gauche répertorie quatre pages :

| Page | Ce qu'elle affiche |
|---|---|
| **Statut** | L'état du projet : **Dernier chargement** avec les boutons **Charger**, **Actualiser** et **Actualiser chaque nuit**, **What to do next**, la liste de contrôle **Configuration**, **Données chargées**, **Périodes**, **Préparation** et le menu **Actions**. |
| **Réponses requises** | Les questions qui vous attendent, comme les codes qu'utilisent plusieurs sources, pour lesquels vous indiquez s'ils ont le même sens. |
| **Couverture des sources** | Les endroits où les sources se chevauchent ou laissent des lacunes pour une société et un mois, et quelle source compte à partir de quand. |
| **Sources** | Chaque source dans la liste **Load order**, avec **Modifier** et **Remove this source**, les cartes **Groupe** et **Names**, et **Connect a system** (ou **Connect another system**), où vous choisissez un type de système, sélectionnez sa connexion, choisissez les sociétés et le nombre de mois d'historique à charger, ou ajoutez un fichier. Les fichiers que vous avez ajoutés se trouvent dans la carte **Fichiers**. |

Les badges du rail comptent ce qui est à examiner : les questions en suspens sur **Réponses requises**, les problèmes de couverture sur **Couverture des sources** et les sources sur **Sources**. **Statut** n'affiche aucun badge. Le résultat d'un **Charger** ou d'un **Apply changes** et la bannière de statut s'affichent au-dessus de la page ouverte, quelle qu'elle soit : vous les voyez donc sur chaque page. Les boutons de **Statut** qui renvoient à une question ou à un problème de couverture, comme **Answer codes ›** et **Choose sources ›**, vous amènent à la page correspondante. Fermer **Réponses requises** ou **Couverture des sources** vous ramène à **Statut**.

Lorsque vous modifiez vos sources, une barre au-dessus de chaque page indique **You have changed your sources. Press Apply changes to use them.** Elle comporte **Show what changed** et **Apply changes**, et c'est le seul endroit où appliquer une modification. Lorsque rien n'attend d'être appliqué, **Charger** est le bouton principal de **Statut**. Sur **Statut**, **What to do next** répertorie d'abord les problèmes, puis les éléments à examiner, numérotés à travers les deux groupes. Sur **Réponses requises**, **Answer all** propose **Accept suggestions**, **All the same** et **All different**. Sur **Couverture des sources**, **Save choice** conserve quelle source compte à partir de quand.

La liste de contrôle **Configuration** comprend : **Connecter vos données**, **Charger vos données**, **Vérifier la concordance des totaux**, **Vérifier vos hiérarchies**, **Configurer l'actualisation nocturne**, **Partager avec votre équipe**, **Télécharger le dossier de preuves** et **Confier le projet à son propriétaire**. L'élément en cours est en gras. Les noms métier, les fichiers que vous avez ajoutés et l'état de leur correspondance (**✓ Confirmé** ou **○ En attente de confirmation**), ainsi que la grille de préparation, avec une ligne par entité, période et contrôle et sa colonne **Que faire**, se trouvent sur les mêmes pages. Consultez [Noms métier](#noms-métier).

Pendant l'exécution d'un chargement, l'onglet s'actualise de lui-même et continue de lire même si une lecture échoue. Si le statut ne peut pas être lu, **Le statut de Foundation n'a pas pu être lu.** s'affiche avec **Réessayer**, qui le relit ; l'onglet réessaie aussi une fois de lui-même avant d'afficher le message, et le message disparaît lorsque le serveur répond.

La page **Statut** signale aussi :

- Un dossier sous `/sources/` dont les tables ne comportent pas les colonnes nécessaires n'est pas ajouté comme source. Une note nomme chaque table exclue et la colonne qui lui manque. Ajoutez la colonne, puis appuyez sur **Charger** ou **Apply changes**.
- Si un chargement a réussi mais n'a apporté aucune ligne de grand livre à comparer, une ligne **Model P&L ties to GL** orange indique que rien n'a concordé. **Vérifier la concordance des totaux** reste en attente dans la liste de contrôle de configuration, et non terminé, jusqu'à ce que quelque chose ait concordé. Ajoutez une source comportant des lignes de grand livre, puis appuyez sur **Charger**.

La liste de contrôle de configuration suit votre progression :

- **Connecter vos données** et **Charger vos données** se cochent d'eux-mêmes dès qu'une source est rattachée et qu'un chargement réussit.
- **Vérifier la concordance des totaux** se coche de lui-même lorsque les contrôles de concordance réussissent.
- **Vérifier vos hiérarchies** : cliquez sur **Ouvrir les dimensions** pour vérifier les hiérarchies Entité, Compte et Département, puis cochez **Je les ai examinés**. Vous confirmez celui-ci vous-même.
- **Configurer l'actualisation nocturne**, **Partager avec votre équipe**, **Télécharger le dossier de preuves** et **Confier le projet à son propriétaire** terminent la liste. Consultez [Transmettre le projet](#transmettre-le-projet) et [Gérer l'accès au projet](/fr/guides/projects/managing-projects/#gérer-laccès-au-projet).

Le menu **Actions** contient **Allocations...**, **Board pack...**, **Cloner...**, **Restaurer...** et **Save as my template...**. Consultez [Règles d'allocation](#règles-dallocation), [Dossier du conseil](#dossier-du-conseil), [Cloner un projet](#cloner-un-projet), [Points de restauration](#points-de-restauration) et [Enregistrer comme mon modèle](#enregistrer-comme-mon-modèle).

## Tables du Common Finance Model

Data Foundation conforme chaque source, ERP ou fichier, aux mêmes quinze tables : les rapports, les métriques et les modèles de calcul construits sur elles fonctionnent donc de la même façon, quelle que soit la source. Chaque ligne enregistre aussi son système source et la date à laquelle elle a été lue. La colonne **Jeu de données** contient le nom que vous choisissez lorsque vous ajoutez un fichier.

| Jeu de données | Table | Contenu |
|---|---|---|
| Entités | `cfm_entity` | Les entités juridiques avec leur parent, leurs devises locale et de groupe, et leur pays. |
| Correspondance des entités | `cfm_entity_map` | Les codes d'entité des sources et l'entité à laquelle chacun appartient. Consultez [Correspondance des entités](#correspondance-des-entités). |
| Taux de change | `cfm_fx_rate` | Les taux mensuels moyens, de clôture et historiques par paire de devises. Consultez [Taux de change](#taux-de-change). |
| Calendrier fiscal | `cfm_fiscal_calendar` | Une ligne par période fiscale d'entité, avec les dates de début et de fin et l'indication de clôture. |
| Plan comptable | `cfm_account` | Les comptes avec leur parent, leur type (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), leur état financier, leur solde normal et leur type de taux. |
| Départements | `cfm_department` | Les départements et centres de coût avec leur parent et leur centre de profit. |
| Produits | `cfm_product` | Le référentiel de produits avec le parent, la famille, le groupe, l'unité de mesure et le coût standard. |
| Clients | `cfm_customer` | Le référentiel de clients avec le parent, le groupe, la région et le pays. Les noms de clients ne sont pas masqués. |
| Valeurs de segment | `cfm_segment` | Les valeurs de segment avec leur nom et leur parent. Consultez [Hiérarchies](#hiérarchies). |
| Grand livre | `cfm_gl_journal` | Les lignes d'écriture en devise de transaction, en devise locale et en devise de reporting. |
| Balance de vérification | `cfm_trial_balance` | Les débits, crédits et soldes nets de la période par entité, compte et département, en devise locale et en devise de reporting. |
| Lignes de vente | `cfm_sales_line` | Les lignes de vente facturées avec la quantité et les montants bruts, de remise, nets et de coût des ventes. |
| Soldes de stock | `cfm_inventory_balance` | Le stock de fin de période par produit et par entrepôt. |
| Budget | `cfm_budget` | Le budget et les prévisions par scénario, version, compte et département. |
| Inducteurs d'allocation | `cfm_stat_driver` | Les inducteurs statistiques comme l'effectif, la surface ou les unités. |

Les périodes s'écrivent `YYYY-MM`, et les transactions sont placées selon leur période de comptabilisation. Le budget est facultatif : un ERP sans budgets charge quand même tout le reste.

Un fichier de balance générale peut comporter des colonnes de débit et de crédit, une colonne de solde net, ou les deux. Avec seulement le débit et le crédit, le solde net est égal au débit moins le crédit, et un côté vide compte pour zéro. Avec seulement un solde net, un solde net positif devient le débit et un solde net négatif devient le crédit, sous forme de montant positif. Une colonne de département est facultative.

## Dépannage

| Symptôme | Que faire |
|---|---|
| **Tester la connexion** indique que l'ERP a refusé les identifiants | Vérifiez les identifiants de la connexion, et que l'utilisateur d'intégration peut se connecter à l'ERP. |
| **Tester la connexion** affiche **Autorisation manquante** pour un jeu de données | Demandez à votre administrateur ERP d'ajouter les autorisations nommées. Le [guide de connexion](/fr/guides/connections/) de votre ERP répertorie ce dont la connexion a besoin. |
| Un message d'erreur de l'ERP est plus court que celui de l'ERP lui-même | PlaidCloud supprime les identifiants, jetons et clés des erreurs du fournisseur avant de les afficher : certains détails sont donc omis. Exécutez **Tester la connexion** pour voir quel jeu de données est concerné. |
| **Données chargées** est un problème pour une période | Une lecture de l'ERP pour cette période a échoué. Exécutez de nouveau **Charger** ; les périodes déjà chargées sont ignorées. |
| **Comptes absents du plan comptable** est un problème | Ajoutez les comptes manquants au plan comptable dans l'ERP ou dans votre fichier, puis exécutez de nouveau **Charger**. |
| **Conversion de devises** est un problème | La devise d'une entité n'a pas de taux vers la devise de reporting pour cette période, ou aucune devise de reporting unique n'a été trouvée. Ajoutez les taux dans un fichier **Taux de change**, vérifiez que la connexion peut lire les taux de change de l'ERP, ou définissez la variable de projet `reporting_currency`. Exécutez ensuite de nouveau **Charger**. |
| **Conversion de devises** est à examiner | Des lignes de bilan, de stock ou de budget n'ont pas de taux de clôture, historique ou prévisionnel pour la période. Le compte de résultat n'est pas affecté. Ajoutez les taux, y compris des taux prévisionnels pour les mois budgétaires, puis exécutez de nouveau **Charger**. |
| **Codes en attente de votre réponse** est à examiner | Cliquez sur **Answer codes ›**, répondez pour chaque code, puis cliquez sur **Apply changes**. |
| **Quelle source couvre quels mois** est à examiner | Cliquez sur **Choose sources ›**, choisissez la source, cliquez sur **Save choice**, puis sur **Apply changes**. |
| **Intercompany balances** est rouge ou orange | Vérifiez les paires dans **Paires intragroupe**. Comptabilisez la partie manquante, ajoutez le partenaire commercial aux lignes, ou ajoutez le taux manquant. |
| **Group views are off** | Demandez à un Architecte de cocher **Everyone on the project may see the group results** sous **Groupe**. |
| **Entités non mappées** est un problème | Ajoutez l'entité au référentiel d'entités, ou mettez son code en correspondance avec une entité existante dans le fichier **Correspondance des entités**, puis exécutez de nouveau **Charger**. |
