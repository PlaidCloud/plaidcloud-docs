**Data Foundation** est la base de données financières de vos projets PlaidCloud. Son **Common Finance Model** réunit dans un modèle unique les données ERP de plusieurs systèmes ERP, et de plusieurs instances de chacun : un seul plan comptable, un seul jeu d'entités et une seule devise de reporting. Les rapports, les métriques et les assistants IA construits sur le modèle lisent tous les mêmes chiffres, quel que soit l'ERP d'origine.

Votre ERP se connecte par sa connexion PlaidCloud, de sorte que le grand livre, la balance générale, les données de base et les budgets arrivent directement de la source, sans aucun export. Les fichiers apportent les données qu'un système ne contient pas, comme les taux de change, les inducteurs d'allocation ou un budget tenu hors de l'ERP, et peuvent remplacer les lignes de l'ERP qu'ils couvrent. **Charger** harmonise chaque source dans le modèle, la convertit dans la devise de reporting et vérifie que les totaux concordent, le tout depuis l'onglet **Foundation** du projet. Lorsque des sources utilisent le même code pour des choses différentes, vous indiquez si elles désignent la même chose, et une consolidation de gestion construit le compte de résultat du groupe avec les opérations intercompagnies éliminées. Des modèles, tels que **Rentabilité de l'entreprise**, construisent leurs rapports et leurs modèles par-dessus.

## Connecter votre ERP

Votre ERP se connecte à Data Foundation par sa connexion PlaidCloud. Data Foundation lit directement à partir de celle-ci le grand livre, la balance générale, les données de base, les taux de change et les budgets, et ne fait jamais que lire. Vous pouvez choisir une connexion existante ou en créer une dans l'onglet ; les [guides de connexion](/fr/guides/connections/) décrivent la configuration de l'accès pour chaque ERP.

<Steps>

1. Dans Analyze, ouvrez **Projets** et cliquez sur **Nouveau projet**. Saisissez un nom et, sous **Partir de**, choisissez un modèle, tel que **Rentabilité de l'entreprise (modèle)**, au lieu de **Projet vierge**. Cliquez sur **Créer**.

   Le projet s'ouvre sur son onglet **Foundation**. Il est privé et vous en êtes le seul Architecte, jusqu'à ce que vous le partagiez.

2. Dans l'onglet **Foundation**, choisissez une connexion existante pour votre ERP, ou sélectionnez **Créer une nouvelle connexion**. Chaque connexion existante indique les workflows qui l'utilisent déjà, ou affiche **Pas encore utilisé par un workflow**.

3. Pour une nouvelle connexion, saisissez un **Nom de la connexion**, choisissez l'**Environnement** et renseignez les identifiants que demande la connexion à votre ERP.

   Vous n'avez pas encore les identifiants ? Le formulaire affiche une demande d'accès toute prête pour l'administrateur de votre ERP. Cliquez sur **Copier la demande** ou **Envoyer la demande par e-mail**, envoyez-la, puis saisissez les valeurs qu'il vous renvoie.

4. Cliquez sur **Tester la connexion**. PlaidCloud se connecte et essaie de lire chaque jeu de données, puis indique pour chacun **Lisible**, **Autorisation manquante** ou **Erreur**. Lorsqu'il manque quelque chose, il nomme les autorisations à demander à l'administrateur de votre ERP.

5. Définissez **Mois d'historique** : le nombre de mois à charger en remontant dans le temps, de 1 à 120. La valeur par défaut est 24.

6. Pour une connexion existante, cochez les entités à charger, ou laissez-les toutes décochées pour charger chaque entité. Les entités inactives et les entités d'élimination restent masquées tant que vous ne choisissez pas de les afficher. Cliquez ensuite sur **Connecter**.

7. Pour une nouvelle connexion, cliquez sur **Connecter** pour la créer. Cochez ensuite les entités à charger et cliquez de nouveau sur **Connecter** pour les enregistrer. Tant que vous ne le faites pas, toutes les entités sont chargées.

8. Pour ajouter un autre système ERP ou une autre instance, répétez ces étapes et cochez **Add this as another source instead of replacing the current one** avant de cliquer sur **Connecter**. Sans cette option, la nouvelle connexion remplace la source actuelle.

</Steps>

Une fois la connexion établie, la carte indique la connexion, l'environnement, les entités et le nombre de mois d'historique que le projet charge.

Chaque chargement ne lit que ce qui a changé : les périodes ouvertes et la dernière période clôturée sont relues, et les périodes clôturées déjà chargées sont conservées. Augmenter **Mois d'historique** ne lit que les mois ajoutés. Un taux de change, une correspondance des entités ou une devise de reporting modifiés font relire les mois qu'ils affectent.

## Sources

Chaque système ERP et chaque instance à partir desquels le projet charge des données constituent une source. La liste **Sources** de l'onglet **Foundation** affiche une ligne par source, dans l'ordre, avec son nom, la date de son dernier chargement, le nombre de lignes qu'elle a fournies et les livres de reporting qu'elle lit, par exemple `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Une source qui n'a pas encore été chargée indique **not loaded yet**. Les fichiers que vous confirmez sont aussi des sources.

Ouvrez **Avancé** sur une source pour modifier la façon dont elle est utilisée :

| Paramètre | Rôle |
|---|---|
| **Nom** | Le libellé que les rapports, les questions de correspondance et les messages utilisent pour la source. |
| **Place in the order** | Le rang de la source. Lorsque deux sources couvrent le même mois de la même société, celle qui est plus haut dans l'ordre l'emporte. |
| **Reporting books, separated by commas** | Les livres comptables à lire, pour un système qui en tient plusieurs. **All reporting books** lit tous les livres. |
| **Société**, **De (2026-01)** et **À (2026-12)** | Les mois que cette source fournit pour chaque société. Laissez un mois vide pour ne fixer aucune limite. Écrivez les mois sous la forme année-mois, par exemple `2026-03`. |

Cliquez sur **Enregistrer** pour conserver vos modifications. Pour retirer une source, cliquez sur **Remove this source** et confirmez avec **Supprimer**. Tout ce qui a été chargé à partir d'elle est supprimé, et vous pourrez la reconnecter plus tard.

Modifier les sources ne relit pas votre ERP. La carte **Dernier chargement** indique **Changes not applied yet** jusqu'à ce que vous cliquiez sur **Apply changes**, qui lance un chargement à partir des données déjà extraites : il harmonise de nouveau les sources avec votre nouvel ordre, vos correspondances, vos noms et vos fichiers, puis reconstruit le modèle. Cliquez sur **Charger** lorsque vous voulez aussi des données fraîches issues des ERP.

## Ajouter des fichiers pour les données hors de votre ERP

Les fichiers complètent votre connexion ERP avec des données qu'un système ne contient pas, comme les taux de change, les inducteurs d'allocation, une [Correspondance des entités](#correspondance-des-entités) ou un budget tenu hors de l'ERP. Chaque fichier appartient à l'un des jeux de données listés sous [Tables du Common Finance Model](#tables-du-common-finance-model).

<Steps>

1. Sous **Fichiers**, choisissez le **Compte de documents** où stocker le fichier.

2. Déposez un fichier CSV ou Excel sur **Déposez un fichier CSV ou Excel ici**, ou cliquez sur **Choisir un fichier**. Le fichier est téléversé dans le dossier `/foundation/` du compte de documents.

   Pour un fichier qui se trouve déjà dans le compte de documents, saisissez son **Chemin du fichier**, par exemple `/foundation/budget.csv`, puis cliquez sur **Ajouter un fichier**.

   Pour lire un nouveau fichier chaque mois, ajoutez tous les fichiers d'un dossier dont le nom correspond : saisissez le dossier et ce que les **File names that** doivent contenir, commencer par, terminer par, correspondre exactement à ou correspondre à un motif, puis cliquez sur **Add files**. Les fichiers situés dans des sous-dossiers ne sont pas lus.

3. PlaidCloud lit le fichier et propose une correspondance :

   - **Détection du délimiteur, du séparateur décimal et des dates.** Le délimiteur (virgule, point-virgule, tabulation ou barre verticale), le séparateur décimal et le format de date sont détectés pour vous.
   - **Jeu de données** : la table du Common Finance Model à laquelle le fichier appartient, déterminée à partir du nom du fichier et des en-têtes de colonnes. Lorsque la correspondance n'est pas claire, choisissez-la dans la liste.
   - **Séparateur décimal** : **Point (1,234.56)** ou **Virgule (1.234,56)**.
   - **Format de date** : affiché lorsque le fichier contient des dates. Modifiez-le si le format détecté est incorrect : `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Une grille **Colonne du fichier**, **Type**, **Exemples** et **Destination**. Modifiez **Destination** pour envoyer une colonne vers un autre champ, ou vers **Ne pas charger**.

4. Répondez aux questions que soulève le fichier, telles que **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** ou **Are revenues shown as negative numbers?** Chacune n'est posée que lorsque le fichier ne l'indique pas déjà.

5. Vérifiez la destination de chaque colonne, puis cliquez sur **Confirmer la correspondance**.

</Steps>

Ces options apparaissent sur un fichier lorsqu'elles s'appliquent :

| Option | Utilisez-la pour |
|---|---|
| **Which source do these rows apply to?** | Limiter un fichier de correspondance de codes à une seule source. **Every source** l'applique à toutes. |
| **Where does this file come from?** | Indiquer si le fichier contient **This project's own codes** ou provient d'**Another system**, que vous nommez, par exemple `SAP Germany export`. Un fichier issu d'un autre système est contrôlé pour les codes partagés comme une source ERP. |
| **Split … into … parts at each …** (sous **Avancé**) | Scinder une colonne qui contient plusieurs valeurs, comme `100-200-300`, et envoyer chaque partie vers son propre champ. |
| **Which currency do you report in?** | Définir la devise de reporting lorsque le projet n'en a pas encore. Écrivez-la en trois lettres, par exemple `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Charger les résultats de votre système de consolidation afin que le compte de résultat du groupe puisse être [rapproché](#rapprocher-avec-votre-système-de-consolidation). |

Pour retirer un fichier du projet, cliquez sur **Supprimer** à côté de lui sous **Fichiers**, ou sur **Remove this file** dans sa correspondance, puis confirmez. Ses chiffres disparaissent de vos rapports la prochaine fois que vous cliquez sur **Apply changes**.

Lorsque PlaidCloud ne peut pas déterminer seul le jeu de données, le séparateur décimal ou l'ordre des dates, par exemple pour un fichier dont les dates peuvent se lire jour/mois ou mois/jour, il vous demande de choisir avant que vous ne confirmiez. Ajouter un second fichier pour le même jeu de données remplace le premier. Si les colonnes d'un fichier ultérieur ne correspondent pas au jeu de données, le chargement nomme le fichier et les colonnes, et vous demande de corriger le fichier ou le nom de ses colonnes, ou de définir **Schema Mismatch** de l'étape sur `union`.

Les fichiers acceptés sont les fichiers texte CSV, TSV et TXT, les fichiers Excel `.xlsx` (lus à partir de la première feuille) et les fichiers Parquet.

<Aside type="note">
Un fichier manquant ou vide n'interrompt jamais un chargement. Son ajout indique qu'il n'y a encore rien à mettre en correspondance, et un chargement se termine par un avertissement qui nomme le chemin, en laissant ce jeu de données vide. Ajoutez de nouveau le fichier une fois qu'il existe.
</Aside>

## Charger vos données

Cliquez sur **Charger** dans la carte **Charger** ou dans la carte **Dernier chargement**. Le chargement lit votre ERP connecté et vos fichiers confirmés, les harmonise dans le Common Finance Model, les convertit dans la devise de reporting, exécute les contrôles de préparation et reconstruit les modèles du modèle de projet.

- Un seul chargement à la fois s'exécute pour un projet. Un second clic sur **Charger** ou **Apply changes** indique qu'un chargement est déjà en cours, et vous ne pouvez pas modifier les sources pendant qu'il s'exécute.
- Si d'autres workflows utilisent la même connexion ERP, le premier chargement les liste et vous demande de confirmer, car un chargement lit l'ERP et peut ralentir ces workflows. Cliquez sur **Charger quand même** pour poursuivre.
- Après une mise à niveau de PlaidCloud, le **Charger** d'un Architecte met aussi à jour les workflows générés du projet, en créant les tables de travail dont ils ont besoin. D'ici là, la page de statut affiche un élément en orange : « The workflows were generated by an earlier release. An Architect's Load updates them. », et le **Charger** d'un Manager avertit que seul un Architecte peut les mettre à jour.
- Un chargement en échec s'affiche en rouge et ne se cache jamais derrière des résultats antérieurs. Si la consolidation échoue, l'état nomme l'étape où elle s'est arrêtée au lieu d'afficher d'anciens résultats de groupe. Les lignes d'un chargement précédent affichent **Issu d'un chargement précédent. Rechargez.** jusqu'à ce qu'un chargement réussisse.
- Si la lecture d'une entité et d'une période échoue, le reste est tout de même chargé. Exécutez **Charger** de nouveau pour ne récupérer que ce qui a échoué.

### Lignes retenues

Lorsque des sources se recoupent, un chargement conserve une seule copie de chaque chiffre et retient les autres au lieu de les compter deux fois. Les lignes retenues sont enregistrées avec leur source, leur entité et la raison, et le chargement se termine par un avertissement qui indique les nombres, par exemple `120 rows of NetSuite EU also provided by a source ranked ahead`. Les raisons sont les suivantes :

| Raison | Signification |
|---|---|
| In another accounting book | La ligne appartient à un livre de reporting que la source n'est pas configurée pour lire. |
| Outside the periods the source provides | La ligne se situe en dehors des mois **De** et **À** définis pour la société. |
| Also provided by a source ranked ahead | Une source située plus haut dans l'ordre couvre la même société et le même mois. |
| Also in an earlier file of the source | Un fichier antérieur de la même source couvre déjà le mois. |
| Replaced by a file | Un fichier remplace les lignes de l'ERP pour cette entité et ce mois. |
| Carrying a code another source also uses | Le code attend votre réponse. Voir [Faire correspondre les codes entre les sources](#faire-correspondre-les-codes-entre-les-sources). |
| Carrying a code mapped to two codes | La table de correspondance de codes donne deux réponses au code. |

Les comptes statistiques passent dans les inducteurs d'allocation plutôt que dans le grand livre, et sont signalés comme déplacés, et non comme un problème.

### Données ERP et fichiers ensemble

Un fichier ne remplace que ce qu'il couvre, et les autres lignes de votre ERP sont conservées.

- Les **fichiers de données de base** (comptes, départements, clients, produits et Valeurs de segment) remplacent les lignes de l'ERP portant le même code.
- Les **fichiers de transactions** remplacent les lignes de l'ERP pour la même entité et le même mois. Les fichiers de grand livre et de balance générale correspondent aussi par registre, les fichiers de budget par scénario, et les fichiers d'inducteurs statistiques par scénario et par inducteur.

Si un fichier cesse plus tard de couvrir un mois, les données de l'ERP pour ce mois reviennent au chargement suivant.

## Correspondance des entités

Chaque source nomme ses entités avec ses propres codes. La **Correspondance des entités** fait correspondre ces codes aux entités de votre référentiel d'entités, de sorte que les lignes de toutes les sources atterrissent sur la même entité.

Pour en utiliser une, ajoutez un fichier CSV ou Excel et choisissez le jeu de données **Correspondance des entités** :

| Colonne | Contenu |
|---|---|
| `source_entity` | Le code tel que la source le porte, comme un code de société. |
| `entity` | L'entité à laquelle il appartient, telle que le référentiel d'entités la nomme. |

- Un code qui ne figure pas dans la correspondance est utilisé tel quel.
- Plusieurs codes peuvent correspondre à une même entité. Leurs lignes sont combinées, et un mois est considéré comme clôturé une fois qu'il est clôturé pour chacun d'eux.
- Les codes de la correspondance s'appliquent à toutes les sources ; les codes d'entité de chaque source doivent donc être uniques entre les sources.
- Une ligne du fichier **Entités** remplace l'entité de l'ERP portant le même code d'entité.

Le contrôle **Entités non mappées** signale toute ligne dont l'entité ne figure ni dans le référentiel d'entités ni dans la correspondance des entités. Tant qu'aucun référentiel d'entités n'est chargé, il affiche **– Sans objet**.

## Faire correspondre les codes entre les sources

Deux sources peuvent utiliser le même code pour des choses différentes, ou des codes différents pour la même chose. Lorsqu'un code apparaît dans plusieurs sources, Data Foundation retient ses lignes jusqu'à ce que vous indiquiez s'il signifie la même chose partout, afin que chaque montant ne soit compté qu'une fois. Le contrôle **Codes waiting for your answer** les liste, les 10 premiers puis « et K autres », et la carte **What to do next** de l'onglet **Foundation** comporte un bouton **À examiner**.

**À examiner** ouvre **Codes waiting for your answer**. Il regroupe les codes selon leur nature : **Account types**, **Companies**, **Accounts**, **Departments**, **Profit centers**, **Customers**, **Products** et chaque catégorie supplémentaire. Pour chaque code, il affiche le nom que lui donne chaque source et une suggestion :

- **Looks like the same thing** lorsque les sources donnent le même nom au code.
- **Looks like different things** lorsque les noms diffèrent.
- **We can't tell. Please answer.** lorsqu'il n'y a aucun élément pour trancher.

Répondez code par code avec **Yes, the same** ou **No, different**, ou répondez à tout un groupe à la fois avec **Accept all** (accepter toutes les suggestions), **All the same** ou **All different**. Pour les comptes, vous pouvez aussi répondre pour tout un groupe parent du plan comptable à la fois. Lorsqu'une source ne porte aucun type de compte, choisissez **Use this type** pour un groupe de comptes : **Revenue**, **Cost of goods sold**, **Operating expenses**, **Non-operating income and expenses**, **Assets**, **Liabilities** ou **Equity**.

Les correspondances sont conservées par source et par dimension ; une réponse donnée pour les départements d'une source ne modifie donc jamais les comptes d'une autre source. Les réponses sont enregistrées au fur et à mesure, avec **Saved. Press Apply changes to use your answers.** Cliquez sur **Apply changes** pour les utiliser.

Vous pouvez aussi fournir les correspondances dans un fichier. Ajoutez un fichier avec le jeu de données **Code map**, et choisissez **Which source do these rows apply to?** pour le limiter à une seule source.

## Choisir quelle source compte à partir de quand

Lorsque deux sources fournissent les mêmes mois, le contrôle **Which source covers which months** vous demande de choisir. Cliquez sur **Choose which source counts from when** dans la carte **What to do next** pour ouvrir **Which source counts from when**, qui liste chaque chevauchement par société. Choisissez la source qui compte, saisissez le mois à partir duquel elle compte dans **That month is**, par exemple `2026-04`, puis cliquez sur **Apply changes**. L'autre source conserve les mois antérieurs.

La même boîte de dialogue vous avertit lorsque deux sources donnent des taux de change différents pour une devise ; les taux de la source située plus haut dans l'ordre sont utilisés.

## Conversion de devises

Chaque chargement convertit les montants du grand livre, de la balance générale, des ventes, des stocks et des budgets de leur devise locale vers une seule devise de reporting. Les rapports et les modèles lisent les montants convertis, de sorte que les entités en devises différentes, issues de n'importe quel système, se totalisent correctement.

### La devise de reporting

Pour choisir la devise de reporting, définissez la variable de projet `reporting_currency` sur un code de devise tel que `USD`. Voir [Gérer les variables de projet](/fr/guides/projects/managing-projects/#gestion-des-variables-du-projet). Le modèle la crée vide. Tant qu'elle est vide, chaque chargement utilise la première des options suivantes qui désigne exactement une devise :

1. La devise du groupe des entités.
2. La devise locale des entités de premier niveau, celles qui n'ont pas de parent.
3. La devise locale des fichiers.

Si aucune ne désigne exactement une devise, **Conversion de devises** affiche un problème jusqu'à ce que vous définissiez `reporting_currency`.

Les montants déjà dans la devise de reporting restent tels quels ; un projet dont toutes les données sont dans une seule devise n'a donc besoin d'aucun taux.

Les fichiers de ventes, de stocks et de budgets peuvent aussi porter une devise. Associez une colonne nommée `Currency` ou `Local Currency` et elle est prise en compte automatiquement, et les montants locaux du fichier sont convertis dans la devise de reporting. Un montant de groupe ou de reporting déjà présent dans le fichier est conservé tel quel. Le coût standard des produits n'est pas converti.

### Taux de change

Un taux convertit une unité d'une devise dans la devise de reporting pour un mois : le montant converti est le montant local multiplié par le taux.

- **À partir de votre ERP**, chaque chargement lit les taux de change que l'ERP contient.
- **À partir d'un fichier**, ajoutez un fichier CSV ou Excel et choisissez le jeu de données **Taux de change**. Un taux du fichier remplace le taux de l'ERP pour les mêmes devises et le même mois. Utilisez un fichier pour faire du reporting dans une devise dans laquelle vos ERP ne publient pas de taux, ou pour ajouter des taux prévisionnels pour les mois budgétés.

| Colonne | Contenu |
|---|---|
| `from_currency` | La devise à convertir, par exemple `EUR`. |
| `to_currency` | La devise de reporting, par exemple `USD`. |
| `period` | Le mois, sous la forme `YYYY-MM`. |
| `average_rate` | Le taux moyen du mois. |
| `closing_rate` | Le taux de fin de mois. |
| `historical_rate` | Le taux historique, pour les capitaux propres et pour les comptes configurés sur le taux historique. |

Seuls les taux vers la devise de reporting sont utilisés. Un taux coté dans l'autre sens, de la devise de reporting vers une autre devise, n'est pas inversé.

### Quel taux s'applique

Chaque ligne est convertie à partir de sa propre devise ; une ligne dans une devise différente de celle de son entité est donc convertie à partir de la devise dans laquelle elle se trouve. La première règle qui correspond à la ligne s'applique :

| Ligne | Taux |
|---|---|
| Comptes statistiques et comptes sans écriture | Non convertis. |
| Déjà dans la devise de reporting | Non convertie. |
| Compte avec un type de taux | Ce taux : moyen, de clôture ou historique. Le taux historique se rabat sur le taux de clôture lorsqu'il n'existe pas de taux historique. Depuis un ERP, le type de taux est celui du compte lui-même. Dans un fichier de plan comptable, associez une colonne de type de taux à `fx_rate_type` avec `average`, `closing` ou `historical`. |
| Ligne de vente | Le taux moyen de la période. |
| Solde de stock | Le taux de clôture de la période. |
| Ligne de budget | Par compte, comme le grand livre : le taux moyen pour les comptes de produits et charges et le taux de clôture pour les comptes de bilan. |
| Compte de produits et charges | Le taux moyen de la période. |
| Compte de capitaux propres | Le taux historique, ou le taux de clôture lorsqu'il n'existe pas de taux historique. |
| Tout autre compte de bilan | Le taux de clôture de la période. |

Les montants convertis ne sont pas arrondis, afin que les totaux ne dérivent pas.

<Aside type="note">
La balance générale contient les mouvements de chaque période ; les montants de bilan sont donc les mouvements de chaque mois convertis au taux de clôture de ce mois. Il ne s'agit pas d'un bilan reconverti au taux de fin de période, et il n'y a ni écart de conversion cumulé ni élimination intercompagnies. Utilisez les montants convertis pour le compte de résultat.
</Aside>

## Hiérarchies

Chaque chargement reconstruit les dimensions à partir des données de base de chaque source. Il y a sept dimensions au départ, et jusqu'à dix catégories supplémentaires :

| Dimension | Construite à partir de |
|---|---|
| **Entité** | Les entités et leurs parents |
| **Compte** | Le plan comptable et les comptes parents |
| **Département** | Les départements et leurs parents |
| **Client** | Les clients et leurs clients parents |
| **Produit** | Les produits et leurs produits parents |
| **Segment 1** | Les valeurs de segment pour `segment_1` |
| **Segment 2** | Les valeurs de segment pour `segment_2` |
| **Segment 3** à **Segment 10** | Les valeurs de segment pour `segment_3` à `segment_10`, lorsque vos sources en portent |

- Un enregistrement sans parent, ou qui se nomme lui-même comme parent, est chargé comme membre de premier niveau.
- Comme chaque chargement reconstruit les hiérarchies, modifiez un parent dans l'ERP ou dans votre fichier, pas dans la dimension.
- Un problème dans une hiérarchie n'affecte que cette dimension. Le chargement et les modèles du modèle de projet se terminent tout de même.
- Vous pouvez renommer chaque catégorie supplémentaire selon ce qu'elle contient, par exemple **Classe** ou **Région**. Sous **Rename extra categories**, saisissez les noms qu'utilisent vos rapports et cliquez sur **Save names**. Les noms utilisent des lettres, des chiffres, des espaces, des points, des tirets et des tirets bas, jusqu'à 60 caractères.
- Chaque source indique sous lequel de vos noms de catégorie va chacune de ses propres catégories supplémentaires. Ouvrez **Avancé** sur la source, choisissez le nom de chacune, ou choisissez **Leave out**, puis cliquez sur **Enregistrer**. Les sources qui appellent une catégorie par des noms différents, comme `Class` et `Business area`, partagent alors un seul emplacement.

Pour fournir des hiérarchies de segments à partir d'un fichier, choisissez le jeu de données **Valeurs de segment** :

| Colonne | Contenu |
|---|---|
| `segment` | Le segment auquel appartient la valeur : `segment_1` à `segment_10`. |
| `segment_value` | La valeur, telle que les lignes de grand livre, de ventes et de budget la portent. |
| `segment_value_name` | Son nom. |
| `parent_segment_value` | Son parent dans le même segment. |

## Contrôles de préparation

Après chaque chargement, la grille **Préparation** liste chaque contrôle pour chaque entité et chaque période, avec l'un de ces statuts :

| Statut | Signification |
|---|---|
| **● Prêt** | Le contrôle a réussi. |
| **▲ À examiner** | Mérite un coup d'œil, mais les chiffres sont utilisables. |
| **■ Problème** | À corriger avant de vous fier aux résultats. |
| **– Sans objet** | Il n'y a pas encore de données pour ce contrôle. |

Les contrôles sont les suivants :

| Contrôle | Ce qu'il confirme |
|---|---|
| **Données chargées** | Chaque période fiscale comporte des lignes de grand livre, et chaque lecture de l'ERP a réussi. Une période clôturée sans ligne est un problème ; une période ouverte sans ligne nécessite une attention. |
| **La balance de vérification concorde avec le grand livre** | La balance générale est égale au grand livre pour chaque entité, période et compte. Lorsque la balance générale et le grand livre portent tous deux des départements pour un compte, il vérifie aussi la concordance de chaque département. |
| **Les ventes concordent avec le grand livre** | Les lignes de vente sont égales aux comptes de chiffre d'affaires et de coût des marchandises vendues du grand livre pour chaque période. |
| **Produits/clients inconnus** | Chaque ligne de vente nomme un produit et un client qui existent dans les référentiels de produits et de clients. |
| **Comptes absents du plan comptable** | Chaque ligne de grand livre nomme un compte du plan comptable. Les lignes dont le compte est inconnu sont exclues du compte de résultat. Un compte comportant des écritures mais sans type de compte est aussi un problème, et une source dont le plan comptable type des comptes de produits mais aucun compte de coût des ventes demande votre attention. |
| **Conversion de devises** | Chaque ligne de grand livre, de balance générale, de ventes, de stocks et de budget a un montant dans la devise de reporting. Une ligne de compte de résultat ou de ventes sans taux est un problème, car le compte de résultat lit les montants convertis. Une ligne de bilan, de stocks ou de budget sans taux nécessite une attention. Un mois de budget sans taux apparaît en orange ; chargez donc des taux prévisionnels pour les mois budgétés. Voir [Conversion de devises](#conversion-de-devises). |
| **Entités non mappées** | Chaque ligne de grand livre, de balance générale et de ventes nomme une entité du référentiel d'entités, directement ou par la correspondance des entités. Sans objet tant qu'aucun référentiel d'entités n'est chargé. Voir [Correspondance des entités](#correspondance-des-entités). |

Les chargements comportant plus d'une source ajoutent ces contrôles :

| Contrôle | Ce qu'il confirme |
|---|---|
| **Reporting book** | Une source qui tient plusieurs livres comptables pour une entité s'est vu attribuer son livre de reporting. Tant que vous n'en choisissez pas un, seul le premier livre compte. |
| **Codes waiting for your answer** | Chaque code utilisé par plusieurs sources a reçu une réponse. Voir [Faire correspondre les codes entre les sources](#faire-correspondre-les-codes-entre-les-sources). |
| **Extra categories from your sources** | Chaque catégorie supplémentaire portée par une source a un nom ou a été exclue. |
| **Which source covers which months** | Aucune paire de sources ne fournit les mêmes mois d'une société, sauf si vous avez choisi laquelle compte. |
| **Account types and hierarchy** | Chaque parent nommé par une dimension existe, et aucun membre n'est son propre parent ni son propre ancêtre. Un parent manquant place ses enfants au sommet de la hiérarchie, et une boucle empêche cette hiérarchie de se charger. Les totaux ne sont pas affectés. |
| **Calendrier fiscal** | Les périodes fiscales de chaque entité sont des mois civils, et chaque mois de lignes peut être placé dans une seule période fiscale. Cela demande votre attention lorsque les périodes d'une entité ne sont pas des mois civils (4-4-5, 13 périodes), ou lorsque les lignes d'un mois pourraient relever de plusieurs périodes fiscales ou que le calendrier fiscal n'a pas ce mois. |

Chaque ligne qui n'est pas prête indique la marche à suivre dans la colonne **Que faire**, par exemple charger le plan comptable, charger les taux de change ou exécuter de nouveau **Charger** pour une période.

La grille affiche aussi deux contrôles de configuration, qui n'apparaissent que lorsqu'ils nécessitent une attention :

| Contrôle | Quand il apparaît |
|---|---|
| **Répartition des frais généraux** | Une seule des variables de projet `overhead_department` et `overhead_driver` est définie, ou aucun inducteur d'allocation ne correspond à `overhead_driver`, de sorte que l'allocation ne ferait rien. Définissez les deux, ou videz les deux pour désactiver la répartition des frais généraux. |
| **Comparaison budgétaire** | Des lignes de budget sont chargées, mais aucune ne se trouve dans la version que nomme la variable de projet `budget_version`, de sorte que la comparaison budgétaire serait vide. |

## Consolidation de gestion

Chaque chargement construit une consolidation de gestion : le compte de résultat du groupe de toutes les entités du groupe, dans la devise de reporting, avec les opérations intercompagnies éliminées. Elle est destinée au reporting de gestion. Votre système de consolidation reste la référence pour le groupe statutaire ; rapprochez-vous-en comme décrit plus bas.

<Aside type="note">
La consolidation de gestion ne couvre que le compte de résultat. Ce n'est pas une consolidation statutaire ou légale, et elle ne comporte ni bilan consolidé, ni écart de conversion, ni goodwill, ni intérêts minoritaires.
</Aside>

### Choisir le groupe

Sous **Sources**, ouvrez **Groupe** pour voir les sociétés du groupe. Une société que vous décochez reste dans vos rapports à titre individuel, mais est exclue du total du groupe. Cliquez sur **Save group**. La modification s'applique au prochain **Charger** ou **Apply changes**. Une nouvelle société fait partie du groupe tant que vous ne la décochez pas.

L'exercice fiscal du groupe commence au mois défini par la variable de projet `group_fy_start_month`, qui vaut `1` sauf modification.

### Ce que vous obtenez

| Table | Contenu |
|---|---|
| **Compte de résultat du groupe** | Une ligne par entité, période et poste (chiffre d'affaires, coût des marchandises vendues, charges d'exploitation, hors exploitation, écart intercompagnies), dans la devise de reporting. Le chiffre d'affaires et les coûts conservent leur signe naturel. |
| **Compte de résultat du groupe cumulé depuis le début de l'exercice** | La même chose, cumulée depuis le début de l'exercice, jusqu'à la dernière période entièrement chargée du groupe. |
| **Paires intercompagnies** | Une ligne par paire d'entités, groupe et période, avec le montant de chaque côté et le résidu. |
| **Lignes intercompagnies** | Les lignes du grand livre derrière un chiffre du groupe ou une paire, avec le partenaire commercial. |
| **Rapprochement** | Le compte de résultat du groupe cumulé depuis le début de l'exercice, comparé à votre système de consolidation. |

Trois noms d'entité apparaissent dans ces tables :

| Entité | Signification |
|---|---|
| **Éliminations** | Les éliminations intercompagnies. Elles s'annulent à zéro ; laissez-les donc pour les chiffres du groupe et filtrez-les pour obtenir la somme des entités avant élimination. |
| **Total du groupe** | Le total du système de consolidation, dans le rapprochement. |
| **Non mappé** | Les lignes sans période, et les comptes ou entités de votre système de consolidation que ce projet n'a pas. |

Les métriques « Revenu consolidé », « Résultat consolidé » et « Écart intercompagnies », ainsi qu'un chemin d'analyse pour chaque table, répondent aux questions sur le groupe.

### Éliminations intercompagnies

Les lignes intercompagnies sont appariées par partenaire commercial. Le partenaire porté par la ligne est utilisé ; lorsqu'une ligne n'en a pas, c'est celui de son client. Les deux côtés d'une paire sont éliminés, et le montant dont les deux côtés ne concordent pas est comptabilisé sur une ligne d'écart intercompagnies. Chaque paire reçoit une raison :

| Raison | Signification |
|---|---|
| **Correspondant** | Les deux côtés ont comptabilisé le même montant. |
| **Only one side booked** | Une entité a comptabilisé la transaction et son partenaire ne l'a pas fait. |
| **Not eliminated** | Une ligne de la paire n'a pas de taux de change ; aucun des deux côtés n'est donc éliminé. |

Une paire est jugée sur son cumul depuis le début de l'exercice. La ligne **Intercompany balances** passe en orange lorsque l'écart d'une paire dépasse la variable de projet `group_amber` (`1` par défaut) et en rouge au-delà de `group_red` (`1000` par défaut). Les lignes sans partenaire, ou avec un partenaire qui n'est pas une entité, ne sont pas éliminées et sont comptées sur cette ligne. Une source qui porte des partenaires à côté d'une qui n'en porte pas apparaît en orange.

Les entités d'élimination propres à une source restent hors du compte de résultat du groupe, et la ligne **Consolidation** le signale.

### Rapprocher avec votre système de consolidation

Ajoutez sous forme de fichier les résultats que rapporte votre système de consolidation, et cochez **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** lorsque vous confirmez sa correspondance. Répondez à **Which version of the numbers is this?** avec le nom du système. La table **Rapprochement** affiche alors **ours**, **reported** et **écart** pour chaque entité et chaque poste, cumulés depuis le début de l'exercice. Un écart s'explique généralement sur les lignes **Éliminations**, **Total du groupe** et **Non mappé**, ou par les taux de change qu'utilise le système. La ligne **Reconciliation to the source** liste chaque poste dépassant `group_amber`.

### Qui peut le voir

Les résultats du groupe suivent l'accès aux lignes du projet. Lorsque l'accès aux lignes bloque les résultats du groupe, l'état s'affiche en orange. Une personne qui ne voit que certaines entités voit les sommes de ces entités avant élimination. Les lignes **Éliminations** et les tables intercompagnies exigent l'accès à toutes les entités.

Si le projet limite les lignes visibles par une colonne que les tables du groupe ne portent pas, comme le département, les résultats du groupe restent désactivés pour tout le monde et **Consolidation** indique **Group views are off**. Seul un Architecte peut alors cocher **Everyone on the project may see the group results** sous **Groupe**. La modification s'applique au prochain **Charger** ou **Apply changes**.

## Garder les données à jour

Lorsqu'un chargement depuis votre connexion ERP réussit sans aucun problème, **Actualiser chaque nuit** apparaît sur la carte **Dernier chargement**. Cliquez dessus pour exécuter **Charger** chaque nuit à 2 h 00 dans votre fuseau horaire. La carte affiche alors **Nightly refresh: Every night at 2:00** et la personne qui l'a configuré.

Le chargement nocturne s'exécute au nom de la personne qui l'a configuré. Si cette personne ne peut plus utiliser la connexion ERP, la grille indique que le chargement nocturne est ignoré ; configurez-le de nouveau. Un projet qui n'a que des données d'exemple ne peut pas être planifié.

Un fichier manquant ou vide lors d'un chargement nocturne se termine par un avertissement qui nomme le chemin, et non par une erreur, et le reste du modèle est tout de même chargé.

## Construire sur le modèle avec un modèle de projet

Un modèle de projet construit ses rapports et ses modèles sur le Common Finance Model, de sorte qu'ils fonctionnent de la même façon quels que soient les ERP qui l'alimentent. Lorsque vous démarrez un projet à partir d'un modèle, tel que **Rentabilité de l'entreprise**, il crée :

- Les [tables du Common Finance Model](#tables-du-common-finance-model), vides ou remplies de données d'exemple.
- Les dimensions **Entité**, **Compte**, **Département**, **Client**, **Produit**, **Segment 1** et **Segment 2** construites à partir de ces tables. Voir [Hiérarchies](#hiérarchies).
- Le workflow **Charger** et les workflows qu'il exécute pour lire votre ERP et vos fichiers, les harmoniser, vérifier la préparation et construire les modèles du modèle de projet.
- Les rapports et modèles propres au modèle de projet. **Rentabilité de l'entreprise** ajoute une table de compte de résultat avec le chiffre d'affaires, le coût des marchandises vendues, la marge brute, les charges d'exploitation directes et indirectes, la contribution et la marge d'exploitation, ainsi que des passerelles de marge d'une année sur l'autre et par rapport au budget.
- Des métriques et un chemin d'analyse pour poser des questions sur les résultats.

Pour explorer avant de connecter votre propre ERP, cochez **Commencer avec des données d'exemple** lorsque vous créez le projet. Le projet exécute immédiatement un premier chargement, de sorte que l'onglet **Foundation** affiche un exemple complet, y compris une entité en euros convertie en dollars américains. Lorsque vous connectez votre propre ERP ou ajoutez vos propres fichiers, les lignes d'exemple sont effacées et vos données prennent leur place.

## Tables du Common Finance Model

Data Foundation harmonise chaque source, ERP ou fichier, dans les mêmes quinze tables, de sorte que les rapports, les métriques et les modèles construits dessus fonctionnent de la même façon quelle que soit la source. Chaque ligne enregistre aussi son système source et le moment où elle a été lue. La colonne **Jeu de données** est le nom que vous choisissez lorsque vous ajoutez un fichier.

| Jeu de données | Table | Contenu |
|---|---|---|
| Entités | `cfm_entity` | Entités juridiques avec parent, devise locale et devise du groupe, et pays. |
| Correspondance des entités | `cfm_entity_map` | Codes d'entité source et entité à laquelle chacun appartient. Voir [Correspondance des entités](#correspondance-des-entités). |
| Taux de change | `cfm_fx_rate` | Taux mensuels moyen, de clôture et historique par paire de devises. Voir [Taux de change](#taux-de-change). |
| Calendrier fiscal | `cfm_fiscal_calendar` | Une ligne par période fiscale d'entité, avec les dates de début et de fin et l'indication de clôture. |
| Plan comptable | `cfm_account` | Comptes avec parent, type (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), état, solde normal et type de taux. |
| Départements | `cfm_department` | Départements et centres de coûts avec parent et centre de profit. |
| Produits | `cfm_product` | Référentiel de produits avec parent, famille, groupe, unité de mesure et coût standard. |
| Clients | `cfm_customer` | Référentiel de clients avec parent, groupe, région et pays. Les noms de clients ne sont pas masqués. |
| Valeurs de segment | `cfm_segment` | Valeurs de segment avec nom et parent. Voir [Hiérarchies](#hiérarchies). |
| Grand livre | `cfm_gl_journal` | Lignes de journal en devise de transaction, locale et de reporting. |
| Balance de vérification | `cfm_trial_balance` | Débits, crédits et net de période par entité, compte et département, en devise locale et de reporting. |
| Lignes de vente | `cfm_sales_line` | Lignes de vente facturées avec quantité, montants brut, remise, net et coût des marchandises vendues. |
| Soldes de stock | `cfm_inventory_balance` | Stock de fin de période par produit et par entrepôt. |
| Budget | `cfm_budget` | Budget et prévision par scénario, version, compte et département. |
| Inducteurs d'allocation | `cfm_stat_driver` | Inducteurs statistiques tels que l'effectif, la surface en pieds carrés ou les unités. |

Les périodes s'écrivent `YYYY-MM`, et les transactions sont placées selon la période de comptabilisation. Le budget est facultatif : un ERP sans budgets charge tout le reste.

Un fichier de balance générale peut porter des colonnes de débit et de crédit, une colonne de net, ou les deux. Avec seulement le débit et le crédit, le net est le débit moins le crédit, et un côté vide compte pour zéro. Avec seulement un net, un net positif devient le débit et un net négatif devient le crédit, sous forme de montant positif. Une colonne de département est facultative.

## Dépannage

| Symptôme | Que faire |
|---|---|
| **Tester la connexion** indique que l'ERP a refusé les identifiants | Vérifiez les identifiants de la connexion, et que l'utilisateur d'intégration peut se connecter à l'ERP. |
| **Tester la connexion** affiche **Autorisation manquante** pour un jeu de données | Demandez à l'administrateur de votre ERP d'ajouter les autorisations qu'elle nomme. Le [guide de connexion](/fr/guides/connections/) de votre ERP liste ce dont la connexion a besoin. |
| Un message d'erreur de l'ERP est plus court que celui de l'ERP lui-même | PlaidCloud supprime les identifiants, les jetons et les clés des erreurs des fournisseurs avant de les afficher, si bien que certains détails sont omis. Exécutez **Tester la connexion** pour voir quel jeu de données est concerné. |
| **Données chargées** est un problème pour une période | Une lecture de l'ERP pour cette période a échoué. Exécutez **Charger** de nouveau ; les périodes déjà chargées sont ignorées. |
| **Comptes absents du plan comptable** est un problème | Ajoutez les comptes manquants au plan comptable dans l'ERP ou dans votre fichier, puis exécutez **Charger** de nouveau. |
| **Conversion de devises** est un problème | La devise d'une entité n'a pas de taux vers la devise de reporting pour cette période, ou aucune devise de reporting unique n'a été trouvée. Ajoutez les taux dans un fichier **Taux de change**, vérifiez que la connexion peut lire les taux de change de l'ERP, ou définissez la variable de projet `reporting_currency`. Exécutez ensuite **Charger** de nouveau. |
| **Conversion de devises** nécessite une attention | Des lignes de bilan, de stocks ou de budget n'ont ni taux de clôture, ni taux historique, ni taux prévisionnel pour la période. Le compte de résultat n'est pas affecté. Ajoutez les taux, y compris les taux prévisionnels pour les mois budgétés, puis exécutez **Charger** de nouveau. |
| **Codes waiting for your answer** nécessite une attention | Cliquez sur **À examiner**, répondez pour chaque code, puis cliquez sur **Apply changes**. |
| **Which source covers which months** nécessite une attention | Cliquez sur **Choose which source counts from when**, choisissez la source, puis cliquez sur **Apply changes**. |
| **Intercompany balances** est rouge ou orange | Vérifiez les paires dans **Paires intercompagnies**. Comptabilisez le côté manquant, ajoutez le partenaire commercial aux lignes, ou ajoutez le taux manquant. |
| **Group views are off** | Demandez à un Architecte de cocher **Everyone on the project may see the group results** sous **Groupe**. |
| **Entités non mappées** est un problème | Ajoutez l'entité au référentiel d'entités, ou faites correspondre son code à une entité existante dans le fichier **Correspondance des entités**, puis exécutez **Charger** de nouveau. |
