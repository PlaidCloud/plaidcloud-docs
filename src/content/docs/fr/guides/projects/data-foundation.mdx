**Data Foundation** est le socle de données financières de vos projets PlaidCloud. Son **Common Finance Model** rassemble les données de plusieurs systèmes ERP, et de plusieurs instances de chacun, dans un modèle unique : un seul plan comptable, un seul ensemble d'entités et une seule devise de reporting. Les rapports, les métriques et les assistants IA construits sur le modèle lisent tous les mêmes chiffres, quel que soit l'ERP d'origine.

Votre ERP se connecte par sa connexion PlaidCloud : le grand livre, la balance générale, les données de base et les budgets arrivent donc directement de la source, sans rien à exporter. Les fichiers ajoutent les données qu'un système ne contient pas, comme les taux de change, les inducteurs d'allocation ou un budget tenu hors de l'ERP, et peuvent remplacer les lignes de l'ERP qu'ils couvrent. **Charger** met chaque source en conformité avec le modèle, la convertit dans la devise de reporting et vérifie qu'elle concorde, le tout depuis l'onglet **Foundation** du projet. Lorsque des sources utilisent le même code pour des choses différentes, vous indiquez si elles désignent la même chose, et une consolidation de gestion construit le compte de résultat de groupe avec les opérations intersociétés éliminées. Les modèles, tels que **Enterprise Profitability**, construisent leurs rapports et leurs modèles par-dessus.

## Connecter votre ERP

Votre ERP se connecte à Data Foundation par sa connexion PlaidCloud. Data Foundation lit directement par elle le grand livre, la balance générale, les données de base, les taux de change et les budgets, et ne fait jamais que lire. Vous pouvez choisir une connexion existante ou en créer une dans l'onglet. Chaque système a une page destinée à l'administrateur qui accorde l'accès, listée dans [Les systèmes qui peuvent alimenter le modèle](/fr/guides/projects/data-foundation-getting-started/#les-systèmes-qui-peuvent-alimenter-le-modèle), et la [matrice de couverture de Data Foundation](/fr/reference/data-foundation-coverage-matrix/) indique les jeux de données que chaque système fournit directement.

<Steps>

1. Dans Analyze, ouvrez **Projets** et cliquez sur **Nouveau projet**. Saisissez un nom et, sous **Partir de**, choisissez un modèle, tel que **Rentabilité de l'entreprise (modèle)**, au lieu de **Projet vierge**. Cliquez sur **Créer**.

   Le projet s'ouvre sur son onglet **Foundation**. Il vous est privé, et vous en êtes le seul Architecte, tant que vous ne le partagez pas.

2. Dans l'onglet **Foundation**, choisissez une connexion existante pour votre ERP, ou **Créer une nouvelle connexion**. Chaque connexion existante liste les workflows qui l'utilisent déjà, ou indique **Pas encore utilisé par un workflow**.

3. Pour une nouvelle connexion, saisissez un **Nom de la connexion**, choisissez l'**Environnement** et renseignez les identifiants que demande la connexion à votre ERP.

   Vous n'avez pas encore les identifiants ? Le formulaire affiche une demande d'accès prête à l'emploi pour l'administrateur de votre ERP. Cliquez sur **Copier la demande** ou **Envoyer la demande par e-mail**, envoyez-la, puis saisissez les valeurs qu'il vous renvoie.

4. Cliquez sur **Tester la connexion**. PlaidCloud se connecte et tente de lire chaque jeu de données, puis indique pour chacun **Lisible**, **Autorisation manquante** ou **Erreur**. Lorsqu'il manque quelque chose, il nomme les autorisations à demander à l'administrateur de votre ERP d'ajouter.

5. Définissez **Mois d'historique** : le nombre de mois à charger en remontant dans le passé, de 1 à 120. La valeur par défaut est 24.

6. Pour une connexion existante, cochez les entités à charger, ou laissez-les toutes décochées pour charger toutes les entités. Les entités inactives et les entités d'élimination restent masquées tant que vous ne choisissez pas de les afficher. Cliquez ensuite sur **Connecter**.

7. Pour une nouvelle connexion, cliquez sur **Connecter** pour la créer. Cochez ensuite les entités à charger et cliquez de nouveau sur **Connecter** pour les enregistrer. Tant que vous ne le faites pas, toutes les entités sont chargées.

8. Pour intégrer un autre système ERP ou une autre instance, répétez ces étapes et cochez **Add this as another source instead of replacing the current one** avant de cliquer sur **Connecter**. Sans cette option, la nouvelle connexion remplace la source actuelle.

</Steps>

Une fois la connexion établie, la carte indique la connexion, l'environnement, les entités et les mois d'historique que le projet charge.

Chaque chargement ne lit que ce qui a changé : les périodes ouvertes et la dernière période clôturée sont relues, et les périodes clôturées déjà chargées sont conservées. Augmenter **Mois d'historique** ne lit que les mois ajoutés. Un taux de change, une correspondance d'entités ou une devise de reporting modifié relit les mois qu'il touche.

## Sources

Chaque système et chaque instance ERP depuis lesquels le projet charge des données est une source. La liste **Sources** de l'onglet **Foundation** affiche une ligne pour chacune, dans l'ordre, avec son nom, la date de son dernier chargement et le nombre de lignes fournies, ainsi que les livres de reporting lus, par exemple `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Une source qui n'a pas encore été chargée indique **not loaded yet**. Les fichiers que vous confirmez sont aussi des sources.

Ouvrez **Avancé** sur une source pour modifier la façon dont elle est utilisée :

| Paramètre | Effet |
|---|---|
| **Nom** | Le libellé que les rapports, les questions de correspondance et les messages utilisent pour la source. |
| **Place in the order** | Le rang de la source. Lorsque deux sources couvrent le même mois de la même société, celle qui est plus haut dans l'ordre l'emporte. |
| **Reporting books, separated by commas** | Les livres comptables à lire, pour un système qui en tient plusieurs. **All reporting books** lit tous les livres. |
| **Société**, **From (2026-01)** et **To (2026-12)** | Les mois que cette source fournit pour chaque société. Laissez un mois vide pour ne fixer aucune limite. Écrivez les mois sous la forme année-mois, par exemple `2026-03`. |

Cliquez sur **Enregistrer** pour conserver vos modifications. Pour supprimer une source, cliquez sur **Remove this source** et confirmez avec **Supprimer**. Tout ce qui a été chargé depuis elle est supprimé, et vous pouvez la reconnecter plus tard.

Modifier les sources ne relit pas votre ERP. La carte **Dernier chargement** indique **Changes not applied yet** jusqu'à ce que vous cliquiez sur **Apply changes**, qui exécute un chargement à partir des données déjà extraites : il remet les sources en conformité avec votre nouvel ordre, vos correspondances, vos noms et vos fichiers, puis reconstruit le modèle. Cliquez sur **Charger** lorsque vous voulez aussi des données fraîches des ERP.

## Ajouter des fichiers pour les données extérieures à votre ERP

Les fichiers complètent votre connexion ERP avec des données qu'un système ne contient pas, comme les taux de change, les inducteurs d'allocation, une [correspondance des entités](#correspondance-des-entités) ou un budget tenu hors de l'ERP. Chaque fichier appartient à l'un des jeux de données listés sous [Tables du Common Finance Model](#tables-du-common-finance-model).

<Steps>

1. Sous **Fichiers**, choisissez le **Compte de documents** où stocker le fichier.

2. Déposez un fichier CSV ou Excel sur **Déposez un fichier CSV ou Excel ici**, ou cliquez sur **Choisir un fichier**. Le fichier est téléversé dans le dossier `/foundation/` du compte de documents.

   Pour un fichier déjà présent dans le compte de documents, saisissez son **Chemin du fichier**, par exemple `/foundation/budget.csv`, et cliquez sur **Ajouter un fichier**.

   Pour lire chaque mois un nouveau fichier, ajoutez tous les fichiers d'un dossier dont le nom correspond : saisissez le dossier et ce que les **File names that** contiennent, commencent par, finissent par, correspondent exactement ou correspondent comme motif, puis cliquez sur **Add files**. Les fichiers situés dans des dossiers imbriqués ne sont pas lus.

3. PlaidCloud lit le fichier et propose une correspondance :

   - **Detected delimiter, decimal separator and dates.** Le délimiteur (virgule, point-virgule, tabulation ou barre verticale), le séparateur décimal et le format de date sont détectés pour vous.
   - **Jeu de données** : la table du Common Finance Model à laquelle appartient le fichier, déterminée d'après le nom du fichier et les en-têtes de colonnes. Lorsque la correspondance n'est pas claire, choisissez-la dans la liste.
   - **Séparateur décimal** : **Point (1,234.56)** ou **Virgule (1.234,56)**.
   - **Format de date** : affiché lorsque le fichier contient des dates. Modifiez-le si le format détecté est incorrect : `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Une grille **Colonne du fichier**, **Type**, **Exemples** et **Destination**. Modifiez **Destination** pour envoyer une colonne vers un autre champ, ou vers **Ne pas charger**.

4. Répondez aux questions que soulève le fichier, telles que **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** ou **Are revenues shown as negative numbers?** Chacune n'est posée que lorsque le fichier ne répond pas déjà.

5. Vérifiez la destination de chaque colonne, puis cliquez sur **Confirmer la correspondance**. Pendant le traitement, la note sous le bouton indique pourquoi il attend. Dans un projet qui contient encore les données d'exemple, le premier fichier que vous confirmez supprime aussi l'exemple, ce qui peut prendre quelques minutes.

</Steps>

Ces options apparaissent sur un fichier lorsqu'elles s'appliquent :

| Option | À utiliser pour |
|---|---|
| **Which source do these rows apply to?** | Limiter un fichier de correspondance de codes à une seule source. **Every source** l'applique à toutes. |
| **Where does this file come from?** | Indiquer si le fichier contient **This project's own codes** ou provient d'**Another system**, que vous nommez, par exemple `SAP Germany export`. Un fichier provenant d'un autre système est contrôlé pour les codes partagés comme une source ERP. |
| **Split … into … parts at each …** (sous **Avancé**) | Scinder une colonne qui contient plusieurs valeurs, comme `100-200-300`, et envoyer chaque partie vers son propre champ. |
| **Which currency do you report in?** | Définir la devise de reporting lorsque le projet n'en a pas encore. Écrivez-la en trois lettres, par exemple `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Charger les résultats de votre système de consolidation afin de pouvoir [rapprocher](#rapprocher-avec-votre-système-de-consolidation) le compte de résultat de groupe. |

Pour retirer un fichier du projet, cliquez sur **Supprimer** à côté de lui sous **Fichiers**, ou sur **Remove this file** dans sa correspondance, et confirmez. Ses chiffres quittent vos rapports la prochaine fois que vous cliquez sur **Apply changes**.

Lorsque PlaidCloud ne peut pas déterminer seul le jeu de données, le séparateur décimal ou l'ordre des dates, par exemple pour un fichier dont les dates peuvent se lire jour/mois ou mois/jour, il vous demande de choisir avant que vous ne confirmiez. Ajouter un second fichier pour le même jeu de données remplace le premier. Si les colonnes d'un fichier ultérieur ne correspondent pas au jeu de données, le chargement nomme le fichier et les colonnes et vous demande de corriger le fichier ou le nom de ses colonnes, ou de définir **Schema Mismatch** de l'étape sur `union`.

Les fichiers acceptés sont les fichiers texte CSV, TSV et TXT, les fichiers Excel `.xlsx` (lus à partir de la première feuille) et les fichiers Parquet.

<Aside type="note">
Un fichier absent ou vide n'interrompt jamais un chargement. Son ajout indique qu'il n'y a encore rien à faire correspondre, et un chargement se termine par un avertissement qui nomme le chemin, en laissant ce jeu de données vide. Ajoutez de nouveau le fichier une fois qu'il existe.
</Aside>

## Charger vos données

Cliquez sur **Charger** dans la carte **Charger** ou dans la carte **Dernier chargement**. Le chargement lit votre ERP connecté et vos fichiers confirmés, les met en conformité avec le Common Finance Model, les convertit dans la devise de reporting, exécute les contrôles de préparation et reconstruit les modèles du modèle de projet.

- Un seul chargement à la fois s'exécute pour un projet. Un second **Charger** ou **Apply changes** indique qu'un chargement est déjà en cours, et vous ne pouvez pas modifier les sources pendant qu'il s'exécute.
- Si d'autres workflows utilisent la même connexion ERP, le premier chargement les liste et vous demande de confirmer, car un chargement lit depuis l'ERP et peut ralentir ces workflows. Cliquez sur **Charger quand même** pour continuer.
- Après une mise à niveau de PlaidCloud, le **Charger** d'un Architecte met aussi à jour les workflows générés du projet, en créant les tables de travail dont ils ont besoin. D'ici là, la page d'état liste un élément orange, « The workflows were generated by an earlier release. An Architect's Load updates them. », et le **Charger** d'un Gestionnaire avertit que seul un Architecte peut les mettre à jour.
- L'application d'une mise à jour conserve vos propres modifications des étapes générées. Si vous avez modifié une étape et que la mise à jour l'a modifiée aussi, votre modification est conservée et la page d'état signale le conflit par le nom de l'étape. Une étape que vous avez modifiée et que la mise à jour ne génère plus est conservée mais désactivée ; supprimez-la, ou réactivez-la si vous en avez encore besoin. Une étape que la mise à jour remplace est nommée, et l'ancienne reste dans les versions de l'étape.
- Si une mise à jour s'est arrêtée en cours de route, ou est encore en cours, la page d'état l'indique, et ses étapes peuvent s'exécuter dans le désordre tant qu'elle n'est pas terminée. Appuyez de nouveau sur **Charger** en tant qu'Architecte pour la terminer. Si elle s'arrête encore, contactez l'assistance.
- Un chargement en échec s'affiche en rouge et ne se cache jamais derrière des résultats antérieurs. Si la consolidation échoue, l'état nomme l'étape où elle s'est arrêtée au lieu d'afficher d'anciens résultats de groupe. Les lignes d'un chargement antérieur affichent **Issu d'un chargement précédent. Rechargez.** jusqu'à ce qu'un chargement réussisse.
- Si la lecture d'une entité et d'une période échoue, le reste se charge quand même. Exécutez de nouveau **Charger** pour ne récupérer que ce qui a échoué.

### Lignes retenues

Lorsque des sources se chevauchent, un chargement conserve une seule copie de chaque chiffre et retient les autres au lieu de les compter deux fois. Les lignes retenues sont enregistrées avec leur source, leur entité et la raison, et le chargement se termine par un avertissement qui nomme les nombres, par exemple `120 rows of NetSuite EU also provided by a source ranked ahead`. Les raisons sont les suivantes :

| Raison | Signification |
|---|---|
| Dans un autre livre comptable | La ligne appartient à un livre de reporting que la source n'est pas configurée pour lire. |
| En dehors des périodes fournies par la source | La ligne tombe en dehors des mois **De** et **À** définis pour la société. |
| Également fournie par une source mieux classée | Une source placée plus haut dans l'ordre couvre la même société et le même mois. |
| Également dans un fichier antérieur de la source | Un fichier antérieur de la même source couvre déjà le mois. |
| Remplacée par un fichier | Un fichier remplace les lignes de l'ERP pour cette entité et ce mois. |
| Carrying a code another source also uses | Le code appelle votre réponse. Voir [Faire correspondre les codes entre les sources](#faire-correspondre-les-codes-entre-les-sources). |
| Carrying a code mapped to two codes | La correspondance de codes donne deux réponses au code. |

Les comptes statistiques passent dans les inducteurs d'allocation plutôt que dans le grand livre, et s'affichent comme déplacés, et non comme un problème.

### Données de l'ERP et fichiers ensemble

Un fichier ne remplace que ce qu'il couvre, et les autres lignes de votre ERP restent.

- Les **fichiers de données de base** (comptes, départements, clients, produits et valeurs de segment) remplacent les lignes de l'ERP portant le même code.
- Les **fichiers de transactions** remplacent les lignes de l'ERP pour la même entité et le même mois. Les fichiers du grand livre et de la balance générale font aussi la correspondance par registre, les fichiers de budget par scénario, et les fichiers d'inducteurs statistiques par scénario et par inducteur.

Si un fichier cesse plus tard de couvrir un mois, les données de l'ERP pour ce mois reviennent au chargement suivant.

## Correspondance des entités

Chaque source nomme ses entités avec ses propres codes. La **Entity crosswalk** fait correspondre ces codes aux entités de votre référentiel d'entités, de sorte que les lignes de chaque source aboutissent sur la même entité.

Pour en utiliser une, ajoutez un fichier CSV ou Excel et choisissez le jeu de données **Entity crosswalk** :

| Colonne | Contenu |
|---|---|
| `source_entity` | Le code tel que la source le porte, comme un code société. |
| `entity` | L'entité à laquelle il appartient, telle que le référentiel d'entités la nomme. |

- Un code absent de la correspondance est utilisé tel quel.
- Plusieurs codes peuvent correspondre à une même entité. Leurs lignes sont combinées, et un mois est considéré comme clôturé dès qu'il l'est pour chacun d'eux.
- Les codes de la correspondance s'appliquent à toutes les sources ; les codes d'entité de chaque source doivent donc être uniques d'une source à l'autre.
- Une ligne d'un fichier **Entités** remplace l'entité de l'ERP portant le même code d'entité.

Le contrôle **Entités non mappées** signale toute ligne dont l'entité ne figure ni dans le référentiel d'entités ni dans la correspondance. Tant qu'aucun référentiel d'entités n'est chargé, il affiche **– Sans objet**.

## Faire correspondre les codes entre les sources

Deux sources peuvent utiliser le même code pour des choses différentes, ou des codes différents pour la même chose. Lorsqu'un code apparaît dans plus d'une source, Data Foundation retient ses lignes jusqu'à ce que vous indiquiez s'il désigne la même chose partout, de sorte que chaque montant soit compté une seule fois. Le contrôle **Codes waiting for your answer** les liste, les 10 premiers puis « et K autres », et la carte **What to do next** de l'onglet **Foundation** comporte un bouton **À examiner**.

**À examiner** ouvre **Codes waiting for your answer**. Il regroupe les codes selon leur nature : **Types de compte**, **Sociétés**, **Comptes**, **Départements**, **Centres de profit**, **Clients**, **Produits** et chaque catégorie supplémentaire. Pour chaque code, il affiche comment chaque source l'appelle, ainsi qu'une suggestion :

- **Looks like the same thing** lorsque les sources donnent le même nom au code.
- **Looks like different things** lorsque les noms diffèrent.
- **We can't tell. Please answer.** lorsqu'il n'y a rien sur quoi s'appuyer.

Répondez code par code avec **Yes, the same** ou **No, different**, ou répondez à tout un groupe à la fois avec **Accept all** (accepter chaque suggestion), **All the same** ou **All different**. Pour les comptes, vous pouvez aussi répondre à tout un groupe parent du plan comptable en une fois. Lorsqu'une source ne porte aucun type de compte, choisissez **Use this type** pour un groupe de comptes : **Chiffre d'affaires**, **Coût des marchandises vendues**, **Charges d'exploitation**, **Produits et charges hors exploitation**, **Actifs**, **Passifs** ou **Capitaux propres**.

Les correspondances sont conservées par source et par dimension ; une réponse pour les départements d'une source ne change donc jamais les comptes d'une autre. Les réponses sont enregistrées au fur et à mesure, avec **Saved. Press Apply changes to use your answers.** Cliquez sur **Apply changes** pour les utiliser.

Vous pouvez aussi fournir les correspondances dans un fichier. Ajoutez un fichier avec le jeu de données **Code map**, et choisissez **Which source do these rows apply to?** pour le limiter à une source.

## Choisir quelle source compte à partir de quand

Lorsque deux sources fournissent les mêmes mois, le contrôle **Which source covers which months** vous demande de choisir. Cliquez sur **Choose which source counts from when** dans la carte **What to do next** pour ouvrir **Which source counts from when**, qui liste chaque chevauchement par société. Choisissez la source qui compte, saisissez le mois à partir duquel elle compte dans **That month is**, par exemple `2026-04`, puis cliquez sur **Apply changes**. L'autre source conserve les mois antérieurs.

La même boîte de dialogue avertit lorsque deux sources donnent des taux de change différents pour une devise ; les taux de la source placée plus haut dans l'ordre sont utilisés.

## Conversion de devises

Chaque chargement convertit les montants du grand livre, de la balance générale, des ventes, des stocks et du budget de leur devise locale vers une seule devise de reporting. Les rapports et les modèles lisent les montants convertis, de sorte que les entités en devises différentes, issues de n'importe quel système, se totalisent correctement.

### La devise de reporting

Pour choisir la devise de reporting, définissez la variable de projet `reporting_currency` sur un code de devise tel que `USD`. Voir [Gérer les variables de projet](/fr/guides/projects/managing-projects/#gestion-des-variables-du-projet). Le modèle la crée vide. Tant qu'elle est vide, chaque chargement utilise la première des options suivantes qui désigne exactement une devise :

1. La devise du groupe des entités.
2. La devise locale des entités de premier niveau, celles qui n'ont pas de parent.
3. La devise locale des fichiers.

Si aucune ne désigne exactement une devise, **Conversion de devises** affiche un problème tant que vous n'avez pas défini `reporting_currency`.

Les montants déjà dans la devise de reporting restent tels quels ; un projet dont toutes les données sont dans une seule devise n'a donc besoin d'aucun taux.

Les fichiers de ventes, de stocks et de budget peuvent aussi porter une devise. Faites correspondre une colonne nommée `Currency` ou `Local Currency` et elle est prise en compte automatiquement, et les montants locaux du fichier sont convertis dans la devise de reporting. Un montant de groupe ou de reporting déjà présent dans le fichier est conservé tel quel. Le coût standard des produits n'est pas converti.

### Taux de change

Un taux convertit une unité d'une devise dans la devise de reporting pour un mois : le montant converti est le montant local multiplié par le taux.

- **Depuis votre ERP**, chaque chargement lit les taux de change que l'ERP contient.
- **Depuis un fichier**, ajoutez un fichier CSV ou Excel et choisissez le jeu de données **Taux de change**. Un taux du fichier remplace le taux de l'ERP pour les mêmes devises et le même mois. Utilisez un fichier pour rendre compte dans une devise vers laquelle vos ERP ne publient pas de taux, ou pour ajouter des taux prévisionnels pour les mois de budget.

| Colonne | Contenu |
|---|---|
| `from_currency` | La devise à convertir, par exemple `EUR`. |
| `to_currency` | La devise de reporting, par exemple `USD`. |
| `period` | Le mois, sous la forme `YYYY-MM`. |
| `average_rate` | Le taux moyen du mois. |
| `closing_rate` | Le taux de fin de mois. |
| `historical_rate` | Le taux historique, pour les capitaux propres et pour les comptes réglés sur le taux historique. |

Lorsqu'une devise n'a pas de taux vers la devise de reporting, son taux dans l'autre sens, de la devise de reporting vers elle, est inversé, en conservant 12 décimales. À défaut, son taux vers une autre devise est multiplié par le taux de cette autre devise vers la devise de reporting.

### Quel taux s'applique

Chaque ligne est convertie à partir de sa propre devise ; une ligne dans une devise différente de celle de son entité est donc convertie à partir de la devise dans laquelle elle se trouve. La première règle qui correspond à la ligne s'applique :

| Ligne | Taux |
|---|---|
| Comptes statistiques et comptes sans écriture | Non converti. |
| Déjà dans la devise de reporting | Non converti. |
| Compte avec un type de taux | Ce taux : moyen, de clôture ou historique. Le taux historique se rabat sur le taux de clôture lorsqu'il n'y a pas de taux historique. Depuis un ERP, le type de taux est celui du compte lui-même. Dans un fichier de plan comptable, faites correspondre une colonne de type de taux à `fx_rate_type` avec `average`, `closing` ou `historical`. |
| Ligne de vente | Le taux moyen de la période. |
| Solde de stock | Le taux de clôture de la période. |
| Ligne de budget | Par compte, comme le grand livre : le taux moyen pour les comptes de compte de résultat et le taux de clôture pour les comptes de bilan. |
| Compte de compte de résultat | Le taux moyen de la période. |
| Compte de capitaux propres | Le taux historique, ou le taux de clôture lorsqu'il n'y a pas de taux historique. |
| Tout autre compte de bilan | Le taux de clôture de la période. |

Les montants convertis ne sont pas arrondis, de sorte que les totaux ne dérivent pas.

<Aside type="note">
La balance générale contient les mouvements de chaque période ; les montants du bilan sont donc les mouvements de chaque mois convertis au taux de clôture de ce mois. Ce n'est pas un bilan converti de nouveau au taux de fin de période, et il n'y a ni écart de conversion cumulé ni élimination intersociétés. Utilisez les montants convertis pour le compte de résultat.
</Aside>

## Hiérarchies

Chaque chargement reconstruit les dimensions à partir des données de base de chaque source. Il y a sept dimensions au départ, et jusqu'à dix catégories supplémentaires :

| Dimension | Construite à partir de |
|---|---|
| **Entité** | Les entités et leurs parents |
| **Compte** | Le plan comptable et les comptes parents |
| **Département** | Les départements et leurs parents |
| **Client** | Les clients et leurs clients parents |
| **Produit** | Les produits et leurs produits parents |
| **Segment 1** | Les valeurs de segment pour `segment_1` |
| **Segment 2** | Les valeurs de segment pour `segment_2` |
| **Segment 3** à **Segment 10** | Les valeurs de segment pour `segment_3` à `segment_10`, lorsque vos sources en portent |

- Un enregistrement sans parent, ou qui se nomme lui-même comme parent, se charge comme membre de premier niveau.
- Comme chaque chargement reconstruit les hiérarchies, modifiez un parent dans l'ERP ou dans votre fichier, et non dans la dimension.
- Un problème dans une hiérarchie n'affecte que cette dimension. Le chargement et les modèles du modèle de projet se terminent quand même.
- Vous pouvez renommer chaque catégorie supplémentaire selon ce qu'elle contient, par exemple **Classe** ou **Région**. Sous **Rename extra categories**, saisissez les noms qu'utilisent vos rapports et cliquez sur **Save names**. Les noms comportent des lettres, des chiffres, des espaces, des points, des tirets et des tirets bas, jusqu'à 60 caractères.
- Chaque source indique sous quel nom de vos catégories va chacune de ses propres catégories supplémentaires. Ouvrez **Avancé** sur la source, choisissez le nom de chacune, ou choisissez **Leave out**, puis cliquez sur **Enregistrer**. Les sources qui appellent une catégorie par des noms différents, tels que `Class` et `Business area`, partagent alors un seul emplacement.

Pour fournir des hiérarchies de segments depuis un fichier, choisissez le jeu de données **Valeurs de segment** :

| Colonne | Contenu |
|---|---|
| `segment` | Le segment auquel appartient la valeur : de `segment_1` à `segment_10`. |
| `segment_value` | La valeur, telle que les lignes du grand livre, des ventes et du budget la portent. |
| `segment_value_name` | Son nom. |
| `parent_segment_value` | Son parent au sein du même segment. |

## Contrôles de préparation

Après chaque chargement, la grille **Préparation** liste chaque contrôle pour chaque entité et chaque période, avec l'un de ces statuts :

| Statut | Signification |
|---|---|
| **● Prêt** | Le contrôle a réussi. |
| **▲ À examiner** | Mérite un coup d'œil, mais les chiffres sont utilisables. |
| **■ Problème** | À corriger avant de vous fier aux résultats. |
| **– Sans objet** | Il n'y a pas encore de données pour ce contrôle. |

Les contrôles sont les suivants :

| Contrôle | Ce qu'il confirme |
|---|---|
| **Données chargées** | Chaque période fiscale comporte des lignes de grand livre, et chaque lecture de l'ERP a réussi. Une période clôturée sans ligne est un problème ; une période ouverte sans ligne est à examiner. |
| **La balance de vérification concorde avec le grand livre** | La balance générale est égale au grand livre pour chaque entité, période et compte. Lorsque la balance générale et le grand livre portent tous deux des départements pour un compte, le contrôle vérifie aussi la concordance de chaque département. |
| **Les ventes concordent avec le grand livre** | Les lignes de vente sont égales aux comptes de chiffre d'affaires et de coût des marchandises vendues du grand livre pour chaque période. |
| **Produits/clients inconnus** | Chaque ligne de vente nomme un produit et un client qui existent dans les référentiels de produits et de clients. |
| **Comptes absents du plan comptable** | Chaque ligne du grand livre nomme un compte du plan comptable. Les lignes dont le compte est inconnu sont exclues du compte de résultat. Un compte avec des écritures mais sans type de compte est aussi un problème, et une source dont le plan type des comptes de chiffre d'affaires mais aucun compte de coût des marchandises vendues est à examiner. |
| **Conversion de devises** | Chaque ligne du grand livre, de la balance générale, des ventes, des stocks et du budget a un montant dans la devise de reporting. Une ligne de compte de résultat ou de ventes sans taux est un problème, car le compte de résultat lit les montants convertis. Une ligne de bilan, de stock ou de budget sans taux est à examiner. Un mois de budget sans taux apparaît en orange ; chargez donc des taux prévisionnels pour les mois de budget. Voir [Conversion de devises](#conversion-de-devises). |
| **Entités non mappées** | Chaque ligne du grand livre, de la balance générale et des ventes nomme une entité du référentiel d'entités, directement ou par la correspondance des entités. Sans objet tant qu'aucun référentiel d'entités n'est chargé. Voir [Correspondance des entités](#correspondance-des-entités). |

Les chargements comportant plus d'une source ajoutent ces contrôles :

| Contrôle | Ce qu'il confirme |
|---|---|
| **Reporting book** | Pour une source qui porte plusieurs livres comptables pour une entité, le livre de reporting a été choisi. Tant que vous n'avez pas choisi, seul le premier livre compte. |
| **Codes waiting for your answer** | Chaque code utilisé par plus d'une source a reçu une réponse. Voir [Faire correspondre les codes entre les sources](#faire-correspondre-les-codes-entre-les-sources). |
| **Extra categories from your sources** | Chaque catégorie supplémentaire que porte une source a un nom ou a été exclue. |
| **Which source covers which months** | Deux sources ne fournissent pas les mêmes mois d'une société, sauf si vous avez choisi laquelle compte. |
| **Account types and hierarchy** | Chaque parent nommé par une dimension existe, et aucun membre n'est son propre parent ou ancêtre. Un parent manquant place ses enfants au sommet de la hiérarchie, et une boucle empêche le chargement de cette hiérarchie. Les totaux ne sont pas affectés. |
| **Fiscal calendar** | Les périodes fiscales de chaque entité sont des mois calendaires, et chaque mois de lignes peut être placé dans une seule période fiscale. Il est à examiner lorsque les périodes d'une entité ne sont pas des mois calendaires (4-4-5, 13 périodes), ou lorsque les lignes d'un mois peuvent appartenir à plus d'une période fiscale ou que le calendrier fiscal ne contient pas le mois. |

Chaque ligne qui n'est pas prête indique la marche à suivre dans la colonne **What to do**, par exemple charger le plan comptable, charger les taux de change ou exécuter de nouveau **Charger** pour une période.

La grille affiche aussi deux contrôles de configuration, qui n'apparaissent que lorsqu'ils demandent de l'attention :

| Contrôle | Quand il apparaît |
|---|---|
| **Répartition des frais généraux** | Une seule des variables de projet `overhead_department` et `overhead_driver` est définie, ou aucun inducteur d'allocation ne correspond à `overhead_driver`, de sorte que l'allocation ne ferait rien. Définissez les deux, ou videz les deux pour désactiver la répartition des frais généraux. |
| **Comparaison budgétaire** | Des lignes de budget sont chargées, mais aucune ne se trouve dans la version que nomme la variable de projet `budget_version`, de sorte que la comparaison budgétaire serait vide. |

## Consolidation de gestion

Chaque chargement construit une consolidation de gestion : le compte de résultat de groupe de chaque entité du groupe, dans la devise de reporting, avec les opérations intersociétés éliminées. Elle sert au reporting de gestion. Votre système de consolidation reste la référence pour le groupe statutaire ; effectuez le rapprochement avec lui ci-dessous.

<Aside type="note">
La consolidation de gestion ne couvre que le compte de résultat. Ce n'est pas une consolidation statutaire ou légale, et elle ne comporte ni bilan consolidé, ni écart de conversion, ni goodwill, ni intérêts minoritaires.
</Aside>

### Choisir le groupe

Sous **Sources**, ouvrez **Groupe** pour voir les sociétés du groupe. Une société que vous décochez reste dans vos rapports à titre individuel, mais est exclue du total du groupe. Cliquez sur **Save group**. La modification s'applique au prochain **Charger** ou **Apply changes**. Une nouvelle société fait partie du groupe tant que vous ne la décochez pas.

L'exercice fiscal du groupe commence au mois défini par la variable de projet `group_fy_start_month`, qui vaut `1` sauf si vous la modifiez.

### Ce que vous obtenez

| Table | Contenu |
|---|---|
| **Group P&L** | Une ligne par entité, période et poste (chiffre d'affaires, coût des marchandises vendues, charges d'exploitation, hors exploitation, écart intersociétés), dans la devise de reporting. Les produits et les coûts portent leur signe naturel. |
| **Group P&L year to date** | La même chose, cumulée depuis le début de l'exercice, jusqu'à la dernière période entièrement chargée du groupe. |
| **Intercompany pairs** | Une ligne par paire d'entités, groupe et période, avec le montant de chaque côté et le résidu. |
| **Intercompany lines** | Les lignes du grand livre derrière un chiffre de groupe ou une paire, avec le partenaire commercial. |
| **Rapprochement** | Le compte de résultat de groupe cumulé depuis le début de l'exercice face à votre système de consolidation. |

Trois noms d'entité apparaissent dans ces tables :

| Entité | Signification |
|---|---|
| **Eliminations** | Les éliminations intersociétés. Leur somme est nulle ; laissez-les donc pour les chiffres de groupe et filtrez-les pour obtenir la somme des entités avant élimination. |
| **Group total** | Le total du système de consolidation, dans le rapprochement. |
| **Unmapped** | Les lignes sans période, et les comptes ou entités de votre système de consolidation que ce projet n'a pas. |

Les métriques **Consolidated income**, **Consolidated result** et **IC difference**, ainsi qu'un chemin d'analyse pour chaque table, répondent aux questions sur le groupe.

### Éliminations intersociétés

Les lignes intersociétés sont rapprochées par partenaire commercial. Le partenaire de la ligne est utilisé ; lorsqu'une ligne n'en a pas, c'est celui de son client. Les deux côtés d'une paire sont éliminés, et le montant dont les deux côtés ne concordent pas est inscrit sur une ligne d'écart intersociétés. Chaque paire reçoit une raison :

| Raison | Signification |
|---|---|
| **Matched** | Les deux côtés ont comptabilisé le même montant. |
| **Only one side booked** | Une entité a comptabilisé la transaction et son partenaire ne l'a pas fait. |
| **Not eliminated** | Une ligne de la paire n'a pas de taux de change, aucun des deux côtés n'est donc éliminé. |

Une paire est jugée sur son cumul depuis le début de l'exercice. La ligne **Intercompany balances** passe à l'orange lorsque l'écart d'une paire dépasse la variable de projet `group_amber` (par défaut `1`) et au rouge au-delà de `group_red` (par défaut `1000`). Les lignes sans partenaire, ou dont le partenaire n'est pas une entité, ne sont pas éliminées et sont comptées sur cette ligne. Une source qui porte des partenaires à côté d'une qui n'en porte pas s'affiche en orange.

Les entités d'élimination propres à une source restent hors du compte de résultat de groupe, et la ligne **Consolidation** l'indique.

### Rapprocher avec votre système de consolidation

Ajoutez sous forme de fichier les résultats que rapporte votre système de consolidation, et cochez **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** lorsque vous confirmez sa correspondance. Répondez à **Which version of the numbers is this?** avec le nom du système. La table **Rapprochement** affiche alors **ours**, **reported** et **écart** pour chaque entité et chaque poste, cumulés depuis le début de l'exercice. Un écart s'explique généralement sur les lignes **Eliminations**, **Group total** et **Unmapped**, ou par les taux de change que le système utilise. La ligne **Reconciliation to the source** liste chaque poste dépassant `group_amber`.

### Qui peut le voir

Les résultats de groupe suivent la sécurité au niveau des lignes du projet. Lorsque cette sécurité bloque les résultats de groupe, l'état s'affiche en orange. Une personne qui ne voit que certaines entités voit les sommes de ces entités avant élimination. Les lignes **Eliminations** et les tables intersociétés exigent l'accès à toutes les entités.

Si le projet limite qui voit quelles lignes selon une colonne que les tables de groupe ne portent pas, comme le département, les résultats de groupe restent désactivés pour tout le monde et **Consolidation** indique **Group views are off**. Seul un Architecte peut alors cocher **Everyone on the project may see the group results** sous **Groupe**. La modification s'applique au prochain **Charger** ou **Apply changes**.

## Garder à jour

Une fois qu'un chargement depuis votre connexion ERP a réussi sans problème, **Actualiser chaque nuit** apparaît sur la carte **Dernier chargement**. Cliquez dessus pour exécuter **Charger** chaque nuit à 2 h 00 dans votre fuseau horaire. La carte affiche alors **Nightly refresh: Every night at 2:00** et la personne qui l'a configurée.

Le chargement de nuit s'exécute sous l'identité de la personne qui l'a configuré. Si cette personne ne peut plus utiliser la connexion ERP, la grille indique que le chargement de nuit est ignoré ; configurez-le de nouveau. Un projet qui ne contient que des données d'exemple ne peut pas être planifié.

Un fichier absent ou vide lors d'un chargement de nuit se termine par un avertissement qui nomme le chemin, et non par une erreur, et le reste du modèle se charge quand même.

## Noms métier

**Business names** dans l'onglet **Foundation** donne aux codes de votre modèle les noms que votre entreprise utilise. Les rapports, les métriques et l'assistant affichent ces noms, et un nom que vous enregistrez s'applique aussitôt. Les chargements suivants le conservent.

1. Cliquez sur **Add a name** et choisissez le **Genre** : **Catégorie**, **Ligne de compte de résultat**, **Métrique** ou **Colonne**.
2. Saisissez le **Code** : `segment_1` à `segment_10` pour une catégorie, la clé du poste pour une ligne de compte de résultat, le nom de la métrique, ou `table.column` pour une colonne.
3. Saisissez le **Nom**, au plus 60 caractères sur une seule ligne.
4. Cliquez sur **Save names**.

L'enregistrement remplace toute la liste. Une ligne dont le nom est vide supprime ce nom, et **Supprimer la sélection** supprime les lignes que vous cochez. Nommer deux fois le même code est refusé. Les noms métier sont aussi écrits dans la description du chemin d'analyse afin que l'assistant utilise vos mots, et cette description a une limite de longueur : si un nom la rendait trop longue, rien n'est enregistré et vous en êtes informé.

## Expliquer un chiffre

**Explain this number** montre ce qui compose un chiffre du compte de résultat. Dans la grille **Préparation**, une ligne d'entité et de mois comporte **Explain this number**, qui ouvre la marge d'exploitation de l'entité pour ce mois. La fenêtre décompose le chiffre en couches dont la somme donne le total en haut :

| Couche | Contenu |
|---|---|
| **From the general ledger** | Ce que le grand livre a comptabilisé sur le poste. |
| **Allocated in** | Le coût réparti vers cette entité par vos [règles d'allocation](#règles-dallocation). |
| **Allocated out** | Le coût que cette entité a réparti vers d'autres. |
| **Eliminated in the group** | Les opérations intersociétés qui ont été éliminées dans le résultat de groupe. |

Chaque couche comporte une phrase qui dit ce qu'elle est et ses principaux documents sources, avec leur système source, leur document et leur compte. Seules les couches qui ont des lignes sont affichées. La fenêtre suit votre sécurité au niveau des lignes : vous n'expliquez que les chiffres que vous voyez. Un chiffre sans rien derrière indique **Nothing to explain**.

## Règles d'allocation

Les allocations répartissent les coûts partagés, tels que les frais généraux, vers des départements, des produits et des clients. Le modèle comporte deux phases : **Stage 1: overhead to departments** et **Stage 2: departments to products and customers**. Ouvrez **Actions > Allocations...** pour voir ou modifier la manière dont chacune est réalisée. Sans modification, elles fonctionnent comme avant l'existence de l'assistant. Un lecteur peut ouvrir les règles mais pas les enregistrer.

Pour chaque phase, l'assistant pose quatre questions :

| Étape | Question | Choix |
|---|---|---|
| **Pool** | Quels coûts voulez-vous répartir ? | Le type de compte et, pour la phase 1, le département qui porte le coût, ou **Tous les départements**. |
| **Driver** | Selon quoi voulez-vous les répartir ? | **Statistic** que vous avez chargée comme inducteurs d'allocation, tels que l'effectif ou la surface en mètres carrés, **Net sales amount**, **Sales quantity** ou **Spread evenly**. Utilisez l'inducteur de **Same period** ou de **Same period last year**. |
| **Target** | Où aboutissent-ils ? | Phase 1 : les départements. Phase 2 : les produits, les clients ou les deux. |
| **Method** | Que se passe-t-il lorsqu'un inducteur est négatif ? | **Ignore negative values** ou **Stop and tell me**. |

Sous les étapes, **Preview for** un mois, écrit sous la forme année-mois comme `2026-09`, montre ce que feraient les règles, y compris celles que vous n'avez pas enregistrées : `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Tout ce qui n'est pas alloué est un coût qu'aucun inducteur n'a pris en charge. L'aperçu suit votre sécurité au niveau des lignes.

Cliquez sur **Enregistrer**. Les règles prennent effet au prochain **Charger**, ou lorsque vous cliquez sur **Apply changes**. Si vous avez modifié à la main une étape d'allocation, votre modification est conservée, et non écrasée, et l'enregistrement la nomme. Vous ne pouvez pas enregistrer pendant qu'un chargement s'exécute.

## Board Pack

Un board pack écrit vos résultats dans un dossier d'un compte de documents, prêts à être envoyés. Ouvrez **Actions > Board pack...**, choisissez un **Compte de documents** et un **Dossier**, tel que `/board-packs`, puis cliquez sur **Enregistrer**. Chaque **Charger** produit alors le pack, de sorte que les fichiers du dossier sont aussi à jour que le dernier chargement. Chaque exécution écrit :

- Un classeur Excel, `Board pack.xlsx`, avec le compte de résultat par entité, un pont de marge, et les meilleurs et les moins bons clients.
- Un PDF du tableau de bord du compte de résultat.

Cliquez sur **Run now** pour produire un pack immédiatement ; ses fichiers apparaissent dans le dossier à la fin. La boîte de dialogue montre la dernière exécution et son résultat, ainsi que la prochaine exécution. **Apply changes** ne produit pas de pack. Pour en produire un chaque nuit, configurez l'actualisation de nuit (voir [Garder à jour](#garder-à-jour)) ; d'ici là, la boîte de dialogue indique **Not scheduled yet**. Seule une personne qui peut modifier le projet la configure.

Un pack qui ne peut pas être produit en entier ne fait jamais échouer le chargement :

- Si les rapports sont désactivés pour votre espace de travail, le pack se limite au classeur Excel, et l'exécution indique **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- Si un tableau de bord créé par quelqu'un d'autre porte déjà l'adresse dont Data Foundation a besoin pour le tableau de bord du compte de résultat, ce tableau de bord reste tel quel et le PDF n'est pas produit. Le message nomme l'adresse ; donnez une autre adresse à l'autre tableau de bord, puis exécutez de nouveau **Charger**.
- Si une étape du pack échoue, la liste **Statut** affiche une ligne orange **Board pack** qui nomme l'étape et la raison. Le chargement lui-même a quand même réussi.

## Points de restauration

Un point de restauration est créé au démarrage de chaque **Charger** ou **Apply changes**, quelle que soit la personne qui le lance, y compris un chargement planifié, et avant chaque modification des correspondances ou des sources. Il contient les tables du modèle, les dimensions et les paramètres à partir desquels le chargement suivant construit : vos sources, vos fichiers et vos règles d'allocation. Les sept derniers points pris pour des chargements et les cinq derniers pris avant des modifications sont conservés, de sorte que les modifications ne font jamais sortir les points pris pour des chargements. Les points plus anciens disparaissent.

Pour revenir en arrière, ouvrez **Actions > Restore...**. Chaque point indique quand il a été créé et, en dessous, combien de tables sa restauration ramène, par exemple **Puts back 12 tables.**, ainsi que les éventuels avertissements. Choisissez un point et cliquez sur **Restaurer**. **Restaurer** n'est proposé qu'une fois qu'un point existe. La restauration enregistre d'abord le projet tel qu'il est maintenant comme un point à part entière, de sorte que vous puissiez revenir de nouveau. Elle remet ensuite les tables, les dimensions et ces paramètres tels qu'ils étaient, et le chargement suivant construit à partir d'eux. Restaurer les sources que vous aviez déjà ne les marque pas comme modifiées. Une vue, une dimension qui ne peut pas être enregistrée ou une table sans copie enregistrée est nommée dans un avertissement, et le reste est restauré. Un point de restauration qui a disparu est refusé, et vous ne pouvez pas restaurer pendant qu'un chargement s'exécute.

## Cloner un projet

**Actions > Clone...** copie le projet sous un nom que vous donnez. La copie conserve le modèle de projet, vos modifications du modèle, ainsi que vos métriques et vos chemins d'analyse, et charge les données d'exemple. Ses sources ne sont pas connectées ; connectez-les donc dans la copie avant de charger. Vous pouvez continuer à travailler pendant la création de la copie, et **Ouvrir le projet** vous y conduit lorsqu'elle est prête.

## Enregistrer comme mon modèle

Enregistrez la configuration d'un projet pour la réutiliser pour le client ou l'entité suivant. Ouvrez **Actions > Save as my template...**, choisissez le compte de documents et nommez le fichier. Un nom se terminant par `.zip` est ajouté si vous l'omettez. Enregistrer par-dessus un fichier existant est refusé ; choisissez donc un autre nom.

Le fichier contient la structure du projet, vos modifications du modèle, les métriques et les chemins d'analyse, les noms métier des entités et des comptes, ainsi que les lignes des tables de configuration du modèle de projet, telles que la carte des activités de [Cost to Serve](/fr/guides/projects/cost-to-serve/) ou les fourchettes de politique d'[Operational Transfer Pricing](/fr/guides/projects/operational-transfer-pricing/). Il exclut les connexions, les fichiers, la planification de nuit, les exécutions, les points de restauration, le board pack et les personnes qui ont accès.

Pour l'utiliser, créez un projet, choisissez **From a template file...** sous **Partir de**, et indiquez le compte de documents et le chemin. Le nouveau projet vous est privé, avec chaque source en attente de connexion. Une version ultérieure du modèle de projet fusionne ses modifications autour des étapes que vous avez modifiées. S'il n'y a aucun fichier au chemin indiqué, rien n'est créé et vous en êtes informé. Toute personne qui peut lire le compte de documents peut installer à partir du fichier. Pour l'utiliser dans un autre espace de travail, téléchargez le fichier et téléversez-le dans cet espace.

## Résoudre les questions ouvertes avec Ask

Après un chargement, un projet peut encore attendre qu'on lui dise trois choses : les comptes que le plan comptable laisse sans type, les codes que plus d'une source utilise, et les colonnes de vos fichiers qui n'ont correspondu à rien. Demandez à l'assistant de les résoudre : depuis un assistant IA via MCP, utilisez l'invite **Resolve Data Foundation residue**. Il lit ce qui est en attente et propose une réponse pour chaque élément, avec une raison.

L'assistant n'écrit rien. Vous appliquez ses réponses là où vous auriez répondu vous-même : les comptes et les codes sous **Codes waiting for your answer**, et les colonnes de fichier dans la correspondance du fichier. Il ne propose jamais d'entité.

## Transmettre le projet

La liste de contrôle **Configuration** comporte quatre éléments de clôture après **Vérifier vos hiérarchies** :

- **Set up the nightly refresh** est terminé dès que **Actualiser chaque nuit** est activé.
- **Partager avec votre équipe** est terminé dès qu'une personne autre que celle qui a configuré le projet en est membre.
- **Download the evidence pack** est terminé lorsque vous téléchargez le pack après le dernier chargement réussi.
- **Hand the project over to its owner** est terminé dès qu'il existe un Architecte autre que la personne qui l'a configuré et que les totaux concordent. Tant que ce n'est pas terminé, la liste de contrôle indique quoi faire : faire du propriétaire du client un Architecte de ce projet, puis vous retirer de ses membres.

La liste de contrôle indique qui a configuré le projet (**Set up by**).

## Construire sur le modèle à partir d'un modèle

Un modèle de projet construit ses rapports et ses modèles sur le Common Finance Model, de sorte qu'ils fonctionnent de la même façon quels que soient les ERP qui l'alimentent. Lorsque vous démarrez un projet à partir d'un modèle, tel que **Enterprise Profitability**, il crée :

- Les [tables du Common Finance Model](#tables-du-common-finance-model), vides ou remplies de données d'exemple.
- Les dimensions **Entité**, **Compte**, **Département**, **Client**, **Produit**, **Segment 1** et **Segment 2** construites à partir de ces tables. Voir [Hiérarchies](#hiérarchies).
- Le workflow **Charger** et les workflows qu'il exécute pour lire votre ERP et vos fichiers, les mettre en conformité, vérifier la préparation et construire les modèles du modèle de projet.
- Les rapports et modèles propres au modèle de projet. **Enterprise Profitability** ajoute une table de compte de résultat avec le chiffre d'affaires, le coût des marchandises vendues, la marge brute, les charges d'exploitation directes et indirectes, la contribution et la marge d'exploitation, ainsi que des ponts de marge d'une année sur l'autre et par rapport au budget.
- Des métriques et un chemin d'analyse pour interroger les résultats.

Trois modèles sont proposés sous **Partir de**, chacun s'appuyant sur le même modèle :

| Modèle | Ajoute |
|---|---|
| **Enterprise Profitability** | Le compte de résultat et les ponts de marge. |
| **Cost to Serve** | Le coût de service de chaque client, et la marge après ce coût. Voir [Cost to Serve](/fr/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | Le niveau de profit de chaque entité par rapport à votre fourchette de politique, et la régularisation. Voir [Operational Transfer Pricing](/fr/guides/projects/operational-transfer-pricing/). |

**From a template file...** démarre à partir d'un projet que vous avez enregistré. Voir [Enregistrer comme mon modèle](#enregistrer-comme-mon-modèle).

Pour explorer avant de connecter votre propre ERP, cochez **Commencer avec des données d'exemple** lorsque vous créez le projet. Le projet exécute immédiatement un premier Charger, de sorte que l'onglet **Foundation** affiche un exemple complet, y compris une entité en euros convertie en dollars américains. Lorsque vous connectez votre propre ERP ou ajoutez vos propres fichiers, l'exemple est supprimé et vos données prennent sa place. Si la suppression est interrompue, le **Charger** suivant la termine. Un dossier de votre cru nommé `sample` n'est jamais supprimé : la page d'état note que l'exemple occupe ce dossier, que les autres tables qu'il contient ne sont donc pas lues, et vous demande de les déplacer vers un dossier d'un autre nom.

## L'onglet Foundation

L'onglet **Foundation** est l'endroit où vous connectez, chargez et contrôlez vos données. Il comporte ces sections, de haut en bas :

| Section | Ce qu'elle montre |
|---|---|
| **Dernier chargement** | Si le dernier chargement a réussi, échoué ou est encore en cours, avec les boutons **Charger**, **Apply changes**, **Actualiser** et **Actualiser chaque nuit**. |
| **What to do next** | Ce qui demande votre attention, le plus important en premier, chaque élément avec un bouton **À examiner** ou **Choose which source counts from when**. |
| **Sources** | Chaque source dans l'ordre, avec **Avancé**, **Remove this source**, **Groupe** et **Rename extra categories**. |
| **Configuration** | La liste de contrôle de configuration : **Connecter vos données**, **Charger vos données**, **Vérifier la concordance des totaux**, **Vérifier vos hiérarchies**, **Set up the nightly refresh**, **Partager avec votre équipe**, **Download the evidence pack** et **Hand the project over to its owner**. L'élément en cours est en gras. |
| **Business names** | Les noms que votre entreprise utilise pour les catégories, les lignes du compte de résultat, les métriques et les colonnes. Voir [Noms métier](#noms-métier). |
| **Fichiers** | Chaque fichier que vous avez ajouté, son jeu de données, tel que **Grand livre** ou **Taux de change**, et si sa correspondance est **✓ Confirmé** ou **○ En attente de confirmation**. |
| **Données chargées** | Pour chaque entité, la première et la dernière période chargées et le nombre de périodes prêtes. |
| **Périodes** | Les périodes fiscales de chaque entité et si chacune est **✓ Clos** ou **○ Ouvert**. |
| **Préparation** | La grille de préparation : une ligne par entité, période et contrôle, avec son statut et **What to do**. |
| Connexion | Connecter votre ERP, choisir les entités et le nombre de mois d'historique à charger, ou ajouter une autre source. |
| **Fichiers** (ajout) | Ajouter un fichier CSV, TSV, TXT, Excel ou Parquet et confirmer la correspondance de ses colonnes. |
| **Charger** | Lancer un chargement. **Apply changes** en exécute un sans extraire de nouveau les données des ERP. |

Pendant l'exécution d'un chargement, l'onglet s'actualise tout seul et continue de lire même si une lecture échoue. Si l'état ne peut pas être lu, **Le statut de Foundation n'a pas pu être lu.** apparaît avec **Réessayer**, qui le relit à neuf ; l'onglet réessaie aussi une fois de lui-même avant d'afficher le message, et le message disparaît lorsque le serveur répond.

La page d'état note aussi :

- Un dossier sous `/sources/` dont les tables n'ont pas les colonnes nécessaires n'est pas ajouté comme source. Une note nomme chaque table écartée et la colonne qui lui manque. Ajoutez la colonne, puis appuyez sur **Charger** ou **Apply changes**.
- Si un chargement a réussi mais n'a apporté aucune ligne de grand livre à comparer, une ligne orange **Model P&L ties to GL** indique que rien n'a concordé. **Vérifier la concordance des totaux** reste en attente dans la liste de contrôle de configuration, non terminé, tant que quelque chose n'a pas concordé. Ajoutez une source avec des lignes de grand livre, puis appuyez sur **Charger**.

La liste de contrôle de configuration suit votre progression :

- **Connecter vos données** et **Charger vos données** se cochent d'elles-mêmes dès qu'une source est rattachée et qu'un chargement réussit.
- **Vérifier la concordance des totaux** se coche de lui-même lorsque les contrôles de concordance réussissent.
- **Vérifier vos hiérarchies** : cliquez sur **Ouvrir les dimensions** pour examiner les hiérarchies Entité, Compte et Département, puis cochez **Je les ai examinés**. Vous confirmez celui-ci vous-même.
- **Set up the nightly refresh**, **Partager avec votre équipe**, **Download the evidence pack** et **Hand the project over to its owner** terminent la liste. Voir [Transmettre le projet](#transmettre-le-projet) et [Gérer l'accès aux projets](/fr/guides/projects/managing-projects/#gestion-de-laccès-aux-projets).

Le menu **Actions** contient **Allocations...**, **Board pack...**, **Clone...**, **Restore...** et **Save as my template...**. Voir [Règles d'allocation](#règles-dallocation), [Board Pack](#board-pack), [Cloner un projet](#cloner-un-projet), [Points de restauration](#points-de-restauration) et [Enregistrer comme mon modèle](#enregistrer-comme-mon-modèle).

## Tables du Common Finance Model

Data Foundation met chaque source, ERP ou fichier, en conformité avec les quinze mêmes tables, de sorte que les rapports, les métriques et les modèles construits dessus fonctionnent de la même façon quelle que soit la source. Chaque ligne enregistre aussi son système source et le moment où elle a été lue. La colonne **Jeu de données** est le nom que vous choisissez lorsque vous ajoutez un fichier.

| Jeu de données | Table | Contenu |
|---|---|---|
| Entités | `cfm_entity` | Entités juridiques avec parent, devise locale et devise du groupe, et pays. |
| Entity crosswalk | `cfm_entity_map` | Codes d'entité source et entité à laquelle chacun appartient. Voir [Correspondance des entités](#correspondance-des-entités). |
| Taux de change | `cfm_fx_rate` | Taux moyens, de clôture et historiques mensuels par paire de devises. Voir [Taux de change](#taux-de-change). |
| Calendrier fiscal | `cfm_fiscal_calendar` | Une ligne par période fiscale d'entité, avec les dates de début et de fin et son état de clôture. |
| Plan comptable | `cfm_account` | Comptes avec parent, type (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), état financier, sens normal du solde et type de taux. |
| Départements | `cfm_department` | Départements et centres de coûts avec parent et centre de profit. |
| Produits | `cfm_product` | Référentiel de produits avec parent, famille, groupe, unité de mesure et coût standard. |
| Clients | `cfm_customer` | Référentiel de clients avec parent, groupe, région et pays. Les noms de clients ne sont pas masqués. |
| Valeurs de segment | `cfm_segment` | Valeurs de segment avec nom et parent. Voir [Hiérarchies](#hiérarchies). |
| Grand livre | `cfm_gl_journal` | Lignes de journal en devise de transaction, locale et de reporting. |
| Balance de vérification | `cfm_trial_balance` | Débits, crédits et net de la période par entité, compte et département, en devise locale et de reporting. |
| Lignes de vente | `cfm_sales_line` | Lignes de vente facturées avec quantité, montants bruts, remise, net et coût des marchandises vendues. |
| Soldes de stock | `cfm_inventory_balance` | Stock de fin de période par produit et par entrepôt. |
| Budget | `cfm_budget` | Budget et prévision par scénario, version, compte et département. |
| Inducteurs d'allocation | `cfm_stat_driver` | Inducteurs statistiques tels que l'effectif, la surface en pieds carrés ou les unités. |

Les périodes s'écrivent `YYYY-MM`, et les transactions sont placées selon la période de comptabilisation. Le budget est facultatif : un ERP sans budgets charge quand même tout le reste.

Un fichier de balance générale peut porter des colonnes de débit et de crédit, une colonne de net, ou les deux. Avec seulement un débit et un crédit, le net est le débit moins le crédit, et un côté vide compte pour zéro. Avec seulement un net, un net positif devient le débit et un net négatif devient le crédit, sous forme de montant positif. Une colonne de département est facultative.

## Dépannage

| Symptôme | Que faire |
|---|---|
| **Tester la connexion** indique que l'ERP a refusé les identifiants | Vérifiez les identifiants de la connexion, et que l'utilisateur d'intégration peut se connecter à l'ERP. |
| **Tester la connexion** affiche **Autorisation manquante** pour un jeu de données | Demandez à l'administrateur de votre ERP d'ajouter les autorisations qu'elle nomme. Le [guide de connexion](/fr/guides/connections/) de votre ERP liste ce dont la connexion a besoin. |
| Un message d'erreur de l'ERP est plus court que celui de l'ERP lui-même | PlaidCloud retire les identifiants, les jetons et les clés des erreurs du fournisseur avant de les afficher, de sorte que certains détails sont omis. Exécutez **Tester la connexion** pour voir quel jeu de données est concerné. |
| **Données chargées** est un problème pour une période | Une lecture de l'ERP pour cette période a échoué. Exécutez de nouveau **Charger** ; les périodes déjà chargées sont ignorées. |
| **Comptes absents du plan comptable** est un problème | Ajoutez les comptes manquants au plan comptable dans l'ERP ou dans votre fichier, puis exécutez de nouveau **Charger**. |
| **Conversion de devises** est un problème | La devise d'une entité n'a pas de taux vers la devise de reporting pour cette période, ou aucune devise de reporting unique n'a été trouvée. Ajoutez les taux dans un fichier **Taux de change**, vérifiez que la connexion peut lire les taux de change de l'ERP, ou définissez la variable de projet `reporting_currency`. Puis exécutez de nouveau **Charger**. |
| **Conversion de devises** est à examiner | Des lignes de bilan, de stock ou de budget n'ont pas de taux de clôture, historique ou prévisionnel pour la période. Le compte de résultat n'est pas affecté. Ajoutez les taux, y compris les taux prévisionnels pour les mois de budget, puis exécutez de nouveau **Charger**. |
| **Codes waiting for your answer** est à examiner | Cliquez sur **À examiner**, répondez pour chaque code, puis cliquez sur **Apply changes**. |
| **Which source covers which months** est à examiner | Cliquez sur **Choose which source counts from when**, choisissez la source, puis cliquez sur **Apply changes**. |
| **Intercompany balances** est rouge ou orange | Vérifiez les paires dans **Intercompany pairs**. Comptabilisez le côté manquant, ajoutez le partenaire commercial aux lignes, ou ajoutez le taux manquant. |
| **Group views are off** | Demandez à un Architecte de cocher **Everyone on the project may see the group results** sous **Groupe**. |
| **Entités non mappées** est un problème | Ajoutez l'entité au référentiel d'entités, ou faites correspondre son code à une entité existante dans le fichier **Entity crosswalk**, puis exécutez de nouveau **Charger**. |
