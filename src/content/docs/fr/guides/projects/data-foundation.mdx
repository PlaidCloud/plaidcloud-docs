**Data Foundation** est le socle de données financières de vos projets PlaidCloud. Son **Common Finance Model** rassemble dans un modèle unique les données ERP de plusieurs systèmes ERP, et de plusieurs instances de chacun : un seul plan comptable, un seul ensemble d'entités et une seule devise de reporting. Les rapports, les métriques et les assistants IA construits sur ce modèle lisent tous les mêmes chiffres, quel que soit l'ERP d'origine.

Votre ERP se connecte par sa connexion PlaidCloud : le grand livre, la balance de vérification, les données de base et les budgets arrivent donc directement de la source, sans rien à exporter. Les fichiers ajoutent les données qu'un système ne contient pas, comme les taux de change, les inducteurs d'allocation ou un budget tenu en dehors de l'ERP, et peuvent remplacer les lignes de l'ERP qu'ils couvrent. **Charger** conforme chaque source au modèle, la convertit dans la devise de reporting et vérifie que les totaux concordent, le tout depuis l'onglet **Foundation** du projet. Les modèles, tels que **Rentabilité de l'entreprise**, construisent leurs rapports et leurs modèles de calcul par-dessus.

## Connecter votre ERP

Votre ERP se connecte à Data Foundation par sa connexion PlaidCloud. Data Foundation lit directement à travers elle le grand livre, la balance de vérification, les données de base, les taux de change et les budgets, et ne fait jamais que lire. Vous pouvez choisir une connexion existante ou en créer une dans l'onglet ; les [guides de connexion](/fr/guides/connections/) décrivent la configuration d'accès de chaque ERP.

<Steps>

1. Dans Analyze, ouvrez **Projets** et cliquez sur **Nouveau projet**. Saisissez un nom et, sous **Partir de**, choisissez un modèle, tel que **Rentabilité de l'entreprise (modèle)**, au lieu de **Projet vierge**. Cliquez sur **Créer**.

   Le projet s'ouvre sur son onglet **Foundation**. Il est privé et vous en êtes le seul Architecte, jusqu'à ce que vous le partagiez.

2. Dans l'onglet **Foundation**, choisissez une connexion existante pour votre ERP, ou sélectionnez **Créer une nouvelle connexion**. Chaque connexion existante liste les workflows qui l'utilisent déjà, ou indique **Pas encore utilisé par un workflow**.

3. Pour une nouvelle connexion, saisissez un **Nom de la connexion**, choisissez l'**Environnement** et renseignez les identifiants que demande la connexion à votre ERP.

   Vous n'avez pas encore les identifiants ? Le formulaire affiche une demande d'accès prête à l'emploi pour l'administrateur de votre ERP. Cliquez sur **Copier la demande** ou **Envoyer la demande par e-mail**, envoyez-la, puis saisissez les valeurs qu'il vous renvoie.

4. Cliquez sur **Tester la connexion**. PlaidCloud se connecte et tente de lire chaque jeu de données, puis indique pour chacun **Lisible**, **Autorisation manquante** ou **Erreur**. Lorsqu'il manque quelque chose, il nomme les autorisations à demander à l'administrateur de votre ERP.

5. Définissez **Mois d'historique** : le nombre de mois à charger en remontant dans le temps, de 1 à 120. La valeur par défaut est 24.

6. Pour une connexion existante, cochez les entités à charger, ou laissez-les toutes décochées pour charger toutes les entités. Les entités inactives et d'élimination restent masquées tant que vous ne choisissez pas de les afficher. Cliquez ensuite sur **Connecter**.

7. Pour une nouvelle connexion, cliquez sur **Connecter** pour la créer. Cochez ensuite les entités à charger et cliquez de nouveau sur **Connecter** pour les enregistrer. Tant que vous ne le faites pas, toutes les entités sont chargées.

</Steps>

Une fois connectée, la carte indique la connexion, l'environnement, les entités et le nombre de mois d'historique que le projet charge.

Chaque chargement ne lit que ce qui a changé : les périodes ouvertes et la dernière période clôturée sont relues, et les périodes clôturées déjà chargées sont conservées. Augmenter **Mois d'historique** ne lit que les mois ajoutés. Un taux de change, une correspondance des entités ou une devise de reporting modifiés entraînent la relecture des mois qu'ils concernent.

## Ajouter des fichiers pour les données extérieures à votre ERP

Les fichiers complètent votre connexion ERP avec des données qu'un système ne contient pas, comme les taux de change, les inducteurs d'allocation, une [correspondance des entités](#correspondance-des-entités) ou un budget tenu en dehors de l'ERP. Chaque fichier appartient à l'un des jeux de données listés sous [Tables du Common Finance Model](#tables-du-common-finance-model).

<Steps>

1. Sous **Fichiers**, choisissez le **Compte de documents** dans lequel stocker le fichier.

2. Déposez un fichier CSV ou Excel sur **Déposez un fichier CSV ou Excel ici**, ou cliquez sur **Choisir un fichier**. Le fichier est téléversé dans le dossier `/foundation/` du compte de documents.

   Pour un fichier déjà présent dans le compte de documents, saisissez son **Chemin du fichier**, par exemple `/foundation/budget.csv`, puis cliquez sur **Ajouter un fichier**.

3. PlaidCloud lit le fichier et propose une correspondance :

   - **Délimiteur, séparateur décimal et dates détectés.** Le délimiteur (virgule, point-virgule, tabulation ou barre verticale), le séparateur décimal et le format de date sont détectés pour vous.
   - **Jeu de données** : la table du Common Finance Model à laquelle le fichier appartient, déterminée d'après le nom du fichier et les en-têtes de colonnes. Lorsque la correspondance n'est pas claire, choisissez-la dans la liste.
   - **Séparateur décimal** : **Point (1,234.56)** ou **Virgule (1.234,56)**.
   - **Format de date** : affiché lorsque le fichier contient des dates. Modifiez-le si le format détecté est incorrect : `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Une grille **Colonne du fichier**, **Type**, **Exemples** et **Destination**. Modifiez **Destination** pour envoyer une colonne vers un autre champ, ou vers **Ne pas charger**.

4. Vérifiez la destination de chaque colonne, puis cliquez sur **Confirmer la correspondance**.

</Steps>

Lorsque PlaidCloud ne parvient pas à déterminer seul le jeu de données, le séparateur décimal ou l'ordre des dates, par exemple pour un fichier dont les dates pourraient se lire jour/mois ou mois/jour, il vous demande de choisir avant que vous ne confirmiez. Ajouter un second fichier pour le même jeu de données remplace le premier.

Les fichiers acceptés sont les fichiers texte CSV, TSV et TXT, les fichiers Excel `.xlsx` (lus à partir de la première feuille) et les fichiers Parquet.

<Aside type="note">
Un fichier manquant ou vide n'interrompt jamais un chargement. Son ajout indique qu'il n'y a encore rien à mapper, et un chargement se termine par un avertissement qui nomme le chemin, en laissant ce jeu de données vide. Ajoutez de nouveau le fichier une fois qu'il existe.
</Aside>

## Charger vos données

Cliquez sur **Charger** sur la carte **Charger** ou sur la carte **Dernier chargement**. Le chargement lit votre ERP connecté et vos fichiers confirmés, les conforme au Common Finance Model, les convertit dans la devise de reporting, exécute les contrôles de préparation et reconstruit les modèles de calcul du modèle de projet.

- Un seul chargement à la fois s'exécute pour un projet. Un second **Charger** indique qu'un chargement est déjà en cours.
- Si d'autres workflows utilisent la même connexion ERP, le premier chargement les liste et vous demande de confirmer, car un chargement lit les données de l'ERP et peut ralentir ces workflows. Cliquez sur **Charger quand même** pour continuer.
- Un chargement en échec s'affiche en rouge et ne se cache jamais derrière des résultats antérieurs. Les lignes d'un chargement antérieur affichent **Issu d'un chargement précédent. Rechargez.** jusqu'à ce qu'un chargement réussisse.
- Si la lecture d'une entité et d'une période échoue, le reste est tout de même chargé. Relancez **Charger** pour récupérer uniquement ce qui a échoué.

### Données ERP et fichiers ensemble

Un fichier ne remplace que ce qu'il couvre, et les autres lignes de votre ERP sont conservées.

- Les **fichiers de données de base** (comptes, départements, clients, produits et valeurs de segment) remplacent les lignes de l'ERP portant le même code.
- Les **fichiers de transactions** remplacent les lignes de l'ERP pour la même entité et le même mois. Les fichiers du grand livre et de la balance de vérification correspondent aussi par registre, les fichiers de budget par scénario, et les fichiers d'inducteurs statistiques par scénario et par inducteur.

Si un fichier cesse ensuite de couvrir un mois, les données de l'ERP pour ce mois reviennent au chargement suivant.

## Correspondance des entités

Chaque source nomme ses entités avec ses propres codes. La **Correspondance des entités** associe ces codes aux entités de votre référentiel d'entités, de sorte que les lignes de toutes les sources aboutissent sur la même entité.

Pour en utiliser une, ajoutez un fichier CSV ou Excel et choisissez le jeu de données **Correspondance des entités** :

| Colonne | Contient |
|---|---|
| `source_entity` | Le code tel que la source le porte, comme un code de société. |
| `entity` | L'entité à laquelle il appartient, telle que le référentiel d'entités la nomme. |

- Un code qui ne figure pas dans la correspondance est utilisé tel quel.
- Plusieurs codes peuvent correspondre à une même entité. Leurs lignes sont combinées, et un mois est considéré comme clôturé dès qu'il est clôturé pour chacun d'eux.
- Les codes de la correspondance s'appliquent à toutes les sources ; les codes d'entité de chaque source doivent donc être uniques d'une source à l'autre.
- Une ligne d'un fichier **Entités** remplace l'entité de l'ERP portant le même code d'entité.

Le contrôle **Entités non mappées** signale toute ligne dont l'entité ne figure ni dans le référentiel d'entités ni dans la correspondance des entités. Tant qu'un référentiel d'entités n'est pas chargé, il affiche **– Sans objet**.

## Conversion de devises

Chaque chargement convertit les montants du grand livre, de la balance de vérification, des ventes, des stocks et du budget de leur devise locale vers une devise de reporting unique. Les rapports et les modèles de calcul lisent les montants convertis, de sorte que les entités en devises différentes, issues de n'importe quel système, se totalisent correctement.

### La devise de reporting

Pour choisir la devise de reporting, définissez la variable de projet `reporting_currency` sur un code de devise tel que `USD`. Consultez [Gérer les variables de projet](/fr/guides/projects/managing-projects/#gestion-des-variables-du-projet). Le modèle la crée vide. Tant qu'elle est vide, chaque chargement utilise la première des sources suivantes qui désigne exactement une devise :

1. La devise de groupe des entités.
2. La devise locale des entités de premier niveau, celles qui n'ont pas de parent.
3. La devise locale des fichiers.

Si aucune ne désigne exactement une devise, **Conversion de devises** affiche un problème jusqu'à ce que vous définissiez `reporting_currency`.

Les montants déjà dans la devise de reporting restent tels quels : un projet dont toutes les données sont dans une seule devise n'a donc besoin d'aucun taux.

Les fichiers de ventes, de stocks et de budget peuvent aussi porter une devise. Mappez une colonne nommée `Currency` ou `Local Currency` et elle est prise en compte automatiquement, et les montants locaux du fichier sont convertis dans la devise de reporting. Un montant de groupe ou de reporting déjà présent dans le fichier est conservé tel quel. Le coût standard des produits n'est pas converti.

### Taux de change

Un taux convertit une unité d'une devise dans la devise de reporting pour un mois : le montant converti est le montant local multiplié par le taux.

- **Depuis votre ERP**, chaque chargement lit les taux de change que l'ERP contient.
- **Depuis un fichier**, ajoutez un fichier CSV ou Excel et choisissez le jeu de données **Taux de change**. Un taux du fichier remplace le taux de l'ERP pour les mêmes devises et le même mois. Utilisez un fichier pour produire des rapports dans une devise vers laquelle vos ERP ne publient pas de taux, ou pour ajouter des taux prévisionnels pour les mois budgétaires.

| Colonne | Contient |
|---|---|
| `from_currency` | La devise de départ, par exemple `EUR`. |
| `to_currency` | La devise de reporting, par exemple `USD`. |
| `period` | Le mois, au format `YYYY-MM`. |
| `average_rate` | Le taux moyen du mois. |
| `closing_rate` | Le taux de fin de mois. |
| `historical_rate` | Le taux historique, pour les capitaux propres et pour les comptes réglés sur le taux historique. |

Seuls les taux vers la devise de reporting sont utilisés. Un taux coté dans l'autre sens, de la devise de reporting vers une autre devise, n'est pas inversé.

### Taux applicable

Chaque ligne est convertie à partir de sa propre devise : une ligne dans une devise différente de celle de son entité est donc convertie à partir de la devise dans laquelle elle se trouve. La première règle qui correspond à la ligne s'applique :

| Ligne | Taux |
|---|---|
| Comptes statistiques et non comptabilisables | Non convertis. |
| Déjà dans la devise de reporting | Non convertie. |
| Compte avec un type de taux | Ce taux : moyen, de clôture ou historique. Le taux historique se rabat sur le taux de clôture en l'absence de taux historique. Depuis un ERP, le type de taux est celui du compte lui-même. Dans un fichier de plan comptable, mappez une colonne de type de taux sur `fx_rate_type` avec `average`, `closing` ou `historical`. |
| Ligne de vente | Le taux moyen de la période. |
| Solde de stock | Le taux de clôture de la période. |
| Ligne de budget | Par compte, comme pour le grand livre : le taux moyen pour les comptes de résultat et le taux de clôture pour les comptes de bilan. |
| Compte de résultat | Le taux moyen de la période. |
| Compte de capitaux propres | Le taux historique, ou le taux de clôture en l'absence de taux historique. |
| Tout autre compte de bilan | Le taux de clôture de la période. |

Les montants convertis ne sont pas arrondis, de sorte que les totaux ne dérivent pas.

<Aside type="note">
La balance de vérification contient les mouvements de chaque période : les montants du bilan sont donc les mouvements de chaque mois convertis au taux de clôture de ce mois. Il ne s'agit pas d'un bilan reconverti au taux de fin de période, et il n'y a ni écart de conversion cumulé ni élimination intersociétés. Utilisez les montants convertis pour le compte de résultat.
</Aside>

## Hiérarchies

Chaque chargement reconstruit sept dimensions à partir des données de base de chaque source :

| Dimension | Construite à partir de |
|---|---|
| **Entité** | Entités et leurs parents |
| **Compte** | Plan comptable et comptes parents |
| **Département** | Départements et leurs parents |
| **Client** | Clients et leurs clients parents |
| **Produit** | Produits et leurs produits parents |
| **Segment 1** | Valeurs de segment pour `segment_1` |
| **Segment 2** | Valeurs de segment pour `segment_2` |

- Un enregistrement sans parent, ou qui se nomme lui-même comme parent, est chargé comme membre de premier niveau.
- Comme chaque chargement reconstruit les hiérarchies, modifiez un parent dans l'ERP ou dans votre fichier, pas dans la dimension.
- Un problème dans une hiérarchie n'affecte que cette dimension. Le chargement et les modèles de calcul du modèle de projet se terminent tout de même.
- Vous pouvez renommer **Segment 1** et **Segment 2** selon ce qu'ils contiennent, par exemple **Classe** et **Emplacement**.

Pour fournir des hiérarchies de segments depuis un fichier, choisissez le jeu de données **Valeurs de segment** :

| Colonne | Contient |
|---|---|
| `segment` | Le segment auquel appartient la valeur : de `segment_1` à `segment_5`. **Segment 1** et **Segment 2** ont des dimensions. |
| `segment_value` | La valeur, telle que les lignes du grand livre, des ventes et du budget la portent. |
| `segment_value_name` | Son nom. |
| `parent_segment_value` | Son parent au sein du même segment. |

## Contrôles de préparation

Après chaque chargement, la grille **Préparation** liste chaque contrôle pour chaque entité et chaque période, avec l'un des statuts suivants :

| Statut | Signification |
|---|---|
| **● Prêt** | Le contrôle a réussi. |
| **▲ À examiner** | Mérite un coup d'œil, mais les chiffres sont exploitables. |
| **■ Problème** | À corriger avant de vous fier aux résultats. |
| **– Sans objet** | Il n'y a pas encore de données pour ce contrôle. |

Les contrôles sont les suivants :

| Contrôle | Ce qu'il confirme |
|---|---|
| **Données chargées** | Chaque période fiscale comporte des lignes de grand livre, et chaque lecture de l'ERP a réussi. Une période clôturée sans ligne est un problème ; une période ouverte sans ligne nécessite une attention. |
| **La balance de vérification concorde avec le grand livre** | La balance de vérification est égale au grand livre pour chaque entité, période et compte. Lorsque la balance de vérification et le grand livre portent tous deux des départements pour un compte, la concordance est aussi vérifiée pour chaque département. |
| **Les ventes concordent avec le grand livre** | Les lignes de ventes sont égales aux comptes de revenus et de coût des ventes (COGS) du grand livre pour chaque période. |
| **Produits/clients inconnus** | Chaque ligne de vente désigne un produit et un client qui existent dans les référentiels de produits et de clients. |
| **Comptes absents du plan comptable** | Chaque ligne du grand livre désigne un compte du plan comptable. Les lignes dont le compte est inconnu sont exclues du compte de résultat. |
| **Conversion de devises** | Chaque ligne du grand livre, de la balance de vérification, des ventes, des stocks et du budget a un montant dans la devise de reporting. Une ligne de compte de résultat ou de ventes sans taux est un problème, car le compte de résultat lit les montants convertis. Une ligne de bilan, de stock ou de budget sans taux nécessite une attention. Un mois budgétaire sans taux s'affiche en orange : chargez donc des taux prévisionnels pour les mois budgétaires. Consultez [Conversion de devises](#conversion-de-devises). |
| **Entités non mappées** | Chaque ligne du grand livre, de la balance de vérification et des ventes désigne une entité du référentiel d'entités, directement ou par la correspondance des entités. Sans objet tant qu'un référentiel d'entités n'est pas chargé. Consultez [Correspondance des entités](#correspondance-des-entités). |

Chaque ligne qui n'est pas prête indique quoi faire dans la colonne **Que faire**, par exemple charger le plan comptable, charger des taux de change ou relancer **Charger** pour une période.

La grille affiche aussi deux contrôles de configuration, qui n'apparaissent que lorsqu'ils nécessitent une attention :

| Contrôle | Quand il apparaît |
|---|---|
| **Répartition des frais généraux** | Une seule des variables de projet `overhead_department` et `overhead_driver` est définie, ou aucun inducteur d'allocation ne correspond à `overhead_driver` : l'allocation ne ferait donc rien. Définissez les deux, ou effacez les deux pour désactiver la répartition des frais généraux. |
| **Comparaison budgétaire** | Des lignes de budget sont chargées, mais aucune ne se trouve dans la version que nomme la variable de projet `budget_version` : la comparaison budgétaire serait donc vide. |

## Le garder à jour

Une fois qu'un chargement depuis votre connexion ERP a réussi sans aucun problème, **Actualiser chaque nuit** apparaît sur la carte **Dernier chargement**. Cliquez dessus pour exécuter **Charger** chaque nuit à 2 h 00 dans votre fuseau horaire. La carte affiche alors **Nightly refresh: Every night at 2:00** ainsi que la personne qui l'a configuré.

Le chargement nocturne s'exécute au nom de la personne qui l'a configuré. Si cette personne ne peut plus utiliser la connexion ERP, la grille indique que le chargement nocturne est ignoré ; configurez-le de nouveau. Un projet qui ne contient que des données d'exemple ne peut pas être planifié.

Un fichier manquant ou vide lors d'un chargement nocturne se termine par un avertissement qui nomme le chemin, et non par une erreur, et le reste du modèle est tout de même chargé.

## Construire sur le modèle avec un modèle de projet

Un modèle construit ses rapports et ses modèles de calcul sur le Common Finance Model, de sorte qu'ils fonctionnent de la même manière quels que soient les ERP qui l'alimentent. Lorsque vous démarrez un projet à partir d'un modèle, tel que **Rentabilité de l'entreprise**, il crée :

- Les [tables du Common Finance Model](#tables-du-common-finance-model), vides ou remplies de données d'exemple.
- Les dimensions **Entité**, **Compte**, **Département**, **Client**, **Produit**, **Segment 1** et **Segment 2** construites à partir de ces tables. Consultez [Hiérarchies](#hiérarchies).
- Le workflow **Charger** et les workflows qu'il exécute pour lire votre ERP et vos fichiers, les conformer, vérifier la préparation et construire les modèles de calcul du modèle.
- Les rapports et modèles de calcul propres au modèle. **Rentabilité de l'entreprise** ajoute une table de compte de résultat avec le chiffre d'affaires, le coût des ventes (COGS), la marge brute, les charges d'exploitation directes et indirectes, la contribution et la marge d'exploitation, ainsi que des passerelles de marge d'une année sur l'autre et par rapport au budget.
- Des métriques et un chemin d'analyse pour poser des questions sur les résultats.

Pour explorer avant de connecter votre propre ERP, cochez **Commencer avec des données d'exemple** lors de la création du projet. Le projet exécute immédiatement un premier chargement : l'onglet **Foundation** affiche donc un exemple complet, y compris une entité en euros convertie en dollars américains. Lorsque vous connectez votre propre ERP ou ajoutez vos propres fichiers, les lignes d'exemple sont effacées et vos données prennent leur place.

## L'onglet Foundation

L'onglet **Foundation** est l'endroit où vous connectez, chargez et vérifiez vos données. Il comporte les sections suivantes, de haut en bas :

| Section | Ce qu'elle affiche |
|---|---|
| **Dernier chargement** | Si le dernier chargement a réussi, échoué ou est encore en cours, avec les boutons **Charger**, **Actualiser** et **Actualiser chaque nuit**. |
| **Configuration** | La liste de contrôle de configuration : **Connecter vos données**, **Charger vos données**, **Vérifier la concordance des totaux**, **Vérifier vos hiérarchies** et **Partager avec votre équipe**. L'élément en cours est en gras. |
| **Fichiers** | Chaque fichier que vous avez ajouté, son jeu de données, tel que **Grand livre** ou **Taux de change**, et si sa correspondance est **✓ Confirmé** ou **○ En attente de confirmation**. |
| **Données chargées** | Pour chaque entité, la première et la dernière période chargées et le nombre de périodes prêtes. |
| **Périodes** | Les périodes fiscales de chaque entité et si chacune est **✓ Clos** ou **○ Ouvert**. |
| **Préparation** | La grille de préparation : une ligne par entité, période et contrôle, avec son statut et **Que faire**. |
| Connexion | Connectez votre ERP, choisissez les entités et le nombre de mois d'historique à charger. |
| **Fichiers** (ajout) | Ajoutez un fichier CSV, TSV, TXT, Excel ou Parquet et confirmez la correspondance de ses colonnes. |
| **Charger** | Démarrez un chargement. |

Pendant l'exécution d'un chargement, l'onglet s'actualise de lui-même.

La liste de contrôle de configuration suit votre progression :

- **Connecter vos données** et **Charger vos données** se cochent d'eux-mêmes dès qu'une source est rattachée et qu'un chargement réussit.
- **Vérifier la concordance des totaux** se coche de lui-même lorsque les contrôles de concordance réussissent.
- **Vérifier vos hiérarchies** : cliquez sur **Ouvrir les dimensions** pour examiner les hiérarchies Entité, Compte et Département, puis cochez **Je les ai examinés**. Vous confirmez celui-ci vous-même.
- **Partager avec votre équipe** : partagez le projet lorsqu'il est prêt. Consultez [Gérer l'accès au projet](/fr/guides/projects/managing-projects/#gestion-de-laccès-aux-projets).

## Tables du Common Finance Model

Data Foundation conforme chaque source, ERP ou fichier, aux quinze mêmes tables, de sorte que les rapports, les métriques et les modèles de calcul construits dessus fonctionnent de la même manière quelle que soit la source. Chaque ligne enregistre aussi son système source et le moment où elle a été lue. La colonne **Jeu de données** est le nom que vous choisissez lorsque vous ajoutez un fichier.

| Jeu de données | Table | Contient |
|---|---|---|
| Entités | `cfm_entity` | Entités juridiques avec parent, devise locale et de groupe, et pays. |
| Correspondance des entités | `cfm_entity_map` | Codes d'entité source et entité à laquelle chacun appartient. Consultez [Correspondance des entités](#correspondance-des-entités). |
| Taux de change | `cfm_fx_rate` | Taux mensuels moyens, de clôture et historiques par paire de devises. Consultez [Taux de change](#taux-de-change). |
| Calendrier fiscal | `cfm_fiscal_calendar` | Une ligne par période fiscale d'entité, avec les dates de début et de fin et l'indication si elle est clôturée. |
| Plan comptable | `cfm_account` | Comptes avec parent, type (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), état, solde normal et type de taux. |
| Départements | `cfm_department` | Départements et centres de coûts avec parent et centre de profit. |
| Produits | `cfm_product` | Référentiel de produits avec parent, famille, groupe, unité de mesure et coût standard. |
| Clients | `cfm_customer` | Référentiel de clients avec parent, groupe, région et pays. Les noms de clients ne sont pas masqués. |
| Valeurs de segment | `cfm_segment` | Valeurs de segment avec nom et parent. Consultez [Hiérarchies](#hiérarchies). |
| Grand livre | `cfm_gl_journal` | Lignes d'écriture en devise de transaction, locale et de reporting. |
| Balance de vérification | `cfm_trial_balance` | Débits, crédits et net de la période par entité, compte et département, en devise locale et de reporting. |
| Lignes de vente | `cfm_sales_line` | Lignes de ventes facturées avec quantité, montants bruts, remises, nets et coût des ventes. |
| Soldes de stock | `cfm_inventory_balance` | Stock de fin de période par produit et par entrepôt. |
| Budget | `cfm_budget` | Budget et prévision par scénario, version, compte et département. |
| Inducteurs d'allocation | `cfm_stat_driver` | Inducteurs statistiques tels que l'effectif, les mètres carrés ou les unités. |

Les périodes s'écrivent `YYYY-MM`, et les transactions sont placées selon leur période de comptabilisation. Le budget est facultatif : un ERP sans budgets charge tout le reste.

Un fichier de balance de vérification peut contenir des colonnes de débit et de crédit, une colonne de net, ou les deux. Avec seulement le débit et le crédit, le net est le débit moins le crédit, et un côté vide compte pour zéro. Avec seulement un net, un net positif devient le débit et un net négatif devient le crédit, sous forme de montant positif. Une colonne de département est facultative.

## Dépannage

| Symptôme | Que faire |
|---|---|
| **Tester la connexion** indique que l'ERP a refusé les identifiants | Vérifiez les identifiants de la connexion, ainsi que le fait que l'utilisateur d'intégration peut se connecter à l'ERP. |
| **Tester la connexion** affiche **Autorisation manquante** pour un jeu de données | Demandez à l'administrateur de votre ERP d'ajouter les autorisations nommées. Le [guide de connexion](/fr/guides/connections/) de votre ERP liste ce dont la connexion a besoin. |
| Un message d'erreur de l'ERP est plus court que celui de l'ERP lui-même | PlaidCloud retire les identifiants, jetons et clés des erreurs du fournisseur avant de les afficher, de sorte que certains détails sont omis. Exécutez **Tester la connexion** pour voir quel jeu de données est concerné. |
| **Données chargées** est un problème pour une période | Une lecture de l'ERP pour cette période a échoué. Relancez **Charger** ; les périodes déjà chargées sont ignorées. |
| **Comptes absents du plan comptable** est un problème | Ajoutez les comptes manquants au plan comptable dans l'ERP ou dans votre fichier, puis relancez **Charger**. |
| **Conversion de devises** est un problème | La devise d'une entité n'a pas de taux vers la devise de reporting pour cette période, ou aucune devise de reporting unique n'a été trouvée. Ajoutez les taux dans un fichier **Taux de change**, vérifiez que la connexion peut lire les taux de change de l'ERP, ou définissez la variable de projet `reporting_currency`. Puis relancez **Charger**. |
| **Conversion de devises** nécessite une attention | Des lignes de bilan, de stock ou de budget n'ont pas de taux de clôture, historique ou prévisionnel pour la période. Le compte de résultat n'est pas affecté. Ajoutez les taux, y compris des taux prévisionnels pour les mois budgétaires, puis relancez **Charger**. |
| **Entités non mappées** est un problème | Ajoutez l'entité au référentiel d'entités, ou mappez son code sur une entité existante dans le fichier **Correspondance des entités**, puis relancez **Charger**. |
