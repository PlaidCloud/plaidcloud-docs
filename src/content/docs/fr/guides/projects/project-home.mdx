## Description

**Project home** est le point de départ dans un projet. Un rail à gauche répertorie six pages : **Vue d'ensemble**, **Variables**, **Schedules & sensors**, **Access & sharing**, **Data & connections** et **Apps & branding**. La page Vue d'ensemble résume le projet. Les cinq autres pages permettent de modifier les paramètres du projet.

Le badge **Variables** sur le rail indique le nombre de variables du projet. Le badge **Schedules & sensors** indique le nombre de planifications et de capteurs actifs.

Un projet verrouillé est en lecture seule. Ses pages affichent une bannière indiquant « This project is locked, so it is read only. Unlock it on Overview to make changes. » et leurs commandes sont désactivées.

## Vue d'ensemble

![Page Vue d'ensemble de Project home affichant le nom du projet, six tuiles, Coming up et Project defaults](/images/projects/project-home-overview.png)

Le haut de la page affiche le nom du projet et indique s'il est **Modifiable** ou en **Lecture seule**.

- **Description.** Cliquez sur le crayon pour modifier la description directement. Appuyez sur Entrée pour enregistrer, ou sur Échap pour annuler.
- **Libellés.** Saisissez un libellé dans **Ajouter une étiquette…** et cliquez sur **Ajouter**. Consultez [Organiser le travail avec des étiquettes](/fr/guides/projects/organizing-with-labels/).
- **Verrouiller** et **Unlock** font passer le projet de l'état modifiable à l'état lecture seule, et inversement.

Les tuiles comptent le contenu du projet :

| Tuile | Affiche |
|---|---|
| **Tables** | Les tables du projet. |
| **Workflows** | Les workflows du projet. |
| **Étapes** | Les étapes de tous les workflows. |
| **Variables** | Les variables du projet. |
| **Tables publiées** | Les tables que vous avez publiées. |
| **Taille des données** | Ce que stockent les tables du projet. Cliquez dessus pour ouvrir **Stockage**. Consultez [Gérer le stockage](/fr/guides/projects/managing-storage/). |

Si certaines lignes du projet sont filtrées à votre intention, **Taille des données** affiche un tiret, car le total ne serait pas exact.

**Coming up** répertorie les trois prochaines exécutions planifiées avec le nom de leur workflow, ainsi que le nombre de capteurs actifs. **View schedules ›** ouvre **Schedules & sensors**.

**Project defaults** affiche les valeurs **Environnement**, **Stockage des tables**, **Accès** et **Écriture ERP** que les workflows et les étapes utilisent, sauf s'ils définissent les leurs. **Change settings ›** ouvre la page où vous les modifiez.

Les boutons de l'en-tête sont les suivants :

- **Rapport du projet** génère un rapport du projet au format **Document PDF** ou **HTML interactif**.
- **Exporter l'archive** enregistre le projet sous forme d'archive.
- **Actualiser** recharge les tuiles et les listes de la page.

## Variables

La page **Variables** répertorie les variables du projet dans une grille. Un workflow ou une étape fait référence à une variable par son nom, sous la forme `{name}`, et la variable propre à un workflow remplace une variable de projet du même nom.

La grille affiche **Nom**, **Valeur**, **Mémo**, **Dernière mise à jour** et **Par**. Utilisez **Filtre** pour restreindre la liste, **Nouvelle variable** pour en ajouter une, et **Modifier** ou **Supprimer** pour la ligne sélectionnée.

## Schedules & Sensors

![Page Schedules and sensors avec une bande récapitulative et deux grilles](/images/projects/project-home-schedules.png)

Cette page indique ce qui démarre automatiquement les workflows du projet. Une bande récapitulative affiche la prochaine exécution, le nombre de planifications actives et suspendues, ainsi que le nombre de capteurs actifs.

- **Schedules** exécutent un workflow selon un calendrier. La grille affiche **Nom**, **Workflow**, **Exécutions** (le calendrier et son fuseau horaire), **Prochaine exécution** et **Statut**.
- **Capteurs** exécutent un workflow lorsque de nouvelles données arrivent. La grille affiche **Nom**, **Watches**, **Début** (le workflow), **Last triggered** et **Statut**.

**Statut** vaut **Actif**, **Paused** ou, pour un capteur qui rencontre un problème, **Failing**. Chaque grille propose **New schedule** ou **Nouveau capteur**, **Modifier**, **Supprimer** et **Filtre**. Ouvrez **Actions** pour **Activate** ou **Deactivate** la ligne sélectionnée.

**Calendar view** affiche les exécutions à venir dans un calendrier, ce qui vous permet de repérer les conflits de planification.

## Access & Sharing

Cette page définit qui peut accéder au projet et à ses données.

- **Project access** définit **Who can open this project** : **Tous les membres de l'espace de travail**, **Groupes de sécurité spécifiques uniquement** ou **Membres spécifiques uniquement**. **Edit groups ›** et **Edit members ›** ouvrent les listes dans lesquelles choisir.
- **Dashboard audience** définit **Default audience for new dashboards** : tout le monde dans le projet, ou des groupes spécifiques. Chaque tableau de bord peut modifier sa propre audience. Consultez [Contrôler qui peut voir un tableau de bord](/fr/guides/dashboards/control-who-can-see-a-dashboard/).
- **Partages de données** répertorie les projets qui peuvent lire les tables de celui-ci. Consultez [Partager des données entre projets](/fr/guides/projects/managing-projects/#partager-des-données-entre-projets).

## Data & Connections

![Page Data and connections avec les connexions, le stockage des tables et l'écriture ERP](/images/projects/project-home-data.png)

Ces paramètres s'appliquent à chaque workflow et à chaque étape du projet, sauf si un workflow ou une étape définit les siens.

- **Environnement de connexion** choisit les identifiants qu'une étape utilise lorsqu'elle n'en choisit pas. La page vous avertit lorsqu'une connexion du projet n'a aucune configuration pour l'environnement sélectionné.
- **Compte de documents par défaut** choisit où les étapes lisent et écrivent les fichiers.
- **Stockage de table par défaut** choisit où les nouvelles tables sont créées.
- **Time travel retention** définit pendant combien de jours les versions antérieures des données de table sont conservées. Les tables qui héritent de ce paramètre conservent également un historique plus long. L'historique déjà expiré ne peut pas être récupéré.
- **Mode de comptabilisation** définit la manière dont le projet envoie les écritures de journal aux ERP connectés. C'est un plafond pour le projet : l'exécution d'un workflow ne peut pas comptabiliser de façon plus permissive que ce paramètre. **Réel** comptabilise normalement. **Simuler** construit et valide, mais ne comptabilise jamais et ne contacte jamais l'ERP. **Désactivé** ignore les étapes de comptabilisation.
- **Write authorizations** indique combien de connexions ERP sont autorisées pour la comptabilisation. Les administrateurs peuvent cliquer sur **Manage authorizations ›**.

## Apps & Branding

Cette page couvre les applications construites sur les données du projet.

- **Applications Panel** indique combien d'applications sont construites sur le projet. **Open Panel apps ›** les ouvre, et **Nouvelle application Studio** en démarre une.
- **Branding** définit le logo et les couleurs que les applications du projet utilisent. **Edit branding ›** ouvre les paramètres.
- **Home tile image** est l'image affichée sur la tuile du projet dans la page Home. Cliquez sur **Choisir…** pour sélectionner une image, ou sur **Effacer** pour la supprimer.
