## Description

Sélectionnez une étape ou un workflow dans un projet et son panneau de détails s'ouvre. En
bas, une section **Documentation** affiche une page que Weave rédige à son sujet à partir
des paramètres enregistrés du projet. Le panneau de détails d'une table affiche à la place ses **Colonnes**,
avec le type et la description de chaque colonne ; la page ci-dessous décrit
ce que Weave et les assistants IA lisent pour une table :

- pour une table, les étapes qui l'écrivent et la lisent, ainsi que ses colonnes ;
- pour une étape, ce qu'elle fait et où elle s'exécute ;
- pour un workflow, ses étapes dans l'ordre et les tables qu'il lit et écrit.

La page est rédigée chaque fois que vous sélectionnez l'élément, à partir des paramètres tels qu'ils
sont enregistrés à ce moment-là ; elle n'est donc jamais obsolète et il n'y a rien à
actualiser manuellement. Aucune IA n'intervient : elle fonctionne même lorsqu'aucun fournisseur d'IA
n'est disponible. Après un enregistrement dans le même panneau de détails, par exemple une nouvelle description,
la page est rédigée de nouveau.

Weave AI, le chat de l'onglet **Weave** d'un projet, et les assistants IA connectés
via MCP peuvent lire la même page. Consultez [Pour les assistants IA](#pour-les-assistants-ia).

## Page d'une table

- **La description** : le **Mémo** de la table, affiché sous forme de citation. PlaidCloud
  définit le mémo *Created dynamically* sur une table créée par une étape ; celui-ci n'est pas
  affiché, car il n'apporte aucune information sur la table.
- **Written by** et **Read by** : chaque étape, par son nom, avec son type d'étape et
  les workflows dans lesquels elle figure. *(disabled)* suit un workflow dans lequel l'étape
  est désactivée, et *not in any workflow* signale une étape qui ne figure dans aucun workflow. Une étape
  dont le nom de table contient une variable qui peut ou non désigner cette table
  est listée avec *depending on the values of its variables*. Une étape qui indique
  seulement un nom partagé par plusieurs tables est listée avec, par exemple, *unless it
  means another of the 2 tables with this name*, en ne comptant que les tables que vous pouvez
  ouvrir. Une étape Table : vider, Table : supprimer ou Table : suppression sur place compte comme écrivant la table qu'elle modifie, et
  une étape qui lit une table et la réécrit est listée dans les deux.
- **No step in this project reads this table.** signifie qu'aucune étape de ce projet
  ne la liste comme source. La page ne vérifie pas les tableaux de bord, les exports, les autres
  projets ni rien d'autre en dehors des étapes du projet.
- **Colonnes** : chaque colonne et son type, avec sa description issue de **Propriétés de la
  colonne** lorsqu'il y en a une.

## Page d'une étape

**What it does** donne une phrase pour chaque action de l'étape :

| Étape | Ce que dit la page |
| --- | --- |
| Allocation : Split | Quelle valeur elle fractionne et à partir de quelle table, sur quelles colonnes, avec quelle colonne d'inducteur, et comment chaque part est calculée, par exemple « Each `product`'s share is its `weight` divided by the total `weight` for the same `cost_center`, `year` and `month`. » Les colonnes sont nommées comme dans les tables source et d'inducteurs. Un filtre sur la source ou l'inducteur de l'étape est indiqué, et les tables qu'elle écrit sont nommées. |
| Allocation : fractionnement selon la dimension | Quelle valeur elle fractionne et à partir de quelle table, quelle colonne d'inducteur elle utilise, et chaque table qu'elle écrit, y compris ses tables de mappage, de chemin et de synthèse. |
| Importation | Le ou les fichiers qu'elle importe et la table dans laquelle elle importe. |
| Exportation | La table qu'elle exporte et le fichier qu'elle écrit. |
| Extraction : SQL sans source listée | Qu'elle exécute une requête SQL, et la table qu'elle écrit. |
| Table : vider, Table : supprimer, Table : suppression sur place | Qu'elle vide sa table, la supprime ou en supprime des lignes ou, lorsqu'elle choisit des tables par recherche ou par dossier, qu'elle agit sur les tables que ce paramètre sélectionne. |
| Importer la table de projet externe | Qu'elle copie une table d'un autre projet dans une table de celui-ci. |
| Une étape qui exécute un autre workflow | Le workflow qu'elle exécute et comment : lorsque ses conditions sont remplies, dans une boucle, en tant que macro (une fois pour chaque ligne de sa table source, pour une exécution simultanée), ou par inclusion. Un workflow choisi par une variable est affiché sous le nom que l'étape lui donne, et un workflow d'un autre projet est décrit comme tel. Toute table que l'étape lit elle-même, comme la table qu'une boucle parcourt, est également listée. |
| Toute autre étape | Les tables qu'elle lit et les tables qu'elle écrit. |

La page indique ensuite où l'étape s'exécute — *It is step 3 in* suivi du
workflow, numéroté comme dans la liste des étapes du workflow — ou qu'elle ne figure dans aucun
workflow.

Une table que l'étape nomme au moyen d'une variable est affichée sous son nom, suivi de
*(named by a variable)*.

## Page d'un workflow

- **Étapes** : numérotées comme dans la liste des étapes du workflow, avec le type
  de chaque étape et la table qu'elle écrit, ou le workflow qu'elle exécute. Les étapes d'un workflow qu'il
  inclut sont listées à leur place, comme la liste des étapes les présente.
- **Reads from outside this workflow** : tables qu'une étape lit avant qu'aucune étape de ce
  workflow ne les écrive.
- **Writes** : tables que les étapes du workflow écrivent.

Les étapes désactivées sont listées dans **Étapes** mais exclues des deux autres listes. La page
l'indique, car une table qu'écrit une étape désactivée peut alors être listée comme lue
depuis l'extérieur. Les tables utilisées par un workflow qu'exécute l'une de ses étapes figurent sur la
page propre à ce workflow.

## Dossier de passation pour l'ensemble du projet

Pour transmettre un projet, par exemple à un client à la fin d'une mission,
téléchargez toutes les pages en une seule fois. Dans la fenêtre **Projets**, sélectionnez un projet
et choisissez **Télécharger le dossier de passation** dans le menu **Actions** ou dans le menu
contextuel. Vous avez besoin d'un accès en lecture au projet, à ses étapes, à ses
workflows et à ses tables.

Le dossier est un fichier Markdown unique, nommé d'après le projet — par exemple *Month
End handover.md* — et rédigé à partir des paramètres enregistrés au moment du téléchargement. Il s'ouvre sur la description du projet
et le décompte de son contenu, puis comporte quatre sections :

- **Workflows** : la page de chaque workflow. Les workflows qu'aucun autre workflow n'exécute
  viennent en premier, par nom, et chacun est suivi des workflows qu'il exécute, dans
  l'ordre où il les exécute. Un workflow exécuté depuis deux endroits n'est listé qu'une fois.
- **Tables** : la page de chaque table, comme ci-dessus, y compris ses colonnes et leurs
  descriptions.
- **Metrics** : la version actuelle de chaque définition de métrique, en phrases
  simples : ce qu'elle mesure, à partir de quelle table, les tables qu'elle joint,
  les lignes qu'elle utilise, ses lignes réelles et budgétaires, ses périodes et les axes selon lesquels elle peut être
  ventilée. Une métrique construite à partir d'autres indique
  comment, par exemple *Revenue divided by Orders*. Consultez [Définitions de
  métriques](/fr/integrations/ai-coding-agents/metric-definitions/).
- **Allocation models** : chaque chaîne d'étapes d'allocation qui alimentent
  les suivantes, avec l'étape ou les étapes par lesquelles elle se termine et le fractionnement de chaque étape, dans l'ordre
  d'exécution. Une étape qui ne s'exécute dans aucun workflow est exclue. Un modèle porte le nom de son workflow, ou du dossier que ses workflows
  partagent. Lorsqu'il n'a pas de tel nom, le partage avec un autre modèle, ou le tire
  d'un élément que votre rôle masque, il est intitulé d'après l'une de ses étapes.
  Un modèle d'allocation n'a pas de page propre en dehors du dossier.

Le dossier suit les mêmes règles qu'une page unique pour ce que votre rôle masque. Un
workflow, une table ou un modèle d'allocation que vous ne pouvez pas ouvrir est exclu et comptabilisé en
haut de page, par exemple *It leaves out 2 workflows and 5 tables you can't
open.* Une étape que vous ne pouvez pas ouvrir n'est jamais nommée, comme sur une page unique.

## Ce que votre rôle masque

Une table, une étape ou un workflow peut être masqué au rôle Gestionnaire ou Explorateur. Une
page ne nomme jamais un élément que votre rôle masque :

- Une étape que vous ne pouvez pas ouvrir est comptabilisée — par exemple, *2 more steps you can't open*
  — et conserve son numéro dans la liste des étapes d'un workflow.
- Une table, une étape ou un workflow que vous ne pouvez pas ouvrir se lit comme un élément qui n'existe plus
  — par exemple, *a table you can't open or that no longer exists* — de sorte
  qu'une page ne peut pas servir à savoir si un élément masqué existe. Les étapes
  exclues des listes d'un workflow de cette manière sont signalées, car une table qu'une d'elles
  écrit peut alors être listée comme lue depuis l'extérieur. Une table qu'une
  étape nomme et que vous ne pouvez pas ouvrir, ou qui n'existe pas, est affichée sous le nom
  que l'étape lui donne, suivi de *(not a table you can open)*, et un workflow
  de même par *(not a workflow you can open)*.
- Demander la page d'un élément que votre rôle masque renvoie la même réponse que s'il n'existait pas.

Un Architecte peut tout ouvrir ; les pages d'un Architecte indiquent donc *a deleted
table*, *(table not found)*, *A deleted step* ou *(workflow not found)* à la place.

## Ce qu'elle ne couvre pas

- **Les nombres de lignes, les tailles et les heures de mise à jour.**
- **Les tables qu'une étape n'atteint que par son texte SQL ou une expression.** La
  page liste les tables qu'une étape nomme dans ses paramètres.
- **Les modifications non enregistrées.** La page décrit les paramètres enregistrés.

<Aside type="note">
La page n'interprète pas vos données et ne juge pas si une étape est correcte. Elle
énonce ce que disent les paramètres enregistrés, en langage clair.
</Aside>

## Pour les assistants IA

- **Weave AI** peut lire la page d'une table, d'une étape ou d'un workflow lorsque vous l'interrogez à son sujet
  dans une conversation ouverte sur un projet, et répondre à partir de ce que dit la page.
  Consultez [Chat Weave AI](/fr/guides/ai-assistant/weave-tab/#chat-weave-ai).
- **Les assistants IA connectés via MCP** peuvent lire la même page avec l'outil
  `doc_describe`, en indiquant le projet, si l'élément est une table, une étape ou un
  workflow, et son identifiant. Il faut un accès en lecture aux étapes, aux workflows et aux tables,
  et les mêmes règles s'appliquent pour ce que votre rôle masque. Consultez [Agents IA
  (MCP)](/fr/integrations/ai-coding-agents/).
