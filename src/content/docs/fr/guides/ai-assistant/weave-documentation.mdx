## Description

Sélectionnez une étape ou un workflow dans un projet : son panneau de détails
s'ouvre. En bas, une section **Documentation** affiche une page que Weave rédige à son sujet à partir des
paramètres enregistrés du projet. Le panneau de détails d'une table affiche à la place ses **Colonnes**,
avec le type et la description de chacune ; la page ci-dessous décrit
ce que Weave et les assistants IA lisent pour une table :

- pour une table, les étapes qui l'écrivent et la lisent, ainsi que ses colonnes ;
- pour une étape, ce qu'elle fait et où elle s'exécute ;
- pour un workflow, ses étapes dans l'ordre, ainsi que les tables qu'il lit et écrit.

La page est rédigée chaque fois que vous sélectionnez l'élément, à partir des paramètres tels qu'ils
sont enregistrés à cet instant : elle n'est donc jamais obsolète et il n'y a rien à
actualiser manuellement. Aucune IA n'intervient, elle fonctionne donc même lorsqu'aucun fournisseur d'IA
n'est disponible. Après un enregistrement dans le même panneau de détails, par exemple une nouvelle description,
la page est rédigée à nouveau.

Weave AI, le chat de l'onglet **Weave** d'un projet, et les assistants IA connectés
via MCP peuvent lire cette même page. Consultez [Pour les assistants IA](#pour-les-assistants-ia).

## La page d'une table

- **La description** — le **Mémo** de la table, affiché sous forme de citation. PlaidCloud
  définit le mémo *Created dynamically* sur une table créée par une étape ; celui-ci n'est pas
  affiché, car il ne dit rien sur la table.
- **Écrite par** et **Lue par** — chaque étape, par son nom, avec son type d'étape et
  les workflows dans lesquels elle figure. *(désactivée)* suit un workflow où l'étape
  est désactivée, et *dans aucun workflow* signale une étape qui ne figure dans aucun workflow. Une étape
  dont le nom de table contient une variable qui peut désigner ou non cette table
  est listée avec *selon les valeurs de ses variables*. Une étape qui ne donne
  qu'un nom partagé par plusieurs tables est listée avec, par exemple, *sauf s'il s'agit d'une autre des 2 tables portant ce nom*, en ne comptant que les tables que vous pouvez
  ouvrir. Une étape Table : vider, Table : supprimer ou Table : suppression sur place
  compte comme écrivant la table qu'elle modifie, et
  une étape qui lit une table et la réécrit est listée dans les deux cas.
- **Aucune étape de ce projet ne lit cette table.** signifie qu'aucune étape de ce projet
  ne la liste comme source. La page ne vérifie ni les tableaux de bord, ni les exports, ni les autres
  projets, ni rien de ce qui se trouve hors des étapes du projet.
- **Colonnes** — chaque colonne et son type, avec sa description issue de **Propriétés de la colonne** lorsqu'elle est renseignée.

## La page d'une étape

**Ce qu'elle fait** donne une phrase pour chaque action de l'étape :

| Étape | Ce que dit la page |
| --- | --- |
| Allocation: Split | Quelle valeur elle fractionne et de quelle table, sur quelles colonnes, avec quelle colonne d'inducteur, et comment chaque part est calculée — par exemple, « La part de chaque `product` est son `weight` divisé par le `weight` total pour les mêmes `cost_center`, `year` et `month`. » Les colonnes sont nommées comme le font les tables source et d'inducteur. Un filtre sur la source ou sur l'inducteur de l'étape est signalé, et les tables qu'elle écrit sont nommées. |
| Allocation : fractionnement selon la dimension | Quelle valeur elle fractionne et de quelle table, quelle colonne d'inducteur elle utilise, et chaque table qu'elle écrit, y compris ses tables de correspondance, de chemin et de synthèse. |
| Import | Le ou les fichiers qu'elle importe et la table dans laquelle elle importe. |
| Export | La table qu'elle exporte et le fichier qu'elle écrit. |
| Extraire SQL sans source listée | Qu'elle exécute une requête SQL, et la table qu'elle écrit. |
| Table : vider, Table : supprimer, Table : suppression sur place | Qu'elle vide sa table, la supprime ou en supprime des lignes ou, lorsqu'elle choisit les tables par recherche ou par dossier, qu'elle agit sur les tables désignées par ce paramètre. |
| Importer la table de projet externe | Qu'elle copie une table d'un autre projet dans une table de celui-ci. |
| Une étape qui exécute un autre workflow | Le workflow qu'elle exécute et comment : lorsque ses conditions sont remplies, dans une boucle, comme macro (une fois pour chaque ligne de sa table source, ou en exécution simultanée), ou par inclusion. Un workflow choisi par une variable est affiché sous le nom que l'étape lui donne, et un workflow d'un autre projet est décrit comme tel. Toute table que l'étape lit elle-même, comme la table qu'une boucle parcourt, est également listée. |
| Toute autre étape | Les tables qu'elle lit et les tables qu'elle écrit. |

La page indique ensuite où l'étape s'exécute — *C'est l'étape 3 de* suivi du
workflow, numérotée comme dans la liste des étapes du workflow — ou qu'elle ne figure dans aucun
workflow.

Une table que l'étape désigne par une variable est affichée sous son nom, suivi de
*(désignée par une variable)*.

## La page d'un workflow

- **Étapes** — numérotées comme dans la liste des étapes du workflow, avec le type de chaque étape
  et la table qu'elle écrit, ou le workflow qu'elle exécute. Les étapes d'un workflow qu'il
  inclut sont listées à leur place, comme les affiche la liste des étapes.
- **Lectures hors de ce workflow** — tables qu'une étape lit avant qu'une étape de
  ce workflow ne les écrive.
- **Écritures** — tables que les étapes du workflow écrivent.

Les étapes désactivées sont listées dans **Étapes** mais exclues des deux autres listes. La page
le signale, car une table qu'écrit une étape désactivée peut alors figurer parmi les lectures hors du workflow. Les tables utilisées par un workflow qu'une de ses étapes exécute figurent sur la
page propre à ce workflow.

## Un dossier de passation pour l'ensemble du projet

Pour transmettre un projet, par exemple à un client à la fin d'une mission,
téléchargez toutes les pages d'un seul coup. Dans la fenêtre **Projets**, sélectionnez un projet
et choisissez **Télécharger le dossier de passation** dans le menu **Actions** ou dans le menu
contextuel. Vous avez besoin d'un accès en lecture au projet, à ses étapes, à ses
workflows et à ses tables.

Le dossier est un seul fichier Markdown, nommé d'après le projet — par exemple *Month
End handover.md* — et rédigé à partir des paramètres enregistrés au moment du téléchargement. Il s'ouvre sur la description du projet
et le décompte de son contenu, puis comprend quatre sections :

- **Workflows** — la page de chaque workflow. Les workflows qu'aucun autre workflow n'exécute
  viennent en premier, par nom, et chacun est suivi des workflows qu'il exécute, dans
  l'ordre où il les exécute. Un workflow exécuté depuis deux endroits n'est listé qu'une fois.
- **Tables** — la page de chaque table, comme ci-dessus, avec ses colonnes et leurs
  descriptions.
- **Métriques** — la version actuelle de chaque définition de métrique, en phrases
  simples : ce qu'elle mesure, à partir de quelle table, les tables qu'elle joint,
  les lignes qu'elle utilise, ses lignes réelles et budgétaires, ses périodes et les axes selon lesquels elle peut être ventilée. Une métrique construite à partir d'autres indique
  comment, par exemple *Revenue divided by Orders*. Consultez [Définitions de
  métriques](/fr/integrations/ai-coding-agents/metric-definitions/).
- **Modèles d'allocation** — chaque chaîne d'étapes d'allocation qui s'alimentent
  mutuellement, avec la ou les étapes par lesquelles elle se termine et le fractionnement de chaque étape, dans l'ordre
  d'exécution. Une étape qui ne s'exécute dans aucun workflow est exclue. Un modèle porte le nom de son workflow, ou du dossier que ses workflows
  partagent. Lorsqu'il n'a pas de tel nom, qu'il le partage avec un autre modèle, ou qu'il le tire
  d'un élément que votre rôle masque, il est intitulé d'après l'une de ses étapes. Un modèle d'allocation n'a pas de page propre en dehors du dossier.

Le dossier suit les mêmes règles qu'une page seule pour ce que votre rôle masque. Un
workflow, une table ou un modèle d'allocation que vous ne pouvez pas ouvrir est exclu et compté
en tête, par exemple *Il exclut 2 workflows et 5 tables que vous ne pouvez pas
ouvrir.* Une étape que vous ne pouvez pas ouvrir n'est jamais nommée, comme sur une page seule.

## Ce que votre rôle masque

Une table, une étape ou un workflow peut être masqué au rôle Gestionnaire ou Explorateur. Une
page ne nomme jamais un élément que votre rôle masque :

- Une étape que vous ne pouvez pas ouvrir est comptée — par exemple, *2 autres étapes que vous ne pouvez pas ouvrir*
  — et conserve son numéro dans la liste des étapes d'un workflow.
- Une table, une étape ou un workflow que vous ne pouvez pas ouvrir s'affiche comme un élément qui n'existe plus
  — par exemple, *une table que vous ne pouvez pas ouvrir ou qui n'existe plus* — de sorte
  qu'une page ne permet pas de savoir si un élément masqué existe. Les étapes
  exclues ainsi des listes d'un workflow sont signalées, car une table que l'une d'elles
  écrit peut alors figurer parmi les lectures hors du workflow. Une table qu'une
  étape désigne et que vous ne pouvez pas ouvrir, ou qui n'existe pas, est affichée sous le nom
  que lui donne l'étape, suivi de *(pas une table que vous pouvez ouvrir)*, et un workflow
  de même par *(pas un workflow que vous pouvez ouvrir)*.
- Demander la page d'un élément que votre rôle masque renvoie la même réponse que s'il n'existait pas.

Un Architecte peut tout ouvrir ; les pages d'un Architecte indiquent donc *une table supprimée*,
*(table introuvable)*, *Une étape supprimée* ou *(workflow introuvable)* à la place.

## Ce qui n'est pas couvert

- **Les nombres de lignes, les tailles et les heures de mise à jour.**
- **Les tables qu'une étape n'atteint que par son texte SQL ou une expression.** La
  page liste les tables qu'une étape nomme dans ses paramètres.
- **Les modifications non enregistrées.** La page décrit les paramètres enregistrés.

<Aside type="note">
La page n'interprète pas vos données et ne juge pas si une étape est correcte. Elle
énonce en langage clair ce que disent les paramètres enregistrés.
</Aside>

## Pour les assistants IA

- **Weave AI** peut lire la page d'une table, d'une étape ou d'un workflow lorsque vous l'interrogez
  à son sujet dans une conversation ouverte sur un projet, et répondre à partir de ce que dit la page.
  Consultez [Chat Weave AI](/fr/guides/ai-assistant/weave-tab/#chat-weave-ai).
- **Les assistants IA connectés via MCP** peuvent lire la même page avec l'outil
  `doc_describe`, en indiquant le projet, si l'élément est une table, une étape ou un
  workflow, et son identifiant. Cela exige un accès en lecture aux étapes, aux workflows et aux tables,
  et suit les mêmes règles pour ce que votre rôle masque. Consultez [Agents IA
  (MCP)](/fr/integrations/ai-coding-agents/).
