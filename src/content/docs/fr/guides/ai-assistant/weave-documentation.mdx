## Description

Sélectionnez une table, une étape ou un workflow dans un projet et son panneau de détails s'ouvre. En
bas, une section **Documentation** affiche une page que Weave rédige à son sujet à partir des
paramètres enregistrés du projet :

- pour une table, les étapes qui l'écrivent et la lisent, ainsi que ses colonnes ;
- pour une étape, ce qu'elle fait et où elle s'exécute ;
- pour un workflow, ses étapes dans l'ordre et les tables qu'il lit et écrit.

La page est rédigée à chaque sélection de l'élément, à partir des paramètres tels qu'ils
sont enregistrés à ce moment-là ; elle n'est donc jamais périmée et il n'y a rien à
actualiser manuellement. Aucune IA n'intervient, elle fonctionne donc lorsqu'aucun fournisseur d'IA n'est
disponible. Après un enregistrement dans le même panneau de détails, comme une nouvelle description,
la page est rédigée de nouveau.

Weave AI, le chat de l'onglet **Weave** d'un projet, et les assistants IA connectés
via MCP peuvent lire la même page. Consultez [Pour les assistants IA](#pour-les-assistants-ia).

## La page d'une table

- **La description** — le **Mémo** de la table, affiché sous forme de citation. PlaidCloud
  attribue le mémo *Created dynamically* à une table créée par une étape ; celui-ci n'est pas
  affiché, car il ne dit rien sur la table.
- **Écrite par** et **Lue par** — chaque étape, par son nom, avec son type d'étape et
  les workflows dans lesquels elle figure. *(désactivée)* suit un workflow dans lequel l'étape
  est désactivée, et *dans aucun workflow* signale une étape qui n'est dans aucun. Une étape
  dont le nom de table contient une variable qui peut ou non désigner cette table est
  listée avec *selon les valeurs de ses variables*. Une étape qui ne donne
  qu'un nom partagé par plusieurs tables est listée avec, par exemple, *sauf s'il
  s'agit d'une autre des 2 tables portant ce nom*, ne comptant que les tables que vous pouvez
  ouvrir. Une étape Table : vider,
  Table : supprimer ou Table : suppression sur place compte comme écrivant la table qu'elle modifie, et
  une étape qui lit une table et la réécrit est listée dans les deux.
- **Aucune étape de ce projet ne lit cette table.** signifie qu'aucune étape de ce projet
  ne la liste comme source. La page ne contrôle ni les tableaux de bord, ni les exports, ni les autres projets,
  ni rien en dehors des étapes du projet.
- **Colonnes** — chaque colonne et son type, avec sa description issue de **Propriétés de la
  colonne** lorsqu'elle est renseignée.

## La page d'une étape

**Ce qu'elle fait** donne une phrase pour chaque chose que fait l'étape :

| Étape | Ce que dit la page |
| --- | --- |
| Allocation : fractionnement | Quelle valeur elle fractionne et à partir de quelle table, sur quelles colonnes, avec quelle colonne d'inducteur, et comment chaque part est calculée — par exemple : « La part de chaque `product` est son `weight` divisé par le `weight` total pour les mêmes `cost_center`, `year` et `month`. » Les colonnes sont nommées comme les nomment les tables source et d'inducteur. Un filtre sur la source ou l'inducteur de l'étape est signalé, et les tables qu'elle écrit sont nommées. |
| Allocation : fractionnement selon la dimension | Quelle valeur elle fractionne et à partir de quelle table, quelle colonne d'inducteur elle utilise, et toutes les tables qu'elle écrit, y compris ses tables de mappage, de chemin et de synthèse. |
| Importation | Le ou les fichiers qu'elle importe et la table dans laquelle elle importe. |
| Exportation | La table qu'elle exporte et le fichier qu'elle écrit. |
| Extraire SQL sans sources listées | Qu'elle exécute une requête SQL, et la table qu'elle écrit. |
| Table : vider, Table : supprimer, Table : suppression sur place | Qu'elle vide, supprime ou efface des lignes de sa table, ou, lorsqu'elle choisit les tables par recherche ou par dossier, qu'elle agit sur les tables que ce paramètre désigne. |
| Importer la table de projet externe | Qu'elle copie une table d'un autre projet dans une table de celui-ci. |
| Une étape qui exécute un autre workflow | Le workflow qu'elle exécute et comment : lorsque ses conditions sont remplies, dans une boucle, comme macro (une fois pour chaque ligne de sa table source, pour une exécution concurrente), ou par inclusion. Un workflow choisi par une variable est affiché sous le nom que lui donne l'étape, et un workflow d'un autre projet est décrit comme tel. Toute table que l'étape lit elle-même, comme la table parcourue par une boucle, est également listée. |
| Toute autre étape | Les tables qu'elle lit et les tables qu'elle écrit. |

La page indique ensuite où l'étape s'exécute — *C'est l'étape 3 de* suivi du
workflow, numérotée comme dans la liste des étapes du workflow — ou qu'elle n'est dans aucun
workflow.

Une table que l'étape désigne par une variable est affichée par son nom, suivi de
*(nommée par une variable)*.

## La page d'un workflow

- **Étapes** — numérotées comme dans la liste des étapes du workflow, avec le type de chaque étape
  et la table qu'elle écrit, ou le workflow qu'elle exécute. Les étapes d'un workflow qu'il
  inclut sont listées à leur place, comme les affiche la liste des étapes.
- **Lectures hors de ce workflow** — les tables qu'une étape lit avant qu'une étape de
  ce workflow ne les écrive.
- **Écritures** — les tables qu'écrivent les étapes du workflow.

Les étapes désactivées sont listées dans **Étapes** mais exclues des deux autres listes. La page
l'indique, car une table qu'écrit une étape désactivée peut alors être listée comme lue
hors du workflow. Les tables utilisées par un workflow qu'exécute l'une de ses étapes figurent sur
la page de ce workflow.

## Un dossier de passation pour tout le projet

Pour transmettre un projet, par exemple à un client à la fin d'une mission,
téléchargez toutes les pages en une fois. Dans la fenêtre **Projets**, sélectionnez un projet
et choisissez **Télécharger le dossier de passation** dans le menu **Actions** ou dans le menu
contextuel. Vous avez besoin d'un accès en lecture au projet, à ses étapes, à ses
workflows et à ses tables.

Le dossier est un fichier Markdown unique, nommé d'après le projet — par exemple *Month
End handover.md* — et rédigé à partir des paramètres enregistrés au moment du téléchargement. Il s'ouvre sur la description du projet
et un décompte de son contenu, puis comporte quatre sections :

- **Workflows** — la page de chaque workflow. Les workflows qu'aucun autre workflow n'exécute
  viennent en premier, par nom, et chacun est suivi des workflows qu'il exécute, dans
  l'ordre où il les exécute. Un workflow exécuté à partir de deux endroits n'est listé qu'une fois.
- **Tables** — la page de chaque table, comme ci-dessus, avec ses colonnes et leurs
  descriptions.
- **Métriques** — la version actuelle de chaque définition de métrique, en phrases
  simples : ce qu'elle mesure, à partir de quelle table, les tables qu'elle joint,
  les lignes qu'elle utilise, ses lignes réelles et budgétaires, ses périodes et selon quoi elle peut être
  ventilée. Une métrique construite à partir d'autres indique
  comment, par exemple *Revenue divisé par Orders*. Consultez [Définitions de
  métriques](/fr/integrations/ai-coding-agents/metric-definitions/).
- **Modèles d'allocation** — chaque chaîne d'étapes d'allocation qui s'alimentent
  mutuellement, avec la ou les étapes par lesquelles elle se termine et le fractionnement de chaque étape, dans l'ordre
  d'exécution. Une étape qui ne s'exécute dans aucun workflow est exclue. Un modèle porte le nom de son workflow, ou du dossier que ses workflows
  partagent. Lorsqu'il n'a pas de tel nom, le partage avec un autre modèle, ou le tient
  d'un élément que votre rôle masque, il est intitulé d'après l'une de ses étapes. Un modèle d'allocation n'a pas de page propre en dehors du dossier.

Le dossier suit les mêmes règles qu'une page isolée pour ce que votre rôle masque. Un
workflow, une table ou un modèle d'allocation que vous ne pouvez pas ouvrir est exclu et compté en
tête, par exemple *Il exclut 2 workflows et 5 tables que vous ne pouvez pas
ouvrir.* Une étape que vous ne pouvez pas ouvrir n'est jamais nommée, comme sur une page isolée.

## Ce que votre rôle masque

Une table, une étape ou un workflow peut être masqué pour le rôle Gestionnaire ou Explorateur. Une
page ne nomme jamais un élément que votre rôle masque :

- Une étape que vous ne pouvez pas ouvrir est comptée — par exemple, *2 autres étapes que vous ne pouvez pas ouvrir*
  — et conserve son numéro dans la liste des étapes d'un workflow.
- Une table, une étape ou un workflow que vous ne pouvez pas ouvrir se lit comme un élément qui n'existe plus
  — par exemple, *une table que vous ne pouvez pas ouvrir ou qui n'existe plus* — de sorte
  qu'une page ne peut pas servir à savoir si un élément masqué existe. Les étapes
  exclues ainsi des listes d'un workflow sont signalées, car une table qu'écrit l'une d'elles
  peut alors être listée comme lue hors du workflow. Une table qu'une
  étape désigne et que vous ne pouvez pas ouvrir, ou qui n'existe pas, est affichée sous le nom
  que lui donne l'étape, suivi de *(table que vous ne pouvez pas ouvrir)*, et un workflow
  de même par *(workflow que vous ne pouvez pas ouvrir)*.
- Demander la page d'un élément que votre rôle masque donne la même réponse que s'il n'existait pas.

Un Architecte peut tout ouvrir ; les pages d'un Architecte indiquent donc *une table supprimée*,
*(table introuvable)*, *Une étape supprimée* ou *(workflow introuvable)* à la place.

## Ce qu'elle ne couvre pas

- **Les nombres de lignes, les tailles et les heures de mise à jour.**
- **Les tables qu'une étape n'atteint que par son texte SQL ou une expression.** La
  page liste les tables qu'une étape désigne dans ses paramètres.
- **Les modifications non enregistrées.** La page décrit les paramètres enregistrés.

<Aside type="note">
La page n'interprète pas vos données et ne juge pas si une étape est correcte. Elle
énonce ce que disent les paramètres enregistrés, en langage clair.
</Aside>

## Pour les assistants IA

- **Weave AI** peut lire la page d'une table, d'une étape ou d'un workflow lorsque vous l'interrogez
  à son sujet dans une conversation ouverte sur un projet, et répondre à partir de ce que dit la page.
  Consultez [Chat Weave AI](/fr/guides/ai-assistant/weave-tab/#chat-weave-ai).
- **Les assistants IA connectés via MCP** peuvent lire la même page avec l'outil
  `doc_describe`, à partir du projet, du type d'élément (table, étape ou
  workflow) et de son identifiant. Il faut un accès en lecture aux étapes, workflows et tables,
  et les mêmes règles s'appliquent pour ce que votre rôle masque. Consultez [Agents IA
  (MCP)](/fr/integrations/ai-coding-agents/).
