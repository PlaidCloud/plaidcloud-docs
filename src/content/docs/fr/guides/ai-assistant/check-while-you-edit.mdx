## Description

Lorsque vous cliquez sur **Enregistrer** pour une étape, PlaidCloud contrôle ses paramètres et refuse
ceux qu'il ne peut pas exécuter, comme une expression qui ne se compile pas ou une colonne utilisée
d'une manière que son type n'autorise pas. Pendant que vous modifiez une étape, Weave exécute désormais la plupart de
ces contrôles au fur et à mesure et affiche ce que l'enregistrement refuserait dans une bande juste au-dessus
des boutons **Enregistrer** :

> 1 problème que l'enregistrement va refuser.

Chaque problème est répertorié sous cette ligne. Lorsqu'il désigne une ligne de l'onglet **Colonnes**, **Aller à** ouvre cet onglet avec la ligne sélectionnée.

Les contrôles lisent uniquement les paramètres de l'étape et les variables de votre projet ; ils sont donc
rapides. Ils ne bloquent jamais l'enregistrement : Enregistrer reste
disponible et exécute lui-même tous les contrôles lorsque vous cliquez dessus.

<Aside type="note">
L'enregistrement contrôle aussi quelques éléments que cette bande ne vérifie pas, comme la présence dans les tables source
et cible des colonnes que l'étape utilise, ou le renseignement des champs obligatoires. Ainsi, « Aucun problème détecté » signifie qu'aucun
des contrôles exécutés pendant la modification n'en a trouvé, et non que l'enregistrement acceptera l'étape.
</Aside>

## Ce que dit la bande

| Weave affiche | Signification |
| --- | --- |
| Recherche de problèmes dans cette étape… | Weave exécute les contrôles sur votre dernière modification. |
| 1 problème que l'enregistrement va refuser. | L'enregistrement refuserait l'étape en l'état. Chaque problème est répertorié en dessous. |
| Aucun problème détecté. L'enregistrement contrôle quelques éléments supplémentaires, comme les tables source et cible. | Les contrôles exécutés pendant la modification n'ont rien trouvé. L'enregistrement exécute quand même ses propres contrôles, dont certains que cette bande ignore. |
| Weave n'a pas pu vérifier les expressions de cette étape. … | Une partie de l'étape n'a pas pu être contrôlée ; la raison suit. Ce n'est jamais une réussite. |
| Weave n'a pas pu vérifier cette étape à l'instant. L'enregistrement la contrôle quand même. | Le contrôle ne s'est pas exécuté, par exemple parce que le serveur était occupé. Votre prochaine modification le relance. |

### Pourquoi les expressions n'ont pas pu être contrôlées

| Raison | Signification |
| --- | --- |
| Cette étape ne fait pas partie d'un workflow ; ses expressions ne peuvent donc pas être contrôlées. L'enregistrement ne les contrôle pas non plus. | Les expressions peuvent utiliser des variables de workflow ; elles sont donc contrôlées dans le workflow de l'étape. Une étape ouverte en dehors de tout workflow n'est pas contrôlée, ni ici ni par l'enregistrement. |
| Certaines de ses expressions se trouvent dans des paramètres que Weave ne sait pas encore contrôler. | L'étape conserve certaines expressions dans des paramètres que ces contrôles ne lisent pas, comme le filtre d'une seconde source. Les autres sont toujours contrôlées. |
| Sa configuration de colonnes est de celles que Weave ne sait pas encore contrôler. | L'étape décrit ses colonnes d'une façon que le contrôle ne peut pas compiler, comme le fait une Jointure multi-tables. |

Une expression qui utilise une variable que ni le workflow ni le projet ne définit
est un problème, et non une raison : « Une expression utilise la variable rate, qui n'est
définie ni dans ce workflow ni dans ce projet. » Il en va de même d'une accolade qui ne commence ni ne termine aucun
nom de variable, comme une variable à moitié saisie : « Une expression contient une accolade qui
ne fait pas partie d'un nom de variable. » L'enregistrement refuse les deux avec les mêmes phrases.

## Dans l'éditeur d'expressions

Ouvrez l'**Éditeur d'expressions** depuis une cellule **Expression** de l'onglet **Colonnes**, ou depuis **Sélectionner un sous-ensemble de données** ou **Appliquer un filtre secondaire aux données de résultat** dans l'onglet **Filtres**, et une ligne sous l'éditeur contrôle
l'expression au fil de la saisie :

| L'éditeur affiche | Signification |
| --- | --- |
| Vérification… | Weave contrôle ce que vous venez de saisir. |
| Aucune erreur détectée. | L'expression se compile comme la compile l'enregistrement. Pointez la ligne pour lire ce qu'elle ne couvre pas : Weave contrôle la syntaxe et les noms de colonnes ; certaines erreurs n'apparaissent qu'à l'exécution de l'étape. |
| Erreur : … | L'enregistrement refuserait l'expression, pour la raison indiquée. Une erreur de syntaxe est aussi signalée sur sa ligne, à côté du numéro de ligne. |
| Vérification impossible. … | L'expression n'a pas pu être contrôlée, pour l'une des raisons ci-dessus. |
| Vérification impossible à l'instant. L'enregistrement de l'étape la contrôle quand même. | Le contrôle ne s'est pas exécuté. Cliquer sur **Enregistrer** pour l'étape contrôle quand même l'expression. |

L'éditeur contrôle l'expression par rapport aux paramètres de l'étape tels qu'ils étaient lors du dernier contrôle
de l'étape par Weave, avec votre expression en place. Ouvert depuis ailleurs,
comme l'Explorateur de tables, il n'affiche aucune ligne.

## Quand elle apparaît

- Pendant que vous modifiez une étape que vous pouvez changer. Une étape qui s'ouvre en lecture seule pour votre
  rôle n'est pas contrôlée pendant la modification.
- Après chaque modification, dès que vous faites une pause. Une modification qui laisse les paramètres
  inchangés n'est pas contrôlée de nouveau.
- Elle lit les paramètres de l'étape et les variables du projet ; elle n'interroge donc jamais
  votre entrepôt de données.
