## Description

L'étape de workflow **Extraire SQL** exécute un `SELECT` en lecture seule sur les données de
votre projet et écrit le résultat dans une nouvelle table. Écrire cette requête à la main exige
de connaître les tables sources, leurs colonnes et le SQL nécessaire pour les façonner.

L'éditeur d'étape peut écrire la requête pour vous. Décrivez en langage courant le résultat voulu
et l'assistant IA produit le `SELECT` — et si vous ne lui indiquez pas
les tables à lire, il examine les tables du projet et choisit lui-même
celles qui sont pertinentes. Le SQL généré et les colonnes détectées sont présentés
pour relecture et restent entièrement modifiables avant l'enregistrement de l'étape.

<Aside type="note">
Cette fonction utilise le même modèle intégré que l'assistant IA — il n'y a **rien à
configurer**. Vous n'avez pas besoin de configurer un agent IA ni une connexion LLM par espace de travail
pour cela.
</Aside>

## Ouvrir l'étape

Dans la vue **Étapes** d'un workflow, cliquez sur **Créer une étape** et choisissez l'une des options suivantes :

- **Tables → Extraire SQL**, ou
- **AI → SQL Extract (AI Assisted)**

Les deux ouvrent le même éditeur d'étape Extraire SQL, qui comprend désormais un panneau **Generate SQL
with AI** en haut de la page Paramètres d'extraction SQL.

## Générer la requête

1. **(Facultatif) Choisissez des tables sources.** Dans la liste **Tables sources**, sélectionnez une
   ou plusieurs tables que la requête doit lire. Laissez la liste vide pour que
   l'assistant examine le projet et choisisse les tables pertinentes à votre place.
2. **Décrivez ce que vous voulez.** Dans la zone **Décrire**, écrivez le résultat attendu en langage
   courant — par exemple : *« classer chaque compte du grand livre dans un pool d'activités
   selon sa plage de numéros de compte »*.
3. **Cliquez sur Générer le SQL.** L'assistant écrit un seul `SELECT` en lecture seule,
   le valide en l'exécutant, puis renseigne :
   - l'éditeur **Requête SQL SELECT** avec l'instruction générée, et
   - la page de mappage **Sélection des données de la table** avec les colonnes détectées.

   Si vous avez laissé la liste des sources vide, les tables choisies par l'assistant sont
   resélectionnées dans la liste afin que vous voyiez ce qu'il a utilisé et puissiez l'ajuster.

## Relire et enregistrer

Le SQL généré est un point de départ, pas une boîte noire :

- **Modifiez-le librement.** L'éditeur SQL est entièrement modifiable — affinez la requête, ajoutez une
  jointure ou changez la liste des colonnes avant d'enregistrer. (Pour joindre plusieurs tables, vous pouvez
  sélectionner plusieurs tables sources, ou simplement modifier la requête générée.)
- **Choisissez une table cible.** Choisissez ou nommez la **Table cible** dans laquelle l'étape écrit
  son résultat.
- **Enregistrez l'étape.** Elle est enregistrée comme une étape Extraire SQL ordinaire et s'exécute au sein
  du workflow comme n'importe quelle autre.

<Aside type="tip">
Si l'assistant renvoie une requête qui ne s'exécute pas, l'éditeur affiche tout de même le SQL
avec l'erreur afin que vous puissiez le corriger — ou ajuster votre description et
générer de nouveau.
</Aside>

## Remarques et limites

- L'assistant n'écrit que des instructions `SELECT` **en lecture seule** ; il ne produit jamais
  de SQL `INSERT`, `UPDATE`, `DELETE` ni aucun autre SQL qui modifie des données.
- La génération **ne crée ni n'exécute** l'étape — elle se contente de rédiger la requête et
  de prévisualiser les colonnes. L'étape est créée lorsque vous l'enregistrez, et s'exécute lorsque le
  workflow s'exécute.
- La requête générée utilise les **noms d'affichage** de vos tables — chaque table est
  liée une seule fois en tête de requête sous son nom (de sorte que les colonnes, jointures et
  filtres s'écrivent avec des noms lisibles plutôt qu'avec les identifiants internes `analyzetable_…`).
  Les vrais identifiants sont rétablis automatiquement à l'enregistrement, de sorte que la requête
  s'exécute sans modification. Une table dont le nom n'est pas unique conserve son identifiant.
