## Description

Weave travaille à vos côtés dans l'éditeur de workflow et dans les formulaires d'étape. Il suggère, compte et
contrôle, mais n'enregistre jamais rien : une suggestion ne vous appartient qu'une fois que vous l'avez conservée et que vous avez enregistré
l'étape, et un contrôle ne vous empêche jamais d'enregistrer.

## Suggestions dans un formulaire d'étape

Une fois que vous avez commencé à remplir un formulaire d'étape, cliquez dans un champ vide. Lorsque Weave a une
suggestion, elle apparaît en grisé sous le champ, avec une ligne indiquant sa provenance et
un bouton **Utiliser**.

- Appuyez sur **Tabulation** ou cliquez sur **Utiliser** pour la conserver.
- Appuyez sur **Échap**, ou continuez à saisir, pour l'écarter.

Weave suggère :

- les colonnes clés d'une jointure, comme `cost_center = cost_center` ;
- le mappage des colonnes d'une nouvelle étape ;
- le filtre **WHERE** ;
- une cellule d'expression vide, et un éditeur d'expressions vide.

La ligne sous une suggestion indique sa provenance, par exemple *Used in 3 other steps that
read Freight*, *The columns of Freight* ou, pour une jointure, *These keys come from another join
step in this project that joins the same two tables.* Lorsque les clés ont seulement des noms
similaires, elle indique *These columns have similar names in both tables. Check them before you
save.*

Weave ne fait des suggestions qu'à partir des étapes que vous pouvez voir, et écarte tout ce qui empêcherait
l'enregistrement de l'étape. Un champ qui a déjà une valeur, et un formulaire en lecture seule, ne reçoivent aucune suggestion.
Le mappage des colonnes n'est suggéré que pour les nouvelles étapes.

**Suggest settings**, dans le menu contextuel d'une étape, la palette de commandes et la liste `/` du dock,
demande d'un coup toutes les suggestions pour l'étape.

## Ce qui vient ensuite

Après que vous avez ajouté une étape au canevas, un bouton **What next?** apparaît à sa droite. Cliquez dessus
pour obtenir jusqu'à trois vignettes, chacune correspondant à un type d'étape, comme **Résumer**, **Look up** ou
**Exportation : CSV**. Une vignette ouvre le formulaire de cette étape, rempli et pas encore enregistré.

Weave suggère les étapes qui viennent le plus souvent ensuite dans ce projet. Un projet avec peu
d'historique reçoit à la place des étapes suivantes courantes. **What comes next?** dans le menu contextuel, la
palette de commandes et le dock fait de même.

## Compter les lignes avant d'enregistrer

Le bandeau au-dessus de **Enregistrer** dans un formulaire d'étape indique comment l'étape s'est exécutée la dernière fois, par exemple *Last run
46,800 rows, ended 11 Nov 06:12 UTC*, ou **Not run yet**.

Cliquez sur **Count rows** pour compter ce que l'étape écrirait avec les paramètres affichés,
sans l'enregistrer ni l'exécuter :

> This change: 46,912 rows (last run 46,800; usually 45,100 to 47,300, compared with the
> last 8 runs)

Cliquez sur **Show the rows** pour afficher les 20 premières lignes. Une ligne sous le décompte indique la portée de
l'étape : cliquez sur **Afficher les étapes** ou sur **Show the dashboards** pour voir ce qui lit sa
sortie.

- Le comptage fonctionne pour les étapes Extract, Lookup, Join (interne, externe et anti), Union et Union All.
  Les autres étapes indiquent **No preview for this step type yet**.
- Une étape qui ne peut pas être comptée en indique la raison, par exemple une table qu'elle lit qui n'a pas encore été
  construite.
- Le comptage s'arrête au bout de 5 secondes.
- Si l'accès aux lignes limite ce que vous pouvez voir, le décompte porte sur les lignes que vous pouvez voir, et l'indique.

**Aperçu** dans le menu contextuel d'une étape, la palette de commandes ou le dock donne la même
ligne de dernière exécution et le même décompte.

## Voir les données d'une étape sur le canevas

Placez le pointeur sur une étape qui écrit une table. Une petite fenêtre affiche la table, ses lignes
et la date de la dernière exécution de l'étape, avec :

- **Show the first rows** — lit les 10 premières lignes, sous votre identité, et les conserve avec l'heure
  à laquelle elles ont été lues.
- **Ouvrir la table** — ouvre la table dans l'Explorateur de tables.
- **Demander à Weave** — ouvre le dock sur la table.

Toute personne qui peut lire les tables du projet voit cette fenêtre, y compris les membres qui peuvent seulement consulter
le workflow.

## Contrôlé lorsque vous exécutez

Lorsque vous exécutez un workflow, avec **Exécuter le workflow**, une plage d'étapes ou **Exécuter la sélection**, Weave
contrôle ses paramètres et sa structure, avec les mêmes contrôles que **Vérifier** effectue sur eux. Si tout est
correct, vous ne voyez rien. Si quelque chose ne va pas, un bandeau au-dessus du canevas indique *Weave found 2
problems in the workflow "Month-End Close"*, suivi du premier problème :

- **Examiner** ouvre le résultat complet dans la fenêtre Vérification Weave.
- **Stop run** arrête l'exécution. Il apparaît pendant l'exécution, lorsqu'un problème est une
  erreur et non un avertissement.

Chaque étape présentant un problème reçoit une marque sur le canevas, qui nomme le problème lorsque vous la pointez.
Weave ne contrôle de nouveau qu'après que vous avez enregistré une modification d'une étape ou du workflow, et
n'affiche le bandeau que pour les problèmes qu'il ne vous a pas déjà montrés. Le lignage, les colonnes de l'entrepôt
de données et la sécurité au niveau des lignes sont toujours contrôlés lorsque vous cliquez sur **Vérifier**. Pointez
**Vérifier** pour voir quand les paramètres ont été contrôlés pour la dernière fois.

## Lorsqu'une étape échoue

Une étape dont la dernière exécution a échoué porte un point rouge sur le canevas : *Last run failed. Select it to
see why.* Sélectionnez-la, et la carte **Dernière erreur d'exécution** de l'Inspecteur comporte un bouton :

- **Corriger**, lorsque Weave peut proposer une correction. Consultez
  [Corriger les erreurs de workflow avec l'IA](/fr/guides/ai-assistant/fixing-workflow-errors/).
- **Demander à Weave** sinon, ainsi que sur un avertissement. Weave explique l'erreur, et répond aux
  erreurs qu'il connaît sans appeler de modèle d'IA.

Le **⋯** à côté contient les autres actions Weave. Les messages d'erreur ailleurs proposent aussi
**Demander à Weave** : la boîte de dialogue **Échec de l'action**, une étape qui n'a pas pu être enregistrée, un workflow
qui n'a pas pu démarrer et une importation CSV en échec.

## Weave en train de travailler sur un workflow

Pendant que Weave exécute une tâche sur un workflow, comme une construction ou une correction, son icône rejoint celles des personnes
qui consultent le workflow sur le canevas. Pointez-la pour voir *Weave, working for* et le nom de
la personne pour laquelle il travaille.

Le bouton de commentaires de la barre d'outils du canevas ouvre les commentaires du workflow. Consultez
[Commentaires et @Weave](/fr/guides/ai-assistant/weave-team/#commentaires-et-weave).

<Aside type="note">
Les suggestions, les décomptes, la fenêtre du canevas et le contrôle à l'exécution lisent votre projet sous votre identité, et
ne modifient rien.
</Aside>
