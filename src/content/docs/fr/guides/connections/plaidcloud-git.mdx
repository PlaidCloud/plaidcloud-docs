Une **connexion PlaidCloud Git** dirige un workflow, ou le build d'une application Panel serveur, vers un dépôt hébergé sur le serveur Git géré propre à votre espace de travail. Ce serveur Git étant hébergé pour vous à l'adresse `git.<your-workspace>.plaid.cloud` et vous étant déjà connecté via votre connexion PlaidCloud habituelle, le formulaire de connexion est beaucoup plus simple que celui d'un fournisseur Git externe : il n'y a ni URL de serveur à saisir, ni nom d'utilisateur, jeton ou clé SSH à gérer.

<Aside type="note">Vous ne saisissez jamais d'URL de serveur ni d'identifiants pour une connexion PlaidCloud Git. Le serveur Git de votre espace de travail et votre accès à celui-ci sont gérés automatiquement à partir de votre connexion PlaidCloud (SSO compris) : il n'y a donc aucun jeton à générer, à stocker ou à renouveler.</Aside>

## Quand l'utiliser

Utilisez une connexion PlaidCloud Git chaque fois que le dépôt à lire se trouve dans [PlaidCloud Git](/fr/guides/git/), le service Git intégré à votre espace de travail, plutôt que sur un hôte externe. Le cas d'usage le plus courant est l'automatisation des builds d'applications **Panel serveur** ou **Dash** à partir d'un dépôt géré : un push sur une branche reconstruit et redéploie l'application, sans compte GitHub externe ni jeton d'accès personnel.

Pour un dépôt hébergé sur un service externe (GitHub, GitLab, Bitbucket, Forgejo ou Gitea), utilisez plutôt une [connexion Git externe](/fr/reference/connectors/git/). Ces connexions conservent le formulaire complet avec une **Server URL**, une authentification par utilisateur/jeton ou SSO, ainsi que les onglets **SSL** et **SSH**.

## Créer une connexion PlaidCloud Git

1. Ouvrez **Tools > Connections**
2. Cliquez sur `New Connection` et choisissez **PlaidCloud Git** dans le menu
3. Renseignez le formulaire simplifié :
   - **Nom du compte** : un nom d'affichage pour la connexion
   - **Mémo** : une note facultative indiquant à quoi sert la connexion
   - **Dépôt** : cliquez sur `Refresh` pour lister les dépôts accessibles à votre espace de travail, puis choisissez-en un (par exemple votre dépôt `udfs` ou `apps`). Vous le sélectionnez dans la liste au lieu de saisir son chemin.
   - **Branche par défaut** : choisissez la branche à lire par défaut dans la liste des branches du dépôt sélectionné
   - **Chemin de départ** : parcourez éventuellement le dépôt et choisissez un dossier pour limiter chaque recherche de fichier à un sous-dossier ; laissez ce champ vide pour utiliser l'ensemble du dépôt
4. Définissez **Utilisation** : `Active` pour activer la connexion, et `Read Only` si la connexion ne doit jamais écrire
5. Définissez le **Modèle de sécurité** : qui, dans l'espace de travail, peut utiliser la connexion
6. Cliquez sur `Create` pour enregistrer

C'est tout le formulaire. Contrairement à un fournisseur Git externe, il n'y a ni URL de serveur, ni onglet d'authentification, ni configuration SSL ou SSH : tout cela est géré pour vous.

<Aside type="note">Le dépôt, la branche par défaut et le chemin de départ se choisissent dans des listes actualisées en direct : sélectionnez d'abord un dépôt, puis sa branche, puis parcourez-le jusqu'à un dossier, de sorte qu'il n'y a aucune faute de saisie possible. Chaque liste est lue avec l'accès propre à la connexion ; pour une connexion PlaidCloud Git, elles s'affichent donc immédiatement, sans identifiants à saisir.</Aside>

## Modèle de sécurité

Le `Security Model` détermine qui, dans l'espace de travail, peut utiliser la connexion :

| Option | Qui peut utiliser la connexion |
|---|---|
| Privé (propriétaires uniquement) | Uniquement les propriétaires. |
| Membres spécifiques uniquement | Les propriétaires, plus une liste explicite de membres. |
| Groupes de sécurité spécifiques uniquement | Les propriétaires, plus les membres de groupes de sécurité nommés. |
| Tous les membres de l'espace de travail | Tous les membres de l'espace de travail. |

Pour `Specific Members Only` ou `Specific Security Groups Only`, accordez l'accès depuis le menu `Actions` de la liste après l'enregistrement. Pour le fonctionnement commun des connexions, consultez [Créer et gérer une connexion](/fr/guides/connections/create-connection/#modèle-de-sécurité).

## Qui peut voir les dépôts

Chaque dépôt que PlaidCloud crée pour vous est lisible par tous les membres connectés de votre espace de travail. Cela inclut les dépôts qui sous-tendent vos applications Panel et Dash, ainsi que les dépôts intégrés `apps` et `udfs`. Personne ne peut les lire sans être connecté.

De ce fait, les membres peuvent ouvrir et republier des applications, et choisir un dépôt pour une connexion PlaidCloud Git, sans aucune configuration par dépôt.

### Avancé : dépôts privés

Un administrateur Git peut rendre un dépôt privé dans l'interface Git. Un dépôt privé n'est plus visible de tous les membres ; par conséquent :

- Il n'apparaît pas dans la liste **Dépôt** des connexions PlaidCloud Git.
- Le code d'une UDF adossée à Git ne peut pas y être lu : une UDF adossée à Git stockée dans un dépôt privé ne s'exécutera donc pas.
- Les membres ne peuvent pas y publier d'application.

Pour utiliser un dépôt privé comme source, créez plutôt une [connexion Git externe](/fr/reference/connectors/git/) avec son propre jeton d'accès.

## Automatiser les builds d'applications Panel et Dash depuis Git géré

Une [application Panel serveur](/fr/guides/panel-apps/creating/) ou une [application Dash](/fr/guides/dash-apps/) se construit à partir d'une branche Git et se reconstruit automatiquement à chaque push sur cette branche. En la dirigeant vers une connexion PlaidCloud Git, vous gardez toute la boucle à l'intérieur de votre espace de travail : aucun hôte externe et aucun jeton d'accès personnel à maintenir valide.

1. Poussez votre application vers un dépôt du serveur PlaidCloud Git de votre espace de travail : un fichier `.py` de point d'entrée (pour Panel, il appelle `.servable()` ; pour Dash, il expose `server = app.server`) et, éventuellement, un fichier `requirements.txt` à la racine du dépôt ou à côté de votre point d'entrée. Consultez [Créer une application Panel](/fr/guides/panel-apps/creating/#préparer-le-dépôt-de-votre-application) ou [Déployer une application Dash depuis PlaidCloud Git](/fr/guides/dash-apps/deploy-from-git/) pour la structure du dépôt.
2. Créez une connexion PlaidCloud Git dont le **Dépôt** est ce dépôt, en suivant les étapes ci-dessus.
3. Dans **Mes applications Panel**, cliquez sur **Nouvelle application serveur** ou **Nouvelle application Dash** et, sous **Connexion Git et observateur de publication** :
   - **Connexion Git** : choisissez la connexion PlaidCloud Git que vous venez de créer
   - **Branche** : la branche à partir de laquelle construire ; les push sur celle-ci reconstruisent et redéploient l'application
   - **Point d'entrée** : le fichier `.py` que l'application doit servir
4. Terminez la boîte de dialogue de publication et cliquez sur **Publier**.

Dès lors, chaque push sur cette branche de votre serveur Git géré reconstruit l'application : un build automatisé de bout en bout qui ne quitte jamais PlaidCloud.
