Une **connexion PlaidCloud Git** oriente un workflow, ou le build d'une application Panel serveur, vers un dépôt hébergé sur le serveur Git géré de votre propre espace de travail. Ce serveur Git étant hébergé pour vous à l'adresse `git.<your-workspace>.plaid.cloud` et vous étant déjà connecté via votre connexion PlaidCloud habituelle, le formulaire de connexion est bien plus simple que celui d'un fournisseur Git externe : il n'y a pas d'URL de serveur à saisir, ni de nom d'utilisateur, de jeton ou de clé SSH à gérer.

<Aside type="note">Vous ne saisissez jamais d'URL de serveur ni d'identifiants pour une connexion PlaidCloud Git. Le serveur Git de votre espace de travail et votre accès à celui-ci sont gérés automatiquement à partir de votre connexion PlaidCloud (SSO compris) : il n'y a donc aucun jeton à créer, stocker ou renouveler.</Aside>

## Quand l'utiliser

Utilisez une connexion PlaidCloud Git chaque fois que le dépôt que vous souhaitez lire se trouve dans [PlaidCloud Git](/fr/guides/git/), le service Git intégré à votre espace de travail, plutôt que sur un hôte externe. L'usage le plus courant est d'automatiser les builds d'**applications Panel serveur** ou d'**applications Dash** à partir d'un dépôt géré, de sorte qu'un push sur une branche reconstruise et redéploie l'application sans compte GitHub externe ni jeton d'accès personnel dans la boucle.

Pour un dépôt hébergé sur un service externe (GitHub, GitLab, Bitbucket, Forgejo ou Gitea), utilisez plutôt une [connexion Git externe](/fr/reference/connectors/git/). Celles-ci conservent le formulaire complet avec une **URL du serveur**, une authentification par utilisateur/jeton ou SSO, et les onglets **SSL** et **SSH**.

## Créer une connexion PlaidCloud Git

1. Ouvrez **Tools > Connections**
2. Cliquez sur `New Connection` et choisissez **PlaidCloud Git** dans le menu
3. Renseignez le formulaire simplifié :
   - **Nom du compte** : un nom d'affichage pour la connexion
   - **Mémo** : une note facultative sur l'objet de la connexion
   - **Dépôt** : cliquez sur `Refresh` pour lister les dépôts accessibles à votre espace de travail, puis choisissez-en un (par exemple votre dépôt `udfs` ou `apps`). Vous le sélectionnez dans la liste au lieu de saisir le chemin.
   - **Branche par défaut** : choisissez la branche à lire par défaut dans la liste des branches du dépôt sélectionné
   - **Chemin de départ** : parcourez éventuellement le dépôt et choisissez un dossier pour limiter chaque recherche de fichier à un sous-dossier ; laissez-le non défini pour utiliser tout le dépôt
4. Définissez **Utilisation** : `Active` pour activer la connexion, et `Read Only` si la connexion ne doit jamais écrire
5. Définissez le **Modèle de sécurité** : qui, dans l'espace de travail, peut utiliser la connexion
6. Cliquez sur `Create` pour enregistrer

C'est tout le formulaire. Contrairement à un fournisseur Git externe, il n'y a ni URL de serveur, ni onglet d'authentification, ni configuration SSL ou SSH : tout cela est géré pour vous.

<Aside type="note">Le dépôt, la branche par défaut et le chemin de départ se choisissent dans des listes en direct (choisissez d'abord un dépôt, puis sa branche, puis parcourez jusqu'à un dossier), il n'y a donc rien à saisir par erreur. Chaque liste est lue avec l'accès propre à la connexion ; pour une connexion PlaidCloud Git, elles se remplissent donc immédiatement, sans identifiants à saisir.</Aside>

## Modèle de sécurité

Le `Security Model` contrôle qui, dans l'espace de travail, peut utiliser la connexion :

| Option | Qui peut utiliser la connexion |
|---|---|
| Privé (propriétaires uniquement) | Uniquement les propriétaires. |
| Membres spécifiques uniquement | Les propriétaires plus une liste explicite de membres. |
| Groupes de sécurité spécifiques uniquement | Les propriétaires plus les membres de groupes de sécurité nommés. |
| Tous les membres de l'espace de travail | Tous les membres de l'espace de travail. |

Pour `Specific Members Only` ou `Specific Security Groups Only`, accordez l'accès depuis le menu `Actions` de la liste après l'enregistrement. Consultez [Créer et gérer une connexion](/fr/guides/connections/create-connection/#modèle-de-sécurité) pour le fonctionnement commun des connexions.

## Automatiser les builds d'applications Panel et Dash depuis Git géré

Une [application Panel serveur](/fr/guides/panel-apps/creating/) ou une [application Dash](/fr/guides/dash-apps/) est construite à partir d'une branche Git et se reconstruit automatiquement à chaque push sur cette branche. La pointer vers une connexion PlaidCloud Git garde toute la boucle à l'intérieur de votre espace de travail : pas d'hôte externe ni de jeton d'accès personnel à maintenir.

1. Poussez votre application dans un dépôt du serveur PlaidCloud Git de votre espace de travail : un fichier `.py` de point d'entrée (celui de Panel appelle `.servable()` ; celui de Dash expose `server = app.server`) et un `requirements.txt` facultatif à la racine du dépôt ou à côté de votre point d'entrée. Consultez [Créer une application Panel](/fr/guides/panel-apps/creating/#préparer-le-dépôt-de-votre-application) ou [Déployer une application Dash depuis PlaidCloud Git](/fr/guides/dash-apps/deploy-from-git/) pour l'organisation du dépôt.
2. Créez une connexion PlaidCloud Git dont le **Dépôt** est ce dépôt, en suivant les étapes ci-dessus.
3. Dans **Mes applications Panel**, cliquez sur **Nouvelle application serveur** ou **Nouvelle application Dash** et, sous **Connexion Git et observateur de publication** :
   - **Connexion Git** : choisissez la connexion PlaidCloud Git que vous venez de créer
   - **Branche** : la branche à partir de laquelle construire ; les push sur celle-ci reconstruisent et redéploient l'application
   - **Point d'entrée** : le fichier `.py` que l'application doit servir
4. Terminez la boîte de dialogue de publication et cliquez sur **Publier**.

Dès lors, chaque push sur cette branche de votre serveur Git géré reconstruit l'application, dans un build automatisé de bout en bout qui ne quitte jamais PlaidCloud.
