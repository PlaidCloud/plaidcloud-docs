[Data Foundation](/fr/guides/projects/data-foundation/) rassemble dans un seul Common Finance Model les données de chaque système ERP et de chaque instance que vous connectez, et SAP S/4HANA Cloud fait partie des ERP qu'il lit directement. La connexion lit les services OData publiés du locataire avec les identifiants client OAuth 2.0 ; aucun agent n'intervient. Cette page s'adresse à l'administrateur S/4HANA Cloud qui effectue cette configuration, et à l'utilisateur PlaidCloud qui la lui demande.

PlaidCloud ne fait que lire les données. Personne n'envoie de mot de passe ni de secret client par e-mail.

## Envoyer la demande d'accès

Dans la page **Systèmes** du projet, sous **Data Foundation** dans **Accueil**, choisissez votre système dans **Système** sous **Ajouter un système**, puis cliquez sur **Vous n’avez pas encore accès ?**. Le système attend l'accès, et une demande unique couvrant les systèmes du projet s'affiche. Cliquez sur **Copier la demande** pour la coller dans votre propre message, ou sur **Envoyer la demande par e-mail** pour l'ouvrir dans votre messagerie avec l'objet « Accès à PlaidCloud. »

## Ce que l'administrateur S/4HANA Cloud configure

<Steps>

1. **Créez un utilisateur de communication** pour PlaidCloud, dans l'application **Maintain Communication Users**. Sa méthode d'authentification est OAuth 2.0 ou nom d'utilisateur et mot de passe, selon ce que votre paysage exige.

2. **Créez un système de communication** pour PlaidCloud, dans l'application **Communication Systems**, avec cet utilisateur pour la communication entrante et les identifiants client OAuth 2.0.

3. **Créez un arrangement de communication** pour chacun des scénarios ci-dessous, dans l'application **Communication Arrangements**, tous pour le système de l'étape 2. Ensemble, ils exposent les services OData que PlaidCloud lit :

   | Scénario | Service |
   |---|---|
   | Company Code | `API_COMPANYCODE_SRV` |
   | G/L Account in Chart of Accounts | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
   | Cost Center | `API_COSTCENTER_SRV` |
   | Business Partner and Customer | `API_BUSINESS_PARTNER` |
   | Product | `API_PRODUCT_SRV` |
   | Fiscal Year Variant Periods | `API_FISCALYEARPERIODFORVARIANT_SRV` |
   | Exchange Rates | `API_EXCHANGERATE_SRV` |
   | Journal Entry Item | `API_JOURNALENTRYITEMBASIC_SRV` (le journal et le solde reporté) |
   | Billing Document | `API_BILLING_DOCUMENT_SRV` (facultatif : il ajoute les ventes facturées, les documents et les postes) |

   Pour les jeux de données facultatifs, mettez aussi en place les scénarios qui exposent ces services :

   | Service | Ajoute |
   |---|---|
   | `API_JOURNALENTRY_SRV` | Qui a saisi chaque journal, quand, et le journal qu'il contrepasse |
   | `API_BUSINESS_PARTNER` (`A_Supplier`) | Les fournisseurs |
   | `API_PLANT_SRV` | Les usines, lues comme sites, et les usines des soldes de stock |
   | `API_PROFITCENTER_SRV` | Les centres de profit |
   | `API_SUPPLIERINVOICE_PROCESS_SRV` | Les lignes de factures fournisseurs |
   | `API_OPLACCTGDOCITEMCUBE_SRV` | Les postes ouverts et les paiements, ainsi que les dates d'échéance des factures fournisseurs |
   | `API_FINPLANNINGDATA_SRV` | Les budgets |
   | `API_MATERIAL_STOCK_SRV` | Les soldes de stock |

   Donnez à l'utilisateur de communication l'accès à chaque code société sur lequel vous produisez des rapports.

</Steps>

## Ce qu'il faut renvoyer

| L'administrateur envoie | Saisi dans PlaidCloud comme |
|---|---|
| L'hôte de l'API du locataire, par exemple `https://my300000-api.s4hana.cloud.sap` | **URL de l'hôte de l'API** |
| L'URL du jeton : celle du locataire (`/sap/bc/sec/oauth2/token`), ou celle de votre serveur d'autorisation XSUAA si votre paysage en utilise un | **URL du jeton OAuth2** |
| L'ID client | **ID client** |
| Le secret client, via le formulaire de connexion sécurisé | **Secret client**, que votre équipe saisit elle-même |
| Si **Carry Forward Balances** a été exécuté pour chaque exercice que vous chargez | Rien à saisir. Les soldes d'ouverture y sont lus. |

<Aside type="caution">
N'envoyez jamais le secret client par e-mail. **Secret client** est un secret : il est stocké dans la connexion et jamais affiché de nouveau.
</Aside>

## Vérifier l'accès

De retour dans PlaidCloud, une fois le système ajouté, cliquez sur **Tester la connexion** sur sa ligne dans la page **Systèmes**. Il lit les jeux de données obligatoires et affiche chacun comme **Lisible**, **Autorisation manquante** ou **Erreur**. Les jeux de données facultatifs ne font pas partie du test : si S/4HANA Cloud en refuse un, après le chargement suivant, les contrôles de préparation, sur le tableau de bord **CFM-Accounting - Close and assurance**, nomment le service à ajouter à l'arrangement de communication.

| Jeu de données | Service requis |
|---|---|
| Entités | `API_COMPANYCODE_SRV` |
| Plan comptable | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
| Départements | `API_COSTCENTER_SRV` |
| Clients | `API_BUSINESS_PARTNER` |
| Produits | `API_PRODUCT_SRV` |
| Taux de change | `API_EXCHANGERATE_SRV` |
| Calendrier fiscal | `API_FISCALYEARPERIODFORVARIANT_SRV` |
| Grand livre | `API_JOURNALENTRYITEMBASIC_SRV` |
| Balance de vérification | `API_JOURNALENTRYITEMBASIC_SRV` |
| Lignes de vente | `API_BILLING_DOCUMENT_SRV` (facultatif) |

Lorsqu'un jeu de données affiche **Autorisation manquante**, demandez à l'administrateur d'ajouter l'arrangement de communication de son service, puis testez à nouveau. Les lignes de vente, le budget, les soldes de stock, les fournisseurs, les sites, les centres de profit, les lignes de factures fournisseurs, les postes ouverts et les paiements sont facultatifs : un locataire qui n'en contient pas un charge quand même tout le reste. Les postes ouverts ou les paiements d'un mois qui ne peuvent pas être lus, et les lignes de factures fournisseurs d'un mois dont la lecture échoue, conservent les lignes qu'ils avaient déjà et sont relus au chargement suivant.

Les services ne communiquent ni statut de période ni solde de fin de mois propre ; chaque période est donc ouverte et le grand livre est comparé à sa propre balance générale.
