[Data Foundation](/fr/guides/projects/data-foundation/) rassemble dans un seul Common Finance Model les données de chaque système ERP et de chaque instance que vous connectez, et Sage Intacct fait partie des ERP qu'il lit directement. La connexion utilise Intacct Web Services : une autorisation d'expéditeur pour PlaidCloud et un utilisateur Web Services en lecture seule. Cette page s'adresse à l'administrateur Sage Intacct qui effectue cette configuration, et à l'utilisateur PlaidCloud qui la lui demande.

PlaidCloud ne fait que lire les données. Personne n'envoie de mot de passe par e-mail.

## Envoyer la demande d'accès

Dans la page **Systèmes** du projet, sous **Data Foundation** dans **Accueil**, choisissez votre système dans **Système** sous **Ajouter un système**, puis cliquez sur **Vous n’avez pas encore accès ?**. Le système attend l'accès, et une demande unique couvrant les systèmes du projet s'affiche. Cliquez sur **Copier la demande** pour la coller dans votre propre message, ou sur **Envoyer la demande par e-mail** pour l'ouvrir dans votre messagerie avec l'objet « Accès à PlaidCloud. »

## Ce que l'administrateur Sage Intacct configure

<Steps>

1. **Autorisez PlaidCloud comme expéditeur Web Services.** Sous **Company > Admin > Web Services authorizations**, ajoutez l'ID d'expéditeur que PlaidCloud vous a fourni. Renvoyez l'ID d'expéditeur et le mot de passe d'expéditeur que Sage a émis pour lui.

2. **Créez un utilisateur Web Services.** Sous **Company > Admin > Users**, créez un utilisateur de type « Business » avec l'option « Web services only », et un rôle disposant de l'autorisation **View** sur :

   | Domaine | Objets |
   |---|---|
   | General Ledger | Comptes, comptes statistiques, écritures de journal (tous les journaux, y compris les journaux d'ajustement), soldes de comptes, périodes de reporting, taux de change, budgets |
   | Company | Entités (emplacements), départements, classes, projets |
   | Accounts Receivable | Clients, factures, ajustements, paiements |
   | Accounts Payable | Fournisseurs, factures fournisseurs, ajustements, paiements |
   | Cash Management | Comptes courants |
   | Inventory Control | Articles |
   | Order Entry | Transactions (factures de vente, ainsi que les avoirs et retours qui les annulent), si vous voulez les ventes |

   Donnez à l'utilisateur l'accès au niveau supérieur de la société et à chaque entité sur laquelle PlaidCloud produit des rapports. Si les définitions de vos transactions d'avoir et de retour ne s'appellent pas Sales Credit Memo et Sales Return, indiquez leurs noms à l'utilisateur PlaidCloud.

3. **Autorisez l'adresse IP de l'utilisateur** si votre société restreint Web Services par IP.

</Steps>

## Ce qu'il faut renvoyer

| L'administrateur envoie | Saisi dans PlaidCloud comme |
|---|---|
| L'ID de la société | **ID de la société** |
| L'ID de l'utilisateur Web Services | **Nom d'utilisateur du service web** |
| L'ID d'expéditeur | **ID client** |
| Le mot de passe d'expéditeur | **Secret client** |
| Les noms de vos définitions de transactions d'avoir et de retour, s'ils ne sont pas ceux par défaut | Le paramètre système **Credit memo and return document types** (par défaut : Sales Credit Memo, Sales Return) |
| Les entités que PlaidCloud peut lire | Sous **Options**, **Sociétés** : cochez-les, ou aucune pour toutes les lire |

Les mots de passe passent par votre gestionnaire de mots de passe, jamais par e-mail. L'équipe de l'utilisateur PlaidCloud saisit elle-même le mot de passe d'expéditeur comme **Secret client**. Les entités qui sont les éliminations propres à votre société sont à renseigner dans le paramètre système **Elimination entities**.

## Vérifier l'accès

De retour dans PlaidCloud, une fois le système ajouté, cliquez sur **Tester la connexion** sur sa ligne dans la page **Systèmes**. Il lit les jeux de données obligatoires et affiche chacun comme **Lisible**, **Autorisation manquante** ou **Erreur**. Les jeux de données facultatifs, signalés ci-dessous, ne font pas partie du test : si Sage Intacct en refuse un, après le chargement suivant, les contrôles de préparation, sur le tableau de bord **CFM-Accounting - Close and assurance**, nomment l'objet à autoriser.

| Jeu de données | Autorisation requise |
|---|---|
| Entités | Company : Entities (View) |
| Plan comptable | General Ledger : Accounts et Statistical accounts (View) |
| Départements | Company : Departments (View) |
| Clients | Accounts Receivable : Customers (View) |
| Produits | Inventory Control : Items (View) |
| Taux de change | General Ledger : Exchange rates (View) |
| Calendrier fiscal | General Ledger : Reporting periods (View) |
| Balance de vérification | General Ledger : Account balances (View) |
| Grand livre | General Ledger : Journal entries (View) |
| Solde de fin de mois (facultatif) | General Ledger : Account balances (View) |
| Soldes bancaires (facultatif) | Cash Management : Checking accounts (View), avec le solde de fin de mois |
| Sites (facultatif) | Company : Entities (locations) (View) |
| Centres de profit (facultatif) | Company : Classes (View) |
| Projets (facultatif) | Company : Projects (View) |
| Fournisseurs (facultatif) | Accounts Payable : Vendors (View) |
| Lignes de vente (facultatif) | Order Entry : Transactions (View) |
| Lignes de factures fournisseurs (facultatif) | Accounts Payable : Bills et Adjustments (View) |
| Postes ouverts et Paiements (facultatif) | Accounts Receivable : Invoices, Adjustments et Payments, et Accounts Payable : Bills, Adjustments et Payments (View) |
| Budget (facultatif) | General Ledger : Budgets (View) |
| Inducteurs d'allocation (facultatif) | General Ledger : Account balances (View) |

Lorsqu'un jeu de données est manquant, le test nomme l'autorisation à ajouter. Demandez à l'administrateur de l'ajouter au rôle, puis testez à nouveau. Une société qui n'utilise pas un jeu de données facultatif charge quand même tout le reste. Lorsque Sage Intacct refuse une lecture à partir de laquelle sont construits les factures fournisseurs, les postes ouverts ou les paiements d'un mois, ce mois conserve les lignes qu'il avait déjà et est relu au chargement suivant.

Qui a saisi un journal, quand, qui l'a approuvé et ce qu'il contrepasse sont lus dans le lot du journal. Un rôle qui ne peut pas lire le lot les laisse vides.
