Une **connexion** est une configuration enregistrée qui permet à PlaidCloud d'atteindre un système externe : base de données, lac de données, ERP, API REST, service cloud ou fournisseur Git. Les étapes de workflow référencent la connexion par son nom ; les détails du point de terminaison et les identifiants se trouvent donc à un seul endroit et sont réutilisés par toutes les étapes et tous les projets qui en ont besoin.

Les connexions se gèrent depuis **Tools > Connections**.

## Créer une connexion

1. Ouvrez **Tools > Connections**
2. Cliquez sur `New Connection` dans la barre d'outils et choisissez dans le menu le système auquel vous voulez vous connecter
3. Renseignez le formulaire de connexion (les onglets et les champs varient selon le type ; consultez [Formulaire de connexion](#formulaire-de-connexion) ci-dessous)
4. Cliquez sur `Create` pour enregistrer

La nouvelle connexion apparaît dans la liste, et vous en êtes le propriétaire.

<Aside type="note">La liste des types de connexions et les champs requis pour chacun sont répertoriés dans la [référence des connecteurs](/fr/reference/connectors/). Pour un service sans connecteur dédié, utilisez la [connexion REST générique](/fr/reference/connectors/rest/generic-rest/).</Aside>

## Formulaire de connexion

La plupart des connexions ouvrent un formulaire à plusieurs onglets. Les onglets exacts dépendent du type, mais vous verrez couramment :

- **Configuration de la connexion** (ou **Détails de la connexion** pour REST) : le `Name` de la connexion, un `Memo` facultatif, l'hôte, le port et la base de données (ou l'hôte et le type d'authentification pour REST), l'interrupteur `Usage` (`Active`) et le `Security Model`. Pour une connexion à une base de données, les identifiants se trouvent ici, dans un groupe **Identifiants d'authentification** ; pour une connexion REST, ils ont leur propre onglet **Authentification**.
- **Configuration SSL** : `Use SSL` ainsi que le mode SSL et des certificats client ou racine facultatifs pour une connexion chiffrée.
- **Configuration SSH** : `Use SSH` ainsi que l'hôte bastion, le port, l'utilisateur et la clé pour faire passer la connexion par un hôte de rebond SSH.

Les champs de mot de passe, de jeton et autres identifiants sont en écriture seule : ils apparaissent vides lorsque vous rouvrez une connexion enregistrée, et les laisser vides à l'enregistrement conserve le secret stocké. Ressaisissez une valeur uniquement pour la modifier. Cela concerne la clé d'API, le secret client OAuth et le jeton d'actualisation OAuth d'une connexion REST. Les identifiants multilignes (un certificat privé NetSuite, un certificat et une clé privée Anaplan, une clé d'API Postman, une URL de webhook entrant Slack ou Teams) sont eux aussi en écriture seule et sont masqués pendant que vous les saisissez ou les collez. Un remplacement composé uniquement d'espaces est refusé plutôt qu'enregistré à la place de l'identifiant stocké ; videz le champ pour conserver la valeur enregistrée. La clé client SSL et la clé privée SSH d'une connexion SQL ou Git sont également en écriture seule, mais restent visibles pendant que vous les saisissez. Tous les autres champs affichent leur vraie valeur enregistrée partout où la connexion est présentée, dans l'éditeur comme via l'API, y compris les champs qui semblent sensibles d'après leur nom (l'indicateur de lecture seule d'une base de données, un identifiant de compte, un schéma, un nom d'hôte) : seul un véritable identifiant est masqué ou caché.

Via l'API REST et MCP, un champ d'identifiant suit la même règle que dans l'éditeur : envoyez une chaîne vide et PlaidCloud conserve la valeur stockée ; envoyez `null` pour l'effacer. Tout champ qui n'est pas un identifiant s'efface toujours lorsque vous l'envoyez vide.

Les champs obligatoires sont validés à l'enregistrement ; s'il en manque un, le formulaire bascule vers l'onglet qui contient le premier champ non valide et le signale.

## Modèle de sécurité

Le `Security Model` d'une connexion contrôle qui, dans l'espace de travail, peut l'utiliser :

| Option | Qui peut utiliser la connexion |
|---|---|
| Privé (propriétaires uniquement) | Uniquement les propriétaires. |
| Membres spécifiques uniquement | Les propriétaires et une liste explicite de membres. |
| Groupes de sécurité spécifiques uniquement | Les propriétaires et les membres de groupes de sécurité nommés. |
| Tous les membres de l'espace de travail | Tout le monde dans l'espace de travail. |

Lorsque vous choisissez `Specific Members Only` ou `Specific Security Groups Only`, accordez l'accès depuis le menu `Actions` de la liste : `Members` pour `Specific Members Only` ou `Groups` pour `Specific Security Groups Only`, ainsi que `Agents` et `Owners`, ouvrent chacun un sélecteur à double liste pour ajouter et retirer des accès. Seul un propriétaire de la connexion, ou un administrateur de l'espace de travail, peut y modifier l'accès. Toute autre personne qui peut modifier des connexions peut les ouvrir pour voir qui y a accès, sans le modifier. Un administrateur de l'espace de travail peut modifier l'accès à une connexion dont il n'est pas propriétaire, afin de la transmettre lorsque ses propriétaires sont partis.

## Environnements

Une connexion peut contenir une configuration différente par **environnement** (par exemple un hôte de développement et un hôte de production sous un même nom de connexion). Le sélecteur d'environnement de la barre d'outils choisit la configuration de l'environnement que vous consultez et modifiez.

- `New Environment` : ajoute un environnement de connexion
- `Edit Environment` : renomme l'environnement sélectionné
- `Delete Environment` : supprime l'environnement sélectionné

La colonne `Available` de la liste indique si la connexion sélectionnée est configurée pour l'environnement choisi.

<Aside type="note">L'enregistrement d'une configuration est fusionné avec celle stockée pour cet environnement ; les secrets en écriture seule laissés vides ne sont donc jamais écrasés par des valeurs vides.</Aside>

Les environnements sont partagés avec les agents PlaidLink ; l'environnement d'un projet peut donc changer l'agent qui exécute ses étapes distantes ainsi que les connexions qu'il lit. Consultez [Environnements d'agent](/fr/reference/cli/plaidlink/agents/#environnements-des-agents).

## Modifier une connexion

1. Sélectionnez la connexion dans la liste
2. Cliquez sur `Edit` dans la barre d'outils (ou cliquez avec le bouton droit sur la ligne)
3. Modifiez les champs et cliquez sur `Update`

## Tester une connexion

La façon de tester dépend du type :

- Les **connexions à une base de données** (Databricks, Snowflake, PostgreSQL et Redshift) disposent d'un bouton **Tester la connexion** dans l'éditeur. Il ouvre la connexion avec les identifiants saisis et indique soit le succès (avec la version du serveur atteint), soit la raison de l'échec, sans fermer l'éditeur ; vous pouvez ainsi corriger et réessayer sur place.
- Les connexions à une base de données avec SSH exposent aussi un test du tunnel SSH dans l'onglet `SSH Config`.
- La [connexion REST générique](/fr/reference/connectors/rest/generic-rest/) possède un onglet `Testing` qui envoie une requête ad hoc via la connexion enregistrée.

Enregistrez la connexion avant de la tester : les tests s'exécutent sur la configuration stockée.

<Aside type="note">**Tester la connexion** apparaît pour un type de connexion dès que son éditeur le propose : actuellement les types de bases de données ci-dessus ainsi que [TM1](/fr/guides/connections/tm1/), [Oracle Essbase](/fr/guides/connections/essbase/), [HFM/FCCS](/fr/guides/connections/hfm-fccs/), Salesforce et Anaplan. Les autres connexions REST, comme NetSuite, ne l'ont pas encore ; testez-les en envoyant une petite requête depuis une étape de workflow (pour NetSuite, consultez [Se connecter à NetSuite](/fr/guides/connections/netsuite/#tester-le-bon-fonctionnement-de-la-connexion)).</Aside>

## Cloner, supprimer et tracer l'utilisation

- **Cloner** : duplique la configuration d'une connexion comme base d'une nouvelle. Consultez [Cloner une connexion](/fr/guides/connections/clone-connection/).
- **Supprimer** : supprime la connexion sélectionnée depuis la barre d'outils (une confirmation vous est demandée).
- **Où utilisé…** : liste les étapes de workflow qui référencent la connexion, afin de mesurer l'impact avant de la modifier ou de la supprimer.

<Aside type="caution">`Edit`, `Clone` et `Delete` ne sont disponibles que sur les connexions dont vous êtes propriétaire. Si ces actions sont grisées pour la ligne sélectionnée, vous n'êtes pas propriétaire : demandez à un propriétaire d'effectuer la modification ou de vous ajouter via `Owners`.</Aside>
