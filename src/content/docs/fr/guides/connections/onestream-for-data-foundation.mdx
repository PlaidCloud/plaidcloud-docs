Connectez PlaidCloud à **OneStream** pour que Data Foundation lise vos résultats consolidés et rapproche de ceux-ci son compte de résultat de gestion du groupe. OneStream est pris en charge par son connecteur : PlaidCloud se connecte avec les identifiants client OAuth 2.0 et lit un adaptateur de données que construit votre administrateur OneStream. Il ne fait que lire. Si vous nommez une séquence Data Management, PlaidCloud exécute d'abord cette séquence pour actualiser ce que lit l'adaptateur, et n'exécute rien d'autre.

OneStream est une source de résultats auxquels se rapprocher, et non de lignes de grand livre : ses lignes sont chargées comme le scénario `Consolidated` de la table budgétaire du modèle, version `OneStream`. Voir [Rapprochement avec votre système de consolidation](/fr/guides/projects/data-foundation/#rapprocher-avec-votre-système-de-consolidation).

<Aside type="note">
Les colonnes de l'adaptateur sont un contrat que vous convenez avec votre administrateur OneStream. Lorsque l'adaptateur est construit selon cette page, ses lignes sont chargées comme décrit ci-dessous. Comparez les résultats du premier chargement avec un rapport OneStream en lequel vous avez confiance.
</Aside>

## Ce que configure votre administrateur OneStream

L'onglet **Foundation** rédige une demande d'accès à lui envoyer. Elle demande ce qui suit.

1. Un client pour PlaidCloud dans le service d'identité de OneStream, qui utilise l'octroi par **identifiants client**, avec un utilisateur de service autorisé à exécuter l'adaptateur et, si vous souhaitez que PlaidCloud actualise d'abord les résultats, la séquence Data Management.

2. Dans l'application et l'espace de travail sur lesquels vous produisez vos rapports, un adaptateur de données nommé **Foundation_Results** qui renvoie une table unique des résultats consolidés avec exactement ces colonnes :

   | Colonne | Contenu |
   |---|---|
   | `entity` | Le membre de consolidation : une entité, un membre d'élimination ou le total du groupe. |
   | `account` | Le code du compte. Comptes de base uniquement. |
   | `time` | Le mois, au format `YYYY-MM`. |
   | `scenario` | Le scénario. |
   | `view` | `YTD` ou `Periodic`. PlaidCloud ne lit que les lignes de la vue que vous choisissez. |
   | `amount` | Un nombre, dans le signe et l'échelle que montrent vos rapports. |
   | `currency` | La devise dans laquelle le montant est exprimé : la devise de reporting de votre groupe. |
   | `flow`, `ud1`, `ud2`, `ud3`, `ud4` | Dimensions de flux et dimensions définies par l'utilisateur. Membres de base uniquement. |

   Servez les membres de base des dimensions de compte, de flux et définies par l'utilisateur. La ligne d'un membre parent compterait ses enfants deux fois. L'adaptateur lit le membre de consolidation dans la variable de substitution `Member` et la vue dans `View`.

3. Les membres à lire : les entités, les membres d'élimination et le total du groupe.

## Créer la connexion

<Steps>

1. Ouvrez **Tools > Connections** et cliquez sur `New Connection`, puis choisissez **OneStream**. Vous pouvez aussi la créer depuis l'onglet **Foundation** lorsque vous ajoutez la source.

2. Renseignez les champs :

   | Champ | Valeur |
   |---|---|
   | Hôte | L'URL de base de OneStream, commençant par `https://`. |
   | ID client | L'ID client du client PlaidCloud. |
   | Secret client | Son secret. Stocké chiffré et jamais réaffiché. |
   | URL du jeton | Laissez vide pour utiliser l'hôte suivi de `/identity/connect/token`. |
   | Application par défaut | Utilisée par une lecture qui laisse son application vide. |
   | Espace de travail par défaut | Utilisé par une lecture qui laisse son espace de travail vide. |
   | Délai d'expiration (secondes) | 120 par défaut. |

3. Cliquez sur `Create`.

</Steps>

## L'ajouter à un projet Data Foundation

Dans l'onglet **Foundation**, ajoutez la connexion comme source, comme pour toute autre (voir [Connecter votre ERP](/fr/guides/projects/data-foundation/#connecter-votre-erp)), et choisissez les membres de consolidation à lire. Répondez ensuite à ce qui décrit les montants de l'adaptateur :

| Paramètre | Signification |
|---|---|
| Membres | Les membres de consolidation à lire, avec un appel à l'adaptateur pour chacun. |
| Vue | Indique si les montants de l'adaptateur sont cumulés depuis le début de l'exercice (par défaut) ou périodiques. Les lignes cumulées depuis le début de l'exercice sont chargées comme des montants périodiques. |
| Signe | **Naturel** : chaque compte dans son propre signe, tel que OneStream le présente (par défaut). **Débit positif** : les débits sont positifs. |
| Échelle | Le multiplicateur pour obtenir des unités monétaires entières : `1000` lorsque OneStream sert des milliers. |
| Mois de début de l'exercice fiscal | Le mois où commence votre exercice fiscal, pour convertir le cumul depuis le début de l'exercice en montants périodiques. |
| Application, espace de travail | Remplacent ceux de la connexion. |
| Variables de substitution | Variables supplémentaires que lit l'adaptateur, par exemple `Time=2026M1`. |
| Séquence Data Management | Une séquence exécutée avant la lecture pour actualiser ce que lit l'adaptateur. |

Associez les membres OneStream à vos entités à l'aide d'un fichier de correspondance de codes qui s'applique à cette source. Voir [Correspondance des entités](/fr/guides/projects/data-foundation/#correspondance-des-entités). La source ne lit aucune fenêtre d'historique : ce sont les variables de substitution propres à l'adaptateur qui la délimitent.

Un chargement dont l'adaptateur ne renvoie aucune ligne se termine par un avertissement, et non par une erreur, et la table reste vide.
