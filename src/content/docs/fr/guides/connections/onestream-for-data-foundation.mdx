Connectez PlaidCloud à **OneStream** pour que Data Foundation puisse lire vos résultats consolidés et y rapprocher son compte de résultat de gestion du groupe. OneStream est pris en charge via son connecteur : PlaidCloud se connecte avec les identifiants client OAuth 2.0 et lit un adaptateur de données que construit votre administrateur OneStream. Il ne fait que lire.

OneStream est une source de résultats auxquels se rapprocher, et non de lignes de grand livre : ses lignes sont chargées comme le scénario `Consolidated` de la table de budget du modèle, version `OneStream`. Consultez [Rapprocher de votre système de consolidation](/fr/guides/projects/data-foundation/#rapprocher-avec-votre-système-de-consolidation).

<Aside type="note">
Les colonnes de l'adaptateur sont un contrat que vous convenez avec votre administrateur OneStream. Lorsque l'adaptateur est construit selon cette page, ses lignes sont chargées comme décrit ci-dessous. Comparez les résultats du premier chargement avec un rapport OneStream auquel vous faites confiance.
</Aside>

## Ce que votre administrateur OneStream configure

La page **Systèmes** du projet rédige une demande d'accès à envoyer ; consultez [Connecter votre ERP](/fr/guides/projects/data-foundation/#connecter-votre-erp). Elle demande les éléments suivants.

1. Un client pour PlaidCloud dans le service d'identité de OneStream qui utilise l'autorisation **client credentials**, avec un utilisateur de service qui ne peut qu'exécuter les adaptateurs ci-dessous : aucun droit Data Management, de chargement ou de consolidation. PlaidCloud n'exécute aucune séquence Data Management ; maintenez donc à jour, selon votre propre calendrier, les résultats que lisent les adaptateurs.

2. Dans l'application et l'espace de travail sur lesquels vous produisez des rapports, un adaptateur de données nommé **Foundation_Results** qui renvoie une table des résultats consolidés avec exactement ces colonnes :

   | Colonne | Contenu |
   |---|---|
   | `entity` | Le membre de consolidation : une entité, un membre d'élimination ou le total du groupe. |
   | `account` | Le code du compte. Comptes de base uniquement. |
   | `time` | Le mois, au format `YYYY-MM`. |
   | `scenario` | `Actual` pour les résultats consolidés. `Budget` ou `Forecast` pour un plan, lu comme le plan. |
   | `view` | `YTD` ou `Periodic`. PlaidCloud ne lit que les lignes de la vue que vous choisissez. |
   | `amount` | Un nombre, avec le signe et l'échelle que montrent vos rapports. |
   | `currency` | La devise dans laquelle le montant est exprimé : la devise de reporting de votre groupe. |
   | `flow` | Le membre de flux. Membres de base uniquement. |
   | `ud1` à `ud5` | Les membres de département, de produit, de site, de commercial et de projet, `None` lorsque la ligne n'en a pas. Membres de base uniquement. |
   | `version` | La version d'un plan. Laissez `None` ou vide pour `Actual`. |
   | `version_as_of` | Le mois, au format `YYYY-MM`, à la date duquel la version d'un plan a été établie. Laissez `None` ou vide pour `Actual`. |
   | `quantity` | Les unités pour lesquelles la ligne d'un plan est planifiée, par mois quelle que soit la vue. Laissez `None` ou vide pour `Actual`. |

   Servez les membres de base des dimensions de compte, de flux et définies par l'utilisateur. La ligne d'un membre parent compterait deux fois ses enfants. L'adaptateur lit le membre de consolidation dans la variable de substitution `Member` et la vue dans `View`.

   Si votre plan contient des effectifs ou des unités produites, créez aussi un adaptateur nommé **Foundation_Drivers** avec les colonnes `entity`, `time`, `scenario`, `driver` (par exemple `headcount` ou `units_produced`), `value`, `unit` (`FTE`, `EA`, etc.), `ud1` (département), `ud2` (produit), `ud3` (site), `version` et `version_as_of`. Il lit `Member` de la même façon et est facultatif : sans lui, ou sans accès à lui, aucun inducteur planifié n'est chargé et les contrôles de préparation le signalent.

3. Les membres à lire : les entités, les membres d'élimination et le total du groupe.

## Créer la connexion

<Steps>

1. Ouvrez **Tools > Connections** et cliquez sur `New Connection`, puis choisissez **REST - OneStream**.

2. Renseignez les champs :

   | Champ | Valeur |
   |---|---|
   | Hôte | L'URL de base de OneStream, commençant par `https://`. |
   | ID client | L'ID client du client PlaidCloud. |
   | Secret client | Son secret. Stocké chiffré et jamais affiché de nouveau. |
   | URL du jeton | Laissez vide pour utiliser l'hôte suivi de `/identity/connect/token`. |
   | Application par défaut | Utilisée par une lecture qui laisse son application vide. |
   | Espace de travail par défaut | Utilisé par une lecture qui laisse son espace de travail vide. |
   | Délai d'expiration (secondes) | 120 par défaut. |

3. Cliquez sur `Create`.

</Steps>

Vous pouvez aussi créer la connexion lorsque vous ajoutez le système dans la page **Systèmes** : choisissez **Nouvelle connexion** sous **Connexion**, et le même éditeur de connexion s'ouvre.

## L'ajouter à un projet Data Foundation

Dans la page **Systèmes** du projet, ajoutez OneStream avec sa connexion, comme pour tout autre système (consultez [Connecter votre ERP](/fr/guides/projects/data-foundation/#connecter-votre-erp)). OneStream ne liste aucun membre à cocher ; sous **Options**, **Sociétés**, saisissez donc les membres de consolidation à lire, séparés par des virgules : au moins un. Puis, sous **Paramètres du système**, décrivez les montants de l'adaptateur :

| Paramètre | Signification |
|---|---|
| **View member** | `ytd` (par défaut) lorsque les montants de l'adaptateur sont cumulés depuis le début de l'exercice, ou `periodic`. Les lignes cumulées sont chargées comme des montants périodiques. |
| **Sign convention** | `natural` (par défaut) : chaque compte dans son propre signe, tel que OneStream le présente. `debit_positive` : débits positifs. |
| **Amount scale** | Le multiplicateur vers les unités monétaires entières : `1000` lorsque OneStream sert des milliers. `1` par défaut. |
| **First month of the fiscal year** | Le mois de début de votre exercice, de `1` à `12`, pour convertir le cumul en montant périodique. `1` par défaut. |
| **Application**, **Workspace** | Remplacent ceux de la connexion. Laissez vide pour utiliser ceux de la connexion. |
| **Adapter results table** | Le nom de la table dans le jeu de données de l'adaptateur. `Results` par défaut. |
| **Substitution variables** | Les variables de substitution définies pour l'adaptateur, une par ligne sous la forme `name = value`, par exemple `Time = 2026M1`. |

Associez les membres OneStream à vos entités avec un fichier de correspondance de codes qui s'applique à cette source. Consultez [Table de correspondance des entités](/fr/guides/projects/data-foundation/#correspondance-des-entités). La source ne lit aucune fenêtre d'historique : ce sont les variables de substitution propres à l'adaptateur qui la délimitent.

Un chargement dont l'adaptateur ne renvoie aucune ligne se termine par un avertissement, et non par une erreur, et la table est vide.
