Connectez PlaidCloud à **OneStream** pour que Data Foundation puisse lire vos résultats consolidés et y rapprocher son compte de résultat de gestion du groupe. OneStream est pris en charge via son connecteur : PlaidCloud se connecte avec les identifiants client OAuth 2.0 et lit un adaptateur de données que construit votre administrateur OneStream. Il ne fait que lire. Si vous nommez une séquence Data Management, PlaidCloud exécute d'abord cette séquence pour actualiser ce que l'adaptateur lit, et n'exécute rien d'autre.

OneStream est une source de résultats auxquels se rapprocher, et non de lignes de grand livre : ses lignes sont chargées comme le scénario `Consolidated` de la table de budget du modèle, version `OneStream`. Consultez [Rapprocher de votre système de consolidation](/fr/guides/projects/data-foundation/#se-rapprocher-de-votre-système-de-consolidation).

<Aside type="note">
Les colonnes de l'adaptateur sont un contrat que vous convenez avec votre administrateur OneStream. Lorsque l'adaptateur est construit selon cette page, ses lignes sont chargées comme décrit ci-dessous. Comparez les résultats du premier chargement avec un rapport OneStream auquel vous faites confiance.
</Aside>

## Ce que votre administrateur OneStream configure

L'onglet **Foundation** rédige une demande d'accès à envoyer. Elle demande les éléments suivants.

1. Un client pour PlaidCloud dans le service d'identité de OneStream qui utilise l'autorisation **client credentials**, avec un utilisateur de service pouvant exécuter l'adaptateur et, si vous voulez que PlaidCloud actualise d'abord les résultats, la séquence Data Management.

2. Dans l'application et l'espace de travail sur lesquels vous produisez des rapports, un adaptateur de données nommé **Foundation_Results** qui renvoie une table des résultats consolidés avec exactement ces colonnes :

   | Colonne | Contenu |
   |---|---|
   | `entity` | Le membre de consolidation : une entité, un membre d'élimination ou le total du groupe. |
   | `account` | Le code du compte. Comptes de base uniquement. |
   | `time` | Le mois, au format `YYYY-MM`. |
   | `scenario` | Le scénario. |
   | `view` | `YTD` ou `Periodic`. PlaidCloud ne lit que les lignes de la vue que vous choisissez. |
   | `amount` | Un nombre, avec le signe et l'échelle que montrent vos rapports. |
   | `currency` | La devise dans laquelle le montant est exprimé : la devise de reporting de votre groupe. |
   | `flow`, `ud1`, `ud2`, `ud3`, `ud4` | Dimensions de flux et dimensions définies par l'utilisateur. Membres de base uniquement. |

   Servez les membres de base des dimensions de compte, de flux et définies par l'utilisateur. La ligne d'un membre parent compterait deux fois ses enfants. L'adaptateur lit le membre de consolidation dans la variable de substitution `Member` et la vue dans `View`.

3. Les membres à lire : les entités, les membres d'élimination et le total du groupe.

## Créer la connexion

<Steps>

1. Ouvrez **Tools > Connections** et cliquez sur `New Connection`, puis choisissez **REST - OneStream**.

2. Renseignez les champs :

   | Champ | Valeur |
   |---|---|
   | Hôte | L'URL de base de OneStream, commençant par `https://`. |
   | ID client | L'ID client du client PlaidCloud. |
   | Secret client | Son secret. Stocké chiffré et jamais affiché de nouveau. |
   | URL du jeton | Laissez vide pour utiliser l'hôte suivi de `/identity/connect/token`. |
   | Application par défaut | Utilisée par une lecture qui laisse son application vide. |
   | Espace de travail par défaut | Utilisé par une lecture qui laisse son espace de travail vide. |
   | Délai d'expiration (secondes) | 120 par défaut. |

3. Cliquez sur `Create`.

</Steps>

Vous pouvez aussi créer la connexion dans l'onglet **Foundation** lorsque vous ajoutez la source : choisissez **Créer une nouvelle connexion** et renseignez **URL de l'hôte de l'API**, **ID client**, **Secret client**, **URL du jeton**, **Application** et **Espace de travail**, qui ont le même sens que les champs ci-dessus.

## L'ajouter à un projet Data Foundation

Dans l'onglet **Foundation**, ajoutez la connexion comme source, comme pour toute autre (consultez [Connecter votre ERP](/fr/guides/projects/data-foundation/#connecter-votre-erp)). OneStream ne liste aucun membre à cocher ; le formulaire demande donc le membre de consolidation à lire : saisissez-le sous **Nom**. Puis, sous **Paramètres système**, décrivez les montants de l'adaptateur. Les paramètres s'affichent sous ces noms :

| Paramètre | Signification |
|---|---|
| `view` | `ytd` (par défaut) lorsque les montants de l'adaptateur sont cumulés depuis le début de l'exercice, ou `periodic`. Les lignes cumulées sont chargées comme des montants périodiques. |
| `sign` | `natural` (par défaut) : chaque compte dans son propre signe, tel que OneStream le présente. `debit_positive` : débits positifs. |
| `scale` | Le multiplicateur vers les unités monétaires entières : `1000` lorsque OneStream sert des milliers. `1` par défaut. |
| `fy_start_month` | Le mois de début de votre exercice, de `1` à `12`, pour convertir le cumul en montant périodique. `1` par défaut. |
| `application`, `workspace` | Remplacent ceux de la connexion. Laissez vide pour utiliser ceux de la connexion. |
| `table` | Le nom de la table dans le jeu de données de l'adaptateur. `Results` par défaut. |
| `sequence` | Une séquence Data Management exécutée avant la lecture pour actualiser ce que l'adaptateur lit. |

Associez les membres OneStream à vos entités avec un fichier de correspondance de codes qui s'applique à cette source. Consultez [Table de correspondance des entités](/fr/guides/projects/data-foundation/#correspondance-des-entités). La source ne lit aucune fenêtre d'historique : ce sont les variables de substitution propres à l'adaptateur qui la délimitent.

Un chargement dont l'adaptateur ne renvoie aucune ligne se termine par un avertissement, et non par une erreur, et la table est vide.
