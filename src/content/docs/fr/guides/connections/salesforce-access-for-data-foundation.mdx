[Data Foundation](/fr/guides/projects/data-foundation/) rassemble dans un seul Common Finance Model les données de chaque système que vous connectez, dans autant d'instances que vous en avez. Salesforce fait partie des systèmes qu'il lit directement. Salesforce est une source CRM, et non un registre comptable : il fournit les clients, les produits, le pipeline commercial, les commerciaux, les campagnes, ses mois fiscaux et les commandes, jamais d'écritures de grand livre. Ses mois fiscaux ne remplacent jamais le calendrier d'une source de grand livre ; consultez [Choisir quelle source compte à partir de quand](/fr/guides/projects/data-foundation/#choisir-quelle-source-compte-à-partir-de-quand). Cette page s'adresse à l'administrateur Salesforce qui configure l'accès, et à l'utilisateur PlaidCloud qui le lui demande.

PlaidCloud ne fait que lire les données. Personne n'envoie de mot de passe ni de jeton de sécurité par e-mail.

## Envoyer la demande d'accès

Dans la page **Systèmes** du projet, sous **Data Foundation** dans **Accueil**, choisissez votre système dans **Système** sous **Ajouter un système**, puis cliquez sur **Vous n’avez pas encore accès ?**. Le système attend l'accès, et une demande unique couvrant les systèmes du projet s'affiche. Cliquez sur **Copier la demande** pour la coller dans votre propre message, ou sur **Envoyer la demande par e-mail** pour l'ouvrir dans votre messagerie avec l'objet « Accès à PlaidCloud. »

## Ce que l'administrateur Salesforce configure

<Steps>

1. **Créez une External Client App** sous **Setup > Apps > External Client Apps > New**, ou une Connected App si votre organisation en utilise encore :

   - Activez les paramètres OAuth, et cochez uniquement **Enable Client Credentials Flow** (ni flux de code d'autorisation, ni flux de mot de passe).
   - **Portée OAuth :** Manage user data via APIs (`api`).
   - **Run As :** un utilisateur d'intégration dédié (étape 2).

2. **Donnez à l'utilisateur d'intégration un profil ou un jeu d'autorisations** comprenant :

   - API Enabled
   - Read sur Account (y compris le champ numérique Account Number), Product2, Opportunity, OpportunityLineItem et Organization (pour la devise par défaut)
   - Read sur User (commerciaux), Campaign (campagnes, lues comme projets), FiscalYearSettings et Period (les mois fiscaux), OpportunityHistory et OpportunityStage (le pipeline tel qu'il se présentait à chaque fin de mois), et Order et OrderItem (commandes, avec Orders activé), si vous voulez les inclure dans le modèle
   - View All Data, ou un partage qui lui permet de voir chaque opportunité sur laquelle vous produisez des rapports

   Salesforce limite chaque ligne et chaque champ que PlaidCloud peut lire à ce que cet utilisateur peut voir.

3. **Copiez la Consumer Key (ID client) et le Consumer Secret** depuis l'application, ainsi que l'URL My Domain de l'organisation, par exemple `https://yourcompany.my.salesforce.com`.

</Steps>

## Ce qu'il faut renvoyer

| L'administrateur envoie | Saisi dans PlaidCloud comme |
|---|---|
| L'URL My Domain | **My Domain** : le nom de domaine uniquement, par exemple `yourcompany` ; `.my.salesforce.com` est ajouté pour vous |
| L'ID client (Consumer Key) | **ID client** |
| Le secret client (Consumer Secret), via le formulaire de connexion sécurisé et non par e-mail | **Secret client** |

Sous **Options**, **Sociétés**, saisissez l'entité unique à laquelle appartient le pipeline de l'organisation Salesforce : une organisation n'a aucune entité à lister. Une organisation correspond à une entité ; deux organisations correspondent donc à deux connexions.

## Vérifier l'accès

De retour dans PlaidCloud, une fois le système ajouté, cliquez sur **Tester la connexion** sur sa ligne dans la page **Systèmes**. Chaque jeu de données s'affiche comme **Lisible**, **Autorisation manquante** ou **Erreur** :

| Jeu de données | Ce qu'il lit dans Salesforce |
|---|---|
| Clients | Account |
| Produits | Product2 |
| Pipeline | Opportunity et OpportunityLineItem, avec les numéros de compte |
| La devise par défaut de l'organisation | Organization |

Tous sont facultatifs. Lorsque l'un d'eux affiche **Autorisation manquante**, demandez à l'administrateur d'ajouter l'accès en lecture à cet objet pour l'utilisateur d'intégration, puis testez à nouveau.

Le test ne lit pas les autres jeux de données, tous facultatifs eux aussi :

| Jeu de données | Ce qu'il lit dans Salesforce |
|---|---|
| Commerciaux | User |
| Projets | Campaign |
| Calendrier fiscal | FiscalYearSettings et Period, les mois uniquement |
| Pipeline, tel qu'il se présentait à chaque fin de mois passée | OpportunityHistory et OpportunityStage |
| Commandes client | Order et OrderItem |

Si Salesforce en refuse un, après le chargement suivant, les contrôles de préparation, sur le tableau de bord **CFM-Accounting - Close and assurance**, nomment les objets sur lesquels donner Read à l'utilisateur d'intégration. Le pipeline ou les commandes d'un mois qui ne peuvent pas être lus conservent les lignes qu'ils avaient déjà.

Les montants du pipeline sont exprimés dans la devise de l'opportunité. Une organisation qui n'utilise qu'une seule devise n'a pas ce champ ; PlaidCloud utilise alors la devise par défaut de l'organisation issue d'Organization, et à défaut la devise de l'entité.
