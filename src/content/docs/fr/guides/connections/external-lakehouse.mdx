Les tables d'un projet résident normalement dans le PlaidCloud Lakehouse intégré. Un administrateur de l'espace de travail peut à la place connecter **votre propre entrepôt Snowflake ou Databricks** depuis PlaidCloud, sans l'aide du personnel de PlaidCloud. Les workflows lisent et écrivent alors les tables du projet directement dans votre entrepôt. Les données restent dans votre compte, sous votre gouvernance et votre facturation, tandis que PlaidCloud pilote les transformations, les workflows et les tableaux de bord qui s'appuient dessus.

## Connecter votre entrepôt de données

Seul un administrateur de l'espace de travail peut connecter, modifier ou supprimer un entrepôt de données.

1. Ouvrez votre menu utilisateur, choisissez **Gérer les entrepôts de données**, puis **Ajouter un entrepôt de données**. Vous pouvez aussi choisir **Connecter** sur la ligne **Utiliser votre entrepôt de données** de la liste de contrôle de l'accueil, ou choisir **Utiliser ceci comme entrepôt de données** dans une boîte de dialogue de connexion Snowflake ou Databricks.
2. Choisissez **Snowflake** ou **Databricks**.
3. Connectez-vous de l'une des deux manières suivantes : **Sign in with Snowflake** ou **Sign in with Databricks** (la plus rapide, décrite dans [Se connecter avec Snowflake ou Databricks](#se-connecter-avec-snowflake-ou-databricks)), ou exécutez le script de configuration et collez les identifiants qu'il produit (ci-dessous).

### 1. Exécuter d'abord le script de configuration

<Aside type="caution">Exécutez le script de configuration avant de vous connecter. Tant que vous ne l'avez pas fait, la vérification de la connexion échoue.</Aside>

La boîte de dialogue génère un script de configuration à partir des noms que vous choisissez et le met à jour au fil de la saisie. Copiez-le avec **Copier le script** et exécutez-le dans votre propre compte. Il ne modifie jamais vos entrepôts existants.

| | Snowflake | Databricks |
|---|---|---|
| Exécuté en tant que | `ACCOUNTADMIN` | Un administrateur de l'espace de travail et du metastore |
| Crée | Un entrepôt qui se suspend après 60 secondes d'inactivité, avec un plafond mensuel de crédits qui envoie une notification à 90 % et suspend à 100 % ; une base de données ; un rôle ; un utilisateur de service | Un service principal ; un SQL warehouse qui s'arrête lorsqu'il est inactif ; le catalogue, s'il n'existe pas déjà |
| Noms modifiables | Entrepôt de données, taille, plafond mensuel de crédits, base de données, rôle, utilisateur de service | Nom du service principal, nom du SQL warehouse, taille, minutes d'inactivité avant l'arrêt, catalogue |
| Valeurs par défaut | `PLAIDCLOUD_WH` (`XSMALL`, 100 crédits par mois), `PLAIDCLOUD`, `PLAIDCLOUD_ROLE`, `PLAIDCLOUD_SVC` | `plaidcloud`, `PlaidCloud` (`2X-Small`, 10 minutes d'inactivité), catalogue `plaidcloud` |
| Authentification | Paire de clés (le script indique comment en générer une) | Secret OAuth pour le service principal |

Le script configure également les éléments suivants.

- **Accès réseau.** Le script liste les adresses depuis lesquelles PlaidCloud se connecte : celle du plan de contrôle, `130.211.116.97/32`, et celle de votre espace de travail lorsqu'elle est différente. Le script Snowflake crée une politique réseau qui n'autorise que ces adresses pour l'utilisateur de service. Sur Databricks, si votre espace de travail applique déjà des listes d'accès IP, le script inclut l'instruction qui les autorise ; ajoutez-les à toute politique réseau ou liste d'accès IP qui protège votre compte.
- **Les politiques sont conservées.** Sur Snowflake, le rôle reçoit les privilèges permettant d'appliquer les politiques et balises d'accès aux lignes, de masquage, de projection, d'agrégation et de jointure, de sorte que vos politiques survivent lorsque PlaidCloud réécrit une table. Sur Databricks, accordez au service principal `EXECUTE` sur toute fonction de filtre de lignes ou de masque de colonne que vous utilisez.
- **Coûts d'exécution.** Le rôle Snowflake reçoit le rôle de base de données `SNOWFLAKE.GOVERNANCE_VIEWER`, qui permet à PlaidCloud de lire les crédits attribués à chaque exécution et couvre aussi [Dernière lecture](/fr/guides/projects/managing-tables-and-views/#dernière-lecture). Databricks reçoit un accès en lecture à l'historique des requêtes et aux tailles d'entrepôt dans le catalogue `system`.
- **Dernière lecture.** Sur Databricks, le script accorde également `USE SCHEMA` sur `system.access` et `SELECT` sur `system.access.table_lineage`, dont les informations de dernière lecture de la table ont besoin. Consultez [Coût de l'entrepôt par exécution](#coût-de-lentrepôt-par-exécution).

### 2. Se connecter

| Champ | Moteur | Ce qu'il faut saisir |
|---|---|---|
| Nom | Les deux | Le nom que PlaidCloud donne à l'entrepôt. Il suit l'adresse, par exemple `Snowflake — myorg-myaccount`, jusqu'à ce que vous saisissiez le vôtre. |
| URL du compte | Snowflake | L'hôte de votre compte, par exemple `myorg-myaccount.snowflakecomputing.com`. |
| Clé privée | Snowflake | La clé privée de l'utilisateur de service (PEM). Une paire de clés n'expire jamais. |
| URL de l'espace de travail | Databricks | L'hôte de votre espace de travail, par exemple `adb-1234567890123456.7.azuredatabricks.net`. |
| Chemin HTTP du SQL warehouse | Databricks | Par exemple `/sql/1.0/warehouses/abc123def456`. |
| ID d'application | Databricks | L'ID d'application (client) du service principal. |
| Secret OAuth | Databricks | Le secret OAuth du service principal. PlaidCloud le renouvelle pour vous. |

Sous **Avancé**, vous pouvez utiliser à la place un jeton d'accès programmatique Snowflake ou un jeton d'accès personnel Databricks. Les jetons expirent : à cette date, PlaidCloud n'accède plus à votre entrepôt tant que vous n'en ajoutez pas un nouveau. Quatorze jours avant l'expiration, puis après, une bannière vous indique la date et propose **Renouveler**, qui ouvre [Gérer les entrepôts de données](#gérer-les-entrepôts-de-données) sur cet entrepôt et demande le nouveau jeton. Une paire de clés ou un secret OAuth évite l'expiration.

L'adresse doit être l'URL publique de votre compte, se terminant par `.snowflakecomputing.com`, `.cloud.databricks.com`, `.azuredatabricks.net` ou `.gcp.databricks.com`. Les points de terminaison privés et personnalisés ne sont pas pris en charge ici ; pour joindre votre entrepôt de façon privée, [demandez une connexion directe](#connexions-directes) après l'avoir rattaché.

### 3. Vérifier, puis l'utiliser

- **Tester la connexion** teste l'adresse, la connexion et tous les privilèges dont PlaidCloud a besoin, sans rien enregistrer.
- **Utiliser comme mon entrepôt de données** effectue la même vérification et rattache l'entrepôt. Ouvert depuis n'importe quel endroit autre que **Ajouter un entrepôt de données**, il définit aussi l'entrepôt par défaut et attend que l'espace de travail bascule dessus. Cela prend généralement quelques minutes et vous pouvez fermer la fenêtre. Les nouveaux projets de l'espace de travail utilisent ensuite votre entrepôt, et la fenêtre propose **Exécuter un exemple** (voir [Exécuter un exemple](#exécuter-un-exemple)). Ouvert depuis **Ajouter un entrepôt de données**, il ne modifie pas la valeur par défaut ; choisissez **Définir par défaut** dans [Gérer les entrepôts de données](#gérer-les-entrepôts-de-données) lorsque les nouveaux projets doivent l'utiliser.

Une vérification en échec explique le problème et sa solution en langage clair. Les privilèges requis manquants sont listés sous forme d'instructions `GRANT` prêtes à l'emploi, chacune avec un bouton **Copier** et une case **Terminé** à cocher une fois l'instruction exécutée, ainsi qu'un bouton **Tout copier** et **Afficher le script de configuration**. **Copier pour l'assistance** copie le texte d'erreur propre à l'entrepôt pour l'assistance PlaidCloud.

La vérification liste aussi séparément des autorisations sous **Recommandé — active « Dernière lecture »**, chacune avec **Copier**. Elles permettent aux informations de [Dernière lecture](/fr/guides/projects/managing-tables-and-views/#dernière-lecture) de la table de lire l'historique de votre entrepôt. Elles ne vous empêchent jamais d'utiliser l'entrepôt : sans elles, il se connecte normalement et « Dernière lecture » affiche **Read history incomplete**.

- **Snowflake :** `GRANT DATABASE ROLE SNOWFLAKE.GOVERNANCE_VIEWER TO ROLE <role>;` (`IMPORTED PRIVILEGES` sur la base de données `SNOWFLAKE` fonctionne aussi). « Dernière lecture » nécessite Access History, que l'édition Snowflake Standard n'offre pas.
- **Databricks :** `USE CATALOG` sur `system`, `USE SCHEMA` sur `system.access` et `SELECT` sur `system.access.table_lineage` pour le service principal.

| Ce que vous voyez | Solution |
|---|---|
| L'utilisateur de service ne peut pas utiliser un objet | Accordez à son rôle le privilège sur cet objet. Le script de configuration contient toutes les autorisations. |
| Votre entrepôt est suspendu ou n'existe pas | Vérifiez le nom de l'entrepôt et qu'il peut démarrer seul (`AUTO_RESUME` sur Snowflake, un SQL warehouse en cours d'exécution sur Databricks). |
| Votre entrepôt a épuisé son quota de crédits | Augmentez le quota du moniteur de ressources ou le budget, ou attendez sa réinitialisation. |
| Une politique réseau bloque PlaidCloud | Autorisez dans la politique les adresses que liste le script de configuration, comme le fait le script. |
| Le jeton ou la clé a expiré ou n'est plus valide | Créez un nouveau jeton ou passez à une paire de clés. |
| Unity Catalog a refusé l'accès au service principal | Accordez `USE CATALOG`, `CREATE SCHEMA` et `USE SCHEMA` sur le catalogue. |
| PlaidCloud n'a pas pu se connecter | Vérifiez l'utilisateur ou le service principal, ainsi que sa clé, son jeton ou son secret. |
| PlaidCloud n'a pas pu joindre votre entrepôt | Vérifiez l'URL et autorisez l'adresse de PlaidCloud dans toute politique réseau ou liste d'accès IP. |
| Les points de terminaison privés ou personnalisés ne sont pas pris en charge | Utilisez l'URL publique de votre compte. |

## Se connecter avec Snowflake ou Databricks

Au lieu de coller une clé, un secret ou un jeton, un administrateur peut rattacher l'entrepôt en se connectant. Chaque personne se connecte ensuite avec sa propre identité Snowflake ou Databricks, de sorte que les tableaux de bord et les requêtes s'exécutent avec ses propres autorisations dans votre entrepôt.

### Ce qu'un administrateur configure d'abord

Une seule fois, dans votre propre compte, un administrateur de compte enregistre PlaidCloud comme application de connexion. La boîte de dialogue de connexion (**Utiliser votre propre entrepôt de données**, ou **Ajouter un entrepôt de données** lorsqu'elle est ouverte depuis **Gérer les entrepôts de données**) affiche le texte exact à utiliser, y compris l'URL de redirection de PlaidCloud.

- **Snowflake.** Exécutez l'instruction `CREATE SECURITY INTEGRATION` affichée dans la boîte de dialogue, puis copiez `OAUTH_CLIENT_ID` depuis le résultat de l'instruction `SELECT SYSTEM$SHOW_OAUTH_CLIENT_SECRETS`.
- **Databricks.** Dans la console de compte, sous **Settings > App connections**, ajoutez une application nommée `PlaidCloud`. Donnez-lui l'URL de redirection affichée dans la boîte de dialogue et l'accès à toutes les API, laissez **Generate a client secret** désactivé et copiez son ID client.

### Rattacher l'entrepôt

1. Dans **Quickest: sign in with Snowflake** (ou Databricks), saisissez l'**URL du compte** (ou l'**URL de l'espace de travail**) et l'**ID client**.
2. Sur Snowflake, saisissez la **Base de données** et le **Rôle de données pour PlaidCloud**. **Entrepôt de données** est facultatif et prend par défaut votre valeur. Sur Databricks, saisissez le **Chemin HTTP du SQL warehouse**. **Catalogue** est facultatif et prend par défaut votre valeur.
3. Choisissez **Sign in with Snowflake** ou **Sign in with Databricks**, connectez-vous à votre compte chez le fournisseur et approuvez.

De retour dans PlaidCloud, l'entrepôt est vérifié une dernière fois. Lorsque la vérification réussit, **Vos entrepôts de données** s'ouvre avec le nouvel entrepôt sélectionné. Si quelque chose manque, la fenêtre reste ouverte et liste ce qu'il faut corriger, avec les autorisations manquantes à copier.

PlaidCloud crée sa propre identité de service dans votre compte, dédiée à cet entrepôt. Les workflows, les planifications et tout ce qui n'a aucune personne derrière s'exécutent sous cette identité.

- **Snowflake.** PlaidCloud crée un nouvel utilisateur de service avec une paire de clés qui ne détient que le rôle de données que vous nommez. Le rôle doit être un simple rôle de données. PlaidCloud refuse un rôle qui est celui avec lequel vous vous êtes connecté, qui est `ACCOUNTADMIN`, `SECURITYADMIN`, `USERADMIN`, `SYSADMIN` ou `ORGADMIN` ou en hérite, qui détient `CREATE USER`, `CREATE ROLE`, `MANAGE GRANTS`, `CREATE INTEGRATION` ou `CREATE NETWORK POLICY`, ou qui possède un utilisateur. Le rôle peut détenir les autorisations `APPLY ROW ACCESS POLICY`, `APPLY MASKING POLICY`, `APPLY PROJECTION POLICY`, `APPLY AGGREGATION POLICY`, `APPLY JOIN POLICY` et `APPLY TAG` du script de configuration, dont les tables reconstruites ont besoin pour conserver leurs politiques. PlaidCloud refuse également de réutiliser un utilisateur Snowflake existant. Le rôle avec lequel vous vous connectez doit pouvoir créer des utilisateurs et accorder le rôle de données.
- **Databricks.** PlaidCloud crée un nouveau service principal disposant uniquement de l'accès au SQL warehouse et des privilèges de données du catalogue. Connectez-vous en tant qu'administrateur de l'espace de travail pour que PlaidCloud puisse le créer.

Si vous n'avez pas un privilège dont l'identité de service a besoin, l'entrepôt se rattache quand même pour les personnes connectées, avec un avertissement qui le nomme, et les exécutions de workflow sont refusées pour le même motif jusqu'à ce qu'un administrateur se reconnecte.

### Tout le monde se connecte

Dès que l'espace de travail dispose d'un entrepôt joint par connexion, chaque membre voit **Se connecter à votre entrepôt** dans le menu utilisateur. Choisissez-le, puis **Sign in with Snowflake** ou **Sign in with Databricks**. PlaidCloud maintient votre session. Un tableau de bord ouvert sans connexion, ou après l'expiration de la vôtre, affiche *Sign in with Snowflake to view this dashboard: in PlaidCloud, open your user menu and choose Sign in to your warehouse.* (ou *Databricks*). Reconnectez-vous depuis cet élément de menu.

Un tableau de bord sur un tel entrepôt s'exécute avec les propres autorisations du lecteur dans cet entrepôt. Un lecteur qui ne s'est pas connecté voit ce message : *Sign in with Snowflake to view this dashboard: in PlaidCloud, open your user menu and choose Sign in to your warehouse.*

## Prérequis Databricks

- **Un espace de travail accessible à une URL publique.** Consultez la règle sur l'adresse sous [Connecter](#2-se-connecter).
- **Unity Catalog** avec un catalogue dans lequel PlaidCloud peut créer des schémas. Un catalogue sans stockage géré refuse `CREATE SCHEMA`, et aucun privilège n'y remédie. Le catalogue historique `hive_metastore` n'a pas de volumes : les importations de fichiers dans un projet y échouent, et un envoi vers une connexion Databricks y s'exécute ligne par ligne.
- **Un SQL warehouse.** Nous recommandons un SQL warehouse **serverless**. Un SQL warehouse classique arrêté met plusieurs minutes à démarrer, et la première vérification de connexion ou requête après son arrêt l'attend, alors qu'un SQL warehouse serverless est prêt bien plus tôt.
- **Un administrateur de l'espace de travail et du metastore** pour exécuter le script de configuration, ou un administrateur du compte pour ajouter la connexion d'application et un administrateur de l'espace de travail pour se connecter.

PlaidCloud s'identifie auprès de Databricks avec le User-Agent `PlaidCloud_Lakehouse` pour votre entrepôt de données et ses tableaux de bord, et `PlaidCloud_Connector` pour une connexion Databricks utilisée par des workflows. Il n'inclut jamais le nom d'un locataire, d'une organisation ou d'un utilisateur.

## Méthodes de connexion à Databricks

PlaidCloud accède à Databricks de l'une de trois façons. Chacune est choisie lorsque vous ajoutez l'entrepôt de données.

| Méthode | À utiliser quand | Renouvellement |
|---|---|---|
| Sign in with Databricks (OAuth U2M) | Vous voulez que les tableaux de bord et les requêtes de chaque personne s'exécutent avec ses propres autorisations Databricks | PlaidCloud maintient la connexion à jour |
| Secret OAuth d'un service principal (OAuth M2M) | Les workflows et les tableaux de bord doivent s'exécuter sous un seul service principal | PlaidCloud génère un nouveau jeton d'accès avant l'expiration de l'ancien |
| Jeton d'accès personnel | Vous ne pouvez utiliser aucune des deux méthodes OAuth | Le jeton expire à sa date, et vous en ajoutez un nouveau |

### Se connecter avec Databricks

PlaidCloud se connecte avec le flux OAuth par code d'autorisation et PKCE.

1. En tant qu'administrateur du compte, ouvrez **Account console > Settings > App connections** et ajoutez une application nommée `PlaidCloud`. Donnez-lui l'URL de redirection affichée dans la fenêtre de connexion et l'accès à toutes les API, et laissez **Generate a client secret** désactivé. L'accès à toutes les API est obligatoire : PlaidCloud utilise la connexion de l'administrateur pour créer son service principal, et les personnes qui se connectent ensuite n'obtiennent que la portée `sql`.
2. Copiez l'ID client de l'application.
3. Dans PlaidCloud, ouvrez votre menu utilisateur, choisissez **Gérer les entrepôts de données**, puis **Ajouter un entrepôt de données**, et choisissez **Databricks**.
4. Sous **Le plus rapide : se connecter avec Databricks**, saisissez **URL de l'espace de travail**, **ID client** et **Chemin HTTP du SQL warehouse**. **Catalogue** est facultatif.
5. Choisissez **Se connecter avec Databricks**, connectez-vous en tant qu'administrateur de l'espace de travail Databricks, et approuvez. PlaidCloud crée son propre service principal pour les workflows. Consultez [Rattacher l'entrepôt](#rattacher-lentrepôt).

### Secret OAuth d'un service principal

1. Dans PlaidCloud, ouvrez **Gérer les entrepôts de données**, choisissez **Ajouter un entrepôt de données**, puis choisissez **Databricks**.
2. En tant qu'administrateur de l'espace de travail et du metastore, exécutez le script de configuration depuis la fenêtre (voir [Exécuter d'abord le script de configuration](#1-exécuter-dabord-le-script-de-configuration)). Il crée le service principal, le SQL warehouse et le catalogue. Ou créez vous-même un service principal, générez-lui un secret OAuth dans Databricks et accordez-lui les privilèges de [Privilèges minimaux Databricks](#privilèges-minimaux-databricks).
3. Sous **2. Connecter**, saisissez **URL de l'espace de travail**, **Chemin HTTP du SQL warehouse**, **ID d'application** (l'ID d'application du service principal) et **Secret OAuth**.
4. Choisissez **Tester la connexion**, puis **Utiliser comme mon entrepôt de données**.

PlaidCloud demande la portée `all-apis` lorsqu'il génère un jeton.

### Jeton d'accès personnel

1. Dans Databricks, créez un jeton d'accès personnel pour un utilisateur ou un service principal qui dispose des privilèges de [Privilèges minimaux Databricks](#privilèges-minimaux-databricks).
2. Dans PlaidCloud, ouvrez **Gérer les entrepôts de données**, choisissez **Ajouter un entrepôt de données**, puis choisissez **Databricks**.
3. Sous **2. Connecter**, saisissez **URL de l'espace de travail** et **Chemin HTTP du SQL warehouse**.
4. Sélectionnez **Avancé : utiliser plutôt un jeton d'accès personnel** et collez le jeton dans **Jeton**. **ID d'application** et **Secret OAuth** ne sont pas nécessaires.
5. Choisissez **Tester la connexion**, puis **Utiliser comme mon entrepôt de données**.

Un jeton expire à sa date, et PlaidCloud n'accède plus à votre entrepôt de données tant que vous n'en ajoutez pas un nouveau. Consultez [Connecter](#2-se-connecter) pour la bannière de renouvellement.

## Privilèges minimaux Databricks

Accordez-les au service principal, ou à l'utilisateur dans le cas d'un jeton d'accès personnel. **Tester la connexion** vérifie les privilèges nécessaires pour rattacher l'entrepôt de données et liste ceux qui manquent sous forme d'instructions `GRANT` prêtes à exécuter. Un privilège manquant sur un volume n'apparaît qu'au moment d'une importation ou d'un envoi.

| Pour | Accorder |
|---|---|
| Rattacher l'entrepôt de données | `USE CATALOG`, `CREATE SCHEMA` et `USE SCHEMA` sur le catalogue, et `CAN_USE` sur le SQL warehouse |
| Interroger et écrire des tables | `USE SCHEMA`, `SELECT`, `MODIFY` et `CREATE TABLE` sur le schéma du projet, et `CAN_USE` sur le SQL warehouse |
| Importer des fichiers et des documents (le volume `plaid_import` dans le schéma du projet) | `CREATE VOLUME` sur le schéma, ou `READ VOLUME` et `WRITE VOLUME` sur un volume `plaid_import` créé par un administrateur |
| Pousser une table depuis un workflow vers une connexion Databricks (le volume `plaid_export` dans le schéma cible) | `USE CATALOG` et `USE SCHEMA` sur la cible, `MODIFY` sur la table cible (et `CREATE TABLE` sur le schéma lorsque l'étape la crée), et `CREATE VOLUME` sur le schéma, ou `READ VOLUME` et `WRITE VOLUME` sur un volume `plaid_export` créé par un administrateur |

Un envoi place chaque lot dans un fichier Parquet du volume et le charge avec `COPY INTO`, avec le mode ANSI activé : une valeur qui ne tient pas dans sa colonne fait donc échouer l'étape au lieu de devenir `NULL`. Sans les privilèges sur les volumes, l'envoi se replie sur des instructions `INSERT` ligne par ligne, bien plus lentes, et l'étape émet un avertissement qui nomme les privilèges à ajouter. Sur le catalogue `hive_metastore`, l'envoi s'exécute toujours ligne par ligne, sans avertissement.

## Comportements Databricks à connaître

- **L'importation de fichiers et de documents nécessite le service principal.** Sur un entrepôt de données rattaché par connexion sans service principal (un rattachement SQL uniquement), une importation s'arrête et indique qu'un administrateur de l'espace de travail doit se reconnecter avec Databricks pour en ajouter un.
- **Les tableaux de bord se réenregistrent une fois après la mise à niveau.** Chaque connexion de tableau de bord Databricks est enregistrée de nouveau une fois avec le User-Agent PlaidCloud. Vous n'avez rien à faire.
- **Supprimer un entrepôt de données ne peut pas révoquer une connexion chez Databricks.** Databricks ne documente aucun moyen de révoquer le jeton de connexion que PlaidCloud détient pour une personne. PlaidCloud supprime sa copie et, lorsque chacun est le seul, le secret du service principal et un jeton d'accès personnel, mais un jeton de connexion lui-même reste valide chez Databricks. PlaidCloud ne supprime pas le service principal qu'il a créé ; supprimez-le dans Databricks. Pour mettre fin aux connexions, supprimez la connexion d'application `PlaidCloud` sous **Account console > Settings > App connections**.

## Gérer les entrepôts de données

Un administrateur de l'espace de travail ouvre le menu utilisateur et choisit **Gérer les entrepôts de données**. La fenêtre **Vos entrepôts de données** liste pour chaque entrepôt son **Nom**, son **Moteur**, son **Statut**, **Par défaut** et ses **Projets**. Tant que l'espace de travail n'a aucun entrepôt Snowflake ou Databricks, une carte au-dessus de la liste indique **Vous utilisez l'entrepôt de données de PlaidCloud – apportez le vôtre**.

**Ajouter un entrepôt de données** dans la barre d'outils ouvre le même parcours que la connexion, intitulé **Ajouter un entrepôt de données**. Votre entrepôt est ajouté, et l'entrepôt par défaut des nouveaux projets ne change pas.

Pour toute autre opération, sélectionnez un entrepôt et choisissez dans le ⋯ au début de sa ligne, dans son menu contextuel (clic droit) ou dans **Actions**. Chaque choix n'apparaît que là où il s'applique.

| Action | Ce qu'elle fait |
|---|---|
| **Détails** | Ouvre [Détails de l'entrepôt de données](#détails-de-lentrepôt-de-données). |
| **Définir par défaut** | Les nouveaux projets utilisent cet entrepôt une fois que l'espace de travail a basculé dessus, ce qui prend généralement quelques minutes. Les projets déjà créés restent sur l'entrepôt sur lequel ils ont été créés. Seul un entrepôt **Actif** peut devenir l'entrepôt par défaut. |
| **Renommer…** | Modifie le nom de l'entrepôt. |
| **Renouveler la connexion…** | Pour un entrepôt rattaché par connexion : vous reconnecte à Snowflake ou à Databricks. |
| **Renouveler l'identifiant…** | Pour une paire de clés, un jeton ou un secret OAuth : collez le nouveau. PlaidCloud le vérifie d'abord auprès de votre entrepôt et ne remplace l'actuel que si la vérification réussit. |
| **Désactiver…** | Suspend l'entrepôt. La confirmation indique combien de projets l'utilisent ; ils sont suspendus jusqu'à sa réactivation et conservent leurs données. L'entrepôt par défaut ne peut pas être désactivé. |
| **Activer** | Réactive un entrepôt désactivé. |
| **Supprimer** | Déconnecte l'entrepôt. Fonctionne uniquement lorsque l'entrepôt n'est pas celui par défaut et qu'aucun projet ne l'utilise ; sinon, il vous en indique la raison. |

**Statut** indique où en est chaque entrepôt.

| Statut | Signification |
|---|---|
| **Provisionnement** | PlaidCloud configure encore l'entrepôt. |
| **Changement en cours…** | Une modification est enregistrée et en route vers votre espace de travail. |
| **Actif** | Prêt à l'emploi. |
| **Désactivé** | Les projets qui l'utilisent sont suspendus jusqu'à sa réactivation. |
| **Attention** | Sa dernière vérification a échoué, ou son jeton d'accès personnel expire dans moins de 14 jours. [Détails de l'entrepôt de données](#détails-de-lentrepôt-de-données) en donne la raison. |

<Aside type="note">Une modification, comme un nouvel entrepôt, un nouvel entrepôt par défaut, un nouveau nom ou la désactivation d'un entrepôt, met quelques minutes à parvenir à votre espace de travail. Chaque espace de travail s'exécute de façon isolée des autres et prend en compte seul les changements de configuration ; tant que la modification n'est pas arrivée, l'entrepôt affiche **Changement en cours…**, et un nouvel entrepôt ne peut pas encore être utilisé par les projets. La liste se vérifie à nouveau toutes les quelques secondes pendant 10 minutes au maximum, puis affiche **Pas encore appliqué – actualisez plus tard.** Si la modification n'est toujours pas arrivée après une heure, contactez l'assistance PlaidCloud.</Aside>

Lorsque vous supprimez un entrepôt, PlaidCloud révoque son identifiant dans votre compte et en supprime sa copie. Sur Snowflake, cela comprend toutes les connexions et l'identité de service. Sur Databricks, cela comprend le secret du service principal, mais pas les connexions des personnes (voir [Comportements Databricks à connaître](#comportements-databricks-à-connaître)). Vos données restent dans votre entrepôt. Si l'identifiant ne peut pas être révoqué, PlaidCloud vous indique de le révoquer vous-même dans votre compte.

### Exécuter un exemple

Lorsque **Vos entrepôts de données** s'ouvre sur un entrepôt précis, comme c'est le cas après un rattachement par connexion, et que cet entrepôt est l'entrepôt par défaut et **Actif**, la fenêtre indique **Votre entrepôt de données est prêt. Exécutez un exemple pour le voir fonctionner.** **Exécuter un exemple** demande d'abord **Supprimer les données d'échantillon ?** : cela supprime définitivement le projet d'exemple fourni au départ, qui s'exécutait sur l'ancien entrepôt, et laisse vos propres projets et données intacts. Il charge ensuite un nouvel exemple et l'exécute sur votre entrepôt ; suivez-le dans Workflows. Un projet d'exemple qui contient vos propres modifications n'est pas remplacé, et rien ne s'exécute.

## Détails de l'entrepôt de données

Choisissez **Détails** sur un entrepôt pour ouvrir **Détails de l'entrepôt de données**.

| Ligne | Ce qu'elle affiche |
|---|---|
| **Statut** | Le statut de l'entrepôt. Lorsqu'il n'est pas **Actif**, **Pourquoi** l'explique : par exemple, le problème trouvé par une vérification en échec et sa solution, ou la date d'expiration d'un jeton. |
| **Moteur** | Snowflake ou Databricks. |
| **Hôte** | L'adresse de l'entrepôt, partiellement masquée. |
| **Compte** | Votre compte Snowflake ou Databricks, lorsque PlaidCloud le connaît. |
| **Authentification** | **Paire de clés**, **Jeton d'accès personnel**, **Principal de service** ou **Connecté auprès du fournisseur**. |
| **Le jeton expire** | Pour un jeton d'accès personnel : sa date d'expiration, avec **Renouveler l'identifiant…**. |
| **Dernière vérification** | Quand l'entrepôt a été vérifié pour la dernière fois, et si le résultat est **OK** ou **Échec**. |
| **Projets** | Le nombre de projets qui l'utilisent. |
| **Connexion** | La façon dont votre espace de travail l'atteint. Voir [Connexions directes](#connexions-directes). |

**Vérifier maintenant** vérifie à nouveau un entrepôt Snowflake ou Databricks avec l'identifiant que PlaidCloud détient, enregistre le résultat comme **Dernière vérification**, et indique **Tout ce dont PlaidCloud a besoin est en place.** ou ce qui ne va pas et comment le corriger. Lorsque des autorisations manquent, il les liste sous forme d'instructions à exécuter dans votre entrepôt, chacune avec **Copier** et **Terminé**, comme dans [Vérifier, puis l'utiliser](#3-vérifier-puis-lutiliser). Exécutez-les, puis choisissez à nouveau **Vérifier maintenant**.

Tant qu'une modification est en cours d'application ou qu'une connexion directe est en cours de configuration, la fenêtre se met à jour toute seule pendant 10 minutes au plus après son ouverture ou votre demande de connexion. Passé ce délai, actualisez **Vos entrepôts de données** (F5) et choisissez de nouveau **Détails**.

## Connexions directes

La ligne **Connexion** de [Détails de l'entrepôt de données](#détails-de-lentrepôt-de-données) indique comment votre espace de travail atteint l'entrepôt. PlaidCloud déduit l'endroit où l'entrepôt s'exécute de son adresse : une adresse Snowflake à localisateur de compte, comme `xy12345.us-east-2.aws.snowflakecomputing.com`, nomme son cloud et sa région, une adresse Databricks ne nomme que son cloud, et une adresse Snowflake de compte d'organisation ne nomme ni l'un ni l'autre.

| Connexion | Signification |
|---|---|
| **Même cloud et même région** | L'entrepôt s'exécute dans le même cloud et la même région que votre espace de travail. |
| **Internet public** | L'entrepôt s'exécute dans un autre cloud ou une autre région. Les requêtes traversent l'internet public ; le temps de réponse et les frais de sortie de données s'appliquent. |
| **Privée – lien direct** | Votre espace de travail atteint l'entrepôt par un lien privé, tel qu'AWS PrivateLink, Azure Private Link ou Google Private Service Connect, et ses requêtes ne traversent pas l'internet public. |
| **Non détecté** | PlaidCloud n'a pas pu déterminer où s'exécute l'entrepôt. |

Une connexion directe remplace le chemin public entre votre espace de travail et l'entrepôt par un chemin privé. Elle est destinée à un entrepôt situé dans le même cloud et la même région que votre espace de travail.

### Demander une connexion directe

**Demander une connexion directe** apparaît dans **Détails de l'entrepôt de données** lorsque le forfait de votre espace de travail inclut la connectivité privée, que l'entrepôt est un entrepôt Snowflake ou Databricks activé, et qu'aucune demande n'est ouverte. Seul un administrateur de l'espace de travail peut en faire la demande. Après que vous l'avez choisie, la ligne **Connexion** suit la demande.

| Connexion | Signification |
|---|---|
| **Demandé** | PlaidCloud a reçu la demande et va commencer à la configurer. |
| **Configuration en cours** | PlaidCloud configure la connexion privée. |
| **En attente de l'administrateur de votre entrepôt de données** | La connexion nécessite quelques étapes dans le compte de votre entrepôt avant de pouvoir se terminer. |
| **Privée – lien direct** | La connexion est vérifiée et utilisée. |
| **Nécessite une attention** | La connexion privée ne fonctionne pas. Vérifiez les étapes ou contactez PlaidCloud. |

Tant que la connexion directe n'a pas réussi sa vérification, votre espace de travail continue d'atteindre l'entrepôt comme avant. Pendant que PlaidCloud la vérifie, la ligne indique **Vérification de la connexion…**. Si PlaidCloud ramène l'entrepôt sur le chemin public, la ligne indique de nouveau comment l'entrepôt est atteint et **Demander une connexion directe** est de nouveau proposé.

### Étapes dans le compte de votre entrepôt

Pendant la configuration de la connexion, ou lorsqu'elle nécessite une attention, **afficher les étapes** à côté de la ligne **Connexion** ouvre les étapes destinées à l'administrateur de votre entrepôt, numérotées, avec le texte exact à exécuter et **Copier** lorsqu'une étape en comporte. Une étape qui attend PlaidCloud l'indique jusqu'à ce que PlaidCloud la renseigne. Prévenez votre contact PlaidCloud une fois les étapes exécutées.

| Moteur | Ce que demandent les étapes |
|---|---|
| Snowflake | L'édition Business Critical ou supérieure. Une instruction, exécutée en tant que `ACCOUNTADMIN`, qui autorise le point de terminaison privé de PlaidCloud. Une modification de la politique réseau créée par le script de configuration, effectuée avant que PlaidCloud ne bascule : elle ajoute une règle réseau pour le point de terminaison privé et déplace les adresses publiques de PlaidCloud dans une règle distincte, car une politique comportant des règles réseau ne lit plus sa liste d'adresses IP. Les instructions peuvent être exécutées plusieurs fois sans risque. |
| Databricks | Un espace de travail du niveau que requiert la connectivité privée (Enterprise sur AWS, Premium sur Google Cloud, Premium avec injection VNet sur Azure). L'enregistrement du point de terminaison de PlaidCloud pour l'espace de travail dans votre console de compte ou, sur Azure, l'approbation de la connexion de point de terminaison privé en attente de PlaidCloud dans l'onglet Networking de l'espace de travail. L'autorisation de PlaidCloud en privé dans vos paramètres d'accès privé, en laissant l'accès public activé pour les adresses de PlaidCloud. |

<Aside type="note">Le plan de contrôle de PlaidCloud atteint toujours votre entrepôt à son adresse publique pour se connecter, configurer et déconnecter. Laissez l'accès public activé pour les adresses du script de configuration, comme le font les étapes.</Aside>

## Coût de l'entrepôt par exécution

Sur votre propre entrepôt, l'historique d'exécution d'un workflow Alteryx converti affiche une colonne **Coût de l'entrepôt**, et la fenêtre [Prouvez votre migration](/fr/guides/workflows/validate-converted-alteryx-workflows/#prouvez-votre-migration) affiche le coût de la dernière exécution et une estimation pour la prochaine. Les coûts sont exprimés en crédits sur Snowflake et en DBU sur Databricks.

| Libellé | Signification |
|---|---|
| *attributed* | Snowflake a facturé ces crédits aux requêtes de l'exécution, lus grâce à l'autorisation `GOVERNANCE_VIEWER`. L'attribution apparaît après le délai de reporting de Snowflake. |
| *estimated* | Calculé à partir du temps d'exécution des requêtes et de la taille de l'entrepôt, affiché avec un ≈ en tête. C'est toujours le cas sur Databricks, et sur Snowflake avant l'arrivée de l'attribution ou sans l'autorisation. |

Le coût couvre les étapes exécutées par le moteur de PlaidCloud. Une exécution tarifée en partie est marquée *partial*, et une exécution dont le coût n'a pas encore été rapporté l'indique.

## Vos politiques et descriptions sont conservées

Les descriptions de schéma, de table et de colonne définies dans PlaidCloud sont écrites sous forme de commentaires dans le catalogue propre à votre entrepôt. Les politiques d'accès aux lignes, de masquage, de projection, d'agrégation et de jointure sur Snowflake, ainsi que les filtres de lignes et les masques de colonne sur Databricks, restent attachés lorsque PlaidCloud remplace, recrée ou clone une table. Si une politique ne peut pas être conservée, PlaidCloud laisse la table telle quelle et le message nomme la politique et la raison.

## Lier un projet à votre entrepôt de données

Dès que votre espace de travail dispose d'un entrepôt connecté, la boîte de dialogue **Nouveau projet** (**Analyze > Projets > Nouveau projet**) propose un sélecteur de lakehouse : choisissez **Valeur par défaut du locataire** ou sélectionnez un entrepôt précis. **Valeur par défaut du locataire** correspond au PlaidCloud Lakehouse intégré, sauf si un entrepôt est défini par défaut, auquel cas les nouveaux projets y sont créés automatiquement. Choisissez **Définir par défaut** dans [Gérer les entrepôts de données](#gérer-les-entrepôts-de-données), ou **Utiliser comme mon entrepôt de données** dans une boîte de dialogue qui n'a pas été ouverte depuis **Ajouter un entrepôt de données**, pour définir la valeur par défaut. Cela n'affecte que les projets créés ensuite ; les projets existants conservent le backend avec lequel ils ont été créés. À partir de là :

- Chaque table que les workflows du projet créent, chargent ou transforment est créée et écrite dans votre lakehouse.
- Les lectures — dans les étapes, les vues et les tableaux de bord — s'exécutent sous forme de requêtes sur votre entrepôt.
- Rien n'est copié dans le PlaidCloud Lakehouse ; les données restent dans votre compte.

Créez vos workflows exactement comme sur le lakehouse intégré : les étapes d'importation, de transformation, de jointure et de publication fonctionnent toutes de la même façon. Le backend est défini à la création du projet et s'applique à l'ensemble du projet.

## Importer des fichiers dans un projet lié à un lakehouse

L'importation d'un fichier CSV, Parquet, XML ou Access dans un projet lié à un lakehouse le charge via le **chemin de chargement en masse natif et parallèle** de votre entrepôt : une zone de transit interne Snowflake plus `COPY INTO` pour Snowflake, un volume géré Databricks plus `COPY INTO` pour Databricks (voir [Privilèges minimaux Databricks](#privilèges-minimaux-databricks)) — au lieu de transiter le fichier par un bucket cloud externe. Aucun IAM cloud supplémentaire n'est à configurer, et le fonctionnement est identique quel que soit le cloud sur lequel s'exécute votre entrepôt.

## Exporter les résultats de requêtes et de tables

L'exportation des résultats de requêtes ou de tables depuis un projet lié à un lakehouse les livre directement dans le stockage cloud, au lieu de faire repasser chaque ligne par PlaidCloud :

- **Snowflake** — l'export s'exécute comme un déchargement côté serveur Snowflake (`COPY INTO` vers une zone de transit), de sorte que l'entrepôt écrit les résultats directement dans le stockage. Les exports volumineux sont automatiquement répartis en plusieurs fichiers (auparavant, un export dépassant la limite de fichier unique de Snowflake échouait).
- **Databricks** — l'export s'exécute comme un déchargement côté serveur Databricks (`INSERT OVERWRITE DIRECTORY` dans un volume géré Unity Catalog), de sorte que l'entrepôt écrit et encode lui-même les résultats et que PlaidCloud se contente de relayer les fichiers terminés vers le stockage. Les exports volumineux sont automatiquement répartis sur plusieurs fichiers, et le CSV peut être livré compressé en gzip.

## Tableaux de bord sur les données du lakehouse

Les tableaux de bord fonctionnent avec les deux moteurs.

- **Databricks** — les tableaux de bord se connectent via le pilote Databricks, avec les identifiants OAuth du service principal (ou un jeton d'accès personnel). Sur un entrepôt rattaché par [connexion](#se-connecter-avec-snowflake-ou-databricks), le tableau de bord de chaque lecteur s'exécute avec sa propre identité Databricks.
- **Snowflake** — les tableaux de bord se connectent avec l'utilisateur de service de l'entrepôt et sa paire de clés. Sur un entrepôt rattaché par [connexion](#se-connecter-avec-snowflake-ou-databricks), le tableau de bord de chaque lecteur s'exécute à la place avec sa propre identité Snowflake. Le tableau de bord d'un projet est configuré lors de la création ou de la publication du projet.

## Faire enregistrer un entrepôt de données par PlaidCloud

Vous n'êtes pas obligé de connecter un entrepôt vous-même. Communiquez à votre contact PlaidCloud les informations ci-dessous pour le moteur que vous connectez, et un administrateur l'enregistre en votre nom.

### Snowflake

| Champ | Ce qu'il faut fournir |
|---|---|
| Nom d'hôte | L'hôte de votre compte Snowflake. |
| Superutilisateur | L'utilisateur Snowflake sous lequel PlaidCloud s'authentifie. |
| Base de données | La base de données dans laquelle PlaidCloud crée et gère les schémas de projet. |
| Entrepôt de données | L'entrepôt de calcul sous lequel PlaidCloud exécute les requêtes. |
| Rôle | Le rôle Snowflake que PlaidCloud endosse. |
| Clé privée | La clé privée PEM **brute et non chiffrée** pour l'authentification par paire de clés — collez le texte de la clé lui-même, pas une copie encodée en base64. Les clés protégées par phrase secrète ne sont pas encore prises en charge. |

Générez une paire de clés et attribuez la clé publique au superutilisateur Snowflake avant de transmettre la clé privée. Le rôle doit pouvoir créer, lire et écrire des tables dans la base de données cible.

### Databricks

| Champ | Ce qu'il faut fournir |
|---|---|
| Nom d'hôte | L'URL de votre espace de travail Databricks. |
| Chemin HTTP | Le chemin HTTP du SQL warehouse sur lequel PlaidCloud exécute les requêtes. |
| Unity Catalog | Le catalogue Unity Catalog dans lequel PlaidCloud crée et gère les schémas de projet. |
| Jeton d'accès personnel | Un PAT Databricks pour l'authentification. |

L'identité du jeton doit pouvoir créer, lire et écrire des tables dans ce catalogue.

Aucun des deux enregistrements ne demande de schéma : chaque projet obtient le sien, dérivé automatiquement de son DSN lorsque le projet est lié au lakehouse.

Le formulaire d'enregistrement comporte un bouton **Tester la connexion** qui ouvre une connexion réelle avec les informations saisies et indique la réussite ou la raison de l'échec, sans rien enregistrer — ce qui permet de vérifier les identifiants avant l'enregistrement du lakehouse. Un test Snowflake nécessite la clé privée PEM brute et non chiffrée (une clé protégée par phrase secrète est signalée comme non prise en charge) ; un test Databricks utilise le PAT.

Un entrepôt enregistré n'est pas utilisable dès qu'il est sauvegardé. Il affiche **Changement en cours…** dans **Vos entrepôts de données** pendant quelques minutes, pour la même raison qu'un entrepôt que vous ajoutez vous-même (consultez [Gérer les entrepôts de données](#gérer-les-entrepôts-de-données)).

<Aside type="note">La connexion à un catalogue Iceberg/Lakekeeper s'enregistre séparément et est facultative : elle n'est pas nécessaire pour utiliser un entrepôt Snowflake ou Databricks.</Aside>
