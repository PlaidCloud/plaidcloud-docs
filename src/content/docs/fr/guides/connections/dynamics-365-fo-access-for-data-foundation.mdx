[Data Foundation](/fr/guides/projects/data-foundation/) rassemble dans un seul Common Finance Model les données de chaque système ERP et de chaque instance que vous connectez, et Dynamics 365 Finance and Operations fait partie des ERP qu'il lit directement. La connexion utilise une application Microsoft Entra ID avec un secret client pour les données de base, et le point de terminaison SQL de votre Fabric (Synapse) Link pour le journal général, les sous-registres et les soldes bancaires. Cette page s'adresse à l'administrateur Dynamics 365 qui effectue cette configuration, et à l'utilisateur PlaidCloud qui la lui demande.

PlaidCloud ne fait que lire les données. Personne n'envoie de secret client ni de mot de passe SQL par e-mail.

## Envoyer la demande d'accès

Dans la page **Systèmes** du projet, sous **Data Foundation** dans **Accueil**, choisissez votre système dans **Système** sous **Ajouter un système**, puis cliquez sur **Vous n’avez pas encore accès ?**. Le système attend l'accès, et une demande unique couvrant les systèmes du projet s'affiche. Cliquez sur **Copier la demande** pour la coller dans votre propre message, ou sur **Envoyer la demande par e-mail** pour l'ouvrir dans votre messagerie avec l'objet « Accès à PlaidCloud. »

## Ce que l'administrateur Dynamics 365 configure

<Steps>

1. **Enregistrez une application dans Microsoft Entra ID** pour PlaidCloud, avec un secret client. Notez son ID d'application (client), l'ID de l'annuaire (locataire) et le secret.

2. **Associez l'application à un utilisateur.** Dans Dynamics 365, sous **System administration > Setup > Microsoft Entra ID applications**, ajoutez l'ID client et associez-le à un utilisateur disposant d'un rôle qui peut consulter, pour chaque entité juridique que vous voulez charger :

   - Grand livre : entités juridiques, calendriers fiscaux, comptes principaux, valeurs de dimensions financières, taux de change
   - Comptes clients : clients et lignes de facture client
   - Comptes fournisseurs : fournisseurs (facultatif)
   - Gestion des informations produit : produits diffusés
   - Gestion des stocks : stock disponible et transactions de stock (facultatif)
   - Budgétisation : écritures du registre budgétaire (facultatif)

3. **Configurez Fabric Link pour le journal général.** Les lignes du journal général sont lues depuis le point de terminaison SQL de votre Fabric (Synapse) Link, et non depuis le service OData. Vérifiez que Fabric Link est activé pour ces tables, et créez sur ce point de terminaison un identifiant SQL en lecture seule pour PlaidCloud :

   - `generaljournalaccountentry`
   - `generaljournalentry`
   - `fiscalcalendarperiod`
   - `dimensionattributelevelvalue`, avec une ligne par valeur de dimension pour chaque combinaison de dimensions financières, ainsi que le nom de sa dimension
   - pour les postes ouverts et les paiements (facultatif) : `custtrans`, `vendtrans`, `custsettlement`, `vendsettlement`
   - pour les lignes de factures fournisseurs (facultatif) : `vendinvoicetrans`, `vendinvoicejour`
   - pour les soldes bancaires (facultatif) : `bankaccounttrans`, `bankaccounttable`

   Les sites et les centres de profit sont les valeurs des dimensions financières `Site` et `BusinessUnit`.

</Steps>

## Ce qu'il faut renvoyer

| L'administrateur envoie | Saisi dans PlaidCloud comme |
|---|---|
| L'URL de l'environnement, `https://<name>.operations.dynamics.com` | **URL de l'environnement** |
| L'ID de l'annuaire (locataire) | **ID du locataire Azure AD** |
| L'ID de l'application (client) | **ID client** |
| Le `dataAreaId` d'une entité juridique | **Entité juridique / société (dataAreaId)** : la connexion en a besoin d'un, et Data Foundation lit les entités juridiques choisies sous **Sociétés** |
| Le point de terminaison SQL Fabric Link, la base de données et l'identifiant | Une connexion SQL distincte dans PlaidCloud, dont l'ID de connexion se renseigne dans le paramètre système **Fabric Link SQL connection (its connection ID)** |
| Les catégories de comptes principaux de vos comptes de coût des marchandises vendues (PlaidCloud suppose `COGS`) | Le paramètre système **Cost of goods sold main account categories** |
| Les catégories de comptes principaux des comptes hors exploitation : intérêts, impôt sur le revenu, gains et pertes de change, autres produits | Le paramètre système **Non-operating main account categories** |
| La dimension financière qui nomme le partenaire intersociétés d'une ligne (PlaidCloud suppose `IntercompanyPartner`) | Le paramètre système **Intercompany partner dimension** |
| Les entités juridiques que PlaidCloud peut lire | Sous **Options**, **Sociétés** : cochez-les, ou aucune pour toutes les lire |

Le secret client et le mot de passe de l'identifiant SQL ne passent jamais par e-mail. L'équipe de l'utilisateur PlaidCloud colle elle-même le **Secret client** dans PlaidCloud, et la connexion SQL conserve l'identifiant SQL. Les entités juridiques qui sont des entités de consolidation sont à renseigner dans le paramètre système **Consolidation legal entities**, afin que leurs écritures ne soient pas comptées comme l'activité d'une société.

## Vérifier l'accès

De retour dans PlaidCloud, une fois le système ajouté, cliquez sur **Tester la connexion** sur sa ligne dans la page **Systèmes**. Chaque jeu de données s'affiche comme **Lisible**, **Autorisation manquante** ou **Erreur** :

| Jeu de données | Autorisation requise |
|---|---|
| Entités | Grand livre : consulter les entités juridiques |
| Calendrier fiscal | Grand livre : consulter les calendriers fiscaux |
| Plan comptable | Grand livre : consulter les comptes principaux |
| Départements | Grand livre : consulter les valeurs de dimensions financières |
| Clients | Comptes clients : consulter les clients |
| Produits | Gestion des informations produit : consulter les produits diffusés |
| Taux de change | Grand livre : consulter les taux de change |
| Balance de vérification, Grand livre | Consulter le grand livre (le journal, via Fabric Link) |
| Tous les autres jeux de données | Facultatif, hors du test |

Lorsqu'un jeu de données est manquant, le test nomme l'autorisation à ajouter. Demandez à l'administrateur de l'ajouter au rôle, puis testez à nouveau.

Les jeux de données facultatifs sont les sites, les centres de profit, les fournisseurs, les lignes de vente, les soldes de stock, les budgets, les soldes bancaires, les lignes de factures fournisseurs, les postes ouverts et les paiements. Un environnement qui n'en contient pas un charge quand même tout le reste. Les soldes bancaires, les lignes de factures fournisseurs, les postes ouverts ou les paiements d'un mois qui ne peuvent pas être lus depuis Fabric Link conservent les lignes qu'ils avaient déjà et sont relus au chargement suivant.

Dynamics 365 n'a aucun objet de solde que la connexion puisse lire ; aucun solde de fin de mois n'est donc chargé : le grand livre est comparé à sa propre balance générale.
