[Data Foundation](/fr/guides/projects/data-foundation/) rassemble dans un seul Common Finance Model les données de chaque système ERP et de chaque instance que vous connectez, et Oracle Fusion Cloud ERP fait partie des ERP qu'il lit directement. La connexion Oracle Fusion utilise les identifiants client OAuth 2.0, un utilisateur d'intégration en lecture seule et un petit ensemble de rapports BI Publisher. Cette page s'adresse à l'administrateur Oracle Fusion qui effectue cette configuration, et à l'utilisateur PlaidCloud qui la lui demande.

PlaidCloud ne fait que lire les données. Personne n'envoie de mot de passe ni de secret client par e-mail.

## Envoyer la demande d'accès

Dans l'onglet **Foundation** du projet, choisissez **Créer une nouvelle connexion** sous **Connexion Oracle Fusion**. Le formulaire affiche la demande complète. Cliquez sur **Copier la demande** pour la coller dans votre propre message, ou sur **Envoyer la demande par e-mail** pour l'ouvrir dans votre messagerie avec l'objet « Read-only Oracle Fusion Cloud ERP access for PlaidCloud (OAuth 2.0 client credentials) ».

## Ce que l'administrateur Oracle Fusion configure

<Steps>

1. **Créez un utilisateur d'intégration** et attribuez-lui un rôle de poste qui peut consulter, pour chaque registre sur lequel vous produisez des rapports :

   - Grand livre : registres, calendriers comptables et statuts de période, lots d'écritures de journal, journaux et soldes de comptes (par exemple « General Accountant » avec accès aux données de ces registres)
   - Taux de conversion de devises (taux journaliers)
   - Libellés des segments de flexfield clé, jeux de valeurs et leur hiérarchie de comptes (arbres)
   - Comptes clients : factures et leurs distributions, et comptes clients
   - Articles de stock
   - Accès en exécution aux rapports BI Publisher de l'étape 3 et à l'ERP Integration Service (tâches ESS)

2. **Enregistrez une application confidentielle** dans le domaine d'identité (IAM) avec l'autorisation client credentials et la portée de l'API REST de Fusion Applications. Copiez son ID client et son secret.

3. **Déployez neuf rapports BI Publisher** sous `/Custom/PlaidCloud/DataFoundation`. Chacun s'exécute comme une tâche ESS, avec le nom du rapport comme définition de tâche, et renvoie un CSV avec les colonnes listées dans la demande :

   | Rapport | Ce qu'il renvoie |
   |---|---|
   | `PlaidCloudKeyFlexLabels` | Une ligne par segment de chaque plan comptable du grand livre : sa position, son libellé et son jeu de valeurs |
   | `PlaidCloudSegmentValues` | Chaque valeur de ces jeux de valeurs, avec le type de compte naturel et la hiérarchie des valeurs |
   | `PlaidCloudCalendar` | Les périodes comptables de chaque registre, avec les types de taux moyen de période et de fin de période du registre |
   | `PlaidCloudCodeCombinations` | Les combinaisons de codes et leurs segments |
   | `PlaidCloudBalances` | Les soldes d'ouverture de chaque registre |
   | `PlaidCloudJournalLines` | Les lignes de journal, lues registre par registre, période par période et valeur de segment d'équilibrage par valeur de segment d'équilibrage |
   | `PlaidCloudCustomers` | Les comptes clients et les noms de leurs tiers |
   | `PlaidCloudItems` | Les articles de l'organisation de stock principale |
   | `PlaidCloudSalesLines` | Une ligne par ligne de facture Comptes clients |

   Les colonnes exactes de chaque rapport figurent dans le texte de la demande, dans l'onglet **Foundation**. Donnez les noms de rapport exactement comme indiqués.

</Steps>

## Ce qu'il faut renvoyer

| L'administrateur envoie | Saisi dans PlaidCloud comme |
|---|---|
| L'hôte de votre URL Fusion Applications, sans `https://` | **Hôte du pod** |
| L'URL du jeton du domaine d'identité | **Token URL** |
| La portée de l'application API REST | **Portée** |
| L'ID client de l'étape 2 | **ID client** |
| Le secret client de l'étape 2 | **Secret client** |
| Les valeurs de segment d'équilibrage que PlaidCloud peut lire | Sous **Balancing segment values**, que Fusion ne peut pas lister : saisissez une valeur sous **Nom**, ou laissez vide pour toutes les charger |

La liste finale de la demande réclame ces valeurs ensemble. Partagez le secret client via votre gestionnaire de mots de passe, pas par e-mail. L'équipe de l'utilisateur PlaidCloud le colle elle-même dans PlaidCloud.

## Vérifier l'accès

De retour dans PlaidCloud, saisissez les valeurs et cliquez sur **Tester la connexion**. Chaque jeu de données s'affiche comme **Lisible**, **Autorisation manquante** ou **Erreur** :

| Jeu de données | Source de lecture |
|---|---|
| Entités, Calendrier fiscal, Plan comptable, Départements | Les registres, ainsi que les rapports sur les libellés de flexfield clé, les valeurs de segment et le calendrier |
| Taux de change | Les taux de conversion journaliers |
| Grand livre | Les lots d'écritures de journal et le rapport sur les lignes de journal |
| Balance de vérification | Les rapports sur les soldes et sur les combinaisons de codes |
| Clients, Produits, Lignes de vente | Les rapports sur les clients, les articles et les lignes de vente (facultatif) |

Lorsqu'un jeu de données est manquant, le test indique quelle autorisation ajouter. Demandez à l'administrateur de l'ajouter au rôle de poste, puis testez à nouveau. Les clients, les produits et les lignes de vente sont facultatifs : un pod Fusion qui ne les contient pas charge tout le reste.
