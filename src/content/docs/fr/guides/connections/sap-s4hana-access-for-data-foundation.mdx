[Data Foundation](/fr/guides/projects/data-foundation/) rassemble dans un seul Common Finance Model les données de chaque système ERP et de chaque instance que vous connectez, et SAP S/4HANA fait partie des ERP qu'il lit directement. PlaidCloud atteint le système par l'intermédiaire d'un agent [PlaidLink](/fr/reference/cli/plaidlink/) installé sur votre propre réseau, via RFC. Cette page s'adresse à l'administrateur SAP qui effectue cette configuration, et à l'utilisateur PlaidCloud qui la lui demande.

PlaidCloud ne fait que lire les données. Personne n'envoie de mot de passe par e-mail.

## Envoyer la demande d'accès

Dans la page **Systèmes** du projet, sous **Data Foundation** dans **Accueil**, choisissez votre système dans **Système** sous **Ajouter un système**, puis cliquez sur **Vous n’avez pas encore accès ?**. Le système attend l'accès, et une demande unique couvrant les systèmes du projet s'affiche. Cliquez sur **Copier la demande** pour la coller dans votre propre message, ou sur **Envoyer la demande par e-mail** pour l'ouvrir dans votre messagerie avec l'objet « Accès à PlaidCloud. »

## Ce que l'administrateur SAP configure

<Steps>

1. **Installez le package ABAP PlaidCloud** (groupe de fonctions de `Z_PLAIDCL_B5_READ_TABLE`) dans le mandant à partir duquel vous produisez des rapports, et installez un agent PlaidLink qui peut atteindre le système via RFC.

2. **Créez un utilisateur de communication**, par exemple `PLAIDCLOUD_RFC`, avec un rôle contenant ces autorisations :

   - `S_RFC` : exécuter le groupe de fonctions de `Z_PLAIDCL_B5_READ_TABLE`.
   - `S_TABU_NAM` (affichage, `ACTVT` 03) pour les tables ci-dessous.

   | Tables | Ce qu'elles contiennent |
   |---|---|
   | `T001` | Codes société |
   | `T009`, `T009B`, `T001B` | Variantes d'exercice et périodes comptables |
   | `SKA1`, `SKAT` | Comptes du grand livre |
   | `FAGL_011PC`, `FAGL_011ZC` | Version de bilan et compte de résultat |
   | `CSKS`, `CSKT` | Centres de coûts |
   | `SETHEADER`, `SETNODE` | Groupes de centres de coûts et de centres de profit |
   | `CEPC`, `CEPCT` | Centres de profit (facultatif) |
   | `KNA1`, `KNVV`, `KNVH` | Clients et leur hiérarchie |
   | `MARA`, `MAKT`, `T006A` | Articles et unités |
   | `TCURR`, `TCURF`, `TCURX` | Taux de change et décimales des devises |
   | `ACDOCA` | Écritures de journal du registre principal et son report à nouveau des soldes |
   | `VBRK`, `VBRP`, `PRCD_ELEMENTS` | Documents de facturation et leurs conditions |
   | `ACDOCP` | Données de planification |
   | `COSR` | Chiffres clés statistiques |
   | `T001K`, `MBEW`, `MBEWH` | Zones de valorisation, valeurs de stock des articles et prix standard |
   | `T001W`, `TKA02` | Usines, lues comme sites, et périmètre analytique de chaque code société (facultatif) |
   | `T016T`, `TKUKT`, `KNVP`, `TSPAT`, `T052U` | Noms des secteurs d'activité et des classifications de clients, commercial de chaque client, noms des divisions et des conditions de paiement (facultatif) |
   | `LFA1`, `LFB1` | Fournisseurs (facultatif) |
   | `RBKP`, `RSEG`, `BKPF` | Factures fournisseurs et leurs pièces comptables (facultatif) |
   | `EKKO`, `EKPO`, `EKKN`, `EKET`, `EKBE` | Bons de commande, ainsi que leurs réceptions et factures (facultatif) |
   | `ANLA`, `ANLZ`, `ANLB`, `ANKA`, `T095` | Le registre des immobilisations (facultatif) |
   | La table des postes individuels du domaine de résultat (`CE1` suivi de son nom) | CO-PA par valorisation (facultatif) |

   Les postes ouverts et les paiements sont lus à partir des lignes clients et fournisseurs d'`ACDOCA`, et les mouvements d'immobilisations à partir de ses écritures sur les comptes d'immobilisations.

3. **Répondez aux questions comptables** (voir ci-dessous).

</Steps>

### Questions auxquelles l'administrateur répond

| L'administrateur vous indique | Vous le saisissez dans PlaidCloud sous **Paramètres du système** |
|---|---|
| Le type de taux de change qui contient le taux moyen. PlaidCloud fait la moyenne des taux de ce type pour chaque mois. C'est souvent `M`. | **Average rate type** |
| Le type de taux de change qui contient le taux de clôture, c'est-à-dire son taux en fin de mois. Si vous n'en nommez aucun, le taux de clôture est le taux `M`. | **Closing rate type** |
| La version de bilan et compte de résultat qui présente le compte de résultat de gestion et le bilan | **Financial statement version** |
| Lesquels de ses nœuds sont les revenus, le coût des marchandises vendues, les charges d'exploitation, le hors exploitation, les actifs, les passifs, les capitaux propres et l'intersociétés | **Account type of each statement node** : une ligne par nœud, sous la forme `node = type`, avec un type que la zone liste, par exemple `Revenue` ou `Asset`. **Intercompany statement nodes** nomme les nœuds intersociétés. Les deux ne s'appliquent que lorsque **Financial statement version** est défini. |
| Que le report à nouveau des soldes (`FAGLGVTR`) a été exécuté pour chaque exercice sur lequel vous produisez des rapports | Rien à saisir. Les soldes d'ouverture y sont lus. |
| Le domaine d'amortissement de chaque livre d'immobilisations, comptable ou fiscal. Le premier est celui du registre. PlaidCloud suppose que le domaine `01` est le livre comptable. | **Depreciation area of each book** |
| Le type de mouvement de chaque type de transaction d'immobilisation, selon son premier chiffre. PlaidCloud suppose `1` entrée, `2` sortie, `3` transfert, `6` amortissement et `9` ouverture. | **Movement type of each transaction type** |
| La table des postes individuels du domaine de résultat, si vous voulez CO-PA par valorisation. Si aucune n'est nommée, aucune donnée CO-PA n'est lue. | **Operating concern line item table** |
| Le champ de valeur CO-PA de chaque compte, et lesquels d'entre eux sont des coûts | **Value field of each CO-PA account**, **CO-PA cost value fields** |

## Ce qu'il faut renvoyer

| L'administrateur envoie | Saisi dans PlaidCloud comme |
|---|---|
| L'ID du système et le serveur d'application (ou le serveur de messages et le groupe de connexion) | **Hôte** et **Numéro du système**, ou, avec **Utiliser une connexion multisystème avec équilibrage de charge**, **Hôte MS**, **Serveur MS**, **ID du système** et **Groupe** |
| Le mandant | **Client** |
| Le nom de l'utilisateur de communication | **Utilisateur** |
| Le mot de passe de l'utilisateur de communication, via votre gestionnaire de mots de passe | **Mot de passe**, que votre équipe saisit elle-même |
| Le nom de l'agent PlaidLink qui atteint le système | Le paramètre système **PlaidLink agent** |
| Les codes société que PlaidCloud peut lire | Sous **Options**, **Sociétés**, que SAP ne peut pas lister : saisissez les codes société, séparés par des virgules, ou laissez vide pour charger tous les codes société |

<Aside type="caution">
N'envoyez jamais le mot de passe par e-mail. **Mot de passe** est un secret : il est stocké dans la connexion et jamais affiché de nouveau.
</Aside>

## Vérifier l'accès

SAP est lu via un agent PlaidLink ; **Tester la connexion** ne le lit donc pas : c'est le premier chargement qui le lit, et qui nomme une table que l'utilisateur n'est pas autorisé à lire. Chaque jeu de données lit :

| Jeu de données | Tables qu'il lit |
|---|---|
| Entités | `T001` |
| Calendrier fiscal | `T001`, `T009`, `T009B`, `T001B` |
| Taux de change | `TCURR`, `TCURF` |
| Plan comptable | `SKA1`, `SKAT`, `FAGL_011PC`, `FAGL_011ZC` |
| Départements | `CSKS`, `CSKT`, `SETHEADER`, `SETNODE` |
| Centres de profit | `CEPC`, `CEPCT`, `SETHEADER`, `SETNODE` |
| Clients | `KNA1`, `KNVV`, `KNVH` |
| Produits | `MARA`, `MAKT`, `T006A` |
| Grand livre | `ACDOCA` |
| Balance de vérification | Report à nouveau des soldes `ACDOCA` |
| Lignes de vente | `VBRK`, `VBRP`, `PRCD_ELEMENTS` |
| Budget | `ACDOCP` |
| Inducteurs d'allocation | `COSR` |
| Soldes de stock | `T001K`, `MBEW`, `MBEWH` |
| Sites | `T001W`, `T001K` |
| Fournisseurs | `LFA1`, `LFB1` |
| Lignes de factures fournisseurs | `RBKP`, `RSEG`, `BKPF` |
| Bons de commande | `EKKO`, `EKPO`, `EKKN`, `EKET`, `EKBE` |
| Postes ouverts, Paiements | Lignes clients et fournisseurs d'`ACDOCA` |
| Immobilisations | `ANLA`, `ANLZ`, `ANLB`, `ANKA`, `T095` |
| Mouvements d'immobilisations | `ACDOCA`, avec `ANLA`, `ANKA`, `T095` |
| Coûts standard | `T001K`, `MBEW`, `MBEWH` |
| CO-PA par valorisation | La table nommée dans **Operating concern line item table** |

Lorsqu'un chargement nomme une table que l'utilisateur n'est pas autorisé à lire, demandez à l'administrateur de l'ajouter au rôle, puis relancez le chargement. Les centres de profit, les sites, les fournisseurs, les lignes de factures fournisseurs, les bons de commande, les postes ouverts, les paiements, les immobilisations, les mouvements d'immobilisations, les coûts standard, CO-PA, les lignes de vente, le budget, les inducteurs d'allocation et les soldes de stock sont facultatifs : un système qui n'en contient pas un charge quand même tout le reste. Les postes ouverts ou les paiements d'un mois que SAP refuse conservent les lignes qu'ils avaient déjà.

S/4HANA ne conserve pas de solde de fin de mois distinct que Data Foundation lise ; le grand livre est donc comparé à sa propre balance générale. Les domaines d'amortissement qui ne comptabilisent dans aucun registre ne sont pas lus, et les contrôles de préparation les nomment.
