[Data Foundation](/fr/guides/projects/data-foundation/) rassemble les données de chaque système ERP et de chaque instance que vous connectez dans un seul Common Finance Model, et Microsoft Dynamics 365 Business Central fait partie des ERP qu'il lit directement. La connexion repose sur une application Microsoft Entra ID avec des identifiants client, un jeu d'autorisations en lecture seule et quelques objets de page publiés comme services web. Cette page s'adresse à l'administrateur Business Central qui effectue cette configuration, et à l'utilisateur PlaidCloud qui la lui demande.

PlaidCloud lit uniquement les données. Personne n'envoie de secret client par e-mail.

## Envoyer la demande d'accès

Dans la page **Systèmes** du projet, sous **Data Foundation** dans **Accueil**, choisissez votre système dans **Système** sous **Ajouter un système**, puis cliquez sur **Vous n’avez pas encore accès ?**. Le système attend l'accès, et une demande unique couvrant les systèmes du projet s'affiche. Cliquez sur **Copier la demande** pour la coller dans votre propre message, ou sur **Envoyer la demande par e-mail** pour l'ouvrir dans votre messagerie avec l'objet « Accès à PlaidCloud. »

## Ce que l'administrateur Business Central configure

<Steps>

1. **Enregistrez une application dans Microsoft Entra ID.** Sous **App registrations > New registration**, ajoutez un secret client, puis notez l'ID de répertoire (locataire), l'ID d'application (client) et le secret.

2. **Ajoutez l'application dans Business Central.** Ouvrez **Microsoft Entra Applications**, ajoutez l'application, définissez son état sur **Activé**, puis attribuez-lui uniquement le jeu d'autorisations **D365 READ**, pour chaque société sur laquelle vous produisez des rapports. Il permet de lire toutes les pages ci-dessous. Ne lui attribuez pas **D365 BASIC** ni aucun autre jeu d'autorisations permettant d'écrire.

3. **Publiez des objets de page comme services web.** Sous **Search > Web Services > New**, publiez ces objets de page avec exactement ces noms de service, en cochant **Published**. L'API standard ne contient pas leurs champs :

   | Page | Nom du service | Remarques |
   |---|---|---|
   | 20 G/L Entries | `GLEntries` | |
   | 16 Chart of Accounts | `GLAccounts` | |
   | 100 Accounting Periods | `AccountingPeriods` | |
   | 537 Dimension Values | `DimensionValues` | |
   | 240 Business Units | `BusinessUnits` | |
   | 605 IC Partner List | `ICPartners` | |
   | 5802 Value Entries | `ValueEntries` | Coût des ventes et soldes de stocks ; facultatif |
   | 120 G/L Budget Entries | `GLBudgetEntries` | Budgets ; facultatif |
   | Statistical Ledger Entries | `StatisticalLedgerEntries` | Inducteurs statistiques ; facultatif |
   | 118 General Ledger Setup | `GeneralLedgerSetup` | Dimensions raccourcies 3 à 8 ; facultatif |
   | 479 Dimension Set Entries | `DimensionSetEntries` | Dimensions raccourcies 3 à 8 ; facultatif |
   | 573 Detailed Cust. Ledg. Entries | `DetailedCustLedgEntries` | Postes ouverts et paiements ; facultatif |
   | 574 Detailed Vendor Ledg. Entries | `DetailedVendorLedgEntries` | Postes ouverts et paiements ; facultatif |
   | 371 Bank Account List | `BankAccounts` | Soldes bancaires ; facultatif |
   | 277 Bank Account Posting Groups | `BankAccountPostingGroups` | Soldes bancaires ; facultatif |
   | Inventory Posting Setup (recherchez sa page) | `InventoryPostingSetup` | Le compte des lignes d'achat d'un article ; facultatif |

4. **Communiquez trois choix à l'utilisateur PlaidCloud :** le code source sous lequel vos écritures d'ajustement d'audit sont comptabilisées (PlaidCloud suppose `ADJUSTMENT`), la dimension qui correspond à votre département (PlaidCloud suppose Global Dimension 1, nommée `DEPARTMENT`), et celle qui correspond à votre centre de profit (PlaidCloud suppose Global Dimension 2, nommée `PROFITCENTER`). Un site est un emplacement Business Central.

</Steps>

## Ce qu'il faut renvoyer

| L'administrateur envoie | Saisi dans PlaidCloud comme |
|---|---|
| L'ID de répertoire (locataire) | **ID du locataire Azure AD** |
| L'ID d'application (client) | **ID client** |
| Le secret client | **Secret client**, saisi dans l'éditeur de connexion, pas par e-mail |
| Le nom de l'environnement, par exemple `production` | **Environnement** |
| L'ID d'une société | **ID de la société** : la connexion en a besoin d'un, et Data Foundation lit les sociétés choisies sous **Sociétés** |
| Le nom de la dimension qui correspond à votre département | Le paramètre système **Department dimension** |
| Le nom de la dimension qui correspond à votre centre de profit | Le paramètre système **Profit centre dimension** |
| Le code source sous lequel vos écritures d'ajustement d'audit sont comptabilisées | Le paramètre système **Audit adjustment source code** |
| Les sociétés que PlaidCloud peut lire | Sous **Options**, **Sociétés** : cochez-les, ou aucune pour toutes les sociétés |

Les sociétés de consolidation se déclarent dans le paramètre système **Consolidation companies**, afin que leurs écritures ne soient pas comptées comme l'activité d'une société. Les taux de change proviennent d'une seule société : indiquez-la dans le paramètre système **Exchange rate company**, sinon PlaidCloud utilise la première société.

## Vérifier l'accès

De retour dans PlaidCloud, une fois le système ajouté, cliquez sur **Tester la connexion** sur sa ligne dans la page **Systèmes**. Chaque jeu de données s'affiche comme **Lisible**, **Autorisation manquante** ou **Erreur** :

| Jeu de données | Ce dont il a besoin |
|---|---|
| Entités, Plan comptable, Clients, Produits, Taux de change, Balance de vérification | Accès à l'API (jeu d'autorisations D365 READ) |
| Calendrier fiscal | Le service web `AccountingPeriods` |
| Départements | Le service web `DimensionValues` |
| Grand livre | Le service web `GLEntries` |
| Tous les autres jeux de données | Facultatif, hors du test |

Lorsqu'un jeu de données est manquant, le test indique l'autorisation ou le service web à ajouter. Demandez à l'administrateur de l'ajouter, puis testez à nouveau.

Les jeux de données facultatifs sont les sites, les centres de profit, les fournisseurs, le solde de fin de mois, les soldes bancaires, les soldes de stocks, les lignes de vente, les lignes de factures fournisseurs, les postes ouverts, les paiements, les budgets et les inducteurs d'allocation. Un environnement qui n'en utilise pas un charge quand même tout le reste, et après le chargement suivant, les contrôles de préparation, sur le tableau de bord **CFM-Accounting - Close and assurance**, nomment toute page que Business Central refuse. Le solde de fin de mois est la balance générale à chaque fin de mois ; les soldes bancaires sont ce solde pour les comptes sur lesquels vos comptes bancaires comptabilisent. Lorsque Business Central refuse une lecture à partir de laquelle sont construits le solde de fin de mois, les soldes bancaires, les stocks, les lignes de vente, les lignes de factures fournisseurs, les postes ouverts ou les paiements d'un mois, ce mois conserve les lignes qu'il avait déjà et est relu au chargement suivant.
