[Data Foundation](/fr/guides/projects/data-foundation/) rassemble dans un seul Common Finance Model les données de chaque système ERP et de chaque instance que vous connectez, et Microsoft Dynamics 365 Business Central fait partie des ERP qu'il lit directement. La connexion utilise une application Microsoft Entra ID avec des identifiants client, un jeu d'autorisations en lecture seule et quelques pages publiées comme services web. Cette page s'adresse à l'administrateur Business Central qui effectue cette configuration, et à l'utilisateur PlaidCloud qui la lui demande.

PlaidCloud ne fait que lire les données. Personne n'envoie de secret client par e-mail.

## Envoyer la demande d'accès

Dans l'onglet **Foundation** du projet, choisissez **Créer une nouvelle connexion** sous **Connexion Business Central**. Le formulaire affiche la demande complète. Cliquez sur **Copier la demande** pour la coller dans votre propre message, ou sur **Envoyer la demande par e-mail** pour l'ouvrir dans votre messagerie avec l'objet « Read-only Business Central access for PlaidCloud (Microsoft Entra ID, client credentials) ».

## Ce que l'administrateur Business Central configure

<Steps>

1. **Enregistrez une application dans Microsoft Entra ID.** Sous **App registrations > New registration**, ajoutez un secret client, puis notez l'ID de l'annuaire (locataire), l'ID de l'application (client) et le secret.

2. **Ajoutez l'application dans Business Central.** Ouvrez **Microsoft Entra Applications**, ajoutez l'application, définissez son état sur **Activé**, et attribuez-lui les jeux d'autorisations **D365 READ** et **D365 BASIC** pour chaque société sur laquelle vous produisez des rapports. Ne lui attribuez aucun jeu d'autorisations en écriture.

3. **Publiez des pages comme services web.** Sous **Search > Web Services > New**, publiez ces pages avec exactement ces noms de service, en cochant **Published**. L'API standard n'expose pas leurs champs :

   | Page | Nom du service | Remarques |
   |---|---|---|
   | 20 G/L Entries | `GLEntries` | |
   | 16 Chart of Accounts | `GLAccounts` | |
   | 100 Accounting Periods | `AccountingPeriods` | |
   | 537 Dimension Values | `DimensionValues` | |
   | 240 Business Units | `BusinessUnits` | |
   | 605 IC Partner List | `ICPartners` | |
   | 5802 Value Entries | `ValueEntries` | Coût des marchandises vendues ; facultatif |
   | 120 G/L Budget Entries | `GLBudgetEntries` | Budgets ; facultatif |
   | Statistical Ledger Entries | `StatisticalLedgerEntries` | Inducteurs statistiques ; facultatif |
   | 118 General Ledger Setup | `GeneralLedgerSetup` | Dimensions de raccourci 3 à 8 ; facultatif |
   | 479 Dimension Set Entries | `DimensionSetEntries` | Dimensions de raccourci 3 à 8 ; facultatif |

4. **Communiquez à l'utilisateur PlaidCloud deux choix :** le code source sous lequel vos ajustements d'audit sont comptabilisés (PlaidCloud suppose `ADJUSTMENT`), et la dimension qui correspond à votre département (PlaidCloud suppose la dimension globale 1, nommée `DEPARTMENT`).

</Steps>

## Ce qu'il faut renvoyer

| L'administrateur envoie | Saisi dans PlaidCloud comme |
|---|---|
| L'ID de l'annuaire (locataire) | **Directory (tenant) ID** |
| Le nom de l'environnement, par exemple `production` | **Nom de l'environnement** |
| L'ID de l'application (client) | **Application (client) ID** |
| Le secret client | **Secret client**, saisi dans le formulaire et non envoyé par e-mail |
| Le nom de la dimension qui correspond à votre département | Le paramètre système `department_dimension` |
| Les sociétés que PlaidCloud peut lire | Choisies sous **Sociétés** dans PlaidCloud (au moins une) |

Les sociétés de consolidation sont à renseigner dans le paramètre système `consolidation_companies`, afin que leurs écritures ne soient pas comptées comme l'activité d'une société. Les taux de change proviennent d'une seule société : nommez-la dans le paramètre système `rate_company`, sinon PlaidCloud utilise la première société.

## Vérifier l'accès

De retour dans PlaidCloud, saisissez les valeurs et cliquez sur **Tester la connexion**. Chaque jeu de données s'affiche comme **Lisible**, **Autorisation manquante** ou **Erreur** :

| Jeu de données | Ce dont il a besoin |
|---|---|
| Entités, Plan comptable, Clients, Produits, Taux de change, Balance de vérification | Accès à l'API (jeu d'autorisations D365 READ) |
| Calendrier fiscal | Le service web `AccountingPeriods` |
| Départements | Le service web `DimensionValues` |
| Grand livre | Le service web `GLEntries` |
| Lignes de vente, Budget, Inducteurs d'allocation | Facultatif |

Lorsqu'un jeu de données est manquant, le test indique quelle autorisation ou quel service web ajouter. Demandez à l'administrateur de l'ajouter, puis testez à nouveau. Les lignes de vente, le budget et les inducteurs d'allocation sont facultatifs : un environnement qui ne les utilise pas charge tout le reste.
