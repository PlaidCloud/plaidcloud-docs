Une étiquette marque un commit comme important, généralement une version telle que `v1.2.0`. Une release s'appuie sur une étiquette en y ajoutant des notes lisibles et des pièces jointes facultatives, afin que les utilisateurs puissent parcourir et télécharger des versions précises depuis l'interface web.

## Créer une étiquette

Vous pouvez créer une étiquette depuis l'interface ou depuis votre clone local.

**Depuis l'interface :**

1. Ouvrez votre dépôt et sélectionnez **Releases**, puis **Étiquettes**.
2. Sélectionnez **Create Tag**.
3. Saisissez un nom d'étiquette (par exemple `v1.2.0`), choisissez la branche ou le commit cible, puis sélectionnez **Create Tag**.

**Depuis la ligne de commande :**

```bash
git tag v1.2.0
git push origin v1.2.0
```

Pour étiqueter un ancien commit précis, indiquez son ID de commit au lieu de vous appuyer sur `HEAD` :

```bash
git tag v1.2.0 abc1234
git push origin v1.2.0
```

## Publier une release

1. Ouvrez votre dépôt et sélectionnez **Releases**.
2. Sélectionnez **New Release**.
3. Dans le champ **Tag Name**, choisissez une étiquette existante ou saisissez un nouveau nom pour en créer une à l'extrémité actuelle de la branche par défaut.
4. Saisissez un **Release Title** et rédigez les notes de release dans le corps en Markdown : journaux des modifications, instructions de mise à niveau et problèmes connus y ont tous leur place.
5. Sélectionnez **This is a pre-release** si la version n'est pas prête pour un usage général, ou **Enregistrer le brouillon** pour la terminer plus tard sans la publier.
6. Sélectionnez **Publish Release** lorsqu'elle est prête.

<Aside>Les releases en brouillon ne sont visibles que des membres du dépôt disposant d'un accès en écriture. Une préversion est visible de toute personne ayant accès, mais elle est exclue de la désignation « Latest » dans la vue d'ensemble du dépôt.</Aside>

## Joindre des fichiers

Les fichiers téléversés apparaissent sur la page de la release sous forme de liens de téléchargement nommés, à côté de l'archive source générée automatiquement.

1. Dans le formulaire de création ou de modification de la release, accédez à la section **Attach Files**.
2. Faites glisser les fichiers sur la zone de téléversement, ou sélectionnez-la pour parcourir : binaires compilés, archives compressées, sommes de contrôle et signatures sont des choix courants.
3. Répétez l'opération pour chaque fichier, puis publiez ou mettez à jour la release.

Gardez une taille raisonnable pour chaque fichier afin que les téléchargements restent rapides pour votre équipe.

<Aside type="tip">Pour les packages installables (modules npm, images de conteneur, wheels PyPI et équivalents), le [registre de packages](/fr/guides/git/packages/) est mieux adapté que les pièces jointes de release. Il gère la résolution des versions, les métadonnées de dépendances et les outils clients (`npm`, `pip`, `docker pull`) d'une manière qu'un simple téléchargement de fichier ne permet pas.</Aside>

## Consulter et télécharger des releases

1. Sélectionnez **Releases** pour voir la liste complète, de la plus récente à la plus ancienne.
2. La dernière release qui n'est pas une préversion est mise en évidence par un badge **Latest**.
3. Chaque entrée affiche le nom de l'étiquette, le titre de la release, les notes et des liens vers :
   - **Source code** : archives `zip` et `tar.gz` générées automatiquement du commit étiqueté.
   - **Assets** : tous les fichiers que vous avez joints lors de la publication de la release.
4. Sélectionnez un lien de fichier pour le télécharger directement, ou copiez l'URL pour la partager.

Pour comparer deux releases, ouvrez leurs noms d'étiquette sous forme d'URL de comparaison :

```bash
https://git.example.plaidcloud.com/you/my-repo/compare/v1.1.0...v1.2.0
```
