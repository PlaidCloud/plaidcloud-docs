Les tickets offrent à votre équipe un endroit partagé pour suivre les bogues, planifier les fonctionnalités et consigner tout ce qui demande de l'attention, le tout directement lié au code de votre dépôt.

## Créer un ticket

1. Ouvrez votre dépôt et sélectionnez l'onglet **Issues**.
2. Sélectionnez **New Issue**.
3. Saisissez un **Titre** concis qui décrit le problème ou la tâche.
4. Rédigez une **Description** en Markdown : incluez les étapes de reproduction, les critères d'acceptation, des captures d'écran ou des blocs de code selon les besoins.
5. Sélectionnez **Submit New Issue** pour le publier.

<Aside>Un dépôt peut définir des modèles de tickets réutilisables sous **Paramètres → Issue Templates**. Lorsque des modèles sont configurés, l'ouverture d'un nouveau ticket affiche un sélecteur, de sorte que les contributeurs partent d'un formulaire cohérent plutôt que d'une page blanche.</Aside>

## Organiser avec des libellés et des jalons

Les **Libellés** catégorisent et hiérarchisent les tickets. Appliquez un ou plusieurs libellés depuis la barre latérale de droite lorsque vous consultez un ticket, ou directement depuis la liste des tickets grâce au filtre **Libellé**. Les conventions courantes consistent à combiner des libellés de type (`bug`, `enhancement`) avec des libellés de priorité (`high`, `low`), mais vous pouvez créer tous les libellés adaptés à votre workflow sous **Issues → Libellés**.

Les **jalons** regroupent des tickets autour d'un objectif commun : une date de release, un sprint ou un objectif fonctionnel. Créez des jalons sous **Issues → Milestones**, puis affectez un ticket à un jalon depuis sa barre latérale. La vue du jalon montre la progression à mesure que les tickets sont fermés.

## Assigner et discuter

- **Personnes assignées** : utilisez le champ **Assignees** de la barre latérale pour indiquer qui est responsable. Tout membre de l'espace de travail ayant accès au dépôt peut être assigné.
- **Commentaires** : ajoutez du contexte, des décisions ou des mises à jour de statut dans le fil de commentaires sous la description du ticket.
- **@mentions** : saisissez `@username` n'importe où dans un commentaire ou une description pour notifier directement cette personne.
- **Réactions** : utilisez les réactions emoji sur les commentaires pour accuser réception d'un point sans ajouter de réponse.

## Lier les tickets au code

Référencer les tickets depuis les commits et les pull requests rend votre historique traçable.

- **Référence par numéro** : saisissez `#12` dans un message de commit, une description de pull request ou un commentaire pour créer un lien cliquable vers le ticket 12 du même dépôt.
- **Fermeture automatique à la fusion** : incluez un mot-clé de fermeture dans la description d'une pull request (par exemple `Closes #12`, `Fixes #34` ou `Resolves #56`). Lorsque la pull request est fusionnée dans la branche par défaut, les tickets référencés se ferment automatiquement.
- **Références croisées vers d'autres tickets** : utilisez librement `#number` dans n'importe quel commentaire de ticket pour lier des tickets associés ; chaque ticket référencé affiche un lien retour, de sorte que la relation est visible des deux côtés.

## Rechercher des tickets

La liste des tickets prend en charge plusieurs filtres que vous pouvez combiner :

| Filtre | Fonction |
|---|---|
| **État** | Afficher les tickets ouverts ou fermés |
| **Libellé** | Se limiter à un ou plusieurs libellés |
| **Jalon** | Afficher les tickets affectés à un jalon |
| **Personne assignée** | Afficher les tickets assignés à une personne précise |
| **Auteur** | Afficher les tickets ouverts par une personne précise |

Sélectionnez la colonne appropriée dans la barre de filtres au-dessus de la liste des tickets pour appliquer chaque filtre. Pour rechercher des mots-clés dans les titres et les corps des tickets, consultez [Recherche de code](/fr/guides/git/searching-code/).
