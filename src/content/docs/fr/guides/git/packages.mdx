PlaidCloud Git inclut un registre de packages intégré pour les artefacts distribuables, ainsi que Git Large File Storage (LFS) pour les gros fichiers binaires au sein de vos dépôts.

## À propos du registre de packages

Le registre de packages est propre à chaque propriétaire et prend en charge un large éventail de formats d'écosystème : npm, PyPI, Maven, NuGet, RubyGems, images de conteneur, et plus encore. Les packages sont privés pour votre espace de travail et accessibles uniquement aux membres authentifiés.

Chaque type de package dispose de son propre point de terminaison sous :

```
https://git.example.plaidcloud.com/api/packages/you/<type>
```

où `<type>` est l'identifiant de l'écosystème (par exemple `npm`, `pypi` ou `maven`).

## S'authentifier auprès du registre

Les opérations du gestionnaire de packages utilisent votre nom d'utilisateur PlaidCloud Git et un jeton d'accès personnel en guise de mot de passe. Consultez [Dépôts](/fr/guides/git/repositories/) pour savoir comment créer un jeton.

## Publier un package

Les étapes varient selon l'écosystème, mais le principe est le même : faites pointer votre gestionnaire de packages vers l'URL du registre et exécutez sa commande de publication standard.

Pour npm, ajoutez un fichier `.npmrc` à votre projet afin de limiter la portée des packages au registre :

```ini
@you:registry=https://git.example.plaidcloud.com/api/packages/you/npm/
//git.example.plaidcloud.com/api/packages/you/npm/:_authToken=YOUR_TOKEN
```

Publiez ensuite comme d'habitude :

```bash
npm publish
```

Pour PyPI, Maven, NuGet et les autres écosystèmes, configurez le paramètre de dépôt ou de source de l'outil avec l'URL de registre correspondante et utilisez la commande de publication standard de cet outil (par exemple `twine upload`, `mvn deploy` ou `dotnet nuget push`).

## Installer un package

Faites pointer votre gestionnaire de packages vers la même URL de registre et installez comme d'habitude. Avec le fichier `.npmrc` ci-dessus en place :

```bash
npm install @you/my-package
```

Pour les autres écosystèmes, ajoutez le registre comme source supplémentaire dans la configuration de votre outil et utilisez sa commande d'installation standard.

## Gros fichiers avec Git LFS

Git LFS préserve la rapidité de votre dépôt en remplaçant dans l'historique les fichiers volumineux ou binaires par des pointeurs légers et en stockant séparément les données des fichiers. LFS est activé pour chaque dépôt PlaidCloud Git.

1. Installez une seule fois le client LFS sur votre machine :

   ```bash
   git lfs install
   ```

2. Indiquez à LFS quels motifs de fichiers suivre, depuis l'intérieur de votre dépôt :

   ```bash
   git lfs track "*.parquet"
   ```

   Cela crée ou met à jour `.gitattributes`. Validez ce fichier :

   ```bash
   git add .gitattributes
   git commit -m "Track Parquet files with LFS"
   ```

3. Ajoutez et poussez normalement : les fichiers correspondants sont téléversés automatiquement vers LFS :

   ```bash
   git add data/large-dataset.parquet
   git commit -m "Add dataset"
   git push origin main
   ```

<Aside type="tip">Git LFS sert aux gros fichiers qui résident dans l'historique d'un dépôt et sont récupérés avec `git clone` ou `git pull`. Le registre de packages sert aux artefacts versionnés et distribuables que les consommateurs installent avec un gestionnaire de packages. Si vos collègues vont exécuter `npm install` ou `pip install` dessus, utilisez le registre ; s'ils en ont besoin dans le cadre d'un checkout, utilisez LFS.</Aside>
