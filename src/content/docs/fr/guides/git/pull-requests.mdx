## Créer une branche

Travaillez sur une nouvelle branche afin que vos modifications restent séparées de la branche par défaut jusqu'à ce qu'elles soient prêtes.

**Dans l'interface :**

1. Ouvrez votre dépôt et sélectionnez le sélecteur de branche en haut à gauche (il affiche le nom de la branche actuelle).
2. Saisissez un nom de nouvelle branche dans la zone de recherche et sélectionnez **Create Branch**.

**En local :**

1. Créez la branche et basculez dessus : `git checkout -b feature-x`
2. Effectuez vos modifications, puis indexez-les et validez-les : `git add .` puis `git commit -m "Describe what changed"`
3. Poussez la branche vers PlaidCloud Git : `git push -u origin feature-x`

## Ouvrir une pull request

1. Ouvrez votre dépôt et sélectionnez l'onglet **Pull Requests**, puis **New Pull Request**.
2. Définissez la branche **Comparer** sur votre branche de fonctionnalité et la branche **De base** sur la cible (généralement `main` ou `master`).
3. Rédigez un titre clair et une description qui explique ce qui a changé et pourquoi.
4. Pour lier des tickets associés, ajoutez un mot-clé de fermeture dans la description, par exemple `Closes #12`, afin que le ticket se ferme automatiquement lors de la fusion de la pull request.
5. Assignez des relecteurs si nécessaire, puis sélectionnez **Create Pull Request**.

## Relire les modifications

Les relecteurs examinent la pull request sans rien fusionner :

1. Ouvrez la pull request et sélectionnez **Files Changed** pour lire le diff.
2. Sélectionnez une ligne du diff pour laisser un commentaire en ligne sur cette modification précise.
3. Une fois terminé, soumettez un avis global : **Approuver** pour valider, ou **Request Changes** pour demander d'abord des révisions.
4. L'auteur pousse de nouveaux commits sur la même branche pour répondre aux retours : la pull request se met à jour automatiquement, sans qu'il soit nécessaire d'en ouvrir une nouvelle.
5. Les relecteurs marquent chaque fil de commentaires comme résolu une fois la remarque traitée.

<Aside>Un administrateur du dépôt peut activer la protection de branche sur la branche par défaut pour exiger un nombre minimal d'approbations avant qu'une pull request puisse être fusionnée.</Aside>

## Fusionner

Une fois la pull request approuvée :

1. Choisissez une méthode de fusion dans la liste déroulante à côté du bouton **Merge** :
   - **Create a merge commit** : conserve l'historique complet de la branche avec un commit de fusion.
   - **Squash and merge** : combine tous les commits de la branche en un seul commit sur la branche cible.
   - **Rebase and merge** : rejoue les commits de la branche sur la branche cible sans commit de fusion.
2. Sélectionnez **Merge** pour terminer.
3. Sélectionnez éventuellement **Delete Branch** pour nettoyer la branche de fonctionnalité lorsqu'elle n'est plus nécessaire.
