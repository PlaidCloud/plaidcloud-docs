Utilisez cette liste de contrôle avant d'importer des workflows Alteryx dans PlaidCloud. Un package complet aide PlaidCloud à créer des workflows avancés, des workflows de macro, des dépendances stockées dans Document et des entrées d'exécution contrôlées, avec un minimum de suivi.

<Aside type="note">
  Pour les grands portefeuilles, exécutez cette liste de contrôle une fois pour l'ensemble du portefeuille, puis de nouveau pour chaque famille de workflows prioritaire.
</Aside>

## Rassembler les fichiers de workflow

Rassemblez tous les fichiers de workflow qui font partie de la migration :

1. Workflows standard : `.yxmd`.
2. Applications analytiques : `.yxwz`.
3. Macros : `.yxmc`.
4. Macros imbriquées ou partagées référencées par d'autres workflows.
5. Versions de workflows toujours utilisées en production.

Conservez ensemble les workflows et les macros associés lorsqu'ils s'appellent mutuellement. PlaidCloud s'appuie sur ces relations pour générer les workflows de macro et connecter les ports d'entrée et de sortie des macros.

## Rassembler les dépendances de données

Regroupez les fichiers que les workflows lisent, écrivent ou inspectent :

- Fichiers CSV, TSV, à largeur fixe, JSON, XML, Excel, Access, YXDB et extractions de base de données.
- Dossiers utilisés par les outils Directory ou Dynamic Input.
- Fichiers de sortie attendus pour la validation.
- Ressources de rapport telles que images, PDF, modèles et couches cartographiques.
- Tables de correspondance et tables de règles utilisées par les jointures, les formules, les remplacements et les rapprochements.

Si un workflow référence un chemin local du poste de travail, incluez ce fichier ou ce dossier dans le package d'importation et choisissez le chemin Document où PlaidCloud doit le stocker.

## Rassembler les fichiers annexes spatiaux

Les formats de fichiers spatiaux nécessitent souvent que plusieurs fichiers restent ensemble. Incluez tous les fichiers annexes dans le même dossier :

- Groupes Shapefile tels que `.shp`, `.shx`, `.dbf` et `.prj`.
- Groupes MapInfo tels que `.tab`, `.map`, `.id` et `.dat`.
- Fichiers KML, GeoJSON et autres fichiers spatiaux autonomes.
- Fichiers de projection ou de système de coordonnées de référence utilisés par le workflow.

Des fichiers annexes manquants sont une source fréquente d'écarts de validation spatiale.

## Capturer les entrées d'exécution

Pour les applications analytiques, notez les valeurs que les utilisateurs fournissent habituellement :

1. Entrées de type texte, numérique, date, fichier et dossier.
2. Sélections de listes déroulantes, de boutons radio, de cases à cocher, de listes et d'arborescences.
3. Valeurs par défaut utilisées pour les exécutions planifiées ou répétables.
4. Valeurs qui déclenchent des conditions, des avertissements ou des erreurs.

PlaidCloud convertit ces entrées en variables de workflow contrôlées.

## Choisir l'emplacement cible

Avant l'importation, décidez des éléments suivants :

1. Projet PlaidCloud cible.
2. Compte de documents cible.
3. Dossier Document cible pour les fichiers importés.
4. Convention de nommage des workflows et des macros convertis.
5. Si la première importation est une importation de préproduction ou de production.

Pour les migrations de portefeuille, utilisez un dossier de migration dédié dans Document afin que les dépendances restent faciles à auditer.

## Choisir les preuves de validation

Pour chaque workflow, choisissez le niveau de validation :

- La validation structurelle confirme que le workflow se convertit en un DAG PlaidCloud exécutable.
- La validation de la parité des sorties compare le schéma, le nombre de lignes et les valeurs des lignes à des sorties Alteryx de référence.
- La validation des artefacts passe en revue les rapports, PDF, images, graphiques, cartes ou sorties de modèles.

Conservez les sorties attendues avec le package de migration chaque fois que la parité des sorties est requise.

## Liste de contrôle de préparation à l'importation

Avant d'importer, vérifiez les points suivants :

- Les fichiers de workflow, d'application et de macro sont présents.
- Les macros référencées sont présentes.
- Les fichiers et dossiers d'entrée sont présents.
- Les fichiers annexes spatiaux sont regroupés.
- Les sorties attendues sont disponibles lorsque la validation de la parité fait partie du plan de migration.
- Les valeurs des entrées d'exécution sont connues pour les applications analytiques.
- Le projet cible et le chemin Document sont sélectionnés.
- Les identifiants ou connexions externes nécessaires au workflow sont disponibles dans PlaidCloud.
