PlaidCloud importe les fichiers de workflows Alteryx depuis Document et utilise des chemins Document pour les dépendances et les artefacts. Vous pouvez téléverser des fichiers dans Document, demander à un agent connecté via MCP d'organiser les fichiers à votre place, ou connecter Document directement à un stockage partagé comme OneDrive, Google Drive, SharePoint, S3, Azure Blob ou SFTP.

<Aside type="note">
  Utilisez le sélecteur de chemin Document pendant l'importation pour choisir précisément où PlaidCloud doit lire les fichiers source et stocker les artefacts générés.
</Aside>

## Téléverser ou connecter un stockage partagé

Choisissez l'emplacement source qui convient le mieux à votre migration :

- Téléverser le package dans un compte de documents.
- Connecter un emplacement de stockage partagé existant comme compte de documents.
- Demander à un agent connecté via MCP de copier, déplacer, renommer et organiser les fichiers déjà disponibles dans Document.

Les connexions à un stockage partagé peuvent réduire la préparation de la migration, car l'équipe peut garder les fichiers là où elle collabore déjà :

- [Google Drive](/fr/guides/documents/adding-accounts/add-google-drive-account/)
- [OneDrive ou SharePoint](/fr/guides/documents/adding-accounts/add-onedrive-account/)
- [AWS S3](/fr/guides/documents/adding-accounts/add-aws-s3-account/)
- [Azure Blob Storage](/fr/guides/documents/adding-accounts/add-azure-blob-storage-account/)
- [SFTP](/fr/guides/documents/adding-accounts/add-sftp-account/)

## Arborescence recommandée

Pour chaque lot de migration, utilisez une arborescence de ce type avant l'importation :

```text
workflow-package/
  workflows/
  macros/
  inputs/
  expected-outputs/
  reports/
  spatial/
```

Cette structure est facultative, mais elle facilite la relecture et la validation.

## Workflows et macros

Placez les fichiers de workflows et de macros dans des dossiers prévisibles :

- Placez les fichiers `.yxmd` et `.yxwz` dans `workflows/`.
- Placez les fichiers `.yxmc` dans `macros/`.
- Gardez les macros imbriquées avec le reste de la bibliothèque de macros.
- Évitez les noms de macros en double dans un même package, sauf s'ils sont volontairement versionnés.

PlaidCloud utilise les fichiers source des macros pour créer des workflows de macros PlaidCloud et relier les appels de macros depuis les workflows convertis.

## Fichiers d'entrée

Placez les données d'entrée sous `inputs/` :

- Fichiers CSV, TSV, à largeur fixe, JSON, XML, Excel, Access, YXDB, SAS, SPSS, Stata, Avro, Parquet et HDF.
- Fichiers de référence utilisés par les formules, le remplacement dynamique, la correspondance approximative ou les jointures.
- Dossiers référencés par les outils Directory et Dynamic Input.
- Fichiers ASCII à plat Alteryx : incluez le fichier de disposition `.flat` à côté des données qu'il décrit. Les largeurs de colonnes ne figurent que dans ce fichier et la conversion le lit pour construire l'étape ; un fichier de disposition manquant n'empêche donc pas la conversion, mais le rapport de conversion nomme le fichier à téléverser. Fournissez-le et réimportez le workflow plutôt que de simplement le réexécuter.

Lorsque PlaidCloud importe le package, les étapes converties pointent vers les emplacements Document sélectionnés.

## Fichiers spatiaux

Placez les fichiers spatiaux sous `spatial/` et gardez ensemble leurs fichiers annexes :

- Shapefiles : incluez `.shp`, `.shx`, `.dbf` et `.prj`.
- Fichiers MapInfo : incluez `.tab`, `.map`, `.id` et `.dat`.
- Incluez les fichiers de projection et les couches de référence lorsqu'ils existent.
- Gardez les fichiers KML, GeoJSON et les autres entrées spatiales dans le même package de dépendances.

Ne répartissez pas les fichiers annexes spatiaux entre plusieurs dossiers. PlaidCloud a besoin du groupe complet pour matérialiser correctement la géométrie.

## Ressources de rapports et d'artefacts

Placez les ressources de rapports sous `reports/` :

- Images utilisées par les outils de composition de rapports.
- Entrées PDF.
- Fragments ou modèles HTML.
- Couches cartographiques utilisées par les cartes des rapports.
- Exemples de rapports générés lorsque la validation des artefacts est requise.

Les étapes de rapport converties créent des artefacts PlaidCloud que vous pouvez consulter depuis Document et l'historique d'exécution des workflows.

## Modèles Excel

Si un workflow écrit une sortie mise en forme dans un modèle Excel stylisé (les étapes
[Export to Excel](/fr/reference/workflow-steps/export/export-to-excel/) et
[Export to Excel Sheets](/fr/reference/workflow-steps/export/export-to-excel-sheets/),
qui préservent la mise en forme), placez ces classeurs modèles dans le compte de documents
avec les entrées. Mettez-les dans un dossier `04_Templates` à côté du dossier `03_Inputs` où
vous avez préparé les données source, afin que l'étape convertie puisse lire le modèle qu'elle remplit.

<Aside type="caution">
  Un export converti qui préserve la mise en forme lit son modèle dans le compte de documents
  **à l'exécution**. Si le modèle est absent au moment de la conversion, l'étape se rabat
  sans risque sur un export simple ; en revanche, si le modèle préparé est absent à l'exécution,
  un export converti qui préserve la mise en forme **échoue de façon explicite** plutôt que
  d'écrire silencieusement un fichier non mis en forme. Préparez `04_Templates` avant d'exécuter
  le workflow converti.
</Aside>

## Sorties attendues

Placez les sorties attendues sous `expected-outputs/` :

- Tables de sortie Alteryx de référence.
- Rapports, PDF, cartes, images ou graphiques attendus.
- Remarques sur l'ordre des lignes, la précision numérique et le traitement des dates acceptés.

Les sorties attendues sont facultatives pour la validation structurelle et constituent la meilleure preuve pour la validation de la parité des sorties.

## Connexions externes

Pour les workflows qui s'appuient sur des bases de données, des API et des sources cloud, consignez :

1. Le nom du système source.
2. Le type de connexion.
3. Les noms de base de données, de schéma, de table, de point de terminaison ou de bucket.
4. Le responsable des identifiants ou le nom du secret.
5. La date d'instantané lorsque la parité des sorties dépend d'une source à un instant donné.

Utilisez les connexions ou les identifiants PlaidCloud pour des exécutions de production répétables.
