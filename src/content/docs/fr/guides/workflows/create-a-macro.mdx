Une **macro** est un workflow avancé (DAG) réutilisable, doté d'un contrat d'entrée/sortie déclaré. Vous appelez une macro depuis un autre workflow avec une étape [Macro Run](/fr/reference/workflow-steps/workflow-control/run-macro/) ou [Macro Concurrent](/fr/reference/workflow-steps/workflow-control/macro-concurrent/). Chaque appel s'exécute dans son propre schéma de travail isolé : la même macro peut donc être appelée simultanément par plusieurs workflows parents, ou pour plusieurs lignes d'inducteur, sans que les exécutions n'entrent en collision.

Utilisez une macro lorsque vous avez une transformation de données répétable et paramétrée (par exemple « traiter un mois de données de ventes pour une région ») que vous souhaitez appeler depuis un workflow pilote une fois par mois, par région, ou les deux. L'appelant lie des tables et des variables aux ports d'entrée déclarés de la macro. Une fois l'exécution terminée, les tables de sortie déclarées sont recopiées vers des destinations côté appelant.

<Aside type="note">
Les macros sont une fonctionnalité réservée aux workflows avancés. Convertissez d'abord votre workflow en workflow avancé. Les étapes à l'intérieur de la macro doivent être compatibles avec les macros : transformations de tables, importations, exportations, étapes de variables limitées à l'exécution, appels imbriqués de Macro Run et quelques étapes de contrôle de flux. Les importations de dimensions et les étapes qui mettent à jour des dimensions sont refusées, car les dimensions constituent un état global au projet.
</Aside>

## Étapes

1. Ouvrez le projet qui contient le workflow que vous voulez transformer en macro.
2. Passez à l'onglet **Workflows** et sélectionnez la ligne du workflow.
3. Dans le panneau **Détails du workflow** à droite, vérifiez que le **Type de workflow** est **Avancé**. S'il est standard, utilisez d'abord l'action **Convertir en avancé**.
4. Dans la section **Macro** du panneau Détails du workflow, cliquez sur **Convertir en macro…** et confirmez dans la boîte de dialogue. Le workflow passe en mode macro et un éditeur de ports apparaît.
5. Cliquez sur **Ajouter un port** pour déclarer chaque entrée ou sortie que la macro accepte ou produit. Pour chaque port :
   - **Nom** : un identifiant court que l'appelant utilise pour se lier à ce port (par exemple `month`, `region_sales`).
   - **Direction** : **Entrée** (l'appelant fournit cette valeur ou cette table) ou **Sortie** (la macro produit cet élément et l'appelant le récupère).
   - **Genre** : **Table** pour une table de données, **Scalaire** pour une valeur unique (chaîne / entier / décimal / booléen / date) ou **Dimension** pour une référence à une dimension hiérarchique.
   - **Obligatoire** : décochez cette option si la macro peut s'exécuter sans que ce port soit lié.
   - **Mémo** : une courte note décrivant ce que représente ce port, affichée aux auteurs dans le formulaire de liaison côté appelant.
6. Cliquez sur **Enregistrer les ports**.

Le workflow est désormais une macro. Les auteurs qui ajoutent une étape [Macro Run](/fr/reference/workflow-steps/workflow-control/run-macro/) dans un autre workflow voient vos ports déclarés et s'y lient par leur nom.

## Appeler une macro

Dans le workflow appelant :

1. Ajoutez une étape **Macro : exécuter**.
2. Dans **Macro à exécuter**, sélectionnez le projet et le workflow de la macro.
3. **Liaisons d'entrée** : pour chaque port d'entrée déclaré par la macro, ajoutez une liaison :
   - Les ports **Table** prennent une table source côté appelant. Vous pouvez sélectionner un sous-ensemble de colonnes et ajouter un filtre (une clause `WHERE` qui référence les variables d'entrée scalaires de la macro) afin que seule la portion nécessaire soit matérialisée dans le schéma d'exécution de la macro.
   - Les ports **Scalaire / Dimension** prennent une valeur (souvent une variable de workflow de l'appelant). Elle est définie AVANT la copie des tables en entrée, de sorte que le filtre de la table d'entrée puisse y faire référence.
4. **Liaisons de sortie** : pour chaque port de sortie produit par la macro, désignez une table de destination côté appelant (créée à la volée si elle n'existe pas encore).
5. Enregistrez l'étape.

Lorsque le workflow parent s'exécute et atteint l'étape Macro Run, l'exécuteur procède ainsi :

1. Il génère un nouveau `run_id` pour cet appel de la macro.
2. Il crée un schéma de travail propre à l'exécution (`macrorun_<run_id>`) dans le catalogue du projet.
3. Il copie les tables d'entrée liées dans le schéma de travail (projection des colonnes et filtre appliqués lors de la copie, de sorte que le filtre soit poussé vers la source).
4. Il définit les variables d'entrée scalaires et de dimension liées dans la surcouche de variables de la macro, limitée à l'exécution.
5. Il exécute les étapes de la macro dans le même processus. Chaque étape SQL de la macro lit et écrit dans le schéma de travail plutôt que dans le schéma du projet.
6. Il recopie les tables de sortie déclarées vers les destinations de l'appelant.
7. Il supprime le schéma de travail (toujours, même si une étape de la macro a échoué).

## Exécuter une macro par ligne d'inducteur

Utilisez **Macro : exécution parallèle** lorsqu'une table de l'appelant doit piloter de nombreux appels indépendants de la macro.

1. Ajoutez une étape **Macro : exécution parallèle**.
2. Dans **Inducteur**, sélectionnez la table d'inducteurs côté appelant et définissez **Exécutions simultanées** sur le nombre maximal d'appels enfants de la macro à exécuter en même temps.
3. Dans **Sélection des données de la table**, mappez les colonnes de la table d'inducteurs dont chaque appel enfant a besoin.
4. Dans **Filtre d'inducteur**, vous pouvez restreindre les lignes d'inducteur à traiter.
5. Dans **Macro**, sélectionnez le workflow de la macro.
6. Dans **Liaisons d'entrée**, liez les valeurs des colonnes d'inducteur aux variables scalaires ou de dimension de la macro, et liez les tables côté appelant aux ports de table de la macro.
7. Dans **Liaisons de sortie**, mappez les ports de sortie de la macro vers les tables de destination côté appelant.

Chaque ligne d'inducteur sélectionnée reçoit son propre `run_id` et son propre schéma de travail. L'arrêt de l'étape parente arrête tous les appels enfants actifs et supprime leurs schémas d'exécution.

## Rétrograder une macro

Vous pouvez retirer l'indicateur de macro à tout moment en cliquant sur **Rétrograder en avancé…** dans le panneau Détails du workflow. Le workflow redevient un simple workflow avancé, et toutes les étapes Macro Run côté appelant qui le référencent échouent à l'exécution avec une erreur « not a macro ». Les ports déclarés restent enregistrés, ce qui permet de les retrouver si vous reconvertissez le workflow plus tard.

## Limitations (v1)

- Les macros peuvent contenir des transformations de tables, des importations et des exportations, car les lectures et écritures de tables sont isolées dans le schéma de travail de l'appel. Les importations de dimensions et les étapes qui mettent à jour des dimensions ne sont pas autorisées, car les dimensions constituent un état global au projet. Les autres étapes à effets de bord hors tables, comme les opérations sur les documents et les appels d'agent, ne sont pas compatibles avec les macros en v1.
- Les macros doivent se trouver dans le même projet que l'appelant. Les macros inter-projets ne sont pas encore prises en charge.
- Une étape Macro Run ne peut pas être appelée depuis une étape [Run Workflow](/fr/reference/workflow-steps/workflow-control/run-workflow/), [Workflow Loop](/fr/reference/workflow-steps/workflow-control/workflow-loop/) ou Run Workflow conditionnelle : ces étapes s'exécutent sans isolation et briseraient le contrat de schéma propre à chaque exécution. Utilisez plutôt une étape Macro Run dans l'appelant.
