## Description

Lorsque vous modifiez une colonne à la source — en la renommant, en changeant son type ou en la supprimant — chaque étape en aval qui est mappée à cette colonne doit être mise à jour en conséquence. **Propagation de colonnes** s'en charge pour vous en une seule confirmation.

La propagation est disponible depuis toute étape disposant d'un **ColumnMapper** (Project Table, Calculate, Append, Merge, etc.). Deux boutons de la barre d'outils du mapper la pilotent :

* `Propagate All` — propage toutes les colonnes du mapper
* `Propagate Selected` — propage uniquement les colonnes que vous avez sélectionnées dans la grille du mapper


## Propager une modification de colonne

1. Ouvrez l'étape de workflow contenant la colonne que vous souhaitez modifier
2. Dans le **ColumnMapper**, effectuez la modification (renommage, changement de type, etc.)
3. Cliquez sur `Propagate All` (ou sélectionnez des lignes et cliquez sur `Propagate Selected`) dans la barre d'outils du mapper
4. La boîte de dialogue **Propager en aval** s'ouvre avec une arborescence de toutes les étapes qui dépendent de l'étape source
5. Cochez les étapes auxquelles vous souhaitez appliquer la modification — les étapes enfants sont cochées automatiquement en cascade
6. Pour les étapes d'agrégation, choisissez la fonction d'agrégation des nouvelles colonnes dans le panneau **Aggregation** inférieur
7. Cliquez sur `Confirm`

Le panneau **Aggregation** liste les fonctions d'agrégation standard. **Avancé hors regroupement**, utilisé avec les fonctions de fenêtrage, se définit dans le mapper de l'étape elle-même et n'est pas proposé ici. Si l'agrégation que vous choisissez ne convient pas à une colonne, la boîte de dialogue indique de quelle colonne il s'agit et pourquoi, afin que vous puissiez en choisir une autre.

La boîte de dialogue applique des valeurs par défaut sûres : lorsqu'une ligne en aval n'a aucun mappage explicite pour la colonne, le nom source est réutilisé comme nom cible, afin qu'aucune information ne soit perdue en chemin.


## Ce qui est propagé

* Renommage de colonne — changement du nom source → cible
* Changement de type — dtype mis à jour partout où la colonne apparaît
* Nouvelles colonnes ajoutées dans cette étape — transmises vers l'avant dans les mappers en aval
* Opérations de suppression (strip) appliquées à la source

Les étapes qui ne référencent pas la colonne sont tout de même affichées dans l'arborescence, mais sont décochées par défaut.


## Erreurs et nouvelles tentatives

Si une étape en aval a été modifiée par quelqu'un d'autre depuis l'ouverture de la boîte de dialogue, la propagation échoue avec une erreur de version obsolète. La boîte de dialogue recharge automatiquement le graphe de dépendances et vous permet de réessayer sans perdre vos sélections. Si le rechargement lui-même échoue, vos sélections sont tout de même conservées, ce qui vous permet de résoudre le problème sous-jacent et de réessayer.

<Aside>La propagation de colonnes ne modifie que les étapes du même workflow. Si un workflow en aval consomme la table, mettez à jour ses mappers séparément ou exécutez un [audit des dépendances](../view-a-dependency-audit/) pour trouver les étapes concernées.</Aside>
