Alteryx écrit les fichiers `.yxdb` dans deux formats. Le format classique (écrit par le moteur d'origine) est bien connu, et PlaidCloud l'importe directement. Le moteur AMP écrit une variante plus récente — l'en-tête du fichier indique `Alteryx e2 Database file` — dont la spécification est propriétaire et non publiée ; aucun outil extérieur à Alteryx ne peut donc la lire, PlaidCloud compris.

Pendant une migration, vous disposez encore d'Alteryx Designer sous licence, et Designer lit les deux formats. Utilisez-le une fois, avant de le désactiver, pour réécrire les fichiers au format AMP sous une forme portable.

<Aside type="note">
  Les fichiers `.yxdb` classiques s'importent directement dans PlaidCloud — aucune conversion n'est nécessaire. Si l'importation d'un fichier `.yxdb` échoue avec une erreur de fichier illisible, un fichier au format AMP en est la cause la plus probable.
</Aside>

## Identifier les fichiers au format AMP

- Le workflow qui a produit le fichier s'est exécuté avec le moteur AMP activé.
- PlaidCloud signale le fichier comme illisible lors de l'importation, alors que les autres fichiers `.yxdb` du même package s'importent correctement.
- Les premiers octets du fichier indiquent `Alteryx e2 Database file` au lieu de `Alteryx Database File` (visible dans n'importe quel éditeur de texte ou hexadécimal).

## Option A : réenregistrer les fichiers individuellement dans Designer

Pour quelques fichiers, réenregistrez chacun depuis Designer :

1. Dans Alteryx Designer, ajoutez un outil **Input Data** et sélectionnez le fichier `.yxdb`.
2. Connectez un outil **Output Data** et choisissez un nouveau chemin `.yxdb`.
3. Dans les options de l'outil Output Data, activez l'option d'enregistrement du fichier **compatible avec Designer 18.1 et versions antérieures**. Cela force le format classique.
4. Exécutez le workflow, puis importez le nouveau fichier dans PlaidCloud.

Écrire en CSV plutôt qu'en `.yxdb` à l'étape 2 fonctionne aussi et dispense de l'option de compatibilité.

## Option B : convertir un dossier par lots avec le workflow téléchargeable

Pour de nombreux fichiers, téléchargez le workflow préconstruit et exécutez-le dans Designer :

<a href="/downloads/convert_yxdb_folder.yxmd" download>Télécharger convert_yxdb_folder.yxmd</a>

Il enchaîne un outil **Directory**, un outil **Dynamic Input** et un outil **Output Data** de sorte que chaque fichier `.yxdb` d'un dossier — classique ou AMP — soit réécrit sous la forme d'un fichier CSV nommé `converted_<original name>.csv`. Le CSV est portable et PlaidCloud l'importe sans perte.

1. Ouvrez `convert_yxdb_folder.yxmd` dans Alteryx Designer.
2. Dans l'outil **Directory**, définissez le dossier qui contient vos fichiers `.yxdb`.
3. Dans l'outil **Dynamic Input**, faites pointer le modèle de source de données d'entrée vers n'importe quel fichier `.yxdb` de ce dossier.
4. Dans l'outil **Output Data**, définissez le dossier de sortie.
5. Exécutez le workflow, puis chargez les CSV dans Document et importez-les.

<Aside type="caution">
  L'outil Dynamic Input exige que tous les fichiers d'un lot partagent la même disposition de champs que le fichier modèle. Les fichiers dont la disposition diffère sont ignorés avec un avertissement — le volet de résultats de Designer nomme chaque fichier ignoré. Regroupez les fichiers différents dans leur propre dossier avec leur propre modèle et relancez l'exécution, ou réenregistrez les retardataires individuellement avec l'option A.
</Aside>

Les fichiers convertis en CSV perdent le typage propre à `.yxdb` (tout arrive sous forme de texte et est retypé à l'importation) ; vérifiez donc par sondage les types de colonnes des tables importées — en particulier les dates et les décimaux de haute précision.
