Le serveur MCP de PlaidCloud permet à un agent IA de coordonner une migration portant sur de nombreux workflows Alteryx. L'agent peut aider à préparer et organiser les fichiers dans Document, inventorier les packages de workflows, appeler le convertisseur Alteryx, organiser les workflows générés, exécuter les workflows de validation et résumer l'avancement pour l'équipe de migration.

<Aside type="note">
  MCP est idéal pour une coordination à l'échelle d'un portefeuille. L'importeur PlaidCloud effectue toujours la conversion ; l'agent aide à planifier, séquencer, exécuter et résumer le travail.
</Aside>

## Quand utiliser MCP

Utilisez l'orchestration MCP lorsque vous migrez de nombreux workflows ou que vous souhaitez qu'un agent IA vous aide dans des tâches de migration répétables :

- Inventorier les fichiers Alteryx préparés dans Document.
- Téléverser, copier, déplacer, renommer et organiser les fichiers de migration avec les outils Document.
- Travailler à partir d'un compte de stockage partagé connecté, comme OneDrive, Google Drive, SharePoint, S3, Azure Blob ou SFTP.
- Regrouper les workflows, les applications et les macros en lots de migration.
- Convertir chaque fichier `.yxmd`, `.yxwz` ou `.yxmc` dans PlaidCloud.
- Suivre les résultats de conversion sur l'ensemble du portefeuille.
- Exécuter les workflows convertis ou les workflows de validation.
- Produire une synthèse de migration pour relecture.

Pour un seul workflow, le formulaire d'importation est souvent le chemin le plus rapide. Pour un portefeuille, MCP offre à l'agent un moyen structuré de coordonner de façon répétée les mêmes fonctionnalités de PlaidCloud.

## Ce que l'agent peut appeler

Le catalogue d'outils MCP comprend un outil de conversion Alteryx nommé `alteryx_convert`. Il crée des workflows PlaidCloud à partir de fichiers Alteryx stockés dans Document.

L'appel de conversion comprend :

- Le compte de documents source et le chemin du fichier Alteryx.
- Le projet PlaidCloud de destination.
- Le compte de documents de destination et le chemin des artefacts de conversion.
- Des préfixes facultatifs pour les workflows, les étapes et les tables. Le préfixe des tables prend par défaut le nom du workflow lui-même, ce qui évite que deux conversions d'un même projet n'empiètent sur les tables l'une de l'autre ; transmettez un préfixe vide pour obtenir les noms nus.
- Le type de workflow, avec les workflows avancés par défaut.

L'agent peut combiner cela avec les outils MCP habituels de projet, de workflow, de Document, d'exécution de workflow et de table pour gérer l'ensemble de la migration.

## Préparer les fichiers avec l'agent

Un agent connecté via MCP peut vous aider dans le travail de préparation des fichiers qui entoure la conversion :

- Rechercher les fichiers `.yxmd`, `.yxwz` et `.yxmc` dans Document.
- Repérer les fichiers d'entrée probables, les fichiers de macros, les ressources de rapports, les fichiers annexes spatiaux et les sorties attendues.
- Créer une arborescence de dossiers de migration propre.
- Copier, déplacer ou renommer les fichiers dans cette arborescence.
- Garder ensemble les fichiers de workflows, de macros, de données, spatiaux, de rapports et de validation qui vont de pair.
- Résumer le package avant la conversion.

C'est utile lorsqu'un package de migration contient de nombreux dossiers ou que les équipes veulent que l'agent produise un inventaire répétable avant le début de la conversion.

## Utiliser un stockage partagé sans téléversement

Vous n'avez pas à téléverser les fichiers dans un nouveau dossier géré par PlaidCloud avant la migration. PlaidCloud Document peut se connecter directement au stockage partagé qui contient déjà le package de migration Alteryx.

Parmi les options courantes :

- [Google Drive](/fr/guides/documents/adding-accounts/add-google-drive-account/)
- [OneDrive ou SharePoint](/fr/guides/documents/adding-accounts/add-onedrive-account/)
- [AWS S3](/fr/guides/documents/adding-accounts/add-aws-s3-account/)
- [Azure Blob Storage](/fr/guides/documents/adding-accounts/add-azure-blob-storage-account/)
- [SFTP](/fr/guides/documents/adding-accounts/add-sftp-account/)

Une fois le compte de documents connecté, l'agent peut travailler à partir de ce compte de documents et de ce chemin. La migration reste ainsi proche du stockage partagé existant du client, et vous pouvez vous passer d'une étape de téléversement distincte.

## Préparer ou sélectionner les fichiers dans Document

Avant de demander à un agent d'orchestrer la migration, choisissez l'une de ces approches :

- Connecter un emplacement de stockage partagé existant comme compte de documents.
- Téléverser les packages de workflows dans un compte de documents.
- Demander à l'agent d'organiser les fichiers déjà disponibles dans Document.

Confirmez ensuite que :

1. Les workflows, applications, macros, fichiers d'entrée, fichiers annexes spatiaux, rapports et sorties attendues sont disponibles via Document.
2. Le projet de destination est sélectionné.
3. Le chemin Document des dépendances et des artefacts des workflows convertis est sélectionné.
4. L'agent est autorisé à utiliser les outils MCP Document et workflow concernés.

L'agent peut alors référencer des chemins Document stables lorsqu'il appelle le convertisseur.

## Exemple d'invite pour l'agent

Utilisez une invite comme celle-ci avec un agent connecté via MCP :

```text
In PlaidCloud, migrate the Alteryx workflows in the connected Document account
"Migration Share" under /q4-alteryx-package into the project "Q4 Migration".

First inventory the .yxmd, .yxwz, and .yxmc files. Organize the package by
workflow, macro, input, spatial, report, and expected-output files. Group macros
with the workflows that call them. Then convert the workflows as Advanced
workflows using the Document output path /q4-alteryx-converted. Prefix created
workflows with "Q4 - ". After each conversion, summarize the generated workflow,
macros, readiness notes, and next validation step. Ask before making mutating calls.
```

Adaptez le nom du projet, le chemin source, le chemin de destination et le préfixe à votre lot de migration.

## Flux d'orchestration recommandé

Pour les migrations de portefeuilles, demandez à l'agent de suivre ce flux :

1. Connecter ou sélectionner le compte de documents qui contient le package de migration.
2. Inventorier le dossier Document source.
3. Identifier les fichiers `.yxmd`, `.yxwz` et `.yxmc`.
4. Organiser les fichiers en groupes de workflows, de macros, d'entrées, de fichiers spatiaux, de rapports et de sorties attendues.
5. Regrouper les workflows et les macros associés.
6. Confirmer le projet de destination et le chemin de sortie Document.
7. Convertir les macros et les workflows en workflows avancés.
8. Ouvrir ou décrire les workflows générés.
9. Exécuter la validation structurelle.
10. Exécuter la validation de la parité des sorties lorsque des sorties attendues sont disponibles.
11. Résumer les workflows convertis, les macros générées, les artefacts et l'état de la validation.

L'équipe de migration obtient ainsi un seul rapport d'avancement pour tout le portefeuille, tout en continuant d'utiliser l'importeur natif de PlaidCloud pour chaque conversion.

## Examiner les appels qui modifient des données

La plupart des clients MCP affichent les appels d'outils avant leur exécution. Examinez les appels de conversion et d'exécution de workflow avant de les approuver, en particulier dans les projets de production.

Pour les migrations en préproduction, utilisez un projet de migration et un dossier Document dédiés. Après validation, promouvez les workflows convertis dans le projet de production.

## Suivre les résultats

Demandez à l'agent de produire un tableau de migration contenant :

- Le fichier Alteryx source.
- Le workflow PlaidCloud généré.
- Les workflows de macros générés.
- L'état de la conversion.
- Le niveau de validation.
- Le chemin de sortie Document.
- Les remarques pour le suivi.

Cette synthèse est utile pour le reporting de projet, la passation et la revue de préparation à la production.
