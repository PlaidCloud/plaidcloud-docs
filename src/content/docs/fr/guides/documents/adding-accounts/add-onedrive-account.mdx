Connectez un emplacement Microsoft **OneDrive for Business** ou **SharePoint** à PlaidCloud Document. Vous inscrivez une application Entra (Azure AD), vous choisissez quelle partie de votre locataire elle peut atteindre, et PlaidCloud l'utilise pour lire et écrire des fichiers.

## Choisir un modèle d'accès

Déterminez quelle partie de votre locataire Microsoft 365 l'application peut atteindre. C'est le choix le plus important de toute la configuration.

| Modèle | Autorisation d'application Graph | Ce que l'application peut atteindre | À choisir lorsque |
|---|---|---|---|
| **Sites sélectionnés** (recommandé) | `Sites.Selected` | Uniquement les sites précis auxquels vous accordez explicitement l'accès | Un site contient des données sensibles : paie, RH, finance, données de santé |
| **Tous les sites** | `Sites.Read.All` (lecture) ou `Sites.ReadWrite.All` (lecture + écriture) | **Tous** les sites du locataire | Aucun site n'est sensible et vous souhaitez la configuration la plus simple |

**La plupart des organisations devraient choisir Sites sélectionnés.** Si un seul site contient des informations sensibles, un accès à l'ensemble du locataire les expose. Avec `Sites.Selected`, l'application ne peut rien atteindre tant qu'un administrateur ne lui a pas accordé l'accès à chaque site nommé : les sites auxquels vous n'accordez jamais l'accès restent totalement hors de portée.

<Aside type="caution">
N'accordez **pas** `Directory.*`, `Files.*` ni `User.Read.All`. Un connecteur de documents n'en a jamais besoin, et `Directory.ReadWrite.All` en particulier permet la lecture et l'écriture sur l'ensemble de votre annuaire d'identités. Une seule autorisation `Sites.Selected` (ou une seule `Sites.Read.All` / `Sites.ReadWrite.All`) suffit.
</Aside>

## Enregistrer l'application dans Azure

1. Connectez-vous au [portail Azure](https://portal.azure.com) et accédez à **Microsoft Entra ID** → **App registrations** → **+ New registration**.
2. Saisissez un nom (par exemple `PlaidCloud`).
3. Sous **Supported account types**, choisissez **Accounts in this organizational directory only** (locataire unique, le cas le plus courant).
4. Laissez le champ **Redirect URI** vide et cliquez sur **Register**.
5. Sur la page de vue d'ensemble, copiez l'**Application (client) ID** (votre **ID client**) et le **Directory (tenant) ID** (votre **ID du locataire**).
6. Accédez à **Certificates & secrets** → **+ New client secret**, définissez une description et une date d'expiration, cliquez sur **Ajouter**, puis copiez immédiatement la **Valeur** du secret : elle ne sera plus affichée.

## Accorder l'autorisation d'API

Ajoutez exactement **une** autorisation **Application** Microsoft Graph, correspondant au modèle d'accès choisi :

- **Sites sélectionnés :** `Sites.Selected`
- **Tous les sites :** `Sites.Read.All` (lecture seule) ou `Sites.ReadWrite.All` (lecture + écriture)

Étapes : **API permissions** → **+ Add a permission** → **Microsoft Graph** → **Application permissions** → ajoutez l'autorisation ci-dessus → **Grant admin consent**.

<Aside type="note">
L'octroi du consentement administrateur nécessite un **Global Administrator** ou un **Privileged Role Administrator** : un administrateur SharePoint seul ne peut pas consentir à une autorisation d'application.
</Aside>

Si vous avez choisi **Tous les sites**, votre configuration est terminée : passez directement à [Ajouter le compte dans PlaidCloud](#ajouter-le-compte-dans-plaidcloud). Si vous avez choisi **Sites sélectionnés**, accordez ensuite à l'application l'accès à chaque site.

## Autoriser l'application sur chaque site (modèle Sites sélectionnés)

`Sites.Selected` n'accorde par lui-même aucun accès à l'application : un administrateur SharePoint ou général doit lui accorder l'accès à chaque site que vous voulez qu'elle atteigne. Aucun écran du centre d'administration ne le permet ; vous utilisez donc deux appels Microsoft Graph dans [Graph Explorer](https://developer.microsoft.com/graph/graph-explorer). Comme vous accordez l'accès site par site, les sites sensibles ne sont tout simplement jamais accordés.

**Configuration unique.** Dans Graph Explorer, connecté en tant qu'administrateur SharePoint ou général, ouvrez l'onglet **Modify permissions** et cliquez sur **Consent** pour `Sites.FullControl.All` (c'est cette portée qui vous permet de définir les accès aux sites). Si une requête ultérieure renvoie `accessDenied`, c'est ce consentement qui manque : déconnectez-vous puis reconnectez-vous après avoir donné votre consentement afin d'actualiser le jeton.

### Étape 1 : trouver l'ID du site

Listez les sites de votre locataire (méthode **GET**) :

```text
GET https://graph.microsoft.com/v1.0/sites?search=*&$select=displayName,webUrl,id
```

Ou résolvez directement un site à partir de son URL :

```text
GET https://graph.microsoft.com/v1.0/sites/contoso.sharepoint.com:/sites/TeamName
```

Copiez l'`id` du site dans la réponse ; il a la forme `contoso.sharepoint.com,<guid>,<guid>`.

### Étape 2 : autoriser l'application

Définissez la méthode sur **POST** pour la collection `permissions` de ce site (collez l'`id` obtenu à l'étape 1) :

```text
POST https://graph.microsoft.com/v1.0/sites/{site-id}/permissions
```

Dans l'onglet **Request body**, collez le contenu suivant ; définissez `roles` sur `["read"]` ou `["write"]` et utilisez l'**Application (client) ID** de votre application :

```json
{
  "roles": ["read"],
  "grantedToIdentities": [
    { "application": { "id": "your-client-id", "displayName": "PlaidCloud" } }
  ]
}
```

Exécutez la requête. En cas de succès, elle renvoie un objet d'autorisation avec un `id` et vos `roles`. **Répétez l'étape 2 pour chaque site** que PlaidCloud doit atteindre. Pour vérifier les accès accordés par un site :

```text
GET https://graph.microsoft.com/v1.0/sites/{site-id}/permissions
```

<Aside type="caution">
`Sites.Selected` s'accorde par **site**, et non par dossier ou par bibliothèque : accorder l'accès à un site expose tout son contenu. Conservez le contenu sensible dans des sites qui lui sont dédiés, afin qu'il ne soit jamais exposé avec le contenu que vous souhaitez partager.
</Aside>

## Ajouter le compte dans PlaidCloud

1. Connectez-vous à PlaidCloud et sélectionnez l'espace de travail dans lequel le compte sera créé.
2. Accédez à `Document` → `Manage` → **Nouveau compte**.
3. Choisissez **OneDrive** comme **Service**.
4. Saisissez un nom et une description, puis choisissez un **Modèle de sécurité** (laissez `Private` en cas de doute).
5. Sous **Identifiants d'authentification**, collez l'**ID client**, le **Secret client** et l'**ID de locataire OneDrive** issus de l'inscription de l'application.
6. Dans **URL du site SharePoint**, collez l'URL d'un site auquel l'application a obtenu l'accès (par exemple `https://contoso.sharepoint.com/sites/TeamName`). La liste **Lecteur/Site** affiche alors les bibliothèques de documents de ce site : choisissez celle qui servira de racine au compte. Le **Chemin de départ** est alors renseigné.
7. Sélectionnez **Enregistrer**.

<Aside type="note">
Un lecteur ou un site est obligatoire : le compte ne peut pas être enregistré sans. Sans lui, le compte listerait les dossiers mais aucun fichier.
</Aside>

## Créer le compte avec un assistant IA

Un assistant IA connecté via le connecteur MCP PlaidCloud peut créer ou mettre à jour le compte pour vous avec l'outil `document_account_upsert`, une fois que vous avez terminé les étapes Azure ci-dessus. Fournissez-lui les valeurs issues de l'inscription de l'application :

| Champ du compte | Valeur |
|---|---|
| `service_type` | `onedrive` |
| `public_key` | ID d'application (client) |
| `private_key` | Secret client |
| `tenant_id` | ID d'annuaire (locataire) |
| `start_path` | ID du lecteur, éventuellement suivi de `/folder` |

Les identifiants sont en écriture seule : `document_account_describe` les masque. L'outil est disponible dans votre propre session MCP connectée, et non pour les étapes de workflow ni pour les agents intégrés à l'application.
