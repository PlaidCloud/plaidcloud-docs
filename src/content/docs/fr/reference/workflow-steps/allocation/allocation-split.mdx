## Description



Découpe la valeur d'une ligne source en parts et oriente chaque part vers une cible différente, avec des proportions déterminées par les données de l'inducteur. Plus simple que [Allocation By Assignment Dimension](/fr/reference/workflow-steps/allocation/allocation-rules/) : utilisez-la lorsque vous avez simplement besoin de répartir des valeurs sans dimension d'affectation.

Schéma courant : prendre un montant total, le répartir entre plusieurs bénéficiaires selon des pourcentages ou des pondérations d'une table d'inducteurs, et produire une ligne de sortie par bénéficiaire.

## Paramètres de la table de données  

La **Table des valeurs à allouer**, la **Table de données de l'inducteur** et la **Table de résultat d'allocation** peuvent être sélectionnées de façon dynamique ou statique.

### Sélection dynamique de table
L'option de table dynamique permet de spécifier une table à l'aide de texte et de variables. Elle est utile dans les workflows pilotés par des variables, où les références de tables ou de vues sont relatives aux variables indiquées.

Exemple utilisant la variable `current_month` pour pointer dynamiquement vers une table :

```text
legal_entity/inputs/{current_month}/ledger_values
```

### Sélection statique de table
Lorsque vous souhaitez une table précise comme source, laissez la case *Dynamique* décochée et sélectionnez la table source dans le menu déroulant.


L'Explorateur de tables est toujours disponible avec toute sélection de table. Cliquez sur le bouton Explorateur de tables à droite de la sélection de table pour ouvrir une fenêtre Explorateur de tables.

<Aside>La **Table de résultat d'allocation** doit être une table et non une vue.</Aside>

### Table des valeurs à allouer

C'est la table qui contient les valeurs à allouer. Il s'agit généralement de valeurs de coûts ou de revenus.  


### Table de données de l'inducteur

La table de données de l'inducteur contient les valeurs que l'étape d'allocation utilisera pour allouer les coûts. 


Exemples :

- Pour qu'une chaîne logistique impute des coûts à des clients, vous pouvez utiliser des données de livraison avec le nombre de livraisons ou le poids des livraisons comme inducteur.
- Pour qu'un support informatique impute ses coûts aux services qu'il assiste, les données de l'inducteur peuvent être le nombre de tickets par centre de coûts. 

#### Règle de signe des données de l'inducteur
Les données de l'inducteur peuvent contenir des valeurs positives et négatives. La **Règle de signe des données de l'inducteur** vous permet de décider comment les signes contradictoires sont traités.
- **Erreur en cas de signes contradictoires** : l'étape d'allocation produit une erreur et s'arrête si des signes contradictoires sont rencontrés.
- **Continuer avec un avertissement en cas de signes contradictoires** : l'étape d'allocation utilise à la fois les valeurs d'inducteur négatives et positives, mais affiche un avertissement.
- **Utiliser uniquement les valeurs d'inducteur positives** : l'étape d'allocation n'utilise que les valeurs d'inducteur positives et ignore les valeurs négatives.
- **Utiliser uniquement les valeurs d'inducteur négatives** : l'étape d'allocation n'utilise que les valeurs d'inducteur négatives et ignore les valeurs positives.
- **Utiliser les valeurs absolues des données de l'inducteur** : l'étape d'allocation utilise les valeurs absolues des données de l'inducteur.


### Table de résultat d'allocation



#### Ajouter les résultats à la table cible
Si cette case est cochée, les résultats de l'allocation sont ajoutés à la table de résultat d'allocation. 
Si cette case n'est pas cochée, la table de résultats d'allocation est écrasée à chaque exécution de l'étape d'allocation.

#### Colonnes distinctes pour les résultats alloués

Si cette case est cochée, la table de résultats affiche le montant de chaque enregistrement alloué ainsi que le montant réellement alloué à chaque enregistrement d'inducteur.
