## Description

L'étape **ML : scorer** score une table de données avec un modèle entraîné par [ML : entraîner un modèle](/fr/reference/workflow-steps/machine-learning/ml-train/) et écrit les données avec une colonne de prédiction ajoutée. Comme le modèle arrive sous forme de table ordinaire, vous pouvez entraîner une fois et scorer plusieurs tables, ou rescorer chaque fois que de nouvelles données arrivent. L'étape s'exécute comme un job PlaidCloud géré (comme l'étape LLM).

## Onglet de scoring

- **Table de données** : la table à scorer. Elle doit contenir toutes les colonnes de variables explicatives sur lesquelles le modèle a été entraîné.
- **Table du modèle** : une table de modèle écrite par une étape ML : entraîner un modèle. L'étape échoue si la table est vide ou si une partie du modèle stocké est manquante.
- **Table de sortie** : l'emplacement où les données scorées sont écrites.
- **Colonne de prédiction** : le nom de la colonne ajoutée. Laissez vide pour utiliser `prediction`. L'étape échoue si ce nom existe déjà dans la table de données.

## Sortie

La table de sortie contient toutes les colonnes de la table de données plus la colonne de prédiction : des libellés de classe textuels pour les classifieurs, des valeurs numériques pour les régresseurs. Les valeurs des variables explicatives sont préparées exactement comme lors de l'entraînement, et les valeurs catégorielles que le modèle n'a jamais vues pendant l'entraînement sont ignorées au lieu de provoquer une erreur.

La table du modèle doit avoir la forme qu'écrit une étape ML : entraîner un modèle : l'ensemble complet des colonnes du modèle, un algorithme connu et chaque partie du modèle stocké présente. Le modèle lui-même est chargé sous une restriction qui rejette tout ce qui sort de la pile scientifique standard, de sorte qu'une ligne de modèle fabriquée à la main ne peut pas exécuter de code arbitraire.

### Autres colonnes de sortie

La section **Options d'évaluation** comporte ces champs. Les workflows KNIME convertis les utilisent aussi.

- **Colonnes de probabilité de classe** (`probability_column_template`) : pour un classifieur, ajoute une colonne de probabilité par classe, nommée d'après ce modèle avec `{class}` remplacé. **Probabilités avant la prédiction** (`probabilities_first`) les place avant la colonne de prédiction, et **Ordonner les classes selon leur première apparition à l'apprentissage** (`classes_in_domain_order`) les ordonne selon l'ordre de première apparition des classes dans les données d'entraînement au lieu de les trier.
- **Colonne de confiance** (`confidence_column`) : pour un classifieur, ajoute sous ce nom la probabilité de la classe gagnante.
- **Colonne de variance** (`variance_column`) : pour un régresseur de type forêt, ajoute sous ce nom la variance des prédictions des arbres.
- **Colonne du nombre de modèles** (`model_count_column`) : pour un modèle à arbres, ajoute sous ce nom le nombre d'arbres.
- **Ordre des colonnes ajoutées** (`column_order`) : l'ordre des colonnes ajoutées. Vide : prédiction, probabilités, confiance, variance, puis nombre de modèles.
- **Écrire plutôt** (`report`) : écrit l'une des tables propres au modèle au lieu des données scorées, par exemple `variable_importance`, `coefficients`, `statistics`, `pmml` (le modèle sous forme de document PMML), `centers`, `cluster_counts` ou `association_rules`.
- **Format du modèle** (`model_format`) : `pmml` score avec un document PMML : la table du modèle contient le document, ou le modèle d'un apprenant qui possède une forme PMML.
- **Paramètres de l'algorithme** (`algorithm_settings`) : paramètres du scoring ou du rapport propres à l'algorithme du modèle, comme le nombre de composantes sur lequel projette un modèle `pca`.
- **Troisième table** (`source_c`) : une troisième table que lisent certains algorithmes, comme la forêt aléatoire qu'utilise un modèle `knn_distance`.

Un assistant IA ou l'API REST peut aussi définir `report` sur `shap_values`.

## Limites et mises en garde

- **Jeu de travail en mémoire** : la table de données est lue en mémoire, de sorte que l'étape vise environ un million de lignes par exécution.
- **Workflows Alteryx convertis** : un outil Predict converti fixe la colonne de prédiction sur le nom de la variable cible avec le suffixe `_predicted`.
