## Description

Joint des documents justificatifs à des enregistrements Sage Intacct via votre [connexion Sage Intacct](/fr/guides/connections/sage-intacct/), en passant par le pipeline d'écriture ERP partagé de PlaidCloud. Chaque ligne de la table source correspond à un fichier : son contenu, son nom et la clé de l'enregistrement Intacct auquel il se rattache. L'étape le crée comme document justificatif Sage Intacct (`supdoc`) et le lie à cet enregistrement. **Validate Only** vérifie chaque ligne sans rien créer dans Intacct ; la table de résultat consigne l'issue de chaque pièce jointe.

Utilisez-la pour envoyer des fichiers qu'un workflow a déjà en main (un PDF de facture généré, un reçu numérisé, un rapport exporté) vers les transactions ou enregistrements Intacct auxquels ils appartiennent, au cours de l'exécution même qui les produit ou les comptabilise. Elle se combine naturellement avec [Intacct : comptabiliser une écriture de journal](/fr/reference/workflow-steps/sage-intacct/export-to-sage/) : comptabilisez les écritures, puis joignez leurs justificatifs avec la clé Intacct renvoyée par chaque comptabilisation.

## Contrat de structure des données

Construisez la table des pièces jointes en amont avec des étapes standard, de sorte que chaque ligne soit un fichier complet lié à un enregistrement :

- **`parent_key`** : l'enregistrement Sage Intacct auquel le fichier est joint. Un fichier et un parent par ligne ; pour joindre le même fichier à plusieurs enregistrements, répétez-le sur plusieurs lignes.
- **`file_name`** : le nom de fichier du document justificatif, extension comprise (`invoice-1043.pdf`).
- **`mime_type`** : le type de contenu du fichier (`application/pdf`, `image/png`), afin qu'Intacct le stocke et le diffuse correctement.
- **`content_base64`** : le contenu du fichier, encodé en base64, dans la ligne.

## Configuration

### Connexion

- **Connexion Sage Intacct** : la connexion Sage Intacct à utiliser pour joindre les documents. Seules les connexions Sage Intacct sont proposées ; la même connexion sert à lire et à écrire dans Intacct.
- **Environnement** : l'environnement de la connexion.

### Données

- **Table des pièces jointes** : la table source décrite ci-dessus, une ligne par fichier, avec `parent_key`, `file_name`, `mime_type` et `content_base64`.
- **Table de résultat** : identifiant de la table de sortie : une ligne par pièce jointe avec `parent_key`, `file_name`, `supdoc_id`, `status`, `message`.
- **Validate Only** : case cochée par défaut. Contrôle préalable uniquement : vérifie chaque ligne et écrit la table de résultat, mais ne crée aucun document justificatif dans Intacct. Une configuration d'étape qui omet entièrement ce champ (par exemple créée via l'API REST, MCP ou l'importation d'un bundle de workflow) est elle aussi en mode Validate Only par défaut, et non en jonction réelle.
- **Continue On Error** : case cochée par défaut. Poursuit la jonction des fichiers restants après l'échec de l'un d'eux. Si elle est décochée, l'exécution s'arrête au premier échec.

## Table de résultat

Chaque exécution, en Validate Only ou réelle, écrit dans la table de résultat une ligne par ligne source :

| Colonne | Description |
|---|---|
| `parent_key` | L'enregistrement Intacct visé par cette pièce jointe. |
| `file_name` | Le nom de fichier de la ligne source. |
| `supdoc_id` | L'identifiant du document justificatif Sage Intacct créé pour le fichier, lorsque la jonction a réussi. |
| `status` | L'issue pour cette ligne : validée, jointe ou en échec. |
| `message` | Une brève description nettoyée de ce qui a échoué, lorsque la ligne est en échec. |
