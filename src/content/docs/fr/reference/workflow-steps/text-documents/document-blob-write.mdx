## Description

L'étape **Document : écrire un Blob** (Document Write Blob) est le pendant de [Document : lire un blob](/fr/reference/workflow-steps/text-documents/document-blob-extract/). Elle écrit les octets base64 d'une colonne de chaque ligne d'entrée dans un fichier d'un compte de documents, un fichier par ligne. La table de sortie contient les lignes d'entrée inchangées.

Le formulaire de l'étape comporte trois groupes d'options : **Tables**, **Écriture** et **Archive**. Les workflows KNIME et Alteryx migrés utilisent cette étape pour leurs écrivains d'objets binaires et de fichiers.

## Configuration

- **Table source** (`source`) et **Table de sortie** (`target_frame`) — la table à lire, et la table dans laquelle les lignes d'entrée sont écrites sans modification. **Colonnes source** (`source_columns`) liste les colonnes transmises.
- **Écriture** — l'écriture elle-même : **Un fichier par ligne** ou **Les lignes en une seule archive**. Les paramètres ci-dessous sont enregistrés dans `alteryx_config`.
  - **Colonne blob** (`blob_field`) — la colonne qui contient les octets base64.
  - **Colonne de fichier** (`field`) — la colonne qui nomme le fichier de chaque ligne.
  - **La colonne de fichier contient** (`method`) — **Un nom de fichier dans le dossier ci-dessous** (`FileName`, la valeur par défaut) : la colonne de fichier est un nom de fichier placé dans le **Dossier** (`path`). **Le chemin de destination complet** (`Path`) : la colonne de fichier est le chemin de destination complet.
  - **Dossier** (`path`) — le `{account, path}` de destination.
  - **Un fichier qui existe déjà** (`if_exists`) — lorsqu'un fichier est déjà présent : **L'écraser** (`overwrite`, la valeur par défaut), **Faire échouer l'étape** (`fail`) ou **Le laisser tel quel** (`skip`).
  - **Compresser** (`compress`) — **Compresser chaque fichier avec gzip** (`gz`) compresse avec gzip les octets de chaque fichier avant son écriture.
  - **Un blob qui commence par < est du texte XML ou SVG, pas du base64** (`xml_text`) — une valeur qui commence par `<` est écrite sous forme de ses octets UTF-8.

**Les lignes en une seule archive** écrit les lignes sources sous forme d'une seule archive au lieu d'un fichier par ligne, à partir de leurs colonnes `Path` et `Blob` (et `Selected` et `EntryName` lorsqu'elles nomment les entrées). La table de sortie contient alors `ArchivePath` et `Blob`. Le groupe **Archive** la définit, et les paramètres sont enregistrés dans `alteryx_config.archive` :

  - **Chemin du document d'archive** (`destination`) — l'endroit où l'archive est écrite.
  - **Format** (`format`) — `zip` (la valeur par défaut), `jar`, `tar`, `tar.gz`, `tar.bz2` ou `cpio`.
  - **Nommer chaque entrée d'après son seul nom de fichier** (`flatten`), **Noms des entrées** (`truncate`) et **Préfixe de dossier à retirer** (`prefix`) — la façon dont les noms d'entrée sont construits à partir des chemins.
  - **Conserver dans l'entrée le nom propre du dossier sélectionné** (`root`), **Document dont l'entrée porte le nom** (`file`) et **Nommer une entrée d'après son EntryName lorsqu'elle en a un** (`named`) — un contrôle plus fin des noms d'entrée.
  - **Table des dossiers vides** (`folders`) — une table avec les colonnes `Path` et `Selected`, qui nomme les dossiers vides à ajouter comme entrées.
  - **Fusionner dans une archive existante** (`append`) — **Non**, **Abandonner si une entrée est en conflit** (`abort`) ou **Remplacer une entrée en conflit** (`overwrite`).
