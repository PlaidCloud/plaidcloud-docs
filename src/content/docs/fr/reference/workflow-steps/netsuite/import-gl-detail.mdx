## Description

Importe le détail des lignes de transactions du grand livre depuis NetSuite, via votre [connexion NetSuite](/fr/guides/connections/netsuite/), dans une table de projet : les lignes de comptabilisation qui sous-tendent vos soldes, pour le rapprochement, l'analyse détaillée ou un compte de résultat détaillé. Choisissez la connexion, nommez une table cible, puis définissez la période et la filiale ; l'étape récupère les lignes et les écrit, sans SuiteQL à rédiger ni à maintenir.

Cette étape fait partie des [étapes d'importation NetSuite](/fr/reference/workflow-steps/netsuite/) prédéfinies. Chacune s'appuie sur une couche de lecture partagée qui actualise le jeton OAuth, parcourt les résultats volumineux page par page et relance automatiquement les erreurs transitoires : une extraction sur une période complète revient donc complète, sans réglage manuel. Pour obtenir les soldes de période plutôt que les lignes, utilisez [NetSuite : importer les soldes](/fr/reference/workflow-steps/netsuite/import-balances/).

## Configuration

| Champ | Obligatoire | Remarques |
|---|---|---|
| Connexion NetSuite | Oui | La connexion NetSuite à utiliser pour la lecture, filtrée sur les connexions de type NetSuite. |
| Table cible | Oui | La table de projet dans laquelle les lignes de transactions sont écrites. Elle est entièrement écrasée à chaque exécution. |
| Date de début | Non | La première date de transaction à inclure, au format `YYYY-MM-DD`, bornes comprises. Laissez vide pour ne définir aucune borne inférieure. Lorsqu'elle est renseignée avec la date de fin, l'extraction est automatiquement découpée en fenêtres de dates pour rester sous la limite de lignes SuiteQL de NetSuite ; consultez l'avertissement ci-dessous. |
| Date de fin | Non | La dernière date de transaction à inclure, au format `YYYY-MM-DD`, bornes comprises. Laissez vide pour ne définir aucune borne supérieure. |
| Filiale | Non | L'ID interne d'une filiale NetSuite, pour limiter l'extraction à cette filiale. Laissez vide pour toutes les filiales. |
| Livre comptable | Non | L'ID interne d'un livre comptable NetSuite. Laissez vide pour extraire **uniquement le livre principal (ID interne 1)**, ou saisissez `all` pour additionner tous les livres. |
| Numéro de compte | Non | Un numéro de compte exact du grand livre, pour limiter l'extraction à un seul compte. Laissez vide pour tous les comptes. |
| Période comptable | Non | L'ID interne d'une période comptable NetSuite. Laissez vide pour toutes les périodes. |

<Aside type="caution">
**Comptes multi-livres :** un compte NetSuite qui utilise la comptabilité multi-livres enregistre une ligne par livre et par ligne de transaction ; extraire tous les livres sans filtre compte donc un total N fois. Si vous laissez Livre comptable vide, l'extraction porte sur **le livre principal uniquement**. Ne saisissez `all` que si vous voulez délibérément un total inter-livres, ou l'ID interne d'un livre précis pour ne traiter que celui-ci.
</Aside>

<Aside type="note">
Limitez la période à la tranche dont vous avez besoin. Chaque exécution remplace toute la table cible : une extraction planifiée relit donc l'intégralité du résultat à chaque fois ; une fenêtre de dates glissante garde rapide une extraction récurrente du grand livre, au lieu de relire tout l'historique.
</Aside>

<Aside type="note">
L'API SuiteQL de NetSuite limite une requête à environ 100 000 lignes sans SuiteAnalytics Connect. Si vous renseignez à la fois la date de début et la date de fin, PlaidCloud découpe préventivement l'extraction en fenêtres qui restent sous cette limite. Le détail du grand livre est l'extraction la plus susceptible de s'en approcher : cela compte donc davantage ici que pour l'importation des soldes. Une extraction **sans borne** qui dépasse la limite échoue avec un message vous invitant à ajouter une plage de dates, plutôt que de renvoyer silencieusement un résultat tronqué.
</Aside>
