## Description

Importe les soldes de comptes depuis NetSuite, via votre [connexion NetSuite](/fr/guides/connections/netsuite/), dans une table de projet : une balance générale sur laquelle vous pouvez construire vos rapports. Choisissez la connexion, nommez une table cible, puis définissez la période et la filiale ; l'étape récupère les soldes et les écrit, sans SuiteQL à rédiger ni à maintenir.

Cette étape fait partie des [étapes d'importation NetSuite](/fr/reference/workflow-steps/netsuite/) prédéfinies. Chacune s'appuie sur une couche de lecture partagée qui actualise le jeton OAuth, parcourt les résultats volumineux page par page et relance automatiquement les erreurs transitoires : une extraction sur une année complète ou sur toutes les filiales revient donc complète, sans réglage manuel. Pour une extraction au niveau des transactions, utilisez [NetSuite : importer le détail du grand livre](/fr/reference/workflow-steps/netsuite/import-gl-detail/) ; pour les comptes, les filiales et les autres listes, utilisez [NetSuite : importer les données de base](/fr/reference/workflow-steps/netsuite/import-master-data/).

## Configuration

| Champ | Obligatoire | Remarques |
|---|---|---|
| Connexion NetSuite | Oui | La connexion NetSuite à utiliser pour la lecture, filtrée sur les connexions de type NetSuite. |
| Table cible | Oui | La table de projet dans laquelle les soldes sont écrits. Elle est entièrement écrasée à chaque exécution. |
| Date de début | Non | La première date à inclure, au format `YYYY-MM-DD`, bornes comprises. Laissez vide pour ne définir aucune borne inférieure. Lorsqu'elle est renseignée avec la date de fin, l'extraction est automatiquement découpée en fenêtres de dates pour rester sous la limite de lignes SuiteQL de NetSuite ; consultez l'avertissement ci-dessous. |
| Date de fin | Non | La dernière date à inclure, au format `YYYY-MM-DD`, bornes comprises. Laissez vide pour ne définir aucune borne supérieure. |
| Filiale | Non | L'ID interne d'une filiale NetSuite, pour limiter l'extraction à cette filiale. Laissez vide pour toutes les filiales. |
| Livre comptable | Non | L'ID interne d'un livre comptable NetSuite. Laissez vide pour extraire **uniquement le livre principal (ID interne 1)**, ou saisissez `all` pour additionner tous les livres. |
| Numéro de compte | Non | Un numéro de compte exact du grand livre, pour limiter l'extraction à un seul compte. Laissez vide pour tous les comptes. |
| Période comptable | Non | L'ID interne d'une période comptable NetSuite. Laissez vide pour toutes les périodes. |

<Aside type="caution">
**Comptes multi-livres :** un compte NetSuite qui utilise la comptabilité multi-livres enregistre une ligne par livre et par ligne de transaction. Si vous laissez Livre comptable vide, l'extraction porte sur **le livre principal uniquement**, ce qui convient pour une balance générale standard. Ne saisissez `all` que si vous voulez délibérément un total inter-livres (qui additionne les livres au lieu de les rapprocher), ou l'ID interne d'un livre précis pour ne traiter que celui-ci.
</Aside>

<Aside type="note">
Filiale et Livre comptable attendent l'ID interne NetSuite, et non un nom. Récupérez une fois les ID internes avec [NetSuite : importer les données de base](/fr/reference/workflow-steps/netsuite/import-master-data/) (type d'enregistrement **filiale**) et conservez-les dans une petite table de référence.
</Aside>

<Aside type="note">
L'API SuiteQL de NetSuite limite une requête à environ 100 000 lignes sans SuiteAnalytics Connect. Si vous renseignez à la fois la date de début et la date de fin, PlaidCloud découpe préventivement l'extraction en fenêtres qui restent sous cette limite : une extraction sur une année complète revient donc complète, sans aucune action de votre part. Une extraction **sans borne** (date de début ou date de fin laissée vide) qui dépasse la limite échoue avec un message vous invitant à ajouter une plage de dates, plutôt que de renvoyer silencieusement un résultat tronqué.
</Aside>
