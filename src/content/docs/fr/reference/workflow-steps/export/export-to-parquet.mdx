## Description

Écrit une table de projet dans un compte de documents sous la forme d'un fichier [Apache Parquet](https://parquet.apache.org/). Parquet stocke les données par colonne plutôt que par ligne ; il se compresse donc bien mieux que CSV sur les tables larges et permet à un lecteur en aval de ne charger que les colonnes dont il a besoin.

C'est généralement le bon choix pour transmettre de grandes tables à une plateforme de données cloud ou à un workflow de science des données. Les types — entiers, décimaux, dates et horodatages — sont conservés, et une colonne de nombres entiers reste une colonne d'entiers même lorsque certaines de ses valeurs sont vides. Associez-le à [Import Parquet](/fr/reference/workflow-steps/import/import-parquet/).

## Éléments de configuration propres à l'étape

### Compression

Parquet compresse par segment de colonne :

* **Snappy** — lecture la plus rapide, taille de fichier moyenne
* **Zstandard** — fichiers plus petits, nécessite un lecteur compatible avec Zstandard 0.8 ou version ultérieure

### Préfixe du fichier cible

Lorsque l'étape exporte une table vers un seul fichier et que la valeur se termine déjà par `.parquet`, par exemple `Loadfile1.parquet`, le fichier est écrit exactement sous ce nom. Sinon, la valeur est un préfixe : chaque table est écrite sous la forme `<prefix><table name>.parquet`.

### Un seul fichier par table

Les exportations Parquet écrivent un fichier par table. Le choix d'écrire plusieurs fichiers est refusé avec un message l'indiquant ; décochez ce choix pour exécuter l'exportation.

### Si le fichier existe

**Un fichier qui existe déjà** (`if_exists`), sous **Si le fichier existe** sur la page **Paramètres du fichier** :

* **L'écraser** (`overwrite`, par défaut) remplace un fichier déjà présent.
* **Faire échouer l'étape sans rien écrire** (`fail`) arrête l'étape sans rien écrire lorsqu'un fichier qu'elle écrirait existe déjà.
