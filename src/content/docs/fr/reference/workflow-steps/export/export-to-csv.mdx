## Description



Écrit une table de projet PlaidCloud dans un compte de documents sous forme de fichier CSV (valeurs séparées par des virgules). C'est le format d'exportation le plus courant, pris en charge par pratiquement tous les systèmes en aval, outils de tableur et plateformes de BI.

Configurable : délimiteur (virgule, tabulation, barre verticale, personnalisé), mise entre guillemets, ligne d'en-tête et encodage.

### Sélection de la compression de fichier

Tous les fichiers exportés sont non compressés, mais les options de compression suivantes sont disponibles :

* Aucune compression
* Zip
* GZip
* BZip2



### Format des données

![Format des données de l'exportation CSV](/images/export_file_csv_data_format.png)



#### Délimiteur
La transformation Exporter en CSV sert à exporter des tables de données vers des fichiers texte délimités enregistrés dans PlaidCloud Document. Cela inclut, sans s'y limiter, les types de délimiteurs suivants :


* Excel CSV (séparé par des virgules)
* Excel TSV (séparé par des tabulations)
* Séparateur défini par l'utilisateur –>


	+ virgule (,)
	+ barre verticale (|)
	+ point-virgule (;)
	+ tabulation
	+ espace ( )
	+ autre/personnalisé (tilde, tiret, etc.)

Pour indiquer un délimiteur personnalisé, sélectionnez **Séparateur défini par l'utilisateur –>** puis **Autre –>**, et saisissez le délimiteur personnalisé dans la zone de texte.


#### Caractères spéciaux

La section **Caractères spéciaux** permet d'indiquer comment traiter les données contenant des guillemets et des caractères d'échappement. Choisissez parmi les paramètres suivants :

* Caractères spéciaux (QUOTE_MINIMAL) : met entre guillemets les champs contenant des caractères spéciaux (tout ce qui pourrait perturber un analyseur configuré avec le même dialecte et les mêmes options). C'est le paramètre par défaut.
* Tous (QUOTE_ALL) : met tout entre guillemets, quel que soit le type.
* Non numérique (QUOTE_NONNUMERIC) : met entre guillemets tous les champs qui ne sont pas des entiers ou des flottants. Avec le lecteur, les champs d'entrée non entre guillemets sont convertis en flottants.
* Aucun (QUOTE_NONE) : ne met rien entre guillemets en sortie. Les caractères de citation sont inclus en sortie avec le caractère d'échappement fourni par l'utilisateur. Notez qu'un seul caractère d'échappement peut être fourni.

Par défaut, un guillemet à l'intérieur d'un champ entre guillemets est écrit doublé (`""`). Activez `escape_quotes` pour l'écrire avec le caractère d'échappement à la place, comme le fait Spark : avec `\` comme caractère d'échappement, le champ `say "hi"` est écrit `"say \"hi\""`. Ce paramètre est désactivé par défaut ; les exportations existantes restent donc inchangées. 

Par défaut, une valeur qui contient un caractère de citation est mise entre guillemets pour cette seule raison. Décochez **Mettre entre guillemets les valeurs contenant le caractère de citation** pour écrire une telle valeur sans guillemets l'entourant, comme le fait Spark avec `escapeQuotes` désactivé ; une valeur qui contient le délimiteur ou un saut de ligne reste entre guillemets. La case est cochée par défaut. Une fois décochée, le fichier est écrit par PlaidCloud plutôt que par l'entrepôt.

Laissez le **Caractère de citation** vide pour écrire chaque valeur exactement telle quelle : rien n'est mis entre guillemets et rien n'est échappé. Une valeur qui contient le délimiteur ou un saut de ligne est alors relue comme plusieurs champs ; choisissez donc un délimiteur que vos données ne contiennent pas.

#### Écrire l'en-tête dans la première ligne
Si cette case est cochée, les en-têtes de la table sont exportés dans la première ligne. Sinon, le fichier exporté n'aura pas d'en-têtes.

#### Inclure les types de données dans les en-têtes
Si cette case est cochée, les en-têtes du fichier exporté contiendront le type de données de la colonne.

#### Fins de ligne Windows

Enfin, la case **Use Windows Compatible Line Endings** est cochée par défaut pour garantir la compatibilité avec les systèmes Windows. Il est conseillé de laisser ce paramètre activé, sauf si vous travaillez dans un environnement exclusivement Unix.




### Si le fichier existe

Dans **Autres options CSV**, **Un fichier qui existe déjà** (`if_exists`) détermine ce qui se passe lorsque le fichier est déjà présent : `replace` (valeur par défaut) écrit un nouveau fichier, `append` ajoute les lignes à la fin du fichier existant sans ligne d'en-tête, et `fail` arrête l'étape sans rien écrire. Un ajout télécharge le fichier, y ajoute les lignes et le téléverse de nouveau ; lorsque deux exécutions ajoutent au même fichier en même temps, la dernière à se terminer l'emporte. Avec `append`, sélectionnez **Réécrire l'en-tête sous les lignes déjà présentes** (`header_on_append`) pour écrire de nouveau la ligne d'en-tête sous les lignes déjà présentes.

### Paramètres supplémentaires

**Autres options CSV** contient également ces champs :

* **Trier les lignes par** (`sort_columns`) — ordonne les lignes écrites selon ces colonnes source, la première clé en premier, chacune avec un paramètre **Colonne**, **Croissant** et **Valeurs nulles**. Une colonne de clé n'a pas besoin d'être écrite. **Valeurs nulles** vaut par défaut « en premier » en ordre croissant et « en dernier » en ordre décroissant. Non utilisé avec **Résumer** ou **Distinct**.
* **Fin de ligne** (`line_ending`) — la fin de chaque ligne, `\n`, `\r\n` ou `\r`, à la place de **Use Windows Compatible Line Endings**.
* **Mettre entre guillemets** (`quote_mode`) — les valeurs mises entre guillemets : **Jamais**, **Toujours**, **Toutes les valeurs sauf les nombres et booléens** ou **Une valeur contenant le délimiteur**. Par défaut, une valeur est mise entre guillemets lorsque c'est nécessaire.
* **Guillemet fermant** (`quote_end`) — le guillemet fermant, lorsqu'il diffère du guillemet ouvrant.
* **Guillemet fermant dans une valeur** (`quote_replacement`) — écrit à la place d'un guillemet fermant à l'intérieur d'une valeur entre guillemets. Si le champ est vide, le guillemet est doublé.
* **Délimiteur dans une valeur** (`delimiter_replacement`) — lorsque **Mettre entre guillemets** est défini sur **Jamais**, écrit à la place du délimiteur à l'intérieur d'une valeur.
* **Commencer le fichier par une marque d'ordre des octets** (`write_bom`) — commence le fichier par une marque d'ordre des octets.
* **Séparateur décimal** (`decimal_separator`) — le caractère écrit pour la virgule décimale d'un nombre.
* **Lignes avant l'en-tête** (`comment_lines`) — un tableau JSON de lignes écrites telles quelles avant l'en-tête.
* **Écrire les nombres décimaux comme Java** (`scientific_numbers`) — écrit un nombre décimal en notation scientifique à partir de 10 millions et en dessous de 0,001, comme `1.0E10`.
* **Écrire chaque nom de fichier tel quel, sans ajouter .csv ou .tsv** (`keep_file_extension`) — écrit chaque nom de fichier exactement tel qu'il est donné.
* **Avec gzip, enregistrer le fichier sous le nom donné, sans ajouter .gz** (`exact_file_name`) — avec la compression gzip, enregistre le fichier sous le nom donné.
