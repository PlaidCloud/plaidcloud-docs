## Description


Copie les données d'une table du projet courant dans une table d'un autre projet. Utile lorsque des projets partagent des données de référence, lorsqu'un projet de consolidation s'alimente auprès de plusieurs projets opérationnels, ou lorsque vous souhaitez transmettre des résultats traités au projet d'une autre équipe.

Les schémas de la source et de la cible doivent être compatibles. Le projet cible doit accorder à ce projet un partage de données en **Écriture**.


## Gestion du partage de données

![Gestion du partage de données](/images/import_external_project_table_1.png)

Avant de pouvoir exporter une table vers un autre projet, ce projet doit autoriser celui-ci à y écrire. Ouvrez l'onglet **Accueil** du projet **cible**, puis sous **Gestion du partage de données** cliquez sur **Nouveau partage de données**, sélectionnez ce projet, cochez **Écriture** sous **Opérations autorisées**, puis cliquez sur **Ajouter un partage de données**. Voir [Partager des données entre projets](/fr/guides/projects/managing-projects/#partage-de-données-entre-projets).

L'étape s'exécute avec l'identité propre à ce projet : une exécution fonctionne donc via le partage quelle que soit la personne qui la lance.

## Exporter la table de projet externe

![Exporter la table de projet externe](/images/export_external_project_table.png)

### Lire depuis
Sélectionnez la **Table source** dans le menu déroulant.

<Aside type="note" title="Table source vide">
Si la table source ne contient aucune ligne lorsque l'étape s'exécute, l'exportation se termine par un avertissement indiquant que la source était vide plutôt que par un succès silencieux, ce qui permet de repérer facilement une cible vide de façon inattendue. Le plus souvent, cela signifie que le workflow n'avait pas encore construit cette table ; assurez-vous que la source est alimentée (et, pour les exécutions planifiées, qu'elle est ordonnée pour s'exécuter en premier) avant l'exportation.
</Aside>

### Écrire vers

#### Projet cible
Sélectionnez le **Projet cible** dans le menu déroulant.

#### Table cible statique

Pour définir la table cible, sélectionnez une table existante avec la liste déroulante **Table cible**, ou cliquez sur le signe vert **« + »** pour créer une nouvelle table comme cible. 

##### Création de table
Lorsque vous créez une nouvelle table, vous pouvez la créer sous forme de **Vue** ou de **Table**. 
###### Vues
Les vues sont utiles car le temps d'exécution d'une étape est nettement plus court qu'avec une table. L'inconvénient des vues est qu'elles sont peu adaptées à l'exploration des données dans le mode Détails de la table.

###### Tables
Lorsqu'une table sert de cible, l'étape met plus de temps à s'exécuter, mais l'exploration des données en mode Détails est bien plus rapide qu'avec une vue.

<Aside>Utilisez des tables pour les étapes clés de vos workflows où la validation des données ou la possibilité d'effectuer des analyses ad hoc sera nécessaire. Pour toutes les autres étapes, utilisez des vues afin de réduire le temps de calcul global du workflow. Il est possible de transformer une table en vue et inversement ; vous pouvez donc toujours modifier ultérieurement le type de la table cible.</Aside>

#### Table cible dynamique

L'option Dynamique permet de désigner une table à l'aide de texte, y compris des variables. C'est utile pour les workflows pilotés par des variables, où les références de tables et de vues sont relatives aux variables indiquées.

Voici un exemple qui utilise la variable `current_month` pour pointer dynamiquement vers la table cible :

```text
legal_entity/inputs/{current_month}/ledger_values
```

<Aside>Si la table n'existe pas, elle sera créée dynamiquement lors de l'exécution du processus d'importation</Aside>

#### Ajouter aux données existantes

Pour ajouter les données de la table source à la table cible, cochez la case ***Ajouter aux données existantes***.
