## Description


Exporte une table de données Analyze vers PlaidCloud Document sous la forme d'un fichier JSON. Plusieurs options (présentées ci-dessous) permettent de choisir l'orientation des données.



Pour en savoir plus sur les fichiers JSON, consultez le site officiel de JSON : http://json.org/.


<Aside>Les fichiers JSON ne conservent *pas* l'ordre des colonnes. L'ordre des colonnes de la table de données source ne correspond pas nécessairement à celui du fichier exporté.</Aside>

### Orientation JSON


Prenons le jeu de données suivant :




| ID |  Name  | Gender | State |
|----|--------|--------|-------|
| 1  | Jack   |   M    |   MO  |
| 2  | Jill   |   F    |   MO  |
| 3  | George |   M    |   VA  |
| 4  | Abe    |   M    |   KY  |

Les fichiers JSON peuvent être exportés dans l'un des quatre formats de données suivants :


* Records : les données sont stockées dans des dictionnaires Python, chaque ligne étant stockée au format \{Colonne -> Valeur, …}. Par exemple : **[\{“ID”:1,”Name”:”Jack”,”Gender”:”M”,”State”:”MO”},\{“ID”:2,”Name”:”Jill”,”Gender”:”F”,”State”:”MO”},\{“ID”:3,”Name”:”George”,”Gender”:”M”,”State”:”VA”},\{“ID”:4,”Name”:”Abe”,”Gender”:”M”,”State”:”KY”}]**
* Index : les données sont stockées dans des dictionnaires Python imbriqués, chaque ligne étant stockée au format \{Index -> \{Colonne -> Valeur, …},…}. Par exemple : **\{“0”:\{“ID”:1,”Name”:”Jack”,”Gender”:”M”,”State”:”MO”},”1”:\{“ID”:2,”Name”:”Jill”,”Gender”:”F”,”State”:”MO”},”2”:\{“ID”:3,”Name”:”George”,”Gender”:”M”,”State”:”VA”},”3”:\{“ID”:4,”Name”:”Abe”,”Gender”:”M”,”State”:”KY”}}**
* Split : les données sont stockées dans un seul dictionnaire Python, les valeurs étant stockées dans des listes. Par exemple : **\{“columns”:[“ID”,”Name”,”Gender”,”State”],”index”:[0,1,2,3],”data”:[[1,”Jack”,”M”,”MO”],[2,”Jill”,”F”,”MO”],[3,”George”,”M”,”VA”],[4,”Abe”,”M”,”KY”]]}**
* Values : les données sont stockées dans plusieurs listes Python. Par exemple : **[[1,”Jack”,”M”,”MO”],[2,”Jill”,”F”,”MO”],[3,”George”,”M”,”VA”],[4,”Abe”,”M”,”KY”]]**


### Gestion des dates


Indiquez le **Format de date** à l'aide de la liste déroulante. Choisissez parmi les formats suivants :


* **Epoch (horodatage Unix – secondes écoulées depuis le 1/1/1970)**
* **Format ISO 8601 (AAAA-MM-JJ HH:MM:SS avec décalage de fuseau horaire)**

Indiquez l'**Unité de date** à l'aide de la liste déroulante. Choisissez parmi les formats suivants, classés par précision croissante :


* **Secondes (s)**
* **Millisecondes (ms)**
* **Microsecondes (us)**
* **Nanosecondes (ns)**

### Forcer l'ASCII


Cochez cette case pour que toutes les chaînes soient encodées au format ASCII. Cette option est activée par défaut.



### Type de fichier de sortie


Tous les fichiers exportés sont non compressés, mais les options de compression suivantes sont disponibles :


* Zip
* GZip
* BZip2


### Paramètres supplémentaires

* **Un fichier qui existe déjà** (`if_exists`), sous **Si le fichier existe** — **L'écraser** (`overwrite`, par défaut) remplace un fichier déjà présent ; **Faire échouer l'étape sans rien écrire** (`fail`) arrête l'étape sans rien écrire lorsqu'un fichier qu'elle écrirait existe déjà.
* **Trier les lignes par** (`sort_columns`), sous **Ordre des lignes** — trie les lignes écrites selon ces colonnes sources, la première clé en premier, chacune avec un paramètre **Colonne**, **Croissant** et **Valeurs nulles**. Une colonne clé n'a pas besoin d'être écrite. **Valeurs nulles** vaut par défaut « en premier » en tri croissant et « en dernier » en tri décroissant. Non utilisé avec **Résumer** ou **Distinct**.
