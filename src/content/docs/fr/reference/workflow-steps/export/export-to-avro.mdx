## Description

Écrit une table de projet dans un compte de documents sous forme de fichier [Apache Avro](https://avro.apache.org/). Avro embarque son schéma dans le fichier : les noms et types de colonnes sont donc conservés lors de l'aller-retour sans définition de schéma distincte, ce qui en fait un bon choix pour transmettre des données à un consommateur Kafka, Spark ou Hadoop.

Associez-la à [Importer depuis Avro](/fr/reference/workflow-steps/import/import-avro/) pour déplacer des tables entre projets sans perdre le typage.

## Éléments de configuration spécifiques

### Compression

Le fichier écrit peut être compressé à la sortie :

* Aucune compression
* Zip
* GZip
* BZip2

### Nom du fichier

Le fichier porte le **Nom du fichier** de l'exportation, avec l'extension `.avro` ajoutée si le nom n'a pas d'extension. Une exportation nommée `customers` écrit `customers.avro`. Lorsque l'exportation écrit plusieurs tables, chaque fichier porte le nom de l'exportation suivi de l'alias de la table, comme dans `customers_orders.avro`. Avec **Many Files** activé, l'exportation écrit un dossier de ce nom contenant `data1.avro`, `data2.avro`, et ainsi de suite, chacun avec au plus la taille de lot en lignes.

### Si le fichier existe

**Un fichier qui existe déjà** (`if_exists`), sous **Si le fichier existe** dans la page **Paramètres du fichier** :

* **L'écraser** (`overwrite`, valeur par défaut) remplace un fichier déjà présent.
* **Faire échouer l'étape sans rien écrire** (`fail`) arrête l'étape, sans rien écrire, lorsqu'un fichier qu'elle écrirait existe déjà.
