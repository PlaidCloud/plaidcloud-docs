## Description

Importe dans une table de projet des données de Workday Financials via votre [connexion Workday Financials](/fr/guides/connections/workday-financials/). Contrairement à NetSuite, Acumatica ou Business Central, PlaidCloud n'a pas d'ensemble fixe d'entités Workday Financials prédéfinies : vous créez dans Workday un **rapport Report-as-a-Service (RaaS)**, vous le publiez avec un accès par service web, puis vous indiquez à cette étape l'URL du rapport comme source d'extraction.

## Configuration

| Champ | Obligatoire | Remarques |
|---|---|---|
| Connexion Workday | Oui | La connexion Workday Financials à utiliser pour la lecture. |
| URL du rapport RaaS | Oui | L'URL de service web du rapport RaaS que vous avez créé et publié dans Workday. |
| Table cible | Oui | La table de projet dans laquelle les résultats sont écrits. Elle est entièrement écrasée à chaque exécution. |
| Filtres | Non | `company`, `ledger`, `period`, `accounting_date` (plage), `ledger_account` (plage), `cost_center`. Chacun est transmis comme paramètre de rapport : un filtre n'a d'effet que si votre rapport RaaS définit une invite correspondante. |

<Aside type="caution">
Définir un filtre sans invite correspondante dans le rapport est rejeté, et non ignoré silencieusement. Ajoutez d'abord l'invite au rapport RaaS dans Workday, puis définissez le filtre ici.
</Aside>

<Aside type="note">
Comme c'est le rapport lui-même qui définit les champs renvoyés, la forme de votre import (noms des colonnes, granularité, dimensions incluses) est celle que produit votre rapport RaaS. Concevez le rapport en tenant compte de la forme attendue de la table cible.
</Aside>
