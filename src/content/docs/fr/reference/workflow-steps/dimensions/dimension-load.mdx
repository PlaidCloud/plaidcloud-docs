## Description

Charge ou met à jour une dimension à partir des données d'une table PlaidCloud. Prend en charge à la fois les chargements initiaux (création de la hiérarchie de zéro) et les mises à jour incrémentielles (ajout de membres, changement de parents, mise à jour de propriétés sans tout reconstruire).

Deux formes de données source sont prises en charge : **Parent-Enfant** (une ligne par arête de l'arbre) et **Niveaux** (une colonne par niveau de la hiérarchie, un chemin complet par ligne). Les valeurs, les alias et les propriétés peuvent être chargés avec les données structurelles.


## Sélection de la dimension
### Spécifier la dimension dynamiquement
Pour spécifier une dimension dynamiquement, incluez dans son nom des variables de **projet** et/ou **locales**.


Les variables sont utiles lorsque les dimensions sont mises à jour à intervalles réguliers et que vous souhaitez conserver la vue historique.

Exemple qui utilise la variable `current_month` pour charger dynamiquement la dimension :

```text
dimension_name_{current_month}
```
### Utiliser une dimension spécifique

Pour utiliser une dimension spécifique, sélectionnez la **dimension** dans la liste déroulante.


### Charger dans une hiérarchie alternative

Pour charger une hiérarchie alternative, sélectionnez d'abord la dimension, dynamiquement ou spécifiquement, cochez la case Charger dans une hiérarchie alternative, puis saisissez le nom de la hiérarchie alternative à charger.

<Aside>Il est souvent utile de disposer de vues ou de consolidations alternatives de la dimension principale. Par exemple, les centres de coûts ont généralement une consolidation comptable, mais une vue alternative fondée sur la structure organisationnelle peut être souhaitée.</Aside>

Un membre absent de la hiérarchie principale ne peut figurer que dans une seule hiérarchie alternative. Un chargement qui le placerait aussi dans une deuxième hiérarchie alternative échoue et nomme le membre ainsi que la hiérarchie alternative qui le contient déjà. Pour utiliser une feuille dans plusieurs hiérarchies alternatives, ajoutez-la d'abord à la hiérarchie principale. Un parent a besoin de son propre nom dans chaque hiérarchie alternative, car une hiérarchie alternative ne peut pas ajouter de membres sous un membre de la hiérarchie principale.

## Table source

### Dynamique 
Pour spécifier la table source dynamiquement, cochez la case **Dynamic Checkbox** et saisissez le nom de la table en incluant dans son nom des variables de **projet** et/ou **locales**.

### Statique

Pour utiliser une **table source** spécifique, sélectionnez la table dans la liste déroulante.

## Propriétés de la dimension et disposition de la table

### Type de consolidation par défaut

Il existe trois options de type de consolidation :
* **"+"** : agrège les valeurs dans la dimension.
* **"-"** : soustrait les valeurs dans la dimension.
* **"~"** : aucune agrégation n'est effectuée dans la dimension.

<Aside>Dans la table de données source, vous pouvez inclure **Type de consolidation** comme colonne afin d'utiliser plusieurs types de consolidation au sein d'une même dimension. La colonne **Type de consolidation** est ensuite utilisée dans la section **Mappage des colonnes** ci-dessous.</Aside>

### Format des colonnes de la table
Il existe deux options de mise en forme de la **Table source** lors du chargement d'une dimension. 
#### Parent-Enfant
Dans une table Parent-Enfant, deux colonnes représentent la structure de la dimension : **Parent** et **Enfant**.

**EXEMPLE PARENT-ENFANT**

| PARENT    | ENFANT    | Type de consolidation |
|-----------|----------|--------------------|
|Parent Total | Parent 1 |        ~           |
|Parent Total | Parent 2 | ~                  |
| Parent 1  | Enfant 1  | +                  |
| Parent 2  | Enfant 2  | +                  |
| Enfant 1   | Enfant 3  | +                  |
| Enfant 1   | Enfant 4  | +                  |
| Enfant 2   | Enfant 5  | +                  |

<Aside>Dans le format de table Parent-Enfant, vous pouvez aussi inclure une colonne **Type de consolidation** dans la table. Le **Type de consolidation** est associé à l'enfant.</Aside>

Une ligne dont le parent est vide charge son enfant comme membre de premier niveau, directement sous la racine. Une ligne dont l'enfant est vide est ignorée.

#### Niveaux aplatis
Dans une table à niveaux aplatis, le nombre de colonnes est illimité, chaque colonne représentant un niveau de la dimension.

**EXEMPLE DE NIVEAUX APLATIS**

|Niveau 1   |Niveau 2 |Niveau 3|Niveau 4|
|----------|--------|-------|-------|
|Parent Total|Parent 1|Enfant 1|Enfant 3|
|Parent Total|Parent 1|Enfant 1|Enfant 4|
|Parent Total|Parent 2|Enfant 2|Enfant 5|

## Mappage des colonnes

Le bouton de menu **Inspecter la source** renseigne la **Colonne source** dans le Data Mapper.
Une fois la **Colonne source** renseignée, utilisez la liste déroulante **Genre** pour mapper les **Colonnes source** vers le type de colonne approprié.
