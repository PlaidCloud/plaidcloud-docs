## Description

L'étape **Table : KNIME Rule Engine** applique une liste de règles KNIME Rule Engine conservées dans une table et lues à l'exécution de l'étape. La première règle qui correspond à une ligne détermine son résultat. Les [workflows KNIME migrés](/fr/guides/workflows/migrate-knime-workflows/) utilisent cette étape pour les nœuds Rule Engine (Dictionary), Rule Engine Variable (Dictionary), Rule-based Row Filter (Dictionary) et Rule-based Row Splitter (Dictionary), y compris les jeux de règles PMML, lorsque les règles proviennent d'une table que l'on ne connaît qu'à l'exécution du workflow.

L'étape convertit les règles qu'elle lit de la même façon que le convertisseur. Une règle qu'elle ne peut pas prendre en charge, par exemple une règle qui utilise une syntaxe propre à Java ou une variable de flux, fait échouer l'étape plutôt que d'écrire une colonne erronée.

Le formulaire de l'étape comprend une section **Tables** dans laquelle **Utiliser les règles pour** choisit le type de règle et où vous choisissez les tables source, de sortie et de règles, une section **Sortie**, une section **Évaluation par jeu de règles** pour les jeux de règles PMML, et une section **Colonnes**.

## Configuration

- `source` et `target_frame` : la table à lire et la table à écrire. `source_columns` et `target_columns` sont les colonnes lues et écrites ; la colonne cible désignée par `output_column` reçoit le résultat des règles.
- `rules_source` : la table dont les lignes sont les règles. `rules_column` contient chaque règle, `outcome_column` son résultat et `rules_order_column`, lorsqu'elle est définie, ordonne les règles.
- `rule_kind` : `engine` (par défaut) écrit le résultat des règles dans `output_column`, typé par `output_dtype`. `filter` et `splitter` écrivent les lignes que les règles conservent : `include` (true par défaut) détermine si un résultat TRUE conserve ou écarte la ligne, et `port` vaut `1` pour les lignes conservées ou `2` pour les autres. `variable` écrit la table d'une ligne de la valeur que calculent les règles, sans table source.
- `outcome_cell` : le type de cellule KNIME de la colonne de résultat, qui détermine la manière d'écrire un résultat dans une règle. `knime_types` donne le type de cellule KNIME des colonnes d'entrée de type date-heure avec fuseau, durée et période.
- `dollar_references` : les résultats de la forme `$column$` désignent des colonnes plutôt que du texte. `disallow_long` (true par défaut) correspond au paramètre de même nom de KNIME.
- Jeux de règles PMML : `default_rule` est une règle qui se déclenche toujours, ajoutée en dernier. `weight_column` et `default_weight` (1.0 par défaut) définissent le poids de chaque règle pour la sélection pondérée, où la règle la plus lourde est essayée en premier. `confidence_column`, `confidence_cell`, `confidence_output` et `default_confidence_rule` écrivent la confiance du résultat de chaque règle.
