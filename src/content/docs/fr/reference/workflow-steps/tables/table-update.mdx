## Description

Met à jour les lignes qui correspondent à votre filtre et écrit le résultat dans une table cible. Chaque
ligne source parvient à la cible : les lignes correspondant au filtre avec vos nouvelles valeurs, et
toutes les autres lignes exactement telles qu'elles étaient. Le nombre de lignes de la cible est toujours égal au nombre de lignes
de la source.

Le filtre choisit les lignes qui sont *modifiées*, et non celles qui sont renvoyées. C'est ce qui distingue cette étape de [Table Extract](/fr/reference/workflow-steps/tables/table-extract/),
où le filtre supprime les lignes qui ne correspondent pas.

<Aside type="note" title="Cette étape ne modifie plus la table source">
Elle mettait auparavant à jour la table source sur place. Elle laisse désormais la source intacte et
écrit dans une cible distincte, de sorte que les données d'origine restent disponibles pour comparaison et
que l'étape s'exécute sur tous les entrepôts de données, y compris ceux qui n'autorisent pas la modification d'une table
sur place. Les étapes enregistrées avant ce changement nécessitent qu'une table cible soit sélectionnée avant de
pouvoir s'exécuter, et toute étape qui lisait la source en s'attendant à y voir les lignes mises à jour
doit être redirigée vers la nouvelle cible.
</Aside>

## Paramètres de mise à jour

<SnippetCommonTableSourceAndTarget />

La cible doit être une table différente de la source : cette étape lit chaque ligne source
et l'écrit, de sorte que la rediriger vers sa propre source ajouterait le résultat aux
données qu'elle vient de lire.

<Aside type="note" title="La source doit être une table, pas une vue">
Les vues peuvent être choisies comme **cible** (et constituent un bon choix ici : une vue ne stocke aucune
donnée et se réévalue par rapport à la source à chaque lecture), mais pas comme
**source** : cette étape reprend la liste des colonnes de la cible à partir du schéma propre de la table source,
ce qu'une vue ne porte pas.
</Aside>

Les colonnes de la cible reflètent toujours celles de la source ; vous ne les choisissez donc jamais. Les colonnes que vous
ne mettez pas à jour sont reportées sans modification, y compris toute colonne ajoutée à la source
depuis la dernière ouverture de cette étape.

## Colonnes à mettre à jour

Dans l'onglet **Colonnes**, ajoutez une ligne pour chaque colonne que vous voulez modifier et
définissez exactement un des éléments suivants :

- **Constante** : une valeur fixe.
- **Expression** : un calcul, qui peut référencer d'autres colonnes de la même ligne.
- **Définir sur Null** : vide la colonne.

Les colonnes que vous ne listez pas sont laissées telles quelles.

Une **Colonne de mise à jour** que ne listent pas les colonnes source de gauche s'affiche en rouge derrière un panneau d'avertissement ⚠, même sur une ligne comportant une **Constante**, une **Expression** ou **Définir sur Null**, car l'étape met à jour cette colonne par son nom exact. Enregistrer avec une telle ligne ouvre une boîte de dialogue **Colonnes obsolètes détectées** qui propose **Tout supprimer et enregistrer**, **Enregistrer quand même** ou **Annuler**.

L'enregistrement contrôle aussi chaque **Colonne de mise à jour** par rapport à la table source telle qu'elle est maintenant, par son nom exact, quelles que soient les colonnes source listées. Une colonne de mise à jour que la table ne possède pas est nommée dans la boîte de dialogue **Colonnes source manquantes**, car l'étape échouerait dessus à l'exécution. La liste des colonnes source elle-même n'est pas contrôlée par rapport à la table : cette étape lit la table telle qu'elle est, et non la liste.

<Aside type="caution" title="Les expressions lisent les valeurs d'origine de la ligne">
Une expression voit la ligne telle qu'elle était *avant* la mise à jour, de sorte que deux colonnes peuvent
échanger leurs valeurs en toute sécurité dans une seule étape.
</Aside>

## Filtres de données pour la mise à jour

Dans l'onglet **Filtres**, saisissez la condition qui identifie les lignes à
modifier. Laissez-la vide pour mettre à jour toutes les lignes.

Une ligne dont la condition ne peut pas être évaluée (le plus souvent parce qu'une colonne testée est
nulle) est traitée comme ne correspondant pas, et passe sans modification. Cela correspond à la façon dont une
base de données évalue la même condition.
