## Description

Copie une table d'un projet vers un autre. Utilisez-la pour transférer entre projets une table de référence partagée, un jeu de résultats publié ou une table de correspondance adossée à une dimension, sans passer par un export vers un fichier puis une réimportation.

Les deux côtés sont nommés explicitement — un projet et une table source, et un projet et une table cible. Le projet cible est d'abord le projet courant, mais il peut s'agir de n'importe quel projet : une étape peut donc copier vers ce projet, depuis ce projet, ou entre deux autres projets. La table cible est créée si elle n'existe pas, et doit être une table et non une vue.

## Gestion du partage de données

Une copie nécessite jusqu'à deux partages de données :

- **Lecture, du projet source vers le projet cible**, de sorte que les données de la source n'arrivent que là où la source les partage. Ouvrez l'onglet **Accueil** du projet **source**, puis, sous **Gestion du partage de données**, cliquez sur **Nouveau partage de données**, sélectionnez le projet cible, cochez **Lecture** sous **Opérations autorisées**, et cliquez sur **Ajouter un partage de données**.
- **Écriture, du projet cible vers ce projet** — le projet dans lequel se trouve le workflow, qui effectue l'écriture — lorsque la cible est un autre projet. Ouvrez l'onglet **Accueil** du projet **cible**, puis, sous **Gestion du partage de données**, cliquez sur **Nouveau partage de données**, sélectionnez ce projet, cochez **Écriture** sous **Opérations autorisées**, et cliquez sur **Ajouter un partage de données**.

Une copie vers ce projet n'a donc besoin que du partage en lecture, et une copie au sein d'un même projet n'en nécessite aucun. Consultez [Partage de données entre projets](/fr/guides/projects/managing-projects/#partage-de-données-entre-projets).

Sans un partage requis, l'enregistrement de l'étape est refusé et une exécution échoue, avec un message qui nomme chaque partage à ajouter — par exemple *Project 'Sales' can't write to project 'Finance': in project 'Finance', under Data Sharing Management, add a data share for 'Sales' that allows Write.* Une exécution refusée laisse le projet cible tel quel, sans créer la table cible. Un projet indiqué sous forme de variable est vérifié lors de l'exécution de l'étape.

L'étape s'exécute avec l'identité propre à ce projet ; une exécution fonctionne donc grâce aux partages, quel que soit l'utilisateur qui la lance.

## Paramètres de copie

### Lire depuis

- **Projet source** — le projet à copier.
- **Table source** — la table à copier, choisie dans le projet source.

### Écrire vers

- **Projet cible** — le projet dans lequel copier. Il s'agit d'abord du projet courant.
- **Table cible** — la table à écrire, choisie dans le projet cible. Choisir un autre **Projet cible** efface une table choisie dans l'ancien ; une table indiquée par son nom ou son chemin est conservée, puis recherchée dans le nouveau projet.
- **Ajouter aux données existantes** — cochez pour ajouter les lignes copiées à ce que la table cible contient déjà. Laissez décoché pour remplacer les lignes de la table par celles de la source.

Un projet enregistré que vous ne pouvez pas voir, ou qui a été supprimé, s'affiche marqué **(missing)** au lieu d'être remplacé par un autre projet.
