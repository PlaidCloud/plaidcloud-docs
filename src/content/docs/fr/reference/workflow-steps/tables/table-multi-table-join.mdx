## Description

L'étape **Jointure multi-tables** joint plusieurs tables (jusqu'à 32) en une seule opération à l'aide d'un **concepteur visuel de graphe de jointures**, en remplacement du schéma qui consiste à enchaîner plusieurs étapes de jointure de deux tables. Vous ajoutez des tables, tracez des jointures entre leurs colonnes, choisissez un type de jointure et des conditions pour chaque jointure, puis mappez les colonnes de sortie. L'éditeur comporte trois onglets : **Tables & Joins**, **Colonnes de sortie** et **Post-Join Filter**.

Pour un tutoriel complet, consultez le [guide de l'étape Jointure multi-tables](/fr/guides/workflows/multi-table-join-step/).

## Concepteur

* **Ajouter une table** : place une table source sur le canevas sous forme de carte de colonnes. Chaque table a un **alias** (utilisé sous la forme `alias.column`) qui doit commencer par une lettre ou un tiret bas et ne peut pas être un mot-clé SQL.
* **Table cible** : la table dans laquelle le résultat joint est écrit ; elle est créée si elle n'existe pas.
* **Dynamique** : indiquez une source ou la cible sous forme de référence plutôt que de la choisir : un nom de table, un chemin de projet (`/03 Results/FACT_GL`), ou l'un ou l'autre contenant des jetons `{variable}` résolus à l'exécution. Les colonnes d'une source dynamique ne peuvent pas être lues à la conception ; elles sont donc saisies à la main dans le panneau latéral.
* **Tracer des jointures** : faites glisser depuis un point de colonne d'une table vers une colonne d'une autre pour créer une jointure ; un **Libellé** facultatif nomme le lien.
* **Filtre entrant** : un filtre par table appliqué *avant* la jointure.
* **Réextraire depuis le serveur** : actualise les colonnes d'une carte de table à partir du catalogue le plus récent.
* **Réorganiser la disposition** / **Ajuster** / **1:1** : range automatiquement le graphe, zoome pour l'ajuster ou revient à 100 % ; les boutons de zoom, la molette de la souris et le panoramique sont aussi disponibles, et une minicarte affiche tout le graphe.
* **Défaire** / **Rétablir** / **Historique** : parcourir, examiner et restaurer les modifications.
* **Filtrer les colonnes…** : réduit les colonnes affichées sur une carte de table.
* **Exporter en PDF** / **Exporter en PNG** : télécharge le diagramme de jointures, depuis le bouton d'exportation et son menu.

## Types de jointure

| Type | Conserve |
|------|-------|
| `INNER` | Les lignes qui correspondent entre les tables jointes. |
| `LEFT` | Toutes les lignes de la table de gauche, les lignes correspondantes de droite. |
| `FULL` | Toutes les lignes des deux tables. |
| `CROSS` | Toutes les combinaisons de lignes (aucune condition autorisée). |

## Conditions

Chaque jointure non croisée comporte une ou plusieurs conditions combinées avec **AND** / **OR**, utilisant les opérateurs `=`, `<>`, `<`, `<=`, `>`, `>=`, `BETWEEN`, `IS NULL`, `IS NOT NULL`, `IN`, `NOT IN`, `LIKE`, `NOT LIKE`.

Une condition peut nommer une colonne dont le nom comporte des espaces ou de la ponctuation, comme `Build Plant` ou `Cust (Id)` ; la colonne doit exister dans cette entrée. Les noms contenant un guillemet double, une apostrophe inverse, une barre oblique inverse ou un caractère de contrôle sont refusés.

Pour `BETWEEN`, une borne écrite sous la forme de l'alias d'une entrée, d'un point et d'une colonne (`cust.Max Id`) est lue comme une colonne de cette entrée. Toute autre borne est un texte littéral, y compris un simple nom d'alias sans point. Une borne de texte qui commence par un alias et un point, comme `cust.2024` lorsqu'une entrée a l'alias `cust`, est donc lue comme une colonne et signalée comme manquante.

## Sortie

Dans l'onglet **Colonnes**, mappez les colonnes de résultat ; renommez, définissez le type de données et agrégez selon les besoins. Les colonnes de même nom sont automatiquement préfixées de leur alias de source pour éviter les collisions.

Chaque ligne tire sa valeur d'exactement un de trois champs ; en définir plusieurs, ou aucun, est rejeté :

| Type | Champs |
|------|--------|
| Colonne source | **Alias de la source** (l'alias du canevas qui la détient) plus **Source** (`alias.column`). Les deux sont obligatoires. |
| Constante | **Constante** : la même valeur fixe sur chaque ligne. |
| Expression | **Expression** : une expression SQLAlchemy qui peut référencer n'importe quel alias du canevas sous la forme `alias.column`. |

* **Choisir dans le canevas…** : cochez des colonnes de chaque source du canevas.
* **Ajouter toutes les colonnes source** : ajoute toutes les colonnes de toutes les sources.
* **Ajouter une colonne d'expression** : ajoute une ligne d'expression et ouvre l'éditeur d'expressions.

<Aside type="caution" title="Chaque colonne de sortie nécessite un type de données">
Une colonne de sortie laissée sans **Type** arrête cette étape, qui nomme la colonne pour que vous puissiez le définir. Les autres étapes se rabattent sur le type de la colonne source que lit cette sortie ; celle-ci ne le fait pas, délibérément : elle indexe ses colonnes par alias de source, donc dans une jointure portant sur plusieurs tables une supposition aurait autant de chances d'être fausse que juste, et savoir quelle colonne corriger est plus utile qu'une conversion silencieuse.
</Aside>

L'onglet **Post-Join Filter** applique un filtre facultatif au résultat de la jointure (l'équivalent d'un `HAVING` SQL) avant son écriture, modifié dans le même éditeur d'expressions. Il référence les colonnes de sortie sous la forme `result.column_name` ; les alias de source n'y sont pas dans la portée.

## Colonnes nommées à l'exécution

Sélectionnez **Reporter aussi les colonnes nommées à l'exécution** pour transmettre, sans modification, chaque colonne source que l'étape ne liste pas, telle que la table les contient lorsque l'étape s'exécute. Utilisez cette option lorsqu'une étape antérieure crée des colonnes dont les noms dépendent des données, comme un pivot, de sorte que vous ne pouvez pas les lister lorsque vous construisez l'étape. Laissez-la désactivée pour n'écrire que les colonnes que vous listez.

## Comportement

* Le graphe de jointures est un arbre : chaque table se joint au résultat par exactement un lien (sans cycles), et une table ne peut pas être jointe à elle-même.
* La configuration est validée à la fois lorsque vous enregistrez l'étape et lorsqu'elle s'exécute ; les erreurs marquent la table ou la jointure fautive d'un repère ⚠, un enregistrement échoué vous place sur l'onglet qui contient le premier problème, et **Aller au problème** y mène à la demande. Les expressions des colonnes de sortie et le Post-Join Filter sont contrôlés à l'enregistrement ; une jointure qui reporte des colonnes nommées à l'exécution ignore le contrôle des expressions à l'enregistrement et est contrôlée à l'exécution de l'étape.

<Aside type="caution">Les jointures `CROSS` produisent le produit cartésien de leurs entrées et peuvent être très coûteuses sur de grandes tables.</Aside>
