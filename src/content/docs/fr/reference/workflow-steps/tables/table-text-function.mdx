## Description

L'étape **Table : fonction de texte** (Table Text Function) applique une fonction de texte aux colonnes de chaque ligne que la fonction lit, et écrit le résultat dans une nouvelle colonne d'une copie de la table source. Un NULL dans une colonne lue par la fonction donne NULL.

## Source et options

- **Table source** et **Table de sortie** — la table à lire et la table à écrire.
- **Fonction** — la fonction à appliquer. Le formulaire propose les fonctions des deux tableaux ci-dessous et affiche un champ de colonne, libellé selon son rôle, pour chaque argument que la fonction sélectionnée lit.
- **Colonnes d'arguments** — les colonnes que la fonction lit, dans l'ordre où le tableau les indique. Chacune est obligatoire.
- **Colonne de sortie** — le nom de la colonne ajoutée à la copie de la source.

| Fonction | Arguments | Résultat |
| --- | --- | --- |
| `levenshtein` | Première colonne, Deuxième colonne | Distance d'édition sensible à la casse, sous forme d'entier |
| `soundex` | Texte | Texte |
| `json_format` | JSON | Texte JSON mis en forme |
| `json_field` | JSON, Chemin | Texte |
| `json_set_text`, `json_set_number`, `json_set_boolean` | JSON, Chemin, Valeur | Texte JSON avec la valeur définie |
| `regex_match` | Texte, Motif, Respecter la casse | Vrai ou faux |
| `regex_search` | Texte, Motif, Occurrence, Respecter la casse | Position, sous forme d'entier |
| `regex_extract` | Texte, Motif, Occurrence, Respecter la casse | Texte |
| `regex_replace` | Texte, Motif, Remplacement, Respecter la casse | Texte |
| `to_text_number` | Nombre, Motif | Texte : le nombre écrit avec un motif de style DecimalFormat |
| `to_text_datetime` | Date/heure, Motif | Texte : la date écrite avec un motif de date et d'heure |
| `parse_date` | Texte, Motif | Le texte lu comme une date |
| `parse_datetime` | Texte, Motif | Le texte lu comme une date et heure |

Une analyse Savant convertie peut contenir n'importe laquelle de ces fonctions, et elles s'exécutent de la même façon. Une fonction que le formulaire ne propose pas affiche ses colonnes enregistrées et est conservée exactement telle qu'elle a été enregistrée.

### Autres fonctions

La liste **Fonction** propose aussi ces fonctions. Les workflows KNIME convertis les utilisent également.

| Fonction | Arguments | Résultat |
| --- | --- | --- |
| `damerau_levenshtein`, `hamming`, `lcs` | Première colonne, Deuxième colonne | La distance d'édition correspondante, sous forme d'entier |
| `jaro`, `jaro_winkler` | Première colonne, Deuxième colonne | 1 moins la similarité, 0 pour des textes identiques |
| `ngram_distance` | Première colonne, Deuxième colonne | 1 moins le coefficient de Dice des bigrammes de caractères |
| `jaccard_tokens`, `dice_tokens`, `cosine_tokens` | Première colonne, Deuxième colonne | 1 moins la similarité ensembliste des mots des deux textes, 1 si l'un d'eux n'en a aucun |
| `java_compare` | Première colonne, Deuxième colonne | La différence des premiers caractères qui diffèrent, telle que la donne `compareTo` de Java, sous forme d'entier |
| `java_regex` | Texte, Motif, Remplacement *(mode remplacement uniquement)* | Une expression régulière Java lue depuis une colonne : vrai ou faux dans les modes `matches` et `find`, texte dans `extract` et `replace` |
| `knime_count` | Texte, Texte recherché | Le nombre d'occurrences du texte recherché, sous forme d'entier |
| `knime_binomial`, `long_pow` | Deux nombres | Le coefficient binomial, ou la puissance entière, en arithmétique 64 bits avec bouclage |
| `encode`, `decode` | Texte | Le texte sous forme d'octets base64 dans un jeu de caractères, et inversement |
| `url_encode` | Texte | Le texte encodé en pourcentage comme une valeur de formulaire, un espace s'écrivant `+` |
| `list_sort_numeric` | Texte | Une liste stockée sous forme de texte séparé, triée par valeur numérique |
| `geojson_to_wkt` | JSON, Chemin | La géométrie GeoJSON à un chemin tel que `$.a[0]`, ou `$` pour le texte lui-même, en WKT |
| `json_patch_apply` | JSON | Le document après application d'un JSON Patch ou d'un Merge Patch |
| `json_diff` | Premier JSON, Second JSON | Le JSON Patch qui transforme le premier document en second |
| `json_schema_check` | JSON | Les erreurs du document par rapport à un schéma JSON, sous forme de JSON ; NULL s'il n'en a aucune |
| `json_normalize` | JSON | Le document sous forme de texte JSON normalisé |
| `json_to_xml`, `xml_to_json` | Document | Le document converti en XML, ou en JSON |
| `xml_well_formed` | XML | Le texte s'il s'agit de XML bien formé, sinon NULL |
| `xslt` | XML, Feuille de style | Le document transformé par la feuille de style XSLT |
| `message_text`, `message_tool_calls` | JSON | Le texte d'un message d'IA, ou ses appels d'outils sous forme de JSON |

Définissez les options d'une fonction dans `function_options` :

- `java_regex` — `mode` : `matches` (par défaut, le texte entier), `find` (n'importe où), `extract` (groupe `group` de la première correspondance, 0 par défaut) ou `replace` (chaque correspondance) ; `flags` `i` ignore la casse.
- `knime_count` — `modifiers` : `i` ignore la casse, `w` compte les mots entiers délimités par des espaces.
- `encode` et `decode` — `charset`, un nom de jeu de caractères Java ; la valeur par défaut est UTF-8.
- `json_patch_apply` — `patch`, le tableau JSON Patch ou l'objet Merge Patch ; `merge` vaut true pour un Merge Patch ; `keep` conserve le document lorsqu'un test du correctif échoue.
- `json_schema_check` — `schema` ; `fail` arrête l'étape à la première erreur au lieu de la renvoyer.
- `json_normalize` — `comments` autorise les commentaires `/* */` et `//` ; `fail` (true par défaut) arrête l'étape sur un texte qui n'est pas du JSON, et false donne NULL.
- `json_to_xml` — `root`, `item`, `typed`, `parent_keys`, `namespace`, `text_key` et `text_key_enabled`. `xml_to_json` — `text_key`, `comments` et `pis`.
- `list_sort_numeric` — `separator` ; `empty`, le texte écrit pour une liste sans élément ; et `missing`, le texte d'un élément manquant, trié en dernier.

Par défaut, l'étape lit toutes les colonnes de la source et écrit toutes les colonnes sources suivies de la colonne de sortie. Définissez `source_columns` pour ne lire que certaines colonnes, et `target_columns` (chacune `{source, target, dtype}`) pour choisir et ordonner les colonnes écrites. Une colonne cible portant le même nom que la colonne de sortie prend sa place, avec le type de données indiqué.
