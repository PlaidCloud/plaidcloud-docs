## Description

Combine l'insertion et la mise à jour en une seule opération, à partir d'une ou plusieurs colonnes que vous désignez comme clé de correspondance. Pour chaque ligne de la source : si une ligne correspondante existe dans la cible (mêmes valeurs de clé), elle est mise à jour ; sinon, une nouvelle ligne est insérée.

Utilisez cette étape lorsque vous avez un flux de données incrémentiel qui comprend à la fois de nouveaux enregistrements et des révisions d'enregistrements existants : mises à jour de ventes, modifications de fiches d'employés ou tout scénario où l'on veut toujours refléter l'état le plus récent. Choisissez soigneusement les colonnes de correspondance : les lignes qui partagent les mêmes valeurs de clé mais diffèrent sur les autres colonnes seront écrasées, et une mauvaise clé peut donc corrompre les données sans avertissement.

## Paramètres d'upsert

![Source et cible](/images/table_source_and_target_EN.png)

Pour définir les tables source et cible, sélectionnez d'abord la table de données à extraire dans la liste déroulante **Table source**. Sélectionnez ensuite une table existante comme table cible dans la liste déroulante **Table cible**.


## Sélection des données de la table source

![Table Upsert](/images/table_upsert.png)

Le Data Mapper sert à mapper les colonnes des données sources vers la table de données cible.

### Inspection et renseignement du mappeur

Le bouton de menu **Inspecter la source** offre d'autres moyens de mapper les colonnes de la source vers la cible :

* Renseigner les deux tables de mappage : propage toutes les valeurs de la table de données source vers la table de données cible. C'est le comportement par défaut.
* Renseigner uniquement la table de mappage source : mappe uniquement toutes les valeurs de la table de données source. C'est utile lorsque vous modifiez un workflow existant dont la structure des colonnes sources a changé.
* Renseigner uniquement la table de mappage cible : propage toutes les valeurs vers la table de données cible uniquement.

Si les options de colonnes source et cible ne suffisent pas, vous pouvez ajouter d'autres colonnes à la table de données cible de plusieurs façons :

* **Tout propager** insère toutes les colonnes sources dans la table de données cible, qu'elles existent déjà ou non.
* **Propager la sélection** insère uniquement les colonnes sources sélectionnées.
* Faites un clic droit côté cible et sélectionnez **Insérer une ligne** pour insérer une ligne juste au-dessus de la ligne actuellement sélectionnée.
* Faites un clic droit côté cible et sélectionnez **Ajouter une ligne** pour insérer une ligne en bas (à l'extrême droite) de la table de données cible.

<Aside type="danger">Sélectionner *Tout propager* duplique les colonnes si elles existent déjà dans la liste cible</Aside>

### Suppression de colonnes

Pour supprimer des colonnes de la table de données cible, sélectionnez les colonnes voulues, faites un clic droit, puis sélectionnez **Supprimer**.

### Modification de l'ordre des colonnes

Pour réorganiser les colonnes de la table de données cible, sélectionnez les colonnes voulues. Vous pouvez utiliser :
* **Flèches de déplacement groupé** : sélectionnez l'option de déplacement voulue avec les flèches en haut à droite
* **Menu contextuel** : faites un clic droit et sélectionnez **Déplacer en haut**, **Monter**, **Descendre** ou **Déplacer en bas**.

### Réduire le résultat aux enregistrements distincts uniquement

Pour ne renvoyer que les enregistrements distincts, sélectionnez l'option de menu **Distinct**. Elle affiche une série de cases à cocher, une pour chaque colonne de la source. Il suffit de cocher la case en regard de la colonne correspondante pour ne renvoyer que les résultats distincts.

Selon la situation, vous pouvez envisager d'utiliser plutôt une synthèse.

Le traitement distinct conserve le premier enregistrement unique trouvé et écarte les autres.  Il peut être judicieux de trier les données si la cohérence entre les exécutions est importante.

<Aside type="danger">Sélectionner toutes les colonnes pour déterminer le caractère distinct peut donner l'impression que le traitement n'est pas appliqué. Sélectionnez uniquement les colonnes qui, selon vous, définissent le caractère distinct des données.</Aside>
### Clé de mise à jour

La grille des colonnes cibles comporte une colonne **Clé de mise à jour**, juste après le nom de la colonne cible. Cochez-la pour les colonnes qui, ensemble, identifient une ligne : une ligne source dont les valeurs de clé correspondent à une ligne déjà présente dans la cible met à jour cette ligne, et toute autre ligne source est insérée.

Toutes les colonnes sont cochées au départ : décochez donc celles qui ne font pas partie de la clé. Une colonne sans paramètre de clé de mise à jour, par exemple une colonne que Renseigner vient d'ajouter ou une colonne enregistrée via l'API sans ce paramètre, compte comme une clé. Au moins une colonne doit rester cochée.

## Contrôles effectués à l'enregistrement

- **Au moins une clé de mise à jour.** Sinon, l'enregistrement est refusé avec le message *At least one target column must be marked as Update Key.*
- **Le mappage correspond à une table cible existante.** Lorsque la table cible existe déjà, l'étape doit mapper chacune de ses colonnes, ne mapper aucune colonne que la table n'a pas et attribuer à chaque colonne le type de la table, afin qu'un upsert ne puisse pas supprimer une colonne de la table, avec ses données, ni changer le type d'une colonne. Les types numérique et monétaire comptent comme un seul type. Le refus nomme chaque différence, par exemple *The target columns must match the existing target table 'customers'. The table has columns the step doesn't map: region.* Une table cible qui n'existe pas encore, ou dont le nom est donné par une variable, est vérifiée à l'exécution de l'étape.
- **Un mappage vide est renseigné pour vous.** L'enregistrement avec une table source choisie mais sans colonnes source ou cible renseigne le côté vide à partir de la source, comme le ferait **Renseigner les deux tables de mappage**.
