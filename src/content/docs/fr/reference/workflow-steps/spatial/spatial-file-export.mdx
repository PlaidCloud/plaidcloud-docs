## Description

L'étape **Spatial : export de fichier** écrit une table dans un fichier spatial d'un compte de documents, avec une entité par ligne : la géométrie provient d'une colonne WKT et les autres colonnes deviennent les attributs de l'entité. Associez-la à [Spatial File Import](/fr/reference/workflow-steps/spatial/spatial-file-import/).

Le formulaire de l'étape comporte une section **Source et fichier** pour la table source, ses colonnes, le fichier de sortie et le comportement si le fichier existe, ainsi qu'une section **Géométrie** pour la colonne de géométrie et le système de coordonnées. Les [workflows KNIME migrés](/fr/guides/workflows/migrate-knime-workflows/) utilisent cette étape pour leurs écritures de fichiers géospatiaux.

## Configuration

- **Table source** (`source`) — la table à exporter. **Colonnes source** (`source_columns`) liste les colonnes écrites.
- **Fichier de sortie** (`output_file`) — le compte de documents et le chemin du fichier. L'extension détermine le format : `.shp` (shapefile ESRI), `.geojson` ou `.json` (GeoJSON), `.gpkg` (GeoPackage), `.kml`, `.gml`, ou `.tab` et `.mif` (MapInfo). Un format composé de plusieurs fichiers, comme un shapefile, est écrit avec ses fichiers associés à côté.
- **Colonne de géométrie** (`geometry_column`) — la colonne contenant la géométrie de chaque entité en WKT. La valeur par défaut est `SpatialObj`.
- **Système de coordonnées** (`crs`) — le système de coordonnées de référence des géométries, par exemple `EPSG:4326`, écrit avec le fichier.
- **Un fichier qui existe déjà** (`if_exists`) — **L'écraser** (`overwrite`, par défaut) remplace un fichier déjà présent ; **Faire échouer l'étape sans rien écrire** (`fail`) arrête l'étape avant toute écriture.
