## Description

Importe une entité SAP S/4HANA Cloud dans une table de projet, via votre [connexion S/4HANA Cloud](/fr/guides/connections/s4hana-cloud/). Choisissez la connexion, le type d'entité et les filtres éventuels. L'étape récupère les enregistrements correspondants et les écrit, sans requête OData à rédiger.

Il s'agit d'une étape générique prédéfinie : un seul type d'étape couvre deux entités, un cube agrégé `trial_balance` pour le reporting de fin de période et `journal_entry_items`, au niveau des lignes, pour le détail des transactions comptabilisées.

## Configuration

| Champ | Obligatoire | Remarques |
|---|---|---|
| Connexion S/4HANA | Oui | Connexion S/4HANA Cloud à utiliser pour la lecture. |
| Table cible | Oui | Table de projet dans laquelle les résultats sont écrits. Elle est entièrement écrasée à chaque exécution. |
| Type d'entité | Oui | Entité à importer. Valeur par défaut : `trial_balance`. Valeurs possibles : `trial_balance`, `journal_entry_items`. |
| Filtres | Non | Filtres de plage et d'égalité traduits dans le `$filter` OData de la requête. Chaque entité limite les filtres aux champs que S/4HANA peut réellement évaluer côté serveur : un champ non pris en charge est rejeté, et non ignoré silencieusement. |

### Entités et champs filtrables

| Type d'entité | Données importées | Service OData | Champs filtrables |
|---|---|---|---|
| `trial_balance` | Soldes agrégés de fin de période des comptes du grand livre | `API_OPLACCTGDOCITEMCUBE_SRV` | `CompanyCode`, `GLAccount`, `CostCenter`, `ProfitCenter`, `FiscalYear` (plage), `FiscalPeriod` (plage), `Ledger` |
| `journal_entry_items` | Lignes d'écritures comptabilisées | `API_JOURNALENTRYITEMBASIC_SRV` | `CompanyCode`, `GLAccount`, `CostCenter`, `ProfitCenter`, `PostingDate` (plage), `FiscalYear` (plage), `FiscalPeriod` (plage), `Ledger` |

<Aside type="note">
`PostingDate`, `FiscalYear` et `FiscalPeriod` acceptent des filtres de **plage** (bornes de type `ge`/`le`). C'est le principal moyen de délimiter une extraction de `journal_entry_items`, car une extraction sans borne du détail des lignes peut être très volumineuse. Définissez au moins une borne sur une grande entité avant de l'exécuter sur des données de production.
</Aside>

<Aside type="caution">
`CostCenter` et `ProfitCenter` ne sont filtrables que si votre scénario de communication les expose. Une dimension qui ne fait pas partie de ce scénario est rejetée comme filtre non pris en charge, et non ignorée silencieusement.
</Aside>
