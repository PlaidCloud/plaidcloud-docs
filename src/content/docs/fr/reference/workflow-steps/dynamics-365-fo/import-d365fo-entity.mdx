## Description

Importe une entité Dynamics 365 Finance & Operations via votre [connexion D365 F&O](/fr/guides/connections/dynamics-365-fo/) dans une table de projet. Choisissez la connexion, le type d'entité, le mode de synchronisation et les éventuels filtres ; l'étape récupère les enregistrements correspondants et les écrit, sans requête OData à rédiger.

Il s'agit d'une étape prédéfinie générique : un seul type d'étape couvre six entités, des données de base et de référence (comptes principaux, devises, clients, fournisseurs, produits diffusés) aux enregistrements transactionnels (en-têtes de journal du grand livre), soit par un appel OData direct, soit par une extraction en bloc DMF asynchrone.

## Configuration

| Champ | Obligatoire | Remarques |
|---|---|---|
| Connexion D365 F&O | Oui | La connexion D365 F&O par laquelle lire. |
| Table cible | Oui | La table de projet dans laquelle les résultats sont écrits. Elle est entièrement écrasée à chaque exécution. |
| Type d'entité | Oui | L'entité à récupérer. `main_accounts` par défaut. L'une des valeurs `main_accounts`, `currencies`, `customers`, `vendors`, `released_products`, `ledger_journal_headers`. |
| Mode de synchronisation | Oui | `odata` par défaut. `odata` appelle directement le point de terminaison OData standard de l'entité. `dmf` soumet une tâche d'exportation asynchrone Data Management Framework et télécharge le résultat une fois celle-ci terminée, pour les extractions trop volumineuses ou trop lentes avec la simple pagination OData. |
| Filtres | Non | Filtres de plage et d'égalité traduits dans le `$filter` OData de la requête. Chaque entité limite les filtres aux champs que D365 F&O peut réellement évaluer côté serveur : un champ non pris en charge est rejeté, pas ignoré en silence. |

### Entités et champs filtrables

| Type d'entité | Ce qu'elle récupère | Champs filtrables |
|---|---|---|
| `main_accounts` | Plan comptable | plage de comptes, dimension |
| `currencies` | Données de base des devises | — |
| `customers` | Données de base des clients | plage de comptes |
| `vendors` | Données de base des fournisseurs | plage de comptes |
| `released_products` | Données de base des produits diffusés | — |
| `ledger_journal_headers` | En-têtes de journal, comptabilisés ou non | plage de dates, plage de comptes, dimension |

<Aside type="note">
Les filtres de **plage** de dates, de comptes et de dimensions (bornes de style `ge`/`le`) sont le principal moyen de délimiter une extraction de `ledger_journal_headers` : une extraction non bornée de l'historique des transactions peut être très volumineuse. Définissez au moins une borne sur une grande entité avant d'exécuter l'étape sur des données de production.
</Aside>

<Aside type="caution">
Le mode `dmf` (en bloc) attend une tâche d'exportation asynchrone et est nettement plus lent que le mode `odata` pour la même entité et le même ensemble de filtres. Réservez-le aux extractions trop volumineuses pour un appel OData direct.
</Aside>
