## Description

Importe des fichiers texte JSON depuis PlaidCloud Document.

Pour plus de détails sur les fichiers JSON, consultez le site officiel de JSON : http://json.org/.

Les fichiers JSON ne conservent *pas* l'ordre des colonnes. L'ordre des colonnes du fichier source ne reflète pas nécessairement celui de la table de données importée.

Les importations JSON transitent par un stockage temporaire au lieu de charger tout le document en mémoire, de sorte que les très gros fichiers s'importent sans manquer de mémoire. Les colonnes qui n'apparaissent que tardivement dans un gros document sont incluses dans la table importée. Les objets et tableaux imbriqués sont importés sous forme de texte JSON compact standard, de sorte que les étapes en aval peuvent les analyser avec n'importe quel outil JSON.

## Éléments de configuration propres à l'étape

### Orientation des données JSON

Considérez le jeu de données suivant :

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

Les fichiers JSON peuvent être importés dans l'un des trois formats de données suivants :

* Records : les données sont stockées dans des dictionnaires Python, chaque ligne étant stockée au format \{Column -> Value, …}. Par exemple :


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index : les données sont stockées dans des dictionnaires Python imbriqués, chaque ligne étant stockée au format \{Index -> \{Column -> Value, …},…}. Par exemple :


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split : les données sont stockées dans un seul dictionnaire Python, avec les valeurs stockées dans des listes. Par exemple :


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

Outre les formats ci-dessus, le JSON délimité par des sauts de ligne (NDJSON) est accepté : un objet JSON autonome par ligne, sans tableau englobant. Par exemple :

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### Document entier

Pour conserver intact le JSON de chaque fichier, sélectionnez **Importer chaque fichier comme une ligne contenant tout son document JSON** (`whole_document`) dans **Autres options JSON**. Chaque fichier est alors importé comme une ligne contenant tout son document JSON, avec les nombres conservés tels qu'écrits.

### Dates et horodatages

Un champ est importé comme dates ou horodatages lorsque toutes ses valeurs suivent la même disposition parmi les suivantes :

| Disposition | Dates | Horodatages |
| --- | --- | --- |
| ISO 8601 | `2026-01-23` | `2026-01-23T23:14:00` |
| Mois d'abord | `01-23-2026` ou `01-23-26` | `01-23-2026 11:14:00 PM`, avec une heure sur 12 heures |
| Jour d'abord | `23-01-2026` ou `23-01-26` | `23-01-2026 23:14:00`, avec une heure sur 24 heures |
| Année à deux chiffres d'abord | `99-01-23` | `99-01-23 23:14:00`, avec une heure sur 24 heures |

Toutes les valeurs d'un champ sont lues de la même manière, quel que soit l'ordre des lignes. Un champ dans une autre disposition, comme `01/23/2026` ou `01-23-2026 23:14:00`, est importé comme texte. Il en va de même pour un champ dont les valeurs mélangent plusieurs dispositions, bien que certains mélanges d'années à deux et à quatre chiffres, comme `01-23-2026` et `01-24-26`, interrompent l'importation avec une erreur qui nomme le champ.

#### Lorsqu'une valeur correspond à plusieurs dispositions

`01-03-2026` peut désigner le 3 janvier ou le 1er mars, et `23-01-26` peut désigner le 23 janvier 2026 ou, lu en commençant par l'année, le 26 janvier 2023. Lorsque toutes les valeurs d'un champ correspondent à plusieurs des dispositions ci-dessus, le **Format de date** de l'étape tranche selon son ordre du jour, du mois et de l'année :

* Un choix commençant par Mois/jour lit le mois d'abord : `01-03-2026` correspond au 3 janvier.
* Un choix commençant par Jour/mois ou Abrégé lit le jour d'abord : `01-03-2026` correspond au 1er mars, et `23-01-26` au 23 janvier 2026.
* Avec tout autre Format de date, l'importation s'interrompt avec une erreur qui nomme le champ et les choix qui permettraient de trancher.

Ces choix lisent aussi un horodatage selon l'autre horloge lorsque le jour et le mois de chaque valeur sont inférieurs ou égaux à 12 : un choix Mois/jour lit `01-03-2026 23:14:00` comme le 3 janvier, et un choix Jour/mois ou Abrégé lit `01-03-2026 11:14:00 PM` comme le 1er mars. Tout autre Format de date les lit comme le tableau, jour d'abord avec une heure sur 24 heures et mois d'abord avec une heure sur 12 heures.

Aucun choix de Format de date ne lit l'année à deux chiffres d'abord, de sorte qu'un champ tel que `26-01-23` est importé en commençant par l'année seulement si ses valeurs ne peuvent pas être lues autrement, comme avec `99-01-23`. Écrite avec une année à quatre chiffres, comme `2026-01-23`, une telle date est importée comme ISO 8601.

Un fichier qui contient aussi un horodatage dans un objet ou un tableau imbriqué fait exception : aucune des vérifications ci-dessus ne s'applique, et une valeur qui correspond à plusieurs dispositions peut être lue différemment d'une ligne à l'autre.
