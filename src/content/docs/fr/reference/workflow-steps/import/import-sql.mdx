## Description


Importe le résultat d'une requête SQL exécutée sur une base de données externe dans une table de projet PlaidCloud. La requête s'exécute sur la base de données distante ; seul le jeu de résultats est amené dans PlaidCloud.

Diffère de [Importer les tables de base de données externe](/fr/reference/workflow-steps/import/import-external-database-tables/) en ce que vous écrivez vous-même le SQL, ce qui est utile pour les jointures, filtres ou agrégations complexes que vous voulez faire effectuer par la base de données source avant que les données n'arrivent dans PlaidCloud.

### Détection du type de colonne
Les importations SQL peuvent tenter de deviner le type de données pendant le chargement, ou définir toutes les colonnes sur le type Texte. Définir les types de données dynamiquement peut être plus rapide si les données sont propres, mais peut poser des problèmes dans certaines circonstances.

Par exemple, si la plupart des données semblent numériques mais qu'il y a aussi du texte, l'importation peut tenter de les définir comme numériques, ce qui provoque des problèmes de chargement dus à des types de données incompatibles. Des problèmes peuvent aussi survenir avec un code produit numérique de 16 chiffres, par exemple : les zéros de tête seraient supprimés, ce qui donnerait un nombre au lieu d'un code à 16 chiffres.

Définir toutes les données sur du texte exige en revanche une étape Extract ultérieure pour convertir au type approprié, comme des dates ou des valeurs numériques, toute donnée qui ne devrait pas être du texte.

## Dépannage

| Symptôme | Cause probable |
| --- | --- |
| L'étape a pris nettement plus de temps que d'habitude, jusqu'à une demi-heure de plus environ, sans que rien d'autre ne change dans votre requête, votre connexion ou le volume de données | Le worker d'arrière-plan qui exécutait l'importation a été interrompu en cours de route (un redémarrage ou une éviction côté plateforme, et non un élément de votre workflow), et la plateforme a retenté l'importation de la table pour vous. La nouvelle tentative ne démarre qu'une fois l'interruption détectée, ce qui explique le temps supplémentaire. |
| L'étape s'est quand même terminée avec succès après ce délai | La nouvelle tentative remplace intégralement le contenu de la table ; le résultat est donc le même que pour une seule exécution propre, et il n'y a rien d'autre à vérifier ni à refaire. |
| L'étape échoue avec « has already been attempted and cannot be safely re-run » | Pour une étape Importer depuis SQL, ce refus ne se produit plus : une interruption en cours d'exécution est retentée. Vous le verrez toujours, par conception, pour la [restauration d'une archive de projet](/fr/guides/projects/archive-a-project/#restaurer-une-archive) ou le [chargement d'une dimension](/fr/reference/workflow-steps/dimensions/dimension-load/), où une réexécution créerait un doublon au lieu de remplacer quoi que ce soit. Ouvrez un ticket d'assistance si vous le voyez depuis une étape Importer depuis SQL elle-même.
