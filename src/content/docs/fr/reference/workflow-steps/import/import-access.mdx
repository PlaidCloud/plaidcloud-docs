## Description

Lit un fichier de base de données Microsoft Access depuis un compte de documents et importe ses tables, avec une table de projet par table Access, nommée avec un préfixe de votre choix.

Comme un fichier Access contient plusieurs tables, cette étape importe le fichier dans son ensemble au lieu de mapper les colonnes d'une seule table.

## Éléments de configuration propres à l'étape

### Source

Le fichier de base de données Access situé dans un compte de documents. Le sélecteur de fichiers permet aussi une correspondance par recherche plutôt que par chemin exact, avec une option récursive et une règle pour réconcilier les différences de schéma entre les fichiers correspondants.

### Cible

**Préfixe de table** : ajouté au début du nom de chaque table importée, afin que les tables d'un même fichier restent regroupées et n'entrent pas en collision avec celles d'une autre importation.

### Ignorer si inchangé

Activé par défaut. Une exécution de workflow ignore entièrement l'importation, téléchargement compris, lorsque le fichier source n'a pas changé depuis la dernière exécution et que les tables cibles contiennent toujours les lignes qu'elle a chargées. Une table qui a été vidée est de nouveau importée.

## Lorsque le fichier ne peut pas être lu

L'étape échoue en nommant le fichier et la table qu'elle n'a pas pu lire, au lieu de se terminer en laissant une table vide. Cela se produit lorsque le fichier ne liste aucune table que PlaidCloud peut lire, lorsqu'une table est nommée mais que ses colonnes ne peuvent pas être décrites, ou lorsque la lecture des lignes d'une table échoue ; la cause habituelle est un fichier écrit par une version d'Access plus récente que celle que le lecteur comprend. Convertissez ou réexportez le fichier depuis Access, puis relancez l'importation.

Un fichier dont toutes les tables sont réellement vides s'importe avec succès et signale un avertissement indiquant qu'aucun enregistrement n'a été chargé.
