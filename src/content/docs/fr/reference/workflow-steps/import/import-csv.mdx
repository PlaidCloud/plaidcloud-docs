## Description

Importe des fichiers texte délimités depuis PlaidCloud Document. Cela inclut, sans s'y limiter, les types de délimiteurs suivants :
* virgule (, )
* barre verticale (|)
* point-virgule (; )
* tabulation
* espace ( )
* arobase (@)
* tilde (~)
* deux-points (:)

### Inspecter le fichier source sélectionné

Lorsque vous cliquez sur le bouton *Deviner les paramètres à partir du fichier source*, PlaidCloud ouvre le fichier et l'inspecte pour tenter de déterminer le format des données. Vérifiez toujours
que les paramètres devinés semblent corrects.

<Aside>Si vous sélectionnez un répertoire de fichiers à importer, ou si vous utilisez la recherche, le premier fichier trouvé est utilisé pour la détection</Aside>

Une étape dont le fichier ne produit aucune colonne ne peut pas être enregistrée : l'enregistrement s'interrompt avec le message **Aucune colonne détectée**. Lorsque PlaidCloud n'a pas pu lire le fichier, le message en indique la raison, par exemple une extension inhabituelle pour un fichier délimité, ou un chemin de fichier qui utilise une variable de workflow non définie. Sinon, vérifiez que le délimiteur, le caractère de citation et le caractère d'échappement correspondent au fichier, qu'il s'agit bien d'un fichier texte délimité et qu'il n'est pas vide.

### Format des données

#### Délimiteur
Comme indiqué plus haut, **Inspecter le fichier source sélectionné** tente de déterminer le délimiteur du fichier source. Si vous souhaitez un autre délimiteur, utilisez cette
section pour le spécifier. Vous pouvez choisir dans une liste de délimiteurs standard. Une étape sans délimiteur défini utilise la virgule.
* virgule (, )
* barre verticale (|)
* point-virgule (; )
* tabulation
* espace ( )
* arobase (@)
* tilde (~)
* deux-points (:)

#### Type d'en-tête

Comme les fichiers CSV peuvent contenir ou non des en-têtes, PlaidCloud permet soit d'utiliser les en-têtes, soit de les ignorer, soit d'utiliser l'ordre des colonnes pour déterminer leur alignement.
* **Sans en-tête** : le fichier CSV ne contient pas d'en-tête. Utilisez la liste source du *Data Mapper* pour déterminer l'alignement des colonnes.
* **Avec en-tête : utiliser l'en-tête et remplacer la liste des champs** : le fichier CSV contient un en-tête. Utilisez les noms d'en-tête spécifiés et ignorez la liste source du *Data Mapper*.
* **Avec en-tête : ignorer l'en-tête et utiliser la liste des champs** : le fichier CSV contient un en-tête, mais il doit être ignoré. Utilisez les noms d'en-tête spécifiés par la liste source du *Data Mapper*.

Le **Type d'en-tête** est stocké dans `header_treatment` sous la forme `use` ou `skip` pour les deux options avec en-tête. Importer depuis Excel accepte aussi `dynamic`.

#### Format de date

Ce paramètre est utile lorsque les dates contenues dans le fichier CSV ne sont pas facilement reconnaissables comme des dates et des heures. Le processus d'importation tente de convertir les dates, mais quelques informations supplémentaires
peuvent l'aider.

Une valeur que l'entrepôt ne parvient pas à lire avec le format indiqué est stockée comme vide au lieu d'interrompre l'importation. Un format qui ne correspond pas au fichier
produit donc une colonne de dates vides et une importation qui signale tout de même un succès. Après avoir modifié ce paramètre, vérifiez la colonne importée avant de vous fier au résultat.

<Aside type="caution" title="Colonnes Heure sur Lakehouse v2">
Une colonne dont le type de données est **Heure** est importée comme vide sur Lakehouse v2, quel que soit le format de date que vous fournissez. La fonction de l'entrepôt utilisée pour l'analyser ne peut pas
produire une simple heure de la journée. Importez la colonne en tant qu'**Horodatage** et lisez-en l'heure, ou importez-la en tant que **Texte**. Les colonnes **Date** et **Horodatage**
ne sont pas concernées.
</Aside>

### Caractères spéciaux

Les entrées de caractères spéciaux contrôlent la manière dont PlaidCloud traite la présence de certains caractères et leur signification dans le contexte du traitement du fichier CSV.
 * **Caractère de citation** : le caractère qui délimite un bloc de texte à traiter comme un seul champ. S'il n'est pas défini, il s'agit du guillemet double (`"`).
 * **Caractère d'échappement** : le caractère qui indique que le caractère suivant doit être traité tel quel et non interprété comme un caractère spécial. Utile lorsqu'un champ peut contenir le délimiteur. S'il n'est pas défini, il s'agit de la barre oblique inverse (`\`).
 * **Caractère nul** : comme les fichiers CSV n'ont pas de types de données, ce caractère permet d'indiquer que la valeur doit être NULL plutôt qu'une chaîne vide ou 0.
 * **Champs vides** : un champ vide est chargé comme NULL sur tous les lakehouses, pour les colonnes de texte comme pour les colonnes numériques ; un nombre vide devient donc NULL et non 0. Une cellule qui ne contient que des espaces est chargée telle quelle.
 * **Négatifs en fin de valeur** : certains systèmes sources génèrent des nombres négatifs avec le signe moins à la fin au lieu de le placer en préfixe. Ce paramètre traite ces valeurs comme des nombres négatifs.

### Sélection des lignes

Pour les fichiers d'entrée contenant des enregistrements superflus, définissez **Ignorer les lignes** sur le nombre de lignes à ignorer avant de traiter les données. C'est utile si les fichiers contiennent des blocs d'en-tête à ignorer avant d'arriver aux données tabulaires.

Les lignes ignorées incluent les lignes vides. Avec un **Type d'en-tête** défini sur **Avec en-tête : utiliser l'en-tête et remplacer la liste des champs**, l'en-tête est lu à la première ligne qui suit les lignes ignorées ; les données sont ainsi mappées à vos colonnes cibles par nom d'en-tête. Un fichier qui ne contient que les lignes ignorées et un en-tête, sans aucune ligne de données, n'importe rien, et l'étape se termine tout de même.

#### Exemple : export de liste SAP

Un export de liste SAP tel que KE24, KSB1 ou FAGLL03 commence par un bloc de sélection, souvent accompagné de lignes vides, avant l'en-tête des colonnes :

```text
Line Item Journal Entries
Company Code: 1000
Posting Date: 2026-09-01 to 2026-09-30

Company Code|Document Number|Posting Date|Amount
1000|100004512|2026-09-03|1,500.00
```

L'en-tête se trouve à la ligne 5 ; il y a donc quatre lignes avant lui. Définissez **Ignorer les lignes** sur `4` et le **Type d'en-tête** sur **Avec en-tête : utiliser l'en-tête et remplacer la liste des champs**. L'importation lit `Company Code`, `Document Number`, `Posting Date` et `Amount` comme noms de colonnes, et la première ligne de données est la ligne qui suit l'en-tête.

Sélectionnez **Keep Quoted Empty Fields ("") As Empty String** pour charger un champ vide entre guillemets comme une chaîne vide au lieu de NULL.

### Paramètres supplémentaires

**Autres options CSV** contient les champs suivants :

* **Encodage** (`encoding`) : le codec Python avec lequel le fichier est lu, au lieu de le détecter. Les octets qui ne se décodent pas sont lus comme U+FFFD.
* **Délimiteurs** (`delimiters`) : un tableau JSON de tous les textes qui séparent les colonnes, à la place d'un délimiteur unique. Chacun peut comporter plusieurs caractères. Sélectionnez **Plusieurs délimiteurs consécutifs comptent pour un** (`combine_delimiters`) pour compter plusieurs délimiteurs consécutifs comme un seul.
* **Délimiteur de ligne** (`row_delimiter`) : le texte qui termine une ligne lorsqu'il se trouve en dehors de guillemets ; un saut de ligne ailleurs fait alors partie de la valeur. Si ce champ est vide, tout saut de ligne termine une ligne.
* **Préfixe de ligne de commentaire** (`comment`) : les lignes qui commencent par ce texte ne sont pas importées. **Commentaires** (`comments`) liste les commentaires sous forme de paires **Commence par** et **Se termine par**, qui sont retirées partout où elles se trouvent en dehors de guillemets ; sans **Se termine par**, un commentaire se poursuit jusqu'à la fin de la ligne.
* **Continuation de ligne** (`line_continuation`) : ce texte placé avant un saut de ligne joint la ligne à la suivante.
* **Guillemet fermant** (`quote_end`) : le guillemet qui termine une valeur entre guillemets, lorsqu'il diffère du **Caractère de citation**. Sélectionnez **Une valeur entre guillemets conserve ses guillemets** (`keep_quotes`) pour conserver les guillemets d'une valeur entre guillemets.
* **Importer une ligne vide comme une ligne de valeurs vides** (`keep_blank_lines`) : une ligne vide est importée comme une ligne de valeurs vides au lieu d'être omise.
