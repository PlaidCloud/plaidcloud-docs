## Description

Lit une ou plusieurs listes Anaplan via votre [connexion Anaplan](/fr/guides/connections/anaplan/) et les charge dans une dimension PlaidCloud. **Une seule étape lit toute une hiérarchie composite** : nommez toutes les listes qu'elle couvre, en commençant par la racine (par exemple Région, puis Pays, puis Magasin), plutôt que de la répartir sur plusieurs étapes. La table intermédiaire est entièrement remplacée à chaque exécution ; plusieurs étapes pointant vers une même table intermédiaire effaceraient donc chacune les lignes de la précédente.

Cette étape apparaît dans le menu des étapes sous **Anaplan**, avec le libellé **Lecture de listes**.

L'étape atteint Anaplan en **direct depuis le cloud** via son API d'intégration ; il n'existe aucun chemin passant par un agent sur site.

<Aside type="tip">
Ce connecteur est en lecture seule et s'authentifie avec des identifiants Basic (nom d'utilisateur et mot de passe) ou un certificat d'AC ; consultez [Authentification](/fr/guides/connections/anaplan/#authentification). Le budget de requêtes d'Anaplan est partagé à l'échelle du locataire ; échelonnez donc la planification de cette étape par rapport à vos autres workflows Anaplan ; consultez [Points à considérer pour la planification](/fr/guides/connections/anaplan/#considérations-sur-la-planification).
</Aside>

## Configuration

### Source Anaplan

| Champ | Obligatoire | Remarques |
|---|---|---|
| Connexion Anaplan | Oui | La [connexion Anaplan](/fr/guides/connections/anaplan/) à utiliser pour la lecture. |
| Environnement | Non | **Environnement du projet** (par défaut) utilise l'environnement de connexion du projet. **Environnement fixe** utilise toujours celui que vous choisissez. Voir [Fixer une étape à un environnement](/fr/guides/projects/managing-projects/#fixer-une-étape-à-un-environnement). |
| Modèle | Non | Remplace l'ID de modèle enregistré sur la connexion. Détecté en direct depuis la connexion, ou saisi à la main. |
| Listes | Oui | Toutes les listes Anaplan que couvre la hiérarchie, sous forme de liste ordonnée. Ajoutez des listes détectées à partir du modèle choisi, ou saisissez un ID à la main, puis réordonnez avec Monter / Descendre. Les lister en commençant par la racine est plus lisible, mais l'ordre ne change pas ce qui est chargé : toutes les listes sont lues avant la résolution de tout parent. |
| Table intermédiaire | Oui | Les lignes brutes de parent/enfant/consolidation/nom et de propriétés sont chargées ici avant que la dimension PlaidCloud n'en soit construite. |

### Dimension PlaidCloud cible

| Champ | Obligatoire | Remarques |
|---|---|---|
| Spécifier la dimension dynamiquement | L'un des deux | Nom de la dimension cible, pouvant contenir des jetons `{variable}` résolus à l'exécution. Sélectionné par défaut. |
| Utiliser une dimension spécifique | L'un des deux | Choisissez plutôt une dimension PlaidCloud existante. |

## Aperçu

**Aperçu** dans l'onglet **Source** affiche les colonnes et les types de données que produirait cette lecture de liste, sans exécuter l'étape. Il n'est pas disponible sur un projet verrouillé.

## Ce que cette étape ne peut pas représenter

| Limite | Signification |
|---|---|
| Chaque lien se consolide avec un simple `+` | Les hiérarchies de listes Anaplan ne portent ni poids ni signe par lien : il n'y a rien à lire, donc rien n'est perdu à la traduction, mais rien de plus ne peut être représenté non plus. Si un modèle exprime des exclusions ou des consolidations négatives par un élément de ligne ou une propriété, cette logique n'est pas reportée dans la dimension et doit être reconstruite en aval. |
| Les indicateurs de contrôle d'accès et l'appartenance aux sous-ensembles ne sont pas importés | Les indicateurs de lecture/écriture de l'accès sélectif et l'appartenance de chaque élément aux sous-ensembles de listes sont des métadonnées Anaplan, et non des données de dimension : importer chaque sous-ensemble comme sa propre colonne entrerait sinon en collision avec de véritables propriétés dans un espace de noms partagé en expansion. Une véritable propriété de liste dont le nom entre en collision avec l'un ou l'autre est refusée plutôt que chargée silencieusement sous le nom de l'autre. |
| Les sous-ensembles d'éléments de ligne ne sont pas lisibles comme dimensions | Anaplan les expose uniquement via un point de terminaison générique d'éléments de dimension, et non comme une liste que cette étape peut lire. |
| Une liste de plus de 1 000 000 d'enregistrements ne peut pas être lue par ce chemin | Le point de terminaison d'éléments que cette étape lit refuse net au-delà de ce plafond documenté plutôt que de renvoyer un résultat partiel, et n'offre aucun moyen de paginer pour le contourner ; l'étape refuse donc et nomme le plafond plutôt que de charger une dimension partielle. En attendant, scindez la liste dans Anaplan ou lisez-en un sous-ensemble. |
| Un nœud se trouve sous exactement un parent | Un élément dont le nom de parent et l'ID de parent ne concordent pas, dont le parent se trouve dans une liste que cette étape ne lit pas, ou dont le parent nommé n'existe pas du tout, est refusé nommément plutôt que rattaché silencieusement à la racine de la dimension. |
| L'élément de premier niveau d'une liste n'est pas importé | L'élément de premier niveau d'Anaplan est un nœud de consolidation qui se situe au-dessus de tous les éléments de la liste plutôt que d'être un élément de la liste elle-même ; il n'est donc jamais renvoyé par les éléments que cette étape lit. La dimension se retrouve avec un niveau de moins que la liste Anaplan, et les racines propres à la liste deviennent les racines de la dimension. L'étape avertit lorsqu'une liste que vous lisez en déclare un. |
| Les ID de nœud doivent être uniques dans toutes les listes lues ensemble | L'ID d'un nœud est le code Anaplan de l'élément, ou son nom s'il n'en a pas ; or un code Anaplan n'est garanti unique qu'au sein d'une seule liste. Deux listes qui réutilisent les mêmes codes courts sont refusées nommément plutôt que fusionnées silencieusement en un seul nœud. |
| Les hiérarchies alternatives ne sont pas prises en charge | Chaque liste est chargée dans la hiérarchie principale de la dimension. |
| Lecture seule | Rien n'est jamais réécrit dans Anaplan. |
