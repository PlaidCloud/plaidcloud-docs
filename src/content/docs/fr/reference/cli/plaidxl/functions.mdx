PlaidXL ajoute à Excel des fonctions qui lisent les données PlaidCloud directement dans les cellules. Saisissez `=PLAIDXL.` dans une cellule et la saisie semi-automatique d'Excel les liste, avec une courte description de chaque argument. L'onglet **Formulas** du volet des tâches peut aussi écrire une formule à votre place ; consultez [Insérer une formule depuis le volet des tâches](#insérer-une-formule-depuis-le-volet-des-tâches).

| Groupe | Fonctions | Utilisez-les pour |
|---|---|---|
| Listes | [`LIST_PROJECTS`](#list_projects), [`TABLE.TBL_LIST`](#tbl_list), [`TABLE.GET_COLUMNS`](#get_columns), [`DIMENSION.DIM_LIST`](#dim_list) | Voir ce qui est disponible pour construire vos rapports |
| Tables | [`TABLE.GET_TABLE`](#get_table) | Lire une table entière dans une plage |
| Hiérarchies | [`DIMENSION.GET_DIMENSION`](#get_dimension), [`DRILL`](#drill) | Présenter les nœuds d'une dimension sous forme de lignes de rapport |
| Valeurs | [`CELL`](#cell), [`CELLS`](#cells) | Calculer une valeur consolidée pour n'importe quelle combinaison de nœuds |
| Blocs de construction | [`REPR.TABLE_REPR`](#table_repr), [`REPR.MEASURE`](#measure), [`REPR.MEASURES`](#measures), [`REPR.MEASURE_TYPE`](#measure_type), [`REPR.DIMENSION_REPR`](#dimension_repr), [`REPR.DRILL_KEY`](#drill_key) | Décrire la table, la mesure, l'agrégation, les nœuds et la profondeur d'exploration que `CELL`, `CELLS` et `DRILL` utilisent |

[Créer un rapport avec des fonctions personnalisées](/fr/reference/cli/plaidxl/build-a-report/) montre ces fonctions à l'œuvre ensemble.

## Fonctionnement des fonctions

- **Connectez-vous d'abord.** Les fonctions lisent les données avec votre connexion PlaidCloud ; [connectez-vous](/fr/reference/cli/plaidxl/connect/) donc depuis le volet des tâches avant de les utiliser.
- **Elles lisent le projet du classeur.** Chaque fonction lit le projet lié au classeur dans le volet des tâches. `GET_TABLE`, `TBL_LIST` et `DIM_LIST` acceptent aussi un ID de projet facultatif, pour lire un autre projet sans modifier le lien. Chaque classeur a son propre projet : deux classeurs ouverts peuvent donc lire des projets différents.
- **Les résultats se déversent.** Une fonction qui renvoie une liste ou une table remplit les cellules situées en dessous (ou à droite). Laissez la place nécessaire aux résultats ; si quelque chose gêne, Excel affiche une erreur `#SPILL!`.
- **Recalculez pour prendre en compte les changements.** Une formule PlaidXL récupère de nouveau les données lorsqu'un de ses arguments change. Pour obtenir les nouvelles données de PlaidCloud, ou un autre projet lié dans le volet des tâches, forcez un recalcul complet — sous Windows, appuyez sur **Ctrl+Alt+F9**. **Refresh All Tables** actualise les tables récupérées, pas les formules.
- **Utilisez les noms exacts.** Saisissez les noms de tables, de colonnes, de dimensions et de nœuds exactement comme ils apparaissent dans PlaidCloud.

Les arguments entre crochets sont facultatifs.

## Listes

### LIST_PROJECTS

`=PLAIDXL.LIST_PROJECTS([horizontal])`

Liste les noms des projets que vous pouvez ouvrir, triés par nom.

- `horizontal` — `TRUE` pour lister sur une ligne. La valeur par défaut est `FALSE`, soit une colonne.

### TBL_LIST

`=PLAIDXL.TABLE.TBL_LIST([project_id], [horizontal])`

Liste les noms des tables d'un projet, triés par nom.

- `project_id` — le projet à lire. Par défaut, le projet du classeur.
- `horizontal` — `TRUE` pour lister sur une ligne. La valeur par défaut est `FALSE`, soit une colonne.

### GET_COLUMNS

`=PLAIDXL.TABLE.GET_COLUMNS(table_name, [column_filter], [orientation])`

Liste les noms des colonnes d'une table du projet sélectionné.

- `table_name` — le nom de la table dans PlaidCloud.
- `column_filter` — un type de données, tel que `"text"`, pour ne lister que les colonnes de ce type. Omettez-le pour lister toutes les colonnes.
- `orientation` — `"vertical"` (valeur par défaut) pour une colonne, ou `"horizontal"` pour une ligne.

### DIM_LIST

`=PLAIDXL.DIMENSION.DIM_LIST([project_id], [horizontal])`

Liste les noms des dimensions d'un projet.

- `project_id` — le projet à lire. Par défaut, le projet du classeur.
- `horizontal` — `TRUE` pour lister sur une ligne. La valeur par défaut est `FALSE`, soit une colonne.

## Tables

### GET_TABLE

`=PLAIDXL.TABLE.GET_TABLE(table_name, [project_id], [limit])`

Renvoie les lignes d'une table avec une ligne d'en-tête, déversées à partir de la cellule de la formule. Les valeurs vides sont renvoyées sous forme de cellules vides.

- `table_name` — le nom de la table dans PlaidCloud.
- `project_id` — le projet à lire. Par défaut, le projet du classeur.
- `limit` — le nombre maximal de lignes à renvoyer. La valeur par défaut est 1 048 575, le maximum que contient une feuille de calcul sous une ligne d'en-tête.

`GET_TABLE` renvoie toutes les colonnes. Pour choisir des colonnes ou filtrer des lignes, [récupérez plutôt la table depuis le volet des tâches](/fr/reference/cli/plaidxl/retrieve/#récupérer-une-table).

## Hiérarchies

### GET_DIMENSION

`=PLAIDXL.DIMENSION.GET_DIMENSION(dimension_name, start_node, [hierarchy], [orientation], [generation_limit])`

Présente les nœuds d'une dimension, en partant de `start_node` et en descendant dans ses descendants. Chaque génération est décalée de quatre espaces de plus que son parent, et les groupes de plan d'Excel permettent de réduire et de développer chaque niveau.

- `dimension_name` — le nom de la dimension, ou son chemin dans le projet.
- `start_node` — le nœud de départ, tel que la racine de la dimension.
- `hierarchy` — la [hiérarchie alternative](/fr/guides/dimensions/dimensions/#hiérarchies-alternatives-dattributs) à suivre. La valeur par défaut est `"main"`.
- `orientation` — `"vertical"` (valeur par défaut) pour lister les nœuds dans une colonne, ou `"horizontal"` pour les lister sur une ligne.
- `generation_limit` — le nombre de générations à renvoyer, `start_node` comptant pour la première : `2` renvoie le nœud de départ et ses enfants. Omettez-le pour renvoyer toutes les générations.

### DRILL

`=PLAIDXL.DRILL(dimension_name, start_node, drill_key, [hierarchy])`

Renvoie `start_node` et les nœuds situés en dessous que `drill_key` demande, dans une colonne, avec un retrait par génération et regroupés dans un plan Excel.

- `dimension_name` — le nom de la dimension, ou son chemin dans le projet.
- `start_node` — le nœud à partir duquel explorer.
- `drill_key` — la profondeur d'exploration, issue de [`DRILL_KEY`](#drill_key) : tous les descendants, seulement les feuilles, un nombre de niveaux, ou une plage de générations.
- `hierarchy` — la hiérarchie alternative à suivre. La valeur par défaut est `"main"`.

Par exemple, `=PLAIDXL.DRILL("Region", "Total", PLAIDXL.REPR.DRILL_KEY("leaves"))` liste **Total**, suivi de chaque région feuille située en dessous.

Les [commandes de développement du ruban](/fr/reference/cli/plaidxl/ribbon/#drill-functions) font la même chose pour une dimension et un nœud saisis dans deux cellules, sans écrire de formule.

## Valeurs

`CELL` et `CELLS` calculent une mesure — une colonne numérique d'une table — consolidée selon les nœuds que vous choisissez dans une ou plusieurs dimensions. Considérez chaque appel comme une intersection d'un rapport : le **Chiffre d'affaires** de **EMEA** en **FY2026**.

Vous décrivez l'intersection avec les fonctions de blocs de construction ci-dessous, généralement dans leurs propres cellules, puis vous passez ces cellules à `CELL` ou `CELLS` dans n'importe quel ordre :

| Argument | Construit avec | Obligatoire |
|---|---|---|
| La table à lire | [`TABLE_REPR`](#table_repr) | Exactement un |
| La colonne à agréger | [`MEASURE`](#measure) pour `CELL`, [`MEASURES`](#measures) ou plusieurs cellules `MEASURE` pour `CELLS` | Oui |
| Comment l'agréger | [`MEASURE_TYPE`](#measure_type) | Non — `sum` par défaut |
| Un filtre sur une colonne | [`DIMENSION_REPR`](#dimension_repr) | Au moins un, un par colonne |

Chaque filtre désigne une **colonne de la table** et une valeur. Lorsque cette colonne est liée à une dimension dans PlaidCloud, la valeur est un nœud, et le filtre inclut tout ce qui se consolide vers ce nœud dans la hiérarchie principale de la dimension — sur une colonne **Région** liée à une dimension géographique, le nœud **EMEA** couvre tous les pays situés en dessous. Sur une colonne qui n'est pas liée à une dimension, le filtre correspond exactement à la valeur.

Les exemples de cette page utilisent une table dont les colonnes **Région** et **Période** sont liées à des dimensions. Utilisez les noms de colonnes de votre propre table.

### CELL

`=PLAIDXL.CELL(table, measure, [measure_type], node, [node], ...)`

Renvoie un seul nombre : la mesure, agrégée sur les lignes qui relèvent de chaque nœud que vous passez.

```text
A1  =PLAIDXL.REPR.TABLE_REPR("Sales")
A2  =PLAIDXL.REPR.MEASURE("revenue")
A3  =PLAIDXL.REPR.MEASURE_TYPE("sum")
A4  =PLAIDXL.REPR.DIMENSION_REPR("Region", "EMEA")
A5  =PLAIDXL.REPR.DIMENSION_REPR("Period", "FY2026")
B1  =PLAIDXL.CELL(A1, A2, A3, A4, A5)
```

`B1` affiche le chiffre d'affaires total de EMEA en FY2026.

Une feuille remplie de formules `CELL` nécessite moins de recherches par cellule, car PlaidXL réutilise pendant un court laps de temps les détails des colonnes de la table au lieu de les récupérer pour chaque cellule. Si une valeur ne peut pas être calculée, la cellule affiche `#VALUE!` et le survol de la cellule affiche la raison telle que PlaidCloud l'a signalée, par exemple une colonne de filtre absente de la table ou un nœud sans membres. `CELLS` affiche la première raison pour l'ensemble du résultat.

### CELLS

`=PLAIDXL.CELLS(table, measures, [measure_type], node, [node], ...)`

Comme `CELL`, mais pour plusieurs mesures à la fois. Renvoie un nombre par mesure, dans une colonne, dans l'ordre où vous les avez listées.

```text
D1:F1  revenue | cost | units
D2     =PLAIDXL.REPR.MEASURES(D1:F1)
B2     =PLAIDXL.CELLS(A1, D2#, A3, A4, A5)
```

`D2#` passe l'intégralité du résultat déversé de `MEASURES`. `B2:B4` affichent le chiffre d'affaires, le coût et les unités de EMEA en FY2026.

## Blocs de construction

Ces fonctions ne lisent pas de données elles-mêmes. Chacune renvoie un court texte qui décrit une partie d'un calcul, prêt à être passé à `CELL`, `CELLS` ou `DRILL`. Placez-les dans des cellules que vous référencez, afin qu'une seule modification — une autre période, par exemple — mette à jour toutes les formules qui les utilisent.

### TABLE_REPR

`=PLAIDXL.REPR.TABLE_REPR(table_name)`

La table que `CELL` et `CELLS` lisent, par son nom dans le projet sélectionné.

### MEASURE

`=PLAIDXL.REPR.MEASURE(column_name)`

La colonne numérique que `CELL` agrège.

### MEASURES

`=PLAIDXL.REPR.MEASURES(column_names)`

Plusieurs colonnes de mesure pour `CELLS`, à partir d'une plage de cellules contenant des noms de colonnes. Le résultat se déverse sur une cellule par colonne ; passez-le à `CELLS` avec l'opérateur de déversement, tel que `D2#`.

### MEASURE_TYPE

`=PLAIDXL.REPR.MEASURE_TYPE(agg_function)`

Comment agréger la mesure. `agg_function` est l'une des valeurs suivantes, en minuscules :

| Valeur | Renvoie |
|---|---|
| `sum` | Le total (valeur par défaut lorsque vous ne passez pas de type de mesure) |
| `mean` | La moyenne |
| `median` | La valeur médiane |
| `min` | La plus petite valeur |
| `max` | La plus grande valeur |
| `std` | L'écart type |
| `var` | La variance |

### DIMENSION_REPR

`=PLAIDXL.REPR.DIMENSION_REPR(dimension_name, start_node)`

Un filtre pour `CELL` et `CELLS`. Passez-en un pour chaque colonne selon laquelle vous voulez filtrer.

- `dimension_name` — le nom d'une **colonne de la table** — la colonne qui contient les valeurs de la dimension, telle que `"Region"`. Il doit correspondre exactement au nom de la colonne ; une colonne absente de la table renvoie une erreur.
- `start_node` — le nœud vers lequel consolider, tel que `"EMEA"`. Sur une colonne qui n'est pas liée à une dimension, la valeur à faire correspondre.

Référencez une cellule pour le nœud afin de construire une grille : `=PLAIDXL.REPR.DIMENSION_REPR("Region", $A7)`. Les espaces de début et de fin sont ignorés, vous pouvez donc la faire pointer vers les noms de nœuds en retrait que `DRILL` présente.

### DRILL_KEY

`=PLAIDXL.REPR.DRILL_KEY(d_key)`

La profondeur à laquelle [`DRILL`](#drill) descend sous son nœud de départ. `d_key` est du texte brut, soit une forme littérale, soit une clé d'exploration écrite explicitement :

| `d_key` | Explore jusqu'à |
|---|---|
| `"all"` | Tous les descendants |
| `"leaves"` | Seulement les feuilles, c'est-à-dire les nœuds sans rien en dessous |
| `"1 level"`, `"2 levels"`, … | Ce nombre de générations vers le bas |
| `">[...]"` | La clé d'exploration écrite explicitement, comme dans le tableau suivant |

Écrivez le nombre en chiffres : `"2 levels"`, et non `"two levels"`. Un `drill` en tête est ignoré, donc `"drill 2 levels"` fonctionne aussi.

Une clé écrite explicitement compte les générations vers le bas à partir du nœud de départ, qui est la génération 0 et toujours inclus. Les nombres négatifs comptent vers le haut à partir des feuilles de chaque branche, de sorte qu'une hiérarchie irrégulière fonctionne comme vous l'attendez.

| Clé | Inclut |
|---|---|
| `>[*]` ou `>[:]` | Tous les nœuds |
| `>[]` ou `>[-1]` | Seulement les feuilles |
| `>[n]` | Le nœud de départ et `n` générations en dessous. `>[0]` est le nœud de départ seul. |
| `>[a:]` | Le nœud de départ, puis la génération `a` et tout ce qui est en dessous |
| `>[a:b]` | Le nœud de départ, puis les générations `a` à `b - 1` |
| `>[0:-k]` | Le nœud de départ et chaque nœud qui a au moins `k` générations en dessous, de sorte que les `k` dernières générations de chaque branche sont exclues. `>[0:-1]` correspond à tous les nœuds sauf les feuilles. |
| `>[a:-k]` | Idem, en partant de la génération `a` |

Pour la hiérarchie `A`, avec les enfants `B`, `C` et `D`, où `B` a `B1` et `B2` et `C` a `C1` :

| Clé | Résultat |
|---|---|
| `>[1]` | `A`, `B`, `C`, `D` |
| `>[2]` | `A`, `B`, `B1`, `B2`, `C`, `C1`, `D` |
| `>[]` | `A`, `B1`, `B2`, `C1`, `D` |
| `>[0:-1]` | `A`, `B`, `C` |
| `>[2:]` | `A`, `B1`, `B2`, `C1` |

Les nœuds sont listés dans l'ordre de la hiérarchie, chacun sous son propre parent, et les groupes de plan Excel suivent le même ordre. Les espaces à l'intérieur d'une clé sont ignorés. Une clé qui ne correspond à aucune de ces formes renvoie une erreur qui liste les formes valides.

<Aside type="caution">
`>[-1]` et `>[0:-1]` ont un sens différent de celui des versions antérieures de PlaidXL, où ils étaient inversés. `>[-1]` renvoie désormais uniquement les feuilles, et `>[0:-1]` tout sauf les feuilles. Vérifiez tout classeur dans lequel une clé d'exploration a été écrite à la main. Les formes littérales `"all"`, `"leaves"` et `"2 levels"` sont inchangées.
</Aside>

<Aside type="note">
`CELL`, `CELLS` et `DRILL` attendent le résultat de ces fonctions de blocs de construction. Construisez chaque argument avec sa fonction plutôt que de saisir le texte vous-même.
</Aside>

## Insérer une formule depuis le volet des tâches

L'onglet **Formulas** du volet des tâches écrit une formule à votre place. Sous **What do you want in the cell?**, choisissez l'une des options suivantes :

- **A whole table** (`GET_TABLE`) — sélectionnez ou saisissez la table, et éventuellement un nombre maximal de lignes.
- **One number** (`CELL`) — sélectionnez ou saisissez la table, puis choisissez la **Column to total** et **How to combine the values**.
- **A list of dimension nodes** (`DRILL`) — sélectionnez ou saisissez la dimension et le nœud de départ, choisissez **All levels**, **Lowest level only** ou **Down** un nombre de **levels**, et éventuellement une **Alternate hierarchy**.

L'aperçu **Formula** affiche le résultat à mesure que vous remplissez les champs. Cliquez sur **Insert in active cell** pour l'insérer dans la cellule sélectionnée, ou sur **Copy** pour la coller vous-même. Le choix d'une table dans l'onglet **Tables** ou d'une dimension dans l'onglet **Dimensions** renseigne le champ correspondant.
