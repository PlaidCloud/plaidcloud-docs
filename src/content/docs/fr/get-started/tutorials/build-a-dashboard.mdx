*~30 minutes · une table publiée, un graphique, un tableau de bord partagé*

Vous disposez d'une table propre publiée depuis un workflow. Ce tutoriel la transforme en quelque chose que l'on peut lire d'un coup d'œil : un graphique, puis un tableau de bord construit autour de lui, puis un tableau de bord partagé avec les bonnes personnes. Aucun SQL n'est nécessaire pour afficher un premier graphique — vous pointez, cliquez et interrogez.

Si vous avez suivi [Charger, transformer et publier des données](/fr/get-started/tutorials/load-and-transform-data/), la table `sales_final` que vous y avez publiée est exactement le point de départ que suppose ce tutoriel. N'importe quelle table publiée convient tout aussi bien.

## Ce que vous allez construire

Un seul tableau de bord avec deux graphiques sur une même table publiée — un Big Number affichant le chiffre d'affaires total et un histogramme ventilant le chiffre d'affaires selon une colonne de regroupement — mis en forme, enregistré et visible par votre espace de travail.

## Prérequis

- Un espace de travail PlaidCloud et un projet que vous pouvez ouvrir.
- Une table **publiée** dans ce projet. Si vous n'en avez pas, suivez d'abord [Charger, transformer et publier des données](/fr/get-started/tutorials/load-and-transform-data/), ou publiez n'importe quelle table existante — faites un clic droit dessus dans l'onglet **Tables** et choisissez **Set Published Table Reporting Name**. Consultez [Publier des tables](/fr/guides/data/publish/).
- Rien à installer dans la zone Tableaux de bord — votre compte de tableaux de bord est créé automatiquement la première fois que vous ouvrez un tableau de bord depuis PlaidCloud.

> **Seules les tables publiées parviennent aux tableaux de bord.** Un tableau de bord lit une table d'après son nom de reporting publié, et non son nom de table interne. Si votre table n'apparaît pas ensuite comme jeu de données, la cause habituelle est qu'elle n'a jamais été publiée, ou qu'elle a été publiée sous un nom que vous ne reconnaissez pas — vérifiez la colonne **Publié sous** dans l'onglet **Tables**.

## Étape 1 : ouvrir la zone Tableaux de bord

1. Depuis votre projet dans PlaidCloud, ouvrez la zone **Tableaux de bord**.
2. La première fois, votre compte de tableaux de bord est configuré automatiquement — il n'y a rien à créer à la main. Ce que vous pouvez voir découle de votre appartenance à l'espace de travail et de vos groupes de sécurité.
3. Votre table publiée est désormais disponible comme **jeu de données**, car elle appartient à un projet auquel vous avez accès.

Pour savoir comment la visibilité des tableaux de bord dépend de l'appartenance à l'espace de travail, consultez [Utiliser les tableaux de bord](/fr/guides/dashboards/using-dashboards/).

## Étape 2 : préparer le jeu de données

Avant de créer un graphique, indiquez au tableau de bord comment chaque colonne doit se comporter. Il s'agit d'une configuration unique par table qui permet à l'explorateur en pointer-cliquer de bien fonctionner.

1. Cliquez sur l'icône de modification de votre jeu de données.
2. Ouvrez l'onglet **List Columns**.
3. Pour chaque colonne, définissez les rôles qui s'appliquent, puis cliquez sur **Enregistrer** :

| Paramètre | À activer quand |
|---|---|
| **Groupable** | Vous voulez ventiler les métriques selon ce champ (région, produit, mois) |
| **Filterable** | Vous voulez filtrer sur ce champ |
| **Somme** / **Min** / **Max** | C'est une mesure numérique que vous allez totaliser ou résumer |
| **Count Distinct** | Vous voulez compter les valeurs uniques de ce champ |
| **Is temporal** | C'est un champ de date ou d'heure |

> **Marquez votre colonne de date comme temporelle.** Les filtres temporels et les contrôles « Since / Until » de l'explorateur ne fonctionnent que sur une colonne marquée **Is temporal**. C'est le paramètre le plus facile à oublier.

## Étape 3 : créer votre premier graphique

Commencez dans l'explorateur, qui s'ouvre sous forme de Table View simple, et transformez-le en Big Number pour le chiffre d'affaires total.

> **Utilisez votre propre colonne de mesure.** Ce tutoriel représente une colonne `revenue`, mais le seul prérequis est « n'importe quelle table publiée » — partout où vous voyez `revenue`, remplacez-la par la colonne numérique que vous souhaitez réellement totaliser (`amount`, `sales`, `quantity`, etc.).

1. Cliquez sur le jeu de données pour l'ouvrir. Par défaut, vous obtenez une **Table View**.
2. Dans la section des métriques, ajoutez la mesure souhaitée — pour un total cumulé, saisissez-la et choisissez votre colonne sommée (par exemple un `SUM` de `revenue`), ou utilisez **COUNT(\*)** pour compter les lignes.
3. Ajoutez les champs **Regrouper par** selon lesquels vous voulez ventiler le nombre. Pour un seul chiffre clé, laissez Regrouper par vide.
4. Cliquez sur **Requête** pour l'exécuter et voir le résultat.
5. Faites défiler jusqu'à **Chart Options** (ou le sélecteur de type de visualisation) et passez le type de graphique à **Big Number**. Les graphiques peuvent être des Tables, des Big Numbers, des Bar Charts, etc. — chacun affiche différemment le même résultat interrogé.
6. Cliquez de nouveau sur **Requête** pour redessiner.

Créez maintenant un second graphique qui ventile la même mesure :

1. Lancez une nouvelle exploration sur le même jeu de données.
2. Conservez le `SUM` de `revenue` comme métrique, et ajoutez un **Regrouper par** sur une colonne groupable telle que `region` ou `product`.
3. Définissez le type de graphique sur **Bar Chart** et cliquez sur **Requête**.
4. Si vous ne voulez que les premières lignes, ouvrez **Options** et définissez une **Limite de lignes** — par exemple `10` pour un histogramme des dix premiers.

> **Privilégiez la mise en forme à l'affichage plutôt que la modification des données.** Vous pouvez arrondir ou reformater les valeurs de deux façons : les transformer dans la table, ou les mettre en forme à l'affichage. La mise en forme à l'affichage est le choix courant — les valeurs sous-jacentes gardent toute leur précision et chaque lecteur voit un nombre propre. C'est l'étape suivante.

## Étape 4 : mettre en forme les nombres

Les mesures brutes reviennent sans mise en forme. Corrigez cela sur le graphique, pas dans les données.

- **Big Number :** modifiez le graphique, ouvrez l'onglet **Customize** et définissez **Number Format**.
- **Table :** modifiez le graphique, ouvrez l'onglet **Customize**, sélectionnez une colonne numérique (indiquée par un `#`) sous **Customize Column**, puis définissez son **D3 Format**.

La valeur par défaut est **Adaptive formatting**, qui s'ajuste aux valeurs. Pour figer un format, choisissez-en un dans la liste déroulante ou saisissez une chaîne de format D3 :

| Format | Entrée | Affiche |
|---|---|---|
| `,d` | `12345.67` | `12,346` |
| `$,d` | `12345.67` | `$12,346` |
| `$,.2f` | `12345.67` | `$12,345.67` |
| `,.2%` | `13.215` | `1,321.50%` |

La grammaire complète des formats — symboles monétaires, remplissage, précision, préfixes SI — est décrite dans [Mettre en forme les nombres et autres types de données](/fr/guides/dashboards/formatting-numbers/).

> **Arrondir à l'unité monétaire ? Utilisez `,d` ou `$,d`, et non `,.0f`.** La forme `,.0f` est une source connue de mise en forme défaillante des nombres ; `,d` (décimal, arrondi à l'entier) est le moyen fiable de supprimer les décimales.

## Étape 5 : ajouter une mesure calculée (facultatif)

Si le nombre que vous voulez n'est pas une simple colonne — un ratio, un pourcentage de marge, une somme conditionnelle — écrivez-le sous forme de métrique. Les métriques et les colonnes calculées s'écrivent en SQL de type PostgreSQL sur le jeu de données.

```sql
SUM("revenue") / (COUNT(*) + 0.00001)
```

Le `+ 0.00001` évite une division par zéro lorsqu'un groupe n'a aucune ligne. Pour d'autres modèles — logique `CASE`, `COALESCE` pour les valeurs nulles, sommes conditionnelles — consultez [Exemples de métriques](/fr/guides/dashboards/example-metrics/) et [Exemples de colonnes calculées](/fr/guides/dashboards/example-calculated-columns/).

## Étape 6 : assembler le tableau de bord

Un tableau de bord est une mise en page de graphiques enregistrés. Associez chaque graphique que vous avez créé au même tableau de bord pour qu'ils soient réunis.

1. Ouvrez **Edit Chart** sur votre Big Number.
2. Dans la section **Tableaux de bord**, saisissez le nom du tableau de bord sur lequel il doit apparaître. Si le tableau de bord n'existe pas encore, c'est ici que vous le nommez.
3. Enregistrez, puis répétez l'opération pour votre histogramme en le rattachant au même tableau de bord.
4. Ouvrez le tableau de bord pour voir les deux graphiques. Depuis le mode d'édition propre au tableau de bord, vous pouvez organiser les vignettes, les redimensionner et ajouter des filtres.

Pour toutes les options de mise en page, de filtres et d'interaction, consultez [Découvrir les tableaux de bord](/fr/guides/dashboards/learning-dashboard/).

## Étape 7 : le partager

Qui voit le tableau de bord dépend d'abord de l'accès à PlaidCloud, puis des éventuels rôles du service de tableaux de bord qui s'y ajoutent.

- **Par défaut, il est visible par les membres du projet.** La liste des tableaux de bord dans PlaidCloud affiche les tableaux de bord publiés appartenant aux projets auxquels une personne a accès — ainsi, toute personne pouvant ouvrir le projet peut trouver votre tableau de bord, sans étape supplémentaire.
- **Ajoutez les propriétaires du graphique au fur et à mesure.** Lorsque vous enregistrez un graphique, ajoutez toutes les personnes qui en ont besoin à ses **Propriétaires** — sinon un collègue risque de rencontrer une erreur « requires the datasource… permission » sur un graphique inaccessible. Ajouter les propriétaires au moment de l'enregistrement est plus simple que de rétablir l'accès après coup.
- **Ne limitez à des rôles précis que si nécessaire.** Un tableau de bord peut être limité à certains rôles du service de tableaux de bord, définis dans les propriétés du tableau de bord. Un tableau de bord restreint est masqué de la liste pour toute personne sans rôle correspondant — si vous en restreignez un, prévenez donc les personnes qui doivent y accéder. L'accès au projet dans PlaidCloud s'applique toujours en plus : l'attribution d'un rôle ne donne jamais accès à un tableau de bord d'un projet inaccessible.

Consultez [Utiliser les tableaux de bord](/fr/guides/dashboards/using-dashboards/) pour l'ensemble des règles de visibilité.

## Garder le tableau de bord à jour

Vous n'actualisez pas les tableaux de bord à la main. Lorsqu'un workflow republie la table derrière un graphique, chaque graphique qui la lit abandonne ses résultats en cache, et la prochaine personne qui ouvre le tableau de bord voit les nouveaux chiffres.

> **Un tableau de bord qui semble périmé n'est presque jamais un problème de cache.** Si les chiffres paraissent anciens après l'exécution d'un workflow, vérifiez le workflow — que l'exécution s'est terminée et a republié la table attendue — et non le cache. Republiez aussi sous le **même** nom publié : les graphiques restent rattachés à un nom, donc une table reconstruite sous un nouveau nom laisse les anciens graphiques pointer vers d'anciennes données.

Si vous devez malgré tout forcer l'actualisation, ouvrez le menu à côté de **Edit dashboard** et choisissez **Force refresh dashboard**. Les détails complets, y compris la durée de conservation des résultats, figurent dans [Mise en cache des tableaux de bord](/fr/guides/dashboards/dashboard-caching/).
