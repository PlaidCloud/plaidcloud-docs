*~20 minutes · une étape en échec, un diagnostic de l'IA, une correction appliquée*

Vous exécutez un workflow, une étape passe au rouge, et le texte de l'erreur seul ne vous dit pas quoi modifier. Ce tutoriel parcourt précisément ce moment : vous ouvrez l'**Assistant IA** intégré de PlaidCloud, le laissez diagnostiquer l'étape en échec sur vos données réelles, approuvez la correction qu'il propose, puis exécutez à nouveau pour confirmer. Vous utilisez ensuite le même assistant pour écrire une étape Extraire SQL à partir d'une description en langage courant.

Il s'agit de l'assistant IA intégré au produit, qui vous aide à construire et à corriger des workflows. Ce n'est **pas** la même chose que connecter un agent de codage IA externe (Claude Code, Cursor, MCP) à votre tenant — ce parcours complémentaire est décrit dans [Connecter un agent de codage IA](/fr/get-started/tutorials/mcp-with-ai-agent/).

## Ce que vous allez faire

| Phase | Ce que vous utiliserez |
|---|---|
| Voir l'étape échouer et lire l'erreur | L'onglet **Journal** du projet |
| Diagnostiquer et corriger l'étape en échec | L'assistant de correction, dans l'onglet **Assistant IA** de l'entrée du journal |
| Confirmer la correction | Répondre oui lorsque l'assistant propose d'exécuter à nouveau l'étape |
| Ajouter une nouvelle requête sans écrire de SQL | **Generate SQL with AI** dans une étape Extraire SQL |

## Prérequis

- Un espace de travail PlaidCloud ([démarrez un essai gratuit](https://app.plaidcloud.com) si vous n'en avez pas) et un projet que vous pouvez modifier.
- Un workflow comportant au moins une étape — idéalement une étape qui échoue, ou que vous pouvez faire échouer (un nom de colonne mal saisi dans une transformation suffit à reproduire le scénario).

> **L'assistant corrige avec vos autorisations.** Il ne peut modifier qu'une étape que vous pourriez déjà modifier vous-même, et chaque modification qu'il apporte est réversible en l'exécutant à nouveau ou en modifiant directement l'étape. Consultez [Corriger les erreurs de workflow avec l'IA](/fr/guides/ai-assistant/fixing-workflow-errors/).

## Étape 1 : exécuter le workflow et trouver l'erreur

Lorsqu'une étape échoue, un indicateur d'erreur apparaît à la fois sur le workflow et sur l'étape en échec, et l'échec est écrit dans le journal du workflow.

1. Ouvrez votre projet et exécutez le workflow (ou l'étape que vous testez).
2. Passez à l'onglet **Journal** du projet. Le journal liste les événements au fil de l'exécution des étapes — y compris les avertissements et les erreurs.
3. Dans la liste du journal, sélectionnez l'entrée de l'étape qui a échoué. Son message complet — y compris toute trace d'appels — s'ouvre dans le panneau de droite, sous l'onglet **Message du journal**.

> **Pas de workflow en panne sous la main ? Créez-en un en 30 secondes.** Dans n'importe quelle étape de transformation, modifiez l'expression d'une colonne pour qu'elle référence une colonne qui n'existe pas — remplacez `net_amount` par `net_amnt`, par exemple — et enregistrez. Exécutez l'étape : elle échoue avec, dans le journal, une erreur indiquant que la colonne `net_amnt` n'existe pas. C'est une véritable erreur de configuration que l'assistant de correction est conçu pour détecter, ce qui permet de suivre ce tutoriel de bout en bout.

Pour en savoir plus sur la façon dont les erreurs remontent et sur les options pour les gérer, consultez [Gérer les erreurs d'étape](/fr/guides/workflows/managing-step-errors/) et [Consulter le journal du workflow](/fr/guides/workflows/viewing-workflow-log/).

## Étape 2 : ouvrir l'assistant de correction

L'assistant de correction se trouve juste à côté de l'erreur brute, déjà dirigé vers l'étape qui a échoué.

1. L'entrée du journal en échec étant sélectionnée, repérez le panneau de droite qui affiche **Message du journal**.
2. Basculez ce panneau sur l'onglet **Assistant IA**.

Le chat **Assistant IA** s'ouvre déjà dirigé vers le workflow et l'étape dont provient l'entrée du journal sélectionnée ; vous n'avez donc pas à lui dire quelle étape a échoué. Vous pouvez lire l'erreur brute sous **Message du journal** et discuter avec l'assistant sous **Assistant IA**, côte à côte.

Pour la plupart des erreurs, il commence aussitôt le diagnostic. Pour quelques erreurs courantes, comme une expression qui nomme une colonne inexistante, la première réponse est plutôt une courte explication que PlaidCloud possède déjà pour ce type d'erreur : ce qui la cause habituellement, quels mots du message d'erreur examiner et comment la corriger. Cette explication n'examine pas votre étape. Répondez — par exemple, *« Veuillez vérifier cette étape et la corriger »* — et l'assistant prend la suite. Consultez [Erreurs courantes](/fr/guides/ai-assistant/fixing-workflow-errors/#erreurs-courantes).

## Étape 3 : le laisser diagnostiquer et proposer une correction

L'assistant procède dans un ordre fixe, et rien n'est enregistré tant que vous ne l'avez pas dit :

1. **Il diagnostique** — il lit la configuration de l'étape en échec ainsi que les tables et colonnes qu'elle touche, en vérifiant ses affirmations sur vos données plutôt qu'en devinant à partir du seul texte de l'erreur.
2. **Il propose** — s'il trouve une véritable erreur de configuration, il affiche la configuration corrigée de l'étape et explique clairement ce qu'il a changé et pourquoi. Rien n'est écrit à ce stade.
3. **Vous approuvez** — il attend votre accord explicite. Une réponse ambiguë n'est pas considérée comme une approbation.
4. **Il applique** — une fois que vous avez approuvé, il écrit la configuration corrigée dans l'étape, par le même chemin que l'éditeur d'étape.
5. **Il propose une nouvelle exécution** — il demande s'il doit exécuter à nouveau l'étape maintenant. Répondez oui : il exécute l'étape et vous dit si la correction a fonctionné.

Lisez la modification proposée avant de l'approuver. L'assistant répare la configuration de l'unique étape d'où provient l'erreur — par exemple un nom de colonne ou de fonction mal saisi, une expression invalide, un type de données ou un cast incorrect, ou du SQL mal formé — et il modifie le strict minimum pour corriger l'erreur.

> **Il est honnête sur ce qu'il ne peut pas corriger.** Son seul levier est la configuration de cette étape. Il ne créera pas, ne supprimera pas et ne réordonnera pas d'étapes, ne modifiera pas une autre étape et ne changera pas vos données. De nombreux échecs ne sont pas du tout des problèmes de configuration — données sources manquantes ou mal formées, étape en amont ayant échoué en premier, erreur transitoire ou d'infrastructure, problème d'autorisations, ou logique défaillante dans une transformation ou une fonction définie par l'utilisateur (UDF). Dans ces cas, il explique ce qu'il a trouvé et vous indique où se trouve la vraie correction, plutôt que de maquiller une modification en solution.

## Étape 4 : approuver et exécuter à nouveau

1. Lorsque la configuration proposée vous paraît correcte, confirmez explicitement la modification. L'assistant l'applique à l'étape.
2. Lorsque l'assistant demande s'il doit exécuter à nouveau l'étape, répondez oui. Il exécute l'étape et vous dit si elle a réussi ou échoué de nouveau. Vous pouvez aussi exécuter vous-même l'étape, ou le workflow, à nouveau.

Si l'assistant vous a indiqué que la cause se situe en dehors de la configuration de l'étape — données erronées, échec en amont, problème d'autorisations — c'est la réponse. Corrigez-la là où elle se trouve réellement plutôt que de demander à l'assistant de modifier quand même l'étape.

> **Les avertissements sont souvent bénins.** Si l'entrée du journal est un avertissement plutôt qu'un échec franc, l'assistant vous indiquera souvent qu'aucune modification n'est nécessaire plutôt que d'inventer une retouche. C'est un résultat valable, pas une impasse.

## Étape 5 : générer une étape Extraire SQL avec l'IA

Utilisez maintenant le même assistant pour ajouter du nouveau travail, et pas seulement pour réparer. L'étape **Extraire SQL** exécute un `SELECT` en lecture seule et écrit le résultat dans une nouvelle table — et l'éditeur d'étape peut écrire cette requête pour vous.

1. Depuis la vue **Étapes** du workflow, cliquez sur **Créer une étape** et choisissez **Tables → Extraire SQL** ou **AI → SQL Extract (AI Assisted)**. Les deux ouvrent le même éditeur, qui comprend un panneau **Generate SQL with AI** en haut de la page Paramètres d'extraction SQL.
2. **(Facultatif) Choisissez des tables sources.** Dans la liste **Tables sources**, sélectionnez une ou plusieurs tables que la requête doit lire. Laissez-la vide pour que l'assistant examine le projet et choisisse lui-même les tables pertinentes.
3. **Décrivez ce que vous voulez.** Dans la zone **Décrire**, écrivez le résultat attendu en langage courant — par exemple, *« classe chaque compte du grand livre dans un pool d'activité selon sa plage de numéros de compte »*.
4. **Cliquez sur Générer le SQL.** L'assistant écrit un unique `SELECT` en lecture seule, le valide en l'exécutant et renseigne l'éditeur **Requête SQL SELECT** ainsi que la page de mappage **Sélection des données de la table** avec les colonnes détectées. Si vous avez laissé la liste des sources vide, les tables qu'il a choisies sont sélectionnées en retour dans la liste pour que vous voyiez ce qu'il a utilisé.

> **Il n'y a rien à configurer.** Cette fonction utilise le même modèle intégré que l'Assistant IA — vous n'avez pas besoin de configurer un agent IA ni une connexion LLM par espace de travail.

## Étape 6 : vérifier et enregistrer l'étape

Le SQL généré est un point de départ, pas une boîte noire.

1. **Modifiez-le librement.** L'éditeur SQL est entièrement modifiable — affinez la requête, ajoutez une jointure ou changez la liste des colonnes avant d'enregistrer.
2. **Choisissez une table cible.** Choisissez ou nommez la **Table cible** dans laquelle l'étape écrit son résultat.
3. **Enregistrez l'étape.** Elle est enregistrée comme une étape Extraire SQL ordinaire et s'exécute dans le cadre du workflow comme n'importe quelle autre.

L'assistant n'écrit que des instructions `SELECT` en lecture seule — jamais `INSERT`, `UPDATE`, `DELETE` ni aucun autre SQL qui modifie des données. La génération ne fait que rédiger et prévisualiser ; l'étape est créée lorsque vous l'enregistrez et s'exécute quand le workflow s'exécute. Si une requête générée ne s'exécute pas, l'éditeur affiche le SQL avec l'erreur pour que vous puissiez la corriger — ou ajuster votre description et générer à nouveau. Tous les détails figurent dans [Générer des étapes Extraire SQL avec l'IA](/fr/guides/ai-assistant/generate-sql-extract/).

**Voilà l'assistance.** Vous avez diagnostiqué une étape en échec sur des données réelles, approuvé et appliqué la correction de l'IA, confirmé le résultat par une nouvelle exécution et généré une étape Extraire SQL fonctionnelle à partir d'une simple phrase — le même assistant qui répare ce qui est cassé et construit ce qui est nouveau.
