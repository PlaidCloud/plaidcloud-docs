*~10 minutes · votre CSV, une table chargée, un premier résultat*

Voici la version rapide. Vous apportez un CSV et, à la fin, vous l'aurez importé, chargé dans une table, vous aurez exécuté une seule transformation et lu un vrai résultat tiré de vos propres données.

C'est le complément rapide de [Charger, transformer et publier des données](/fr/get-started/tutorials/load-and-transform-data/) — ce dernier prend environ une heure et construit un pipeline complet à plusieurs étapes, avec des jointures et une publication. Commencez ici pour obtenir un premier succès ; passez à l'autre tutoriel quand vous voulez approfondir.

## Prérequis

- Un espace de travail PlaidCloud ([démarrez un essai gratuit](https://app.plaidcloud.com) si vous n'en avez pas).
- Un projet dans lequel travailler — créez-en un depuis l'onglet **Projets** si vous n'en avez pas encore.
- Un fichier CSV à vous. Tout fichier avec une ligne d'en-tête et une colonne numérique convient — ventes, dépenses, liste de commandes.

## Étape 1 : créer un workflow

Un workflow est le pipeline qui importe et transforme vos données.

1. Ouvrez votre projet et passez à l'onglet **Workflows**.
2. Cliquez sur **Nouveau workflow** dans la barre d'outils.
3. Donnez-lui un nom comme « CSV Quick Start » et laissez **Type de workflow** sur sa valeur par défaut, **Standard série**.
4. Cliquez sur **Créer**, puis double-cliquez sur le nouveau workflow pour ouvrir l'[explorateur de workflows](/fr/guides/workflows/workflow-explorer/).

## Étape 2 : importer votre CSV

1. Ajoutez une nouvelle étape et choisissez une étape **Import → CSV** (ou l'étape d'importation qui correspond au format de votre fichier).
2. Dans la configuration de l'étape :
   - **Fichier source** — pointez vers votre CSV : téléversez-le ou choisissez-le dans un compte de documents connecté.
   - **Table cible** — nommez-la `my_data`.
   - **Délimiteur, caractère de citation, ligne d'en-tête** — ajustez-les uniquement si votre fichier n'est pas standard ; les valeurs par défaut conviennent à un fichier typique séparé par des virgules avec une ligne d'en-tête.
3. Exécutez l'étape.

Votre CSV est maintenant chargé sous forme de [table](/fr/guides/data/tables-views/) dans le projet. Une table contient les données physiques en lignes et en colonnes ; c'est ce que lit tout le reste en aval.

> **La source n'est jamais modifiée.** Chaque étape lit depuis une source et écrit dans une cible, en laissant l'original intact. L'import de votre CSV a écrit `my_data` ; la transformation de l'étape suivante la lit et écrit ailleurs.

## Étape 3 : vérifier la table chargée

Passez à l'onglet **Tables** et cliquez sur `my_data`. Vérifiez le nombre de colonnes, quelques lignes d'exemple et que les types de données semblent corrects — une colonne numérique doit être lue comme un nombre, pas comme du texte. Si un type est incorrect, vous pouvez le corriger avec les mappeurs de colonnes de l'étape d'import, puis l'exécuter à nouveau.

## Étape 4 : exécuter une transformation

Transformez maintenant la table brute en réponse. Cet exemple filtre les lignes qui comptent et ne conserve que les colonnes qui vous intéressent — adaptez les détails à votre fichier.

1. Ajoutez une étape **Tables → Table Lookup** (ou toute transformation de table qui permet de filtrer et de sélectionner des colonnes).
2. Configurez :
   - **Table source** — `my_data`
   - **Table cible** — `my_result`
   - **Conditions de filtre** — une condition qui réduit les lignes, par exemple `amount > 0`
   - **Colonnes à conserver** — le sous-ensemble que vous voulez lire, plus toute colonne calculée comme `revenue = quantity * price`
3. Exécutez l'étape.

Pour l'ensemble des fonctions utilisables dans une colonne calculée — opérations sur les chaînes, calculs de dates, logique conditionnelle — consultez la [référence des expressions](/fr/reference/expressions/).

> **Ce que vous devriez voir.** Une fois l'étape exécutée, `my_result` contient moins de lignes que `my_data` — le filtre les a réduites — et votre colonne calculée (comme `revenue`) est présente et renseignée sur chaque ligne restante. Si le nombre de lignes n'a pas diminué ou si la colonne calculée est vide, revérifiez la condition de filtre et l'expression avant de continuer.

## Étape 5 : lire le résultat

Ouvrez l'onglet **Tables** et cliquez sur `my_result`. Moins de lignes que `my_data`, seulement les colonnes conservées et votre colonne calculée renseignée : voilà votre première réponse, tirée directement de vos propres données.

Vous pouvez aussi exécuter les deux étapes d'un coup : dans le workflow, cliquez sur **Exécuter** (ou **Run All** dans le menu **Actions**) pour tout exécuter dans l'ordre. Chaque étape affiche une icône d'état au fil de l'exécution — **Completed** signifie qu'elle s'est terminée sans problème. Consultez [Exécuter un workflow](/fr/guides/workflows/run-a-workflow/) pour connaître la signification de chaque état et savoir comment reprendre une exécution arrêtée.

> **Une erreur ?** Les deux causes habituelles sont un type de données importé comme du texte alors qu'il vous fallait un nombre, et une condition de filtre qui référence un nom de colonne absent de la table. Vérifiez la table de l'étape 3, puis exécutez à nouveau. [Gérer les erreurs d'étape](/fr/guides/workflows/managing-step-errors/) couvre le reste.
