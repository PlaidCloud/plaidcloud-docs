## Opis


Importuje wynik zapytania SQL do zewnętrznej bazy danych do tabeli projektu PlaidCloud. Zapytanie jest wykonywane w zdalnej bazie danych; do PlaidCloud trafia tylko zbiór wyników.

Różni się od [Importuj zewnętrzne tabele bazy danych](/pl/reference/workflow-steps/import/import-external-database-tables/) tym, że SQL piszesz samodzielnie — przydatne w przypadku złożonych złączeń, filtrów lub agregacji, które chcesz, aby baza źródłowa wykonała, zanim dane trafią do PlaidCloud.

### Zgadywanie typów kolumn
Importy SQL mogą próbować odgadnąć typ danych podczas ładowania lub ustawić wszystkie kolumny na typ Tekst. Dynamiczne ustawianie typów danych może być szybsze, jeśli dane są czyste, ale w niektórych okolicznościach może powodować problemy.

Na przykład, jeśli większość danych wygląda na liczbowe, ale zawierają one także tekst, może spróbować ustawić typ liczbowy, powodując problemy z ładowaniem z powodu niezgodnych typów danych. Problemy mogą wystąpić także wtedy, gdy na przykład istnieje liczbowy kod produktu o 16 cyfrach. Zostałyby obcięte początkowe zera, w wyniku czego otrzymano by liczbę zamiast 16-cyfrowego kodu.

Ustawienie wszystkich danych na tekst wymaga jednak późniejszego kroku Extract, który przekonwertuje wszystkie dane niebędące tekstem na odpowiedni typ, taki jak daty lub wartości liczbowe.

## Rozwiązywanie problemów

| Objaw | Prawdopodobna przyczyna |
| --- | --- |
| Krok trwał zauważalnie dłużej niż zwykle — nawet około pół godziny dłużej — bez żadnej zmiany w zapytaniu, połączeniu ani wolumenie danych | Proces roboczy w tle uruchamiający import został przerwany w połowie (restart lub wywłaszczenie po stronie platformy, nie coś w Twoim przepływie pracy), a platforma ponowiła import tabeli za Ciebie. Ponowienie startuje dopiero po wykryciu przerwania, co tłumaczy dodatkowy czas. |
| Krok mimo tego opóźnienia zakończył się powodzeniem | Ponowienie w całości zastępuje zawartość tabeli, więc wynik jest taki sam jak przy jednym czystym uruchomieniu — nie ma nic więcej do sprawdzenia ani powtórzenia. |
| Krok kończy się błędem „została już podjęta i nie można jej bezpiecznie uruchomić ponownie” | W przypadku kroku Importuj SQL to odrzucenie już się nie zdarza — przerwanie w trakcie uruchomienia jest ponawiane. Nadal będzie ono widoczne, z założenia, przy [przywracaniu archiwum projektu](/pl/guides/projects/archive-a-project/#przywracanie-archiwum) lub [ładowaniu wymiaru](/pl/reference/workflow-steps/dimensions/dimension-load/), gdzie ponowne uruchomienie utworzyłoby duplikat zamiast cokolwiek zastąpić. Jeśli widzisz je w samym kroku Importuj SQL, skontaktuj się z pomocą techniczną.
