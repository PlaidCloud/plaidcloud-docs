## Opis

Importuje pliki tekstowe JSON z PlaidCloud Document.

Więcej informacji o plikach JSON znajdziesz na oficjalnej stronie JSON: http://json.org/.

Pliki JSON *nie* zachowują kolejności kolumn. Kolejność kolumn w pliku źródłowym niekoniecznie odzwierciedla kolejność kolumn w zaimportowanej tabeli danych.

Import JSON odbywa się strumieniowo przez pamięć tymczasową, bez wczytywania całego dokumentu do pamięci, dlatego bardzo duże pliki importują się bez wyczerpania pamięci. Kolumny, które pojawiają się dopiero późno w dużym dokumencie, są uwzględniane w zaimportowanej tabeli. Zagnieżdżone obiekty i tablice są importowane jako standardowy zwarty tekst JSON, dzięki czemu kolejne kroki mogą je analizować dowolnym narzędziem JSON.

## Unikatowe elementy konfiguracji

### Orientacja danych JSON

Rozważ następujący zestaw danych:

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

Pliki JSON można importować z jednego z trzech formatów danych:

* Records: dane są przechowywane w słownikach Python, a każdy wiersz w formacie \{Column -> Value, …}. Na przykład:


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index: dane są przechowywane w zagnieżdżonych słownikach Python, a każdy wiersz w formacie \{Index -> \{Column -> Value, …},…}. Na przykład:


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split: dane są przechowywane w jednym słowniku Python, a wartości w listach. Na przykład:


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

Oprócz powyższych formatów akceptowany jest JSON rozdzielany znakami nowego wiersza (NDJSON): jeden samodzielny obiekt JSON w każdym wierszu, bez otaczającej tablicy. Na przykład:

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### Cały dokument

Aby zachować nienaruszony JSON każdego pliku, wybierz **Importuj każdy plik jako jeden wiersz z całym dokumentem JSON** (`whole_document`) w sekcji **Więcej opcji JSON**. Każdy plik jest wtedy importowany jako jeden wiersz zawierający cały dokument JSON, z liczbami zachowanymi tak, jak zapisano.

### Daty i znaczniki czasu

Pole jest importowane jako daty lub znaczniki czasu, gdy wszystkie jego wartości mają ten sam układ spośród poniższych:

| Układ | Daty | Znaczniki czasu |
| --- | --- | --- |
| ISO 8601 | `2026-01-23` | `2026-01-23T23:14:00` |
| Miesiąc na początku | `01-23-2026` lub `01-23-26` | `01-23-2026 11:14:00 PM`, z czasem 12-godzinnym |
| Dzień na początku | `23-01-2026` lub `23-01-26` | `23-01-2026 23:14:00`, z czasem 24-godzinnym |
| Dwucyfrowy rok na początku | `99-01-23` | `99-01-23 23:14:00`, z czasem 24-godzinnym |

Każda wartość w polu jest odczytywana w ten sam sposób, niezależnie od kolejności wierszy. Pole w dowolnym innym układzie, takim jak `01/23/2026` lub `01-23-2026 23:14:00`, jest importowane jako tekst. Tak samo jest z polem, którego wartości mieszają układy, chociaż niektóre mieszanki lat dwucyfrowych i czterocyfrowych, takie jak `01-23-2026` i `01-24-26`, zatrzymują import z błędem wskazującym to pole.

#### Gdy wartość pasuje do więcej niż jednego układu

`01-03-2026` może oznaczać 3 stycznia lub 1 marca, a `23-01-26` może oznaczać 23 stycznia 2026 lub, przy odczycie z rokiem na początku, 26 stycznia 2023. Gdy wszystkie wartości pola pasują do więcej niż jednego z powyższych układów, o odczycie decyduje **Format daty** kroku, według kolejności dnia, miesiąca i roku:

* Wybór zaczynający się od Miesiąc-dzień odczytuje miesiąc na początku: `01-03-2026` jako 3 stycznia.
* Wybór zaczynający się od Dzień-miesiąc lub Skrócony odczytuje dzień na początku: `01-03-2026` jako 1 marca, a `23-01-26` jako 23 stycznia 2026.
* Przy każdym innym ustawieniu Format daty import zatrzymuje się z błędem wskazującym pole oraz wybory, które by to rozstrzygnęły.

Te wybory odczytują też znacznik czasu na drugim zegarze, gdy dzień i miesiąc każdej wartości wynoszą 12 lub mniej: wybór Miesiąc-dzień odczytuje `01-03-2026 23:14:00` jako 3 stycznia, a wybór Dzień-miesiąc lub Skrócony odczytuje `01-03-2026 11:14:00 PM` jako 1 marca. Każdy inny Format daty odczytuje je tak, jak w tabeli: dzień na początku z czasem 24-godzinnym, a miesiąc na początku z czasem 12-godzinnym.

Żaden wybór Format daty nie odczytuje roku dwucyfrowego na początku, więc pole takie jak `26-01-23` jest importowane z rokiem na początku tylko wtedy, gdy jego wartości nie da się odczytać inaczej, jak w przypadku `99-01-23`. Zapisana z rokiem czterocyfrowym, jak `2026-01-23`, taka data jest importowana jako ISO 8601.

Wyjątkiem jest plik, który zawiera też znacznik czasu wewnątrz zagnieżdżonego obiektu lub tablicy: żadne z powyższych sprawdzeń go nie dotyczy, a wartość pasująca do więcej niż jednego układu może być odczytana inaczej w jednym wierszu niż w następnym.
