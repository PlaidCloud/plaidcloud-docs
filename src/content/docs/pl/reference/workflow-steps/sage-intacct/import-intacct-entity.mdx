## Opis

Importuje jeden obiekt Sage Intacct przez [połączenie Sage Intacct](/pl/guides/connections/sage-intacct/) do tabeli projektu, używając operacji `readByQuery`/`readMore` bramy Intacct XML Gateway do automatycznego przejścia przez cały zestaw wyników. Wybierz połączenie, obiekt i ewentualne filtry; krok pobiera pasujące rekordy i zapisuje je, bez ręcznego zarządzania stronicowaniem.

To ogólny, gotowy krok — jeden typ kroku obsługuje siedem obiektów, od szczegółów transakcji i sald księgi głównej (`GLDETAIL`, `GLACCOUNTBALANCE`, `GLENTRY`) przez wzorce wymiarów (`LOCATION`, `DEPARTMENT`, `CLASS`) po dokumenty zamówień (`SODOCUMENT`).

<Aside type="note">
Ten krok różni się od [Import Sage Intacct Query](/pl/reference/workflow-steps/sage-intacct/import-intacct-query/), który obsługuje **dowolny** obiekt Intacct za pomocą ogólnego selektora pól. `Import Intacct Entity` to krok natywnego katalogu dla właśnie tych siedmiu obiektów, z dobraną listą dozwolonych filtrów dla każdego obiektu i automatycznym stronicowaniem `readMore` dla dużych zestawów wyników (szczegóły księgi głównej mogą w szczególności znacznie przekraczać pojedynczą stronę API Intacct).
</Aside>

## Konfiguracja

| Pole | Wymagane | Uwagi |
|---|---|---|
| Połączenie Sage | Tak | Połączenie Sage Intacct, przez które odbywa się odczyt. |
| Tabela docelowa | Tak | Tabela projektu, do której zapisywane są wyniki. Przy każdym uruchomieniu jest w całości nadpisywana. |
| Object | Tak | Który obiekt Intacct pobrać. Jeden z: `GLDETAIL`, `GLACCOUNTBALANCE`, `GLENTRY`, `LOCATION`, `DEPARTMENT`, `CLASS`, `SODOCUMENT`. |
| Filters | Nie | Tablica klauzul `{field, operator, value}`. Operatory to m.in. `eq`, `ne`, `gt`, `ge`, `lt`, `le`. Zakres wyraża się dwiema klauzulami na tym samym polu — jedną `ge`, jedną `le`. Każdy obiekt ogranicza filtry do własnej listy dozwolonych pól i operatorów; nieobsługiwana kombinacja pola lub operatora jest odrzucana, a nie po cichu pomijana. |

### Obiekty i typowe filtry zakresu

| Obiekt | Co pobiera | Typowe filtry zakresu |
|---|---|---|
| `GLDETAIL` | Szczegóły wierszy transakcji księgi głównej | data księgowania (`ge`/`le`), kwota (`ge`/`le`) |
| `GLACCOUNTBALANCE` | Salda kont według okresów | data końca okresu (`ge`/`le`) |
| `GLENTRY` | Wiersze zaksięgowanych zapisów dziennika | data księgowania (`ge`/`le`) |
| `LOCATION` | Wzorzec wymiaru lokalizacji | — (tylko filtry równości) |
| `DEPARTMENT` | Wzorzec wymiaru działu | — (tylko filtry równości) |
| `CLASS` | Wzorzec wymiaru klasy | — (tylko filtry równości) |
| `SODOCUMENT` | Dokumenty zamówień sprzedaży | data dokumentu (`ge`/`le`) |

## Jak działa stronicowanie

Brama XML Gateway Intacct zwraca wyniki po jednej stronie naraz. Ten krok wysyła początkowe wywołanie `readByQuery`, a następnie kolejne wywołania `readMore` z identyfikatorem zestawu wyników zwróconym przez Intacct, aż każda strona zostanie odczytana — dzięki temu pobranie `GLDETAIL` obejmujące dziesiątki tysięcy wierszy kończy się w jednym uruchomieniu kroku, bez konieczności dostrajania rozmiaru strony.

<Aside type="caution">
Bardzo szerokie, niefiltrowane pobranie z `GLDETAIL` lub `GLENTRY` nadal może trwać długo przy pełnym stronicowaniu. Ogranicz duże pobranie zakresem dat księgowania, zamiast polegać wyłącznie na stronicowaniu, aby było szybkie.
</Aside>
