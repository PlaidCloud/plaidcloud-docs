Serwer MCP PlaidCloud umożliwia agentowi AI koordynowanie migracji wielu przepływów pracy Alteryx. Agent może pomagać w przygotowywaniu i porządkowaniu plików w Document, tworzeniu spisu pakietów przepływów pracy, wywoływaniu konwertera Alteryx, porządkowaniu wygenerowanych przepływów pracy, uruchamianiu przepływów pracy walidacyjnych oraz podsumowywaniu postępów dla zespołu migracyjnego.

<Aside type="note">
  MCP idealnie nadaje się do koordynacji na skalę całego portfolio. Konwersję nadal wykonuje importer PlaidCloud; agent pomaga planować, porządkować w sekwencję, uruchamiać i podsumowywać pracę.
</Aside>

## Kiedy używać MCP

Używaj orkiestracji MCP, gdy migrujesz wiele przepływów pracy lub gdy chcesz, aby agent AI pomagał w powtarzalnych zadaniach migracyjnych:

- Sporządzanie spisu plików Alteryx przygotowanych w Document.
- Przesyłanie, kopiowanie, przenoszenie, zmienianie nazw i porządkowanie plików migracji za pomocą narzędzi Document.
- Praca z podłączonym współdzielonym kontem magazynu, takim jak OneDrive, Google Drive, SharePoint, S3, Azure Blob lub SFTP.
- Grupowanie przepływów pracy, aplikacji i makr w partie migracyjne.
- Konwertowanie każdego pliku `.yxmd`, `.yxwz` lub `.yxmc` do PlaidCloud.
- Śledzenie wyników konwersji w całym portfolio.
- Uruchamianie przekonwertowanych przepływów pracy lub przepływów pracy walidacyjnych.
- Tworzenie podsumowania migracji do przeglądu.

W przypadku pojedynczego przepływu pracy formularz importu jest często najszybszą drogą. W przypadku portfolio MCP daje agentowi uporządkowany sposób wielokrotnej koordynacji tych samych możliwości PlaidCloud.

## Co może wywoływać agent

Katalog narzędzi MCP zawiera narzędzie konwersji Alteryx o nazwie `alteryx_convert`. Tworzy ono przepływy pracy PlaidCloud z plików Alteryx przechowywanych w Document.

Wywołanie konwersji obejmuje:

- Źródłowe konto dokumentów i ścieżkę pliku Alteryx.
- Docelowy projekt PlaidCloud.
- Docelowe konto dokumentów i ścieżkę dla artefaktów konwersji.
- Opcjonalne prefiksy przepływów pracy, kroków i tabel. Prefiks tabeli domyślnie przyjmuje nazwę samego przepływu pracy, co zapobiega kolizjom tabel między dwiema konwersjami w jednym projekcie; przekaż pusty prefiks, aby uzyskać nazwy bez prefiksu.
- Typ przepływu pracy, domyślnie zaawansowane przepływy pracy.

Agent może łączyć to ze zwykłymi narzędziami MCP dla projektów, przepływów pracy, Document, uruchomień przepływów pracy i tabel, aby zarządzać całą migracją.

## Przygotowanie plików z agentem

Agent połączony przez MCP może pomóc w przygotowaniu plików wokół konwersji:

- Znajdowanie plików `.yxmd`, `.yxwz` i `.yxmc` w Document.
- Rozpoznawanie prawdopodobnych plików wejściowych, plików makr, zasobów raportów, plików pomocniczych danych przestrzennych i oczekiwanych wyników.
- Tworzenie przejrzystej struktury folderów migracji.
- Kopiowanie, przenoszenie lub zmiana nazw plików w ramach tej struktury.
- Utrzymywanie razem powiązanych plików przepływów pracy, makr, danych, danych przestrzennych, raportów i walidacji.
- Podsumowanie pakietu przed konwersją.

Jest to przydatne, gdy pakiet migracyjny zawiera wiele folderów lub gdy zespoły chcą, aby agent przygotował powtarzalny spis przed rozpoczęciem konwersji.

## Korzystanie ze współdzielonego magazynu bez przesyłania

Nie musisz przesyłać plików do nowego folderu należącego do PlaidCloud przed migracją. Document w PlaidCloud może łączyć się bezpośrednio ze współdzielonym magazynem, który już zawiera pakiet migracyjny Alteryx.

Typowe opcje:

- [Google Drive](/pl/guides/documents/adding-accounts/add-google-drive-account/)
- [OneDrive lub SharePoint](/pl/guides/documents/adding-accounts/add-onedrive-account/)
- [AWS S3](/pl/guides/documents/adding-accounts/add-aws-s3-account/)
- [Azure Blob Storage](/pl/guides/documents/adding-accounts/add-azure-blob-storage-account/)
- [SFTP](/pl/guides/documents/adding-accounts/add-sftp-account/)

Po połączeniu konta dokumentów agent może pracować na tym koncie dokumentów i ścieżce. Dzięki temu migracja pozostaje blisko istniejącego współdzielonego magazynu klienta i może zniknąć osobny etap przesyłania.

## Przygotowanie lub wybór plików w Document

Zanim poprosisz agenta o koordynację migracji, wybierz jedną z poniższych dróg:

- Połącz istniejącą lokalizację współdzielonego magazynu jako konto dokumentów.
- Prześlij pakiety przepływów pracy na konto dokumentów.
- Poproś agenta o uporządkowanie plików już dostępnych w Document.

Następnie potwierdź, że:

1. Przepływy pracy, aplikacje, makra, pliki wejściowe, pliki pomocnicze danych przestrzennych, raporty i oczekiwane wyniki są dostępne w Document.
2. Wybrano projekt docelowy.
3. Wybrano ścieżkę Document dla zależności i artefaktów przekonwertowanych przepływów pracy.
4. Agent ma uprawnienia do korzystania z odpowiednich narzędzi MCP dla Document i przepływów pracy.

Agent może wtedy odwoływać się do stałych ścieżek Document podczas wywoływania konwertera.

## Sugerowany monit dla agenta

Użyj monitu podobnego do poniższego z agentem połączonym przez MCP:

```text
In PlaidCloud, migrate the Alteryx workflows in the connected Document account
"Migration Share" under /q4-alteryx-package into the project "Q4 Migration".

First inventory the .yxmd, .yxwz, and .yxmc files. Organize the package by
workflow, macro, input, spatial, report, and expected-output files. Group macros
with the workflows that call them. Then convert the workflows as Advanced
workflows using the Document output path /q4-alteryx-converted. Prefix created
workflows with "Q4 - ". After each conversion, summarize the generated workflow,
macros, readiness notes, and next validation step. Ask before making mutating calls.
```

Dostosuj nazwę projektu, ścieżkę źródłową, ścieżkę docelową i prefiks do swojej partii migracyjnej.

## Zalecany przebieg orkiestracji

W przypadku migracji portfolio poproś agenta o wykonanie następującego przebiegu:

1. Połącz lub wybierz konto dokumentów zawierające pakiet migracyjny.
2. Sporządź spis źródłowego folderu Document.
3. Rozpoznaj pliki `.yxmd`, `.yxwz` i `.yxmc`.
4. Uporządkuj pliki w grupy: przepływy pracy, makra, dane wejściowe, dane przestrzenne, raporty i oczekiwane wyniki.
5. Zgrupuj powiązane przepływy pracy i makra.
6. Potwierdź projekt docelowy i ścieżkę wyjściową Document.
7. Skonwertuj makra i przepływy pracy do zaawansowanych przepływów pracy.
8. Otwórz lub opisz wygenerowane przepływy pracy.
9. Uruchom walidację strukturalną.
10. Uruchom walidację zgodności wyników tam, gdzie dostępne są oczekiwane wyniki.
11. Podsumuj przekonwertowane przepływy pracy, wygenerowane makra, artefakty i stan walidacji.

Dzięki temu zespół migracyjny otrzymuje jeden raport postępu dla całego portfolio, a do każdej konwersji nadal używa natywnego importera PlaidCloud.

## Przeglądanie wywołań modyfikujących

Większość klientów MCP pokazuje wywołania narzędzi, zanim zostaną wykonane. Przejrzyj wywołania konwersji i uruchomień przepływów pracy przed ich zatwierdzeniem, zwłaszcza w projektach produkcyjnych.

W przypadku migracji przejściowych użyj dedykowanego projektu migracyjnego i folderu Document. Po walidacji przenieś przekonwertowane przepływy pracy do projektu produkcyjnego.

## Śledzenie wyników

Poproś agenta o utworzenie tabeli migracji zawierającej:

- Źródłowy plik Alteryx.
- Wygenerowany przepływ pracy PlaidCloud.
- Wygenerowane przepływy pracy makr.
- Stan konwersji.
- Poziom walidacji.
- Ścieżkę wyjściową Document.
- Uwagi do dalszych działań.

To podsumowanie jest przydatne w raportowaniu projektu, przekazaniu prac i przeglądzie gotowości produkcyjnej.
