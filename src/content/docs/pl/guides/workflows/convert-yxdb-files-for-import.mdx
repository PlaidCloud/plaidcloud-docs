Alteryx zapisuje pliki `.yxdb` w dwóch formatach. Format klasyczny (zapisywany przez pierwotny silnik) jest dobrze znany, a PlaidCloud importuje go bezpośrednio. Silnik AMP zapisuje nowszy wariant — nagłówek pliku brzmi `Alteryx e2 Database file` — którego specyfikacja jest własnościowa i nieopublikowana, więc żadne narzędzie spoza Alteryx, w tym PlaidCloud, nie może go odczytać.

Podczas migracji nadal masz licencjonowany Alteryx Designer, a Designer odczytuje oba formaty. Użyj go jednorazowo, przed wycofaniem z użycia, aby przepisać pliki w formacie AMP do postaci przenośnej.

<Aside type="note">
  Klasyczne pliki `.yxdb` są importowane do PlaidCloud bezpośrednio — konwersja nie jest potrzebna. Jeśli import pliku `.yxdb` kończy się błędem nieczytelnego pliku, najbardziej prawdopodobną przyczyną jest plik w formacie AMP.
</Aside>

## Rozpoznawanie plików w formacie AMP

- Przepływ pracy, który utworzył plik, został uruchomiony z włączonym silnikiem AMP.
- PlaidCloud zgłasza plik jako nieczytelny podczas importu, podczas gdy inne pliki `.yxdb` z tego samego pakietu są importowane bez problemu.
- Pierwsze bajty pliku brzmią `Alteryx e2 Database file` zamiast `Alteryx Database File` (widoczne w dowolnym edytorze tekstowym lub szesnastkowym).

## Opcja A: ponowny zapis plików pojedynczo w Designer

W przypadku niewielkiej liczby plików zapisz każdy z nich ponownie z poziomu Designer:

1. W Alteryx Designer dodaj narzędzie **Input Data** i wybierz plik `.yxdb`.
2. Połącz narzędzie **Output Data** i wybierz nową ścieżkę `.yxdb`.
3. W opcjach narzędzia Output Data włącz opcję zapisu pliku **w formacie zgodnym z Designer 18.1 i starszymi**. Wymusza to format klasyczny.
4. Uruchom przepływ pracy, a następnie zaimportuj nowy plik do PlaidCloud.

Zapis do pliku CSV zamiast `.yxdb` w kroku 2 również działa i pomija opcję zgodności.

## Opcja B: wsadowa konwersja folderu za pomocą przepływu pracy do pobrania

W przypadku wielu plików pobierz gotowy przepływ pracy i uruchom go w Designer:

<a href="/downloads/convert_yxdb_folder.yxmd" download>Pobierz convert_yxdb_folder.yxmd</a>

Łączy on narzędzia **Directory**, **Dynamic Input** i **Output Data**, dzięki czemu każdy plik `.yxdb` w folderze — klasyczny lub AMP — jest zapisywany jako plik CSV o nazwie `converted_<original name>.csv`. CSV jest formatem przenośnym, a PlaidCloud importuje go bez strat.

1. Otwórz `convert_yxdb_folder.yxmd` w Alteryx Designer.
2. W narzędziu **Directory** ustaw folder zawierający pliki `.yxdb`.
3. W narzędziu **Dynamic Input** wskaż szablon źródła danych wejściowych (Input Data Source Template) na dowolny jeden plik `.yxdb` z tego folderu.
4. W narzędziu **Output Data** ustaw folder wyjściowy.
5. Uruchom przepływ pracy, a następnie prześlij pliki CSV do Document i zaimportuj je.

<Aside type="caution">
  Narzędzie Dynamic Input wymaga, aby wszystkie pliki w partii miały taki sam układ pól jak plik szablonu. Pliki o innym układzie są pomijane z ostrzeżeniem — okienko wyników Designer wymienia każdy pominięty plik. Zgrupuj różniące się pliki we własnym folderze z własnym szablonem i uruchom ponownie albo zapisz opornych pojedynczo za pomocą opcji A.
</Aside>

Pliki przekonwertowane do CSV tracą typowanie specyficzne dla `.yxdb` (wszystko trafia jako tekst i jest ponownie typowane podczas importu), dlatego wyrywkowo sprawdź typy kolumn zaimportowanych tabel — zwłaszcza dat i liczb dziesiętnych o wysokiej precyzji.
