## Opis

Krok **Żądanie REST** wywołuje API REST jako jeden krok przepływu pracy. To pojedynczy krok w stylu Postmana obejmujący całą pętlę „zbuduj → wyślij → sprawdź": wybierz punkt końcowy (wpisany ręcznie lub zaimportowany z kolekcji Postman, specyfikacji OpenAPI/Swagger albo zapisu HAR), ustaw nagłówki, parametry zapytania i treść żądania, wyślij **żądanie testowe**, aby zobaczyć odpowiedź na żywo, a następnie zapisz krok.

To Ty wybierasz, dokąd trafia odpowiedź. Domyślnie jest analizowana do **tabeli**. Krok może też zapisać odpowiedź w **zmiennych przepływu pracy**, aby późniejszy krok mógł rozgałęziać się według kodu stanu lub odczytać wartość z treści.

Jeśli zamkniesz lub przeładujesz przeglądarkę przed zapisem, edytor zachowuje lokalną wersję roboczą w tej przeglądarce. Otwórz ponownie ten sam krok i po wyświetleniu monitu wybierz **Przywróć**, aby odzyskać niezapisane ustawienia żądania.

<Aside type="note">Krok Żądanie REST zastępuje starsze kroki w stylu REST jednym ujednoliconym krokiem. Używaj go w nowej pracy; istniejące kroki REST nadal działają.</Aside>

## Zanim zaczniesz

Zwykle przyda Ci się **połączenie** rodzaju REST, które przechowuje bazowy adres URL i uwierzytelnianie usługi. Krok może też wywołać w pełni kwalifikowany adres URL bezpośrednio, bez połączenia. Zobacz [połączenia REST](/pl/reference/connectors/rest/).

## Dodawanie kroku Żądanie REST

1. Otwórz przepływ pracy i dodaj krok w wybranym miejscu.
2. Wybierz **Żądanie REST (unified)** jako typ kroku (w grupie kroków REST). Edytor otwiera się z kartą **Żądanie**, kartą **Odpowiedź** i kartą **Wybór danych tabeli**.

## Budowanie żądania

Na karcie **Żądanie**:

### Źródło punktów końcowych

Wybierz, jak podasz punkt końcowy, a PlaidCloud wypełni za Ciebie żądanie:

- **Ręcznie** — wpisz metodę i adres URL samodzielnie.
- **Z definicji API połączenia** — użyj definicji OpenAPI/Swagger zapisanej w wybranym połączeniu, aby nie powtarzać jej w każdym kroku. Zobacz [Ponowne użycie definicji API połączenia](#ponowne-użycie-definicji-api-połączenia) poniżej.
- **Kolekcja Postman (plik)** / **Kolekcja Postman (URL)** — import z kolekcji Postman.
- **OpenAPI / Swagger (URL)** / **OpenAPI / Swagger (plik)** — import ze specyfikacji API.
- **Archiwum HAR (plik)** — import żądania zapisanego z dziennika sieciowego przeglądarki.

W przypadku zaimportowanego źródła wybierz **Załaduj katalog**, aby wyświetlić dostępne punkty końcowe, a następnie wybierz jeden w polu **Punkt końcowy**. Krok wypełnia jego metodę, adres URL, nagłówki, parametry zapytania i treść, używając przykładowej lub domyślnej wartości każdego parametru; opcjonalny parametr, który nie ma żadnej z nich, startuje jako wyłączony. Jeśli żądanie zawiera już coś, co wpisano, krok pyta przed zastąpieniem. Naciśnij **Ctrl+Z** (**Cmd+Z** na komputerze Mac), gdy nie piszesz w polu, lub wybierz **Cofnij zamianę**, aby przywrócić poprzednie żądanie.

Duży katalog łatwo zawęzić: wpisz tekst w **Filtruj według metody, ścieżki lub nazwy…**, aby wyświetlić tylko pasujące punkty końcowe. Katalog pokazuje, ile punktów końcowych zawiera (**12 of 340** podczas filtrowania) i kiedy został załadowany, a krok informuje, gdy bardzo duża definicja została obcięta na limicie podglądu.

### Wklejanie kolekcji lub specyfikacji zamiast wybierania pliku

Trzy źródła oparte na plikach — kolekcja Postman, OpenAPI/Swagger i archiwum HAR — mają przycisk **Wklej…** obok selektora plików. Użyj go, gdy masz zawartość pod ręką, ale nie zapisano jej w Document: wklej JSON i wybierz **Użyj tego**. Katalog ładuje się od razu, więc nie trzeba potem klikać **Załaduj katalog**.

Wklejona zawartość jest używana zamiast selektora plików i trwa tak długo, jak krok pozostaje otwarty — nie jest zapisywana z krokiem, więc wklej ją ponownie, jeśli otworzysz krok ponownie i chcesz z niej przeładować katalog. Jeśli dla tego samego źródła wybierzesz plik, plik ma pierwszeństwo, a wklejona zawartość jest odrzucana — krok informuje o tym.

Możesz też upuścić plik `.json` na selektor źródła. Krok sprawdza zawartość względem wybranego źródła i informuje, co jest nie tak, na przykład kolekcję Postman wklejoną tam, gdzie oczekiwana jest specyfikacja OpenAPI, albo plik, który nie jest JSON-em, a każde źródło ma łącze **How do I get a …?** wyjaśniające, jak wyeksportować kolekcję Postman, specyfikację OpenAPI lub plik HAR.

<Aside type="note">Wklejanie i upuszczanie akceptują JSON. W przypadku specyfikacji YAML zapisz plik w Document i wybierz go zamiast tego.</Aside>

### Ponowne użycie definicji API połączenia

Konektory zbudowane dla konkretnej usługi już znają jej punkty końcowe. Ogólne połączenia REST i MuleSoft nie — mogą wskazywać dowolne API — więc pozwalają dołączyć definicję API do samego połączenia.

Ustaw ją raz w połączeniu (zobacz [Ogólne połączenie REST](/pl/reference/connectors/rest/generic-rest/#definicja-api)), a następnie w dowolnym kroku używającym tego połączenia:

1. Wybierz połączenie w polu **Połączenie**.
2. Ustaw **Źródło punktów końcowych** na **Z definicji API połączenia**.
3. Wybierz **Załaduj katalog** i wybierz punkt końcowy.

Każdy krok współdzielący to połączenie oferuje tę samą listę punktów końcowych, a aktualizacja definicji w połączeniu aktualizuje je wszystkie.

### Podsumowanie połączenia i środowisko

Pod selektorem **Połączenie** wiersz podsumowania pokazuje, czego użyje krok: typ uwierzytelniania, hosta i liczbę domyślnych nagłówków, które połączenie wysyła z każdym żądaniem. Wybierz przycisk odświeżania obok selektora po zmianie połączenia, aby przeładować jego uwierzytelnianie, hosta i domyślne nagłówki bez ponownego otwierania kroku. Gdy połączenie definiuje środowiska, selektor **Środowisko** wybiera, względem którego krok jest uruchamiany.

<Aside type="note">
**URL** definicji musi być osiągalny z internetu. Jeśli specyfikacja Twojego API jest opublikowana tylko w Twojej sieci, prześlij plik do Document i wybierz go w połączeniu jako plik.
</Aside>

### Połączenie, metoda i punkt końcowy

- **Połączenie** — połączenie REST używane do uwierzytelniania. Pozostaw je nieustawione, aby wywołać w pełni kwalifikowany adres URL bezpośrednio. Użyj skrótu edycji obok selektora, aby wyświetlić lub edytować wybrane połączenie bez opuszczania edytora żądania.
- **Metoda** — `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD` lub `OPTIONS`.
- **Punkt końcowy** — ścieżka (gdy ustawiono połączenie) lub pełny adres URL.

### Nagłówki, parametry zapytania i treść żądania

- **Nagłówki** i **Parametry zapytania** to edytowalne tabele wierszy nazwa/wartość, każdy z przełącznikiem **Włączone** i opisem. Dodawaj wiersze za pomocą **Dodaj** i usuwaj je za pomocą **Usuń**.
- **Treść żądania** zawiera ładunek żądania (JSON, formularz lub dane surowe) w edytorze kodu.

**Formatuj JSON** dodaje wcięcia w treści, a **Waliduj JSON** sprawdza ją i zgłasza wiersz oraz kolumnę każdego błędu. Oba odczytują każdą zmienną `{{…}}` jako wartość, więc Twoje zmienne pozostają dokładnie takie, jak zapisano. **Opis zmiennych…** wymienia każdą zmienną, której możesz użyć w żądaniu, a **Wstaw `{{…}}`** umieszcza zmienną w miejscu kursora.

Podczas edycji krok oznacza problemy pod żądaniem:

- Nazwa nagłówka lub parametru zapytania, która występuje dwukrotnie, przez co jedna wartość zostałaby utracona.
- Nazwa nagłówka, która wygląda na literówkę, z sugestią **Did you mean…**, na przykład `Authorisation` zamiast `Authorization`.
- Sekret, taki jak wartość `Authorization` lub `X-API-Key`, wpisany jawnym tekstem. Zachowaj go w zmiennej projektu i napisz `{{project_var.NAME}}`, aby sekret nie był zapisany w kroku.
- Treść JSON bez nagłówka `Content-Type: application/json`, którą niektóre serwery odrzucają z kodem HTTP 415.
- Adres URL z błędnym schematem, podwójnym ukośnikiem w ścieżce, końcowym ukośnikiem lub zbędnymi spacjami.

### Podstawianie zmiennych

W dowolnym miejscu punktu końcowego, nagłówków, wartości zapytania lub treści możesz wstrzyknąć zmienną w czasie uruchomienia, ujmując jej nazwę w podwójne nawiasy klamrowe: `{{name}}`. Możesz też napisać `{{var.name}}` dla zmiennej uruchomienia przepływu pracy lub `{{project_var.name}}` dla zmiennej projektu — prefiks jest opcjonalny i oba rozwiązują tę samą nazwę.

Edytor wyróżnia wykryte tokeny `{{...}}` w tabelach punktu końcowego, nagłówków i zapytania oraz w edytorze treści, dzięki czemu podstawienia łatwo dostrzec przed testem lub zapisem.

Podstawiane są tylko podwójne nawiasy klamrowe, więc pojedyncze `{` lub `}` w treści JSON pozostaje dokładnie takie, jak zapisano — możesz swobodnie mieszać zmienne z JSON-em, na przykład `{"id": "{{var.order_id}}", "qty": 1}`. Nieznana nazwa zmiennej powoduje niepowodzenie kroku, dzięki czemu literówka od razu wychodzi na jaw.

Gdy przepływ pracy jest uruchamiany przez sensor lub webhook, dostępne są także cztery zmienne wyzwalacza: `{{trigger_sensor_id}}`, `{{trigger_sensor_type}}`, `{{trigger_fired_at}}` i `{{trigger_payload_json}}` (przychodzący ładunek jako ciąg JSON — przeanalizuj go w późniejszym kroku, aby dotrzeć do zagnieżdżonych pól). Przy uruchomieniu ręcznym lub zaplanowanym są one rozwiązywane do pustego ciągu.

### Testowanie żądania

- **Wyślij żądanie testowe** wysyła żądanie z bieżącymi ustawieniami i pokazuje odpowiedź na żywo w tym samym miejscu, dzięki czemu możesz potwierdzić działanie wywołania przed zapisem. Naciśnij **Ctrl+Enter** (**Cmd+Enter** na komputerze Mac), aby wysłać z dowolnego miejsca formularza. Wiersz stanu pokazuje status HTTP i czas odpowiedzi, a licznik czasu rośnie, gdy żądanie jest w toku. (Wysyła to pojedyncze żądanie; stronicowanie działa tylko podczas wykonywania kroku.)
- **Testuj stronicowanie** podąża za skonfigurowanym stronicowaniem i zgłasza, ile rekordów wraca na kolejnych stronach (do limitu podglądu), dzięki czemu możesz potwierdzić, że tryb stronicowania oraz jego łańcuch parametrów/ścieżek działają poprawnie przed pełnym uruchomieniem. Uruchamiane jest tylko tyle stron, ile trzeba do osiągnięcia limitu.
- **Kopiuj jako curl** kopiuje do schowka równoważne polecenie curl do udostępnienia lub debugowania (z zamaskowanymi sekretami).
- **Importuj z curl** działa odwrotnie: wklej polecenie curl — na przykład „Copy as cURL" z przeglądarki — a jego metoda, adres URL, nagłówki i treść zastępują bieżące żądanie. Uwierzytelnianie podstawowe (`-u`) staje się nagłówkiem Authorization; nieobsługiwane opcje są zgłaszane, a nie po cichu pomijane. Użyj **Cofnij zamianę**, aby przywrócić poprzednie wartości.

Odpowiedź otwiera się w przeglądarce z widokami **Sformatowany** i **Zwarty**. Ostatnie pięć wyników testów jest przechowywane, gdy krok jest otwarty, i możesz wybrać jeden, aby go ponownie obejrzeć lub uruchomić ponownie. Gdy odpowiedź zawiera listę rekordów, **Zasugeruj** ustawia **Ścieżka elementów** na pierwszą znalezioną listę.

Grupa **Podgląd żądania** pokazuje żądanie dokładnie tak, jak wysłałoby je uruchomienie, z rozwiązanymi zmiennymi i zamaskowanymi sekretami, bez wysyłania czegokolwiek. Wybierz **Odśwież podgląd** po edycji.

Jeśli zmienisz pola żądania wychodzącego i zapiszesz przed udanym **Wyślij żądanie testowe**, PlaidCloud pyta **Zapisać bez udanego testu?**, a Ty wybierasz **Zapisz mimo to** lub wracasz. W trybie rozgałęziania użyj **Testuj wiersz 1**, aby przetestować pierwszy wiersz tabeli sterującej przed zapisem.

## Kierowanie odpowiedzi

Na karcie **Odpowiedź** ustaw **Miejsce docelowe odpowiedzi**:

### Tabela (domyślnie)

Odpowiedź jest analizowana do **Tabela docelowa**, która jest w tym trybie wymagana. Wybierz istniejącą tabelę lub utwórz ją z selektora; widoki nie są oferowane. Grupa **Stronicowanie i analiza** kontroluje, jak:

- **Format wiersza** — **Obiekt** (domyślnie), gdy każdy rekord jest obiektem JSON, lub **Tablica**, gdy każdy rekord jest listą wartości. Tablica nie jest dostępna z **Jedno żądanie na wiersz tabeli**. **Ścieżka elementów** określa, gdzie w odpowiedzi znajdują się rekordy.
- **Tryb stronicowania** — **Bez stronicowania** (domyślnie), **Stronicowanie z przesunięciem**, **Stronicowanie według numeru strony**, **Stronicowanie według adresu URL następnej strony**, **Stronicowanie kursorem** lub **Stronicowanie według nagłówka Link (RFC 5988)**. **Parametry trybu** i **Ścieżki trybu** określają, które parametry i pola odpowiedzi sterują stronicowaniem, i są dostępne tylko po wybraniu trybu stronicowania. Wybranie trybu wypełnia oba wartościami domyślnymi, które możesz edytować.

  | Tryb | Domyślne parametry trybu | Domyślne ścieżki trybu | Sposób stronicowania |
  | --- | --- | --- | --- |
  | Przesunięcie | `{"offset": "offset", "limit": "limit"}` | `{"has_more": ["has_more"]}` | Wysyła parametry zapytania offset i limit i czyta dalej, dopóki `has_more` w odpowiedzi ma wartość true. |
  | Numer strony | `{"offset": "page"}` | `{"has_more": ["has_more"]}` | Wysyła numer strony w parametrze `page` i nie wysyła limitu. |
  | Adres URL następnej strony | `{}` | `{"next": ["next"]}` | Żąda adresu URL znalezionego w ścieżce `next` każdej odpowiedzi. Względny adres URL jest odczytywany względem strony, z której pochodzi. |
  | Kursor | `{"cursor": "after"}` | `{"has_more": ["has_more"], "cursor": ["next_cursor"]}` | Wysyła kursor z poprzedniej odpowiedzi w parametrze `after`. Dodaj `"send_as": "header"` lub `"send_as": "body_field"` do **Parametry trybu**, aby wysłać go jako nagłówek żądania lub pole treści. Aby odczytać kursor z nagłówka odpowiedzi, takiego jak nagłówek `x-ms-continuation` wysyłany przez Azure Cosmos DB, wpisz `"token_header": "x-ms-continuation"` w **Ścieżki trybu** zamiast `has_more` i `cursor`; ostatnią stroną jest ta bez nagłówka. |
  | Nagłówek Link | `{"rel": "next"}` | `{}` | Podąża za relacją nagłówka odpowiedzi `Link` o nazwie podanej w `rel`. |

  Przesunięcie i Numer strony akceptują więcej kluczy w **Parametry trybu**: `start` to pierwsze przesunięcie lub numer strony (domyślnie 0), `stop_on_empty` zatrzymuje na pierwszej stronie bez rekordów w ścieżce elementów, więc odpowiedź nie potrzebuje pola `has_more`, a `send_limit` określa, czy parametr `limit` jest wysyłany (domyślnie true dla Przesunięcia, false dla Numeru strony).
- **Zrzuć surowy JSON zamiast analizować wiersze** — zapisz surowy ładunek zamiast analizować go do kolumn.
- **Ponowienia** (0 do 100) i **Limit czasu (s)** (1 do 600) — jak żądanie zachowuje się przy awarii i jak długo może trwać. Uruchomienie czeka do ustawionego limitu czasu; **Wyślij żądanie testowe**, **Testuj wiersz 1** i **Testuj stronicowanie** czekają najwyżej 300 s. Ponowienia obejmują awarie połączenia, błędy serwera (5xx) i ograniczanie szybkości (HTTP 429) dla metod idempotentnych (GET, HEAD, OPTIONS, DELETE). POST, PUT lub PATCH jest ponawiany tylko po odpowiedzi o ograniczeniu szybkości (HTTP 429), która informuje, że serwer nic z nim nie zrobił, i nigdy po błędzie serwera, więc treść żądania nieidempotentnego nigdy nie jest wysyłana dwa razy, gdy serwer mógł już zadziałać; gdy API zwraca nagłówek `Retry-After`, krok czeka żądany interwał (maksymalnie 2 minuty) przed ponowieniem.

Karta **Wybór danych tabeli** mapuje pola odpowiedzi na kolumny tabeli docelowej. **Sprawdź źródło → Populate** wypełnia mapowanie z odpowiedzi na żywo: wysyła żądanie kroku przez jego połączenie, tak jak zrobiłoby to uruchomienie. Wymaga połączenia i pyta najpierw, gdy metoda jest inna niż GET, HEAD lub OPTIONS. **Podsumuj** i **Unikalne** nie są tu oferowane, ponieważ krok zapisuje przeanalizowaną odpowiedź bezpośrednio w tabeli docelowej.

### Zmienne przepływu pracy

Ustaw **Miejsce docelowe** na **Zmienne przepływu pracy** i podaj **Prefiks zmiennej** (zwykła nazwa, taka jak `my_call`). Krok wysyła **jedno** żądanie i zapisuje cztery zmienne przepływu pracy:

| Zmienna | Zawartość |
|----------|----------|
| `{prefix}_status` | Kod stanu HTTP (na przykład `200`). |
| `{prefix}_body` | Treść odpowiedzi jako ciąg (odpowiedzi JSON są przechowywane jako tekst JSON). |
| `{prefix}_headers` | Nagłówki odpowiedzi jako tekst JSON. |
| `{prefix}_elapsed_ms` | Czas trwania żądania w milisekundach. |

Odwołuj się do nich w dalszych krokach jak do każdej zmiennej przepływu pracy — na przykład `{my_call_status}`. To element konstrukcyjny wzorców „wyślij jedno żądanie, a następnie rozgałęź według wyniku".

<Aside type="caution">Prefiks musi zaczynać się od litery lub podkreślenia i zawierać wyłącznie litery, cyfry i podkreślenia. Nie może być jedną z zarezerwowanych nazw `cloud`, `project`, `model` ani `date`. W trybie zmiennych krok przechwytuje pojedynczą odpowiedź — stronicowanie i analiza wierszy nie mają zastosowania.</Aside>

## Wysyłanie jednego żądania na wiersz tabeli

Domyślnie krok wysyła **jedno** żądanie. Aby wywołać API raz dla każdego wiersza tabeli — na przykład sprawdzić każdy identyfikator klienta w tabeli lub wysłać POST z każdym wierszem jako rekordem — ustaw **Wyślij** (na karcie Żądanie) na **Jedno żądanie na wiersz tabeli**. Ujawnia to pola tabeli sterującej:

- **Tabela sterująca** — wybierz tabelę, której wiersze sterują żądaniami. Wybierz ją z tabel przepływu pracy za pomocą selektora lub wpisz nazwę tabeli. Kolumny każdego wiersza są dostępne jako tokeny `{{row.column}}`.
- **Filtr tabeli sterującej** *(opcjonalnie)* — klauzula SQL `WHERE` ograniczająca, które wiersze są używane.
- **Kolumny kluczowe** *(opcjonalnie)* — rozdzielone przecinkami kolumny tabeli sterującej przenoszone do każdego wiersza wyniku, aby wyniki można było złączyć z tabelą sterującą.
- **Limit wierszy** i **Współbieżność** — maksymalna liczba przetwarzanych wierszy i liczba jednocześnie uruchomionych żądań.
- **Maks. liczba żądań/s** *(opcjonalnie)* — ogranicz, jak szybko żądania startują we wszystkich procesach roboczych, aby nagły wzrost nie przekroczył limitu szybkości API (0 = bez limitu). Wartość może być ułamkiem: 0,5 uruchamia jedno żądanie co dwie sekundy. Wartość powyżej 1000 jest uruchamiana jako 1000 z ostrzeżeniem. Jest to niezależne od **Współbieżność**: współbieżność ogranicza, ile żądań działa naraz, a Maks. liczba żądań/s reguluje, jak często startuje nowe.
- **Add Idempotency-Key header** *(opcjonalnie)* — dla pojedynczego (bez stronicowania) żądania POST, PUT lub PATCH na wiersz wysyła stabilny nagłówek `Idempotency-Key` wyprowadzony z każdego wiersza, aby ponowne uruchomienie kroku nie tworzyło podwójnych rekordów w API obsługującym idempotentność (ten sam wiersz zawsze wysyła ten sam klucz, więc API usuwa duplikat). Jest ignorowany, z ostrzeżeniem, dla GET/HEAD/DELETE lub gdy włączony jest tryb stronicowania. Żądanie, które samo ustawia `Idempotency-Key`, zachowuje go.
- **Odpowiedź** — jak każda odpowiedź staje się wierszami. **Przeanalizowane rekordy** (domyślnie) zapisuje każdy rekord odpowiedzi jako wiersz. **Tekst (jeden wiersz na żądanie)** zapisuje jeden wiersz na żądanie z kolumnami `DownloadData` i `DownloadHeaders`; nieudane żądanie jest pomijane. **Tekst surowy, błędy jako wiersze** również zapisuje jeden wiersz na żądanie, ale zachowuje treść dokładnie tak, jak wysłał ją serwer, dodaje kolumnę `DownloadStatus` i zachowuje błąd HTTP lub transportu jako wiersz z treścią błędu i statusem. Poświadczenia są maskowane w treści, nagłówkach i tekście błędu każdego surowego wiersza, a przekierowanie do innego źródła nie jest wykonywane w żądaniu niosącym poświadczenia. Stronicowanie nie ma zastosowania do trybów tekstowych. W **Tekst (jeden wiersz na żądanie)** opcja **Keep error response** (`keep_error_response`) zapisuje treść odpowiedzi HTTP 400 lub wyższej w wierszu tak jak przy powodzeniu, zamiast kończyć wiersz niepowodzeniem, a **Dodaj DownloadStatus, DownloadReason i DownloadUrl do wyniku** (`response_meta`) dodaje kolumny `DownloadStatus`, `DownloadReason` i `DownloadUrl` zawierające status, powód i końcowy adres URL odpowiedzi. Obie są domyślnie wyłączone. Formularz kroku ma opcję **Dodaj DownloadStatus, DownloadReason i DownloadUrl do wyniku**; `keep_error_response` ustaw za pomocą asystenta AI lub REST API.
- **Continue on error** — gdy włączone, wiersz, który kończy się niepowodzeniem, jest rejestrowany, a krok kończy się ostrzeżeniem zamiast przerwać przy pierwszym niepowodzeniu. Dziennik uruchomienia wymienia kilka pierwszych nieudanych wierszy (według ich kolumn kluczowych) i błąd, jaki każdy napotkał, abyś wiedział, które wiersze zawiodły i dlaczego.

Używaj tokenów `{{row.column}}` w dowolnym miejscu punktu końcowego, zapytania, nagłówków lub treści, aby podstawić wartości danego wiersza — na przykład `GET /customers/{{row.customer_id}}`. Wartość w parametrze zapytania jest kodowana jako URL raz, więc serwer otrzymuje `A 1` i `a/b` tak, jak wpisano. Wcześniejsze wersje kodowały ją dwukrotnie, a serwer otrzymywał `A%201` i `a%2Fb`. Jeśli krok POST, PUT lub PATCH ma włączone **Add Idempotency-Key header** i wartość wiersza wymagającą kodowania w zapytaniu, jego klucz zmienia się jednorazowo po aktualizacji, ponieważ żądanie się zmieniło. Ponowne uruchomienie obejmujące moment aktualizacji może wysłać jedno powtórzone żądanie dla każdego takiego wiersza. Wartości złożone wyłącznie z liter, cyfr i `-._~` pozostają bez zmian. Rekordy odpowiedzi każdego wiersza są analizowane do tabeli docelowej (z dołączonymi z przodu kolumnami kluczowymi); przy włączonym **Zrzuć surowy JSON** otrzymujesz zamiast tego jeden wiersz na żądanie.

Menu **Wstaw `{{row.column}}`** wymienia kolumny wybranej tabeli sterującej, dzięki czemu możesz wstawić token w stylu `{{row.customer_id}}` do punktu końcowego lub treści — w zależności od tego, które pole edytowano ostatnio — zamiast wpisywać nazwy kolumn ręcznie. Podczas edycji formularz wymienia też użyte tokeny `{{row.column}}` i oznacza na czerwono te, które nie są kolumną tabeli sterującej, więc literówki wychodzą na jaw przed uruchomieniem kroku.

**Testuj wiersz 1** odczytuje pierwszy wiersz tabeli sterującej (uwzględniając filtr tabeli sterującej), podstawia jego wartości do punktu końcowego, zapytania, nagłówków i treści i wysyła to jedno żądanie — dzięki czemu możesz potwierdzić, że rozgałęzianie jest poprawnie podłączone, zanim uruchomisz je dla każdego wiersza. Odpowiedź jest pokazywana w tym samym miejscu jak przy **Wyślij żądanie testowe**, wraz z użytymi wartościami wiersza tabeli sterującej. **Preview Row 1** podobnie rozwiązuje wartości `{{row.column}}` pierwszego wiersza tabeli sterującej i pokazuje rozwiązane żądanie bez jego wysyłania.

<Aside type="note">Jedno żądanie na wiersz tabeli zapisuje do tabeli — nie może przechwytywać do zmiennych przepływu pracy. Miejsce docelowe odpowiedzi pozostaje **Tabela**.</Aside>
