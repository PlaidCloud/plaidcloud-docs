Tag oznacza commit jako istotny — zwykle jest to wersja, np. `v1.2.0`. Wydanie rozbudowuje tag, dodając czytelne dla człowieka notatki i opcjonalne załączniki, dzięki czemu użytkownicy mogą przeglądać i pobierać konkretne wersje z interfejsu webowego.

## Tworzenie tagu

Tag można utworzyć w interfejsie lub w lokalnym klonie.

**W interfejsie:**

1. Otwórz repozytorium i wybierz **Wydania**, a następnie **Tagi**.
2. Wybierz **Create Tag**.
3. Wpisz nazwę tagu (na przykład `v1.2.0`), wybierz docelową gałąź lub commit i wybierz **Create Tag**.

**Z wiersza poleceń:**

```bash
git tag v1.2.0
git push origin v1.2.0
```

Aby otagować konkretny wcześniejszy commit, podaj jego identyfikator zamiast polegać na `HEAD`:

```bash
git tag v1.2.0 abc1234
git push origin v1.2.0
```

## Publikowanie wydania

1. Otwórz repozytorium i wybierz **Wydania**.
2. Wybierz **New Release**.
3. W polu **Tag Name** wybierz istniejący tag lub wpisz nową nazwę, aby utworzyć tag na bieżącym końcu gałęzi domyślnej.
4. Wpisz **Release Title** i napisz notatki do wydania w treści Markdown — tutaj powinny trafić listy zmian, instrukcje aktualizacji i znane problemy.
5. Wybierz **This is a pre-release**, jeśli wersja nie jest gotowa do ogólnego użytku, lub **Zapisz wersję roboczą**, aby dokończyć później bez publikowania.
6. Wybierz **Publish Release**, gdy wydanie będzie gotowe.

<Aside>Robocze wydania są widoczne tylko dla członków repozytorium z dostępem do zapisu. Wersja wstępna jest widoczna dla wszystkich z dostępem, ale jest wyłączona z oznaczenia „Latest” w przeglądzie repozytorium.</Aside>

## Dołączanie plików

Przesłane pliki pojawiają się na stronie wydania jako nazwane łącza do pobrania obok automatycznie wygenerowanego archiwum źródeł.

1. W formularzu nowego lub edytowanego wydania przejdź do sekcji **Attach Files**.
2. Przeciągnij pliki na obszar przesyłania albo wybierz go, aby przeglądać — typowe wybory to zbudowane pliki binarne, skompresowane archiwa, sumy kontrolne i podpisy.
3. Powtórz dla każdego pliku, a następnie opublikuj lub zaktualizuj wydanie.

Utrzymuj rozsądny rozmiar poszczególnych plików, aby pobieranie pozostało szybkie dla zespołu.

<Aside type="tip">W przypadku instalowalnych pakietów — modułów npm, obrazów kontenerów, kół PyPI i podobnych — lepszym wyborem niż załączniki wydań jest [rejestr pakietów](/pl/guides/git/packages/). Rozumie on rozwiązywanie wersji, metadane zależności i narzędzia klienckie (`npm`, `pip`, `docker pull`) w sposób, którego zwykłe pobranie pliku nie zapewnia.</Aside>

## Wyświetlanie i pobieranie wydań

1. Wybierz **Wydania**, aby zobaczyć pełną listę, od najnowszych.
2. Najnowsze wydanie, które nie jest wersją wstępną, jest wyróżnione plakietką **Latest**.
3. Każda pozycja pokazuje nazwę tagu, tytuł wydania, notatki oraz łącza do:
   - **Source code** — automatycznie generowane archiwa `zip` i `tar.gz` otagowanego commita.
   - **Assets** — wszystkie pliki dołączone podczas publikowania wydania.
4. Wybierz łącze pliku, aby pobrać go bezpośrednio, lub skopiuj adres URL, aby go udostępnić.

Aby porównać dwa wydania, otwórz ich nazwy tagów jako adres URL porównania:

```bash
https://git.example.plaidcloud.com/you/my-repo/compare/v1.1.0...v1.2.0
```
