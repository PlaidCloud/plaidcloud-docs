## Tworzenie gałęzi

Pracuj na nowej gałęzi, aby zmiany pozostały oddzielone od gałęzi domyślnej, dopóki nie będą gotowe.

**W interfejsie:**

1. Otwórz repozytorium i wybierz selektor gałęzi w lewym górnym rogu (pokazuje nazwę bieżącej gałęzi).
2. Wpisz nazwę nowej gałęzi w polu wyszukiwania i wybierz **Create Branch**.

**Lokalnie:**

1. Utwórz gałąź i przełącz się na nią: `git checkout -b feature-x`
2. Wprowadź zmiany, a następnie dodaj je do poczekalni i zatwierdź: `git add .`, a potem `git commit -m "Describe what changed"`
3. Wypchnij gałąź do PlaidCloud Git: `git push -u origin feature-x`

## Otwieranie pull requesta

1. Otwórz repozytorium i wybierz kartę **Pull Requests**, a następnie **New Pull Request**.
2. Ustaw jako gałąź **Porównaj** swoją gałąź funkcji, a jako gałąź **Podstawowy** gałąź docelową (zwykle `main` lub `master`).
3. Napisz czytelny tytuł oraz opis wyjaśniający, co się zmieniło i dlaczego.
4. Aby powiązać pokrewne zgłoszenia, dodaj w opisie słowo kluczowe zamykające — na przykład `Closes #12` — dzięki czemu zgłoszenie zamknie się automatycznie po scaleniu pull requesta.
5. W razie potrzeby przypisz recenzentów, a następnie wybierz **Create Pull Request**.

## Recenzowanie zmian

Recenzenci przeglądają pull request bez scalania czegokolwiek:

1. Otwórz pull request i wybierz **Files Changed**, aby przeczytać różnice.
2. Wybierz dowolny wiersz w różnicach, aby zostawić komentarz w tekście do tej konkretnej zmiany.
3. Po zakończeniu przekaż ogólną ocenę: **Zatwierdź**, aby wyrazić zgodę, lub **Request Changes**, aby najpierw poprosić o poprawki.
4. Autor wypycha kolejne commity do tej samej gałęzi, aby uwzględnić uwagi — pull request aktualizuje się automatycznie, bez potrzeby otwierania nowego.
5. Recenzenci oznaczają poszczególne wątki komentarzy jako rozwiązane, gdy każda kwestia zostanie uwzględniona.

<Aside>Administrator repozytorium może włączyć ochronę gałęzi domyślnej, aby wymagać minimalnej liczby zatwierdzeń przed scaleniem pull requesta.</Aside>

## Scalanie

Gdy pull request zostanie zatwierdzony:

1. Wybierz metodę scalania z listy rozwijanej obok przycisku **Merge**:
   - **Create a merge commit** — zachowuje pełną historię gałęzi dzięki commitowi scalającemu.
   - **Squash and merge** — łączy wszystkie commity z gałęzi w jeden commit w gałęzi docelowej.
   - **Rebase and merge** — odtwarza commity gałęzi w gałęzi docelowej bez commita scalającego.
2. Wybierz **Merge**, aby zakończyć.
3. Opcjonalnie wybierz **Delete Branch**, aby posprzątać gałąź funkcji, gdy nie jest już potrzebna.
