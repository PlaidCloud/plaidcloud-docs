Opcja **Eksportuj do formatu przenośnego** pakuje przepływy pracy projektu jako samodzielny program w Pythonie, który działa na [DuckDB](https://duckdb.org) bez połączenia z PlaidCloud. Tworzy przenośną kopię logiki i danych projektu, która działa offline, samodzielnie.

Jest to eksport jednokierunkowy. Wygenerowany pakiet jest migawką z określonego momentu; nie synchronizuje się z powrotem, a ponowny eksport po zmianach tworzy nowy pakiet.

<Aside type="caution" title="Wierność w miarę możliwości">
Eksport odtwarza kroki transformacji oparte na SQL dokładnie. Operacje własnościowe i z efektami ubocznymi — alokacje, ładowanie wymiarów, powiadomienia, kroki dokumentów i raportów, skrypty — są eksportowane jako **namiastki**: ich oryginalna konfiguracja jest zachowana, a tam, gdzie tabela wyjściowa została zmaterializowana, jej dane są dołączone jako migawka, ale sam krok nie jest uruchamiany ponownie. Wierność każdego kroku jest zapisana w `COVERAGE.md` wewnątrz pakietu. Aby uzyskać gwarantowane, w pełni przeliczone wyniki, uruchom projekt w PlaidCloud.
</Aside>

## Eksportowanie projektu

1. Otwórz **Analyze** i wybierz kartę **Projekty**.
2. Wybierz pojedynczy projekt.
3. Otwórz menu **Akcje** (lub kliknij projekt prawym przyciskiem myszy) i wybierz **Eksportuj do formatu przenośnego** — znajduje się obok **Eksportuj projekt**.
4. W oknie dialogowym:
   - **Konto dokumentów** — konto dokumentów, na którym zapisywany jest pakiet.
   - **Ścieżka folderu** — folder na tym koncie, na przykład `/exports`.
   - **Include data** — po zaznaczeniu (domyślnie) tabele źródłowe i migawkowe są dołączane jako Parquet, aby pakiet działał bez zewnętrznych danych. Odznacz, aby dostarczyć tylko kod i kontrakty schematów, które następnie wypełnisz samodzielnie.
5. Kliknij **Eksportuj**. Po zakończeniu komunikat potwierdza, gdzie zapisano pakiet i ile tabel zapisano w migawce.

Ta akcja wymaga dostępu do projektu i odczytu jego tabel — tego samego poziomu dostępu, który jest dziś potrzebny do eksportu danych tabel.

## Zawartość pakietu

Eksport to plik `.zip` zawierający:

- `pipeline_<workflow>.py` — jeden skrypt na przepływ pracy, z krokami w kolejności wykonania.
- `config.py` — wybór silnika (domyślnie DuckDB) i nazwa schematu projektu.
- `_runtime.py` — mała warstwa zgodności silnika; jedyna zależność poza DuckDB.
- `stubs.py` — funkcje bez działania dla operacji nieprzenośnych, z których każda zawiera oryginalną konfigurację kroku.
- `data/` — migawki Parquet tabel źródłowych i zamrożonych (gdy zaznaczono **Include data**).
- `requirements.txt` — zależności Pythona (tylko `duckdb`).
- `README.md`, `COVERAGE.md`, `RUN_ORDER.md` — jak go uruchomić, wierność poszczególnych kroków oraz kolejność uruchamiania skryptów przepływów pracy.

## Uruchamianie pakietu

1. Rozpakuj pakiet i utwórz środowisko Pythona:

   ```bash
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. Uruchom każdy skrypt przepływu pracy w kolejności podanej w `RUN_ORDER.md`:

   ```bash
   python pipeline_<workflow>.py
   ```

Każdy skrypt buduje swoje tabele w lokalnej bazie DuckDB (domyślnie `export.duckdb`). Kroki transformacji SQL są przeliczane na żywo; kroki-namiastki wypisują komunikat i pozostawiają na miejscu swoje wyjście z migawki. Aby skierować pakiet na własny magazyn danych zamiast DuckDB, ustaw `ENGINE` w `config.py`.
