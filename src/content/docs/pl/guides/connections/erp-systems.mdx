**System** to jedno połączenie ERP w jednym środowisku. Krok **Księgowanie dokumentów**, księgowanie z pliku i każdy inny sposób księgowania (zobacz [Księgowanie dokumentów w systemach ERP](/pl/guides/connections/post-documents/)) wysyłają każdy dokument do systemu, a system decyduje, jak dokument jest budowany, sprawdzany i wysyłany. Każde połączenie ERP, które widzisz, pojawia się jako osobny system — pięć połączeń SAP to pięć systemów, chmurowych i lokalnych obok siebie — a to samo połączenie w środowisku piaskownicy i produkcyjnym [środowisku](/pl/guides/connections/create-connection/#środowiska) to dwa systemy, każdy z własnymi ustawieniami.

Systemy konfigurujesz raz dla każdego środowiska. Wszystkie projekty w tym środowisku współdzielą siatkę określającą, która jednostka księguje gdzie, oraz ustawienia każdego systemu. Tylko uruchomienie produkcyjne jest ustawiane dla projektu.

## Otwieranie systemów

Otwórz [Rejestr księgowań](/pl/guides/connections/posting-register/) i wybierz **Systemy** w grupie **Ustawienia** na pasku po lewej stronie. Nagłówek zawiera:

- Selektor środowiska: środowisko, którego systemy są wyświetlane.
- Selektor projektu, początkowo ustawiony na **Brak projektu**. Wybierz projekt, aby zobaczyć, czy każdy system jest w nim rzeczywisty, i aby uruchomić produkcyjnie.
- **Akcje**, z pozycjami **Uruchom produkcyjnie w tym projekcie…** (widoczna dla architekta projektu), **Kopiuj do innego środowiska…** (widoczna dla administratora obszaru roboczego), **Zasugeruj, która jednostka księguje gdzie…** i **Historia zmian**.

Strona pokazuje dwie karty: **Systemy · *środowisko*** i **Która jednostka księguje gdzie**. Gdy w środowisku nie ma żadnego połączenia ERP, strona wyświetla **Brak systemów do księgowania**: dodaj połączenie z systemem ERP w sekcji Połączenia, a pojawi się tutaj.

## Lista systemów

Każdy system to jeden wiersz: jego nazwa, typ ERP i zestaw plakietek.

| Plakietka | Co oznacza |
|---|---|
| **Chmura** | System chmurowy. |
| **Lokalnie · agent online** | System lokalny, którego agent skontaktował się w ciągu ostatnich pięciu minut. |
| **Lokalnie · agent offline od *czas*** / **Lokalnie · agent niepołączony** | Agent nie jest online lub żaden agent nie obsługuje tego środowiska. |
| **Może księgować** | Do systemu można księgować. |
| **Nie sprawdzono** | System lokalny, którego agent nie jest online. |
| **Rzeczywiste** / **Symuluj** | Wyświetlane tylko po wybraniu projektu: czy ten system księguje naprawdę w tym projekcie. |
| **Wycofany** | System nie przyjmuje nowych księgowań. Wyświetlane zamiast Rzeczywiste lub Symuluj. |

Wiersz może mieć też dwa przyciski:

- **Połącz ponownie** — wyświetlany, gdy agent systemu lokalnego nie jest online. Otwiera połączenie, aby można było zalogować się ponownie.
- **Uruchom produkcyjnie ›** — wyświetlany architektowi projektu, po wybraniu projektu, przy systemie, który nie jest wycofany, może księgować i nadal działa w trybie Simulate. Zobacz [Uruchomienie produkcyjne](#uruchomienie-produkcyjne).

### Co otwiera wiersz

Otwórz wiersz przełącznikiem po jego lewej stronie. Wyświetla trzy elementy i rząd linków.

**Co zostało** to lista kontrolna tego, co dzieli system od księgowania, z informacją, kto wykonuje każdą pozycję. Pozycja, która jest wykonana, jest zaznaczona i oznaczona jako wykonana.

| Pozycja | Kto | Gotowe, gdy |
|---|---|---|
| Konto usługi i jego uprawnienia | **IT** | Zawsze wykonane na razie; nie ma nic do skonfigurowania. |
| Agent zainstalowany i online (tylko system lokalny) | **IT** | Agent jest online. |
| Jakaś jednostka księguje do tego systemu | **Administrator obszaru roboczego** | Wiersz sekcji [Która jednostka księguje gdzie](#która-jednostka-księguje-gdzie) wskazuje ten system. |
| Uruchomienie produkcyjne | **Architekt projektu** | System jest rzeczywisty w wybranym projekcie. |

**Co potrafi** to jedna linia, na przykład „Przyjmuje zapisy dziennika, faktury klientów · odwraca zapisy dziennika · odpowiada w wywołaniu”. Wymienia typy dokumentów, które system przyjmuje, te, które potrafi odwrócić, oraz to, czy jego odpowiedź wraca **odpowiada w wywołaniu**, czy **odpowiada później**. Pełna lista dla każdego systemu znajduje się poniżej, w sekcji [Co potrafi każdy system](#co-potrafi-każdy-system).

**Kopia jego list** pokazuje, jak stara jest kopia kont, spółek i okresów systemu, z przyciskami **Odśwież teraz** i **Wyświetl kopię**. Zobacz [Kopia list systemu](#kopia-list-systemu).

Linki pod nimi to **Dla IT**, **Ustawienia…**, **Oznacz jako wycofany** (lub **Przywróć z wycofanych**) oraz **Historia**, która otwiera [Historię zmian](#historia-zmian) tylko dla tego systemu.

## Dostępne ustawienia

Każde ustawienie ma wartość początkową, a większość projektów nigdy żadnego nie zmienia.

| Ustawienie | Gdzie | Kto zmienia | Wartość początkowa |
|---|---|---|---|
| Która jednostka księguje gdzie | [Systemy](#która-jednostka-księguje-gdzie), raz dla każdego środowiska | Administrator obszaru roboczego | Brak wierszy. Gdy nie ma wierszy, jedyny system, który nie jest wycofany i jest wymieniony w sekcji **Systemy**, przyjmuje wszystkie jednostki. |
| Wycofany | Wiersz systemu | Administrator obszaru roboczego | Nie wycofany |
| Symulacja lub księgowanie rzeczywiste | [Uruchomienie produkcyjne](#uruchomienie-produkcyjne), dla każdego systemu i każdego projektu | Architekt projektu | Symulacja |
| **Wartości wymagane za każdym razem** | [Ustawienia](#ustawienia-systemu) systemu | Administrator obszaru roboczego | Brak |
| **Dopasowania kodów** (w tym dopasowanie jednostki) | [Ustawienia](#ustawienia-systemu) systemu | Administrator obszaru roboczego | Brak |
| **Własna funkcja klienta** (SAP lokalny) | [Ustawienia](#ustawienia-systemu) systemu | Administrator obszaru roboczego | Brak lub funkcja, którą wnosi przekonwertowany krok |
| Reguły wstrzymania | [Reguły wstrzymania](#reguły-wstrzymania), dla każdego systemu | Administrator rejestru (`erp.register.admin`) | Nic nie jest wstrzymane |
| **Wstrzymaj do decyzji osoby** | Krok, w sekcji **Więcej ▸** | Twórca kroku | Nic nie jest wstrzymane |
| **Kto otrzymuje powiadomienie** | Krok, w sekcji **Więcej ▸** | Twórca kroku | **Osoba, która rozpoczęła uruchomienie** |
| **Konto zaokrągleń i limit** | Krok, w sekcji **Więcej ▸** | Twórca kroku | Bez zaokrągleń |
| **Gdy zaksięgowany dokument wraca zmieniony** | Krok, w sekcji **Więcej ▸** | Twórca kroku | **Zapytaj (wartość początkowa). Trafia do sekcji Wymaga uwagi z dwiema opcjami.** |

Cztery ustawienia kroku są opisane razem z krokiem w [Księgowanie dokumentów w systemach ERP](/pl/guides/connections/post-documents/); własne wstrzymanie kroku jest opisane [poniżej](#własne-wstrzymanie-kroku).

## Ustawienia systemu

Wybierz **Ustawienia…** w otwartym wierszu. Okno **Ustawienia: *system*** może edytować tylko administrator obszaru roboczego; pozostali widzą **Tylko administrator obszaru roboczego może to zmieniać.** **Zapisz** zastępuje całe ustawienia systemu, a każda zmiana jest zapisywana w [Historii zmian](#historia-zmian).

**Wartości wymagane za każdym razem** to wartości dodawane do każdego dokumentu wysyłanego do tego systemu, w parach **Wartość** i **Ustaw na**. System odczytuje potrzebne mu wartości według nazwy, a własna kolumna dokumentu o tym samym znaczeniu ma pierwszeństwo przed wartością systemu:

| System | Wartość | Do czego służy |
|---|---|---|
| Sage Intacct | `gl_journal_id` | Dziennik, do którego księgowany jest zapis dziennika, gdy dokument nie ma `journal_type`. |
| Sage 100 | `bank_code` | Rachunek bankowy, z którego obciążana jest płatność, gdy dokument nie ma `bank_code`. |

**Dopasowania kodów** określają, że kod tutaj jest innym kodem w systemie: **Wymiar**, **Nasz kod** i **Kod w systemie**. Użyj wymiaru `entity` dla jednostki, której spółka w systemie ma inny kod, oraz `account` dla konta. [Sprawdzenia](#sprawdzenia-względem-list) wyszukują kod na listach systemu za pomocą jego dopasowania lub w postaci, w jakiej został zapisany, gdy dopasowania nie ma, a dopasowanie jednostki pozwala też siatce [zasugerować](#sugerowane-wiersze) ten system dla tej jednostki.

**Własna funkcja klienta** pojawia się tylko dla SAP lokalnego. Podaj funkcję dla każdego **Typu dokumentu**. Ustawienia wskazują tylko funkcję: dopasowanie pól każdej funkcji — które pole SAP przyjmuje którą kolumnę — jest przechowywane w systemie bez zmian, a funkcja, którą wniósł przekonwertowany krok księgowania SAP, zachowuje dopasowanie pól, które miał krok. Zobacz [SAP lokalny](#sap-lokalny).

## Która jednostka księguje gdzie

Druga karta to siatka określająca, która jednostka księguje do którego systemu, od jakiej daty, ustawiana raz dla każdego środowiska i współdzielona przez wszystkie projekty w nim. Każdy wiersz to jednostka, **→**, system i opcjonalne pole **Od (RRRR-MM-DD)**.

1. Wybierz **Dodaj wiersz**, wpisz jednostkę i wybierz system z listy **Wybierz system**. Oferowane są tylko systemy, które nie są wycofane.
2. Pozostaw **Od (RRRR-MM-DD)** puste dla „od początku” lub podaj datę, od której jednostka zaczyna księgować do tego systemu. Aby przenieść jednostkę do innego systemu w trakcie roku, zachowaj jej pierwszy wiersz i dodaj drugi wiersz dla nowego systemu od daty przeniesienia, na przykład `2026-07-01`.
3. Wybierz **Zapisz**. Data w innej postaci jest odrzucana z komunikatem **Data wygląda tak: 2026-07-01.**

Edycja siatki wymaga administratora obszaru roboczego; pozostali widzą ją tylko do odczytu. Zapisanej już jednostki nie można zmienić nazwy: usuń jej wiersz krzyżykiem na końcu i dodaj inny. Jednostki, które wskazały dokumenty, ale których nie wskazuje jeszcze żaden wiersz, są wyświetlane bez wybranego systemu; gdy nie ma żadnej, karta wyświetla **Brak jednostek. Są to te, które znaleziono w księgowanych tabelach. Dodaj wiersz, aby jakąś wskazać.**

### Jak dokument znajduje swój system

Dokument jest księgowany przez systemy środowiska swojego projektu.

- Jego system to najnowszy wiersz jednostki, którego data **Od** przypada nie później niż w dniu daty księgowania dokumentu (dzisiaj, gdy dokument jej nie ma).
- Gdy siatka środowiska nie ma żadnych wierszy, a w sekcji **Systemy** jest wymieniony tylko jeden system, który nie jest wycofany, ten system przyjmuje każdy dokument.
- Dokument, którego jednostki nie obejmuje w tym dniu żaden wiersz, nie jest księgowany i informuje, że dla jego jednostki nie ma systemu.
- Dokument, którego wiersz wskazuje wycofany system, nie jest księgowany i informuje, że system jest wycofany.

### Sugerowane wiersze

Dla jednostki, której nie wskazuje jeszcze żaden wiersz, siatka sugeruje system, gdy dokładnie jeden niewycofany system w środowisku wskazuje tę jednostkę — przez [dopasowanie kodu](#ustawienia-systemu) `entity` lub we własnej kopii listy spółek. Wiersz pokazuje **Sugerowane** i pozostaje tylko do odczytu, dopóki nie wybierzesz **Akceptuj**; zapisywane są tylko zaakceptowane wiersze.

**Zasugeruj, która jednostka księguje gdzie…** w menu **Akcje** to sugestia Weave oparta na Data Foundation: po wybraniu projektu wypełnia każdą jednostkę, którą załadował Foundation projektu, połączeniem, z którego ją załadował. Nic nie jest obliczane przez model i nic nie jest zapisywane: wiersze są wypełniane, komunikat podaje ich liczbę, a Ty czytasz każdy z nich i wybierasz **Zapisz**. Gdy nic nie załadowano, wyświetla **Na razie brak sugestii.**

### Wiersze, których nie możesz tu zmienić

- Wiersz, którego system jest wycofany, jest wyświetlany tylko do odczytu z oznaczeniem **Wycofany**. Zapis siatki go zachowuje.
- Wiersz, którego systemu nie widzisz, jest wyświetlany tylko do odczytu z oznaczeniem **Brak na tej liście**. Zapis siatki go usuwa, więc **Zapisz** najpierw prosi o potwierdzenie w oknie **Zapisz trasowanie**.

## Uruchomienie produkcyjne

Nic nie jest księgowane naprawdę, dopóki ktoś celowo nie uruchomi produkcyjnie. Uruchomienie produkcyjne jest ustawiane dla każdego systemu i każdego projektu: w jednym projekcie niektóre systemy mogą być rzeczywiste, a inne nadal w trybie Simulate. Projekt nowy, skopiowany lub próbny zaczyna w trybie Simulate na każdym systemie, dopóki ktoś nie uruchomi w nim produkcyjnie.

1. Wybierz projekt w selektorze projektu w nagłówku.
2. Wybierz **Uruchom produkcyjnie ›** w wierszu systemu lub **Uruchom produkcyjnie w tym projekcie…** w menu **Akcje** dla każdego systemu, który może księgować i nie jest jeszcze rzeczywisty. Bez wybranego projektu zobaczysz komunikat **Wybierz projekt, w którym ma nastąpić uruchomienie produkcyjne.**
3. Okno **Uruchomienie produkcyjne** najpierw sprawdza, co by się zmieniło, niczego nie zmieniając, i to pokazuje:
   - **Te staną się rzeczywiste**: systemy, które będą księgować naprawdę.
   - **Tryb księgowania projektu zmienia się na produkcyjny, więc każdy system produkcyjny księguje naprawdę.** — wyświetlane, gdy sam projekt nie jest jeszcze w trybie Live.
   - **Już rzeczywiste**: systemy, które już takie są.
   - ***system* nie może zostać uruchomiony produkcyjnie:** wraz z powodem: system jest wycofany, projekt jest zablokowany, nie masz dostępu do zapisu do tego połączenia albo nie jest to system, do którego możesz księgować.
4. Wybierz **Uruchomienie produkcyjne**. Przycisk jest aktywny tylko wtedy, gdy co najmniej jeden system stałby się rzeczywisty.

Uruchomienie produkcyjne zapisuje autoryzację projektu dla tych systemów w tym środowisku i ustawia tryb księgowania projektu na Live tam, gdzie nie był ustawiony. Każdy system, który zostaje uruchomiony produkcyjnie, jest zapisywany w [Historii zmian](#historia-zmian). Uruchomienie produkcyjne nigdy nie jest kopiowane do innego środowiska ani projektu.

Uruchomienie produkcyjne wymaga architekta projektu, w projekcie, który nie jest zablokowany, z Twoim własnym dostępem do zapisu do każdego połączenia. To samo sprawdzenie obowiązuje przez REST API (`POST /erp/go-live`) i przez narzędzie MCP `erp_go_live`, które odrzuca także delegowany token AI: produkcyjnie uruchamia człowiek, nigdy agent działający w jego imieniu. Oba tylko zgłaszają, co by się zmieniło, chyba że `dry_run` ustawiono na false.

## Wycofanie systemu

Wybierz **Oznacz jako wycofany** w otwartym wierszu i potwierdź przyciskiem **Wycofaj**: system przestaje być oferowany do księgowania, dopóki nie zostanie przywrócony. Jego wiersze w siatce są zachowywane, a dokumenty skierowane do niego nie są księgowane. **Przywróć z wycofanych** cofa tę operację. Obie wymagają administratora obszaru roboczego i są zapisywane w [Historii zmian](#historia-zmian).

## Dla IT

**Dla IT** otwiera okno **Dla IT: *system***, czyli to, co produkt robi w tym systemie, aby można to było dopuścić i poddać audytowi:

- **Loguje się jako** — konto, którym loguje się połączenie.
- **Rozmiar partii** — rozmiar partii określony w ustawieniach systemu albo **Nie ustawiono**.
- **Agent** i **Wersja agenta** — dla systemu lokalnego.
- **Jak to nazywamy** — każda funkcja lub usługa, którą produkt wywołuje po nazwie, wraz z datą ostatniego użycia. Dla SAP lokalnego są to funkcje ustawione w [Ustawieniach](#ustawienia-systemu). Zanim cokolwiek zostanie zaksięgowane lub przetestowane, wyświetla **Jeszcze nic. Pojawi się, gdy do tego systemu zostanie coś zaksięgowane lub gdy zostanie przetestowany.**

Gdy logowanie wygasło, okno to zgłasza i oferuje **Połącz ponownie**.

## Kopiowanie do innego środowiska

Skonfiguruj piaskownicę raz i skopiuj ją do produkcji zamiast wpisywać wszystko od nowa. Wybierz **Kopiuj do innego środowiska…** w menu **Akcje** (tylko administrator obszaru roboczego).

1. Wybierz środowisko w polu **Kopiuj do**.
2. Wszystkie systemy tego środowiska są wymienione i zaznaczone, gdy to samo połączenie jest systemem w drugim środowisku; system, który nim nie jest, jest wyświetlany jako ***system* (brak w tym środowisku)** i nie można go zaznaczyć.
3. Wybierz **Kopiuj** i potwierdź.

Dla każdego zaznaczonego systemu kopia zastępuje ustawienia, dopasowania kodów i funkcje SAP tego systemu w drugim środowisku tymi, oraz dodaje wiersze siatki, które go wskazują, a których drugie środowisko nie ma (ta sama jednostka od tej samej daty). Wiersze, które już tam są, pozostają bez zmian. Wynik podaje, ile wierszy siatki i ustawień ilu systemów skopiowano. Uruchomienie produkcyjne nie jest kopiowane: każdy projekt w drugim środowisku pozostaje w trybie Simulate, dopóki ktoś nie uruchomi w nim produkcyjnie.

## Kopia list systemu

Sprawdzenia porównują dokumenty z własnymi listami systemu: **Konta**, **Spółki** i **Okresy**. PlaidCloud przechowuje kopię każdej z nich, odczytaną z samego systemu:

- **Na początku każdego uruchomienia Live na systemie rzeczywistym**, z systemu, z limitem do 60 sekund na cały odczyt. Dokument może zatrzymać tylko odczyt tego uruchomienia.
- **Po wybraniu Odśwież teraz**, w otwartym wierszu. Odświeżenie kontaktuje się z Twoim systemem ERP tak jak księgowanie, więc wymaga administratora obszaru roboczego i Twojego własnego dostępu do zapisu do tego połączenia. Podaje, ile kont, spółek i okresów odczytano oraz ile trwał odczyt. Odświeżona kopia służy do wyświetlania: nie zasila sprawdzenia.

Każda lista pokazuje swój wiek w wierszu — na przykład „Konta odczytano 3 godziny temu”, „Okresy częściowe, odczytano 2 dni temu” lub „Spółki jeszcze nie odczytano” — albo informację, że nie można jej było odczytać, i dlaczego. Kopia, która została przerwana lub wróciła pusta, nie zastępuje poprzedniej.

**Wyświetl kopię** otwiera okno **Kopia list**, po jednej liście naraz (**Konta**, **Spółki** lub **Okresy**), z kolumnami **Kod**, **Nazwa**, **Zablokowane**, **Status w systemie**, **Od** i **Do**. Pokazuje do 5000 pierwszych wierszy. Kody podatkowe, klienci i dostawcy nie są kopiowani; pozostawia się je systemowi.

Uruchomienie Simulate nie odczytuje niczego z systemu, więc w trybie Simulate te sprawdzenia nie działają, a system rozstrzyga, gdy uruchomisz produkcyjnie.

## Sprawdzenia względem list

Na początku uruchomienia Live na systemie rzeczywistym każdy dokument jest sprawdzany względem list odczytanych przez to uruchomienie. Sprawdzenie, którego listy nie udało się odczytać, która wróciła częściowa lub pusta albo której odczyt nie zakończył się w czasie, jest oznaczane jako nie sprawdzone — nigdy zaliczone, nigdy zatrzymujące — a rozstrzyga system. Strona uruchomienia pokazuje, które sprawdzenia wykonano dla każdego dokumentu.

- **Period open** (Okres otwarty). Okres dokumentu jest znajdowany po kodzie okresu lub, w przeciwnym razie, po okresach, w które wpada jego data księgowania. Dokument jest zatrzymywany tylko wtedy, gdy każdy okres, który go obejmuje, jest w systemie zamknięty dla księgowania — okres korygujący, który nakłada się na jego miesiąc, utrzymuje datę otwartą. Okres, którego status system zgłasza słowami nieznanymi PlaidCloud, nie jest sprawdzany.
- **Jednostka jest spółką.** Gdy odczytano listę spółek, jednostka dokumentu — przez jej dopasowanie kodu `entity`, jeśli je ma, a w przeciwnym razie w postaci, w jakiej został zapisany — musi być jedną ze spółek systemu.
- **Konta istnieją.** Gdy odczytano listę kont, konto każdego wiersza — przez jego dopasowanie kodu `account`, jeśli je ma, a w przeciwnym razie w postaci, w jakiej został zapisany — musi istnieć w systemie i nie być zablokowane dla księgowania. Kody liczbowe są dopasowywane niezależnie od zer wiodących, więc `6100` znajduje `0000006100`.

Zatrzymany dokument jest Niezaksięgowany wraz z powodem, na przykład „Wiersz 3: konto 6100 nie istnieje w *system*”. To, które listy oferuje każdy system ERP, jest podane w tabeli poniżej.

## Reguły wstrzymania

Nic nie jest wstrzymywane, dopóki reguła tak nie postanowi. Dokument wstrzymany przez regułę czeka w stanie Wymaga zatwierdzenia na zatwierdzenie przez osobę w [Zatwierdzeniach](/pl/guides/connections/posting-register/); wszystko inne, co przejdzie sprawdzenia, jest wysyłane bez niego. Wybierz **Reguły wstrzymania** w grupie **Ustawienia** na pasku po lewej stronie.

Lista ma kolumny **Nazwa**, **Dotyczy**, **Wstrzymaj, gdy**, **Zatwierdzający** i **Przez**. Gdy nie ma reguł, wyświetla **Nic nie jest wstrzymane**. Każdy z uprawnieniem `erp.register.view` może czytać reguły; dodawanie, edytowanie i usuwanie wymagają administratora rejestru (`erp.register.admin`), który widzi na pasku narzędzi **Nowa reguła**, **Edytuj** i **Usuń**. Usunięcie reguły powoduje, że przestaje wstrzymywać nowe dokumenty; dokumenty już oczekujące czekają, dopóki ktoś nie zdecyduje. Każda zmiana jest zapisywana w [Historii zmian](#historia-zmian).

### Warunki reguły

**Nowa reguła** otwiera okno **Nowa reguła wstrzymania**:

1. Nadaj regule **Nazwę**, na przykład „Zapisy dziennika powyżej 250 000”.
2. Wybierz system w polu **Dotyczy**. Oferowane są systemy wszystkich środowisk, które widzisz.
3. Zaznacz, co wstrzymuje dokument, w polu **Wstrzymaj, gdy**. Wszystkie zaznaczone warunki muszą być spełnione; gdy nic nie zaznaczono, nic nie jest wstrzymywane.
   - **Kwota przekracza** wartość, **w walucie własnej jednostki**: rozmiar dokumentu to jego debety plus dodatnie kwoty lokalne, lub jego kwoty transakcyjne, gdy tabela nie podaje lokalnych.
   - **Został zaksięgowany z pliku**.
   - **To jest** **storno**, **uznanie** lub **korekta** — zaznacz dowolne z trzech.
   - **Jest oznaczony jako nietypowy** — zobacz [Oznaczenie jako nietypowy](#oznaczenie-jako-nietypowy).
   - **Zawsze, na przykład podczas zamknięcia** — wstrzymuje każdy dokument w systemie; wyłącza pozostałe warunki.
4. Wybierz zatwierdzającego w polu **Zatwierdzający**: **Zatwierdzający rejestru** lub **Wskazane osoby** — zaznacz osoby i, opcjonalnie, jednostki, dla których zatwierdzają, oddzielone przecinkami (puste oznacza każdą jednostkę).
5. Wybierz **Zapisz**. Przycisk jest aktywny, gdy reguła ma nazwę, system, co najmniej jeden warunek, kwotę będącą liczbą oraz, dla wskazanych osób, co najmniej jedną osobę.

Wstrzymany dokument wstrzymuje każdy inny dokument swojego zestawu, więc zestaw jest zatwierdzany i księgowany jako całość.

### Kto może zatwierdzać

Zatwierdzający potrzebuje `erp.register.approve` i własnego uprawnienia do połączenia dokumentu. Gdy reguła wskazuje osoby, zatwierdzają tylko te osoby — i tylko dla jednostek, które wymienia, jeśli jakieś wymienia. Nikt nie zatwierdza dokumentu, który sam wysłał: ani osoba, która rozpoczęła uruchomienie, ani osoba, której **Zaksięgować te** go wysłało.

Zatwierdzenie udzielone, gdy dokument był wysłany w trybie Simulate, nie liczy się przy wysyłce Live: gdy ten sam dokument zostanie później wysłany Live, jest ponownie wstrzymywany do nowej decyzji.

Jeśli Twój obszar roboczy wymaga rozdziału obowiązków przy księgowaniach, storno, uznanie lub korekta, którą to obejmuje, jest też wstrzymywane do decyzji drugiej osoby, nawet bez reguły.

### Własne wstrzymanie kroku

Krok **Księgowanie dokumentów** może wstrzymywać więcej niż jego systemy, w sekcji **Więcej ▸** → **Wstrzymaj do decyzji osoby**. Jego warunki to **Kwota jest wyższa niż**, **Został zaksięgowany z pliku**, **To jest storno, uznanie lub korekta**, **Jest oznaczony jako nietypowy** i **Zawsze**, łączone w ten sam sposób; gdy nic nie zaznaczono, nic więcej nie jest wstrzymywane. Wstrzymanie kroku tylko uzupełnia reguły systemu — nie może zwolnić tego, co wstrzymuje reguła systemu — a jego dokumenty zatwierdzają zatwierdzający rejestru. Wskazanych zatwierdzających ustawia się w regule systemu.

Zmiana wstrzymania kroku przez REST API (`PUT /erp/steps/{step_id}/holds`) lub narzędzie MCP `erp_hold_upsert` wymaga `analyze.step.write` oraz roli Architekta lub Menedżera projektu w projekcie, który nie jest zablokowany.

### Oznaczenie jako nietypowy

Dokument jest oznaczany jako nietypowy, gdy w porównaniu z tym, co jego jednostka księgowała wcześniej:

- jego kwota jest ponad dziesięć razy większa lub mniejsza niż ostatnie księgowanie tego samego odniesienia;
- używa konta, klienta, dostawcy lub partnera handlowego, którego jego jednostka nie użyła w swoich ostatnich 500 dokumentach; lub
- jego data księgowania wypada poza jego okresem.

Każde oznaczenie zapisuje zdanie wyjaśniające, dlaczego, na przykład „Data księgowania 2026-08-02 wypada poza okresem 2026-07.” Oznaczenie jest obliczane na podstawie wcześniejszych dokumentów jednostki; żaden model AI nie jest wywoływany. Jednostka bez wcześniejszych dokumentów nigdy nie jest oznaczana.

### SAP lokalny

SAP lokalny księguje przez agenta, wywołując własną funkcję klienta dla każdego typu dokumentu — ustawianą w sekcji [**Własna funkcja klienta**](#ustawienia-systemu). Dokument, którego typ nie ma funkcji lub którego dopasowanie pól funkcji nie zawiera pola dla odniesienia dokumentu, jest Niezaksięgowany. Konwersja istniejącego kroku księgowania SAP przenosi jego funkcję i dopasowanie pól do systemu, gdy system nie ma jeszcze funkcji dla tego typu dokumentu; zobacz [Księgowanie dokumentów w systemach ERP](/pl/guides/connections/post-documents/).

- **Symuluj** buduje to samo żądanie i zatrzymuje się przed agentem: nic nie dociera do SAP.
- **Rzeczywiste** przekazuje dokumenty agentowi obsługującemu środowisko systemu. Agent zapisuje odpowiedzi SAP w raporcie w domyślnym koncie dokumentów projektu (w `/erp_posting/sap`), a każdy dokument pozostaje w stanie Oczekuje, dopóki ten raport nie zostanie odczytany. Projekt bez domyślnego konta dokumentów nie może księgować do SAP w trybie Live, a jego dokumenty są Niezaksięgowane z tym powodem.
- **Gdy agent jest offline**, nic nie jest wysyłane: dokumenty są Niezaksięgowane z informacją, że agent był offline, i można je ponowić, gdy wróci. Gdy agent nie przyjmie dokumentów w ciągu około 18 sekund, są zabierane z powrotem niewysłane i Niezaksięgowane w ten sam sposób.
- Dokument, którego raport SAP nie rozstrzyga, jest w stanie Niepotwierdzone. Rozstrzygnij go w Rejestrze księgowań.

### Sage 100

Sage 100 jest lokalny i nie ma sieciowego API: dokumenty docierają do niego przez agenta, który uruchamia Business Object Interface firmy Sage.

- **Jedna spółka na połączenie.** Połączenie wskazuje spółkę Sage i jej walutę. Dokument dla innej spółki lub z wierszem w innej walucie nie jest wysyłany.
- **Zapisy dziennika** są księgowane jako zapisy dziennika GL. Odniesienie zapisu dziennika jest jego opisem w Sage, więc może mieć najwyżej 30 znaków.
- **Płatności** są księgowane jako ręczne czeki AP dla płatności dokonanych poza Sage: jeden dostawca na płatność, odniesienie jako numer czeku (najwyżej 7 znaków), `bank_code` (z dokumentu lub z [wartości wymaganych za każdym razem](#ustawienia-systemu) systemu) oraz każdy wiersz wskazujący opłacaną fakturę z dodatnią kwotą.
- **W uruchomieniu Live** agent najpierw pyta Sage: zapis dziennika datowany w okresie zamkniętym w Sage jest zatrzymywany, podobnie jak płatność za fakturę, której Sage nie ma jako otwartej.
- **Po wysłaniu** dokument jest Zaksięgowany tylko wtedy, gdy pokazują go tabele zaksięgowane Sage. Dokument wprowadzony do partii Sage, ale jeszcze niezaktualizowany, pozostaje w stanie Oczekuje; proces w tle ponownie pyta agenta, najwyżej raz na godzinę, a dokument nadal oczekujący po siedmiu dniach przechodzi w stan Niepotwierdzone.

## Historia zmian

Każda zmiana systemu jest zapisywana wraz z informacją, kto ją wprowadził i kiedy: **Ustawienia systemu**, **Wycofany**, **Funkcja SAP**, **Dopasowanie kodu**, **Która jednostka księguje gdzie**, **Reguła wstrzymania**, **Uruchomienie produkcyjne** i **Kopia list** (każdy odczyt list systemu). Wybierz **Historia zmian** w grupie **Ustawienia** na pasku po lewej stronie lub w menu **Akcje**, albo **Historia** w wierszu systemu, aby zobaczyć tylko ten system. Lista ma kolumny **Kiedy**, **Przez**, **Co**, **System**, **Które**, **Od** i **Do**.

Widzisz zmiany systemów, do których masz uprawnienie; uruchomienie produkcyjne tylko dla projektów, do których masz dostęp, a wstrzymanie kroku tylko w projektach, do których masz dostęp.

## Kto co może robić

Każda poniższa reguła jest sprawdzana przez serwer, tak samo dla aplikacji, REST API i narzędzi MCP, chyba że jej wiersz mówi inaczej.

| Aby | Potrzebujesz |
|---|---|
| Zobaczyć Systemy, ustawienia systemu, siatkę i jego kopię list | `analyze.connection.read`, i tylko połączenia, które widzisz |
| Zmienić ustawienia, wycofać system, zapisać siatkę, kopiować do innego środowiska | Administrator obszaru roboczego |
| Odświeżyć listy systemu | Administrator obszaru roboczego na stronie Systemy lub `analyze.connection.read` przez REST API i narzędzie MCP `erp_system_lists`; w obu przypadkach Twój własny dostęp do zapisu do tego połączenia |
| Uruchomić produkcyjnie | Architekt projektu w projekcie, który nie jest zablokowany, z Twoim własnym dostępem do zapisu do każdego połączenia; człowiek, nigdy delegowany token AI |
| Czytać reguły wstrzymania | `erp.register.view` |
| Dodać, zmienić lub usunąć regułę wstrzymania systemu | Administrator rejestru (`erp.register.admin`) |
| Zmienić własne wstrzymanie kroku | `analyze.step.write` oraz rola Architekta lub Menedżera projektu w projekcie, który nie jest zablokowany |
| Zatwierdzić wstrzymany dokument | `erp.register.approve` i Twoje własne uprawnienie do połączenia dokumentu; wskazany w regule, gdy ta wskazuje osoby; nigdy własna wysyłka |
