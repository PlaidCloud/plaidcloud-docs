[Data Foundation](/pl/guides/projects/data-foundation/) łączy dane ze wszystkich podłączonych systemów ERP i ich instancji w jednym Common Finance Model, a SAP S/4HANA Cloud to jeden z systemów ERP, które odczytuje bezpośrednio. Połączenie odczytuje wydane usługi OData tenanta za pomocą poświadczeń klienta OAuth 2.0; nie uczestniczy w tym żaden agent. Ta strona jest przeznaczona dla administratora S/4HANA Cloud, który to konfiguruje, oraz dla użytkownika PlaidCloud, który go o to prosi.

PlaidCloud tylko odczytuje dane. Nikt nie wysyła hasła ani klucza tajnego klienta e-mailem.

## Wyślij prośbę o dostęp

Na stronie projektu **Systemy**, w sekcji **Data Foundation** w obszarze **Strona główna**, wybierz swój system w polu **System** w sekcji **Dodaj system** i kliknij **Brak jeszcze dostępu?**. System czeka na dostęp, a wyświetlana jest jedna prośba obejmująca systemy projektu. Kliknij **Kopiuj żądanie**, aby wkleić ją do własnej wiadomości, lub **Wyślij żądanie e-mailem**, aby otworzyć ją w programie pocztowym z tematem „Dostęp do PlaidCloud”.

## Co konfiguruje administrator S/4HANA Cloud

<Steps>

1. **Utwórz użytkownika komunikacyjnego** dla PlaidCloud w aplikacji **Maintain Communication Users**. Jego metoda uwierzytelniania to OAuth 2.0 albo nazwa użytkownika i hasło, zależnie od wymagań Twojego środowiska.

2. **Utwórz system komunikacyjny** dla PlaidCloud w aplikacji **Communication Systems**, z tym użytkownikiem dla komunikacji przychodzącej i z poświadczeniami klienta OAuth 2.0.

3. **Utwórz ustalenie komunikacyjne** dla każdego poniższego scenariusza w aplikacji **Communication Arrangements**, wszystkie dla systemu z kroku 2. Razem udostępniają usługi OData, które odczytuje PlaidCloud:

   | Scenariusz | Usługa |
   |---|---|
   | Company Code | `API_COMPANYCODE_SRV` |
   | G/L Account in Chart of Accounts | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
   | Cost Center | `API_COSTCENTER_SRV` |
   | Business Partner and Customer | `API_BUSINESS_PARTNER` |
   | Product | `API_PRODUCT_SRV` |
   | Fiscal Year Variant Periods | `API_FISCALYEARPERIODFORVARIANT_SRV` |
   | Exchange Rates | `API_EXCHANGERATE_SRV` |
   | Journal Entry Item | `API_JOURNALENTRYITEMBASIC_SRV` (dziennik i przeniesione saldo) |
   | Billing Document | `API_BILLING_DOCUMENT_SRV` (opcjonalne: dodaje fakturowaną sprzedaż, dokumenty i pozycje) |

   Dla opcjonalnych zbiorów danych przygotuj też ustalenia dla scenariuszy, które udostępniają te usługi:

   | Usługa | Dodaje |
   |---|---|
   | `API_JOURNALENTRY_SRV` | Kto i kiedy wprowadził każdy dziennik oraz dziennik, który stornuje |
   | `API_BUSINESS_PARTNER` (`A_Supplier`) | Dostawców |
   | `API_PLANT_SRV` | Zakłady, odczytywane jako lokalizacje, oraz zakłady stanów magazynowych |
   | `API_PROFITCENTER_SRV` | Centra zysku |
   | `API_SUPPLIERINVOICE_PROCESS_SRV` | Pozycje faktur dostawców |
   | `API_OPLACCTGDOCITEMCUBE_SRV` | Pozycje otwarte i płatności oraz terminy płatności faktur dostawców |
   | `API_FINPLANNINGDATA_SRV` | Budżety |
   | `API_MATERIAL_STOCK_SRV` | Stany magazynowe |

   Nadaj użytkownikowi komunikacyjnemu dostęp do każdego kodu firmy, dla którego raportujesz.

</Steps>

## Co odesłać

| Administrator przesyła | Wprowadzane w PlaidCloud jako |
|---|---|
| Host API tenanta, na przykład `https://my300000-api.s4hana.cloud.sap` | **Adres URL hosta API** |
| Adres URL tokenu: własny adres tenanta (`/sap/bc/sec/oauth2/token`) lub adres serwera autoryzacji XSUAA, jeśli Twoje środowisko go używa | **Adres URL tokenu OAuth2** |
| Identyfikator klienta | **Identyfikator klienta** |
| Klucz tajny klienta, przez bezpieczny formularz połączenia | **Klucz tajny klienta**, który Twój zespół wprowadza samodzielnie |
| Czy **Carry Forward Balances** zostało uruchomione dla każdego ładowanego roku obrotowego | Nic do wprowadzenia. Salda otwarcia są z niego odczytywane. |

<Aside type="caution">
Nigdy nie wysyłaj klucza tajnego klienta e-mailem. **Klucz tajny klienta** jest sekretem: jest przechowywany w połączeniu i nigdy więcej nie jest pokazywany.
</Aside>

## Sprawdź dostęp

Po powrocie do PlaidCloud, gdy system zostanie już dodany, kliknij **Testuj połączenie** w jego wierszu na stronie **Systemy**. Test odczytuje wymagane zbiory danych i oznacza każdy z nich jako **Czytelne**, **Brak uprawnienia** lub **Błąd**. Opcjonalne zbiory danych nie są objęte testem: jeśli S/4HANA Cloud odmówi odczytu któregoś z nich, po następnym ładowaniu sprawdzenia gotowości na pulpicie **CFM-Accounting - Close and assurance** wskażą usługę, którą należy dodać do ustalenia komunikacyjnego.

| Zbiór danych | Wymagana usługa |
|---|---|
| Jednostki | `API_COMPANYCODE_SRV` |
| Plan kont | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
| Działy | `API_COSTCENTER_SRV` |
| Klienci | `API_BUSINESS_PARTNER` |
| Produkty | `API_PRODUCT_SRV` |
| Kursy walut | `API_EXCHANGERATE_SRV` |
| Kalendarz fiskalny | `API_FISCALYEARPERIODFORVARIANT_SRV` |
| Księga główna | `API_JOURNALENTRYITEMBASIC_SRV` |
| Bilans próbny | `API_JOURNALENTRYITEMBASIC_SRV` |
| Pozycje sprzedaży | `API_BILLING_DOCUMENT_SRV` (opcjonalne) |

Gdy zbiór danych ma status **Brak uprawnienia**, poproś administratora o dodanie ustalenia komunikacyjnego dla jego usługi i przetestuj ponownie. Pozycje sprzedaży, budżet, stany magazynowe, dostawcy, lokalizacje, centra zysku, pozycje faktur dostawców, pozycje otwarte i płatności są opcjonalne: tenant, który któregoś z nich nie zawiera, nadal ładuje wszystko inne. Pozycje otwarte lub płatności za dany miesiąc, których nie można odczytać, oraz pozycje faktur dostawców za dany miesiąc, których odczyt się nie powiedzie, zachowują wiersze, które już miały, i są odczytywane ponownie przy następnym ładowaniu.

Usługi nie podają statusu okresu ani własnego salda na koniec miesiąca, więc każdy okres jest otwarty, a księga jest porównywana z jej własnym zestawieniem obrotów i sald.
