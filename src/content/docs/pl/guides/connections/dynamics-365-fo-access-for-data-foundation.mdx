[Data Foundation](/pl/guides/projects/data-foundation/) łączy dane ze wszystkich podłączonych systemów ERP i ich instancji w jednym Common Finance Model, a Dynamics 365 Finance and Operations to jeden z systemów ERP, które odczytuje bezpośrednio. Połączenie korzysta z aplikacji Microsoft Entra ID z kluczem tajnym klienta dla danych głównych oraz z punktu końcowego SQL Fabric (Synapse) Link dla dziennika głównego, ksiąg pomocniczych i sald bankowych. Ta strona jest przeznaczona dla administratora Dynamics 365, który to konfiguruje, oraz dla użytkownika PlaidCloud, który go o to prosi.

PlaidCloud tylko odczytuje dane. Nikt nie wysyła klucza tajnego klienta ani hasła SQL e-mailem.

## Wyślij prośbę o dostęp

Na stronie projektu **Systemy**, w sekcji **Data Foundation** w obszarze **Strona główna**, wybierz swój system w polu **System** w sekcji **Dodaj system** i kliknij **Brak jeszcze dostępu?**. System czeka na dostęp, a wyświetlana jest jedna prośba obejmująca systemy projektu. Kliknij **Kopiuj żądanie**, aby wkleić ją do własnej wiadomości, lub **Wyślij żądanie e-mailem**, aby otworzyć ją w programie pocztowym z tematem „Dostęp do PlaidCloud”.

## Co konfiguruje administrator Dynamics 365

<Steps>

1. **Zarejestruj aplikację w Microsoft Entra ID** dla PlaidCloud, z kluczem tajnym klienta. Zanotuj jej Application (client) ID, Directory (tenant) ID oraz klucz tajny.

2. **Przypisz aplikację do użytkownika.** W Dynamics 365, w sekcji **System administration > Setup > Microsoft Entra ID applications**, dodaj identyfikator klienta i przypisz go do użytkownika z rolą, która może wyświetlać następujące dane dla każdej jednostki prawnej, którą chcesz załadować:

   - Księga główna: jednostki prawne, kalendarze fiskalne, konta główne, wartości wymiarów finansowych, kursy wymiany
   - Należności: klienci i pozycje faktur klientów
   - Zobowiązania: dostawcy (opcjonalne)
   - Zarządzanie informacjami o produktach: zwolnione produkty
   - Zarządzanie zapasami: stany bieżące i transakcje magazynowe (opcjonalne)
   - Budżetowanie: wpisy rejestru budżetu (opcjonalne)

3. **Skonfiguruj Fabric Link dla dziennika głównego.** Pozycje dziennika głównego są odczytywane z punktu końcowego SQL Fabric (Synapse) Link, a nie z usługi OData. Potwierdź, że Fabric Link jest włączony dla tych tabel, i utwórz na tym punkcie końcowym login SQL tylko do odczytu dla PlaidCloud:

   - `generaljournalaccountentry`
   - `generaljournalentry`
   - `fiscalcalendarperiod`
   - `dimensionattributelevelvalue`, z jednym wierszem na wartość wymiaru dla każdej kombinacji wymiarów finansowych i z nazwą jej wymiaru
   - dla pozycji otwartych i płatności (opcjonalne): `custtrans`, `vendtrans`, `custsettlement`, `vendsettlement`
   - dla pozycji faktur dostawców (opcjonalne): `vendinvoicetrans`, `vendinvoicejour`
   - dla sald bankowych (opcjonalne): `bankaccounttrans`, `bankaccounttable`

   Lokalizacje i centra zysku to wartości wymiarów finansowych `Site` i `BusinessUnit`.

</Steps>

## Co odesłać

| Administrator przesyła | Wprowadzane w PlaidCloud jako |
|---|---|
| Adres URL środowiska, `https://<name>.operations.dynamics.com` | **Adres URL środowiska** |
| Directory (tenant) ID | **ID tenanta Azure AD** |
| Application (client) ID | **Identyfikator klienta** |
| `dataAreaId` jednej jednostki prawnej | **Podmiot prawny / firma (dataAreaId)**: połączenie wymaga jednej, a Data Foundation odczytuje jednostki prawne wybrane w polu **Spółki** |
| Punkt końcowy SQL Fabric Link, baza danych i login | Osobne połączenie SQL w PlaidCloud, którego identyfikator połączenia trafia do ustawienia systemowego **Fabric Link SQL connection (its connection ID)** |
| Kategorie kont głównych dla Twoich kont kosztu własnego sprzedanych towarów (PlaidCloud zakłada `COGS`) | Ustawienie systemowe **Cost of goods sold main account categories** |
| Kategorie kont głównych dla kont nieoperacyjnych: odsetki, podatek dochodowy, zyski i straty z różnic kursowych, pozostałe przychody | Ustawienie systemowe **Non-operating main account categories** |
| Wymiar finansowy, który nazywa partnera wewnątrzgrupowego pozycji (PlaidCloud zakłada `IntercompanyPartner`) | Ustawienie systemowe **Intercompany partner dimension** |
| Jednostki prawne, które PlaidCloud może odczytywać | W sekcji **Opcje**, w polu **Spółki**: zaznacz je lub nie zaznaczaj żadnej, aby odczytywać wszystkie |

Klucz tajny klienta i hasło loginu SQL nigdy nie są wysyłane e-mailem. Zespół użytkownika PlaidCloud sam wkleja **Klucz tajny klienta** do PlaidCloud, a połączenie SQL przechowuje login SQL. Jednostki prawne będące jednostkami konsolidacyjnymi trafiają do ustawienia systemowego **Consolidation legal entities**, aby ich księgowania nie były liczone jako aktywność firmy.

## Sprawdź dostęp

Po powrocie do PlaidCloud, gdy system zostanie już dodany, kliknij **Testuj połączenie** w jego wierszu na stronie **Systemy**. Każdy zbiór danych jest oznaczony jako **Czytelne**, **Brak uprawnienia** lub **Błąd**:

| Zbiór danych | Wymagane uprawnienie |
|---|---|
| Jednostki | Księga główna: wyświetlanie jednostek prawnych |
| Kalendarz fiskalny | Księga główna: wyświetlanie kalendarzy fiskalnych |
| Plan kont | Księga główna: wyświetlanie kont głównych |
| Działy | Księga główna: wyświetlanie wartości wymiarów finansowych |
| Klienci | Należności: wyświetlanie klientów |
| Produkty | Zarządzanie informacjami o produktach: wyświetlanie zwolnionych produktów |
| Kursy walut | Księga główna: wyświetlanie kursów wymiany |
| Bilans próbny, Księga główna | Wyświetlanie księgi głównej (dziennik, przez Fabric Link) |
| Każdy inny zbiór danych | Opcjonalny, nieobjęty testem |

Gdy brakuje zbioru danych, test wskazuje uprawnienie do dodania. Poproś administratora o dodanie go do roli i przetestuj ponownie.

Opcjonalne zbiory danych to lokalizacje, centra zysku, dostawcy, pozycje sprzedaży, stany magazynowe, budżety, salda bankowe, pozycje faktur dostawców, pozycje otwarte i płatności. Środowisko, które któregoś z nich nie zawiera, nadal ładuje wszystko inne. Salda bankowe, pozycje faktur dostawców, pozycje otwarte lub płatności za dany miesiąc, których nie można odczytać z Fabric Link, zachowują wiersze, które już miały, i są odczytywane ponownie przy następnym ładowaniu.

Dynamics 365 nie ma obiektu sald, który połączenie mogłoby odczytać, więc saldo na koniec miesiąca nie jest ładowane: księga jest porównywana z jej własnym zestawieniem obrotów i sald.
