[Data Foundation](/pl/guides/projects/data-foundation/) łączy dane ze wszystkich podłączonych systemów ERP i ich instancji w jednym Common Finance Model, a Oracle Fusion Cloud ERP to jeden z systemów ERP, które odczytuje bezpośrednio. Połączenie z Oracle Fusion korzysta z poświadczeń klienta OAuth 2.0, użytkownika integracji tylko do odczytu oraz niewielkiego zestawu raportów BI Publisher. Ta strona jest przeznaczona dla administratora Oracle Fusion, który to konfiguruje, oraz dla użytkownika PlaidCloud, który go o to prosi.

PlaidCloud tylko odczytuje dane. Nikt nie wysyła hasła ani klucza tajnego klienta e-mailem.

## Wyślij prośbę o dostęp

Na stronie projektu **Systemy**, w sekcji **Data Foundation** w obszarze **Strona główna**, wybierz swój system w polu **System** w sekcji **Dodaj system** i kliknij **Brak jeszcze dostępu?**. System czeka na dostęp, a wyświetlana jest jedna prośba obejmująca systemy projektu. Kliknij **Kopiuj żądanie**, aby wkleić ją do własnej wiadomości, lub **Wyślij żądanie e-mailem**, aby otworzyć ją w programie pocztowym z tematem „Dostęp do PlaidCloud”.

## Co konfiguruje administrator Oracle Fusion

<Steps>

1. **Utwórz użytkownika integracji** i nadaj mu niestandardową rolę zawodową, która może tylko wyświetlać dane, dla każdej księgi, dla której raportujesz. Nie używaj roli, która może cokolwiek wprowadzać, księgować lub zatwierdzać, takiej jak General Accountant. Rola wymaga:

   - Księga główna: księgi, kalendarze księgowe i statusy okresów, partie dziennika, dzienniki i salda kont (uprawnienia do zapytań, z dostępem do danych tych ksiąg)
   - Kursy przeliczania walut (kursy dzienne)
   - Etykiety segmentów key flexfield, zbiory wartości i ich hierarchia kont (drzewa)
   - Należności i zobowiązania: faktury, wpływy, płatności i ich rozksięgowania oraz konta klientów i dostawcy
   - Rachunki bankowe Cash Management
   - Pozycje zapasów i ilości dostępne
   - Dla każdego wdrażanego raportu opcjonalnego odpowiedni dostęp tylko do wyświetlania: Purchasing (View Purchase Order, `PO_VIEW_PURCHASE_ORDER_PRIV`, oraz zapytania o przyjęcia, z dostępem do danych jednostek biznesowych zakupów), Fixed Assets (zapytania o środki trwałe, z dostępem do danych ksiąg środków trwałych: korporacyjnych i podatkowych), Cost Management (Review Item Costs, z dostępem do danych organizacji kosztowych) i Budgets (zapytania o salda budżetowe Księgi głównej)
   - Prawo uruchamiania raportów BI Publisher z kroku 3 oraz ERP Integration Service (zadania ESS)

2. **Zarejestruj aplikację poufną** w domenie tożsamości (IAM) z przepływem client credentials i zakresem interfejsu REST API Fusion Applications. Skopiuj jej identyfikator klienta i klucz tajny.

3. **Wdróż raporty BI Publisher** w `/Custom/PlaidCloud/DataFoundation`. Każdy z nich działa jako zadanie ESS, z nazwą raportu jako definicją zadania, i zwraca plik CSV z kolumnami wymienionymi w prośbie. Pierwsze sześć jest wymaganych: na ich podstawie budowana jest księga. Pozostałe są opcjonalne: bez któregoś z nich dane, które przenosi, pozostają puste i nic innego się nie zmienia.

   | Raport | Co zwraca |
   |---|---|
   | `PlaidCloudKeyFlexLabels` | Jeden wiersz na segment każdego planu kont Księgi głównej: jego pozycję, etykietę i zbiór wartości |
   | `PlaidCloudSegmentValues` | Każdą wartość tych zbiorów wartości, z typem konta naturalnego i hierarchią wartości |
   | `PlaidCloudCalendar` | Okresy księgowe każdej księgi, z typami kursów średnich okresowych i na koniec okresu |
   | `PlaidCloudCodeCombinations` | Kombinacje kodów i ich segmenty |
   | `PlaidCloudBalances` | Salda każdej księgi w każdym okresie, łącznie z okresami korygującymi: salda otwarcia oraz saldo na koniec miesiąca, z którym porównywana jest księga |
   | `PlaidCloudJournalLines` | Pozycje dziennika, odczytywane po jednej księdze, okresie i wartości segmentu bilansującego, z informacją, kto i kiedy wprowadził i zatwierdził każdy dziennik, oraz dziennikiem, który stornuje |
   | `PlaidCloudCustomers` | Konta klientów i nazwy ich stron (opcjonalne) |
   | `PlaidCloudItems` | Pozycje głównej organizacji zapasów (opcjonalne) |
   | `PlaidCloudSalesLines` | Jeden wiersz na pozycję faktury Należności (opcjonalne) |
   | `PlaidCloudSites` | Wartości segmentu `GL_SITE` (opcjonalne) |
   | `PlaidCloudSuppliers` | Dostawcy (opcjonalne) |
   | `PlaidCloudArDocuments`, `PlaidCloudReceipts` | Transakcje należności i to, co zostało do nich zastosowane, dla pozycji otwartych i płatności (opcjonalne) |
   | `PlaidCloudApInvoices`, `PlaidCloudApPayments` | Faktury zobowiązań i to, co zostało do nich zastosowane, dla pozycji otwartych i płatności (opcjonalne) |
   | `PlaidCloudApInvoiceLines` | Jeden wiersz na pozycję faktury Zobowiązań (opcjonalne) |
   | `PlaidCloudBankBalances` | Własne saldo każdego rachunku bankowego na koniec każdego miesiąca (opcjonalne) |
   | `PlaidCloudInventory` | Ilość dostępna i wartość każdej pozycji i każdego podmagazynu na koniec każdego miesiąca (opcjonalne) |
   | `PlaidCloudBudget` | Zatwierdzony budżet w podziale na miesiące (opcjonalne) |
   | `PlaidCloudPurchaseOrders`, `PlaidCloudPurchaseOrderEvents` | Pozycje zamówień zakupu oraz ich przyjęcia i dopasowane faktury (opcjonalne) |
   | `PlaidCloudAssets`, `PlaidCloudAssetMovements` | Rejestr środków trwałych księgi korporacyjnej oraz ruchy każdego środka trwałego w księgach korporacyjnych i podatkowych (opcjonalne) |
   | `PlaidCloudStandardCosts` | Koszt standardowy każdej pozycji w podziale na miesiące (opcjonalne) |

   Dokładne kolumny każdego raportu znajdują się w treści prośby o dostęp. Podaj nazwy raportów dokładnie tak, jak pokazano. Jeśli raporty `PlaidCloudBalances` lub `PlaidCloudApInvoices` zostały wdrożone dla wcześniejszej wersji, rozszerz je zgodnie z opisem w prośbie: `PlaidCloudBalances` musi teraz zwracać każdy okres wraz z jego obrotami.

</Steps>

## Co odesłać

| Administrator przesyła | Wprowadzane w PlaidCloud jako |
|---|---|
| Host Twojego adresu URL Fusion Applications, bez `https://` | **Host poda** |
| Adres URL tokenu domeny tożsamości | **Adres URL tokenu domeny tożsamości** |
| Zakres aplikacji REST API | **Zakres** |
| Identyfikator klienta z kroku 2 | **Identyfikator klienta** |
| Klucz tajny klienta z kroku 2 | **Klucz tajny klienta** |
| Wartości segmentu bilansującego, które PlaidCloud może odczytywać | W sekcji **Opcje**, w polu **Spółki**, ponieważ Fusion nie może ich wylistować: wpisz wartości oddzielone przecinkami lub pozostaw pole puste, aby załadować wszystkie |

Zamykająca lista prośby wymaga podania tych wartości razem. Przekaż klucz tajny klienta przez menedżera haseł, a nie e-mailem. Zespół użytkownika PlaidCloud sam wkleja go do PlaidCloud.

## Sprawdź dostęp

Po powrocie do PlaidCloud, gdy system zostanie już dodany, kliknij **Testuj połączenie** w jego wierszu na stronie **Systemy**. Test odczytuje jeden obiekt dla każdego wymaganego zbioru danych i oznacza każdy zbiór danych jako **Czytelne**, **Brak uprawnienia** lub **Błąd**. Same raporty są uruchamiane przy pierwszym ładowaniu, a raporty opcjonalne nie są objęte testem: raport, którego brakuje lub którego użytkownik nie może uruchomić, jest wskazywany przy następnym ładowaniu.

| Zbiór danych | Co odczytuje test |
|---|---|
| Jednostki, Kalendarz fiskalny, Plan kont, Działy, Bilans próbny | Księgi |
| Kursy walut | Dzienne kursy przeliczania |
| Księga główna | Partie dziennika |

Gdy brakuje zbioru danych, test wskazuje, które uprawnienie dodać. Poproś administratora o dodanie go do roli zawodowej i przetestuj ponownie. Pod Fusion bez raportu opcjonalnego nadal ładuje wszystko inne: klienci, produkty, lokalizacje i dostawcy są ładowani jako puste, a każdy inny zbiór danych zachowuje to, co załadowało wcześniejsze ładowanie, dopóki raportu nie będzie można ponownie odczytać.

Oracle Fusion nie ma listy centrów zysku, którą odczytywałby Data Foundation. Centrum zysku pozycji dziennika to segment zarządczy jej planu kont.
