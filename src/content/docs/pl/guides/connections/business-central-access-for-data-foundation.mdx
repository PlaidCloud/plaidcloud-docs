[Data Foundation](/pl/guides/projects/data-foundation/) łączy dane ze wszystkich podłączonych systemów ERP i ich instancji w jeden Common Finance Model, a Microsoft Dynamics 365 Business Central to jeden z systemów ERP, które odczytuje bezpośrednio. Połączenie wykorzystuje aplikację Microsoft Entra ID z poświadczeniami klienta, zestaw uprawnień tylko do odczytu oraz kilka obiektów stron opublikowanych jako usługi sieci Web. Ta strona jest przeznaczona dla administratora Business Central, który to konfiguruje, oraz dla użytkownika PlaidCloud, który go o to prosi.

PlaidCloud tylko odczytuje dane. Klucza tajnego klienta nigdy nie wysyła się e-mailem.

## Wysyłanie żądania dostępu

Na stronie projektu **Systemy**, w sekcji **Data Foundation** w obszarze **Strona główna**, wybierz swój system w polu **System** w sekcji **Dodaj system** i kliknij **Brak jeszcze dostępu?**. System czeka na dostęp, a wyświetlane jest jedno żądanie obejmujące systemy projektu. Kliknij **Kopiuj żądanie**, aby wkleić je do własnej wiadomości, lub **Wyślij żądanie e-mailem**, aby otworzyć je w programie pocztowym z tematem "Dostęp do PlaidCloud."

## Co konfiguruje administrator Business Central

<Steps>

1. **Zarejestruj aplikację w Microsoft Entra ID.** W sekcji **App registrations > New registration** dodaj klucz tajny klienta i zapisz identyfikator katalogu (dzierżawy), identyfikator aplikacji (klienta) oraz klucz tajny.

2. **Dodaj aplikację w Business Central.** Otwórz **Microsoft Entra Applications**, dodaj aplikację, ustaw jej stan na **Włączone** i nadaj jej wyłącznie zestaw uprawnień **D365 READ** dla każdej firmy, dla której tworzysz raporty. Odczytuje on wszystkie poniższe strony. Nie nadawaj jej **D365 BASIC** ani żadnego innego zestawu uprawnień umożliwiającego zapis.

3. **Opublikuj obiekty stron jako usługi sieci Web.** W sekcji **Search > Web Services > New** opublikuj te obiekty stron dokładnie z podanymi wartościami **Nazwa usługi** i zaznaczonym polem **Published**. Standardowy interfejs API nie zawiera ich pól:

   | Strona | Nazwa usługi | Uwagi |
   |---|---|---|
   | 20 G/L Entries | `GLEntries` | |
   | 16 Chart of Accounts | `GLAccounts` | |
   | 100 Accounting Periods | `AccountingPeriods` | |
   | 537 Dimension Values | `DimensionValues` | |
   | 240 Business Units | `BusinessUnits` | |
   | 605 IC Partner List | `ICPartners` | |
   | 5802 Value Entries | `ValueEntries` | Koszt własny sprzedaży i salda zapasów; opcjonalne |
   | 120 G/L Budget Entries | `GLBudgetEntries` | Budżety; opcjonalne |
   | Statistical Ledger Entries | `StatisticalLedgerEntries` | Klucze statystyczne; opcjonalne |
   | 118 General Ledger Setup | `GeneralLedgerSetup` | Wymiary skrótów od 3 do 8; opcjonalne |
   | 479 Dimension Set Entries | `DimensionSetEntries` | Wymiary skrótów od 3 do 8; opcjonalne |
   | 573 Detailed Cust. Ledg. Entries | `DetailedCustLedgEntries` | Pozycje otwarte i płatności; opcjonalne |
   | 574 Detailed Vendor Ledg. Entries | `DetailedVendorLedgEntries` | Pozycje otwarte i płatności; opcjonalne |
   | 371 Bank Account List | `BankAccounts` | Salda bankowe; opcjonalne |
   | 277 Bank Account Posting Groups | `BankAccountPostingGroups` | Salda bankowe; opcjonalne |
   | Inventory Posting Setup (wyszukaj jego stronę) | `InventoryPostingSetup` | Konto pozycji zakupu towaru; opcjonalne |

4. **Przekaż użytkownikowi PlaidCloud trzy decyzje:** kod źródłowy, pod którym księgowane są korekty audytowe (PlaidCloud zakłada `ADJUSTMENT`), wymiar odpowiadający działowi (PlaidCloud zakłada Global Dimension 1 o nazwie `DEPARTMENT`) oraz wymiar odpowiadający centrum zysku (PlaidCloud zakłada Global Dimension 2 o nazwie `PROFITCENTER`). Lokalizacją jest lokalizacja Business Central.

</Steps>

## Co odesłać

| Administrator przesyła | Wprowadzane w PlaidCloud jako |
|---|---|
| Identyfikator katalogu (dzierżawy) | **ID tenanta Azure AD** |
| Identyfikator aplikacji (klienta) | **Identyfikator klienta** |
| Klucz tajny klienta | **Klucz tajny klienta**, wprowadzany w edytorze połączeń, nie e-mailem |
| Nazwę środowiska, na przykład `production` | **Środowisko** |
| Identyfikator jednej firmy | **ID firmy**: połączenie wymaga jednego, a Data Foundation odczytuje firmy wybrane w polu **Spółki** |
| Nazwę wymiaru odpowiadającego działowi | Ustawienie systemowe **Department dimension** |
| Nazwę wymiaru odpowiadającego centrum zysku | Ustawienie systemowe **Profit centre dimension** |
| Kod źródłowy, pod którym księgowane są korekty audytowe | Ustawienie systemowe **Audit adjustment source code** |
| Firmy, które PlaidCloud może odczytywać | W sekcji **Opcje**, w polu **Spółki**: zaznacz je lub nie zaznaczaj żadnej, aby odczytywać wszystkie firmy |

Firmy będące firmami konsolidacyjnymi trafiają do ustawienia systemowego **Consolidation companies**, dzięki czemu ich zapisy nie są liczone jako aktywność żadnej firmy. Kursy walutowe pochodzą z jednej firmy: wskaż ją w ustawieniu systemowym **Exchange rate company**, w przeciwnym razie PlaidCloud użyje pierwszej firmy.

## Sprawdzanie dostępu

Po powrocie do PlaidCloud, gdy system zostanie już dodany, kliknij **Testuj połączenie** w jego wierszu na stronie **Systemy**. Każdy zbiór danych jest oznaczony jako **Czytelne**, **Brak uprawnienia** lub **Błąd**:

| Zbiór danych | Czego wymaga |
|---|---|
| Jednostki, Plan kont, Klienci, Produkty, Kursy walut, Bilans próbny | Dostępu do interfejsu API (zestaw uprawnień D365 READ) |
| Kalendarz fiskalny | Usługi sieci Web `AccountingPeriods` |
| Działy | Usługi sieci Web `DimensionValues` |
| Księga główna | Usługi sieci Web `GLEntries` |
| Każdy inny zbiór danych | Opcjonalny, nieobjęty testem |

Gdy brakuje zbioru danych, test wskazuje, które uprawnienie lub którą usługę sieci Web należy dodać. Poproś administratora o jej dodanie i przetestuj ponownie.

Opcjonalne zbiory danych to lokalizacje, centra zysku, dostawcy, saldo na koniec miesiąca, salda bankowe, salda zapasów, pozycje sprzedaży, pozycje faktur dostawców, pozycje otwarte, płatności, budżety i klucze alokacji. Środowisko, które któregoś z nich nie używa, nadal ładuje wszystko pozostałe, a po następnym ładowaniu sprawdzenia gotowości na pulpicie **CFM-Accounting - Close and assurance** wskazują każdą stronę, której odczytu Business Central odmawia. Saldo na koniec miesiąca to zestawienie obrotów i sald na koniec każdego miesiąca; salda bankowe to to saldo dla kont, na które księgują Twoje rachunki bankowe. Gdy Business Central odmawia odczytu, na podstawie którego za dany miesiąc budowane są saldo na koniec miesiąca, salda bankowe, zapasy, pozycje sprzedaży, pozycje faktur dostawców, pozycje otwarte lub płatności, ten miesiąc zachowuje wiersze, które już miał, i jest odczytywany ponownie przy następnym ładowaniu.
