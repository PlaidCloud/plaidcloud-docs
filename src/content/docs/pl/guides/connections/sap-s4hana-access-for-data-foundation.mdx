[Data Foundation](/pl/guides/projects/data-foundation/) łączy dane ze wszystkich podłączonych systemów ERP i ich instancji w jednym Common Finance Model, a SAP S/4HANA to jeden z systemów ERP, które odczytuje bezpośrednio. PlaidCloud łączy się z systemem przez agenta [PlaidLink](/pl/reference/cli/plaidlink/) zainstalowanego w Twojej sieci, przez RFC. Ta strona jest przeznaczona dla administratora SAP, który to konfiguruje, oraz dla użytkownika PlaidCloud, który go o to prosi.

PlaidCloud tylko odczytuje dane. Nikt nie wysyła hasła e-mailem.

## Wyślij prośbę o dostęp

Na stronie projektu **Systemy**, w sekcji **Data Foundation** w obszarze **Strona główna**, wybierz swój system w polu **System** w sekcji **Dodaj system** i kliknij **Brak jeszcze dostępu?**. System czeka na dostęp, a wyświetlana jest jedna prośba obejmująca systemy projektu. Kliknij **Kopiuj żądanie**, aby wkleić ją do własnej wiadomości, lub **Wyślij żądanie e-mailem**, aby otworzyć ją w programie pocztowym z tematem „Dostęp do PlaidCloud”.

## Co konfiguruje administrator SAP

<Steps>

1. **Zainstaluj pakiet ABAP PlaidCloud** (grupa funkcji `Z_PLAIDCL_B5_READ_TABLE`) w kliencie, z którego raportujesz, i zainstaluj agenta PlaidLink, który ma dostęp do systemu przez RFC.

2. **Utwórz użytkownika komunikacyjnego**, na przykład `PLAIDCLOUD_RFC`, z rolą zawierającą te autoryzacje:

   - `S_RFC`: wykonywanie grupy funkcji `Z_PLAIDCL_B5_READ_TABLE`.
   - `S_TABU_NAM` (wyświetlanie, `ACTVT` 03) dla poniższych tabel.

   | Tabele | Co zawierają |
   |---|---|
   | `T001` | Kody firm |
   | `T009`, `T009B`, `T001B` | Warianty roku obrotowego i okresy księgowania |
   | `SKA1`, `SKAT` | Konta księgi głównej |
   | `FAGL_011PC`, `FAGL_011ZC` | Wersja sprawozdania finansowego |
   | `CSKS`, `CSKT` | Centra kosztów |
   | `SETHEADER`, `SETNODE` | Grupy centrów kosztów i centrów zysku |
   | `CEPC`, `CEPCT` | Centra zysku (opcjonalne) |
   | `KNA1`, `KNVV`, `KNVH` | Klienci i ich hierarchia |
   | `MARA`, `MAKT`, `T006A` | Materiały i jednostki miary |
   | `TCURR`, `TCURF`, `TCURX` | Kursy wymiany i miejsca dziesiętne walut |
   | `ACDOCA` | Zapisy dziennika księgi wiodącej i jej przeniesienie sald |
   | `VBRK`, `VBRP`, `PRCD_ELEMENTS` | Dokumenty fakturowania i ich warunki |
   | `ACDOCP` | Dane planu |
   | `COSR` | Statystyczne wskaźniki |
   | `T001K`, `MBEW`, `MBEWH` | Obszary wyceny, wartości zapasów materiałów i ceny standardowe |
   | `T001W`, `TKA02` | Zakłady, odczytywane jako lokalizacje, oraz obszar controllingu każdego kodu firmy (opcjonalne) |
   | `T016T`, `TKUKT`, `KNVP`, `TSPAT`, `T052U` | Nazwy branż i klasyfikacji klientów, pracownik sprzedaży każdego klienta, nazwy dywizji i warunków płatności (opcjonalne) |
   | `LFA1`, `LFB1` | Dostawcy (opcjonalne) |
   | `RBKP`, `RSEG`, `BKPF` | Faktury dostawców i ich dokumenty księgowe (opcjonalne) |
   | `EKKO`, `EKPO`, `EKKN`, `EKET`, `EKBE` | Zamówienia zakupu oraz ich przyjęcia i faktury (opcjonalne) |
   | `ANLA`, `ANLZ`, `ANLB`, `ANKA`, `T095` | Rejestr środków trwałych (opcjonalne) |
   | Tabela pozycji jednostkowych obszaru wynikowego (`CE1`, a po nim jego nazwa) | CO-PA według wyceny (opcjonalne) |

   Pozycje otwarte i płatności są odczytywane z pozycji klientów i dostawców w `ACDOCA`, a ruchy środków trwałych z jej księgowań na kontach środków trwałych.

3. **Odpowiedz na pytania księgowe** (zobacz poniżej).

</Steps>

### Pytania, na które odpowiada administrator

| Administrator informuje Cię o | Wprowadzasz w PlaidCloud w sekcji **Ustawienia systemu** |
|---|---|
| Typie kursu wymiany, który zawiera kurs średni. PlaidCloud uśrednia kursy tego typu z każdego miesiąca. Często jest to `M`. | **Average rate type** |
| Typie kursu wymiany, który zawiera kurs zamknięcia, czyli kurs na koniec miesiąca. Jeśli nie wskażesz żadnego, kursem zamknięcia jest kurs `M`. | **Closing rate type** |
| Wersji sprawozdania finansowego, która raportuje zarządczy rachunek zysków i strat oraz bilans | **Financial statement version** |
| Tym, które z jej węzłów to przychody, koszt własny sprzedanych towarów, koszty operacyjne, pozycje nieoperacyjne, aktywa, zobowiązania, kapitał własny i pozycje wewnątrzgrupowe | **Account type of each statement node**: jeden wiersz na węzeł w postaci `node = type`, z typem z listy w polu, na przykład `Revenue` lub `Asset`. **Intercompany statement nodes** wskazuje węzły wewnątrzgrupowe. Oba mają zastosowanie tylko wtedy, gdy ustawiono **Financial statement version**. |
| Tym, że przeniesienie sald (`FAGLGVTR`) zostało uruchomione dla każdego raportowanego roku obrotowego | Nic do wprowadzenia. Salda otwarcia są z niego odczytywane. |
| Obszarze amortyzacji każdej księgi środków trwałych, bilansowej lub podatkowej. Pierwszy jest obszarem rejestru. PlaidCloud zakłada, że obszar `01` to księga bilansowa. | **Depreciation area of each book** |
| Typie ruchu każdego typu transakcji na środkach trwałych, według jego pierwszej cyfry. PlaidCloud zakłada: `1` przychód, `2` rozchód, `3` przeniesienie, `6` amortyzacja i `9` otwarcie. | **Movement type of each transaction type** |
| Tabeli pozycji jednostkowych obszaru wynikowego, jeśli chcesz uzyskać CO-PA według wyceny. Gdy żadna nie jest wskazana, CO-PA nie jest odczytywane. | **Operating concern line item table** |
| Polu wartości CO-PA każdego konta oraz o tym, które z nich są kosztami | **Value field of each CO-PA account**, **CO-PA cost value fields** |

## Co odesłać

| Administrator przesyła | Wprowadzane w PlaidCloud jako |
|---|---|
| Identyfikator systemu i serwer aplikacji (lub serwer komunikatów i grupa logowania) | **Host** i **Numer systemu** albo, przy opcji **Użyj połączenia wielosystemowego z równoważeniem obciążenia**, **Host MS**, **Serwer MS**, **ID systemu** i **Grupa** |
| Klient (client) | **Klient** |
| Nazwa użytkownika komunikacyjnego | **Użytkownik** |
| Hasło użytkownika komunikacyjnego, przez menedżera haseł | **Hasło**, które Twój zespół wprowadza samodzielnie |
| Nazwa agenta PlaidLink, który łączy się z systemem | Ustawienie systemowe **PlaidLink agent** |
| Kody firm, które PlaidCloud może odczytywać | W sekcji **Opcje**, w polu **Spółki**, ponieważ SAP nie może ich wylistować: wpisz kody firm oddzielone przecinkami lub pozostaw pole puste, aby załadować wszystkie kody firm |

<Aside type="caution">
Nigdy nie wysyłaj hasła e-mailem. **Hasło** jest sekretem: jest przechowywane w połączeniu i nigdy więcej nie jest pokazywane.
</Aside>

## Sprawdź dostęp

SAP jest odczytywany przez agenta PlaidLink, więc **Testuj połączenie** go nie odczytuje: robi to pierwsze ładowanie, które wskazuje tabelę, której użytkownik nie może odczytać. Każdy zbiór danych odczytuje:

| Zbiór danych | Tabele, które odczytuje |
|---|---|
| Jednostki | `T001` |
| Kalendarz fiskalny | `T001`, `T009`, `T009B`, `T001B` |
| Kursy walut | `TCURR`, `TCURF` |
| Plan kont | `SKA1`, `SKAT`, `FAGL_011PC`, `FAGL_011ZC` |
| Działy | `CSKS`, `CSKT`, `SETHEADER`, `SETNODE` |
| Centra zysku | `CEPC`, `CEPCT`, `SETHEADER`, `SETNODE` |
| Klienci | `KNA1`, `KNVV`, `KNVH` |
| Produkty | `MARA`, `MAKT`, `T006A` |
| Księga główna | `ACDOCA` |
| Bilans próbny | Przeniesienie sald z `ACDOCA` |
| Pozycje sprzedaży | `VBRK`, `VBRP`, `PRCD_ELEMENTS` |
| Budżet | `ACDOCP` |
| Klucze alokacji | `COSR` |
| Stany magazynowe | `T001K`, `MBEW`, `MBEWH` |
| Lokalizacje | `T001W`, `T001K` |
| Dostawcy | `LFA1`, `LFB1` |
| Pozycje faktur dostawców | `RBKP`, `RSEG`, `BKPF` |
| Zamówienia zakupu | `EKKO`, `EKPO`, `EKKN`, `EKET`, `EKBE` |
| Pozycje otwarte, Płatności | Pozycje klientów i dostawców w `ACDOCA` |
| Środki trwałe | `ANLA`, `ANLZ`, `ANLB`, `ANKA`, `T095` |
| Ruchy środków trwałych | `ACDOCA` wraz z `ANLA`, `ANKA`, `T095` |
| Koszty standardowe | `T001K`, `MBEW`, `MBEWH` |
| CO-PA według wyceny | Tabela wskazana w **Operating concern line item table** |

Gdy ładowanie wskaże tabelę, której użytkownik nie może odczytać, poproś administratora o dodanie jej do roli i załaduj ponownie. Centra zysku, lokalizacje, dostawcy, pozycje faktur dostawców, zamówienia zakupu, pozycje otwarte, płatności, środki trwałe, ruchy środków trwałych, koszty standardowe, CO-PA, pozycje sprzedaży, budżet, klucze alokacji i stany magazynowe są opcjonalne: system, który któregoś z nich nie zawiera, nadal ładuje wszystko inne. Pozycje otwarte lub płatności za dany miesiąc, których odczytu SAP odmawia, zachowują wiersze, które już miały.

S/4HANA nie przechowuje osobnego salda na koniec miesiąca, które odczytywałby Data Foundation, więc księga jest porównywana z jej własnym zestawieniem obrotów i sald. Obszary amortyzacji, które nie księgują do żadnej księgi, nie są odczytywane, a sprawdzenia gotowości je wskazują.
