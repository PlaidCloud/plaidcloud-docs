**Połączenie PlaidCloud Git** kieruje przepływ pracy — lub kompilację aplikacji Server Panel — do repozytorium na własnym zarządzanym serwerze Git obszaru roboczego. Ponieważ ten serwer Git jest hostowany dla Ciebie pod adresem `git.<your-workspace>.plaid.cloud`, a Ty jesteś już zalogowany(-a) przez zwykłe logowanie do PlaidCloud, formularz połączenia jest znacznie prostszy niż w przypadku zewnętrznego dostawcy Git: nie trzeba wpisywać adresu URL serwera ani zarządzać nazwą użytkownika, tokenem czy kluczem SSH.

<Aside type="note">W połączeniu PlaidCloud Git nigdy nie podajesz adresu URL serwera ani poświadczeń. Serwer Git obszaru roboczego i dostęp do niego są obsługiwane automatycznie na podstawie logowania do PlaidCloud (w tym SSO), więc nie ma tokenów do tworzenia, przechowywania ani rotowania.</Aside>

## Kiedy używać

Użyj połączenia PlaidCloud Git zawsze wtedy, gdy repozytorium, z którego chcesz czytać, znajduje się w [PlaidCloud Git](/pl/guides/git/) — wbudowanej usłudze Git obszaru roboczego — a nie u zewnętrznego dostawcy. Najczęściej służy to do automatyzacji kompilacji **serwerowych aplikacji Panel** lub **aplikacji Dash** z zarządzanego repozytorium, dzięki czemu wypchnięcie zmian do gałęzi powoduje ponowne zbudowanie i wdrożenie aplikacji bez zewnętrznego konta GitHub ani osobistego tokenu dostępu.

W przypadku repozytorium hostowanego w usłudze zewnętrznej — GitHub, GitLab, Bitbucket, Forgejo lub Gitea — użyj zamiast tego [zewnętrznego połączenia Git](/pl/reference/connectors/git/). Zachowuje ono pełny formularz z polem **Server URL**, uwierzytelnianiem przez użytkownika i token lub SSO oraz kartami **SSL** i **SSH**.

## Utwórz połączenie PlaidCloud Git

1. Otwórz **Tools > Connections**
2. Kliknij `New Connection` i wybierz z menu **PlaidCloud Git**
3. Wypełnij uproszczony formularz:
   - **Nazwa konta** — wyświetlana nazwa połączenia
   - **Notatka** — opcjonalna notatka o przeznaczeniu połączenia
   - **Repozytorium** — kliknij `Refresh`, aby wyświetlić repozytoria dostępne dla obszaru roboczego, a następnie wybierz jedno z nich (na przykład repozytorium `udfs` lub `apps`). Wybierasz z listy, zamiast wpisywać ścieżkę.
   - **Domyślna gałąź** — wybierz gałąź, z której domyślnie ma być odczyt, z listy gałęzi w wybranym repozytorium
   - **Ścieżka początkowa** — opcjonalnie przejrzyj repozytorium i wybierz folder, aby ograniczyć każde wyszukiwanie plików do podfolderu; pozostaw nieustawioną, aby użyć całego repozytorium
4. Ustaw **Użycie** — `Active`, aby włączyć połączenie, oraz `Read Only`, jeśli połączenie nigdy nie powinno zapisywać
5. Ustaw **Model zabezpieczeń** — określa, kto w obszarze roboczym może używać połączenia
6. Kliknij `Create`, aby zapisać

To cały formularz. W przeciwieństwie do zewnętrznego dostawcy Git nie ma tu adresu URL serwera, karty uwierzytelniania ani konfiguracji SSL czy SSH — wszystko to jest obsługiwane automatycznie.

<Aside type="note">Repozytorium, domyślna gałąź i ścieżka początkowa są wybierane z list pobieranych na żywo — najpierw wybierz repozytorium, potem jego gałąź, a następnie przejdź do folderu — więc nie ma możliwości literówki. Każda lista jest odczytywana z użyciem własnego dostępu połączenia, dlatego w przypadku połączenia PlaidCloud Git wypełnia się od razu, bez wpisywania poświadczeń.</Aside>

## Model zabezpieczeń

Opcja `Security Model` określa, kto w obszarze roboczym może używać połączenia:

| Opcja | Kto może używać połączenia |
|---|---|
| Prywatne (tylko właściciele) | Wyłącznie właściciele. |
| Tylko wybrani członkowie | Właściciele oraz jawnie wskazana lista członków. |
| Tylko wybrane grupy zabezpieczeń | Właściciele oraz członkowie wskazanych grup zabezpieczeń. |
| Wszyscy członkowie obszaru roboczego | Wszyscy w obszarze roboczym. |

W przypadku opcji `Specific Members Only` lub `Specific Security Groups Only` nadaj dostęp z menu `Actions` na liście po zapisaniu. Wspólne mechanizmy połączeń opisano w [Tworzenie połączeń i zarządzanie nimi](/pl/guides/connections/create-connection/#model-zabezpieczeń).

## Kto widzi repozytoria

Każde repozytorium utworzone dla Ciebie przez PlaidCloud jest czytelne dla każdego zalogowanego członka obszaru roboczego. Dotyczy to repozytoriów aplikacji Panel i Dash oraz wbudowanych repozytoriów `apps` i `udfs`. Osoby niezalogowane nie mogą ich czytać.

Dzięki temu członkowie mogą otwierać i ponownie publikować aplikacje oraz wybierać repozytorium dla połączenia PlaidCloud Git bez konfiguracji poszczególnych repozytoriów.

### Zaawansowane: repozytoria prywatne

Administrator Git może ustawić repozytorium jako prywatne w interfejsie Git. Takie repozytorium nie jest już widoczne dla każdego członka, w związku z czym:

- Nie pojawia się na liście **Repozytorium** w połączeniach PlaidCloud Git.
- Nie można z niego odczytać kodu UDF opartego na Git, więc UDF oparty na Git, przechowywany w repozytorium prywatnym, nie zostanie uruchomiony.
- Członkowie nie mogą z niego opublikować aplikacji.

Aby użyć repozytorium prywatnego jako źródła, utwórz zamiast tego [zewnętrzne połączenie Git](/pl/reference/connectors/git/) z własnym tokenem dostępu.

## Automatyzacja kompilacji aplikacji Panel i Dash z zarządzanego Git

[Serwerowa aplikacja Panel](/pl/guides/panel-apps/creating/) lub [aplikacja Dash](/pl/guides/dash-apps/) jest budowana z gałęzi Git i automatycznie przebudowywana po każdym wypchnięciu zmian do tej gałęzi. Skierowanie jej na połączenie PlaidCloud Git utrzymuje całą pętlę wewnątrz obszaru roboczego — bez zewnętrznego hosta i bez osobistego tokenu dostępu, który trzeba odnawiać.

1. Wypchnij aplikację do repozytorium na serwerze PlaidCloud Git obszaru roboczego — plik `.py` punktu wejścia (w Panel wywołuje `.servable()`; w Dash udostępnia `server = app.server`) oraz opcjonalny plik `requirements.txt` w katalogu głównym repozytorium lub obok punktu wejścia. Układ repozytorium opisano w [Tworzenie aplikacji Panel](/pl/guides/panel-apps/creating/#przygotowanie-repozytorium-aplikacji) oraz [Wdrażanie aplikacji Dash z PlaidCloud Git](/pl/guides/dash-apps/deploy-from-git/).
2. Utwórz połączenie PlaidCloud Git, w którym **Repozytorium** wskazuje to repozytorium, zgodnie z powyższymi krokami.
3. W **Moje aplikacje Panel** kliknij **Nowa aplikacja serwerowa** lub **Nowa aplikacja Dash** i w sekcji **Połączenie Git i obserwator publikacji**:
   - **Połączenie Git** — wybierz właśnie utworzone połączenie PlaidCloud Git
   - **Gałąź** — gałąź, z której ma być budowana aplikacja; wypchnięcia do niej powodują przebudowę i ponowne wdrożenie aplikacji
   - **Punkt wejścia** — plik `.py`, który aplikacja ma udostępniać
4. Dokończ okno publikacji i kliknij **Opublikuj**.

Od tej chwili każde wypchnięcie do tej gałęzi na zarządzanym serwerze Git przebudowuje aplikację — w pełni zautomatyzowana kompilacja, która nigdy nie opuszcza PlaidCloud.
