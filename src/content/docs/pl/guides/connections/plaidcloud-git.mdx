**Połączenie PlaidCloud Git** wskazuje przepływowi pracy — lub kompilacji serwerowej aplikacji Panel — repozytorium na zarządzanym serwerze Git Twojego obszaru roboczego. Ponieważ ten serwer Git jest dla Ciebie hostowany pod adresem `git.<your-workspace>.plaid.cloud`, a Ty jesteś już zalogowany przez standardowe logowanie PlaidCloud, formularz połączenia jest znacznie prostszy niż w przypadku zewnętrznego dostawcy Git: nie trzeba wpisywać adresu URL serwera ani zarządzać nazwą użytkownika, tokenem czy kluczem SSH.

<Aside type="note">W połączeniu PlaidCloud Git nigdy nie podajesz adresu URL serwera ani poświadczeń. Serwer Git obszaru roboczego i Twój dostęp do niego są obsługiwane automatycznie na podstawie logowania do PlaidCloud (w tym SSO), więc nie ma tokenów do tworzenia, przechowywania ani rotowania.</Aside>

## Kiedy używać

Użyj połączenia PlaidCloud Git zawsze, gdy repozytorium, z którego chcesz czytać, znajduje się w [PlaidCloud Git](/pl/guides/git/) — wbudowanej usłudze Git obszaru roboczego — a nie na zewnętrznym hoście. Najczęstsze zastosowanie to automatyzacja kompilacji **serwerowej aplikacji Panel** lub **aplikacji Dash** z zarządzanego repozytorium, dzięki czemu wypchnięcie zmian do gałęzi przebudowuje i ponownie wdraża aplikację bez zewnętrznego konta GitHub ani osobistego tokenu dostępu.

W przypadku repozytorium hostowanego w usłudze zewnętrznej — GitHub, GitLab, Bitbucket, Forgejo lub Gitea — użyj zamiast tego [zewnętrznego połączenia Git](/pl/reference/connectors/git/). Zachowuje ono pełny formularz z polem **Adres URL serwera**, uwierzytelnianiem użytkownik/token lub SSO oraz kartami **SSL** i **SSH**.

## Tworzenie połączenia PlaidCloud Git

1. Otwórz **Tools > Connections**
2. Kliknij `New Connection` i wybierz z menu **PlaidCloud Git**
3. Wypełnij uproszczony formularz:
   - **Nazwa konta** — wyświetlana nazwa połączenia
   - **Notatka** — opcjonalna uwaga o przeznaczeniu połączenia
   - **Repozytorium** — kliknij `Refresh`, aby wyświetlić repozytoria dostępne w Twoim obszarze roboczym, a następnie wybierz jedno z nich (na przykład repozytorium `udfs` lub `apps`). Wybierasz z listy, zamiast wpisywać ścieżkę.
   - **Domyślna gałąź** — wybierz gałąź, z której domyślnie ma być odczyt, z listy gałęzi w wybranym repozytorium
   - **Ścieżka początkowa** — opcjonalnie przeglądaj repozytorium i wybierz folder, aby ograniczyć każde wyszukiwanie plików do podfolderu; pozostaw nieustawioną, aby używać całego repozytorium
4. Ustaw **Użycie** — `Active`, aby włączyć połączenie, oraz `Read Only`, jeśli połączenie nigdy nie ma zapisywać
5. Ustaw **Model zabezpieczeń** — kto w obszarze roboczym może używać połączenia
6. Kliknij `Create`, aby zapisać

To cały formularz. W przeciwieństwie do zewnętrznego dostawcy Git nie ma adresu URL serwera, karty uwierzytelniania ani konfiguracji SSL czy SSH — wszystko to jest obsługiwane za Ciebie.

<Aside type="note">Repozytorium, domyślna gałąź i ścieżka początkowa są wybierane z list na żywo — najpierw wybierz repozytorium, potem jego gałąź, a następnie przejdź do folderu — więc nie ma możliwości literówki. Każda lista jest odczytywana z uprawnieniami samego połączenia, dlatego w połączeniu PlaidCloud Git wypełnia się od razu, bez podawania poświadczeń.</Aside>

## Model zabezpieczeń

`Security Model` określa, kto w obszarze roboczym może używać połączenia:

| Opcja | Kto może używać połączenia |
|---|---|
| Private (Only Owners) | Tylko właściciele. |
| Specific Members Only | Właściciele oraz jawna lista członków. |
| Specific Security Groups Only | Właściciele oraz członkowie wskazanych grup zabezpieczeń. |
| All Workspace Members | Wszyscy w obszarze roboczym. |

Dla `Specific Members Only` lub `Specific Security Groups Only` nadaj dostęp z menu `Actions` na liście po zapisaniu. Wspólne zasady działania połączeń opisano w [Tworzenie połączeń i zarządzanie nimi](/pl/guides/connections/create-connection/#model-zabezpieczeń).

## Automatyzacja budowania aplikacji Panel i Dash z zarządzanego Git

[Serwerowa aplikacja Panel](/pl/guides/panel-apps/creating/) lub [aplikacja Dash](/pl/guides/dash-apps/) jest budowana z gałęzi Git i przebudowywana automatycznie po każdym wypchnięciu do tej gałęzi. Wskazanie jej połączenia PlaidCloud Git utrzymuje całą pętlę wewnątrz obszaru roboczego — bez zewnętrznego hosta i bez osobistego tokenu dostępu, który trzeba odnawiać.

1. Wypchnij aplikację do repozytorium na serwerze PlaidCloud Git obszaru roboczego — plik `.py` z punktem wejścia (w Panel wywołuje `.servable()`, w Dash udostępnia `server = app.server`) oraz opcjonalny plik `requirements.txt` w katalogu głównym repozytorium lub obok punktu wejścia. Układ repozytorium opisano w [Tworzenie aplikacji Panel](/pl/guides/panel-apps/creating/#przygotowanie-repozytorium-aplikacji) oraz [Wdrażanie aplikacji Dash z PlaidCloud Git](/pl/guides/dash-apps/deploy-from-git/).
2. Utwórz połączenie PlaidCloud Git, w którym **Repozytorium** to to repozytorium, zgodnie z powyższymi krokami.
3. W **Moje aplikacje Panel** kliknij **Nowa aplikacja serwerowa** lub **Nowa aplikacja Dash** i w sekcji **Połączenie Git i obserwator publikacji**:
   - **Połączenie Git** — wybierz właśnie utworzone połączenie PlaidCloud Git
   - **Gałąź** — gałąź, z której ma być budowana aplikacja; wypchnięcia do niej przebudowują i ponownie wdrażają aplikację
   - **Punkt wejścia** — plik `.py`, który aplikacja ma udostępniać
4. Dokończ okno publikacji i kliknij **Opublikuj**.

Od tej chwili każde wypchnięcie do tej gałęzi na zarządzanym serwerze Git przebudowuje aplikację — w pełni zautomatyzowana kompilacja, która nigdy nie opuszcza PlaidCloud.
