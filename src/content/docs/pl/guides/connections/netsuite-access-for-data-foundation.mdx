[Data Foundation](/pl/guides/projects/data-foundation/) łączy dane z każdego podłączonego systemu i instancji ERP w jeden Common Finance Model, a NetSuite jest jednym z systemów ERP, które odczytuje bezpośrednio. Połączenie z NetSuite korzysta z dostępu maszyna-maszyna OAuth 2.0: roli tylko do odczytu, rekordu integracji używającego przyznania poświadczeń klienta (client credentials) oraz certyfikatu. Ta strona jest przeznaczona dla administratora NetSuite, który to konfiguruje, oraz dla użytkownika PlaidCloud, który go o to prosi.

PlaidCloud wyłącznie odczytuje dane. Nikt nie wysyła hasła, sekretu tokenu ani klucza prywatnego pocztą e-mail.

## Zanim zaczniesz: utwórz certyfikat

Zespół użytkownika PlaidCloud tworzy parę kluczy RSA i zachowuje klucz prywatny. Do NetSuite trafia tylko certyfikat publiczny. Na przykład za pomocą OpenSSL:

```bash
openssl req -new -x509 -newkey rsa:3072 -nodes -days 730 \
    -keyout plaidcloud_netsuite.pem \
    -out plaidcloud_netsuite_public.pem \
    -subj "/CN=PlaidCloud"
```

Dołącz `plaidcloud_netsuite_public.pem` do prośby wysyłanej administratorowi. Zachowaj `plaidcloud_netsuite.pem` na potrzeby pola **Certyfikat prywatny NetSuite** w PlaidCloud.

## Wyślij prośbę o dostęp

Na stronie projektu **Systemy**, w sekcji **Data Foundation** w obszarze **Strona główna**, wybierz swój system w polu **System** w sekcji **Dodaj system** i kliknij **Brak jeszcze dostępu?**. System czeka na dostęp, a wyświetlana jest jedna prośba obejmująca systemy projektu. Kliknij **Kopiuj żądanie**, aby wkleić ją do własnej wiadomości, lub **Wyślij żądanie e-mailem**, aby otworzyć ją w programie pocztowym z tematem „Dostęp do PlaidCloud”. Dołącz certyfikat publiczny.

## Co konfiguruje administrator NetSuite

<Steps>

1. **Włącz funkcje.** W **Setup > Company > Enable Features > SuiteCloud** włącz:

   - REST Web Services
   - OAuth 2.0
   - SuiteAnalytics Workbook (potrzebny dla SuiteQL)

2. **Utwórz rolę tylko do odczytu**, na przykład „PlaidCloud Read Only”, z następującymi uprawnieniami:

   | Uprawnienie | Poziom |
   |---|---|
   | Setup: REST Web Services | Full |
   | Setup: Log in using OAuth 2.0 Access Tokens | Full |
   | Transactions: Invoice, Cash Sale and Credit Memo | View |
   | Lists: Items and Locations | View |
   | Transactions: Budget | View |
   | Reports: General Ledger | View |
   | Setup: Accounting Periods | View |
   | Lists: Subsidiaries | View |
   | Lists: Accounts | View |
   | Lists: Departments | View |
   | Lists: Classes | View |
   | Lists: Locations | View |
   | Lists: Customers | View |
   | Lists: Currency | View |
   | Lists: Consolidated Exchange Rates | View |
   | Lists: Custom Record Entries, jeśli używasz segmentów niestandardowych | View |
   | Lists: Vendors, dla dostawców | View |
   | Lists: Employees, dla przedstawicieli handlowych | View |
   | Transactions: Bills, dla pozycji faktur dostawców, pozycji otwartych i płatności | View |
   | Transactions: Customer Payment and Pay Bills, dla pozycji otwartych i płatności | View |
   | Transactions: Find Transaction, dla tego, co rozliczyła każda płatność | View |

   Ostatnie sześć jest opcjonalnych. Nadaj roli dostęp do każdej spółki zależnej, dla której PlaidCloud tworzy raporty.

3. **Utwórz rekord integracji.** W **Setup > Integration > Manage Integrations > New**:

   - **Nazwa:** PlaidCloud
   - **Uwierzytelnianie:** zaznacz tylko **Client Credentials (Machine to Machine) Grant** — bez uwierzytelniania opartego na tokenach i bez przyznania kodu autoryzacji.
   - **Zakresy:** REST Web Services i RESTlets.

   Zapisz go i skopiuj **Identyfikator klienta**. NetSuite pokazuje go jednorazowo, na stronie potwierdzenia.

4. **Zmapuj certyfikat.** W **Setup > Integration > OAuth 2.0 Client Credentials (M2M) Setup > Create New**:

   - **Jednostka:** użytkownik, jako którego działa PlaidCloud.
   - **Rola:** rola z kroku 2.
   - **Aplikacja:** PlaidCloud, integracja z kroku 3.
   - **Certyfikat:** certyfikat publiczny dołączony do prośby.

   Zapisz go i skopiuj **ID certyfikatu**.

</Steps>

## Co odesłać

| Administrator przekazuje | Zapisywane w połączeniu NetSuite jako |
|---|---|
| **Identyfikator konta** z **Setup > Company > Company Information** — na przykład `1234567` lub `1234567_SB1` dla piaskownicy | **ID konta NetSuite** |
| **Identyfikator klienta** z kroku 3 | **Identyfikator klienta** |
| **ID certyfikatu** z kroku 4 | **ID certyfikatu** |
| Spółki zależne, które PlaidCloud może odczytywać | W sekcji **Opcje**, w polu **Spółki** podczas dodawania systemu: zaznacz je lub nie zaznaczaj żadnej, aby odczytywać wszystkie aktywne spółki zależne, które nie są spółkami eliminacyjnymi |

Klucz prywatny odpowiadający certyfikatowi pozostaje w zespole użytkownika PlaidCloud. Użytkownicy sami wprowadzają go w polu **Certyfikat prywatny NetSuite** połączenia.

<Aside type="caution">
Wprowadź identyfikator konta dokładnie tak, jak pokazuje go NetSuite, łącznie z sufiksem `_SB1` dla piaskownicy. PlaidCloud wyznacza na jego podstawie adres NetSuite.
</Aside>

## Sprawdź dostęp

Po powrocie do PlaidCloud, gdy system zostanie już dodany, kliknij **Testuj połączenie** w jego wierszu na stronie **Systemy**. Każdy zbiór danych jest pokazany jako **Czytelne**, **Brak uprawnienia** lub **Błąd**:

| Zbiór danych | Wymagane uprawnienie |
|---|---|
| Pozycje sprzedaży | Transactions: Invoice, Cash Sale and Credit Memo (View) |
| Stany magazynowe | Lists: Items and Locations (View) |
| Budżety | Transactions: Budget (View) |
| Konta statystyczne | Reports: General Ledger (View) |
| Okresy księgowe | Setup: Accounting Periods (View) |
| Spółki zależne | Lists: Subsidiaries (View) |
| Kursy wymiany | Lists: Consolidated Exchange Rates (View) |
| Klasy | Lists: Classes (View) |
| Lokalizacje | Lists: Locations (View) |

Gdy brakuje zbioru danych, test wskazuje uprawnienia do dodania. Poproś administratora o dodanie ich do roli i przetestuj ponownie. Budżety są opcjonalne: konto NetSuite, które nie używa budżetów, nadal ładuje wszystko inne. Kursy wymiany, klasy i lokalizacje również nie zatrzymują ładowania: jeśli NetSuite odmówi odczytu któregoś z nich, nie jest ono w ogóle ładowane, a sprawdzenia gotowości wskazują uprawnienie do dodania. Bez kursów wymiany dostarcz kursy w pliku **Kursy walut**.

Test nie odczytuje dostawców, przedstawicieli handlowych, pozycji faktur dostawców, sald bankowych, pozycji otwartych ani płatności. Są one opcjonalne: jeśli NetSuite odmówi odczytu któregoś z nich, po następnym ładowaniu sprawdzenia gotowości na pulpicie **CFM-Accounting - Close and assurance** wskazują uprawnienie do dodania, a reszta jest ładowana. Klasy są ładowane jako centra zysku, a lokalizacje jako lokalizacje (site). Budżety, faktury dostawców, salda bankowe, pozycje otwarte lub płatności za dany miesiąc, których odczytu NetSuite odmawia, zachowują wiersze, które już miały, i są odczytywane ponownie przy następnym ładowaniu. NetSuite nie ma własnego salda na koniec miesiąca, które odczytywałby Data Foundation, więc jego księga jest porównywana z jego własnym zestawieniem obrotów i sald.
