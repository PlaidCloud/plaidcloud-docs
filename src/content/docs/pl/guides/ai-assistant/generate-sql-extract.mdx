## Opis

Krok przepływu pracy **Wyodrębnij SQL** uruchamia zapytanie `SELECT` tylko do
odczytu na danych Twojego projektu i zapisuje wynik w nowej tabeli. Napisanie
takiego zapytania ręcznie wymaga znajomości tabel źródłowych, ich kolumn i SQL
potrzebnego do ich przekształcenia.

Edytor kroku może napisać zapytanie za Ciebie. Opisz zwykłym językiem wynik,
jaki chcesz uzyskać, a asystent AI utworzy `SELECT` — a jeśli nie powiesz mu,
z których tabel czytać, sam przeanalizuje tabele projektu i wybierze właściwe.
Wygenerowany SQL i wykryte kolumny są pokazywane do przeglądu i można je w pełni
edytować przed zapisaniem kroku.

<Aside type="note">
Korzysta to z tego samego wbudowanego modelu, którego używa asystent AI —
**nie wymaga żadnej konfiguracji**. Nie musisz w tym celu konfigurować agenta AI
ani połączenia LLM dla obszaru roboczego.
</Aside>

## Otwieranie kroku

W widoku **Kroki** przepływu pracy kliknij **Utwórz krok** i wybierz jedną z opcji:

- **Tables → Extract SQL** lub
- **AI → SQL Extract (AI Assisted)**

Obie otwierają ten sam edytor kroku Extract SQL, który zawiera teraz panel
**Generate SQL with AI** u góry strony Parametry ekstrakcji SQL.

## Generowanie zapytania

1. **(Opcjonalnie) Wybierz tabele źródłowe.** Na liście **Tabele źródłowe** wybierz
   jedną lub więcej tabel, z których ma czytać zapytanie. Pozostaw listę pustą,
   aby asystent przeanalizował projekt i wybrał za Ciebie odpowiednie tabele.
2. **Opisz, czego chcesz.** W polu **Opisz** zapisz oczekiwany wynik zwykłym
   językiem — na przykład *„sklasyfikuj każde konto księgowe do puli aktywności
   na podstawie zakresu jego numeru”*.
3. **Kliknij Wygeneruj SQL.** Asystent pisze pojedyncze zapytanie `SELECT` tylko do
   odczytu, weryfikuje je przez uruchomienie i wypełnia:
   - edytor **Zapytanie SQL SELECT** wygenerowaną instrukcją oraz
   - stronę mapowania **Wybór danych tabeli** wykrytymi kolumnami.

   Jeśli lista źródeł była pusta, tabele wybrane przez asystenta są zaznaczane
   z powrotem na liście, aby można było zobaczyć, czego użył, i dokonać korekt.

## Przeglądanie i zapisywanie

Wygenerowany SQL to punkt wyjścia, a nie czarna skrzynka:

- **Edytuj go swobodnie.** Edytor SQL jest w pełni edytowalny — przed zapisem
  możesz dopracować zapytanie, dodać złączenie lub zmienić listę kolumn. (Aby
  złączyć kilka tabel, możesz wybrać wiele tabel źródłowych lub po prostu
  zmodyfikować wygenerowane zapytanie.)
- **Wybierz tabelę docelową.** Wybierz lub nazwij **Tabela docelowa**, do której
  krok zapisuje wynik.
- **Zapisz krok.** Jest zapisywany jako zwykły krok Extract SQL i działa w ramach
  przepływu pracy jak każdy inny.

<Aside type="tip">
Jeśli asystent zwróci zapytanie, które się nie uruchamia, edytor nadal pokazuje
SQL wraz z błędem, aby można było go poprawić — lub zmienić opis i wygenerować
zapytanie ponownie.
</Aside>

## Uwagi i ograniczenia

- Asystent pisze wyłącznie instrukcje `SELECT` **tylko do odczytu**; nigdy nie
  tworzy `INSERT`, `UPDATE`, `DELETE` ani innego SQL zmieniającego dane.
- Generowanie **nie tworzy ani nie uruchamia** kroku — jedynie przygotowuje
  szkic zapytania i pokazuje podgląd kolumn. Krok jest tworzony po zapisaniu,
  a uruchamiany, gdy działa przepływ pracy.
- Wygenerowane zapytanie używa **nazw wyświetlanych** Twoich tabel — każda tabela
  jest powiązana raz na początku zapytania pod swoją nazwą (dzięki czemu kolumny,
  złączenia i filtry są zapisane zwykłymi nazwami, a nie wewnętrznymi
  identyfikatorami `analyzetable_…`). Rzeczywiste identyfikatory są przywracane
  automatycznie podczas zapisu, więc zapytanie działa bez zmian. Tabela, której
  nazwa nie jest unikatowa, zachowuje swój identyfikator.
