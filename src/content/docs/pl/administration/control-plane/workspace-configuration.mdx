Strona **Obszary robocze** zawiera listę obszarów roboczych PlaidCloud, którymi możesz zarządzać. Używaj jej do tworzenia obszaru roboczego, edytowania jego ustawień, otwierania obszaru roboczego, otwierania pulpitów, otwierania konsoli SQL, wyświetlania dzienników i metryk oraz stosowania akcji zbiorczych do wybranych obszarów roboczych.

<Aside type="caution">
	Usunięcie kasuje obszar roboczy i powiązane z nim dane. Przed usunięciem obszaru roboczego potwierdź wymagania dotyczące kopii zapasowych i retencji.
</Aside>

## Lista obszarów roboczych

Tabela obszarów roboczych zawiera nazwę, unikatowy identyfikator, wersję, kanał wydań, stan, stan wstrzymania, datę utworzenia, stan aprowizacji, klaster, dzień konserwacji i godzinę konserwacji. Tabela obsługuje wyszukiwanie, odświeżanie, akcje wierszy i akcje zbiorcze.

Dostępne akcje wierszy obejmują:

| Akcja | Opis |
| --- | --- |
| View | Otwiera szczegóły obszaru roboczego tylko do odczytu. |
| Edit | Zmienia konfigurację obszaru roboczego. |
| Delete | Usuwa obszar roboczy. |
| Home | Otwiera aplikację obszaru roboczego. |
| Dashboards | Otwiera usługę pulpitów obszaru roboczego. |
| SQL | Otwiera konsolę SQL obszaru roboczego. |
| Logs & Metrics | Otwiera dzienniki operacyjne i metryki obszaru roboczego. |

Cztery akcje usług — Home, Dashboards, SQL i Logs & Metrics — pojawiają się tylko przy obszarze roboczym, który jest uruchomiony, i tylko dla usług włączonych w tym obszarze. Obszar roboczy, który jest jeszcze tworzony, nie pokazuje żadnych ikon usług, więc nie ma łącza, które prowadziłoby donikąd.

## Stan aprowizacji

Utworzenie obszaru roboczego trwa kilka minut, a do czasu zakończenia obszar roboczy istnieje, ale nie można go otworzyć. Kolumny **Utworzono**, **Stan** i **Provisioning** informują, na jakim etapie jest obszar roboczy, a karta **Provisioning** w oknie dialogowym szczegółów obszaru roboczego pokazuje te same informacje dla jednego obszaru roboczego wraz z adresami URL usług aktualnie dla niego opublikowanymi.

| Kolumna | Co oznacza |
| --- | --- |
| Utworzono | Kiedy utworzono rekord obszaru roboczego. To także moment rozpoczęcia pierwszej próby aprowizacji. |
| Stan | Faza, na której jest aprowizacja, na przykład `activating`. Ukończony obszar roboczy ma wartość `running`. |
| Provisioning | Faza ujęta w jednym słowie: `provisioning`, `running`, `failed`, `paused`, `trashed` lub `deleting`. |

Obszar roboczy, który pozostaje w tej samej fazie dłużej niż około pół godziny, utknął, a ten ze stanem `failed` został zatrzymany. W obu przypadkach skontaktuj się z pomocą techniczną PlaidCloud, podając identyfikator obszaru roboczego i wyświetlaną fazę — szczegóły awarii zawierają nazwy wewnętrznych komponentów PlaidCloud, dlatego są przechowywane w obszarze PlaidAdmin i nie są tu pokazywane.

<Aside type="note">
	Obszar roboczy może wyglądać poprawnie w narzędziach wdrożeniowych, a mimo to nie nadawać się do użycia, ponieważ zakończenie wdrożenia to nie to samo, co zakończenie przez obszar roboczy własnej konfiguracji. Kolumna **Provisioning** raportuje własną konfigurację obszaru roboczego, a to ona decyduje, czy możesz się zalogować.
</Aside>

## Logowanie jednokrotne

Pozwól użytkownikom logować się do obszaru roboczego za pomocą dostawcy tożsamości Twojej firmy zamiast osobnego hasła PlaidCloud. Na stronie **Obszary robocze** wybierz **Single sign-on** przy obszarze roboczym. Okno dialogowe wyświetla bieżące **Sign-in options**, każdą z jej stanem (**Włączone** lub **Wyłączone**), opcją **Test sign-in** i **Usuń**, a nowe opcje dodaje się w sekcji **Add an identity provider**.

### Plany i metody logowania

Każdy plan, w tym Free (Sandbox), obejmuje logowanie hasłem z uwierzytelnianiem wieloskładnikowym (MFA) oraz logowanie społecznościowe przez Google, Microsoft (konto osobiste lub organizacyjne, logowanie „common”) i GitHub. Wyższe plany dodają logowanie jednokrotne dla przedsiębiorstw z własnym dostawcą tożsamości:

| Plan | Dodaje |
| --- | --- |
| Free (Sandbox) | Nic ponad metody logowania wchodzące w skład każdego planu |
| Starter | Nic ponad metody logowania wchodzące w skład każdego planu |
| Zespół | SAML |
| Business | Microsoft Entra ID i Okta |
| Enterprise | Inni dostawcy OpenID Connect i SCIM |

Każdy plan obejmuje wszystko, co zawierają plany niższe. W planach Free (Sandbox) i Starter okno dialogowe **Single sign-on** pokazuje informację o konieczności uaktualnienia zamiast wyboru dostawców tożsamości.

Po obniżeniu planu dodani wcześniej dostawcy pozostają na liście i nadal możesz ich usuwać, ale nie możesz dodawać nowych, których plan nie obejmuje.

### Dodawanie dostawcy tożsamości

1. Wybierz **Identity provider**: **Microsoft Entra ID**, **Okta** lub **Other (OpenID Connect)**, zależnie od tego, na co pozwala Twój plan.
2. Skopiuj **Redirect URI** przyciskiem **Kopiuj** i zarejestruj go u dostawcy tożsamości zgodnie z opisem poniżej.
3. Wypełnij pola dla swojego dostawcy i wybierz **Add provider**.
4. Wybierz **Test sign-in**, co otworzy Twój obszar roboczy, abyś mógł zalogować się przez nowego dostawcę w oknie prywatnym. Przetestuj to, zanim powiadomisz zespół.

| Dostawca | Rejestracja u dostawcy tożsamości | Dane do wprowadzenia w PlaidCloud |
|---|---|---|
| Microsoft Entra ID | W centrum administracyjnym Microsoft Entra zarejestruj aplikację (platforma Web) z identyfikatorem URI przekierowania, dodaj klucz tajny klienta w sekcji **Certificates & secrets** i dodaj opcjonalne oświadczenie `email` do tokenu ID w sekcji **Token configuration**. | **Directory (tenant) ID**, **Identyfikator klienta**, **Klucz tajny klienta** |
| Okta | W konsoli administracyjnej Okta utwórz aplikację internetową OIDC, ustawiając identyfikator URI przekierowania jako jej identyfikator URI przekierowania logowania, i przypisz osoby, które mają mieć dostęp. | **Okta domain** (na przykład `acme.okta.com`), **Identyfikator klienta**, **Klucz tajny klienta** |
| Other (OpenID Connect) | Zarejestruj poufnego klienta internetowego z identyfikatorem URI przekierowania. | **Button label**, **Discovery URL**, **Identyfikator klienta**, **Klucz tajny klienta** |

W przypadku **Other (OpenID Connect)** PlaidCloud odczytuje punkty końcowe z adresu URL wykrywania. Jeśli nie może stamtąd odczytać konfiguracji lub wystawca znajduje się w innej witrynie niż adres URL wykrywania, wybierz **Enter endpoints manually** i wypełnij **Issuer**, **Authorization URL**, **Token URL**, **JWKS URL** oraz opcjonalnie **Userinfo URL (optional)**. Adresy dostawców muszą być hostami publicznymi, z którymi PlaidCloud może się połączyć.

**Button label** to nazwa widoczna dla użytkowników na stronie logowania, na przykład *Acme SSO*.

### Istniejące konta i weryfikacja adresu e-mail

- Osoba, która ma już konto PlaidCloud z tym samym adresem e-mail, łączy je, logując się raz na to konto. PlaidCloud nigdy nie łączy kont wyłącznie na podstawie zgodnego adresu e-mail.
- **Trust email addresses from this provider (new people skip email verification)** jest domyślnie wyłączone. Nowe osoby weryfikują adres e-mail przy pierwszym logowaniu. Włącz tę opcję tylko wtedy, gdy Twój dostawca tożsamości gwarantuje prawdziwość wysyłanych adresów.

### Usuwanie dostawcy tożsamości

Wybierz **Usuń** przy dostawcy. Użytkownicy nie będą już mogli logować się przez niego. Ich istniejące konta pozostają, a aby się zalogować, mogą zresetować hasło.

## Ustawienia podstawowe

Ustawienia podstawowe identyfikują obszar roboczy, przypisują własność i kontrolują sposób wydawania aktualizacji.

| Ustawienie | Opis |
| --- | --- |
| Nazwa | Nazwa wyświetlana obszaru roboczego. |
| Identyfikator | Unikatowy identyfikator obszaru roboczego. Staje się częścią tożsamości obszaru roboczego i jest ustawiany podczas tworzenia. |
| Notatka | Opcjonalny opis lub notatka administracyjna. |
| Organizacja | Organizacja, do której należy obszar roboczy. |
| Właściciel | Adres e-mail właściciela obszaru roboczego. |
| Centrum danych (klaster) | Centrum danych lub klaster, w którym działa obszar roboczy. |
| Wydanie | Kanał wydań: Rapid, Regular, Stable lub No Release (pinned). |
| Wersja | Konkretna wdrożona wersja. |
| Aktywny | Oznacza obszar roboczy jako aktywny. |
| Wstrzymany | Wstrzymuje działanie obszaru roboczego bez jego usuwania. |
| Okres ważności łącza zaproszenia | Jak długo łącza zaproszeń dla nowych użytkowników pozostają ważne. Dostępne opcje to 12 godzin, 1 dzień, 2 dni, 3 dni, 5 dni, 7 dni, 10 dni i 14 dni. |

## Opcje wydań

| Wydanie | Typowe zastosowanie |
| --- | --- |
| Rapid | Otrzymuje aktualizacje najwcześniej. Dla obszarów roboczych, które mogą przyjmować szybsze zmiany w produkcie. |
| Regular | Domyślna częstotliwość aktualizacji dla większości obszarów roboczych. |
| Stable | Wolniejsza częstotliwość dla obszarów roboczych, dla których priorytetem jest stabilność aktualizacji. |
| No Release (pinned) | Utrzymuje obszar roboczy na wybranej wersji, dopóki administrator jej nie zmieni. |

Okno konserwacji określa, kiedy stosowane są automatyczne aktualizacje wydań.

## Automatyczne aktualizacje wydań

PlaidCloud publikuje nowe wydania w sposób ciągły i dostarcza je do Twoich obszarów roboczych automatycznie. Nie musisz żądać ani instalować aktualizacji — gdy wydanie dotrze do kanału wydań obszaru roboczego, PlaidCloud uaktualnia obszar roboczy w jego oknie konserwacji. Kanał wydań decyduje, jak szybko wydanie dotrze, a okno konserwacji — o której godzinie nastąpi uaktualnienie.

### Jak wydanie trafia do obszaru roboczego

1. PlaidCloud publikuje wydanie w kanale. Najpierw otrzymuje je Rapid, następnie Regular, a potem Stable.
2. Wszyscy w organizacji otrzymują wiadomość e-mail z wyprzedzającym powiadomieniem co najmniej siedem dni przed uaktualnieniem, zawierającą nazwę wydania i datę jego zastosowania.
3. W pierwszym oknie konserwacji obszaru roboczego po tym powiadomieniu PlaidCloud uaktualnia obszar roboczy do danego wydania. Domyślne okno konserwacji to niedziela o 02:00 UTC — dzień i godzinę ustawisz w sekcji [Konserwacja](#konserwacja).
4. **Wersja** obszaru roboczego zmienia się na nowe wydanie. Nie jest wymagane żadne działanie ze strony Ciebie ani użytkowników obszaru roboczego.

Ponieważ obszar roboczy jest uaktualniany tylko w ramach własnego okna konserwacji, aktualizacje trafiają w przewidywalnym czasie o niskim natężeniu ruchu, a siedmiodniowe powiadomienie daje każdej organizacji czas na zaplanowanie zmiany.

### Rezygnacja przez przypięcie obszaru roboczego

Aby zatrzymać obszar roboczy na bieżącej wersji, ustaw jego kanał **Wydanie** na **No Release (pinned)**. Automatyczne uaktualnienia pomijają przypięty obszar roboczy, który pozostaje na wybranej wersji, dopóki administrator nie wybierze nowej wersji lub nie przeniesie go z powrotem do kanału. Przypnij obszar roboczy, gdy musi pozostać niezmieniony — na przykład na czas cyklu walidacji lub regulowanego zamknięcia.

Przypięcie zatrzymuje tylko przyszłe uaktualnienia; nie cofa uaktualnienia, które zostało już zastosowane. Aby ponownie przesunąć przypięty obszar roboczy do przodu, wybierz konkretną **Wersję** lub kanał Rapid, Regular albo Stable, a obszar roboczy wróci do automatycznego harmonogramu.

Ustawienia usług włączają opcjonalne aplikacje i usługi pomocnicze w obszarze roboczym.

| Ustawienie | Opis |
| --- | --- |
| JupyterHub | Włącza hostowany dostęp do notatników dla użytkowników obszaru roboczego. |
| Web SQL Console (CloudBeaver) | Włącza dostęp do SQL w przeglądarce. |
| Dashboards (Apache Superset) | Włącza usługę pulpitów. |
| User Forms & Workflows (Forms Flow) | Włącza obsługę aplikacji formularzy i przepływów pracy. |

Niektóre usługi mogą wymagać dodatkowej aprowizacji poza formularzem płaszczyzny sterowania, zanim użytkownicy będą mogli z nich korzystać.

## Lakehouse

Ustawienia Lakehouse kontrolują zewnętrzną łączność z bazą danych i dodatkowych użytkowników bazy danych.

| Ustawienie | Opis |
| --- | --- |
| Enable External Database Access | Pozwala klientom zewnętrznym łączyć się z lakehouse obszaru roboczego. |
| Allowed CIDRs | Rozdzielone przecinkami zakresy CIDR, którym wolno się łączyć. Pozostaw puste, jeśli lista dozwolonych nie jest potrzebna. |
| Denied CIDRs | Rozdzielone przecinkami zakresy CIDR, którym odmawia się dostępu. |
| Additional Lakehouse Users | Dodatkowe nazwy użytkowników i hasła lakehouse do dostępu do bazy danych. |

Używaj najwęższych zakresów CIDR, które obsługują Twoich użytkowników i integracje. Usuń nieużywanych użytkowników lakehouse, gdy dostęp nie jest już potrzebny.

## Konserwacja

Ustawienia konserwacji określają preferowane okno aktualizacji obszaru roboczego.

| Ustawienie | Opis |
| --- | --- |
| Dzień | Dzień tygodnia konserwacji: od niedzieli do soboty. |
| Godzina | Pora dnia w odstępach 15-minutowych. |

Uaktualnienia kanału wydań korzystają z okna konserwacji obszaru roboczego. Przypięte obszary robocze są pomijane przez automatyczne uaktualnienia kanału wydań, dopóki administrator nie wybierze nowej wersji lub kanału.
