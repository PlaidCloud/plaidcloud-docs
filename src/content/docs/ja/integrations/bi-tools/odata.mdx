OData フィードは、プロジェクトのテーブルを OData v4 サービスとして提供します。Power BI、Excel、Tableau は、それぞれ独自の OData コネクタで読み取るため、インストールするものはありません。接続する前に、BI フィードクライアントを作成してプロジェクトに追加してください。[BI ツールを接続する](/ja/integrations/bi-tools/)を参照してください。

フィードのアドレスは、プロジェクトの**アクセスと共有**ページの **BI フィードクライアント**カードにある、プロジェクトの**フィード URL**です。

```text
https://odata.<workspace host>/v1/projects/<project id>/
```

どのツールも基本認証でサインインします。ユーザー名にクライアント ID、パスワードにクライアントシークレットを入力します。

<Aside type="caution">
クライアント ID とシークレットは、ツールが認証情報を求める場所にのみ入力してください。Power Query（M）のクエリで `Web.Contents` を呼び出してトークンを取得したり、シークレットを自分で送信したりしないでください。フィードにトークンは不要であり、クエリに書いた内容はレポートやブックに保存され、ファイルを開いた人なら誰でも読み取れます。
</Aside>

## Power BI Desktop

1. **Get data** > **OData feed** を選択します。
2. プロジェクトの**フィード URL**を貼り付けて、**OK** を選択します。
3. Power BI が認証情報を求めたら、**Basic** を選択し、**User name** にクライアント ID、**Password** にシークレットを入力して、**Connect** を選択します。
4. **Navigator** で、読み込むテーブルを選択します。

Power BI はテーブルをインポートします。OData フィードでは DirectQuery は使用できません。

行数が 1,000,000 を超え、[ページ単位で提供](#ページ単位で提供されるテーブル)されないテーブルは、読み込む前にフィルターするか、[増分更新](#power-bi-で増分更新を使用する)を設定してください。[1 回の読み取りを行数の上限内に収める](#1-回の読み取りを行数の上限内に収める)を参照してください。

## Power BI Service

Power BI Desktop からレポートを公開し、セマンティックモデルにクライアントの認証情報を設定します。

1. セマンティックモデルの設定で **Data source credentials** を開き、OData ソースの **Edit credentials** を選択します。
2. **Authentication method** で **Basic** を選択し、クライアント ID とシークレットを入力してサインインします。
3. スケジュールされた更新を設定します。

Power BI Service はフィードを直接更新するため、オンプレミスのデータゲートウェイは不要です。Microsoft のクラウドアドレスから接続するため、ワークスペースですべてのアドレスを許可する必要があります。[外部アクセスを有効にする](/ja/integrations/bi-tools/#外部アクセスを有効にする)を参照してください。

クライアントのシークレットを再生成したときは、ここにも新しいシークレットを入力してください。入力しないと、次の更新が失敗します。

Power BI Service は、1 分あたり約 100 万行の速度でフィードを読み取るため、1,000 万行のテーブルの更新には約 10 分かかります。速度はテーブルとウェアハウスによって異なります。シークレットが再生成された場合やクライアントがプロジェクトから外された場合など、フィードが更新を拒否したときは、Power BI Service は失敗を報告する前に何度か再試行するため、15 分ほどかかることがあります。

## Excel

1. **Data** タブで、**Get Data** > **From Other Sources** > **From OData Feed** を選択します。
2. プロジェクトの**フィード URL**を貼り付けて、**OK** を選択します。
3. **Basic** を選択し、**User name** にクライアント ID、**Password** にシークレットを入力して、**Connect** を選択します。
4. **Navigator** でテーブルを選択し、**Load** を選択します。

ワークシートに入る行数は最大 1,048,576 行です。それより大きなテーブルは、代わりに **Load To...** でデータモデルに読み込みます。

## Tableau

Tableau Desktop の場合:

1. **Connect** で **To a Server** > **OData** を選択します。
2. **Server** として、プロジェクトの**フィード URL**を貼り付けます。
3. **Authentication** で **Username and Password** を選択し、クライアント ID とシークレットを入力して、**Sign In** を選択します。

Tableau Cloud の場合は、データに接続するときに **OData** コネクタを選択し、同じ**フィード URL**、クライアント ID、シークレットを入力します。

Tableau は OData フィードをエクストラクトに読み込みます。テーブル全体を読み取る前に、読み取りを開始して途中で止め、サンプルを取得するため、各テーブルは複数回読み取られます。Tableau Cloud でエクストラクトを更新するには、認証情報を埋め込んでデータソースを公開します。Tableau Cloud は独自のアドレスから接続するため、ワークスペースでそのアドレスを許可する必要があります。[外部アクセスを有効にする](/ja/integrations/bi-tools/#外部アクセスを有効にする)を参照してください。

Lakehouse v2 では、Tableau Desktop は[ページ単位の読み取り](#ページ単位で提供されるテーブル)を最後まで追跡するため、ページ単位で提供されるテーブルは、サイズにかかわらず読み取れます。それ以外の場合に、行数の上限を超えるテーブルを読み取るには、Tableau Desktop または Tableau Server から、行数の上限がない [Flight SQL](/ja/integrations/bi-tools/flight-sql/#tableau-desktop-と-tableau-server) を使用してください。

## 1 回の読み取りを行数の上限内に収める

1 回のリクエストで返される行数は最大 1,000,000 行です。テーブルが[ページ単位で提供](#ページ単位で提供されるテーブル)されない限り、それを超える読み取りは、黙って途中で止まるのではなく、次のメッセージで失敗します。

> This table has more rows than one OData request may return (1,000,000). Filter it with $filter, or use incremental refresh.

上限内に収めるには、次の方法があります。

- **Power Query で値または範囲でフィルターする。** 値と等しい行、または 2 つの数値や日付の間にある行を残すフィルターはフィードに送信されるため、条件を満たす行だけが読み取られます。
- **Power BI で増分更新を使用する。** 更新のたびに 1 つの日付範囲だけが読み取られます。[下記](#power-bi-で増分更新を使用する)を参照してください。

### Power BI と Excel がフィードに送信する内容

Power BI と Excel の Power Query は、一部のステップをフィードに任せ、残りは自分で処理します。

- **フィードが処理するもの:** 値、数値の範囲、日付の範囲によるフィルター、列の選択、並べ替え、上位の行の取得。
- **Power Query が処理するもの:** **Contains**（`Text.Contains`）などのテキストフィルターと、行数のカウント（`Table.RowCount`）。Power Query はテーブル全体を読み取ってローカルで処理するため、大きなテーブルでは、代わりに値または範囲でフィルターしてください。
- **フィードが処理できないステップの後**（列の追加など）では、Power Query はテーブル全体を読み取り、エラーなしでクエリの残りを自分で処理します。そのようなステップの前にフィルターを置いてください。

Power Query は、送信する読み取りのたびに、同じクエリの最初の 1,000 行も読み取ります。

### ページ単位で提供されるテーブル

Lakehouse v2（StarRocks）では、上限を超える行数のテーブルを、代わりにページ単位で提供できます。各ページの末尾には次のページへのリンクがあり、Power BI、Excel、Tableau Desktop が自動的にたどります。ページのサイズは一定ではありません。各ページには上限の半分以上、上限以下の行が含まれ、最後のページには残りの行が含まれます。すべてのページは、最初のページが読み取られた時点のテーブルを読み取るため、更新中に書き込みがあっても、行が欠けたり重複したりしません。

ページ単位の読み取りでは、各ページを前のページから 15 分以内に取得し、最初のページから 6 時間以内に完了する必要があります。そうでない場合や、読み取り中のテーブルのバージョンが、テーブルが置き換えられた場合などで保持されなくなった場合は、もう一度更新するよう求めるメッセージとともに更新が失敗します。

Lakehouse v1（Databend）や、お客様自身の Snowflake または Databricks ウェアハウスでは、ページ単位の読み取りは行われません。`$orderby` で並べ替える場合、`$top` で上限以下の行数を指定する場合、独自の列 `_row_id` を持つテーブルを読み取る場合も同様です。レイクハウスのカタログが時間内に応答しない場合など、PlaidCloud が読み取るテーブルのバージョンを固定できないときも、ページ単位にはなりません。その場合は、1 回のリクエストで上限までの行が返されます。

## Power BI で増分更新を使用する

大きなテーブルには、増分更新を設定します。Power BI は、テーブルを 1 つの日付範囲ずつ更新するため、各リクエストが行数の上限内に収まります。

1. Power Query で、`RangeStart` と `RangeEnd` という名前の 2 つのパラメーターを、**Date/Time** 型で作成します。
2. テーブルの日付またはタイムスタンプの列を、`RangeStart` 以降、`RangeEnd` より前の行にフィルターします。
3. Power BI Desktop でテーブルの増分更新ポリシーを設定し、公開します。

パラメーターは単なる日付と時刻ですが、フィードはタイムスタンプをタイムゾーン付きの UTC で、日付を時刻なしで送信します。そのため、タイムスタンプの列は `RangeStart` そのものではなく `DateTime.AddZone(RangeStart, 0)` と、日付の列は `Date.From(RangeStart)` と比較してください。タイムスタンプの列を `RangeStart` そのものと比較すると、更新は `We cannot apply operator < to types DateTime and DateTimeZone.` で失敗します。

例:

```text
let
    Source = OData.Feed("https://odata.<workspace host>/v1/projects/<project id>/", null, [Implementation = "2.0"]),
    Orders = Source{[Name = "Orders"]}[Data],
    InRange = Table.SelectRows(Orders, each [OrderDate] >= DateTime.AddZone(RangeStart, 0) and [OrderDate] < DateTime.AddZone(RangeEnd, 0))
in
    InRange
```

Power BI はこのフィルターをフィードの `$filter` に変換するため、各範囲の更新では、その範囲の行だけが読み取られます。フィルターは、テーブルを選択した直後に、フィードに渡せないステップより前に置いてください。

## クエリオプション

| オプション | フィードの動作 |
| --- | --- |
| `$select` | 指定したプロパティだけを返します。 |
| `$filter` | 条件を満たす行だけを返します。[フィルター](#フィルター)を参照してください。 |
| `$orderby` | 1 つ以上のプロパティで、それぞれ `asc` または `desc` で並べ替えます。空の値は、昇順では先頭、降順では末尾に並びます。 |
| `$top` | 指定した行数までを返します。 |
| `$skip` | 指定した行数をスキップします。`$orderby` と併用した場合のみです。 |
| `/$count` | `<entity set>/$count` は、`$filter` で残る行数をプレーンテキストで返します。 |
| `$format` | JSON のみです。 |

フィードは、`$expand`、`$search`、`$apply`、`$count=true`（代わりに `/$count` を使用してください）、`$orderby` を伴わない `$skip`、式による `$orderby` には応答しません。その場合、Power BI と Excel は、そのオプションなしでテーブルを取得し、そのステップを自分で適用します。

### フィルター

`$filter` では、次のものを使用できます。

- **比較:** `eq`、`ne`、`gt`、`ge`、`lt`、`le`、`in`。`eq null` と `ne null` で、空の値と入力済みの値を検索できます。
- **論理と算術:** `and`、`or`、`not`、`add`、`sub`、`mul`、`div`、`mod`。
- **テキスト関数:** `contains`、`startswith`、`endswith`、`length`、`indexof`、`substring`、`tolower`、`toupper`、`trim`、`concat`、`matchesPattern`。
- **日付と時刻の関数:** `year`、`month`、`day`、`hour`、`minute`、`second`、`date`、`now`。
- **数値関数:** `round`、`floor`、`ceiling`。

日付は `2024-01-31`、タイムスタンプは `2024-01-31T09:00:00Z`（別のオフセットを持つものは、UTC の同じ時点として読み取られます）、テキストは単一引用符で囲み、内部の引用符は `'O''Neil'` のように重ねて書きます。小数は、最大 38 桁まで、書かれたとおりに正確に比較され、整数は 64 ビットに収まる必要があります。

`cast`、`isof`、`time`、期間、地理関数、日付と時刻の算術はサポートされていません。

これは、ツールが送信したときにフィードが応答する内容です。Power BI と Excel が送信するのはその一部だけです。[Power BI と Excel がフィードに送信する内容](#power-bi-と-excel-がフィードに送信する内容)を参照してください。

## フィードが提供する内容

### テーブルと名前

クライアントが読み取れる各テーブルはエンティティセットに、その各列はプロパティになります。ビューは含まれません。

名前は、テーブルと列の名前から付けられます。

- A から Z の文字、数字、アンダースコアだけで構成され、文字またはアンダースコアで始まる名前は、そのまま使用されます。
- それ以外の名前では、スペースや記号などの文字の並びが 1 つのアンダースコアに置き換えられ、先頭と末尾にはアンダースコアは残りません。A から Z 以外の文字は保持されますが、A から Z またはアンダースコアで始まらない名前には、先頭にアンダースコアが付きます。したがって、`Sales 2024 (EMEA)` は `Sales_2024_EMEA`、`2024 Sales` は `_2024_Sales`、列 `Cost Center Name` は `Cost_Center_Name` になります。
- テーブルの名前は 125 文字、列の名前は 128 文字で切り詰められます。

名前は、Power BI の比較方法と同様に、大文字小文字を区別せずに比較されます。`Sales` と `SALES`、`Sales 2024` と `Sales_2024` のように 2 つの名前が同じになる場合は、それぞれに、アンダースコアと、そのテーブルまたは列から作られた短いコード（`Sales_1a2b3c4d` など）が付きます。コードは、更新のたびに変わりません。ただし、名前の変更によって 1 つのテーブルの名前が別のテーブルの名前と衝突した場合は、両方にコードが付くため、どちらかを元の名前で読み取るレポートは何も見つけられなくなります。解消するには、どちらかのテーブルの名前を変更してください。

### キー

各エンティティセットのキーは、テーブルに更新キーがあり、そのどれも浮動小数点数やバイナリではない場合に、その更新キーです。そうでない場合は、そのどちらでもない最初の列で、それもなければ最初の列です。キーは一意である必要も、入力済みである必要もありません。Power BI と Excel は、キーの値が重複したり空だったりするテーブルも読み込みます。

### 型

| 列の内容 | OData の型 |
| --- | --- |
| true または false | `Edm.Boolean` |
| 整数 | サイズに応じて `Edm.Int16`、`Edm.Int32`、`Edm.Int64` |
| 通貨を含む小数 | 列の精度と位取りを持つ `Edm.Decimal` |
| 浮動小数点数 | `Edm.Double` |
| テキスト | `Edm.String`。列に最大長がある場合はその長さを持ちます |
| 日付 | `Edm.Date` |
| タイムスタンプ | UTC の `Edm.DateTimeOffset` |
| 時刻 | `Edm.TimeOfDay` |
| 日と時間の間隔 | `Edm.Duration` |
| バイナリ | `Edm.Binary` |
| JSON、リスト、構造体、UUID、64 ビットを超える整数、月を含む間隔、その他すべて | 値をテキストとして保持する `Edm.String` |

フィードは、小数と 64 ビットの整数を、1 桁ずつ正確に送信します。ただし、Power BI と Excel は数値を倍精度浮動小数点数として保持し、有効桁数は約 15 桁です。それより桁数の多い小数は末尾の桁が失われ、9,007,199,254,740,992 を超える整数も同様です。金額の場合は、Power Query で列の型を **Fixed decimal number** に変更すると、小数点以下 4 桁が正確に保持されます。

## 読み取りが失敗した場合

サインインのメッセージは、[BI ツールを接続する](/ja/integrations/bi-tools/#ツールがサインインできないまたはテーブルが表示されない場合)に記載されています。サインインした後は、次のようになります。

| メッセージ | 対応 |
| --- | --- |
| This table has more rows than one OData request may return (1,000,000). Filter it with $filter, or use incremental refresh. | [1 回の読み取りを行数の上限内に収める](#1-回の読み取りを行数の上限内に収める)を参照してください。 |
| This feed has no entity set … | テーブルが削除された、名前が変更された、クライアントのロールから非表示になった、または名前が[別のテーブルと衝突している](#テーブルと名前)可能性があります。ツールのテーブル一覧を更新してください。 |
| … not a property of … | クエリが、テーブルにすでに存在しない列、またはフィードでの名前を使っていない列を指定しています。 |
| The $filter is not valid … | ツールが、フィードで読み取れないフィルターを送信しました。メッセージに、読み取れなかった内容が示されます。 |
| This next link has expired … | [ページ単位の読み取り](#ページ単位で提供されるテーブル)で、ページ間に 15 分を超えて待機しました。もう一度更新してください。 |
| This read began more than 6 hours ago … | ページ単位の読み取りに 6 時間を超えてかかりました。もう一度更新してください。 |
| The table changed while this feed was reading it, or was written to a moment ago. Refresh to read it again. | テーブルが置き換えられた場合などで、ページ単位の読み取りが、読み取り中のテーブルのバージョンを失いました。もう一度更新してください。 |
