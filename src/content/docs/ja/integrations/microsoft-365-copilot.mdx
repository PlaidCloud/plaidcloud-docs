PlaidCloudのデータを **Microsoft 365 Copilot** で利用できます。PlaidCloudエージェントをインストールし、ユーザーにアクセス権を付与すると、プロジェクト、テーブル、ディメンション、配賦モデルについて、自然な言葉でCopilotに質問できます。別途ログインする必要も、PlaidCloudのウィンドウを開く必要も、SQLを書く必要もありません。

> *「自分のPlaidCloudプロジェクトを一覧表示して」*
> *「Enterprise Profitabilityにはどのテーブルがありますか。そのうち1つの先頭の行を見せてください」*
> *「アトランタのコストセンターに配賦されたITコストが前四半期に増えたのはなぜですか」*

<Aside type="note">
これは、開発者のIDEをPlaidCloudに接続する [GitHub Copilot](/ja/integrations/ai-coding-agents/copilot/) とは異なります。このページで扱うのは **Microsoft 365 Copilot** です。Teams、Outlook、Microsoft 365アプリに搭載されている、チーム全員がすでに使っているアシスタントです。
</Aside>

## 仕組み

PlaidCloudは、Microsoft 365 Copilotに組み込める小さな **エージェント** を公開しています。ユーザーがCopilotにデータについて質問すると、エージェントがPlaidCloudワークスペースに安全に接続し、そのユーザー自身の権限でリクエストを実行します。そして、Copilotが結果を説明します。

- **ほとんどのユーザーは読み取り専用です。** 一般的なアクセスレベルは読み取り専用で、プロジェクトやテーブルの一覧表示と詳細確認、テーブルデータの読み取り、ディメンションメンバーの一覧表示、配賦結果の説明ができます。数値を作り出すことはありません。すべての回答は実際のデータに対するクエリから得られ、各回答には信頼度のシグナルと平易な言葉での注意事項が付きます。詳しくは[信頼できる回答](/ja/integrations/ai-coding-agents/honest-answers/)をご覧ください。
- **各ユーザーには自分のデータだけが表示されます。** リクエストはサインインしたユーザーとして実行され、そのユーザーがすでに持っているPlaidCloudのロールとアクセス制御の範囲内に制限されます。エージェントが、認証情報、ID、アクセス制御の設定にアクセスすることはありません。
- **付与されるまでアクセスはできません。** エージェントをインストールしただけでは、アクセスは付与されません。PlaidCloud管理者がアクセスレベルを付与するまで、サインインしたユーザーには「アクセスが付与されていません」というメッセージが表示されます。これは意図的な仕様です。[アクセスレベル](#アクセスレベル)をご覧ください。

これらの背後で何が行われているか（公開されるエージェントパッケージ、専用のOAuthクライアント、アクセスレベルの解決と適用の方法）については、[Copilotアーキテクチャ](/ja/integrations/ai-architecture/microsoft-365-copilot/)をご覧ください。

## セットアップの概要

完全なパスを順に示します。関与するロールは最大3つですが、同じ人が複数の役割を兼ねることもよくあります。**手順1～5でエージェントをインストールし、手順6で実際にデータが流れるようになります。**

| # | 手順 | 担当 | 場所 |
|---|---|---|---|
| 1 | [エージェントパッケージをダウンロードする](#手順1エージェントパッケージをダウンロードする)（`.zip`） | PlaidCloudワークスペース管理者 | PlaidCloudコントロールプレーン → **Workspaces** |
| 2 | [カスタムアプリを許可する](#手順2カスタムアプリを許可する) | Microsoft 365 / Teams管理者 | Teams管理センター → **Setup policies** |
| 3 | [パッケージをアップロードする](#手順3パッケージをアップロードする) | Microsoft 365 / Teams管理者 | Teams管理センター → **Manage apps → アクション** |
| 4 | [Copilotにエージェントを追加する](#手順4copilotにエージェントを追加する) | 各ユーザー | Microsoft 365 Copilot → **More agents** |
| 5 | [サインインする](#手順5サインインする) | 各ユーザー | Copilot（初回のみ） |
| 6 | [アクセスレベルを付与する](#手順6アクセスレベルを付与する) | PlaidCloud管理者 | PlaidCloud |

<Aside type="caution">
**手順6を完了するまで、エージェントは接続できますがデータは返しません。** サインインに成功した後に「アクセスが付与されていません」という回答が表示された場合は、すべて正常に動作しています。そのユーザーにアクセスレベルが必要なだけで、エラーではありません。
</Aside>

## 手順1：エージェントパッケージをダウンロードする

組織のエージェントパッケージは単一の `.zip` ファイルで、[PlaidCloudコントロールプレーン](/ja/administration/control-plane/)から自分でダウンロードできます。依頼する必要も、ファイルの到着を待つ必要もありません。

<Steps>

1. **PlaidCloudコントロールプレーン** にサインインし、左のナビゲーションから **Workspaces** を開きます。

2. データを保持しているワークスペースを開きます（**編集** または **ビュー** のアクション）。

3. ワークスペースダイアログの下部にある **Download Copilot Package** をクリックし、`.zip` を保存します。

</Steps>

<Aside type="note">
**Download Copilot Package** ボタンは、PlaidCloudがワークスペースのCopilot接続を設定した後にのみ表示されます。表示されない場合は、接続の準備がまだ整っていません。PlaidCloudの担当者にお問い合わせください。（このボタンは、管理者専用のTenants画面ではなく、**Workspaces** 画面にあります。）
</Aside>

## 手順2：カスタムアプリを許可する

*Microsoft 365 / Teams管理者向け。* Microsoft 365は、デフォルトでは公式ストア以外のアプリをブロックします。そのため、この設定を有効にするまでPlaidCloudエージェントをインストールできません。

<Steps>

1. [Teams管理センター](https://admin.teams.microsoft.com/)で、**Teams apps → Setup policies → Global (Org-wide default)** に移動します。

2. **Upload custom apps** を **有効** に設定し、**保存** をクリックします。

</Steps>

<Aside type="caution">
グローバル管理者であることは、この設定が有効になっていることとは **異なります**。これは別のポリシーです。この設定をしないと、アップロードは「Uploading custom apps is not allowed.」というエラーで失敗します。ポリシーの変更が反映されるまでに最大24時間ほどかかることがあります（多くの場合ははるかに短時間です）。組織全体ではなくパイロットグループに限定する場合は、別のセットアップポリシーを作成して、そのユーザーに割り当ててください。
</Aside>

## 手順3：パッケージをアップロードする

*Microsoft 365 / Teams管理者向け。* `.zip` を組織のアプリカタログに追加します。

<Steps>

1. Teams管理センターで、**Teams apps → Manage apps** に移動します。

2. ページの **右上** にある **アクション** メニューをクリックし、**Upload new app** をクリックします。

   <Aside type="note">
   「Upload new app」は、右上隅の **アクション** メニューにあります。グレーのツールバー（Edit installs / Edit availability / …）にはありません。このツールバーは、すでに選択したアプリに対して操作します。
   </Aside>

3. ダウンロードした `.zip` を選択します。アプリがアップロードされて公開されます（**Published version 1.0.0** と表示されます）。Teams、Outlook、Copilotに対応しています。

4. アプリのページで **Availability** を設定します。全体に展開する場合は **Everyone (org-wide default)**、パイロットの場合は特定のグループを選択します。

</Steps>

<Aside type="tip">
**組織全体に展開せず、まず自分で試したい場合は、** 管理センターを使わずに [Microsoft 365 Copilot](https://m365.cloud.microsoft/chat) を開き、**エージェント** でカスタムアプリのアップロードを選択して `.zip` を指定します。自分専用にサイドロードされ、すぐに表示されます。
</Aside>

## 手順4：Copilotにエージェントを追加する

次に、各ユーザーのCopilotにエージェントを追加する必要があります。

<Steps>

1. **Microsoft 365 Copilot**（[m365.cloud.microsoft/chat](https://m365.cloud.microsoft/chat) またはTeams）を開き、エージェントの一覧にある **More agents** をクリックします。

2. **PlaidCloud** エージェントを見つけて **追加** をクリックします。エージェントの一覧に表示され、すぐに開けるようになります。どのワークスペースのエージェントも名前は **PlaidCloud** です。複数ある場合は、エージェントの説明にワークスペース名が表示されるので、区別できます。

</Steps>

<Aside type="note">
**組織全体に公開** したばかりのエージェントが **More agents** に表示されるまでには、Microsoftによる反映のため、数分、場合によっては数時間かかることがあります。**サイドロード** したアプリ（手順3のヒント）はすぐに表示されます。ユーザーが自分で追加しなくても済むよう全員にあらかじめエージェントをインストールするには、Teamsの **セットアップポリシー** でピン留めします。
</Aside>

## 手順5：サインインする

ユーザーが初めてエージェントを開いて質問すると、Copilotは **サインイン** を求めます。これは通常の、一度だけの手順です。

<Steps>

1. エージェントを開いて質問します。たとえば *「自分のPlaidCloudプロジェクトを一覧表示して」* と入力します。

2. 求められたら **Sign in** を選択し、PlaidCloudのサインインを完了します。

</Steps>

その後は接続が記憶されるため、毎回、あるいは毎日サインインする必要はありません。新たにサインインが必要になるのは、たまに（おおよそ月に1回）、またはアクセスが変更された場合のみです。

<Aside type="note">
すでにMicrosoft 365にサインインしていても、このサインインは対話的に行われます。Copilotが独自のサインインウィンドウを開き、既存のセッションは引き継がれないためです。これは想定どおりの動作です。ウィンドウにはPlaidCloud独自のブランドが表示されるので、PlaidCloudのサインイン画面であれば、そのまま完了してください。
</Aside>

エージェントが初めてPlaidCloudのデータを読み取るとき、Copilotは一度だけ確認します。*「PlaidCloudに接続して、このリクエストと今後のリクエストを支援します。アクセスは設定からいつでも管理できます。」* ここで **許可** を選択します。以降、エージェントは確認なしに読み取り専用の検索を実行するため、複数のステップからなる質問にも一度で回答できます。エージェントによるPlaidCloudデータの検索はすべて読み取り専用で、アクセスは引き続き、そのユーザーのPlaidCloudアクセスレベル、権限、行レベルセキュリティで許可される範囲に限定されます。

## 手順6：アクセスレベルを付与する

この手順によって、「アクセスが付与されていません」という状態から、実際の回答が返る状態になります。ユーザーがサインインしたら、**PlaidCloud管理者** がそのユーザーにアクセスレベルを付与します（後述の[アクセスレベル](#アクセスレベル)をご覧ください）。アクセスは **デフォルトで拒否** されます。レベルが割り当てられていない場合、エージェントは接続できますがデータは返しません。

各レベルはPlaidCloudのグループに対応しており、ユーザーはそのうち1つに所属します。

| レベル | グループ |
|---|---|
| 読み取り専用 | **Microsoft 365 Copilot Read Only** |
| 読み取り/書き込み | **Microsoft 365 Copilot Read and Write** |
| 完全 | **Microsoft 365 Copilot Full Access** |

これらのグループのいずれにも所属していないユーザーには、管理者に依頼して **Microsoft 365 Copilot Read Only** グループ（または他の2つのうちのいずれか）に追加してもらうよう伝えるメッセージが表示されます。必要なアクセスに合ったグループに追加してください。

レベルが付与されたら、ユーザーは **もう一度質問する** だけです。サインアウトや再インストールは不要です。アクセスはリクエストのたびにリアルタイムで確認されるため、次のメッセージからデータが返されます。

<Aside type="note">
アクセスレベルはPlaidCloud側で管理されます。ユーザーへの付与（または変更）については、PlaidCloudの担当者または [support@plaidcloud.com](mailto:support@plaidcloud.com) にお問い合わせください。PlaidCloud管理者がIDを直接管理している場合は、PlaidCloudのID管理でレベルを割り当ててください。
</Aside>

## アクセスレベル

PlaidCloud Copilotのすべてのユーザーは、3つのレベルのうち1つを持ちます。このレベルはエージェントができることの **上限** です。その範囲内でも、ユーザー自身のPlaidCloud権限が引き続き適用されるため、エージェントがユーザー自身にアクセスできないデータを表示したり変更したりすることはありません。

| レベル | エージェントが読み込むツール | 書き込み | 生のSQL | 主な用途 |
|---|---|---|---|---|
| **読み取り専用** | 読み取りと検索のツールのみ。プロジェクトとテーブルの一覧表示と詳細確認、テーブルデータの読み取り、ディメンションメンバーの一覧表示、配賦の説明。 | 不可。読み取りと詳細確認のみ。 | 読み取りクエリのみ（`SELECT` と集合演算）。書き込みを行うステートメントは拒否されます。 | ほとんどのユーザー。安全なデフォルトです。 |
| **読み取り/書き込み** | 読み取り専用のすべてに加え、ユーザーが使用を許可されている書き込みツール（テーブルデータの更新、ディメンションノードの編集、ドキュメントのアップロードなど）。 | 可。構造化された書き込みのみで、いずれもユーザー自身の権限の範囲内です。 | 読み取りクエリのみ。変更は書き込みツール経由で行い、生の書き込みSQLは使えません。 | データを管理するアナリスト。 |
| **完全** *（非推奨。2027年1月15日に廃止）* | ユーザーが利用できるPlaidCloudのツールセット全体から、以下の常時ブロックされる操作を除いたもの。 | 可。構造化された書き込みと、書き込みを行う生のSQL。ユーザー自身のデータベースロールの範囲内です。 | 読み取りと書き込みのSQL。 | パワーユーザーとビルダー。 |

どのレベルにも共通するルールがあります。

- **デフォルトで拒否。** レベルが割り当てられていなければ、アクセスはできません。レベルが付与されるまで、何も公開されません。
- **最も権限が広いレベルが優先。** 何らかの理由で複数のレベルを持つユーザーには、最も高いレベルが適用されます。
- **完全レベルであっても、エージェントが決して利用できない操作があります。** 認証情報、ID、アクセス制御、コードデプロイに関するツールは、ユーザー自身のPlaidCloud権限にかかわらず、人間のみが操作できます。エージェントは、どのレベルでも次のことを行えません。
  - **認証情報やアクセス制御の変更**：データ接続の認証情報と、接続の所有者やアクセス権を持つユーザー、ドキュメントストアの認証情報とそのアクセス制御、プロジェクトのアクセス制御、プロジェクトのERP転記モード、メンバーアカウント、グループのメンバーシップとロール、配布リスト、パスワードのリセット、公開。
  - **コードのデプロイや作成**：ユーザー定義関数のコード、JupyterLiteアプリ、Panelアプリ。

## エージェントの使い方

Copilotを開き、PlaidCloudエージェントを選択して、自然な言葉で質問します。最初の質問の例を示します。

- **作業内容を探す：** *「自分のPlaidCloudプロジェクトを一覧表示して」* / *「プロジェクトXにはどのテーブルがありますか」*
- **データを読む：** *「customersテーブルの先頭の20行を見せてください」* / *「Regionディメンションにはどの値がありますか」*
- **結果を説明する：** *「アトランタのコストセンターに配賦されたコストが第1四半期から第2四半期で変わったのはなぜですか」*
- **持ち出す：** *「これをスプレッドシートとしてエクスポートして」* エージェントは、取得したデータからCSV、Excel、PowerPoint、Wordのファイルを作成します。

エージェントは適切なツールを選び、データに対してクエリを実行し、Copilotが回答します。回答は結果から始まり、その後に短い表や要約が続きます。権限のないデータが必要なリクエストや、自分のレベルを超える変更のリクエストの場合は、推測せずにその旨を伝えます。

## すぐに答えが得られる質問のしかた

Copilotは、ビジネス上の質問に合った分析パス、プロジェクト、テーブルを見つけます。また、PlaidCloudが返したエラーを読み取って、リクエストを修正して再試行するため、問題が起きても言い換える必要はありません。いくつかの工夫で、回答がより速く正確になります。

- **指標とフィルターを平易な言葉で示す。** *「UDMのFY2027 EBITDA、Allocated、DairyCheese」* は、指標（EBITDA）とフィルター（会計年度、測定単位、シナリオ、事業部門）を示しています。フィルター済みの合計は、1回の検索で返ります。
- **対象範囲を明示する。** 合計が会社全体、事業部、1つの事業部門のいずれにもなり得る場合は、どれを指すのかを伝えてください。曖昧な場合、Copilotは推測せずに質問します。
- **Copilotが示すフィルターを確認する。** すべての回答には、適用したフィルターが一覧表示されます。意図と異なるものがあれば伝えると、Copilotがやり直します。
- **複数の分析パスを使う場合は、分析パスの名前を指定する。** [分析パス](/ja/integrations/ai-coding-agents/analysis-paths/)をご覧ください。

## 得意な質問

エージェントは、具体的なビジネス上の質問で最も力を発揮します。例を示します。

| 質問 | エージェントの動作 |
|---|---|
| *「UDM、Allocatedの、DairyCheeseのFY2027 EBITDA」* | フィルター済みの合計を返します。[メトリック定義](/ja/integrations/ai-coding-agents/metric-definitions/)がある場合はそれを使用し、適用したフィルターを一覧表示します。 |
| *「製品別の売上、数量、コストを表示して」* | 行のサンプルではなく、テーブル全体を1回で処理して、製品ごとにすべての指標を集計します。 |
| *「工場12のポンドあたりのコストはいくらですか」* | $/lbなどの名前付きの数値を、そのメトリック定義から回答します。 |
| *「ITコストはコストセンターにどのように配賦されていますか」* | 配賦モデルに基づいて、使用されているドライバーとその基準という方法論を説明します。 |
| *「これをスプレッドシートとしてエクスポートして」* | 取得したばかりのデータから、CSV、Excel、PowerPoint、Wordのファイルを作成します。 |

エージェントは、各分析パスの説明に書かれた固定のフィルター、符号の規則、ビジネス用語も読み取り、そのパスに対するすべての質問に適用します。

## 管理者向けセットアップチェックリスト

エージェントの精度は、管理者が与えるコンテキストの質に左右されます。インストール後に、次の作業を行ってください。

1. **各分析パスに説明を書く。** テーブルの内容、符号の規則、常に適用されるフィルター、ビジネス用語を記述します。エージェントは、そのパスに対するクエリのたびにこれを読みます。[AIアシスタントに役立つパスにする](/ja/integrations/ai-coding-agents/analysis-paths/#aiアシスタントに役立つパスにする)をご覧ください。
2. **ユーザーが尋ねるビジネスメトリックを定義する。** プロジェクトにメトリック定義がある場合、エージェントは売上やポンドあたりのコストなどの名前付きの数値をそこから回答するため、全員が同じ数値を得られます。[メトリック定義](/ja/integrations/ai-coding-agents/metric-definitions/)をご覧ください。
3. **パッケージを最新に保つ。** ファイルの作成と、メトリック、内訳、配賦方法論に関する回答には、パッケージバージョン1.4.0以降が必要です。パッケージを再度ダウンロードして[更新](#エージェントパッケージの更新)してください。

| 症状 | 原因と対処 |
|---|---|
| Manage appsに **Upload new app** が見つからない | ページの右上にある **アクション** メニューにあります。グレーのツールバーにはありません。まったく表示されない場合は、[カスタムアプリを許可する](#手順2カスタムアプリを許可する)がまだ有効になっていません。 |
| インストール時に **「Uploading custom apps is not allowed」** と表示される | *Upload custom apps* ポリシーが無効です。有効にして（[手順2](#手順2カスタムアプリを許可する)）、反映されるまで待ってから、再試行してください。 |
| エージェントがCopilotのエージェント一覧にない | **More agents** で探し、**追加** をクリックしてください。組織全体に公開したエージェントは、表示されるまで時間がかかることがあります。すぐに試すには、[`.zip` を自分にサイドロード](#手順3パッケージをアップロードする)してください。 |
| **「No Microsoft 365 Copilot access has been granted to this user」** | [アクセスレベルが付与される](#手順6アクセスレベルを付与する)までは想定どおりの動作です。ユーザーはサインインして接続済みで、レベルが必要なだけです。付与された直後にもう一度質問してください。 |
| **「Ask an administrator to add you to the Microsoft 365 Copilot Read Only group」**（または別のレベル） | ユーザーがまだCopilotのアクセスグループに所属していません。必要なレベルの[グループにユーザーを追加](#手順6アクセスレベルを付与する)してから、もう一度質問してもらってください。 |
| CopilotがPlaidCloudにクエリを実行するツールがないと言う | エージェントパッケージが古くなっています。コントロールプレーンから最新バージョンに[更新](#エージェントパッケージの更新)し、新しいチャットを開始してください。 |
| データを変更するリクエストが拒否される | ユーザーのアクセスレベル（またはユーザー自身のPlaidCloud権限）では、その書き込みが許可されていません。適切であれば、[アクセスレベル](#アクセスレベル)を引き上げてください。 |
| 正常に動作していたのに、再度サインインを求められた | 正常な動作です。保存された接続は定期的（おおよそ月に1回）に更新されます。もう一度サインインして続行してください。 |
| 回答に、ユーザーがアクセスできないデータが必要なようだ | 想定どおりの動作です。エージェントは、サインインしたユーザーがすでに閲覧を許可されているデータだけを返します。 |
| **読み取り専用** のユーザーがサインインできるのにテーブルを読み取れない | 暫定的な問題で、対応を進めています。現在、読み取り専用のCopilotユーザーがテーブルを読み取るには、より広いAnalyzeアクセスが必要です。[support@plaidcloud.com](mailto:support@plaidcloud.com) にお問い合わせください。 |

## エージェントパッケージの更新

PlaidCloudがエージェントパッケージの新しいバージョンをリリースしたら、管理者は次の3つの手順で更新します。

<Steps>

1. コントロールプレーンからパッケージを再度ダウンロードします（[手順1](#手順1エージェントパッケージをダウンロードする)）。

2. Teams管理センターで **Manage apps** を開き、PlaidCloudエージェントを選択して **更新** を選び、新しい `.zip` をアップロードします（[手順3](#手順3パッケージをアップロードする)）。

3. ユーザーに、エージェントとの **新しいチャット** を開始するよう依頼します。すでに開いているチャットは、以前の動作のままです。

</Steps>

アクセスレベルとサインインは引き継がれるため、誰も再度サインインする必要はありません。更新後もCopilotが以前のバージョンを使い続ける場合は、エージェントを削除して追加し直してください。Agent Storeを開き、エージェントの **…** メニューから **Uninstall** を選択し、**Built by your org** から再度追加します。その後、新しいチャットを開始してください。
