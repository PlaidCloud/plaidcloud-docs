**LLMプロバイダー接続**では、ワークスペースのAIを動かすモデルを選択します。接続には、プロバイダー、APIキー、デフォルトモデル、標準の指示が含まれます。また、モデルに許可する操作の範囲を管理者が決定する場所でもあります。

## 接続に含まれる内容

| フィールド | 内容 |
|---|---|
| **プロバイダー** | Anthropic、OpenAI、Google Gemini、xAI Grok、Azure OpenAI、GitHub Modelsのいずれかです。 |
| **APIキー** | ご自身のキーです。利用料金は、PlaidCloud経由で再販されるのではなく、そのプロバイダーのご自身のアカウントに請求されます。 |
| **デフォルトモデル** | APIキーを使って取得した、プロバイダー自身の最新のラインナップから選択します。**その他…** オプションでは、一覧にないモデルのIDを入力できます。 |
| **ベースURL** | 読み取りを行うプロバイダーにのみ表示されます。Azure OpenAIでは必須（リソースのエンドポイント）で、OpenAI、Grok、GitHub Modelsでは任意の上書きです。AnthropicとGeminiでは使用しません。 |
| **APIバージョン** | Azure OpenAIのみです。 |
| **ルール** | すべてのシステムメッセージの先頭に付加される標準の指示です。社内の規約、トーン、やってはいけないことなどを指定します。 |
| **エージェントアクセス** | この接続を使用するエージェントとステップに許可する操作の上限です。引き上げない限り読み取り専用です。 |

名前、メモ、接続を表示できるユーザーもここで設定します。また、**接続をテスト**でキーを事前に確認できます。

ワークスペースには複数の接続を登録でき、そのうち1つがデフォルトになります。ワークフローのステップで、ワークスペースのデフォルトとは別のモデルが必要な場合は、特定の接続を固定できます。

ワークスペースには、プロバイダーが1つの接続タイプのフィールドになる前から存在する、古い**Anthropic Claude**接続が残っている場合があります。設定内容は同じで、同じエディターで開き、プロバイダーはAnthropicに固定されます。新しい接続は**LLMプロバイダー**として作成してください。

<Aside type="tip">
**モデルの一覧はPlaidCloudではなく、プロバイダーから取得されます。** 接続を開くと、キーで利用できるモデルをプロバイダーに問い合わせるため、今朝リリースされたモデルでも、PlaidCloudのリリースを待たずに選択できます。プロンプトに応答できないモデル（埋め込み、音声、画像、モデレーションのモデル）は除外されます。

プロバイダーに接続できない場合（キーが未入力、キーの誤り、障害など）は、一覧がPlaidCloud組み込みのものに切り替わり、その旨が表示されます。**その他…** オプションでは、入力した任意のモデルIDを引き続き使用できます。
</Aside>

## プロバイダーとアダプター

ユーザー向けの6つのプロバイダーは、4つの実行アダプターに対応します。アダプターは、リクエストの形式と、モデルがアクセスできる範囲を決定します。以下のプロバイダー名は、接続フォームのドロップダウンに表示されるラベルです。

| プロバイダー | アダプター | 備考 |
|---|---|---|
| Anthropic (Claude) | `anthropic` | テーブル、ディメンション、ドキュメントへのスコープ付きバインディングを使用できる唯一の経路です。 |
| OpenAI (ChatGPT) | `openai_compatible` | |
| xAI (Grok) | `openai_compatible` | |
| GitHub Models | `openai_compatible` | GitHub中心のチーム向けの、GitHubがホストするモデルです。 |
| Google (Gemini) | `gemini` | |
| Azure OpenAI | `azure` | リソースのエンドポイントを使用します。「モデル」は**デプロイ名**で、APIバージョンは接続から取得されます。 |

<Aside type="caution">
**GitHub Copilotはここでは選択できません。これは見落としではありません。** Copilotには、サーバーから接続できる単独のチャットAPIがなく、OAuthトークンをエディターの利用権限と交換する仕組みです。CopilotクラスのGPTモデルに対するMicrosoftの経路は、**Azure OpenAI**（またはGitHub Models）です。*IDEクライアントとしての*GitHub CopilotがPlaidCloudに接続することはまったく別の話で、問題なく動作します。[GitHub Copilot](/ja/integrations/ai-coding-agents/copilot/)を参照してください。
</Aside>

## ツールの仲介方法

ここでのLLMは、PlaidCloudのツールを呼び出せて初めて役に立ちます。**対話型**アシスタントには2つの仕組みがあり、どちらが動作するかはプロバイダーによって決まります。（無人の[LLMワークフローステップ](#llmワークフローステップは別扱い)は動作が異なります。そのセクションも併せてお読みください。）

### サーバー側コネクター：Anthropic

AnthropicのAPIは、有効期間の短い委任トークンを携えて、PlaidCloudのMCPエンドポイントに自ら接続します。ツールカタログはAnthropic側で管理されるため、モデルにはトークンが呼び出しを許可されているすべてのものが見え、補助なしでツールを検出できます。

これは、後述する**スコープ付きバインディング**をサポートする唯一の経路でもあります。

### クライアント側ループ：それ以外のすべて

他のプロバイダーには同等のコネクターがないため、PlaidCloudが自らループを実行します。クライアントとして自身のMCPサーバーに接続し、ツールを一覧表示し、ネイティブの関数定義としてモデルに渡します。モデルが要求した呼び出しを実行して結果を返し、モデルが回答を生成するまで繰り返します。

次の2つの上限により、動作は予測可能になります。

- **ツールの公開範囲の上限。** プロバイダーは1つのリクエストで宣言できる関数の数を制限しており、スキーマごとにプロンプトトークンを消費します。公開されるセットには上限があり、直接のリスト外にあるものもモデルが見つけて呼び出せるように、検出用のメタツールは常に含まれます。
- **固定のラウンドトリップ制限。** ツールのループが暴走した場合は、トークンを際限なく消費せずに停止します。

<Aside type="note">
仲介の方法は異なりますが、適用されるルールは同じです。クライアント側ループは同じ委任トークンで同じMCPサーバーを呼び出すため、スコープ、ACL、エージェントアクセス、拒否リストは、Anthropicの経路とまったく同じように適用されます。
</Aside>

## LLMワークフローステップは別扱い

ここまで説明した内容は、対話型のAIに関するものです。無人の**LLMワークフローステップ**はクライアント側ループをまったく使用しません。ステップ用のプロバイダーを選ぶ前に、この違いを理解しておくことが重要です。

| ステップの接続のプロバイダー | ステップでできること |
|---|---|
| **Anthropic** | MCPコネクター経由でデータにアクセスします。アクセスは**スコープ付きバインディング**、つまりステップで指定した特定のテーブル、ディメンション、ドキュメント（それぞれ読み取りまたは書き込みを指定）に制限されます。ツールが存在していても、それ以外のオブジェクトへのアクセスは拒否されます。 |
| **それ以外すべて** | **データアクセスなし。** ステップは構造化された1回の補完です。プロンプト、ルール、スキーマを入力し、JSONを出力します。 |

これにより、次の2つの結果が直接生じます。

- **Anthropic以外のステップでは、バインディングは無視されます。** 暗黙に適用されることも、エラーになることもありません。スコープ付きのデータアクセスはAnthropic専用であることをステップがログに記録し、バインディングなしで実行されます。バインディング付きのステップをAnthropicから別のプロバイダーに切り替えると、データを読み取らなくなります。
- **Anthropic以外のステップでは、結果スキーマが必須です。** 呼び出すツールがないため、ステップが生成するのは構造化された出力だけです。

<Aside type="caution">
ステップでプロジェクトのオブジェクトを読み書きする必要がある場合は、Anthropic接続を使用してください。それ以外のプロバイダーでも、プロンプトで渡したテキストの分類、要約、抽出、書き換えは可能ですが、何かを取得しに行くことはできません。
</Aside>

## エージェントアクセス

すべてのLLM接続には**エージェントアクセス**の設定があります。これは**上限**であり、操作するユーザー本人の実際の権限と常に重ね合わせて適用されます。

| エージェントアクセス | この接続上のエージェントとステップに許可される操作 |
|---|---|
| **読み取り専用** *（デフォルト）* | 一覧表示、説明、テーブルデータの読み取り、ディメンションメンバーの読み取り、ドキュメントの読み取り、読み取り専用SQLの実行。 |
| **読み取りと書き込み** | 上記に加えて、PlaidCloudの書き込みツールを通じて、ユーザー本人にすでに許可されている変更。生のSQLは読み取り専用のままです。 |
| **完全** *（非推奨：2027年1月15日に削除）* | 書き込みを行うSQLを含む、ユーザー本人のすべてのツール。代わりに**読み取りと書き込み**を使用してください。 |

どのエージェントアクセス設定でも、無条件の拒否リストが適用されます。接続と認証情報の設定、接続の所有者やアクセス権を持つユーザー、ドキュメントアカウントの認証情報とACL、メンバーとグループの管理、パスワードのリセット、プロジェクトのACL、プロジェクトのERP転記モード、公開、ユーザー定義関数のコード、アプリのデプロイは、AIの認証情報から呼び出すことはできません。

Anthropicのワークフローステップでは、エージェントアクセスは**バインディング**と連動します。**読み取りと書き込み**では、書き込みはバインドされたオブジェクトごとに許可されるため、ステップはチェックを入れた1つのテーブルにだけ書き込め、それ以外には書き込めません。

## 構造化された結果

ステップで結果スキーマを宣言すると、回答は文章から解析されるのではなく、スキーマに照らして検証されます。プロバイダーによってスキーマの表現が異なるため、スキーマはプロバイダーごとに変換されます。OpenAI互換のエンドポイントには厳密なJSON形式、Geminiには OpenAPIのサブセットが使われます。拒否や途中で切れた応答は、わかりにくい「無効なJSON」ではなく、それぞれ個別のエラーとして示されます。

## 知っておきたい安全対策

- **送信先URLは、呼び出しの前に検証されます。** ベースURLはHTTPSで、パブリックアドレスに解決される必要があります。ループバック、プライベート範囲、リンクローカル、クラウドのメタデータアドレスは拒否され、リダイレクトは無効化されているため、応答によって呼び出しが別の場所に飛ばされることはありません。
- **キーはログやエラーに含まれません。** プロバイダーのエラーは、認証情報を含んだままそのまま返されるのではなく、除去されます。
- **ルールは指示であり、権限ではありません。** 接続の標準ルールはモデルの動作を方向づけますが、モデルがアクセスを許可される範囲を引き上げることはできません。
