*約 20 分 · セキュリティグループ、割り当て済みのメンバー、範囲を絞ったアクセス*

あなたは PlaidCloud ワークスペースの管理者になったばかりで、参加を待っている人たちがいます。ただし、全員にすべてを見せるべきではありません。このチュートリアルでは、一連の流れを一通り説明します。適切な人をワークスペースに参加させ、一連の権限を**セキュリティグループ**にまとめ、メンバーを割り当て、そのグループがアクセスできる範囲をプロジェクト単位、さらに設定されていれば個々の行にまで絞り込みます。

ここで扱う要素（組織、ワークスペース、メンバー、セキュリティグループ）は、決まった形で組み合わさっています。このモデルに慣れていない場合は、先に[IDおよびアクセス管理（IAM）](/ja/administration/access/)をお読みください。図が掲載されています。要点は次のとおりです。組織にはワークスペースが含まれ、ワークスペースにはメンバーが含まれ、**セキュリティグループは 1 つのワークスペース内の権限のまとまり**で、これにメンバーを割り当てます。ワークスペース間で何かが漏れることはなく、それぞれが独自にアクセスを管理します。

以降の作業の大半は、ワークスペースの左側にある **ID** タブで行います。そこでセキュリティを管理できるだけの管理アクセスが必要です。

> **付与できるのは、自分が持っている権限だけです。** グループの権限を保存するとき、PlaidCloud は自分が持っていない権限には何も変更を加えず、表示すらしません。付与したい機能がマトリックスにない場合は、その権限を持つ人に依頼してください。マトリックスで編集できるのは、自分が管理している権限だけです。

## ステップ 1: 適切な人をワークスペースに参加させる

セキュリティグループを割り当てられるのは、すでにワークスペースにいるメンバーだけなので、まずここから始めます。メンバーをワークスペースに追加するには、その前に**組織**の一員であり、メンバー管理フォームに表示されている必要があります。

ワークスペースに新しいメンバーを追加するには、次の手順を実行します。

1. **ID** を開き、**メンバー** タブを選択します。
2. ドロップダウンメニューで **すべて** をクリックして、現在のメンバーを一覧表示します。
3. **ワークスペースメンバーを追加** をクリックし、必須フィールドに入力して **作成** をクリックします。

新しいメンバーには、サインイン用の認証情報を記載したウェルカムメールが自動的に送信されます。すでに組織にいる人を*このワークスペース*に追加するには、**Organization Settings**（右上のメニュー）→ **Workspaces** → メンバーアイコンの順に選択し、その人をワークスペースにドラッグして **提出** をクリックします。その人がまだ組織にまったく所属していない場合は、同じ画面の招待アイコンを使って招待メールを送信します。

> **メンバーシップは外側の関門であり、細かな制御ではありません。** ワークスペースに所属していれば、そのワークスペースにアクセスできます。中に入ってから*何ができるか*は、割り当てられているセキュリティグループによって決まります。これが次の 3 つのステップです。

追加、招待、削除の全手順については、[ワークスペースメンバーの管理](/ja/administration/access/overview/managing-workspace-members/)と[メンバー管理](/ja/administration/access/member-management/)を参照してください。

## ステップ 2: セキュリティグループを作成する

セキュリティグループは、名前を付けた権限のまとまりです。1 人ずつ機能を付与するのではなく、まとまりを一度定義して、そこに人を割り当てます。

1. **ID** を開き、**セキュリティ** タブを選択します。
2. ドロップダウンメニューで **セキュリティグループ** をクリックします。既存のグループがフォームに表示されます。
3. **セキュリティグループを作成** をクリックし、役割に基づいたわかりやすい名前を付けます。たとえば `Analysts`、`Report Viewers`、`Workspace Admins` などです。
4. グループの権限を設定するには、グループの横にある一番左のアイコンをクリックして権限マトリックスを開き、このグループに持たせる機能を選択して保存します。

マトリックスで使用できる権限は、ワークスペース内のアプリケーションから提供されます。各アプリケーションが独自の権限セットを公開しています。グループを作成する前に、アプリケーションが提供する権限の全一覧を確認するには、**セキュリティ** ドロップダウンで **Security Bins** をクリックし、左側のタグアイコンでアプリケーションを開きます。このビューは参照用です。実際の権限の付与は、上記のグループのマトリックスで行います。

> **グループは多くせず、少なく。** ワークスペースで作成できるセキュリティグループの数に上限はありませんが、グループが増えるほど、監査時に考慮すべき対象も増えます。実際にメンバーが共有する役割に基づいてグループを設計し、業務が許す範囲で数を少なく保ってください。

## ステップ 3: グループにメンバーを割り当てる

グループを定義したら、そこに人を入れます。

1. **ID → セキュリティ → セキュリティグループ** で、グループの横にある **メンバー** アイコンをクリックします。
2. このグループの権限を持たせる人にチェックを入れます。フィルターボックスに入力して検索したり、メールアドレスの一覧を貼り付けたりできます。誰かからグループを外すには、そのチェックボックスのチェックを外します。変更ごとに、**Will add** または **Will remove** のピルが表示されます。
3. **割り当てを更新** をクリックします。

これで付与は完了です。チェックを入れたメンバーは、グループにまとめられたすべての権限を持ち、チェックを入れていないメンバーは持ちません。フィルター、貼り付け、その他のコントロールについては、[ピッカーを使った割り当て](/ja/administration/access/managing-security-groups-and-assignments/#ピッカーによる割り当て)で説明しています。

> **空の割り当ては何も行いません。これは意図的な動作です。** 誰も割り当てずにグループを保存しても、何も変更されず、その旨が通知されます。グループの権限を全員から取り除くには、権限を削除するか、グループを削除してください。メンバーの一覧を空にして取り消そうとしないでください。

### オプション: グループを新規メンバーのデフォルトにする

すべての新規メンバーに基本の権限（たとえば、共有レポートの読み取りアクセス）を持たせたい場合は、グループをデフォルトとして設定します。新規メンバーは自動的にそのグループに割り当てられるため、手動で割り当てるのを忘れる心配がありません。グループの作成時または編集時に、セキュリティグループウィンドウの下部にある **新規ユーザーにデフォルトで割り当て** にチェックを入れます。

## ステップ 4: グループがアクセスできる範囲を絞り込む

これで、定義済みの権限セットを持つメンバーができました。PlaidCloud は、**組織 → ワークスペース → プロジェクト**という段階的なレイヤーでアクセスの範囲を絞り込むため、外側から内側へ制限を強めていくことができます。

| レイヤー | 制御する対象 | 設定する場所 |
|---|---|---|
| ワークスペース | メンバーがそもそもワークスペースにアクセスできるかどうか | ワークスペースのメンバーシップ（ステップ 1） |
| セキュリティグループ | 中に入った後に持つ機能 | グループの権限（ステップ 2） |
| プロジェクト | **アーキテクト** などのプロジェクトレベルの権利 | プロジェクトごとのセキュリティグループの権限 |
| 行（オプション） | ガバナンス対象のテーブルのうち、グループに見せる*行* | 行アクセス（後述） |

ほとんどのチームでは、最初の 3 つのレイヤーで十分です。人をワークスペースに入れ、各グループにその役割に必要な権限だけを付与し、プロジェクト上の **アーキテクト** などのプロジェクトレベルの権利は、グループの権限を通じて範囲を絞ります。プロジェクトに対する権利を持たないグループは、そのプロジェクトで操作できません。

### 行単位の制御が必要な場合

2 人が*同じ*テーブルを見る一方で、*見える行は異なる*ようにしたい場合（たとえば、各地域のマネージャーに自分の地域だけを見せる場合）は、**行アクセス** を使います。プロジェクトの列（たとえば `region`）を、セキュリティグループが見られる行を決める列として指定し、特定の値（`East`、`Central`）を特定のグループに付与できます。これは最も細かいレイヤーで、オプションです。使用しない場合、グループは他の権限で許可されているすべての行を見ることができます。

プロジェクトのアーキテクトは、**テーブルエクスプローラー**のテーブル、列のファセットメニュー、またはプロジェクトの **セキュリティ** タブから行アクセスを開きます。保存すると、すぐに有効になります。ダッシュボードには約 1 分以内に反映され、追加で適用する作業は必要ありません。列の制限、値の付与、ダッシュボードへの変更の反映といった仕組みについては、[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)で詳しく説明しています。このチュートリアルでは、意図的にそこへの案内にとどめています。

> **行アクセスは、データを読み取るあらゆる場所でユーザーに従います。** 保存すると、グループの行の付与により、そのメンバーがダッシュボードや、閲覧者として読み取るアプリで見られる内容がフィルターされます。これは、Panel アプリがサインイン中のユーザーとして認証する際に使用するユーザー単位のモデルと同じです。その経路については、[データの読み取りとサインイン中のユーザー](/ja/guides/panel-apps/accessing-data/)を参照してください。

> **行を制限すると、プロジェクトを変更できるユーザーも絞られます。** プロジェクトで列を制限すると、そのワークフロー、ステップ、ユーザー定義関数、スケジュール、変数を変更できるのは、そのプロジェクトのアーキテクトとテナント管理者のみになります。それ以外のユーザーは、引き続きそれらを実行できます。[行を制限するプロジェクトを変更できるユーザー](/ja/administration/access/managing-security-groups-and-assignments/#行を制限しているプロジェクトを変更できるユーザー)を参照してください。

## ステップ 5: 作業内容を確認する

完了とする前に、割り当てが意図したとおりになっていることを確認します。

1. **ID** を開き、レールの **セキュリティ** の下にある **Group audit** を選択します。
2. すべてのメンバーとグループにわたるグループのメンバーシップを、1 か所で確認します。
3. 記録を残すには、テーブルの **ユーザー名** の右端にあるアイコンをクリックし、**CSVのエクスポート** または **Export XLSX** を選択します。

役割が変わるたびに、この監査をもう一度実行してください。誰がどのグループに属しているかの全体像を一度に確認できる、唯一の画面です。

**設定は完了です。** セキュリティグループができ、メンバーが割り当てられ、ワークスペースからプロジェクトまで、そして必要であれば個々の行まで、アクセスの範囲が絞り込まれました。
