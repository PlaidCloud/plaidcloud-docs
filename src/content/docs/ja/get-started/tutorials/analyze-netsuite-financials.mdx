これは、経理責任者やFP&Aアナリストが最初の日に進める手順です。最後まで進めると、NetSuiteから**総勘定元帳**を直接取得し、財務諸表のように読める**月次の損益計算書**に変換し、**売掛金エージング**を作成して、両方をダッシュボードに配置し、全体が自動的に更新されるように設定できます。スプレッドシートへのエクスポートも手作業での再入力も不要で、数値はNetSuiteから取得され、常に最新の状態に保たれます。

接続は1回、取得も1回です。その後は、本当に重要な作業、つまり月曜の朝にビジネス担当者が読む集計へ、元の総勘定元帳の行を整形していきます。

## 前提条件

- PlaidCloudのワークスペースと、作業用のプロジェクト（必要な場合は[トライアルを開始](https://app.plaidcloud.com)してください）。
- **動作するNetSuite接続。** 最初に[NetSuiteに接続する](/ja/guides/connections/netsuite/)の手順を完了してください。NetSuiteでOAuth 2.0とREST Web Servicesを有効にし、統合のクライアントID、証明書ID、アカウントID、秘密鍵のPEMを用意する必要があります。ここから始める前に、**テストリクエストを送信**が成功していることを確認してください。
- データの整形にSQLは不要です。標準の変換ステップで行います。クエリを書くのはNetSuiteからの**取得**だけで、取得用のクエリはすべて用意されています。このチュートリアルはその内容を基にしているので、[NetSuite SuiteQLクエリ例](/ja/guides/connections/netsuite-financial-queries/)をタブで開いておいてください。

<Aside type="note">
クエリを書くのはNetSuiteからの**取得**だけです。これは*NetSuite内部で*実行される**SuiteQL**です。その後の処理（総勘定元帳を損益計算書にまとめる、売掛金をバケットに分ける）は、PlaidCloudのポイント&クリックの変換ステップで行い、SQLは使いません。（SQLに慣れている方向けにSQL抽出ステップもありますが、ここでは必要ありません。）
</Aside>

## ステップ1: ワークフローを作成する

ワークフローは、データを取得して整形するパイプラインです。

<Steps>

1. プロジェクトを開き、**ワークフロー**タブに切り替えます。
2. **新規ワークフロー**をクリックし、`NetSuite Financials`のような名前を付けて開きます。

</Steps>

## ステップ2: 総勘定元帳を取得する

1回のSuiteQLクエリで、1年分の転記アクティビティ（すべての勘定科目、すべての月）を取得できます。これだけで、損益計算書と、後で作成するその他の財務諸表の両方を作成できます。

<Steps>

1. [RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を追加します。**リクエスト**タブで、**接続**にNetSuite接続を、**メソッド**に`POST`を、**エンドポイント**に`/services/rest/query/v1/suiteql`を設定します。

2. **本文**に、次のSuiteQLを`{"q": "…"}`の形式で囲んで入力します。

   ```sql
   SELECT
       TO_CHAR(t.trandate, 'YYYY-MM')  AS period,
       a.accttype                      AS account_type,
       a.acctnumber                    AS account_number,
       BUILTIN.DF(a.id)                AS account_name,
       tal.amount                      AS amount
   FROM transactionaccountingline tal
       JOIN transaction t ON t.id = tal.transaction
       JOIN account a     ON a.id = tal.account
   WHERE tal.posting = 'T'
       AND tal.accountingbook = 1
       AND t.trandate BETWEEN TO_DATE('2026-01-01', 'YYYY-MM-DD')
                          AND TO_DATE('2026-12-31', 'YYYY-MM-DD')
   ORDER BY period, a.acctnumber
   ```

3. **レスポンス**タブで、保存先を**テーブル**に設定して`netsuite_gl`という名前を付け、列のタイプを設定します。`amount`は**通貨**、それ以外はすべて**テキスト**にします。（SuiteQLは数値と日付をテキストとして返します。タイプを設定することで、`amount`を合計できるようになります。）

4. **テストリクエストを送信**をクリックして実行できることを確認し、ステップを実行します。これで`netsuite_gl`テーブルができました。勘定科目ごと、月ごとに1行で、符号付きの転記金額が入っています。

</Steps>

<Aside type="note">
`amount`は**借方が正、貸方が負**です。これはNetSuiteの総勘定元帳の規則で、元データそのままの値です。次のステップで、読みやすい財務諸表に変換します。帳簿が複数の子会社や通貨にまたがる場合は、1つの子会社に絞り込んでください（`t.subsidiary = <id>`）。[クエリ例](/ja/guides/connections/netsuite-financial-queries/#すべてのレシピで共通の規則)にある、複数通貨に関する注意を参照してください。
</Aside>

## ステップ3: 総勘定元帳を損益計算書に整形する

ここからが分析です。ポイント&クリックの変換1つで行い、SQLは使いません。損益計算書は、総勘定元帳を集約したものにすぎません。収益と費用の勘定科目をいくつかの行にまとめ、収益がプラスで表示されるよう符号を反転します。[Table Extract ステップ](/ja/reference/workflow-steps/tables/table-extract/)の**テーブルデータの選択**タブと**フィルター**タブで、これをすべて実行できます。

<Steps>

1. **Table Extract**ステップを追加します。**ソース**に`netsuite_gl`を、**ターゲット**に新しいテーブル`netsuite_pnl`を設定します。

2. **フィルター**タブで、収益と費用の勘定科目だけを残します（貸借対照表の勘定科目は除外します）。**`account_type`** の条件に **いずれかに一致** を選び、`Income`、`OthIncome`、`COGS`、`Expense`、`OthExpense` を指定するフィルターを追加します。

3. **列**タブで**集計**をクリックして集計を有効にし、3つのターゲット列を設定します。

   - **`period`** — ソースからそのままマッピングします。集計は**グループ化**です。
   - **`pnl_line`** — 勘定科目タイプを損益計算書の行に変換する**式**（下記）です。集計は**グループ化**です。
   - **`amount`** — **式** `netsuite_gl.amount * -1`（符号の反転）です。集計は**合計**です。

   `pnl_line`では、**式**のセルをダブルクリックして次の式を入力します（エディターでは、列と、**条件**グループの`case`関数をポイント&クリックで選択できます）。

   ```python
   case(
       (netsuite_gl.account_type.in_(['Income', 'OthIncome']),  '1 - Revenue'),
       (netsuite_gl.account_type == 'COGS',                     '2 - Cost of Goods Sold'),
       (netsuite_gl.account_type.in_(['Expense', 'OthExpense']), '3 - Operating Expenses'),
   )
   ```

4. ステップを実行します。

</Steps>

`amount * -1`の式が、唯一の会計上の操作です。借方が正の金額の符号を反転することで、**収益がプラス、コストがマイナス**になり、各月の3つの行を合計すると*純利益になります*。続いて、`period`と`pnl_line`で**グループ化**して**合計**することで、すべての勘定科目が月ごとにこの3つの行にまとめられます。式にはPlaidCloudのポイント&クリックのエディターを使用します。[データマッパーの高度な使い方](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/)と[式リファレンス](/ja/reference/expressions/)を参照してください。

<Aside type="tip">
数十の勘定科目を3つの行にまとめるのは、最初の分析としてあえて大まかにしています。営業費用を部門別に分けるには、ステップ2の取得に`department`を追加し（`transactionline`を結合して`BUILTIN.DF(tl.department)`を使用）、ここで`department`を別の**グループ化**列として追加します。
</Aside>

## ステップ4: 財務担当者のように読む

`netsuite_pnl`テーブルを開きます。月ごとに3つの数値があります。

| period | pnl_line | amount |
|---|---|---|
| 2026-01 | 1 - Revenue | 486,200.00 |
| 2026-01 | 2 - Cost of Goods Sold | -190,540.00 |
| 2026-01 | 3 - Operating Expenses | -212,880.00 |

そのまま次のように読み取れます。

- **売上総利益** = 収益 + 売上原価（売上原価はすでにマイナス）→ `486,200 − 190,540 = 295,660`。
- **純利益** = 3つの行の合計 → `82,780`。
- **売上総利益率（%）** = 売上総利益 ÷ 収益 → 約61%。

最初に行うべきことは**突合**です。同じ月についてNetSuite自身の損益計算書を実行し、収益と純利益が一致することを確認します。一致しない場合は、ほとんどが範囲の違いです。子会社や通貨のフィルター、または転記期間と取引日の不一致が原因です（[期間に関する注記](/ja/guides/connections/netsuite-financial-queries/#試算表)を参照）。突合できて初めて、このパイプラインを信頼してください。

<Aside type="tip">
月が横に並ぶ従来のレイアウトにしたい場合は、`netsuite_pnl`を読み取る[Table Pivot ステップ](/ja/reference/workflow-steps/tables/table-pivot/)を追加します。`period`を列にピボットし、`pnl_line`を行のままにして、`amount`を合計します。これで、月ごとに1列、損益計算書の行ごとに1行になり、SQLなしで月次推移をひと目で確認できます。
</Aside>

## ステップ5: 売掛金エージングを作成する

2つ目の最初の日の成果で、接続、取得、整形という同じ流れで進めます。まず未回収売掛金のレシピから始め、各請求書の延滞状況でバケットに分けます。

<Steps>

1. 別の**RESTリクエスト**ステップを追加し（同じ接続、`POST`、suiteqlエンドポイント）、次の本文を設定します。

   ```sql
   SELECT
       t.tranid                            AS invoice_number,
       BUILTIN.DF(t.entity)                AS customer,
       TO_CHAR(t.trandate, 'YYYY-MM-DD')   AS invoice_date,
       TO_CHAR(t.duedate, 'YYYY-MM-DD')    AS due_date,
       t.foreigntotal                      AS invoice_total,
       t.foreignamountunpaid               AS amount_unpaid
   FROM transaction t
   WHERE t.type = 'CustInvc'
       AND t.foreignamountunpaid <> 0
   ORDER BY t.tranid
   ```

   `netsuite_open_ar`として取り込み、`invoice_total`と`amount_unpaid`は**通貨**、`invoice_date`と`due_date`は**日付**、残りは**テキスト**にします。

2. `netsuite_open_ar`を読み取り、新しいテーブル`netsuite_ar_aging`に出力する**Table Extract**ステップを追加します。**列**タブで**集計**をクリックし、3つのターゲット列を設定します。

   - **`aging_bucket`** — 各請求書の延滞状況をラベル付けする**式**（下記）です。集計は**グループ化**です。
   - **`invoices`** — 任意の列（例: `invoice_number`）です。集計は**件数**です。
   - **`balance`** — `amount_unpaid`からマッピングします。集計は**合計**です。

   `aging_bucket`には次の式を入力します。この式は延滞日数（日付から日付を引くと日数になります）を計算し、区分をラベル付けします。

   ```python
   case(
       ((func.today() - netsuite_open_ar.due_date) <= 0,  '0 - Current'),
       ((func.today() - netsuite_open_ar.due_date) <= 30, '1 - 1-30 days'),
       ((func.today() - netsuite_open_ar.due_date) <= 60, '2 - 31-60 days'),
       ((func.today() - netsuite_open_ar.due_date) <= 90, '3 - 61-90 days'),
       else_='4 - Over 90 days',
   )
   ```

3. 実行します。`netsuite_ar_aging`には、5行で、延滞していない金額と30/60/90日以上延滞している金額が示されます。これは、ビジネス担当者が最初に読む回収状況のビューです。（日付の引き算を行うには、`due_date`の型が**日付**である必要があります。これは上記のRESTリクエストステップの**レスポンス**タブで設定済みです。）

</Steps>

## ステップ6: ダッシュボードに配置する

表の数値でも問題ありませんが、CFOに送るならグラフです。`netsuite_pnl`と`netsuite_ar_aging`を[公開](/ja/get-started/tutorials/load-and-transform-data/#ステップ7結果を公開する)してから、[ダッシュボードを作成する](/ja/get-started/tutorials/build-a-dashboard/)に従って、次を追加します。

- `period`ごとの純利益（または収益）の**棒グラフ**
- `aging_bucket`ごとの売掛金`balance`の**円グラフまたは棒グラフ**

これで、エクスポート不要のライブなNetSuite財務ダッシュボードが完成しました。ワークフローを実行するたびに更新されます。

## ステップ7: 更新をスケジュールする

<Steps>

1. ワークフロー全体を上から下まで1回実行し、すべてのステップが成功することを確認します。
2. [ワークフローをスケジュールします](/ja/get-started/tutorials/schedule-a-workflow/)。決算のタイミングに合わせて月次にするか、売掛金エージングを毎朝最新にしたい場合は毎晩実行します。

</Steps>

取得はすべてテーブル全体の置き換えなので、実行のたびに`WHERE`句で定義した範囲が再抽出されます。全期間ではなく、必要な範囲（当年、未回収の請求書のみ）に絞ってください。

## 作成したもの

空のワークフローから始めて、NetSuiteの総勘定元帳と売掛金をライブで取得し、2つの標準変換ステップでSQLなしに**月次の損益計算書**と**売掛金エージング**に整形し、ダッシュボードに配置し、更新するよう設定しました。財務チームが実行する中核のレポーティングの流れが、自動化されました。
