*約 30 分 · 公開テーブル、グラフ、共有ダッシュボード*

ワークフローから公開された整理済みのテーブルがあります。このチュートリアルでは、それを誰もがひと目で読める形にします。まずグラフを作成し、次にそのグラフを中心にダッシュボードを構成して、最後に適切な相手とダッシュボードを共有します。最初のグラフを表示するのに SQL は不要で、ポイント、クリック、クエリだけで進められます。

[データの読み込み、変換、公開](/ja/get-started/tutorials/load-and-transform-data/)の手順を完了している場合は、そこで公開した `sales_final` テーブルが、このチュートリアルの出発点としてそのまま使えます。公開されているテーブルであれば、どれでも問題なく使用できます。

## 作成するもの

1 つの公開テーブルに対する 2 つのグラフを含む 1 つのダッシュボードです。売上合計を示す Big Number と、グループ化する列ごとに売上を内訳表示する棒グラフを、書式設定して保存し、ワークスペースで表示できるようにします。

## 前提条件

- PlaidCloud ワークスペースと、開くことのできるプロジェクト。
- そのプロジェクト内の**公開された**テーブル。ない場合は、先に[データの読み込み、変換、公開](/ja/get-started/tutorials/load-and-transform-data/)の手順を完了するか、既存の任意のテーブルを公開してください。**テーブル**タブでテーブルを右クリックし、**Set Published Table Reporting Name** を選択します。[テーブルの公開](/ja/guides/data/publish/)を参照してください。
- ダッシュボード領域でインストールするものはありません。PlaidCloud から初めてダッシュボードを開いたときに、ダッシュボードのアカウントが自動的に作成されます。

> **ダッシュボードに表示されるのは公開テーブルだけです。** ダッシュボードは、内部のテーブル名ではなく、公開時のレポート名でテーブルを読み取ります。後でテーブルがデータセットとして表示されない場合、通常の原因は、テーブルが一度も公開されていないか、見覚えのない名前で公開されていることです。**テーブル**タブの**公開名**列を確認してください。

## ステップ 1: ダッシュボード領域を開く

1. PlaidCloud のプロジェクトから、**ダッシュボード**領域を開きます。
2. 初めて開くときは、ダッシュボードのアカウントが自動的に設定されるため、手動で作成するものはありません。表示できる内容は、ワークスペースのメンバーシップとセキュリティグループによって決まります。
3. 公開したテーブルは、アクセスできるプロジェクトに属しているため、**データセット**として利用できるようになります。

ダッシュボードの表示範囲とワークスペースのメンバーシップの対応については、[ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。

## ステップ 2: データセットを準備する

グラフを作成する前に、各列をどのように扱うかをダッシュボードに伝えます。これはテーブルごとに一度だけ行う設定で、ポイント＆クリックのエクスプローラーを使いやすくします。

1. データセットの編集アイコンをクリックします。
2. **List Columns** タブを開きます。
3. 列ごとに、該当するロールを設定して**保存**します。

| 設定 | オンにする場合 |
|---|---|
| **Groupable** | このフィールドで指標を分解したい場合（リージョン、製品、月など） |
| **Filterable** | このフィールドでフィルターしたい場合 |
| **合計** / **最小** / **最大** | 合計または集計する数値の指標である場合 |
| **Count Distinct** | このフィールドの一意の値を数えたい場合 |
| **Is temporal** | 日付または時刻のフィールドである場合 |

> **日付の列を temporal としてマークしてください。** エクスプローラーの時間ベースのフィルターと「Since / Until」コントロールは、**Is temporal** が設定された列でしか機能しません。最も見落とされやすい設定です。

## ステップ 3: 最初のグラフを作成する

通常の Table View として開くエクスプローラーから始め、売上合計の Big Number に整形します。

> **ご自身の指標列を使用してください。** このチュートリアルでは `revenue` 列をグラフにしますが、前提条件は「公開されている任意のテーブル」だけです。`revenue` と書かれている箇所は、実際に合計したい数値列（`amount`、`sales`、`quantity` など）に置き換えてください。

1. データセットをクリックして開きます。デフォルトでは **Table View** が表示されます。
2. 指標のセクションで、必要な指標を追加します。累計の場合は、入力して合計する列を選択します（例: `revenue` の `SUM`）。行数を数える場合は **COUNT(\*)** を使用します。
3. 数値を分解したい**グループ化**フィールドを追加します。見出しとなる 1 つの数値だけが必要な場合は、グループ化を空のままにします。
4. **クエリ**をクリックして実行し、結果を表示します。
5. **Chart Options**（または可視化タイプのセレクター）までスクロールし、グラフのタイプを **Big Number** に切り替えます。グラフにはテーブル、Big Number、棒グラフなどの種類があり、同じクエリ結果をそれぞれ異なる方法で表示します。
6. もう一度**クエリ**をクリックして再描画します。

次に、同じ指標を分解する 2 つ目のグラフを作成します。

1. 同じデータセットで新しい探索を開始します。
2. 指標には `revenue` の `SUM` をそのまま使用し、`region` や `product` など Groupable な列で**グループ化**を追加します。
3. グラフのタイプを **Bar Chart** に設定して**クエリ**を実行します。
4. 上位の行だけが必要な場合は、**オプション**を開いて**行数の上限**を設定します。たとえば、上位 10 件の棒グラフなら `10` にします。

> **データを変更するより、表示書式を使用してください。** 値の丸めや書式変更には 2 つの方法があります。テーブルで値を変換する方法と、表示時に書式を設定する方法です。一般的には表示時の書式設定が選ばれます。元の値は完全な精度のまま保持され、どの閲覧者にもきれいな数値が表示されるためです。これが次のステップです。

## ステップ 4: 数値の書式を設定する

指標の生の値は、書式が設定されずに返されます。これはデータではなく、グラフ側で修正します。

- **Big Number:** グラフを編集し、**Customize** タブを開いて、**Number Format** を設定します。
- **テーブル:** グラフを編集し、**Customize** タブを開いて、**Customize Column** の下で数値列（`#` で表示）を選択し、その **D3 Format** を設定します。

デフォルトは **Adaptive formatting** で、値に合わせて調整されます。書式を固定するには、ドロップダウンから選択するか、D3 書式文字列を入力します。

| 書式 | 入力 | 表示 |
|---|---|---|
| `,d` | `12345.67` | `12,346` |
| `$,d` | `12345.67` | `$12,346` |
| `$,.2f` | `12345.67` | `$12,345.67` |
| `,.2%` | `13.215` | `1,321.50%` |

通貨記号、パディング、精度、SI 接頭辞を含む書式の完全な文法は、[数値およびその他のデータ型の書式設定](/ja/guides/dashboards/formatting-numbers/)を参照してください。

> **ドル単位に丸めるには、`,.0f` ではなく `,d` または `$,d` を使用してください。** `,.0f` 形式は数値の書式が崩れる原因として知られています。小数を切り捨てる確実な方法は `,d`（10 進数、整数に丸め）です。

## ステップ 5: 計算指標を追加する（任意）

必要な数値が単純な列ではない場合（比率、マージン率、条件付き合計など）は、メトリックとして記述します。メトリックと計算列は、データセット上で PostgreSQL 系の SQL で記述します。

```sql
SUM("revenue") / (COUNT(*) + 0.00001)
```

`+ 0.00001` は、グループに行がない場合のゼロ除算を避けるためのものです。`CASE` ロジック、NULL に対する `COALESCE`、条件付き合計など、その他のパターンについては、[メトリックの例](/ja/guides/dashboards/example-metrics/)と[計算列の例](/ja/guides/dashboards/example-calculated-columns/)を参照してください。

## ステップ 6: ダッシュボードを構成する

ダッシュボードは、保存したグラフのレイアウトです。作成した各グラフを同じダッシュボードに関連付けて、まとめて配置されるようにします。

1. Big Number の **Edit Chart** を開きます。
2. **ダッシュボード**セクションに、表示先のダッシュボードの名前を入力します。ダッシュボードがまだ存在しない場合は、ここで名前を付けます。
3. 保存し、棒グラフでも同じダッシュボードを指定して同様に繰り返します。
4. ダッシュボードを開いて、両方のグラフを確認します。ダッシュボード自体の編集モードで、タイルの配置、サイズ変更、フィルターの追加ができます。

レイアウト、フィルター、操作のオプションの全体については、[ダッシュボードについて学ぶ](/ja/guides/dashboards/learning-dashboard/)を参照してください。

## ステップ 7: 共有する

ダッシュボードを誰が見られるかは、まず PlaidCloud のアクセス権によって決まり、その上にダッシュボードサービスのロールが重なります。

- **デフォルトでは、プロジェクトのメンバーに表示されます。** PlaidCloud のダッシュボード一覧には、ユーザーがアクセスできるプロジェクトに属する公開済みのダッシュボードが表示されます。そのため、プロジェクトを開けるユーザーは誰でも、追加の手順なしでダッシュボードを見つけられます。
- **グラフの所有者は作成しながら追加します。** グラフを保存するときに、そのグラフが必要なすべてのユーザーをグラフの**所有者**に追加してください。追加しないと、同僚がアクセスできないグラフで「requires the datasource… permission」エラーに遭遇する場合があります。保存時に所有者を追加するほうが、後からアクセス権を付与し直すより簡単です。
- **特定のロールに制限するのは、必要な場合だけにしてください。** ダッシュボードは、ダッシュボードサービス内の特定のロールに限定できます。これはダッシュボード自体のプロパティで設定します。制限されたダッシュボードは、一致するロールを持たないユーザーの一覧には表示されません。そのため、制限する場合は、アクセスできるべきユーザーに伝えてください。PlaidCloud のプロジェクトのアクセス権はその上でも引き続き適用されます。ロールを付与しても、ユーザーがアクセスできないプロジェクトのダッシュボードが公開されることはありません。

表示ルールの詳細は、[ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。

## ダッシュボードを最新に保つ

ダッシュボードを手動で更新する必要はありません。ワークフローがグラフの元になっているテーブルを再公開すると、そのテーブルを読み取るすべてのグラフがキャッシュされた結果を破棄し、次にダッシュボードを開いたユーザーには新しい数値が表示されます。

> **ダッシュボードが古く見える原因が、キャッシュであることはほとんどありません。** ワークフローの実行後も数値が古い場合は、キャッシュではなくワークフローを確認してください。実行が完了し、想定どおりのテーブルが再公開されたかを確認します。また、**同じ**公開名で再公開してください。グラフは名前に紐付いているため、新しい名前でテーブルを再構築すると、古いグラフは古いデータを指したままになります。

強制的に更新する必要がある場合は、**Edit dashboard** の横のメニューを開き、**Force refresh dashboard** を選択します。結果の保持期間などの詳細は、[ダッシュボードのキャッシュ](/ja/guides/dashboards/dashboard-caching/)を参照してください。
