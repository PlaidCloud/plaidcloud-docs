このチュートリアルには約1時間かかります。終えるころには、CSVをインポートし、いくつかのテーブルステップで変換して、結果を公開する、動作するワークフローが完成します。

## 作成するもの

生の売上CSVを取り込んでクレンジングし、製品の参照テーブルと結合し、派生列を計算して、結果をクリーンなファクトテーブルとして公開するワークフローです。

```text
sales.csv  →  import  →  filter  →  join with products  →  add columns  →  publish
                              ↓
                       products.csv  →  import
```

## 前提条件

- PlaidCloudワークスペース（お持ちでない場合は[無料トライアルを開始](https://app.plaidcloud.com)してください）
- 作業用のプロジェクト（必要に応じて**プロジェクト**タブから作成してください）
- インポートする2つのCSVファイル。このチュートリアルでは、単純な売上取引ファイルと製品カタログファイルを使います。ご自身のファイルを使うことも、任意のスプレッドシートツールでサンプルデータを作成することもできます

## ステップ1：ワークフローを作成する

<Steps>

1. プロジェクトを開き、**ワークフロー**タブに切り替えます。
2. **新規ワークフロー**をクリックします。「Sales Cleanup」のようなわかりやすい名前を付けます。
3. **作成**をクリックします。空のワークフローが一覧に表示されます。
4. ワークフローをダブルクリックして、Workflow Explorerを開きます。

</Steps>

## ステップ2：売上CSVをインポートする

<Steps>

1. Workflow Explorerで、新しいステップを追加します。
2. **Import → CSV**を選択します（ソースの形式に合うインポートステップでも構いません）。
3. ステップの設定で次を指定します。
   - **ソースファイル** — 売上CSVを指定します（アップロードするか、接続済みのドキュメントアカウントから選択します）
   - **ターゲットテーブル** — `sales_raw` という名前を付けます
   - **区切り文字、引用符文字、ヘッダー行** — ファイルが標準的でない場合は調整します
4. ステップを実行します。CSVは、プロジェクトの新しいテーブルとして取り込まれます。

</Steps>

**テーブル**タブで `sales_raw` を確認します。クリックして開き、列数、サンプル行、データ型など、データが正しいかを確認します。

## ステップ3：製品カタログをインポートする

製品CSVを使ってステップ2を繰り返し、ターゲットを `products_raw` というテーブルにします。これで、結合に必要な2つの参照テーブルがそろいます。

## ステップ4：不要な行を除外する

実際の売上データには、NULLの金額、テスト取引、メインのファクトテーブルに含めたくない返金など、欠落や不要なものがあります。フィルターステップを追加して、それらを取り除きます。

<Steps>

1. **Tables → Table Lookup**ステップ（またはフィルターができる任意のテーブル変換）を追加します。
2. 次のように設定します。
   - **ソーステーブル**：`sales_raw`
   - **ターゲットテーブル**：`sales_clean`
   - **フィルター条件**：例：`amount > 0 AND status = 'completed'`
3. ステップを実行します。`sales_clean` の行数は `sales_raw` より少なくなるはずです。

</Steps>

<Aside>
フィルターは、データがソースからターゲットへ流れる際に適用されます。ソーステーブルは変更されません。これはPlaidCloudの基本的なパターンです。各ステップは1つ以上のソースから読み取り、1つ以上のターゲットに書き込み、監査可能性のために元のデータをそのまま残します。
</Aside>

## ステップ5：製品カタログと結合する

クレンジング済みの売上行と、カタログの製品詳細を組み合わせます。

<Steps>

1. **Tables → Table Inner Join**ステップを追加します。
2. 次のように設定します。
   - **左テーブル**：`sales_clean`
   - **右テーブル**：`products_raw`
   - **結合キー**：2つのテーブルを結び付ける列（例：`product_id`）
   - **ターゲットテーブル**：`sales_enriched`
3. ステップを実行します。

</Steps>

`sales_enriched` には、両方のテーブルのすべての列が含まれています。おそらく必要なのは一部の列だけです。それは次で行います。

## ステップ6：列を選択して計算する

クレンジングでは通常、不要な列を削除し、派生列を計算します。別のテーブルステップを追加します。

<Steps>

1. **Tables → Table Lookup**ステップを追加します（ここでは、列の選択と計算に使います）。
2. 次のように設定します。
   - **ソース**：`sales_enriched`
   - **ターゲット**：`sales_final`
   - **保持する列**：下流の利用側に必要なサブセット
   - **計算列**：例：`revenue = amount * price`、`margin = revenue - cost`
3. ステップを実行します。

</Steps>

列単位の計算については、[式リファレンス](/ja/reference/expressions/)で、利用できるすべての関数を説明しています。文字列操作、日付計算、条件ロジック、集計などです。

## ステップ7：結果を公開する

`sales_final` を、ダッシュボードや下流のシステムから利用できるようにします。

<Steps>

1. **Data → 公開**ステップを追加します（またはテーブルで**公開**オプションを直接使用します）。
2. 公開したテーブルを誰が読み取れるかを設定します。通常は、ワークスペースの他のメンバーと、アクセス権を持つ外部システムです。
3. ステップを実行します。

</Steps>

公開したテーブルは、適切な権限を持つ[ダッシュボード](/ja/guides/dashboards/)、BIツール、および外部の利用側から参照できるようになります。

## ステップ8：ワークフロー全体を実行する

ワークフローの**実行**をクリックします（1つのステップだけではありません）。各ステップが順番に実行される間、ログを確認します。CSVのインポートから公開までのパイプライン全体が実行されます。

いずれかのステップでエラーが出た場合は、[ステップのエラーへの対処](/ja/guides/workflows/managing-step-errors/)ガイドにデバッグの方法があります。最も多い問題は、結合キーの不良（テーブル間の不一致）と、計算列での予期しないNULL値です。
