*約 25 分 · バージョン履歴、比較、共有リンク*

複数のメンバーが同じプロジェクトで作業するとき、最初の日から重要になる疑問はいつも同じです。*何が変更されたのか。以前の状態を取り戻せるか。変更をあるプロジェクトから別のプロジェクトへ移すにはどうするか。見ているものへチームメンバーを直接案内するにはどうするか。* PlaidCloud はこの 4 つすべてに標準で対応しています。作業は**バージョン管理され、比較でき、共有できます**。このチュートリアルでは、それぞれを順に説明します。

覚えておいていただきたいのは、何も失われないということです。すべての変更が追跡され、任意の 2 つのプロジェクトを比較でき、すべての画面にリンクがあります。

## 学ぶこと

1. プロジェクトの自動的な変更履歴を確認し、そのログを読む。
2. 2 つのプロジェクトを比較し、マージの動作を理解する。
3. ラベルで作業を整理し、後から見つけやすくする。
4. チームメンバーを正確な場所に案内するディープリンクをコピーする。

## 前提条件

- PlaidCloud ワークスペースと、開くことのできるプロジェクト。
- 実際の内容で比較を試したい場合は、2 つ目のプロジェクト（コピー、または QA と本番の対応するプロジェクト）。[コピーしたプロジェクト](/ja/guides/projects/managing-projects/#プロジェクトのコピー)が適しています。

## パート 1: 作業はバージョン管理される

プロジェクトで作成するものはすべて自動的に追跡されます。有効にする操作は不要です。

> **何も失われません。** プロジェクトに対するすべての変更（ワークフロー、データエディター、階層、テーブル構造、ユーザー定義関数）が追跡され、その状態の**特定時点への復元**が可能です。つまり、誤って行った変更を元に戻せるほか、以前の任意の時点を比較用にコピーして取り出せます。

この自動追跡に加えて、プロジェクトとその要素は**バージョン管理**に対応しています。バージョンは簡単に作成でき、**あるバージョンから別のバージョンへ変更をマージ**できます。スナップショットを保管したり、1 つのバージョンで開発を行い、準備ができたらその変更を開発以外のバージョンにマージしたりするための簡単な方法です。

### プロジェクトログを読む

プロジェクトログは、個々のワークフローログをすべて 1 つにまとめ、割り当てられたメンバーや実行されたワークフローなど、プロジェクトのアクティビティを包括的に表示します。

1. **分析**を開きます。
2. **プロジェクト**を選択します。
3. **ログ**タブ（プロジェクトログ）を開きます。

ログが多くて見づらい場合は、ログメッセージの横にあるフィルターのコントロールを使用して、フィルターの条件を選択します。1 つのエントリを全文で読むには、右クリックして**ログメッセージ**ボックスを表示します。

> **ログをクリアすると、サブログも削除されます。** **ログのクリア**ボタンは、プロジェクトログと、その下にあるすべてのワークフローのサブログを*まとめて*削除します。その履歴が本当に不要な場合にだけクリアしてください。

## パート 2: 2 つのプロジェクトを比較する

比較を使用すると、2 つのプロジェクトの違いを正確に確認できます。安全にコピーできる部分については、選択した変更を一方から他方へマージできます。次の 2 つの日常的な場面に適しています。**環境間での変更の反映**（QA プロジェクトから対応する本番プロジェクトへ）と、**以前のコピーとの照合**（月次のクローンで、何が変わったかを確認する）です。

操作は常にユーザーの管理下にあります。特定の項目を選択して適用するまで何も書き込まれず、事前にドライランで検証することもできます。

### 比較を開く

1. **分析**を開き、**プロジェクト**を選択します。
2. 比較の起点にするプロジェクトを右クリックし（またはそのアクションメニューを使用し）、**比較先…** メニューを選択します。
3. 起点にしたプロジェクトが**ソース**として自動入力されます。ドロップダウンから**ターゲット**を選択します。
4. **比較**をクリックします。

2 つのプロジェクトは同じワークスペースにある必要があります。比較する前に、**入れ替え**でソースとターゲットを逆にできます。マージはソース*から*ターゲット*へ*コピーするため、方向が重要です。

### 比較結果を読む

左側には、すべての違いがカテゴリ別にグループ化されて表示されます。**ワークフロー**（**ステップ**が入れ子になります）、**変数**、**ディメンション**、**エディター**、**UDF**、**ビュー**、**テーブル**です。各項目には状態を示すバッジが付きます。

| バッジ | 意味 |
|---|---|
| **追加** | ソースにあってターゲットにない。ターゲットに作成される |
| **変更** | 両方にあるが、構成が異なる |
| **削除** | ターゲットにあってソースにない |
| **変更なし** | 両側で同一（デフォルトでは非表示） |

変更された項目を選択すると、右側に**フィールド / ソース / ターゲット**の表が表示され、その下に**構成の差分**の全体が表示されます。長い一覧を絞り込むには、名前またはパスでフィルターするか、状態のチェックボックスを切り替えます。

### マージの動作を理解する

すべての違いを安全にコピーできるわけではないため、比較では各項目にラベルが付けられます。

- **ワークフロー、ステップ、変数**はマージできます。
- **ディメンション、エディター、UDF、ビュー、テーブル**は**表示専用**です。ここで確認はできますが、コピーするには専用のツールを使用します。

マージするには、マージ可能な項目を選択し、**ドライラン**をクリックして書き込まずに検証してから、**適用**をクリックして確定します。マージされた項目はターゲットでも同一性が保たれるため、後でもう一度比較して、重複を作らずに追加の変更をマージできます。

> **マージはターゲットを変更します。** 適用する前に、差分を確認し、ドライランを実行して、ソースとターゲットの向きが正しいことを確認してください。比較を読み込んだ後に他のユーザーがターゲットを編集していた場合、マージはその作業を上書きせずに停止します。更新して、もう一度適用してください。

互いにコピーされたプロジェクト間で開発 → QA → 本番へ反映する場合は、名前ではなくコピーの系統で項目を対応付ける[コピー元のプロジェクトから再同期する](/ja/guides/projects/compare-and-merge-projects/#コピー元のプロジェクトからの再同期)を参照してください。

## パート 3: ラベルで整理する

**ラベル**は、オブジェクトに付ける自由形式のタグです。プロジェクト自体、そのワークフロー、ステップ、テーブル、ディメンション、データエディター、UDF に付けられます。作業のフェーズ、ソースシステム、担当者、リリースなど、重要な基準で関連する項目をグループ化し、すばやく見つけるために使用します。

タグを付けられるすべてのオブジェクトの詳細パネルには、**ラベル**ボックスがあります。

1. **ラベル**ボックス内の任意の場所をクリックして、カーソルを置きます。
2. ラベルのテキストを入力します。
3. **Enter** キーを押して（またはカンマを入力して）追加します。

ラベルを削除するには、チップの **×** をクリックします。入力フィールドが空の状態で **Backspace** キーを押すと、最後のラベルを削除できます。

> **ラベルは小文字で保存されます。** PlaidCloud は各ラベルを自動的に小文字にし、同じオブジェクトでの重複を受け付けません。ラベルの体系を一貫させると、大規模なプロジェクトを手軽に絞り込む方法になります。

タグ付きの項目を見つけるには、プロジェクト一覧のフィルターボックスにラベルを入力します。検索では、項目名とともにラベルのテキストも照合されます。

## パート 4: ディープリンクを共有する

PlaidCloud は、アドレスバーを開いている内容に合わせて更新します。ワークフロー、テーブル、ディメンションを開くと、URL がそれへの**ディープリンク**になります。個別の共有ボタンはありません。アドレスバーそのものがリンクです。

1. 共有したいオブジェクトを開きます。
2. ブラウザーのアドレスバーから URL 全体をコピーします。
3. それを送信します。開いた相手は同じ画面に移動します。

リンクはプロジェクトが先頭になります。最初にプロジェクト、続いてその中のオブジェクトが `~` で区切られます。

| 画面 | リンクの末尾 |
|---|---|
| プロジェクト | `#p~<project>` |
| ワークフロー（ステップのグリッド） | `#p~<project>~w~<workflow>` |
| ワークフロー（ビジュアルワークフローデザイナーのキャンバス） | `#p~<project>~c~<workflow>` |
| ワークフロー内のステップ | `…~w~<workflow>~s~<step>` |
| テーブルエクスプローラー | `#p~<project>~t~<table>` |
| ディメンション階層 | `#p~<project>~d~<dimension>` |
| データエディター | `#p~<project>~e~<editor>` |

リンクを開くと、1 つのウィンドウだけでなく**親のコンテキスト**も復元されます。ワークフローへのリンクはそのプロジェクトも開くため、受け取った相手のタブバーには周囲のプロジェクトも表示されます。ステップへのリンクの場合は、そのステップも選択された状態になります。

> **リンクが伝えるのは*場所*であり、権限ではありません。** 開いた人にも、プロジェクトへのアクセス権が必要です。アクセス権のない人にはオブジェクトが表示されないため、リンクの共有は安全です。誰が何を見られるかを管理する方法は、[データアクセスの制御](/ja/get-started/tutorials/control-data-access/)を参照してください。

以前の `#te?p=…&t=…` 形式のリンクも引き続き動作し、最初に移動したときに、現在のより読みやすい形式に自動的に書き換えられます。

**何も失われません。そして、それを示せるようになりました。** プロジェクトの履歴を読み、2 つのプロジェクトを比較して一方向に安全にマージし、ラベルで作業を整理して見つけやすくし、チームメンバーを今いる場所にそのまま案内するディープリンクを渡す手順を学びました。
