*約15分 · プロジェクトをコピーまたはインポートして、自分のものにする*

PlaidCloud で初日に成果を出す最も早い方法は、ゼロから構築することではなく、すでに動作するものから始めることです。データのインポート、変換、結果の生成がすでにできているプロジェクトを選び、自分用のコピーを作成して、自分に関係する部分を変更します。

閲覧できるテンプレートギャラリーはありません。その代わりに、動作するプロジェクトから始める確実な方法が2つあります。

- ワークスペースにすでにあるプロジェクトを、自分専用の新しいプロジェクトに**コピーする**。[プロジェクトのコピー](/ja/guides/projects/managing-projects/#プロジェクトのコピー)を参照してください。
- **ポータブルバンドルを実行する**。誰かが自己完結型の[ポータブル形式](/ja/guides/projects/export-to-portable-format/)パッケージとしてエクスポートしたプロジェクトで、PlaidCloud の外でも単独で実行できます。

どちらを選ぶかは、これからどこへ向かうかによって決まります。

| 目的 | 使用するもの | 結果 |
|---|---|---|
| PlaidCloud 内のプロジェクトを土台にして、改良を続ける | **プロジェクトをコピー** | 編集と実行をすぐに行える、自分が所有する新しいプロジェクト |

## 前提条件

- PlaidCloud ワークスペース（お持ちでない場合は[無料トライアルを開始](https://app.plaidcloud.com)してください）。
- **パスA**の場合: **プロジェクト**タブに表示されている既存のプロジェクト。自分のプロジェクト、共有されているサンプル、同僚からアクセス権を与えられたプロジェクトのいずれかです。
- **パスB**の場合: 誰かがエクスポートしたポータブル形式の `.zip`、またはエクスポートする自分のプロジェクト。

> **プロジェクトとは何かご存じですか?** プロジェクトは PlaidCloud における作業の単位です。独自のデータ、ワークフロー、ディメンション、履歴を持ち、他のプロジェクトと状態を共有しません。初めての場合は、先に[プロジェクト](/ja/guides/projects/)をお読みください。

## パスA: 既存のプロジェクトをコピーする

コピーすると、すべて、または選択した一部が完全な編集可能な複製として、完全に自分専用の新しいプロジェクトに作成されます。

1. **Analyze** を開き、**プロジェクト**タブを選択します。
2. 起点にするプロジェクトを選択します。
3. **アクション**ボタンをクリックして、**プロジェクトをコピー**を選択します。
4. ターゲットとして **a new project** を選択します。名前と **ID** を指定します。
5. 選択ツリーをすべてオンのままにしてプロジェクト全体を取り込み、**プロジェクトをコピー**をクリックします。

> **ID は変更できません。** 新しいプロジェクトに指定した ID がスキーマ名になり、後から変更できません。今後も使い続けられるものを選んでください。名前はいつでも自由に変更できますが、ID は変更できません。

コピーはバックグラウンドで実行され、完了すると通知されます。ダイアログの詳細は、[プロジェクトのコピー](/ja/guides/projects/managing-projects/#プロジェクトのコピー)を参照してください。

### 必要な部分だけを取り込む

すべてをコピーする必要はありません。選択ツリーには、プロジェクトが保持するものが種類別（ワークフロー、ステップ、テーブル、ディメンション、データエディター、ユーザー定義関数）に表示されるので、必要な部分だけにチェックを入れられます。チェックを入れたものには、依存関係が自動的に含まれます。ステップが読み書きするテーブル、ステップがロードするディメンション、呼び出す関数、実行するサブワークフローです。これらの依存関係を自分で調べる必要はありません。

> **参照をコピー先に向けたままにしてください。** **参照を更新**はオン（デフォルト）のままにします。これにより、コピーされたステップは元のプロジェクトではなく、新しいプロジェクトのテーブルとオブジェクトを指すように書き換えられます。ほとんどの場合、これが望ましい動作です。コピーが元のプロジェクトのオブジェクトを読み取り続けるようにしたい場合にのみ、オフにしてください。

## パスB: ポータブルバンドルから始める

ポータブルバンドルとは、自己完結型の Python プログラムとしてパッケージ化されたプロジェクトで、PlaidCloud に接続せずに [DuckDB](https://duckdb.org) 上で実行されます。ノート PC、CI ジョブ、PlaidCloud にログインできない人の手元など、*プラットフォームの外*で動作させたい場合に、動作するプロジェクトから始める方法です。

同僚からすでにバンドルを受け取っている場合は、[実行する](#実行する)に進んでください。自分で作成するには、次の手順を実行します。

1. **Analyze** を開き、**プロジェクト**タブを選択します。
2. プロジェクトを1つ選択します。
3. **アクション**メニューを開き、**ポータブル形式にエクスポート**を選択します。
4. パッケージの書き込み先として**ドキュメントアカウント**と**フォルダーパス**を設定し、外部ソースなしで実行できるように **Include data** をオンのままにして、**エクスポート**をクリックします。

結果は `.zip` ファイルで、ワークフローごとに1つの Python スクリプト、Parquet 形式のデータスナップショット、スクリプトに必要な Python パッケージを列挙した `requirements.txt`、そして `README.md`、`COVERAGE.md`、`RUN_ORDER.md` が含まれます。各ファイルの内容は、[ポータブル形式へのエクスポート](/ja/guides/projects/export-to-portable-format/)を参照してください。

> **ポータブルバンドルは一方向のスナップショットであり、再インポートはできません。** PlaidCloud の*外*で実行され、同期して戻ることはありません。パッケージに加えた変更はプロジェクトに戻らず、編集後に再エクスポートすると新しいパッケージが生成されます。PlaidCloud 内で作業を続けるには、代わりに**パスA**を使用してください。PlaidCloud で改良を続けながら、実行可能なコピーも配布したい場合は、両方を行ってください。

> **再現性はベストエフォートです。** SQL トランスフォームステップは正確に再現されます。アロケーション、ディメンションのロード、通知、ドキュメントとレポートのステップ、スクリプトなど、独自仕様のステップや副作用のあるステップは、再実行されないスタブとしてエクスポートされ、その代わりに、最後に具体化された出力がスナップショットとして同梱されます。各ステップの再現性は `COVERAGE.md` に記録されています。完全に再計算された結果が必要な場合は、PlaidCloud でプロジェクトを実行してください。

### 実行する

パッケージを解凍し、Python 環境を作成して、`RUN_ORDER.md` に記載された順序で各ワークフローのスクリプトを実行します。

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python pipeline_<workflow>.py
```

各スクリプトは、ローカルの DuckDB データベースにテーブルを構築します。SQL ステップはその場で再計算され、スタブ化されたステップはスナップショットされた出力をそのまま残します。

## 自分のものにする

どの方法で始めた場合も、コピーはもうあなたのものであり、自由に変更できます。ここから、初日の成果が実を結びます。最初の取り組みをいくつか紹介します。

| 内容 | 場所 |
|---|---|
| インポートの向け先を、サンプルのデータではなく*自分の*データに変更する | 各ワークフローのインポートステップ。[データのロード、変換、公開](/ja/get-started/tutorials/load-and-transform-data/)を参照 |
| プロジェクトの名前を変更する、または開ける人を調整する | [プロジェクトを管理する](/ja/guides/projects/managing-projects/) → アクセス制御 |
| 複数のワークフローで繰り返し使う値に、プロジェクト変数を設定する | [プロジェクト変数を管理する](/ja/guides/projects/managing-projects/#プロジェクト変数の管理) |
| 全体がエンドツーエンドで実行できることを確認する | 各ワークフローで**実行**をクリックして、ログを確認する |

すべての変更が追跡されるため、自由に試すことができます。[自動変更追跡](/ja/guides/projects/managing-projects/#バージョン履歴)により、編集が失敗した場合は、以前の任意の時点の状態に復旧できます。
