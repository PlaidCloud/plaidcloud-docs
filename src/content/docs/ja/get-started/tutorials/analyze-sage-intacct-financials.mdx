接続は1回、取得も1回です。その後は、本当に重要な作業、つまり月曜の朝にビジネス担当者が読む集計へ、元の残高を整形していきます。

## 前提条件

- PlaidCloudのワークスペースと、作業用のプロジェクト（必要な場合は[トライアルを開始](https://app.plaidcloud.com)してください）。
- **動作するSage Intacct接続。** 最初に[Sage Intacctに接続する](/ja/guides/connections/sage-intacct/)の手順を完了してください。Web Servicesが有効であること、読み取るオブジェクトに対する権限を持つWebサービスユーザー、そして接続の4つの認証情報フィールド（**クライアントID**、**クライアントシークレット**、**Webサービスユーザーのユーザー名**、**会社ID**）が必要です。ここから始める前に、接続が動作することを確認してください。
- 報告対象の**事業体**（エンティティID）と、損益計算書の勘定科目（収益と費用）が含まれるおおよその**勘定科目番号の範囲**を把握しておいてください。以下の例では、エンティティに`201`と`301`、損益計算書の範囲に`4010`〜`9999`を使用しています。ご自身の値に置き換えてください。

<Aside type="note">
取得後の作業はすべてポイント&クリックで行い、SQLもコードも使いません。Intacct固有の部分は**Sageのインポート**ステップだけで、日付と勘定科目の範囲を指定して、Intacctの*ディメンション別の勘定残高*を読み取ります。勘定科目とディメンションの組み合わせごとに1行が返され、それぞれに期首残高、期間残高、期末残高が含まれます。
</Aside>

## ステップ1: ワークフローを作成する

ワークフローは、データを取得して整形するパイプラインです。

<Steps>

1. プロジェクトを開き、**ワークフロー**タブに切り替えます。
2. **新規ワークフロー**をクリックし、`Intacct Financials`のような名前を付けて開きます。

</Steps>

## ステップ2: 試算表を取得する

[Sageのインポートステップ](/ja/reference/workflow-steps/sage-intacct/import-sage/)は、日付範囲と勘定科目の範囲を指定して勘定残高を取得し、選択したディメンションをすべての行に付与します。これが試算表になります。

<Steps>

1. **Sageのインポート**ステップを追加します。

2. 設定で、次を指定します。

   | フィールド | 値 |
   |---|---|
   | **接続** | Sage Intacct接続 |
   | **会社** | 読み取るIntacctの会社 |
   | **開始日** / **終了日** | 締めを行う期間（例: 月の初日と最終日） |
   | **Start account** / **End account** | 損益計算書の範囲（例: `4010`〜`9999`） |
   | **エンティティ** | 運用上のエンティティ（例: `201`、`301`） |
   | **ディメンション** | レポートに使用するものをオンにします。一般的には**場所**、**部門**、**従業員**、**クラス**です |

3. **ターゲット**を、`intacct_trial_balance`という名前の新しいテーブルに設定します。

4. ステップを実行します。これで、勘定科目とディメンションの組み合わせごとに1行ができました。`startbalance`、`periodbalance`、`endbalance`の各列に加え、有効にしたディメンションごとのIDと名前のペア（例: `departmentid` / `departmentname`、`locationname`）が含まれます。

</Steps>

<Aside type="caution">
Intacctはすべての列を**テキスト**として返します。また、Sageの取得は**単一リクエスト**（ページングなし）です。勘定残高の結果は小さいため、ここでは問題ありませんが、このステップを大量の明細データに使用しないでください。実際の列のタイプは、重要になる次のステップで設定します。
</Aside>

<Aside type="note">
**開始日**と**終了日**の両方を設定する必要があります。開始日または終了日の一方だけでは無視されます。IDと名前が不要なディメンションを有効にした場合は、次のステップで余分な列を削除できます。（**ウェアハウス**ディメンションのチェックボックスは効果がありません。出力にウェアハウスが必要な場合は、**Custom dimensions**を使用してください。）
</Aside>

## ステップ3: 残高を損益計算書に整形する

ここからが分析です。ポイント&クリックの変換1つで行い、SQLは使いません。損益計算書の範囲が、部門ごとにいくつかの財務諸表の行にまとめられ、収益がプラスで表示されるよう符号が反転されます。[Table Extract ステップ](/ja/reference/workflow-steps/tables/table-extract/)の**テーブルデータの選択**タブと**フィルター**タブで、これをすべて実行できます。

<Steps>

1. **Table Extract**ステップを追加します。**ソース**に`intacct_trial_balance`を、**ターゲット**に新しいテーブル`intacct_pnl`を設定します。

2. **列**タブで**集計**をクリックして集計を有効にし、3つのターゲット列を設定します。

   - **`departmentname`** — ソースからそのままマッピングします。タイプは**テキスト**、集計は**グループ化**です。
   - **`pnl_line`** — 勘定科目番号を損益計算書の行に変換する**式**（下記）です。タイプは**テキスト**、集計は**グループ化**です。
   - **`amount`** — **式** `func.to_float64(intacct_trial_balance.endbalance) * -1` で、テキストの残高を数値に変換して符号を反転します。タイプは**通貨**、集計は**合計**です。

   `amount`ターゲット列の**タイプ**を**通貨**に設定することで、テキストの残高を合計できるようになります。`pnl_line`では、**式**のセルをダブルクリックして次の式を入力します（列と、**条件**グループの`case`関数をポイント&クリックで選択します）。

   ```python
   case(
       (func.to_float64(intacct_trial_balance.glaccountno) < 5000, '1 - Revenue'),
       (func.to_float64(intacct_trial_balance.glaccountno) < 6000, '2 - Cost of Goods Sold'),
       else_='3 - Operating Expenses',
   )
   ```

3. ステップを実行します。

</Steps>

`* -1`が、唯一の会計上の操作です。Intacctでは収益が貸方（マイナス）、費用が借方（プラス）で保持されるため、期末残高の符号を反転すると**収益がプラス、コストがマイナス**になり、各部門の行を合計すると*純利益になります*。`case()`の勘定科目番号の区切りは、ご自身の勘定科目表に合わせて調整してください。式にはPlaidCloudのポイント&クリックのエディターを使用します。[データマッパーの高度な使い方](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/)と[式リファレンス](/ja/reference/expressions/)を参照してください。

<Aside type="tip">
部門別ではなく全社の損益計算書にしたい場合は、ターゲット列から`departmentname`を外し、`pnl_line`（グループ化）と`amount`（合計）だけを残します。
</Aside>

## ステップ4: 財務担当者のように読む

`intacct_pnl`テーブルを開きます。部門ごとに3つの数値があります。

| departmentname | pnl_line | amount |
|---|---|---|
| Operations | 1 - Revenue | 486,200.00 |
| Operations | 2 - Cost of Goods Sold | -190,540.00 |
| Operations | 3 - Operating Expenses | -212,880.00 |

そのまま次のように読み取れます。

- **売上総利益** = 収益 + 売上原価（売上原価はすでにマイナス）→ `486,200 − 190,540 = 295,660`。
- **純利益** = 3つの行の合計 → `82,780`。
- **売上総利益率（%）** = 売上総利益 ÷ 収益 → 約61%。

最初に行うべきことは**突合**です。同じ期間とエンティティについてIntacct自身の損益計算書（財務レポート）を実行し、収益と純利益が一致することを確認します。一致しない場合は、ほとんどが範囲の違いです。含めていないエンティティ、損益計算書の一部を除外してしまう勘定科目の範囲、または期間の不一致が原因です。突合できて初めて、このパイプラインを信頼してください。

<Aside type="tip">
期間が横に並ぶ従来のレイアウトにしたい場合は、`intacct_pnl`を読み取る[Table Pivot ステップ](/ja/reference/workflow-steps/tables/table-pivot/)を追加します。期間を列にピボットし、`pnl_line`を行のままにして、`amount`を合計します。そもそも期間の列を用意するには、ステップ3で`end_date`を**グループ化**列として追加します。これで、SQLなしで月次推移をひと目で確認できます。
</Aside>

## ステップ5: ダッシュボードに配置する

表の数値でも問題ありませんが、CFOに送るならグラフです。`intacct_pnl`を[公開](/ja/get-started/tutorials/load-and-transform-data/#ステップ7結果を公開する)してから、[ダッシュボードを作成する](/ja/get-started/tutorials/build-a-dashboard/)に従って、次を追加します。

- `departmentname`ごとの純利益（または収益）の**棒グラフ**
- 各`pnl_line`の**棒グラフ**。収益、売上原価、営業費用の構成がひと目で分かります。

これで、エクスポート不要のライブなSage Intacct財務ダッシュボードが完成しました。ワークフローを実行するたびに更新されます。

## ステップ6: 更新をスケジュールする

<Steps>

1. ワークフロー全体を上から下まで1回実行し、すべてのステップが成功することを確認します。
2. [ワークフローをスケジュールします](/ja/get-started/tutorials/schedule-a-workflow/)。決算のタイミングに合わせて月次にするか、月中も数値を最新にしたい場合は週次にします。

</Steps>

取得はテーブル全体の置き換えなので、実行のたびに、設定した日付と勘定科目の範囲の残高が再度読み取られます。全期間ではなく、必要な範囲（当期、損益計算書の勘定科目）に絞ってください。

## ステップ7: 統計勘定で1人当たりのメトリックを追加する

Intacctは、財務の勘定科目表とあわせて、人数、面積、数量などの金額以外の**統計勘定**も管理しています。2つ目の**Sageのインポート**ステップを統計モードで設定して取得し、損益計算書に結合すると、部門別の従業員1人当たり営業費用のようなメトリックを確認できます。標準ステップをさらに3つ使うだけで、SQLは引き続き不要です。

<Steps>

1. 2つ目の**Sageのインポート**ステップを追加します。設定で、次を指定します。

   | フィールド | 値 |
   |---|---|
   | **接続** | Sage Intacct接続 |
   | **会社** | 読み取るIntacctの会社 |
   | **開始日** / **終了日** | ステップ2と同じ期間 |
   | **統計** | **統計のみ** |
   | **Start account** / **End account** | `0000`〜`9999`。統計勘定が財務の勘定科目表の番号体系に収まるとは限らないため、ステップ2の損益計算書の範囲ではなく、全範囲を取得します |
   | **エンティティ** | 運用上のエンティティ（例: `201`、`301`） |
   | **ディメンション** | **部門**。1人当たりのレポートに使用するディメンションです |

2. **ターゲット**を、`intacct_statistics`という名前の新しいテーブルに設定します。

3. ステップを実行します。統計勘定と部門の組み合わせごとに1行が得られ、`endbalance`にその統計値自体（例: 期末時点のその部門の人数）が入ります。

</Steps>

次に、人数を損益計算書に取り込んで割り算をしますが、`intacct_statistics`から直接ではありません。このテーブルには*統計勘定と部門の組み合わせごとに1行*（人数、面積、数量など、管理しているすべて）があるため、`departmentname`だけで結合すると、その部門の統計勘定の数だけ損益計算書の各行が増えてしまい、`amount_per_head`はたまたまその行に入った統計勘定で割られることになります。先に人数に絞り込み、結合が部門ごとに1行になるようにして、比率が意味を持つようにします。

<Steps>

1. **Table Extract**ステップを追加します。**ソース**に`intacct_statistics`を、**ターゲット**に新しいテーブル`intacct_headcount`を設定します。**列**では、すべての列をそのまま反映します。ここでは集計は不要です。**フィルター**タブで、ソースデータに対する**データのサブセットを選択**フィルターを追加します: `intacct_statistics.glaccountno == '9000'` — `9000`は、ご自身の人数の統計勘定番号に置き換えてください（取得結果が勘定科目名の列を返す場合は、代わりにその列でフィルターします。`glaccountno`は引き続きテキストなので、引用符付きの文字列と比較してください）。ステップを実行します。`intacct_headcount`には、部門ごとにちょうど1行が入ります。

2. [Table Outer Join ステップ](/ja/reference/workflow-steps/tables/table-outer-join/)を追加します。**Table 1**に`intacct_pnl`を、**Table 2**に`intacct_headcount`を設定し、`departmentname`で結合します。これで部門ごとに1対1の対応になります。**結合タイプ**はデフォルトの**左結合**のままにします。すべての損益計算書の行が保持され、部門が一致する場合は人数が補われます。ターゲットを新しいテーブル`intacct_pnl_with_headcount`にし、両方のテーブルのすべての列を反映します。

3. ステップを実行し、`intacct_pnl_with_headcount`を読み取って新しいテーブル`intacct_pnl_per_head`に出力する**Table Extract**ステップを追加します。**列**で既存の列を反映してから、ターゲット列をもう1つ追加します。`amount_per_head`は**式** `intacct_pnl_with_headcount.amount / func.to_float64(intacct_pnl_with_headcount.endbalance)` で、タイプは**通貨**です。

4. ステップを実行します。

</Steps>

**`3 - Operating Expenses`** の行の`amount_per_head`を見ると、部門別の従業員1人当たり営業費用が分かります。ステップ4と同じ読み方で、列が1つ増えるだけです。損益計算書と一緒にダッシュボードに追加するか、ステップ6のスケジュールに組み込んで、ほかのすべてと一緒に更新されるようにします。

## 作成したもの

空のワークフローから始めて、Sage Intacctの勘定残高をライブで取得し、1つの標準変換ステップで**部門別の損益計算書**に整形し、統計勘定を結合して1人当たりのメトリックを追加しました。パイプライン全体でSQLは一切使っていません。さらにダッシュボードに配置し、更新するよう設定しました。財務チームが実行する中核のレポーティングの流れが、自動化されました。
