このチュートリアルでは、PlaidCloud でコスト配賦を最初から最後まで作成します。完了すると、ドライバーデータを使用してコストプールをターゲットのディメンションに配分する、動作するモデルができます。これは、活動基準原価計算、IT チャージバック、共有サービスの配分の基礎となるものです。

所要時間は約 1 時間です。配賦は PlaidCloud の最大の特長であり、このモデルを理解するには、このチュートリアルが最適です。

## 作成するもの

IT 部門の総コストを、各ユニットのユーザー数で重み付けして、事業部門に配分します。

```text
IT cost table  →  ┐
                  ├→  Allocation step  →  results table
User counts    →  ┤      (driver-based)
                  ┘
                  ↑
        Business unit dimension
```

## 前提条件

- PlaidCloud ワークスペース（お持ちでない場合は[無料トライアルを開始](https://app.plaidcloud.com)してください）
- 次のものを含む、またはインポートできるプロジェクト:
  - **配賦する値** — 月ごとの IT コスト（合計またはサブカテゴリ別）
  - **ドライバーデータ** — 事業部門ごとのユーザー数
  - **ディメンション** — 事業部門の階層（ユニット → 部門 → 会社）
- [コンセプト](/ja/get-started/concepts/)の理解 — ワークスペース、プロジェクト、ワークフロー、ディメンション、配賦

<Aside>
ソースデータがまだない場合は、小さな CSV ファイルを用意し、[データの読み込み、変換、公開](/ja/get-started/tutorials/load-and-transform-data/)の手順でインポートしてから始めることができます。
</Aside>

## ステップ 1: 入力を設定する

プロジェクトに次の 3 つがあることを確認します。

| オブジェクト | 保持する内容 |
|---|---|
| `it_cost` テーブル | IT コストの合計（例: 月ごとに 1 行で金額を保持） |
| `users_by_bu` テーブル | 事業部門ごとに 1 行で、`user_count` 列を持つ |
| `business_units` ディメンション | 事業部門の階層。リーフノードは `users_by_bu` のユニット名と一致する |

不足しているものがある場合は、続行する前にワークフローで読み込んでください。

## ステップ 2: 配賦ワークフローを作成する

<Steps>

1. プロジェクトを開き、**ワークフロー**タブに切り替えます。
2. **新規ワークフロー**をクリックします。名前を「IT Cost Allocation」にします。
3. 新しいワークフローを Workflow Explorer で開きます。

</Steps>

## ステップ 3: 配賦ステップを追加する

<Steps>

1. **Allocation** カテゴリから新しいステップを追加します。最も柔軟なオプションである **Allocation Rules** を選択します。
2. ソースを構成します。
   - **ソーステーブル**: `it_cost`
   - **ソース金額列**: 金額が入っている列
3. ドライバーを構成します。
   - **ドライバーテーブル**: `users_by_bu`
   - **ドライバー値の列**: `user_count`
   - **ドライバー照合列**: 事業部門名が入っている列
4. ターゲットを構成します。
   - **ターゲットディメンション**: `business_units`
   - **ターゲットレベル**: 配賦先とする階層のレベルを選択します（通常はリーフレベル）
5. 出力を構成します。
   - **結果テーブル**: `it_cost_allocated`

</Steps>

## ステップ 4: 実行して確認する

<Steps>

1. ステップを実行します。
2. **テーブル**タブを開き、`it_cost_allocated` を開きます。
3. 各行は、1 つの事業部門に配分されるコストの 1 区分を表します。列は次のとおりです。
   - ソースの金額（例: 月の IT コスト合計）
   - ターゲットの事業部門
   - 使用されたドライバー値（そのユニットのユーザー数）
   - 配賦率（ユーザー数 ÷ 全ユニットのユーザー数合計）
   - 配賦金額（ソース × 配賦率）

</Steps>

## ステップ 5: 数値を検証する

すべての配賦が通過すべき 3 つのチェックがあります。

1. **合計の照合** — 配賦金額の合計がソースの合計と等しいこと（丸め誤差の許容範囲内）
2. **配賦率の合計** — ソースの行ごとに配賦率の合計が 1.0（= 100%）になること
3. **カバレッジ** — 配分を受けるべきディメンション内のすべての事業部門が、実際に配分を受けていること

検証の完全なチェックリストは、[配賦結果](/ja/guides/allocations/results/allocation-results/)ガイドを参照してください。

数値が合わない場合、最もよくある原因は次のとおりです。
- **ドライバーデータの欠落** — ディメンション内の事業部門に対応する行が `users_by_bu` にない場合、その部門は配賦を受けません
- **名前の不一致** — ドライバーテーブルでは「Sales East」でも、ディメンションでは「Sales-East」の場合（スペースや大文字小文字の違いは一致しません）
- **ゼロまたは負のドライバー** — ゼロや想定外の配賦になります

## ステップ 6: 結果を活用する

結果テーブルは、他の PlaidCloud のテーブルと同じように扱えます。たとえば、次のことができます。

- 以降のワークフローのステップで他のテーブルと**結合**する（例: GL に全部原価の列を追加する）
- ダッシュボードや外部の利用者向けに**公開**する
- 次の配賦ラウンドのソースとして**再配賦**する（段階的なモデルの場合）

## 試してみたいバリエーション

基本モデルが動作したら、次のような拡張をよく行います。

- **複数のコストプール** — 1 行の `it_cost` を、IT のサブカテゴリ（コンピューティング、ストレージ、ライセンス）ごとの行に置き換え、それぞれ異なるドライバーで個別に配賦します
- **複数期間** — ソースを月ごとに分割し、期間ごとに 1 つの配賦結果を生成します
- **多層の配賦** — 部門の間接費をユニットに、ユニットのコストを製品に、製品のコストを顧客に配賦します。各層がそれぞれ独立した配賦ステップになります
- **再帰的な配賦** — 共有サービスが相互に利用し合う場合（IT が HR にサービスを提供し、HR が IT にサービスを提供する）。[再帰的な配賦](/ja/guides/allocations/setup/recursive-allocations/)を参照してください
- **ルールベースの割り当て** — 配分が複数のドライバーに依存し、ソースによって異なる場合は、単一のドライバーテーブルを接続する代わりに、ガイド付きビルダーで配賦ディメンションを作成します。[配賦ディメンションの作成](/ja/guides/dimensions/dimensions/#配賦ディメンションの作成)を参照してください
