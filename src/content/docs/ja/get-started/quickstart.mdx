## 作成するもの

次の処理を行う小さなワークフローです。

1. CSV をプロジェクトのテーブルにインポートする
2. いくつかのステップでデータをフィルターおよび変換する
3. 結果を公開して、他のツールから利用できるようにする

<Aside>
これはあえて軽量にしてあり、各要素を一通り見て回るためのものです。詳しい解説ではありません。完了したら、[コンセプト](/ja/get-started/concepts/)のページで、なぜこのように構成されているのかを確認でき、[ガイド](/ja/guides/)のセクションで各タスクを詳しく説明しています。
</Aside>

## サンプルプロジェクトから始める

完成した結果を先に見てから自分で作りたい場合は、近道があります。新しいワークスペースには、**サンプルを読み込む**ボタンが表示されます。ワークスペースで複数のガイド付きサンプルが提供されている場合は、まず短い一覧から読み込むサンプルを選択します。

- **Retail Sales Analysis** — 小売と販売
- **Campaign Performance by Channel** — マーケティング
- **Inventory Status Report** — サプライチェーンとオペレーション
- **Budget vs Actual by Department** — 財務

どのサンプルも、PlaidCloud のローコード変換ステップだけで作られた、現実的な小規模データセットです。SQL を手書きしていないので、後から完成したワークフローを開いて、仕組みをそのまま確認できます。1つ選択すると（サンプルが1つしかない場合は PlaidCloud が直接読み込みます）、PlaidCloud がプロジェクトを作成してワークフローを実行し、各段階を順に表示します。ファイルの**インポート**、**クリーニング**、いくつかの並列サマリーへの分岐、そしてそれらを1つの最終結果テーブルに結合する流れです。その後、結果を開いて表示します。実行が終わると、PlaidCloud は結果テーブルをレポート用に公開し、そこからダッシュボードも自動的に作成します。内容は、KPI サマリー、時系列の推移、サンプルの主要カテゴリー別の内訳、そして小売と在庫のサンプルでは米国の州別の内訳です。最初の実行はウェアハウスの準備のために約1分かかりますが、2回目以降はほぼ一瞬で終わります。画面にもその旨が表示されるので、待ち時間に驚くことはありません。何も構築せずに、数分で最初の本物の結果と完成したダッシュボードにたどり着けます。作成されたものはすべてご自身のもので、開いて、変更して、再実行できます。サンプルの読み込みや実行で問題が発生した場合は、PlaidCloud がお知らせし、再試行を提案します。

サンプルプロジェクト、そのワークフロー、作成される各ダッシュボードは、作成された瞬間にワークスペース全体と共有されます。閲覧者のアクセス権を持つチームメンバーにも、あなたと同じ完成したサンプルが表示され、別途共有する手順は必要ありません。

空の画面でも、何もないグリッドのまま放置されることはなく、次のステップへ案内されます。**プロジェクト**、**ワークフロー**、**テーブル**、**接続**、**ダッシュボード**の各画面には、短い説明と主要なアクション（**新規プロジェクト**、**新規ワークフロー**、**テーブルバンドルのインポート**など）が表示されるため、進むべき方向が常にわかります。これらの画面とウェルカムパネルにある**お困りですか?** リンクから、行き詰まったときにサポートへすぐにアクセスできます。ワークスペースに閲覧者として追加された場合、これらの画面では、実行できない操作を提示せずに、表示内容を説明します。また、閲覧者が表示可能なコンテンツがまだないワークスペースに入った場合は、簡単な使い方の紹介、アプリのガイドツアー、ヘルプへのクイックアクセスを含むウェルカムが表示されるため、次の一歩が必ず用意されています。

このガイド付きの初回体験は、すべてのプランで、新しいワークスペースごとに表示されます。すでに操作に慣れている場合は、ウェルカムパネルで**閉じる**を選択してください。ガイダンスが引き続き利用可能であることを知らせる簡単な確認が表示され、パネルは非表示になります。いつでも再表示するには、右上のユーザーメニューを開き、**オンボーディングを再開**を選択します。

## 自分の CSV から始める

サンプルではなく自分のデータから始めるには、**独自のデータを取り込む**を選択します。空の**プロジェクト**画面では**サンプルを読み込む**の横に表示され、ホームにも表示されます。表示されるには、プロジェクトとテーブルを作成する権限と、ドキュメントストレージに書き込む権限が必要です。すでにプロジェクトがある場合は、**プロジェクト**画面で**新規** > **CSVファイルからプロジェクト**を選択すると、同じウィンドウが開きます。既存のプロジェクトに CSV を追加するには、[CSVファイルをインポート](/ja/guides/projects/managing-tables-and-views/#csvファイルをインポート)を参照してください。

CSV ファイルをボックスにドロップするか、**CSVファイルを選択**を選択してファイルを選びます。受け付けるのは `.csv` で終わるファイルのみです。PlaidCloud は、ファイルを**個人用の一時ドライブ**にアップロードします。個人用の一時ドライブがない場合は、ワークスペースの**一時ドライブ**にアップロードします。次に、ファイル名にちなんだ名前のプロジェクトを作成し、同じくファイル名にちなんだ名前のテーブルにインポートして（`Sales Data.csv` はプロジェクト **Sales Data** とテーブル `sales_data` になります）、新しいプロジェクトの**テーブル**一覧を開きます。続いて**次の推奨ステップ**パネルが開き、PlaidCloud がテーブルを最初に確認し終えると、**データの概要**に切り替わります。ここには、テーブルの行数に加えて、最初の6列について、各列のタイプ、空の値の割合、異なる値の数が表示されます。

その下には、スターター用の棒グラフがあります。棒は、地域のように繰り返される値が少数の列の値を表し、各棒はその値について数値列を合計または平均するか、行数を数えたものです。描画するのに適したグラフが複数ある場合は、PlaidCloud の AI が1つを選んでタイトルを付けます。AI が参照するのは列名、タイプ、件数のみで、ファイル内の値は一切参照しません。繰り返される値が少数の列がない場合、パネルにはスターターグラフがない旨が表示されます。

レポート機能が有効で、テーブルを公開する権限がある場合、PlaidCloud はテーブルをレポート用に公開し、グラフからスターターダッシュボードを作成します。**ダッシュボードを開く**を選択すると、新しいタブで開きます。ダッシュボードのチャートには「地域別の総売上」のように、表示する列にちなんだ名前が付けられます。AI が付けたタイトルが表示されるのは、パネル上のグラフだけです。新しいダッシュボードはすべてそうであるように、最初はプロジェクト内の全員に表示されます。変更するには、[ダッシュボードを閲覧できるユーザーを制御する](/ja/guides/dashboards/control-who-can-see-a-dashboard/)を参照してください。

また、パネルには**このデータをクリーンアップ**と**このデータを集計**も表示されます。それぞれ、確認できる状態のステップを開きます。スキップするには**今はしない**を選択します。

インポートに失敗した場合、PlaidCloud は作成したばかりのプロジェクトを削除し、何が問題だったかをお知らせします。アップロードされたファイルは、インポートが成功したかどうかにかかわらず、完了後に PlaidCloud が一時ドライブから削除します。それができなかった場合は、一時ドライブが1日後に削除します。ワークスペースに一時ドライブがない場合、ウィンドウにファイルの保存先がない旨が表示されるため、ワークスペース管理者がサポートに連絡する必要があります。

## ホームで進捗を確認する

ワークスペースに入ると、ホームには**はじめに**カードが1枚表示され、セットアップの進捗をステップごとに追跡します。進捗メーター（「M 件中 N 件」）も組み込まれています。表示内容はロールによって異なります。管理者には5つのステップがあります。サンプルを試す、データを接続する、最初のワークフローを構築する、ダッシュボードを公開する、チームを招待する、の5つです。ビルダーには3つのステップがあります。サンプルを試す、最初のワークフローを構築する、ダッシュボードを公開する、の3つです。閲覧者にはカードは表示されません。

カードは、まだ完了していないものを常に主要なアクションとして先頭に表示し、残りのステップは、それぞれクリックするとその場所へ直接移動できる行になります。完了したステップにはチェックが付き、そのまま戻ることはありません。完了したステップは折りたたまれるため、カードは残りの作業に集中した状態を保ちます。

<Aside>
「ダッシュボードを公開する」は、自分で公開したダッシュボードだけがカウントされます。チームメンバーが公開しても、あなたのチェックは付きません。
</Aside>

カードを表示したくない場合は、**非表示**を選択すると、ツールバーの小さな「はじめに · N/M」ボタンに折りたたまれます。そのボタンをクリックすれば、いつでもカード全体を再表示できます。ユーザーメニューの**オンボーディングを再開**からも再表示できます。オンボーディングを完全にオフにするには、代わりに**オンボーディングを閉じる**を使用します。**オンボーディングを再開**を選択するまで、オフのままです。

すべてのステップを完了すると、カードは自動的に役目を終えます。ホームから消え、「準備完了です」というお祝いのメッセージが1回だけ表示されます。使用したデバイスやブラウザの数にかかわらず、ワークスペースごとに1回です。

進捗状況、カードの表示または非表示の状態、ツアー、ヒント、ホームで閉じたものはすべて、ブラウザではなくアカウントに紐付けられます。新しいデバイス、別のブラウザ、シークレットウィンドウからサインインしても、最初からやり直すことなく、前回の続きから再開できます。

このクイックスタートの残りの部分では、同様のワークフローを手作業で構築し、各要素を確認します。

## 1. プロジェクトを開く

サインインすると、ワークスペースが表示されます。**プロジェクト**タブを開き、新しいプロジェクトを作成します。「Quickstart」のようなわかりやすい名前を付けてください。プロジェクトは、データ、ワークフロー、ディメンションをまとめて管理する場所です。

プロジェクトのライフサイクルの詳細は、[プロジェクトの管理](/ja/guides/projects/managing-projects/)を参照してください。

## 2. CSV をインポートする

プロジェクト内で**ワークフロー**タブを開き、新しいワークフローを作成します。**Import → CSV**ステップを追加します。ローカルマシンから小さな CSV をアップロードするか、接続済みのドキュメントストア内の CSV を指定します。

そのステップを実行します。CSV はプロジェクトにテーブルとして格納されます。**テーブル**タブを開いて確認してください。

リファレンス：[CSVのインポートステップ](/ja/reference/workflow-steps/import/import-csv/) · ガイド：[ワークフローはどこにありますか?](/ja/guides/workflows/where-are-workflows/)

## 3. 変換ステップを追加する

ワークフローに戻り、**Tables → Table Lookup**ステップ（またはその他のテーブルステップ）を追加します。ソースとターゲットを設定し、保持する列を選択して、簡単なフィルターを適用します。

ステップを実行すると、プレビューできる新しいテーブルが出力されます。

リファレンス：[ワークフローステップ](/ja/reference/workflow-steps/)

## 4. 結果を公開する

最後に**公開**ステップ（**Data → Publish** の下）を追加して、テーブルをダッシュボード、BI ツール、外部の利用者が使えるようにします。

ガイド：[データの公開](/ja/guides/data/publish/)

## 5. ワークフロー全体を実行する

ワークフローで**実行**をクリックします。各ステップの実行に合わせてログを確認します。エラーが発生した場合は、[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)ガイドにデバッグの方法が記載されています。
