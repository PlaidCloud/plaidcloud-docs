## 説明

**Lakehouse** エリアでは、PlaidCloud を離れることなく、ワークスペースの Lakehouse コンピュートと Iceberg カタログをポイントアンドクリックで管理できます。メインツールバーの **Lakehouse** ボタンから開きます。

ウィンドウ上部のウェアハウスセレクターは、すべてのタブに適用されます。このエリアは、**クエリ**、**プロファイル**、**カタログ**、**ウェアハウス**、**ユーザー**、**ロード**、**管理者**の7つのタブに分かれています。


## クエリ

実行中のクエリを監視し、履歴を参照します。このタブは、移動可能な分割バーで上下に分かれています。

* **実行中** — 現在実行されているクエリです。ツールバーで選択した間隔で自動的にポーリングします。
* **履歴** — 最近完了したクエリです。

**クエリのプランを表示するには:**

1. 行の先頭にある `Profile` アイコンをクリックします
2. クエリの SQL が**プロファイル**タブに読み込まれます。そこから EXPLAIN または EXPLAIN ANALYZE を実行できます

**実行中のクエリを強制終了するには:**

1. **実行中**テーブルで1つ以上の行を選択します
2. ツールバーの `Kill selected` をクリックします
3. ダイアログで確認します


## プロファイル

SQL ステートメントに対して `EXPLAIN` または `EXPLAIN ANALYZE` を実行し、得られたプランをヒートマップ付きのツリーとして可視化します。

1. **Lakehouse > プロファイル**を開きます
2. SQL ステートメントを貼り付けるか入力します
3. `EXPLAIN`（プランのみ）または `EXPLAIN ANALYZE`（プランに加えて実際の行数と所要時間）をクリックします

プランツリーでは、最もコストの高いノードが強調表示されるため、低速なクエリのボトルネックを一目で把握できます。


## カタログ

選択したウェアハウスの Iceberg カタログを参照します。ペインの左側に名前空間、右側にテーブルが一覧表示され、作成および削除の操作用のアクションバーがあります。

**名前空間を作成するには:**

1. **Lakehouse > カタログ**を開きます
2. `New namespace` をクリックします
3. 名前空間の名前を入力して確認します

**テーブルを削除するには:**

1. 名前空間を選択し、続いてテーブルを選択します
2. `Drop table` をクリックします
3. ダイアログで確認します

タブの下部にある削除済みテーブルの一覧では、復旧可能な間は、最近削除したテーブルを `UNDROP` で元に戻せます。

<Aside>選択したウェアハウスがワークスペースのデフォルトの場合、破壊的な操作（名前空間の削除、テーブルの削除）は無効になります。</Aside>


## ウェアハウス

Lakehouse を支える Iceberg ウェアハウスを作成、一覧表示、削除します。

**ウェアハウスを作成するには:**

1. **Lakehouse > ウェアハウス**を開きます
2. `Add warehouse` をクリックします
3. ウェアハウス名とストレージ設定を入力します
4. `Add` をクリックします

**ウェアハウスを削除するには:**

1. ウェアハウスの行を選択します
2. `Delete` をクリックします
3. ダイアログで確認します

<Aside>デフォルトのウェアハウスは保護されており、削除できません。</Aside>

<Aside title="アイドル状態のウェアハウスは自動的にスケールダウンします">ウェアハウスのクエリ実行容量は、しばらくアイドル状態が続くと最小限の水準までスケールダウンし、クエリが戻ってくると自動的に再びスケールアウトします。そのため、使用していないアイドル状態の容量は、24時間課金され続けることなく解放されます。注意点は1つだけで、しばらくアイドル状態だったウェアハウスに対する最初のクエリは、容量が復帰するまで少し時間がかかる場合があります。安定して、または頻繁に使用されているウェアハウスには影響せず、その間もウェアハウスには常に接続できます。ウェアハウスがオフラインになることはありません。</Aside>


## ユーザー

外部の SQL クライアント（DBeaver など）から Lakehouse に接続するデータベースユーザーを管理します。パスワードベースのユーザーと SSO でプロビジョニングされたユーザーの両方が一覧表示されます。

**ユーザーを追加するには:**

1. **Lakehouse > ユーザー**を開きます
2. `Add user` をクリックします
3. ユーザー名とパスワードを入力します
4. `Add` をクリックします
5. パスワードを保存します。パスワードは一度だけ表示され、後から取得することはできません

**パスワードをリセットするには:**

1. ユーザーの行を選択します
2. `Reset password` をクリックします
3. ダイアログに表示された新しいパスワードを保存します

**ユーザーを削除するには:**

1. ユーザーの行を選択します
2. `Drop user` をクリックします
3. ダイアログで確認します


## ロード

クラスターのアクティビティを一目で確認できます。このタブには、カウンター（アクティブなクエリ、最近のスループット）の行が表示され、その下に、**クエリ**タブと同じポーリング間隔でサンプリングされたスパークラインが表示されます。


## 管理者

コンピュートのワークロードの状態を確認し、必要に応じてウェアハウスのコンピュートを再起動します。

ワークロードテーブルには、各コンポーネントとその現在の状態が一覧表示されます。**ローリング再起動**セクションでは、選択したウェアハウスのコンピュートポッドを順番に再起動できます。

**コンピュートを再起動するには:**

1. **Lakehouse > 管理者**を開きます
2. 中断に関する警告を読みます
3. 確認欄にウェアハウス ID を入力します
4. `Restart compute` をクリックします

再起動の間にはクールダウンが設けられており、誤って短時間に繰り返し再起動することを防ぎます。残りのクールダウン時間はボタンの横に表示されます。

<Aside>ローリング再起動を行うと、アクティブなセッションが一時的に中断されます。確認する前にユーザーと調整してください。</Aside>

<Aside title="アイドル時のスケールダウンと実行中のクエリ">自動のアイドル時スケールダウン（上記の**ウェアハウス**を参照）は、クエリのアクティビティがない状態が一定期間続いた後にのみ動作するため、実行中のクエリが中断されることはありません。特定のワークスペースのウェアハウスを常にフル容量で維持したい場合は、PlaidCloud サポートに連絡して、そのワークスペースでこの機能を無効にしてもらってください。</Aside>
