**ODBC（Open Database Connectivity）** は、[PlaidLinkエージェント](/ja/reference/cli/plaidlink/)が動作しているマシンのODBC設定を通じて、データベースに接続します。PlaidCloudに専用のコネクタがないデータベースに対して、[Agent Remote Export of SQL Result](/ja/reference/workflow-steps/agent/agent-remote-export-of-sql-result/)ステップなどのエージェントステップから使用します。作成するには、接続タイプとして**ODBC**を選択します。

:::note
ODBC接続には、エージェントでPlaidLink 1.2.31以降が必要です。[Upgrade](/ja/reference/cli/plaidlink/upgrade/)を参照してください。
:::

ODBC接続は、次の2つの方法のいずれかで動作します。

- **DSN経由。** **ODBCドライバー**を空白にして、エージェントのマシンに設定したデータソース（DSN）を指定します。DSNにはドライバー、サーバー、データベース、その他のドライバー設定が含まれ、**接続属性**でそれらを上書きできます。この方法は、あらゆるODBCドライバーで使用できます。
- **ドライバー経由。** エージェントのマシンにインストールされている**ODBCドライバー**を選択または入力してから、サーバーとデータベースを指定します。PlaidCloudは、ドライバーに`Server`設定と`Database`設定を渡し、続けて**接続属性**を渡します。この方法は、MicrosoftのSQL Serverドライバーで使用できます。リストに候補として表示される他のドライバーを含め、それ以外のドライバーではDSNを使用してください。

## 上流のドキュメント
各データベースのODBCドライバーには、それぞれ固有の設定があります。DSNを作成するときも接続属性を記述するときも、ドライバーが受け付けるキーワードについては、ドライバーベンダーのドキュメントを参照してください。

## エージェントのマシンでDSNを作成する

エージェントがどのアカウントで実行されていてもDSNを見つけられるように、エージェントが動作しているマシンで、システムDSNとしてDSNを設定します。

### Windowsの場合

1. **ODBC Data Sources (64-bit)** を開きます。
2. **System DSN**タブで、データベースのODBCドライバーを使用するデータソースを追加し、サーバー、データベース、およびドライバーが要求するその他の設定を入力します。
3. **データソース名**を控えておきます。接続に入力します。

:::caution
DSNは、64ビットの**System DSN**である必要があります。Windowsではエージェントがサービスとして動作するため、ユーザーDSNや32ビットのODBC管理ツールで作成したDSNは参照できません。その場合、ステップは`ODBC data source '<name>' is not defined on the agent machine`というエラーで失敗します。
:::

### Linuxの場合

Linuxでは、エージェントはunixODBC経由でODBCに接続します。

1. unixODBCと、データベースのODBCドライバーをインストールします。
2. ドライバーが`odbcinst.ini`に、角かっこで囲まれた名前で登録されていることを確認します。ほとんどのドライバーパッケージは、インストール時に自動的に登録されます。`odbcinst -q -d`で登録済みのドライバーを一覧表示できます。
3. システムの`odbc.ini`に、DSNの名前を付けたセクションとしてデータソースを追加します。`Driver`には登録済みのドライバー名を設定し、サーバー、データベース、およびドライバーが要求するその他の設定を追加します。

   ```ini
   [Sales]
   Driver=ODBC Driver 18 for SQL Server
   Server=sales-db.example.com
   Database=Sales
   ```

4. セクション名（ここでは`Sales`）を控えておきます。接続に入力します。

`odbcinst -j`を実行すると、システムの`odbcinst.ini`と`odbc.ini`の場所が表示されます。通常は`/etc`です。ユーザー自身の`~/.odbc.ini`にあるDSNは、エージェントがそのユーザーとして動作している場合にのみ見つかります。

### コンテナーの場合

PlaidLinkのコンテナーイメージにはunixODBCが含まれていますが、ODBCドライバーは含まれていません。DockerまたはKubernetesで動作するエージェントからODBCを使用するには、このイメージをベースにドライバーをインストールしたイメージをビルドし、DSNを記述したシステムの`odbc.ini`をイメージに追加するか、コンテナーにマウントします。イメージは`plaid`ユーザーとして動作するため、ドライバーのインストール時は`root`に切り替え、完了後に`plaid`に戻します。

## 構成

### データベース接続

| フィールド | 必須 | 説明 |
|---|---|---|
| ODBCドライバー | いいえ | DSN経由で接続する場合は空白にします。それ以外の場合は、エージェントのマシンにインストールされているODBCドライバーの名前を、そのマシンに登録されているとおりに指定します。Windowsでは**ODBC Data Sources (64-bit)** の**Drivers**タブに表示される名前、Linuxでは`odbcinst.ini`のセクション名です。リストには一般的なドライバーが表示され、それ以外のドライバーは入力できます。ここで動作するのは、MicrosoftのSQL Serverドライバーのみです。リストに表示される他のドライバーを含め、それ以外のドライバーでは、空白のままDSNを使用してください。ドライバー名に波かっこやセミコロンを含めることはできません。 |
| データソース名（DSN）またはサーバー | はい | ドライバーを指定しない場合は、エージェントのマシンにあるシステムDSNの名前。ドライバーを指定する場合は、データベースサーバーのホスト名。デフォルト以外のポートを使うSQL Serverの場合は`host,port`。 |
| データベース | ドライバー指定時 | 開くデータベース。DSNが独自のデータベースを指定するため、ドライバーを指定しない場合は使用できず、ドライバーなしでデータベースを指定すると保存が拒否されます。 |
| 接続属性 | いいえ | ドライバーに渡すその他の設定。`;`で区切った`KEY=value`形式のペアで指定します。[接続属性](#接続属性)を参照してください。 |

接続にポートフィールドはありません。デフォルト以外のポートを使うSQL Serverの場合は、MicrosoftのSQL Serverドライバーにポートのキーワードがないため、サーバーに`host,port`の形式でポートを追加します。DSNを使う場合は、DSNでポートを設定するか、ポートを受け付けるドライバーであれば`PORT=5433`のような属性で上書きします。

### 接続属性

**接続属性**は、どちらのモードでも、ODBCの記法のままODBC設定をドライバーに渡します。

- ドライバーを指定する場合、接続自身の設定の後ろに追加されます。読み取り専用レプリカに接続するための`ApplicationIntent=ReadOnly`など、ドライバーが必要とするその他の設定に使用します。
- DSNを使う場合、DSN自身の設定を上書きします。たとえば`PORT=5433`や、IBM iのデフォルトライブラリを指定する`DBQ=MYLIB`です。

ペアは`Encrypt=yes;ApplicationIntent=ReadOnly`のように`;`で区切ります。`;`を含む値は`KEY={first;second}`のように波かっこで囲み、波かっこの内側では`}`を`}}`と書きます。キーワードは大文字でドライバーに渡されます。ODBCのキーワードは大文字と小文字を区別しません。

次の場合、保存が拒否されます。

- `KEY=value`形式のペアではないテキスト（閉じられていない波かっこや、値のないキーワードを含む）。
- 大文字と小文字を問わず、同じキーワードが複数回指定されている場合。
- 接続が自身のフィールドから設定するキーワード：`DRIVER`、`DSN`、`SERVER`、`DATABASE`、`UID`、`PWD`、`USER`、`USERID`、`USERNAME`、`PASSWORD`。
- `FILEDSN`と`SAVEFILE`。エージェントがマシン上のファイルから接続設定を読み取ったり、ファイルに書き込んだりすることになるためです。

ドライバーが独自の資格情報キーワードを受け付ける可能性があるため、接続の一覧では属性がマスクされます。接続自身のフォームには表示されます。属性を削除するには、フィールドを空にします。ユーザーとパスワードは**認証情報**に入力します。

:::note
**ODBC Driver 18 for SQL Server**は、デフォルトで接続を暗号化し、サーバーの証明書を検証します。自己署名証明書を使用しているサーバーの場合は、属性に`TrustServerCertificate=yes`を追加してください。
:::

### 認証情報

| フィールド | 説明 |
|---|---|
| ユーザー | 接続に使用するユーザー。DSN経由の場合、空白にするとDSNの設定どおりにサインインします。SQL Serverの場合は、属性に`TRUSTED_CONNECTION=Yes`を追加すると、エージェント自身のアカウントでサインインします。SQL Serverドライバーでユーザーを指定しない場合、接続はエージェント自身のアカウント（Windowsアカウント、またはLinuxではKerberosチケット）でサインインします。 |
| シングルサインオン認証を使用（パスワードなし、ユーザーは任意） | 保存済みのパスワードなしで接続します。 |
| パスワード | ユーザーのパスワード（書き込み専用）。編集時に空白のままにすると、保存済みのパスワードが維持されます。 |

### SSL構成とSSH構成

これらのタブは、ODBC接続には適用されません。暗号化やその他のドライバーオプションは、DSNまたは接続属性で設定してください。

## 以前のバージョンで保存された接続

以前のバージョンのこのフォームでは、**データベース**と固定リストから選択したドライバーが必須で、**ポート**も自動的に入力されていましたが、ドライバーは渡されなかったため、それらの接続は接続できませんでした。接続を開いて、次のいずれかを行います。

- **DSN経由で接続する：** **ODBCドライバー**をクリアし、DSNを入力して保存します。保存すると、以前のデータベースがクリアされます。
- **SQL Serverドライバー経由で接続する：** **ODBCドライバー**が、エージェントのマシンにインストールされているSQL Serverドライバーと一致していることを確認します。以前のリストにあった名前の多くは、ドライバーが登録する名前ではありませんでした。

以前のリストのドライバーが残っている接続は、ドライバー接続として開きます。ドライバーが、エージェントのマシンにインストールされているSQL Serverドライバーになるまで、接続は失敗します。それ以外のデータベースには、DSNで接続してください。

保存すると、以前のポートもクリアされます。DSNのみでデータベースがなかった接続は、**ODBCドライバー**が空白の状態で開きます。
