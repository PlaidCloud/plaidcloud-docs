PlaidCloudをOracle **FCCS**（Oracle EPM Cloudの一部であるFinancial Consolidation and Close）に接続すると、財務担当ユーザーがHFMチームにチケットを起票することなく、データスライスをセルフサービスで取得できます。[HFM/FCCS: データの読み取り（アドホック）](/ja/reference/workflow-steps/oracle-epm/hfm-fccs-read/)ステップはライブクエリのように動作しますが、内部ではFCCSのデータエクスポートジョブAPIに対する非同期のリクエスト → ポーリング → 取得として処理されます。

この接続の種類は、接続ピッカーに**REST - HFM/FCCS**として表示されます。

:::note[エンティティディメンションのスコープを限定する]
すべてのポイントオブビューには範囲の上限を設けてください。スコープを限定しない抽出は、エクスポートジョブの実行中にFCCSアプリケーションを長時間ロックすることがあります。
:::

## APIドキュメント

このコネクターは、Oracle EPM Cloudの[REST API](https://docs.oracle.com/en/cloud/saas/enterprise-performance-management-common/prest/index.html)を使用します。具体的には、アプリケーションのメタデータエンドポイント（ディメンションとメンバーの検出用）と、データエクスポートジョブのエンドポイント（グリッドのリクエスト、ポーリング、取得用）です。

## 認証の仕組み

この接続は、従来のEPM Cloudポッド上で**サービスアカウントによるHTTP基本認証**を使用します。OAuthやトークンのフローはありません（OCI / Gen 2のベアラートークンポッドは対象外です）。**IDドメイン**を設定すると、PlaidCloudはログインを`identitydomain.username`（ドメイン、ドット、ユーザー名の順）として組み立てます。IDドメインを空白のままにした場合、またはユーザー名にすでにドットが含まれている場合は、ユーザー名がそのまま送信されます。接続先には、セルフサービスのユーザーが取得するアプリケーションとポイントオブビューのスライスに対する読み取りアクセスを持つ、専用の連携用サービスアカウントを指定してください。

## 設定

| フィールド | 必須 | 説明 |
|---|---|---|
| 名前 | はい | この接続の表示名。 |
| EPM Cloud URL | はい | EPM CloudポッドまたはサービスのURL（例：`https://planning-test-yourdomain.epm.us2.oraclecloud.com`）。 |
| IDドメイン | いいえ | EPM CloudのIDドメイン。設定すると、PlaidCloudはログイン時にユーザー名の前に`identitydomain.username`の形式で付加します。 |
| ユーザー名 | はい | 連携用サービスアカウントのユーザー名。 |
| パスワード | はい | サービスアカウントのパスワード。暗号化して保存されます。 |
| デフォルトアプリケーション | いいえ | ステップのポイントオブビューピッカーにあらかじめ入力しておく、デフォルトのFCCSアプリケーション。各ステップで上書きできます。 |

## 接続でできること

- **アドホックなスライスをセルフサービスで取得する。** ステップフォームでポイントオブビュー（POV）、つまりアプリケーションとFCCSのディメンションを組み立てて実行を押すと、結果のテーブルが自動的に作成されます。[HFM/FCCS: データの読み取り（アドホック）](/ja/reference/workflow-steps/oracle-epm/hfm-fccs-read/)ステップを参照してください。
- **チケットを省略する。** スライスは接続のサービスアカウントで実行されるため、財務担当ユーザーはHFM管理者を待たずに自分でデータを取得できます。
- **繰り返しの取得をキャッシュする。** 同じPOVと基準日で再度取得すると、FCCSに再アクセスする代わりに、すでに取り込まれたコピーが即座に返されます。
- **どのエンティティを誰が見られるかを制御する。** 取り込まれたテーブルは**行レベルセキュリティに対応**しています。管理者が`Entity`列に対して行アクセスを宣言すると、セルフサービスのユーザーには、権限のあるエンティティのみが表示されます。これは管理者の管理下で制御されるもので、自動ではありません。ステップのリファレンスを参照してください。
- **定期ロードをスケジュールする。** **バインドしたターゲット**を有効にすると、アドホックなスライスを永続テーブルに昇格できます。テーブルは追記で増え、上書きではなくマージされるため、同じステップをスケジュールされたワークフローに配置すると、毎晩の定期ロードになります。

## メタデータの検出

対応するFCCSポッドでは、接続とアプリケーションを選択すると、ステップフォームがアプリケーションのメタデータから各ディメンションのメンバー一覧をライブで検出します。そのため、POVピッカーでは実際のメンバーから選択できます（どちらかが変更されるたびに再検出されます）。メタデータエンドポイントを公開していない古いポッドでは、検出結果は空になり、ピッカーは手動入力に切り替わります。メンバー名を手で入力し、保存したポイントオブビューは常に正しく復元されます。どちらの場合も、取得の動作は同じです。

## 既知の制限事項

| 制限事項 | 意味 |
|---|---|
| 読み取り専用 | このコネクターはFCCSからデータを抽出します。連結データの書き込み、連結の実行、書き戻しは行いません。 |
| エンティティディメンションのスコープを限定する | スコープを限定しない抽出（`Entity`の選択なし）は、エクスポートジョブの実行中にFCCSアプリケーションを長時間ロックすることがあります。エンティティの選択には範囲の上限を設けてください。 |
| 古いポッドでは手動入力のメンバー | ポッドがメタデータエンドポイントを公開していない場合、メンバー一覧は自動入力されません。メンバー名を手で入力してください。 |
| 行レベルセキュリティは管理者が制御するもので、自動ではない | 取り込まれたテーブルは行アクセスで制御できますが、管理者が公開し、`Entity`列を宣言し、最初の制御付き書き込みを承認し、照合を行う必要があります。それまでは、テーブルはフィルターされません。 |
