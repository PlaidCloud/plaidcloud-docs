## 説明

**LLMステップ** は、大規模言語モデルにプロンプトを送信します。Anthropic の LLM 接続を使用すると、モデルは、バインドしたプロジェクトのテーブル、ディメンション、ドキュメントに、スコープ付きでアクセスできます。オブジェクトごとに **読み取り**、**書き込み**、またはその両方を指定でき、モデルは書き込みが有効なバインディングに結果を直接書き込みます。書き込みバインディングがこのステップの出力であり、別個の出力形式はありません。

詳しい手順については、[LLMステップのガイド](/ja/guides/workflows/llm-step/)を参照してください。

## 設定

* **LLM接続** *（必須）* — 種類が LLM の接続（たとえば Anthropic）です。書き込みバインディングを使用するには、その **エージェントアクセス** を **読み取りと書き込み** にする必要があります。**完全** でも、2027 年 1 月 15 日に廃止されるまでは書き込みが可能で、これを使用するステップは完了時に警告をログに記録します。**読み取りと書き込み** では、ステップは書き込みにチェックを付けたバインディングにのみ書き込み、書き込みを行う SQL の実行やテーブルの作成はできません。
* **モデル** *（任意）* — デフォルトは、接続のデフォルトモデルです。Anthropic の接続では、Claude Sonnet 4.5 などの古いモデルを含め、任意の Claude モデルを使用できます。
* **プロンプト** *（必須）* — バインドしたオブジェクトを参照する `{{tables.NAME}}`、`{{dimensions.NAME}}`、`{{documents.NAME}}` に対応しています。
* **Result schema** *（Anthropic では任意、他のプロバイダーでは必須）* — 取得する構造化サマリーの JSON スキーマ（ルートは `"type": "object"`）です。Anthropic では、モデルの作業が MCP への書き込みである場合は空白のままにします。Anthropic 以外のプロバイダーは MCP にアクセスできないため、スキーマが必須です。
* **Bindings** — モデルがアクセスできるテーブル、ディメンション、ドキュメントです。それぞれセレクターで選択し、**読み取り** または **書き込み**（あるいはその両方）を付与します。書き込み対象のテーブルには行が挿入され、書き込み対象のディメンションにはノードが、書き込み対象のドキュメントにはアップロードされたファイルが追加されます。
* **制限** — 最大出力トークン数（1,024～128,000）と Credential TTL（60～3,600 秒）です。

## 動作

* モデルの呼び出しは、独自のジョブで実行されます。短期間のスコープ付き認証情報が実行ごとに発行され、終了時に取り消されます。
* アクセスはオブジェクトごと、チェックボックスごとに制御されます。モデルは、読み取りバインディングのオブジェクトだけを読み取り、書き込みバインディングのオブジェクトだけに書き込みます。バインドしていないオブジェクトには一切アクセスしません。書き込みには既存の書き込み先オブジェクトが必要で、ステップがそれを作成することはありません。
* 実行のたびに、課金対象のプロバイダー呼び出しが行われ、バインドしたオブジェクトに書き込まれます。

## 保存時のチェック

* **Result schema** — 指定する場合は、有効な JSON であり、JSON オブジェクトで、ルートに `"type": "object"` を宣言している必要があります。そうでない場合、保存は拒否されます。たとえば、*The result schema must declare "type": "object" at its root.* と表示されます。
* **バインディングと接続** — モデルにバインディングへのアクセスを与えるのは Anthropic の接続だけです。他のプロバイダーの接続でバインディングのあるステップを保存すると、プロバイダー名を示し、*Remove the bindings or choose an Anthropic connection.*（バインディングを削除するか、Anthropic の接続を選択してください）と促すメッセージとともに拒否されます。**書き込み** にチェックを付けたバインディングには、**エージェントアクセス** が書き込みを許可している接続が必要です。読み取り専用の接続では、*The selected LLM connection has Read-only Agent Access, so a binding with Write checked could not write. Set the connection to 'Read & write' or uncheck Write on the bindings.* と表示されて保存が拒否されます。接続のないステップを API 経由で保存した場合は、ワークスペースのデフォルトの LLM 接続に対してチェックされ、そのステップもその接続で実行されます。デフォルトの LLM 接続は、管理者がデフォルトに指定したもの、指定がなければ最後に更新されたものです。管理者がデフォルトを指定していない場合、別の LLM 接続を編集すると、その接続がデフォルトになり、ステップの次回の保存が拒否されることがあります。
