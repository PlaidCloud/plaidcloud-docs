## 説明

ワークスペースの利用状況をプロジェクトテーブルに書き込みます。導入状況の経時的な追跡、部門やチームごとの利用状況のレポート、独自のダッシュボードの作成、スケジュール済みワークフローでの活動低下の検知に使用できます。数値は、[利用状況レポート](/ja/administration/access/usage-reports/)に表示されるものと同じです。

3つのデータセットは合計のみを保持します。メンバーを特定する行はなく、ノートブックのパスは `*` に置き換えられます。残りの4つ（**メンバー**、**メンバー別（日次）**、**内容**、**メンバー別の内容**）は、レポート用に作られています。**メンバー**、**メンバー別（日次）**、**メンバー別の内容**にはメンバーの識別情報（ユーザーID、ユーザー名、メールアドレス、姓名、セキュリティグループ）が含まれるため、ターゲットテーブルはメンバー一覧と同様に扱ってください。このステップの各実行は、セキュリティログに記録されます。

## 設定

### 利用データ

**データセット**で、各行に含める内容を選択します。

| データセット | 1行の単位 | 識別情報の有無 |
|---|---|---|
| **項目別（日次）** | 日、エリア、イベント、対象 | なし |
| **項目別（月次）** | 月、エリア、イベント、対象 | なし |
| **月次合計**（デフォルト） | 月、エリア | なし |
| **メンバー** | ワークスペース内の各ユーザー | あり |
| **メンバー別（日次）** | ユーザー、日、エリア | あり |
| **内容** | ダッシュボード、アプリ、ノートブック | なし |
| **メンバー別の内容** | ユーザーと項目 | あり |

**エリア**で、行を1つのエリア（**PlaidCloud アプリ**、**ダッシュボード**、**アプリ**、**アプリ訪問**、**ノートブック**）に絞り込みます。すべてを含めるには、**すべてのエリア**のままにします。

### 列

#### 項目別（日次）

`day`、`source`、`event`、`subject`、`events`。

#### 項目別（月次）

`month`、`source`、`event`、`subject`、`users`、`events`、`unattributed_events`、`coverage_start`、`partial`。

#### 月次合計

`month`、`source`、`active_users`、`coverage_start`、`partial`。

`partial` は、履歴が全期間をカバーしていない月で true になり、`coverage_start` は収集が始まった日付です。月は、締められて確定した後（3日かかります）に含まれます。

#### メンバー列

**メンバー**、**メンバー別（日次）**、**メンバー別の内容**は、同じ7つの列から始まります。

| 列 | 内容 |
|---|---|
| `user_id` | メンバーのID。 |
| `user_name` | メンバーのユーザー名。 |
| `email` | メンバーのメールアドレス（小文字）。 |
| `first_name` | 名。 |
| `last_name` | 姓。 |
| `is_active` | メンバーが有効な場合は true、無効化されている場合は false。 |
| `groups` | メンバーのセキュリティグループ（`; ` 区切り）。 |

`groups` には最上位のグループのみが含まれます。サブグループは展開されません。

#### メンバー

メンバー列に続いて、次の列があります。

| 列 | 内容 |
|---|---|
| `first_seen` | 日付範囲に関係なく、メンバーが初めてPlaidCloudを使用した日。 |
| `last_seen` | 範囲内でメンバーが最後に活動した日。 |
| `active_days` | 範囲内で活動があった日数。 |
| `events` | 範囲内の活動イベント数。 |
| `active_minutes` | 活動の分数。エリア間で重なる分は1回として数えられます。 |
| `session_minutes` | セッションの分数。 |
| `app_open_minutes` | メンバーがPanelアプリを開いていた分数。 |

ワークスペース内のすべてのユーザーに行があります。範囲内に活動がないメンバーは、`groups` の後の値が空白になります。合計は、その後に削除されたメンバーを除き、[利用状況レポート](/ja/administration/access/usage-reports/)と一致します。

#### メンバー別（日次）

メンバー列に続いて、`day`、`source`（エリア）、`events`、`active_minutes`、`session_minutes`、`first_at`、`last_at`（その日の最初と最後の活動時刻）があります。

#### 内容

| 列 | 内容 |
|---|---|
| `type` | `dashboard`、`panel_app`、`wasm_app`、`notebook` のいずれか。 |
| `subject` | 項目のID。すべてのノートブックは1行を共有し、ここには `*` が入ります。 |
| `name` | 項目の名前。ノートブックの場合は `*`。 |
| `deleted` | 項目がその後削除された場合は true。 |
| `users` | 開いたメンバーの数。 |
| `opens` | 開かれた回数。 |
| `last_used` | 最後に使用された日時。 |
| `app_open_minutes` | Panelアプリが開かれていた分数。 |

#### メンバー別の内容

メンバー列に続いて、`type`、`subject`、`name`（**内容**と同じ）、`opens`（このメンバーが項目を開いた回数）、`last_day`（メンバーが最後に使用した日）があります。

### メンバーのデータセットに関する注記

- エージェント、サービスアカウント、その後に削除されたメンバーによる活動では、識別情報の列が空白になります。削除されたメンバーには `user_id` のみが残ります。
- **内容**の開かれた回数は、**メンバー別の内容**の開かれた回数の合計を上回ることがあります。その差は、ダッシュボードの埋め込み表示やゲスト表示など、メンバーに帰属させられない開かれた回数です。**内容**ではこれらが数えられ、**メンバー別の内容**では数えられません。

### 例: 部門別の活動分数

**メンバー**と**メンバー別の内容**にはメンバーの `email`（小文字）が含まれるため、人事テーブルや組織マスターテーブルなど、独自のテーブルと結合して部門別にレポートできます。

1. **データセット**を**メンバー**に設定した**Get Workspace Usage**ステップと、`usage_members` などのターゲットテーブルを追加します。
2. 小文字の `email` 列が一致する条件で `usage_members` と組織テーブルを結合する**テーブル: 内部結合**ステップを追加します。部門は自分のテーブルから、`active_minutes` と `events` の列は `usage_members` から保持します。
3. 同じステップで、部門ごとに集計し、`active_minutes` を合計します。

結果は、部門別の活動分数です。組織テーブルにないメンバーは内部結合から除外されるため、それらも確認したい場合は左結合を使用してください。**メンバー別の内容**に対して2つ目のステップで同様に実行し、部門ごとに `opens` を合計すると、どの部門がどのダッシュボードやアプリを使用しているかをレポートできます。

### 日付範囲

**範囲**で、読み取る日を選択します。

- **直近の日数**（デフォルトは30）は、今日を含む直近の日数分を読み取ります。
- **前月**は、直前の暦月全体を読み取ります。
- **月初から本日まで**は、今月1日から今日までを読み取ります。
- **期間指定**は、**開始日**から**終了日**までを読み取ります。**終了日**を空にすると、今日まで読み取ります。

日と日付はUTCです。**日**、**開始日**、**終了日**には、数値や `YYYY-MM-DD` 形式の日付のほか、`{report_start}` などの[変数](/ja/guides/workflows/manage-workflow-variables/)も指定できます。開始日が終了日より後になってはいけません。

### 利用状況のターゲット

**ターゲットテーブル**が結果を受け取ります。このステップはテーブルの既存の内容を置き換え、行がない場合でも、常にデータセットの列を書き込みます。

## 警告

次の場合、ステップは失敗しません。何が起きたかを示す警告付きで完了し、テーブルも書き込まれます。

- ワークスペースで利用状況の収集がまだ設定されていません。
- 範囲内に利用状況がありませんでした。
- 範囲が保持されている期間より前から始まっているため、履歴の開始日から始まるように切り詰められました。日次データは180日間、月次データは25か月間保持されます。

## セキュリティログ

各実行は、データセット、範囲、ターゲットテーブル、ワークフロー、ステップ、実行、書き込まれた行数を記録したエントリーをセキュリティログに書き込みます。
