## 説明

ワークスペースの利用状況をプロジェクトのテーブルに書き込みます。導入状況の経時的な追跡、部門やチームごとの利用状況のレポート、独自ダッシュボードの作成、スケジュールされたワークフローでの利用低下の検知に使用できます。数値は[利用状況レポート](/ja/administration/access/usage-reports/)と同じ利用状況データに基づいており、どのデータセットもすべての領域を対象とします。

**アクティビティ**と**メンバー**にはメンバーの識別情報（ユーザー ID、ユーザー名、メールアドレス、姓名、セキュリティグループ）が含まれます。ターゲットテーブルは通常のプロジェクトテーブルなので、プロジェクトにアクセスできるユーザーなら誰でも読み取れます。メンバー一覧と同様に扱ってください。テーブルに書き込む各実行はセキュリティログに記録されます。

## 設定

### 利用状況データ

**データセット**は、各行に格納する内容を選択します。その下のテキストに、選択したデータセットの行の内容と主な列が示されます。

| データセット | 値 | 1 行の単位 | 識別情報 |
|---|---|---|---|
| **アクティビティ**（デフォルト） | `activity` | 日、メンバー、アクション、項目 | あり |
| **メンバー** | `members` | メンバー（アクティビティのないメンバーを含む） | あり |
| **内容** | `content` | ダッシュボード、アプリ、ノートブック（誰も使わなかったダッシュボードとアプリを含む） | なし |
| **トレンド** | `trends` | 範囲内の日、週、月 | なし |

この値は、API または AI アシスタントを通じてステップを作成または編集するときに、ステップが保持する値です。この一覧にないデータセットで保存されたステップは、実行時に 4 つのデータセット名を示して失敗します。ステップを開いて**データセット**を選択し、保存してください。以前に保存された**メンバー**または**内容**のステップは引き続き実行され、以下の列を書き込みます。また、1 つの領域に限定されていたステップは、すべての領域を対象にするようになりました。**内容**では、`subject` が `item_id` になり、`type` には `Dashboard`、`App`、`Notebook` のいずれかが入ります。

### 列

日付と日は、UTC の午前 0 時のタイムスタンプとして書き込まれます。

#### メンバー列

**アクティビティ**と**メンバー**には、次の列が含まれます。

| 列 | 内容 |
|---|---|
| `user_id` | メンバーの ID。 |
| `user_name` | メンバーのユーザー名。 |
| `email` | メンバーのメールアドレス（小文字）。 |
| `first_name` | 名。 |
| `last_name` | 姓。 |
| `is_active` | メンバーがアクティブな場合は true、無効化されている場合は false。 |
| `groups` | メンバーのセキュリティグループ（`; ` 区切り）。 |

`groups` には、メンバーが直接所属する最上位のグループが含まれます。

#### アクティビティ

| 列 | 内容 |
|---|---|
| `day` | 日。 |
| メンバー列 | 上記のとおり。 |
| `member` | メンバーの姓名。どちらも設定されていない場合はユーザー名。 |
| `area` | `PlaidCloud app`、`Dashboards`、`Apps`、`Notebooks` のいずれか。 |
| `action` | `Opened app`、`Opened screen`、`Opened step`、`Saved step`、`Used palette action`、`Viewed dashboard`、`Used chart`、`Opened notebook`、`Saved notebook` のいずれか。 |
| `item_type` | `App area`、`Screen`、`Step`、`Palette action`、`Dashboard`、`Chart`、`App`、`Notebook` のいずれか。 |
| `item_id` | 項目の ID。ノートブックの場合はそのパス。 |
| `item_name` | 項目の名前。画面またはアプリ領域は `Members List` のような言葉、ステップはステップタイプ、ダッシュボード、グラフ、アプリはその名前、ノートブックはそのパス。名前が見つからない場合は項目の ID。 |
| `events` | その日にメンバーがそれを行った回数。 |
| `source` | 領域のキー。[利用状況レポート](/ja/administration/access/usage-reports/)のエクスポートでの名前と同じ。 |
| `event` | アクションのキー。エクスポートでの名前と同じ。 |

`member` とメンバー列は、操作した主体によって異なります。

- どのメンバーにも関連付けられないアクティビティでは、`member` が `Unattributed` になり、メンバー列は空になります。
- その後に削除されたメンバーには `user_id` のみが残り、`member` は `Deleted user` になります。
- サービスアカウントやエージェントなどのその他のアカウントには `user_id` のみが残り、`member` はそのユーザー名になります。

`Used chart` は、各 5 分間の枠内でメンバーとグラフごとに 1 回として数えるため、クエリ数ではなく利用を表します。

#### メンバー

| 列 | 内容 |
|---|---|
| メンバー列 | 上記のとおり。 |
| `member` | メンバーの姓名。どちらも設定されていない場合はユーザー名。 |
| `created` | メンバーがワークスペースに追加された日（判明している場合）。 |
| `status` | 範囲内でメンバーがアクティブだった場合は `Active`、以前は PlaidCloud を使用したが範囲内では使用していない場合は `Dormant`、範囲の終了時点で使用記録がない場合は `Never active`。 |
| `first_seen` | 範囲に関係なく、記録上メンバーが初めて PlaidCloud を使用した日。 |
| `last_seen` | 範囲内でメンバーが最後に活動した日。 |
| `active_days` | 範囲内で活動があった日数。 |
| `events` | 範囲内のアクティビティイベント数。 |
| `active_minutes` | 範囲内のアクティビティの分数。 |
| `session_minutes` | 範囲内のセッションの分数。 |
| `app_open_minutes` | 範囲内でメンバーが Panel アプリを開いていた分数。Studio のプレビューは含まれません。 |

利用状況が消去されたメンバーを除き、無効化されたメンバーを含むすべてのメンバーに行があります。サービスアカウントとエージェントは一覧に含まれません。範囲内にアクティビティがないメンバーには `last_seen` がなく、その他のアクティビティ列は空になります。

#### 内容

| 列 | 内容 |
|---|---|
| `type` | `Dashboard`、`App`、`Notebook` のいずれか。 |
| `item_id` | ダッシュボードまたはアプリの ID、もしくはノートブックのパス。 |
| `name` | ダッシュボードまたはアプリの名前、もしくはノートブックのパス。項目が削除されている場合や名前を読み取れない場合は空。 |
| `deleted` | ダッシュボードまたはアプリがその後に削除された場合は true。 |
| `unused` | 範囲内に誰も使わなかったダッシュボードまたはアプリの場合は true。 |
| `users` | 範囲内に使用したメンバー数。 |
| `opens` | 範囲内に開かれた回数（メンバーに関連付けられない開かれた回数を含む）。 |
| `last_used` | 範囲内で最後に使用された日。未使用の項目では、範囲の終了前に最後に開かれた日、または空。 |
| `app_open_minutes` | 範囲内で Panel アプリが開かれていた分数。ダッシュボード、ノートブック、Dash アプリ、WASM アプリでは空。 |

ノートブックのパスごとに行があります。行は、使用されたものが先に、ユーザー数の多い順に並び、その後に誰も使わなかったダッシュボードとアプリが続きます。これらは、公開済みのダッシュボードと、範囲の開始時点で既に存在していたアプリです。範囲の開始日が保持されている日次データの期間内にあり、その時点でこの種の項目の利用状況が収集されていて、名前を読み取れる場合にのみ一覧に含まれます。アプリの Studio プレビューは除外されます。

#### トレンド

| 列 | 内容 |
|---|---|
| `period` | `Day`、`Week`、`Month` のいずれか。 |
| `period_start` | 期間の初日。週は月曜日に始まります。 |
| `active_members` | 範囲内で、その期間にアクティブだったメンバー数。 |
| `events` | その期間のアクティビティイベント数。 |
| `active_minutes` | その期間のアクティビティの分数。 |
| `session_minutes` | その期間のセッションの分数。 |
| `active_members_7d` | `Day` 行では、その日までの 7 日間にアクティブだったメンバー数。 |
| `active_members_28d` | `Day` 行では、その日までの 28 日間にアクティブだったメンバー数。 |
| `stickiness` | `Day` 行では、`active_members` を `active_members_28d` で割った値。 |
| `complete` | 今日、今日を含む週または月、および範囲で途中までしか含まれない週または月では false。 |

範囲内のすべての日（保持されている日次データの開始日以降）に、利用がなくても行があります。それらの日が含まれるすべての週と月にも行があります。`active_members_7d`、`active_members_28d`、`stickiness` は、`Week` 行と `Month` 行、および 7 日間または 28 日間が保持されている日次データより前に及ぶ `Day` 行では空になります。`stickiness` は、`active_members_28d` が 0 の場合にも空になります。保持されている日次データより前に始まり、範囲に完全に含まれる月は、月次サマリーから取得されます。この場合は `active_members` はありますが、イベントと分数は空で、`complete` はサマリーが月全体を対象としていたかどうかを示します。

### 例：部門別のアクティブ分数

**アクティビティ**と**メンバー**には、メンバーの `email`（小文字）が含まれるため、人事テーブルや組織マスターテーブルなど独自のテーブルと結合して、部門別にレポートできます。

1. **データセット**を**メンバー**に設定し、`usage_members` などのターゲットテーブルを指定して、**Get Workspace Usage** ステップを追加します。
2. 小文字の `email` 列が一致する条件で `usage_members` と組織テーブルを結合する **テーブル: 内部結合** ステップを追加します。部門は組織テーブルから、`active_minutes` 列と `events` 列は `usage_members` から保持します。
3. 同じステップで、部門ごとに集計し、`active_minutes` を合計します。

結果は部門別のアクティブ分数になります。組織テーブルにないメンバーは内部結合から除外されるため、表示したい場合は左結合を使用してください。**アクティビティ**に対して 2 つ目のステップで同様に実行し、部門と `item_name` ごとに `events` を合計すると、どの部門がどのダッシュボードやアプリを使っているかをレポートできます。

### 日付範囲

**範囲**は、読み取る日数を選択します。

| 範囲 | 値 | 読み取り対象 |
|---|---|---|
| **直近の日数**（デフォルトは 30） | `last_days` | 本日を含む直近の日数。 |
| **前月** | `previous_month` | 直近の完全な暦月。 |
| **月初から本日まで** | `month_to_date` | 今月 1 日から本日まで。 |
| **日付範囲指定** | `dates` | **開始日**から**終了日**まで。**終了日**を空にすると本日まで読み取ります。 |

日数と日付は UTC です。**日**には整数を指定します。**開始日**と**終了日**には、`YYYY-MM-DD` 形式の日付、または `{report_start}` などの[変数](/ja/guides/workflows/manage-workflow-variables/)を指定します。開始日が終了日より後であってはなりません。

日次データは 180 日間、月次サマリーは 25 か月間保持されます。

### 利用状況のターゲット

**ターゲットテーブル**に結果が書き込まれます。ステップはテーブルの既存の内容を置き換え、行がない場合でも常にデータセットの列を書き込みます。

## 警告

これらはステップを失敗させません。ステップは警告付きで完了し、データセットの列を持つテーブルで既存の内容を置き換えます。

| 警告 | 意味 |
|---|---|
| "Usage data is not available yet: the usage database has not been set up on this workspace." | ワークスペースで利用状況の収集がまだ設定されていません。 |
| "Usage data is not available right now: the usage database could not be reached." | 利用状況データを読み取れませんでした。後でもう一度ステップを実行してください。 |
| "No usage from *start* to *end*." | 範囲内に利用状況がありませんでした。 |
| "Usage before *date* isn't kept, so the range was clipped to start there." | 範囲の開始日が保持されている日次データより前だったため、アクティビティは *date* から集計されます。**トレンド**には、それより前の完全な月が月次サマリーから引き続き含まれます。 |
| "This took too long to compute: narrow the date range." | 読み取りがタイムアウトしたため、テーブルに行はありません。より短い範囲を選択してください。 |
| "Some names are unavailable right now, so those items are named by their id." | **アクティビティ**のみ。一部のダッシュボード、グラフ、アプリの名前を読み取れなかったため、`item_name` には ID が入ります。 |
| "Members could not be read right now, so they are named by their id." | **アクティビティ**のみ。メンバー一覧を読み取れなかったため、`member` にはメンバーの ID が入り、メンバー列のうち `user_id` のみが入力されます。 |
| "Names are unavailable right now, so items nobody used are not listed." | **内容**のみ。ダッシュボードまたはアプリの名前を読み取れなかったため、使用された項目のみが一覧に含まれます。 |
| "Activity before *date* isn't kept, so items nobody used in this range can't be listed." | **内容**のみ。範囲の開始日が保持されている日次データより前のため、使用された項目のみが一覧に含まれます。 |

メンバー一覧を読み取れない場合、**メンバー**は代わりに失敗し、ターゲットテーブルはそのまま残ります。

## セキュリティログ

テーブルに書き込む各実行は、データセット、範囲、ターゲットテーブルとそのプロジェクト、ワークフロー、ステップ、実行、書き込まれた行数、および**アクティビティ**と**メンバー**については行にメンバーの識別情報が含まれることを記録したエントリをセキュリティログに追加します。
