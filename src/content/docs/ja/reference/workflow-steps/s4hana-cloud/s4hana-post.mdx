## 説明

[S/4HANA Cloud接続](/ja/guides/connections/s4hana-cloud/)を使用して、SAP S/4HANA Cloud に総勘定元帳の仕訳を転記します。転記は PlaidCloud 共通の ERP 書き込みパイプラインを経由します。このステップは、ヘッダーテーブル（仕訳ごとに 1 行）と明細テーブル（仕訳ごとに 1 行以上の借方/貸方行）を受け取り、各仕訳を S/4HANA Cloud の `JournalEntryBulkCreateRequest_In` SOAP サービスに送信します。**Validate Only** では、元帳の確保も転記も行わずに、すべての仕訳を構築して検証します。オプションの結果テーブルには、各仕訳の結果が記録されます。

<Aside type="caution">
本番の仕訳を無人で転記する前に、まずすべてのバッチを **Validate Only** で実行して結果テーブルを確認し、いくつかの転記内容を S/4HANA 上で直接照合してください。
</Aside>

## 設定

### 接続

- **S/4HANA Connection** — 転記に使用する S/4HANA Cloud 接続です。

### データ

- **ヘッダーテーブル** — 仕訳ごとに 1 行です。`journal_id`（仕訳識別子、必須）、`company_code`（必須）、`document_date`、`posting_date`、`fiscal_year`、`ledger`、`header_text` を含みます。
- **明細テーブル** — `journal_id` ごとに 1 行以上です。`gl_account`、`debit`、`credit`、および元帳で必要な `cost_center`/`profit_center` のディメンション列を含みます。
- **結果テーブル** — 出力テーブル ID です。仕訳ごとに 1 行で、`journal_id`、`natural_key`、`confirmation_id`、`status`（`posted`/`validated`/`error`）、`message` を含みます。
- **Validate Only** — デフォルトでオンです。事前チェックのみを行い、元帳の確保も転記も行いません。このフィールドが完全に省略されたステップ設定（たとえば REST API、MCP、またはワークフローバンドルのインポートで作成された設定）でも、本番の転記ではなく Validate Only がデフォルトになります。
- **Continue On Error** — デフォルトでオンです。1 つの仕訳が失敗しても、残りの仕訳の転記を続行します。オフにすると、最初の失敗でバッチが停止します。

## 転記の仕組み

PlaidCloud は、各仕訳を `JournalEntryBulkCreateRequest_In` 経由で送信し、その仕訳の最終的な処理状態を報告する対応する `JournalEntryBulkCreateConfirmation_Out` メッセージをポーリングします。仕訳が `posted` と報告されるのは、その確認メッセージを**受信**した場合だけです。受理されたものの確認メッセージが届かない仕訳は、送信が受理されただけで成功と記録されることなく、隔離されたままになります（転記済みとは報告されず、黙って破棄されることもありません）。

## 転記済みの仕訳の訂正

このステップが、転記済みの仕訳を削除したり書き換えたりすることはありません。訂正するには、元の仕訳を直接編集するのではなく、元の仕訳と借方・貸方を入れ替えた新しい仕訳（転記済みの取消仕訳）を転記します。

## 機能上の制限

| 制限 | 内容 |
|---|---|| 確認の待ち時間 | 一括作成サービスはリクエストを非同期に処理するため、最終状態のポーリングでは同期的な結果ではなく確認メッセージを待ちます。 |
| 取消は新しい仕訳であり、元の仕訳の編集ではない | 訂正では、借方・貸方を入れ替えた新しい取消仕訳を転記します。転記済みの仕訳を無効にしたり削除したりすることはできません。 |
| ディメンションの検証は元帳の設定に依存する | 勘定科目構成に対して無効なコストオブジェクトやディメンションの組み合わせは、PlaidCloud が事前に検出するのではなく、S/4HANA 自身の検証で失敗し、`error` 行として表示されます。 |
