## 説明

[Xero接続](/ja/guides/connections/xero/)を使用して、接続先の組織にスコープされた Xero Accounting API のエンティティを1つ、プロジェクトテーブルにインポートします。接続、エンティティタイプ、必要なフィルターを選択すると、ステップが一致するレコードを取得して書き込みます。クエリを作成する必要はありません。

このステップタイプ1つで、参照データ（勘定科目表、取引先、品目、税率、通貨）から取引レコード（請求書、クレジットノート、支払、手動仕訳、銀行取引）まで、11種類のエンティティを扱えます。

## 構成

| フィールド | 必須 | 注記 |
|---|---|---|
| Xero接続 | はい | 読み取りに使用する Xero 接続です。 |
| ターゲットテーブル | はい | 結果の書き込み先となるプロジェクトテーブルです。 |
| エンティティタイプ | はい | 取得するエンティティです。デフォルトは**請求書**です。 |
| ステータス | いいえ | Xero の `Status` 値を1つ指定して絞り込みます（例: `AUTHORISED`、`PAID`）。 |
| 開始日 | いいえ | エンティティの `Date` の下限を `YYYY-MM-DD` 形式で指定します。 |
| 終了日 | いいえ | エンティティの `Date` の上限を `YYYY-MM-DD` 形式で指定します。 |
| 更新日時以降 | いいえ | 更新日時のカットオフとして送信されるため、それ以降に変更された行だけが返されます。空白の場合はすべてを取得します。 |

<Aside type="note">
**更新日時以降**はリクエスト側のフィルターであり、保存されるウォーターマークはありません。PlaidCloudは前回の実行がどこで終わったかを記憶しないため、増分処理にするには、実行のたびにカットオフを自分で指定してください。
</Aside>

## エンティティタイプ

| エンティティタイプ | 保持する内容 |
|---|---|
| 勘定科目表 | 勘定科目コード、名前、タイプ、クラス、税タイプ、ステータス、レポートコード。 |
| 取引先 | 顧客と仕入先。ステータス、税番号、デフォルト通貨を含みます。 |
| 請求書 | 販売および購買の請求書。取引先、日付、ステータス、合計、未払額を含みます。 |
| クレジットノート | 販売または購買に対するクレジットノート。取引先、日付、ステータス、合計を含みます。 |
| 支払 | 日付、金額、ステータス、銀行口座を含む支払。 |
| 手動仕訳 | 仕訳の摘要、日付、ステータス。 |
| 銀行取引 | 支出および入金の取引。日付、ステータス、合計、照合フラグを含みます。 |
| 品目 | 在庫品目とサービス品目。追跡フラグと手持数量を含みます。 |
| トラッキングカテゴリ | トラッキングカテゴリの名前とステータス。 |
| 税率 | 税率の名前、タイプ、ステータス、実効税率。 |
| 通貨 | 通貨コードと説明。 |

<Aside type="note">
すべてのエンティティがすべてのフィルターに対応しているわけではありません。品目と通貨はどちらも使用できず、勘定科目表と取引先はステータスを使用できますが日付範囲は使用できません。フィルターフィールドはすべてのエンティティで有効なままです。エンティティが対応していないフィルターは Xero によって拒否されるため、ステップは誤った結果セットを返すのではなく、エラーを報告します。
</Aside>

<Aside type="caution">
**組織は、このステップではなく接続から決まります。** Xero へのリクエストはすべて1つの組織を指定し、その組織は接続が保持しているため、ステップには組織のフィールドがありません。同じエンティティを2つ目の組織から取得するには、その組織を指す2つ目の Xero 接続を作成します。
</Aside>
