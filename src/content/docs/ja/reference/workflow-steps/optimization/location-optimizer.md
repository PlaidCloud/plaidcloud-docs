ロケーションオプティマイザーステップは、候補地点のテーブルから、需要ポイントのテーブルまでの合計距離または加重距離が最小になる **K** 個のサイトを選択します。PlaidCloud の HiGHS ソルバー上で混合整数計画として解かれる、p-メディアン型の施設配置モデルです。

ロケーションオプティマイザーは、[ソルバー](/ja/reference/workflow-steps/optimization/solver/)が使用するのと同じジョブイメージの、ワークフロージョブのポッドで実行され、結果をプロジェクトテーブルに書き戻します。

## 入力

### 候補サイト

候補となるサイトの位置のテーブルです。テーブルにマッピングされる入力すべてに共通の、ソース／ターゲットの列マッピング、フィルター、集計を使用してマッピングします。

### 需要ポイント

選択されたサイトのうち最も近いものまでの距離を最小化する対象となるポイントのテーブルです。同じ方法でマッピングします。

### 距離テーブル（任意）

候補から需要ポイントまでの距離を事前に計算したテーブルです。未設定のままにすると、ステップが距離を自分で計算します。

### K

候補サイトから選択するサイトの数です。

## ソルバーオプション

| オプション | 説明 |
| --- | --- |
| 時間制限 | 実行時間の上限（秒）。任意です。 |
| MIPギャップ | 相対 MIP ギャップ。任意です。 |
| プレソルブを有効にする | 解く前にソルバーがモデルを簡略化します。デフォルトで有効です。 |
| カスタムリソースを使用 | ジョブのポッドの CPU コア数とメモリを設定します。 |

**時間制限**または **MIPギャップ**で停止した場合は、真の最適解ではなく、その制限内で見つかった最良の解が返されます。これは、[ソルバー](/ja/reference/workflow-steps/optimization/solver/#ステータスの動作)が最適でないステータスの場合に行うのと同じトレードオフです。完全な最適解まで解くには、両方とも未設定のままにします。

## 出力

ロケーションオプティマイザーは 3 つの出力テーブルを書き込みます。これらはすべて異なる名前にする必要があります。

### 選択されたサイトの出力テーブル

選択されたサイトごとに 1 行です。

### 割り当ての出力テーブル

需要ポイントごとに 1 行で、割り当てられた選択済みサイトが示されます。

### サマリーの出力テーブル

ソルバーのステータス、目的関数値、実行の詳細を含む 1 行です。

## 制限事項と注意点

このステップは **p-メディアン**モデルです。需要ポイントから最も近い選択済みサイトまでの合計距離（任意で加重）を常に最小化します。重力型のスコア、カスタムのスコア計算式、距離が小さいほどではなくスコアが高いほど良いとする目的関数は表現できません。これらが必要なサイト選定の問題には、代わりに手動で作成した[ソルバー](/ja/reference/workflow-steps/optimization/solver/)モデルを使用してください。

## 関連項目

- [ソルバー](/ja/reference/workflow-steps/optimization/solver/) — 汎用の線形および混合整数最適化です。このステップの固定された p-メディアンモデルでは扱えないサイト選定の目的関数に使用します。
- [Alteryx 変換マトリックス](/ja/reference/alteryx-conversion-matrix/) — Alteryx の Location Optimizer ツールは、線形の距離最小化のケースに限りこのステップに変換されます。重力カーネルやカスタムのスコアリングマクロは、引き続き変換されません。
