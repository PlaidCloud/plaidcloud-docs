## 説明

[D365 F&O接続](/ja/guides/connections/dynamics-365-fo/)を通じて、Dynamics 365 Finance & Operationsの1つのエンティティをプロジェクトテーブルにインポートします。接続、エンティティタイプ、同期モード、必要なフィルターを選択すると、ステップが一致するレコードを取得して書き込みます。ODataクエリを作成する必要はありません。

これは汎用の定型ステップです。1つのステップタイプで6つのエンティティを扱えます。マスター/参照データ（主勘定科目、通貨、顧客、仕入先、リリース済み製品）から、トランザクションレコード（元帳仕訳ヘッダー）まで、直接のODataコール、または非同期のDMF一括抽出のいずれかで取得します。

## 設定

| フィールド | 必須 | 備考 |
|---|---|---|
| D365 F&O接続 | はい | 読み取りに使用するD365 F&O接続です。 |
| ターゲットテーブル | はい | 結果の書き込み先のプロジェクトテーブルです。実行のたびに全体が上書きされます。 |
| エンティティタイプ | はい | 取得するエンティティです。デフォルトは `main_accounts` です。`main_accounts`、`currencies`、`customers`、`vendors`、`released_products`、`ledger_journal_headers` のいずれかです。 |
| 同期モード | はい | デフォルトは `odata` です。`odata` はエンティティの標準ODataエンドポイントを直接呼び出します。`dmf` は非同期のData Management Frameworkエクスポートジョブを送信し、完了後に結果をダウンロードします。通常のODataページングでは大きすぎる、または遅すぎる取得に使用します。 |
| フィルター | いいえ | リクエストのOData `$filter` に変換される、範囲フィルターと等価フィルターです。各エンティティで指定できるフィルターは、D365 F&Oがサーバー側で実際に評価できるフィールドに限られます。サポートされていないフィールドは、黙って無視されるのではなく、拒否されます。 |

### エンティティとフィルター可能なフィールド

| エンティティタイプ | 取得する内容 | フィルター可能なフィールド |
|---|---|---|
| `main_accounts` | 勘定科目表 | 勘定科目の範囲、ディメンション |
| `currencies` | 通貨マスター | — |
| `customers` | 顧客マスター | 勘定科目の範囲 |
| `vendors` | 仕入先マスター | 勘定科目の範囲 |
| `released_products` | リリース済み製品マスター | — |
| `ledger_journal_headers` | 仕訳ヘッダー（転記済みと未転記） | 日付の範囲、勘定科目の範囲、ディメンション |

<Aside type="note">
日付、勘定科目、ディメンションの**範囲**フィルター（`ge`/`le` 形式の境界）は、`ledger_journal_headers` の取得を絞り込む主な方法です。範囲を指定せずにトランザクション履歴を取得すると、非常に大きくなることがあります。本番データに対して実行する前に、大きなエンティティには少なくとも1つの境界を設定してください。
</Aside>

<Aside type="caution">
`dmf`（一括）モードは非同期のエクスポートジョブの完了を待つため、同じエンティティとフィルターの組み合わせでも、`odata` モードよりかなり遅くなります。直接のOData取得では大きすぎる抽出にのみ使用してください。
</Aside>
