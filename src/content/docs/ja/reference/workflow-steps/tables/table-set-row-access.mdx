## 説明

行アクセスを設定ステップは、ソーステーブルから管理対象列の行アクセスの付与を再計算し、適用します。各行がセキュリティグループと、そのグループが閲覧できる値を組み合わせたテーブルを列に指定すると、このステップがそれらの行を読み取り、結果の付与を書き込みます。そのため、グリッドを手作業で編集しなくても、ソースデータの変更に合わせて行アクセスが常に最新の状態に保たれます。

列は、あらかじめ行を制限するように設定されている必要があります。まず行アクセスのグリッドで設定してください。ステップの最初の実行で、列がソーステーブルにバインドされます。列に手動で設定されていた付与はクリアされ、テーブルの行で置き換えられます。それ以降、その列は行アクセスのグリッドでソースバッジ付きのロック状態で表示され、誰かが **バインディングを削除** をクリックするまで、グリッド上での手動編集は拒否されます。行アクセスのガイドの[付与のソーステーブルへのバインド](/ja/administration/access/managing-security-groups-and-assignments/#付与のソーステーブルへのバインド)を参照してください。

<Aside type="note" title="データの変更に合わせて付与を同期させるために使用します">
典型的な使い方は、ソーステーブルを読み込む、または更新するワークフローの後にこのステップをスケジュールすることです。新しいグループ、削除された値、担当変更された地域が、次回の実行時に自動的に行アクセスへ反映されるため、誰かがグリッドを手作業で更新するのを覚えておく必要がなくなります。
</Aside>

## パラメーター

- **プロジェクト** — このステップが更新する管理対象列を含むプロジェクト。
- **列** — 管理対象列。プロジェクトの実際の列から選択します。
- **ソーステーブル** — （グループ、値）の行を提供するテーブル。列がバインドされているテーブルとは別のテーブルを指定すると、列は新しいテーブルにバインドし直されます。
- **グループ列** — セキュリティグループを示す、ソーステーブルの列。
- **値列** — そのグループが閲覧できる値を示す、ソーステーブルの列。

## 動作

実行のたびに、ソーステーブルに現在あるすべての（グループ、値）の行を読み取り、列の付与をまさにその集合で置き換えます。ソーステーブルに存在しなくなったグループは、このステップがそれまでに与えたすべての付与を失います。存在しないセキュリティグループを指定した行は、ステップを失敗させずにスキップされます。更新は、手動で保存した場合と同じように、PlaidCloud自身のクエリとSupersetダッシュボードの両方に、通常1分ほどで反映されます。

ソーステーブルが誰に何を見せるかを決めるため、バインドされた後にその行を変更したり、テーブルを削除したりできるのは、プロジェクトのアーキテクト、テナント管理者、またはプロジェクト自身のワークフローだけです。

<Aside type="caution">
このステップは、管理する付与の*すべて*を置き換えます。列の付与の一部を手作業で管理し、他の一部をソーステーブルから管理する場合は、2つを別々の列に分けてください。ソースにバインドされた列に手動で編集した付与は、実行の間で保持されません。
</Aside>
