## 説明


同じ列構造を持つ複数のデータテーブルを、1つのデータテーブルに結合するために使用します。たとえば、時系列データはこの変換に最適です。結果は、結合したテーブルのすべてのレコードになります。

<Aside>**Union All** は重複を削除しません。重複レコードを削除する場合は、代わりに **Union Distinct** を使用してください。</Aside>

## ソース


**ソース** セクションは、追加（連結）するすべてのデータテーブルの一覧です。通常、すべてのデータテーブルは同じ（または類似した）列構造を持ちます。データテーブルをリストに追加するボタンは2つあります。


* **行を挿入**
* **行を追加**

また、**編集するソースを選択** ウィンドウ内で右クリックすると、同じオプションが表示されます。すでに追加済みのテーブルを右クリックすると、**削除** オプションも表示されます。


変換を正しく実行するには、追加するソースのデータテーブルごとに、**ソース** セクションに1つのエントリが必要です。これらのエントリは、追加される順序で一覧表示されます。順序を調整するには、テーブルを右クリックして次のオプションを表示します。


* **下へ移動**（該当する場合）
* **末尾へ移動**（該当する場合）
* **上へ移動**（該当する場合）
* **先頭へ移動**（該当する場合）

デフォルトでは、各ソースの名前は *New Frame* ですが、名前をダブルクリックして、わかりやすい名前に変更することをお勧めします。


<Aside>表示されるテキストは、ソースのデータテーブルの名前とは**無関係**であることに注意してください。わかりやすい名前を付けることをお勧めします。多くの場合はソースのデータテーブルと同じ名前になりますが、両者の名前にはまったく関連がないことに留意してください。</Aside>


## ターゲットテーブル


デフォルトでは、**ターゲットテーブル** は空欄です。名前を付ける前に、データテーブルはLinuxの命名規則に従う必要があることに注意してください。そのため、名前は英数字のみで構成することをお勧めします。Analyzeは、名前から無効な文字を自動的に取り除きます。また、長さは256文字に制限されるため、簡潔な名前にしてください。

## 列の照合

**ターゲットテーブル** の下にある **列の照合方法** で、ソース同士をどのように揃えるかを選びます。

* **名前**（デフォルト）— 各ソースの列は、名前によって最初のソースの列と照合されます。
* **位置** — ソースは順番に積み重ねられます。Sparkの `union` と同じ動作です。結果は最初のソースの列名を使用し、すべてのソースの列数が同じである必要があります。各ソースの列マッピングは使用されないため、その **テーブルデータの選択** タブは無効になります。

**位置** を選ぶと、各列には、すべてのソースが収まる型が割り当てられます。2つの数値型は、より広い方の型になります。日付とタイムスタンプはタイムスタンプになり、それ以外の組み合わせはテキストになります。ブール型またはバイナリ型の列を別の型と混在させると共通の型がなく、ステップは失敗します。列数が異なるソースの場合も同様です。

どちらのモードでも、すべてのソーステーブルが存在しない場合、ステップは失敗せずに警告付きで終了します。

## 保存時のチェック内容

すべてのソースは、最初のソースと同じ列を生成する必要があります。列名が同じであること、また両方が型を宣言している場合は型も同じであることが条件です。ターゲットテーブルは、最初のソースの列から作成されます。列は名前で照合されるため、ソースは列を異なる順序で並べることができます。ソースが異なるステップを保存しようとすると、それぞれの相違点が示されて拒否されます。*Source 'east' must produce the same columns as 'west': missing region; not in 'west': area.*

保存時には、ソーステーブルはあるもののソース列またはターゲット列がないソースのマッピングも、そのテーブルから自動的に入力されます。これは **両方のマッピングテーブルを入力** を実行した場合と同じです。
