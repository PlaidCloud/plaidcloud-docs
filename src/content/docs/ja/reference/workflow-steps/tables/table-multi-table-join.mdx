## 説明

**複数テーブル結合**ステップは、ビジュアルな**結合グラフデザイナー**を使用して、1回の操作で多数のテーブル（最大32個）を結合します。2テーブルの結合ステップを連鎖させるパターンに代わるものです。テーブルを追加し、列間の結合を描画し、結合ごとに結合タイプと条件を選択して、出力列をマッピングします。エディターには3つのタブがあります: **Tables & Joins**、**出力列**、**Post-Join Filter**。

詳しい手順については、[複数テーブル結合ステップガイド](/ja/guides/workflows/multi-table-join-step/)を参照してください。

## デザイナー

* **テーブルを追加** — ソーステーブルを、列のカードとしてキャンバスに配置します。各テーブルには**エイリアス**（`alias.column`として使用）があり、英字またはアンダースコアで始まる必要があり、SQLキーワードにはできません。
* **ターゲットテーブル** — 結合結果の書き込み先となるテーブルです。存在しない場合は作成されます。
* **動的** — ソースまたはターゲットを、選択する代わりに参照として指定します。テーブル名、プロジェクトパス（`/03 Results/FACT_GL`）、またはどちらかに実行時に解決される`{variable}`トークンを含めたものです。動的なソースの列は設計時に読み取れないため、サイドパネルで手動で入力します。
* **結合を描画** — あるテーブルの列のドットから別のテーブルの列へドラッグして、結合を作成します。任意の**ラベル**でエッジに名前を付けられます。
* **結合前フィルター** — 結合の*前*に適用される、テーブルごとのフィルターです。
* **サーバーから再取得** — テーブルカードの列を最新のカタログから更新します。
* **レイアウトを整理** / **全体を表示** — グラフを自動配置するか、全体が収まるようにズームします。パンとズームは手動でも操作できます。
* **元に戻す** / **やり直し** / **履歴** — 編集を前後に移動し、確認し、復元します。
* **列をフィルター…** — テーブルカードに表示する列を絞り込みます。
* **エクスポート** — 結合の図をSVGとしてダウンロードします。

## 結合タイプ

| タイプ | 保持する行 |
|------|-------|
| `INNER` | 結合したテーブル間で一致する行。 |
| `LEFT` | 左テーブルのすべての行と、右テーブルの一致した行。 |
| `FULL` | 両方のテーブルのすべての行。 |
| `CROSS` | 行のすべての組み合わせ（条件は使用できません）。 |

## 条件

クロス結合以外の各結合には、**AND** / **OR**で組み合わせた1つ以上の条件があり、演算子`=`、`<>`、`<`、`<=`、`>`、`>=`、`BETWEEN`、`IS NULL`、`IS NOT NULL`、`IN`、`NOT IN`、`LIKE`、`NOT LIKE`を使用できます。

条件では、`Build Plant`や`Cust (Id)`のように、スペースや句読点を含む名前の列を指定できます。その列は、その入力に存在する必要があります。二重引用符、バッククォート、バックスラッシュ、制御文字を含む名前は拒否されます。

`BETWEEN`では、入力のエイリアス、ドット、列の順に書かれた境界（`cust.Max Id`）は、その入力の列として読み取られます。それ以外の境界はリテラルテキストとして扱われ、ドットのない単なるエイリアス名も同様です。そのため、入力にエイリアス`cust`がある場合の`cust.2024`のように、エイリアスとドットで始まるテキストの境界は、列として読み取られ、存在しないと報告されます。

## 出力

**列**タブで、結果の列をマッピングします。必要に応じて、名前の変更、データ型の設定、集計を行います。同じ名前の列には、衝突を避けるために、ソースエイリアスが自動的にプレフィックスとして付けられます。

各行は、次の3つのフィールドのうちちょうど1つから値を取得します。複数を設定したり、何も設定しなかったりすると拒否されます。

| 種類 | フィールド |
|------|--------|
| ソース列 | **ソースエイリアス**（その列を持つキャンバス上のエイリアス）と**ソース**（`alias.column`）。どちらも必須です。 |
| 定数 | **定数** — すべての行で同じ固定値です。 |
| 式 | **式** — キャンバス上の任意のエイリアスを`alias.column`として参照できるSQLAlchemyの式です。 |

* **キャンバスから選択…** — キャンバス上のすべてのソースの列からチェックを入れて選択します。
* **すべてのソース列を追加** — すべてのソースのすべての列を追加します。
* **式の列を追加** — 式の行を追加し、式エディターを開きます。

<Aside type="caution" title="すべての出力列にデータ型が必要です">
**タイプ**が設定されていない出力列があると、このステップは停止し、設定できるようにその列が示されます。ほかのステップは、その出力が読み取るソース列の型にフォールバックしますが、このステップはあえてそうしません。このステップは列をソースエイリアスで管理しており、複数のテーブルにまたがる結合では、推測が当たるのも外れるのも同じくらいの確率であるためです。黙って変換するよりも、修正すべき列が示される方が役に立ちます。
</Aside>

**Post-Join Filter**タブは、結合結果が書き込まれる前に、任意のフィルター（SQLの`HAVING`に相当）を適用します。同じ式エディターで編集します。出力列を`result.column_name`として参照し、ソースエイリアスはここではスコープ外です。

## 実行時に指定された列

**実行時に指定された列も引き継ぐ**を選択すると、ステップが列挙していないすべてのソース列が、ステップの実行時にテーブルが持っているとおりに、そのまま渡されます。ピボットのように、データに応じて名前が決まる列を前のステップが作成するため、ステップの構築時にそれらを列挙できない場合に使用します。オフのままにすると、列挙した列だけが書き込まれます。

## 動作

* 結合グラフはツリーです。各テーブルはちょうど1つのエッジを通じて結果に結合され（循環なし）、テーブルを自分自身に結合することはできません。
* 設定は、ステップの保存時と実行時の両方で検証されます。エラーがあると、問題のあるテーブルまたは結合に⚠マーカーが付き、保存に失敗すると最初の問題があるタブに切り替わり、**問題へ移動**でも、必要に応じてそこに移動できます。出力列の式とPost-Join Filterは保存時にチェックされます。実行時に指定された列を引き継ぐ結合では、保存時の式のチェックは省略され、ステップの実行時にチェックされます。

<Aside type="caution">`CROSS`結合は入力のデカルト積を生成するため、大きなテーブルでは非常にコストが高くなる可能性があります。</Aside>
