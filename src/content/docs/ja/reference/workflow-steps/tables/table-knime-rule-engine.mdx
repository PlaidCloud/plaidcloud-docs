## 説明

**Table: KNIME Rule Engine** ステップは、テーブルに保持されたKNIME Rule Engineのルールの一覧を、ステップの実行時に読み取って適用します。行に最初に一致したルールが、その行の結果を決定します。[移行されたKNIMEワークフロー](/ja/guides/workflows/migrate-knime-workflows/)では、ルールがワークフローの実行時にのみわかるテーブルから取得される場合に、Rule Engine (Dictionary)、Rule Engine Variable (Dictionary)、Rule-based Row Filter (Dictionary)、Rule-based Row Splitter (Dictionary) の各ノード（PMMLルールセットを含む）にこのステップが使用されます。

ステップは、読み取ったルールをコンバーターと同じ方法で変換します。Java専用の構文やフロー変数を使用するルールなど、引き継げないルールがある場合、誤った列を書き込むのではなく、ステップが失敗します。

ステップのフォームには、**ルールの用途** でルールの種類を選択し、ソース、出力、ルールの各テーブルを選択する **テーブル** セクション、**出力** セクション、PMMLルールセット用の **ルール セットのスコアリング** セクション、**列** セクションがあります。

## 設定

- `source` と `target_frame` — 読み取るテーブルと書き込むテーブルです。`source_columns` と `target_columns` は読み取る列と書き込む列で、`output_column` で指定されたターゲット列にルールの結果が入ります。
- `rules_source` — 行がルールとなっているテーブルです。`rules_column` は各ルール、`outcome_column` はその結果を保持し、`rules_order_column` を設定した場合はルールの順序を指定します。
- `rule_kind` — `engine`（デフォルト）は、ルールの結果を `output_dtype` で型指定された `output_column` に書き込みます。`filter` と `splitter` は、ルールが保持する行を書き込みます。`include`（デフォルトはtrue）は、ルールの結果がTRUEのときに行を保持するか除外するかを決め、`port` は保持された行が `1`、それ以外が `2` です。`variable` は、ルールが計算する値の1行のテーブルを、ソーステーブルなしで書き込みます。
- `outcome_cell` — 結果列のKNIMEセルタイプで、ルール内での結果の書き方を決めます。`knime_types` は、タイムゾーン付き日時、期間（duration、period）の入力列のKNIMEセルタイプを指定します。
- `dollar_references` — `$column$` 形式の結果は、テキストではなく列を指します。`disallow_long`（デフォルトはtrue）は、KNIMEの同名の設定に対応します。
- PMMLルールセット — `default_rule` は、常に実行され、最後に追加されるルールです。`weight_column` と `default_weight`（デフォルトは1.0）は、重み付き選択における各ルールの重みを設定し、最も重いルールが最初に試されます。`confidence_column`、`confidence_cell`、`confidence_output`、`default_confidence_rule` は、各ルールの結果の信頼度を書き込みます。
