## 説明


既存のAnalyzeデータテーブルから、別のデータテーブルにデータを抽出する際に使用します。例には次のようなものがありますが、これらに限定されません。


* 並べ替え
* グループ化
* 集計
* 行のフィルター/サブセット化
* 余分な列の削除
* 数値演算
* 文字列操作

<Aside>この変換に固有の関数はありません。並べ替え、グループ化、フィルターなどは、**列**タブと**フィルター**タブを使用して、ほかのどの変換でも実行できます。</Aside>

## 実行時に指定された列

**実行時に指定された列も引き継ぐ**を選択すると、ステップが列挙していないすべてのソース列が、ステップの実行時にテーブルが持っているとおりに、そのまま渡されます。ピボットのように、データに応じて名前が決まる列を前のステップが作成するため、ステップの構築時にそれらを列挙できない場合に使用します。オフのままにすると、列挙した列だけが書き込まれます。

オンにすると、**引き継ぐ列**セクションが表示され、**データで名前が決まる列**セクションは常に利用できます。これらには次のフィールドがあります。

* **引き継ぎ方法**（`carry_expression`）— 引き継ぐ各列を、そのままではなく、この式として書き込みます。`__column__`は引き継ぐ列を表します。グループ化するステップは、実行時にしか名前が分からない列をこのようにして取り込みます。集計するステップは、これがないと何も引き継ぎません。**引き継ぐ列の型**（`carry_dtype`）は、引き継ぐ各列のデータ型を設定し（デフォルトはその列自身の型）、**引き継ぐ列の集計**（`carry_agg`）は、集計するステップがその列をどう扱うかを設定します（式が集計する場合は`dont_group`）。
* **引き継ぐ列の名前変更**（`carry_rename`）— 正規表現`pattern`に一致し、`keep`に一致しない名前の引き継ぐ各列の名前を、一致した各部分を`replacement`に置き換えて変更します（グループには`\1`、設定されている場合は最初の`max`個の一致）。`replacement`内の`__index__`は、名前を変更する列の中での、`start`から数えたその列の位置です。すでに使用されている名前には、` (#n)`が追加されます。
* **動的列**（`dynamic_columns`）— データで名前が決まるターゲット列で、ステップがソースから読み取る個別の値ごとに1セットが、ステップの実行時に書き込まれます。各エントリには、`rows`（ソースに対する式`key`、`label`、`where`、`order`）、`__key__`、`__label__`、`__index__`を使用する`target`の列または列のリスト、そして新しい列を追加する位置となるターゲット列`after`（デフォルトは末尾）を指定します。値は、テキスト、整数、ブール値、またはNULLである必要があります。ステップが書き込む列は最大1,000列で、出力はテーブルである必要があります。ステップの実行時、`rows`の式とステップのフィルターは[拒否される関数と演算子](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#拒否される関数と演算子)のルールに従う必要があり、従わない場合はステップが失敗します。
