## 説明

あるプロジェクトから別のプロジェクトにテーブルをコピーします。共有された参照テーブル、公開された結果セット、ディメンションに基づくルックアップを、ファイルにエクスポートして再度インポートすることなく、プロジェクト間で取得する場合に使用します。

両側を明示的に指定します。ソースのプロジェクトとテーブル、ターゲットのプロジェクトとテーブルです。ターゲットプロジェクトの初期値は現在のプロジェクトですが、任意のプロジェクトを指定できます。そのため、このステップは、このプロジェクトへのコピー、このプロジェクトからのコピー、他の2つのプロジェクト間のコピーのいずれにも使用できます。ターゲットテーブルが存在しない場合は作成されます。ターゲットはビューではなくテーブルである必要があります。

## データ共有の管理

コピーには、最大2つのデータ共有が必要です。

- **ソースプロジェクトからターゲットプロジェクトへの読み取り** — ソースのデータは、ソースが共有している先にのみ届きます。**ソース**プロジェクトの**ホーム**タブを開き、**データ共有の管理**で**新規データ共有**をクリックします。ターゲットプロジェクトを選択し、**許可される操作**で**読み取り**にチェックを入れて、**データ共有を追加**をクリックします。
- **ターゲットプロジェクトからこのプロジェクトへの書き込み** — ターゲットが別のプロジェクトの場合に必要です。ここでの「このプロジェクト」とは、ワークフローがあり、書き込みを行うプロジェクトです。**ターゲット**プロジェクトの**ホーム**タブを開き、**データ共有の管理**で**新規データ共有**をクリックします。このプロジェクトを選択し、**許可される操作**で**書き込み**にチェックを入れて、**データ共有を追加**をクリックします。

したがって、このプロジェクトへのコピーに必要なのは読み取り共有のみで、1つのプロジェクト内でのコピーにはどちらも不要です。[プロジェクト間でのデータ共有](/ja/guides/projects/managing-projects/#プロジェクト間でのデータ共有)を参照してください。

必要な共有がない場合、ステップの保存は拒否され、実行は失敗します。メッセージには、追加が必要な各共有が示されます。たとえば、*Project 'Sales' can't write to project 'Finance': in project 'Finance', under Data Sharing Management, add a data share for 'Sales' that allows Write.* のようになります。拒否された実行では、ターゲットテーブルは作成されず、ターゲットプロジェクトは元の状態のままです。変数として指定されたプロジェクトは、ステップの実行時にチェックされます。

このステップはこのプロジェクト自身のIDで実行されるため、誰が開始しても、実行は共有を通じて動作します。

## コピーパラメーター

### 読み取り元

- **ソースプロジェクト** — コピー元のプロジェクトです。
- **ソーステーブル** — コピーするテーブルです。ソースプロジェクトから選択します。

### 書き込み先

- **ターゲットプロジェクト** — コピー先のプロジェクトです。初期値は現在のプロジェクトです。
- **ターゲットテーブル** — 書き込むテーブルです。ターゲットプロジェクトから選択します。別の**ターゲットプロジェクト**を選択すると、以前のプロジェクトから選択したテーブルはクリアされます。名前またはパスで指定したテーブルは保持され、新しいプロジェクトで検索されます。
- **既存のデータに追加** — チェックを入れると、ターゲットテーブルにすでにあるデータにコピーした行が追加されます。チェックを外すと、テーブルの行がソースの行で置き換えられます。

保存されているプロジェクトが表示できない場合や削除されている場合は、別のプロジェクトに置き換えられることなく、**(missing)** と表示されます。
