## 説明

フィルターに一致する行を更新し、その結果をターゲットテーブルに書き込みます。すべての
ソース行がターゲットに届きます。フィルターに一致する行は新しい値で、
それ以外の行はそのままの状態で書き込まれます。ターゲットの行数は、常にソースの行数と
同じになります。

フィルターは、どの行が*変更される*かを選択するものであり、どの行が返されるかを選択する
ものではありません。この点が、フィルターが一致しない行を除外する
[Table Extract ステップ](/ja/reference/workflow-steps/tables/table-extract/)との違いです。

<Aside type="note" title="このステップはソーステーブルを変更しなくなりました">
以前は、ソーステーブルをその場で更新していました。現在は、ソースには手を加えず、
別のターゲットに書き込みます。これにより、元のデータを比較用に残しておくことができ、
テーブルをその場で変更できないウェアハウスを含め、すべてのウェアハウスでステップを
実行できます。この変更より前に保存されたステップは、実行する前にターゲットテーブルを
選択する必要があります。また、更新された行が表示されることを期待してソースを読み取って
いたステップは、新しいターゲットを指すように変更する必要があります。
</Aside>

## 更新パラメーター

<SnippetCommonTableSourceAndTarget />

ターゲットは、ソースとは別のテーブルである必要があります。このステップはすべてのソース行を
読み取って書き出すため、ターゲットをそのソース自身に戻すと、読み取ったばかりのデータに
結果が追加されてしまいます。

<Aside type="note" title="ソースはビューではなくテーブルである必要があります">
ビューは**ターゲット**として選択できます（ビューはデータを保存せず、読み取られるたびに
ソースに対して再評価されるため、ここでは適した選択です）。ただし、**ソース**としては
選択できません。このステップは、ターゲットの列リストをソーステーブル自身のスキーマから
取得しますが、ビューにはスキーマがないためです。
</Aside>

ターゲットの列は常にソースの列と同じになるため、選択する必要はありません。更新しない列は、
このステップを最後に開いた後でソースに追加された列も含め、そのまま引き継がれます。

## 更新する列

**列**タブで、変更したい列ごとに行を追加し、次のうち、ちょうど1つを設定します。

- **定数** — 固定値です。
- **式** — 計算です。同じ行のほかの列を参照できます。
- **NULLに設定** — 列をクリアします。

一覧にない列は、そのまま残されます。

左側のソース列に含まれていない**更新列**は、**定数**、**式**、**NULLに設定**のいずれかが設定された行であっても、⚠警告マークの後ろに赤で表示されます。このステップは、その列を正確な名前で更新するためです。そのような行がある状態で保存すると、**古い列が見つかりました**ダイアログが開き、**すべて削除して保存**、**このまま保存**、**キャンセル**を選択できます。

保存時には、ソース列の一覧にかかわらず、各**更新列**が現在のソーステーブルに対して、正確な名前でもチェックされます。テーブルにない更新列は、ステップの実行時にそれが原因で失敗するため、**不足しているソース列**ダイアログで名前が示されます。ソース列の一覧自体は、テーブルに対してチェックされません。このステップは、一覧ではなく、テーブルをそのまま読み取るためです。

<Aside type="caution" title="式は行の元の値を読み取ります">
式は、更新*前*の行を参照します。そのため、2つの列の値を
1つのステップで安全に入れ替えることができます。
</Aside>

## 更新のためのデータフィルター

**フィルター**タブで、変更する行を特定する条件を入力します。すべての行を更新する場合は、
空のままにします。

条件を評価できない行（多くの場合、条件が検証する列がnullであることが原因）は、
一致しないものとして扱われ、変更されずにそのまま通過します。これは、データベースが同じ条件を
評価する方法と一致しています。
