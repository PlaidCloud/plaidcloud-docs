## 説明

フィルターに一致する行を更新し、その結果をターゲットテーブルに書き込みます。すべてのソース行がターゲットに届きます。フィルターに一致する行は新しい値で、それ以外のすべての行は元のままです。ターゲットの行数は、常にソースの行数と等しくなります。

フィルターが決めるのは、どの行が*変更される*かであり、どの行が返されるかではありません。この点が、フィルターに一致しない行を削除する[Table Extractステップ](/ja/reference/workflow-steps/tables/table-extract/)との違いです。

<Aside type="note" title="このステップはソーステーブルを変更しなくなりました">
以前は、ソーステーブルをその場で更新していました。現在はソースには手を加えず、別のターゲットに書き込みます。そのため、元のデータを比較用に残しておくことができ、テーブルのその場での変更を許可しないウェアハウスを含め、すべてのウェアハウスでステップを実行できます。この変更より前に保存されたステップは、実行する前にターゲットテーブルを選択する必要があります。また、ソースを読み取って更新後の行を期待していたステップは、新しいターゲットを指すように変更する必要があります。
</Aside>

## 更新パラメーター

<SnippetCommonTableSourceAndTarget />

ターゲットは、ソースとは異なるテーブルである必要があります。このステップはすべてのソース行を読み取って書き出すため、ターゲットを自分自身のソースに向けると、読み取ったばかりのデータに結果が追加されてしまいます。

<Aside type="note" title="ソースはビューではなくテーブルである必要があります">
ビューは**ターゲット**として選択できます（ビューはデータを保存せず、読み取られるたびにソースに対して再評価されるため、ここでは適しています）。しかし、**ソース**としては選択できません。このステップは、ターゲットの列リストをソーステーブル自身のスキーマから取得しますが、ビューにはスキーマがないためです。
</Aside>

ターゲットの列は常にソースの列を反映するため、選択する必要はありません。更新しない列は、このステップが最後に開かれたあとでソースに追加された列も含め、変更されずにそのまま渡されます。

## 更新する列

**テーブルデータの選択** タブで、変更する列ごとに行を追加し、次のいずれか1つだけを設定します。

- **定数** — 固定値。
- **式** — 計算。同じ行の他の列を参照できます。
- **NULLに設定** — 列をクリアします。

一覧にない列は、そのまま残されます。

左側のソース列に一覧表示されていない **更新列** は、**定数**、**式**、**NULLに設定** が設定された行であっても、⚠の警告マークとともに赤で表示されます。このステップは、その列を正確な名前で更新するためです。そのような行を含めたまま保存すると、**古い列が見つかりました** ダイアログが開き、**すべて削除して保存**、**このまま保存**、**キャンセル** が表示されます。

保存時には、ソース列の一覧とは関係なく、各 **更新列** が現在のソーステーブルに対して、正確な名前でチェックされます。テーブルにない更新列は **不足しているソース列** ダイアログに名前が表示されます。そのままではステップの実行時に失敗するためです。ソース列の一覧自体はテーブルに対してチェックされません。このステップが読み取るのは、一覧ではなくテーブルそのものだからです。

<Aside type="caution" title="式は行の元の値を読み取ります">
式は、更新の*前*の行の状態を参照します。そのため、2つの列の値を1つのステップで安全に入れ替えることができます。
</Aside>

## 更新用のデータフィルター

**更新用のデータフィルター** タブで、変更する行を特定する条件を入力します。空のままにすると、すべての行が更新されます。

条件を評価できない行（最も多いのは、テストする列がNULLの場合）は、一致しないものとして扱われ、変更されずにそのまま渡されます。これは、データベースが同じ条件を評価する方法と同じです。
