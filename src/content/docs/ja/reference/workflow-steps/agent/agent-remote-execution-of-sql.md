## 説明

PlaidLinkエージェント経由でのみPlaidCloudから到達できるデータベース（通常は、ファイアウォールの内側、プライベートネットワーク上、またはオンプレミスのデータセンターにあるデータベース）でSQLを実行します。エージェントがSQLをローカルで実行し、成功または失敗をPlaidCloudに報告します。

ソースデータベースをパブリックインターネットに公開せずに、PlaidCloudのワークフローの一部として、リモートのストアドプロシージャ、更新ルーチン、メンテナンスジョブを起動する場合に使用します。

## 行ごとに1回ステートメントを実行する

エージェントを介さずデータベースに直接接続する**リモート実行: SQL**ステップは、テーブルの各行に対してステートメントを1回ずつ実行できます。たとえば、入力行ごとにストアドプロシージャを呼び出す場合です。**SQLの実行**を**行ごとに1回**に設定し、**ドライバーテーブル**を選択して、**パラメーター**を入力します。ステートメント内の各値は`:name`プレースホルダーとして記述し（たとえば`CALL load_region(:region, :period)`）、**パラメーター**の各プレースホルダーを、その値を供給する**ドライバー列**にマッピングします。各値はバインドパラメーターとしてデータベースに送信され、ステートメントのテキストに埋め込まれることはありません。

すべてのパラメーターに名前とドライバー列の両方が必要で、同じパラメーターを2回リストすることはできません。ステートメント内の`:name`にマッピングがない場合や、マッピングがステートメント内にない場合は、フォームが警告します。ドライバーテーブルはビューではなくテーブルである必要があります。行のないドライバーテーブルは、警告を出して終了し、何も実行しません。100,000行を超えるドライバーテーブルは、どの行も実行せずにステップが失敗するため、先にフィルターしてください。

## スクリプトを1つのトランザクションで実行する

**リモート実行: SQL**ステップで、**SQL を 1 つのトランザクション内のステートメントのスクリプトとして実行する（すべて適用されるか、何も適用されない）**（`transaction`）をオンにすると、SQLがステートメントのスクリプトとして1つのトランザクション内で順番に実行され、すべてのステートメントが適用されるか、1つも適用されないかのどちらかになります。
