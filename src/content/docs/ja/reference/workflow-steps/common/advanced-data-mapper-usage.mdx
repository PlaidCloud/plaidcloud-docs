## 復習

データマッパーの高度な機能に進む前に、基本的な機能を簡単に復習しておきましょう。

### データマッパーの設定

データマッパーは、ソースデータの列をターゲットのデータテーブルにマッピングするために使用します。

#### マッパーの検査と入力

**ソースを検査**メニューボタンを使うと、ソースからターゲットへ列をマッピングする方法が追加で用意されています。

* 両方のマッピングテーブルを入力: ソースデータテーブルのすべての値をターゲットのデータテーブルに反映します。これがデフォルトです。
* ソースマッピングテーブルのみを入力: ソースデータテーブルのすべての値のみをマッピングします。ソース列の構造が変わったときに、既存のワークフローを修正する場合に便利です。
* ターゲットマッピングテーブルのみを入力: すべての値をターゲットのデータテーブルにのみ反映します。

ソース列とターゲット列のオプションだけでは足りない場合は、次のようないくつかの方法で、ターゲットのデータテーブルに他の列を追加できます。

* **すべてを反映**は、すでに存在するかどうかにかかわらず、すべてのソース列をターゲットのデータテーブルに挿入します。
* **選択を反映**は、選択したソース列のみを挿入します。
* ターゲット側を右クリックして**行を挿入**を選択すると、現在選択している行の直前に行を挿入します。
* ターゲット側を右クリックして**行を追加**を選択すると、ターゲットのデータテーブルの末尾（右端）に行を挿入します。

<Aside type="danger">**すべてを反映**を選択すると、すべての列が重複して作成される場合があります。Analyzeは、列がすでにマッピングされているかどうかをチェックしません。重複する列名がないことを確認してください。</Aside>

#### 列の削除

ターゲットのデータテーブルから列を削除するには、削除する列を選択し、右クリックして**削除**を選択します。

#### 列の順序の変更

ターゲットのデータテーブルで列を並べ替えるには、対象の列を選択します。次のいずれかを使用できます。
* **一括移動の矢印**: 右上の矢印から、目的の移動オプションを選択します。
* **コンテキストメニュー**: 右クリックして、**先頭へ移動**、**上へ移動**、**下へ移動**、**末尾へ移動**のいずれかを選択します。

#### 結果を重複のないレコードのみに絞り込む

重複のない結果のみを返すには、**重複排除**メニューオプションを選択します。ソースの各列にチェックボックスが表示されます。重複のない結果のみを返したい列の横にあるチェックボックスをオンにするだけです。

<Aside type="danger">ターゲットのデータテーブルにソースデータテーブルの一部の列しか含まれない場合は、ターゲットのデータテーブルに**含める**列の横にあるチェックボックスのみを選択してください。すべてのチェックボックスを選択すると、出力が重複のない結果に見えない場合があります。</Aside>

#### 集計とグループ化

結果を集計するには、**集計**メニューオプションを選択します。ターゲットのデータテーブルの各列に選択ボックスが表示されます。各列に適切な集計方法を選択してください。

<Aside>集計を使用する場合、すべての列に集計タイプを**必ず**指定する必要があります。</Aside>

## 高度な使い方

### 集計オプション

結果を集計するには、**集計**メニューオプションを選択します。ターゲットのデータテーブルの各列に選択ボックスが表示されます。次の集計オプションを使用できます。

| 関数 | 説明 |
|----------|-------------|
| グループ化 | 値で結果をグループ化します |
| 件数 | グループ内のnullでない観測値の数 |
| 件数（nullを含む） | グループ内の観測値の数 |
| 合計 | グループ内の値の合計 |
| 平均 | グループ内の値の平均 |
| 中央値 | グループ内の値の中央値 |
| 最頻値 | グループ内の値の最頻値 |
| 最小 | グループ内の値の最小値 |
| 最大 | グループ内の値の最大値 |
| 最初 | ソート順におけるグループ内の最初の値 |
| 最後 | ソート順におけるグループ内の最後の値 |
| 標準偏差 | グループ内の不偏標準偏差 |
| 標本標準偏差 | グループ内の標本標準偏差 |
| 母標準偏差 | グループ内の母標準偏差 |
| 分散 | グループ内の不偏分散 |
| 標本分散 | グループ内の標本分散 |
| 母分散 | グループ内の母分散 |
| グループ化以外の詳細 | ウィンドウ関数を使用する場合の特別な集計の選択肢 |


列に適切な集計方法を選択してください。

#### RESTとAIアシスタント向けの集計キー

REST APIまたはAIアシスタントでステップを設定する場合、各ターゲット列は`agg`に集計方法を持ち、ステップの`aggregation_type`が同じ選択肢を指定します。データマッパーを持つすべてのステップが、次の値を受け付けます。

| キー | 集計 |
|-----|---------------|
| `group` | グループ化 |
| `dont_group` | グループ化以外の詳細: 列はグループ化も集計もされません。式自体が集計またはウィンドウ処理を行う場合に使用します |
| `count` | グループ内のnullでない観測値の数 |
| `count_null` | nullを含む件数 |
| `count_distinct` | グループ内の異なる値の数 |
| `sum` | 合計 |
| `avg` | 平均 |
| `median` | 中央値 |
| `min` | 最小 |
| `max` | 最大 |
| `stddev` | 標準偏差 |
| `stddev_samp` | 標本標準偏差 |
| `stddev_pop` | 母標準偏差 |
| `variance` | 分散 |
| `var_samp` | 標本分散 |

#### 行のソート

各ターゲット列には`sort`を指定できます。`asc`、`desc`、`none`のいずれか、またはオブジェクト`{ascending, order}`です。`ascending`は`true`または`false`です。`order`はキーの優先順位を決める整数です。`order`を持つ列が先にソートされ、番号の小さいものが先になります。その後に、残りのソート対象列が列の位置順に続きます。

<Aside>集計を使用する場合、すべての列に集計タイプを**必ず**指定する必要があります。</Aside>

ウィンドウ関数を使用する場合は、集計方法として**グループ化以外の詳細**を選択します。ウィンドウ関数にはすでに集計が内在しているため、この特別な選択が必要です。

### 定数

*定数*列に値を指定すると、ソース列の値が指定されていても、それを上書きして、列に指定した定数値を設定します。

### ソース、定数、式の併用

ターゲット列は、次の優先順位で、入力されたもののうちいずれかから値を取得します。*定数*が最優先で、次に*式*、最後に*ソース*列です。

そのため、値を計算する列には*ソース*は不要です。定数や式を指定する場合は空欄にしてください。定数や式がすでに値を定めているため、併せて指定した*ソース*は無視されます。受信データから列をそのままマッピングする場合、名前を変更する場合、または途中で型をキャストする場合は、*ソース*を入力します。

式は、*ソース*セルではなく、`get_column(table, 'Column Name')`を使って、受信列を名前で読み取ります。

<Aside>ファイルインポートでは、式が読み取れる列は、マッパーが取り込む列です。つまり、いずれかのターゲット列の*ソース*として指定されている列と、*ソース*を空欄にした場合のターゲット自身の名前の列です。他の方法ではインポートしない列が式で必要な場合、その列は見つからないため、その列もターゲットにマッピングしてください。</Aside>

### クリーナー

データマッパーには、列内のデータに変換を適用するための、ポイントアンドクリックで使える便利なクリーナー機能があります。

クリーニング操作には、次のカテゴリがあります。
 * テキストのトリム
 * テキストの書式設定
 * テキスト変換
 * NULL値との相互変換
 * 数値書式
 * 日付の解析

クリーナーで選択した内容は、1つの式にまとめて変換され、式の情報で確認できます。

<Aside>生成された式を編集すると、クリーナーフォームは式と連動しなくなります。ただし、式を表示するだけでは連動は解除されません。</Aside>

### 式

データマッパーの[式](/ja/reference/expressions/)は、PlaidCloudで最も強力で柔軟な概念の1つです。非常に大きなデータでも優れたパフォーマンスを発揮しながら、ほぼ無制限の柔軟性を提供します。

[式](/ja/reference/expressions/)は、[Python SQLAlchemy](https://www.sqlalchemy.org/)の構文と、PlaidCloudで利用できるいくつかの追加ヘルパー関数を使って記述します。
これにより、PlaidCloudは基盤となるデータウェアハウス（Greenplum、SAP HANA、Redshiftなど）の機能一式を直接利用できます。さらに、SQLAlchemyの操作に関するクイックリファレンスが公開されており、数多く入手できます。標準のSQLAlchemy構文を使うことで、PlaidCloudは、また新たなドメイン固有の構文を作ってしまうというよくある落とし穴を避けています。

式エディターは、列の式セルをダブルクリックして開きます。開くと、左側に列の一覧、右側に豊富な関数ライブラリが表示されます。

式を直接エディターに入力することも十分可能ですが、通常は、ポイントアンドクリックで関数と列を選択して始めるほうが簡単です。関数ライブラリには、次のグループがあります。

 * 条件
 * 列固有の条件
 * 変換
 * 日付
 * 数学
 * テキスト
 * 集計
 * ウィンドウ関数の操作
 * 配列
 * JSON
 * PostGIS（地理空間）
 * 三角関数

式が完成したら、保存すると列に適用されます。

例と式の関数については、[式](/ja/reference/expressions/)のセクションを参照してください。

<Aside>式は、変換ステップの保存時に検証されます。</Aside>

#### Floatへのキャスト

`cast(x, Float)`は、どのウェアハウスでも64ビットの倍精度数を返すため、`1225541207.71`のような金額もすべての桁が保持されます。StarRocksでは、以前はスキップされていた`Float`へのキャストが適用されるようになり、Databendでは単精度ではなく倍精度になります。PlaidCloudがfloatデータから作成するFloat列も倍精度です。単精度の列を持つ既存のテーブルは、次にステップが**上書き**でテーブルを再構築した時点で、倍精度になります。

StarRocksでは、次のとおりです。

* 大きな整数へのキャストでは、約21億を超える値を保持できます。
* 精度を指定しない`Numeric`へのキャストでは、整数に丸められず、最大10桁までの小数が保持されます。
* JSONへのキャストが適用されます。

どのウェアハウスでも、数値以外のテキストを数値にキャストする場合のように、変換できない値は、ステップを停止させずにnullになります。

### 式から別のテーブルを読み取る

`sqlalchemy.literal_column`は、SQLの断片をウェアハウスにそのまま渡します。受け付けるのは、列、計算、`CASE`、関数呼び出し、キャスト、ウィンドウ関数など、単一の値です。**サブクエリ**（`(SELECT ... FROM ...)`）を含む`literal_column`は、ステップが宣言していないテーブルにアクセスしてしまうため、拒否されます。

このセクションのルールは、式がどこで記述されても適用されます。ここでのマッパー、ステップのフィルター、別の場所で組み立ててプラットフォームに送信されるクエリのいずれも対象です。ルールは、ステップの保存時と、式がSQLに変換される際に再度チェックされます。

代わりに`sqlalchemy.select(...)`でサブクエリを構築してください。列に単一の値が必要な場合は`.scalar_subquery()`、サブクエリから選択する場合は`.subquery()`を使用します。

```python
# Refused
sqlalchemy.literal_column('(SELECT rate FROM fx WHERE fx.cc = t.cc)')

# Supported — a single value in a column
sqlalchemy.select(fx.c.rate).where(fx.c.cc == t.c.cc).scalar_subquery()

# Supported — a table to select from
sqlalchemy.select(fx.c.rate).subquery()
```

### 最上位のORを括弧で囲む

最も外側の演算子が`OR`である`literal_column`も拒否されます。PlaidCloudはテキストをそのまま渡すため、その後に追加された条件は、全体の半分にしか結び付きません。`a OR b`の後に`AND region = 'East'`が続くと、`a OR (b AND region = 'East')`として解釈され、除外するつもりだった行が返されてしまいます。

括弧を追加すれば、これまでどおり動作します。

```python
# Refused
sqlalchemy.literal_column("status = 'open' OR status = 'pending'")

# Supported
sqlalchemy.literal_column("(status = 'open' OR status = 'pending')")
```

式の*内側*にある論理和（`CASE`内にあるもの、またはすでに括弧で囲まれているもの）には影響しません。

`XOR`は、括弧の有無にかかわらず、どこにあっても拒否されます。ウェアハウスによって結合の強さの扱いが異なるため、すべての環境で安全な解釈がないからです。代わりに、`(a AND NOT b) OR (NOT a AND b)`のように展開して記述してください。

コメントを含む`literal_column`も、同じ理由で拒否されます。コメントはステートメントの末尾まで続くため、記述した部分だけでなく、PlaidCloudが式の後ろに追加する内容まで消してしまうからです。

`--`は、ステートメントの残りの部分に及ぶ場合に拒否されます。**`#`は、例外なくテキスト内のどこにあっても拒否されます**。引用符で囲まれた文字列の内部や、Postgresの`#>`および`#>>` JSONパス演算子も含まれます。

```python
# Refused
sqlalchemy.literal_column("attrs #> '{a,b}'")
sqlalchemy.literal_column("code || '#'")
```

`#`は、StarRocksなどのMySQL互換ウェアハウスではコメントの開始になります。また、式を記述する時点では、PlaidCloudはどのウェアハウスが式を実行するかを把握していません。そのため、テキスト内に確実に安全な位置はなく、あるエンジンでは引用符で囲まれているように見える`#`が、別のエンジンではコメントの開始になります。この文字をデータとして必要な場合は、値として渡してください。

```python
# Supported
sqlalchemy.func.concat(table.code, sqlalchemy.literal('#'))
```

`.op('...')`でも、同じ2つの記述が拒否されます。

`literal_column`が通常使われるその他の用途には影響しません。`literal_column('current_date')`、`literal_column("CASE WHEN amount > 0 THEN 'p' ELSE 'n' END")`、`func.count()`は、これまでどおりすべて動作します。スペース、ドット、引用符を含む列名にも影響しません。ウェアハウスが自動的に引用符で囲みます。
