## 説明

Sage Intacct接続を使用し、Intacct の REST v1 API で Sage Intacct に仕訳を転記します。転記用のユーザー定義関数（UDF）を作成する代わりに使える、ローコードのネイティブな方法です。接続を選択して列をマッピングするだけで、認証、バッチ処理、仕訳ごとのエラー処理はステップが行います。

このステップは、上流であらかじめ整形しておいた 2 つのテーブル、**ヘッダーテーブル**と**明細テーブル**を読み取り、各仕訳を検証して転記します。1 回の実行で多数の仕訳を、それぞれ独立して転記し追跡するバッチ処理に対応しています。

<Aside type="danger" title="重複防止の仕組みはありません。再実行する前に結果テーブルを確認してください">
このステップは、どの仕訳がすでに転記済みかを追跡**しません**。再実行すると、前回正常に転記された仕訳も含め、ヘッダーテーブルの**すべての**仕訳が再転記されます。重複を排除する仕組みはありません。再実行する前に、前回の実行の結果テーブルを開いて、実際に転記が必要な仕訳を確認してください。前回の実行で `status` が `unknown` の仕訳が残っている場合は、他の操作を行う前に、下記の[結果テーブル](#結果テーブル)を参照してください。
</Aside>

## データ形式の規約

どの行がどの仕訳に属するかは、ステップでは推測しません。このステップを実行する前に、標準ステップ（代入式、集計など）を使って上流でその構造を構築します。

- **ヘッダーテーブル**には、**仕訳ごとにちょうど 1 行**が必要で、その行に **`entry_key`** 列を含めます。値は仕訳ごとに一意であれば何でもかまいません（バッチ番号、日付と説明を連結したもの、生成した連番など）。
- **明細テーブル**には、転記する明細行ごとに 1 行が必要で、**すべての明細行**が、属するヘッダー行と同じ `entry_key` の値を持つ必要があります。

バッチ処理を行わない 1 件の仕訳でも、この形式が必要です。両方のテーブルのすべての行に、同じ定数の `entry_key` を設定してください。

ステップは、検証や転記の前に両方のテーブルを `entry_key` でグループ化します。そのため、対応する明細行のないヘッダー行、対応するヘッダー行のない明細行、同じキーに対して複数のヘッダー行がある場合は、いずれもその仕訳の検証で失敗し、不正な転記が作成されることはありません。

## 固有の設定項目

### Sage接続

転記に使用する **Sage Intacct** 接続です。ここには Sage Intacct 接続のみが表示されます。汎用の REST 接続は使用できません。転記には、Sage Intacct 接続だけが持つ Intacct 固有のトークン交換と、会社/エンティティの解決が必要なためです。

同じ接続は、Intacct からの*読み取り*（たとえば [Import Sage APステップ](/ja/reference/workflow-steps/sage-intacct/import-sage-ap/)や [Import Sage Intacct Queryステップ](/ja/reference/workflow-steps/sage-intacct/import-intacct-query/)）にも使用されます。1 つの接続で双方向に対応します。[Sage Intacct RESTコネクター](/ja/reference/connectors/rest/sage-intacct/)を参照してください。

### Entry Key

ヘッダーのソース列と明細のソース列の両方に含まれる、ヘッダー行と明細行を 1 つの仕訳にグループ化する列の名前です。上記の[データ形式の規約](#データ形式の規約)を参照してください。

### ソース列

タブごとに 1 つずつ、合計 2 つの列マッピングがあります。それぞれについて、ソース列を、その値を渡す仕訳フィールドにマッピングします。

- **ヘッダー列** — 仕訳レベルのフィールドです。ジャーナル、転記日、説明、参照番号、オプションの `base_location`（仕訳を転記する Intacct のエンティティ/ロケーション。単一エンティティの会社では省略します）、**Entry Key** として指定した関連付け用の列、およびこれに類するヘッダーレベルの詳細が含まれます。
- **明細列** — 転記明細行ごとのフィールドです。総勘定元帳の勘定科目、借方/貸方の金額、明細行の説明、同じ **Entry Key** 列、およびディメンション（ロケーション、部門、従業員、クラスなど）が含まれます。

ソース列の名前を変更する必要はありません。名前が何であっても、上記のターゲットフィールド名にマッピングしてください。

### 結果テーブル

このステップが、仕訳ごとに 1 行を書き込むターゲットテーブルです。仕訳の検証と、（プレビューでない場合は）転記の結果が記録されます。列と `status` の値については、下記の[結果テーブル](#結果テーブル)を参照してください。

### Preview

チェックボックスで、**デフォルトでオン**です。Preview をオンにすると、ステップは実際の実行とまったく同じようにすべての仕訳を検証して結果テーブルを書き込みますが、Intacct への認証は行わず、何も転記**しません**。Preview モードでは Intacct へのネットワーク呼び出しはまったく発生しません。結果テーブルの行は `status = preview` として書き込まれ、総勘定元帳に何かが届く前に、どの仕訳が問題なく転記され、どの仕訳が検証で失敗するかを確認できます。

実際の実行と同様に、Preview は結果テーブルをその実行の行で**置き換えます**。結果テーブルは累積ログではなく、ステップの実行ごとの出力です。そのため、本番の実行後に Preview を行うと、その実行の `posted` 行と `unknown` 行が上書きされます。前回の実行の結果テーブルがまだ必要な場合は、再実行（Preview でも本番でも）する前に、開いてコピーしてください。

Preview では Intacct の**認証情報**は検証されません。接続自体を行わないため、不正な接続や期限切れの認証情報はここでは表面化しません。認証情報は、接続の**接続をテスト**アクション（**Tools > Connections** 内）で別途確認してください。

このフィールドが完全に省略されたステップ設定（たとえば REST API、MCP、またはワークフローバンドルのインポートで作成された設定）でも、本番の転記ではなく Preview がデフォルトになります。

Preview をオフにするのは、本番の転記を行う準備ができたときだけにしてください。まず Preview をオンにして実行し、結果テーブルを確認してから、Preview をオフにして再実行することをお勧めします。

## 結果テーブル

Preview でも本番でも、実行のたびに、仕訳ごとに 1 行を結果テーブルに書き込みます。

| 列 | 説明 |
|---|---|
| `entry_key` | この行が報告する対象の仕訳です。 |
| `status` | `preview`、`posted`、`failed`、`unknown` のいずれかです。詳細は下記を参照してください。 |
| `intacct_key` | 転記された仕訳に Intacct が割り当てたキーです（利用可能な場合）。 |
| `http_status` | 転記の試行に対して Intacct が返した HTTP ステータスです（利用可能な場合）。 |
| `error_message` | `status` が `failed` または `unknown` の場合の、問題の内容を簡潔に（機密情報を除いて）説明したメッセージです。 |
| `line_count` | この仕訳に対応付けられた明細行の数です。 |
| `posting_date` | Intacct に送信された転記日です（Preview の場合は、送信される予定の転記日です）。 |

### ステータスの値

- **`preview`** — Preview モードです。仕訳は検証されましたが、転記されていません。
- **`posted`** — 仕訳は Intacct に正常に転記されました。
- **`failed`** — Intacct が仕訳を明確に拒否しました（または、転記が試行される前に検証で失敗しました）。根本的な問題を修正して、その仕訳だけを再転記しても安全です。
- **`unknown`** — 結果を特定できませんでした。タイムアウト、接続の切断、または Intacct からの明確な応答がないサーバーエラーです。

<Aside type="danger" title="unknown は失敗を意味しません">
`unknown` の仕訳は、Intacct ですでに正常に転記されている可能性があります。接続が切れる前、または応答が返される前に、リクエストが受信されてコミットされた可能性があるためです。**このステップを再実行する前に、Intacct で仕訳のステータスを直接確認してください。** `unknown` の仕訳を確認せずに再転記すると、総勘定元帳に仕訳が重複して作成されるおそれがあります。
</Aside>

`failed` または `unknown` の行がある実行では警告が報告されるため、結果テーブルを開かなくても確認できます。ただし、次に何をすべきかの判断は、結果テーブルを正とします。
