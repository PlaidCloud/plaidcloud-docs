## 説明



定義したルールに基づいて、ソーステーブルの行に、ディメンションの属性でタグを付けます。出力テーブルには、元の列に加えて新しいタグ列が含まれ、後続の配賦ステップや分析ステップがレコードの振り分けやグループ化に使用できます。

行の特性に応じて配賦や分析を変えたい場合に使用します。たとえば、各コスト行に配賦プール、ターゲット階層、または処理カテゴリのタグを付けて、次のステップがタグの値ごとに異なる分配を行えるようにします。

## データテーブルの設定

**ソーステーブル**と**タグ付け結果テーブル**は、動的または静的に選択できます。

### 動的なテーブルの選択
動的テーブルのオプションでは、テキストと変数を使ってテーブルを指定できます。テーブルやビューへの参照が、指定した変数に応じて変わる、変数駆動のワークフローを使う場合に便利です。

`current_month`変数を使って、動的にテーブルを指す例:

```text
legal_entity/inputs/{current_month}/ledger_values
```

### 静的なテーブルの選択
特定のテーブルをソースにしたい場合は、*動的*ボックスをオフのままにして、ドロップダウンメニューからソーステーブルを選択します。


テーブルエクスプローラーは、どのテーブル選択でも常に利用できます。テーブル選択の右にあるテーブルエクスプローラーボタンをクリックすると、テーブルエクスプローラーのウィンドウが開きます。

<Aside>**タグ付け結果テーブル**はビューではなく、テーブルである必要があります。</Aside>

### ソーステーブル

_割り当てディメンション_の属性を追加したいデータを含むテーブルです。

![ルールベースのタグ付け](/images/rule_based_tagging_source.png)


### タグ付け結果テーブル

_タグ付け結果テーブル_には、_ソースデータテーブル_のデータと、_割り当てディメンションの階層_に含まれる属性が格納されます。

**レコードを1つのルールにのみ照合**をオンにした場合、どのルールにも一致しない行もそのまま書き込まれ、そのタグ列は空になります。一致したルールがタグを空のままにしている場合も、タグは空になり、空だったソースの値も空のままです。**PandasではなくSQLでルールを適用**がオンかどうかにかかわらず、空とは空文字列ではなくnullを意味します。そのため、後続のステップでそれらの行を抽出するときは、`''`ではなくnullを探してください。

![ルールベースのタグ付け](/images/rule_based_tagging_target.png)

### 複数のルールにレコードを照合する

デフォルトでは、レコードは最初に一致したルールだけを適用します。**レコードを1つのルールにのみ照合**をオフにすると、一致したすべてのルールが適用されます。レコードは一致したルールごとに1回ずつ現れ、どのルールにも一致しないレコードは除外されます。

ルールは、**シーケンス**タイプの割り当てディメンションのプロパティによって、反復に分割することもできます。そのプロパティの値が、各ルールが実行される反復です。**レコードを1つのルールにのみ照合**をオフにしたステップでは、両方を同時に使うことはできません。実行されるルールが複数の反復にまたがる場合、ステップは*Cannot apply rules when there are multiple iterations and records can match more than one rule*というエラーで停止します。このオプションをオンにするか、各反復を別々のステップとして実行してください。

### 割り当てディメンションの階層

![ルールベースのタグ付け](/images/rule_based_tagging_assignment.png)

**割り当てディメンションの階層**を使うと、ポイントとクリックで***ソーステーブル***をフィルターし、***タグ付け結果テーブル***に属性を追加できます。
**割り当てディメンションの階層**は、***ソーステーブル***を参照するディメンションを組み合わせて作成します。

#### 割り当てディメンションの階層を作成する

**割り当てディメンションの階層**を作成するには、まず、***ソーステーブル***のフィルターとして使用するディメンションを作成する必要があります。ディメンションの作成方法は、次のリンクを参照してください。


[ディメンションの作成](https://docs.plaidcloud.com/docs/workflow-steps/dimensions/dimension-create/) 

[ディメンションのロード](https://docs.plaidcloud.com/docs/workflow-steps/dimensions/dimension-load/) 

##### メイン階層を作成する

***ソーステーブル***のディメンションを作成したら、次に、それらのうちどれを**割り当てディメンションの階層**の***メイン階層***にするかを決めます。

PlaidCloudのディメンションタブでディメンションをクリックし、***アクション***、***ディメンションをコピー***の順に選択して、このディメンションをコピーします。
ディメンションをコピーすると、コピーしたディメンションの名前を入力するポップアップが表示されます。

<Aside>**割り当てディメンションの階層**の名前は、「Ledger to Activity」のように、どのような配賦を行うかが伝わるものにしてください。</Aside>


##### 割り当て階層にディメンションを追加する


新しく作成した**割り当てディメンション**を開き、***プロパティ***の横にある下向き矢印をクリックして、***新規プロパティ***を選択します。

![割り当て階層のプロパティ](/images/allocation_by_dimension_add_property.png)

***プロパティ構成***ダイアログボックスが開きます。
###### プロパティ構成

![割り当て階層のプロパティ構成](/images/allocation_by_dimension_configure_property.png)

- **プロパティ名** - 通常は、割り当て階層に追加するディメンションの名前です。
- **プロパティ表示** - 「Tag」に設定します。
- **プロパティタイプ** - _Rule Based Tagging_では、プロパティタイプを_ソース_に設定します。
  - **ソース** - ***ソーステーブル***と組み合わせて使用します。

- **エディタータイプ** - このドロップダウンは***Select Dimension***に設定します。

割り当て階層に追加するディメンションに適切なプロパティを選択したら、「構成を編集」を選択します。
###### ディメンションの構成

![割り当て階層の構成](/images/allocation_by_dimension_configure.png)

- **ディメンション** - ドロップダウンを使ってディメンションを選択します。
- **階層** - 選択したディメンションに代替階層がある場合は、メイン階層に加えて、それらもここに表示され、選択できます。
- **Start Node** - ディメンションを最上位のノードから表示したくない場合は、階層内の任意のノードを、ディメンションの表示を開始するノードとして選択できます。
- **複数選択を許可** - オンにすると、階層内の複数のノードを選択できるようになります。
- **特殊なケース** - _Rule Based Tagging_では使用しません。
