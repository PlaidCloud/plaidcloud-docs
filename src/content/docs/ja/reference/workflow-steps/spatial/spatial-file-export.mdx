## 説明

**空間: ファイルのエクスポート**ステップは、テーブルをドキュメントアカウント内の空間ファイルに書き込みます。1行が1つのフィーチャーに対応し、ジオメトリはWKT列から、その他の列はフィーチャーの属性として書き込まれます。[空間ファイルのインポート](/ja/reference/workflow-steps/spatial/spatial-file-import/)と組み合わせて使用します。

ステップフォームには、ソーステーブル、その列、出力ファイル、ファイルが存在する場合の動作を設定する**ソースとファイル**セクションと、ジオメトリ列と座標系を設定する**ジオメトリ**セクションがあります。[移行されたKNIMEワークフロー](/ja/guides/workflows/migrate-knime-workflows/)では、地理空間ファイルの書き込みにこのステップが使用されます。

## 設定

- **ソーステーブル**（`source`） — エクスポートするテーブルです。**ソース列**（`source_columns`）は、書き込む列の一覧です。
- **出力ファイル**（`output_file`） — ファイルのドキュメントアカウントとパスです。拡張子で形式が決まります。`.shp`（ESRIシェープファイル）、`.geojson`または`.json`（GeoJSON）、`.gpkg`（GeoPackage）、`.kml`、`.gml`、`.tab`および`.mif`（MapInfo）に対応しています。シェープファイルのように複数のファイルで構成される形式では、関連ファイルも同じ場所に書き込まれます。
- **ジオメトリ列**（`geometry_column`） — 各フィーチャーのジオメトリをWKTで保持する列です。デフォルトは`SpatialObj`です。
- **座標系**（`crs`） — ジオメトリの座標参照系です（`EPSG:4326`など）。ファイルとともに書き込まれます。
- **すでに存在するファイル**（`if_exists`） — **上書きする**（`overwrite`、デフォルト）は既存のファイルを置き換えます。**何も書き込まずにステップを失敗させる**（`fail`）は、何も書き込まれる前にステップを停止します。
