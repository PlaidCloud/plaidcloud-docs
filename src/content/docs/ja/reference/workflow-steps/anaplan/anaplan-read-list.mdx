## 説明

[Anaplan接続](/ja/guides/connections/anaplan/)を通じて1つ以上のAnaplanリストを読み取り、PlaidCloudディメンションにロードします。**1つのステップで複合階層全体を読み取ります**。階層が含むすべてのリストをルートから順に指定してください（例: Region、Country、Storeの順）。複数のステップに分割しないでください。ステージングテーブルは実行のたびに完全に置き換えられるため、1つのステージングテーブルに複数のステップを向けると、各ステップが前のステップの行を消してしまいます。

このステップは、ステップメニューの**Anaplan**の下に**リスト読み取り**というラベルで表示されます。

このステップは、Integration APIを使用して**クラウド直接**でAnaplanに接続します。オンプレミスのエージェント経由のパスはありません。

<Aside type="tip">
このコネクターは読み取り専用で、Basic（ユーザー名とパスワード）またはCA証明書の資格情報で認証します。[認証](/ja/guides/connections/anaplan/#認証)を参照してください。Anaplanのリクエスト予算はテナント全体で共有されるため、他のAnaplanワークフローとこのステップのスケジュールをずらしてください。[スケジュールに関する考慮事項](/ja/guides/connections/anaplan/#スケジュールに関する注意点)を参照してください。
</Aside>

## 設定

### Anaplanソース

| フィールド | 必須 | 注記 |
|---|---|---|
| Anaplan接続 | はい | 読み取りに使用する[Anaplan接続](/ja/guides/connections/anaplan/)です。 |
| 環境 | はい | 接続の環境です。 |
| モデル | いいえ | 接続に保存されているモデルIDを上書きします。接続から動的に検出するか、手動で入力します。 |
| リスト | はい | 階層が含むすべてのAnaplanリストを順序付きリストとして指定します。選択したモデルから検出したリストを追加するか、IDを手動で入力し、上へ移動 / 下へ移動で並べ替えます。ルートから順に並べると読みやすくなりますが、順序は取り込まれる内容には影響しません。親を解決する前に、すべてのリストが読み取られます。 |
| ステージングテーブル | はい | PlaidCloudディメンションが構築される前に、生の親/子/統合/名前およびプロパティの行がここに格納されます。 |

### ターゲットのPlaidCloudディメンション

| フィールド | 必須 | 注記 |
|---|---|---|
| ディメンションを動的に指定 | どちらか一方 | ターゲットのディメンション名です。実行時に解決される`{variable}`トークンを含めることができます。デフォルトで選択されています。 |
| 特定のディメンションを使用 | どちらか一方 | 代わりに、既存のPlaidCloudディメンションを選択します。 |

## このステップで表現できないこと

| 制限事項 | 内容 |
|---|---|
| すべてのエッジは単純な`+`で集計される | Anaplanのリスト階層にはエッジごとの重みや符号がないため、読み取るものがなく、変換で失われるものはありませんが、それ以上のことも表現できません。モデルがラインアイテムやプロパティを通じて除外や負の集計を表現している場合、そのロジックはディメンションに引き継がれないため、後続の処理で再構築する必要があります。 |
| アクセス制御フラグとサブセットのメンバーシップはインポートされない | 選択的アクセスの読み取り/書き込みフラグと各アイテムのリストサブセットのメンバーシップは、ディメンションデータではなくAnaplanのメタデータです。すべてのサブセットを個別の列としてインポートすると、増え続ける共有の名前空間内で実際のプロパティと衝突してしまいます。どちらかと名前が衝突する本物のリストプロパティは、もう一方の名前で暗黙的に取り込まれることなく、拒否されます。 |
| ラインアイテムのサブセットはディメンションとして読み取れない | Anaplanはこれらを汎用のディメンションアイテム用エンドポイントを通じてのみ公開しており、このステップが読み取れるリストとしては公開していません。 |
| 1,000,000件を超えるレコードのリストはこのパスでは読み取れない | このステップが読み取るアイテムエンドポイントは、文書化されている上限を超えると部分的な結果を返さずに完全に拒否し、ページ分割で回避する方法も提供していません。そのため、このステップは部分的なディメンションを取り込まず、上限を明示して拒否します。当面は、Anaplanでリストを分割するか、そのサブセットを読み取ってください。 |
| ノードの親は1つだけ | 親の名前と親IDが一致しないアイテム、親がこのステップで読み取らないリストにあるアイテム、指定された親がまったく存在しないアイテムは、ディメンションのルートに暗黙的に付け替えられることなく、名前を挙げて拒否されます。 |
| リストの最上位アイテムはインポートされない | Anaplanの最上位アイテムは、リスト自体のアイテムではなく、リスト内のすべてのアイテムの上に位置する集計ノードであるため、このステップが読み取るアイテムには含まれません。その結果、ディメンションはAnaplanのリストより1階層浅くなり、リスト自身のルートがディメンションのルートになります。読み取ったリストにこれが宣言されている場合、ステップは警告します。 |
| ノードIDは、一緒に読み取るすべてのリストで一意でなければならない | ノードIDはアイテムのAnaplanコード、コードがない場合は名前です。Anaplanのコードは1つのリスト内でしか一意であることが保証されません。同じ短いコードを再利用している複数のリストは、1つのノードに暗黙的に統合されることなく、名前を挙げて拒否されます。 |
| 代替階層はサポートされない | すべてのリストは、ディメンションのメイン階層にロードされます。 |
| 読み取り専用 | Anaplanに書き戻されることはありません。 |
