## 説明

[Anaplan接続](/ja/guides/connections/anaplan/)を介して1つ以上のAnaplanリストを読み取り、PlaidCloudのディメンションに読み込みます。**1つのステップで複合階層全体を読み取ります。** 階層が含むすべてのリストを、ルートから順に指定してください（例: Region、Country、Store）。複数のステップに分割しないでください。ステージングテーブルは実行のたびに完全に置き換えられるため、1つのステージングテーブルを指す複数のステップがあると、それぞれが前のステップの行を消去してしまいます。

このステップは、ステップメニューの**Anaplan**の下に、**リスト読み取り**というラベルで表示されます。

このステップは、Integration APIを介してAnaplanに**クラウド直接**で到達します。オンプレミスエージェントを経由するパスはありません。

<Aside type="tip">
このコネクターは読み取り専用で、Basic（ユーザー名とパスワード）またはCA証明書の認証情報で認証します。[認証](/ja/guides/connections/anaplan/#認証)を参照してください。Anaplanのリクエスト予算はテナント全体で共有されるため、このステップのスケジュールは、ほかのAnaplanワークフローとずらしてください。[スケジュールに関する考慮事項](/ja/guides/connections/anaplan/#スケジュール上の考慮事項)を参照してください。
</Aside>

## 設定

### Anaplanソース

| フィールド | 必須 | 備考 |
|---|---|---|
| Anaplan接続 | はい | 読み取りに使用する[Anaplan接続](/ja/guides/connections/anaplan/)です。 |
| 環境 | はい | 接続の環境です。 |
| モデル | いいえ | 接続に保存されているモデルIDを上書きします。接続からライブで検出するか、手入力します。 |
| リスト | はい | 階層が含むすべてのAnaplanリストを、順序付きのリストとして指定します。選択したモデルから検出されたリストを追加するか、IDを手入力し、上へ移動 / 下へ移動で並べ替えます。ルートから順に並べると読みやすくなりますが、順序は取り込まれる内容に影響しません。親が解決される前に、すべてのリストが読み取られるためです。 |
| ステージングテーブル | はい | 生の親/子/統合/名前とプロパティの行は、PlaidCloudのディメンションが作成される前に、ここに格納されます。 |

### ターゲットのPlaidCloudディメンション

| フィールド | 必須 | 備考 |
|---|---|---|
| ディメンションを動的に指定 | どちらか一方 | ターゲットのディメンション名で、実行時に解決される`{variable}`トークンを含めることができます。デフォルトで選択されています。 |
| 特定のディメンションを使用 | どちらか一方 | 代わりに、既存のPlaidCloudディメンションを選択します。 |

## プレビュー

**ソース**タブの**プレビュー**は、ステップを実行せずに、このリスト読み取りで生成される列とデータ型を表示します。ロックされたプロジェクトでは利用できません。

## このステップで表現できないこと

| 制限事項 | 意味 |
|---|---|
| すべてのエッジは単純な`+`でロールアップされる | Anaplanのリスト階層には、エッジごとの重みや符号がありません。読み取るものがないため、変換で失われるものはありませんが、それ以上表現できるものもありません。モデルが、ラインアイテムやプロパティを通じて除外や負のロールアップを表現している場合、そのロジックはディメンションに引き継がれず、後続で再構築する必要があります。 |
| アクセス制御フラグとサブセットのメンバーシップはインポートされない | 選択的アクセスの読み取り/書き込みフラグと、各項目のリストサブセットのメンバーシップは、ディメンションデータではなくAnaplanのメタデータです。すべてのサブセットを個別の列としてインポートすると、増え続ける共有名前空間の中で、実際のプロパティと衝突してしまいます。どちらかと名前が衝突する本物のリストプロパティは、もう一方の名前で黙って取り込まれることなく、拒否されます。 |
| ラインアイテムのサブセットはディメンションとして読み取れない | Anaplanは、これらを汎用のディメンション項目エンドポイントを通じてのみ公開しており、このステップが読み取れるリストとしては公開していません。 |
| 1,000,000件を超えるレコードのリストは、このパスでは読み取れない | このステップが読み取る項目エンドポイントは、文書化されているその上限を超えると、部分的な結果を返さずに完全に拒否し、その上限を回避してページングする方法も提供しません。そのため、ステップは部分的なディメンションを取り込まず、上限を明示して拒否します。当面は、Anaplanでリストを分割するか、そのサブセットを読み取ってください。 |
| ノードは必ず1つの親の下にある | 親の名前と親IDが一致しない項目、このステップが読み取らないリストに親がある項目、または指定された親がまったく存在しない項目は、ディメンションのルートに黙って付け替えられることなく、名前を示して拒否されます。 |
| リストの最上位の項目はインポートされない | Anaplanの最上位の項目は、リストの項目自体ではなく、リストのすべての項目の上にあるロールアップノードであるため、このステップが読み取る項目には含まれません。ディメンションはAnaplanのリストより1階層浅くなり、リスト自体のルートがディメンションのルートになります。読み取るリストが最上位の項目を宣言している場合、ステップは警告します。 |
| ノードIDは、一緒に読み取るすべてのリストで一意である必要がある | ノードのIDは、項目のAnaplanコード（コードがない場合は名前）です。Anaplanのコードが一意であることが保証されるのは、1つのリスト内だけです。同じ短いコードを再利用している2つのリストは、1つのノードに黙って統合されることなく、名前を示して拒否されます。 |
| 代替階層はサポートされない | すべてのリストは、ディメンションのメイン階層に読み込まれます。 |
| 読み取り専用 | Anaplanには何も書き戻されません。 |
