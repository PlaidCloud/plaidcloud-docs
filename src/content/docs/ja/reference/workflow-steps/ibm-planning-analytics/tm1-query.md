## 説明

[TM1接続](/ja/guides/connections/tm1/)を介して、IBM **TM1 / Planning Analytics**のキューブからデータを読み取ります。保存済みの**ビュー**を実行するか、**MDX**クエリを記述して実行します。POV（ポイントオブビュー）を使うと、ビューやMDXですでに固定されているもの以外のディメンションメンバーも固定できます。返されたセルセットは、プロジェクトのテーブルとして取り込まれます。スキーマはスキーマオンリードで、クエリ自体の軸から、ディメンション列と `Value` メジャー列が作成されます。

このステップは、ステップメニューの**IBM TM1 / Planning Analytics**に表示されます。

このステップは、RESTのAPIを介して**クラウドから直接**TM1にアクセスします。オンプレミスのエージェントは関与せず、このステップではまだ利用できません。

## 設定

### ソースとターゲット

| フィールド | 必須 | 注記 |
|---|---|---|
| TM1接続 | はい | 読み取りに使用する[TM1接続](/ja/guides/connections/tm1/)です。 |
| 環境 | はい | 接続の環境です。 |
| データベース | はい | クエリ対象のTM1データベース（インスタンス）です。接続にデフォルトのデータベースが設定されている場合は、それがデフォルトになります。 |
| キューブ | はい | クエリ対象のTM1キューブです。接続先のデータベースから動的に検出されるほか、手入力もできます。 |
| ターゲットテーブル | はい | 返されたセルセットの取り込み先となるプロジェクトのテーブルです。 |

### スライス

| フィールド | 必須 | 注記 |
|---|---|---|
| ソースモード | はい | `By View`（デフォルト）は、保存済みのTM1ビューを実行します。`By MDX` は、記述した生のMDXクエリを実行します。 |
| ビュー | By Viewの場合 | 実行する保存済みのTM1キューブビューです。キューブを選択すると動的に検出されるほか、手入力もできます。 |
| MDX | By MDXの場合 | キューブに対して実行するMDXクエリです。 |

### POV（ポイントオブビュー）

ディメンションごとに1つのメンバーを固定して、ビューやMDXですでに固定されている範囲をさらに絞り込みます。増分抽出に便利です（後述）。ディメンションの行を追加し、ディメンションを選択して、メンバーを入力します。メンバーの値には、リテラル（`Jan-2026`）か、実行時にワークフロー自身の変数から解決される `{variable}` トークンを指定できます。これはMDXフィールド自体に適用されるものと同じ置換です。単純なビューやMDXの読み取りでは、POVを空のままにします。`By View` とPOVの併用はサポートされていません。POVが必要な場合は `By MDX` を使用してください。

### オプション

| フィールド | デフォルト | 注記 |
|---|---|---|
| ゼロ/空のセルを除外 | オフ | 値がちょうど数値の `0` のセルを、取得した**後**に除外します。帯域幅の節約にはならず、計画キューブで登録された `0` が実際の事実である場合には、それを破棄してしまいます。ゼロの除外は、クエリ自体で行うことをお勧めします。MDXの `NON EMPTY` や、保存済みビュー自体の抑制設定を使えば、TM1がそもそもゼロを計算しなくなります。 |
| 行数の上限 | 250,000 | 返されるセルの数を制限します。空白のままにすると、デフォルトの上限250,000が適用されます。明示的に引き上げたり引き下げたりもできます。行数の上限が未設定の場合でも、無制限にはなりません。有効な上限を超えるクエリは、暗黙的に切り詰められるのではなく、拒否されます。 |

## 増分抽出

TM1には変更追跡の仕組みが組み込まれていないため、「前回以降に変更されたものだけを取得する」呼び出しはできません。代わりに、実行のたびに**期間（またはバージョン）でスライスする**パターンを使用します。POVの `Period` を、リテラルのメンバー名ではなく `{period}` ワークフロー変数に固定すると、実行ごとにその実行の対象期間が代入され、キューブ全体ではなく1期間分のデータが取得されます。スケジュールされたワークフローと、実行のたびに進む変数を組み合わせると、1期間ずつ増分の履歴を構築できます。

## プレビュー

保存する前に、**プレビュー**で現在のスライスをTM1に対して実行し、最初の数行とセル数を表示します。表示される行数は、ステップ自体に設定された行数の上限とは無関係に、小さな上限に制限されます。

## 値がテキストとして取り込まれる場合

TM1のメジャーディメンションには、数値の要素（`Sales`、`Cost`）と文字列の要素（`Comment`、`Status`）が同じディメンション内に混在していることがよくあります。両方にまたがるスライスでは、`Value` 列はテキストとして取り込まれます。1つの列には1つの物理型しかなく、スライス内に数値でないセルが1つでもあれば、それで型が決まるためです。

これは正しい処理です。文字列のセルをnullにするとデータが失われ、クエリを失敗させると正当なキューブがブロックされ、2つの列に分割するとスキーマが返されるデータに依存してしまいます。代わりに、このステップはその旨を警告します。警告には、列名、規模、原因となった要素が含まれます。例を示します。

> Column Value landed as text: 3 of 4,812 cells are non-numeric (text or boolean), and a column can only have one type. The non-numeric cells come from element Comment. Exclude that element from the slice, or query it separately, to keep this column numeric.

**プレビュー**では保存前に同じ詳細が表示され、POVのメンバーピッカーには各要素のTM1の型（数値、文字列、またはコンソリデーション）が表示されるため、固定する前に文字列の要素を確認できます。POVで文字列の要素を固定することはブロックされません。テキストのメジャーを読み取る正当な方法だからです。ただし、メジャーが軸ではなくPOVにあるため、`Value` 列全体がテキストとして取り込まれます。この場合、軸上のすべてのメンバーが等しく数値ではなく、スライスを区別するものがないため、警告は要素名を挙げずに件数のみを報告します。

`Value` を数値のままにするには、文字列の要素をスライスから除外するか、文字列のメジャーと数値のメジャーを別々にクエリします。

## 機能の制限

| 制限 | 意味 |
|---|---|
| 読み取り専用 | TM1からキューブデータを読み取ります。書き戻しやTIプロセスの実行はできません。 |
| クラウド直接のみ | このステップには、オンプレミスのPlaidLinkエージェント経由のパスはまだありません。TM1サーバーには、PlaidCloudが直接到達できるネットワークパスが必要です。 |
| 変更追跡なし | TM1には差分や変更後の取得を行うAPIがありません。代わりに、実行のたびに期間またはバージョンでスライスしてください（上記の増分抽出を参照）。 |
| ディメンション/階層のインポートなし | このステップはキューブデータを読み取ります。TM1のディメンション階層をPlaidCloudのディメンションとしてインポートする機能は、まだ利用できません。 |
