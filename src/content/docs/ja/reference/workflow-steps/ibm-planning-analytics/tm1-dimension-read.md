## 説明

[TM1 接続](/ja/guides/connections/tm1/)を介して、IBM **TM1 / Planning Analytics** のディメンションから 1 つの階層を読み取り、PlaidCloud ディメンションに読み込みます。TM1 階層の要素、親子関係のエッジ、要素属性は、まず親子の行としてテーブルにステージングされ、そのステージングテーブルから PlaidCloud ディメンションが構築されます。これは PlaidCloud 独自の Dimension Load ステップが実行する読み込みと同じであるため、TM1 階層は、手作業で構築した階層や他の外部ソースの階層とまったく同じように取り込まれます。

このステップは、ステップメニューの **IBM TM1 / Planning Analytics** の下に表示されます。

このステップは、REST API を介して TM1 に **クラウドから直接** アクセスします。オンプレミスのエージェントは関与しません。オンプレミスの経路については、[TM1: キューブのクエリ（エージェント）](/ja/reference/workflow-steps/ibm-planning-analytics/tm1-query-remote/)を参照してください。

## 設定

### TM1ソース

| フィールド | 必須 | 備考 |
|---|---|---|
| TM1接続 | はい | 読み取りに使用する [TM1 接続](/ja/guides/connections/tm1/)です。 |
| 環境 | はい | 接続の環境です。 |
| データベース | はい | 読み取り元の TM1 データベース（インスタンス）です。デフォルトのデータベースが設定されている場合は、接続のデフォルトのデータベースが初期値になります。 |
| TM1ディメンション | はい | 読み取る TM1 ディメンションです。接続先のデータベースからライブで検出されるか、手入力します。 |
| TM1階層 | いいえ | ディメンション内の階層です。ディメンションを選択するとライブで検出されるか、手入力します。空白のままにすると、ディメンション自身の（暗黙の）階層、つまり TM1 がディメンションにちなんで名付けた階層を読み取ります。 |
| ステージングテーブル | はい | PlaidCloud ディメンションを構築する前に、未加工の親/子/属性の行を書き込むテーブルです。 |

ディメンションと階層を選択すると、どの TM1 要素属性が PlaidCloud の **エイリアス** になり、どれが **プロパティ** になるかがフォームに表示されます。これは TM1 自身の属性タイプ（`Alias` と `Numeric`/`String`）に基づきます。各要素自身の TM1 タイプ（Numeric、String、Consolidated）も、`tm1_element_type` という名前のプロパティとして取り込まれます。

### ターゲットのPlaidCloudディメンション

| フィールド | 必須 | 備考 |
|---|---|---|
| ディメンションを動的に指定 | どちらか一方 | ターゲットのディメンション名です。実行時に解決される `{variable}` トークンを含めることができます。デフォルトで選択されています。 |
| 特定のディメンションを使用 | どちらか一方 | 代わりに、既存の PlaidCloud ディメンションをツリーから選択します。 |
| 代替階層 | いいえ | 読み込み先の PlaidCloud 代替階層のキーです。空白のままにすると、メイン階層に読み込みます。 |

代替階層への読み込みは、何かが書き込まれる前に検証されます。PlaidCloud の代替階層では、ディメンションのメイン階層にすでに存在するノードの親を付け替えることはできません。また、TM1 の代替階層は定義上、TM1 自身のメイン階層と要素を共有するため、このオプションでは通常この形になり、特殊なケースではありません。解析された行の親がターゲットディメンションのメイン階層にすでに存在する場合、ステップはステージングテーブルに触れる前に、競合する親を示して失敗します。

## このステップで表現できないこと

| 制限 | 内容 |
|---|---|
| 複数の親を持つ要素は拒否されます | PlaidCloud のディメンションノードには、階層ごとにちょうど 1 つの親があります。同じ階層内の 2 つのコンソリデーションの下にある TM1 要素は読み込めません。ステップは、最初のコンソリデーションから要素を黙って除外するのではなく、問題のあるすべての要素とその親を一覧にした名前付きのエラーで失敗します。代替ロールアップは別の PlaidCloud ディメンションとして読み取るか、先に TM1 で重複した親子関係を解消してください。 |
| コンソリデーションの重みは符号のみを保持します | PlaidCloud のエッジが持つのは係数ではなく、コンソリデーションのフラグ（`+`、`-`、`~`）です。TM1 の重み `0` は `~`（メンバーは親にロールアップされません）になり、負の重みは `-`、正の重みは `+` になります。重みがない場合（TM1 のデフォルト）は `+` として扱われます。**0.5 や 2.0 のような小数の重みや倍率は表現できません**。単純な `+` として取り込まれ、倍率は失われます。これは見過ごされることなく、カウントされて名前が示されます。実行時のステップ警告には、影響を受けたエッジの数が報告され、`parent -> child (weight)` の形式（たとえば `Total Revenue -> Product A (0.5)`）で一覧表示されます。表示は最大 10 件で、それを超える場合は「(and N more)」と示されます。ルートのエッジ（親なし）は、空白ではなく `(root)` と表示されます。数値でない重みが存在する場合は、推測せずに完全に拒否されます。 |
| エージェント経由の検出なし | このステップはクラウド直接のみです。クラウドから到達できない TM1 サーバーの読み取りについては、[TM1: キューブのクエリ（エージェント）](/ja/reference/workflow-steps/ibm-planning-analytics/tm1-query-remote/)を参照してください。 |
