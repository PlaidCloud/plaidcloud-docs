## 説明

**ML: スコアリング**ステップは、[ML: モデルの学習](/ja/reference/workflow-steps/machine-learning/ml-train/)で学習したモデルでデータテーブルをスコアリングし、予測列を1つ追加したデータを書き出します。モデルは通常のテーブルとして渡されるため、一度学習すれば多数のテーブルをスコアリングでき、新しいデータが届くたびに再スコアリングもできます。このステップは、管理されたPlaidCloudジョブとして実行されます（LLMステップと同様です）。

## スコアリングタブ

- **データテーブル** — スコアリングするテーブルです。モデルの学習に使用したすべての特徴量の列が含まれている必要があります。
- **モデルテーブル** — ML: モデルの学習ステップで書き出されたモデルテーブルです。テーブルが空の場合や、保存されたモデルの一部が欠けている場合、ステップは失敗します。
- **出力テーブル** — スコアリングされたデータの書き込み先です。
- **予測列** — 追加する列の名前です。空白の場合は `prediction` が使用されます。その名前がデータテーブルにすでに存在する場合、ステップは失敗します。

## 出力

出力テーブルには、データテーブルのすべての列に加えて予測列が含まれます。分類器ではテキストのクラスラベル、回帰器では数値です。特徴量の値は学習時とまったく同じように準備され、学習中にモデルが一度も見ていないカテゴリ値は、エラーにならず無視されます。

モデルテーブルは、ML: モデルの学習ステップが書き出す形式である必要があります。つまり、モデルの列がすべて揃っていて、既知のアルゴリズムであり、保存されたモデルのすべての部分が存在している必要があります。モデル自体は、標準的な科学計算スタック以外のものを拒否する制限下で読み込まれるため、細工されたモデルの行によって任意のコードが実行されることはありません。

### その他の出力列

**スコアリング オプション**セクションには、次のフィールドがあります。変換されたKNIMEワークフローでも使用されます。

- **クラス確率列**（`probability_column_template`）— 分類器では、クラスごとに1つの確率列を追加します。列名はこのテンプレートの `{class}` を置き換えたものになります。**予測の前に確率を配置**（`probabilities_first`）にすると、確率列が予測列の前に配置されます。**学習で最初に現れた順にクラスを並べる**（`classes_in_domain_order`）にすると、クラスは並べ替えられた順ではなく、学習データで最初に現れた順に並びます。
- **信頼度列**（`confidence_column`）— 分類器では、最も確率の高いクラスの確率を、この名前で追加します。
- **分散列**（`variance_column`）— フォレスト回帰器では、各ツリーの予測の分散を、この名前で追加します。
- **モデル数の列**（`model_count_column`）— ツリーモデルでは、ツリーの数を、この名前で追加します。
- **追加列の順序**（`column_order`）— 追加される列の順序です。空白の場合は、予測、確率、信頼度、分散、モデル数の順です。
- **代わりに書き込む**（`report`）— スコアリングされたデータの代わりに、`variable_importance`、`coefficients`、`statistics`、`pmml`（PMML ドキュメントとしてのモデル）、`centers`、`cluster_counts`、`association_rules` など、モデル自体のテーブルのいずれかを書き込みます。
- **モデル形式**（`model_format`）— `pmml` は、PMML ドキュメントを使ってスコアリングします。モデルテーブルがそのドキュメントを保持しているか、PMML形式を持つ学習器のモデルを保持している必要があります。
- **アルゴリズムの設定**（`algorithm_settings`）— `pca` モデルが射影する成分の数など、モデルのアルゴリズムに固有の、スコアリングまたはレポートの設定です。
- **3 つ目のテーブル**（`source_c`）— `knn_distance` モデルが使用するランダムフォレストなど、一部のアルゴリズムが読み取る3つ目のテーブルです。

AIアシスタントまたはREST APIでは、`report` を `shap_values` に設定することもできます。

## 制限と注意事項

- **インメモリの作業セット** — データテーブルはメモリに読み込まれるため、このステップは1回の実行あたり約100万行を対象としています。
- **変換されたAlteryxワークフロー** — 変換されたPredictツールは、予測列の名前を、ターゲット変数の名前に `_predicted` のサフィックスを付けたものに固定します。
