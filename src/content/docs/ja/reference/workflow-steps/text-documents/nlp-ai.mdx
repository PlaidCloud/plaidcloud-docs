## 説明

**Text NLP AI** ステップは、データに対して7つの行単位のタスクのいずれかを、構造化された（ツール使用を強制した）LLM呼び出しのバッチとして実行します。タスクは、**固有表現認識**、**品詞タグ付け**、**サマリー**、**ゼロショット分類**、**キー／値の抽出**、**プロンプト**、**埋め込み** です。このステップは、管理されたPlaidCloudジョブとして実行されるため（[ML: モデルの学習](/ja/reference/workflow-steps/machine-learning/ml-train/)や[LLMステップ](/ja/reference/workflow-steps/general/llm-step/)と同様）、ワークフローの他の部分とリソースを奪い合うことはありません。

すべてのタスクが実際のLLM呼び出しであるため、結果は実行間でビット単位では再現されません。詳しくは[非決定性](#非決定性llmベースの結果)を参照してください。

## 設定

- **ソース / 出力テーブル** — 入力テーブルと、結果の書き込み先のテーブル。
- **テキスト列**（`field`）— 各タスクが読み取る列。
- **タスク**（`task`）— `ner`、`pos`、`summary`、`zeroshot`、`keyvalue`、`prompt` のいずれか。`embed` タスクはフォームのタスクリストにはありません。AIアシスタントまたはREST APIで設定してください。
- **言語**（`language`）— モデルに渡すテキストの言語。デフォルトは `en` です。
- **LLM接続**（`llm_connection_id`）— Anthropic、OpenAI、Gemini、Azure OpenAI、Grok、GitHub Models向けのLLM接続。空欄にすると、ワークスペースのデフォルトを使用します。
- **モデル**（`llm_model`）— 空欄にすると、接続のデフォルトモデルを使用します。
- **温度**（`temperature`）— オプションのサンプリング温度。[非決定性](#非決定性llmベースの結果)を参照してください。現行世代のモデルはこの設定を無視します。
- **最大行数**（`max_rows`）— ソースの順序で最初のN行のみに回答します。残りの行の回答は空のままです。すべての行に回答する場合は空欄にします。
- **バッチサイズ**（`batch_size`）— LLM呼び出しごとに送信する行数。1から500。デフォルトは25です。応答が切り詰められたバッチは、行が失われる代わりに半分に分割して再試行されます。

## タスク

4つのタスクは、入力行ごとに1つの出力行を返します（**行保持型**）。3つのタスクは、入力行ごとに0行以上を返し、ソースの識別子列（`id_columns`）を各行に引き継ぎます（**行展開型**）。

| タスク | 展開 | 出力列 | タスク固有のフィールド |
| --- | --- | --- | --- |
| 固有表現認識（`ner`） | 行展開型 | `entity_text`、`entity_type` | **エンティティタイプ**（`entity_types`）— 許可するタイプのリスト。空欄の場合、デフォルトは `people`、`organizations`、`locations`、`dates`、`quantities` です。 |
| 品詞タガー（`pos`） | 行展開型 | `token`、`pos`（ユニバーサル品詞タグ。たとえば `NOUN`、`VERB`、`ADJ`） | なし。 |
| サマリー（`summary`） | 行保持型 | `summary` | **Summary Length**（`summary_length`）— 最大文数、1から20。デフォルトは3です。 |
| ゼロショット分類（`zeroshot`） | 行保持型 | `label`、`score`（0から1） | **ラベルフィールド**（`label_field`）— 各行の候補ラベルを保持するソース列。これがないと、モデルには選択肢がありません。**Multi-Label**（`multi`）— 最も適切な1つを選ぶ代わりに、行ごとに複数のラベルを許可します（`, ` で連結されます）。 |
| プロンプト（`prompt`） | 行保持型 | `answer`、`error` | **プロンプト**（`prompt`）— すべての行に適用される指示。必須です。**入力フィールド**（`input_fields`）— プロンプトとともにモデルに送信する列。行ごとに1レコードとして送信されます。空欄の場合は **テキスト列** が送信されます。 |
| 埋め込み（`embed`） | 行保持型 | `embedding`（数値のJSON配列）、`error` | なし。AIアシスタントまたはREST APIで設定します。OpenAI互換またはAzure OpenAIの接続が必要で、接続のデフォルトは通常チャットモデルのため、ステップの **モデル** には埋め込みモデルを指定する必要があります。Anthropicの接続は、埋め込みAPIがないため拒否されます。リクエストが失敗した場合は、そのバッチのすべての行が保持され、`embedding` は空になり、理由が `error` に入ります。 |
| キー／値のペア（`keyvalue`） | 行展開型 | `key`、`value` | **キーフィールド**（`key_field`）— 各行の、抽出する候補キーを保持するソース列。空欄にすると、モデルが自由にキーを見つけます。**Fuzzy**（`fuzzy`）— 候補キーを完全一致ではなく、あいまいに照合します。 |

**ID列**（`id_columns`）は、行展開型のタスクのすべての出力行に、ソーステーブルの識別列を引き継ぎます。これにより、抽出されたエンティティやペアを元のソースレコードまでたどれます。ID列には、タスク自身の出力列と同じ名前を付けることはできません。たとえば、`ner` タスクでID列に `entity_type` という名前を付けると、ステップを保存するときに拒否され、*ID column 'entity_type' has the name of a column the ner task writes; rename or remove it.* と表示されます。

`error` 列には、その行で失敗した呼び出しのメッセージが入ります。プロンプトタスクは、*このレビューの感情を分類してください。* のように、他のタスクではカバーされない行単位の質問に使用します。フィールドの値はデータとして送信され、モデルへの指示として扱われることはありません。

プロンプトタスクでは、**ドキュメント列**（`content_field`）に、各行のドキュメントをbase64で保持する列を指定します。ステップは、1回の呼び出しにつき1つのドキュメントを送信します。ドキュメントは、プロバイダーがその種類とサイズを受け付ける場合、画像またはPDFとしてプロバイダーに送られます。そうでない場合、ステップは **テキストのフォールバック列**（`text_fallback_field`）のテキスト（たとえばOCRテキスト）を送信します。ドキュメント全体がPlaidCloudからプロバイダーに送信されるため、お使いのデータで許容できるかどうかを確認してください。行は1つずつ送信されるため、**バッチサイズ** は無視されます。バッチが失敗した場合、その行は空の `answer` のまま保持され、ステップは警告を出します。

また、ソーステーブルがない場合（*Source table is required.*）や、**バッチサイズ** または **Summary Length** が上記の範囲外の場合も、保存は拒否されます。

## 非決定性（LLMベースの結果）

すべてのタスクは実際のLLM呼び出しであるため、入力がまったく同じでも結果は実行ごとに変わることがあります。ビット単位の再現性は保証されておらず、これは不具合ではなく想定された動作です。

**温度** には、さらに注意点があります。現行世代のモデル（Opus 4.7以降、Sonnet 5以降、Fable）は、明示的なサンプリング温度を完全に拒否します。温度を設定した場合、ステップは一度それを試します。最初の拒否が検出されると、実行は残りのバッチでモデル自身のサーバーデフォルトにフォールバックし、ステップの結果には失敗ではなく、一度だけの情報メモが付きます。温度を空欄のままにする（デフォルト）と、この往復が完全に省かれます。現行のモデルでは、この設定をお勧めします。
