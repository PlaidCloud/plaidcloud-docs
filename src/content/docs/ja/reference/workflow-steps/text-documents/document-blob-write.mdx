## 説明

**ドキュメント: Blob の書き込み** ステップは、[ドキュメント: BLOBの読み取り](/ja/reference/workflow-steps/text-documents/document-blob-extract/)に対応するステップです。各入力行の列にあるbase64のバイト列を、ドキュメントアカウントのファイルに、行ごとに1ファイルで書き込みます。出力テーブルには、入力行が変更されずにそのまま入ります。

ステップのフォームには、**テーブル**、**書き込み**、**アーカイブ** の3つのオプショングループがあります。移行されたKNIMEおよびAlteryxのワークフローは、バイナリオブジェクトおよびファイルの書き込みにこのステップを使用します。

## 設定

- **ソーステーブル**（`source`）と **出力テーブル**（`target_frame`）— 読み取るテーブルと、入力行が変更されずに書き込まれるテーブル。**ソース列**（`source_columns`）には、そのまま渡す列を一覧表示します。
- **書き込み** — 書き込み自体。**行ごとに 1 ファイル** または **行を 1 つのアーカイブとして** を選びます。以下の設定は `alteryx_config` に保存されます。
  - **BLOB 列**（`blob_field`）— base64のバイト列を保持する列。
  - **ファイル列**（`field`）— 各行のファイルを指定する列。
  - **ファイル列の内容**（`method`）— **下のフォルダー内のファイル名**（`FileName`、デフォルト）: ファイル列は、**フォルダー**（`path`）に置かれるファイル名です。**宛先パス全体**（`Path`）: ファイル列は、宛先パス全体です。
  - **フォルダー**（`path`）— 宛先の `{account, path}`。
  - **すでに存在するファイル**（`if_exists`）— すでにファイルがある場合の動作: **上書きする**（`overwrite`、デフォルト）、**ステップを失敗させる**（`fail`）、**そのままにする**（`skip`）。
  - **圧縮**（`compress`）— **各ファイルを gzip 圧縮**（`gz`）は、各ファイルのバイト列を書き込む前にgzipで圧縮します。
  - **< で始まる BLOB は Base64 ではなく XML または SVG テキストです**（`xml_text`）— `<` で始まる値は、そのUTF-8バイトとして書き込まれます。

**行を 1 つのアーカイブとして** は、ソース行を行ごとに1ファイルではなく1つのアーカイブとして、`Path` 列と `Blob` 列（エントリに名前を付ける場合は `Selected` 列と `EntryName` 列も）から書き込みます。その場合、出力テーブルには `ArchivePath` と `Blob` が入ります。**アーカイブ** グループで設定し、設定は `alteryx_config.archive` に保存されます。

  - **アーカイブ ドキュメントのパス**（`destination`）— アーカイブの書き込み先。
  - **形式**（`format`）— `zip`（デフォルト）、`jar`、`tar`、`tar.gz`、`tar.bz2`、`cpio` のいずれか。
  - **ファイル名のみで各エントリに名前を付ける**（`flatten`）、**エントリ名**（`truncate`）、**削除するフォルダー プレフィックス**（`prefix`）— パスからエントリ名を作る方法。
  - **選択したフォルダー自体の名前をエントリに保持**（`root`）、**エントリ名の元になるドキュメント**（`file`）、**EntryName がある場合はそれでエントリに名前を付ける**（`named`）— エントリ名のさらなる制御。
  - **空フォルダーのテーブル**（`folders`）— `Path` 列と `Selected` 列を持つテーブル。エントリとして追加する空のフォルダーを指定します。
  - **既存のアーカイブにマージ**（`append`）— **いいえ**、**競合するエントリで中止**（`abort`）、**競合するエントリを置換**（`overwrite`）のいずれか。
