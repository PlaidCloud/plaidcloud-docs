## 説明

PlaidCloud DocumentからJSONテキストファイルをインポートします。

JSONファイルの詳細については、JSONの公式サイト（http://json.org/）を参照してください。

JSONファイルでは列の順序は保持され*ません*。ソースファイルの列の順序が、インポートされたデータテーブルの列の順序に反映されるとは限りません。

JSONのインポートは、ドキュメント全体をメモリに読み込むのではなく一時ストレージ経由でストリーミングされるため、非常に大きなファイルでもメモリ不足にならずにインポートできます。大きなドキュメントの後半で初めて現れる列も、インポートされるテーブルに含まれます。ネストされたオブジェクトと配列は、標準的なコンパクトなJSONテキストとしてインポートされるため、後続のステップで任意のJSONツールを使って解析できます。

## 固有の設定項目

### JSONデータの向き

次のデータセットを考えてみましょう。

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

JSONファイルは、次の3つのデータ形式のいずれかでインポートできます。

* Records: データはPythonの辞書のセットに保存され、各行は \{Column -> Value, …} の形式で保存されます。例を示します。


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index: データはネストされたPythonの辞書のセットに保存され、各行は \{Index -> \{Column -> Value, …},…} の形式で保存されます。例を示します。


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split: データは単一のPythonの辞書のセットに保存され、値はリストに保存されます。例を示します。


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

上記の形式に加えて、改行区切りのJSON（NDJSON）も使用できます。これは、配列で囲まず、1行に1つの独立したJSONオブジェクトを記述する形式です。例を示します。

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### ドキュメント全体

各ファイルのJSONをそのまま保持するには、**その他の JSON オプション**で**各ファイルを JSON ドキュメント全体を保持する 1 行としてインポートする**（`whole_document`）を選択します。すると、各ファイルは、JSONドキュメント全体を保持する1行としてインポートされ、数値は記述されたとおりに保持されます。
