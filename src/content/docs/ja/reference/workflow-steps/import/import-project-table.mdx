## 説明


別のプロジェクトのテーブルのデータを、現在のプロジェクトにコピーします。[Export Project Table ステップ](/ja/reference/workflow-steps/export/export-project-table/)の逆で、プッシュではなくプルを行います。

統合プロジェクトが多数の運用プロジェクトからデータを取得する場合や、参照データを1つのプロジェクトに集約して他のプロジェクトが読み取る場合に便利です。ソースプロジェクトは、このプロジェクトに**読み取り**のデータ共有を許可している必要があります。


## データ共有の管理

![データ共有の管理](/images/import_external_project_table_1.png)

別のプロジェクトのテーブルをインポートするには、そのプロジェクトがこのプロジェクトによる読み取りを許可している必要があります。**ソース**プロジェクトの**ホーム**タブを開き、**データ共有の管理**で**新規データ共有**をクリックして、このプロジェクトを選択し、**許可される操作**の**読み取り**をオンにして、**データ共有を追加**をクリックします。[プロジェクト間でのデータ共有](/ja/guides/projects/managing-projects/#プロジェクト間でのデータ共有)を参照してください。

ステップはこのプロジェクト自身のIDで実行されるため、誰が開始しても、実行は共有を通じて動作します。

## 外部プロジェクトテーブルのインポート

![ソースとターゲットのインポート](/images/import_external_project_table_2.png)

### 読み取り元
ドロップダウンから**ソースプロジェクト**と**ソーステーブル**を選択します。

### 書き込み先

<SnippetCommonImportTargetSelection />

<Aside type="note" title="空のソーステーブル">
ステップの実行時にソーステーブルに行がない場合、インポートは何も通知せずに成功するのではなく、ソースが空だったという警告を出して完了します。そのため、ターゲットが予期せず空になっていることに気づきやすくなります。多くの場合、これはソースプロジェクトのワークフローがまだそのテーブルを構築していないことを意味します。インポートの前に、ソースにデータが入っていること（スケジュールされた実行の場合は、先に実行されるよう順序付けされていること）を確認してください。
</Aside>

<Aside type="note" title="ソーステーブルの削除">
読み取り元のソーステーブルは、このステップによって使用中として扱われます。削除しようとすると、PlaidCloudは参照を表示し、通常の削除ではなく強制削除の確認を求めます。**テーブルを強制的に削除しますか?**をオンにして**強制削除**を選択します。これは、インポートステップがデータを共有する別のプロジェクトにある場合でも同様です。そのプロジェクト間のケースでは、別のプロジェクトのステップにアクセスできない場合があるため、警告にはそのステップの名前を示さずに参照だけが一覧表示されます。
</Aside>
