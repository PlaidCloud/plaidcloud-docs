## 説明

MongoDBコレクションのドキュメントを、ドキュメントごとに1行として、プロジェクトのテーブルに読み込みます。必要なドキュメントだけを読み取るにはフィルターを使用し、取り込む前にMongoDB側でドキュメントの形を整えるには集計パイプラインを使用します。ステップは、[MongoDB接続](/ja/reference/connectors/databases/mongodb/)を介してMongoDBにアクセスします。

## ソースとターゲット

| 設定 | 必須 | 内容 |
| --- | --- | --- |
| MongoDB接続 | はい | 読み取りに使用する接続です。 |
| データベース | いいえ | 読み取るデータベースです。空白にすると、接続の**デフォルトのデータベース**が使用されます。 |
| コレクション | はい | 読み取るコレクションです。 |
| ターゲットテーブル | はい | ドキュメントの取り込み先のテーブルです。ビューではなくテーブルである必要があります。 |

## クエリ

| 設定 | 内容 |
| --- | --- |
| フィルター（JSON） | JSONオブジェクトで指定するMongoDBのクエリフィルターです（例: `{"status": "open"}`）。一致するドキュメントのみが読み取られます。 |
| 集計パイプライン（JSON） | JSON配列で指定する集計パイプラインです（例: `[{"$match": {"status": "open"}}]`）。設定すると、コレクションはフィルターされる代わりに集計されます。`$out` または `$merge` ステージを含むパイプラインは、MongoDBに書き込んでしまうため拒否されます。 |
| 行数の上限（0 = すべて） | 読み取るドキュメントの最大数です。`0` はすべてを読み取ります。 |
| 時間制限（秒） | MongoDBが読み取りに費やせる時間で、これを超えると読み取りが停止されます。 |
| 列の判定に使うドキュメント数 | ステップで列が宣言されていない場合に、先頭から何件のドキュメントで列とその型を決定するかを指定します。ドキュメントに含まれる各トップレベルのフィールドが列になります。デフォルトは1000です。 |

フィルターとパイプラインには、`{"region": "{region}"}` のように、`{name}` の形式で記述したワークフロー変数を使用できます。各変数の値は、単一のJSON文字列または数値として挿入されるため、変数によってクエリにキーや演算子を追加することはできません。定義されていない変数があると、その変数名を示すエラーでステップが停止します。

## 列マッピング

マッピングタブで、各ドキュメントのフィールドをターゲットテーブルの列にマッピングします。列は、同じ名前のドキュメントのフィールドを読み取ります。存在しないコレクションの場合は、警告を出して完了し、ターゲットテーブルは空のままになります。
