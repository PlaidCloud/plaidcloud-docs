## 説明

PlaidCloud Documentに保存された[Delta Lake](https://delta.io/)テーブルを、プロジェクトのテーブルにインポートします。ステップには、テーブルのフォルダー（`_delta_log` フォルダーとデータファイルを含むフォルダー）を指定します。テーブルは最新バージョンで読み取られます。

ステップのフォームには、[Parquetのインポート](/ja/reference/workflow-steps/import/import-parquet/)と同じタブがあります。**インポートパラメーター**ではテーブルのフォルダーである**ソースファイル**と**ターゲットテーブル**を選択し、**テーブルデータの選択**では列をマッピングし、**データフィルター**では行をフィルターします。**取り込み**は、テーブルの `_delta_log` から列とその型を読み取り、パーティション列があれば最後にテキストとして追加します。フォルダーが存在しない場合や空の場合、**取り込み**は警告にパスを示して*取り込む列がありません*と応答し、現在のマッピングはそのまま保持されます。

[移行されたKNIMEワークフロー](/ja/guides/workflows/migrate-knime-workflows/)では、Delta Table Readerノードにこのステップが使用されます。

## 設定

* `input_file` — ドキュメントアカウントと、Deltaテーブルフォルダーのパスです。検索で複数のテーブルが見つかった場合、`schema_mismatch` が `union`（デフォルト）に設定されていれば、各テーブルは列名で読み込まれ、テーブルにない列はNULLになり、マッピングで宣言されていない列は除外されます。`error` の場合はステップが停止し、テーブルと列が示されます。`schema_mismatch` は、AIアシスタントまたはREST APIで設定します。
* `target_frame` — 行の書き込み先のテーブルです。
* `source_columns` と `target_columns` — 列のマッピングです。
* `source_where`、`having`、`aggregate`、`aggregation_type`、`distinct` — 他のインポートステップと同様に、行のフィルターと集計を行います。
* `use_target_slicer`、`limit_target_start`、`limit_target_end` — 結果の一部のみを保持します。
* `delete_file` — インポート後に、インポートしたファイルを削除します。
* `ascii_only` — ASCII以外の文字を削除します。
* `skip_if_unchanged` — デフォルトでオンです。前回の成功した実行以降、ソースファイルとステップの設定が変更されていない場合、ワークフローの実行はインポートをスキップします。
