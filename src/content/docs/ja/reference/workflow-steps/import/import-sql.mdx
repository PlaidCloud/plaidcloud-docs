## 説明


外部データベースに対するSQLクエリの結果を、PlaidCloudのプロジェクトテーブルにインポートします。クエリはリモートデータベース上で実行され、結果セットだけがPlaidCloudに取り込まれます。

[外部データベーステーブルのインポート](/ja/reference/workflow-steps/import/import-external-database-tables/)との違いは、SQLを自分で記述する点です。データがPlaidCloudに取り込まれる前に、ソースデータベースで実行したい複雑な結合、フィルター、集計がある場合に便利です。

### 列タイプの推測
SQLのインポートでは、読み込み時にデータ型の推測を試みるか、すべての列をテキスト型に設定するかを選択できます。データがクリーンな場合は、データ型を動的に設定する方が高速ですが、状況によっては問題が発生することがあります。

たとえば、データのほとんどが数値に見えても一部にテキストが含まれていると、数値として設定しようとして、データ型の不一致による読み込みの問題が発生することがあります。また、たとえば16桁の数値の商品コードがある場合にも問題が発生することがあります。先頭のゼロが切り捨てられ、16桁のコードではなく数値になってしまいます。

ただし、データをすべてテキストに設定した場合は、後続のExtractステップで、日付や数値など、テキストにすべきでないデータ型を適切な型に変換する必要があります。

## トラブルシューティング

| 症状 | 考えられる原因 |
| --- | --- |
| クエリ、接続、データ量に変更がないにもかかわらず、ステップに通常よりも著しく長い時間（最大で約30分）がかかった | インポートを実行しているバックグラウンドワーカーが途中で中断され（ワークフローではなく、プラットフォーム側の再起動または退避によるものです）、プラットフォームがそのテーブルのインポートを再試行しました。再試行は中断が検出されてから開始されるため、余分な時間がかかります。 |
| その遅延の後、ステップは正常に完了した | 再試行ではテーブルの内容が完全に置き換えられるため、結果は1回で正常に実行された場合と同じです。確認や再実行は必要ありません。 |
| ステップが「has already been attempted and cannot be safely re-run」で失敗する | SQLのインポートステップでは、この拒否はなくなりました。実行途中の中断は再試行されます。[プロジェクトアーカイブの復元](/ja/guides/projects/archive-a-project/#アーカイブの復元)や[ディメンションの読み込み](/ja/reference/workflow-steps/dimensions/dimension-load/)では、再実行すると何かを置き換えるのではなく重複が作成されるため、設計上、引き続きこのエラーが表示されます。SQLのインポートステップ自体でこのエラーが表示された場合は、サポートチケットを開いてください。
