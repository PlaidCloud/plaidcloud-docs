## 説明

ドキュメントアカウントからMicrosoft Accessデータベースファイルを読み取り、そのテーブルをインポートします。Accessのテーブルごとに1つのプロジェクトテーブルが作成され、指定したプレフィックスが名前に付きます。

Accessファイルには多数のテーブルが含まれるため、このステップは単一テーブルの列をマッピングするのではなく、ファイル全体をインポートします。

## 固有の設定項目

### ソース

ドキュメントアカウント内のAccessデータベースファイルです。ファイルピッカーでは、完全一致のパスではなく検索による一致も使用でき、再帰オプションと、一致した複数ファイル間のスキーマの違いを調整するルールも指定できます。

### ターゲット

**テーブルプレフィックス** — インポートされる各テーブルの名前の先頭に付加されます。これにより、1つのファイルのテーブルがまとまり、別のインポートのテーブルと衝突しません。

### 変更がない場合はスキップ

デフォルトでオンです。前回の実行以降にソースファイルが変更されておらず、ターゲットテーブルに読み込まれた行が残っている場合、ワークフローの実行ではダウンロードも含めてインポート全体をスキップします。空になったテーブルは再度インポートされます。

## ファイルを読み取れない場合

ステップは、処理を完了して空のテーブルを残すのではなく、読み取れなかったファイルとテーブルを示して失敗します。これは、PlaidCloudが読み取れるテーブルがファイルにない場合、テーブル名はあるものの列を記述できない場合、またはテーブルの行の読み取りに失敗した場合に発生します。リーダーが対応していない新しいバージョンのAccessで書き込まれたファイルが、よくある原因です。Accessからファイルを変換または再エクスポートして、インポートをもう一度実行してください。

すべてのテーブルが実際に空であるファイルは正常にインポートされ、レコードが読み込まれなかったという警告が報告されます。
