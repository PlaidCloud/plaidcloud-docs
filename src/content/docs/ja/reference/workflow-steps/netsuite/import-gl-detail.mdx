## 説明

[NetSuite 接続](/ja/guides/connections/netsuite/)を使用して、NetSuite の総勘定元帳のトランザクション明細の詳細をプロジェクトテーブルにインポートします。残高の基になる転記レベルの明細行で、照合、ドリルダウン、詳細な損益計算書に利用できます。接続を選択し、ターゲットテーブルの名前を指定して、期間と子会社を設定すると、ステップが明細行を取得して書き込みます。SuiteQL を作成したり保守したりする必要はありません。

これは、あらかじめ用意された [NetSuite インポートステップ](/ja/reference/workflow-steps/netsuite/)の 1 つです。いずれも共通の読み取りレイヤー上で動作し、OAuth トークンの更新、大きな結果のページング、一時的なエラーの再試行を自動的に行うため、全期間の取得でも、手動で調整することなく完全な結果が返されます。明細行ではなく期間残高が必要な場合は、[NetSuite: 残高のインポート](/ja/reference/workflow-steps/netsuite/import-balances/)を使用してください。

## 設定

| フィールド | 必須 | 備考 |
|---|---|---|
| NetSuite接続 | はい | 読み取りに使用する NetSuite 接続です。タイプが NetSuite の接続に絞り込まれます。 |
| ターゲットテーブル | はい | トランザクション明細行の書き込み先のプロジェクトテーブルです。実行のたびに全体が上書きされます。 |
| 開始日 | いいえ | 含める最も早いトランザクション日付（`YYYY-MM-DD`、この日を含む）。空白にすると下限なしになります。終了日と併せて指定すると、NetSuite の SuiteQL の行数上限を超えないよう、取得が自動的に日付単位のチャンクに分割されます。後述の注意を参照してください。 |
| 終了日 | いいえ | 含める最も遅いトランザクション日付（`YYYY-MM-DD`、この日を含む）。空白にすると上限なしになります。 |
| 子会社 | いいえ | 取得を 1 つの子会社に限定する場合の、NetSuite の子会社の内部 ID です。空白にすると全子会社が対象になります。 |
| 会計帳簿 | いいえ | NetSuite の会計帳簿の内部 ID です。空白にすると**プライマリ帳簿（内部 ID 1）のみ**を取得します。`all` と入力すると、すべての帳簿を合算します。 |
| 勘定科目番号 | いいえ | 取得を 1 つの勘定科目に限定する場合の、総勘定元帳の勘定科目番号（完全一致）です。空白にすると全勘定科目が対象になります。 |
| 転記期間 | いいえ | NetSuite の転記期間／会計期間の内部 ID です。空白にすると全期間が対象になります。 |

<Aside type="caution">
**複数帳簿の勘定科目：** 複数帳簿会計（Multi-Book Accounting）を使用している NetSuite アカウントでは、トランザクション明細ごとに帳簿ごとの行が 1 行ずつ転記されるため、フィルターなしですべての帳簿を取得すると、合計が帳簿の数だけ重複計上されます。会計帳簿を空白にすると**プライマリ帳簿のみ**を取得します。帳簿をまたぐ合計が必要な場合にのみ `all` を設定するか、特定の帳簿のみを対象にする場合はその帳簿の内部 ID を設定してください。
</Aside>

<Aside type="note">
期間は必要な範囲に絞り込んでください。実行のたびにターゲットテーブル全体が置き換えられるため、スケジュール実行の取得では毎回全結果が再抽出されます。ローリングの日付ウィンドウを使用すると、定期的な総勘定元帳の取得が、全履歴を毎回読み直すことなく高速になります。
</Aside>

<Aside type="note">
NetSuite の SuiteQL API は、SuiteAnalytics Connect を使用しない場合、1 回のクエリを約 100,000 行に制限します。開始日と終了日の両方を指定すると、PlaidCloud は取得をこの上限に収まるチャンクに事前に分割します。GL明細は上限に達しやすい取得であるため、残高のインポートよりもここで重要になります。**期間が開いた**取得が上限を超えた場合は、切り詰められた結果を黙って返すのではなく、日付範囲を追加するよう求めるメッセージとともに失敗します。
</Aside>
