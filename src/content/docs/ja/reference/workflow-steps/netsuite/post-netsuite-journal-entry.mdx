## 説明

[NetSuite 接続](/ja/guides/connections/netsuite/)を使用して、仕訳を NetSuite に転記します。このステップは、仕訳 1 件につき 1 行のヘッダーテーブルと、仕訳ごとに 1 行以上の借方／貸方の行を持つ明細テーブルという 2 つのソーステーブルを受け取り、明細を仕訳ごとにグループ化して、各仕訳を NetSuite に転記します。**テスト専用モード**では、NetSuite を呼び出すことなくすべての仕訳を作成して検証します。オプションの結果テーブルには、各仕訳の結果が記録されます。

<Aside type="caution">
このステップで本番の仕訳を無人で転記する前に、必ずすべてのバッチを**テスト専用モード**で実行して結果テーブルを確認し、いくつかの転記を NetSuite で直接照合してください。
</Aside>

## 設定

### 接続

- **NetSuite接続** — 転記に使用する NetSuite 接続です。タイプが NetSuite の接続に絞り込まれます。
- **環境** — 接続の環境です。

NetSuite 接続は **Tools > Connections** で管理します。詳しくは [NetSuite への接続](/ja/guides/connections/netsuite/)を参照してください。

### データ

- **仕訳エントリヘッダーテーブル** — 仕訳 1 件につき 1 行です。
- **仕訳エントリ明細行テーブル** — 仕訳ごとに 1 行以上の借方／貸方の行で、仕訳 ID によってヘッダーの行に関連付けられます。
- **テスト専用モード** — デフォルトでオンです。各仕訳を以下のチェックで検証しますが、NetSuite は呼び出さず、何も転記されません。実際に転記するにはオフにします。このフィールド自体が省略されたステップ設定（たとえば REST API、MCP、ワークフローバンドルのインポートで作成されたもの）も、本番転記ではなくテスト専用モードがデフォルトになります。
- **1 件の仕訳が失敗しても残りの仕訳の転記を続行する** — デフォルトでオンです。仕訳がチェックまたは転記自体に失敗した場合、PlaidCloud はその仕訳のエラーを記録し、バッチを停止せずに残りの処理に進みます。
- **非同期で送信** — デフォルトではオフです。同期的な作成と読み戻しの経路ではなく、NetSuite の非同期 `Prefer: respond-async` ヘッダーを付けて各仕訳を送信します。NetSuite がジョブをキューに入れ、PlaidCloud は完了を待たずに、送信参照とともにその仕訳を `pending` として記録します。これは接続ごとの選択です。特定の接続に対しては、混在させずにすべての実行で同じ設定を使用してください。**保留中の仕訳を自動的に解決する仕組みは現在ありません。ステップを再実行すると、仕訳を照会して最終結果が記録され、解決されます。** これをオンにする場合は、`pending` の行を完了済みとみなさず、ステップを再実行する（または NetSuite で直接確認する）ことを前提にしてください。
- **転記結果テーブル** — 任意です。設定すると、PlaidCloud が仕訳ごとに 1 行を書き込みます（上書き）。詳しくは[結果テーブルの列](#結果テーブルの列)を参照してください。

### ヘッダーマップ／ヘッダーフィルター

[標準のデータマッピングタブとフィルタータブ](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/)を使用して、ヘッダーテーブルの列を以下の仕訳フィールドにマッピングし、必要に応じて転記するヘッダー行をフィルターします。

| フィールド | 必須 | 備考 |
|---|---|---|
| 仕訳 ID | はい | ヘッダー行とその明細を関連付けます。一意の仕訳 ID ごとに 1 行です。 |
| 子会社 | はい | NetSuite の子会社の内部 ID です。 |
| 転記日 | はい | 仕訳のトランザクション日付です。 |
| 通貨 | いいえ | NetSuite の通貨の内部 ID です。 |
| メモ | いいえ | 仕訳レベルのメモです。 |
| 外部 ID | いいえ | PlaidCloud が仕訳に対して生成する決定論的な外部 ID を上書きします。[再転記と重複した仕訳](#再転記と重複した仕訳)を参照してください。 |

### 明細マップ／明細フィルター

明細テーブルの列をマッピングし、必要に応じて転記する明細行をフィルターします。

| フィールド | 必須 | 備考 |
|---|---|---|
| 仕訳 ID | はい | ヘッダー行の仕訳 ID と一致します。 |
| 勘定科目 | はい | NetSuite の総勘定元帳の勘定科目の内部 ID です。 |
| 借方 | はい | 借方金額です。貸方のみの行では 0 にします。 |
| 貸方 | はい | 貸方金額です。借方のみの行では 0 にします。 |
| メモ | いいえ | 明細レベルのメモです。 |
| 部門 | いいえ | NetSuite の部門の内部 ID です。 |
| クラス | いいえ | NetSuite のクラスの内部 ID です。 |
| 場所 | いいえ | NetSuite の場所の内部 ID です。 |
| エンティティ | いいえ | NetSuite のエンティティ（顧客または仕入先）の内部 ID です。 |

## 転記の仕組み

PlaidCloud は明細テーブルを仕訳 ID ごとにグループ化し、ヘッダーの行ごとに 1 件の NetSuite 仕訳を作成します。各仕訳を転記する前に（テスト専用モードでは、検証済みとして記録する前に）、PlaidCloud は次の点をチェックします。

- 仕訳に少なくとも 1 つの明細行がある
- 借方と貸方が 1 セント単位まで一致している
- すべての明細行に勘定科目がある
- ヘッダーの行に子会社がある
- 転記日が有効な日付である

いずれかのチェックに失敗すると、その仕訳のエラー行が記録され、**1 件の仕訳が失敗しても残りの仕訳の転記を続行する**がオフでない限り、バッチ内の次の仕訳に進みます。

### 再転記と重複した仕訳

各仕訳は、プロジェクト、接続、仕訳 ID、転記日、明細の金額から作成される決定論的な外部 ID を付けて転記されます。明細が変更されていない仕訳を再転記すると同じ外部 ID が再利用され、NetSuite 自体の外部 ID の処理によって、仕訳の重複作成が防がれます。仕訳の明細を変更すると（金額の変更や、明細行の追加または削除など）、PlaidCloud はその仕訳に新しい外部 ID を計算し、NetSuite は以前の仕訳の更新ではなく新しい仕訳として受け付けます。ID を自分で管理するには、ヘッダーテーブルの外部 ID 列に値を設定します。

<Aside type="caution">
再転記による重複排除は、NetSuite がすでに保有している仕訳と同一とみなされる仕訳にのみ有効です。仕訳の明細を編集してステップを再実行しても、NetSuite の元の転記は更新されず、2 件目の仕訳が作成されます。転記済みの仕訳を修正する場合は、データを変更してこのステップを再実行するのではなく、NetSuite で直接修正してください。
</Aside>

### 結果テーブルの列

| 列 | 説明 |
|---|---|
| journal_id | ヘッダーテーブルの仕訳 ID です。 |
| external_id | この転記の試行で使用された外部 ID です。 |
| internal_id | 作成された仕訳に対する NetSuite の内部 ID です。`pending` の間は非同期送信の参照です。テスト専用モードおよびエラー時は空白です。 |
| status | `validated`（テスト専用モード）、`posted`、`pending`（非同期で送信が仕訳を受け付けたが NetSuite がまだ確認していない状態）、または `error` のいずれかです。 |
| message | `error` の場合はエラーの詳細です。`pending` の場合は、ステップを再実行すると解決されることを示すメモです。`posted`／`validated` では空白です。 |
