## 説明


現在のプロジェクトのテーブルから、別のプロジェクトのテーブルにデータをコピーします。プロジェクト間で参照データを共有する場合、統合プロジェクトが複数の運用プロジェクトからデータを取得する場合、処理済みの結果を別のチームのプロジェクトに引き渡す場合などに便利です。

スキーマは、ソースとターゲットの間で互換性がある必要があります。ターゲットのプロジェクトは、このプロジェクトに**書き込み**のデータ共有を許可している必要があります。


## データ共有の管理

![データ共有の管理](/images/import_external_project_table_1.png)

別のプロジェクトにテーブルをエクスポートするには、事前に、そのプロジェクトがこのプロジェクトからの書き込みを許可している必要があります。**ターゲット**プロジェクトの**ホーム**タブを開き、**データ共有の管理**の下で**新規データ共有**をクリックして、このプロジェクトを選択し、**許可される操作**の下の**書き込み**にチェックを入れて、**データ共有を追加**をクリックします。[プロジェクト間でのデータ共有](/ja/guides/projects/managing-projects/#プロジェクト間でのデータ共有)を参照してください。

ステップはこのプロジェクト自身のIDで実行されるため、誰が開始しても、実行は共有を通じて動作します。

## 外部プロジェクトテーブルのエクスポート

![外部プロジェクトテーブルのエクスポート](/images/export_external_project_table.png)

### 読み取り元
ドロップダウンメニューから**ソーステーブル**を選択します。

<Aside type="note" title="空のソーステーブル">
ステップの実行時にソーステーブルに行がない場合、エクスポートは何事もなく成功したことにはならず、ソースが空であったことを示す警告とともに終了します。そのため、ターゲットが想定外に空になっていても気づきやすくなります。多くの場合、これはワークフローがまだそのテーブルを構築していないことを意味します。エクスポートの前に、ソースにデータが入っていること（スケジュール実行の場合は、先に実行される順序になっていること）を確認してください。
</Aside>

### 書き込み先

#### ターゲットプロジェクト
ドロップダウンメニューから**ターゲットプロジェクト**を選択します。

#### ターゲットテーブル（静的）

ターゲットテーブルを設定するには、**ターゲットテーブル**ドロップダウンから既存のテーブルを選択するか、緑色の **「+」** 記号をクリックして新しいテーブルをターゲットとして作成します。

##### テーブルの作成
新しいテーブルを作成するとき、**ビュー**または**テーブル**のどちらで作成するかを選択できます。
###### ビュー：
ビューは、テーブルを使用する場合と比べて、ステップの実行にかかる時間が大幅に短くなる点で便利です。短所は、テーブルの詳細モードでのデータ探索には向いていないことです。

###### テーブル：
ターゲットにテーブルを使用すると、ステップの実行には時間がかかりますが、詳細モードでのデータ探索は、ビューよりもはるかに高速です。

<Aside>データの検証やアドホックな分析が必要になる、ワークフローの重要なステップにはテーブルを使用してください。それ以外のステップには、ワークフロー全体の計算時間を短縮するため、ビューを使用してください。テーブルをビューに、またはその逆に変更することもできるため、ターゲットのタイプは後でいつでも更新できます。</Aside>

#### ターゲットテーブル（動的）

動的オプションでは、変数を含むテキストでテーブルを指定できます。これは、変数によって動作が決まるワークフローで、テーブルやビューの参照が指定した変数に応じて変わる場合に便利です。

`current_month` 変数を使用して、ターゲットテーブルを動的に指す例を示します。

```text
legal_entity/inputs/{current_month}/ledger_values
```

<Aside>テーブルが存在しない場合は、インポート処理の実行時に動的に作成されます</Aside>

#### 既存のデータに追加

ソーステーブルのデータをターゲットテーブルに追加するには、***既存のデータに追加***チェックボックスをオンにします。
