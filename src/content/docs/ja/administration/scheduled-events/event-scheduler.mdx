## 説明


特定のワークフローをスケジュールすることは、業務を整理するのに役立つため、PlaidCloud にはその機能が用意されています。イベントスケジューラーを使用すると、月、日、曜日、時、分を指定して、ワークフローの実行をスケジュールできます。スケジュールを読み取るタイムゾーンも自由に選択できます。



スケジュールされたイベントは、1 つのプロジェクト内の 1 つのワークフローと、その実行スケジュールを指定します。同じ頻度で複数のワークフローを実行するには、ワークフローごとにイベントを追加します。



イベントテーブルには、ワークスペース内のすべてのイベントが一覧表示されます。実行するプロジェクトとワークフロー、UTC オフセット、前回の実行のステータスと開始時刻および終了時刻、次回の実行予定が確認できます。



**イベントを表示するには、次の手順に従います。**


1. Analyze を開きます
2. 「Tools」を選択します
3. 「イベントスケジューラー」をクリックします

ワークスペースに構成されているすべての現在のイベントを示す**イベントテーブル**が開きます。

<Aside>イベントがアクティブな場合は、「アクティブ」アイコンが表示されます。</Aside>

## イベントの作成


**イベントを作成するには、次の手順に従います。**


1. Analyze を開きます
2. 「Tools」を選択します
3. 「イベントスケジューラー」をクリックします
4. 「Add Scheduled Event」をクリックします
5. 以下で説明する詳細、タイムゾーン、スケジュールのフィールドに入力します
6. 「Create」をクリックします

### 詳細


**名前** — イベントテーブルに表示されるイベントの名前です。必須です。



**メモ** — イベントの目的に関する任意のメモです。



**ジョブを有効化し、定義済みスケジュールで実行** — デフォルトでオンになっています。オフにすると、イベントを実行させずに保存できます。[イベントの一時停止](#イベントの一時停止)を参照してください。



**プロジェクト**と**ワークフロー** — このイベントが実行するワークフローです。最初にプロジェクトを選択します。ワークフローの一覧は、選択したプロジェクトに基づいて表示されます。どちらも必須で、イベントの作成後は変更できません。イベントを別のワークフローに移すには、削除して新しいイベントを追加します。



### タイムゾーン


スケジュールは、このタイムゾーンで読み取られます。**UTC -12** から **UTC +14** までのオフセットで選択します。デフォルトは **UTC +0** で、夏時間（英国夏時間）を含むロンドン時間として読み取られます。



ほとんどのオフセットは、そのオフセットにある地域の現地時間で、その地域の夏時間に従います。たとえば、**UTC -5** で 09:00 に設定したイベントは、夏も冬もニューヨークの 09:00 に実行されます。これは、夏は 13:00 UTC、冬は 14:00 UTC です。**次回実行**列と[今後の実行カレンダー](/ja/administration/scheduled-events/upcoming-runs-calendar/)で、イベントが実際に実行される時刻を確認できます。

### スケジュール


スケジュールは、**月**、**時間**、**分**、**日(月)**、**曜日**の 5 つのフィールドで構成され、それぞれ上部に**すべて**ボックスがあるチェックボックスの一覧になっています。現在時刻が、すべてのフィールドでチェックした値に同時に一致するたびに、イベントが実行されます。



すべてのフィールドに値が必要です。すべての値に一致させるには**すべて**にチェックを入れ、特定の値を指定するには個々の値にチェックを入れます。空白のままのフィールドがあると、イベントを保存できず、該当するフィールドを示すメッセージが表示されます。



例をいくつか示します。


- **毎日 06:30** — 月、日(月)、曜日はすべて**すべて**、時間は **06**、分は **30**。
- **毎月 1 日の午前 0 時** — 月と曜日は**すべて**、日(月)は **01**、時間と分は **00**。
- **毎週平日の 18:00** — 月と日(月)は**すべて**、曜日は月曜日から金曜日、時間は **18**、分は **00**。
- **15 分ごと** — 月、日(月)、曜日、時間は**すべて**、分は **00**、**15**、**30**、**45**。

<Aside>新しいイベントは何もチェックされていない状態で始まるため、スケジュールを選択するまで実行されません。</Aside>


### ERP転記モード

各イベントは、それぞれ独自の [ERP 転記モード](/ja/guides/workflows/run-a-workflow/#転記モードの選択)（**本番**、**シミュレート**、**オフ**）を持ち、イベントが開始するすべての実行でそのモードが使用されます。モードが設定されていないイベントは本番で実行されます。さらにプロジェクト自体の転記モードの上限も適用されるため、イベントがプロジェクトで許可されている以上に自由に転記することはありません。

モードは、API または AI アシスタントで設定します。`PUT /rest/v1/analyze/workflow/scheduled-event` の `erp_write_mode` フィールド（`live`、`simulate`、`off`）、または `workflow_schedule` MCP ツールのアップサートで指定します。イベントはその後もそのモードを保持します。イベントスケジューラーでのイベントの編集、一時停止、再有効化では、モードは変更されません。そのため、シミュレートに設定されたスケジュールは、モード自体を変更するまで、起動のたびにシミュレートされたままになります。

## イベントの編集


**イベントを編集するには、次の手順に従います。**


1. Analyze を開きます
2. 「Tools」を選択します
3. 「イベントスケジューラー」をクリックします
4. 編集アイコンをクリックします
5. 必要に応じてフィールドを調整します
6. 「更新」をクリックします

編集中は、プロジェクトとワークフローが読み取り専用で表示されます。イベントは、作成時に指定したワークフローに関連付けられたままになります。

AI アシスタントは、`workflow_schedule` MCP ツールを通じて、新しい名前やスケジュールなど、変更するフィールドだけを送信してイベントを編集できます。省略したフィールドは、現在の値のまま保持されます。

## イベントの削除


**イベントを削除するには、次の手順に従います。**


1. Analyze を開きます
2. 「Tools」を選択します
3. 「イベントスケジューラー」をクリックします
4. 削除アイコンをクリックします
5. もう一度削除をクリックします

<Aside type="note">
ワークフローを削除すると、そのワークフローに対してスケジュールされたすべてのイベントも削除されます。先にイベントを削除する必要はなく、存在しなくなったワークフローを実行しようとするイベントが残ることもありません。他のワークフローに対してスケジュールされたイベントには影響しません。
</Aside>

## イベントの一時停止


**1 つ以上のイベントを一時停止するには、次の手順に従います。**


1. Analyze を開きます
2. 「Tools」を選択します
3. 「イベントスケジューラー」をクリックします
4. 1 つまたは複数のイベントを選択します
5. 「Disable Selected」をクリックします

再び実行を開始するには、**選択を有効化**をクリックします。一時停止されたイベントはスケジュールと実行履歴を保持します。再び有効にするまで起動が停止するだけで、イベントテーブルの**アクティブ**アイコンが消えます。



イベントの編集中に、1 つのイベントだけを一時停止することもできます。**ジョブを有効化し、定義済みスケジュールで実行**のチェックを外し、**更新**をクリックします。



## イベントのオンデマンド実行


**イベントをすぐに実行するには、次の手順に従います。**


1. Analyze を開きます
2. 「Tools」を選択します
3. 「イベントスケジューラー」をクリックします
4. 実行するイベントを 1 つまたは複数選択します
5. 「Run Selected Events」をクリックします

各イベントは、それぞれ独自の [ERP 転記モード](#erp転記モード)で実行されるため、シミュレートのイベントはシミュレートとして実行されます。ワークフローがすでに実行中のイベントはスキップされ、実行後のメッセージには、開始されたイベントだけが数えられます。
