**Workspaces** ページには、管理できる PlaidCloud ワークスペースが一覧表示されます。このページから、ワークスペースの作成、ワークスペース設定の編集、ワークスペースの起動、ダッシュボードの起動、SQL コンソールの起動、ログとメトリックの表示、選択した複数のワークスペースへの一括操作を行えます。

<Aside type="caution">
	削除すると、ワークスペースと関連するデータが削除されます。ワークスペースを削除する前に、バックアップと保持要件を確認してください。
</Aside>

## ワークスペースの一覧

ワークスペースのテーブルには、名前、一意の ID、バージョン、リリースチャネル、ステータス、一時停止の状態、作成日、プロビジョニングの状態、クラスター、メンテナンスの曜日、メンテナンスの時刻が含まれます。テーブルでは、検索、更新、行ごとの操作、一括操作を利用できます。

利用できる行ごとの操作は次のとおりです。

| 操作 | 説明 |
| --- | --- |
| 表示 | 読み取り専用のワークスペースの詳細を開きます。 |
| 編集 | ワークスペースの構成を変更します。 |
| 削除 | ワークスペースを削除します。 |
| ホーム | ワークスペースのアプリケーションを開きます。 |
| ダッシュボード | ワークスペースのダッシュボードサービスを開きます。 |
| SQL | ワークスペースの SQL コンソールを開きます。 |
| ログとメトリック | ワークスペースの運用ログとメトリックを開きます。 |

ホーム、ダッシュボード、SQL、ログとメトリックの 4 つのサービス操作は、実行中のワークスペースにのみ、そのワークスペースで有効になっているサービスに限って表示されます。作成中のワークスペースにはサービスアイコンがまったく表示されないため、クリックしても何も起こらないリンクはありません。

## プロビジョニングの状況

ワークスペースの作成には数分かかり、完了するまでは、ワークスペースは存在していても開くことはできません。**作成日時**、**ステータス**、**Provisioning** の各列で、どこまで進んでいるかを確認できます。ワークスペースの詳細ダイアログの **Provisioning** タブには、1 つのワークスペースについて同じ情報と、現在公開されているサービス URL が表示されます。

| 列 | わかること |
| --- | --- |
| 作成日時 | ワークスペースのレコードが作成された日時。最初のプロビジョニングが開始された日時でもあります。 |
| ステータス | プロビジョニングの現在のフェーズ（`activating` など）。完了したワークスペースは `running` と表示されます。 |
| プロビジョニング | フェーズを 1 語にまとめたもの。`provisioning`、`running`、`failed`、`paused`、`trashed`、`deleting` のいずれかです。 |

同じフェーズに約 30 分以上とどまっているワークスペースは停滞しており、`failed` と表示されているワークスペースは停止しています。いずれの場合も、ワークスペース ID と表示されているフェーズを添えて、PlaidCloud サポートにお問い合わせください。失敗の詳細には PlaidCloud の内部コンポーネント名が含まれるため、ここには表示されず、PlaidAdmin 領域で管理されています。

<Aside type="note">
	デプロイメントツール上ではワークスペースが正常に見えても、使用できない場合があります。デプロイメントの完了は、ワークスペース自身のセットアップの完了とは異なるためです。**Provisioning** 列には、ワークスペース自身のセットアップの状況が表示されます。サインインできるかどうかを決めるのは、こちらです。
</Aside>

## シングルサインオン

別の PlaidCloud パスワードの代わりに、会社の ID プロバイダーでワークスペースにサインインできるようにします。**Workspaces** ページで、ワークスペースの **Single sign-on** を選択します。ダイアログには、現在の **Sign-in options** が、それぞれの状態（**有効**または**オフ**）、**Test sign-in**、**削除**とともに一覧表示され、**Add an identity provider** の下で新しいオプションを追加できます。

### プランとサインイン方法

Free（Sandbox）を含むすべてのプランに、多要素認証（MFA）付きのパスワードサインインと、Google、Microsoft（個人アカウントまたは組織の「common」サインイン）、GitHub によるソーシャルサインインが含まれます。上位のプランでは、独自の ID プロバイダーを使用するエンタープライズ向けシングルサインオンが追加されます。

| プラン | 追加される機能 |
| --- | --- |
| Free（Sandbox） | すべてのプランに含まれるサインイン方法のみ |
| Starter | すべてのプランに含まれるサインイン方法のみ |
| Team | SAML |
| Business | Microsoft Entra ID と Okta |
| Enterprise | その他の OpenID Connect プロバイダーと SCIM |

各プランには、それより下位のプランのすべての機能が含まれます。Free（Sandbox）と Starter では、**Single sign-on** ダイアログに、ID プロバイダーの選択肢の代わりにアップグレードを案内するメモが表示されます。

ダウングレードした場合、すでに追加したプロバイダーは一覧に残り、引き続き削除できますが、そのプランに含まれない新しいプロバイダーは追加できません。

### ID プロバイダーの追加

1. **Identity provider** を選択します。プランで許可されている **Microsoft Entra ID**、**Okta**、**Other (OpenID Connect)** から選びます。
2. **Redirect URI** を**コピー**し、以下の説明に従って ID プロバイダーに登録します。
3. プロバイダーに応じたフィールドに入力し、**Add provider** を選択します。
4. **Test sign-in** を選択すると、ワークスペースが開き、プライベートウィンドウで新しいプロバイダーを通じたサインインを試せます。チームに知らせる前にテストしてください。

| プロバイダー | ID プロバイダーでの登録内容 | PlaidCloud に入力する項目 |
|---|---|---|
| Microsoft Entra ID | Microsoft Entra 管理センターで、リダイレクト URI を指定してアプリ（Web プラットフォーム）を登録し、**Certificates & secrets** でクライアントシークレットを追加し、**Token configuration** で ID トークンに任意の `email` クレームを追加します。 | **Directory (tenant) ID**、**クライアントID**、**クライアントシークレット** |
| Okta | Okta 管理コンソールで、リダイレクト URI をサインインリダイレクト URI として指定した OIDC Web アプリケーションを作成し、アクセスを許可するユーザーを割り当てます。 | **Okta domain**（例: `acme.okta.com`）、**クライアントID**、**クライアントシークレット** |
| Other (OpenID Connect) | リダイレクト URI を指定して、機密 Web クライアントを登録します。 | **Button label**、**Discovery URL**、**クライアントID**、**クライアントシークレット** |

**Other (OpenID Connect)** の場合、PlaidCloud はディスカバリー URL からエンドポイントを読み取ります。そこから構成を読み取れない場合や、発行者がディスカバリー URL とは別のサイトにある場合は、**Enter endpoints manually** を選択し、**Issuer**、**Authorization URL**、**Token URL**、**JWKS URL**、必要に応じて **Userinfo URL (optional)** を入力します。プロバイダーのアドレスは、PlaidCloud が到達できるパブリックホストである必要があります。

**Button label** は、サインインページに表示される名前です（例: *Acme SSO*）。

### 既存のアカウントとメールアドレスの確認

- 同じメールアドレスの PlaidCloud アカウントをすでに持っているユーザーは、そのアカウントに一度サインインすることで、アカウントを関連付けられます。PlaidCloud が、メールアドレスの一致だけを根拠にアカウントを関連付けることはありません。
- **Trust email addresses from this provider (new people skip email verification)** はデフォルトでオフです。新しいユーザーは、初回サインイン時にメールアドレスを確認します。オンにするのは、ID プロバイダーが送信するアドレスを保証している場合に限ってください。

### ID プロバイダーの削除

プロバイダーの横にある**削除**を選択します。以降、そのプロバイダーではサインインできなくなります。ユーザーがすでに持っているアカウントは残り、パスワードをリセットしてサインインできます。

## 一括操作

1 つ以上のワークスペースを選択すると、一括操作を利用できます。

| 一括操作 | 説明 |
| --- | --- |
| バージョンを設定 | 選択したワークスペースを、指定したバージョンに固定します。選択したすべてのワークスペースが、同じリリースチャネルを使用している必要があります。 |
| 一時停止 | 選択したワークスペースを一時停止します。 |
| 再開 | 一時停止中の、選択したワークスペースを復元します。 |

## 基本設定

基本設定では、ワークスペースの識別、オーナーの割り当て、リリース動作の制御を行います。

| 設定 | 説明 |
| --- | --- |
| 名前 | ワークスペースの表示名。 |
| ID | ワークスペースの一意の識別子。ワークスペースの ID の一部となり、作成時に設定されます。 |
| メモ | 任意の説明または管理用のメモ。 |
| 組織 | ワークスペースを所有する組織。 |
| オーナー | ワークスペースのオーナーのメールアドレス。 |
| データセンター（クラスター） | ワークスペースが稼働するデータセンターまたはクラスター。 |
| リリース | リリースチャネル（Rapid、Regular、Stable、No Release（固定））。 |
| バージョン | デプロイされている特定のバージョン。 |
| 有効 | ワークスペースを有効としてマークします。 |
| 一時停止 | ワークスペースを削除せずに、稼働を一時停止します。 |
| 招待リンクの有効期間 | 新規ユーザー向けの招待リンクが有効な期間。選択肢は 12 時間、1 日、2 日、3 日、5 日、7 日、10 日、14 日です。 |

## リリースオプション

| リリース | 一般的な用途 |
| --- | --- |
| Rapid | 最も早く更新を受け取ります。製品の変更をより早く受け入れられるワークスペースに使用します。 |
| Regular | ほとんどのワークスペースのデフォルトの更新頻度です。 |
| Stable | 更新の安定性を優先するワークスペース向けの、より緩やかな頻度です。 |
| No Release（固定） | 管理者が変更するまで、ワークスペースを選択したバージョンのままにします。 |

メンテナンスウィンドウによって、自動リリース更新が適用される時期が決まります。

## 自動リリース更新

PlaidCloud は新しいリリースを継続的に公開し、ワークスペースへ自動的に配信します。更新をリクエストしたりインストールしたりする必要はありません。リリースがワークスペースのリリースチャネルに到達すると、PlaidCloud はメンテナンスウィンドウ中にワークスペースをアップグレードします。リリースチャネルはリリースが届く速さを決め、メンテナンスウィンドウはアップグレードが行われる時間帯を決めます。

### リリースがワークスペースに届くまで

1. PlaidCloud がリリースをチャネルに公開します。最初に Rapid、次に Regular、最後に Stable が受け取ります。
2. 組織内のすべてのユーザーに、アップグレードの少なくとも 7 日前に、リリースと適用日を記載した事前通知メールが届きます。
3. その通知後、ワークスペースの最初のメンテナンスウィンドウで、PlaidCloud がワークスペースをそのリリースにアップグレードします。デフォルトのメンテナンスウィンドウは日曜日の 02:00 UTC です。曜日と時刻は[メンテナンス](#メンテナンス)で設定します。
4. ワークスペースの**バージョン**が新しいリリースに更新されます。ユーザーやワークスペースの利用者による操作は必要ありません。

ワークスペースは自身のメンテナンスウィンドウ内でのみアップグレードされるため、更新は予測可能でトラフィックの少ない時間帯に適用されます。7 日前の通知により、すべての組織が変更に備える時間を確保できます。

### ワークスペースを固定してオプトアウトする

ワークスペースを現在のバージョンに維持するには、その**リリース**チャネルを **No Release (pinned)** に設定します。自動アップグレードは固定されたワークスペースをスキップし、管理者が新しいバージョンを選択するか、チャネルに戻すまで、選択したバージョンのままになります。検証サイクルや規制対象の決算期間中など、ワークスペースを固定しておく必要がある場合は、固定してください。

固定すると、今後のアップグレードが停止するだけで、すでに適用されたアップグレードは元に戻りません。固定されたワークスペースを再び先に進めるには、特定の**バージョン**を選択するか、Rapid、Regular、Stable のいずれかのチャネルを選択します。そうすると、ワークスペースは自動スケジュールに復帰します。

## テーマ設定

テーマ設定では、ワークスペースの各入口でのブランディングをカスタマイズします。

| 設定 | 説明 |
| --- | --- |
| アプリのロゴ | ワークスペースのアプリケーションに表示されるロゴ。 |
| スプラッシュ画面のロゴ | ワークスペースのスプラッシュ画面またはサインイン画面に表示されるロゴ。 |
| Superset のロゴ | ダッシュボードサービスに表示されるロゴ。 |
| Superset のカスタムテーマ | ワークスペースで利用できるダッシュボードのカスタムカラーテーマ。 |

## サービス

サービス設定では、ワークスペース内で任意のアプリケーションと補助サービスを有効にします。

| 設定 | 説明 |
| --- | --- |
| JupyterHub | ワークスペースのユーザー向けに、ホスト型のノートブックアクセスを有効にします。 |
| Web SQL コンソール（CloudBeaver） | ブラウザーベースの SQL アクセスを有効にします。 |
| ダッシュボード（Apache Superset） | ダッシュボードサービスを有効にします。 |
| ユーザーフォームとワークフロー（Forms Flow） | フォームとワークフローアプリのサポートを有効にします。 |
| 変更データキャプチャ（Apache Flink） | 変更データキャプチャ処理を有効にします。 |
| SFTP アクセスと Web UI | SFTP アクセスと SFTP の Web インターフェースを有効にします。 |
| PlaidCloud プロキシダウンロードを使用 | ダウンロードを PlaidCloud プロキシ経由にします。 |
| ベクターデータベース（Weaviate）を有効化 | ベクターデータベースのサポートを有効にします。 |
| カスタムアプリサンドボックスを有効化 | カスタムアプリのサンドボックスのサポートを有効にします。 |
| プロジェクト管理アプリを有効化 | プロジェクト管理アプリケーションを有効にします。 |

一部のサービスは、ユーザーが使用できるようになる前に、コントロールプレーンのフォームの外で追加のプロビジョニングが必要になる場合があります。

## Lakehouse

Lakehouse 設定では、外部データベース接続と追加のデータベースユーザーを制御します。

| 設定 | 説明 |
| --- | --- |
| 外部データベースアクセスを有効化 | 外部クライアントがワークスペースの Lakehouse に接続できるようにします。 |
| 許可する CIDR | 接続を許可する CIDR 範囲をカンマ区切りで指定します。許可リストが不要な場合は空白のままにします。 |
| 拒否する CIDR | 接続を拒否する CIDR 範囲をカンマ区切りで指定します。 |
| 追加の Lakehouse ユーザー | データベースアクセス用の、追加の Lakehouse のユーザー名とパスワード。 |

ユーザーや連携に対応できる範囲で、できるだけ狭い CIDR 範囲を使用してください。アクセスが不要になった Lakehouse ユーザーは削除してください。

## メンテナンス

メンテナンス設定では、ワークスペースで希望する更新ウィンドウを定義します。

| 設定 | 説明 |
| --- | --- |
| 曜日 | メンテナンスを行う曜日（日曜日から土曜日）。 |
| 時刻 | 1 日の時刻（15 分刻み）。 |

リリースチャネルのアップグレードには、ワークスペースのメンテナンスウィンドウが使用されます。固定されたワークスペースは、管理者が新しいバージョンまたはチャネルを選択するまで、リリースチャネルの自動アップグレードの対象外となります。
