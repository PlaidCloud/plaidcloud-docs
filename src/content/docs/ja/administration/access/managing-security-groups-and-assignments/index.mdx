PlaidCloudのセキュリティとアクセス管理はシンプルです。メンバーは、所属するグループに基づいてアクセスが許可または拒否されます。メンバーのセキュリティの関連付けは、簡単に追加や変更ができます。

<Aside>各ワークスペースで作成できるセキュリティグループの数に上限はありませんが、セキュリティ管理を容易にするため、数を最小限に抑えることをお勧めします。</Aside>



## セキュリティグループの管理


セキュリティグループは、追加、更新、削除ができます。



**セキュリティグループを管理するには：**


1. 「Identity」を開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューの「セキュリティグループ」をクリックします（既存のグループを表示するフォームが開きます）
4. グループを追加するには、「Create Security Group」をクリックします
5. グループの権限を編集するには、左端のアイコンをクリックします

**グループのメンバーを管理するには：**


1. 「Identity」を開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューの「セキュリティグループ」をクリックします
4. メンバーアイコンをクリックします
5. 追加したいメンバーを「Unassigned Members」列から「Assigned Members」列にドラッグします。メンバーを削除するには、逆方向にドラッグします

<Aside>「Assigned Members」列を空にして保存しても何も変更されず、その旨が表示されます。グループを全員から外すには、メンバーシップを空にするのではなく、グループの権限を削除するか、グループを削除してください。</Aside>

<Aside>グループに[行アクセス](#行アクセスの管理)で行が付与されている場合、メンバーシップの変更は約1分以内にダッシュボードへ反映されます。追加したユーザーはダッシュボードでそのグループの行を表示できるようになり、削除したユーザーは表示できなくなります。メンバーの無効化や削除、グループの削除も同様に反映されます。</Aside>

<Aside type="caution">自分で付与できない権限は、グループの権限マトリックスを保存しても変更されず、マトリックスにも表示されません。変更が必要な場合は、その権限を持つユーザーに依頼してください。マトリックスで編集できるのは、自分が管理できる権限だけです。</Aside>

## 行アクセスの管理

行アクセスは、1つの列の値に基づいて、セキュリティグループがテーブルのどの行を表示できるかを制限します。たとえば、`region`列で制限を設定し、`East`と`Central`が付与されたグループは、それらの値を持つ行のみに限定できます。プロジェクトと列に関するすべての操作（列の選択、値のソースの選択、どのグループに何を表示するかの決定）は1つの画面で行え、保存するとすぐに有効になります。

行アクセスの設定と変更には、プロジェクトのアーキテクトまたはテナント管理者の権限が必要です。それ以外のユーザーがプロジェクトの「Security」タブを開くと、行アクセスはアーキテクト専用であることが表示され、以下の入り口は表示されません。

### 行アクセスを開く

どの入り口からでも、同じ行アクセス画面が開きます。

- **テーブルエクスプローラー**のツールバーには**行アクセス**ボタンがあり、テーブルがすでに行を制限している場合はバッジが表示されます。テーブルに制限された列がある場合は最初の制限列で開き、テーブルの他の任意の列に切り替えることもできます。
- **列のファセットメニュー**には**この列で行を制限…** という項目があり、その列で行アクセスを開きます。すでに行を制限している列では、この項目は**この列で行を制限中 - 編集…** と表示されます。
- **プロジェクトの「Security」タブ**には、プロジェクトで制限されているすべての列が、適用先のテーブル、付与を持つグループ、**同期**の状態とともに一覧表示されます。列を選択して編集するか、**列を制限…** ボタンをクリックして新しく開始します。テーブルを選び、次に列を選びます。すでに行を制限している列にはロックのマークが付きます。
- **Identity → Member**のメンバーの**行アクセス**タブと、**Identity → Security → セキュリティグループ**のグループの行アクセスの概要です。**行アクセスを開く**（または**編集**）で選択した列が開き、**追加**でその行のプロジェクト内の別の列を制限します。

列を指定して開いた場合、画面はその列のままです。**列を制限…** ボタンまたは**追加**から開いた場合は、列を選択できます。

### 行アクセスのグリッド

列でテーブルを制限するには、次の手順に従います。

1. 上記のいずれかの入り口から行アクセスを開きます。列を指定せずに開いた場合は列を選択します。ピッカーには自由入力ではなく、テーブルの実際の列が表示されます。
2. **値のソース**を選択します。**列**（テーブルの列の異なる値）、**ディメンション**（ディメンションのノード）、**リスト**（入力した値）から選べます。値の型は列のデータ型に従います。
3. セキュリティグループごとに、そのグループが表示できる値をオンにします。グリッドには、プロジェクトにアクセスできるグループと、その列にすでに付与を持つグループが一覧表示されます。
4. **Everyone else**を**sees all rows**または**sees no rows**に設定します。これは、グリッドで何もオンになっていないすべてのグループに適用されます。
5. **保存**をクリックします。

保存はすぐに反映されます。PlaidCloud自身のクエリには即座に、Supersetダッシュボードには約1分以内に変更が反映され、適用のための別の手順や承認ダイアログはありません。画面の同期ステータスには、変更がどこまで進んだかが表示されます。詳しくは[ダッシュボードとの同期の維持](#ダッシュボードとの同期の維持)をご覧ください。

グリッドは、次の細かな点も自動で処理します。

- **値が多い場合。** 値は並べ替えられます。列の値が表示しきれない数ある場合、グリッドに「ここに収まりきらない数の値があります — 入力して検索してください。」と表示され、フィルターボックスで列全体を検索できます。グループがすでに持っている値は、すべて保持されます。
- **空白の値。** **空白の値 — 付与のあるすべてのグループに表示**というチェックボックス1つで、列に値がない行の扱いが決まります。オンにすると、その列に付与を持つすべてのグループがそれらの行を表示できます。
- **まだ構築されていないテーブル**では、空のリストの代わりに**先にこのテーブルを構築してください（作成するワークフローを実行します）** と表示されます。
- **保存は、画面上の値の読み込みを待ちます。** 値のソース、ディメンション、テーブルを切り替えた後やテンプレートを適用した後など、値の読み込み中は**保存**が無効になり、「このソースの値が読み込まれると保存できます。」というツールチップが表示されます。読み込みに失敗した場合は、グリッドにその旨が表示され、ソースの再選択を求められます。読み込みに成功するまで、何も保存されません。

### 1つの列名がすべてのテーブルに適用される

制限は、1つのテーブルではなく、プロジェクト内の列の*名前*に対して設定されます。`region`で行を制限すると、プロジェクト内で`region`という名前の列を持つすべてのテーブルが、PlaidCloud自身のクエリでもダッシュボードでも、その制限でフィルターされます。グリッドの**Applies to**リストには、それらのテーブルが表示されます。このリストは列名によって決まるため読み取り専用です。後から同じ名前の列を持つテーブルを追加した場合も、公開された時点で制限の対象になります。

プロジェクト内にその名前の列を持つテーブルが1つもない場合、ウィンドウには**Applies to 0 tables**の表示に加えて、テーブルができるまでその制限がどのダッシュボードもフィルターしないという警告が表示されます。テーブルに列を追加するか、列名を修正すると、警告は消えます。

<Aside type="caution">
**列名は、大文字と小文字、空白も含めて完全に一致する必要があります。** `Region`と`region`は別の名前であり、`region`と末尾に空白のある`region `も別の名前です。ピッカーには実在する列名しか表示されないため、主に他の場所で列名が変更された場合に問題になります。その場合、行アクセスは何も制限しないまま黙っているのではなく、警告を表示し、最も近い列の名前を示します。
</Aside>

<Aside type="caution">
**行を制限するテーブルを公開すると、同じ手順でそのダッシュボードフィルターも設定されます。** ダッシュボードはテーブルを公開済みのレポートビュー経由で読み取るため、制限された列を持つテーブルを公開または再公開すると、公開が完了する前に、PlaidCloudがそのテーブルのダッシュボードフィルターを登録します。登録できない場合は公開が拒否され、その試行で作成されたものはすべてロールバックされるため、制限されたテーブルがフィルターなしのままダッシュボードに残ることはありません。ビューのクエリは制限された列の名前を変更したり派生させたりできるため、行を制限するプロジェクトでは*ビュー*を公開できません。[テーブルの公開](/ja/guides/data/publish/)をご覧ください。
</Aside>

### 制限の解除

グリッドの**制限を解除**は、インラインの確認の後で制限を削除します。確認メッセージは「‘region’による行の制限を解除しますか？すべてのグループの付与が削除され、全員がその行を表示できるようになります。」です。その後、行アクセスに「‘region’の行はもう制限されていません。」と表示されます。その列のSupersetデータセットも一緒に削除されますが、チャートがまだ使用している場合は削除されません。その場合、行アクセスはデータセットが残ることと、使用しているチャートの数を表示します。

行を制限している列は、名前の変更や削除ができません。アーキテクトには、先に行アクセスで制限を解除するよう通知されます。それ以外のユーザーには、プロジェクトのアーキテクトに依頼するよう通知されます。

### 行を制限するプロジェクトを変更できるユーザー

プロジェクトのワークフロー、ステップ、ユーザー定義関数は、すべての行を読み取れるプロジェクト自身のサービスIDとして実行されます。それらを変更できるユーザーは、付与されていない行を、自分が読み取れるテーブルにコピーするステップを作成できてしまいます。そのため、プロジェクトで行を制限すると、プロジェクトの動作を変更できるユーザーも制限されます。プロジェクトで少なくとも1つの列が制限されると、次のようになります。

- **自動化はアーキテクト専用になります。** ワークフロー、ステップ、ユーザー定義関数、スケジュール、ワークフロー変数とプロジェクト変数、通知メールテンプレートを変更できるのは、プロジェクトのアーキテクトとテナント管理者だけです。同じ理由で、ワークフローバンドルのインポート、Alteryxワークフローの変換、プロジェクトへのインポート、コピー、復元、プロジェクトの接続環境、デフォルトのドキュメントアカウント、ERP転記モードの変更も同様です。それ以外のユーザーも、プロジェクトのワークフローを実行することはできます。**開始**、**停止**、**再開**、**選択したステップを実行**は引き続き利用できます。ステップエディター、ワークフローの作成コントロール、UDFエディター、スケジュールフォームは、これらのユーザーには読み取り専用で開き、依頼先のアーキテクトを示すバナーが表示されます。「このプロジェクトは行を制限しているため、ワークフロー、ステップ、UDF、スケジュール、変数、通知テンプレートを変更できるのはアーキテクトのみです。実行することは引き続き可能です。」
- **制限された列が読み取るディメンションはアーキテクト専用になります。** どのユーザーがどの行を表示できるかを決めるディメンション、つまり制限された列の値のソースは、プロジェクトのアーキテクトまたはテナント管理者と、プロジェクト自身のワークフローだけが変更できます。ノードの追加、移動、名前の変更、コピー、クリア、読み込み、復元と、ディメンション自体の変更が対象です。それ以外のユーザーには、「このディメンションは‘region’のどのユーザーがどの行を表示できるかを決めるため、変更できるのはプロジェクトのアーキテクトのみです。」と通知されます。どの制限にも読み取られていないディメンションには影響しません。
- **付与のソーステーブルはアーキテクト専用になります。** 列の[付与のソース](#付与のソーステーブルへのバインド)としてバインドされたテーブルの行の変更や削除ができるのは、プロジェクトのアーキテクト、テナント管理者、またはプロジェクトのワークフローだけです。データエディター、インポート、コネクターの読み込み、APIのいずれを通じた場合も同様です。
- **プロジェクトのコピーもアーキテクト専用です。** コピーには「このコピーには行の制限がありません。」と表示され、新しいプロジェクトには、設定するまで制限が引き継がれません。
- **以前のバージョンの復元も、他の変更と同じ扱いです。** プロジェクト自身の設定や上記のディメンションを復元するには、プロジェクトのアーキテクトが必要です。復元は常にそのバージョンが属する項目に適用されるため、この制限を回避するために別のプロジェクトを指定することはできません。[バージョン履歴](/ja/guides/projects/managing-projects/#バージョン履歴)をご覧ください。
- **制限されたテーブルのデータの編集**には、[行アクセスとデータエディター](#行アクセスとデータエディター)で説明するとおり、アーキテクトが必要です。

プロジェクトで最初の列を制限する前に、行アクセスは影響を受けるユーザーを通知します。「ここで行を制限すると、このプロジェクトのワークフロー、ステップ、UDF、スケジュール、通知テンプレートを変更できるのはアーキテクトのみになります。現在N人のメンバーがこれらを変更できますが、今後も実行は可能です。」

実行は、スケジュールされたものも含め、プロジェクトのサービスIDとして実行されるため、これまでと同じように動作します。実行の結果は、アーキテクトがその実行に与えた設計に従います。制限された列を含まない出力テーブル、エクスポートファイル、通知メール、ログの行は、それを読むユーザーに対してフィルターされません。

**実行の開始時に指定される値。** ワークフローを実行できるユーザーは、そのワークフローの変数に独自の値を指定して開始できます。[App Runner](/ja/guides/workflows/use-converted-alteryx-apps/#app-runnerフロントエンド)はフォームの回答でこれを行い、APIやAIツールでも可能です。これらの値はその実行に限り有効で、ワークフローに保存されることはなく、他の実行、エクスポート、閲覧者には表示されません。実行はサービスIDとして行われるため、これらの値によってその実行が読み書きする内容が変わる可能性があります。ワークフローを実行する権限は、信頼できる人にのみ付与してください。

**行を制限しないプロジェクト。** これらのルールは、プロジェクトで列が制限された時点から有効になります。列を制限していないプロジェクトでは、プロジェクトの自動化を変更できるユーザーが、プロジェクトのサービスIDとして実行され、プロジェクトのアクセスを変更して自分自身をアーキテクトの1人にするステップやユーザー定義関数を作成できます。これは仕様です。そのようなプロジェクトは行の分離を保証しません。そのプロジェクトの作成権限は、アーキテクトとして信頼できる人に限定するか、列を制限してください。

### ダッシュボードとの同期の維持

行アクセスは、変更がダッシュボードに届くまでの状況を、グリッドとプロジェクトの「Security」タブの**同期**列に表示します。

| ステータス | 意味 |
|---|---|
| **待機中** | 変更が保存され、ダッシュボードへ送信されています。通常は約1分以内に完了します。 |
| **再試行中** | 送信に失敗し、再試行しています。失敗の理由がステータスの横に表示され、**再試行**ですぐに再送信できます。 |
| **未適用** | プロジェクトの制限は、まだダッシュボードに送信されていません。 |
| **適用済み** | 制限をダッシュボードに送信する直近の試行が成功しました。 |
| **ダッシュボードと同期済み** | 行アクセスは、ダッシュボードが適用している内容と、書き込む内容を比較し、一致しています。 |
| **ダッシュボードと差異あり** | ダッシュボードが、行アクセスが書き込む内容を適用していません。Supersetでルールが変更または削除されたか、テーブルの公開ビューをチェックできません。 |
| **エラー** | 制限の送信に失敗しました。理由がステータスの横に表示されます。 |

変更が**適用済み**になると、グリッドはそれをダッシュボードと照合し、**ダッシュボードと同期済み**または**ダッシュボードと差異あり**に移ります。**ダッシュボードと差異あり**と**エラー**ではどちらも**再試行**を利用でき、プロジェクトの制限をもう一度送信します。ステータスをまったく読み取れない場合、グリッドには「同期ステータスをチェックできませんでした。」と表示されます。

1つのテーブルが原因の**エラー**では、そのテーブルの名前と対処方法が表示されます。たとえば、制限された列なしで公開されたテーブルの場合は「再公開するか、公開を取り消してください。」、制限された列があるのに公開されていないテーブルの場合は、公開するまでダッシュボードがフィルターできない旨が表示されます。ステータスは**エラー**のままで、そのテーブルを公開するか、公開済みのテーブルの列を制限するまで、未公開のテーブルの名前が表示されます。このようなテーブルがあっても、プロジェクトの他の部分は止まらず、他のすべてのテーブルは同期が保たれます。

ダッシュボードは、PlaidCloud自身のクエリと同じ付与に従います。

- **その列を持つ公開済みのすべてのテーブルがフィルターされます。** 制限を設定したときに見ていたテーブルだけではありません。
- **一部の値のみが付与されたグループは、他の全員がすべての行を表示できる場合でもフィルターされます。** ダッシュボードデータセットが存在するすべてのテーブルが対象です。
- **プロジェクトのアーキテクトは、すべての行を表示できます。** ダッシュボードでも、テーブルエクスプローラーやPlaidCloudの他の部分と同じです。これは、プロジェクトのアーキテクトグループと、個々のメンバーと共有されているプロジェクトのアーキテクトに適用されます。アーキテクトのアクセスを取り消すと、ダッシュボードにすぐに反映されます。メンバーのロールの変更、プロジェクトからのメンバーやそのグループの削除、プロジェクトのアクセスタイプの変更、以前のプロジェクトバージョンの復元、グループの削除のいずれでも同様です。
- **セキュリティグループのメンバーシップの変更は、自動的にダッシュボードに反映されます。** PlaidCloudでのグループへのユーザーの追加や削除、メンバーの無効化や削除、グループの削除、デフォルトのセキュリティグループに参加する新しいメンバーの追加を行うと、そのグループに値を付与しているすべてのプロジェクトで、ダッシュボードに表示される内容が約1分以内に更新されます。行アクセスを開き直す必要はありません。PlaidCloudの外部で行われたメンバーシップの変更（Keycloakでの直接の変更や、シングルサインオンによるサインイン時のグループへの割り当て）は、保存や再試行をしなくても、約15分以内にダッシュボードに反映されます。

### ディメンションの付与

値のソースに**ディメンション**を選択した場合、ノードをオンにすると、その配下のすべてが付与されます。付与はディメンションに追従します。オンにしたノードの配下に追加されたメンバーは、ディメンションの保存後の次の同期でそのグループに付与され、その配下から移動または削除されたメンバーは付与されなくなります。グリッドを開き直す必要はありません。開き直したときは、オンにしたノードはオンのまま表示されます。

オンにしたノードの配下のいずれかをオフにすると、そのノードはオフになり、グループにはオンのままのメンバーだけが残ります。そのメンバーをもう一度オンにしても、ノードは再びオンにはなりません。ノードをオンにするには、ノード自身のボックスをクリックしてください。**貼り付け**、**すべて選択**、**選択を反転**がオンにするのはメンバーだけで、ノードにはなりません。

名前が行アクセスの値として使用できないディメンションメンバーは、保存時に名前が示されて拒否されます。そのようなメンバーが後から現れた場合、その行は誰にも付与されず、同期ステータスにその名前が表示されます。「ディメンション‘…’のメンバー‘…’は行アクセスの値として使用できないため、その行は付与されません。ディメンションで名前を変更してください。」

### 付与のソーステーブルへのバインド

値を手作業でオンにする代わりに、制限された列を、答えをすでに保持しているソーステーブル、つまりグループとそのグループが表示できる値を1行ずつ持つテーブルに関連付けることができます。まずグリッドで列を制限し、次に、列、ソーステーブル、ソーステーブルのグループ列と値の列を指定する[**行アクセスを設定**](/ja/reference/workflow-steps/tables/table-set-row-access/)ワークフローステップを追加します。ステップの最初の実行で、列がそのテーブルにバインドされます。列に手作業で設定された付与はクリアされ、付与はテーブルの行から設定されます。

バインドされると、その列は**ソース所有**になります。行アクセスのグリッドには、ソーステーブルの名前を示すバッジとともにロックされた状態で表示され、**バインディングを削除**をクリックするまで、付与の手作業での編集は拒否されます。

ステップを実行するたびに、ソーステーブルが読み直され、付与が再適用されます。そのテーブルを読み込んだり更新したりするワークフローの後に実行されるようスケジュールすると、ソースデータでグループが追加、削除、再割り当てされた場合に、誰かがグリッドを手作業で編集しなくても、次の実行で行アクセスに反映されます。

ソーステーブルが誰にどの行を表示するかを決めるため、その行の変更や削除ができるのは、プロジェクトのアーキテクト、テナント管理者、またはプロジェクト自身のワークフローだけです。それ以外のユーザーには、「このテーブルは‘region’の行アクセスの付与を提供しているため、その行の変更や削除ができるのはプロジェクトのアーキテクトのみです。」と通知されます。

### 制限テンプレート

同じ値のソース、値の型、空白値の設定など、再利用したい制限の形を作成した場合は、一度保存しておけば、列ごとに作り直さなくても必要な場所に適用できます。

- 開いている行アクセス画面の**テンプレートとして保存…** は、現在の列の形を、名前を付けたテナントレベルのテンプレートとして保存します。保存されるのは形だけで、付与は含まれません。
- 別のプロジェクトの列での**テンプレートを適用**は、その列をテンプレートの形から開始し、すべてのグループの付与を空にして、入力できる状態にします。

テンプレートの保存と適用は、どのプロジェクトのアーキテクトでも行えます。テンプレートはテナント全体で共有されるため、名前の変更（**名前の変更…**）と削除（**削除**）にはテナント管理者が必要です。テンプレートを削除しても、それを適用した列の制限はそのまま残ります。

<Aside type="note">
テンプレートはリンクではなくコピーです。後からテンプレートを編集しても、すでにそれを適用した列は変更されません。列を後の改訂に合わせるには、テンプレートをもう一度適用してください。
</Aside>

### SSOグループ属性からの付与

列は、PlaidCloudではなくIDプロバイダーから付与を受け取ることもできます。プロジェクトのアーキテクトが、行アクセスで**Accept row-access grants from SSO group attributes**を有効にして、列を対象に設定します。

有効にすると、セキュリティグループのKeycloak属性`row_access.<column>`が、そのグループがその列で表示できる値を設定します。Keycloakでグループに属性を設定すると、PlaidCloudは、すでにプロジェクトへのアクセスを持つグループに対して自動的にそれを取り込みます。行アクセス自体で設定することは他にありません。付与は、PlaidCloud自身のクエリとSupersetダッシュボードの両方で同期されます。

<Aside type="caution">
これは、すでにプロジェクトにアクセスできるグループにのみ値を付与します。プロジェクトへのアクセスがないグループに`row_access.region`を追加しても、そのグループにプロジェクトへのアクセスも付与するまで、何も付与されません。
</Aside>

### 保存前のプレビュー

行アクセスは、確定する前に変更の意味を表示します。

- **プレビュー表示ユーザー**フッターには、グループがテーブルの全行のうち何行を表示できるかが、実際の行のサンプルとともに表示されます。グリッドで任意のグループを選択してプレビューできます。プレビューは保存後に更新されます。
- 保存前に、行アクセスは確認が必要な点を警告します。何もオンになっていないグループがある場合は、**Everyone else**の設定に応じて、そのグループがすべての行を表示するのか、まったく表示しないのか。プロジェクトへのアクセスを持つが、どのグループの付与にも含まれていないメンバー。その列の値が空白（`NULL`）で、どのグループにも付与されていない行。

### 制限されたメンバーに表示される内容

制限されたメンバーがテーブルを名前で読み取る場所では、どこでも自分の行だけが表示されます。テーブルエクスプローラーのグリッド、列のファセット、ダウンロード、テーブルのダウンロードダイアログ、閲覧者として読み取るアプリやツール、ダッシュボードが対象です。テーブルエクスプローラーは、表示しているグリッドが付与によってフィルターされている場合、ツールバーに**アクセス権により行が制限されています**と表示します。フィルターされるダウンロードを開始すると、「アクセス権により行が制限されています」と表示されます。すべての行を読み取れるアーキテクトには、どちらの通知も表示されません。

### 行アクセスと自分で作成するクエリ

行アクセスは、定義されたテーブルをフィルターすることで、グループが表示できる行を制限します。自分で作成するクエリには、そのフィルターを付けられる単一のテーブルがありません。クエリは、好きなだけテーブルを結合、統合、ネストできるためです。そのため、行を制限するプロジェクトでは、PlaidCloudは、何も検証されていない行を返すことを避け、呼び出し元が指定したクエリの実行を拒否します。

これは、自分のSQLによる読み取り、自分のSQLの結果のファイルや別のデータベースへのエクスポート、ファンアウトステップの「Test row 1」プレビューへの行条件の入力に適用されます。アプリやツールがデータを読み取る通常の方法である、テーブルを名前で読み取る場合には適用されません。それらは付与を適用し、閲覧者が表示できる行を返します。単一のテーブルに対する単純なクエリとして書かれた列のファセットも名前で読み取られるため、拒否されることなく、メンバー自身の値が返されます。

拒否されたユーザーには、対象のプロジェクトが通知され、名前による読み取り方法が案内されます。アーキテクトは、制限された列のすべての値を自分に付与できるため、プロジェクトのアーキテクトは、クエリをそのまま実行し、結果を任意の形式でエクスポートできます。

スプレッドシートのインポートは、それ自体では、自分で作成するクエリではありません。通常のファイルのインポートは、制限されたデータをまったく読み取らず、アップロードしたファイルからプロジェクト自身の新しいテーブルを作成するだけなので、行アクセスの影響を受けません。例外は、データの射影が呼び出し元によって指定されるインポート、つまり列ごとの式や動的なExcelマッピングです。対話型のインポート画面では、これらは上記の自由形式のSQLの画面と同様に拒否され、プロジェクトのアーキテクトが必要になります。呼び出し元が指定した射影は、別のテーブルを読み取る可能性があるためです。ワークフローから実行されるインポートは、プロジェクト自身のサービスIDで実行されるため、どちらの場合も影響を受けません。

<Aside type="caution">
プロジェクトで最初の列を制限すると、それを使用するすべてのユーザーに影響します。そのプロジェクトのPanelアプリ、ノートブック、連携が、独自に作成したSQLでデータを読み取っている場合は、制限する前に、テーブルを名前で読み取るように切り替えてください。そうしないと、アーキテクト以外のすべてのユーザーで動作しなくなります。
</Aside>

### 行アクセスとデータエディター

データエディターはテーブルを直接読み書きするため、行アクセスは両方の側に適用されます。

制限されたテーブルをデータエディターで開くと、セキュリティグループに付与されている行だけが表示されます。これはダッシュボードでも適用されるのと同じフィルターで、制限された列がグリッドに表示される列に含まれていない場合でも適用されます。

編集内容の保存には、プロジェクトの**アーキテクト**が必要です。保存はテーブルの行を読み取るのではなく一括で置き換え、行ごとにフィルターされないため、制限されたテーブルのデータの編集は、読み取りではなく作成の操作として扱われます。アーキテクトでないユーザーには、アーキテクトが必要であることが通知されます。制限された列を持たないテーブルは、これまでどおり編集でき、行を制限していないプロジェクトも同様です。

### 行数とテーブルサイズ

テーブルの行数とストレージサイズは、表示できる行ではなくテーブル全体を表すため、制限されたユーザーに、付与の範囲外にどれだけ行があるかを知らせてしまいます。行を制限するプロジェクトでは、読み取りがフィルターされるユーザーには、プロジェクトのどのテーブルについても、テーブルの一覧、検索、テーブルの詳細、スナップショット、およびMCPで接続されたAIアシスタントとAIツールで、行数やサイズが表示されません。これは、制限された列を持たないテーブルを含め、プロジェクト内のすべてのテーブルに適用されます。プロジェクト自身の合計値も、ホーム、プロジェクトの一覧と検索、プロジェクトの詳細での合計行数とサイズが、これらのユーザーには非表示になります。

ワークフローの実行履歴にも同じことが当てはまります。各実行とステップが記録した読み取り行数と書き込み行数もテーブル全体を表すため、同じユーザーに対しては、ワークフローとステップの実行履歴、およびMCPで接続されたAIアシスタントとAIツールで、これらの数値は空白になります。これらのユーザーに対して、[Weave](/ja/guides/ai-assistant/weave-findings/)は、以前の実行と比べた行数や空の値のステップのチェックを行いません。検出事項自体が、テーブル全体の件数が変化したことを知らせてしまうためです。

プロジェクトのアーキテクトには、これまでどおり数値が表示され、行を制限していないプロジェクトのすべてのユーザーにも同様に表示されます。

### メンバーが表示できる内容の確認

グループに付与されている内容ではなく、特定の人が表示できる内容を確認するには、**Identity → Member**を開き、メンバーを選択して、その**行アクセス**タブを開きます。**有効なアクセス**列には、制限されたすべてのプロジェクトと列について、そのメンバーがすべてのグループを合わせて表示できる値が一覧表示されます。SSOグループ属性からの付与や、グループの付与に含まれる空白（`NULL`）の行も含まれます。プロジェクトのアーキテクトは、すべての行を読み取れるため、**すべての行を表示（アーキテクト）** と表示されます。これはPlaidCloud自身のクエリが適用する答えと同じなので、サポートや、問題が報告される前に変更が意図したとおりに動作したかを確認するのに役立ちます。

### わかりやすいエラー

行アクセスがアクションをブロックした場合（制限されたプロジェクトで自分で作成したクエリ、アーキテクトなしでの編集、自動化、ディメンション、付与のソーステーブルの変更、その他の上記のケース）、メッセージには、一般的なエラーではなく、何が制限されているかと、次に何をすべきか（依頼先のアーキテクトなど）が示されます。

### 行アクセスの監査

列の制限や制限の解除、グループの付与の編集は、すべてそのプロジェクトの[プロジェクトログ](/ja/get-started/tutorials/collaborate-versions-and-sharing/#プロジェクトログを読む)に、誰がいつ変更したかとともに記録されます。プロジェクトの**Analyze → Projects → Log**を開くと確認できます。この記録を取るために、行アクセスで有効にする設定はありません。プロジェクトに対する他のすべての追跡対象の変更と同じ方法で記録されます。

## デフォルトのセキュリティグループの設定


新しいメンバーを追加する時間を短縮するために、デフォルトのセキュリティグループを指定します。これにより、各ユーザーを手作業で割り当てなくても、新しいメンバーに基本となるセキュリティグループが設定されます。この設定は、セキュリティグループを追加するときに、「セキュリティグループ」ウィンドウの下部にある「Assign to New Users by Default」というチェックボックスをオンにすると利用できます。



## セキュリティ監査の実行


セキュリティ監査機能では、すべてのメンバーとグループにわたるグループメンバーシップを確認できます。



**セキュリティ監査を実行するには：**


1. 「Identity」を開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューの「Security Group Audit」をクリックします

PlaidCloudのすべてのテーブルはCSVファイル形式でエクスポートできるため、グループとメンバーの関連付けは、過去の記録のために、あるいはオフラインで気軽に確認するために、PlaidCloudの外部でも確認できます。



**「Security Group Audit」フォームからエクスポートするには：**


1. 「Identity」を開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューの「Security Group Audit」をクリックします
4. テーブルの「Username」の右端にある小さなアイコンをクリックします
5. 好みに応じて「Export CSV」または「Export XLXS」をクリックします

## 利用可能な権限設定の表示


ワークスペースで使用される各アプリケーションには、それぞれ利用可能な権限があります。セキュリティグループの権限は、これらのアプリケーションの権限に基づいています。


各アプリケーションで利用可能な権限の完全な一覧は、Security Binで確認できます。



**Security Binにアクセスするには：**


1. 「Identity」を開きます
2. 「Security」を選択します
3. ドロップダウンメニューの「Security Bins」をクリックします

各アプリケーションの詳細なセキュリティ設定を表示するには、左端のタグアイコンを選択します。



この利用可能なセキュリティ設定の情報は、参照用です。権限の管理の詳細については、上記の「セキュリティグループの管理」セクションをご覧ください。
