PlaidCloudのセキュリティおよびアクセス管理はシンプルです。メンバーは、所属しているグループに基づいてアクセスを許可または拒否されます。メンバーのセキュリティの関連付けは、簡単に追加や変更ができます。

<Aside>各ワークスペースで作成できるセキュリティグループの数に上限はありませんが、セキュリティ管理を容易にするため、数を最小限に抑えることをお勧めします。</Aside>



## セキュリティグループの管理


セキュリティグループは、追加、更新、削除ができます。



**セキュリティグループを管理するには：**


1. Identityを開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューの「Security Groups」をクリックします（既存のグループを含むフォームが表示されます）
4. グループを追加するには、「Create Security Group」をクリックします
5. グループの権限を編集するには、左端のアイコンをクリックします

**グループメンバーを管理するには：**


1. Identityを開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューの「Security Groups」をクリックします
4. メンバーアイコンをクリックします
5. 追加したいメンバーを「Unassigned Members」列から「Assigned Members」列にドラッグします。削除する場合は逆方向にドラッグします

<Aside>「Assigned Members」列を空にして保存しても何も変更されず、その旨が表示されます。グループを全員から外すには、メンバーシップを空にするのではなく、権限を削除するかグループを削除してください。</Aside>

<Aside>[行アクセス](#行アクセスの管理)によってグループに行が付与されている場合、メンバーシップの変更は約1分以内にダッシュボードに反映されます。追加したユーザーにはダッシュボードでそのグループの行が表示され、削除したユーザーには表示されなくなります。メンバーの無効化や削除、およびグループの削除も同様に反映されます。</Aside>

<Aside type="caution">自分では付与できない権限は、グループの権限マトリックスを保存する際にそのまま残され、マトリックスにも表示されません。変更が必要な場合は、その権限を持つユーザーに依頼してください。マトリックスで編集できるのは、自分が管理できる権限だけです。</Aside>

## 行アクセスの管理

行アクセスは、1つの列の値に基づいて、セキュリティグループがテーブルのどの行を表示できるかを制限します。たとえば、`region`列でアクセスを制限し、`East`と`Central`を付与したグループには、それらの値を持つ行だけを表示します。プロジェクトと列に関するすべての操作（列の選択、値の取得元の選択、どのグループに何を表示するかの決定）は1つの画面で行え、保存するとすぐに有効になります。

行アクセスの設定と変更には、プロジェクトのアーキテクトまたはテナント管理者の権限が必要です。それ以外のユーザーがプロジェクトの「Security」タブを開くと、行アクセスはアーキテクト専用であると表示され、以下のエントリポイントは表示されません。

### 行アクセスを開く

どのエントリポイントからでも、同じ行アクセス画面が開きます。

- **テーブルエクスプローラーのツールバー**には**行アクセス**ボタンがあり、テーブルがすでに行を制限している場合はバッジが表示されます。テーブルに制限された列がある場合は最初の制限列で開き、テーブルの他の任意の列に切り替えることもできます。
- **列のファセットメニュー**には**この列で行を制限…** があり、その列で行アクセスを開きます。すでに行を制限している列では、この項目は**この列で行を制限中 - 編集…** と表示されます。
- **プロジェクトの「Security」タブ**には、プロジェクト上の制限されているすべての列が、適用先のテーブル、付与を持つグループ、**同期**の状態とともに一覧表示されます。列を選択して編集するか、**列を制限…** をクリックして新規に開始します。テーブルを選び、次に列を選びます。すでに行を制限している列にはロックのマークが付きます。
- **Identity → Member**のメンバーの**行アクセス**タブと、**Identity → Security → Security Groups**のグループの行アクセスの概要。**行アクセスを開く**（または**編集**）で選択した列を開き、**追加**でその行のプロジェクトの別の列を制限します。

列を指定して開いた場合、画面はその列のままです。**列を制限…** または**追加**から開いた場合は、列を選択できます。

### 行アクセスのグリッド

列でテーブルを制限するには：

1. 上記のいずれかのエントリポイントから行アクセスを開き、列を指定せずに開いた場合は列を選択します。ピッカーには自由入力ではなく、テーブルの実際の列が表示されます。
2. **値のソース**を選択します。**列**（テーブルの列の一意の値）、**ディメンション**（ディメンションのノード）、**リスト**（入力した値）のいずれかです。値の型は列のデータ型に従います。
3. セキュリティグループごとに、そのグループが表示できる値にチェックを付けます。グリッドには、プロジェクトにアクセスできるグループに加え、その列にすでに付与を持つグループが表示されます。
4. **Everyone else**を**sees all rows**または**sees no rows**に設定します。これは、グリッドでチェックがまったくないグループすべてに適用されます。
5. **保存**をクリックします。

保存はすぐに反映されます。PlaidCloud自身のクエリには即座に、Supersetダッシュボードには約1分以内に変更が反映されます。適用のための別の手順はなく、**保存**は、付与にソースにもうない値が含まれている場合にのみ確認を求めます（後述）。画面の同期ステータスには、変更がどこまで届いたかが表示されます。[ダッシュボードの同期の維持](#ダッシュボードの同期の維持)を参照してください。

グリッドは次の詳細も自動的に処理します。

- **多数の値。** 値は並べ替えられます。列の値が表示しきれない数になる場合、グリッドに「More values than fit here — type to search.」と表示され、フィルターボックスで列全体を検索できます。グループがすでに持っている値はすべて保持されます。
- **ソースにもうない値。** グループに付与された値は、そのソースから失われてもグリッドに残ります。テーブルのどの行にもその値がない、ディメンションにそのメンバーがない、またはリストにその値がない、という場合です。列見出しには警告アイコンが付き、ホバーすると理由が表示されます。**すべて選択**、**選択を反転**、**貼り付け**は、そのような値を各グループが持っている状態のまま残します。チェックを外さない限り、付与から取り除かれるものはありません。**保存**をクリックしたときにグループがそのような値をまだ持っていると、行アクセスは**ソースにもうない値**でグループと値を示して確認します。**保持して保存**はそのまま保存し、**削除して保存**はまずすべてのグループの付与からそれらを取り除きます。確認を閉じた場合は何も保存されません。削除するとチェックが1つもないグループが残る場合、確認では、**Everyone else**の設定に従って、そのグループがすべての行を表示するのかまったく表示しないのかが示されます。まだ保存していないチェックは、その値とともに消えます。列に表示しきれないほど値がある場合、またはテーブルがまだ構築されていない場合、行アクセスはテーブルにない値を判別できないため、印を付けずに付与されたすべての値を保持します。
- **空白の値。** 1つの**空白の値 — 付与のあるすべてのグループに表示**チェックボックスで、列に値がない行の扱いを決めます。オンにすると、その列に何らかの付与を持つすべてのグループがそれらの行を表示できます。
- **まだ構築されていないテーブル**では、空のリストの代わりに**先にこのテーブルを構築してください（作成するワークフローを実行します）** と表示されます。
- **保存は画面上の値の読み込みを待ちます。** 値の読み込み中（値のソース、ディメンション、テーブルを切り替えた後や、テンプレートを適用した後）は、**保存**が無効になり、「Save is available once this source's values load.」というツールチップが表示されます。読み込みに失敗した場合、グリッドはその旨を表示してソースを選び直すよう促します。読み込みが成功するまで何も保存されません。

### 1つの列名、すべてのテーブル

制限は、単一のテーブルではなく、プロジェクト上の列の*名前*に属します。`region`で行が制限されると、プロジェクト内で`region`という名前の列を持つすべてのテーブルが、PlaidCloud自身のクエリでもダッシュボードでも同様にフィルターされます。グリッドの**Applies to**リストには、それらのテーブルが表示されます。リストは列名によって決まるため、読み取り専用です。後から同じ列を持つテーブルを追加した場合も、公開された時点で対象になります。

プロジェクト内にその名前の列を持つテーブルがない場合、ウィンドウに**Applies to 0 tables**と表示されることに加えて、テーブルが追加されるまでその制限はどのダッシュボードもフィルターしないという警告が表示されます。テーブルに列を追加するか、列名を修正すると、警告は消えます。

<Aside type="caution">
**列名は、大文字と小文字や空白も含めて完全に一致する必要があります。**`Region`と`region`は別の名前で、`region`と末尾に空白のある`region `も別の名前です。ピッカーには実在する列名のみが表示されるため、主に他の場所で列の名前が変更された場合に問題になります。その場合、行アクセスは何も制限しないままにするのではなく、警告を表示し、見つかった最も近い列の名前を示します。
</Aside>

<Aside type="caution">
**行を制限するテーブルを公開すると、同じ手順でそのダッシュボードフィルターも設定されます。** ダッシュボードはテーブルを公開済みのレポートビュー経由で読み取るため、制限された列を持つテーブルを公開または再公開すると、PlaidCloudは公開が完了する前にそのテーブルのダッシュボードフィルターを登録します。登録できない場合は公開が拒否され、その試行で作成されたものはすべてロールバックされるため、制限されたテーブルがフィルターなしのままダッシュボードに残ることはありません。*ビュー*のクエリは制限された列の名前を変更したり派生させたりできるため、行を制限するプロジェクトではビューを公開できません。[テーブルの公開](/ja/guides/data/publish/)を参照してください。
</Aside>

### 制限の解除

グリッドの**制限を解除**をクリックし、インラインの確認を行うと、制限が削除されます。確認メッセージは「Stop restricting rows by ‘region’? Every group's grant on it is removed and everyone sees its rows.」です。その後、行アクセスは「Rows in ‘region’ are no longer restricted.」と確認します。その列のSupersetデータセットも一緒に削除されます。ただし、チャートがまだ使用している場合は削除されず、行アクセスはデータセットが残ることと、使用しているチャートの数を通知します。

行を制限している列の名前変更や削除はできません。アーキテクトには、先に行アクセスで制限を解除するよう通知されます。それ以外のユーザーには、プロジェクトのアーキテクトに依頼するよう通知されます。

### 行を制限するプロジェクトを変更できるユーザー

プロジェクトのワークフロー、ステップ、ユーザー定義関数は、すべての行を読み取れるプロジェクト自身のサービスIDとして実行されます。それらを変更できるユーザーは、付与されていない行を、自分が読み取れるテーブルにコピーするステップを作成できてしまいます。そのため、プロジェクトで行を制限すると、プロジェクトの動作を変更できるユーザーも制限されます。プロジェクトで少なくとも1つの列が制限されると、次のようになります。

- **自動化はアーキテクト専用です。** ワークフロー、ステップ、ユーザー定義関数、スケジュール、ワークフロー変数とプロジェクト変数、通知メールテンプレートを変更できるのは、プロジェクトのアーキテクトとテナント管理者のみです。同じ理由で、ワークフローバンドルのインポート、Alteryxワークフローの変換、プロジェクトへのインポート、コピー、復元、またはプロジェクトの接続環境、デフォルトのドキュメントアカウント、ERP転記モードの変更も同様です。それ以外のユーザーも、プロジェクトのワークフローを実行することはできます。**開始**、**停止**、**再開**、**選択したステップを実行**は引き続き使用できます。これらのユーザーには、ステップエディター、ワークフローの編集コントロール、UDFエディター、スケジュールフォームが読み取り専用で開き、依頼先のアーキテクトを示すバナーが表示されます。「This project restricts rows, so only its Architects can change workflows, steps, UDFs, schedules, variables and notify templates. You can still run them.」
- **制限された列が読み取るディメンションはアーキテクト専用です。** 誰がどの行を表示できるかを決めるディメンション（制限された列の値のソース）を変更できるのは、プロジェクトのアーキテクトまたはテナント管理者と、プロジェクト自身のワークフローのみです。これには、ノードの追加、移動、名前の変更、コピー、クリア、ロード、復元、およびディメンション自体が含まれます。それ以外のユーザーには「This dimension decides who sees which rows of ‘region’, so only a project Architect can change it.」と通知されます。どの制限からも読み取られないディメンションには影響しません。
- **付与ソーステーブルはアーキテクト専用です。** 列の[付与のソース](#ソーステーブルへの付与のバインド)としてバインドされたテーブルの行を変更したり、そのテーブルを削除したりできるのは、プロジェクトのアーキテクト、テナント管理者、プロジェクトのワークフローのみです。データエディター、インポート、コネクターのロード、APIのいずれを使用した場合も同様です。
- **プロジェクトのコピーはアーキテクト専用です。** コピーには「This copy is not row-restricted.」と表示され、新しいプロジェクトには、設定するまで制限がありません。
- **以前のバージョンの復元も、他の変更と同じ扱いです。** プロジェクト自体の設定、または上記のディメンションを復元するには、プロジェクトのアーキテクトが必要です。復元は常にそのバージョンが属する項目に適用されるため、これを回避するために別のプロジェクトを指定することはできません。[バージョン履歴](/ja/guides/projects/managing-projects/#バージョン履歴)を参照してください。
- **制限されたテーブルのデータ編集**にはアーキテクトが必要です。詳細は[行アクセスとデータエディター](#行アクセスとデータエディター)を参照してください。

プロジェクトで最初の列を制限する前に、行アクセスは影響を受けるユーザーを通知します。「Restricting rows here means only Architects can change this project's workflows, steps, UDFs, schedules and notify templates. N members can change them today; they will still be able to run them.」

実行は、スケジュールされたものも含め、プロジェクトのサービスIDとして実行されるため、これまでとまったく同じように動作します。実行によって生成されるものは、アーキテクトが設計した内容に従います。制限された列を含まない出力テーブル、エクスポートファイル、通知メール、ログ行は、それを読むユーザーに対してフィルターされません。

**実行の開始時に指定される値。** ワークフローを実行できるユーザーは誰でも、変数に独自の値を指定して開始できます。[App Runner](/ja/guides/workflows/use-converted-alteryx-apps/#app-runnerフロントエンド)はフォームの回答でこれを行い、APIやAIツールでも可能です。これらの値はその実行のみで有効であり、ワークフローに保存されることはなく、他の実行、エクスポート、閲覧者にも表示されません。実行はサービスIDとして行われるため、これらの値はその実行が読み取り、書き込む内容を変えられます。したがって、ワークフローを実行する権限は、信頼できるユーザーにのみ付与してください。

**行を制限しないプロジェクト。** これらのルールは、プロジェクトが列を制限した時点で初めて有効になります。何も制限していないプロジェクトでは、プロジェクトの自動化を変更できるユーザーが、プロジェクトのサービスIDとして実行されるステップやユーザー定義関数を作成して、プロジェクトのアクセスを変更し、自分自身をアーキテクトにすることができます。このようなプロジェクトは行の分離を保証しないため、これは仕様です。そのようなプロジェクトでは、アーキテクトとして信頼できるユーザーにのみ作成権限を与えるか、列を制限してください。

### ダッシュボードの同期の維持

行アクセスは、変更がダッシュボードに届くまでの状況を、グリッドと、プロジェクトの「Security」タブの**同期**列に表示します。

| ステータス | 意味 |
|---|---|
| **待機中** | 変更は保存され、ダッシュボードへ送信中です。通常は約1分以内に解消されます。 |
| **再試行中** | 送信に失敗し、再試行されています。失敗の理由がステータスの横に表示され、**再試行**ですぐに再送信できます。 |
| **未適用** | プロジェクトの制限はまだダッシュボードに送信されていません。 |
| **適用済み** | 制限をダッシュボードに送信する直近の試行が成功しました。 |
| **ダッシュボードと同期済み** | 行アクセスは、ダッシュボードが適用している内容と、書き込む内容を比較し、一致していました。 |
| **ダッシュボードと差異あり** | ダッシュボードが、行アクセスが書き込む内容を適用していません。Supersetでルールが変更または削除されたか、テーブルの公開ビューを確認できません。 |
| **エラー** | 制限の送信に失敗しました。理由がステータスの横に表示されます。 |

変更が**適用済み**になると、グリッドはそれをダッシュボードと照合し、**ダッシュボードと同期済み**または**ダッシュボードと差異あり**に移行します。**ダッシュボードと差異あり**と**エラー**のどちらにも**再試行**があり、プロジェクトの制限を再送信します。ステータスをまったく読み取れない場合、グリッドは「Couldn't check sync status.」と表示します。

1つのテーブルが原因の**エラー**では、そのテーブルが示され、対処方法が表示されます。たとえば、制限された列なしで公開されたテーブル（「Republish or unpublish it.」）や、制限された列を持つが公開されていないテーブル（公開されるまでダッシュボードはフィルターできません）などです。ステータスは**エラー**のままで、そのテーブルを公開するか、代わりに公開済みのテーブルの列を制限するまで、未公開のテーブルが示されます。このようなテーブルがあっても、プロジェクトの他の部分は止まりません。他のすべてのテーブルは同期が維持されます。

ダッシュボードは、PlaidCloud自身のクエリと同じ付与に従います。

- **その列を持つ公開済みのすべてのテーブルがフィルターされます。** 制限を設定したときに表示していたテーブルだけではありません。
- **一部の値のみを付与されたグループは、他のすべてのユーザーがすべての行を表示できる場合でもフィルターされます。** ダッシュボードデータセットが存在するすべてのテーブルが対象です。
- **プロジェクトのアーキテクトはすべての行を表示できます。** テーブルエクスプローラーやPlaidCloudの他の部分と同様に、ダッシュボードでも同じです。これは、プロジェクトのアーキテクトグループと、個々のメンバーと共有されているプロジェクトのアーキテクトに適用されます。アーキテクトアクセスの取り消しは、メンバーのロールの変更、メンバーまたはそのグループのプロジェクトからの削除、プロジェクトのアクセスタイプの変更、以前のプロジェクトバージョンの復元、グループの削除のいずれの場合も、ダッシュボードにすぐに反映されます。
- **セキュリティグループのメンバーシップの変更は自動的にダッシュボードに反映されます。** PlaidCloudでのグループへのユーザーの追加や削除、メンバーの無効化や削除、グループの削除、デフォルトのセキュリティグループに参加する新しいメンバーの追加は、そのグループに値を付与しているすべてのプロジェクトで、行アクセスを開き直さなくても、約1分以内にダッシュボードに表示される内容を更新します。PlaidCloudの外で行われたメンバーシップの変更（Keycloakでの直接変更や、サインイン時のシングルサインオンによるグループへの配置）は、保存や再試行の操作なしで、約15分以内にダッシュボードに反映されます。

### ディメンションの付与

値のソースが**ディメンション**の場合、ノードにチェックを付けると、その配下のすべてが付与されます。付与はディメンションに追従します。チェックされたノードの配下に追加されたメンバーは、ディメンションを保存した後の次の同期でそのグループに付与され、その配下から移動または削除されたメンバーは付与されなくなります。グリッドを開き直す必要はありません。開き直すと、チェックしたノードは再びチェックされた状態で表示されます。

ノードを通じてではなく単独でチェックしたメンバーは、ディメンションから削除されても付与されたままで、グリッドにはソースにもうない値として印が付きます。

チェックされたノードの配下の項目のチェックを外すと、ノードのチェックも外れ、グループはチェックされたままのメンバーだけを保持します。そのメンバーに再びチェックを付けても、ノードは再びチェックされません。ノードのチェックボックス自体をクリックしてください。**貼り付け**、**すべて選択**、**選択を反転**はメンバーのみをチェックし、ノードはチェックしません。

名前が行アクセスの値として使用できないディメンションメンバーは、保存時に名前が示されて拒否されます。後からそのようなメンバーが現れた場合、その行は誰にも付与されず、同期ステータスにそのメンバーが示されます。「Dimension ‘…’ member ‘…’ cannot be used as a row access value, so its rows are not granted. Rename it in the dimension.」

### ソーステーブルへの付与のバインド

値を手作業でチェックする代わりに、制限された列を、答えをすでに保持しているソーステーブルに紐付けることができます。このテーブルには、グループと、そのグループが表示できる値が1行ずつ格納されています。まずグリッドで列を制限し、次に、列、ソーステーブル、およびソーステーブルのグループ列と値の列を指定した[**行アクセスを設定**](/ja/reference/workflow-steps/tables/table-set-row-access/)ワークフローステップを追加します。ステップの最初の実行で、列がそのテーブルにバインドされます。列の手動で設定した付与はクリアされ、付与はテーブルの行から設定されます。

バインドされると、その列は**ソース所有**になります。行アクセスのグリッドではロックされた状態で表示され、ソーステーブルの名前を示すバッジが付き、**バインディングを削除**をクリックするまで、手動での付与の編集は拒否されます。

ステップの以降の実行では、そのたびにソーステーブルを再読み込みして付与を再適用します。そのテーブルをロードまたは更新するワークフローの後に実行されるようスケジュールしておくと、ソースデータで追加、削除、再割り当てされたグループが、グリッドを手作業で編集することなく、次の実行で行アクセスに反映されます。

ソーステーブルが誰に何を表示するかを決めるため、その行を変更したりテーブルを削除したりできるのは、プロジェクトのアーキテクト、テナント管理者、プロジェクト自身のワークフローのみです。それ以外のユーザーには「This table supplies the row access grants for ‘region’, so only a project Architect can change its rows or delete it.」と通知されます。

### 制限テンプレート

同じ値のソース、値の型、空白値の設定といった、再利用したい制限の形を作成した場合は、一度保存しておけば、列ごとに作り直すことなく、必要な場所に適用できます。

- 開いている行アクセス画面の**テンプレートとして保存…** は、現在の列の形を、名前付きのテナントレベルのテンプレートとして保存します。保存されるのは形だけで、付与は含まれません。
- 別のプロジェクトの列に対する**テンプレートを適用**は、その列をテンプレートの形から開始します。すべてのグループの付与は空の状態で、自分で入力します。

プロジェクトのアーキテクトであれば、誰でもテンプレートを保存して適用できます。テンプレートの名前の変更（**名前の変更…**）と削除（**削除**）には、テンプレートがテナント全体で共有されるため、テナント管理者が必要です。テンプレートを削除しても、適用済みの列の制限はそのまま残ります。

<Aside type="note">
テンプレートはコピーであり、リンクではありません。テンプレートを後から編集しても、すでに適用した列は変更されません。後の改訂内容に列を合わせるには、テンプレートを再度適用してください。
</Aside>

### SSOグループ属性からの付与

列は、PlaidCloudではなくIDプロバイダーから付与を取得することもできます。プロジェクトのアーキテクトは、行アクセスで**Accept row-access grants from SSO group attributes**を有効にして、列をオプトインします。

有効にすると、セキュリティグループのKeycloak属性`row_access.<column>`が、そのグループがその列で表示できる値を設定します。Keycloakでグループに属性を設定すると、プロジェクトにすでにアクセスできるすべてのグループについて、PlaidCloudが自動的にそれを取得します。行アクセス自体で設定する項目はこれ以上ありません。付与は、PlaidCloud自身のクエリとSupersetダッシュボードの両方で同期されたままになります。

<Aside type="caution">
これは、すでにプロジェクトにアクセスできるグループに値を付与するだけです。プロジェクトにアクセスできないグループに`row_access.region`を追加しても、そのグループにプロジェクトへのアクセスも付与するまで、何も付与されません。
</Aside>

### 保存前のプレビュー

行アクセスでは、変更を確定する前に、その意味を確認できます。

- フッターの**プレビュー表示ユーザー…** には、グループが全体の行数のうち何行を表示できるかと、行のサンプルが表示されます。グリッドで任意のグループを選んでプレビューできます。プレビューは保存後に更新されます。
- 保存前に、行アクセスは注意が必要な点を警告します。何もチェックされていないグループがあり、**Everyone else**の設定によってそのグループがすべての行を表示するのか、まったく表示しないのか。プロジェクトアクセスを持つメンバーのうち、どのグループの付与にも含まれていない人がいること。その列の値が空白（`NULL`）の行で、どのグループにも付与されていないものがあること、などです。

### 制限されたメンバーに表示される内容

制限されたメンバーがテーブルを名前で読み取る場合は、常に自分の行だけが取得されます。これは、テーブルエクスプローラーのグリッド、列のファセット、ダウンロード、テーブルのダウンロードダイアログ、閲覧者として読み取るアプリやツール、ダッシュボードのすべてに当てはまります。テーブルエクスプローラーは、表示しているグリッドが付与によってフィルターされている場合、ツールバーに**アクセス権により行が制限されています**と表示し、フィルターされるダウンロードを開始すると「Rows limited by your access.」と表示します。すべての行を読み取れるアーキテクトには、どちらの通知も表示されません。

### 行アクセスと自分で作成するクエリ

行アクセスは、それが定義されているテーブルをフィルターすることで、グループが表示できる行を制限します。自分で作成したクエリには、そのフィルターを適用する単一のテーブルがありません。クエリは、任意の数のテーブルを結合したり、組み合わせたり、入れ子にしたりできるためです。そのため、行を制限するプロジェクトでは、PlaidCloudは、何も検証されていない行を返すのではなく、呼び出し元が指定したクエリの実行を拒否します。

これは、自分のSQLによる読み取り、自分のSQLの結果をファイルや別のデータベースにエクスポートすること、およびファンアウトステップの「Test row 1」プレビューに行の条件を入力することに適用されます。アプリやツールがデータを読み取る通常の方法である、テーブルを名前で読み取ることには適用**されません**。これらは付与を適用し、閲覧者が表示できる行を返します。単一テーブルの単純なクエリとして記述された列のファセットも名前で読み取られるため、拒否されずに、メンバー自身の値が返されます。

拒否されたユーザーには、どのプロジェクトだったかが通知され、名前による読み取り方法が案内されます。アーキテクトは、制限された列のすべての値を自分に付与できるため、プロジェクトのアーキテクトは、クエリを記述どおりに実行し、その結果を任意の形式でエクスポートできます。

スプレッドシートのインポートは、それ自体では自分で作成したクエリではありません。通常のファイルのインポートは制限されたデータをまったく読み取らず、アップロードしたファイルからプロジェクト自身の新しいテーブルを作成するだけなので、行アクセスの影響を受けません。例外は、データのプロジェクションを呼び出し元が指定するインポートで、列ごとの式や動的なExcelマッピングが該当します。対話型のインポート画面では、これらは上記の自由形式SQLの場合と同様に拒否され、プロジェクトのアーキテクトが必要です。呼び出し元が指定したプロジェクションが別のテーブルを読み取れる可能性があるためです。ワークフローから実行されるインポートは、プロジェクト自身のサービスIDとして実行されるため、どちらの場合も影響を受けません。

<Aside type="caution">
プロジェクトで最初の列を制限すると、それを使用するすべてのユーザーに対してこの動作が変わります。そのプロジェクトのPanelアプリ、ノートブック、連携が独自のSQLを組み立ててデータを読み取っている場合は、制限する前に、テーブルを名前で読み取るように切り替えてください。切り替えないと、アーキテクト以外のすべてのユーザーに対して動作しなくなります。
</Aside>

### 行アクセスとデータエディター

データエディターはテーブルを直接読み書きするため、行アクセスは両方の側に適用されます。

データエディターで制限されたテーブルを開くと、セキュリティグループに付与された行のみが表示されます。これはダッシュボードにも引き継がれるフィルターと同じで、制限された列がグリッドに表示される列でない場合にも適用されます。

編集内容を保存するには、プロジェクトの**アーキテクト**権限が必要です。保存はテーブルの行を読み取るのではなく一括で置き換え、行ごとにフィルターされないため、制限されたテーブルのデータ編集は、読み取りではなく作成作業として扱われます。アーキテクト以外のユーザーには、アーキテクトが必要であると通知されます。制限された列を持たないテーブルは、従来どおり編集でき、行を制限しないプロジェクトも同様です。

### 行数とテーブルサイズ

テーブルの行数とストレージサイズは、表示できる行ではなくテーブル全体を表すため、制限された閲覧者に付与範囲外の行がいくつあるかを知らせてしまいます。行を制限するプロジェクトでは、読み取りがフィルターされるユーザーには、プロジェクトのどのテーブルについても、テーブル一覧、検索、テーブルの詳細、スナップショット、およびMCP経由で接続されたAIアシスタントとAIツールで、行数もサイズも表示されません。これは、制限された列を持たないテーブルも含め、プロジェクト内のすべてのテーブルに適用されます。プロジェクト自体の合計も、ホーム、プロジェクト一覧と検索、プロジェクトの詳細にある合計の行数とサイズを含め、これらのユーザーには非表示になります。

ワークフローの実行履歴にも同じことが適用されます。各実行とステップが記録した読み取り行数と書き込み行数も、テーブル全体を表すため、同じユーザーに対しては、ワークフローとステップの実行履歴、およびMCP経由で接続されたAIアシスタントとAIツールで、これらの数値は空白になります。これらのユーザーに対して、[Weave](/ja/guides/ai-assistant/weave-findings/)は、過去の実行と比べた行数や空の値についてステップをチェックしません。検出事項そのものが、テーブル全体の件数が変化したことを伝えてしまうためです。

プロジェクトのアーキテクトには、従来どおり数値が表示され、行を制限しないプロジェクトのすべてのユーザーも同様です。

### メンバーに表示される内容の確認

グループに付与された内容ではなく、特定のユーザーに表示される内容を確認するには、**Identity → Member**を開き、メンバーを選択して、その**行アクセス**タブを開きます。**有効なアクセス**列には、制限されているすべてのプロジェクトと列について、そのメンバーのすべてのグループを合わせて表示される値が一覧表示されます。これには、SSOグループ属性からの付与や、グループの付与に含まれている場合の空白（`NULL`）行も含まれます。プロジェクトのアーキテクトは、すべての行を読み取れるため、**すべての行を表示（アーキテクト）** と表示されます。これはPlaidCloud自身のクエリが適用する答えと同じなので、サポートや、問題が報告される前に変更が意図どおりになったかを確認する際に役立ちます。

### わかりやすいエラー

行アクセスがアクションをブロックした場合（制限されたプロジェクトで自分で作成したクエリ、アーキテクトなしでの編集、自動化、ディメンション、付与ソーステーブルの変更、および上記のその他のケース）、メッセージには、汎用的な失敗ではなく、何が制限されているかと、依頼すべきアーキテクトなどの次の対応が示されます。

### 行アクセスは監査される

列の制限や制限解除、グループの付与の編集は、すべてそのプロジェクトの[プロジェクトログ](/ja/get-started/tutorials/collaborate-versions-and-sharing/#プロジェクトログを読む)にエントリとして記録され、誰がいつ変更したかがわかります。確認するには、プロジェクトの**Analyze → Projects → Log**を開きます。この記録を残すために、行アクセスで何かを有効にする必要はありません。プロジェクトへの他のすべての追跡対象の変更と同じ方法で記録されます。

## デフォルトのセキュリティグループの設定


新しいメンバーを追加する時間を減らすため、デフォルトのセキュリティグループのセットを指定できます。これにより、各ユーザーを手作業で割り当てなくても、新しいメンバーにセキュリティグループの基本セットが付与されます。この設定は、新しいセキュリティグループを追加するときに、Security Groupウィンドウの下部にある「Assign to New Users by Default」というチェックボックスをオンにすると使用できます。



## セキュリティ監査の実行


セキュリティ監査機能により、すべてのメンバーとグループにわたるグループメンバーシップを確認できます。



**セキュリティ監査を実行するには：**


1. Identityを開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューの「Security Group Audit」をクリックします

PlaidCloudのすべてのテーブルはCSVファイル形式でエクスポートできるため、履歴の目的でも、単にオフラインで確認するためでも、グループとメンバーの関連付けをPlaidCloudの外で確認できます。



**「Security Group Audit」フォームからエクスポートするには：**


1. Identityを開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューの「Security Group Audit」をクリックします
4. テーブルの「Username」の右端にある小さなアイコンをクリックします
5. 好みに応じて、「Export CSV」または「Export XLXS」をクリックします

## 利用可能な権限設定の表示


ワークスペースで使用される各アプリケーションには、それぞれ利用可能な権限があります。セキュリティグループの権限は、これらのアプリケーション権限に基づいています。


各アプリケーションで利用可能な権限の完全な一覧は、Security Binで確認できます。



**Security Binにアクセスするには：**


1. Identityを開きます
2. 「Security」を選択します
3. ドロップダウンメニューの「Security Bins」をクリックします

各アプリケーションの詳細なセキュリティ設定を表示するには、左端のタグアイコンを選択します。



この利用可能なセキュリティ設定の情報は参照用です。権限の管理の詳細については、上記のセキュリティグループの管理のセクションを参照してください。
