PlaidCloudのセキュリティおよびアクセス管理はシンプルです。メンバーは、所属しているグループに基づいてアクセスを許可または拒否されます。メンバーのセキュリティ関連付けの追加や変更は、簡単にカスタマイズできます。

<Aside>各ワークスペースで作成できるセキュリティグループの数に上限はありませんが、セキュリティ管理を容易にするため、数を最小限に抑えることをお勧めします。</Aside>



## セキュリティグループの管理


セキュリティグループは、追加、更新、削除ができます。



**セキュリティグループを管理するには：**


1. Identityを開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューで「セキュリティグループ」をクリックします（既存のグループを一覧表示するフォームが表示されます）
4. グループを追加するには、「Create Security Group」をクリックします
5. グループの権限を編集するには、左端のアイコンをクリックします

**グループのメンバーを管理するには：**


1. Identityを開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューで「セキュリティグループ」をクリックします
4. メンバーアイコンをクリックします
5. 追加したいメンバーを「Unassigned Members」列から「Assigned Members」列にドラッグします。メンバーを削除するには、その逆にドラッグします

<Aside>「Assigned Members」列を空にして保存しても何も変更されず、その旨が通知されます。グループを全員から外すには、メンバーシップを空にするのではなく、グループの権限を削除するか、グループ自体を削除してください。</Aside>

<Aside>グループに[行アクセス](#行アクセスの管理)で行が付与されている場合、メンバーシップの変更は約1分以内にダッシュボードに反映されます。追加したユーザーはダッシュボードでそのグループの行を表示でき、削除したユーザーは表示できなくなります。メンバーの無効化や削除、およびグループの削除も同様に反映されます。</Aside>

<Aside type="caution">自分で付与できない権限は、グループの権限マトリックスを保存しても変更されず、マトリックスにも表示されません。変更が必要な場合は、その権限を持つユーザーに依頼してください。マトリックスで編集できるのは、自分が管理できる権限だけです。</Aside>

<Aside type="caution">メンバーをグループに追加したり、メンバーのグループを選択したりできるのは、そのグループが付与するすべての権限を自分が持っている場合です。Architect としてユーザーを招待する場合も同様です。ワークスペース管理者にはこの制限はありません。</Aside>

## 行アクセスの管理

行アクセスは、1つの列の値に基づいて、セキュリティグループがテーブルのどの行を表示できるかを制限します。たとえば、`region` 列でアクセスを制限し、`East` と `Central` を付与したグループには、それらの値を持つ行だけを表示させることができます。プロジェクトと列に関するすべての操作（列の選択、値の取得元の選択、どのグループに何を表示するかの決定）は1つの画面で行い、保存するとすぐに有効になります。

行アクセスの設定と変更には、プロジェクトのアーキテクトまたはテナント管理者の権限が必要です。それ以外のユーザーがプロジェクトの「Security」タブを開くと、行アクセスはアーキテクト専用であると表示され、以下のエントリポイントは表示されません。

### 行アクセスを開く

どのエントリポイントからでも、同じ行アクセス画面が開きます。

- **テーブルエクスプローラーのツールバー**には**行アクセス**ボタンがあり、テーブルがすでに行を制限している場合はバッジが表示されます。制限された最初の列がある場合はその列で開き、テーブルの他の列に切り替えることもできます。
- **列のファセットメニュー**には**この列で行を制限…** があり、その列で行アクセスが開きます。すでに行を制限している列では、この項目は**この列で行を制限中 - 編集…** になります。
- **プロジェクトの「Security」タブ**には、プロジェクト上で制限されているすべての列が、適用先のテーブル、付与を持つグループ、および**同期**の状態とともに一覧表示されます。列を選択して編集するか、**列を制限…** をクリックして新しく開始します。テーブルを選択し、続いて列を選択します。すでに行を制限している列にはロックのマークが付きます。
- **Identity → Member** のメンバーの**行アクセス**タブと、**Identity → Security → セキュリティグループ**のグループの行アクセスのサマリー。**行アクセスを開く**（または**編集**）で選択した列が開きます。**追加**でその行のプロジェクト内の別の列を制限します。

列を指定して開いた場合、画面はその列のままです。**列を制限…** または**追加**から開いた場合は、列を選択できます。

### 行アクセスのグリッド

列でテーブルを制限するには、次の手順に従います。

1. 上記のいずれかのエントリポイントから行アクセスを開き、列を指定せずに開いた場合は列を選択します。ピッカーには、自由入力のテキストではなく、テーブルの実際の列が表示されます。
2. **値のソース**を選択します。**列**（テーブルの列の個別値）、**ディメンション**（ディメンションのノード）、**リスト**（手入力した値）のいずれかです。値の型は列のデータ型に従います。
3. セキュリティグループごとに、そのグループが表示できる値にチェックを入れます。グリッドには、プロジェクトへのアクセス権を持つグループと、その列にすでに付与を持つグループが一覧表示されます。
4. **Everyone else**を**sees all rows**または**sees no rows**に設定します。これは、グリッドでチェックのないすべてのグループに適用されます。
5. **保存**をクリックします。

保存すると即座に反映されます。PlaidCloud自身のクエリには変更がすぐに反映され、Supersetダッシュボードには約1分以内に反映されます。適用するための別の手順はなく、**保存**で確認が表示されるのは、付与された値がソースから失われている場合のみです（以下を参照）。画面の同期ステータスには、変更がどこまで進んだかが表示されます。[ダッシュボードとの同期の維持](#ダッシュボードとの同期の維持)を参照してください。

グリッドは、次のような細かな点も処理します。

- **多数の値。** 値は並べ替えられます。列の値がグリッドに収まらない場合、グリッドに「More values than fit here — type to search.」と表示され、フィルターボックスで列全体を検索できます。グループがすでに保持している値は、すべて保持されます。
- **ソースに存在しなくなった値。** グループに付与された値は、ソースからなくなってもグリッドに残ります。テーブルのどの行にもその値がなくなった場合、ディメンションからそのメンバーがなくなった場合、またはリストからその値がなくなった場合が該当します。その列のヘッダーには警告アイコンが表示され、ポイントすると理由が表示されます。**すべて選択**、**選択を反転**、**貼り付け**は、そのような値を各グループが保持している状態のままにします。チェックを外さない限り、付与から何も削除されることはありません。グループがそのような値を保持したまま**保存**をクリックすると、行アクセスは**Values No Longer in the Source**にグループと値を表示して確認します。**Keep and Save**はそのまま保存し、**Remove and Save**はまずすべてのグループの付与からそれらを削除します。確認ダイアログを閉じると何も保存されません。削除するとチェックがひとつもないグループが生じる場合は、**Everyone else**の設定に従って、そのグループがすべての行を表示するか、まったく表示しないかが確認ダイアログに表示されます。まだ保存していないチェックは、その値とともになくなります。列の値がグリッドに収まらない場合やテーブルがまだ構築されていない場合、行アクセスはテーブルにない値を判別できないため、付与されたすべての値を保持し、いずれにも印を付けません。
- **空白の値。** **空白の値 — 付与のあるすべてのグループに表示**チェックボックスが1つあり、列に値がない行の扱いを決めます。オンにすると、その列に付与を持つすべてのグループがそれらの行を表示できます。
- **まだ構築されていないテーブル**では、空のリストの代わりに**先にこのテーブルを構築してください（作成するワークフローを実行します）** と表示されます。
- **保存は画面上の値の読み込みを待ちます。** 値のソース、ディメンション、テーブルを切り替えた後や、テンプレートを適用した後など、値の読み込み中は**保存**が無効になり、「Save is available once this source's values load.」というツールチップが表示されます。読み込みに失敗した場合、グリッドにその旨が表示され、ソースを選び直すよう求められます。読み込みが成功するまで、何も保存されません。

### 1つの列名がすべてのテーブルに適用される

制限は、1つのテーブルではなく、プロジェクト上の列の*名前*に属します。`region` で行が制限されると、プロジェクト内の `region` という名前の列を持つすべてのテーブルが、PlaidCloud自身のクエリでもダッシュボードでも、その制限によってフィルターされます。グリッドの**Applies to**リストには、それらのテーブルが表示されます。リストは列名によって決まるため読み取り専用で、後から同じ列を持つテーブルを追加した場合も、公開された時点で対象になります。

プロジェクト内にその名前の列を持つテーブルがない場合、**Applies to 0 tables**が表示されることに加えて、テーブルが追加されるまでその制限がどのダッシュボードもフィルターしないという警告がウィンドウに表示されます。テーブルに列を追加するか、列名を修正すると、警告は消えます。

<Aside type="caution">
**列名は、大文字と小文字や空白も含めて完全に一致している必要があります。** `Region` と `region` は別の名前であり、`region` と末尾に空白のある `region ` も別の名前です。ピッカーには実在する列名のみが表示されるため、これが問題になるのは主に、別の場所で列名が変更された場合です。その場合、行アクセスは何も制限せずに放置するのではなく、警告を表示し、見つかった最も近い列を示します。
</Aside>

<Aside type="caution">
**行を制限するテーブルを公開すると、同じ手順でそのダッシュボードフィルターが設定されます。** ダッシュボードはテーブルを公開済みのレポートビュー経由で読み取るため、制限された列を持つテーブルを公開または再公開すると、PlaidCloudは公開が完了する前にそのテーブルのダッシュボードフィルターを登録します。登録できない場合は公開が拒否され、その試行で作成されたものはすべてロールバックされるため、制限されたテーブルがフィルターなしのままダッシュボードに残ることはありません。ビューのクエリは制限された列の名前を変更したり、そこから別の列を派生させたりできるため、行を制限するプロジェクトでは*ビュー*を公開できません。[テーブルの公開](/ja/guides/data/publish/)を参照してください。
</Aside>

### 制限の解除

グリッドの**制限を解除**は、インラインの確認を経て制限を削除します。確認メッセージは「‘region’による行の制限を解除しますか？ すべてのグループの付与が削除され、全員がその行を表示できるようになります。」です。その後、行アクセスは「‘region’の行はもう制限されていません。」と通知します。その列のSupersetデータセットも一緒に削除されますが、グラフがまだそれを使用している場合は削除されません。その場合、行アクセスはデータセットが残ること、およびそれを使用しているグラフの数を通知します。

行を制限している間は、列の名前変更や削除はできません。アーキテクトには、先に行アクセスで制限を解除するよう通知されます。それ以外のユーザーには、プロジェクトのアーキテクトに依頼するよう通知されます。

### 行を制限するプロジェクトを変更できるユーザー

プロジェクトのワークフロー、ステップ、ユーザー定義関数は、すべての行を読み取れるプロジェクト自身のサービスIDとして実行されます。それらを変更できるユーザーは、付与されていない行を、自分が読み取れるテーブルにコピーするステップを作成できてしまいます。そのため、プロジェクトで行を制限すると、プロジェクトの動作を変更できるユーザーも制限されます。プロジェクトが少なくとも1つの列を制限すると、次のようになります。

- **自動化はアーキテクト専用になります。** ワークフロー、ステップ、ユーザー定義関数、スケジュール、ワークフロー変数とプロジェクト変数、通知メールテンプレートを変更できるのは、プロジェクトのアーキテクトとテナント管理者だけです。同じ理由で、ワークフローバンドルのインポート、Alteryxワークフローの変換、プロジェクトへのインポート・コピー・復元、プロジェクトの接続環境、デフォルトのドキュメントアカウント、ERP転記モードの変更も同様です。それ以外のユーザーも、プロジェクトのワークフローを実行することはできます。**開始**、**停止**、**再開**、**選択したステップを実行**は引き続き利用できます。ステップエディター、ワークフローの作成コントロール、UDFエディター、スケジュールフォームは、これらのユーザーには読み取り専用で開き、依頼先のアーキテクトを示すバナーが表示されます。「このプロジェクトは行を制限しているため、ワークフロー、ステップ、UDF、スケジュール、変数、通知テンプレートを変更できるのはアーキテクトのみです。実行は引き続き可能です。」
- **制限された列が読み取るディメンションはアーキテクト専用です。** 誰がどの行を表示できるかを決めるディメンション（制限された列の値のソース）は、プロジェクトのアーキテクトまたはテナント管理者、およびプロジェクト自身のワークフローのみが変更できます。これには、ノードの追加、移動、名前変更、コピー、クリア、読み込み、復元、およびディメンション自体の操作が含まれます。それ以外のユーザーには、「このディメンションは‘region’のどの行を誰が表示できるかを決定するため、変更できるのはプロジェクトのアーキテクトのみです。」と通知されます。どの制限からも読み取られないディメンションには影響しません。
- **付与のソーステーブルはアーキテクト専用です。** 列の[付与のソース](#ソーステーブルへの付与のバインド)としてバインドされたテーブルの行の変更や削除ができるのは、プロジェクトのアーキテクト、テナント管理者、またはプロジェクトのワークフローだけです。これは、データエディター、インポート、コネクターによる読み込み、APIのいずれを通じても同じです。
- **プロジェクトのコピーはアーキテクト専用です。** コピーには「このコピーは行が制限されていません。」と表示されます。新しいプロジェクトには、設定するまで制限は引き継がれません。
- **以前のバージョンの復元も、他の変更と同様の変更です。** プロジェクト自体の設定や上記のディメンションを復元するには、プロジェクトのアーキテクトが必要です。復元は常に、そのバージョンが属する項目に適用されるため、これを回避するために別のプロジェクトを指定することはできません。[バージョン履歴](/ja/guides/projects/managing-projects/#バージョン履歴)を参照してください。
- **制限されたテーブルのデータ編集**にはアーキテクトが必要です。詳細は[行アクセスとデータエディター](#行アクセスとデータエディター)を参照してください。
- **制限されたテーブルへのDataFrameの書き込み、レコードの保存、クリアは、すべての行を表示できる場合を除き、自分の行にのみ影響します。** 詳細は[制限されたテーブルへのデータの読み込み](#制限されたテーブルへのデータの読み込み)を参照してください。
- **制限されたテーブルのインポート、コピー、ブランチの切り替え、復元、削除は、自分に見えない行がテーブルにある間は拒否されます。** 詳細は[制限されたテーブルへのデータの読み込み](#制限されたテーブルへのデータの読み込み)を参照してください。

プロジェクトで最初の列が制限される前に、行アクセスは影響を受けるユーザーを通知します。「ここで行を制限すると、このプロジェクトのワークフロー、ステップ、UDF、スケジュール、通知テンプレートを変更できるのはアーキテクトのみになります。現在、N人のメンバーがこれらを変更できます。実行は引き続き可能です。」

実行は、スケジュールされたものも含め、プロジェクトのサービスIDとして実行されるため、これまでとまったく同じように動作します。実行によって生成されるものは、アーキテクトが設計した内容に従います。制限された列を含まない出力テーブル、エクスポートファイル、通知メール、ログの行は、それを読むユーザーに対してフィルターされません。

**実行の開始時に指定する値。** ワークフローを実行できるユーザーは、変数に独自の値を指定して開始できます。[App Runner](/ja/guides/workflows/use-converted-alteryx-apps/#app-runnerフロントエンド)はフォームの回答でこれを行い、APIやAIツールでも可能です。これらの値はその実行にのみ有効で、ワークフローに保存されることはなく、他の実行、エクスポート、読み取りには見えません。実行はサービスIDとして行われるため、これらの値によってその実行が読み取る内容や書き込む内容が変わる可能性があります。ワークフローを実行する権限は、信頼できる人にのみ付与してください。

**行を制限しないプロジェクト。** これらのルールは、プロジェクトが列を制限した時点で初めて有効になります。何も制限していないプロジェクトでは、プロジェクトの自動化を変更できるユーザーが、プロジェクトのサービスIDとして実行されるステップやユーザー定義関数を作成し、プロジェクトのアクセスを変更して自分自身をアーキテクトにすることができます。これは仕様です。そのようなプロジェクトは行の分離を保証しません。そのため、作成権限はアーキテクトとして信頼できる人に限定するか、列を制限してください。

### ダッシュボードとの同期の維持

行アクセスは、変更がダッシュボードに届くまでの状況を、グリッドと、プロジェクトの「Security」タブの**同期**列に表示します。

| ステータス | 意味 |
|---|---|
| **待機中** | 変更は保存され、ダッシュボードへ送信中です。通常は約1分以内に解消されます。 |
| **再試行中** | 送信に失敗し、再試行しています。失敗の理由がステータスの横に表示され、すぐに再送信する**再試行**が用意されています。 |
| **未適用** | プロジェクトの制限は、まだダッシュボードに送信されていません。 |
| **適用済み** | 制限をダッシュボードに送信する最後の試行は成功しました。 |
| **ダッシュボードと同期済み** | 行アクセスは、ダッシュボードが適用している内容と自身が書き込む内容を比較し、一致していることを確認しました。 |
| **ダッシュボードと差異あり** | ダッシュボードは、行アクセスが書き込む内容を適用していません。Supersetでルールが変更または削除されたか、テーブルの公開ビューをチェックできません。 |
| **エラー** | 制限の送信に失敗しました。理由はステータスの横に表示されます。 |

変更が**適用済み**になると、グリッドはそれをダッシュボードと照合し、**ダッシュボードと同期済み**または**ダッシュボードと差異あり**に移行します。**ダッシュボードと差異あり**と**エラー**ではどちらも**再試行**が表示され、プロジェクトの制限が再送信されます。ステータスをまったく読み取れない場合、グリッドには「同期ステータスをチェックできませんでした。」と表示されます。

1つのテーブルが原因の**エラー**では、そのテーブル名と対処方法が表示されます。たとえば、制限された列なしで公開されたテーブル（「再公開するか、公開を解除してください。」）や、制限された列を持つのに公開されていないテーブルで、公開されるまでダッシュボードがフィルターできない場合などです。ステータスは**エラー**のままで、そのテーブルを公開するか、代わりに公開済みのテーブルで列を制限するまで、未公開のテーブルの名前が表示されます。そのようなテーブルがプロジェクトの他の部分を妨げることはなく、他のすべてのテーブルは同期されます。

ダッシュボードは、PlaidCloud自身のクエリと同じ付与に従います。

- **その列を持つ公開済みのすべてのテーブルがフィルターされます。** 制限を設定したときに表示していたテーブルだけではありません。
- **一部の値のみを付与されたグループは、他のユーザーがすべての行を表示できる場合でもフィルターされます。** これは、ダッシュボードのデータセットが存在するすべてのテーブルに適用されます。
- **プロジェクトのアーキテクトは、ダッシュボードでもすべての行を表示できます。** これはテーブルエクスプローラーやPlaidCloudの他の部分と同様です。これは、プロジェクトのアーキテクトグループと、個々のメンバーと共有されているプロジェクトのアーキテクトに適用されます。アーキテクトアクセスの取り消しは、メンバーのロールの変更、メンバーまたはそのグループのプロジェクトからの削除、プロジェクトのアクセスタイプの変更、以前のプロジェクトバージョンの復元、グループの削除のいずれの場合も、ダッシュボードですぐに有効になります。
- **セキュリティグループのメンバーシップの変更は、自動的にダッシュボードに反映されます。** PlaidCloudでのグループへのユーザーの追加や削除、メンバーの無効化や削除、グループの削除、デフォルトのセキュリティグループに参加する新しいメンバーの追加は、そのグループに値を付与しているすべてのプロジェクトで、誰も行アクセスを開き直すことなく、約1分以内にダッシュボードでの表示内容に反映されます。PlaidCloudの外部で行われたメンバーシップの変更（Keycloakでの直接変更や、サインイン時にシングルサインオンによってグループに所属させた場合）は、保存や再試行の必要なく、約15分以内にダッシュボードに反映されます。

### ディメンションの付与

値のソースに**ディメンション**を使用している場合、ノードにチェックを入れると、その配下のすべてが付与されます。付与はディメンションに追従します。チェックされたノードの配下に追加されたメンバーは、ディメンションの保存後の次回の同期でそのグループに付与され、その配下から移動または削除されたメンバーは付与されなくなります。グリッドを開き直す必要はありません。グリッドを開き直すと、チェックしたノードは再びチェックされた状態で表示されます。

ノードを通じてではなく個別にチェックしたメンバーは、ディメンションから削除されても付与されたままになり、グリッドではソースに存在しなくなった値として印が付けられます。

チェックされたノードの配下のいずれかのチェックを外すと、そのノードのチェックも外れ、グループにはまだチェックされているメンバーだけが残ります。そのメンバーを再度チェックしても、ノードは再びチェックされません。その場合は、ノード自体のチェックボックスをクリックしてください。**貼り付け**、**すべて選択**、**選択を反転**はメンバーをチェックし、ノードはチェックしません。

行アクセスの値として使用できない名前のディメンションメンバーは、保存時にその名前が示されて拒否されます。そのようなメンバーが後から現れた場合、その行は誰にも付与されず、同期ステータスにその名前が表示されます。「ディメンション‘…’のメンバー‘…’は行アクセスの値として使用できないため、その行は付与されません。ディメンションで名前を変更してください。」

### ソーステーブルへの付与のバインド

値を手作業でチェックする代わりに、制限された列を、答えをすでに保持しているソーステーブルに紐付けることができます。このテーブルには、グループと、そのグループが表示できる値が1行ずつ入っています。まずグリッドで列を制限し、次に、列、ソーステーブル、およびソーステーブルのグループ列と値の列を指定した[**行アクセスを設定**](/ja/reference/workflow-steps/tables/table-set-row-access/)ワークフローステップを追加します。ステップの最初の実行で、列がそのテーブルにバインドされます。列に手動で設定された付与はクリアされ、付与はテーブルの行から設定されます。

バインドされると、その列は**ソース所有**になります。行アクセスのグリッドではその列がロックされた状態で表示され、ソーステーブルを示すバッジが付き、**バインディングを削除**をクリックするまで、付与の手動編集は拒否されます。

ステップの以降の実行のたびに、ソーステーブルが再読み込みされ、付与が再適用されます。そのテーブルを読み込む、または更新するワークフローの後に実行するようスケジュールしておけば、ソースデータでグループが追加、削除、再割り当てされた場合に、次の実行で行アクセスに反映され、グリッドを手作業で編集する必要はありません。

ソーステーブルが誰に何を表示するかを決めるため、その行の変更やテーブルの削除ができるのは、プロジェクトのアーキテクト、テナント管理者、またはプロジェクト自身のワークフローだけです。それ以外のユーザーには、「このテーブルは‘region’の行アクセスの付与を提供しているため、その行の変更やテーブルの削除ができるのはプロジェクトのアーキテクトのみです。」と通知されます。

### 制限テンプレート

同じ値のソース、値の型、空白値の設定といった、再利用したい制限の形を作成した場合は、一度保存しておけば、列ごとに作り直す代わりに、必要な場所に適用できます。

- **テンプレートとして保存…** は、開いている行アクセス画面で、現在の列の形を、名前を付けたテナントレベルのテンプレートとして保存します。保存されるのは形のみで、付与は引き継がれません。
- **テンプレートを適用**は、別のプロジェクトの列で、テンプレートの形から開始します。すべてのグループの付与は空になっているため、自分で入力します。

プロジェクトのアーキテクトであれば、誰でもテンプレートを保存および適用できます。テンプレートはテナント全体で共有されるため、名前の変更（**名前の変更…**）と削除（**削除**）にはテナント管理者が必要です。テンプレートを削除しても、そのテンプレートを適用した列は制限されたままです。

<Aside type="note">
テンプレートはリンクではなくコピーです。テンプレートを後から編集しても、すでにそれを適用した列は変更されません。後の改訂内容に列を合わせるには、テンプレートを再度適用してください。
</Aside>

### SSOグループ属性からの付与

列は、PlaidCloudではなくIDプロバイダーから付与を取得することもできます。プロジェクトのアーキテクトは、行アクセスで**Accept row-access grants from SSO group attributes**を有効にして、列をオプトインします。

有効にすると、セキュリティグループのKeycloak属性 `row_access.<column>` が、そのグループがその列を通じて表示できる値を設定します。Keycloakでグループに属性を設定すると、すでにプロジェクトへのアクセス権を持つグループについて、PlaidCloudが自動的に取り込みます。行アクセス自体で設定する項目はこれ以上なく、付与はPlaidCloud自身のクエリとSupersetダッシュボードの両方で同期されたままになります。

<Aside type="caution">
これは、すでにプロジェクトにアクセスできるグループにのみ値を付与します。プロジェクトへのアクセス権がないグループに `row_access.region` を追加しても、そのグループがプロジェクトへのアクセスも付与されるまで、何も付与されません。
</Aside>

### 保存前のプレビュー

行アクセスでは、変更を確定する前に、その意味を確認できます。

- **プレビュー表示ユーザー…** フッターには、テーブルの総行数のうちグループが表示できる行数と、実際の行のサンプルが表示されます。グリッドで任意のグループを選択すると、そのグループをプレビューできます。プレビューは保存後に更新されます。
- 保存前に、注意が必要な事項について行アクセスが警告します。チェックのないグループ（**Everyone else**の設定に従って、すべての行を表示するのかまったく表示しないのかも含む）、プロジェクトアクセスを持つがどのグループの付与にも含まれていないメンバー、およびその列の値が空白（`NULL`）で、どのグループにも付与されていない行です。

### 制限されたメンバーに表示される内容

制限されたメンバーが名前でテーブルを読み取る場所では、どこでも自分の行のみが取得されます。これには、テーブルエクスプローラーのグリッド、列のファセットとダウンロード、テーブルのダウンロードダイアログ、ビューアーとして読み取るアプリやツール、ダッシュボードが含まれます。テーブルエクスプローラーでは、表示しているグリッドが付与によってフィルターされている場合、ツールバーに**アクセス権により行が制限されています**と表示され、フィルターされるダウンロードを開始するときにも「アクセス権により行が制限されています。」と表示されます。すべての行を読み取るアーキテクトには、どちらの通知も表示されません。

### 行アクセスとご自身で記述するクエリ

行アクセスによって表示できる行が制限されている場合でも、プロジェクトのクエリ画面で独自のSQLクエリを実行し、付与で許可された行だけを正確に取得できます。結果はCSV、Excel、JSONにエクスポートでき、エクスポートにはそれらの行だけが含まれ、**アクセス権により行が制限されています**という通知が付きます。プロジェクトのアーキテクトは、すべての制限された列のすべての値を自分に付与できるため、すべての行を読み取り、通知は表示されません。

パーセント記号（`%`）を含む付与値では、クエリ画面で付与された行が返され、そのようなクエリをCSVとしてダウンロードすることもできます。

プロジェクトのアーキテクトではないメンバーに対しては、次の操作は引き続き拒否されます。

- SnowflakeまたはDatabricksのプロジェクトウェアハウスで、独自の自由形式SQLを実行する。
- Postgres系のウェアハウスから、独自のSQLの結果をエクスポートする。
- 独自のSQLの結果を別のデータベースにエクスポートする。
- ファンアウトステップの「Test row 1」プレビューに行条件を入力する。
- 制限されたテーブルを、以前のスナップショットの時点で読み取る（タイムトラベル）。

拒否されたユーザーには、どのプロジェクトだったかが通知され、名前による読み取り方法が案内されます。名前によるテーブルの読み取りは、アプリやツールがデータを読み取る通常の方法であり、付与が適用され、ビューアーが表示できる行が返されます。単一のテーブルに対するプレーンなクエリとして記述された列のファセットも名前で読み取られるため、拒否されることなく、メンバー自身の値が返されます。プロジェクトのアーキテクトは、これらをすべて記述したとおりに実行できます。

行アクセスはビューを制限された列でフィルターするため、ビューではその列を元の名前のまま保持する必要があります。制限された列を除外したり名前を変更したりするビューはフィルターされません。

スプレッドシートのインポートは、それ自体では自分で記述したクエリではありません。通常のファイルインポートは制限されたデータをまったく読み取らず、アップロードしたファイルからプロジェクト自身の新しいテーブルを作成するだけなので、行アクセスの影響を受けません。例外は、データの射影が呼び出し元から指定されるインポート、つまり列ごとの式や動的なExcelマッピングです。対話型のインポート画面では、これらは上記の自由形式SQLの画面と同様に拒否され、プロジェクトのアーキテクトが必要になります。呼び出し元が指定した射影は別のテーブルを読み取れる可能性があるためです。ワークフローから実行されるインポートは、プロジェクト自身のサービスIDで実行されるため、どちらの場合も影響を受けません。

<Aside type="caution">
プロジェクトで最初の列を制限すると、それを使用するすべてのユーザーに影響が及びます。そのプロジェクトのPanelアプリ、ノートブック、連携が、SnowflakeまたはDatabricksのウェアハウスで独自にSQLを組み立てている場合や、Postgres系のウェアハウスから独自のクエリ結果をエクスポートしている場合は、制限する前に、名前でテーブルを読み取るように切り替えてください。そうしないと、アーキテクト以外のすべてのユーザーに対して動作しなくなります。
</Aside>

### 行アクセスとデータエディター

データエディターはテーブルを直接読み書きするため、行アクセスは読み取りと書き込みの両方に適用されます。

制限されたテーブルをデータエディターで開くと、自分のセキュリティグループに付与された行のみが表示されます。これはダッシュボードでも同様のフィルターであり、制限された列がグリッドに表示される列に含まれていない場合でも適用されます。

編集内容を保存するには、プロジェクトの**アーキテクト**が必要です。保存はテーブルの行を読み取らずに丸ごと置き換え、行単位でフィルターされないため、制限されたテーブルのデータ編集は読み取りではなく作成操作として扱われ、アーキテクトでないユーザーには、それが必要であると通知されます。制限された列を持たないテーブルは、従来どおり編集でき、行を制限しないプロジェクトも同様です。

### 制限されたテーブルへのデータの読み込み

行アクセスで表示できる行が制限されている場合、Pythonクライアント（`PlaidConnection`）でDataFrameを制限されたテーブルに書き込む、またはクリアする操作や、REST APIでレコードを保存する、またはクリアする操作は、自分の行にのみ作用します。テーブルのデータを置き換えると、自分に見える行だけが置き換えられ、クリアすると、それらの行だけがクリアされ、追加では行が加わります。それ以外の行はそのまま残ります。

アクセス権の範囲外の行を含む読み込みは、何も変更される前に拒否され、エラーにはアクセス権の範囲外の各値と、その値を持つ行数が示されます。制限された列を省略した行は、その列が空白であるものとして確認されるため、アクセス権に空白の行が含まれていない限り拒否されます。列の型が変わるようなデータの置き換えも拒否されます。その変更はプロジェクトのアーキテクトに依頼してください。

プロジェクトのアーキテクト、付与がすべての行を対象とするメンバー、およびプロジェクトのサービスIDとして実行されるワークフローの実行は、従来どおりテーブル全体を書き込みます。制限された列を持たないテーブルは影響を受けません。

制限されたテーブル全体を置き換えたり削除したりするその他の操作は、自分に見えない行がテーブルにある間は拒否され、何も変更されません。該当するのは、ファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えやマージ、アーカイブからの復元やプロジェクトの保留スナップショットの復元の一環としての復元、削除、削除後の復旧、および再び埋める前にテーブルを空にするその他の操作です。制限された列が空白の行は、アクセス権に空白の行が含まれていない限り、見えない行として扱われます。すべての行が見えるテーブル（たとえば自分の行だけを含む、自分で作成したテーブル）は、従来どおり置き換えや削除ができます。

人が任意のテーブルに対して行うこれらの書き込みは、拒否されたものも含め、セキュリティログに記録されます。ワークフローの実行は、そこには記録されません。

### 行数とテーブルサイズ

テーブルの行数とストレージサイズは、表示できる行ではなくテーブル全体を表すため、制限された閲覧者に、付与範囲を超えて存在する行数が知られてしまいます。行を制限するプロジェクトでは、読み取りがフィルターされるユーザーには、プロジェクトのどのテーブルについても行数やサイズが表示されません。これは、テーブル一覧、検索、テーブルの詳細、スナップショット、およびMCP経由で接続されたAIアシスタントとAIツールに適用されます。これには、制限された列を持たないテーブルも含め、プロジェクト内のすべてのテーブルが対象です。プロジェクト自体の合計も、ホーム、プロジェクト一覧と検索、プロジェクトの詳細における合計行数とサイズを含め、非表示になります。

ワークフローの実行履歴にも同じことが適用されます。各実行とステップが記録した読み取り行数と書き込み行数もテーブル全体を表すため、同じ閲覧者に対しては、ワークフローとステップの実行履歴、およびMCP経由で接続されたAIアシスタントとAIツールで、これらの数値は空白になります。これらのユーザーに対して、[Weave](/ja/guides/ai-assistant/weave-findings/)は、検出事項自体がテーブル全体の行数が変化したことを知らせてしまうため、ステップの行数や空の値が過去の実行と異なっていないかをチェックしません。

プロジェクトのアーキテクトには従来どおり数値が表示され、行を制限しないプロジェクトの全員にも同様に表示されます。

### メンバーに表示される内容の確認

グループに付与された内容ではなく、特定の人が何を表示できるかを確認するには、**Identity → Member**を開き、メンバーを選択して、その**行アクセス**タブを開きます。その**有効なアクセス**列には、制限されたすべてのプロジェクトと列について、そのメンバーがすべてのグループを合わせて表示できる値が一覧表示されます。これにはSSOグループ属性からの付与や、グループの付与に含まれている場合の空白（`NULL`）の行も含まれます。プロジェクトのアーキテクトはすべての行を読み取るため、**すべての行を表示（アーキテクト）** と表示されます。これはPlaidCloud自身のクエリが適用するのと同じ答えであるため、サポートの場面や、問題が報告される前に変更が意図したとおりに動作したかを確認する場合に役立ちます。

### より分かりやすいエラー

行アクセスがアクションをブロックする場合（制限されたプロジェクトで自分で記述したクエリ、アーキテクトなしでの編集、自動化・ディメンション・付与のソーステーブルの変更、および上記のその他のケース）、メッセージには、汎用的なエラーではなく、何が制限されているか、および次に何をすべきか（依頼先のアーキテクトなど）が示されます。

### 行アクセスは監査される

列の制限や制限の解除、およびグループの付与の編集は、いずれもそのプロジェクトの[プロジェクトログ](/ja/get-started/tutorials/collaborate-versions-and-sharing/#プロジェクトログを読む)にエントリとして記録され、誰がいつ変更したかが分かります。確認するには、プロジェクトの**Analyze → Projects → Log**を開きます。この記録を取得するために行アクセスで何かを有効にする必要はなく、プロジェクトの他の追跡対象の変更と同じ方法で記録されます。

## デフォルトのセキュリティグループの設定


新しいメンバーを追加する時間を短縮するため、デフォルトのセキュリティグループのセットを指定します。これにより、各ユーザーを手動で割り当てることなく、新しいメンバーに基本となるセキュリティグループのセットが付与されます。この設定は、新しいセキュリティグループを追加する際に、「セキュリティグループ」ウィンドウの下部にある「Assign to New Users by Default」というチェックボックスをオンにすると利用できます。



## セキュリティ監査の実施


セキュリティ監査機能では、すべてのメンバーとグループにわたるグループメンバーシップを確認できます。



**セキュリティ監査を実施するには：**


1. Identityを開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューで「Security Group Audit」をクリックします

PlaidCloudのすべてのテーブルはCSVファイル形式でエクスポートできるため、グループとメンバーの関連付けは、履歴の確認用として、あるいはオフラインで気軽に眺める目的で、PlaidCloudの外部で確認できます。



**「Security Group Audit」フォームからエクスポートするには：**


1. Identityを開きます
2. 「Security」タブを選択します
3. ドロップダウンメニューで「Security Group Audit」をクリックします
4. テーブルの「Username」の右端にある小さなアイコンをクリックします
5. 使用したい形式に応じて、「Export CSV」または「Export XLXS」をクリックします

## 利用可能な権限設定の確認


ワークスペースで使用される各アプリケーションには、それぞれ利用可能な権限があります。セキュリティグループの権限は、これらのアプリケーション権限に基づいています。


各アプリケーションで利用可能なすべての権限の一覧は、Security Binで確認できます。



**Security Binにアクセスするには：**


1. Identityを開きます
2. 「Security」を選択します
3. ドロップダウンメニューで「Security Bins」をクリックします

各アプリケーションの詳細なセキュリティ設定を確認するには、左端のタグアイコンを選択します。



この利用可能なセキュリティ設定の情報は、参考情報です。権限の管理の詳細については、上記の「セキュリティグループの管理」セクションを参照してください。
