PlaidCloudのセキュリティとアクセスの管理はシンプルです。メンバーは、所属しているグループに基づいてアクセスが許可または拒否されます。メンバーのセキュリティ上の関連付けは、簡単に追加・変更できます。

<Aside>各ワークスペースで作成できるセキュリティグループの数に上限はありませんが、セキュリティ管理を容易にするため、数を最小限に抑えることをお勧めします。</Aside>



## セキュリティグループの管理


セキュリティグループは、追加、更新、削除できます。



**セキュリティグループを管理するには：**


1. Identityを開きます
2. レールで**セキュリティグループ**を選択します（既存のグループの一覧が表示されます）
3. グループを追加するには、**New group**をクリックします
4. グループの権限を編集するには、左端のアイコンをクリックします

**グループのメンバーを管理するには：**


1. Identityを開きます
2. レールで**セキュリティグループ**を選択します
3. メンバーアイコンをクリックします
4. グループに所属させるメンバーにチェックを入れ、所属させないメンバーのチェックを外します。フィルターボックスを使うと、ユーザーを検索できます。[ピッカーによる割り当て](#ピッカーによる割り当て)を参照してください
5. **割り当てを更新**をクリックします

<Aside>誰も割り当てずに保存しても変更は行われず、その旨が通知されます。グループをすべてのユーザーから外すには、メンバーシップを空にするのではなく、グループの権限を削除するか、グループを削除してください。</Aside>

<Aside>グループに[行アクセス](#行アクセスの管理)で行が付与されている場合、メンバーシップの変更は約1分以内にダッシュボードに反映されます。追加したユーザーにはダッシュボードでそのグループの行が表示され、削除したユーザーには表示されなくなります。メンバーの無効化や削除、グループの削除も同様に反映されます。</Aside>

<Aside type="caution">自分では付与できない権限は、グループの権限マトリックスを保存する際には変更されず、マトリックスにも表示されません。そのような権限を変更する必要がある場合は、その権限を持つユーザーに依頼してください。マトリックスで編集できるのは、自分が管理できる権限のみです。</Aside>

<Aside type="caution">メンバーをグループに追加したり、メンバーのグループを選択したりできるのは、そのグループが付与するすべての権限を自分が持っている場合に限られます。アーキテクトとしてユーザーを招待する場合も同様です。ワークスペース管理者にはこの制限はありません。</Aside>

## ピッカーによる割り当て

人、グループ、その他の項目にアクセス権を付与する場所ではどこでも、従来の2つのリストに代わって1つのチェックリストが使われます。各行にはチェックボックスがあり、チェックされた行が割り当て済みです。各行には、名前とメールアドレスが別々の列に表示されます。このチェックリストは、グループのメンバー、メンバーのセキュリティグループ、アカウントのメンバー・グループ・エージェント・所有者、接続のアクセス、配信リストのワークスペースメンバー、Weaveの準備状況セットのワークフローを設定するときに使用します。

- **フィルター**：フィルターボックスに入力すると、リストが絞り込まれます。一致は部分一致で、大文字と小文字は区別されないため、`smith`と入力すると、その文字列を含むすべての名前またはメールアドレスが見つかり、`@example.com`と入力するとそのドメインのすべてのユーザーが見つかります。複数の単語を入力すると、そのすべてに一致する行のみが残ります。
- **メールアドレスの一覧の貼り付け**：スペース、カンマ、セミコロン、改行で区切った複数のメールアドレスを貼り付けると、リストにはそれらのユーザーだけが表示されます。`@example.com`のようなドメイン全体を混在させることもできます。フィルターの下の行には、貼り付けた項目のうち何件が一致したかが表示され、見つからなかった項目があればその一覧も表示されます。**Assign**の後に一致した件数が続くボタンをクリックすると、一致したすべてのユーザーを一度にチェックできます。
- **All、Assigned、Not assigned**：リストの上にある3つのボタンで、すべて、割り当て済みのみ、未割り当てのみの表示を切り替えます。それぞれに件数が表示されます。フィルターと組み合わせて使えます。
- **Assign all shown と Unassign all shown**：フィルターとビューで現在表示されているすべての行をチェックまたは解除します。非表示の行には影響しません。リストの上の行には、合計のうち何行が表示されているかが示されます。
- **Will add と Will remove**：保存ボタンをクリックするまで、何も保存されません。チェックを入れた行には色が付き、**Will add**のピルが表示されます。チェックを外した行には**Will remove**が表示されます。リストの上のサマリーには、割り当て済みの件数と保留中の変更が表示されます。サマリーは、たとえば`12 assigned · +3 to add · −1 to remove`のように表示されます。**変更を元に戻す**をクリックすると、ウィンドウを開いた時点の状態にすべて戻ります。
- **変更があったときのみ保存**：**割り当てを更新**、**メンバーを更新**、**グループを更新**などの保存ボタンは、変更を加えたときにのみ使用できます。
- **キーボード**：**スペース**キーで、選択した行のチェックを入れたり外したりします。フィルターボックスで**Enter**キーを押しても保存されないため、検索中にアクセスが変更されることはありません。

誰がアクセス権を持っているかは確認できても変更できない場合（たとえば、所有していない接続）は、ピッカーは読み取り専用になります。その旨がメモで表示され、すでに割り当てられているユーザーのみが、チェックボックスの代わりにイニシャルとともに一覧表示され、変更するためのボタンは表示されません。

## 行アクセスの管理

行アクセスは、1つの列の値に基づいて、セキュリティグループがテーブルのどの行を表示できるかを制限します。たとえば、`region`列でアクセスを制限し、`East`と`Central`が付与されたグループには、それらの値を持つ行のみを表示するようにできます。プロジェクトと列に関するすべての作業（列の選択、値の取得元の選択、どのグループに何を表示するかの決定）は1つの画面で行い、保存すると直ちに有効になります。

行アクセスの設定と変更には、プロジェクトのアーキテクトまたはテナント管理者が必要です。それ以外のユーザーがプロジェクトの「セキュリティ」タブを開くと、行アクセスはアーキテクト専用であることが通知され、以下の入口は表示されません。

### 行アクセスを開く

どの入口からでも、同じ行アクセス画面が開きます。

- **テーブルエクスプローラーのツールバー**には**行アクセス**ボタンがあります。テーブルがすでに行を制限している場合は、バッジが表示されます。テーブルで最初に制限されている列があれば、その列で開き、テーブルの他の任意の列に切り替えることもできます。
- **列のファセットメニュー**には**この列で行を制限…** メニュー項目があり、その列で行アクセスが開きます。すでに行を制限している列では、この項目の表示は**この列で行を制限中 - 編集…** メニュー項目になります。
- **プロジェクトのセキュリティタブ**には、プロジェクトで制限されているすべての列が、適用先のテーブル、付与を持つグループ、その**同期**の状態とともに一覧表示されます。列を選択して編集するか、**列を制限…** ボタンをクリックして新しい制限を開始します。テーブルを選び、次に列を選びます。すでに行を制限している列には、鍵のマークが付きます。
- **Identity → メンバー**のメンバーの**行アクセス**タブと、**Identity → セキュリティ → セキュリティグループ**のグループの行アクセスのサマリー。**行アクセスを開く**（または**編集**）をクリックすると、選択した列が開きます。**追加**をクリックすると、その行のプロジェクトで別の列を制限できます。

列を指定して開いた場合、画面はその列のままになります。**列を制限…** ボタンまたは**追加**ボタンから開いた場合は、列を選択できます。

### 行アクセスのグリッド

列を使ってテーブルを制限するには：

1. 上記のいずれかの入口から行アクセスを開き、列を指定せずに開いた場合は列を選択します。ピッカーには、自由入力ではなく、テーブルの実際の列が表示されます。
2. **値のソース**を選択します。**列**（テーブルの列の個別の値）、**ディメンション**（ディメンションのノード）、**リスト**（手入力した値）のいずれかです。値の型は、列のデータ型に従います。
3. セキュリティグループごとに、そのグループが表示できる値にチェックを入れます。グリッドには、プロジェクトへのアクセス権を持つグループと、その列にすでに付与を持っているグループが一覧表示されます。
4. **Everyone else**を**sees all rows**または**sees no rows**に設定します。これは、グリッドでチェックがないすべてのグループに適用されます。
5. **保存**をクリックします。

保存は即時に反映されます。PlaidCloud自身のクエリには変更が直ちに反映され、Supersetダッシュボードには約1分以内に反映されます。変更を適用するための別の手順はなく、**保存**で確認が表示されるのは、グループが付与されている値がそのソースにもう存在しない場合のみです（以下を参照）。画面の同期ステータスには、変更がどこまで進んでいるかが表示されます。[ダッシュボードの同期の維持](#ダッシュボードの同期の維持)を参照してください。

グリッドは、次のような細かい点も処理します。

- **多数の値**：値は並べ替えられます。列の値が多くて表示しきれない場合、グリッドには「More values than fit here — type to search.」と表示され、フィルターボックスで列全体を検索できます。グループがすでに保持している値は、すべて保持されます。
- **ソースにもう存在しない値**：グループに付与された値は、そのソースから失われても（テーブルのどの行にも存在しなくなった、ディメンションからメンバーがなくなった、リストから値がなくなった場合）、グリッドに残ります。その列ヘッダーには警告アイコンが表示され、ポイントすると理由が表示されます。**すべて選択**、**選択を反転**、**貼り付け**を実行しても、そのような値は各グループが保持している状態のままです。チェックを外さない限り、付与から何も削除されません。グループがそのような値を保持したまま**保存**をクリックすると、行アクセスは**Values No Longer in the Source**にグループと値の名前を表示して確認します。**Keep and Save**はそのまま保存し、**Remove and Save**は先にすべてのグループの付与からそれらを削除します。確認を閉じた場合は何も保存されません。削除するとグループのチェックがすべてなくなる場合は、**Everyone else**の設定に従って、そのグループがすべての行を表示するのか、まったく表示しないのかが確認に示されます。まだ保存していないチェックは、その値とともに失われます。列の値が多すぎて表示しきれない場合や、テーブルがまだ構築されていない場合、行アクセスはテーブルにない値を判別できないため、付与されたすべての値をマークなしで保持します。
- **空白の値**：**空白の値 — 付与のあるすべてのグループに表示**チェックボックスが1つあり、列に値がない行の扱いを決定します。チェックを入れると、その列に何らかの付与を持つすべてのグループに、それらの行が表示されます。
- **まだ構築されていないテーブル**では、空のリストの代わりに**先にこのテーブルを構築してください（作成するワークフローを実行します）** と表示されます。
- **保存は画面上の値の読み込みを待ちます**：値の読み込み中（値のソース、ディメンション、テーブルを切り替えた後、またはテンプレートを適用した後）は、**保存**が無効になり、ツールチップに「Save is available once this source's values load.」と表示されます。読み込みに失敗した場合、グリッドにその旨が表示され、ソースを選び直すよう求められます。読み込みが成功するまで、何も保存されません。

### 1つの列名、すべてのテーブル

制限は、単一のテーブルではなく、プロジェクト内の列*名*に属します。`region`で行が制限されると、プロジェクト内の`region`という名前の列を持つすべてのテーブルが、PlaidCloud自身のクエリでもダッシュボードでも、その制限によってフィルターされます。グリッドの**Applies to**リストには、それらのテーブルが表示されます。列名で決まるため、このリストは読み取り専用です。後から同じ列を持つテーブルを追加した場合も、公開された時点で対象になります。

プロジェクト内にその名前の列を持つテーブルがない場合、ウィンドウには**Applies to 0 tables**が表示されることに加えて、テーブルが追加されるまでその制限はどのダッシュボードもフィルターしないという警告が表示されます。テーブルに列を追加するか、列名を修正すると、警告は消えます。

<Aside type="caution">
**列名は、大文字と小文字、空白を含めて完全に一致する必要があります。**`Region`と`region`は別の名前であり、`region`と末尾にスペースのある`region `も別の名前です。ピッカーには実際の列名のみが表示されるため、これが問題になるのは主に、列が別の場所で名前変更された場合です。その場合、行アクセスは何も制限しないまま黙って処理を続けるのではなく、警告を表示し、見つかった最も近い列の名前を示します。
</Aside>

<Aside type="caution">
**行を制限するテーブルを公開すると、同じ手順でそのダッシュボードフィルターも設定されます。** ダッシュボードは、テーブルを公開されたレポート用ビューを通じて読み取ります。そのため、制限された列を持つテーブルを公開または再公開すると、PlaidCloudは公開が完了する前に、そのテーブルのダッシュボードフィルターを登録します。登録できない場合は公開が拒否され、その試行で作成されたものはロールバックされるため、制限されたテーブルがフィルターされないままダッシュボードに残ることはありません。ビューのクエリは制限された列の名前を変更したり、導出したりできるため、行を制限するプロジェクトでは*ビュー*を公開できません。[テーブルの公開](/ja/guides/data/publish/)を参照してください。
</Aside>

### 制限の解除

グリッドの**制限を解除**をクリックし、インラインの確認に応じると、制限が削除されます。確認メッセージは「Stop restricting rows by ‘region’? Every group's grant on it is removed and everyone sees its rows.」です。その後、行アクセスに「Rows in ‘region’ are no longer restricted.」と表示されます。チャートがまだ使用している場合を除き、その列のSupersetデータセットも一緒に削除されます。使用している場合は、データセットが残ることと、それを使用しているチャートの数が行アクセスに表示されます。

行を制限している列は、名前の変更も削除もできません。アーキテクトには、まず行アクセスで制限を解除するよう通知されます。それ以外のユーザーには、プロジェクトのアーキテクトに依頼するよう通知されます。

### 行を制限しているプロジェクトを変更できるユーザー

プロジェクトのワークフロー、ステップ、ユーザー定義関数は、すべての行を読み取れるプロジェクト自身のサービスIDとして実行されます。これらを変更できるユーザーは、付与されていない行を、自分が読み取れるテーブルにコピーするステップを作成できてしまいます。そのため、プロジェクトで行を制限すると、プロジェクトの動作を変更できるユーザーも制限されます。プロジェクトで少なくとも1つの列が制限されると、次のようになります。

- **自動化はアーキテクト専用になります。** ワークフロー、ステップ、ユーザー定義関数、スケジュール、ワークフロー変数とプロジェクト変数、通知メールテンプレートを変更できるのは、プロジェクトのアーキテクトとテナント管理者のみです。同じ理由で、ワークフローバンドルのインポート、Alteryxワークフローの変換、プロジェクトへのインポート・コピー・復元、プロジェクトの接続環境、デフォルトのドキュメントアカウント、ERP転記モードの変更も、これらのユーザーに限られます。それ以外のユーザーも、プロジェクトのワークフローを実行することはできます。**開始**、**停止**、**再開**、**選択したステップを実行**は引き続き使用できます。ステップエディター、ワークフローの編集コントロール、UDFエディター、スケジュールフォームは、これらのユーザーには読み取り専用で開き、依頼すべきアーキテクトを示すバナーが表示されます。「This project restricts rows, so only its Architects can change workflows, steps, UDFs, schedules, variables and notify templates. You can still run them.」
- **制限された列が読み取るディメンションはアーキテクト専用です。** 誰がどの行を表示できるかを決定するディメンション（制限された列の値のソース）を変更できるのは、プロジェクトのアーキテクトまたはテナント管理者と、プロジェクト自身のワークフローのみです。これには、ノードの追加、移動、名前の変更、コピー、クリア、読み込み、復元と、ディメンション自体の変更が含まれます。それ以外のユーザーには「This dimension decides who sees which rows of ‘region’, so only a project Architect can change it.」と通知されます。どの制限にも読み取られていないディメンションには影響しません。
- **付与のソーステーブルはアーキテクト専用です。** 列の[付与のソース](#付与のソーステーブルへのバインド)としてバインドされたテーブルは、行の変更や削除を、プロジェクトのアーキテクト、テナント管理者、またはプロジェクトのワークフローのみが行えます。データエディター、インポート、コネクターのロード、APIのいずれを通じた場合も同様です。
- **プロジェクトのコピーはアーキテクト専用です。** また、コピーには「This copy is not row-restricted.」と表示されます。新しいプロジェクトには、制限を設定するまで制限はありません。
- **以前のバージョンの復元も、他の変更と同様の変更です。** プロジェクト自体の設定、または上記のディメンションを復元するには、プロジェクトのアーキテクトが必要です。復元は常に、そのバージョンが属する項目に適用されるため、これを回避するために別のプロジェクトを指定することはできません。[バージョン履歴](/ja/guides/projects/managing-projects/#バージョン履歴)を参照してください。
- **制限されたテーブルのデータの編集**にはアーキテクトが必要です。[行アクセスとデータエディター](#行アクセスとデータエディター)を参照してください。
- **制限されたテーブルへのDataFrameの書き込み、レコードの保存、クリアでは、すべての行が見える場合を除き、自分の行のみが変更されます。**[制限されたテーブルへのデータの読み込み](#制限されたテーブルへのデータの読み込み)を参照してください。
- **制限されたテーブルのインポート、コピー、ブランチの切り替え、復元、削除は、見えない行がテーブルにある間は拒否されます。**[制限されたテーブルへのデータの読み込み](#制限されたテーブルへのデータの読み込み)を参照してください。

プロジェクトで最初の列が制限される前に、行アクセスは影響を受けるユーザーを通知します。「Restricting rows here means only Architects can change this project's workflows, steps, UDFs, schedules and notify templates. N members can change them today; they will still be able to run them.」

実行は、スケジュールされたものも含めて、プロジェクトのサービスIDとして実行されるため、これまでどおりに動作します。実行によって生成されるもの（制限された列のない出力テーブル、エクスポートファイル、通知メール、ログ行）は、アーキテクトが設計した内容に従い、それを読むユーザーのためにフィルターされることはありません。

**実行の開始時に指定する値。** ワークフローを実行できるユーザーは、変数に独自の値を指定してワークフローを開始できます。[アプリランナー](/ja/guides/workflows/use-converted-alteryx-apps/#app-runner-フロントエンド)はフォームの回答でこれを行い、APIとAIツールでも可能です。これらの値はその実行のみで有効で、ワークフローに保存されることはなく、他の実行、エクスポート、閲覧者から見えることもありません。実行はサービスIDとして行われるため、これらの値によってその実行が読み書きする内容が変わる可能性があります。ワークフローを実行する権限は、信頼できる人にのみ付与してください。

**行を制限していないプロジェクト。** これらのルールは、プロジェクトで列が制限された時点で初めて有効になります。何も制限していないプロジェクトでは、プロジェクトの自動化を変更できるユーザーが、プロジェクトのサービスIDとして実行されるステップまたはユーザー定義関数を作成し、プロジェクトのアクセス権を変更して、自分自身をアーキテクトの1人にすることができます。これは仕様です。そのようなプロジェクトでは、行の分離は保証されません。そのようなプロジェクトでは、アーキテクトとして信頼できるユーザーにのみ編集権限を付与するか、列を制限してください。

### ダッシュボードの同期の維持

行アクセスは、変更がダッシュボードに届くまでの状況を、グリッドと、プロジェクトのセキュリティタブの**同期**列に表示します。

| ステータス | 意味 |
|---|---|
| **待機中** | 変更が保存され、ダッシュボードに送信中です。通常は約1分以内に完了します。 |
| **再試行中** | 送信に失敗し、再試行しています。失敗の理由がステータスの横に表示され、**再試行**で直ちに再送信できます。 |
| **未適用** | プロジェクトの制限は、まだダッシュボードに送信されていません。 |
| **適用済み** | 制限をダッシュボードに送信する直近の試行が成功しました。 |
| **ダッシュボードと同期済み** | 行アクセスは、ダッシュボードが適用している内容と、行アクセスが書き込む内容を比較し、両者が一致しています。 |
| **ダッシュボードと差異あり** | ダッシュボードが、行アクセスが書き込む内容を適用していません。Supersetでルールが変更または削除されたか、テーブルの公開ビューを確認できません。 |
| **エラー** | 制限の送信に失敗しました。理由がステータスの横に表示されます。 |

変更が**適用済み**になると、グリッドはそれをダッシュボードと照合し、**ダッシュボードと同期済み**または**ダッシュボードと差異あり**に移行します。**ダッシュボードと差異あり**と**エラー**には、どちらもプロジェクトの制限を再送信する**再試行**が表示されます。ステータスをまったく読み取れない場合、グリッドには「Couldn't check sync status.」と表示されます。

1つのテーブルが原因の**エラー**では、そのテーブルの名前と対処方法が表示されます。たとえば、制限された列なしで公開されたテーブル（「Republish or unpublish it.」）や、制限された列を持つ未公開のテーブル（公開されるまでダッシュボードはフィルターできません）などです。ステータスは**エラー**のままで、そのテーブルを公開するか、代わりに公開済みのテーブルの列を制限するまで、未公開のテーブルの名前が表示されます。このようなテーブルがあっても、プロジェクトの他の部分が止まることはありません。他のすべてのテーブルは同期が維持されます。

ダッシュボードは、PlaidCloud自身のクエリと同じ付与に従います。

- **その列を持つ公開済みのすべてのテーブルがフィルターされます。** 制限を設定した際に見ていたテーブルだけではありません。
- **一部の値のみを付与されたグループは、他のすべてのユーザーがすべての行を表示する場合でもフィルターされます。** ダッシュボードのデータセットが存在するすべてのテーブルが対象です。
- **プロジェクトのアーキテクトは、すべての行を表示します。** これは、テーブルエクスプローラーやPlaidCloudの他の場所と同様で、ダッシュボードにも当てはまります。これは、プロジェクトのアーキテクトグループと、個々のメンバーと共有されたプロジェクトのアーキテクトに適用されます。アーキテクトのアクセスを取り消すと、ダッシュボードには直ちに反映されます。メンバーのロールの変更、プロジェクトからのメンバーまたはそのグループの削除、プロジェクトのアクセスタイプの変更、以前のプロジェクトバージョンの復元、グループの削除のいずれの場合も同様です。
- **セキュリティグループのメンバーシップの変更は、自動的にダッシュボードに反映されます。** PlaidCloudでユーザーをグループに追加または削除する、メンバーを無効化または削除する、グループを削除する、デフォルトのセキュリティグループに参加する新しいメンバーを追加するといった操作は、そのグループに値を付与しているすべてのプロジェクトで、誰も行アクセスを開き直さなくても、約1分以内にダッシュボードでの表示に反映されます。PlaidCloudの外で行われたメンバーシップの変更（Keycloakでの直接の変更や、シングルサインオンによるサインイン時のグループへの配置）は、保存や再試行をしなくても、約15分以内にダッシュボードに反映されます。

### ディメンションの付与

値のソースが**ディメンション**の場合、ノードにチェックを入れると、その配下のすべてが付与されます。付与はディメンションに追従します。チェックされたノードの配下に追加されたメンバーは、ディメンションが保存された後の次の同期でそのグループに付与され、ノードの配下から移動または削除されたメンバーは付与されなくなります。誰もグリッドを開き直す必要はありません。開き直すと、チェックしたノードはチェック済みのまま表示されます。

ノードを通じてではなく、単独でチェックしたメンバーは、ディメンションから削除されても付与されたままで、グリッドにはソースにもう存在しない値としてマークされます。

チェックされたノードの配下のいずれかのチェックを外すと、ノードのチェックが外れ、グループにはまだチェックされているメンバーのみが残ります。そのメンバーをもう一度チェックしても、ノードは再びチェックされません。ノードをチェックするには、ノード自体のチェックボックスをクリックしてください。**貼り付け**、**すべて選択**、**選択を反転**では、メンバーがチェックされ、ノードがチェックされることはありません。

名前が行アクセスの値として使えないディメンションメンバーは、保存時に名前を示して拒否されます。そのようなメンバーが後から現れた場合、その行は誰にも付与されず、同期ステータスにその名前が表示されます。「Dimension ‘…’ member ‘…’ cannot be used as a row access value, so its rows are not granted. Rename it in the dimension.」

### 付与のソーステーブルへのバインド

値を手動でチェックする代わりに、制限された列を、答えをすでに保持しているソーステーブル（グループとそのグループが表示できる値を1行ずつ持つテーブル）に関連付けることができます。まずグリッドで列を制限し、次に、列、ソーステーブル、ソーステーブルのグループ列と値の列を指定した[**行アクセスを設定**](/ja/reference/workflow-steps/tables/table-set-row-access/)ワークフローステップを追加します。ステップの最初の実行で、列がそのテーブルにバインドされます。列の手動で設定した付与はクリアされ、付与はテーブルの行から設定されます。

バインドされると、その列は**ソース所有**になります。行アクセスのグリッドでは、その列が、ソーステーブルの名前を示すバッジとともにロックされた状態で表示され、**バインディングを削除**をクリックするまで、付与の手動編集は拒否されます。

ステップを実行するたびに、ソーステーブルが再読み込みされ、付与が再適用されます。このテーブルを読み込む、または更新するワークフローの後に実行されるようにスケジュールしておけば、ソースデータでグループが追加、削除、または再割り当てされると、誰もグリッドを手動で編集しなくても、次の実行で行アクセスに反映されます。

誰がどの行を表示できるかをソーステーブルが決定するため、その行の変更や削除ができるのは、プロジェクトのアーキテクト、テナント管理者、またはプロジェクト自身のワークフローのみです。それ以外のユーザーには「This table supplies the row access grants for ‘region’, so only a project Architect can change its rows or delete it.」と通知されます。

### 制限テンプレート

再利用したい制限の形（同じ値のソース、値の型、空白の値の設定）を作成した場合は、一度保存しておけば、列ごとに作り直すのではなく、必要な場所に適用できます。

- 開いている行アクセス画面の**テンプレートとして保存…** ボタンは、現在の列の形を、名前付きのテナントレベルのテンプレートとして保存します。保存されるのは形のみで、付与は含まれません。
- 別のプロジェクトの列に対する**テンプレートを適用**は、テンプレートの形からその列を開始します。すべてのグループの付与は空になっており、入力できます。

テンプレートの保存と適用は、プロジェクトのアーキテクトなら誰でも行えます。テンプレートはテナント全体で共有されるため、名前の変更（**名前の変更…** ボタン）と削除（**削除**）にはテナント管理者が必要です。テンプレートを削除しても、そのテンプレートが適用された列の制限はそのまま残ります。

<Aside type="note">
テンプレートはコピーであり、リンクではありません。後からテンプレートを編集しても、すでにそれを適用した列は変更されません。その後の改訂内容を列に反映するには、テンプレートをもう一度適用してください。
</Aside>

### SSOグループ属性からの付与

列は、PlaidCloudではなく、ID プロバイダーから付与を取得することもできます。プロジェクトのアーキテクトが、行アクセスで**Accept row-access grants from SSO group attributes**を有効にして、列を対象にします。

有効にすると、セキュリティグループのKeycloak属性`row_access.<column>`が、そのグループがその列で表示できる値を設定します。Keycloakでグループに属性を設定すると、すでにプロジェクトへのアクセス権を持つすべてのグループについて、PlaidCloudが自動的に取り込みます。行アクセス自体で設定すべきことはほかになく、付与は、PlaidCloud自身のクエリとSupersetダッシュボードの両方で同期されたままになります。

<Aside type="caution">
これは、すでにプロジェクトにアクセスできるグループにのみ値を付与します。プロジェクトへのアクセス権を持たないグループに`row_access.region`を追加しても、そのグループがプロジェクトへのアクセスを付与されるまで、何も付与されません。
</Aside>

### 保存前のプレビュー

行アクセスでは、変更を確定する前に、その意味を確認できます。

- **プレビュー表示ユーザー**フッターには、グループが合計のうち何行のテーブルの行を表示できるかが、行のサンプルとともに表示されます。グリッドで任意のグループを選択すると、プレビューできます。プレビューは保存後に更新されます。
- 保存の前に、行アクセスは注意が必要な点を警告します。チェックがないグループ（**Everyone else**の設定に応じて、すべての行を表示するのか、まったく表示しないのか）、プロジェクトへのアクセス権を持つがどのグループの付与にも含まれていないメンバー、その列の値が空白（`NULL`）で、どのグループにも付与されていない行などです。

### 制限されたメンバーに表示される内容

制限されたメンバーが名前でテーブルを読み取る場所では、どこでも自分の行のみが取得されます。テーブルエクスプローラーのグリッド、列ファセット、ダウンロード、テーブルのダウンロードダイアログ、閲覧者として読み取るアプリとツール、ダッシュボードが該当します。表示しているグリッドがユーザーの付与によってフィルターされている場合、テーブルエクスプローラーはツールバーに**アクセス権により行が制限されています**を表示し、フィルターされるダウンロードを開始すると「Rows limited by your access.」と表示されます。すべての行を読み取るアーキテクトには、どちらの通知も表示されません。

### 行アクセスと自分で作成するクエリ

行アクセスで行が制限されている場合でも、プロジェクトのクエリ画面で独自のSQLクエリを実行でき、付与によって許可された行のみが取得されます。結果はCSV、Excel、JSONにエクスポートできます。エクスポートにはそれらの行のみが含まれ、**アクセス権により行が制限されています**という通知が表示されます。プロジェクトのアーキテクトは、制限されたすべての列のすべての値を自分に付与できるため、すべての行を読み取ることができ、通知は表示されません。

パーセント記号（`%`）を含む付与値は、クエリ画面で付与された行を返し、そのようなクエリをCSVとしてダウンロードすることもできます。

プロジェクトのアーキテクトではないメンバーについては、次の操作は引き続き拒否されます。

- SnowflakeまたはDatabricksのプロジェクトウェアハウスで、独自の自由形式のSQLを実行すること。
- Postgres系のウェアハウスから、独自のSQLの結果をエクスポートすること。
- 独自のSQLの結果を別のデータベースにエクスポートすること。
- ファンアウトステップの「Test row 1」プレビューに行条件を入力すること。
- 管理対象のテーブルを以前のスナップショット時点で読み取ること（タイムトラベル）。

拒否されたユーザーには、どのプロジェクトであったかが通知され、名前で読み取る方法が案内されます。名前でテーブルを読み取るのは、アプリやツールがデータを読み取る通常の方法であり、付与が適用されて、閲覧者が参照できる行が返されます。単一のテーブルに対する単純なクエリとして記述された列ファセットも名前で読み取られるため、拒否されることなく、メンバー自身の値が返されます。プロジェクトのアーキテクトは、これらのいずれもそのまま実行できます。

行アクセスは、管理対象の列でビューをフィルターするため、ビューはその列を元の名前のまま保持する必要があります。管理対象の列を削除または名前変更したビューは、フィルターされません。

スプレッドシートのインポートは、それ自体では、自分で作成したクエリには当たりません。通常のファイルのインポートは制限されたデータをまったく読み取らず、アップロードしたファイルからプロジェクト自身の新しいテーブルを作成するだけなので、行アクセスの影響を受けません。例外は、データの射影を呼び出し元が指定するインポートです（列ごとの式、または動的なExcelマッピング）。対話型のインポート画面では、これらは上記の自由形式SQLの画面と同様に拒否され、プロジェクトのアーキテクトが必要です。呼び出し元が指定する射影では、別のテーブルを読み取れる可能性があるためです。ワークフローから実行されるインポートは、プロジェクト自身のサービスIDの下で実行されるため、どちらの場合も影響を受けません。

<Aside type="caution">
プロジェクトで最初の列を制限すると、そのプロジェクトを使用するすべてのユーザーに影響します。そのプロジェクトのPanelアプリ、ノートブック、連携が、SnowflakeまたはDatabricksのウェアハウスで独自のSQLを組み立てている場合や、Postgres系のウェアハウスから独自のクエリ結果をエクスポートしている場合は、制限する前に、テーブルを名前で読み取る方式に切り替えてください。切り替えないと、アーキテクト以外のすべてのユーザーに対して動作しなくなります。
</Aside>

### 行アクセスとデータエディター

データエディターはテーブルを直接読み書きするため、行アクセスは読み取りと書き込みの両方に適用されます。

制限されたテーブルをデータエディターで開くと、セキュリティグループに付与された行のみが表示されます。これはダッシュボードにも適用されるのと同じフィルターで、制限された列がグリッドに表示されている列に含まれていない場合でも適用されます。

編集内容を保存するには、プロジェクトの**アーキテクト**であることが必要です。保存はテーブルの行を読み取るのではなく一括で置き換え、行ごとにフィルターされないため、制限されたテーブルのデータ編集は、読み取りではなく編集作業として扱われます。アーキテクトでないユーザーには、アーキテクトが必要であることが通知されます。制限された列を持たないテーブルは、これまでどおり編集でき、行を制限していないプロジェクトでも同様です。

### 制限されたテーブルへのデータの読み込み

行アクセスによって表示される行が制限されている場合、Pythonクライアント（`PlaidConnection`）でDataFrameを制限されたテーブルに書き込む、またはクリアする、あるいはREST APIでレコードを保存する、またはクリアする操作は、自分の行のみを対象に行われます。テーブルのデータを置き換えると、表示できる行のみが置き換えられ、クリアすると、それらの行のみがクリアされ、追加すると行が追加されます。他のすべての行は変更されません。

アクセス権の範囲外の行を含む読み込みは、何かが変更される前に拒否され、エラーにはアクセス権の範囲外の各値と、その値を持つ行数が示されます。制限された列を省略した行は、その列が空白であるものとしてチェックされるため、アクセス権に空白の行が含まれていない限り拒否されます。列の型が変わるようなデータの置き換えも拒否されます。その変更は、プロジェクトのアーキテクトに依頼してください。

プロジェクトのアーキテクト、付与がすべての行をカバーしているメンバー、プロジェクトのサービスIDとして実行されるワークフローの実行は、テーブル全体に書き込みます。制限された列のないテーブルには影響しません。

制限されたテーブル全体を置き換える、または削除するその他の操作は、見えない行がテーブルにある間は拒否され、何も変更されません。該当するのは、ファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えまたはマージ、アーカイブからの復元、プロジェクトの保持されたスナップショットの復元の一環としての復元、削除、削除後の復元、その他テーブルを空にしてから再び埋める操作です。制限された列が空白の行は、アクセス権に空白の行が含まれていない限り、見えない行として扱われます。すべての行が見えるテーブル（たとえば、自分の行のみを保持するものとして作成したテーブル）は、置き換えまたは削除できます。

人が行うこれらの書き込みは、どのテーブルに対するものであっても、拒否されたものも含めて、セキュリティログに記録されます。ワークフローの実行は、そこには記録されません。

### 行数とテーブルサイズ

テーブルの行数とストレージサイズは、表示できる行ではなくテーブル全体を表すため、制限された閲覧者に、付与の範囲外に存在する行数を知らせてしまいます。行を制限しているプロジェクトでは、読み取りがフィルターされるユーザーには、プロジェクトのどのテーブルについても、テーブル一覧、検索、テーブルの詳細、スナップショット、MCP経由で接続されたAIアシスタントとAIツールで、行数もサイズも表示されません。これは、制限された列を持たないテーブルを含め、プロジェクトのすべてのテーブルに適用されます。ホーム、プロジェクト一覧と検索、プロジェクトの詳細での合計行数とサイズなど、プロジェクト自体の合計も、これらのユーザーには非表示になります。

ワークフローの実行履歴にも同じことが当てはまります。各実行とステップに記録された読み取り行数と書き込み行数も、テーブル全体を表すため、同じユーザーにはそれらの数値が、ワークフローとステップの実行履歴、MCP経由で接続されたAIアシスタントとAIツールで、空白のままになります。これらのユーザーに対しては、[Weave](/ja/guides/ai-assistant/weave-findings/)は、以前の実行と比べて行数や空の値に異常がないかステップをチェックしません。検出事項そのものが、テーブル全体の件数が変動したことを知らせてしまうためです。

プロジェクトのアーキテクトには、これまでどおり数値が表示され、行を制限していないプロジェクトでは、すべてのユーザーに表示されます。

### メンバーが表示できる内容の確認

グループに付与されている内容ではなく、特定のユーザーが表示できる内容を確認するには、**Identity → メンバー**を開いてメンバーを選択し、その**行アクセス**タブを開きます。**Effective Access**列には、制限されたすべてのプロジェクトと列について、そのメンバーがすべてのグループを合わせて表示できる値が一覧表示されます。これには、SSOグループ属性からの付与や、グループの付与に含まれている場合の空白（`NULL`）の行も含まれます。プロジェクトのアーキテクトは、すべての行を読み取るため、**すべての行を表示（アーキテクト）** と表示されます。これはPlaidCloud自身のクエリが適用するのと同じ結果であり、サポート対応や、問題が報告される前に変更が意図したとおりに機能したかを確認するのに便利です。

### わかりやすいエラー

行アクセスが操作をブロックした場合（制限されたプロジェクトで自分で作成したクエリ、アーキテクトなしでの編集、自動化・ディメンション・付与のソーステーブルの変更、上記のその他のケース）、メッセージには、一般的なエラーではなく、何が制限されているか、依頼すべきアーキテクトなど次に何をすべきかが示されます。

### 行アクセスは監査されます

列の制限または制限解除と、グループの付与の編集は、いずれもそのプロジェクトの[プロジェクトログ](/ja/get-started/tutorials/collaborate-versions-and-sharing/#プロジェクトログを読む)にエントリとして記録され、誰がいつ変更したかがわかります。ログを表示するには、プロジェクトで**Analyze → プロジェクト → Log**を開きます。この記録を得るために行アクセスで有効にする必要のある設定はありません。プロジェクトに対する他のすべての追跡対象の変更と同じように記録されます。

## デフォルトのセキュリティグループの設定


新しいメンバーを追加する時間を短縮するため、デフォルトのセキュリティグループのセットを指定します。これにより、各ユーザーに手動で割り当てることなく、新しいメンバーの基本となるセキュリティグループのセットが提供されます。この設定は、新しいセキュリティグループを追加するときに、「セキュリティグループ」ウィンドウの下部にある「Assign to New Users by Default」というチェックボックスをオンにすることで利用できます。



## セキュリティ監査の実施


セキュリティ監査機能では、すべてのメンバーとグループにわたるグループメンバーシップを確認できます。



**セキュリティ監査を実施するには：**


1. Identityを開きます
2. レールの**セキュリティ**の下にある**Group audit**を選択します

PlaidCloudのすべてのテーブルはCSVファイル形式でエクスポートできるため、グループメンバーの関連付けは、履歴の確認や、オフラインでの閲覧のために、PlaidCloudの外部でも確認できます。



**「Security Group Audit」フォームからエクスポートするには：**


1. Identityを開きます
2. レールの**セキュリティ**の下にある**Group audit**を選択します
3. テーブルの「Username」の右端にある小さなアイコンをクリックします
4. 好みに応じて、「Export CSV」または「Export XLXS」をクリックします

## 利用可能な権限設定の表示


ワークスペースで使用される各アプリケーションには、固有の利用可能な権限があります。セキュリティグループの権限は、これらのアプリケーションの権限に基づいています。


各アプリケーションで利用可能な権限の完全な一覧は、セキュリティビンで確認できます。



**セキュリティビンにアクセスするには：**


1. Identityを開きます
2. 「セキュリティ」を選択します
3. ドロップダウンメニューの「Security Bins」をクリックします

各アプリケーションの詳細なセキュリティ設定を表示するには、左端のタグアイコンを選択します。



この利用可能なセキュリティ設定の情報は、参考情報です。権限の管理の詳細については、上記のセキュリティグループの管理のセクションを参照してください。
