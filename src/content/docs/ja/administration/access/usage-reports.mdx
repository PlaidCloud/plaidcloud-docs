**利用状況レポート**では、ワークスペース内で誰が何を利用しているかを確認できます。メンバーが開いた画面、ダッシュボード、アプリ、ノートブック、再訪しているメンバーの人数、次に移動した先がわかります。メンバーがどの機能を定着させているか、どのダッシュボード、アプリ、ノートブックが活用され、どれが誰にも使われていないか、しばらく利用していないのは誰か、プロセスのどこで離脱しているかを把握するのに役立ちます。

**ID**タブから、セキュリティログの隣にある項目として開きます。

## 閲覧できる人

利用状況レポートには、セキュリティログと同じ権限 `identity.security_log.read` が必要です。この権限がないとボタンは表示されず、レポートを直接開いたメンバーには、アクセス権がないことを示す通知が表示されます。

メンバー単位の利用状況は、**ユーザー**タブとメンバーのプロフィール、**内容**タブの各項目のメンバー一覧、そしてメンバー ID を含む **メンバー別の日別アクティビティ** と **初回利用** のエクスポートに表示されます。それ以外はすべてメンバー全体の集計です。この権限は、個々のアクティビティを確認する必要がある人にだけ付与してください。

名前の付いたメンバーのプロフィールを開いたとき、**Not seen** のメンバーを一覧表示したとき、項目のメンバー一覧を開いたとき、そして CSV をダウンロードするたびに、セキュリティログにエントリが書き込まれます。[プライバシーと監査](#プライバシーと監査)を参照してください。

## 集計の対象

利用状況レポートは、次のソースを組み合わせて集計します。**ソース**から1つを選択するか、**すべてのソース**のままにします。

| ソース | 記録される内容 |
|---|---|
| PlaidCloud アプリ | メンバーがアプリ内で開いた画面と実行した操作。 |
| Superset | ダッシュボードとチャートの閲覧。 |
| Panelアプリ | アプリへのアクセスと、メンバーが各アプリで過ごした時間。 |
| App visits | Dash アプリと WASM アプリへのアクセス。 |
| JupyterHub | メンバーが JupyterHub セッションで過ごした時間。 |
| Jupyter ノートブック | メンバーが開いて保存したノートブック。 |

JupyterHub セッションと Jupyter ノートブックは別々のソースなので、どちらか一方を選択できます。Panelアプリは1つのソースで、**App visits** には Dash アプリと WASM アプリが含まれます。ノートブックのイベントは、デフォルトのノートブックイメージで実行されるノートブックについてのみ記録されます。カスタムイメージでは報告されません。

イベント、ソース、画面は、内部コードではなく、**Opened Dash app**、**Opened WASM app**、**Opened notebook**、**App visits** のようにわかりやすい名前で表示されます。削除済みのダッシュボードやアプリは、**Deleted dashboard** または **Deleted app** と表示されます。

<Aside type="note">
レポート内の日付はすべて UTC の日付です。アメリカ大陸で夜遅くに作業しているメンバーは、翌日のアクティビティとして表示されることがあります。
</Aside>

## レポートの見方

ウィンドウ上部でソースと**日付範囲**を選択し、**更新**を選択します。範囲は直近7日、30日、90日、180日から選べます。各タブは最初に開いたときと、ソースや範囲を変更したときに読み込まれます。

### 概要

範囲内の主要な数値です。

| 数値 | 意味 |
|---|---|
| **アクティブユーザー** | 何らかのアクティビティがあったメンバー。 |
| **新規ユーザー** | 範囲内で初めて確認されたメンバー。 |
| **リピートユーザー** | 範囲より前に初めて確認された、アクティブなメンバー。 |
| **Activity minutes** | 推定値です。操作または閲覧が1回でもあった5分間ごとに5分として数えます。 |
| **イベント** | 記録されたすべてのもの。 |
| **メンバー未紐付けのイベント** | どのメンバーにも紐付けられなかったイベント。イベントとして数えますが、ユーザーには数えません。 |
| **App open minutes** | Panelアプリと JupyterHub サーバーが開いていた時間（アイドル時間を含む）。Activity minutes とは別に集計されます。 |

各数値には、直前の同じ長さの期間と比較した**変更**が表示されます。たとえば30日の範囲は、その前の30日と比較されます。**新規**は、0から増加したことを意味します。ダッシュ（**—**）は、保持されている履歴では直前の期間を完全にカバーできず、公平に比較できないことを意味します。

ワークスペースの履歴が範囲の途中から始まる場合は、**History starts** のバナーに開始日が表示されます。それより前の日にアクティビティが表示されないのは、データが収集されていなかったためであり、誰も製品を使っていなかったという意味ではありません。

**利用状況の定着度**には、画面、ダッシュボード、チャート、各項目について、ソース、イベント、ユーザー数、アクティブユーザーに占める割合、イベント数、メンバー未紐付けのイベント数が一覧表示されます。**月別**には、月ごとのアクティブユーザー、1日あたりの平均ユーザー数、スティッキネスが表示され、その月がまだ進行中の場合、一部のみが対象の場合、固定されたスナップショットの場合には注記が付きます。

### アクティビティ

**毎日**、**毎週**、**毎月**の期間別のアクティブユーザーと、**初回週別の継続率**を表示します。継続率は、メンバーが初めて現れた週ごとに、その後の各週に何人が戻ってきたかを示します。アスタリスクが付いた期間は、全体が範囲内に収まっていません。

### パス

アプリやソースをまたいだ、画面間で最も多く行われた移動を、**移動元**、**移動先**、**通過回数**として表示します。パスの対象は最大で直近30日間です。

### ユーザー

**Seen** または **Not seen** を選択します。

**Seen** にはメンバーごとに1行が表示され、名前、ユーザー名、アクティブな日数、イベント、**Activity minutes**、**App open minutes**、初回と最終の確認日時が含まれます。メンバーを選択するとプロフィールが開きます。

メンバーのプロフィールには、**アクティブな日数**、**イベント**、**Activity minutes**、**App open minutes**、初回と最終の確認日時、日ごとのイベントのチャート、利用した項目が表示されます。項目ごとに、ソース、イベント、イベント数、最後に利用した日時が確認できます。項目は、ダッシュボードやアプリのタイトルなど、わかりやすい名前で表示されます。**戻る**を選択すると一覧に戻ります。

**Not seen** には、範囲内にアクティビティがないメンバーが、**メンバー登録日**と**最終確認日時**とともに一覧表示されます。**None recorded** は、保持されている履歴（最大25か月、かつ収集開始以降のみ）にアクティビティがないことを意味します。**CSVをダウンロード**を選択すると、一覧を保存できます。

### 内容

ダッシュボード、Panelアプリ、Dash アプリ、WASM アプリ、ノートブックがそれぞれどのくらい利用されているかを確認します。**タイプ**で絞り込むか、**All types** のままにします。

| 列 | 意味 |
|---|---|
| **名前** | 項目の名前。削除された項目は **Deleted dashboard** または **Deleted app** と表示されます。ノートブックは、何人のサーバーにあっても、パスごとに1回として数えます。 |
| **タイプ** | ダッシュボード、Panelアプリ、Dash アプリ、WASM アプリ、またはノートブック。 |
| **ユーザー** | 範囲内にそれを利用した個別のメンバー数。 |
| **利用状況の定着度** | 範囲内のアクティブユーザーに対するユーザーの割合。 |
| **開封** | ダッシュボードは、ページの読み込み。Panelアプリは、開始されたセッション。ノートブックは、メンバー・ノートブックごとに30分あたり1回の開封。Dash アプリと WASM アプリは、アクセス。 |
| **App open minutes** | Panelアプリのみ。アプリが開いていた時間（アイドル時間を含む）。 |
| **推移** | 範囲内の週ごとの開封数（古い週から順）。 |
| **Last used (UTC)** | メンバーが最後に利用した日時。 |

範囲内に誰も利用しなかった項目も一覧に含まれるため、廃止の判断に役立ちます。それらを除外するには **Hide unused** を選択します。項目を選択すると、その項目を利用したメンバーが、**開封**数と各自の最終利用日時とともに表示されます。**CSVをダウンロード**では、項目一覧または項目のメンバー一覧を保存できます。

ノートブックは、誰かが開いた時点で表示されます。Dash アプリと WASM アプリのアクセスは、このリリースがワークスペースに反映された時点から集計され、一覧の上の注記に、タイプごとの収集開始日が表示されます。

ダッシュボードやアプリの名前を取得できない場合は、**Names are unavailable right now, so items nobody used are not listed** という警告が表示されます。利用された項目は引き続き表示されます。

### エクスポート

サマリーを CSV としてダウンロードします。**サマリー**と、最長25か月までの**日付範囲**を選択し、**CSVをダウンロード**を選択します。

| サマリー | 内容 |
|---|---|
| **日別アクティビティ** | 日、ソース、イベント、件名ごとのユーザー数とイベント数。 |
| **メンバー別の日別アクティビティ** | 同じ内容をメンバーごとに集計したもので、メンバー ID を含みます。 |
| **月別の利用状況** | 月、ソース、イベント、件名ごとのユーザー数とイベント数。 |
| **月間アクティブユーザー** | 月とソースごとのアクティブユーザー数。 |
| **初回利用** | 各メンバーが各ソースを初めて利用した日時で、メンバー ID を含みます。 |

エクスポートでは、タブの上で選択したソースが使用されます。大きなサマリーは最大50,000行ずつのバッチでダウンロードされ、ウィンドウがそれらを1つのファイルにまとめます。ウィンドウが組み立てられるサイズよりファイルが大きくなる場合は、そこまでの内容を保存し、ファイルが不完全であることを通知します。残りを取得するには、より短い範囲を選択してください。

エクスポートのたびに、誰がどのサマリーをどの範囲でエクスポートしたか、およびその行数を記録するエントリがセキュリティログに書き込まれます。複数のバッチにまたがるサマリーは、バッチごとにエントリが書き込まれます。

<Aside type="caution">
月別のサマリーには、各イベントの合計行が含まれ、件名は `*` です。この行は、そのイベントのすべての件名にわたる個別ユーザー数とイベント数です。件名ごとの行に加算しないでください。すべてが二重に集計されます。
</Aside>

### ファンネル

一連のステップを何人のメンバーが通過するかを確認します。ステップは、いずれかのソースのイベントを特定の件名で指定するか、**すべての件名**を指定します。

1. **ステップを追加**を選択し、各ステップのソース、イベント、件名を選択します。ファンネルのステップ数は2〜6です。
2. **ステップ間の許容時間**を選択します。1、6、24、72、168時間から選べます。
3. 7、30、90日から**日付範囲**を選択します。
4. **ファンネルを実行**を選択します。

結果には、ステップごとに、到達したメンバー数、開始した人に対する割合、そこで止まった人数、前のステップからの所要時間の中央値が表示されます。ステップではソースを混在させることができるため、PlaidCloud の画面から Superset のダッシュボードまでメンバーの動きを追跡できます。**最近のファンネル**から、以前に実行したファンネルを開き直せます。ステップの一覧には、範囲内に記録されたイベントのみが表示されます。

## メンバー未紐付けの利用状況

一部のイベントは、PlaidCloud のメンバーに紐付けることができません。これらは**イベント**と**メンバー未紐付けのイベント**には数えられますが、ユーザー数には含まれません。主なケースは次のとおりです。

- PlaidCloud 経由ではなく、Superset 内で作成された Superset アカウント。
- Superset ユーザーが存在しない、埋め込みダッシュボードの閲覧。
- プラットフォームのログからメンバーを特定できない Panel と JupyterHub のアクティビティ。これらの紐付けはログに基づくため、ベストエフォートとして扱ってください。

あるソースでメンバー未紐付けの割合が大きい場合、そのソースのユーザー数は実際より少なく表示されています。

## 履歴の開始時点

履歴は、ワークスペースで利用状況の収集が有効になった時点から始まり、それより前の日や月にはアクティビティが表示されません。データのある最初の月は、一部のみの月として示されます。

Panel と JupyterHub はプラットフォームのログから読み取られ、ログは約90日間保持されます。収集の開始時には、これら2つのソースについて、最大でその期間分だけ過去の履歴が補完されます。Superset は独自のログから最大180日分が補完されます。収集の開始時に何もない状態から始まるのは、PlaidCloud アプリだけです。

利用状況レポートは、詳細なアクティビティを180日間保持します。そのため、最長の範囲は180日です。また、各メンバーと各項目の初回利用と最終利用を、月別のサマリーとともに25か月間保持します。180日より前から始まる範囲では、誰が不在だったかを判断するための詳細が失われているため、**Not seen** の一覧と誰も利用しなかった項目の代わりに警告が表示されます。SCIM や Keycloak など PlaidCloud の外部でメンバーが削除された場合、そのメンバーの生の利用データは180日後に、初回利用の記録は25か月後に失効します。

## プライバシーと監査

名前の付いたメンバーの利用状況を閲覧する操作自体が監査対象です。次の操作を行うと、実行者を記録するエントリがセキュリティログに書き込まれます。

- 名前の付いたメンバーのプロフィールを開く。
- **Not seen** のメンバーを一覧表示する。
- 項目を利用したメンバーの一覧を開く。
- **エクスポート**タブ、**Not seen** の一覧、**内容**タブからのすべての CSV ダウンロード。

`identity.security_log.read` 権限を持つメンバーだけが、レポートを開くことができます。

## メンバーの利用データの消去

`identity.security_log.read` 権限を持つワークスペース管理者（またはスーパーユーザー）は、1人のメンバーの利用データを消去して収集を停止し、後から消去を解除できます。消去と復元のどちらも、その権限とロールが必要です。これら2つの操作は REST API からのみ利用できます。

| 操作 | リクエスト |
|---|---|
| 消去 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 復元 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

消去すると、そのメンバーのイベントと初回利用の記録が削除され、その時点からレポートとエクスポートではそのメンバーが除外されます。そのメンバーの利用データは再び収集されることはなく、後から Panel と JupyterHub のログで読み込まれる履歴も破棄されます。削除をすぐに完了できない場合は、その旨が応答に示され、次の1時間ごとのメンテナンス実行で完了します。

復元すると消去が解除され、新しいアクティビティが再び収集されます。消去されたデータは元に戻りません。

どちらの操作も、セキュリティログにエントリが書き込まれます。
