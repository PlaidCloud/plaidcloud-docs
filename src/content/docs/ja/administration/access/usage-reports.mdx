**利用状況レポート**では、ワークスペースで誰が何を使っているかを確認できます。メンバーが開く画面、ダッシュボード、アプリ、ノートブック、再訪するメンバーの数、その次に移動する先がわかります。メンバーが何を採用しているか、どのダッシュボードやアプリが役立っているか、プロセスのどこで離脱しているかを把握するのに使用します。

**ID**タブのレールにある**インサイト**の下の**利用状況レポート**から開きます。別ウィンドウではなく、IDの内部でレールの横のページとして開きます。

## 閲覧できるユーザー

利用状況レポートには、セキュリティログと同じ権限 `identity.security_log.read` が必要です。この権限がない場合、ボタンは表示されず、それでもレポートを開こうとしたメンバーには、アクセス権がないことを示す通知が表示されます。

レポートでは、次の場所でメンバーごとの利用状況が表示されます。**メンバー**タブ、**内容**と**概要**から開くメンバーの一覧、そしてメンバー ID を含む**メンバー別の日別アクティビティ**と**初回利用**のエクスポートです。それ以外はすべてメンバー全体で集計されます。この権限は、個々のアクティビティを確認すべきユーザーにのみ付与してください。

## 集計の対象

利用状況レポートは5つのエリアを組み合わせたものです。**エリア**から1つを選択するか、**すべてのエリア**のままにします。

| エリア | 記録される内容 |
|---|---|
| PlaidCloud アプリ | メンバーが開く画面と、アプリで実行する操作。 |
| ダッシュボード | ダッシュボードとチャートの閲覧。 |
| アプリ | アプリへのアクセスと、各アプリでメンバーが費やした時間。 |
| ノートブックサーバー | メンバーがノートブックサーバーのセッションで費やした時間。 |
| ノートブック | メンバーが開いて保存したノートブック。 |

ノートブックサーバーとノートブックは別々のエリアなので、どちらかを選択できます。アプリは単一のエリアです。ノートブックのイベントは、デフォルトのノートブックイメージで実行されるノートブックについてのみ記録されます。カスタムイメージはこれらを報告しません。

<Aside type="note">
レポート内の日付はすべて UTC の日付です。南北アメリカで夜遅くに作業しているメンバーは、翌日として表示されることがあります。
</Aside>

## レポートの読み方

ページ上部のバーにはフィルターがあります。各タブは、最初に開いたときとフィルターを変更したときに読み込まれます。

| フィルター | 機能 |
|---|---|
| **エリア** | レポートを1つのエリアに限定します。ステップごとにエリアを選択する**ファネル**と、独自の選択肢を持つ**エクスポート**では非表示になります。 |
| **グループ** | レポートを1つのセキュリティグループのメンバーに限定します。[グループへの絞り込み](#グループへの絞り込み)を参照してください。 |
| **日付範囲** | **過去7日間**、**過去30日間**、**過去90日間**、**過去180日間**、**今月**、**前月**、または最大180日間の開始日と終了日を指定する**カスタム…** です。 |
| **更新** | 数値を再読み込みします（F5）。**更新**には最後に読み込まれた日時が表示されます。 |

日付範囲はすべてのタブで共有されます。開いていたタブと選択した範囲はアカウント設定とともに保存されるため、どのコンピューターでも、ページは前回の状態で開きます。範囲を変更すると、開いているタブが再読み込みされ、他のタブは開いたときに再読み込みされます。各タブには独自の説明があります。見出しや数値にポインターを合わせると、その意味が表示されます。

タブの読み込み中は、空白のページではなくプレースホルダーが表示されます。レポートを読み込めない場合、タブには理由とともに**再試行**と **Copy details** が表示されます。範囲内にアクティビティがない場合、タブはより長い範囲を試すよう提案します。行を開くには、ダブルクリックするか、行を選択して Enter キーを押します。**戻る**を選択すると、開いた項目から一覧に戻ります。

### 概要

範囲の主要な数値です。それぞれに矢印と、同じ長さの前の期間からの変化を示すパーセンテージが付いています。

| 数値 | 意味 |
|---|---|
| **アクティブなメンバー** | 何らかのアクティビティがあったメンバー。 |
| **新規メンバー** | 範囲内で初めて確認されたメンバー。範囲が収集の開始前から始まる場合は、それ以前の初回利用を判別できないため、ダッシュで表示されます。 |
| **再訪メンバー** | 範囲より前に初めて確認された、アクティブなメンバー。 |
| **アクティビティ時間（分）** | 推定値：操作または閲覧があった5分間ごとに5分としてカウントします。 |
| **アプリ表示時間（分）** | アプリとノートブックサーバーが開いていた時間（アイドル時間を含む）。アクティビティ時間（分）とは別にカウントされます。 |
| **イベント** | 記録されたすべてのもの。 |

メンバーに紐付けられないイベントは、数値の下の行で別にカウントされます。これらはメンバーではなく、イベントとしてカウントされます。

**Highlights** には、確認する価値のある項目が最大4つ一覧表示され、それぞれ詳細を確認できる場所へのリンクになっています。

- 前の期間と比べて、アクティブなメンバーが10%以上増減した場合。
- 範囲内でアクティブでなかったメンバーの数。選択すると、非アクティブなメンバーの一覧が開きます。
- 誰も開かなかったダッシュボードとアプリの数。選択すると、未使用のものが先頭に表示された**内容**が開きます。
- 最もよく使われた項目（5人以上のメンバーが使用した場合）。

ハイライトは、伝えるべき内容がある場合にのみ表示されます。PlaidCloud が件数を算出できない場合、ハイライトは0を表示せずに非表示になります。目立つ項目がない場合は **No notable changes in this range.** と表示されます。

**Most used** には、各画面、ダッシュボード、チャート、項目が、エリア、イベント、メンバー数、**Reach**（範囲内にその項目を使用したアクティブなメンバーの割合）とともに一覧表示されます。列の選択で**イベント**と**メンバー未紐付けのイベント**を追加できます。**月別（全履歴）** には、各月のアクティブなメンバー、1日あたりの平均メンバー数、**定着率（DAU/MAU）** が表示され、その月がまだ進行中の場合や一部しか対象になっていない場合は注記が付きます。定着率は、1日あたりの平均アクティブメンバー数をその月のアクティブなメンバー数で割った値です。値が高いほど、より多くの日にメンバーが戻ってきていることを意味します。

### アクティビティ

**毎日**、**毎週**、**毎月**の期間別のアクティブなメンバーと、**初回週別の継続率**を表示します。継続率は、メンバーが最初に現れた週ごとに、**Cohort size** と、その後の各週にまだアクティブなメンバーの割合を示します。アスタリスクが付いた期間は、全体が範囲内に収まっていません。

### パス

画面間で最も多く行われた移動を、エリアをまたいで**移動元**、**移動先**、**通過回数**として表示します。パスの対象は最大で過去30日間です。

### メンバー

**表示**で、2つの一覧を切り替えます。

- **アクティブ**は、範囲内で確認されたメンバーごとに1行で、名前、ユーザー名、アクティブな日数、イベント、アクティビティ時間（分）、アプリ表示時間（分）、初回と最終に確認された日時を表示します。行を開くと、そのメンバーの1日あたりのイベントと使用したものが表示されます。
- **非アクティブ**は、範囲内にアクティビティがない現在のメンバーを、メンバーになった日時と最終に確認された日時とともに一覧表示します。**None recorded** は、保持されている履歴内にアクティビティがないことを意味します。履歴は最大25か月で、収集を開始してからのものに限られます。**CSVをダウンロード**で一覧をダウンロードします。非アクティブとは、どのエリアにもアクティビティがないことを意味するため、**エリア**は無視されます。ワークスペースから削除された、または無効化されたメンバーは、一覧にも集計にも含まれません。

### 内容

すべてのダッシュボード、アプリ、ノートブックを、**タイプ**、**メンバー**、**Reach**、**開封**、**アプリ表示時間（分）**（アプリのみ）、週ごとの **Trend**、**最終使用**とともに表示します。**タイプ**を選択して一覧を絞り込むか、**Hide unused** を選択して誰も開かなかった項目を除外します。行を開くと、その項目を使用したメンバーが表示されます。どちらの一覧も**CSVをダウンロード**でダウンロードできます。一覧の下の注記には、まだ収集されていないタイプや、後の日付から収集されたタイプが示されます。

### グループへの絞り込み

**グループ**は、**概要**、**内容**、**非アクティブ**の一覧を、1つのセキュリティグループのメンバーに限定します。制限を解除するには**全員**を選択します。ボックスに入力すると、ワークスペースのグループを検索できます。レポートはアクティビティが発生した時点ではなく現在のグループのメンバーシップを使用し、そのことがフィルターの横に表示されます。

- **アクティブ**なメンバー、**アクティビティ**、**パス**、**エクスポート**は絞り込まれません。これらのタブではフィルターが無効になり、その理由が表示されます。
- 月別の履歴はすべてのメンバーについて保持されるため、グループには**月別**は表示されません。
- メンバーがいないグループや、すでに存在しないグループでは、エラーではなく、空の結果とその旨の警告が返されます。
- ワークスペースのセキュリティグループを読み取れない場合、フィルターは表示されません。

### エクスポート

サマリーを CSV としてダウンロードします。**サマリー**と**日付範囲**を選択し、**CSVをダウンロード**を選択します。範囲は最大25か月です。

| サマリー | 内容 |
|---|---|
| **日別アクティビティ** | 日、エリア、イベント、対象ごとのメンバーとイベント。 |
| **メンバー別の日別アクティビティ** | 同じ内容をメンバーごとに、メンバー ID とともに。 |
| **月別の利用状況** | 月、エリア、イベント、対象ごとのメンバーとイベント。 |
| **月別アクティブメンバー** | 月とエリアごとのアクティブなメンバー。 |
| **初回利用** | 各メンバーが各エリアを初めて使用した日時を、メンバー ID とともに。 |

エクスポートでは、タブの上で選択したエリアが使用されます。大きなサマリーは最大50,000行のバッチに分けてダウンロードされ、ページがそれらを1つのファイルに結合します。ファイルがページで構築できるサイズを超える場合は、取得済みの内容を保存し、ファイルが不完全であることを通知します。残りを取得するには、より短い範囲を選択してください。

エクスポートを行うたびに、誰がどのサマリーを、どの範囲で、何行エクスポートしたかを記録するエントリがセキュリティログに書き込まれます。複数のバッチにまたがるサマリーでは、バッチごとにエントリが書き込まれます。

これらの数値をスケジュールに従ってテーブルに格納するには、代わりに [Get Workspace Usage](/ja/reference/workflow-steps/general/get-workspace-usage/) ステップを使用します。

<Aside type="caution">
月別のサマリーには、対象が `*` のイベントごとの合計行が含まれます。この行は、イベントのすべての対象にわたる重複を除いたメンバーとイベントです。対象の行に加算しないでください。すべてが二重にカウントされます。
</Aside>

### ファネル

メンバーが一連のステップをどれだけ通過するかを確認します。ステップは、いずれかのエリアのイベントを、特定の対象または**すべての件名**に対して指定したものです。ファネルでは選択した日付範囲（最大で過去90日間）が使用され、より長い範囲が短縮された場合はその旨が表示されます。

1. **ステップを追加**を選択し、各ステップのエリア、イベント、対象を選択します。ファネルには2〜6のステップを設定できます。
2. **ステップ間の許容時間**を選択します：1、6、24、72、168時間のいずれかです。
3. **ファネルを実行**を選択します。

結果には、各ステップについて、そこに到達したメンバーの数、開始したメンバーに対する割合、前のステップからの所要時間の中央値が表示されます。最後のステップを除く各ステップには、そこで離脱したメンバーの数が表示されます。最後のステップには、ファネルを完了した数が表示されます。ステップではエリアを混在させられるため、PlaidCloud の画面からダッシュボードまでメンバーを追跡できます。**最近のファネル**では、以前に実行したファネルを再度開けます。ステップの一覧には、範囲内に記録されたイベントのみが表示されます。

## メンバー未紐付けの利用状況

一部のイベントは、PlaidCloud のメンバーに紐付けられません。これらは**イベント**と**メンバー未紐付けのイベント**にはカウントされますが、メンバー数にはカウントされません。主なケースは次のとおりです。

- PlaidCloud 経由ではなく、Superset 内で作成された Superset アカウント。
- 埋め込みダッシュボードの閲覧（Superset ユーザーが存在しません）。
- プラットフォームのログではメンバーに紐付けられない、アプリとノートブックサーバーのアクティビティ。その紐付けはこれらのログに基づくため、ベストエフォートとして扱ってください。

あるエリアでメンバー未紐付けの割合が大きい場合、そのエリアのメンバー数は実際より少なく表示されています。

## 履歴の開始時期

履歴は、ワークスペースで利用状況の収集が有効になった時点から始まり、それより前の日や月にはアクティビティが表示されません。データがある最初の月は、部分的なものとして表示されます。

Panel と JupyterHub はプラットフォームのログから読み取られ、ログは約90日間保持されます。収集が開始されると、これら2つのエリアは最大でその期間分の過去の履歴で補完されます。Superset は独自のログから最大180日間分が補完されます。収集の開始時に何もない状態から始まるのは、PlaidCloud アプリだけです。

利用状況レポートは生のイベントを180日間保持します。これが最長の範囲が180日である理由です。月別のサマリーは25か月間保持されます。メンバーが PlaidCloud の外部（SCIM や Keycloak など）で削除された場合、そのメンバーの生の利用状況は180日後に、初回利用の記録は25か月後に失効します。

## メンバーの利用状況の消去

`identity.security_log.read` 権限を持つワークスペース管理者（またはスーパーユーザー）は、1人のメンバーの利用状況を消去して収集を停止し、後で消去を解除できます。消去と復元はどちらも、その権限とそのロールが必要です。これら2つの操作は REST API からのみ利用できます。

| 操作 | リクエスト |
|---|---|
| 消去 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 復元 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

消去すると、そのメンバーのイベントと初回利用の記録が削除され、その時点からレポートとエクスポートではそのメンバーが除外されます。そのメンバーの利用状況が再び収集されることはなく、後から Panel と JupyterHub のログから読み込まれる履歴も破棄されます。削除をすぐに完了できない場合は、レスポンスにその旨が示され、次回の毎時のメンテナンス実行で完了します。

復元すると消去が解除され、新しいアクティビティが再び収集されます。消去されたものは元に戻りません。

どちらの操作も、セキュリティログにエントリを書き込みます。
