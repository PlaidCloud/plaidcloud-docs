**利用状況レポート**では、ワークスペースで誰が何を使っているかを確認できます。メンバーが開く画面、ダッシュボード、アプリ、ノートブック、再訪するメンバーの数、次に移動する先がわかります。メンバーが何を活用しているか、どのダッシュボードやアプリが役立っているか、プロセスのどこで人が離脱しているかを把握するために使用します。

**ID**タブから、セキュリティログの隣にある項目として開きます。

## 表示できるユーザー

利用状況レポートには、セキュリティログと同じ `identity.security_log.read` 権限が必要です。権限がない場合はボタンが表示されず、レポートを開いたメンバーにはアクセス権がないことを示す通知が表示されます。

レポートでは、次の場所でメンバーごとの利用状況が表示されます。**メンバー**タブ、**内容**と**概要**から開くメンバーのリスト、メンバーIDを含む**日別のメンバー別アクティビティ**と**初回利用**のエクスポートです。それ以外は、メンバー全体で集計されます。権限は、個々のアクティビティを閲覧すべきユーザーにのみ付与してください。

## 集計の対象

利用状況レポートは5つのエリアを組み合わせています。**エリア**から1つを選択するか、**すべてのエリア**のままにします。

| エリア | 記録される内容 |
|---|---|
| PlaidCloud アプリ | メンバーが開く画面と、アプリ内で実行する操作。 |
| ダッシュボード | ダッシュボードとチャートの閲覧。 |
| アプリ | アプリへの訪問と、各アプリでメンバーが費やす時間。 |
| ノートブックサーバー | ノートブックサーバーのセッションでメンバーが費やす時間。 |
| ノートブック | メンバーが開いて保存するノートブック。 |

ノートブックサーバーとノートブックは別々のエリアなので、どちらか一方を選択できます。アプリは単一のエリアです。ノートブックのイベントは、デフォルトのノートブックイメージで実行されるノートブックについてのみ記録されます。カスタムイメージでは報告されません。

<Aside type="note">
レポート内の日付はすべてUTCの日付です。南北アメリカで夜遅くに作業しているメンバーは、翌日として表示されることがあります。
</Aside>

## レポートの見方

ウィンドウ上部のバーにフィルターがあります。各タブは、最初に開いたときと、フィルターを変更したときに読み込まれます。

| フィルター | 動作 |
|---|---|
| **エリア** | レポートを1つのエリアに限定します。ステップごとにエリアを選ぶ**ファネル**と、独自の選択肢がある**エクスポート**では非表示になります。 |
| **グループ** | レポートを1つのセキュリティグループのメンバーに限定します。[グループへの絞り込み](#グループへの絞り込み)を参照してください。 |
| **日付範囲** | **過去7日間**、**過去30日間**、**過去90日間**、**過去180日間**、**今月**、**前月**、または最大180日間の開始日と終了日を指定する**カスタム…**。 |
| **更新** | 数値を再読み込みします（F5）。**更新**には最後に読み込んだ日時が表示されます。 |

日付範囲はすべてのタブで共有されます。表示していたタブと選択した範囲はアカウント設定に保存されるため、どのコンピューターでも前回の状態でウィンドウが開きます。範囲を変更すると、表示中のタブが再読み込みされ、ほかのタブは開いたときに再読み込みされます。各タブにはそれぞれ説明があり、見出しや数値にポインターを合わせると意味を確認できます。

タブの読み込み中は、空白ではなくプレースホルダーが表示されます。レポートを読み込めない場合は、タブに理由が**再試行**と**詳細をコピー**とともに表示されます。範囲内にアクティビティがない場合は、より長い範囲を試すよう提案が表示されます。行を開くには、ダブルクリックするか、選択して Enter キーを押します。**戻る**を選択すると、開いた項目から一覧に戻ります。

### 概要

範囲全体の主要な数値です。それぞれに、同じ長さの前の期間からの変化を示す矢印とパーセンテージが付きます。

| 数値 | 意味 |
|---|---|
| **アクティブなメンバー** | 何らかのアクティビティがあるメンバー。 |
| **新規メンバー** | 範囲内で初めて確認されたメンバー。範囲が収集開始前から始まる場合は、それ以前の初回利用を判別できないため、ダッシュで表示されます。 |
| **再訪メンバー** | 範囲より前に初めて確認された、アクティブなメンバー。 |
| **アクティビティ分数** | 推定値：操作または閲覧のある5分間ごとに5分として計算します。 |
| **アプリ使用分数** | アプリとノートブックサーバーが開かれていた時間（アイドル時間を含む）。アクティビティ分数とは別に集計されます。 |
| **イベント** | 記録されたすべてのもの。 |

メンバーに紐付けられないイベントは、数値の下の行で別に集計されます。これらはメンバーではなくイベントとして数えられます。

**ハイライト**には、確認する価値のある項目が最大4つ表示され、それぞれ詳細を確認できる場所へのリンクになっています。

- 前の期間と比べて、アクティブなメンバーが10%以上増減した場合。
- 範囲内でアクティブでなかったメンバーの数。選択すると、非アクティブなメンバーの一覧が開きます。
- 誰も開かなかったダッシュボードとアプリの数。選択すると、未使用のものを先頭にした**内容**が開きます。
- 最もよく使われた項目（5人以上のメンバーが使用した場合）。

ハイライトは、伝える内容がある場合にのみ表示されます。PlaidCloudが件数を算出できない場合は、0を表示せずにハイライトを非表示にします。目立つものがない場合は、**この期間に注目すべき変化はありません。** と表示されます。

**利用上位**には、各画面、ダッシュボード、チャート、項目が、エリア、イベント、メンバー数、**リーチ**（範囲内で使用したアクティブなメンバーの割合）とともに一覧表示されます。列チューザーで**イベント**と**メンバーに紐付かないイベント**を追加できます。**月別（全履歴）** には、月ごとのアクティブなメンバー、1日あたりの平均メンバー数、**定着率（DAU/MAU）** が表示され、その月がまだ進行中の場合や一部しかカバーされていない場合は注記が付きます。定着率は、1日あたりの平均アクティブなメンバー数をその月のアクティブなメンバー数で割った値で、値が高いほど、より多くの日にメンバーが戻ってきていることを示します。

### アクティビティ

**毎日**、**毎週**、**毎月**の期間別のアクティブなメンバーと、**初回週別の継続率**を表示します。継続率は、メンバーが初めて現れた週ごとに、**コホートサイズ**と、その後の各週にもアクティブだったメンバーの割合を示します。アスタリスクが付いた期間は、全体が範囲内に収まっていません。

### パス

画面間で最もよく行われた移動を、エリアをまたいで**移動元**、**移動先**、**通過回数**として表示します。パスの対象は最大で過去30日間です。

### メンバー

**表示**で、2つの一覧を切り替えます。

- **アクティブ**には、範囲内で確認されたメンバーごとに1行が表示されます。名前、ユーザー名、アクティブな日数、イベント、アクティビティ分数、アプリ使用分数、初めて確認された日時と最後に確認された日時が含まれます。行を開くと、そのメンバーの日別のイベントと使用した内容を確認できます。
- **非アクティブ**には、範囲内にアクティビティがない現在のメンバーが、メンバーになった日時と最後に確認された日時とともに表示されます。**記録なし**は、保持されている履歴内にアクティビティがないことを意味します。履歴は最大25か月で、収集開始以降のものに限られます。一覧は**CSVをダウンロード**でダウンロードできます。非アクティブとは、どのエリアにもアクティビティがないことを意味するため、**エリア**の設定は無視されます。ワークスペースから削除されたメンバーは表示されません。

### 内容

すべてのダッシュボード、アプリ、ノートブックが、**タイプ**、**メンバー**、**リーチ**、**開封**、**アプリ使用分数**（アプリのみ）、週ごとの**トレンド**、**最終使用**とともに表示されます。**タイプ**を選択して一覧を絞り込むか、**未使用を非表示**を選択して誰も開かなかった項目を除外します。行を開くとその項目を使用したメンバーが表示され、どちらの一覧も**CSVをダウンロード**でダウンロードできます。一覧の下の注記には、まだ収集されていないタイプや、後の日付から収集が始まったタイプが示されます。

### グループへの絞り込み

**グループ**は、**概要**、**内容**、**非アクティブ**の一覧を1つのセキュリティグループのメンバーに限定します。制限を解除するには**全員**を選択します。ボックスに入力すると、ワークスペースのグループを検索できます。レポートは、アクティビティが発生した時点ではなく現在のグループのメンバーシップを使用し、その旨がフィルターの横に表示されます。

- **アクティブ**なメンバー、**アクティビティ**、**パス**、**エクスポート**は絞り込まれません。これらのタブではフィルターが無効になり、その理由が表示されます。
- **月別**は、月別の履歴が全員分で保持されているため、グループでは表示されません。
- メンバーのいないグループや、すでに存在しないグループでは、エラーではなく、空の結果とその旨の警告が返されます。
- ワークスペースのセキュリティグループを読み取れない場合、フィルターは表示されません。

### エクスポート

サマリーをCSVとしてダウンロードします。**サマリー**と**日付範囲**を選択し、**CSVをダウンロード**を選択します。範囲は最大25か月です。

| サマリー | 内容 |
|---|---|
| **日別アクティビティ** | 日、エリア、イベント、件名ごとのメンバーとイベント。 |
| **メンバー別の日別アクティビティ** | 上記をメンバーごとにしたもので、メンバーIDを含みます。 |
| **月別の利用状況** | 月、エリア、イベント、件名ごとのメンバーとイベント。 |
| **月間アクティブメンバー** | 月とエリアごとのアクティブなメンバー。 |
| **初回利用** | 各メンバーが各エリアを初めて使用した日時で、メンバーIDを含みます。 |

エクスポートでは、タブの上で選択したエリアが使用されます。大きなサマリーは最大50,000行のバッチに分けてダウンロードされ、ウィンドウがそれらを1つのファイルに結合します。ファイルがウィンドウで作成できるサイズを超える場合は、そこまでの内容を保存し、ファイルが不完全であることを通知します。残りを取得するには、より短い範囲を選択してください。

エクスポートのたびに、誰がどのサマリーを、どの範囲で、何行エクスポートしたかを記録したエントリーがセキュリティログに書き込まれます。複数のバッチにまたがるサマリーでは、バッチごとにエントリーが書き込まれます。

これらの数値をスケジュールに従ってテーブルに書き込むには、[Get Workspace Usageステップ](/ja/reference/workflow-steps/general/get-workspace-usage/)を使用します。

<Aside type="caution">
月別のサマリーには、各イベントの合計行が含まれ、件名は `*` です。この行は、そのイベントのすべての件名にわたる重複のないメンバーとイベントを表します。件名ごとの行に加算すると二重に数えることになるため、加算しないでください。
</Aside>

### ファネル

一連のステップを通過するメンバーの数を確認します。ステップは、いずれかのエリアのイベントを特定の件名、または**すべての件名**に対して指定したものです。ファネルでは選択した日付範囲を最大で過去90日間まで使用し、それより長い範囲を短縮した場合はその旨が表示されます。

1. **ステップを追加**を選択し、各ステップのエリア、イベント、件名を選択します。ファネルは2〜6ステップで構成します。
2. **ステップ間の許容時間**を、1、6、24、72、168時間から選択します。
3. **ファネルを実行**を選択します。

結果には、ステップごとに、到達したメンバーの数、開始したメンバーに対する割合、前のステップからの所要時間の中央値が表示されます。最後のステップ以外では、そこで止まったメンバーの数が表示されます。最後のステップでは、ファネルを完了したメンバーの数が表示されます。ステップではエリアを混在させられるため、PlaidCloud の画面からダッシュボードまでメンバーを追跡できます。**最近のファネル**では、以前に実行したファネルを開き直せます。ステップの一覧には、範囲内で記録されたイベントのみが表示されます。

## 紐付けられない利用状況

一部のイベントは、PlaidCloud のメンバーに紐付けられません。これらは**イベント**と**メンバー未紐付けのイベント**には含まれますが、メンバー数には含まれません。主なケースは次のとおりです。

- PlaidCloud 経由ではなく Superset 内で作成された Superset アカウント。
- 埋め込みダッシュボードの閲覧（Superset ユーザーが存在しません）。
- プラットフォームのログからメンバーに紐付けられないアプリとノートブックサーバーのアクティビティ。これらの紐付けはそのログに基づくため、ベストエフォートとして扱ってください。

あるエリアで紐付けられないイベントの割合が大きい場合、そのエリアのメンバー数は実際より少なく表示されています。

## 履歴の開始時期

履歴は、ワークスペースで利用状況の収集がオンになった時点から始まり、それ以前の日や月にはアクティビティが表示されません。データがある最初の月は、一部のみとして表示されます。

PanelとJupyterHubは、約90日間保持されるプラットフォームログから読み取られます。収集が開始されると、この2つのエリアでは、最大でその期間分の過去の履歴が補完されます。Superset は独自のログから最大180日分が補完されます。収集開始時に何もない状態から始まるのは、PlaidCloud アプリだけです。

利用状況レポートは、生のイベントを180日間保持します。そのため、最長の範囲は180日間です。月別のサマリーは25か月間保持されます。SCIMやKeycloakなど、PlaidCloud の外部でメンバーが削除された場合、そのメンバーの生の利用状況は180日後に、初回利用の記録は25か月後に期限切れになります。

## メンバーの利用状況の消去

`identity.security_log.read` 権限を持つワークスペース管理者（またはスーパーユーザー）は、1人のメンバーの利用状況を消去して収集を停止し、後で消去を解除できます。消去と復元のどちらにも、その権限とロールが必要です。この2つの操作はREST APIでのみ利用できます。

| 操作 | リクエスト |
|---|---|
| 消去 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 復元 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

消去すると、そのメンバーのイベントと初回利用の記録が削除され、その時点からレポートとエクスポートにそのメンバーは含まれなくなります。利用状況は再び収集されることはなく、後からPanelやJupyterHubのログで読み取られる履歴も破棄されます。削除をすぐに完了できない場合はレスポンスでその旨が通知され、次回の1時間ごとのメンテナンス実行で完了します。

復元すると消去が解除され、新しいアクティビティが再び収集されます。消去されたものは元に戻りません。

どちらの操作も、セキュリティログにエントリーを書き込みます。
