**利用状況レポート**では、ワークスペースで誰が何を使っているかを確認できます。メンバーが開く画面、ダッシュボード、アプリ、ノートブック、再訪するメンバーの数、そして次にどこへ移動するかがわかります。メンバーが何を活用しているか、どのダッシュボードやアプリが役立っているか、プロセスのどこで離脱が起きているかを把握するために使用します。

**ID** タブから、セキュリティログの隣にある項目として開きます。

## 閲覧できるユーザー

利用状況レポートには、セキュリティログと同じ権限 `identity.security_log.read` が必要です。この権限がない場合はボタンが表示されず、それでもレポートを開いたメンバーには、アクセス権がないことを知らせる通知が表示されます。

レポートでは、次の場所でメンバーごとの利用状況が表示されます。**メンバー**タブ、**内容**や**概要**から開くメンバーの一覧、そしてメンバー ID を含む**メンバー別の日別アクティビティ**と**初回利用**のエクスポートです。それ以外はすべてメンバー全体の集計です。個々のアクティビティを閲覧する必要がある人にのみ、この権限を付与してください。

## 集計の対象

利用状況レポートは5つのエリアを組み合わせたものです。**エリア**から1つを選ぶか、**すべてのエリア**のままにします。

| エリア | 記録される内容 |
|---|---|
| PlaidCloud アプリ | メンバーが開く画面と、アプリ内で行う操作。 |
| ダッシュボード | ダッシュボードとチャートの表示。 |
| アプリ | アプリへのアクセスと、メンバーが各アプリで過ごした時間。 |
| ノートブックサーバー | メンバーがノートブックサーバーのセッションで過ごした時間。 |
| ノートブック | メンバーが開いて保存したノートブック。 |

ノートブックサーバーとノートブックは別々のエリアなので、どちらか一方を選択できます。アプリは1つのエリアです。ノートブックのイベントは、デフォルトのノートブックイメージで実行されるノートブックについてのみ記録されます。カスタムイメージでは報告されません。

<Aside type="note">
レポート内の日付はすべて UTC の日付です。南北アメリカで夜遅くに作業しているメンバーは、翌日として表示されることがあります。
</Aside>

## レポートの見方

ウィンドウ上部のバーにフィルターがあります。各タブは、最初に開いたときと、フィルターを変更したときに読み込まれます。

| フィルター | 動作 |
|---|---|
| **エリア** | レポートを1つのエリアに絞り込みます。各ステップでエリアを選ぶ**ファネル**と、独自の選択肢を持つ**エクスポート**では非表示になります。 |
| **グループ** | レポートを1つのセキュリティグループのメンバーに絞り込みます。[グループへの絞り込み](#グループへの絞り込み)を参照してください。 |
| **日付範囲** | **過去7日間**、**過去30日間**、**過去90日間**、**過去180日間**、**今月**、**前月**、または開始日と終了日（最大180日間）を指定する **カスタム…** オプション。 |
| **更新** | 数値を再読み込みします（F5）。**更新**の表示で最後に読み込んだ時刻を確認できます。 |

日付範囲はすべてのタブで共有されます。表示中のタブと選択した範囲はアカウント設定に保存されるため、どのコンピューターでも前回の状態でウィンドウが開きます。範囲を変更すると、表示中のタブが再読み込みされ、ほかのタブは開いたときに再読み込みされます。各タブには独自の説明があり、見出しや数値にポインターを合わせると意味が表示されます。

タブの読み込み中は、空白のページではなくプレースホルダーが表示されます。レポートを読み込めない場合、タブには理由とともに**再試行**と**詳細をコピー**が表示されます。範囲内にアクティビティがない場合は、より長い範囲を試すよう提案が表示されます。行を開くには、ダブルクリックするか、行を選択して Enter を押します。開いた項目から一覧に戻るには**戻る**を使用します。

### 概要

選択した範囲の主要な数値です。それぞれ、同じ長さの前の期間からの変化を示す矢印とパーセンテージが付きます。

| 数値 | 意味 |
|---|---|
| **アクティブなメンバー** | 何らかのアクティビティがあったメンバー。 |
| **新規メンバー** | 範囲内で初めて確認されたメンバー。範囲が収集開始前から始まる場合は、それ以前の初回利用を判別できないため、ダッシュで表示されます。 |
| **再訪メンバー** | 範囲より前に初めて確認されたアクティブなメンバー。 |
| **アクティビティ時間（分）** | 推定値。操作または表示のあった5分間ごとに5分として計算します。 |
| **アプリ起動時間（分）** | アプリとノートブックサーバーが開いていた時間（アイドル時間を含む）。アクティビティ時間とは別に集計されます。 |
| **イベント** | 記録されたすべてのもの。 |

メンバーに紐付けられないイベントは、数値の下の行に別途集計されます。これらはメンバーではなくイベントとして数えられます。

**ハイライト**には、確認する価値のある項目が最大4つ表示され、それぞれ詳細を確認できる場所へのリンクになっています。

- アクティブなメンバーが、前の期間と比べて10%以上増減した場合。
- 範囲内でアクティブでなかったメンバーの数。選択すると、非アクティブなメンバーの一覧が開きます。
- 誰も開かなかったダッシュボードとアプリの数。選択すると、未使用のものを先頭にして**内容**が開きます。
- 最も使用されている項目（5人以上のメンバーが使用した場合）。

ハイライトは、伝えるべき内容がある場合にのみ表示されます。PlaidCloud が件数を算出できない場合、0 を表示せずにそのハイライトを非表示にします。目立つものがない場合は、**この期間に目立った変化はありません。** と表示されます。

**最も使用されているもの**には、各画面、ダッシュボード、チャート、項目が、エリア、イベント、メンバー数、**リーチ**（範囲内にそれを使用したアクティブなメンバーの割合）とともに一覧表示されます。列の選択から**イベント**と**メンバーに紐付かないイベント**を追加できます。**月別（全期間）** には、月ごとのアクティブなメンバー、1日あたりの平均メンバー数、**定着率（DAU/MAU）** が表示され、その月がまだ進行中の場合や一部しか対象になっていない場合は注記が付きます。定着率は、1日あたりの平均アクティブメンバー数をその月のアクティブなメンバー数で割った値で、値が高いほど、より多くの日にメンバーが戻ってきていることを意味します。

### アクティビティ

**毎日**、**毎週**、**毎月**の期間別のアクティブなメンバーと、**初回週別の継続率**を表示します。継続率では、メンバーが初めて現れた週ごとに、**コホートサイズ**と、その後の各週にもアクティブだったメンバーの割合が示されます。アスタリスクが付いた期間は、全体が範囲内に収まっていません。

### パス

エリアをまたいだ、画面間で最も多く行われた移動を、**移動元**、**移動先**、**通過回数**として表示します。パスの対象は最大で過去30日間です。

### メンバー

**表示**で2つの一覧を切り替えます。

- **アクティブ**は、範囲内で確認されたメンバーごとに1行で、名前、ユーザー名、アクティブな日数、イベント、アクティビティ時間（分）、アプリ起動時間（分）、初めて確認された日時と最後に確認された日時が表示されます。行を開くと、そのメンバーの日ごとのイベントと使用したものを確認できます。
- **非アクティブ**は、範囲内にアクティビティがない現在のメンバーを、メンバーになった日時と最後に確認された日時とともに一覧にします。**記録なし**は、保持されている履歴にアクティビティがないことを意味し、履歴は最大25か月分で、収集開始以降のものに限られます。一覧は**CSVをダウンロード**でダウンロードできます。非アクティブとはいずれのエリアにもアクティビティがないことを意味するため、**エリア**は無視されます。ワークスペースから削除されたメンバーは一覧に含まれません。

### 内容

すべてのダッシュボード、アプリ、ノートブックが、**タイプ**、**メンバー**、**リーチ**、**開封**、**アプリ起動時間（分）**（アプリのみ）、週ごとの**推移**、**最終使用**とともに表示されます。**タイプ**を選んで一覧を絞り込むか、**未使用を非表示**を選択して誰も開いていない項目を除外します。行を開くと、その項目を使用したメンバーを確認できます。どちらの一覧も**CSVをダウンロード**でダウンロードできます。一覧の下の注記には、まだ収集されていないタイプや、それ以降の日付からしか収集されていないタイプが示されます。

### グループへの絞り込み

**グループ**は、**概要**、**内容**、**非アクティブ**の一覧を、1つのセキュリティグループのメンバーに絞り込みます。**全員**を選ぶと絞り込みが解除されます。ボックスに入力すると、ワークスペースのグループを検索できます。レポートでは、アクティビティが発生した時点ではなく現在のグループメンバーシップが使用され、そのことがフィルターの横に表示されます。

- **アクティブ**なメンバー、**アクティビティ**、**パス**、**エクスポート**は絞り込まれません。これらのタブではフィルターが無効になり、その理由が表示されます。
- 月別の履歴は全員分が保持されるため、グループを指定した場合は**月別**は表示されません。
- メンバーがいないグループ、または存在しなくなったグループでは、エラーではなく、空の結果とその旨の警告が返されます。
- ワークスペースのセキュリティグループを読み取れない場合、フィルターは表示されません。

### エクスポート

サマリーを CSV としてダウンロードします。**サマリー**と**日付範囲**を選び、**CSVをダウンロード**を選択します。範囲は最大25か月です。

| サマリー | 内容 |
|---|---|
| **日別アクティビティ** | 日、エリア、イベント、件名ごとのメンバー数とイベント数。 |
| **メンバー別の日別アクティビティ** | 同じ内容をメンバーごとに表示し、メンバー ID を含みます。 |
| **月別の利用状況** | 月、エリア、イベント、件名ごとのメンバー数とイベント数。 |
| **月別アクティブなメンバー** | 月とエリアごとのアクティブなメンバー数。 |
| **初回利用** | 各メンバーが各エリアを初めて使用した日時。メンバー ID を含みます。 |

エクスポートでは、タブの上で選択したエリアが使用されます。大きなサマリーは最大50,000行ずつのバッチでダウンロードされ、ウィンドウがそれらを1つのファイルにまとめます。ファイルがウィンドウで構築できるサイズを超える場合は、そこまでの内容を保存し、ファイルが不完全であることを通知します。残りを取得するには、範囲を短くしてください。

エクスポートのたびに、誰がどのサマリーを、どの範囲で、何行エクスポートしたかがセキュリティログに記録されます。複数のバッチにまたがるサマリーでは、バッチごとにエントリが書き込まれます。

これらの数値を定期的にテーブルに書き込むには、代わりに [Get Workspace Usageステップ](/ja/reference/workflow-steps/general/get-workspace-usage/)を使用します。

<Aside type="caution">
月別のサマリーには、各イベントの合計行が件名 `*` で含まれます。この行は、そのイベントのすべての件名にわたる重複のないメンバー数とイベント数です。件名の行に加算しないでください。すべてが二重に計算されます。
</Aside>

### ファネル

メンバーが一連のステップをどれだけ通過するかを確認します。ステップは、いずれかのエリアのイベントを特定の件名または**すべての件名**で指定したものです。ファネルは、選択した日付範囲（最大で過去90日間）を使用し、長い範囲を短縮した場合はその旨が表示されます。

1. **ステップを追加**を選択し、各ステップのエリア、イベント、件名を選びます。ファネルのステップ数は2〜6です。
2. **ステップ間の許容時間**を1、6、24、72、168時間から選びます。
3. **ファネルを実行**を選択します。

結果には、ステップごとに、そこに到達したメンバー数、開始したメンバーに対する割合、前のステップからの所要時間の中央値が表示されます。最後のステップを除く各ステップには、そこで離脱したメンバー数が表示されます。最後のステップには、ファネルを完了した人数が表示されます。ステップではエリアを混在させられるため、PlaidCloud の画面からダッシュボードまで、メンバーの動きを追跡できます。**最近のファネル**から、以前に実行したファネルを開き直せます。ステップの一覧には、範囲内で記録されたイベントのみが表示されます。

## メンバー未紐付けの利用状況

一部のイベントは PlaidCloud のメンバーに紐付けられません。これらは**イベント**と**メンバー未紐付けのイベント**には含まれますが、メンバー数には含まれません。主なケースは次のとおりです。

- PlaidCloud ではなく Superset 内で作成された Superset アカウント。
- 埋め込みダッシュボードの表示（Superset ユーザーが存在しません）。
- プラットフォームのログからメンバーに紐付けられないアプリとノートブックサーバーのアクティビティ。これらの紐付けはそれらのログに基づくため、ベストエフォートとして扱ってください。

あるエリアで紐付けられないイベントの割合が大きい場合、そのエリアのメンバー数は実際より少なく表示されています。

## 履歴の開始時点

履歴は、ワークスペースで利用状況の収集が有効になった時点から始まり、それ以前の日や月にはアクティビティが表示されません。データのある最初の月は、部分的なデータとして示されます。

Panel と JupyterHub はプラットフォームのログから読み取られ、ログは約90日間保持されます。収集が開始されると、この2つのエリアでは、最大でその期間分の過去の履歴が補完されます。Superset は独自のログから最大180日分が補完されます。収集の開始時に何もない状態から始まるのは、PlaidCloud アプリだけです。

利用状況レポートは生のイベントを180日間保持するため、最長の範囲は180日間になります。月別のサマリーは25か月間保持されます。SCIM や Keycloak など PlaidCloud の外部でメンバーが削除された場合、そのメンバーの生の利用状況は180日後に、初回利用の記録は25か月後に削除されます。

## メンバーの利用状況を消去する

`identity.security_log.read` 権限を持つワークスペース管理者（またはスーパーユーザー）は、1人のメンバーの利用状況を消去して収集を停止し、後で消去を解除できます。消去と復元のどちらも、この権限とこのロールが必要です。この2つの操作は REST API からのみ利用できます。

| 操作 | リクエスト |
|---|---|
| 消去 | `DELETE /rest/v1/identity/usage/users/{user_id}` |
| 復元 | `DELETE /rest/v1/identity/usage/users/{user_id}/erasure` |

消去すると、そのメンバーのイベントと初回利用の記録が削除され、その時点からレポートとエクスポートではそのメンバーが除外されます。以降、そのメンバーの利用状況は収集されず、後から Panel や JupyterHub のログで読み込まれる履歴も破棄されます。削除をすぐに完了できない場合は、その旨がレスポンスに示され、次回の毎時のメンテナンス実行で完了します。

復元すると消去が解除され、新しいアクティビティが再び収集されます。消去されたデータは元に戻りません。

どちらの操作もセキュリティログにエントリが書き込まれます。
