## 追加

- **Data Foundation で ERP データを 1 つの Common Finance Model に統合できます。** Common Finance Model は、複数の ERP システムやインスタンスの ERP データを 1 つのモデルにまとめます。勘定科目表、エンティティ、報告通貨はそれぞれ 1 つに統一されます。このモデルを基に構築したレポート、メトリック、AI アシスタントは、元の ERP が何であっても同じ数値を参照します。

  - **ERP から直接取り込み。** 総勘定元帳、試算表、マスターデータ、予算は、PlaidCloud の ERP 直接接続で取り込まれます。**エンティティ対応表** で各ソースの会社コードを共通のエンティティに対応付けます。為替レートや配賦ドライバーなど、システムに存在しないデータはファイルで補えます。
  - **1 つのモデル、1 つの通貨。** **ロード** はすべてのソースを Common Finance Model に整合させ、報告通貨に換算します。損益計算書は期間の平均レート、貸借対照表は期末レート、資本は取得時のレートで換算されます。階層はマスターデータから構築されます。
  - **準備状況の確認。** エンティティと期間ごとにチェックを実行します。試算表と売上が総勘定元帳と一致していること、すべての製品、顧客、勘定科目が既知であること、通貨が換算されること、すべてのエンティティが対応付けられていることを確認します。
  - **常に最新の状態に保つ。** **夜間に更新** は毎晩モデルを再ロードします。ファイルが存在しない、または空の場合は、エラーではなく警告付きで完了します。

  **Enterprise Profitability** などのテンプレートからプロジェクトを開始すると、プロジェクトの **Foundation** タブで、ERP の接続からロードとチェックが完了したモデルまで進められます。[Data Foundation: Common Finance Model](/ja/guides/projects/data-foundation/) を参照してください。

- **PlaidCloud を独自の Snowflake または Databricks ウェアハウスで実行できます。** ワークスペース管理者がユーザーメニューの **自分のウェアハウスを使用する** を開き、生成されたセットアップスクリプトを自分のアカウントで実行します。このスクリプトは、上限付きのウェアハウスと PlaidCloud 用のサービス ID を作成し、既存のウェアハウスには一切触れません。**接続を確認** は、問題とその解決方法を分かりやすい言葉で説明します。以降、新しいプロジェクトのテーブルの保存とワークフローの実行は、お使いのウェアハウスで行われます。ウェアハウスを削除すると、そこでの PlaidCloud のアクセス権も取り消されます。[自分のウェアハウスを使用する](/ja/guides/connections/external-lakehouse/) を参照してください。

  - **Snowflake または Databricks でサインイン。** 管理者は、資格情報を貼り付ける代わりに、サインインしてウェアハウスを接続できます。これにより、ダッシュボードは各ユーザー自身のウェアハウス権限で実行され、ワークフローは、指定したデータロールのみを持つサービス ID として実行されます。[Snowflake または Databricks でサインイン](/ja/guides/connections/external-lakehouse/#snowflake-または-databricks-でサインインする) を参照してください。
  - **複数のウェアハウスを接続。** **ウェアハウスの管理** の **デフォルトに設定** を使うと、新しいプロジェクトの保存先を別のウェアハウスに切り替えられます。既存のプロジェクトは現在の場所に残ります。[ウェアハウスの管理](/ja/guides/connections/external-lakehouse/#ウェアハウスを管理する) を参照してください。
  - **実行のコストを確認。** 実行履歴には、実行ごとのクレジットまたは DBU を示す **ウェアハウスコスト** 列が表示されます。[実行ごとのウェアハウスコスト](/ja/guides/connections/external-lakehouse/#実行ごとのウェアハウスコスト) を参照してください。
  - **ガバナンスはそのまま維持。** 説明はウェアハウス自身のカタログに書き込まれます。PlaidCloud がテーブルを置き換え、再作成、またはクローンしても、Snowflake の行アクセスポリシーとマスキングポリシー、Databricks の行フィルターと列マスクは引き継がれます。[ポリシーと説明の引き継ぎ](/ja/guides/connections/external-lakehouse/#ポリシーと説明が引き継がれる) を参照してください。

- **Panel アプリの構築、公開、ブランド設定を PlaidCloud 内で行えます。**

  - **Panel Studio。** **マイPanelアプリ** の最初のボタンである **新しい Studio アプリ** から、空のアプリ、テーブル、ビュー、別の Studio アプリ、またはアプリギャラリーを出発点にできます。**テーブル** タブの **Panel アプリを作成** は、選択したテーブルから開始します。**Studio で開く** を選ぶと、アプリのファイルがエディターで開きます。下書きを保存し、非公開のビルドを **プレビュー** し、稼働中のアプリを **公開** できます。ビルドエラーには該当のファイルと行が示され、**履歴** から公開済みの任意のバージョンを復元でき、**インサイト** には表示回数、読み込み時間、エラーが表示されます。**Weave に質問** はアプリのファイルとビルドの状態を把握しており、コードを保存する前に、変更点の全体を承認用に表示します。[Panel Studio](/ja/guides/panel-apps/studio/) と [Weave で Panel アプリを構築する](/ja/guides/panel-apps/build-with-weave/) を参照してください。
  - **PlaidCloud らしい見た目のアプリキット。** このキットで構築したアプリは、ライトとダークの両方で PlaidCloud の配色、書体、余白を使用します。キットには、ナビゲーション、フィルター、主要な数値のカード、チャート、フォーム、コマンドパレット、ワークフローを実行するボタン、印刷、そしてデータグリッドが含まれます。データグリッドは、サーバー側での並べ替えと集計、列ごとの数値書式設定、1 画面分ずつの行の読み込みに対応しているため、どんな大きさのテーブルでも扱えます。アプリは、サインインしている閲覧者として、行セキュリティを適用してテーブルを読み取ります。[Panel アプリキット](/ja/guides/panel-apps/app-kit/)、[DataGrid](/ja/guides/panel-apps/app-kit/#datagrid)、[Panel アプリのデータ API](/ja/guides/panel-apps/data-api/) を参照してください。
  - **アラートとダイジェスト。** プロジェクトのテーブルの数値が上限を超えたときに、プッシュ通知、メール、Slack、Microsoft Teams で通知を受け取れます。最大 10 個の数値を毎日または毎週まとめたダイジェストも受け取れます。いずれも常にご自身の行アクセスの範囲内で動作します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/) を参照してください。
  - **プロジェクト、ブランド設定、共有。** アプリをプロジェクトに割り当てられます。その際は、プロジェクトのメンバーではないが開くことができるユーザーを確認します。プロジェクトの **ホーム** タブにある **ブランディングを編集** で、そのプロジェクトのすべてのアプリに適用される 8 色のブランドカラーとロゴを設定します。**ギャラリー…** ボタンは、プロジェクトに属する Studio アプリを、そのプロジェクトを閲覧できる全員向けのテンプレートとして掲載し、**ギャラリーから外す** で掲載を取り消します。[プロジェクトのブランド設定とアプリのプロジェクト](/ja/guides/panel-apps/branding/) と [アプリギャラリー](/ja/guides/panel-apps/gallery/) を参照してください。

- **ビジネス上の数値の計算方法を一度決めれば、AI の回答はすべてその計算を使います。** プロジェクトのアーキテクトが、*純売上* や *従業員数* などの **メトリック** を定義します。定義する内容は、ソーステーブル、行の合計方法、常に含める行、結合するルックアップテーブル、内訳に使える列です。定義は保存した時点で有効になります。存在しないテーブルや列を指定している場合や、ルックアップに 1 つのキーに対して複数の行がある場合は、保存が拒否されます。AI アシスタントにメトリックを名前または同義語で尋ねると、数値はアシスタントが独自に算出するのではなく、定義に従って、ご自身の行アクセスの範囲内で計算されます。定義の管理は、AI アシスタントまたは REST API から行います。[メトリック定義](/ja/integrations/ai-coding-agents/metric-definitions/) を参照してください。

  - **派生メトリック。** 1 人あたりの純売上のように 2 つのメトリックの比率、合計、差を定義したり、メトリックに固定の係数を掛けたりできます。[他のメトリックから派生させる](/ja/integrations/ai-coding-agents/metric-definitions/#他のメトリックから派生させる) を参照してください。
  - **比較、ランキング、構成比。** 予算との差異、同順位を保持した上位または下位 N 件、各行の合計に占める割合を尋ねられます。[比較、ランキング、構成比](/ja/integrations/ai-coding-agents/metric-definitions/#比較ランキング構成比) を参照してください。
  - **ふだんの言葉で、合意した値を。** 内訳の列をディメンションに紐付けると、*EMEA* のような言葉がその配下のすべての地域として解釈されます。何にも一致しない言葉や、複数のメンバーに一致する言葉は、推測せずに候補として返され、確認を求められます。[メトリックについて尋ねる](/ja/integrations/ai-coding-agents/metric-definitions/#メトリックについて質問する) を参照してください。
  - **会計時間。** メトリックの行が会計カレンダーのどこに位置するかを指定すると、会計期間、年初来、前年比、前期比を尋ねられます。[時間軸で比較する](/ja/integrations/ai-coding-agents/metric-definitions/#時間の経過に沿って比較する) を参照してください。

  PlaidCloud 自身の AI アシスタントは、ビジネス上の数値にはまずメトリックから回答し、その数値を ✓ 付きの専用カードに表示します。この ✓ がアシスタント自身のテキストに付くことはありません。[ビジネス上の数値](/ja/guides/ai-assistant/weave-tab/#ビジネス数値) と [メトリックの数値](/ja/guides/ai-assistant/weave-tab/#メトリックからの数値) を参照してください。

- **締め処理の準備ができているか Weave に尋ね、2 つのテーブルが一致するか確認できます。** どちらにも AI は使用しません。

  - **締め処理の準備状況。** 締め処理、予測、その他の期限が依存するワークフローを、プロジェクトの **Weave** タブの **準備状況** から **準備状況セット** として指定します。1 つのチェックリストですべてに答えます。たとえば「13 件中 11 件が準備完了、1 件が未準備、1 件はチェックできませんでした」のように表示されます。ワークフローが準備完了になるのは、Weave が実行できたすべてのチェックに合格した場合のみです。Weave が判断できなかったものは、理由とともに **チェックできませんでした** と表示され、準備完了とは決して表示されません。新しいワークフローなど、直近の実行と比較できる過去の履歴が少ない場合は、通常どおりとして扱われます。メールの送信やファイルのエクスポートなど、テーブルに書き込まないステップには、確認すべき行や空の値がないため、ワークフローが **チェックできませんでした** のまま止まることはありません。[締め処理の前に準備状況を確認する](/ja/guides/ai-assistant/weave-readiness/) を参照してください。
  - **照合。** 2 つのテーブル、または 1 つのテーブルの 2 つの期間を、対応付けたキー列で行ごとに比較します。Weave は、一致するかどうか、差がどれだけあるか、どの行が異なるかを示し、全体を読み取れなかったデータについて「一致する」とは決して言いません。各照合は、使用される前に別のアーキテクトが承認します。[2 つのテーブルが一致するか確認する](/ja/guides/ai-assistant/weave-reconciliation/) を参照してください。

- **Weave は問題になりうる事象をより広く監視し、実行の合間にも通知します。** Weave のチェックに AI は使用しません。すべての検出事項と AI アシスタントのすべての回答に **Weaveが把握する方法** パネルがあります。検出事項では、チェックの内容とその根拠となる値が表示されます。回答では、アシスタントが実行した各クエリが表示され、各文に **一致**、**不一致**、**未確認** のいずれかが付きます。[Weave が現在チェックする内容](/ja/guides/ai-assistant/weave-findings/#現在weaveがチェックする内容)、[Weave が把握する方法](/ja/guides/ai-assistant/weave-findings/#weaveが把握する方法)、[AI アシスタントでの Weave が把握する方法](/ja/guides/ai-assistant/weave-tab/#weaveが把握する方法) を参照してください。

  - **テーブルの書き込みが期限どおりか。** スケジュールの期限が過ぎても書き込まれていないテーブルや、テーブルの詳細の **鮮度** で設定した鮮度のしきい値（1 時間から 180 日）より長く書き込まれていないテーブルを報告します。
  - **古い、または壊れた入力。** 別のワークフローがその後に書き込んだテーブルを読み取っているワークフローを報告します。また、失敗した実行に依存するすべてのワークフローとダッシュボードも報告します。これには、SQL データセットを基にしたチャートを持つダッシュボードも含まれます。**依存関係の同期** は、ステップと、そのステップが読み取るテーブルとの間に不足しているコネクターを追加します。[依存関係の同期](/ja/guides/workflows/sync-dependencies/) を参照してください。
  - **形が変わったデータ。** 実行後に値の分布が大きく変わった小数列、行を複数回書き込むようになった結合、型を変換できなかったために Extract ステップが空のままにした値、ファイルが見つからなかったインポートを報告します。また、最新の期間が通常から大きく外れているメトリックについても、その要因となった項目を挙げて報告します。Weave は月末や曜日のパターンを考慮するため、月末に常に負荷が高いロードは報告されません。[メトリックの異常な合計](/ja/guides/ai-assistant/weave-metric-insights/) を参照してください。
  - **遅くなった実行。** 実行を遅くしたステップを特定します。また、新しい実行が古い実行より 4 分の 1 以上長くかかっているワークフローを報告し、所要時間が最も増えたステップを挙げます。
  - **実行の合間の通知。** 1 時間ごとのチェックで、各問題の所有者にアプリ内メッセージで 1 回だけ通知します。ヘッダーの **Weave** ボタンには、すべてのプロジェクトで未読の問題の数が表示されます。[実行の合間の通知](/ja/guides/ai-assistant/weave-findings/#実行の合間の通知) と [ヘッダーの Weave ボタン](/ja/guides/ai-assistant/weave-tab/#ヘッダーのweaveボタン) を参照してください。
  - **所有者、コメント、想定内の警告。** 各検出事項には所有者がいて、既定ではそのワークフローを最後に実行した人です。**割り当て** で別の人に引き継ぎ、コメントで進捗を記録し、**チーム** ビューで誰が何を担当しているかを確認できます。アーキテクトは、理由と終了日を付けて警告を **これは想定内** としてマークできます。[検出事項に所有者を設定する](/ja/guides/ai-assistant/weave-tab/#検出事項に担当者を設定する) と [検出事項を想定内としてマークする](/ja/guides/ai-assistant/weave-tab/#検出事項を想定内としてマークする) を参照してください。

- **修正アシスタントは、エラーを説明し、承認できる変更をカードで提案し、ステップを再実行し、修正を元に戻すこともできます。** テーブルにない列、空の必須設定、データベースが読み取れない SQL、型の誤った値など、よくある失敗については、最初の返信で一般的な原因と修正方法を説明します。提案された変更はカードとして表示され、ステップが失敗した理由と、変更される各設定が、現在の値は赤、新しい値は緑で示されます。**承認** で適用され、アシスタントはステップの再実行を提案し、新たな失敗があれば診断します。**Weave** タブの検出事項にある **修正** を押すと、その問題についてアシスタントが開きます。**元に戻す** はステップの以前の設定を復元し、**元に戻して実行** は出力を再構築します。[AI でワークフローのエラーを修正する](/ja/guides/ai-assistant/fixing-workflow-errors/)、[AI アシスタントで検出事項を修正する](/ja/guides/ai-assistant/weave-tab/#aiアシスタントで検出事項を修正する)、[修正を元に戻す](/ja/guides/ai-assistant/fixing-workflow-errors/#修正を元に戻す) を参照してください。

- **プロジェクト内で Weave が行ったすべての操作を確認し、監査人向けにエクスポートできます。** プロジェクトの **Weave** タブの **アクティビティ** には、Weave が見つけた後に見つからなくなった問題、AI アシスタントが提案したすべての変更、リクエストした人と承認または却下した人、置き換えた内容と書き込んだ内容の詳細、そして結果が一覧表示されます。Weave は、変更を行う前に承認を記録し、記録できない変更は行いません。**CSVのエクスポート** または **PDFのエクスポート** で、期間を監査証跡として保存できます。エントリーの編集や削除はできません。**サマリー** には、見つかって解決された問題、承認された変更、元に戻された件数など、1 か月の概要が表示されます。ワークスペース管理者は、**ワークスペースサマリー…** ボタンからすべてのプロジェクトについて同じ情報を確認できます。[Weave のアクティビティ履歴](/ja/guides/ai-assistant/weave-activity/) と [Weave の月次サマリー](/ja/guides/ai-assistant/weave-monthly-summary/) を参照してください。

- **保存する前に、ステップの内容と、変更の影響を把握できます。** これらはすべてプロジェクトの保存済みの設定から作成され、AI は使用しません。ロールによって非表示になっているものは、数に含まれますが、名前は表示されません。

  - **すべてのテーブル、ステップ、ワークフローのドキュメント。** 詳細パネルの **ドキュメント** セクションには、ステップの動作とワークフローのステップの順序が記載されます。テーブルの読み取りと書き込みを行うものは、Weave と AI アシスタントから参照できます。テーブルの詳細パネルには、**列** がその型と説明とともに一覧表示されます。**引き継ぎパックをダウンロード** は、メトリック定義や配賦モデルを含むプロジェクト全体を 1 つのドキュメントとして保存します。[テーブル、ステップ、ワークフローのドキュメント](/ja/guides/ai-assistant/weave-documentation/) を参照してください。
  - **変更の影響範囲。** **保存** の上に、そのステップが書き込む内容を読み取る下流のステップの数が表示されます。たとえば「このステップの変更は、2 つのワークフローの 8 個の下流ステップに影響します」のようになり、**ステップを表示** でそれらが一覧表示されます。[変更の影響範囲](/ja/guides/ai-assistant/impact-preview/) を参照してください。
  - **保存が拒否される内容。** **保存** の上のバーが、編集中にステップのチェックを実行し、問題ごとに **移動** が表示されます。式エディターは入力中に式をチェックします。[保存が拒否される内容](/ja/guides/ai-assistant/check-while-you-edit/) を参照してください。
  - **1 つのワークフローのレビュー。** ワークフローのキャンバスまたは **ステップ** グリッドの **チェック** は、Weave のチェックに加えて、配賦と行レベルセキュリティのチェックも実行します。[1 つのワークフローをレビューする](/ja/guides/ai-assistant/weave-findings/#ひとつのワークフローのレビュー) を参照してください。

- **ワークスペースで Weave の AI 機能をそれぞれオフにできます。** ワークスペース管理者は、ヘッダーの **Weave** ボタンの **AI機能…** ボタンを選んで、Weave チャット、修正アシスタント、インポートとエクスポートのアシスタント、式アシスタント、説明からの SQL 生成、ワークフローレビューの要約、スターターチャートを、それぞれ個別にオンまたはオフにできます。管理者がオフにするまですべてオンです。Weave のチェックと検出事項は常にオンのままで、変更はセキュリティログに記録されます。[AI 機能](/ja/guides/ai-assistant/weave-ai-features/) を参照してください。

- **Allocation Split ステップで、ドライバーのホワットイフを試せます。** ステップを右クリックして **ホワットイフ…** ボタンを選ぶと、ドライバーの値を変えた場合、ドライバーテーブルの別の列を使った場合、または同じキーを持つ別のテーブルの数値列を使った場合に、ステップがコストをどう分け合うかを確認できます。最大 10 個のシナリオを比較でき、各シナリオはステップの前回の実行結果から 1 セント単位まで計算されます。誰が得をして誰が損をするか、どの行には何も配賦されないかも確認できます。**内訳の基準** は、各メンバーの変化がどの勘定科目やその他の値に及ぶかを示し、**後続のステップ** は、配賦の出力から作成されるテーブルにシナリオを引き継ぎます。再実行は行われず、データも変更されません。[ドライバーのホワットイフを試す](/ja/guides/allocations/results/driver-what-if/) を参照してください。

- **プロジェクトの Lakehouse v2 への移行を、準備状況の確認から元に戻すまでガイドします。** **移行準備状況の確認** は、テーブル、ビュー、ステップ、ダッシュボード、データ共有、容量を、問題なし、要確認、ブロックのいずれかで報告し、すべての検出事項に分かりやすい説明を付けます。**v2で試す…** ボタンは、スケジュールをオフにし、ERP 転記をシミュレートモードにした非公開の試用コピーを作成します。移行は今すぐ開始することも、指定した時刻に開始することもできます。実行中はプロジェクトのスケジュールが一時停止され、終了後に復元されます。完了時にはメッセージとメールで通知されます。**変更内容…** ボタンは各テーブルの結果を報告し、**移行を元に戻す…** ボタンは、元に戻せる期間内であればプロジェクトを Lakehouse v1 に戻します。[プロジェクトを Lakehouse v2 に移行する](/ja/guides/data/migrate-project-lakehouse/) を参照してください。

  - **テーブルとフロー。** [Table Extract](/ja/reference/workflow-steps/tables/table-extract/) ステップと結合は、実行時に名前が決まる列を引き継げるため、ピボットの後のステップに列の一覧は不要です。[テーブル: 和集合（すべて）](/ja/reference/workflow-steps/tables/table-union-all/#列の照合) は、位置でソースを積み重ねられます。ステップは、テーブルが存在するかどうかに応じて実行できます（[テーブル存在条件](/ja/guides/workflows/step-conditions/#テーブル存在の条件)）。[Workflow Loop](/ja/reference/workflow-steps/workflow-control/workflow-loop/#反復が失敗した場合) ステップは、失敗した反復を越えて処理を続けられ、[待機](/ja/reference/workflow-steps/general/wait/#時刻またはファイルの待機) ステップは、時刻やファイルの変更を待てます。
  - **通知、AI、リモート SQL。** [Notify Via Email](/ja/reference/workflow-steps/notifications/notify-via-email/) ステップは Cc、Bcc、Reply-To を追加し、ドライバーテーブルの各行にそれぞれのメールを送信できます。[Text: NLP (AI)](/ja/reference/workflow-steps/text-documents/nlp-ai/) ステップは埋め込みを書き込め、失敗した呼び出しをそれぞれ報告します。[リモート実行: SQL](/ja/reference/workflow-steps/agent/agent-remote-execution-of-sql/#行ごとに1回ステートメントを実行する) は、ストアドプロシージャなどのステートメントを行ごとに 1 回実行できます。

- **RESTリクエストのフォームで、リクエストの構築と確認がしやすくなります。** 大規模なエンドポイントカタログを絞り込んだり、Postman コレクション、OpenAPI 仕様、HARファイルを貼り付けたりドロップしたりできます。ヘッダーとパラメーターは、重複、名前の入力ミス、プレーンテキストで入力されたシークレットがチェックされ、テストリクエストでは整形されたレスポンスと推奨される項目パスが表示されます。このステップには、ページ番号、カーソル、Link ヘッダーによるページング、プロキシ、Digest 認証と NTLM 認証、SOAP 呼び出し、小数のリクエストレート、実行中のジョブのポーリング、各エラーを資格情報をマスクした行として残す raw レスポンスモードが追加されました。POST、PUT、PATCH はレート制限の後には再試行されますが、サーバーエラーの後には再試行されません。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/) と [RESTリクエスト](/ja/reference/workflow-steps/general/rest-request/) を参照してください。

- **列、値、またはそのテーブルを使うワークフローから、あらゆるテーブルを見つけられます。** **テーブル** タブには **ワークフロー別** フォルダーがあり、列検索では、一致した列ごとに、そのテーブルを供給するテーブルと供給されるテーブルの **列ツリー** が表示されます。**データ内の値を検索… (低速)** オプションは、入力した値を持つテーブルと列を、すでに開くことができた行の範囲内で一覧表示し、結果はテーブルエクスプローラーで開けます。**テーブルの詳細** にはテーブルの **公開名** がコピーボタン付きで表示され、Snowflake または Databricks のウェアハウスでは、削除ウィンドウに、テーブルが最後に読み取られた日時と読み取った人が表示されます。ドキュメントアカウントでは、**使用箇所** がそのアカウントを使用しているすべてのステップ、ワークフロー、プロジェクトのデフォルトを一覧表示し、**参照先を変更...** ボタンがプレビューの後でそれらを別のアカウントに移します。[テーブルを探す](/ja/guides/projects/managing-tables-and-views/#テーブルの検索)、[値を検索](/ja/guides/projects/managing-tables-and-views/#値の検索)、[最終読み取り](/ja/guides/projects/managing-tables-and-views/#最終読み取り)、[ドキュメントアカウントの使用箇所と参照先の変更](/ja/guides/documents/account-management/document-account-used-by/) を参照してください。

- **CSV を任意のプロジェクトのテーブルにして、すぐに概要を確認できます。** CSV をプロジェクトの **テーブル** 一覧にドロップするか、**新規** > **CSVファイルからテーブルを作成** を選ぶと、PlaidCloud が新しいテーブルとしてインポートします。**新規** > **CSVファイルからプロジェクト** は、CSV からプロジェクトを作成します。その後、**データの概要** に、行数、各列の型、空の値と一意の値の割合、スターターチャートが表示され、ワンクリックでスターターダッシュボードを作成できます。[CSVファイルをインポート](/ja/guides/projects/managing-tables-and-views/#csvファイルのインポート) と [自分の CSV から始める](/ja/get-started/quickstart/#自分の-csv-から始める) を参照してください。

- **高度なワークフローのキャンバスの配置と編集がより直接的になりました。** **Cmd** または **Ctrl** を押したままドラッグすると、ステップをコンテナーの内外に移動でき、実行コンテナーの出力は **出力ポート** から配線できます。**配置** メニューでは、順序を保ったまま、メモをステップと一緒に移動しながら、ステップの整頓、整列、等間隔配置、スナップができ、それぞれ **元に戻す** 1 回で戻せます。空白部分を右クリックすると、クリックした位置にステップをコピーして貼り付けられます。選択したステップの **ステップを作成** は、そのステップが書き込むテーブルから結合や抽出を開始し、未保存の変更があるウィンドウは、破棄する前に確認します。ステップの入力または出力の目のアイコンで、まさにそのテーブルのプレビューが開きます。[コンテナー](/ja/guides/workflows/advanced-workflows/#コンテナー)、[キャンバスの配置](/ja/guides/workflows/advanced-workflows/#キャンバスを配置する)、[高度なキャンバスでのコピーと貼り付け](/ja/guides/workflows/copy-paste-steps/#高度なキャンバスでのコピーと貼り付け)、[ステップを作成する](/ja/guides/workflows/workflow-explorer/#ステップの作成) を参照してください。

- **高度なワークフローを最適化して高速に実行できます。** ワークフローを右クリックして **最適化…** ボタンを選ぶと、変更が行われる前に内容を確認できます。**Rebuild dependencies from data lineage** は、各ステップを、そのテーブルを使用するステップにだけ接続するので、独立したステップは並列に実行されます。**Merge** は、連続する Extract Data ステップを 1 つにまとめます。これは、現在のデータで両方のバージョンが同一の結果になる場合にのみ適用されます。ウィンドウには短縮される時間と、最適化できなかった各ステップがその理由とともに表示され、**最適化を元に戻す…** ボタンでワークフローを復元できます。[ワークフローを最適化する](/ja/guides/workflows/optimize-a-workflow/) を参照してください。

- **実行する前に、結合のキーを正しく設定できます。** **結合マップ** の **自動判定** は、同じ 2 つのテーブルを結合している別のステップのキー、次にメトリック、次にテーブルのキー列、次に一致する名前の順に使用し、どれを使用したかを表示します。**キーを確認** は、結合先のテーブルで繰り返されるキー値を数えます。繰り返しがあると行が増えることがあります。**ソースを検査** がステップの列を取り込むときは、`customer_id` のような識別子の列は **合計** ではなく **グループ化** から始まります。[Inner Join](/ja/reference/workflow-steps/tables/table-inner-join/#キーを確認) を参照してください。

- **AI アシスタントと Microsoft 365 Copilot が、お客様のデータをより深く理解し、より多くのことを実行します。**

  - **分析パスと列ごとのガイダンス。** 各分析パスには、常に適用するフィルター、会計カレンダー、ビジネス用語を記述するための **プロンプトガイダンス**（最大 1,000 文字）があります。列のメモは、テーブルの列とともにアシスタントと LLM ステップに渡されるため、コードやフラグが意図したとおりに読み取られます。[AI アシスタント向けにパスを使いやすくする](/ja/integrations/ai-coding-agents/analysis-paths/#aiアシスタントに役立つパスにする) を参照してください。
  - **Copilot の機能強化。** Microsoft 365 Copilot の PlaidCloud エージェントは、CSV、Excel、PowerPoint、Word のファイルを作成し、ビジネス上の数値をメトリックから回答し、内訳をテーブル全体で集計し、配賦の仕組みを説明します。管理者は更新されたパッケージをダウンロードし、Teams 管理センターで更新します。[Microsoft 365 Copilot](/ja/integrations/microsoft-365-copilot/) を参照してください。
  - **1 回の呼び出しで完了する処理が増加。** アシスタントは、最初に行アクセスを適用した上で、サーバー側でテーブルをグループ化して集計したり、PlaidCloud のドキュメントを検索して読んだり、OneDrive や SharePoint を含む、完全に構成されたドキュメントアカウントを書き込み専用の資格情報で作成したり、ラベルを追加するだけでなく削除したり、PlaidCloud で表示されるビューを扱ったりできます。[分析パス](/ja/integrations/ai-coding-agents/analysis-paths/#mcp経由での使用) と [AI エージェントを使い始める](/ja/integrations/ai-coding-agents/getting-started/) を参照してください。

## 変更

- **1 つの Weave タブに、検出事項と Weave AI チャットがまとまりました。** チャットは **検出事項** の後にある **Weave** タブ内のタブです。各検出事項は、それぞれ **修正**、**移動**、**既読にする** ボタンを持つカードで、破線のカードは Weave がチェックできなかった項目を表し、チップで要対応の内容に絞り込めます。式に関する検出事項は、エラーの場所を示し、式自体は **Weaveが把握する方法** の下に表示されます。Weave は、実行の終了時に各問題を 1 回だけ通知し、1 つのプロジェクトに関するメッセージは積み重ならずに 1 つにまとめられます。Weave は変更があった部分だけを再チェックするため、大規模なプロジェクトでもタブがすばやく開きます。ワークフロー一覧の Weave 列は廃止されました。[Weave タブ](/ja/guides/ai-assistant/weave-tab/) と [実行の終了時の通知](/ja/guides/ai-assistant/weave-findings/#実行終了時の通知) を参照してください。

- **Ctrl/Cmd-K で、どの画面からでもコマンドパレットを開けます。** 入力前は、最後に開いたものと、実行できる操作（ホーム、プロジェクト、ダッシュボード、ドキュメントへの移動、ライトとダークの切り替え、AI の接続、ヘルプの表示）が一覧表示されます。入力すると両方のリストが絞り込まれ、2 文字以上では、プロジェクト、ワークフロー、テーブル、ダッシュボード、Panel アプリも検索されます。[検索とコマンド](/ja/guides/launcher/#検索とコマンド) を参照してください。

- **ステップの問題は、実行時ではなく保存時に検出されます。** 実行が失敗する、または誤った結果になる設定のステップを保存しようとすると、変更すべき内容を示すメッセージとともに拒否されます。各ステップのリファレンスページに、チェックする内容が記載されています。マッピングされたソース列が、ステップまたはそのソーステーブルに存在しなくなった場合は赤で示され、保存すると **すべて削除して保存**、**このまま保存**、**キャンセル** のあるダイアログが開きます。結合、ルックアップ、空間のステップは、そのような行を自動で削除せず、そのまま残します。未定義の変数を使用する式は、その変数名を示し、実行時に拒否されたステップは、その理由を分かりやすい言葉で説明します。[一覧にないソース列](/ja/reference/workflow-steps/tables/table-extract/#一覧になくなったソース列)、[ソーステーブルにない列](/ja/reference/workflow-steps/tables/table-extract/#ソーステーブルに存在しない列)、[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/) を参照してください。

- **ソースが存在しない、または空であってもエラーにはなりません。** ファイルが存在しない、または空のファイルインポートは、パスを示す警告付きで完了し、ターゲットテーブルを宣言された列を持つ空の状態にするため、後続のステップは 0 行を読み取ります。存在しない、または空のフォルダーに対するドキュメントステップは「Nothing to process」と報告し、ワークフローは続行します。リモートファイルステップは、存在しないパスについて警告し、安全でないパスは拒否します。ファイルが存在しないことのチェックは、OneDrive、SharePoint、SFTP で動作します。バッチテーブルが空の **レポート: バッチ生成** は、警告付きで完了し、レポートを生成しません。[インポートステップ](/ja/reference/workflow-steps/import/)、[ドキュメントワークフローステップ](/ja/reference/workflow-steps/document/)、[ドキュメントパス条件](/ja/guides/workflows/step-conditions/#ドキュメントパスの条件) を参照してください。

- **大規模なワークフローが安定して動作し、停止でインポートとエクスポートがキャンセルされます。** PlaidCloud が混み合っている場合、ステップは失敗せずに処理能力が空くまで待機し、ステップが待ち行列に入るにつれて処理能力が追加されます。外部データベーステーブルのインポートは、最大 10 個のテーブルを同時に実行します。ステップを実行しているサーバーが失われた場合、出力を置き換えるステップは自動的に再実行され、安全に繰り返せないステップは *interrupted* というメッセージで 1 回だけ失敗します。**停止** は実行中のインポートとエクスポートのジョブをキャンセルし、停止された実行には「停止」と表示されます。[中断されたステップ](/ja/guides/workflows/run-a-workflow/#中断されたステップ) と [一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開) を参照してください。

- **すべての Lakehouse で保存と計算の方法が同じになりました。** CSVのインポート、XMLのインポート、アーカイブのインポート（テーブル）の空のフィールドは null としてロードされるため、後続のステップで `= ''` や `= 0` を判定している場合は、null を判定するように変更が必要です。`cast(x, Float)` はどこでも 64 ビットなので、大きな金額も桁が保たれ、PlaidCloud が作成する Float 列は倍精度です。JSON 列、**テーブル: 行の削除**、集計する条件は、すべての Lakehouse で動作します。Solver、Forecast、pandas で実行される Pivot と Allocation Split のように独自の結果を作成するステップは、それらを型付きデータとして、はるかに高速にロードします。テーブルエクスプローラーには、数値列の最小値、最大値、平均、合計、標準偏差、分散が表示されます。[Float へのキャスト](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#floatへのキャスト) と [列データと一意の数](/ja/guides/data/table-explorer/#列のデータと一意な値の数) を参照してください。

- **ファイルのエクスポートで型が保持されます。** Parquet ファイルは整数列を整数のまま保持し、タイムスタンプをマイクロ秒で保存し、タイムゾーンを UTC と表示します。Avro ファイルは日付、タイムスタンプ、ブール値の型を保持し、単一テーブルの Avro エクスポートにはエクスポート名が付きます。Parquet のエクスポートで複数ファイルを選択すると、Parquet は単一のファイルに書き込むというメッセージとともに停止します。非常に大きな Parquet、ORC、JSON のエクスポートは、行を読み取りながら書き込まれるため、メモリ不足になることはなくなり、Parquet は選択した圧縮を使用します。バージョン 1.2.33 以降の PlaidLink エージェントは、エクスポートされたテーブルを Parquet ファイルとして受け取ります。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro](/ja/reference/workflow-steps/export/export-to-avro/)、[データがエージェントに届く仕組み](/ja/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#データがエージェントに届く仕組み) を参照してください。

- **ERP 転記は各スケジュールのモードに従い、不確かな応答は確認のために保留されます。** スケジュールされたイベントは、プロジェクトの設定を上限として、**本番**、**シミュレート**、**オフ** のいずれかの独自の転記モードを保持し、**選択したイベントを実行** は各イベントのモードを使用します。タイムアウトやサーバーエラーなど、PlaidCloud が確認できない ERP の応答は、却下として記録されず、不確定として保留され、転記を二重に取り消すことはできません。転記レジスターには **reversal outstanding** の転記が一覧表示され、アーキテクトは、プロジェクトのホームページの **ERP書き込み承認** からプロジェクトに転記を許可します。[ERP 転記モード](/ja/administration/scheduled-events/event-scheduler/#erp転記モード)、[取消](/ja/guides/connections/posting-register/#取消)、[プロジェクトに転記を許可する](/ja/guides/workflows/run-a-workflow/#プロジェクトに転記を承認する) を参照してください。

- **行アクセスはグループの変更に追従し、問題の内容を示します。** サインイン時にシングルサインオンが設定したグループメンバーシップは、約 15 分以内にダッシュボードの行アクセスに反映され、デフォルトグループの新しいメンバーには約 1 分以内に行が付与されます。行アクセスのウィンドウは、制限が何もフィルターしていない場合に警告し、`&`、`/`、`%` を含む列名を処理し、同期が失敗したときは、理由付きの **エラー** または **再試行** ボタン付きの **再試行中** を表示します。[ダッシュボードを同期した状態に保つ](/ja/administration/access/managing-security-groups-and-assignments/#ダッシュボードの同期の維持) を参照してください。

- **ユーザー定義関数は、Python 3.14 と新しいライブラリで実行されます。** ほとんどの関数は変更なしで動作します。numba をインポートする関数や、`cgi` や `telnetlib` など Python から削除された標準ライブラリのモジュールをインポートする関数は、失敗するようになったため、書き直しが必要です。Forecast の AutoTheta の境界値は、以前の実行とわずかに異なる場合があります。[User Defined Transform](/ja/reference/workflow-steps/general/user-defined-transform/) を参照してください。

- **完全なエージェントアクセスは非推奨となり、2027 年 1 月 15 日に削除されます。** **完全** アクセスを使用する LLM ステップは、警告をログに記録します。**読み取りと書き込み** に移行してください。この設定では、エージェントは PlaidCloud の書き込みツールを通じてデータを変更し、LLM ステップは **書き込み** にチェックを入れたバインディングにのみ書き込みます。[エージェントアクセス](/ja/integrations/ai-architecture/llm-providers/#エージェントアクセス) を参照してください。

- **ドキュメントアカウントの設定とブラウズが簡単になりました。** OneDrive または SharePoint アカウントのファイルブラウザーは、開始パス配下のフォルダーを開きます。Google Cloud Storage アカウントには有効なサービスアカウントキーが必要で、キーのない既存のアカウントは、キーを追加するまで動作しなくなります。拒否された設定はその理由を説明し、使われていないバックアップアイコンは **アカウントの管理** から削除されました。[Google Cloud Storage アカウントを追加する](/ja/guides/documents/adding-accounts/add-google-cloud-storage-account/) と [ドキュメントアカウントのバックアップ](/ja/guides/documents/account-management/managing-document-account-backups/) を参照してください。

- **プロジェクトアプリが、請求書、出張、遅れた時間入力により完全に対応します。** 新しい請求書は、顧客と発注書番号を提供するマスタープロジェクトから始まります。下書きの請求書を削除すると、その時間と出張が再び請求可能になり、**売掛金の受信者** で請求書の提出時にメールを送る相手を設定します。出張の引き出しパネルには、各明細のベンダー、カテゴリー、監査ステータスが表示され、**遅延入力の時間を追加** は承認済みの週のシートを開始します。[プロジェクトアプリで時間と経費を記録する](/ja/guides/time-expense/track-time-and-expenses/) を参照してください。

- **どのステップからも参照されていないテーブルをすべて削除していた API 呼び出しは廃止されました。** 代わりに ID を指定してテーブルを削除してください。

- **アプリ全体の細かな変更。** アカウント、ダッシュボード、メンバー、グループ、設定の一覧で行をダブルクリックすると開きます。空の **ディメンション**、**データエディター**、**UDF**、**ステップ** タブには、次にすべきことが表示され、アプリがないメンバーはランチャーに移動します。ステップのテーブルセレクターには、テーブルが最後に更新された日時が表示されます（[ソーステーブルの最終更新を確認する](/ja/guides/workflows/create-workflow/#ソーステーブルの最終変更日時の確認)）。Export External Database Tables は専用のタブで列をマッピングし、**レポート: バッチ生成** には、使われていない **Report Constants** セクションが表示されなくなりました。Convert Encoding は、中央ヨーロッパ、トルコ、アラビアのエンコーディングを認識します。削除された画面へのリンクは、その旨を表示します。

## 修正

- **AI アシスタントは、承認するまで何も変更せず、名前を書かれたとおりに表示します。** 新しいテーブルにステップを構築するとき、承認前にテーブルが作成されていましたが、今後は承認後にテーブルとステップが一緒に作成されます。プロジェクト、ワークフロー、ディメンションの作成、テーブルのコピー、テーブルのプロパティやラベルの変更も、事前に確認を求めます。承認は、次の返信にのみ有効です。アシスタントが提案するインポートまたはエクスポートは、そのテーブル、ドキュメントアカウント、ワークフローを名前で表示し、存在しないものや開くことができないものと一緒に提示されることはありません。アンダースコアを含む名前は斜体にならず、そのまま表示され、テーブルとコードはダークテーマで読みやすくなり、図はテキストではなく描画され、式エディターの Weave パネルは編集中の式を読み取ります。アシスタントは、名前のないテーブルがあってもプロジェクトのテーブルを一覧表示し、ステップが複数のテーブルを読み書きしている場合でも、エラーで止まらずに、どのステップがテーブルを読み書きするかを答えます。[ワークフローステップを構築する](/ja/guides/ai-assistant/weave-tab/#ワークフローステップの作成) を参照してください。

- **ファイルのインポートは、指定したものを読み取ります。** Excelのインポートは、列全体の範囲と XLSB ブックを読み取り、zip 圧縮されたブック内のシートを見つけ、パディングや改行のあるヘッダーでも失敗しなくなりました。CSVのインポートは **スキップする行** を適用するため、SAP のリストエクスポートのようにヘッダーの上に行があるファイルでも列名でインポートでき、デフォルトの区切り文字、引用符、エスケープ文字で実行されます。1 つのソース列で複数のターゲット列を満たせます。列がすべて固定値のインポートはすべての行をロードし、大文字の圧縮拡張子が付いたファイルは展開され、変更がなければスキップするインポートは、空にされたテーブルを再ロードします。AI アシスタントに **プロジェクトのデフォルト** からファイルをインポートするよう依頼すると、プロジェクトのデフォルトのドキュメントアカウントを読み取り、設定されていない場合はその旨をはっきり伝えます。新しい列型を持つ Parquet ファイルがドキュメントで開きます。[Excelのインポート](/ja/reference/workflow-steps/import/import-excel/#読み取り対象) と [CSVのインポート](/ja/reference/workflow-steps/import/import-csv/#行の選択) を参照してください。

- **ワークフローステップは、設定したとおりに保存され、実行されます。** Table: Upsert ステップが再び保存できるようになり、**更新キー** 列も戻りました。テーブル: プロジェクト間コピーは、ターゲットプロジェクトを名前で指定し、データ共有を介して読み取ります。ドキュメント: ダッシュボードをPDFとして保存は列の型を保持し、Table: Union Distinct とテーブル: 和集合（すべて）は列を名前で照合します。複数テーブル結合は複数の入力で保存でき、スペースを含む列名を受け付けます。Table Lookup はルックアップ列の集計設定を無視し、SCD-2時点指定結合は日付として変数を受け取ります。LLM ステップは 4.6 より前の Claude モデルで実行され、AI アシスタントが編集してもモデルが保持されます。RESTリクエストは行の値を 1 回だけエンコードして送信し、リモートデータベースへのエクスポートは行をコミットします。[更新キー](/ja/reference/workflow-steps/tables/table-upsert/#更新キー)、[データ共有の管理](/ja/reference/workflow-steps/tables/frame-project-copy/#データ共有の管理)、[複数テーブル結合](/ja/reference/workflow-steps/tables/table-multi-table-join/) を参照してください。Workflow Delete、Copy、Rename、Stop など、ワークフローを選ぶステップは、存在しなくなったワークフローを *id (missing)* として保持し、一覧の先頭のワークフローに切り替わることはありません。

- **ワークフローの実行は期待どおりに完了します。** Workflow Loop は、反復のたびにループ対象のワークフローを実行します。反復するコンテナーや、1 回の実行内で複数回実行されるワークフローも同様です。ステップの途中や並列グループの内部から開始した実行は、正しいステップを実行して完了します。長時間のインポートまたはエクスポートが二重に開始されたり、PlaidCloud の更新中に停止したりすることはなく、サーバーエラーで終わったアクションが再送されることもありません。データベースドライバーのクラッシュは、そのステップだけを、データベースが示す理由とともに失敗させます。実行履歴はすべてのステップの行数を集計し、作業の開始前に失敗したステップは、その理由をワークフローログに書き込みます。[Workflow Loop](/ja/reference/workflow-steps/workflow-control/workflow-loop/) と [実行履歴](/ja/guides/workflows/advanced-workflows/#実行履歴) を参照してください。

- **プロジェクトのコピー、インポート、オープンが想定どおりに動作します。** プロジェクトのインポートは、復元できたものをすべて保持し、除外したものを **インポート結果** ウィンドウに一覧表示し、進捗を表示し、失敗した理由を示し、再試行もできます。選択したオブジェクトのコピーは、プロジェクトに変数があっても動作します。プロジェクトを開いても設定が変更されなくなり、**独自のデータを取り込む** は CSV をインポートし、PostgreSQL ウェアハウスでのテーブル作成も動作します。App Runner アプリは PlaidCloud の更新時に自動的に更新され、行を制限するプロジェクトの閲覧者に対しても動作します。[アーカイブの一部がインポートされない場合](/ja/guides/projects/archive-a-project/#アーカイブの一部がインポートされない場合) と [アプリを最新に保つ](/ja/guides/workflows/use-converted-alteryx-apps/#アプリを最新の状態に保つ) を参照してください。

- **ディメンションと配賦が正しくロードされ、読み取られます。** 親子のロードは、親が空の行を最上位のメンバーとして保持し、あらゆる種類のロードで、メイン階層の外にあるメンバーは 2 つ目の代替階層には拒否されます。メンバーを、その階層に含まれない親の下に移動することは拒否され、ディメンションのステップは見つからなかったディメンションの名前を示し、空白を含む列を貼り付けても各値は元の行に残ります。大きなディメンションの読み取りが、ワークスペース内の他のユーザーを妨げることはなくなりました。ディメンションプロパティの **階層** が **未指定** のままの配賦ルールも実行されます。[代替階層へのロード](/ja/reference/workflow-steps/dimensions/dimension-load/#代替階層へのロード) と [ディメンション型のプロパティとメンバーピッカー](/ja/guides/dimensions/dimensions/#ディメンション型のプロパティとメンバーピッカー) を参照してください。

- **ワークフローのキャンバスと画面が正しく動作します。** **ワークフローにドリルダウン** は、高度なワークフローをそのキャンバスで開き、キャンバスはすべてのワークフローを開き、レイアウトの一部を読み取れなかった場合はその旨を表示します。収まらないツールバーボタンは **その他** メニューに移動し、一覧は保存するとすぐに更新されます。通知はメッセージ全体を表示し、警告は **ログ** タブで警告アイコンを表示し、テーブルエクスプローラーは列のプロファイルが失敗したことを表示し、データエディターは空の日付セルを空のままにします。列フィルターをオンにしてデータエディターを保存しても、フィルターで非表示の行は、行の追加、削除、移動の後も保持されます。ユーザー定義関数のエディターは、変更を許可されているすべてのユーザーに対して編集可能な状態で開きます。[キャンバスがワークフローを開けない場合](/ja/guides/workflows/advanced-workflows/#キャンバスでワークフローを開けない場合) を参照してください。**テーブル** 一覧からテーブルを削除するとき、`/Periods/{period}/Sales` のような変数パス経由でのみそのテーブルを参照しているステップがあれば一覧表示し、強制した場合にのみそのテーブルを削除します。[削除](/ja/guides/projects/managing-tables-and-views/#削除) を参照してください。

- **メンバーと接続が正しく動作します。** **ワークスペースメンバーを追加** は、シングルサインオンで作成されたアカウントを含め、すでにアカウントを持つユーザーに対して動作し、そのユーザーが持つプロジェクトのロールを下げることはありません。ODBC 接続は、PlaidLink エージェントのマシン上の DSN またはドライバーを通じて接続します。OAuth 資格情報を拒否したプロバイダーは、資格情報の再入力または再承認を促し、Databricks のサンプルとエクスポートは期限切れのトークンを更新し、古い種類のデータベースの接続は削除できます。**使用箇所** には通知ステップが含まれ、無料のワークスペースでは、日次、週次、月次のバックアップが保持されます。[メンバー管理](/ja/administration/access/member-management/) と [ODBC](/ja/reference/connectors/databases/odbc/) を参照してください。

- **REST API と AI アシスタントのツールは、指示したとおりに動作します。** メンバー、グループ、スケジュールされたイベントの部分更新では、指定したフィールドだけが変更されるため、一時停止中のイベントは一時停止のままです。指定したステップから実行を開始すると、そのステップから始まり、テーブルのスナップショットを復元すると、安全用のスナップショットと監査記録が保持されます。AI ツールのドライバーのホワットイフは、モデルが実際に行った配賦と一致する場合にのみ回答します。以前はサーバーエラーで失敗していたリクエストは、正常に動作するか、何が問題だったかを説明するようになりました。[配賦の追跡](/ja/integrations/ai-coding-agents/tracing-allocations/) と [スナップショットの復帰または復元](/ja/guides/data/table-snapshots/#スナップショットを巻き戻しまたは復元する) を参照してください。

## セキュリティ

- **AI アシスタントはお客様の権限の範囲内にとどまります。** アシスタントのデータクエリは、実行前に構造がチェックされ、単一の読み取りクエリだけが実行されます。Microsoft 365 Copilot を含む読み取り専用の AI 接続では、ファイルのエクスポート、ダッシュボード PDF の保存、行の別プロジェクトへのコピー、REST 接続経由での変更の送信はできません。AI アシスタント経由のインポートは、指定したプロジェクトでご自身として実行され、会話を続けられるのは開始した本人だけです。アシスタントとテーブル参照では、ロールによって非表示になっているテーブル、ステップ、ワークフロー、ディメンションは除外され、Weave は開くことのできない失敗したステップを、名前を表示せずに数のみで示します。[アクセスレベル](/ja/integrations/microsoft-365-copilot/#アクセスレベル)、[ロールで非表示になるもの](/ja/guides/ai-assistant/weave-tab/#ロールによって非表示になる内容)、[過去の会話を管理する](/ja/guides/ai-assistant/weave-tab/#過去の会話を管理する) を参照してください。

- **ERP 転記は、統制を回避できません。** 職務分掌をオンにすると、取消は転記レジスターを経由し、そこで承認が適用されます。コピーまたはインポートされたプロジェクトが転記の権限を引き継ぐことはなくなり、SAP と EBS の転記をエージェントに直接送ることはできず、テストのみモードの SAP Post ステップには、本番の転記と同じ権限が必要です。これらのチェックなしで Sage Intacct に転記していた非公開のエンドポイントは削除されました。ERP 接続と REST 接続のエラーメッセージには、資格情報が含まれなくなりました。[職務分掌](/ja/guides/connections/posting-register/#職務分掌) を参照してください。

- **シークレットは書き込み専用で、接続を使用できるユーザーを決められるのは所有者だけです。** ドキュメントアカウントのキー、パスワード、トークンは、保存後は二度と表示されず、アカウントの接続先を変更するには、再度シークレットが必要です。ステップ内のパスワードとキーは変数にのみ保持され、ステップに入力されていたシークレットは、アーキテクトだけに表示されるプロジェクト変数に移されました。複数行の資格情報は入力中にマスクされます。接続へのアクセス権を変更できるのは、接続の所有者またはワークスペース管理者のみです。[保存されたシークレットは書き込み専用](/ja/guides/documents/adding-accounts/#保存されたシークレットは書き込み専用)、[キーは変数に保持](/ja/reference/workflow-steps/document/encrypt-decrypt-file/#キーは変数に保持する)、[接続を作成して管理する](/ja/guides/connections/create-connection/#セキュリティモデル) を参照してください。

- **使用できないドキュメントアカウントは、引き続きアクセスできません。** ファイルが存在するかのチェック、Parquet、Avro、ORC、Delta ファイルの列の読み取り、**取り込み** によるインポートステップの列の入力、AI アシスタントによるファイルの検査は、ブラウズと同様に、アクセス権のないアカウントを拒否するようになりました。

- **ワークスペース管理者を変更できるのは、ワークスペース管理者だけです。** 管理者の編集、無効化、削除、グループの変更、ユーザーを管理者にすることは、すべてワークスペース管理者の権限が必要です。[ワークスペース管理者を変更する](/ja/administration/access/member-management/#ワークスペース管理者の変更) を参照してください。

- **データ共有は、共有先のプロジェクトのメンバーに対してのみ有効です。** 共有経由の読み取りには、受信側プロジェクトでのロールが必要で、書き込みには **書き込み** 共有と、そのプロジェクトでのマネージャーまたはアーキテクトのロールが必要です。[プロジェクト間でデータを共有する](/ja/guides/projects/managing-projects/#プロジェクト間でのデータ共有) を参照してください。

- **復元は、指定した項目にのみ適用されます。** 以前のバージョンの復元では項目自体が復元され、権限のチェックはその項目に対して行われます。内容が自身のヘッダーにあるディメンションに属さないディメンションのバックアップファイルは、拒否されます。[バージョン履歴](/ja/guides/projects/managing-projects/#バージョン履歴) を参照してください。

- **テンプレート、インポート、アーカイブは、安全でないコンテンツを拒否します。** エクスポートテンプレートとレポートテンプレートは、与えられたデータのみを読み取るサンドボックス内でレンダリングされます。インポートは、ロード用クエリを自身の設定から構築し、PlaidCloud のアーカイブには決して含まれない内容を持つプロジェクトアーカイブは拒否され、別のプロジェクトのレポートスキーマを共有することになるプロジェクトスラッグも拒否されます。[テンプレートで使用できるもの](/ja/reference/workflow-steps/export/export-templated/#テンプレートで使用できるもの) と [アーカイブの復元](/ja/guides/projects/archive-a-project/#アーカイブの復元) を参照してください。

- **ダッシュボードは、PlaidCloud のサインインとお客様の行アクセスに従います。** ダッシュボードのサムネイルはお客様として描画され、アカウントは PlaidCloud のサインインからのみ作成され、ダッシュボードのインポートは、エクスポートが生成する ZIP ファイルからのみ可能です。[既存のダッシュボードをインポートする](/ja/guides/dashboards/learning-dashboard/#既存のダッシュボードのインポート) を参照してください。

- **ワークフローの実行を開始しても、その実行の資格情報は返されなくなりました。**

- **ユーザー定義関数を実行する環境には、既知の脆弱性があった PySpark の Java ライブラリが含まれなくなりました。** PySpark の DataFrame と SQL API は引き続きお使いの Spark Compute Cluster に接続できますが、`SparkContext` や `RDD` をインポートする関数は失敗するようになりました。[PySpark を使い始める](/ja/integrations/pyspark/getting-started/) を参照してください。

- **添付ファイル、復元、変換は、使用できるアカウントのみを読み取ります。** ファイルのメール送信、ファイルからのディメンションまたはテーブルアーカイブの復元、テーブルバンドルの検査またはインポート、テンプレートからの Excel エクスポートの入力、Alteryx ワークフローの変換は、アクセス権のないドキュメントアカウントを拒否するようになりました。ディメンションをドキュメントアカウントにバックアップするには、そのアカウントへの書き込みアクセスが必要です。ワークフローステップは影響を受けませんが、ファイルをメール送信するステップ、テーブルを復元するステップ、Excel テンプレートを入力するステップは、Personal Temp Drive から読み取れなくなります。
