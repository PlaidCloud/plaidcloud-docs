## 追加

- **Data Foundation が ERP データを 1 つの Common Finance Model に統合します**。Common Finance Model は、複数の ERP システムとインスタンスの ERP データを、1 つの勘定科目表、1 つのエンティティセット、1 つの報告通貨からなる単一のモデルに統合します。このモデルに基づくレポート、メトリック、AI アシスタントはすべて、どの ERP 由来であっても同じ数値を参照します。

  - **ERP から直接取得します。** 総勘定元帳、試算表、マスターデータ、予算は、PlaidCloud の ERP 直接接続を通じて取り込まれます。**エンティティ対応表**が各ソースの会社コードを共通のエンティティに対応付け、為替レートや配賦ドライバーなど、システムが保持していないものはファイルで補います。
  - **1 つのモデル、1 つの通貨にします。** **ロード**がすべてのソースを Common Finance Model に適合させ、報告通貨に換算します。損益計算書は期間の平均レート、貸借対照表は期末レート、資本は取得時レートで換算されます。階層はマスターデータから構築されます。
  - **準備状況を確認します。** エンティティと期間ごとにチェックが実行されます。試算表と売上が総勘定元帳と一致していること、すべての製品、顧客、勘定科目が既知であること、通貨が換算できること、すべてのエンティティがマッピングされていることを確認します。
  - **複数のソースを1つのモデルに。** ERPシステム、ERPインスタンス、ファイルのいずれかであるソースを、追加、並べ替え、編集、削除できます。**ロード**はすべてのソースを統合し、重複する部分は1件に絞り、除外した行はその理由とともに記録します。**Apply changes**は、ERPから再取得せずに統合だけをやり直します。
  - **ソース間のコードのマッピング。** 複数のソースで同じコードが使われている場合、名前の一致に基づく候補が提示され、同じ意味かどうかを尋ねられます。コード1件ごとに回答することも、**Accept all**、**All the same**、**All different**でグループ全体に回答することもできます。マッピングはソースとディメンションごとに保持されます。最大10個の追加カテゴリには、指定した名前が付きます。カバレッジビューでは、どのソースをどの月から採用するかを選択できます。
  - **ファイルのオプション。** ファイルは、1つのソースにのみ適用したり、必要な質問に答えさせたり、1つの列を複数のフィールドに分割したり、報告通貨を設定したり、削除したりできます。
  - **管理連結。** ロードのたびに、年初来を含むグループの損益計算書が作成されます。会社間取引は**Eliminations**エンティティで消去され、**Unmapped**バケットと、連結システムの結果との照合が含まれます。これは管理上のビューであり、プロジェクトの行アクセスに従います。法定連結ではありません。
  - **最新の状態に保ちます。** **夜間に更新**は毎晩モデルを再ロードします。ファイルが存在しない、または空の場合は、エラーではなく警告付きで完了します。

  **Enterprise Profitability** などのテンプレートからプロジェクトを開始すると、プロジェクトの **Foundation** タブで、ERP の接続からロードおよびチェック済みのモデルまでを順に進められます。[Data Foundation: Common Finance Model](/ja/guides/projects/data-foundation/)を参照してください。

- **PlaidCloud を独自の Snowflake または Databricks ウェアハウスで実行できます**。ワークスペース管理者がユーザーメニューの**自分のウェアハウスを使用する**を開き、生成されたセットアップスクリプトを自分のアカウントで実行します。このスクリプトは、上限付きのウェアハウスと PlaidCloud 用のサービス ID を作成し、既存のウェアハウスには一切触れません。**接続を確認**は、問題とその対処方法を平易な言葉で説明します。その後、新しいプロジェクトはテーブルを保存しワークフローを実行する場所としてお客様のウェアハウスを使用し、ウェアハウスを削除すると PlaidCloud のアクセス権も取り消されます。[独自のウェアハウスを使用する](/ja/guides/connections/external-lakehouse/)を参照してください。

  - **Snowflake または Databricks でサインインします。** 認証情報を貼り付ける代わりに、管理者はサインインしてウェアハウスを接続できます。その場合、ダッシュボードは各ユーザー自身のウェアハウス権限で実行され、ワークフローは指定したデータロールだけを持つサービス ID として実行されます。[Snowflake または Databricks でサインインする](/ja/guides/connections/external-lakehouse/#snowflake-または-databricks-でサインインする)を参照してください。
  - **複数を接続できます。** **ウェアハウスの管理**で**デフォルトに設定**を選択すると、新しいプロジェクトが別のウェアハウスに割り当てられます。既存のプロジェクトはそのまま残ります。[ウェアハウスを管理する](/ja/guides/connections/external-lakehouse/#ウェアハウスを管理する)を参照してください。
  - **実行のコストを確認できます。** 実行履歴には、実行ごとのクレジットまたは DBU を示す**ウェアハウスコスト**列が表示されます。[実行ごとのウェアハウスコスト](/ja/guides/connections/external-lakehouse/#実行ごとのウェアハウスコスト)を参照してください。
  - **ガバナンスはそのまま維持されます。** 説明はウェアハウス自身のカタログに書き込まれ、PlaidCloud がテーブルを置換、再作成、またはクローンしても、Snowflake の行アクセスポリシーとマスキングポリシー、Databricks の行フィルターと列マスクは付与されたままです。[ポリシーと説明の引き継ぎ](/ja/guides/connections/external-lakehouse/#ポリシーと説明が引き継がれる)を参照してください。

- **PlaidCloud 内で Panelアプリを作成、公開、ブランド設定できます**。

  - **Panel Studio。** **マイPanelアプリ**の最初のボタンである**新しい Studio アプリ**では、空のアプリ、テーブル、ビュー、別の Studio アプリ、またはアプリギャラリーから開始できます。**テーブル**タブの **Panel アプリを作成**では、選択したテーブルから開始できます。**Studio で開く**を選択すると、アプリのファイルがエディターで開きます。下書きを保存し、非公開のビルドを**プレビュー**し、稼働中のアプリを**公開**します。ビルドエラーは該当のファイルと行を示し、**履歴**では公開済みのどのバージョンにも復元でき、**インサイト**ではビュー数、読み込み時間、エラーを確認できます。**Weave に質問**はアプリのファイルとビルドの状態を把握しており、コードを保存する前に、承認用に変更差分のすべてを表示します。[Panel Studio](/ja/guides/panel-apps/studio/)と[Weave で Panelアプリを作成する](/ja/guides/panel-apps/build-with-weave/)を参照してください。
  - **PlaidCloud らしい外観のアプリキット。** キットで作成したアプリは、ライトとダークの両方で PlaidCloud の配色、書体、余白を使用します。キットには、ナビゲーション、フィルター、主要な数値のカード、グラフ、フォーム、コマンドパレット、ワークフローを実行するボタン、印刷、そしてサーバー側で並べ替えと合計を行い、列ごとに数値を書式設定し、1 画面分の行ずつ読み込むデータグリッドが含まれるため、どのサイズのテーブルでも扱えます。アプリは、ログインしている閲覧者としてテーブルを読み取り、行セキュリティが適用されます。[Panel アプリキット](/ja/guides/panel-apps/app-kit/)、[DataGrid](/ja/guides/panel-apps/app-kit/#datagrid)、[Panelアプリ向けデータ API](/ja/guides/panel-apps/data-api/)を参照してください。
  - **アラートとダイジェスト。** プロジェクトテーブルの数値が上限を超えたときにプッシュ通知、メール、Slack、Microsoft Teams で通知を受け取れます。最大 10 個の数値の日次または週次のダイジェストも受け取れます。いずれも常に自分の行アクセスの範囲で実行されます。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
  - **プロジェクト、ブランディング、共有。** プロジェクトに属していないが開くことができるユーザーの確認を経て、アプリをプロジェクトに割り当てます。プロジェクトの**ホーム**タブの**ブランディングを編集**では、プロジェクト内のすべてのアプリに 8 つのブランドカラーとロゴを設定します。**ギャラリー…** は、プロジェクトに属する Studio アプリを、そのプロジェクトを閲覧できるすべてのユーザー向けのテンプレートとして掲載し、**ギャラリーから外す**で削除します。[プロジェクトのブランディングとアプリのプロジェクト](/ja/guides/panel-apps/branding/)と[アプリギャラリー](/ja/guides/panel-apps/gallery/)を参照してください。

- **ビジネス数値の計算方法を一度合意すれば、すべての AI の回答がその計算を使用します**。プロジェクトのアーキテクトが*純売上*や*従業員数*などの**メトリック**を定義します。ソーステーブル、行の合算方法、常にカウントされる行、結合するルックアップテーブル、内訳に使用できる列を指定します。定義は保存するとすぐに有効になり、存在しないテーブルや列を指定した保存、またはキーごとに複数の行があるルックアップを含む保存は拒否されます。AI アシスタントにメトリックを名前または同義語で尋ねると、数値は AI アシスタント自身が算出するのではなく、定義に従って自分の行アクセスの範囲で計算されます。定義は AI アシスタントまたは REST API から管理します。[メトリック定義](/ja/integrations/ai-coding-agents/metric-definitions/)を参照してください。

  - **派生メトリック。** 2 つのメトリックの比率、合計、差（たとえば FTE あたりの純売上）、またはメトリックに固定係数を掛けたものを定義できます。[他のメトリックからメトリックを派生させる](/ja/integrations/ai-coding-agents/metric-definitions/#他のメトリックから派生させる)を参照してください。
  - **比較、ランキング、構成比。** 予算との差異、同順位を残した上位または下位 N 件、各行の合計に対する構成比を求められます。[比較、ランキング、構成比](/ja/integrations/ai-coding-agents/metric-definitions/#比較ランキング構成比)を参照してください。
  - **自分の言葉で、合意された値を使えます。** 内訳の列をディメンションにバインドすると、*EMEA* などの言葉が、その配下のすべての地域になります。何にも一致しない言葉や複数のメンバーに一致する言葉は、推測されずに候補として返され、確認を求められます。[メトリックについて質問する](/ja/integrations/ai-coding-agents/metric-definitions/#メトリックについて質問する)を参照してください。
  - **会計時間。** メトリックの行が会計カレンダー上のどこにあるかを指定すると、会計期間、年初来、前年比、前期比を求められます。[期間を比較する](/ja/integrations/ai-coding-agents/metric-definitions/#時間の経過に沿って比較する)を参照してください。

  PlaidCloud 独自の AI アシスタントは、ビジネス数値にまずメトリックを使用して回答し、数値を ✓ 付きの専用カードに表示します。この ✓ がアシスタント自身のテキストに付くことはありません。[ビジネス数値](/ja/guides/ai-assistant/weave-tab/#ビジネス数値)と[メトリックからの数値](/ja/guides/ai-assistant/weave-tab/#メトリックからの数値)を参照してください。

- **クローズの準備ができているかを Weave に尋ねたり、2 つのテーブルが一致するかを確認したりできます**。どちらも AI は使用しません。

  - **クローズ準備状況。** クローズ、予測、その他の期限が依存するワークフローを、プロジェクトの **Weave** タブの**準備状況**から**準備状況セット**として指定します。1 つのチェックリストがそのすべてに回答します。「13 件中 11 件が準備完了、1 件が準備未完了、1 件がチェックできませんでした」といった形です。ワークフローが準備完了になるのは、Weave が実行できたすべてのチェックに合格した場合だけです。Weave が判断できなかったものは、準備完了ではなく、理由付きで**チェックできませんでした**と表示されます。新しいワークフローの最後の実行など、比較対象となる以前の履歴が少なすぎる実行は、通常どおりとして扱われます。メールの送信やファイルのエクスポートなど、テーブルに書き込まないステップには、チェックする行や空の値がないため、ワークフローが**チェックできませんでした**のままになることはありません。[クローズ前に準備状況を確認する](/ja/guides/ai-assistant/weave-readiness/)を参照してください。
  - **照合。** 2 つのテーブル、または 1 つのテーブルの 2 つの期間を、対応付けたキー列で行ごとに比較します。Weave は、一致するかどうか、差がどれくらいか、どの行が異なるかを示し、全体を読み取れなかったデータについて「一致」と言うことはありません。各照合は、使用される前に別のアーキテクトが承認します。[2 つのテーブルが一致するか確認する](/ja/guides/ai-assistant/weave-reconciliation/)を参照してください。

- **Weave は問題が起こり得るより多くの箇所を監視し、実行の合間にも通知します**。Weave のチェックに AI は使用されません。すべての検出事項と AI アシスタントのすべての回答に**Weaveが把握する方法**パネルがあります。検出事項ではチェックとその根拠となる値、回答ではアシスタントが実行した各クエリが表示され、すべての文に**一致**、**不一致**、**未確認**のいずれかが付きます。[Weave が現在確認する内容](/ja/guides/ai-assistant/weave-findings/#現在weaveがチェックする内容)、[Weave が把握する方法](/ja/guides/ai-assistant/weave-findings/#weaveが把握する方法)、[AI アシスタントでの Weave が把握する方法](/ja/guides/ai-assistant/weave-tab/#weaveが把握する方法)を参照してください。

  - **テーブルが期限どおりに書き込まれているか。** Weave は、スケジュールの期限を過ぎても書き込まれていないテーブル、またはテーブルの詳細の**鮮度**で設定した 1 時間から 180 日までのしきい値を超えて書き込まれていないテーブルを報告します。
  - **古い、または壊れた入力。** Weave は、別のワークフローがその後に書き込んだテーブルを読み取るワークフロー、および失敗した実行に依存するすべてのワークフローとダッシュボード（SQL データセットに基づくグラフを持つダッシュボードを含む）を報告します。**依存関係の同期**は、ステップと、そのステップが読み取るテーブルとの間に不足しているコネクターを追加します。[依存関係の同期](/ja/guides/workflows/sync-dependencies/)を参照してください。
  - **形が変わったデータ。** Weave は、実行後に値の分布が大きく変わった小数列、行が複数回書き込まれるようになった結合、列の型に変換できなかったため Extract ステップが空にした値、およびファイルが見つからなかったインポートを報告します。また、最新期間が通常から大きく離れたメトリックを、その要因となった項目とともに報告します。Weave は月末や曜日のパターンを考慮するため、月末に常に負荷が高いロードは報告されません。[メトリック合計値の異常](/ja/guides/ai-assistant/weave-metric-insights/)を参照してください。
  - **遅くなった実行。** Weave は、実行を遅くしたステップを特定し、新しい実行が古い実行より少なくとも 4 分の 1 長くかかっているワークフローを、時間が最も増えたステップとともに報告します。
  - **実行の合間の通知。** 1 時間ごとのチェックにより、各問題の所有者にアプリ内メッセージで 1 回だけ通知されます。ヘッダーの **Weave** ボタンには、すべてのプロジェクトで未読の問題の数が表示されます。[実行の合間の通知](/ja/guides/ai-assistant/weave-findings/#実行の合間の通知)と[ヘッダーの Weave ボタン](/ja/guides/ai-assistant/weave-tab/#ヘッダーのweaveボタン)を参照してください。
  - **所有者、コメント、想定内の警告。** 各検出事項には所有者がおり、デフォルトでは、そのワークフローを最後に実行したユーザーです。**割り当て**で引き継ぎ、コメントで進捗を記録し、**チーム**ビューで誰が何を担当しているかを確認できます。アーキテクトは、警告に理由と終了日を付けて**これは想定内**とマークできます。[検出事項に所有者を割り当てる](/ja/guides/ai-assistant/weave-tab/#検出事項に担当者を設定する)と[検出事項を想定内としてマークする](/ja/guides/ai-assistant/weave-tab/#検出事項を想定内としてマークする)を参照してください。

- **修正アシスタントはエラーを説明し、承認する変更をカードで提案し、ステップを再実行し、修正を元に戻すこともできます**。テーブルにない列、空の必須設定、データベースが読み取れない SQL、型が誤った値など、最も一般的な障害については、最初の返信で、よくある原因と修正方法が説明されます。提案された変更は、ステップが失敗した理由を示し、変更された各設定を、現在の値は赤、新しい値は緑で表示するカードとして表示されます。**承認**で適用され、アシスタントがステップの再実行を提案し、新たな失敗があれば診断します。**Weave** タブの検出事項の**修正**を選択すると、その問題についてアシスタントが開きます。**元に戻す**はステップの以前の設定を復元し、**元に戻して実行**は出力を再構築します。[AI によるワークフローエラーの修正](/ja/guides/ai-assistant/fixing-workflow-errors/)、[AI アシスタントで検出事項を修正する](/ja/guides/ai-assistant/weave-tab/#aiアシスタントで検出事項を修正する)、[修正を元に戻す](/ja/guides/ai-assistant/fixing-workflow-errors/#修正を元に戻す)を参照してください。

- **プロジェクトで Weave が行ったすべてを確認し、監査人向けにエクスポートできます**。プロジェクトの **Weave** タブの**アクティビティ**には、Weave が見つけて後に検出されなくなった問題、AI アシスタントが提案したすべての変更、誰が要求し、誰が承認または却下したか、置き換えた内容と書き込んだ内容、どのように終了したかが一覧表示されます。Weave は変更を行う前にあなたの承認を記録し、記録できない変更は行いません。**CSVのエクスポート**または**PDFのエクスポート**で、期間を監査証跡として保存できます。エントリを編集または削除することはできません。**サマリー**には月の概要が表示されます。見つかった問題と解決した問題、承認された変更、そのうち元に戻された数です。ワークスペース管理者は、**ワークスペースサマリー…** から全プロジェクトの同じ情報を確認できます。[Weave のアクティビティ履歴](/ja/guides/ai-assistant/weave-activity/)と[Weave の月次サマリー](/ja/guides/ai-assistant/weave-monthly-summary/)を参照してください。

- **保存する前に、ステップが何をするか、変更が何に影響するかがわかります**。これらはすべてプロジェクトの保存済みの設定から作成され、AI は使用されません。ロールによって非表示になっているものは、名前が表示されず件数のみが数えられます。

  - **すべてのステップとワークフローのドキュメント、およびすべてのテーブルの列。** 詳細パネルの**ドキュメント**セクションには、ステップの処理内容とワークフローのステップの順序が記され、テーブルを読み書きするものは Weave と AI アシスタントが参照できます。テーブルの詳細パネルには、**列**が型と説明とともに一覧表示されます。**引き継ぎパックをダウンロード**は、メトリック定義と配賦モデルを含むプロジェクト全体を 1 つのドキュメントとして保存します。[テーブル、ステップ、ワークフローのドキュメント](/ja/guides/ai-assistant/weave-documentation/)を参照してください。
  - **変更が何に影響するか。** **保存**の上に、ステップが書き込む内容を読み取る下流のステップの数が表示されます。たとえば「このステップの変更は、2 つのワークフローの 8 つの下流ステップに影響します」のように表示され、**ステップを表示**でその一覧を確認できます。[変更が影響する範囲](/ja/guides/ai-assistant/impact-preview/)を参照してください。

- **Allocation Split ステップでドライバーのホワットイフを試せます**。ステップを右クリックして**ホワットイフ…** を選択すると、異なるドライバー値、ドライバーテーブルの別の列、または同じキーを持つ別のテーブルの数値列を使った場合に、コストがどのように配分されるかを確認できます。最大 10 個のシナリオを比較でき、各シナリオはステップの最後の実行から正確に計算されます。誰が得をし、誰が損をし、どの行に何も配分されなくなるかを確認できます。**内訳の基準:** では、各メンバーの変化がどの勘定科目やその他の値に及ぶかがわかり、**後続のステップ**では、配賦の出力から構築されるテーブルにシナリオを引き継ぎます。再実行は行われず、データも変更されません。[ドライバーのホワットイフを試す](/ja/guides/allocations/results/driver-what-if/)を参照してください。

  - **インポート。** [Excelのインポート](/ja/reference/workflow-steps/import/import-excel/#シート対応表)は、ブックごとに異なるワークシートのセットを読み取り、パスワードで保護されたブックを開きます。[固定幅のインポート](/ja/reference/workflow-steps/import/import-fixed-width/#レイアウト)は EBCDIC と Latin-1 のファイルを読み取り、[XMLのインポート](/ja/reference/workflow-steps/import/import-xml/#レコードの読み取り形式)は繰り返し要素を 1 つのテーブルに読み取ります。ファイルの検索では、ワイルドカードと正規表現のパターンを使用できます。
  - **エクスポート。** CSV と Excel のエクスポートは既存のファイルに追加でき、ほとんどのエクスポートは、すでにあるファイルを置き換えずに停止でき、CSV、Excel、JSON、SQL のエクスポートは行を並べ替えられます。[Export to Excel](/ja/reference/workflow-steps/export/export-to-excel/#分割)は、列の値ごとにシートまたはファイルを書き込め、[Export to CSV](/ja/reference/workflow-steps/export/export-to-csv/)は、Spark と同じ方法で引用符をエスケープまたは省略できます。
  - **テーブルとフロー。** [Table Extract](/ja/reference/workflow-steps/tables/table-extract/)と結合は、実行時に名前が決まる列を引き継げるため、ピボットの後のステップには列リストが不要です。[テーブル: 和集合（すべて）](/ja/reference/workflow-steps/tables/table-union-all/#列の照合)は、ソースを位置で積み重ねられます。ステップは、テーブルが存在するかどうかに応じて実行できます（[テーブル存在条件](/ja/guides/workflows/step-conditions/#テーブル存在の条件)）。[Workflow Loop](/ja/reference/workflow-steps/workflow-control/workflow-loop/#反復が失敗した場合)は、失敗した反復の後も続行でき、[待機](/ja/reference/workflow-steps/general/wait/#時刻またはファイルの待機)は、時刻やファイルの変更を待機できます。
  - **通知、AI、リモート SQL。** [Notify Via Email](/ja/reference/workflow-steps/notifications/notify-via-email/)には Cc、Bcc、Reply-To が追加され、ドライバーテーブルの各行に個別のメールを送信できます。[Text: NLP (AI)](/ja/reference/workflow-steps/text-documents/nlp-ai/)は埋め込みを書き込め、失敗した各呼び出しを報告します。[リモート実行: SQL](/ja/reference/workflow-steps/agent/agent-remote-execution-of-sql/#行ごとに1回ステートメントを実行する)は、ストアドプロシージャなどのステートメントを行ごとに 1 回実行できます。

- **REST Request フォームは、リクエストの作成と確認を支援します**。大規模なエンドポイントカタログを絞り込んだり、Postman コレクション、OpenAPI 仕様、HAR ファイルを貼り付けたりドロップしたりできます。ヘッダーとパラメーターは、重複、名前の入力ミス、平文で入力されたシークレットがチェックされ、テストリクエストでは整形されたレスポンスと推奨される項目パスが表示されます。ステップには、ページ番号、カーソル、Link ヘッダーによるページング、プロキシ、Digest と NTLM のサインイン、SOAP 呼び出し、小数のリクエストレート、実行中のジョブのポーリング、各エラーを認証情報をマスクした行として保持する生レスポンスモードが追加されました。POST、PUT、PATCH は、レート制限後には再試行されますが、サーバーエラー後には再試行されません。[REST Request ステップ](/ja/guides/workflows/rest-request-step/)と [RESTリクエスト](/ja/reference/workflow-steps/general/rest-request/)を参照してください。

- **列、値、使用しているワークフローから、あらゆるテーブルを見つけられます**。**テーブル**タブには、**ワークフロー別**フォルダー、一致した各列にデータを供給するテーブルとその供給先のテーブルを示す**列ツリー**付きの列検索、入力した値を保持する各テーブルと列を、すでに開くことができる行の範囲内で一覧表示し、結果をテーブルエクスプローラーで開く**データ内の値を検索… (低速)** があります。**テーブルの詳細**には、テーブルの**公開名**がコピーボタン付きで表示され、Snowflake または Databricks のウェアハウスでは、削除ウィンドウにテーブルが最後に読み取られた時刻と読み取ったユーザーが表示されます。ドキュメントアカウントでは、**使用箇所**にアカウントを使用するすべてのステップ、ワークフロー、プロジェクトのデフォルトが一覧表示され、**参照先を変更...** は、プレビューの後にそれらを別のアカウントに移します。[テーブルを検索する](/ja/guides/projects/managing-tables-and-views/#テーブルを検索する)、[値を検索](/ja/guides/projects/managing-tables-and-views/#値を検索)、[最後の読み取り](/ja/guides/projects/managing-tables-and-views/#最後の読み取り)、[ドキュメントアカウントの使用箇所と参照先の変更](/ja/guides/documents/account-management/document-account-used-by/)を参照してください。

- **CSV を任意のプロジェクトのテーブルに変換し、概要をすぐに確認できます**。CSV をプロジェクトの**テーブル**リストにドロップするか、**新規** > **CSVファイルからテーブルを作成**を選択すると、PlaidCloud が新しいテーブルとしてインポートします。**新規** > **CSVファイルからプロジェクト**は、CSV からプロジェクトを作成します。その後、**データの概要**に、行数、各列の型、空の値と固有の値の割合、スターターグラフが表示され、スターターダッシュボードもワンクリックで作成できます。[CSVファイルをインポート](/ja/guides/projects/managing-tables-and-views/#csvファイルをインポート)と[独自の CSV から始める](/ja/get-started/quickstart/#自分の-csv-から始める)を参照してください。

- **高度なワークフローのキャンバスを、より直接的に整理して編集できます**。**Cmd** または **Ctrl** を押しながらステップをドラッグして、コンテナーの内外に移動でき、実行コンテナーの出力は**出力ポート**から配線できます。**配置**メニューは、順序を維持し、メモをステップとともに移動しながら、ステップの整頓、整列、均等配置、スナップを行い、それぞれ 1 回の**元に戻す**で取り消せます。何もない場所を右クリックすると、クリックした場所にステップをコピーして貼り付けられます。選択したステップの**ステップを作成**は、そのステップが書き込むテーブルから、結合または抽出を開始し、未保存の変更があるウィンドウは、破棄する前に確認します。ステップの入力または出力の目のアイコンは、まさにそのテーブルのプレビューを開きます。[コンテナー](/ja/guides/workflows/advanced-workflows/#コンテナー)、[キャンバスを整理する](/ja/guides/workflows/advanced-workflows/#キャンバスを配置する)、[高度なキャンバスでのコピーと貼り付け](/ja/guides/workflows/copy-paste-steps/#高度なキャンバスでのコピーと貼り付け)、[ステップを作成する](/ja/guides/workflows/workflow-explorer/#ステップの作成)を参照してください。

- **高度なワークフローを最適化して、より速く実行できます**。ワークフローを右クリックして**最適化…** を選択すると、変更が行われる前に内容を確認できます。**Rebuild dependencies from data lineage** は、各ステップを、そのステップが使用するテーブルを持つステップとだけ接続するため、独立したステップは並列に実行されます。**Merge** は、Extract Data ステップのチェーンを 1 つに結合し、両方のバージョンが現在のデータで同一の結果になることを確認した後にのみ適用されます。ウィンドウには短縮された時間が表示され、最適化できなかった各ステップが理由とともに一覧表示されます。**最適化を元に戻す**でワークフローが復元されます。[ワークフローを最適化する](/ja/guides/workflows/optimize-a-workflow/)を参照してください。

- **結合のキーを、実行する前に正しく設定できます**。**Join Map** の**自動判定**は、同じ 2 つのテーブルを結合する別のステップのキー、次にメトリック、次にテーブルのキー列、次に一致する名前の順に使用し、どれを使用したかを示します。**キーを確認**は、結合先のテーブルで繰り返されるキー値を数えます。繰り返されると行が増える可能性があります。**ソースを検査**でステップの列を入力するときに、`customer_id` などの識別子列は、**合計**ではなく**グループ化**から始まります。[Inner Join](/ja/reference/workflow-steps/tables/table-inner-join/#キーを確認)を参照してください。

- **AI アシスタントと Microsoft 365 Copilot は、データについてより多くを把握し、より多くのことができます**。

  - **分析パスと列ごとのガイダンス。** 各分析パスには、常に適用されるフィルター、会計カレンダー、ビジネス用語を記述する、最大 1,000 文字の**プロンプトガイダンス**があります。列のメモは、テーブルの列とともにアシスタントと LLM ステップに渡されるため、コードやフラグは意図したとおりに解釈されます。[AI アシスタント向けにパスを活用する](/ja/integrations/ai-coding-agents/analysis-paths/#aiアシスタントに役立つパスにする)を参照してください。
  - **Copilot でできることが増えました。** Microsoft 365 Copilot の PlaidCloud エージェントは、CSV、Excel、PowerPoint、Word のファイルを作成し、ビジネスの数値にメトリックから回答し、内訳をテーブル全体で合計し、配賦の仕組みを説明します。管理者は更新されたパッケージをダウンロードし、Teams 管理センターで更新します。[Microsoft 365 Copilot](/ja/integrations/microsoft-365-copilot/)を参照してください。
  - **1 回の呼び出しでできることが増えました。** アシスタントは、行アクセスを先に適用した上で、サーバー上でテーブルのグループ化と合計を行い、PlaidCloud のドキュメントを検索して読み取り、OneDrive と SharePoint を含む完全に設定されたドキュメントアカウントを書き込み専用の認証情報で作成し、ラベルの追加だけでなく削除も行い、PlaidCloud で表示されるビューを扱えます。[分析パス](/ja/integrations/ai-coding-agents/analysis-paths/#mcp経由での使用)と [AI エージェントを使い始める](/ja/integrations/ai-coding-agents/getting-started/)を参照してください。

## 変更

- **1 つの Weave タブに、検出事項と Weave AI チャットがまとまりました**。チャットは **Weave** タブ内のタブとして**検出事項**の後に配置されます。各検出事項は、独自の**修正**、**移動**、**既読にする**ボタンを持つカードで、Weave がチェックできなかったものは破線のカードで示され、対応が必要なものでリストを絞り込むチップがあります。式に関する検出事項は、エラーの場所を示し、式自体は**Weaveが把握する方法**の下に表示されます。Weave は、実行が終了したときに各問題を 1 回だけ通知し、1 つのプロジェクトに関するメッセージは、積み重ならずに 1 つにまとめられます。Weave は変更されたものだけを再チェックするため、大規模なプロジェクトでもタブがすばやく開きます。ワークフローリストから Weave 列はなくなりました。[Weave タブ](/ja/guides/ai-assistant/weave-tab/)と[実行終了時の通知](/ja/guides/ai-assistant/weave-findings/#実行終了時の通知)を参照してください。

- **Ctrl/Cmd-K で、どの画面からでもコマンドパレットが開きます**。入力する前に、最後に開いたものと実行できるアクションが一覧表示されます。ホーム、プロジェクト、ダッシュボード、ドキュメントへの移動、ライトとダークの切り替え、AI の接続、ヘルプの表示などです。入力すると両方のリストが絞り込まれ、2 文字以上では、プロジェクト、ワークフロー、テーブル、ダッシュボード、Panelアプリも検索されます。[検索とコマンド](/ja/guides/launcher/#検索とコマンド)を参照してください。

- **ステップの問題は、実行時ではなく保存時に検出されます**。実行が失敗する、または誤った結果になる設定のステップを保存しようとすると、変更すべき内容を示すメッセージとともに拒否されます。各ステップのリファレンスページには、チェックされる内容が一覧表示されています。マッピングされたソース列がステップまたはそのソーステーブルに存在しなくなっている場合は赤で示され、保存すると**すべて削除して保存**、**このまま保存**、**キャンセル**のダイアログが開きます。結合、ルックアップ、空間のステップは、そのような行を自動的に削除せず、そのまま保持します。未定義の変数を使用する式は、その変数の名前を示し、実行時に拒否されたステップは、その理由を平易な言葉で説明します。[一覧にない状態になったソース列](/ja/reference/workflow-steps/tables/table-extract/#一覧になくなったソース列)、[ソーステーブルにない列](/ja/reference/workflow-steps/tables/table-extract/#ソーステーブルに存在しない列)、[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。

- **ソースが存在しない、または空であってもエラーにはなりません**。ファイルが存在しない、または空のファイルインポートは、パスを示す警告付きで完了し、ターゲットテーブルは宣言された列を持つ空の状態になるため、後続のステップは 0 行を読み取ります。存在しない、または空のフォルダーに対するドキュメントステップは「処理対象なし」と報告され、ワークフローは続行されます。リモートファイルのステップは、存在しないパスでは警告し、安全でないパスは拒否します。存在しないファイルのチェックは、OneDrive、SharePoint、SFTP で動作します。空のバッチテーブルでの**レポート: バッチ生成**は、警告付きで完了し、レポートを生成しません。[インポートステップ](/ja/reference/workflow-steps/import/)、[ドキュメントワークフローステップ](/ja/reference/workflow-steps/document/)、[ドキュメントパス条件](/ja/guides/workflows/step-conditions/#ドキュメントパスの条件)を参照してください。

- **大規模なワークフローが確実に実行され、「停止」はインポートとエクスポートもキャンセルします**。PlaidCloud が混み合っているとき、ステップは失敗せずに容量を待機し、ステップがキューに溜まるにつれて容量が追加されます。外部データベーステーブルのインポートは、最大 10 個のテーブルを同時に実行します。ステップを実行しているサーバーが失われた場合、出力を置き換えるステップは自動的に再実行され、安全に繰り返せないステップは *interrupted* メッセージとともに 1 回だけ失敗します。**停止**は実行中のインポートとエクスポートのジョブをキャンセルし、停止した実行は「停止」と報告されます。[中断されたステップ](/ja/guides/workflows/run-a-workflow/#中断されたステップ)と[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)を参照してください。

- **すべての Lakehouse が同じ方法で保存と計算を行います**。CSVのインポート、XMLのインポート、またはテーブルアーカイブのインポートの空のフィールドは null としてロードされるため、後続のステップで `= ''` や `= 0` をテストしている場合は、代わりに null をテストする必要があります。`cast(x, Float)` はどこでも 64 ビットになり、大きな金額も桁数が維持され、PlaidCloud が作成する Float 列は倍精度になります。JSON 列、**テーブル: 行の削除**、集計を行う条件は、すべての Lakehouse で動作します。Solver、Forecast、および pandas で実行される Pivot と Allocation Split など、独自の結果を構築するステップは、それらを型付きデータとして、はるかに高速にロードします。テーブルエクスプローラーには、数値列の最小値、最大値、平均、合計、標準偏差、分散が表示されます。[Float へのキャスト](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#floatへのキャスト)と[列データと一意の数](/ja/guides/data/table-explorer/#列のデータと一意な値の数)を参照してください。

- **ファイルのエクスポートで型が維持されます**。Parquet ファイルは整数列を整数として保持し、タイムスタンプをマイクロ秒で保存し、タイムゾーンを UTC として示します。Avro ファイルは日付、タイムスタンプ、ブール値を型付きで保持し、単一テーブルの Avro エクスポートにはエクスポート名が付きます。Parquet エクスポートで複数のファイルを選択すると、Parquet は単一のファイルを書き込むというメッセージとともに停止します。非常に大きな Parquet、ORC、JSON のエクスポートは、行を読み取りながら書き込まれるため、メモリ不足になることがなくなり、Parquet では選択した圧縮が使用されます。バージョン 1.2.33 以降の PlaidLink エージェントは、エクスポートされたテーブルを Parquet ファイルとして受信します。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro](/ja/reference/workflow-steps/export/export-to-avro/)、[データがエージェントに届く方法](/ja/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#データがエージェントに届く仕組み)を参照してください。

- **ERP 転記は各スケジュールのモードに従い、不確かな応答は確認のために保留されます**。スケジュールされたイベントは、プロジェクトの設定を上限として、独自の転記モード（**本番**、**シミュレート**、**オフ**）を保持し、**選択したイベントを実行**は各イベントのモードを使用します。タイムアウトやサーバーエラーなど、PlaidCloud が確認できない ERP の応答は、却下として記録されず、不明として保留されます。転記が二重に取り消されることはありません。**転記レジスター**には **reversal outstanding** の転記が一覧表示され、アーキテクトは、プロジェクトのホームページの **ERP書き込み承認**で、プロジェクトに転記を許可します。[ERP 転記モード](/ja/administration/scheduled-events/event-scheduler/#erp転記モード)、[取消](/ja/guides/connections/posting-register/#取消)、[プロジェクトに転記を許可する](/ja/guides/workflows/run-a-workflow/#プロジェクトに転記を承認する)を参照してください。

- **行アクセスはグループの変更に追従し、問題の内容を示します**。シングルサインオンがサインイン時に設定するグループメンバーシップは、約 15 分以内にダッシュボードの行アクセスに反映され、デフォルトグループの新しいメンバーは、約 1 分以内に自分の行を取得します。**行アクセス**ウィンドウは、何もフィルターしない制限について警告し、`&`、`/`、`%` を含む列名を処理し、同期が失敗した場合は、理由付きの**エラー**、または**再試行**ボタン付きの**再試行中**を表示します。[ダッシュボードを同期した状態に保つ](/ja/administration/access/managing-security-groups-and-assignments/#ダッシュボードの同期の維持)を参照してください。

- **ユーザー定義関数は、より新しいライブラリを備えた Python 3.14 で実行されます**。ほとんどの関数は変更なしで実行されます。numba をインポートする関数や、`cgi` や `telnetlib` など Python から削除された標準ライブラリのモジュールをインポートする関数は、失敗するようになり、書き直しが必要です。Forecast の AutoTheta の境界は、以前の実行とわずかに異なる場合があります。[User Defined Transform](/ja/reference/workflow-steps/general/user-defined-transform/)を参照してください。

- **フルエージェントアクセスは非推奨となり、2027年1月15日に削除されます**。**完全**アクセスを使用する LLM ステップは、警告をログに記録します。エージェントが PlaidCloud の書き込みツールを通じてデータを変更し、LLM ステップが**書き込み**にチェックを入れたバインディングにのみ書き込む**読み取りと書き込み**に移行してください。[エージェントアクセス](/ja/integrations/ai-architecture/llm-providers/#エージェントアクセス)を参照してください。

- **ドキュメントアカウントの設定と閲覧が簡単になりました**。OneDrive または SharePoint アカウントのファイルブラウザーは、開始パスの下のフォルダーを開きます。Google Cloud Storage アカウントには有効なサービスアカウントキーが必要で、キーがない既存のアカウントは、キーを追加するまで動作しなくなります。拒否された設定はその理由を説明し、未使用のバックアップアイコンは**アカウントの管理**から削除されました。[Google Cloud Storage アカウントを追加する](/ja/guides/documents/adding-accounts/add-google-cloud-storage-account/)と[ドキュメントアカウントのバックアップ](/ja/guides/documents/account-management/managing-document-account-backups/)を参照してください。

- **Project アプリが、請求書、出張、遅延入力をより完全に扱えるようになりました**。新しい請求書は、顧客と発注書番号を提供するマスタープロジェクトから開始します。下書きの請求書を削除すると、その時間と出張が再び請求可能になり、**売掛金の受信者**で、請求書が提出されたときにメールを受け取るユーザーを設定します。出張のドロワーには、各明細のベンダー、カテゴリー、監査状況が表示され、**遅延入力の時間を追加**は、承認済みの週のシートを開始します。[Project アプリで時間と経費を追跡する](/ja/guides/time-expense/track-time-and-expenses/)を参照してください。

- **どのステップからも参照されていないすべてのテーブルを削除していた API 呼び出しは削除されました**。代わりに ID を指定してテーブルを削除してください。

- **アプリ全体の細かな変更**。アカウント、ダッシュボード、メンバー、グループ、セットアップのリストで行をダブルクリックすると、開きます。空の**ディメンション**、**データエディター**、**UDF**、**ステップ**タブには、次に行うことが説明され、アプリがないメンバーはランチャーが表示されます。ステップのテーブルセレクターには、テーブルが最後に更新された時刻が表示されます（[ソーステーブルが最後に変更された時刻を確認する](/ja/guides/workflows/create-workflow/#ソーステーブルの最終変更日時の確認)）。外部データベーステーブルのエクスポートは、専用のタブで列をマッピングし、**レポート: バッチ生成**には、使用されない **Report Constants** セクションが表示されなくなりました。Convert Encoding は、中央ヨーロッパ、トルコ、アラビアのエンコーディングを認識します。削除された画面へのリンクには、その旨が表示されます。

## 修正

- **AI アシスタントは、承認するまで何も変更せず、名前を記述どおりに表示します**。新しいテーブルへのステップの作成では、承認する前にテーブルが作成されていましたが、現在は承認後にテーブルとステップが一緒に作成されます。プロジェクト、ワークフロー、ディメンションの作成、テーブルのコピー、テーブルのプロパティやラベルの変更でも、事前に確認が求められます。承認は、次の返信にのみ有効です。アシスタントが提案するインポートまたはエクスポートは、テーブル、ドキュメントアカウント、ワークフローを名前で表示し、存在しないものや開くことができないものと一緒に提案されることはありません。アンダースコアを含む名前は斜体にならずそのまま表示され、テーブルとコードはダークテーマで読みやすくなり、図はテキストではなく描画され、式エディターの Weave パネルは編集中の式を読み取ります。アシスタントは、名前のないテーブルがあってもプロジェクトのテーブルを一覧表示し、ステップが複数のテーブルを読み書きしていても、どのステップがテーブルを読み書きしているかにエラーで停止せず回答します。[ワークフローステップを作成する](/ja/guides/ai-assistant/weave-tab/#ワークフローステップの作成)を参照してください。

- **ファイルのインポートは、指定したものを読み取ります**。Excelのインポートは、列全体の範囲と XLSB ブックを読み取り、zip 圧縮されたブック内のシートを見つけ、パディングや改行を含むヘッダーでも失敗しなくなりました。CSVのインポートは**スキップする行：** を尊重するため、SAP のリストエクスポートなど、ヘッダーの上に行があるファイルでも列名でインポートでき、デフォルトの区切り文字、引用符、エスケープ文字で実行されます。1 つのソース列が複数のターゲット列に供給でき、すべての列が固定値であるインポートはすべての行をロードし、大文字の圧縮拡張子のファイルは解凍され、変更がない場合にスキップするインポートは、空にされたテーブルを再ロードします。AI アシスタントに**プロジェクトのデフォルト**からファイルをインポートするよう依頼すると、プロジェクトのデフォルトのドキュメントアカウントが読み取られ、設定されていない場合はその旨が明確に示されます。新しい列タイプを持つ Parquet ファイルは、ドキュメントで開きます。[Excelのインポート](/ja/reference/workflow-steps/import/import-excel/#読み取り対象)と[CSVのインポート](/ja/reference/workflow-steps/import/import-csv/#行の選択)を参照してください。

- **ワークフローステップは、設定どおりに保存および実行されます**。テーブル: アップサートのステップが再び保存され、**更新キー**列が戻りました。テーブル: プロジェクト間コピーはターゲットプロジェクトを名前で指定し、データ共有を通じて読み取ります。ドキュメント: ダッシュボードをPDFとして保存は列の型を保持し、テーブル: 和集合（重複なし）とテーブル: 和集合（すべて）は列を名前で照合します。複数テーブル結合は複数の入力で保存でき、スペースを含む列名を受け付けます。Table Lookup はルックアップ列の集計設定を無視し、SCD-2時点指定結合は日付として変数を受け付けます。LLM ステップは 4.6 より古い Claude モデルで実行され、AI アシスタントが編集してもモデルが維持されます。REST Request は行の値を 1 回だけエンコードして送信し、リモートデータベースへのエクスポートは行をコミットします。[更新キー](/ja/reference/workflow-steps/tables/table-upsert/#更新キー)、[データ共有の管理](/ja/reference/workflow-steps/tables/frame-project-copy/#データ共有の管理)、[複数テーブル結合](/ja/reference/workflow-steps/tables/table-multi-table-join/)を参照してください。Workflow Delete、Copy、Rename、Stop など、ワークフローを選択するステップは、存在しなくなったワークフローを、リストの最初のワークフローに切り替えるのではなく、*id (missing)* として保持します。

- **ワークフローの実行が正しく終了します**。Workflow Loop は、反復のたびにループ対象のワークフローを実行します。反復コンテナーと、1 回の実行内で複数回実行されるワークフローも同様です。ステップから、または並列グループ内から開始した実行は、正しいステップを実行して終了します。長時間実行されるインポートまたはエクスポートが 2 回開始されることはなく、PlaidCloud の更新中に停止することもなく、サーバーエラーで終了したアクションが再送信されることもありません。データベースドライバーのクラッシュは、そのステップだけを、データベースが示す理由とともに失敗させます。実行履歴はすべてのステップの行数をカウントし、作業が始まる前に失敗したステップは、その理由をワークフローログに書き込みます。[Workflow Loop](/ja/reference/workflow-steps/workflow-control/workflow-loop/)と[実行履歴](/ja/guides/workflows/advanced-workflows/#実行履歴)を参照してください。

- **プロジェクトのコピー、インポート、オープンが、予期せぬ動作なく行えます**。プロジェクトのインポートは、復元できたすべてを保持し、除外したものを**インポート結果**ウィンドウに一覧表示し、進捗を表示し、失敗の理由を示し、再試行できます。選択したオブジェクトのコピーは、プロジェクトに変数がある場合でも動作します。プロジェクトを開いても設定が変更されなくなり、**独自のデータを取り込む**で CSV がインポートされ、PostgreSQL ウェアハウスでのテーブルの作成が動作します。App Runner のアプリは PlaidCloud の更新時に自動的に更新され、行を制限するプロジェクトの閲覧者に対しても動作します。[アーカイブの一部がインポートされない場合](/ja/guides/projects/archive-a-project/#アーカイブの一部がインポートされない場合)と[アプリを最新の状態に保つ](/ja/guides/workflows/use-converted-alteryx-apps/#アプリを最新の状態に保つ)を参照してください。

- **ディメンションと配賦が正しくロードされ、読み取られます**。親子ロードでは、親が空の行が最上位のメンバーとして保持され、メインの階層外のメンバーは、あらゆる種類のロードで、2 番目の代替階層に対して拒否されます。メンバーを、その階層に含まれない親の下に移動することは拒否され、ディメンションのステップは、見つからなかったディメンションの名前を示し、空白を含む列を貼り付けても、各値がその行に維持されます。大規模なディメンションを読み取っても、ワークスペース内の他のユーザーが待たされることはなくなりました。ディメンションプロパティの**階層**が**未指定**のままの配賦ルールが実行されます。[代替階層へのロード](/ja/reference/workflow-steps/dimensions/dimension-load/#代替階層へのロード)と[ディメンションタイプのプロパティとメンバーピッカー](/ja/guides/dimensions/dimensions/#ディメンション型のプロパティとメンバーピッカー)を参照してください。

- **ワークフローのキャンバスと画面が正しく動作します**。**ワークフローにドリルダウン**は、高度なワークフローをキャンバスで開き、キャンバスはあらゆるワークフローを開き、レイアウトの一部を読み取れなかった場合はその旨を表示します。収まらないツールバーのボタンは**その他**メニューに移動し、リストは保存するとすぐに更新されます。通知はメッセージ全体を表示し、警告は**ログ**タブに警告アイコンを表示し、テーブルエクスプローラーは列のプロファイルが失敗したときにその旨を表示し、データエディターは空の日付セルを空のまま保持します。列フィルターをオンにしたままデータエディターを保存すると、行を追加、削除、移動した後でも、フィルターで非表示になっている行が保持されます。ユーザー定義関数のエディターは、変更が許可されているすべてのユーザーに対して編集可能な状態で開きます。[キャンバスがワークフローを開けない場合](/ja/guides/workflows/advanced-workflows/#キャンバスでワークフローを開けない場合)を参照してください。**テーブル**リストからテーブルを削除するとき、`/Periods/{period}/Sales` のような変数パスを通じてのみテーブルに到達するステップが一覧表示され、強制した場合にのみそのテーブルが削除されます。[削除](/ja/guides/projects/managing-tables-and-views/#削除)を参照してください。

- **メンバーと接続が正しく動作します**。**ワークスペースメンバーを追加**は、シングルサインオンで作成されたアカウントを含め、すでにアカウントを持つユーザーに対して動作し、そのユーザーが持つプロジェクトロールを下げることはありません。ODBC 接続は、PlaidLink エージェントのマシン上の DSN またはドライバーを通じて接続します。OAuth 認証情報を拒否したプロバイダーは、再入力または再承認を促し、Databricks のサンプルとエクスポートは期限が切れるトークンを更新し、古いデータベースタイプの接続も削除できます。**使用箇所**には通知ステップが含まれ、無料のワークスペースでは日次、週次、月次のバックアップが保持されます。[メンバー管理](/ja/administration/access/member-management/)と [ODBC](/ja/reference/connectors/databases/odbc/)を参照してください。

- **REST API と AI アシスタントのツールは、依頼したとおりに動作します**。メンバー、グループ、スケジュールされたイベントの部分的な更新では、指定したフィールドだけが変更されるため、一時停止中のイベントは一時停止のままです。名前付きのステップで実行を開始すると、そこから開始され、テーブルスナップショットを復元すると、安全のためのスナップショットと監査記録が保持されます。AI ツールからのドライバーのホワットイフは、モデルが実際に行った分割と一致する場合にのみ回答します。以前はサーバーエラーで失敗していたリクエストは、動作するか、何が間違っていたかを説明するようになりました。[配賦をトレースする](/ja/integrations/ai-coding-agents/tracing-allocations/)と[スナップショットの復帰または復元](/ja/guides/data/table-snapshots/#スナップショットを巻き戻しまたは復元する)を参照してください。

## セキュリティ

- **AI アシスタントは、お客様の権限の範囲内で動作します**。アシスタントのデータクエリは、実行前に構造がチェックされ、単一の読み取りクエリだけが実行されます。Microsoft 365 Copilot を含む読み取り専用の AI 接続では、ファイルのエクスポート、ダッシュボードの PDF の保存、別のプロジェクトへの行のコピー、REST 接続を通じた変更の送信はできません。AI アシスタントを通じたインポートは、指定したプロジェクトで、お客様として実行され、会話を続行できるのは開始したユーザーだけです。アシスタントとテーブル参照では、ロールによって非表示になっているテーブル、ステップ、ワークフロー、ディメンションは除外され、Weave は、開くことができない失敗したステップについて、名前を示さず件数のみを数えます。[アクセスレベル](/ja/integrations/microsoft-365-copilot/#アクセスレベル)、[ロールによって非表示になる内容](/ja/guides/ai-assistant/weave-tab/#ロールによって非表示になる内容)、[過去の会話を管理する](/ja/guides/ai-assistant/weave-tab/#過去の会話を管理する)を参照してください。

- **ERP 転記は、統制を迂回できません**。職務分掌がオンの場合、取消は転記レジスターを通じて行われ、承認が適用されます。コピーまたはインポートされたプロジェクトは、転記の権限を継承しなくなり、SAP と EBS の転記はエージェントに直接送信できず、テストのみモードの SAP Post ステップには、本番の転記と同じ権限が必要です。これらのチェックなしに Sage Intacct に転記していた非公開のエンドポイントは削除されました。ERP 接続と REST 接続のエラーメッセージには、認証情報が含まれません。[職務分掌](/ja/guides/connections/posting-register/#職務分掌)を参照してください。

- **シークレットは書き込み専用で、接続を誰が使用できるかを決められるのは所有者だけです**。ドキュメントアカウントのキー、パスワード、トークンは、保存後に再び表示されることはなく、アカウントの接続先を変更するにはシークレットの再入力が必要です。ステップ内のパスワードとキーは変数にのみ保持されます。ステップに入力されていたシークレットは、アーキテクトだけが閲覧できるプロジェクト変数に移動されました。複数行の認証情報は、入力中にマスクされます。接続へのアクセス権を持つユーザーを変更できるのは、接続の所有者またはワークスペース管理者だけです。[保存されたシークレットは書き込み専用です](/ja/guides/documents/adding-accounts/#保存されたシークレットは書き込み専用)、[キーは変数に保持されます](/ja/reference/workflow-steps/document/encrypt-decrypt-file/#キーは変数に保持する)、[接続の作成と管理](/ja/guides/connections/create-connection/#セキュリティモデル)を参照してください。

- **使用できないドキュメントアカウントは、お客様に対して閉じたままです**。ファイルが存在するかどうかのチェック、Parquet、Avro、ORC、Delta ファイルの列の読み取り、**取り込み**によるインポートステップの列の入力、AI アシスタントによるファイルの検査では、アクセス権のないアカウントは拒否されるようになりました。ブラウズでは、以前から拒否されていました。

- **ワークスペース管理者を変更できるのは、ワークスペース管理者だけです**。管理者の編集、無効化、削除、グループの変更、および誰かを管理者にすることには、いずれもワークスペース管理者が必要です。[ワークスペース管理者の変更](/ja/administration/access/member-management/#ワークスペース管理者の変更)を参照してください。

- **データ共有は、共有が許可されたプロジェクトのメンバーに対してのみ有効です**。共有を通じた読み取りには、受信側プロジェクトでのロールが必要で、書き込みには**書き込み**共有と、そのプロジェクトでのマネージャーまたはアーキテクトのロールが必要です。[プロジェクト間でデータを共有する](/ja/guides/projects/managing-projects/#プロジェクト間でのデータ共有)を参照してください。

- **復元は、指定した項目にのみ適用されます**。以前のバージョンを復元すると、その項目自体が復元され、権限のチェックはその項目に対して行われます。ヘッダーに記載されたディメンションに属さない内容を含むディメンションのバックアップファイルは、拒否されます。[バージョン履歴](/ja/guides/projects/managing-projects/#バージョン履歴)を参照してください。

- **テンプレート、インポート、アーカイブは、安全でない内容を拒否します**。エクスポートテンプレートとレポートテンプレートは、渡されたデータだけを読み取るサンドボックスでレンダリングされます。インポートは、独自の設定からロードクエリを構築し、PlaidCloud のアーカイブには含まれない内容を持つプロジェクトアーカイブは拒否され、別のプロジェクトのレポートスキーマを共有することになるプロジェクトのスラッグは拒否されます。[テンプレートで使用できるもの](/ja/reference/workflow-steps/export/export-templated/#テンプレートで使用できるもの)と[アーカイブの復元](/ja/guides/projects/archive-a-project/#アーカイブの復元)を参照してください。

- **ダッシュボードは、PlaidCloud のサインインとお客様の行アクセスに従います**。ダッシュボードのサムネイルはお客様として描画され、アカウントは PlaidCloud のサインインからのみ取得され、ダッシュボードは、エクスポートが生成する ZIP ファイルからのみインポートされます。[既存のダッシュボードをインポートする](/ja/guides/dashboards/learning-dashboard/#既存のダッシュボードのインポート)を参照してください。

- **ワークフローの実行を開始しても、実行の認証情報が返されなくなりました**。

- **ユーザー定義関数を実行する環境には、PySpark の Java ライブラリが含まれなくなりました**。これらには既知の脆弱性がありました。PySpark の DataFrame と SQL API は引き続きお客様の Spark Compute Cluster に接続しますが、`SparkContext` や `RDD` をインポートする関数は失敗するようになります。[PySpark を使い始める](/ja/integrations/pyspark/getting-started/)を参照してください。

- **添付ファイル、復元、変換は、使用できるアカウントのみを読み取ります**。ファイルのメール送信、ファイルからのディメンションまたはテーブルアーカイブの復元、テーブルバンドルの検査またはインポート、テンプレートからの Excel エクスポートへの入力、Alteryx ワークフローの変換では、アクセス権のないドキュメントアカウントは拒否されるようになりました。ディメンションをドキュメントアカウントにバックアップするには、そのアカウントへの書き込みアクセスが必要です。ワークフローステップは影響を受けませんが、ファイルをメール送信するステップ、テーブルを復元するステップ、Excel テンプレートに入力するステップは、個人用の一時ドライブから読み取れなくなります。
