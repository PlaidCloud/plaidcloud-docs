## 追加

- **Data Foundation で ERP データを 1 つの Common Finance Model に集約できます。** Common Finance Model は、複数の ERP システムとインスタンスの ERP データを 1 つのモデルにまとめます。勘定科目表、エンティティ、報告通貨はそれぞれ 1 つです。このモデルをもとに作成したレポート、メトリック、AI アシスタントは、どの ERP 由来のデータであっても同じ数値を参照します。

  - **ERP から直接取り込み。** 総勘定元帳、試算表、マスターデータ、予算は、PlaidCloud の ERP 直接接続で取り込まれます。**エンティティ対応表** は、各ソースの会社コードを共通のエンティティに対応付けます。為替レートや配賦ドライバーなど、システムが保持していない情報はファイルで補います。
  - **1 つのモデル、1 つの通貨。** **ロード** は、すべてのソースを Common Finance Model に整合させ、報告通貨に換算します。損益計算書は期間の平均レート、貸借対照表は期末レート、資本は取得時レートを使います。階層はマスターデータから構築されます。
  - **準備状況のチェック。** エンティティと期間ごとにチェックを実行します。試算表と売上が総勘定元帳と一致しているか、すべての製品、顧客、勘定科目が既知か、通貨が換算できるか、すべてのエンティティが対応付けられているかを確認します。
  - **多数のソースを 1 つのモデルに。** ソースを追加、並べ替え、編集、削除できます。ソースは ERP システム、インスタンス、ファイルのいずれかです。**ロード** はすべてのソースを整合させ、重複する部分は 1 件だけを残し、除外した行は理由とともに記録します。**Apply changes** は、ERP から再度取得せずに整合処理だけを再実行します。
  - **ソース間のコード対応付け。** 複数のソースで同じコードを使っている場合は、名前の一致に基づく提案が同じ意味かどうかを確認します。コード 1 件ずつ、または **Accept all**、**All the same**、**All different** でグループ全体に回答できます。対応付けはソースとディメンションごとに保持されます。追加カテゴリは最大 10 個まで、指定した名前で使えます。カバレッジビューでは、どの月からどのソースを採用するかを選べます。
  - **ファイルのオプション。** ファイルは 1 つのソースにだけ適用したり、必要な質問に回答させたり、1 つの列を複数のフィールドに分割したり、報告通貨を設定したり、削除したりできます。
  - **管理連結。** ロードのたびに、グループの損益計算書（年度累計を含む）を作成します。会社間取引は **Eliminations** エンティティで消去され、**Unmapped** バケットと、連結システムの結果との照合も含まれます。これは管理用のビューであり、プロジェクトの行アクセスに従います。法定連結ではありません。
  - **最新の状態を保つ。** **夜間に更新** は毎晩モデルをリロードします。ファイルが存在しない場合や空の場合は、エラーではなく警告付きで完了します。

  **Enterprise Profitability** などのテンプレートからプロジェクトを開始すると、プロジェクトの **Foundation** タブで、ERP の接続からロード済みでチェック済みのモデルまで進められます。[Data Foundation: Common Finance Model](/ja/guides/projects/data-foundation/) を参照してください。

- **独自の Snowflake または Databricks ウェアハウスで PlaidCloud を実行できます。** ワークスペース管理者は、ユーザーメニューの **自分のウェアハウスを使用する** を開き、生成されたセットアップスクリプトを自分のアカウントで実行します。このスクリプトは、上限付きのウェアハウスと PlaidCloud 用のサービス ID を作成し、既存のウェアハウスには一切触れません。**接続を確認** は、問題とその対処法を分かりやすい言葉で説明します。新しいプロジェクトは、テーブルの保存とワークフローの実行をそのウェアハウスで行い、ウェアハウスを削除すると PlaidCloud のアクセス権が取り消されます。[独自のウェアハウスを使用する](/ja/guides/connections/external-lakehouse/) を参照してください。

  - **Snowflake または Databricks でサインイン。** 管理者は、資格情報を貼り付ける代わりに、サインインしてウェアハウスを接続できます。ダッシュボードは各ユーザー自身のウェアハウス権限で実行され、ワークフローは指定したデータロールだけを持つサービス ID として実行されます。[Snowflake または Databricks でサインインする](/ja/guides/connections/external-lakehouse/#snowflake-または-databricks-でサインインする) を参照してください。
  - **複数のウェアハウスを接続。** **ウェアハウスの管理** の **デフォルトに設定** で、新しいプロジェクトの保存先を別のウェアハウスに切り替えられます。既存のプロジェクトは元の場所に残ります。[ウェアハウスの管理](/ja/guides/connections/external-lakehouse/#ウェアハウスを管理する) を参照してください。
  - **実行コストの確認。** 実行履歴には、実行ごとのクレジットまたは DBU で表した **ウェアハウスコスト** 列が表示されます。[実行ごとのウェアハウスコスト](/ja/guides/connections/external-lakehouse/#実行ごとのウェアハウスコスト) を参照してください。
  - **ガバナンスはそのまま維持。** 説明はウェアハウス自体のカタログに書き込まれ、PlaidCloud がテーブルを置換、再作成、クローンしても、Snowflake の行アクセスポリシーとマスキングポリシー、Databricks の行フィルターと列マスクは付いたままです。[ポリシーと説明の引き継ぎ](/ja/guides/connections/external-lakehouse/#ポリシーと説明が引き継がれる) を参照してください。

- **PlaidCloud 内で Panel アプリを構築、公開、ブランディングできます。**

  - **Panel Studio。** **マイPanelアプリ** の最初のボタンである **新しい Studio アプリ** では、空のアプリ、テーブル、ビュー、別の Studio アプリ、アプリギャラリーのいずれかから開始できます。**テーブル** タブの **Panel アプリを作成** では、選択したテーブルから開始します。**Studio で開く** は、アプリのファイルをエディターで開きます。下書きを保存し、非公開ビルドを **プレビュー** し、本番のアプリを **公開** できます。ビルドエラーはファイルと行を示し、**履歴** では公開済みの任意のバージョンを復元でき、**インサイト** には閲覧数、読み込み時間、エラーが表示されます。**Weave に質問** は、アプリのファイルとビルドの状況を把握しており、コードを保存する前に差分の全体を表示して承認を求めます。[Panel Studio](/ja/guides/panel-apps/studio/) と [Weave で Panel アプリを構築する](/ja/guides/panel-apps/build-with-weave/) を参照してください。
  - **PlaidCloud らしい外観のアプリキット。** キットで構築したアプリは、ライトモードとダークモードの両方で PlaidCloud の配色、書体、余白を使います。キットには、ナビゲーション、フィルター、主要な数値のカード、グラフ、フォーム、コマンドパレット、ワークフローを実行するボタン、印刷、そしてサーバー側で並べ替えと集計を行い、列ごとに数値を書式設定し、一度に 1 画面分の行を読み込むデータグリッドが含まれるため、どんな規模のテーブルでも扱えます。アプリは、ログインしている閲覧者としてテーブルを読み取り、行セキュリティが適用されます。[Panel アプリキット](/ja/guides/panel-apps/app-kit/)、[DataGrid](/ja/guides/panel-apps/app-kit/#datagrid)、[Panel アプリ用のデータ API](/ja/guides/panel-apps/data-api/) を参照してください。
  - **アラートとダイジェスト。** プロジェクトテーブルの数値がしきい値を超えたときに、プッシュ通知、メール、Slack、Microsoft Teams で通知を受け取れます。また、最大 10 個の数値を日次または週次のダイジェストとして受け取れます。いずれも常にご自身の行アクセスに従います。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/) を参照してください。
  - **プロジェクト、ブランディング、共有。** アプリをプロジェクトに割り当てられます。その際は、プロジェクトのメンバーではないが開けるユーザーを確認します。プロジェクトの **ホーム** タブの **ブランディングを編集** では、プロジェクト内のすべてのアプリに適用する 8 色のブランドカラーとロゴを設定します。**ギャラリー…** は、プロジェクトに属する Studio アプリを、そのプロジェクトを閲覧できるすべてのユーザー向けのテンプレートとして掲載し、**ギャラリーから外す** で掲載を取り下げます。[プロジェクトのブランディングとアプリのプロジェクト](/ja/guides/panel-apps/branding/) と [アプリギャラリー](/ja/guides/panel-apps/gallery/) を参照してください。

- **ビジネス上の数値の計算方法を一度決めれば、AI のすべての回答がその計算を使います。** プロジェクトのアーキテクトが **メトリック** を定義します。たとえば *Net Revenue* や *Headcount* です。定義には、ソーステーブル、行の合計方法、常に集計対象とする行、結合するルックアップテーブル、内訳の基準にできる列を含めます。定義は保存した時点で有効になります。存在しないテーブルや列を指定した場合や、キーごとに複数の行を持つルックアップがある場合、保存は拒否されます。AI アシスタントにメトリックを名前または同義語で尋ねると、数値はアシスタントが算出するのではなく、定義に従って、ご自身の行アクセスのもとで計算されます。定義は AI アシスタントまたは REST API で管理します。[メトリック定義](/ja/integrations/ai-coding-agents/metric-definitions/) を参照してください。

  - **派生メトリック。** 2 つのメトリックの比率、合計、差（1 人あたりの純収益など）や、メトリックに固定の係数を掛けたものを定義できます。[他のメトリックから派生させる](/ja/integrations/ai-coding-agents/metric-definitions/#他のメトリックから派生させる) を参照してください。
  - **比較、ランキング、構成比。** 予算との差異、同順位を残した上位または下位 N 件、各行の合計に対する構成比を尋ねられます。[比較、ランキング、構成比](/ja/integrations/ai-coding-agents/metric-definitions/#比較ランキング構成比) を参照してください。
  - **ご自身の言葉で、合意した値を。** 内訳の列をディメンションに紐付けると、*EMEA* のような言葉がその配下のすべてのリージョンになります。何にも一致しない言葉や、複数のメンバーに一致する言葉は、推測ではなく候補として返され、確認を求められます。[メトリックについて尋ねる](/ja/integrations/ai-coding-agents/metric-definitions/#メトリックについて質問する) を参照してください。
  - **会計時間。** メトリックの行が会計カレンダーのどこにあたるかを指定すると、会計期間、年度累計、前年比、前期比を尋ねられます。[期間を超えた比較](/ja/integrations/ai-coding-agents/metric-definitions/#時間の経過に沿って比較する) を参照してください。

  PlaidCloud 独自の AI アシスタントは、ビジネス上の数値にはまずメトリックから回答し、数値を ✓ 付きの専用カードに表示します。この ✓ がアシスタント自身の文章に付くことはありません。[ビジネス上の数値](/ja/guides/ai-assistant/weave-tab/#ビジネス数値) と [メトリックからの数値](/ja/guides/ai-assistant/weave-tab/#メトリックの数値) を参照してください。

- **締めの準備ができているかを Weave に尋ねたり、2 つのテーブルが一致するかを確認したりできます。** どちらも AI は使いません。

  - **締め準備状況。** 締め、予測、その他の期限が依存するワークフローを **準備状況セット** として指定します。プロジェクトの **Weave** タブの **準備状況** から設定します。1 つのチェックリストですべてに回答します。「13 件中 11 件が準備完了、1 件が未準備、1 件がチェックできませんでした」のように表示されます。ワークフローは、Weave が実行できたすべてのチェックに合格した場合にのみ準備完了となります。Weave が判断できなかった項目は、理由とともに **チェックできませんでした** と表示され、準備完了として扱われることはありません。比較対象となる過去の履歴が少なすぎる最終実行（新しいワークフローなど）は、通常どおりとみなされます。メールの送信やファイルのエクスポートのように、テーブルに書き込まないステップには、チェックする行や空の値がないため、ワークフローが **チェックできませんでした** のまま止まることはありません。[締め前に準備状況を確認する](/ja/guides/ai-assistant/weave-readiness/) を参照してください。
  - **照合。** 2 つのテーブル、または 1 つのテーブルの 2 つの期間を、対応付けたキー列で行ごとに比較します。Weave は、一致するか、どれだけ差があるか、どの行が異なるかを示し、全体を読み取れなかったデータについて「一致」とは決して言いません。使用する前に、別のアーキテクトが各照合を承認します。[2 つのテーブルが一致するかを確認する](/ja/guides/ai-assistant/weave-reconciliation/) を参照してください。

- **Weave が問題の起こりうる箇所をより広く監視し、実行の合間にも通知します。** Weave のチェックに AI は使いません。すべての検出事項と AI アシスタントのすべての回答に、**Weaveが把握する方法** パネルがあります。検出事項では、チェックとその根拠となる値を、回答では、アシスタントが実行した各クエリを表示し、各文には **一致**、**不一致**、**未確認** のいずれかが付きます。[Weave が今日確認する内容](/ja/guides/ai-assistant/weave-findings/#現在weaveがチェックする内容)、[Weave が把握する方法](/ja/guides/ai-assistant/weave-findings/#weaveが把握する方法)、[AI アシスタントで Weave が把握する方法](/ja/guides/ai-assistant/weave-tab/#weaveが把握する方法) を参照してください。

  - **テーブルが期限どおりに書き込まれているか。** スケジュールの期限を過ぎても書き込まれていないテーブルや、テーブルの詳細の **鮮度** で設定した鮮度のしきい値（1 時間から 180 日）を超えて書き込まれていないテーブルを報告します。
  - **古い入力や壊れた入力。** 別のワークフローがその後に書き込んだテーブルを読み取っているワークフローや、失敗した実行に依存しているすべてのワークフローとダッシュボード（グラフが SQL データセットに基づくダッシュボードを含む）を報告します。**依存関係の同期** は、ステップと、そのステップが読み取るテーブルの間に不足しているコネクターを追加します。[依存関係の同期](/ja/guides/workflows/sync-dependencies/) を参照してください。
  - **形が変わったデータ。** 実行後に値の分布が大きく変わった小数列、行が複数回書き込まれるようになった結合、列の型に変換できず抽出ステップが空のままにした値、ファイルが見つからなかったインポートを報告します。また、最新期間が通常から大きく外れているメトリックも、その要因となった項目を示して報告します。Weave は月末や曜日のパターンを考慮するため、常に月末に負荷が高くなるロードは報告されません。[メトリック合計の異常](/ja/guides/ai-assistant/weave-metric-insights/) を参照してください。
  - **遅くなった実行。** 実行を遅くしたステップを示し、新しい実行が古い実行より 4 分の 1 以上長くかかっているワークフローを、最も時間が増えたステップとともに報告します。
  - **実行の合間の通知。** 1 時間ごとのチェックが、各問題の所有者に一度だけアプリ内メッセージで通知します。ヘッダーの **Weave** ボタンには、すべてのプロジェクトで未読の問題の数が表示されます。[実行の合間の通知](/ja/guides/ai-assistant/weave-findings/#実行の合間の通知) と [ヘッダーの Weave ボタン](/ja/guides/ai-assistant/weave-tab/#ヘッダーのweaveボタン) を参照してください。
  - **所有者、コメント、想定内の警告。** 各検出事項には所有者がおり、デフォルトでは、そのワークフローを最後に実行した人です。**割り当て** で別の人に引き継げ、コメントで進捗を記録でき、**チーム** ビューで誰が何を担当しているかが分かります。アーキテクトは、理由と終了日を付けて警告を **これは想定内** にできます。[検出事項に所有者を設定する](/ja/guides/ai-assistant/weave-tab/#検出事項に担当者を設定する) と [検出事項を想定内にする](/ja/guides/ai-assistant/weave-tab/#検出事項を想定内としてマークする) を参照してください。

- **修正アシスタントがエラーを説明し、承認できる変更をカードで提案し、ステップを再実行し、修正を元に戻せます。** テーブルにない列、空の必須設定、データベースが読み取れない SQL、型の誤った値など、よくある失敗については、最初の返信で一般的な原因と修正方法を説明します。提案された変更はカードとして表示され、ステップが失敗した理由と、変更される各設定の現在の値（赤）と新しい値（緑）が示されます。**承認** で適用され、その後アシスタントがステップの再実行を提案し、新たな失敗があれば診断します。**Weave** タブの検出事項で **修正** を選ぶと、その問題についてアシスタントが開きます。**元に戻す** はステップの以前の設定を復元し、**元に戻して実行** は出力を再構築します。[AI でワークフローのエラーを修正する](/ja/guides/ai-assistant/fixing-workflow-errors/)、[AI アシスタントで検出事項を修正する](/ja/guides/ai-assistant/weave-tab/#aiアシスタントで検出事項を修正する)、[修正を元に戻す](/ja/guides/ai-assistant/fixing-workflow-errors/#修正を元に戻す) を参照してください。

- **プロジェクトで Weave が行ったすべてを確認し、監査人向けにエクスポートできます。** プロジェクトの **Weave** タブの **アクティビティ** には、Weave が見つけて後に検出されなくなった問題、AI アシスタントが提案したすべての変更、リクエストした人と承認または却下した人、置き換えた内容と書き込んだ内容の詳細、そして最終的な結果が一覧表示されます。Weave は変更を行う前に承認を記録し、記録できない変更は行いません。**CSVのエクスポート** または **PDFのエクスポート** で期間を監査証跡として保存でき、エントリーは編集も削除もできません。**サマリー** には、見つかって解決された問題、承認された変更、元に戻された件数など、1 か月の概要が表示されます。ワークスペース管理者は、**ワークスペースサマリー…** からすべてのプロジェクトについて同じ内容を確認できます。[Weave アクティビティ履歴](/ja/guides/ai-assistant/weave-activity/) と [Weave 月次サマリー](/ja/guides/ai-assistant/weave-monthly-summary/) を参照してください。

- **保存する前に、ステップが何をするか、変更が何に影響するかを把握できます。** これらはすべてプロジェクトの保存済みの設定から作成され、AI は使いません。ロールで非表示になっているものは、名前を出さず件数だけに含まれます。

  - **すべてのステップとワークフローのドキュメント、すべてのテーブルの列。** 詳細パネルの **ドキュメント** セクションには、ステップの動作と、ワークフローのステップの順序が記載されます。テーブルを読み書きするものは、Weave と AI アシスタントが参照できます。テーブルの詳細パネルには、**列** が型と説明とともに一覧表示されます。**引き継ぎパックをダウンロード** は、メトリック定義と配賦モデルを含むプロジェクト全体を 1 つのドキュメントとして保存します。[テーブル、ステップ、ワークフローのドキュメント](/ja/guides/ai-assistant/weave-documentation/) を参照してください。
  - **変更が影響する範囲。** **保存** の上に、ステップが書き込む内容を読み取る下流のステップの数が表示されます。たとえば「このステップの変更は、2 つのワークフローの 8 個の下流ステップに影響します」のように表示され、**ステップを表示** で一覧を確認できます。[変更が影響する範囲](/ja/guides/ai-assistant/impact-preview/) を参照してください。
  - **保存が拒否する内容。** **保存** の上のバーは、編集中にステップのチェックを実行し、問題ごとに **移動** が表示されます。式エディターは入力中に式をチェックします。[保存が拒否する内容](/ja/guides/ai-assistant/check-while-you-edit/) を参照してください。
  - **1 つのワークフローのレビュー。** ワークフローのキャンバスまたは **ステップ** グリッドの **チェック** は、Weave のチェックに加えて、配賦と行レベルセキュリティのチェックを実行します。[1 つのワークフローをレビューする](/ja/guides/ai-assistant/weave-findings/#ひとつのワークフローのレビュー) を参照してください。

- **ワークスペースで Weave の AI 機能を個別にオフにできます。** ワークスペース管理者は、ヘッダーの **Weave** ボタンで **AI機能…** を選び、Weave チャット、修正アシスタント、インポートとエクスポートのアシスタント、式アシスタント、説明からの SQL 生成、ワークフローレビューの要約、スターターチャートを、それぞれ個別にオン、オフできます。管理者がオフにするまではすべてオンで、Weave のチェックと検出事項は常にオンのままです。変更はすべてセキュリティログに記録されます。[AI機能](/ja/guides/ai-assistant/weave-ai-features/) を参照してください。

- **Allocation Split ステップでドライバーのホワットイフを試せます。** ステップを右クリックして **ホワットイフ…** を選ぶと、ドライバーの値を変えた場合、ドライバーテーブルの別の列を使った場合、同じキーを持つ別のテーブルの数値列を使った場合に、そのステップがコストをどのように配分するかを確認できます。最大 10 個のシナリオを比較でき、各シナリオはステップの最後の実行結果から 1 セント単位まで計算されます。誰が増え、誰が減り、どの行に何も配分されないかが分かります。**内訳の基準:** では、各メンバーの変化がどの勘定科目やその他の値に影響するかを確認でき、**後続のステップ** は、配賦の出力から作成されるテーブルにシナリオを反映します。再実行は行われず、データも変更されません。[ドライバーのホワットイフを試す](/ja/guides/allocations/results/driver-what-if/) を参照してください。

- **プロジェクトの Lakehouse v2 への移行を、準備状況の確認から元に戻すまでガイドします。** **移行準備状況の確認** は、テーブル、ビュー、ステップ、ダッシュボード、データ共有、容量を「問題なし」「要確認」「ブロック」のいずれかで報告し、すべての検出事項に分かりやすい説明を付けます。**v2で試す…** は、スケジュールをオフにし、ERP 転記をシミュレートモードにした非公開の試用コピーを作成します。移行は今すぐ、または指定した時刻に開始できます。実行中はプロジェクトのスケジュールが一時停止され、完了後に復元されます。完了時にはメッセージとメールで通知されます。**変更内容…** は各テーブルの結果を報告し、**移行を元に戻す…** は、元に戻せる期間内であればプロジェクトを Lakehouse v1 に戻します。[プロジェクトを Lakehouse v2 に移行する](/ja/guides/data/migrate-project-lakehouse/) を参照してください。

- **プロジェクトをコピーするとデータもコピーされ、コピーする量を選べます。** **プロジェクトをコピー** では、サイズと警告を確認したうえで、**構造のみ**、**全データ**、**サンプル** のいずれかを、同じ Lakehouse 内、または Lakehouse 間で選べます。データ付きのコピーは、作成した本人だけが利用できます。**コピー結果** は各テーブルの結果を一覧表示し、**失敗したテーブルを再試行** は失敗したテーブルだけをコピーし、**インポートまたはコピーの結果を表示** は後でウィンドウを開き直します。センサーとスケジュールイベントはコピー先ではオフの状態で作成されるため、そこでオンにするまで何も起動しません。[プロジェクトのコピー](/ja/guides/projects/managing-projects/#プロジェクトのコピー) を参照してください。

- **ストレージを確認し、保持する履歴の量を管理できます。** ワークスペースの **ストレージ** ウィンドウには、含まれる分、予約分、オンデマンドの各帯を示すメーター、課金に使われる月平均の予測値、各プロジェクトの現在のデータと履歴が表示されます。**プロジェクト** の一覧には **サイズ** 列があり、各プロジェクトの **テーブル** タブには **現在のデータ**、**履歴**、**タイムトラベル日数**、**注記** の列と、空き容量を確保する方法を提案する **ストレージ** ボタンが表示されます。タイムトラベルのデフォルトは 1 日で、プロジェクトのデフォルトを 1 日から 90 日の範囲で設定でき、任意のテーブルについて延長できます。テーブルが保持する日数（テーブル自体の設定とプロジェクトのデフォルトのうち長いほう）より古い履歴は復元できないため、長く保持する必要があるものについては設定を引き上げてください。サイズは、履歴を含め実際に保存されている内容を反映します。設定より古い履歴は毎晩クリーンアップされるため、使用量はその後の数日間で減少します。**Deleted tables awaiting cleanup** 行には、削除されたテーブルのうち、まだ解放処理中のストレージが表示されます。[ストレージの管理](/ja/guides/projects/managing-storage/) と [履歴とタイムトラベル](/ja/guides/projects/managing-storage/#履歴とタイムトラベル) を参照してください。

- **各ダッシュボードを閲覧できるセキュリティグループを、1 つのダイアログで選べます。** **閲覧できるユーザー** では、ダッシュボードを **プロジェクトの全員**、**特定のグループ**、**所有者のみ (下書き)** のいずれかに設定でき、アクセス権を得るユーザーと失うユーザーのプレビューが表示されます。ダッシュボードにアクセスできないユーザーには、所有者にメールを送る **Request access** ページが表示されます。ワークスペース管理者は **ダッシュボードアクセスレビュー** を利用でき、プロジェクトの **デフォルトのダッシュボード対象者** は、そのプロジェクトの新しいダッシュボードに適用されます。対象者の設定でダッシュボード自体は非表示になりますが、グラフのデータはプロジェクトのアクセスと行アクセスに従います。[ダッシュボードを閲覧できるユーザーを制御する](/ja/guides/dashboards/control-who-can-see-a-dashboard/) を参照してください。

- **別途の接続なしで、AI アシスタントからグラフとダッシュボードを作成できます。** PlaidCloud の MCP コネクターだけを接続し、公開済みのテーブルまたはビューに対して、表、棒グラフ、折れ線グラフ、円グラフ、大きな数値のグラフを依頼し、そのグラフをダッシュボードに配置します。リンクと確認用のデータサンプルが提供され、自分が所有するグラフの編集も依頼できます。計算済みのメジャーはビューの列に置き、新しいダッシュボードにはプロジェクトのデフォルトの対象者が設定され、グラフを追加しても既存のものが削除されることはなく、1 つのダッシュボードには 1 つのプロジェクトのグラフを配置できます。最初の依頼の前に、ダッシュボードサイトを一度開いておいてください。Microsoft 365 Copilot、PlaidCloud のアプリ内アシスタント、ワークフローのステップ、サービスアカウントでは作成できません。[AI アシスタントでグラフとダッシュボードを作成する](/ja/integrations/ai-coding-agents/build-dashboards/) を参照してください。

- **有料プランでは、独自の ID プロバイダーでシングルサインオンを設定できます。** **Workspaces** ページの **Single sign-on** で、Microsoft Entra ID、Okta、または任意の OpenID Connect プロバイダーを追加できます。コピーできるリダイレクト URI と **Test sign-in** ボタンが用意されています。既存のアカウントを持つユーザーは、そのアカウントに一度サインインすることでリンクできます。MFA 付きのパスワードと、Google、Microsoft、GitHub によるソーシャルサインインは、すべてのプランで引き続き利用できます。[シングルサインオン](/ja/administration/control-plane/workspace-configuration/#シングルサインオン) を参照してください。

- **利用状況レポートで、誰が何を使っているかを確認できます。** **ID** タブから、セキュリティログの権限を持つ管理者は、アクティブなユーザー、新規ユーザー、再訪ユーザー、各画面、ダッシュボード、Panel アプリ、ノートブックの利用状況、画面間で最も多い経路、最大 6 ステップのファネルを確認できます。最大 180 日の範囲を選択でき、サマリーを CSV でダウンロードでき、依頼に応じてメンバーの利用状況を消去できます。[利用状況レポート](/ja/administration/access/usage-reports/) を参照してください。

- **スマートフォンからワークフローを実行、監視し、外出先で Weave に質問できます。** 無料の PlaidCloud アプリは、iPhone と iPad 向けに [App Store](https://apps.apple.com/app/id6769620647)、Android 向けに [Google Play](https://play.google.com/store/apps/details?id=com.plaidcloud.mobile) で提供されています。ワークスペースのサインインページ（シングルサインオンを含む）からサインインし、プロジェクトを閲覧し、各ステップの状態と実行履歴を確認し、ワークフローを **実行**、**一時停止**、**再開**、**停止** できます。ワークスペースについて Weave に質問したり、失敗したステップで **Weave に質問** をタップして、そのコンテキストから始めたりできます。Weave が提案する変更は、**承認** をタップして Face ID または指紋で確認するまで保留されます。[PlaidCloud モバイルアプリ](/ja/guides/mobile-app/) と [モバイルでの Weave](/ja/guides/mobile-app/weave-on-mobile/) を参照してください。

- **PlaidXL で Excel から PlaidCloud のデータを扱えます。** アドインは通常のサインインでサインインし、各ブックは自身のプロジェクトとワークスペースを記憶します。テーブルの選択した列と行をワークシートに取得でき、**Refresh All Tables** で最新の状態に更新できます。取得したテーブルを編集し、**Save to PlaidCloud…** で確認後に書き戻せます。復元ポイントと **Restore previous version** リンクが用意されます。空のセルとエラーが表示されているセルは空として保存され、フィルターされたテーブルや取得していない列には、それぞれ事前に明示的な警告が表示されます。`PLAIDXL` 数式は階層を展開してドリルダウンし、ディメンションノードの任意の組み合わせにロールアップしたメジャーを計算します。`>[2]`、`>[]`、`>[0:-1]` などのドリルキーは、開始ノードから世代を数え、各ノードをそれぞれの親の下に一覧表示します。`>[-1]` は葉のみ、`>[0:-1]` は葉を除くすべてを意味します。`CELL` 数式だらけのレポートは、はるかに少ないリクエスト数で再計算され、計算できないセルにはマウスを重ねると理由が表示されます。**Formulas** タブは数式を作成してくれ、タスクペインは Office のテーマに従ってキーボードで操作でき、リボンの **Convert to values (for sharing)** と **Restore PlaidXL formulas** は、PlaidXL を使っていない人向けのコピーを準備します。[PlaidXL で Excel を使う](/ja/get-started/tutorials/excel-with-plaidxl/) と [PlaidXL リファレンス](/ja/reference/cli/plaidxl/) を参照してください。

- **新しいワークフローステップ。** [Delta Lake のインポート](/ja/reference/workflow-steps/import/import-delta/)、[ORC のインポート](/ja/reference/workflow-steps/import/import-orc/)、[Export to ORC ステップ](/ja/reference/workflow-steps/export/export-to-orc/)、[空間の再投影](/ja/reference/workflow-steps/spatial/spatial-reproject/)、[空間ファイルのエクスポート](/ja/reference/workflow-steps/spatial/spatial-file-export/)、[Update Excel Cells ステップ](/ja/reference/workflow-steps/document/document-excel-update/)、[Document Write Blob ステップ](/ja/reference/workflow-steps/text-documents/document-blob-write/)、[KNIME Rule Engine ステップ](/ja/reference/workflow-steps/tables/table-knime-rule-engine/)、そして [テーブル: タイムスタンプへ復元](/ja/reference/workflow-steps/tables/table-restore-timestamp/) は、指定した時刻以前で最新のスナップショットにテーブルを戻します。[NetSuite: SuiteQL クエリのインポート](/ja/reference/workflow-steps/netsuite/import-suiteql-query/) は、作成した SuiteQL クエリを型付きテーブルにロードします。[ドキュメント: ファイルを暗号化とドキュメント: ファイルを復号](/ja/reference/workflow-steps/document/encrypt-decrypt-file/) は、AES または Blowfish を使用するか、Excel ブックのパスワードを設定または削除し、キーは常に変数に保持されます。[ML: モデルの学習](/ja/reference/workflow-steps/machine-learning/ml-train/#その他のアルゴリズム) には XGBoost、勾配ブースティング、サポートベクターマシン、クラスタリング、PCA が加わり、[ML: スコアリング](/ja/reference/workflow-steps/machine-learning/ml-score/#その他の出力列) にはクラスの確率とモデルレポートが加わり、[テーブル: テキスト関数](/ja/reference/workflow-steps/tables/table-text-function/#その他の関数) には文字列距離と JSON および XML の関数が加わります。ファイルのインポートとエクスポートは、Zstandard、Snappy、LZ4、LZO、Deflate のファイルを読み書きします。

- **すでに使っているステップのオプションが増えました。** すべてのオプションは、ステップのフォームのフィールドとして用意されています。

  - **インポート。** [Excelのインポート](/ja/reference/workflow-steps/import/import-excel/#シート対応表) は、ブックごとに異なるワークシートの組み合わせを読み取り、パスワード保護されたブックを開けます。[固定幅のインポート](/ja/reference/workflow-steps/import/import-fixed-width/#レイアウト) は EBCDIC と Latin-1 のファイルを読み取り、[XMLのインポート](/ja/reference/workflow-steps/import/import-xml/#レコードの読み取り形式) は 1 つの繰り返し要素をテーブルに読み取ります。ファイル検索では、ワイルドカードと正規表現のパターンを使えます。
  - **エクスポート。** CSV と Excel のエクスポートは既存のファイルに追記でき、ほとんどのエクスポートは、すでに存在するファイルを置き換える代わりに停止でき、CSV、Excel、JSON、SQL のエクスポートは行を並べ替えられます。[Export to Excel ステップ](/ja/reference/workflow-steps/export/export-to-excel/#分割) は、列の値ごとにシートまたはファイルを書き出せ、[Export to CSV ステップ](/ja/reference/workflow-steps/export/export-to-csv/) は、Spark と同じ方法で引用符をエスケープまたは省略できます。
  - **テーブルとフロー。** [Table Extract ステップ](/ja/reference/workflow-steps/tables/table-extract/) と結合は、実行時に名前が決まる列を引き継げるため、ピボットの後のステップに列の一覧は不要です。[テーブル: 和集合（すべて）](/ja/reference/workflow-steps/tables/table-union-all/#列の照合) は、ソースを位置で積み重ねられます。ステップは、テーブルが存在するかどうかに応じて実行できます（[テーブル存在条件](/ja/guides/workflows/step-conditions/#テーブル存在の条件)）。[Workflow Loop ステップ](/ja/reference/workflow-steps/workflow-control/workflow-loop/#反復が失敗した場合) は、失敗した反復の後も続行でき、[待機](/ja/reference/workflow-steps/general/wait/#時刻またはファイルの待機) は、時刻またはファイルの変更を待機できます。
  - **通知、AI、リモート SQL。** [Notify Via Email ステップ](/ja/reference/workflow-steps/notifications/notify-via-email/) には Cc、Bcc、Reply-To が加わり、ドライバーテーブルの各行にそれぞれのメールを送信できます。[Text: NLP (AI) ステップ](/ja/reference/workflow-steps/text-documents/nlp-ai/) は埋め込みを書き込め、失敗した呼び出しをそれぞれ報告します。[リモート実行: SQL](/ja/reference/workflow-steps/agent/agent-remote-execution-of-sql/#行ごとに1回ステートメントを実行する) は、ストアドプロシージャなどのステートメントを、行ごとに 1 回ずつ実行できます。

- **REST Request フォームで、リクエストの作成と確認ができます。** 大規模なエンドポイントカタログを絞り込んだり、Postman コレクション、OpenAPI 仕様、HAR ファイルを貼り付けたりドロップしたりできます。ヘッダーとパラメーターは、重複、名前の入力ミス、平文で入力されたシークレットがチェックされ、テストリクエストでは整形されたレスポンスと、推奨されるアイテムパスが表示されます。このステップには、ページ番号、カーソル、Link ヘッダーによるページング、プロキシ、Digest と NTLM のサインイン、SOAP 呼び出し、小数のリクエストレート、実行中ジョブのポーリング、各エラーを資格情報をマスクした行として残す生のレスポンスモードが加わります。POST、PUT、PATCH はレート制限後には再試行されますが、サーバーエラー後には再試行されません。[REST Request ステップ](/ja/guides/workflows/rest-request-step/) と [RESTリクエスト](/ja/reference/workflow-steps/general/rest-request/) を参照してください。

- **列、値、使用しているワークフローから、あらゆるテーブルを探せます。** **テーブル** タブには **ワークフロー別** フォルダーがあります。列の検索では、一致した列ごとに、その列に供給するテーブルと供給されるテーブルの **列ツリー** が表示されます。**データ内の値を検索… (低速)** は、入力した値を持つテーブルと列を、すでに開ける行の範囲で一覧表示し、結果をテーブルエクスプローラーで開きます。**テーブルの詳細** には、テーブルの **公開名** がコピーボタン付きで表示され、Snowflake または Databricks ウェアハウスでは、削除ウィンドウに、テーブルが最後に読み取られた日時と読み取った人が表示されます。ドキュメントアカウントについては、**使用箇所** がそのアカウントを使用しているすべてのステップ、ワークフロー、プロジェクトのデフォルトを一覧表示し、**参照先を変更...** はプレビュー後にそれらを別のアカウントに移します。[テーブルを探す](/ja/guides/projects/managing-tables-and-views/#テーブルを検索する)、[値を検索](/ja/guides/projects/managing-tables-and-views/#値を検索)、[最後の読み取り](/ja/guides/projects/managing-tables-and-views/#最後の読み取り)、[ドキュメントアカウントの使用箇所と参照先の変更](/ja/guides/documents/account-management/document-account-used-by/) を参照してください。

- **任意のプロジェクトで CSV をテーブルに変換し、ひと目で確認できます。** プロジェクトの **テーブル** 一覧に CSV をドロップするか、**新規** > **CSVファイルからテーブルを作成** を選ぶと、PlaidCloud が新しいテーブルとしてインポートします。**新規** > **CSVファイルからプロジェクト** は、CSV からプロジェクトを作成します。続いて **データの概要** に、行数、各列の型、空の値と異なる値の割合、スターターチャートが表示され、スターターダッシュボードもワンクリックで作成できます。[CSVファイルをインポートする](/ja/guides/projects/managing-tables-and-views/#csvファイルをインポート) と [自分の CSV から始める](/ja/get-started/quickstart/#自分の-csv-から始める) を参照してください。

- **高度なワークフローのキャンバスを、より直接的に配置、編集できます。** **Cmd** または **Ctrl** を押しながらステップをドラッグして、コンテナーの内外に移動し、実行コンテナーの出力を **出力ポート** から接続します。**配置** メニューは、ステップの順序を保ち、ノートをそのステップと一緒に移動しながら、整理、整列、均等配置、スナップを行い、それぞれ 1 回の **元に戻す** で戻せます。何もない場所を右クリックすると、クリックした位置にステップをコピー、貼り付けできます。選択したステップの **ステップを作成** は、そのステップが書き込むテーブルから結合または抽出を開始し、未保存の変更があるウィンドウは、破棄する前に確認します。ステップの入力または出力の目のアイコンは、まさにそのテーブルのプレビューを開きます。[コンテナー](/ja/guides/workflows/advanced-workflows/#コンテナー)、[キャンバスを整える](/ja/guides/workflows/advanced-workflows/#キャンバスを配置する)、[高度なキャンバスでのコピーと貼り付け](/ja/guides/workflows/copy-paste-steps/#高度なキャンバスでのコピーと貼り付け)、[ステップを作成する](/ja/guides/workflows/workflow-explorer/#ステップの作成) を参照してください。

- **高度なワークフローを最適化して高速に実行できます。** ワークフローを右クリックして **最適化...** を選ぶと、変更が行われる前に確認できます。**Rebuild dependencies from data lineage** は、各ステップを、そのテーブルを使用するステップにだけ接続するため、独立したステップは並列に実行されます。**Merge** は、連続した Extract Data ステップを 1 つにまとめ、現在のデータで両方のバージョンが同じ結果になる場合にのみ適用されます。ウィンドウには短縮された時間が表示され、最適化できなかった各ステップが理由とともに一覧表示され、**最適化を元に戻す...** でワークフローを復元できます。[ワークフローを最適化する](/ja/guides/workflows/optimize-a-workflow/) を参照してください。

- **実行する前に、結合のキーを正しく設定できます。** **Join Map** の **自動判定** は、同じ 2 つのテーブルを結合している別のステップのキー、次にメトリック、次にテーブルのキー列、次に一致する名前の順に使い、どれを使ったかを示します。**キーを確認** は、結合先のテーブルで繰り返されるキー値の数を数えます。これは行数を増やす原因になりえます。**ソースを検査** がステップの列を入力すると、`customer_id` のような識別子の列は、**合計** ではなく **グループ化** から始まります。[内部結合](/ja/reference/workflow-steps/tables/table-inner-join/#キーを確認) を参照してください。

- **AI アシスタントと Microsoft 365 Copilot が、データをより深く理解し、より多くのことができるようになりました。**

  - **分析パスと列ごとのガイダンス。** 各分析パスには **プロンプトガイダンス**（最大 1,000 文字）があり、常に適用されるフィルター、会計カレンダー、ビジネス用語を記述できます。列のメモは、テーブルの列とともにアシスタントと LLM ステップに渡されるため、コードやフラグが意図どおりに解釈されます。[分析パスを AI アシスタントに役立てる](/ja/integrations/ai-coding-agents/analysis-paths/#aiアシスタントに役立つパスにする) を参照してください。
  - **Copilot の機能強化。** Microsoft 365 Copilot の PlaidCloud エージェントは、CSV、Excel、PowerPoint、Word のファイルを作成し、ビジネス数値にメトリックから回答し、内訳をテーブル全体で合計し、配賦の仕組みを説明します。管理者は更新されたパッケージをダウンロードし、Teams 管理センターで更新します。[Microsoft 365 Copilot](/ja/integrations/microsoft-365-copilot/) を参照してください。
  - **1 回の呼び出しでより多くを実行。** アシスタントは、行アクセスを先に適用したうえで、サーバー側でテーブルのグループ化と合計を行い、PlaidCloud のドキュメントを検索して読み取り、OneDrive と SharePoint を含む完全に設定済みのドキュメントアカウントを書き込み専用の資格情報で作成し、ラベルの追加だけでなく削除も行い、PlaidCloud で見ているビューを扱えます。[分析パス](/ja/integrations/ai-coding-agents/analysis-paths/#mcp経由での使用) と [AI エージェントを使い始める](/ja/integrations/ai-coding-agents/getting-started/) を参照してください。

## 変更

- **Go To Metric は、Weave の検出事項が対象とするメトリックを開きます。** クリックしたときに、ご自身の行アクセスのもとで計算されたメトリックの数値が、元となったバージョンを示す ✓ とともに表示されます。異常な合計の場合は、Weave が判断した期間の、Weave が名前を挙げた項目が対象です。それ以外のメトリックの検出事項（他のメトリックから計算されるメトリックに関するものを含む）では、メトリックの合計です。数値の下の **行へ移動** は、変化の元になった行を引き続きテーブルエクスプローラーで開きます。[メトリックへ移動](/ja/guides/ai-assistant/weave-metric-insights/#メトリックへ移動) を参照してください。

- **1 つの Weave タブに、検出事項と Weave AI のチャットがまとまりました。** チャットは **Weave** タブ内のタブで、**検出事項** の後ろにあります。各検出事項は、専用の **修正**、**移動**、**既読にする** ボタンを持つカードで、破線のカードは Weave がチェックできなかったものを示し、チップで注意が必要なものに応じて一覧を絞り込めます。式に関する検出事項はエラーの場所を示し、式自体は **Weaveが把握する方法** の下にあります。Weave は実行が終了したときに各問題を一度だけ知らせ、1 つのプロジェクトに関するメッセージは積み重ならず 1 つにまとめられます。Weave は変更された部分だけを再チェックするため、大規模なプロジェクトでもタブはすばやく開きます。ワークフロー一覧の Weave 列は削除されました。[Weave タブ](/ja/guides/ai-assistant/weave-tab/) と [実行の終了時に通知を受ける](/ja/guides/ai-assistant/weave-findings/#実行終了時の通知) を参照してください。

- **Ctrl/Cmd-K で、どの画面からでもコマンドパレットを開けます。** 入力する前には、最後に開いたものと実行できる操作が一覧表示されます。ホーム、プロジェクト、ダッシュボード、ドキュメントへの移動、ライトモードとダークモードの切り替え、AI の接続、ヘルプの表示などです。入力すると両方の一覧が絞り込まれ、2 文字以上では、プロジェクト、ワークフロー、テーブル、ダッシュボード、Panel アプリも検索します。[検索とコマンド](/ja/guides/launcher/#検索とコマンド) を参照してください。

- **ステップは、実行時ではなく保存時に問題を検出します。** 実行が失敗する、または誤った結果になる設定のステップを保存しようとすると、変更すべき内容を示すメッセージとともに拒否されます。各ステップのリファレンスページに、チェック内容が一覧されています。ステップまたはそのソーステーブルにもう存在しない、対応付け済みのソース列は赤で示され、保存すると **すべて削除して保存**、**このまま保存**、**キャンセル** のダイアログが開きます。結合、ルックアップ、空間のステップは、そのような行を勝手に削除せず、そのまま残します。未定義の変数を使う式は、その変数の名前を示し、実行時に拒否されたステップは、その理由を分かりやすい言葉で説明します。[一覧にないソース列](/ja/reference/workflow-steps/tables/table-extract/#一覧になくなったソース列)、[ソーステーブルにない列](/ja/reference/workflow-steps/tables/table-extract/#ソーステーブルに存在しない列)、[ステップのエラーの管理](/ja/guides/workflows/managing-step-errors/) を参照してください。

- **存在しないソースや空のソースは、決してエラーになりません。** ファイルが存在しない、または空のファイルインポートは、パスを示す警告付きで完了し、ターゲットテーブルは宣言された列を持つ空の状態のままになるため、後続のステップは 0 行を読み取ります。存在しない、または空のフォルダーに対するドキュメントステップは「Nothing to process」と報告し、ワークフローは続行されます。リモートファイルのステップは、存在しないパスについては警告し、安全でないパスは拒否します。ファイルが存在しないことのチェックは、OneDrive、SharePoint、SFTP で動作します。バッチテーブルが空の **レポート: バッチ生成** は、警告付きで完了し、レポートは作成されません。[インポートステップ](/ja/reference/workflow-steps/import/)、[ドキュメントワークフローステップ](/ja/reference/workflow-steps/document/)、[ドキュメントパス条件](/ja/guides/workflows/step-conditions/#ドキュメントパスの条件) を参照してください。

- **大規模なワークフローも安定して実行され、停止でインポートとエクスポートがキャンセルされます。** PlaidCloud が混み合っているときは、ステップは失敗せずに空き容量を待ち、ステップが滞留するにつれて容量が追加されます。外部データベーステーブルのインポートは、最大 10 個のテーブルを同時に実行します。ステップを実行しているサーバーが失われた場合、出力を置き換えるステップは自動的に再実行され、安全に繰り返せないステップは、*interrupted* というメッセージで一度だけ失敗します。**停止** は実行中のインポートジョブとエクスポートジョブをキャンセルし、停止された実行は Stopped と報告されます。[中断されたステップ](/ja/guides/workflows/run-a-workflow/#中断されたステップ) と [一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開) を参照してください。

- **すべての Lakehouse が同じ方法で保存、計算します。** CSVのインポート、XMLのインポート、Import Table Archive での空のフィールドは null としてロードされるため、後続のステップで `= ''` や `= 0` を判定している場合は、代わりに null を判定する必要があります。`cast(x, Float)` はどこでも 64 ビットなので、大きな金額も桁数が保たれ、PlaidCloud が作成する Float 列は倍精度です。JSON 列、**Table: Delete Rows**、集計を行う条件は、すべての Lakehouse で動作します。ソルバー、予測、そして pandas で実行される Pivot と Allocation Split など、独自の結果を構築するステップは、それらを型付きデータとして、はるかに高速にロードします。テーブルエクスプローラーは、数値列の最小値、最大値、平均、合計、標準偏差、分散を表示します。[Float へのキャスト](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#floatへのキャスト) と [列データと一意のカウント](/ja/guides/data/table-explorer/#列のデータと一意な値の数) を参照してください。

- **ファイルのエクスポートで型が保持されます。** Parquet ファイルは整数列を整数のまま保持し、タイムスタンプをマイクロ秒で保存し、タイムゾーンを UTC と表示します。Avro ファイルは日付、タイムスタンプ、ブール値の型を保持し、単一テーブルの Avro エクスポートには、エクスポート名が付きます。Parquet エクスポートで複数のファイルを選択すると、Parquet は 1 つのファイルを書き込むというメッセージで停止します。非常に大きな Parquet、ORC、JSON のエクスポートは、行を読み取りながら書き込まれるため、メモリ不足にならなくなり、Parquet は選択した圧縮を使用します。バージョン 1.2.33 以降の PlaidLink エージェントは、エクスポートされたテーブルを Parquet ファイルとして受け取ります。[Export to Parquet ステップ](/ja/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro ステップ](/ja/reference/workflow-steps/export/export-to-avro/)、[データがエージェントに届く仕組み](/ja/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#データがエージェントに届く仕組み) を参照してください。

- **ERP 転記は各スケジュールのモードに従い、確証のない応答は確認のために保留されます。** スケジュールイベントは、プロジェクトの設定を上限として、独自の転記モード（**本番**、**シミュレート**、**オフ**）を保持し、**選択したイベントを実行** は各イベントのモードを使用します。タイムアウトやサーバーエラーなど、PlaidCloud が確認できない ERP の応答は、却下として記録されず、不確定として保留され、転記を 2 回取り消すことはできません。転記レジスターには **reversal outstanding** の転記が一覧表示され、アーキテクトは、プロジェクトのホームページの **ERP書き込み承認** でプロジェクトに転記を許可します。[ERP転記モード](/ja/administration/scheduled-events/event-scheduler/#erp転記モード)、[取り消し](/ja/guides/connections/posting-register/#取消)、[プロジェクトに転記を許可する](/ja/guides/workflows/run-a-workflow/#プロジェクトに転記を承認する) を参照してください。

- **行アクセスがグループの変更に追従し、問題の内容も分かります。** シングルサインオンがサインイン時に設定するグループメンバーシップは、約 15 分以内にダッシュボードの行アクセスに反映され、デフォルトグループの新しいメンバーは、約 1 分以内に自分の行を取得します。行アクセスのウィンドウは、制限が何もフィルターしない場合に警告し、`&`、`/`、`%` を含む列名を処理し、同期が失敗したときには、理由付きの **エラー** と、**再試行** ボタン付きの **再試行中** を表示します。[ダッシュボードの同期を保つ](/ja/administration/access/managing-security-groups-and-assignments/#ダッシュボードの同期の維持) を参照してください。

- **ユーザー定義関数は、新しいライブラリとともに Python 3.14 で実行されます。** ほとんどの関数は変更なしで動作します。numba をインポートする関数や、`cgi` や `telnetlib` など Python から削除された標準ライブラリのモジュールをインポートする関数は、失敗するようになり、書き直しが必要です。予測の AutoTheta の境界は、以前の実行とわずかに異なる場合があります。[User Defined Transform ステップ](/ja/reference/workflow-steps/general/user-defined-transform/) を参照してください。

- **エージェントの完全アクセスは非推奨となり、2027 年 1 月 15 日に削除されます。** **完全** アクセスを使用する LLMステップは、警告をログに記録します。**読み取りと書き込み** に移行してください。この設定では、エージェントは PlaidCloud の書き込みツールを通じてデータを変更し、LLMステップは **書き込み** にチェックが入ったバインディングにのみ書き込みます。[エージェントアクセス](/ja/integrations/ai-architecture/llm-providers/#エージェントアクセス) を参照してください。

- **ドキュメントアカウントの設定と参照が簡単になりました。** OneDrive または SharePoint アカウントのファイルブラウザーは、開始パス以下のフォルダーを開きます。Google Cloud Storage アカウントには有効なサービスアカウントキーが必要で、キーのない既存のアカウントは、キーを追加するまで動作しなくなります。拒否された設定は理由を説明し、未使用の Backup アイコンは **アカウントの管理** から削除されました。[Google Cloud Storage アカウントを追加する](/ja/guides/documents/adding-accounts/add-google-cloud-storage-account/) と [ドキュメントアカウントのバックアップ](/ja/guides/documents/account-management/managing-document-account-backups/) を参照してください。

- **Project アプリが、請求書、出張、遅延入力をより完全に扱えるようになりました。** 新しい請求書は、顧客と発注書番号を提供するマスタープロジェクトから開始します。下書きの請求書を削除すると、その時間と出張が再び請求対象になり、**売掛金の受信者** は、請求書が提出されたときにメールを送信する相手を設定します。出張のドロワーには、各明細のベンダー、カテゴリ、監査ステータスが表示され、**遅延入力の時間を追加** は、承認済みの週のシートを開始します。[Project アプリで時間と経費を記録する](/ja/guides/time-expense/track-time-and-expenses/) を参照してください。

- **どのステップからも参照されないすべてのテーブルを削除していた API 呼び出しを削除しました。** 代わりに、ID を指定してテーブルを削除してください。

- **アプリ全体のその他の小さな変更。** アカウント、ダッシュボード、メンバー、グループ、設定の一覧で行をダブルクリックすると、開きます。空の **ディメンション**、**データエディター**、**UDF**、**ステップ** タブには、次に行うことが説明され、アプリのないメンバーはランチャーに移動します。ステップのテーブルセレクターには、テーブルが最後に更新された日時が表示されます（[ソーステーブルが最後に変更された日時を確認する](/ja/guides/workflows/create-workflow/#ソーステーブルの最終変更日時の確認)）。外部データベーステーブルのエクスポートは、専用のタブで列をマッピングし、**レポート: バッチ生成** には、未使用の **Report Constants** セクションが表示されなくなりました。Convert Encoding ステップは、中央ヨーロッパ、トルコ、アラビアのエンコーディングを認識します。削除された画面へのリンクは、その旨を表示します。

## 修正

- **AI アシスタントは、承認するまで何も変更せず、名前をそのまま表示します。** 新しいテーブルへのステップの構築では、承認前にテーブルが作成されていましたが、現在は承認後にテーブルとステップが一緒に作成され、プロジェクト、ワークフロー、ディメンションの作成、テーブルのコピー、テーブルのプロパティやラベルの変更も、事前に確認を求めます。承認は次の返信でのみ有効です。アシスタントが提案するインポートまたはエクスポートは、テーブル、ドキュメントアカウント、ワークフローを名前で表示し、存在しないものや開けないものと組み合わせて提示されることはありません。アンダースコアを含む名前は、斜体にならずそのまま表示され、テーブルとコードはダークテーマでも読みやすく、図は文字ではなく描画され、式エディターの Weave パネルは、編集中の式を読み取ります。アシスタントは、名前のないテーブルがあっても、プロジェクトのテーブルを一覧表示し、ステップが複数のテーブルを読み書きしている場合でも、どのステップがテーブルを読み書きするかにエラーで止まらず回答します。[ワークフローステップを構築する](/ja/guides/ai-assistant/weave-tab/#ワークフローのステップを作成する) を参照してください。

- **ファイルインポートが、指定したものを正しく読み取ります。** Excelのインポートは、列全体の範囲と XLSB ブックを読み取り、zip 圧縮されたブック内のシートを見つけ、パディングや改行のあるヘッダーでも失敗しなくなりました。CSVのインポートは **スキップする行** を尊重するため、SAP のリストエクスポートのように、ヘッダーの上に行があるファイルも列名でインポートされ、デフォルトの区切り文字、引用符、エスケープ文字で実行されます。1 つのソース列で複数のターゲット列に供給でき、すべての列が固定値のインポートは全行をロードし、大文字の圧縮拡張子が付いたファイルは展開され、変更がなければスキップするインポートは、空にされたテーブルを再ロードします。AI アシスタントに **プロジェクトのデフォルト** からファイルをインポートするよう依頼すると、プロジェクトのデフォルトのドキュメントアカウントを読み取り、プロジェクトに設定がない場合はその旨をはっきりと伝えます。新しい列型の Parquet ファイルも、ドキュメントで開けます。[Excelのインポート](/ja/reference/workflow-steps/import/import-excel/#読み取り対象) と [CSVのインポート](/ja/reference/workflow-steps/import/import-csv/#行の選択) を参照してください。

- **ワークフローのステップが、設定どおりに保存、実行されます。** テーブル: アップサートのステップが再び保存でき、**更新キー** 列も元に戻りました。テーブル: プロジェクト間コピーは、ターゲットプロジェクトの名前を示し、データ共有を通じて読み取ります。ドキュメント: ダッシュボードをPDFとして保存は列の型を保持し、テーブル: 和集合（重複なし）とテーブル: 和集合（すべて）は列を名前で対応付けます。複数テーブル結合は複数の入力で保存でき、スペースを含む列名を受け付けます。Table Lookup はルックアップ列の集計設定を無視し、SCD-2時点指定結合は変数を日付として受け付けます。LLMステップは 4.6 より古い Claude モデルで実行され、AI アシスタントが編集してもモデルを保持します。RESTリクエストは行の値を 1 回だけエンコードして送信し、リモートデータベースへのエクスポートは行をコミットします。[更新キー](/ja/reference/workflow-steps/tables/table-upsert/#更新キー)、[データ共有の管理](/ja/reference/workflow-steps/tables/frame-project-copy/#データ共有の管理)、[複数テーブル結合](/ja/reference/workflow-steps/tables/table-multi-table-join/) を参照してください。ワークフローを選択するステップ（ワークフローの削除、ワークフローのコピー、ワークフローの名前の変更、ワークフローの停止）は、存在しなくなったワークフローを *id (missing)* と表示したまま保持し、一覧の最初のワークフローに切り替わることはありません。

- **ワークフローの実行が、正しく終了します。** Workflow Loop ステップは、反復のたびにループ対象のワークフローを実行し、反復するコンテナーや、1 回の実行で複数回実行されるワークフローも同様です。ステップから、または並列グループ内から開始する実行は、正しいステップを実行して終了します。長時間実行されるインポートまたはエクスポートが 2 回開始されることはなく、PlaidCloud の更新中に停止することもなく、サーバーエラーで終わったアクションが再送されることもありません。データベースドライバーのクラッシュは、そのステップだけを、データベースが示す理由とともに失敗させます。実行履歴はすべてのステップの行数をカウントし、作業が始まる前に失敗したステップは、理由をワークフローログに書き込みます。[Workflow Loop ステップ](/ja/reference/workflow-steps/workflow-control/workflow-loop/) と [実行履歴](/ja/guides/workflows/advanced-workflows/#実行履歴) を参照してください。

- **プロジェクトのコピー、インポート、オープンが、思いがけない動作なく行えます。** プロジェクトのインポートは、復元できたものをすべて保持し、除外したものを **インポート結果** ウィンドウに一覧表示し、進捗を表示し、失敗した理由を示し、再試行できます。選択したオブジェクトのコピーは、プロジェクトに変数がある場合でも動作します。プロジェクトを開いても設定は変更されなくなり、**独自のデータを取り込む** は CSV をインポートし、PostgreSQL ウェアハウスでのテーブル作成も動作します。App Runner アプリは、PlaidCloud の更新時に自動で更新され、行を制限するプロジェクトの閲覧者でも動作します。[アーカイブの一部がインポートされない場合](/ja/guides/projects/archive-a-project/#アーカイブの一部がインポートされない場合) と [アプリを最新に保つ](/ja/guides/workflows/use-converted-alteryx-apps/#アプリを最新の状態に保つ) を参照してください。

- **ディメンションと配賦が、正しくロード、読み取りされます。** 親子ロードでは、親が空の行を最上位メンバーとして保持し、メイン階層の外にあるメンバーは、あらゆる種類のロードで 2 つ目の代替階層に対して拒否されます。階層に含まれない親の下にメンバーを移動することは拒否され、ディメンションのステップは見つからなかったディメンションの名前を示し、空白を含む列の貼り付けでは、各値が自分の行に保たれます。大規模なディメンションの読み取りが、ワークスペースの他のユーザーを待たせることはなくなりました。ディメンションのプロパティで **階層** が **未指定** のままの配賦ルールも実行されます。[代替階層へのロード](/ja/reference/workflow-steps/dimensions/dimension-load/#代替階層へのロード) と [ディメンション型のプロパティとメンバーピッカー](/ja/guides/dimensions/dimensions/#ディメンション型のプロパティとメンバーピッカー) を参照してください。

- **ワークフローのキャンバスと画面が正しく動作します。** **ワークフローにドリルダウン** は、高度なワークフローをキャンバスで開き、キャンバスはすべてのワークフローを開き、レイアウトの一部を読み取れなかった場合はその旨を伝えます。収まらないツールバーのボタンは **その他** メニューに移動し、一覧は保存するとすぐに更新されます。通知はメッセージ全体を表示し、警告は **ログ** タブに警告アイコンで表示され、テーブルエクスプローラーは列のプロファイルが失敗したときにその旨を表示し、データエディターは空の日付セルを空のまま保持します。列フィルターを有効にしたままデータエディターを保存すると、行の追加、削除、移動の後でも、フィルターで非表示の行が保持されます。ユーザー定義関数のエディターは、変更を許可されているすべてのユーザーに対して、編集可能な状態で開きます。[キャンバスでワークフローを開けない場合](/ja/guides/workflows/advanced-workflows/#キャンバスでワークフローを開けない場合) を参照してください。**テーブル** 一覧からテーブルを削除するとき、`/Periods/{period}/Sales` のように変数パスを介してのみテーブルに到達するステップがあれば一覧表示され、強制した場合にのみそのテーブルが削除されます。[削除](/ja/guides/projects/managing-tables-and-views/#削除) を参照してください。

- **メンバーと接続が正しく動作します。** **ワークスペースメンバーを追加** は、シングルサインオンで作成されたものを含め、すでにアカウントを持つユーザーに対して動作し、そのユーザーが持つプロジェクトロールを下げることはありません。ODBC 接続は、PlaidLink エージェントのマシン上の DSN またはドライバーを通じて接続します。OAuth 資格情報を拒否したプロバイダーは、再入力または再認可を促し、Databricks のサンプルとエクスポートは有効期限が近いトークンを更新し、古いデータベース型の接続も削除できます。**使用箇所** には通知ステップが含まれ、無料のワークスペースは日次、週次、月次のバックアップを保持します。[メンバー管理](/ja/administration/access/member-management/) と [ODBC](/ja/reference/connectors/databases/odbc/) を参照してください。

- **REST API と AI アシスタントのツールが、依頼したとおりに動作します。** メンバー、グループ、スケジュールイベントの部分更新は、指定したフィールドだけを変更するため、一時停止中のイベントは一時停止のままです。指定したステップから実行を開始すると、そこから開始され、テーブルのスナップショットを復元すると、安全用のスナップショットと監査記録が残ります。AI ツールからのドライバーのホワットイフは、モデルが実際に行った配分と一致する場合にのみ回答します。以前はサーバーエラーで失敗していたリクエストは、動作するか、何が問題だったかを説明するようになりました。[配賦の追跡](/ja/integrations/ai-coding-agents/tracing-allocations/) と [スナップショットの復帰または復元](/ja/guides/data/table-snapshots/#スナップショットを巻き戻しまたは復元する) を参照してください。

## セキュリティ

- **AI アシスタントは、ご自身の権限の範囲内で動作します。** アシスタントのデータクエリは、実行前に構造がチェックされ、単一の読み取りクエリだけが実行されます。Microsoft 365 Copilot を含む読み取り専用の AI 接続では、ファイルのエクスポート、ダッシュボード PDF の保存、別のプロジェクトへの行のコピー、REST 接続を介した変更の送信はできません。AI アシスタントによるインポートは、指定したプロジェクトで、ご自身として実行され、会話を続行できるのは開始した本人だけです。アシスタントとテーブル参照には、ロールで非表示になっているテーブル、ステップ、ワークフロー、ディメンションは含まれず、Weave は、開けない失敗したステップについて、名前を出さず件数だけを数えます。[アクセスレベル](/ja/integrations/microsoft-365-copilot/#アクセスレベル)、[ロールで非表示になるもの](/ja/guides/ai-assistant/weave-tab/#ロールで非表示になる内容)、[過去の会話を管理する](/ja/guides/ai-assistant/weave-tab/#過去の会話を管理する) を参照してください。

- **ERP 転記は、統制を回避できません。** 職務分掌がオンの場合、取り消しは、承認が適用される転記レジスターを経由します。コピーまたはインポートされたプロジェクトが転記の権限を引き継ぐことはなくなり、SAP と EBS の転記をエージェントに直接送信することはできず、テスト専用モードの SAP Post ステップには、本番の転記と同じ権限が必要です。これらのチェックなしで Sage Intacct に転記していた非公開のエンドポイントは削除されました。ERP 接続と REST 接続のエラーメッセージには、資格情報が含まれません。[職務分掌](/ja/guides/connections/posting-register/#職務分掌) を参照してください。

- **シークレットは書き込み専用で、接続を誰が使えるかを決めるのは所有者だけです。** ドキュメントアカウントのキー、パスワード、トークンは、保存後は二度と表示されず、アカウントの接続先を変更するにはシークレットの再入力が必要です。ステップ内のパスワードとキーは変数にのみ保持され、すでにステップに入力されていたシークレットは、アーキテクトだけに表示されるプロジェクト変数に移されました。複数行の資格情報は、入力時にマスクされます。接続へのアクセスを誰に許可するかを変更できるのは、接続の所有者またはワークスペース管理者だけです。[保存されたシークレットは書き込み専用](/ja/guides/documents/adding-accounts/#保存されたシークレットは書き込み専用)、[キーは変数に保持される](/ja/reference/workflow-steps/document/encrypt-decrypt-file/#キーは変数に保持する)、[接続を作成して管理する](/ja/guides/connections/create-connection/#セキュリティモデル) を参照してください。

- **使用できないドキュメントアカウントは、引き続きアクセスできません。** ファイルが存在するかどうかのチェック、Parquet、Avro、ORC、Delta ファイルの列の読み取り、**取り込み** でインポートステップの列を入力すること、AI アシスタントによるファイルの検査は、これまでブラウズがそうだったように、アクセス権のないアカウントを拒否するようになりました。

- **ワークスペース管理者を変更できるのは、ワークスペース管理者だけです。** 管理者の編集、無効化、削除、グループの変更、誰かを管理者にすることには、すべてワークスペース管理者が必要です。[ワークスペース管理者を変更する](/ja/administration/access/member-management/#ワークスペース管理者の変更) を参照してください。

- **データ共有は、共有先のプロジェクトのメンバーに対してのみ有効です。** 共有を通じた読み取りには、受け取り側のプロジェクトでのロールが必要で、書き込みには、**書き込み** の共有と、そこでのマネージャーまたはアーキテクトのロールが必要です。[プロジェクト間でデータを共有する](/ja/guides/projects/managing-projects/#プロジェクト間でのデータ共有) を参照してください。

- **復元は、指定した項目にのみ適用されます。** 以前のバージョンを復元すると、項目自体が復元され、権限チェックはその項目に対して行われます。内容が、自身のヘッダーにあるディメンションに属さないディメンションのバックアップファイルは、拒否されます。[バージョン履歴](/ja/guides/projects/managing-projects/#バージョン履歴) を参照してください。

- **テンプレート、インポート、アーカイブは、安全でない内容を拒否します。** エクスポートテンプレートとレポートテンプレートは、与えられたデータだけを読み取るサンドボックスでレンダリングされます。インポートは、自身の設定からロードクエリを構築し、PlaidCloud のアーカイブには決して含まれない内容を持つプロジェクトアーカイブは拒否され、別のプロジェクトのレポートスキーマを共有してしまうプロジェクトスラッグも拒否されます。[テンプレートで使えるもの](/ja/reference/workflow-steps/export/export-templated/#テンプレートで使用できるもの) と [アーカイブの復元](/ja/guides/projects/archive-a-project/#アーカイブの復元) を参照してください。

- **ダッシュボードは、PlaidCloud のサインインとご自身の行アクセスに従います。** ダッシュボードのサムネイルはご自身として描画され、アカウントは PlaidCloud のサインインからのみ取得され、ダッシュボードのインポートは、エクスポートが生成する ZIP ファイルからのみ行えます。[既存のダッシュボードをインポートする](/ja/guides/dashboards/learning-dashboard/#既存のダッシュボードのインポート) を参照してください。

- **ワークフローの実行を開始しても、実行の資格情報が返されなくなりました。**

- **ユーザー定義関数を実行する環境には、PySpark の Java ライブラリが含まれなくなりました。** これらには既知の脆弱性がありました。PySpark の DataFrame と SQL API は引き続き Spark Compute Cluster に到達しますが、`SparkContext` や `RDD` をインポートする関数は失敗するようになりました。[PySpark を使い始める](/ja/integrations/pyspark/getting-started/) を参照してください。

- **添付、復元、変換は、使用できるアカウントのみを読み取ります。** ファイルのメール送信、ファイルからのディメンションまたはテーブルアーカイブの復元、テーブルバンドルの検査またはインポート、テンプレートからの Excel エクスポートの入力、Alteryx ワークフローの変換は、アクセス権のないドキュメントアカウントを拒否するようになりました。ディメンションをドキュメントアカウントにバックアップするには、そのアカウントへの書き込みアクセスが必要です。ワークフローのステップは影響を受けませんが、ファイルをメール送信するステップ、テーブルを復元するステップ、Excel テンプレートに入力するステップは、Personal Temp Drive から読み取れなくなります。

- **エクスポートは、書き込めるアカウントにのみ保存されます。** あらゆる形式でのテーブルまたはクエリのファイルへのエクスポート、テーブルアーカイブ、プロジェクトアーカイブ、テーブルバンドルのエクスポート、プロジェクトからのローカル Python ワークフローの作成、REST レスポンスのファイルとしての保存、Alteryx または Prophecy ワークフローの変換には、保存先のドキュメントアカウントへの書き込みアクセスが必要になりました。クエリのエクスポートでは、そのプロジェクトを使用できるかどうかも確認されます。テーブルバンドルのインポートは、読み取りしかできないアカウントにインポートログを書き込まなくなりました。ワークフローのエクスポートステップは影響を受けませんが、Personal Temp Drive には保存できなくなります。
