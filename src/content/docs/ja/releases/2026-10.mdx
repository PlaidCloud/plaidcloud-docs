## 追加

- **Data Foundation で、ERP データを 1 つの Common Finance Model に統合できます。** Common Finance Model は、複数の ERP システムとインスタンスの ERP データを 1 つのモデルに統合します。勘定科目表、エンティティ、報告通貨がそれぞれ 1 つにまとまります。このモデルを基にしたレポート、メトリック、AI アシスタントはすべて、どの ERP のデータであっても同じ数値を参照します。

  - **ERP から直接取得。** 総勘定元帳、試算表、マスターデータ、予算は、PlaidCloud の ERP 直接接続を通じて取り込まれます。**エンティティ対応表**が各ソースの会社コードを共通のエンティティに対応付け、通貨レートや配賦ドライバーのようにシステムが保持していない情報はファイルで補います。
  - **1 つのモデル、1 つの通貨。** **ロード**がすべてのソースを Common Finance Model に整合させ、報告通貨に換算します。損益計算書は期間の平均レート、貸借対照表は期末レート、資本は取得時レートで換算されます。階層はマスターデータから構築されます。
  - **準備状況の確認。** エンティティと期間ごとにチェックが実行されます。試算表と売上が総勘定元帳と一致しているか、すべての製品、顧客、勘定科目が既知か、通貨が換算できるか、すべてのエンティティがマッピングされているかを確認します。
  - **常に最新に保つ。** **夜間に更新**は毎晩モデルを再ロードします。ファイルが存在しない場合や空の場合は、エラーではなく警告付きで完了します。

  **Enterprise Profitability** などのテンプレートからプロジェクトを開始すると、プロジェクトの **Foundation** タブで、ERP の接続からロード済みでチェック済みのモデルまで進められます。[Data Foundation: Common Finance Model](/ja/guides/projects/data-foundation/)を参照してください。

- **PlaidCloud を独自の Snowflake または Databricks ウェアハウスで実行できます。** ワークスペース管理者はユーザーメニューの**自分のウェアハウスを使用する**を開き、生成されたセットアップスクリプトを自分のアカウントで実行します。このスクリプトは、上限付きのウェアハウスと PlaidCloud 用のサービス ID を作成し、既存のウェアハウスには一切触れません。**接続を確認**では、問題とその対処方法が平易な言葉で説明されます。以降、新しいプロジェクトのテーブルの保存とワークフローの実行はお客様のウェアハウスで行われ、ウェアハウスを削除すると、そこへの PlaidCloud のアクセス権が取り消されます。[独自のウェアハウスを使用する](/ja/guides/connections/external-lakehouse/)を参照してください。

  - **Snowflake または Databricks でサインイン。** 認証情報を貼り付ける代わりに、管理者はサインインしてウェアハウスを接続できます。ダッシュボードは各ユーザー自身のウェアハウス権限で実行され、ワークフローは指定したデータロールのみを持つサービス ID として実行されます。[Snowflake または Databricks でサインインする](/ja/guides/connections/external-lakehouse/#snowflake-または-databricks-でサインインする)を参照してください。
  - **複数を接続。** **ウェアハウスの管理**で**デフォルトに設定**を選ぶと、新しいプロジェクトが別のウェアハウスに割り当てられます。既存のプロジェクトは元のウェアハウスのままです。[ウェアハウスの管理](/ja/guides/connections/external-lakehouse/#ウェアハウスを管理する)を参照してください。
  - **実行のコストを確認。** 実行履歴には、各実行のクレジットまたは DBU を示す**ウェアハウスコスト**列が表示されます。[実行ごとのウェアハウスコスト](/ja/guides/connections/external-lakehouse/#実行ごとのウェアハウスコスト)を参照してください。
  - **ガバナンスはそのまま維持。** 説明はウェアハウス自身のカタログに書き込まれ、PlaidCloud がテーブルを置換、再作成、クローンしても、Snowflake の行アクセスポリシーとマスキングポリシー、Databricks の行フィルターと列マスクはそのまま適用されます。[ポリシーと説明の引き継ぎ](/ja/guides/connections/external-lakehouse/#ポリシーと説明が引き継がれる)を参照してください。

- **Panel アプリを PlaidCloud 内で構築、公開、ブランディングできます。**

  - **Panel Studio。** **マイPanelアプリ**の最初のボタンである**新しい Studio アプリ**では、空のアプリ、テーブル、ビュー、別の Studio アプリ、またはアプリギャラリーから開始できます。**テーブル**タブの **Panel アプリを作成**では、選択したテーブルから開始できます。**Studio で開く**を選ぶと、アプリのファイルがエディターで開きます。下書きを保存し、非公開のビルドを**プレビュー**し、ライブアプリを**公開**できます。ビルドエラーは該当するファイルと行を示し、**履歴**から公開済みの任意のバージョンを復元でき、**インサイト**ではビュー数、読み込み時間、エラーを確認できます。**Weave に質問**はアプリのファイルとビルドの状態を把握しており、コードを保存する前に差分をすべて表示して承認を求めます。[Panel Studio](/ja/guides/panel-apps/studio/)と [Weave で Panel アプリを構築する](/ja/guides/panel-apps/build-with-weave/)を参照してください。
  - **PlaidCloud らしい外観のアプリキット。** このキットで構築したアプリは、ライトとダークの両方で PlaidCloud の配色、書体、余白を使用します。キットにはナビゲーション、フィルター、主要数値カード、チャート、フォーム、コマンドパレット、ワークフローを実行するボタン、印刷、サーバー側で並べ替えと合計を行い、列ごとに数値を書式設定し、1 画面分の行ずつ読み込むデータグリッドが含まれるため、どのサイズのテーブルでも扱えます。アプリは、ログイン中の閲覧者としてテーブルを読み取り、行セキュリティが適用されます。[Panel アプリキット](/ja/guides/panel-apps/app-kit/)、[DataGrid](/ja/guides/panel-apps/app-kit/#datagrid)、[Panel アプリのデータ API](/ja/guides/panel-apps/data-api/)を参照してください。
  - **アラートとダイジェスト。** プロジェクトテーブルの数値が上限を超えたときに、プッシュ通知、メール、Slack、Microsoft Teams で通知を受け取れます。最大 10 個の数値を毎日または毎週まとめたダイジェストも受け取れます。いずれも常に自分の行アクセスの範囲で動作します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
  - **プロジェクト、ブランディング、共有。** アプリをプロジェクトに割り当てると、プロジェクトのメンバーではないが開ける人を確認するレビューが行われます。プロジェクトの**ホーム**タブの**ブランディングを編集**で、プロジェクト内のすべてのアプリに適用される 8 つのブランドカラーとロゴを設定できます。**ギャラリー…** ボタンは、プロジェクトに属する Studio アプリを、そのプロジェクトを閲覧できる全員向けのテンプレートとして掲載し、**ギャラリーから外す**で掲載を解除します。[プロジェクトのブランディングとアプリプロジェクト](/ja/guides/panel-apps/branding/)と[アプリギャラリー](/ja/guides/panel-apps/gallery/)を参照してください。

- **ビジネス数値の計算方法を一度合意すれば、すべての AI の回答がその計算を使います。** プロジェクトのアーキテクトが*純収益*や*人員数*などの**メトリック**を定義します。定義する内容は、ソーステーブル、行の集計方法、常にカウントする行、結合するルックアップテーブル、内訳に使える列です。定義は保存した時点で有効になり、存在しないテーブルや列を指定した保存、またはキーごとに複数の行があるルックアップを含む保存は拒否されます。AI アシスタントにメトリックを名前または同義語で尋ねると、数値は定義に従って自分の行アクセスの範囲で計算され、アシスタント自身が算出することはありません。定義は AI アシスタントまたは REST API で管理します。[メトリック定義](/ja/integrations/ai-coding-agents/metric-definitions/)を参照してください。

  - **派生メトリック。** 1 人あたりの純収益のような 2 つのメトリックの比率、合計、差、またはメトリックに固定係数を掛けたものを定義できます。[他のメトリックから派生させる](/ja/integrations/ai-coding-agents/metric-definitions/#他のメトリックから派生させる)を参照してください。
  - **比較、ランキング、構成比。** 予算との差異、同順位を含む上位または下位 N 件、各行の合計に占める構成比を尋ねられます。[比較、ランキング、構成比](/ja/integrations/ai-coding-agents/metric-definitions/#比較ランキング構成比)を参照してください。
  - **お客様の言葉で、合意した値を。** 内訳の列をディメンションにバインドすると、*EMEA* のような言葉がその配下のすべてのリージョンになります。どれにも一致しない言葉や、複数のメンバーに一致する言葉は、推測されることなく、確認のための候補として返されます。[メトリックについて尋ねる](/ja/integrations/ai-coding-agents/metric-definitions/#メトリックについて質問する)を参照してください。
  - **会計時間。** メトリックの行が会計カレンダーのどこに位置するかを指定すると、会計期間、年初来、前年比、前期比を尋ねられます。[時間経過で比較する](/ja/integrations/ai-coding-agents/metric-definitions/#時間の経過に沿って比較する)を参照してください。

  PlaidCloud 独自の AI アシスタントは、ビジネス数値にまずメトリックで答え、数値を専用のカードに ✓ 付きで表示します。この印がアシスタント自身のテキストに付くことはありません。[ビジネス数値](/ja/guides/ai-assistant/weave-tab/#ビジネス数値)と[メトリックからの数値](/ja/guides/ai-assistant/weave-tab/#メトリックからの数値)を参照してください。

- **クローズの準備ができているかを Weave に尋ねたり、2 つのテーブルが一致するかを確認したりできます。** どちらも AI は使用しません。

  - **クローズの準備状況。** クローズ、予測、またはその他の期限が依存するワークフローを、プロジェクトの **Weave** タブの**準備状況**から**準備状況セット**として指定します。1 つのチェックリストが「13 件中 11 件が準備完了、1 件が未準備、1 件がチェックできませんでした」のようにまとめて答えます。ワークフローが準備完了となるのは、Weave が実行できたすべてのチェックに合格した場合のみです。Weave が判断できなかった項目は、準備完了とは扱われず、理由とともに**チェックできませんでした**と表示されます。比較できる過去の履歴が少ない最後の実行（新しいワークフローなど）は、通常どおりに扱われます。メールの送信やファイルのエクスポートのようにテーブルを書き込まないステップには、チェック対象の行や空の値がないため、ワークフローが**チェックできませんでした**のままになることはありません。[クローズ前に準備状況を確認する](/ja/guides/ai-assistant/weave-readiness/)を参照してください。
  - **照合。** 2 つのテーブル、または 1 つのテーブルの 2 つの期間を、対応付けたキー列で行ごとに比較します。Weave は、一致するかどうか、差がどれだけあるか、どの行が異なるかを示し、全体を読み取れなかったデータについて「一致」とは言いません。各照合は、使用される前に別のアーキテクトが承認します。[2 つのテーブルが一致するか確認する](/ja/guides/ai-assistant/weave-reconciliation/)を参照してください。

- **Weave は問題になりうる事象をより多く監視し、実行の合間にも通知します。** Weave のチェックに AI は使いません。すべての検出事項と、AI アシスタントのすべての回答には**Weaveが把握する方法**パネルがあります。検出事項ではチェック内容とその根拠となる値、回答ではアシスタントが実行した各クエリと、**一致**、**不一致**、**未確認**のいずれかが付いた各文が表示されます。[Weave が現在確認する内容](/ja/guides/ai-assistant/weave-findings/#現在weaveがチェックする内容)、[Weave が把握する方法](/ja/guides/ai-assistant/weave-findings/#weaveが把握する方法)、[AI アシスタントでの Weave の把握方法](/ja/guides/ai-assistant/weave-tab/#weaveが把握する方法)を参照してください。

  - **予定どおりに書き込まれるテーブル。** スケジュールの期限を過ぎても書き込まれていないテーブルや、テーブルの詳細の**鮮度**で設定した 1 時間から 180 日の鮮度のしきい値より長く書き込まれていないテーブルを Weave が報告します。
  - **古い、または壊れた入力。** あるワークフローが、別のワークフローが書き込んだあとのテーブルを読み取っている場合や、失敗した実行に依存するすべてのワークフローとダッシュボード（チャートが SQL データセットに基づくダッシュボードを含む）を Weave が報告します。**依存関係の同期**は、ステップと、それが読み取るテーブルとの間に不足しているコネクターを追加します。[依存関係の同期](/ja/guides/workflows/sync-dependencies/)を参照してください。
  - **形が変わったデータ。** 実行後に値の分布が大きく変わった小数列、行が複数回書き込まれるようになった結合、列の型に変換できずに抽出ステップが空のままにした値、ファイルが見つからなかったインポートを Weave が報告します。直近の期間が通常から大きく外れているメトリックも、その要因となった項目を挙げて報告します。Weave は月末や曜日のパターンを考慮するため、月末に常に負荷が高いロードは報告されません。[異常なメトリック合計](/ja/guides/ai-assistant/weave-metric-insights/)を参照してください。
  - **遅くなった実行。** Weave は、実行を遅くしたステップを挙げ、新しい実行が古い実行より少なくとも 4 分の 1 長くかかっているワークフローについて、時間が最も増えたステップを挙げて報告します。
  - **実行の合間の通知。** 1 時間ごとのチェックで、各問題の担当者にアプリ内メッセージで 1 回通知します。ヘッダーの **Weave** ボタンには、すべてのプロジェクトで未読の問題の数が表示されます。[実行の合間に通知を受け取る](/ja/guides/ai-assistant/weave-findings/#実行の合間の通知)と[ヘッダーの Weave ボタン](/ja/guides/ai-assistant/weave-tab/#ヘッダーのweaveボタン)を参照してください。
  - **担当者、コメント、想定内の警告。** 各検出事項には担当者がいて、デフォルトではそのワークフローを最後に実行した人です。**割り当て**で別の人に引き継ぎ、コメントで進捗を記録し、**チーム**ビューで誰が何を担当しているかを確認できます。アーキテクトは警告を、理由と終了日を付けて**これは想定内**としてマークできます。[検出事項に担当者を割り当てる](/ja/guides/ai-assistant/weave-tab/#検出事項に担当者を設定する)と[検出事項を想定内としてマークする](/ja/guides/ai-assistant/weave-tab/#検出事項を想定内としてマークする)を参照してください。

- **修正アシスタントがエラーを説明し、カードで承認できる変更を提案し、ステップを再実行し、修正を元に戻せます。** 存在しない列、空の必須設定、データベースが読み取れない SQL、型の異なる値といった、最も一般的な障害では、最初の返信で一般的な原因と修正方法が説明されます。提案された変更は、ステップが失敗した理由と、変更される各設定の現在値（赤）と新しい値（緑）を示すカードとして表示されます。**承認**で適用され、アシスタントはステップの再実行を提案し、新たな失敗があれば診断します。**Weave** タブの検出事項にある**修正**を選ぶと、その問題についてアシスタントが開きます。**元に戻す**でステップの以前の設定を復元でき、**元に戻して実行**で出力を再構築できます。[AI でワークフローのエラーを修正する](/ja/guides/ai-assistant/fixing-workflow-errors/)、[AI アシスタントで検出事項を修正する](/ja/guides/ai-assistant/weave-tab/#aiアシスタントで検出事項を修正する)、[修正を元に戻す](/ja/guides/ai-assistant/fixing-workflow-errors/#修正を元に戻す)を参照してください。

- **プロジェクトで Weave が行ったすべてを確認し、監査人向けにエクスポートできます。** プロジェクトの **Weave** タブの**アクティビティ**には、Weave が見つけて後に検出しなくなった問題、AI アシスタントが提案したすべての変更、依頼した人と承認または却下した人、置き換えられた内容と書き込まれた内容、結果が一覧表示されます。Weave は変更を行う前に承認を記録し、記録できない変更は行いません。**CSVのエクスポート**または**PDFのエクスポート**で、期間を監査証跡として保存でき、エントリーの編集や削除はできません。**サマリー**では、見つかって解決した問題、承認された変更、取り消された件数など、1 か月の状況を一目で確認できます。ワークスペース管理者は、**ワークスペースサマリー…** ボタンで、すべてのプロジェクトについて同じ内容を確認できます。[Weave のアクティビティ履歴](/ja/guides/ai-assistant/weave-activity/)と [Weave の月次サマリー](/ja/guides/ai-assistant/weave-monthly-summary/)を参照してください。

- **保存する前に、ステップが何をするか、変更が何に影響するかを確認できます。** これらはすべてプロジェクトの保存済み設定から構築され、AI は使用されません。ロールで非表示になっている項目は、名前を挙げずに件数のみで示されます。

  - **すべてのテーブル、ステップ、ワークフローのドキュメント。** 詳細パネルの**ドキュメント**セクションには、ステップの動作とワークフローのステップの順序が記載され、テーブルを読み書きする対象は Weave と AI アシスタントが参照できます。テーブルの詳細パネルには、その**列**が型と説明とともに一覧表示されます。**引き継ぎパックをダウンロード**では、メトリック定義と配賦モデルを含むプロジェクト全体を 1 つのドキュメントとして保存できます。[テーブル、ステップ、ワークフローのドキュメント](/ja/guides/ai-assistant/weave-documentation/)を参照してください。
  - **変更が何に影響するか。** **保存**の上に、そのステップが書き込む内容を読み取る下流のステップの数が「このステップの変更は、2 つのワークフローの 8 個の下流ステップに影響します」のように表示され、**ステップを表示**でそれらを一覧できます。[変更の影響](/ja/guides/ai-assistant/impact-preview/)を参照してください。
  - **保存が拒否される内容。** **保存**の上のバーに、編集中にステップのチェックが実行され、各問題に**移動**が表示されます。式エディターは、入力中に式をチェックします。[保存が拒否される内容](/ja/guides/ai-assistant/check-while-you-edit/)を参照してください。
  - **1 つのワークフローのレビュー。** ワークフローのキャンバスまたは**ステップ**グリッドの**チェック**は、Weave のチェックに加えて、配賦と行レベルセキュリティのチェックを実行します。[1 つのワークフローをレビューする](/ja/guides/ai-assistant/weave-findings/#ひとつのワークフローのレビュー)を参照してください。

- **ワークスペースで Weave の AI 機能を個別にオフにできます。** ワークスペース管理者は、ヘッダーの **Weave** ボタンの **AI機能…** ボタンから、Weave チャット、修正アシスタント、インポートとエクスポートのアシスタント、式アシスタント、説明からSQLを生成、ワークフローレビューのサマリー、スターターチャートを、それぞれ個別にオンまたはオフにできます。管理者がオフにするまではすべてオンで、Weave のチェックと検出事項は常にオンのままです。各変更はセキュリティログに記録されます。[AI機能](/ja/guides/ai-assistant/weave-ai-features/)を参照してください。

- **配賦分割ステップでドライバーのホワットイフを試せます。** ステップを右クリックして**ホワットイフ…** ボタンを選ぶと、異なるドライバー値、ドライバーテーブルの別の列、または同じキーを持つ別のテーブルの数値列を使った場合に、コストがどう配分されるかを確認できます。最大 10 件のシナリオを比較でき、それぞれがステップの最後の実行に基づいて 1 セント単位まで計算され、誰が得をし、誰が損をし、どの明細に何も配賦されないかが分かります。**内訳の基準:** フィールドでは、各メンバーの変化がどの勘定科目やその他の値に及ぶかを確認でき、**後続のステップ**では、そのシナリオを配賦の出力から作られるテーブルに反映します。再実行は行われず、データも変更されません。[ドライバーのホワットイフを試す](/ja/guides/allocations/results/driver-what-if/)を参照してください。

- **プロジェクトの Lakehouse v2 への移行は、準備状況の確認から取り消しまでガイドされます。** **移行準備状況の確認**は、テーブル、ビュー、ステップ、ダッシュボード、データ共有、容量を、問題なし、要確認、ブロックのいずれかで報告し、すべての検出事項に平易な説明を付けます。**v2で試す…** ボタンは、スケジュールをオフにし、ERP 転記をシミュレートモードにした非公開の試用コピーを作成します。移行は今すぐ、または指定した時刻に開始できます。実行中はプロジェクトのスケジュールが一時停止され、完了後に復元されます。完了時にはメッセージとメールで通知されます。**変更内容…** ボタンは各テーブルの結果を報告し、**移行を元に戻す…** ボタンは、取り消し可能期間内であればプロジェクトを Lakehouse v1 に戻します。[プロジェクトを Lakehouse v2 に移行する](/ja/guides/data/migrate-project-lakehouse/)を参照してください。

- **プロジェクトをコピーするとデータもコピーされ、コピーする量を選べます。** **プロジェクトをコピー**では、サイズと警告のレビューを経て、1 つの Lakehouse 内、または 1 つの Lakehouse から別の Lakehouse へ、**構造のみ**、**全データ**、**サンプル**のいずれかを選べます。データ付きのコピーは、作成した人だけが閲覧できます。**コピー結果**には各テーブルの結果が一覧表示され、**失敗したテーブルを再試行**ではそれらのみをコピーし、**インポートまたはコピーの結果を表示**で後からウィンドウを再度開けます。センサーとスケジュールイベントはコピー先でオフの状態で作成されるため、そこでオンにするまで何も実行されません。[プロジェクトのコピー](/ja/guides/projects/managing-projects/#プロジェクトのコピー)を参照してください。

- **ストレージを確認し、保持する履歴の量を管理できます。** ワークスペースの**ストレージ**ウィンドウには、含まれる分、予約分、オンデマンドの帯を持つメーター、請求に使われる月次の予測平均、各プロジェクトの現在のデータと履歴が表示されます。**プロジェクト**一覧には**サイズ**列があり、各プロジェクトの**テーブル**タブには**現在のデータ**、**履歴**、**注記**の各列と、スペースを空ける方法を提案する**ストレージ**ボタンがあります。タイムトラベルのデフォルトは 1 日です。プロジェクトのデフォルトを 1 日から 90 日の範囲で設定でき、任意のテーブルで延ばせます。テーブルの設定より古い履歴は削除されて復元できないため、より長く保持する必要があるものについては設定を引き上げてください。サイズは履歴を含め実際に保存されている量を反映し、設定より古い履歴は毎晩クリーンアップされるため、使用量はその後の数日で減少します。**クリーンアップ待ちの削除済みテーブル**の行には、削除されたテーブルのうち、まだ解放中のストレージが表示されます。[ストレージの管理](/ja/guides/projects/managing-storage/)と[履歴とタイムトラベル](/ja/guides/projects/managing-storage/#履歴とタイムトラベル)を参照してください。

- **各ダッシュボードを閲覧できるセキュリティグループを、1 つのダイアログで選べます。** **閲覧できるユーザー**では、ダッシュボードを**プロジェクトの全員**、**特定のグループ**、**所有者のみ (下書き)** の各オプションのいずれかに設定でき、アクセス権を得る人と失う人のプレビューも表示されます。ダッシュボードへのアクセスをブロックされた人には、所有者にメールを送る**Request access**ページが表示されます。ワークスペース管理者は**ダッシュボードアクセスレビュー**を利用でき、プロジェクトの**デフォルトのダッシュボード対象者**は新しいダッシュボードに適用されます。対象者の設定はダッシュボードを非表示にしますが、チャートのデータはプロジェクトのアクセスと行アクセスに従います。[ダッシュボードを閲覧できるユーザーを制御する](/ja/guides/dashboards/control-who-can-see-a-dashboard/)を参照してください。

- **すでに使っているステップのオプションが増えました。** すべてのオプションは、ステップのフォームのフィールドとして用意されています。

  - **エクスポート。** CSV と Excel のエクスポートは既存のファイルに追記でき、ほとんどのエクスポートは、すでにあるファイルを置き換える代わりに停止でき、CSV、Excel、JSON、SQL のエクスポートは行を並べ替えられます。[Export to Excel ステップ](/ja/reference/workflow-steps/export/export-to-excel/#分割)は、列の値ごとにシートまたはファイルを書き出せ、[Export to CSV ステップ](/ja/reference/workflow-steps/export/export-to-csv/)は、Spark と同じ方法で引用符をエスケープまたは省略できます。
  - **テーブルとフロー。** [Table Extract ステップ](/ja/reference/workflow-steps/tables/table-extract/)と各種結合は、実行時に名前が決まる列を引き継げるため、ピボットの後のステップに列リストは不要です。[テーブル: 和集合（すべて）](/ja/reference/workflow-steps/tables/table-union-all/#列の照合)は、位置でソースを積み重ねられます。ステップは、テーブルが存在するかどうかに応じて実行できます（[テーブル存在条件](/ja/guides/workflows/step-conditions/#テーブル存在の条件)）。[Workflow Loop ステップ](/ja/reference/workflow-steps/workflow-control/workflow-loop/#反復が失敗した場合)は、失敗した反復を越えて続行でき、[待機](/ja/reference/workflow-steps/general/wait/#時刻またはファイルの待機)は、時刻またはファイルの変更を待機できます。
  - **通知、AI、リモート SQL。** [Notify Via Email ステップ](/ja/reference/workflow-steps/notifications/notify-via-email/)には Cc、Bcc、Reply-To が追加され、ドライバーテーブルの各行にそれぞれ専用のメールを送信できます。[Text: NLP (AI) ステップ](/ja/reference/workflow-steps/text-documents/nlp-ai/)は埋め込みを書き込め、失敗した各呼び出しを報告します。[リモート実行: SQL](/ja/reference/workflow-steps/agent/agent-remote-execution-of-sql/#行ごとに1回ステートメントを実行する)は、ストアドプロシージャなどのステートメントを行ごとに 1 回実行できます。

- **REST リクエストのフォームが、リクエストの構築と確認を支援します。** 大規模なエンドポイントカタログをフィルターしたり、Postman コレクション、OpenAPI 仕様、HAR ファイルを貼り付けたりドロップしたりできます。ヘッダーとパラメーターは、重複、名前の入力ミス、平文で入力されたシークレットがチェックされ、テストリクエストでは整形されたレスポンスと推奨される項目パスが表示されます。このステップには、ページ番号、カーソル、Link ヘッダーによるページング、プロキシ、Digest 認証と NTLM 認証によるサインイン、SOAP 呼び出し、小数のリクエストレート、実行中のジョブのポーリング、各エラーを資格情報をマスクした行として保持する生のレスポンスモードが追加されています。POST、PUT、PATCH はレート制限の後に再試行されますが、サーバーエラーの後には再試行されません。[REST リクエストステップ](/ja/guides/workflows/rest-request-step/)と [RESTリクエスト](/ja/reference/workflow-steps/general/rest-request/)を参照してください。

- **列、値、または使用しているワークフローから、任意のテーブルを見つけられます。** **テーブル**タブには、**ワークフロー別**フォルダー、一致した各列に対してそのテーブルへ入力されるテーブルと出力先のテーブルを示す**列ツリー**を備えた列検索、そして入力した値を保持するテーブルと列を、すでに開ける行の範囲で一覧表示し、結果をテーブルエクスプローラーで開く**データ内の値を検索… (低速)** 機能があります。**テーブルの詳細**には、テーブルの**公開名**がコピーボタン付きで表示され、Snowflake または Databricks のウェアハウスでは、削除ウィンドウにテーブルが最後に読み取られた日時と読み取った人が表示されます。ドキュメントアカウントでは、**使用箇所**にアカウントを使用するすべてのステップ、ワークフロー、プロジェクトのデフォルトが一覧表示され、**参照先を変更...** ボタンはプレビューの後にそれらを別のアカウントに移します。[テーブルを探す](/ja/guides/projects/managing-tables-and-views/#テーブルの検索)、[値を検索する](/ja/guides/projects/managing-tables-and-views/#値の検索)、[最後の読み取り](/ja/guides/projects/managing-tables-and-views/#最終読み取り)、[ドキュメントアカウントの使用箇所と参照先の変更](/ja/guides/documents/account-management/document-account-used-by/)を参照してください。

- **CSV を任意のプロジェクトのテーブルに変換し、概要をひと目で確認できます。** プロジェクトの**テーブル**一覧に CSV をドロップするか、**新規** > **CSVファイルからテーブルを作成**を選ぶと、PlaidCloud が CSV を新しいテーブルとしてインポートします。**新規** > **CSVファイルからプロジェクト**を選ぶと、CSV からプロジェクトを作成できます。**データの概要**には、行数、各列の型、空の値と異なる値の割合、スターターチャートが表示され、スターターダッシュボードもワンクリックで作成できます。[CSV ファイルをインポートする](/ja/guides/projects/managing-tables-and-views/#csvファイルのインポート)と [独自の CSV で始める](/ja/get-started/quickstart/#自分の-csv-から始める)を参照してください。

- **高度なワークフローのキャンバスを、より直接的に配置、編集できます。** **Cmd** または **Ctrl** を押しながらステップをドラッグして、コンテナーの内外に移動でき、実行コンテナーの出力は**出力ポート**から接続できます。**配置**メニューは、順序を保ち、メモをステップとともに移動しながら、ステップの整理、整列、均等配置、スナップを行い、それぞれが 1 回の**元に戻す**で取り消せます。空白部分を右クリックすると、クリックした位置にステップをコピーして貼り付けられます。選択したステップの**ステップを作成**は、そのステップが書き込むテーブルから結合や抽出を開始し、未保存の変更があるウィンドウは、破棄する前に確認します。ステップの入力または出力にある目のアイコンは、まさにそのテーブルのプレビューを開きます。[コンテナー](/ja/guides/workflows/advanced-workflows/#コンテナー)、[キャンバスの配置](/ja/guides/workflows/advanced-workflows/#キャンバスを配置する)、[高度なキャンバスでのコピーと貼り付け](/ja/guides/workflows/copy-paste-steps/#高度なキャンバスでのコピーと貼り付け)、[ステップを作成する](/ja/guides/workflows/workflow-explorer/#ステップの作成)を参照してください。

- **高度なワークフローを最適化して、より高速に実行できます。** ワークフローを右クリックして**最適化…** ボタンを選ぶと、何かが変更される前に変更内容を確認できます。**Rebuild dependencies from data lineage** は、各ステップを、そのステップが使用するテーブルを書き込むステップにのみ接続するため、独立したステップが並列で実行されます。**Merge** は、データ抽出ステップの連鎖を 1 つにまとめ、両方のバージョンが現在のデータで同一の結果になった場合にのみ適用されます。ウィンドウには短縮される時間と、最適化できなかった各ステップがその理由とともに表示され、**最適化を元に戻す...** ボタンでワークフローを復元できます。[ワークフローを最適化する](/ja/guides/workflows/optimize-a-workflow/)を参照してください。

- **結合を実行する前に、結合キーを正しく設定できます。** **結合マップ**の**自動判定**は、同じ 2 つのテーブルを結合する別のステップのキー、次にメトリック、次にテーブルのキー列、次に一致する名前の順に使用し、どれを使ったかを示します。**キーを確認**は、結合先のテーブルで繰り返されるキー値の数を数えます。繰り返されると行数が増える可能性があります。**ソースを検査**でステップの列が入力されるとき、`customer_id` のような識別子の列は、**合計**ではなく**グループ化**から始まります。[内部結合](/ja/reference/workflow-steps/tables/table-inner-join/#キーを確認)を参照してください。

- **AI アシスタントと Microsoft 365 Copilot が、データについてより多くを把握し、より多くのことをこなせます。**

  - **各分析パスと列のガイダンス。** 各分析パスには、常に適用されるフィルター、会計カレンダー、業務用語のための**プロンプトガイダンス**があり、最大 1,000 文字まで入力できます。列のメモは、テーブルの列とともにアシスタントと LLM ステップに渡されるため、コードやフラグは意図どおりに解釈されます。[AI アシスタントに役立つパスにする](/ja/integrations/ai-coding-agents/analysis-paths/#aiアシスタントに役立つパスにする)を参照してください。
  - **Copilot の機能拡張。** Microsoft 365 Copilot の PlaidCloud エージェントは、CSV、Excel、PowerPoint、Word のファイルを作成し、ビジネス数値にメトリックから回答し、内訳をテーブル全体で集計し、配賦の仕組みを説明します。管理者は更新されたパッケージをダウンロードして、Teams 管理センターで更新します。[Microsoft 365 Copilot](/ja/integrations/microsoft-365-copilot/)を参照してください。
  - **1 回の呼び出しでできることが増えました。** アシスタントは、行アクセスを先に適用したうえで、サーバー上でテーブルをグループ化して合計でき、PlaidCloud のドキュメントを検索して読み取れ、OneDrive と SharePoint を含む完全に構成されたドキュメントアカウントを書き込み専用の資格情報で作成でき、ラベルを追加するだけでなく削除でき、PlaidCloud で表示されるビューを扱えます。[分析パス](/ja/integrations/ai-coding-agents/analysis-paths/#mcp経由での使用)と [AI エージェントを始める](/ja/integrations/ai-coding-agents/getting-started/)を参照してください。

## 変更

- **1 つの Weave タブに、検出事項と Weave AI のチャットがまとまりました。** チャットは **Weave** タブ内のタブとして、**検出事項**の後に表示されます。各検出事項は、独自の**修正**、**移動**、**既読にする**ボタンを持つカードで、破線のカードは Weave がチェックできなかった項目を示し、チップで対応が必要なものに絞り込めます。式に関する検出事項は、エラーの場所を示し、式自体は**Weaveが把握する方法**に表示されます。Weave は、実行が終わったときに各問題を 1 回だけ通知し、1 つのプロジェクトに関するメッセージは積み重ならずに 1 つにまとまります。Weave は変更があった部分のみを再チェックするため、大規模なプロジェクトでもタブがすばやく開きます。ワークフロー一覧の Weave 列は削除されました。[Weave タブ](/ja/guides/ai-assistant/weave-tab/)と[実行終了時の通知](/ja/guides/ai-assistant/weave-findings/#実行終了時の通知)を参照してください。

- **Ctrl/Cmd-K で、どの画面からでもコマンドパレットを開けます。** 入力前には、最近開いたものと実行できる操作が一覧表示されます。ホーム、プロジェクト、ダッシュボード、ドキュメントへの移動、ライトとダークの切り替え、AI の接続、ヘルプなどです。入力すると両方の一覧が絞り込まれ、2 文字以上で、プロジェクト、ワークフロー、テーブル、ダッシュボード、Panel アプリも検索されます。[検索とコマンド](/ja/guides/launcher/#検索とコマンド)を参照してください。

- **ステップの問題は、実行時ではなく保存時に検出されます。** 実行が失敗する設定や誤った結果になる設定のステップを保存すると、何を変更すべきかを示すメッセージとともに拒否されます。各ステップのリファレンスページに、チェック内容が記載されています。マッピングされたソース列が、ステップまたはそのソーステーブルに存在しなくなった場合は赤で示され、保存すると、**すべて削除して保存**、**このまま保存**、**キャンセル**を選べるダイアログが開きます。結合、ルックアップ、空間ステップは、そのような行を自動的に削除せず、そのまま残します。未定義の変数を使用する式は変数名を示し、実行時に拒否されたステップは理由を平易な言葉で説明します。[一覧にないソース列](/ja/reference/workflow-steps/tables/table-extract/#一覧になくなったソース列)、[ソーステーブルにない列](/ja/reference/workflow-steps/tables/table-extract/#ソーステーブルに存在しない列)、[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。

- **ソースが存在しない、または空であってもエラーにはなりません。** ファイルが存在しない、または空のファイルインポートは、パスを示す警告付きで完了し、ターゲットテーブルを宣言された列のまま空にするため、後続のステップは 0 行を読み取ります。存在しない、または空のフォルダーに対するドキュメントステップは「処理対象がありません」と報告され、ワークフローは続行されます。リモートファイルのステップは、存在しないパスでは警告を出し、安全でないパスは拒否します。ファイルが存在しないことのチェックは、OneDrive、SharePoint、SFTP で動作します。**レポート: バッチ生成**は、バッチテーブルが空の場合、警告付きで完了し、レポートを生成しません。[インポートステップ](/ja/reference/workflow-steps/import/)、[ドキュメントワークフローステップ](/ja/reference/workflow-steps/document/)、[ドキュメントパス条件](/ja/guides/workflows/step-conditions/#ドキュメントパスの条件)を参照してください。

- **大規模なワークフローが安定して実行され、停止でインポートとエクスポートもキャンセルされます。** PlaidCloud が混み合っているときは、ステップは失敗せずに空き容量を待機し、ステップがキューに溜まると容量が追加されます。外部データベーステーブルのインポートは、最大 10 テーブルを同時に実行します。ステップを実行しているサーバーが失われた場合、出力を置き換えるステップは自動的に再実行され、安全に繰り返せないステップは*中断*のメッセージとともに 1 回だけ失敗します。**停止**は実行中のインポートとエクスポートのジョブをキャンセルし、停止された実行は停止済みと報告されます。[中断されたステップ](/ja/guides/workflows/run-a-workflow/#中断されたステップ)と[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)を参照してください。

- **すべての Lakehouse で、保存と計算が同じ方法になります。** CSVのインポート、XMLのインポート、Import Table Archive ステップの空のフィールドは null としてロードされるため、後続のステップで `= ''` や `= 0` をテストしている場合は、代わりに null をテストする必要があります。`cast(x, Float)` はどこでも 64 ビットなので、大きな金額も桁が保たれ、PlaidCloud が作成する Float 列は倍精度になります。JSON 列、**Table: Delete Rows**、集計を行う条件は、すべての Lakehouse で動作します。ソルバー、予測、および pandas で実行される Pivot と Allocation Split ステップのように、独自の結果を構築するステップは、それらを型付きデータとして、はるかに高速にロードします。テーブルエクスプローラーは、数値列の最小値、最大値、平均、合計、標準偏差、分散を表示します。[Float へのキャスト](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#floatへのキャスト)と[列データと一意のカウント](/ja/guides/data/table-explorer/#列のデータと一意な値の数)を参照してください。

- **ファイルのエクスポートで型が保持されます。** Parquet ファイルは整数列を整数のまま保持し、タイムスタンプをマイクロ秒で保存し、タイムゾーンを UTC と表記します。Avro ファイルは日付、タイムスタンプ、ブール値の型を保持し、単一テーブルの Avro エクスポートはエクスポート名で命名されます。Parquet エクスポートで複数のファイルを選択すると、Parquet は 1 つのファイルに書き込むというメッセージとともに停止します。非常に大きな Parquet、ORC、JSON のエクスポートは、行を読み取りながら書き込まれるため、メモリ不足にならなくなり、Parquet は選択した圧縮を使用します。バージョン 1.2.33 以降の PlaidLink エージェントは、エクスポートされたテーブルを Parquet ファイルとして受信します。[Export to Parquet ステップ](/ja/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro ステップ](/ja/reference/workflow-steps/export/export-to-avro/)、[データがエージェントに届く仕組み](/ja/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#データがエージェントに届く仕組み)を参照してください。

- **ERP 転記は各スケジュールのモードに従い、不確かな応答は確認のために保留されます。** スケジュールイベントは、プロジェクトの設定を上限として、**本番**、**シミュレート**、**オフ**のいずれかの独自の転記モードを保持し、**選択したイベントを実行**は各イベントのモードを使用します。タイムアウトやサーバーエラーなど、PlaidCloud が確認できない ERP の応答は、却下として記録されず、保留中として保持され、転記を 2 回取り消すことはできません。転記レジスターには **reversal outstanding** の転記が一覧表示され、アーキテクトはプロジェクトのホームページの**ERP書き込み承認**で、プロジェクトに転記を許可します。[ERP 転記モード](/ja/administration/scheduled-events/event-scheduler/#erp転記モード)、[取り消し](/ja/guides/connections/posting-register/#取消)、[プロジェクトに転記を許可する](/ja/guides/workflows/run-a-workflow/#プロジェクトに転記を承認する)を参照してください。

- **行アクセスはグループの変更に追従し、問題点も示されます。** シングルサインオンがサインイン時に設定するグループメンバーシップは、約 15 分以内にダッシュボードの行アクセスに反映され、デフォルトグループの新しいメンバーは約 1 分以内に自分の行を取得します。行アクセスウィンドウは、制限が何もフィルターしない場合に警告し、`&`、`/`、`%` を含む列名を処理し、同期が失敗すると、理由とともに**エラー**を、または**再試行**ボタン付きで**再試行中**を表示します。[ダッシュボードの同期を保つ](/ja/administration/access/managing-security-groups-and-assignments/#ダッシュボードの同期の維持)を参照してください。

- **ユーザー定義関数は、新しいライブラリを備えた Python 3.14 で実行されます。** ほとんどの関数は変更なしで動作します。numba、または `cgi` や `telnetlib` のように Python から削除された標準ライブラリモジュールをインポートする関数は、失敗するようになり、書き直しが必要です。予測の AutoTheta の範囲は、以前の実行とわずかに異なる場合があります。[User Defined Transform ステップ](/ja/reference/workflow-steps/general/user-defined-transform/)を参照してください。

- **完全なエージェントアクセスは非推奨となり、2027年1月15日に削除されます。** **完全**アクセスを使用する LLMステップは、警告をログに記録します。**読み取りと書き込み**に移行してください。この設定では、エージェントは PlaidCloud の書き込みツールを通じてデータを変更し、LLMステップは**書き込み**にチェックを入れたバインディングにのみ書き込みます。[エージェントアクセス](/ja/integrations/ai-architecture/llm-providers/#エージェントアクセス)を参照してください。

- **ドキュメントアカウントの設定と参照が簡単になりました。** OneDrive または SharePoint アカウントのファイルブラウザーは、開始パスの下のフォルダーを開きます。Google Cloud Storage アカウントには有効なサービスアカウントキーが必要で、キーのない既存のアカウントは、キーを追加するまで動作しなくなります。拒否された設定にはその理由が示され、未使用のバックアップアイコンは**アカウントの管理**から削除されました。[Google Cloud Storage アカウントを追加する](/ja/guides/documents/adding-accounts/add-google-cloud-storage-account/)と[ドキュメントアカウントのバックアップ](/ja/guides/documents/account-management/managing-document-account-backups/)を参照してください。

- **プロジェクトアプリが請求書、出張、遅延入力にさらに完全に対応しました。** 新しい請求書は、顧客と発注書番号を提供するマスタープロジェクトから開始します。下書きの請求書を削除すると、その時間と出張が再び請求可能になり、**売掛金の受信者**で、請求書の提出時にメールを受け取る人を設定します。出張ドロワーには各明細のベンダー、カテゴリー、監査ステータスが表示され、**遅延入力の時間を追加**で、承認済みの週のシートを開始できます。[プロジェクトアプリで時間と経費を記録する](/ja/guides/time-expense/track-time-and-expenses/)を参照してください。

- **どのステップも参照していないすべてのテーブルを削除していた API 呼び出しは削除されました。** 代わりに ID でテーブルを削除してください。

- **アプリ全体の小さな変更。** アカウント、ダッシュボード、メンバー、グループ、設定の一覧の行をダブルクリックすると開きます。空の**ディメンション**、**データエディター**、**UDF**、**ステップ**の各タブには次の手順が表示され、アプリのないメンバーはランチャーに移動します。ステップのテーブルセレクターには、テーブルが最後に更新された日時が表示されます（[ソーステーブルが最後に変更された日時を確認する](/ja/guides/workflows/create-workflow/#ソーステーブルの最終変更日時の確認)）。Export External Database Tables ステップは、列を独自のタブでマッピングし、**レポート: バッチ生成**には、未使用の **Report Constants** セクションが表示されなくなりました。Convert Encoding ステップは、中央ヨーロッパ、トルコ、アラビアの文字コードを認識します。削除された画面へのリンクには、その旨が表示されます。

## 修正

- **AI アシスタントは、承認するまで何も変更せず、名前をそのまま表示します。** 新しいテーブルにステップを構築する場合、承認前にテーブルが作成されていましたが、現在は承認後にテーブルとステップが一緒に作成されます。また、プロジェクト、ワークフロー、ディメンションの作成、テーブルのコピー、テーブルのプロパティやラベルの変更でも、先に確認が求められます。承認は、次の返信にのみ有効です。アシスタントが提案するインポートまたはエクスポートは、テーブル、ドキュメントアカウント、ワークフローを名前で表示し、存在しないものや、開けないものと一緒に提案されることはありません。アンダースコアを含む名前は、斜体にならずそのまま表示され、ダークテーマでもテーブルとコードが読みやすくなり、図はテキストではなく描画され、式エディターの Weave パネルは編集中の式を読み取ります。アシスタントは、名前のないテーブルがある場合でもプロジェクトのテーブルを一覧表示し、ステップが複数のテーブルを読み書きする場合でも、どのステップがテーブルを読み書きしているかを、エラーで止まることなく回答します。[ワークフローステップを構築する](/ja/guides/ai-assistant/weave-tab/#ワークフローステップの作成)を参照してください。

- **ファイルのインポートは、指定したものを読み取ります。** Excelのインポートは、列全体の範囲と XLSB ブックを読み取り、zip 形式のブック内のシートを検出し、パディングや改行を含むヘッダーでも失敗しなくなりました。CSVのインポートは**スキップする行**に従うため、SAP のリストエクスポートのようにヘッダーの上に行があるファイルでも、列名でインポートでき、デフォルトの区切り文字、引用符、エスケープ文字で実行されます。1 つのソース列を複数のターゲット列に割り当てることができ、すべての列が固定値であるインポートはすべての行をロードし、大文字の圧縮拡張子を持つファイルは展開され、変更がなければスキップするインポートは、空にされたテーブルを再ロードします。AI アシスタントに**プロジェクトのデフォルト**からのファイルのインポートを依頼すると、プロジェクトのデフォルトのドキュメントアカウントが読み取られ、プロジェクトに設定されていない場合は、その旨が明確に伝えられます。新しい列型の Parquet ファイルは、ドキュメントで開けます。[Excelのインポート](/ja/reference/workflow-steps/import/import-excel/#読み取り対象)と[CSVのインポート](/ja/reference/workflow-steps/import/import-csv/#行の選択)を参照してください。

- **ワークフローステップは、設定どおりに保存され、実行されます。** Table: Upsert ステップは再び保存でき、**更新キー**列が戻りました。Table: Project to Project Copy ステップはターゲットプロジェクトを指定し、データ共有を通じて読み取ります。ドキュメント: ダッシュボードをPDFとして保存は列の型を保持し、テーブル: 和集合（重複なし）とテーブル: 和集合（すべて）は列を名前で照合します。複数テーブル結合は複数の入力で保存でき、スペースを含む列名を受け付けます。Table Lookup ステップはルックアップ列の集計設定を無視し、SCD-2時点指定結合は日付として変数を受け付けます。LLMステップは 4.6 より前の Claude モデルで実行され、AI アシスタントが編集してもモデルが保持されます。RESTリクエストは行の値を 1 回だけエンコードして送信し、リモートデータベースへのエクスポートは行をコミットします。[更新キー](/ja/reference/workflow-steps/tables/table-upsert/#更新キー)、[データ共有の管理](/ja/reference/workflow-steps/tables/frame-project-copy/#データ共有の管理)、[複数テーブル結合](/ja/reference/workflow-steps/tables/table-multi-table-join/)を参照してください。ワークフローの削除、コピー、名前の変更、停止などのワークフローを選択するステップは、存在しなくなったワークフローを、一覧の最初のワークフローに切り替えずに、*id（存在しません）* として保持します。

- **ワークフローの実行が正しく完了します。** ワークフローループは、反復するコンテナーや、1 回の実行で複数回実行されるワークフローと同様に、ループ対象のワークフローをすべての反復で実行します。ステップから、または並列グループの内部から開始した実行は、正しいステップを実行して完了します。長時間実行されるインポートやエクスポートが二重に開始されることはなく、PlaidCloud の更新中に停止することもなく、サーバーエラーで終了した操作が再送されることもありません。データベースドライバーのクラッシュは、そのステップのみを、データベースの理由とともに失敗させます。実行履歴はすべてのステップの行数をカウントし、作業を始める前に失敗したステップは、理由をワークフローログに書き込みます。[Workflow Loop ステップ](/ja/reference/workflow-steps/workflow-control/workflow-loop/)と[実行履歴](/ja/guides/workflows/advanced-workflows/#実行履歴)を参照してください。

- **プロジェクトのコピー、インポート、オープンが予期せぬ動作をしなくなりました。** プロジェクトのインポートは、復元できたものをすべて保持し、除外したものを**インポート結果**ウィンドウに一覧表示し、進行状況を表示し、失敗の理由を示し、再試行できます。選択したオブジェクトのコピーは、プロジェクトに変数がある場合でも動作します。プロジェクトを開いても設定が変更されなくなり、**独自のデータを取り込む**で CSV がインポートされ、PostgreSQL ウェアハウスでのテーブル作成が動作します。App Runner アプリは PlaidCloud の更新時に自動的に更新され、行を制限するプロジェクトの閲覧者にも動作します。[アーカイブの一部がインポートされない場合](/ja/guides/projects/archive-a-project/#アーカイブの一部がインポートされない場合)と[アプリを最新に保つ](/ja/guides/workflows/use-converted-alteryx-apps/#アプリを最新の状態に保つ)を参照してください。

- **ディメンションと配賦が正しくロードされ、読み取られます。** 親子ロードは、親が空の行を最上位のメンバーとして保持し、すべての種類のロードで、メイン階層外のメンバーは 2 つ目の代替階層には拒否されます。階層に含まれない親の下へメンバーを移動することは拒否され、ディメンションステップは見つからなかったディメンション名を示し、空白を含む列を貼り付けても各値は各行に保持されます。大規模なディメンションを読み取っても、ワークスペース内の他のユーザーが待たされなくなりました。ディメンションプロパティの**階層**が**未指定**のままの配賦ルールは実行されます。[代替階層へのロード](/ja/reference/workflow-steps/dimensions/dimension-load/#代替階層へのロード)と[ディメンションタイプのプロパティとメンバーピッカー](/ja/guides/dimensions/dimensions/#ディメンション型のプロパティとメンバーピッカー)を参照してください。

- **ワークフローキャンバスと画面が正しく動作します。** **ワークフローにドリルダウン**は高度なワークフローをキャンバスで開き、キャンバスはすべてのワークフローを開き、レイアウトの一部を読み取れなかった場合はそのことを通知します。収まらないツールバーのボタンは**その他**メニューに移動し、保存するとすぐに一覧が更新されます。通知はメッセージ全体を表示し、警告は**ログ**タブに警告アイコンを表示し、テーブルエクスプローラーは列のプロファイルが失敗したことを通知し、データエディターは空の日付セルを空のまま保持します。列フィルターを有効にしたままデータエディターを保存すると、フィルターで非表示の行も、行の追加、削除、移動の後でも保持されます。ユーザー定義関数エディターは、変更を許可されているユーザーに編集可能な状態で開きます。[キャンバスがワークフローを開けない場合](/ja/guides/workflows/advanced-workflows/#キャンバスでワークフローを開けない場合)を参照してください。**テーブル**一覧からのテーブルの削除では、`/Periods/{period}/Sales` のような変数パスを通じてのみテーブルに到達するステップも一覧表示され、強制した場合にのみそのテーブルが削除されます。[削除](/ja/guides/projects/managing-tables-and-views/#削除)を参照してください。

- **メンバーと接続が正しく動作します。** **ワークスペースメンバーを追加**は、シングルサインオンで作成されたアカウントを含め、すでにアカウントを持つ人にも動作し、保持しているプロジェクトロールを下げることはありません。ODBC 接続は、PlaidLink エージェントのマシン上の DSN またはドライバーを通じて接続します。OAuth 資格情報を拒否したプロバイダーは、再入力または再認可を求め、Databricks のサンプルとエクスポートは期限切れ間近のトークンを更新し、古いデータベースタイプの接続も削除できます。**使用箇所**には通知ステップが含まれ、無料のワークスペースでも日次、週次、月次のバックアップが保持されます。[メンバー管理](/ja/administration/access/member-management/)と [ODBC](/ja/reference/connectors/databases/odbc/)を参照してください。

- **REST API と AI アシスタントのツールが、依頼どおりに動作します。** メンバー、グループ、スケジュールイベントの部分更新は、指定したフィールドのみを変更するため、一時停止中のイベントは一時停止のままです。名前を指定したステップから実行を開始すると、そこから開始され、テーブルのスナップショットの復元では、安全のためのスナップショットと監査記録が保持されます。AI ツールからのドライバーのホワットイフは、モデルが実際に行った分割と一致する場合にのみ回答します。以前はサーバーエラーで失敗していたリクエストは、動作するか、何が問題だったかを説明するようになりました。[配賦のトレース](/ja/integrations/ai-coding-agents/tracing-allocations/)と[スナップショットを元に戻す、または復元する](/ja/guides/data/table-snapshots/#スナップショットを巻き戻しまたは復元する)を参照してください。

## セキュリティ

- **AI アシスタントは、権限の範囲内にとどまります。** アシスタントのデータクエリは、実行前に構造がチェックされ、単一の読み取りクエリのみが実行されます。Microsoft 365 Copilot を含む読み取り専用の AI 接続では、ファイルのエクスポート、ダッシュボード PDF の保存、別のプロジェクトへの行のコピー、REST 接続を通じた変更の送信はできません。AI アシスタントを通じたインポートは、指定したプロジェクトで、あなたとして実行され、会話は開始した本人のみが続行できます。アシスタントとテーブル参照では、ロールで非表示になっているテーブル、ステップ、ワークフロー、ディメンションは除外され、Weave は、開けない失敗したステップを名前で示さず、件数として数えます。[アクセスレベル](/ja/integrations/microsoft-365-copilot/#アクセスレベル)、[ロールで非表示になる内容](/ja/guides/ai-assistant/weave-tab/#ロールによって非表示になる内容)、[過去の会話を管理する](/ja/guides/ai-assistant/weave-tab/#過去の会話を管理する)を参照してください。

- **ERP 転記は、その制御を迂回できません。** 職務分掌がオンの場合、取り消しは転記レジスターを通り、そこで承認が適用されます。コピーまたはインポートされたプロジェクトは、転記の権限を継承しなくなり、SAP と EBS の転記をエージェントに直接送信することはできず、テスト専用モードの SAP Post ステップは、本番の転記と同じ権限を必要とします。これらのチェックなしで Sage Intacct に転記していた非公開のエンドポイントは削除されました。ERP 接続と REST 接続のエラーメッセージには、資格情報が含まれません。[職務分掌](/ja/guides/connections/posting-register/#職務分掌)を参照してください。

- **シークレットは書き込み専用で、接続を誰が使うかを決められるのは所有者だけです。** ドキュメントアカウントのキー、パスワード、トークンは、保存後は二度と表示されず、アカウントの接続先を変更するには、シークレットを再入力する必要があります。ステップ内のパスワードとキーは変数にのみ保持され、ステップに直接入力されていたシークレットは、アーキテクトのみが見られるプロジェクト変数に移動されました。複数行の資格情報は、入力中にマスクされます。接続へのアクセス権を持つユーザーを変更できるのは、接続の所有者またはワークスペース管理者のみです。[保存されたシークレットは書き込み専用](/ja/guides/documents/adding-accounts/#保存されたシークレットは書き込み専用)、[キーは変数に保持される](/ja/reference/workflow-steps/document/encrypt-decrypt-file/#キーは変数に保持する)、[接続を作成して管理する](/ja/guides/connections/create-connection/#セキュリティモデル)を参照してください。

- **使用できないドキュメントアカウントは、閉じたままです。** ファイルの存在の確認、Parquet、Avro、ORC、Delta ファイルの列の読み取り、**取り込み**によるインポートステップの列の入力、AI アシスタントによるファイルの検査は、アクセス権のないアカウントを拒否するようになりました。参照はすでに拒否されていました。

- **ワークスペース管理者を変更できるのは、ワークスペース管理者だけです。** 管理者の編集、無効化、削除、グループの変更、ユーザーの管理者への昇格には、いずれもワークスペース管理者が必要です。[ワークスペース管理者の変更](/ja/administration/access/member-management/#ワークスペース管理者の変更)を参照してください。

- **データ共有は、共有先のプロジェクトのメンバーに対してのみ有効です。** 共有を通じた読み取りには受信側プロジェクトでのロールが必要で、書き込みには**書き込み**共有と、そこでのマネージャーまたはアーキテクトのロールが必要です。[プロジェクト間でデータを共有する](/ja/guides/projects/managing-projects/#プロジェクト間でのデータ共有)を参照してください。

- **復元は、指定した項目にのみ適用されます。** 以前のバージョンを復元すると項目自体が復元され、権限チェックはその項目に対して行われます。ディメンションのバックアップファイルの内容が、自身のヘッダーにあるディメンションに属さない場合は拒否されます。[バージョン履歴](/ja/guides/projects/managing-projects/#バージョン履歴)を参照してください。

- **テンプレート、インポート、アーカイブは、安全でない内容を拒否します。** エクスポートテンプレートとレポートテンプレートは、渡されたデータのみを読み取るサンドボックスで描画されます。インポートは自身の設定からロードクエリを構築し、PlaidCloud のアーカイブには含まれない内容を持つプロジェクトアーカイブは拒否され、別のプロジェクトのレポートスキーマを共有してしまうプロジェクトスラッグも拒否されます。[テンプレートで使えるもの](/ja/reference/workflow-steps/export/export-templated/#テンプレートで使用できるもの)と[アーカイブを復元する](/ja/guides/projects/archive-a-project/#アーカイブの復元)を参照してください。

- **ダッシュボードは、PlaidCloud のサインインと行アクセスに従います。** ダッシュボードのサムネイルはあなたとしてレンダリングされ、アカウントは PlaidCloud のサインインからのみ取得され、ダッシュボードは、エクスポートが生成する ZIP ファイルからのみインポートできます。[既存のダッシュボードをインポートする](/ja/guides/dashboards/learning-dashboard/#既存のダッシュボードのインポート)を参照してください。

- **ワークフローの実行を開始しても、その実行の資格情報は返されなくなりました。**

- **ユーザー定義関数を実行する環境から、PySpark の Java ライブラリが削除されました。** これらには既知の脆弱性がありました。PySpark の DataFrame と SQL API は引き続きお客様の Spark Compute Cluster に接続しますが、`SparkContext` や `RDD` をインポートする関数は失敗するようになりました。[PySpark を始める](/ja/integrations/pyspark/getting-started/)を参照してください。

- **添付ファイル、復元、変換は、使用できるアカウントのみを読み取ります。** ファイルのメール送信、ファイルからのディメンションまたはテーブルアーカイブの復元、テーブルバンドルの検査またはインポート、テンプレートからの Excel エクスポートの入力、Alteryx ワークフローの変換は、アクセス権のないドキュメントアカウントを拒否するようになりました。ディメンションをドキュメントアカウントにバックアップするには、そのアカウントへの書き込みアクセスが必要です。ファイルのメール送信、テーブルの復元、Excel テンプレートの入力を行うステップが Personal Temp Drive から読み取れなくなった点を除き、ワークフローステップには影響しません。
