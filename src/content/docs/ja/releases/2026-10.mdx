## 追加

- **Data Foundation が、ERP データを 1 つの Common Finance Model に統合します。** Common Finance Model は、複数の ERP システムとインスタンスの ERP データを、1 つの勘定科目表、1 組のエンティティ、1 つの報告通貨からなる単一のモデルに統合します。このモデルをもとに作成したレポート、メトリック、AI アシスタントはすべて、どの ERP 由来であっても同じ数値を参照します。

  - **ERP から直接取得。** 総勘定元帳、試算表、マスターデータ、予算は、PlaidCloud の ERP への直接接続を通じて取り込まれます。**Entity crosswalk** が、各ソースの会社コードを同じエンティティに対応付け、システムが保持していない為替レートや配賦ドライバーなどはファイルで補います。
  - **1 つのモデル、1 つの通貨。** **ロード** は、すべてのソースを Common Finance Model に適合させ、報告通貨に換算します。損益計算書は期間の平均レート、貸借対照表は期末レート、資本は取得時レートで換算します。階層は、マスターデータから構築されます。
  - **準備状況を確認。** エンティティと期間ごとにチェックが実行されます。試算表と売上が総勘定元帳と一致していること、すべての製品、顧客、勘定科目が既知であること、通貨が換算できること、すべてのエンティティがマッピングされていることを確認します。
  - **複数のソース、1 つのモデル。** ERP システム、インスタンス、またはファイルであるソースを、追加、並べ替え、編集、削除できます。**ロード** はすべてを適合させ、重複する部分は 1 件だけ残し、保留した行を理由とともに記録します。**Apply changes** は、ERP から再度取り込むことなく、適合処理を再実行します。
  - **ソース間でコードをマッピング。** 複数のソースで同じコードが使われている場合、名前の一致による提案が、同じ意味かどうかを尋ねます。1 つのコードまたはグループ全体に対して、**Accept all**、**All the same**、**All different** で回答できます。マッピングは、ソースとディメンションごとに保持されます。最大 10 個の追加カテゴリには、指定した名前が付き、カバレッジビューでは、どのソースをどの月から使用するかを選択できます。
  - **ファイルのオプション。** ファイルは、1 つのソースに適用したり、回答が必要な質問を表示したり、列を複数のフィールドに分割したり、報告通貨を設定したり、削除したりできます。
  - **管理連結。** ロードのたびに、グループの損益計算書（年度累計も含む）が作成されます。会社間取引は **Eliminations** エンティティで消去され、**Unmapped** バケットと、連結システムの結果との照合も含まれます。これはプロジェクトの行アクセスに従う管理用のビューであり、法定連結ではありません。
  - **最新の状態を維持。** **夜間に更新** は、毎晩モデルを再ロードします。ファイルが存在しない場合や空の場合は、エラーではなく警告付きで完了します。

  **Enterprise Profitability** などのテンプレートからプロジェクトを開始すると、プロジェクトの **Foundation** タブで、ERP の接続から、ロードとチェックが済んだモデルまでを順に進められます。[Data Foundation: Common Finance Model](/ja/guides/projects/data-foundation/)を参照してください。

- **独自の Snowflake または Databricks ウェアハウスで PlaidCloud を実行します。** ワークスペース管理者は、ユーザーメニューの **自分のウェアハウスを使用する** を開き、生成されたセットアップスクリプトを自身のアカウントで実行します。このスクリプトは、上限付きのウェアハウスと PlaidCloud 用のサービス ID を作成し、既存のウェアハウスには一切手を加えません。**接続を確認** は、問題とその対処方法を分かりやすい言葉で説明します。以降、新しいプロジェクトのテーブルの保存とワークフローの実行は、お客様のウェアハウスで行われ、ウェアハウスを削除すると、そこへの PlaidCloud のアクセス権が取り消されます。[独自のウェアハウスを使用する](/ja/guides/connections/external-lakehouse/)を参照してください。

  - **Snowflake または Databricks でサインイン。** 認証情報を貼り付ける代わりに、管理者はサインインしてウェアハウスを接続できます。ダッシュボードは各ユーザー自身のウェアハウス権限で実行され、ワークフローは、指定したデータロールのみを持つサービス ID として実行されます。[Snowflake または Databricks でサインインする](/ja/guides/connections/external-lakehouse/#snowflake-または-databricks-でサインインする)を参照してください。
  - **複数のウェアハウスを接続。** **ウェアハウスの管理** の **デフォルトに設定** を使用すると、新しいプロジェクトが別のウェアハウスに配置されます。既存のプロジェクトはそのまま残ります。[ウェアハウスを管理する](/ja/guides/connections/external-lakehouse/#ウェアハウスを管理する)を参照してください。
  - **実行にかかるコストを確認。** 実行履歴には、実行ごとにクレジットまたは DBU 単位の **ウェアハウスコスト** 列が表示されます。[実行ごとのウェアハウスコスト](/ja/guides/connections/external-lakehouse/#実行ごとのウェアハウスコスト)を参照してください。
  - **ガバナンスはそのまま維持。** 説明はウェアハウス自身のカタログに書き込まれます。PlaidCloud がテーブルを置き換え、再作成、またはクローンする場合も、Snowflake の行アクセスポリシーとマスキングポリシー、Databricks の行フィルターと列マスクは、そのまま適用されます。[ポリシーと説明の引き継ぎ](/ja/guides/connections/external-lakehouse/#ポリシーと説明が引き継がれる)を参照してください。

- **PlaidCloud 内で Panel アプリを構築、公開、ブランド設定できます。**

  - **Panel Studio。** **マイPanelアプリ** の最初のボタンである **新しい Studio アプリ** では、空のアプリ、テーブル、ビュー、別の Studio アプリ、またはアプリギャラリーから開始できます。**テーブル** タブの **Panel アプリを作成** では、選択したテーブルから開始します。**Studio で開く** を選択すると、アプリのファイルがエディターで開きます。下書きを保存し、非公開のビルドを **プレビュー** し、稼働中のアプリを **公開** します。ビルドエラーには、該当するファイルと行が示され、**履歴** で公開済みの任意のバージョンを復元でき、**インサイト** には、表示回数、読み込み時間、エラーが表示されます。**Weave に質問** は、アプリのファイルとビルドの状態を把握しており、コードを保存する前に、変更点の全体を承認用に表示します。[Panel Studio](/ja/guides/panel-apps/studio/)と[Weave で Panel アプリを構築する](/ja/guides/panel-apps/build-with-weave/)を参照してください。
  - **PlaidCloud らしいアプリキット。** このキットで構築したアプリは、ライトとダークの両方で、PlaidCloud の色、書体、余白を使用します。キットには、ナビゲーション、フィルター、主要な数値を表示するカード、チャート、フォーム、コマンドパレット、ワークフローを実行するボタン、印刷、そしてサーバー上で並べ替えと集計を行い、列ごとに数値を書式設定し、1 画面分の行ずつ読み込むデータグリッドが含まれます。そのため、どのようなサイズのテーブルでも扱えます。アプリは、ログインしている閲覧者として、行セキュリティを適用してテーブルを読み取ります。[Panel アプリキット](/ja/guides/panel-apps/app-kit/)、[DataGrid](/ja/guides/panel-apps/app-kit/#datagrid)、[Panel アプリ向けデータ API](/ja/guides/panel-apps/data-api/)を参照してください。
  - **アラートとダイジェスト。** プロジェクトテーブルの数値が上限を超えたときに、プッシュ通知、メール、Slack、または Microsoft Teams で通知を受け取れます。また、最大 10 個の数値を含む日次または週次のダイジェストも受け取れます。いずれも、常にご自身の行アクセスの範囲内で動作します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
  - **プロジェクト、ブランド設定、共有。** アプリをプロジェクトに割り当てます。その際、プロジェクトのメンバーではないが、そのアプリを開ける人を確認します。プロジェクトの **ホーム** タブの **ブランディングを編集** では、プロジェクト内のすべてのアプリに共通する 8 色のブランドカラーとロゴを設定します。**ギャラリー…** メニューは、プロジェクトに属する Studio アプリを、そのプロジェクトを閲覧できる全員向けのテンプレートとして一覧に掲載し、**ギャラリーから外す** でそれを取り下げます。[プロジェクトのブランド設定とアプリプロジェクト](/ja/guides/panel-apps/branding/)と[アプリギャラリー](/ja/guides/panel-apps/gallery/)を参照してください。

- **ビジネス上の数値の計算方法を一度合意すれば、AI のすべての回答がその計算を使用します。** プロジェクトのアーキテクトが、*純収益* や *従業員数* などの **メトリック** を定義します。ソーステーブル、行の集計方法、常に対象となる行、結合するルックアップテーブル、内訳に使用できる列を定義します。定義は保存するとすぐに有効になり、存在しないテーブルや列を指定した場合や、キーごとに複数の行があるルックアップを指定した場合の保存は拒否されます。AI アシスタントにメトリックを名前または同義語で尋ねると、AI アシスタント自身が算出するのではなく、ご自身の行アクセスの範囲内で、その定義に従って数値が計算されます。定義は、AI アシスタントまたは REST API を通じて管理します。[メトリック定義](/ja/integrations/ai-coding-agents/metric-definitions/)を参照してください。

  - **派生メトリック。** 純収益を FTE で割った値のような 2 つのメトリックの比率、合計、差、またはメトリックに固定の係数を掛けた値を定義できます。[他のメトリックから派生メトリックを作成する](/ja/integrations/ai-coding-agents/metric-definitions/#他のメトリックから派生させる)を参照してください。
  - **比較、ランキング、構成比。** 予算との差異、同順位を維持した上位または下位 N 件、各行の合計に対する構成比を尋ねられます。[比較、ランキング、構成比](/ja/integrations/ai-coding-agents/metric-definitions/#比較ランキング構成比)を参照してください。
  - **お客様の言葉で、合意された値を。** 内訳の列をディメンションにバインドすると、*EMEA* のような言葉が、その下にあるすべてのリージョンになります。どれにも一致しない言葉や、複数のメンバーに一致する言葉は、推測せずに、確認のための候補として返されます。[メトリックについて尋ねる](/ja/integrations/ai-coding-agents/metric-definitions/#メトリックについて質問する)を参照してください。
  - **会計期間。** メトリックの行が会計カレンダーのどこに位置するかを指定すると、会計期間、年度累計、前年比、前期比を尋ねられます。[時系列で比較する](/ja/integrations/ai-coding-agents/metric-definitions/#時間の経過に沿って比較する)を参照してください。

  PlaidCloud 独自の AI アシスタントは、ビジネス上の数値をまずメトリックから回答し、その数値を ✓ の付いた専用のカードに表示します。この ✓ がアシスタント自身の文章に付くことはありません。[ビジネス上の数値](/ja/guides/ai-assistant/weave-tab/#ビジネス数値)と[メトリックから得た数値](/ja/guides/ai-assistant/weave-tab/#メトリックの数値)を参照してください。

- **決算の準備ができているかを Weave に尋ね、2 つのテーブルが一致するかを確認できます。** どちらも AI は使用しません。

  - **決算準備状況。** 決算、予測、またはその他の期限が依存するワークフローを、プロジェクトの **Weave** タブの **準備状況** から **準備状況セット** として指定します。1 つのチェックリストが、それらすべてに回答します。たとえば「13 件中 11 件が準備完了、1 件が未準備、1 件がチェックできませんでした」のようになります。ワークフローが準備完了とされるのは、Weave が実行できたすべてのチェックに合格した場合に限られます。Weave が判断できなかったものは、準備完了ではなく、理由とともに **チェックできませんでした** と表示されます。新しいワークフローのように、比較対象となる過去の履歴が少なすぎる最後の実行は、通常どおりとみなされます。メールの送信やファイルのエクスポートなど、テーブルに書き込まないステップには、チェックすべき行や空の値がないため、ワークフローを **チェックできませんでした** の状態に留めることはありません。[決算前に準備状況を確認する](/ja/guides/ai-assistant/weave-readiness/)を参照してください。
  - **照合。** 2 つのテーブル、または 1 つのテーブルの 2 つの期間を、対応付けたキー列で行ごとに比較します。Weave は、それらが一致するかどうか、どれだけ差があるか、どの行が異なるかを示し、すべてを読み取れなかったデータについては「一致」とは決して言いません。照合は、使用される前に、2 人目のアーキテクトが承認します。[2 つのテーブルが一致するか確認する](/ja/guides/ai-assistant/weave-reconciliation/)を参照してください。

- **Weave は、問題になりうる点をさらに多く監視し、実行の合間にお知らせします。** Weave のチェックに AI は使用しません。すべての検出事項と AI アシスタントのすべての回答に、**Weaveが把握する方法** パネルがあります。検出事項では、チェックとその根拠となる値が示され、回答では、アシスタントが実行した各クエリが示され、すべての文に **一致**、**不一致**、**未確認** のいずれかが付きます。[Weave が現在チェックする内容](/ja/guides/ai-assistant/weave-findings/#現在weaveがチェックする内容)、[Weave が把握する方法](/ja/guides/ai-assistant/weave-findings/#weaveが把握する方法)、[AI アシスタントで Weave が把握する方法](/ja/guides/ai-assistant/weave-tab/#weaveが把握する方法)を参照してください。

  - **テーブルの書き込みが期限どおりか。** Weave は、スケジュールの期限が来てから書き込まれていないテーブルや、テーブルの詳細の **鮮度** で設定した、1 時間から 180 日までの鮮度のしきい値を超えて書き込まれていないテーブルを報告します。
  - **古い、または壊れた入力。** Weave は、別のワークフローがその後に書き込んだテーブルを読み取っているワークフローと、失敗した実行に依存するすべてのワークフローとダッシュボード（チャートが SQL データセットに基づくダッシュボードを含む）を報告します。**依存関係の同期** は、ステップと、そのステップが読み取るテーブルとの間で不足しているコネクターを追加します。[依存関係の同期](/ja/guides/workflows/sync-dependencies/)を参照してください。
  - **形が変わったデータ。** Weave は、実行後に値の分布が大きく変わった小数列、行を複数回書き込むようになった結合、列の型に変換できなかったため Extract ステップが空にした値、ファイルが見つからなかったインポートを報告します。また、直近の期間が通常から大きくかけ離れているメトリックも報告し、その要因となった項目を示します。Weave は月末や曜日のパターンを考慮するため、常に月末に負荷が高いロードは報告されません。[メトリック合計の異常](/ja/guides/ai-assistant/weave-metric-insights/)を参照してください。
  - **遅くなった実行。** Weave は、実行を遅くしたステップを示し、新しい実行が古い実行より少なくとも 4 分の 1 長くかかっているワークフローを報告して、所要時間が最も増えたステップを示します。
  - **実行の合間の通知。** 1 時間ごとのチェックで、各問題の所有者にアプリ内メッセージで 1 回だけ通知されます。ヘッダーの **Weave** ボタンには、すべてのプロジェクトで未読の問題の数が表示されます。[実行の合間に通知を受ける](/ja/guides/ai-assistant/weave-findings/#実行の合間の通知)と[ヘッダーの Weave ボタン](/ja/guides/ai-assistant/weave-tab/#ヘッダーのweaveボタン)を参照してください。
  - **所有者、コメント、想定内の警告。** 各検出事項には所有者がおり、デフォルトでは、そのワークフローを最後に実行した人です。**割り当て** で別の人に引き継ぎ、コメントで進捗を記録し、**チーム** ビューで誰が何を所有しているかを確認できます。アーキテクトは、理由と終了日を付けて、警告を **これは想定内** としてマークできます。[検出事項に所有者を設定する](/ja/guides/ai-assistant/weave-tab/#検出事項に担当者を設定する)と[検出事項を想定内としてマークする](/ja/guides/ai-assistant/weave-tab/#検出事項を想定内としてマークする)を参照してください。

- **修正アシスタントが、エラーを説明し、カードで承認できる変更を提案し、ステップを再実行し、修正を元に戻すこともできます。** テーブルにない列、空の必須設定、データベースが読み取れない SQL、型の異なる値など、最もよくある失敗については、最初の返信で、よくある原因と修正方法を説明します。提案された変更はカードとして表示され、ステップが失敗した理由と、変更される各設定が、現在の値を赤、新しい値を緑で示されます。**承認** で適用すると、アシスタントがステップの再実行を提案し、新たな失敗があれば診断します。**Weave** タブの検出事項にある **修正** で、その問題についてアシスタントが開きます。**元に戻す** は、ステップの以前の設定を復元し、**元に戻して実行** で、その出力を再構築します。[AI によるワークフローエラーの修正](/ja/guides/ai-assistant/fixing-workflow-errors/)、[AI アシスタントで検出事項を修正する](/ja/guides/ai-assistant/weave-tab/#aiアシスタントで検出事項を修正する)、[修正を元に戻す](/ja/guides/ai-assistant/fixing-workflow-errors/#修正を元に戻す)を参照してください。

- **プロジェクトで Weave が行ったすべてを確認し、監査人向けにエクスポートできます。** プロジェクトの **Weave** タブの **アクティビティ** には、Weave が見つけて後に検出されなくなった問題、AI アシスタントが提案したすべての変更、それを依頼した人、承認または却下した人、置き換えた内容と書き込んだ内容の詳細、最終的な結果が一覧表示されます。Weave は、変更を行う前に承認を記録し、記録できない変更は行いません。**CSVのエクスポート** または **PDFのエクスポート** で、ある期間を監査証跡として保存でき、エントリは編集も削除もできません。**サマリー** には、見つかって解決した問題、承認された変更、そのうち元に戻された件数など、1 か月の概要が表示されます。ワークスペース管理者は、**ワークスペースサマリー…** メニューで、すべてのプロジェクトについて同じ情報を確認できます。[Weave のアクティビティ履歴](/ja/guides/ai-assistant/weave-activity/)と[Weave の月次サマリー](/ja/guides/ai-assistant/weave-monthly-summary/)を参照してください。

- **保存する前に、ステップの動作と、変更の影響範囲を確認できます。** これらはすべて、プロジェクトの保存済みの設定から作成され、AI は使用しません。ロールによって非表示になっているものは、数だけが示され、名前は表示されません。

  - **すべてのステップとワークフローのドキュメント、すべてのテーブルの列。** 詳細パネルの **ドキュメント** セクションには、ステップの動作と、ワークフローのステップが順番に説明されます。テーブルを読み書きするものは、Weave と AI アシスタントが参照できます。テーブルの詳細パネルには、**列** が、型と説明とともに一覧表示されます。**引き継ぎパックをダウンロード** は、プロジェクト全体を、メトリック定義と配賦モデルも含めて 1 つのドキュメントとして保存します。[テーブル、ステップ、ワークフローのドキュメント](/ja/guides/ai-assistant/weave-documentation/)を参照してください。
  - **変更の影響範囲。** **保存** の上に、そのステップが書き込む内容を読み取る下流のステップの数が、「このステップを変更すると、2 つのワークフローの 8 個の下流ステップに影響します」のように表示され、**ステップを表示** で一覧を確認できます。[変更の影響範囲](/ja/guides/ai-assistant/impact-preview/)を参照してください。
  - **保存が拒否される内容。** **保存** の上のバーでは、編集中にステップのチェックが実行され、問題ごとに **移動** ボタンが表示されます。また、式エディターは入力中に式をチェックします。[保存が拒否される内容](/ja/guides/ai-assistant/check-while-you-edit/)を参照してください。
  - **1 つのワークフローのレビュー。** ワークフローのキャンバスまたは **ステップ** グリッドの **チェック** は、そのワークフローに対して Weave のチェックと、配賦および行レベルセキュリティのチェックを実行します。[1 つのワークフローをレビューする](/ja/guides/ai-assistant/weave-findings/#ひとつのワークフローのレビュー)を参照してください。

- **ワークスペースで、Weave の AI 機能をそれぞれオフにできます。** ワークスペース管理者は、ヘッダーの **Weave** ボタンの **AI機能…** メニューを選択して、Weave チャット、修正アシスタント、インポートアシスタントとエクスポートアシスタント、式アシスタント、説明からの SQL 生成、ワークフローレビューの概要、スターターチャートを、それぞれ個別にオンまたはオフにできます。管理者がオフにするまで、すべてオンです。Weave のチェックと検出事項は常にオンのままで、各変更はセキュリティログに記録されます。[AI 機能](/ja/guides/ai-assistant/weave-ai-features/)を参照してください。

- **Allocation Split ステップで、ドライバーのホワットイフを試せます。** ステップを右クリックして **ホワットイフ…** メニューを選択すると、異なるドライバー値、ドライバーテーブルの別の列、または同じキーを持つ別のテーブルの数値列を使った場合に、コストがどのように配分されるかを確認できます。最大 10 個のシナリオを比較でき、それぞれがステップの最後の実行結果から 1 円単位まで計算され、誰が得をして誰が損をするか、どの行が何も受け取らないかが分かります。**内訳の基準** では、各メンバーの変化が、どの勘定科目やその他の値に表れるかが分かり、**後続のステップ** では、配賦の出力から作られるテーブルにシナリオが反映されます。再実行は行われず、データも変更されません。[ドライバーのホワットイフを試す](/ja/guides/allocations/results/driver-what-if/)を参照してください。

- **プロジェクトの Lakehouse v2 への移行は、準備状況の確認から元に戻すまでガイドされます。** **移行準備状況の確認** は、テーブル、ビュー、ステップ、ダッシュボード、データ共有、容量を、問題なし、要確認、またはブロックとして報告し、すべての検出事項を分かりやすく説明します。**v2で試す…** メニューは、スケジュールがオフで、ERP への転記がシミュレートモードの、非公開の試用コピーを作成します。移行は、今すぐ、または指定した時刻に開始できます。移行中はプロジェクトのスケジュールが一時停止され、完了後に復元されます。完了時にはメッセージとメールで通知されます。**変更内容…** メニューは、各テーブルの結果を報告し、**移行を元に戻す…** メニューは、元に戻せる期間内であれば、プロジェクトを Lakehouse v1 に戻します。[プロジェクトを Lakehouse v2 に移行する](/ja/guides/data/migrate-project-lakehouse/)を参照してください。

- **プロジェクトをコピーすると、データもコピーされ、どの程度コピーするかを選べます。** **プロジェクトをコピー** では、1 つの Lakehouse 内、または 1 つの Lakehouse から別の Lakehouse へのコピーについて、サイズと警告を確認した上で、**構造のみ**、**全データ**、**サンプル** を選択できます。データ付きのコピーは、作成した本人のみが利用できます。**コピー結果** には各テーブルの結果が一覧表示され、**失敗したテーブルを再試行** は、それらのテーブルだけをコピーし、**インポートまたはコピーの結果を表示** は、後でウィンドウを再び開きます。センサーとスケジュールされたイベントは、コピー先ではオフの状態で作成されるため、そこでオンにするまで何も実行されません。[プロジェクトをコピーする](/ja/guides/projects/managing-projects/#プロジェクトのコピー)を参照してください。

- **ストレージを確認し、保持する履歴の量を管理できます。** ワークスペースの **ストレージ** ウィンドウには、含まれる分、予約分、オンデマンド分の帯を示すメーターと、課金に使用される月平均の予測値、各プロジェクトの現在のデータと履歴が表示されます。**プロジェクト** 一覧には **サイズ** 列があり、各プロジェクトの **テーブル** タブには、**現在のデータ**、**履歴**、**タイムトラベル日数**、**注記** の各列と、空き容量を確保する方法を提案する **ストレージ** ボタンが表示されます。タイムトラベルは、デフォルトで 1 日です。プロジェクトのデフォルトは 1 日から 90 日の範囲で設定でき、個別のテーブルでは、さらに長くできます。テーブルが保持する日数（テーブル自身の設定とプロジェクトのデフォルトのうち、長い方）より古い履歴は復元できないため、それより長く保持する必要があるものについては設定を引き上げてください。サイズは、履歴も含めて実際に保存されているものを反映しており、設定より古い履歴は毎晩クリーンアップされるため、使用量はその後の数日で減少します。**Deleted tables awaiting cleanup** 行には、削除されたテーブルのストレージのうち、まだ解放中のものが表示されます。[ストレージの管理](/ja/guides/projects/managing-storage/)と[履歴とタイムトラベル](/ja/guides/projects/managing-storage/#履歴とタイムトラベル)を参照してください。

- **各ダッシュボードを閲覧できるセキュリティグループを、1 つのダイアログで選択できます。** **閲覧できるユーザー** では、ダッシュボードを **プロジェクトの全員**、**特定のグループ**、**所有者のみ (下書き)** のいずれかに設定し、アクセス権を得る人と失う人をプレビューで確認できます。ダッシュボードへのアクセスをブロックされたユーザーには、所有者にメールを送る **Request access** ページが表示されます。ワークスペース管理者は **ダッシュボードアクセスレビュー** を利用でき、プロジェクトの **デフォルトのダッシュボード対象者** は、そのプロジェクトの新しいダッシュボードに適用されます。対象者の設定はダッシュボード自体を非表示にしますが、チャートのデータは引き続きプロジェクトのアクセス権と **行アクセス** に従います。[ダッシュボードの閲覧者を制御する](/ja/guides/dashboards/control-who-can-see-a-dashboard/)を参照してください。

- **別途接続を設定することなく、AI アシスタントからチャートとダッシュボードを構築できます。** PlaidCloud の MCP コネクターだけを接続し、公開済みのテーブルまたはビューに対して、テーブル、棒、折れ線、円、ビッグナンバーのチャートを依頼し、それらをダッシュボードに配置します。リンクと、確認用のデータのサンプルが提供され、自分が所有するチャートの編集を依頼することもできます。計算されたメジャーはビューの列に配置し、新しいダッシュボードにはプロジェクトのデフォルトの対象者が設定され、チャートを追加しても対象者が削除されることはなく、1 つのダッシュボードには 1 つのプロジェクトのチャートを配置できます。最初の依頼の前に、一度ダッシュボードサイトを開いてください。Microsoft 365 Copilot、PlaidCloud のアプリ内アシスタント、ワークフローのステップ、サービスアカウントでは構築できません。[AI アシスタントでチャートとダッシュボードを構築する](/ja/integrations/ai-coding-agents/build-dashboards/)を参照してください。

- **有料プランで、独自の ID プロバイダーを使ったシングルサインオンを設定できます。** **Workspaces** ページの **Single sign-on** で、Microsoft Entra ID、Okta、または任意の OpenID Connect プロバイダーを追加できます。コピー可能なリダイレクト URI と **Test sign-in** ボタンも用意されています。既存のアカウントを持つユーザーは、そのアカウントに一度サインインすることでリンクします。MFA 付きのパスワードと、Google、Microsoft、GitHub によるソーシャルサインインは、すべてのプランで引き続き利用できます。[シングルサインオン](/ja/administration/control-plane/workspace-configuration/#シングルサインオン)を参照してください。

- **利用状況レポートで、誰が何を使っているかを確認できます。** **ID** タブから、セキュリティログの権限を持つ管理者は、アクティブユーザー、新規ユーザー、再訪ユーザー、各画面、ダッシュボード、Panel アプリ、ノートブックの利用状況、画面間で最も多い遷移経路、最大 6 ステップのファネルを確認できます。最大 180 日間の範囲を選択でき、サマリーを CSV としてダウンロードでき、依頼に応じてメンバーの利用履歴を消去できます。[利用状況レポート](/ja/administration/access/usage-reports/)を参照してください。

- **スマートフォンからワークフローを実行して監視し、外出先から Weave に質問できます。** 無料の PlaidCloud アプリは、iPhone と iPad 向けに [App Store](https://apps.apple.com/app/id6769620647) で、Android 向けに [Google Play](https://play.google.com/store/apps/details?id=com.plaidcloud.mobile) で提供されています。ワークスペースのサインインページ（シングルサインオンを含む）でサインインして、プロジェクトを閲覧し、各ステップの状態と実行履歴を確認し、ワークフローを **実行**、**一時停止**、**再開**、**停止** できます。ワークスペースについて Weave に質問したり、失敗したステップで **Weave に質問** をタップして、そのコンテキストから開始したりできます。Weave が提案した変更は、**承認** をタップして Face ID または指紋で確認するまで保留されます。[PlaidCloud モバイルアプリ](/ja/guides/mobile-app/)と[モバイルでの Weave](/ja/guides/mobile-app/weave-on-mobile/)を参照してください。

- **PlaidXL で、Excel から PlaidCloud のデータを扱えます。** このアドインは、いつものサインインでサインインでき、各ブックは、それぞれのプロジェクトとワークスペースを記憶します。テーブルの選択した列と行をワークシートに取得し、**Refresh All Tables** で最新の状態にします。取得したテーブルを編集して **Save to PlaidCloud…** ボタンをクリックすると、確認の後に書き戻され、復元ポイントと **Restore previous version** リンクが付きます。空のセルとエラーが表示されているセルは空として保存され、フィルターしたテーブルや取得しなかった列については、それぞれ事前に明示的な警告が表示されます。`PLAIDXL` 数式は、階層をレイアウトしてドリルし、ディメンションノードの任意の組み合わせに集約されたメジャーを計算します。`>[2]`、`>[]`、`>[0:-1]` などのドリルキーは、開始ノードから世代を数え、各ノードをそれぞれの親の下に一覧表示します。`>[-1]` はリーフのみを意味し、`>[0:-1]` はリーフを除くすべてを意味します。`CELL` 数式だらけのレポートでも、セルごとの参照回数が少なくて済み、計算できないセルは、ポイントすると理由が表示されます。**Formulas** タブは数式を作成し、タスクペインは Office のテーマに従い、キーボードでも操作できます。リボンの **Convert to values (for sharing)** と **Restore PlaidXL formulas** は、PlaidXL を持たないユーザー向けのコピーを準備します。[PlaidXL で Excel を使う](/ja/get-started/tutorials/excel-with-plaidxl/)と [PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。

- **ワークフローのテキストメッセージは、オプトインしたメンバーに送信され、確認されます。** **通知: SMS** は、ワークスペースメンバーまたは配信リストにテキストメッセージを送信します。各メンバーは、ユーザーメニューの **テキストアラート** で、確認済みの米国の携帯電話番号を使ってオプトインします。配信できないテキストメッセージはステップに報告され、代わりにメールで送信されます。重複は 1 件にまとめられ、サイレント時間帯は終了するまでテキストメッセージが保留されます。廃止されたキャリアゲートウェイ方式のテキストメッセージ用に設定されたままのステップは、警告付きで完了し、受信者を選択するまで何も送信しません。[Notify Via SMS ステップ](/ja/reference/workflow-steps/notifications/notify-via-sms/)と[テキストアラート](/ja/guides/workflows/text-alerts/)を参照してください。

  - **MongoDB と Kafka** の接続には、[MongoDBのインポート](/ja/reference/workflow-steps/import/import-mongodb/)、[MongoDBのエクスポート](/ja/reference/workflow-steps/export/export-mongodb/)、[Kafkaのインポート](/ja/reference/workflow-steps/import/import-kafka/)、[Kafkaのエクスポート](/ja/reference/workflow-steps/export/export-kafka/)の各ステップが付属します。Kafka は、ユーザーとパスワード、または Confluent Cloud などのサービス向けの OAuth でサインインします。

  - **Tableau、PDF、Slack。** [Publish to Tableau ステップ](/ja/reference/workflow-steps/export/export-to-tableau/)は、Tableau Server または Tableau Cloud 上のデータソースを、作成、上書き、追加、またはアップサートします。[Export to PDF ステップ](/ja/reference/workflow-steps/export/export-to-pdf/)は、テーブルを PDF に書き込み、[Notify via Slack ステップ](/ja/reference/workflow-steps/notifications/notify-via-slack/)は、ファイルを添付できます。

- **新しいワークフローステップ。** [Delta Lake のインポート](/ja/reference/workflow-steps/import/import-delta/)、[ORC のインポート](/ja/reference/workflow-steps/import/import-orc/)、[Export to ORC ステップ](/ja/reference/workflow-steps/export/export-to-orc/)、[空間の再投影](/ja/reference/workflow-steps/spatial/spatial-reproject/)、[空間ファイルのエクスポート](/ja/reference/workflow-steps/spatial/spatial-file-export/)、[Update Excel Cells ステップ](/ja/reference/workflow-steps/document/document-excel-update/)、[Document Write Blob ステップ](/ja/reference/workflow-steps/text-documents/document-blob-write/)、[KNIME Rule Engine ステップ](/ja/reference/workflow-steps/tables/table-knime-rule-engine/)、そして、指定した時刻以前の最新のスナップショットにテーブルを戻す[テーブル: タイムスタンプへ復元](/ja/reference/workflow-steps/tables/table-restore-timestamp/)です。[NetSuite: SuiteQL クエリのインポート](/ja/reference/workflow-steps/netsuite/import-suiteql-query/)は、作成した SuiteQL クエリを型付きのテーブルにロードします。[ドキュメント: ファイルを暗号化、ドキュメント: ファイルを復号](/ja/reference/workflow-steps/document/encrypt-decrypt-file/)は、AES または Blowfish を使用するか、Excel ブックのパスワードを設定または削除し、キーは常に変数に保持されます。[ML: モデルの学習](/ja/reference/workflow-steps/machine-learning/ml-train/#その他のアルゴリズム)には、XGBoost、勾配ブースティング、サポートベクターマシン、クラスタリング、PCA が追加され、[ML: スコアリング](/ja/reference/workflow-steps/machine-learning/ml-score/#その他の出力列)には、クラス確率とモデルレポートが追加され、[テーブル: テキスト関数](/ja/reference/workflow-steps/tables/table-text-function/#その他の関数)には、文字列距離と JSON および XML の関数が追加されます。ファイルのインポートとエクスポートでは、Zstandard、Snappy、LZ4、LZO、Deflate のファイルを読み書きできます。

- **すでに使用しているステップにオプションが増えました。** すべてのオプションは、ステップのフォームのフィールドとして提供されます。

  - **インポート。** [Excelのインポート](/ja/reference/workflow-steps/import/import-excel/#シート対応表)は、ブックごとに異なるワークシートの組を読み取り、パスワード保護されたブックを開きます。[固定幅のインポート](/ja/reference/workflow-steps/import/import-fixed-width/#レイアウト)は、EBCDIC と Latin-1 のファイルを読み取り、[XMLのインポート](/ja/reference/workflow-steps/import/import-xml/#レコードの読み取り形式)は、繰り返される 1 つの要素をテーブルに読み取ります。ファイルの検索では、ワイルドカードと正規表現のパターンを使用できます。
  - **エクスポート。** CSV と Excel のエクスポートでは、既存のファイルに追記でき、ほとんどのエクスポートでは、すでにあるファイルを置き換えずに停止でき、CSV、Excel、JSON、SQL のエクスポートでは、行を並べ替えられます。[Export to Excel ステップ](/ja/reference/workflow-steps/export/export-to-excel/#分割)は、列の値ごとにシートまたはファイルを書き込め、[Export to CSV ステップ](/ja/reference/workflow-steps/export/export-to-csv/)は、Spark と同様に、引用符をエスケープしたり省略したりできます。
  - **テーブルとフロー。** [Table Extract ステップ](/ja/reference/workflow-steps/tables/table-extract/)と結合では、実行時に指定した列を引き継げるため、ピボットの後のステップに列の一覧は不要です。[テーブル: 和集合（すべて）](/ja/reference/workflow-steps/tables/table-union-all/#列の照合)は、位置でソースを積み重ねることができます。テーブルが存在するかどうかに応じてステップを実行できます（[テーブル存在条件](/ja/guides/workflows/step-conditions/#テーブル存在の条件)）。[Workflow Loop ステップ](/ja/reference/workflow-steps/workflow-control/workflow-loop/#反復が失敗した場合)は、失敗した反復があっても続行でき、[待機](/ja/reference/workflow-steps/general/wait/#時刻またはファイルの待機)は、時刻またはファイルの変更を待機できます。
  - **通知、AI、リモート SQL。** [Notify Via Email ステップ](/ja/reference/workflow-steps/notifications/notify-via-email/)には、Cc、Bcc、Reply-To が追加され、ドライバーテーブルの各行に個別のメールを送信できます。[Text: NLP (AI) ステップ](/ja/reference/workflow-steps/text-documents/nlp-ai/)は、埋め込みを書き込み、失敗した各呼び出しを報告できます。[リモート実行: SQL](/ja/reference/workflow-steps/agent/agent-remote-execution-of-sql/#行ごとに1回ステートメントを実行する)は、ストアドプロシージャなどのステートメントを、行ごとに 1 回ずつ実行できます。

- **REST Request フォームが、リクエストの作成と確認を支援します。** 大規模なエンドポイントカタログをフィルターしたり、Postman コレクション、OpenAPI 仕様、HAR ファイルを貼り付けたりドロップしたりできます。ヘッダーとパラメーターは、重複、入力ミス、平文で入力されたシークレットがないかチェックされ、テスト用のリクエストでは、整形されたレスポンスと、推奨される項目パスが表示されます。ステップには、ページ番号、カーソル、Link ヘッダーによるページング、プロキシ、Digest 認証と NTLM 認証によるサインイン、SOAP 呼び出し、小数のリクエストレート、実行中のジョブのポーリング、認証情報をマスクした上で各エラーを行として保持する生のレスポンスモードが追加されました。POST、PUT、PATCH は、レート制限の後には再試行されますが、サーバーエラーの後には再試行されません。[REST Request ステップ](/ja/guides/workflows/rest-request-step/)と [RESTリクエスト](/ja/reference/workflow-steps/general/rest-request/)を参照してください。

- **列、値、またはそれを使用するワークフローから、あらゆるテーブルを検索できます。** **テーブル** タブには、**ワークフロー別** フォルダー、一致した各列にデータを供給するテーブルと、その列から供給を受けるテーブルを示す **列ツリー** を備えた列検索、そして、入力した値を含む各テーブルと列を、すでに開くことができる行の範囲内で一覧表示し、結果をテーブルエクスプローラーで開く **データ内の値を検索… (低速)** ボタンがあります。**テーブルの詳細** には、テーブルの **公開名** がコピー用ボタン付きで表示され、Snowflake または Databricks ウェアハウスでは、削除ウィンドウに、テーブルが最後に読み取られた日時と読み取った人が表示されます。ドキュメントアカウントについては、**使用箇所** に、そのアカウントを使用するすべてのステップ、ワークフロー、プロジェクトのデフォルトが一覧表示され、**参照先を変更...** ボタンで、プレビューの後に別のアカウントに移行できます。[テーブルを検索する](/ja/guides/projects/managing-tables-and-views/#テーブルを検索する)、[値を検索する](/ja/guides/projects/managing-tables-and-views/#値を検索)、[最後の読み取り](/ja/guides/projects/managing-tables-and-views/#最後の読み取り)、[ドキュメントアカウントの使用箇所と参照先の変更](/ja/guides/documents/account-management/document-account-used-by/)を参照してください。

- **CSV を任意のプロジェクトのテーブルにして、すぐに概要を確認できます。** プロジェクトの **テーブル** 一覧に CSV をドロップするか、**新規** > **CSVファイルからテーブルを作成** を選択すると、PlaidCloud が新しいテーブルとしてインポートします。**新規** > **CSVファイルからプロジェクト** は、CSV からプロジェクトを作成します。その後、**データの概要** には、行数、各列の型、空の値の割合と個別値の割合、スターターチャートが表示され、ワンクリックでスターターダッシュボードを作成できます。[CSVファイルをインポートする](/ja/guides/projects/managing-tables-and-views/#csvファイルをインポート)と [独自の CSV で始める](/ja/get-started/quickstart/#自分の-csv-から始める)を参照してください。

- **高度なワークフローのキャンバスを、より直接的に配置、編集できます。** **Cmd** または **Ctrl** を押しながらステップをドラッグして、コンテナーの内外に移動し、実行コンテナーの出力を **出力ポート** から接続します。**配置** メニューは、ステップの順序を維持し、メモをステップとともに移動しながら、ステップを整理、整列、均等配置、スナップします。それぞれ 1 回の **元に戻す** で取り消せます。何もない場所を右クリックすると、クリックした場所にステップをコピーして貼り付けられます。選択したステップの **ステップを作成** は、そのステップが書き込むテーブルから、結合または抽出を開始し、未保存の変更があるウィンドウは、破棄する前に確認します。ステップの入力または出力の目のアイコンは、まさにそのテーブルのプレビューを開きます。[コンテナー](/ja/guides/workflows/advanced-workflows/#コンテナー)、[キャンバスを整理する](/ja/guides/workflows/advanced-workflows/#キャンバスを配置する)、[高度なキャンバスでのコピーと貼り付け](/ja/guides/workflows/copy-paste-steps/#高度なキャンバスでのコピーと貼り付け)、[ステップを作成する](/ja/guides/workflows/workflow-explorer/#ステップの作成)を参照してください。

- **高度なワークフローを最適化して、より速く実行できます。** ワークフローを右クリックして **最適化…** メニューを選択すると、変更が行われる前に内容を確認できます。**Rebuild dependencies from data lineage** は、各ステップを、そのテーブルを使用するステップにのみ接続するため、独立したステップが並列で実行され、**Merge** は、一連の Extract Data ステップを 1 つに結合しますが、現在のデータで両方のバージョンが同一の結果を返した場合にのみ適用されます。ウィンドウには、短縮された時間が表示され、最適化できなかった各ステップが理由とともに一覧表示され、**最適化を元に戻す…** メニューでワークフローを復元できます。[ワークフローを最適化する](/ja/guides/workflows/optimize-a-workflow/)を参照してください。

- **実行する前に、結合のキーを正しく設定できます。** **Join Map** の **自動判定** は、同じ 2 つのテーブルを結合している別のステップのキー、次にメトリック、次にテーブルのキー列、次に一致する名前の順に使用し、どれを使用したかを示します。**キーを確認** は、結合先のテーブルで繰り返されるキー値の数をカウントします。これらは、行数を増やす可能性があります。**ソースを検査** がステップの列を入力するとき、`customer_id` などの識別子の列は、**合計** ではなく **グループ化** から始まります。[Inner Join](/ja/reference/workflow-steps/tables/table-inner-join/#キーを確認)を参照してください。

- **AI アシスタントと Microsoft 365 Copilot が、データについてさらに多くを把握し、より多くのことを実行できます。**

  - **分析パスと列ごとのガイダンス。** 各分析パスには、常に適用されるフィルター、会計カレンダー、ビジネス用語向けの **プロンプトガイダンス**（最大 1,000 文字）があります。列のメモは、テーブルの列とともにアシスタントと LLM ステップに伝わるため、コードやフラグが意図したとおりに解釈されます。[AI アシスタント向けにパスを役立てる](/ja/integrations/ai-coding-agents/analysis-paths/#aiアシスタントに役立つパスにする)を参照してください。
  - **Copilot の機能強化。** Microsoft 365 Copilot の PlaidCloud エージェントは、CSV、Excel、PowerPoint、Word のファイルを作成し、ビジネス上の数値をメトリックから回答し、内訳をテーブル全体で集計し、配賦の仕組みを説明します。管理者は、更新されたパッケージをダウンロードして、Teams 管理センターで更新します。[Microsoft 365 Copilot](/ja/integrations/microsoft-365-copilot/)を参照してください。
  - **1 回の呼び出しでより多くを実行。** アシスタントは、行アクセスを先に適用した上で、サーバー上でテーブルをグループ化して集計したり、PlaidCloud のドキュメントを検索して読み取ったり、OneDrive と SharePoint を含む、完全に構成されたドキュメントアカウントを書き込み専用の認証情報で作成したり、ラベルを追加するだけでなく削除したり、PlaidCloud で表示されるビューを操作したりできます。[分析パス](/ja/integrations/ai-coding-agents/analysis-paths/#mcp経由での使用)と [AI エージェントを使い始める](/ja/integrations/ai-coding-agents/getting-started/)を参照してください。

## 変更

- **Go To Metric は、Weave の検出事項が対象とするメトリックを開きます。** メトリックの数値が、クリックした時点で、ご自身の行アクセスの範囲内で計算され、その元となったバージョンを示す ✓ が付いて表示されます。異常な合計の場合は、Weave が判断した期間で Weave が示した項目です。他のメトリックの検出事項（他のメトリックから計算されるメトリックに関するものを含む）の場合は、メトリックの合計です。数値の下の **行へ移動** は、引き続き、変更の元となった行をテーブルエクスプローラーで開きます。[Go To Metric](/ja/guides/ai-assistant/weave-metric-insights/#メトリックへ移動)を参照してください。

- **1 つの Weave タブに、検出事項と Weave AI チャットがまとまりました。** チャットは、**Weave** タブ内の、**検出事項** の後ろのタブです。各検出事項は、それぞれ **修正**、**移動**、**既読にする** ボタンを持つカードで、Weave がチェックできなかったものは破線のカードで示され、チップで、注意が必要なものに絞り込めます。式に関する検出事項は、エラーの場所を示し、式そのものは **Weaveが把握する方法** にあります。Weave は、実行が終了したときに各問題を 1 回だけ通知し、1 つのプロジェクトに関するメッセージは、積み重なることなく 1 つにまとめられます。Weave は変更されたものだけを再チェックするため、大規模なプロジェクトでもタブがすばやく開きます。ワークフロー一覧の Weave 列はなくなりました。[Weave タブ](/ja/guides/ai-assistant/weave-tab/)と[実行の終了時に通知を受ける](/ja/guides/ai-assistant/weave-findings/#実行終了時の通知)を参照してください。

- **Ctrl/Cmd-K で、どの画面からでもコマンドパレットを開けます。** 入力する前に、最後に開いたものと、実行できる操作が表示されます。ホーム、プロジェクト、ダッシュボード、ドキュメントへの移動、ライトとダークの切り替え、AI の接続、ヘルプの表示などです。入力すると両方の一覧が絞り込まれ、2 文字以上になると、プロジェクト、ワークフロー、テーブル、ダッシュボード、Panel アプリも検索されます。[検索とコマンド](/ja/guides/launcher/#検索とコマンド)を参照してください。

- **ステップの問題は、実行時ではなく、保存時に検出されます。** 実行が失敗する、または誤った結果になる設定のステップは、保存が拒否され、何を変更すべきかがメッセージで示されます。各ステップのリファレンスページに、チェックされる内容が一覧表示されています。マッピングされたソース列が、ステップまたはそのソーステーブルにもうない場合は、赤で示され、保存すると、**すべて削除して保存**、**このまま保存**、**キャンセル** を選べるダイアログが開きます。結合、ルックアップ、空間のステップは、そのような行を自動的に削除せず、そのまま残します。未定義の変数を使用している式は、その変数を示し、実行時に拒否されたステップは、その理由を分かりやすい言葉で説明します。[一覧にない状態になったソース列](/ja/reference/workflow-steps/tables/table-extract/#一覧になくなったソース列)、[ソーステーブルにない列](/ja/reference/workflow-steps/tables/table-extract/#ソーステーブルに存在しない列)、[ステップエラーを管理する](/ja/guides/workflows/managing-step-errors/)を参照してください。

- **存在しないソースや空のソースは、決してエラーになりません。** ファイルが存在しない、または空のファイルインポートは、パスを示す警告付きで完了し、ターゲットテーブルは宣言された列を持つ空の状態のままになるため、後続のステップは 0 行を読み取ります。存在しないフォルダーや空のフォルダーに対するドキュメントのステップは、「Nothing to process」と報告し、ワークフローは続行されます。リモートファイルのステップは、存在しないパスについて警告し、安全でないパスは拒否します。ファイルが存在しないことのチェックは、OneDrive、SharePoint、SFTP で機能します。バッチテーブルが空の **レポート: バッチ生成** は、警告付きで完了し、レポートを生成しません。[インポートステップ](/ja/reference/workflow-steps/import/)、[ドキュメントワークフローのステップ](/ja/reference/workflow-steps/document/)、[ドキュメントパス条件](/ja/guides/workflows/step-conditions/#ドキュメントパスの条件)を参照してください。

- **大規模なワークフローが確実に実行され、停止でインポートとエクスポートがキャンセルされます。** PlaidCloud が混み合っているときは、ステップは失敗せずに容量を待機し、ステップがキューに溜まると容量が追加されます。外部データベーステーブルのインポートは、最大 10 個のテーブルを同時に実行します。ステップを実行しているサーバーが失われた場合、出力を置き換えるステップは自動的に再実行され、安全に繰り返せないステップは、*interrupted* というメッセージで一度だけ失敗します。**停止** は、実行中のインポートジョブとエクスポートジョブをキャンセルし、停止した実行は「Stopped」と報告されます。[中断されたステップ](/ja/guides/workflows/run-a-workflow/#中断されたステップ)と[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)を参照してください。

- **すべての Lakehouse で、保存と計算が同じになりました。** CSVのインポート、XMLのインポート、Import Table Archive の空のフィールドは、null としてロードされるため、後続のステップで `= ''` や `= 0` をテストしている場合は、代わりに null をテストする必要があります。`cast(x, Float)` はどこでも 64 ビットのため、大きな金額も桁が維持され、PlaidCloud が作成する Float 列は倍精度です。JSON 列、**Table: Delete Rows**、および集計する条件は、すべての Lakehouse で機能します。Solver、Forecast、pandas で実行する場合の Pivot と Allocation Split など、独自の結果を構築するステップは、それらを型付きのデータとして、はるかに高速にロードします。テーブルエクスプローラーには、数値列の最小値、最大値、平均、合計、標準偏差、分散が表示されます。[Float へのキャスト](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#floatへのキャスト)と[列データと一意の数](/ja/guides/data/table-explorer/#列のデータと一意な値の数)を参照してください。

- **ファイルのエクスポートで型が維持されます。** Parquet ファイルでは、整数列が整数のまま維持され、タイムスタンプはマイクロ秒で保存され、タイムゾーンは UTC と表記されます。Avro ファイルでは、日付、タイムスタンプ、ブール値が型付きで維持され、1 つのテーブルの Avro エクスポートには、エクスポートの名前が付けられます。Parquet エクスポートで複数のファイルを選択すると、Parquet は 1 つのファイルを書き込むというメッセージとともに停止します。非常に大きな Parquet、ORC、JSON のエクスポートは、行を読み取りながら書き込まれるため、メモリ不足にならなくなり、Parquet では選択した圧縮方式が使用されます。バージョン 1.2.33 以降の PlaidLink エージェントは、エクスポートされたテーブルを Parquet ファイルとして受け取ります。[Export to Parquet ステップ](/ja/reference/workflow-steps/export/export-to-parquet/)、[Export to Avro ステップ](/ja/reference/workflow-steps/export/export-to-avro/)、[データがエージェントに届く仕組み](/ja/reference/workflow-steps/agent/agent-remote-import-table-into-sql-database/#データがエージェントに届く仕組み)を参照してください。

- **ERP への転記は各スケジュールのモードに従い、不確かな応答は確認のために保留されます。** スケジュールされたイベントは、プロジェクトの設定を上限として、**本番**、**シミュレート**、**オフ** のいずれかの独自の転記モードを保持し、**選択したイベントを実行** は、各イベントのモードを使用します。タイムアウトやサーバーエラーなど、PlaidCloud が確認できない ERP の応答は、却下として記録されるのではなく、保留中として保持され、転記を 2 回取り消すことはできません。転記レジスターには **reversal outstanding** の転記が一覧表示され、アーキテクトは、プロジェクトのホームページの **ERP書き込み承認** で、プロジェクトに転記を許可します。[ERP 転記モード](/ja/administration/scheduled-events/event-scheduler/#erp転記モード)、[取り消し](/ja/guides/connections/posting-register/#取消)、[プロジェクトに転記を許可する](/ja/guides/workflows/run-a-workflow/#プロジェクトに転記を承認する)を参照してください。

- **行アクセスはグループの変更に追従し、問題の内容を示します。** シングルサインオンがサインイン時に設定するグループメンバーシップは、約 15 分以内にダッシュボードの行アクセスに反映され、デフォルトのグループの新しいメンバーには、約 1 分以内に行が付与されます。行アクセスのウィンドウは、制限が何もフィルターしていない場合に警告し、`&`、`/`、`%` を含む列名を処理し、同期が失敗したときは、理由付きの **エラー** と、**再試行** ボタン付きの **再試行中** を表示します。[ダッシュボードを同期した状態に保つ](/ja/administration/access/managing-security-groups-and-assignments/#ダッシュボードの同期の維持)を参照してください。

- **ユーザー定義関数が、新しいライブラリを備えた Python 3.14 で実行されます。** ほとんどの関数は、そのまま実行されます。numba をインポートする関数や、`cgi`、`telnetlib` など、Python が削除した標準ライブラリのモジュールをインポートする関数は、失敗するようになり、書き直す必要があります。Forecast の AutoTheta の境界は、以前の実行とわずかに異なる場合があります。[User Defined Transform](/ja/reference/workflow-steps/general/user-defined-transform/)を参照してください。

- **フルエージェントアクセスは非推奨となり、2027 年 1 月 15 日に削除されます。** **完全** アクセスを使用する LLMステップは、警告をログに記録します。**読み取りと書き込み** に移行してください。そこでは、エージェントは PlaidCloud の書き込みツールを通じてデータを変更し、LLMステップは、**書き込み** がオンになっているバインディングにのみ書き込みます。[エージェントアクセス](/ja/integrations/ai-architecture/llm-providers/#エージェントアクセス)を参照してください。

- **ドキュメントアカウントの設定と参照が簡単になりました。** OneDrive または SharePoint アカウントのファイルブラウザーは、開始パスの下のフォルダーを開きます。Google Cloud Storage アカウントには有効なサービスアカウントキーが必要で、キーのない既存のアカウントは、キーを追加するまで動作しなくなります。拒否された設定は、その理由を説明し、使用されていなかったバックアップアイコンは、**アカウントの管理** から削除されました。[Google Cloud Storage アカウントを追加する](/ja/guides/documents/adding-accounts/add-google-cloud-storage-account/)と[ドキュメントアカウントのバックアップ](/ja/guides/documents/account-management/managing-document-account-backups/)を参照してください。

- **Project アプリが、請求書、出張、遅延入力をより完全に扱えるようになりました。** 新しい請求書は、顧客と PO 番号を提供するマスタープロジェクトから開始します。下書きの請求書を削除すると、その時間と出張が再び請求可能になり、**売掛金の受信者** で、請求書が提出されたときにメールを受け取る人を設定します。出張のドロワーには、各明細のベンダー、カテゴリ、監査状況が表示され、**遅延入力の時間を追加** は、承認済みの週のシートを開始します。[Project アプリで時間と経費を記録する](/ja/guides/time-expense/track-time-and-expenses/)を参照してください。

- **参照されていないテーブルをすべて削除していた API 呼び出しは削除されました。** 代わりに、ID を指定してテーブルを削除してください。

- **アプリ全体のその他の小さな変更。** アカウント、ダッシュボード、メンバー、グループ、セットアップの一覧で行をダブルクリックすると、それが開きます。空の **ディメンション**、**データエディター**、**UDF**、**ステップ** タブには、次に何をすればよいかが表示され、アプリを持たないメンバーはランチャーに移動します。ステップのテーブルセレクターには、テーブルが最後に更新された日時が表示されます（[ソーステーブルの最終更新を確認する](/ja/guides/workflows/create-workflow/#ソーステーブルの最終変更日時の確認)）。Export External Database Tables は、独自のタブで列をマッピングし、**レポート: バッチ生成** には、使用されていない **Report Constants** セクションが表示されなくなりました。Convert Encoding は、中央ヨーロッパ、トルコ、アラビアのエンコーディングを認識します。削除された画面へのリンクは、その旨を表示します。

## 修正

- **AI アシスタントは、承認するまで何も変更せず、名前は記述どおりに表示されます。** ステップを新しいテーブルに構築すると、承認する前にテーブルが作成されていましたが、現在は、承認後にテーブルとステップがまとめて作成されます。また、プロジェクト、ワークフロー、ディメンションの作成、テーブルのコピー、テーブルのプロパティやラベルの変更でも、先に確認されます。承認は、次の返信にのみ有効です。アシスタントが提案するインポートまたはエクスポートは、そのテーブル、ドキュメントアカウント、ワークフローを名前で示し、存在しないものや、開く権限がないものとともに提示されることはありません。アンダースコアを含む名前は、斜体にならずに正確に表示され、テーブルとコードはダークテーマでも読みやすく、図は文字として表示されずに描画され、式エディターの Weave パネルは、編集中の式を読み取ります。アシスタントは、名前のないテーブルがあってもプロジェクトのテーブルを一覧表示し、ステップが複数のテーブルを読み書きしている場合でも、エラーで停止せずに、どのステップがテーブルを読み書きするかに回答します。[ワークフローステップを構築する](/ja/guides/ai-assistant/weave-tab/#ワークフローのステップを作成する)を参照してください。

- **ファイルのインポートが、指定したものを読み取ります。** Excelのインポートは、列全体の範囲と XLSB ブックを読み取り、zip 形式のブック内のシートを見つけ、パディングや改行のあるヘッダーでも失敗しなくなりました。CSVのインポートは **スキップする行** に従うため、SAP のリストエクスポートのように、ヘッダーの上に行があるファイルも、列名でインポートされ、デフォルトの区切り文字、引用符、エスケープ文字で実行されます。1 つのソース列で複数のターゲット列にデータを供給でき、列がすべて固定値のインポートはすべての行をロードし、大文字の圧縮拡張子が付いたファイルは展開され、変更がなければスキップするインポートは、空にされたテーブルを再ロードします。AI アシスタントに **プロジェクトのデフォルト** からファイルをインポートするよう依頼すると、プロジェクトのデフォルトのドキュメントアカウントが読み取られ、プロジェクトに設定がない場合は、その旨が分かりやすく通知されます。新しい列の型を持つ Parquet ファイルは、ドキュメントで開きます。[Excelのインポート](/ja/reference/workflow-steps/import/import-excel/#読み取り対象)と[CSVのインポート](/ja/reference/workflow-steps/import/import-csv/#行の選択)を参照してください。

- **ワークフローのステップが、設定どおりに保存され、実行されます。** テーブル: アップサートのステップは、**更新キー** 列が戻り、再び保存できるようになりました。テーブル: プロジェクト間コピーは、ターゲットプロジェクトを名前で指定し、データ共有を通じて読み取ります。ドキュメント: ダッシュボードをPDFとして保存は、列の型を維持し、テーブル: 和集合（重複なし）と和集合（すべて）は、列を名前で一致させます。複数テーブル結合は、複数の入力を指定して保存でき、スペースを含む列名を受け付けます。Table Lookup は、ルックアップ列の集計設定を無視し、SCD-2時点指定結合は、日付として変数を受け付けます。LLMステップは、4.6 より古い Claude モデルで実行され、AI アシスタントが編集してもモデルが維持されます。REST Request は、行の値を一度だけエンコードして送信し、リモートデータベースへのエクスポートは、行をコミットします。[更新キー](/ja/reference/workflow-steps/tables/table-upsert/#更新キー)、[データ共有の管理](/ja/reference/workflow-steps/tables/frame-project-copy/#データ共有の管理)、[複数テーブル結合](/ja/reference/workflow-steps/tables/table-multi-table-join/)を参照してください。ワークフローの削除、コピー、名前の変更、停止など、ワークフローを選択するステップは、存在しなくなったワークフローを *id (missing)* として表示したまま維持し、一覧の最初のワークフローに切り替わることはなくなりました。

- **ワークフローの実行が、意図どおりに完了します。** Workflow Loop ステップは、反復のたびにループ対象のワークフローを実行します。反復するコンテナーや、1 回の実行で複数回実行されるワークフローも同様です。ステップから、または並列グループ内から開始した実行は、正しいステップを実行して完了します。実行時間の長いインポートまたはエクスポートが 2 回開始されることはなく、PlaidCloud の更新中に停止することもなく、サーバーエラーで終了したアクションが再送されることもありません。データベースドライバーのクラッシュは、そのステップだけを、データベースが示す理由とともに失敗させます。実行履歴は、すべてのステップの行数をカウントし、作業を開始する前に失敗したステップは、その理由をワークフローログに書き込みます。[Workflow Loop ステップ](/ja/reference/workflow-steps/workflow-control/workflow-loop/)と[実行履歴](/ja/guides/workflows/advanced-workflows/#実行履歴)を参照してください。

- **プロジェクトのコピー、インポート、オープンが、予期せぬ動作なく行われます。** プロジェクトのインポートは、復元できたものをすべて維持し、除外したものを **インポート結果** ウィンドウに一覧表示し、進捗を表示し、失敗の理由を示し、再試行できます。選択したオブジェクトのコピーは、プロジェクトに変数がある場合でも機能します。プロジェクトを開いても設定は変更されなくなり、**独自のデータを取り込む** は CSV をインポートし、PostgreSQL ウェアハウスでのテーブル作成も機能します。App Runner のアプリは、PlaidCloud の更新時に自動的に更新され、行を制限するプロジェクトの閲覧者に対しても機能します。[アーカイブの一部がインポートされない場合](/ja/guides/projects/archive-a-project/#アーカイブの一部がインポートされない場合)と[アプリを最新の状態に保つ](/ja/guides/workflows/use-converted-alteryx-apps/#アプリを最新の状態に保つ)を参照してください。

- **ディメンションと配賦が、正しくロードおよび読み取られます。** 親子形式のロードは、親が空の行を最上位のメンバーとして保持し、メイン階層外のメンバーは、あらゆる種類のロードで、2 つ目の代替階層に対して拒否されます。階層に含まれない親の下にメンバーを移動することは拒否され、ディメンションのステップは、見つからなかったディメンションの名前を示し、空白を含む列を貼り付けても、各値が各行に維持されます。大きなディメンションを読み取っても、ワークスペース内の他のユーザーを待たせることはなくなりました。ディメンションプロパティの **階層** を **未指定** のままにした配賦ルールも実行されます。[代替階層へのロード](/ja/reference/workflow-steps/dimensions/dimension-load/#代替階層へのロード)と[ディメンション型のプロパティとメンバーピッカー](/ja/guides/dimensions/dimensions/#ディメンション型のプロパティとメンバーピッカー)を参照してください。

- **ワークフローのキャンバスと画面が、正しく動作します。** **ワークフローにドリルダウン** は、高度なワークフローをキャンバスで開き、キャンバスはすべてのワークフローを開き、レイアウトの一部を読み取れなかった場合は通知します。収まらないツールバーのボタンは **その他** メニューに移動し、一覧は、保存するとすぐに更新されます。通知はメッセージ全体を表示し、警告は **ログ** タブに警告アイコンを表示し、テーブルエクスプローラーは、列のプロファイルが失敗したときにそれを示し、データエディターは、空の日付セルを空のまま維持します。列フィルターをオンにしたままデータエディターを保存すると、フィルターで非表示になっている行は、行の追加、削除、移動の後も維持されます。ユーザー定義関数エディターは、変更を許可されたすべてのユーザーに対して、編集可能な状態で開きます。[キャンバスがワークフローを開けない場合](/ja/guides/workflows/advanced-workflows/#キャンバスでワークフローを開けない場合)を参照してください。**テーブル** 一覧からテーブルを削除するとき、`/Periods/{period}/Sales` のように変数パスを介してのみテーブルに到達するステップがあれば一覧表示され、強制した場合にのみそのテーブルが削除されます。[削除](/ja/guides/projects/managing-tables-and-views/#削除)を参照してください。

- **メンバーと接続が、正しく動作します。** **ワークスペースメンバーを追加** は、シングルサインオンで作成されたアカウントを含む、すでにアカウントを持っているユーザーに対して機能し、そのユーザーが持つプロジェクトのロールを下げることはありません。ODBC 接続は、PlaidLink エージェントのマシン上の DSN またはドライバーを介して接続します。OAuth 認証情報を拒否したプロバイダーについては、認証情報の再入力または再認可が案内され、Databricks のサンプルとエクスポートは、期限切れが近いトークンを更新し、古いデータベースタイプの接続も削除できます。**使用箇所** には通知ステップが含まれ、無料のワークスペースでは、日次、週次、月次のバックアップが保持されます。[メンバー管理](/ja/administration/access/member-management/)と [ODBC](/ja/reference/connectors/databases/odbc/)を参照してください。

- **REST API と AI アシスタントのツールが、依頼どおりに動作します。** メンバー、グループ、スケジュールされたイベントの部分更新は、指定したフィールドだけを変更するため、一時停止中のイベントは一時停止のままです。指定したステップから実行を開始すると、そこから開始し、テーブルのスナップショットを復元すると、安全用のスナップショットと監査記録が保持されます。AI ツールからのドライバーのホワットイフは、モデルが実際に行った配分と一致する場合にのみ回答します。以前はサーバーエラーで失敗していたリクエストは、正常に動作するか、何が問題だったかを説明するようになりました。[配賦をトレースする](/ja/integrations/ai-coding-agents/tracing-allocations/)と[スナップショットを元に戻す、または復元する](/ja/guides/data/table-snapshots/#スナップショットを巻き戻しまたは復元する)を参照してください。

## セキュリティ

- **AI アシスタントは、お客様の権限の範囲内にとどまります。** アシスタントのデータクエリは、実行前に構造がチェックされ、単一の読み取りクエリのみが実行されます。Microsoft 365 Copilot を含む、読み取り専用の AI 接続は、ファイルのエクスポート、ダッシュボード PDF の保存、別のプロジェクトへの行のコピー、REST 接続を通じた変更の送信を行えません。AI アシスタントを通じたインポートは、ご自身として、指定したプロジェクトで実行され、会話を続けられるのは開始した本人だけです。アシスタントとテーブル参照では、ロールによって非表示になっているテーブル、ステップ、ワークフロー、ディメンションは除外され、Weave は、開けない失敗したステップを、名前を示す代わりに件数として数えます。[アクセスレベル](/ja/integrations/microsoft-365-copilot/#アクセスレベル)、[ロールによって非表示になるもの](/ja/guides/ai-assistant/weave-tab/#ロールで非表示になる内容)、[過去の会話を管理する](/ja/guides/ai-assistant/weave-tab/#過去の会話を管理する)を参照してください。

- **ERP への転記が、制御を回避できなくなりました。** 職務分掌がオンの場合、取り消しは転記レジスターを経由し、そこで承認が適用されます。コピーまたはインポートしたプロジェクトは、転記の権限を引き継がなくなり、SAP と EBS の転記をエージェントに直接送信できなくなり、テスト専用モードの SAP Post ステップには、本番の転記と同じ権限が必要です。これらのチェックなしに Sage Intacct へ転記していた、文書化されていないエンドポイントは削除されました。ERP 接続と REST 接続のエラーメッセージには、認証情報が含まれません。[職務分掌](/ja/guides/connections/posting-register/#職務分掌)を参照してください。

- **シークレットは書き込み専用で、接続を誰が使用するかを決められるのは所有者だけです。** ドキュメントアカウントのキー、パスワード、トークンは、保存した後は二度と表示されず、アカウントの接続先を変更するには、再度シークレットが必要です。ステップ内のパスワードとキーは変数にのみ保持され、ステップに直接入力されていたシークレットは、アーキテクトにのみ表示されるプロジェクト変数に移されました。複数行の認証情報は、入力中にマスクされます。接続にアクセスできる人を変更できるのは、接続の所有者またはワークスペース管理者だけです。[保存されたシークレットは書き込み専用](/ja/guides/documents/adding-accounts/#保存されたシークレットは書き込み専用)、[キーは変数に保持される](/ja/reference/workflow-steps/document/encrypt-decrypt-file/#キーは変数に保持する)、[接続を作成して管理する](/ja/guides/connections/create-connection/#セキュリティモデル)を参照してください。

- **使用できないドキュメントアカウントは、お客様に対して閉じられたままです。** ファイルが存在するかどうかのチェック、Parquet、Avro、ORC、Delta ファイルの列の読み取り、**取り込み** によるインポートステップの列の入力、AI アシスタントによるファイル検査は、閲覧がすでにそうであったように、アクセス権のないアカウントを拒否するようになりました。

- **ワークスペース管理者を変更できるのは、ワークスペース管理者だけです。** 管理者の編集、無効化、削除、グループの変更、誰かを管理者にする操作は、いずれもワークスペース管理者が必要です。[ワークスペース管理者を変更する](/ja/administration/access/member-management/#ワークスペース管理者の変更)を参照してください。

- **データ共有は、共有が付与されたプロジェクトのメンバーに対してのみ有効です。** 共有を通じた読み取りには、受信側のプロジェクトでのロールが必要で、書き込みには、**書き込み** 共有と、そこでのマネージャーまたはアーキテクトのロールが必要です。[プロジェクト間でデータを共有する](/ja/guides/projects/managing-projects/#プロジェクト間でのデータ共有)を参照してください。

- **復元は、指定した項目にのみ適用されます。** 以前のバージョンの復元は、その項目自体を復元し、権限チェックはその項目に対して行われます。内容が、自身のヘッダーのディメンションに属さないディメンションのバックアップファイルは、拒否されます。[バージョン履歴](/ja/guides/projects/managing-projects/#バージョン履歴)を参照してください。

- **テンプレート、インポート、アーカイブは、安全でない内容を拒否します。** エクスポートテンプレートとレポートテンプレートは、与えられたデータだけを読み取るサンドボックスでレンダリングされます。インポートは、独自の設定からロードクエリを構築し、PlaidCloud のアーカイブには含まれない内容を持つプロジェクトアーカイブは拒否され、別のプロジェクトのレポートスキーマを共有することになるプロジェクトスラッグも拒否されます。[テンプレートで使用できるもの](/ja/reference/workflow-steps/export/export-templated/#テンプレートで使用できるもの)と[アーカイブを復元する](/ja/guides/projects/archive-a-project/#アーカイブの復元)を参照してください。

- **ダッシュボードは、PlaidCloud のサインインと行アクセスに従います。** ダッシュボードのサムネイルは、ご自身としてレンダリングされ、アカウントは PlaidCloud のサインインからのみ取得され、ダッシュボードは、エクスポートが生成する ZIP ファイルからのみインポートされます。[既存のダッシュボードをインポートする](/ja/guides/dashboards/learning-dashboard/#既存のダッシュボードのインポート)を参照してください。

- **ワークフローの実行を開始しても、実行の認証情報が返されなくなりました。**

- **ユーザー定義関数を実行する環境には、PySpark の Java ライブラリが含まれなくなりました。** これらには既知の脆弱性がありました。PySpark の DataFrame と SQL API は、引き続き Spark Compute Cluster に接続しますが、`SparkContext` や `RDD` をインポートする関数は、失敗するようになりました。[PySpark を使い始める](/ja/integrations/pyspark/getting-started/)を参照してください。

- **添付、復元、変換は、使用できるアカウントのみを読み取ります。** ファイルのメール送信、ファイルからのディメンションやテーブルアーカイブの復元、テーブルバンドルの検査やインポート、テンプレートからの Excel エクスポートの入力、Alteryx ワークフローの変換は、アクセス権のないドキュメントアカウントを拒否するようになりました。ディメンションをドキュメントアカウントにバックアップするには、そのアカウントへの書き込み権限が必要です。ワークフローのステップは影響を受けませんが、ファイルをメール送信するステップ、テーブルを復元するステップ、Excel テンプレートを入力するステップは、Personal Temp Drive から読み取れなくなります。

- **エクスポートは、書き込み権限のあるアカウントにのみ保存されます。** 任意の形式でのテーブルまたはクエリのファイルへのエクスポート、テーブルアーカイブ、プロジェクトアーカイブ、テーブルバンドルのエクスポート、プロジェクトからのローカル Python ワークフローの作成、REST レスポンスのファイルとしての保存、Alteryx または Prophecy ワークフローの変換には、保存先のドキュメントアカウントへの書き込み権限が必要になりました。クエリのエクスポートでは、そのプロジェクトを使用できるかどうかも確認されるようになりました。テーブルバンドルのインポートは、読み取りしかできないアカウントにインポートログを書き込まなくなりました。ワークフローのエクスポートステップは影響を受けませんが、Personal Temp Drive には保存できなくなります。
