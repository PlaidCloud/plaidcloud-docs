## 追加

- **コントロールプレーンの Trust Center で、セキュリティチームが PlaidCloud のセキュリティ文書を入手できます**。Admin と Security のユーザーは、組織の **Trust Center** を開いて、サブプロセッサーのリストや DPA などの公開文書をすぐにダウンロードできます。また、組織として一度だけセキュリティ文書の NDA に署名すると、SOC 2 Type II レポートなどの制限付き文書のロックが解除されます。他の Admin と Security のユーザーは、誰がいつ署名したかを確認できます。契約にすでに NDA が含まれている組織では、署名なしで文書のロックが解除されるよう、NDA を提出済みとしてマークできます。制限付きの文書のダウンロードには透かしが入り、記録されます。また、NDA の新しいバージョンは改めて承諾する必要があります。[Trust Center](/ja/administration/control-plane/trust-center/)を参照してください。
- **PlaidXL は Excel でレポートの作成、ドリル、説明、計画を行えます**。**PlaidCloud** リボンタブは**接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有**にグループ化されています。よく使うコマンドは **PlaidXL** の右クリックメニューと **PlaidXL Cell** タブにもあり、主なコマンドには変更可能なキーボードショートカットがあります（フィールドへの入力中は動作しません）。コマンドが失敗した場合は、どのコマンドがなぜ失敗したかが表示されます。サインイン前に実行したコマンドはサインイン画面を開き、サインイン後に一度だけ実行されます。サインインは1つのワークスペースに対して有効なため、ワークスペースを切り替えると新しいワークスペースへのサインインが求められます（元に戻す場合は不要です）。また、Office で Microsoft Entra の職場アカウントを使用している場合、PlaidXL がワークスペースを自動的に見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます**。**Report** タブは、テーブルからライブレポートをレイアウトします。1つのディメンションを行方向に、別のディメンションを列方向にドリルダウンし、各交点に `CELL` の値を配置します。**Build my first report** は、あなた自身のデータからサンプルを作成します。ドリルすると、レポートは行全体と列全体を挿入および削除し、入力した値、メモ、書式は行とともに移動します。[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます**。**Drill down**、**Drill up**、**Keep only**、**Remove only** は、ノード、ディメンションの見出し、またはレポートの値から、ノードをライブの `DRILL` 数式に変換し、その編集も行います。**Custom drill** は挿入前に行をプレビューし、メンバーピッカーはメンバーを挿入するか、ノードの子のドロップダウンをセルに追加します。`DRILL` は除外または展開するノードを受け取り、行をまたいで実行できます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明できます**。**Explain this number** は、値が何を計算しているか、現在の PlaidCloud と一致しているか、およびその値の元になっているテーブルとワークフローのステップを示します。**Show detail rows** は、値の裏付けとなる行を専用のシートに表示し、合計が一致するかどうかのチェックも行います。
  - **Excel でガバナンスされたメトリックを利用できます**。`PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるとおりにビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計では `0` を表示し、それ以外では理由とともに `#VALUE!` を表示します（`CELLS` のスピルでは空白）。**Metric...** は、プロジェクトのメトリックを現在の値とともに一覧表示します。メトリックは複数の代替階層でフィルターでき、代替階層のメンバーと他のディメンションのメンバーを組み合わせることもできます。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに入力して計画できます**。`CELL` の値に数値を上書き入力すると、PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの形状に合わせた配分、金額またはパーセンテージによる調整が可能で、保留したセルは変更されません。平均、中央値、最小、最大、標準偏差、分散のセルにも入力値を指定でき、入力値は、行や列が挿入または削除されてもセルに追従します（削除されたセルの値は報告されます）。**Undo last write** は、入力値と保存を新しいものから順に取り消します。書き込みを取り消せるのは、その書き込みを行ったユーザーとワークスペースのみです。合計の取り消し、または空のセルに入力した平均の取り消しでは、その後に同じセルへ書き込まれた内容が保持されます。また、完了前に中断された書き込みは取り消せません。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要なものだけを更新できます**。シート、選択範囲、またはすべてのテーブルを更新でき、各テーブルの進行状況と**キャンセル**はタスクペインに表示されます。または PlaidXL の数式のみを再計算します。取得したテーブルは、データ型ごとに書式設定された Excel テーブルとして取り込まれ、更新時に独自の列と数値書式が保持され、それぞれの場所で更新されます。取得や更新で他のセルが上書きされたり、別の Excel テーブルと重なったりすることはなく、Excel で扱えないほど大きい整数の ID や1900年より前の日付はテキストとして取り込まれます。テーブルを再度取得しても更新リストに2回追加されることはなく、**Stop refreshing** で1つをリストから外せます。また、ディメンションはテーブルとともに更新されます。[すべてのテーブルを更新](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます**。**Save to PlaidCloud** は確認なしで書き込み、実行した内容を表示し、**元に戻す**を提供します。これは Lakehouse テーブルでは各保存後 最大7日間有効です。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーの場合、置き換えられるのはそれらの行のみであり、他のユーザーの行は保持されます。取得後にメンバーが変更されたドリルスルーのシートは保存されません。保存に失敗した場合は、テーブルを元に戻せるようリストアポイントの名前が表示されます。[テーブルを PlaidCloud に保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)を参照してください。
  - **Excel で Weave に質問できます**。**Weave** タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼するか、**Ask Weave about this cell** を選択します。Weave はあなたとして PlaidCloud を読み取り、ブックのみを変更します。入力済みの内容を置き換える前に確認し、ブックの外に及ぶ数式は書き込まず、各変更はペインを再読み込みするまで元に戻せます。[Excel で Weave に質問する](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1つのシートまたはブック全体の値のみのコピーを共有できます**。**Convert to values** は、ブック全体、1つのシート、または元に戻せない値の変換を行い（実行前に確認します）、PlaidXL の数式とそのスピルのみを変更します。まだ計算中の数式は再試行できるように残され、シートの名前を変更した後でも **Restore PlaidXL formulas** は引き続き機能します。
- **転記レジスターは、対応が必要なものから開きます**。確認が必要なものがある場合は**例外**、承認待ちのリクエストがある場合は**承認**、それ以外の場合は**すべての転記**から開きます。レールでは画面が**自分の対応待ち**、**レジスター**、**インサイト**、**設定**にグループ化され、**例外**と**承認**には件数が表示されます。すべての画面が1つのヘッダーとスコープバーを共有します。期間（**今月**、**前月**、**過去7日間**、**過去30日間**、**カスタム**）、接続、プロジェクト、環境、エンティティ、そして**本番**、**シミュレーション**、**すべて**を選択し、**リセット**するか、**Saved scope** を保持します。最後に使用したスコープは記憶されます。
  - **例外では、確認が必要なものが整理されます**。**要確認**、**未確認**、**保留中**、**失敗**、**取消待ち**のチップにそれぞれの件数が表示され、接続の状態を示す行には「All N connections posting normally」と表示されます。すべての転記には、次に何をすべきかを説明するツールチップ付きの、わかりやすい言葉による状態が付いています。未処理のものがない場合は **All clear** と表示されます。**Find a posting by ledger id** またはコマンドパレットに元帳 ID を貼り付けると、その転記が直接開きます。
  - **承認、委任、ウォッチは、受信トレイ形式の画面です**。**Waiting on me** と **Submitted by me** を切り替え、理由を添えて**承認**または**却下**し、複数をまとめて承認し、トーストから承認を**元に戻す**ことができます。**Delegate approvals** は短いダイアログで、**ウォッチ一覧**はフォローしているものを一覧表示します。**転記を取消**と、一括の再試行およびクリアのダイアログは、同じレイアウトを共有します。
  - **転記のドロワーで、何が起きたかがわかります**。状態とその意味、名前付きの主要な事実、**Lines**、**履歴**、**承認**のタブが表示され、**レビュー済みにする**、**再試行**、**取消…**、**接続をウォッチ**、**実行をウォッチ**、**Copy link**（その転記を直接開きます）があります。
  - **アシスト、エクスポート、保持期間も同じデザインに従います**。**アシスト**には質問ボックスとインサイトカード、**Draft — nothing applied** と表示されるアドバイス、**すべての転記**の異常カードと**これらを表示**があります。**エクスポートとアラート**には **New schedule** があり、**保持期間**は1枚のカードです。
  - **レジスターは常に最新の状態に保たれます**。転記が変更されるとレールのバッジが更新され、転記が変更されると開いている一覧に**更新**が表示され、開いているドロワーはその場で更新されます。**ホーム**の**要対応**の下には**転記レジスター**カードが表示されます。[転記レジスターの確認](/ja/guides/connections/posting-register/)を参照してください。
- **プロジェクトホームは6つのページで構成されます**。テキストのみのレールには、**概要**、**変数**、**スケジュールとセンサー**、**アクセスと共有**、**データと接続**、**アプリとブランディング**が一覧表示され、変数の数と、アクティブなスケジュールおよびセンサーのバッジが付きます。**概要**には、プロジェクトの説明とラベル、ロックの状態、テーブル、ワークフロー、ステップ、変数、公開済みテーブル、**データサイズ**（**ストレージ**が開きます）のタイル、次の3回のスケジュール実行、プロジェクトのデフォルトが表示されます。**データサイズ**は**プロジェクト**画面に表示されるものと同じ合計で、復元用に保持されている以前のバージョンも含まれ、現在のデータと以前のバージョンを分けて示すツールチップが付きます。また、**プロジェクトレポート**（PDF またはインタラクティブ HTML）と**アーカイブのエクスポート**もあります。他のページでは、変数、スケジュールとセンサー（**Calendar view** と **Activate** または **Deactivate** 付き）、プロジェクトとそのダッシュボードを開けるユーザーおよびそのテーブルを読み取れるプロジェクト、ERP 転記モードを含む接続とテーブルストレージのデフォルト、そして Panel アプリ、ブランディング、プロジェクトのタイル画像を管理します。ロックされたプロジェクトにはバナーが表示され、そのコントロールは無効になります。[プロジェクトホーム](/ja/guides/projects/project-home/)を参照してください。
- **ドキュメントは概要から開き、ページのレールがあります**。**概要**、**参照**、**Your accounts**、**管理**がレールに並び、各ページにはタイトルとサブタイトルがあり、そのアクションはヘッダーにあります。**概要**には、アカウントのタイル、フォルダーでファイルが選択された状態で**参照**を開く **Pinned** ファイル、サービス別のアカウント、そしてそれらを使用できるユーザーが表示されます。**Your accounts** は、使用できるすべてのアカウントを1つにまとめた一覧で、各行に **Shared** または**プライベート**のピルが付きます。**管理**には所有しているアカウントが一覧表示され、ワークスペース管理者はそこですべてのドキュメントアカウントを確認でき、他の方法で管理できる任意のアカウントを管理できます（システム管理のアカウントは拒否され、管理対象バケットのアカウントは複製できません）。行の **⋯** メニューには、**開く**、**編集**、**Clone…**、**Who can use it**、**使用箇所…**、**Version history**、**有効にする**または**無効**、**削除**があります。アカウントは、**一般**、**アクセス**、**Credentials**、SFTP の場合は **SSH** のカードを持つページとして開き、保存されていない変更がある状態で離れる前に確認されます。**参照**は、お気に入りのアカウント、またはワークスペースのデフォルトのアカウントを開き、ラベル付きのツールバー、行メニュー、2つのドロップゾーン（左はアカウントのルートへ、右は選択したフォルダーへアップロード）、そして各アップロードとテーブルへのインポートを進行状況とアクションとともに表示する **Uploads and imports** パネルがあります。**Pop out** は、フォルダーを新しいブラウザータブで開きます。[ドキュメント](/ja/guides/documents/)と[ドキュメントアカウントの使い方](/ja/guides/documents/using-document/)を参照してください。
- **ダッシュボードは概要から開き、ページのレールがあります**。**概要**、**ダッシュボード**、**アプリ**、**Notebooks**、そしてワークスペース管理者向けの**アクセスレビュー**がレールに並び、下部には、独自のウィンドウで開くことを示す印が付いた **Open navigator ↗** があります。各ページにはタイトルとサブタイトルがあり、そのアクションはヘッダーにあります。**概要**には、一致する一覧をすでにフィルターした状態で開く、ダッシュボードとアプリのタイル、最近開いた、またはスターを付けたもの、失敗したアプリと自分の対応待ちのアクセスリクエスト、そして利用状況へのアクセス権を持つメンバー向けに、最もよく開かれたダッシュボードが表示されます。**ダッシュボード**は**すべて**、**You manage**、**お気に入り**でフィルターし、**アプリ**には各アプリの**種類**とライブのステータスが表示されます。[ダッシュボードの使い方](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **ID は概要から開き、ページのレールがあります**。レールには、**概要**、**メンバー**、**ディレクトリ**、**セキュリティグループ**、**配布リスト**、続いて**セッション**、**セキュリティログ**、**APIクライアント**、**Group audit**、**All scopes** が一覧表示され、**利用状況レポート**はレールの横のページとして開き、**概要**、**アクティビティ**、**パス**、**メンバー**、**内容**、**エクスポート**、**ファネル**のタブがあります。各ページにはタイトルとサブタイトルがあり、そのアクションはヘッダーにあります。**概要**には、メンバー、アクティブなメンバー、一度もサインインしていないメンバー、ビルダーシート、現在サインインしているユーザーのタイル、**アクティブなメンバー**グラフ、**ウェルカムメールを再送信**と**確認**付きの**要対応**、そして過去7日間のセキュリティイベントが表示されます。メンバーは、**プロファイル**、**アクセス**、**Groups and data** のカードを持つページとして開き、**Invite member** は概要とホームの初回実行カードから使用できます。[メンバー管理](/ja/administration/access/member-management/)を参照してください。
- **一覧を標準行、ゆったり行、カードで表示できます**。**ダッシュボード**、**アプリ**、ERP レジスター、ID の**メンバー**などの一覧のツールバーにある**ビュー**メニューが、従来の高密度の切り替えに代わります。カードは、選択、並べ替え、列、右クリックの**コピー**、お気に入りのスターなど、一覧でできることをすべて維持します。**ダッシュボード**のカードにはサムネイルが表示されます。[標準、ゆったり、カードの表示](/ja/guides/dashboards/using-dashboards/#標準ゆったりカードの表示)を参照してください。
- **Lakehouse ウィンドウに、サイドレール、テーブルの詳細、タイムトラベルが加わりました**。**クエリ**、**プロファイル**、**ロード**、**カタログ**がレールに並び、**Administration** の下に **Lakehouse catalogs**、**Database users**、**Compute** があります。**Database users** と **Compute** は、Lakehouse 管理者または Lakehouse クラスターのロールを持つメンバーにのみ表示されます。**クエリ**は、SQL テキスト、ユーザー、種類、所要時間で履歴をフィルターし、**Copy SQL** でステートメントをコピーし、**Profile this query** でクエリを**プロファイル**で開きます。**カタログ**は、テーブルの列、現在のスナップショット、パーティション、場所、プロパティ、スナップショット履歴を開き、**Copy query as of this snapshot** は、その時点のテーブルを読み取る `FOR VERSION AS OF` クエリをコピーします。[Lakehouse ウィンドウ](/ja/guides/data/lakehouse-window/)を参照してください。
- **ステップフォームのプレビュー**。インポート: SQL、実行: SQL、SQL抽出、エクスポート: SQL、Salesforce: オブジェクトのクエリ では、ステップを実行せずに最大100行を表示し、Anaplan のビューとリストの読み取りでは、生成される列と型が表示されます。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように補完されますが、`{x:>9}` のような変数の書式はサポートされていません。プレビューは標準の SQL 関数のみを実行し、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトや、エージェントベースの Execute SQL ステップでは使用できません。[Import SQL](/ja/reference/workflow-steps/import/import-sql/) と [Extract SQL](/ja/reference/workflow-steps/tables/table-extract-sql/) を参照してください。
- **利用状況レポートで変化を確認し、グループに絞り込み、ワークフローに連携できます**。**概要**に、前の期間と比較した推移の矢印と、非アクティブなメンバーや誰も開かなかったダッシュボードとアプリを示す **Highlights** のリストが加わりました。無効化されたメンバーは、非アクティブとしてカウントも一覧表示もされません。**グループ**は、**概要**、**内容**、非アクティブの一覧を、1つのセキュリティグループのメンバーに限定します。日付範囲には**前月**と**今月**が加わり、すべてのタブで共有され、アカウントとともに記憶されます。すべての数値に説明が付き、テーブルには**メンバー**や**エリア**などのわかりやすい名前が使われ、行は Enter キーで開き、読み込みとエラーの表示がわかりやすくなり、最後の**ファネル**のステップには完了したメンバーの数が表示されます。**Get Workspace Usage** ステップは、メンバー名を含まない日別または月別の合計として、またはレポート用のデータセット（**メンバー**、**Daily per member**、**内容**、**Content per member**）として、スケジュールに従って利用状況をテーブルに書き込みます。メンバーのデータセットには、名前、メールアドレス、グループ、アクティビティが含まれるため、メールアドレスで自社の組織テーブルと結合し、部門別のアクティブ時間やダッシュボードの閲覧数をレポートできます。各実行は、**Get Workspace Members** と同様に、セキュリティログに記録されます。[利用状況レポート](/ja/administration/access/usage-reports/)と [Get Workspace Usage](/ja/reference/workflow-steps/general/get-workspace-usage/) を参照してください。
- **AI アシスタントがテーブルをプロファイルできます**。MCP 経由で、`table_profile` は、テーブルエクスプローラーに表示される列の統計とデータ品質レーダーのチェックに加えて、各列の最も一般的な値を、一度に最大50列、表示できる行に対してのみ返します。[AI アシスタントからのプロファイルの読み取り](/ja/guides/data/table-explorer/#ai-アシスタントからプロファイルを読み取る)を参照してください。

- **Git アプリがリポジトリを一覧表示し、できることを示します**。アプリリストの **Git** には、あなたのロール（**Administrator**、**Contributor**、**Viewer**）と、ワークスペースのリポジトリが、それぞれの説明、最終更新日、コピーボタン付きのクローンアドレス、**開く**とともに表示されます。**Set up Git on your computer** カードは、Git のインストール、トークンの作成、クローンの手順を案内し、**How to clone** で再び開けます。**View all in Git** は完全な Git インターフェースを開き、**Manage who can push** はグループ管理を開きます。アクセスは **Viewer**、**Contributor**（アプリのコードを `apps` にプッシュ）、**Administrator**（`udfs` を含むすべてにプッシュ）で、Viewer には問い合わせ先として最大3人のワークスペース管理者が表示されます。新しい **Git Contributors** グループは Contributor を付与し、デフォルトのグループにできるため、新しいメンバーに自動的に付与されます。**Git Administration** は Admin を付与します。メンバーの **Git** タブには、Git のユーザー名、レベル、それを付与するグループが表示されます。メンバーの Git アカウントはメンバーシップに追従します。メンバーを無効化または削除すると、約1時間以内に、トークンと SSH キーを含め、その Git アカウントがブロックされ、再有効化するとブロックが解除され、リポジトリと履歴は保持されます。シングルサインオンで Git にサインインすると、そのメンバー自身のアカウントが開きます。Contributor は、ワークスペースの Git 組織に直接リポジトリを作成できません。リポジトリは PlaidCloud を通じて作成されます。アプリのウィンドウには **Repository** セクションが表示され、UDF には**開く**があり、Git にはワークスペースへの **← Back to** リンクがあります。アプリのリポジトリや組み込みの `apps` および `udfs` リポジトリを含め、プラットフォームが作成するすべてのリポジトリは、ワークスペースのサインイン済みの全メンバーが読み取れるため、メンバーはリポジトリごとの設定なしでアプリを開いて再公開できます。Git 管理者は引き続きリポジトリをプライベートにでき、その場合、リポジトリピッカーから非表示になり、メンバーはそこからの公開や、そこに保存された Git ベースの UDF コードの実行ができなくなります。[PlaidCloud Git](/ja/guides/git/#gitを開く)と[リポジトリを閲覧できるユーザー](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)を参照してください。
- **Cost to Serve と Operational Transfer Pricing のテンプレートは、Common Finance Model を基盤としています**。**Cost to Serve** からプロジェクトを開始すると、各部門に設定したアクティビティとドライバーに基づいて営業費用を顧客に按分し、各顧客のサービス提供コスト差引後のマージンを、総勘定元帳に結び付けて確認できます。**Operational Transfer Pricing** から開始すると、各エンティティの利益水準（売上高利益率、ネットコストプラスまたは再販価格マイナス）をポリシーの範囲に照らしてテストし、範囲外のエンティティを目標に戻すための True-up を確認できます。売上高利益率は、EBIT を被テスト当事者の売上高で割ったものです。[Cost to Serve](/ja/guides/projects/cost-to-serve/) と [Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/) を参照してください。
- **OneStream と Anaplan が Data Foundation にデータを供給し、OneStream には読み取りステップがあります**。Data Foundation は、OneStream の管理者が構築するデータアダプターを通じて OneStream の連結結果を、エクスポートアクションを通じて Anaplan のプランを読み取り、グループの損益計算書をそれらと照合します。新しい **OneStream: Read Adapter** ステップは、アダプターを連結メンバーごとに1回呼び出して読み取り、任意のワークフローのテーブルに格納します。[OneStream for Data Foundation](/ja/guides/connections/onestream-for-data-foundation/)、[Anaplan as a Data Foundation Source](/ja/guides/connections/anaplan/#data-foundation-のソースとしての-anaplan)、[OneStream: Read Adapter](/ja/reference/workflow-steps/onestream/onestream-read-adapter/) を参照してください。
- **Data Foundation が共有コストを配賦する方法を選択できます**。**Actions > Allocations...** は、どのコストを配賦するか、何を基準に配賦するか、どこに計上するか、負のドライバーの場合にどうするかを、間接費の部門への配賦と、部門から製品および顧客への配賦の両方について案内し、プール、配賦済み、未配賦の内容を示す1か月分のプレビューを表示します。手動で編集したルールは保持されます。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。

- **Data Foundation は、ロードのたびにボードパックを書き込み、元に戻すことができます**。**ロード**のたびに、損益計算書ダッシュボードの Excel ブックと PDF が、ドキュメントアカウントのフォルダーに書き込まれます。レポートがオフの場合、パックはブックのみとなり、ダイアログにその旨が表示されます。リストアポイントは、各ロードの開始時と、マッピングまたはソースを変更する前に作成され、**Actions > Restore...** には、それぞれが元に戻すテーブルの数が表示され、ディメンションを含むプロジェクトを元に戻します。**Foundation** タブには独自のレールがあり、**Status**、**Answers needed**、**Source coverage**、**Sources** のページと、対応が必要なもののバッジ、すべてのページの上に変更を適用するための1つのバーがあります。また、何が起きているかがわかりやすくなりました。実行中の、または途中で停止した更新を表示し、テーブルのフォルダーがソースではない理由を説明し、**合計が一致することを確認**は、何かが一致するまで保留のままにし、ステータスの読み取りに失敗した場合は回復します。更新を適用しても、生成されたステップへの独自の編集は保持され、競合は通知されます。[ボードパック](/ja/guides/projects/data-foundation/#取締役会資料)と[リストアポイント](/ja/guides/projects/data-foundation/#復元ポイント)を参照してください。

## 変更

- **ワークスペースで Grok を使用している場合、モバイルの Weave は AI に関する通知への同意を再度求めます**。通知からは、xAI がデータをモデルのトレーニングに使用しないという記述がなくなりました。現在は、PlaidCloud と xAI の間にゼロデータ保持契約がないため、xAI がデータを保持し、標準の利用規約で許可された範囲で使用する可能性があると記載されています。[Weave によるデータの使用方法](/ja/guides/ai-assistant/weave-data-use/)を参照してください。
- **ホワットイフウィンドウは、1つの期間ずつ読み取ります**。Allocation Split ステップの出力に期間の列がある場合、ウィンドウは最新の期間で開き、**期間:** で別の期間または**すべての期間**を選択できます。すべての期間にわたって読み取るには大きすぎる、すべての期間に行があるドライバーを持つステップは、1つの期間について開いて回答するようになりました。保存されたシナリオは、保存時の期間があればそれを保持し、それを開くと、その期間が一覧にある間は、ウィンドウがその期間に移動します。[期間の選択](/ja/guides/allocations/results/driver-what-if/#期間を選択する)を参照してください。
- **PlaidCloud の Web アプリと Python クライアントライブラリは REST API を使用し、JSON-RPC は非推奨になりました**。Web アプリは、リクエストを REST API に送信します。`plaidcloud-rpc` 1.25.0 以降では、`SimpleRPC` の呼び出しはコードを変更することなく REST API に送られます。REST API がまだ対応していない呼び出しや、古いリリースのままのワークスペースでは、これまでどおり JSON-RPC が使用されます。JSON-RPC は今後のリリースで削除されるため、スクリプトとノートブックを `plaidcloud-rpc` 1.25.0 以降にアップグレードし、新しい連携は REST API に対して作成してください。[コマンドライン](/ja/reference/cli/jupyter/command-line/)を参照してください。
- **ステップは、別の環境に固定しない限り、プロジェクトの接続環境に従います**。プロジェクトの環境を QA と本番などの間で切り替えると、すべてのステップが移動します。1つの環境にとどまる必要があるステップには、代わりに **Fixed environment** を指定できます。フォームには警告が表示され、ログにはプロジェクトの環境以外での各実行が記録され、プロジェクトを切り替えるときには、追従しないステップが示されます。ERP の転記ステップは、常にプロジェクトの環境を使用します。プロジェクト、固定されたステップ、またはエージェントが使用している間は、環境を削除できません。また、エージェントフォームのフィールドは **Environment this agent serves** になりました。[ステップを1つの環境に固定する](/ja/guides/projects/managing-projects/#ステップを1つの環境に固定する)を参照してください。
- **ステップフォームは1つのレイアウトに従います**。タブには標準の名前と標準の順序があります。一般、設定、ソース、列、フィルター、出力、詳細設定で、ERP の転記フォームには Header columns と Line columns があります。必須フィールドには * が付き、フォームは、ステップに必要なものについてのみ保存をブロックします。
- **プロジェクトのコピーでは、テーブルデータとディメンションメンバーを別々に選択でき、データのコピーが高速になり、プライベートコピーの ERP 書き込み承認が保持されます**。**Data to copy** の下で、**Table data**（**No table data**（デフォルト）、**完全**、**サンプル**）を選択し、これとは別に、デフォルトでオンの **Copy dimension members** を選択します。そのため、テーブルの行なしのコピーでも、ディメンションにはデータが入った状態で作成され、短時間で作成できます。**完全**と**サンプル**のコピーは、複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトは、より速く完了します。**コピー結果**には、各ディメンションの結果がテーブルとともに一覧表示され、**Retry failed items** は、失敗したテーブルとディメンションをまとめて再試行します。データ付きで作成された新しいコピーは自分専用となり、自分で付与できる、コピー元の ERP 書き込み承認を保持します。コピー元が本番で転記する場合、コピーはシミュレートで作成されるため、本番に切り替えるまで ERP には何も送られません。REST API と `project_copy` MCP ツールも `dimension_members` を受け取ります。[コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーでの ERP 書き込み承認](/ja/guides/projects/managing-projects/#コピーでのerp書き込み承認)を参照してください。
- **テーブルの詳細パネルに、それを使用するステップがより早く表示されます**。別のテーブルを選択すると、前のテーブルのステップがすぐにクリアされ、このプロジェクトのデータを共有する他のプロジェクトのステップは、パネル全体を待たせることなく、残りの少し後に追加されます。[テーブルの使用箇所の確認](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)を参照してください。
- **行アクションは、すべての一覧で同じように動作します**。行のメニューは、行の先頭にある **⋯** ボタン、右クリック、またはツールバーの**アクション**メニューから開きます。常に、**開く**、**詳細**、**編集**が先頭に、続いてその一覧に固有のアクション、最後に**削除**があり、行に該当しないアクションは、その位置でグレー表示になります。**Enter** と **Del** は、実行する項目に表示されます。行にアクションが1つしかない一覧では、**⋯** の代わりにそのアクションのアイコンが表示され、ダッシュボード、アプリ、Notebooks には、再び**開く**アイコンが表示されます。[行アクションメニュー](/ja/guides/dashboards/using-dashboards/#行アクションメニュー)を参照してください。
- **PlaidCloud の外観が、ライトとダークの両方で刷新されたブルーになりました**。ボタン、チェックボックス、選択された行、タブ、リンク、ワークスペースのページを一覧表示するレールには、1つの PlaidCloud ブルーが使用され、どちらのテーマでも読み取れるコントラストが確保されています。アプリのタブアイコンは、統一されたセットになりました。
- **新しい読み込み画面**。PlaidCloud は、ライトまたはダークのテーマに従う、より洗練された読み込み画面で開きます。アイドル状態から復帰する Panel または Dash アプリは、**開始中**、**準備中**、**Loading app** の進行状況を表示し、起動しない場合は、どのステップで停止したかを示して**再試行**を提供します。[Panel アプリの使い方](/ja/guides/panel-apps/using/)を参照してください。
- **検証設定のない保存済みの ERP 書き込みステップは、検証のみで開きます**。これは、SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL と AP Post、Xero のエクスポートが対象です。ライブで実行するよう明示的に設定されたステップは、ライブのままです。
- **長時間実行されるジョブは、どこでも同じ方法で進行状況を表示します**。
- **ワークフローは、正直に停止、失敗、報告します**。ワークフローを停止すると、それが開始したすべてが停止し、完了できない実行やステップは、ハングせずに理由とともに失敗し、実行ステータスは、実際に実行された内容と一致します。
  - **ワークフローを停止すると、それが開始したすべてが停止し、完了できない実行やステップは、ハングせずに失敗します**。停止は、まだキューにあったインポートとディメンションのステップをキャンセルするため、ワークスペース内の後続のインポートとディメンションのロードは、通常どおり開始され、ワークフローのキューにある、または実行中のコネクター（Singer）の同期も停止します。ステップのジョブを開始できない場合、そのステップは、永遠に待機する代わりに、理由とともに失敗します。約40分以内にワーカーが開始しない、ワーカーが開始したあとにいなくなった、そのポッドが約20分間 Pending のまま、イメージを約5分間取得できない、または約20分間ポッドが作成されない、といった場合です。どのランナーも約30分以内に取得しないコネクターの同期は、その同期の名前を示すメッセージとともに失敗します。ステップがワーカーを待機している間、ステータスメッセージには、これまでの分数とともに「Waiting for a worker…」と表示され、作業が開始されるとクリアされます。マクロを停止すると、実行中のそのすべてのコピーが停止しますが、1つのコピーを停止した場合や、**Macro Concurrent** ステップが応答しなくなったコピーを断念した場合は、それを呼び出したワークフローは実行されたままです。他のワークフロー内でのみ実行されているマクロは、ワークフローリストで**実行中**と表示され、**停止**が利用でき、各ステップのステータス、開始時刻、終了時刻は、最新の実行のものが表示されます。サーバーが失われた実行は失敗として終了し、12時間後も実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」で失敗します。[ワークフローの実行](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
  - **再開、実行履歴、実行ステータスは、実際に実行された内容と一致します**。親ワークフローを再開すると、子ワークフローのステップを単独で再実行した後でも、子ワークフローが残していたすべてが実行され、1回の実行内での子ワークフローの各呼び出しには、それぞれ独自の実行履歴エントリがあります。サーバーが停止したために再開されたステップは、そのログにその旨が記録され、`workflow_run_status` と REST API の実行結果は、失敗したが続行したステップを、実行が問題なかったと報告する代わりに、`continued_step_ids` と `continued_step_count` に一覧表示します。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。
  - **ステップのエラーに、固有のメッセージが表示されます**。PlaidCloud が想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードには、エラーが1行で表示され、すでに削除されたワークフローの実行は除外されます。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。
  - **完了しない ERP 抽出はそのステップを失敗させ、再開で続行できます**。**SAP: アドホック抽出**が行数または時間の制限で一時停止した、そのエージェントが時間内に応答しなかった、または Salesforce、Oracle Fusion のバルク、HFM/FCCS のエクスポートジョブが、ステップが待機を停止した時点でもまだ実行中の場合、後続のステップが部分的なテーブルに対して実行されないよう、そのステップは失敗します。ワークフローを再開するか、ステップを再実行すると、抽出は、同じジョブで、停止した場所から続行されます。[実行制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)を参照してください。
  - **エクスポートをキャンセルすると、ウェアハウスでそのクエリも停止します**。ワークフローの停止によるものを含め、エクスポートまたはダウンロードがキャンセルされると、そのデータを読み取っているクエリも、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplum で停止し、リモートデータベースへのエクスポートは、最後まで実行し続ける代わりに、ソースの読み取りを停止します。
- **ワークスペースがアップグレードされると、REST、Import REST、Import Postman ステップは RESTリクエスト ステップに変換されます**。きれいに変換できないステップは、そのまま残ります。[REST リクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **セッションの有効期限が切れた後に開いたダッシュボードリンクは、サインイン後にそのダッシュボードに移動します**。[ダッシュボードの使い方](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは、認識できないフィールドを拒否し**、無視する代わりに、エラーでそのフィールドを示します。`workflow_upsert` は `memo` を受け取り、その別名として `description` も受け付けます。[不明なフィールドは拒否される](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2 では、Lakehouse が Parquet のエクスポートを Google Cloud Storage に直接書き込みます**。Google Cloud Storage ドキュメントアカウントへのエクスポートは、すべての行が最初に PlaidCloud を経由する代わりに、アカウント自身の認証情報で書き込まれ、アカウントのバケットに直接格納されます。Amazon S3 と Azure Blob Storage アカウントへのエクスポートは、これまでどおり動作します。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/)を参照してください。
- **Slack、Microsoft Teams、Web Hook ステップは、メッセージが送信されなかった理由を示します**。ステップのエラーには、接続を試みたサーバーと、Slack と Teams の場合は接続が示され、何が問題だったかが説明されます。たとえば、Slack がウェブフックを認識しなくなった、チャネルに投稿できない、サーバーが見つからない、または60秒以内に応答しない、接続が削除されたなどです。Slack または Teams のウェブフック URL は、それを持つ人なら誰でもあなたの連携として投稿できるため、表示されることはありません。[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/)を参照してください。
- **プロジェクトのサービスアカウントのアクセストークンは、少なくとも24時間有効です**。UDF ステップなど、プロジェクトとして実行されるワークフロージョブは、24時間有効なトークンを取得します。それより短い有効期間は、ワークスペースのアップグレード時に引き上げられ、設定したより長い期間は保持されます。
- **ワークスペースの組織、オーナー、リリース、バージョンは PlaidCloud が設定し、データセンターはユーザーが選択します**。コントロールプレーンで作成したワークスペースは、あなたがオーナーとなり、PlaidCloud が設定するリリースチャネルに配置され、サインアップ時に提示されるリージョンから **Data Center** を選択します。ワークスペースを編集するとき、組織、オーナー、リリース、バージョンは読み取り専用です。バージョンを変更するには **Set Version** を使用し、ワークスペースの移動、オーナーまたはチャネルの変更、固定については、PlaidCloud サポートに依頼してください。[ワークスペースの構成](/ja/administration/control-plane/workspace-configuration/#基本設定)を参照してください。

## 修正

- **無効なプロジェクト設定が、わかりやすいメッセージで報告されます**。不明な環境またはドキュメントアカウント、すでに使用されている、または予約されているスラッグ、無効なストレージタイプまたは転記モードは、一般的なサーバーエラーではなく、問題を示すメッセージを返すようになりました。REST API では 500 ではなく 400 になり、AI アシスタントまたは MCP では無効な引数のエラーになります。
- **REST API のディメンション値リクエストが機能します**。`POST /rest/v1/analyze/query/retrieve-dimension-values` は、グリッドリクエストとして応答され、無効として拒否されていました。現在は `value_columns` の各列について集計された1つの値を返し、グリッド（行フィルターと列フィルターの各組み合わせについて1つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **低速なテーブル読み取りとファイル処理が、他のリクエストを妨げなくなりました**。ウェアハウスからのテーブルの列の読み取り、Data Foundation ファイルの登録、Excel へのエクスポート、REST または SOAP インポートの応答の読み取り、ドキュメントアカウントの使用箇所の検索、Panel アプリのコードやロゴのチェックは、それぞれが完了するまで、同じサーバーが処理している他のすべてのリクエストを一時停止させる可能性がありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクトとワークフローの変数ダイアログがスクロールします**。小さい画面や低い解像度では、追加と編集のダイアログがウィンドウより高く、**作成**と**更新**ボタンに手が届かない場合がありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storage ドキュメントアカウントの256 MiB を超えるファイルをコピー、移動、名前の変更できます**。これらはそれぞれ、そのサイズのファイルで失敗していました。そのようなファイルを含むフォルダーの移動や名前の変更も同様でした。
- **Lakehouse v2 では、テーブルの行数に、書き込まれたばかりの内容が反映されます**。テーブルを書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが0行と表示されたり、インポートが0行がインポートされたと報告したりしていました。行数は、新しい行がどこからでも参照できるようになってから読み取られるため、後続のステップもそれらを読み取ります。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりしたときも、その行数と列数が更新されます。
- **Weave の空値チェックは、各実行を、以前の実行が実際に残したものと比較します**。ステップの空値は、ステップがテーブルを空にして再入力した直後にカウントされることが多く、以前の実行には空値がないように見えたり、常に一部が空だった列が、たった今そうなったかのように報告されたりしていました。現在は、各実行は、ステップがテーブルを残した状態でカウントされます。以前に記録されたカウントは、正しいものと区別できないため使用されません。各ステップの空値チェックは履歴を最初からやり直し、5回の実行がカウントされるまで、未チェックとして報告されます。また、行数と値の分布のチェックも、別のステップが完了後2秒を超えて同じテーブルに行う書き込みを、そのステップのものとしてカウントしなくなりました。[Weave が確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **Data Foundation は、反転した為替レートと小数のしきい値の精度を保持します**。レートがレポーティング通貨から別の通貨への相場で表示されているために PlaidCloud が反転させたレートは、小数点以下6桁に丸められる場合があり、インドネシアルピアのようにレートの小さい通貨の金額が約1%ずれていました。反転したレートは、小数点以下12桁を保持するようになりました。`0.5` のように小数を含む `group_amber` または `group_red` のしきい値は、整数に丸められていました。次の**ロード**では、正確な値が使用されます。[為替レート](/ja/guides/projects/data-foundation/#為替レート)を参照してください。
- **無効化されたメンバーのアラートとダイジェストが停止します**。所有者が無効化された Panel アプリのアラートまたはダイジェストが、チェックと送信を続けていました。現在は、無効化されている間は一時停止し、再有効化されると再開します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
- **削除された接続を REST API に要求すると 404 が返されます**。削除された接続や、存在しない ID を要求すると、一般的なサーバーエラー（500）で応答していました。現在は、接続 ID を示すメッセージとともに 404 を返します。
- **テンプレートを使用したテーブルのエクスポートが、AI アシスタントと MCP で機能します**。`table_data_export` の `templated` 形式は、テーブルが指定されるたびに失敗していました。現在は、テンプレートを通じてテーブルをエクスポートし、読み取れる行に限定されます。テンプレートでは、テーブルの行は、テーブル ID に含まれる各 `-` を `_` に置き換えた名前で参照されます。
- **Amazon S3 および S3 互換のドキュメントアカウントが、リージョンを保持します**。これらのアカウントを保存すると、入力した**リージョン**が破棄されていたため、次にアカウントを開いたときにフィールドが空白になっていました。リージョンが保存されるようになりました。この修正前に保存されたアカウントでは、リージョンを再入力して保存してください。[AWS S3 アカウントの追加](/ja/guides/documents/adding-accounts/add-aws-s3-account/)を参照してください。
- **AI アシスタントと JSON-RPC は、ロールで非表示のテーブルを使用するステップを名指ししなくなりました**。そのようなテーブルがどこで使用されているかを尋ねると、ロールで表示できる、それを読み書きする各ステップが、その設定とワークフローとともに名前で示されていました。現在は、プロジェクトのテーブル参照と同様に、ステップが名前なしでテーブルを使用していることが示されます。[ロールで非表示になるもの](/ja/guides/ai-assistant/weave-tab/#ロールで非表示になる内容)を参照してください。
- **選択したデフォルトの AI 接続が、デフォルトのままになります**。AI 接続をワークスペースのデフォルトとしてマークすると、成功したように見えましたが保存されておらず、デフォルトに依存するエージェントとステップは、最後に更新された接続を使い続けていました。選択が保存されるようになりました。[LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **Weave の履歴で会話を右クリックしても、スレッドを削除の上に名前の変更が開かなくなりました**。**名前の変更**はチャットのタブに移動しました。これまで何も表示されなかったタブを右クリックしてください。[Weave タブのタブ](/ja/guides/ai-assistant/weave-tab/#weaveタブ内のタブ)を参照してください。

## セキュリティ

- **Weave は、各会話の開始時にあなたの名前とメールアドレスを AI プロバイダーに送信しなくなりました**。これらが使用されたことはありません。
- **パスワードでのサインインには認証アプリが必要になり、パスワードが強化されました**。PlaidCloud のパスワードでサインインするメンバーは、次回のサインイン時に認証アプリの設定を求められ、その後は毎回そのコードを入力します。シングルサインオン、Google、Microsoft、GitHub でのサインイン、API トークン、サービスアカウントは変更されません。新しいパスワードは12文字以上で、ユーザー名や直近6回のパスワードのいずれかと同じにはできず、サインインに繰り返し失敗すると、アカウントは短時間ロックされます。ワークスペースにすでにあったより厳格なルールは保持されます。[メンバー認証](/ja/administration/access/member-authentication/)を参照してください。
- **接続は、パブリックとプライベートネットワークのアドレスを指します**。接続は、ループバック、リンクローカル、クラウドメタデータのアドレスを指すことができず、エラーにはホストと解決されたアドレスが示されます。プライベートネットワーク上のアドレスは影響を受けません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続が到達できないアドレス)を参照してください。
- **保存された接続の認証情報は、接続またはワークフローを編集できるメンバーにのみ表示されます**。REST API と MCP では、保存された接続のパスワード、トークン、キーは他のメンバーに対してマスクされますが、それらのメンバーも接続を開いて参照できます。[接続の認証情報を確認できるユーザー](/ja/guides/connections/create-connection/#接続の資格情報を見られるユーザー)を参照してください。
- **アプリのビルドは、ワークスペースの Git 認証情報にアクセスせずに実行されます**。
- **エージェントの秘密鍵は、エージェントを編集できるメンバーにのみ表示されます**。キーは、REST API と MCP を通じたエージェントの一覧や詳細に表示されなくなり、エージェントフォームは、**秘密鍵**と**RPC構成を表示**を、エージェントを編集できるメンバーにのみ表示します。サービスアカウント、プロジェクトとエージェントのトークン、AI が委任したトークンは、キーや RPC 構成を取得できません。実行中のエージェントは影響を受けず、公開鍵は引き続き表示されます。[エージェントの認証情報の取得](/ja/reference/cli/plaidlink/agents/#エージェントの認証情報の取得)を参照してください。
- **プロキシのダウンロードリンクは1時間有効です**。**Use PlaidCloud Proxy Download** がオンの場合、リンクの有効期限が切れたときは、ダウンロードを再度開いて新しいリンクを取得してください。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)を参照してください。
- **セキュリティグループへのユーザーの追加は、保有している権限に従います**。グループが付与するすべての権限を保有している場合に、メンバーをセキュリティグループに追加したり、メンバーのグループを選択したり、アーキテクトを招待したりできます。ワークスペース管理者は制限されません。[セキュリティグループの管理](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)を参照してください。
- **接続のオーナー、またはワークスペース管理者が、その設定を変更し、オンとオフを切り替えます**。REST API、JSON-RPC、AI アシスタントまたは MCP を通じた接続の設定の変更には、そのオーナーの1人、またはオーナーのいない接続ではワークスペース管理者が必要です。接続の有効化、無効化、ロック、ロック解除には、オーナーまたはワークスペース管理者が必要で、複数の接続を指定するリクエストは、そのすべてを変更できる場合にのみ適用されます。ワークスペースのデフォルトの AI 接続を選択できるのはワークスペース管理者のみで、メンバーが所有する接続がデフォルトになるのは、管理者が所有する接続、またはオーナーのいない接続がなりえない場合に限られます。[接続の編集](/ja/guides/connections/create-connection/#接続を編集する)と [LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **行アクセスは、メンバーが制限されたテーブルに対して行うすべての操作に適用されます**。メンバーは、ダッシュボード、自分の SQL、ロードにおいて、付与された権限で許可された行のみを表示および変更できます。
  - **プロジェクトのアーキテクトは、ダッシュボードで行制限されたテーブルのすべての行を表示します**。これは Analyze での表示と一致します。アーキテクトアクセスを取り消すと、ダッシュボードでは即座に反映されます。ロールを変更した場合、プロジェクトからユーザーやそのグループを削除した場合、プロジェクトのアクセスタイプを変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれでも同様です。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
  - **行アクセスで制限されているメンバーは、自分の SQL クエリを実行し、結果をエクスポートできます**。行アクセスのあるプロジェクトで、アーキテクトではないメンバーは、クエリ画面での自分のクエリから、付与された権限で許可された行だけを取得し、**Rows limited by your access** の通知とともに、CSV、Excel、JSON にエクスポートできます。以前は、これらは拒否されていました。パーセント記号（`%`）を含む付与値は、クエリ画面でその行を返すようになり、そのようなクエリを CSV としてダウンロードできるようになりました。Snowflake または Databricks 上の自分の自由形式の SQL、Postgres 系ウェアハウスからの自分の SQL のエクスポート、ガバナンスされたテーブルのスナップショット時点の読み取りは、引き続き拒否され、ビューは、フィルターされるために、ガバナンスされた列を元の名前のまま保持する必要があります。[行アクセスと自分で作成するクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスとご自身で記述するクエリ)を参照してください。
  - **行アクセスの保存では、ソースにない付与済みの値が保持されます**。セキュリティグループに付与された値は、テーブルにその値を持つ行がない、ディメンションにそのメンバーがない、またはリストにそれがない場合でも、マーク付きでグリッドに残ります。**保存**は、そのような各値を保持するか削除するかを尋ねます。[行アクセスグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
  - **行制限されたテーブルへの DataFrame の書き込み、レコードの保存、クリアは、表示できる行のみを変更します**。行アクセスで行が制限されている場合、Python クライアントで制限されたテーブルに DataFrame を書き込んだりクリアしたりしたとき、または REST API でレコードを保存したりクリアしたりしたときは、自分の行のみが変更され、アクセス範囲外の行を含むロードは、何かが変更される前に、見つかった値を示して拒否されます。プロジェクトのアーキテクト、すべての行を表示できるメンバー、ワークフローの実行は、テーブル全体を書き込みます。人が任意のテーブルに対して行うこれらの書き込みは、セキュリティログに記録されます。[制限されたテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
  - **行制限されたテーブルのインポート、コピー、復元、削除には、すべての行が表示できる必要があります**。行アクセスで行が制限されている場合、制限されたテーブルへのファイルのインポート、別のプロジェクトからそのテーブルへのテーブルのコピー、そのブランチの切り替えまたはマージ、復元、削除、削除後の復旧、またはテーブル全体を置き換えるその他の操作は、テーブルのすべての行を表示できる場合にのみ実行され、それ以外の場合は拒否され、何も変更されません。REST API でテーブルの行を保存すると、他のロードと同様に、自分の行のみが変更されます。プロジェクトのアーキテクト、すべての行を表示できるメンバー、ワークフローの実行は影響を受けず、これらの操作もセキュリティログに記録されます。[制限されたテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
- **アカウントのオーナーのみが、以前のバージョンを復元できます**。ドキュメントアカウントを以前のバージョンに復元する、バージョンを保持または解放する、バックアップを作成するには、そのアカウントのオーナーの1人が必要で、システム管理のアカウントではどれも利用できません。アカウントのバージョン履歴を確認するには、そのアカウントへのアクセス権が必要です。
- **`query_run` は読み取り専用のステートメントを実行します**。AI アシスタントと MCP クライアントが使用する `query_run` ツールは、1つの SELECT または WITH ステートメント、その EXPLAIN、または SHOW を受け付け、それ以外のステートメントは実行されません。データを変更するには、`query_transform` を使用してください。MCP のテーブルエクスポートの SQL にも同じルールが適用されます。REST と JSON-RPC API では、プロジェクトのデータを変更できないメンバーに対して、クエリの実行、列ファセットの構築、クエリの CSV としてのダウンロード、クエリのリモートデータベースへのエクスポート、独自のクエリによるテーブルデータのエクスポートにも適用され、拒否されたクエリは 403 を返します。Explain Analyze は、測定のためにクエリを実行するため、クエリログと Lakehouse では、読み取りのみを行うクエリだけを受け付け、行アクセスのあるプロジェクトでは、プロジェクトのアーキテクトのみがクエリログから実行できます。
- **テーブルエクスプローラーのフィルター、PlaidCloud に送信されるクエリ、Table Extract ステップの動的列を検索するクエリは、SQL を実行する関数やサーバーのファイルを読み取る関数を呼び出せません**。`query_to_xml`、`dblink`、`pg_read_file` などの呼び出しは拒否され、エラーには関数名が示されます。同じ場所で、`.op()` は演算子のみを受け付け、`literal_column` は Unicode エスケープされた引用符を使用できません。動的列のクエリには、ステップのフィルターと、ソースから列名を読み取る式が含まれるため、ルールに違反するものは、実行時にステップを失敗させます。[拒否される関数と演算子](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#拒否される関数と演算子)を参照してください。
- **Data Foundation の配賦ルールは、一重引用符、バックスラッシュ、改行を含む部門名または統計名を拒否します**。名前は配賦ステップのフィルターに書き込まれるため、**保存**とステージ1のプレビューは、それを拒否し、その値を示します。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。
