## 追加

- **PlaidXLで、Excel上でレポートの作成、ドリル、数値の説明、計画ができます。** **PlaidCloud**リボンタブは**接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有**にグループ化されました。よく使うコマンドは**PlaidXL**の右クリックメニューと**PlaidXL Cell**タブからも使え、主なコマンドには変更可能なキーボードショートカットがあります。フィールドに入力している間はショートカットは動作しません。コマンドが失敗した場合は、どのコマンドがなぜ失敗したかが表示されます。サインイン前に実行したコマンドはサインイン画面を開き、サインイン後に一度だけ実行されます。サインインは1つのワークスペースにのみ有効なため、ワークスペースを切り替えると新しいワークスペースへのサインインを求められます（元のワークスペースに戻る場合は求められません）。また、Office で Microsoft Entra の職場アカウントを使うと、PlaidXLがワークスペースを自動的に見つけます。詳しくは[PlaidXLリファレンス](/ja/reference/cli/plaidxl/)をご覧ください。
  - **数回のクリックでレポートを作成できます。** **レポート**タブは、テーブルから最新のレポートを配置します。1つのディメンションを行方向にドリルダウンし、別のディメンションを列方向に並べ、交差する各セルに `CELL` の値が入ります。**Build my first report**は、お使いのデータからサンプルを作成します。ドリルすると、レポートは行全体や列全体を挿入・削除し、入力済みの値、メモ、書式は元の行についていきます。詳しくは[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)をご覧ください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only**は、ノード、ディメンションの見出し、レポートの値から、ライブの `DRILL` 式への変換と編集を行います。**Custom drill**は、挿入前に行をプレビューします。メンバーピッカーでは、メンバーの挿入や、ノードの子要素のドロップダウンをセルに追加できます。`DRILL` は除外するノードや展開するノードを指定でき、行方向にも実行できます。詳しくは[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)をご覧ください。
  - **数値を説明できます。** **Explain this number**は、値の計算内容、現在のPlaidCloudと一致しているかどうか、元になっているテーブルとワークフローのステップを表示します。**Show detail rows**は、値の元になった行を専用のシートに表示し、合計が一致することのチェックも行います。
  - **Excelでガバナンスされたメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるとおりのビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計の場合は `0` を表示し、それ以外の場合は理由とともに `#VALUE!` を表示します（`CELLS` のスピルでは空白になります）。**Metric...** ボタンは、プロジェクトのメトリックを現在の値とともに一覧表示します。詳しくは[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)をご覧ください。
  - **レポートに直接入力して計画できます。** `CELL` の値に数値を上書き入力すると、その値がPlaidCloudに書き込まれます。比例配分、均等配分、別のメンバーの形に合わせた配分、金額またはパーセンテージによる調整が可能で、保留したセルは変更されません。平均、中央値、最小値、最大値、標準偏差、分散のセルにも入力でき、入力した値は行や列の挿入・削除に合わせてセルについていきます（削除されたセルの値は報告されます）。**Undo last write**は、入力した値と保存を新しいものから順に取り消します。書き込みを元に戻せるのは、その書き込みを行った本人と、そのワークスペースだけです。詳しくは[PlaidCloudに値を入力する](/ja/reference/cli/plaidxl/write-values/)をご覧ください。
  - **必要な分だけ更新できます。** シート、選択範囲、またはすべてのテーブルを更新できます。各テーブルの進行状況と**キャンセル**はタスクペインに表示され、PlaidXLの式だけを再計算することもできます。取得したテーブルはデータ型に応じて書式設定されたExcelテーブルとして届き、更新しても独自の列や数値書式は保持され、同じ場所で更新されます。取得や更新で他のセルが上書きされたり、別のExcelテーブルと重なったりすることはありません。Excelで扱えない大きさの整数のIDや1900年より前の日付は、テキストとして届きます。テーブルを再度取得しても更新リストに二重に追加されることはなく、**Stop refreshing**でリストから外せます。ディメンションはテーブルと一緒に更新されます。詳しくは[すべてのテーブルを更新](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)をご覧ください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud**は確認なしで書き込み、実行内容を知らせ、**元に戻す**を提示します。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーの場合は、それらの行だけが置き換えられ、他のユーザーの行は保持されます。取得後にメンバーが変更されたドリルスルーのシートは保存されません。保存に失敗した場合は、テーブルを復元できるようにリストアポイントが示されます。詳しくは[PlaidCloudにテーブルを保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)をご覧ください。
  - **ExcelでWeaveに質問できます。** **Weave**タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼するか、**Ask Weave about this cell**を選びます。WeaveはあなたとしてPlaidCloudを読み取り、変更するのはブックだけです。入力済みの内容を置き換える前に確認し、ブックの外部を参照する数式は書き込みません。各変更は、ペインを再読み込みするまで元に戻せます。詳しくは[ExcelでWeaveに質問する](/ja/reference/cli/plaidxl/weave/)をご覧ください。
  - **1つのシートまたはブック全体の、値のみのコピーを共有できます。** **Convert to values**は、ブック全体、1つのシート、または元に戻せない値のみへの変換（事前に確認が表示されます）に対応します。変更されるのはPlaidXLの式とそのスピルだけで、まだ計算中の式は再試行のために残されます。シート名を変更しても、**Restore PlaidXL formulas**は引き続き使えます。
- **ステップフォームでプレビューできます。** インポート: SQL、Execute: SQL、SQL抽出、エクスポート: SQL、Salesforceクエリの各ステップは、ステップを実行せずに最大100行を表示します。Anaplanのビューとリストの読み取りは、生成される列と型を表示します。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように埋め込まれますが、`{x:>9}` のような変数の書式はサポートされていません。プレビューで実行できるのは標準のSQL関数のみで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトでは使えません。また、エージェントベースのExecute SQLステップでも使えません。詳しくは[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と[SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)をご覧ください。
- **利用状況レポートで変化を確認し、グループで絞り込み、ワークフローに取り込めます。** **概要**には、前の期間と比較した推移の矢印と、非アクティブなメンバーや誰も開いていないダッシュボードやアプリを示す**Highlights**リストが加わりました。**グループ**を選ぶと、**概要**、**内容**、非アクティブ一覧が1つのセキュリティグループのメンバーに限定されます。日付範囲には**Previous month**と**This month**が加わり、すべてのタブで共通になり、アカウントに記憶されます。すべての数値に説明が付き、テーブルには**メンバー**や**Area**のようなわかりやすい名前が使われ、行はEnterキーで開き、読み込み中の表示とエラーの表示も明確になりました。また、**ファネル**の最後のステップには、完了したメンバーの数が表示されます。新しいGet Workspace Usage ステップは、日次または月次の利用状況の合計を、メンバー名を含めずにスケジュールに従ってテーブルに書き込みます。Get Workspace Members ステップと同様に、各実行は**セキュリティログ**に記録されます。詳しくは[利用状況レポート](/ja/administration/access/usage-reports/)と[Get Workspace Usage ステップ](/ja/reference/workflow-steps/general/get-workspace-usage/)をご覧ください。
- **AIアシスタントは、テーブルの公開を解除し、プロジェクトのデフォルトのダッシュボード対象者を設定できます。** `publish_manage` は、テーブルの公開を解除し、あわせてその公開ビューと、どのチャートも使っていないダッシュボードのデータセットも解除します。チャートがまだ使っているデータセットは残り、公開ビューの上にレポートビューが作られている場合も、そのビューとデータセットは残りますが、テーブルの公開は解除されます。`project_upsert` は `dashboard_default_audience` を設定します。これはプロジェクトの新しいダッシュボードの共有先となるグループで、`[]` を指定するとクリアされます。詳しくは[公開の解除](/ja/guides/data/publish/#ai-アシスタントまたは-mcp-で公開を取り消す)と[AIアシスタントまたはMCPでデフォルトの対象者を設定する](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ai-アシスタントまたは-mcp-でデフォルトの対象ユーザーを設定する)をご覧ください。

- **Git アプリがリポジトリを一覧表示し、できることを案内します。** アプリ一覧の **Git** には、お客様のロール（**管理者**、**コントリビューター**、**閲覧者**）と、ワークスペースのリポジトリが表示されます。各リポジトリには説明、最終更新日、コピーボタン付きのクローンアドレス、**開く**があります。**コンピューターで Git を設定する**カードは、Git のインストール、トークンの作成、クローンの手順を案内し、**クローンの方法**で再度開けます。**Git ですべて表示**は完全な Git インターフェースを開き、**プッシュできるユーザーを管理**はグループ管理を開きます。アクセスレベルは**閲覧者**、**コントリビューター**（アプリコードを `apps` にプッシュ）、**管理者**（`udfs` を含むすべてにプッシュ）で、閲覧者には問い合わせ先として最大 3 人のワークスペース管理者が表示されます。新しい **Git Contributors** グループはコントリビューターの権限を付与し、デフォルトグループにできるため、新しいメンバーは自動的に付与されます。**Git Administration** は管理者の権限を付与します。メンバーの **Git** タブには、Git のユーザー名、レベル、それを付与しているグループが表示されます。アプリウィンドウには**リポジトリ**セクションが表示され、UDF には**開く**があり、Git にはワークスペースへ戻る **← 戻る**リンクがあります。アプリのリポジトリや組み込みの `apps` および `udfs` リポジトリを含め、プラットフォームが作成するすべてのリポジトリは、ワークスペースのサインイン済みのすべてのメンバーが読み取れ、サインインしていないユーザーは読み取れないため、メンバーはリポジトリごとの設定なしでアプリを開いて再公開できます。Git 管理者は引き続きリポジトリを非公開にでき、その場合はリポジトリ選択から非表示になり、メンバーはそこからの公開や、そこに保存された Git ベースの UDF コードの実行ができなくなります。[PlaidCloud Git](/ja/guides/git/#gitを開く)と[リポジトリを閲覧できるユーザー](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)を参照してください。
- **モバイルのWeaveでは、音声入力がワンタップで使えます。** マイクをタップして質問を話すと、話し終えた時点でWeaveが送信します。もう一度マイクをタップすると途中で止められ、何も聞き取れない場合は自動的にオフになります。話している途中で**Weave**タブを離れたりアプリをバックグラウンドにしたりすると、話した内容は送信されずに質問ボックスに残るため、確認できます。実行、一時停止、停止、再開の確認画面では、誤ったダブルタップは無視されます。アプリのバージョン1.3.0以降が必要です。詳しくは[音声を使う](/ja/guides/mobile-app/weave-on-mobile/#音声を使う)をご覧ください。

## 変更

- **ステップフォームは共通のレイアウトになりました。** タブの名前と順序が統一され、General、設定、ソース、列、フィルター、出力、詳細設定の順に並びます。ERP転記フォームには、ヘッダー列と明細行の列があります。必須フィールドには * が付き、フォームは、そのステップに必要な項目についてのみ保存をブロックします。
- **プロジェクトをコピーでは、テーブルデータとディメンションメンバーを個別に選べるようになり、データのコピーが高速になり、非公開コピーではERP書き込み承認が引き継がれます。** **Data to copy**の下で、**テーブルデータ**（**テーブルデータなし**（デフォルト）、**完全**、**サンプル**）を選び、これとは別に**Copy dimension members**を選びます。後者はデフォルトでオンのため、テーブルの行を含めないコピーでも、ディメンションにはデータが入った状態で届き、すばやく作成できます。**完全**と**サンプル**のコピーは複数のテーブルを同時にコピーするため、テーブルが多いプロジェクトでも短時間で終わります。**コピー結果**には、テーブルとあわせて各ディメンションの結果が一覧表示され、**Retry failed items**は、失敗したテーブルとディメンションをまとめて再試行します。データ付きで新しく作成したコピーは自分だけの非公開になり、コピー元のERP書き込み承認のうち、自分で付与できるものが引き継がれます。コピー元がライブで転記している場合、コピーはシミュレートの状態で作成されるため、ライブに切り替えるまでERPには何も反映されません。REST APIと `project_copy` MCPツールも `dimension_members` を受け付けます。詳しくは[コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーに含まれるERP書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認)をご覧ください。
- **テーブルの詳細パネルに、そのテーブルを使うステップがより早く表示されます。** 別のテーブルを選ぶと、前のテーブルのステップがすぐにクリアされます。このプロジェクトのデータを共有している他のプロジェクトのステップは、パネル全体を待たせず、他の分より少し遅れて追加されます。詳しくは[テーブルの使用箇所を確認する](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)をご覧ください。
- **行アクションメニュー（⋯）が、すべてのグリッド行の左端に移動しました。**
- **アプリのタブアイコンが、ライトとダークで共通のセットに統一されました。**
- **検証設定のない保存済みのERP書き込みステップは、検証のみで開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL と AP Post、Xeroエクスポートです。明示的にライブで実行するよう設定されているステップは、ライブのままです。
- **時間のかかるジョブの進行状況が、どこでも同じ方法で表示されます。**
- **ワークフローを停止すると、開始したすべての処理が停止し、完了できない実行やステップは、待機し続けずに失敗します。** 停止すると、キューに入ったままのインポートステップとディメンションステップがキャンセルされるため、ワークスペース内の後続のインポートやディメンションのロードは通常どおり開始されます。また、そのワークフローのキュー中または実行中のコネクター（Singer）の同期も停止されます。ステップのジョブを開始できない場合、ステップは永久に待機せず、理由を示して失敗します。理由は、約40分以内にワーカーが開始しなかった、ワーカーが開始した後に消えた、ポッドが約20分間Pendingのままになった、イメージを約5分間取得できなかった、約20分間ポッドが作成されなかった、のいずれかです。約30分以内にどのランナーも受け取らないコネクターの同期は、その同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間、ステータスメッセージに「Waiting for a worker…」と経過時間（分）が表示され、処理が始まると消えます。マクロを停止すると、実行中のすべてのコピーが停止します。他のワークフロー内でのみ実行されているマクロは、ワークフロー一覧で**実行中**と表示され、**停止**が使え、各ステップのステータスと開始・終了時刻は直近の実行から取得されます。サーバーが失われた実行は失敗として終了し、12時間たっても実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」で失敗します。詳しくは[ワークフローの実行](/ja/guides/workflows/run-a-workflow/#開始されないステップ)をご覧ください。
- **再開、実行履歴、実行ステータスが、実際に実行された内容と一致するようになりました。** 親ワークフローを再開すると、子ワークフローの個別のステップだけを再実行した後でも、子ワークフローに残っていたすべての処理が実行されます。また、1回の実行内での子ワークフローの呼び出しごとに、それぞれ実行履歴のエントリーが作られます。サーバーが停止したために再開されたステップは、そのことがログに記録されます。`workflow_run_status` とREST APIの実行結果は、失敗したが続行したステップを `continued_step_ids` と `continued_step_count` に一覧表示し、実行を問題なしとは報告しなくなりました。詳しくは[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に続行](/ja/guides/workflows/continue-on-error/)をご覧ください。
- **ステップのエラーに、そのエラー自身のメッセージが表示されます。** PlaidCloudが想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードにはエラーが1行で表示され、その後削除されたワークフローの実行は表示されません。詳しくは[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)をご覧ください。
- **ERP抽出が完了しない場合はそのステップが失敗し、再開すると続きから実行されます。** **SAP: アドホック抽出**が行数や時間の上限で一時停止した場合や、エージェントが時間内に応答しなかった場合、また、Salesforce、Oracle FusionのバルクまたはHFM/FCCSのエクスポートジョブが、ステップが待機をやめた時点でまだ実行中の場合、ステップは失敗します。そのため、後続のステップが一部しかないテーブルに対して実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は中断した位置から同じジョブで続行されます。詳しくは[実行の上限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と[Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)をご覧ください。
- **REST、Import REST、Import Postmanの各ステップは、ワークスペースのアップグレード時にRESTリクエストステップに変換されます。** きれいに変換できないステップは、元のまま残ります。詳しくは[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)をご覧ください。
- **プロジェクトのアーキテクトは、ダッシュボードで行制限のあるテーブルのすべての行を表示できます。** これはAnalyzeでの表示と一致します。アーキテクトのアクセスを取り消すと、ダッシュボードにはすぐに反映されます。対象は、ユーザーのロールの変更、ユーザーまたはそのグループのプロジェクトからの削除、プロジェクトのアクセスタイプの変更、以前のプロジェクトバージョンの復元、セキュリティグループの削除です。以前アーキテクトだったユーザーが、行制限のあるデータのすべての行を表示することはなくなりました。詳しくは[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)をご覧ください。
- **セッションの有効期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードに移動します。** 詳しくは[ダッシュボードの使い方](/ja/guides/dashboards/using-dashboards/)をご覧ください。
- **MCPツールは、認識できないフィールドを無視せず、エラーでそのフィールド名を示して拒否します。** `workflow_upsert` は `memo` を受け付け、その別名として `description` も使えます。詳しくは[不明なフィールドは拒否されます](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)をご覧ください。
- **Lakehouse v2では、LakehouseがParquetエクスポートをGoogle Cloud Storageに直接書き込みます。** Google Cloud Storageドキュメントアカウントへのエクスポートは、すべての行がいったんPlaidCloudを経由するのではなく、アカウント自身の認証情報で書き込まれ、アカウントのバケットに直接保存されます。Amazon S3とAzure Blob Storageのアカウントへのエクスポートは、従来どおりです。詳しくは[Export to Parquet ステップ](/ja/reference/workflow-steps/export/export-to-parquet/)をご覧ください。
- **Slack、Microsoft Teams、Web Hookの各ステップが、メッセージを送信できなかった理由を示します。** ステップのエラーには、接続しようとしたサーバーが示され、SlackとTeamsでは接続も示され、何が問題だったかが説明されます。たとえば、Slackがwebhookを認識しなくなった、チャンネルに投稿できない、サーバーが見つからないか60秒以内に応答しない、接続が削除された、などです。SlackまたはTeamsのwebhook URLは、それを知っていれば誰でもあなたの連携として投稿できてしまうため、表示されることはありません。詳しくは[Notify via Slack ステップ](/ja/reference/workflow-steps/notifications/notify-via-slack/)をご覧ください。

## 修正

- **無効なプロジェクト設定が、わかりやすいメッセージで報告されます。** 不明な環境またはドキュメントアカウント、使用済みまたは予約済みのスラッグ、無効なストレージタイプまたは転記モードの場合、汎用のサーバーエラーではなく、問題を示すメッセージが返されます。REST APIでは500ではなく400が返り、AIアシスタントまたはMCPでは無効な引数のエラーになります。
- **REST APIのディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして処理され、無効として拒否されていました。現在は `value_columns` の各列について集計値を1つ返します。グリッド（行フィルターと列フィルターの組み合わせごとに1つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **テーブルの読み取りやファイル処理が遅くても、他のリクエストを止めなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundationファイルの登録、Excelへのエクスポート、RESTまたはSOAPインポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panelアプリのコードやロゴのチェックは、それぞれが終わるまで、同じサーバーが処理している他のすべてのリクエストを止めることがありました。現在はそれらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 小さい画面や低い解像度では、追加・編集ダイアログがウィンドウより高くなり、**作成**と**更新**のボタンに手が届かないことがありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storageドキュメントアカウントの256 MiBを超えるファイルを、コピー、移動、名前変更できます。** これまでは、そのサイズのファイルでは、これらの操作がいずれも失敗しており、そのようなファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2では、テーブルの行数に、書き込まれた直後の内容が反映されます。** テーブルを書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロード直後のテーブルが0行と表示されたり、インポートが0行のインポートと報告されたりしていました。現在は、新しい行がすべての場所で見えるようになってから行数を読み取るため、後続のステップもそれらの行を読み取れます。テーブルを別のブランチに切り替えた場合や、ブランチをテーブルにマージした場合も、行数と列数が更新されます。
- **Weaveの空値チェックは、以前の実行が実際に残した状態と各実行を比較します。** ステップの空値は、ステップがテーブルを空にして再投入した直後に数えられることが多く、そのため以前の実行には空値がなかったように見えました。また、常に一部が空だった列が、ちょうど空になったかのように報告されていました。現在は、ステップがテーブルに残した状態で各実行が数えられます。以前に記録されたカウントは、正しいものと区別できないため使用されず、各ステップの空値チェックは履歴を最初からやり直し、5回の実行が数えられるまでは未チェックと報告されます。行数と値の分布のチェックでも、ステップの終了から2秒を超えた後に別のステップが同じテーブルに行う書き込みを、そのステップの書き込みとして扱わなくなりました。詳しくは[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)をご覧ください。
- **削除された接続をREST APIに要求すると404が返ります。** 削除された接続や存在しないIDを要求すると、汎用のサーバーエラー（500）が返っていました。現在は、接続IDを示すメッセージとともに404が返ります。

## セキュリティ

- **行アクセスを保存しても、ソースに存在しなくなった付与済みの値は保持されます。** セキュリティグループに付与された値は、テーブルにその値の行がなくなった場合、ディメンションからメンバーがなくなった場合、リストからその値がなくなった場合に、次回の保存で付与から外れていました。何もチェックされていないグループは**Everyone else**にフォールバックし、すべての行が対象になる可能性がありました。現在は、その値はグリッドに印付きで残り、**保存**時に保持するか削除するかが確認されます。詳しくは[行アクセスグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)をご覧ください。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントのオーナーだけです。** ドキュメントアカウントを以前のバージョンに復元する操作、バージョンの保持または解除、バックアップの取得には、アカウントのオーナーのいずれかであることが必要になりました。システム管理のアカウントでは、いずれも使えません。アカウントのバージョン履歴の表示には、アカウントへのアクセスが必要です。
- **データの読み取り専用のクエリは、データを変更できなくなりました。** AIアシスタントとMCPクライアントが使う `query_run` ツールは、データを読み取る文（SELECTまたはWITH文1つ、そのEXPLAIN、SHOW）のみを実行し、それ以外は実行せずに拒否します。データを変更するには `query_transform` を使います。MCPのテーブルエクスポートのSQLも同じ規則に従います。REST APIとJSON-RPC APIでは、プロジェクトデータを変更できないメンバーに対して、クエリの実行、列ファセットの作成、クエリのCSVとしてのダウンロード、クエリのリモートデータベースへのエクスポート、独自クエリによるテーブルデータのエクスポートにも同じ規則が適用され、拒否されたクエリには403が返ります。Explain Analyzeはクエリを実行して測定するため、クエリログとLakehouseでは、データを読み取るクエリのみを受け付けるようになりました。行アクセスのあるプロジェクトでは、クエリログからこれを実行できるのはプロジェクトのアーキテクトだけです。
- **行制限のあるテーブルへのDataFrameの書き込み、レコードの保存、クリアでは、見える行だけが変更されます。** 行アクセスで行が制限されている場合、Pythonクライアントで制限付きテーブルにDataFrameを書き込む操作やクリアする操作、REST APIでレコードを保存する操作やクリアする操作では、自分の行だけが変更されます。アクセス範囲外の行を含むロードは、何も変更されないうちに拒否され、見つかった値が示されます。プロジェクトのアーキテクト、すべての行を表示できるメンバー、ワークフローの実行は、従来どおりテーブル全体を書き込みます。人が任意のテーブルに対して行うこれらの書き込みは、すべて**セキュリティログ**に記録されるようになりました。詳しくは[制限付きテーブルにデータをロードする](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)をご覧ください。
- **インポート、コピー、復元、削除で、見えない行が置き換えられることはなくなりました。** 行アクセスで行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えやマージ、復元、削除、その他テーブル全体を置き換える操作は、見えない行がテーブルに含まれている間は拒否され、何も変更されません。REST APIでテーブルの行を保存する場合も、他のロードと同様に、自分の行だけが変更されるようになりました。プロジェクトのアーキテクト、すべての行を表示できるメンバー、ワークフローの実行には影響しません。これらの操作も**セキュリティログ**に記録されます。詳しくは[制限付きテーブルにデータをロードする](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)をご覧ください。
