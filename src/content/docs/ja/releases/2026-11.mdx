## 追加

- **PlaidXLがExcelでレポートの作成、ドリル、数値の説明、計画を行えます。** **PlaidCloud** リボンタブは **接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有** にグループ化されています。よく使うコマンドは **PlaidXL** 右クリックメニューと **PlaidXL Cell** タブにもあり、主なコマンドには変更可能なキーボードショートカットがあります。サインイン前に実行したコマンドはサインイン画面を開き、サインイン後に1回実行されます。OfficeでMicrosoft Entraの職場アカウントを使っている場合、PlaidXLがワークスペースを自動的に見つけます。[PlaidXLリファレンス](/ja/reference/cli/plaidxl/) を参照してください。
  - **数クリックでレポートを作成します。** **レポート** タブは、テーブルからライブレポートをレイアウトします。行方向に1つのディメンションを、列方向に別のディメンションをドリルダウンし、交差するすべてのセルに `CELL` 値を配置します。**Build my first report** は、お客様自身のデータからサンプルを作成します。ドリルすると、レポートは行全体と列全体を挿入または削除し、入力した値、メモ、書式は元の行に付いたままになります。[レポートを作成する](/ja/reference/cli/plaidxl/build-a-report/) を参照してください。
  - **任意のセルからドリルします。** **Drill down**、**Drill up**、**Keep only**、**Remove only** は、ノード、ディメンション見出し、レポートの値から、ノードをライブの `DRILL` 数式に変えて編集します。**Custom drill** は挿入前に行をプレビューし、メンバーピッカーはメンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりします。`DRILL` は、除外または展開するノードを指定でき、行をまたいで実行することもできます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/) を参照してください。
  - **数値を説明します。** **Explain this number** は、値の計算内容、現在のPlaidCloudと一致しているかどうか、元になっているテーブルとワークフローステップを表示します。**Show detail rows** は、値の元になった行を専用のシートに表示し、合計が一致することを確認します。
  - **Excelでガバナンスされたメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるのと同じビジネスメトリックを返します。**Metric...** コマンドは、プロジェクトのメトリックを現在の値とともに一覧表示します。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック) を参照してください。
  - **レポートに入力して計画します。** `CELL` の値に数値を上書き入力すると、PlaidCloudに書き込まれます。比例配分、均等配分、別のメンバーの形に合わせた配分、金額または割合による調整が可能で、保留したセルはそのまま残ります。平均、中央値、最小値、最大値、標準偏差、分散のセルにも入力値を指定できます。**Undo last write** は、入力した値と保存を新しいものから順に元に戻します。[PlaidCloudに値を入力する](/ja/reference/cli/plaidxl/write-values/) を参照してください。
  - **必要なものだけを更新します。** シート、選択範囲、またはすべてのテーブルを更新でき、各テーブルの進行状況と **キャンセル** がタスクペインに表示されます。PlaidXLの数式だけを再計算することもできます。取得したテーブルはデータ型ごとに書式設定されたExcelテーブルとして届き、お客様自身の列と数値書式は更新後も保持され、元の場所で更新されます。同じテーブルをもう一度取得しても更新リストに重複して追加されることはなく、**Stop refreshing** でリストから外せます。ディメンションもテーブルと一緒に更新されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する) を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud** は確認なしで書き込み、実行した内容を表示して、**元に戻す** を提示します。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーの場合は、それらの行だけが置き換えられ、他のユーザーの行は保持されます。[テーブルをPlaidCloudに保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する) を参照してください。
  - **ExcelでWeaveに質問できます。** **Weave** タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼できます。または **Weave にこのセルについて質問** を選択します。Weaveはお客様としてPlaidCloudを読み取り、変更するのはワークブックだけです。入力済みの内容を置き換える前に確認し、各変更はペインを再読み込みするまで元に戻せます。[ExcelでWeaveに質問する](/ja/reference/cli/plaidxl/weave/) を参照してください。
  - **1つのシートまたはワークブック全体の値のみのコピーを共有できます。** **Convert to values** は、ワークブック全体、1つのシート、または元に戻せない値に変換します。**Restore PlaidXL formulas** は、シート名を変更した後でも使用できます。
- **ステップフォームでプレビューできます。** SQLのインポート、Execute: SQL、SQL抽出、エクスポート: SQL、Salesforce: オブジェクトのクエリは、ステップを実行せずに最大100行を表示します。Anaplan: ビューの読み取りとAnaplan: リストの読み取りは、生成される列と型を表示します。**ソース** タブで **プレビュー** をクリックします。変数は実行時と同じように補完されますが、`{x:>9}` のような変数の書式指定はサポートされません。プレビューが実行するのは標準のSQL関数だけで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトや、エージェントベースのExecute SQLステップでは使用できません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/) と [SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/) を参照してください。
- **利用状況レポートで変化を確認し、グループに絞り込み、ワークフローに連携できます。** **概要** には、前の期間との比較を示すトレンド矢印と、非アクティブなメンバーや、誰も開いていないダッシュボードやアプリを指し示す **Highlights** の一覧が加わります。**グループ** を使うと、**概要**、**内容**、非アクティブ一覧が1つのセキュリティグループのメンバーに限定されます。日付範囲には **Previous month** と **This month** が加わり、すべてのタブで共有され、アカウントに記憶されます。すべての数値に説明が付き、テーブルには **メンバー** や **エリア** のようなわかりやすい名前が使われ、Enterキーで行を開け、読み込み中とエラーの表示がわかりやすくなり、最後の **ファネル** ステップには完了したメンバー数が表示されます。新しい **Get Workspace Usage** ステップは、日次または月次の利用状況の合計を、メンバー名を含めずにスケジュールに従ってテーブルに書き込み、**Get Workspace Members** と同様に、各実行は **セキュリティログ** に記録されます。[利用状況レポート](/ja/administration/access/usage-reports/) と [Get Workspace Usage](/ja/reference/workflow-steps/general/get-workspace-usage/) を参照してください。
- **AIアシスタントはテーブルの公開を解除し、プロジェクトのデフォルトのダッシュボード対象者を設定できます。** `publish_manage` は、テーブルと、その公開ビュー、どのチャートでも使われていないダッシュボードデータセットの公開を解除します。チャートがまだ使っているデータセットは残り、公開ビューの上にレポートビューが作られている場合はビューとデータセットも残りますが、テーブルの公開は解除されます。`project_upsert` は `dashboard_default_audience` を設定します。これはプロジェクトの新しいダッシュボードの共有先となるグループで、`[]` を指定すると消去されます。[公開解除](/ja/guides/data/publish/#ai-アシスタントまたは-mcp-で公開を取り消す) と [AIアシスタントまたはMCPでデフォルトの対象者を設定する](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ai-アシスタントまたは-mcp-でデフォルトの対象ユーザーを設定する) を参照してください。

- **Gitアプリがリポジトリを一覧表示し、できることを案内します。** アプリ一覧の **Git** には、お客様のロール（**管理者**、**コントリビューター**、**閲覧者**）とワークスペースのリポジトリが表示され、各リポジトリには説明、最終更新日、コピーボタン付きのクローンアドレス、**開く** が付きます。**Set up Git on your computer** カードがGitのインストール、トークンの作成、クローンの手順を案内し、**How to clone** で再び開けます。**View all in Git** でGitの完全なインターフェースが開き、**Manage who can push** でグループ管理が開きます。アクセスレベルは **閲覧者**、**コントリビューター**（`apps` にアプリコードをプッシュ）、**管理者**（`udfs` を含むすべてにプッシュ）で、閲覧者には依頼先として最大3人のワークスペース管理者が表示されます。新しい **Git Contributors** グループはコントリビューター権限を付与し、デフォルトグループにできるため、新しいメンバーは自動的にこの権限を得ます。**Git Administration** は管理者権限を付与します。メンバーの **Git** タブには、Gitユーザー名、レベル、そのレベルを付与しているグループが表示されます。アプリのウィンドウには **リポジトリ** セクションが表示され、UDFには **開く** が追加され、Gitにはワークスペースへ戻る **← Back to** リンクがあります。[PlaidCloud Git](/ja/guides/git/#gitを開く) を参照してください。
- **モバイルのWeaveでの音声入力は、1タップで使えます。** マイクをタップして質問を話すと、話し終えたところでWeaveが送信します。早く止めたいときはもう一度マイクをタップします。何も聞こえなければ自動的にオフになります。話している途中で **Weave** タブを離れたりアプリをバックグラウンドにしたりしても、話した内容は送信されずに質問ボックスに残るので、確認できます。実行、一時停止、停止、再開は、確認時の誤った二重タップを無視します。アプリのバージョン1.3.0以降が必要です。[音声を使う](/ja/guides/mobile-app/weave-on-mobile/#音声を使う) を参照してください。

## 変更

- **ステップフォームは1つのレイアウトに統一されました。** タブは標準の名前と順序（一般、設定、ソース、列、フィルター、出力、詳細設定）になり、ERP転記フォームにはヘッダー列と明細列が加わります。必須フィールドには * が付き、フォームが保存をブロックするのは、そのステップに必要な項目についてだけです。
- **プロジェクトをコピーではテーブルデータとディメンションメンバーを個別に選択でき、データのコピーが高速になり、プライベートコピーはERP書き込み承認を保持します。** **Data to copy** で **テーブルデータ**（**No table data**（デフォルト）、**完全**、**サンプル**）を選択し、それとは別に **Copy dimension members**（デフォルトでオン）を選択します。そのため、テーブルの行なしのコピーでも、ディメンションにはメンバーが入った状態で届き、短時間で作成できます。**完全** と **サンプル** のコピーは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも早く終わります。**コピー結果** には、テーブルと並んで各ディメンションの結果が一覧表示され、**Retry failed items** は失敗したテーブルとディメンションをまとめて再試行します。データ付きで新しく作成したコピーはお客様だけのプライベートなもので、コピー元のERP書き込み承認のうち、お客様自身が付与できるものを保持します。コピー元がLiveで転記する場合、コピーはSimulateで届くため、Liveに切り替えるまでERPには何も届きません。REST APIと `project_copy` MCPツールも `dimension_members` を受け付けます。[コピーするデータ量を選ぶ](/ja/guides/projects/managing-projects/#コピーするデータ量の選択) と [コピーに含まれるERP書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認) を参照してください。
- **行アクションメニュー（⋯）がすべてのグリッド行の左端に表示されます。**
- **アプリのタブアイコンが、ライトとダークの両方で統一されたセットになりました。**
- **検証設定のない保存済みのERP書き込みステップは、検証のみで開きます。** 対象はSAP Post、SAP Attach、NetSuite Post、Oracle EBS GLおよびAP Post、Xeroエクスポートです。明示的にLiveで実行する設定になっているステップはLiveのままです。
- **長時間実行されるジョブの進行状況が、どこでも同じ方法で表示されます。**
- **ワークフローを停止すると、それが開始したすべてが停止し、完了できない実行やステップはハングせずに失敗します。** 停止すると、キューにあるインポートとディメンションのステップがキャンセルされるため、ワークスペース内の後続のインポートとディメンションのロードは通常どおり開始されます。ワークフローのキューにある、または実行中のコネクター（Singer）の同期も停止します。ステップのジョブを開始できない場合、ステップは待ち続けることなく理由を示して失敗します。ワーカーが約40分以内にジョブを開始しない場合、ワーカーが開始した後に消えた場合、そのPodが約20分間Pendingのままの場合、イメージを約5分間取得できない場合、Podが約20分間作成されない場合です。ランナーが約30分以内に拾わないコネクターの同期は、その同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間、ステータスメッセージには経過分数とともに「ワーカーを待機しています…」と表示され、処理が始まると消えます。マクロを停止すると、実行中のすべてのコピーが停止します。他のワークフロー内でのみ実行中のマクロは、ワークフロー一覧に **実行中** と表示され、**停止** を使用でき、各ステップのステータス、開始時刻、終了時刻は直近の実行のものが表示されます。サーバーが失われた実行は失敗として終了し、12時間経っても実行中の実行は「実行に失敗しました: 12時間の上限を超えても実行中です。ワークフローを再実行してください。」で失敗します。[ワークフローを実行する](/ja/guides/workflows/run-a-workflow/#開始されないステップ) を参照してください。
- **再開、実行履歴、実行ステータスが、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローの1つのステップだけを単独で再実行した後でも、子ワークフローに残っていたものがすべて実行され、1回の実行内での子ワークフローの各呼び出しには、それぞれ実行履歴のエントリーがあります。サーバーが停止したために再開するステップは、そのログにそう記録されます。`workflow_run_status` とREST APIの実行結果は、実行をエラーなしと報告する代わりに、失敗したが続行したステップを `continued_step_ids` と `continued_step_count` に一覧表示します。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開) と [エラー時に続行](/ja/guides/workflows/continue-on-error/) を参照してください。
- **ステップのエラーに、そのエラー自体のメッセージが表示されます。** PlaidCloudが想定していなかったエラーは、「ステップが予期しないエラー（*type*）で停止しました: *message*」と表示されます。ランチャーの **要対応** カードにはエラーが1行で表示され、すでに削除されたワークフローの実行は除外されます。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/) を参照してください。
- **完了しないERP抽出はステップを失敗させ、再開すると続行されます。** **SAP: アドホック抽出** が行数または時間の上限で一時停止したとき、またはそのエージェントが時間内に応答しないとき、あるいはSalesforce、Oracle Fusionバルク、HFM/FCCSのエクスポートジョブがステップの待機終了時点でまだ実行中のとき、ステップは失敗するため、後続のステップが一部しかないテーブルで実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は停止した場所から同じジョブで続行されます。[実行制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限) と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合) を参照してください。
- **REST、Import REST、Import Postmanステップは、ワークスペースのアップグレード時にRESTリクエストに変換されます。** きれいに変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/) を参照してください。
- **プロジェクトのアーキテクトは、ダッシュボードで行制限付きテーブルのすべての行を表示できます。** これはAnalyzeでの表示と一致します。アーキテクトのアクセス権の取り消しは、ダッシュボードにすぐに反映されます。ユーザーのロールを変更した場合、ユーザーまたはそのグループをプロジェクトから削除した場合、プロジェクトのアクセスタイプを変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれでも同様です。元アーキテクトが、行制限付きデータのすべての行を表示することはなくなります。[行アクセスを管理する](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理) を参照してください。
- **セッションの期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードへ移動します。** [ダッシュボードを使う](/ja/guides/dashboards/using-dashboards/) を参照してください。
- **MCPツールは認識できないフィールドを無視せず、拒否してエラーでそのフィールド名を示します。** `workflow_upsert` は `memo` を受け付け、その別名として `description` も受け付けます。[不明なフィールドは拒否されます](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される) を参照してください。
- **Lakehouse v2では、レイクハウスがParquetのエクスポートをGoogle Cloud Storageに直接書き込みます。** Google Cloud Storageのドキュメントアカウントへのエクスポートは、すべての行がいったんPlaidCloudを経由する代わりに、アカウント自身の認証情報で書き込まれ、アカウントのバケットに直接格納されます。Amazon S3とAzure Blob Storageのアカウントへのエクスポートは、従来どおり動作します。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/) を参照してください。
- **Slack、Microsoft Teams、Web Hookステップは、メッセージが送信されなかった理由を示します。** ステップのエラーには、接続しようとしたサーバーと、SlackとTeamsの場合は接続が示され、何が起きたかが説明されます。たとえば、Slackがwebhookを認識しなくなった、チャンネルに投稿できない、サーバーが見つからないか60秒以内に応答しない、接続が削除された、などです。SlackまたはTeamsのwebhook URLは、それを持つ人なら誰でもお客様の連携として投稿できるため、表示されることはありません。[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/) を参照してください。

## 修正

- **無効なプロジェクト設定が、わかりやすいメッセージで報告されます。** 不明な環境またはドキュメントアカウント、使用済みまたは予約済みのスラッグ、無効なストレージタイプまたは転記モードについて、汎用のサーバーエラーではなく、問題を示すメッセージが返されます。REST APIでは500ではなく400、AIアシスタントまたはMCPでは無効な引数のエラーになります。
- **REST APIのディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして処理され、無効として拒否されていました。現在は `value_columns` の各列について集計値を1つずつ返します。行フィルターと列フィルターの組ごとに値を1つ返すグリッドには、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **処理の遅いテーブル読み取りとファイル処理が、他のリクエストを止めなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundationファイルの登録、Excelへのエクスポート、RESTまたはSOAPインポートの応答の読み取り、ドキュメントアカウントの使用箇所の検索、Panelアプリのコードやロゴの確認は、いずれも完了するまで、同じサーバーが処理している他のすべてのリクエストを一時停止させることがありました。現在はそれらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 小さい画面や低い解像度では、追加と編集のダイアログがウィンドウより高くなり、**作成** と **更新** ボタンに手が届かないことがありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storageドキュメントアカウントの256 MiBを超えるファイルをコピー、移動、名前変更できます。** これらはいずれも、そのサイズのファイルで失敗していました。そのようなファイルを含むフォルダーの移動や名前変更も同様でした。
- **Lakehouse v2では、テーブルの行数が書き込んだばかりの内容を反映します。** テーブルに書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロード直後のテーブルが0行と表示されたり、インポートが0行インポートと報告されたりしていました。現在は、新しい行がどこからでも見える状態になってから行数を読み取るため、後続のステップもそれらを読み取れます。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりした場合も、行数と列数が更新されます。
- **Weaveの空値チェックは、以前の実行が実際に残したものと比較します。** ステップの空値は、ステップがテーブルを空にして再入力した直後にカウントされることが多く、そのため以前の実行には空値がなかったように見え、常に一部が空だった列が、たった今そうなったかのように報告されていました。現在は、ステップがテーブルを残した状態で各実行をカウントします。以前に記録されたカウントは正しいものと区別できないため使用されず、各ステップの空値チェックは履歴をやり直し、5回の実行がカウントされるまでは未チェックとして報告されます。行数と値のばらつきのチェックも、別のステップが同じテーブルに、完了から2秒より後に行った書き込みを、そのステップの書き込みとして扱わなくなりました。[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/) を参照してください。
- **削除された接続をREST APIで要求すると404が返ります。** 削除された接続や存在しないIDを要求すると、汎用のサーバーエラー（500）が返されていました。現在は、接続IDを示すメッセージとともに404が返ります。

## セキュリティ

- **行アクセスの保存では、ソースにもうない付与済みの値が保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がなくなった場合、ディメンションからメンバーがなくなった場合、リストにその値がなくなった場合に、次回の保存時に付与から外れていました。何もチェックされていないグループは **その他すべてのユーザー** にフォールバックし、それがすべての行を意味することがありました。現在は、値はマーク付きでグリッドに残り、**保存** は保持するか削除するかを確認します。[行アクセスグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド) を参照してください。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントのオーナーだけです。** ドキュメントアカウントを以前のバージョンに復元すること、バージョンを保留または解除すること、バックアップを取ることには、アカウントのオーナーの1人であることが必要になり、システム管理のアカウントではどれも使用できません。アカウントのバージョン履歴を表示するには、そのアカウントへのアクセスが必要です。
- **データの読み取り専用のクエリが、データを変更できなくなりました。** AIアシスタントとMCPクライアントが使用する `query_run` ツールは、データを読み取る文（SELECTまたはWITH文1つ、そのEXPLAIN、またはSHOW）だけを実行し、それ以外は実行せずに拒否します。データを変更するには `query_transform` を使用してください。MCPのテーブルエクスポートのSQLにも同じルールが適用されます。REST APIとJSON-RPC APIでは、プロジェクトデータを変更できないメンバーについて、クエリの実行、列ファセットの作成、クエリのCSVダウンロード、クエリのリモートデータベースへのエクスポート、独自のクエリによるテーブルデータのエクスポートにも適用され、拒否されたクエリは403を返します。Explain Analyzeは計測のためにクエリを実行するため、クエリログとレイクハウスでは読み取りのクエリだけを受け付けるようになり、行アクセスのあるプロジェクトでは、クエリログから実行できるのはプロジェクトのアーキテクトだけです。
