## 追加

- **コントロールプレーンの Trust Center で、セキュリティ担当チームが PlaidCloud のセキュリティドキュメントを入手できます。** 管理者とセキュリティのユーザーは、組織の**Trust Center**を開き、サブプロセッサー一覧や DPA などの公開ドキュメントをすぐにダウンロードできます。また、セキュリティドキュメント用 NDA に組織として一度署名すると、SOC 2 Type II レポートなどの制限付きドキュメントのロックが解除されます。ほかの管理者とセキュリティのユーザーには、署名者と署名日が表示されます。契約にすでに NDA が含まれている組織は、NDA を登録済みとして設定でき、署名なしでドキュメントのロックが解除されます。制限付きドキュメントのダウンロードには透かしが入り、記録されます。NDA の新バージョンは再度の同意が必要です。管理者とセキュリティのユーザーは、組織ごとに、新規または更新されたドキュメントと NDA の新バージョンをまとめた毎日のメールを受け取るよう設定することもできます。メールにドキュメント本体が含まれることはありません。[Trust Center](/ja/administration/control-plane/trust-center/)を参照してください。
- **PlaidXL で、Excel 上でレポートの作成、ドリル、数値の説明、計画ができます。** **PlaidCloud**リボンタブは**接続**、**挿入**、**更新**、**ドリル**、**書き込み**、**共有**にグループ化されました。よく使うコマンドは**PlaidXL**右クリックメニューと**PlaidXL Cell**タブからも使え、主なコマンドには変更可能なキーボードショートカットがあります。フィールドに入力している間はショートカットは動作しません。コマンドが失敗すると、どのコマンドがなぜ失敗したかが表示されます。サインイン前に実行したコマンドはサインインを開き、サインイン後に一度だけ実行されます。サインインは1つのワークスペースに対して有効なため、ワークスペースを切り替えると新しいワークスペースへのサインインが求められます（元に戻す場合は求められません）。Office で Microsoft Entra の職場アカウントを使うと、PlaidXL がワークスペースを自動的に見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます。** **レポート**タブは、テーブルからライブレポートをレイアウトします。行方向にディメンションをドリルダウンし、列方向に別のディメンションを展開し、各交点に `CELL` 値を配置します。**Build my first report**は、お使いのデータからサンプルを作成します。ドリルすると、レポートは行全体と列全体を挿入または削除し、入力済みの値、メモ、書式は該当の行に付いたまま残ります。[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only**は、ノード、ディメンション見出し、レポートの値から、ノードをライブの `DRILL` 数式に変換して編集します。**Custom drill**は挿入前に行をプレビューし、メンバーピッカーはメンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりします。`DRILL` は、除外または展開するノードを指定でき、行をまたいで実行することもできます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明できます。** **Explain this number**は、値の計算内容、現在の PlaidCloud と一致しているか、元になっているテーブルとワークフローステップを示します。**Show detail rows**は、値の元になった行を専用のシートに表示し、合計が一致するかのチェックも行います。
  - **Excel でガバナンスされたメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるのと同じビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計では `0` を表示し、それ以外では理由とともに `#VALUE!` を表示します（`CELLS` のスピルでは空白）。**Metric...** ボタンは、プロジェクトのメトリックを現在の値とともに一覧表示します。メトリックは、複数の代替階層でフィルターしたり、代替階層のメンバーと他のディメンションのメンバーを組み合わせたりできます。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに入力して計画できます。** `CELL` の値に数値を上書き入力すると、PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの形に合わせた配分、金額またはパーセンテージによる調整が可能で、保留したセルはそのまま維持されます。平均、中央値、最小値、最大値、標準偏差、分散のセルにも入力した値を設定できます。入力した値は、行や列の挿入または削除に合わせてセルに追従します（削除されたセル内の値は報告されます）。**Undo last write**は、入力した値と保存を新しいものから順に取り消します。書き込みを取り消せるのは、その書き込みを行った本人と元のワークスペースだけです。合計の取り消しや、空のセルに入力した平均の取り消しでは、その後に同じセルへ書き込まれた内容が保持されます。完了前に中断された書き込みは取り消せません。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要なものだけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新できます。各テーブルの進行状況と**キャンセル**はタスクペインに表示されます。PlaidXL の数式だけを再計算することもできます。取得したテーブルは、データ型に合わせて書式設定された Excel テーブルとして取り込まれ、更新しても独自の列と数値書式が保持され、その場で更新されます。取得や更新で他のセルが上書きされたり、別の Excel テーブルと重なったりすることはなく、Excel で扱えないほど大きい整数 ID と1900年より前の日付はテキストとして取り込まれます。テーブルを再取得しても更新リストに重複して追加されず、**Stop refreshing**でリストから外せます。ディメンションもテーブルと一緒に更新されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud**は、確認なしで書き込み、実行内容を表示し、**元に戻す**を提供します。Lakehouse テーブルでは、保存後7日間まで元に戻せます。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーの保存では、該当する行だけが置き換えられるため、他のユーザーの行は保持されます。取得後にメンバーが変更されたドリルスルーのシートは保存されません。保存に失敗した場合は、テーブルを復元できるようにリストアポイントが示されます。[テーブルを PlaidCloud に保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave**タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼するか、**Ask Weave about this cell**を選択します。Weave はあなたとして PlaidCloud を読み取り、ブックだけを変更します。入力済みの内容を置き換える前に確認し、ブックの外に届く数式は書きません。各変更は、ペインを再読み込みするまで元に戻せます。[Excel で Weave に質問する](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1つのシートまたはブック全体の値のみのコピーを共有できます。** **Convert to values**は、ブック全体、1つのシート、または元に戻せない値への変換を行い（元に戻せない場合は先に確認します）、PlaidXL の数式とそのスピルだけを変更します。まだ計算中の数式は残して再試行でき、シートの名前を変更した後でも**Restore PlaidXL formulas**は引き続き使えます。
- **転記レジスターは、対応が必要な内容から開きます。** 確認が必要なものがある場合は**例外**で、承認待ちのリクエストがある場合は**承認**で、それ以外は**すべての転記**で開きます。レールの画面は**自分の対応待ち**、**レジスター**、**インサイト**、**設定**にグループ化され、**例外**と**承認**には件数が表示されます。すべての画面が共通のヘッダーとスコープバーを使用します。期間（**今月**、**前月**、**過去7日間**、**過去30日間**、**カスタム**）、接続、プロジェクト、環境、エンティティ、そして**本番**、**シミュレーション**、**すべて**を選び、**リセット**するか**Saved scope**を保持します。前回のスコープは記憶されます。
  - **例外で、確認が必要なものを整理できます。** **要確認**、**未確認**、**保留中**、**失敗**、**取消未完了**のチップに件数が表示されます。接続の正常性の行には「All N connections posting normally」と表示され、すべての転記に、次に何をすべきかのツールチップ付きで、分かりやすい状態が表示されます。未処理がない場合は**All clear**と表示されます。**Find a posting by ledger id**またはコマンドパレットに元帳 ID を貼り付けると、その転記が直接開きます。
  - **承認、委任、ウォッチは受信トレイ形式の画面です。** **自分の承認待ち**と**自分が申請したもの**を切り替え、理由を添えて**承認**または**却下**し、複数をまとめて承認し、トーストから承認を**元に戻す**ことができます。**承認の委任**は短いダイアログで、**ウォッチ一覧**には自分がフォローしているものが一覧表示されます。**転記を取消**、およびまとめての再試行とクリアのダイアログは、同じレイアウトを共有します。
  - **転記のドロワーで、何が起きたかが分かります。** 状態とその意味、名前付きの主要な事実、**明細**、**履歴**、**承認**タブが表示され、**レビュー済みにする**、**再試行**、**取消…** ボタン、**接続をウォッチ**、**実行をウォッチ**、**リンクをコピー**を使えます。**リンクをコピー**は、その転記を直接開きます。
  - **アシスト、エクスポート、保持期間も同じデザインに従います。** **アシスト**には質問ボックスとインサイトカードがあり、**Draft — nothing applied**と表示されたアドバイスと、**すべての転記**の異常カード（**これらを表示**付き）が含まれます。**エクスポートとアラート**には**新規スケジュール**があり、**保持期間**は1枚のカードになりました。
  - **レジスターは常に最新です。** レールのバッジは転記の変化に合わせて更新され、転記が変更されると開いている一覧に**更新**が表示され、開いているドロワーはその場で更新されます。**ホーム**の**要対応**の下に**転記レジスター**カードが表示されます。[転記レジスターを確認する](/ja/guides/connections/posting-register/)を参照してください。
- **プロジェクトホームは6つのページで構成されます。** テキストのみのレールには**概要**、**変数**、**スケジュールとセンサー**、**アクセスと共有**、**データと接続**、**アプリとブランディング**が並び、変数の数と、有効なスケジュールおよびセンサーの数がバッジで表示されます。**概要**には、プロジェクトの説明とラベル、ロックの状態、テーブル、ワークフロー、ステップ、変数、公開済みテーブル、**データサイズ**（**ストレージ**を開きます）のタイル、直近3回のスケジュール実行、プロジェクトのデフォルトが表示され、**プロジェクトレポート**（PDF またはインタラクティブ HTML）と**アーカイブのエクスポート**も利用できます。データサイズのタイルは**プロジェクト**画面と同じ合計を、復元用に保持されている以前のバージョンを含めて示し、ツールチップでは現在のデータと以前のバージョンを分けて表示します。それ以外のページでは、変数、スケジュールとセンサー（**カレンダービュー**と**有効化**、**無効化**付き）、プロジェクトとそのダッシュボードを開けるユーザー、およびそのテーブルを読み取れるプロジェクト、接続とテーブルストレージのデフォルトと ERP 転記モード、Panel アプリ、ブランディング、プロジェクトのタイル画像を管理します。ロックされたプロジェクトにはバナーが表示され、コントロールは無効になります。[プロジェクトホーム](/ja/guides/projects/project-home/)を参照してください。
- **ドキュメントは概要から開き、ページのレールが付きました。** **概要**、**参照**、**共有**、**自分の非公開**、**管理**がレールに並びます。**概要**には、アカウントのタイル、**Pinned**ファイル（クリックすると、ファイルを選択した状態でそのフォルダーの**参照**が開きます）、サービス別のアカウント、利用できるユーザーが表示されます。**管理**には自分が所有するアカウントが一覧表示され、ワークスペースの管理者はすべてのドキュメントアカウントを確認でき、ほかの方法で管理できるアカウントはすべて管理できます（システム管理のアカウントは拒否され、マネージドバケットのアカウントは複製できません）。行の **⋯** メニューには、**開く**、**編集**、**複製…** ボタン、**利用できるユーザー**、**使用箇所…** ボタン、**バージョン履歴**、**有効にする**または**無効にする**、**削除**があります。アカウントは**General**、**Access**、**Credentials**のカードを持つページとして開き（SFTP の場合は**SSH**カードも）、未保存の変更がある状態で離れる前に確認します。**参照**には、ラベル付きのツールバー、行メニュー、ドロップゾーン、各アップロードとテーブルへのインポートの進行状況と操作を表示する**Uploads and imports**パネルがあります。**Pop out**はフォルダーを別ウィンドウで開き、**Dock**で元に戻します。[ドキュメント](/ja/guides/documents/)と[ドキュメントアカウントの使用](/ja/guides/documents/using-document/)を参照してください。
- **ダッシュボードは概要から開き、ページのレールが付きました。** **概要**、**ダッシュボード**、**アプリ**、**ノートブック**、そしてワークスペース管理者向けの**アクセスレビュー**がレールに並び、下部に**ナビゲーターを開く**があります。**概要**には、対応する一覧を絞り込んだ状態で開くダッシュボードとアプリのタイル、最近開いたものやスターを付けたもの、失敗したアプリと自分の対応待ちのアクセスリクエスト、利用状況アクセスを持つメンバー向けの最も多く開かれたダッシュボードが表示されます。**ダッシュボード**は**すべて**、**管理中**、**お気に入り**で絞り込み、**アプリ**は各アプリの**種類**とライブの状態を表示します。[ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **アイデンティティは概要から開き、ページのレールが付きました。** レールには**概要**、**メンバー**、**ディレクトリ**、**セキュリティグループ**、**配布リスト**に続いて**セッション**、**セキュリティログ**、**APIクライアント**、**グループ監査**、**すべてのスコープ**が並び、**利用状況レポート**はページの上に重ねて開きます。**概要**には、メンバー、アクティブなメンバーとまだサインインしていないメンバー、ビルダーシート、現在サインインしているユーザーのタイル、**アクティブなメンバー**のチャート、**要対応**（**ウェルカムメールを再送信**と**確認**付き）、直近7日間のセキュリティイベントが表示されます。メンバーは**プロファイル**、**アクセス**、**グループとデータ**のカードを持つページとして開き、**メンバーを招待**は概要とホームの初回カードから使えます。[メンバー管理](/ja/administration/access/member-management/)を参照してください。
- **Lakehouse ウィンドウに、サイドレール、テーブルの詳細、タイムトラベルが加わりました。** **クエリ**、**プロファイル**、**ロード**、**カタログ**がレールに並び、**管理**の下に**Lakehouse カタログ**、**データベースユーザー**、**コンピュート**があります。**データベースユーザー**と**コンピュート**は、Lakehouse 管理者または Lakehouse クラスターのロールを持つメンバーにのみ表示されます。**クエリ**では、SQL テキスト、ユーザー、種類、所要時間で履歴を絞り込み、**Copy SQL**でステートメントをコピーし、**Profile this query**でクエリを**プロファイル**に開きます。**カタログ**では、テーブルの列、現在のスナップショット、パーティション分割、場所、プロパティ、スナップショット履歴を確認でき、**Copy query as of this snapshot**で、その時点のテーブルを読み取る `FOR VERSION AS OF` クエリをコピーします。[Lakehouse ウィンドウ](/ja/guides/data/lakehouse-window/)を参照してください。
- **ステップフォームのプレビュー。** インポート: SQL、Execute: SQL、SQL抽出、エクスポート: SQL、Salesforce: オブジェクトのクエリの各ステップは、ステップを実行せずに最大100行を表示し、Anaplan のビューとリストの読み取りは、生成される列と型を表示します。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように埋め込まれますが、`{x:>9}` のような変数の書式はサポートされません。プレビューが実行するのは標準の SQL 関数のみで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトと、エージェントベースの Execute SQL ステップでは利用できません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と[SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)を参照してください。
- **利用状況レポートで、変化の確認、グループへの絞り込み、ワークフローへの連携ができます。** **概要**に、前の期間と比較するトレンド矢印と、非アクティブなメンバーや誰も開いていないダッシュボードとアプリを示す**Highlights**リストが加わりました。無効化されたメンバーは、非アクティブとして集計も一覧表示もされません。**グループ**は**概要**、**内容**、非アクティブ一覧を1つのセキュリティグループのメンバーに限定します。日付範囲には**前月**と**今月**が加わり、すべてのタブで共有され、アカウントに記憶されます。すべての数値に説明が付き、テーブルは**メンバー**や**エリア**などの分かりやすい名前を使い、行は Enter キーで開き、読み込みとエラーの表示が分かりやすくなり、**ファネル**の最後のステップには完了したメンバーの数が表示されます。**Get Workspace Usage**ステップは、使用状況をスケジュールに従ってテーブルに書き込みます。メンバー名なしの日次または月次の合計として、またはレポート用のデータセット（**メンバー**、**Daily per member**、**内容**、**Content per member**）として書き込めます。メンバーのデータセットには氏名、メールアドレス、グループ、アクティビティが含まれるため、メールアドレスで自社の組織テーブルと結合して、部署ごとのアクティブ時間やダッシュボードを開いた回数をレポートできます。**Get Workspace Members**と同様に、実行のたびにセキュリティログに記録されます。[利用状況レポート](/ja/administration/access/usage-reports/)と [Get Workspace Usage](/ja/reference/workflow-steps/general/get-workspace-usage/) ステップを参照してください。

- **Git アプリに、リポジトリと自分にできる操作が一覧表示されます。** アプリ一覧の**Git**には、自分のロール（**管理者**、**コントリビューター**、**閲覧者**）と、ワークスペースのリポジトリが表示されます。各リポジトリには、説明、最終更新日、コピーボタン付きのクローン用アドレス、**開く**が表示されます。**Set up Git on your computer**カードでは、Git のインストール、トークンの作成、クローンの手順を案内し、**How to clone**で再度開けます。**View all in Git**は完全な Git インターフェースを開き、**Manage who can push**はグループ管理を開きます。アクセスレベルは、**閲覧者**、**コントリビューター**（`apps` にアプリコードをプッシュ）、**管理者**（`udfs` を含むすべてにプッシュ）で、閲覧者には、依頼先として最大3人のワークスペース管理者が表示されます。新しい**Git Contributors**グループはコントリビューターの権限を付与し、デフォルトグループにもできるため、新しいメンバーに自動的に付与されます。**Git Administration**は管理者の権限を付与します。メンバーの**Git**タブには、Git のユーザー名、レベル、権限を付与しているグループが表示されます。メンバーの Git アカウントはメンバーシップに連動します。メンバーを無効化または削除すると、トークンと SSH キーを含む Git アカウントが約1時間以内にブロックされ、再有効化するとブロックが解除されます。リポジトリと履歴は保持されます。シングルサインオンで Git にサインインすると、そのメンバー自身のアカウントが開きます。コントリビューターは、ワークスペースの Git 組織に直接リポジトリを作成しません。リポジトリは PlaidCloud から作成されます。アプリのウィンドウには**リポジトリ**セクションが表示され、UDF には**開く**があり、Git にはワークスペースに戻る **← Back to**リンクが加わりました。アプリのリポジトリや組み込みの `apps`、`udfs` リポジトリを含め、プラットフォームが作成するすべてのリポジトリは、ワークスペースのサインイン済みのすべてのメンバーが読み取れるため、メンバーはリポジトリごとの設定なしでアプリを開いて再公開できます。Git 管理者は引き続きリポジトリを非公開にできます。非公開にすると、リポジトリピッカーに表示されなくなり、メンバーはそのリポジトリからの公開や、そこに保存された Git ベースの UDF コードの実行ができなくなります。[PlaidCloud Git](/ja/guides/git/#gitを開く)と[リポジトリを閲覧できるユーザー](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)を参照してください。
- **Cost to Serve と Operational Transfer Pricing のテンプレートは Common Finance Model を基盤にしています。** **Cost to Serve**からプロジェクトを開始すると、部門ごとに設定したアクティビティとドライバーによって営業費用を顧客に配分し、各顧客のサービス提供コスト控除後のマージンを、総勘定元帳に結び付けて確認できます。**Operational Transfer Pricing**から開始すると、各エンティティの利益水準（売上高利益率、ネットコストプラスまたは再販価格マイナス）をポリシーの範囲に照らしてテストし、範囲外のエンティティを目標に戻す調整額を算出できます。売上高利益率は、EBIT を被テスト当事者の売上高で割った値です。[Cost to Serve](/ja/guides/projects/cost-to-serve/)と [Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/)を参照してください。
- **OneStream と Anaplan が Data Foundation にデータを提供し、OneStream には読み取りステップがあります。** Data Foundation は、OneStream の連結結果を OneStream 管理者が構築するデータアダプター経由で、Anaplan のプランをエクスポートアクション経由で読み取り、グループの損益計算書をそれらと突き合わせます。新しい**OneStream: Read Adapter**ステップは、アダプターを、連結メンバーごとに1回呼び出して、任意のワークフローのテーブルに読み取ります。[Data Foundation 向けの OneStream](/ja/guides/connections/onestream-for-data-foundation/)、[Data Foundation のソースとしての Anaplan](/ja/guides/connections/anaplan/#data-foundation-のソースとしての-anaplan)、[OneStream: Read Adapter ステップ](/ja/reference/workflow-steps/onestream/onestream-read-adapter/)を参照してください。

## 変更

- **ワークスペースでGrokを使用している場合、モバイルのWeaveはAIに関する通知への同意を再度求めます。** この通知は、xAIがお客様のデータをモデルの学習に使用しないとは述べなくなりました。PlaidCloudはxAIとゼロデータ保持契約を結んでいないため、xAIはそのデータを保持し、標準利用規約が認める範囲で使用する場合がある、と説明します。[Weaveによるお客様のデータの利用について](/ja/guides/ai-assistant/weave-data-use/)を参照してください。
- **ホワットイフウィンドウは、一度に1つの期間を読み取ります。** Allocation Splitステップの出力に期間列がある場合、ウィンドウは最新の期間で開き、**期間:** で別の期間または**すべての期間**を選択できます。ドライバーが期間ごとに行を持ち、すべての期間をまたぐと大きすぎて読み取れなかったステップも、1つの期間で開いて回答できるようになりました。保存したシナリオには、保存時の期間（ある場合）が保存され、開くと、その期間が一覧に残っている限り、ウィンドウがその期間に移動します。[期間を選択する](/ja/guides/allocations/results/driver-what-if/#期間を選択する)を参照してください。
- **PlaidCloud の Web アプリと Python クライアントライブラリは REST API を使用し、JSON-RPC は非推奨になりました。** Web アプリはリクエストを REST API に送信します。`plaidcloud-rpc` 1.25.0以降では、`SimpleRPC` の呼び出しはコードを変更しなくても REST API に送られます。REST API がまだ対応していない呼び出しや、古いリリースのままのワークスペースでは、従来どおり JSON-RPC が使われます。JSON-RPC は今後のリリースで削除されるため、スクリプトとノートブックを `plaidcloud-rpc` 1.25.0以降にアップグレードし、新しい連携は REST API で作成してください。[コマンドライン](/ja/reference/cli/jupyter/command-line/)を参照してください。
- **ステップは、別の環境に固定しない限り、プロジェクトの接続環境に従います。** プロジェクトの環境（QA や本番など）を切り替えると、すべてのステップが移動します。1つの環境にとどめる必要があるステップには、代わりに**Fixed environment**を設定できます。フォームには警告が表示され、ログにはプロジェクトの環境以外で実行するたびに記録が残り、プロジェクトを切り替えるときには、従わないステップが表示されます。ERP 転記ステップは、常にプロジェクトの環境を使用します。プロジェクト、固定されたステップ、またはエージェントが使用している環境は削除できず、エージェントフォームのフィールドは**Environment this agent serves**になりました。[ステップを1つの環境に固定する](/ja/guides/projects/managing-projects/#ステップを1つの環境に固定する)を参照してください。
- **ステップフォームは1つのレイアウトに統一されました。** タブには標準の名前と標準の順序（General、Settings、Source、Columns、Filters、Output、Advanced）があり、ERP 転記フォームには Header columns と Line columns が加わります。必須フィールドには * が付き、フォームはステップに必要なものについてのみ保存をブロックします。
- **プロジェクトのコピーで、テーブルデータとディメンションメンバーを別々に選べ、データのコピーが高速になり、非公開コピーの ERP 書き込み承認が保持されます。** **Data to copy**で、**テーブルデータ**（**No table data**（デフォルト）、**完全**、**サンプル**）と、別に**Copy dimension members**（デフォルトでオン）を選択します。そのため、テーブルの行なしのコピーでも、ディメンションにはデータが入った状態で作成され、短時間で完了します。**完全**と**サンプル**のコピーは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも短時間で完了します。**コピー結果**には、テーブルと並んで各ディメンションの結果が一覧表示され、**Retry failed items**は失敗したテーブルとディメンションをまとめて再試行します。データ付きで作成した新しいコピーは自分だけの非公開で、コピー元の ERP 書き込み承認のうち自分で付与できるものが保持されます。コピー元が本番で転記している場合、コピーはシミュレーションで作成されるため、本番に切り替えるまで ERP には何も届きません。REST API と `project_copy` MCP ツールも `dimension_members` を受け付けます。[コピーするデータ量を選ぶ](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピー内の ERP 書き込み承認](/ja/guides/projects/managing-projects/#コピーでのerp書き込み承認)を参照してください。
- **テーブルの詳細パネルに、そのテーブルを使うステップがより早く表示されます。** 別のテーブルを選択すると、前のテーブルのステップがすぐに消え、このプロジェクトのデータを共有する他のプロジェクトのステップは、パネル全体を待たせずに、少し遅れて追加されます。[テーブルの使用箇所を確認する](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)を参照してください。
- **行の操作は、すべての一覧で同じように動作します。** 行のメニューは、行の先頭にある **⋯** ボタン、行の右クリック、ツールバーの**アクション**メニューから開きます。常に、**開く**、**詳細**、**編集**が先頭に並び、続いてその一覧固有の操作、最後に**削除**が表示されます。その行に当てはまらない操作は、その場所でグレーアウトされます。**Enter**と**Del**は、実行するアイテムに表示されます。行の操作が1つだけの一覧では、**⋯** の代わりにその操作のアイコンが表示され、ダッシュボード、アプリ、ノートブックでは、**開く**アイコンが再び表示されます。[行操作メニュー](/ja/guides/dashboards/using-dashboards/#行アクションメニュー)を参照してください。
- **PlaidCloud の外観が、ライトとダークの両方で新しいブルーに刷新されました。** ボタン、チェックボックス、選択された行、タブ、リンク、ワークスペースのページを一覧表示するレールには、両方のテーマで読み取れるコントラストを備えた1つの PlaidCloud ブルーが使われます。アプリのタブアイコンは1つの統一されたセットになりました。
- **新しい読み込み画面。** PlaidCloud は、ライトまたはダークのテーマに合わせた、すっきりした読み込み画面で開きます。アイドル状態から復帰する Panel または Dash アプリは、**開始中**、**準備中**、**アプリを読み込み中**と進行状況を表示し、起動しなかった場合は、どの段階で止まったかを示して**再試行**を提示します。[Panel アプリの使用](/ja/guides/panel-apps/using/)を参照してください。
- **検証設定のない保存済みの ERP 書き込みステップは、検証のみで開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS の GL と AP の Post、Xero のエクスポートです。本番で実行するよう明示的に設定されたステップは、そのまま本番で実行されます。
- **長時間実行されるジョブの進行状況が、どこでも同じ方法で表示されます。**
- **ワークフローは正直に停止、失敗、報告します。** ワークフローを停止すると、そのワークフローが開始したものすべてが停止し、完了できない実行やステップはハングせずに理由付きで失敗し、実行ステータスは実際に実行された内容と一致します。
  - **ワークフローを停止すると、そのワークフローが開始したものすべてが停止し、完了できない実行やステップはハングせずに失敗します。** 停止すると、キューに入ったままのインポートとディメンションのステップがキャンセルされるため、ワークスペース内の後続のインポートとディメンションのロードは通常どおり開始されます。また、そのワークフローのキュー中または実行中のコネクター（Singer）同期も停止します。ステップのジョブを開始できない場合、ステップは永久に待機せず、理由付きで失敗します。約40分以内にワーカーが開始しない、ワーカーが開始した後にいなくなった、ポッドが約20分間 Pending のままである、イメージを約5分間取得できない、約20分間ポッドが作成されない、のいずれかの場合です。どのランナーにも約30分以内に取得されないコネクター同期は、同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間、そのステータスメッセージには経過分とともに「ワーカーを待機しています…」と表示され、作業が始まると消えます。マクロを停止すると、実行中のそのすべてのコピーが停止します。1つのコピーの停止や、応答しなくなったコピーを**Macro Concurrent**ステップが見切ることでは、呼び出し元のワークフローは実行されたままです。他のワークフロー内でのみ実行されているマクロは、ワークフロー一覧で**実行中**と表示され、**停止**が使え、各ステップのステータスと開始・終了時刻は最新の実行のものが表示されます。サーバーが失われた実行は失敗として終了し、12時間たっても実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」で失敗します。[ワークフローを実行する](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
  - **再開、実行履歴、実行ステータスは、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローのステップを単独で再実行した後でも、子ワークフローに残っていたものがすべて実行されます。1回の実行内での子ワークフローの呼び出しごとに、実行履歴のエントリが作成されます。サーバーが停止したために再開されたステップは、そのログに記録されます。`workflow_run_status` と REST API の実行結果は、失敗したものの続行したステップを、実行をクリーンとして報告する代わりに、`continued_step_ids` と `continued_step_count` に一覧表示します。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時の続行](/ja/guides/workflows/continue-on-error/)を参照してください。
  - **ステップのエラーに、それ自身のメッセージが表示されます。** PlaidCloud が想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードにはエラーが1行で表示され、すでに削除されたワークフローの実行は含まれません。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。
  - **完了しない ERP 抽出はステップを失敗させ、再開で続行できます。** **SAP: アドホック抽出**が行数または時間の上限で一時停止した場合や、エージェントが時間内に応答しなかった場合、また、Salesforce、Oracle Fusion の一括エクスポート、HFM/FCCS のエクスポートジョブがステップの待機終了時にまだ実行中の場合、ステップは失敗します。そのため、後続のステップが一部のみのテーブルに対して実行されることはありません。ワークフローを再開するか、ステップを再実行すると、抽出は同じジョブで、止まった場所から続行されます。[実行上限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)を参照してください。
  - **エクスポートをキャンセルすると、ウェアハウスでのクエリも停止します。** エクスポートまたはダウンロードがキャンセルされると（ワークフローの停止による場合も含む）、そのデータを読み取っているクエリも、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplum で停止し、リモートデータベースへのエクスポートはソースの読み取りを停止します。最後まで実行され続けることはありません。
- **REST、Import REST、Import Postman の各ステップは、ワークスペースのアップグレード時に RESTリクエストに変換されます。** きれいに変換できないステップは、そのまま残ります。[REST Request ステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **セッションの期限切れ後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードを開きます。** [ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは、認識できないフィールドを無視せず、エラーでそのフィールドを示して拒否します。** `workflow_upsert` は `memo` を受け付け、その別名として `description` も受け付けます。[不明なフィールドは拒否される](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2では、Lakehouse が Parquet エクスポートを Google Cloud Storage に直接書き込みます。** Google Cloud Storage ドキュメントアカウントへのエクスポートは、すべての行が最初に PlaidCloud を経由するのではなく、アカウント自身の認証情報でアカウントのバケットに直接書き込まれます。Amazon S3と Azure Blob Storage アカウントへのエクスポートは、従来どおり動作します。[Export to Parquet ステップ](/ja/reference/workflow-steps/export/export-to-parquet/)を参照してください。
- **Slack、Microsoft Teams、Web Hook のステップが、メッセージを送信できなかった理由を示します。** ステップのエラーには、接続しようとしたサーバーと、Slack と Teams の場合は接続が示され、何が問題だったかが説明されます。たとえば、Slack がもうそのウェブフックを認識しない、チャンネルに投稿できない、サーバーが見つからないか60秒以内に応答しない、接続が削除された、などです。Slack または Teams のウェブフック URL は、それを知っていれば誰でも連携先として投稿できてしまうため、表示されません。[Notify via Slack ステップ](/ja/reference/workflow-steps/notifications/notify-via-slack/)を参照してください。
- **プロジェクトのサービスアカウントのアクセストークンは、少なくとも24時間有効です。** UDF ステップなど、プロジェクトとして実行されるワークフロージョブは、24時間有効なトークンを取得します。これより短い有効期間は、ワークスペースのアップグレード時に引き上げられ、設定した長い有効期間はそのまま維持されます。
- **ワークスペースの組織、オーナー、リリース、バージョンは PlaidCloud が設定し、データセンターはお客様が選択します。** コントロールプレーンで作成するワークスペースは自分が所有し、PlaidCloud が設定するリリースチャネルに配置され、サインアップ時に提供されるリージョンから**Data Center**を選択します。ワークスペースを編集するとき、組織、オーナー、リリース、バージョンは読み取り専用です。バージョンを変更するには**Set Version**を使用し、ワークスペースの移動、オーナーやチャネルの変更、ピン留めは PlaidCloud サポートに依頼してください。[ワークスペースの設定](/ja/administration/control-plane/workspace-configuration/#基本設定)を参照してください。

## 修正

- **無効なプロジェクト設定が、分かりやすいメッセージで報告されます。** 不明な環境やドキュメントアカウント、使用済みまたは予約済みのスラッグ、無効なストレージタイプや転記モードに対して、汎用のサーバーエラーではなく、問題を示すメッセージが返されるようになりました。REST API では500ではなく400、AI アシスタントまたは MCP では引数無効のエラーになります。
- **REST API のディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして扱われ、無効として拒否されていました。現在は `value_columns` の各列について1つの集計値を返し、グリッド（行フィルターと列フィルターの各組み合わせにつき1つの値）には専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` が用意されています。
- **テーブルの読み取りやファイル処理が遅くても、他のリクエストを止めなくなりました。** ウェアハウスからのテーブル列の読み取り、Data Foundation のファイル登録、Excel へのエクスポート、REST または SOAP インポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panel アプリのコードやロゴのチェックは、それぞれが完了するまで、同じサーバーが処理している他のすべてのリクエストを一時停止させることがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 小さい画面や低い解像度では、追加と編集のダイアログがウィンドウより高くなり、**作成**と**更新**のボタンに手が届かないことがありました。フォームがスクロールし、ボタンは下部に固定されるようになりました。
- **Azure Blob Storage ドキュメントアカウントの256 MiB を超えるファイルをコピー、移動、名前変更できます。** これらの操作は、そのサイズのファイルで失敗しており、そのようなファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2では、テーブルの行数が書き込んだ直後の内容を反映します。** テーブルに書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが0行と表示されたり、インポートが0行インポートと報告したりしました。行数は、新しい行がどこからでも見える状態になってから読み取られるため、後続のステップもその行を読み取れます。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりしたときも、行数と列数が更新されます。
- **Weave の空値チェックは、各実行を、以前の実行が実際に残した内容と比較します。** ステップの空値が、ステップがテーブルを空にして再投入した直後に数えられることが多く、そのため以前の実行には空値がなかったように見えたり、以前から一部が空だった列が、たった今そうなったかのように報告されたりしていました。現在は、ステップがテーブルを残した状態で各実行が数えられます。以前に記録された件数は、正しいものと区別できないため使用されません。各ステップの空値チェックは履歴を最初からやり直し、5回の実行が数えられるまで未チェックとして報告されます。行数と値の分散のチェックも、別のステップが同じテーブルに、そのステップの終了から2秒以上たってから行った書き込みを、そのステップの書き込みとして扱わなくなりました。[Weave が確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **Data Foundation は、反転した為替レートと小数のしきい値の精度を保持します。** お客様のレートが報告通貨から別の通貨への換算で提示されているために PlaidCloud が反転させるレートは、小数第6位に丸められることがあり、インドネシアルピアのようにレートが小さい通貨の金額が約1% ずれていました。反転したレートは小数第12位まで保持されるようになりました。`0.5` のように小数を含む `group_amber` または `group_red` のしきい値は、整数に丸められていました。次回のロードから、正確な値が使われます。[為替レート](/ja/guides/projects/data-foundation/#為替レート)を参照してください。
- **無効化されたメンバーのアラートとダイジェストが停止します。** オーナーが無効化された Panel アプリのアラートやダイジェストは、チェックと送信を続けていました。現在は、無効化されている間は一時停止し、再有効化されると再開します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
- **削除された接続を REST API で要求すると404が返ります。** 削除された接続や存在しない ID を要求すると、汎用のサーバーエラー（500）が返されていました。現在は、接続 ID を示すメッセージとともに404が返ります。
- **テンプレート化されたテーブルエクスポートが、AI アシスタントと MCP で動作します。** `table_data_export` の `templated` 形式は、テーブルを指定すると常に失敗していました。現在は、読み取れる行に限定して、テンプレートを通してテーブルをエクスポートします。テンプレート内では、テーブルの行はテーブル ID で名付けられ、各 `-` は `_` と表記されます。
- **Amazon S3と S3互換のドキュメントアカウントがリージョンを保持します。** これらのアカウントを保存すると、入力した**リージョン**が破棄され、次にアカウントを開いたときにフィールドが空白になっていました。現在は、リージョンが保存されます。この修正前に保存したアカウントでは、リージョンを再入力して保存してください。[AWS S3アカウントの追加](/ja/guides/documents/adding-accounts/add-aws-s3-account/)を参照してください。
- **AI アシスタントと JSON-RPC は、ロールから非表示のテーブルを使用するステップを名指ししなくなりました。** そのようなテーブルがどこで使われているかを尋ねると、ロールから表示できる、テーブルを読み書きする各ステップを、その設定とワークフローとともに名指ししていました。現在は、プロジェクトのテーブル参照と同様に、ステップを名指しせずに、ステップがそのテーブルを使用していることだけを伝えます。[ロールで非表示になる内容](/ja/guides/ai-assistant/weave-tab/#ロールで非表示になる内容)を参照してください。
- **選択したデフォルトの AI 接続がデフォルトのままになります。** AI 接続をワークスペースのデフォルトとして設定しても、成功したように見えるだけで保存されておらず、デフォルトに依存するエージェントやステップは、最後に更新された接続を使い続けていました。現在は、選択した内容が保存されます。[LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **Weave の履歴で会話を右クリックしても、「スレッドを削除」の上に「名前の変更」が開かなくなりました。** **名前の変更** はチャットのタブに移りました。タブを右クリックしてください（これまでタブを右クリックしても何も表示されませんでした）。[Weaveタブ内のタブ](/ja/guides/ai-assistant/weave-tab/#weaveタブ内のタブ) を参照してください。
- **1つの値が必要な場所に複数の値を返す式は拒否され、Table ExtractステップまたはTable Union Allステップはターゲットテーブルのデータを保持します。** 主な原因は、`table.amount,`のような末尾のカンマや、`table.region == ('EU', 'US')`のように複数の値と比較する式です。Databendでは、Table ExtractステップまたはTable Union Allステップがターゲットテーブルをすでに空にした後で、ステップが`'tuple' object has no attribute 'replace'`というエラーで失敗していました。ほかの一部のウェアハウスではこのような式が実行されていましたが、記述どおりに動作するとは限りませんでした。そのため、これまでエラーなく動作していたステップが、このメッセージで停止する場合があります。ステップフォームはステップの保存時に式を拒否し、メッセージには変更すべき内容が示されます。[1つの値が必要な場所に複数の値がある場合](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#1つの値が必要な場所に複数の値がある場合)を参照してください。

## セキュリティ

- **Weaveは、各会話の開始時に、お客様の氏名とメールアドレスをAIプロバイダーに送信しなくなりました。** これらが使用されることはありませんでした。
- **パスワードによるサインインには認証アプリが必要になり、パスワードの強度が上がります。** PlaidCloud のパスワードでサインインするメンバーは、次回のサインイン時に認証アプリのセットアップを求められ、それ以降は毎回そのコードを入力します。シングルサインオン、Google、Microsoft、GitHub によるサインイン、API トークン、サービスアカウントは変わりません。新しいパスワードは12文字以上で、ユーザー名や過去6回のパスワードと同じにはできません。サインインの失敗が繰り返されると、アカウントは短時間ロックされます。ワークスペースにすでに設定されていたより厳しいルールは維持されます。[メンバー認証](/ja/administration/access/member-authentication/)を参照してください。
- **接続は、パブリックアドレスとプライベートネットワークのアドレスを指します。** 接続は、ループバック、リンクローカル、クラウドメタデータのアドレスを指すことはできず、エラーにはホストと解決されたアドレスが示されます。プライベートネットワーク上のアドレスは影響を受けません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続が到達できないアドレス)を参照してください。
- **保存された接続の認証情報は、接続またはワークフローを編集できるメンバーにのみ表示されます。** REST API と MCP では、保存された接続のパスワード、トークン、キーは他のメンバーにはマスクされますが、そのメンバーも接続を開いて参照できます。[接続の認証情報を確認できるユーザー](/ja/guides/connections/create-connection/#接続の資格情報を見られるユーザー)を参照してください。
- **アプリのビルドは、ワークスペースの Git 認証情報にアクセスせずに実行されます。**
- **エージェントの秘密鍵は、エージェントを編集できるメンバーにのみ表示されます。** 鍵は、REST API と MCP のエージェント一覧や詳細には表示されなくなり、エージェントフォームは**秘密鍵**と**RPC構成を表示**を、エージェントを編集できるメンバーにのみ表示します。サービスアカウント、プロジェクトトークン、エージェントトークン、AI に委任されたトークンは、鍵や RPC 構成を取得できません。実行中のエージェントは影響を受けず、公開鍵は引き続き表示されます。[エージェント認証情報の取得](/ja/reference/cli/plaidlink/agents/#エージェントの認証情報の取得)を参照してください。
- **プロキシのダウンロードリンクの有効期間は1時間です。** **Use PlaidCloud Proxy Download**をオンにしている場合、リンクの期限が切れたら、ダウンロードをもう一度開いて新しいリンクを取得します。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)を参照してください。
- **セキュリティグループへのユーザー追加は、保有する権限に従います。** グループが付与するすべての権限を自分が保有している場合に、メンバーをセキュリティグループに追加したり、メンバーのグループを選択したり、アーキテクトを招待したりできます。ワークスペース管理者には制限がありません。[セキュリティグループの管理](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)を参照してください。
- **接続の設定の変更とオン・オフの切り替えは、接続のオーナーまたはワークスペース管理者が行います。** REST API、JSON-RPC、AI アシスタントまたは MCP から接続の設定を変更するには、その接続のオーナーの1人、またはオーナーのいない接続ではワークスペース管理者であることが必要です。接続の有効化、無効化、ロック、ロック解除には、オーナーまたはワークスペース管理者が必要で、複数の接続を指定したリクエストは、そのすべてを変更できる場合にのみ適用されます。ワークスペースのデフォルトの AI 接続を選択できるのはワークスペース管理者のみで、メンバーが所有する接続がデフォルトになるのは、管理者が所有する接続やオーナーのいない接続がデフォルトになれない場合に限られます。[接続の編集](/ja/guides/connections/create-connection/#接続を編集する)と [LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **行アクセスは、メンバーが制限付きテーブルに対して行うすべての操作に適用されます。** メンバーは、ダッシュボード、自分の SQL、ロードのいずれでも、自分の権限が許可する行のみを参照および変更できます。
  - **プロジェクトのアーキテクトは、ダッシュボードで行が制限されたテーブルのすべての行を参照できます。** Analyze で参照できる範囲と同じです。アーキテクトのアクセスを取り消すと、ダッシュボードにはただちに反映されます。ロールの変更、メンバーやそのグループのプロジェクトからの削除、プロジェクトのアクセスタイプの変更、以前のプロジェクトバージョンの復元、セキュリティグループの削除のいずれの場合も同様です。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
  - **行アクセスで制限されたメンバーは、自分の SQL クエリを実行し、その結果をエクスポートできます。** 行アクセスが設定されたプロジェクトで、アーキテクトではないメンバーは、クエリ画面での自分のクエリから、権限が許可する行のみを正確に取得し、**アクセス権により行が制限されています**という通知とともに、CSV、Excel、JSON にエクスポートできます。以前は、これらは拒否されていました。パーセント記号（`%`）を含む権限値は、クエリ画面で行を返すようになり、そのようなクエリを CSV としてダウンロードできるようになりました。Snowflake や Databricks での自分の自由形式の SQL、Postgres 系ウェアハウスでの自分の SQL のエクスポート、ガバナンス対象テーブルのスナップショット時点での読み取りは、引き続き拒否されます。また、ビューがフィルターされるには、ガバナンス対象の列を元の名前のまま保持している必要があります。[行アクセスと自分で書くクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスとご自身で記述するクエリ)を参照してください。
  - **行アクセスの保存では、ソースに存在しない付与済みの値が保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がない場合、ディメンションにそのメンバーがない場合、リストにその値がない場合でも、印が付いた状態でグリッドに残ります。**保存**では、そのような値ごとに、保持するか削除するかを確認します。[行アクセスグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
  - **DataFrame の書き込み、レコードの保存とクリアは、行が制限されたテーブルでは、自分に見える行のみを変更します。** 行アクセスで自分の行が制限されている場合、Python クライアントで制限付きテーブルに DataFrame を書き込んだりクリアしたり、REST API でレコードを保存したりクリアしたりすると、自分の行のみが変更されます。アクセス範囲外の行を含むロードは、何も変更される前に拒否され、見つかった値が示されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は、テーブル全体に書き込みます。個人が任意のテーブルに対して行うこれらの書き込みは、すべてセキュリティログに記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
  - **行が制限されたテーブルへのインポート、コピー、復元、削除には、すべての行が自分に見えている必要があります。** 行アクセスで自分の行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えやマージ、復元、削除、削除後の復旧、その他テーブル全体を置き換える操作は、テーブルのすべての行が自分に見えている場合にのみ実行されます。それ以外の場合は拒否され、何も変更されません。REST API でテーブルの行を保存すると、他のロードと同様に、自分の行のみが変更されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は影響を受けず、これらの操作も**セキュリティログ**に記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントのオーナーだけです。** ドキュメントアカウントを以前のバージョンに復元すること、バージョンの保持または解除、バックアップの作成には、アカウントのオーナーの1人が必要で、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、そのアカウントへのアクセスが必要です。
- **`query_run` は読み取り専用のステートメントを実行します。** AI アシスタントと MCP クライアントが使用する `query_run` ツールは、SELECT または WITH ステートメント1つ、その EXPLAIN、または SHOW を受け付け、それ以外のステートメントは実行されません。データを変更するには `query_transform` を使用します。MCP テーブルエクスポートの SQL にも同じルールが適用されます。REST と JSON-RPC API では、プロジェクトのデータを変更できないメンバーに対して、クエリの実行、列ファセットの構築、クエリの CSV としてのダウンロード、リモートデータベースへのクエリのエクスポート、独自のクエリでのテーブルデータのエクスポートにも適用され、拒否されたクエリは403を返します。Explain Analyze は計測のためにクエリを実行するため、クエリログと Lakehouse では読み取りのみのクエリを受け付け、行アクセスのあるプロジェクトでは、クエリログから実行できるのはプロジェクトのアーキテクトだけです。
- **テーブルエクスプローラーのフィルター、PlaidCloudに送信されるクエリ、Table Extractステップが動的列を見つけるためのクエリでは、SQLを実行する関数やサーバーのファイルを読み取る関数を呼び出せなくなりました。** `query_to_xml`、`dblink`、`pg_read_file`などの呼び出しは拒否され、エラーには関数名が示されます。同じ場所で、`.op()`は演算子だけを受け付け、`literal_column`ではUnicodeエスケープを使った引用符を使用できません。動的列のクエリにはステップのフィルターと、ソースから列名を読み取る式が含まれるため、ルールに違反する式があるとステップは実行時に失敗します。[拒否される関数と演算子](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#拒否される関数と演算子)をご覧ください。
- **Data Foundationの配賦ルールでは、一重引用符、バックスラッシュ、改行を含む部門名や統計名は拒否されます。** 名前は配賦ステップのフィルターに書き込まれるため、**保存**とステージ 1のプレビューはその名前を拒否し、値を示します。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)をご覧ください。
