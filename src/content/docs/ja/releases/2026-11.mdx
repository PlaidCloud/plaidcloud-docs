## 追加

- **PlaidXLで、Excel上でのレポート作成、ドリル、数値の説明、計画ができます。** **PlaidCloud** リボンタブは **接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有** にグループ化されています。よく使うコマンドは **PlaidXL** の右クリックメニューと **PlaidXL Cell** タブにもあり、主要なコマンドには変更可能なキーボードショートカットが用意されています（フィールドへの入力中は動作しません）。コマンドが失敗すると、どのコマンドがなぜ失敗したかが表示されます。サインイン前に実行したコマンドはサインインを開き、サインイン後に1回実行されます。サインインは1つのワークスペースに対して有効なため、ワークスペースを切り替えると新しいワークスペースへのサインインが求められます（元に戻す場合は不要です）。OfficeでMicrosoft Entraの職場アカウントを使用している場合は、PlaidXLがワークスペースを自動的に検出します。[PlaidXLリファレンス](/ja/reference/cli/plaidxl/)をご覧ください。
  - **数回のクリックでレポートを作成できます。** **レポート** タブは、テーブルからライブレポートをレイアウトします。行方向に1つのディメンションをドリルダウンし、列方向に別のディメンションを配置し、各交点に `CELL` 値が入ります。**Build my first report** は、お持ちのデータからサンプルを作成します。ドリルすると、レポートは行や列をまるごと挿入・削除し、入力した値、メモ、書式は各行に追従します。[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)をご覧ください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only** は、ノード、ディメンション見出し、レポート値から、ノードをライブの `DRILL` 数式に変換し、その編集も行います。**Custom drill** は挿入前に行をプレビューし、メンバーピッカーはメンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりします。`DRILL` では、除外または展開するノードを指定でき、行方向にも実行できます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)をご覧ください。
  - **数値を説明できます。** **Explain this number** は、値の計算内容、現在のPlaidCloudと一致しているかどうか、およびその元となるテーブルとワークフローのステップを表示します。**Show detail rows** は、値の元になっている行を専用のシートに表示し、合計が一致するかのチェックも行います。
  - **Excelでガバナンス下のメトリックを使用できます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるとおりのビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計では `0` を、それ以外では理由とともに `#VALUE!` を表示します（`CELLS` のスピルでは空白）。また、**Metric...** ボタンでプロジェクトのメトリックを現在値とともに一覧表示します。メトリックでは、複数の代替階層でフィルターしたり、代替階層のメンバーとほかのディメンションのメンバーを組み合わせたりできます。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)をご覧ください。
  - **レポートに直接入力して計画できます。** `CELL` 値の上に数値を入力すると、PlaidCloudに書き込まれます。比例配分、均等配分、別のメンバーの形状に合わせた配分、金額または割合による調整が可能で、固定したセルはそのまま保持されます。平均、中央値、最小、最大、標準偏差、分散のセルにも入力でき、入力した値は行や列の挿入・削除に伴ってセルに追従します（削除されたセルの値は報告されます）。**Undo last write** は、入力した値と保存を新しいものから順に取り消します。書き込みを取り消せるのは、その書き込みを行ったユーザーとワークスペースのみです。合計の取り消し、または空のセルに入力した平均の取り消しでは、同じセルにその後書き込まれた内容が保持されます。完了前に中断された書き込みは取り消せません。[PlaidCloudに値を入力する](/ja/reference/cli/plaidxl/write-values/)をご覧ください。
  - **必要なものだけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新でき、各テーブルの進行状況と **キャンセル** がタスクペインに表示されます。PlaidXLの数式だけを再計算することもできます。取得したテーブルはデータ型ごとに書式設定されたExcelテーブルとして届き、更新しても独自の列や数値書式が保持され、元の場所で更新されます。取得や更新で、ほかのセルが上書きされたり、別のExcelテーブルと重なったりすることはありません。Excelで扱えない大きさの整数IDや1900年より前の日付はテキストとして届きます。同じテーブルを再度取得しても更新リストに重複して追加されず、**Stop refreshing** で1件を外せます。ディメンションはテーブルとともに更新されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)をご覧ください。
  - **保存は即座に書き込まれ、元に戻せます。** **Save to PlaidCloud** は確認なしで書き込み、実行した内容を通知し、**元に戻す** を提供します。**元に戻す** は、Lakehouseテーブルでは各保存から最大7日間利用できます。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーの保存では、対象の行のみが置き換えられるため、ほかのユーザーの行は保持されます。取得後にメンバーが変更されたドリルスルーシートは保存されず、失敗した保存ではリストアポイントが示されるため、テーブルを元に戻せます。[テーブルをPlaidCloudに保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)をご覧ください。
  - **ExcelでWeaveに質問できます。** **Weave** タブで、レポート、数式、ドリル、テーブルを平易な言葉で依頼するか、**Ask Weave about this cell** を選択します。Weaveはあなたとして PlaidCloudを読み取り、変更するのはブックのみです。入力済みの内容を置き換える前に確認し、ブックの外部を参照する数式は書き込まず、各変更はペインを再読み込みするまで元に戻せます。[ExcelでWeaveに質問する](/ja/reference/cli/plaidxl/weave/)をご覧ください。
  - **1つのシートまたはブック全体の値のみのコピーを共有できます。** **Convert to values** は、ブック全体、1つのシート、または元に戻せない値のみへの変換を行い（事前に確認があります）、PlaidXLの数式とそのスピルのみを変更し、まだ計算中の数式は再試行のために残します。シート名を変更した後も、**Restore PlaidXL formulas** は引き続き使用できます。
- **転記レジスターは、対応が必要な項目から開きます。** 確認が必要な項目がある場合は **例外** で、承認待ちの依頼がある場合は **承認** で、それ以外の場合は **すべての転記** で開きます。レールは画面を **自分の対応待ち**、**レジスター**、**インサイト**、**設定** にグループ化し、**例外** と **承認** には件数が表示されます。すべての画面で、ヘッダーとスコープバーを共有します。期間（**This month**、**前月**、**過去7日間**、**過去30日間**、**カスタム**）、接続、プロジェクト、環境またはエンティティ、そして **本番**、**シミュレーション**、**すべて** を選択し、**リセット** するか **Saved scope** を保存できます。最後に使ったスコープは記憶されます。
  - **例外では、確認が必要な項目を整理できます。** **Needs a look**、**未確認**、**保留中**、**失敗**、**Reversal outstanding** のチップに件数が表示され、接続の状態を示す行に「All N connections posting normally」と表示されます。すべての転記には、次に何をすべきかを示すツールチップ付きの分かりやすい状態が表示されます。未処理の項目がなければ **All clear** と表示されます。**Find a posting by ledger id** またはコマンドパレットに元帳IDを貼り付けると、その転記が直接開きます。
  - **承認、委任、ウォッチは受信トレイ形式の画面です。** **Waiting on me** と **Submitted by me** を切り替え、理由を添えて **承認** または **却下** し、複数をまとめて承認し、トーストから承認を **元に戻す** ことができます。**Delegate approvals** は短いダイアログで、**ウォッチ一覧** にはフォロー中の項目が表示されます。**転記を取消** と、一括再試行およびクリアのダイアログは、同じレイアウトを共有します。
  - **転記のドロワーには何が起きたかが表示されます。** 状態とその意味、主要な情報が名前付きで表示され、**Lines**、**履歴**、**承認** タブがあります。操作として **レビュー済みにする**、**再試行**、**取消…**、**接続をウォッチ**、**実行をウォッチ**、**Copy link** があり、**Copy link** はその転記を直接開きます。
  - **アシスト、エクスポート、保持期間も同じデザインに従います。** **アシスト** には質問ボックスとインサイトカードがあり、アドバイスには **Draft — nothing applied** と表示され、**すべての転記** には **これらを表示** 付きの異常カードがあります。**エクスポートとアラート** には **New schedule** があり、**保持期間** は1枚のカードになっています。
  - **レジスターは常に最新です。** 転記が変わるとレールのバッジが更新され、転記が変更されたときは未決の一覧に **更新** が表示され、開いているドロワーはその場で更新されます。**ホーム** には、**要対応** の下に **転記レジスター** カードが表示されます。[転記レジスターを確認する](/ja/guides/connections/posting-register/)をご覧ください。
- **ステップフォームでプレビューできます。** Import: SQL、Execute: SQL、Extract: SQL、Export: SQL、Salesforce Queryでは、ステップを実行せずに最大100行を表示できます。また、Anaplanのビューとリストの読み取りでは、生成される列と型が表示されます。**ソース** タブで **プレビュー** をクリックします。変数は実行時と同じように埋め込まれますが、`{x:>9}` のような変数の書式指定はサポートされていません。プレビューで実行されるのは標準のSQL関数のみで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトや、エージェントベースのExecute SQLステップでは利用できません。[SQLのインポート ステップ](/ja/reference/workflow-steps/import/import-sql/)と[SQL抽出 ステップ](/ja/reference/workflow-steps/tables/table-extract-sql/)をご覧ください。
- **使用状況レポートで変化を確認し、グループで絞り込み、ワークフローに連携できます。** **概要** には、前の期間と比較したトレンド矢印と、非アクティブなメンバーや、誰も開いていないダッシュボードとアプリを示す **Highlights** リストが追加されました。無効化されたメンバーは、非アクティブとしてカウントも一覧表示もされません。**グループ** は、**概要**、**内容**、非アクティブ一覧を1つのセキュリティグループのメンバーに限定します。日付範囲には **Previous month** と **This month** が追加され、すべてのタブで共有され、アカウントに記憶されます。すべての数値に説明が付き、テーブルでは **メンバー** や **Area** のような分かりやすい名前を使用し、行は Enter で開き、読み込みとエラーの表示が分かりやすくなり、**ファネル** の最後のステップには完了したメンバー数が表示されます。新しい **Get Workspace Usage** ステップは、メンバー名を含めずに、日次または月次の使用状況の合計をスケジュールに従ってテーブルに書き込みます。**Get Workspace Members** と同様に、実行のたびにセキュリティログに記録されます。[使用状況レポート](/ja/administration/access/usage-reports/)と[Get Workspace Usage ステップ](/ja/reference/workflow-steps/general/get-workspace-usage/)をご覧ください。
- **AIアシスタントで、テーブルの公開を取り消し、プロジェクトのダッシュボードの既定の対象ユーザーを設定できます。** `publish_manage` は、テーブルの公開を取り消し、あわせて公開済みビューと、どのチャートでも使われていないダッシュボードデータセットも取り消します。チャートがまだ使用しているデータセットは残り、公開済みビューをもとにレポートビューが作成されている場合はビューとデータセットも残りますが、テーブルの公開は取り消されます。`project_upsert` は `dashboard_default_audience`（プロジェクト内の新しいダッシュボードの共有先グループ）を設定し、`[]` でクリアします。[公開の取り消し](/ja/guides/data/publish/#ai-アシスタントまたは-mcp-で公開を取り消す)と[AIアシスタントまたはMCPで既定の対象ユーザーを設定する](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ai-アシスタントまたは-mcp-でデフォルトの対象ユーザーを設定する)をご覧ください。

- **Gitアプリには、リポジトリの一覧と、できることが表示されます。** アプリ一覧の **Git** には、あなたのロール（**Administrator**、**Contributor**、**閲覧者**）と、ワークスペースのリポジトリが表示されます。各リポジトリには、説明、最終更新日、コピーボタン付きのクローンアドレス、**開く** があります。**Set up Git on your computer** カードでは、Gitのインストール、トークンの作成、クローンの手順を案内し、**How to clone** でもう一度開けます。**View all in Git** でGitの完全なインターフェースが開き、**Manage who can push** でグループ管理が開きます。アクセスレベルは **閲覧者**、**Contributor**（アプリコードを `apps` にプッシュ）、**Administrator**（`udfs` を含むすべてにプッシュ）で、閲覧者には問い合わせ先として最大3人のワークスペース管理者が表示されます。新しい **Git Contributors** グループはContributorの権限を付与し、デフォルトグループにできるため、新しいメンバーには自動的に付与されます。**Git Administration** はAdminの権限を付与します。メンバーの **Git** タブには、Gitのユーザー名、レベル、それを付与しているグループが表示されます。メンバーのGitアカウントはメンバーシップに連動します。メンバーを無効化または削除すると、約1時間以内にトークンとSSHキーを含むGitアカウントがブロックされ、再有効化するとブロックが解除され、リポジトリと履歴は保持されます。シングルサインオンでGitにサインインすると、そのメンバー自身のアカウントが開きます。Contributorは、ワークスペースのGit組織にリポジトリを直接作成することはできず、リポジトリはPlaidCloud経由で作成されます。アプリのウィンドウには **リポジトリ** セクションが表示され、UDFには **開く** があり、Gitには自分のワークスペースへの **← Back to** リンクがあります。アプリのリポジトリ、組み込みの `apps` と `udfs` リポジトリなど、プラットフォームが作成するすべてのリポジトリは、ワークスペースにサインインしているすべてのメンバーが読み取れるため、メンバーはリポジトリごとの設定なしでアプリを開いて再公開できます。Git管理者は、引き続きリポジトリを非公開にできます。非公開にすると、リポジトリピッカーに表示されなくなり、メンバーはそのリポジトリから公開したり、そこに保存されたGitベースのUDFコードを実行したりできなくなります。[PlaidCloud Git](/ja/guides/git/#gitを開く)と[リポジトリを閲覧できるユーザー](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)をご覧ください。
- **Cost to ServeおよびOperational Transfer Pricingテンプレートは、Common Finance Modelをベースにしています。** **Cost to Serve** からプロジェクトを開始すると、各部門に設定したアクティビティとドライバーに基づいて営業費用を顧客に配分し、各顧客に対応するコストを差し引いた後のマージンを、元帳と突き合わせて確認できます。**Operational Transfer Pricing** から開始すると、各エンティティの利益水準（売上高利益率、ネットコストプラス、または再販売価格マイナス）をポリシーの範囲に対してテストし、範囲外のエンティティを目標に戻す調整額（トゥルーアップ）を確認できます。売上高利益率は、EBITをテスト対象当事者の売上高で割った値です。[Cost to Serve](/ja/guides/projects/cost-to-serve/)と[Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/)をご覧ください。
- **OneStreamとAnaplanがData Foundationにデータを供給し、OneStreamには読み取りステップがあります。** Data Foundationは、OneStreamの管理者が構築するデータアダプター経由でOneStreamの連結結果を、またエクスポートアクション経由でAnaplanのプランを読み取り、グループの損益計算書をそれらと照合します。新しい **OneStream: Read Adapter** ステップは、連結メンバーごとに1回の呼び出しでアダプターを読み取り、任意のワークフロー内のテーブルに格納します。[Data Foundation向けOneStream](/ja/guides/connections/onestream-for-data-foundation/)、[Data FoundationソースとしてのAnaplan](/ja/guides/connections/anaplan/#data-foundation-のソースとしての-anaplan)、[OneStream: Read Adapter ステップ](/ja/reference/workflow-steps/onestream/onestream-read-adapter/)をご覧ください。
- **Data Foundationで共有コストの配賦方法を選択できます。** **アクション > Allocations...** では、どのコストを配賦するか、何を基準にするか、どこに配賦するか、ドライバーが負の値の場合にどうするかを、間接費の部門への配賦と、部門から製品・顧客への配賦の両方について順に設定できます。1か月分のプレビューで、プールされた額、配賦された額、未配賦の額を確認できます。手作業で編集したルールは保持されます。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)をご覧ください。
- **Data Foundationで数値を説明し、独自の名前を付けられます。** **Explain this number** は、損益計算書の数値を、元帳に保持されている額、配賦で出入りした額、グループで消去された額に分け、最大の元伝票も示します。これはご自身の行アクセスの範囲で行われます。**Business names** は、カテゴリ、損益計算書の行、メトリック、列に、レポート、メトリック、アシスタントで使われる、ビジネスで使用している名前を付けます。[数値を説明する](/ja/guides/projects/data-foundation/#数値を説明する)と[Business Names](/ja/guides/projects/data-foundation/#ビジネス名)をご覧ください。
- **Data Foundationは、ロードのたびにボードパックを作成し、元に戻せます。** **ロード** のたびに、損益計算書ダッシュボードのExcelブックとPDFが、ドキュメントアカウントのフォルダーに書き込まれます。レポートがオフの場合、パックはブックのみとなり、ダイアログにもその旨が表示されます。ロードの開始時と、マッピングやソースを変更する前にリストアポイントが作成され、**アクション > Restore...** は、それぞれが元に戻すテーブル数を表示し、ディメンションを含むプロジェクトを元に戻します。**Foundation** タブは、現在の状況がより分かりやすくなりました。実行中または途中で停止した更新を表示し、テーブルのフォルダーがソースにならない理由を示し、何かが一致するまで **合計が一致することを確認** を保留のままにし、ステータスの読み取りが失敗しても復旧します。更新を適用しても、生成されたステップとメモに対するご自身の編集は保持され、競合があれば通知されます。[ボードパック](/ja/guides/projects/data-foundation/#ボードパック)と[リストアポイント](/ja/guides/projects/data-foundation/#復元ポイント)をご覧ください。

## 変更

- **PlaidCloudのWebアプリとPythonクライアントライブラリはREST APIを使用し、JSON-RPCは非推奨になりました。** Webアプリは、リクエストをREST APIに送信します。`plaidcloud-rpc` 1.25.0以降では、`SimpleRPC` の呼び出しはコードを変更せずにREST APIに送られます。REST APIがまだ対応していない呼び出しや、古いリリースのままのワークスペースでは、これまでどおりJSON-RPCが使われます。JSON-RPCは今後のリリースで削除されるため、スクリプトとノートブックを `plaidcloud-rpc` 1.25.0以降にアップグレードし、新しい連携はREST APIに対して作成してください。[コマンドライン](/ja/reference/cli/jupyter/command-line/)をご覧ください。
- **ステップフォームは統一されたレイアウトに従います。** タブは、General、Settings、Source、Columns、Filters、Output、Advancedという標準の名前と順序になり、ERP転記フォームには Header columns と Line columns があります。必須フィールドには * が付き、フォームが保存をブロックするのは、ステップに必要な項目のみです。
- **プロジェクトのコピーでは、テーブルデータとディメンションメンバーを別々に選択でき、データのコピーが高速化し、非公開コピーのERP書き込み承認も保持されます。** **Data to copy** で **テーブルデータ**（**No table data**（デフォルト）、**完全**、**サンプル**）を選択し、それとは別に **Copy dimension members**（デフォルトでオン）を選択します。そのため、テーブルの行を含まないコピーでもディメンションにはデータが入った状態で届き、短時間で作成できます。**完全** と **サンプル** のコピーは複数のテーブルを同時にコピーするため、テーブル数の多いプロジェクトでも短時間で完了します。**コピー結果** には、テーブルと並んで各ディメンションの結果が一覧表示され、**Retry failed items** は、失敗したテーブルとディメンションをまとめて再試行します。データ付きで作成した新しいコピーは自分だけの非公開になり、自分で付与できるコピー元のERP書き込み承認を引き継ぎます。コピー元が本番で転記している場合、コピーはシミュレーションで届くため、本番に切り替えるまでERPには何も届きません。REST APIと `project_copy` MCPツールも `dimension_members` を受け付けます。[コピーするデータ量を選択する](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーに含まれるERP書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認)をご覧ください。
- **テーブルの詳細パネルで、そのテーブルを使用するステップがより早く表示されます。** 別のテーブルを選択すると、前のテーブルのステップは直ちにクリアされ、このプロジェクトのデータを共有する別のプロジェクトのステップは、パネル全体を待たせることなく少し後に追加されます。[テーブルの使用箇所を確認する](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)をご覧ください。
- **行アクションは、すべての一覧で同じように動作します。** 行のメニューは、行の先頭にある **⋯** ボタン、行の右クリック、またはツールバーの **アクション** メニューから開けます。常に **開く**、**詳細**、**編集** が先頭に並び、続いてその一覧に固有のアクション、最後に **削除** が表示されます。行に適用できないアクションは、その位置のままグレーアウトされます。**Enter** と **Del** は、それぞれが実行する項目に表示されます。行のアクションが1つだけの一覧では、**⋯** の代わりにそのアクションのアイコンが表示され、**マイダッシュボード**、**マイPanelアプリ**、JupyterLiteには、再び **開く** アイコンが表示されます。[行アクションメニュー](/ja/guides/dashboards/using-dashboards/#行アクションメニュー)をご覧ください。
- **アプリのタブアイコンが、ライトとダークの両方で統一されたセットになりました。**
- **検証設定のない保存済みのERP書き込みステップは、検証のみで開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS GLとAP Post、Xeroのエクスポートです。本番で実行するよう明示的に設定されたステップは、そのまま本番で実行されます。
- **長時間実行されるジョブの進行状況が、どこでも同じ方法で表示されます。**
- **ワークフローは、正確に停止、失敗、報告します。** ワークフローを停止すると開始したすべてが停止し、完了できない実行やステップは停止したままにならず理由付きで失敗し、実行ステータスは実際に実行された内容と一致します。
  - **ワークフローを停止すると、開始したすべてが停止し、完了できない実行やステップは停止したままにならず失敗します。** 停止すると、キューに残っていたインポートとディメンションのステップがキャンセルされるため、ワークスペース内の後続のインポートとディメンションのロードは通常どおり開始されます。また、そのワークフローのキュー中または実行中のコネクター（Singer）同期も停止します。ステップのジョブを開始できない場合、ステップはいつまでも待たずに理由付きで失敗します。ワーカーが約40分以内に開始しない場合、ワーカーが開始した後に消えた場合、Podが約20分間Pendingのままの場合、イメージを約5分間取得できない場合、Podが約20分間作成されない場合が該当します。どのランナーにも約30分以内に取得されないコネクター同期は、その同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間、そのステータスメッセージには経過した分数とともに「Waiting for a worker…」と表示され、作業が始まると消えます。マクロを停止すると、実行中のすべてのコピーが停止します。一方、1つのコピーを停止した場合や、応答しなくなったコピーを **Macro Concurrent** ステップが見切った場合は、それを呼び出したワークフローは実行されたままです。ほかのワークフロー内でのみ実行されているマクロは、ワークフロー一覧で **実行中** と表示され、**停止** を利用でき、各ステップのステータスと開始・終了時刻は直近の実行のものが表示されます。サーバーが失われた実行は失敗として終了し、12時間経過しても実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」で失敗します。[ワークフローを実行する](/ja/guides/workflows/run-a-workflow/#開始されないステップ)をご覧ください。
  - **再開、実行履歴、実行ステータスは、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローのステップを単独で再実行した後でも、子ワークフローに残っていたすべてが実行され、1回の実行内での子ワークフローの各呼び出しは、それぞれ実行履歴のエントリーを持ちます。サーバーが停止したために再開されたステップは、そのログにその旨が記録され、`workflow_run_status` とREST APIの実行結果は、実行を問題なしと報告する代わりに、失敗したが続行したステップを `continued_step_ids` と `continued_step_count` に一覧表示します。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に続行](/ja/guides/workflows/continue-on-error/)をご覧ください。
  - **ステップのエラーには、そのエラー自体のメッセージが表示されます。** PlaidCloudが想定していなかったエラーは「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの **要対応** カードには、エラーが1行で表示され、その後削除されたワークフローの実行は含まれません。[ステップエラーを管理する](/ja/guides/workflows/managing-step-errors/)をご覧ください。
  - **完了しないERP抽出は、そのステップを失敗させ、再開すれば続行されます。** **SAP: アドホック抽出** が行数または時間の上限で一時停止したとき、またはエージェントが時間内に応答しないとき、あるいはSalesforce、Oracle Fusionの一括、HFM/FCCSのエクスポートジョブが、ステップが待機を終えた時点でまだ実行中のとき、ステップは失敗し、後続のステップが部分的なテーブルに対して実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は停止した位置から同じジョブで続行されます。[実行制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と[Salesforce: オブジェクトのクエリ ステップ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)をご覧ください。
  - **エクスポートをキャンセルすると、ウェアハウス内のクエリも停止します。** エクスポートまたはダウンロードがキャンセルされると（そのワークフローの停止による場合も含みます）、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplumでは、そのデータを読み取っているクエリも停止し、リモートデータベースへのエクスポートはソースの読み取りを停止します。以前は最後まで実行され続けていました。
- **REST、Import REST、Import Postmanステップは、ワークスペースのアップグレード時にRESTリクエストステップに変換されます。** きれいに変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)をご覧ください。
- **セッションの期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードを表示します。** [ダッシュボードの使い方](/ja/guides/dashboards/using-dashboards/)をご覧ください。

## 修正

- **無効なプロジェクト設定が、分かりやすいメッセージで報告されます。** 不明な環境やドキュメントアカウント、すでに使用されているか予約されているスラッグ、無効なストレージタイプや転記モードは、汎用的なサーバーエラーではなく、問題を示すメッセージを返すようになりました。REST APIでは500ではなく400、AIアシスタントまたはMCPでは引数が無効であることを示すエラーになります。
- **REST APIのディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして扱われ、無効として拒否されていました。現在は、`value_columns` の各列について集計値を1つ返します。また、グリッド（行フィルターと列フィルターの各組み合わせにつき1つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` が用意されています。
- **テーブルの読み取りやファイル処理が遅くても、ほかのリクエストが待たされなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundationファイルの登録、Excelへのエクスポート、RESTまたはSOAPインポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panelアプリのコードやロゴのチェックは、それぞれが完了するまで、同じサーバーが処理しているほかのすべてのリクエストを停止させる場合がありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 小さな画面や低い解像度では、追加と編集のダイアログがウィンドウより高くなり、**作成** と **更新** ボタンに手が届かないことがありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storageのドキュメントアカウントで、256 MiBを超えるファイルをコピー、移動、名前変更できます。** これらの操作はいずれも、そのサイズのファイルで失敗し、それを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2では、テーブルの行数に、書き込んだ直後の内容が反映されます。** テーブルを書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが0行と表示されたり、インポートが0行をインポートしたと報告されたりしていました。行数は、新しい行がすべての場所で参照できるようになってから読み取られるため、後続のステップもそれらを読み取れます。テーブルを別のブランチに切り替えたり、ブランチをマージしたりした場合も、行数と列数が更新されます。
- **Weaveの空の値のチェックは、各実行を、以前の実行が実際に残した内容と比較します。** ステップの空の値は、ステップがテーブルを補充するために空にした直後にカウントされることが多く、以前の実行には空の値がないように見え、常に一部が空だった列が、たった今そうなったかのように報告されていました。現在は、ステップがテーブルに残した状態で各実行がカウントされます。以前に記録されたカウントは、正しいものと区別できないため使用されません。各ステップの空の値のチェックは履歴を最初からやり直し、5回の実行がカウントされるまでは未チェックとして報告されます。また、行数と値の分布のチェックでは、ステップの完了から2秒を超えて別のステップが同じテーブルに書き込んだ分を、そのステップの書き込みとして扱わなくなりました。[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)をご覧ください。
- **Data Foundationは、反転した為替レートと小数のしきい値の精度を保持します。** レートがレポート通貨から別の通貨への相場で表示されているためにPlaidCloudが反転したレートは、小数点以下6桁に丸められる場合があり、インドネシアルピアのようにレートの小さい通貨の金額が約1%ずれていました。反転したレートは、小数点以下12桁が保持されます。`0.5` のように小数を含む `group_amber` または `group_red` のしきい値は、整数に丸められていました。次回の **ロード** から、正確な値が使われます。[為替レート](/ja/guides/projects/data-foundation/#為替レート)をご覧ください。
- **無効化されたメンバーのアラートとダイジェストが停止します。** オーナーが無効化されたPanelアプリのアラートやダイジェストが、チェックと送信を続けていました。現在は、無効化されている間は一時停止し、再有効化されると再開します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)をご覧ください。
- **削除された接続をREST APIに問い合わせると404が返ります。** 削除された接続や存在しないIDをリクエストすると、汎用的なサーバーエラー（500）が返っていました。現在は、接続IDを示すメッセージとともに404が返ります。

## セキュリティ

- **パスワードでのサインインには認証アプリが必要になり、パスワードが強化されました。** PlaidCloudのパスワードでサインインするメンバーは、次回のサインイン時に認証アプリの設定を求められ、以降は毎回そのコードを入力します。シングルサインオン、Google、Microsoft、GitHubでのサインイン、APIトークン、サービスアカウントは変更ありません。新しいパスワードは12文字以上で、ユーザー名や直近6回のパスワードと同じにはできません。サインインの失敗が繰り返されると、アカウントは短時間ロックされます。ワークスペースにすでにあったより厳格なルールは維持されます。[メンバー認証](/ja/administration/access/member-authentication/)をご覧ください。
- **接続は、パブリックアドレスとプライベートネットワークのアドレスを指します。** 接続は、ループバック、リンクローカル、クラウドメタデータのアドレスを指すことはできず、エラーにはホストと解決されたアドレスが示されます。プライベートネットワーク上のアドレスには影響しません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続が到達できないアドレス)をご覧ください。
- **保存された接続の認証情報は、接続またはワークフローを編集できるメンバーにのみ表示されます。** REST APIとMCPでは、保存された接続のパスワード、トークン、キーは、ほかのメンバーに対してはマスクされますが、そのメンバーも引き続き接続を開いて参照できます。[接続の認証情報を確認できるユーザー](/ja/guides/connections/create-connection/#接続の資格情報を見られるユーザー)をご覧ください。
- **アプリのビルドは、ワークスペースのGit認証情報にアクセスせずに実行されます。**
- **エージェントの秘密鍵は、エージェントを編集できるメンバーにのみ表示されます。** 鍵は、REST APIとMCPのエージェント一覧や詳細に表示されなくなり、エージェントフォームは、**秘密鍵** と **RPC構成を表示** をエージェントを編集できるメンバーにのみ表示します。サービスアカウント、プロジェクトトークン、エージェントトークン、AI委任トークンでは、鍵やRPC構成を取得できません。実行中のエージェントには影響がなく、公開鍵は引き続き表示されます。[エージェントの認証情報を取得する](/ja/reference/cli/plaidlink/agents/#エージェントの認証情報の取得)をご覧ください。
- **プロキシダウンロードリンクは1時間有効です。** **Use PlaidCloud Proxy Download** がオンの場合、リンクの有効期限が切れたときは、ダウンロードをもう一度開いて新しいリンクを取得してください。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)をご覧ください。
- **セキュリティグループへのユーザーの追加は、保持している権限に従います。** メンバーをセキュリティグループに追加したり、メンバーのグループを選択したり、アーキテクトを招待したりできるのは、そのグループが付与するすべての権限を保持している場合です。ワークスペース管理者には制限がありません。[セキュリティグループを管理する](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)をご覧ください。
- **接続の設定の変更と有効・無効の切り替えは、接続のオーナーまたはワークスペース管理者が行います。** REST API、JSON-RPC、AIアシスタントまたはMCP経由で接続の設定を変更するには、オーナーのいずれか、オーナーのいない接続ではワークスペース管理者である必要があります。接続の有効化、無効化、ロック、ロック解除には、オーナーまたはワークスペース管理者が必要で、複数の接続を指定したリクエストは、そのすべてを変更できる場合にのみ適用されます。ワークスペースのデフォルトのAI接続を選択できるのはワークスペース管理者のみで、メンバーがオーナーの接続がデフォルトになるのは、管理者がオーナーの接続、またはオーナーのいない接続がデフォルトになり得ない場合に限られます。[接続を編集する](/ja/guides/connections/create-connection/#接続を編集する)と[LLMプロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)をご覧ください。
- **行アクセスは、メンバーが制限付きテーブルに対して行うすべての操作に適用されます。** メンバーは、ダッシュボード、自身のSQL、ロードのいずれでも、付与された範囲の行のみを表示・変更できます。
  - **プロジェクトのアーキテクトは、ダッシュボードで、行が制限されたテーブルのすべての行を表示できます。** これはAnalyzeでの表示と同じです。アーキテクトのアクセス権を取り消すと、ダッシュボードでも直ちに反映されます。これは、ユーザーのロールを変更した場合、ユーザーまたはそのグループをプロジェクトから削除した場合、プロジェクトのアクセスタイプを変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれでも同様です。[行アクセスを管理する](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)をご覧ください。
  - **行アクセスで制限されたメンバーも、自身のSQLクエリを実行し、結果をエクスポートできます。** 行アクセスのあるプロジェクトでは、アーキテクトではないメンバーは、クエリ画面での自身のクエリから、付与された範囲の行のみを正確に取得し、**アクセス権により行が制限されています** という通知とともに、CSV、Excel、JSONにエクスポートできます。以前は、これらは拒否されていました。パーセント記号（`%`）を含む付与値は、クエリ画面で行を返すようになり、そのようなクエリをCSVとしてダウンロードすることもできます。SnowflakeまたはDatabricksでの自由形式のSQL、Postgres系ウェアハウスでの自身のSQLのエクスポート、スナップショット時点でのガバナンス対象テーブルの読み取りは、引き続き拒否されます。また、ビューがフィルターされるには、ガバナンス対象の列を元の名前のまま保持する必要があります。[行アクセスと自分で書くクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスとご自身で記述するクエリ)をご覧ください。
  - **行アクセスを保存しても、ソースにない付与値は保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がない場合、ディメンションにそのメンバーがない場合、またはリストにその値がない場合でも、マークが付いたままグリッドに残ります。**保存** は、そのような各値を保持するか削除するかを確認します。[行アクセスグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)をご覧ください。
  - **行が制限されたテーブルへのDataFrameの書き込み、レコードの保存、クリアは、表示できる行のみを変更します。** 行アクセスで行が制限されている場合、Pythonクライアントで制限付きテーブルにDataFrameを書き込んだりクリアしたりしたとき、またはREST API経由でレコードを保存したりクリアしたりしたときは、自分の行のみが変更されます。アクセス範囲外の行を含むロードは、何かが変更される前に、見つかった値を示して拒否されます。プロジェクトのアーキテクト、すべての行を表示できるメンバー、ワークフローの実行は、テーブル全体に書き込みます。個人が行うこれらの書き込みは、どのテーブルに対するものでも、セキュリティログに記録されます。[制限付きテーブルにデータをロードする](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)をご覧ください。
  - **行が制限されたテーブルへのインポート、コピー、復元、削除は、すべての行を表示できる場合にのみ実行できます。** 行アクセスで行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えまたはマージ、復元、削除、削除後の復旧など、テーブル全体を置き換えるあらゆる操作は、テーブルのすべての行を表示できる場合にのみ実行され、それ以外は拒否され、何も変更されません。REST API経由でテーブルの行を保存すると、ほかのロードと同様に、自分の行のみが変更されます。プロジェクトのアーキテクト、すべての行を表示できるメンバー、ワークフローの実行には影響がなく、これらの操作もセキュリティログに記録されます。[制限付きテーブルにデータをロードする](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)をご覧ください。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントのオーナーのみです。** ドキュメントアカウントを以前のバージョンに復元すること、バージョンを保持または解放すること、バックアップを取ることには、アカウントのオーナーのいずれかが必要で、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、そのアカウントへのアクセス権が必要です。
- **`query_run` は読み取り専用のステートメントを実行します。** AIアシスタントとMCPクライアントが使用する `query_run` ツールは、1つのSELECTまたはWITHステートメント、そのEXPLAIN、またはSHOWを受け付け、それ以外のステートメントは実行されません。データを変更するには、`query_transform` を使用してください。MCPのテーブルエクスポートのSQLにも、同じルールが適用されます。REST APIとJSON-RPC APIでは、プロジェクトデータを変更できないメンバーに対して、クエリの実行、列ファセットの作成、クエリのCSVとしてのダウンロード、リモートデータベースへのクエリのエクスポート、独自のクエリによるテーブルデータのエクスポートにも適用され、拒否されたクエリは403を返します。Explain Analyzeはクエリを実行して計測するため、クエリログとLakehouseでは読み取りを行うクエリのみを受け付け、行アクセスのあるプロジェクトでは、クエリログからこれを実行できるのはプロジェクトのアーキテクトのみです。
