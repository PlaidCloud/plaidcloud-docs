## 追加

- **PlaidXL で Excel からレポートの作成、ドリル、数値の説明、計画ができます。** **PlaidCloud** リボンタブは **接続**、**挿入**、**更新**、**ドリル**、**書き込み**、**共有**にグループ化され、よく使うコマンドは **PlaidXL** の右クリックメニューと **PlaidXL セル**タブにもあり、主なコマンドには変更可能なキーボードショートカットがあります。サインイン前に実行したコマンドはサインインを開き、サインイン後に一度だけ実行されます。Office で Microsoft Entra の職場アカウントを使用している場合、PlaidXL がワークスペースを自動的に見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成します。** **レポート**タブは、テーブルからライブレポートをレイアウトします。あるディメンションを行方向に、別のディメンションを列方向にドリルダウンし、交点ごとに `CELL` 値を配置します。**最初のレポートを作成**は、お客様自身のデータからサンプルを作成します。ドリルすると、レポートは行全体と列全体を挿入・削除し、入力済みの値、メモ、書式は行とともに保持されます。[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます。** **ドリルダウン**、**ドリルアップ**、**これのみ保持**、**これのみ削除**は、ノードをライブの `DRILL` 数式に変換して編集します。ノード、ディメンション見出し、レポートの値のいずれからでも使えます。**カスタムドリル**は挿入前に行をプレビューし、メンバーピッカーはメンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりします。`DRILL` は除外または展開するノードを受け取り、行をまたいで実行できます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明します。** **この数値を説明**は、値が何を計算しているか、現在の PlaidCloud と一致しているか、元になっているテーブルとワークフローステップを表示します。**詳細行を表示**は、値の根拠となる行を専用のシートに表示し、合計が合うかどうかのチェックも行います。
  - **Excel でガバナンスされたメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるのと同じビジネスメトリックを返し、**メトリック...** はプロジェクトのメトリックを現在の値とともに一覧表示します。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに入力して計画します。** `CELL` 値に数値を上書き入力すると PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの形状に合わせた配分、金額または割合による調整が可能で、保留したセルはそのまま残ります。平均、中央値、最小値、最大値、標準偏差、分散のセルにも入力できます。**最後の書き込みを元に戻す**は、入力した値と保存を新しい順に取り消します。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要なものだけを更新します。** シート、選択範囲、またはすべてのテーブルを更新でき、各テーブルの進行状況と**キャンセル**がタスクペインに表示されます。PlaidXL の数式だけを再計算することもできます。取得したテーブルはデータ型ごとに書式設定された Excel テーブルとして届き、更新時にお客様自身の列と表示形式が保持され、その場で更新されます。テーブルを再取得しても更新リストに二重に追加されず、**更新を停止**で 1 つをリストから外せます。ディメンションはテーブルとともに更新されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存は即座に書き込まれ、元に戻せます。** **PlaidCloud に保存**は確認なしで書き込み、何を行ったかを通知し、**元に戻す**を提示します。フィルター付きで取得したシート、詳細行のシート、または一部の行にのみアクセスできるユーザーの場合は、それらの行だけが置き換えられるため、他のユーザーの行は保持されます。[テーブルを PlaidCloud に保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave** タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼するか、**このセルについて Weave に質問**を選択します。Weave はお客様として PlaidCloud を読み取り、ブックのみを変更します。入力済みの内容を置き換える前に確認し、各変更はペインを再読み込みするまで元に戻せます。[Excel で Weave に質問する](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1 枚のシートまたはブック全体の値のみのコピーを共有できます。** **値に変換**はブック全体、1 枚のシート、または元に戻せない値に変換し、**PlaidXL 数式を復元**はシート名を変更した後でも引き続き使えます。
- **ステップフォームでのプレビュー。** インポート: SQL、Execute: SQL、SQL抽出、エクスポート: SQL、Salesforce クエリは、ステップを実行せずに最大 100 行を表示し、Anaplan のビューとリストの読み取りは、生成される列と型を表示します。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように埋め込まれますが、`{x:>9}` のような変数の書式指定はサポートされません。プレビューは標準 SQL 関数のみを実行し、それ以外の場合はステップを実行するよう案内します。ロックされたプロジェクトや、エージェントベースの Execute SQL ステップでは利用できません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と [SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)を参照してください。
- **利用状況レポートで変化を確認し、グループで絞り込み、ワークフローに取り込めます。** **概要**には、前期間と比較したトレンド矢印と、非アクティブなメンバーや誰にも開かれていないダッシュボードやアプリを示す**ハイライト**一覧が加わりました。**グループ**は、**概要**、**内容**、非アクティブ一覧を 1 つのセキュリティグループのメンバーに限定します。日付範囲には**先月**と**今月**が加わり、すべてのタブで共有され、アカウントに記憶されます。すべての数値に説明が付き、テーブルには**メンバー**や**エリア**などの分かりやすい名前が使われ、行は Enter キーで開き、読み込みとエラーの表示が明確になり、最後の**ファネル**ステップには完了したメンバー数が表示されます。新しい**ワークスペース利用状況の取得**ステップは、日次または月次の利用状況合計を、メンバー名を含めずにスケジュールに従ってテーブルに書き込み、**ワークスペースメンバーの取得**と同様に、各実行が**セキュリティログ**に記録されます。[利用状況レポート](/ja/administration/access/usage-reports/)と[ワークスペース利用状況の取得](/ja/reference/workflow-steps/general/get-workspace-usage/)を参照してください。
- **AI アシスタントはテーブルの公開を解除し、プロジェクトのデフォルトのダッシュボード対象者を設定できます。** `publish_manage` は、テーブルの公開を、その公開ビューと、どのチャートでも使われていないダッシュボードデータセットとともに解除します。チャートがまだ使用しているデータセットは残り、公開ビューの上にレポートビューが構築されている場合はそのビューとデータセットも残りますが、テーブルの公開は解除されます。`project_upsert` は `dashboard_default_audience`、つまりプロジェクトの新しいダッシュボードを共有するグループを設定し、`[]` でクリアします。[公開解除](/ja/guides/data/publish/#ai-アシスタントまたは-mcp-で公開を取り消す)と[AI アシスタントまたは MCP でデフォルトの対象者を設定する](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ai-アシスタントまたは-mcp-でデフォルトの対象ユーザーを設定する)を参照してください。

- **Git アプリがリポジトリを一覧表示し、できることを案内します。** アプリ一覧の **Git** には、お客様のロール（**管理者**、**コントリビューター**、**閲覧者**）と、ワークスペースのリポジトリが表示されます。各リポジトリには説明、最終更新日、コピーボタン付きのクローンアドレス、**開く**があります。**コンピューターで Git を設定する**カードは、Git のインストール、トークンの作成、クローンの手順を案内し、**クローンの方法**で再度開けます。**Git ですべて表示**は完全な Git インターフェースを開き、**プッシュできるユーザーを管理**はグループ管理を開きます。アクセスレベルは**閲覧者**、**コントリビューター**（アプリコードを `apps` にプッシュ）、**管理者**（`udfs` を含むすべてにプッシュ）で、閲覧者には問い合わせ先として最大 3 人のワークスペース管理者が表示されます。新しい **Git Contributors** グループはコントリビューターの権限を付与し、デフォルトグループにできるため、新しいメンバーは自動的に付与されます。**Git Administration** は管理者の権限を付与します。メンバーの **Git** タブには、Git のユーザー名、レベル、それを付与しているグループが表示されます。アプリウィンドウには**リポジトリ**セクションが表示され、UDF には**開く**があり、Git にはワークスペースへ戻る **← 戻る**リンクがあります。アプリのリポジトリや組み込みの `apps` および `udfs` リポジトリを含め、プラットフォームが作成するすべてのリポジトリは、ワークスペースのサインイン済みのすべてのメンバーが読み取れ、サインインしていないユーザーは読み取れないため、メンバーはリポジトリごとの設定なしでアプリを開いて再公開できます。Git 管理者は引き続きリポジトリを非公開にでき、その場合はリポジトリ選択から非表示になり、メンバーはそこからの公開や、そこに保存された Git ベースの UDF コードの実行ができなくなります。[PlaidCloud Git](/ja/guides/git/#gitを開く)と[リポジトリを閲覧できるユーザー](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)を参照してください。
- **モバイルの Weave では音声入力がワンタップになります。** マイクをタップして質問を話すと、話し終えたところで Weave が送信します。もう一度マイクをタップすると早めに停止し、何も聞き取れない場合は自動的にオフになります。話している途中で **Weave** タブを離れたり、アプリをバックグラウンドにしたりしても、話した内容は未送信のまま質問ボックスに残るため、確認できます。実行、一時停止、停止、再開は、確認時の誤った二重タップを無視します。アプリのバージョン 1.3.0 以降が必要です。[音声を使う](/ja/guides/mobile-app/weave-on-mobile/#音声を使う)を参照してください。

## 変更

- **ステップフォームのレイアウトが統一されました。** タブは標準の名前と順序（General、Settings、Source、Columns、Filters、Output、Advanced）になり、ERP 転記フォームには Header columns と Line columns があります。必須フィールドには * が付き、フォームはステップに必要な項目についてのみ保存をブロックします。
- **プロジェクトのコピーでテーブルデータとディメンションメンバーを個別に選択でき、データのコピーが高速になり、非公開コピーでは ERP 書き込み承認が保持されます。** **コピーするデータ**で、**テーブルデータ**（**テーブルデータなし**（デフォルト）、**完全**、**サンプル**）を選択し、これとは別に、デフォルトでオンの**ディメンションメンバーをコピー**を選択できます。そのため、テーブルの行をコピーしなくてもディメンションにメンバーが入った状態でコピーされ、短時間で作成できます。**完全**と**サンプル**のコピーは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも短時間で完了します。**コピー結果**には、テーブルと並んで各ディメンションの結果が表示され、**失敗した項目を再試行**は、失敗したテーブルとディメンションをまとめて再試行します。データ付きで作成した新しいコピーはお客様専用となり、コピー元の ERP 書き込み承認のうち、お客様自身が付与できるものが保持されます。コピー元が Live で転記する場合、コピーは Simulate で作成されるため、Live に切り替えるまで ERP には何も届きません。REST API と `project_copy` MCP ツールも `dimension_members` を受け取ります。[コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーに含まれる ERP 書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認)を参照してください。
- **テーブルの詳細パネルで、そのテーブルを使用しているステップがより早く表示されます。** 別のテーブルを選択すると、前のテーブルのステップがすぐにクリアされ、このプロジェクトのデータを共有している他のプロジェクトのステップは、パネル全体を待たせることなく、少し遅れて追加されます。[テーブルの使用箇所を確認する](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)を参照してください。
- **行アクションメニュー（⋯）がすべてのグリッド行の左端に配置されました。**
- **アプリのタブアイコンが、ライトとダークの両方で統一されたセットになりました。**
- **検証設定のない保存済みの ERP 書き込みステップは、検証のみとして開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS の GL と AP の Post、Xero エクスポートです。明示的に Live で実行するよう設定されたステップは Live のままです。
- **長時間実行されるジョブの進行状況が、どこでも同じ方法で表示されます。**
- **ワークフローを停止すると、そのワークフローが開始したものすべてが停止し、完了できない実行やステップはハングせずに失敗します。** 停止すると、キューに入っていたインポートステップとディメンションステップがキャンセルされるため、ワークスペース内の後続のインポートとディメンションのロードは通常どおり開始されます。また、ワークフローのキュー済みまたは実行中のコネクタ（Singer）同期も停止します。ステップのジョブを開始できない場合、ステップは永遠に待つのではなく、理由を示して失敗します。理由は、約 40 分以内にどのワーカーも開始しなかった、ワーカーが開始した後に消えた、その Pod が約 20 分間 Pending のままである、イメージを約 5 分間取得できない、約 20 分間 Pod が作成されない、のいずれかです。約 30 分以内にどのランナーも拾わないコネクタ同期は、その同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間、ステータスメッセージには経過分数とともに「ワーカーを待機中…」と表示され、処理が始まると消えます。マクロを停止すると、実行中のそのマクロのすべてのコピーが停止します。他のワークフロー内でのみ実行されているマクロは、ワークフロー一覧で**実行中**と表示され、**停止**が利用でき、各ステップのステータス、開始時刻、終了時刻は直近の実行のものが表示されます。サーバーが失われた実行は失敗として終了し、12 時間を超えても実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」で失敗します。[ワークフローを実行する](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
- **再開、実行履歴、実行ステータスが、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローのステップを単独で再実行した後でも、子ワークフローに残っていたものすべてが実行され、1 回の実行内での子ワークフローの各呼び出しには、それぞれ実行履歴のエントリがあります。サーバーが停止したために再開されたステップは、そのログに記載されます。`workflow_run_status` と REST API の実行結果は、失敗したが続行されたステップを、実行を問題なしと報告する代わりに、`continued_step_ids` と `continued_step_count` に一覧表示します。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。
- **ステップのエラーに固有のメッセージが表示されます。** PlaidCloud が想定していなかったエラーは「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードはエラーを 1 行で表示し、その後削除されたワークフローの実行は表示しません。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。
- **完了しない ERP 抽出はステップを失敗させ、再開で続行されます。** **SAP: アドホック抽出**が行数または時間の上限で一時停止したとき、またはエージェントが時間内に応答しなかったとき、あるいは Salesforce、Oracle Fusion バルク、HFM/FCCS のエクスポートジョブがステップの待機終了時点でまだ実行中のときは、ステップが失敗するため、後続のステップが不完全なテーブルに対して実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は同じジョブで停止した位置から続行されます。[実行制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)を参照してください。
- **REST、Import REST、Import Postman ステップは、ワークスペースのアップグレード時に RESTリクエストに変換されます。** きれいに変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **プロジェクトのアーキテクトは、ダッシュボードで行制限付きテーブルのすべての行を見られます。** Analyze での表示と一致します。アーキテクトのアクセス権の削除は、ダッシュボードに即座に反映されます。これは、ユーザーのロールの変更、ユーザーまたはそのグループのプロジェクトからの削除、プロジェクトのアクセスタイプの変更、プロジェクトの以前のバージョンの復元、セキュリティグループの削除のいずれの場合も同様です。元アーキテクトには、行制限付きデータのすべての行が表示されなくなります。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
- **セッションの有効期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードに移動します。** [ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは、認識できないフィールドを無視せず、エラーでそのフィールド名を示して拒否します。** `workflow_upsert` は `memo` を受け取り、その別名として `description` も受け付けます。[不明なフィールドは拒否される](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2 では、Lakehouse が Parquet エクスポートを Google Cloud Storage に直接書き込みます。** Google Cloud Storage ドキュメントアカウントへのエクスポートは、すべての行が PlaidCloud を経由する代わりに、アカウント自身の認証情報を使って、アカウントのバケットに直接書き込まれます。Amazon S3 と Azure Blob Storage アカウントへのエクスポートはこれまでどおりです。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/)を参照してください。
- **Slack、Microsoft Teams、Web Hook ステップが、メッセージが送信されなかった理由を示します。** ステップのエラーには、接続を試みたサーバーと、Slack と Teams の場合は接続が示され、何が問題だったかが記載されます。たとえば、Slack がウェブフックを認識しなくなった、チャンネルに投稿できない、サーバーが見つからない、または 60 秒以内に応答しない、接続が削除された、などです。Slack または Teams のウェブフック URL は、それを知っていれば誰でもお客様のインテグレーションとして投稿できるため、表示されません。[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/)を参照してください。

## 修正

- **無効なプロジェクト設定が分かりやすいメッセージで報告されます。** 不明な環境またはドキュメントアカウント、使用済みまたは予約済みのスラッグ、無効なストレージタイプまたは転記モードは、一般的なサーバーエラーではなく、問題を示すメッセージを返すようになりました。REST API では 500 ではなく 400 になり、AI アシスタントまたは MCP では無効な引数のエラーになります。
- **REST API のディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして処理され、無効として拒否されていました。現在は `value_columns` の各列について集計値を 1 つ返します。また、グリッド（行フィルターと列フィルターの組み合わせごとに 1 つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **テーブルの読み取りやファイル処理が遅くても、他のリクエストが待たされなくなりました。** ウェアハウスからのテーブル列の読み取り、Data Foundation ファイルの登録、Excel へのエクスポート、REST または SOAP インポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panelアプリのコードまたはロゴのチェックは、それぞれ完了するまで同じサーバーが処理している他のすべてのリクエストを停止させることがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 小さな画面や低解像度では、追加・編集ダイアログがウィンドウより高くなり、**作成**ボタンと**更新**ボタンに手が届かないことがありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storage ドキュメントアカウント内の 256 MiB を超えるファイルをコピー、移動、名前変更できます。** これらはいずれもそのサイズのファイルで失敗しており、そのようなファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2 では、テーブルの行数が書き込んだばかりの内容を反映します。** テーブルに書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが 0 行と表示されたり、インポートが 0 行インポートと報告したりしていました。現在は、新しい行がすべての場所で参照可能になってから行数を読み取るため、後続のステップもそれらの行を読み取れます。テーブルを別のブランチに切り替えたり、ブランチをマージしたりしたときも、行数と列数が更新されます。
- **Weave の空値チェックは、以前の実行が実際に残した状態と各実行を比較します。** ステップの空値は、ステップがテーブルを空にして再投入した直後にカウントされることが多く、そのため以前の実行には空値がないように見え、常に一部が空だった列が、たった今そうなったかのように報告されていました。現在は、ステップがテーブルを残した状態で各実行がカウントされます。以前に記録されたカウントは正しいものと区別できないため使用されず、各ステップの空値チェックは履歴を最初からやり直し、5 回の実行がカウントされるまで未チェックと報告されます。行数と値の分布のチェックも、別のステップが同じテーブルに対し、完了から 2 秒を超えた後に行った書き込みを、ステップの書き込みとして扱わなくなりました。[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **削除された接続を REST API に要求すると 404 が返ります。** 削除された接続や存在しない ID を要求すると、一般的なサーバーエラー（500）が返されていました。現在は、接続 ID を示すメッセージとともに 404 が返ります。

## セキュリティ

- **行アクセスの保存時に、ソースにもう存在しない付与済みの値が保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がなくなった、ディメンションからメンバーがなくなった、またはリストからなくなった場合、次の保存時に付与から外れていました。その結果、何もチェックされていないグループが**その他全員**にフォールバックし、すべての行が対象になる可能性がありました。現在は、その値はマーク付きでグリッドに残り、**保存**時に保持するか削除するかを確認します。[行アクセスグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントのオーナーのみです。** ドキュメントアカウントを以前のバージョンに復元する、バージョンを保持または解放する、バックアップを取る操作は、いずれもアカウントのオーナーである必要があり、システム管理のアカウントではどれも利用できません。アカウントのバージョン履歴の表示には、アカウントへのアクセスが必要です。
- **データの読み取り専用のクエリでは、データを変更できなくなりました。** AI アシスタントと MCP クライアントが使用する `query_run` ツールは、データを読み取るステートメント、つまり 1 つの SELECT または WITH ステートメント、その EXPLAIN、または SHOW のみを実行し、それ以外は実行せずに拒否します。データを変更するには `query_transform` を使用してください。MCP のテーブルエクスポートの SQL にも同じルールが適用されます。REST API と JSON-RPC API では、プロジェクトデータを変更できないメンバーに対して、クエリの実行、列ファセットの作成、クエリの CSV ダウンロード、クエリのリモートデータベースへのエクスポート、独自のクエリによるテーブルデータのエクスポートにも適用され、拒否されたクエリは 403 を返します。Explain Analyze は測定のためにクエリを実行するため、クエリログと Lakehouse では、読み取りクエリのみを受け付けるようになり、行アクセスのあるプロジェクトでは、クエリログから実行できるのはプロジェクトのアーキテクトのみです。
- **行制限付きテーブルへの DataFrame の書き込み、レコードの保存、クリアでは、見える行のみが変更されます。** 行アクセスで行が制限されている場合、Python クライアントで制限付きテーブルに DataFrame を書き込む、またはクリアする操作と、REST API でレコードを保存する、またはクリアする操作は、自分の行のみを変更し、アクセス範囲外の行を含むロードは、何も変更される前に、見つかった値を示して拒否されます。プロジェクトのアーキテクト、すべての行が見えるメンバー、ワークフローの実行は、これまでどおりテーブル全体を書き込みます。ユーザーが任意のテーブルに対して行うこれらの書き込みは、すべて**セキュリティログ**に記録されるようになりました。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
- **インポート、コピー、復元、削除で、見えない行が置き換えられなくなりました。** 行アクセスで行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからのテーブルのコピー、そのブランチの切り替えまたはマージ、復元、削除、その他テーブル全体を置き換える操作は、見えない行がテーブルにある間は拒否され、何も変更されません。REST API でテーブルの行を保存する操作も、他のロードと同様に、自分の行のみを変更するようになりました。プロジェクトのアーキテクト、すべての行が見えるメンバー、ワークフローの実行は影響を受けず、これらの操作も**セキュリティログ**に記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
