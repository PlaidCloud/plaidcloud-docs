## 追加

- **PlaidXL で Excel 上でのレポート作成、ドリル、数値の説明、計画ができます。** **PlaidCloud** リボンタブは **接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有** にグループ化されています。よく使うコマンドは **PlaidXL** の右クリックメニューと **PlaidXL Cell** タブにもあり、主なコマンドには変更可能なキーボードショートカットがあります。ショートカットはフィールドへの入力中には動作しません。コマンドが失敗した場合は、どのコマンドがなぜ失敗したかが表示されます。サインイン前にコマンドを実行するとサインイン画面が開き、サインイン後に一度だけ実行されます。サインインは 1 つのワークスペースに対して有効なため、ワークスペースを切り替えると新しいワークスペースへのサインインを求められます（元のワークスペースに戻る場合は求められません）。Office で Microsoft Entra の職場アカウントを使っている場合、PlaidXL がワークスペースを自動的に見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます。** **レポート**タブは、テーブルからライブレポートを配置します。行にはディメンションをドリルダウンして表示し、列には別のディメンションを展開して、交差する位置ごとに `CELL` の値を入れます。**Build my first report** は、お使いのデータからサンプルを作成します。ドリルすると、レポートは行全体や列全体を挿入または削除し、入力した値、メモ、書式は行とともに移動します。[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only** は、ノード、ディメンションの見出し、レポートの値から、ノードをライブの `DRILL` 数式に変え、その数式を自動で編集します。**Custom drill** は挿入前に行をプレビューし、メンバーピッカーはメンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりします。`DRILL` は、除外または展開するノードを指定でき、行方向にも実行できます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明できます。** **Explain this number** は、値の計算内容、現在の PlaidCloud と一致しているか、およびその元になっているテーブルとワークフローステップを表示します。**Show detail rows** は、値の根拠となる行を専用のシートに表示し、合計が一致するかどうかのチェックも行います。
  - **Excel でガバナンスされたメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるとおりにビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計では `0` を、それ以外では理由付きの `#VALUE!` を表示します（`CELLS` のスピルでは空白）。**Metric...** は、プロジェクトのメトリックを現在の値とともに一覧表示します。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに直接入力して計画できます。** `CELL` の値に数値を上書き入力すると、その値がPlaidCloudに書き込まれます。比例配分、均等配分、別のメンバーの形に合わせた配分、金額またはパーセンテージによる調整が可能で、保留したセルは変更されません。平均、中央値、最小値、最大値、標準偏差、分散のセルにも入力でき、入力した値は行や列の挿入・削除に合わせてセルについていきます（削除されたセルの値は報告されます）。**Undo last write**は、入力した値と保存を新しいものから順に取り消します。書き込みを元に戻せるのは、その書き込みを行った本人と、そのワークスペースだけです。合計、または空のセルに入力した平均を取り消しても、その後に同じセルに書き込まれた内容は保持されます。また、完了前に中断された書き込みは取り消せません。詳しくは[PlaidCloudに値を入力する](/ja/reference/cli/plaidxl/write-values/)をご覧ください。
  - **必要な部分だけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新でき、各テーブルの進行状況と**キャンセル**がタスクペインに表示されます。PlaidXL の数式だけを再計算することもできます。取得したテーブルは、データ型に応じて書式設定された Excel テーブルとして届き、更新しても独自の列と数値書式が保持され、同じ場所で更新されます。取得や更新で他のセルが上書きされたり、別の Excel テーブルと重なったりすることはなく、Excel で扱えないほど大きな整数 ID や 1900 年より前の日付はテキストとして届きます。テーブルを再取得しても更新リストに重複して追加されることはなく、**Stop refreshing** でリストから外せます。ディメンションはテーブルとともに更新されます。[すべてのテーブルを更新](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud** は確認なしで書き込み、実行内容を表示して、**元に戻す**を提示します。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセスできない場合は、それらの行だけが置き換えられるため、他のユーザーの行は保持されます。取得後にメンバーが変更されたドリルスルーのシートは保存されません。保存に失敗した場合は、テーブルを元に戻せるよう復元ポイントの名前が表示されます。[テーブルを PlaidCloud に保存](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave** タブで、レポート、数式、ドリル、テーブルを平易な言葉で依頼するか、**Ask Weave about this cell** を選びます。Weave はあなたの権限で PlaidCloud を読み取り、変更するのはワークブックだけです。入力済みの内容を置き換える前には確認し、ワークブックの外を参照する数式は書かず、各変更はペインを再読み込みするまで元に戻せます。[Excel で Weave に質問](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1 つのシートまたはワークブック全体の値のみのコピーを共有できます。** **Convert to values** は、ワークブック全体、1 つのシート、または元に戻せない値への変換を行います（この場合は事前に確認します）。変換するのは PlaidXL の数式とそのスピルだけで、まだ計算中の数式は残して再試行できます。シート名を変更した後でも **Restore PlaidXL formulas** が使えます。
- **ステップフォームのプレビュー。** インポート: SQL、Execute: SQL、SQL抽出、エクスポート: SQL、Salesforce Query では、ステップを実行せずに最大 100 行を表示できます。Anaplan のビューとリストの読み取りでは、生成される列と型が表示されます。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように埋め込まれますが、`{x:>9}` のような変数の書式指定には対応していません。プレビューで実行できるのは標準の SQL 関数のみで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトや、エージェントを使う Execute SQL ステップでは使えません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と [SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)を参照してください。
- **利用状況レポートで変化を確認し、グループで絞り込み、ワークフローに取り込めます。** **概要**には、前の期間と比較した推移の矢印と、非アクティブなメンバーや誰も開いていないダッシュボードやアプリを示す**Highlights**リストが加わりました。無効化されたメンバーは、集計されず、非アクティブとしても一覧に表示されません。**グループ**を選ぶと、**概要**、**内容**、非アクティブ一覧が1つのセキュリティグループのメンバーに限定されます。日付範囲には**Previous month**と**This month**が加わり、すべてのタブで共通になり、アカウントに記憶されます。すべての数値に説明が付き、テーブルには**メンバー**や**Area**のようなわかりやすい名前が使われ、行はEnterキーで開き、読み込み中の表示とエラーの表示も明確になりました。また、**ファネル**の最後のステップには、完了したメンバーの数が表示されます。新しいGet Workspace Usage ステップは、日次または月次の利用状況の合計を、メンバー名を含めずにスケジュールに従ってテーブルに書き込みます。Get Workspace Members ステップと同様に、各実行は**セキュリティログ**に記録されます。詳しくは[利用状況レポート](/ja/administration/access/usage-reports/)と[Get Workspace Usage ステップ](/ja/reference/workflow-steps/general/get-workspace-usage/)をご覧ください。
- **AI アシスタントでテーブルの公開を取り消し、プロジェクトのデフォルトのダッシュボード対象者を設定できます。** `publish_manage` は、テーブルの公開を取り消し、公開されたビューと、どのチャートにも使われていないダッシュボードのデータセットも削除します。チャートがまだ使っているデータセットは残り、公開ビューの上にレポートビューが作られている場合もビューとデータセットは残りますが、テーブルの公開は取り消されます。`project_upsert` は `dashboard_default_audience`（プロジェクト内の新しいダッシュボードの共有先グループ）を設定でき、`[]` でクリアされます。[公開の取り消し](/ja/guides/data/publish/#ai-アシスタントまたは-mcp-で公開を取り消す)と[AI アシスタントまたは MCP でデフォルトの対象者を設定](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ai-アシスタントまたは-mcp-でデフォルトの対象ユーザーを設定する)を参照してください。

- **Git アプリがリポジトリを一覧表示し、できることを案内します。** アプリ一覧の **Git** には、お客様のロール（**管理者**、**コントリビューター**、**閲覧者**）と、ワークスペースのリポジトリが表示されます。各リポジトリには説明、最終更新日、コピーボタン付きのクローンアドレス、**開く**があります。**コンピューターで Git を設定する**カードは、Git のインストール、トークンの作成、クローンの手順を案内し、**クローンの方法**で再度開けます。**Git ですべて表示**は完全な Git インターフェースを開き、**プッシュできるユーザーを管理**はグループ管理を開きます。アクセスレベルは**閲覧者**、**コントリビューター**（アプリコードを `apps` にプッシュ）、**管理者**（`udfs` を含むすべてにプッシュ）で、閲覧者には問い合わせ先として最大 3 人のワークスペース管理者が表示されます。新しい **Git Contributors** グループはコントリビューターの権限を付与し、デフォルトグループにできるため、新しいメンバーは自動的に付与されます。**Git Administration** は管理者の権限を付与します。メンバーの **Git** タブには、Git のユーザー名、レベル、それを付与しているグループが表示されます。メンバーを無効化または削除すると、トークンと SSH キーを含めてそのメンバーの Git アカウントがブロックされ、再有効化するとブロックが解除されます。アプリウィンドウには**リポジトリ**セクションが表示され、UDF には**開く**があり、Git にはワークスペースへ戻る **← 戻る**リンクがあります。アプリのリポジトリや組み込みの `apps` および `udfs` リポジトリを含め、プラットフォームが作成するすべてのリポジトリは、ワークスペースのサインイン済みのすべてのメンバーが読み取れ、サインインしていないユーザーは読み取れないため、メンバーはリポジトリごとの設定なしでアプリを開いて再公開できます。Git 管理者は引き続きリポジトリを非公開にでき、その場合はリポジトリ選択から非表示になり、メンバーはそこからの公開や、そこに保存された Git ベースの UDF コードの実行ができなくなります。[PlaidCloud Git](/ja/guides/git/#gitを開く)と[リポジトリを閲覧できるユーザー](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)を参照してください。
- **Cost to Serve と Operational Transfer Pricing のテンプレートは Common Finance Model を土台にしています。** **Cost to Serve** からプロジェクトを開始すると、部門ごとに設定したアクティビティとドライバーに基づいて営業費用を顧客に配分し、各顧客の提供コスト控除後のマージンを、元帳に突き合わせて確認できます。**Operational Transfer Pricing** から開始すると、各エンティティの利益水準（売上高利益率、ネットコストプラス、または再販売価格マイナス）をポリシーの範囲に照らしてテストし、範囲外のエンティティを目標に戻すための調整額（トゥルーアップ）を算出します。売上高利益率は、EBIT を被テスト当事者の売上高で割った値です。[Cost to Serve](/ja/guides/projects/cost-to-serve/)と [Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/)を参照してください。
- **OneStream と Anaplan が Data Foundation にデータを供給し、OneStream には読み取りステップがあります。** Data Foundation は、OneStream の管理者が構築するデータアダプター経由で OneStream の連結結果を読み取り、エクスポートアクション経由で Anaplan のプランを読み取って、グループの損益計算書をそれらと照合します。新しい **OneStream: Read Adapter** ステップは、連結メンバーごとに 1 回呼び出してアダプターを読み取り、任意のワークフロー内でテーブルに書き込みます。[Data Foundation 用の OneStream](/ja/guides/connections/onestream-for-data-foundation/)、[Data Foundation のソースとしての Anaplan](/ja/guides/connections/anaplan/#data-foundation-のソースとしての-anaplan)、[OneStream: Read Adapter](/ja/reference/workflow-steps/onestream/onestream-read-adapter/)を参照してください。
- **Data Foundation で共通コストの配賦方法を選べます。** **Actions > Allocations...** では、どのコストを配賦するか、何を基準に配賦するか、どこに配賦するか、負のドライバーをどう扱うかを順に設定します。これは、間接費の部門への配賦と、部門から製品や顧客への配賦の両方に使えます。1 か月分のプレビューでは、プールされた額、配賦された額、未配賦の額が表示されます。手動で編集したルールは保持されます。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。
- **Data Foundation で数値を説明し、独自の名前を付けられます。** **Explain this number** は、損益計算書の数値を、元帳にある金額、配賦された額（配賦元と配賦先）、グループで消去された額に分解し、金額の大きい元伝票も表示します。いずれもあなた自身の行アクセスの範囲で表示されます。**Business names** は、カテゴリ、損益計算書の行、メトリック、列に、ビジネスで使っている名前を付け、レポート、メトリック、アシスタントに反映します。[数値の説明](/ja/guides/projects/data-foundation/#数値を説明する)と[ビジネス名](/ja/guides/projects/data-foundation/#ビジネス名)を参照してください。
- **Data Foundation はロードのたびにボードパックを作成し、元に戻すこともできます。** **ロード**のたびに、損益計算書ダッシュボードの Excel ワークブックと PDF がドキュメントアカウントのフォルダーに書き込まれます。レポートがオフの場合、ボードパックはワークブックのみになり、ダイアログにその旨が表示されます。復元ポイントは、各ロードの開始時と、マッピングまたはソースを変更する前に作成されます。**Actions > Restore...** には、それぞれが復元するテーブル数が表示され、ディメンションを含めてプロジェクトを元の状態に戻せます。**Foundation** タブは、現在の状況が分かりやすくなりました。実行中の更新や途中で停止した更新を表示し、テーブルのフォルダーがソースにならない理由を説明し、何かの照合が済むまで**合計が一致することを確認**を保留のままにし、ステータスの読み取りが失敗しても復旧します。更新を適用しても、生成されたステップとノートに加えたあなた自身の編集は保持され、競合があれば記録されます。[ボードパック](/ja/guides/projects/data-foundation/#ボードパック)と[復元ポイント](/ja/guides/projects/data-foundation/#復元ポイント)を参照してください。
- **Data Foundation プロジェクトをクローンしたり、テンプレートとして保存したりできます。** **Actions > Clone...** は、モデルの編集、メトリック、分析パスを含めてプロジェクトをコピーします。**Save as my template...** は、設定をドキュメントアカウントに保存し、**From a template file...** は、そのファイルから新しい非公開プロジェクトを開始します。ソースは接続待ちの状態になります。[プロジェクトのクローン](/ja/guides/projects/data-foundation/#プロジェクトを複製する)と[マイテンプレートとして保存](/ja/guides/projects/data-foundation/#マイテンプレートとして保存する)を参照してください。
- **Data Foundation のセットアップチェックリストは引き継ぎまで続き、アシスタントが残りの項目を解決できます。** チェックリストには、夜間更新、エビデンスパック、プロジェクトの所有者への引き継ぎが加わり、誰がプロジェクトをセットアップしたかも表示されます。タイプのない勘定科目、複数のソースが使うコード、どれにも一致しなかったファイルの列について、アシスタントに回答案を提案してもらえます。アシスタントは何も書き込まず、回答はあなたが適用します。[Data Foundation を始める](/ja/guides/projects/data-foundation-getting-started/)と[Ask で未解決の質問を解決](/ja/guides/projects/data-foundation/#ask-で未解決の質問を解決する)を参照してください。

- **モバイルの Weave での音声入力は、タップ 1 回で使えます。** マイクをタップして質問を話すと、話し終えた時点で Weave が一度だけ送信します。もう一度マイクをタップすると途中で停止し、何も聞き取れない場合は自動的にオフになります。話している途中で **Weave** タブから離れたり、アプリをバックグラウンドにしたりした場合は、話した内容が送信されずに質問ボックスに残るので、確認できます。実行、一時停止、**停止**、再開は、確認画面での誤った二度タップを無視します。アプリのバージョン 1.3.0 以降が必要です。[音声の利用](/ja/guides/mobile-app/weave-on-mobile/#音声を使う)を参照してください。

## 変更

- **PlaidCloud の Web アプリと Python クライアントライブラリは REST API を使用し、JSON-RPC は非推奨になりました。** Web アプリはリクエストを REST API に送信します。`plaidcloud-rpc` 1.25.0 以降では、`SimpleRPC` の呼び出しはコードを変更しなくても REST API に送られます。REST API がまだ対応していない呼び出しや、まだ以前のリリースで稼働しているワークスペースへの呼び出しは、これまでどおり JSON-RPC を使用します。JSON-RPC は今後のリリースで削除されるため、スクリプトとノートブックを `plaidcloud-rpc` 1.25.0 以降に更新し、新しい連携は REST API を使って作成してください。[コマンドライン](/ja/reference/cli/jupyter/command-line/)を参照してください。
- **ステップフォームのレイアウトが統一されました。** タブの名前と順序が標準化され、General、Settings、**ソース**、Columns、Filters、Output、Advanced の順になり、ERP 転記フォームには Header columns と Line columns があります。必須フィールドには * が付き、フォームは、ステップに必要な項目についてのみ保存をブロックします。
- **プロジェクトをコピーでは、テーブルデータとディメンションメンバーを別々に選べ、データのコピーが高速になり、非公開コピーでは ERP書き込み承認が維持されます。** **Data to copy** の下で、**テーブルデータ**（**No table data**（デフォルト）、**完全**、**サンプル**）と、別に **Copy dimension members**（デフォルトでオン）を選びます。そのため、テーブルの行を含まないコピーでも、ディメンションにはデータが入った状態で作成され、短時間で完了します。**完全**コピーと**サンプル**コピーは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも早く完了します。**コピー結果**には、テーブルと並んで各ディメンションの結果が表示され、**Retry failed items** は失敗したテーブルとディメンションをまとめて再試行します。データ付きで作成した新しいコピーはあなた専用になり、コピー元の ERP書き込み承認のうち、あなた自身が付与できるものが維持されます。コピー元が Live で転記している場合、コピーは Simulate で作成されるため、Live に切り替えるまで ERP には何も送信されません。REST API と `project_copy` MCP ツールも `dimension_members` を受け付けます。[コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーでの ERP書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認)を参照してください。
- **テーブルの詳細パネルで、そのテーブルを使うステップがより早く表示されます。** 別のテーブルを選択すると、前のテーブルのステップがすぐにクリアされ、このプロジェクトのデータを共有する他のプロジェクトのステップは、パネル全体の表示を待たせずに少し遅れて追加されます。[テーブルの使用箇所の確認](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)を参照してください。
- **行アクションメニュー（⋯）が、すべてのグリッド行の左端に表示されます。**
- **アプリのタブアイコンが、ライトテーマとダークテーマで統一されたセットになりました。**
- **検証設定のない保存済みの ERP 書き込みステップは、検証のみとして開きます。** 対象は SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL と AP Post、Xero のエクスポートです。明示的に Live で実行するよう設定されたステップは Live のままです。
- **長時間実行されるジョブの進行状況が、どこでも同じ方法で表示されます。**
- **ワークフローを停止すると、開始したすべての処理が停止し、完了できない実行やステップは、待機し続けずに失敗します。** 停止すると、キューに入ったままのインポートステップとディメンションステップがキャンセルされるため、ワークスペース内の後続のインポートやディメンションのロードは通常どおり開始されます。また、そのワークフローのキュー中または実行中のコネクター（Singer）の同期も停止されます。ステップのジョブを開始できない場合、ステップは永久に待機せず、理由を示して失敗します。理由は、約40分以内にワーカーが開始しなかった、ワーカーが開始した後に消えた、ポッドが約20分間Pendingのままになった、イメージを約5分間取得できなかった、約20分間ポッドが作成されなかった、のいずれかです。約30分以内にどのランナーも受け取らないコネクターの同期は、その同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間、ステータスメッセージに「Waiting for a worker…」と経過時間（分）が表示され、処理が始まると消えます。マクロを停止すると、実行中のすべてのコピーが停止します。一方、1つのコピーを停止した場合や、**Macro Concurrent**ステップが応答しなくなったコピーを見限った場合は、それを呼び出したワークフローは実行を続けます。他のワークフロー内でのみ実行されているマクロは、ワークフロー一覧で**実行中**と表示され、**停止**が使え、各ステップのステータスと開始・終了時刻は直近の実行から取得されます。サーバーが失われた実行は失敗として終了し、12時間たっても実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」で失敗します。詳しくは[ワークフローの実行](/ja/guides/workflows/run-a-workflow/#開始されないステップ)をご覧ください。
- **再開、実行履歴、実行ステータスが、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローのステップを単独で再実行した後でも、子ワークフローに残っていたものがすべて実行されます。1 回の実行内での子ワークフローの呼び出しは、それぞれ独自の実行履歴エントリを持ちます。サーバーが停止したために再開するステップは、ログにその旨が記録されます。`workflow_run_status` と REST API の実行結果は、失敗したものの続行したステップを `continued_step_ids` と `continued_step_count` に一覧表示し、実行が問題なく完了したかのようには報告しません。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。
- **ステップのエラーに固有のメッセージが表示されます。** PlaidCloud が想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードには、エラーが 1 行で表示され、すでに削除されたワークフローの実行は含まれません。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。
- **完了しない ERP 抽出はステップを失敗させ、再開すると続行されます。** **SAP: アドホック抽出**が行数または時間の上限で一時停止した場合や、そのエージェントが時間内に応答しなかった場合、また Salesforce、Oracle Fusion のバルク、HFM/FCCS のエクスポートジョブが、ステップが待機をやめた時点でも実行中の場合、ステップは失敗し、その後のステップが不完全なテーブルに対して実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は停止した位置から同じジョブで続行されます。[実行の制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)を参照してください。
- **エクスポートをキャンセルすると、ウェアハウスのクエリも停止します。** ワークフローの停止によるものも含め、エクスポートやダウンロードがキャンセルされると、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplumではデータを読み取っているクエリも停止し、リモートデータベースへのエクスポートはソースの読み取りを停止します。最後まで実行され続けることはありません。
- **REST、Import REST、Import Postman ステップは、ワークスペースのアップグレード時に RESTリクエストに変換されます。** きれいに変換できないステップはそのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **プロジェクトのアーキテクトは、ダッシュボードで行が制限されたテーブルのすべての行を閲覧できます。** これは Analyze での表示と同じです。アーキテクトのアクセスを取り消すと、ダッシュボードにも即座に反映されます。これは、ユーザーのロールの変更、ユーザーまたはそのグループのプロジェクトからの削除、プロジェクトのアクセスタイプの変更、以前のプロジェクトバージョンの復元、セキュリティグループの削除のいずれの場合も同様です。元のアーキテクトは、行が制限されたデータのすべての行を閲覧できなくなります。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
- **行アクセスで制限されたメンバーも、自分の SQL クエリを実行して結果をエクスポートできます。** 行アクセスが設定されたプロジェクトで、アーキテクトでないメンバーは、クエリ画面での自分のクエリで、付与された行だけを取得でき、**アクセス権により行が制限されています**という通知とともに、CSV、Excel、JSON にエクスポートできます。以前はこれらは拒否されていました。パーセント記号（`%`）を含む付与値は、クエリ画面で行を返すようになり、そのようなクエリを CSV としてダウンロードする操作も動作します。Snowflake や Databricks での自分のフリーフォーム SQL、Postgres 系ウェアハウスでの自分の SQL のエクスポート、スナップショット時点でのガバナンス対象テーブルの読み取りは、引き続き拒否されます。また、ビューでフィルターを適用するには、ガバナンス対象の列を元の名前のまま保持する必要があります。[行アクセスと自分で書くクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスとご自身で記述するクエリ)を参照してください。
- **セッションの期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードへ移動します。** [ダッシュボードの利用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは、認識できないフィールドを無視せず、エラーでフィールド名を示して拒否します。** `workflow_upsert` は `memo` を受け付け、`description` も別名として受け付けます。[不明なフィールドは拒否されます](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2 では、レイクハウスが Parquet のエクスポートを Google Cloud Storage に直接書き込みます。** Google Cloud Storage のドキュメントアカウントへのエクスポートは、すべての行がいったん PlaidCloud を経由するのではなく、アカウント自身の認証情報を使ってアカウントのバケットに直接書き込まれます。Amazon S3 と Azure Blob Storage のアカウントへのエクスポートは、これまでどおり動作します。[Parquet へのエクスポート](/ja/reference/workflow-steps/export/export-to-parquet/)を参照してください。
- **Slack、Microsoft Teams、Web Hook の各ステップは、メッセージが送信されなかった理由を示します。** ステップのエラーには、接続を試みたサーバーと（Slack と Teams の場合は）接続が示され、何が問題だったかが説明されます。たとえば、Slack が Webhook を認識しなくなった、チャンネルに投稿できない、サーバーが見つからない、または 60 秒以内に応答しない、接続が削除されている、などです。Webhook URL を知っていれば誰でもあなたの連携として投稿できてしまうため、Slack や Teams の Webhook URL は表示されません。[Slack で通知](/ja/reference/workflow-steps/notifications/notify-via-slack/)を参照してください。
- **プロジェクトのサービスアカウントのアクセストークンは 24 時間以上有効です。** UDF ステップなど、プロジェクトとして実行されるワークフローのジョブには、24 時間有効なトークンが発行されます。これより短い有効期間はワークスペースのアップグレード時に引き上げられ、ユーザーが設定したより長い有効期間はそのまま維持されます。
- **ワークスペースの組織、オーナー、データセンター、リリース、バージョンは PlaidCloud が設定します。** コントロールプレーンでは、ワークスペースの編集時にこれらのフィールドは読み取り専用になります。また、作成したワークスペースはあなたがオーナーとなり、既定のデータセンターとリリースチャネルに配置されます。バージョンを変更するには **バージョンを設定** を使用し、ワークスペースの移動、オーナーやチャネルの変更、固定は PlaidCloud サポートに依頼してください。[ワークスペースの構成](/ja/administration/control-plane/workspace-configuration/#基本設定)を参照してください。

## 修正

- **無効なプロジェクト設定がわかりやすいメッセージで報告されます。** 不明な環境やドキュメントアカウント、すでに使われている、または予約されているスラッグ、無効なストレージタイプや転記モードは、汎用的なサーバーエラーではなく、問題を示すメッセージを返すようになりました。REST API では 500 ではなく 400 になり、AI アシスタントまたは MCP では無効な引数のエラーになります。
- **REST API のディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして扱われ、無効として拒否されていました。現在は `value_columns` の各列について集計された値を 1 つ返します。行フィルターと列フィルターの組ごとに値を 1 つ返すグリッドには、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **遅いテーブルの読み取りやファイル処理が、他のリクエストを止めなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundation のファイルの登録、Excel へのエクスポート、REST または SOAP インポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panel アプリのコードやロゴの確認は、それぞれが完了するまで、同じサーバーが処理している他のすべてのリクエストを止めることがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 小さい画面や低い解像度では、追加と編集のダイアログがウィンドウより高くなり、**作成**ボタンと**更新**ボタンに手が届かないことがありました。現在はフォームがスクロールし、ボタンは下部に固定されます。
- **Azure Blob Storage のドキュメントアカウントで、256 MiB を超えるファイルをコピー、移動、名前変更できます。** これらの操作はそのサイズのファイルで失敗していて、そのようなファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2 では、テーブルの行数に、書き込んだばかりの内容が反映されます。** テーブルに書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが 0 行と表示されたり、インポートが 0 行のインポートと報告されたりしました。現在は、新しい行がどこからでも参照できるようになってから行数を読み取るため、後続のステップもそれらの行を読み取ります。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりした場合も、行数と列数が更新されます。
- **Weave の空値チェックは、各実行を、以前の実行が実際に残した内容と比較します。** ステップの空値は、ステップがテーブルを空にして再入力した直後にカウントされることが多く、そのため以前の実行には空値がなかったように見え、常に一部が空だった列が、ちょうど空になったかのように報告されていました。現在は、ステップがテーブルを残したとおりの状態で各実行がカウントされます。以前に記録されたカウントは、正しいものと区別できないため使用されません。各ステップの空値チェックは履歴を最初からやり直し、5 回の実行がカウントされるまで未チェックとして報告されます。行数と値の分布のチェックでも、ステップが終了してから 2 秒を超えて別のステップが同じテーブルに行った書き込みを、そのステップの成果として扱わなくなりました。[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **Data Foundationで、反転した為替レートと小数のしきい値の精度が保たれます。** 報告通貨から別の通貨への形でレートが提示されているためにPlaidCloudが反転するレートは、小数点以下6桁に丸められることがあり、そのためインドネシア・ルピアのようにレートが小さい通貨の金額が約1%ずれていました。反転したレートは、小数点以下12桁まで保持されるようになりました。`0.5`のような小数を含む`group_amber`または`group_red`のしきい値は、整数に丸められていました。次回のロードでは、正確な値が使用されます。詳しくは[為替レート](/ja/guides/projects/data-foundation/#為替レート)をご覧ください。
- **無効化されたメンバーのアラートとダイジェストが停止します。** 所有者が無効化されたPanelアプリのアラートやダイジェストは、チェックと送信を続けていました。現在は、所有者が無効化されている間は一時停止し、再有効化されると再開します。詳しくは[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)をご覧ください。
- **削除された接続を REST API に問い合わせると 404 が返ります。** 削除された接続や存在しない ID を要求すると、汎用的なサーバーエラー（500）が返されていました。現在は、接続 ID を示すメッセージとともに 404 が返ります。

## セキュリティ

- **パスワードでのサインインには認証アプリが必要になり、パスワードの要件も強化されました。** PlaidCloud のパスワードでサインインするメンバーは、次回のサインイン時に認証アプリの設定を求められ、以降はサインインのたびにそのコードを入力します。シングルサインオン、Google・Microsoft・GitHub でのサインイン、API トークン、サービスアカウントは変わりません。新しいパスワードは 12 文字以上で、ユーザー名や直近 6 回分のパスワードと同じにはできません。また、サインインに 30 回失敗すると、アカウントは短時間ロックされます。ワークスペースですでに設定されているより厳しいルールはそのまま維持されます。[メンバー認証](/ja/administration/access/member-authentication/)を参照してください。
- **接続はループバックアドレスやクラウドのメタデータアドレスに到達できません。** データベース接続とそのテスト、SFTP、TM1、Essbase、HFM/FCCS、Salesforce、Anaplan、NetSuite、Workday、Xero、QuickBooks、Acumatica、SAP S/4HANA、Dynamics 365 Finance and Operations は、`localhost` などのループバックアドレスや、`169.254.169.254` などのリンクローカルアドレスまたはクラウドのメタデータアドレスであるホスト、またはそれらに解決されるホストを、リダイレクト後も含めて拒否します。エラーにはホストとアドレスが示されます。プライベートネットワーク上のアドレスは影響を受けません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続が到達できないアドレス)を参照してください。
- **接続の資格情報は、接続またはワークフローを編集できるユーザーにのみ渡されます。** REST API と MCP では、接続を表示できても接続とワークフローのどちらも編集できないメンバーには、保存済み接続のパスワード、トークン、キーがマスクされた状態で返されます。その接続を開いたり参照したりすることは引き続きできます。保存済みとは異なるサーバー URL で Git 接続を参照した場合、保存済みのトークンは送信されません。また、リポジトリの外に出るファイルパスやブランチは拒否されます。[接続の資格情報を見られるユーザー](/ja/guides/connections/create-connection/#接続の資格情報を見られるユーザー)を参照してください。
- **アプリのビルドから Git の資格情報は見えません。** Panel アプリや Dash アプリのビルドは、開始前にリポジトリを取得します。そのため、ビルドされるコードは、その依存パッケージも含めて、ワークスペースの Git の資格情報にアクセスできません。
- **プロキシダウンロードのリンクは署名付きで、有効期間は 1 時間です。** **PlaidCloud プロキシダウンロードを使用** がオンの場合、ダウンロードリンクは PlaidCloud が作成したものだけが、1 時間に限り機能します。新しいリンクを取得するには、ダウンロードをもう一度開いてください。手作業で組み立てたリンクは拒否されます。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)を参照してください。
- **自分が持っている権限のグループにのみユーザーを追加できます。** セキュリティグループへのメンバーの追加、メンバーのグループの選択、Architect の招待は、そのグループが自分の持っていない権限を付与する場合に拒否されます。ワークスペース管理者にはこの制限はありません。[セキュリティグループの管理](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)を参照してください。
- **ツールチップやメッセージでは、データがテキストとして表示されます。** ツールチップ、ダイアログ、メッセージ内の名前や値はプレーンテキストとして表示されるため、データに含まれるマークアップはレンダリングされません。ブラウザーで実行される Panel アプリや JupyterLite 向けに提供されるファイルは、種類が不明な場合は開かずにダウンロードされ、SVG ファイルと XML ファイルはスクリプトが無効な状態で開きます。
- **接続の設定を変更したり無効化したりできるのは、接続の所有者またはワークスペース管理者だけです。** REST API、JSON-RPC、AIアシスタントやMCPを通じて接続の設定を変更するには、PlaidCloudでの編集と同様に、その接続の所有者のいずれかであるか、所有者のいない接続についてはワークスペース管理者である必要があります。接続の有効化、無効化、ロック、ロック解除には所有者またはワークスペース管理者の権限が必要で、複数の接続を指定したリクエストは、そのうち1つでも変更できない接続がある場合、何かが変更される前に全体が拒否されます。ワークスペースのデフォルトのAI接続を選択できるのはワークスペース管理者だけで、メンバーが所有する接続がデフォルトになるのは、管理者が所有する接続や所有者のいない接続がデフォルトになり得ない場合に限られます。詳しくは[接続を編集する](/ja/guides/connections/create-connection/#接続を編集する)と[LLMプロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)をご覧ください。
- **行アクセスを保存しても、ソースにもうない付与済みの値が保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がなくなった場合、ディメンションからメンバーがなくなった場合、リストから外れた場合に、次の保存時に付与から外れていました。何もチェックされていないグループは **Everyone else** にフォールバックし、それはすべての行を意味する場合がありました。現在は、その値がマーク付きでグリッドに残り、**保存**時に保持するか削除するかを確認します。[行アクセスのグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
- **ドキュメントアカウントの以前のバージョンを復元できるのは、アカウントの所有者のみです。** ドキュメントアカウントを以前のバージョンに復元すること、バージョンを保持または解放すること、バックアップを取ることは、アカウントの所有者である必要があり、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、アカウントへのアクセスが必要です。
- **読み取り専用であるべきクエリで、データを変更できなくなりました。** AI アシスタントと MCP クライアントが使う `query_run` ツールは、データを読み取る文（SELECT または WITH 文 1 つ、その EXPLAIN、または SHOW）のみを実行し、それ以外は実行せずに拒否します。データを変更するには `query_transform` を使います。MCP のテーブルエクスポートの SQL にも同じルールが適用されます。REST と JSON-RPC API では、プロジェクトデータを変更できないメンバーについて、クエリの実行、列ファセットの作成、クエリの CSV としてのダウンロード、クエリのリモートデータベースへのエクスポート、独自のクエリによるテーブルデータのエクスポートにも適用され、拒否されたクエリは 403 を返します。Explain Analyze は、測定のためにクエリを実行するため、クエリログとレイクハウスでは、読み取りのクエリのみを受け付けるようになりました。行アクセスが設定されたプロジェクトでは、クエリログからこれを実行できるのはプロジェクトのアーキテクトのみです。
- **行が制限されたテーブルへの DataFrame の書き込み、レコードの保存、クリアは、閲覧できる行だけを変更します。** 行アクセスで行が制限されている場合、Python クライアントで制限されたテーブルに DataFrame を書き込んだりクリアしたりすると、また REST API でそこにレコードを保存したりクリアしたりすると、自分の行だけが変更されます。アクセス範囲外の行を含むロードは、何も変更される前に、見つかった値を示して拒否されます。プロジェクトのアーキテクト、すべての行を閲覧できるメンバー、ワークフローの実行は、これまでどおりテーブル全体に書き込みます。人が行うこれらの書き込みは、どのテーブルに対するものでも、セキュリティログに記録されるようになりました。[制限されたテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
- **インポート、コピー、復元、削除で、見えない行が置き換えられることはなくなりました。** 行アクセスで行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えやマージ、復元、削除、削除後の復旧、その他テーブル全体を置き換える操作は、見えない行がテーブルに含まれている間は拒否され、何も変更されません。REST APIでテーブルの行を保存する場合も、他のロードと同様に、自分の行だけが変更されるようになりました。プロジェクトのアーキテクト、すべての行を表示できるメンバー、ワークフローの実行には影響しません。これらの操作も**セキュリティログ**に記録されます。詳しくは[制限付きテーブルにデータをロードする](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)をご覧ください。
