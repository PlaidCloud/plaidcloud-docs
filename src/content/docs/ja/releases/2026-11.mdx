## 追加

- **コントロールプレーンの Trust Center で、セキュリティチームが PlaidCloud のセキュリティドキュメントを入手できます。** 管理者とセキュリティのユーザーは、組織の**Trust Center**を開き、サブプロセッサー一覧や DPA などの公開ドキュメントをすぐにダウンロードできます。また、組織としてセキュリティドキュメント用の NDA に一度署名すると、SOC 2 Type II レポートなどの制限付きドキュメントのロックが解除されます。ほかの管理者とセキュリティのユーザーには、誰がいつ署名したかが表示されます。契約にすでに NDA が含まれている組織は、NDA を締結済みとして登録してもらうことで、署名せずにドキュメントのロックを解除できます。制限付きドキュメントのダウンロードには透かしが入り、記録が残ります。NDA の新しいバージョンには、改めて同意が必要です。管理者とセキュリティのユーザーは、新規または更新されたドキュメントと NDA の新しいバージョンをまとめた毎日のメールを、組織ごとに受け取るよう設定することもできます。このメールにドキュメント本体が含まれることはありません。[Trust Center](/ja/administration/control-plane/trust-center/)を参照してください。
- **PlaidXL で、Excel 上でレポートの作成、ドリル、数値の説明、計画ができます。** **PlaidCloud**リボンタブは**接続**、**挿入**、**更新**、**ドリル**、**書き込み**、**共有**にグループ化されました。よく使うコマンドは**PlaidXL**右クリックメニューと**PlaidXL Cell**タブからも使えます。主なコマンドには変更可能なキーボードショートカットがあり、フィールドに入力している間は動作しません。コマンドが失敗すると、どのコマンドがなぜ失敗したかが表示されます。サインイン前に実行したコマンドはサインイン画面を開き、サインインが完了すると実行されます。サインインは1つのワークスペースに対して有効なため、ワークスペースを切り替えると新しいワークスペースへのサインインを求められます（元のワークスペースに戻るときは求められません）。Office で Microsoft Entra の職場アカウントを使っている場合は、PlaidXL がワークスペースを自動的に見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます。** **レポート**タブでは、テーブルからライブレポートをレイアウトできます。行方向にあるディメンションをドリルダウンし、列方向に別のディメンションを配置して、各交点に `CELL` 値を表示します。**Build my first report**は、お使いのデータからサンプルを作成します。ドリルすると、レポートは行全体と列全体を挿入または削除し、入力した値、メモ、書式は元の行に付いたまま残ります。[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only**は、ノード、ディメンションの見出し、またはレポートの値から、ノードをライブの `DRILL` 数式に変換し、編集まで行います。**Custom drill**では挿入前に行をプレビューでき、メンバーピッカーではメンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりできます。`DRILL` には、除外するノードや展開するノードを指定でき、行方向に実行することもできます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明できます。** **Explain this number**は、値の計算内容、現在の PlaidCloud の値と一致しているかどうか、元になっているテーブルとワークフローのステップを表示します。**Show detail rows**は、値の元になった行を専用のシートに書き出し、合計が一致するかどうかのチェックも行います。
  - **Excel でガバナンスされたメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるとおりにビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計では `0` を表示し、それ以外では理由とともに `#VALUE!` を表示します（`CELLS` のスピルでは空白）。**Metric...** ボタンは、プロジェクトのメトリックを現在の値とともに一覧表示します。メトリックは、複数の代替階層でフィルターしたり、代替階層のメンバーとほかのディメンションのメンバーを組み合わせたりできます。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに入力して計画を立てられます。** `CELL` の値に数値を上書き入力すると、その値が PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの形状に合わせた配分、金額またはパーセンテージによる調整が可能で、固定したセルはそのまま維持されます。平均、中央値、最小値、最大値、標準偏差、分散のセルにも値を入力できます。入力した値は、行や列が挿入または削除されてもそのセルに追従します（削除されたセルの値は報告されます）。**Undo last write**は、入力した値と保存を新しいものから順に取り消します。書き込みを取り消せるのは、その書き込みを行った本人が同じワークスペースで操作する場合に限られます。合計の取り消しや、空のセルに入力した平均の取り消しでは、その後に同じセルへ書き込まれた内容が保持されます。完了前に中断された書き込みは取り消せません。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要なものだけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新でき、各テーブルの進行状況と**キャンセル**はタスクペインに表示されます。PlaidXL の数式だけを再計算することもできます。取得したテーブルは、データ型に合わせて書式設定された Excel テーブルとして取り込まれ、更新しても独自に追加した列と数値の書式が保持され、元の場所で更新されます。取得や更新でほかのセルが上書きされたり、別の Excel テーブルと重なったりすることはありません。Excel で扱えないほど大きい整数の ID と1900年より前の日付は、テキストとして取り込まれます。テーブルを再取得しても更新リストに重複して追加されることはなく、**Stop refreshing**でリストから外せます。ディメンションもテーブルと一緒に更新されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud**は確認なしで書き込み、実行した内容を表示して、**元に戻す**を提示します。Lakehouse テーブルでは、保存のたびに最大7日間まで元に戻せます。フィルターを指定して取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーによる保存では、該当する行だけが置き換えられるため、ほかのユーザーの行は保持されます。取得した後にメンバーが変更されたドリルスルーのシートは保存されません。保存に失敗した場合は、テーブルを元に戻せるように復元ポイントが示されます。[テーブルを PlaidCloud に保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave**タブで、レポート、数式、ドリル、テーブルを普段の言葉で依頼するか、**Ask Weave about this cell**を選択します。Weave はあなたの権限で PlaidCloud を読み取り、変更するのはブックだけです。入力済みの内容を置き換える前には確認し、ブックの外を参照する数式を書くことはありません。各変更は、ペインを再読み込みするまで元に戻せます。[Excel で Weave に質問する](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1つのシートまたはブック全体を、値のみのコピーとして共有できます。** **Convert to values**は、ブック全体、1つのシート、または元に戻せない値のみへの変換を行い（元に戻せない変換は先に確認します）、変更するのは PlaidXL の数式とそのスピルだけです。まだ計算中の数式は変換せずに残して再試行でき、シートの名前を変更した後でも**Restore PlaidXL formulas**を使えます。
- **転記レジスターは、対応が必要な内容から開きます。** 確認が必要なものがある場合は**例外**、承認待ちのリクエストがある場合は**承認**、それ以外の場合は**すべての転記**で開きます。レールの画面は**自分の対応待ち**、**レジスター**、**インサイト**、**設定**にグループ化され、**例外**と**承認**には件数が表示されます。すべての画面が共通のヘッダーとスコープバーを使います。期間（**今月**、**前月**、**過去7日間**、**過去30日間**、**カスタム**）、接続、プロジェクト、環境、エンティティ、そして**本番**、**シミュレーション**、**すべて**を選び、**リセット**するか、**Saved scope**として保持します。前回のスコープは記憶されます。
  - **例外で、確認が必要なものを整理できます。** **要確認**、**未確認**、**保留中**、**失敗**、**取消未完了**のチップに件数が表示され、接続の正常性を示す行には「All N connections posting normally」と表示されます。すべての転記には、分かりやすい言葉で状態が表示され、次に何をすべきかがツールチップで示されます。未処理のものがない場合は**All clear**と表示されます。**Find a posting by ledger id**またはコマンドパレットに元帳 ID を貼り付けると、その転記を直接開けます。
  - **承認、委任、ウォッチは受信トレイ形式の画面になりました。** **Waiting on me**と**Submitted by me**を切り替え、理由を添えて**承認**または**却下**し、複数をまとめて承認できます。承認はトーストから**元に戻す**ことができます。**Delegate approvals**は短いダイアログで、**ウォッチ一覧**には自分がフォローしているものが一覧表示されます。**転記を取消**と、一括での再試行とクリアのダイアログは、同じレイアウトを使います。
  - **転記のドロワーで、何が起きたかが分かります。** 状態とその意味、項目名付きの主要な情報、**明細**、**履歴**、**承認**タブが表示され、**レビュー済みにする**、**再試行**、**取消…**、**接続をウォッチ**、**実行をウォッチ**、**リンクをコピー**を使えます。コピーしたリンクからは、その転記を直接開けます。
  - **アシスト、エクスポート、保持期間も同じデザインになりました。** **アシスト**には、質問ボックス、インサイトカード、**Draft — nothing applied**と表示されたアドバイスがあり、**すべての転記**には**これらを表示**付きの異常カードが表示されます。**エクスポートとアラート**には**New schedule**があり、**保持期間**は1枚のカードにまとめられました。
  - **レジスターは常に最新の状態に保たれます。** レールのバッジは転記の変化に合わせて更新され、転記が変更されると開いている一覧に**更新**が表示され、開いているドロワーはその場で更新されます。**ホーム**では、**要対応**の下に**転記レジスター**カードが表示されます。[転記レジスターを確認する](/ja/guides/connections/posting-register/)を参照してください。
- **プロジェクトホームは6つのページで構成されます。** テキストのみのレールには**概要**、**変数**、**スケジュールとセンサー**、**アクセスと共有**、**データと接続**、**アプリとブランディング**が並び、変数の数と、有効なスケジュールおよびセンサーの数がバッジで表示されます。**概要**には、プロジェクトの説明とラベル、ロックの状態、テーブル、ワークフロー、ステップ、変数、公開済みテーブル、**データサイズ**（**ストレージ**を開きます）のタイル、直近3回のスケジュール実行、プロジェクトのデフォルトが表示され、**プロジェクトレポート**（PDF またはインタラクティブな HTML）と**アーカイブのエクスポート**も利用できます。データサイズは**プロジェクト**画面に表示されるのと同じ合計で、復元用に保持されている以前のバージョンも含まれます。ツールチップでは、現在のデータと以前のバージョンが分けて表示されます。ほかのページでは、変数、スケジュールとセンサー（**カレンダービュー**と、**有効化**または**無効化**付き）、プロジェクトとそのダッシュボードを開けるユーザーと、そのテーブルを読み取れるプロジェクト、接続とテーブルストレージのデフォルトと ERP 転記モード、Panelアプリ、ブランディング、プロジェクトのタイル画像を管理します。ロックされたプロジェクトにはバナーが表示され、コントロールが無効になります。[プロジェクトホーム](/ja/guides/projects/project-home/)を参照してください。
- **ドキュメントは概要から開き、ページのレールが付きました。** **概要**、**参照**、**共有**、**自分の非公開**、**管理**がレールに並びます。**概要**には、アカウントのタイル、**Pinned**ファイル（そのフォルダーの**参照**を、ファイルを選択した状態で開きます）、サービス別のアカウント、アカウントを利用できるユーザーが表示されます。**管理**には自分が所有するアカウントが一覧表示されます。ワークスペース管理者にはすべてのドキュメントアカウントが表示され、ほかの場面で管理できるアカウントはここでも管理できます（システム管理のアカウントは拒否され、マネージドバケットのアカウントは複製できません）。行の **⋯** メニューには、**開く**、**編集**、**複製…**、**利用できるユーザー**、**使用箇所…**、**バージョン履歴**、**有効にする**または**無効にする**、**削除**があります。アカウントは、**一般**、**アクセス**、**認証情報**、SFTP の場合はさらに**SSH**のカードを備えたページとして開き、未保存の変更があるままページを離れようとすると確認します。**参照**には、ラベル付きのツールバー、行メニュー、ドロップゾーン、**Uploads and imports**パネルがあり、このパネルには各アップロードとテーブルへのインポートが、進行状況と操作とともに表示されます。**Pop out**はフォルダーを別ウィンドウで開き、**Dock**で元に戻します。[ドキュメント](/ja/guides/documents/)と[ドキュメントアカウントの使用](/ja/guides/documents/using-document/)を参照してください。
- **ダッシュボードは概要から開き、ページのレールが付きました。** **概要**、**ダッシュボード**、**アプリ**、**ノートブック**、そしてワークスペース管理者向けの**アクセスレビュー**がレールに並び、下部には**ナビゲーターを開く**があります。**概要**には、ダッシュボードとアプリのタイル（クリックすると、絞り込み済みの対応する一覧が開きます）、最近開いたものやスターを付けたもの、失敗したアプリと自分の対応待ちのアクセスリクエスト、利用状況へのアクセス権を持つメンバー向けに最も多く開かれたダッシュボードが表示されます。**ダッシュボード**は**すべて**、**管理中**、**お気に入り**で絞り込め、**アプリ**には各アプリの**種類**とライブの状態が表示されます。[ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **アイデンティティは概要から開き、ページのレールが付きました。** レールには**概要**、**メンバー**、**ディレクトリ**、**セキュリティグループ**、**配布リスト**に続いて、**セッション**、**セキュリティログ**、**APIクライアント**、**グループ監査**、**すべてのスコープ**が並び、**利用状況レポート**はページの上に重ねて開きます。**概要**には、メンバー、アクティブなメンバー、一度もサインインしていないメンバー、ビルダーシート、現在サインインしているユーザーのタイル、**アクティブなメンバー**のチャート、**要対応**（**ウェルカムメールを再送信**と**確認**付き）、直近7日間のセキュリティイベントが表示されます。メンバーは**プロファイル**、**アクセス**、**グループとデータ**のカードを持つページとして開き、**メンバーを招待**は概要とホームの初回カードから使えます。[メンバー管理](/ja/administration/access/member-management/)を参照してください。
- **Lakehouse ウィンドウに、サイドレール、テーブルの詳細、タイムトラベルが加わりました。** **クエリ**、**プロファイル**、**ロード**、**カタログ**がレールに並び、**管理**の下に**Lakehouse カタログ**、**データベースユーザー**、**コンピュート**があります。**データベースユーザー**と**コンピュート**は、Lakehouse 管理者または Lakehouse クラスターのロールを持つメンバーにのみ表示されます。**クエリ**では、SQL テキスト、ユーザー、種類、所要時間で履歴を絞り込み、**Copy SQL**でステートメントをコピーし、**Profile this query**でクエリを**プロファイル**で開けます。**カタログ**では、テーブルの列、現在のスナップショット、パーティション分割、場所、プロパティ、スナップショット履歴を確認でき、**Copy query as of this snapshot**で、その時点のテーブルを読み取る `FOR VERSION AS OF` クエリをコピーできます。[Lakehouse ウィンドウ](/ja/guides/data/lakehouse-window/)を参照してください。
- **ステップフォームでのプレビュー。** インポート: SQL、Execute: SQL、SQL抽出、エクスポート: SQL、Salesforce: オブジェクトのクエリの各ステップでは、ステップを実行せずに最大100行を表示でき、Anaplan のビューとリストの読み取りでは、生成される列と型を表示できます。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように埋め込まれますが、`{x:>9}` のような変数の書式はサポートされません。プレビューで実行できるのは標準の SQL 関数のみで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトと、エージェントベースの Execute SQL ステップでは利用できません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と[SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)を参照してください。

- **Cost to Serve と Operational Transfer Pricing のテンプレートは、Common Finance Model を基盤としています。** **Cost to Serve**からプロジェクトを開始すると、部門ごとに設定したアクティビティとドライバーに基づいて営業費用を顧客に配賦し、サービス提供コストを差し引いた後の各顧客のマージンを、総勘定元帳と結び付けて確認できます。**Operational Transfer Pricing**から開始すると、各エンティティの利益水準（売上高利益率、ネットコストプラス、または再販売価格マイナス）をポリシーの範囲に照らしてテストし、範囲外のエンティティを目標に戻すための調整額を確認できます。売上高利益率は、EBIT を検証対象当事者の売上高で割った値です。[Cost to Serve](/ja/guides/projects/cost-to-serve/)と[Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/)を参照してください。

## 変更

- **ワークスペースで Grok を使用している場合、モバイルの Weave は AI に関する通知への同意を再度求めます。** この通知から、xAI がお客様のデータをモデルの学習に使用しないという記述がなくなりました。代わりに、PlaidCloud は xAI とゼロデータ保持契約を結んでいないため、xAI がデータを保持し、xAI の標準規約が認める範囲で使用する可能性があることが記載されています。[Weave によるお客様データの利用](/ja/guides/ai-assistant/weave-data-use/)を参照してください。
- **ホワットイフウィンドウは、一度に1つの期間を読み取ります。** Allocation Split ステップの出力に期間列がある場合、ウィンドウは最新の期間で開き、**期間:** 欄で別の期間または**すべての期間**を選択できます。ドライバーに期間ごとの行があり、すべての期間をまたいで読み取るには大きすぎたステップも、1つの期間で開いて回答できるようになりました。保存したシナリオには、保存時の期間（ある場合）が保持されます。シナリオを開くと、その期間が一覧に残っている限り、ウィンドウはその期間に移動します。[期間を選択する](/ja/guides/allocations/results/driver-what-if/#期間を選択する)を参照してください。
- **PlaidCloud の Web アプリと Python クライアントライブラリは REST API を使用するようになり、JSON-RPC は非推奨になりました。** Web アプリはリクエストを REST API に送信します。`plaidcloud-rpc` 1.25.0以降では、コードを変更しなくても `SimpleRPC` の呼び出しが REST API に送られます。REST API がまだ対応していない呼び出しや、古いリリースのままのワークスペースでは、従来どおり JSON-RPC が使われます。JSON-RPC は今後のリリースで削除されるため、スクリプトとノートブックを `plaidcloud-rpc` 1.25.0以降にアップグレードし、新しい連携は REST API を使って作成してください。[コマンドライン](/ja/reference/cli/jupyter/command-line/)を参照してください。
- **ステップは、別の環境に固定しない限り、プロジェクトの接続環境に従います。** QA と本番など、プロジェクトの環境を切り替えると、すべてのステップが移動します。1つの環境にとどめる必要があるステップには、代わりに**Fixed environment**を設定できます。その場合、フォームには警告が表示され、プロジェクトの環境以外で実行するたびにログに記録が残り、プロジェクトを切り替えるときには追従しないステップが示されます。ERP 転記ステップは、常にプロジェクトの環境を使用します。プロジェクト、固定されたステップ、またはエージェントが使用している環境は削除できません。また、エージェントフォームのフィールドは**Environment this agent serves**になりました。[ステップを1つの環境に固定する](/ja/guides/projects/managing-projects/#ステップを1つの環境に固定する)を参照してください。
- **ステップフォームのレイアウトが統一されました。** タブには標準の名前と順序があり、一般、設定、ソース、列、フィルター、出力、詳細設定の順に並びます。ERP 転記フォームには、ヘッダー列と明細列があります。必須フィールドには * が付き、フォームで保存がブロックされるのは、ステップに必要な項目が欠けている場合だけです。
- **「プロジェクトをコピー」では、テーブルデータとディメンションメンバーを別々に選べるようになり、データのコピーが速くなり、非公開のコピーでは ERP書き込み承認が保持されます。** **Data to copy**で、**テーブルデータ**として**No table data**（デフォルト）、**完全**、**サンプル**のいずれかを選び、それとは別に**Copy dimension members**を選択します。これはデフォルトでオンのため、テーブルの行を含まないコピーでもディメンションにはメンバーが入った状態で作成され、短時間で完了します。**完全**と**サンプル**のコピーでは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも早く完了します。**コピー結果**には、テーブルと並んで各ディメンションの結果が一覧表示され、**Retry failed items**は失敗したテーブルとディメンションをまとめて再試行します。データ付きで作成した新しいコピーは自分だけの非公開になり、コピー元の ERP書き込み承認のうち、自分で付与できるものが保持されます。コピー元が本番で転記している場合、コピーはシミュレーションの状態で作成されるため、本番に切り替えるまで ERP には何も送られません。REST API と `project_copy` MCP ツールも `dimension_members` を受け付けます。[コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーでのERP書き込み承認](/ja/guides/projects/managing-projects/#コピーでのerp書き込み承認)を参照してください。
- **テーブルの詳細パネルに、そのテーブルを使うステップがより早く表示されます。** 別のテーブルを選択すると、前のテーブルのステップがすぐに消えます。このプロジェクトのデータを共有するほかのプロジェクトのステップは、パネル全体の表示を待たせることなく、ほかのステップより少し遅れて追加されます。[テーブルの使用箇所を確認する](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)を参照してください。
- **行の操作は、すべての一覧で同じように動作します。** 行のメニューは、行の先頭にある **⋯** ボタン、行の右クリック、またはツールバーの**アクション**メニューから開きます。メニューには常に**開く**、**詳細**、**編集**が先頭に並び、続いてその一覧固有の操作、最後に**削除**（Delete）または**削除**（Remove）が並びます。その行に当てはまらない操作は、その位置にグレーアウトで表示されます。**Enter**と**Del**は、それぞれのキーで実行される項目に表示されます。行の操作が1つだけの一覧では、**⋯** の代わりにその操作のアイコンが表示され、ダッシュボード、アプリ、ノートブックでは**開く**アイコンが再び表示されます。[行操作メニュー](/ja/guides/dashboards/using-dashboards/#行アクションメニュー)を参照してください。
- **PlaidCloud の外観が、ライトとダークの両方で新しいブルーに刷新されました。** ボタン、チェックボックス、選択された行、タブ、リンク、ワークスペースのページを一覧表示するレールには、どちらのテーマでも読み取れるコントラストを備えた、1つの PlaidCloud ブルーが使われます。アプリのタブアイコンも統一されたセットになりました。
- **新しい読み込み画面。** PlaidCloud は、ライトまたはダークのテーマに合わせた、すっきりした読み込み画面で開きます。アイドル状態から復帰する Panel または Dash のアプリは、**開始中**、**準備中**、**アプリを読み込み中**と進行状況を表示し、起動しなかった場合は、どの段階で止まったかを示して**再試行**を表示します。[Panel アプリの使用](/ja/guides/panel-apps/using/)を参照してください。
- **検証の設定がない保存済みの ERP 書き込みステップは、検証のみとして開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS の GL と AP の Post、Xero のエクスポートです。本番で実行するよう明示的に設定されたステップは、引き続き本番で実行されます。
- **長時間実行されるジョブの進行状況が、どこでも同じ方法で表示されます。**
- **ワークフローの停止、失敗、報告が実態どおりになります。** ワークフローを停止すると、そのワークフローが開始したものすべてが停止します。完了できない実行やステップは、ハングせずに理由とともに失敗し、実行ステータスは実際に実行された内容と一致します。
  - **ワークフローを停止すると、そのワークフローが開始したものすべてが停止し、完了できない実行やステップはハングせずに失敗します。** 停止すると、キューに入ったままのインポートとディメンションのステップがキャンセルされるため、ワークスペースの後続のインポートとディメンションのロードは通常どおり開始されます。また、そのワークフローのキュー内または実行中のコネクター（Singer）同期も停止します。ステップのジョブを開始できない場合、ステップはいつまでも待機せずに、理由とともに失敗します。対象となるのは、約40分以内にどのワーカーもジョブを開始しない場合、ワーカーが開始した後にいなくなった場合、ポッドが約20分間 Pending のままの場合、イメージを約5分間プルできない場合、約20分間ポッドが作成されない場合です。約30分以内にどのランナーにも取得されないコネクター同期は、同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間、そのステータスメッセージには経過した分数とともに「Waiting for a worker…」と表示され、作業が始まると消えます。マクロを停止すると、実行中のそのマクロのすべてのコピーが停止します。一方、1つのコピーを停止した場合や、応答しなくなったコピーを**Macro Concurrent**ステップが見切った場合、そのマクロを呼び出したワークフローは実行を続けます。ほかのワークフロー内でのみ実行されているマクロは、ワークフロー一覧に**実行中**と表示され、**停止**を使用できます。各ステップのステータスと開始・終了時刻は、最新の実行のものが表示されます。サーバーが失われた実行は失敗として終了し、12時間後もまだ実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」というメッセージで失敗します。[ワークフローを実行する](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
  - **再開、実行履歴、実行ステータスが、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローのステップの1つを単独で再実行した後でも、子ワークフローに残っていたものがすべて実行されます。また、1回の実行内での子ワークフローの呼び出しごとに、実行履歴のエントリが作成されます。サーバーが停止したために再起動したステップは、その旨がログに記録されます。`workflow_run_status` と REST API の実行結果は、実行をエラーなしとして報告するのではなく、失敗したものの続行されたステップを `continued_step_ids` と `continued_step_count` に一覧表示します。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時の続行](/ja/guides/workflows/continue-on-error/)を参照してください。
  - **ステップのエラーには、そのエラー自体のメッセージが表示されます。** PlaidCloud が想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードではエラーが1行で表示され、その後削除されたワークフローの実行は含まれません。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。
  - **完了しない ERP 抽出はステップを失敗させ、再開すると抽出が続行されます。** **SAP: アドホック抽出**が行数または時間の上限で一時停止した場合やそのエージェントが時間内に応答しない場合、または Salesforce、Oracle Fusion の一括エクスポート、HFM/FCCS のエクスポートジョブが、ステップが待機を終えた時点でまだ実行中の場合、ステップは失敗します。これにより、後続のステップが不完全なテーブルに対して実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は同じジョブで、停止した箇所から続行されます。[実行の制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と[Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)を参照してください。
  - **エクスポートをキャンセルすると、ウェアハウスでのクエリも停止します。** ワークフローの停止による場合を含め、エクスポートやダウンロードがキャンセルされると、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplum では、そのデータを読み取っているクエリも停止します。また、リモートデータベースへのエクスポートはソースの読み取りを停止します。いずれも、最後まで実行され続けることはなくなりました。
- **REST、Import REST、Import Postman の各ステップは、ワークスペースのアップグレード時に RESTリクエストに変換されます。** 正しく変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **セッションの期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードを開きます。** [ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは認識できないフィールドを拒否し**、無視する代わりに、エラーでそのフィールド名を示します。`workflow_upsert` は `memo` を受け付け、その別名として `description` も受け付けます。[不明なフィールドは拒否される](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2 では、Lakehouse が Parquet のエクスポートを Google Cloud Storage に直接書き込みます。** Google Cloud Storage ドキュメントアカウントへのエクスポートは、すべての行がいったん PlaidCloud を経由するのではなく、アカウント自身の認証情報を使ってアカウントのバケットに直接書き込まれます。Amazon S3 と Azure Blob Storage のアカウントへのエクスポートは、従来どおり動作します。[Export to Parquet ステップ](/ja/reference/workflow-steps/export/export-to-parquet/)を参照してください。
- **Slack、Microsoft Teams、Web Hook のステップが、メッセージを送信できなかった理由を示します。** ステップのエラーには、接続しようとしたサーバーと、Slack と Teams の場合は接続が示され、何が問題だったかが説明されます。たとえば、Slack がそのウェブフックをもう認識しない、チャンネルに投稿できない、サーバーが見つからないか60秒以内に応答しない、接続が削除された、などです。Slack または Teams のウェブフック URL は表示されません。URL を知っていれば誰でもその連携として投稿できるためです。[Notify via Slack ステップ](/ja/reference/workflow-steps/notifications/notify-via-slack/)を参照してください。
- **プロジェクトのサービスアカウントのアクセストークンは、少なくとも24時間有効です。** UDF ステップなど、プロジェクトとして実行されるワークフロージョブは、24時間有効なトークンを取得します。これより短い有効期間はワークスペースのアップグレード時に引き上げられ、より長い有効期間を設定している場合はそのまま維持されます。
- **ワークスペースの組織、所有者、リリース、バージョンは PlaidCloud が設定し、データセンターはお客様が選択します。** コントロールプレーンで作成したワークスペースは自分が所有者となり、PlaidCloud が設定するリリースチャネルに配置されます。**Data Center**は、サインアップ時に提供されるリージョンから選択します。ワークスペースを編集するとき、組織、所有者、リリース、バージョンは読み取り専用です。バージョンを変更するには**Set Version**を使用します。ワークスペースの移動、所有者やチャネルの変更、バージョンの固定は、PlaidCloud サポートに依頼してください。[ワークスペースの設定](/ja/administration/control-plane/workspace-configuration/#基本設定)を参照してください。

## 修正

- **無効なプロジェクト設定が、分かりやすいメッセージで報告されるようになりました。** 不明な環境やドキュメントアカウント、使用済みまたは予約済みのスラッグ、無効なストレージタイプや転記モードを指定すると、汎用的なサーバーエラーではなく、問題を示すメッセージが返されるようになりました。REST API では500ではなく400が返り、AI アシスタントまたは MCP では引数が無効であることを示すエラーになります。
- **REST API のディメンション値リクエストが動作するようになりました。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして処理され、無効として拒否されていました。現在は、`value_columns` の各列について1つの集計値を返します。グリッド（行フィルターと列フィルターの組み合わせごとに1つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` が用意されました。
- **時間のかかるテーブルの読み取りやファイル処理が、ほかのリクエストを妨げなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundation のファイルの登録、Excel へのエクスポート、REST または SOAP のインポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panel アプリのコードやロゴのチェックは、それぞれが完了するまで、同じサーバーが処理しているほかのすべてのリクエストを一時停止させることがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールするようになりました。** 小さい画面や低い解像度では、追加と編集のダイアログがウィンドウより高くなり、**作成**ボタンと**更新**ボタンに手が届かないことがありました。現在はフォームがスクロールし、ボタンは下部に表示されたままになります。
- **Azure Blob Storage ドキュメントアカウントにある 256 MiB を超えるファイルを、コピー、移動、名前変更できるようになりました。** これらの操作はいずれも、このサイズのファイルで失敗していました。このようなファイルを含むフォルダーの移動や名前変更も同様でした。
- **Lakehouse v2 では、テーブルの行数に、書き込んだばかりの内容が反映されます。** テーブルに書き込んだステップやインポートが書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが0行と表示されたり、インポートで0行がインポートされたと報告されたりしていました。現在は、新しい行がすべての場所から見える状態になってから行数が読み取られるため、後続のステップもその行を読み取れます。テーブルを別のブランチに切り替えたときや、ブランチをテーブルにマージしたときにも、行数と列数が更新されます。
- **Weave の空の値のチェックは、各実行を、以前の実行が実際に残した状態と比較します。** ステップの空の値は、ステップが再投入のためにテーブルを空にした直後に数えられることが多く、そのため以前の実行には空の値がなかったように見え、以前から一部が空だった列が、たった今そうなったかのように報告されていました。現在は、各実行について、ステップがテーブルを残した状態で数えます。以前に記録された件数は正しいものと区別できないため、使用されません。各ステップの空の値のチェックは履歴を最初から作り直し、5回の実行が数えられるまでは未チェックとして報告されます。行数と値の分布のチェックも、ステップの終了から2秒以上たってから別のステップが同じテーブルに行った書き込みを、そのステップの書き込みとして扱わなくなりました。[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **Data Foundation は、反転した為替レートと小数のしきい値の精度を保持します。** レートが報告通貨から別の通貨への形式で提示されているために PlaidCloud が反転させるレートは、小数点以下6桁に丸められることがあり、インドネシアルピアのようにレートが小さい通貨の金額が約1%ずれていました。反転したレートは、小数点以下12桁まで保持されるようになりました。また、`0.5` のように小数を含む `group_amber` または `group_red` のしきい値は、整数に丸められていました。次回のロードからは正確な値が使われます。[為替レート](/ja/guides/projects/data-foundation/#為替レート)を参照してください。
- **無効化されたメンバーのアラートとダイジェストが停止します。** 所有者が無効化された Panel アプリのアラートやダイジェストは、チェックと送信を続けていました。現在は、所有者が無効化されている間は一時停止し、再有効化されると再開します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
- **削除された接続を REST API で要求すると404が返るようになりました。** 削除された接続や存在しない ID を要求すると、汎用的なサーバーエラー（500）が返されていました。現在は、接続 ID を示すメッセージとともに404が返ります。
- **テンプレート形式のテーブルエクスポートが、AI アシスタントと MCP で動作するようになりました。** `table_data_export` の `templated` 形式は、テーブルを指定すると必ず失敗していました。現在は、読み取れる行に限定して、テンプレートを通じてテーブルをエクスポートします。テンプレート内では、テーブルの行はテーブル ID で参照され、ID の各 `-` は `_` と表記されます。
- **Amazon S3 と S3 互換のドキュメントアカウントで、リージョンが保持されるようになりました。** これらのアカウントを保存すると、入力した**リージョン**が破棄され、次にアカウントを開いたときにフィールドが空になっていました。現在は、リージョンが保存されます。この修正より前に保存したアカウントでは、リージョンを再入力して保存してください。[AWS S3 アカウントの追加](/ja/guides/documents/adding-accounts/add-aws-s3-account/)を参照してください。
- **AI アシスタントと JSON-RPC が、ロールで非表示になっているテーブルを使用するステップを名指ししなくなりました。** そのようなテーブルがどこで使われているかを尋ねると、そのテーブルを読み書きするステップのうちロールで表示できるものを、その設定とワークフローとともに名指ししていました。現在は、プロジェクトのテーブル参照と同様に、ステップがそのテーブルを使用していることだけを伝え、ステップ名は示しません。[ロールで非表示になる内容](/ja/guides/ai-assistant/weave-tab/#ロールで非表示になる内容)を参照してください。
- **選択したデフォルトの AI 接続が、デフォルトのまま維持されるようになりました。** AI 接続をワークスペースのデフォルトに設定すると成功したように見えましたが、実際には保存されておらず、デフォルトに依存するエージェントやステップは、最後に更新された接続を使い続けていました。現在は、選択した内容が保存されます。[LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **Weave の履歴で会話を右クリックしたときに、「スレッドを削除」の上に「名前の変更」が開かなくなりました。** **名前の変更**はチャットのタブに移動しました。タブを右クリックしてください（これまでは、タブを右クリックしても何も表示されませんでした）。[Weave タブ内のタブ](/ja/guides/ai-assistant/weave-tab/#weaveタブ内のタブ)を参照してください。
- **出力列に同じ名前を2回指定したステップは、ターゲットを空にする前に停止します。** Table Lookup ステップ、Table Extract ステップ、または結合ステップで、同じ名前の**ターゲット出力列**が2つあると、ステップはターゲットテーブルを空にしてから、分かりにくいエラーで失敗していました。現在は、ステップが先に停止して重複している列を示すメッセージを表示するため、出力列ごとに別の名前を付けられます。クエリが返す順序で列を書き込む SQL抽出ステップは、変更されていません。[Table Lookup ステップ](/ja/reference/workflow-steps/tables/table-lookup/)を参照してください。

## セキュリティ

- **Weave は、各会話の開始時に、お客様の氏名とメールアドレスを AI プロバイダーに送信しなくなりました。** これらの情報が使われることはありませんでした。
- **パスワードによるサインインには認証アプリが必要になり、パスワードの要件が強化されました。** PlaidCloud のパスワードでサインインするメンバーは、次回のサインイン時に認証アプリのセットアップを求められ、それ以降は毎回そのコードを入力します。シングルサインオン、Google、Microsoft、GitHub によるサインイン、API トークン、サービスアカウントに変更はありません。新しいパスワードは12文字以上で、ユーザー名や直近6回のパスワードと同じものは使えません。サインインの失敗が繰り返されると、アカウントは短時間ロックされます。ワークスペースですでにより厳しいルールを設定している場合は、そのルールが維持されます。[メンバー認証](/ja/administration/access/member-authentication/)を参照してください。
- **接続が指定できるのは、パブリックアドレスとプライベートネットワークのアドレスです。** 接続には、ループバック、リンクローカル、クラウドメタデータのアドレスを指定できず、エラーにはホストとその解決先のアドレスが示されます。プライベートネットワーク上のアドレスは影響を受けません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続が到達できないアドレス)を参照してください。
- **保存された接続の認証情報は、接続またはワークフローを編集できるメンバーにのみ表示されます。** REST API と MCP では、保存された接続のパスワード、トークン、キーがほかのメンバーにはマスクされます。ほかのメンバーも、接続を開いて参照することはできます。[接続の認証情報を確認できるユーザー](/ja/guides/connections/create-connection/#接続の資格情報を見られるユーザー)を参照してください。
- **アプリのビルドは、ワークスペースの Git 認証情報にアクセスできない状態で実行されます。**
- **エージェントの秘密鍵は、エージェントを編集できるメンバーにのみ表示されます。** REST API と MCP のエージェント一覧や詳細には鍵が表示されなくなり、エージェントフォームの**秘密鍵**と**RPC構成を表示**は、エージェントを編集できるメンバーにのみ表示されます。サービスアカウント、プロジェクトトークンとエージェントトークン、AI に委任されたトークンでは、鍵も RPC 構成も取得できません。実行中のエージェントは影響を受けず、公開鍵は引き続き表示されます。[エージェントの認証情報の取得](/ja/reference/cli/plaidlink/agents/#エージェントの認証情報の取得)を参照してください。
- **プロキシのダウンロードリンクの有効期間は1時間です。** **Use PlaidCloud Proxy Download**をオンにしている場合、リンクの有効期限が切れたら、もう一度ダウンロードを開いて新しいリンクを取得してください。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)を参照してください。
- **セキュリティグループへのユーザーの追加は、自分が保有する権限に従います。** メンバーをセキュリティグループに追加したり、メンバーのグループを選択したり、アーキテクトを招待したりできるのは、そのグループが付与するすべての権限を自分が保有している場合です。ワークスペース管理者には制限がありません。[セキュリティグループの管理](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)を参照してください。
- **接続の設定の変更とオン・オフの切り替えは、接続の所有者またはワークスペース管理者が行います。** REST API、JSON-RPC、AI アシスタントまたは MCP を通じて接続の設定を変更するには、その接続の所有者の1人であるか、所有者のいない接続の場合はワークスペース管理者である必要があります。接続の有効化、無効化、ロック、ロック解除には、所有者またはワークスペース管理者である必要があり、複数の接続を指定したリクエストは、そのすべてを変更できる場合にのみ適用されます。ワークスペースのデフォルトの AI 接続を選択できるのはワークスペース管理者だけです。また、メンバーが所有する接続がデフォルトになるのは、管理者が所有する接続や所有者のいない接続のいずれもデフォルトになれない場合に限られます。[接続の編集](/ja/guides/connections/create-connection/#接続を編集する)と[LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **行アクセスは、メンバーが制限付きテーブルに対して行うすべての操作に適用されます。** メンバーは、ダッシュボード、自分で書いた SQL、ロードのいずれでも、自分の権限で許可されている行のみを参照および変更できます。
  - **プロジェクトのアーキテクトは、ダッシュボードでも行が制限されたテーブルのすべての行を参照できるようになり**、Analyze で参照できる範囲と一致しました。アーキテクトのアクセスを取り消すと、ダッシュボードにもただちに反映されます。ロールの変更、メンバーやそのグループのプロジェクトからの削除、プロジェクトのアクセスタイプの変更、以前のプロジェクトバージョンの復元、セキュリティグループの削除のいずれの場合も同様です。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
  - **行アクセスで制限されたメンバーが、自分の SQL クエリを実行し、その結果をエクスポートできるようになりました。** 行アクセスが設定されたプロジェクトでは、アーキテクトではないメンバーがクエリ画面で自分のクエリを実行すると、権限で許可されている行だけが正確に返され、**アクセス権により行が制限されています**という通知とともに、CSV、Excel、JSON にエクスポートできます。以前は、これらの操作は拒否されていました。パーセント記号（`%`）を含む権限の値は、クエリ画面で該当する行を返すようになり、そのようなクエリを CSV としてダウンロードすることもできます。Snowflake や Databricks での自分の自由形式の SQL、Postgres 系ウェアハウスからの自分の SQL のエクスポート、ガバナンス対象テーブルのスナップショット時点での読み取りは、引き続き拒否されます。また、ビューがフィルターされるには、ガバナンス対象の列を元の名前のまま保持している必要があります。[行アクセスと自分で書くクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスとご自身で記述するクエリ)を参照してください。
  - **行アクセスを保存しても、ソースに存在しない付与済みの値は保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がない場合、ディメンションにそのメンバーがない場合、またはリストにその値がない場合でも、印が付いた状態でグリッドに残ります。**保存**を実行すると、そのような値ごとに、保持するか削除するかを確認します。[行アクセスのグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
  - **行が制限されたテーブルへの DataFrame の書き込み、レコードの保存、クリアでは、自分に見える行だけが変更されます。** 行アクセスによって自分の行が制限されている場合、Python クライアントで制限付きテーブルに DataFrame を書き込んだりテーブルをクリアしたりしたとき、また REST API でレコードを保存したりテーブルをクリアしたりしたときは、自分の行だけが変更されます。アクセス範囲外の行を含むロードは、何かが変更される前に拒否され、見つかった値が示されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は、テーブル全体に書き込みます。個人が行うこれらの書き込みは、どのテーブルに対するものでもセキュリティログに記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
  - **行が制限されたテーブルに対するインポート、コピー、復元、削除には、すべての行が自分に見えている必要があります。** 行アクセスによって自分の行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えやマージ、復元、削除、削除後の復旧、その他テーブル全体を置き換える操作は、テーブルのすべての行が自分に見えている場合にのみ実行されます。それ以外の場合は拒否され、何も変更されません。REST API でテーブルの行を保存した場合は、ほかのロードと同様に、自分の行だけが変更されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は影響を受けません。これらの操作もセキュリティログに記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントの所有者だけになりました。** ドキュメントアカウントを以前のバージョンに復元する操作、バージョンの保持と解除、バックアップの作成には、アカウントの所有者の1人である必要があり、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、そのアカウントへのアクセス権が必要です。
- **`query_run` は読み取り専用のステートメントを実行します。** AI アシスタントと MCP クライアントが使用する `query_run` ツールは、1つの SELECT または WITH ステートメント、その EXPLAIN、または SHOW を受け付け、それ以外のステートメントは実行しません。データを変更するには `query_transform` を使用してください。MCP のテーブルエクスポートの SQL にも同じルールが適用されます。REST API と JSON-RPC API では、プロジェクトのデータを変更できないメンバーに対して、クエリの実行、列ファセットの作成、クエリの CSV としてのダウンロード、リモートデータベースへのクエリのエクスポート、独自のクエリによるテーブルデータのエクスポートにもこのルールが適用され、拒否されたクエリには403が返ります。Explain Analyze は計測のためにクエリを実行するため、クエリログと Lakehouse では読み取りを行うクエリのみを受け付けます。また、行アクセスが設定されたプロジェクトでは、クエリログから Explain Analyze を実行できるのはプロジェクトのアーキテクトだけです。
- **テーブルエクスプローラーのフィルター、PlaidCloud に送信されるクエリ、Table Extract ステップの動的列を見つけるクエリでは、SQL を実行する関数やサーバーのファイルを読み取る関数を呼び出せなくなりました。** `query_to_xml`、`dblink`、`pg_read_file` などの関数の呼び出しは拒否され、エラーにはその関数名が示されます。同じ場所で、`.op()` は演算子だけを受け付け、`literal_column` では Unicode エスケープを使った引用符を使用できません。動的列のクエリには、ステップのフィルターと、ソースから列名を読み取る式が含まれるため、ルールに違反するクエリは、実行時にステップを失敗させます。[拒否される関数と演算子](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#拒否される関数と演算子)を参照してください。
- **Data Foundation の配賦ルールでは、一重引用符、バックスラッシュ、改行を含む部門名や統計名が拒否されます。** 名前は配賦ステップのフィルターに書き込まれるため、**保存**とステージ1のプレビューでその名前が拒否され、値が示されます。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。
