## 追加

- **ステップフォームでのプレビュー。** Import: SQL、Execute: SQL、Extract: SQL、Export: SQL、Salesforce Query の各ステップでは、ステップを実行せずに最大100行を表示でき、Anaplanのビューとリストの読み取りでは、生成される列と型を表示できます。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように埋め込まれますが、`{x:>9}` のような変数の書式指定はサポートされていません。プレビューで実行できるのは標準のSQL関数のみで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトや、エージェントベースの Execute SQL ステップでは利用できません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と[SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)を参照してください。
- **利用状況レポートで変化を確認し、グループに絞り込み、ワークフローに連携できます**。**概要**に、前の期間と比べた推移の矢印と、非アクティブなメンバーや誰も開かなかったダッシュボードとアプリを示す**ハイライト**の一覧が追加されました。**グループ**は、**概要**、**内容**、非アクティブの一覧を1つのセキュリティグループのメンバーに限定します。日付範囲には**前月**と**今月**が加わり、すべてのタブで共有され、アカウントに保存されます。すべての数値に説明が付き、テーブルでは**メンバー**や**エリア**のようなわかりやすい名前が使われ、Enterキーで行を開けるようになり、読み込み中とエラーの表示も改善され、**ファネル**の最後のステップには完了したメンバーの数が表示されます。新しい**Get Workspace Usage**ステップは、日別または月別の利用状況の合計を、メンバー名なしでスケジュールに従ってテーブルに書き込みます。**Get Workspace Members**と同様に、実行のたびにセキュリティログに記録されます。[利用状況レポート](/ja/administration/access/usage-reports/)と[Get Workspace Usageステップ](/ja/reference/workflow-steps/general/get-workspace-usage/)を参照してください。
- **AIアシスタントがテーブルの公開を解除し、プロジェクトのデフォルトのダッシュボード対象者を設定できます。** `publish_manage` は、テーブルとその公開済みビュー、およびどのチャートも使用していないダッシュボードデータセットの公開を解除します。チャートがまだ使用しているデータセットは残り、公開済みビューの上にレポートビューが構築されている場合はそのビューとデータセットも残りますが、テーブルの公開は解除されます。`project_upsert` は `dashboard_default_audience`（プロジェクトの新しいダッシュボードの共有先となるグループ）を設定し、`[]` でクリアします。[公開の解除](/ja/guides/data/publish/#ai-アシスタントまたは-mcp-で公開を取り消す)と[AIアシスタントまたはMCPからデフォルトの対象者を設定する](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ai-アシスタントまたは-mcp-でデフォルトの対象ユーザーを設定する)を参照してください。

- **モバイルのWeaveでは、音声入力がワンタップで使えます。** マイクをタップして質問を話すと、話し終えた時点でWeaveが送信します。早めに終了するにはもう一度マイクをタップします。何も聞き取れない場合は自動的にオフになります。話している途中で**Weave**タブを離れたり、アプリをバックグラウンドにしたりすると、話した内容は送信されずに質問ボックスに残るため、確認できます。実行、一時停止、停止、再開の確認画面では、誤った二重タップは無視されます。アプリのバージョン1.3.0以降が必要です。[音声を使用する](/ja/guides/mobile-app/weave-on-mobile/#音声を使う)を参照してください。

## 変更

- **ステップフォームが共通のレイアウトになりました。** タブは標準の名前で標準の順序に並びます。General、Settings、Source、Columns、Filters、Output、Advanced の順で、ERP転記フォームにはヘッダー列と明細列が加わります。必須フィールドには * が付き、フォームはステップに必要なものについてのみ保存をブロックします。
- **プロジェクトのコピーでは、テーブルデータとディメンションメンバーを個別に選択でき、データのコピーが高速になり、自分専用のコピーのERP書き込み承認が維持されます。** **Data to copy** で、**Table data**（**No table data**（デフォルト）、**完全**、または**サンプル**）を選択し、これとは別に **Copy dimension members** を選択します。後者はデフォルトでオンのため、テーブルの行を含まないコピーでも、ディメンションにはメンバーが入った状態で作成され、短時間で完了します。**完全**と**サンプル**のコピーでは複数のテーブルを同時にコピーするため、テーブルが多いプロジェクトでも短時間で完了します。**コピー結果**には、テーブルと並んで各ディメンションの結果が一覧表示され、**Retry failed items** は失敗したテーブルとディメンションをまとめて再試行します。データを含めて作成した新しいコピーは自分専用となり、自分で付与できるソースのERP書き込み承認が引き継がれます。ソースがLiveで転記する場合、コピーはSimulateの状態で作成されるため、Liveに切り替えるまでERPには何も届きません。REST APIと `project_copy` MCPツールでも `dimension_members` を指定できます。[コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーにおけるERP書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認)を参照してください。
- **行のアクションメニュー（⋯）が、すべてのグリッド行の左端に表示されます。**
- **検証設定のない保存済みのERP書き込みステップは、検証のみの状態で開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL と AP Post、Xero のエクスポートです。明示的にライブで実行する設定になっているステップは、ライブのままです。
- **長時間実行されるジョブの進行状況が、どこでも同じ方法で表示されます。**
- **ワークフローを停止すると、そのワークフローが開始したものがすべて停止し、開始できないステップはハングせずに失敗します。** 停止すると、キューに入っていたインポートおよびディメンションステップがキャンセルされるため、ワークスペース内の後続のインポートやディメンションのロードは通常どおり開始されます。また、ワークフローのキューに入っているまたは実行中のコネクター（Singer）の同期も停止されます。ステップのジョブを開始できない場合、ステップは永久に待ち続けるのではなく、理由を示して失敗します。約40分以内にワーカーが開始しない場合、ワーカーが開始した後に失われた場合、Podが約20分間Pendingのままの場合、イメージを約5分間プルできない場合、または約20分間Podが作成されない場合です。約30分以内にランナーが取得しないコネクターの同期は、その同期を示すメッセージとともに失敗します。ステップがワーカーを待っている間、ステータスメッセージには経過した分数とともに「ワーカーを待機中…」と表示され、作業が開始されると消えます。[ワークフローの実行](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
- **ワークスペースのアップグレード時に、REST、Import REST、Import Postman の各ステップがRESTリクエストステップに変換されます。** きれいに変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **プロジェクトのアーキテクトは、ダッシュボードで行制限付きテーブルのすべての行を閲覧できます。** Analyzeでの表示と同じです。アーキテクトのアクセス権の取り消しは、ダッシュボードですぐに反映されます。これは、ロールの変更、メンバーまたはそのグループのプロジェクトからの削除、プロジェクトのアクセスタイプの変更、以前のプロジェクトバージョンの復元、セキュリティグループの削除のいずれの場合でも同様です。元アーキテクトは、行制限付きデータのすべての行を閲覧できなくなります。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
- **セッションの有効期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードへ移動します。** [ダッシュボードを使用する](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCPツールは、認識できないフィールドを無視せずに拒否し、エラーにそのフィールド名を示します。** `workflow_upsert` は `memo` を受け付け、その別名として `description` も受け付けます。[不明なフィールドは拒否されます](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2では、LakehouseがParquetエクスポートをGoogle Cloud Storageに直接書き込みます。** Google Cloud Storageのドキュメントアカウントへのエクスポートは、すべての行をいったんPlaidCloud経由で渡すのではなく、アカウント自身の認証情報を使って、アカウントのバケットに直接書き込まれます。Amazon S3およびAzure Blob Storageアカウントへのエクスポートは、従来どおり動作します。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/) ステップを参照してください。
- **Slack、Microsoft Teams、Web Hook の各ステップは、メッセージが送信されなかった理由を示します。** ステップのエラーには、接続を試みたサーバーと（SlackとTeamsの場合は）接続が示され、何が問題だったかが説明されます。たとえば、Slackがwebhookを認識しなくなった、チャンネルに投稿できない、サーバーが見つからないか60秒以内に応答しない、接続が削除されている、などです。SlackまたはTeamsのwebhook URLは、それを知っていれば誰でも連携として投稿できてしまうため、表示されることはありません。[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/) ステップを参照してください。

## 修正

- **無効なプロジェクト設定が、わかりやすいメッセージで報告されます。** 不明な環境やドキュメントアカウント、すでに使用されている、または予約されているスラッグ、無効なストレージタイプや転記モードの場合、汎用的なサーバーエラーではなく、問題を示すメッセージが返されるようになりました。REST APIでは500ではなく400、AIアシスタントまたはMCPでは無効な引数のエラーになります。
- **REST APIのディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして処理され、無効として拒否されていました。現在は `value_columns` の各列について集計された値を1つ返します。また、行フィルターと列フィルターの組み合わせごとに1つの値を返すグリッドには、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **テーブルの読み取りやファイル処理が遅い場合でも、他のリクエストが止まらなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundationファイルの登録、Excelへのエクスポート、RESTまたはSOAPインポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panelアプリのコードやロゴの確認は、それぞれ完了するまで、同じサーバーが処理している他のすべてのリクエストを停止させることがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 画面が小さい場合や解像度が低い場合、追加および編集ダイアログがウィンドウより縦に長くなり、**作成**ボタンと**更新**ボタンに手が届かないことがありました。現在はフォームがスクロールし、ボタンは下部に固定されます。
- **Azure Blob Storageドキュメントアカウントの256 MiBを超えるファイルをコピー、移動、名前変更できます。** これらの操作は、そのサイズのファイルでは失敗していました。そのようなファイルを含むフォルダーの移動や名前変更も同様でした。
- **Lakehouse v2では、テーブルの行数に直前に書き込まれた内容が反映されます。** テーブルに書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが0行と表示されたり、インポートが0行のインポートと報告されたりしていました。現在は、新しい行がすべての場所から参照できるようになってから行数を読み取るため、後続のステップもそれらを読み取れます。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりした場合も、行数と列数が更新されます。
- **Weaveの空の値のチェックは、各実行を、以前の実行が実際に残した状態と比較します。** ステップの空の値は、ステップがテーブルを空にして再入力した直後にカウントされることが多く、そのため以前の実行には空の値がないように見え、常に一部が空だった列が、ちょうど空になったかのように報告されていました。現在は、ステップがテーブルを残した状態で各実行がカウントされます。以前に記録されたカウントは正しいものと区別できないため使用せず、各ステップの空の値のチェックは履歴を最初からやり直し、5回の実行がカウントされるまでは未チェックとして報告されます。行数と値の分布のチェックでも、ステップが完了してから2秒を超えた後に別のステップが同じテーブルに行った書き込みを、そのステップの実績として扱わなくなりました。[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **削除された接続をREST APIに要求すると404が返されます。** 削除された接続や存在しないIDを要求すると、汎用的なサーバーエラー（500）が返されていました。現在は、接続IDを示すメッセージとともに404が返されます。

## セキュリティ

- **アカウントの以前のバージョンを復元できるのは、アカウントの所有者のみです。** ドキュメントアカウントを以前のバージョンに復元する、バージョンを保留または解放する、バックアップを取る、といった操作には、アカウントの所有者の1人であることが必要になり、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、アカウントへのアクセス権が必要です。
