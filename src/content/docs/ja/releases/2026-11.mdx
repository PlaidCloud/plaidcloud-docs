## 追加

- **PlaidXLでExcel上のレポート作成、ドリル、数値の説明、計画ができます。** **PlaidCloud**リボンタブは**接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有**にグループ化されています。よく使うコマンドは **PlaidXL** 右クリックメニューと **PlaidXL Cell** タブにもあり、主なコマンドにはキーボードショートカットがあって変更もできます。サインイン前に実行したコマンドはサインイン画面を開き、サインイン後に一度だけ実行されます。Officeで Microsoft Entra の職場アカウントを使うと、PlaidXLがワークスペースを自動で見つけます。詳しくは [PlaidXLリファレンス](/ja/reference/cli/plaidxl/) をご覧ください。
  - **数回のクリックでレポートを作成できます。** **レポート**タブは、テーブルから動的なレポートを配置します。1つのディメンションを行方向に、別のディメンションを列方向にドリルダウンし、交差するセルごとに `CELL` 値を置きます。**Build my first report** は、お使いのデータからサンプルを作成します。ドリルすると、レポートは行全体と列全体を挿入または削除します。入力した値、メモ、書式は元の行に付いたまま残ります。詳しくは [レポートの作成](/ja/reference/cli/plaidxl/build-a-report/) をご覧ください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only** は、ノード、ディメンションの見出し、レポートの値から、ノードを動的な `DRILL` 数式に変えて編集します。**Custom drill** は挿入前に行をプレビューします。メンバーピッカーは、メンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりします。`DRILL` は、除外または展開するノードを受け取り、行方向にも実行できます。詳しくは [ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/) をご覧ください。
  - **数値を説明できます。** **Explain this number** は、値の計算内容、PlaidCloudの現在の値と一致しているか、元になっているテーブルとワークフローステップを表示します。**Show detail rows** は、値の元になった行を専用のシートに表示し、合計が一致するかを確認します。
  - **Excelでガバナンスされたメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるとおりにビジネスメトリックを返します。**Metric...** コマンドは、プロジェクトのメトリックを現在の値とともに一覧表示します。詳しくは [メトリック](/ja/reference/cli/plaidxl/functions/#メトリック) をご覧ください。
  - **レポートに入力して計画できます。** `CELL` 値に数値を上書き入力すると、PlaidCloudに書き込まれます。比例配分、均等配分、別のメンバーの形に合わせた配分、金額または割合による調整に対応し、保留したセルはそのまま残ります。平均、中央値、最小値、最大値、標準偏差、分散のセルにも入力できます。**Undo last write** は、入力した値と保存を新しいものから順に取り消します。詳しくは [PlaidCloudに値を入力する](/ja/reference/cli/plaidxl/write-values/) をご覧ください。
  - **必要な部分だけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新でき、各テーブルの進行状況と**キャンセル**はタスクペインに表示されます。PlaidXLの数式だけを再計算することもできます。取得したテーブルはデータ型に応じて書式設定されたExcelテーブルとして届き、更新しても独自の列と表示形式が保たれ、元の場所で更新されます。テーブルを再取得しても更新リストに重複して追加されず、**Stop refreshing** で1つずつリストから外せます。ディメンションもテーブルと一緒に更新されます。詳しくは [すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する) をご覧ください。
  - **保存は即座に書き込まれ、元に戻せます。** **Save to PlaidCloud** は確認なしで書き込み、実行した内容を表示し、**元に戻す**を提供します。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーの場合、置き換えられるのはその行だけなので、他のユーザーの行は保たれます。詳しくは [テーブルをPlaidCloudに保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する) をご覧ください。
  - **Excelで Weave に質問できます。** **Weave** タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼するか、**Ask Weave about this cell** を選びます。Weaveはあなたの権限でPlaidCloudを読み取り、変更するのはブックだけです。入力済みの内容を置き換える前には確認し、各変更はペインを再読み込みするまで元に戻せます。詳しくは [Excelで Weave に質問する](/ja/reference/cli/plaidxl/weave/) をご覧ください。
  - **1つのシートまたはブック全体の値だけのコピーを共有できます。** **Convert to values** は、ブック全体、1つのシート、または元に戻せない値だけに変換します。**Restore PlaidXL formulas** は、シート名を変更した後でも使えます。
- **ステップフォームでプレビューできます。** インポート: SQL、Execute: SQL、エクスポート: SQL、Extract: SQL、Salesforce: オブジェクトのクエリでは、ステップを実行せずに最大100行を表示できます。Anaplanのビューとリストの読み取りでは、生成される列と型が表示されます。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように埋め込まれますが、`{x:>9}` のような変数の書式指定には対応していません。プレビューで実行できるのは標準のSQL関数だけで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトと、エージェントを使うExecute SQLステップでは利用できません。詳しくは [SQLのインポート](/ja/reference/workflow-steps/import/import-sql/) と [SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/) をご覧ください。
- **利用状況レポートで変化を確認し、グループに絞り込み、ワークフローに取り込めます。** **概要**には、前の期間と比較した傾向の矢印と、非アクティブなメンバーや、誰も開いていないダッシュボードとアプリを示す **Highlights** リストが加わりました。**グループ**を選ぶと、**概要**、**内容**、非アクティブなリストが1つのセキュリティグループのメンバーに限定されます。日付範囲には **Previous month** と **This month** が加わり、すべてのタブで共有され、アカウントに記憶されます。すべての数値に説明が付き、テーブルには **メンバー** や **エリア** などわかりやすい名前が使われ、Enterキーで行を開け、読み込み中とエラーの表示も明確になり、最後の**ファネル**ステップには完了したメンバーの数が表示されます。新しい Get Workspace Usage ステップは、日次または月次の利用状況の合計を、メンバー名なしでスケジュールに従ってテーブルに書き込みます。Get Workspace Members ステップと同様に、各実行は**セキュリティログ**に記録されます。詳しくは [利用状況レポート](/ja/administration/access/usage-reports/) と [Get Workspace Usage](/ja/reference/workflow-steps/general/get-workspace-usage/) をご覧ください。
- **AIアシスタントはテーブルの公開を解除し、プロジェクトのデフォルトのダッシュボード対象グループを設定できます。** `publish_manage` は、テーブルとその公開ビュー、およびどのチャートも使っていないダッシュボードデータセットの公開を解除します。チャートがまだ使っているデータセットは残り、レポートビューが公開ビューを基に作られている場合はそのビューとデータセットも残りますが、テーブルの公開は解除されます。`project_upsert` は `dashboard_default_audience`、つまりプロジェクトの新しいダッシュボードが共有されるグループを設定し、`[]` で消去します。詳しくは [公開解除](/ja/guides/data/publish/#ai-アシスタントまたは-mcp-で公開を取り消す) と [AIアシスタントまたはMCPでデフォルトの対象グループを設定する](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ai-アシスタントまたは-mcp-でデフォルトの対象ユーザーを設定する) をご覧ください。

- **Gitアプリがリポジトリを一覧表示し、できる操作を示します。** アプリ一覧の **Git** には、ワークスペースのリポジトリが説明、デフォルトブランチ、最終更新とともに表示されます。**Copy clone URL** にはアクセストークンでクローンする方法の短いヒントが付き、**View all in Git** もあります。アクセスレベルは**読み取り**、**コントリビューター**（アプリのコードを `apps` にプッシュ）、**管理者**（`udfs` を含むすべてにプッシュ）で、読み取りメンバーには、問い合わせ先としてワークスペースの管理者が最大3人表示されます。新しい **Git Contributors** グループはコントリビューターのアクセスを付与し、デフォルトグループにできるため、新しいメンバーは自動的にアクセスを得ます。**Git Administration** は管理者のアクセスを付与します。メンバーの **Git** タブには、Gitのユーザー名、アクセスレベル、それを付与しているグループが表示されます。アプリのウィンドウには**リポジトリ**セクションが表示され、UDFには **Open** があり、Gitにはワークスペースへの **← Back to** リンクがあります。詳しくは [PlaidCloud Git](/ja/guides/git/#gitを開く) をご覧ください。
- **モバイルのWeaveで、音声入力がワンタップになりました。** マイクをタップして質問を話すと、話し終えた時点でWeaveが送信します。もう一度マイクをタップすると途中で止められ、何も聞こえないと自動的にオフになります。話している途中で **Weave** タブを離れたりアプリをバックグラウンドにしたりした場合、話した内容は送信されないまま質問ボックスに残るので、確認できます。実行、一時停止、停止、再開は、確認画面での誤った二重タップを無視します。アプリのバージョン1.3.0以降が必要です。詳しくは [音声を使う](/ja/guides/mobile-app/weave-on-mobile/#音声を使う) をご覧ください。

## 変更

- **ステップフォームのレイアウトが統一されました。** タブは標準の名前と標準の順序になりました。一般、設定、**ソース**、列、フィルター、出力、詳細設定の順で、ERP転記フォームにはヘッダー列と明細列が加わります。必須フィールドには * が付き、フォームが保存をブロックするのは、そのステップに必要な項目だけです。
- **プロジェクトをコピーでは、テーブルデータとディメンションメンバーを個別に選べます。コピーが速くなり、非公開コピーではERP書き込み承認も引き継がれます。** **Data to copy** で、**テーブルデータ**（**テーブルデータなし**（デフォルト）、**完全**、**サンプル**）を選び、それとは別に **Copy dimension members**（デフォルトでオン）を選びます。そのため、テーブルの行なしでコピーしても、ディメンションにはメンバーが入った状態で届き、コピーもすぐに終わります。**完全**と**サンプル**のコピーは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも速く終わります。**コピー結果**には、テーブルとあわせて各ディメンションの結果が一覧表示され、**Retry failed items** は失敗したテーブルとディメンションをまとめて再試行します。データ付きで新しく作成したコピーは自分専用の非公開になり、コピー元のERP書き込み承認のうち、自分で付与できるものが引き継がれます。コピー元が Live で転記する場合、コピーは Simulate で届くため、Live に切り替えるまでERPには何も届きません。REST APIと `project_copy` MCPツールも `dimension_members` を受け取ります。詳しくは [コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択) と [コピーに含まれるERP書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認) をご覧ください。
- **行のアクションメニュー（⋯）が、すべてのグリッド行の左端に配置されました。**
- **アプリのタブアイコンが、ライトモードとダークモードの両方で統一されたセットになりました。**
- **検証設定のない保存済みのERP書き込みステップは、検証のみの設定で開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL と AP Post、Xeroのエクスポートです。明示的に Live で実行する設定のステップは Live のままです。
- **長時間実行されるジョブの進行状況が、どこでも同じ方法で表示されます。**
- **ワークフローを停止すると、そのワークフローが開始したものがすべて停止します。完了できない実行やステップは、待ち続けずに失敗します。** 停止すると、まだキューに入っていたインポートとディメンションのステップがキャンセルされるため、ワークスペース内の後続のインポートとディメンションのロードは通常どおり開始されます。ワークフローのキュー内または実行中のコネクタ（Singer）の同期も停止します。ステップのジョブを開始できない場合、ステップは待ち続けずに理由を示して失敗します。理由は、約40分以内にどのワーカーも開始しなかった、ワーカーが開始した後に消えた、ポッドが約20分間 Pending のままである、イメージを約5分間取得できない、約20分間ポッドが作成されない、のいずれかです。どのランナーも約30分以内に拾わなかったコネクタの同期は、その同期を示すメッセージとともに失敗します。ステップがワーカーを待っている間は、ステータスメッセージに「ワーカーを待機しています…」と経過した分数が表示され、作業が始まると消えます。マクロを停止すると、実行中のマクロのコピーがすべて停止します。他のワークフローの中でだけ実行されているマクロは、ワークフロー一覧で**実行中**と表示され、**停止**を利用でき、各ステップのステータス、開始時刻、終了時刻は最新の実行から表示されます。サーバーが失われた実行は失敗として終了し、12時間を過ぎても実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」で失敗します。詳しくは [ワークフローの実行](/ja/guides/workflows/run-a-workflow/#開始されないステップ) をご覧ください。
- **再開、実行履歴、実行ステータスが、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローの1つのステップだけを単独で再実行した後でも、子ワークフローに残っていたものがすべて実行されます。1回の実行内での子ワークフローの呼び出しごとに、実行履歴のエントリが作られます。サーバーが停止したために再開したステップは、そのことをログに記録します。`workflow_run_status` とREST APIの実行結果は、失敗しても続行したステップを `continued_step_ids` と `continued_step_count` に一覧表示し、実行を問題なしとは報告しません。詳しくは [一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開) と [エラー時も続行](/ja/guides/workflows/continue-on-error/) をご覧ください。
- **ステップのエラーに、そのエラー自身のメッセージが表示されます。** PlaidCloudが想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードは、エラーを1行で表示し、すでに削除されたワークフローの実行は表示しません。詳しくは [ステップエラーの管理](/ja/guides/workflows/managing-step-errors/) をご覧ください。
- **ERP抽出が完了しない場合はそのステップが失敗し、再開すると続行されます。** **SAP: アドホック抽出** が行数または時間の上限で一時停止した場合やエージェントが時間内に応答しない場合、またはSalesforce、Oracle Fusionのバルク、HFM/FCCSのエクスポートジョブがステップの待機終了時点でまだ実行中の場合、ステップは失敗するため、後続のステップが不完全なテーブルに対して実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は同じジョブで停止した場所から続行されます。詳しくは [実行の上限](/ja/guides/connections/sap-adhoc-extract/#実行の制限) と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合) をご覧ください。
- **REST、Import REST、Import Postmanの各ステップは、ワークスペースのアップグレード時に RESTリクエスト に変換されます。** きれいに変換できないステップは、そのまま残ります。詳しくは [RESTリクエストステップ](/ja/guides/workflows/rest-request-step/) をご覧ください。
- **プロジェクトのアーキテクトは、ダッシュボードで行制限付きテーブルのすべての行を表示できます。** Analyzeで表示される内容と同じです。アーキテクトのアクセス権を取り消すと、ダッシュボードにも即座に反映されます。ユーザーのロールを変更した場合、ユーザーまたはそのグループをプロジェクトから削除した場合、プロジェクトのアクセスタイプを変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれも同様です。元アーキテクトには、行制限付きデータのすべての行は表示されなくなります。詳しくは [行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理) をご覧ください。
- **セッションの有効期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードへ移動します。** 詳しくは [ダッシュボードを使う](/ja/guides/dashboards/using-dashboards/) をご覧ください。
- **MCPツールは、認識できないフィールドを無視せず、拒否してエラーで名前を示します。** `workflow_upsert` は `memo` を受け取り、その別名として `description` も受け付けます。詳しくは [不明なフィールドは拒否される](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される) をご覧ください。
- **Lakehouse v2では、LakehouseがParquetエクスポートをGoogle Cloud Storageに直接書き込みます。** Google Cloud Storageのドキュメントアカウントへのエクスポートは、すべての行がPlaidCloudを経由する代わりに、アカウント自身の認証情報を使ってアカウントのバケットに直接書き込まれます。Amazon S3とAzure Blob Storageのアカウントへのエクスポートは、これまでどおり動作します。詳しくは [Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/) ステップをご覧ください。
- **Slack、Microsoft Teams、Web Hookの各ステップが、メッセージが送信されなかった理由を示します。** ステップのエラーには、接続を試みたサーバーが示され、SlackとTeamsの場合は接続も示され、何が問題だったかが説明されます。たとえば、Slackがwebhookを認識しなくなった、チャンネルに投稿できない、サーバーが見つからないか60秒以内に応答しない、接続が削除された、などです。SlackまたはTeamsのwebhook URLは、知っている人なら誰でもあなたの連携として投稿できてしまうため、表示されることはありません。詳しくは [Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/) ステップをご覧ください。

## 修正

- **無効なプロジェクト設定が、わかりやすいメッセージで報告されます。** 不明な環境やドキュメントアカウント、すでに使われているか予約されているスラッグ、無効なストレージタイプや転記モードは、一般的なサーバーエラーではなく、問題を示すメッセージを返すようになりました。REST APIでは500ではなく400になり、AIアシスタントまたはMCPでは無効な引数のエラーになります。
- **REST APIのディメンション値のリクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドのリクエストとして処理され、無効として拒否されていました。現在は `value_columns` の列ごとに集計値を1つ返します。グリッド、つまり行フィルターと列フィルターの組み合わせごとに1つの値を返す処理には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **テーブルの読み取りやファイル処理が遅くても、他のリクエストを止めなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundationのファイルの登録、Excelへのエクスポート、RESTまたはSOAPのインポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panelアプリのコードやロゴの確認は、それぞれが終わるまで、同じサーバーが処理している他のすべてのリクエストを一時停止させることがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 小さい画面や低い解像度では、追加と編集のダイアログがウィンドウより高くなり、**作成**と**更新**のボタンに手が届かないことがありました。現在はフォームがスクロールし、ボタンは下部に固定されます。
- **Azure Blob Storageのドキュメントアカウントで、256 MiBを超えるファイルをコピー、移動、名前変更できます。** これまでは、そのサイズのファイルでこれらの操作がすべて失敗し、そのようなファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2では、テーブルの行数に書き込んだ直後の内容が反映されます。** テーブルに書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが0行と表示されたり、インポートが0行のインポートと報告したりしていました。現在は、新しい行がどこからでも見えるようになってから行数を読み取るため、後続のステップもそれらの行を読み取れます。テーブルを別のブランチに切り替えた場合や、ブランチをテーブルにマージした場合も、行数と列数が更新されます。
- **Weaveの空の値のチェックは、以前の実行が実際に残した内容と比較します。** ステップの空の値は、ステップが再入力のためにテーブルを空にした直後に数えられることが多く、以前の実行には空の値がないように見えたり、以前から一部が空だった列が最近そうなったかのように報告されたりしていました。現在は、ステップがテーブルを残した状態で各実行が数えられます。以前に記録されたカウントは正常なものと区別できないため使用されません。各ステップの空の値のチェックは履歴を最初から始め、5回の実行が数えられるまで未チェックとして報告されます。行数と値の分布のチェックも、ステップが終了してから2秒より後に別のステップが同じテーブルに行った書き込みを、そのステップの書き込みとして扱わなくなりました。詳しくは [Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/) をご覧ください。
- **削除された接続をREST APIで要求すると404が返ります。** 削除された接続や存在しないIDを要求すると、一般的なサーバーエラー（500）が返っていました。現在は、接続IDを示すメッセージとともに404を返します。

## セキュリティ

- **行アクセスを保存しても、ソースにもうない付与済みの値が保持されます。** セキュリティグループに付与された値は、テーブルにその値の行がなくなった場合、ディメンションからメンバーがなくなった場合、リストにその値がなくなった場合に、次の保存時に付与から外れていました。その結果、何もチェックされていないグループは **Everyone else** にフォールバックし、すべての行が対象になることがありました。現在は、その値がマークされたままグリッドに残り、**保存**時に保持するか削除するかを確認します。詳しくは [行アクセスグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド) をご覧ください。
- **ドキュメントアカウントの以前のバージョンを復元できるのは、そのアカウントのオーナーだけです。** ドキュメントアカウントを以前のバージョンに復元する、バージョンを保持または解放する、バックアップを取るには、アカウントのオーナーである必要があり、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、そのアカウントへのアクセス権が必要です。
- **データの読み取りだけを行うはずのクエリが、データを変更できなくなりました。** AIアシスタントとMCPクライアントが使う `query_run` ツールは、データを読み取る文（1つのSELECTまたはWITH文、そのEXPLAIN、またはSHOW）だけを実行し、それ以外は実行せずに拒否します。データを変更するには `query_transform` を使います。MCPのテーブルエクスポートのSQLにも同じルールが適用されます。REST APIとJSON-RPC APIでは、プロジェクトのデータを変更できないメンバーについて、クエリの実行、列ファセットの作成、クエリのCSVとしてのダウンロード、クエリのリモートデータベースへのエクスポート、独自のクエリによるテーブルデータのエクスポートにも適用され、拒否されたクエリは403を返します。Explain Analyzeは測定のためにクエリを実行するため、クエリログとLakehouseでは、読み取りのクエリだけを受け付けるようになりました。行アクセスのあるプロジェクトでは、クエリログから実行できるのはプロジェクトのアーキテクトだけです。
