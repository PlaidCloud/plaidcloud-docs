## 追加

- **コントロールプレーンの Trust Center で、セキュリティ担当チームが PlaidCloud のセキュリティドキュメントを入手できます。** 管理者とセキュリティのユーザーは、組織の**Trust Center**を開き、サブプロセッサー一覧や DPA などの公開ドキュメントをすぐにダウンロードできます。また、セキュリティドキュメント用の NDA に組織として一度署名すると、SOC 2 Type II レポートなどの制限付きドキュメントのロックが解除されます。ほかの管理者とセキュリティのユーザーには、署名者と署名日時が表示されます。契約にすでに NDA が含まれている組織は、NDA を締結済みとして登録してもらうことで、署名しなくてもドキュメントのロックが解除されます。制限付きドキュメントのダウンロードには透かしが入って記録され、NDA の新しいバージョンには改めて同意が必要です。管理者とセキュリティのユーザーは、組織ごとに、新規または更新されたドキュメントと NDA の新しいバージョンをまとめた毎日のメールを受け取るよう選択することもできます。このメールにドキュメント本体が含まれることはありません。[Trust Center](/ja/administration/control-plane/trust-center/)を参照してください。
- **PlaidXL で、Excel 上でレポートの作成、ドリル、数値の説明、計画ができます。** **PlaidCloud**リボンタブは**接続**、**挿入**、**更新**、**ドリル**、**書き込み**、**共有**にグループ化されています。よく使うコマンドは**PlaidXL**右クリックメニューと**PlaidXL Cell**タブにもあり、主なコマンドには変更可能なキーボードショートカットがあります。ショートカットは、フィールドに入力している間は動作しません。コマンドが失敗すると、どのコマンドがなぜ失敗したかが表示されます。サインイン前に実行したコマンドはサインイン画面を開き、サインインが完了すると実行されます。サインインは1つのワークスペースに対して有効なため、ワークスペースを切り替えると新しいワークスペースへのサインインを求められます（元のワークスペースに戻すときは求められません）。Office で Microsoft Entra の職場アカウントを使用している場合は、PlaidXL がワークスペースを自動的に見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます。** **レポート**タブは、テーブルからライブレポートを配置します。1つのディメンションを行方向にドリルダウンし、別のディメンションを列方向に展開して、各交点に `CELL` 値を配置します。**Build my first report**は、お使いのデータからサンプルを作成します。ドリルすると、レポートは行全体と列全体を挿入または削除し、入力した値、メモ、書式は元の行に付いたまま残ります。[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only**は、ノード、ディメンション見出し、レポートの値から、ノードをライブの `DRILL` 数式に変換し、その数式を自動的に編集します。**Custom drill**は挿入前に行をプレビューし、メンバーピッカーはメンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりします。`DRILL` には除外または展開するノードを指定でき、1行に横方向に展開することもできます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明できます。** **Explain this number**は、値が何を計算しているか、現在の PlaidCloud と一致しているか、元になっているテーブルとワークフローステップを表示します。**Show detail rows**は、値の元になっている行を専用のシートに表示し、合計が一致するかどうかのチェックも行います。
  - **ガバナンスされたメトリックを Excel で使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるとおりにビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計では `0` を表示し、それ以外では理由とともに `#VALUE!` を表示します（`CELLS` のスピルでは空白）。**Metric...** ボタンは、プロジェクトのメトリックを現在の値とともに一覧表示します。メトリックは、複数の代替階層でフィルターしたり、代替階層のメンバーと他のディメンションのメンバーを組み合わせたりできます。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに入力して計画できます。** `CELL` の値の上に数値を入力すると、PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの形状に合わせた配分、金額またはパーセンテージによる調整ができ、ホールドしたセルはそのまま残ります。平均、中央値、最小値、最大値、標準偏差、分散のセルにも値を入力できます。入力した値は、行や列を挿入または削除してもそのセルに追従します（削除されたセルの値は報告されます）。**Undo last write**は、入力した値と保存を新しいものから順に取り消します。書き込みを取り消せるのは、その書き込みを行ったユーザーとワークスペースだけです。合計の取り消しや、空のセルに入力した平均の取り消しでは、その後に同じセルへ書き込まれた内容が保持されます。完了前に中断された書き込みは取り消せません。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要なものだけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新でき、各テーブルの進行状況と**キャンセル**がタスクペインに表示されます。PlaidXL の数式だけを再計算することもできます。取得したテーブルは、データ型に合わせて書式設定された Excel テーブルとして取り込まれ、更新しても独自に追加した列と数値の書式が保持され、元の場所で更新されます。取得や更新によって他のセルが上書きされたり、別の Excel テーブルと重なったりすることはありません。Excel で扱えないほど大きい整数の ID と1900年より前の日付は、テキストとして取り込まれます。テーブルを再取得しても更新リストに二重に追加されることはなく、**Stop refreshing**でリストから外せます。ディメンションもテーブルと一緒に更新されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud**は確認なしで書き込み、実行した内容を表示して、**元に戻す**を提示します。これは、Lakehouse テーブルでは各保存から最大7日間使えます。フィルターを指定して取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーによる保存では、該当する行だけが置き換えられるため、他のユーザーの行は保持されます。取得後にメンバーが変わったドリルスルーシートは保存されません。保存が失敗した場合は、テーブルを元に戻せるよう復元ポイントが示されます。[テーブルを PlaidCloud に保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave**タブで、レポート、数式、ドリル、テーブルを普段の言葉で依頼するか、**Ask Weave about this cell**を選択します。Weave はあなたの権限で PlaidCloud を読み取ってブックだけを変更し、入力済みの内容を置き換える前に確認します。ブックの外を参照する数式を書くことはなく、各変更はペインを再読み込みするまで元に戻せます。[Excel で Weave に質問する](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1つのシートまたはブック全体を、値のみのコピーとして共有できます。** **Convert to values**は、ブック全体、1つのシート、または元に戻せない値のみへの変換（事前に確認があります）を行います。変更するのは PlaidXL の数式とそのスピルだけで、まだ計算中の数式は再試行できるよう残します。シートの名前を変更した後も、**Restore PlaidXL formulas**は引き続き使えます。
- **転記レジスターは、自分の対応が必要な内容から開きます。** 確認が必要なものがある場合は**例外**で、自分の承認を待っているリクエストがある場合は**承認**で、それ以外の場合は**すべての転記**で開きます。レールは画面を**自分の対応待ち**、**レジスター**、**インサイト**、**設定**にグループ化し、**例外**と**承認**には件数が表示されます。すべての画面が1つのヘッダーとスコープバーを共有します。期間（**今月**、**前月**、**過去7日間**、**過去30日間**、**カスタム**）、接続、プロジェクト、環境、エンティティ、そして**本番**、**シミュレーション**、**すべて**のいずれかを選び、**リセット**するか、**Saved scope**として保持します。前回のスコープは記憶されます。
  - **例外では、確認が必要なものを整理できます。** **要確認**、**未確認**、**保留中**、**失敗**、**取消未完了**のチップに件数が表示され、接続の正常性を示す行には「All N connections posting normally」と表示されます。すべての転記に分かりやすい状態が表示され、ツールチップで次に何をすべきかが分かります。未処理のものがない場合は**All clear**と表示されます。**Find a posting by ledger id**またはコマンドパレットに元帳 ID を貼り付けると、その転記が直接開きます。
  - **承認、委任、ウォッチは受信トレイ形式の画面です。** **Waiting on me**と**Submitted by me**を切り替え、理由を添えて**承認**または**却下**し、複数をまとめて承認し、トーストから承認を**元に戻す**ことができます。**Delegate approvals**は短いダイアログで、**ウォッチ一覧**には自分がフォローしているものが表示されます。**転記を取消**と、一括での再試行とクリアのダイアログは、同じレイアウトを共有します。
  - **転記のドロワーで、何が起きたかが分かります。** 状態とその意味、名前付きの主要な事実、**明細**、**履歴**、**承認**タブが表示され、**レビュー済みにする**、**再試行**、**取消…** ボタン、**接続をウォッチ**、**実行をウォッチ**、**リンクをコピー**（その転記を直接開くリンクをコピーします）を使えます。
  - **アシスト、エクスポート、保持期間も同じデザインになりました。** **アシスト**には質問ボックスとインサイトカードがあり、アドバイスには**Draft — nothing applied**と表示されます。また、**すべての転記**には、**これらを表示**付きの異常カードが表示されます。**エクスポートとアラート**には**New schedule**があり、**保持期間**は1枚のカードにまとめられています。
  - **レジスターは常に最新の状態に保たれます。** 転記が変化するとレールのバッジが更新され、転記が変更された場合は開いている一覧に**更新**が表示され、開いているドロワーはその場で更新されます。**ホーム**の**要対応**の下に**転記レジスター**カードが表示されます。[転記レジスターを確認する](/ja/guides/connections/posting-register/)を参照してください。
- **プロジェクトホームは6つのページで構成されます。** テキストのみのレールに**概要**、**変数**、**スケジュールとセンサー**、**アクセスと共有**、**データと接続**、**アプリとブランディング**が並び、変数の数と、有効なスケジュールとセンサーの数がバッジで表示されます。**概要**には、プロジェクトの説明とラベル、ロックの状態、テーブル、ワークフロー、ステップ、変数、公開済みテーブル、**データサイズ**のタイル（**ストレージ**を開きます。合計は**プロジェクト**画面に表示されるものと同じで、復元用に保持されている以前のバージョンも含まれ、ツールチップで現在のデータと以前のバージョンの内訳を確認できます）、次の3回のスケジュール実行、プロジェクトのデフォルトが表示され、**プロジェクトレポート**（PDF またはインタラクティブ HTML）と**アーカイブのエクスポート**も使えます。その他のページでは、変数、スケジュールとセンサー（**カレンダービュー**と、**有効化**または**無効化**を使用可能）、プロジェクトとそのダッシュボードを開けるユーザーと、そのテーブルを読み取れるプロジェクト、接続とテーブルストレージのデフォルトと ERP 転記モード、Panelアプリ、ブランディング、プロジェクトのタイル画像を管理します。ロックされたプロジェクトにはバナーが表示され、コントロールが無効になります。[プロジェクトホーム](/ja/guides/projects/project-home/)を参照してください。
- **ドキュメントは概要から開き、ページのレールが付きました。** **概要**、**参照**、**あなたのアカウント**、**管理**がレールに並びます。各ページにはタイトルがあり、多くの場合はサブタイトルも付き、アクションはヘッダーにあります。**概要**には、アカウントのタイル、**ピン留め**したファイル（そのフォルダーでファイルが選択された状態の**参照**が開きます）、サービス別のアカウント、それを使えるユーザーが表示されます。**あなたのアカウント**は、使用できるすべてのアカウントの一覧で、各行に**共有**または**プライベート**のピルが付きます。**管理**には自分が所有するアカウントが表示されます。ワークスペース管理者には、ここにすべてのドキュメントアカウントが表示され、ほかの方法で管理できるアカウントはすべてここから管理できます（システム管理のアカウントは拒否され、マネージドバケットのアカウントは複製できません）。行の **⋯** メニューには、**開く**、**編集**、**複製…**、**利用できるユーザー**、**使用箇所…**、**バージョン履歴**、**有効にする**または**無効にする**、**削除**があります。アカウントは、**一般**、**アクセス**、**認証情報**のカード（SFTP の場合は**SSH**カードも）を持つページとして開き、未保存の変更がある状態でページを離れようとすると確認を求めます。**参照**は、お気に入りのアカウント、またはワークスペースのデフォルトのアカウントを開きます。ラベル付きのツールバー、行メニュー、ドラッグ＆ドロップによるアップロード（ファイル一覧またはフォルダーにドロップするとそこへ、ツリーの空いている場所にドロップするとアカウントのルートへアップロードされます）、そして各アップロードとテーブルへの各インポートを進行状況と操作とともに表示する**Uploads and imports**パネルがあります。**別ウィンドウで開く**は、フォルダーを新しいブラウザータブで開きます。[ドキュメント](/ja/guides/documents/)と[ドキュメントアカウントの使用](/ja/guides/documents/using-document/)を参照してください。
- **ダッシュボードは概要から開き、ページのレールが付きました。** **概要**、**ダッシュボード**、**アプリ**、**ノートブック**、そしてワークスペース管理者には**アクセスレビュー**がレールに並び、下部には**ナビゲーターを開く ↗** があります。独自のウィンドウで開くため、矢印が付いています。各ページにはタイトルがあり、多くの場合はサブタイトルも付き、アクションはヘッダーにあります。**概要**には、対応する一覧を絞り込んだ状態で開くダッシュボードとアプリのタイル、最近開いたものやスターを付けたもの、失敗したアプリと自分の対応を待っているアクセスリクエスト、そして利用状況へのアクセス権を持つメンバー向けに、最も多く開かれたダッシュボードが表示されます。**ダッシュボード**は**すべて**、**管理中**、**お気に入り**で絞り込め、**アプリ**には各アプリの**種類**と稼働状態が表示されます。[ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **ID は概要から開き、ページのレールが付きました。** レールには、**概要**、**メンバー**、**ディレクトリ**、**セキュリティグループ**、**配布リスト**、続いて**セッション**、**セキュリティログ**、**APIクライアント**、**グループ監査**、**すべてのスコープ**が並びます。各ページにはタイトルがあり、多くの場合はサブタイトルも付き、アクションはヘッダーにあります。**概要**には、メンバー、アクティブなメンバーとまだ一度もサインインしていないメンバー、ビルダーシート、現在サインインしているユーザーのタイル、**アクティブなメンバー**のチャート、**ウェルカムメールを再送信**と**確認**を備えた**要対応**、直近7日間のセキュリティイベントが表示されます。メンバーは、**プロファイル**、**アクセス**、**グループとデータ**のカードを持つページとして開き、**メンバーを招待**は概要とホームの初回用カードから使えます。[メンバー管理](/ja/administration/access/member-management/)を参照してください。
- **一覧を、標準の行、ゆったりした行、カードで表示できます。** **ダッシュボード**、**アプリ**、ERP レジスター、ID の**メンバー**などの一覧では、ツールバーの**ビュー**メニューでこれらを切り替えられます。カードでも、選択、並べ替え、列、右クリックの**コピー**、さらにお気に入りがある一覧ではお気に入りの星など、一覧の機能をすべて使えます。**ダッシュボード**のカードにはサムネイルが表示されます。[標準の行、ゆったりした行、カードのビュー](/ja/guides/dashboards/using-dashboards/#標準の行ゆったりした行カードのビュー)を参照してください。
- **Lakehouse ウィンドウに、サイドレール、テーブルの詳細、タイムトラベルが加わりました。** **クエリ**、**プロファイル**、**ロード**、**カタログ**がレールに並び、**Administration**の下に**Lakehouse catalogs**、**Database users**、**Compute**があります。**Database users**と**Compute**は、Lakehouse 管理者または Lakehouse クラスターのロールを持つメンバーにのみ表示されます。**クエリ**では、SQL テキスト、ユーザー、種類、所要時間で履歴を絞り込み、**Copy SQL**でステートメントをコピーし、**Profile this query**でクエリを**プロファイル**で開けます。**カタログ**では、テーブルの列、現在のスナップショット、パーティション分割、場所、プロパティ、スナップショット履歴を確認でき、**Copy query as of this snapshot**を使うと、その時点のテーブルを読み取る `FOR VERSION AS OF` クエリをコピーできます。[Lakehouse ウィンドウ](/ja/guides/data/lakehouse-window/)を参照してください。
- **ステップフォームでプレビューできます。** インポート: SQL、実行: SQL、SQL抽出、エクスポート: SQL、Salesforce: オブジェクトのクエリの各ステップでは、ステップを実行せずに最大100行を表示できます。Anaplan のビューとリストの読み取りでは、生成される列と型が表示されます。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように値が埋め込まれますが、`{x:>9}` のような変数の書式はサポートされません。プレビューで実行できるのは標準の SQL 関数だけで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトや、エージェントベースの SQL 実行ステップでは使えません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)ステップと[SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)ステップを参照してください。

## 変更

- **ワークスペースで Grok を使用している場合、モバイルの Weave は AI に関する通知への同意を再度求めます。** この通知から、xAI がお客様のデータをモデルの学習に使用しないという記述が削除されました。現在は、PlaidCloud が xAI とゼロデータ保持契約を結んでいないため、xAI がデータを保持し、標準の利用規約で認められる範囲で使用する場合があると説明しています。[Weave によるお客様のデータの利用について](/ja/guides/ai-assistant/weave-data-use/)を参照してください。
- **ホワットイフウィンドウは、一度に1つの期間を読み取ります。** Allocation Split ステップの出力に期間列がある場合、ウィンドウは最新の期間で開き、**期間:** リストで別の期間または**すべての期間**を選択できます。ドライバーに期間ごとの行があり、全期間をまとめて読み取るには大きすぎたステップも、1つの期間で開いて回答できるようになりました。保存したシナリオは保存時の期間（ある場合）を保持し、そのシナリオを開くと、その期間がまだ一覧にあれば、ウィンドウがその期間に移動します。[期間を選択する](/ja/guides/allocations/results/driver-what-if/#期間を選択する)を参照してください。
- **PlaidCloud の Web アプリと Python クライアントライブラリは REST API を使用するようになり、JSON-RPC は非推奨になりました。** Web アプリは REST API にリクエストを送信します。`plaidcloud-rpc` 1.25.0以降では、`SimpleRPC` の呼び出しはコードを変更しなくても REST API に送られます。REST API がまだ対応していない呼び出しや、古いリリースのままのワークスペースでは、従来どおり JSON-RPC が使われます。JSON-RPC は今後のリリースで削除されるため、スクリプトとノートブックを `plaidcloud-rpc` 1.25.0以降にアップグレードし、新しい連携は REST API を使って作成してください。[コマンドライン](/ja/reference/cli/jupyter/command-line/)を参照してください。
- **ステップは、別の環境に固定しない限り、プロジェクトの接続環境に従います。** プロジェクトの環境（QA や本番など）を切り替えると、すべてのステップが一緒に移ります。1つの環境にとどめる必要があるステップには、代わりに**Fixed environment**を設定できます。その場合、フォームには警告が表示され、プロジェクトとは別の環境で実行されるたびにログに記録され、プロジェクトを切り替えるときには追従しないステップが示されます。ERP 転記ステップは常にプロジェクトの環境を使用します。プロジェクト、固定されたステップ、エージェントのいずれかが使用している環境は削除できず、エージェントフォームのフィールド名は**Environment this agent serves**になりました。[ステップを1つの環境に固定する](/ja/guides/projects/managing-projects/#ステップを1つの環境に固定する)を参照してください。
- **ステップフォームのレイアウトが統一されました。** タブには標準の名前が標準の順序で付いています。一般、設定、ソース、列、フィルター、出力、詳細設定の順で、ERP 転記フォームにはヘッダー列と明細列があります。必須フィールドには * が付き、フォームが保存をブロックするのは、ステップに必要な項目が不足している場合だけです。
- **「プロジェクトをコピー」で、テーブルデータとディメンションメンバーを別々に選べるようになり、データのコピーが速くなり、プライベートなコピーでは ERP書き込み承認が保持されます。** **Data to copy**で、**テーブルデータ**として**テーブルデータなし**（デフォルト）、**完全**、**サンプル**のいずれかを選び、それとは別に、デフォルトでオンになっている**Copy dimension members**を選択します。そのため、テーブルの行を含まないコピーでもディメンションにはメンバーが入った状態で作成され、短時間で完了します。**完全**と**サンプル**のコピーでは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも早く完了します。**コピー結果**には、テーブルと並んで各ディメンションの結果が表示され、**Retry failed items**は失敗したテーブルとディメンションをまとめて再試行します。データ付きで作成した新しいコピーは自分専用のプライベートなプロジェクトになり、コピー元の ERP書き込み承認のうち、自分で自分に付与できるものが保持されます。コピー元が本番で転記している場合、コピーはシミュレーションの状態で作成されるため、本番に切り替えるまで ERP には何も送られません。REST API と `project_copy` MCP ツールでも `dimension_members` を指定できます。[コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーでの ERP書き込み承認](/ja/guides/projects/managing-projects/#コピーでのerp書き込み承認)を参照してください。
- **テーブルの詳細パネルに、そのテーブルを使用するステップがより早く表示されます。** 別のテーブルを選択すると、前のテーブルのステップがすぐに消去されます。このプロジェクトのデータを共有する他のプロジェクトのステップは、パネル全体の表示を待たせることなく、ほかのステップより少し遅れて追加されます。[テーブルの使用箇所を確認する](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)を参照してください。
- **行の操作は、すべての一覧で同じように動作します。** 行のメニューは、行の先頭にある **⋯** ボタン、行の右クリック、ツールバーの**アクション**メニューのいずれかから開きます。メニューには常に**開く**、**詳細**、**編集**が先頭に並び、続いてその一覧固有の操作、最後に**削除**（Delete）または**削除**（Remove）が表示されます。その行に当てはまらない操作は、同じ位置でグレーアウトされます。**Enter**と**Del**は、それぞれが実行する項目に表示されます。行の操作が1つだけの一覧では、**⋯** の代わりにその操作のアイコンが表示され、ダッシュボード、アプリ、ノートブックでは**開く**アイコンが再び表示されるようになりました。[行アクションメニュー](/ja/guides/dashboards/using-dashboards/#行アクションメニュー)を参照してください。
- **PlaidCloud の外観が、ライトとダークの両方で新しいブルーに刷新されました。** ボタン、チェックボックス、選択された行、タブ、リンク、ワークスペースのページを一覧表示するレールには、どちらのテーマでも読みやすいコントラストを備えた、1つの PlaidCloud ブルーが使われます。アプリのタブアイコンは、統一された1つのセットになりました。
- **新しい読み込み画面。** PlaidCloud は、ライトまたはダークのテーマに合わせた、すっきりとした読み込み画面で開きます。アイドル状態から復帰する Panel アプリまたは Dash アプリは、**開始中**、**準備中**、**アプリを読み込み中**と進行状況を表示し、起動しなかった場合はどの段階で止まったかを示して**再試行**を提示します。[Panel アプリの使用](/ja/guides/panel-apps/using/)を参照してください。
- **検証の設定がない保存済みの ERP 書き込みステップは、検証のみとして開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS の GL と AP の Post、Xero のエクスポートです。本番で実行するよう明示的に設定されたステップは、本番のままです。
- **長時間実行されるジョブの進行状況が、どこでも同じ方法で表示されます。**
- **ワークフローは正しく停止・失敗し、実態どおりに報告します。** ワークフローを停止すると、そのワークフローが開始したものがすべて停止します。完了できない実行やステップは、ハングせずに理由を示して失敗し、実行ステータスは実際に実行された内容と一致します。
  - **ワークフローを停止すると、そのワークフローが開始したものがすべて停止し、完了できない実行やステップはハングせずに失敗します。** 停止すると、まだキューに入っているインポートとディメンションのステップがキャンセルされるため、ワークスペース内の後続のインポートとディメンションのロードは通常どおり開始されます。また、そのワークフローのキュー中または実行中のコネクター（Singer）同期も停止します。ステップのジョブを開始できない場合、ステップは永遠に待機せず、理由を示して失敗します。約40分以内にどのワーカーも開始しない、ワーカーが開始した後に消えた、ポッドが約20分間 Pending のまま、イメージを約5分間プルできない、約20分間ポッドが作成されない、のいずれかの場合です。約30分以内にどのランナーにも取得されないコネクター同期は、その同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間は、ステータスメッセージに経過分数とともに「Waiting for a worker…」と表示され、作業が始まると消えます。マクロを停止すると、実行中のすべてのコピーが停止します。一方、1つのコピーを停止した場合や、応答しなくなったコピーを**Macro Concurrent**ステップが見切った場合は、呼び出し元のワークフローは実行を続けます。他のワークフローの中でのみ実行されているマクロは、ワークフロー一覧に**実行中**と表示され、**停止**を使用でき、各ステップのステータスと開始・終了時刻は最新の実行のものが表示されます。サーバーが失われた実行は失敗として終了し、12時間たってもまだ実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」で失敗します。[ワークフローを実行する](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
  - **再開、実行履歴、実行ステータスが、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローのステップの1つを単独で再実行した後でも、子ワークフローに残っていたものがすべて実行されます。また、1回の実行の中で子ワークフローを呼び出すたびに、それぞれ実行履歴のエントリが作成されます。サーバーが停止したために再開したステップは、ログにその旨が記録されます。`workflow_run_status` と REST API の実行結果は、実行を問題なしと報告するのではなく、失敗したものの続行したステップを `continued_step_ids` と `continued_step_count` に一覧表示します。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時の続行](/ja/guides/workflows/continue-on-error/)を参照してください。
  - **ステップのエラーに、そのエラー自身のメッセージが表示されます。** PlaidCloud が想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードではエラーが1行で表示され、その後削除されたワークフローの実行は表示されません。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。
  - **完了しない ERP 抽出はステップを失敗させ、再開すると続きから実行されます。** **SAP: アドホック抽出**が行数または時間の上限で一時停止した場合やエージェントが時間内に応答しなかった場合、また、Salesforce、Oracle Fusion の一括、HFM/FCCS のエクスポートジョブが、ステップが待機を終えた時点でまだ実行中の場合、ステップは失敗します。そのため、後続のステップが不完全なテーブルに対して実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は同じジョブで、停止した箇所から続行されます。[実行の制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と[Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)を参照してください。
  - **エクスポートをキャンセルすると、ウェアハウスでのクエリも停止します。** エクスポートまたはダウンロードがキャンセルされると（ワークフローの停止によるキャンセルを含む）、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplum では、そのデータを読み取っているクエリも停止します。リモートデータベースへのエクスポートも、最後まで実行し続けることなく、ソースの読み取りを停止します。

- **セッションの期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードを開きます。** [ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。

- **Slack、Microsoft Teams、Web Hook の各ステップで、メッセージが送信されなかった理由が示されます。** ステップのエラーには、接続しようとしたサーバーと、Slack と Teams の場合は接続が示され、何が問題だったかが説明されます。たとえば、Slack がそのウェブフックをもう認識しない、そのチャンネルに投稿できない、サーバーが見つからないか60秒以内に応答しない、接続が削除された、などです。Slack や Teams のウェブフック URL を知っていれば誰でも連携として投稿できるため、URL が表示されることはありません。[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/) ステップを参照してください。

- **ワークスペースの組織、オーナー、リリース、バージョンは PlaidCloud が設定し、データセンターはお客様が選択します。** コントロールプレーンで作成したワークスペースは自分が所有者となり、PlaidCloud が設定するリリースチャネルに配置されます。**Data Center**は、サインアップ時に提示されたリージョンから選択します。ワークスペースを編集するとき、組織、オーナー、リリース、バージョンは読み取り専用です。バージョンを変更するには**Set Version**を使用し、ワークスペースの移動、オーナーやチャネルの変更、バージョンの固定は PlaidCloud サポートに依頼してください。[ワークスペースの設定](/ja/administration/control-plane/workspace-configuration/#基本設定)を参照してください。
- **エンコード変換ステップで、フォルダーのサブフォルダーを保持できます。** **ドキュメント: ファイルをASCIIエンコードに変換**、**ドキュメント: ファイルをUnicode（UTF-8）エンコードに変換**、**ドキュメント: ファイルをUnicode（UTF-16）エンコードに変換**に、**サブフォルダーを保持**ボックスが加わりました。オンにすると、入力フォルダーのサブフォルダーにある各ファイルが、宛先の対応するサブフォルダーに書き込まれます。圧縮ファイルの内容は、その圧縮ファイルがあったサブフォルダーに入ります。オフのままにすると、従来どおり、すべてのファイルが宛先フォルダーそのものに書き込まれます。[Convert Document Encoding to UTF-16](/ja/reference/workflow-steps/document/convert-document-encoding-to-utf-16/) ステップを参照してください。

## 修正

- **無効なプロジェクト設定が、分かりやすいメッセージで報告されます。** 不明な環境やドキュメントアカウント、すでに使用されているか予約されているスラッグ、無効なストレージタイプや転記モードに対して、汎用のサーバーエラーではなく、問題を示すメッセージが返されるようになりました。REST API では500ではなく400が返され、AI アシスタントまたは MCP では無効な引数のエラーになります。
- **REST API のディメンション値リクエストが正しく動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` は、グリッドリクエストとして処理され、無効として拒否されていました。現在は `value_columns` の各列について1つの集計値を返します。グリッド（行フィルターと列フィルターの組み合わせごとに1つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **時間のかかるテーブルの読み取りやファイル処理が、他のリクエストを妨げなくなりました。** ウェアハウスからのテーブル列の読み取り、Data Foundation のファイルの登録、Excel へのエクスポート、REST または SOAP インポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panel アプリのコードやロゴのチェックは、それぞれ完了するまで、同じサーバーが処理している他のすべてのリクエストを一時停止させることがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールできるようになりました。** 小さい画面や低い解像度では、追加と編集のダイアログがウィンドウより縦に長くなり、**作成**ボタンと**更新**ボタンに手が届かないことがありました。現在はフォームがスクロールし、ボタンは下部に固定されます。
- **Azure Blob Storage ドキュメントアカウントにある256 MiBを超えるファイルを、コピー、移動、名前変更できます。** これまでは、そのサイズのファイルではいずれの操作も失敗し、そのようなファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2 では、テーブルの行数に、書き込んだばかりの内容が反映されます。** テーブルに書き込んだステップやインポートが書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが0行と表示されたり、インポートが0行をインポートしたと報告したりしていました。現在は、新しい行がすべての場所から見えるようになった時点で行数が読み取られるため、後続のステップもその行を読み取れます。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりしたときも、行数と列数が更新されます。
- **Weave の空値チェックは、各実行を、以前の実行が実際に残した内容と比較します。** ステップの空値は、ステップがテーブルを再投入するために空にした直後に数えられることが多く、そのため以前の実行には空値がなかったように見え、以前から一部が空だった列が、たった今そうなったかのように報告されていました。現在は、ステップがテーブルを残した状態で各実行が数えられます。以前に記録された件数は正しいものと区別できないため使用されません。各ステップの空値チェックは履歴を最初からやり直し、5回の実行が数えられるまでは未チェックとして報告されます。行数と値の分布のチェックでも、ステップの終了から2秒以上たってから別のステップが同じテーブルに行った書き込みを、そのステップの書き込みとして扱わなくなりました。[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **Data Foundation は、反転した為替レートと小数のしきい値の精度を保持します。** 為替レートが報告通貨から別の通貨への形で提示されているために PlaidCloud が反転させたレートは、小数点以下6桁に丸められることがあり、インドネシアルピアのようにレートの小さい通貨の金額が約1%ずれていました。反転したレートは小数点以下12桁まで保持されるようになりました。`0.5` のように小数を含む `group_amber` または `group_red` のしきい値は、整数に丸められていました。次回のロードでは正確な値が使われます。[為替レート](/ja/guides/projects/data-foundation/#為替レート)を参照してください。
- **無効化されたメンバーのアラートとダイジェストが停止します。** オーナーが無効化された Panel アプリのアラートやダイジェストは、チェックと送信を続けていました。現在は、オーナーが無効化されている間は一時停止し、再有効化されると再開します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
- **削除された接続を REST API で要求すると404が返されます。** 削除された接続や存在しない ID を要求すると、汎用のサーバーエラー（500）が返されていました。現在は、接続 ID を示すメッセージとともに404が返されます。
- **テンプレートを使ったテーブルのエクスポートが、AI アシスタントと MCP で動作します。** `table_data_export` の `templated` 形式は、テーブルを指定すると必ず失敗していました。現在は、読み取れる行に限定して、テンプレートを通してテーブルをエクスポートします。テンプレートでは、テーブルの行はテーブル ID で参照され、ID 内の各 `-` は `_` として記述します。
- **Amazon S3 および S3 互換のドキュメントアカウントで、リージョンが保持されます。** これらのアカウントを保存すると、入力した**リージョン**が破棄され、次にアカウントを開いたときにフィールドが空になっていました。現在はリージョンが保存されます。この修正より前に保存したアカウントでは、リージョンを再入力して保存してください。[AWS S3 アカウントの追加](/ja/guides/documents/adding-accounts/add-aws-s3-account/)を参照してください。
- **フォルダーのエンコード変換で、同じ名前の別のファイルが上書きされなくなりました。** 宛先の同じ場所に書き込まれる2つのファイル（たとえば、異なるサブフォルダーにある同じ名前の2つのファイル）では、最後に書き込まれたファイルだけが残っていました。現在、ステップは2つ目のファイルを書き込む前に停止し、両方のファイルとその書き込み先を示します。また、**サブフォルダーを保持**をオンにすれば別々に保持できる場合は、その旨を示します。
- **ドキュメント: ファイルをASCIIエンコードに変換で文字の置き換えをオフにすると、正しく反映されます。** **ターゲットエンコードで表現できない文字を ? に置き換える**をオンにして保存したステップは、ボックスをオフにしてステップを再保存しても、オンのままでした。現在は、オフにすると置き換えが無効になります。
- **AI アシスタントと JSON-RPC は、ロールで非表示になっているテーブルを使用するステップを名指ししなくなりました。** そのようなテーブルがどこで使われているかを尋ねると、そのテーブルを読み書きするステップのうちロールで表示できるものを、設定とワークフローとともに1つずつ挙げていました。現在は、プロジェクトのテーブル参照と同様に、ステップの名前を挙げずに、ステップがそのテーブルを使用していることだけを伝えます。[ロールで非表示になる内容](/ja/guides/ai-assistant/weave-tab/#ロールで非表示になる内容)を参照してください。
- **選択したデフォルトの AI 接続が、デフォルトのまま維持されます。** AI 接続をワークスペースのデフォルトとして設定すると、成功したように見えても保存されておらず、デフォルトに依存するエージェントやステップは、最後に更新された接続を使い続けていました。現在は、選択した内容が保存されます。[LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **Weave の履歴で会話を右クリックしても、「スレッドを削除」の上に「名前の変更」が開かなくなりました。** **名前の変更**はチャットのタブに移動しました。これまで何も表示されなかったタブを右クリックしてください。[Weave タブ内のタブ](/ja/guides/ai-assistant/weave-tab/#weaveタブ内のタブ)を参照してください。
- **メモが空でも保存できるようになりました。** **メモ**ボックスを空のままプロジェクト、ディメンション、テーブル、ウェアハウス、エディター、スケジュールされたワークフローイベント、配布リストを作成または保存すると、「Memo: Input should be a valid string」というエラーで失敗していました。現在は、空のメモが受け付けられます。
- **1つの値が必要な場所で複数の値を返す式は拒否され、Table Extract ステップや Table Union All ステップではターゲットテーブルのデータが保持されます。** よくある原因は、`table.amount,` のような末尾のカンマや、`table.region == ('EU', 'US')` のような複数の値との比較です。Databend ではステップが失敗し、Table Extract ステップや Table Union All ステップでは、その時点ですでにターゲットテーブルが空になっていました。ほかの一部のウェアハウスではこのような式が実行されていましたが、記述どおりに動作するとは限らなかったため、これまでエラーなく実行されていたステップが拒否されるようになる場合があります。ステップフォームはステップの保存時にその式を拒否し、メッセージに変更すべき内容が示されます。[1つの値が必要な場所に複数の値がある場合](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#1つの値が必要な場所に複数の値がある場合)を参照してください。
- **出力列に同じ名前を2回指定したステップは、ターゲットテーブルを空にする前に停止します。** Table Lookup、Table Extract、または結合のステップで、同じ名前の**ターゲット出力列**が2つあると、ステップはターゲットテーブルを空にしてから、分かりにくいエラーで失敗していました。現在は、ステップが先に停止し、重複している列名を示すメッセージを表示するため、出力列それぞれに別の名前を付けられます。クエリが返す順序で列を書き込む SQL抽出ステップは変わりません。[Table Lookup](/ja/reference/workflow-steps/tables/table-lookup/) ステップを参照してください。
- **何も選択されていないユニオンとエクスポートは、何が不足しているかを示します。** ソース列のない Table Union All または Table Union Distinct のソース、またはテーブルのない Export to Parquet、Export to ORC、Export to Avro、Export to XML ステップは、内部設定名を示す予期しないエラーで失敗していました。現在は、何も書き込む前にステップが停止し、ユニオンではソースが示され、エクスポートでは *No Tables Specified* と表示されます。REST API、JSON-RPC、AI アシスタントまたは MCP からこのようなユニオンのソースを保存すると、ソースが示されたうえで拒否されます。

## セキュリティ

- **Weave は、各会話の開始時に、お客様の氏名とメールアドレスを AI プロバイダーに送信しなくなりました。** これらが使われることはありませんでした。
- **パスワードによるサインインには認証アプリが必要になり、パスワードの要件が強化されました。** PlaidCloud のパスワードでサインインするメンバーは、次回のサインイン時に認証アプリの設定を求められ、それ以降はサインインのたびにそのコードを入力します。シングルサインオン、Google、Microsoft、GitHub によるサインイン、API トークン、サービスアカウントは変わりません。新しいパスワードは12文字以上で、ユーザー名や過去6回分のパスワードと同じものは使えません。サインインに繰り返し失敗すると、アカウントは短時間ロックされます。ワークスペースにすでに設定されている、より厳しいルールは維持されます。[メンバー認証](/ja/administration/access/member-authentication/)を参照してください。
- **接続の接続先は、パブリックアドレスとプライベートネットワークのアドレスに限られます。** 接続にループバック、リンクローカル、クラウドメタデータのアドレスを指定することはできず、エラーにはホストとその解決先のアドレスが示されます。プライベートネットワーク上のアドレスは影響を受けません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続が到達できないアドレス)を参照してください。
- **保存された接続の認証情報は、接続またはワークフローを編集できるメンバーにのみ表示されます。** REST API と MCP では、保存された接続のパスワード、トークン、キーは他のメンバーに対してマスクされますが、そのメンバーも接続を開いて参照することはできます。[接続の認証情報を確認できるユーザー](/ja/guides/connections/create-connection/#接続の資格情報を見られるユーザー)を参照してください。
- **アプリのビルドは、ワークスペースの Git 認証情報にアクセスできない状態で実行されます。**
- **エージェントの秘密鍵は、エージェントを編集できるメンバーにのみ表示されます。** 鍵は、REST API と MCP のエージェント一覧や詳細に表示されなくなり、エージェントフォームの**秘密鍵**と**RPC構成を表示**は、エージェントを編集できるメンバーにのみ表示されます。サービスアカウント、プロジェクトトークン、エージェントトークン、AI に委任されたトークンでは、鍵や RPC 構成を取得できません。実行中のエージェントは影響を受けず、公開鍵は引き続き表示されます。[エージェントの認証情報の取得](/ja/reference/cli/plaidlink/agents/#エージェントの認証情報の取得)を参照してください。
- **プロキシのダウンロードリンクの有効期間は1時間です。** **Use PlaidCloud Proxy Download**がオンの場合、リンクの期限が切れたら、もう一度ダウンロードを開いて新しいリンクを取得してください。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)を参照してください。
- **セキュリティグループへのユーザーの追加は、自分が保有する権限に従います。** メンバーをセキュリティグループに追加したり、メンバーのグループを選択したり、アーキテクトを招待したりできるのは、そのグループが付与するすべての権限を自分が保有している場合です。ワークスペース管理者には制限はありません。[セキュリティグループの管理](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)を参照してください。
- **接続の設定の変更とオン・オフの切り替えは、接続のオーナーまたはワークスペース管理者が行います。** REST API、JSON-RPC、AI アシスタントまたは MCP から接続の設定を変更するには、その接続のオーナーの1人であるか、オーナーのいない接続の場合はワークスペース管理者である必要があります。接続の有効化、無効化、ロック、ロック解除には、オーナーまたはワークスペース管理者の権限が必要で、複数の接続を指定したリクエストは、そのすべてを変更できる場合にのみ適用されます。ワークスペースのデフォルトの AI 接続を選択できるのはワークスペース管理者だけです。メンバーが所有する接続がデフォルトになるのは、管理者が所有する接続やオーナーのいない接続がデフォルトになれない場合に限られます。[接続の編集](/ja/guides/connections/create-connection/#接続を編集する)と[LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **行アクセスは、制限付きテーブルに対してメンバーが行うすべての操作に適用されます。** メンバーは、ダッシュボード、自分で書いた SQL、ロードのいずれでも、自分に付与された権限が許可する行だけを参照・変更できます。
  - **プロジェクトのアーキテクトは、ダッシュボードで、行が制限されたテーブルのすべての行を参照できます**。これは Analyze で参照できる範囲と一致します。アーキテクトのアクセスを取り消すと、ダッシュボードにただちに反映されます。ロールの変更、メンバーやそのグループのプロジェクトからの削除、プロジェクトのアクセスタイプの変更、以前のプロジェクトバージョンの復元、セキュリティグループの削除のいずれの場合も同様です。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
  - **行アクセスで制限されたメンバーが、自分の SQL クエリを実行し、その結果をエクスポートできるようになりました。** 行アクセスが設定されたプロジェクトでは、アーキテクトではないメンバーがクエリ画面で自分のクエリを実行すると、付与された権限が許可する行だけが正確に返され、それを**アクセス権により行が制限されています**という通知付きで CSV、Excel、JSON にエクスポートできます。以前は、これらは拒否されていました。パーセント記号（`%`）を含む付与値も、クエリ画面で該当する行を返すようになり、そのようなクエリを CSV としてダウンロードすることもできます。Snowflake や Databricks での自分の自由形式の SQL、Postgres 系ウェアハウスからの自分の SQL のエクスポート、ガバナンス対象テーブルのスナップショット時点での読み取りは、引き続き拒否されます。また、ビューがフィルターされるには、ガバナンス対象の列を元の名前のまま保持している必要があります。[行アクセスと自分で書くクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスとご自身で記述するクエリ)を参照してください。
  - **行アクセスを保存しても、ソースにない付与済みの値は保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がない場合、ディメンションにそのメンバーがない場合、リストにその値がない場合でも、マークが付いた状態でグリッドに残ります。**保存**では、そのような値ごとに、保持するか削除するかを確認します。[行アクセスのグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
  - **行が制限されたテーブルへの DataFrame の書き込み、レコードの保存、クリアでは、自分に見える行だけが変更されます。** 行アクセスで自分の行が制限されている場合、Python クライアントで制限付きテーブルに DataFrame を書き込んだりテーブルをクリアしたりするとき、また REST API でレコードを保存したりテーブルをクリアしたりするときは、自分の行だけが変更されます。アクセス範囲外の行を含むロードは、何かが変更される前に拒否され、見つかった値が示されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は、テーブル全体に書き込みます。個人が行うこれらの書き込みは、どのテーブルに対するものでもセキュリティログに記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
  - **行が制限されたテーブルへのインポート、コピー、復元、削除には、すべての行が自分に見えている必要があります。** 行アクセスで自分の行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えやマージ、復元、削除、削除後の復旧、その他テーブル全体を置き換える操作は、テーブルのすべての行が自分に見えている場合にのみ実行されます。それ以外の場合は拒否され、何も変更されません。REST API でテーブルの行を保存すると、他のロードと同様に、自分の行だけが変更されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は影響を受けず、これらの操作もセキュリティログに記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントのオーナーだけです。** ドキュメントアカウントの以前のバージョンへの復元、バージョンの保持と解除、バックアップの作成には、アカウントのオーナーの1人である必要があり、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、そのアカウントへのアクセス権が必要です。
- **`query_run` は読み取り専用のステートメントを実行します。** AI アシスタントと MCP クライアントが使用する `query_run` ツールは、1つの SELECT ステートメントまたは WITH ステートメント、その EXPLAIN、または SHOW を受け付け、それ以外のステートメントは実行しません。データを変更するには `query_transform` を使用します。MCP のテーブルエクスポートの SQL にも同じルールが適用されます。REST API と JSON-RPC API では、プロジェクトのデータを変更できないメンバーに対して、クエリの実行、列ファセットの作成、クエリの CSV ダウンロード、リモートデータベースへのクエリのエクスポート、独自のクエリによるテーブルデータのエクスポートにも同じルールが適用され、拒否されたクエリは403を返します。Explain Analyze は計測のためにクエリを実行するため、クエリログと Lakehouse では読み取りを行うクエリだけを受け付けます。また、行アクセスが設定されたプロジェクトでは、クエリログから Explain Analyze を実行できるのはプロジェクトのアーキテクトだけです。
- **テーブルエクスプローラーのフィルター、PlaidCloud に送信されるクエリ、Table Extract ステップの動的列を見つけるクエリでは、SQL を実行する関数やサーバーのファイルを読み取る関数を呼び出せません。** `query_to_xml`、`dblink`、`pg_read_file` などの関数の呼び出しは拒否され、エラーには関数名が示されます。同じ場所で、`.op()` は演算子だけを受け付け、`literal_column` では Unicode エスケープを使った引用符を使用できません。動的列のクエリには、ステップのフィルターと、ソースから列名を読み取る式が含まれるため、ルールに違反するクエリがあると、ステップは実行時に失敗します。[拒否される関数と演算子](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#拒否される関数と演算子)を参照してください。
- **Data Foundation の配賦ルールでは、一重引用符、バックスラッシュ、改行を含む部門名や統計名は拒否されます。** 名前は配賦ステップのフィルターに書き込まれるため、**保存**とステージ1のプレビューではその名前が拒否され、該当する値が示されます。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。
