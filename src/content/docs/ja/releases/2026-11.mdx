## 追加

- **PlaidXL で Excel からレポートの作成、ドリル、説明、計画ができます。** **PlaidCloud**リボンタブは、**接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有**にグループ化されています。よく使うコマンドは**PlaidXL**右クリックメニューと**PlaidXL Cell**タブにもあり、主なコマンドには変更可能なキーボードショートカットがあります。サインイン前に実行したコマンドはサインインを開き、サインイン後に一度だけ実行されます。Office で Microsoft Entra の職場アカウントを使用している場合、PlaidXL がワークスペースを自動的に検出します。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます。** **レポート**タブは、テーブルからライブのレポートを作成します。行にはドリルダウンしたディメンション、列には別のディメンションを配置し、すべての交点に `CELL` の値が入ります。**Build my first report**は、ユーザー自身のデータからサンプルを作成します。ドリルすると、レポートは行や列全体を挿入または削除し、入力した値、メモ、書式はその行に追従します。[レポートを作成する](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only**は、ノード、ディメンション見出し、またはレポートの値から、ノードをライブの `DRILL` 数式に変換して編集します。**Custom drill**は、挿入する前に行をプレビューし、メンバーピッカーはメンバーを挿入したり、ノードの子ノードのドロップダウンをセルに追加したりします。`DRILL` は除外または展開するノードを指定でき、行方向にも展開できます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明できます。** **Explain this number**は、値が何を計算しているか、現在の PlaidCloud と一致しているか、その出どころとなるテーブルとワークフローのステップを表示します。**Show detail rows**は、値の裏付けとなる行を専用のシートに配置し、合計が一致することを確認します。
  - **Excel で管理されたメトリックを利用できます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるとおりにビジネスメトリックを返し、**Metric...** はプロジェクトのメトリックを現在の値とともに一覧表示します。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに入力して計画できます。** `CELL` の値に数値を上書き入力すると、PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの分布に合わせた配分、金額または割合による調整が可能で、保留されたセルは変更されません。平均、中央値、最小値、最大値、標準偏差、分散のセルにも入力した値を反映できます。**Undo last write**は、入力した値と保存を新しいものから順に取り消します。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要なものだけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新できます。タスクペインにはテーブルごとの進行状況と**キャンセル**が表示され、PlaidXL 数式だけを再計算することもできます。取得したテーブルは、データ型に合わせて書式設定された Excel テーブルとして取り込まれ、更新時にも独自の列と数値書式が保持され、同じ場所で更新されます。テーブルを再取得しても更新リストに二重に追加されることはなく、**Stop refreshing**でリストから外せます。ディメンションはテーブルとともに更新されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud**は、確認なしで書き込み、実行内容を伝え、**元に戻す**を表示します。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーの場合は、それらの行だけが置き換えられるため、他のユーザーの行は保持されます。[テーブルを PlaidCloud に保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave**タブで、レポート、数式、ドリル、テーブルを普段の言葉で依頼するか、**Ask Weave about this cell**を選択します。Weave はユーザー自身として PlaidCloud を読み取り、ワークブックのみを変更し、入力済みの内容を置き換える前に確認し、ペインを再読み込みするまで各変更を巻き戻せます。[Excel で Weave に質問する](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1 つのシートまたはワークブック全体の、値のみのコピーを共有できます。** **Convert to values**は、ワークブック全体、1 つのシート、または元に戻せない値のみに変換します。**Restore PlaidXL formulas**は、シート名を変更した後でも引き続き機能します。
- **ステップフォームでプレビューできます。** インポート: SQL、実行: SQL、SQL抽出、エクスポート: SQL、Salesforce クエリは、ステップを実行せずに最大 100 行を表示し、Anaplan のビューとリストの読み取りは、生成される列と型を表示します。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように入力されますが、`{x:>9}` のような変数の書式はサポートされていません。プレビューは標準の SQL 関数のみを実行します。それ以外の場合は、ステップを実行するよう案内されます。ロックされたプロジェクトや、エージェントベースの SQL 実行ステップでは使用できません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と[SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)を参照してください。
- **AI アシスタントがテーブルの公開を取り消し、プロジェクトのデフォルトのダッシュボード対象者を設定できます。** `publish_manage` は、テーブルとその公開済みビュー、およびどのチャートも使用していないダッシュボードデータセットの公開を取り消します。チャートがまだ使用しているデータセットは残り、レポートビューが公開済みビューを基に作成されている場合は、そのビューとデータセットも残りますが、テーブルの公開は取り消されます。`project_upsert` は `dashboard_default_audience` を設定します。これはプロジェクト内の新しいダッシュボードの共有先となるグループで、`[]` を指定するとクリアされます。[公開の取り消し](/ja/guides/data/publish/#ai-アシスタントまたは-mcp-で公開を取り消す)と [AI アシスタントまたは MCP でデフォルトの対象者を設定する](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ai-アシスタントまたは-mcp-でデフォルトの対象ユーザーを設定する)を参照してください。

- **モバイルの Weave の音声入力は、1 回のタップで使えます。** マイクをタップして質問を話すと、話し終えた時点で Weave が送信します。もう一度マイクをタップすると途中で止められ、何も聞き取れない場合は自動的にオフになります。話している途中で**Weave**タブを離れたりアプリをバックグラウンドにしたりした場合、話した内容は送信されずに質問ボックスに残るため、確認できます。実行、一時停止、停止、再開は、確認画面での誤った二重タップを無視します。アプリのバージョン 1.3.0 以降が必要です。[音声を使用する](/ja/guides/mobile-app/weave-on-mobile/#音声を使う)を参照してください。

## 変更

- **ステップフォームは共通のレイアウトになりました。** タブは標準の名前と標準の順序で並びます。一般、設定、ソース、列、フィルター、出力、高度の順で、ERP 転記フォームにはヘッダー列と明細列が加わります。必須フィールドには * が付き、フォームは、ステップに必要な項目についてのみ保存をブロックします。
- **プロジェクトのコピーでは、テーブルデータとディメンションメンバーを個別に選択でき、データのコピーが高速になり、非公開コピーの ERP 書き込み承認が維持されます。** **Data to copy**で、**テーブルデータ**（**テーブルデータなし**（デフォルト）、**完全**、**サンプル**）を選択し、これとは別に**Copy dimension members**を選択します。後者はデフォルトでオンになっているため、テーブルの行を含まないコピーでも、ディメンションにはデータが入った状態で作成され、短時間で完了します。**完全**と**サンプル**のコピーは複数のテーブルを同時にコピーするため、テーブル数の多いプロジェクトでも短時間で完了します。**コピー結果**には、テーブルとともに各ディメンションの結果が一覧表示され、**Retry failed items**は失敗したテーブルとディメンションをまとめて再試行します。データを含めて作成した新しいコピーはユーザー専用の非公開となり、コピー元の ERP 書き込み承認のうち、ユーザー自身が付与できるものが維持されます。コピー元が Live で転記する場合、コピーは Simulate で作成されるため、Live に切り替えるまで ERP には何も送信されません。REST API と `project_copy` MCP ツールも `dimension_members` を受け付けます。[コピーするデータ量を選択する](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピー内の ERP 書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認)を参照してください。
- **行アクションメニュー（⋯）は、すべてのグリッド行の左端に配置されました。**
- **検証設定のない保存済みの ERP 書き込みステップは、検証のみの状態で開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS GL と AP Post、Xero のエクスポートです。明示的に実行を有効にしたステップは、そのままです。
- **長時間実行されるジョブの進行状況が、どこでも同じ形式で表示されます。**
- **ワークフローを停止しても後続のインポートが停滞しなくなり、開始されないステップはハングせずに失敗します。** 停止すると、キューに残っていたインポートステップとディメンションステップがキャンセルされるため、ワークスペース内の後続のインポートとディメンションのロードは通常どおり開始されます。ステップのジョブが約 40 分以内にどのワーカーでも開始されなかった場合、またはワーカーが開始した後に消失した場合、ステップは 24 時間のタイムアウトまで実行中と表示される代わりに、その旨のメッセージとともに失敗し、**ここから実行**を案内します。[ワークフローを実行する](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
- **REST、Import REST、Import Postman ステップは、ワークスペースのアップグレード時に RESTリクエストに変換されます。** 問題なく変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **プロジェクトのアーキテクトは、ダッシュボードで行制限付きテーブルのすべての行を閲覧できます。** これは Analyze で閲覧できる内容と一致します。アーキテクトのアクセス権の取り消しは、ダッシュボードにすぐに反映されます。これは、ユーザーのロールを変更した場合、ユーザーまたはそのグループをプロジェクトから削除した場合、プロジェクトのアクセスタイプを変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれでも同様です。以前アーキテクトだったユーザーは、行制限付きデータのすべての行を閲覧できなくなります。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
- **セッションの有効期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードに移動します。** [ダッシュボードを使用する](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは、認識できないフィールドを無視せずに拒否し、エラーにそのフィールド名を示します。** `workflow_upsert` は `memo` を受け付け、その別名として `description` も受け付けます。[不明なフィールドは拒否される](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2 では、Lakehouse が Parquet のエクスポートを Google Cloud Storage に直接書き込みます。** Google Cloud Storage のドキュメントアカウントへのエクスポートは、すべての行が先に PlaidCloud を経由するのではなく、アカウントのバケットに直接、アカウント自身の認証情報で書き込まれます。Amazon S3 と Azure Blob Storage のアカウントへのエクスポートは、従来どおりに動作します。[Export to Parquet ステップ](/ja/reference/workflow-steps/export/export-to-parquet/)を参照してください。
- **Slack、Microsoft Teams、Web Hook ステップは、メッセージが送信されなかった理由を示します。** ステップのエラーには、接続を試みたサーバーと、Slack と Teams の場合は接続が示され、何が問題だったかが説明されます。たとえば、Slack が Webhook を認識しなくなった、チャンネルに投稿できない、サーバーが見つからない、または 60 秒以内に応答しない、接続が削除されている、などです。Slack または Teams の Webhook URL は、それを知っている人なら誰でもユーザーの連携として投稿できてしまうため、表示されることはありません。[Notify via Slack ステップ](/ja/reference/workflow-steps/notifications/notify-via-slack/)を参照してください。

## 修正

- **無効なプロジェクト設定が、わかりやすいメッセージで報告されます。** 不明な環境またはドキュメントアカウント、使用済みまたは予約済みのスラッグ、無効なストレージタイプまたは転記モードは、汎用的なサーバーエラーではなく、問題を示すメッセージを返すようになりました。REST API では 500 ではなく 400 になり、AI アシスタントまたは MCP では無効な引数のエラーになります。
- **REST API のディメンション値リクエストが機能するようになりました。** `POST /rest/v1/analyze/query/retrieve-dimension-values` は、グリッドリクエストとして処理され、無効として拒否されていました。現在は、`value_columns` の各列について集計された値を 1 つ返します。グリッド（行フィルターと列フィルターの各組み合わせに対する 1 つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **テーブルの読み取りやファイル処理が遅くても、他のリクエストが止まらなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundation ファイルの登録、Excel へのエクスポート、REST または SOAP インポートのレスポンスの読み取り、ドキュメントアカウントの使用場所の検索、Panel アプリのコードやロゴのチェックは、それぞれが完了するまで、同じサーバーが処理している他のすべてのリクエストを停止させることがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールするようになりました。** 小さい画面や低い解像度では、追加と編集のダイアログがウィンドウより高くなり、**作成**ボタンと**更新**ボタンに手が届かないことがありました。現在は、フォームがスクロールし、ボタンは下部に固定されます。
- **Azure Blob Storage のドキュメントアカウントで、256 MiB を超えるファイルをコピー、移動、名前変更できるようになりました。** これまで、このサイズのファイルでは、これらの操作がいずれも失敗し、そのファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2 では、テーブルの行数が直前に書き込まれた内容を反映するようになりました。** テーブルに書き込んだステップやインポートが、書き込み前の行数を記録することがあり、読み込んだばかりのテーブルが 0 行と表示されたり、インポートが 0 行のインポートと報告されたりしていました。現在は、新しい行がすべての場所で参照できるようになってから件数を読み取るため、その後のステップも新しい行を読み取れます。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりした場合も、行数と列数が更新されます。
- **Weave の空の値のチェックは、各実行を、以前の実行が実際に残した状態と比較するようになりました。** ステップの空の値は、ステップがテーブルを再入力のために空にした直後にカウントされることが多く、そのため以前の実行には空の値がないように見え、常に一部が空だった列が、たった今そうなったかのように報告されていました。現在は、各実行がステップの終了時のテーブルの状態でカウントされます。以前に記録されたカウントは、正しいものと区別できないため使用されません。各ステップの空の値のチェックは履歴を最初から開始し、5 回の実行がカウントされるまで未チェックとして報告されます。また、行数と値の分布のチェックでは、あるステップの完了から 2 秒を超えて別のステップが同じテーブルに行う書き込みを、そのステップの実績として扱わなくなりました。[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **削除された接続を REST API で要求すると 404 が返されます。** 削除された接続や存在しない ID を要求すると、汎用的なサーバーエラー（500）が返されていました。現在は、接続 ID を示すメッセージとともに 404 が返されます。

## セキュリティ

- **アカウントのオーナーのみが、以前のバージョンを復元できます。** ドキュメントアカウントを以前のバージョンに復元する、バージョンを保留または解除する、バックアップを取る、といった操作は、アカウントのオーナーである必要があり、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴の表示には、アカウントへのアクセス権が必要です。
