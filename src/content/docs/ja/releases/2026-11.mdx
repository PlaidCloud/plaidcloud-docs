## 追加

- **コントロールプレーンの Trust Center で、セキュリティチームが PlaidCloud のセキュリティ文書を入手できます。** 管理者およびセキュリティのユーザーは、組織の **Trust Center** を開き、サブプロセッサー一覧や DPA などの公開文書をすぐにダウンロードできます。また、組織として一度セキュリティ文書用の NDA に署名すると、SOC 2 Type II レポートなどの制限付き文書が利用可能になります。ほかの管理者およびセキュリティのユーザーは、誰がいつ署名したかを確認できます。契約にすでに NDA が含まれている組織では、NDA を取得済みとして記録しておけば、署名なしで文書が利用可能になります。制限付き文書のダウンロードには透かしが入り、記録されます。NDA の新しいバージョンが出た場合は、あらためて同意する必要があります。管理者およびセキュリティのユーザーは、組織ごとに、新規または更新された文書と新しい NDA バージョンをまとめた日次メールを受け取るよう設定することもできます。このメールに文書そのものは含まれません。[Trust Center](/ja/administration/control-plane/trust-center/)を参照してください。
- **PlaidXL で、Excel 上でのレポート作成、ドリル、数値の説明、計画ができます。** **PlaidCloud** リボンタブは **接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有**にグループ化されています。よく使うコマンドは **PlaidXL** の右クリックメニューと **PlaidXL Cell** タブにもあり、主要なコマンドには変更可能なキーボードショートカットが割り当てられています（フィールドに入力している間は動作しません）。コマンドが失敗すると、どのコマンドがなぜ失敗したかが表示されます。サインイン前に実行したコマンドはサインインを開き、サインイン後に一度だけ実行されます。サインインは 1 つのワークスペースに対して有効なので、ワークスペースを切り替えると新しいワークスペースへのサインインを求められます（元に戻すときは求められません）。Office で Microsoft Entra の職場アカウントを使っている場合、PlaidXL がワークスペースを自動的に見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます。** **レポート**タブは、テーブルからライブレポートを配置します。1 つのディメンションを行にドリルダウンし、もう 1 つを列に並べ、交差する位置ごとに `CELL` 値を置きます。**Build my first report** は、お使いのデータからサンプルを作成します。ドリルすると、レポートは行全体や列全体を挿入または削除し、入力した値、メモ、書式はそれぞれの行に付いて移動します。[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only** は、ノード、ディメンション見出し、レポート値から、ライブの `DRILL` 数式への変換と編集を行います。**Custom drill** は、挿入前に行をプレビューします。メンバーピッカーでは、メンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりできます。`DRILL` では、除外するノードや展開するノードを指定でき、行方向に実行することもできます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値の根拠を説明できます。** **Explain this number** は、値が何を計算しているか、現在 PlaidCloud と一致しているか、元になっているテーブルとワークフローのステップを表示します。**Show detail rows** は、値の背後にある行を専用のシートに出力し、合計が一致するかのチェックも行います。
  - **Excel でガバナンスされたメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるのと同じビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計では `0` を、それ以外では理由付きの `#VALUE!` を表示します（`CELLS` のスピルでは空白）。**Metric...** は、プロジェクトのメトリックを現在の値とともに一覧表示します。メトリックでは、複数の代替階層でフィルターしたり、代替階層のメンバーを他のディメンションのメンバーと組み合わせたりできます。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに直接入力して計画できます。** `CELL` の値に数値を上書きすると、PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの形に合わせた配分、金額または割合による調整が可能で、保留したセルは変更されません。平均、中央値、最小値、最大値、標準偏差、分散のセルにも値を入力できます。入力した値は、行や列の挿入または削除に伴ってセルと一緒に移動します（削除されたセル内の値は報告されます）。**Undo last write** は、入力した値と保存を新しいものから順に取り消します。書き込みを元に戻せるのは、その書き込みを行った本人とワークスペースだけです。合計の取り消し、または空のセルに入力した平均の取り消しでは、その後に同じセルへ書き込まれた内容が保持されます。完了前に中断された書き込みは取り消せません。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要なものだけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新でき、各テーブルの進行状況と**キャンセル**がタスクペインに表示されます。PlaidXL の数式だけを再計算することもできます。大きなテーブルは、Web 版 Excel と最新のデスクトップ版 Excel で大幅に高速に取得されます（143,000 行・77 列のテーブルで、10 分以上かかっていたものが約 1 分になります。古いバージョンの Excel はこれまでどおり動作します）。Excel のセルに収まらない長さのテキストは、フラグが付けられ、切り捨てられた状態で保存されないようになります。取得したテーブルはデータ型ごとに書式設定された Excel テーブルとして届き、更新しても独自の列と数値書式が保持され、同じ場所で更新されます。取得や更新が他のセルを上書きしたり、別の Excel テーブルと重なったりすることはありません。Excel で扱えないほど大きな整数 ID と 1900 年より前の日付は、テキストとして届きます。テーブルを再取得しても更新リストに重複して追加されることはなく、**Stop refreshing** で 1 つ外すことができ、ディメンションはテーブルと一緒に更新されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud** は確認なしで書き込み、行った内容を表示し、**元に戻す**を提示します。これは、Lakehouse テーブルでは各保存から最長 7 日間使えます。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーの場合は、該当する行だけが置き換えられ、他のユーザーの行は保持されます。取得後にメンバーが変わったドリルスルーのシートは保存されません。保存に失敗した場合は、テーブルを戻せるように復元ポイントが示されます。[テーブルを PlaidCloud に保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルをplaidcloudに保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave** タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼するか、**Ask Weave about this cell** を選びます。Weave はあなたの権限で PlaidCloud を読み取り、変更するのはブックだけです。入力済みの内容を置き換える前には確認し、ブックの外に届く数式は書き込まず、各変更はペインを再読み込みするまで元に戻せます。[Excel で Weave に質問する](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1 つのシートまたはブック全体の値のみのコピーを共有できます。** **Convert to values** は、ブック全体、1 つのシート、または元に戻せない値のみへの変換（事前に確認します）を行います。変更されるのは PlaidXL の数式とそのスピルだけで、まだ計算中の数式は残されるので再試行できます。また、シート名を変更した後でも **Restore PlaidXL formulas** は引き続き使えます。
  - **タスクペインの外観が新しくなりました。** PlaidCloud の Web アプリに合わせ、ブランドブルー、レール型のタブとリスト、範囲が限定されたスクロール可能なカードに収められたテーブル、ディメンション、プロジェクト、列で構成されています。キーボードフォーカスにはわかりやすいリングが表示され、ペインは Office のライトテーマまたはダークテーマに従います。狭いペインではタブが 3 列 2 段に並び、幅が 560 ピクセル以上では 1 行に並びます。[ライトテーマとダークテーマ](/ja/reference/cli/plaidxl/connect/#ライトテーマとダークテーマ)を参照してください。
  - **ペイン内の数値は Excel の表示言語に従います。** 行数と列数、更新、再計算、Explain、数式、レポート、計画のメッセージには、お使いの Excel と同じ形式で数値が表示されます。たとえばドイツ語版 Excel では 4.812.233 と表示されます。セルに書き込まれる値は変わりません。
  - **更新中はシートのタブが黄色になります。** **Refresh All Tables** の実行中は、ペイン、リボン、Weave のどこから実行しても、各シートのタブがそのシートの更新中に黄色になり、完了、失敗、キャンセルのいずれかで元の色（ご自身で設定した色を含む）に戻ります。ブックを途中で保存して閉じた場合、次に PlaidXL がそのブックで起動したときにタブが元に戻ります。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
- **転記レジスターは、対応が必要なものから開きます。** 確認が必要なものがあるときは**例外**、承認待ちの依頼があるときは**承認**、それ以外のときは**すべての転記**が開きます。レールの画面は**自分の対応待ち**、**レジスター**、**インサイト**、**設定**にまとめられ、**例外**と**承認**には件数が表示されます。すべての画面で同じヘッダーとスコープバーを共有しており、期間（**This month**、**前月**、**過去 7 日間**、**過去 30 日間**、**カスタム**）、接続、プロジェクト、環境、エンティティ、そして**本番**、**シミュレーション**、**すべて**を選び、**リセット**するか **Saved scope** として保存できます。最後に使ったスコープは記憶されます。
  - **例外では、確認が必要なものを仕分けできます。** **Needs a look**、**未確認**、**保留中**、**失敗**、**Reversal outstanding** のチップに件数が表示され、接続の状態を示す行には「All N connections posting normally」と表示されます。すべての転記には、次に何をすべきかを示すツールチップ付きの、わかりやすい言葉の状態が付きます。未処理のものがない場合は **All clear** が表示されます。**Find a posting by ledger id** またはコマンドパレットに元帳 ID を貼り付けると、その転記を直接開けます。
  - **承認、委任、ウォッチは受信トレイ型の画面です。** **Waiting on me** と **Submitted by me** を切り替え、理由を添えて**承認**または**却下**し、複数をまとめて承認し、承認をトーストから**元に戻す**ことができます。**Delegate approvals** は短いダイアログで、**ウォッチ一覧**には自分がフォローしているものが表示されます。**転記を取消**と、一括の再試行およびクリアのダイアログは、同じレイアウトを共有しています。
  - **転記のドロワーで、何が起きたかがわかります。** 状態とその意味、名前付きの主要な事実、**Lines**、**履歴**、**承認**のタブが表示され、**レビュー済みにする**、**再試行**、**取消…**、**接続をウォッチ**、**実行をウォッチ**、**Copy link**（その転記を直接開きます）を使えます。
  - **アシスト、エクスポート、保持期間も同じデザインに従います。** **アシスト**には、質問ボックスとインサイトカード、**Draft — nothing applied** と表示されるアドバイス、**すべての転記**上の異常カードと **これらを表示** があります。**エクスポートとアラート**には **New schedule** があり、**保持期間**は 1 枚のカードにまとめられています。
  - **レジスターは常に最新の状態に保たれます。** レールのバッジは転記の変化に合わせて更新され、開いているリストは転記が変わると**更新**を提示し、開いているドロワーはその場で更新されます。**ホーム**の**要対応**の下には**転記レジスター**カードが表示されます。[転記レジスターを確認する](/ja/guides/connections/posting-register/)を参照してください。
- **プロジェクトホームが 7 つのページになりました。** テキストのみのレールに、**概要**、**変数**、**Schedules & sensors**、**Access & sharing**、**Data & connections**、**Data model**、**Apps & branding** が並び、変数の数、アクティブなスケジュールとセンサーの数、エレメントの数がバッジで表示されます。**概要**には、プロジェクトの説明とラベル、ロックの状態、テーブル、ワークフロー、ステップ、変数、公開テーブル、**データサイズ**（**ストレージ**を開きます）のタイル、直近 3 回のスケジュール実行、プロジェクトのデフォルトが表示されます。データサイズは**プロジェクト**画面と同じ合計で、復元用に保持されている以前のバージョンも含み、ツールチップで現在のデータと以前のバージョンの内訳がわかります。さらに、**プロジェクトレポート**（PDF またはインタラクティブ HTML）と**アーカイブのエクスポート**もあります。ほかのページでは、変数、スケジュール、センサー（**Calendar view** と **Activate** または **Deactivate** を含む）、プロジェクトとそのダッシュボードを開ける人、テーブルを読み取れるプロジェクト、ERP 転記モードを含む接続とテーブルストレージのデフォルト、Panel アプリ、ブランディング、プロジェクトのタイル画像を管理します。ロックされたプロジェクトにはバナーが表示され、コントロールは無効になります。[プロジェクトホーム](/ja/guides/projects/project-home/)を参照してください。
- **共有する列を 1 回だけプロジェクトエレメントとして説明すれば、テーブルのつながりも確認できます。** `Period` や `Org` など、複数のテーブルが共有する列名は、説明、タイプ、マスク、ディメンション、エイリアスを持つエレメントになります。その名前の列を持つすべてのテーブルでは、列自身に設定がない場合に、エレメントの説明、マスク、ディメンションが表示され、テーブルに保存されている内容は何も変わりません。プロジェクトホームの新しい **Data model** ページには、エレメントの一覧、各エレメントを共有するテーブルのグラフまたはマトリックス、型が異なるテーブルのフラグ、エレメントにする価値のある名前の提案が表示されます。エレメント名は、テーブルエクスプローラー、列のプロパティ、ステップのデータマッピングタブで、列の横に表示されます。Data Foundation プロジェクトには、共有される Common Finance Model の列用のエレメントが最初から含まれています。エレメントは REST API と `element_find`、`element_upsert`、`element_delete` の MCP ツールで管理でき、AI アシスタントは各列のエレメントの意味を参照できます。[データモデルとプロジェクトエレメント](/ja/guides/projects/data-model/)を参照してください。
- **ドキュメントは概要から開き、ページのレールが付きました。** **概要**、**参照**、**Your accounts**、**管理**がレールに並び、各ページにはタイトル（多くはサブタイトル付き）とヘッダー内のアクションがあります。**概要**には、アカウントのタイル、**Pinned** ファイル（ファイルを選択した状態でそのフォルダーの**参照**を開きます）、サービス別のアカウント、利用できるユーザーが表示されます。**Your accounts** は使えるすべてのアカウントの 1 つのリストで、各行に**共有済み**または**プライベート**のピルが付きます。**管理**には自分が所有するアカウントが一覧表示され、ワークスペース管理者はここで、すべてのドキュメントアカウントを確認でき、管理できるアカウントであればどれでも管理できます（システム管理のアカウントは拒否され、管理対象バケットのアカウントは複製できません）。行の **⋯** メニューには、**開く**、**編集**、**複製…**、**Who can use it**、**使用箇所…**、**Version history**、**有効にする**または**無効にする**、**削除**があります。アカウントはページとして開き、**一般**、**アクセス**、**Credentials**、SFTP の場合は **SSH** のカードがあります。未保存の変更がある状態で離れるときは確認されます。**参照**はお気に入りのアカウント、またはワークスペースのデフォルトを開き、ラベル付きのツールバー、行メニュー、ドラッグ＆ドロップによるアップロード（ファイルリストまたはフォルダーにドロップするとそこへアップロードされ、ツリーの空白にドロップするとアカウントのルートへアップロードされます）、そして各アップロードとテーブルへのインポートの進行状況とアクションを表示する **Uploads and imports** パネルがあります。**Pop out** は、フォルダーを新しいブラウザータブで開きます。[ドキュメント](/ja/guides/documents/)と[ドキュメントアカウントの使用](/ja/guides/documents/using-document/)を参照してください。
- **ダッシュボードは概要から開き、ページのレールが付きました。** **概要**、**ダッシュボード**、**アプリ**、**Notebooks**、そしてワークスペース管理者向けの**アクセスレビュー**がレールに並び、下部には、別ウィンドウで開くことを示す印が付いた **Open navigator ↗** があります。各ページにはタイトル（多くはサブタイトル付き）とヘッダー内のアクションがあります。**概要**には、ダッシュボードとアプリのタイル（対応する一覧がフィルター済みの状態で開きます）、最近開いた、またはスターを付けたもの、失敗したアプリ、自分の対応待ちのアクセスリクエスト、利用状況へのアクセス権を持つメンバー向けに最も多く開かれたダッシュボードが表示されます。**ダッシュボード**は **すべて**、**You manage**、**お気に入り**で絞り込め、**アプリ**には各アプリの**種類**とライブの状態が表示されます。[ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。

- **Git アプリにリポジトリが一覧表示され、できることが示されます。** アプリリストの **Git** には、自分のロール（**Administrator**、**Contributor**、**閲覧者**）と、ワークスペースのリポジトリが表示され、各リポジトリには説明、最終更新日、コピーボタン付きのクローン用アドレス、**開く**が付きます。**Set up Git on your computer** カードでは、Git のインストール、トークンの作成、クローンの手順を案内し、**How to clone** でもう一度開けます。**View all in Git** は Git のインターフェース全体を開き、**Manage who can push** はグループ管理を開きます。アクセス権は **閲覧者**、**Contributor**（アプリのコードを `apps` にプッシュ）、**Administrator**（`udfs` を含むすべての場所にプッシュ）のいずれかで、閲覧者には問い合わせ先として最大 3 人のワークスペース管理者が表示されます。新しい **Git Contributors** グループは Contributor 権限を付与し、デフォルトグループにすることもできるため、新しいメンバーは自動的に権限を得ます。**Git Administration** は管理者権限を付与します。メンバーの **Git** タブには、Git のユーザー名、レベル、権限を付与しているグループが表示されます。メンバーの Git アカウントはメンバーシップに連動し、メンバーを無効化または削除すると、約 1 時間以内にそのメンバーの Git アカウントがトークンと SSH キーも含めてブロックされ、再び有効にするとブロックが解除され、リポジトリと履歴は保持されます。シングルサインオンで Git にサインインすると、メンバー本人のアカウントが開きます。Contributor は、ワークスペースの Git 組織内にリポジトリを直接作成することはできず、リポジトリは PlaidCloud を通じて作成されます。アプリのウィンドウには**リポジトリ**セクションが表示され、UDF には**開く**があり、Git にはワークスペースへの **← Back to** リンクがあります。アプリリポジトリや組み込みの `apps` および `udfs` リポジトリを含め、プラットフォームが作成するすべてのリポジトリは、ワークスペースのサインイン済みの全メンバーが読み取れるため、メンバーはリポジトリごとの設定なしにアプリを開き、再公開できます。Git 管理者は、リポジトリをプライベートにすることもでき、その場合、リポジトリピッカーに表示されなくなり、メンバーはそのリポジトリからの公開や、そこに保存された Git ベースの UDF コードの実行ができなくなります。[PlaidCloud Git](/ja/guides/git/#git-を開く)と[リポジトリを閲覧できる人](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)を参照してください。
- **Cost to Serve と Operational Transfer Pricing のテンプレートは Common Finance Model を土台としています。** **Cost to Serve** からプロジェクトを開始すると、部門ごとに設定したアクティビティとドライバーに基づいて営業費用を顧客に配分し、各顧客に対するサービス提供コスト控除後のマージンを、総勘定元帳に紐付けて確認できます。**Operational Transfer Pricing** から開始すると、各エンティティの利益水準（売上高利益率、ネットコストプラス、再販価格基準）をポリシーの範囲に照らしてテストでき、範囲外のエンティティを目標に戻すためのトゥルーアップも行えます。売上高利益率は、EBIT を被テスト当事者の売上高で割った値です。[Cost to Serve](/ja/guides/projects/cost-to-serve/)と [Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/)を参照してください。

- **Data Foundation のプロジェクトを複製するか、テンプレートとして保存できます。** **アクション > 複製...** は、モデルの編集内容、メトリック、分析パスとともにプロジェクトをコピーします。**Save as my template...** は、設定をドキュメントアカウントに保存し、**From a template file...** は、そこから新しいプライベートプロジェクトを開始し、ソースは接続待ちの状態になります。[プロジェクトを複製する](/ja/guides/projects/data-foundation/#プロジェクトの複製)と[マイテンプレートとして保存する](/ja/guides/projects/data-foundation/#マイテンプレートとして保存)を参照してください。
- **Data Foundation のセットアップチェックリストは引き渡しまでカバーし、アシスタントが残りの項目を解決できます。** チェックリストには、夜間更新、エビデンスパック、プロジェクトのオーナーへの引き渡しが追加され、プロジェクトをセットアップした人も表示されます。タイプのない勘定科目、複数のソースが使うコード、どれにも一致しなかったファイルの列について、アシスタントに回答案を提案させることができます。アシスタントは何も書き込まず、回答はあなたが適用します。[Data Foundation を始める](/ja/guides/projects/data-foundation-getting-started/)と [Ask で未解決の質問を解決する](/ja/guides/projects/data-foundation/#ask-で未解決の質問を解決する)を参照してください。

- **やりたいことを Weave に伝えると、Weave が作成して実行します。** プロジェクト、ワークフロー、ステップ、インポート、ディメンションを作成するダイアログ、および空のリストとキャンバスには、**Tell Weave what you want** が表示され、その横に **Fill in the form instead** があります。ワークフローを説明すると、Weave は 1 枚のプランカードで答えます。承認すると、ステップがキャンバスに現れ、**Built by Weave** と表示され、**停止**でビルドを終了できます。Weave に、ワークフロー、ステップの範囲、または 1 つのステップの実行、ワークフローのスケジュール設定やスケジュールの変更、ステップの変更または追加を依頼できます。いずれも承認するカードとして表示され、すべての実行で ERP 転記はオフになり、ERP への転記や PlaidCloud 外への書き込みを行うステップは Weave は手を付けず、あなたに任せます。データファイルをプロジェクトの**概要**やキャンバスにドロップするとテーブルまたはインポートステップが作られ、SQL スクリプトをドロップまたは貼り付けると標準ステップとして再構築され、Alteryx ワークフロー（またはそれらを含むフォルダー名）を渡すと、Weave が新しいプロジェクトに変換し、実行して、その結果を、元のワークフローが書き出したファイルと比較して移行レポートにまとめます。インポート後には、**次の推奨ステップ**が最初のチャートやクリーンアップを提案します。[Weave でビルドして実行する](/ja/guides/ai-assistant/weave-build/)を参照してください。
- **Weave はすべてのアプリのそばにいて、どこからでも質問できます。** ウィンドウ右側の **Weave dock** には、Weave との会話、Weave が提案する変更、ジョブが収められています。クリックまたは **Ctrl+J**（Mac では **Cmd+J**）で開き、幅を記憶し、現在開いているものを起点として、削除可能なチップで表示します。未読の問題の件数とメニューを備えた **Weave** ボタンはドックのヘッダーにあり、折りたたんだドックには、対応待ちの件数が表示されます。ステップ、複数のステップ、ワークフロー、テーブル、列、ダッシュボード、ログのエラー行を右クリックして、**説明**、**Where is this used**、**変更内容**、**チェック**、**修正**、**Change…**、**ドキュメント**、**Weave に質問**を選べます。ほとんどは AI モデルを呼び出さずに答え、Weave がどうやって知ったかも示します。コマンドパレットは、**Weave に質問**、ヘルプトピック、Weave のアクション、ログエントリ、エラーメッセージの質問に答え、Panel Studio とサポートからもドックが開きます。ブラウザーでは、マイクをクリックして声で質問し、回答の要約を音声で聞けます。Weave を訂正すると、その用語をプロジェクトの全員向けに記憶するよう提案されます。質問するまで何もスキャンされません。[Weave ドック](/ja/guides/ai-assistant/weave-dock/)を参照してください。
- **Weave はワークフローの作成中にも手助けします。** ステップフォームの空のフィールドには、**Tab** または**使用**で採用できる候補（結合キー、新しいステップの列マッピング、フィルター、式）が、その根拠とともに表示されます。新しいステップの横の **What next?** は、次のステップを提案します。**Count rows** は、保存前にステップが書き込む行数を、通常の範囲と比較して数え、ステップにポインターを合わせると、そのテーブルの行数が表示されます。ワークフローの実行時には設定がチェックされ、問題が見つかったときだけ、**確認**と **Stop run** とともに通知されます。失敗したステップのインスペクターのカードには、**修正**または **Weave に質問**が表示されます。[ワークフローエディターでの Weave](/ja/guides/ai-assistant/weave-editor/)を参照してください。
- **失敗したステップをワンステップで修正できます。** ステップを右クリックして**修正**を選ぶか、ログエントリまたはインスペクターの**修正**を使います。Weave は、何が変わるか、どこまで影響するか、次に何が起きるかを示すカードを表示します。1 回の承認で、複数のステップにまたがる場合も含めて修正が適用され、修正したステップが ERP 転記オフで再実行され、問題が解消したかどうかがはっきり伝えられます。スケジュール実行が失敗した場合は、Weave がすぐに修正を準備し、そのカードは **Monitor**、ログエントリ、ドックで、失敗した実行に紐付けられて承認を待ち、**Apply and re-run** が表示され、所有者には PlaidCloud とスマートフォンで通知されます。承認はブラウザーでのみ行えます。不在中に Weave が準備したカードは、会話内に **Waiting for you** の行として残り、そこから開けます。状況が変わっている場合は、現在の状態も表示されます。Weave が行う変更のうち元に戻せるものには、それぞれ**元に戻す**があり、カード全体を 1 回の操作で戻せます。戻す前に、何が復元されるかが表示されます。[AI によるワークフローエラーの修正](/ja/guides/ai-assistant/fixing-workflow-errors/)を参照してください。
- **Weave のジョブは、画面を離れても動き続けます。** ドックの **Weave** ボタンから **Weave jobs…** を選ぶと、各ジョブの状態の確認、進行状況の追跡、会話を開く、停止ができます。ドックやタブを閉じてもジョブは続行され、完了したときや対応が必要なときにメッセージが届きます。また、1 分を超えて実行され、停止されなかったジョブについては、アプリを使っていればスマートフォンにも通知されます。[動き続けるジョブ](/ja/guides/ai-assistant/weave-dock/#処理を続けるジョブ)を参照してください。
- **Weave に Monitor ができました。** **Weave** タブの**検出事項**ページは **Monitor** になり、レールには**検出事項**、**チーム**、**アクティビティ**、**月次サマリー**、**想定内**、**リクエスト**がまとまり、クローズチェックの**準備状況**と**照合**は **Close checks** の下にあります。**検出事項**は、「未解決の問題が 3 件あり、1 件があなた宛てです。」のような Weave の判定、不在中に起きたこと、クローズの進み具合を示す 1 行から始まります。タイルには、未解決の問題、担当者のいない問題、最も古い未解決の問題が表示されます。検出事項は重大度別にグループ化され、ほかにどれだけ影響が及ぶかで順位付けされ、失敗した実行は 1 行にまとめられて、その影響を受けるワークフローとダッシュボードがその下に折りたたまれます。各行には、所有者、未解決の経過時間、1 つのアクションが表示され、**修正**または**開く**が先頭に、残りは **⋯** の下に置かれます。行を開くと、Weave の説明、根拠、Weave がどうやって知ったか、コメントを読めます。**所有者**と**ワークフロー**で絞り込めます。**Suggestions** では、誰かが一定のパターンで手動実行しているワークフローに **Automate this** が表示され、スケジュールが提案されます。**これは想定内**は、ある範囲を今後は正常として扱うよう設定し、**想定内**には、Weave がプロジェクトについて学習した用語や慣例も一覧表示されます。[Weave タブ](/ja/guides/ai-assistant/weave-tab/)を参照してください。
- **クローズは夜間に準備されます。** 期限が設定された準備状況セットでは、Weave が毎日、またその前提となる実行の後に、クローズを確認し、対応できる問題ごとに修正または再実行を準備して、「月次クローズは 92% 完了しています。2 件の対応が必要です。」のような 1 枚のカードを表示します。各判断には番号が付き、それぞれに承認用のカードがあります。[夜間に準備されるクローズ](/ja/guides/ai-assistant/weave-readiness/#夜間に準備される締め処理)を参照してください。
- **Weave の回答を保持し、レポートとアラートを依頼できます。** 回答の下の **Keep ▾** で、その回答を定期リクエスト、メトリック、ホワットイフシナリオ、チームレシピ、ピン留めした回答として保持できます。レポートまたはアラートを、スケジュールで、またはワークフローの実行後に、自分の言葉で Weave に依頼すると、PlaidCloud、スマートフォン、そして（数値を除いて）メールで通知されます。リクエストは **Monitor → Requests** で、**Run now**、**一時停止**、**Change**、**削除**を使って管理します。[回答と定期リクエストを保持する](/ja/guides/ai-assistant/weave-requests/)を参照してください。
- **数値がなぜその値なのかを尋ねられます。** テーブルエクスプローラーのセル、またはダッシュボードのチャートの点やセルを右クリックして **Why this number** を選ぶと、Weave が、その値を書き込むステップとその元、前回の実行および前期からの変化を示します。テーブルエクスプローラーの **As of** は、テーブルの以前のバージョンを、それを書き込んだ実行別に一覧表示し、**Compare with now** は、その後どの行と列が変わったかを示します。配賦結果についてのホワットイフを言葉で質問すると、すぐに見積もりが得られます。照合の最新の結果は保持され、たとえば「06:02 に Cost Pool と一致しました。」と表示されます。[数値がその値である理由](/ja/guides/ai-assistant/weave-numbers/)を参照してください。
- **Weave をチームで共有できます。** 回答をピン留めすると、プロジェクトの全員に表示され、それぞれ自分のアクセス権で再実行できます。質問をレシピとして保存すると、誰でもドックから `/` で、またはトリガーで実行できます。どちらもプロジェクトの**概要**の **From your team** に一覧表示されます。ステップ、ワークフロー、テーブル、検出事項にはコメントスレッドがあり、チームメンバーへのメンションや @Weave への質問ができ、Weave がワークフローを処理している間はキャンバス上に表示されます。[Weave をチームで共有する](/ja/guides/ai-assistant/weave-team/)を参照してください。
- **Weave の効果を確認できます。** 一部の検出事項では、通知する価値があったかどうかを、高評価と低評価のボタンで尋ねます。**月次サマリー**には、Weave の検出事項と回答がどれだけ役に立ったか、Weave が修正した失敗した実行、チームメンバーが再利用したピン留めした回答が、節約できた時間の見積もりとともに、プロジェクト単位またはあなた個人について表示されます。[Weave の月次サマリー](/ja/guides/ai-assistant/weave-monthly-summary/)を参照してください。
- **モバイルの Weave では、音声入力がワンタップになりました。** マイクをタップして質問を話すと、話し終えたところで Weave が送信します。もう一度マイクをタップすると途中で終了でき、何も聞こえないときは自動的にオフになります。話の途中で **Weave** タブを離れたり、アプリをバックグラウンドにしたりしても、話した内容は未送信のまま質問ボックスに残るので、確認できます。実行、一時停止、停止、再開は、確認画面での誤った二重タップを無視します。アプリのバージョン 1.3.0 以降が必要です。[音声を使う](/ja/guides/mobile-app/weave-on-mobile/#音声を使う)を参照してください。
- **Weave から問題がメールで届きます。** ご自身向けに、ワークフローの実行が確認すべき重大な問題で終了したときのメールと、まだ読んでいない Weave からの通知をまとめた日次サマリー（時刻は選択可能）をオンにできます。メールには、プロジェクト名と、各ワークフロー、ステップ、テーブル、メトリックが問題の種類とともに記載され、**Weave** タブへのリンクが付きますが、データの数値や値は含まれません。ワークスペース管理者は、全員の Weave メールをオフにしたり、各メンバー自身のタイムゾーンで、終了までアラートを保留するサイレント時間を設定したりできます。[Weave メール](/ja/guides/ai-assistant/weave-email/)を参照してください。
- **Weave によるデータの使われ方を確認できます。** **Weave** メニュー、すべての AI チャットの下、**AI機能**に新しいパネルが加わり、ワークスペースの Weave に回答する AI プロバイダーとその所在地、Weave がそのプロバイダーに送信する内容、学習と保持についてまだ確認中の事項が示されます。[Weave によるデータの使われ方](/ja/guides/ai-assistant/weave-data-use/)を参照してください。

## 変更

- **フィルターできる 1 つのチェックリストで、あらゆる場所のユーザー、グループ、ワークフローを割り当てられます。** セキュリティグループのメンバー、メンバーのグループとの関連付け、配布リストのメンバー、ドキュメントアカウントのメンバー、グループ、エージェント、所有者、接続アクセス、Weave の準備状況セットのワークフローが、ドラッグで移動する 2 つのリストではなく、同じピッカーを使うようになりました。名前やメールアドレス（`@example.com` のようなドメインを含む）で絞り込み、メールアドレスの一覧を貼り付けてそのユーザーだけに一致させ、**すべて**、**割り当て済み**、**Not assigned** を切り替え、**Assign all shown** または **Unassign all shown** を使えます。変更した行には **Will add** または **Will remove** のピルが付き、**Undo changes** で元に戻せます。保存ボタンは、変更があったときだけ使えます。フィルター内の **Enter** では保存されず、**Space** で選択中の行にチェックが入ります。アクセスを確認できても変更できない場合、リストは読み取り専用です。
- **ワークスペースが Grok を使っている場合、モバイルの Weave は AI に関する通知への同意を再度求めます。** 通知には、xAI がお客様のデータをモデルの学習に使わないという記載がなくなりました。現在は、PlaidCloud は xAI とゼロデータ保持契約を結んでおらず、xAI がデータを保持し、標準の利用規約で認められる範囲で使用する可能性があることが記載されています。[Weave によるデータの使われ方](/ja/guides/ai-assistant/weave-data-use/)を参照してください。
- **What if ウィンドウは、一度に 1 つの期間を読み取ります。** Allocation Split ステップの出力に期間列がある場合、ウィンドウは最新の期間で開き、**期間:** で別の期間または **All periods** を選択できます。ドライバーがすべての期間に行を持ち、全期間にわたって読み取るには大きすぎるステップでも、1 つの期間について開いて回答できるようになりました。保存したシナリオは、保存時の期間（ある場合）を保持し、開くと、その期間がまだ一覧にある限り、ウィンドウがその期間に移動します。[期間を選択する](/ja/guides/allocations/results/driver-what-if/#期間を選択する)を参照してください。
- **PlaidCloud の Web アプリと Python クライアントライブラリは REST API を使用し、JSON-RPC は非推奨になりました。** Web アプリは、リクエストを REST API に送信します。`plaidcloud-rpc` 1.25.0 以降では、`SimpleRPC` の呼び出しはコードを変更せずに REST API に送られます。REST API がまだ対応していない呼び出しや、古いリリースのままのワークスペースでは、従来どおり JSON-RPC が使われます。JSON-RPC は今後のリリースで削除されるため、スクリプトとノートブックを `plaidcloud-rpc` 1.25.0 以降にアップグレードし、新しい連携は REST API に対して作成してください。[コマンドライン](/ja/reference/cli/jupyter/command-line/)を参照してください。
- **ステップは、別の環境に固定しない限り、プロジェクトの接続環境に従います。** プロジェクトの環境（QA と本番など）を切り替えると、すべてのステップが移動します。1 つの環境にとどまる必要があるステップには、代わりに **Fixed environment** を設定できます。フォームには警告が表示され、ログには、プロジェクトの環境以外で実行されるたびにその旨が記録され、プロジェクトを切り替えるときには、従わないステップの名前が表示されます。ERP 転記ステップは、常にプロジェクトの環境を使用します。プロジェクト、固定されたステップ、またはエージェントが使用している環境は削除できず、エージェントフォームのフィールドは **Environment this agent serves** になりました。[ステップを 1 つの環境に固定する](/ja/guides/projects/managing-projects/#ステップを1つの環境に固定する)を参照してください。
- **ステップフォームは 1 つのレイアウトに統一されました。** タブには、標準の名前が標準の順序で付けられています。一般、設定、ソース、列、フィルター、出力、詳細設定です。ERP 転記フォームには、ヘッダー列と明細列も加わります。必須フィールドには * が付き、フォームは、ステップに必要なものがない場合にのみ保存をブロックします。
- **Acumatica、Bill.com、Dynamics、Eclipse、HFM/FCCS、NetSuite、Workday、Workday Financials の接続は、設定を失うことなく作成、編集し、ステップで選択できます。** これらは REST 接続として保存され、**接続**の一覧にはそれぞれのタイプが表示されます。接続を右クリックして **Edit REST settings** を選ぶと、ヘッダー、認証、ページングを開けます。**接続をテスト** は、保存済みの NetSuite 接続と HFM/FCCS 接続で使用できます。Workday Financials 接続は、統合システムユーザーとそのパスワード（両方を指定）または OAuth クライアントでサインインし、Workday、Bill.com、Dynamics、Eclipse のフォームには **APIホスト** フィールドがあります。[接続の作成と管理](/ja/guides/connections/create-connection/)を参照してください。
- **データ入力フォームでは、各フィールドがラベルの隣に配置されます。** Data Foundation の **接続** と **ソース**、ドキュメントアカウントの設定、メンバープロファイルで、フィールドは右端に寄せられず、一定の幅で左揃えになります。
- **Copy Project は、テーブルデータとディメンションメンバーを別々に選択でき、データのコピーが高速になり、プライベートコピーの ERP 書き込み承認も保持されます。** **Data to copy** で、**Table data**（**No table data**（デフォルト）、**完全**、**サンプル**）を選択し、それとは別に、デフォルトでオンの **Copy dimension members** を選択します。そのため、テーブルの行を含まないコピーでも、ディメンションにはデータが入った状態で届き、短時間で作成できます。**完全**と**サンプル**のコピーは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも短時間で完了します。**コピー結果**には、テーブルとともに各ディメンションの結果が一覧表示され、**Retry failed items** は、失敗したテーブルとディメンションをまとめて再試行します。データ付きで作成した新しいコピーは、あなた専用のプライベートなものとなり、あなた自身が付与できるソースの ERP 書き込み承認を保持します。ソースが本番で転記している場合、コピーはシミュレートで作成されるため、本番に切り替えるまで ERP には何も届きません。REST API と `project_copy` MCP ツールも `dimension_members` を受け付けます。[コピーするデータ量を選択する](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーでの ERP 書き込み承認](/ja/guides/projects/managing-projects/#コピーでのerp書き込み承認)を参照してください。

- **すべてのテーブルで、レイアウト、フィルター、行アクションが統一されました。** 左側には、**新規**や**開く**などの独自のアクションが最初に並び、続いて**アクション**、ビューがあるテーブルでは**ビュー**、右端にアイコンの**更新**が並びます。**その他**メニューを持つツールバーはなくなり、あまり使わないコマンドは**アクション**に入っています。たとえば、テーブルでは**ストレージ**と **Download Table**、ワークフローでは**すべて停止**と**ステータスをクリア**、ワークフローの詳細ウィンドウでは **選択した項目を移動**、**診断モード**、**ワークフローをロック**、**依存関係**、**フラッシュバック**で、移動の矢印はツールバーに残ります。**フィルター**はすべてのテーブルの下部、行数の横にあり、**/** または Ctrl/Cmd+F でジャンプでき、ツリービューでは 1 つのフィルターでツリーとフラットリストの両方が絞り込まれます。テーブルリストにはフィルターの横に **すべて | 公開済み** の切り替えがあり、ディメンションの階層には、フィルターが検索するツリーを選ぶ **メイン | 両方 | 代替** の切り替えがあり、**代替階層を表示**、列、レイアウトは**ビュー**メニューにあります。ロックされたワークフローでは、詳細ツールバーに **Locked** のマークが表示され、ワークフローを編集できる場合は、クリックしてロックを解除できます。接続とプロジェクトのセキュリティリストにもフィルターが加わりました。**データ共有**、Scheduled events、**フラッシュバック**、ワークフローの実行履歴、メンバーの**行アクセス**リストも、ほかのリストと同様に、フィルター、更新、行メニューの表示、**Enter** での開く操作に対応し、**F5** で更新できます。**削除**では、確認が求められるようになりました（データ共有では、以前は確認がありませんでした）。すべてのダイアログで、**キャンセル**または**閉じる**が右端のボタンです。
- **行アクションはどこでも同じです。** 行のメニューは、行の先頭の **⋯** ボタン、右クリック、またはツールバーの**アクション**メニューから開きます。常に、**開く**、**詳細**、**編集**が最初に並び、続いてそのリスト固有のアクション、最後に**削除**（または一覧から取り除く操作）が並びます。行に適用できないアクションは、その位置でグレーアウトされます。**Enter** と **Del** は、それらが実行する項目に表示されます。行のアクションが 1 つだけのリストでは、**⋯** の代わりにそのアクションのアイコンが表示され、ダッシュボード、アプリ、Notebooks では**開く**アイコンが再び表示されます。[行アクションメニュー](/ja/guides/dashboards/using-dashboards/#行アクションメニュー)を参照してください。

- **PlaidCloud の外観が、ライトとダークの両方で、青を基調に一新されました。** ボタン、チェックボックス、選択された行、タブ、リンク、ワークスペースのページを一覧表示するレールには、1 つの PlaidCloud ブルーが使われ、両方のテーマで読み取れるコントラストが確保されています。アプリのタブアイコンは、統一されたセットになりました。

- **検証設定のない保存済み ERP 書き込みステップは、検証のみで開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS の GL と AP の Post、Xero のエクスポートです。明示的に本番実行に設定されているステップは、そのまま本番のままです。
- **実行時間の長いジョブは、どこでも同じ方法で進行状況を表示します。**
- **ワークフローは正しく停止し、失敗し、正直に報告します。** ワークフローを停止すると、それが開始したものがすべて停止します。完了できない実行やステップは、ハングせずに理由付きで失敗し、実行ステータスは実際に実行された内容と一致します。
  - **ワークフローを停止すると、それが開始したものがすべて停止し、完了できない実行やステップはハングせずに失敗します。** 停止すると、キューに残っていたインポートとディメンションのステップがキャンセルされるため、ワークスペース内の後続のインポートとディメンションのロードは通常どおり開始され、ワークフローのキュー済みまたは実行中のコネクター（Singer）同期も停止されます。ステップのジョブを開始できない場合、ステップは永久に待機せず、理由付きで失敗します。理由は、約 40 分以内にどのワーカーも開始しなかった、ワーカーが開始した後に消えた、Pod が約 20 分間 Pending のままである、イメージを約 5 分間取得できない、約 20 分間 Pod が作成されない、のいずれかです。どのランナーも約 30 分以内に取得しなかったコネクター同期は、同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間は、ステータスメッセージに、経過した分数とともに「Waiting for a worker…」と表示され、作業が開始されると消えます。マクロを停止すると、その実行中のコピーがすべて停止します。1 つのコピーを停止した場合や、応答しなくなったコピーを **Macro Concurrent** ステップが見限った場合は、それを呼び出したワークフローは実行を続けます。他のワークフロー内でのみ実行されているマクロは、ワークフローリストで**実行中**と表示され、**停止**を使えるほか、各ステップのステータス、開始時刻、終了時刻が最新の実行から表示されます。サーバーが失われた実行は失敗として終了し、12 時間経っても実行中の場合は、「Run failed: still running at the 12-hour limit. Re-run the workflow.」で失敗します。[ワークフローを実行する](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
  - **再開、実行履歴、実行ステータスは、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローの残りがすべて実行されます。これは、子ワークフローのステップを単独で再実行した後でも同様で、1 回の実行内の子ワークフローの各呼び出しには、それぞれ実行履歴のエントリがあります。サーバーが停止したために再起動したステップは、ログにその旨が記録され、`workflow_run_status` と REST API の実行結果では、失敗したが続行されたステップが `continued_step_ids` と `continued_step_count` に一覧表示され、実行が問題なく完了したとは報告されません。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。
  - **ステップのエラーには、そのエラー固有のメッセージが表示されます。** PlaidCloud が想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードには、エラーが 1 行で表示され、その後に削除されたワークフローの実行は含まれません。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。
  - **完了しない ERP 抽出は、そのステップを失敗させ、再開すると続行されます。** **SAP: アドホック抽出**が行数または時間の上限で一時停止したとき、またはエージェントが時間内に応答しないとき、あるいは Salesforce、Oracle Fusion バルク、HFM/FCCS のエクスポートジョブが、ステップが待機をやめた時点でまだ実行中のときは、ステップが失敗するため、後続のステップが部分的なテーブルに対して実行されることはありません。ワークフローを再開するか、ステップを再実行すると、抽出は停止した位置から、同じジョブで続行されます。[実行制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)を参照してください。
  - **エクスポートをキャンセルすると、ウェアハウス内のクエリも停止します。** エクスポートまたはダウンロードがキャンセルされた場合（ワークフローの停止によるものを含む）、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplum では、そのデータを読み取るクエリも停止し、リモートデータベースへのエクスポートはソースの読み取りを停止して、最後まで実行されることはありません。
- **REST、Import REST、Import Postman のステップは、ワークスペースのアップグレード時に REST Request に変換されます。** きれいに変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **セッションの期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードに移動します。** [ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは、認識できないフィールドを無視せずに拒否し**、エラーにそのフィールド名を示します。`workflow_upsert` は `memo` を受け付け、その別名として `description` も受け付けます。[不明なフィールドは拒否されます](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2 では、Lakehouse が Parquet のエクスポートを Google Cloud Storage に直接書き込みます。** Google Cloud Storage のドキュメントアカウントへのエクスポートは、すべての行がまず PlaidCloud を経由するのではなく、アカウント自身の認証情報で、アカウントのバケットに直接書き込まれます。Amazon S3 と Azure Blob Storage のアカウントへのエクスポートは、これまでどおり動作します。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/)を参照してください。
- **Slack、Microsoft Teams、Web Hook のステップは、メッセージが送信されなかった理由を示します。** ステップのエラーには、接続しようとしたサーバーと、Slack と Teams では接続が示され、何が問題だったかが示されます。たとえば、Slack がもうこの Webhook を認識しない、チャンネルに投稿できない、サーバーが見つからない、または 60 秒以内に応答しない、接続が削除されている、などです。Slack や Teams の Webhook URL は、それを知っていれば誰でもあなたの連携として投稿できてしまうため、表示されません。[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/)を参照してください。

- **ワークスペースの組織、所有者、リリース、バージョンは PlaidCloud が設定し、データセンターは自分で選べます。** コントロールプレーンで作成したワークスペースは、あなたが所有し、PlaidCloud が設定するリリースチャネルに配置され、**Data Center** はサインアップ時に提示されるリージョンから選択します。ワークスペースの編集時には、組織、所有者、リリース、バージョンは読み取り専用です。バージョンの変更には **Set Version** を使い、ワークスペースの移動、所有者またはチャネルの変更、固定は PlaidCloud サポートに依頼してください。[ワークスペースの構成](/ja/administration/control-plane/workspace-configuration/#基本設定)を参照してください。
- **エンコード変換ステップで、フォルダーのサブフォルダーを保持できます。** **ドキュメント: ファイルをASCIIエンコードに変換**、**ドキュメント: ファイルをUnicode（UTF-8）エンコードに変換**、**ドキュメント: ファイルをUnicode（UTF-16）エンコードに変換**には、**サブフォルダーを保持**ボックスがあります。オンにすると、入力フォルダーのサブフォルダー内の各ファイルが、出力先の対応するサブフォルダーに書き込まれ、圧縮ファイルの内容は、そのファイルがあったサブフォルダーに入ります。オフのままの場合は、これまでどおり、すべてのファイルが出力先そのものに書き込まれます。[Convert Document Encoding to UTF-16](/ja/reference/workflow-steps/document/convert-document-encoding-to-utf-16/)を参照してください。
- **ソーステーブルがステップの設定と一致しない場合、ステップは何も書き込まずに停止し、すべての問題を一度に示します。** Table Extract、Table Lookup、Table Inner Join、Table Cross Join、Table Outer Join、Table Anti Join、複数テーブル結合、Table Union Distinct、Table Union All、Table Pivot、Table Melt、Table In-Place Delete、Table Upsert、Table Append の各ステップは、書き込む前にソーステーブルをチェックします。ステップが読み取る列がテーブルにない、結合キーがない、またはステップのソース列にない、ステップが読み取るソーステーブルがまだ作成されていない、といった場合は、それぞれの問題と修正方法を示す 1 つのエラーでステップが停止し、すでに存在していたターゲットテーブルは、それまでの内容を保持します。ただし、まだ作成されていないソーステーブルについては、Table Union Distinct と Table Union All が例外です。これまでと同様、警告なしにそのテーブルを除外して残りを結合し、1 つも作成されていない場合は、失敗せずに警告付きで完了します。ステップが一覧に挙げているものの読み取らず、テーブルにもなくなった列は、代わりに警告となるため、以前に実行できたステップは引き続き実行できます。ターゲットがビューのステップでは、挙げられた列と結合キーは、ウェアハウスがいずれにしてもビューの作成を拒否する場合に限り、そのテーブルと照合してチェックされます。これらの失敗は、これまではデータベースから、データベース独自の言葉で、1 列ずつ報告されており、ターゲットテーブルを置き換えるステップでは、すでにテーブルが空にされていました。ワークフローのエラー処理がデータベースのテキストに一致させている場合は、更新してください。[ステップの実行時](/ja/reference/workflow-steps/tables/table-extract/#実行時に指定された列)を参照してください。
- **テーブルのないエクスポートは、完了せずに停止します。** テーブルのない Export to Parquet、Export to ORC、Export to Avro のステップは、ファイルを書き込まずに完了し、テーブルのない Export to XML ステップは、何も含まないファイルを書き込んでいました。これらのステップは、何も書き込まずに停止し、*No Tables Specified* と表示されるようになりました。テーブルのリストがまったく保存されていないステップは、内部設定を示す予期しないエラーで失敗していましたが、同じメッセージで停止するようになりました。

## 修正

- **無効なプロジェクト設定が、わかりやすいメッセージで報告されるようになりました。** 不明な環境またはドキュメントアカウント、すでに使われている、または予約されているスラッグ、無効なストレージタイプまたは転記モードは、汎用のサーバーエラーではなく、問題を示すメッセージを返します。REST API では 500 ではなく 400 になり、AI アシスタントまたは MCP では無効な引数のエラーになります。
- **REST API のディメンション値リクエストが動作するようになりました。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして処理され、無効として拒否されていました。現在は `value_columns` の各列について 1 つの集計値を返し、グリッド（行フィルターと列フィルターの各組み合わせに 1 つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **テーブルの読み取りとファイル処理の遅さが、ほかのリクエストを妨げなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundation ファイルの登録、Excel へのエクスポート、REST または SOAP インポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panel アプリのコードやロゴのチェックは、それぞれ完了するまで、同じサーバーが処理しているほかのすべてのリクエストを止めることがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクトとワークフローの変数ダイアログがスクロールするようになりました。** 画面が小さい場合や解像度が低い場合、追加および編集ダイアログがウィンドウより高くなり、**作成**ボタンと**更新**ボタンに手が届かないことがありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storage のドキュメントアカウントで、256 MiB を超えるファイルをコピー、移動、名前変更できるようになりました。** これらの操作は、そのサイズのファイルで失敗しており、そのようなファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2 で、テーブルの行数に書き込んだ直後の内容が反映されるようになりました。** テーブルを書き込んだステップまたはインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが 0 行と表示されたり、インポートが 0 行のインポートと報告されたりしていました。行数は、新しい行がすべての場所から見えるようになってから読み取られるため、その後のステップでも読み取れます。テーブルを別のブランチに切り替えたり、ブランチをマージしたりしたときも、行数と列数が更新されます。
- **Weave の空の値のチェックは、各実行を、以前の実行が実際に残した状態と比較します。** ステップの空の値は、ステップがテーブルを空にして再度埋め直した直後にカウントされることが多く、そのため以前の実行には空の値がなかったように見え、以前から一部が空だった列が、たった今そうなったかのように報告されていました。現在は、各実行がステップによってテーブルが残された状態でカウントされます。以前に記録されたカウントは、正しいものと区別できないため使用されません。各ステップの空の値のチェックは履歴をやり直し、5 回の実行がカウントされるまで未チェックとして報告されます。また、行数と値の分布のチェックでは、ステップが完了してから 2 秒を超えて別のステップが同じテーブルに行った書き込みを、そのステップの書き込みとして扱わなくなりました。[Weave が確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **Data Foundation で、逆数にした為替レートと小数のしきい値の精度が保持されます。** レートが報告通貨から別の通貨への相場で提示されているために、PlaidCloud が逆数にしたレートは、小数第 6 位に丸められることがあり、インドネシアルピアのようにレートの小さい通貨の金額で約 1% のずれが生じていました。逆数にしたレートは、小数第 12 位まで保持されるようになりました。`0.5` のように小数を含む `group_amber` または `group_red` のしきい値は、整数に丸められていました。次回の**ロード**から、正確な値が使われます。[為替レート](/ja/guides/projects/data-foundation/#為替レート)を参照してください。
- **無効化されたメンバーのアラートとダイジェストが停止します。** 所有者が無効化された Panel アプリのアラートまたはダイジェストが、チェックと送信を続けていました。現在は、無効化されている間は一時停止し、再び有効になると再開します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
- **削除された接続を REST API に要求すると 404 が返ります。** 削除された接続、または存在しない ID を要求すると、汎用のサーバーエラー（500）が返っていました。現在は、接続 ID を示すメッセージとともに 404 を返します。
- **テンプレートを使うテーブルのエクスポートが、AI アシスタントと MCP で動作します。** `table_data_export` の `templated` 形式は、テーブルを渡すと常に失敗していました。現在は、テンプレートを通してテーブルをエクスポートし、読み取れる行に限定されます。テンプレート内では、テーブルの行はテーブル ID で指定し、`-` はすべて `_` と書きます。
- **Amazon S3 と S3 互換のドキュメントアカウントで、リージョンが保持されます。** これらのアカウントを保存すると、入力した**リージョン**が破棄され、次にアカウントを開いたときにフィールドが空になっていました。リージョンは保存されるようになりました。この修正前に保存したアカウントでは、リージョンをもう一度入力して保存してください。[AWS S3 アカウントの追加](/ja/guides/documents/adding-accounts/add-aws-s3-account/)を参照してください。
- **フォルダーのエンコード変換で、同じ名前のファイルがほかのファイルを上書きしなくなりました。** 出力先の同じ場所に向かう 2 つのファイル（たとえば、別々のサブフォルダーにある同じ名前の 2 つのファイル）は、最後に書き込まれた 1 つだけが残っていました。ステップは、2 つ目を書き込む前に停止し、両方のファイルとその書き込み先を示し、**サブフォルダーを保持**にチェックを付ければ分けて保持できる場合はそのことも伝えます。
- **「ドキュメント: ファイルをASCIIエンコードに変換」で、文字の置き換えをオフにした設定が反映されます。** **ターゲットエンコードで表現できない文字を ? に置き換える**をオンにして保存したステップが、ボックスをオフにして再度保存してもオンのままでした。オフにすると、置き換えが無効になります。
- **AI アシスタントと JSON-RPC は、ロールで非表示のテーブルを使うステップの名前を示さなくなりました。** そのようなテーブルがどこで使われているかを尋ねると、ロールで見えるステップのうち、そのテーブルを読み取るか書き込むものすべてについて、設定とワークフローとともに名前が示されていました。現在は、プロジェクトのテーブル参照と同様に、ステップがそのテーブルを使っていることのみを示し、ステップ名は示しません。[ロールで非表示になるもの](/ja/guides/ai-assistant/weave-tab/#ロールで非表示になる内容)を参照してください。
- **選択したデフォルトの AI 接続がデフォルトのまま保持されます。** AI 接続をワークスペースのデフォルトとして設定すると、成功したように見えて、実際には保存されておらず、デフォルトに依存するエージェントとステップは、最後に更新された接続を使い続けていました。選択内容が保存されるようになりました。[LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **Weave の履歴で会話を右クリックしても、スレッドを削除の上に名前の変更が開かなくなりました。** **名前の変更**はチャットのタブに移りました。これまで何も表示されなかったタブを右クリックしてください。[Weave タブのタブ](/ja/guides/ai-assistant/weave-tab/#weaveタブ内のタブ)を参照してください。
- **空のメモがあっても保存できるようになりました。** **メモ**ボックスを空にしたままプロジェクト、ディメンション、テーブル、ウェアハウス、エディター、ワークフローのスケジュールイベント、配布リストを作成または保存すると、「Memo: Input should be a valid string」で失敗していました。空のメモが受け付けられるようになりました。
- **1 つの値が必要な場所で複数の値を返す式は拒否され、Table Extract または Table Union All ステップはターゲットテーブルのデータを保持します。** よくある原因は、`table.amount,` のような末尾のカンマや、`table.region == ('EU', 'US')` のような複数の値との比較です。Databend ではステップが失敗し、Table Extract または Table Union All ステップでは、その時点でターゲットテーブルがすでに空にされていました。ほかの一部のウェアハウスではこのような式が実行されていましたが、書いたとおりに実行されるとは限らなかったため、これまでエラーなく動いていたステップが拒否される場合があります。ステップフォームはステップの保存時にその式を拒否し、メッセージに何を変更すべきかが示されます。[1 つの値が必要な場所での複数の値](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#1つの値が必要な場所に複数の値がある場合)を参照してください。
- **出力列の名前が重複するステップは、ターゲットを空にする前に停止します。** Table Lookup、Table Extract、または結合で、同じ名前の **ターゲット出力列**が 2 つあると、ステップがターゲットテーブルを空にしたうえで、わかりにくいエラーで失敗していました。ステップは先に停止し、重複した列を示すメッセージを表示するので、各出力列に別々の名前を付けられます。クエリが返す順序で列を書き込む SQL抽出は変更ありません。[Table Lookup](/ja/reference/workflow-steps/tables/table-lookup/)を参照してください。
- **ソース列なしで保存されたユニオンのソースについて、不足している内容が示されます。** REST API、JSON-RPC、または AI アシスタントや MCP を通じて、ソース列のリストなしで保存された Table Union All または Table Union Distinct のソースは、ステップの実行時に、内部設定を示す予期しないエラーで失敗していました。現在は、そのような保存はソースを示して拒否され、以前に保存されたものを読み取るステップは、何も書き込まずに停止し、ソースを示します。テーブルのすべての列を取り込む、または位置で積み重ねる変換済みの Table Union All には、リストは不要で、リストがなくても拒否されません。
- **列の定数に、数値、`0`、`false` を指定できます。** 出力列の定数が数値のステップは、予期しないエラーで失敗していました。`0` または `false` の定数は、定数がないものとして扱われ、その列は代わりに式またはソース列を使うか、読み取るものがないためステップが失敗していました。これらの定数は、列のデータ型に変換されてすべての行に書き込まれるようになり、AI アシスタントも定数付きのステップを提案できます。
- **変換された Alteryx の Data Cleansing ツールが、null の行を削除します。** **Remove Null Rows** をオンにした Data Cleansing または Data Cleanse Pro ツールは、変換レポートで確認が必要とフラグが付けられ、変換されたステップはすべての行を保持していました。ステップは、Alteryx と同様に、すべての列が null の行を削除するようになりました。空のテキスト値を持つ行は保持されます。Data Cleanse Pro は、ほかのオプションの後で各行をチェックするため、null が空白に置き換えられた行も保持されます。**Remove Null Columns** は、引き続き確認が必要とフラグが付けられます。この変更を反映するには、ワークフローを再度インポートしてください。
- **列を指定していないメール通知には、すべての列が含まれます。** 列が選択されていない Notify Via Email のフレームは、これまで実行が失敗していました。テンプレート本文では、件名内の `{variable}` プレースホルダーが、スケジュール送信、プレビュー、**自分にテスト送信**で埋め込まれます。
- **式の検証が、実行時に受け付けられる関数を受け付けます。** `int(...)` などの関数を呼び出す有効な式が、チェック時に拒否されていました。

## セキュリティ

- **Weave は、各会話の開始時に、あなたの名前とメールアドレスを AI プロバイダーに送信しなくなりました。** これらは使われていませんでした。
- **パスワードでのサインインには認証アプリが必要になり、パスワードが強化されました。** PlaidCloud のパスワードでサインインするメンバーは、次回のサインイン時に認証アプリの設定を求められ、それ以降は毎回そのコードを入力します。シングルサインオン、Google、Microsoft、GitHub でのサインイン、API トークン、サービスアカウントは変更ありません。新しいパスワードは 12 文字以上で、ユーザー名や直近 6 回のパスワードと同じにはできず、サインインの失敗が繰り返されると、アカウントは短時間ロックされます。ワークスペースにすでに設定されていたより厳しいルールは維持されます。[メンバー認証](/ja/administration/access/member-authentication/)を参照してください。
- **接続は、パブリックアドレスとプライベートネットワークのアドレスを指します。** 接続は、ループバック、リンクローカル、クラウドメタデータのアドレスを指定できず、エラーにはホストと解決先のアドレスが示されます。プライベートネットワーク上のアドレスには影響しません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続できないアドレス)を参照してください。
- **保存された接続の認証情報は、接続またはワークフローを編集できるメンバーにのみ表示されます。** REST API と MCP を通じて、保存された接続のパスワード、トークン、キーは、ほかのメンバーにはマスクされ、そのメンバーも接続を開いて参照することはできます。[接続の認証情報を確認できる人](/ja/guides/connections/create-connection/#接続の認証情報を確認できるユーザー)を参照してください。
- **アプリのビルドは、ワークスペースの Git 認証情報にアクセスせずに実行されます。**
- **エージェントの秘密鍵は、エージェントを編集できるメンバーにのみ表示されます。** 鍵は、REST API と MCP を通じたエージェントの一覧や詳細には表示されなくなり、エージェントフォームの**秘密鍵**と **RPC構成を表示**は、エージェントを編集できるメンバーにのみ表示されます。サービスアカウント、プロジェクトトークンとエージェントトークン、AI に委任されたトークンは、鍵や RPC 構成を取得できません。実行中のエージェントには影響せず、公開鍵は引き続き表示されます。[エージェントの認証情報の取得](/ja/reference/cli/plaidlink/agents/#エージェントの認証情報の取得)を参照してください。
- **プロキシのダウンロードリンクは 1 時間有効です。** **Use PlaidCloud Proxy Download** がオンの場合、リンクの有効期限が切れたら、ダウンロードをもう一度開いて新しいリンクを取得してください。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)を参照してください。
- **セキュリティグループへのユーザーの追加は、保有している権限に従います。** メンバーをセキュリティグループに追加する、メンバーのグループを選択する、アーキテクトを招待するには、そのグループが付与するすべての権限を保有している必要があります。ワークスペース管理者には制限がありません。[セキュリティグループの管理](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)を参照してください。
- **接続の所有者またはワークスペース管理者が、接続の設定を変更し、オンとオフを切り替えます。** REST API、JSON-RPC、AI アシスタントまたは MCP を通じて接続の設定を変更するには、その所有者の 1 人、または所有者のいない接続ではワークスペース管理者である必要があります。接続の有効化、無効化、ロック、ロック解除には、所有者またはワークスペース管理者が必要で、複数の接続を指定したリクエストは、そのすべてを変更できる場合にのみ適用されます。ワークスペースのデフォルトの AI 接続を選択できるのはワークスペース管理者だけで、メンバーが所有する接続がデフォルトになるのは、管理者が所有する接続、または所有者のいない接続がデフォルトになり得ない場合に限られます。[接続の編集](/ja/guides/connections/create-connection/#接続の編集)と [LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **行アクセスは、メンバーが制限付きテーブルに対して行うすべての操作に適用されます。** メンバーは、ダッシュボード、自分の SQL、ロードで、付与された権限が許可する行のみを参照、変更できます。
  - **プロジェクトのアーキテクトは、ダッシュボードで、行が制限されたテーブルのすべての行を参照できます。** これは、Analyze で参照できる内容と同じです。アーキテクトのアクセスを取り消すと、ダッシュボードにすぐに反映されます。これは、ユーザーのロールを変更した場合、そのユーザーまたはグループをプロジェクトから削除した場合、プロジェクトのアクセスタイプを変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれでも同様です。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
  - **行アクセスで制限されたメンバーも、自分の SQL クエリを実行し、結果をエクスポートできます。** 行アクセスが設定されたプロジェクトで、アーキテクトではないメンバーは、クエリ画面での自分のクエリから、付与された権限が許可する行だけを正確に取得し、**アクセス権により行が制限されています**という通知とともに、CSV、Excel、JSON にエクスポートできます。以前は、これらは拒否されていました。パーセント記号（`%`）を含む権限の値は、クエリ画面で行を返すようになり、そのようなクエリを CSV としてダウンロードできます。Snowflake または Databricks での自由形式の SQL、Postgres 系ウェアハウスでの自分の SQL のエクスポート、スナップショット時点での管理対象テーブルの読み取りは、引き続き拒否され、ビューをフィルターするには、管理対象の列を元の名前のまま保持する必要があります。[行アクセスと自分で書くクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスと自分で作成するクエリ)を参照してください。
  - **行アクセスを保存しても、ソースにない付与済みの値は保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がない、ディメンションにそのメンバーがない、またはリストにない場合でも、マークが付いてグリッドに残ります。**保存**では、そのような各値を保持するか削除するかを尋ねます。[行アクセスグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
  - **行が制限されたテーブルへの DataFrame の書き込み、レコードの保存、クリアは、自分に見える行だけを変更します。** 行アクセスで行が制限されている場合、Python クライアントで制限付きテーブルに DataFrame を書き込む、またはクリアする、あるいは REST API でレコードを保存する、またはクリアするときは、自分の行だけが変更され、アクセス範囲外の行を含むロードは、何かが変更される前に、見つかった値を示して拒否されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は、テーブル全体に書き込みます。個人が行うこれらの書き込みは、どのテーブルに対するものでも、**セキュリティログ**に記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
  - **行が制限されたテーブルへのインポート、コピー、復元、削除には、すべての行が自分に見える必要があります。** 行アクセスで行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えやマージ、復元、削除、削除後の復旧、またはテーブル全体を置き換えるその他の操作は、テーブルのすべての行が見える場合にのみ実行され、それ以外の場合は拒否され、何も変更されません。REST API でテーブルの行を保存すると、ほかのロードと同様に、自分の行だけが変更されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行には影響せず、これらの操作も**セキュリティログ**に記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントの所有者だけです。** ドキュメントアカウントを以前のバージョンに復元する、バージョンを保持または解放する、バックアップを取るには、アカウントの所有者の 1 人である必要があり、システム管理のアカウントではいずれも使えません。アカウントのバージョン履歴を表示するには、アカウントへのアクセス権が必要です。
- **`query_run` は読み取り専用のステートメントを実行します。** AI アシスタントと MCP クライアントが使う `query_run` ツールは、SELECT または WITH ステートメント 1 つ、そのいずれかの EXPLAIN、または SHOW を受け付け、それ以外のステートメントは実行されません。データを変更するには `query_transform` を使います。MCP のテーブルエクスポートの SQL にも同じルールが適用されます。REST と JSON-RPC の API では、プロジェクトデータを変更できないメンバーに対して、クエリの実行、列ファセットの作成、クエリの CSV ダウンロード、リモートデータベースへのクエリのエクスポート、独自のクエリによるテーブルデータのエクスポートにも適用され、拒否されたクエリは 403 を返します。**Explain Analyze** はクエリを実行して測定するため、クエリログと Lakehouse では読み取りクエリのみを受け付け、行アクセスのあるプロジェクトでは、プロジェクトのアーキテクトだけがクエリログから実行できます。
- **テーブルエクスプローラーのフィルター、PlaidCloud に送信されるクエリ、Table Extract ステップの動的列を検索するクエリは、SQL を実行する、またはサーバーのファイルを読み取る関数を呼び出せません。** `query_to_xml`、`dblink`、`pg_read_file` など、そうした関数の呼び出しは拒否され、エラーに関数名が示されます。同じ場所で、`.op()` は演算子のみを受け付け、`literal_column` では Unicode エスケープ形式の引用符を使えません。動的列のクエリには、ステップのフィルターと、ソースから列名を読み取る式が含まれるため、ルールに違反するものがあると、ステップの実行時にステップが失敗します。[拒否される関数と演算子](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#拒否される関数と演算子)を参照してください。
- **Data Foundation の配賦ルールは、単一引用符、バックスラッシュ、改行を含む部門名または統計名を拒否します。** この名前は配賦ステップのフィルターに書き込まれるため、**保存**とステージ 1 のプレビューは、その値を示して拒否します。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。
