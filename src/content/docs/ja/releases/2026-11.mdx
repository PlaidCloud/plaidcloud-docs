## 追加

- **ハンズオンのラボで PlaidCloud 認定バッジを取得できます。** ユーザーメニューの **認定** には、マイバッジ、管理者が設定したターゲット、各ティアのラボが表示されます。ティアは、ファンデーション、続いてデータエンジニアリング、モデリング、アナリティクスの各トラックのプラクティショナーとエキスパートです。各ラボでは、PlaidCloud の認定ワークスペースに課題と自分専用のプロジェクトが用意され、認定ワークスペースは **ラボを開始** で新しいタブに開きます。**採点に提出** は作業内容をバックグラウンドで採点するため、いったん離れて戻ってから結果を確認でき、失敗したチェックには、何が問題だったかと、該当するガイドへのリンクが表示されます。バッジの有効期限は 2 年で、公開の検証ページで共有できます。エキスパートバッジを 3 つ取得すると、マスターレビューの対象になります。[PlaidCloud 認定](/ja/guides/certification/)を参照してください。
- **コントロールプレーンの Trust Center で、セキュリティチームが PlaidCloud のセキュリティ文書を入手できます。** 管理者とセキュリティユーザーは、組織の **Trust Center** を開き、サブプロセッサー一覧や DPA などの公開文書をすぐにダウンロードできます。また、組織として 1 回、セキュリティ文書の NDA に署名すると、SOC 2 Type II レポートなどの制限付き文書のロックが解除されます。他の管理者とセキュリティユーザーは、誰がいつ署名したかを確認できます。契約にすでに NDA が含まれている組織では、NDA を提出済みとして記録しておけば、署名なしで文書のロックが解除されます。制限付き文書のダウンロードには透かしが入り、記録されます。新しいバージョンの NDA は、あらためて承諾が必要です。管理者とセキュリティユーザーは、組織ごとに、新規または更新された文書と新しい NDA バージョンをまとめた日次メールを受け取るよう設定することもできます。このメールに文書そのものが含まれることはありません。[Trust Center](/ja/administration/control-plane/trust-center/)を参照してください。
- **PlaidXL は、Excel でのレポート作成、ドリル、数値の説明、計画に対応します。** **PlaidCloud** リボンタブは **接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有**にグループ分けされています。よく使うコマンドは **PlaidXL** の右クリックメニューと **PlaidXL Cell** タブにもあり、主要なコマンドには変更できるキーボードショートカットがあります。フィールドに入力している間は、ショートカットは動作しません。コマンドが失敗すると、どのコマンドがなぜ失敗したかが、わかりやすい言葉で表示されます。サインイン前に実行したコマンドはサインインを開き、サインイン後に 1 回実行されます。サインインは 1 つのワークスペースに対して有効なので、ワークスペースを切り替えると新しいワークスペースへのサインインが求められます（元に戻す場合は求められません）。Office で Microsoft Entra の職場アカウントを使っている場合、PlaidXL がワークスペースを自動的に見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます。** **レポート** タブは、テーブルからライブレポートをレイアウトします。1 つのディメンションを行方向に、もう 1 つを列方向にドリルダウンし、各交点に `CELL` の値が入り、罫線付きの見出し、網掛けのラベル、経理向けの数値書式で仕上げられます。**Build my first report** は、お客様自身のデータからサンプルを作成します。**参照** でノードを選択して代替階層を選び、別のメンバーと比較して差異と差異率をその横に表示し、データのない行と列を非表示にし、合計をメンバーの下に置き、入力できるセルを網掛けにできます。作成したレポートでは、**Swap rows and columns** で行と列を入れ替え、**ポイントオブビュー** で各フィルターをそのメンバーに沿って順に切り替えられ、各フィルターのセルにはメンバーのドロップダウンがあり、ディメンションの **One sheet per part of** は子ごとのシートにレポートをコピーします。ドリルに合わせて、レポートは行全体と列全体を挿入、削除し、入力した値、メモ、書式は行に付いたまま移動します。大きなレポートは計算が速くなります。[レポートを作成する](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only** は、ノード、ディメンション見出し、レポートの値から、ノードをライブの `DRILL` 数式に変換し、その編集も行います。レポートの外にあるシート上の `DRILL` をドリルすると、セルをクリアする代わりに行全体を挿入、削除するため、横のグリッドは形を保ち、削除する行にほかの内容がある場合は何も変更されません。**Custom drill** は、挿入前に行をプレビューします。メンバーピッカーは、各ノードの ID をエイリアスとともに表示し、メンバーを挿入し、ノードの子、兄弟、下位レベルのドリルを書き込み、ノードの子のドロップダウンをセルに追加し、最近使ったメンバーを記憶します。**Formulas** タブと **レポート** タブのノードフィールドの横にある **参照** は、メンバーをフィールドに選択します。`DRILL` では、除外または展開するノードを指定でき、行をまたいで実行でき、合計をメンバーの下に置くこともできます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明できます。** **Explain this number** は、値の計算内容、現在の PlaidCloud と一致しているか、値の元になっているテーブルとワークフローステップを表示します。**Show detail rows** は、値の元になっている行を専用のシートに表示し、合計が一致するかの確認も行います。
  - **Excel でガバナンスされたメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるのと同じビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計の場合は `0` を表示し、それ以外は理由とともに `#VALUE!` を表示します（`CELLS` のスピルでは空白）。**Metric...** は、プロジェクトのメトリックを現在の値とともに一覧表示します。メトリックは、複数の代替階層でフィルターしたり、代替階層のメンバーと他のディメンションのメンバーを組み合わせたりできます。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに直接入力して計画できます。** `CELL` の値の上に数値を入力すると、PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの形に合わせた配分、金額またはパーセンテージによる調整が可能で、保持されたセルには影響せず、レポートは入力できるセルを網掛けにできます。単一の `CELL` で **Delete** を押すと数式が元に戻り、セルのブロックをクリアするとそのままクリアされます。平均、中央値、最小値、最大値、標準偏差、分散のセルにも入力でき、入力した値は、行や列の挿入、削除に合わせてセルとともに移動します（削除されたセルの値は報告されます）。**Undo last write** は、入力した値と保存を新しい順に取り消します。書き込みを取り消せるのは、その書き込みを行ったユーザーとワークスペースだけです。合計の取り消しや、空のセルに入力した平均の取り消しでは、それ以降に同じセルへ書き込まれた内容が保持されます。完了前に中断された書き込みは取り消せません。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要なものだけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新できます。各テーブルの進行状況と**キャンセル**はタスクペインに表示されます。PlaidXL の数式だけを再計算することもできます。大きなテーブルは、Excel on the web と最新のデスクトップ版 Excel で大幅に高速に取得できます（143,000 行、77 列のテーブルで、10 分以上かかっていたものが約 1 分になります。古い Excel バージョンでは従来どおり動作します）。Excel のセルに入る長さを超えるテキストは、検出され、切り詰められた状態で保存されないよう保護されます。取得したテーブルは、データ型ごとに書式設定された Excel テーブルとして届き、更新しても独自の列と数値書式が保持され、同じ場所で更新されます。取得や更新で他のセルが上書きされたり、別の Excel テーブルと重なったりすることはなく、Excel で扱えないほど大きな整数 ID や 1900 年より前の日付はテキストとして届きます。同じテーブルをもう一度取得しても更新リストに二重に追加されず、**Stop refreshing** で 1 つずつ外せます。ディメンションはテーブルとともに更新されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud** は、確認なしで書き込み、何を行ったかを表示し、**元に戻す**を提供します。この操作は、Lakehouse テーブルでは各保存から最大 7 日間有効です。フィルター付きで取得したシート、詳細行のシート、一部の行にしかアクセス権がないユーザーの場合は、それらの行だけが置き換えられるため、他のユーザーの行は保持されます。取得後にメンバーが変更されたドリルスルーシートは保存されません。保存に失敗した場合は、テーブルを元に戻せるよう、復元ポイントの名前が表示されます。[テーブルを PlaidCloud に保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルをplaidcloudに保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave** タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼するか、**Ask Weave about this cell** を選択します。Weave はあなたの権限で PlaidCloud を読み取り、ブックだけを変更します。入力済みの内容を置き換える前に確認し、ブックの外に到達する数式は書きません。各変更は、ペインを再読み込みするまで元に戻せます。[Excel で Weave に質問する](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1 つのシートまたはブック全体の値のみのコピーを共有できます。** **Convert to values** は、ブック全体、1 つのシート、または元に戻せない値のみへの変換を行います（最後の場合は先に確認があります）。変更されるのは PlaidXL の数式とそのスピルだけで、まだ計算中の数式は 2 回目の試行のために残され、シート名を変更した後でも **Restore PlaidXL formulas** は動作します。
  - **タスクペインの外観が新しくなりました。** PlaidCloud の Web アプリに合わせた、ブランドブルー、レール形式のタブとリスト、スクロールできる枠付きカードに入ったテーブル、ディメンション、プロジェクト、列になっています。キーボードフォーカスは明確な枠で表示され、ペインは Office のライトテーマまたはダークテーマに従います。タブは、幅の狭いペインでは横 3 つ、縦 2 段に並び、幅 560 ピクセル以上では 1 行に並びます。[ライトテーマとダークテーマ](/ja/reference/cli/plaidxl/connect/#ライトテーマとダークテーマ)を参照してください。
  - **ペイン内の数値は Excel の表示言語に従います。** 行数と列数、および更新、再計算、Explain、Formulas、Report、計画のメッセージでは、お使いの Excel と同じ形式で数値が表示されます。たとえばドイツ語版 Excel では 4.812.233 と表示されます。セルに書き込まれる値は変わりません。
  - **更新中はシートのタブが黄色になります。** ペイン、リボン、Weave のいずれから実行した場合でも、**Refresh all tables** の間は、更新中のシートのタブが黄色になり、更新が完了、失敗、またはキャンセルされると、元の色（ご自身で設定した色を含む）に戻ります。途中でブックを保存して閉じた場合は、次にそのブックで PlaidXL が起動したときにタブが元に戻されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
- **Power BI、Excel、Tableau、Python、DBeaver からプロジェクトのテーブルを読み取れます。** 登録済みシステムで **BI / 外部データフィード**クライアントを作成し、**アクセスと共有**でマネージャーまたはエクスプローラーとしてプロジェクトに追加します。クライアントは、そのロールに表示されるテーブルを、所有者であるあなたとして、あなたの行アクセスを適用して読み取り、そのシークレットは BI フィードでのみ使用できます。Power BI、Excel、Tableau は、クライアントの ID とシークレットを使用して、プロジェクトの読み取り専用 OData フィードに接続します。Power BI Service はゲートウェイなしで更新できます。1 回の OData リクエストで返される行数は最大 1,000,000 行です。それより大きなテーブルは、フィルターまたは Power BI の増分更新で読み取るか、Lakehouse v2 ではページ単位で読み取ります。ページ単位の読み取りには、Power BI、Excel、Tableau Desktop が対応しています。Python、DBeaver、Tableau Desktop は、行数の上限がない Arrow Flight SQL で独自の SQL を送信することもできます。このフィードは、ワークスペースで外部データベースアクセスが有効になっている場合に、許可リストのアドレスから利用できます。[BI ツールを接続する](/ja/integrations/bi-tools/)を参照してください。
- **個人用アクセストークンで BI フィードにサインインできます。** ユーザーメニューで**個人用アクセストークン**を選択し、有効期間が 30日、90日、180日、1年のいずれかのトークンを作成してコピーします。トークンが表示されるのは 1 回だけです。Power BI、Excel、Tableau、または Python や DBeaver などの Flight SQL クライアントで、ユーザー名にメールアドレス、パスワードにトークンを入力してサインインします。BI フィードクライアントを設定する必要はありません。ツールは、PlaidCloud でのあなたと同じ範囲で、開けるすべてのプロジェクト、ロールに表示されるテーブル、あなたの行アクセスを適用して読み取ります。トークンを取り消すか有効期限が切れると、次のリクエストから使えなくなり、トークンで PlaidCloud 自体、その REST API、MCP にサインインすることはできません。1 人に依存させたくないフィードには、引き続き BI フィードクライアントを使用します。[BI ツールを接続する](/ja/integrations/bi-tools/#個人用アクセストークンでサインインする)を参照してください。
- **Google ドライブのドキュメントアカウントをワークフローで使用できます。** Google Cloud のサービスアカウントで設定し、そのキー JSON をアカウントの秘密キーとして入力した Google ドライブアカウントで、ワークフローからファイルの一覧表示、インポート、エクスポート、コピー、移動、名前の変更、削除、およびフォルダーの作成ができます。最上位のロケーションは、サービスアカウントと共有されているフォルダーと、サービスアカウントがメンバーになっている共有ドライブで、Google スプレッドシートは `.xlsx` エクスポートとして読み取られます。個人のマイドライブにあるフォルダーでは、既存のファイルの上書きはできますが、新しいファイルは作成できないため、先にファイルを作成するか、共有ドライブを使用してください。存在しないフォルダーは空として一覧表示され、スロットリングや Google の一時的なエラーは自動的に再試行されます。[Google ドライブ アカウントの追加](/ja/guides/documents/adding-accounts/add-google-drive-account/#ワークフローでのアカウントの使用)を参照してください。
- **Sage 100 をオンプレミスで接続し、Data Foundation と転記に使用できます。** ネットワーク内の Windows コンピューターにある PlaidLink エージェント経由で、Data Foundation が Sage 100 の会社の勘定科目表、会計カレンダー、仕訳、期間残高を読み取ります。対応エディションは Premium、Standard、Advanced で、1 接続につき 1 社です。ワークフローから、総勘定元帳の仕訳と買掛金の手動小切手を転記することもできます。ドキュメントが転記済みと見なされるのは、PlaidCloud が Sage 100 から読み戻せた場合のみです。Sage 100 のバッチ内にある間は待機中と表示され、Sage 100 に存在するかどうか PlaidCloud が判断できない場合は再送信されません。エージェントには PlaidLink 1.2.36 以降が必要です。[Sage 100（オンプレミス）](/ja/guides/connections/sage-100/)を参照してください。
- **`{date_iso}` は、実行時刻を ISO 8601 形式で提供します。** 現在の UTC 時刻を `2026-11-12T22:49:56+00:00` の形式で保持するため、式で先頭の 7 文字または 10 文字を取得して、月または日を得られます。`{date}`（長い形式）が使える場所ならどこでも使用できます。ステップの設定と式、プレビューや**自分にテスト送信**を含む通知メールテンプレート、Forecast、Parity、Solver の各ステップです。[組み込み変数](/ja/guides/workflows/manage-workflow-variables/#組み込み変数)を参照してください。
- **任意のERPに、1つのステップでドキュメントを転記し、すべての転記を1か所に記録します。** **伝票を転記** ステップは、テーブル内のドキュメントを、各エンティティの転記先のシステムに転記するため、1つのステップで複数のERPシステムや、同じERPの複数のインスタンスに転記できます。Data Foundationの形式の仕訳は対応付けなしで転記され、請求済みの販売明細のテーブルは `account` と `document_type` を追加すると転記されます。すべての転記は、どのシステムに対しても同じ方法で記録され、何かが送信される前にチェックされ、各実行には専用のページがあります。転記フィールドの名前を持つ列でも、モデルテーブルでは別の意味を持つ場合や、別の列がそのフィールドにマッピングされている場合など、そのフィールドとして読み取られない列は転記されず、ステップはその列名を示して警告するため、列でマッピングできます。[ERPシステムに伝票を転記する](/ja/guides/connections/post-documents/)を参照してください。
  - **まずシミュレート、次に本番。** 実行と各システムは **シミュレート** または **本番** に設定されます。シミュレートされたドキュメントは **転記予定** と表示され、何も送信されません。**Balanced** や **Sets agree** を含む5つのチェックが、送信前にドキュメントを停止し、丸め勘定と上限を指定できます。ワークフローキャンバスでは、**シミュレート** ボタンが **テスト実行** になりました。引き続き、ステップを実行せずにワークフローをたどり、転記モードの「シミュレート」とは別のものです。
  - **実行にはページがあります。** 実行ページには各ドキュメントと、停止された理由が表示され、**実行を停止**、**これらを転記**、**システムで確認** を使用できます。ステップの本番の実行には、ステップが以前に転記して今回は生成しなかったものが一覧表示され、**これらを取り消す** でそれらを取り消せます。転記レジスターの **ファイルから転記…** メニュー項目は、ワークフローなしでスプレッドシートを転記し、ファイルの実行のページの **再転記** は、新しい日付で、1回（シミュレートから開始）または毎月再転記します。どちらもREST APIとMCPからも利用でき、PlaidCloudの利用前に転記されたドキュメントを転記済みとして記録することもできます。配賦からも転記でき、**ドキュメント転記に変換…** は、SAP転記ステップを新しいステップに変換します。RESTやMCPでの転記とファイルからの転記の開始には、ロックされていないプロジェクトのアーキテクトまたはマネージャーのロールが必要です。
  - **システム、振り分け、本番稼働。** 各システムには、テーブルにない列の固定値を含む設定と、ある日付からそのシステムに転記するエンティティがあります。システムの行の **本番稼働 ›**、または **アクション** の **このプロジェクトで本番稼働…** は、既存の書き込み認可とプロジェクトのモードを使用します。システムは別の環境にコピーでき、**今すぐ更新** は、システムの勘定科目、会社、期間のリストを、表示できるコピーに再読み込みします。期間が未締めであること、存在、コード対応のチェックは、本番のシステムでの本番の実行が開始されるときに読み取ったリストのみを使用します。その実行でリストが読み取られなかったチェックは「not checked」と表示されます。[転記用にERPシステムを設定する](/ja/guides/connections/erp-systems/)を参照してください。
  - **保留ルールは、リスクの高いドキュメントを担当者に回します。** 保留ルール、またはステップ自身の保留により、ドキュメントは **承認** の受信トレイに送られ、大きなドキュメントは異常としてフラグ付けでき、承認は1つの操作を対象とします。取消、貸方、訂正も、2人目の担当者のために保留されます。
  - **対応システム。** システムごとの表に、各ERPでできることが一覧表示されます。NetSuiteの請求書、QuickBooks、Xero、Acumaticaのクレジットメモ、エージェント経由のSAP（エージェントがオフラインの場合は何も送信されず、復旧後にドキュメントを再試行できます）が含まれます。
  - **転記レジスターは、転記を中心に再構築されました。** レールは、**要対応**、**転記**、**実行回数**；**承認**、**委任**、**自分のウォッチ**；**システム**、**保留ルール**、**変更履歴**、**エクスポートとアラート**、**保持期間** の3つにグループ化されています。すべての転記は7つの状態のいずれかで表示され、そのドロワーには、理由、明細、バージョン、システムへのリンクが表示され、**取消…**、**貸方票…**、**訂正…**、**再試行**、コメント、ウォッチが使えます。**転記** は、**質問** で自分の言葉による質問に回答します。**ホーム** には、対応が必要なものがある間、**転記レジスター** カードが表示され、コマンドパレットには **要対応** と **承認** が表示され、**Find posting** で台帳IDから転記を見つけられます。レジスター内では、Ctrl+K（MacではCmd+K）は、独自の一覧ではなく、そのコマンドパレットを開きます。**未確認** の転記は **転記されたかどうかを報告** で、SAPの場合はシステム自身の保存済みレポートから確定します。**要確認** の台帳エントリー、またはシステムが保持しているのに **却下** になっている台帳エントリーは、**解決…** でREST API経由で確定します。可能な場合は、システムに保持内容を問い合わせます。以前のレジスターの画面（一覧、集計、照合、推移、系統、シミュレーション転記、例外キュー、アシスト）と保存済みビューは、これらに置き換えられました。[転記レジスターを確認する](/ja/guides/connections/posting-register/)を参照してください。
- **Run Insight は、ワークフローの実行の時間がどこに使われたかを示します。** キャンバスで**履歴**をクリックするか、**ワークフロー**タブの**アクション**メニューから**Run Insight**を選ぶか、ホームのワークフローカードで**最新の実行を開く**を選ぶか、遅い実行に関するWeaveメッセージで**実行を開く**をクリックします。見出しで何が起きたかを示し、**要対応**には失敗、通常範囲を超えた時間、待機の順に表示されます。**フロー**、**タイムライン**、**テーブル**の各ビューで、実行をブロックごとに確認できます。各ステップは自身の最近の実行と比較して判定され、**比較対象**で前回の実行または選択した実行を追加できます。進行中の実行は自動的に更新されます。AIアシスタントは `include=['run_insight']` を指定した `workflow_describe` で、REST APIは `GET /rest/v1/analyze/workflow/run-insight` で、同じプロファイルを取得できます。[Run Insight](/ja/guides/workflows/run-a-workflow/#run-insight)を参照してください。
- **プロジェクトホームは 7 つのページで構成されます。** テキストのみのレールに、**概要**、**変数**、**スケジュールとセンサー**、**アクセスと共有**、**データと接続**、**データモデル**、**アプリとブランディング** が並び、変数の数、有効なスケジュールおよびセンサーの数、要素の数がバッジで表示されます。**概要**には、プロジェクトの説明とラベル、ロックの状態、テーブル、ワークフロー、ステップ、変数、公開済みテーブル、**データサイズ**（**ストレージ**を開きます）のタイルが表示されます。データサイズは、**プロジェクト**画面に表示される合計（復元用に保持された以前のバージョンを含む）と同じ値で、現在のデータと以前のバージョンを分けて示すツールチップが付きます。さらに、次の 3 回のスケジュール実行、プロジェクトのデフォルト、PDF またはインタラクティブ HTML 形式の**プロジェクトレポート**、**アーカイブのエクスポート**も表示されます。その他のページでは、変数、スケジュールとセンサー（**Calendar view** と **Activate** または **Deactivate** 付き）、プロジェクトとそのダッシュボードを開けるユーザーおよびそのテーブルを読み取れるプロジェクト、接続とテーブルストレージのデフォルト（ERP 転記モードを含む）、Panelアプリ、ブランディング、プロジェクトのタイル画像を管理します。ロックされたプロジェクトにはバナーが表示され、コントロールが無効になります。[プロジェクトホーム](/ja/guides/projects/project-home/)を参照してください。
- **共有する列を1回だけプロジェクト要素として記述し、テーブルのつながりを確認できます。** 複数のテーブルが共有する列名（`Period` や `Org` など）を、説明、タイプ、マスク、ディメンション、エイリアスを持つ要素にできます。その名前の列を持つすべてのテーブルでは、列に独自の値がない場合に要素の説明、マスク、ディメンションが表示され、テーブルに保存されている内容は何も変わりません。プロジェクトホームの新しい **データモデル** ページには、要素の一覧、各要素を共有するテーブルのグラフまたはマトリックス、タイプが異なるテーブルの警告、要素にする価値のある名前の提案が表示されます。グラフはマウスホイールまたはズームボタンでズームでき、**全体表示**、**1:1**、ミニマップがあり、PDF または PNG にエクスポートできます。要素の名前は、テーブルエクスプローラー、列のプロパティ、ステップのデータマッピングタブ、結合ステップまたはルックアップステップの結合マップで列の横に表示されます。結合マップの**自動判定**は、名前が異なっていても、2つのテーブルが同じ要素に対して持つ列を対応付け、`dim_customer` のように要素にちなんだ名前のテーブルは、その要素だけで結合します。マップの下の注記は、2つの異なる要素を対応付ける行を示し、**自動判定**がキーを見つけられない場合は**データモデル**リンクが表示され、そのリンクをクリックするとステップが閉じてそのページが開きます。Data Foundation プロジェクトには、共有される Common Finance Model の列用の要素が最初から含まれています。REST API と MCP ツールの `element_find`、`element_upsert`、`element_delete` で要素を管理でき、AI アシスタントは各列の要素としての意味を確認できます。[データモデルとプロジェクト要素](/ja/guides/projects/data-model/)を参照してください。
- **ドキュメントは概要から開き、ページのレールが付きます。** レールには**概要**、**参照**、**あなたのアカウント**、**管理**が並び、各ページにはタイトル（多くはサブタイトル付き）があり、ヘッダーにアクションが配置されます。**概要**には、アカウント、**ピン留め**ファイル（**参照**でそのフォルダーを開き、ファイルが選択された状態になります）、サービス別のアカウント、利用できるユーザーのタイルが表示されます。**あなたのアカウント**は、利用できるすべてのアカウントを 1 つにまとめた一覧で、各行に**共有**または**プライベート**のピルが付きます。**管理**には、自分が所有するアカウントが一覧表示されます。ワークスペース管理者はここですべてのドキュメントアカウントを確認でき、それ以外に管理できるアカウントは管理できます（システム管理のアカウントは拒否され、管理対象バケットのアカウントは複製できません）。行の **⋯** メニューには、**開く**、**編集**、**複製…**、**Who can use it**、**使用箇所…**、**バージョン履歴**、**有効にする**または**無効にする**、**削除**があります。アカウントはページとして開き、**一般**、**アクセス**、**認証情報**のカードと、SFTP の場合は **SSH** カードがあり、未保存の変更がある状態で移動しようとすると確認が表示されます。**参照**は、お気に入りのアカウントまたはワークスペースのデフォルトのアカウントを開き、ラベルとアイコン付きのツールバー、**アップロード**ボタン、行メニュー、ドラッグ＆ドロップによるアップロード（ファイル一覧、フォルダー、またはパンくずリストの項目にドロップするとそこにアップロードされ、ツリーの**ルート**行または空白部分にドロップするとアカウントのルートにアップロードされます）、**ルート**にドラッグできるフォルダー、各アップロードとテーブルへのインポートの進行状況とアクションを表示する**アップロードとインポート**パネルを備えています。**別ウィンドウで開く**は、フォルダーを新しいブラウザータブで開きます。[ドキュメント](/ja/guides/documents/)と[ドキュメントアカウントの使用](/ja/guides/documents/using-document/)を参照してください。
- **インサイト（旧ダッシュボード）は概要から開き、レールが付きます。** アプリは、アプリメニュー、コマンドパレットの**インサイトへ移動**、Weaveで**インサイト**という名前で表示されます。レールには**概要**、**ダッシュボード**、**アプリ**、**ノートブック**、**非表示のアプリ**が並び、ワークスペース管理者向けに**アクセス審査**と**公開済みアプリ**が加わり、下部には、独自のウィンドウで開くことを示す印が付いた **ナビゲーターを開く ↗** があります。各ページにはタイトル（多くはサブタイトル付き）があり、ヘッダーにアクションが配置されます。**概要**には、ダッシュボードとアプリのタイルが表示され、選択すると対応する一覧がすでにフィルターされた状態で開きます。さらに、最近開いたものとお気に入り、失敗したアプリ、自分の対応待ちのアクセスリクエストが表示され、利用状況にアクセスできるメンバーには、最も多く開かれたダッシュボードも表示されます。**ダッシュボード**は、**すべて**、**管理中**、**お気に入り**でフィルターでき、**アプリ**には、各アプリの**種類**とライブの状態が表示されます。[ダッシュボードを使用する](/ja/guides/dashboards/using-dashboards/#インサイトのワークスペース)を参照してください。
- **ダッシュボード、アプリ、ノートブックをアプリメニューに公開できます。** ダッシュボード、PanelアプリまたはDashアプリ、JupyterLiteノートブックの**アプリメニューに公開…**で、製品アプリの下のアプリメニューに追加できます。対象は**ワークスペースの全員**、選択した**グループ**、または選択した**ユーザー**で、ラベルとアイコンも選べます。公開してもアクセス権は付与されません。項目をすでに開ける人にだけエントリーが表示され、ダイアログには、対象ユーザーのうち開けない人の数が表示され、ダッシュボードには**アクセスを修正**があります。ダッシュボード、**ブラウザのみ**のPanelアプリ、ノートブックは、**再読み込み**と**新しいウィンドウで開く**を備えたPlaidCloud内のタブとして開き、そのタブには共有できるリンクがあります。**サーバーベース**のPanelアプリとDashアプリは新しいウィンドウで開きます。そこで公開できるメンバーには、一覧で公開済みの項目に**公開済み**のバッジが表示されます。インサイトを使えるメンバーは、**自分のメニューから非表示**でエントリーを自分のメニューから外し、**非表示のアプリ**から元に戻せます。ワークスペース管理者は**公開済みアプリ**で、エントリーの並べ替え、公開の取り消し、対象ユーザーの変更ができます。アプリメニューに**ホーム**と公開済みのエントリーだけがある場合、**ホーム**にはそれらが**アプリ**の行として先頭に表示されます。メニューのエントリーがメニューいっぱいに並ぶと、その下のボタンでメニューをアイコン表示に折りたたみ、再び展開できます。MCPでは、`publication_manage` が同じ操作を行います。[アプリメニューへの公開](/ja/guides/dashboards/publish-to-app-menu/)を参照してください。
- **ID は概要から開き、ページのレールが付きます。** レールには**概要**、**メンバー**、**ディレクトリ**、**セキュリティグループ**、**配布リスト**、続いて**セッション**、**セキュリティログ**、**APIクライアント**、**Group audit**、**All scopes** が並びます。各ページにはタイトル（多くはサブタイトル付き）があり、ヘッダーにアクションが配置されます。**概要**には、メンバー、アクティブなメンバーと一度もサインインしていないメンバー、ビルダー席、現在サインインしているユーザーのタイル、**アクティブなメンバー**グラフ、**ウェルカムメールを再送信**と**確認**が付いた**要対応**、過去 7 日間のセキュリティイベントが表示されます。メンバーは **プロファイル**、**アクセス**、**Groups and data** のカードがあるページとして開き、**Invite member** は、概要と、ホームの初回実行カードの両方から使えます。[メンバー管理](/ja/administration/access/member-management/)を参照してください。
- **一覧は Standard rows、Roomy rows、Cards で表示できます。** **ダッシュボード**、**アプリ**、ERP レジスター、ID の**メンバー**などの一覧のツールバーにある**ビュー**メニューで、切り替えられます。Cards は、選択、並べ替え、列、右クリックの**コピー**、お気に入りがある一覧ではお気に入りの星など、一覧の機能をすべて保持します。**ダッシュボード**のカードにはサムネイルが表示されます。[Standard、Roomy、Cards ビュー](/ja/guides/dashboards/using-dashboards/#標準ゆったりカードのビュー)を参照してください。
- **Lakehouse ウィンドウに、サイドレール、テーブル詳細、タイムトラベルが加わりました。** **クエリ**、**プロファイル**、**ロード**、**カタログ**がレールに並び、**Administration** の下に **Lakehouse catalogs**、**Database users**、**Compute** があります。**Database users** と **Compute** は、Lakehouse 管理者または Lakehouse クラスターロールを持つメンバーにのみ表示されます。**クエリ**では、履歴を SQL テキスト、ユーザー、種類、実行時間でフィルターでき、**Copy SQL** で文をコピーし、**Profile this query** でクエリを**プロファイル**で開きます。**カタログ**では、テーブルの列、現在のスナップショット、パーティション、場所、プロパティ、スナップショット履歴を開け、**Copy query as of this snapshot** は、そのときのテーブルを読み取る `FOR VERSION AS OF` クエリをコピーします。[Lakehouse ウィンドウ](/ja/guides/data/lakehouse-window/)を参照してください。
- **ステップフォームでプレビューできます。** インポート: SQL、Execute: SQL、SQL抽出、エクスポート: SQL、Salesforce: オブジェクトのクエリの各ステップでは、ステップを実行せずに最大 100 行を表示でき、Anaplan のビューとリストの読み取りでは、生成される列と型が表示されます。**ソース**タブで**プレビュー**をクリックします。変数は、実行時と同じように値が埋め込まれますが、`{x:>9}` のような変数の書式指定はサポートされていません。プレビューが実行するのは標準の SQL 関数のみで、それ以外の場合は、ステップを実行するよう案内が表示されます。ロックされたプロジェクトや、エージェントベースの Execute SQL ステップでは使用できません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と[SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)を参照してください。
- **Table Append と Table Upsert で、ターゲットテーブルにないターゲット列にマークが付くようになりました。** これらのステップは、すでに存在するテーブルに列を追加しないため、マッピングした列がテーブルにないと実行は失敗します。**列**タブは、ステップを開いたときと、別のターゲットテーブルを選択するたびに、ターゲットテーブルの列を読み取り、該当する各**ターゲット列**に ⚠ 警告マークを付けます。マークされた列があるまま保存すると、サーバーがそのマッピングを保存しないため、選択肢は、マークされた行を削除する**すべて削除して保存**と、**キャンセル**のみになります。行を残すには、その列をテーブルに追加してください。変数で指定されたターゲットテーブルは、ステップの実行時にチェックされるため、引き続き**このまま保存**が表示されます。すべてのステップの**古い列が見つかりました**ダイアログで、マークされた行の一覧の冒頭に *次の行は、ステップで使用できない列を指定しています:* と表示されるようになりました。**チェック**から実行するワークフローのレビューでも、マッピングする列がターゲットテーブルにない Table Append ステップや Table Upsert ステップが報告されます。これは多くの場合、ステップの保存後にテーブルが変更されたことを意味します。[ターゲットテーブルに存在しないターゲット列](/ja/reference/workflow-steps/tables/table-upsert/#ターゲットテーブルに存在しないターゲット列)と[ひとつのワークフローのレビュー](/ja/guides/ai-assistant/weave-findings/#ひとつのワークフローのレビュー)を参照してください。

- **Git アプリには、リポジトリの一覧と、できることが表示されます。** アプリ一覧の **Git** には、あなたのロール（**Administrator**、**Contributor**、**閲覧者**）と、ワークスペースのリポジトリが表示され、各リポジトリには、説明、最終更新日、コピーボタン付きのクローンアドレス、**開く**が表示されます。**Set up Git on your computer** カードは、Git のインストール、トークンの作成、クローンの手順を案内し、**How to clone** で再び開けます。**View all in Git** は Git のインターフェース全体を開き、**Manage who can push** はグループ管理を開きます。アクセスレベルは **閲覧者**、**Contributor**（`apps` にアプリコードをプッシュ）、**Administrator**（`udfs` を含むすべてにプッシュ）で、閲覧者には、依頼できるワークスペース管理者が最大 3 人表示されます。新しい **Git Contributors** グループは Contributor を付与し、デフォルトグループにできるため、新しいメンバーは自動的に付与されます。**Git Administration** は Admin を付与します。メンバーの **Git** タブには、Git ユーザー名、レベル、それを付与しているグループが表示されます。メンバーの Git アカウントはメンバーシップに連動します。メンバーを無効化または削除すると、トークンと SSH キーを含む Git アカウントが約 1 時間以内にブロックされ、再び有効化するとブロックが解除されて、リポジトリと履歴は保持されます。シングルサインオンで Git にサインインすると、そのメンバー自身のアカウントが開きます。Contributor は、ワークスペースの Git 組織に直接リポジトリを作成することはありません。リポジトリは PlaidCloud を通じて作成されます。アプリのウィンドウには **Repository** セクションが表示され、UDF には**開く**があり、Git には、ワークスペースに戻る **← Back to** リンクがあります。アプリのリポジトリや組み込みの `apps` と `udfs` リポジトリを含め、プラットフォームが作成するすべてのリポジトリは、ワークスペースのサインイン済みメンバー全員が読み取れるため、メンバーはリポジトリごとの設定なしでアプリを開き、再公開できます。Git 管理者は、リポジトリを引き続きプライベートにでき、その場合はリポジトリピッカーに表示されなくなり、メンバーがそこから公開したり、そこに保存された Git ベースの UDF コードを実行したりできなくなります。[PlaidCloud Git](/ja/guides/git/#git-を開く)と[リポジトリを閲覧できるユーザー](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)を参照してください。

- **Data Foundation がプロジェクトのホームに統合され、どのプロジェクトでも使えるようになりました。** **サマリー**、**システム**、**質問**、**レポート**は、ホームのレールの **Data Foundation** グループにあり、ソリューションで作成したプロジェクトには **配賦** も加わります。**Data Foundation** または Data Foundation を含むソリューションからプロジェクトを作成するか、初回のサインイン時に **財務システムに接続** から始めるか、既存のプロジェクトで **Data Foundation を追加** を選択します。お客様自身の作業はそのまま残ります。**サマリー**には、常に次に行うべき 1 つのステップが表示されます。[Data Foundation を導入する](/ja/guides/projects/data-foundation/#data-foundation-の導入)と[Data Foundation のページ](/ja/guides/projects/data-foundation/#data-foundation-のページ)を参照してください。

- **CFM-Executive - Growth and efficiency は、経常収益、維持率、ユニットエコノミクスを示します。** 年間経常収益を独自の収益クラス別に、また直近 12 か月での変化を顧客ごとに示します。さらに、正味収益維持率と総収益維持率、クラス別の粗利益、新規顧客の獲得コスト、顧客生涯価値、マジックナンバー、バーン倍率、純バーンと現金の月数、従業員 1 人あたりの収益、各年の実績と最新の予測の対比も示します。年間経常収益は契約から求められ、契約ファイルは契約期間のレジスターにもでき、ロードのたびに、各期間が及ぶすべての月末にコピーされ、会社の列がない契約ファイルでは常に **このファイルはどの会社のものですか?** と尋ねられます。**サマリー**の **アクション ▾ > プロジェクトの設定…** を開き、**収益クラス** でクラスに名前を付けます。**質問** では、収益勘定科目と売上原価勘定科目ごと、および契約上の製品ごとのクラスと、各チームの機能を尋ね、可能な場合は名前から回答を提案します。まだ回答していないものは、影響を受ける数値の下に注記が追加されるだけで、何も保留にしません。勘定科目ロールには **手数料** と **転換社債とSAFE** が追加され、それぞれ財務諸表に独自の行を持ち、**手数料** は **CFM-Finance - Operating expense** と **CFM-Finance - Performance against plan** でもコストになります。株主ローン、オーナーローン、個人からの借入にちなんだ名前の勘定科目には、名前に未払も含まれていても **借入金**、請負業者にちなんだ名前の費用勘定科目には **人件費** が提案されます。[成長と効率](/ja/guides/projects/data-foundation-dashboards/#成長と効率)、[収益クラスとチームの機能](/ja/guides/projects/data-foundation/#収益クラスとチームの機能)、[契約レジスター](/ja/guides/projects/data-foundation/#契約レジスター)を参照してください。

- **Weave は Data Foundation プロジェクトを把握し、エージェントと API からも利用できます。** Data Foundation プロジェクトのチャットでは、Weave は、プロジェクトが誰かに求めている対応と、前回のロードが自動で処理した内容を伝えます。また、財務諸表の行の構成、その変動の理由、保証が赤色になっている理由を、原因となっている勘定科目と伝票、およびその修正担当者を示しながら説明し、月末のコメントを下書きします。**サマリー**には、最初に尋ねるとよい質問が表示されます。MCP 接続のエージェントは、プロジェクトの現状の読み取り、数値の説明、質問への回答、テンプレートからのプロジェクトの作成ができます。新しい REST エンドポイントは、システム、質問、サマリー、締め、履歴、レポートを扱います。これまで企業収益性専用だった REST の説明エンドポイントは、財務諸表のすべての行を説明します。[Weave AI チャット](/ja/guides/ai-assistant/weave-tab/#data-foundation)と[MCP 接続の AI エージェントで Data Foundation を使う](/ja/integrations/ai-coding-agents/data-foundation/)を参照してください。
- **メトリックは、直近 N 期間と四半期初来累計に回答し、各数値が対象とする日付を示し、残高、中央値、負の合計に対する構成比、報告どおりの前年を読み取れます。** 直近12か月、四半期初来、年初来を、単独で、または1年前の同じ範囲と比較して尋ねることができ、範囲は会計年度をまたいでさかのぼれます。期間についてのすべての回答は、ウィンドウを会計期間で示し、日付カレンダーでは日付でも示します。Weaveの回答では、1つの数値がカードの先頭に表示され、その下に日付と、以前の期間または予算に対する変化が示され、カードには、残高であることや、データが範囲の途中、または比較対象の範囲の途中から始まることも示されます。カードの**詳しく調べる**は、期間まで続く数値について、**期間**、**四半期初来累計**、**年初来累計**、**直近 N 期間**で範囲を変更できるウィンドウでメトリックを開き、範囲付きの回答から保持した定期リクエストは、その範囲を保持します。メトリックがディメンションを指定していない場合、内訳を表す語は、列またはその要素にあるディメンションを通じて解決されます。現金や売掛金残高のように、時間列が残高としてマークされたメトリックは、期間を合計するのではなく、四半期や年をその最後の期間で読み取ります。期間を指定しない質問は、メトリックの内訳を求めるか、期間でフィルターしない限り拒否されます。メジャーに `median` が加わり、`ratio_abs` は 2 つ目の入力の大きさで割るため、負の合計に対する構成比が正の合計に対する構成比として読み取れます。`prior` は、前の会計年度について読み取るメジャーとフィルターを時間の比較に与えるため、前年の為替レートによる今年の数値を、報告どおりの前年の数値と並べられます。[メトリック定義](/ja/integrations/ai-coding-agents/metric-definitions/)と[メトリックの数値](/ja/guides/ai-assistant/weave-tab/#メトリックの数値)を参照してください。

- **Weave に目的を伝えると、Weave が構築して実行します。** プロジェクトまたはワークフローを作成するダイアログは、フォームで開き、**フォーム** の横に **Weave** の選択肢があります。空の一覧やキャンバスは、**Weave にしたいことを伝える** から始まります。ワークフローを説明すると、Weave は 1 枚の計画カードで回答します。承認すると、ステップが **Built by Weave** のマーク付きでキャンバスに表示されていく様子を確認でき、**停止** で構築を終了できます。ワークフロー、ステップの範囲、または 1 つのステップの実行、ワークフローのスケジュール設定やスケジュールの変更、ステップの変更や追加を Weave に依頼すると、それぞれが承認するカードになります。すべての実行で ERP 転記はオフになり、ERP に転記するステップや PlaidCloud の外部に書き込むステップは、Weave が手を付けずにあなたに任せます。データファイルをプロジェクトの**概要**やキャンバスにドロップするとテーブルやインポートステップになり、SQL スクリプトをドロップまたは貼り付けると標準ステップとして再構築されます。Alteryx ワークフローをドロップするか、そのフォルダーを指定すると、Weave が新しいプロジェクトに変換して実行し、それらが書き込んだファイルと結果を比較した移行レポートを作成します。インポートの後には、**次の推奨ステップ** で最初のグラフやクリーンアップの作成を提案します。[Weave で構築・実行する](/ja/guides/ai-assistant/weave-build/)を参照してください。

- **失敗したステップを1回の操作で修正できます。** ステップを右クリックして **Fix** を選択するか、ログエントリやインスペクターの**修正**を使用します。Weave は、何が変わるか、影響がどこまで及ぶか、次に何が起こるかを示すカードを表示します。1回の承認で、複数のステップにまたがる場合でも変更が適用され、修正したステップを ERP 転記をオフにして再実行し、問題が解消したかどうかをはっきりと伝えます。スケジュールされた実行が失敗すると、Weave はすぐに修正を準備し、カードは **Monitor** の失敗した実行、ログエントリ、ドックで **Apply and re-run** とともに待機し、その所有者には PlaidCloud とスマートフォンで通知されます。承認はブラウザーでのみ行えます。不在の間に Weave が準備したカードは、その会話で**Waiting for you**の行として待機し、開いて確認でき、何かが変更されている場合は現在の状態が表示されます。Weave が行った変更のうち元に戻せるものにはすべて**元に戻す**があり、カード全体を1回の操作で元に戻せます。復元される内容は事前に表示されます。[AIでワークフローのエラーを修正する](/ja/guides/ai-assistant/fixing-workflow-errors/)を参照してください。
- **Weave のジョブは、画面を離れても処理を続けます。** ドックの **Weave** ボタンから**Weave jobs…** を選択すると、各ジョブの状態の確認、進行状況の追跡、会話を開く操作、停止ができます。ドックやタブを閉じてもジョブは続行され、完了したときや対応が必要なときにメッセージが届きます。1分を超えて実行され、停止されなかったジョブについては、アプリを使用していればスマートフォンにも通知が届きます。[処理を続けるジョブ](/ja/guides/ai-assistant/weave-dock/#処理を続けるジョブ)を参照してください。
- **Weave に Monitor が加わりました。** **Weave**タブの**検出事項**ページは**Monitor**になり、レールに**検出事項**、**チーム**、**アクティビティ**、**月次サマリー**、**想定内**、**リクエスト**がまとめられ、クローズのチェックである**準備状況**と**照合**は**Close checks**の下にまとめられています。**検出事項**は、*3 open problems, 1 is yours.* のような Weave の判定を示す 1 行、不在の間に起きたことのメモ、締め処理の状況から始まります。タイルには、未解決の問題、未割り当ての問題、最も古い未解決の問題が表示されます。検出事項は重大度別にグループ化され、影響が及ぶ範囲の大きい順に並びます。失敗した実行は 1 行で表示され、影響を受けるワークフローとダッシュボードはその下にまとめられます。各行には所有者、未解決の期間、1つのアクション（**Fix**、**Ask Weave**、または **Go to**）が表示され、残りは **⋯** の下にあります。行を開くと、Weave の説明文、根拠、Weave がどのように判断したか、コメントを読むことができ、**所有者**と**ワークフロー**で絞り込めます。**提案**の下では、誰かが一定のパターンで手動実行しているワークフローに **Automate this** が表示され、スケジュールを提案します。**これは想定内** は今後通常とする範囲をマークし、**想定内** には Weave がプロジェクトについて学習した用語と規則も一覧表示されます。[Weave タブ](/ja/guides/ai-assistant/weave-tab/)を参照してください。
- **締め処理が夜間に準備されます。** 期限がある準備状況セットについて、Weave は毎日、および依存する実行の後に締め処理をチェックし、対応できる問題ごとに修正または再実行を準備して、*Month-end close is 92% done. Two things need you.* のような 1 枚のカードを表示します。各判断には番号が付き、それぞれ承認用のカードがあります。[夜間に準備される締め処理](/ja/guides/ai-assistant/weave-readiness/#夜間に準備される締め処理)を参照してください。
- **Weave の回答を保持し、レポートやアラートを依頼できます。** 回答の下にある **Keep ▾** で、その回答を定期リクエスト、メトリック、ホワットイフシナリオ、チームのレシピ、またはピン留めした回答として保持できます。スケジュールに従って、またはワークフローの実行後に届くレポートやアラートを普通の言葉で Weave に依頼すると、PlaidCloud、スマートフォン、そして数値を含まないメールで知らせます。リクエストは **Monitor → リクエスト** で、**今すぐ実行**、**一時停止**、**変更**、**削除** を使って管理します。[回答と定期リクエストを保持する](/ja/guides/ai-assistant/weave-requests/)を参照してください。
- **数値の根拠をたずねられます。** テーブルエクスプローラーのセル、またはダッシュボードのグラフのポイントやセルを右クリックして **Why this number** を選択すると、Weave がその数値を書き込むステップとその元になっているもの、前回の実行や前期からどのように変化したかを示します。テーブルエクスプローラーでは、**時点** にテーブルの以前のバージョンがそれを書き込んだ実行ごとに一覧表示され、**Compare with now** でそれ以降に変更された行と列が分かります。配賦の結果についてのホワットイフを言葉で質問すると、即座に見積もりが得られます。照合の最後の結果は、*Tied out to Cost Pool at 06:02.* のように保持されます。[数値の根拠](/ja/guides/ai-assistant/weave-numbers/)を参照してください。
- **Weave をチームで共有できます。** 回答をピン留めすると、プロジェクトの全員がそれを見ることができ、各自のアクセス権で再実行されます。質問をレシピとして保存すると、誰でもドックから `/` で、またはトリガーで実行できます。どちらもプロジェクトの**概要**の **From your team** に一覧表示されます。ステップ、ワークフロー、テーブル、検出事項にはコメントスレッドがあり、チームメンバーにメンションしたり @Weave に質問したりできます。また、Weave がワークフローで作業している間は、キャンバスにその様子が表示されます。[Weave をチームで共有する](/ja/guides/ai-assistant/weave-team/)を参照してください。
- **Weave の価値を確認できます。** 検出事項によっては、通知する価値があったかどうかを高評価と低評価のアイコンで尋ねるものがあります。**月次サマリー**には、Weave の検出事項と回答がどの程度役に立ったか、Weave が修正した失敗実行、チームメンバーが再利用したピン留めされた回答が、節約できた時間の推定値とともに、プロジェクト全体またはあなた個人について表示されます。[Weave 月次サマリー](/ja/guides/ai-assistant/weave-monthly-summary/)を参照してください。
- **モバイルの Weave で、1回のタップで音声入力できます。** マイクをタップして質問を話すと、話し終えた時点で Weave が送信します。もう一度マイクをタップすると途中で停止でき、何も聞き取れない場合は自動的にオフになります。話している途中で**Weave**タブを離れたりアプリをバックグラウンドにしたりした場合、話した内容は送信されずに質問ボックスに残るため、確認できます。実行、一時停止、停止、再開は、確認時の誤った二重タップを無視します。アプリのバージョン1.3.0以降が必要です。[音声を使う](/ja/guides/mobile-app/weave-on-mobile/#音声を使う)を参照してください。
- **Weave が問題をメールで知らせます。** ワークフローの実行が、確認が必要な重大な問題で終了したときのメールと、Weave が知らせた問題のうち未読のものをまとめた毎日のサマリー（指定した時刻に送信）を、自分用にオンにできます。メールには、プロジェクトと、各ワークフロー、ステップ、テーブル、メトリックが問題の種類とともに記載され、**Weave**タブへのリンクが付きます。データの数値や値が含まれることはありません。ワークスペース管理者は、全員の Weave メールをオフにしたり、各メンバーのタイムゾーンでお休み時間を設定し、その時間が終わるまでアラートを保留したりできます。[Weave メール](/ja/guides/ai-assistant/weave-email/)を参照してください。
- **Weave によるお客様のデータの利用について。** **Weave**メニュー、すべての AI チャットの下、**AI機能**に新しいパネルが加わり、Weave が AI プロバイダーに送信する内容と、プロバイダーがそのデータをどのように利用できるかを何が決めるかが分かります。[Weave によるお客様のデータの利用について](/ja/guides/ai-assistant/weave-data-use/)を参照してください。
- **Weave は、メトリックへの寄与を開始または停止した項目を報告します。** Weave は毎日、プロジェクトの各メトリックを内訳列で分割し、工場や顧客などの項目が開始または停止し、その状態が3期間続いた場合に、メトリックの所有者へ、その発生時期とともに通知します。複数のメトリックで同時に開始または停止した項目は、それぞれのメトリックを挙げた1件の検出事項になります。会計四半期のように一度に1つの項目しかない内訳は、合計値の異常の要因となる項目として名指しされなくなりました。[開始または停止した項目](/ja/guides/ai-assistant/weave-metric-insights/#開始または停止した項目)を参照してください。
- **Weaveは、割合が変化してその状態が続いた項目を報告します。** 項目がメトリックの合計に占める割合と、その項目自身の値が4期間連続で同じ方向に動いた場合、Weaveはメトリックの所有者へ、変化が始まった時期とともに1回だけ通知します。1年前の同じ時点でも起きていた変化は、季節性のものとして扱われ、報告されません。[割合が変化した項目](/ja/guides/ai-assistant/weave-metric-insights/#割合が変化した項目)を参照してください。
- **1日待たずに、プロジェクトのメトリックを今すぐチェックできます。** Weaveがまだ読み取っていないメトリック、または最後の読み取りが古くなっているメトリックがある場合、プロジェクトのアーキテクトには**すべてのメトリックを今すぐチェック**が表示されます。Weaveは毎日のチェックと同じ方法で、プロジェクトのメトリックをすぐに読み取り、完了するとWeaveタブが更新されます。チェックは、プロジェクトごとに15分に1回開始できます。[メトリックを今すぐチェックする](/ja/guides/ai-assistant/weave-metric-insights/#メトリックを今すぐチェックする)を参照してください。
- **Databricks パートナー連携で、一括ロードとより明確な識別に対応しました。** PlaidCloud は、Databricks に対して `PlaidCloud_Lakehouse`（お客様のウェアハウスとそのダッシュボード）または `PlaidCloud_Connector`（ワークフローの Databricks 接続）として自身を識別させるため、管理者は PlaidCloud のクエリを見分けられます。Databricks 接続へのテーブルのプッシュは、行ごとではなく、Unity Catalog ボリュームにステージングして一括でロードされ、Databricks のレイクハウスプロジェクトへのファイルとドキュメントのインポートも同様です。ボリュームの権限がない場合でも、プッシュは行ごとに完了し、ステップは警告を表示します。要件、手順付きの 3 つのサインイン方法、Unity Catalog の最小権限、サーバーレス SQL ウェアハウスの推奨事項については、[自分のウェアハウスを使用する](/ja/guides/connections/external-lakehouse/#databricks-の要件)を参照してください。Databricks のウェアハウスを削除すると、PlaidCloud が保持するそのサインインのコピーは削除されますが、Databricks 側では取り消せません。Databricks ウェアハウス上のダッシュボードは、自動的に一度だけ再登録されます。
- **お客様のウェアハウスに、ダイレクトなプライベート接続で到達できます。** **ウェアハウスの詳細** の**接続**行に、ワークスペースがウェアハウスに、同じクラウドとリージョン内で到達しているのか、公共のインターネット経由か、プライベートリンク経由かが表示されます。プライベート接続を含むプランでは、ワークスペース管理者が、ワークスペースと同じクラウドおよびリージョンにある Snowflake または Databricks のウェアハウスに対して**直接接続をリクエスト**を選択します。この行はリクエストの状況に従って変わり、ウェアハウス管理者が実行する手順がある間は、**手順を表示**に各手順がコピー可能な正確なテキスト付きで一覧表示されます。ワークスペースは、プライベート接続がチェックに合格するまで現在の経路を使い続けます。[直接接続](/ja/guides/connections/external-lakehouse/#直接接続)を参照してください。

## 変更

- **お気に入りがすべてのブラウザーに引き継がれます。** ダッシュボード、アプリ、プロジェクト、ワークフローなどの項目に付けたスターは、1つのブラウザーではなくアカウントに保存されます。JupyterLiteノートブックにもスターを付けられ、**ホーム**にはそのための**ノートブック**フィルターチップがあります。フィルターチップは、開くことができる種類にのみ表示されます。ブラウザーが初めてお気に入りを読み込むときは、そのブラウザー自身が保持していたものがアカウントのものの後ろに最大100件まで追加され、収まらなかった件数はメッセージで表示されます。[ピン留め（お気に入り）](/ja/guides/launcher/#ピン留めお気に入り)を参照してください。
- **ホームには一度に1つのメモが表示され、ページはよりシンプルになりました。** セットアップのステップは、次のステップとそのボタンがある1行になり、**すべてのステップ**で残りが開きます。ホームには、セットアップの行、組織と請求に関するメモ、ヘルプのメモ、ヒントのうち1つだけが表示され、**要対応**はその上に表示されます。ホームのツールバーに**検索**ボタンはなくなりました。ヘッダーの**検索**または **Ctrl/Cmd-K** を使用してください。種類のチップとプロジェクトのタイルの数値にアイコンはなくなり、**要対応**のカードは短くなり、件数には桁区切りが付き、サムネイルも説明もないダッシュボードのタイルには**プレビューはまだありません**と表示されます。ホームと、ワークフローのインスペクターの**最終実行**では、時刻は30日までは何日前かで、それ以降は短い日付で表示されます。[ランチャー](/ja/guides/launcher/)を参照してください。
- **Weave は、各メトリックの最大15個の内訳列を読み取ります。** 以前は最初の5つしか読み取らなかったため、それ以降の列にある項目（たとえば工場）は、合計値の異常の要因として名指しされたり、開始または停止として報告されたりすることがありませんでした。ディメンションに関連付けられた列は、これまでどおり最初に読み取られます。[メトリックの合計値の異常](/ja/guides/ai-assistant/weave-metric-insights/)を参照してください。
- **プロジェクトウィンドウのアクティビティパネルに、何が実行され、成功したかどうか、誰が何を変更したかが表示されます。** 以前のアクティビティストリームに代わるものです。ワークフローの実行ごとに 1 行が表示され、結果、所要時間、実行したユーザー（またはスケジュールやセンサー）がわかります。失敗した実行にはエラーが表示され、実行中に失敗または警告が出たステップには名前とメッセージが表示されます。クリックすると、そのステップでワークフローが開きます。**現在実行中**には進行中の実行が一覧表示され、それぞれに**停止**があります。行は日ごとの見出しの下に並び、見出しには実行数、失敗数、変更数が表示されます。連続する編集や成功した実行は 1 行にまとめられます。実行の上にマウスを置くと、**ログを開く**と**ワークフローの実行**のアイコンボタンが表示されます。パネル下部で**すべて**、**実行回数**、**変更**、**問題**、**自分**を選ぶか、**フィルター**に入力します。パネルのヘッダーにある問題の件数をクリックすると、失敗または警告が出たものだけが表示されます。**前回の訪問以降の新着**の行は、そのブラウザーでプロジェクトウィンドウを前回訪問してから届いた内容を示します。一覧は過去 7 日間から始まり、**以前のものを表示**で 30 日ずつさかのぼれます。パネルのラベル、文、日付はお使いの言語で表示され、エラーテキストは英語のままです。REST API の `GET /rest/v1/analyze/activity` は、同じアクティビティと実行中の実行を返します。[アクティビティパネル](/ja/guides/projects/viewing-projects/#アクティビティパネル)を参照してください。
- **列を検索は、入力に合わせて検索し、近いつづりに一致し、列の型を表示します。** **テーブル**タブのツールバーの**列を検索**が、列検索ボックスと列ツリーのウィンドウに代わります。ウィンドウには入力に合わせてテーブルが一覧表示され、列名は**完全一致**、**含む**、**あいまい**で一致させられます。**あいまい**は区切り文字を無視し、小さなタイプミスも許容します。テーブルを展開すると、一致した列とその型が表示され、他の結果で型が異なる列にはフラグが付き、**参照元**と**参照先**に各テーブルをつなぐステップの名前が表示されます。チップで結果を 1 つの列名に絞り込め、そのプロジェクトでの最近の検索もワンクリックで呼び出せます。テーブルをダブルクリックすると**テーブル**タブで選択され、Ctrl+Enter（Mac では Cmd+Enter）を押すとテーブルエクスプローラーで開き、**ツリーに表示**を選択するとツリーが結果に絞り込まれます。**コピー**は結果をクリップボードにコピーします。Lakehouse v2 では、列名の検索がより高速になります。AI アシスタントは `table_find(column=..., column_match='fuzzy')` で検索でき、一致した各列の型を取得できます。[列別](/ja/guides/projects/managing-tables-and-views/#列別)を参照してください。
- **すべて整理は各列の中の順序を決めます。** **配置** → **すべて整理**では、上から下の順序はこれまでどおりには保たれなくなります。ステップは引き続き左から右へ流れ、レイアウトはキャンバス上の元の位置にとどまりますが、各列の中の順序は、リンクの交差が減るように決められます。**選択範囲を整理**では、選択した項目の順序が保たれます。[キャンバスを配置する](/ja/guides/workflows/advanced-workflows/#キャンバスを配置する)を参照してください。
- **フィルターできる 1 つのチェックリストで、あらゆる場所のユーザー、グループ、ワークフローを割り当てられます。** セキュリティグループのメンバー、メンバーのグループとの関連付け、配布リストのメンバー、ドキュメントアカウントのメンバー、グループ、エージェント、所有者、接続アクセス、Weave の準備状況セットのワークフローが、ドラッグで移動する 2 つのリストではなく、同じピッカーを使うようになりました。名前やメールアドレス（`@example.com` のようなドメインを含む）で絞り込み、メールアドレスの一覧を貼り付けてそのユーザーだけに一致させ、**すべて**、**割り当て済み**、**Not assigned** を切り替え、**Assign all shown** または **Unassign all shown** を使えます。変更した行には **Will add** または **Will remove** のピルが付き、**Undo changes** で元に戻せます。保存ボタンは、変更があったときだけ使えます。フィルター内の **Enter** では保存されず、**Space** で選択中の行にチェックが入ります。アクセスを確認できても変更できない場合、リストは読み取り専用です。

Re-run the workflow.」で失敗します。[ワークフローを実行する](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
  - **再開、実行履歴、実行ステータスが、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローの 1 つのステップを単独で再実行した後でも、子ワークフローが残していたすべてが実行され、1 回の実行の中での子ワークフローの呼び出しごとに、それぞれ実行履歴のエントリが作成されます。サーバーが停止したために再開するステップは、そのことをログに記録します。`workflow_run_status` と REST API の実行結果は、失敗したものの続行されたステップを `continued_step_ids` と `continued_step_count` に一覧表示し、実行を問題なしとして報告しなくなりました。また、警告付きで終了したステップも `warned_step_ids` と `warned_step_count` に一覧表示します。警告のある実行も成功として表示されるためです。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。

  - **完了しない ERP 抽出はそのステップを失敗させ、再開で続行できます。** **SAP: アドホック抽出** が行数または時間の上限で一時停止したり、そのエージェントが時間内に応答しなかったりした場合、または、ステップが待機を打ち切ったときに、Salesforce、Oracle Fusion の一括、HFM/FCCS のエクスポートジョブがまだ実行中だった場合、ステップは失敗するため、その後のステップが一部のテーブルで実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は、停止した場所から同じジョブで続行されます。[実行制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)を参照してください。
  - **エクスポートをキャンセルすると、ウェアハウス内のクエリも停止します。** エクスポートまたはダウンロードがキャンセルされた場合（ワークフローの停止による場合を含みます）、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplum では、そのデータを読み取っているクエリも停止し、リモートデータベースへのエクスポートは、最後まで実行を続ける代わりに、ソースの読み取りを停止します。
- **REST、Import REST、Import Postman の各ステップは、ワークスペースのアップグレード時に RESTリクエスト ステップに変換されます。** きれいに変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **セッションの有効期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードに移動します。** [ダッシュボードを使用する](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは、認識できないフィールドを無視せず、拒否して、エラーにその名前を表示します。** `workflow_upsert` は `memo` を受け付け、その別名として `description` も受け付けます。[不明なフィールドは拒否されます](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2 では、Lakehouse が Parquet のエクスポートを Google Cloud Storage と Amazon S3 に直接書き込みます。** Google Cloud Storage または Amazon S3 のドキュメントアカウントへのエクスポートは、すべての行がいったん PlaidCloud を経由するのではなく、そのアカウント自身の認証情報で、アカウントのバケットに直接書き込まれます。Azure Blob Storage のアカウントへのエクスポートは、従来どおり動作します。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/)を参照してください。
- **Slack、Microsoft Teams、Web Hook の各ステップは、メッセージが送信されなかった理由を表示します。** ステップのエラーには、接続を試みたサーバー、Slack と Teams の場合は接続の名前、何が問題だったかが示されます。たとえば、Slack がもう Webhook を認識しない、チャンネルに投稿できない、サーバーが見つからないか 60 秒以内に応答しない、接続が削除されている、などです。Slack または Teams の Webhook URL は、それを持つ誰もがあなたの連携として投稿できてしまうため、表示されることはありません。[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/)を参照してください。
- **プロジェクトのサービスアカウントのアクセストークンは、少なくとも 24 時間有効です。** UDF ステップなど、プロジェクトとして実行されるワークフロージョブには、24 時間有効なトークンが発行されます。それより短い有効期間は、ワークスペースのアップグレード時に引き上げられ、設定したそれより長い有効期間は保持されます。
- **ワークスペースの組織、所有者、リリース、バージョンは PlaidCloud が設定し、データセンターは選択できます。** コントロールプレーンで作成したワークスペースは、あなたが所有者となり、PlaidCloud が設定するリリースチャネルに配置され、**Data Center** は、サインアップ時に提示されるリージョンから選択します。ワークスペースを編集するとき、組織、所有者、リリース、バージョンは読み取り専用です。バージョンを変更するには **Set Version** を使用し、ワークスペースの移動、所有者やチャネルの変更、固定が必要な場合は、PlaidCloud サポートに依頼してください。[ワークスペース構成](/ja/administration/control-plane/workspace-configuration/#基本設定)を参照してください。
- **エンコード変換ステップで、フォルダーのサブフォルダーを保持できます。** **ドキュメント: ファイルをASCIIエンコードに変換**、**ドキュメント: ファイルをUnicode（UTF-8）エンコードに変換**、**ドキュメント: ファイルをUnicode（UTF-16）エンコードに変換**に、**サブフォルダーを保持**ボックスが加わりました。チェックを入れると、入力フォルダーのサブフォルダー内の各ファイルが、書き込み先の対応するサブフォルダーに書き込まれ、圧縮ファイルの内容は、そのファイルがあったサブフォルダーに入ります。チェックを外したままにすると、従来どおり、すべてのファイルが書き込み先に直接書き込まれます。[ドキュメントのエンコードを UTF-16 に変換する](/ja/reference/workflow-steps/document/convert-document-encoding-to-utf-16/)を参照してください。
- **ソーステーブルが設定と一致しないステップは、何も書き込む前に停止し、すべての問題をまとめて示します。** Table Extract、Table Lookup、Table Inner Join、Table Cross Join、Table Outer Join、Table Anti Join、複数テーブル結合、Table Union Distinct、Table Union All、Table Pivot、Table Melt、Table In-Place Delete、Table Upsert、Table Append の各ステップは、書き込む前にソーステーブルを確認します。ステップが読み取る列がテーブルにない、結合キーがない、またはステップのソース列に含まれていない、ステップが読み取るソーステーブルがまだ作成されていない、といった場合は、それぞれの問題と修正方法を示す 1 つのエラーでステップが停止し、すでに存在していたターゲットテーブルは、それまでの内容を保持します。ソーステーブルが作成されていない場合、Table Union Distinct と Table Union All は例外です。従来どおり、警告なしにそのテーブルを除外して残りを結合し、1 つも作成されていなければ、失敗せずに警告付きで完了します。ステップが一覧に挙げているものの読み取らず、テーブルにももうない列は、代わりに警告となるため、以前に実行できたステップは引き続き実行できます。ターゲットがビューのステップでは、それが一覧に挙げる列と結合キーは、ウェアハウスがいずれにせよビューの作成を拒否する場合に限り、そのテーブルと照合して確認されます。これらの失敗は、以前はデータベースから、データベース独自の言葉で、列ごとに 1 つずつ返されており、ターゲットテーブルを置き換えるステップでは、すでにそのテーブルが空になっていました。ワークフローのエラー処理がデータベースのテキストに一致させている場合は、更新してください。[ステップが実行されるとき](/ja/reference/workflow-steps/tables/table-extract/#実行時に指定された列)を参照してください。
- **テーブルのないエクスポートは、完了せずに停止します。** テーブルのない Export to Parquet、Export to ORC、Export to Avro の各ステップは、ファイルを書き込まずに完了し、テーブルのない Export to XML ステップは、何も含まないファイルを書き込んでいました。これらのステップは、何も書き込む前に、*No Tables Specified* で停止するようになりました。テーブルの一覧がまったくない状態で保存されたステップは、内部設定の名前を挙げた予期しないエラーで失敗していましたが、同じメッセージで停止するようになりました。
- **ワークフロー: 実行ステップで開始されたワークフローは、呼び出し元の実行の開始時に指定された値を使用できます。** アプリランナーで入力された回答や、実行の開始時に渡された値は、その実行が開始するワークフローに引き継がれます。対象は、呼び出されたワークフローとそのプロジェクトが自身で定義していない変数です。[ワークフローの実行](/ja/reference/workflow-steps/workflow-control/run-workflow/)を参照してください。
- **ウェアハウスは、ウェアハウスの管理から接続・管理します。** ユーザーメニューに**自分のウェアハウスを使用する**という項目はなくなりました。**ウェアハウスの管理**が同じ役割を果たすためです。**ウェアハウスを追加**でウェアハウスを接続し、**デフォルトに設定**で新規プロジェクトのデフォルトにします。各ウェアハウスは**詳細**で開けるほか、名前の変更、認証情報のローテーション、サインインの更新、無効化と再有効化ができます。**ステータス**には、変更がまだワークスペースに届いている最中か（**切り替え中…**）、対応が必要か（**注意**）が表示され、**今すぐ確認**でもう一度チェックして、不足している付与をコピー用に一覧表示し、それぞれに実行したらチェックを入れる**完了**ボックスが付きます。**Snowflake でサインイン** または **Databricks でサインイン** の後はウェアハウスがもう一度チェックされ、チェックに成功すると、そのウェアハウスが選択された状態で**お使いのウェアハウス**が開き、そうでなければ、ウィンドウに不足しているものが一覧表示されます。新しいウェアハウスには、アドレスから付けられた名前（例: `Snowflake — myorg-myaccount`）が付き、変更できます。**サンプルを実行**は、デフォルトにしたばかりのウェアハウスでサンプルプロジェクトを実行します。有効期限が近いトークンのホームバナーには、**ローテーション**が表示されます。[ウェアハウスの管理](/ja/guides/connections/external-lakehouse/#ウェアハウスを管理する)を参照してください。
- **Lakehouse 設定がコントロールプレーンのワークスペースダイアログからなくなりました。** 外部データベースアクセス、その許可する CIDR 範囲と拒否する CIDR 範囲、追加の Lakehouse ユーザーは、PlaidCloud が設定するようになりました。ご自身のウェアハウスは、ワークスペースの**ウェアハウスの管理**から接続します。[Lakehouse](/ja/administration/control-plane/workspace-configuration/#lakehouse)を参照してください。
- **PlaidCloudが実行前に確認するSQLは、最大65,536文字です。** これより長いSQLは実行されずに拒否され、メッセージにはその長さと上限をどれだけ超えているかが示されます。文字数には、コメント、空白、入力済みのパラメーターも含まれます。この上限は、`query_run`とMCPのテーブルエクスポートで実行するSQL、AIアシスタントからのクエリ、プロジェクトデータを変更できないメンバーによるREST APIおよびJSON-RPC APIのクエリ、行アクセスでフィルターされるすべてのクエリに適用されます。ワークフローのステップが生成するSQLには、この上限はありません。[クエリが長すぎて拒否される](/ja/integrations/ai-coding-agents/troubleshooting/#クエリが長すぎて拒否される) を参照してください。
- **MCP で接続された AI エージェントは、ネイティブのテーブルステップを使うよう誘導されます。** データが PlaidCloud に入ったら、エージェントは、変数を置き換えず 1 つのウェアハウス向けに記述される SQL抽出ステップではなく、Table Extract、結合、Table Melt、Table Union All などのステップで各変換を構築するよう指示されます。`query_run` は、`step_upsert` が受け取るとおりに Table Extract の設定をプレビューし、SQL抽出ステップを保存すると、代わりに使うネイティブステップを示す注記が返されます。[ネイティブステップでワークフローを構築する](/ja/integrations/ai-coding-agents/getting-started/#ネイティブステップでワークフローを構築する)を参照してください。
- **新しいサポートチケットに「キャンセル」があり、入力中も開いたままになります。** **ヘルプとサポート**で、**キャンセル**をクリックすると、新しいチケットを送信せずに破棄できます。また、チケット一覧を更新しても、入力中のチケットが置き換えられなくなりました。

- **認定に関する修正です。**
  - **バッジは確認済みのメールアドレスにのみ表示されます。** **メンバー** 一覧と、MCP 経由でメンバーを読み取る AI エージェントでは、メールアドレスが確認済みでないメンバーのバッジも表示されていました。現在、そのようなメンバーには表示されません。

  - **残されたラボのプロジェクトは削除されます。** 挑戦の終了時に削除できなかったラボのプロジェクトが、認定ワークスペースに残っていました。現在は、夜間クリーンアップが削除します。

- **すべて整理で、変換されたワークフローのステップがグループ内に保たれます。** グループが別のグループの内側にある状態で変換されたワークフローでは、**すべて整理**がステップをグループの外へ出してしまっていました。そのようなことは起こらなくなりました。以前に変換されたワークフローは、ワークスペースがアップグレードされるたびに修正されます。その大半では、入れ子のグループが分離され、名前とレイアウトは保たれます。[コンテナー](/ja/guides/workflows/advanced-workflows/#コンテナー)を参照してください。
- **無効なプロジェクト設定が、分かりやすいメッセージで報告されます。** 不明な環境またはドキュメントアカウント、使用済みまたは予約済みのスラッグ、無効なストレージタイプまたは転記モードは、一般的なサーバーエラーの代わりに、問題を示すメッセージを返すようになりました。REST API では 500 ではなく 400 に、AI アシスタントまたは MCP では無効な引数のエラーになります。
- **REST API のディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` は、グリッドリクエストとして処理され、無効として拒否されていました。現在は、`value_columns` の各列に対して集計された 1 つの値を返します。グリッド（行フィルターと列フィルターの各組み合わせに対する 1 つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` が用意されています。
- **テーブルの読み取りやファイル処理が遅くても、他のリクエストが待たされなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundation ファイルの登録、Excel へのエクスポート、REST または SOAP インポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panelアプリのコードやロゴの確認は、それぞれ、完了するまで同じサーバーが処理している他のすべてのリクエストを停止させる可能性がありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 小さな画面や低解像度では、追加および編集ダイアログがウィンドウより高くなり、**作成**ボタンと**更新**ボタンに手が届かないことがありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storage のドキュメントアカウントで、256 MiB を超えるファイルをコピー、移動、名前変更できます。** 以前は、そのサイズのファイルではこれらがすべて失敗し、そのようなファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2 では、テーブルの行数に、書き込んだばかりの内容が反映されます。** テーブルを書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが 0 行と表示されたり、インポートが 0 行をインポートしたと報告したりすることがありました。現在は、新しい行がすべての場所で見えるようになってから行数を読み取るため、その後のステップもそれらを読み取れます。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりしても、行数と列数が更新されます。
- **Weave の空値チェックは、各実行を、以前の実行が実際に残したものと比較します。** ステップの空値は、ステップがテーブルを空にして再入力した直後にカウントされることが多く、以前の実行には空値がなかったように見え、常に一部が空だった列が、たった今そうなったかのように報告されていました。現在は、各実行を、ステップがテーブルを残した状態でカウントします。以前に記録されたカウントは、正しいものと区別できないため使用されません。各ステップの空値チェックは履歴を最初から取り直し、5 回の実行がカウントされるまでは未チェックとして報告されます。また、行数と値の分散のチェックでは、ステップの完了から 2 秒を超えて後に別のステップが同じテーブルに行った書き込みを、そのステップの書き込みとして扱わなくなりました。[Weave が確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **Data Foundation は、反転した為替レートと小数のしきい値の精度を保持します。** 為替レートが報告通貨から別の通貨への相場で提示されているために PlaidCloud が逆数にしたレートは、小数点以下 6 桁に丸められることがあり、インドネシアルピアのようにレートの小さい通貨では、金額が約 1% ずれていました。反転したレートは、小数点以下 12 桁を保持するようになりました。`0.5` のように小数を含む `group_amber` または `group_red` のしきい値は、整数に丸められていました。次の**ロード**から、正確な値が使われます。[為替レート](/ja/guides/projects/data-foundation/#為替レート)を参照してください。
- **無効化されたメンバーのアラートとダイジェストは停止します。** 所有者が無効化されたPanelアプリのアラートやダイジェストは、チェックと送信を続けていました。現在は、無効化されている間は一時停止し、再び有効化されると再開します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
- **削除された接続を REST API に要求すると、404 が返されます。** 削除された接続や、存在しない ID を要求すると、一般的なサーバーエラー（500）が返されていました。現在は、接続 ID を示すメッセージとともに 404 が返されます。
- **テンプレート化されたテーブルのエクスポートが、AI アシスタントと MCP で動作します。** `table_data_export` の `templated` 形式は、テーブルを指定すると常に失敗していました。現在は、テンプレートを通じてテーブルをエクスポートし、読み取れる行に限定されます。テンプレート内では、テーブルの行は、テーブル ID の各 `-` を `_` に置き換えた名前で参照されます。
- **Amazon S3 と S3 互換のドキュメントアカウントが、リージョンを保持します。** これらのアカウントを保存すると、入力した**リージョン**が破棄され、次にアカウントを開いたときにフィールドが空になっていました。リージョンが保存されるようになりました。この修正より前に保存したアカウントでは、リージョンをもう一度入力して保存してください。[AWS S3 アカウントを追加する](/ja/guides/documents/adding-accounts/add-aws-s3-account/)を参照してください。
- **開始パスのない SFTP ドキュメントアカウントは、すべてのパスをサインイン先のフォルダーから読み取ります。** ファイルのダウンロード、詳細の読み取り、エクスポートでは、`/` で始まるパスを、アカウントがサインインするフォルダーではなく SFTP サーバーのルートから読み取っていました。ドキュメントブラウザーでは、そのパスはサインイン先のフォルダー内のものとして表示されます。現在は、ブラウザーと同じようにそのフォルダーから読み取り、サインイン先のフォルダーで始まるパスも、これまでと同じファイルに届きます。フォルダー内のすべてのファイルのインポートと、フォルダーに対するドキュメント変換ステップの実行は、そのフォルダー内の各ファイルに届くようになりました。以前は、フォルダーを付けずに各ファイルを探していました。
- **ASCIIのみでWindowsの文字が少しだけ含まれるファイルを、正確に読み取ります。** ASCIIのみで、Windowsのダッシュ、引用符、アクセント付きの文字が少しだけ含まれるファイルは、エンコード変換ステップで「reads as neither UTF-8 nor ascii」というエラーで失敗したり、Data Foundationへの追加時に失敗したり誤ったエンコードで読み取られたり、**インポート: CSV** でそれらの文字が � に置き換わったり誤ったエンコードでインポートされたりすることがありました。エンコード変換ステップと、**エンコーディング**を空白にした場合の**インポート: CSV**は、文字を書かれたとおりに読み取るようになり、Data Foundationもファイルの最初の4 MBにそれらの文字がある場合は同様です。エンコードを割り出せないインポートは、文字の代わりに � をインポートするのではなく、ファイルを示すエラーで停止するようになりました。[ドキュメントのエンコードをUTF-8に変換する](/ja/reference/workflow-steps/document/convert-document-encoding-to-utf-8/#仕組み)を参照してください。
- **フォルダーのエンコード変換で、同じ名前の別のファイルが上書きされなくなりました。** 書き込み先の同じ場所に向かう 2 つのファイル（たとえば、異なるサブフォルダーにある同じ名前の 2 つのファイル）では、最後に書き込まれた 1 つしか残りませんでした。ステップは、2 つ目を書き込む前に停止し、両方のファイルと書き込み先を示し、**サブフォルダーを保持**にチェックを入れるとそれらを分けて保持できる場合はその旨を表示するようになりました。
- **ドキュメント: ファイルをASCIIエンコードに変換 の「ターゲットエンコードで表現できない文字を ? に置き換える」をオフにすると反映されます。** **ターゲットエンコードで表現できない文字を ? に置き換える**にチェックを入れて保存したステップは、チェックを外してもう一度保存しても、そのままの状態でした。チェックを外すと、置き換えがオフになります。
- **AI アシスタントと JSON-RPC は、ロールで非表示になっているテーブルを使用するステップの名前を表示しなくなりました。** そのようなテーブルの使用箇所を尋ねると、ロールで参照できる、そのテーブルを読み取るまたは書き込む各ステップが、その設定とワークフローとともに表示されていました。現在は、プロジェクトのテーブル参照と同様に、ステップ名を表示せず、ステップがそのテーブルを使用していることだけを伝えます。[ロールで非表示になるもの](/ja/guides/ai-assistant/weave-tab/#ロールで非表示になる内容)を参照してください。
- **選択したデフォルトの AI 接続は、デフォルトのままになります。** AI 接続をワークスペースのデフォルトとして設定しても、成功したように見えるだけで保存されておらず、デフォルトに依存するエージェントとステップは、最後に更新された接続を使い続けていました。選択内容が保存されるようになりました。[LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **Weave の履歴で会話を右クリックしても、「スレッドを削除」の上に「名前の変更」が開かなくなりました。** **名前の変更**は、チャットのタブに移動しました。これまで何も表示されなかったタブを右クリックしてください。[Weave タブのタブ](/ja/guides/ai-assistant/weave-tab/#weaveタブ内のタブ)を参照してください。
- **多くの参照が必要な質問で、Weave が汎用エラーで止まらなくなりました。** 質問への回答や失敗したステップの診断に 12 回前後を超える参照が必要な場合、Weave は *An internal error occurred. Please try again.* で終了し、すでに用意していた修正も破棄していました。現在はその 2 倍まで参照できます。それでも足りない場合は、見つけた内容と用意した修正を表示し、途中で止まったことを伝えます。
- **空白のメモがあっても保存できます。** **メモ**ボックスを空のままにして、プロジェクト、ディメンション、テーブル、ウェアハウス、エディター、スケジュール済みワークフローイベント、配布リストを作成または保存すると、「Memo: Input should be a valid string」で失敗していました。空白のメモが受け付けられるようになりました。
- **1 つの値が期待される場所に複数の値を返す式は拒否され、Table Extract または Table Union All ステップは、ターゲットテーブルのデータを保持します。** よくある原因は、`table.amount,` のような末尾のカンマや、`table.region == ('EU', 'US')` のような複数の値との比較です。Databend ではステップが失敗し、Table Extract または Table Union All ステップでは、その時点でターゲットテーブルがすでに空になっていました。他のウェアハウスの中には、このような式を実行するものもありましたが、必ずしも記述どおりには実行されなかったため、これまでエラーなく動作していたステップが拒否されることがあります。ステップフォームは、ステップを保存するときにその式を拒否し、メッセージに変更すべき点が示されます。[1 つの値が期待される場所に複数の値](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#1つの値が必要な場所に複数の値がある場合)を参照してください。
- **出力列の名前を 2 回指定したステップは、ターゲットを空にする前に停止します。** Table Lookup、Table Extract、結合で、同じ名前の **ターゲット出力列** が 2 つあると、ステップはターゲットテーブルを空にした後、分かりにくいエラーで失敗していました。現在は、先にステップが停止し、重複している列を示すメッセージが表示されるため、各出力列に固有の名前を付けられます。クエリが返す順序で列を書き込む SQL抽出は、変更ありません。[Table Lookup](/ja/reference/workflow-steps/tables/table-lookup/)を参照してください。
- **ソース列なしで保存されたユニオンのソースは、不足しているものを示します。** REST API、JSON-RPC、または AI アシスタントや MCP で、ソース列の一覧なしに保存された Table Union All または Table Union Distinct のソースは、ステップの実行時に、内部設定の名前を挙げた予期しないエラーで失敗していました。現在は、そのようなソースの保存は、ソースの名前を示して拒否され、以前に保存されたものを読み取るステップは、何も書き込む前に、そのソースの名前を示して停止します。テーブルのすべての列を取り込む、または位置で積み重ねる、変換済みの Table Union All には一覧は不要で、一覧がないことを理由に拒否されることはありません。
- **列の定数に、数値、`0`、`false` を使用できます。** 出力列の定数が数値のステップは、予期しないエラーで失敗していました。`0` または `false` の定数は、定数なしとして扱われていたため、その列は代わりに式またはソース列を使用するか、列に読み取るものがないためにステップが失敗していました。これらの定数は、すべての行に、列のデータ型に変換して書き込まれるようになり、AI アシスタントもそのようなステップを提案できます。
- **変換された Alteryx の Data Cleansing ツールが null 行を削除します。** **Remove Null Rows** をオンにした Data Cleansing または Data Cleanse Pro ツールは、変換レポートで確認対象としてフラグが付けられ、変換後のステップはすべての行を残していました。現在は、Alteryx と同様に、すべての列が null である行をステップが削除します。空のテキスト値を持つ行は残ります。Data Cleanse Pro は他のオプションの後に各行をチェックするため、null を空の値に置き換えた行も残ります。**Remove Null Columns** は引き続き確認対象としてフラグが付けられます。この修正を反映するには、ワークフローをもう一度インポートしてください。
- **列が指定されていないメールの通知とエクスポートは、すべての列を含めます。** 列を選択していない Notify Via Email のフレームや、ターゲット列がマッピングされていないエクスポートステップは、以前は実行が失敗していました。現在は、どちらもテーブルのすべての列を含めます。外部の宛先にエクスポートする前に、データマッパーを確認してください。[Export ステップ](/ja/reference/workflow-steps/export/#書き込まれる列)を参照してください。テンプレート本文では、件名の `{variable}` プレースホルダーが、スケジュールされた送信、プレビュー、**自分にテスト送信** で置き換えられます。
- **5 つのエクスポートステップと Run SAP PCM Hyper Loader は、ソースが存在しない、空、または列がない場合、失敗せずに警告します。** MongoDBのエクスポート、Export External Database Tables、Tableau Hyper Export、空間ファイルのエクスポート、Export to Excel Sheets、Run SAP PCM Hyper Loaderは、失敗するか、何も書き込まれなかったことを示さずに完了していました。現在は成功し、ソースまたはターゲットの名前を示す警告をログに記録します。MongoDBのエクスポートは、存在しないテーブルではコレクションに何も書き込まず、テーブルに行がなく**書き込み前にコレクション内のすべてのドキュメントを削除**がオンの場合はコレクションを空にして、その旨を示します。Export External Database Tablesステップは、ソースが存在しない、または列がないターゲットをスキップし、ターゲットテーブルには以前の行が残ります。Tableau Hyper Exportステップと空間ファイルのエクスポートは、存在しない、または列のないソースではファイルを書き込まず、ソースに行がない場合は警告します。Export to Excel Sheetsステップは、どのシートにも書き込むものがなく、元になるテンプレートやブックもない場合、ブックを書き込みません。Run SAP PCM Hyper Loaderステップは、そのようなソースをスキップして残りをロードし、ロードするものがない場合は何もロードされなかったことをログに記録します。[MongoDBのエクスポート](/ja/reference/workflow-steps/export/export-mongodb/)と[Export External Database Tablesステップ](/ja/reference/workflow-steps/export/export-external-tables/)を参照してください。
- **式の検証は、実行時に受け入れられる関数を受け入れます。** `int(...)` などの関数を呼び出す有効な式が、チェック時に拒否されていました。
- **行アクセスのあるプロジェクトで、テーブルからのディメンションの読み込みが動作します。** 行を制限しているプロジェクトでは読み込みが失敗し、Data Foundation の階層が再構築されませんでした。現在は、プロジェクトのアーキテクトとワークフローの実行が読み込めます。ソーステーブルで読み取れる内容が行アクセスによって制限されているユーザーには、プロジェクトのアーキテクトに依頼するか、ワークフローから読み込むよう案内されます。読み込みで作成されるメンバーはプロジェクトの全員に表示されるためです。[制限されたテーブルへのデータの読み込み](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
- **行アクセスのあるプロジェクトで、Data Foundation がロードを行い、ダッシュボードを作成します。** 行を制限しているプロジェクトでは、**ロード**と**変更を適用**がステージ別のパイプラインの構築中に停止することがあり、レポートビューをレポート用に公開できなかったため、ほとんどのダッシュボードが作成されませんでした。現在は、そこでのレポートビューはテーブルとなり、ダッシュボードで行アクセスによってフィルターされます。元となる Data Foundation のテーブルが持つ制限された列がないレポートは対象外となり、警告にそのレポートと列の名前が表示されます。[表示できるユーザー](/ja/guides/projects/data-foundation-dashboards/#表示できるユーザー)を参照してください。
- **元帳のないソースが、Data Foundation の会計カレンダーで ERP と競わなくなりました。** Salesforce などのソースが会計カレンダーをロードすると、**ソースの対象範囲**に ERP の月の 2 つ目のソースとして表示され、**One source for each key** が赤のままとなって夜間ロードをスケジュールできず、ロード順で先になる場合はそのカレンダーが使用されていました。現在は、総勘定元帳または試算表をロードするソースのカレンダーが、ロード順に関係なく計上されます。[どのソースをいつから採用するかを選択](/ja/guides/projects/data-foundation/#どのソースをいつから採用するかを選択)を参照してください。
- **Databend で、日数を数える Data Foundation のレポートビューが作成され、Sage Intacct の会計カレンダーと勘定残高がロードされます。** **ロード**中にいくつかのレポートビューが失敗し、それらを読み取るダッシュボードのグラフが欠けていたほか、Sage Intacct ソースの会計カレンダーと勘定残高の読み取りも失敗していました。
- **公開されていない制限付きテーブルで、行アクセスがエラーにならなくなりました。** テーブルが公開されるまで、**同期**のステータスがテーブル名を示して**エラー**のままでした。制限は保持され、テーブルを公開するとダッシュボードに適用されます。[ダッシュボードの同期の維持](/ja/administration/access/managing-security-groups-and-assignments/#ダッシュボードの同期の維持)を参照してください。
- **Data Foundation のダッシュボードは、「Period」フィルターに表示された月で開きます。** フィルターには選択した月が表示されていましたが、1 か月分を読み取るグラフは、フィルターを適用するまですべての月を合計していました。
- **Data Foundation のダッシュボードのタイルとコンテキスト行が全文表示されます。** 最後の行が切れることがありました。
- **空のファイルがあると、Data Foundation のロードは、そのファイルを示す警告とともに終了します。** ヘッダーの後に行のないファイルは、何も伝えずに新しいものを何もロードしていませんでした。データセットには、ファイルが最後に与えた行が残ります。
- **人員数と生産数量は、シナリオのない配賦ドライバーの行を、ドライバー名の大文字と小文字にかかわらず数えます。** シナリオのないドライバーの行は実績として数えられるようになり、`Headcount` という名前のドライバーは `headcount` として数えられます。
- **Salesforce、SAP、Oracle E-Business Suite、Oracle Fusion のソースが、データを Data Foundation にロードします。** **ロード**中にそれらを読み取ると、ロード自体は完了していたにもかかわらず失敗していました。
- **Salesforce から読み取ったアクセント付き文字などの英語以外の文字が、正しく取り込まれます。** Hernández のような名前が、**Salesforce: オブジェクトのクエリ**ステップと Data Foundation の Salesforce ソースで文字化けしていました。
- **メトリックカードの表で `pct` がパーセンテージとして表示されます。** 内訳のあるカードで、`pct` 列に *12.3456* のような表示のない長い数値が表示されていました。現在は *12.3%* のように小数点以下1桁のパーセンテージで表示されます。[メトリックの数値](/ja/guides/ai-assistant/weave-tab/#メトリックの数値)を参照してください。
- **四半期初来累計または年初来累計の定期リクエストは、範囲の最初の月または期間でも範囲を明示します。** 四半期の最初の月に四半期初来累計を対象とするレポートやアラートでは、*October 2026* のように月だけが表示されていました。現在は *October 2026, quarter to date* と表示され、年の最初の期間の年初来累計も同様に表示されます。そのような範囲ですでに送信されたアラートは、もう一度送信されることがあります。[回答と定期リクエストを保持する](/ja/guides/ai-assistant/weave-requests/)を参照してください。
- **REST API または MCP で拒否されたメトリックのリクエストは、理由だけを返します。** 四半期のない `qoq` のようなリクエストは、理由の周りに長い技術レポートが付いた状態で拒否されていました。現在は *qoq には四半期が必要です* のように理由のみが返されます。[MCP と REST API 経由](/ja/integrations/ai-coding-agents/metric-definitions/#mcp-と-rest-api-経由)を参照してください。
- **データモデルのグラフで、キーのマークが重ならなくなりました。** 複数のテーブルが同じ要素をキーにしている場合、各テーブルのキーを示す **1** が線が要素から出る位置に描かれていたため、マークが「11」のように重なっていました。各 **1** は、線のテーブル側の端、テーブルのカードのすぐ左に描かれるようになりました。[データモデルを読み取る](/ja/guides/projects/data-model/#データモデルを読み取る)を参照してください。
- **ウェアハウスをデフォルトにすると、切り替えがまだ進行中であることが表示され、ウェアハウスのダイアログで誤ったエラーが表示されなくなりました。** **ウェアハウスの管理**の**デフォルトに設定**は、ワークスペースがそのウェアハウスに切り替わるまで数分かかるにもかかわらず、ウェアハウスがすぐにデフォルトになったと表示していました。現在は、切り替え中であることが表示されます。ベータワークスペースでは、ウェアハウスのダイアログで **Snowflake** と **Databricks** を切り替えたときに、開発チームへの連絡を求めるエラーメッセージが表示されることもなくなりました。
- **共有リンクや古いリンクから開いたサーバー型または Dashアプリで、読み込み画面が表示されます。** 起動時のリンク以外のリンク（起動後にコピーしたアドレスバーのリンク、ダイジェストメール、Slack や Microsoft Teams のアラートまたはダイジェストカード、REST API の `location` フィールドにある古い `/serve/panel/` リンク、Studio のプレビューリンクなど）からサーバー型または Dashアプリを開くと、スリープ中のアプリが起動するまで空白のタブが表示されていました。現在は読み込み画面が表示され、リンクのページ、クエリ、`#` セクションがアプリに引き継がれます。サインアウトしている場合、ブラウザーのタブで開いたリンクは、まずサインインを経てから読み込み画面またはアプリに移動します。サインインが必要な場合、`#` セクションは失われることがあります。別のページに埋め込まれたアプリでは、サインアウトしているとエラーが引き続き表示されます。
- **項目のバージョン履歴には、その項目自身のバージョンだけが表示されます。** ステップ、ユーザー定義関数、ディメンション、ドキュメントアカウント、保存済みレイアウトのバージョンに、ID が同じ文字で始まる同じ種類の別の項目（ステップ `load` とステップ `load_2` など）のバージョンが含まれることがありました。現在は、それぞれ自身のバージョンだけが表示されます。
- **エージェントのリモートエクスポート: SQLが選択したテーブルをロードします。** ステップフォームで**分析テーブルにエクスポート**を指定して作成、コピー、または切り替えたステップは、結果を代わりに**ターゲットディレクトリ**内のファイルに書き込んでいたため、**ターゲットテーブル**はロードされませんでした。選択が保存されるようになりました。このようなステップは、現在は**ファイルにエクスポート**で開きます。これは、実際にそれを実行してきたためです。**分析テーブルにエクスポート**を選択し、ステップをもう一度保存してください。
- **失敗した Table Project to Project Copyステップでも、ターゲットテーブルのデータは保持されます。** **既存のデータに追加**のチェックを外していると、ステップはコピー前にターゲットテーブルを空にしていたため、その後でコピーが失敗するとターゲットテーブルは空のままでした。コピーが失敗した場合、ターゲットテーブルの行と列は元の状態のまま残るようになりました。[Table Project to Project Copyステップ](/ja/reference/workflow-steps/tables/frame-project-copy/)を参照してください。
- **Lakehouse v2 では、テーブルの復元で、任意の AWS リージョンの Amazon S3 バケットからアーカイブを読み取れます。** `us-east-1` 以外のリージョンのバケットからの復元は失敗していました。[テーブルの復元](/ja/reference/workflow-steps/import/restore-tables/)を参照してください。
- **Databend では、時間切れになったプレビューまたはホワットイフが、ウェアハウスを占有し続けなくなりました。** ステップの**プレビュー**が 30 秒を超えた場合、または Weave がシナリオを後続のステップに反映している途中で時間切れになった場合、PlaidCloud は待機を終了していましたが、クエリはウェアハウス内で完了するまで実行され続け、再試行すると別のクエリが開始されていました。現在はウェアハウスもクエリを停止し、停止されたプレビューには 30 秒を超えたことが表示されます。[シナリオを後続のステップに反映する](/ja/guides/allocations/results/driver-what-if/#シナリオを後続のステップに反映する)を参照してください。
- **メンバーを削除しても、アカウントと履歴は保持されます。** これまでは、メンバーを削除するとアカウントも削除されていました。現在は **ワークスペースから削除…** で、メンバーはサインインできなくなり、アクセスが取り消されますが、アカウントとその履歴は保持され、メンバーは **非アクティブ** として一覧に残ります。ワークスペース管理者が使える **完全に消去…** では、アカウントとメンバーの利用状況データも削除されます。[メンバーの編集と削除](/ja/administration/access/member-management/#メンバーの編集と削除)を参照してください。
- **Excel へのエクスポートは、既存のブックの他のシートを保持します。** 既存のブックを置き換えるエクスポートでは、ステップが書き込まないシートがすべて失われていました。現在は、ステップが自身のシートだけを書き込み、残りは保持されます。ただし、読み取れるブックではないファイルは除きます。[ファイルが存在する場合](/ja/reference/workflow-steps/export/export-to-excel/#ファイルが存在する場合)を参照してください。
- **列に集計が設定されたステップは、設定に特に指定がない場合は集計します。** REST API または MCP で作成された、結合やルックアップなどのステップで、列に集計が設定されているのに **集計** 設定がない場合、グループ化されていない行が返されていました。現在は集計されます。**集計** をオフにしたステップは、これまでどおり集計されません。
- **ステップの記録が最初に失敗しても、ステップは実行履歴に残ります。** ステップの実行を実行履歴に書き込むのが、たとえばウェアハウスへの接続がリセットされるなどして失敗すると、そのステップが実行履歴や、その実行についての Weave のアラートから欠落していました。PlaidCloud は書き込みを再試行するようになりました。
- **ERP からサーバーエラーが返された転記は、却下ではなく要確認になります。** Acumatica、Business Central、NetSuite、Oracle Fusion、QuickBooks Online、Sage Intacct、Xero が転記に対してサーバーエラーを返した場合、ドキュメントが存在している可能性があるにもかかわらず却下として記録されていたため、再試行すると二重に転記されるおそれがありました。現在は **未確認** になり（台帳IDで開くと **要確認**）、誰かが確認するまで再送信されず、**解決…** で確定できます。[台帳エントリの解決](/ja/guides/connections/posting-register/#台帳エントリの解決)を参照してください。
- **一致するものがないフィルターが、空のリストのように見えなくなりました。** プロジェクト、ワークフロー、ステップ、テーブル、ディメンション、データエディター、ユーザー定義関数で、一致する項目がなくなったフィルター（一致する唯一の項目を削除した後やリストを更新した後など）は「プロジェクトはまだありません」などと表示してフィルターボックスを隠すため、ページを再読み込みするしかありませんでした。現在は、フィルターに一致する結果がないことが表示され、**フィルターをクリア**ボタンが表示されます。
- **Databricks の Lakehouse で、CSV のインポートが読み込まれ、リテラル値を含むステップが実行され、ダッシュボード用にテーブルを公開できます。** Databricks の Lakehouse では、CSV ファイルのインポートがスキーマ不一致のエラーで失敗し、`Unit Price` のような名前の列は、Lakehouse のテーブルでも、Databricks 接続上でエクスポートが作成するテーブルでも作成できませんでした。インポートまたはキャストされた数値は小数部が失われ、10.5 は 11 として読み込まれ、10 桁を超える値は空として読み込まれていました。フィルターや式にリテラル値を含むステップ(たとえば `id > 2` で絞り込んだ Table Extract ステップ)が、未バインドのパラメーターのエラーで失敗していました。また、保存された値、フィルター、列名とエイリアス、ビューの定義にある `%` は、2 文字に重なって Databricks に届いており、テーブルをダッシュボード用に公開できませんでした。これらはすべて正常に動作するようになりました。PlaidCloud が Databricks 上に作成するテーブルは Delta の列マッピングを使用するようになったため、それらを直接読み取るツールはこれに対応している必要があります。
- **接続が切断されても、操作が再送信されなくなりました。** PlaidCloudが応答を待っている間に接続が切断されると、サーバーがすでに処理を実行している可能性があるにもかかわらず、一部のリクエストが最大3回まで再送信されていました。そのため、ワークフローの実行、コピー、メールなどの同じ操作が2回行われることがありました。現在は1回だけ送信されます。接続が切断された場合は代わりにエラーが表示されることがあります。再試行する前に、操作が完了したかどうかを確認してください。
- **JSON のインポートで、月が先の日付と日が先の日付を読み取れるようになりました。** ISO 8601 形式ではない日付やタイムスタンプ（`01-23-2026 11:14:00 PM`、`23-01-2026` など）を含む JSON のインポートは失敗し、`02-01-26` のように 2 桁の年を持つ日付は誤った年でインポートされていました。現在はこれらが日付とタイムスタンプとしてインポートされ、フィールド内のすべての値が同じ方法で読み取られます。値が複数の方法で読み取れる場合は、ステップの**日付形式**で判断されるか、選択すべき日付形式を示すエラーでインポートが停止します。[JSONのインポート](/ja/reference/workflow-steps/import/import-json/#日付とタイムスタンプ)を参照してください。
- **アプリが開くときに、ビジーなウェアハウスを待たなくなりました。** アプリを開くたびに、PlaidCloudはこれまでにワークフローを実行したことがあるかをウェアハウスに問い合わせており、ウェアハウスがビジーだと、読み込み画面で1分以上待たされることがありました。現在は数秒で待機を打ち切り、一度でも実行した後は問い合わせを行いません。
- **Lakehouse v1では、ステップがテーブルの以前のバージョンの検索に数分かけなくなりました。** Weaveの値のばらつきのチェックでは、テーブルを書き込むステップが、実行前のテーブルのバージョンを探します。この検索ではテーブルが保持していたすべてのバージョンを読み取っていたため、何度も書き込まれたテーブルでは、ステップの実行のたびにウェアハウスで数分の処理がかかっていました。現在は新しい20件だけを読み取り、実行前のバージョンがそれより古いテーブルは、未チェックとして報告されます。[Weaveがチェックする内容](/ja/guides/ai-assistant/weave-findings/#現在weaveがチェックする内容)を参照してください。
- **ダッシュボードグループのメンバーがノートブックを使えるようになりました。** ワークスペース管理者ではない**Dashboard Read Only**と**Dashboard Read and Write**のメンバーは、JupyterLiteデプロイメントの一覧を開けませんでした。ワークスペースのアップグレードに伴い、両方のグループが一覧を開けるようになり、**Dashboard Read and Write**のメンバーはデプロイメントを追加できます。デプロイメントを変更または削除できるのは、それを追加した本人かワークスペース管理者だけです。
- **名前にスペースを含むノートブックとブラウザのみのアプリが再び開くようになりました。** 独自のスラッグを持たない JupyterLite デプロイメントや**ブラウザのみ**のPanelアプリは名前で開かれますが、その名前にスペースが含まれていると、**ノートブック**または**アプリ**から開いても何も見つかりませんでした。リンクにスペースが正しく含まれるようになりました。
- **ワークフローを停止すると、実行中のインポートとエクスポートも停止します。** **停止**を押した時点ですでに実行中だったインポートまたはエクスポートのジョブは、そのまま実行を続け、実行が停止した後でもテーブルをロードしたりファイルをアップロードしたりすることがありました。現在は数秒以内に停止して新たな書き込みを開始せず、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplum では、エクスポートが読み取っていたクエリも停止します。すでに進行中の書き込みは先に完了するため、ファイルやテーブルが書きかけのまま残ることはありません。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)を参照してください。
- **別のプロジェクトへのステップのコピーが途中で止まらなくなりました。** コピーしたステップが、コピー先のプロジェクトにないテーブルを使用していて、そのテーブルが[レポート用に公開](/ja/guides/projects/managing-tables-and-views/#レポート用にテーブルを公開する)されていた場合、コピーまたは貼り付けがエラーで途中で止まっていました。現在は最後まで完了し、コピー先のプロジェクトに追加されたテーブルは、公開するまでそのプロジェクトでは公開されません。

## セキュリティ

- **プロジェクトとウェアハウスのメンバー一覧では、メールアドレス、電話番号、ユーザー名は、ワークスペースのメンバーを閲覧できる人にのみ表示されます。** それ以外の人には名前のみが表示されます。
- **Weave は、各会話の開始時に、お客様の名前とメールアドレスを AI プロバイダーに送信しなくなりました。** これらが使われることはありませんでした。
- **Weave が AI プロバイダーに送信する行は、1 つのクエリにつき最大 500 行になりました。** これは Weave が作成するクエリと実行するメトリクスが対象で、以前は返されたすべての行が送信されることがありました。メトリクスが 500 行を超える行を返した場合は、会話内のそのカードにその旨が表示されます。[Weave によるお客様のデータの利用について](/ja/guides/ai-assistant/weave-data-use/)を参照してください。
- **パスワードによるサインインには認証アプリが必要になり、パスワードが強化されました。** PlaidCloud のパスワードでサインインするメンバーは、次回のサインイン時に認証アプリの設定を求められ、その後は毎回コードを入力します。シングルサインオン、Google、Microsoft、GitHub によるサインイン、API トークン、サービスアカウントは変わりません。新しいパスワードは 12 文字以上で、ユーザー名や直近 6 回のパスワードのいずれかと同じにはできず、サインインの失敗が繰り返されると、アカウントは短時間ロックされます。ワークスペースにすでにあったより厳しいルールは維持されます。[メンバー認証](/ja/administration/access/member-authentication/)を参照してください。
- **接続は、パブリックアドレスとプライベートネットワークのアドレスを指します。** 接続は、ループバック、リンクローカル、クラウドメタデータのアドレスを指すことはできず、エラーにはホストと解決先のアドレスが表示されます。プライベートネットワーク上のアドレスは影響を受けません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続できないアドレス)を参照してください。
- **保存された接続の認証情報は、ユーザーには表示されません。** REST API と MCP では、保存された接続のパスワード、トークン、キーは、権限にかかわらず全員に対してマスクされますが、メンバーは引き続き接続を開いて参照できます。これらを受け取るのは、PlaidLink エージェントやプロジェクト自身のサービスアカウントなどのサービスアカウントのみで、ユーザーのサインインでは受け取りません。認証情報の送信先（ホストなど）を変更するには、認証情報をもう一度入力する必要があります。プロジェクト自身のデータベースパスワードは、そのアーキテクトにのみ表示されます。[接続の認証情報を確認できるユーザー](/ja/guides/connections/create-connection/#接続の認証情報を確認できるユーザー)を参照してください。
- **接続の認証情報は、別のオリジンへのリダイレクトには付随しません。** 標準の `Authorization` ヘッダーは、スキーム、ホスト、ポートのいずれかが異なる場所へリダイレクトされるリクエストには付けられず、APIキーのヘッダーなど、それ以外の方法で認証情報を送るリクエストは、リダイレクトに従わずに停止します。HFM/FCCS 接続は、リダイレクトにまったく従いません。[汎用REST接続](/ja/reference/connectors/rest/generic-rest/)を参照してください。
- **制限のない Google、Microsoft、GitHub のサインインでは、ワークスペースにアカウントが作成されなくなりました。** 自分の Google Workspace ドメインに限定されていない Google サインイン、自分の組織のディレクトリに限定されていない Microsoft サインイン、GitHub サインインでは、ワークスペースにすでにアカウントを持っているユーザー（招待したメンバーなど）だけがサインインできます。[既存のアカウントとメールアドレスの確認](/ja/administration/control-plane/workspace-configuration/#既存のアカウントとメールアドレスの確認)を参照してください。
- **制限付きダッシュボードは、そのデータにアクセスできるメンバーにのみ届きます。** セキュリティグループに限定されたダッシュボードは、そのグループのメンバーに対して、データセットの少なくとも 1 つがそのメンバーのアクセスできるプロジェクトにある場合、またはデータセットがない場合にのみ、一覧表示され、開けます。ダッシュボードのデータセットとチャートからは、アクセスできないプロジェクトのものが除外されます。[表示されるダッシュボード](/ja/guides/dashboards/using-dashboards/#表示されるダッシュボード)を参照してください。
- **アプリのビルドは、ワークスペースの Git 認証情報にアクセスせずに実行されます。**
- **Weave の変更を承認するには、その変更に必要な権限が必要です。** カードやプランを承認すると、ステップの変更、ワークフローの実行、Panel アプリの変更など、その変更に必要な権限をお持ちの場合にのみ変更が適用されます。権限がない場合、Weave は適用できないことを伝えます。[変更を承認する](/ja/guides/ai-assistant/weave-dock/#変更を承認する)を参照してください。
- **転記には、ロックされていないプロジェクトでのアーキテクトまたはマネージャーのロールが必要です。** REST や MCP でのドキュメントの転記、ファイル転記の開始、所属するプロジェクトから SAP、Oracle E-Business Suite、Sage 100 向けの PlaidLink エージェントへの転記の送信は、エクスプローラーの場合およびロックされたプロジェクトでは拒否されます。[誰が何をできるか](/ja/guides/connections/post-documents/#誰が何をできるか)を参照してください。
- **セキュリティグループは MFA の免除を付与できません。** 免除はメンバーに設定します。[パスワードでのサインインには認証アプリが必要](/ja/administration/access/member-authentication/#パスワードでのサインインには認証アプリが必要)を参照してください。
- **転記済みとして記録しても、表示できないプロジェクトのドキュメントは確定されなくなりました。** そのドキュメントは「*This document belongs to a project you cannot see.*」と一覧表示されます。
- **Data Foundation プロジェクトの複製では、アーカイブは、全メンバーが参照できる一時アカウントではなく、ワークスペース管理者のみがアクセスできる場所にステージングされます。**
- **登録済みシステムの一覧にクライアントシークレットが表示されなくなりました。** OAuth クライアントのシークレットは、その行の歯車アイコンから開く、クライアントの構成ダイアログで、クライアントの所有者が確認できます。
- **エージェントの秘密鍵は、エージェントを編集できるメンバーにのみ表示されます。** 鍵は、REST API と MCP のエージェント一覧や詳細に表示されなくなり、エージェントフォームは、**秘密鍵**と **RPC構成を表示**を、エージェントを編集できるメンバーにのみ表示します。サービスアカウント、プロジェクトトークンとエージェントトークン、AI に委任されたトークンは、鍵や RPC 構成を取得できません。エージェントの構成内の認証情報（パスワードなど）は、REST API と MCP のエージェント一覧や詳細ではマスクされます。実行中のエージェントには影響せず、公開鍵は引き続き表示されます。[エージェントの認証情報を取得する](/ja/reference/cli/plaidlink/agents/#エージェントの認証情報の取得)を参照してください。
- **プロキシのダウンロードリンクは 1 時間有効です。** **Use PlaidCloud Proxy Download** がオンの場合、リンクの有効期限が切れたら、ダウンロードをもう一度開いて新しいリンクを取得してください。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)を参照してください。
- **セキュリティグループへのユーザーの追加は、保有する権限に従います。** セキュリティグループにメンバーを追加する、メンバーのグループを選択する、アーキテクトを招待するには、そのグループが付与するすべての権限を保有している必要があります。ワークスペース管理者には制限はありません。[セキュリティグループの管理](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)を参照してください。
- **接続の所有者またはワークスペース管理者が、その設定を変更し、オンとオフを切り替えます。** REST API、JSON-RPC、AI アシスタントまたは MCP で接続の設定を変更するには、その所有者のいずれか、所有者のない接続ではワークスペース管理者である必要があります。接続の有効化、無効化、ロック、ロック解除には、所有者またはワークスペース管理者が必要で、複数の接続を指定したリクエストは、そのすべてを変更できる場合にのみ適用されます。ワークスペースのデフォルトの AI 接続を選択できるのはワークスペース管理者だけで、メンバーが所有する接続がデフォルトになるのは、管理者が所有する、または所有者のいない接続がどれもデフォルトになりえない場合に限られます。[接続を編集する](/ja/guides/connections/create-connection/#接続の編集)と [LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **保存済みレイアウトのバージョン履歴の対象は、使用できるレイアウトのみです。** REST API、JSON-RPC、MCP では、テーブルの保存済みレイアウトのバージョンを一覧表示、復元、保持、解放、バックアップできるのは、自分が所有するレイアウト、自分と共有されているレイアウト、グローバルレイアウトに限られます。それ以外のレイアウトは不明として報告されます。バージョンを復元すると、レイアウトの列とフィルターが元に戻り、所有者と共有先は保持されます。テーブル上のすべての保存済みレイアウトを復元するには、ワークスペース管理者が必要です。所有者が保存済みレイアウトを削除すると、保持されたバージョンを含め、そのバージョン履歴も一緒に削除されます。レイアウトのバージョンはその場で復元されます。ターゲットを省略するか、同じレイアウトを指定してください。[バージョン履歴](/ja/guides/projects/managing-projects/#バージョン履歴)を参照してください。
- **行アクセスは、メンバーが制限付きテーブルに対して行うすべての操作に適用されます。** メンバーは、ダッシュボード、自身の SQL、ロードで、付与された範囲の行だけを表示、変更できます。
  - **プロジェクトのアーキテクトは、ダッシュボードで行が制限されたテーブルのすべての行を表示できます。** これは、Analyze で表示される内容と一致します。アーキテクトのアクセス権を取り消すと、ダッシュボードにも即座に反映されます。これは、誰かのロールを変更した場合、その人またはそのグループをプロジェクトから削除した場合、プロジェクトのアクセスタイプを変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれにも当てはまります。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
  - **行アクセスで制限されたメンバーは、自身の SQL クエリを実行し、結果をエクスポートできます。** 行アクセスのあるプロジェクトで、アーキテクトではないメンバーは、クエリ画面での自分のクエリから、付与された範囲の行だけを正確に取得でき、**アクセス権により行が制限されています**という通知とともに、CSV、Excel、JSON にエクスポートできます。以前は、これらは拒否されていました。パーセント記号（`%`）を含む付与値は、クエリ画面で行を返すようになり、そのようなクエリを CSV としてダウンロードすることも可能です。Snowflake または Databricks 上での自由形式の SQL、Postgres 系ウェアハウスでの自身の SQL のエクスポート、ガバナンス対象のテーブルをスナップショット時点で読み取る操作は、引き続き拒否されます。また、ビューがフィルターされるには、ガバナンス対象の列を元の名前のままにしておく必要があります。[行アクセスと自分で作成するクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスと自分で作成するクエリ)を参照してください。
  - **行アクセスを保存しても、ソースにない付与値は保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がない、ディメンションにそのメンバーがない、またはリストにその値がない場合でも、マークが付いた状態でグリッドに残ります。**保存**を押すと、そのような値ごとに、保持するか削除するかを確認されます。[行アクセスのグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
  - **行が制限されたテーブルへの DataFrame の書き込み、レコードの保存、クリアは、表示できる行のみを変更します。** 行アクセスで行が制限されている場合、Python クライアントで制限付きテーブルに DataFrame を書き込んだりクリアしたり、REST API でレコードを保存したりクリアしたりしても、変更されるのは自分の行だけです。アクセス範囲外の行を含むロードは、何かが変更される前に、見つかった値を示して拒否されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は、テーブル全体を書き込みます。人が任意のテーブルに対して行うこれらの書き込みは、すべて**セキュリティログ**に記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
  - **行が制限されたテーブルに対するインポート、コピー、復元、削除には、すべての行を表示できる必要があります。** 行アクセスで行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからテーブルへのコピー、ブランチの切り替えやマージ、復元、削除、削除後の復旧、その他テーブル全体を置き換える操作は、テーブルのすべての行を表示できる場合にのみ実行されます。それ以外の場合は拒否され、何も変更されません。REST API でテーブルの行を保存すると、他のロードと同様に、自分の行だけが変更されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は影響を受けず、これらの操作も**セキュリティログ**に記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
  - **ERP 転記ステップは、行アクセスのあるプロジェクトで実行できます。** Workday などの ERP に転記するステップは、行が制限されたプロジェクトで実行でき、スナップショット、ブランチ、最適化候補の一覧もそこで動作します。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントの所有者だけです。** ドキュメントアカウントを以前のバージョンに復元する、バージョンを保持または解放する、バックアップを取る、といった操作には、そのアカウントの所有者のいずれかが必要で、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、そのアカウントへのアクセス権が必要です。
- **`query_run` は読み取り専用の文を実行します。** AI アシスタントと MCP クライアントが使用する `query_run` ツールは、SELECT または WITH の文 1 つ、その EXPLAIN、または SHOW を受け付け、それ以外の文は実行されません。データを変更するには、`query_transform` を使用してください。MCP のテーブルエクスポートに含まれる SQL にも、同じルールが適用されます。REST API と JSON-RPC API では、プロジェクトデータを変更できないメンバーに対して、クエリの実行、列ファセットの作成、クエリの CSV としてのダウンロード、クエリのリモートデータベースへのエクスポート、独自のクエリによるテーブルデータのエクスポートにも適用され、拒否されたクエリは 403 を返します。Explain Analyze は、測定のためにクエリを実行するため、クエリログと Lakehouse では、読み取るクエリのみを受け付け、行アクセスのあるプロジェクトでは、クエリログからこれを実行できるのはプロジェクトのアーキテクトだけです。
- **テーブルエクスプローラーのフィルター、PlaidCloud に送信されるクエリ、Table Extract ステップの動的列を検出するクエリは、SQL を実行する関数やサーバーのファイルを読み取る関数を呼び出せません。** `query_to_xml`、`dblink`、`pg_read_file` などの呼び出しは拒否され、エラーには関数名が示されます。同じ場所で、`.op()` は演算子のみを受け付け、`literal_column` では Unicode エスケープされた引用符は使用できません。動的列のクエリは、ステップのフィルターと、ソースから列名を読み取る式を含むため、ルールに違反するものは、実行時にステップを失敗させます。[拒否される関数と演算子](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#拒否される関数と演算子)を参照してください。
- **Data Foundation の配賦ルールは、単一引用符、バックスラッシュ、改行を含む部門名または統計名を拒否します。** 名前は配賦ステップのフィルターに書き込まれるため、**保存**とステージ 1 のプレビューは、それを拒否し、その値を示します。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。
- **アクティビティパネルのエントリーは、API から偽造できません。** `POST /rest/v1/analyze/workflow/update-stream` とその JSON-RPC 相当は、開けるプロジェクト内のスケジュール実行の開始またはスキップのみを受け付け、渡せるのはプロジェクト、ワークフロー、実行の ID だけです。それ以外のエントリーと、各エントリーに表示される名前は、すべて PlaidCloud 自身が生成します。
- **読み取り専用のクエリと行アクセスは、ウェアハウスが複数の方法で読み取れるクエリを拒否します。** 読み取り専用で実行されるクエリや、行アクセスが適用されたクエリは、ウェアハウスがそのコメントと引用符で囲まれたテキストを読み取る可能性のある各方法でチェックされるようになり、いずれかの方法で読み取り方が異なる場合は、理由を示すメッセージとともに拒否されます。これまでは、チェックがコメントや文字列と判断したテキストの中に、クエリが 2 つ目の文や、フィルターなしでのテーブルの読み取りを隠すことができました。今後は、引用符で囲まれたテキスト内のバックスラッシュや、コメント内の `/*` によって拒否される場合があります。テキスト内の単一引用符は、単一引用符 2 つ（`''`）として記述してください。
- **式は、行アクセスのフィルターを回避して制限付きテーブルを読み取ることはできません。** テーブルエクスプローラー、Weave の **Why this number**、結合またはルックアップのステップの**キーを確認**、JSON-RPC の `read_frame` 呼び出しで読み取るテーブルにおける式とフィルターは、それらが作成するサブクエリも含め、付与された範囲の行だけを読み取ります。それ以外の方法でテーブルのデータにアクセスする式やフィルターは拒否されます。
- **サインイン後に戻る先は、PlaidCloud 自身のページだけです。** サインイン後に別のサイトへ移動させるように作られたサインインリンクでも、代わりに PlaidCloud に移動するようになりました。
