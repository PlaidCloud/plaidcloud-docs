## 追加

- **コントロールプレーンの Trust Center で、セキュリティチームが PlaidCloud のセキュリティ文書を入手できます。** 管理者とセキュリティユーザーは、組織の **Trust Center** を開き、サブプロセッサー一覧や DPA などの公開文書をすぐにダウンロードできます。また、組織として 1 回、セキュリティ文書の NDA に署名すると、SOC 2 Type II レポートなどの制限付き文書のロックが解除されます。他の管理者とセキュリティユーザーは、誰がいつ署名したかを確認できます。契約にすでに NDA が含まれている組織では、NDA を提出済みとして記録しておけば、署名なしで文書のロックが解除されます。制限付き文書のダウンロードには透かしが入り、記録されます。新しいバージョンの NDA は、あらためて承諾が必要です。管理者とセキュリティユーザーは、組織ごとに、新規または更新された文書と新しい NDA バージョンをまとめた日次メールを受け取るよう設定することもできます。このメールに文書そのものが含まれることはありません。[Trust Center](/ja/administration/control-plane/trust-center/)を参照してください。
- **PlaidXL は、Excel でのレポート作成、ドリル、数値の説明、計画に対応します。** **PlaidCloud** リボンタブは **接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有**にグループ分けされています。よく使うコマンドは **PlaidXL** の右クリックメニューと **PlaidXL Cell** タブにもあり、主要なコマンドには変更できるキーボードショートカットがあります。フィールドに入力している間は、ショートカットは動作しません。コマンドが失敗すると、どのコマンドがなぜ失敗したかが表示されます。サインイン前に実行したコマンドはサインインを開き、サインイン後に 1 回実行されます。サインインは 1 つのワークスペースに対して有効なので、ワークスペースを切り替えると新しいワークスペースへのサインインが求められます（元に戻す場合は求められません）。Office で Microsoft Entra の職場アカウントを使っている場合、PlaidXL がワークスペースを自動的に見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます。** **Report** タブは、テーブルからライブレポートをレイアウトします。1 つのディメンションを行方向に、もう 1 つを列方向にドリルダウンし、各交点に `CELL` の値が入ります。**Build my first report** は、お客様自身のデータからサンプルを作成します。ドリルに合わせて、レポートは行全体と列全体を挿入、削除し、入力した値、メモ、書式は行に付いたまま移動します。[レポートを作成する](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only** は、ノード、ディメンション見出し、レポートの値から、ノードをライブの `DRILL` 数式に変換し、その編集も行います。**Custom drill** は、挿入前に行をプレビューします。メンバーピッカーは、メンバーを挿入するか、ノードの子のドロップダウンをセルに追加します。`DRILL` では、除外または展開するノードを指定でき、行をまたいで実行することもできます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明できます。** **Explain this number** は、値の計算内容、現在の PlaidCloud と一致しているか、値の元になっているテーブルとワークフローステップを表示します。**Show detail rows** は、値の元になっている行を専用のシートに表示し、合計が一致するかの確認も行います。
  - **Excel でガバナンスされたメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるのと同じビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計の場合は `0` を表示し、それ以外は理由とともに `#VALUE!` を表示します（`CELLS` のスピルでは空白）。**Metric...** は、プロジェクトのメトリックを現在の値とともに一覧表示します。メトリックは、複数の代替階層でフィルターしたり、代替階層のメンバーと他のディメンションのメンバーを組み合わせたりできます。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに直接入力して計画できます。** `CELL` の値の上に数値を入力すると、PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの形に合わせた配分、金額またはパーセンテージによる調整が可能で、保持されたセルには影響しません。平均、中央値、最小値、最大値、標準偏差、分散のセルにも入力でき、入力した値は、行や列の挿入、削除に合わせてセルとともに移動します（削除されたセルの値は報告されます）。**Undo last write** は、入力した値と保存を新しい順に取り消します。書き込みを取り消せるのは、その書き込みを行ったユーザーとワークスペースだけです。合計の取り消しや、空のセルに入力した平均の取り消しでは、それ以降に同じセルへ書き込まれた内容が保持されます。完了前に中断された書き込みは取り消せません。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要なものだけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新できます。各テーブルの進行状況と**キャンセル**はタスクペインに表示されます。PlaidXL の数式だけを再計算することもできます。大きなテーブルは、Excel on the web と最新のデスクトップ版 Excel で大幅に高速に取得できます（143,000 行、77 列のテーブルで、10 分以上かかっていたものが約 1 分になります。古い Excel バージョンでは従来どおり動作します）。Excel のセルに入る長さを超えるテキストは、検出され、切り詰められた状態で保存されないよう保護されます。取得したテーブルは、データ型ごとに書式設定された Excel テーブルとして届き、更新しても独自の列と数値書式が保持され、同じ場所で更新されます。取得や更新で他のセルが上書きされたり、別の Excel テーブルと重なったりすることはなく、Excel で扱えないほど大きな整数 ID や 1900 年より前の日付はテキストとして届きます。同じテーブルをもう一度取得しても更新リストに二重に追加されず、**Stop refreshing** で 1 つずつ外せます。ディメンションはテーブルとともに更新されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud** は、確認なしで書き込み、何を行ったかを表示し、**元に戻す**を提供します。この操作は、Lakehouse テーブルでは各保存から最大 7 日間有効です。フィルター付きで取得したシート、詳細行のシート、一部の行にしかアクセス権がないユーザーの場合は、それらの行だけが置き換えられるため、他のユーザーの行は保持されます。取得後にメンバーが変更されたドリルスルーシートは保存されません。保存に失敗した場合は、テーブルを元に戻せるよう、復元ポイントの名前が表示されます。[テーブルを PlaidCloud に保存する](/ja/reference/cli/plaidxl/retrieve/#テーブルをplaidcloudに保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave** タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼するか、**Ask Weave about this cell** を選択します。Weave はあなたの権限で PlaidCloud を読み取り、ブックだけを変更します。入力済みの内容を置き換える前に確認し、ブックの外に到達する数式は書きません。各変更は、ペインを再読み込みするまで元に戻せます。[Excel で Weave に質問する](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1 つのシートまたはブック全体の値のみのコピーを共有できます。** **Convert to values** は、ブック全体、1 つのシート、または元に戻せない値のみへの変換を行います（最後の場合は先に確認があります）。変更されるのは PlaidXL の数式とそのスピルだけで、まだ計算中の数式は 2 回目の試行のために残され、シート名を変更した後でも **Restore PlaidXL formulas** は動作します。
  - **タスクペインの外観が新しくなりました。** PlaidCloud の Web アプリに合わせた、ブランドブルー、レール形式のタブとリスト、スクロールできる枠付きカードに入ったテーブル、ディメンション、プロジェクト、列になっています。キーボードフォーカスは明確な枠で表示され、ペインは Office のライトテーマまたはダークテーマに従います。タブは、幅の狭いペインでは横 3 つ、縦 2 段に並び、幅 560 ピクセル以上では 1 行に並びます。[ライトテーマとダークテーマ](/ja/reference/cli/plaidxl/connect/#ライトテーマとダークテーマ)を参照してください。
  - **ペイン内の数値は Excel の表示言語に従います。** 行数と列数、および更新、再計算、Explain、Formulas、Report、計画のメッセージでは、お使いの Excel と同じ形式で数値が表示されます。たとえばドイツ語版 Excel では 4.812.233 と表示されます。セルに書き込まれる値は変わりません。
  - **更新中はシートのタブが黄色になります。** ペイン、リボン、Weave のいずれから実行した場合でも、**Refresh All Tables** の間は、更新中のシートのタブが黄色になり、更新が完了、失敗、またはキャンセルされると、元の色（ご自身で設定した色を含む）に戻ります。途中でブックを保存して閉じた場合は、次にそのブックで PlaidXL が起動したときにタブが元に戻されます。[すべてのテーブルを更新する](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
- **転記レジスターは、対応が必要な項目から開きます。** 確認が必要なものがある場合は**例外**、承認待ちの依頼がある場合は**承認**、それ以外の場合は**すべての転記**から開きます。レールでは、画面が**自分の対応待ち**、**レジスター**、**インサイト**、**設定**にグループ化され、**例外**と**承認**には件数が表示されます。すべての画面が 1 つのヘッダーとスコープバーを共有します。期間（**This month**、**前月**、**過去7日間**、**過去30日間**、**カスタム**）、接続、プロジェクト、環境、エンティティ、そして**本番**、**シミュレーション**、**すべて**を選択し、**リセット**するか、**Saved scope** として保持できます。直前のスコープは記憶されます。
  - **例外は、確認が必要なものを整理します。** **Needs a look**、**未確認**、**保留中**、**失敗**、**Reversal outstanding** のチップに件数が表示され、接続の状態を示す行には「All N connections posting normally」と表示されます。すべての転記には、次に何をすべきかを説明するツールチップ付きの、分かりやすい状態が表示されます。未処理のものがない場合は **All clear** が表示されます。**Find a posting by ledger id** またはコマンドパレットに元帳 ID を貼り付けると、その転記が直接開きます。
  - **承認、委任、ウォッチは受信トレイ形式の画面です。** **Waiting on me** と **Submitted by me** を切り替え、理由を付けて**承認**または**却下**し、複数の承認を一括で行い、トーストから承認を**元に戻す**ことができます。**Delegate approvals** は短いダイアログで、**ウォッチ一覧**はフォロー中の項目を一覧表示します。**転記を取消**と、一括再試行およびクリアのダイアログは、同じレイアウトを共有します。
  - **転記のドロワーに、何が起きたかが表示されます。** 状態とその意味、名前付きの主要な事実、**Lines**、**履歴**、**承認**のタブが表示され、**レビュー済みにする**、**再試行**、**取消…**、**接続をウォッチ**、**実行をウォッチ**、**Copy link** が使えます。**Copy link** は、その転記を直接開きます。
  - **アシスト、エクスポート、保持期間も同じデザインに従います。** **アシスト**には、質問ボックスとインサイトカード、**Draft — nothing applied** と表示されるアドバイス、**すべての転記**上の異常カードと **これらを表示** があります。**エクスポートとアラート**には **New schedule** があり、**保持期間**は 1 枚のカードです。
  - **レジスターは常に最新の状態に保たれます。** レールのバッジは転記の変化に合わせて更新され、開いている一覧は転記が変更されると**更新**を提示し、開いているドロワーはその場で更新されます。**ホーム**には、**要対応**の下に**転記レジスター**カードが表示されます。[転記レジスターを確認する](/ja/guides/connections/posting-register/)を参照してください。
- **プロジェクトホームは 6 つのページで構成されます。** テキストのみのレールに、**概要**、**変数**、**Schedules & sensors**、**Access & sharing**、**Data & connections**、**Apps & branding** が並び、変数の数と、有効なスケジュールおよびセンサーの数がバッジで表示されます。**概要**には、プロジェクトの説明とラベル、ロックの状態、テーブル、ワークフロー、ステップ、変数、公開済みテーブル、**データサイズ**（**ストレージ**を開きます）のタイルが表示されます。データサイズは、**プロジェクト**画面に表示される合計（復元用に保持された以前のバージョンを含む）と同じ値で、現在のデータと以前のバージョンを分けて示すツールチップが付きます。さらに、次の 3 回のスケジュール実行、プロジェクトのデフォルト、PDF またはインタラクティブ HTML 形式の**プロジェクトレポート**、**アーカイブのエクスポート**も表示されます。その他のページでは、変数、スケジュールとセンサー（**Calendar view** と **Activate** または **Deactivate** 付き）、プロジェクトとそのダッシュボードを開けるユーザーおよびそのテーブルを読み取れるプロジェクト、接続とテーブルストレージのデフォルト（ERP 転記モードを含む）、Panelアプリ、ブランディング、プロジェクトのタイル画像を管理します。ロックされたプロジェクトにはバナーが表示され、コントロールが無効になります。[プロジェクトホーム](/ja/guides/projects/project-home/)を参照してください。
- **ドキュメントは概要から開き、ページのレールが付きます。** レールには**概要**、**参照**、**Your accounts**、**管理**が並び、各ページにはタイトル（多くはサブタイトル付き）があり、ヘッダーにアクションが配置されます。**概要**には、アカウント、**Pinned** ファイル（**参照**でそのフォルダーを開き、ファイルが選択された状態になります）、サービス別のアカウント、利用できるユーザーのタイルが表示されます。**Your accounts** は、利用できるすべてのアカウントを 1 つにまとめた一覧で、各行に **Shared** または**プライベート**のピルが付きます。**管理**には、自分が所有するアカウントが一覧表示されます。ワークスペース管理者はここですべてのドキュメントアカウントを確認でき、それ以外に管理できるアカウントは管理できます（システム管理のアカウントは拒否され、管理対象バケットのアカウントは複製できません）。行の **⋯** メニューには、**開く**、**編集**、**複製…**、**Who can use it**、**使用箇所…**、**Version history**、**有効にする**または **Disable**、**削除**があります。アカウントはページとして開き、**一般**、**アクセス**、**Credentials** のカードと、SFTP の場合は **SSH** カードがあり、未保存の変更がある状態で移動しようとすると確認が表示されます。**参照**は、お気に入りのアカウントまたはワークスペースのデフォルトのアカウントを開き、ラベル付きのツールバー、行メニュー、ドラッグ＆ドロップによるアップロード（ファイル一覧またはフォルダーにドロップするとそこにアップロードされ、ツリーの空白部分にドロップするとアカウントのルートにアップロードされます）、各アップロードとテーブルへのインポートの進行状況とアクションを表示する **Uploads and imports** パネルを備えています。**Pop out** は、フォルダーを新しいブラウザータブで開きます。[ドキュメント](/ja/guides/documents/)と[ドキュメントアカウントの使用](/ja/guides/documents/using-document/)を参照してください。
- **ダッシュボードは概要から開き、ページのレールが付きます。** レールには**概要**、**ダッシュボード**、**アプリ**、**Notebooks**、そしてワークスペース管理者向けに**アクセスレビュー**が並び、下部には、独自のウィンドウで開くことを示す印が付いた **Open navigator ↗** があります。各ページにはタイトル（多くはサブタイトル付き）があり、ヘッダーにアクションが配置されます。**概要**には、ダッシュボードとアプリのタイルが表示され、選択すると対応する一覧がすでにフィルターされた状態で開きます。さらに、最近開いた、またはスターを付けたもの、失敗したアプリ、自分の対応待ちのアクセスリクエストが表示され、利用状況にアクセスできるメンバーには、最も多く開かれたダッシュボードも表示されます。**ダッシュボード**は、**すべて**、**You manage**、**お気に入り**でフィルターでき、**アプリ**には、各アプリの**種類**とライブの状態が表示されます。[ダッシュボードを使用する](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **ID は概要から開き、ページのレールが付きます。** レールには**概要**、**メンバー**、**ディレクトリ**、**セキュリティグループ**、**配布リスト**、続いて**セッション**、**セキュリティログ**、**APIクライアント**、**Group audit**、**All scopes** が並びます。各ページにはタイトル（多くはサブタイトル付き）があり、ヘッダーにアクションが配置されます。**概要**には、メンバー、アクティブなメンバーと一度もサインインしていないメンバー、ビルダー席、現在サインインしているユーザーのタイル、**アクティブなメンバー**グラフ、**ウェルカムメールを再送信**と**確認**が付いた**要対応**、過去 7 日間のセキュリティイベントが表示されます。メンバーは **プロファイル**、**アクセス**、**Groups and data** のカードがあるページとして開き、**Invite member** は、概要と、ホームの初回実行カードの両方から使えます。[メンバー管理](/ja/administration/access/member-management/)を参照してください。
- **一覧は Standard rows、Roomy rows、Cards で表示できます。** **ダッシュボード**、**アプリ**、ERP レジスター、ID の**メンバー**などの一覧のツールバーにある**ビュー**メニューで、切り替えられます。Cards は、選択、並べ替え、列、右クリックの**コピー**、お気に入りがある一覧ではお気に入りの星など、一覧の機能をすべて保持します。**ダッシュボード**のカードにはサムネイルが表示されます。[Standard、Roomy、Cards ビュー](/ja/guides/dashboards/using-dashboards/#標準の行ゆったりした行カードのビュー)を参照してください。

- **Git アプリには、リポジトリの一覧と、できることが表示されます。** アプリ一覧の **Git** には、あなたのロール（**Administrator**、**Contributor**、**閲覧者**）と、ワークスペースのリポジトリが表示され、各リポジトリには、説明、最終更新日、コピーボタン付きのクローンアドレス、**開く**が表示されます。**Set up Git on your computer** カードは、Git のインストール、トークンの作成、クローンの手順を案内し、**How to clone** で再び開けます。**View all in Git** は Git のインターフェース全体を開き、**Manage who can push** はグループ管理を開きます。アクセスレベルは **閲覧者**、**Contributor**（`apps` にアプリコードをプッシュ）、**Administrator**（`udfs` を含むすべてにプッシュ）で、閲覧者には、依頼できるワークスペース管理者が最大 3 人表示されます。新しい **Git Contributors** グループは Contributor を付与し、デフォルトグループにできるため、新しいメンバーは自動的に付与されます。**Git Administration** は Admin を付与します。メンバーの **Git** タブには、Git ユーザー名、レベル、それを付与しているグループが表示されます。メンバーの Git アカウントはメンバーシップに連動します。メンバーを無効化または削除すると、トークンと SSH キーを含む Git アカウントが約 1 時間以内にブロックされ、再び有効化するとブロックが解除されて、リポジトリと履歴は保持されます。シングルサインオンで Git にサインインすると、そのメンバー自身のアカウントが開きます。Contributor は、ワークスペースの Git 組織に直接リポジトリを作成することはありません。リポジトリは PlaidCloud を通じて作成されます。アプリのウィンドウには **Repository** セクションが表示され、UDF には**開く**があり、Git には、ワークスペースに戻る **← Back to** リンクがあります。アプリのリポジトリや組み込みの `apps` と `udfs` リポジトリを含め、プラットフォームが作成するすべてのリポジトリは、ワークスペースのサインイン済みメンバー全員が読み取れるため、メンバーはリポジトリごとの設定なしでアプリを開き、再公開できます。Git 管理者は、リポジトリを引き続きプライベートにでき、その場合はリポジトリピッカーに表示されなくなり、メンバーがそこから公開したり、そこに保存された Git ベースの UDF コードを実行したりできなくなります。[PlaidCloud Git](/ja/guides/git/#git-を開く)と[リポジトリを閲覧できるユーザー](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)を参照してください。
- **Cost to Serve と Operational Transfer Pricing のテンプレートは、Common Finance Model 上に構築されます。** **Cost to Serve** からプロジェクトを開始すると、各部門に設定したアクティビティとドライバーに基づいて営業費用を顧客に配分し、各顧客のサービス提供コストを差し引いたマージンを、総勘定元帳に結び付けて確認できます。**Operational Transfer Pricing** から開始すると、各エンティティの利益水準（売上高利益率、ネットコストプラスまたは再販売価格マイナス）をポリシーの範囲に照らしてテストでき、範囲外のエンティティを目標に戻すための調整（true-up）も行えます。売上高利益率は、EBIT を被テスト当事者の売上高で割った値です。[Cost to Serve](/ja/guides/projects/cost-to-serve/)と[Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/)を参照してください。

- **Data Foundation はロードのたびにボードパックを作成し、元の状態に戻せます。** **ロード**のたびに、損益計算書ダッシュボードの Excel ブックと PDF が、ドキュメントアカウントのフォルダーに書き込まれます。レポートがオフの場合、パックはブックのみとなり、ダイアログにその旨が表示されます。各ロードの開始時、およびマッピングやソースを変更する前に復元ポイントが作成され、**アクション > Restore...** では、それぞれが戻すテーブルの数が表示され、ディメンションを含むプロジェクトを元に戻せます。**Foundation** タブには専用のレールがあり、**ステータス**、**Answers needed**、**Source coverage**、**ソース**のページが並び、対応が必要な項目のバッジと、変更を適用するための各ページ上部の 1 本のバーがあります。さらに、状況が分かりやすくなっています。実行中または途中で停止した更新を表示し、テーブルのフォルダーがソースにならない理由を示し、何かが一致するまでは **合計が一致することを確認** を保留のままにし、ステータスの読み取りに失敗しても回復します。更新を適用しても、生成されたステップに対するお客様自身の編集は保持され、競合があれば記録されます。[ボードパック](/ja/guides/projects/data-foundation/#取締役会資料)と[復元ポイント](/ja/guides/projects/data-foundation/#復元ポイント)を参照してください。

- **Weave がすべてのアプリの横に表示され、右クリックで質問できます。** ウィンドウの右側にある **Weave ドック**には、Weave との会話、Weave が提案する変更、ジョブがまとまっています。クリックまたは **Ctrl+J**（Mac では **Cmd+J**）で開き、幅を記憶し、開いているものを起点にして、削除できるチップとして表示します。ステップ、複数のステップ、ワークフロー、テーブル、列、ダッシュボード、またはログのエラー行を右クリックして、**説明**、**使用箇所**、**変更内容**、**チェック**、**修正**、**変更…**、**ドキュメント**、**Weave に質問**を選択できます。ほとんどはAIモデルを呼び出さずに回答し、Weave がどのように把握したかを示します。質問するまで、何もスキャンされません。[Weaveドック](/ja/guides/ai-assistant/weave-dock/)を参照してください。
- **失敗したステップを1回の操作で修正できます。** ステップを右クリックして**修正**を選択します。Weave は、何が変わるか、影響がどこまで及ぶか、次に何が起こるかを示すカードを表示します。1回の承認で、複数のステップにまたがる場合でも変更が適用され、修正したステップを ERP 転記をオフにして再実行し、問題が解消したかどうかをはっきりと伝えます。承認はブラウザーでのみ行えます。不在の間に Weave が準備したカードは、その会話で**Waiting for you**の行として待機し、開いて確認でき、何かが変更されている場合は現在の状態が表示されます。Weave が行った変更のうち元に戻せるものにはすべて**元に戻す**があり、カード全体を1回の操作で元に戻せます。復元される内容は事前に表示されます。[AIでワークフローのエラーを修正する](/ja/guides/ai-assistant/fixing-workflow-errors/)を参照してください。
- **Weave のジョブは、画面を離れても処理を続けます。** **Weave**ボタンから**Weave jobs…** を選択すると、各ジョブの状態の確認、進行状況の追跡、会話を開く操作、停止ができます。ドックやタブを閉じてもジョブは続行され、完了したときや対応が必要なときにメッセージが届きます。1分を超えて実行され、停止されなかったジョブについては、アプリを使用していればスマートフォンにも通知が届きます。[処理を続けるジョブ](/ja/guides/ai-assistant/weave-dock/#処理を続けるジョブ)を参照してください。
- **検出事項が役に立ったかどうかを Weave に伝えられます。** 検出事項によっては、通知する価値があったかどうかを高評価と低評価のアイコンで尋ねるものがあり、**月次サマリー**には Weave の検出事項と回答がどの程度役に立ったかが表示されます。[Weaveタブ](/ja/guides/ai-assistant/weave-tab/)を参照してください。
- **モバイルの Weave で、1回のタップで音声入力できます。** マイクをタップして質問を話すと、話し終えた時点で Weave が送信します。もう一度マイクをタップすると途中で停止でき、何も聞き取れない場合は自動的にオフになります。話している途中で**Weave**タブを離れたりアプリをバックグラウンドにしたりした場合、話した内容は送信されずに質問ボックスに残るため、確認できます。実行、一時停止、停止、再開は、確認時の誤った二重タップを無視します。アプリのバージョン1.3.0以降が必要です。[音声を使う](/ja/guides/mobile-app/weave-on-mobile/#音声を使う)を参照してください。
- **Weave が問題をメールで知らせます。** ワークフローの実行が、確認が必要な重大な問題で終了したときのメールと、Weave が知らせた問題のうち未読のものをまとめた毎日のサマリー（指定した時刻に送信）を、自分用にオンにできます。メールには、プロジェクトと、各ワークフロー、ステップ、テーブル、メトリックが問題の種類とともに記載され、**Weave**タブへのリンクが付きます。データの数値や値が含まれることはありません。ワークスペース管理者は、全員の Weave メールをオフにしたり、各メンバーのタイムゾーンでお休み時間を設定し、その時間が終わるまでアラートを保留したりできます。[Weave メール](/ja/guides/ai-assistant/weave-email/)を参照してください。
- **Weave によるお客様のデータの利用について。** **Weave**メニュー、すべての AI チャットの下、**AI機能**に新しいパネルが加わり、ワークスペースで Weave に回答する AI プロバイダーとその所在地、Weave がプロバイダーに送信する内容、学習と保持について現在確認中の事項が分かります。[Weave によるお客様のデータの利用について](/ja/guides/ai-assistant/weave-data-use/)を参照してください。

## 変更

- **フィルターできる 1 つのチェックリストで、あらゆる場所のユーザー、グループ、ワークフローを割り当てられます。** セキュリティグループのメンバー、メンバーのグループとの関連付け、配布リストのメンバー、ドキュメントアカウントのメンバー、グループ、エージェント、所有者、接続アクセス、Weave の準備状況セットのワークフローが、ドラッグで移動する 2 つのリストではなく、同じピッカーを使うようになりました。名前やメールアドレス（`@example.com` のようなドメインを含む）で絞り込み、メールアドレスの一覧を貼り付けてそのユーザーだけに一致させ、**すべて**、**割り当て済み**、**Not assigned** を切り替え、**Assign all shown** または **Unassign all shown** を使えます。変更した行には **Will add** または **Will remove** のピルが付き、**Undo changes** で元に戻せます。保存ボタンは、変更があったときだけ使えます。フィルター内の **Enter** では保存されず、**Space** で選択中の行にチェックが入ります。アクセスを確認できても変更できない場合、リストは読み取り専用です。
- **ワークスペースが Grok を使っている場合、モバイルの Weave は AI に関する通知への同意を再度求めます。** 通知には、xAI がお客様のデータをモデルの学習に使わないという記載がなくなりました。現在は、PlaidCloud は xAI とゼロデータ保持契約を結んでおらず、xAI がデータを保持し、標準の利用規約で認められる範囲で使用する可能性があることが記載されています。[Weave によるデータの使われ方](/ja/guides/ai-assistant/weave-data-use/)を参照してください。
- **What if ウィンドウは、一度に 1 つの期間を読み取ります。** Allocation Split ステップの出力に期間列がある場合、ウィンドウは最新の期間で開き、**期間:** で別の期間または **All periods** を選択できます。ドライバーがすべての期間に行を持ち、全期間にわたって読み取るには大きすぎるステップでも、1 つの期間について開いて回答できるようになりました。保存したシナリオは、保存時の期間（ある場合）を保持し、開くと、その期間がまだ一覧にある限り、ウィンドウがその期間に移動します。[期間を選択する](/ja/guides/allocations/results/driver-what-if/#期間を選択する)を参照してください。
- **PlaidCloud の Web アプリと Python クライアントライブラリは REST API を使用し、JSON-RPC は非推奨になりました。** Web アプリは、リクエストを REST API に送信します。`plaidcloud-rpc` 1.25.0 以降では、`SimpleRPC` の呼び出しはコードを変更せずに REST API に送られます。REST API がまだ対応していない呼び出しや、古いリリースのままのワークスペースでは、従来どおり JSON-RPC が使われます。JSON-RPC は今後のリリースで削除されるため、スクリプトとノートブックを `plaidcloud-rpc` 1.25.0 以降にアップグレードし、新しい連携は REST API に対して作成してください。[コマンドライン](/ja/reference/cli/jupyter/command-line/)を参照してください。
- **ステップは、別の環境に固定しない限り、プロジェクトの接続環境に従います。** プロジェクトの環境（QA と本番など）を切り替えると、すべてのステップが移動します。1 つの環境にとどまる必要があるステップには、代わりに **Fixed environment** を設定できます。フォームには警告が表示され、ログには、プロジェクトの環境以外で実行されるたびにその旨が記録され、プロジェクトを切り替えるときには、従わないステップの名前が表示されます。ERP 転記ステップは、常にプロジェクトの環境を使用します。プロジェクト、固定されたステップ、またはエージェントが使用している環境は削除できず、エージェントフォームのフィールドは **Environment this agent serves** になりました。[ステップを 1 つの環境に固定する](/ja/guides/projects/managing-projects/#ステップを1つの環境に固定する)を参照してください。
- **ステップフォームは 1 つのレイアウトに統一されました。** タブには、標準の名前が標準の順序で付けられています。一般、設定、ソース、列、フィルター、出力、詳細設定です。ERP 転記フォームには、ヘッダー列と明細列も加わります。必須フィールドには * が付き、フォームは、ステップに必要なものがない場合にのみ保存をブロックします。
- **Acumatica、Bill.com、Dynamics、Eclipse、HFM/FCCS、NetSuite、Workday、Workday Financials の接続は、設定を失うことなく作成、編集し、ステップで選択できます。** これらは REST 接続として保存され、**接続**の一覧にはそれぞれのタイプが表示されます。接続を右クリックして **Edit REST settings** を選ぶと、ヘッダー、認証、ページングを開けます。**接続をテスト** は、保存済みの NetSuite 接続と HFM/FCCS 接続で使用できます。Workday Financials 接続は、統合システムユーザーとそのパスワード（両方を指定）または OAuth クライアントでサインインし、Workday、Bill.com、Dynamics、Eclipse のフォームには **APIホスト** フィールドがあります。[接続の作成と管理](/ja/guides/connections/create-connection/)を参照してください。
- **データ入力フォームでは、各フィールドがラベルの隣に配置されます。** Data Foundation の **接続** と **ソース**、ドキュメントアカウントの設定、メンバープロファイルで、フィールドは右端に寄せられず、一定の幅で左揃えになります。
- **Copy Project は、テーブルデータとディメンションメンバーを別々に選択でき、データのコピーが高速になり、プライベートコピーの ERP 書き込み承認も保持されます。** **Data to copy** で、**Table data**（**No table data**（デフォルト）、**完全**、**サンプル**）を選択し、それとは別に、デフォルトでオンの **Copy dimension members** を選択します。そのため、テーブルの行を含まないコピーでも、ディメンションにはデータが入った状態で届き、短時間で作成できます。**完全**と**サンプル**のコピーは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも短時間で完了します。**コピー結果**には、テーブルとともに各ディメンションの結果が一覧表示され、**Retry failed items** は、失敗したテーブルとディメンションをまとめて再試行します。データ付きで作成した新しいコピーは、あなた専用のプライベートなものとなり、あなた自身が付与できるソースの ERP 書き込み承認を保持します。ソースが本番で転記している場合、コピーはシミュレートで作成されるため、本番に切り替えるまで ERP には何も届きません。REST API と `project_copy` MCP ツールも `dimension_members` を受け付けます。[コピーするデータ量を選択する](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーでの ERP 書き込み承認](/ja/guides/projects/managing-projects/#コピーでのerp書き込み承認)を参照してください。
- **テーブルの詳細パネルに、そのテーブルを使うステップがより早く表示されます。** 別のテーブルを選択すると、前のテーブルのステップがすぐにクリアされ、このプロジェクトのデータを共有する他のプロジェクトのステップは、パネル全体を待たせることなく、残りより少し遅れて追加されます。[テーブルの使用箇所を確認する](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)を参照してください。
- **行アクションは、すべての一覧で同じように動作します。** 行のメニューは、行の先頭にある **⋯** ボタン、右クリック、ツールバーの**アクション**メニューから開けます。メニューには常に、**開く**、**詳細**、**編集**が最初に表示され、続いてその一覧固有のアクション、最後に**削除**または**削除**が表示されます。その行に当てはまらないアクションは、その位置でグレーアウトします。**Enter** と **Del** は、実行する項目に表示されます。行のアクションが 1 つだけの一覧では、**⋯** の代わりにそのアクションのアイコンが表示され、ダッシュボード、アプリ、ノートブックでは、再び**開く**アイコンが表示されます。[行アクションメニュー](/ja/guides/dashboards/using-dashboards/#行アクションメニュー)を参照してください。
- **PlaidCloud の外観が、ライトとダークの両方で、青を基調に一新されました。** ボタン、チェックボックス、選択された行、タブ、リンク、ワークスペースのページを一覧表示するレールには、1 つの PlaidCloud ブルーが使われ、両方のテーマで読み取れるコントラストが確保されています。アプリのタブアイコンは、統一されたセットになりました。
- **新しい読み込み画面。** PlaidCloud は、ライトまたはダークのテーマに従う、すっきりした読み込み画面で開きます。アイドル状態から復帰する Panel アプリまたは Dash アプリは、**開始中**、**準備中**、**Loading app** の順に進行状況を表示し、起動しなかった場合は、どのステップで停止したかを表示して、**再試行**を提示します。[Panelアプリを使用する](/ja/guides/panel-apps/using/)を参照してください。
- **検証設定のない保存済み ERP 書き込みステップは、検証のみで開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS の GL と AP の Post、Xero のエクスポートです。明示的に本番実行に設定されているステップは、そのまま本番のままです。
- **実行時間の長いジョブは、どこでも同じ方法で進行状況を表示します。**
- **ワークフローは、停止、失敗、報告が正確になりました。** ワークフローを停止すると、そのワークフローが開始したすべてが停止し、完了できない実行やステップはハングせずに理由付きで失敗し、実行ステータスは実際に実行された内容と一致します。
  - **ワークフローを停止すると、そのワークフローが開始したすべてが停止し、完了できない実行やステップはハングせずに失敗します。** 停止すると、まだキューに入っていたインポートとディメンションのステップがキャンセルされるため、ワークスペース内の後続のインポートとディメンションのロードは通常どおり開始されます。また、そのワークフローのキュー内または実行中のコネクタ（Singer）同期も停止します。ステップのジョブを開始できない場合、ステップは、永遠に待機する代わりに理由付きで失敗します。約 40 分以内にどのワーカーも開始しない、ワーカーが開始したあとに消えた、そのポッドが約 20 分間 Pending のままである、イメージを約 5 分間プルできない、約 20 分間ポッドが作成されない、のいずれかの場合です。約 30 分以内にどのランナーにも拾われないコネクタ同期は、その同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間、そのステータスメッセージには、経過した分数とともに「Waiting for a worker…」と表示され、作業が始まるとクリアされます。マクロを停止すると、実行中のすべてのコピーが停止します。一方、1 つのコピーを停止した場合や、応答しなくなったコピーを **Macro Concurrent** ステップが見限った場合は、それを呼び出したワークフローは実行を続けます。他のワークフローの内部でのみ実行されているマクロは、ワークフロー一覧に**実行中**と表示され、**停止**が利用でき、各ステップのステータス、開始時刻、終了時刻は最新の実行のものが表示されます。サーバーが失われた実行は失敗として終了し、12 時間を超えて実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」で失敗します。[ワークフローを実行する](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
  - **再開、実行履歴、実行ステータスが、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローの 1 つのステップを単独で再実行した後でも、子ワークフローが残していたすべてが実行され、1 回の実行の中での子ワークフローの呼び出しごとに、それぞれ実行履歴のエントリが作成されます。サーバーが停止したために再開するステップは、そのことをログに記録します。`workflow_run_status` と REST API の実行結果は、失敗したものの続行されたステップを `continued_step_ids` と `continued_step_count` に一覧表示し、実行を問題なしとして報告しなくなりました。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。
  - **ステップのエラーに、固有のメッセージが表示されます。** PlaidCloud が想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードは、エラーを 1 行で表示し、その後に削除されたワークフローの実行は表示しません。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。
  - **完了しない ERP 抽出はそのステップを失敗させ、再開で続行できます。** **SAP: アドホック抽出** が行数または時間の上限で一時停止したり、そのエージェントが時間内に応答しなかったりした場合、または、ステップが待機を打ち切ったときに、Salesforce、Oracle Fusion の一括、HFM/FCCS のエクスポートジョブがまだ実行中だった場合、ステップは失敗するため、その後のステップが一部のテーブルで実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は、停止した場所から同じジョブで続行されます。[実行制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)を参照してください。
  - **エクスポートをキャンセルすると、ウェアハウス内のクエリも停止します。** エクスポートまたはダウンロードがキャンセルされた場合（ワークフローの停止による場合を含みます）、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplum では、そのデータを読み取っているクエリも停止し、リモートデータベースへのエクスポートは、最後まで実行を続ける代わりに、ソースの読み取りを停止します。
- **REST、Import REST、Import Postman の各ステップは、ワークスペースのアップグレード時に RESTリクエスト ステップに変換されます。** きれいに変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **セッションの有効期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードに移動します。** [ダッシュボードを使用する](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは、認識できないフィールドを無視せず、拒否して、エラーにその名前を表示します。** `workflow_upsert` は `memo` を受け付け、その別名として `description` も受け付けます。[不明なフィールドは拒否されます](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2 では、Lakehouse が Parquet のエクスポートを Google Cloud Storage に直接書き込みます。** Google Cloud Storage のドキュメントアカウントへのエクスポートは、すべての行がいったん PlaidCloud を経由するのではなく、そのアカウント自身の認証情報で、アカウントのバケットに直接書き込まれます。Amazon S3 と Azure Blob Storage のアカウントへのエクスポートは、従来どおり動作します。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/)を参照してください。
- **Slack、Microsoft Teams、Web Hook の各ステップは、メッセージが送信されなかった理由を表示します。** ステップのエラーには、接続を試みたサーバー、Slack と Teams の場合は接続の名前、何が問題だったかが示されます。たとえば、Slack がもう Webhook を認識しない、チャンネルに投稿できない、サーバーが見つからないか 60 秒以内に応答しない、接続が削除されている、などです。Slack または Teams の Webhook URL は、それを持つ誰もがあなたの連携として投稿できてしまうため、表示されることはありません。[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/)を参照してください。
- **プロジェクトのサービスアカウントのアクセストークンは、少なくとも 24 時間有効です。** UDF ステップなど、プロジェクトとして実行されるワークフロージョブには、24 時間有効なトークンが発行されます。それより短い有効期間は、ワークスペースのアップグレード時に引き上げられ、設定したそれより長い有効期間は保持されます。
- **ワークスペースの組織、所有者、リリース、バージョンは PlaidCloud が設定し、データセンターは選択できます。** コントロールプレーンで作成したワークスペースは、あなたが所有者となり、PlaidCloud が設定するリリースチャネルに配置され、**Data Center** は、サインアップ時に提示されるリージョンから選択します。ワークスペースを編集するとき、組織、所有者、リリース、バージョンは読み取り専用です。バージョンを変更するには **Set Version** を使用し、ワークスペースの移動、所有者やチャネルの変更、固定が必要な場合は、PlaidCloud サポートに依頼してください。[ワークスペース構成](/ja/administration/control-plane/workspace-configuration/#基本設定)を参照してください。
- **エンコード変換ステップで、フォルダーのサブフォルダーを保持できます。** **ドキュメント: ファイルをASCIIエンコードに変換**、**ドキュメント: ファイルをUnicode（UTF-8）エンコードに変換**、**ドキュメント: ファイルをUnicode（UTF-16）エンコードに変換**に、**サブフォルダーを保持**ボックスが加わりました。チェックを入れると、入力フォルダーのサブフォルダー内の各ファイルが、書き込み先の対応するサブフォルダーに書き込まれ、圧縮ファイルの内容は、そのファイルがあったサブフォルダーに入ります。チェックを外したままにすると、従来どおり、すべてのファイルが書き込み先に直接書き込まれます。[ドキュメントのエンコードを UTF-16 に変換する](/ja/reference/workflow-steps/document/convert-document-encoding-to-utf-16/)を参照してください。
- **ソーステーブルが設定と一致しないステップは、何も書き込む前に停止し、すべての問題をまとめて示します。** Table Extract、Table Lookup、Table Inner Join、Table Cross Join、Table Outer Join、Table Anti Join、複数テーブル結合、Table Union Distinct、Table Union All、Table Pivot、Table Melt、Table In-Place Delete、Table Upsert、Table Append の各ステップは、書き込む前にソーステーブルを確認します。ステップが読み取る列がテーブルにない、結合キーがない、またはステップのソース列に含まれていない、ステップが読み取るソーステーブルがまだ作成されていない、といった場合は、それぞれの問題と修正方法を示す 1 つのエラーでステップが停止し、すでに存在していたターゲットテーブルは、それまでの内容を保持します。ソーステーブルが作成されていない場合、Table Union Distinct と Table Union All は例外です。従来どおり、警告なしにそのテーブルを除外して残りを結合し、1 つも作成されていなければ、失敗せずに警告付きで完了します。ステップが一覧に挙げているものの読み取らず、テーブルにももうない列は、代わりに警告となるため、以前に実行できたステップは引き続き実行できます。ターゲットがビューのステップでは、それが一覧に挙げる列と結合キーは、ウェアハウスがいずれにせよビューの作成を拒否する場合に限り、そのテーブルと照合して確認されます。これらの失敗は、以前はデータベースから、データベース独自の言葉で、列ごとに 1 つずつ返されており、ターゲットテーブルを置き換えるステップでは、すでにそのテーブルが空になっていました。ワークフローのエラー処理がデータベースのテキストに一致させている場合は、更新してください。[ステップが実行されるとき](/ja/reference/workflow-steps/tables/table-extract/#実行時に指定された列)を参照してください。
- **テーブルのないエクスポートは、完了せずに停止します。** テーブルのない Export to Parquet、Export to ORC、Export to Avro の各ステップは、ファイルを書き込まずに完了し、テーブルのない Export to XML ステップは、何も含まないファイルを書き込んでいました。これらのステップは、何も書き込む前に、*No Tables Specified* で停止するようになりました。テーブルの一覧がまったくない状態で保存されたステップは、内部設定の名前を挙げた予期しないエラーで失敗していましたが、同じメッセージで停止するようになりました。

## 修正

- **無効なプロジェクト設定が、分かりやすいメッセージで報告されます。** 不明な環境またはドキュメントアカウント、使用済みまたは予約済みのスラッグ、無効なストレージタイプまたは転記モードは、一般的なサーバーエラーの代わりに、問題を示すメッセージを返すようになりました。REST API では 500 ではなく 400 に、AI アシスタントまたは MCP では無効な引数のエラーになります。
- **REST API のディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` は、グリッドリクエストとして処理され、無効として拒否されていました。現在は、`value_columns` の各列に対して集計された 1 つの値を返します。グリッド（行フィルターと列フィルターの各組み合わせに対する 1 つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` が用意されています。
- **テーブルの読み取りやファイル処理が遅くても、他のリクエストが待たされなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundation ファイルの登録、Excel へのエクスポート、REST または SOAP インポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panelアプリのコードやロゴの確認は、それぞれ、完了するまで同じサーバーが処理している他のすべてのリクエストを停止させる可能性がありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 小さな画面や低解像度では、追加および編集ダイアログがウィンドウより高くなり、**作成**ボタンと**更新**ボタンに手が届かないことがありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storage のドキュメントアカウントで、256 MiB を超えるファイルをコピー、移動、名前変更できます。** 以前は、そのサイズのファイルではこれらがすべて失敗し、そのようなファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2 では、テーブルの行数に、書き込んだばかりの内容が反映されます。** テーブルを書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが 0 行と表示されたり、インポートが 0 行をインポートしたと報告したりすることがありました。現在は、新しい行がすべての場所で見えるようになってから行数を読み取るため、その後のステップもそれらを読み取れます。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりしても、行数と列数が更新されます。
- **Weave の空値チェックは、各実行を、以前の実行が実際に残したものと比較します。** ステップの空値は、ステップがテーブルを空にして再入力した直後にカウントされることが多く、以前の実行には空値がなかったように見え、常に一部が空だった列が、たった今そうなったかのように報告されていました。現在は、各実行を、ステップがテーブルを残した状態でカウントします。以前に記録されたカウントは、正しいものと区別できないため使用されません。各ステップの空値チェックは履歴を最初から取り直し、5 回の実行がカウントされるまでは未チェックとして報告されます。また、行数と値の分散のチェックでは、ステップの完了から 2 秒を超えて後に別のステップが同じテーブルに行った書き込みを、そのステップの書き込みとして扱わなくなりました。[Weave が確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **Data Foundation は、反転した為替レートと小数のしきい値の精度を保持します。** 為替レートが報告通貨から別の通貨への相場で提示されているために PlaidCloud が逆数にしたレートは、小数点以下 6 桁に丸められることがあり、インドネシアルピアのようにレートの小さい通貨では、金額が約 1% ずれていました。反転したレートは、小数点以下 12 桁を保持するようになりました。`0.5` のように小数を含む `group_amber` または `group_red` のしきい値は、整数に丸められていました。次の**ロード**から、正確な値が使われます。[為替レート](/ja/guides/projects/data-foundation/#為替レート)を参照してください。
- **無効化されたメンバーのアラートとダイジェストは停止します。** 所有者が無効化されたPanelアプリのアラートやダイジェストは、チェックと送信を続けていました。現在は、無効化されている間は一時停止し、再び有効化されると再開します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
- **削除された接続を REST API に要求すると、404 が返されます。** 削除された接続や、存在しない ID を要求すると、一般的なサーバーエラー（500）が返されていました。現在は、接続 ID を示すメッセージとともに 404 が返されます。
- **テンプレート化されたテーブルのエクスポートが、AI アシスタントと MCP で動作します。** `table_data_export` の `templated` 形式は、テーブルを指定すると常に失敗していました。現在は、テンプレートを通じてテーブルをエクスポートし、読み取れる行に限定されます。テンプレート内では、テーブルの行は、テーブル ID の各 `-` を `_` に置き換えた名前で参照されます。
- **Amazon S3 と S3 互換のドキュメントアカウントが、リージョンを保持します。** これらのアカウントを保存すると、入力した**リージョン**が破棄され、次にアカウントを開いたときにフィールドが空になっていました。リージョンが保存されるようになりました。この修正より前に保存したアカウントでは、リージョンをもう一度入力して保存してください。[AWS S3 アカウントを追加する](/ja/guides/documents/adding-accounts/add-aws-s3-account/)を参照してください。
- **フォルダーのエンコード変換で、同じ名前の別のファイルが上書きされなくなりました。** 書き込み先の同じ場所に向かう 2 つのファイル（たとえば、異なるサブフォルダーにある同じ名前の 2 つのファイル）では、最後に書き込まれた 1 つしか残りませんでした。ステップは、2 つ目を書き込む前に停止し、両方のファイルと書き込み先を示し、**サブフォルダーを保持**にチェックを入れるとそれらを分けて保持できる場合はその旨を表示するようになりました。
- **ドキュメント: ファイルをASCIIエンコードに変換 の「ターゲットエンコードで表現できない文字を ? に置き換える」をオフにすると反映されます。** **ターゲットエンコードで表現できない文字を ? に置き換える**にチェックを入れて保存したステップは、チェックを外してもう一度保存しても、そのままの状態でした。チェックを外すと、置き換えがオフになります。
- **AI アシスタントと JSON-RPC は、ロールで非表示になっているテーブルを使用するステップの名前を表示しなくなりました。** そのようなテーブルの使用箇所を尋ねると、ロールで参照できる、そのテーブルを読み取るまたは書き込む各ステップが、その設定とワークフローとともに表示されていました。現在は、プロジェクトのテーブル参照と同様に、ステップ名を表示せず、ステップがそのテーブルを使用していることだけを伝えます。[ロールで非表示になるもの](/ja/guides/ai-assistant/weave-tab/#ロールで非表示になる内容)を参照してください。
- **選択したデフォルトの AI 接続は、デフォルトのままになります。** AI 接続をワークスペースのデフォルトとして設定しても、成功したように見えるだけで保存されておらず、デフォルトに依存するエージェントとステップは、最後に更新された接続を使い続けていました。選択内容が保存されるようになりました。[LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **Weave の履歴で会話を右クリックしても、「スレッドを削除」の上に「名前の変更」が開かなくなりました。** **名前の変更**は、チャットのタブに移動しました。これまで何も表示されなかったタブを右クリックしてください。[Weave タブのタブ](/ja/guides/ai-assistant/weave-tab/#weaveタブ内のタブ)を参照してください。
- **空白のメモがあっても保存できます。** **メモ**ボックスを空のままにして、プロジェクト、ディメンション、テーブル、ウェアハウス、エディター、スケジュール済みワークフローイベント、配布リストを作成または保存すると、「Memo: Input should be a valid string」で失敗していました。空白のメモが受け付けられるようになりました。
- **1 つの値が期待される場所に複数の値を返す式は拒否され、Table Extract または Table Union All ステップは、ターゲットテーブルのデータを保持します。** よくある原因は、`table.amount,` のような末尾のカンマや、`table.region == ('EU', 'US')` のような複数の値との比較です。Databend ではステップが失敗し、Table Extract または Table Union All ステップでは、その時点でターゲットテーブルがすでに空になっていました。他のウェアハウスの中には、このような式を実行するものもありましたが、必ずしも記述どおりには実行されなかったため、これまでエラーなく動作していたステップが拒否されることがあります。ステップフォームは、ステップを保存するときにその式を拒否し、メッセージに変更すべき点が示されます。[1 つの値が期待される場所に複数の値](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#1つの値が必要な場所に複数の値がある場合)を参照してください。
- **出力列の名前を 2 回指定したステップは、ターゲットを空にする前に停止します。** Table Lookup、Table Extract、結合で、同じ名前の **ターゲット出力列** が 2 つあると、ステップはターゲットテーブルを空にした後、分かりにくいエラーで失敗していました。現在は、先にステップが停止し、重複している列を示すメッセージが表示されるため、各出力列に固有の名前を付けられます。クエリが返す順序で列を書き込む SQL抽出は、変更ありません。[Table Lookup](/ja/reference/workflow-steps/tables/table-lookup/)を参照してください。
- **ソース列なしで保存されたユニオンのソースは、不足しているものを示します。** REST API、JSON-RPC、または AI アシスタントや MCP で、ソース列の一覧なしに保存された Table Union All または Table Union Distinct のソースは、ステップの実行時に、内部設定の名前を挙げた予期しないエラーで失敗していました。現在は、そのようなソースの保存は、ソースの名前を示して拒否され、以前に保存されたものを読み取るステップは、何も書き込む前に、そのソースの名前を示して停止します。テーブルのすべての列を取り込む、または位置で積み重ねる、変換済みの Table Union All には一覧は不要で、一覧がないことを理由に拒否されることはありません。
- **列の定数に、数値、`0`、`false` を使用できます。** 出力列の定数が数値のステップは、予期しないエラーで失敗していました。`0` または `false` の定数は、定数なしとして扱われていたため、その列は代わりに式またはソース列を使用するか、列に読み取るものがないためにステップが失敗していました。これらの定数は、すべての行に、列のデータ型に変換して書き込まれるようになり、AI アシスタントもそのようなステップを提案できます。
- **変換された Alteryx の Data Cleansing ツールが null 行を削除します。** **Remove Null Rows** をオンにした Data Cleansing または Data Cleanse Pro ツールは、変換レポートで確認対象としてフラグが付けられ、変換後のステップはすべての行を残していました。現在は、Alteryx と同様に、すべての列が null である行をステップが削除します。空のテキスト値を持つ行は残ります。Data Cleanse Pro は他のオプションの後に各行をチェックするため、null を空の値に置き換えた行も残ります。**Remove Null Columns** は引き続き確認対象としてフラグが付けられます。この修正を反映するには、ワークフローをもう一度インポートしてください。
- **列が指定されていないメールの通知は、すべての列を含めます。** 列を選択していない Notify Via Email のフレームは、以前は実行が失敗していました。テンプレート本文では、件名の `{variable}` プレースホルダーが、スケジュールされた送信、プレビュー、**自分にテスト送信** で置き換えられます。
- **式の検証は、実行時に受け入れられる関数を受け入れます。** `int(...)` などの関数を呼び出す有効な式が、チェック時に拒否されていました。

## セキュリティ

- **Weave は、各会話の開始時に、お客様の名前とメールアドレスを AI プロバイダーに送信しなくなりました。** これらが使われることはありませんでした。
- **パスワードによるサインインには認証アプリが必要になり、パスワードが強化されました。** PlaidCloud のパスワードでサインインするメンバーは、次回のサインイン時に認証アプリの設定を求められ、その後は毎回コードを入力します。シングルサインオン、Google、Microsoft、GitHub によるサインイン、API トークン、サービスアカウントは変わりません。新しいパスワードは 12 文字以上で、ユーザー名や直近 6 回のパスワードのいずれかと同じにはできず、サインインの失敗が繰り返されると、アカウントは短時間ロックされます。ワークスペースにすでにあったより厳しいルールは維持されます。[メンバー認証](/ja/administration/access/member-authentication/)を参照してください。
- **接続は、パブリックアドレスとプライベートネットワークのアドレスを指します。** 接続は、ループバック、リンクローカル、クラウドメタデータのアドレスを指すことはできず、エラーにはホストと解決先のアドレスが表示されます。プライベートネットワーク上のアドレスは影響を受けません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続できないアドレス)を参照してください。
- **保存された接続の認証情報は、接続またはワークフローを編集できるメンバーにのみ表示されます。** REST API と MCP では、保存された接続のパスワード、トークン、キーは、他のメンバーに対してはマスクされますが、そのメンバーも接続を開いて参照できます。[接続の認証情報を確認できるユーザー](/ja/guides/connections/create-connection/#接続の認証情報を確認できるユーザー)を参照してください。
- **アプリのビルドは、ワークスペースの Git 認証情報にアクセスせずに実行されます。**
- **エージェントの秘密鍵は、エージェントを編集できるメンバーにのみ表示されます。** 鍵は、REST API と MCP のエージェント一覧や詳細に表示されなくなり、エージェントフォームは、**秘密鍵**と **RPC構成を表示**を、エージェントを編集できるメンバーにのみ表示します。サービスアカウント、プロジェクトトークンとエージェントトークン、AI に委任されたトークンは、鍵や RPC 構成を取得できません。実行中のエージェントには影響せず、公開鍵は引き続き表示されます。[エージェントの認証情報を取得する](/ja/reference/cli/plaidlink/agents/#エージェントの認証情報の取得)を参照してください。
- **プロキシのダウンロードリンクは 1 時間有効です。** **Use PlaidCloud Proxy Download** がオンの場合、リンクの有効期限が切れたら、ダウンロードをもう一度開いて新しいリンクを取得してください。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)を参照してください。
- **セキュリティグループへのユーザーの追加は、保有する権限に従います。** セキュリティグループにメンバーを追加する、メンバーのグループを選択する、アーキテクトを招待するには、そのグループが付与するすべての権限を保有している必要があります。ワークスペース管理者には制限はありません。[セキュリティグループの管理](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)を参照してください。
- **接続の所有者またはワークスペース管理者が、その設定を変更し、オンとオフを切り替えます。** REST API、JSON-RPC、AI アシスタントまたは MCP で接続の設定を変更するには、その所有者のいずれか、所有者のない接続ではワークスペース管理者である必要があります。接続の有効化、無効化、ロック、ロック解除には、所有者またはワークスペース管理者が必要で、複数の接続を指定したリクエストは、そのすべてを変更できる場合にのみ適用されます。ワークスペースのデフォルトの AI 接続を選択できるのはワークスペース管理者だけで、メンバーが所有する接続がデフォルトになるのは、管理者が所有する、または所有者のいない接続がどれもデフォルトになりえない場合に限られます。[接続を編集する](/ja/guides/connections/create-connection/#接続の編集)と [LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **行アクセスは、メンバーが制限付きテーブルに対して行うすべての操作に適用されます。** メンバーは、ダッシュボード、自身の SQL、ロードで、付与された範囲の行だけを表示、変更できます。
  - **プロジェクトのアーキテクトは、ダッシュボードで行が制限されたテーブルのすべての行を表示できます。** これは、Analyze で表示される内容と一致します。アーキテクトのアクセス権を取り消すと、ダッシュボードにも即座に反映されます。これは、誰かのロールを変更した場合、その人またはそのグループをプロジェクトから削除した場合、プロジェクトのアクセスタイプを変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれにも当てはまります。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
  - **行アクセスで制限されたメンバーは、自身の SQL クエリを実行し、結果をエクスポートできます。** 行アクセスのあるプロジェクトで、アーキテクトではないメンバーは、クエリ画面での自分のクエリから、付与された範囲の行だけを正確に取得でき、**アクセス権により行が制限されています**という通知とともに、CSV、Excel、JSON にエクスポートできます。以前は、これらは拒否されていました。パーセント記号（`%`）を含む付与値は、クエリ画面で行を返すようになり、そのようなクエリを CSV としてダウンロードすることも可能です。Snowflake または Databricks 上での自由形式の SQL、Postgres 系ウェアハウスでの自身の SQL のエクスポート、ガバナンス対象のテーブルをスナップショット時点で読み取る操作は、引き続き拒否されます。また、ビューがフィルターされるには、ガバナンス対象の列を元の名前のままにしておく必要があります。[行アクセスと自分で作成するクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスと自分で作成するクエリ)を参照してください。
  - **行アクセスを保存しても、ソースにない付与値は保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がない、ディメンションにそのメンバーがない、またはリストにその値がない場合でも、マークが付いた状態でグリッドに残ります。**保存**を押すと、そのような値ごとに、保持するか削除するかを確認されます。[行アクセスのグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
  - **行が制限されたテーブルへの DataFrame の書き込み、レコードの保存、クリアは、表示できる行のみを変更します。** 行アクセスで行が制限されている場合、Python クライアントで制限付きテーブルに DataFrame を書き込んだりクリアしたり、REST API でレコードを保存したりクリアしたりしても、変更されるのは自分の行だけです。アクセス範囲外の行を含むロードは、何かが変更される前に、見つかった値を示して拒否されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は、テーブル全体を書き込みます。人が任意のテーブルに対して行うこれらの書き込みは、すべて**セキュリティログ**に記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータのロード)を参照してください。
  - **行が制限されたテーブルに対するインポート、コピー、復元、削除には、すべての行を表示できる必要があります。** 行アクセスで行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからテーブルへのコピー、ブランチの切り替えやマージ、復元、削除、削除後の復旧、その他テーブル全体を置き換える操作は、テーブルのすべての行を表示できる場合にのみ実行されます。それ以外の場合は拒否され、何も変更されません。REST API でテーブルの行を保存すると、他のロードと同様に、自分の行だけが変更されます。プロジェクトのアーキテクト、すべての行を参照できるメンバー、ワークフローの実行は影響を受けず、これらの操作も**セキュリティログ**に記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータのロード)を参照してください。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントの所有者だけです。** ドキュメントアカウントを以前のバージョンに復元する、バージョンを保持または解放する、バックアップを取る、といった操作には、そのアカウントの所有者のいずれかが必要で、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、そのアカウントへのアクセス権が必要です。
- **`query_run` は読み取り専用の文を実行します。** AI アシスタントと MCP クライアントが使用する `query_run` ツールは、SELECT または WITH の文 1 つ、その EXPLAIN、または SHOW を受け付け、それ以外の文は実行されません。データを変更するには、`query_transform` を使用してください。MCP のテーブルエクスポートに含まれる SQL にも、同じルールが適用されます。REST API と JSON-RPC API では、プロジェクトデータを変更できないメンバーに対して、クエリの実行、列ファセットの作成、クエリの CSV としてのダウンロード、クエリのリモートデータベースへのエクスポート、独自のクエリによるテーブルデータのエクスポートにも適用され、拒否されたクエリは 403 を返します。Explain Analyze は、測定のためにクエリを実行するため、クエリログと Lakehouse では、読み取るクエリのみを受け付け、行アクセスのあるプロジェクトでは、クエリログからこれを実行できるのはプロジェクトのアーキテクトだけです。
- **テーブルエクスプローラーのフィルター、PlaidCloud に送信されるクエリ、Table Extract ステップの動的列を検出するクエリは、SQL を実行する関数やサーバーのファイルを読み取る関数を呼び出せません。** `query_to_xml`、`dblink`、`pg_read_file` などの呼び出しは拒否され、エラーには関数名が示されます。同じ場所で、`.op()` は演算子のみを受け付け、`literal_column` では Unicode エスケープされた引用符は使用できません。動的列のクエリは、ステップのフィルターと、ソースから列名を読み取る式を含むため、ルールに違反するものは、実行時にステップを失敗させます。[拒否される関数と演算子](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#拒否される関数と演算子)を参照してください。
- **Data Foundation の配賦ルールは、単一引用符、バックスラッシュ、改行を含む部門名または統計名を拒否します。** 名前は配賦ステップのフィルターに書き込まれるため、**保存**とステージ 1 のプレビューは、それを拒否し、その値を示します。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。
