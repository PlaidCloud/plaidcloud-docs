## 追加

- **PlaidXL で、Excel 上でレポートの作成、ドリル、数値の説明、計画ができます。** **PlaidCloud** リボンタブは、**接続**、**挿入**、**更新**、**ドリル**、**書き込み**、**共有**にグループ化されています。よく使うコマンドは **PlaidXL** の右クリックメニューと **PlaidXL Cell** タブにもあり、主要なコマンドには変更可能なキーボードショートカットがあります。フィールドに入力している間は、ショートカットは動作しません。コマンドが失敗した場合は、どのコマンドがなぜ失敗したかが表示されます。サインイン前に実行したコマンドはサインイン画面を開き、サインイン後に実行されます。サインインは 1 つのワークスペースに対して有効なため、ワークスペースを切り替えると新しいワークスペースへのサインインが求められます（元のワークスペースに戻すときは求められません）。また、Office で Microsoft Entra の職場アカウントを使用している場合は、PlaidXL がワークスペースを自動的に見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます。** **レポート**タブは、テーブルから、1 つのディメンションを行方向に、別のディメンションを列方向にドリルダウンし、各交点に `CELL` 値を配置したライブレポートをレイアウトします。**Build my first report** は、ご自身のデータからサンプルを作成します。ドリルすると、レポートは行や列全体を挿入・削除し、入力した値、メモ、書式は行とともに保持されます。[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **任意のセルからドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only** は、ノード、ディメンションの見出し、レポートの値から、ノードをライブの `DRILL` 数式に変換して編集します。**Custom drill** は挿入前に行をプレビューし、メンバーピッカーはメンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりします。`DRILL` には、除外または展開するノードを指定でき、行方向にも実行できます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明できます。** **Explain this number** は、値の計算内容、現在の PlaidCloud と一致しているかどうか、その元となるテーブルとワークフローステップを表示します。**Show detail rows** は、値の根拠となる行を専用のシートに表示し、合計が一致するかどうかもチェックします。
  - **ガバナンスされたメトリックを Excel で使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるのと同じビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計では `0` を、それ以外では理由とともに `#VALUE!` を表示します（`CELLS` のスピルでは空白）。**Metric...** は、プロジェクトのメトリックを現在の値とともに一覧表示します。メトリックは複数の代替階層でフィルターでき、代替階層のメンバーを他のディメンションのメンバーと組み合わせることもできます。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに入力して計画できます。** `CELL` の値に数値を上書き入力すると、PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの形状に合わせた配分、金額または割合による調整が可能で、保持されたセルは変更されません。平均、中央値、最小値、最大値、標準偏差、分散のセルにも値を入力でき、入力値は行や列が挿入または削除されてもセルに追従します（削除されたセルの値は報告されます）。**Undo last write** は、入力した値と保存を新しいものから順に取り消します。書き込みを元に戻せるのは、その書き込みを行ったユーザーとワークスペースだけです。合計の取り消しや、空のセルに入力した平均の取り消しでは、その後同じセルに書き込まれた内容が保持されます。完了前に中断された書き込みは取り消せません。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要なものだけを更新できます。** シート、選択範囲、またはすべてのテーブルを更新でき、各テーブルの進行状況と**キャンセル**はタスクペインに表示されます。PlaidXL の数式だけを再計算することもできます。取得したテーブルは、データ型に応じて書式設定された Excel テーブルとして届き、更新時も独自の列や数値書式を保持し、同じ場所で更新されます。取得や更新で他のセルが上書きされたり、別の Excel テーブルと重なったりすることはありません。Excel で扱えない大きさの整数 ID や 1900 年より前の日付はテキストとして届きます。テーブルを再取得しても更新リストに二重に追加されることはなく、**Stop refreshing** で 1 つずつ外せます。ディメンションはテーブルとともに更新されます。[すべてのテーブルを更新](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存はすぐに書き込まれ、元に戻せます。** **Save to PlaidCloud** は確認なしで書き込み、何を行ったかを表示して、**元に戻す**を提示します。Lakehouse テーブルでは、各保存から最大 7 日間元に戻せます。フィルター付きで取得したシート、詳細行のシート、一部の行にしかアクセスできないユーザーの場合は、それらの行だけが置き換えられるため、他のユーザーの行は保持されます。取得後にメンバーが変更されたドリルスルーシートは保存されません。保存に失敗した場合は、テーブルを元に戻せるようにリストアポイントが示されます。[テーブルを PlaidCloud に保存](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave** タブで、レポート、数式、ドリル、テーブルを平易な言葉で依頼するか、**Ask Weave about this cell** を選択します。Weave はあなたとして PlaidCloud を読み取り、ワークブックだけを変更します。入力済みの内容を置き換える前に確認し、ワークブックの外を参照する数式は書きません。各変更は、ペインを再読み込みするまで元に戻せます。[Excel で Weave に質問](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1 つのシートまたはワークブック全体の値のみのコピーを共有できます。** **Convert to values** は、ワークブック全体、1 つのシート、または元に戻せない値のみ（事前に確認されます）に変換します。変更されるのは PlaidXL の数式とそのスピルだけで、まだ計算中の数式は再試行できるように残されます。シート名を変更した後でも **Restore PlaidXL formulas** は動作します。
- **転記レジスターは、対応が必要なものから開きます。** 確認が必要なものがあるときは**例外**、承認待ちのリクエストがあるときは**承認**、それ以外のときは**すべての転記**で開きます。レールは画面を**自分の対応待ち**、**レジスター**、**インサイト**、**設定**にグループ化し、**例外**と**承認**には件数が表示されます。すべての画面が 1 つのヘッダーとスコープバーを共有し、期間（**今月**、**前月**、**過去7日間**、**過去30日間**、**カスタム**）、接続、プロジェクト、環境、エンティティ、そして**本番**、**シミュレーション**、**すべて**を選択して、**リセット**するか **Saved scope** として保存できます。前回のスコープは記憶されます。
  - **例外画面で、確認が必要なものを整理できます。** **要確認**、**未確認**、**保留中**、**失敗**、**取消未完了**のチップに件数が表示され、接続の状態を示す行には「All N connections posting normally」と表示されます。すべての転記には、次に何をすべきかを示すツールチップ付きの分かりやすい状態が表示されます。未解決のものがない場合は **All clear** が表示されます。**Find a posting by ledger id** またはコマンドパレットに元帳 ID を貼り付けると、その転記が直接開きます。
  - **承認、委任、ウォッチは受信トレイ形式の画面です。** **Waiting on me** と **Submitted by me** を切り替え、理由を付けて**承認**または**却下**できます。複数件をまとめて承認することもでき、承認はトーストから**元に戻す**ことができます。**Delegate approvals** は短いダイアログで、**ウォッチ一覧**にはフォローしているものが表示されます。**転記を取消**と、一括の再試行・クリアのダイアログは、同じレイアウトを共有します。
  - **転記のドロワーで、何が起きたかが分かります。** 状態とその意味、名前付きの主要な事実、**明細**、**履歴**、**承認**タブが表示され、**レビュー済みにする**、**再試行**、**取消…**、**接続をウォッチ**、**実行をウォッチ**、そしてその転記を直接開く**リンクをコピー**があります。
  - **アシスト、エクスポート、保持期間も同じデザインに従います。** **アシスト**には質問ボックスとインサイトカードがあり、アドバイスには **Draft — nothing applied** と表示されます。**すべての転記**には、**これらを表示**付きの異常カードがあります。**エクスポートとアラート**には **New schedule** があり、**保持期間**は 1 つのカードにまとめられています。
  - **レジスターは常に最新の状態に保たれます。** レールのバッジは転記の変化に応じて更新され、転記が変更されると、開いているリストに**更新**が表示されます。開いているドロワーはその場で更新されます。**ホーム**には、**要対応**の下に**転記レジスター**カードが表示されます。[転記レジスターのレビュー](/ja/guides/connections/posting-register/)を参照してください。
- **プロジェクトホームは 6 つのページで構成されます。** レールには**概要**、**変数**、**スケジュールとセンサー**、**アクセスと共有**、**データと接続**、**アプリとブランディング**が並び、変数の数と、アクティブなスケジュールとセンサーの数のバッジが表示されます。**概要**には、プロジェクトの説明とラベル、ロックの状態、テーブル、ワークフロー、ステップ、変数、公開済みテーブル、**データサイズ**（**ストレージ**が開きます）のタイル、次の 3 件のスケジュール済み実行、プロジェクトのデフォルトが表示され、PDF またはインタラクティブ HTML の**プロジェクトレポート**と**アーカイブのエクスポート**があります。その他のページでは、変数、スケジュールとセンサー（**Calendar view** と **Activate** または **Deactivate** 付き）、プロジェクトとそのダッシュボードを開けるユーザーとそのテーブルを読み取れるプロジェクト、接続とテーブルストレージのデフォルトと ERP 転記モード、Panelアプリ、ブランディング、プロジェクトのタイル画像を管理します。ロックされたプロジェクトにはバナーが表示され、コントロールは無効になります。[プロジェクトホーム](/ja/guides/projects/project-home/)を参照してください。
- **ドキュメントは概要から開き、ページを切り替えるレールを備えています。** レールには**概要**、**参照**、**共有**、**自分専用**、**管理**が並びます。**概要**には、アカウントのタイル、そのフォルダーで**参照**を開いてファイルを選択した状態にする**ピン留め**したファイル、サービス別のアカウント、アカウントを使用できるユーザーが表示されます。**管理**には所有しているアカウントが一覧表示され、ワークスペース管理者にはすべてのドキュメントアカウントが表示され、ほかの方法でも管理できるアカウントであれば管理できます（システム管理のアカウントは拒否され、マネージドバケットのアカウントは複製できません）。行の **⋯** メニューには、**開く**、**編集**、**複製…**、**使用できるユーザー**、**使用箇所…**、**バージョン履歴**、**有効にする**または**無効にする**、**削除**があります。アカウントは、**一般**、**アクセス**、**認証情報**、SFTPの場合は**SSH**のカードを持つページとして開き、未保存の変更があるままページを離れる前に確認します。**参照**には、ラベル付きのツールバー、行メニュー、ドロップゾーン、各アップロードとテーブルへの各インポートを進行状況とアクションとともに表示する**Uploads and imports**パネルがあります。**Pop out**でフォルダーを別ウィンドウで開き、**Dock**で元に戻せます。[ドキュメント](/ja/guides/documents/)と[ドキュメントアカウントの使用](/ja/guides/documents/using-document/)を参照してください。
- **ダッシュボードは概要から開き、ページを切り替えるレールを備えています。** レールには**概要**、**ダッシュボード**、**アプリ**、**Notebooks**、ワークスペース管理者向けの**アクセスレビュー**が並び、下部には**Open navigator**があります。**概要**には、該当する一覧をあらかじめ絞り込んだ状態で開くダッシュボードとアプリのタイル、最近開いたものやお気に入りに登録したもの、失敗したアプリと対応待ちのアクセスリクエスト、そして利用状況へのアクセス権を持つメンバー向けに、最もよく開かれたダッシュボードが表示されます。**ダッシュボード**は**すべて**、**You manage**、**お気に入り**で絞り込むことができ、**アプリ**には各アプリの**種類**とリアルタイムのステータスが表示されます。[ダッシュボードの使い方](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **Identityは概要から開き、ページを切り替えるレールを備えています。** レールには**概要**、**メンバー**、**ディレクトリ**、**セキュリティグループ**、**配布リスト**、続いて**セッション**、**セキュリティログ**、**APIクライアント**、**Group audit**、**All scopes**が並び、**利用状況レポート**はページの上に開きます。**概要**には、メンバー、アクティブなメンバー、一度もサインインしていないメンバー、ビルダーシート、現在サインインしているユーザーのタイル、**アクティブなメンバー**のグラフ、**ウェルカムメールを再送信**と**確認**を備えた**要対応**、過去7日間のセキュリティイベントが表示されます。メンバーは**プロファイル**、**アクセス**、**Groups and data**のカードを持つページとして開き、**Invite member**は概要とホームの初回カードから使用できます。[メンバー管理](/ja/administration/access/member-management/)を参照してください。
- **ステップフォームにプレビューが追加されました。** インポート: SQL、Execute: SQL、SQL抽出、エクスポート: SQL、Salesforce Query は、ステップを実行せずに最大 100 行を表示し、Anaplan のビューとリストの読み取りは、生成される列と型を表示します。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように補完されますが、`{x:>9}` のような変数の書式はサポートされていません。プレビューは標準の SQL 関数のみを実行し、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトや、エージェントベースの Execute SQL ステップでは利用できません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と[SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)を参照してください。
- **利用状況レポートで、変化の確認、グループへの絞り込み、ワークフローへの連携ができます。** **概要**に、前の期間との比較を示すトレンド矢印と、非アクティブなメンバーや誰も開いていないダッシュボードとアプリを示す **Highlights** リストが追加されました。無効化されたメンバーは、非アクティブとして数えられたり一覧表示されたりしません。**グループ**は、**概要**、**内容**、非アクティブなメンバーのリストを 1 つのセキュリティグループのメンバーに絞り込みます。日付範囲には**前の月**と**今月**が追加され、すべてのタブで共有され、アカウントに記憶されます。すべての数値に説明が付き、テーブルには**メンバー**や**エリア**などの分かりやすい名前が使われ、行は Enter キーで開き、読み込みとエラーの表示が分かりやすくなりました。最後の**ファネル**ステップには、それを完了したメンバーの数が表示されます。**Get Workspace Usage** ステップは、利用状況を、メンバー名を含まない日次または月次の合計として、またはレポート用のデータセット（**メンバー**、**メンバー別（日次）**、**内容**、**メンバー別の内容**）として、スケジュールに従ってテーブルに書き込みます。メンバーのデータセットには名前、メールアドレス、グループ、活動が含まれるため、メールアドレスで独自の組織テーブルと結合し、部門別にアクティブな時間（分）やダッシュボードを開いた回数をレポートできます。各実行は、**Get Workspace Members** と同様に、セキュリティログに記録されます。[利用状況レポート](/ja/administration/access/usage-reports/)と [Get Workspace Usage](/ja/reference/workflow-steps/general/get-workspace-usage/) を参照してください。
- **AI アシスタントで、テーブルの公開解除と、プロジェクトのデフォルトのダッシュボードオーディエンスの設定ができます。** `publish_manage` は、テーブルを、その公開ビューと、どのグラフも使用していないダッシュボードデータセットとともに公開解除します。グラフがまだ使用しているデータセットは残ります。公開ビューの上にレポートビューが作成されている場合は、そのビューとデータセットも残りますが、テーブルは公開解除されます。`project_upsert` は `dashboard_default_audience`（プロジェクトの新しいダッシュボードの共有先グループ）を設定し、`[]` を指定するとクリアされます。[公開解除](/ja/guides/data/publish/#ai-アシスタントまたは-mcp-で公開を取り消す)と[AI アシスタントまたは MCP でデフォルトのオーディエンスを設定](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ai-アシスタントまたは-mcp-でデフォルトの対象ユーザーを設定する)を参照してください。

- **Git アプリで、リポジトリが一覧表示され、できることが分かります。** アプリリストの **Git** には、ロール（**管理者**、**コントリビューター**、**閲覧者**）と、ワークスペースのリポジトリが表示されます。各リポジトリには、説明、最終更新日、コピーボタン付きのクローンアドレス、**開く**があります。**Set up Git on your computer** カードでは、Git のインストール、トークンの作成、クローンの手順が案内され、**How to clone** で再度開けます。**View all in Git** は Git の完全なインターフェースを開き、**Manage who can push** はグループ管理を開きます。アクセスは、**閲覧者**、**コントリビューター**（アプリのコードを `apps` にプッシュ）、**管理者**（`udfs` を含むすべてにプッシュ）のいずれかで、閲覧者には問い合わせ先として最大 3 人のワークスペース管理者が表示されます。新しい **Git Contributors** グループはコントリビューターの権限を付与し、デフォルトのグループにもできるため、新しいメンバーに自動的に付与されます。**Git Administration** は管理者の権限を付与します。メンバーの **Git** タブには、Git のユーザー名、レベル、それを付与するグループが表示されます。メンバーの Git アカウントはメンバーシップに従います。メンバーを無効化または削除すると、約 1 時間以内にそのメンバーの Git アカウントがトークンと SSH キーを含めてブロックされ、再度有効化するとブロックが解除されます。リポジトリと履歴は保持されます。シングルサインオンで Git にサインインすると、メンバー自身のアカウントが開きます。コントリビューターは、ワークスペースの Git 組織にリポジトリを直接作成しません。リポジトリは PlaidCloud を通じて作成されます。アプリのウィンドウには**リポジトリ**セクションが表示され、UDF には**開く**があり、Git にはワークスペースに戻る **← Back to**リンクがあります。アプリのリポジトリや組み込みの `apps`、`udfs` リポジトリを含め、プラットフォームが作成するすべてのリポジトリは、ワークスペースのサインイン済みの全メンバーが読み取れるため、メンバーはリポジトリごとの設定なしでアプリを開いて再公開できます。Git 管理者は引き続きリポジトリを非公開にでき、その場合はリポジトリピッカーに表示されなくなり、メンバーはそのリポジトリからの公開や、そこに保存された Git ベースの UDF コードの実行ができなくなります。[PlaidCloud Git](/ja/guides/git/#gitを開く)と[リポジトリを閲覧できるユーザー](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)を参照してください。
- **Cost to Serve と Operational Transfer Pricing のテンプレートは、Common Finance Model の上に構築されます。** **Cost to Serve** からプロジェクトを開始すると、部門ごとに設定した活動とドライバーに基づいて営業費用を顧客に配分し、元帳と紐づいた、顧客ごとの対応コスト控除後のマージンを確認できます。**Operational Transfer Pricing** から開始すると、各エンティティの利益水準（売上高利益率、ネットコストプラス、リセールマイナス）をポリシーの範囲と照らして検証し、範囲外のエンティティを目標に戻すための調整額を確認できます。売上高利益率は、EBIT を検証対象当事者の売上高で割った値です。[Cost to Serve](/ja/guides/projects/cost-to-serve/) と [Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/) を参照してください。
- **OneStream と Anaplan が Data Foundation にデータを供給し、OneStream には読み取りステップがあります。** Data Foundation は、OneStream の連結結果を OneStream 管理者が構築するデータアダプター経由で、Anaplan のプランをエクスポートアクション経由で読み取り、グループの損益計算書をそれらと照合します。新しい **OneStream: Read Adapter** ステップは、連結メンバーごとに 1 回ずつ呼び出してアダプターを読み取り、任意のワークフローでテーブルに書き込みます。[Data Foundation 向けの OneStream](/ja/guides/connections/onestream-for-data-foundation/)、[Data Foundation のソースとしての Anaplan](/ja/guides/connections/anaplan/#data-foundation-のソースとしての-anaplan)、[OneStream: Read Adapter](/ja/reference/workflow-steps/onestream/onestream-read-adapter/) を参照してください。
- **Data Foundation で共通コストの配賦方法を選択できます。** **アクション > Allocations...** では、間接費の部門への配賦と、部門の製品や顧客への配賦について、どのコストを配賦するか、何を基準に配賦するか、どこに配賦するか、ドライバーが負の場合にどうするかを順に設定します。プールされた金額、配賦された金額、未配賦の金額が分かる 1 か月分のプレビューも表示されます。手動で編集したルールは保持されます。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。
- **Data Foundation で数値を説明し、独自の名前を付けられます。** **Explain this number** は、損益計算書の数値を、元帳が保持する金額、配賦によって入ってきた金額と出ていった金額、グループで消去された金額に分け、最大のソースドキュメントとともに、ご自身の行アクセスの範囲で表示します。**Business names** を使うと、カテゴリ、損益計算書の行、メトリック、列に、ビジネスで使っている名前を付けられ、その名前がレポート、メトリック、アシスタントで使われます。[数値の説明](/ja/guides/projects/data-foundation/#数値を説明する)と [Business Names](/ja/guides/projects/data-foundation/#ビジネス名) を参照してください。
- **Data Foundation はロードのたびにボードパックを作成し、以前の状態に戻すこともできます。** **ロード**のたびに、Excel ワークブックと損益計算書ダッシュボードの PDF がドキュメントアカウントのフォルダーに書き込まれます。レポートがオフの場合、パックはワークブックのみで、ダイアログにその旨が表示されます。リストアポイントは各ロードの開始時と、マッピングやソースを変更する前に作成されます。**アクション > Restore...** には、それぞれのリストアポイントで復元されるテーブルの数が表示され、ディメンションを含めてプロジェクトを元に戻します。**Foundation** タブでは、現在の状況がより分かりやすくなりました。実行中の更新や途中で停止した更新を表示し、テーブルのフォルダーがソースにならない理由を示します。また、何かが一致するまで**合計が一致することを確認**を保留のままにし、ステータスの読み取りに失敗しても回復します。更新を適用しても、生成されたステップへの独自の編集は保持され、競合があれば通知されます。[ボードパック](/ja/guides/projects/data-foundation/#ボードパック)と[リストアポイント](/ja/guides/projects/data-foundation/#復元ポイント)を参照してください。
- **Data Foundation プロジェクトをクローンしたり、テンプレートとして保存したりできます。** **アクション > Clone...** は、モデルの編集内容、メトリック、分析パスとともにプロジェクトをコピーします。**Save as my template...** はセットアップをドキュメントアカウントに保存し、**From a template file...** はそれをもとに、接続待ちのソースを持つ新しいプライベートプロジェクトを開始します。[プロジェクトのクローン](/ja/guides/projects/data-foundation/#プロジェクトを複製する)と[マイテンプレートとして保存](/ja/guides/projects/data-foundation/#マイテンプレートとして保存する)を参照してください。
- **Data Foundation のセットアップチェックリストは引き渡しまでカバーし、残った課題はアシスタントで解決できます。** チェックリストに、夜間の更新、エビデンスパック、プロジェクトのオーナーへの引き渡しが加わり、プロジェクトを設定した人も表示されます。タイプのない勘定科目、複数のソースが使用するコード、何にも一致しなかったファイルの列について、アシスタントに回答の提案を依頼できます。アシスタントは何も書き込まず、回答を適用するのはあなたです。[Data Foundation を始める](/ja/guides/projects/data-foundation-getting-started/)と[Ask で未解決の質問を解決](/ja/guides/projects/data-foundation/#ask-で未解決の質問を解決する)を参照してください。

- **モバイルの Weave での音声入力は 1 回のタップで行えます。** マイクをタップして質問すると、話し終えた時点で Weave が送信します。もう一度マイクをタップすると早めに停止でき、何も聞き取れない場合は自動的にオフになります。話している途中で **Weave** タブを離れたり、アプリをバックグラウンドにしたりした場合、話した内容は未送信のまま質問ボックスに残るため、確認できます。実行、一時停止、停止、再開は、確認時の誤ったダブルタップを無視します。アプリバージョン 1.3.0 以降が必要です。[音声を使う](/ja/guides/mobile-app/weave-on-mobile/#音声を使う)を参照してください。

## 変更

- **PlaidCloud の Web アプリと Python クライアントライブラリは REST API を使用し、JSON-RPC は非推奨になりました。** Web アプリは、リクエストを REST API に送信します。`plaidcloud-rpc` 1.25.0 以降では、`SimpleRPC` の呼び出しはコードを変更せずに REST API に送られます。REST API がまだ対応していない呼び出しや、古いリリースのままのワークスペースでは、これまでどおり JSON-RPC が使用されます。JSON-RPC は今後のリリースで削除されるため、スクリプトとノートブックを `plaidcloud-rpc` 1.25.0 以降にアップグレードし、新しい連携は REST API を使用して作成してください。[コマンドライン](/ja/reference/cli/jupyter/command-line/)を参照してください。
- **ステップは、別の環境に固定しない限り、プロジェクトの接続環境に従います。** プロジェクトを QA と本番などの環境間で切り替えると、すべてのステップが切り替わります。1 つの環境にとどめる必要があるステップには、代わりに **Fixed environment** を設定できます。フォームには警告が表示され、ログにはプロジェクトとは異なる環境での各実行が記録されます。プロジェクトを切り替えると、それに従わないステップの名前が示されます。ERP 転記ステップは常にプロジェクトの環境を使用します。プロジェクト、環境を固定したステップ、またはエージェントが使用している間は、環境を削除できません。エージェントフォームのフィールドは **Environment this agent serves** になりました。[ステップを 1 つの環境に固定する](/ja/guides/projects/managing-projects/#ステップを1つの環境に固定する)を参照してください。
- **ステップフォームは 1 つのレイアウトに従います。** タブは標準の名前と標準の順序で、一般、設定、ソース、列、フィルター、出力、詳細設定となり、ERP 転記フォームにはヘッダー列と明細列があります。必須フィールドには * が付き、フォームはステップに必要な項目についてのみ保存をブロックします。
- **プロジェクトのコピーでは、テーブルデータとディメンションメンバーを個別に選択でき、データのコピーが高速になり、プライベートなコピーでは ERP 書き込み承認が保持されます。** **Data to copy** で、**テーブルデータ**（**テーブルデータなし**（デフォルト）、**完全**、**サンプル**）と、それとは別に **Copy dimension members** を選択します。後者はデフォルトでオンのため、テーブルの行を含まないコピーでもディメンションにはメンバーが入った状態で作成され、短時間で完了します。**完全**と**サンプル**のコピーでは複数のテーブルが同時にコピーされるため、テーブル数の多いプロジェクトでも早く完了します。**コピー結果**には、テーブルと並んで各ディメンションの結果が表示され、**Retry failed items** は失敗したテーブルとディメンションをまとめて再試行します。データを含めて作成した新しいコピーは自分専用のプライベートなものになり、コピー元の ERP 書き込み承認のうち、自分で付与できるものが保持されます。コピー元が本番で転記する場合、コピーはシミュレーションの状態で作成されるため、本番に切り替えるまで ERP には何も届きません。REST API と `project_copy` MCP ツールも `dimension_members` を受け付けます。[コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーでの ERP 書き込み承認](/ja/guides/projects/managing-projects/#コピーでのerp書き込み承認)を参照してください。
- **テーブルの詳細パネルに、そのテーブルを使用するステップがより早く表示されます。** 別のテーブルを選択すると、前のテーブルのステップがすぐにクリアされます。このプロジェクトのデータを共有する他のプロジェクトのステップは、パネル全体を待たせることなく、残りの少し後に追加されます。[テーブルの使用場所を確認する](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)を参照してください。
- **行アクションは、すべてのリストで同じように動作します。** 行のメニューは、行の先頭にある **⋯** ボタン、行の右クリック、またはツールバーの**アクション**メニューから開きます。常に**開く**、**詳細**、**編集**が最初に表示され、次にそのリスト独自のアクション、最後に**削除**（Delete）または**削除**（Remove）が表示されます。行に適用できないアクションは、その位置でグレー表示になります。**Enter** と **Del** は、それぞれが実行する項目に表示されます。行のアクションが 1 つだけのリストでは、**⋯** の代わりにそのアクションのアイコンが表示され、ダッシュボード、アプリ、ノートブック には再び**開く**アイコンが表示されます。[行アクションメニュー](/ja/guides/dashboards/using-dashboards/#行アクションメニュー)を参照してください。
- **アプリのタブアイコンは、ライトとダークの両方で統一されたセットになりました。**
- **読み込み画面が新しくなりました。** PlaidCloud は、ライトまたはダークのテーマに合わせた、よりすっきりした読み込み画面で開きます。アイドル状態から復帰する Panel または Dash のアプリは、**開始中**、**準備中**、**アプリを読み込み中**という進行状況を表示し、起動しない場合は、どの段階で停止したかを示して**再試行**を提示します。[Panelアプリの使い方](/ja/guides/panel-apps/using/)を参照してください。
- **検証設定のない保存済みの ERP 書き込みステップは、検証のみの状態で開きます。** 対象は、SAP Post、SAP Attach、NetSuite Post、Oracle EBS の GL と AP の転記、Xero のエクスポートです。本番で実行するよう明示的に設定されたステップは、本番のままです。
- **長時間実行されるジョブは、すべての場所で同じ方法で進行状況を表示します。**
- **ワークフローの停止、失敗、報告が正確になりました。** ワークフローを停止すると、そのワークフローが開始したものがすべて停止し、完了できない実行やステップはハングせずに理由とともに失敗し、実行ステータスは実際に実行された内容と一致します。
  - **ワークフローを停止すると、そのワークフローが開始したものがすべて停止し、完了できない実行やステップはハングせずに失敗します。** 停止すると、待機中のインポートとディメンションのステップがキャンセルされるため、ワークスペース内の後続のインポートやディメンションのロードは通常どおり開始されます。ワークフローの待機中または実行中のコネクター（Singer）の同期も停止します。ステップのジョブを開始できない場合、ステップはいつまでも待機するのではなく、理由とともに失敗します。対象となるのは、約 40 分以内にどのワーカーもジョブを開始しない場合、ワーカーが開始した後にいなくなった場合、ポッドが約 20 分間 Pending のままの場合、イメージを約 5 分間プルできない場合、約 20 分間ポッドが作成されない場合です。約 30 分以内にどのランナーにも取得されないコネクターの同期は、その同期を示すメッセージとともに失敗します。ステップがワーカーを待っている間、ステータスメッセージには経過した分数とともに「Waiting for a worker…」と表示され、作業が開始されると消えます。マクロを停止すると、実行中のすべてのコピーが停止します。一方、1 つのコピーを停止した場合や、応答しなくなったコピーを **Macro Concurrent** ステップが見限った場合は、それを呼び出したワークフローは実行を続けます。他のワークフローの内部でのみ実行されているマクロは、ワークフローリストで**実行中**と表示され、**停止**を利用できます。各ステップのステータス、開始時刻、終了時刻は最新の実行のものが表示されます。サーバーが失われた実行は失敗として終了し、12 時間後もまだ実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」というメッセージで失敗します。[ワークフローの実行](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
  - **再開、実行履歴、実行ステータスは、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローのステップの 1 つを単独で再実行した後でも、子ワークフローに残っていたものがすべて実行されます。1 回の実行内での子ワークフローの各呼び出しには、それぞれ実行履歴のエントリがあります。サーバーが停止したために再開したステップは、ログにその旨が記録されます。`workflow_run_status` と REST API の実行結果は、実行に問題がなかったと報告するのではなく、失敗したものの継続したステップを `continued_step_ids` と `continued_step_count` に一覧表示します。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に継続](/ja/guides/workflows/continue-on-error/)を参照してください。
  - **ステップのエラーには、そのエラー自身のメッセージが表示されます。** PlaidCloud が想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードには、エラーが 1 行で表示され、その後削除されたワークフローの実行は除外されます。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。
  - **完了しない ERP 抽出はそのステップを失敗させ、再開すると続行されます。** **SAP: アドホック抽出**が行数または時間の上限で一時停止した場合や、エージェントが時間内に応答しない場合、あるいは Salesforce、Oracle Fusion の一括エクスポート、HFM/FCCS のエクスポートのジョブが、ステップが待機をやめた時点でまだ実行中の場合は、ステップが失敗するため、後続のステップが不完全なテーブルに対して実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は停止した場所から同じジョブで続行されます。[実行の制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)を参照してください。
  - **エクスポートをキャンセルすると、ウェアハウスでそのクエリが停止します。** エクスポートまたはダウンロードがキャンセルされた場合（ワークフローの停止によるものを含む）、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplum では、そのデータを読み取るクエリも停止します。リモートデータベースへのエクスポートは、最後まで実行されるのではなく、ソースの読み取りを停止します。
- **REST、Import REST、Import Postman のステップは、ワークスペースのアップグレード時に RESTリクエストに変換されます。** きれいに変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **セッションの有効期限が切れた後に開いたダッシュボードのリンクは、サインイン後にそのダッシュボードに移動します。** [ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは、認識できないフィールドを拒否します。** 無視するのではなく、エラーでそのフィールド名を示します。`workflow_upsert` は `memo` を受け付け、その別名として `description` も受け付けます。[不明なフィールドは拒否される](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2 では、Lakehouse が Parquet のエクスポートを Google Cloud Storage に直接書き込みます。** Google Cloud Storage のドキュメントアカウントへのエクスポートは、すべての行がいったん PlaidCloud を経由するのではなく、アカウント自身の認証情報で書き込まれ、アカウントのバケットに直接送られます。Amazon S3 と Azure Blob Storage のアカウントへのエクスポートは、これまでどおりに動作します。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/) を参照してください。
- **Slack、Microsoft Teams、Web Hook のステップは、メッセージが送信されなかった理由を示します。** ステップのエラーには、接続しようとしたサーバーと、Slack と Teams の場合は接続が示され、何が問題だったかが説明されます。たとえば、Slack が Webhook を認識しなくなった、チャンネルに投稿できない、サーバーが見つからないか 60 秒以内に応答しない、接続が削除された、などです。Slack や Teams の Webhook URL を知っていれば誰でもその連携として投稿できるため、Webhook URL は表示されません。[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/) を参照してください。
- **プロジェクトのサービスアカウントのアクセストークンは、少なくとも 24 時間有効です。** UDF ステップなど、プロジェクトとして実行されるワークフローのジョブは、24 時間有効なトークンを取得します。これより短い有効期間はワークスペースのアップグレード時に引き上げられ、設定済みのより長い有効期間は保持されます。
- **ワークスペースの組織、オーナー、リリース、バージョンは PlaidCloud が設定し、データセンターは自分で選択します。** コントロールプレーンで作成したワークスペースはあなたがオーナーとなり、PlaidCloud が設定したリリースチャネルに配置されます。**Data Center** は、サインアップ時に提供されるリージョンから選択します。ワークスペースを編集するとき、組織、オーナー、リリース、バージョンは読み取り専用です。バージョンを変更するには **Set Version** を使用し、ワークスペースの移動、オーナーやチャネルの変更、固定については PlaidCloud サポートに依頼してください。[ワークスペースの構成](/ja/administration/control-plane/workspace-configuration/#基本設定)を参照してください。

## 修正

- **無効なプロジェクト設定が、分かりやすいメッセージで報告されます。** 不明な環境やドキュメントアカウント、使用済みまたは予約済みのスラッグ、無効なストレージタイプや転記モードに対して、汎用のサーバーエラーではなく、問題を示すメッセージが返されるようになりました。REST API では 500 ではなく 400 が返され、AI アシスタントまたは MCP では無効な引数のエラーになります。
- **REST API のディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして処理され、無効として拒否されていました。現在は `value_columns` の各列について集計された値を 1 つずつ返します。グリッド（行フィルターと列フィルターの組み合わせごとに 1 つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **時間のかかるテーブルの読み取りやファイル処理が、他のリクエストを妨げなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundation のファイルの登録、Excel へのエクスポート、REST または SOAP のインポートのレスポンスの読み取り、ドキュメントアカウントの使用場所の検索、Panelアプリのコードやロゴのチェックは、それぞれ完了するまで、同じサーバーが処理している他のすべてのリクエストを止めてしまうことがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクトとワークフローの変数ダイアログがスクロールします。** 小さい画面や低い解像度では、追加と編集のダイアログがウィンドウより高くなり、**作成**ボタンと**更新**ボタンを操作できないことがありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storage のドキュメントアカウントで、256 MiB を超えるファイルをコピー、移動、名前変更できます。** 以前は、このサイズのファイルではこれらの操作がいずれも失敗し、そのようなファイルを含むフォルダーの移動や名前変更も失敗していました。
- **Lakehouse v2 では、テーブルの行数が書き込まれた直後の内容を反映します。** テーブルに書き込んだステップやインポートが書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが 0 行と表示されたり、インポートで 0 行がインポートされたと報告されたりしていました。現在は、新しい行がすべての場所で参照できるようになってから行数が読み取られるため、後続のステップもそれらの行を読み取れます。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりした場合も、行数と列数が更新されます。
- **Weave の空値チェックは、各実行を、以前の実行が実際に残した内容と比較します。** ステップの空値は、ステップがテーブルを再投入するために空にした直後に数えられることが多く、そのため以前の実行には空値がなかったように見え、常に一部が空だった列が、最近そうなったかのように報告されていました。現在は、ステップがテーブルを残した状態で各実行が数えられます。以前に記録された件数は正しいものと区別できないため使用されません。各ステップの空値チェックは履歴を最初からやり直し、5 回の実行が数えられるまでは未チェックとして報告されます。行数と値の分布のチェックも、ステップの完了から 2 秒を超えて別のステップが同じテーブルに行った書き込みを、そのステップによるものとして扱わなくなりました。[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **Data Foundation は、反転した為替レートと小数のしきい値の精度を保持します。** 為替レートが報告通貨から別の通貨へのレートとして提示されているために PlaidCloud が反転したレートは、小数第 6 位に丸められることがあり、インドネシアルピアのようにレートの小さい通貨の金額が約 1% ずれていました。反転したレートは小数第 12 位まで保持されるようになりました。また、`0.5` のように小数を含む `group_amber` または `group_red` のしきい値は、整数に丸められていました。次回のロードから正確な値が使用されます。[為替レート](/ja/guides/projects/data-foundation/#為替レート)を参照してください。
- **無効化されたメンバーのアラートとダイジェストが停止します。** オーナーが無効化された Panelアプリのアラートやダイジェストが、チェックと送信を続けていました。現在は、オーナーが無効化されている間は一時停止し、再度有効化されると再開します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
- **削除された接続を REST API で要求すると 404 が返されます。** 削除された接続や存在しない ID を要求すると、汎用のサーバーエラー（500）が返されていました。現在は、接続 ID を示すメッセージとともに 404 が返されます。
- **テンプレートを使ったテーブルのエクスポートが、AI アシスタントと MCP で動作します。** `table_data_export` の `templated` 形式は、テーブルを指定すると必ず失敗していました。現在は、読み取り可能な行に限定して、テンプレートを使ってテーブルをエクスポートします。テンプレートでは、テーブルの行は、テーブル ID の `-` を `_` に置き換えた名前で参照します。
- **Amazon S3 および S3 互換のドキュメントアカウントで、リージョンが保持されます。** これらのアカウントを保存すると、入力した**リージョン**が破棄されていたため、次にアカウントを開いたときにフィールドが空になっていました。現在はリージョンが保存されます。この修正より前に保存したアカウントでは、リージョンをもう一度入力して保存してください。[AWS S3 アカウントの追加](/ja/guides/documents/adding-accounts/add-aws-s3-account/)を参照してください。

## セキュリティ

- **パスワードによるサインインには認証アプリが必要になり、パスワードが強化されました。** PlaidCloud のパスワードでサインインするメンバーは、次回のサインイン時に認証アプリの設定を求められ、それ以降は毎回そのコードを入力します。シングルサインオン、Google、Microsoft、GitHub でのサインイン、API トークン、サービスアカウントは変わりません。新しいパスワードは 12 文字以上で、ユーザー名や直近 6 回のパスワードと同じにはできません。サインインの失敗が繰り返されると、アカウントは短時間ロックされます。ワークスペースですでに設定されている、より厳しいルールは保持されます。[メンバー認証](/ja/administration/access/member-authentication/)を参照してください。
- **接続が指すのは、パブリックアドレスとプライベートネットワークのアドレスです。** 接続にループバック、リンクローカル、クラウドメタデータのアドレスを指定することはできず、エラーにはホストと解決されたアドレスが示されます。プライベートネットワーク上のアドレスは影響を受けません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続が到達できないアドレス)を参照してください。
- **保存された接続の認証情報は、接続やワークフローを編集できるメンバーにのみ表示されます。** REST API と MCP では、保存された接続のパスワード、トークン、キーは他のメンバーに対してマスクされますが、それらのメンバーも接続を開いて参照できます。[接続の認証情報を閲覧できるユーザー](/ja/guides/connections/create-connection/#接続の資格情報を見られるユーザー)を参照してください。
- **アプリのビルドは、ワークスペースの Git 認証情報にアクセスせずに実行されます。**
- **エージェントの秘密鍵は、エージェントを編集できるメンバーにのみ表示されます。** 鍵は、REST API と MCP のエージェントのリストや詳細には表示されなくなり、エージェントフォームでは、エージェントを編集できるメンバーにのみ**秘密鍵**と**RPC構成を表示**が表示されます。サービスアカウント、プロジェクトとエージェントのトークン、AI に委任されたトークンでは、鍵や RPC 構成を取得できません。実行中のエージェントは影響を受けず、公開鍵は引き続き表示されます。[エージェントの認証情報の取得](/ja/reference/cli/plaidlink/agents/#エージェントの認証情報の取得)を参照してください。
- **プロキシダウンロードのリンクは 1 時間有効です。** **Use PlaidCloud Proxy Download** がオンの場合、リンクの有効期限が切れたら、ダウンロードを開き直して新しいリンクを取得します。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)を参照してください。
- **セキュリティグループへのユーザーの追加は、保有する権限に従います。** メンバーをセキュリティグループに追加したり、メンバーのグループを選択したり、アーキテクトを招待したりできるのは、そのグループが付与するすべての権限を保有している場合です。ワークスペース管理者は制限されません。[セキュリティグループの管理](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)を参照してください。
- **接続の設定の変更とオン・オフの切り替えは、接続のオーナーまたはワークスペース管理者が行います。** REST API、JSON-RPC、AI アシスタントまたは MCP で接続の設定を変更するには、その接続のオーナーの 1 人であるか、オーナーのいない接続の場合はワークスペース管理者である必要があります。接続の有効化、無効化、ロック、ロック解除にはオーナーまたはワークスペース管理者の権限が必要で、複数の接続を指定したリクエストは、そのすべてを変更できる場合にのみ適用されます。ワークスペースのデフォルトの AI 接続を選択できるのはワークスペース管理者だけです。メンバーが所有する接続がデフォルトになるのは、管理者が所有する接続またはオーナーのいない接続がデフォルトになれない場合だけです。[接続の編集](/ja/guides/connections/create-connection/#接続を編集する)と [LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **行アクセスは、メンバーが制限されたテーブルに対して行うすべての操作に適用されます。** メンバーは、ダッシュボード、自分の SQL、ロードのいずれにおいても、付与された行だけを閲覧および変更できます。
  - **プロジェクトのアーキテクトは、ダッシュボードで、行が制限されたテーブルのすべての行を閲覧できます。** これは Analyze で閲覧できる内容と一致します。アーキテクトのアクセス権の削除は、ダッシュボードにすぐに反映されます。ユーザーのロールを変更した場合、ユーザーやそのグループをプロジェクトから削除した場合、プロジェクトのアクセスの種類を変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれも同様です。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
  - **行アクセスで制限されたメンバーも、自分の SQL クエリを実行し、結果をエクスポートできます。** 行アクセスのあるプロジェクトでは、アーキテクトではないメンバーは、クエリ画面での自分のクエリから付与された行だけを取得し、**アクセス権により行が制限されています**という通知とともに CSV、Excel、JSON にエクスポートできます。以前は、これらは拒否されていました。パーセント記号（`%`）を含む付与値も、クエリ画面でその行を返すようになり、そのようなクエリを CSV としてダウンロードすることもできます。Snowflake や Databricks での自分の自由形式の SQL、Postgres 系ウェアハウスでの自分の SQL のエクスポート、スナップショット時点でのガバナンス対象テーブルの読み取りは引き続き拒否されます。また、ビューでフィルターを適用するには、ガバナンス対象の列を元の名前のまま保持する必要があります。[行アクセスと自分で書くクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスとご自身で記述するクエリ)を参照してください。
  - **行アクセスを保存しても、ソースにない付与値は保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がない場合、ディメンションにそのメンバーがない場合、またはリストにその値がない場合でも、マーク付きでグリッドに残ります。**保存**すると、そのような値ごとに保持するか削除するかを確認されます。[行アクセスのグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
  - **行が制限されたテーブルへの DataFrame の書き込み、レコードの保存、クリアは、閲覧できる行だけを変更します。** 行アクセスによって行が制限されている場合、Python クライアントで制限されたテーブルに DataFrame を書き込んだりクリアしたりしたとき、または REST API でレコードを保存したりクリアしたりしたときは、自分の行だけが変更されます。アクセス範囲外の行を含むロードは、何も変更されないうちに、見つかった値を示して拒否されます。プロジェクトのアーキテクト、すべての行を閲覧できるメンバー、ワークフローの実行は、テーブル全体に書き込みます。ユーザーが任意のテーブルに対して行うこれらの書き込みは、すべてセキュリティログに記録されます。[制限されたテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
  - **行が制限されたテーブルに対するインポート、コピー、復元、削除には、すべての行を閲覧できる必要があります。** 行アクセスによって行が制限されている場合、制限されたテーブルへのファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えまたはマージ、復元、削除、削除後の復元、その他テーブル全体を置き換える操作は、テーブルのすべての行を閲覧できる場合にのみ実行されます。それ以外の場合は拒否され、何も変更されません。REST API でテーブルの行を保存すると、他のロードと同様に、自分の行だけが変更されます。プロジェクトのアーキテクト、すべての行を閲覧できるメンバー、ワークフローの実行は影響を受けず、これらの操作もセキュリティログに記録されます。[制限されたテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
- **以前のバージョンを復元できるのは、アカウントのオーナーだけです。** ドキュメントアカウントを以前のバージョンに復元する、バージョンを保持または解放する、バックアップを取得するには、そのアカウントのオーナーの 1 人である必要があり、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、そのアカウントへのアクセス権が必要です。
- **`query_run` は読み取り専用のステートメントを実行します。** AI アシスタントと MCP クライアントが使用する `query_run` ツールは、1 つの SELECT または WITH ステートメント、そのステートメントの EXPLAIN、または SHOW を受け付け、それ以外のステートメントは実行されません。データを変更するには `query_transform` を使用してください。MCP のテーブルエクスポートの SQL にも同じルールが適用されます。REST API と JSON-RPC API では、プロジェクトのデータを変更できないメンバーに対して、クエリの実行、列ファセットの作成、クエリの CSV としてのダウンロード、クエリのリモートデータベースへのエクスポート、独自のクエリによるテーブルデータのエクスポートにもこのルールが適用され、拒否されたクエリは 403 を返します。Explain Analyze は測定のためにクエリを実行するため、クエリログと Lakehouse では読み取りを行うクエリだけを受け付けます。行アクセスのあるプロジェクトでは、クエリログから Explain Analyze を実行できるのはプロジェクトのアーキテクトだけです。
