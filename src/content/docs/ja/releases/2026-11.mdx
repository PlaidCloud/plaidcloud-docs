## 追加

- **PlaidXLでExcel上のレポート作成、ドリル、数値の説明、計画ができます**。**PlaidCloud**リボンタブは**接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有**にグループ化されています。よく使うコマンドは**PlaidXL**の右クリックメニューと**PlaidXL Cell**タブにもあり、主なコマンドには変更可能なキーボードショートカットがあります。サインイン前にコマンドを実行するとサインインが開き、サインイン後に一度だけ実行されます。Office で Microsoft Entra の職場アカウントを使っている場合、PlaidXLがワークスペースを自動的に見つけます。詳しくは[PlaidXLリファレンス](/ja/reference/cli/plaidxl/)をご覧ください。
  - **数回のクリックでレポートを作成できます**。**レポート**タブは、テーブルから、行方向に1つのディメンションを、列方向に別のディメンションをドリルダウンしたライブレポートをレイアウトし、各交点に`CELL`値を配置します。**Build my first report**では、お使いのデータからサンプルを作成します。ドリルすると、レポートは行や列全体を挿入または削除し、入力した値、メモ、書式は該当する行に付随したままになります。詳しくは[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)をご覧ください。
  - **任意のセルからドリルできます**。**Drill down**、**Drill up**、**Keep only**、**Remove only**は、ノード、ディメンション見出し、レポート値からノードをライブの`DRILL`数式に変換し、編集まで行います。**Custom drill**は挿入前に行をプレビューし、メンバーピッカーはメンバーを挿入したり、ノードの子のドロップダウンをセルに追加したりします。`DRILL`は除外または展開するノードを指定でき、行をまたいで実行することもできます。詳しくは[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)をご覧ください。
  - **数値を説明できます**。**Explain this number**は、値の計算内容、PlaidCloudの現在の値と一致するかどうか、およびその元になっているテーブルとワークフローステップを表示します。**Show detail rows**は、値の根拠となる行を専用のシートに表示し、合計が一致するかのチェックも行います。
  - **Excelでガバナンス済みのメトリックを利用できます**。`PLAIDXL.METRIC`と`PLAIDXL.METRIC_BREAKDOWN`は、ダッシュボードに表示されるのと同じビジネスメトリックを返します。**Metric...** コマンドは、プロジェクトのメトリックを現在の値とともに一覧表示します。詳しくは[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)をご覧ください。
  - **レポートに直接入力して計画できます**。`CELL`値に数値を上書き入力すると、PlaidCloudに書き込まれます。比例配分、均等配分、別のメンバーの形に合わせた配分、金額またはパーセンテージによる調整が可能で、保持したセルは変更されません。平均、中央値、最小値、最大値、標準偏差、分散のセルにも入力した値を指定できます。**Undo last write**は、入力した値と保存を新しいものから順に取り消します。詳しくは[PlaidCloudへの値の入力](/ja/reference/cli/plaidxl/write-values/)をご覧ください。
  - **必要な部分だけを更新できます**。シート、選択範囲、またはすべてのテーブルを更新でき、タスクペインには各テーブルの進行状況と**キャンセル**が表示されます。PlaidXLの数式だけを再計算することもできます。取得したテーブルはデータ型に応じて書式設定されたExcelテーブルとして届き、更新しても独自の列や数値書式は保持され、元の場所で更新されます。テーブルを再取得しても更新リストに二重に追加されることはなく、**Stop refreshing**でリストから外せます。ディメンションもテーブルと一緒に更新されます。詳しくは[すべてのテーブルを更新](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)をご覧ください。
  - **保存はすぐに書き込まれ、元に戻せます**。**Save to PlaidCloud**は確認なしで書き込み、実行内容を伝え、**元に戻す**を提示します。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセスできないユーザーの場合は、該当する行だけが置き換えられるため、他のユーザーの行は保持されます。詳しくは[テーブルをPlaidCloudに保存](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)をご覧ください。
  - **Excel上でWeaveに質問できます**。**Weave**タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼するか、**Ask Weave about this cell**を選択します。WeaveはあなたとしてPlaidCloudを読み取り、変更するのはワークブックのみです。入力済みの内容を置き換える前に確認し、各変更はペインを再読み込みするまで元に戻せます。詳しくは[ExcelでWeaveに質問](/ja/reference/cli/plaidxl/weave/)をご覧ください。
  - **1つのシートまたはワークブック全体の値のみのコピーを共有できます**。**Convert to values**は、ワークブック全体、1つのシート、または元に戻せない値のみに変換します。また、シート名を変更した後でも**Restore PlaidXL formulas**を使用できます。
- **ステップフォームでプレビューできます**。インポート: SQL、Execute: SQL、SQL抽出、エクスポート: SQL、Salesforce Queryの各ステップは、ステップを実行せずに最大100行を表示します。Anaplanのビューとリストの読み取りは、生成される列と型を表示します。**ソース**タブで**プレビュー**をクリックします。変数は実行時と同じように補完されますが、`{x:>9}`のような変数の書式指定には対応していません。プレビューで実行できるのは標準のSQL関数のみで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトや、エージェントベースのExecute SQLステップでは利用できません。詳しくは[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と[SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)をご覧ください。
- **利用状況レポートで変化を確認し、グループで絞り込み、ワークフローに連携できます**。**概要**には、前の期間と比較した傾向を示す矢印と、非アクティブなメンバーや誰も開いていないダッシュボードおよびアプリを示す**Highlights**リストが加わりました。**グループ**を使うと、**概要**、**内容**、非アクティブ一覧を1つのセキュリティグループのメンバーに限定できます。日付範囲には**Previous month**と**This month**が加わり、すべてのタブで共有され、アカウントごとに記憶されます。すべての数値に説明が付き、テーブルには**メンバー**や**Area**のようなわかりやすい名前が使われ、行はEnterキーで開き、読み込み中の表示とエラーもわかりやすくなり、最後の**ファネル**ステップには完了したメンバーの数が表示されます。新しいGet Workspace Usageステップは、日次または月次の利用状況の合計をスケジュールに従ってテーブルに書き込みます。メンバー名は含まれず、Get Workspace Membersステップと同様に、各実行は**セキュリティログ**に記録されます。詳しくは[利用状況レポート](/ja/administration/access/usage-reports/)と[Get Workspace Usage](/ja/reference/workflow-steps/general/get-workspace-usage/)をご覧ください。
- **AIアシスタントがテーブルの非公開化とプロジェクトのデフォルトのダッシュボードオーディエンスの設定を行えます**。`publish_manage`は、テーブルを、公開済みビューおよびどのチャートでも使われていないダッシュボードデータセットとともに非公開にします。チャートがまだ使用しているデータセットは残り、レポートビューが公開済みビューを基に作られている場合は、そのビューとデータセットも残りますが、テーブルは非公開になります。`project_upsert`は`dashboard_default_audience`、つまりプロジェクトの新しいダッシュボードの共有先グループを設定し、`[]`でクリアします。詳しくは[非公開化](/ja/guides/data/publish/#ai-アシスタントまたは-mcp-で公開を取り消す)と[AIアシスタントまたはMCPによるデフォルトオーディエンスの設定](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ai-アシスタントまたは-mcp-でデフォルトの対象ユーザーを設定する)をご覧ください。

- **モバイルのWeaveでは、音声入力がワンタップで使えます**。マイクをタップして質問を話すと、話し終えたところでWeaveが送信します。もう一度マイクをタップすると途中で停止し、何も聞き取れなかった場合は自動的にオフになります。文の途中で**Weave**タブを離れたりアプリをバックグラウンドにしたりすると、話した内容は送信されずに質問ボックスに残るので、確認できます。実行、一時停止、停止、再開の確認操作では、誤ってダブルタップしても無視されます。アプリのバージョン1.3.0以降が必要です。詳しくは[音声を使う](/ja/guides/mobile-app/weave-on-mobile/#音声を使う)をご覧ください。

## 変更

- **ステップフォームのレイアウトが統一されました**。タブの名前と順序が標準化され、全般、設定、ソース、列、フィルター、出力、詳細設定の順になり、ERP転記フォームにはヘッダー列と明細列があります。必須フィールドには*が付き、フォームはステップに必要な項目についてのみ保存をブロックします。
- **プロジェクトのコピーでは、テーブルデータとディメンションメンバーを別々に選択でき、データのコピーが高速になり、非公開コピーではERP書き込み承認が引き継がれます**。**Data to copy**で、**テーブルデータ**として**テーブルデータなし**（デフォルト）、**完全**、**サンプル**のいずれかを選択し、これとは別に**Copy dimension members**（デフォルトでオン）を選択します。そのため、テーブルの行を含まないコピーでも、ディメンションにメンバーが入った状態で作成され、短時間で完了します。**完全**と**サンプル**のコピーは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも短時間で完了します。**コピー結果**には、テーブルと並んで各ディメンションの結果が一覧表示され、**Retry failed items**は失敗したテーブルとディメンションをまとめて再試行します。データ付きで作成した新しいコピーはあなた専用の非公開となり、コピー元のERP書き込み承認のうち、あなた自身が付与できるものが引き継がれます。コピー元がLiveで転記する場合、コピーはSimulateで作成されるため、Liveに切り替えるまでERPには何も届きません。REST APIと`project_copy` MCPツールも`dimension_members`を受け付けます。詳しくは[コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーに含まれるERP書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認)をご覧ください。
- **行アクションメニュー**（⋯）**がすべてのグリッド行の左端に表示されます**。
- **検証設定のない保存済みのERP書き込みステップは、検証のみとして開きます**。対象はSAP Post、SAP Attach、NetSuite Post、Oracle EBS GLおよびAP Post、Xeroエクスポートです。明示的にライブ実行に設定されているステップはライブのままです。
- **長時間実行されるジョブの進行状況が、どこでも同じ方法で表示されます**。
- **ワークフローを停止すると開始したすべてが停止し、完了できない実行やステップはハングせずに失敗します**。停止すると、キューに入ったままのインポートとディメンションのステップがキャンセルされるため、ワークスペース内の後続のインポートやディメンションのロードは通常どおり開始されます。ワークフローのキュー中または実行中のコネクタ（Singer）同期も停止します。ステップのジョブを開始できない場合、ステップは永遠に待ち続けるのではなく、理由とともに失敗します。理由は、約40分以内にどのワーカーも開始しなかった、ワーカーが開始した後に消えた、ポッドが約20分間Pendingのままになっている、イメージを約5分間取得できない、約20分間ポッドが作成されない、のいずれかです。どのランナーも約30分以内に取得しないコネクタ同期は、その同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間、ステータスメッセージには経過した分数とともに「Waiting for a worker…」と表示され、作業が始まると消えます。マクロを停止すると、実行中のすべてのコピーが停止します。他のワークフローの中でのみ実行されているマクロは、ワークフロー一覧に**実行中**と表示されて**停止**を使用でき、各ステップの最新の実行におけるステータス、開始時刻、終了時刻が表示されます。サーバーが失われた実行は失敗として終了し、12時間後もまだ終わっていない実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」というメッセージとともに失敗します。詳しくは[ワークフローの実行](/ja/guides/workflows/run-a-workflow/#開始されないステップ)をご覧ください。
- **再開、実行履歴、実行ステータスが、実際に実行された内容と一致します**。親ワークフローを再開すると、子ワークフローのステップの1つを単独で再実行した後でも、子ワークフローに残っていたすべてが実行されます。また、1回の実行の中での子ワークフローの呼び出しごとに、個別の実行履歴エントリが作成されます。サーバーが停止したために最初からやり直されたステップは、ログにその旨が示されます。`workflow_run_status`とREST APIの実行結果は、実行を問題なしと報告するのではなく、失敗したものの続行したステップを`continued_step_ids`と`continued_step_count`に一覧表示します。詳しくは[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に続行](/ja/guides/workflows/continue-on-error/)をご覧ください。
- **ステップのエラーには、そのエラー自体のメッセージが表示されます**。PlaidCloudが想定していなかったエラーは「The step stopped on an unexpected error (*type*): *message*」と表示されます。ランチャーの**要対応**カードには、エラーが1行で表示され、その後に削除されたワークフローの実行は含まれません。詳しくは[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)をご覧ください。
- **完了しないERP抽出はステップを失敗させ、再開で続行できます**。**SAP: アドホック抽出**が行数または時間の制限で一時停止した場合やエージェントが時間内に応答しなかった場合、またはSalesforce、Oracle Fusionのバルク、HFM/FCCSのエクスポートジョブが、ステップが待機を終えた時点でまだ実行中の場合、ステップは失敗するため、後続のステップが不完全なテーブルで実行されることはありません。ワークフローを再開するか、ステップを再実行すると、抽出は同じジョブで、停止した箇所から続行します。詳しくは[実行の制限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と[Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合)をご覧ください。
- **REST、Import REST、Import Postmanの各ステップは、ワークスペースのアップグレード時にRESTリクエストステップに変換されます**。きれいに変換できないステップは元のまま残ります。詳しくは[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)をご覧ください。
- **プロジェクトのアーキテクトは、行が制限されたテーブルのすべての行をダッシュボードで確認できます**。これはAnalyzeでの表示と同じです。アーキテクトのアクセス権を取り消すと、ダッシュボードにも即座に反映されます。ユーザーのロールを変更した場合、そのユーザーやグループをプロジェクトから削除した場合、プロジェクトのアクセスタイプを変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれも同様です。元アーキテクトは、行が制限されたデータのすべての行を見ることはなくなります。詳しくは[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)をご覧ください。
- **セッションの有効期限が切れた後にダッシュボードのリンクを開くと、サインイン後にそのダッシュボードが表示されます**。詳しくは[ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)をご覧ください。
- **MCPツールは、認識できないフィールドを無視せずに拒否し**、エラーでそのフィールド名を示します。`workflow_upsert`は`memo`を受け付け、その別名として`description`も受け付けます。詳しくは[不明なフィールドは拒否されます](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)をご覧ください。
- **Lakehouse v2では、LakehouseがParquetエクスポートをGoogle Cloud Storageに直接書き込みます**。Google Cloud Storageのドキュメントアカウントへのエクスポートは、すべての行がいったんPlaidCloudを経由するのではなく、アカウント自身の認証情報で書き込まれ、アカウントのバケットに直接送られます。Amazon S3およびAzure Blob Storageアカウントへのエクスポートは従来どおり動作します。詳しくは[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/)をご覧ください。
- **Slack、Microsoft Teams、Web Hookの各ステップが、メッセージが送信されなかった理由を示します**。ステップのエラーには、接続を試みたサーバーと、SlackとTeamsの場合は接続が示され、何が問題だったかがわかります。たとえば、Slackがウェブフックを認識しなくなった、チャンネルに投稿できない、サーバーが見つからないか60秒以内に応答しない、接続が削除された、などです。SlackまたはTeamsのウェブフックURLは、それを知っていれば誰でもあなたの連携として投稿できてしまうため、表示されることはありません。詳しくは[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/)をご覧ください。

## 修正

- **無効なプロジェクト設定が、わかりやすいメッセージで報告されます**。不明な環境またはドキュメントアカウント、使用済みまたは予約済みのスラッグ、無効なストレージタイプまたは転記モードに対して、汎用的なサーバーエラーではなく、問題を示すメッセージが返されるようになりました。REST APIでは500ではなく400、AIアシスタントまたはMCPでは無効な引数のエラーになります。
- **REST APIのディメンション値リクエストが動作するようになりました**。`POST /rest/v1/analyze/query/retrieve-dimension-values`はグリッドリクエストとして処理され、無効として拒否されていました。現在は`value_columns`の各列について集計された値を1つ返します。また、行フィルターと列フィルターの組ごとに値を1つ返すグリッドには、専用の`POST /rest/v1/analyze/query/retrieve-dimension-cells`があります。
- **テーブルの読み取りやファイル処理が遅くても、他のリクエストが待たされなくなりました**。ウェアハウスからのテーブルの列の読み取り、Data Foundationファイルの登録、Excelへのエクスポート、RESTまたはSOAPインポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panelアプリのコードやロゴのチェックは、それぞれ完了するまで同じサーバーが処理している他のすべてのリクエストを止めることがありました。現在はそれらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールするようになりました**。小さい画面や低い解像度では、追加と編集のダイアログがウィンドウより高くなり、**作成**ボタンや**更新**ボタンに手が届かないことがありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storageのドキュメントアカウントで、256 MiBを超えるファイルのコピー、移動、名前の変更ができるようになりました**。これまで、このサイズのファイルではいずれも失敗し、そのようなファイルを含むフォルダーの移動や名前の変更も失敗していました。
- **Lakehouse v2では、テーブルの行数に書き込んだ直後の内容が反映されます**。テーブルに書き込んだステップやインポートが書き込み前の行数を記録することがあり、読み込んだばかりのテーブルが0行と表示されたり、インポートが0行インポートと報告されたりしていました。現在は、新しい行がすべての場所から見えるようになってから行数を読み取るため、後続のステップもそれらの行を読み取れます。テーブルを別のブランチに切り替えた場合や、ブランチをテーブルにマージした場合も、行数と列数が更新されます。
- **Weaveの空値チェックは、過去の実行が実際に残した状態と各実行を比較します**。ステップの空値は、ステップがテーブルを空にして再投入した直後に数えられることが多く、そのため過去の実行には空値がないように見え、常に一部が空だった列が、たった今そうなったかのように報告されていました。現在は、ステップがテーブルを残した状態で各実行が数えられます。以前に記録されたカウントは正しいものと区別できないため使用されません。各ステップの空値チェックは履歴を最初からやり直し、5回の実行が数えられるまで未チェックとして報告されます。行数と値の分布のチェックも、ステップが終了してから2秒を超えて別のステップが同じテーブルに行った書き込みを、そのステップの書き込みとして扱わなくなりました。詳しくは[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)をご覧ください。
- **削除された接続をREST APIに要求すると404が返されます**。削除された接続や存在しないIDを要求すると、汎用的なサーバーエラー（500）が返されていました。現在は、接続IDを示すメッセージとともに404を返します。

## セキュリティ

- **行アクセスを保存しても、ソースにもうない付与済みの値が保持されるようになりました。** セキュリティグループに付与された値は、テーブルにその値の行がなくなった、ディメンションからメンバーが失われた、またはリストからその値がなくなった場合に、次の保存で付与から外れていました。その結果チェックが1つもなくなったグループは**Everyone else**にフォールバックし、すべての行が表示される場合がありました。現在はその値に印が付いたままグリッドに残り、**保存**時に保持するか削除するかを確認します。[行アクセスのグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
- **アカウントの以前のバージョンを復元できるのは、そのアカウントのオーナーのみです**。ドキュメントアカウントを以前のバージョンに復元する操作、バージョンの保持または解除、バックアップの作成には、アカウントのオーナーである必要があり、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を表示するには、アカウントへのアクセス権が必要です。
- **データの読み取りだけを行うべきクエリが、データを変更できなくなりました。** AI アシスタントと MCP クライアントが使用する `query_run` ツールは、データを読み取るステートメント（SELECT または WITH ステートメント 1 つ、その EXPLAIN、または SHOW）だけを実行し、それ以外は実行せずに拒否します。データを変更するには `query_transform` を使用してください。MCP のテーブルエクスポートの SQL にも同じルールが適用されます。REST API と JSON-RPC API では、プロジェクトのデータを変更できないメンバーに対して、クエリの実行、列ファセットの作成、クエリの CSV としてのダウンロード、リモートデータベースへのクエリのエクスポート、独自のクエリによるテーブルデータのエクスポートにも同じルールが適用され、拒否されたクエリは 403 を返します。Explain Analyze は計測のためにクエリを実行するため、クエリログとレイクハウスでは読み取りを行うクエリだけを受け付けるようになりました。また、行アクセスが設定されたプロジェクトでは、クエリログから実行できるのはプロジェクトの Architect だけです。
