## 追加

- **コントロールプレーンの Trust Center で、セキュリティチームが PlaidCloud のセキュリティ関連ドキュメントを入手できます。** 管理者とセキュリティ担当のユーザーは、組織の **Trust Center** を開き、サブプロセッサー一覧や DPA などの公開ドキュメントをすぐにダウンロードできます。SOC 2 Type II レポートなどの制限付きドキュメントは、組織として一度だけセキュリティ関連ドキュメントの NDA に署名すると利用できるようになります。ほかの管理者とセキュリティ担当のユーザーには、署名者と署名日時が表示されます。契約にすでに NDA が含まれている組織では、NDA を締結済みとして登録しておくことで、署名なしでドキュメントを利用できます。制限付きドキュメントのダウンロードには透かしが入り、記録も残ります。NDA の新しいバージョンは、あらためて承諾する必要があります。[Trust Center](/ja/administration/control-plane/trust-center/) を参照してください。
- **PlaidXL は Excel でレポートの作成、ドリル、数値の説明、計画ができます。** **PlaidCloud** リボンタブは **接続**、**挿入**、**更新**、**Drill**、**書き込み**、**共有** にグループ分けされました。よく使うコマンドは **PlaidXL** の右クリックメニューと **PlaidXL Cell** タブにもあり、主なコマンドには変更可能なキーボードショートカットがあります。ショートカットはフィールドに入力している間は動作しません。コマンドが失敗した場合は、どのコマンドがなぜ失敗したかが表示されます。サインインする前に実行したコマンドはサインインを開始し、サインイン後に一度だけ実行されます。サインインは 1 つのワークスペースに対して有効なため、ワークスペースを切り替えると新しいワークスペースへのサインインを求められます（元に戻すときは不要です）。Office で Microsoft Entra の職場アカウントを使っている場合、PlaidXL がワークスペースを自動で見つけます。[PlaidXL リファレンス](/ja/reference/cli/plaidxl/)を参照してください。
  - **数回のクリックでレポートを作成できます。** **レポート** タブは、テーブルからライブレポートを作成します。1 つのディメンションを行方向にドリルダウンし、別のディメンションを列方向に配置し、交差する位置すべてに `CELL` 値を置きます。**Build my first report** は、お使いのデータからサンプルを作成します。ドリルすると、レポートは行や列をまるごと挿入・削除し、入力した値、メモ、書式は行と一緒に保持されます。[レポートの作成](/ja/reference/cli/plaidxl/build-a-report/)を参照してください。
  - **どのセルからでもドリルできます。** **Drill down**、**Drill up**、**Keep only**、**Remove only** は、ノード、ディメンション見出し、レポートの値から、ライブの `DRILL` 式への変換と編集を自動で行います。**Custom drill** は挿入前に行をプレビューし、メンバーピッカーはメンバーの挿入や、ノードの子のドロップダウンをセルに追加できます。`DRILL` では除外または展開するノードを指定でき、行方向にも実行できます。[ドリル、メンバーの選択、数値の説明](/ja/reference/cli/plaidxl/drill/)を参照してください。
  - **数値を説明します。** **Explain this number** は、値の計算内容、現在の PlaidCloud と一致しているか、元になっているテーブルとワークフローステップを表示します。**Show detail rows** は、値の元になった行を専用のシートに表示し、合計が一致するかのチェックも行います。
  - **Excel でガバナンス対象のメトリックを使えます。** `PLAIDXL.METRIC` と `PLAIDXL.METRIC_BREAKDOWN` は、ダッシュボードに表示されるのと同じビジネスメトリックを返します。集計対象のない `CELL` または `CELLS` は、合計では `0` を表示し、それ以外では理由とともに `#VALUE!` を表示します（`CELLS` のスピルでは空白になります）。**Metric...** ボタンは、プロジェクトのメトリックを現在の値とともに一覧表示します。メトリックは複数の代替階層でフィルターでき、代替階層のメンバーと他のディメンションのメンバーを組み合わせられます。[メトリック](/ja/reference/cli/plaidxl/functions/#メトリック)を参照してください。
  - **レポートに入力して計画できます。** `CELL` の値に数値を上書き入力すると、PlaidCloud に書き込まれます。比例配分、均等配分、別のメンバーの形状に合わせた配分、金額またはパーセンテージによる調整ができ、保留中のセルは変更されません。平均、中央値、最小値、最大値、標準偏差、分散のセルにも値を入力でき、入力した値は行や列の挿入・削除に合わせてセルと一緒に移動します（削除したセルの値は報告されます）。**Undo last write** は、入力した値と保存を新しいものから順に取り消します。取り消せるのは、その書き込みを行ったユーザーとワークスペースだけです。合計の取り消しや、空のセルに入力した平均の取り消しでは、その後に同じセルへ書き込まれた内容が保持されます。完了前に中断された書き込みは取り消せません。[PlaidCloud に値を入力する](/ja/reference/cli/plaidxl/write-values/)を参照してください。
  - **必要な分だけ更新できます。** シート、選択範囲、またはすべてのテーブルを更新できます。各テーブルの進捗と **キャンセル** はタスクペインに表示され、PlaidXL の数式だけを再計算することもできます。取得したテーブルはデータ型に応じて書式設定された Excel テーブルとして届き、更新時もお客様自身の列と数値書式が保持され、元の場所で更新されます。取得や更新で他のセルが上書きされたり、別の Excel テーブルと重なったりすることはありません。Excel で扱えない大きさの整数 ID や 1900 年より前の日付はテキストとして届きます。同じテーブルを再取得しても更新リストに二重に追加されず、**Stop refreshing** でリストから外せます。ディメンションはテーブルと一緒に更新されます。[すべてのテーブルを更新](/ja/reference/cli/plaidxl/retrieve/#すべてのテーブルを更新する)を参照してください。
  - **保存は即座に書き込まれ、元に戻せます。** **Save to PlaidCloud** は確認なしで書き込み、実行内容を表示し、**元に戻す** を提示します。Lakehouse テーブルでは、保存のたびに 7 日間まで元に戻せます。フィルター付きで取得したシート、詳細行のシート、または一部の行にしかアクセス権がないユーザーの保存では、対象の行だけが置き換えられ、他のユーザーの行は保持されます。取得後にメンバーが変更されたドリルスルーシートは保存されず、保存に失敗した場合は、テーブルを元に戻せるよう復元ポイントが示されます。[PlaidCloud へのテーブルの保存](/ja/reference/cli/plaidxl/retrieve/#テーブルを-plaidcloud-に保存する)を参照してください。
  - **Excel で Weave に質問できます。** **Weave** タブで、レポート、数式、ドリル、テーブルを普通の言葉で依頼するか、**Ask Weave about this cell** を選びます。Weave はお客様の権限で PlaidCloud を読み取り、変更するのはワークブックだけです。入力済みの内容を置き換える前には確認し、ワークブックの外を参照する数式は書かず、各変更はペインを再読み込みするまで元に戻せます。[Excel で Weave に質問](/ja/reference/cli/plaidxl/weave/)を参照してください。
  - **1 つのシートまたはワークブック全体の値のみのコピーを共有できます。** **Convert to values** は、ワークブック全体、1 つのシート、または元に戻せない値のみへの変換を行い（最後の場合は事前に確認します）、PlaidXL の数式とそのスピルだけを変更します。まだ計算中の数式は、再試行のために残されます。シート名を変更したあとでも **Restore PlaidXL formulas** が使えます。
- **転記レジスターは、対応が必要な内容から開きます。** 確認が必要なものがあれば **例外** で、承認待ちの依頼があれば **承認** で、それ以外は **すべての転記** で開きます。レールは画面を **自分の対応待ち**、**レジスター**、**インサイト**、**設定** にまとめ、**例外** と **承認** には件数が表示されます。すべての画面で、1 つのヘッダーとスコープバーを共有します。期間（**This month**、**前月**、**過去7日間**、**過去30日間**、**カスタム**）、接続、プロジェクト、環境、エンティティ、そして **本番**、**シミュレーション**、**すべて** を選び、**リセット** するか **Saved scope** として保存できます。最後に使ったスコープは記憶されます。
  - **例外は、確認が必要なものを仕分けます。** **Needs a look**、**未確認**、**保留中**、**失敗**、**Reversal outstanding** のチップに件数が表示され、接続の状態を示す行には「All N connections posting normally」（N 件すべての接続が正常に転記しています）と表示されます。すべての転記には、次に何をすべきかを示すツールチップ付きの分かりやすい状態が付きます。未処理のものがなければ **All clear** と表示されます。**Find a posting by ledger id** またはコマンドパレットに元帳 ID を貼り付けると、その転記を直接開けます。
  - **承認、委任、ウォッチは受信トレイ形式の画面です。** **Waiting on me** と **Submitted by me** を切り替え、理由を添えて **承認** または **却下** し、複数をまとめて承認でき、トースト通知から承認を **元に戻す** こともできます。**Delegate approvals** は短いダイアログで、**ウォッチ一覧** はフォローしている内容を一覧表示します。**転記を取消** と、一括の再試行・クリアのダイアログは同じレイアウトを共有します。
  - **転記のドロワーには、何が起きたかが表示されます。** 状態とその意味、主要な事実が名前付きで表示され、**Lines**、**履歴**、**承認** のタブがあります。**レビュー済みにする**、**再試行**、**取消…** ボタン、**接続をウォッチ**、**実行をウォッチ**、**Copy link** が使え、**Copy link** はその転記を直接開きます。
  - **アシスト、エクスポート、保持期間も同じデザインに従います。** **アシスト** には質問ボックスとインサイトカードがあり、**Draft — nothing applied** と表示されるアドバイスや、**すべての転記** の異常カードには **これらを表示** が付きます。**エクスポートとアラート** には **New schedule** があり、**保持期間** は 1 枚のカードになりました。
  - **レジスターは常に最新です。** 転記が変化するとレールのバッジが更新され、転記が変更されると開いている一覧に **更新** が表示され、開いているドロワーはその場で更新されます。**ホーム** の **要対応** の下には **転記レジスター** カードが表示されます。[転記レジスターの確認](/ja/guides/connections/posting-register/)を参照してください。
- **プロジェクトホームは 6 つのページで構成されます。** テキストのみのレールに **概要**、**変数**、**Schedules & sensors**、**Access & sharing**、**Data & connections**、**Apps & branding** が並び、変数の数や、有効なスケジュールとセンサーの数がバッジで表示されます。**概要** には、プロジェクトの説明とラベル、ロック状態、テーブル・ワークフロー・ステップ・変数・公開済みテーブルのタイル、**データサイズ**（クリックすると **ストレージ** が開きます）、直近 3 件のスケジュール実行、プロジェクトのデフォルトが表示されます。**データサイズ** は **プロジェクト** 画面と同じ合計で、復元用に保持している以前のバージョンも含まれ、ツールチップで現在のデータと以前のバージョンの内訳を確認できます。**プロジェクトレポート** は PDF またはインタラクティブな HTML で出力でき、**アーカイブのエクスポート** も使えます。ほかのページでは、変数、スケジュールとセンサー（**Calendar view** と **Activate** または **Deactivate** 付き）、プロジェクトとそのダッシュボードを開けるユーザーとテーブルを読み取れるプロジェクト、接続とテーブルストレージのデフォルトおよび ERP 転記モード、Panelアプリ、ブランディング、プロジェクトのタイル画像を管理します。ロックされたプロジェクトにはバナーが表示され、コントロールは無効になります。[プロジェクトホーム](/ja/guides/projects/project-home/)を参照してください。
- **ドキュメントは概要から開き、ページのレールがあります。** レールには **Overview**、**参照**、**Shared**、**My private**、**管理** が並びます。**Overview** には、アカウントのタイル、**Pinned** のファイル（クリックすると **参照** がそのフォルダーで開き、ファイルが選択されます）、サービス別のアカウント、利用できるユーザーが表示されます。**管理** には自分が所有するアカウントが一覧表示され、ワークスペース管理者はここですべてのドキュメントアカウントを確認でき、そのほかの方法で管理できるアカウントであれば管理もできます（システム管理のアカウントは対象外で、管理バケットのアカウントは複製できません）。行の **⋯** メニューには、**開く**、**編集**、**複製…**、**Who can use it**、**使用箇所…**、**Version history**、**有効にする** または **Disable**、**削除** があります。アカウントはページとして開き、**一般**、**アクセス**、**Credentials** のカードと、SFTP の場合は **SSH** カードがあり、未保存の変更がある状態で離れる前に確認します。**参照** には、ラベル付きのツールバー、行メニュー、ドロップゾーン、各アップロードとテーブルへのインポートの進捗とアクションを表示する **Uploads and imports** パネルがあります。**Pop out** でフォルダーを別ウィンドウに開き、**Dock** で元に戻します。[ドキュメント](/ja/guides/documents/)と[ドキュメントアカウントの使用](/ja/guides/documents/using-document/)を参照してください。
- **ダッシュボードは概要から開き、ページのレールがあります。** レールには **Overview**、**ダッシュボード**、**アプリ**、**Notebooks** が並び、ワークスペース管理者には **アクセスレビュー** も表示されます。下部には **Open navigator** があります。**Overview** には、ダッシュボードとアプリのタイル（クリックすると、該当の一覧がフィルター済みで開きます）、最近開いたりスターを付けたりしたもの、失敗したアプリ、自分の対応待ちのアクセスリクエストが表示され、利用状況へのアクセス権を持つメンバーには最も開かれているダッシュボードも表示されます。**ダッシュボード** は **すべて**、**You manage**、**お気に入り** でフィルターでき、**アプリ** には各アプリの **種類** とライブのステータスが表示されます。[ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **Identity は概要から開き、ページのレールがあります。** レールには **Overview**、**メンバー**、**ディレクトリ**、**セキュリティグループ**、**配布リスト** が並び、続いて **セッション**、**セキュリティログ**、**APIクライアント**、**Group audit**、**All scopes** があり、**利用状況レポート** はページの上に重ねて開きます。**Overview** には、メンバー、アクティブなメンバーとまだサインインしていないメンバー、ビルダー席、現在サインインしている人のタイル、**アクティブなメンバー** のグラフ、**ウェルカムメールを再送信** と **確認** が付いた **要対応**、過去 7 日間のセキュリティイベントが表示されます。メンバーはページとして開き、**プロファイル**、**アクセス**、**Groups and data** のカードがあります。**Invite member** は Overview とホームの初回カードから使えます。[メンバー管理](/ja/administration/access/member-management/)を参照してください。
- **Lakehouse ウィンドウにサイドレール、テーブルの詳細、タイムトラベルが加わりました。** レールには **クエリ**、**プロファイル**、**ロード**、**カタログ** が並び、**Administration** の下に **Lakehouse catalogs**、**Database users**、**Compute** があります。**Database users** と **Compute** は、Lakehouse 管理者または Lakehouse クラスターのロールを持つメンバーにのみ表示されます。**クエリ** では、SQL テキスト、ユーザー、種類、実行時間で履歴をフィルターでき、**Copy SQL** でステートメントをコピーし、**Profile this query** でクエリを **プロファイル** で開けます。**カタログ** では、テーブルの列、現在のスナップショット、パーティション、場所、プロパティ、スナップショット履歴を開け、**Copy query as of this snapshot** は、その時点のテーブルを読み取る `FOR VERSION AS OF` クエリをコピーします。[Lakehouse ウィンドウ](/ja/guides/data/lakehouse-window/)を参照してください。
- **ステップのフォームでプレビューできます。** インポート: SQL、Execute: SQL、SQL抽出、エクスポート: SQL、Salesforce: オブジェクトのクエリの各ステップでは、ステップを実行せずに最大 100 行を表示でき、Anaplan のビューとリストの読み取りでは、生成される列と型が表示されます。**ソース** タブで **プレビュー** をクリックします。変数は実行時と同じように埋め込まれますが、`{x:>9}` のような変数の書式指定には対応していません。プレビューで実行できるのは標準の SQL 関数のみで、それ以外の場合はステップを実行するよう案内されます。ロックされたプロジェクトや、エージェントベースの Execute SQL ステップでは利用できません。[SQLのインポート](/ja/reference/workflow-steps/import/import-sql/)と [SQL抽出](/ja/reference/workflow-steps/tables/table-extract-sql/)を参照してください。
- **利用状況レポートは変化を示し、グループに絞り込め、ワークフローに連携できます。** **Overview** には、前の期間と比べた傾向の矢印と、非アクティブなメンバーや誰も開いていないダッシュボードとアプリを示す **Highlights** の一覧が加わりました。無効化されたメンバーは、非アクティブとして数えられたり一覧に表示されたりしません。**グループ** は **Overview**、**内容**、非アクティブ一覧を 1 つのセキュリティグループのメンバーに限定します。日付範囲には **Previous month** と **This month** が加わり、すべてのタブで共有され、アカウントに記憶されます。すべての数値に説明が付き、テーブルは **メンバー** や **Area** などの分かりやすい名前を使い、行は Enter キーで開き、読み込み中とエラーの表示も分かりやすくなり、最後の **ファネル** ステップには完了したメンバーの数が表示されます。**Get Workspace Usage** ステップは、使用状況をスケジュールに従ってテーブルに書き込みます。メンバー名のない日次または月次の合計として、またはレポートに使えるデータセット（**メンバー**、**メンバー別日次**、**内容**、**メンバー別内容**）として書き込めます。メンバーのデータセットには氏名、メールアドレス、グループ、アクティビティが含まれるため、メールアドレスで自社の組織テーブルと結合し、部署ごとのアクティブ時間やダッシュボードを開いた回数をレポートできます。**Get Workspace Members** と同様に、各実行はセキュリティログに記録されます。[利用状況レポート](/ja/administration/access/usage-reports/)と [Get Workspace Usage](/ja/reference/workflow-steps/general/get-workspace-usage/) を参照してください。
- **AI アシスタントがテーブルをプロファイルできます。** MCP 経由で、`table_profile` は、テーブルエクスプローラーが表示する列の統計と データ品質レーダー のチェックに加え、各列の最頻値を返します。一度に最大 50 列まで、また自分が閲覧できる行に対してのみ動作します。[AI アシスタントからのプロファイルの読み取り](/ja/guides/data/table-explorer/#ai-アシスタントからプロファイルを読み取る)を参照してください。

- **Git アプリがリポジトリを一覧表示し、できることを示します。** アプリ一覧の **Git** には、自分のロール（**管理者**、**コントリビューター**、**閲覧者**）と、ワークスペースのリポジトリが表示されます。各リポジトリには、説明、最終更新日、コピーボタン付きのクローン用アドレス、**開く** が付きます。**Set up Git on your computer** カードは、Git のインストール、トークンの作成、クローンの手順を案内し、**How to clone** で再び開けます。**View all in Git** は Git の完全なインターフェイスを開き、**Manage who can push** はグループ管理を開きます。アクセスレベルは **閲覧者**、**コントリビューター**（アプリのコードを `apps` にプッシュ）、**管理者**（`udfs` を含むすべてにプッシュ）で、閲覧者には問い合わせ先としてワークスペース管理者が最大 3 人表示されます。新しい **Git Contributors** グループはコントリビューターの権限を付与し、デフォルトグループにもできるため、新しいメンバーに自動で付与されます。**Git Administration** は管理者の権限を付与します。メンバーの **Git** タブには、Git のユーザー名、レベル、それを付与しているグループが表示されます。メンバーの Git アカウントはメンバーシップに連動します。メンバーを無効化または削除すると、トークンと SSH キーを含め、約 1 時間以内にその Git アカウントがブロックされ、再び有効化するとブロックが解除され、リポジトリと履歴は保持されます。シングルサインオンで Git にサインインすると、メンバー自身のアカウントが開きます。コントリビューターは、ワークスペースの Git 組織にリポジトリを直接作成することはできず、リポジトリは PlaidCloud を通じて作成されます。アプリウィンドウには **リポジトリ** セクションが表示され、UDF には **開く** があり、Git にはワークスペースへの **← Back to** リンクがあります。アプリのリポジトリや組み込みの `apps` と `udfs` リポジトリを含め、プラットフォームが作成するすべてのリポジトリは、ワークスペースのサインイン済みメンバー全員が読み取れるため、メンバーはリポジトリごとの設定なしでアプリを開いて再公開できます。Git 管理者は引き続きリポジトリを非公開にでき、その場合はリポジトリピッカーに表示されなくなり、メンバーはそこから公開したり、そこに保存された Git ベースの UDF コードを実行したりできなくなります。[PlaidCloud Git](/ja/guides/git/#gitを開く) と [リポジトリを閲覧できるユーザー](/ja/guides/connections/plaidcloud-git/#リポジトリを閲覧できるユーザー)を参照してください。
- **Cost to Serve と Operational Transfer Pricing のテンプレートは Common Finance Model を基盤にしています。** **Cost to Serve** からプロジェクトを開始すると、部門ごとに設定したアクティビティとドライバーに基づいて営業費用を顧客に配賦し、サービス提供コストを差し引いた各顧客のマージンを、元帳に結び付けて確認できます。**Operational Transfer Pricing** から開始すると、各エンティティの利益水準（売上高利益率、ネットコストプラス、再販売価格マイナス）を、ポリシーで定めた範囲に対してテストし、範囲外のエンティティを目標に戻す真水調整（true-up）を行えます。売上高利益率は、EBIT を被テスト当事者の売上高で割ったものです。[Cost to Serve](/ja/guides/projects/cost-to-serve/) と [Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/) を参照してください。

- **Data Foundation が共通コストを配賦する方法を選べます。** **アクション > Allocations...** は、どのコストを配賦するか、何を基準に配賦するか、どこに配賦するか、負のドライバーをどう扱うかを順に案内します。間接費から部門へ、また部門から製品と顧客への配賦に対応し、1 か月分のプレビューで、プールされた金額、配賦された金額、未配賦の金額を確認できます。手作業で編集したルールは保持されます。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。

- **Data Foundation はロードのたびにボードパックを作成し、元に戻せます。** **ロード** のたびに、損益計算書ダッシュボードの Excel ワークブックと PDF が、ドキュメントアカウントのフォルダーに書き込まれます。レポートがオフの場合、パックはワークブックのみで、ダイアログにもそう表示されます。各ロードの開始時と、マッピングやソースを変更する前に復元ポイントが作成され、**アクション > Restore...** は各復元ポイントで元に戻るテーブルの数を表示し、ディメンションを含めてプロジェクトを元に戻します。**Foundation** タブには専用のレールがあり、**ステータス**、**Answers needed**、**Source coverage**、**ソース** のページと、対応が必要なものを示すバッジ、変更を適用するためにすべてのページの上部にある 1 つのバーがあります。また、状況もより分かりやすくなりました。実行中のまま、または途中で停止した更新を表示し、テーブルのフォルダーがソースにならない理由を示し、何かが一致するまで **合計が一致することを確認** を保留中のままにし、ステータスの読み取りに失敗しても復旧します。更新を適用しても、生成されたステップやノートへのお客様自身の編集は保持され、競合があれば通知されます。[ボードパック](/ja/guides/projects/data-foundation/#取締役会資料)と[復元ポイント](/ja/guides/projects/data-foundation/#復元ポイント)を参照してください。
- **Data Foundation は複数の ERP とシステムを 1 つのモデルに統合し、ロードする会社を選べます。** **ソース** ページの **Connect a system** には、システムの種類ごとにタイルがあり、**Connect another system** は、既存のものを置き換えずに別の ERP や別のインスタンスを追加します。**Load order** で、ソースの **編集** をクリックすると子会社の **Companies** 一覧があり、ロードする会社にチェックを付けます（何も付けなければすべてが対象です）。会社を除外する場合は、保存時にロード済みの行が消去されるため、先に確認が表示され、次の **ロード** でチェックした会社が再び取り込まれます。ソースの接続が別のアカウントを読むようになっている場合は、別のソースを変更するのではなく、メッセージとともに保存が拒否されます。[ソース](/ja/guides/projects/data-foundation/#ソース)を参照してください。

- **Weave に Monitor が加わりました。** **Weave** タブの **検出事項** ページは **Monitor** になり、レールに **検出事項**、**チーム**、**アクティビティ**、**月次サマリー**、**想定内** がまとめられ、クローズチェックの **準備状況** と **照合** は **Close checks** の下にあります。**検出事項** には、未解決の問題、担当者のいない問題、最も古い未解決の問題のタイルが表示され、検出事項は重大度別にグループ化されます。各行には、**所有者**、未解決の期間、1 つのアクションが表示され、**修正** または **開く** が先頭に、残りは **⋯** メニューの下に並びます。行を開くと、Weave の説明文、根拠、Weave がどう判断したか、コメントを確認でき、**所有者** と **ワークフロー** でフィルターできます。[Weave タブ](/ja/guides/ai-assistant/weave-tab/)を参照してください。

## 変更

- **PlaidCloud の Web アプリと Python クライアントライブラリは REST API を使用し、JSON-RPC は非推奨になりました。** Web アプリは REST API にリクエストを送ります。`plaidcloud-rpc` 1.25.0 以降では、`SimpleRPC` の呼び出しはコードを変更せずに REST API に送られます。REST API がまだ対応していない呼び出しや、古いリリースのままのワークスペースでは、従来どおり JSON-RPC を使います。JSON-RPC は今後のリリースで削除されるため、スクリプトとノートブックを `plaidcloud-rpc` 1.25.0 以降にアップグレードし、新しい連携は REST API に対して作成してください。[コマンドライン](/ja/reference/cli/jupyter/command-line/)を参照してください。
- **ステップは、別の環境に固定しない限り、プロジェクトの接続環境に従います。** プロジェクトの環境を QA と本番などの間で切り替えると、すべてのステップが切り替わります。1 つの環境にとどまる必要があるステップには、代わりに **Fixed environment** を設定できます。フォームには警告付きで表示され、ログにはプロジェクトとは別の環境での各実行が記録され、プロジェクトを切り替えるときには従わないステップが名前付きで示されます。ERP 転記ステップは常にプロジェクトの環境を使います。プロジェクト、固定されたステップ、エージェントが使っている環境は削除できず、エージェントフォームのフィールドは **Environment this agent serves** になりました。[ステップを 1 つの環境に固定する](/ja/guides/projects/managing-projects/#ステップを1つの環境に固定する)を参照してください。
- **ステップのフォームは同じレイアウトに従います。** タブには標準の名前が標準の順序で付きます。一般、設定、ソース、列、フィルター、出力、詳細設定で、ERP 転記フォームにはヘッダー列と明細列があります。必須フィールドには * が付き、フォームが保存をブロックするのはステップに必要な項目だけです。
- **プロジェクトのコピーでは、テーブルデータとディメンションメンバーを別々に選べ、データのコピーが速くなり、非公開コピーでは ERP 書き込み承認が保持されます。** **Data to copy** で **テーブルデータ**（**テーブルデータなし**（デフォルト）、**完全**、**サンプル**）を選び、それとは別に **Copy dimension members**（デフォルトでオン）を選びます。そのため、テーブルの行をコピーしない場合でも、ディメンションにはデータが入った状態で届き、短時間で作成できます。**完全** と **サンプル** のコピーは複数のテーブルを同時にコピーするため、テーブルの多いプロジェクトでも速く完了します。**コピー結果** には、テーブルと並べて各ディメンションの結果が一覧表示され、**Retry failed items** は失敗したテーブルとディメンションをまとめて再試行します。データ付きで新しく作成したコピーは自分専用で、元の **ERP書き込み承認** のうち自分で付与できるものが保持されます。元が本番で転記している場合、コピーはシミュレーションで届くため、本番に切り替えるまで ERP には何も送られません。REST API と `project_copy` MCP ツールも `dimension_members` を受け付けます。[コピーするデータ量の選択](/ja/guides/projects/managing-projects/#コピーするデータ量の選択)と[コピーでの ERP 書き込み承認](/ja/guides/projects/managing-projects/#コピーでのerp書き込み承認)を参照してください。
- **テーブルの詳細パネルで、そのテーブルを使うステップが速く表示されます。** 別のテーブルを選ぶと、前のテーブルのステップがすぐに消え、このプロジェクトのデータを共有する他のプロジェクトのステップは、パネル全体を待たせずに少し遅れて追加されます。[テーブルの使用箇所を確認する](/ja/guides/projects/managing-tables-and-views/#テーブルの使用場所を確認する)を参照してください。
- **行のアクションはすべての一覧で同じように動作します。** 行のメニューは、行の先頭の **⋯** ボタン、右クリック、またはツールバーの **アクション** メニューから開きます。メニューには常に **開く**、**詳細**、**編集** が先頭に並び、続いてその一覧固有のアクション、最後に **削除** または **削除** が並びます。行に適用できないアクションは、その位置でグレーアウトされます。**Enter** と **Del** は、実行するアイテムに表示されます。行のアクションが 1 つだけの一覧では、**⋯** の代わりにそのアクションのアイコンが表示され、ダッシュボード、アプリ、Notebooks には再び **開く** アイコンが表示されます。[行アクションメニュー](/ja/guides/dashboards/using-dashboards/#行アクションメニュー)を参照してください。
- **PlaidCloud の外観が刷新され、ライトとダークの両方で新しいブルーになりました。** ボタン、チェックボックス、選択された行、タブ、リンク、ワークスペースのページを一覧表示するレールには、1 つの PlaidCloud ブルーが使われ、どちらのテーマでも読みやすいコントラストが確保されています。アプリのタブアイコンは統一されたセットになりました。
- **新しい読み込み画面。** PlaidCloud は、ライトまたはダークのテーマに合わせた、すっきりした読み込み画面で開きます。アイドル状態から復帰する Panel または Dash アプリは、**開始中**、**準備中…**、アプリを読み込み中 の順に進捗を表示し、起動しない場合はどのステップで止まったかを示して **再試行** を提示します。[Panelアプリの使用](/ja/guides/panel-apps/using/)を参照してください。
- **検証設定のない保存済みの ERP 書き込みステップは、検証のみで開きます。** SAP Post、SAP Attach、NetSuite Post、Oracle EBS の GL と AP の Post、Xero のエクスポートが対象です。本番で実行するよう明示的に設定されたステップは、本番のままです。
- **長時間実行されるジョブの進捗は、どこでも同じ方法で表示されます。**
- **ワークフローは、正直に停止し、失敗し、報告します。** ワークフローを停止すると、それが開始したすべてが停止し、完了できない実行やステップはハングせずに理由付きで失敗し、実行ステータスは実際に実行された内容と一致します。
  - **ワークフローを停止すると、それが開始したすべてが停止し、完了できない実行やステップはハングせずに失敗します。** 停止すると、キューに入っているインポートとディメンションのステップがキャンセルされるため、ワークスペース内の後続のインポートとディメンションのロードは通常どおり開始されます。また、ワークフローのキュー中または実行中のコネクター（Singer）同期も停止されます。ステップのジョブを開始できない場合、そのステップは永遠に待つ代わりに理由付きで失敗します。約 40 分以内にどのワーカーも開始しない場合、ワーカーが開始したあと消えた場合、そのポッドが約 20 分間 Pending のままの場合、イメージを約 5 分間取得できない場合、約 20 分間ポッドが作成されない場合です。どのランナーにも約 30 分以内に取得されないコネクター同期は、その同期名を示すメッセージとともに失敗します。ステップがワーカーを待っている間、そのステータスメッセージには経過した分数とともに「ワーカーを待機しています…」と表示され、作業が始まると消えます。マクロを停止すると実行中のすべてのコピーが停止しますが、1 つのコピーを停止した場合や、**Macro Concurrent** ステップが応答しなくなったコピーを見限った場合は、それを呼び出したワークフローは実行され続けます。ほかのワークフローの中でのみ実行されているマクロは、ワークフロー一覧に **実行中** と表示され、**停止** が使え、各ステップのステータス、開始時刻、終了時刻は最新の実行から取得されます。サーバーが失われた実行は失敗として終了し、12 時間経っても実行中の実行は「Run failed: still running at the 12-hour limit. Re-run the workflow.」（実行失敗: 12 時間の上限を超えても実行中です。ワークフローを再実行してください。）で失敗します。[ワークフローの実行](/ja/guides/workflows/run-a-workflow/#開始されないステップ)を参照してください。
  - **再開、実行履歴、実行ステータスは、実際に実行された内容と一致します。** 親ワークフローを再開すると、子ワークフローのステップを単独で再実行したあとでも、子ワークフローで残っていたすべてが実行され、1 回の実行内での子ワークフローの各呼び出しには、それぞれ実行履歴のエントリが付きます。サーバーが停止したために再開されるステップは、ログにその旨が記録され、`workflow_run_status` と REST API の実行結果は、失敗したものの続行したステップを `continued_step_ids` と `continued_step_count` に一覧表示し、実行を問題なしとは報告しません。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)と[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。
  - **ステップのエラーに固有のメッセージが表示されます。** PlaidCloud が想定していなかったエラーは、「The step stopped on an unexpected error (*type*): *message*」（ステップが予期しないエラー（*type*）で停止しました: *message*）と表示されます。ランチャーの **要対応** カードにはエラーが 1 行で表示され、すでに削除されたワークフローの実行は除外されます。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。
  - **完了しない ERP 抽出はステップを失敗させ、再開で続行できます。** **SAP: アドホック抽出** が行数や時間の上限で一時停止した場合やエージェントが時間内に応答しない場合、または Salesforce、Oracle Fusion の一括、HFM/FCCS のエクスポートジョブが、ステップが待機をやめた時点でまだ実行中の場合、ステップは失敗し、後続のステップが不完全なテーブルで実行されることはありません。ワークフローを再開するかステップを再実行すると、抽出は停止した地点から同じジョブで続行されます。[実行の上限](/ja/guides/connections/sap-adhoc-extract/#実行の制限)と [Salesforce: オブジェクトのクエリ](/ja/reference/workflow-steps/salesforce/query-salesforce-object/#実行が完了しない場合) ステップを参照してください。
  - **エクスポートをキャンセルすると、ウェアハウスでのクエリも停止します。** ワークフローの停止によるものを含め、エクスポートまたはダウンロードがキャンセルされると、Lakehouse v2、Snowflake、Databricks、PostgreSQL、Greenplum では、そのデータを読み取っているクエリも停止し、リモートデータベースへのエクスポートはソースの読み取りを停止します。最後まで実行され続けることはありません。
- **REST、Import REST、Import Postman の各ステップは、ワークスペースのアップグレード時に RESTリクエスト に変換されます。** きれいに変換できないステップは、そのまま残ります。[RESTリクエストステップ](/ja/guides/workflows/rest-request-step/)を参照してください。
- **セッションの有効期限が切れたあとに開いたダッシュボードのリンクは、サインイン後にそのダッシュボードへ移動します。** [ダッシュボードの使用](/ja/guides/dashboards/using-dashboards/)を参照してください。
- **MCP ツールは、認識できないフィールドを無視せずに拒否し**、エラーにそのフィールド名を示します。`workflow_upsert` は `memo` を受け付け、その別名として `description` も受け付けます。[不明なフィールドは拒否される](/ja/integrations/ai-coding-agents/getting-started/#不明なフィールドは拒否される)を参照してください。
- **Lakehouse v2 では、Lakehouse が Parquet のエクスポートを Google Cloud Storage に直接書き込みます。** Google Cloud Storage のドキュメントアカウントへのエクスポートは、すべての行を PlaidCloud 経由で渡す代わりに、アカウント自身の認証情報で書き込まれ、アカウントのバケットに直接入ります。Amazon S3 と Azure Blob Storage のアカウントへのエクスポートは、従来どおり動作します。[Export to Parquet](/ja/reference/workflow-steps/export/export-to-parquet/) ステップを参照してください。
- **Slack、Microsoft Teams、Web Hook の各ステップは、メッセージが送信されなかった理由を示します。** ステップのエラーには、接続しようとしたサーバーと、Slack と Teams の場合は接続が示され、何が問題だったかが説明されます。たとえば、Slack が Webhook を認識しなくなった、チャンネルに投稿できない、サーバーが見つからない、または 60 秒以内に応答しない、接続が削除された、などです。Slack または Teams の Webhook URL は、持っている人なら誰でも連携としてなりすまして投稿できるため、表示されません。[Notify via Slack](/ja/reference/workflow-steps/notifications/notify-via-slack/) ステップを参照してください。
- **プロジェクトのサービスアカウントのアクセストークンは、少なくとも 24 時間有効です。** UDF ステップなど、プロジェクトとして実行されるワークフロージョブには、24 時間有効なトークンが渡されます。これより短い有効期間は、ワークスペースのアップグレード時に引き上げられ、設定済みのより長い有効期間はそのまま保持されます。
- **ワークスペースの組織、所有者、リリース、バージョンは PlaidCloud が設定し、データセンターは選択できます。** コントロールプレーンで作成したワークスペースは、作成者が所有者になり、PlaidCloud が設定するリリースチャネルに配置されます。**Data Center** は、サインアップ時に提示されるリージョンから選べます。ワークスペースを編集するとき、組織、所有者、リリース、バージョンは読み取り専用です。バージョンの変更には **Set Version** を使い、ワークスペースの移動、所有者やチャネルの変更、固定は PlaidCloud サポートに依頼してください。[ワークスペースの構成](/ja/administration/control-plane/workspace-configuration/#基本設定)を参照してください。

## 修正

- **無効なプロジェクト設定は、分かりやすいメッセージで報告されます。** 不明な環境やドキュメントアカウント、すでに使われている、または予約されているスラッグ、無効なストレージタイプや転記モードは、一般的なサーバーエラーではなく、問題を示すメッセージを返すようになりました。REST API では 500 ではなく 400 になり、AI アシスタントまたは MCP では無効な引数のエラーになります。
- **REST API のディメンション値リクエストが動作します。** `POST /rest/v1/analyze/query/retrieve-dimension-values` はグリッドリクエストとして処理され、無効として拒否されていました。現在は `value_columns` の列ごとに集計値を 1 つ返します。グリッド（行フィルターと列フィルターの組み合わせごとに 1 つの値）には、専用の `POST /rest/v1/analyze/query/retrieve-dimension-cells` があります。
- **遅いテーブルの読み取りとファイル処理が、ほかのリクエストを止めなくなりました。** ウェアハウスからのテーブルの列の読み取り、Data Foundation のファイルの登録、Excel へのエクスポート、REST または SOAP のインポートのレスポンスの読み取り、ドキュメントアカウントの使用箇所の検索、Panel アプリのコードやロゴのチェックは、いずれも完了するまで、同じサーバーが処理しているほかのすべてのリクエストを一時停止させることがありました。現在は、それらのリクエストと並行して実行されます。
- **プロジェクト変数とワークフロー変数のダイアログがスクロールします。** 小さな画面や低解像度では、追加と編集のダイアログがウィンドウより高くなり、**作成** と **更新** のボタンに手が届かないことがありました。フォームがスクロールするようになり、ボタンは下部に固定されます。
- **Azure Blob Storage ドキュメントアカウントで、256 MiB を超えるファイルをコピー、移動、名前変更できます。** これらはいずれも、そのサイズのファイルで失敗していました。そのようなファイルを含むフォルダーの移動や名前変更も同様でした。
- **Lakehouse v2 では、テーブルの行数に書き込んだ直後の内容が反映されます。** テーブルに書き込んだステップやインポートが、書き込み前の行数を記録することがあり、ロードしたばかりのテーブルが 0 行と表示されたり、インポートが 0 行のインポートと報告したりしていました。現在は、新しい行がすべての場所から見えるようになってから行数を読み取るため、その後のステップでも読み取れます。テーブルを別のブランチに切り替えたり、ブランチをテーブルにマージしたりした場合も、行数と列数が更新されます。
- **Weave の空値チェックは、各実行を以前の実行が実際に残した内容と比較します。** ステップの空値は、ステップがテーブルを空にして再投入した直後に数えられることが多く、そのため以前の実行には空値がなかったように見え、以前から一部が空だった列が、たった今そうなったかのように報告されていました。現在は、ステップがテーブルを残した状態で各実行が数えられます。以前に記録された数は、正しいものと区別できないため使用されません。各ステップの空値チェックの履歴は最初からやり直しとなり、5 回の実行が数えられるまでは未チェックとして報告されます。行数と値の分布のチェックも、ステップの完了から 2 秒を超えて別のステップが同じテーブルに行った書き込みを、そのステップの書き込みとして扱わなくなりました。[Weave が確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。
- **Data Foundation は、逆数にした為替レートと小数のしきい値の精度を保持します。** 為替レートが報告通貨から別の通貨への換算で示されているために PlaidCloud が逆数にしたレートは、小数第 6 位に丸められることがあり、インドネシアルピアのようにレートの小さい通貨の金額が約 1% ずれていました。逆数にしたレートは小数第 12 位まで保持されます。`0.5` のように小数を含む `group_amber` または `group_red` のしきい値が、整数に丸められていました。次回の **ロード** から、正確な値が使われます。[為替レート](/ja/guides/projects/data-foundation/#為替レート)を参照してください。
- **無効化されたメンバーのアラートとダイジェストが停止します。** 所有者が無効化された Panel アプリのアラートやダイジェストは、チェックと送信を続けていました。現在は、所有者が無効化されている間は一時停止し、再び有効化されると再開します。[アラートとダイジェスト](/ja/guides/panel-apps/alerts-and-digests/)を参照してください。
- **削除された接続を REST API で要求すると 404 が返ります。** 削除された接続や存在しない ID を要求すると、一般的なサーバーエラー（500）が返っていました。現在は、接続 ID を示すメッセージとともに 404 を返します。
- **テンプレート付きのテーブルエクスポートが AI アシスタントと MCP で動作します。** `table_data_export` の `templated` 形式は、テーブルを指定すると常に失敗していました。現在は、読み取り可能な行に限定して、テンプレートを通じてテーブルをエクスポートします。テンプレート内では、テーブルの行はテーブル ID で参照され、各 `-` は `_` と書きます。
- **Amazon S3 と S3 互換のドキュメントアカウントがリージョンを保持します。** これらのアカウントを保存すると、入力した **リージョン** が破棄され、次にアカウントを開いたときにフィールドが空になっていました。リージョンが保存されるようになりました。この修正より前に保存したアカウントでは、リージョンを再入力して保存してください。[AWS S3 アカウントの追加](/ja/guides/documents/adding-accounts/add-aws-s3-account/)を参照してください。
- **出力列の名前を 2 回指定したステップは、ターゲットを空にする前に停止します。** Table Lookup、Table Extract、結合で、同じ名前の **ターゲット出力列** が 2 つあると、ステップはターゲットテーブルを空にしたあと、分かりにくいエラーで失敗していました。現在は、ステップが先に停止し、重複した列を示すメッセージを表示するため、各出力列に別々の名前を付けられます。クエリが返す順序で列を書き込む SQL抽出 は変わりません。[Table Lookup](/ja/reference/workflow-steps/tables/table-lookup/) ステップを参照してください。

## セキュリティ

- **パスワードでのサインインには認証アプリが必要になり、パスワードが強化されました。** PlaidCloud のパスワードでサインインするメンバーは、次回のサインイン時に認証アプリの設定を求められ、それ以降は毎回そのコードを入力します。シングルサインオン、Google、Microsoft、GitHub でのサインイン、API トークン、サービスアカウントは変わりません。新しいパスワードは 12 文字以上で、ユーザー名や直近 6 つのパスワードと同じにはできず、サインインの失敗が繰り返されると、アカウントは短時間ロックされます。ワークスペースにすでにあるより厳しいルールは維持されます。[メンバーの認証](/ja/administration/access/member-authentication/)を参照してください。
- **接続は、パブリックアドレスとプライベートネットワークのアドレスを指します。** 接続は、ループバック、リンクローカル、クラウドメタデータのアドレスを指せず、エラーにはホストと、解決されたアドレスが示されます。プライベートネットワーク上のアドレスは影響を受けません。[接続が到達できないアドレス](/ja/guides/connections/create-connection/#接続が到達できないアドレス)を参照してください。
- **保存された接続の認証情報は、接続またはワークフローを編集できるメンバーにのみ表示されます。** REST API と MCP では、保存された接続のパスワード、トークン、キーは、ほかのメンバーにはマスクされますが、そのメンバーも接続を開いて参照できます。[接続の認証情報を確認できるユーザー](/ja/guides/connections/create-connection/#接続の資格情報を見られるユーザー)を参照してください。
- **アプリのビルドは、ワークスペースの Git 認証情報にアクセスせずに実行されます。**
- **エージェントの秘密鍵は、エージェントを編集できるメンバーにのみ表示されます。** 鍵は、REST API と MCP のエージェント一覧や詳細に表示されなくなり、エージェントフォームは **秘密鍵** と **RPC構成を表示** を、エージェントを編集できるメンバーにのみ表示します。サービスアカウント、プロジェクトトークン、エージェントトークン、AI が委任したトークンは、鍵や RPC 構成を取得できません。実行中のエージェントは影響を受けず、公開鍵は引き続き表示されます。[エージェント認証情報の取得](/ja/reference/cli/plaidlink/agents/#エージェントの認証情報の取得)を参照してください。
- **プロキシのダウンロードリンクは 1 時間有効です。** **Use PlaidCloud Proxy Download** をオンにしている場合、リンクの期限が切れたら、ダウンロードをもう一度開いて新しいリンクを取得してください。[サービス](/ja/administration/control-plane/workspace-configuration/#サービス)を参照してください。
- **セキュリティグループへのユーザーの追加は、保持している権限に従います。** セキュリティグループが付与するすべての権限を保持している場合に、メンバーをセキュリティグループに追加したり、メンバーのグループを選択したり、アーキテクトを招待したりできます。ワークスペース管理者には制限がありません。[セキュリティグループの管理](/ja/administration/access/managing-security-groups-and-assignments/#セキュリティグループの管理)を参照してください。
- **接続の所有者またはワークスペース管理者が、その設定を変更し、オン・オフを切り替えます。** REST API、JSON-RPC、AI アシスタントまたは MCP による接続の設定変更には、その所有者の 1 人、または所有者のいない接続ではワークスペース管理者が必要です。接続の有効化、無効化、ロック、ロック解除には、所有者またはワークスペース管理者が必要で、複数の接続を指定したリクエストは、そのすべてを変更できる場合にのみ適用されます。ワークスペースのデフォルトの AI 接続を選べるのはワークスペース管理者だけで、メンバーが所有する接続がデフォルトになるのは、管理者が所有する接続や所有者のいない接続でデフォルトになれるものがない場合に限られます。[接続の編集](/ja/guides/connections/create-connection/#接続を編集する)と [LLM プロバイダー](/ja/integrations/ai-architecture/llm-providers/#接続に含まれる内容)を参照してください。
- **行アクセスは、メンバーが制限付きテーブルで行うすべての操作に適用されます。** メンバーは、ダッシュボード、自分の SQL、ロードで、付与された権限が許可する行だけを閲覧し、変更できます。
  - **プロジェクトのアーキテクトは、ダッシュボードで行が制限されたテーブルのすべての行を閲覧できます。** これは Analyze で閲覧できる内容と一致します。アーキテクトのアクセスを取り消すと、ダッシュボードでは即座に反映されます。これは、ユーザーのロールを変更した場合、ユーザーやそのグループをプロジェクトから削除した場合、プロジェクトのアクセスタイプを変更した場合、以前のプロジェクトバージョンを復元した場合、セキュリティグループを削除した場合のいずれでも同じです。[行アクセスの管理](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を参照してください。
  - **行アクセスで制限されたメンバーは、自分で SQL クエリを実行し、結果をエクスポートできます。** 行アクセスのあるプロジェクトで、アーキテクトではないメンバーは、クエリ画面での自分のクエリから、付与された権限が許可する行だけを取得し、**アクセス権により行が制限されています** という通知とともに、CSV、Excel、JSON にエクスポートできます。以前は拒否されていました。パーセント記号（`%`）を含む付与値は、クエリ画面で行を返すようになり、そのようなクエリを CSV としてダウンロードできます。Snowflake や Databricks での自由形式の自分の SQL、Postgres 系ウェアハウスでの自分の SQL のエクスポート、ガバナンス対象のテーブルをスナップショット時点で読み取ることは、引き続き拒否されます。また、ビューでフィルターを適用するには、ガバナンス対象の列を元の名前のまま保持する必要があります。[行アクセスと自分で書くクエリ](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスとご自身で記述するクエリ)を参照してください。
  - **行アクセスを保存しても、ソースにない付与値は保持されます。** セキュリティグループに付与された値は、テーブルにその値を持つ行がない場合、ディメンションにそのメンバーがない場合、リストにそれがない場合でも、印が付いてグリッドに残ります。**保存** は、そのような値ごとに、保持するか削除するかを確認します。[行アクセスグリッド](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスのグリッド)を参照してください。
  - **行が制限されたテーブルへの DataFrame の書き込み、レコードの保存、クリアは、見える行だけを変更します。** 行アクセスで行が制限されている場合、Python クライアントで制限付きテーブルに DataFrame を書き込んだりクリアしたりしたとき、または REST API でレコードを保存したりクリアしたりしたときは、自分の行だけが変更されます。アクセス権のない行を含むロードは、何も変更されないうちに、見つかった値を示して拒否されます。プロジェクトのアーキテクト、すべての行を閲覧できるメンバー、ワークフローの実行は、テーブル全体に書き込みます。ユーザーが任意のテーブルに対して行うこれらの書き込みは、すべてセキュリティログに記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
  - **行が制限されたテーブルのインポート、コピー、復元、削除には、すべての行が見えている必要があります。** 行アクセスで行が制限されている場合、制限付きテーブルへのファイルのインポート、別のプロジェクトからのテーブルのコピー、ブランチの切り替えやマージ、復元、削除、削除後の復旧、そのほかテーブル全体を置き換える操作は、テーブルのすべての行が見えている場合にのみ実行され、そうでなければ拒否され、何も変更されません。REST API でテーブルの行を保存する場合は、ほかのロードと同様に、自分の行だけが変更されます。プロジェクトのアーキテクト、すべての行を閲覧できるメンバー、ワークフローの実行は影響を受けず、これらの操作もセキュリティログに記録されます。[制限付きテーブルへのデータのロード](/ja/administration/access/managing-security-groups-and-assignments/#制限されたテーブルへのデータの読み込み)を参照してください。
- **ドキュメントアカウントの以前のバージョンを復元できるのは、そのアカウントの所有者だけです。** ドキュメントアカウントを以前のバージョンに復元する、バージョンを保持または解除する、バックアップを取るには、アカウントの所有者の 1 人が必要で、システム管理のアカウントではいずれも利用できません。アカウントのバージョン履歴を確認するには、アカウントへのアクセス権が必要です。
- **`query_run` は読み取り専用のステートメントを実行します。** AI アシスタントと MCP クライアントが使う `query_run` ツールは、SELECT または WITH のステートメント 1 つ、その EXPLAIN、または SHOW を受け付け、それ以外のステートメントは実行されません。データを変更するには `query_transform` を使います。MCP のテーブルエクスポートの SQL にも同じルールが適用されます。REST と JSON-RPC の API では、プロジェクトのデータを変更できないメンバーに対し、クエリの実行、列ファセットの作成、クエリの CSV としてのダウンロード、リモートデータベースへのクエリのエクスポート、独自のクエリによるテーブルデータのエクスポートにも適用され、拒否されたクエリは 403 を返します。Explain Analyze は、測定のためにクエリを実行するため、クエリログと Lakehouse では読み取りのクエリのみを受け付け、行アクセスのあるプロジェクトでは、クエリログから実行できるのはプロジェクトのアーキテクトだけです。
- **テーブルエクスプローラーのフィルター、PlaidCloud に送信されるクエリ、Table Extract ステップの 動的列 を見つけるクエリは、SQL を実行したりサーバーのファイルを読み取ったりする関数を呼び出せません。** `query_to_xml`、`dblink`、`pg_read_file` などを呼び出すと拒否され、エラーには関数名が示されます。同じ場所で、`.op()` は演算子のみを受け付け、`literal_column` は Unicode エスケープ形式の引用符を使えません。動的列 のクエリには、ステップのフィルターと、ソースから列名を読み取る式が含まれるため、ルールに違反するものがあれば、実行時にステップが失敗します。[拒否される関数と演算子](/ja/reference/workflow-steps/common/advanced-data-mapper-usage/#拒否される関数と演算子)を参照してください。
- **Data Foundation の配賦ルールは、一重引用符、バックスラッシュ、改行を含む部門名または統計名を拒否します。** この名前は配賦ステップのフィルターに書き込まれるため、**保存** とステージ 1 のプレビューはそれを拒否し、その値を示します。[配賦ルール](/ja/guides/projects/data-foundation/#配賦ルール)を参照してください。
