## 説明


ダッシュボードは、静的なレポートから動的な分析まで、幅広いユースケースに対応します。複雑なレポート要件に対応しながら、直感的なポイント&クリックのインターフェースも提供します。問題が発生することもあるかもしれません。PlaidCloud サポートチームのメンバーがいつでもサポートしますが、同様の問題に遭遇した場合に備えて、以下にいくつかのヒントをまとめています。



## **ダッシュボードに関するよくある質問と回答**



### 推奨ブラウザー


キャッシュが頻繁に使われるため、ダッシュボードには通常 Google Chrome が最適です。ほかのブラウザーを使用していて問題が発生した場合は、まずキャッシュと Cookie をクリアして、問題が解決するかどうかを確認することをお勧めします。解決しない場合は、Google Chrome に切り替えて、問題が再発するかどうかを確認してください。



### 同期の遅延


* *問題:* ダッシュボード領域でテーブルの公開を解除して再度公開した後、データが正しく同期されていないように見える。
* *解決策:* テーブルを再公開すると、そのテーブルを読み取るすべてのチャートのキャッシュされた結果が消去されるため、ワークフローの実行後に開いたダッシュボードには、手動で更新しなくても新しいデータが表示されます。表示されない場合は、実行が完了したこと、そして想定したテーブルが再公開されたことを確認してください。[ダッシュボードのキャッシュ](/ja/guides/dashboards/dashboard-caching/)をご覧ください。

### テーブル同期エラー


* *問題:* 以前のテーブルと同じ公開名でテーブルを再作成した後、ダッシュボードで更新をクリックしたり、テーブルの公開、公開解除、再公開を行ったりしても、テーブルが同期されない。
* *解決策:* テーブルを別の名前で再公開してください。ダッシュボードのデータモデルでは、重複するテーブル、つまり公開名とプロジェクト ID が同じテーブルは許可されません。

### キャッシュの警告


* *問題:* 右上に「Loaded data cached **3 hours ago**. Click to force-refresh.」という警告が表示された。
* *解決策:* 警告をクリックしてキャッシュを強制的に更新します。「Edit dashboard」の横にあるドロップダウンメニューをクリックして、「Force refresh dashboard」を選択することもできます。どちらの方法でもシステム内で更新され、ブラウザー自体を更新するよりも推奨されます。結果を保持する期間は設定可能です。[ダッシュボードのキャッシュ](/ja/guides/dashboards/dashboard-caching/)をご覧ください。

### 権限の警告


* *問題:* 公開したダッシュボードの、データが表示されるはずのすべてのセクションに、「This endpoint requires the datasource… permission」という同じエラーが表示される。
* *解決策:* データソースが古くなっていないか確認してください。多くの場合、チャートが古い資料を参照しています。その場合は、チャートを新しいデータソースで更新してください。
* *問題:* 上記と同じ権限の警告が表示されるが、同僚にはチャートのデータが表示される。
* *解決策:* 1人はチャートのデータを閲覧でき、もう1人は閲覧できない場合は、権限を持つカテゴリのメンバーが、2人目に権限を付与する必要があるかもしれません。次の手順で付与します。


	1. Charts に移動します
	2. アクセスを許可したいチャートの横にある、鉛筆と紙の2番目の小さなアイコンを選択します
	3. Edit Table をクリックします
	4. Detail をクリックします
	5. Owners をクリックし、アクセスを許可したい人の名前を追加して保存します。

<Aside>ベストプラクティスとして、新しいチャートを作成して保存するときは、そのたびに該当するすべてのユーザーを Owners セクションに追加してください。そうしないと、新しくアクセスが必要なユーザーが出るたびに、チャートを開き直して編集し、Owners を追加する必要があります。</Aside>


### 変更したフィルターをダッシュボードに保存する


* *問題:* 下書きのモデルでフィルターを変更したので、ダッシュボードに保存したい。しかしフィルターが一覧にない。下書きのモデルには「There is no chart definition associated with this component, could it have been deleted? Delete this container and save to remove this message.」という警告が表示された。
* *解決策:* 「Edit Chart」に移動します。そこで、「Dashboards」セクションに正しいダッシュボードが入力されていることを確認してください。空白の場合は、正しいダッシュボード名を追加します。

### 数値の書式設定: 表示が崩れる場合


* *問題:* 数値の書式が崩れていて、順序がおかしい。
* *解決策:* この問題の原因として最も可能性が高いのは、数値列に NULL が含まれていることです。フィルターを使って、数値列の NULL をすべて除外し、もう一度実行してみてください。それでも解決しない場合は、こちらの資料を確認してください: http://bl.ocks.org/zanarmstrong/05c1e95bf7aa16c4768e またはこちら: https://github.com/apache-superset/superset-ui/issues 。それでも解決しない場合は、遠慮なく PlaidCloud サポートチームのメンバーにお問い合わせください。この問題は把握されており、より恒久的な解決策を開発中です。

### 数値の書式設定


数値を最も近い整数に丸めるには、次のようにします。


1. *使用しない:* ,.0f
2. *代わりに使用する:* ,d、ドルの場合は $,d

### 既存のダッシュボードのインポート


* *問題:* 既存のダッシュボードをインポートしようとすると、エクスポートしたファイルでエラーが発生する。
* *解決策:* まず、ファイルを確認してください。ダッシュボードとデータセットは、**エクスポート**で作成される ZIP ファイルからインポートされます。古い JSON または YAML のエクスポートファイルは受け付けられないため、ダッシュボードをもう一度エクスポートし、新しい ZIP ファイルをインポートしてください。
* 次に、ダッシュボードに「Slug」があるかどうかを確認します。これには Edit Dashboard を開き、2番目のセクションの Slug を確認します。そのセクションが空であるか「null」と表示されている場合は、これが原因ではありません。そうでない場合、スラッグは一意である必要があります。ほかのダッシュボードで使用されていない値に変更し、もう一度エクスポートして、新しいファイルをインポートしてください。
