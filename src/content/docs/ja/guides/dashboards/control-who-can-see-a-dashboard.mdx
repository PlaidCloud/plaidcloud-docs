すべてのダッシュボードには、開くことができる人である対象ユーザーがいます。ダッシュボードの所有者とワークスペース管理者は、PlaidCloud の1つのダイアログで、セキュリティグループを使って対象ユーザーを選択します。PlaidCloud は、その選択をダッシュボードが表示されるあらゆる場所に適用します。対象となるのは、ホーム、マイダッシュボード、ダッシュボード自体、直接リンク、サムネイル、PDF エクスポート、AI アシスタントです。

<Aside>対象ユーザーの設定で隠れるのはダッシュボードであり、そのデータではありません。ダッシュボードのロールが付与するのは可視性だけです。チャートのデータは引き続きプロジェクトのアクセス権に従うため、ダッシュボードを開いた人に表示されるのは、その人がアクセスできるプロジェクトのデータだけです。表示される行を制限するには、[行アクセス](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)を使います。</Aside>

## 対象ユーザー

| 対象ユーザー | ダッシュボードを開ける人 |
|---|---|
| **プロジェクトの全員** | ダッシュボードのプロジェクトにアクセスできる全員。これがデフォルトです。 |
| **特定のグループ** | 選択したグループのメンバー、ダッシュボードの所有者、ワークスペース管理者。 |
| **所有者のみ (下書き)** | ダッシュボードの所有者とワークスペース管理者。以前に選択したグループは保持され、ダッシュボードを再公開するとアクセス権が復活します。 |
| **限定公開** | どこにも一覧表示されませんが、リンクを知っているプロジェクト内の誰でも開けます。未公開のダッシュボードは、この状態から始まります。 |
| **カスタム (Supersetロール)** | ダッシュボードサービスで直接設定されたロールの保持者。PlaidCloud ではこれらを読み取り専用で表示します。 |

所有者とワークスペース管理者は、対象ユーザーの設定にかかわらず、常にダッシュボードを閲覧できます。ワークスペース管理者はダッシュボードサービスの管理者であるため、下書きを含むすべてのダッシュボードを閲覧できます。ホームのタイルとマイダッシュボードのバッジにはダッシュボードの対象ユーザーが表示され、所有者は自分の下書きと限定公開のダッシュボードをバッジ付きで確認できます。

## ダッシュボードを閲覧できるユーザーを選択する

1. ダッシュボードの**閲覧できるユーザー**アクションを開きます。ホームのタイル、マイダッシュボードの行、または**対象ユーザー**列から開けます。
2. **プロジェクトの全員**、**特定のグループ**、**所有者のみ (下書き)** のいずれかを選択します。各オプションには、対象となる人数が表示されます。
3. **特定のグループ**の場合は、グループにチェックを入れます。一覧には、ダッシュボードのプロジェクトにアクセスできるグループがメンバー数とともに表示され、**グループを検索**で絞り込めます。
4. **影響**の行を確認します（例: 「42人のプロジェクトメンバーのうち28人がこれを閲覧できます」）。**対象ユーザーを表示**では、アクセス権を得る人と失う人が一覧表示されます。**プレビュー表示ユーザー…** では、選択した任意のメンバーについて、ダッシュボードを閲覧できるかどうかとその理由が表示されます。
5. **保存**を選択します。

**常に含める**には、所有者とワークスペース管理者が表示され、削除できません。ダッシュボードの対象ユーザーを変更できるのは、所有者とワークスペース管理者だけです。それ以外のユーザーには、ダイアログが読み取り専用で表示されます。

ダイアログで確認できる内容は次のとおりです。

- 複数のプロジェクトにまたがるダッシュボードには、いずれかのプロジェクトにアクセスできるすべてのグループが一覧表示されます。プロジェクトの1つにアクセスできないグループにはフラグが表示されます。そのグループのメンバーには、すべてのチャートが表示されるわけではありません。
- チャートのないダッシュボードには「閲覧できるユーザーを設定するには、チャートを追加してください。」と表示されます。
- 削除されたグループは「削除されたグループ（0人）」と表示され、保存するとアクセス権を失います。空のグループには「このグループにはまだ誰もいません。」と表示されます。
- Superset のロールが設定されたダッシュボードには**カスタム (Supersetロール)** と表示されます。**特定のグループ**を選ぶと、選択したグループとともにそれらのロールが保持されます。**プロジェクトの全員**を選ぶとロールが削除されます。その際は、**ロールを削除して保存**で確定します。
- ダイアログを開いている間に別のユーザーがダッシュボードを保存した場合、ダイアログが再読み込みされ、内容を確認して再度保存するよう求められます。

グループのメンバーシップの変更は約1分以内に反映されます。グループにユーザーを追加すればそのユーザーはダッシュボードを開けるようになり、削除すれば開けなくなります。サインアウトの必要はありません。ダッシュボードサービスにあるダッシュボードのプロパティにも同じ対象ユーザーが読み取り専用で表示され、このダイアログに戻る **Manage in PlaidCloud** リンクが表示されます。

### コピーは対象ユーザーを引き継ぐ

ダッシュボードのコピーは元のダッシュボードと同じ対象ユーザーになるため、コピーが元より多くの人に表示されることはありません。対象ユーザーの制限がないダッシュボードを閲覧できる人は誰でも、名前を付けて保存でコピーできます。グループに制限されたダッシュボードをコピーできるのは、所有者とワークスペース管理者だけです。

## アクセスのリクエスト

プロジェクト内でダッシュボードのグループに属していないユーザーがダッシュボードを開くと、ダッシュボードの所有者名が記載された **Request access** ページが表示されます。任意のメモを追加して、リクエストを送信します。ダッシュボードのどのプロジェクトにもアクセスできないユーザーには、ダッシュボードが存在しないか、利用できないことだけが表示されます。

所有者とワークスペース管理者には、リクエストしたユーザーとそのメモが記載されたメールが届きます。メールを開くと、ダッシュボードの**閲覧できるユーザー**ダイアログが開き、**アクセスリクエスト**パネルが表示されます。

- **Add one of the groups the requester is already in** には、リクエストしたユーザーが属しているグループが一覧表示されます。自動でチェックが入るグループはありません。1つ選択して**保存**を選択すると、アクセス権が付与されます。
- **閉じる**を選択すると、何も付与せずにリクエストを閉じます。

リクエストは、そのユーザーがアクセス権を得たとき、または誰かが閉じたときに終了します。リクエストしたユーザーが対象となるグループに属していない場合は、[セキュリティグループと割り当ての管理](/ja/administration/access/managing-security-groups-and-assignments/)でグループに追加してください。

## ダッシュボードアクセスレビュー

ワークスペース管理者は、ダッシュボードのツールバーにある**アクセスレビュー**を開くと、すべてのダッシュボードを一度に監査できます。**ダッシュボードアクセスレビュー**には、各ダッシュボードの対象ユーザー、グループ、人数、所有者、最終変更日時と変更者、**データの公開範囲**が一覧表示されます。

**表示**を使って、**制限あり**、**プロジェクトの全員**、**所有者のみ (下書き)**、**限定公開**、**カスタム (Supersetロール)**、**制限ありですがデータが保護されていません**（データセットに行ルールがない制限付きダッシュボード）、**所有者が退出済み**で絞り込めます。ダッシュボードを選択すると、その対象ユーザーのダイアログが開きます。**行アクセスを開く**を選択すると、保護されていないデータセットの行アクセス画面に移動します。**CSVをダウンロード**を選択すると、絞り込んだ状態の一覧がエクスポートされます。

レビューの対象は、ご自身がアクセスできるプロジェクトです。ダッシュボードがアクセスできないプロジェクトも使用している場合は、その旨が表示されます。

## 複数のダッシュボードをまとめて変更する

マイダッシュボードで最大50件のダッシュボードを選択し、**対象ユーザーを設定…** を選びます。ダイアログには、選択したすべてのダッシュボードを閲覧できるグループだけが表示され、**影響**の行にはそれらすべての合計が表示されます。完了すると、**結果**に、変更されたダッシュボード、スキップされたダッシュボード、失敗したダッシュボード、競合したダッシュボードの数が報告され、スキップされたダッシュボードにはそれぞれ理由が示されます。たとえば、所有していないダッシュボードや、**Supersetロールを削除して、それも保存**を選択していないのに Superset のロールが設定されているダッシュボードなどです。

## 新規ダッシュボードのデフォルトの対象ユーザー

プロジェクトは、そのデータに基づいて作成されたダッシュボードを誰が閲覧できるかを決めることができます。プロジェクトのホームタブにある**デフォルトのダッシュボード対象者**は、**プロジェクトの全員**（デフォルト）または**特定のグループ**のどちらかで、後者の場合は新規ダッシュボードを制限するグループを指定します。

デフォルトが適用されるのは、ダッシュボードを最初に公開するときで、既存のダッシュボードには適用されません。所有者が対象ユーザーを選択したダッシュボードは、明示的に**プロジェクトの全員**を選んだ場合も含め、その選択が維持されます。複数のプロジェクトにまたがるダッシュボードには、それらすべてのデフォルトに共通するグループが適用されます。すべてに共通するグループがない場合は、所有者向けの下書きとして始まります。グループではなく個々のメンバーと共有されているプロジェクトには、設定できるデフォルトの対象ユーザーがありません。

## AI アシスタントの利用

`dashboard_audience_manage` ツールを使うと、AI アシスタントや MCP サーバーから同じ操作ができます。ダッシュボードの対象ユーザーの取得（**get**）、変更のプレビュー（**preview**）、設定（**set**）、アクセスのリクエスト（**request**）と却下（**dismiss**）を実行できます。
