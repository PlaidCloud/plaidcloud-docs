## 概要

ダッシュボードを使用すると、アクセス権を持つ任意のプロジェクトまたはワークスペースのデータに対して、インタラクティブなビューを作成できます。1つのダッシュボードで、複数のプロジェクトのテーブルを組み合わせたり、可視化と生データの探索を併用したりでき、定型レポートにもアドホック分析にも対応します。ダッシュボードは、小規模な参照テーブルから数十億行のデータセットまで、構成を変更せずにスケールします。

## ダッシュボードアカウント

ダッシュボードアカウントは、PlaidCloudから初めてダッシュボードを開いたときに設定されるため、手動で作成する必要はありません。表示できる内容は、PlaidCloudのワークスペースのメンバーシップとセキュリティグループによって決まります。

<Aside>ユーザーの追加、変更、削除は、ダッシュボードサービス内ではなくPlaidCloudで行ってください。[ワークスペースメンバーの管理](/ja/administration/access/overview/managing-workspace-members/)を参照してください。ダッシュボードサービスで直接ユーザーアカウントを作成できるのは管理者のみで、その方法で作成したアカウントは、ワークスペースのメンバーシップと関連付けられません。</Aside>

## 表示されるダッシュボード

PlaidCloudの**ダッシュボード**ページには、アクセスできるプロジェクトに属する、公開済みのダッシュボードが表示されます。これが通常のケースで、ほぼすべてのダッシュボードが該当します。

ダッシュボードの所有者とワークスペース管理者は、特定のセキュリティグループのみにダッシュボードを制限できます。制限されたダッシュボードは、それらのグループのメンバーと、すべてのダッシュボードを表示できる所有者およびワークスペース管理者にのみ表示されます。制限のないダッシュボードは、そのプロジェクトにアクセスできるすべてのユーザーに表示されるため、1つのダッシュボードを制限しても、他のダッシュボードの表示範囲が変わることはありません。

ダッシュボードが一覧に表示されない場合は、次の2点を確認してください。

- **制限されたダッシュボードは、開けないだけでなく、一覧からも非表示になります。** ダッシュボードのプロジェクトにアクセスでき、そのリンクを開いた場合は、**Request access**ページが表示されます。それ以外の場合は、削除されたものと決めつけず、所有者に問い合わせてください。
- **制限されたダッシュボードが表示されるには、ダッシュボードアカウントが存在している必要があります。** アカウントは、PlaidCloudから初めてダッシュボードを開いたときに作成され、その時点でグループが適用されます。

<Aside>PlaidCloudで誰がダッシュボードを閲覧できるかは、**閲覧できるユーザー**で設定します。[ダッシュボードを閲覧できるユーザーの制御](/ja/guides/dashboards/control-who-can-see-a-dashboard/)を参照してください。プロジェクトのアクセス権は引き続きその上に適用されます。ダッシュボードを閲覧できても、アクセスできないプロジェクトのデータが表示されることはありません。</Aside>

## ダッシュボードワークスペース

**ダッシュボード**は、左側のレールと、その横に選択したページが表示される形で開きます。ページを開けないメンバーには、その項目は表示されません。ページの上部にはタイトルがあり、短いサブタイトルが付くことも多く、その横のヘッダーにはアクションが表示されます。

| レールの項目 | 表示される内容 |
|---|---|
| **概要** | **ダッシュボード**、**Visible to everyone**、**制限あり**、**You manage**、**Apps ready**、**Apps failed**のタイルです。タイルを選択すると、すでにフィルターされた状態でそのリストが開きます。**Recently opened and favorites**には、このデバイスで最近開いた、またはスターを付けた項目が一覧表示されます。**要対応**には、失敗したアプリと、自分への承認待ちのアクセスリクエストが一覧表示され、**確認**をクリックすると、自分が管理するダッシュボードが開きます。**Most opened in the last 30 days**は、利用状況へのアクセス権を持つメンバーに表示されます。 |
| **ダッシュボード** | 表示できるダッシュボードです。リストの上で、**すべて**、**You manage**、**お気に入り**を選択します。列には、**対象ユーザー**、**所有者**、**Opens (30 days)** などがあります。**Import dashboard archive…** ボタンと**対象ユーザーを設定…** ボタンはツールバーにあります。 |
| **アプリ** | プロジェクト上に構築されたPanelアプリ、Dashアプリ、ブラウザーアプリで、**種類**、**ステータス**、**プロジェクト**が表示されます。ステータスはリアルタイムで更新されます。**New app**メニューには、**Panelアプリ**の見出しの下に**Studio**、**Browser only**、**Server based**が、続いて**Dashアプリ**と**From gallery…** メニュー項目があります。**タイプ**列にも同じ名前が使用されます。 |
| **Notebooks** | JupyterLiteのデプロイメントです。 |
| **アクセスレビュー** | **管理者**の下にあり、ワークスペース管理者向けです。[ダッシュボードを閲覧できるユーザーの制御](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ダッシュボードアクセスレビュー)を参照してください。 |
| **Open navigator ↗** | レールの下部にあります。矢印は、これが独自のウィンドウで開く唯一の項目であることを示します。ダッシュボードサービスが新しいタブで開きます。 |

**ダッシュボード**と**アプリ**の横の数字は、表示できる件数を示します。

## ダッシュボードページからのダッシュボードの表示

**ダッシュボード**ページで、ダッシュボードの行の先頭にある**開く**アイコンをクリックすると、新しいタブで開きます。行をダブルクリックしても開きます。

### 行アクションメニュー

**ダッシュボード**ページを含め、PlaidCloudで行ごとのアクションがあるすべてのリストには、行アクションメニューがあります。行の先頭の **⋯** ボタン、行の右クリック、またはツールバーの**アクション**メニューから開きます。メニューは常に同じ構成です。

1. **開く**、**詳細**、**編集**（この順序）。
2. **アクセス**、**グループ**、**パスワードをリセット**、**複製**など、そのリスト独自のアクション。
3. **削除**または**削除**（最後）。

グループの間には区切り線があります。選択した行に適用できないアクションは、そのままの位置でグレー表示になるため、行が変わっても項目の位置が移動することはありません。

2つの項目にはショートカットが表示されます。**Enter**キーで実行される項目（行を開く）には**Enter**と表示されます。**Delete**キーで実行される項目には**Del**（Macでは**Backspace**）と表示されます。

行に対するアクションが1つしかないリストでは、**⋯** の代わりに、そのアクションのアイコンが行の先頭に表示されます。アイコンをクリックするとアクションが実行されます。破壊的なアクションの場合は、引き続き確認が求められます。そのアクションを実行できない行には、アイコンは表示されません。

### 標準、ゆったり、カードのビュー

**ダッシュボード**、**アプリ**、ERPの**レジスター**、Identityの**メンバー**など、PlaidCloudのワークスペースアプリのリストには、ツールバーに**ビュー**メニューがあり、次の3つから選択できます。

- **Standard rows**：コンパクトなリストで、1行に1件を表示します。
- **Roomy rows**：各行の周囲に余白を多く取った同じリストです。
- **Cards**：行ごとに1枚のカードを表示します。**ダッシュボード**のカードにはダッシュボードのサムネイルが表示され、ERPレジスターのカードには金額、日付、エンティティ、接続、ドキュメントが表示されます。

カードはリストと同じように動作します。カードを選択し、Shiftキーで選択範囲を拡張し、**ビュー**メニューで並べ替えと列の選択を行い、右クリックで**コピー**と行のアクションを実行し、**ダッシュボード**や**アプリ**のようにお気に入りのあるリストでは、星をクリックしてお気に入りに追加します。

## 数値の理由を尋ねる

ダッシュボードで、チャートのポイントまたはテーブルチャートのセルを右クリックし、**Why this number**を選択します。PlaidCloudが新しいタブで開き、Weaveが、その数値を書き込むステップ、その数値の元になるもの、前回の実行からどう変化したかを示します。[数値の理由](/ja/guides/ai-assistant/weave-numbers/#この数値の根拠)を参照してください。

## セッションの有効期限が切れた後にダッシュボードのリンクを開く

ダッシュボードへのリンクを開いたときにセッションの有効期限が切れている場合は、ダッシュボードのホームページではなく、サインインを求められ、その後、そのダッシュボードに移動します。

## 表示コントロール

表示コントロールは、ダッシュボードを閲覧するすべてのユーザーが、チャートを編集用に開かなくても、チャートのグループ化の基準を変更できる（たとえば、「Region」を「Product Line」に切り替える）フィルターバーのコントロールです。ダッシュボードの編集者は、フィルターバーの設定メニューで**Add or edit filters and controls**を選択し、**新規**メニューから**Add display control**を選択して、表示コントロールを追加および設定します。

### 表示する列の制限

デフォルトでは、表示コントロールのドロップダウンには、基になるデータセットで**Is filterable**にマークされているすべての列が一覧表示されます。列数の多いデータセットでは、目的の列を探すために数百の列をスクロールする必要があることもあります。

すべての表示コントロールの構成パネルに、専用の**Available columns**フィールドが追加されました。特定の列のリストを設定すると、そのコントロールのドロップダウンには、それらの列のみが表示されます。空のままにすると、コントロールはこれまでどおりに動作し、フィルター可能なすべての列が表示されます。これまでどおり動作させるために、ダッシュボードを変更する必要はありません。

表示コントロールを制限するには：

1. フィルターバーの設定メニューから**Add or edit filters and controls**を開きます。
2. 制限する表示コントロールを選択するか、新しいコントロールを追加します。
3. **Available columns**で、閲覧者に表示する列を検索して選択します。
4. 保存します。

### 「Is Filterable」との関係

**Available columns**には、データセットですでに**Is filterable**にマークされている列のみが表示されます。このリストをさらに絞り込むものであり、それを回避するものではありません。列の**Is filterable**のチェックを外すと、**Available columns**、アドホックフィルター、ネイティブフィルター、そのデータセットに対して構築されたすべてのチャートの**Simple Metric**ピッカーなど、あらゆる場所からその列が削除されることに変わりはありません。

この影響範囲の広さこそ、**Available columns**が存在する理由です。これが追加される前は、表示コントロールのドロップダウンを短くする唯一の方法は、そこに表示したくない列の**Is filterable**のチェックを外すことでしたが、その場合、そのデータセットのすべてのチャートのメトリックピッカーからも同じ列が非表示になってしまいました。メトリックまたはアドホックフィルターとしてチャートで必要になる可能性のあるすべての列では、**Is filterable**をチェックしたままにし、各表示コントロールのGroup Byドロップダウンに何を表示するかは、そのコントロール自身の**Available columns**で決定してください。

<Aside type="caution">表示コントロールの**Available columns**リストにある列の名前変更や削除は、自動的には検出されません。コントロールは、次に開いたときに、警告なしに表示する列が少なくなるだけです。データセットの列の名前変更または削除を行った後は、表示コントロールの**Available columns**を見直してください。</Aside>

### 保存される場所

**Available columns**は、そのコントロールの他の設定とともに、表示コントロールごとに保存されます。エクスポートとインポートを通じてダッシュボードとともに移動し、同じダッシュボード上の他のコントロールにも、同じデータセットから構築された他のダッシュボードにも影響しません。

## テーブルの編集


新しいテーブルを作成した後に表示されるメッセージでも、テーブル構成の編集が案内されます。構成を編集するための高度な機能はほかにもありますが、ここでは限定的でシンプルな部分から始めます。テーブル構成を編集するには：


1. 目的のテーブルの編集アイコンをクリックします
2. 「List Columns」タブをクリックします
3. 列を好みに合わせて並べ替えます
4. 「保存」をクリックします

これにより、データを探索するときに、テーブルの特定の列をどのように使用するかを定義できます。


* **Groupable：** 特定のフィールドでメトリックをグループ化できるようにする場合
* **Filterable：** 特定のフィールドでフィルターする必要がある場合
* **Count Distinct：** このフィールドの個別カウントを取得する場合
* **合計：** 合計するメトリックの場合
* **最小：** 基本的な要約統計量を収集するメトリックの場合
* **最大：** 基本的な要約統計量を収集するメトリックの場合
* **Is temporal：** 日付または時刻のフィールドにはチェックを入れてください

## データの探索


データの探索を開始するには、目的のテーブルをクリックするだけです。デフォルトでは、テーブルビューが表示されます。



### データ件数の取得


テーブル内のすべてのレコードの件数を取得するには：


1. フィルターを「Since」に変更します
2. 目的のsinceフィルターを入力します


	* 「3 years ago」のような簡単なフレーズを使用できます
3. 目的のuntilフィルターを入力します


	* 時間の上限のデフォルトは「now」です
4. 「グループ化」ヘッダーを選択します
5. メトリックセクションに「Count」と入力します
6. 「COUNT(*)」を選択します
7. 「Query」ボタンをクリックします

結果がテーブルに表示されます。

**特定のフィールドや制限の件数を調べるには：**

1. 「グループ化」フィールドに、目的の制限を入力します
2. クエリを実行します

<Aside>制限で「measurement」を使用すると、測定された値を指し、その値は測定の種類によって異なります。そのため、「filter section（例：weather_description と Maximum temperature）」の下で、測定の種類が同じであることを確認してください。</Aside>

### 結果数の制限

上位10件など、一定の件数の結果のみが必要な場合：

1. 「Options」を選択します
2. 「Row Limit」セクションに、目的の最大結果件数を入力します
3. 「Query」をクリックします

### その他の可視化ツール

省略された値を完全な長さに展開するには：

1. 「Edit Table Config」を選択します
2. 「List Sql Metric」をクリックします
3. 「Edit Metric」をクリックします
4. 「D3Format」をクリックします

測定単位を編集するには：


1. 「Edit Table Config」を選択します
2. 「List Sql Metric」をクリックします
3. 「Edit Metric」をクリックします
4. 「SQL Expression」をクリックします

チャートの種類を変更するには：


1. 「Chart Options」までスクロールします
2. 必要なフィールドに入力します
3. 「Query」をクリックします

ここから、軸ラベル、余白、目盛りなどを設定できます。
