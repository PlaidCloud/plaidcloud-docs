## 概要

ダッシュボードを使用すると、アクセス権のあるあらゆるプロジェクトやワークスペースのデータに対して、インタラクティブなビューを構築できます。1つのダッシュボードで複数のプロジェクトのテーブルを組み合わせたり、可視化と生データの探索を併用したりでき、定型レポートにもアドホック分析にも使用できます。ダッシュボードは、小さな参照テーブルから数十億行のデータセットまで、設定を変更せずに対応できます。

## ダッシュボードアカウント

ダッシュボードアカウントは、PlaidCloudから初めてダッシュボードを開いたときに自動で設定されるため、手動で作成する必要はありません。表示できる内容は、PlaidCloudのワークスペースのメンバーシップとセキュリティグループによって決まります。

<Aside>ユーザーの追加、変更、削除は、ダッシュボードサービス内ではなくPlaidCloudで行ってください。詳しくは[ワークスペースメンバーの管理](/ja/administration/access/overview/managing-workspace-members/)をご覧ください。ダッシュボードサービスで直接ユーザーアカウントを作成できるのは管理者のみであり、その方法で作成したアカウントはワークスペースのメンバーシップと連携しません。</Aside>

## 表示されるダッシュボード

PlaidCloudの **ダッシュボード** ページには、アクセスできるプロジェクトに属する公開済みのダッシュボードが表示されます。これが通常のケースであり、ほとんどのダッシュボードが該当します。

ダッシュボードのオーナーとワークスペース管理者は、ダッシュボードを特定のセキュリティグループに限定できます。制限されたダッシュボードは、それらのグループのメンバー、オーナー、およびすべてのダッシュボードを閲覧できるワークスペース管理者にのみ一覧表示されます。制限のないダッシュボードは、そのプロジェクトにアクセスできるすべてのユーザーに一覧表示されるため、1つのダッシュボードを制限しても、ほかのダッシュボードの閲覧範囲は変わりません。

一覧にダッシュボードが表示されない場合は、次の2点を確認してください。

- **制限されたダッシュボードは、開けないだけでなく一覧からも非表示になります。** ダッシュボードのプロジェクトにアクセスでき、そのリンクを開ける場合は **Request access** ページが表示されます。そうでない場合は、削除されたと決めつけずにオーナーに問い合わせてください。
- **制限されたダッシュボードが表示されるには、ダッシュボードアカウントが存在している必要があります。** アカウントは、PlaidCloudから初めてダッシュボードを開いたときに作成され、そのときにグループが適用されます。

<Aside>ダッシュボードを閲覧できるユーザーは、PlaidCloudの **閲覧できるユーザー** で設定します。詳しくは[ダッシュボードの閲覧者を制御する](/ja/guides/dashboards/control-who-can-see-a-dashboard/)をご覧ください。プロジェクトへのアクセス権は引き続き適用されます。ダッシュボードが見えるようになっても、アクセスできないプロジェクトのデータが見えるようになることはありません。</Aside>

## ダッシュボードワークスペース

**ダッシュボード** を開くと、左側にレールが、その横に選択したページが表示されます。ページを開けないメンバーには、その項目は表示されません。

| レールの項目 | 表示内容 |
|---|---|
| **概要** | **ダッシュボード**、**Visible to everyone**、**制限あり**、**You manage**、**Apps ready**、**Apps failed** のタイル。タイルを選択すると、あらかじめ絞り込まれた一覧が開きます。**Recently opened and favorites** には、このデバイスで最近開いたものやお気に入りに登録したものが一覧表示されます。**要対応** には、失敗したアプリと対応待ちのアクセスリクエストが一覧表示され、**確認** を選択すると、管理しているダッシュボードが開きます。**Most opened in the last 30 days** は、利用状況へのアクセス権を持つメンバーに表示されます。 |
| **ダッシュボード** | 閲覧できるダッシュボード。一覧の上で **すべて**、**You manage**、**お気に入り** を選択します。列には **対象ユーザー**、**所有者**、**Opens (30 days)** などがあります。ツールバーには **Import dashboard archive…** ボタンと **対象ユーザーを設定…** ボタンがあります。 |
| **アプリ** | プロジェクト上に構築された Panel、Dash、ブラウザーアプリ。**種類**、**ステータス**、**プロジェクト** が表示されます。ステータスはリアルタイムで更新されます。**New app** には **サーバー** などのアプリの種類があり、**ギャラリー** ではテンプレートから開始できます。 |
| **Notebooks** | JupyterLite のデプロイ。 |
| **アクセスレビュー** | **管理者** の下にあり、ワークスペース管理者向けです。[ダッシュボードの閲覧者を制御する](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ダッシュボードアクセスレビュー)を参照してください。 |
| **Open navigator** | レールの下部にあります。ダッシュボードサービスを新しいタブで開きます。 |

**ダッシュボード** と **アプリ** の横の件数は、閲覧できる数を示します。

## ダッシュボードページからダッシュボードを開く

**ダッシュボード** ページで、ダッシュボードの行の先頭にある **開く** アイコンをクリックすると、新しいタブでダッシュボードが開きます。行をダブルクリックしても開けます。

### 行アクションメニュー

**ダッシュボード** ページを含め、PlaidCloudで行ごとのアクションがあるすべての一覧には、行アクションメニューがあります。メニューは、行の先頭にある **⋯** ボタン、行の右クリック、またはツールバーの **アクション** メニューから開けます。メニューの構成は常に同じです。

1. **開く**、**詳細**、**編集**（この順）。
2. **アクセス**、**グループ**、**パスワードをリセット**、**複製** など、その一覧に固有のアクション。
3. 最後に **削除**。

グループの間は区切り線で分けられます。選択した行に適用できないアクションは、その位置のままグレーアウトされるため、行が変わっても項目の位置は動きません。

2つの項目にはショートカットが表示されます。**Enter** キーで実行される項目（行を開く項目）には **Enter** が表示されます。**Delete** キーで実行される項目には **Del**（Macでは **Backspace**）が表示されます。

行のアクションが1つだけの一覧では、**⋯** の代わりに、そのアクションのアイコンが行の先頭に表示されます。アイコンをクリックするとアクションが実行されます。削除などの破壊的な操作では、引き続き確認が求められます。そのアクションを実行できない行には、アイコンは表示されません。

## セッション期限切れ後にダッシュボードのリンクを開く

セッションの期限が切れた状態でダッシュボードへのリンクを開くと、サインインを求められ、サインイン後にダッシュボードのホームページではなく、そのダッシュボードが表示されます。

## 表示コントロール

表示コントロールは、ダッシュボードを閲覧しているユーザーが、チャートを編集用に開かなくても、チャートのグループ化の基準（たとえば「Region」から「Product Line」への切り替え）を変更できるフィルターバーのコントロールです。ダッシュボードの編集者は、フィルターバーの設定メニューから表示コントロールを追加および設定します。**Add or edit filters and controls** を選択し、**新規** メニューから **Add display control** を選択します。

### 表示される列を制限する

デフォルトでは、表示コントロールのドロップダウンには、基になるデータセットで **Is filterable** に設定されているすべての列が表示されます。列数の多いデータセットでは、目的の列を探すために数百の列をスクロールすることになる場合があります。

すべての表示コントロールの設定パネルに、専用の **Available columns** フィールドが追加されました。列の一覧を指定すると、コントロールのドロップダウンにはそれらの列だけが表示されます。空のままにすると、これまでどおり、フィルター可能なすべての列が表示されます。既存のダッシュボードを変更する必要はありません。

表示コントロールを制限するには、次の手順を実行します。

1. フィルターバーの設定メニューから **Add or edit filters and controls** を開きます。
2. 制限する表示コントロールを選択するか、新しい表示コントロールを追加します。
3. **Available columns** で、閲覧者に表示する列を検索して選択します。
4. 保存します。

### 「Is filterable」との関係

**Available columns** に表示されるのは、データセットで **Is filterable** に設定済みの列のみです。この一覧をさらに絞り込むもので、その制約を回避するものではありません。列の **Is filterable** をオフにすると、**Available columns**、アドホックフィルター、ネイティブフィルター、そのデータセットに基づくすべてのチャートの **Simple Metric** ピッカーなど、あらゆる場所からその列が除外されます。

この影響範囲の広さこそが、**Available columns** が存在する理由です。これまで、表示コントロールのドロップダウンを短くする唯一の方法は、表示したくない列の **Is filterable** をオフにすることでしたが、その場合、同じ列がそのデータセットのすべてのチャートのメトリックピッカーからも非表示になっていました。チャートでメトリックやアドホックフィルターとして使う可能性のある列は、すべて **Is filterable** をオンのままにし、各コントロールが Group By ドロップダウンに表示する内容は、表示コントロールごとの **Available columns** で決めてください。

<Aside type="caution">表示コントロールの **Available columns** 一覧にある列の名前を変更または削除しても、自動的には検出されません。次にコントロールを開いたときに、警告なしに表示される列が減るだけです。データセットの列の名前を変更または削除した後は、表示コントロールの **Available columns** を見直してください。</Aside>

### 保存場所

**Available columns** は、そのコントロールのほかの設定とともに、表示コントロールごとに保存されます。エクスポートとインポートでもダッシュボードとともに引き継がれ、同じダッシュボードやほかのダッシュボードにある、同じデータセットに基づくほかのコントロールには影響しません。

## テーブルを編集する

新しいテーブルを作成した後に表示されるメッセージでも、テーブル設定の編集が案内されます。設定の編集にはより高度な機能もありますが、ここでは限定的でシンプルな部分から始めます。テーブル設定を編集するには、次の手順を実行します。


1. 対象のテーブルの編集アイコンをクリックします
2. “List Columns” タブをクリックします
3. 列を好みの順序に並べ替えます
4. “Save” をクリックします

これにより、データを探索する際にテーブルの特定の列をどのように使用するかを定義できます。


* **Groupable:** 特定のフィールドでユーザーがメトリックをグループ化できるようにする場合
* **Filterable:** 特定のフィールドでフィルターする必要がある場合
* **Count Distinct:** このフィールドの重複を除いた件数を取得する場合
* **合計:** 合計するメトリックの場合
* **最小:** 基本的な要約統計を取得するメトリックの場合
* **最大:** 基本的な要約統計を取得するメトリックの場合
* **Is temporal:** 日付または時刻のフィールドにはオンにします

## データを探索する


データの探索を始めるには、目的のテーブルをクリックするだけです。デフォルトでは、テーブルビューが表示されます。



### データ件数を取得する


テーブル内のすべてのレコードの件数を取得するには、次の手順を実行します。


1. フィルターを “Since” に変更します
2. 目的の開始フィルターを入力します


	* “3 years ago” のような簡単な表現を使用できます
3. 目的の終了フィルターを入力します


	* 時間の上限のデフォルトは “now” です
4. **グループ化** ヘッダーを選択します
5. メトリックのセクションに “Count” と入力します
6. “COUNT(*)” を選択します
7. “Query” ボタンをクリックします

結果がテーブルに表示されます。

**特定のフィールドや条件の件数を取得する場合：**

1. **グループ化** フィールドに目的の条件を入力します
2. クエリを実行します

<Aside>制限条件に “measurement” を使用すると、測定された値を参照します。この値は測定の種類によって異なります。そのため、“filter” セクションで測定の種類が同じであることを確認してください（例：weather_description と Maximum temperature）。</Aside>

### 結果の件数を制限する

上位10件など、一定の件数の結果だけが必要な場合は、次の手順を実行します。

1. “Options” を選択します
2. “Row Limit” セクションに、結果の最大件数を入力します
3. “Query” をクリックします

### その他の可視化ツール

省略された値を完全な長さに展開するには、次の手順を実行します。

1. “Edit Table Config” を選択します
2. “List Sql Metric” をクリックします
3. “Edit Metric” をクリックします
4. “D3Format” をクリックします

測定単位を編集するには、次の手順を実行します。


1. “Edit Table Config” を選択します
2. “List Sql Metric” をクリックします
3. “Edit Metric” をクリックします
4. “SQL Expression” をクリックします

チャートの種類を変更するには、次の手順を実行します。


1. “Chart Options” までスクロールします
2. 必要なフィールドを入力します
3. “Query” をクリックします

ここから、軸ラベル、余白、目盛りなどを設定できます。
