## 概要

ダッシュボードを使用すると、アクセス権を持つ任意のプロジェクトやワークスペースのデータに対して、インタラクティブなビューを構築できます。1つのダッシュボードで複数のプロジェクトのテーブルを組み合わせ、可視化と生データの探索を併用し、定型レポートとアドホック分析の両方に対応できます。ダッシュボードは、小さな参照テーブルから数十億行のデータセットまで、設定を変更することなく拡張できます。

## ダッシュボードアカウント

ダッシュボードアカウントは、PlaidCloud から初めてダッシュボードを開いたときに自動的に設定されるため、手動で作成する必要はありません。表示できる内容は、PlaidCloud ワークスペースのメンバーシップとセキュリティグループによって決まります。

<Aside>ユーザーの追加、変更、削除は、ダッシュボードサービス内ではなく PlaidCloud で行ってください。詳しくは[ワークスペースメンバーの管理](/ja/administration/access/overview/managing-workspace-members/)を参照してください。ダッシュボードサービス内で直接ユーザーアカウントを作成できるのは管理者のみです。この方法で作成されたアカウントは、ワークスペースのメンバーシップとは紐付けられません。</Aside>

## 表示されるダッシュボード

PlaidCloud の**ダッシュボード**ページには、アクセスできるプロジェクトに属する公開済みのダッシュボードが表示されます。これが通常のケースであり、ほぼすべてのダッシュボードが該当します。

ダッシュボードの所有者とワークスペース管理者は、特定のセキュリティグループにダッシュボードを限定できます。制限されたダッシュボードは、それらのグループのメンバーと、すべてのダッシュボードが表示される所有者およびワークスペース管理者にのみ一覧表示されます。制限のないダッシュボードは、そのプロジェクトにアクセスできるすべてのユーザーに一覧表示されるため、1つのダッシュボードを制限しても、他のダッシュボードを閲覧できるユーザーは変わりません。

一覧にダッシュボードが表示されない場合は、次の2点に注意してください。

- **制限されたダッシュボードは、開けないだけでなく一覧からも非表示になります**。ダッシュボードのプロジェクトにアクセスでき、そのリンクを開くと、**Request access** ページが表示されます。そうでない場合は、削除されたと決めつけずに所有者に問い合わせてください。
- **制限されたダッシュボードがユーザーに届くには、ダッシュボードアカウントが存在している必要があります**。アカウントは、PlaidCloud から初めてダッシュボードを開いたときに作成され、そのときにグループが適用されます。

<Aside>ダッシュボードを閲覧できるユーザーは、PlaidCloud の**閲覧できるユーザー**で設定します。詳しくは[ダッシュボードを閲覧できるユーザーの制御](/ja/guides/dashboards/control-who-can-see-a-dashboard/)を参照してください。プロジェクトのアクセス権は引き続き適用されます。ダッシュボードが表示されても、アクセスできないプロジェクトのデータが表示されることはありません。</Aside>

## ダッシュボードワークスペース

**ダッシュボード**を開くと、左側にレールが表示され、その横に選択したページが表示されます。ページを開く権限のないメンバーには、その項目は表示されません。各ページの上部にはタイトルと短いサブタイトルがあり、そのアクションは横のヘッダーに表示されます。

| レールの項目 | 表示内容 |
|---|---|
| **概要** | **ダッシュボード**、**Visible to everyone**、**制限あり**、**You manage**、**Apps ready**、**Apps failed** のタイル。タイルを選択すると、すでにフィルターされた一覧が開きます。**Recently opened and favorites** には、このデバイスで最近開いた、またはスターを付けたものが一覧表示されます。**要対応**には、失敗したアプリと、自分の対応待ちのアクセスリクエストが一覧表示され、**確認**を選択すると、自分が管理するダッシュボードが開きます。**Most opened in the last 30 days** は、利用状況へのアクセス権を持つメンバーに表示されます。 |
| **ダッシュボード** | 表示できるダッシュボード。一覧の上で**すべて**、**You manage**、**お気に入り**を選択します。列には**対象ユーザー**、**所有者**、**Opens (30 days)** があります。**Import dashboard archive…** と**対象ユーザーを設定…**はツールバーにあります。 |
| **アプリ** | プロジェクト上に構築された Panel、Dash、ブラウザーアプリ。**種類**、**ステータス**、**プロジェクト**が表示されます。ステータスはリアルタイムで更新されます。**New app** には**サーバー**とその他のアプリタイプがあり、**ギャラリー**ではテンプレートから開始します。 |
| **Notebooks** | JupyterLite のデプロイメント。 |
| **アクセスレビュー** | **管理者**の下にあり、ワークスペース管理者向けです。[ダッシュボードを閲覧できるユーザーの制御](/ja/guides/dashboards/control-who-can-see-a-dashboard/#ダッシュボードアクセスレビュー)を参照してください。 |
| **Open navigator ↗** | レールの下部にあります。矢印は、これが独自のウィンドウで開く唯一の項目であることを示しています。ダッシュボードサービスが新しいタブで開きます。 |

**ダッシュボード**と**アプリ**の横のカウントは、表示できる数を示します。

## ダッシュボードページからのダッシュボードの表示

**ダッシュボード**ページで、ダッシュボードの行の先頭にある**開く**アイコンをクリックすると、新しいタブで開きます。行をダブルクリックしても開きます。

### 行アクションメニュー

**ダッシュボード**ページを含め、PlaidCloud で行ごとのアクションがあるすべての一覧には、行アクションメニューがあります。行の先頭にある **⋯** ボタン、行の右クリック、またはツールバーの**アクション**メニューから開きます。メニューのレイアウトは常に同じです。

1. **開く**、**詳細**、**編集**（この順序）。
2. **アクセス**、**グループ**、**パスワードをリセット**、**複製**など、その一覧に固有のアクション。
3. 最後に**削除**または**削除**。

区切り線でグループが分けられます。選択した行に該当しないアクションは、位置はそのままでグレー表示になるため、行が変わっても項目の位置は変わりません。

2つの項目にはショートカットが表示されます。**Enter** キーで実行される項目（行を開く項目）には **Enter** と表示されます。**Delete** キーで実行される項目には **Del** と表示されます（Mac では **Backspace**）。

行のアクションが1つしかない一覧では、**⋯** の代わりに、そのアクションのアイコンが行の先頭に表示されます。アイコンをクリックするとアクションが実行されます。破壊的なアクションの場合は、引き続き確認が求められます。アクションを実行できない行にはアイコンが表示されません。

### 標準、ゆったり、カードの表示

**ダッシュボード**、**アプリ**、ERP の**レジスター**、ID の**メンバー**など、PlaidCloud のワークスペースアプリの一覧には、ツールバーに**ビュー**メニューがあり、3つの選択肢があります。

- **Standard rows**：1行に1項目を表示するコンパクトな一覧。
- **Roomy rows**：各行の周囲により多くの余白を設けた同じ一覧。
- **Cards**：行ごとに1枚のカード。**ダッシュボード**のカードにはダッシュボードのサムネイルが表示され、ERP レジスターのカードには金額、日付、エンティティ、接続、ドキュメントが表示されます。

カードは一覧と同じように動作します。カードを選択し、Shift キーで選択範囲を拡張し、**ビュー**メニューから並べ替えと列の選択を行い、右クリックで**コピー**と行のアクションを実行し、スターをクリックしてお気に入りに追加します。

## セッションの有効期限が切れた後のダッシュボードリンクの表示

ダッシュボードへのリンクを開いたときにセッションの有効期限が切れている場合は、ダッシュボードのホームページではなく、サインインを求められた後にそのダッシュボードへ移動します。

## 表示コントロール

表示コントロールは、ダッシュボードを閲覧しているすべてのユーザーが、チャートを開いて編集することなく、チャートのグループ化の基準（たとえば「リージョン」を「製品ライン」に切り替えるなど）を変更できる、フィルターバーのコントロールです。ダッシュボードの編集者は、フィルターバーの設定メニューから表示コントロールを追加および構成します。**Add or edit filters and controls** を選択し、**新規**メニューから **Add display control** を選択します。

### 表示される列の制限

デフォルトでは、表示コントロールのドロップダウンには、基になるデータセットで **Is filterable** とマークされているすべての列が一覧表示されます。列数の多いデータセットでは、目的の列を探すために数百の列をスクロールすることになりかねません。

すべての表示コントロールの設定パネルに、専用の **Available columns** フィールドが追加されました。特定の列のリストを設定すると、コントロールのドロップダウンにはそれらの列のみが表示されます。空のままにすると、コントロールはこれまでどおり動作し、フィルター可能なすべての列が表示されます。従来どおり動作させるために、ダッシュボードを変更する必要はありません。

表示コントロールを制限するには:

1. フィルターバーの設定メニューから **Add or edit filters and controls** を開きます。
2. 制限したい表示コントロールを選択するか、新しいものを追加します。
3. **Available columns** で、閲覧者に表示する列を検索して選択します。
4. 保存します。

### 「Is filterable」との関係

**Available columns** には、データセットですでに **Is filterable** とマークされている列のみが表示されます。このリストをさらに絞り込むものであり、それを迂回するものではありません。列の **Is filterable** のチェックを外すと、引き続きあらゆる場所からその列が削除されます。**Available columns**、アドホックフィルター、ネイティブフィルター、そしてそのデータセットに対して構築されたすべてのチャートの **Simple Metric** ピッカーからです。

このように影響範囲が広いことが、まさに **Available columns** が存在する理由です。これが導入される前は、表示コントロールのドロップダウンを短くする唯一の方法は、表示したくない列の **Is filterable** のチェックを外すことでした。しかし、その場合、そのデータセット上のすべてのチャートのメトリックピッカーからも同じ列が非表示になっていました。チャートがメトリックやアドホックフィルターとして必要とする可能性のあるすべての列で **Is filterable** をオンのままにし、各表示コントロールのグループ化のドロップダウンに何を表示するかは、各表示コントロール固有の **Available columns** で決めてください。

<Aside type="caution">表示コントロールの **Available columns** リストにある列の名前を変更したり削除したりしても、自動的には検出されません。コントロールは次回開いたときに、警告なしに表示される列が少なくなるだけです。データセットの列の名前を変更または削除した後は、表示コントロールの **Available columns** を見直してください。</Aside>

### 保存場所

**Available columns** は、そのコントロールの他の設定とともに、表示コントロールごとに保存されます。エクスポートとインポートでダッシュボードとともに移動し、他のコントロールには影響しません。同じダッシュボードでも、同じデータセットから構築された他のダッシュボードでも同様です。

## テーブルの編集


新しいテーブルを作成した後に表示されるメッセージでも、テーブルの構成を編集するよう案内されます。構成を編集するためのより高度な機能もありますが、ここでは限定的でシンプルな部分から始めます。テーブルの構成を編集するには:


1. 目的のテーブルの編集アイコンをクリックします
2. 「List Columns」タブをクリックします
3. 列を好みの順序に並べ替えます
4. 「保存」をクリックします

これにより、データを探索するときにテーブルの特定の列をどのように使用するかを定義できます。


* **グループ化可能**：ユーザーに特定のフィールドでメトリックをグループ化させたい場合
* **フィルター可能**：特定のフィールドでフィルターする必要がある場合
* **個別カウント**：このフィールドの個別のカウントを取得したい場合
* **合計**：合計したいメトリックの場合
* **最小**：基本的な要約統計量を収集したいメトリックの場合
* **最大**：基本的な要約統計量を収集したいメトリックの場合
* **時間項目**：日付または時刻のフィールドにはチェックを入れてください


## データの探索


データの探索を開始するには、目的のテーブルをクリックするだけです。デフォルトでは、テーブルビューが表示されます。



### データ件数の取得


テーブル内のすべてのレコードの件数を取得するには:


1. フィルターを「Since」に変更します
2. 目的の開始フィルターを入力します


	* 「3 years ago」のような簡単なフレーズを使用できます
3. 目的の終了フィルターを入力します


	* 時間の上限のデフォルトは「now」です
4. 「グループ化」ヘッダーを選択します
5. メトリックのセクションに「Count」と入力します
6. 「COUNT(*)」を選択します
7. 「Query」ボタンをクリックします

すると、テーブルに結果が表示されます。

**特定のフィールドや制約の件数を取得するには:**

1. 「グループ化」フィールドに目的の制約を入力します
2. クエリを実行します

<Aside>制約で「measurement」を使用する場合、それは取得された測定値を指し、測定の種類によって異なります。したがって、「フィルターセクション（例：weather_description と Maximum temperature）」で測定の種類が同じであることを確認してください。</Aside>

### 結果数の制限

上位10件など、特定の件数の結果のみが必要な場合:

1. 「Options」を選択します
2. 「Row Limit」セクションに、最大の結果件数を入力します
3. 「Query」をクリックします

### その他の可視化ツール

省略された値を完全な長さに展開するには:

1. 「Edit Table Config」を選択します
2. 「List Sql Metric」をクリックします
3. 「Edit Metric」をクリックします
4. 「D3Format」をクリックします

測定単位を編集するには:


1. 「Edit Table Config」を選択します
2. 「List Sql Metric」をクリックします
3. 「Edit Metric」をクリックします
4. 「SQL Expression」をクリックします

チャートのタイプを変更するには:


1. 「Chart Options」までスクロールします
2. 必須フィールドを入力します
3. 「Query」をクリックします

ここから、軸ラベル、余白、目盛りなどを設定できます。
