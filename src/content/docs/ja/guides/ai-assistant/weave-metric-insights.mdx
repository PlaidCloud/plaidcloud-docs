## 概要

Weaveは、プロジェクトの各[メトリック](/ja/integrations/ai-coding-agents/metric-definitions/)を
1日に1回読み取り、最新の完了済み期間を確認します。その期間のメトリックの合計値が
通常の範囲を外れており、かつ内訳のうち1つの項目（たとえば1社の顧客、1つの製品、
1か所の工場）が、合計に占める通常の割合から想定される以上に大きく変化している場合、
Weaveはプロジェクトの[Weaveタブ](/ja/guides/ai-assistant/weave-tab/)でその旨を報告し、
該当の項目名を示します。

AIモデルは使用しません。このチェックは固定のルールであり、すべての文は、Weaveが読み取った数値から
あらかじめ決められた形で作成されます。

## 検出事項の内容

```
Weave noticed the metric "Revenue": it came to 16.4M in April 2026, against an
average of 11.2M (usual range 8.9M to 13.5M) over the 12 months before.
"Seasonal Specials" (by product_group), usually 2% of the total, rose from an
average of 210.0K to 1.7M, 1.5M of the rise of 5.2M (29%); the other 3.7M came
from elsewhere
```

金額はK、M、Bに短縮して表示され、通貨や単位は表示されません。メトリック定義には通貨や単位が記録されないためです。
暦年の日付列を持つメトリックでは*April 2026*のように月が示され、それ以外のメトリックでは*period 8 of fiscal 2025*のように期間が示されます。

1つの項目の変動が合計全体の変動を上回った場合、検出事項はその旨と、それ以外の項目が
逆方向に動いたことを述べます。それ以前の期間に値がなかった項目は、値がなかったものとして記述されます。

**Weaveが把握する方法**には、対象期間、合計値、それ以前の期間の平均、比較した期間の数、通常の範囲、
最も大きく動いた項目、および通常より大きく動いたその他の項目が表示されます。

## Weaveがチェックするメトリック

次の条件を満たす、廃止されていないメトリックがチェックの対象です。

- **日付列**、または**年列と期間列**があり、比較できる期間を持っていること。
- **合計またはカウント**であること。Weaveは、これらを各項目の寄与分に分割できます。
- 何が動いたかを示すための**内訳列**（顧客や工場など）が少なくとも1つあること。
- **ほかのメトリックから計算されたものではない**こと。

Weaveは、各メトリックの現在のバージョンを、最後に保存したアーキテクトとして、
そのアーキテクトが閲覧できる範囲だけで読み取ります。Weaveがチェックするのは、プロジェクトごとに最大50個のメトリックで、
保存日時が古いものから順に対象となります。それを超えるメトリックは、未確認として一覧に表示されます。

条件を満たさないメトリックや、Weaveが読み取れなかったメトリックは、理由とともに
**Weaveが確認していないもの**として一覧に表示されます。問題なしとして数えられることはありません。

## チェックの仕組み

**判定する期間。** 日付列を持つメトリックでは、7日以上前に終了した最新の期間です。そのため、
締め処理中にまだ読み込み中の期間は判定されません。日付を持たない年列と期間列を持つメトリックでは、
値のある最新の通常期間の1つ前の期間です。ただし、その後ろにある調整期間（たとえば12期間の年における
期間13〜16）に値がある場合は、その年の最後の期間になります。期間0と調整期間が判定されることはありません。

**通常の範囲。** Weaveは、その期間の合計値を、それ以前の最大12期間と比較します。このうち値のある期間が
少なくとも6つ必要です。範囲は、これらの期間のばらつきの大きさから求められます。

**季節性のある期間。** 範囲を外れた合計値でも、直前の3年のうち少なくとも2年で同じ期間が
同様の結果だった場合は報告されません。期間が四半期に分割される暦では、5週間の月のように、
過去の四半期の同じ位置と整合している場合も報告されません。

**動いた項目。** Weaveは、合計値を最大5つの内訳列で分割します。ディメンションに関連付けられた列から順に使用します。
そして、変化に占める割合が、合計に占める通常の割合よりはるかに大きい場合にのみ、その項目を名指しします。
検出事項では、金額で最も大きく動いた項目が先頭に示されます。多数の項目に分散し、
それぞれが比例して動いた変化は報告されません。

**後からの調整。** ある期間について問題が報告されると、その後の読み取り結果が最初の値の0.5パーセント以内に
収まっている間は、最初に読み取った数値が維持されます。そのため、後から行われた小さな調整によって、
同じ問題が新たに報告し直されることはありません。

## Weaveが確認しないこと

- どの項目も際立っていない状態での、通常の範囲を外れた合計値。
- 合計値が通常の範囲内にある状態での、1つの項目の割合の変化。
- 最初の5つを超える内訳列、または項目と期間をまたいで50,000を超える値を持つ内訳列。
- その変動が誤りなのか、実際の業務上の動きなのか。
- 比較にのみ使用される、それ以前の期間。

## 表示される相手と通知される相手

検出事項は、メトリックを**最後に保存した**担当者のものとなり、その担当者には実行の合間にPlaidCloud内で通知されます。ほかの検出事項と同様に、
ダイジェストを有効にしているユーザーの[毎日のダイジェスト](/ja/guides/ai-assistant/weave-findings/#ダイジェスト)にも
含まれます。最後に保存した担当者がプロジェクトのアーキテクトでなくなった場合、Weaveは、
現在のアーキテクトが保存するまで、そのメトリックのチェックを停止します。

プロジェクトを読み取れるユーザーは、Weaveタブで検出事項を確認できます。
[行アクセス](/ja/administration/access/managing-security-groups-and-assignments/)が設定されたプロジェクトでは、
数値が保存者のアクセス権で読み取られているため、これらの検出事項を確認できるのはアーキテクトのみです。

各検出事項は、最初に報告された時点で、プロジェクトの
[Weaveアクティビティ履歴](/ja/guides/ai-assistant/weave-activity/)に記録されます。同じ期間の後の読み取りで
問題が確認されなくなると、履歴にはWeaveが問題を検出しなくなったことが記録されます。次の期間が締められると、
Weaveの毎日のチェックがその期間に移ったことが記録されます。メトリックが廃止されると、Weaveがチェックを停止したことが記録されます。

## メトリックへ移動

検出事項の**メトリックへ移動**を選択すると、クリックした時点で計算され、ご自身の行アクセスが適用されたメトリックが開きます。
合計値の異常の場合は、判定された期間でWeaveが名指しした項目が表示されます。Weaveがチェックできなかったメトリック
（ほかのメトリックから計算されるメトリックをすべて含む）の場合は、メトリックの合計値が表示されます。✓は、
その数値の算出元となったメトリックのバージョンを示します。表示される数値は現在のメトリックのものであるため、
Weaveが読み取った後にメトリックが変更されていると、検出事項の数値と異なる場合があります。

数値の下にある**行へ移動**を選択すると、メトリックのソーステーブルでテーブルエクスプローラーが開きます。項目、期間、
メトリック自体のフィルターで絞り込まれるため、変化の背後にある行を確認できます。このボタンは、テーブルを読み取れるユーザーに表示されます。
ルックアップテーブルを使用するメトリックでは表示されません。そのようなメトリックの行は、ソーステーブルだけでは確認できないためです。

<Aside type="note">
新しく保存したメトリックは、プロジェクトのメトリックがすでに50個ある場合を除き、1日以内に読み取られます。
それまでは、Weaveがまだ読み取っていないメトリックとして一覧に表示されます。
</Aside>

## Weaveがメトリックをチェックしなかった場合

| 表示される理由 | 対応 |
| --- | --- |
| ほかのメトリックから計算されている | 対応は不要です。Weaveがチェックするのは基本メトリックのみです。 |
| 平均、最小値、最大値、または重複を除いた値の数である | 対応は不要です。項目ごとに分割できるのは、合計とカウントのみです。 |
| 内訳がない | 顧客などの内訳列を追加し、新しいバージョンを保存してください。 |
| 日付列または期間列がない | 時間バインディングを追加し、新しいバージョンを保存してください。 |
| 年列または期間列に*2024-01*のような値が入っている | 時間バインディングを、整数の年列と期間列、または日付列に設定し直してください。 |
| 値のある期間が少数しかない | しばらくお待ちください。Weaveには、それ以前の期間が6つ必要です。 |
| その期間の値がない | その期間のデータが読み込まれたかを確認してください。 |
| 最後に保存した担当者がアーキテクトでなくなった | 現在のアーキテクトに保存してもらってください。 |
| 読み取りに2分を超える時間がかかった | Weaveは翌日に再試行します。 |
| すべての内訳が50,000を超える値を持っている | その状態が続く間、Weaveはチェックしません。 |
| 合計値が通常の範囲外だが、ある内訳が50,000を超える値を持っている | その内訳の1つの項目が変化の要因かどうかを、Weaveは判断できません。その内訳をご自身で確認するか、メトリックの内訳列から削除してください。 |
| プロジェクトのメトリックが50個を超えている | 誰も使っていないメトリックを廃止してください。保存日時が古いものから順にチェックされます。 |
| Weaveが現在のバージョンを読み取れなかった | Weaveは翌日に再試行します。 |
| Weaveの毎日のチェックが最後に実行されたのが数日前である | PlaidCloudの管理者にお問い合わせください。 |
