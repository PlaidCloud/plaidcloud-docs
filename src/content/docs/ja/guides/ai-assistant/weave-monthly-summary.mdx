## 説明

月次サマリーは、1か月間にWeaveがプロジェクトで行ったことを集計します。ワークフローの実行が終了したときに検出した問題、後のチェックで検出されなくなった問題、ユーザーの承認を得て行った変更、想定内として記録された問題が対象です。すべての数値は、プロジェクトの[Weaveアクティビティ履歴](/ja/guides/ai-assistant/weave-activity/)にあるエントリの件数で、各数値の根拠となるエントリを開くことができます。

ワークスペース管理者は、すべてのプロジェクトについて同じ件数をまとめたワークスペースサマリーも利用できます。

推定値は節約できた時間だけで、推定値であることとその算出方法が示されます。報告することがない月にはその旨が表示されます。

## 月次サマリーを開く

1. プロジェクトを開き、**Weave**タブを選択して、その中で**Monitor**を選択します。
2. レールの**月次サマリー**をクリックします。
3. 月を選択します。リストの先頭は当月で、たとえば**2026年10月の途中経過**のように表示され、その後に直前の11か月が続きます。

**Whose figures**で、**For the project**と**For you**を切り替えます。プロジェクトの全員に対してWeaveが行ったことか、ご自身に対してだけ行ったことかを表示します。**For you**には、検出された問題と検出されなくなった問題は含まれません。

ページ上部の**更新**をクリックすると、サマリーが再読み込みされます。**月次サマリー**は、**アクティビティ**と同様に、プロジェクトのステップ、ワークフロー、テーブルを読み取れるロールのユーザーに表示されます。月はUTCの暦月です。

![ある月の月次サマリーページ。3つの数値とエントリを表示するリンクが表示されている](/images/weave/weave-monitor-monthly.png)

## 各数値の集計対象

各数値の横には、何を集計しているかを説明する文が表示されます。サマリーに表示されるのは数値とその文だけで、次の表の1列目の名前はこのページでの説明用です。

| 数値 | 文 |
|---|---|
| 検出された問題 | *ワークフローの実行が終了したときに、Weaveが7件の問題を検出しました。各問題は、何回検出されても1件として数えます。* |
| 検出されなくなった | *今月、後のチェックで5件の問題が検出されなくなりました。以前の月に初めて検出された問題も含みます。* |
| Weaveの変更後に検出されなくなった | *そのうち2件は、問題の対象となるステップ、テーブル、またはワークフロー（ワークフローの場合はそのいずれかのステップ）に対して、Weaveが承認を得て変更を行った後に検出されなくなりました。これは出来事の順序を示すもので、変更によって問題が修正されたことを示すものではありません。Weaveが問題を検出してから（いったん解消した問題の場合は再び検出してから）、その問題が検出されなくなったチェックまでの時間の中央値: 26時間（2件の問題）。* |
| 実施した変更 | *Weaveは、ユーザーが承認した3件の変更を行いました。そのうち1件は、その後元に戻されています。* |
| 想定内として記録 | *1件の問題が想定内として記録されました。この問題は修正されていません。Weaveが問題として報告しなくなるだけです。* |
| 修正した失敗実行 | *Weaveは4件の失敗した実行を修正し、それぞれ再実行で確認しました。* |
| 再利用された回答 | *チームメンバーがピン留めされた回答を9回開きました。* |
| 今月の問題の現状 | *今月検出された7件の問題のうち、3件は検出されなくなり、1件は想定内として記録され、3件は未解決です。* |

**Weaveの変更後に検出されなくなった**は、その月に後のチェックで少なくとも1件の問題が検出されなくなった場合にのみ表示されます。**今月の問題の現状**は、その月にWeaveが少なくとも1件の問題を検出した場合にのみ表示されます。

数値の下にある**3件のエントリを表示**（エントリが1件の場合は**エントリを表示**）をクリックすると、その数値が集計しているアクティビティ履歴のエントリが、それぞれが記録された日時とともに一覧表示されます。**エントリを非表示**をクリックすると、一覧が折りたたまれます。根拠となるエントリがない数値には、ボタンは表示されません。今月の問題の現状では、エントリが**検出されなくなった**、**想定内として記録**、**未解決**の各グループに分けて、それぞれの件数とともに表示されます。**再利用された回答**の下では、**Show answer**で各[ピン留めされた回答](/ja/guides/ai-assistant/weave-team/#ピン留めした回答)が、開かれた回数と最後に開かれた日時とともに一覧表示されます。誰が開いたかは表示されません。

### 節約できた時間

数値の上には、*Weaveは4件の失敗した実行を修正し、それぞれ再実行で確認しました。チームメンバーがピン留めされた回答を9回開きました。これにより約2時間45分を節約しました。* のように、その月をまとめた1行が表示されます。その下には、推定値の前提が示されます。修正した失敗実行1件につき30分、チームメンバーがピン留めされた回答を1回開くごとに5分です。

- **再利用された回答**は、回答をピン留めした本人以外のユーザーが開いた回数だけを数えます。**For you**では、ご自身がピン留めした回答が開かれた回数を数えます。
- 月に1回、プロジェクトで最初にWeaveドックを開いたときに、先月そのプロジェクトでWeaveが節約したおおよその時間が**See how**とともに表示されます。これを選択すると、このページが**For you**で開きます。数えるものがない場合は表示されません。

### 数値の算出方法

- **検出された問題**は、その月にWeaveが提起した各問題を1回ずつ数え、最初に提起された日時を一覧表示します。Weaveが問題を提起するのは最初に検出したときで、再び検出した実行のたびに提起するわけではありません。そのため、以前の月から未解決のままの問題は数えられず、月内にいったん解消して再発した問題は1件として数えられます。
- **検出されなくなった**は、月内に後のチェックで検出されなくなった各問題を数えます。以前の月に初めて検出された問題も含みます。「検出されなくなった」は修正されたことを意味しません。データが変化して、問題が表面に出なくなった可能性もあります。[記録される内容](/ja/guides/ai-assistant/weave-activity/#記録される内容)を参照してください。
- **Weaveの変更後に検出されなくなった**は、**検出されなくなった**の問題のうち、Weaveが問題を検出してから、その問題が検出されなくなったチェックまでの間に、問題の対象となるステップやテーブル（ワークフローに関する問題の場合は、そのワークフロー内のいずれかのステップ）に対してWeaveが承認済みの変更を行い、その変更がチェックの前に元に戻されなかったものを数えます。変更は別の理由で行われた可能性もあり、ステップの再実行など、承認済みのどの操作でもかまいません。これは出来事の順序のみを示します。時間の中央値は、Weaveが問題を検出した時点（以前の月であっても）から、その問題が検出されなくなったチェックまでの時間です。以前にいったん解消して再発した問題の場合は、Weaveが再び検出した時点から数えます。
- **実施した変更**は、AIアシスタントでユーザーの承認を得てWeaveが実行したすべての操作を数えます。既存の設定の編集だけでなく、ステップの修正、それに続く再実行、新しいワークフロー、テーブルのコピーなども含まれます。変更を元に戻した操作は、独立した変更としては数えられません。その月の変更のうち、現在までにいくつが元に戻されたかが文に示されます。自分で行った変更や、MCP経由で接続されたAIアシスタントによる変更は記録されないため、集計されません。
- **想定内として記録**は、月内にユーザーが想定内として記録した各問題を数えます。[検出事項を想定内として記録する](/ja/guides/ai-assistant/weave-tab/#検出事項を想定内としてマークする)を参照してください。
- **今月の問題の現状**は、その月に検出された問題（以前の月にいったん解消して再発した問題を含む）を取り上げ、それぞれの現在の状況を示します。検出されなくなった問題は、想定内としても記録されていた場合でも、検出されなくなった問題として数えられます。想定内として記録された後に想定内の扱いが解除された問題は、未解決として数えられます。問題を解決済みにするのは、プロジェクトのアーキテクトとして実行されたチェックだけです。そのため、ほかのユーザーによる実行の後に修正された問題は、未解決として表示される場合があります。[検出事項は実行の終了時に記録される](/ja/guides/ai-assistant/weave-activity/#検出事項は実行の終了時に記録される)を参照してください。

### 集計されないもの

サマリーが集計するのは、アクティビティ履歴に記録された内容だけです。つまり、ワークフローの実行が終了したときに検出された問題と、Weaveを通じて行われた変更です。レポートがデータを読み取る前に見つかった問題や、受け入れた下書きやデフォルトは集計されません。スケジュールどおりに書き込まれないテーブルなど、Weaveが実行と実行の間にのみ検出する問題は履歴に記録されないため集計されず、Weaveがチェックしない実行も集計されません。[履歴に記録されない内容](/ja/guides/ai-assistant/weave-activity/#履歴に記録されない内容)を参照してください。

<Aside type="caution">
Weaveが報告するのは、チェックで検出した内容だけです。問題が検出されなかった月であっても、何も問題がないとは限りません。
</Aside>

### 報告することがない月

その月に集計するものがない場合、サマリーはゼロを表示する代わりにその旨を表示します。たとえば *「Cost Model」には、2026年9月に集計するものはありません。* のように表示されます。元に戻す操作だけの場合や、検出事項へのコメントは集計されません。

## 表示内容はアクセス権によって異なる

ロールで開けないステップ、テーブル、ワークフロー、またはすでに存在しない対象に関するエントリは、どの数値にも集計されず、除外されたエントリの件数が注記で示されます。行レベルセキュリティによって、プロジェクト内で読み取れる行が制限されている場合、サマリーからは、テーブルのサイズや内容からWeaveが検出した内容も除外され、その旨が表示されます。

## ワークスペースサマリー

ワークスペース管理者は、すべてのプロジェクトの数値を1つのページで確認できます。

1. Weaveドックのヘッダーにある**Weave**ボタンをクリックします。
2. メニューの末尾近くにある**ワークスペースサマリー…** メニュー項目を選択します。
3. プロジェクトのサマリーと同様に、月を選択します。

ウィンドウには、その月にアクティビティがあった各プロジェクトが、**検出された問題**、**検出されなくなった**、**Weaveの変更後に検出されなくなった**、**実施した変更**、**想定内として記録**、**修正した失敗実行**、**推定節約時間**とともに一覧表示され、合計を示す**すべてのプロジェクト**の行も表示されます。表示されるのは件数だけです。プロジェクト名をクリックすると、同じ月のそのプロジェクト自体のサマリーが開き、各数値の根拠となるエントリを確認できます。これにはそのプロジェクトへのアクセス権が必要です。その後に削除されたプロジェクトは *存在しなくなったプロジェクト* として表示され、クリックしても何も開きません。

ワークスペースの件数には、各プロジェクトの履歴にあるすべてのエントリが含まれます。プロジェクト自体のサマリーでは、閲覧するユーザーが開けない対象が除外されるため、ワークスペースサマリーより少ない数値が表示される場合があります。

**ワークスペースサマリー…** メニュー項目は、ワークスペース管理者にのみ表示されます。それ以外のユーザーがAPIを通じてワークスペースサマリーを要求すると、*ワークスペースサマリーを表示できるのはワークスペース管理者だけです。各プロジェクトのサマリーは、そのプロジェクトのWeaveタブにあります。* と返されます。

## API経由での利用

`GET /rest/v1/analyze/weave/monthly` は、`project_id` と、`YYYY-MM` 形式の省略可能な `month`（省略した場合は当月）を指定して、プロジェクトのサマリーを返します。`GET /rest/v1/analyze/weave/monthly/workspace` は、同じ省略可能な `month` を指定して、ワークスペースサマリーを返します。形式が正しくない月や、まだ始まっていない月は拒否されます。

## 有用性

**Usefulness**セクションには、ユーザーが検出事項に付けた評価をもとに、Weaveが伝えた内容のうちどれだけが読む価値があったかが、高評価と低評価の件数とともに表示されます。また、Weaveがルックアップによりその場で返した回答の件数も表示されます。集計されるのは、ご自身が開ける対象だけです。ワークスペース管理者には、ルールごと、プロジェクトごとの数値も表示されます。数値を読み取れない場合はページにその旨が表示され、Weaveが役立ったとは示しません。
