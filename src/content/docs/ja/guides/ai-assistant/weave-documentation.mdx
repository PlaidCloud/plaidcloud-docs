## 説明

プロジェクト内のステップまたはワークフローを選択すると、詳細パネルが開きます。下部の**ドキュメント**セクションには、プロジェクトの保存済みの設定から Weave が作成したページが表示されます。テーブルの詳細パネルには、代わりに各列の型と説明を含む**列**が表示されます。以下のページでは、Weave と AI アシスタントがテーブルについて参照する内容を説明します。

- テーブル: そのテーブルに書き込むステップと読み取るステップ、および列
- ステップ: 処理内容と実行場所
- ワークフロー: ステップの順序、および読み取りと書き込みを行うテーブル

ページは、項目を選択するたびに、その時点で保存されている設定から作成されます。そのため古くなることはなく、手動で更新する必要もありません。AI は使用しないので、AI プロバイダーが利用できないときでも動作します。同じ詳細パネルで新しい説明を保存するなどした場合は、ページが再作成されます。

Weave AI、プロジェクトの **Weave** タブにあるチャット、および MCP 経由で接続された AI アシスタントも、同じページを参照できます。[AI アシスタント向け](#ai-アシスタント向け)を参照してください。

## テーブルのページ

- **説明** — テーブルの**メモ**が引用として表示されます。ステップが作成したテーブルには、PlaidCloud がメモとして *Created dynamically* を設定しますが、テーブルについて何も伝えないため、このメモは表示されません。
- **書き込み元**と**読み取り元** — 各ステップが、名前、ステップの種類、所属するワークフローとともに表示されます。*（無効）*は、ステップが無効になっているワークフローに付きます。*どのワークフローにも含まれていません*は、ワークフローに含まれていないステップを示します。テーブル名に、このテーブルを指す場合も指さない場合もある変数が含まれているステップには、*変数の値によります*と表示されます。複数のテーブルが共有する名前のみを指定しているステップには、たとえば *この名前を持つ他の 2 つのテーブルのいずれかを指す場合を除く*と表示されます。数えるのは、開くことができるテーブルだけです。テーブル: クリア、テーブル: ドロップ、またはテーブル: インプレース削除のステップは、変更するテーブルへの書き込みとして数えられます。テーブルを読み取って同じテーブルに書き戻すステップは、両方に表示されます。
- **このプロジェクトでこのテーブルを読み取るステップはありません。** は、このプロジェクトのどのステップもこのテーブルをソースとして挙げていないことを意味します。ページでは、ダッシュボード、エクスポート、他のプロジェクト、およびプロジェクトのステップ以外のものは確認しません。
- **列** — 各列とその型です。**列のプロパティ**に説明が設定されている場合は、その説明も表示されます。

## ステップのページ

**処理内容**には、ステップが行う処理ごとに 1 文ずつ表示されます。

| ステップ | ページの内容 |
| --- | --- |
| 配賦: 分割 | どのテーブルのどの値を、どの列にわたって、どのドライバー列を使って分割するか、また各シェアがどのように算出されるか。たとえば「各 `product` のシェアは、その `weight` を、同じ `cost_center`、`year`、`month` の `weight` の合計で割った値です。」のように表示されます。列名は、ソーステーブルとドライバーテーブルでの名前で表示されます。ステップのソースまたはドライバーに対するフィルターがある場合はその旨が記され、書き込み先のテーブルも示されます。 |
| 配賦: ディメンションで分割 | どのテーブルのどの値を、どのドライバー列を使って分割するか、および書き込むすべてのテーブル（マッピング、パス、サマリーの各テーブルを含む）。 |
| インポート | インポートするファイルと、インポート先のテーブル。 |
| エクスポート | エクスポートするテーブルと、書き込むファイル。 |
| 抽出: ソースが一覧にない SQL | SQL クエリを実行すること、および書き込むテーブル。 |
| テーブル: クリア、テーブル: ドロップ、テーブル: インプレース削除 | テーブルをクリアする、ドロップする、または行を削除すること。検索やフォルダーでテーブルを選択する場合は、その設定で選択されたテーブルに対して実行すること。 |
| 外部プロジェクトテーブルのインポート | 別のプロジェクトのテーブルを、このプロジェクトのテーブルにコピーすること。 |
| 別のワークフローを実行するステップ | 実行するワークフローと実行方法。条件が満たされたとき、ループ内、マクロとして（ソーステーブルの行ごとに 1 回、同時実行の場合は並行して）、またはインクルードによる実行のいずれかです。変数で選択されたワークフローは、ステップが指定する名前で表示され、別のプロジェクトのワークフローはその旨が記されます。ループが順に処理するテーブルなど、ステップ自体が読み取るテーブルも一覧表示されます。 |
| その他のステップ | 読み取るテーブルと書き込むテーブル。 |

その後、ページにはステップの実行場所が記されます。*これは次のワークフローのステップ 3 です*に続いてワークフロー名が表示され、番号はワークフローのステップ一覧と同じです。ワークフローに含まれていない場合は、その旨が記されます。

ステップが変数経由で指定するテーブルは、その名前の後ろに *（変数で指定）*が付いて表示されます。

## ワークフローのページ

- **ステップ** — ワークフローのステップ一覧と同じ番号で、各ステップの種類と、書き込むテーブルまたは実行するワークフローが表示されます。インクルードされているワークフローのステップは、ステップ一覧と同じようにその場所に一覧表示されます。
- **このワークフローの外部からの読み取り** — このワークフローのどのステップが書き込むより前に、ステップが読み取るテーブルです。
- **書き込み** — ワークフローのステップが書き込むテーブルです。

無効なステップは**ステップ**には一覧表示されますが、この 2 つの一覧からは除外されます。無効なステップが書き込むテーブルが外部から読み取られるテーブルとして表示される場合があるため、ページにはその旨が記されます。ワークフローのステップが実行するワークフローで使用されるテーブルは、そのワークフロー自身のページに表示されます。

## プロジェクト全体の引き継ぎパック

たとえば契約の終了時にクライアントへプロジェクトを引き継ぐ場合は、すべてのページを一度にダウンロードします。**プロジェクト**ウィンドウで 1 つのプロジェクトを選択し、**アクション**メニューまたは右クリックメニューから**引き継ぎパックをダウンロード**を選択します。プロジェクト、そのステップ、ワークフロー、テーブルに対する読み取りアクセスが必要です。

パックは、プロジェクト名が付いた 1 つの Markdown ファイル（たとえば *Month End handover.md*）で、ダウンロード時に保存済みの設定から作成されます。先頭にはプロジェクトの説明と内容の件数が記され、その後に 4 つのセクションが続きます。

- **ワークフロー** — 各ワークフローのページです。他のどのワークフローからも実行されないワークフローが名前順で先に並び、それぞれの後に、そのワークフローが実行するワークフローが実行順に続きます。2 か所から実行されるワークフローは 1 回だけ表示されます。
- **テーブル** — 前述のとおり、列とその説明を含む各テーブルのページです。
- **メトリック** — 各メトリック定義の現在のバージョンを、平易な文章で記述します。何を測定するか、どのテーブルから取得するか、結合するテーブル、使用する行、実績行と予算行、期間、およびどの項目で内訳を表示できるかが含まれます。他のメトリックから作成されたメトリックには、たとえば *売上を注文数で割った値*のように作成方法が記されます。[メトリック定義](/ja/integrations/ai-coding-agents/metric-definitions/)を参照してください。
- **配賦モデル** — 互いにデータを渡し合う配賦ステップの各チェーンです。終点となるステップと、各ステップの分割が実行順に記されます。どのワークフローでも実行されないステップは除外されます。モデルの名前は、そのワークフロー、またはワークフローが共有するフォルダーから付けられます。そのような名前がない場合、他のモデルと共有している場合、またはロールによって非表示になっているものから取得する場合は、代わりにステップのいずれかの名前が付けられます。配賦モデルには、パックの外に専用のページはありません。

パックでも、ロールによって非表示になる内容については、単一のページと同じルールに従います。開くことができないワークフロー、テーブル、配賦モデルは除外され、先頭に件数が記されます。たとえば *開くことができない 2 つのワークフローと 5 つのテーブルを除外しています。*のように表示されます。開くことができないステップは、単一のページと同様に、名前が表示されることはありません。

## ロールによって非表示になる内容

テーブル、ステップ、ワークフローは、マネージャーまたはエクスプローラーのロールから非表示にできます。ページには、ロールによって非表示になっている項目の名前は表示されません。

- 開くことができないステップは件数だけが表示され（たとえば *開くことができない他の 2 つのステップ*）、ワークフローのステップ一覧では番号が維持されます。
- 開くことができないテーブル、ステップ、ワークフローは、存在しないものと同じ表示になります。たとえば *開くことができない、または存在しなくなったテーブル*のように表示されるため、ページから非表示の項目が存在するかどうかを知ることはできません。このようにワークフローの一覧から除外されたステップについては、その旨が記されます。そのうちの 1 つが書き込むテーブルが、外部から読み取られるテーブルとして表示される場合があるためです。ステップが指定するテーブルが、開くことができない、または存在しない場合は、ステップが付けた名前の後ろに *（開くことができるテーブルではありません）*が付いて表示されます。ワークフローの場合も同様に *（開くことができるワークフローではありません）*が付きます。
- ロールによって非表示になっている項目のページを要求すると、その項目が存在しない場合と同じ応答になります。

アーキテクトはすべてを開くことができるため、アーキテクトのページには、代わりに *削除されたテーブル*、*（テーブルが見つかりません）*、*削除されたステップ*、*（ワークフローが見つかりません）*と表示されます。

## 対象外の内容

- **行数、サイズ、更新時刻。**
- **SQL テキストや式を通じてのみステップが参照するテーブル。** ページには、ステップが設定で指定しているテーブルが一覧表示されます。
- **未保存の編集内容。** ページには、保存済みの設定が記されます。

<Aside type="note">
ページは、データを解釈したり、ステップが正しいかどうかを判断したりしません。保存済みの設定の内容を、平易な言葉で示すだけです。
</Aside>

## AI アシスタント向け

- **Weave AI** は、プロジェクトで開いた会話でテーブル、ステップ、ワークフローについて尋ねると、そのページを読み取り、ページの内容に基づいて回答できます。[Weave AI チャット](/ja/guides/ai-assistant/weave-tab/#weave-aiチャット)を参照してください。
- **MCP 経由で接続された AI アシスタント**は、プロジェクト、項目がテーブル、ステップ、ワークフローのどれか、およびその ID を指定して、`doc_describe` ツールで同じページを読み取れます。ステップ、ワークフロー、テーブルに対する読み取りアクセスが必要で、ロールによって非表示になる内容も同じルールに従います。[AI エージェント（MCP）](/ja/integrations/ai-coding-agents/)を参照してください。
