## 説明

プロジェクトでステップまたはワークフローを選択すると、詳細パネルが開きます。
その下部の**ドキュメント**セクションに、プロジェクトの保存済み設定からWeaveが作成したページが表示されます。テーブルの詳細パネルには、代わりに**列**が表示され、各列のタイプと説明を確認できます。以下のページでは、WeaveとAIアシスタントがテーブルについて読み取る内容を説明します。

- テーブルの場合は、そのテーブルに書き込むステップと読み取るステップ、および列
- ステップの場合は、その処理内容と実行場所
- ワークフローの場合は、ステップの順序と、読み取り・書き込みの対象となるテーブル

ページは項目を選択するたびに、その時点で保存されている設定から作成されます。そのため内容が古くなることはなく、手動で更新する必要もありません。AIは使用しないので、AIプロバイダーが利用できない場合でも動作します。同じ詳細パネルで新しい説明などを保存すると、ページは再作成されます。

Weave AI、プロジェクトの**Weave**タブにあるチャット、MCP経由で接続したAIアシスタントも、同じページを読み取れます。[AIアシスタント向け](#aiアシスタント向け)を参照してください。

## テーブルのページ

- **説明** — テーブルの**メモ**が引用として表示されます。ステップが作成したテーブルには、PlaidCloudがメモ「*Created dynamically*」を設定しますが、テーブルについて何も伝えないため表示されません。
- **書き込み元**と**読み取り元** — 各ステップが、名前、ステップタイプ、所属するワークフローとともに表示されます。ステップが無効になっているワークフローには*（無効）*が付き、どのワークフローにも含まれていないステップには*どのワークフローにも含まれていません*と表示されます。テーブル名に変数が含まれ、このテーブルを指すかどうかが変数の値次第であるステップには、*変数の値によって異なります*と表示されます。複数のテーブルが共有する名前だけを指定しているステップには、たとえば*同じ名前の他の2つのテーブルを指す場合を除く*と表示されます。数えられるのは、開くことができるテーブルのみです。テーブル: クリア、テーブル: ドロップ、テーブル: インプレース削除の各ステップは、変更するテーブルへの書き込みとして扱われます。テーブルを読み取って同じテーブルに書き戻すステップは、両方に表示されます。
- **このプロジェクトには、このテーブルを読み取るステップがありません。** — このプロジェクトのどのステップもこのテーブルをソースとして挙げていないことを意味します。ページは、ダッシュボード、エクスポート、他のプロジェクトなど、プロジェクトのステップ以外は確認しません。
- **列** — 各列とそのタイプです。**列のプロパティ**に説明が設定されている場合は、その説明も表示されます。

## ステップのページ

**処理内容**には、ステップが行う処理ごとに1文で説明が表示されます。

| ステップ | ページの内容 |
| --- | --- |
| 配賦: 分割 | どのテーブルのどの値を、どの列にわたって、どのドライバー列を使って分割するか、および各シェアの算出方法。たとえば「各`product`のシェアは、同じ`cost_center`、`year`、`month`の`weight`合計に対するその`weight`の割合です。」のように表示されます。列名は、ソーステーブルとドライバーテーブルでの名称で示されます。ステップのソースまたはドライバーに適用されたフィルターがある場合はそれも記載され、書き込み先のテーブルも示されます。 |
| 配賦: ディメンションで分割 | どのテーブルのどの値を、どのドライバー列を使って分割するか、および書き込むすべてのテーブル（マッピング、パス、サマリーの各テーブルを含む）。 |
| インポート | インポートするファイルと、インポート先のテーブル。 |
| エクスポート | エクスポートするテーブルと、書き込むファイル。 |
| ソースが指定されていないSQL抽出 | SQLクエリを実行すること、および書き込むテーブル。 |
| テーブル: クリア、テーブル: ドロップ、テーブル: インプレース削除 | 対象のテーブルをクリアする、ドロップする、または行を削除すること。検索やフォルダーでテーブルを選択する場合は、その設定で選択されたテーブルに対して実行すること。 |
| 外部プロジェクトテーブルのインポート | 他のプロジェクトのテーブルを、このプロジェクトのテーブルにコピーすること。 |
| 別のワークフローを実行するステップ | 実行するワークフローと実行方法。条件を満たしたとき、ループ、マクロ（ソーステーブルの行ごとに1回、同時実行の場合は並行して）、またはインクルードのいずれかです。変数で選択されるワークフローは、ステップが指定する名前で表示され、別のプロジェクトにあるワークフローはその旨が記載されます。ループが順に処理するテーブルなど、ステップ自身が読み取るテーブルも併せて記載されます。 |
| その他のステップ | 読み取るテーブルと書き込むテーブル。 |

続いて、ページにはステップの実行場所が記載されます。*このステップは次の中で3番目です*の後にワークフローが示され、番号はワークフローのステップ一覧と同じです。どのワークフローにも含まれていない場合は、その旨が記載されます。

ステップが変数を通じて指定するテーブルは、その名前の後に*（変数で指定）*を付けて表示されます。

## ワークフローのページ

- **ステップ** — ワークフローのステップ一覧と同じ番号で、各ステップのタイプと、書き込むテーブルまたは実行するワークフローが表示されます。インクルードされるワークフローのステップは、ステップ一覧と同様にその位置に展開されます。
- **このワークフローの外部からの読み取り** — このワークフロー内のどのステップよりも先に読み取られるテーブルです。
- **書き込み** — ワークフローのステップが書き込むテーブルです。

無効なステップは**ステップ**には表示されますが、2つの一覧からは除外されます。無効なステップが書き込むテーブルが外部から読み取られるものとして表示される場合があるため、ページにはその旨が記載されます。ワークフローのステップが実行する別のワークフローで使われるテーブルは、そのワークフロー自身のページに記載されます。

## プロジェクト全体の引き継ぎパック

たとえば案件の終了時にクライアントへプロジェクトを引き継ぐ場合など、すべてのページを一度にダウンロードできます。**プロジェクト**ウィンドウで1つのプロジェクトを選択し、**アクション**メニューまたは右クリックメニューから**引き継ぎパックをダウンロード**を選択します。プロジェクト、そのステップ、ワークフロー、テーブルに対する読み取りアクセス権が必要です。

パックはプロジェクト名が付いた1つのMarkdownファイルです（例: *Month End handover.md*）。ダウンロード時の保存済み設定から作成されます。先頭にプロジェクトの説明と含まれる項目の数が記載され、続いて次の4つのセクションがあります。

- **ワークフロー** — 各ワークフローのページ。他のワークフローから実行されないワークフローが名前順で先に並び、それぞれの後に、そのワークフローが実行するワークフローが実行順で続きます。2か所から実行されるワークフローは1回だけ記載されます。
- **テーブル** — 上記と同じ形式の各テーブルのページ（列とその説明を含みます）。
- **メトリック** — 各メトリック定義の現在のバージョンを、平易な文章で記載します。何を測定するか、どのテーブルからか、結合するテーブル、使用する行、実績行と予算行、期間、どの項目で内訳を表示できるかが含まれます。他のメトリックから作られたメトリックには、たとえば*売上を注文数で割った値*のように、その作り方が記載されます。[メトリック定義](/ja/integrations/ai-coding-agents/metric-definitions/)を参照してください。
- **配賦モデル** — 互いに入力となる配賦ステップの連鎖ごとに、末尾のステップと、各ステップの分割内容を実行順で記載します。どのワークフローでも実行されないステップは除外されます。モデルの名前は、そのワークフロー、またはワークフローが共有するフォルダーに由来します。そのような名前がない場合、別のモデルと共有している場合、またはロールによって非表示になっているものから名前を取得する場合は、代わりにステップのいずれかが名前として使われます。配賦モデルには、パックの外に独自のページはありません。

ロールによって非表示になる項目については、パックも単一のページと同じルールに従います。開くことができないワークフロー、テーブル、配賦モデルは除外され、先頭にその数が記載されます（例: *開くことができない2件のワークフローと5件のテーブルを除外しています。*）。開くことができないステップは、単一のページと同様に名前が示されることはありません。

## ロールによって非表示になる項目

テーブル、ステップ、ワークフローは、マネージャーまたはエクスプローラーのロールから非表示にできます。ページには、ロールによって非表示になっている項目の名前は表示されません。

- 開くことができないステップは件数として表示され（例: *開くことができない他の2件のステップ*）、ワークフローのステップ一覧では番号が保持されます。
- 開くことができないテーブル、ステップ、ワークフローは、存在しなくなったものと同じ表示になります（例: *開くことができない、または存在しなくなったテーブル*）。そのため、ページを使って非表示の項目が存在するかどうかを調べることはできません。このようにワークフローの一覧から除外されたステップは、その旨が記載されます。除外されたステップが書き込むテーブルが、外部から読み取られるものとして表示される場合があるためです。ステップが指定するテーブルが、開くことができない、または存在しない場合は、ステップが指定する名前の後に*（開くことができるテーブルではありません）*が付いて表示されます。ワークフローの場合は*（開くことができるワークフローではありません）*が付きます。
- ロールによって非表示になっている項目のページを要求した場合、その項目が存在しない場合と同じ応答が返されます。

アーキテクトはすべてを開くことができるため、アーキテクトのページには代わりに*削除されたテーブル*、*（テーブルが見つかりません）*、*削除されたステップ*、*（ワークフローが見つかりません）*と表示されます。

## 対象外の内容

- **行数、サイズ、更新時刻。**
- **SQLテキストや式を通じてのみ参照されるテーブル。** ページには、ステップが設定で名前を指定しているテーブルが記載されます。
- **未保存の編集。** ページには保存済みの設定が記載されます。

<Aside type="note">
ページはデータを解釈したり、ステップが正しいかどうかを判断したりしません。保存済みの設定の内容を、平易な言葉で示すだけです。
</Aside>

## AIアシスタント向け

- **Weave AI**は、プロジェクトで開いた会話でテーブル、ステップ、ワークフローについて尋ねると、そのページを読み取り、ページの内容に基づいて回答できます。[Weave AIチャット](/ja/guides/ai-assistant/weave-tab/#weave-aiチャット)を参照してください。
- **MCP経由で接続したAIアシスタント**は、`doc_describe`ツールで同じページを読み取れます。プロジェクト、項目がテーブル・ステップ・ワークフローのいずれであるか、およびそのIDを指定します。ステップ、ワークフロー、テーブルへの読み取りアクセス権が必要で、ロールによって非表示になる項目には同じルールが適用されます。[AIエージェント（MCP）](/ja/integrations/ai-coding-agents/)を参照してください。
