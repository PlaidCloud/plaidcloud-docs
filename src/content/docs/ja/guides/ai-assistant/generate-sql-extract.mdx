## 説明

**SQL抽出**ワークフローステップは、プロジェクトのデータに対して読み取り専用の`SELECT`を実行し、その結果を新しいテーブルに書き込みます。このクエリを手作業で書くには、ソーステーブル、その列、データを整形するためのSQLを把握している必要があります。

ステップエディターは、クエリを代わりに作成できます。求める出力を自然な言葉で説明すると、AIアシスタントが`SELECT`を生成します。読み取り元のテーブルを指定しなかった場合は、プロジェクトのテーブルを調べて、関連するテーブルを自動的に選択します。生成されたSQLと検出された列は確認用に表示され、ステップを保存する前であれば自由に編集できます。

<Aside type="note">
この機能は、AIアシスタントが使用するものと同じ組み込みモデルを利用するため、**設定は不要**です。ワークスペースごとのAIエージェントやLLM接続を構成する必要はありません。
</Aside>

## ステップを開く

ワークフローの**ステップ**ビューで**ステップを作成**をクリックし、次のいずれかを選択します。

- **テーブル → SQL抽出**
- **AI → SQL Extract (AI Assisted)**

どちらも同じSQL抽出のステップエディターが開き、SQL抽出パラメーターページの上部に**Generate SQL with AI**パネルが表示されます。

## クエリを生成する

1. **（任意）ソーステーブルを選択します。** **ソーステーブル**リストで、クエリの読み取り元となるテーブルを1つ以上選択します。リストを空のままにすると、アシスタントがプロジェクトを調べて関連するテーブルを選択します。
2. **求める内容を説明します。** **説明**ボックスに、結果を自然な言葉で書きます。たとえば、*「勘定科目番号の範囲に基づいて、各総勘定元帳の勘定科目をアクティビティプールに分類する」*のように書きます。
3. **SQLを生成**をクリックします。アシスタントは読み取り専用の`SELECT`を1つ作成し、実行して検証したうえで、次の項目に入力します。
   - **SQL Selectクエリ**エディターに、生成されたステートメント
   - **テーブルデータの選択**のマッピングページに、検出された列

   ソースのリストを空のままにした場合は、アシスタントが選択したテーブルがリスト内で選択された状態に戻るため、使用されたテーブルを確認して調整できます。

## 確認と保存

生成されたSQLはブラックボックスではなく、出発点です。

- **自由に編集できます。** SQLエディターは完全に編集可能です。保存する前に、クエリを調整したり、結合を追加したり、列リストを変更したりできます。（複数のテーブルを結合するには、複数のソーステーブルを選択するか、生成されたクエリを直接編集します。）
- **ターゲットテーブルを指定します。** ステップが結果を書き込む**ターゲットテーブル**を選択するか、名前を付けます。
- **ステップを保存します。** 通常のSQL抽出ステップとして保存され、他のステップと同様にワークフローの一部として実行されます。

<Aside type="tip">
アシスタントが返したクエリが実行できない場合でも、エディターにはエラーとともにSQLが表示されるため、ご自身で修正するか、説明を調整して再度生成できます。
</Aside>

## 注意事項と制限

- アシスタントが作成するのは**読み取り専用**の`SELECT`ステートメントだけです。`INSERT`、`UPDATE`、`DELETE`など、データを変更するSQLは作成しません。
- 生成では、ステップの**作成も実行も行われません**。クエリの下書きと列のプレビューだけが行われます。ステップは保存したときに作成され、ワークフローの実行時に実行されます。
- 生成されたクエリは、テーブルの**表示名**で記述されます。各テーブルは、クエリの先頭でその名前に1回だけバインドされるため、列、結合、フィルターのすべてが、内部の`analyzetable_…`のIDではなく、わかりやすい名前で読めます。保存時に実際の識別子が自動的に復元されるため、クエリはそのまま実行されます。名前が一意でないテーブルは、識別子のまま残ります。
