## 説明

月末、予測の提出、取締役会資料など、最も重要な日に問われるのは「Weaveは何に気付いたか」ではなく「準備はできているか」です。**準備状況セット**は、期限が依存するワークフローを指定するもので、セットを選択すると、すべてのワークフローについてこの問いに一度に答えます。答えは1つのチェックリストにまとめられ、冒頭に集計が表示されます。

> 13件中11件が準備完了、1件が準備未完了、1件がチェックできませんでした。

セット内の各ワークフローには、3つの回答のいずれかが付きます。これは、そのワークフローの各行のうち最も悪い結果です。いずれかのチェックで問題が見つかった場合は**準備未完了**になり、その下に問題が一覧表示されます。問題には、Weaveタブと同じ**修正**、**移動**、**Weaveが把握する方法**のボタンがあります。それ以外で、いずれかのチェックに判定の手段がなかった場合は**チェックできませんでした**になり、理由が記載されます。**準備完了**になるのは、Weaveが実行できたすべてのチェックに合格した場合だけです。Weaveが判定しなかったものが準備完了と表示されることはありません。ただし例外が1つあります。比較できる過去の履歴が少なすぎる最終実行は、[後述](#履歴の少ないワークフロー)のとおり、通常どおりとして数えられます。

ユーザーが[想定内として記録](/ja/guides/ai-assistant/weave-tab/#検出事項を想定内としてマークする)した問題があっても、その行は**準備未完了**のままで、想定内として記録されたことが行に示されます。Weaveタブはそのような問題を報告しなくなりますが、チェックリストは事実をそのまま示します。

チェックは、Weaveがすでに実行しているルールです。AIは関与しないため、チェックリストを何度要求しても費用はかかりません。これらのルールが何を読み取り、その回答が何を意味するかについては、[Weaveが確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。

## 準備状況セットを作成する

1. プロジェクトの**Weave**タブを開き、**Monitor**レールの**Close checks**の下にある**準備状況**をクリックします。
2. **新規**をクリックします。セットに「月末締め」などの名前を付け、セットが依存するワークフローを**プロジェクト内のワークフロー**から**このセット内のワークフロー**に移動します。
3. 必要に応じて**期限あり**をオンにし、セットの期限を、cron式とその式で使用するタイムゾーンで指定します。これは、スケジュールされたイベントで選べる内容と同じです。`0 9 5 * *` は毎月5日の09:00、`0 8 * * 1` は毎週月曜日の08:00を表し、いずれもそのタイムゾーンでの時刻です。オフセットは、スケジュールされたイベントと同じように解釈されます。**UTC +0**はイギリス夏時間を含むロンドン時間で、ほかの一部のオフセットはそのオフセットにある地域の夏時間に従い、残りは固定です。各オフセットがどのように解釈されるかは、[イベントスケジューラー](/ja/administration/scheduled-events/event-scheduler/#タイムゾーン)のページに一覧があります。
4. 期限のあるセットでは、**Tell the owner this many hours before it is due**で、期限の何時間前にWeaveがメッセージを送るかを1～168時間で指定します。デフォルトは24です。
5. **保存**をクリックします。

セットはプロジェクトに属し、プロジェクトのWeaveタブで**Monitor**を利用できるユーザーは誰でもチェックできます。セットを作成、編集、削除できるのはプロジェクトのアーキテクトだけで、セット内のすべてのワークフローはそのプロジェクトに含まれている必要があります。セットを最後に保存したユーザーが、そのセットの担当者になります。2人のユーザーが同じセットを同時に編集した場合は、互いの変更が混ざらないように処理されます。2人目の保存は拒否され、セットが再読み込みされて、フォームに新しい方の内容が理由とともに表示されます。

Weaveが入力テーブルを最新と判断できるのは、そのテーブルがいつ書き込まれるべきかを示すものがある場合だけです。つまり、テーブルに書き込むワークフローのスケジュール、またはテーブルの[鮮度のしきい値](/ja/guides/ai-assistant/weave-findings/#現在weaveがチェックする内容)です。これらを先に設定してください。設定しないと、ほとんどのワークフローの最初の行が**チェックできませんでした**になります。

## チェックリストを読む

左側でセットを選択します。Weaveはプロジェクト全体を読み取り（Weaveタブと同じ読み取りです）、セット内の各ワークフローを判定します。何かを修正した後は、**再チェック**をクリックします。

各項目には、ワークフローの名前、その判定、そのワークフローに該当するチェックごとに1行が表示されます。行が**チェックできませんでした**の場合は、その横に理由が記載されます。よく見かける理由は次のとおりです。

| 行 | Weaveが比較する内容 | 「チェックできませんでした」となる主な理由 |
|------|---------------------|-----------------------------------------|
| **Inputs are fresh** | ワークフローが読み取るすべてのテーブルを、そのテーブルに書き込むワークフローのスケジュール、またはテーブル自体の鮮度のしきい値と比較します。 | ロールがテーブルを読み取れない、ワークフローがどのテーブルを読み取るかをWeaveが特定できなかった、またはWeaveが追跡できるテーブルを読み取っていない、読み取るテーブルが自分には表示されない、変数で選択されるテーブルなど、Weaveが特定できないテーブルをステップが読み取る、読み取るテーブルにスケジュールされた書き込み元も鮮度のしきい値もなく、いつ書き込まれるべきかを示すものがない、テーブルに書き込むワークフローが実行中、キュー待ち、または終了した直後である。 |
| **Last run succeeded** | ワークフローの最新の実行で、終了している必要があります。失敗した実行は**準備未完了**になります。 | 実行の記録がない、実行履歴を読み取れなかった、または最終実行が停止されたか、まだ実行中である。 |
| **Last run looked usual** | 最終実行にかかった時間と、実行後にテーブルに含まれていた行数、空の値の数、値の分布を、過去の実行と比較します。 | 最終実行が失敗した、停止された、またはまだ実行中であるため、通常の状態と比較するものがない、書き込んだテーブルに行アクセスが適用されているため、そのテーブルの値が比較されない、実行に自分のロールでは表示されないステップが含まれている。 |
| **Inputs unchanged since it last ran** | ワークフローが前回テーブルを読み取った後に、そのテーブルに別のワークフローが書き込んだかどうか。 | ロールがテーブルを読み取れない、ワークフローが読み取る内容をWeaveが追跡できない、またはワークフローに比較対象となる実行がない。 |
| **Schedule is healthy** | ワークフローのスケジュールされたイベント。時刻表が有効であること、スケジューラーと同期していること、予定された実行を逃していないこと、実行中の実行のために予定時刻が失われていないことを確認します。 | スケジューラーを読み取れなかった。 |
| **Reconciliations tie out** | ワークフローにリンクされた各[照合](/ja/guides/ai-assistant/weave-reconciliation/)を、承認済みのバージョンで、自分として実行します。 | まだ承認されていない照合がある、ロールがテーブルのデータを読み取れない、行アクセスにより一方の側の行が一部しか表示されない、照合で使用するテーブルまたは列が変更された、チェックリストで照合を処理する時間が足りなかった。 |

スケジュールされたイベントがないワークフローには**Schedule is healthy**の行がなく、項目にはスケジュールされていないことが示されます。リンクされた照合がないワークフローには**Reconciliations tie out**の行がありません。これはワークフローに関する事実であり、Weaveがチェックに失敗したわけではありません。

セットの作成後にプロジェクトから削除されたワークフローや、自分のロールでは表示されないワークフローも、集計に含まれます。そのようなワークフローは理由とともに**チェックできませんでした**として表示されるため、集計がいつの間にか減ることはありません。

<Aside type="note">
**準備完了**は、Weaveが実行できたすべてのチェックに合格したことを意味します。ワークフローの数値が正しいこと、そのダッシュボードが最新であること、プロジェクト外のものが整っていることを示すものではありません。各行には比較した内容が正確に示され、検出事項の**Weaveが把握する方法**には、チェックの対象外となる内容が示されます。
</Aside>

### 履歴の少ないワークフロー

実行が通常と異なるかどうかは、過去の実行と比べることでしか判断できません。比較できる過去の履歴が少なすぎる場合、**Last run looked usual**はその実行を通常どおりとして数え、その旨を示します。これには、新しいワークフローやステップ、週次のワークフローのように実行頻度が低く過去30日間に十分な実行がないもの、テーブルに初めてデータを書き込んだ実行が該当します。

> Weaveには最終実行と比較できる過去の履歴が少なすぎるため、通常どおりとして数えます。

実行の一部を比較できた場合、その行には通常の範囲内だったものが示され、「Weaveに比較できる過去の履歴が少なすぎる場合は、通常どおりとして数えます。」と追記されます。Weaveタブには、これらがWeaveが実行できなかったチェックとして引き続き表示されます。一度も実行されていないワークフローは、**Last run succeeded**と**Last run looked usual**の両方の行で**チェックできませんでした**のままになります。最終実行が停止された、またはまだ実行中のワークフローも同様です。

## 期限の前に通知を受け取る

期限のあるセットでは、期限が近づくとWeaveが自動的にチェックを実行し、セットの担当者（セットを最後に保存したユーザー）に、セットの期限が来るたびに1回、アプリ内メッセージで通知します。

> 「月末締め」の期限まであと3日です（10月31日 17:00 UTC）: 13件のワークフローのうち11件が準備完了、1件が準備未完了、1件はWeaveがチェックできませんでした。

メッセージの**Weaveを開く**をクリックすると、プロジェクトのWeaveタブと、そのセットのチェックリストが開きます。メッセージには件数だけが含まれ、名前と理由はチェックリストにあります。メッセージは30秒間画面に表示され、その時点で担当者がサインインしている場合にのみ表示されます。同じ期限についてメッセージが再送されることはありませんが、チェックリストはいつでもウィンドウで確認できます。担当者がプロジェクトを開けなくなった場合は、何も送信されません。

Weaveは1時間に1回チェックするため、メッセージは通知時点から1時間以内に届きます。たとえば24時間前の通知であれば、期限の24時間前から1時間以内に届きます。通知時点を過ぎてから保存されたセットには、次回のチェックで通知されます。チェックの開始が遅れ、実行される前に期限が過ぎた場合でも、そのチェックは「20分前が期限でした」のように担当者に通知します。ただし、期限の後にセットが保存された場合は除きます。チェックは担当者として実行され、テーブルを読み取るのは、担当者が最後にセットを保存したときにテーブルを読み取れた場合だけです。

## API経由での利用

準備状況セットは、プラットフォームAPIの `/analyze/weave/readiness` で利用できます。`GET /sets` はプロジェクトのセットを一覧表示し、`GET /set`、`POST /set`、`PUT /set`、`DELETE /set` はそれぞれセットの読み取り、作成、置き換え、削除を行います。`GET /check` は、ウィンドウに表示されるとおりのチェックリストを、各行の検出事項とともに返します。APIで読み取ったセットには `etag` が含まれます。これを `PUT` で `if_match` として送り返すと、より新しい保存を上書きする編集は拒否されます。送らない場合は、最後の書き込みが優先されます。
