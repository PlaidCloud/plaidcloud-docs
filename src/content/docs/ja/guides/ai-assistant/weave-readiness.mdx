## 説明

月次決算、予測の提出、取締役会資料など、最も重要な日には、問うべきことは「Weave は何に気づいたか」ではなく、「準備はできているか」です。**準備状況セット**は、期限が依存するワークフローに名前を付けて登録するものです。セットを選択すると、そのすべてについて一度にこの問いに答え、最初に件数を示す 1 つのチェックリストが開きます。

> 13 件中 11 件が準備完了、1 件が準備未完了、1 件がチェックできませんでした。

セット内の各ワークフローには、その行の中で最も悪い結果として、3 つの答えのいずれかが付きます。いずれかのチェックで問題が見つかった場合は **準備未完了** となり、その下に問題が一覧表示されます。Weave タブと同じ **修正**、**移動**、**Weaveが把握する方法** の各ボタンが付きます。そうでなく、いずれかのチェックで判断する手段がなかった場合は **チェックできませんでした** となり、その理由が書き出されます。Weave が実行できるすべてのチェックに合格した場合にのみ、**準備完了** になります。Weave が判断していないものが準備完了として表示されることはありません。ただし、1 つ例外があります。比較対象となる過去の履歴が少なすぎる最終実行は、[後述](#履歴が少ないワークフロー)のとおり、通常どおりとして扱われます。

誰かが[想定内としてマークした](/ja/guides/ai-assistant/weave-tab/#検出事項を想定内としてマークする)問題も、その行は **準備未完了** のままで、行には想定内としてマークされたことが記載されます。Weave タブはそのような問題を報告しなくなりますが、チェックリストには事実がそのまま表示されます。

チェックは Weave がすでに実行しているルールです。AI は使用されないため、チェックリストを何度依頼してもコストはかかりません。これらのルールが何を読み取り、その答えが何を意味するかについては、[Weave が確認する内容](/ja/guides/ai-assistant/weave-findings/)を参照してください。

## 準備状況セットの作成

1. プロジェクトの **Weave** タブを開き、**Monitor** レールの **Close checks** の下にある **準備状況** をクリックします。
2. **新規** をクリックします。セットに「月次決算」などの名前を付け、セットが依存するワークフローにチェックを入れます。フィルターボックスに入力してワークフローを検索したり、**割り当て済み** を使ってすでにセットに含まれているものだけを表示したりできます。
3. 必要に応じて、**期限あり** にチェックを入れ、セットの期限を、cron 式とそれが記述されているタイムゾーンで指定します。スケジュールされたイベントで選べるものと同じ選択肢です。`0 9 5 * *` はそのタイムゾーンで毎月 5 日の 09:00、`0 8 * * 1` は毎週月曜日の 08:00 です。オフセットはスケジュールされたイベントと同じように解釈されます。**UTC +0** は、英国夏時間を含むロンドン時間です。その他のオフセットには、そのオフセットにある地域の夏時間に従うものと、固定のものがあります。各オフセットがどのように解釈されるかは、[イベントスケジューラー](/ja/administration/scheduled-events/event-scheduler/#タイムゾーン)のページに一覧があります。
4. 期限があるセットでは、**Tell the owner this many hours before it is due** で、期限の何時間前に Weave がメッセージを送信するかを、1 〜 168 時間で指定します。デフォルトは 24 です。
5. **保存** をクリックします。

セットはプロジェクトに属し、プロジェクトの Weave タブで **Monitor** を持つ全員がチェックできます。セットを作成、編集、削除できるのはプロジェクトのアーキテクトのみで、セット内のすべてのワークフローがそのプロジェクトに含まれている必要があります。セットを最後に保存した人が、そのセットの所有者です。同じセットを 2 人が同時に編集した場合は、互いに影響しないように分離されます。2 番目の保存は拒否され、セットが再読み込みされて、フォームに新しいコピーと理由が表示されます。

Weave が入力テーブルを最新と判断できるのは、そのテーブルがいつ書き込まれているべきかを示すものがある場合のみです。つまり、それを書き込むワークフローのスケジュール、またはテーブルの[鮮度のしきい値](/ja/guides/ai-assistant/weave-findings/#現在weaveがチェックする内容)です。先にそれらを設定しないと、ほとんどのワークフローの最初の行が **チェックできませんでした** と表示されます。

## チェックリストの読み方

左側でセットを選択します。Weave はプロジェクト全体を読み取り（Weave タブと同じ読み取りです）、セット内の各ワークフローを判定します。何かを修正したら、**再チェック** をクリックします。

各項目には、ワークフローの名前、判定結果、そのワークフローに適用されるチェックごとに 1 行が表示されます。行に **チェックできませんでした** と表示された場合は、その横に理由が書き出されます。よく目にする理由は次のとおりです。

| 行 | Weave が比較する内容 | 「チェックできません」と表示される一般的な理由 |
|------|---------------------|-----------------------------------------|
| **Inputs are fresh** | ワークフローが読み取るすべてのテーブルを、それを書き込むワークフローのスケジュール、またはテーブル自体の鮮度のしきい値と比較します。 | ロールにテーブルを読み取る権限がない。Weave が読み取るテーブルを特定できなかった、または Weave がたどれるテーブルを読み取っていない。読み取るテーブルが自分から非表示になっている。変数で選ばれたテーブルなど、ステップが読み取るテーブルを Weave が特定できない。読み取るテーブルにスケジュールされた書き込み元も鮮度のしきい値もなく、いつ書き込まれているべきかを示すものがない。それを書き込むワークフローが実行中、キュー待ち、または終了したばかりである。 |
| **Last run succeeded** | ワークフローの直近の実行。終了している必要があります。失敗した実行は **準備未完了** になります。 | 実行の記録がない、実行履歴を読み取れなかった、または最終実行が停止された、もしくはまだ実行中である。 |
| **Last run looked usual** | 最終実行にかかった時間、実行後にテーブルが保持していた行数、空の値の数、値の分布を、それ以前の実行と比較します。 | 最終実行が失敗した、停止された、またはまだ実行中で、通常かどうかを比較する対象がない。書き込まれたテーブルに行アクセスが適用されているため、そのテーブルの値は比較されない。実行に、ロールでは表示できないステップが含まれている。 |
| **Inputs unchanged since it last ran** | 読み取るテーブルが、最後に読み取った後に別のワークフローによって書き込まれたかどうか。 | ロールにテーブルを読み取る権限がない。Weave がワークフローの読み取り対象をたどれない。または、比較対象となる実行がワークフローにない。 |
| **Schedule is healthy** | スケジュールされたイベント。有効なタイムテーブルであること、スケジューラーと同期していること、期限の来た実行を逃していないこと、実行中の処理のために期限を失っていないこと。 | スケジューラーを読み取れなかった。 |
| **Reconciliations tie out** | ワークフローにリンクされた各[照合](/ja/guides/ai-assistant/weave-reconciliation/)を、承認済みのバージョンで、あなたとして実行します。 | まだ承認されていないものがある。ロールにテーブルデータを読み取る権限がない。行アクセスにより、片側の行の一部しか表示されない。使用するテーブルまたは列が変更された。チェックリストの処理時間が足りなくなった。 |

スケジュールされたイベントがないワークフローには、**Schedule is healthy** の行がなく、項目にスケジュールされていないことが表示されます。リンクされた照合がないワークフローには、**Reconciliations tie out** の行がありません。これはワークフローに関する事実であり、Weave がチェックに失敗したわけではありません。

セットの作成後にプロジェクトから削除されたワークフロー、またはロールでは表示できないワークフローも、件数に含まれます。理由とともに **チェックできませんでした** と表示されるため、件数が気づかないうちに減ることはありません。

<Aside type="note">
**準備完了** は、Weave が実行できたすべてのチェックに合格したことを意味します。ワークフローの数値が正しいこと、ダッシュボードが最新であること、プロジェクト外の何かが整っていることを保証するものではありません。各行には、何が比較されたかが正確に示されており、検出事項の **Weaveが把握する方法** には、そのチェックが対象としないものが示されています。
</Aside>

### 履歴が少ないワークフロー

実行が通常と異なるように見えるのは、それ以前の実行と比較した場合のみです。比較対象となる過去の履歴が少なすぎる場合、**Last run looked usual** はその実行を通常として扱い、その旨を表示します。これは、新しいワークフローやステップ、直近 30 日間に十分な回数の実行がないほど実行頻度が低いもの（毎週実行されるワークフローなど）、およびテーブルに初めてデータを書き込んだ実行が該当します。

> 最終実行と比較するための過去の履歴が Weave には少なすぎるため、通常として扱われます。

実行の一部を比較できた場合、その行には、通常の範囲内だった項目が示され、「比較するための過去の履歴が Weave に少なすぎるものは、通常として扱われます。」が付加されます。Weave タブには、これらが引き続き Weave が実行できなかったチェックとして一覧表示されます。一度も実行されたことのないワークフローは、**Last run succeeded** と **Last run looked usual** の両方の行で引き続き **チェックできませんでした** となり、最終実行が停止された、またはまだ実行中のワークフローも同様です。

## 期限前の通知

期限があるセットでは、期限が近づくと Weave が自動的にチェックを実行し、セットの所有者（最後に保存した人）に、セットの期限が来るたびに 1 回、アプリ内メッセージで通知します。

> 「月次決算」の期限は 3 日後（10 月 31 日 17:00 UTC）です。13 件のワークフローのうち 11 件が準備完了、1 件が準備未完了、1 件が Weave でチェックできませんでした。

メッセージの **Weaveを開く** をクリックすると、プロジェクトの Weave タブと、そのセットのチェックリストが開きます。メッセージには件数のみが含まれ、名前と理由はチェックリストにあります。メッセージは 30 秒間画面に表示され、その時点で所有者がサインインしている場合にのみ表示されます。同じ期限に対して再送されることはありませんが、チェックリストはウィンドウでいつでも確認できます。所有者がプロジェクトを開けなくなった場合は、何も送信されません。

Weave は 1 時間に 1 回チェックするため、メッセージは通知時点から 1 時間以内に届きます。24 時間前の通知であれば、期限の 24 時間前から 1 時間以内です。通知時点を過ぎてから保存されたセットには、次回のチェック時に通知されます。チェックの開始が遅れ、実行前に期限が過ぎた場合は、セットが期限後に保存されたものでない限り、そのチェックは「20 分前が期限でした」として所有者に通知します。チェックは所有者として実行され、所有者がセットを最後に保存した時点でテーブルを読み取れた場合にのみ、テーブルを読み取ります。

## API 経由

準備状況セットは、プラットフォーム API の `/analyze/weave/readiness` で利用できます。`GET /sets` はプロジェクトのセットを一覧表示し、`GET /set`、`POST /set`、`PUT /set`、`DELETE /set` はそれぞれセットの読み取り、作成、置換、削除を行います。`GET /check` は、ウィンドウに表示されるのと同じチェックリストを、各行の検出事項とともに返します。API 経由で読み取ったセットには `etag` が含まれます。`PUT` でこれを `if_match` として送り返すと、より新しい保存を上書きする編集が拒否されます。送信しない場合は、最後の書き込みが優先されます。
