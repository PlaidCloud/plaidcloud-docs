## 説明

各プロジェクトには、そこでWeaveが行った内容の履歴が保存されます。Weaveが検出し、その後検出されなくなった問題、AIアシスタントで提案した変更、各変更を承認または却下したユーザー、承認された各変更が置き換えた内容と書き込んだ内容、そして最終的な結果が記録されます。テーブルの鮮度のしきい値の変更も同じ履歴に残ります。Weaveの検出事項に対して選ばれた担当者、検出事項へのコメント、想定内としてマークされた検出事項も同様です。

この履歴は、監査人にそのまま提出できるように設計されています。エントリは誰も編集や削除ができず、改ざんチェックで履歴が変更されていないかを確認でき、任意の期間をCSVまたはPDFにエクスポートできます。

## アクティビティ履歴を開く

1. プロジェクトを開き、**Weave** タブを選択して、その中で **検出事項** を選択します。
2. ツールバーの **アクティビティ** をクリックします。隣の **検出事項** ボタンをクリックすると、Weaveの検出事項に戻ります。

履歴は新しいエントリから順に、50件ずつ表示されます。最初は過去30日間が対象です。リストの末尾にある **以前のアクティビティを表示** をクリックすると、次の50件が表示されます。ツールバーの **更新** をクリックすると、履歴が再読み込みされます。

**アクティビティ** は、プロジェクトのステップ、ワークフロー、テーブルを読み取れるロールのユーザーに表示されます。ワークフローの検出事項でWeaveタブを開いた場合や、別のプロジェクトに切り替えた場合は、タブが **検出事項** に戻ります。

## 記録される内容

| 発生した内容 | エントリの表示例 |
|---|---|
| Weaveが、AIアシスタントとのチャットで変更を提案した | *Nadia Brennanとのチャットで、Weaveが提案しました: ステップの設定を変更する。* |
| ユーザーが承認した | *Nadia Brennanが承認しました: ステップの設定を変更する。* |
| ユーザーが却下した | *Nadia Brennanが却下しました: ステップの設定を変更する。* |
| 承認された変更が実施された | *承認どおりに完了しました: ステップの設定を変更する。* |
| 承認された変更が完了しなかった | *完了しませんでした: ステップの設定を変更する。* の後に理由が続く |
| 修正後にステップが再実行された | *承認どおりに完了しました: ステップを再実行する。* の後に、*ステップが正常に再実行されました。* のような実行結果が続く |
| ユーザーがステップの修正を元に戻した | *Nadia Brennanが承認しました: Weaveによるステップの設定変更を元に戻す。* に続いて *承認どおりに完了しました: Weaveによるステップの設定変更を元に戻す。* **元に戻して実行** を選んだ場合、エントリの末尾は *そしてステップを実行する。* になる |
| Weaveが実行後に問題を検出した | *Weaveがステップ「Allocate by Driver」で問題を検出しました: フィルターの式にエラーがあります: 列「cost_center」が存在しません。* |
| 後の実行でWeaveがその問題を検出しなくなった | *ワークフロー「Cost Allocation」の実行後、Weaveはステップ「Allocate by Driver」で検出していた問題を検出しなくなりました — ステップの式。* |
| ユーザーがテーブルの鮮度のしきい値を設定、変更、またはクリアした | *Marcus Okaforが、テーブル「Cost Drivers」が26時間を超えて書き込まれない場合にWeaveが警告するよう設定しました。変更前は24時間でした。* |
| ユーザーが鮮度のしきい値付きでテーブルを作成した | *Marcus Okaforが、テーブル「Cost Drivers」を、24時間を超えて書き込まれない場合にWeaveが警告する設定で作成しました。* |
| テーブルをビューとして保存したため、しきい値がクリアされた | *Marcus Okaforがテーブル「Cost Drivers」をビューとして保存したため、Weaveは一定時間書き込まれなくても警告しなくなりました。変更前は24時間でした。* |
| ユーザーが検出事項の担当者を選んだ、またはWeaveが選ぶ担当者に戻した | *Marcus Okaforが、ステップ「GL Actuals Load」に関する検出事項 — 過去の実行と異なるターゲット行 — の担当者をNadia Brennanにしました。* |
| ユーザーが検出事項にコメントした | *Nadia Brennanが、ステップ「GL Actuals Load」に関する検出事項 — 過去の実行と異なるターゲット行 — にコメントしました: 「GLチームに確認中です。」* |
| ユーザーが検出事項を想定内としてマークした | *Nadia Brennanが、ステップ「GL Actuals Load」に関する検出事項 — 過去の実行と異なるターゲット行 — を、2026年12月31日の終わりまで想定内としてマークしました: 「月末のロードは常に負荷が高い」* |
| ユーザーが検出事項を想定内として扱うのをやめた | *Nadia Brennanが、ステップ「GL Actuals Load」に関する検出事項 — 過去の実行と異なるターゲット行 — を想定内として扱うのをやめたため、Weaveは再びこれを報告します。* |

PlaidCloudのAIアシスタントが、承認後に行うすべての変更が記録されます。承認は、変更が行われる前に記録されます。

- ステップの修正、それに続く再実行、修正の取り消し
- 新しいプロジェクト、ワークフロー、ディメンション
- インポート、エクスポート、変換のステップ
- 新しいテーブルに読み込まれたファイル
- テーブルのコピー
- テーブルのプロパティとラベルの変更

プロジェクトの作成など、どのプロジェクトにも属さない変更は、変更が行われた後に、新しいプロジェクトの履歴に表示されます。

「検出されなくなった」は、文字どおりの意味です。問題が修正された可能性もあれば、データが変化して表面に出なくなった可能性もあります。Weaveはどちらであるかを断定しません。

### 検出事項は実行の終了時に記録される

Weaveは、ワークフローの実行が終了すると、その実行の所有者として、ワークフローとそのステップをチェックします。そして、まだ開いていなかった問題を新たに記録し、開いている問題のうち検出されなくなったものも記録します。問題は、後のチェックで再び検出できる状況だったにもかかわらず検出されなかった時点まで、履歴上で開いたままになります。2つの実行がほぼ同時に終了した場合、それぞれのチェックが順序どおりに記録されないことがあります。次回のチェックで履歴が正しい状態に直されます。

問題を閉じるのは、プロジェクトのアーキテクトとして実行されたチェックだけです。プロジェクトの一部しか表示されないロールでは、問題の原因がまだ残っているかどうかを常に確認できるとは限らないためです。ステップを判定できなかったチェックや、ステップに該当しないチェックも、問題を閉じることはありません。

## 各エントリに表示される内容

- **日時**（UTC）。エクスポートでは、同じ時刻がマイクロ秒単位で出力されます。
- **発生した内容**。Weaveの言葉で記述されます。
- **担当者** — チャットのユーザーは **リクエスト者**、ボタンを押したユーザーは **承認者** または **却下者**、鮮度のしきい値を設定した、検出事項の担当者を選んだ、検出事項にコメントした、または検出事項を想定内としてマークした（もしくは想定内として扱うのをやめた）ユーザーは **変更者** として表示されます。
- **対象** — たとえば **ステップ: Allocate by Driver** のように表示されます。
- **変更内容** — 各 **設定** と、その **以前** の値および **以降** の値。**（なし）** は、列またはレコードが追加または削除されたことを示します。
- **結果** — 変更の結果。完了しなかった変更で何かが残った可能性がある場合は *一部が実行された可能性があります。* と表示されます。変更がまだ実行中の場合や、結果が記録されなかった場合は、**この承認に対する結果は記録されていません。** と表示されます。
- **正確な設定を表示** — 設定そのものを省略せずに表示します。実施されたステップの修正では、**以前** と **以降** に、変更された各設定が表示されます。実施されたその他の変更では、**以降** に書き込まれた内容が表示されます。承認または却下では、**提案どおり** に決定された内容が表示されます。その後に変更が実施されない限り、この内容は書き込まれていません。

## ステップの修正を元に戻す

Weaveがコピーを保持しているステップの修正については、そのエントリに **元に戻す** が表示されます。表示される対象は、ステップを変更できるロールのユーザーで、修正が取り消されるまで表示されます。クリックすると、チャットの **元に戻す** と同じウィンドウが開きます。[修正を元に戻す](/ja/guides/ai-assistant/fixing-workflow-errors/#修正を元に戻す)を参照してください。修正をまだ元に戻せるかどうかは、クリックした時点で確認されます。その後にステップが変更されている場合や、以前の設定が保持されていない場合は、ウィンドウに元に戻せない理由が表示されます。

取り消しの応答があると、履歴が再読み込みされ、取り消しが独立した変更として先頭に表示されます。取り消された修正には、**元に戻す** は表示されなくなります。

## 履歴を絞り込む

リストの上にある項目は次のとおりです。

- **ワークフロー** — 1つのワークフローとそのステップに関するエントリ。
- **ステップ** — 1つのステップに関するエントリ。ワークフローを選択している場合は、そのステップだけが選択肢として表示されます。
- **ユーザー** — ユーザーがリクエスト、承認、却下、変更、またはコメントしたエントリ。
- **期間** — **過去7日間**、**過去30日間**、**過去90日間**、または **カスタム**。**カスタム** では、**開始** と **終了** で最初の日と最後の日を選択します。両方を選択するまでは、リストは表示中の期間のままです。

日付はUTCの暦日単位で、**終了** の日も含まれます。絞り込みを変更するたびに、PlaidCloudから履歴が再読み込みされ、**ワークフロー**、**ステップ**、**ユーザー** の各リストも、選択内容を変えずに最新の状態に更新されます。エクスポートには、画面に表示されているエントリがそのまま出力されます。

## 履歴を監査証跡としてエクスポートする

**CSVのエクスポート** または **PDFのエクスポート** をクリックします。ファイルには、選択した期間のうち、現在の絞り込み条件で表示されているエントリが、画面に表示されているとおりに出力されます。ファイル名は `weave-activity-20261001-20261014.csv` のように、期間にちなんだ名前になります。

ファイルの冒頭には、次の内容が含まれます。

- 誰がどの期間をいつエクスポートしたか — たとえば *プロジェクト「Finance Close FY26」のWeaveアクティビティ、2026年10月1日から2026年10月14日。Nadia Brennanが2026年10月14日15:02 UTCにエクスポート。*
- 改ざんチェックの結果（後述）
- 期間内のエントリが10,000件を超える場合は、*このエクスポートは10,000件で打ち切られます。残りをエクスポートするには、より短い期間を選択してください。*
- 該当する場合は、行レベルセキュリティに関する注記（[表示される内容](#表示される内容)を参照）

CSVはエントリごとに1行で、列は **エントリ**、**時刻（UTC）**、**発生した内容**、**リクエスト者**、**承認または却下したユーザー**、**変更者**、**詳細**、**変更**、**結果**、**正確な変更前**、**正確な変更後**、**提案どおり** です。文字コードはUTF-8で、Excelでそのまま開けます。スプレッドシートが数式として実行してしまう値は、テキストとして書き込まれます。PDFには、どれだけ長くても各エントリがすべて掲載されます。

## エントリは編集も削除もできない

PlaidCloudでは、どの画面、API、ユーザーもエントリを編集または削除できません。データベースがエントリの変更も削除も拒否し、エントリが期限切れになることもありません。

各エントリは、ハッシュのチェーンによって直前のエントリとも結び付けられているため、PlaidCloudの外部でエントリが変更または削除されると、その時点以降のチェーンが壊れます。エクスポートのたびにチェーン全体が検証され、結果が次のように報告されます。

- *改ざんチェックに合格しました: このプロジェクトの履歴にある1,204件のエントリは、それぞれを直前のエントリに結び付けるハッシュのチェーンと一致しています。このチェックでは、末尾から削除されたエントリは検出できません。*
- *改ざんチェックに失敗しました: エントリ312がハッシュのチェーンと一致しないため、この履歴はそのエントリ以降で改ざんされています。PlaidCloudサポートにお問い合わせください。*

<Aside type="note">
改ざんチェックでわかるのは、履歴が書き込まれた後に変更されたかどうかです。末尾のエントリが削除された場合や、データベースに直接アクセスできるユーザーが履歴全体を最初から最後まで書き換えた場合は、検出できません。
</Aside>

エントリは永久に保持されるため、PlaidCloudは秘密情報を識別できる場合は、エントリから除外します。**パスワード**、**トークン**、**APIキー** のような名前の設定、接続URLに含まれるパスワード、エラーメッセージに引用されたパスワードは、すべて `[redacted]` として記録されます。

## 承認を記録できない場合

Weaveは、変更を行う前に承認を記録し、記録できない変更は行いません。履歴を書き込めない場合、カードを承認すると *Weaveはこの承認を記録できなかったため、変更を行いませんでした。後でもう一度お試しください。繰り返し発生する場合は、管理者にお知らせください。* と表示されます。何も保存されておらず、カードは開いたままなので、もう一度承認できます。

それ以外のすべて — 提案、却下、変更の結果、検出事項、鮮度のしきい値 — は、発生した後に記録されます。その時点で履歴を書き込めない場合、イベントは処理を待たせることなく、記録されないままになります。

## 表示される内容

- プロジェクトを開くことができ、そのステップ、ワークフロー、テーブルを読み取れるロールのユーザーは、履歴を読み取れます。
- **ロールで開けない対象に関するエントリ** — ロールから見えないステップ、ワークフロー、テーブル、ディメンション、またはすでに削除されたもの — でも、何かが起きたこと、その日時、実行したユーザーは表示されます。ステップ、ワークフロー、テーブル、設定の名前や値は表示されず、*これは、開けない対象、またはすでに存在しない対象に関するものです。* と表示されます。PlaidCloudはステップ、ワークフロー、テーブル、ディメンションをロールに照らして確認するため、接続など、それ以外の対象を指すエントリは、アーキテクト以外のすべてのユーザーに対してこのように表示されます。開けないステップやワークフローで絞り込んでも、何も見つかりません。アーキテクトはプロジェクト内のすべてを開けるため、すべてのエントリを完全な形で確認できます。
- **検出事項の全文はアーキテクト向けです。** アーキテクトには、Weaveが書いた文がそのまま表示されます。それ以外のユーザーには、ステップまたはワークフローと問題の種類のみが表示されます。たとえば *Weaveがステップ「Load Sales」で問題を検出しました — 列「region」の、過去の実行と異なる空の値。* のようになります。全文には、その実行を行ったユーザーにしか見えない内容が含まれる場合があるためです。
- **担当者、コメント、想定内の扱い。** 検出事項の担当者、コメント、または想定内としてマークされた検出事項に関するエントリでは、Weaveの全文ではなく、ほかのユーザーに表示されるとおりの検出事項が示されます。検出事項の対象を開けないユーザーには、担当者を変更した、コメントした、またはWeaveの想定を変更したユーザーと、その日時だけが表示されます。
- **行レベルセキュリティ。** 行レベルセキュリティによって、プロジェクト内で読み取れる行が制限されている場合、履歴からは、テーブルのサイズや内容からWeaveが検出した内容が、それらの検出事項の担当者、コメント、想定内のマークとともに除外され、その旨がリストの上に表示されます。
- **表示設定。** ステップやテーブルがマネージャーまたはエクスプローラーに表示されるかどうかは、ステップ自体のフォームと同様に、アーキテクトにのみ表示されます。

## 履歴に記録されない内容

- **自分で行った変更**。ただし、テーブルの鮮度のしきい値と、検出事項の担当者およびコメントは除きます。履歴は、Weaveが行った内容に関するものです。
- **MCP経由で接続されたAIアシスタントによる変更**（ClaudeやMicrosoft 365 Copilotなど）。これらは、Weaveの承認ではなく、ユーザー自身の権限で動作します。ただし、この方法で設定された鮮度のしきい値は、どのように設定されても記録されます。
- **ERP転記**。これらは[転記レジスター](/ja/guides/connections/posting-register/)に記録され、管理されます。
- **一部の検出事項**。Weaveが検出事項を記録するのは、ワークフローの実行の終了時に行うチェックのみで、このチェックはそのワークフローとそのステップを対象とします。スケジュールどおりに書き込まれないテーブルや、別のワークフローが書き込んだ後に読み取られたテーブルは、[Weaveタブ](/ja/guides/ai-assistant/weave-tab/)には表示されますが、履歴には表示されません。誰も開始しておらず、どのスケジュールにも属さない実行、停止された実行、ワークフロー内で実行されたマクロの実行、ステップの結果の書き込みが完了しない実行からは、何も記録されません。
- **削除または移動されたステップの検出事項**。後でステップが削除された、またはすべてのワークフローから移動された場合、そのステップに関する問題は、以降の実行でチェックされないため、履歴上で開いたままになります。

## 履歴を利用できない場合

履歴を読み取れない場合、空のリストを表示する代わりに、**Weaveのアクティビティ履歴を利用できません** と表示されます。空のリストでは、Weaveが何も行わなかったように見えるためです。**再試行** をクリックするか、ツールバーの **更新** をクリックしてください。
