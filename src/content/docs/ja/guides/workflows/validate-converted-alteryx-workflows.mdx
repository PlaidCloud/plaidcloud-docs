検証では、変換されたAlteryxワークフローがPlaidCloudで実行できる状態であること、そして想定される出力が利用できる場合は、同じビジネス結果が得られることを確認します。

このガイドは、ワークフロー、アプリ、またはマクロをPlaidCloudにインポートした後に使用してください。

<Aside type="note">
  出力パリティとは、スキーマ、行数、行の値が一致することを意味します。ワークフローがビジネスロジックの一部として順序を使用している場合を除き、行の順序は一致している必要はありません。
</Aside>

## 検証レベルの選択

ほとんどの移行プログラムでは、2つの検証レベルを使用します。

### 構造検証

構造検証では、PlaidCloudがAlteryxの設計から完全なワークフローを作成したことを確認します。移行の準備状況を測定する場合、ポートフォリオのインベントリを準備する場合、または想定される出力が利用できる前にワークフローを変換する場合に、このレベルを使用します。

次を確認します。

1. 変換されたワークフローが、ビジュアルワークフローデザイナーで開く。
2. ワークフローのグラフに、想定される分岐、結合、マクロ、出力が含まれている。
3. 必要なすべての入力ファイルが、選択したドキュメントパスにアップロードされた。
4. 必要なすべてのマクロがインポートまたは生成された。
5. マクロ入力とマクロ出力が接続されている。
6. アナリティックアプリの質問が、制御された入力フィールドを持つワークフロー変数になった。
7. ワークフローの実行が完了し、データに依存する条件について、明確な準備状況の注記が報告される。

### 出力パリティの検証

出力パリティの検証では、変換されたワークフローが、Alteryxのワークフローと同じ表形式の結果を生成することを確認します。

次を比較します。

1. 出力テーブルのスキーマ。
2. 行数。
3. 行の値。
4. NULLの扱い。
5. 数値の精度と丸め。
6. 日付と時刻の値。
7. 空間出力が結果に含まれる場合は、ジオメトリの値。

ワークフローがデータを明示的に並べ替えている場合や、後続のプロセスが行の順序に依存している場合を除き、行の順序は無視します。

PlaidCloudのLakehouse v2（StarRocks）エンジンでは、よく使われる次の変換が、Alteryxの出力と一致することを値でチェックしているため、特別な対応なしに一致する結果が得られます。

- テキストのタイトルケース化。
- 点間の球面（大円）距離。
- 標本共分散。
- テキストとして保存された数値に対する合計と平均。
- 正規表現によるテキストの列への分割。
- 欠損値の平均値による補完。

<Aside type="tip" title="数値の精度を比較する前に再変換する">
AlteryxのDouble列は、32ビットではなく64ビットの数値列に変換されるようになりました。そのため、この修正の前に変換されたワークフローでは、有効数字が約7桁を超える値に丸めが生じることがあります。以前の変換を基準にするのではなく、数値の精度を比較する前に再インポートしてください。[AlteryxのDouble列は完全な精度を保持します](/ja/guides/workflows/migrate-alteryx-workflows/#alteryxのdouble列は完全な精度を保持する)を参照してください。
</Aside>

## 移行を検証する

**移行を検証する**は、変換されたワークフローが生成した結果を、Alteryxが生成した出力と比較するため、手作業で差分を取る必要がありません。Alteryxカバレッジレポートから取り込んだワークスペースでは、ホームのチェックリストに**移行を検証する**として**比較**ボタンとともに表示され、カバレッジレポートにも同じボタンがあります。

1. **Alteryx の出力をインポート…** を選択し、Alteryxのワークフローが生成した各出力ファイルをインポートします。**別の出力を追加**で、さらにペアを追加します。
2. 各ペアについて、**変換後の出力**と、それに一致するはずの**Alteryx の出力**を選択します。
3. **比較**を選択します。

PlaidCloudは、まず行数をチェックし、次にすべての列をチェックして、片側にのみ存在する行（それぞれ最大20行）を表示するため、差異は特定の列まで絞り込まれます。各出力は、次のいずれかの結果を報告します。

| 結果 | 意味 |
|---|---|
| *`<output>`と一致：両側とも`<n>`行、すべての列が同じです。* | 両側で行数が同じで、すべての列が同じです。 |
| *比較したすべての項目で`<output>`と一致：両側とも`<n>`行です。* | 比較したすべての項目が一致しています。*3列は比較されていません。*のような注記で、除外された列数が示されます。 |
| *`<output>`と異なります：変換後は`<n>`行、Alteryxは`<m>`行です。* | 行数、列、または値が異なります。レポートには、片側にのみ存在する列と、各列で何が異なるか（たとえば合計、最小値、または重複しない値の数）が一覧表示されます。 |

500万行を超える側は大きすぎてここでは比較できません。代わりに、それぞれのフィルター済みの抽出結果を比較してください。ホームのチェックリストの行には、直近の結果として、*出力が一致しています*、*比較した列で出力が一致しています*、*一部の出力が異なります*のいずれかが表示されます。

ご自身の[SnowflakeまたはDatabricksウェアハウス](/ja/guides/connections/external-lakehouse/#実行ごとのウェアハウスコスト)では、ウィンドウに、直近の実行の**ウェアハウスコスト**（*attributed*または*estimated*のマーク付き）と、次回の実行の見積もりも表示されます。

## 入力の検証

出力を比較する前に、変換されたワークフローが同じソースデータを使用していることを確認します。

1. インポート時に選択したドキュメントフォルダーを開きます。
2. 必要なファイルとサイドカーファイルが存在することを確認します。
3. 動的入力パターンが、意図したファイルに解決されることを確認します。
4. データベースまたはAPIの認証情報が、ターゲット環境で利用できることを確認します。
5. ワークフロー変数が、Alteryxの実行で使われた値と一致することを確認します。

入力を揃えておくと、検証が速くなり、比較をワークフローの動作に集中させることができます。

## マクロの検証

変換されたAlteryxのマクロは、PlaidCloudのマクロワークフローになります。マクロと、それを呼び出すワークフローを一緒に検証します。

1. 生成されたマクロワークフローを開きます。
2. 各マクロ入力に、対応するマクロ入力ステップがあることを確認します。
3. 各マクロ出力に、対応するマクロ出力ステップがあることを確認します。
4. マクロを呼び出すワークフローを実行します。
5. 繰り返しの実行や同時実行が、互いに分離されたままであることを確認します。
6. 想定されるマクロ出力がある場合は、マクロの出力データを比較します。
7. バッチマクロでは、すべてのパスが集約された結果に表示されることを確認します。マクロがパスを生成しない実行の場合は、前回の実行の残りの行ではなく、空の結果が返されます。マクロのロジックがDouble値の受け渡し方法に依存している場合は、再確認してください。Doubleのマクロ入力は、テキストではなく数値として渡されるようになりました。

## アナリティックアプリの検証

変換されたAlteryxのアナリティックアプリは、制御されたユーザー入力にワークフロー変数を使用します。

次を確認します。

- テキストボックス、数値入力、日付、ファイルピッカー、フォルダーピッカー、リスト、ツリー、ラジオボタン、チェックボックス、ドロップダウンが、想定される入力コントロールとして表示される。
- デフォルト値が存在していた場合は、元のアプリと一致している。
- ワークフローを実行する前に、必須の値が設定されている。
- 設定された入力値に対して、条件が想定されるメッセージ、警告、または停止の動作を生成する。

## 特殊な出力の検証

変換されたワークフローの中には、テーブルだけでなくアーティファクトを作成するものがあります。これらの出力は、使われ方に応じて検証します。

レポート、PDF、画像、チャート、マップについて：

1. アーティファクトが、想定されるドキュメントパスに作成されたことを確認します。
2. アーティファクトに、想定されるデータ、ラベル、画像、レイアウトが含まれていることを確認します。
3. 後続の利用者がアーティファクトを開いたり使用したりできることを確認します。
4. 想定されるアーティファクトがある場合は、それと比較します。

NLP、あいまい一致、空間のワークフローについて：

1. マネージドジョブエグゼキューターが正常に完了したことを確認します。
2. エグゼキューターの注記を確認します。
3. 生成されたテーブルまたはスコアを、想定される出力と比較します。
4. PlaidCloudの出力が、Alteryxのデスクトップ固有の出力と意図的に異なる場合は、クラウドネイティブのアーティファクトの差異を文書化します。

機械学習のワークフローについて：

1. ML Trainステップが1行のモデルテーブルを書き込んだことを確認し、記録された学習メトリックを確認します。
2. ML Scoreの予測列をAlteryxのスコアと比較します。XGBoostモデルでは、同一の値ではなく統計的な同等性が想定されるため、ステップのマッピングに関する注記を確認してください。

## 検証の差異の解決

検証で差異が見つかった場合は、次の順序で項目を確認します。

1. 入力ファイルの欠落または相違。
2. ワークフロー変数の値の相違。
3. データベースのスナップショットまたはAPIレスポンスの相違。
4. 日付、タイムゾーン、NULL、丸め、文字列の照合順序の相違。
5. 空間参照またはジオメトリ形式の相違。
6. レポート、マップ、独自形式、デスクトップ専用レンダラーに関する、クラウドネイティブのアーティファクトの相違。

原因を修正した後、ワークフローを再実行し、比較を繰り返します。

## 検証済みワークフローの本番化

検証に合格したら：

1. 移行をステージングプロジェクトで行った場合は、ワークフローを本番プロジェクトに移動またはコピーします。
2. 本番環境のドキュメントパスと認証情報を確認します。
3. ワークフローをスケジュールします。
4. 最初の本番実行を、実行履歴で監視します。
5. 監査とサポートのために、検証結果を移行記録とともに保管します。
