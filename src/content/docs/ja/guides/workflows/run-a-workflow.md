ワークフロー全体の実行は、**ワークフロー**の階層にある実行アイコンをクリックするか、特定のワークフロー内の**アクション**メニューから**Run All**を選択して開始できます。



ワークフローテーブルの上部にある**Toggle Start/Stop**ボタンをクリックすることもできます。このトグルボタンで、実行中のワークフローを停止したり、ワークフローを開始したりできます。

すでに実行中のワークフローで**実行**をクリックすると、PlaidCloudは2回目の実行を開始せず、その旨を通知します。

## 転記モードの選択

すべての実行にはERP転記モードが設定されます。PlaidCloudでモードを選択するには、ワークフローの右クリックメニューの**転記モードを指定して実行**、またはワークフローキャンバス上の実行モードボタンを使用します。通常の**ワークフローを開始**や**ワークフローの実行**ではLiveが要求されますが、後述のプロジェクトの上限が適用されます。実行APIまたはアシスタントから実行を開始するときにも、モードを選択できます。

| モード | 動作 |
|---|---|
| Live | 転記ステップは従来どおりに転記します。これがデフォルトです。 |
| Simulate | すべてのERP転記ステップは、転記する内容を正確に作成して検証しますが、何もコミットせず、ERPにも接続しません。転記される予定のエントリは記録されるため、Liveで実行する前に確認できます。**伝票を転記** ステップのエントリは[転記レジスター](/ja/guides/connections/posting-register/)に **転記予定** として記録され（[ERPシステムに伝票を転記する](/ja/guides/connections/post-documents/)を参照）、各システム専用の転記ステップのエントリは、シミュレーションとしてマークされて[ERP転記履歴](/ja/guides/connections/erp-post-history/)に記録されます。 |
| Off | 転記ステップは完全にスキップされます。 |

プロジェクトにも独自の転記モード上限があります。これは、ロックされていないプロジェクトへの書き込みアクセス権を持つメンバーであれば、プロジェクトAPIまたはアシスタントから設定できます。上限は実行をより安全にする方向にのみ働き、より緩くすることはありません。実行の実効モードは、選択したモードとプロジェクトの上限のうち、より制限の厳しいほうになります。そのため、上限がSimulateに設定されたプロジェクトは、Liveで実行を開始してもシミュレーションのままです。

[スケジュールされたイベント](/ja/administration/scheduled-events/event-scheduler/#erp転記モード)は独自の転記モードを保持するため、Simulateに設定されたスケジュールは、起動のたびにシミュレーションとして実行されます。

モードは、実行が関わるすべてのものに引き継がれます。サブワークフロー、マクロ、および**Run Model**、**Conditional Run Model**、**Loop Model**の各ステップはすべて親の実行のモードを継承します。停止後に[再開](#一時停止停止再開)した実行も同様です。そのため、シミュレーションの実行が内部のどこかで実際に転記することはありません。

:::caution
SAP転記、SAP添付ファイル、および汎用のSAP RFCステップはドライランを行いません。SimulateまたはOffでは完全にスキップされます。SAP独自のテストフラグを使用しても実際にSAPへの接続が開かれるため、ステップをスキップすることが、シミュレーションの実行がSAPに到達しないようにする唯一の方法だからです。
:::

:::note
個々のERP転記ステップには、上記の実行の転記モードとは別に、独自のValidate Only設定（一部のステップではPreviewまたはTest Only Modeというラベル）もあります。ステップエディターでは、この設定は常に明示的に保存されます。REST API、MCP、ワークフローバンドルのインポートなど、別の方法で書き込まれたステップ設定でこの設定が完全に省略されている場合も、ライブ転記ではなくプレビューがデフォルトになりました。 **伝票を転記** ステップにはこのような設定はありません。転記されるかどうかは、実行のモードと、そのシステム自身のモードによって決まります。[ERPシステムに伝票を転記する](/ja/guides/connections/post-documents/)を参照してください。
:::

## プロジェクトに転記を承認する

ワークフローの実行は、実行を開始した人ではなく、プロジェクトとしてERPに転記します。実行が転記できるようにするには、転記ステップが使用するERP接続と環境ごとに、プロジェクトの承認が必要です。承認がない場合、ステップは接続と環境を示して「This project isn't authorized to post to connection …」というメッセージで失敗します。**Call SAP Financial Document Attachment**、**Call SAP Master Data Table RFC**、**Call SAP RFC**の各ステップには承認は不要です。

プロジェクトを承認するには、プロジェクトのホームページを開き、**ERP転記**の下にある**ERP書き込み承認**を選択します。各行は、1つの環境における1つの接続を表します。**承認済み**をオンにするとプロジェクトがそこに転記できるようになり、オフにすると転記できなくなります。**承認者**と**承認日時**には、最後に承認した人とその日時が表示されます。

- このボタンはプロジェクトのアーキテクトとワークスペース管理者に表示されますが、承認を変更できるのはアーキテクトだけで、しかもプロジェクトがロックされていない場合に限られます。アーキテクトではないワークスペース管理者は、先に自分自身をアーキテクトとして追加できます。
- 行を選択して承認または解除しても、一覧は再読み込みされません。スクロール位置と選択した列の並べ替えはそのまま保たれます。ウィンドウのサイズは変更でき、公開プロジェクトに関する注記は全文が折り返して表示されます。
- 接続を承認するには、自分自身もその接続への書き込みアクセス権が必要です。つまり、自分が所有しているか、名前指定またはいずれかのセキュリティグループを通じて共有されている必要があります。**すべてのワークスペースメンバー**に設定された接続は対象になりません。
- **すべてのワークスペースメンバー**に設定されたプロジェクトも、ほかのプロジェクトと同様に承認されます。すべてのメンバーがそのプロジェクトのアーキテクトであるため、接続への書き込みアクセス権を持つメンバーなら誰でも、そのプロジェクトにその接続を承認できます。承認されると、どのメンバーでも、そのプロジェクトのワークフローからその接続へ転記できるようになり、ウィンドウにはグリッドの上にその旨が表示されます。
- テーブルデータまたはディメンションのメンバーを含めて作成した、自分専用の新しいコピーには、自分で付与できるソースの承認が引き継がれ、ソースがLiveだった場合はSimulateの状態で作成されます。詳しくは[コピーでのERP書き込み承認](/ja/guides/projects/managing-projects/#コピーでの-erp-書き込み承認)をご覧ください。それ以外のコピーや、プロジェクトアーカイブから作成したプロジェクトには、承認がない状態で作成されます。転記する前に承認してください。

## ステップの状況の確認

ワークフローの実行中は、各ステップに現在の状況を示すステータスアイコンと、実行にかかっている時間が表示されます。アイコンにカーソルを合わせると、その状況のメッセージが表示されます。

| ステータス | 意味 |
|---|---|
| Waiting | ステップはキューに入っており、まだ開始されていません。 |
| Running | ステップは処理中で、実行時間が増え続けます。 |
| Completed | ステップは正常に完了しました。 |
| Warning | ステップは完了しましたが、[ワークフローログ](/ja/guides/workflows/viewing-workflow-log/)で確認すべき内容が検出されました。 |
| Error | ステップは失敗しました。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)をご覧ください。 |
| Skipped | ステップは無効になっているか、実行条件が満たされなかったため、実行されませんでした。[ワークフローのステップをスキップする](/ja/guides/workflows/skip-steps-in-a-workflow/)をご覧ください。 |
| Continued | ステップは失敗しましたが、エラー時に続行する設定になっているため、ワークフローは続行されました。[エラー時に続行](/ja/guides/workflows/continue-on-error/)をご覧ください。 |
| Stopped | ステップが終了する前に、実行が停止されました。 |
| Abandoned | ステップの実行が中断されたため、完了することはありません。実行を再開するか、ワークフローを再実行してください。 |

開いているワークフロービューは、実行の進行に合わせて自動的に更新されるため、ページを再読み込みしなくても、表示中のステータスは常に最新です。

### 放棄されたステップ

ステップを実行していたものが実行の途中で失われると、そのステップは**abandoned**（放棄）とマークされます。多くの場合、誰かが**停止**を押したか、プラットフォームのメンテナンスで実行が中断されたことが原因です。ステップの実行時間は増えなくなり、ステータスのツールチップに何が起きたかが表示されます。

放棄されたステップは完了しておらず、出力も生成されていません。処理が遅いわけではなく、データや設定の問題でもありません。

作業を再開するには、実行を[**再開**](#一時停止停止再開)するか（放棄されたステップが再度実行されます）、ワークフロー全体を再実行します。どちらも安全です。

### 中断されたステップ

ステップを実行しているサーバーが実行の途中で失われた場合、PlaidCloudは、繰り返しても安全なときにそのステップを自動的に再実行します。出力を置き換えるステップは、1回で正常に実行した場合と同じ結果になるため、確認する必要はありません。ステップのログには、2回目の試行が始まる位置に「Restarted: the server running this step stopped before it finished (e.g. out of memory or a restart); running it again from the start.」という警告が表示されます。

安全に繰り返せないステップは再実行されません。そのステップは、**interrupted**（中断）メッセージとともに1回だけ失敗します。2回目を実行すると、1回目がすでに書き込んだものが重複するおそれがあるためです。名前やパスに `{date}` または `{date_iso}` を含む出力を書き込むステップは、再実行すると別の日付に書き込まれる可能性があるため、安全に繰り返せないものとして扱われます。復旧するには、ステップのターゲットで1回目に書き込まれた内容を確認し、必要に応じてクリーンアップしてから、[ステップを再実行](/ja/guides/workflows/running-one-step-in-a-workflow/)するか、実行を**再開**します。

### 開始されないステップ

ステップがワーカーを待っている間、そのステータスメッセージには「Waiting for a worker… N min. No import worker has picked this step up yet.」と表示されます（ワーカーの種類はステップに対応し、インポートやエクスポートなどになります）。作業が始まると、このメッセージは消えます。

ステップのジョブが開始できない場合は、永遠に待ち続けるのではなく、理由を示して失敗します。

| 原因 | 失敗するまでのおおよその時間 |
|---|---|
| インポートまたはディメンションのステップのジョブをどのワーカーも取得しない | 40分 |
| ステップのPodがPendingのままになっている | 20分 |
| ステップのイメージをプルできない | 5分 |
| ステップ用のPodが作成されない | 20分 |
| コネクタ（Singer）の同期をどのランナーも取得しない | 30分 |

コネクタの同期のメッセージには、その同期の名前が示されます。ワーカーがジョブを開始した後に失われた場合も、ワーカーが停止したというメッセージとともにステップは失敗します。インポートとディメンションのメッセージには「Use Run from here to retry.」と表示されます。

### 応答しなくなった実行

実行の背後にある処理がなくなった後も、実行が**実行中**のままになることはありません。ワークフローを実行しているサーバーが失われた場合、その実行は失敗として終了します。1回の実行は最大12時間です。その時点でまだ終わっていない実行は、「Run failed: still running at the 12-hour limit. Re-run the workflow.」というメッセージとともに失敗します。

## Run Insight

Run Insight は、ワークフローの1回の実行で時間がどこに使われたか、どのステップが通常より長くまたは短くかかったかを示します。各ステップは、そのステップ自身の最近の実行と比較して判定されるため、常に遅いステップが問題として挙がることはありません。

### Run Insight を開く

- キャンバスで、ツールバーの**履歴**をクリックします。[ビジュアルワークフローデザイナー](/ja/guides/workflows/advanced-workflows/)を参照してください。
- **ワークフロー**タブで、ワークフローを1つ選択し、**アクション**メニューまたは右クリックメニューから**Run Insight**を選びます。
- ホームで、ワークフローカードの**最新の実行を開く**を選びます。
- 実行履歴ダイアログで、**実行回数**テーブルの実行を選び、**Insightで開く**を選ぶか、その行を開きます。
- ワークフローの遅い実行についてアプリ内に表示されるWeaveメッセージで、**実行を開く**をクリックします。[実行の終了通知を受け取る](/ja/guides/ai-assistant/weave-findings/#実行終了時の通知)を参照してください。

ダイアログのタイトルは**実行履歴** — ワークフロー名です。**インサイト** | **実行回数**の切り替えで、このビューと過去の実行のテーブルを切り替えます。インスペクターから開いたステップ自身の実行履歴には、テーブルのみが表示されます。

### 見出しと要対応リストの読み方

見出しには、実行の結果が1行で表示されます。**所要時間** *時間*、実行中は*時間* **実行中**、停止された最新の実行では*時間* **後に停止**、失敗した場合は失敗したワークフローを示す*ワークフロー*で**失敗**です。その下の文で、通常より遅く実行されたステップ、待機に費やされた時間、履歴のあるすべてのステップが通常の範囲内で実行されたことなど、目立つ点が示されます。続いて、開始時刻、ワークフローとステップの数、履歴が少なすぎて判定できないステップがある場合はその数が表示されます。確認が必要な項目がある場合は、見出しの横に**確認事項** *N* **件**の形で件数が表示されます。

見出しの横には、最近の実行の帯が表示され、その上にキャプションが付きます。各バーが1回の実行で、バーの高さは所要時間を表し、日付は日が変わる位置にだけ表示されます。帯の中の実行をクリックすると、その実行が開きます。失敗した実行には赤いキャップと ✕ が付き、最近の実行の多くより少ないステップしか実行しなかった実行には破線の枠が付きます。これは、完全な実行と比較できないためです。

**要対応**には、失敗、通常範囲を超えた時間、待機の順に項目が表示されます。各項目はカードで、名前、失った時間または**失敗**、その場所、そして時間のバーが表示されます。バーでは、灰色が通常の範囲内、アンバーが通常を超えた分で、失敗のバーは赤です。前回の実行以降に保存されたステップには、*日付***に保存**タグが付きます。カードをクリックすると、ビュー内でそのカードが選択され、選択中のカードは強調表示されます。

### フロー、タイムライン、テーブル

ビューの上のヘッダーには、ワークフローの名前、**比較対象**、**ビュー**が順に並び、右端には更新ボタンがあります。**ビュー**の**フロー**、**タイムライン**、**テーブル**の各ボタンでビューを選びます。

| ビュー | 表示内容 |
|---|---|
| **フロー** | 高さが時間を表すブロック。アンバーは、ステップの通常を超えた時間です。開かれていないが失敗を含むブロックには、✕ と赤い枠が表示されます。名前を表示するには短すぎる、失敗したブロックまたは選択中のブロックは、より高く描かれ、その場合は縮尺どおりではないことが凡例に示されます。ステップが他のワークフローを呼び出した場合、**呼び出しオーバーヘッド**のスライスは、それらのワークフローの外でステップ自身が費やした時間です。ステップが実行されていなかった時間には、**待機中**のスライスがその空白を示します。並列に実行されたワークフローには表示されません。 |
| **タイムライン** | 実行開始からの時計上の時間。破線の枠は、比較対象の実行でそのブロックにかかった時間です。 |
| **テーブル** | 呼び出し順にすべてを表示します。列は**名前**、**今回の実行**、**通常**、**追加**、**比較対象の実行**、**ステータス**です。 |

他のワークフローを呼び出したワークフローは、その内部に呼び出し先を表示します。ワークフローのブロックをダブルクリックするか、**拡大**を選ぶと、その内部で作業できます。戻るには、ビューの上のパンくずを使います。通常ペースのステップが複数並んでいる場合、**フロー**はそれらを1つの**通常ペースの** *N* ブロックにまとめて折りたたみます。それをクリックするか、パンくずの右にある*数***個のブロックをすべて表示**をクリックすると開きます。*数*はビュー内のすべてのブロックの数です。**通常ペースのブロックを折りたたむ**で再び折りたたみます。このボタンは、折りたためるものがある場合にのみ表示されます。

ブロックを選択すると、詳細パネルが表示されます。パネルには、ブロックの名前と場所、下記のいずれかのマークを示すステータスのピル、そして**今回の実行**、**通常**、**履歴**、**通常範囲超過**、**比較対象の実行**のうち該当する行が表示されます。続いて傾向線が表示されます。実行自身のワークフローでは、最近の完全な実行が並び、今回の実行が完了していればドットで示されます。通常の範囲があるステップでは、その範囲が帯で示され、今回の実行がドットで示されます。注記がマークを説明し、ボタンは**ワークフロー内で表示**、**ステップを表示**または**拡大**、**ワークフローを開く**、**実行ログを表示**を使えます。**ワークフローを開く**はキャンバスでワークフローを開き、**実行ログを表示**はその[ログ](/ja/guides/workflows/viewing-workflow-log/)を開きます。

### マークの意味

| マーク | 意味 |
|---|---|
| **失敗** | ステップがエラーで終了しました。パネルにそのメッセージが表示されます。ただし、ロールでステップの名前を確認できない場合は表示されません。 |
| **通常より遅い** | ステップの所要時間が通常の範囲を超えました。 |
| **全体的に遅い** | ワークフロー内のすべてのステップが同程度に遅くなりました。これは、1つのステップではなく、ワークフロー全体に共通する何かが原因であることを示します。そのステップには**共通の遅延の一部**と表示されます。 |
| **遅いステップあり** | **内部の遅いステップ**を含むワークフローです。 |
| **通常ペース** | ステップは通常の範囲内で実行されました。 |
| **高速** | ステップは通常の範囲より速く実行されました。 |
| **履歴不足** | ステップの実行回数が少なく、通常の範囲がないため、判定されません。 |
| **エラー、続行** | ステップは失敗しましたが、[エラー時に続行](/ja/guides/workflows/continue-on-error/)が設定されています。 |
| **スキップ済み** | ステップは飛ばされました。 |
| **実行中** | ステップはまだ終了していません。 |

最近の実行がすでに遅かった、またはばらつきが大きいステップは、フラグが付かないことがあります。期間末の実行を通常の日と比較すると、全体的に遅く見えることがあります。以前に停止した実行は、停止ではなく短い実行として表示されます。

パネルでは、マークの理由も説明されます。**待機中**は、実行中のステップがなかった時間で、どのステップにも原因はありません。通常より遅く実行されたステップでは、**書き込み行数**がその出力を通常の件数と比較します。行レベルセキュリティによって読み取れる範囲が制限されている場合は表示されません。同じく通常より遅く実行されたステップでは、**前回の実行以降に保存されました**は、ステップが前回の実行後、今回の実行の開始前に保存されたことを示します。記録に残るのは保存の事実であり、何が変更されたかではありません。**異なる処理**は、実行されなかったステップと、処理を行わずに実行されたステップを、各ステップの履歴、または別の実行と比較する場合はその実行を基準に数えます。**並列実行**は、ワークフローの各部分が同時に実行されたため、それぞれの時間の合計が時計上の時間を超えることを意味します。**呼び出し元が不確定**は、履歴からはどのステップがワークフローを呼び出したかを特定できないことを意味します。**名前非表示**は、ロールでは名前を確認できないステップまたはワークフローを示し、**非表示のステップ**または**非表示のワークフロー**と表示されます。

### 比較対象

**比較対象**は、実行を何と比較するかを設定します。そのメニューボタンには、選択内容として**通常**、**通常 + 前回の実行**、または**通常 +** *開始時刻***の実行**（選択した実行の開始時刻）が表示されます。**通常**は、各ステップの最近の実行を使います。**通常 + 前回の実行**と**通常 + 選択した実行**は、さらにその実行での各ステップの時間を加え、**タイムライン**で枠として、**テーブル**では**比較対象の実行**の下に表示します。**通常 + 選択した実行**を選ぶと、最近の実行の一覧が開き、そこから選びます。

### 大きな実行の中の1つのワークフロー

別のワークフローから呼び出されたワークフローを開くと、インサイトにはそのワークフローが担った部分の実行のみが表示されます。**実行全体を開く**は、実行を開始したワークフローでダイアログを開き直します。

### 進行中の実行

まだ進行中の実行は、ダイアログが表示されている間、30秒ごとに再読み込みされます。ズーム、選択、ビューはそのまま維持されます。インサイトから**実行回数**に移ると更新は停止し、インサイトに戻ると実行を読み込み直して再開します。更新ボタン（ヘッダー右端の円形の矢印）は、実行を最初から読み込み直し、ズームと選択をリセットして、通常ペースのブロックを再び折りたたみます。

### AIアシスタントとREST API向け

同じプロファイルは、ダイアログの外でも利用できます。

- REST: `GET /rest/v1/analyze/workflow/run-insight`（`project_id` と `workflow_id` を指定）。`run_id` で実行を指定します（省略時は最新）。`baseline` は `typical`、`previous`、または `run:<id>` です。
- MCP: `workflow_describe` に `include=['run_insight']` を指定し、必要に応じて `run_id` と `baseline` を指定します。

各ワークフローとステップについて、その時間、実行内での位置、自身の履歴に対する判定、およびその理由が返されます。存在しない実行や、ステップの行がない実行では、エラーではなく、プロファイルなしの結果と警告が返されます。

## 一時停止、停止、再開

ワークフローの実行中は、**一時停止**して実行中のステップを完了させ新しいステップを待機させることも、**停止**してキューに入っていたステップと、数秒以内に、実行中のインポートまたはエクスポートのジョブを、エクスポートが読み取っていたウェアハウスのクエリとともにキャンセルすることもできます。キューに入っていたインポートとディメンションのステップは正常にキャンセルされるため、ワークスペース内の後続のインポートやディメンションのロードを妨げません。停止すると、ワークフローのキュー中または実行中のコネクタ（Singer）の同期も停止されるため、ワークフローの停止後も同期が実行され続けることはありません。

**停止**を押すと、実行中のインポートまたはエクスポートのジョブは新たな書き込みを開始しません。エクスポートはファイルをアップロードせず、インポートはテーブルをロードしません。すでに進行中の書き込みは先に完了するため、ファイル、テーブル、ディメンションが書きかけのまま残ることはありません。複数ファイルのエクスポートや複数テーブルのエクスポートでは、すでに書き込まれたファイルはそのまま残ります。途中で停止された複数ファイルのCSVエクスポートは、すでにフォルダーを空にしているため、フォルダーにはそれらのファイルだけが残り、以前の実行のファイルは残りません。ディメンションのロードと、MongoDBまたはKafkaのエクスポートは、処理しながら書き込むため、開始されたものは最後まで実行されます。**SQLのインポート**または**外部データベーステーブルのインポート**ステップは、PlaidCloudがソースのクエリをキャンセルしないため、読み取っていた内容をソースデータベースが返した時点で停止します。Databendでは、Databendがドキュメントアカウントに直接書き込むエクスポートは1回の書き込みであるため、最後まで実行され、ファイルが書き込まれます。

マクロは、他のワークフローや**マクロ: 並行実行**ステップから呼び出されて、複数の場所で同時に実行されることがあります。マクロを停止すると、実行中のすべてのコピーが停止します。1つのコピーを停止した場合、停止するのはそのコピーとそれが開始したものだけで、それを呼び出したワークフローは実行を続けます。**Macro Concurrent**ステップが応答しなくなったコピーを見限った場合も同様です。他のワークフローの中でのみ実行されているマクロは、ワークフロー一覧に**実行中**と表示されて**停止**を使用でき、開くと各ステップの最新の実行におけるステータス、開始時刻、終了時刻が表示されます。

**再開**すると、一時停止、停止、または失敗した実行を、最初からやり直すのではなく、中断した箇所から続行します。ワークフローの最後の実行が一時停止、停止、またはエラーの状態で終了している場合は、常に利用できます。

「中断した箇所」が何を意味するかは、ワークフローの実行方法によって異なります。

| 実行方式 | 再開時の動作 |
|---|---|
| シリアル | 実行が終了したときに実行中だったステップから再開し、そこから続行します。そのステップがグループ内にある場合、再開ではそれを含む最上位のグループ全体が対象になります。グループ内ですでに正常に完了したステップはそのままで、それ以外が実行され、グループの後から実行が続行されます。 |
| パラレル | 正常に完了していないすべてのステップを再実行し、完了したステップはそのままにします。 |
| 高度（グラフ） | 失敗したノードと、それを待っているすべてのノードを再実行し、完了したノードはそのままにします。 |

別のワークフローを呼び出すステップ（**Run Model**、**Conditional Run Model**、**Loop Model**）は、呼び出し先のワークフローを最初からやり直すのではなく再開します。これは、ネストの階層がいくつあっても同様です。ループステップは、中断された反復を再開し、すでに完了した反復はスキップします。

別のワークフローの**ネストされた子**として実行されたワークフロー（親の**Run Model**ステップが呼び出したもの）を再開するとき、PlaidCloudは**チェーンの先頭から再開**を提示します。子だけを再開しても親のオーケストレーションを続行できないため、このオプションでは代わりに最上位の親（チェーンのルート）を再開し、チェーン全体を停止した箇所から続行します。最上位のワークフローの再開は従来どおりです。チェーンの先頭は同じプロジェクト内で解決されます。別のプロジェクトにまたがるチェーンは、プロジェクト内の部分の先頭から再開されます。

再開は常に**元の**実行を続行します。その実行のうち正常に完了しなかったすべてのステップを再実行します。失敗したステップや放棄されたステップは完了扱いにならず再実行されます。また、その間に個々のステップを単独で再実行しても、次に再開で取得される内容は変わりません。これは子ワークフローにも当てはまります。子ワークフローのステップの1つを単独で再実行した場合でも、親を再開すると、そのステップだけでなく、子ワークフローに残っていたすべてが実行されます。

再開された実行は、ワークフローの実行履歴に**新しい実行**として記録され、再実行したステップのみが含まれます。元の実行は、それ自身の履歴エントリを保持します。1回の実行で同じ子ワークフローが複数回呼び出された場合は、呼び出しごとに子ワークフローの実行履歴にエントリが作成されます。ループステップの反復は、1回の呼び出しとして数えられます。

:::note
ループステップは、変数の値によって、完了した反復を照合します。元の実行から再開までの間にループが反復処理するデータが変更された場合、照合できなくなった反復は、スキップされずに再実行されます。
:::
