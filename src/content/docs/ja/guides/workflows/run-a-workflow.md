ワークフロー全体の実行は、**ワークフロー**階層の実行アイコンをクリックするか、特定のワークフロー内の**アクション**メニューから**Run All**を選択して開始できます。



ワークフローテーブルの上部にある**Toggle Start/Stop**ボタンをクリックすることもできます。このトグルボタンで、実行中のワークフローを停止したり、ワークフローを開始したりできます。

すでに実行中のワークフローで**実行**をクリックすると、PlaidCloudは2回目の実行を開始せず、実行中であることを通知します。

## 転記モードの選択

すべての実行にはERP転記モードが設定されます。PlaidCloudでモードを選択するには、ワークフローの右クリックメニューの**転記モードを指定して実行**か、ワークフローキャンバスの実行モードボタンを使用します。通常の**ワークフローを開始**または**ワークフローの実行**ではライブが指定され、後述のプロジェクトの上限が引き続き適用されます。実行APIまたはアシスタントから実行を開始する際にも、モードを選択できます。

| モード | 動作 |
|---|---|
| ライブ | 転記ステップは従来どおりに転記します。これがデフォルトです。 |
| シミュレート | すべてのERP転記ステップは、転記する内容を正確に構築して検証しますが、何もコミットせず、ERPにも接続しません。転記予定のエントリは、シミュレートとしてマークされた状態で[ERP転記履歴](/ja/guides/connections/erp-post-history/)に記録されるため、ライブで実行する前に確認できます。 |
| オフ | 転記ステップは完全にスキップされます。 |

プロジェクトにも独自の転記モード上限があります。この上限は、ロックされていないプロジェクトへの書き込みアクセス権を持つメンバーが、プロジェクトAPIまたはアシスタントから設定できます。上限は実行をより安全にする方向にのみ働き、より緩くすることはありません。実行の有効なモードは、選択したモードとプロジェクトの上限のうち、より制限の厳しい方になります。そのため、上限がシミュレートに設定されたプロジェクトでは、ライブで実行を開始してもシミュレートのままです。

[スケジュールされたイベント](/ja/administration/scheduled-events/event-scheduler/#erp転記モード)は独自の転記モードを保持するため、シミュレートに設定されたスケジュールは、起動のたびにシミュレートで実行されます。

モードは、実行が関係するすべてのものに引き継がれます。サブワークフロー、マクロ、および**Run Model**、**Conditional Run Model**、**Loop Model**の各ステップはすべて親の実行のモードを継承します。停止後に[再開](#一時停止停止再開)した実行も同様であり、シミュレートの実行は内部のどこでも実際には転記できません。

:::caution
SAP転記、SAP添付、および汎用のSAP RFCの各ステップはドライランを行いません。シミュレートまたはオフでは完全にスキップされます。SAP自体のテストフラグを使ってもSAPへの実際の接続が開かれるため、ステップをスキップすることが、シミュレートの実行がSAPに到達しないようにする唯一の方法だからです。
:::

:::note
個々のERP転記ステップには、上記の実行の転記モードとは別に、独自のValidate Only設定（ステップによってはPreviewまたはTest Only Modeというラベル）があります。ステップエディターでは、この設定は常に明示的に保存されます。REST API、MCP、ワークフローバンドルのインポートなど、別の方法で書き込まれたステップ構成でこの設定が完全に省略されている場合も、ライブ転記ではなくプレビューがデフォルトになります。
:::

## プロジェクトに転記を承認する

ワークフローの実行は、開始した人ではなくプロジェクトとしてERPに転記します。実行が転記できるようにするには、転記ステップが使用するERP接続と環境ごとに、プロジェクトの承認が必要です。承認がない場合、ステップは接続と環境を示す「This project isn't authorized to post to connection …」というメッセージで失敗します。**Call SAP Financial Document Attachment**、**Call SAP Master Data Table RFC**、**Call SAP RFC**の各ステップには承認は不要です。

プロジェクトを承認するには、プロジェクトのホームページを開き、**ERP転記**の下にある**ERP書き込み承認**を選択します。各行は、1つの環境における1つの接続です。**承認済み**にチェックを入れると、そのプロジェクトがそこに転記できるようになり、チェックを外すと転記が停止します。**承認者**と**承認日時**には、最後に承認した人とその日時が表示されます。

- このボタンはプロジェクトのアーキテクトとワークスペース管理者に表示されますが、承認を変更できるのはアーキテクトだけで、しかもプロジェクトのロックが解除されている間に限られます。アーキテクトではないワークスペース管理者は、先に自分自身をアーキテクトとして追加できます。
- 承認またはクリアする行を選択しても、リストは再読み込みされません。スクロール位置と、選択した列の並べ替えはそのまま保持されます。ウィンドウのサイズは変更でき、公開プロジェクトに関する注記は全文が折り返して表示されます。
- 接続を承認するには、その接続への書き込みアクセス権も自分で持っている必要があります。つまり、自分が所有しているか、名前またはセキュリティグループを通じて共有されている必要があります。**すべてのワークスペースメンバー**に設定された接続は対象になりません。
- **すべてのワークスペースメンバー**に設定されたプロジェクトも、他のプロジェクトと同様に承認されます。すべてのメンバーがそのアーキテクトであるため、接続への書き込みアクセス権を持つメンバーなら誰でも、そのプロジェクトを承認できます。承認されると、どのメンバーもプロジェクトのワークフローからその接続に転記でき、グリッドの上のウィンドウにその旨が表示されます。
- コピーしたプロジェクトや、プロジェクトアーカイブから作成したプロジェクトには、承認がない状態から始まります。転記する前に、コピーを承認してください。

## ステップのステータスの確認

ワークフローの実行中、各ステップには現在の状態を示すステータスアイコンが、実行時間とともに表示されます。アイコンにカーソルを合わせると、その背景にあるメッセージが表示されます。

| ステータス | 意味 |
|---|---|
| 待機中 | ステップはキューに入っており、まだ開始されていません。 |
| 実行中 | ステップは処理中で、実行時間が進むにつれてカウントアップされます。 |
| 完了 | ステップは正常に終了しました。 |
| 警告 | ステップは終了しましたが、[ワークフローログ](/ja/guides/workflows/viewing-workflow-log/)で確認すべき事項が報告されました。 |
| エラー | ステップは失敗しました。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。 |
| スキップ | ステップは実行されませんでした。無効になっているか、実行条件が満たされなかったためです。[ワークフローのステップのスキップ](/ja/guides/workflows/skip-steps-in-a-workflow/)を参照してください。 |
| 続行 | ステップは失敗しましたが、エラー時に続行する設定になっているため、ワークフローは処理を続けました。[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。 |
| 停止済み | ステップが終了する前に、実行が停止されました。 |
| 中止 | ステップの実行が中断されたため、完了することはありません。実行を再開するか、ワークフローを再実行してください。 |

実行の進行に合わせて、開いているワークフロービューは自動的に更新されます。そのため、ページを再読み込みしなくても、表示しているステータスは常に最新です。

### 中止されたステップ

ステップを実行していたものが実行の途中で失われた場合、そのステップは**中止**とマークされます。最も多い原因は、誰かが**停止**を押したか、プラットフォームのメンテナンスで実行が中断されたことです。ステップの実行時間のカウントアップは止まり、ステータスのツールチップに何が起きたかが表示されます。

中止されたステップは完了しておらず、出力も生成されていません。処理が遅いステップではなく、データや構成の問題でもありません。

作業を再開するには、実行を[**再開**](#一時停止停止再開)します。この場合、中止されたステップが再度実行されます。または、ワークフロー全体を再実行します。どちらも安全です。

### 中断されたステップ

実行中にステップを実行していたサーバーが失われた場合、PlaidCloudは、安全に繰り返せるときにそのステップを自動的に再実行します。出力を置き換えるステップは、1回で正常に実行した場合と同じ結果になるため、確認の必要はありません。

安全に繰り返せないステップは再実行されません。このようなステップは、**中断**メッセージとともに1回だけ失敗します。2回目を実行すると、最初の試行がすでに書き込んだものが重複する可能性があるためです。名前またはパスに`{date}`を含む出力を書き込むステップは、再実行すると別の日付になる可能性があるため、安全に繰り返せないものとして扱われます。復旧するには、ステップのターゲットで最初の試行が書き込んだ内容を確認し、必要に応じてクリーンアップしてから、[ステップを再実行](/ja/guides/workflows/running-one-step-in-a-workflow/)するか、実行を**再開**します。

## 一時停止、停止、再開

ワークフローの実行中は、**一時停止**して実行中のステップを終わらせたまま新しいステップを待機させるか、**停止**してキューに入っていたステップと、まだ実行中のインポートまたはエクスポートジョブをキャンセルできます。

**再開**は、一時停止、停止、またはエラーになった実行を、最初からやり直さずに中断した位置から再開します。ワークフローの最後の実行が一時停止、停止、またはエラーの状態で終了している場合は、常に利用できます。

「中断した位置」が何を意味するかは、ワークフローの実行方法によって異なります。

| 実行方式 | 再開時の動作 |
|---|---|
| シリアル | 実行が終了したときに実行中だったステップから再開し、そこから続行します。そのステップがグループ内にある場合、再開はそれを含む最上位のグループ全体を対象とします。グループ内ですでに正常に終了したステップはそのままにし、それ以外を実行して、グループの後から実行を続けます。 |
| 並列 | まだ正常に終了していないすべてのステップを再実行し、完了したステップはそのままにします。 |
| 高度（グラフ） | 失敗したノードと、それを待機しているすべてのものを再実行し、完了したノードはそのままにします。 |

別のワークフローを呼び出すステップ（**Run Model**、**Conditional Run Model**、**Loop Model**）は、呼び出し先のワークフローを最初からやり直すのではなく、再開します。これは入れ子が何階層あっても同様です。ループステップは、中断された反復を再開し、すでに完了した反復はスキップします。

親ワークフローの**Run Model**ステップによって呼び出された**入れ子の子**として実行されたワークフローを再開する場合、PlaidCloudは**チェーンの先頭から再開**を提示します。子だけを再開しても親のオーケストレーションを続行できないため、このオプションは最上位の親（チェーンのルート）を再開し、チェーン全体を停止した位置から続行します。最上位のワークフローの再開は従来どおりです。チェーンの先頭は同じプロジェクト内で解決されます。別のプロジェクトにまたがるチェーンは、プロジェクト内の部分の先頭から再開されます。

再開は常に**元の**実行を続行します。その実行のうち正常に終了しなかったすべてのステップを再実行します。失敗したステップや中止されたステップは、完了したものとして扱われず再実行されます。その間に個々のステップを単独で再実行しても、次に再開が拾う内容は変わりません。

再開された実行は、ワークフローの実行履歴に**新しい実行**として記録され、再実行したステップのみが含まれます。元の実行は、独自の履歴エントリのまま残ります。

:::note
ループステップは、変数の値によって、完了した反復を照合します。元の実行と再開の間に、ループが反復するデータが変更された場合、照合できなくなった反復はスキップされず再実行されます。
:::
