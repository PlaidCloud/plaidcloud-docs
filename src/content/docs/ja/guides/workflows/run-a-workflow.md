ワークフローの実行を開始するには、**ワークフロー**階層で実行アイコンをクリックするか、特定のワークフローの**アクション**メニューから **Run All** を選択します。



ワークフローテーブルの上部にある **Toggle Start/Stop** ボタンをクリックすることもできます。このトグルボタンは、実行中のワークフローを停止し、停止中のワークフローを開始します。

すでに実行中のワークフローで**実行**をクリックすると、PlaidCloudは2つ目の実行を開始せず、実行中であることを通知します。

## 転記モードを選択する

すべての実行には、ERP転記モードが設定されています。PlaidCloudでモードを選択するには、ワークフローの右クリックメニューにある**転記モードを指定して実行**、またはワークフローキャンバスの実行モードボタンを使用します。通常の**ワークフローを開始**や**ワークフローの実行**ではLiveが要求されますが、後述のプロジェクトの上限が適用されます。実行APIやアシスタントから実行を開始するときにも、モードを選択できます。

| モード | 動作 |
|---|---|
| Live | 転記ステップは従来どおりに転記します。これがデフォルトです。 |
| Simulate | すべてのERP転記ステップは、転記する内容を作成して検証しますが、何もコミットせず、ERPにも接続しません。転記予定のエントリは、シミュレーションとして記録され、[ERP転記履歴](/ja/guides/connections/erp-post-history/)で確認できるため、Liveで実行する前に内容をレビューできます。 |
| Off | 転記ステップはすべてスキップされます。 |

プロジェクトにも独自の転記モード上限があります。この上限は、ロックされていないプロジェクトに対する書き込み権限を持つメンバーが、プロジェクトAPIまたはアシスタントから設定できます。上限は実行をより安全にする方向にのみ働き、緩和することはありません。実行の有効なモードは、選択したモードとプロジェクトの上限のうち制限の厳しい方になるため、Simulateに制限されたプロジェクトでは、Liveで実行を開始してもシミュレーションのままです。

[スケジュールされたイベント](/ja/administration/scheduled-events/event-scheduler/#erp転記モード)は独自の転記モードを保持するため、Simulateに設定したスケジュールは、起動のたびにシミュレーションとして実行されます。

モードは、実行が関与するすべての処理に引き継がれます。サブワークフロー、マクロ、**Run Model**ステップ、**Conditional Run Model**ステップ、**Loop Model**ステップはすべて親の実行のモードを継承します。停止後に[再開](#一時停止停止再開)した実行も同様です。シミュレーションの実行は、その内部のどこでも実際に転記することはできません。

:::caution
SAP転記、SAP添付ファイル、および汎用のSAP RFCステップはドライランを行いません。SimulateまたはOffでは完全にスキップされます。SAP独自のテストフラグを使用してもSAPへの実際の接続が開かれるため、ステップをスキップすることが、シミュレーションの実行がSAPに到達しない唯一の方法です。
:::

:::note
個々のERP転記ステップには、実行の転記モードとは別に、独自のValidate Only設定（ステップによってはPreviewまたはTest Only Modeと表示）があります。ステップエディターは、この設定を常に明示的に保存します。REST API、MCP、ワークフローバンドルのインポートなど、別の方法で書き込まれたステップ設定でこの設定が完全に省略されている場合も、ライブ転記ではなくプレビューがデフォルトになります。
:::

## プロジェクトに転記を承認する

ワークフローの実行は、開始した本人ではなく、プロジェクトとしてERPに転記します。実行が転記できるようにするには、転記ステップが使用するERP接続と環境ごとに、プロジェクトの承認が必要です。承認がない場合、ステップは接続と環境を示す「This project isn't authorized to post to connection …」というメッセージで失敗します。**Call SAP Financial Document Attachment**ステップ、**Call SAP Master Data Table RFC**ステップ、**Call SAP RFC**ステップでは承認は不要です。

プロジェクトを承認するには、プロジェクトのホームページを開き、**ERP転記**の下にある**ERP書き込み承認**を選択します。各行は、1つの環境における1つの接続を表します。**承認済み**にチェックを入れるとプロジェクトがそこに転記できるようになり、チェックを外すと転記できなくなります。**承認者**と**承認日時**には、最後に承認した人とその日時が表示されます。

- このボタンはプロジェクトのアーキテクトとワークスペース管理者に表示されますが、承認を変更できるのはアーキテクトのみで、プロジェクトがロックされていない場合に限ります。アーキテクトではないワークスペース管理者は、先に自分自身をアーキテクトとして追加できます。
- 行を選択して承認または解除しても、リストは再読み込みされません。スクロール位置と選択した列の並べ替えはそのまま維持されます。ウィンドウのサイズは変更でき、公開プロジェクトに関する注記は全文が折り返して表示されます。
- 接続を承認するには、自分自身にもその接続への書き込みアクセスが必要です。接続を所有しているか、名前またはセキュリティグループを通じて共有されている必要があります。**すべてのワークスペースメンバー**に設定された接続は対象になりません。
- **すべてのワークスペースメンバー**に設定されたプロジェクトも、他のプロジェクトと同様に承認します。すべてのメンバーがそのプロジェクトのアーキテクトであるため、接続への書き込みアクセスを持つメンバーであれば、そのプロジェクトを承認できます。承認されると、どのメンバーもプロジェクトのワークフローからその接続に転記できます。ウィンドウでは、グリッドの上にその旨が表示されます。
- コピーしたプロジェクトや、プロジェクトアーカイブから作成したプロジェクトには、承認が引き継がれません。転記する前に、コピーを承認してください。

## ステップのステータスを確認する

ワークフローの実行中は、各ステップに現在の状態を示すステータスアイコンと、実行時間が表示されます。アイコンにカーソルを合わせると、その背景にあるメッセージが表示されます。

| ステータス | 意味 |
|---|---|
| 待機中 | ステップはキューに入っており、まだ開始されていません。 |
| 実行中 | ステップが処理中で、実行時間が進んでいきます。 |
| 完了 | ステップが正常に終了しました。 |
| 警告 | ステップは終了しましたが、[ワークフローログ](/ja/guides/workflows/viewing-workflow-log/)で確認すべき内容があります。 |
| エラー | ステップが失敗しました。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。 |
| スキップ | ステップは無効になっているか、実行条件を満たさなかったため、実行されませんでした。[ワークフローでステップをスキップする](/ja/guides/workflows/skip-steps-in-a-workflow/)を参照してください。 |
| 続行 | ステップは失敗しましたが、エラー時に続行する設定になっているため、ワークフローは処理を続けました。[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。 |
| 停止 | ステップが終了する前に、実行が停止されました。 |
| 放棄 | ステップの実行が中断されたため、終了することはありません。実行を再開するか、ワークフローを再実行してください。 |

開いているワークフロービューは、実行の進行に合わせて自動的に更新されるため、ページを再読み込みしなくても、表示中のステータスは常に最新です。

### 放棄されたステップ

ステップを実行していたものが実行中に失われると、そのステップは**放棄**とマークされます。多くの場合、誰かが**停止**を押したか、プラットフォームのメンテナンスによって実行が中断されたことが原因です。ステップの実行時間は進まなくなり、ステータスのツールチップに状況が説明されます。

放棄されたステップは完了しておらず、出力も生成されていません。処理が遅いステップではなく、データや設定の問題でもありません。

作業を再開するには、実行を[**再開**](#一時停止停止再開)します。放棄されたステップが再び実行されます。または、ワークフロー全体を再実行します。どちらの方法でも安全です。

### 中断されたステップ

ステップを実行しているサーバーが実行中に失われた場合、PlaidCloudは、安全に繰り返せるときにそのステップを自動的に再実行します。出力を置き換えるステップは、1回で正常に実行された場合と同じ結果になるため、確認の必要はありません。

安全に繰り返せないステップは再実行されません。2回目の実行によって、最初の試行ですでに書き込まれた内容が重複する可能性があるため、**中断**メッセージとともに1回だけ失敗します。名前やパスに `{date}` を含む出力を書き込むステップは、再実行すると別の日付になる可能性があるため、安全に繰り返せないものとして扱われます。復旧するには、ステップのターゲットで最初の試行が書き込んだ内容を確認し、必要に応じてクリーンアップしてから、[ステップを再実行](/ja/guides/workflows/running-one-step-in-a-workflow/)するか、実行を**再開**します。

### 開始されないステップ

インポートステップまたはディメンションステップのジョブをどのワーカーも約40分以内に取得しなかった場合、24時間のタイムアウトまで**実行中**と表示され続けるのではなく、ステップは失敗します。ワーカーがジョブを開始した後に失われた場合も、ワーカーが停止したことを示すメッセージとともにステップは失敗します。どちらのメッセージにも、「Use Run from here to retry.」と表示されます。

## 一時停止、停止、再開

ワークフローの実行中は、**一時停止**して実行中のステップを完了させ新しいステップを待機させることも、**停止**してキューに入っているステップと実行中のインポートまたはエクスポートジョブをキャンセルすることもできます。キューに入っていたインポートステップとディメンションステップは正常にキャンセルされるため、ワークスペース内の後続のインポートやディメンションのロードを妨げることはありません。

**再開**は、一時停止、停止、または失敗した実行を、最初からやり直すのではなく中断した位置から続行します。ワークフローの最後の実行が、一時停止、停止、またはエラーの状態で終了している場合に利用できます。

「中断した位置」が何を意味するかは、ワークフローの実行方法によって異なります。

| 実行方式 | 再開時の動作 |
|---|---|
| シリアル | 実行が終了した時点で実行中だったステップから再開し、そこから続行します。そのステップがグループ内にある場合、再開ではそれを含むトップレベルのグループ全体が対象になります。グループ内ですでに正常に完了したステップはそのままにし、それ以外を実行して、グループの後から実行を続けます。 |
| 並列 | 正常に完了していないステップをすべて再実行し、完了済みのステップはそのままにします。 |
| 高度（グラフ） | 失敗したノードと、それを待機しているすべてのノードを再実行し、完了済みのノードはそのままにします。 |

別のワークフローを呼び出すステップ（**Run Model**ステップ、**Conditional Run Model**ステップ、**Loop Model**ステップ）は、呼び出したワークフローを最初からやり直すのではなく、そのワークフローを再開します。これは、ネストの階層がいくつあっても同様です。ループステップは、中断されたイテレーションから再開し、すでに完了したイテレーションはスキップします。

別のワークフローの**ネストされた子**として実行されたワークフロー（親の**Run Model**ステップが呼び出したもの）を再開するときは、PlaidCloudに**チェーンの先頭から再開**が表示されます。子だけを再開しても親のオーケストレーションを続行できないため、このオプションでは最上位の親（チェーンのルート）を再開し、停止した位置からチェーン全体を続行します。最上位のワークフローの再開は従来どおりです。チェーンの先頭は同じプロジェクト内で解決されます。別のプロジェクトにまたがるチェーンは、プロジェクト内の部分の先頭から再開されます。

再開は常に**元の**実行を続行します。その実行のうち正常に完了しなかったすべてのステップを再実行します。失敗または放棄されたステップは、完了済みとして扱われずに再実行されます。その間に個々のステップを単独で再実行しても、次の再開で対象となるステップは変わりません。

再開された実行は、ワークフローの実行履歴に**新しい実行**として記録され、再実行したステップのみが含まれます。元の実行は、独自の履歴エントリを保持します。

:::note
ループステップは、変数の値によって完了済みのイテレーションを照合します。元の実行から再開までの間にループが処理するデータが変更された場合、照合できなくなったイテレーションはスキップされず再実行されます。
:::
