ワークフロー全体の実行は、**ワークフロー**階層で実行アイコンをクリックするか、特定のワークフロー内の**アクション**メニューから**Run All**を選択して開始できます。



ワークフローテーブルの上部にある**Toggle Start/Stop**ボタンをクリックすることもできます。このトグルボタンは、実行中のワークフローを停止するか、ワークフローを開始します。

すでに実行中のワークフローで**実行**をクリックすると、PlaidCloudは2回目の実行を開始せずに、すでに実行中であることを通知します。

## 転記モードを選択する

すべての実行にはERP転記モードがあります。PlaidCloudでモードを選択するには、ワークフローの右クリックメニューの**転記モードを指定して実行**、またはワークフローキャンバスの実行モードボタンを使用します。通常の**ワークフローを開始**または**ワークフローの実行**ではLiveが要求されますが、後述するプロジェクトの上限は引き続き適用されます。実行APIまたはアシスタントで実行を開始するときにもモードを選択できます。

| モード | 動作 |
|---|---|
| Live | 転記ステップはこれまでどおりに転記します。これがデフォルトです。 |
| Simulate | すべてのERP転記ステップは、転記する内容を正確に作成して検証しますが、何もコミットせず、ERPに接続することもありません。転記される予定だったエントリはシミュレーション済みとして[ERP転記履歴](/ja/guides/connections/erp-post-history/)に記録されるため、本番で実行する前に確認できます。 |
| Off | 転記ステップは完全にスキップされます。 |

プロジェクトにも独自の転記モードの上限があり、ロックされていないプロジェクトへの書き込みアクセス権を持つメンバーであれば誰でも、プロジェクトAPIまたはアシスタントで設定できます。上限は実行をより安全にする方向にのみ働き、より許容的にすることはありません。実行の有効なモードは、選択したモードとプロジェクトの上限のうち制限が厳しい方になります。そのため、Simulateに上限が設定されたプロジェクトでは、Liveとして実行を開始してもシミュレーションのままになります。

[スケジュールされたイベント](/ja/administration/scheduled-events/event-scheduler/#erp転記モード)は独自の転記モードを保持するため、Simulateに設定されたスケジュールは起動するたびにシミュレーションで実行されます。

モードは、実行が関わるすべてのものに引き継がれます。サブワークフロー、マクロ、および**Run Model**、**Conditional Run Model**、**Loop Model**ステップはすべて親の実行のモードを継承し、停止後に[再開](#一時停止停止再開)した実行も同様です。シミュレーションの実行が、その内部のどこかで実際に転記することはありません。

:::caution
SAPの転記、SAPの添付、および汎用SAP RFCステップはドライランを行いません。SimulateまたはOffでは完全にスキップされます。SAP独自のテストフラグを使用してもSAPへの実際の接続が開かれるため、ステップをスキップすることが、シミュレーションの実行がSAPに到達しないようにする唯一の方法です。
:::

:::note
個々のERP転記ステップにも独自の「Validate Only」設定（一部のステップでは「Preview」または「Test Only Mode」と表示）があり、上記の実行の転記モードとは独立しています。ステップエディターでは、この設定が常に明示的に保存されます。REST API、MCP、ワークフローバンドルのインポートなど、別の方法で作成されたステップ構成でこの設定が完全に省略されている場合も、本番の転記ではなくプレビューがデフォルトになりました。
:::

## プロジェクトに転記を承認する

ワークフローの実行は、実行を開始したユーザーとしてではなく、プロジェクトとしてERPに転記します。実行が転記できるようにするには、転記ステップが使用するERP接続と環境ごとに、プロジェクトの承認が必要です。承認がない場合、ステップは接続と環境を示して「このプロジェクトには接続…への転記が承認されていません」というメッセージで失敗します。**Call SAP Financial Document Attachment**、**Call SAP Master Data Table RFC**、**Call SAP RFC**ステップには承認は不要です。

プロジェクトを承認するには、プロジェクトのホームページを開き、**ERP転記**の下にある**ERP書き込み承認**を選択します。各行は、1つの環境における1つの接続を表します。プロジェクトがそこに転記できるようにするには**承認済み**にチェックを入れ、停止するにはチェックを外します。**承認者**と**承認日時**には、最後に承認したユーザーとその日時が表示されます。

- このボタンはプロジェクトのアーキテクトとワークスペース管理者に表示されますが、承認を変更できるのはアーキテクトだけで、プロジェクトがロックされていない間に限られます。アーキテクトではないワークスペース管理者は、先に自分をアーキテクトとして追加できます。
- 承認またはクリアするために行を選択しても、一覧は再読み込みされません。スクロール位置や選択した列の並べ替えはそのまま保持されます。ウィンドウはサイズを変更でき、公開プロジェクトに関する注記は全文が折り返して表示されます。
- 接続を承認するには、自分自身もその接続への書き込みアクセス権を持っている必要があります。つまり、その接続を所有しているか、名前またはいずれかのセキュリティグループを通じて共有されている必要があります。**すべてのワークスペースメンバー**に設定された接続は対象外です。
- **すべてのワークスペースメンバー**に設定されたプロジェクトも、他のプロジェクトと同様に承認されます。すべてのメンバーがそのプロジェクトのアーキテクトであるため、接続への書き込みアクセス権を持つメンバーであれば誰でも、その接続についてプロジェクトを承認できます。承認されると、どのメンバーもプロジェクトのワークフローからその接続に転記でき、ウィンドウのグリッドの上にその旨が表示されます。
- テーブルデータまたはディメンションメンバーを含めて作成した、自分だけが表示できる新しいコピーは、コピー元の承認のうち自分が付与できるものを保持し、コピー元がLiveだった場合はSimulateの状態で届きます。[コピーにおけるERP書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認)を参照してください。それ以外のコピーや、プロジェクトアーカイブから作成されたプロジェクトは、承認なしで開始されます。転記する前に承認してください。

## ステップのステータスを確認する

ワークフローの実行中、各ステップには現在の状況を示すステータスアイコンと、実行時間が表示されます。アイコンにカーソルを合わせると、その背後にあるメッセージが表示されます。

| ステータス | 意味 |
|---|---|
| 待機中 | ステップはキューに入っており、まだ開始していません。 |
| 実行中 | ステップは処理中で、進行に応じて実行時間がカウントアップされます。 |
| 完了 | ステップは正常に完了しました。 |
| 警告 | ステップは完了しましたが、[ワークフローログ](/ja/guides/workflows/viewing-workflow-log/)で確認すべき事項を報告しました。 |
| エラー | ステップは失敗しました。[ステップのエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。 |
| スキップ | ステップは飛ばされました。無効になっているか、実行条件が満たされませんでした。[ワークフロー内のステップをスキップする](/ja/guides/workflows/skip-steps-in-a-workflow/)を参照してください。 |
| 続行 | ステップは失敗しましたが、エラー時に続行するよう設定されているため、ワークフローは処理を続けました。[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。 |
| 停止 | ステップが完了する前に実行が停止されました。 |
| 放棄 | ステップの実行が中断されたため、完了することはありません。実行を再開するか、ワークフローを再実行してください。 |

開いているワークフロービューは実行の進行に応じて自動的に更新されるため、ページを再読み込みしなくても、表示中のステータスは常に最新の状態に保たれます。

### 放棄されたステップ

ステップを実行していたものが実行の途中でなくなった場合、ステップは**放棄**とマークされます。最も多いのは、誰かが**停止**を押した場合や、プラットフォームのメンテナンスによって実行が中断された場合です。ステップの実行時間の増加は止まり、ステータスのツールチップに何が起きたかが説明されます。

放棄されたステップは完了しておらず、出力も生成していません。処理が遅いステップではなく、データや構成の問題でもありません。

作業を再開するには、実行を[**再開**](#一時停止停止再開)する（放棄されたステップが再度実行されます）か、ワークフロー全体を再実行します。どちらも安全です。

### 中断されたステップ

ステップを実行しているサーバーが実行の途中で失われた場合、繰り返しても安全なステップであれば、PlaidCloudはそのステップを自動的に再実行します。出力を置き換えるステップは、1回のクリーンな実行と同じ結果になるため、何も確認する必要はありません。

安全に繰り返すことができないステップは再実行されません。2回目の実行で最初の試行がすでに書き込んだ内容が重複する可能性があるため、そのステップは**中断**メッセージとともに1回だけ失敗します。名前やパスに`{date}`を含む出力を書き込むステップは、再実行すると別の日付になる可能性があるため、安全に繰り返せないものとみなされます。復旧するには、最初の試行が書き込んだ内容をステップのターゲットで確認し、必要に応じてクリーンアップしてから、[ステップを再実行](/ja/guides/workflows/running-one-step-in-a-workflow/)するか、実行を**再開**します。

### 開始されないステップ

インポートステップまたはディメンションステップのジョブを約40分以内にどのワーカーも取得しない場合、ステップは24時間のタイムアウトまで**実行中**と表示され続けるのではなく、失敗します。ワーカーがジョブを開始した後にいなくなった場合も、ワーカーが停止したことを示すメッセージとともにステップは失敗します。どちらのメッセージにも「ここから実行で再試行してください。」と表示されます。

## 一時停止、停止、再開

ワークフローの実行中は、**一時停止**して処理中のステップを完了させ、新しいステップを待機させることも、**停止**してキューに入っていたステップと、まだ実行中のインポートジョブやエクスポートジョブをキャンセルすることもできます。キューに入ったままのインポートステップとディメンションステップは正常にキャンセルされるため、ワークスペース内の後続のインポートやディメンションの読み込みを妨げることはありません。

**再開**は、一時停止、停止、または失敗した実行を、最初からやり直すのではなく中断したところから再開します。ワークフローの最後の実行が一時停止、停止、またはエラーの状態で終了した場合にいつでも使用できます。

「中断したところ」の意味は、ワークフローの実行方法によって異なります。

| 実行方式 | 再開時 |
|---|---|
| シリアル | 実行が終了したときに実行中だったステップから再開し、そこから続行します。そのステップがグループ内にある場合、再開はそれを含む最上位のグループ全体を対象とします。グループ内ですでに正常に完了したステップはそのままにして他のステップを実行し、グループの後から実行を続行します。 |
| パラレル | まだ正常に完了していないすべてのステップを再実行し、完了したステップはそのままにします。 |
| 高度（グラフ） | 失敗したノードと、それを待機しているすべてのノードを再実行し、完了したノードはそのままにします。 |

別のワークフローを呼び出すステップ（**Run Model**、**Conditional Run Model**、**Loop Model**）は、ネストが何階層あっても、呼び出すワークフローを最初からやり直すのではなく再開します。ループステップは中断された反復を再開し、すでに完了した反復はスキップします。

別のワークフローの**ネストされた子**として実行されたワークフロー（親の**Run Model**ステップが呼び出したもの）を再開すると、PlaidCloudは**チェーンの先頭から再開**を提示します。子を単独で再開しても親のオーケストレーションを続行できないため、このオプションは代わりに最上位の親（チェーンのルート）を再開し、チェーン全体を停止したところから続行します。最上位のワークフローの再開は変わりません。チェーンの先頭は同じプロジェクト内で解決されます。別のプロジェクトにまたがるチェーンは、プロジェクト内の部分の先頭から再開されます。

再開は常に**元の**実行を続行します。その実行のうち正常に完了しなかったすべてのステップを再実行します。失敗したステップや放棄されたステップは完了扱いにはならず、再実行されます。また、その間に個々のステップを単独で再実行しても、再開が次に取り上げる内容は変わりません。

再開された実行は、ワークフローの実行履歴に**新しい実行**として記録され、再実行したステップだけが含まれます。元の実行は独自の履歴エントリを保持します。

:::note
ループステップは、完了した反復を変数の値で照合します。元の実行と再開の間にループが反復するデータが変更された場合、照合できなくなった反復はスキップされずに再実行されます。
:::
