ワークフロー全体の実行を開始するには、**ワークフロー**の階層にある実行アイコンをクリックするか、特定のワークフロー内の**アクション**メニューから **Run All** を選択します。



ワークフローテーブルの上部にある **Toggle Start/Stop** ボタンをクリックすることもできます。このトグルボタンは、実行中のワークフローを停止するか、ワークフローを開始します。

すでに実行中のワークフローで**実行**をクリックした場合、PlaidCloudは2つ目の実行を開始せず、その旨を通知します。

## 転記モードを選択する

すべての実行には、ERP転記モードが設定されます。PlaidCloudでモードを選択するには、ワークフローの右クリックメニューにある**転記モードを指定して実行**、またはワークフローキャンバスの実行モードボタンを使用します。通常の**ワークフローを開始**や**ワークフローの実行**ではLiveが指定され、後述するプロジェクトの上限が引き続き適用されます。実行APIまたはアシスタントから実行を開始する場合にも、モードを選択できます。

| モード | 動作 |
|---|---|
| Live | 転記ステップは、これまでとまったく同じように転記します。これがデフォルトです。 |
| Simulate | すべてのERP転記ステップは、転記する内容を正確に構築して検証しますが、何もコミットせず、ERPにも接続しません。転記されるはずだったエントリは、シミュレーション済みとして[ERP転記履歴](/ja/guides/connections/erp-post-history/)に記録されるため、Liveで実行する前に確認できます。 |
| Off | 転記ステップはすべてスキップされます。 |

プロジェクトにも独自の転記モード上限があり、ロックされていないプロジェクトへの書き込みアクセス権を持つメンバーなら誰でも、プロジェクトAPIまたはアシスタントから設定できます。上限は実行をより安全にする方向にのみ働き、より許容的にすることはありません。実行の有効なモードは、選択したモードとプロジェクトの上限のうち、より制限の厳しいほうになります。そのため、上限がSimulateに設定されたプロジェクトは、Liveで実行を開始してもシミュレーションのままです。

[スケジュールされたイベント](/ja/administration/scheduled-events/event-scheduler/#erp転記モード)は独自の転記モードを保持するため、Simulateに設定されたスケジュールは、起動のたびにシミュレーションとして実行されます。

モードは、実行が触れるすべてのものに引き継がれます。サブワークフロー、マクロ、および **Run Model**、**Conditional Run Model**、**Loop Model** の各ステップはすべて親の実行のモードを継承します。停止後に[再開](#一時停止停止再開)した実行も同様です。シミュレーションの実行は、その内部のどこでも実際に転記することはできません。

:::caution
SAP転記、SAP添付、および汎用のSAP RFCステップはドライランされません。SimulateまたはOffでは完全にスキップされます。SAP独自のテストフラグを使用してもSAPへの実際の接続が開かれるため、ステップをスキップすることが、シミュレーションの実行がSAPに到達しないようにする唯一の方法です。
:::

:::note
個々のERP転記ステップには、実行の転記モードとは別に、独自のValidate Only設定（ステップによってはPreviewまたはTest Only Modeと表示されます）もあります。ステップエディターは常にこれを明示的に保存します。REST API、MCP、ワークフローバンドルのインポートなど、別の方法で書き込まれたステップ構成でこの設定が完全に省略されている場合も、ライブ転記ではなくプレビューがデフォルトになりました。
:::

## プロジェクトに転記を承認する

ワークフローの実行は、実行を開始した人ではなく、プロジェクトとしてERPに転記します。実行が転記できるようにするには、転記ステップが使用するERP接続と環境ごとに、プロジェクトの承認が必要です。承認がない場合、ステップは接続と環境を示す「このプロジェクトには接続 … への転記が承認されていません」というメッセージで失敗します。**Call SAP Financial Document Attachment**、**Call SAP Master Data Table RFC**、**Call SAP RFC** の各ステップには承認は不要です。

プロジェクトを承認するには、プロジェクトのホームページを開き、**ERP転記**の下にある**ERP書き込み承認**を選択します。各行は、1つの環境における1つの接続を表します。そこでプロジェクトが転記できるようにするには**承認済み**にチェックを入れ、停止するにはチェックを外します。**承認者**と**承認日時**には、最後に承認した人とその日時が表示されます。

- このボタンはプロジェクトのアーキテクトとワークスペース管理者に表示されますが、承認を変更できるのはアーキテクトのみで、しかもプロジェクトがロックされていない場合に限られます。アーキテクトでないワークスペース管理者は、先に自分をアーキテクトとして追加できます。
- 行を選択して承認または解除しても、リストは再読み込みされません。スクロール位置と、選択した列の並べ替えはそのまま保たれます。ウィンドウはサイズ変更でき、パブリックプロジェクトに関する注記は折り返して全文が表示されます。
- 接続を承認するには、自分自身にもその接続への書き込みアクセス権が必要です。つまり、自分が所有しているか、名前で、またはいずれかのセキュリティグループを通じて共有されている必要があります。**すべてのワークスペースメンバー**に設定された接続は対象になりません。
- **すべてのワークスペースメンバー**に設定されたプロジェクトも、他のプロジェクトと同様に承認されます。すべてのメンバーがそのプロジェクトのアーキテクトであるため、接続への書き込みアクセス権を持つメンバーなら誰でも、その接続についてプロジェクトを承認できます。いったん承認されると、どのメンバーもプロジェクトのワークフローからその接続に転記できます。ウィンドウでは、グリッドの上にその旨が表示されます。
- テーブルデータまたはディメンションメンバーを含めて作成した、自分専用の新しいコピーでは、自分で付与できるソースの承認が引き継がれます。ソースがLiveだった場合、コピーはSimulateの状態で作成されます。詳しくは、[コピーにおけるERP書き込み承認](/ja/guides/projects/managing-projects/#コピーにおけるerp書き込み承認)を参照してください。それ以外のコピーや、プロジェクトアーカイブから作成したプロジェクトには、承認がない状態で始まります。転記する前に承認してください。

## ステップのステータスを確認する

ワークフローの実行中、各ステップには、現在の状態を示すステータスアイコンと、実行にかかっている時間が表示されます。アイコンにカーソルを合わせると、その背景にあるメッセージが表示されます。

| ステータス | 意味 |
|---|---|
| 待機中 | ステップはキューに入っており、まだ開始されていません。 |
| 実行中 | ステップが処理中で、経過時間がカウントアップされます。 |
| 完了 | ステップが正常に完了しました。 |
| 警告 | ステップは完了しましたが、[ワークフローログ](/ja/guides/workflows/viewing-workflow-log/)で確認すべき内容が検出されました。 |
| エラー | ステップが失敗しました。[ステップエラーの管理](/ja/guides/workflows/managing-step-errors/)を参照してください。 |
| スキップ | ステップは無効になっているか、実行条件が満たされなかったため、実行されませんでした。[ワークフローでステップをスキップする](/ja/guides/workflows/skip-steps-in-a-workflow/)を参照してください。 |
| 続行 | ステップは失敗しましたが、エラー時に続行する設定になっているため、ワークフローは処理を続けました。[エラー時に続行](/ja/guides/workflows/continue-on-error/)を参照してください。 |
| 停止 | ステップが完了する前に、実行が停止されました。 |
| 放棄 | ステップの実行が中断されたため、完了することはありません。実行を再開するか、ワークフローを再実行してください。 |

開いているワークフロービューは、実行の進行に合わせて自動的に更新されるため、ページを再読み込みしなくても、表示中のステータスは常に最新です。

### 放棄されたステップ

ステップを実行していたものが実行の途中でなくなった場合、そのステップは**放棄**とマークされます。最も多い原因は、誰かが**停止**を押したか、プラットフォームのメンテナンスによって実行が中断されたことです。ステップの経過時間のカウントは止まり、ステータスのツールチップに何が起きたかが表示されます。

放棄されたステップは完了しておらず、出力も生成されていません。処理が遅いステップではなく、データや構成の問題でもありません。

作業を再開するには、実行を[**再開**](#一時停止停止再開)する（放棄されたステップが再度実行されます）か、ワークフロー全体を再実行します。どちらも安全です。

### 中断されたステップ

ステップを実行していたサーバーが実行の途中で失われた場合、安全に繰り返せるときは、PlaidCloudがそのステップを自動的に再実行します。出力を置き換えるステップは、1回の正常な実行と同じ結果になるため、確認する必要はありません。

安全に繰り返せないステップは再実行されません。2回目の実行では、最初の試行がすでに書き込んだ内容が重複する可能性があるため、そのステップは**中断**メッセージとともに一度だけ失敗します。名前またはパスに `{date}` を含む出力を書き込むステップは、再実行すると別の日付になる可能性があるため、安全に繰り返せないものとして扱われます。復旧するには、ステップのターゲットで最初の試行が書き込んだ内容を確認し、必要に応じてクリーンアップしてから、[ステップを再実行](/ja/guides/workflows/running-one-step-in-a-workflow/)するか、実行を**再開**します。

### 開始されないステップ

ステップがワーカーを待っている間、ステータスメッセージには「ワーカーを待機中… N分。このステップをまだ取得したインポートワーカーはありません。」と表示されます（ワーカーの種類はステップに応じて、インポートやエクスポートなどになります）。作業が開始されると、メッセージは消えます。

ステップのジョブを開始できない場合、ステップは永久に待ち続けるのではなく、理由を示して失敗します。

| 原因 | 失敗するまでの時間（約） |
|---|---|
| インポートまたはディメンションステップのジョブを取得するワーカーがない | 40分 |
| ステップのPodがPendingのまま止まっている | 20分 |
| ステップのイメージをプルできない | 5分 |
| ステップ用のPodが作成されない | 20分 |
| コネクター（Singer）の同期を取得するランナーがない | 30分 |

コネクターの同期に関するメッセージには、その同期が示されます。ワーカーがジョブを開始した後に失われた場合も、ステップはワーカーが停止した旨のメッセージとともに失敗します。インポートとディメンションのメッセージには、「Run from here を使用して再試行してください。」と表示されます。

## 一時停止、停止、再開

ワークフローの実行中は、**一時停止**して、実行中のステップは完了させつつ新しいステップを待機させることも、**停止**してキューに入っていたステップと、まだ実行中のインポートまたはエクスポートジョブをキャンセルすることもできます。キューに入っていたインポートおよびディメンションステップは正常にキャンセルされるため、ワークスペース内の後続のインポートやディメンションのロードを妨げません。停止すると、ワークフローのキューに入っているまたは実行中のコネクター（Singer）の同期も停止されるため、ワークフローが停止した後に同期が実行され続けることはありません。

**再開**すると、一時停止、停止、または失敗した実行を、最初からやり直すのではなく、中断した箇所から続行します。ワークフローの最後の実行が一時停止、停止、またはエラーの状態で終了していれば、いつでも利用できます。

「中断した箇所」が何を意味するかは、ワークフローの実行方法によって異なります。

| 実行方式 | 再開時の動作 |
|---|---|
| シリアル | 実行が終了した時点で実行中だったステップから再開し、そこから続行します。そのステップがグループ内にある場合、再開はそれを含む最上位のグループ全体を対象にします。グループ内ですでに正常に完了したステップはそのままにされ、それ以外が実行され、グループの後から実行が続行されます。 |
| 並列 | まだ正常に完了していないすべてのステップを再実行し、完了したステップはそのままにします。 |
| 高度なワークフロー（グラフ） | 失敗したノードと、それを待っているすべてのものを再実行し、完了したノードはそのままにします。 |

別のワークフローを呼び出すステップ（**Run Model**、**Conditional Run Model**、**Loop Model**）は、呼び出したワークフローを最初からやり直すのではなく再開します。これは、ネストが何階層あっても同様です。ループステップは、中断されたイテレーションを再開し、すでに完了したイテレーションをスキップします。

別のワークフローの**ネストされた子**として実行されたワークフロー（親の **Run Model** ステップによって呼び出されたもの）を再開する場合、PlaidCloudは**チェーンの先頭から再開**を提供します。子を単独で再開しても親のオーケストレーションを続行できないため、このオプションでは代わりに最上位の親（チェーンのルート）を再開し、停止した箇所からチェーン全体を続行します。最上位のワークフローの再開は従来どおりです。チェーンの先頭は同じプロジェクト内で解決されます。別のプロジェクトにまたがるチェーンは、プロジェクト内の部分の先頭から再開されます。

再開は常に**元の**実行を続行します。その実行のうち正常に完了しなかったすべてのステップを再実行します。失敗したステップや放棄されたステップは、完了したものとして扱われず再実行されます。また、その間に個々のステップを単独で再実行しても、次に再開が拾い上げる対象は変わりません。

再開された実行は、ワークフローの実行履歴に**新しい実行**として記録され、再実行したステップのみが含まれます。元の実行は、独自の履歴エントリを保持します。

:::note
ループステップは、完了したイテレーションを変数の値で照合します。元の実行と再開の間にループが反復するデータが変更された場合、照合できなくなったイテレーションはスキップされず、再実行されます。
:::
