PlaidCloudは、Alteryxのワークフローを高度なワークフローとしてインポートし、インポート中に変換の詳細を報告します。このガイドを使うと、依存関係パッケージの補完、生成されたマクロの確認、変数の調整、検証の比較結果の解釈を迅速に行えます。

<Aside type="note">
  まず変換サマリーを確認してください。個々のステップを調べる前に、依存関係、マクロ、変数、エグゼキューター、検証に関する項目が強調表示されます。
</Aside>

## 入力ファイルの補完

症状：

- 変換レポートに、不足しているファイルが一覧表示されている。
- 実行が「No files found at &lt;path&gt;; the target table was created empty.」という警告で終了する。
- 動的入力でファイルが1つも解決されない。
- 検証の行数が想定より少ない。

ワークフローは、読み取るファイルが不足していても変換されるため、未対応の項目を最も早く確認する方法はレポートです。レポートには、不足している各ファイルのアップロード先のドキュメントパス、元のAlteryxパス、想定されるシート、そのファイルを読み取るツールが示されます。

オフにされているAlteryxのツールコンテナー内のツールだけが読み取るファイルは、そのツールもインポートされないため、この一覧には表示されません。[キャンバス上のコメントとツールコンテナー](/ja/guides/workflows/migrate-alteryx-workflows/#キャンバス上のコメントとツールコンテナー)を参照してください。そのファイルを取り込みたい場合は、コンテナーをオンにするか、オフのコンテナーのツールを通常のステップとして取り込むオプションを指定して、再インポートしてください。

対処：

1. レポートに一覧表示されている各ファイルを、示されているドキュメントパスにアップロードします。
2. ほとんどのファイルは、アップロード後にワークフローを再実行するだけで済みます。再インポートは不要です。
3. 固定長ASCIIレイアウト、ワイルドカード入力、Dynamic Inputテンプレート、またはFirstRowの名前変更元が不足している場合は、再実行するだけでなく、ワークフローを再度インポートしてください。これらは変換時に読み取られます。
4. アップロード後も、動的ファイルパターンが一致することを確認します。

## 空間サイドカーファイルの補完

症状：

- 空間入力に付随するファイルが必要。
- ジオメトリフィールドが空である。
- 空間出力が想定した結果と異なる。

対処：

1. シェイプファイルまたはMapInfoのサイドカーファイルがすべて含まれていることを確認します。
2. サイドカーファイルは同じドキュメントフォルダーに置きます。
3. ワークフローが座標参照系の動作に依存する場合は、投影ファイルがあることを確認します。
4. パッケージを修正した後、ワークフローを再実行します。

## マクロの補完または明確化

症状：

- マクロの呼び出しを解決できない。
- マクロの入力または出力が接続されていない。
- ワークフローは構造的にはインポートされたが、マクロの出力の接続が必要。

対処：

1. 参照されている各マクロの`.yxmc`ファイルを含めます。
2. それらのマクロが呼び出す入れ子のマクロも含めます。
3. パッケージにバージョン管理されたマクロを意図的に含める場合を除き、マクロ名の重複は避けます。
4. 生成されたPlaidCloudのマクロに、マクロ入力ステップとマクロ出力ステップがあることを確認します。

## 読み取れない.yxdbファイル

症状：

- 同じパッケージの他のファイルは問題なくインポートされるのに、`.yxdb`ファイルのインポートが失敗する。
- ファイルの先頭バイトが`Alteryx Database File`ではなく`Alteryx e2 Database file`になっている。

このファイルは、Alteryx AMPエンジンによって、PlaidCloudが読み取れない独自形式で書き込まれています。Alteryx Designerがまだ使える間に、書き直してください。ファイルを個別に再保存するか、ダウンロード可能なワークフローを使ってフォルダー全体をCSVに一括変換します。[インポート用に.yxdbファイルを変換する](/ja/guides/workflows/convert-yxdb-files-for-import/)を参照してください。

## 読み取れない.cydb（Calgary）データベース

症状：

- 変換されたCalgaryステップが停止し、まだ存在しない`calgary_<database>`テーブルが示される。
- ソースが`.cydb`ファイルである。Alteryxが提供するライセンス付きの人口統計または参照データベース（Experian、国勢調査など）であることが多いです。

AlteryxのCalgaryデータベースは、オープンなリーダーのない独自のインデックス付きストアであるため、PlaidCloudは`.cydb`を直接ロードできません。Calgaryツール自体は変換されます。それぞれの`.cydb`は、`calgary_<database>`という名前の通常の[代替テーブル](/ja/guides/workflows/migrate-alteryx-workflows/#calgaryデータベース)になりますが、そのテーブルのデータはお客様自身で用意する必要があります。

1. Alteryxで、`.cydb`を読み取るCalgary Inputを追加し、そのレコードをオープンな形式で再エクスポートします。**Output Data**ツールでCSVまたはParquetに出力するか、ウェアハウステーブルに出力します。
2. そのファイルを、変換されたワークフローが想定する`calgary_<database>`テーブルとして、PlaidCloudにインポートします。
3. Skip RecordsまたはMax Recordsで読み取りを制限している場合は、エクスポートに順序付けの列を含めてください。代替テーブルには、レコードの固有の順序がありません。

再エクスポートできないライセンス付きの参照データベースについては、同じデータのライセンス付きコピーをご自身で用意して、指定されたテーブルにロードしてください。

## ワークフロー変数の問題

症状：

- 変換されたアプリの入力が未設定である。
- 条件が予期せず発動する。
- ファイル変数またはフォルダー変数がデスクトップのパスを指している。

対処：

1. 実行する前に、ワークフロー変数を確認します。
2. 必要な値を設定します。
3. デスクトップのファイルパスを、ドキュメントのファイルパスまたはフォルダーパスに置き換えます。
4. 制御された選択肢が、想定するアプリの選択と一致していることを確認します。
5. ワークフローを再実行します。

## 検証の差異

症状：

- スキーマが異なる。
- 行数が異なる。
- 行の値が異なる。
- アーティファクトの出力に確認すべき差異がある。

対処：

1. 両方の実行で同じ入力データが使われたことを確認します。
2. 変数の値が一致していることを確認します。
3. ソースシステムが同じスナップショット日付のものであることを確認します。
4. NULLの扱い、日付の扱い、数値の精度、文字列の照合順序を確認します。
5. 空間出力では、ジオメトリの形式と座標参照系の動作を確認します。
6. アーティファクトでは、意図したクラウドネイティブの出力を確認し、ビジネス上の内容を比較します。

## エグゼキューターに関する注記

あいまい一致、空間処理、PDF抽出、OCR、NLP、レポート作成などの専門的な操作は、マネージドエグゼキューターを通じて実行できます。（機械学習パイプラインは、代わりにネイティブの[ML: モデルの学習](/ja/reference/workflow-steps/machine-learning/ml-train/)ステップと[ML: スコアリング](/ja/reference/workflow-steps/machine-learning/ml-score/)ステップに変換されます。）

エグゼキューターが注記を報告した場合：

1. ワークフローの実行の詳細を開きます。
2. ステップの注記を確認します。
3. 必要な入力とパラメーターが揃っていることを確認します。
4. パリティ検証が必要な場合は、想定される出力が利用可能であることを確認します。
5. 入力または設定を修正した後、再実行します。

## 再インポートするタイミング

次の場合は再インポートします。

- 元のパッケージの後に、重要なファイルやマクロが追加された。
- 誤ったドキュメントパスが選択された。
- インポートしたバージョンを、新しいワークフローのバージョンで置き換える必要がある。
- ワークフローパッケージの依存関係のレイアウトを、よりすっきりさせる必要がある。

変数の値、認証情報、またはドキュメントパスだけが変わった場合は、変換されたワークフローを更新するだけで十分なことがあります。
