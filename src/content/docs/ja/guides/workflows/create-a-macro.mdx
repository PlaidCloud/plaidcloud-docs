**マクロ**は、入出力コントラクトを宣言した、再利用可能な高度な（DAG）ワークフローです。別のワークフローから [Macro Run](/ja/reference/workflow-steps/workflow-control/run-macro/) ステップまたは [Macro Concurrent](/ja/reference/workflow-steps/workflow-control/macro-concurrent/) ステップでマクロを呼び出します。呼び出しごとに専用の分離されたスクラッチスキーマで実行されるため、同じマクロを複数の親ワークフローや複数のドライバー行から同時に呼び出しても、実行同士が衝突しません。

繰り返し実行できるパラメーター化されたデータ変換（たとえば「1つの地域の1か月分の売上データを処理する」）があり、それを月ごと、地域ごと、またはその両方でドライバーワークフローから呼び出したい場合は、マクロを使用します。呼び出し元は、テーブルと変数をマクロで宣言された入力ポートにバインドします。マクロが完了すると、宣言された出力テーブルが呼び出し元側の宛先にコピーされます。

<Aside type="note">
マクロは高度なワークフロー専用の機能です。まず、ワークフローを高度なワークフローに変換してください。マクロ内のステップは、マクロで安全に使用できるものである必要があります。テーブル変換、インポート、エクスポート、実行スコープの変数ステップ、ネストした Macro Run の呼び出し、および一部の制御フローステップです。ディメンションはプロジェクト全体にわたるグローバルな状態であるため、ディメンションのインポートとディメンションを更新するステップは拒否されます。
</Aside>

## 手順

1. マクロにしたいワークフローを含むプロジェクトを開きます。
2. **ワークフロー**タブに切り替えて、ワークフローの行を選択します。
3. 右側の**ワークフローの詳細**パネルで、**ワークフロータイプ**が**高度**になっていることを確認します。標準の場合は、先に**高度なワークフローに変換**アクションを使用してください。
4. ワークフローの詳細パネルの**マクロ**セクションで、**マクロに変換…** をクリックし、ダイアログで確定します。ワークフローがマクロモードに切り替わり、ポートエディターが表示されます。
5. **ポートを追加**をクリックして、マクロが受け取る入力、または生成する出力を宣言します。各ポートには次を指定します。
   - **名前** — 呼び出し元がこのポートにバインドするために使用する短い識別子（例：`month`、`region_sales`）。
   - **方向** — **入力**（呼び出し元がこの値またはテーブルを提供します）または**出力**（マクロがこれを生成し、呼び出し元が受け取ります）。
   - **種類** — データテーブルの場合は**テーブル**、単一の値（string / int / float / bool / date）の場合は**スカラー**、階層ディメンションへの参照の場合は**ディメンション**。
   - **必須** — このポートをバインドしなくてもマクロを実行できる場合は、チェックを外します。
   - **メモ** — このポートが何を表すかについての短い注記。呼び出し元側のバインディングフォームで作成者に表示されます。
6. **ポートを保存**をクリックします。

これでワークフローはマクロになりました。別のワークフローに [Macro Run](/ja/reference/workflow-steps/workflow-control/run-macro/) ステップを追加する作成者には、宣言したポートが表示され、名前でバインドできます。

## マクロを呼び出す

呼び出し元のワークフローで次の操作を行います。

1. **マクロ: 実行**ステップを追加します。
2. **実行するマクロ**で、プロジェクトとマクロのワークフローを選択します。
3. **入力ポートのバインド** — マクロが宣言した入力ポートごとに、バインドを追加します。
   - **テーブル**ポートには、呼び出し元側のソーステーブルを指定します。必要に応じて、列のサブセットを選択し、フィルター（マクロのスカラー入力変数を参照する `WHERE` 句）を追加すると、必要な部分だけがマクロの実行スキーマに実体化されます。
   - **スカラー / ディメンション**ポートには、値（多くの場合、呼び出し元のワークフロー変数）を指定します。テーブルの入力フィルターから参照できるように、テーブルのコピー取り込みより前に設定します。
4. **出力ポートのバインド** — マクロが生成する出力ポートごとに、呼び出し元側の宛先テーブルを指定します（存在しない場合は、その場で作成されます）。
5. ステップを保存します。

親ワークフローが実行され、Macro Run ステップに到達すると、ランナーは次の処理を行います。

1. このマクロ呼び出し用に、新しい `run_id` を発行します。
2. プロジェクトのカタログに、実行ごとのスクラッチスキーマ（`macrorun_<run_id>`）を作成します。
3. バインドされた入力テーブルをスクラッチスキーマにコピーします（コピー取り込み時に列の射影とフィルターが適用されるため、フィルターがプッシュダウンされます）。
4. バインドされたスカラー / ディメンションの入力変数を、マクロの実行スコープの変数オーバーレイに設定します。
5. マクロのステップをインプロセスで実行します。マクロ内のすべての SQL ステップは、プロジェクトスキーマではなくスクラッチスキーマに対して読み書きします。
6. 宣言された出力テーブルを、呼び出し元の宛先にコピーして書き戻します。
7. スクラッチスキーマを削除します（マクロ内のステップが失敗した場合でも、常に削除されます）。

## ドライバー行ごとにマクロを実行する

1つの呼び出し元テーブルで、独立した多数のマクロ呼び出しを駆動したい場合は、**マクロ: 並行実行**を使用します。

1. **マクロ: 並行実行**ステップを追加します。
2. **ドライバー**で、呼び出し元側のドライバーテーブルを選択し、**同時実行数**に、同時に実行する子マクロ呼び出しの最大数を設定します。
3. **テーブルデータの選択**で、各子呼び出しが必要とするドライバーテーブルの列をマッピングします。
4. **ドライバーフィルター**で、必要に応じて、処理するドライバー行を制限します。
5. **マクロ**で、マクロのワークフローを選択します。
6. **入力バインド**で、ドライバー列の値をマクロのスカラー変数またはディメンション変数にバインドし、呼び出し元側のテーブルをマクロのテーブルポートにバインドします。
7. **出力バインド**で、マクロの出力ポートを呼び出し元側の宛先テーブルにマッピングします。

選択された各ドライバー行には、個別の `run_id` とスクラッチスキーマが割り当てられます。親ステップを停止すると、アクティブなすべての子呼び出しが停止し、それらの実行スキーマが削除されます。

## マクロを元に戻す

ワークフローの詳細パネルで**高度なワークフローに戻す…** をクリックすると、いつでもマクロのフラグを解除できます。ワークフローは通常の高度なワークフローに戻り、そのワークフローを参照している呼び出し元側の Macro Run ステップは、実行時に「マクロではありません」というエラーで失敗します。宣言したポートはレコードに残るため、後で再度変換すると復元されます。

## 制限事項（v1）

- テーブルの読み取りと書き込みは呼び出しのスクラッチスキーマに分離されるため、マクロにはテーブル変換、インポート、エクスポートを含めることができます。ディメンションはプロジェクト全体にわたるグローバルな状態であるため、ディメンションのインポートとディメンションを更新するステップは使用できません。ドキュメント操作やエージェント呼び出しなど、その他のテーブル以外の副作用を持つステップは、v1 ではマクロで安全に使用できません。
- マクロは、呼び出し元と同じプロジェクトに存在する必要があります。プロジェクトをまたぐマクロは、まだサポートされていません。
- Macro Run ステップは、[ワークフローの実行](/ja/reference/workflow-steps/workflow-control/run-workflow/)ステップ、[Workflow Loop](/ja/reference/workflow-steps/workflow-control/workflow-loop/) ステップ、または条件付きのワークフローの実行ステップから呼び出すことはできません。これらのステップは分離されずに実行され、実行ごとのスキーマのコントラクトを壊してしまうためです。代わりに、呼び出し元で Macro Run ステップを使用してください。
