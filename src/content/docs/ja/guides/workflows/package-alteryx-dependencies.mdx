PlaidCloudは、DocumentからAlteryxワークフローファイルをインポートし、依存関係とアーティファクトにはDocumentパスを使用します。ファイルをDocumentにアップロードしたり、MCP接続されたエージェントにファイルの整理を依頼したり、OneDrive、Google ドライブ、SharePoint、S3、Azure Blob、SFTPなどの共有ストレージにDocumentを直接接続したりできます。

<Aside type="note">
  インポート時にDocumentパスピッカーを使うと、PlaidCloudがソースファイルを読み取る場所と、生成されたアーティファクトを保存する場所を正確に選択できます。
</Aside>

## 共有ストレージをアップロードまたは接続する

移行に最も適したソースの場所を選択します。

- パッケージをドキュメントアカウントにアップロードする。
- 既存の共有ストレージの場所をドキュメントアカウントとして接続する。
- すでにDocumentにあるファイルのコピー、移動、名前変更、整理を、MCP接続されたエージェントに依頼する。

共有ストレージへの接続により、チームがすでに共同作業している場所にファイルを置いたままにできるため、移行の準備を減らせます。

- [Google ドライブ](/ja/guides/documents/adding-accounts/add-google-drive-account/)
- [OneDriveまたはSharePoint](/ja/guides/documents/adding-accounts/add-onedrive-account/)
- [AWS S3](/ja/guides/documents/adding-accounts/add-aws-s3-account/)
- [Azure Blob Storage](/ja/guides/documents/adding-accounts/add-azure-blob-storage-account/)
- [SFTP](/ja/guides/documents/adding-accounts/add-sftp-account/)

## 推奨されるフォルダー構成

移行バッチごとに、インポート前に次のようなフォルダー構成にします。

```text
workflow-package/
  workflows/
  macros/
  inputs/
  expected-outputs/
  reports/
  spatial/
```

この構成は任意ですが、レビューと検証が容易になります。

## ワークフローとマクロ

ワークフローファイルとマクロは、わかりやすいフォルダーに配置します。

- `.yxmd` と `.yxwz` ファイルは `workflows/` に置きます。
- `.yxmc` ファイルは `macros/` に置きます。
- ネストされたマクロは、ほかのマクロライブラリと一緒に保持します。
- 意図的にバージョン管理している場合を除き、同じパッケージ内でマクロ名を重複させないでください。

PlaidCloudは、マクロのソースファイルを使ってPlaidCloudのマクロワークフローを作成し、変換されたワークフローからのマクロ呼び出しを接続します。

## 入力ファイル

入力データは `inputs/` の下に置きます。

- CSV、TSV、固定幅、JSON、XML、Excel、Access、YXDB、SAS、SPSS、Stata、Avro、Parquet、HDFファイル。
- 式、動的置換、ファジーマッチング、結合で使用されるルックアップファイル。
- DirectoryツールおよびDynamic Inputツールから参照されるフォルダー。
- Alteryxのフラット ASCII ファイル: 記述対象のデータの隣に `.flat` レイアウトファイルを含めてください。列幅はこのファイルにのみ記録されており、変換時にこれを読み取ってステップを構築します。レイアウトファイルがなくても変換はできますが、変換レポートにアップロードすべきファイルが示されます。単に再実行するのではなく、そのファイルを用意してワークフローをもう一度インポートしてください。

PlaidCloudがパッケージをインポートすると、変換されたステップは選択したDocumentの場所を指します。

## 空間ファイル

空間ファイルは `spatial/` の下に置き、サイドカーをまとめて保持します。

- シェープファイル: `.shp`、`.shx`、`.dbf`、`.prj` を含めます。
- MapInfoファイル: `.tab`、`.map`、`.id`、`.dat` を含めます。
- 投影ファイルとルックアップレイヤーがある場合は含めます。
- KML、GeoJSON、その他の空間入力も、同じ依存関係パッケージに保持します。

空間データのサイドカーを複数のフォルダーに分けないでください。ジオメトリを正しく具体化するには、PlaidCloudにグループ全体が必要です。

## レポートとアーティファクトのアセット

レポートのアセットは `reports/` の下に置きます。

- レポートコンポーザーツールで使用する画像。
- PDFの入力。
- HTMLのフラグメントまたはテンプレート。
- レポートのマップで使用するマップレイヤー。
- アーティファクトの検証が必要な場合の、生成済みレポートのサンプル。

変換されたレポートステップは、DocumentとワークフローのRun履歴から確認できるPlaidCloudアーティファクトを作成します。

## Excelテンプレート

書式付きのExcelテンプレートに書式設定済みの出力を書き込むワークフローがある場合（書式を保持する [Export to Excel](/ja/reference/workflow-steps/export/export-to-excel/) ステップと [Export to Excel Sheets](/ja/reference/workflow-steps/export/export-to-excel-sheets/) ステップ）は、それらのテンプレートワークブックを、入力と一緒にドキュメントアカウントにステージングしてください。ソースデータをステージングした `03_Inputs` の隣に `04_Templates` フォルダーを作成してそこに置くと、変換されたステップが、自身が埋めるテンプレートを読み取れます。

<Aside type="caution">
  書式を保持するように変換されたエクスポートは、テンプレートをドキュメントアカウントから**実行時に**読み取ります。変換の実行時にテンプレートがない場合、ステップは安全にプレーンなエクスポートへフォールバックします。しかし、書式を保持するように変換されたエクスポートで、ステージングしたテンプレートが実行時に存在しない場合は、書式のないファイルを黙って書き込むのではなく、**明示的に失敗します**。変換されたワークフローを実行する前に、`04_Templates` をステージングしてください。
</Aside>

## 期待される出力

期待される出力は `expected-outputs/` の下に置きます。

- 信頼できるAlteryxの出力テーブル。
- 期待されるレポート、PDF、マップ、画像、チャート。
- 許容される行の順序、数値の精度、日付の扱いに関するメモ。

期待される出力は構造の検証では任意ですが、出力パリティの検証では最良の根拠になります。

## 外部接続

データベース、API、クラウドソースのワークフローでは、次の情報を記録しておきます。

1. ソースシステム名。
2. 接続タイプ。
3. データベース、スキーマ、テーブル、エンドポイント、バケットの名前。
4. 認証情報の所有者またはシークレット名。
5. 出力パリティが特定時点のソースに依存する場合のスナップショット日。

繰り返し可能な本番実行には、PlaidCloudの接続または認証情報を使用してください。
