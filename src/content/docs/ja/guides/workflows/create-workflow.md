新しいワークフローを作成するには、既存のプロジェクトが必要です。まだプロジェクトがない場合は、[プロジェクトの管理](/ja/guides/projects/managing-projects/)を参照してください。

## 手順

1. ワークフローを含めるプロジェクトを開きます。
2. **ワークフロー**タブに切り替えます。
3. ツールバーの **新規ワークフロー** をクリックします。
4. フォームに入力します。
   - **名前** — 短くわかりやすい名前（例:「月次決算 — 実績のロード」）
   - **メモ** — 補足情報を記載する任意の説明
   - **ワークフロータイプ** — 標準シリアル（デフォルト）、標準パラレル、詳細（DAGキャンバス）のいずれか。後述の[ワークフロータイプの選択](#ワークフロータイプの選択)を参照してください。
   - **エラー時に修復ワークフローを起動** — 任意。有効にすると修復ワークフローを選択できます（後述の[修復ワークフローについて](#修復ワークフローについて)を参照）。
5. **作成**をクリックします。

ワークフローがワークフロータブに表示され、ステップを追加できる状態になります。ダブルクリックして[ワークフローエクスプローラー](/ja/guides/workflows/workflow-explorer/)を開き、構築を開始します。

## ソーステーブルの最終変更日時の確認

ステップのフォームでは、テーブルセレクターに、選択したテーブルの下にグレーの **最終更新** 行が表示され、ローカル時間で日時が示されます。これにより、データが最新かどうかをひと目で確認できます。行にカーソルを合わせると、全文が表示されます。選択が動的な場合や、テーブルが一度も更新されていない場合、この行は表示されません。

## ワークフロータイプの選択

ワークフローの作成時に選択する**ワークフロータイプ**によって、ステップの配置方法と実行方法が決まります。デフォルトは**標準シリアル**で、新規ワークフローフォームのタイプセレクターで設定します。

| タイプ | ステップの配置方法と実行方法 |
|------|--------------------------------|
| **標準シリアル** | ステップは**ステップリスト**から、1つずつ順番に実行されます。 |
| **標準パラレル** | ステップは**ステップリスト**から実行され、依存関係が許す範囲で並列に実行されます。 |
| **詳細（DAGキャンバス）** | ステップは**ビジュアルキャンバス**上に配置され、依存関係の順に実行されます。互いに独立したブランチは並列に実行されます。詳細では、ブレークポイント、コンテナー、ここから実行、シミュレーション、リアルタイムの共同作業も利用できます。 |

4つ目のタイプである**マクロ**（入力と出力を宣言した、呼び出し可能な再利用可能ワークフロー）は近日公開予定で、セレクターでは無効な状態で表示されます。

:::note
ステップは、ワークフロー内に1回しか配置できません。ステップを2回目にワークフローに配置することになる位置への挿入、コピー、複製、インポートは、ステップ名を示して拒否されます。そのため、今後この状態になることはありません。この修正以前のワークフローで、すでに2か所に配置されているステップがある場合、**標準シリアル**の実行は、重複しているステップ名を示すエラーですぐに失敗します。選択した終了ステップで停止する**標準パラレル**の実行（[ワークフロー内のステップ範囲を実行する](/ja/guides/workflows/running-a-range-of-steps-in-a-workflow/)を参照）も同様です。終了点まで実行する場合も順次実行になるためです。**標準パラレル**を最後まで実行する場合は、重複を許容し、そのステップを1回だけ実行します。いずれの場合も、重複したステップを削除してワークフローを修復してください。ステップの削除が制限されることはありません。
:::

最初から[ビジュアルワークフローデザイナー](/ja/guides/workflows/advanced-workflows/)を使いたい場合は、ここで**詳細（DAGキャンバス）** を選択してください。この選択は固定ではありません。標準ワークフローは、後からワークフローリストの **高度なワークフローに変換…** メニュー項目で昇格できます。

## 修復ワークフローについて

新しいワークフローがエラーで終了した場合、PlaidCloudは対応する**修復ワークフロー**を自動的に実行できます。次のような用途に便利です。

- Slackチャンネル、メール配信グループ、Webフックに通知を送り、担当者が調査できるようにする
- ロールバックまたはクリーンアップのワークフローを起動して、正常な状態に復元する
- 失敗を監査テーブルに記録する

修復ワークフローは任意です。今は空欄のままにして、必要に応じて後から設定できます。修復ワークフローは、最終的な失敗時にのみ起動し、ステップごとの警告では起動しません。
