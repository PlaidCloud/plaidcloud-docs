## 概要

ワークフローのステップは通常、ワークフローで定義された順序で実行されます。しかし、あらかじめ定義した条件が満たされた場合にのみ、特定のステップを実行したいことがよくあります。ステップ条件の機能を使うと、次のオプションに基づいて実行を制御できます。
 - 変数の値
 - テーブルに行がある、または空である
 - テーブルが存在する、または存在しない
 - ドキュメントにファイルが存在する
 - ドキュメントにファイルが存在しない
 - テーブルのクエリ結果
 - 日付と時刻の条件が満たされている

変数やテーブルのクエリ結果を比較する場合は、次の比較を使用できます。
 - 等しい
 - 等しくない
 - 含む
 - 含まない
 - 次で始まる
 - 次で終わる
 - より大きい
 - より小さい
 - 以上
 - 以下

また、ステップを実行するために満たす必要がある条件を複数設定できる点も重要です。これにより、ステップをいつ実行するかを正確に制御する強力な手段が得られます。

## 条件の追加と制御

ステップに条件を有効にして追加するには：
1) 条件を追加したいステップを見つけます
2) ステップを右クリックして**ステップの詳細を編集**を選択するか、歯車アイコンをクリックして**一般**タブに切り替えます
3) **一般**タブの下部にある**条件チェック**セクションまでスクロールします
4) **実行前に条件をチェック**チェックボックスにチェックを入れると、ダイアログが有効になり、条件を追加できます。
5) 左側の**条件チェック**セクションで、「+」を選択して新しい条件を追加します
6) 右側のタブ付きセクションから条件を追加します
7) 手順5と6を必要なだけ繰り返して、すべての条件を追加します

## ビジュアルキャンバスでの条件の確認

ステップの条件は、ステップを開かなくてもビジュアルキャンバスから確認できます。条件付きステップに入るコネクターは**破線**で表示され、矢印の先端に小さな**盾**が付きます。盾が小さすぎて判別できないほど縮小表示しているときは、破線で判断します。

盾をクリックすると、**条件チェック**があらかじめスクロールされた状態でステップが開きます。コネクターを右クリックして**条件を編集…** を選択しても同じ操作になります。ステップ自身のタイル（左下）にある盾は、従来どおり、ステップが条件付きであることを示します。

次の2つのケースでは、設計上、矢印に盾は表示されません。

- **入力コネクターのないステップ。** 日付や変数で制御されるステップは、ワークフローの先頭に、入力するものが何もない状態で置くことができます。印を付ける矢印がないため、タイルの盾のみが表示されます。
- **折りたたまれたグループ内のステップ。** そのタイルはグループのタイルに折りたたまれ、矢印はステップではなくグループに接続されるため、印を付けると条件が誤ったものに紐づいてしまいます。

入力コネクターが複数あるステップには、矢印ごとではなく、盾が1つだけ表示されます。

:::note
この方法で条件を開くと、ネイティブのステップフォームを使用するステップタイプでは、条件チェックが表示されます。従来の構成ウィンドウを開くステップタイプでは、先頭の位置で開きます。条件はそこにありますが、スクロールされていません。
:::

### 盾がチェックする内容の表示

盾のツールチップには、ステップが何かをチェックするということだけでなく、実際にチェックする内容が一覧表示されます。

```
Table Row Count (sales_2026) > 0 where region = 'EU'
Day of Week = Monday (UTC+2)
Project Variable (run_mode) = "full"
```

最大3件のチェックが一覧表示され、残りは件数で示されます（*…and 2 more checks*）。そのため、条件の多いステップでも一覧は読みやすいままです。同じ要約は、ステップ自身のタイルの盾にも表示されます。入力コネクターのないステップでは、これが唯一の盾です。

ステップを選択すると、同じ一覧がインスペクターパネルの**条件**セクションに表示されます。長い一覧を読むには、こちらの方が便利です。

表記について、次の点に注意してください。

- **曜日や月のチェックは、保存されている数値ではなく名前で表示されます。** *Day of Week = 3*ではなく、*Day of Week = Monday*のようになります。
- **タイムゾーンは、UTCでない場合にのみ表示されます。** 上の例の*(UTC+2)*のようになります。
- **テーブルチェックのフィルターが表示されます。** フィルターは`where`の後に表示され、長い場合は短縮されます。
- **集計された比較は、その旨が表示されます。** *Query Value (aggregated sales_2026.amount) >= 100*はテーブル全体の合計を比較し、*Query Value (sales_2026.amount) >= 100*は1行の値を比較します。
- **ドキュメントのチェックには、パスは表示されますが、アカウントは表示されません。** 異なるドキュメントアカウントの同じパスを確認する2つの条件は、同じように表示されます。区別するにはステップを開いてください。
- **ツリーブラウザーから選択したテーブルには名前が表示されます。** ワークフローがそのテーブルをどこかで読み書きしている場合に、名前が表示されます。そうでない場合は、内部識別子ではなく、テーブル名なしでチェックが一覧表示されます。


### ゲートによって発生するコスト

盾をクリックせずにホバーすると、キャンバスは、条件付きステップとその下流のすべてを破線のハイライトで囲みます。これは、その条件がブロックした場合に実行されないステップです。何も変更されません。ポインターを離すと、ハイライトは消えます。*上流*のステップは、どちらの場合も実行されるため、ハイライトされることはありません。

これは、無効なグループの**無効**チップが表示するプレビューと同じですが、重要な表現の違いが1つあります。無効なグループは実際にオフになっているため、チップには、スキップされる*予定*のステップ数が表示されます。条件は実行がそこに到達したときにのみ評価されるため、盾には、条件がブロックした**場合に**実行されない*可能性がある*ステップ数が表示されます。すべてを通過させる可能性も十分にあります。

### 盾が示す前回の実行の状況

盾は、直近の実行で何が起きたかも報告するため、完了したフローをたどって、どこで止まったかを確認できます。

| 盾 | 意味 |
| --- | --- |
| 通常の盾 | ステップは条件付きです。まだ実行されていないか、現在実行中です。 |
| **+** 付きの盾 | ステップは前回の実行で実行されました。 |
| **−** 付きの盾 | ステップは前回の実行で実行されませんでした。 |

3つは色ではなく形で区別され、盾のツールチップには状態が言葉で表示されます。ワークフローの実行中はリアルタイムで更新されるため、実行がゲートに到達するのを見るのに、キャンバスを再読み込みする必要はありません。

:::caution
**−** 付きの盾は、ステップが実行されなかったことを示しています。*理由*は示しておらず、「条件によってブロックされた」と解釈しないでください。ステップは、無効になっている場合、そのグループが無効になっている場合、上流のステップが失敗した場合、または部分的な実行の範囲外だった場合にも、実行されなかったものとして記録されます。ツールバーの**ログを表示**を開くと、スキップした各ステップの理由が示される[実行ログ](/ja/guides/workflows/viewing-workflow-log/)が開きます。ブレークポイントで停止しているステップだけは、意図的に除外されています。そこで一時停止したのは実行の結果ではなくあなたの判断であるため、通常の盾のままになります。
:::


## 条件の管理

**条件チェック**セクションには、必要な数だけ条件を追加できます。追加する際は、今後条件を見つけやすいように、わかりやすい名前を付けておくとよいでしょう。

条件を追加したら、左側でそれを選択すると、右側で条件の評価基準を編集できます。

条件の名前を変更するには、条件を選択して、右側の構成パネルの上部にある**名前**フィールドを編集するか、リストで条件をダブルクリックします。条件を右クリックして**名前の変更**と**削除**を選択することもできます。**削除**は、リストの上にある「−」ボタンからも利用できます。

条件タイプが選択されていない条件（古いワークフローやインポートされたワークフローから引き継がれたものなど）は評価できません。このような条件は満たされていないものとして扱われ、ステップはスキップされます。ステップのメッセージには、その条件が何をチェックするのか示されていないと表示されます。条件を開いて、何をチェックするかを選択してください。


## 変数の条件

変数の条件をチェックする場合は、比較を行えるように、**Value Check Parameters**セクションを入力する必要があります。

**Variable or Table Field**に、変数名を入力します。比較タイプを選択し、比較する値を入力します。


## 基本的なテーブル条件

テーブルに行があるか、または空であるかをチェックする条件の場合は、**テーブルデータの選択**タブでテーブルも定義する必要があります。


## テーブル存在の条件

テーブル存在の条件は、テーブルがウェアハウスに作成されている場合にのみ、またはされていない場合にのみ、ステップを実行します。テーブルの行を読み取ることはなく、行数ゼロで書き込まれたテーブルも存在するものとして扱われます。プロジェクト内のどのテーブルにも一致しないテーブル名は、存在しないものとして扱われます。最初の実行でテーブルを構築し、それ以降は触れないようにしたい場合や、前のステップが作成していない可能性のあるテーブルを読み取るステップをスキップしたい場合に使用します。

2つのチェックタイプは、`radio_table_exists`と`radio_table_not_exists`です。テーブルは、基本的なテーブル条件と同じ方法で選択します。この条件は、AIアシスタントまたはREST APIで設定します。**条件チェック**タブには、まだ一覧表示されません。

## 高度なテーブル条件

高度なテーブル条件を使用する場合は、比較を行えるように、**Value Check Parameters**セクションを入力する必要があります。

**Variable or Table Field**に、テーブルの選択からフィールド名を入力します。比較タイプを選択し、比較する値を入力します。

**テーブルデータの選択**タブで、テーブルを選択し、少なくとも条件の比較で参照するフィールドを含めて、データマッピングセクションを完成させます。

## ドキュメントパスの条件

ファイルが存在するかどうかをチェックする条件の場合は、ドキュメントアカウントを選択し、**ドキュメントパス**タブでチェックするドキュメントのパスを指定する必要があります。チェックの対象はファイルであるため、そのパスにあるフォルダーは存在しないものとして扱われます。

## 日付と時刻の条件

日付または時刻の選択では、条件の組み合わせが必要な場合に、複数の条件を追加できます。たとえば、月曜日の午前2時5分にのみステップを実行したい場合は、3つの条件を作成します。
 - 曜日の条件を月曜日（1）に設定
 - 時を2に設定
 - 分を5に設定

### タイムゾーンオフセット

日付と時刻の各条件には、それぞれ独自の**タイムゾーンオフセット**があります。これは、代表的なゾーンの名前が付いた、1時間単位のオフセットとして一覧表示されます。たとえば、*Eastern Time (US & Canada) (UTC -5)*や*Asia/Tokyo (UTC +9)*です。入力した時刻は、そのゾーンの時計と比較されます。

新しい条件は、ブラウザーが報告するオフセットで開始されるため、ほとんどの場合、そのままで問題ありません。スケジュールが現在地とは別の場所に属している場合は、意図的に設定してください。たとえば、財務チームの時計で実行される締め処理などです。使用できるのは1時間単位のオフセットのみであるため、インド（UTC +5:30）のような30分単位のゾーンは、最も近い1時間単位に丸める必要があります。

この設定が有効になる前に保存された条件は、ゾーンを選択するまで引き続きUTCに対して評価されるため、既存の条件は従来とまったく同じように動作します。

:::caution
**曜日**の条件は現在、選択したオフセットに関係なく、UTCと比較されます。UTCから遠く離れたゾーンで、曜日の条件を特定の曜日に合わせる必要がある場合は、真夜中の前後数時間は、現地の曜日と異なる可能性があることに注意してください。
:::

### 財務締め営業日

**Use Financial Close Workday**では、カウントは**月の1日を0として**始まります。フィールドの横のヒントにも記載されているとおりです。したがって、月の5日目に行われる締めは、`5`ではなく`4`になります。

:::caution
この条件は現在、一致することがなく、この条件で制御されるステップは実行されません。この問題が解決されるまでは、**Day of the month**条件を使用してください。月末から逆算することを意図した負の値も機能しません。
:::

## AIアシスタントによる条件の設定

ワークスペースに接続されたAIアシスタントは、ステップの作成時でも既存のステップの編集時でも、ステップの条件を追加または変更できます。**Workdayの財務締めの確認**を除き、前述のすべての条件タイプが利用できます。アシスタントはこの条件を書き込めますが、一致することはないため、気付かれないまま通過するのではなく、アシスタントが警告します。この条件は、ご自身で**条件**タブで設定してください。

手動で条件を編集する場合とは、次の3つの点で動作が異なります。

- **毎回、リスト全体が置き換えられます。** 条件の追加や変更を依頼すると、アシスタントは完全なリストを送信するため、アシスタントが含めなかった条件は削除されます。すべて含まれているか確信が持てない場合は、書き込む前に、ステップの現在の条件を一覧表示するよう依頼してください。
- **評価できない条件は拒否されます。** 何をチェックするのかが示されていない条件は、保存されずに拒否され、ステップは既存の条件を保持します。依頼を修正して、もう一度依頼してください。
- **不完全な条件は、警告付きで保存されます。** 比較する値が欠けている条件や、**実行前に条件をチェック**にチェックを入れずに追加された条件は、保存され、警告として報告されます。**条件**タブを開いて完成させてください。そうしないと、ステップは依頼どおりに動作しません。

アシスタントは、ステップのロック、マネージャーとエクスプローラーのビューでの表示、再試行の設定、エラー時に移動するステップも設定できます。
