## 概要

**高度なワークフロー**は、**ビジュアルワークフローデザイナー**というビジュアルなキャンバス上で実行されます。ステップは有向グラフ（DAG）のノードとして表され、ノード間の線がデータの流れを示します。ランタイムは上から下へではなく、依存関係の順にステップを実行します。互いに依存しないブランチは自動的に並列で実行されます。

高度なワークフローは、PlaidCloud の**ワークフロータイプ**の1つで、もう1つは標準です。このガイドで説明する機能（ビジュアルキャンバス、**ブレークポイント**、**コンテナー**、**ここから実行**、**シミュレート**、ドッキング式の**インスペクター**）は、すべて高度なワークフロー専用です。キャンバスは**リアルタイムの共同編集**にも対応しています。複数のユーザーが同じ高度なワークフローを開いて一緒に編集し、互いの参加状況や変更をリアルタイムで確認できます。

## 標準と高度の違い

すべてのワークフローには、作成時に選択する**タイプ**があります。

| タイプ | ステップの配置先 | 実行方法 |
|------|------------------------|--------------|
| **標準シリアル** | ステップの一覧 | 上から下へ、1つずつ |
| **標準パラレル** | ステップの一覧 | 一覧に従い、依存関係が許す範囲で並列に |
| **詳細（DAGキャンバス）** | ノードと接続のビジュアルなグラフ | 依存関係の順に。独立したブランチは自動的に並列で実行 |

標準と高度は**異なるエンジン**で動作します。標準のワークフローは**ステップの一覧**から実行され、高度なワークフローは、ステップ間のプロデューサーとコンシューマーの明示的な接続に従って、描いた**グラフ**から実行されます。ビジュアルワークフローデザイナーが高度なワークフローでのみ開くのはそのためです。標準のワークフロー上に矢印を描いても、実行方法は変わりません。

<Aside type="note">**マクロ**というワークフロータイプがロードマップに含まれています。入力と出力を宣言した、呼び出し可能な再利用可能ワークフローで、タイプセレクターには「マクロ（近日公開）」と表示されます。</Aside>

## ワークフロータイプを選択する

タイプは、ワークフローの作成時に設定するか、既存の標準ワークフローを変換して変更できます。

- **作成時** — ワークフロータイプのセレクターには、**標準シリアル**、**標準パラレル**、**詳細（DAGキャンバス）**、**マクロ（近日公開）** が表示されます。新しいワークフローのデフォルトは**標準シリアル**です。
- **既存のワークフローを変換する** — **ワークフロー**の一覧で標準のワークフローを選択し、**高度なワークフローに変換…** を選んで確定します。ステップ、その構成、依存関係は保持され、ワークフローの表示方法と実行方法のみが変わります。

REST API または AI アシスタントでワークフローのタイプを標準から高度に変更した場合も、**高度なワークフローに変換…** と同様にステップの順序が保持されます。高度なワークフローを標準に戻すことはできません。

<Aside>アプリ内に「標準に変換」の操作はないため、高度なワークフローへの切り替えは元に戻せないものとして扱ってください。高度なワークフローかどうかはワークフローごとの設定で、1つのワークスペースに標準と高度のワークフローを自由に混在させることができ、1つを変換しても他には影響しません。</Aside>

## キャンバス

各ステップはノードで、ノード間の接続がステップの実行順序を定義します。デザイナーはステップを自動的に配置し、自由に並べ替えることもできます。

### 参加しているユーザー

同じ高度なワークフローを複数のユーザーが開いている場合、キャンバスのツールバーにアバターの列が表示され、他に誰が表示または編集しているかがわかります。共有ドキュメントと同じ、ライブのプレゼンスの考え方です。各ユーザーは **gravatar**（ない場合はイニシャル）で表示され、アバターにカーソルを合わせると名前が表示されます。同じワークフローを複数のブラウザータブで開いていても、ユーザーは**1回だけ**表示され、表示しきれないほど閲覧者が多い場合は、残りが **+N** のマーカーにまとめられます。

### ステップタイル

各タイルは、そのステップの概要を上から順に表示します。

- **ヘッダー** — ステップタイプのアイコンと名前、およびステップの前回の実行結果を示すステータスアイコン。
- **入力** — ステップが読み取る各テーブル、ディメンション、ファイルのアイコン。テーブルのアイコンをクリックすると[データプレビュードロワー](/ja/guides/workflows/preview-step-data/)でプレビューでき、ディメンションのアイコンをクリックするとそのディメンションが開き、ファイルのアイコンをクリックするとダウンロードできます。入力や出力が多いステップでは、余った分が **+N** のマーカーにまとめられます。
- **ステップ名** — タイル本体の中央に表示されます。
- **出力** — ステップの出力を示すアイコンで、クリック時の動作は入力と同じです。出力テーブルが存在する場合は、この行に**行数と列数**（例: `12,345 rows · 8 cols`）も表示されます。これはステップの入力/出力テーブルに表示される行数と列数と同じで、各テーブルを開かなくても、ワークフローを通るデータ量の変化を確認できます。それまでの間（またはステップがファイルやディメンションを出力する場合）は、この行には単に**出力**というラベルが表示されます。テーブルのアイコンにカーソルを合わせると、名前と件数が表示されます。
- **フッター** — ステップの前回と平均の実行時間。直近の実行が過去の履歴と比べて極端に遅かった場合は色が付きます。

### ナビゲート

- **拡大** / **縮小**、**ズームを100%にリセット**、**すべてのノードが収まるように表示**で、ワークフローをどのサイズでも表示できます。
- **パンツール** — 有効な間は、ドラッグでキャンバスを選択する代わりにパンします。中ボタンでのドラッグと Space+ドラッグは、切り替えの状態に関係なくパンします。
- **グリッドにスナップ**は、ノードをドロップしたときに位置を固定のグリッドに揃え、きれいに整列させます。

### ミニマップ

画面に収まらない大規模なワークフローでは、**ミニマップ**を切り替えると、右下に概要パネルがドッキングされます。ワークフロー全体のステップと接続が縮小表示され、現在表示しているキャンバスの範囲が四角形で示されます。

- ビューポートの四角形は、パンやズームに合わせてリアルタイムで動くため、大きな図の中で今どこにいるかを常に把握できます。
- パネル内の任意の場所を**クリックまたはドラッグ**すると、キャンバスがワークフローのその部分へ移動します。
- ワークフローの実行中は、ミニマップ内の各ステップが**実行状態で色分け**されます（実行中、完了、エラーなど）。そのため、このパネルは状態をひと目で把握できる概要としても機能します。

<Aside type="tip">ミニマップを開いているかどうかはセッションをまたいで記憶されるため、便利だと感じるワークフローでは開いたままにしておけます。</Aside>

### レイアウト

- **配置**は、レイアウト操作のメニューを開きます。すべての操作は**元に戻す**（Cmd/Ctrl+Z）で1ステップとして取り消すことができ、確認なしで適用されます。トーストには「*レイアウトを更新しました — 元に戻すには「元に戻す」を押してください*」と表示されます。何も変更しない操作は、何も実行されません。[キャンバスを配置する](#キャンバスを配置する)を参照してください。
- **元に戻す**と**やり直し**は、レイアウトの変更を前後に移動します（Cmd/Ctrl+Z と Cmd/Ctrl+Shift+Z）。**履歴**は変更のパネルを開きます。

#### キャンバスを配置する

| 操作 | 内容 | 必要な条件 |
|---|---|---|
| **すべて整理** | すべてのステップを左から右へ配置します。 | 常に利用可能 |
| **選択範囲を整理** | 選択した項目のみを配置し、左上の角の位置は維持します。他のステップは、重なる場合にのみ下へ移動します。 | 2個以上の項目 |
| **重なりを解消** | 重なっている項目を、重ならなくなるまで下へ押し下げます。順序は変更しません。 | キャンバス上に2個以上の項目 |
| **左揃え / 中央揃え / 右揃え / 上揃え / 中央揃え（縦） / 下揃え** | 選択した項目を、選んだ端または中央に揃えます。 | 2個以上の項目 |
| **左右に整列 / 上下に整列** | 最初と最後の項目は動かさず、その間の項目を等間隔に配置します。 | 3個以上の項目 |
| **すべてグリッドにスナップ** | キャンバス上のすべての項目をグリッドに合わせ、その結果ぶつかった項目は離します。 | 常に利用可能 |

- **すべて整理ではレイアウトが維持されます。** ステップは引き続き左から右へ流れますが、各列の中では既存の上から下の順序が保たれ、レイアウトも原点に移動せずキャンバス上の元の位置にとどまります。
- **グループはまとまったままです。** [コンテナー](#コンテナー)は1つのブロックとして配置されます。折りたたんだコンテナーは1つのタイルとして移動し、その中に隠れたステップも一緒に移動します。
- **メモとハイライトはステップと一緒に移動します。** ステップの上にあるものはすべて、ステップの移動に合わせて動きます。
- **グループは1つの項目として数えられます。** 揃え、整列、選択範囲の整理では、コンテナーまたは折りたたんだコンテナーが1つの項目となり、その中のステップも一緒に移動します。
- **すべてグリッドにスナップ**は、[ナビゲート](#ナビゲート)にある**グリッドにスナップ**の切り替えとは別のものです。切り替えは、ステップをドロップしたときの着地位置にのみ影響します。
- **利用できない操作は薄く表示されます。** 現在の選択に当てはまらないメニュー項目はグレーアウトされます。
- **ロックされたワークフロー**では、すべての配置操作がブロックされます。先にワークフローのロックを解除してください。

### 注釈

注釈は視覚的なものにすぎません。図を説明するためのもので、実行には影響しません。

- **メモを追加** — キャンバス上の任意の場所に付箋を置き、**テキストを編集…** で内容を書き込みます（削除するには**メモを削除**）。
- **ハイライトを追加** — 関連するステップのグループを半透明のボックスで囲み、**ラベルを編集…** でラベルを付けます（削除するには**ハイライトを削除**）。
- **色** — ステップを色分けして（または**デフォルト**に戻して）、作業を視覚的にグループ化します。

### ロック

ワークフローは、誤って編集されないように**ロック**できます。ロックの切り替えをクリックすると、*ワークフローの編集 — クリックしてロック*と*ワークフローはロックされています — クリックして編集のロックを解除*が切り替わります。ロック中は、ロックを解除するまでキャンバスは読み取り専用です。

### パレットとインスペクターのペインを折りたたむ・サイズ変更する

左側のステップパレットと右側のインスペクターは、図にウィンドウ全体を使いたいときに、それぞれ折りたたんで脇に寄せることができます。

- **ペインを折りたたむ** — パレットの見出しまたはインスペクターのヘッダーにあるシェブロンをクリックします。ペインは、タイトルが側面に縦書きで表示される細いレールに縮小します。折りたたまれたインスペクターのレールには**選択中のステップの名前**が表示されるため、キャンバスを全幅にしても、調べていたものを見失いません。名前が切れている場合は、カーソルを合わせると全体が表示されます。
- **元に戻す** — シェブロンだけでなく、レールのどこをクリックしても元に戻ります。
- **キーボード** — `[` を押すとパレットが、`]` を押すとインスペクターが折りたたまれ、または展開されます。どちらもフィールドに入力している間は無視されるため、フィルターボックスやインラインの名前変更が中断されることはありません。
- **区切りをダブルクリック** — ペインの横にある区切りをダブルクリックすると、シェブロンと同じように折りたたみ・展開ができます。
- **サイズ変更** — どちらの区切りもドラッグできます。どちらのペインにも最小幅があり、それを下回ると、インスペクターの入力カードと出力カードは、名前や行数が切れる代わりに横にスクロールします。

<Aside type="note">ペインの幅と折りたたみ状態は、**ブラウザーごとに記憶され、ワークフロー間で共有**されます。ワークフローごとには保存されません。各ペインは個別に記憶されるため、あるキャンバスでインスペクターのサイズを変更しても、別のキャンバスで折りたたんだパレットには影響しません。次に開くキャンバスでは、各ペインの最新の変更が設定として使用され、すでに開いているキャンバスのウィンドウは、閉じて開き直すまで現在のレイアウトを維持します。</Aside>

### 図をエクスポートする

ツールバーのエクスポートボタンは、ドキュメント作成、レビュー、共有のためにキャンバスの画像を保存します。クリックすると PDF がエクスポートされ、ドロップダウンには**PDFとしてエクスポート**と**PNGとしてエクスポート**があります。

<Aside type="note">エクスポートした PNG と PDF の図は、使用しているテーマに関係なく、常にライトカラースキームで描画されます。ダークな図は画面上では適切でも紙の上では不向きなため、エクスポートはライトカラーに固定されており、印刷したりドキュメントに貼り付けたりしてもきれいに読めます。</Aside>

### ダークテーマ

キャンバスは、選択した PlaidCloud のテーマに従います。**ダーク**テーマでは、キャンバスの背景、ステップタイル、コネクター、メモ、ハイライト、コンテナー、ミニマップのほか、隣り合うステップパレット、インスペクター、データプレビュードロワーもすべてダークな背景用に描画され、実行ステータスの色とラベルのテキストは、背景に対して読みやすい色が選ばれます。テーマを切り替えるとインターフェースが再読み込みされ、キャンバスは再び開いたときに新しい色を適用します。

## ステップの追加、接続、編集

**[パレット](#ステップパレット)** でステップタイプをクリックするとキャンバスに配置され、ドラッグすると好きな場所に配置できます。ステップを接続するには、あるステップから別のステップへドラッグして**コネクター**を描きます。これは、あるステップの出力が次のステップに渡されることをランタイムに伝えます。

<Aside type="caution">ワークフローは DAG である必要があります。循環を作るコネクターは拒否されます（「that connector would create a cycle」と表示されます）。コネクターを右クリックすると、**コネクターを削除**するか、どちらの端でも**ソースステップを編集…** / **ターゲットステップを編集…** にジャンプできます。</Aside>

テーブルを読み取るステップは、そのテーブルを書き込むステップの後に実行する必要があります。ツールバーの**依存関係の同期**は、早すぎるタイミングで実行される可能性のあるステップを見つけ、追加すべきコネクターを提案します。[依存関係の同期](/ja/guides/workflows/sync-dependencies/)を参照してください。

任意のステップを右クリックすると、次の操作を利用できます。

- **ステップ構成を編集…** — ステップの設定フォーム。
- **ステップの詳細を編集…** — 名前、メモ、エラー処理、再試行、条件。
- **ステップタイプを変換…** — ステップを別の操作タイプに変更します。
- **ステップを複製…** — このステップをコピーします。ステップフォームが**一般**タブで開き、このステップの内容が入力されているので、コピーの名前を変更したり配置先を選んだりできます。コピーはこのステップの構成を引き継ぎます。
- **ステップを有効化** / **ステップを無効化** — 無効化したステップは、実行時にスキップされます。
- **ステップの入力を表示** / **ステップの出力を表示** — ステップのデータをインスペクターで開きます。
- **出力データをプレビュー** — ステップの出力を、ドッキングされた[データプレビュードロワー](/ja/guides/workflows/preview-step-data/)で開きます。ステップにカーソルを合わせると、同じ操作を行う閲覧用のグリフもフェードインで表示されます。
- **色** — ステップの色を設定またはクリアします。
- **ステップを削除…** — ワークフローの構造から削除します。その出力に依存していた下流のステップは、再構成が必要になります。

## サブワークフローの同時実行

ステップが別のワークフローを呼び出す場合（マクロ**ではない**ワークフローを指す[ワークフローの実行](/ja/reference/workflow-steps/workflow-control/run-workflow/)、ワークフローの条件付き実行、または[ワークフローのループ実行](/ja/reference/workflow-steps/workflow-control/workflow-loop/)ステップ）、そのサブワークフローの呼び出しは、一度に1つしか実行できません。マクロではないサブワークフローは単一の実行状態を共有するため、2つの呼び出しが同時に実行されると衝突します。

高度なキャンバスでは、互いに順序が決まっていないステップは並列で実行されるため、この点が重要になります。そのようなステップが2つとも同じマクロではないサブワークフローを呼び出すと、競合が発生します。

デザイナーはキャンバスの保存時にこれを確認し、問題のあるステップと共有されているサブワークフローの名前を示す、**ワークフローのアドバイザリー**というタイトルのアドバイザリートーストを表示します。例:

> ステップ 'Build'、'Refresh' はいずれもマクロではないサブワークフロー 'Load Dims' を呼び出していますが、互いに順序が決まっていません。同時に実行されて衝突する可能性があります（マクロではないサブワークフローは同時に2回実行できません）。重ならないようにステップの順序を決めるか、'Load Dims' をマクロにしてください（マクロは呼び出しごとに分離されて実行されます）。

解消するには、次のいずれかを行います。

- **ステップの順序を決める** — コネクターを描いて、一方が他方の後に実行されるようにし、重ならないようにします。
- **サブワークフローをマクロにする** — マクロの呼び出しはそれぞれ独自の分離されたスクラッチスキーマで実行されるため、同じマクロを同時に呼び出しても安全です。[マクロを作成する](/ja/guides/workflows/create-a-macro/)と[Macro Run](/ja/reference/workflow-steps/workflow-control/run-macro/)のリファレンスを参照してください。

<Aside type="note">この警告はアドバイザリーであり、ブロックではありません。保存は成功します。コネクターを変更したとき（またはコンテナーを有効化・無効化したとき）に再計算されるため、競合を解消して再度保存すると、警告は消えます。</Aside>

## ステップパレット

キャンバスの左側にある**ステップパレット**には、追加できるすべてのステップタイプが10個のフォルダーに分類されて表示されます。**インポート**、**エクスポートとアーカイブ**、**テーブル**、**ディメンション**、**配賦**、**AI・ML・テキスト**、**空間**、**ドキュメントとレポート**、**ワークフローと変数**、**外部システム**です。フォルダーは最初は閉じています。クリックして開きます。インポートの下の **Sage** や、ワークフローと変数の下の**通知**のように、サブフォルダーを持つものもあります。パレットは、開いたままにしたフォルダーを記憶します。

### フォルダーの陰影とインデントガイド

パレットは、階層のどこにいるかを、覚えておかなくてもわかるように示します。

- **フォルダーは深さに応じて陰影が付く**ため、最上位のフォルダー、サブフォルダー、その中のステップをひと目で区別できます。陰影は補助的な手がかりにすぎません。フォルダーであることは、フォルダーのアイコンと太字のキャプションですでに示されています。
- 開いている各フォルダーには、その中身の左側に**縦のインデントガイド**が描かれ、**ガイドをクリックすると、そのガイドが属するフォルダーが閉じます**。見出しがすでにスクロールで見えなくなった長い開きっぱなしのフォルダーから抜け出すには、これが手早い方法です。ガイドにカーソルを合わせると「*このフォルダーを折りたたむ*」と表示されます。
- フォルダーは、ディメンション画面で使われているものと同じ **+/− ボックス**で開閉するため、製品全体で同じ操作感になります。
- 読んでいるフォルダーの見出しは、スクロール中も**一覧の上部に固定**されるため、ポインターの下にあるステップがどこのものかわからなくなることはありません。サブフォルダーの内側では、その見出しと親の見出しの両方が固定されます。
- **フォルダーを開閉しても、スクロール位置は維持されます。** 一覧の先頭に戻されることはありません。
- **すべてのフォルダーを展開**と**すべてのフォルダーを折りたたむ**は、パレットの見出しにある2つの小さなボタンで、パレット自体を折りたたむシェブロンの隣にあります。

ステップを追加する方法は2つあります。

1. **クリックする。** 行が点滅して追加を確認でき、ステップは表示中のキャンバスの左上付近に、すでに選択された状態で表示されるため、インスペクターにその詳細が表示されます。好きな場所までドラッグしてください。間違ったステップをクリックしてしまった場合は、**Delete** を押して確認します。選択されたままなので、探す必要はありません。
2. パレットからキャンバスに**ドラッグする**と、ドロップした場所に配置されます。

さらに知っておくと便利なことが2つあります。

- **フィルター…** は、開いているか閉じているかに関係なく、カタログ全体をステップ名で検索します。一致した項目は、それぞれ元のフォルダーの見出しの下に表示されるため、何も開かなくても、そのステップがどこに属しているかがわかります。一致するものがない場合、パレットには**一致するステップがありません**と表示されます。
- ステップの横の**星**は、そのステップを**お気に入り**に固定します。お気に入りは、フォルダーの上に置かれ、どのフォルダーにも属さないセクションです。ステップを右クリックしても同じ**お気に入りに追加** / **お気に入りから削除**を利用でき、**キャンバスに追加**も利用できます。

### キーボードナビゲーションとスクリーンリーダー

パレットは完全にキーボードだけで操作でき、**スクリーンリーダーでも操作可能**です。パレットはツリーとして公開され、各行は、フォルダーかどうか、そのフォルダーが開いているかどうか、どの深さにあるかを通知します。フィルターを入力すると、結果は一致した項目のフラットな一覧として公開されます。

Tab キーで**フィルター…** フィールドから一覧に移動します（ステップごとではなく、一覧全体で1か所にだけ止まります）。もう一度 Tab を押すと、キャンバスに移動します。一覧内では次のキーを使用できます。

| キー | 動作 |
|-----|--------------|
| 下 / 上 | 次または前の行に移動します |
| 右 | 現在のフォルダーを開きます。ステップの上にいる場合は、下に移動します |
| 左 | 現在のフォルダーを閉じます。ステップの上にいる場合は、それを含むフォルダーに上がります |
| Enter または Space | 現在のステップをキャンバスに追加するか、フォルダーを開閉します |
| Esc | **フィルター…** フィールドに戻ります |

<Aside type="note">ステップ名がパレットの幅より長くなることがあります。パレットとキャンバスの間の区切りをドラッグして広げるか、パレットを完全に折りたたんでください。幅がどのように記憶されるかについては、[パレットとインスペクターのペインを折りたたむ・サイズ変更する](#パレットとインスペクターのペインを折りたたむサイズ変更する)を参照してください。ステップにカーソルを合わせると、その機能が表示されます。説明がない場合は完全な名前が表示されます。</Aside>

## 実行コントロール

キャンバスからは、ワークフロー全体、またはその一部を実行できます。実行はグラフに従うため、「ここから」と「選択」は、一覧内の位置ではなく依存関係を尊重します。

| 操作 | 実行内容 |
|--------|--------------|
| **ワークフローの実行** | 開始ステップからワークフロー全体。 |
| **このステップを実行** | 選択したステップのみ。 |
| **ここから実行** | 選択したステップと、その後に通常実行されるすべての下流ステップ。 |
| **選択を実行** | 選択したステップのみ。並列で起動し、ランタイムが依存関係に従って順序付けます。 |
| **セクションを実行** | 選択したステップと、選択範囲のうちトポロジー上で最も早いものと最も遅いものの間にグラフ上で位置するすべてのステップ。 |

ワークフローの実行中は、**一時停止**（実行中のステップは完了し、新しいステップは**再開**するまで待機します）、一時停止または停止したワークフローの中断した場所からの**再開**、または**停止**（実行中のステップは完了し、キュー内のステップはキャンセルされます）ができます。再開では、失敗したノードと、その完了を待っているすべてのものを再実行し、完了済みのノードには手を加えません。[一時停止、停止、再開](/ja/guides/workflows/run-a-workflow/#一時停止停止再開)を参照してください。

## シミュレート

**シミュレート**は、実際の変換を実行せずに、ワークフローのグラフをたどります。ステップは実際の実行時と同じように描画されるため、計算を実行する前に、順序とブランチを視覚的に確認できます。何も実行されず、データも変更されません。

<Aside type="tip">シミュレートは、大規模なワークフローや分岐の多いワークフローを検証する最も手早い方法です。順序と依存関係が想定どおりであることを確認してから、実際に実行してください。</Aside>

## ブレークポイント

**ブレークポイント**は、実行がそのステップに達したときに停止し、ワークフローの残りが続行される前に上流の出力を調べられるようにします。

1. ステップを右クリックして**ブレークポイントを設定**を選択します（削除するには**ブレークポイントをクリア**）。
2. ワークフローを実行します。実行がブレークポイントのあるステップに達すると、そこで一時停止し、下流のものはすべて待機します。
3. インスペクターでステップの入力と出力を調べてから、**再開**して続行します。

ブレークポイントはワークフローと一緒に保存されるため、設定したブレークポイントは、クリアするまでセッションをまたいで維持されます。

## コンテナー

**コンテナー**は、関連するステップを、1つの単位として折りたたんだり無効化したりできるラベル付きのボックスにまとめます。大規模なワークフローの整理や、サブプロセス全体のオン・オフの切り替えに便利です。

- **コンテナーにグループ化** — ステップを選択してグループ化し、コンテナーに名前を付けます。
- **コンテナーを折りたたむ** / **コンテナーを展開** — コンテナーを1つのタイルに折りたたんでキャンバスをすっきりさせたり、再び開いたりします。
- **コンテナーを無効化** / **コンテナーを有効化** — コンテナーを無効化すると、メンバーのステップすべてを1回の操作でスキップします。有効化すると元に戻ります。
- **コンテナーの名前を変更…** — ラベルを変更します。
- **コンテナーのグループ化を解除** — コンテナーを削除します。メンバーのステップはキャンバスに残ります。
- **ステップの追加と削除** — Mac では **Cmd**、Windows では **Ctrl** を押しながらステップをコンテナーにドラッグします。コンテナーがドロップ先としてハイライトされ、離すとステップが参加します。ステップをコンテナーから何もないキャンバスへ Cmd/Ctrl+ドラッグすると、取り除かれます。折りたたんだコンテナーにドロップすると、ステップがそこに追加されます。

ステップは最大で1つのコンテナーにしか属さないため、別のコンテナーにドロップすると移動します。選択した複数のステップをドラッグすると、すべてが移動します。コンテナー全体を選択した状態で、そのステップの1つを Cmd/Ctrl+ドラッグした場合は、そのステップだけが移動します。ステップがなくなった通常のコンテナーは削除されます。通常のドラッグはキャンバス上のステップを移動するだけで、Cmd/Ctrl+クリックでは引き続き選択が切り替わり、キャンバスの外で離しても何も変わりません。メンバーシップの変更は、他のレイアウト変更と同じように元に戻したりやり直したりできますが、ロックされたワークフローは変更できません。

<Aside>コンテナーの無効化は、作業のブランチ全体をスキップする最も手早い方法です。たとえば、テスト実行から外したいエクスポートステップのブロックを、ステップを1つずつ無効化せずにスキップできます。</Aside>

**有効にする** — コンテナーを右クリックして**実行**をオンにします。コンテナーは、独自の枠線、ヘッダーの**実行**バッジ、入力ポートと出力ポートが付いた表示に変わるため、実行コンテナーと通常のグループをひと目で区別できます。ポートにカーソルを合わせると、**入力ポート**と**出力ポート**のツールチップが表示されます。

**実行の仕組み — 封じられたサブ DAG。** コンテナーを実行用にすると、その境界は両方向で封じられます。

- **コンテナーの入力が到着するまで、内部では何も開始されません。** すべてのメンバーステップは、グループにデータを渡すものを待ちます。それ自体に上流のないメンバーであっても同様です。
- **すべてのメンバーが完了するまで、コンテナーの下流では何も開始されません。** グループの出力は最後のメンバーが完了したときにのみ解放されるため、親のワークフローはコンテナー全体を1つのノードとして扱います。

コンテナー*内部*の独立したブランチは、オープンなキャンバス上と同じように並列で実行されます。封じられるのはグループの境界のみで、内部の作業の順序は対象外です。

**上流のステップを入力ポートに接続する。** 上流のステップからコンテナーへコネクターをドラッグし、**入力**ポートにドロップします。その1本の接続でグループ全体にデータが渡され、入力を必要とするすべてのメンバーが、コンテナーの入力が到着した時点でそれを受け取ります。

**出力ポートを下流のステップに接続する。** コンテナーの右端にある**出力ポート**から、グループの出力を使用する下流のステップへコネクターをドラッグします。下流のステップは、すべてのメンバーが完了すると開始され、コネクターはコンテナーの端から描かれます。

**メンバーステップ**から下流のステップへ、他の2つのステップを接続するときと同じ方法でコネクターを描くこともできます。ランタイムはその接続をコンテナーの出力ポート経由に自動でルーティングするため、どちらの方法でも結果は同じです。

**失敗時の動作。** 失敗したメンバーには、他のステップと同じエラー処理が適用されます。

- デフォルトの**エラー時に停止**では、メンバーの失敗により実行が停止し、コンテナーより先のものはすべて保留されます。
- **[エラー時に続行](/ja/guides/workflows/continue-on-error/)** では、失敗したメンバーは完了したものとして扱われます。残りのブランチが完了するとコンテナーの出力は解放され、下流の処理が進みます。

**実行コンテナーを無効化する。** 実行コンテナーを無効化すると、1つの単位としてスキップされます。メンバーは実行されず、スキップされたコンテナーは**出力を生成しない**ため、コンテナーの下流にあるものはすべて、存在しない入力に対して実行されるのではなくスキップされます。これは、通常の（実行ではない）コンテナーを無効化した場合とは異なります。通常のコンテナーの場合はメンバーのステップのみがスキップされ、それらのメンバーに依存しない下流のステップは引き続き実行されます。コンテナーを再び有効にすると、グループ全体が元に戻ります。

**ステップの追加と削除。** 実行コンテナーのステップは、Cmd/Ctrl+ドラッグで同じように変更できます。次の場合、PlaidCloud は移動を拒否し、メッセージを表示してステップを元の位置に戻します。

- ステップがコンテナー自身の入力ポートまたは出力ポートに接続されている。
- 移動によって、コンテナーの境界を通る循環が生じる。
- コンテナーの最後のステップが削除されてしまう。代わりに**コンテナーのグループ化を解除**を使用してください。

### 実行コンテナーの実行と監視

実行コンテナーは、1つの単位として実行して監視することもできます。その作業だけを開始し、実行中は集約されたステータスを確認し、その中で発生した失敗にすぐ移動できます。これはキャンバス上でも実行モニターでも同様です。

**グループを実行 / グループと下流を実行。** 実行コンテナーを右クリックすると、ワークフローの他の部分に触れずに実行できます。

- **グループを実行**は、コンテナーのメンバーステップを実行します。
- **グループと下流を実行**は、メンバー*と*コンテナーの下流にあるすべてのものを実行します。

どちらも、コンテナーにデータを渡す上流のステップは再実行しません。すでにある入力を使用して、グループをそのまま実行します。どちらも個々のステップと同じ**選択を実行**の仕組みを使用するため、メンバーは並列で起動し、ランタイムが依存関係に従って順序付けます。

**グループのライブステータス。** ワークフローの実行中、コンテナーにはメンバーを集約したステータスが表示されます。ステータスドット、**N / M 完了**の件数、色付きの枠線です。ステータスはメンバー全体を反映します。メンバーのいずれかが失敗していれば**エラー**、いずれかが実行中であれば**実行中**、すべてのメンバーが終了すると**完了**、グループがスキップされた場合は**スキップ**というようになります。折りたたまれたコンテナーも、その1つのタイルに同じ集約を表示するため、グループを折りたたんでも作業の進行状況は隠れません。

**失敗箇所へジャンプする。** グループに失敗したメンバーがある場合は、そのステータスをクリックすると、そのメンバーがキャンバス上で選択されて中央に表示されます。実行を止めたものをグループ内から探し回る必要はありません。

**失敗から再試行。** 失敗した実行コンテナーを右クリックして**失敗から再試行**を選択すると、失敗したメンバーと、グループ*内*でそれらの下流にあるものだけが再実行され、すでに成功したメンバーはスキップされます。これは、すべてのメンバーを無条件に再実行する**グループを実行**との違いです。失敗から再試行は、メンバーがつまずいた原因を修正した後に、正常な状態へ戻る手早い方法です。

**前回の実行時間。** コンテナーのヘッダーには、メンバーの前回の実行時間の合計が表示されるため、メンバーを自分で足し合わせなくても、グループ全体のコストをひと目で把握できます。

**ポートのツールチップ。** 実行コンテナーの**入力ポート**または**出力ポート**にカーソルを合わせると、その境界を通過するテーブル（グループが取り込む入力、または下流に渡す出力）がツールチップに一覧表示されます。

<Aside type="note">実行モニターのステップテーブルには、各ステップのコンテナーと、そのコンテナーの集約されたステータスが表示されるようになり、キャンバスに表示される内容と一致します。失敗したメンバーはどちらの場所でも同じように表示されるため、開いている方のビューから作業できます。</Aside>

### コンテナーの反復

実行コンテナーは、値のセットの**反復ごとに1回**、封じられたサブ DAG を実行できます。そのため、1つのリージョンのデータをロードして変換するグループで、リージョンごとにステップをコピーしなくても、すべてのリージョンを順に処理できます。実行コンテナーを右クリックして**コンテナー設定…** を選択し、**反復対象**タブを開いて、**この実行コンテナーを反復する**にチェックを入れると、反復が有効になります。反復は単位として実行されるグループを駆動するため、この設定は実行コンテナーにのみ表示されます。反復は任意です。チェックを外したままにするとコンテナーは1回だけ実行されるため、反復の設定なしで、コンテナーだけに[条件](#コンテナーの条件)を設定することもできます。

**ループを設定する。** **コンテナー設定…** ダイアログの**反復対象**タブは、タブ付きのサブページ上で、[ワークフローのループ実行ステップ](/ja/reference/workflow-steps/workflow-control/workflow-loop/)と同じ反復モデルを使用します。反復するセットの作り方を選択します。

- **Specify Variable Values to Iterate Over** — **手動値の反復**タブで値を自分で定義します。1つ以上の**ループ変数**を追加し、それぞれに値の明示的なリストまたは**範囲**を指定します。

  | 範囲タイプ | 反復の単位 |
  |------------|--------------------|
  | **整数** | **開始**、**終了**、**ステップ**で指定した数値ごと |
  | **英大文字** / **英小文字** | 範囲内の文字（`A`〜`Z` または `a`〜`z`）ごと |

  範囲には、スキップする**除外値**のリストを指定できます。複数の変数を定義した場合、コンテナーはそれらの値の**組み合わせ**（直積）ごとに1回実行されます。

- **Use Combination of Unique Values in Table** — **反復対象**タブで**ソーステーブル**を選択し、**Data to Variable Mapping** タブで、その1つ以上の列をループ変数名にマッピングします。コンテナーは、それらの列の値の**一意の組み合わせ**ごとに1回実行されます。**Table Data Filters** タブを使用すると、対象とする行を絞り込めます。

コンテナー内のステップは、他のワークフロー変数と同じように各ループ変数 `{region}` を参照できるため、メンバーの SQL、式、テーブル名、ファイルパスのすべてを反復ごとに変化させることができます。必要に応じて **Combine all iterations' output** をオンにすると、最後の結果だけを保持する代わりに、各回の結果を蓄積できます。この機能の現状については、下の注記を参照してください。

**実行の仕組み。** 反復は1回ずつ**直列**に実行されます。メンバーはループ変数を共有するため、2回分を同時に実行すると、互いの値を読み取ってしまうからです。各反復は、ループ変数を次の値（または組み合わせ）にバインドしてから、グループ全体を[通常の実行コンテナーの実行](#実行コンテナーの実行と監視)として実行します。次の反復は、前の反復が完了してから始まります。コンテナーの上限は**1,000回の反復**です。

**下流が読み取る内容。** 各回でグループの出力テーブルが上書きされるため、コンテナーの下流のステップは**最後の反復**の出力を読み取ります。すべての反復の行が必要な場合は、**Combine all iterations' output** をオンにして、各回の結果が置き換えられずに蓄積されるようにします。

たとえば、リージョンごとに絞り込んだ抽出を1つずつ作成するには、値のリスト `East, West` を持つループ変数 `region` を追加し、メンバーステップに、その変数を読み取るフィルターを設定します。

```sql
SELECT *
  FROM sales
 WHERE region = '{region}'
```

コンテナーは、`region = 'East'`、次に `region = 'West'` の順に2回実行され、毎回、封じられたグループ全体が実行されます。

<Aside type="note">**Combine all iterations' output** は今後の機能です。利用可能になるまでは、下流のステップには最後の反復のテーブルのみが表示されると想定し、すべての反復の結果を保持する必要がある場合は、各回をループ変数にちなんだ名前のテーブル（たとえば `{region}` をキーにした出力テーブル）に書き込んでください。</Aside>

### コンテナーの条件

実行コンテナーには、コンテナー全体を実行するかどうかを制御する**条件**も設定できます。ステップの条件と同じ変数、テーブル、ドキュメント、時刻のチェックを使用するため、両者は同じように機能します。コンテナーを右クリックして**コンテナー設定…** を選択し、**条件**タブを開きます。これはステップの条件が置かれているのと同じ最初のタブで、[ステップが使用するものと同じ条件の UI](/ja/guides/workflows/step-conditions/)がそのまま表示されます。条件に反復は必要ないため、**この実行コンテナーを反復する**をオフにしたまま、コンテナーに条件だけを設定することもできます。

**エントリー時に1回だけ評価。** コンテナーの条件は、グラフ内でコンテナーに到達した時点で1回だけチェックされます。メンバーごとではなく、反復するコンテナーでも反復ごとではありません。条件が成立すれば、すべてのメンバーステップが通常どおり実行されます。成立しない場合はメンバーは実行されず、コンテナーは出力を生成しないため、無効化されたコンテナーと同様に、その下流にあるものもすべてスキップされます。

**スキップのみ — 「移動先」はありません。** ステップで条件が成立しない場合は、そのまま進む代わりに、名前を指定した別のステップに実行を移せますが、コンテナーではできません。ステップに表示される「移動先のステップ」ピッカーはコンテナーでは非表示になるため、コンテナーの条件が成立しない場合は常に*コンテナーとその下流のすべてをスキップ*することを意味し、選択できる別の移動先はありません。

**組み合わせ方:**

- **無効化が優先されます。** 無効化したコンテナーは、条件に関係なくスキップされます。無効化はより強い無条件のスキップで、条件はまったく評価されません。
- **反復はゲートされ、ループされません。** 反復と条件の両方を持つコンテナーは、最初の反復の前に条件を1回チェックして、ループを実行するかどうかを決定します。条件が成立しない場合は最初の反復だけでなくすべての反復がスキップされ、成立した場合は反復ごとに再チェックされません。
- **再開しても判断は維持されます。** この方法でコンテナーをスキップした実行を再開しても、条件は再評価されません。コンテナーは、一時停止前に完了した他の判断と同様に、スキップされたままになります。
- **条件の不具合は実行を失敗させます。** 条件の評価中にエラー（たとえば、チェックの構成ミス）が発生すると、そのエラーで実行が失敗します。これは条件が成立しない場合と同じようには扱われないため、コンテナーが黙ってスキップされることはありません。

<Aside type="note">コンテナーの条件には、ステップの条件と同じ条件タイプを使用します。変数、テーブル、ドキュメント、時刻に基づくチェックと比較の仕組みについては、[ステップの条件付き実行](/ja/guides/workflows/step-conditions/)を参照してください。</Aside>

## インスペクター

ドッキングされた**ステップインスペクター**には、選択したステップに関するあらゆる情報が表示されます。

- **入力**と**出力** — ステップに出入りするデータ。入力カードまたは出力カードの目のアイコンをクリックすると、[データプレビュードロワー](/ja/guides/workflows/preview-step-data/)が開き、そのテーブルの最初の数行をすばやく確認できます。
- **実行統計** — ステップの**最終実行**結果、**前回の所要時間**、実行回数、**平均**と **p95** の所要時間を含む時間のサマリー。また、該当する場合は**前回の実行エラー**または**前回の実行警告**。
- **ステップ構成を編集…** と**ステップの詳細を編集…** — ステップのフォームに直接ジャンプでき、ステップ名をクリックしてその場で名前を変更できます。
- **ステップ設定のロールバック（フラッシュバック）** — ステップの構成を、以前に保存されたバージョンに戻します。
- **実行履歴を表示** — このステップの実行履歴をすべて開きます。

ステップを1つ選択するとそれを調べられ、複数選択すると、インスペクターはキャンバスのツールバーにある一括操作を案内します。

インスペクターは**サイズ変更可能**（インスペクターとキャンバスの間の区切りをドラッグ）で、**折りたたみ可能**です。ステップ名の横のシェブロン（または `]` キー）で細いレールに折りたたまれ、側面に選択中のステップの名前が表示され続けるため、選択していたものを見失わずに幅をキャンバスに返せます。レールのどこかをクリックすると、再び開きます。[パレットとインスペクターのペインを折りたたむ・サイズ変更する](#パレットとインスペクターのペインを折りたたむサイズ変更する)を参照してください。

## 実行履歴

**実行履歴を表示**を選択すると、サマリー統計付きで過去の実行を確認できます。キャンバスには最近の実行記録からヒートマップも描画されるため、頻繁に失敗するステップや遅いステップがひと目でわかります。

## ログを表示

ツールバーの**ログを表示**をクリックすると、このワークフローで絞り込み済みのプロジェクトの**ログ**ビューに直接移動します。通常はプロジェクトの領域から開く、完全な実行ログです。[ワークフローログの表示](/ja/guides/workflows/viewing-workflow-log/)を参照してください。

## キャンバスでワークフローを開けない場合

キャンバスは、保存されたレイアウトの一部が読み取れない場合でも、ワークフローを開きます。

- **保存された位置やサイズがないコンテナー** — たとえば API や MCP で作成されたものは、メンバーのステップを囲んで描画された状態で開きます。
- **読み取れないその他のレイアウト項目** — ワークフローは開き、**レイアウトの一部が読み取れません**という通知に、リセットまたは非表示にされたものが最大3個まで一覧表示され、それ以降は「*…ほか N 件*」と表示されます。非表示になった注釈は、次にレイアウトを保存したときに削除されます。
- **読み込めないワークフロー** — 空白のキャンバスの代わりに、**ワークフローを読み込めませんでした**というメッセージで理由が表示されます。キャンバスを閉じて、ワークフローをもう一度開いてください。
- **標準のワークフロー** — キャンバスには**ビジュアルキャンバスを利用できません — このワークフローは高度なワークフローではありません。ビジュアルキャンバスを有効にするには、「高度なワークフローに変換…」を使用してください。** と表示されます。ワークフローで**高度なワークフローに変換…** を選択して有効にします。[標準と高度の違い](#標準と高度の違い)を参照してください。
