Alteryx は `.yxdb` ファイルを2つの形式で書き込みます。従来の形式（元のエンジンが書き込む形式）は仕様がよく知られており、PlaidCloud で直接インポートできます。AMP エンジンが書き込む新しい形式（ファイルヘッダーが `Alteryx e2 Database file` となっているもの）は、仕様が非公開で公開されていないため、PlaidCloud を含め Alteryx 以外のツールでは読み取れません。

移行の期間中は、両方の形式を読み取れるライセンス済みの Alteryx Designer をまだ利用できます。Designer を廃止する前に一度だけ使用し、AMP 形式のファイルを移植可能な形式に書き換えてください。

<Aside type="note">
  従来形式の `.yxdb` ファイルは、変換せずに PlaidCloud へ直接インポートできます。`.yxdb` のインポートで読み取り不能のファイルというエラーが発生した場合は、AMP 形式のファイルである可能性が最も高いです。
</Aside>

## AMP 形式のファイルを見分ける

- ファイルを生成したワークフローが、AMP エンジンを有効にして実行された。
- 同じパッケージの他の `.yxdb` ファイルは問題なくインポートできるのに、PlaidCloud がそのファイルを読み取り不能と報告する。
- ファイルの先頭バイトが `Alteryx Database File` ではなく `Alteryx e2 Database file` になっている（任意のテキストエディターまたは16進エディターで確認できます）。

## オプション A: Designer でファイルを1つずつ保存し直す

少数のファイルであれば、Designer から1つずつ保存し直します。

1. Alteryx Designer で **Input Data** ツールを追加し、`.yxdb` ファイルを選択します。
2. **Output Data** ツールを接続し、新しい `.yxdb` のパスを指定します。
3. Output Data ツールのオプションで、ファイルを **Designer 18.1 以前と互換性がある形式** で保存するオプションを有効にします。これにより従来の形式が強制されます。
4. ワークフローを実行し、新しいファイルを PlaidCloud にインポートします。

手順2で `.yxdb` の代わりに CSV に書き出す方法でも問題なく、その場合は互換性オプションの設定は不要です。

## オプション B: ダウンロードできるワークフローでフォルダーを一括変換する

多数のファイルがある場合は、あらかじめ用意されたワークフローをダウンロードして Designer で実行します。

<a href="/downloads/convert_yxdb_folder.yxmd" download>convert_yxdb_folder.yxmd をダウンロード</a>

このワークフローは **Directory** ツール、**Dynamic Input** ツール、**Output Data** ツールを連結しており、フォルダー内のすべての `.yxdb` ファイル（従来形式でも AMP 形式でも）を、`converted_<original name>.csv` という名前の CSV ファイルとして書き出します。CSV は移植性が高く、PlaidCloud ではデータを損なうことなくインポートできます。

1. Alteryx Designer で `convert_yxdb_folder.yxmd` を開きます。
2. **Directory** ツールで、`.yxdb` ファイルが入っているフォルダーを指定します。
3. **Dynamic Input** ツールで、Input Data Source Template にそのフォルダー内の任意の `.yxdb` ファイルを1つ指定します。
4. **Output Data** ツールで、出力先フォルダーを指定します。
5. ワークフローを実行し、CSV を Document にアップロードしてインポートします。

<Aside type="caution">
  Dynamic Input ツールでは、バッチ内のすべてのファイルがテンプレートファイルと同じフィールド構成である必要があります。構成が異なるファイルは警告付きでスキップされ、スキップされたファイルは Designer の結果ペインに表示されます。構成の異なるファイルは別のフォルダーにまとめて、専用のテンプレートで再度実行するか、オプション A で個別に保存し直してください。
</Aside>

CSV に変換したファイルでは `.yxdb` 固有の型情報が失われ（すべてテキストとして取り込まれ、インポート時に型が再設定されます）、インポートしたテーブルの列の型、特に日付や高精度の小数を確認することをお勧めします。
