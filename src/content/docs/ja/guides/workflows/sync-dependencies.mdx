高度なワークフローでは、キャンバス上のコネクターがステップの実行順序を決めます。テーブルを読み取るステップは、そのテーブルを書き込むステップの後に実行されるべきですが、そのコネクターを引くことを強制するものはありません。コネクターがないと、2つのステップが同時に実行され、2番目のステップが、最初のステップの書き込みが終わる前にテーブルを読み取ってしまう可能性があります。これは、変換されたワークフローや、他のワークフローからコピーまたは組み立てられたワークフローでよく起こります。

**依存関係の同期**は、各ステップが読み書きするテーブルを調べてこれらのステップを見つけ、順序を整えるコネクターを提案します。すべての提案を確認でき、**コネクターを追加**を選択するまで何も変更されません。

依存関係の同期はコネクターを追加するだけです。コネクターを削除したり移動したりすることはなく、ステップも変更しません。

## 提案されたコネクターの確認

1. [高度なワークフローキャンバス](/ja/guides/workflows/advanced-workflows/)でワークフローを開きます。
2. ツールバーの**チェック**の隣にある**依存関係の同期**を選択します。Weaveにすでに提案がある場合は、ツールバーの下にバナーが表示されます。たとえば、*Weaveは、各ステップが、読み取るテーブルを書き込むステップの後に実行されるよう、3つのコネクターを提案します。*のように表示されます。バナーの**確認…** を選択すると、同じウィンドウが開きます。
3. **依存関係の同期**ウィンドウには、1行に1件の提案が一覧表示されます。たとえば、*「sales」を読み取る「Report」の前に「Load Sales」を実行*のようになります。各行にはチェックボックスがあります。
4. 追加したいコネクターにチェックを入れ、不要なものはチェックを外します。
5. **コネクターを追加**を選択します。

コネクターはすぐにキャンバスに表示されます。**元に戻す**ではそのすべてを1回の操作で削除でき、**やり直し**で元に戻せます。

**依存関係の同期**ボタンは、ワークフローを編集でき、そのテーブルを読み取れる場合に表示されます。

## チェックが入る提案

両方のステップが**テーブル: 抽出**、**テーブル: コピー**、**テーブル: メルト（列から行へ）**、**テーブル: ピボット（行から列へ）**、**テーブル: 特徴量の作成**のいずれかである場合、その提案にはチェックが入ります。これらは1つのテーブルを読み取り、実行のたびにターゲットを置き換えるため、順序は明確です。

それ以外の提案はすべて一覧に表示されますが、チェックは入りません。これらには、追加（**テーブル: 追加**）、インポート、結合、ルックアップを行うステップや、**SQL抽出**のように複数のテーブルを読み取るステップが含まれます。そのステップをもう一方のステップの後に待機させたい場合は、チェックを入れてください。

<Aside type="tip">追加する前に、各行を読んでください。ステップが、別のステップが*前回*の実行で書き込んだ内容を読み取る意図で作られている場合があります。その場合は、その提案のチェックを外したままにしてください。</Aside>

## ウィンドウが示すその他の情報

- **すでに順序が逆になっているステップ。** 読み取るテーブルを書き込むステップの*前*にステップを実行させるコネクターがすでにある場合、ウィンドウにその件数が表示されます。依存関係の同期はステップの順序を入れ替えません。キャンバス上でそれらのコネクターを確認してください。
- **開けないステップ。** ロールによって非表示になっているステップが関係する提案は、一覧には表示されず、件数に含まれます。
- **Weaveがチェックできないワークフロー。** ステップが別のワークフローを実行する場合、Weaveが追跡できないテーブルを使用する場合、またはコネクターがループを形成している場合、ウィンドウにはWeaveがワークフローのステップ順序をチェックできないことが表示され、提案は行われません。
- **追加するものがない場合。** すべてのステップがすでに、読み取るテーブルを書き込むステップの後に実行される場合は、ウィンドウにその旨が表示されます。

## Weaveがチェックしない項目

Weaveは、順序が確実な場合にのみコネクターを提案します。次の項目は判断しません。

- ワークフロー内の複数のステップ、または別のワークフローからも書き込まれるテーブル。ステップが他のワークフローの出力を読み取る意図で作られている場合があるためです。別のステップも書き込むテーブルを、読み取りと書き込みの両方で扱うステップも、同様に扱われます。
- ステップが変数で選択するテーブル、複数のテーブルが共有する名前、ビュー、または別のプロジェクトのテーブル。
- ワークフロー内のステップがクリア、行の削除、または削除（ドロップ）を行うテーブル。テーブルをロードする前に空にするのは、意図された順序だからです。
- [実行コンテナー](/ja/guides/workflows/advanced-workflows/#実行コンテナー)内のステップ。
- 無効なステップ、および無効なコンテナー内のステップ。無効なステップを経由するコネクターのパスも、ワークフローがそのステップをそのまま通過するため、有効なものとして扱われます。

Weaveがチェックするのはステップの実行順序であり、ステップが生成するデータではありません。

## 確認中にワークフローが変更された場合

ウィンドウを開いている間に誰かがワークフローを変更した場合や、提案が適用できなくなった場合は、**コネクターを追加**を選択したときに**ワークフローの変更**の通知が表示され、キャンバスが再読み込みされます。もう一度**依存関係の同期**を選択すると、Weaveの最新の提案を確認できます。

ロックされているワークフローでは、コネクターを追加したり元に戻したりする前にロックを解除してください。

## Weaveが自動的に検出

これらのステップを見つけるためにキャンバスを開く必要はありません。Weaveは、一度も実行されていないものを含むすべての高度なワークフローをバックグラウンドでチェックし、**Weave**タブに**Steps that can run before the table they read is written**を報告します。コネクターが不足している場合は、その検出事項の**修正**を選択すると、ワークフローのキャンバスでこのウィンドウが開きます。[Weaveの検出事項](/ja/guides/ai-assistant/weave-findings/#現在weaveがチェックする内容)を参照してください。
