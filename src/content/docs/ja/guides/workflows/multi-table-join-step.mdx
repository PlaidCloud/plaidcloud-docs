## 説明

**複数テーブル結合**ステップは、1回の操作で多数のテーブルを結合します。2テーブルの結合を連鎖させる方法では、全体像が見えなくなり、同じ出力マッピングを繰り返すことになります。このステップでは、すべてのテーブルをビジュアルな**結合グラフデザイナー**上に配置し、列間の結合を描画して、1つの結果テーブルを作成します。

1つのファクトテーブルを複数のディメンションテーブルやルックアップテーブルに結合するという、分析でよくある結合の形に合わせて作られています。最大32個のテーブルを一度に結合できます。

<Aside type="note">このステップは、複数の内部結合 / 外部結合ステップを連鎖させるパターンを置き換えます。1つのステップ、1つの図、1つの出力マッピングで、テーブルの関係を1つのビューで共有できます。</Aside>

## 複数テーブル結合を追加する

ほかのステップと同様に追加し、**複数テーブル結合**を選択します（ステップメニューの**テーブル**グループ、または[高度なワークフローキャンバス](/ja/guides/workflows/advanced-workflows/)のパレットからドラッグします）。ステップのエディターには3つのタブがあります。

1. **ソース** — テーブルを追加して結合を描画するビジュアルデザイナーです。
2. **列** — 結果テーブルに含める列です。
3. **フィルター** — 結合結果に適用する任意のフィルターです。

作業中は、ステータスインジケーターに**保存できます**または**未保存の変更**と表示されます。

## テーブルと結合

### テーブルを追加する

**テーブルを追加**を選択して、ソーステーブルをキャンバスに配置します。各テーブルは列を一覧にしたカードとして表示され、**エイリアス**が付きます。エイリアスは、ほかの場所でそのテーブルの列を参照するための短い名前です（`alias.column`として使用します）。エイリアスは英字またはアンダースコアで始まる必要があり、SQLキーワードにはできません。必要な数だけ（最大32個）追加し、結果の書き込み先となる**ターゲットテーブル**を選択します。

カタログでテーブルの列が変更された場合は、**サーバーから再取得**を使用すると、カードの列が最新の値に置き換えられます。

### 動的テーブルと変数

ソーステーブルも**ターゲットテーブル**も、リストから選択する代わりに**参照**として指定できます。テーブルピッカーで**動的**にチェックを入れ、次のいずれかを入力します。

- テーブルの**名前** — `FACT_GL`
- プロジェクトの**パス** — `/03 Results/FACT_GL`

どちらにも`{variable}`トークンを含めることができ、ワークフローの実行時に置換されます。たとえば`/03 Results/FACT_GL_{year}`は、プロジェクト変数またはワークフロー変数に応じて、期間ごとに異なるテーブルに書き込みます。ターゲットテーブルが存在しない場合は作成されます。

<Aside type="note">動的な**ソース**は、設計時に列を読み取れません。指定したテーブルは、実行時まで確定しないためです。カードは空の状態で表示され、サイドパネルで列を手動で追加します。結合は、それらの列から描画します。動的な**ターゲット**には、このような制限はありません。</Aside>

対応していない中かっこは保存時に検出されるため、`FACT_{year`のような入力ミスは、実行の途中で失敗するのではなく、ステップ上で報告されます。

### 結合を描画する

あるテーブルの列のドットから別のテーブルの列へドラッグして、**結合**（エッジ）を作成します。エッジを選択すると右側にエディターが開き、次を設定できます。

- **結合タイプ:**

  | タイプ | 保持する行 |
  |------|-------|
  | **INNER** | 一致する行のみ |
  | **LEFT** | 左テーブルのすべての行 |
  | **FULL** | 両側のすべての行 |
  | **CROSS** | 左のすべての行と右のすべての行の組み合わせ（条件なし） |

- **結合条件** — 2つのテーブルの列を比較する1つ以上の条件です。**+ 条件を追加**で追加し、**AND** / **OR**で組み合わせ、すべての演算子（`=`、`<>`、`<`、`<=`、`>`、`>=`、`BETWEEN`、`IS NULL`、`IS NOT NULL`、`IN`、`NOT IN`、`LIKE`、`NOT LIKE`）を使用できます。
- **ラベル(任意)** — 結合に名前を付けます（例: `customer-to-orders`）。図が読みやすくなります。

デザイナーは結合グラフをツリーとして保持します。各テーブルはちょうど1つの結合を通じて結果につながるため、循環や曖昧な経路は生じず、テーブルを自分自身に結合することもできません。結合を削除するには、エッジを選択して**エッジを削除**を選択します。

### 結合前にテーブルをフィルターする

各ソーステーブルには、結合の*前*に適用される**結合前フィルター**があります。これを使用して、必要な行にテーブルを絞り込みます（列は`alias.column`として参照します）。これは、すべての結合の*後*に実行される**Post-Join Filter**とは別のものです。

### デザイナーのツールバー

- **レイアウトを整理**は、結合の順序に従って、テーブルと結合を左から右へ自動的に配置します。
- **全体を表示**は、グラフ全体が収まるように拡大縮小して中央に配置します。手動でパンやズームもできます。
- **列をフィルター…** は、テーブルに列が多い場合に、カードに表示する列を絞り込みます。
- **元に戻す** / **やり直し**は、編集を前後に戻したり進めたりします（Ctrl+Z / Ctrl+Y）。**履歴**は、ダイアログを開いてからのすべての変更のパネルを開き、**復元**できます。
- **エクスポート**は、結合の図をSVG画像としてダウンロードします。ドキュメント作成やレビューに便利です。

## 出力列

**列**タブで、結果テーブルに含める列を選択します。結合したどのテーブルからでも選択できます。**キャンバスから選択…** を使用すると、すべてのソースの列からビジュアルに選択でき、**すべてのソース列を追加**を使用すると、すべてを一度に追加できます。各列について、名前の変更、データ型の設定、集計の適用ができます。2つのソース列の名前が同じ場合、PlaidCloudは衝突しないようにソースエイリアスをプレフィックスとして付けます。

各出力列は、次の3つのうち、ちょうど**1つ**から値を取得します。

- **ソース列** — **ソースエイリアス**にその列を持つキャンバス上のエイリアスを、**ソース**に`alias.column`の参照を設定します。どちらも必須で、ソース列は常に元のテーブルを指定します。
- **定数** — すべての行で同じ固定値です。
- **式** — **式の列を追加**を選択すると行が追加され、式エディターが開きます。式では、キャンバス上の**任意の**ソースエイリアスを`alias.column`として参照できるため、複数の結合テーブルにまたがる値（2つのテーブルにまたがる`CASE`、文字列の連結、計算された金額）はこの方法で作成します。式の行では、**ソースエイリアス**と**ソース**は空のままにします。

複数を入力するとエラーになり、何も入力しない場合もエラーになります。

**式**セルでは、標準のPlaidCloud式エディターが開き、列ブラウザーにはキャンバス上のすべてのテーブル、関数リスト、オートコンプリートが表示されます。

出力列はキャンバスに追従します。**ソース**タブでソースの名前を変更すると、その出力列は新しいエイリアスに移動し、ソースを削除すると、その出力列も削除されます。そのため、結合に含まれなくなったテーブルを指す列が残ることはありません。

## Post-Join Filter

**Post-Join Filter**タブは、結合結果がターゲットテーブルに書き込まれる前に、任意のフィルターを適用します。これはSQLの`HAVING`句に相当します。ボックスをクリックして式エディターを開きます。列ブラウザーには出力列が一覧表示され、`result.column_name`として参照します。ここではソースエイリアスはスコープに含まれません。ボックスの下の**参照**には、使用できるすべての参照が一覧表示されます。空のままにすると、結合後のフィルターは行われません。

## 検証

PlaidCloudは、構築中と、ステップの実行時の両方で結合を検証します。問題がある場合（サポートされていない構成、循環、重複したエイリアス、Source / Constant / Expressionのいずれも設定されていない（または複数が設定されている）出力列、存在しなくなった列など）、タブに件数付きの⚠バッジが表示され、デザイナーは問題のあるテーブルまたは結合をマークし、保存は理由とともに拒否されます。未解決の問題がある状態で保存すると、最初の問題があるタブに切り替わります。**問題へ移動**でも、必要に応じて同じ操作ができます。

保存時、PlaidCloudは各出力列の式も、結合自体の入力に対して、ステップの実行時と同じようにエイリアス（`alias.column`）でチェックし、Post-Join Filterもチェックします。壊れた式は該当する出力列で、壊れたPost-Join Filterはそのフィルターで報告されます。結合が**実行時に指定された列も引き継ぐ**に設定され、集計していない場合、実行時に列が追加されるため、保存時の式のチェックは省略されます。それらの式は、ステップの実行時にチェックされます。ソースごとのフィルターも、ステップの実行時にチェックされます。

<Aside type="tip">`CROSS`結合は、行のすべての組み合わせを生成し、条件はありません。大きなテーブルでは非常にコストが高くなる可能性があるため、意図して使用してください。</Aside>

## ステップを実行する

複数テーブル結合は、ほかのステップと同様に実行されます。すべての結合を1回の操作で実行し、マッピングされた列をターゲットテーブルに書き込みます。
