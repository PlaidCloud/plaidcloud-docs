Panelアプリはプロジェクトに属します。プロジェクトはアプリに対して2つの役割を果たします。アプリがテーブルをデフォルトで読み取る場所であることと、アプリが身にまとう色とロゴを保持することです。ブランディングを一度設定すれば、プロジェクト内のすべてのアプリに反映されます。

## プロジェクトにブランドを設定する

1. プロジェクトを開き、**ホーム**タブに移動します。
2. **Panel App Branding**グループで、**Edit Branding**をクリックします。
3. 任意の色を設定します。スウォッチをクリックして色を選ぶか、`#0078d4`のような16進数の値を入力します。
4. 必要に応じて、ロゴを選択します。
5. **プレビュー**を確認し、**保存**をクリックします。

ブランディングを保存できるのは、マネージャーとアーキテクトだけです。その他のプロジェクトメンバーには、フォームが読み取り専用で表示されます。

**Reset to default**は、すべての色とロゴをクリアします。保存するとブランド全体が置き換えられるため、空白のままにした色はPlaidCloudのデフォルトに戻ります。

### 色

| 設定 | 色を付ける対象 |
|---|---|
| **Brand** | ボタン、アクティブなタブ、スライダーのハンドル、その他の主要なコントロール。 |
| **Brand accent** | 副次的なアクセント。 |
| **Brand hover** | ポインターが重なっているときの主要なコントロール。 |
| **Brand pressed** | 押されているときの主要なコントロール。 |
| **Header background** | アプリのヘッダーバー。 |
| **Header text** | ヘッダーのタイトルとユーザー名。 |
| **リンク** | リンク。 |
| **Text on brand** | ブランドカラーのコントロール上に表示されるテキスト。 |

設定はこの8つだけです。色は3桁または6桁の16進数の値でなければなりません。サーフェス、本文のテキスト、境界線は、ライトとダークの両方でPlaidCloudの外観を維持するため、ブランドによってアプリが読めなくなることはありません。

### ロゴ

ロゴは、プロジェクトのワークスペースにある[ドキュメントアカウント](/ja/guides/documents/)内の画像です。

1. ドキュメントアカウントの最上位にある`branding`という名前のフォルダーに、画像をアップロードします。
2. **Edit Branding**で、**ドキュメントアカウント**を選び、続いて**Image in the branding/ folder**で画像を選びます。

ロゴには、512 KB以下のPNG、JPEG、GIF、WebP、SVGファイルを使用できます。ロゴはアプリのヘッダーの右側に表示されます。画像は`branding/`の直下、またはその中のフォルダーに置く必要があり、ブランディングを保存するユーザーはそのアカウントを読み取れる必要があります。

### 変更が反映されるタイミング

アプリは、閲覧者のセッションが開始されるときにブランディングを読み取ります。保存した変更は、次にアプリが開かれたとき、または再読み込みされたときに反映されます。

## アプリをプロジェクトに割り当てる

### 公開時

**サーバーPanelアプリを公開**ダイアログの**ディレクトリ設定**の下に、**プロジェクト**ピッカーがあります。アプリを所有するプロジェクトを選択します。プロジェクトに公開するには、そのプロジェクトへのアクセス権が必要です。プロジェクトはアプリの公開後は固定されます。アプリを移動するには、以下で説明する**割り当て**を使用します。

プロジェクトを指定して公開したアプリは、デフォルトでそのプロジェクトのテーブルを読み取るため、`table("sales")`にプロジェクトの引数は不要です。

### 既存のアプリの場合

1. **マイPanelアプリ**を開きます。
2. 移動したいアプリの行にある**割り当て**アイコンをクリックします。
3. **プロジェクト**を選択し、**確認**をクリックします。
4. 結果を読みます。現在そのアプリを開けるワークスペースメンバーのうち、プロジェクトのメンバーではないユーザーが一覧表示されます。
5. **割り当て**をクリックします。

確認では何も変更されません。**マイPanelアプリ**の**プロジェクト**列には、各アプリのプロジェクトが表示されます。

### アクセス

アプリを開けるユーザーは、現時点ではプロジェクトによって変わりません。以前アプリを開けた閲覧者は、引き続き開けます。今後は、アプリへのアクセスがプロジェクトのメンバーシップに従うようになります。そのため、**確認**にはプロジェクトに含まれていないメンバーが一覧表示され、先に追加できるようになっています。
