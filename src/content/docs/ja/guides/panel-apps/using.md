公開済みのアプリはすべて**アプリ**画面に表示され、**ランタイム**、**ステータス**、**スラッグ**、タイムスタンプを確認できます。左端の列でアプリを開きます。残りの行アイコンでは、誤操作を防ぐためのアプリのロック、編集、削除ができ、サーバーアプリの場合はさらに再ビルド、ログの表示、使用状況メトリックの表示ができます。開くアイコンはアプリのランタイムに応じて変わるため、WASM アプリとサーバーアプリは一目で区別できます。

## ビルドステータス（サーバーアプリ）

サーバーアプリの**ステータス**列にはビルドの状況が表示され、ビルド中は一覧が自動的に更新されます。

- **ビルド中…**：PlaidCloud がリポジトリをコンテナーにビルドしています。アプリにはまだ URL がありません。
- **準備完了**：ビルドが成功しました。アプリの URL が有効になり、その行に**開く**アイコンが表示されます。
- **失敗**：ビルドが完了しませんでした。エントリポイントとブランチを確認し、アプリを編集して再公開してください。

WASM アプリにはビルド手順がなく、公開するとすぐに利用できます。

## サーバーアプリの再ビルド

サーバーアプリの行にある**再ビルド**アイコンをクリックすると、設定を変更せずにアプリを再ビルドして再デプロイします。PlaidCloud が同じブランチとエントリポイントを再びビルドする間、アプリのステータスは**ビルド中…** に戻り、新しいビルドが有効になると**準備完了**に戻ります。

依存関係の変更、ベースイメージの更新、一時的なビルド失敗の後には、**再ビルド**を使います。サーバーアプリを編集して保存した場合も再ビルドされますが、再ビルドのために編集フォームを開く必要はありません。

[App Runner](/ja/guides/workflows/use-converted-alteryx-apps/#アプリを最新の状態に保つ) アプリ（変換された Alteryx アプリ用に生成される入力フォーム）の場合、**再ビルド**と編集の保存では、まず生成ファイルを現在の App Runner のバージョンに更新してからビルドします。PlaidCloud 自体が更新されるときにも、ロックされていないすべての App Runner アプリに対して同じ処理が行われます。ロックされているアプリは、ロックを解除した後に**再ビルド**が必要です。

## アプリのロック

アプリの行にある**ロック**アイコンをクリックすると、誤操作による変更からアプリを保護できます。アプリがロックされている間は、次のようになります。

- **編集**、**削除**、**再ビルド**は実行されず、アプリがロックされていることが通知されます。
- **サーバーアプリのブランチへのプッシュでは再ビルドされません。** ロックを解除するまで、自動再ビルドはスキップされます。スキップされたプッシュではビルドが実行されないため、アプリのビルドログには何も追加されません。ロック解除後に再度プッシュするか、**再ビルド**を使って変更を反映してください。
- アプリを開く操作、ログの表示、使用状況メトリックの表示は、引き続き利用できます。ロックが止めるのは変更だけで、閲覧者には影響しません。

もう一度アイコンをクリックするとロックが解除されます。アイコンはアプリの現在の状態を示し、ロック中は閉じた状態、ロックされていないときは開いた状態で表示されます。

ロックは、誤った編集、意図しない削除、デモ中のアプリへの git プッシュといった事故を防ぐためのもので、ワークフローやワークフローステップのロックと同じです。セキュリティ制御では**ありません**。Panelアプリを編集できる人なら誰でもロックを解除できます。

> ロックが対象としない点が 2 つあります。ロックした時点で**すでに進行中のビルド**は最後まで完了して公開されます。また、**WASM** アプリのファイルはドキュメントアカウントに保存されているため、それらのファイルを置き換えると、ロックされたレコードには触れずに実行中のアプリが変更されます。

## アプリを開く

準備完了のアプリの行の先頭にある**開く**アイコンをクリックすると、新しいタブでアプリが起動します。**開く**は、行の **⋯** メニューの最初の項目でもあります。[行アクションメニュー](/ja/guides/dashboards/using-dashboards/#行アクションメニュー)をご覧ください。

- サーバーアプリは `https://<your-tenant-host>/serve/<slug>/` で提供されます。
- **開く**アイコンは、サーバーアプリが**準備完了**になってから表示されます。

サーバーアプリはリソースを節約するため、アイドル時にゼロへスケールダウンします。そのため、アイドル期間の後の最初の起動では、アプリを立ち上げる必要があります。その間は空白のタブではなく **PlaidCloud の読み込み画面**が、ライトまたはダークのテーマで表示されます。この画面には、アプリ名、**開始中**、**準備中**、**アプリを読み込み中**という進行状況、ワークスペース ID が示されます。アプリは準備ができ次第自動的に表示され（通常は数秒、コールドスタートでは最大 1 分程度）、次にアイドル状態になるまで通常どおり応答します。

> アプリを起動できない場合、読み込み画面はいつまでも回り続けるのではなく、アプリが起動しなかったことと停止した段階を伝えるメッセージと**再試行**ボタンに切り替わります。それでも解決しない場合は、アプリを編集してエントリポイントとブランチを確認して再公開するか、PlaidCloud 管理者にお問い合わせください。

### 外観

サーバー型の Panelアプリは、デフォルトで PlaidCloud のモダンな **FAST** デザインを使用しますが、既存の CSS がそれに依存している場合は、アプリの**デザイン**設定で Panel の**デフォルト**のスタイルに戻せます。テーマ（ライト、ダーク、または閲覧者が切り替えられるライト／ダーク切り替え）は、アプリのテンプレートで設定します。パターンについては、作成ガイドの[テーマの設定](/ja/guides/panel-apps/creating/#テーマの設定ライトダークまたは切り替え)をご覧ください。アプリのテーブルやカスタムスタイルが明るい背景向けに作られている場合は、ライトに固定してください。

## ログの表示（サーバーアプリ）

サーバーアプリの行にある**ログを表示**アイコンをクリックすると、ログビューアーが開きます（WASM アプリはブラウザー内で完結して動作し、サーバーログがないため、このアイコンはサーバーアプリの行にのみ表示されます）。

ビューアーには 2 つのタブがあります。

- **ランタイム**（最初に表示）：実行中のアプリ自身の出力で、アプリが記録したログ、出力した内容、捕捉されなかったエラーが含まれます。アプリがゼロへスケールダウンした後も保持されるため、以前のセッションで何が起きたかを確認できます。
- **ビルド**：アプリのコンテナーをビルドしたときの出力です。ビルドが**失敗**と表示される*理由*（たとえば、インストールできなかった依存関係）を確認するのに使います。

各タブには、**情報 / 警告 / エラー**のフィルター、**ログの開始時点**の時間範囲（直近 1 時間から 30 日間まで、またはすべて）、**更新**ボタン、新しいエントリを定期的に取得する**自動更新**があります。稼働中のアプリや進行中のビルドを監視するときに便利です。新しいエントリが先頭に表示されます。

> ビルドの出力を取得できなかった場合、ビルドタブは空のままにはならず、その理由を説明する短いメモが表示されます。

### ログメッセージの全文を読む

ログテーブルでは、一覧を読みやすくするために長い行が省略されます。ログの行を選択すると、テーブルの横に**詳細ペイン**が開き、そのエントリのメッセージ全文が表示されます。長いエラーメッセージや完全なスタックトレースなど、テーブルに収まらないものを途切れずに読むには、この方法が最も簡単です。

### ログ行のコピー

複数のログ行を一度に選択し、**コピー**をクリックするとクリップボードにコピーできます。アプリのデバッグ中に AI アシスタントとのチャットへログを貼り付けたり、チームや PlaidCloud サポートへのメッセージに貼り付けたりするときに便利です。

### ログ行を発生させたユーザー

アプリで閲覧者がサインインしている場合、各ログ行には、その行を生成したセッションの**ユーザー**がタグ付けされるため、どの閲覧者が特定のエラーや警告に遭遇したかを確認できます。タグ付けはベストエフォートです。閲覧者が関与する前に実行されるフレームワークや起動時の行には、ユーザーが表示されない場合があります。

## 使用状況メトリック（サーバーアプリ）

サーバーアプリの行にある **Usage Metrics** アイコン（**ログを表示**の隣）をクリックすると、アプリの利用状況を確認できます。ビューには次の内容がまとめられます。

- **ユニークユーザー**：アプリを開いた個別のユーザー数。
- **セッション**：アプリが開かれた回数。
- **セッション時間の平均と中央値**：1 回の訪問のおおよその長さ。
- **最終使用**：アプリが最後に開かれた日時。

サマリーの下には**ユーザーごと**と**日ごと**の内訳が表示され、アプリを誰が使用しているか、使用状況が時間とともにどう推移しているかを確認できます。

> 時間は概算です。サーバーアプリは誰も使用していないときにアイドル状態になってスケールダウンするため、セッションの正確な終了時刻が観測されるとは限りません。時間の数値は正確な計測値ではなく、目安としてご覧ください。

## アプリの編集

アプリの行にある**鉛筆**アイコンをクリックすると、アプリを編集できます。編集フォームはアプリのランタイムに応じたものになります。

**サーバー**アプリでは、名前、スラッグ、ブランチ、エントリポイント、CPU、メモリ、デザイン、アイドル時間、公開フラグ、埋め込み配信のドメイン、メモを変更できます。**Git接続**はアプリの作成後に固定され、読み取り専用で表示されます。保存するとアプリが再ビルドされ、新しいビルドの準備ができるまでステータスは**ビルド中…** に戻ります。

## アプリの削除

アプリの行にある**マイナス**アイコンをクリックして確認します。アプリの削除や公開の取り消しでは、必ず先に確認が求められます。サーバーアプリを削除すると、そのビルドとデプロイメントが破棄されます。WASM アプリを削除すると、静的ファイルの公開が取り消されます。アプリの URL はただちに使えなくなります。

MCP ツール `panel_deployment_manage` では、公開の取り消しは提供されなくなりました。代わりに、この一覧からアプリを削除してください。
