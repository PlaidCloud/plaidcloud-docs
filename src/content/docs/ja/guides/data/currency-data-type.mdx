**通貨**は、金額のために作られた列のデータ型です。数値、整数、テキストなどのおなじみの型と並んで、すべてのデータ型の一覧に表示されます。金額を正確な固定小数点の10進数として保存し、精度は18桁、小数点以下は4桁です。およそ±100兆まで扱え、1/10,000単位まで正確で、浮動小数点の丸め誤差はありません。

メリットは速度です。通貨の列がメモリ上で占める幅は数値の列の半分なので、金額が詰まったテーブルをスキャンするダッシュボードやワークフローのステップは、読み取るデータが約半分になり、より速く完了します。数値は引き続き高精度のデフォルトです（精度38桁、小数点以下10桁）。通貨は、値が金額である場合に選択するよりスリムな型です。

<Aside>
通貨は、現在のプラットフォームリリースとともに提供されます。お使いのワークスペースでアップデートが有効になると、データ型の一覧にこのオプションが表示されます。
</Aside>


## 通貨を使う場合

コスト、収益、価格、利益率、支出、配賦額など、金額を保持する列には通貨を選択します。これらは収益性モデルや財務モデルの大部分を占める列であるため、型を変更するだけで、スキャン負荷の高いダッシュボードやワークフローが最も大きく改善されることがよくあります。

次の場合は数値のままにします。

* 値がおよそ±100兆を超える可能性がある場合、または小数点以下4桁を超える桁数が必要な場合。為替レート、単価、パーセンテージ、配賦係数などが該当します
* 列に金額とそれ以外の指標が混在している場合、または何を保持するかわからない場合

<Aside type="note">
通貨の値は、すべて精度18桁、小数点以下4桁に収まる必要があります。小数点以下4桁の場合、およそ±100兆です。列にそれ以上のスケールや精度が必要な場合は、数値を使用してください。
</Aside>


## 設定場所

通貨は、列のデータ型を選択できるあらゆる場所で利用できます。

### ワークフローステップの列マッピング

任意のステップの出力列マッピング（データマッパーのグリッド）で、列のデータ型ドロップダウンから**通貨**を選択します。数値やテキストを選ぶのと同じ方法です。ステップは次回の実行から、その列を通貨として書き込みます。

### テーブルの列のプロパティ

テーブルの**列のプロパティ**を開き、**データ型**コントロールで列を**数値**と**通貨**の間で切り替えます。変更は、テーブルが次に再構築されたときに有効になります。たとえば、そのテーブルを生成するワークフローのステップが次に実行されるときです。

### AI アシスタントまたは MCP ツールでの設定

[MCP](/ja/integrations/ai-coding-agents/getting-started/) 経由で接続されたエージェントも、型を設定できます。列の型を指定する場所（列の作成、テーブルの定義、ステップの設定）では、データ型の値は `currency` です。アシスタントに*「金額の列を通貨にして」*と依頼するのが、列数の多いテーブルの型を変更する最も速い方法になることがよくあります。


## 通貨の動作

いくつかのルールにより、プラットフォーム全体で通貨の動作が予測しやすくなっています。

* **通貨は常に明示的な選択です。** インポート、型の自動検出、SQL の結果、派生列（合計、式、配賦の出力）は、常にデフォルトで数値になります。結果を通貨にしたい場合は、その出力列の型を自分で変更してください。
* **一度設定すると記憶されます。** 通貨と宣言された列は、読み取り、下流のステップ、テーブルの再構築を経ても通貨のままです。下流のステップがテーブルから列マッピングを取り込むと、通貨の型はステップの設定に自動的に引き継がれます。
* **集計は数値を返します。** 通貨の列に対する SUM やその他の集計は、数値の結果を生成します。集計結果を通貨として保存したい場合は、出力列を通貨に戻してください。
* **空のセルは 0 としてインポートされます。** ファイルのインポートでは、通貨の列の空のセルは、数値の場合と同様に 0 として読み込まれます。

<Aside type="caution">
生の SQL を記述するステップでは、**取り込み**ボタンがクエリ結果から出力列を推論しますが、クエリ結果は常に数値として返されます。取り込みを実行した後で、金額の列を通貨に設定してください。再度実行した場合は、もう一度設定し直す必要があります。
</Aside>
