データパイプラインは、検証やプロセスチェックには役立つものの、最終的な結果のレポートには適さない中間テーブルやビューを数多く生成することがあります。PlaidCloud には、ダッシュボードの作成や PlaidXL でのデータ取得の際に、こうした余計な情報を減らすための `Publish` プロセスがあります。`Publish` プロセスにより、どのテーブルとビューが最終的でレポートに使用できる信頼性のあるものかが明確になります。

## 公開

PlaidCloud のプロジェクト設定にある `Tables` タブで、ダッシュボードや PlaidXL で使用するために公開したいテーブルを探します。テーブルのレコードを右クリックし、メニューから `Set Published Table Reporting Name` を選択します。

一意の公開名を指定できるダイアログが開きます。この名前は、テーブル名やビュー名と同じである必要はありません。ダッシュボードや PlaidXL でデータソースを参照する際に、ユーザーにとってわかりやすい名前を付けられるため、別の名前にすると便利なことがよくあります。

テーブルまたはビューが公開されると、公開名が `Tables` ビューの `Published As` 列に表示されます。

テーブルを選択すると、**テーブルの詳細**パネルの**テーブルID**の下にある、読み取り専用の**公開名**フィールドにも名前が表示されます。公開されていないテーブルでは、このフィールドに「未公開」と表示されます。フィールドの横にあるコピーボタンで名前をコピーできます。名前が長くて収まらない場合は、フィールドにカーソルを合わせると全体が表示されます。

<Aside>公開名にはいくつかの制限があります。最大 63 文字で、特殊文字にも一部制限があります。これは、PlaidCloud の外部にあるシステム、ツール、プロセスとの互換性を最大限に確保するために必要です。</Aside>

<Aside type="caution">
**行アクセス。** [行アクセス](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)で制限されている列を持つテーブルを公開すると、同じ手順でそのテーブルのダッシュボードフィルターも設定されます。ダッシュボードは公開されたレポート用ビューを通じてテーブルを読み取るため、PlaidCloud は公開が完了する前に、グループごとにフィルターを登録します。登録できない場合は、理由とともに公開が拒否され、その試行で作成されたものはすべてロールバックされます。制限されたテーブルが、フィルターなしのままダッシュボードに残ることはありません。行を制限しているプロジェクトでは、*ビュー*を公開できません。ビューのクエリによって、制限された列の名前が変更されたり、その列から派生した列が作られたりする可能性があるためです。代わりに、そのビューが読み取るテーブルを公開してください。[1 つの列名、すべてのテーブル](/ja/administration/access/managing-security-groups-and-assignments/#1つの列名すべてのテーブル)を参照してください。
</Aside>

## 公開テーブルのパフォーマンスを確認する

公開テーブルのパフォーマンスは、PlaidCloud のテーブルパフォーマンスオートパイロットのフェーズ 1 です。公開テーブルがどのように使用されているかを監視して推奨事項を提示しますが、まだテーブルを自動的に変更することはありません。**テーブルオプティマイザー**を開いて公開テーブルを選択し、**公開テーブルのパフォーマンス**を選択すると、確認結果が表示されます。

確認結果には、繰り返し行われる直接クエリやダッシュボードの利用を含め、PlaidCloud がガイダンスを提示するのに十分な最新のアクティビティがあるかどうかが表示されます。有用なパターンがある場合は、今後のレイアウト改善で検討すべき列が示されます。また、変更が不要な場合や、結論を出すためにさらに最新のアクティビティが必要な場合も、明確に示されます。

このフェーズ 1 のリリースは受動的で、ガイダンスの提示のみを行います。改善する価値があると判断した場合は、通常の変更プロセスで計画して適用してください。今後のフェーズ 2 のリリースでは、この根拠と同じ安全性チェックを使って、サポートされている最適化を自動的に適用する予定です。

ガイダンスは、データプラットフォームと、その公開テーブルで利用できる現在のアクティビティによって異なります。PlaidCloud が安全に評価できない場合、確認結果は、提案を確実なものとして示すのではなく、その制約を説明します。

## 公開の取り消し

テーブルまたはビューの公開を取り消す手順は、公開の手順と似ています。PlaidCloud のプロジェクト設定にある `Tables` タブで、ダッシュボードや PlaidXL で使用するために公開したテーブルを探します。テーブルのレコードを右クリックし、メニューから `Set Published Table Reporting Name` を選択します。

公開名を設定するダイアログが表示されたら、`Unpublish` ボタンを選択します。これにより、ダッシュボードと PlaidXL での利用からテーブルが削除されます。

公開名は、`Published As` 列に表示されなくなります。

### AI アシスタントまたは MCP で公開を取り消す

`publish_manage` は、`project_id`、`table_id`、およびテーブルの公開 `name` を指定し、`target='table'` と `action='unpublish'` でテーブルの公開を取り消します。テーブルがその名前で公開されていない場合は拒否されます。

- **公開ビューと未使用のデータセットも削除されます。** テーブルの公開を取り消すと、その公開ビューと、どのチャートでも使用されていないダッシュボードデータセットも削除されます。チャートがまだデータセットを使用している場合、そのデータセットは残ります。
- **公開ビューを基に作成されたレポートビューがある場合、公開ビューは残ります。** テーブルの公開は取り消されますが、レポートビューがそれらに依存しているため、公開ビューとそのデータセットは残ります。
- **繰り返しても何も起こりません。** すでに公開が取り消されているテーブルの公開を取り消しても、何も変更されずに成功します。


## 名前の変更

テーブルまたはビューの名前を変更する手順は、公開の手順と似ています。PlaidCloud のプロジェクト設定にある `Tables` タブで、ダッシュボードや PlaidXL で使用するために公開したテーブルを探します。テーブルのレコードを右クリックし、メニューから `Set Published Table Reporting Name` を選択します。

ダイアログが表示されたら、公開名を新しい名前に変更します。`Publish` ボタンを押して名前を更新します。

更新後の名前は、`Published As` 列のほか、ダッシュボードと PlaidXL にも表示されます。
