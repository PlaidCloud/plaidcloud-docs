課題は、バグの追跡、機能の計画、対応が必要なあらゆる事項の記録を、チームで共有できる場所です。すべてリポジトリ内のコードに直接リンクされます。

## 課題の作成

1. リポジトリを開き、**Issues** タブを選択します。
2. **New Issue** を選択します。
3. 問題またはタスクを簡潔に表す**タイトル**を入力します。
4. Markdownを使用して**説明**を記述します。必要に応じて、再現手順、受け入れ基準、スクリーンショット、コードブロックを含めます。
5. **Submit New Issue** を選択して公開します。

<Aside>リポジトリでは、**Settings → Issue Templates** で再利用可能な課題テンプレートを定義できます。テンプレートが設定されている場合、新しい課題を開くと選択画面が表示されるため、投稿者は白紙の状態からではなく、一貫したフォームから開始できます。</Aside>

## ラベルとマイルストーンによる整理

**ラベル**は、課題の分類と優先順位付けに使用します。課題の表示中に右側のサイドバーから、または課題リストの**ラベル**フィルターから直接、1つ以上のラベルを適用します。一般的には、タイプのラベル（`bug`、`enhancement`）と優先度のラベル（`high`、`low`）を組み合わせて使用しますが、**Issues → Labels** で、ワークフローに合った任意のラベルを作成できます。

**マイルストーン**は、リリース日、スプリント、機能の目標など、共通の目標に向けて課題をグループ化します。マイルストーンは **Issues → Milestones** で作成し、課題のサイドバーから課題をマイルストーンに割り当てます。マイルストーンのビューには、課題が完了するにつれて進捗が表示されます。

## 割り当てとディスカッション

- **担当者** — サイドバーの**担当者**フィールドで、責任者を指定します。リポジトリへのアクセス権を持つワークスペースのメンバーであれば、誰でも割り当てられます。
- **コメント** — 課題の説明の下にあるコメントスレッドに、背景、決定事項、状況の更新を追加します。
- **@メンション** — コメントや説明の任意の場所に `@username` と入力すると、その人に直接通知されます。
- **リアクション** — コメントに絵文字でリアクションすると、返信を追加せずに内容を確認したことを伝えられます。

## 課題とコードのリンク

コミットやプルリクエストから課題を参照すると、履歴を追跡しやすくなります。

- **番号による参照** — コミットメッセージ、プルリクエストの説明、コメントに `#12` と入力すると、同じリポジトリ内の課題12へのクリック可能なリンクが作成されます。
- **マージ時の自動クローズ** — プルリクエストの説明にクローズ用のキーワードを含めます（例：`Closes #12`、`Fixes #34`、`Resolves #56`）。プルリクエストがデフォルトブランチにマージされると、参照されている課題が自動的にクローズされます。
- **ほかの課題への相互参照** — 課題のコメントで `#number` を自由に使用して関連する課題をリンクできます。参照された課題には逆方向のリンクが表示されるため、どちらからも関連を確認できます。

## 課題の検索

課題リストでは、複数のフィルターを組み合わせて使用できます。

| フィルター | 機能 |
|---|---|
| **状態** | オープンまたはクローズ済みの課題を表示します |
| **ラベル** | 1つ以上のラベルに絞り込みます |
| **マイルストーン** | マイルストーンに割り当てられた課題を表示します |
| **担当者** | 特定の担当者に割り当てられた課題を表示します |
| **作成者** | 特定の人が作成した課題を表示します |

各フィルターを適用するには、課題リストの上にあるフィルターバーで該当する列を選択します。キーワードで課題のタイトルと本文を横断して検索するには、[コードの検索](/ja/guides/git/searching-code/)を参照してください。
