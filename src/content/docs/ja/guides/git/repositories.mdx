リポジトリには、1つのプロジェクトのファイル、ブランチ、履歴が格納されます。このガイドでは、リポジトリの作成と、お使いのコンピューターからの接続手順を説明します。

## リポジトリを作成する

1. ワークスペースから **Git** を開きます。
2. 右上の **+** メニューを選択し、**New Repository** を選択します。
3. 名前を入力します。必要に応じて短い説明も入力します。
4. 公開範囲を選択します。新しいリポジトリはデフォルトで **プライベート** になり、アクセス権を付与したメンバーだけが閲覧できます。
5. 必要に応じて **Initialize Repository** を選択し、README、`.gitignore`、ライセンスを追加します。
6. **Create Repository** を選択します。

## パーソナルアクセストークンを生成する

PlaidCloud経由でサインインするため、アカウントにはGit用の別のパスワードがありません。コマンドラインからHTTPS経由でクローンまたはプッシュするには、パーソナルアクセストークンを作成し、パスワードの代わりに使用します。

1. 右上のアバターを選択し、**設定** を選択します。**Git** タブのヒントからも、このページへ直接移動できます。
2. **アプリケーション** タブを開きます。
3. **Manage Access Tokens** の下に、トークンを使用する場所がわかる名前（例: `laptop`）を入力します。
4. トークンでクローンとプッシュができるように、**write:repository** 権限を選択します。
5. **Generate Token** を選択します。
6. トークンをコピーして、安全な場所に保管します。トークンは再表示できません。

<Aside type="caution">トークンはパスワードと同様に扱ってください。トークンを持つ人は誰でも、Gitでお客様として操作できます。1つのトークンを取り消しても他に影響しないよう、マシンごとに別のトークンを生成してください。</Aside>

## リポジトリをクローンする

1. ワークスペースで **Git** を開き、リポジトリの行にある **Copy clone URL** を選択します。リポジトリ内で **コード** を選択し、**HTTPS** のURLをコピーすることもできます。
2. ターミナルで、そのURLを指定して `git clone` を実行します。

   ```bash
   git clone <clone URL>
   ```

3. Gitがパスワードを求めたら、**アクセストークン** を貼り付けます。ユーザー名にはURLにすでに含まれているものを使用します。
4. ヒントに表示される値を使って、コミットに記録されるGitの名前とメールアドレスを設定します。

   ```bash
   git config --global user.name "Your Name"
   git config --global user.email "you@example.com"
   ```

プッシュするには、ContributorまたはAdminのアクセスが必要です。読み取りアクセスではクローンはできますが、プッシュはできません。詳細は[アクセスレベル](/ja/guides/git/#アクセスレベル)を参照してください。

<Aside>プッシュのたびにトークンを再入力しなくて済むよう、オペレーティングシステムのGit認証情報ヘルパーに保存させることができます。たとえばmacOSでは `git config --global credential.helper osxkeychain` を使用します。</Aside>

## 変更をコミットしてプッシュする

クローンしたリポジトリの中で、次の操作を行います。

1. 変更をステージします: `git add .`
2. メッセージを付けて記録します: `git commit -m "Describe what changed"`
3. PlaidCloud Gitに送信します: `git push`

コミットは、リポジトリの **Commits** ビューと **アクティビティ** ビュー、およびそれらを含むすべてのブランチやプルリクエストに表示されます。

## アクセスと公開範囲を管理する

リポジトリの **設定** タブを開くと、名前の変更、公開範囲の変更、所有権の移譲ができます。他のメンバーが貢献できるようにするには、**設定 → Collaborators** を使用して、ユーザー名で追加し、**読み取り**、**書き込み**、または **Administrator** のロールを割り当てます。

<Aside>リポジトリへのアクセスは、ワークスペースのメンバーシップとセキュリティグループにも従います。これらがリポジトリを閲覧・編集できるユーザーにどう対応するかについては、[アクセス管理](/ja/administration/access/)を参照してください。</Aside>
