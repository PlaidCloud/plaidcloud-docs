リポジトリは、1つのプロジェクトのファイル、ブランチ、履歴を保持します。このガイドでは、リポジトリの作成と、お使いのコンピューターからの接続方法を説明します。

## リポジトリを作成する

1. ワークスペースから **Git** を開きます。
2. 右上の **+** メニューを選択し、**New Repository** を選択します。
3. 名前を入力し、必要に応じて短い説明を入力します。
4. 公開範囲を選択します。新しいリポジトリはデフォルトで **プライベート** で、アクセスを許可したメンバーだけが表示できます。
5. 必要に応じて **Initialize Repository** を選択し、README、`.gitignore`、ライセンスを追加します。
6. **Create Repository** を選択します。

## 個人用アクセストークンを生成する

PlaidCloud経由でサインインするため、アカウントには別のGitパスワードがありません。コマンドラインからHTTPSでクローンまたはプッシュするには、個人用アクセストークンを作成し、パスワードの代わりに使用します。

1. 右上のアバターを選択し、**設定** を選択します。**Git** タブのセットアップカードからもこのページに直接移動できます。
2. **アプリケーション** タブを開きます。
3. **Manage Access Tokens** で、トークンを使う場所がわかる名前を入力します（例: `laptop`）。
4. トークンでクローンとプッシュができるように、**write:repository** 権限を選択します。
5. **Generate Token** を選択します。
6. トークンをコピーし、安全な場所に保管します。再度表示することはできません。

<Aside type="caution">トークンはパスワードと同様に扱ってください。トークンを持っている人は誰でも、Git上でお客様として操作できます。1つを取り消しても他に影響が出ないように、マシンごとに別のトークンを生成してください。</Aside>

## リポジトリをクローンする

1. ワークスペースで **Git** を開き、リポジトリのクローンアドレスの横にあるコピーボタンを選択します（セットアップ手順を見るには **How to clone** を選択します）。リポジトリ内で **コード** を選択し、**HTTPS** のURLをコピーすることもできます。
2. ターミナルで、そのURLを指定して `git clone` を実行します。

   ```bash
   git clone <clone URL>
   ```

3. Gitがパスワードを求めたら、**アクセストークン** を貼り付けます。ユーザー名は、URLに含まれているものを使用します。
4. セットアップカードに表示される値を使って、コミットに記録される名前とメールアドレスを設定します。

   ```bash
   git config --global user.name "Your Name"
   git config --global user.email "you@example.com"
   ```

プッシュするにはコントリビューターまたは管理者のアクセス権が必要です。閲覧者は読み取りのみ可能で、プッシュはできません。[アクセスレベル](/ja/guides/git/#アクセスレベル) を参照してください。

<Aside>プッシュのたびにトークンを入力し直さないようにするには、オペレーティングシステムのGit認証情報ヘルパーに保存させることができます。たとえばmacOSでは `git config --global credential.helper osxkeychain` を使います。</Aside>

## 変更をコミットしてプッシュする

クローンしたリポジトリ内で、次の操作を行います。

1. 変更をステージングします: `git add .`
2. メッセージを付けて記録します: `git commit -m "Describe what changed"`
3. PlaidCloud Gitに送信します: `git push`

コミットは、リポジトリの **Commits** ビューと **アクティビティ** ビューのほか、それを含むすべてのブランチやプルリクエストに表示されます。

## アクセスと公開範囲を管理する

リポジトリの **設定** タブを開くと、名前の変更、公開範囲の変更、所有権の移譲ができます。他のメンバーが貢献できるようにするには、**設定 → Collaborators** で、ユーザー名を指定してメンバーを追加し、**読み取り**、**書き込み**、**管理者** のいずれかのロールを割り当てます。

<Aside>リポジトリへのアクセスは、ワークスペースのメンバーシップとセキュリティグループにも従います。これらがリポジトリの閲覧と編集の権限にどう対応するかは、[アクセス管理](/ja/administration/access/) を参照してください。</Aside>
