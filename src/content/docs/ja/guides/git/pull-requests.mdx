## ブランチの作成

変更内容を準備が整うまでデフォルトブランチから切り離しておくために、新しいブランチで作業します。

**UIで作成する場合：**

1. リポジトリを開き、左上付近にあるブランチセレクター（現在のブランチ名が表示されています）を選択します。
2. 検索ボックスに新しいブランチ名を入力し、**Create Branch** を選択します。

**ローカルで作成する場合：**

1. ブランチを作成して切り替えます：`git checkout -b feature-x`
2. 変更を加えてから、ステージしてコミットします：`git add .` に続けて `git commit -m "Describe what changed"`
3. ブランチをPlaidCloud Gitにプッシュします：`git push -u origin feature-x`

## プルリクエストの作成

1. リポジトリを開き、**Pull Requests** タブを選択して、**New Pull Request** を選択します。
2. **比較**ブランチにフィーチャーブランチを、**ベース**ブランチにマージ先（通常は `main` または `master`）を設定します。
3. わかりやすいタイトルと、何がなぜ変更されたかを説明する説明文を記述します。
4. 関連する課題をリンクするには、説明文にクローズ用のキーワード（たとえば `Closes #12`）を追加します。これにより、プルリクエストがマージされたときに課題が自動的にクローズされます。
5. 必要に応じてレビュー担当者を割り当ててから、**Create Pull Request** を選択します。

## 変更のレビュー

レビュー担当者は、何もマージせずにプルリクエストを確認します。

1. プルリクエストを開き、**Files Changed** を選択して差分を確認します。
2. 差分内の任意の行を選択すると、その変更に対するインラインコメントを残せます。
3. 確認が終わったら、全体の判断を送信します。承認する場合は**承認**、先に修正を依頼する場合は **Request Changes** を選択します。
4. 作成者は、フィードバックに対応するために同じブランチへコミットを追加でプッシュします。プルリクエストは自動的に更新されるため、新しく作成し直す必要はありません。
5. レビュー担当者は、各指摘に対応が完了したら、個々のコメントスレッドを解決済みとしてマークします。

<Aside>リポジトリの管理者は、デフォルトブランチでブランチ保護を有効にして、プルリクエストをマージするために必要な最小承認数を設定できます。</Aside>

## マージ

プルリクエストが承認されたら、次の手順に進みます。

1. **Merge** ボタンの横にあるドロップダウンから、マージ方法を選択します。
   - **Create a merge commit** — マージコミットを作成して、ブランチの履歴全体を保持します。
   - **Squash and merge** — ブランチ上のすべてのコミットを、マージ先のブランチ上の1つのコミットにまとめます。
   - **Rebase and merge** — マージコミットを作成せずに、ブランチのコミットをマージ先のブランチ上に再適用します。
2. **Merge** を選択して完了します。
3. 必要に応じて **Delete Branch** を選択し、不要になったフィーチャーブランチを削除します。
