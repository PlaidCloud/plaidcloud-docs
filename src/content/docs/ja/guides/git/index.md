PlaidCloud Git は、ワークスペースに組み込まれたプライベートな Git サービスです。各ワークスペースには専用の Git サーバーがあり、コード、設定、ノートブック、その他のバージョン管理対象ファイルを保管できます。あわせて、チームでの共同作業に使う課題、プルリクエスト、プロジェクトボードも利用できます。

PlaidCloud アカウントでサインインするため、別途ユーザー名やパスワードを設定する必要はありません。新しいリポジトリはデフォルトでプライベートになり、アクセス権を付与したメンバーだけが閲覧できます。

## Git を開く

ワークスペースのアプリ一覧で **Git** を選択します。**Git** タブが開き、ワークスペースのホスト、あなたのロール、**リポジトリ**一覧が表示されます。**View all in Git** を選択すると Git の Web インターフェースに移動し、**Manage who can push**（グループを管理できる場合）を選択するとグループ管理が開きます。更新ボタンで再読み込みできます。PlaidCloud に戻るには、Git 内の **← Back to** ワークスペースを使用します。

ロール表示には、あなたのレベルとして **Administrator**、**Contributor**、閲覧者 のいずれかが表示され、そのレベルで何ができるかが 1 行で示されます。各リポジトリの行には、名前、説明（ある場合）、日付付きの**更新**、コピーボタン付きの読み取り専用クローンフィールド、そしてリポジトリを Git で開く**開く**が表示されます。プライベートに作成したリポジトリはこの一覧には表示されず、Git 上で直接確認できます。

ワークスペースで Git が設定されていない場合や接続できない場合、**Git** タブには **Git is not available** と理由が表示されます。**再試行**を選択すると、もう一度確認します。

## リポジトリをクローンする

リポジトリの行からクローン用アドレスをコピーします。初めてコピーすると、以下の手順を示す **Set up Git on your computer** カードが表示されます。**閉じる**を選択すると非表示になり、ヘッダーの **How to clone** を選択すると再表示されます。

1. お使いのコンピューターに Git をインストールしておく必要があります。
2. **Settings → Applications** で、**write:repository** 権限を持つトークンを作成します。カードにそのページへのリンクがあります。
3. 表示されている 2 つのコマンド `git config --global user.name` と `user.email` で、Git に自分が誰であるかを伝えます。コマンドにはあなたの名前とメールアドレスがすでに入力されています。
4. 表示されている `git clone` コマンドでリポジトリをクローンします。Git がパスワードを求めたら、PlaidCloud のパスワードではなく、そのトークンを貼り付けます。

各コマンドには専用のコピーボタンがあります。詳しい手順は [リポジトリ](/ja/guides/git/repositories/) を参照してください。コピーにはプッシュ権限と有効化済みの Git アカウントが必要です。コピーボタンが無効になっている場合は、いずれかのリポジトリを一度開いてアカウントを有効化してください。**閲覧者**の場合は、後述のとおりプッシュ権限を依頼してください。

## アクセスレベル

Git にアクセスできるすべてのユーザーは、ワークスペースの共有リポジトリを読み取れます。プッシュできるレベルはさらに 2 つあります。

| ロール | できること | 付与方法 |
|---|---|---|
| **閲覧者** | 共有リポジトリの表示とクローン。 | すべてのメンバーのデフォルト。 |
| **Contributor** | 読み取りのすべてに加え、[Panel](/ja/guides/panel-apps/deploy-from-git/) アプリと [Dash](/ja/guides/dash-apps/deploy-from-git/) アプリのコードを置く `apps` リポジトリへのプッシュ。 | **Git Contributors** セキュリティグループ。 |
| **Administrator** | Contributor のすべてに加え、`udfs` を含むすべてのリポジトリへのプッシュと、組織の作成。 | **Git Administration** セキュリティグループ。 |

`udfs` リポジトリが管理者に限定されているのは、ユーザー定義関数が、それを呼び出すワークフローの ID で実行されるためです。

**閲覧者**の場合、**Git** タブには、**Git Contributors** への追加を依頼できるワークスペース管理者が最大 3 人まで表示されます。

## アプリと UDF からの Git

Panelアプリまたは Dashアプリのウィンドウには、リポジトリ、ブランチ、ビルドステータスを表示する **Repository** セクションがあります。プッシュできるメンバーには、**Edit in browser** と **Copy clone URL** も表示されます。Panel Studio アプリと、管理対象の PlaidCloud Git 接続を使う App Runner アプリは `apps` リポジトリ内のフォルダーであるため、ウィンドウにはそのリポジトリが表示されます。[アプリの保存場所](/ja/guides/panel-apps/studio/#アプリの保存場所) を参照してください。Git ベースの UDF のツールバーには、リポジトリをそのブランチで Git 上に開く**開く**があり、管理者向けに **Edit in browser** もあります。

## Git アクセス権を付与する

ワークスペース管理者は、**ID** でメンバーをセキュリティグループに追加するか、独自のグループに権限を追加することでアクセス権を付与します。

1. アプリコードをプッシュできるようにするには、メンバーを **Git Contributors** に追加します。Git 管理者にするには、**Git Administration** に追加します。
2. 新しいメンバー全員にアプリコードへのプッシュ権限を与えるには、**Git Contributors** をデフォルトグループに追加します。**Git Administration** はデフォルトグループにできません。
3. メンバーが何をできるかを確認するには、そのメンバーを開いて **Git** タブを選択します。メンバーの Git ユーザー名、レベル、そのレベルを付与しているグループが表示されます。

変更は、メンバーが次に Git にサインインしたとき、または **Git** タブを開いたときに反映されます。メンバーの Git アカウントは PlaidCloud のメンバーシップに連動します。メンバーを無効化または削除すると、トークンや SSH キーを含む Git アカウントが約 1 時間以内にブロックされ、再び有効化するとブロックが解除されます。削除されるものはなく、リポジトリと履歴は残ります。シングルサインオンで Git にサインインすると、そのメンバー自身のアカウントが開きます。PlaidCloud サポートスタッフには、自動的に Admin アクセス権が付与されます。
