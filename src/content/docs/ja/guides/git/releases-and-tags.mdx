タグは、`v1.2.0` のようなバージョンなど、重要なコミットを示すものです。リリースはタグを土台として、読みやすいノートと任意のファイル添付を加えたもので、ユーザーはWeb UIから特定のバージョンを参照してダウンロードできます。

## タグの作成

タグは、UIまたはローカルのクローンから作成できます。

**UIから作成する場合：**

1. リポジトリを開き、**Releases**、**Tags** の順に選択します。
2. **Create Tag** を選択します。
3. タグ名（たとえば `v1.2.0`）を入力し、対象のブランチまたはコミットを選択して、**Create Tag** を選択します。

**コマンドラインから作成する場合：**

```bash
git tag v1.2.0
git push origin v1.2.0
```

過去の特定のコミットにタグを付けるには、`HEAD` に頼らず、コミットIDを指定します。

```bash
git tag v1.2.0 abc1234
git push origin v1.2.0
```

## リリースの公開

1. リポジトリを開き、**Releases** を選択します。
2. **New Release** を選択します。
3. **Tag Name** フィールドで、既存のタグを選択するか、新しい名前を入力して、現在のデフォルトブランチの先頭に作成します。
4. **Release Title** を入力し、Markdown本文にリリースノートを記述します。変更履歴、アップグレード手順、既知の問題などをここに記載します。
5. そのバージョンを一般向けにまだ使用できない場合は **This is a pre-release** を選択します。公開せずに後で仕上げる場合は**下書きを保存**を選択します。
6. 準備ができたら **Publish Release** を選択します。

<Aside>下書きのリリースは、書き込みアクセス権を持つリポジトリのメンバーにのみ表示されます。プレリリースはアクセス権を持つすべてのユーザーに表示されますが、リポジトリの概要の「Latest」の対象からは除外されます。</Aside>

## ファイルの添付

アップロードしたファイルは、自動生成されるソースアーカイブとともに、リリースページに名前付きのダウンロードリンクとして表示されます。

1. 新規または編集中のリリースのフォームで、**Attach Files** セクションに移動します。
2. ファイルをアップロードエリアにドラッグするか、アップロードエリアを選択して参照します。ビルド済みのバイナリ、圧縮アーカイブ、チェックサム、署名がよく使われます。
3. ファイルごとに繰り返し、リリースを公開または更新します。

チームのダウンロードが速く済むよう、個々のファイルは適度なサイズに収めてください。

<Aside type="tip">npmモジュール、コンテナーイメージ、PyPIホイールなど、インストール可能なパッケージには、リリースの添付ファイルよりも[パッケージレジストリ](/ja/guides/git/packages/)が適しています。パッケージレジストリは、単なるファイルのダウンロードではできない、バージョン解決、依存関係のメタデータ、クライアントツール（`npm`、`pip`、`docker pull`）に対応しています。</Aside>

## リリースの表示とダウンロード

1. **Releases** を選択すると、新しい順にすべてのリストが表示されます。
2. プレリリースではない最新のリリースには、**Latest** バッジが付いて強調表示されます。
3. 各エントリーには、タグ名、リリースタイトル、ノート、および次へのリンクが表示されます。
   - **Source code** — タグ付けされたコミットの `zip` と `tar.gz` のアーカイブ（自動生成）。
   - **Assets** — リリースの公開時に添付したファイル。
4. ファイルのリンクを選択すると直接ダウンロードできます。URLをコピーして共有することもできます。

2つのリリースを比較するには、タグ名を比較用のURLとして開きます。

```bash
https://git.example.plaidcloud.com/you/my-repo/compare/v1.1.0...v1.2.0
```
