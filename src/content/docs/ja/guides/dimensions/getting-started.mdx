ディメンションは PlaidCloud の階層です。コストセンター、製品、勘定科目、地域、期間など、ロールアップされるあらゆる構造を整理するためのツリーです。配賦、ダッシュボード、レポートの基盤になります。

## ディメンションを使う場面

次のような場合は、ディメンションを使用してください。

- 値をリーフから親へロールアップする（部門別にコストを合計し、次に地域別、さらに会社別に合計する）
- 共通の階層に基づいて、ある行の集合から別の集合へ配賦する（IT コストを事業部に分配する）
- フラットなリストよりも深い構造でダッシュボードを切り分ける（大陸 → 国 → 都市とドリルダウンする）
- 同じグループ化ロジックを複数の場所で適用する — ツリーを1回定義して、どこからでも参照する

データがすでにフラットで1次元の場合、ディメンションは必要ありません。通常のテーブルで十分です。

## ディメンションの構造

すべてのディメンションには、1つの**メイン階層**があります。これは、すべてのリーフが正確に1回ずつ登録される標準のツリーです。その上に、同じリーフを異なる親の下で再ロールアップする**代替階層**を重ねられます（たとえば、メインのツリーではコストセンターを部門別にグループ化し、代替階層では地域別にグループ化します）。

ツリーの各ノードにはプロパティ、エイリアス、値を保持できるため、階層は単なる名前のツリーではなく、配賦やレポートから参照できるメタデータを備えた構造になります。

ディメンションの作成、コピー、並べ替え、管理の方法については、[ディメンション（階層）の使用](/ja/guides/dimensions/dimensions/)をご覧ください。

## ディメンションの読み込み方法

ディメンションは通常、ワークフローを使ってソーステーブルから読み込みます。

- **親子形式** — 2つの列（親、子）で、1行に1つのエッジ
- **レベル形式** — 階層のレベルごとに1列で、1行に1つの完全なパス

読み込みの手順については[ディメンションの読み込みとアンロード](/ja/guides/dimensions/loading-unloading/)を、オプションの全体については[Dimension Load](/ja/reference/workflow-steps/dimensions/dimension-load/)ワークフローのステップをご覧ください。
