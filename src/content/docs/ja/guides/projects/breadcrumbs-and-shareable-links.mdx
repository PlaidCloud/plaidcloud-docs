Analyzeのウィンドウは重なって開きます。プロジェクト内のワークフロー、そのワークフロー内のステップ、結果を確認するために開いたテーブルなどです。現在地を把握して元の場所に戻りやすくする機能が2つあります。各ウィンドウのタイトルにある**パンくずリスト**と、**表示中の内容に追従するURL**です。これにより、どのビューでもブックマークしたり、同僚に貼り付けて共有したりできます。

## パンくずリスト

プロジェクトに属するウィンドウでは、ウィンドウのタイトルバーに、階層をたどった内容がタイトルとして表示されます。

```
My Project › Workflow › Nightly Load
```

各部分はセグメントと呼ばれ、最も外側のコンテナーから内側に向かって左から右へ読みます。

1. **プロジェクト** — 表示中の内容を所有するプロジェクト。
2. **オブジェクトタイプ** — ワークフロー、テーブル、ステップ、ディメンション、データエディター。
3. **オブジェクト自体** — 現在のワークフロー、テーブル、ステップなど。この最後のセグメントはすでにいる場所なので、クリックできません。

### パンくずリストでの移動

最初の2つのセグメントのいずれかを選択すると、上の階層に移動できます。

| セグメント | ツールチップ | 動作 |
|---|---|---|
| プロジェクト名 | プロジェクトを開く | そのプロジェクトを開きます。すでに開いている場合は前面に表示します |
| ワークフロー | すべてのワークフローを表示 | プロジェクトをワークフロー一覧で開きます |
| テーブル | すべてのテーブルを表示 | プロジェクトをテーブル一覧で開きます |
| ステップ | すべてのステップを表示 | プロジェクトをステップ一覧で開きます |
| ディメンション | すべてのディメンションを表示 | プロジェクトをディメンション一覧で開きます |
| データエディター | すべてのデータエディターを表示 | プロジェクトをデータエディター一覧で開きます |

タイプのセグメントは、同じ種類の別のオブジェクトに移る近道です。1つのワークフローから1回クリックするだけで、同じプロジェクト内のワークフロー全体の一覧が表示され、別のワークフローをすぐに開けます。

<Aside type="note">
移動元のウィンドウは開いたままです。パンくずリストで移動するとプロジェクトが前面に表示されますが、それまで見ていたウィンドウは閉じられず、画面下部のタブバーから戻ることができます。
</Aside>

### パンくずリストが表示される場所

- **ワークフロー**ウィンドウ — 標準ワークフローのステップグリッド
- **ビジュアルワークフローデザイナー** — 高度なワークフローのキャンバスビュー
- **テーブルエクスプローラー**
- 単独で開かれた**ステップ**ウィンドウ
- **ディメンション**階層ウィンドウ
- **データエディター**ウィンドウ

ステップは複数のワークフローに属することがあるため、ステップのパンくずリストには、所有するワークフローを1つ指定せず、`Project › Step › name` と表示されます。

### キーボードとスクリーンリーダーでの操作

クリックできるセグメントは通常のコントロールです。**Tab**キーでセグメントに移動し、フォーカスのあるセグメントを**Enter**キーまたは**Space**キーで実行できるため、階層をさかのぼるのにマウスは必要ありません。各セグメントはボタンとして読み上げられ、最後のセグメントは現在のページとして読み上げられます。`›` の区切り文字は読み上げられずにスキップされます。

### 未保存の変更があるデータエディターから移動する場合

データエディターは、パンくずリストで移動する前に確認を求める唯一のウィンドウです。編集中の内容がある状態でセグメントを選択すると、**未保存の変更**のプロンプト「*変更を保存せずにデータエディターを閉じますか?*」が表示され、**エディターを閉じる**を選択するとそのまま移動できます。プロンプトをキャンセルすると、変更を保持したままエディターに留まります。

これはエディター自身の**閉じる**ボタンで表示されるものと同じプロンプトなので、作業内容を確認なしに破棄してデータエディターから出る方法はありません。

## 共有可能なリンク

アドレスバーには、常に最前面のウィンドウが示されます。ワークフローを開くとURLがそのワークフローのリンクになり、テーブルを開くとテーブルのリンクになります。このリンクが共有の単位です。

**表示中の内容を共有するには**、ブラウザーのアドレスバーからURLをコピーして送信します。そのプロジェクトにアクセスできるユーザーは、同じビューを開けます。ブックマークしておけば、後からでも使用できます。

### リンクを開いたときの動作

リンクを開いたり更新したりすると、1つのウィンドウだけでなく**親のコンテキスト**も復元されます。ワークフローへのリンクではそのプロジェクトも再び開かれるため、ウィンドウが単独で浮かんだ状態ではなく、自分でそこまで移動した場合と同じように、プロジェクトがタブバーに表示された状態で開きます。

### リンクの形式

リンクはプロジェクトが先頭になる形式で、プロジェクトが最初に来て、その中のオブジェクトが `~` で区切られて続きます。

```
#p~my-project                        a project
#p~my-project~w~<workflow>           a standard workflow
#p~my-project~c~<workflow>           a workflow in the Visual Workflow Designer
#p~my-project~w~<workflow>~s~<step>  a step within a workflow
#p~my-project~t~<table>              a table in the Table Explorer
#p~my-project~d~<dimension>          a dimension hierarchy
#p~my-project~e~<editor>             a Data Editor
#home                                the Home landing page
```

プロジェクトにスキーマ名がある場合はリンクにそれが使用され（上の例では `my-project`）、リンクが読みやすく安定したものになります。ない場合はプロジェクトの識別子が使用されます。どちらの形式でも同じプロジェクトが開きます。

<Aside type="note">
プロジェクトが先頭になる形式より前に作成されたリンクも引き続き動作します。古い `?p=…&t=…` 形式のリンクでも正しいビューが開き、最初に移動した時点でアドレスバーが現在の形式に自動的に更新されます。
</Aside>

### リンクを開けない場合

リンク内のオブジェクトがその後に削除された場合や、そのプロジェクトへのアクセス権がない場合は、エラーにならず、そのビューなしでアプリが開きます。アドレスバーにリンクが表示されているウィンドウを閉じると、URLは所有元のプロジェクトに戻るため、アドレスバーが開いていないものを指し続けることはありません。
