**Operational Transfer Pricing** テンプレートは、テスト対象の当事者ごとの利益水準指標を、ポリシーで定めたレンジに照らしてテストし、レンジ外のエンティティを目標に戻すための調整額（true-up）を算出します。このテンプレートは [Common Finance Model](/ja/guides/projects/data-foundation/) をベースに構築されており、**Enterprise Profitability** が構築するすべてを含みます。

<Aside type="note">
これは、年間を通じてポリシーをモニタリングするための管理ビューです。移転価格の調査報告書や申告書ではありません。
</Aside>

## 仕組み

テンプレートは、エンティティと期間ごとに次の処理を行います。

1. テスト対象の当事者の損益計算書を、エンティティの **現地通貨** で作成します。これは、そのエンティティが帳簿を管理し、調整額を計上する通貨だからです。収益は、会社間取引と第三者に分けられます。
2. 会計年度の年初来で合計します。調整期間はその年の期間として扱われるため、年の最後の行が通年の値になります。
3. エンティティに適用されているポリシーを特定します。
4. 年初来の利益水準指標をパーセントで計算し、レンジと比較します。

## 利益水準指標

エンティティごとに1つの **レンズ** を選択します。

| レンズ | 定義 |
|---|---|
| `ros` | 売上高利益率（ROS）：EBIT ÷ テスト対象当事者の売上高。 |
| `ncp` | ネットコストプラス：EBIT ÷ 総コスト。 |
| `resale_minus` | 再販売価格基準：売上総利益 ÷ 売上高。 |

EBITは、収益から売上原価と営業費用を差し引いたものです。営業外の項目は含まれません。売上高は、利益がそのすべてから得られるため、第三者と会社間取引を合わせたエンティティの収益全体です。

## ポリシーテーブル

レンジは、エンティティとポリシーが有効になる期間ごとに1行ずつ、テーブル `otp_policy_targets` にあります。このテーブルは編集可能で、モデルがこれに書き込むことはありません。

| 列 | 内容 |
|---|---|
| `entity` | テスト対象の当事者。 |
| `role` | 限定リスク販売会社など、その役割のラベル。 |
| `lens` | `ros`、`ncp`、`resale_minus` のいずれか。 |
| `low`、`target`、`high` | レンジと目標（パーセント）。`low <= target <= high`。 |
| `effective_from_period` | 行が有効になる月（`YYYY-MM` 形式）。そのエンティティの次の行までずっと有効です。 |

エンティティに適用されるポリシーは、同時に1つです。レンズやレンジを変更するには、`effective_from_period` が後の新しい行を追加します。サンプルデータには3つのサンプル行があります。ご自身のデータに置き換えてください。

無効な月、空白のレンズ、low、target、high、順序の誤ったレンジなど、判定できない行がある場合は、推測せずに、そのエンティティの結果が **incomplete** になります。

## 結果

結果テーブルには、エンティティと期間ごとに、年初来の指標とステータスが表示されます。

| ステータス | 意味 |
|---|---|
| `in` | レンジ内（境界値を含む）。 |
| `below`、`above` | レンジ外。 |
| `n-a` | 基準となる売上高またはコストが正の値ではありません。 |
| `incomplete` | ポリシーの行に問題があるか、比較に必要なものが不明です。空白が `in` と読まれることはありません。 |

エンティティがレンジ外の場合、`true_up_ytd` は、年初来で目標に達するためにテスト対象の当事者に加算する利益（負の場合は差し引く利益）を現地通貨で示します。`true_up` はその期間での変化額なので、1年の各期間を合計すると年間の調整額になります。調整額はグループ通貨でも示されます。

アシスタントとダッシュボード向けのメトリック：**TP true-up**、**Tested-party EBIT**、**Tested-party sales**、**Third-party sales**、**Intercompany sales**、**Tested-party total cost**、**Return on sales**、**Net cost plus**、および評価別の **CO-PA margin**。

## CO-PAマージン

SAP CO-PAをロードする場合、テンプレートは評価別（法定、グループ、またはプロフィットセンター）のマージンも表示します。評価はそれぞれが独立した数値であるため、評価同士を合算しないでください。CO-PAのファイルは1つの評価を保持し、追加時に確認します。CO-PAファイルのマッピングでは、必ず **Are revenues shown as negative numbers?** が尋ねられます。原価ベースの明細レポートのように、ファイル内のすべての金額が正の場合は、**No, revenues are positive** が自動的に選択されます。それ以外の場合は、確定する前に回答を選択してください。

## プロジェクトを開始する

<Steps>

1. Analyzeで **プロジェクト** を開き、**新規プロジェクト** をクリックします。

2. **開始元** で **Operational Transfer Pricing (template)** を選択します。先に実際の例を見るには、**サンプルデータで開始** にチェックを付けます。

3. ERPを接続して **ロード** を実行します。[Data Foundationを始める](/ja/guides/projects/data-foundation-getting-started/)を参照してください。

4. テスト対象の当事者とレンジに合わせて `otp_policy_targets` を編集し、**Apply changes** をクリックします。

</Steps>

ポリシーテーブルをプロジェクトとともに保存するには、**アクション > Save as my template...** を使用します。[マイテンプレートとして保存する](/ja/guides/projects/data-foundation/#マイテンプレートとして保存する)を参照してください。
