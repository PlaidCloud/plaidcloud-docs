**Data Foundation** は、PlaidCloud プロジェクトのための財務データ基盤です。その **Common Finance Model** は、複数の ERP システム、およびそれぞれの複数のインスタンスの ERP データを 1 つのモデルに統合します。勘定科目表、エンティティのセット、報告通貨はそれぞれ 1 つです。このモデル上に構築されたレポート、メトリック、AI アシスタントは、どの ERP から来たデータであっても、すべて同じ数値を参照します。

ERP は PlaidCloud の接続を通じて接続されるため、総勘定元帳、試算表、マスターデータ、予算はソースから直接取り込まれ、エクスポート作業は不要です。ファイルは、為替レート、配賦ドライバー、ERP の外で管理している予算など、システムが保持していないデータを追加し、対象となる ERP の行を置き換えることもできます。**ロード**は、すべてのソースをモデルに適合させ、報告通貨に換算し、合計が一致することをチェックします。これらはすべてプロジェクトの **Foundation** タブから行います。複数のソースが同じコードを異なる意味で使用している場合は、それらが同じものを指すかどうかを指定します。また、管理連結によって内部取引を消去したグループの損益計算書が作成されます。**企業収益性**などのテンプレートは、その上にレポートやモデルを構築します。

## ERP を接続する

ERP は、PlaidCloud の接続を通じて Data Foundation に接続されます。Data Foundation は、総勘定元帳、試算表、マスターデータ、為替レート、予算をそこから直接読み取り、読み取り以外の操作は一切行いません。既存の接続を選択することも、タブ上で新しい接続を作成することもできます。各システムには、アクセス権を付与する管理者向けのページがあり、[モデルにデータを供給できるシステム](/ja/guides/projects/data-foundation-getting-started/#モデルにデータを供給できるシステム)に一覧があります。また、[Data Foundation カバレッジマトリクス](/ja/reference/data-foundation-coverage-matrix/)には、各システムが直接提供するデータセットが示されています。

<Steps>

1. Analyze で **プロジェクト** を開き、**新規プロジェクト** をクリックします。名前を入力し、**開始元** で **空のプロジェクト** ではなく、**企業収益性(テンプレート)** などのテンプレートを選択します。**作成** をクリックします。

   プロジェクトは **Foundation** タブで開きます。共有するまで、プロジェクトはあなた専用であり、あなたが唯一のアーキテクトです。

2. **Foundation** タブで、ERP の既存の接続を選択するか、**新しい接続を作成** を選択します。既存の各接続には、その接続をすでに使用しているワークフローが一覧表示されるか、**どのワークフローでもまだ使用されていません** と表示されます。

3. 新しい接続の場合は、**接続名** を入力し、**環境** を選択して、ERP 接続で求められる認証情報を入力します。

   まだ認証情報がない場合は、フォームに ERP 管理者向けのアクセス要求文が用意されています。**リクエストをコピー** または **リクエストをメールで送信** をクリックして送信し、返送された値を入力します。

4. **接続をテスト** をクリックします。PlaidCloud はサインインして各データセットの読み取りを試み、それぞれを **読み取り可能**、**権限が不足しています**、**エラー** のいずれかで一覧表示します。不足しているものがある場合は、ERP 管理者に追加を依頼すべき権限が示されます。

5. **履歴の月数** を設定します。何か月前までロードするかを 1 から 120 の範囲で指定します。デフォルトは 24 です。

6. 既存の接続の場合は、ロードするエンティティにチェックを入れるか、すべてのエンティティをロードする場合はすべて未選択のままにします。非アクティブなエンティティと消去用エンティティは、表示を選択するまで非表示になります。次に **接続** をクリックします。

7. 新しい接続の場合は、**接続** をクリックして作成します。次に、ロードするエンティティにチェックを入れ、もう一度 **接続** をクリックして保存します。保存するまでは、すべてのエンティティがロードされます。

8. 別の ERP システムや別のインスタンスを取り込むには、これらの手順を繰り返し、**接続** をクリックする前に **Add this as another source instead of replacing the current one** にチェックを入れます。チェックを入れない場合、新しい接続が現在のソースを置き換えます。

</Steps>

接続が完了すると、カードには、プロジェクトがロードする接続、環境、エンティティ、履歴の月数が表示されます。

各ロードでは、変更された部分だけを読み取ります。未締め期間と直近の締め済み期間は再度読み取られ、ロード済みの締め済み期間はそのまま保持されます。**履歴の月数** を増やすと、追加された月だけが読み取られます。為替レート、エンティティ対応表、報告通貨を変更すると、影響を受ける月が再度読み取られます。

## ソース

プロジェクトがロード元とするすべての ERP システムとインスタンスがソースです。**Foundation** タブの **ソース** 一覧には、ソースごとに 1 行ずつ順番に表示され、名前、最終ロード日時、提供した行数、読み取るレポート用帳簿が示されます。例：`1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`。まだロードされていないソースには **not loaded yet** と表示されます。確定したファイルもソースです。

ソースの使い方を変更するには、そのソースの **高度** を開きます。

| 設定 | 内容 |
|---|---|
| **名前** | レポート、マッピングの質問、メッセージでソースを表すラベルです。 |
| **順序内の位置** | ソースの優先順位です。2 つのソースが同じ会社の同じ月をカバーしている場合は、順序が上位のソースが優先されます。 |
| **レポート用帳簿（カンマ区切り）** | 複数の帳簿を持つシステムで、読み取る会計帳簿です。**すべてのレポート用帳簿** を選択すると、すべての帳簿が読み取られます。 |
| **会社**、**開始 (2026-01)**、**終了 (2026-12)** | 会社ごとにこのソースが提供する月です。制限しない場合は月を空欄にします。月は年と月で指定します（例：`2026-03`）。 |

変更を保持するには **保存** をクリックします。ソースを削除するには、**Remove this source** をクリックし、**削除** で確定します。そのソースからロードされたデータはすべて削除されますが、後で再度接続できます。

ソースを変更しても、ERP は再度読み取られません。**前回のロード** カードには、**変更を適用** をクリックするまで **Changes not applied yet** と表示されます。これをクリックすると、すでに取得済みのデータからロードが実行されます。新しい順序、マッピング、名前、ファイルでソースを再度適合させ、モデルを再構築します。ERP から最新のデータも取得したい場合は、**ロード** をクリックします。

## ERP 外のデータをファイルで追加する

ファイルは、為替レート、配賦ドライバー、[エンティティ対応表](#エンティティ対応表)、ERP の外で管理している予算など、システムが保持していないデータで ERP 接続を補完します。各ファイルは、[Common Finance Model のテーブル](#common-finance-model-のテーブル)に記載されたデータセットのいずれかに属します。

<Steps>

1. **ファイル** で、ファイルを保存する **ドキュメントアカウント** を選択します。

2. CSV または Excel ファイルを **CSV または Excel ファイルをここにドロップ** にドロップするか、**ファイルを選択** をクリックします。ファイルはドキュメントアカウントの `/foundation/` フォルダーにアップロードされます。

   ドキュメントアカウントにすでにあるファイルの場合は、その **ファイルパス**（例：`/foundation/budget.csv`）を入力し、**ファイルを追加** をクリックします。

   毎月新しいファイルを読み取るには、名前が一致するフォルダー内のすべてのファイルを追加します。フォルダーと、**File names that** の条件（含む、で始まる、で終わる、完全一致、パターン一致）を入力し、**Add files** をクリックします。その中のサブフォルダーにあるファイルは読み取られません。

3. PlaidCloud はファイルを読み取り、マッピングを提案します。

   - **検出された区切り文字、小数点の区切り文字、日付。** 区切り文字（カンマ、セミコロン、タブ、パイプ）、小数点の区切り文字、日付形式は自動的に検出されます。
   - **データセット**：ファイルが属する Common Finance Model のテーブルです。ファイル名と列見出しから照合されます。照合結果が明確でない場合は、一覧から選択します。
   - **小数点の区切り文字**：**ピリオド (1,234.56)** または **カンマ (1.234,56)**。
   - **日付形式**：ファイルに日付が含まれる場合に表示されます。検出された形式が誤っている場合は変更します：`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY`、`MM/DD/YYYY`。
   - **ファイル内の列**、**タイプ**、**例**、**対応先** のグリッド。列を別のフィールドに送るには **対応先** を変更し、ロードしない場合は **ロードしない** を選択します。

4. **Which company is this file for?**、**Which currency are the amounts in?**、**Are these amounts year-to-date or for the month?**、**Are the amounts shown in thousands or millions?**、**Are revenues shown as negative numbers?** など、ファイルについての質問に回答します。各質問は、ファイルにその情報がまだ含まれていない場合にのみ表示されます。

5. 各列の対応先を確認し、**マッピングを確定** をクリックします。処理中は、ボタンの下の注記に待機中の理由が表示されます。サンプルデータが残っているプロジェクトでは、最初に確定したファイルによってサンプルも削除されるため、数分かかる場合があります。

</Steps>

ファイルには、該当する場合に次のオプションが表示されます。

| オプション | 用途 |
|---|---|
| **Which source do these rows apply to?** | コードマップファイルを 1 つのソースに限定します。**Every source** を選択すると、すべてのソースに適用されます。 |
| **Where does this file come from?** | ファイルが **This project's own codes** を含むものか、**Another system** から取得したものかを指定します。後者の場合はシステム名を指定します（例：`SAP Germany export`）。別のシステムから取得したファイルは、ERP ソースと同様に共有コードがチェックされます。 |
| **Split … into … parts at each …**（**高度** の下） | `100-200-300` のように複数の値を含む 1 つの列を分割し、各部分をそれぞれのフィールドに送ります。 |
| **Which currency do you report in?** | プロジェクトにまだ報告通貨がない場合に、報告通貨を設定します。3 文字で指定します（例：`USD`）。 |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 連結システムの結果をロードし、グループの損益計算書を[照合](#連結システムとの照合)できるようにします。 |

プロジェクトからファイルを除外するには、**ファイル** でファイルの横にある **削除** をクリックするか、マッピング上の **Remove this file** をクリックして確定します。そのファイルの数値は、次に **変更を適用** をクリックしたときにレポートから除外されます。

データセット、小数点の区切り文字、日付の順序を PlaidCloud が自動的に判断できない場合（たとえば、日付が日/月とも月/日とも読めるファイル）、確定する前に選択するよう求められます。同じデータセットに 2 つ目のファイルを追加すると、最初のファイルが置き換えられます。後から追加したファイルの列がデータセットと一致しない場合、ロードはファイル名と列名を示し、ファイルまたはその列名を修正するか、ステップの **Schema Mismatch** を `union` に設定するよう案内します。

受け付けるファイルは、CSV、TSV、TXT のテキストファイル、Excel の `.xlsx` ファイル（最初のシートから読み取り）、Parquet ファイルです。

<Aside type="note">
ファイルが存在しない、または空であっても、ロードが停止することはありません。そのようなファイルを追加すると、まだマッピングするものがないと表示され、ロードはパスを示す警告とともに完了し、そのデータセットは空のままになります。ファイルが用意できたら、もう一度追加してください。
</Aside>

## データをロードする

**ロード** カードまたは **前回のロード** カードで **ロード** をクリックします。ロードでは、接続された ERP と確定済みのファイルを読み取り、Common Finance Model に適合させ、報告通貨に換算し、準備状況チェックを実行して、テンプレートのモデルを再構築します。

- 1 つのプロジェクトで同時に実行できるロードは 1 つだけです。2 回目の **ロード** または **変更を適用** を行うと、ロードがすでに実行中であることが表示されます。ロードの実行中はソースを変更できません。
- 他のワークフローが同じ ERP 接続を使用している場合、最初のロードでそれらのワークフローが一覧表示され、確認を求められます。ロードは ERP から読み取るため、それらのワークフローの処理が遅くなる可能性があるからです。続行するには **このままロード** をクリックします。
- PlaidCloud のアップグレード後は、アーキテクトが **ロード** を実行すると、プロジェクトの生成済みワークフローも更新され、必要な作業用テーブルが作成されます。それまでは、ステータスページに黄色の項目「The workflows were generated by an earlier release. An Architect's Load updates them.」が表示され、マネージャーが **ロード** を実行すると、更新できるのはアーキテクトのみであるという警告が表示されます。
- 更新を適用しても、生成済みステップに対する独自の編集は保持されます。ステップを変更し、更新でもそのステップが変更された場合は、編集内容が保持され、ステータスページにステップ名とともに競合が記録されます。編集したステップが更新によって生成されなくなった場合、そのステップは保持されますが無効になります。削除するか、まだ必要な場合は再度有効にしてください。更新によって置き換えられるステップは名前が示され、以前のステップはステップのバージョンに残ります。
- 更新が途中で停止した場合や、まだ実行中の場合は、ステータスページにその旨が表示され、完了するまでステップが順不同で実行される可能性があります。完了させるには、アーキテクトとしてもう一度 **ロード** を押します。再び停止する場合は、サポートにお問い合わせください。
- 失敗したロードは赤色で表示され、以前の結果の陰に隠れることはありません。連結が失敗した場合、ステータスには古いグループの結果ではなく、停止したステップが示されます。以前のロードの行には、ロードが成功するまで **以前のロードの結果です。もう一度ロードしてください。** と表示されます。
- 1 つのエンティティと期間の読み取りに失敗しても、残りはロードされます。もう一度 **ロード** を実行すると、失敗した部分のみが取得されます。

### 保留された行

ソースが重複している場合、ロードは各数値のコピーを 1 つだけ保持し、二重計上するのではなく他のコピーを保留します。保留された行は、ソース、エンティティ、理由とともに記録され、ロードはその件数を示す警告とともに完了します（例：`120 rows of NetSuite EU also provided by a source ranked ahead`）。理由は次のとおりです。

| 理由 | 意味 |
|---|---|
| 別の会計帳簿にある | ソースが読み取るよう設定されていないレポート用帳簿に属する行です。 |
| ソースが提供する期間外 | 会社に設定された **開始** と **終了** の月の範囲外にある行です。 |
| 上位のソースでも提供されている | 順序が上位のソースが同じ会社と月をカバーしています。 |
| ソースの以前のファイルにもある | 同じソースの以前のファイルがすでにその月をカバーしています。 |
| ファイルで置き換え済み | ファイルがそのエンティティと月の ERP の行を置き換えます。 |
| 別のソースでも使用されているコードを含む | そのコードには回答が必要です。[ソース間でコードをマッピングする](#ソース間でのコードのマッピング)を参照してください。 |
| 2 つのコードにマッピングされたコードを含む | コードマップがそのコードに 2 つの回答を与えています。 |

統計勘定は、元帳ではなく配賦ドライバーに移動され、問題としてではなく移動済みとして表示されます。

### ERP データとファイルの併用

ファイルは、そのファイルがカバーする範囲だけを置き換え、ERP からの他の行はそのまま残ります。

- **マスターファイル**（勘定科目、部門、顧客、製品、セグメント値）は、同じコードを持つ ERP の行を置き換えます。
- **トランザクションファイル** は、同じエンティティと月の ERP の行を置き換えます。総勘定元帳ファイルと試算表ファイルはさらに元帳で、予算ファイルはシナリオで、統計ドライバーファイルはシナリオとドライバーで照合されます。

後でファイルがある月をカバーしなくなった場合、その月の ERP のデータは次回のロードで復元されます。

## エンティティ対応表

各ソースは、独自のコードでエンティティを識別しています。**エンティティ対応表**は、それらのコードをエンティティマスターのエンティティに対応付けるため、すべてのソースの明細が同じエンティティに集約されます。

対応表を使用するには、CSV または Excel ファイルを追加し、**エンティティ対応表**データセットを選択します。

| 列 | 内容 |
|---|---|
| `source_entity` | 会社コードなど、ソース上のコード。 |
| `entity` | 対応するエンティティ（エンティティマスター上の名前）。 |

- 対応表にないコードは、そのまま使用されます。
- 複数のコードを 1 つのエンティティに対応付けることができます。それらの明細は合算され、ある月はすべてのコードで締め済みになった時点で締め済みとみなされます。
- 対応表のコードはすべてのソースに適用されるため、各ソースのエンティティコードはソース間で一意である必要があります。
- **エンティティ**ファイルの行は、同じエンティティコードを持つ ERP のエンティティを置き換えます。

**未マッピングのエンティティ**チェックは、エンティティがエンティティマスターになく、対応表でもマッピングされていない明細を検出します。エンティティマスターがロードされるまでは **– 対象外**と表示されます。

## ソース間でのコードのマッピング

2 つのソースが同じコードを別の意味で使用していたり、同じものに異なるコードを使用していたりすることがあります。あるコードが複数のソースに現れる場合、Data Foundation は、そのコードがすべてのソースで同じものを意味するかどうかを回答するまでその行を保留し、各金額が 1 回だけ計上されるようにします。**回答待ちのコード** チェックには、該当するコードが最初の 10 件と「and K more」の形式で一覧表示され、**Foundation** タブの **次に行うこと** カードには**確認**ボタンが表示されます。

**確認**をクリックすると **回答待ちのコード** が開きます。コードは種類ごとに、**アカウントタイプ**、**会社**、**勘定科目**、**部門**、**プロフィットセンター**、**顧客**、**製品**、および各追加カテゴリーにグループ化されます。各コードについて、各ソースでの呼び名と提案が表示されます。

- ソースがそのコードに同じ名前を付けている場合は **Looks like the same thing**。
- 名前が異なる場合は **Looks like different things**。
- 判断材料がない場合は **We can't tell. Please answer.** と表示されます。

コードごとに **Yes, the same** または **No, different** で回答するか、**Accept all**（すべての提案を採用）、**All the same**、**All different** でグループ全体に一括で回答します。勘定科目の場合は、勘定科目表の親グループ単位で一括回答することもできます。ソースにアカウントタイプがない場合は、勘定科目のグループに対して **Use this type** を選択し、**収益**、**売上原価**、**営業費用**、**営業外損益**、**資産**、**負債**、**純資産**のいずれかを指定します。

マッピングはソースとディメンションごとに保持されるため、あるソースの部門に対する回答が別のソースの勘定科目に影響することはありません。回答は入力のたびに保存され、**Saved. Press Apply changes to use your answers.** というメッセージが表示されます。回答を使用するには **変更を適用** をクリックします。

マッピングはファイルで指定することもできます。**Code map** データセットのファイルを追加し、**Which source do these rows apply to?** 欄で対象を 1 つのソースに限定します。

## どのソースをいつから採用するかを選択

2 つのソースが同じ月のデータを提供している場合は、**どのソースがどの月をカバーするか** チェックで選択を求められます。**次に行うこと** カードの **どのソースをいつから使用するかを選択** をクリックすると **Which source counts from when** が開き、重複が会社ごとに一覧表示されます。採用するソースを選び、採用を開始する月を **That month is** に入力して（例: `2026-04`）、**変更を適用** をクリックします。それより前の月には、もう一方のソースが使用されます。

同じダイアログでは、2 つのソースがある通貨に対して異なる為替レートを持っている場合にも警告が表示されます。その場合は、順序が上位のソースのレートが使用されます。

## 通貨換算

ロードのたびに、総勘定元帳、試算表、売上、在庫、予算の金額が現地通貨から 1 つの報告通貨に換算されます。レポートやモデルは換算後の金額を読み取るため、どのシステムのデータであっても、通貨の異なるエンティティを正しく合計できます。

### 報告通貨

報告通貨を選択するには、プロジェクト変数 `reporting_currency` に `USD` などの通貨コードを設定します。[プロジェクト変数の管理](/ja/guides/projects/managing-projects/#プロジェクト変数の管理)を参照してください。この変数はテンプレートによって空の状態で作成されます。空の間は、各ロードで次のうち通貨が 1 つに定まる最初のものが使用されます。

1. エンティティのグループ通貨。
2. 最上位エンティティ（親を持たないエンティティ）の現地通貨。
3. ファイルの現地通貨。

いずれでも通貨が 1 つに定まらない場合、`reporting_currency` を設定するまで**通貨換算**に問題が表示されます。

すでに報告通貨で計上されている金額はそのまま使用されるため、すべてのデータが単一通貨のプロジェクトでは為替レートは不要です。

売上、在庫、予算のファイルにも通貨を含めることができます。`Currency` または `Local Currency` という名前の列をマッピングすると自動的に認識され、ファイルの現地通貨金額が報告通貨に換算されます。ファイルにすでに含まれているグループ金額や報告金額はそのまま保持されます。製品の標準原価は換算されません。

### 為替レート

為替レートは、ある月について、ある通貨の 1 単位を報告通貨に換算する値です。換算後の金額は、現地通貨金額に為替レートを掛けたものです。

- **ERP から**: 各ロードで、ERP が保持している為替レートを読み取ります。
- **ファイルから**: CSV または Excel ファイルを追加し、**為替レート**データセットを選択します。ファイルのレートは、同じ通貨と月の ERP のレートを置き換えます。ERP がレートを公開していない通貨で報告する場合や、予算月の計画レートを追加する場合はファイルを使用します。

| 列 | 内容 |
|---|---|
| `from_currency` | 換算元の通貨（例: `EUR`）。 |
| `to_currency` | 報告通貨（例: `USD`）。 |
| `period` | 月（`YYYY-MM` 形式）。 |
| `average_rate` | その月の平均レート。 |
| `closing_rate` | 月末時点のレート。 |
| `historical_rate` | 純資産、および取得時レートが設定された勘定科目に使用する取得時レート。 |

ある通貨に報告通貨へのレートがない場合は、逆方向（報告通貨からその通貨へ）のレートの逆数が、小数点以下 12 桁で使用されます。それもない場合は、その通貨から別の通貨へのレートに、その別の通貨から報告通貨へのレートを掛けた値が使用されます。

### 適用されるレート

各行はその行自体の通貨から換算されるため、エンティティとは異なる通貨の明細は、その明細の通貨から換算されます。行に当てはまる最初のルールが適用されます。

| 行 | レート |
|---|---|
| 統計勘定および非転記勘定 | 換算されません。 |
| すでに報告通貨で計上されている行 | 換算されません。 |
| レートタイプを持つ勘定科目 | そのレート（平均、期末、取得時）。取得時レートがない場合は期末レートが使用されます。ERP の場合、レートタイプは勘定科目自体のレートタイプです。勘定科目表ファイルの場合は、レートタイプの列を `fx_rate_type` にマッピングし、`average`、`closing`、`historical` のいずれかを指定します。 |
| 売上明細 | 期間の平均レート。 |
| 在庫残高 | 期間の期末レート。 |
| 予算行 | 総勘定元帳と同様に勘定科目に応じて決まります。損益計算書の勘定科目には平均レート、貸借対照表の勘定科目には期末レートが使用されます。 |
| 損益計算書の勘定科目 | 期間の平均レート。 |
| 純資産の勘定科目 | 取得時レート。取得時レートがない場合は期末レート。 |
| その他の貸借対照表の勘定科目 | 期間の期末レート。 |

換算後の金額は丸められないため、合計にずれが生じません。

<Aside type="note">
試算表は各期間の増減を保持するため、貸借対照表の金額は、各月の増減をその月の期末レートで換算したものになります。期末レートで再換算した貸借対照表ではなく、為替換算調整勘定や内部取引消去も含まれません。換算後の金額は損益計算書に使用してください。
</Aside>

## 階層

ロードのたびに、すべてのソースのマスターデータからディメンションが再構築されます。最初は 7 つのディメンションがあり、最大 10 個の追加カテゴリーを利用できます。

| ディメンション | 構築元 |
|---|---|
| **エンティティ** | エンティティとその親 |
| **勘定科目** | 勘定科目表と親勘定科目 |
| **部門** | 部門とその親 |
| **顧客** | 顧客とその親顧客 |
| **製品** | 製品とその親製品 |
| **セグメント1** | `segment_1` のセグメント値 |
| **セグメント2** | `segment_2` のセグメント値 |
| **セグメント3**～**セグメント10** | `segment_3`～`segment_10` のセグメント値（ソースに含まれる場合） |

- 親を持たないレコード、または自身を親として指定しているレコードは、最上位メンバーとしてロードされます。
- 階層はロードのたびに再構築されるため、親を変更する場合はディメンションではなく ERP またはファイルで変更してください。
- ある階層の問題は、そのディメンションにのみ影響します。ロードとテンプレートのモデルは引き続き完了します。
- 各追加カテゴリーの名前は、その内容に合わせて変更できます（例: **クラス**、**リージョン**）。**Rename extra categories** で、レポートで使用する名前を入力し、**Save names** をクリックします。名前には英字、数字、スペース、ピリオド、ハイフン、アンダースコアを使用でき、最大 60 文字です。
- 各ソースでは、そのソース独自の追加カテゴリーを、どのカテゴリー名の下に配置するかを指定します。ソースの**高度**を開き、それぞれの名前を選択するか **Leave out** を選択して、**保存**をクリックします。これにより、`Class` と `Business area` のように異なる名前でカテゴリーを呼んでいるソース同士が、1 つの枠を共有します。

セグメント階層をファイルで指定するには、**セグメント値**データセットを選択します。

| 列 | 内容 |
|---|---|
| `segment` | 値が属するセグメント（`segment_1`～`segment_10`）。 |
| `segment_value` | 総勘定元帳、売上、予算の明細上の値。 |
| `segment_value_name` | 値の名前。 |
| `parent_segment_value` | 同じセグメント内での親。 |

## 準備状況チェック

ロードのたびに、**準備状況**グリッドに、すべてのエンティティと期間についてのすべてのチェックが、次のいずれかのステータスとともに一覧表示されます。

| ステータス | 意味 |
|---|---|
| **● 準備完了** | チェックに合格しました。 |
| **▲ 要確認** | 確認をお勧めしますが、数値は使用できます。 |
| **■ 問題** | 結果を利用する前に修正してください。 |
| **– 対象外** | このチェックの対象となるデータがまだありません。 |

チェックは次のとおりです。

| チェック | 確認内容 |
|---|---|
| **ロード済みデータ** | すべての会計期間に総勘定元帳の明細があり、すべての ERP の読み取りが成功したこと。明細のない締め済み期間は問題となり、明細のない未締め期間は要確認となります。 |
| **試算表と総勘定元帳の一致** | エンティティ、期間、勘定科目ごとに、試算表が総勘定元帳と一致すること。ある勘定科目について試算表と総勘定元帳の両方に部門がある場合は、部門ごとの一致も確認します。 |
| **売上と総勘定元帳の一致** | 期間ごとに、売上明細が総勘定元帳の収益および売上原価の勘定科目と一致すること。 |
| **不明な製品/顧客** | すべての売上明細の製品と顧客が、製品マスターと顧客マスターに存在すること。 |
| **勘定科目表にない勘定科目** | すべての総勘定元帳の明細の勘定科目が、勘定科目表に存在すること。不明な勘定科目の明細は損益計算書から除外されます。転記があるのにアカウントタイプのない勘定科目も問題となり、勘定科目表で収益勘定にはタイプがあるのに売上原価の勘定科目がないソースは要確認となります。 |
| **通貨換算** | 総勘定元帳、試算表、売上、在庫、予算のすべての行に報告通貨の金額があること。損益計算書は換算後の金額を読み取るため、レートのない損益計算書または売上の行は問題となります。レートのない貸借対照表、在庫、予算の行は要確認となります。まだレートのない予算月は黄色で表示されるため、予算月の計画レートをロードしてください。[通貨換算](#通貨換算)を参照してください。 |
| **未マッピングのエンティティ** | すべての総勘定元帳、試算表、売上の明細のエンティティが、直接またはエンティティ対応表を通じて、エンティティマスターに存在すること。エンティティマスターがロードされるまでは対象外です。[エンティティ対応表](#エンティティ対応表)を参照してください。 |

複数のソースを含むロードでは、次のチェックが追加されます。

| チェック | 確認内容 |
|---|---|
| **報告用帳簿** | エンティティについて複数の会計帳簿を持つソースで、報告用の帳簿が選択されていること。選択するまでは、最初の帳簿のみが計上されます。 |
| **回答待ちのコード** | 複数のソースで使用されているすべてのコードに回答済みであること。[ソース間でのコードのマッピング](#ソース間でのコードのマッピング)を参照してください。 |
| **ソースの追加カテゴリー** | ソースに含まれるすべての追加カテゴリーに名前が付けられているか、除外されていること。 |
| **どのソースがどの月をカバーするか** | どちらを採用するかを選択していない限り、2 つのソースが同じ会社の同じ月を提供していないこと。 |
| **アカウントタイプと階層** | ディメンションで指定されたすべての親が存在し、自身の親または祖先となっているメンバーがないこと。親が存在しない場合、その子は階層の最上位に配置され、循環がある場合はその階層がロードされません。合計には影響しません。 |
| **会計カレンダー** | 各エンティティの会計期間が暦月であり、各月の行をいずれか 1 つの会計期間に割り当てられること。エンティティの期間が暦月でない場合（4-4-5、13 期間）、ある月の行が複数の会計期間に該当し得る場合、または会計カレンダーにその月がない場合は要確認となります。 |

準備完了でない各行の**対応**列には、勘定科目表のロード、為替レートのロード、期間に対する**ロード**の再実行など、必要な対応が表示されます。

グリッドには 2 つのセットアップチェックも表示されます。これらは要確認の場合にのみ表示されます。

| チェック | 表示される条件 |
|---|---|
| **間接費の配賦** | プロジェクト変数 `overhead_department` と `overhead_driver` の一方のみが設定されている場合、または `overhead_driver` に一致する配賦ドライバーがない場合。この状態では配賦は何も行いません。両方を設定するか、両方をクリアして間接費の配賦を無効にしてください。 |
| **予算比較** | 予算行はロードされているものの、プロジェクト変数 `budget_version` で指定されたバージョンの行がなく、予算比較が空になる場合。 |

## 管理連結

ロードのたびに管理連結が構築されます。これは、グループ内のすべてのエンティティのグループ損益計算書を、内部取引を消去したうえで報告通貨で表したものです。管理会計レポートを目的としています。法定上のグループについては、引き続き連結システムが正式な記録となります。後述の手順で連結システムと照合してください。

<Aside type="note">
管理連結の対象は損益計算書のみです。法定連結や法的連結ではなく、連結貸借対照表、為替換算調整勘定、のれん、非支配持分は含まれません。
</Aside>

### グループの選択

**ソース**で**グループ**を開くと、グループに含まれる会社が表示されます。選択を解除した会社は、単独ではレポートに残りますが、グループ合計からは除外されます。**Save group** をクリックします。変更は次回の**ロード**または **変更を適用** で適用されます。新しい会社は、選択を解除するまでグループに含まれます。

グループの会計年度は、プロジェクト変数 `group_fy_start_month` で設定した月に始まります。変更しない限り、値は `1` です。

### 生成される内容

| テーブル | 内容 |
|---|---|
| **グループ損益計算書** | エンティティ、期間、項目（収益、売上原価、営業費用、営業外、内部取引差異）ごとに 1 行ずつ、報告通貨で表したもの。収益と費用は本来の符号のまま保持されます。 |
| **グループ損益計算書（年初来）** | 上記と同じ内容を、グループで最後にすべてロードされた期間までの年初来で表したもの。 |
| **内部取引ペア** | エンティティのペア、グループ、期間ごとに 1 行ずつ、各側の金額と残差を示したもの。 |
| **内部取引明細** | グループの数値またはペアの基になっている元帳の明細と、その取引相手。 |
| **照合** | グループ損益計算書（年初来）と連結システムとの比較。 |

これらのテーブルには、3 つのエンティティ名が表示されます。

| エンティティ | 意味 |
|---|---|
| **Eliminations** | 内部取引消去。合計するとゼロになるため、グループの数値ではそのまま含め、消去前のエンティティの合計を求める場合はフィルターで除外します。 |
| **Group total** | 照合における連結システムの合計。 |
| **Unmapped** | 期間のない明細、およびこのプロジェクトにない連結システムの勘定科目やエンティティ。 |

メトリック **Consolidated income**、**Consolidated result**、**IC difference**、および各テーブルの分析パスを使用して、グループに関する質問に回答できます。

### 内部取引消去

内部取引の明細は、取引相手によって照合されます。明細上の取引相手が使用され、明細に取引相手がない場合は、その顧客の取引相手が使用されます。ペアの両側が消去され、両側の金額の不一致分は内部取引差異の項目に計上されます。各ペアには理由が付けられます。

| 理由 | 意味 |
|---|---|
| **一致** | 両側が同じ金額を計上しています。 |
| **片側のみ計上** | 一方のエンティティが取引を計上し、取引相手は計上していません。 |
| **未消去** | ペアの明細に為替レートがないため、どちらの側も消去されません。 |

ペアは年初来の金額で判定されます。**Intercompany balances** 行は、ペアの差異がプロジェクト変数 `group_amber`（デフォルトは `1`）を超えると黄色に、`group_red`（デフォルトは `1000`）を超えると赤色になります。取引相手のない明細や、取引相手がエンティティでない明細は消去されず、この行で集計されます。取引相手を持つソースと持たないソースが混在している場合は黄色で表示されます。

ソース独自の消去用エンティティはグループ損益計算書から除外され、**連結**行にその旨が表示されます。

### 連結システムとの照合

連結システムが報告する結果をファイルとして追加し、マッピングを確定するときに **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** チェックボックスをオンにします。**Which version of the numbers is this?** にはシステムの名前を入力します。これにより、**照合**テーブルに、エンティティと項目ごとの年初来の**当方**、**報告値**、**差異**が表示されます。差異は通常、**Eliminations**、**Group total**、**Unmapped** の各行、またはシステムで使用している為替レートによって説明できます。**Reconciliation to the source** 行には、`group_amber` を超えるすべての明細が一覧表示されます。

### 閲覧できるユーザー

グループの結果には、プロジェクトの行アクセスが適用されます。行アクセスによってグループの結果が表示されない場合、ステータスは黄色で表示されます。一部のエンティティのみを閲覧できるユーザーには、それらのエンティティの消去前の合計が表示されます。**Eliminations** 行と内部取引のテーブルを閲覧するには、すべてのエンティティへのアクセス権が必要です。

部門など、グループのテーブルに含まれない列によって閲覧できる行をプロジェクトで制限している場合、グループの結果は全員に対して無効になり、**連結**に **Group views are off** と表示されます。その場合、**グループ**で **Everyone on the project may see the group results** をオンにできるのはアーキテクトのみです。変更は次回の**ロード**または **変更を適用** で適用されます。

## 最新の状態を保つ

ERP 接続からのロードが問題なく成功すると、**前回のロード**カードに**夜間に更新**が表示されます。これをクリックすると、毎晩お使いのタイムゾーンの 2:00 に**ロード**が実行されます。その後、カードには **Nightly refresh: Every night at 2:00** と、設定したユーザーが表示されます。

夜間のロードは、設定したユーザーとして実行されます。そのユーザーが ERP 接続を使用できなくなった場合、グリッドに夜間のロードがスキップされたことが表示されるので、もう一度設定してください。サンプルデータしかないプロジェクトはスケジュールできません。

夜間のロードでファイルが見つからないか空の場合、エラーではなく、そのパスを示す警告付きで完了し、モデルの残りの部分は引き続きロードされます。

## ビジネス名

**Foundation** タブの **Business names** では、モデル内のコードに、ビジネスで使用している名前を付けます。レポート、メトリック、アシスタントはこれらの名前を表示し、保存した名前はすぐに適用されます。以降のロードでもその名前は保持されます。

1. **Add a name** をクリックし、**種類**として**カテゴリー**、**損益計算書の行**、**メトリック**、**列**のいずれかを選択します。
2. **コード**を入力します。カテゴリーの場合は `segment_1` ～ `segment_10`、損益計算書の行の場合はその行のキー、メトリックの場合はメトリック名、列の場合は `table.column` です。
3. **名前**を、1 行で最大 60 文字で入力します。
4. **Save names** をクリックします。

保存すると、リスト全体が置き換えられます。名前が空の行はその名前を削除し、**選択項目を削除**はチェックを付けた行を削除します。同じコードに 2 回名前を付けることはできません。ビジネス名は分析パスの説明にも書き込まれるため、アシスタントはお客様の言葉を使用します。この説明には長さの制限があり、名前によって説明が長くなりすぎる場合は何も保存されず、その旨が通知されます。

## 数値の説明

**Explain this number** は、損益計算書の 1 つの数値の内訳を表示します。**準備状況**グリッドでは、エンティティと月の行に **Explain this number** があり、その月のエンティティの営業利益を開きます。ウィンドウでは、数値が上部の合計に積み上がるレイヤーに分割されます。

| レイヤー | 内容 |
|---|---|
| **From the general ledger** | 元帳がその行に転記した金額。 |
| **Allocated in** | [配賦ルール](#配賦ルール)によってこのエンティティに配分されたコスト。 |
| **Allocated out** | このエンティティが他に配分したコスト。 |
| **Eliminated in the group** | グループの結果で消去された内部取引。 |

各レイヤーには、その内容を説明する文と、最大のソース伝票が、ソースシステム、伝票、勘定科目とともに表示されます。行があるレイヤーのみが表示されます。ウィンドウは行アクセスに従うため、説明できるのは閲覧できる数値のみです。裏付けのない数値には **Nothing to explain** と表示されます。

## 配賦ルール

配賦は、間接費などの共通コストを部門、製品、顧客に配分します。モデルには **Stage 1: overhead to departments** と **Stage 2: departments to products and customers** の 2 つのステージがあります。それぞれの方法を確認または変更するには、**アクション > 配賦...** メニューを開きます。変更しない場合、ウィザードが導入される前と同じように動作します。閲覧者はルールを開くことはできますが、保存はできません。

ウィザードは、ステージごとに 4 つの質問をします。

| ステップ | 質問 | 選択肢 |
|---|---|---|
| **プール** | どのコストを配分しますか？ | 勘定科目の種類と、ステージ 1 ではコストを保持する部門、または **All departments**。 |
| **ドライバー** | 何を基準に配分しますか？ | 配賦ドライバーとしてロードした **Statistic**（人員数や平方フィートなど）、**Net sales amount**、**Sales quantity**、または **Spread evenly**。**Same period** または **Same period last year** のドライバーを使用します。 |
| **ターゲット** | どこに配分されますか？ | ステージ 1：部門。ステージ 2：製品、顧客、またはその両方。 |
| **メソッド** | ドライバーが負の場合はどうしますか？ | **Ignore negative values** または **Stop and tell me**。 |

ステップの下にある **Preview for** で月を `2026-09` のように年と月で指定すると、保存していないルールも含め、ルールによって何が行われるかが表示されます（`Pool 120,000 · Allocated 120,000 · Unallocated 0`）。未配賦の金額は、受け取るドライバーがなかったコストです。プレビューは行アクセスに従います。

**保存**をクリックします。ルールは次回の**ロード**時、または**変更を適用**をクリックしたときに有効になります。配賦ステップを手動で編集していた場合、その編集は上書きされずに保持され、保存時にそのステップ名が示されます。ロードの実行中は保存できません。

## 取締役会資料

取締役会資料は、結果をドキュメントアカウントのフォルダーに書き出し、すぐに送付できる状態にします。**アクション > 取締役会資料...** メニューを開き、**ドキュメントアカウント**と、`/board-packs` などの**フォルダー**を選択して、**保存**をクリックします。以降は**ロード**のたびに資料が作成されるため、フォルダー内のファイルは前回のロード時点で最新の状態になります。各実行では次のものが書き出されます。

- エンティティ別の損益計算書、利益ブリッジ、上位および下位の顧客を含む Excel ブック `Board pack.xlsx`。
- 損益計算書ダッシュボードの PDF。

すぐに資料を作成するには **Run now** をクリックします。完了すると、ファイルがフォルダーに表示されます。ダイアログには、前回の実行とその結果、および次回の実行が表示されます。**変更を適用**では資料は作成されません。毎晩作成するには、夜間更新を設定してください（[最新の状態を保つ](#最新の状態を保つ)を参照）。設定するまでは、ダイアログに **Not scheduled yet** と表示されます。設定できるのは、プロジェクトを変更できるユーザーのみです。

資料を完全に作成できない場合でも、ロードが失敗することはありません。

- ワークスペースでレポート機能がオフになっている場合、資料は Excel ブックのみとなり、実行結果に **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.** メッセージが表示されます。
- Data Foundation が損益計算書ダッシュボードに必要とするアドレスを、他のユーザーが作成したダッシュボードがすでに使用している場合、そのダッシュボードはそのまま残され、PDF は作成されません。メッセージにそのアドレスが示されるので、もう一方のダッシュボードに別のアドレスを付けてから、もう一度**ロード**を実行してください。
- 資料のいずれかのステップが失敗した場合、**ステータス**リストに、そのステップと理由を示す黄色の**取締役会資料**行が表示されます。ロード自体は成功しています。

## 復元ポイント

復元ポイントは、**ロード**または**変更を適用**が開始されるたびに（開始したユーザーにかかわらず、スケジュールされたロードも含む）、およびマッピングやソースを変更する前に作成されます。復元ポイントには、モデルのテーブル、ディメンション、および次回のロードの基になる設定（ソース、ファイル、配賦ルール）が保持されます。ロード時に作成された直近 7 つのポイントと、変更前に作成された直近 5 つのポイントが保持されるため、変更によってロード時のポイントが押し出されることはありません。それより古いポイントは順に削除されます。

元に戻すには、**アクション > 復元...** メニューを開きます。各ポイントには作成日時が表示され、その下に、復元によって戻るテーブルの数（例：**Puts back 12 tables.**）と警告が表示されます。ポイントを選択して**復元**をクリックします。**復元**は、ポイントが存在するようになると利用できます。復元では、まず現在のプロジェクトの状態が独自のポイントとして記録されるため、再び元に戻すことができます。その後、テーブル、ディメンション、および上記の設定が以前の状態に戻され、次回のロードはそれらに基づいて行われます。すでに使用していたソースに復元しても、ソースは変更済みとしてマークされません。ビュー、保存できないディメンション、または保存済みのコピーがないテーブルは警告で示され、それ以外は復元されます。削除済みの復元ポイントへの復元は拒否されます。また、ロードの実行中は復元できません。

## プロジェクトの複製

**アクション > 複製...** メニューでは、指定した名前でプロジェクトをコピーします。コピーには、テンプレート、モデルへの編集内容、メトリックと分析パスが保持され、サンプルデータがロードされます。ソースは接続されていないため、ロードする前にコピー先でソースを接続してください。コピーの作成中も作業を続けることができ、準備ができたら**プロジェクトを開く**でコピーに移動できます。

## マイテンプレートとして保存

プロジェクトのセットアップを保存して、次のクライアントやエンティティで再利用できます。**アクション > マイテンプレートとして保存...** メニューを開き、ドキュメントアカウントを選択して、ファイルに名前を付けます。名前の末尾に `.zip` を付けなかった場合は自動的に追加されます。既存のファイルへの上書き保存は拒否されるため、別の名前を選択してください。

このファイルには、プロジェクトの構造、モデルへの編集内容、メトリックと分析パス、エンティティと勘定科目のビジネス名、およびテンプレートの構成テーブルの行（[サービス提供コスト](/ja/guides/projects/cost-to-serve/)のアクティビティマップや[業務移転価格](/ja/guides/projects/operational-transfer-pricing/)のポリシー範囲など）が保持されます。接続、ファイル、夜間スケジュール、実行、復元ポイント、取締役会資料、およびアクセス権を持つユーザーは含まれません。

使用するには、プロジェクトを作成し、**開始元**で **From a template file...** オプションを選択して、ドキュメントアカウントとパスを指定します。新しいプロジェクトは自分専用で、すべてのソースは接続待ちの状態です。後でテンプレートのリリースが行われると、編集したステップを避けて変更がマージされます。パスにファイルがない場合は何も作成されず、その旨が通知されます。ドキュメントアカウントを読み取れるユーザーであれば誰でも、このファイルからインストールできます。別のワークスペースで使用するには、ファイルをダウンロードしてそのワークスペースにアップロードしてください。

## Ask で未解決の質問を解決する

ロード後も、プロジェクトには回答を待っている事項が 3 つ残っている場合があります。勘定科目表でタイプが指定されていない勘定科目、複数のソースで使用されているコード、およびファイル内でどれとも一致しなかった列です。これらの解決をアシスタントに依頼できます。MCP 経由の AI アシスタントから、**Resolve Data Foundation residue** プロンプトを使用してください。アシスタントは待機中の事項を読み取り、項目ごとに理由を添えて 1 つの回答を提案します。

アシスタントは何も書き込みません。提案された回答は、自分で回答する場合と同じ場所で適用します。勘定科目とコードは**回答待ちのコード**で、ファイルの列はそのファイルのマッピングで適用します。アシスタントがエンティティを提案することはありません。

## プロジェクトの引き継ぎ

**セットアップ**チェックリストには、**階層を確認**の後に 4 つの締めくくりの項目があります。

- **夜間更新を設定**は、**夜間に更新**がオンになると完了します。
- **チームと共有**は、プロジェクトを設定したユーザー以外の誰かがメンバーになると完了します。
- **エビデンスパックをダウンロード**は、前回の成功したロードの後にパックをダウンロードすると完了します。
- **プロジェクトをオーナーに引き継ぐ**は、プロジェクトを設定したユーザー以外のアーキテクトが存在し、合計が一致すると完了します。完了していない間は、チェックリストに対応方法が表示されます。クライアントのオーナーをこのプロジェクトのアーキテクトにしてから、自分をメンバーから削除してください。

チェックリストには、プロジェクトを設定したユーザー（**Set up by**）が表示されます。

## テンプレートでモデルを拡張する

テンプレートは、レポートとモデルを Common Finance Model 上に構築するため、どの ERP からデータが供給されても同じように動作します。**企業収益性**などのテンプレートからプロジェクトを開始すると、次のものが作成されます。

- 空の、またはサンプルデータが入った [Common Finance Model のテーブル](#common-finance-model-のテーブル)。
- これらのテーブルから構築された**エンティティ**、**勘定科目**、**部門**、**顧客**、**製品**、**セグメント 1**、**セグメント 2** の各ディメンション。[階層](#階層)を参照してください。
- **ロード**ワークフローと、それが実行するワークフロー。これらは ERP とファイルを読み取り、適合させ、準備状況をチェックし、テンプレートのモデルを構築します。
- テンプレート独自のレポートとモデル。**企業収益性**は、収益、売上原価、売上総利益、直接および間接の営業費用、貢献利益、営業利益を含む損益計算書テーブルに加えて、前年比および予算比の利益ブリッジを追加します。
- 結果について質問するためのメトリックと分析パス。

**開始元**では 3 つのテンプレートを利用でき、いずれも同じモデル上に構築されます。

| テンプレート | 追加される内容 |
|---|---|
| **企業収益性** | 損益計算書と利益ブリッジ。 |
| **サービス提供コスト** | 各顧客へのサービス提供にかかるコストと、それを差し引いた後の利益。[サービス提供コスト](/ja/guides/projects/cost-to-serve/)を参照してください。 |
| **業務移転価格** | ポリシー範囲に対する各エンティティの利益水準と、その調整。[業務移転価格](/ja/guides/projects/operational-transfer-pricing/)を参照してください。 |

**From a template file...** オプションは、保存したプロジェクトから開始します。[マイテンプレートとして保存](#マイテンプレートとして保存)を参照してください。

独自の ERP を接続する前に試してみるには、プロジェクトの作成時に**サンプルデータで開始**にチェックを付けます。プロジェクトはすぐに最初のロードを実行するため、**Foundation** タブには、米ドルに換算されたユーロのエンティティを含む完全な例が表示されます。独自の ERP を接続するか独自のファイルを追加すると、サンプルは削除され、お客様のデータに置き換わります。削除が中断された場合は、次回の**ロード**で完了します。`sample` という名前の独自のフォルダーは削除されません。ステータスページに、サンプルがそのフォルダーを使用しているためそのフォルダー内の他のテーブルは読み取られないことが示され、それらを別の名前のフォルダーに移動するよう求められます。

## Foundation タブ

**Foundation** タブでは、データの接続、ロード、チェックを行います。左側のレールには 4 つのページが表示されます。

| ページ | 表示内容 |
|---|---|
| **ステータス** | プロジェクトの状態。**ロード**、**変更を適用**、**更新**、**夜間に更新**の各ボタンを含む**前回のロード**、**次に行うこと**、**セットアップ**チェックリスト、**ロード済みデータ**、**期間**、**準備状況**、および**アクション**メニュー。 |
| **回答が必要** | 回答を待っている質問。たとえば、複数のソースで使用されているコードについて、同じものを意味するかどうかを指定します。 |
| **ソースのカバレッジ** | 会社と月について、ソースが重複している箇所や欠けている箇所、およびどのソースをいつから使用するか。 |
| **ソース** | 各ソースを順番に、**高度**、**このソースを削除**、**グループ**、**追加カテゴリーの名前を変更**とともに表示し、**接続**では ERP を接続して、エンティティとロードする履歴の月数を選択するか、ファイルを追加します。 |

レール上のバッジは、対応が必要な項目の数を示します。**回答が必要**では未解決の質問、**ソースのカバレッジ**ではカバレッジの問題、**ソース**ではソースの数です。**ステータス**にはバッジは表示されません。**ロード**または**変更を適用**の結果とステータスバナーは、開いているページの上部に表示されるため、どのページでも確認できます。**ステータス**上の、質問やカバレッジの問題を指すボタン（**確認**など）をクリックすると、そのページに移動します。**回答が必要**または**ソースのカバレッジ**を閉じると、**ステータス**に戻ります。

**セットアップ**チェックリストは、**データを接続**、**データをロード**、**合計が一致することを確認**、**階層を確認**、**夜間更新を設定**、**チームと共有**、**エビデンスパックをダウンロード**、**プロジェクトをオーナーに引き継ぐ**で構成されます。現在の項目は太字で表示されます。ビジネス名、追加したファイルとそのマッピングの状態（**✓ 確認済み** または **○ 確認待ち**）、およびエンティティ、期間、チェックごとに 1 行ずつ表示され、**対応**を含む準備状況グリッドも同じページにあります。[ビジネス名](#ビジネス名)を参照してください。

ロードの実行中、タブは自動的に更新され、1 回の読み取りが失敗しても読み取りを続けます。ステータスを読み取れない場合は、**Foundation のステータスを読み取れませんでした。** というメッセージが**再試行**とともに表示され、これをクリックすると改めて読み取ります。タブはメッセージを表示する前に自動的に 1 回再試行し、サーバーが応答するとメッセージは消えます。

**ステータス**ページには、次の注記も表示されます。

- テーブルに必要な列がない `/sources/` 配下のフォルダーは、ソースとして追加されません。注記には、除外された各テーブルと不足している列が示されます。列を追加してから、**ロード**または**変更を適用**を押してください。
- ロードは成功したものの、比較する元帳の明細が取り込まれなかった場合、黄色の**モデルの損益計算書と総勘定元帳の一致**行に、一致したものがないことが表示されます。何かが一致するまで、セットアップチェックリストの**合計が一致することを確認**は完了にならず、保留のままです。元帳の明細を含むソースを追加してから、**ロード**を押してください。

セットアップチェックリストで進捗を確認できます。

- **データを接続**と**データをロード**は、ソースが接続され、ロードが成功すると自動的にチェックが付きます。
- **合計が一致することを確認**は、一致チェックに合格すると自動的にチェックが付きます。
- **階層を確認**：**ディメンションを開く**をクリックしてエンティティ、勘定科目、部門の階層を確認し、**確認しました**にチェックを付けます。これはご自身で確認してください。
- **夜間更新を設定**、**チームと共有**、**エビデンスパックをダウンロード**、**プロジェクトをオーナーに引き継ぐ**でリストが完了します。[プロジェクトの引き継ぎ](#プロジェクトの引き継ぎ)と[プロジェクトアクセスの管理](/ja/guides/projects/managing-projects/#プロジェクトアクセスの管理)を参照してください。

**アクション**メニューには、**配賦...**、**取締役会資料...**、**複製...**、**復元...**、**マイテンプレートとして保存...** があります。[配賦ルール](#配賦ルール)、[取締役会資料](#取締役会資料)、[プロジェクトの複製](#プロジェクトの複製)、[復元ポイント](#復元ポイント)、[マイテンプレートとして保存](#マイテンプレートとして保存)を参照してください。

## Common Finance Model のテーブル

Data Foundation は、ERP かファイルかを問わず、すべてのソースを同じ 15 個のテーブルに適合させるため、それらの上に構築されたレポート、メトリック、モデルは、ソースにかかわらず同じように動作します。各行には、ソースシステムと読み取り日時も記録されます。**データセット**列は、ファイルを追加するときに選択する名前です。

| データセット | テーブル | 内容 |
|---|---|---|
| エンティティ | `cfm_entity` | 親、現地通貨とグループ通貨、国を持つ法人。 |
| エンティティ対応表 | `cfm_entity_map` | ソースのエンティティコードと、それぞれが属するエンティティ。[エンティティ対応表](#エンティティ対応表)を参照してください。 |
| 為替レート | `cfm_fx_rate` | 通貨ペアごとの月次の平均レート、期末レート、ヒストリカルレート。[為替レート](#為替レート)を参照してください。 |
| 会計カレンダー | `cfm_fiscal_calendar` | エンティティの会計期間ごとに 1 行。開始日と終了日、および締め済みかどうかを含みます。 |
| 勘定科目表 | `cfm_account` | 親、タイプ（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、財務諸表、正常残高、レートタイプを持つ勘定科目。 |
| 部門 | `cfm_department` | 親とプロフィットセンターを持つ部門およびコストセンター。 |
| 製品 | `cfm_product` | 親、ファミリー、グループ、単位、標準原価を持つ製品マスター。 |
| 顧客 | `cfm_customer` | 親、グループ、地域、国を持つ顧客マスター。顧客名はマスクされません。 |
| セグメント値 | `cfm_segment` | 名前と親を持つセグメント値。[階層](#階層)を参照してください。 |
| 総勘定元帳 | `cfm_gl_journal` | 取引通貨、現地通貨、報告通貨での仕訳明細。 |
| 試算表 | `cfm_trial_balance` | エンティティ、勘定科目、部門別の期間の借方、貸方、純額（現地通貨および報告通貨）。 |
| 売上明細 | `cfm_sales_line` | 数量、総額、値引き、純額、売上原価の金額を含む請求済みの売上明細。 |
| 在庫残高 | `cfm_inventory_balance` | 製品および倉庫別の期末在庫。 |
| 予算 | `cfm_budget` | シナリオ、バージョン、勘定科目、部門別の予算と予測。 |
| 配賦ドライバー | `cfm_stat_driver` | 人員数、平方フィート、数量などの統計ドライバー。 |

期間は `YYYY-MM` 形式で記述され、取引は転記期間に基づいて配置されます。予算は省略可能です。予算のない ERP でも、それ以外のデータはすべてロードされます。

試算表ファイルには、借方と貸方の列、純額の列、またはその両方を含めることができます。借方と貸方のみの場合、純額は借方から貸方を差し引いた値となり、空欄はゼロとして扱われます。純額のみの場合、正の純額は借方となり、負の純額は正の金額として貸方となります。部門の列は省略可能です。

## トラブルシューティング

| 症状 | 対応 |
|---|---|
| **接続をテスト**で、ERP が資格情報を拒否したと表示される | 接続の資格情報と、統合ユーザーが ERP にサインインできることを確認してください。 |
| **接続をテスト**で、データセットに**権限が不足しています**と表示される | ERP 管理者に、表示された権限を追加するよう依頼してください。お使いの ERP の[接続ガイド](/ja/guides/connections/)に、接続に必要な権限が記載されています。 |
| ERP のエラーメッセージが ERP 自体のメッセージより短い | PlaidCloud は、プロバイダーのエラーを表示する前に資格情報、トークン、キーを削除するため、一部の詳細が省略されます。**接続をテスト**を実行して、影響を受けるデータセットを確認してください。 |
| ある期間の**ロード済みデータ**が問題になっている | その期間の ERP の読み取りが失敗しました。もう一度**ロード**を実行してください。ロード済みの期間はスキップされます。 |
| **勘定科目表にない勘定科目**が問題になっている | 不足している勘定科目を ERP またはファイルの勘定科目表に追加し、もう一度**ロード**を実行してください。 |
| **通貨換算**が問題になっている | その期間について、エンティティの通貨から報告通貨へのレートがないか、単一の報告通貨が見つかりませんでした。**為替レート**ファイルにレートを追加するか、接続が ERP の為替レートを読み取れることを確認するか、プロジェクト変数 `reporting_currency` を設定してください。その後、もう一度**ロード**を実行してください。 |
| **通貨換算**が要対応になっている | 貸借対照表、在庫、または予算の行に、その期間の期末レート、ヒストリカルレート、または計画レートがありません。損益計算書には影響しません。予算の月の計画レートを含めてレートを追加し、もう一度**ロード**を実行してください。 |
| **回答待ちのコード**が要対応になっている | **確認**をクリックし、各コードに回答して、**変更を適用**をクリックしてください。 |
| **どのソースがどの月をカバーするか**が要対応になっている | **どのソースをいつから使用するかを選択**をクリックし、ソースを選択して、**変更を適用**をクリックしてください。 |
| **内部取引残高**が赤または黄色になっている | **内部取引ペア**のペアを確認してください。不足している側を計上するか、明細に取引先を追加するか、不足しているレートを追加してください。 |
| **グループビューがオフです** | アーキテクトに、**グループ**の**プロジェクトの全員がグループの結果を閲覧可能**にチェックを付けるよう依頼してください。 |
| **未マッピングのエンティティ**が問題になっている | エンティティをエンティティマスターに追加するか、**エンティティ対応表**ファイルでそのコードを既存のエンティティにマッピングして、もう一度**ロード**を実行してください。 |
