**Data Foundation** は、PlaidCloud プロジェクトのための財務データ基盤です。その **Common Finance Model** は、複数の ERP システム、およびそれぞれの複数のインスタンスの ERP データを 1 つのモデルに統合します。勘定科目表、エンティティのセット、報告通貨はそれぞれ 1 つです。このモデル上に構築されたレポート、メトリック、AI アシスタントは、どの ERP から来たデータであっても、すべて同じ数値を参照します。

ERP は PlaidCloud の接続を通じて接続されるため、総勘定元帳、試算表、マスターデータ、予算はソースから直接取り込まれ、エクスポート作業は不要です。ファイルは、為替レート、配賦ドライバー、ERP の外で管理している予算など、システムが保持していないデータを追加し、対象となる ERP の行を置き換えることもできます。**ロード** は、すべてのソースをモデルに適合させ、報告通貨に換算し、合計が一致することをチェックします。これらはすべてプロジェクトの **ホーム** レールにある **Data Foundation** グループから行います。2 つ目のシステムを追加すると、すでに接続されているシステムと同じ勘定科目コードを使用しているかどうかなど、対象ごとに 1 つの質問に回答します。また、管理連結によって内部取引を消去したグループの損益計算書が作成されます。Data Foundation はどのプロジェクトにも追加でき、**企業収益性** などのソリューションは、その上にレポートやモデルを構築します。

## Data Foundation の導入

Data Foundation を使用してプロジェクトを開始することも、既存のプロジェクトに追加することもできます。

- **新しいプロジェクト。** Analyze で **プロジェクト** を開き、**新規プロジェクト** をクリックします。**開始元** には、**空白**、**Data Foundation**、**Enterprise Profitability**、**Cost to Serve**、**Operational Transfer Pricing**、**テンプレート ファイルから** が表示され、一覧の下の行に、選択した内容で何が得られるかが示されます。**Data Foundation** は、モデルとそのレポートのみです。3 つのソリューションはいずれも Data Foundation を含み、独自のモデルを追加します。何かを接続する前に完全な例を確認するには、**サンプルデータで開始** にチェックを入れます。**作成** をクリックします。共有するまで、プロジェクトはあなた専用であり、あなたが唯一のアーキテクトです。
- **初回サインイン時。** プロジェクトを作成できる場合は、初回サインイン時のウェルカム画面に **財務システムに接続** が表示されます。これにより Data Foundation プロジェクトが作成され、名前が自動的に付けられ、構築中にプロジェクトが開きます。
- **既存のプロジェクト。** プロジェクトの **ホーム** を開きます。レールの **Data Foundation** 見出しの下にある **Data Foundation** 行にその内容が表示され、プロジェクトのアーキテクトには **Data Foundation を追加** が表示されます。構築はバックグラウンドで実行され、ページに **Data Foundation を追加しています。数分かかります。** メッセージが表示されます。独自のワークフロー、テーブル、その他の作業はそのまま残ります。モデルがテーブルを保持する場所に、プロジェクトがすでにテーブルを持っている場合は、何もインストールされず、メッセージにそのテーブル名が示されます。

**ホーム** は、すべてのプロジェクトの最初のタブです。プロジェクトに Data Foundation があると、そのレールの **Data Foundation** グループに次の行が表示され、それぞれに独自のリンクがあります。

| 行 | 表示される条件 |
|---|---|
| **サマリー** | 常に表示されます。Data Foundation があり、まだシステムがないプロジェクトは、この行で開きます。 |
| **システム** | プロジェクトに 2 つ以上のシステムがある場合、アクセス待ちのシステムがある場合、または **サマリー** の次のステップがシステムの追加、接続、最新状態の維持である場合。 |
| **質問** | 回答待ちの質問がある間。その数がバッジで表示されます。 |
| **レポート** | 常に表示されます。 |
| **配賦** | ソリューションで作成したプロジェクトの場合。 |

## ERP を接続する

財務システムは、PlaidCloud の接続を通じて Data Foundation に接続されます。Data Foundation は、総勘定元帳、試算表、マスターデータ、為替レート、予算に加え、システムが保持している場合は補助元帳、月末残高、銀行残高をそこから直接読み取り、読み取り以外の操作は一切行いません。認証情報は、必ず標準の接続エディターで入力します。各システムには、アクセス権を付与する管理者向けのページがあり、[モデルにデータを供給できるシステム](/ja/guides/projects/data-foundation-getting-started/#モデルにデータを供給できるシステム)に一覧があります。また、[Data Foundation カバレッジマトリクス](/ja/reference/data-foundation-coverage-matrix/)には、各システムが直接提供するデータセットが示されています。

<Steps>

1. **サマリー** で **財務システムを追加** をクリックします。**システム** が開きます。

2. **システムを追加** で、**システム** からシステムを選択します。次の手順は、システムのサインイン方法によって異なります。

   - **QuickBooks Online と Xero** は、システム独自のウィンドウでアクセスを承認してサインインします。**Connect to** とシステム名をクリックします。PlaidCloud がプロジェクトの環境用の接続を作成し、承認ウィンドウを開きます。承認すると、システムが追加され、ロードが開始されます。ブラウザーでウィンドウがブロックされた場合は、サイトのポップアップを許可してもう一度お試しください。
   - **認証情報でサインインするシステム** では、**接続** に、使用できるその種類の接続が一覧表示され（最初の接続が選択されています）、**新しい接続** も表示されます。接続を選択して **システムを追加** をクリックします。**新しい接続** をクリックすると、プロジェクトの環境が入力された状態で標準の接続エディターが開き、接続を保存するとシステムが追加されます。
   - **SAP S/4HANA、SAP ECC、Oracle E-Business Suite、Sage 100** には、ネットワーク上の PlaidLink エージェントを介して接続します。最初にエージェントを設定してから、認証情報でサインインする他のシステムと同様にその接続を選択します。

3. システムを追加する前にロード対象を変更するには、**オプション** を開きます。**会社** にはシステムの会社が一覧表示されます。ロードする会社にチェックを入れるか、すべてロードする場合はどれにもチェックを入れません。会社を一覧表示しないシステムでは、会社を入力するよう求められます。**履歴の月数** は、何か月前までロードするかを 1 から 120 の範囲で指定します。一部のシステムには **システム設定** もあり、必須の設定があるシステムでは **オプション** が開いてその設定を求められます。**オプション** を使用しない場合は、すべてのアクティブな会社と 24 か月分の履歴がロードされます。

4. 接続とともに追加したシステムは、すぐにロードを開始します。他のワークフローが同じ接続を使用している場合、PlaidCloud はまず **共有接続からロードしますか?** ダイアログでそれらのワークフローを示します。ロードは接続から読み取るため、それらのワークフローの処理が遅くなる可能性があるからです。続行するには **このままロード** をクリックします。

</Steps>

まだアクセス権がない場合は、システムを選択し、代わりに **まだアクセス権がありませんか?** ボタンをクリックします。システムは **アクセス待ち** として追加され、アクセス待ちのすべてのシステムを対象とする 1 件のリクエストが表示されます。このリクエストは **リクエストをコピー** または **リクエストをメールで送信** で送信できます。アクセス権が届いたら、**システムを追加** でその接続とともにシステムを追加します。QuickBooks Online と Xero の場合は、システムの行にある **接続** をクリックします。

別のシステムや別のインスタンスを取り込むには、同じ方法で追加します。システムを追加しても他のシステムは常にそのまま残るため、複数のシステムとインスタンスから 1 つの連結モデルにデータを供給できます。2 つ目のシステムを追加すると、Data Foundation はコードごとではなく対象ごとに 1 つの質問をします。[ソース間でのコードのマッピング](#ソース間でのコードのマッピング)を参照してください。

各ロードでは、変更された部分だけを読み取ります。未締め期間と直近の締め済み期間は再度読み取られ、ロード済みの締め済み期間はそのまま保持されます。**履歴の月数** を増やすと、追加された月だけが読み取られます。為替レート、エンティティ対応表、報告通貨を変更すると、影響を受ける月が再度読み取られます。

## システム

プロジェクトがロード元とするすべてのシステムとインスタンスがソースであり、確定したファイルもソースです。レールの **システム** 行と、そのページ、ボタン、**ファイル** カードは、プロジェクトに 2 つ以上のシステムがある場合、アクセス待ちのシステムがある場合、または **サマリー** の次のステップがシステムの追加、接続、最新状態の維持である場合に表示されます。ロード済みで最新の状態に保たれているシステムが 1 つだけの場合は、代わりに **サマリー** の **Your system** にそのシステムが表示されます。**システム** ページには、すべてのシステムが **システム**、**ステータス**、**前回のロード** とともに一覧表示されます。**ステータス** は、**アクセス待ち**、**接続済み**、**ロード中**、**読み込み済み**、**失敗** のいずれかです。**前回のロード** には、システムが最後にロードされた日時、または **未読み込み** が表示されます。また、プロジェクトがスケジュールに従って更新されるようになると、次回の更新予定日時、または更新がいつから遅れているかも表示されます。失敗したシステムの下には、その行に理由が表示されます。

各行には、システムの状態に応じたボタンがあります。

| ボタン | 表示される条件 |
|---|---|
| **ロード** | システムが接続済みまたはロード済みの場合。そのシステムのみを読み取り、その後、すべてのシステムのデータからモデルを再構築します。失敗したシステムでは、修正用のボタンの横に表示されます。 |
| **接続を開く** | システムのロードに失敗した場合。接続を開いて原因を確認し、修正します。 |
| **再接続** | QuickBooks Online または Xero へのサインインの有効期限が切れた場合。 |
| **接続** | QuickBooks Online または Xero がアクセス待ちの場合。 |
| **アクセスをリクエスト** | 認証情報でサインインするシステムがアクセス待ちの場合。送信するリクエストを再度表示します。 |

その横の **接続をテスト** は、サインインして各データセットの読み取りを試み、それぞれを **読み取り可能**、**権限が不足しています**、**エラー** のいずれかで一覧表示し、システムの管理者に追加を依頼すべき権限を示します。**削除** をクリックし、**このシステムを削除しますか?** ダイアログで確定すると、システムがプロジェクトから削除されます。そのシステムからロードされたデータはすべて削除されますが、後で再度接続できます。

システムの使い方を変更するには、そのシステムの **編集** をクリックしてから、**保存** をクリックします。

| 設定 | 内容 |
|---|---|
| **名前** | レポート、質問、メッセージでシステムを表すラベルです。 |
| **レポート用帳簿（カンマ区切り）** | 複数の帳簿を持つシステムで、読み取る会計帳簿です。**すべてのレポート用帳簿** を選択すると、すべての帳簿が読み取られます。 |
| **このソースが提供する月** | 各 **会社** について、システムが提供する **開始 (2026-01)** から **終了 (2026-12)** までの月です。制限しない場合は月を空欄にします。月は年と月で指定します（例：`2026-03`）。 |
| **このソースの追加カテゴリー** | システムが持つ各追加カテゴリーの **名前** と、それを表示する **表示先**、または **対象外にする**。 |
| **会社** と **履歴の月数** | システムがロードする会社と、何か月前までロードするか。 |

会社を追加した場合や、どれにもチェックを入れなかった場合は、すぐに保存されます。会社を除外する場合は、まず **読み込む会社を減らしますか?** ダイアログで確認を求められます。保存すると、そのシステムからロードされたデータがすぐにすべて消去され、次回の **ロード** でチェックを入れた会社が再度取り込まれるためです。

2 つのシステムが同じ会社の同じ月を提供している場合は、どちらをいつから採用するかを選択するまで、一覧で上にあるシステムが採用されます。[どのソースをいつから採用するかを選択](#どのソースをいつから採用するかを選択)を参照してください。

ソースを変更しても、ERP は再度読み取られません。すべてのページの上部のバーには、**変更を適用** をクリックするまで **ソースを変更しました。使用するには「変更を適用」を押してください。** メッセージが表示されます。クリックすると、すでに取得済みのデータからロードが実行されます。新しいマッピング、名前、ファイルでソースを再度適合させ、モデルを再構築します。システムから最新のデータも取得したい場合は、**ロード** をクリックします。

## ERP 外のデータをファイルで追加する

ファイルは、為替レート、配賦ドライバー、エンティティコードの[コードマップ](#エンティティ対応表)、ERP の外で管理している予算など、システムが保持していないデータで ERP 接続を補完します。各ファイルは、[Common Finance Model のテーブル](#common-finance-model-のテーブル)に記載されたデータセットのいずれかに属します。

<Steps>

1. **システム** のシステム一覧の下にある **ファイル** カードで、ファイルを保存する **ドキュメントアカウント** を選択します。

2. CSV または Excel ファイルを **CSV または Excel ファイルをここにドロップ** にドロップするか、**ファイルを選択** をクリックします。ファイルはドキュメントアカウントの `/foundation/` フォルダーにアップロードされます。

   ドキュメントアカウントにすでにあるファイルの場合は、**ファイルを追加するその他の方法** を開き、**ドキュメントアカウントにあるファイルを追加** で、そのパス（例：`/foundation/budget.csv`）を入力して、**ファイルを追加** をクリックします。

   毎月新しいファイルを読み取るには、**フォルダー内の一致するファイルをすべて追加** を使用します。フォルダーを入力し、入力した文字列に対するファイル名の条件として **含む**、**で始まる**、**で終わる**、**が完全一致**、**パターンに一致（\* は任意の文字列）** オプションのいずれかを選択して、**ファイルを追加** をクリックします。その中のサブフォルダーにあるファイルは読み取られません。

3. PlaidCloud はファイルを読み取り、マッピングを提案します。

   - **検出された区切り文字、小数点の区切り文字、日付。** 区切り文字（カンマ、セミコロン、タブ、パイプ）、小数点の区切り文字、日付形式は自動的に検出されます。
   - **データセット**：ファイルが属する Common Finance Model のテーブルです。ファイル名と列見出しから照合されます。照合結果が明確でない場合は、一覧から選択します。
   - **小数点の区切り文字**：**ピリオド (1,234.56)** または **カンマ (1.234,56)**。
   - **日付形式**：ファイルに日付が含まれる場合に表示されます。検出された形式が誤っている場合は変更します：`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY`、`MM/DD/YYYY`。
   - **ファイル内の列**、**タイプ**、**例**、**対応先** のグリッド。列を別のフィールドに送るには **対応先** を変更し、ロードしない場合は **ロードしない** を選択します。

4. **Which company is this file for?**、**Which currency are the amounts in?**、**Are these amounts year-to-date or for the month?**、**Are the amounts shown in thousands or millions?**、**Are revenues shown as negative numbers?** など、ファイルについての質問に回答します。各質問は、ファイルにその情報がまだ含まれていない場合にのみ表示されます。

5. 各列の対応先を確認し、**マッピングを確定** をクリックします。処理中は、ボタンの下の注記に待機中の理由が表示されます。サンプルデータが残っているプロジェクトでは、最初に確定したファイルによってサンプルも削除されるため、数分かかる場合があります。

</Steps>

ファイルには、該当する場合に次のオプションが表示されます。

| オプション | 用途 |
|---|---|
| **Which source do these rows apply to?** | コードマップファイルを 1 つのソースに限定します。**Every source** を選択すると、すべてのソースに適用されます。 |
| **Where does this file come from?** | ファイルが **This project's own codes** を含むものか、**Another system** から取得したものかを指定します。後者の場合はシステム名を指定します（例：`SAP Germany export`）。別のシステムから取得したファイルは、ERP ソースと同様に共有コードがチェックされます。 |
| **Split … into … parts at each …**（**高度** の下） | `100-200-300` のように複数の値を含む 1 つの列を分割し、各部分をそれぞれのフィールドに送ります。 |
| **Which currency do you report in?** | プロジェクトにまだ報告通貨がない場合に、報告通貨を設定します。3 文字で指定します（例：`USD`）。 |
| **連結結果または報告済みの損益です (OneStream、Anaplan、SAP Group Reporting、FCCS)** | 連結システムの結果をロードし、グループの損益計算書を[照合](#連結システムとの照合)できるようにします。 |

プロジェクトからファイルを除外するには、**ファイル** でファイルの横にある **削除** をクリックするか、マッピング上の **Remove this file** をクリックして確定します。そのファイルの数値は、次に **変更を適用** をクリックしたときにレポートから除外されます。

データセット、小数点の区切り文字、日付の順序を PlaidCloud が自動的に判断できない場合（たとえば、日付が日/月とも月/日とも読めるファイル）、確定する前に選択するよう求められます。同じデータセットに 2 つ目のファイルを追加すると、最初のファイルが置き換えられます。後から追加したファイルの列がデータセットと一致しない場合、ロードはファイル名と列名を示し、ファイルまたはその列名を修正するか、ステップの **Schema Mismatch** を `union` に設定するよう案内します。

受け付けるファイルは、CSV、TSV、TXT のテキストファイル、Excel の `.xlsx` ファイル（最初のシートから読み取り）、Parquet ファイルです。

<Aside type="note">
ファイルが存在しない、または空であっても、ロードが停止することはありません。そのようなファイルを追加すると、まだマッピングするものがないと表示され、ロードはパスを示す警告とともに完了し、そのデータセットは空のままになります。ファイルが用意できたら、もう一度追加してください。
</Aside>

## データをロードする

ロードでは、接続されたシステムと確定済みのファイルを読み取り、Common Finance Model に適合させ、報告通貨に換算し、準備状況チェックを実行して、モデルを再構築します。接続とともに追加したシステムは、最初のロードを自動的に開始します。何もロードされていない間は、**ロード** が **サマリー** の次のステップにもなります。その後は、**システム** にあるシステムの行の **ロード** でそのシステムのみを読み取り、すべてのシステムのデータから適合、再構築、連結を行うため、システムを追加しても他のシステムが再度読み取られることはありません。実行中は、**サマリー** にロード中の内容が表示されます。

- 1 つのプロジェクトで同時に実行できるロードは 1 つだけです。2 回目の **ロード** または **変更を適用** を行うと、ロードがすでに実行中であることが表示されます。ロードの実行中はソースを変更できません。
- 他のワークフローが同じ接続を使用している場合、最初のロードでそれらのワークフローが一覧表示され、確認を求められます。ロードはシステムから読み取るため、それらのワークフローの処理が遅くなる可能性があるからです。続行するには **このままロード** をクリックします。
- PlaidCloud のアップグレード後は、アーキテクトが **ロード** または **変更を適用** を実行すると、プロジェクトの生成済みワークフローも更新され、必要な作業用テーブルが作成されます。新しいバージョンのモデルが利用可能な場合は、すべての Data Foundation ページの上部のバーに **Update available** と表示され、アーキテクトの **ロード** または **変更を適用** でインストールされることが示されます。マネージャーが **ロード** を実行すると、更新できるのはアーキテクトのみであるという警告が表示されます。
- 更新を適用しても、生成済みステップに対する独自の編集は保持されます。ステップを変更し、更新でもそのステップが変更された場合は、編集内容が保持されます。編集したステップが更新によって生成されなくなった場合、そのステップは保持されますが無効になります。削除するか、まだ必要な場合は再度有効にしてください。更新によって置き換えられるステップは名前が示され、以前のステップはステップのバージョンに残ります。
- 更新が途中で停止した場合は、完了するまでステップが順不同で実行される可能性があります。完了させるには、アーキテクトとしてもう一度 **ロード** を押します。再び停止する場合は、サポートにお問い合わせください。
- ロードに失敗したシステムは、**システム** に **失敗** と表示され、その理由と修正方法が示されます。前回のロードが警告付きで終了した場合は、**サマリー** に **The last Load ended with a warning:** メッセージに続けて警告が表示されます。
- 1 つのエンティティと期間の読み取りに失敗しても、残りはロードされます。もう一度 **ロード** を実行すると、失敗した部分のみが取得されます。
- ソースの 1 つのデータセットの読み取りに失敗しても、ソースの残りはロードされ、そのデータセットは既存の行を保持します。また、ロードでそのデータセットが読み取られるまで、そのシステムは **システム** に **失敗** と表示されます。

### 保留された行

ソースが重複している場合、ロードは各数値を 1 回だけ計上します。計上されない行は、保持されるか保留されます。

保持された行は、計上対象外としてマークされてプロジェクトに残るため、システムが保持するデータが失われることも、二重に計上されることもありません。行が保持されるのは、次の場合です。

- ソースが読み取るよう設定されていない、現地帳簿や税務帳簿などの別の会計帳簿にある場合
- その会社に設定された **開始** と **終了** の月の範囲外にある場合
- 別のソースが計上する会社と月の行である場合（例：エンティティの移行元のシステム）
- そのエンティティと月についてファイルで置き換えられている場合

保留された行は、ソース、エンティティ、理由とともに記録され、ロードはその件数を示す警告とともに完了します（例：`120 rows of NetSuite EU carrying a code another source also uses`）。理由は次のとおりです。

| 理由 | 意味 |
|---|---|
| ソースの以前のファイルにもある | 同じソースの以前のファイルがすでにその月をカバーしています。 |
| 後の期首残高 | エンティティの最も古い期首残高と、それ以降の取引がすでに計上されています。 |
| 別のソースでも使用されているコードを含む | そのコードには回答が必要です。[ソース間でコードをマッピングする](#ソース間でのコードのマッピング)を参照してください。 |
| 2 つのコードにマッピングされたコードを含む | コードマップがそのコードに 2 つの回答を与えています。 |
| 自身のマスターにないコードを含む | システム独自の勘定科目、製品、顧客の一覧にそのコードがありません。 |
| レポートの合計行または空白行 | ファイルの合計行または空白行です。 |

統計勘定は、元帳ではなく配賦ドライバーに移動され、問題としてではなく移動済みとして表示されます。

### ERP データとファイルの併用

ファイルは、そのファイルがカバーする範囲だけを置き換え、ERP からの他の行はそのまま残ります。

- **マスターファイル**（勘定科目、部門、顧客、製品、セグメント値）は、同じコードを持つ ERP の行を置き換えます。
- **トランザクションファイル** は、同じエンティティと月の ERP の行を置き換えます。総勘定元帳ファイルと試算表ファイルはさらに元帳で、予算ファイルはシナリオで、統計ドライバーファイルはシナリオとドライバーで照合されます。

後でファイルがある月をカバーしなくなった場合、その月の ERP のデータは次回のロードで復元されます。

## エンティティ対応表

各ソースは、独自のコードでエンティティを識別しています。**コードマップ** ファイルは、それらのコードをエンティティマスターのエンティティに対応付けるため、すべてのソースの明細が同じエンティティに集約されます。

対応表を使用するには、CSV または Excel ファイルを追加し、**コードマップ** データセットを選択します。

| 列 | 内容 |
|---|---|
| `source_code` | 会社コードなど、ソース上のコード。`source_entity` という名前の列もこれに対応付けられます。 |
| `code` | 対応するエンティティ（エンティティマスター上の名前）。`entity` という名前の列もこれに対応付けられます。 |

ファイルに別の指定をする `dimension` 列がない限り、各行はエンティティコードをマッピングします。[ソース間でのコードのマッピング](#ソース間でのコードのマッピング)を参照してください。

- コードマップにないコードは、そのまま使用されます。
- 複数のコードを 1 つのエンティティに対応付けることができます。それらの明細は合算され、ある月はすべてのコードで締め済みになった時点で締め済みとみなされます。
- ファイルの行は、**これらの行はどのソースに適用されますか?** 欄で 1 つを選択しない限り、すべてのソースに適用されます。そのため、2 つのソースが同じコードを異なるエンティティに使用している場合は、ファイルを 1 つのソースに限定してください。
- **エンティティ**ファイルの行は、同じエンティティコードを持つ ERP のエンティティを置き換えます。

**Every entity known** チェックは、エンティティがエンティティマスターになく、コードマップでもマッピングされていない明細を検出します。エンティティマスターがロードされるまでは対象外です。

## ソース間でのコードのマッピング

2 つのシステムが同じコードを別の意味で使用していたり、同じものに異なるコードを使用していたりすることがあります。すでに接続されているシステムとコードが重複するシステムを追加すると、Data Foundation はコードごとではなく対象ごとに 1 つの質問をします。例：**Does SAP ECC use the same account codes as NetSuite?** この質問は、勘定科目、部門、プロフィットセンター、サイト、製品、顧客、および各追加カテゴリーについて行われます。

各質問は、Weave が提案する回答とその根拠（共有されているコードのうち同じ名前を持つものの数など）とともに **質問** ページで待機し、回答するまで保留される行数が示されます。もう一方のシステムと同じコードであれば **Same codes as**、異なるコードであれば **Different codes from** で回答します。

- 回答するまでは、共有されているコードを持つ行が保留されるため、各金額は 1 回だけ計上されます。
- あるシステムが同じコードを使用していると回答すると、後でそのシステムに新しく現れたコードは、新しい質問なしにもう一方のシステムのコードとして扱われます。
- マッピングはシステムとディメンションごとに保持されるため、あるシステムの部門に対する回答が別のシステムの勘定科目に影響することはありません。
- 回答は次回の **ロード** または **変更を適用** で適用され、**サマリー** の **履歴** に、回答者、日時、変更前の値が記録されます。

マッピングはファイルで指定することもできます。**Code map** データセットのファイルを追加し、**Which source do these rows apply to?** 欄で対象を 1 つのソースに限定します。

## どのソースをいつから採用するかを選択

エンティティがあるシステムから別のシステムに移行すると、両方のシステムにそのエンティティが含まれます。**質問** では、新しいシステムがそのエンティティについてどの月から計上されるか（**From which month does** … **count for**）が質問され、以前のシステムの最後の元帳月の翌月が提案されます。以前のシステムには、それより前の月が残ります。

**サマリー** の **ソースの対象範囲** カードには、2 つのソースが両方とも提供しているその他の月が一覧表示されます。**問題** で、ある会社について重複している 2 つのソースに対して、**その月** に月を入力し（例：`2026-04`）、**その月以降はどのソースを使用しますか。** 欄でソースを選択し、**選択を保存** をクリックしてから、ページ上部のバーにある **変更を適用** をクリックします。選択するまでは 2 つのうち最初のソースのみが計上され、もう一方のソースには入力した月より前の月が残ります。**要対応** では、2 つのソースがある会社に対して異なる為替レートを持っている場合など、説明どおりに計上される重複について説明し、どちらのレートが使用されるかを示します。

## 通貨換算

ロードのたびに、総勘定元帳、試算表、売上、在庫、予算、補助元帳の金額が現地通貨から 1 つの報告通貨に換算されます。レポートやモデルは換算後の金額を読み取るため、どのシステムのデータであっても、通貨の異なるエンティティを正しく合計できます。

### 報告通貨

報告通貨を選択するには、プロジェクト変数 `reporting_currency` に `USD` などの通貨コードを設定します。[プロジェクト変数の管理](/ja/guides/projects/managing-projects/#プロジェクト変数の管理)を参照してください。複数のエンティティがあるプロジェクトでは、代わりに **サマリー** の **グループ** カードで **変更** をクリックし、**プロジェクトの設定** の **レポート通貨** にコードを入力することもできます。この変数はテンプレートによって空の状態で作成されます。空の間は、各ロードで次のうち通貨が 1 つに定まる最初のものが使用されます。

1. エンティティのグループ通貨。
2. 最上位エンティティ（親を持たないエンティティ）の現地通貨。
3. ファイルの現地通貨。

いずれでも通貨が 1 つに定まらない場合は、`reporting_currency` を自分で設定してください。

すでに報告通貨で計上されている金額はそのまま使用されるため、すべてのデータが単一通貨のプロジェクトでは為替レートは不要です。

売上、在庫、予算のファイルにも通貨を含めることができます。`Currency` または `Local Currency` という名前の列をマッピングすると自動的に認識され、ファイルの現地通貨金額が報告通貨に換算されます。ファイルにすでに含まれているグループ金額や報告金額はそのまま保持されます。製品マスターの標準原価はすでにグループ通貨で表されているため、換算されません。

### 為替レート

為替レートは、ある月について、ある通貨の 1 単位を報告通貨に換算する値です。換算後の金額は、現地通貨金額に為替レートを掛けたものです。

- **ERP から**: 各ロードで、ERP が保持している為替レートを読み取ります。
- **ファイルから**: CSV または Excel ファイルを追加し、**為替レート**データセットを選択します。ファイルのレートは、同じ通貨と月の ERP のレートを置き換えます。ERP がレートを公開していない通貨で報告する場合や、予算月の計画レートを追加する場合はファイルを使用します。

| 列 | 内容 |
|---|---|
| `from_currency` | 換算元の通貨（例: `EUR`）。 |
| `to_currency` | 報告通貨（例: `USD`）。 |
| `period` | 月（`YYYY-MM` 形式）。 |
| `average_rate` | その月の平均レート。 |
| `closing_rate` | 月末時点のレート。 |
| `historical_rate` | 純資産、および取得時レートが設定された勘定科目に使用する取得時レート。 |

ある通貨に報告通貨へのレートがない場合は、逆方向（報告通貨からその通貨へ）のレートの逆数が、小数点以下 12 桁で使用されます。それもない場合は、その通貨から別の通貨へのレートに、その別の通貨から報告通貨へのレートを掛けた値が使用されます。

### 適用されるレート

各行はその行自体の通貨から換算されるため、エンティティとは異なる通貨の明細は、その明細の通貨から換算されます。行に当てはまる最初のルールが適用されます。

| 行 | レート |
|---|---|
| 統計勘定および非転記勘定 | 換算されません。 |
| すでに報告通貨で計上されている行 | 換算されません。 |
| レートタイプを持つ勘定科目 | そのレート（平均、期末、取得時）。取得時レートがない場合は期末レートが使用されます。ERP の場合、レートタイプは勘定科目自体のレートタイプです。勘定科目表ファイルの場合は、レートタイプの列を `fx_rate_type` にマッピングし、`average`、`closing`、`historical` のいずれかを指定します。 |
| 売上明細 | 期間の平均レート。 |
| 在庫残高 | 期間の期末レート。 |
| 仕入先請求書、発注書、支払、受注、資産の増減、繰延収益の増減、在庫の増減、または標準原価 | 期間の平均レート。 |
| 未決済の売掛金または買掛金、受注の未決済金額、契約の金額、または銀行残高 | 保持されている月末の期末レート。 |
| 予算行 | 総勘定元帳と同様に勘定科目に応じて決まります。損益計算書の勘定科目には平均レート、貸借対照表の勘定科目には期末レートが使用されます。 |
| 損益計算書の勘定科目 | 期間の平均レート。 |
| 純資産の勘定科目 | 取得時レート。取得時レートがない場合は期末レート。 |
| その他の貸借対照表の勘定科目 | 期間の期末レート。 |

換算後の金額は丸められないため、合計にずれが生じません。

パイプラインビュー `cfm_rv_pipeline_month`、`cfm_rv_won_booked`、`cfm_rv_campaign_window` では、商談の受注額、失注額、作成額を、その商談がクローズした月または作成された月の平均レートで換算します。各月の未決のパイプラインはその月の期末レートで換算され、その月の期末レートがまだロードされていない間は、その通貨でロード済みの最新の期末レートで換算されます。

<Aside type="note">
外貨建ての商談の受注額、失注額、作成額は、その通貨にその月の平均レートがない場合、別のレートで表示されるのではなく除外されます。商談自体は引き続きカウントされます。外貨建ての受注の金額は、その月の平均レートがロードされるまで `cfm_rv_pipeline_month`、`cfm_rv_won_booked`、`cfm_rv_campaign_window` に含まれないため、それまでは当月の外貨建ての受注が受注額に反映されません。**為替レート**ファイルにレートを追加するか、接続が ERP の為替レートを読み取れることを確認してから、もう一度**ロード**を実行してください。
</Aside>

<Aside type="note">
総勘定元帳と試算表は各期間の増減を保持するため、それらの貸借対照表の金額は、各月の増減をその月のレートで換算したものになります。一方、連結貸借対照表では残高を表示月の期末レートで換算し、その差額を純資産の下の換算差額の行に計上します。[管理連結](#管理連結)を参照してください。
</Aside>

## 階層

ロードのたびに、すべてのソースのマスターデータからディメンションが再構築されます。最初は 7 つのディメンションがあり、最大 10 個の追加カテゴリーを利用できます。

| ディメンション | 構築元 |
|---|---|
| **エンティティ** | エンティティとその親 |
| **勘定科目** | 勘定科目表と親勘定科目 |
| **部門** | 部門とその親 |
| **顧客** | 顧客とその親顧客 |
| **製品** | 製品とその親製品 |
| **セグメント1** | `segment_1` のセグメント値 |
| **セグメント2** | `segment_2` のセグメント値 |
| **セグメント3**～**セグメント10** | `segment_3`～`segment_10` のセグメント値（ソースに含まれる場合） |

- 親を持たないレコード、または自身を親として指定しているレコードは、最上位メンバーとしてロードされます。
- 階層はロードのたびに再構築されるため、親を変更する場合はディメンションではなく ERP またはファイルで変更してください。
- ある階層の問題は、そのディメンションにのみ影響します。ロードとテンプレートのモデルは引き続き完了します。
- 各追加カテゴリーの名前は、その内容に合わせて変更できます（例：**クラス**、**リージョン**）。複数のエンティティがあるプロジェクトでは、**サマリー** の **グループ** カードで **変更** をクリックし、**プロジェクトの設定** の **名前** に、レポートで使用する名前を入力して、**保存** をクリックします。名前には英字、数字、スペース、ピリオド、ハイフン、アンダースコアを使用でき、最大 60 文字です。
- 各ソースでは、そのソース独自の追加カテゴリーを、どのカテゴリー名の下に配置するかを指定します。**システム** で、ソースの **編集** をクリックし、**このソースの追加カテゴリー** でそれぞれの名前を選択するか **対象外にする** を選択して、**保存** をクリックします。これにより、`Class` と `Business area` のように異なる名前でカテゴリーを呼んでいるソース同士が、1 つの枠を共有します。

セグメント階層をファイルで指定するには、**セグメント値**データセットを選択します。

| 列 | 内容 |
|---|---|
| `segment` | 値が属するセグメント（`segment_1`～`segment_10`）。 |
| `segment_value` | 総勘定元帳、売上、予算の明細上の値。 |
| `segment_value_name` | 値の名前。 |
| `parent_segment_value` | 同じセグメント内での親。 |

## 準備状況チェック

これらのチェックは、**サマリー** にある 5 つの保証の詳細です。[数値は信頼できますか?](/ja/guides/projects/data-foundation-proof/)を参照してください。

各 **ロード** と **変更を適用** で、すべてのエンティティと期間についてこれらのチェックが実行され、各チェックは 5 つの保証のいずれかに計上されます。失敗したチェックは赤色で表示されます。注意は黄色で表示され、確認が必要なものの数値は正しいことを示します。**CFM-Accounting - Close and assurance** ダッシュボードの **What needs fixing** タブには **Every check, by system, month chosen** が表示され、各チェックについてシステムごとの赤色の項目数が示されます。0 は修正の必要がないことを意味します。選択した月の修正が必要な項目のテーブルには、大きいものから順に各赤色項目が示され、勘定科目表のロード、為替レートのロード、**ロード** の再実行など、必要な対応が表示されます。[ダッシュボード、メトリック、分析パス](/ja/guides/projects/data-foundation-dashboards/)を参照してください。

主なチェックは次のとおりです。

| チェック | 区分 | 確認内容 |
|---|---|---|
| **Every month loaded** | **途中で失われたものはありません** | すべての会計期間に総勘定元帳の明細があり、すべての ERP の読み取りが成功したこと。明細のない締め済み期間は失敗となり、明細のない未締め期間は注意となります。 |
| **Trial balance equals the ledger** | **各システムと一致** | エンティティ、期間、勘定科目ごとに、試算表が総勘定元帳と一致すること。ある勘定科目について試算表と総勘定元帳の両方に部門がある場合は、部門ごとの一致も確認します。 |
| **Sales equal the ledger** | **途中で失われたものはありません** | 期間ごとに、売上明細が総勘定元帳の収益および売上原価の勘定科目と一致すること。 |
| **Every product and customer of a sale known** | **途中で失われたものはありません** | すべての売上明細の製品と顧客が、製品マスターと顧客マスターに存在すること。 |
| **Every account known** と **Every account typed** | **途中で失われたものはありません** | すべての総勘定元帳の明細の勘定科目が、勘定科目表に存在すること。不明な勘定科目の明細は損益計算書から除外されます。転記があるのにアカウントタイプのない勘定科目も失敗となり、勘定科目表で収益勘定にはタイプがあるのに売上原価の勘定科目がないソースは注意となります。 |
| **Every amount has a rate** | **グループの合計が一致** | 総勘定元帳、試算表、売上、在庫、予算のすべての行に報告通貨の金額があること。損益計算書は換算後の金額を読み取るため、レートのない損益計算書または売上の行は失敗となります。レートのない貸借対照表、在庫、予算の行は注意となるため、予算月の計画レートをロードしてください。[通貨換算](#通貨換算)を参照してください。 |
| **Every entity known** | **途中で失われたものはありません** | すべての総勘定元帳、試算表、売上の明細のエンティティが、直接または **コードマップ** ファイルでのマッピングを通じて、エンティティマスターに存在すること。エンティティマスターがロードされるまでは対象外です。[エンティティ対応表](#エンティティ対応表)を参照してください。 |

これらのチェックは、対応が必要な場合にのみ表示され、すべて **途中で失われたものはありません** に区分されます。

| チェック | 確認内容 |
|---|---|
| **Reporting book chosen** | エンティティについて複数の会計帳簿を持つソースで、報告用の帳簿が選択されていること。選択するまでは、最初の帳簿のみが計上されます。 |
| **Codes mapped** | 複数のソースで使用されているすべてのコードに回答済みであること。[ソース間でのコードのマッピング](#ソース間でのコードのマッピング)を参照してください。 |
| **One source for each key** | どちらを採用するかを選択していない限り、2 つのソースが同じ会社の同じ月を提供していないこと。 |
| **Hierarchies complete** | ディメンションで指定されたすべての親が存在し、自身の親または祖先となっているメンバーがないこと。親が存在しない場合、その子は階層の最上位に配置され、循環がある場合はその階層がロードされません。合計には影響しません。 |
| **Months placed in the fiscal calendar** | 各エンティティの会計期間が暦月であり、各月の行をいずれか 1 つの会計期間に割り当てられること。エンティティの期間が暦月でない場合（4-4-5、13 期間）、ある月の行が複数の会計期間に該当し得る場合、または会計カレンダーにその月がない場合は注意となります。 |

2 つのセットアップチェックは、対応が必要な場合にのみ表示されます。1 つは、プロジェクト変数 `overhead_department` と `overhead_driver` の一方のみが設定されている場合、または `overhead_driver` に一致する配賦ドライバーがない場合に表示されます。この状態では間接費の配賦は何も行いません。両方を設定するか、両方をクリアして間接費の配賦を無効にしてください。もう 1 つは、予算行はロードされているものの、プロジェクトの設定の **予算バージョン**（プロジェクト変数 `budget_version`）にある行がなく、予算比較が空になる場合に表示されます。

## 管理連結

ロードのたびに管理連結が構築されます。これは、グループ内のすべてのエンティティの損益計算書、貸借対照表、キャッシュフロー計算書を、内部取引を消去したうえで報告通貨で表したものです。管理会計レポートを目的としています。法定上のグループについては、引き続き連結システムが正式な記録となります。後述の手順で連結システムと照合してください。

連結された数値が表示される場所にはすべて、**Management consolidation** というラベルが付きます。対象は、**サマリー** の最初の行の横、各ダッシュボード上部のコンテキスト行、および取締役会資料の **Basis** 列で、その **Basis note** 列には「Entities combined, intercompany eliminated, translated to the reporting currency. Not a statutory consolidation.」と表示されます。エンティティが 1 つのプロジェクトにはラベルは表示されません。

<Aside type="note">
管理連結は、法定連結や法的連結ではありません。投資と資本の相殺消去は行わず、のれんや非支配持分も含まれません。
</Aside>

### グループの選択

**サマリー** の **グループ** カードには報告通貨が表示されます。**変更** をクリックすると **プロジェクトの設定** が開き、**グループと行のアクセス** に **グループ内の会社** が一覧表示されます。チェックを外した会社は、単独ではレポートに残りますが、グループ合計からは除外されます。**保存** をクリックします。変更は次回の **ロード** または **変更を適用** で適用されます。新しい会社は、チェックを外すまでグループに含まれます。

グループの会計年度は、プロジェクト変数 `group_fy_start_month` で設定した月に始まります。この変数は設定しない限り空であり、空の間は、最上位エンティティ（親を持たない唯一のエンティティ）の会計年度が始まる月にグループの会計年度が始まります。最上位エンティティに会計カレンダーがない場合は 1 月に始まります。親を持たないエンティティが複数ある場合、または最上位エンティティが独自の会計カレンダーを持たない階層ノードである場合は 1 月に始まり、月を設定するまで連結は黄色で表示されます。

### 生成される内容

| テーブル | 内容 |
|---|---|
| **グループ損益計算書** | エンティティ、期間、項目（収益、売上原価、営業費用、営業外、内部取引差異）ごとに 1 行ずつ、報告通貨で表したもの。収益と費用は本来の符号のまま保持されます。 |
| **グループ損益計算書（年初来）** | 上記と同じ内容を、グループで最後にすべてロードされた期間までの年初来で表したもの。 |
| `group_statements` | 表示されているとおりの損益計算書、貸借対照表、キャッシュフロー計算書。エンティティ、消去、グループごとに、すべての小計と合計を含めて行ごとに報告通貨で示したもの。収益、資産、キャッシュインは正の値です。各行にはその月の金額と、その月までのグループの会計年度累計があり、貸借対照表の行にはその月の残高があります。 |
| `group_result` | 同じ 3 つの財務諸表を、エンティティ、行、勘定科目、月ごとに、すべてのレポート帳簿について報告通貨で示したもの。別の通貨のエンティティについては、その通貨でも示します。金額は総勘定元帳と同様に借方が正です。 |
| **内部取引ペア** | エンティティのペア、グループ、期間ごとに 1 行ずつ、各側の金額と残差を示したもの。 |
| **内部取引明細** | グループの数値またはペアの基になっている元帳の明細と、その取引相手。 |
| **照合** | グループ損益計算書（年初来）と連結システムとの比較。 |

これらのテーブルには、3 つのエンティティ名が表示されます。

| エンティティ | 意味 |
|---|---|
| **Eliminations** | 内部取引消去。合計するとゼロになるため、グループの数値ではそのまま含め、消去前のエンティティの合計を求める場合はフィルターで除外します。 |
| **Group total** | 照合における連結システムの合計。 |
| **Unmapped** | 期間のない明細、およびこのプロジェクトにない連結システムの勘定科目やエンティティ。 |

メトリック **Consolidated income**、**Consolidated result**、**IC difference** は **グループ損益計算書** を読み取ります。これらのメトリックと、**グループ損益計算書**、内部取引、照合の各テーブルの分析パスを使用して、グループに関する質問に回答できます。**CFM-Finance - Statements** ダッシュボードと取締役会資料には、3 つの財務諸表が表示されます。

#### 3 つの財務諸表

- **損益計算書**：各月をその月の平均レートで換算します。
- **貸借対照表**：各勘定科目の残高は、期首残高にその月までの取引を加えたものです。残高は表示月の期末レートで、純資産はヒストリカルレートで換算されます。勘定科目に独自のレートタイプがある場合は、そのレートタイプが使用されます。ヒストリカルレートのない純資産の勘定科目は期末レートで換算されます。前会計年度までの損益は利益剰余金に、当年度の損益は当期利益に含まれ、それぞれ該当する月の平均レートで換算されます。
- 換算差額は、エンティティごとに純資産の下の行として表示され、期末レートで換算した純資産と利益から、実際の換算額を差し引いて算出されます。これは換算後の貸借対照表の貸借を一致させるものであり、調整用の数値ではありません。別の通貨のエンティティについてある月の期末レートがない場合、その月の貸借対照表は換算されず、貸借が一致しません。その場合、連結はそのエンティティと月を示して黄色で表示されます。レートをロードしてから、**変更を適用** を実行してください。
- **キャッシュフロー計算書**：各貸借対照表勘定科目のその月の増減から、勘定科目ロールに基づいて、その月の平均レートで算出されます。為替レート変動の影響の行には、現金の変動のうち、期末レートでのレートの変動によって生じた部分が含まれます。ロールのない貸借対照表勘定科目は、その他の変動の行に含まれます。

貸借対照表は、資産から負債と純資産を差し引いたチェック行で終わり、キャッシュフロー計算書は、現金の変動から現金勘定の増減を差し引いた行で終わります。財務諸表が正しい場合、どちらも 0 になります。これらを証明する保証については、[数値は信頼できますか?](/ja/guides/projects/data-foundation-proof/)を参照してください。

### 内部取引消去

内部取引の明細は、取引相手によって照合されます。明細上の取引相手が使用され、明細に取引相手がない場合は、その顧客の取引相手が使用されます。ペアの両側が消去され、両側の金額の不一致分は内部取引差異の項目に計上されます。各ペアには理由が付けられます。

| 理由 | 意味 |
|---|---|
| **一致** | 両側が同じ金額を計上しています。 |
| **片側のみ計上** | 一方のエンティティが取引を計上し、取引相手は計上していません。 |
| **未消去** | ペアの明細に為替レートがないため、どちらの側も消去されません。 |

ペアは年初来の金額で判定されます。内部取引チェックは、ペアの差異がプロジェクト変数 `group_amber`（デフォルトは `1`）を超えると黄色に、`group_red`（デフォルトは `1000`）を超えると赤色になります。これらは **プロジェクトの設定** の **会社間許容差** です。取引相手のない明細や、取引相手がエンティティでない明細は消去されず、このチェックで集計されます。取引相手を持つソースと持たないソースが混在している場合は黄色で表示されます。

ソース独自の消去用エンティティはグループ損益計算書から除外され、連結チェックにその旨が表示されます。

3 つの財務諸表では、内部取引の収益とコストに加え、内部取引の売掛金と買掛金もペアごとに消去されます。ペアの両側の不一致額は、損益計算書または貸借対照表の内部取引差額の行に計上されるため、グループの貸借対照表は引き続き貸借が一致し、その増減はキャッシュフロー計算書の内部取引残高の変動の行に計上されます。各消去行には両方のエンティティと、それらが共有する国、リージョン、事業部が含まれるため、事業部、国、リージョンでは両方のエンティティがその内部にあるペアのみが消去され、グループではすべてのペアが消去されます。

### 連結システムとの照合

連結システムが報告する結果をファイルとして追加し、マッピングを確定するときに **連結結果または報告済みの損益です (OneStream、Anaplan、SAP Group Reporting、FCCS)** チェックボックスをオンにします。**これは数値のどのバージョンですか?** 欄にはシステムの名前を入力します。これにより、**照合** テーブルに、エンティティと項目ごとの年初来の **当方**、**報告値**、**差異** が表示されます。差異は通常、**Eliminations**、**Group total**、**Unmapped** の各行、またはシステムで使用している為替レートによって説明できます。照合チェックには、`group_amber` を超えるすべての明細が一覧表示されます。

### 閲覧できるユーザー

グループの結果には、プロジェクトの行アクセスが適用されます。行アクセスによってグループの結果が表示されない場合、連結チェックは黄色で表示されます。一部のエンティティのみを閲覧できるユーザーには、それらのエンティティの消去前の合計が表示され、**サマリー** に「これらの数値は、アクセス権のある事業体のみを対象としており、会社全体ではありません。」と表示されます。**Eliminations** 行と内部取引のテーブルを閲覧するには、すべてのエンティティへのアクセス権が必要です。

**グループと行のアクセス** の **エンティティで行を制限する** は、エンティティを付与されたグループを、エンティティ列を持つすべてのテーブルで、それらのエンティティの行に制限します。これはアーキテクトにのみ表示されます。**制限** のチェックを入れたり外したりするとすぐに適用されますが、ワークスペースで行アクセスがオフになっている間は拒否されます。グループがエンティティの権限を保持している間にチェックを外すと、まず **エンティティの権限を削除しますか?** ダイアログが表示されます。続行するには **オフにする** をクリックします。

部門など、グループのテーブルに含まれない列によって閲覧できる行をプロジェクトで制限している場合、グループの結果は全員に対して無効になり、連結チェックに **Group views are off** と表示されます。その場合、**グループと行のアクセス** で **プロジェクトの全員がグループの結果を閲覧できる** にチェックを入れて **保存** をクリックできるのはアーキテクトのみです。他のユーザーにはこのチェックボックスは表示されません。変更は次回の **ロード** または **変更を適用** で適用されます。

## 最新の状態を保つ

ロードが完了し、待機中の質問がなくなると、**プロジェクトの設定** の **更新** が **毎日**、**毎週**、**毎月** のいずれかになるまで、**サマリー** の次のステップは **常に最新の状態に保つ** になります。**ロード** をスケジュールするには、次の 2 つの方法があります。

- **サマリー** の **アクション ▾ > 夜間に更新** は、毎晩 02:00 UTC に **ロード** を実行します。
- 複数のエンティティがあるプロジェクトでは、**サマリー** の **グループ** カードで **変更** をクリックして **プロジェクトの設定** を開きます。**更新** で **毎日**、**毎週**、**毎月** のいずれかを選択し、**更新時刻 (UTC)** 欄に `02:00` のように時と分で入力します。**毎週** の場合、**更新日** は 1（月曜日）～ 7（日曜日）です。**毎月** の場合は月の日付です。**保存** をクリックします。**オンデマンド** を選択するとスケジュールが削除されます。

ソースを含むロードが赤色のチェックなしで完了すると、スケジュールを設定できるようになります。そのため、サンプルデータしかないプロジェクトはスケジュールできません。プロジェクトの一部のエンティティしか閲覧できない場合は、アーキテクトが設定します。スケジュールを設定できない場合は、その理由が表示されます。**更新** が **毎日**、**毎週**、**毎月** のいずれかの間は、**システム** ページに各システムの次回の更新予定日時が表示されます。[各システムのデータの鮮度](/ja/guides/projects/data-foundation-proof/#各システムのデータの鮮度)を参照してください。**夜間に更新** は **更新** をそのままにするため、次回の更新は表示されず、**常に最新の状態に保つ** が次のステップのまま残ります。

スケジュールされたロードは、設定したユーザーとして実行されます。そのユーザーがシステムの接続を使用できなくなった場合、ロードはそのユーザーと接続を示す警告付きでスキップされます。スケジュールをもう一度設定してください。

スケジュールされたロードでファイルが見つからないか空の場合、エラーではなく、そのパスを示す警告付きで完了し、モデルの残りの部分は引き続きロードされます。

## ビジネス名

**業務上の名前** は、モデル内のコードに、ビジネスで使用している名前を付けます。レポート、メトリック、Ask はこれらの名前を表示し、保存した名前はすぐに適用されます。以降のロードでもその名前は保持されます。複数のエンティティがあるプロジェクトでは、**サマリー** の **グループ** カードで **変更** をクリックします。**業務上の名前** は、**プロジェクトの設定** の **名前** カードにあります。

1. **名前を追加** をクリックし、**種類** として **カテゴリー**、**損益項目**、**メトリック**、**列**、**エンティティ**、**勘定科目** のいずれかを選択します。
2. **コード** を入力します。カテゴリーの場合は `segment_1` ～ `segment_10`、損益計算書の行の場合はその行のキー、メトリックの場合はメトリック名、列の場合は `table.column`、エンティティや勘定科目の場合はそのコードです。
3. **名前**を、1 行で最大 60 文字で入力します。
4. **保存** をクリックします。すべての内容が保存されるとダイアログが閉じます。拒否された名前はグリッドの下に表示され、ダイアログは開いたままになります。

保存すると、リスト全体が置き換えられます。名前が空の行はその名前を削除し、**選択項目を削除**はチェックを付けた行を削除します。同じコードに 2 回名前を付けることはできません。ビジネス名は分析パスの説明にも書き込まれるため、アシスタントはお客様の言葉を使用します。この説明には長さの制限があり、名前によって説明が長くなりすぎる場合は何も保存されず、その旨が通知されます。

## 数値の説明

**この数値を説明** は、数値の内訳を表示します。月のロードが完了すると、**サマリー** に最新の完了月までの年度の純利益が表示され、その横に **この数値を説明** があります。これをクリックすると **Explain: Net income** が開き、上部にその月までの年度の数値、その下にその内訳が表示されます。各一覧は大きいものから順に並びます。

| 一覧 | 内容 |
|---|---|
| **明細** | 合計するとその数値になる財務諸表の行。 |
| **エンティティ** | 各エンティティの割合。グループでは、消去もその 1 つです。 |
| **勘定科目** | 各勘定科目の割合。 |

各一覧には上位 10 件が表示され、残りは 1 つの項目（例：**Other accounts (12)** 行）にまとめられるため、どの一覧も合計するとその数値になります。リンクになっている名前をクリックすると、その行、エンティティ、または勘定科目のみについての説明が開きます。**サイズの大きいドキュメント** には、数値の裏付けとなる上位 10 件の元帳伝票が、**システム**、**エンティティ**、**ドキュメント**、**転記済み**、**勘定科目**、**説明**、**金額** とともに一覧表示され、**すべてのドキュメントをエクスポート** ですべての伝票をダウンロードできます。**Weave に変動の理由を質問** は、その月までの年度で数値が変動した理由と、変動の要因となったエンティティ、勘定科目、伝票を Weave に質問します。

ウィンドウは行アクセスに従うため、説明できるのは閲覧できる数値のみです。まだ存在しないテーブルはエラーではなく警告になります。裏付けのない数値には **説明する内容はありません** と表示されます。

## 配賦ルール

配賦は、間接費などの共通コストを部門、製品、顧客に配分します。モデルには **ステージ 1: 間接費を部門へ** と **ステージ 2: 部門を製品と顧客へ** の 2 つのステージがあります。ソリューションで作成したプロジェクトでは、**ホーム** レールの **Data Foundation** グループにある **配賦** をクリックします。**配賦ルール** が開き、それぞれの方法を確認または変更できます。変更しない場合、ウィザードが導入される前と同じように動作します。閲覧者はルールを開くことはできますが、保存はできません。

ウィザードは、ステージごとに 4 つの質問をします。

| ステップ | 質問 | 選択肢 |
|---|---|---|
| **プール** | どのコストを配分しますか？ | 勘定科目の種類と、ステージ 1 ではコストを保持する部門、または **All departments**。 |
| **ドライバー** | 何を基準に配分しますか？ | 配賦ドライバーとしてロードした **Statistic**（人員数や平方フィートなど）、**Net sales amount**、**Sales quantity**、または **Spread evenly**。**Same period** または **Same period last year** のドライバーを使用します。 |
| **ターゲット** | どこに配分されますか？ | ステージ 1：部門。ステージ 2：製品、顧客、またはその両方。 |
| **メソッド** | ドライバーが負の場合はどうしますか？ | **Ignore negative values** または **Stop and tell me**。 |

ステップの下にある **Preview for** で月を `2026-09` のように年と月で指定すると、保存していないルールも含め、ルールによって何が行われるかが表示されます（`Pool 120,000 · Allocated 120,000 · Unallocated 0`）。未配賦の金額は、受け取るドライバーがなかったコストです。プレビューは行アクセスに従います。

部門名や統計名には、一重引用符（`'`）、バックスラッシュ、改行を含めることはできません。名前は配賦ステップのフィルターに書き込まれるためです。**保存**とステージ 1のプレビューは、そのような名前を拒否して示します。

**保存**をクリックします。ルールは次回の**ロード**時、または**変更を適用**をクリックしたときに有効になります。配賦ステップを手動で編集していた場合、その編集は上書きされずに保持され、保存時にそのステップ名が示されます。ロードの実行中は保存できません。

## 取締役会資料

取締役会資料は、結果をドキュメントアカウントのフォルダーに書き出し、すぐに送付できる状態にします。**レポート** ページで、**取締役会資料** カードの **取締役会資料の設定** をクリックし、**ドキュメントアカウント** と、`/board-packs` などの **フォルダー** を選択して、**保存** をクリックします。以降は **ロード** のたびに資料が作成されるため、フォルダー内のファイルは前回のロード時点で最新の状態になります。各実行では次のものが書き出されます。

- **Profit and loss**、**Balance sheet**、**Cash flow** の各シートを含む Excel ブック `Board pack.xlsx`。各シートには、エンティティ別の各月と各行が、消去とグループ合計とともに示されます。エンティティが 1 つのプロジェクトには、消去とグループの行はありません。
- **CFM-Finance - Statements** ダッシュボードの PDF。

そのダッシュボードが構築されると、同じカードの **取締役会資料を開く** でダッシュボードを開けます。

すぐに資料を作成するには **今すぐ実行** をクリックします。完了すると、ファイルがフォルダーに表示されます。ダイアログには、前回の実行とその結果、および次回の実行が表示されます。**変更を適用** では資料は作成されません。スケジュールに従って作成するには、**ロード** をスケジュールしてください（[最新の状態を保つ](#最新の状態を保つ)を参照）。設定するまでは、ダイアログに **まだスケジュールされていません。ロードのたびに取締役会資料が作成されます。毎晩作成するには夜間更新を設定してください。** メッセージが表示されます。設定できるのは、プロジェクトを変更できるユーザーのみです。

資料を完全に作成できない場合でも、ロードが失敗することはありません。

- ワークスペースでレポート機能がオフになっている場合、資料は Excel ブックのみとなり、実行結果に **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.** メッセージが表示されます。
- Data Foundation が財務諸表ダッシュボードに必要とするアドレスを、他のユーザーが作成したダッシュボードがすでに使用している場合、そのダッシュボードはそのまま残され、PDF は作成されません。メッセージにそのアドレスが示されるので、Superset でもう一方のダッシュボードに別のアドレスを付けてから、もう一度 **ロード** を実行してください。
- 資料のいずれかのステップが失敗した場合、ダイアログの前回の実行に **失敗** と表示されます。ロード自体は成功しています。

## 復元ポイント

復元ポイントは、**ロード**または**変更を適用**が開始されるたびに（開始したユーザーにかかわらず、スケジュールされたロードも含む）、およびマッピングやソースを変更する前に作成されます。復元ポイントには、モデルのテーブル、ディメンション、および次回のロードの基になる設定（ソース、ファイル、配賦ルール）が保持されます。ロード時に作成された直近 7 つのポイントと、変更前に作成された直近 5 つのポイントが保持されるため、変更によってロード時のポイントが押し出されることはありません。それより古いポイントは順に削除されます。

元に戻すには、**サマリー** の **アクション ▾ > 復元…** メニューを開きます。各ポイントには作成日時が表示され、その下に、復元によって戻るテーブルの数（例：**Puts back 12 tables.** メッセージ）と、そのまま残るものについての注記が 1 つ表示されます。ポイントを選択して **復元** をクリックします。**復元** は、ポイントが存在するようになると利用できます。復元では、まず現在のプロジェクトの状態が独自のポイントとして記録されるため、再び元に戻すことができます。その後、テーブル、ディメンション、および上記の設定が以前の状態に戻され、次回のロードはそれらに基づいて行われます。すでに使用していたソースに復元しても、ソースは変更済みとしてマークされません。コネクターまたはファイルのソースが追加される前に作成されたポイントに復元すると、そのソースで取り込まれたテーブルが削除され、警告でソース名が示されます。復元を元に戻すと、コネクターのソースのテーブルは**ロード** でもう一度取得され、ファイルのソースはファイルをあらためて確認します。ソースのテーブルを削除できない場合は、手動で削除するまでソースのフォルダーに残ることが警告で示され、それ以外は引き続き復元されます。ビュー、保存できないディメンション、または保存済みのコピーがないテーブルは警告で示され、それ以外は復元されます。削除済みの復元ポイントへの復元は拒否されます。また、ロードの実行中は復元できません。

## プロジェクトの複製

**サマリー** の **アクション ▾ > 複製…** メニューでは、指定した名前でプロジェクトをコピーします。コピーには、テンプレート、モデルへの編集内容、メトリックと分析パスが保持され、サンプルデータがロードされます。ソースは接続されていないため、ロードする前にコピー先でソースを接続してください。コピーの作成中も作業を続けることができ、準備ができたら **プロジェクトを開く** でコピーに移動できます。

## マイテンプレートとして保存

プロジェクトのセットアップを保存して、次のクライアントやエンティティで再利用できます。**サマリー** の **アクション ▾ > マイ テンプレートとして保存…** メニューを開き、ドキュメントアカウントを選択して、ファイルに名前を付けます。名前の末尾に `.zip` を付けなかった場合は自動的に追加されます。既存のファイルへの上書き保存は拒否されるため、別の名前を選択してください。

このファイルには、プロジェクトの構造、モデルへの編集内容、メトリックと分析パス、エンティティと勘定科目のビジネス名、およびテンプレートの構成テーブルの行（[サービス提供コスト](/ja/guides/projects/cost-to-serve/)のアクティビティマップや[業務移転価格](/ja/guides/projects/operational-transfer-pricing/)のポリシー範囲など）が保持されます。接続、ファイル、夜間スケジュール、実行、復元ポイント、取締役会資料、およびアクセス権を持つユーザーは含まれません。

使用するには、プロジェクトを作成し、**開始元** で **テンプレート ファイルから** を選択して、ドキュメントアカウントとパスを指定します。新しいプロジェクトは自分専用で、すべてのソースは接続待ちの状態です。後でテンプレートのリリースが行われると、編集したステップを避けて変更がマージされます。パスにファイルがない場合は何も作成されず、その旨が通知されます。ドキュメントアカウントを読み取れるユーザーであれば誰でも、このファイルからインストールできます。別のワークスペースで使用するには、ファイルをダウンロードしてそのワークスペースにアップロードしてください。

## Ask で未解決の質問を解決する

ロード後も、プロジェクトには回答を待っている事項が 3 つ残っている場合があります。勘定科目表でタイプが指定されていない勘定科目、複数のソースで使用されているコード、およびファイル内でどれとも一致しなかった列です。これらの解決をアシスタントに依頼できます。MCP 経由の AI アシスタントから、**Resolve Data Foundation residue** プロンプトを使用してください。アシスタントは待機中の事項を読み取り、項目ごとに理由を添えて 1 つの回答を提案します。

アシスタントは何も書き込みません。Weave AI チャットでも、プロジェクトが何を待っているかを確認できます（[Weave AI チャット](/ja/guides/ai-assistant/weave-tab/#data-foundation)を参照）。また、MCP で接続されたエージェントは、質問を自ら読み取って回答できます（[MCP で接続された AI エージェントでの Data Foundation の使用](/ja/integrations/ai-coding-agents/data-foundation/)を参照）。提案された回答は、自分で回答する場合と同じ場所で適用します。勘定科目とコードは **質問** ページで、ファイルの列はそのファイルのマッピングで適用します。アシスタントがエンティティを提案することはありません。**質問** の質問には、Weave 自身の提案がすでに含まれている場合があります。[Data Foundation のページ](#data-foundation-のページ)を参照してください。

## プロジェクトの引き継ぎ

クライアントなど、他の人のためにプロジェクトを設定した場合は、次の手順で仕上げます。

- **最新の状態に保つ。** **ロード** をスケジュールします。[最新の状態を保つ](#最新の状態を保つ)を参照してください。
- **共有する。** プロジェクトの **アクセスと共有** ページで、チームにアクセス権を付与します。[プロジェクトアクセスの管理](/ja/guides/projects/managing-projects/#プロジェクトアクセスの管理)を参照してください。
- **記録を残す。** **サマリー** の **アクション ▾ > 証跡パックをダウンロード** で、**ステータス**、**ソース**、**カバレッジ**、**マッピング**、**連結**、**照合**、**前回の読み込み** の各シートを含む Excel ブックをダウンロードできます。ロードされた内容とそのロード元、コードのマッピング方法、グループが一致していること、前回のロードの結果が記録されています。ダウンロードしたユーザーの行アクセスが適用され、プロジェクトでロールを持つユーザーであれば誰でもダウンロードできます。
- **引き継ぐ。** オーナーをプロジェクトのアーキテクトにしてから、自分をメンバーから削除します。全員にグループの結果の閲覧を許可することや、プロジェクトに Data Foundation を追加することなど、一部の選択はアーキテクトのみが行えます。

## テンプレートでモデルを拡張する

テンプレートは、レポートとモデルを Common Finance Model 上に構築するため、どの ERP からデータが供給されても同じように動作します。**企業収益性**などのテンプレートからプロジェクトを開始すると、次のものが作成されます。

- 空の、またはサンプルデータが入った [Common Finance Model のテーブル](#common-finance-model-のテーブル)。
- これらのテーブルから構築された**エンティティ**、**勘定科目**、**部門**、**顧客**、**製品**、**セグメント 1**、**セグメント 2** の各ディメンション。[階層](#階層)を参照してください。
- **ロード**ワークフローと、それが実行するワークフロー。これらは ERP とファイルを読み取り、適合させ、準備状況をチェックし、テンプレートのモデルを構築します。
- テンプレート独自のレポートとモデル。**企業収益性**は、収益、売上原価、売上総利益、直接および間接の営業費用、貢献利益、営業利益を含む損益計算書テーブルに加えて、前年比および予算比の利益ブリッジを追加します。
- 結果について質問するためのメトリックと分析パス。

**開始元** では、**Data Foundation** はモデルとそのレポートのみです。3 つのソリューションはいずれも Data Foundation を含み、独自のモデルを追加し、レールに **配賦** を表示します。

| ソリューション | 追加される内容 |
|---|---|
| **企業収益性** | 損益計算書と利益ブリッジ。 |
| **サービス提供コスト** | 各顧客へのサービス提供にかかるコストと、それを差し引いた後の利益。[サービス提供コスト](/ja/guides/projects/cost-to-serve/)を参照してください。 |
| **業務移転価格** | ポリシー範囲に対する各エンティティの利益水準と、その調整。[業務移転価格](/ja/guides/projects/operational-transfer-pricing/)を参照してください。 |

**テンプレート ファイルから** は、保存したプロジェクトから開始します。[マイテンプレートとして保存](#マイテンプレートとして保存)を参照してください。

独自の ERP を接続する前に試してみるには、プロジェクトの作成時に **サンプルデータで開始** にチェックを付けます。プロジェクトはすぐに最初のロードを実行するため、**サマリー** には、米ドルに換算されたユーロのエンティティを含む完全な例が表示されます。独自の ERP を接続するか独自のファイルを追加すると、サンプルは削除され、お客様のデータに置き換わります。削除が中断された場合は、次回の **ロード** で完了します。`sample` という名前の独自のフォルダーは削除されませんが、サンプルがそのフォルダーを使用している間は、そのフォルダー内の他のテーブルは読み取られないため、それらを別の名前のフォルダーに移動してください。

## Data Foundation のページ

プロジェクトの **ホーム** レールにある **Data Foundation** グループでは、データの接続、ロード、チェックを行います。表示される行については、[Data Foundation の導入](#data-foundation-の導入)を参照してください。

| ページ | 表示内容 |
|---|---|
| **サマリー** | Data Foundation の状況、数値が信頼できるかどうか、次にやること。以下を参照してください。 |
| **システム** | レポート元のすべてのシステムとその状況、前回のロード日時、**システムを追加**、および **ファイル** カード。[ERP を接続する](#erp-を接続する)、[システム](#システム)、[ERP 外のデータをファイルで追加する](#erp-外のデータをファイルで追加する)を参照してください。 |
| **質問** | 回答を待っているすべての事項。以下を参照してください。 |
| **レポート** | ペルソナ別のダッシュボード（それぞれ新しいタブで開きます）と **取締役会資料** カード。[ダッシュボード、メトリック、分析パス](/ja/guides/projects/data-foundation-dashboards/)と[取締役会資料](#取締役会資料)を参照してください。 |
| **配賦** | ソリューションで作成したプロジェクトで、**配賦ルール** を開きます。[配賦ルール](#配賦ルール)を参照してください。 |

**サマリー** は上から次のように構成されています。

- プロジェクトの状況を示す 1 行と、**財務システムを追加**、**ロード**、**1 件の質問に回答**、**常に最新の状態に保つ**、**レポートを開く** など、次の 1 つのステップを示すボタン、および **この数値を説明** を含む純利益の行。[数値の説明](#数値の説明)を参照してください。
- 複数のエンティティがあるプロジェクトでは、**グループ**：グループの完全性、報告通貨、会計年度の開始月と、**プロジェクトの設定** を開く **変更**。
- **数値は信頼できますか?** 欄の 5 つの保証。システムが 1 つの場合は **Your system**、変更がある場合は **変更点**、および **月を締める**。[Data Foundation：数値は信頼できますか?](/ja/guides/projects/data-foundation-proof/)を参照してください。
- **Weave に質問**：最初に尋ねる質問の例。
- **履歴**：各回答、照合、締め、修正再表示が、実行者、日時、変更前の値とともに記録されます。**履歴を表示** をクリックすると一覧が表示され、**さらに表示** で古いエントリが表示され、**エクスポート** で Excel ブックとしてダウンロードできます。
- **ソースの対象範囲**：2 つのソースが同じ月を提供している場合に、どのソースを採用するかを選択します。[どのソースをいつから採用するかを選択](#どのソースをいつから採用するかを選択)を参照してください。

行アクセスによって一部のエンティティしか表示されない場合、**サマリー** に **これらの数値は、アクセス権のある事業体のみを対象としており、会社全体ではありません。** メッセージが表示されます。

**サマリー** の上部にある **アクション ▾** には、**階層…**、**夜間に更新**、**証跡パックをダウンロード**、**複製…**、**復元…**、**マイ テンプレートとして保存…** メニュー項目があります。[階層](#階層)、[最新の状態を保つ](#最新の状態を保つ)、[プロジェクトの引き継ぎ](#プロジェクトの引き継ぎ)、[プロジェクトの複製](#プロジェクトの複製)、[復元ポイント](#復元ポイント)、[マイテンプレートとして保存](#マイテンプレートとして保存)を参照してください。プロジェクトを変更する項目を使用できるのは、プロジェクトを変更できるユーザーのみです。

**質問** には、回答を待っているすべての事項が対象ごとにグループ化され、各対象の質問数とともに一覧表示されます。システムを追加すると、すでに接続されているシステムと同じコードを使用しているかどうかなど、コードごとではなく対象ごとに 1 つの質問に回答します。数値から行を保留している質問には、その行数と金額が示されます。**Weave suggests:** 欄には、Weave の回答とその根拠が表示されます。**この回答を使用** をクリックするか、一覧で別の回答を選択して **回答** をクリックします。**提案をすべて承認** をクリックすると、提案があるすべての質問に回答します。回答は次回の **ロード** または **変更を適用** で適用されます。**質問** 行は、質問が待機している間のみ表示されます。

ソースを変更すると、すべてのページの上部に **ソースを変更しました。使用するには「変更を適用」を押してください。** メッセージのバーが表示されます。このバーには **変更内容を表示** と **変更を適用** があり、変更を適用できるのはこのバーだけです。**ロード** または **変更を適用** の結果は、開いているページの上部に表示されるため、どのページでも確認できます。

ロードの実行中、ページは自動的に更新され、1 回の読み取りが失敗しても読み取りを続けます。ステータスを読み取れない場合は、**Foundation のステータスを読み取れませんでした。** メッセージが **再試行** とともに表示され、これをクリックすると改めて読み取ります。ページはメッセージを表示する前に自動的に 1 回再試行し、サーバーが応答するとメッセージは消えます。

## Common Finance Model のテーブル

Data Foundation は、ERP かファイルかを問わず、すべてのソースを同じテーブルに適合させるため、それらの上に構築されたレポート、メトリック、モデルは、ソースにかかわらず同じように動作します。各行には、ソースシステムと読み取り日時も記録されます。**データセット** 列は、ファイルを追加するときに選択する名前です。

| データセット | テーブル | 内容 |
|---|---|---|
| エンティティ | `cfm_entity` | 親、現地通貨とグループ通貨、国、リージョン、事業部を持つ法人。 |
| コードマップ | `cfm_code_map` | ソース上のコード（エンティティ、勘定科目、部門のコードなど）から正規のコードへの対応表。[エンティティ対応表](#エンティティ対応表)と[ソース間でのコードのマッピング](#ソース間でのコードのマッピング)を参照してください。 |
| 為替レート | `cfm_fx_rate` | 通貨ペアごとの月次の平均レート、期末レート、ヒストリカルレート。[為替レート](#為替レート)を参照してください。 |
| 会計カレンダー | `cfm_fiscal_calendar` | エンティティの会計期間ごとに 1 行。開始日と終了日、および締め済みかどうかを含みます。 |
| 勘定科目表 | `cfm_account` | 親、タイプ（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、財務諸表、正常残高、レートタイプ、勘定科目ロールを持つ勘定科目。現金、売掛金、買掛金、利益剰余金などのロールによって、勘定科目が表示される財務諸表とキャッシュフローの行が決まります。 |
| 部門 | `cfm_department` | 親とプロフィットセンターを持つ部門およびコストセンター。 |
| プロフィットセンター | `cfm_profit_center` | 親を持つプロフィットセンター。 |
| 製品 | `cfm_product` | 親、ファミリー、グループ、単位、標準原価を持つ製品マスター。 |
| 顧客 | `cfm_customer` | 親、グループ、地域、国を持つ顧客マスター。顧客名はマスクされません。 |
| セグメント値 | `cfm_segment` | 名前と親を持つセグメント値。[階層](#階層)を参照してください。 |
| 総勘定元帳 | `cfm_gl_journal` | 取引通貨、現地通貨、報告通貨での仕訳明細。 |
| 試算表 | `cfm_trial_balance` | エンティティ、勘定科目、部門別の期間の借方、貸方、純額（現地通貨および報告通貨）。 |
| 売上明細 | `cfm_sales_line` | 数量、総額、値引き、純額、売上原価の金額を含む請求済みの売上明細。 |
| パイプライン | `cfm_opportunity` | 営業パイプライン。ステージを問わず、商談明細ごとに 1 行、月末ごとに 1 コピー。 |
| 在庫残高 | `cfm_inventory_balance` | 製品および倉庫別の期末在庫。 |
| 予算 | `cfm_budget` | シナリオ、バージョン、勘定科目、部門別の予算と予測。 |
| 評価別の CO-PA | `cfm_copa` | エンティティ、期間、勘定科目、製品、顧客別の SAP 収益性分析（CO-PA）。評価（法的、グループ、プロフィットセンター）ごとに 1 セットの行があり、合算されることはありません。収益は正、コストは負の値です。テンプレートのうち、これを読み取るのは[Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/#co-paマージン)のみです。 |
| 配賦ドライバー | `cfm_stat_driver` | 人員数、平方フィート、数量などの統計ドライバー。 |

モデルには補助元帳とそのマスターも含まれ、それらを持つシステムからデータが供給されます。

| テーブル | 内容 |
|---|---|
| `cfm_site` | サイト：工場、倉庫の所在地、または事業所。それぞれ 1 つのエンティティに属します。 |
| `cfm_supplier` | 仕入先マスター。 |
| `cfm_sales_rep` | 営業担当者マスター。 |
| `cfm_project` | プロジェクトマスター。マーケティングキャンペーンもプロジェクトです。 |
| `cfm_standard_cost` | 製品、原価計算エンティティ、期間別の単位あたり標準原価。 |
| `cfm_system_balance` | 各システム独自の、月末ごとの勘定科目別期末残高。仕訳明細からではなく、システムの残高レポートから読み取ります。 |
| `cfm_supplier_invoice_line` | 仕入先請求書の明細。 |
| `cfm_purchase_order_line` | 発注書の明細。月末ごとに 1 コピー。 |
| `cfm_open_item` | 未決済の売掛金と買掛金。月末ごとに 1 コピー。 |
| `cfm_payment` | 入金と支払。 |
| `cfm_order_line` | 受注明細。月末ごとに 1 コピー。 |
| `cfm_asset` | 固定資産台帳。 |
| `cfm_asset_movement` | 帳簿と期間別の資産の増減：取得、減価償却、除却、振替。 |
| `cfm_contract` | 契約とサブスクリプション。月末ごとに 1 コピー。 |
| `cfm_deferred_revenue_movement` | 契約と期間別の繰延収益の増減。 |
| `cfm_bank_balance` | 銀行口座とその月末の帳簿残高。 |
| `cfm_inventory_movement` | 在庫の増減：入庫、出庫、生産、振替、調整、評価減。 |

月末ごとに 1 コピーを保持するテーブルでは、ロードのたびに未締めの月のコピーが置き換えられます。伝票テーブルには `counts` 列があり、エンティティと月について計上対象となるシステムの、プロジェクトが報告する帳簿の行で計上されるものは `1`、別のシステムや帳簿から保持されている行は `0` です。レポートとメトリックは、計上される行のみを読み取ります。

Foundation プロジェクトには、これらのテーブルが共有する列（`entity`、`account`、`department`、`profit_center`、`product`、`customer`、`period`、`site`、`supplier`、`sales_rep`、`project`）用の[プロジェクト要素](/ja/guides/projects/data-model/)が最初から含まれています。各要素には説明が付いており、該当する場合はタイプとディメンションも設定されているため、これらの列を持つどのテーブルでも同じ意味が表示されます。Data Foundation は、プロジェクトにないものを追加し、編集済みのものはそのまま残します。これはすべての ERP とファイルソースに当てはまります。

期間は `YYYY-MM` 形式で記述され、取引は転記期間に基づいて配置されます。予算は省略可能です。予算のない ERP でも、それ以外のデータはすべてロードされます。

試算表ファイルには、借方と貸方の列、純額の列、またはその両方を含めることができます。借方と貸方のみの場合、純額は借方から貸方を差し引いた値となり、空欄はゼロとして扱われます。純額のみの場合、正の純額は借方となり、負の純額は正の金額として貸方となります。部門の列は省略可能です。

## トラブルシューティング

| 症状 | 対応 |
|---|---|
| **接続をテスト**で、ERP が資格情報を拒否したと表示される | 接続の資格情報と、統合ユーザーが ERP にサインインできることを確認してください。 |
| **接続をテスト**で、データセットに**権限が不足しています**と表示される | ERP 管理者に、表示された権限を追加するよう依頼してください。お使いの ERP の[接続ガイド](/ja/guides/connections/)に、接続に必要な権限が記載されています。 |
| ERP のエラーメッセージが ERP 自体のメッセージより短い | PlaidCloud は、プロバイダーのエラーを表示する前に資格情報、トークン、キーを削除するため、一部の詳細が省略されます。**接続をテスト**を実行して、影響を受けるデータセットを確認してください。 |
| ある期間の **Every month loaded** が失敗している | その期間の ERP の読み取りが失敗しました。もう一度 **ロード** を実行してください。ロード済みの期間はスキップされます。 |
| **Every account known** が失敗している | 不足している勘定科目を ERP またはファイルの勘定科目表に追加し、もう一度 **ロード** を実行してください。 |
| **Every amount has a rate** が失敗している | その期間について、エンティティの通貨から報告通貨へのレートがないか、単一の報告通貨が見つかりませんでした。**為替レート** ファイルにレートを追加するか、接続が ERP の為替レートを読み取れることを確認するか、プロジェクト変数 `reporting_currency` を設定してください。その後、もう一度 **ロード** を実行してください。 |
| **Every amount has a rate** が注意になっている | 貸借対照表、在庫、または予算の行に、その期間の期末レート、ヒストリカルレート、または計画レートがありません。損益計算書には影響しません。予算の月の計画レートを含めてレートを追加し、もう一度 **ロード** を実行してください。 |
| **Codes mapped** が失敗している | **質問** を開き、各質問に回答します。回答は次回の **ロード** または **変更を適用** で適用されます。 |
| **One source for each key** が失敗している | **サマリー** の **ソースの対象範囲** で、月とソースを選択し、**選択を保存** をクリックしてから、**変更を適用** をクリックしてください。 |
| 内部取引チェックが赤または黄色になっている | **内部取引ペア** のペアを確認してください。不足している側を計上するか、明細に取引先を追加するか、不足しているレートを追加してください。 |
| **Group views are off** | アーキテクトに、**プロジェクトの設定** の **グループと行のアクセス** で **プロジェクトの全員がグループの結果を閲覧できる** にチェックを付けるよう依頼してください。 |
| スケジュールされたロードがスキップされた | スケジュールを設定したユーザーが、システムの接続を使用できなくなっています。スケジュールをもう一度設定してください。[最新の状態を保つ](#最新の状態を保つ)を参照してください。 |
| **Every entity known** が失敗している | エンティティをエンティティマスターに追加するか、**コードマップ** ファイルでそのコードを既存のエンティティにマッピングして、もう一度 **ロード** を実行してください。 |
