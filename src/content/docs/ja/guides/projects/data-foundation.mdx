**Data Foundation** は、PlaidCloud プロジェクトのための財務データ基盤です。その **Common Finance Model** は、複数の ERP システムと、それぞれの複数のインスタンスから集めた ERP データを、1つの勘定科目表、1つのエンティティセット、1つの報告通貨を持つ単一のモデルに統合します。このモデルの上に構築されたレポート、メトリック、AI アシスタントは、どの ERP 由来のデータであっても、すべて同じ数値を読み取ります。

ERP は PlaidCloud の接続を通じて接続されるため、総勘定元帳、試算表、マスターデータ、予算は、エクスポートの必要なく、ソースから直接取り込まれます。ファイルは、為替レート、配賦ドライバー、ERP の外部で管理されている予算など、システムが保持していないデータを補い、対象範囲の ERP の行を置き換えることもできます。**ロード**は、すべてのソースをモデルに適合させ、報告通貨に換算し、合計が一致することをチェックします。これらはすべてプロジェクトの **Foundation** タブから実行します。**企業収益性**などのテンプレートは、その上にレポートとモデルを構築します。

## ERP を接続する

ERP は PlaidCloud の接続を通じて Data Foundation に接続されます。Data Foundation は、総勘定元帳、試算表、マスターデータ、為替レート、予算をその接続から直接読み取り、読み取りのみを行います。既存の接続を選択することも、タブ上で新しく作成することもできます。各 ERP のアクセス設定については、[接続ガイド](/ja/guides/connections/)を参照してください。

<Steps>

1. Analyze で**プロジェクト**を開き、**新規プロジェクト**をクリックします。名前を入力し、**開始元**で**空のプロジェクト**ではなく、**企業収益性(テンプレート)** などのテンプレートを選択します。**作成**をクリックします。

   プロジェクトが **Foundation** タブで開きます。共有するまでは、プロジェクトはあなただけに公開され、あなたが唯一のアーキテクトです。

2. **Foundation** タブで、ERP 用の既存の接続を選択するか、**新しい接続を作成**を選択します。既存の接続ごとに、その接続をすでに使用しているワークフローが一覧表示されます。使用されていない場合は、**どのワークフローでもまだ使用されていません**と表示されます。

3. 新しい接続の場合は、**接続名**を入力し、**環境**を選択して、ERP 接続で求められる認証情報を入力します。

   認証情報がまだない場合は、ERP 管理者宛てのアクセスリクエストがフォームに用意されています。**リクエストをコピー**または**リクエストをメールで送信**をクリックして送信し、返ってきた値を入力します。

4. **接続をテスト**をクリックします。PlaidCloud がサインインし、各データセットの読み取りを試して、それぞれを**読み取り可能**、**権限が不足しています**、**エラー**のいずれかで一覧表示します。不足がある場合は、ERP 管理者に追加を依頼する権限名が表示されます。

5. **履歴の月数**を設定します。ロードする過去の月数を1～120で指定します。デフォルトは24です。

6. 既存の接続の場合は、ロードするエンティティにチェックを付けます。すべてチェックなしのままにすると、すべてのエンティティがロードされます。非アクティブなエンティティと消去エンティティは、表示を選択するまで非表示のままです。その後、**接続**をクリックします。

7. 新しい接続の場合は、**接続**をクリックして作成します。次に、ロードするエンティティにチェックを付け、もう一度**接続**をクリックして保存します。保存するまでは、すべてのエンティティがロードされます。

</Steps>

接続されると、カードには、プロジェクトがロードする接続、環境、エンティティ、履歴の月数が表示されます。

各ロードで読み取るのは変更された部分だけです。未締め期間と最後の締め済み期間は再度読み取られ、すでにロード済みの締め済み期間は保持されます。**履歴の月数**を増やすと、追加された月だけが読み取られます。為替レート、エンティティ対応表、報告通貨が変更された場合は、影響を受ける月が再度読み取られます。

## ERP 以外のデータ用にファイルを追加する

ファイルは、為替レート、配賦ドライバー、[エンティティ対応表](#エンティティ対応表)、ERP の外部で管理されている予算など、システムが保持していないデータで ERP 接続を補います。各ファイルは、[Common Finance Model のテーブル](#common-finance-model-のテーブル)に一覧表示されたデータセットのいずれかに属します。

<Steps>

1. **ファイル**で、ファイルを保存する**ドキュメントアカウント**を選択します。

2. **CSV または Excel ファイルをここにドロップ**にCSVまたはExcelファイルをドロップするか、**ファイルを選択**をクリックします。ファイルは、ドキュメントアカウントの `/foundation/` フォルダーにアップロードされます。

   すでにドキュメントアカウントにあるファイルの場合は、その**ファイルパス**（例：`/foundation/budget.csv`）を入力して、**ファイルを追加**をクリックします。

3. PlaidCloud がファイルを読み取り、マッピングを提案します。

   - **区切り文字、小数点、日付の検出。** 区切り文字（カンマ、セミコロン、タブ、パイプ）、小数点の区切り文字、日付形式が自動的に検出されます。
   - **データセット**：ファイルが属する Common Finance Model のテーブル。ファイル名と列見出しから判定されます。判定が明確でない場合は、一覧から選択します。
   - **小数点の区切り文字**：**ピリオド (1,234.56)** または **カンマ (1.234,56)**。
   - **日付形式**：ファイルに日付がある場合に表示されます。検出された形式が誤っている場合は、`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY`、`MM/DD/YYYY` から選択して変更します。
   - **ファイル内の列**、**タイプ**、**例**、**対応先**のグリッド。**対応先**を変更すると、列を別のフィールドに割り当てるか、**ロードしない**に設定できます。

4. 各列の割り当て先を確認し、**マッピングを確定**をクリックします。

</Steps>

PlaidCloud がデータセット、小数点の区切り文字、日付の順序を自動的に判断できない場合（たとえば、日付が日/月とも月/日とも読めるファイルなど）は、確定する前に選択を求められます。同じデータセットに対して2つ目のファイルを追加すると、1つ目のファイルが置き換えられます。

受け付けるファイルは、CSV、TSV、TXT のテキストファイル、Excel の `.xlsx` ファイル（最初のシートを読み取り）、Parquet ファイルです。

<Aside type="note">
ファイルが存在しない、または空の場合でも、ロードが停止することはありません。追加時にはマッピングする対象がまだない旨が表示され、ロードはパスを示す警告付きで完了し、そのデータセットは空のままになります。ファイルが用意できたら、もう一度追加してください。
</Aside>

## データをロードする

**ロード**カードまたは**前回のロード**カードで**ロード**をクリックします。ロードでは、接続済みの ERP と確定済みのファイルを読み取り、Common Finance Model に適合させ、報告通貨に換算し、準備状況のチェックを実行して、テンプレートのモデルを再構築します。

- プロジェクトごとに同時に実行できるロードは1つだけです。2回目の**ロード**では、すでにロードが実行中であることが表示されます。
- 他のワークフローが同じ ERP 接続を使用している場合、最初のロードでそれらが一覧表示され、確認を求められます。ロードは ERP から読み取るため、それらのワークフローが遅くなる可能性があるからです。続行するには**このままロード**をクリックします。
- 失敗したロードは赤で表示され、以前の結果の陰に隠れることはありません。以前のロードの行には、ロードが成功するまで**以前のロードの結果です。もう一度ロードしてください。** と表示されます。
- 1つのエンティティと期間の読み取りに失敗しても、残りはロードされます。**ロード**をもう一度実行すると、失敗した部分だけが取得されます。

### ERP データとファイルの併用

ファイルが置き換えるのは、そのファイルが対象とする範囲だけで、ERP のその他の行はそのまま残ります。

- **マスターファイル**（勘定科目、部門、顧客、製品、セグメント値）は、同じコードを持つ ERP の行を置き換えます。
- **トランザクションファイル**は、同じエンティティと月の ERP の行を置き換えます。総勘定元帳と試算表のファイルは、さらに元帳でも照合されます。予算ファイルはシナリオで、統計ドライバーファイルはシナリオとドライバーで照合されます。

ファイルが後からある月を対象としなくなった場合、その月の ERP のデータは次回のロードで戻ります。

## エンティティ対応表

各ソースは、それぞれ独自のコードでエンティティを指定します。**エンティティ対応表**は、これらのコードをエンティティマスターのエンティティに対応付けるため、すべてのソースの明細が同じエンティティに集約されます。

使用するには、CSV または Excel ファイルを追加し、**エンティティ対応表**データセットを選択します。

| 列 | 内容 |
|---|---|
| `source_entity` | 会社コードなど、ソースが保持しているコード。 |
| `entity` | エンティティマスターで指定されている、そのコードが属するエンティティ。 |

- 対応表にないコードは、そのまま使用されます。
- 複数のコードを1つのエンティティに対応付けることができます。それらの明細は統合され、すべてのコードで締められた時点で、その月は締め済みとして扱われます。
- 対応表のコードはすべてのソースに適用されるため、各ソースのエンティティコードはソース間で一意である必要があります。
- **エンティティ**ファイルの行は、同じエンティティコードを持つ ERP のエンティティを置き換えます。

**未マッピングのエンティティ**チェックは、エンティティがエンティティマスターになく、対応表でもマッピングされていない明細にフラグを付けます。エンティティマスターがロードされるまでは、**– 対象外**と表示されます。

## 通貨換算

各ロードでは、総勘定元帳、試算表、売上、在庫、予算の金額を、現地通貨から1つの報告通貨に換算します。レポートとモデルは換算後の金額を読み取るため、異なる通貨のエンティティが、どのシステム由来であっても、正しく合計されます。

### 報告通貨

報告通貨を選択するには、プロジェクト変数 `reporting_currency` に `USD` などの通貨コードを設定します。[プロジェクト変数の管理](/ja/guides/projects/managing-projects/#プロジェクト変数の管理)を参照してください。テンプレートはこの変数を空の状態で作成します。空のままの間、各ロードでは、次のうち通貨を1つだけに特定できる最初のものが使用されます。

1. エンティティのグループ通貨。
2. 最上位エンティティ（親を持たないもの）の現地通貨。
3. ファイルの現地通貨。

いずれも通貨を1つだけに特定できない場合、`reporting_currency` を設定するまで、**通貨換算**に問題が表示されます。

すでに報告通貨になっている金額はそのまま保持されるため、すべてのデータが1つの通貨であるプロジェクトではレートは不要です。

売上、在庫、予算のファイルにも通貨を含めることができます。`Currency` または `Local Currency` という名前の列をマッピングすると、自動的に認識され、ファイルの現地金額が報告通貨に換算されます。ファイルにすでにグループ金額または報告金額が含まれている場合は、そのまま保持されます。製品の標準コストは換算されません。

### 為替レート

レートは、通貨1単位をある月の報告通貨に変換するものです。換算後の金額は、現地金額にレートを掛けた値です。

- **ERP から**：各ロードで、ERP が保持している為替レートを読み取ります。
- **ファイルから**：CSV または Excel ファイルを追加し、**為替レート**データセットを選択します。ファイル内のレートは、同じ通貨と月の ERP のレートを置き換えます。ERP が報告通貨向けのレートを公開していない通貨で報告する場合や、予算月の計画レートを追加する場合は、ファイルを使用します。

| 列 | 内容 |
|---|---|
| `from_currency` | 換算元の通貨（例：`EUR`）。 |
| `to_currency` | 報告通貨（例：`USD`）。 |
| `period` | 月（`YYYY-MM` 形式）。 |
| `average_rate` | 月の平均レート。 |
| `closing_rate` | 月末のレート。 |
| `historical_rate` | 履歴レート。資本と、履歴レートが設定された勘定科目に使用されます。 |

使用されるのは、報告通貨へのレートだけです。逆向き（報告通貨から別の通貨へ）で提示されたレートは、反転されません。

### 適用されるレート

各行は、その行自身の通貨から換算されるため、所属するエンティティと異なる通貨の明細は、その明細の通貨から換算されます。行に当てはまる最初のルールが適用されます。

| 行 | レート |
|---|---|
| 統計勘定科目および非転記勘定科目 | 換算されません。 |
| すでに報告通貨になっているもの | 換算されません。 |
| レートタイプを持つ勘定科目 | そのレート：平均、期末、または履歴。履歴レートがない場合、履歴は期末レートにフォールバックします。ERP からの場合、レートタイプは勘定科目自身のレートタイプです。勘定科目表ファイルでは、レートタイプの列を `fx_rate_type` にマッピングし、`average`、`closing`、`historical` のいずれかを指定します。 |
| 売上明細 | 期間の平均レート。 |
| 在庫残高 | 期間の期末レート。 |
| 予算の行 | 総勘定元帳と同様に勘定科目ごと：損益勘定科目は平均レート、貸借対照表勘定科目は期末レート。 |
| 損益勘定科目 | 期間の平均レート。 |
| 資本勘定科目 | 履歴レート。履歴レートがない場合は期末レート。 |
| その他の貸借対照表勘定科目 | 期間の期末レート。 |

換算後の金額は丸められないため、合計にずれが生じません。

<Aside type="note">
試算表は各期間の増減を保持しているため、貸借対照表の金額は、各月の増減をその月の期末レートで換算したものです。期末レートで再換算した貸借対照表ではなく、累積換算調整勘定や会社間取引の消去もありません。換算後の金額は、損益計算書にご利用ください。
</Aside>

## 階層

各ロードでは、すべてのソースのマスターデータから7つのディメンションを再構築します。

| ディメンション | 構築元 |
|---|---|
| **エンティティ** | エンティティとその親 |
| **勘定科目** | 勘定科目表と親勘定科目 |
| **部門** | 部門とその親 |
| **顧客** | 顧客とその親顧客 |
| **製品** | 製品とその親製品 |
| **セグメント1** | `segment_1` のセグメント値 |
| **セグメント2** | `segment_2` のセグメント値 |

- 親を持たないレコード、または自分自身を親として指定しているレコードは、最上位のメンバーとしてロードされます。
- 各ロードで階層が再構築されるため、親の変更は、ディメンションではなく、ERP またはファイルで行ってください。
- 1つの階層の問題が影響するのは、そのディメンションだけです。ロードとテンプレートのモデルは引き続き完了します。
- **セグメント1**と**セグメント2**は、保持する内容に合わせて名前を変更できます（例：**クラス**と**場所**）。

ファイルからセグメント階層を提供するには、**セグメント値**データセットを選択します。

| 列 | 内容 |
|---|---|
| `segment` | 値が属するセグメント：`segment_1` ～ `segment_5`。**セグメント1**と**セグメント2**にはディメンションがあります。 |
| `segment_value` | 総勘定元帳、売上、予算の明細が保持している値。 |
| `segment_value_name` | その名前。 |
| `parent_segment_value` | 同じセグメント内の親。 |

## 準備状況チェック

各ロードの後、**準備状況**グリッドに、すべてのエンティティと期間のすべてのチェックが、次のいずれかのステータスで一覧表示されます。

| ステータス | 意味 |
|---|---|
| **● 準備完了** | チェックに合格しました。 |
| **▲ 要確認** | 確認する価値はありますが、数値は使用できます。 |
| **■ 問題** | 結果を利用する前に修正してください。 |
| **– 対象外** | このチェックの対象となるデータがまだありません。 |

チェックは次のとおりです。

| チェック | 確認する内容 |
|---|---|
| **ロード済みデータ** | すべての会計期間に総勘定元帳の明細があり、すべての ERP の読み取りが成功したこと。明細のない締め済み期間は問題となり、明細のない未締め期間は要対応となります。 |
| **試算表と総勘定元帳の一致** | 試算表が、エンティティ、期間、勘定科目ごとに総勘定元帳と一致すること。ある勘定科目について、試算表と総勘定元帳の両方に部門がある場合は、部門ごとの一致も確認します。 |
| **売上と総勘定元帳の一致** | 売上明細が、期間ごとの総勘定元帳の収益およびCOGS勘定科目と一致すること。 |
| **不明な製品/顧客** | すべての売上明細に、製品マスターと顧客マスターに存在する製品と顧客が指定されていること。 |
| **勘定科目表にない勘定科目** | すべての総勘定元帳の明細に、勘定科目表にある勘定科目が指定されていること。不明な勘定科目を持つ明細は、損益計算書から除外されます。 |
| **通貨換算** | すべての総勘定元帳、試算表、売上、在庫、予算の行に、報告通貨の金額があること。レートのない損益または売上の行は、損益計算書が換算後の金額を読み取るため、問題となります。レートのない貸借対照表、在庫、予算の行は要対応となります。まだレートのない予算月は黄色で表示されるため、予算月の計画レートをロードしてください。[通貨換算](#通貨換算)を参照してください。 |
| **未マッピングのエンティティ** | すべての総勘定元帳、試算表、売上の明細に、直接またはエンティティ対応表を通じて、エンティティマスターにあるエンティティが指定されていること。エンティティマスターがロードされるまでは対象外です。[エンティティ対応表](#エンティティ対応表)を参照してください。 |

準備完了ではない各行には、**対応**列で何をすべきかが表示されます。たとえば、勘定科目表のロード、為替レートのロード、ある期間に対する**ロード**の再実行などです。

グリッドには、対応が必要な場合にのみ表示される2つのセットアップチェックも表示されます。

| チェック | 表示される条件 |
|---|---|
| **間接費の配賦** | プロジェクト変数 `overhead_department` と `overhead_driver` のどちらか一方だけが設定されている、または `overhead_driver` に一致する配賦ドライバーがなく、配賦が何も行われない場合。両方を設定するか、両方をクリアして間接費の配賦をオフにしてください。 |
| **予算比較** | 予算の行はロードされているが、プロジェクト変数 `budget_version` が指定するバージョンに該当する行がなく、予算比較が空になる場合。 |

## 最新の状態を保つ

ERP 接続からのロードが問題なく成功すると、**前回のロード**カードに**夜間に更新**が表示されます。これをクリックすると、毎晩、お使いのタイムゾーンの2:00に**ロード**が実行されます。カードには**夜間の更新：毎晩2:00**と、設定した人が表示されます。

夜間のロードは、設定した人として実行されます。その人が ERP 接続を使用できなくなった場合は、夜間のロードがスキップされる旨がグリッドに表示されるため、再度設定してください。サンプルデータしかないプロジェクトは、スケジュールできません。

夜間のロードでファイルが存在しない、または空の場合は、エラーではなく、パスを示す警告付きで完了し、モデルの残りは引き続きロードされます。

## テンプレートでモデルを拡張する

テンプレートは、Common Finance Model の上にレポートとモデルを構築するため、どの ERP からデータを取り込んでも同じように動作します。**企業収益性**などのテンプレートからプロジェクトを開始すると、次のものが作成されます。

- [Common Finance Model のテーブル](#common-finance-model-のテーブル)。空の状態、またはサンプルデータが入った状態です。
- これらのテーブルから構築された、**エンティティ**、**勘定科目**、**部門**、**顧客**、**製品**、**セグメント1**、**セグメント2**のディメンション。[階層](#階層)を参照してください。
- **ロード**ワークフローと、ERP とファイルの読み取り、適合、準備状況のチェック、テンプレートのモデル構築のために実行されるワークフロー。
- テンプレート独自のレポートとモデル。**企業収益性**では、収益、COGS、売上総利益、直接費および間接費の営業費用、貢献利益、営業利益率を含む損益テーブルに加え、前年比および予算比のマージンブリッジが追加されます。
- 結果について質問するためのメトリックと分析パス。

ご自身の ERP を接続する前に試してみるには、プロジェクトの作成時に**サンプルデータで開始**にチェックを付けます。プロジェクトは最初のロードをすぐに実行するため、**Foundation** タブには、ユーロのエンティティを米ドルに換算した例を含む完全な例が表示されます。ご自身の ERP を接続するか、ご自身のファイルを追加すると、サンプルの行はクリアされ、お客様のデータに置き換わります。

## Foundation タブ

**Foundation** タブは、データの接続、ロード、チェックを行う場所です。次のセクションが上から順に並んでいます。

| セクション | 表示内容 |
|---|---|
| **前回のロード** | 前回のロードが成功したか、失敗したか、まだ実行中か。**ロード**、**更新**、**夜間に更新**ボタンがあります。 |
| **セットアップ** | セットアップのチェックリスト：**データを接続**、**データをロード**、**合計が一致することを確認**、**階層を確認**、**チームと共有**。現在の項目は太字で表示されます。 |
| **ファイル** | 追加した各ファイルと、そのデータセット（**総勘定元帳**や**為替レート**など）、およびマッピングが **✓ 確認済み**か **○ 確認待ち**か。 |
| **ロード済みデータ** | エンティティごとの、ロードされた最初と最後の期間、および準備ができている期間の数。 |
| **期間** | 各エンティティの会計期間と、それぞれが **✓ クローズ済み**か **○ 未締め**か。 |
| **準備状況** | 準備状況グリッド：エンティティ、期間、チェックごとに1行で、ステータスと**対応**が表示されます。 |
| 接続 | ERP を接続し、エンティティとロードする履歴の月数を選択します。 |
| **ファイル**（追加） | CSV、TSV、TXT、Excel、Parquet ファイルを追加し、列のマッピングを確定します。 |
| **ロード** | ロードを開始します。 |

ロードの実行中は、タブが自動的に更新されます。

セットアップのチェックリストで進捗を確認できます。

- **データを接続**と**データをロード**は、ソースが接続され、ロードが成功すると、自動的にチェックが付きます。
- **合計が一致することを確認**は、一致のチェックに合格すると、自動的にチェックが付きます。
- **階層を確認**：**ディメンションを開く**をクリックして、エンティティ、勘定科目、部門の階層を確認し、**確認しました**にチェックを付けます。**これはご自身で確認してください**。
- **チームと共有**：準備ができたら、プロジェクトを共有します。[プロジェクトアクセスの管理](/ja/guides/projects/managing-projects/#プロジェクトアクセスの管理)を参照してください。

## Common Finance Model のテーブル

Data Foundation は、ERP かファイルかを問わず、すべてのソースを同じ15のテーブルに適合させるため、それらの上に構築されたレポート、メトリック、モデルは、ソースが何であっても同じように動作します。各行には、ソースシステムと読み取られた日時も記録されます。**データセット**列は、ファイルを追加するときに選択する名前です。

| データセット | テーブル | 内容 |
|---|---|---|
| エンティティ | `cfm_entity` | 法人エンティティ。親、現地通貨とグループ通貨、国を含みます。 |
| エンティティ対応表 | `cfm_entity_map` | ソースのエンティティコードと、それぞれが属するエンティティ。[エンティティ対応表](#エンティティ対応表)を参照してください。 |
| 為替レート | `cfm_fx_rate` | 通貨ペアごとの月次の平均、期末、履歴レート。[為替レート](#為替レート)を参照してください。 |
| 会計カレンダー | `cfm_fiscal_calendar` | エンティティの会計期間ごとに1行。開始日と終了日、および締め済みかどうかを含みます。 |
| 勘定科目表 | `cfm_account` | 勘定科目。親、タイプ（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、財務諸表、通常残高、レートタイプを含みます。 |
| 部門 | `cfm_department` | 部門とコストセンター。親とプロフィットセンターを含みます。 |
| 製品 | `cfm_product` | 製品マスター。親、ファミリー、グループ、数量単位、標準コストを含みます。 |
| 顧客 | `cfm_customer` | 顧客マスター。親、グループ、地域、国を含みます。顧客名はマスクされません。 |
| セグメント値 | `cfm_segment` | セグメント値。名前と親を含みます。[階層](#階層)を参照してください。 |
| 総勘定元帳 | `cfm_gl_journal` | 取引通貨、現地通貨、報告通貨での仕訳明細。 |
| 試算表 | `cfm_trial_balance` | エンティティ、勘定科目、部門ごとの期間の借方、貸方、純額（現地通貨と報告通貨）。 |
| 売上明細 | `cfm_sales_line` | 請求済みの売上明細。数量、総額、値引き、純額、COGS の金額を含みます。 |
| 在庫残高 | `cfm_inventory_balance` | 製品と倉庫ごとの期末在庫。 |
| 予算 | `cfm_budget` | シナリオ、バージョン、勘定科目、部門ごとの予算と予測。 |
| 配賦ドライバー | `cfm_stat_driver` | 従業員数、平方フィート、単位数などの統計ドライバー。 |

期間は `YYYY-MM` と表記され、取引は転記期間で配置されます。予算は任意です。予算を持たない ERP でも、それ以外のすべてがロードされます。

試算表ファイルには、借方と貸方の列、純額の列、またはその両方を含めることができます。借方と貸方のみの場合、純額は借方から貸方を引いた値になり、空の側はゼロとして扱われます。純額のみの場合、正の純額は借方に、負の純額は貸方に、正の金額として変換されます。部門の列は任意です。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| **接続をテスト**で、ERP が認証情報を拒否したと表示される | 接続の認証情報と、連携用ユーザーが ERP にサインインできることを確認してください。 |
| **接続をテスト**で、あるデータセットに**権限が不足しています**と表示される | 表示された権限を追加するよう、ERP 管理者に依頼してください。お使いの ERP の[接続ガイド](/ja/guides/connections/)に、接続に必要なものが記載されています。 |
| ERP のエラーメッセージが、ERP 自身のものより短い | PlaidCloud は、プロバイダーのエラーを表示する前に、認証情報、トークン、キーを削除するため、一部の詳細が省かれます。**接続をテスト**を実行して、どのデータセットが影響を受けているかを確認してください。 |
| ある期間で**ロード済みデータ**が問題になっている | その期間の ERP の読み取りに失敗しました。**ロード**をもう一度実行してください。ロード済みの期間はスキップされます。 |
| **勘定科目表にない勘定科目**が問題になっている | 不足している勘定科目を、ERP またはファイルの勘定科目表に追加し、**ロード**をもう一度実行してください。 |
| **通貨換算**が問題になっている | あるエンティティの通貨に、その期間の報告通貨へのレートがないか、1つの報告通貨が見つかりませんでした。**為替レート**ファイルにレートを追加するか、接続が ERP の為替レートを読み取れることを確認するか、プロジェクト変数 `reporting_currency` を設定してください。その後、**ロード**をもう一度実行してください。 |
| **通貨換算**が要対応になっている | 貸借対照表、在庫、予算の行に、その期間の期末レート、履歴レート、計画レートがありません。損益計算書には影響しません。予算月の計画レートを含むレートを追加し、**ロード**をもう一度実行してください。 |
| **未マッピングのエンティティ**が問題になっている | エンティティをエンティティマスターに追加するか、そのコードを**エンティティ対応表**ファイルで既存のエンティティにマッピングし、**ロード**をもう一度実行してください。 |
