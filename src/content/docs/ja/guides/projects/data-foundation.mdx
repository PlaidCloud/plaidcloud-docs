**Data Foundation** は、PlaidCloud プロジェクトのための財務データ基盤です。その **Common Finance Model** は、複数の ERP システムとそれぞれの複数のインスタンスの ERP データを、1 つの勘定科目表、1 組のエンティティ、1 つの報告通貨を持つ単一のモデルにまとめます。このモデルを基盤とするレポート、メトリック、AI エージェントは、どの ERP 由来のデータであっても同じ数値を読み取ります。

ERP は PlaidCloud の接続を通じて接続されるため、総勘定元帳、試算表、マスターデータ、予算はソースから直接届き、エクスポートの作業は不要です。ファイルは、為替レート、配賦ドライバー、ERP の外で管理している予算など、システムが保持していないデータを補い、対象範囲の ERP 行を置き換えることもできます。**ロード** はすべてのソースをモデルに整合させ、報告通貨に換算し、合計が一致することをチェックします。これらはすべてプロジェクトの **Foundation** タブから行えます。ソース間で同じコードが別の意味で使われている場合は、同じ意味かどうかを回答し、管理連結が会社間取引を消去したグループの損益計算書を構築します。**Enterprise Profitability** などのテンプレートは、その上にレポートとモデルを構築します。

## ERP を接続する

ERP は PlaidCloud の接続を通じて Data Foundation に接続されます。Data Foundation は総勘定元帳、試算表、マスターデータ、為替レート、予算を接続から直接読み取り、読み取り専用で動作します。既存の接続を選ぶことも、タブ上で新しく作成することもできます。各システムには、アクセスを付与する管理者向けのページがあり、[モデルにデータを供給できるシステム](/ja/guides/projects/data-foundation-getting-started/#モデルにデータを供給できるシステム)に一覧があります。また、[Data Foundation Coverage Matrix](/ja/reference/data-foundation-coverage-matrix/) では、どのシステムがどのデータセットを直接供給するかを確認できます。

<Steps>

1. Analyze で **プロジェクト** を開き、**新規プロジェクト** をクリックします。名前を入力し、**開始元** で **空のプロジェクト** ではなく **企業収益性(テンプレート)** などのテンプレートを選択します。**作成** をクリックします。

   プロジェクトは **Foundation** タブで開きます。共有するまでは、ご自身だけが利用でき、ご自身が唯一のアーキテクトです。

2. **Foundation** タブで、ERP の既存の接続を選ぶか、**新しい接続を作成** を選択します。既存の各接続には、その接続を使用しているワークフローが表示されます。使用しているものがなければ **どのワークフローでもまだ使用されていません** と表示されます。

3. 新しい接続では、**接続名** を入力し、**環境** を選択して、ERP 接続が求める認証情報を入力します。

   認証情報がまだない場合は、フォームに ERP 管理者宛てのアクセス依頼が表示されます。**リクエストをコピー** または **リクエストをメールで送信** をクリックして送信し、返ってきた値を入力します。

4. **接続をテスト** をクリックします。PlaidCloud がサインインして各データセットの読み取りを試し、それぞれを **読み取り可能**、**権限が不足しています**、**エラー** のいずれかで一覧表示します。不足がある場合は、ERP 管理者に追加を依頼する権限が表示されます。

5. **履歴の月数** を設定します。何か月前までさかのぼってロードするかを 1 から 120 の範囲で指定します。デフォルトは 24 です。

6. 既存の接続では、ロードするエンティティにチェックを入れます。すべてのチェックを外したままにすると、全エンティティをロードします。無効なエンティティと消去用のエンティティは、表示を選択するまで非表示です。その後、**接続** をクリックします。

7. 新しい接続では、**接続** をクリックして作成します。次に、ロードするエンティティにチェックを入れ、もう一度 **接続** をクリックして保存します。それまでは、すべてのエンティティがロードされます。

8. 別の ERP システムや別のインスタンスを追加するには、これらの手順を繰り返し、**接続** をクリックする前に **Add this as another source instead of replacing the current one** にチェックを入れます。チェックを入れない場合、新しい接続が現在のソースを置き換えます。

</Steps>

接続が完了すると、カードに、プロジェクトがロードする接続、環境、エンティティ、履歴の月数が表示されます。

各ロードでは変更があった部分だけを読み取ります。未締め期間と最後に締めた期間は再度読み取られ、ロード済みの締め済み期間は保持されます。**履歴の月数** を増やすと、追加した月だけが読み取られます。為替レート、エンティティ対応表、報告通貨を変更すると、影響を受ける月が再度読み取られます。

## ソース

プロジェクトがロードする元の ERP システムとインスタンスは、それぞれソースです。**Foundation** タブの **ソース** リストには、ソースごとに 1 行が順番に表示され、名前、最後にロードした日時、供給した行数、読み取る報告帳簿が示されます。例: `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`。まだロードされていないソースには **not loaded yet** と表示されます。確定したファイルもソースです。

ソースの **高度** を開くと、そのソースの使われ方を変更できます。

| 設定 | 内容 |
|---|---|
| **名前** | レポート、マッピングの質問、メッセージでそのソースに使うラベルです。 |
| **Place in the order** | ソースの優先順位です。2 つのソースが同じ会社の同じ月をカバーしている場合は、順位が上のソースが優先されます。 |
| **Reporting books, separated by commas** | 複数の帳簿を持つシステムで、読み取る会計帳簿です。**All reporting books** はすべての帳簿を読み取ります。 |
| **会社**、**From (2026-01)**、**To (2026-12)** | このソースが会社ごとに提供する月です。月を空にすると制限なしになります。月は年と月の形式で、たとえば `2026-03` のように書きます。 |

変更を保持するには **保存** をクリックします。ソースを削除するには **Remove this source** をクリックし、**削除** で確定します。そのソースからロードしたものはすべて削除されますが、後でもう一度接続できます。

ソースを変更しても、ERP は再度読み取られません。**前回のロード** カードには、**Apply changes** をクリックするまで **Changes not applied yet** と表示されます。**Apply changes** は、すでに取得したデータからロードを実行します。新しい優先順位、マッピング、名前、ファイルでソースを再度整合させ、モデルをリビルドします。ERP から最新のデータも取得したい場合は **ロード** をクリックします。

## ERP 以外のデータをファイルで追加する

ファイルは、為替レート、配賦ドライバー、[エンティティ対応表](#エンティティ対応表)、ERP の外で管理している予算など、システムが保持していないデータで ERP 接続を補います。各ファイルは、[Common Finance Model のテーブル](#common-finance-model-のテーブル)に挙げられたデータセットのいずれかに属します。

<Steps>

1. **ファイル** で、ファイルを保存する **ドキュメントアカウント** を選択します。

2. **CSV または Excel ファイルをここにドロップ** に CSV または Excel ファイルをドロップするか、**ファイルを選択** をクリックします。ファイルはドキュメントアカウントの `/foundation/` フォルダーにアップロードされます。

   すでにドキュメントアカウントにあるファイルについては、**ファイルパス**（例: `/foundation/budget.csv`）を入力し、**ファイルを追加** をクリックします。

   毎月新しいファイルを読み取るには、名前が一致するフォルダー内のすべてのファイルを追加します。フォルダーを入力し、**File names that** で contain、start with、end with、match exactly、match as a pattern のいずれかを選んで条件を指定し、**Add files** をクリックします。その中のフォルダーにあるファイルは読み取られません。

3. PlaidCloud がファイルを読み取り、マッピングを提案します。

   - **Detected delimiter, decimal separator and dates.** 区切り文字（カンマ、セミコロン、タブ、パイプ）、小数点の区切り文字、日付形式が自動検出されます。
   - **データセット**: ファイルが属する Common Finance Model のテーブルです。ファイル名と列見出しから照合されます。一致が明確でない場合は、リストから選択します。
   - **小数点の区切り文字**: **ピリオド (1,234.56)** または **カンマ (1.234,56)**。
   - **日付形式**: ファイルに日付がある場合に表示されます。検出された形式が正しくない場合は変更します。`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY`、`MM/DD/YYYY` のいずれかです。
   - **ファイル内の列**、**タイプ**、**例**、**対応先** のグリッド。**対応先** を変更すると、列を別のフィールドに割り当てたり、**ロードしない** に設定したりできます。

4. ファイルから生じる質問に答えます。たとえば、**Which company is this file for?**、**Which currency are the amounts in?**、**Are these amounts year-to-date or for the month?**、**Are the amounts shown in thousands or millions?**、**Are revenues shown as negative numbers?** などです。それぞれ、ファイルにまだ記載がない場合にのみ尋ねられます。

5. 各列の割り当て先を確認し、**マッピングを確定** をクリックします。処理中は、ボタンの下の注記に待機している理由が表示されます。サンプルデータが残っているプロジェクトでは、最初に確定したファイルによってサンプルも削除され、数分かかることがあります。

</Steps>

ファイルには、該当する場合に次のオプションが表示されます。

| オプション | 用途 |
|---|---|
| **Which source do these rows apply to?** | コードマップファイルを 1 つのソースに限定します。**Every source** はすべてのソースに適用します。 |
| **Where does this file come from?** | ファイルが **This project's own codes** を保持しているのか、名前を付けた **Another system**（例: `SAP Germany export`）のものなのかを指定します。別のシステムからのファイルは、ERP ソースと同様に共有コードがチェックされます。 |
| **Split … into … parts at each …**（**高度** 内） | `100-200-300` のように複数の値を保持する 1 つの列を分割し、各部分をそれぞれのフィールドに割り当てます。 |
| **Which currency do you report in?** | プロジェクトにまだ報告通貨がない場合に設定します。`USD` のように 3 文字で書きます。 |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 連結システムの結果をロードし、グループの損益計算書を[照合](#連結システムと照合する)できるようにします。 |

ファイルをプロジェクトから外すには、**ファイル** の横の **削除** をクリックするか、そのマッピングの **Remove this file** をクリックして確定します。そのファイルの数値は、次に **Apply changes** をクリックしたときにレポートから外れます。

PlaidCloud がデータセット、小数点の区切り文字、日付の順序を自動で判断できない場合（たとえば、日付が日/月とも月/日とも読めるファイルなど）、確定する前に選択するよう求められます。同じデータセットに対して 2 つ目のファイルを追加すると、1 つ目が置き換えられます。後のファイルの列がデータセットと一致しない場合、ロードはファイルと列を示し、ファイルまたは列名を修正するか、ステップの **Schema Mismatch** を `union` に設定するよう案内します。

使用できるファイルは、CSV、TSV、TXT のテキストファイル、Excel の `.xlsx` ファイル（最初のシートを読み取り）、Parquet ファイルです。

<Aside type="note">
存在しないファイルや空のファイルが原因でロードが止まることはありません。追加時にはマッピングする対象がまだないと表示され、ロードはパスを示す警告付きで完了し、そのデータセットは空のままになります。ファイルが用意できたら、もう一度追加してください。
</Aside>

## データをロードする

**ロード** カードまたは **前回のロード** カードで **ロード** をクリックします。ロードは、接続済みの ERP と確定したファイルを読み取り、Common Finance Model に整合させ、報告通貨に換算し、準備状況チェックを実行して、テンプレートのモデルをリビルドします。

- プロジェクトで同時に実行できるロードは 1 つだけです。2 つ目の **ロード** や **Apply changes** を実行すると、ロードがすでに実行中であると表示され、実行中はソースを変更できません。
- 他のワークフローが同じ ERP 接続を使用している場合、最初のロードでそれらが一覧表示され、確認を求められます。ロードは ERP から読み取るため、それらのワークフローが遅くなる可能性があるためです。続行するには **このままロード** をクリックします。
- PlaidCloud のアップグレード後は、アーキテクトの **ロード** で、プロジェクトの生成済みワークフローも更新され、必要な作業用テーブルが作成されます。それまでは、ステータスページに「The workflows were generated by an earlier release. An Architect's Load updates them.」という注意項目がアンバーで表示され、マネージャーの **ロード** では、更新できるのはアーキテクトだけであるという警告が表示されます。
- 更新を適用しても、生成されたステップに加えたご自身の編集は保持されます。ステップを変更し、更新でも同じステップが変更された場合は、ご自身の編集が保持され、ステータスページにステップ名で競合が記載されます。更新で生成されなくなった、編集済みのステップは保持されますがオフになります。まだ必要な場合は削除するか、再度オンにしてください。更新で置き換えられるステップは名前が示され、以前のステップはステップのバージョンに残ります。
- 更新が途中で止まった場合や実行中の場合は、ステータスページに表示され、完了するまでステップが順序どおりに実行されないことがあります。アーキテクトとして **ロード** をもう一度押して完了させてください。再び止まる場合は、サポートにお問い合わせください。
- 失敗したロードは赤で表示され、以前の結果の陰に隠れることはありません。連結が失敗した場合、ステータスには古いグループ結果ではなく、停止したステップの名前が表示されます。以前のロードの行には、ロードが成功するまで **以前のロードの結果です。もう一度ロードしてください。** と表示されます。
- 1 つのエンティティと期間の読み取りが失敗しても、残りはロードされます。**ロード** をもう一度実行すると、失敗した分だけが取得されます。

### 保留された行

ソースが重複している場合、ロードは各数値のコピーを 1 つだけ保持し、他のコピーは二重にカウントせず保留します。保留された行は、ソース、エンティティ、理由とともに記録され、ロードは件数を示す警告付きで完了します。例: `120 rows of NetSuite EU also provided by a source ranked ahead`。理由は次のとおりです。

| 理由 | 意味 |
|---|---|
| In another accounting book | その行は、ソースが読み取る設定になっていない報告帳簿に属しています。 |
| Outside the periods the source provides | その行は、会社に設定された **開始** と **終了** の月の範囲外です。 |
| Also provided by a source ranked ahead | 順位が上のソースが、同じ会社と月をカバーしています。 |
| Also in an earlier file of the source | 同じソースの以前のファイルが、すでにその月をカバーしています。 |
| Replaced by a file | ファイルが、そのエンティティと月の ERP 行を置き換えています。 |
| Carrying a code another source also uses | そのコードには回答が必要です。[ソース間でコードをマッピングする](#ソース間でコードをマッピングする)を参照してください。 |
| Carrying a code mapped to two codes | コードマップがそのコードに 2 つの回答を与えています。 |

統計勘定は総勘定元帳ではなく配賦ドライバーに移動し、問題ではなく移動済みとして表示されます。

### ERP のデータとファイルを併用する

ファイルが置き換えるのはファイルがカバーする範囲だけで、ERP の他の行は残ります。

- **マスターファイル**（勘定科目、部門、顧客、製品、セグメント値）は、同じコードの ERP 行を置き換えます。
- **トランザクションファイル**は、同じエンティティと月の ERP 行を置き換えます。総勘定元帳と試算表のファイルは元帳でも照合され、予算ファイルはシナリオで、統計ドライバーのファイルはシナリオとドライバーでも照合されます。

ファイルが後にある月をカバーしなくなった場合、次のロードでその月の ERP のデータが戻ります。

## エンティティ対応表

各ソースは、独自のコードでエンティティを指定します。**エンティティ対応表** は、そのコードをエンティティマスターのエンティティにマッピングし、すべてのソースの明細が同じエンティティに集まるようにします。

使用するには、CSV または Excel ファイルを追加し、**エンティティ対応表** データセットを選択します。

| 列 | 保持する内容 |
|---|---|
| `source_entity` | 会社コードなど、ソースが保持しているままのコード。 |
| `entity` | エンティティマスターでの名前によるエンティティ。 |

- 対応表にないコードは、そのまま使用されます。
- 複数のコードを 1 つのエンティティにマッピングできます。それらの明細は結合され、すべてのコードで締め済みになった月が締め済みとして扱われます。
- 対応表のコードはすべてのソースに適用されるため、各ソースのエンティティコードはソース間で一意である必要があります。
- **エンティティ** ファイルの行は、同じエンティティコードを持つ ERP のエンティティを置き換えます。

**未マッピングのエンティティ** チェックは、エンティティがエンティティマスターになく、対応表でもマッピングされていない明細にフラグを付けます。エンティティマスターがロードされるまでは、**– 対象外** と表示されます。

## ソース間でコードをマッピングする

2 つのソースが同じコードを別の意味で使っていたり、同じものに別のコードを使っていたりすることがあります。コードが複数のソースに現れる場合、Data Foundation は、そのコードがどこでも同じ意味かどうかを回答するまで該当行を保留し、各金額が 1 回だけカウントされるようにします。**Codes waiting for your answer** チェックには、最初の 10 件と「and K more」が一覧表示され、**Foundation** タブの **What to do next** カードには **確認** ボタンがあります。

**確認** をクリックすると **Codes waiting for your answer** が開きます。コードは種類ごとにグループ化されます。**Account types**、**Companies**、**勘定科目**、**部門**、**プロフィットセンター**、**顧客**、**製品**、および追加の各カテゴリーです。各コードについて、各ソースでの呼び方と提案が表示されます。

- **Looks like the same thing**: ソースがそのコードに同じ名前を付けている場合。
- **Looks like different things**: 名前が異なる場合。
- **We can't tell. Please answer.**: 判断材料がない場合。

コードごとに **Yes, the same** または **No, different** で回答するか、**Accept all**（すべての提案を採用）、**All the same**、**All different** でグループ全体にまとめて回答します。勘定科目では、勘定科目表の親グループ全体にまとめて回答することもできます。ソースにアカウントタイプがない場合は、勘定科目のグループに対して **Use this type** を選択します。**収益**、**Cost of goods sold**、**Operating expenses**、**Non-operating income and expenses**、**Assets**、**Liabilities**、**Equity** のいずれかです。

マッピングはソースとディメンションごとに保持されるため、あるソースの部門への回答が別のソースの勘定科目を変更することはありません。回答は **Saved. Press Apply changes to use your answers.** と表示されて、入力のたびに保存されます。**Apply changes** をクリックすると回答が反映されます。

マッピングはファイルで提供することもできます。**Code map** データセットのファイルを追加し、**Which source do these rows apply to?** を選択して 1 つのソースに限定します。

## どのソースをいつから採用するかを選択する

2 つのソースが同じ月を提供している場合、**Which source covers which months** チェックが選択を求めます。**What to do next** カードで **Choose which source counts from when** をクリックすると **Which source counts from when** が開き、重複が会社ごとに一覧表示されます。採用するソースを選択し、**That month is** に採用を開始する月（例: `2026-04`）を入力して、**Apply changes** をクリックします。もう一方のソースは、それより前の月を保持します。

同じダイアログは、2 つのソースが通貨に対して異なる為替レートを提供している場合にも警告します。その場合は、順位が上のソースのレートが使用されます。

## 通貨換算

ロードのたびに、総勘定元帳、試算表、売上、在庫、予算の金額が現地通貨から 1 つの報告通貨に換算されます。レポートとモデルは換算後の金額を読み取るため、どのシステム由来でも、異なる通貨のエンティティを正しく合計できます。

### 報告通貨

報告通貨を選択するには、プロジェクト変数 `reporting_currency` を `USD` などの通貨コードに設定します。[プロジェクト変数の管理](/ja/guides/projects/managing-projects/#プロジェクト変数の管理)を参照してください。テンプレートは空の状態で作成します。空のあいだは、ロードのたびに次のうち、ちょうど 1 つの通貨を示す最初のものが使用されます。

1. エンティティのグループ通貨。
2. 親を持たない最上位エンティティの現地通貨。
3. ファイルの現地通貨。

どれもちょうど 1 つの通貨を示さない場合、`reporting_currency` を設定するまで **通貨換算** に問題が表示されます。

すでに報告通貨になっている金額はそのまま保持されるため、データがすべて 1 つの通貨のプロジェクトにはレートは不要です。

売上、在庫、予算のファイルにも通貨を含めることができます。`Currency` または `Local Currency` という名前の列をマッピングすると自動的に認識され、ファイルの現地金額が報告通貨に換算されます。ファイルにすでにグループ金額または報告金額がある場合は、そのまま保持されます。製品の標準コストは換算されません。

### 為替レート

レートは、ある通貨 1 単位を、ある月の報告通貨に換算します。換算後の金額は、現地金額にレートを掛けたものです。

- **ERP から**: ロードのたびに、ERP が保持している為替レートを読み取ります。
- **ファイルから**: CSV または Excel ファイルを追加し、**為替レート** データセットを選択します。ファイル内のレートは、同じ通貨と月の ERP のレートを置き換えます。ERP が報告通貨へのレートを公開していない通貨で報告する場合や、予算月の計画レートを追加する場合は、ファイルを使用します。

| 列 | 保持する内容 |
|---|---|
| `from_currency` | 換算元の通貨。たとえば `EUR`。 |
| `to_currency` | 報告通貨。たとえば `USD`。 |
| `period` | 月。`YYYY-MM` の形式。 |
| `average_rate` | 月の平均レート。 |
| `closing_rate` | 月末のレート。 |
| `historical_rate` | 履歴レート。資本と、履歴レートに設定された勘定科目に使用します。 |

報告通貨へのレートだけが使用されます。報告通貨から別の通貨へという逆向きで提示されたレートは、逆数にはされません。

### 適用されるレート

各行は、その行自身の通貨から換算されるため、エンティティと異なる通貨の明細は、その明細の通貨から換算されます。行に適合する最初のルールが適用されます。

| 行 | レート |
|---|---|
| 統計勘定と非転記勘定 | 換算されません。 |
| すでに報告通貨になっている | 換算されません。 |
| レートタイプのある勘定科目 | そのレート（平均、期末、履歴）。履歴レートがない場合、履歴は期末レートにフォールバックします。ERP からの場合、レートタイプは勘定科目自身のレートタイプです。勘定科目表ファイルでは、レートタイプの列を `fx_rate_type` にマッピングし、`average`、`closing`、`historical` のいずれかを指定します。 |
| 売上明細 | 期間の平均レート。 |
| 在庫残高 | 期間の期末レート。 |
| 予算行 | 総勘定元帳と同様に勘定科目で決まります。損益計算書の勘定科目は平均レート、貸借対照表の勘定科目は期末レートです。 |
| 損益計算書の勘定科目 | 期間の平均レート。 |
| 資本の勘定科目 | 履歴レート。履歴レートがない場合は期末レート。 |
| その他の貸借対照表の勘定科目 | 期間の期末レート。 |

換算後の金額は丸められないため、合計にずれは生じません。

<Aside type="note">
試算表は各期間の増減を保持しているため、貸借対照表の金額は、各月の増減をその月の期末レートで換算したものです。期末レートで再換算した貸借対照表ではなく、累積換算調整額や会社間取引の消去もありません。換算後の金額は損益計算書に使用してください。
</Aside>

## 階層

ロードのたびに、すべてのソースのマスターデータからディメンションがリビルドされます。最初に 7 つのディメンションがあり、追加カテゴリーを最大 10 個まで持てます。

| ディメンション | 構築元 |
|---|---|
| **エンティティ** | エンティティとその親 |
| **勘定科目** | 勘定科目表と親勘定科目 |
| **部門** | 部門とその親 |
| **顧客** | 顧客とその親顧客 |
| **製品** | 製品とその親製品 |
| **セグメント 1** | `segment_1` のセグメント値 |
| **セグメント 2** | `segment_2` のセグメント値 |
| **セグメント 3** ～ **セグメント 10** | ソースが保持している場合の、`segment_3` ～ `segment_10` のセグメント値 |

- 親がないレコード、または自身を親として指定しているレコードは、最上位メンバーとしてロードされます。
- ロードのたびに階層がリビルドされるため、親の変更はディメンションではなく、ERP またはファイルで行ってください。
- 1 つの階層の問題は、そのディメンションにだけ影響します。ロードとテンプレートのモデルは引き続き完了します。
- 追加カテゴリーの名前は、保持する内容に合わせて、たとえば **クラス** や **リージョン** に変更できます。**Rename extra categories** で、レポートで使用する名前を入力して **Save names** をクリックします。名前に使用できるのは、文字、数字、スペース、ドット、ダッシュ、アンダースコアで、60 文字までです。
- 各ソースは、自身の追加カテゴリーが、ご自身のどのカテゴリー名に属するかを指定します。ソースの **高度** を開き、それぞれの名前を選択するか **Leave out** を選択して、**保存** をクリックします。`Class` と `Business area` のように、同じカテゴリーを異なる名前で呼んでいるソースは、1 つのスロットを共有します。

ファイルからセグメント階層を提供するには、**セグメント値** データセットを選択します。

| 列 | 保持する内容 |
|---|---|
| `segment` | 値が属するセグメント。`segment_1` ～ `segment_10`。 |
| `segment_value` | 総勘定元帳、売上、予算の明細が保持している値。 |
| `segment_value_name` | その名前。 |
| `parent_segment_value` | 同じセグメント内での親。 |

## 準備状況チェック

ロードのたびに、**準備状況** グリッドに、すべてのエンティティと期間のすべてのチェックが、次のいずれかのステータスで一覧表示されます。

| ステータス | 意味 |
|---|---|
| **● 準備完了** | チェックに合格しました。 |
| **▲ 要確認** | 確認する価値がありますが、数値は使用できます。 |
| **■ 問題** | 結果に依存する前に修正してください。 |
| **– 対象外** | このチェックの対象となるデータがまだありません。 |

チェックは次のとおりです。

| チェック | 確認する内容 |
|---|---|
| **ロード済みデータ** | すべての会計期間に総勘定元帳の明細があり、すべての ERP の読み取りが成功していること。明細のない締め済み期間は問題になり、明細のない未締め期間は要対応になります。 |
| **試算表と総勘定元帳の一致** | 試算表が、エンティティ、期間、勘定科目ごとに総勘定元帳と等しいこと。ある勘定科目について試算表と総勘定元帳の両方が部門を保持している場合は、部門ごとにも一致を確認します。 |
| **売上と総勘定元帳の一致** | 売上明細が、期間ごとの総勘定元帳の収益勘定および COGS 勘定と等しいこと。 |
| **不明な製品/顧客** | すべての売上明細が、製品マスターと顧客マスターに存在する製品と顧客を指定していること。 |
| **勘定科目表にない勘定科目** | すべての総勘定元帳の明細が、勘定科目表にある勘定科目を指定していること。勘定科目が不明な明細は、損益計算書から除外されます。転記があるのにアカウントタイプがない勘定科目も問題になり、勘定科目表で収益勘定にタイプが付いているのに売上原価の勘定科目がないソースは要対応になります。 |
| **通貨換算** | すべての総勘定元帳、試算表、売上、在庫、予算の行に、報告通貨での金額があること。損益計算書は換算後の金額を読み取るため、レートのない損益計算書または売上の行は問題になります。レートのない貸借対照表、在庫、予算の行は要対応になります。まだレートのない予算月はアンバーで表示されるため、予算月の計画レートをロードしてください。[通貨換算](#通貨換算)を参照してください。 |
| **未マッピングのエンティティ** | すべての総勘定元帳、試算表、売上の明細が、直接またはエンティティ対応表を通じて、エンティティマスターにあるエンティティを指定していること。エンティティマスターがロードされるまでは対象外です。[エンティティ対応表](#エンティティ対応表)を参照してください。 |

複数のソースがあるロードでは、次のチェックが追加されます。

| チェック | 確認する内容 |
|---|---|
| **Reporting book** | エンティティに複数の会計帳簿を持つソースで、報告帳簿が選択されていること。選択するまでは、最初の帳簿だけがカウントされます。 |
| **Codes waiting for your answer** | 複数のソースが使用しているすべてのコードに回答済みであること。[ソース間でコードをマッピングする](#ソース間でコードをマッピングする)を参照してください。 |
| **Extra categories from your sources** | ソースが保持しているすべての追加カテゴリーに、名前が付けられているか、除外されていること。 |
| **Which source covers which months** | どのソースを採用するかを選択しない限り、2 つのソースが会社の同じ月を提供していないこと。 |
| **Account types and hierarchy** | ディメンションが指定するすべての親が存在し、メンバーが自身の親または祖先になっていないこと。親が見つからない場合は、その子が階層の最上位に置かれ、ループがあるとその階層のロードが止まります。合計は影響を受けません。 |
| **会計カレンダー** | 各エンティティの会計期間が暦月であり、すべての月の行を 1 つの会計期間に割り当てられること。エンティティの期間が暦月でない場合（4-4-5、13 期間）、または月の行が複数の会計期間に属し得る場合や会計カレンダーにその月がない場合は、要対応になります。 |

準備完了でない各行には、**対応** 列に実行すべきことが示されます。たとえば、勘定科目表のロード、為替レートのロード、期間に対する **ロード** の再実行などです。

グリッドには 2 つのセットアップチェックも表示されますが、対応が必要な場合にのみ表示されます。

| チェック | 表示される場合 |
|---|---|
| **間接費の配賦** | プロジェクト変数 `overhead_department` と `overhead_driver` の片方だけが設定されているか、`overhead_driver` に一致する配賦ドライバーがなく、配賦が何も行われない場合。両方を設定するか、両方を空にして間接費の配賦をオフにします。 |
| **予算比較** | 予算行はロードされているものの、プロジェクト変数 `budget_version` が指定するバージョンに該当する行がなく、予算比較が空になる場合。 |

## 管理連結

ロードのたびに、管理連結が構築されます。これは、グループ内のすべてのエンティティの、報告通貨でのグループ損益計算書で、会社間取引が消去されています。管理会計のためのものです。法定のグループの記録は引き続き連結システムが保持するため、以下の方法でそれと照合してください。

<Aside type="note">
管理連結の対象は損益計算書のみです。法定連結や法的連結ではなく、連結貸借対照表、換算調整、のれん、少数株主持分はありません。
</Aside>

### グループを選択する

**ソース** で **グループ** を開くと、グループ内の会社が表示されます。チェックを外した会社は、単独ではレポートに残りますが、グループ合計からは除外されます。**Save group** をクリックします。変更は次の **ロード** または **Apply changes** で適用されます。新しい会社は、チェックを外すまでグループに含まれます。

グループの会計年度は、プロジェクト変数 `group_fy_start_month` で設定した月から始まります。変更しない限り `1` です。

### 得られるもの

| テーブル | 保持する内容 |
|---|---|
| **Group P&L** | エンティティ、期間、明細（収益、売上原価、営業費用、営業外、会社間差異）ごとに 1 行、報告通貨で。収益とコストは本来の符号を持ちます。 |
| **Group P&L year to date** | 同じ内容を、グループの最後に完全にロードされた期間までの年初来で。 |
| **Intercompany pairs** | エンティティ、グループ、期間のペアごとに 1 行。各側の金額と差額を含みます。 |
| **Intercompany lines** | グループの数値またはペアの裏付けとなる、取引先付きの元帳明細。 |
| **Reconciliation** | 連結システムに対するグループ損益計算書の年初来。 |

これらのテーブルには 3 つのエンティティ名が現れます。

| エンティティ | 意味 |
|---|---|
| **Eliminations** | 会社間取引の消去。合計はゼロになるため、グループの数値ではそのまま残し、消去前のエンティティ合計を求めるときはフィルターで除外します。 |
| **Group total** | 照合における連結システムの合計。 |
| **Unmapped** | 期間のない明細と、このプロジェクトにない連結システムの勘定科目またはエンティティ。 |

メトリック **Consolidated income**、**Consolidated result**、**IC difference** と、各テーブルに対応する分析パスが、グループに関する質問に答えます。

### 会社間取引の消去

会社間取引の明細は、取引先で照合されます。明細にある取引先が使用され、明細にない場合はその顧客の取引先が使用されます。ペアの両側が消去され、両側が一致しない金額は会社間差異の明細に計上されます。各ペアには理由が付きます。

| 理由 | 意味 |
|---|---|
| **一致** | 両側が同じ金額を計上した。 |
| **Only one side booked** | 1 つのエンティティが取引を計上し、その取引先は計上しなかった。 |
| **Not eliminated** | ペアのいずれかの明細に為替レートがないため、どちらの側も消去されない。 |

ペアは年初来で判定されます。**Intercompany balances** 行は、ペアの差額がプロジェクト変数 `group_amber`（デフォルト `1`）を超えるとアンバー、`group_red`（デフォルト `1000`）を超えると赤になります。取引先のない明細や、エンティティでない取引先を持つ明細は消去されず、その行にカウントされます。取引先を保持するソースと保持しないソースが併存する場合は、アンバーになります。

ソース自身の消去用エンティティはグループ損益計算書に含まれず、**連結** 行にその旨が表示されます。

### 連結システムと照合する

連結システムが報告する結果をファイルとして追加し、マッピングを確定するときに **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** にチェックを入れます。**Which version of the numbers is this?** には、システムの名前で答えます。すると **照合** テーブルに、エンティティと明細ごとの年初来の **ours**、**reported**、**差異** が表示されます。差異は通常、**Eliminations**、**Group total**、**Unmapped** の各行、またはシステムが使用する為替レートで説明できます。**Reconciliation to the source** 行には、`group_amber` を超えるすべての明細が一覧表示されます。

### 表示できるユーザー

グループの結果は、プロジェクトの行アクセスに従います。行アクセスによってグループの結果が表示されない場合、ステータスはアンバーになります。一部のエンティティしか表示できないユーザーには、それらのエンティティの消去前の合計が表示されます。**Eliminations** 行と会社間取引のテーブルには、すべてのエンティティへのアクセスが必要です。

プロジェクトが、グループのテーブルにない列（たとえば部門）で、誰がどの行を表示できるかを制限している場合、グループの結果は全員に対してオフのままとなり、**連結** に **Group views are off** と表示されます。その場合、**グループ** の **Everyone on the project may see the group results** にチェックを入れられるのはアーキテクトだけです。変更は次の **ロード** または **Apply changes** で適用されます。

## 最新の状態を保つ

ERP 接続からのロードが問題なく成功すると、**前回のロード** カードに **夜間に更新** が表示されます。これをクリックすると、お使いのタイムゾーンで毎晩 2:00 に **ロード** が実行されます。カードには **Nightly refresh: Every night at 2:00** と設定したユーザーが表示されます。

夜間のロードは、設定したユーザーとして実行されます。そのユーザーが ERP 接続を使用できなくなった場合、グリッドに夜間のロードがスキップされることが表示されます。その場合は設定し直してください。サンプルデータしかないプロジェクトはスケジュールできません。

夜間のロードでファイルが存在しない場合や空の場合は、エラーではなく、パスを示す警告付きで完了し、モデルの残りは引き続きロードされます。

## ビジネス名

**Foundation** タブの **Business names** は、モデルのコードに、ビジネスで使っている名前を付けます。レポート、メトリック、アシスタントにはこれらの名前が表示され、保存した名前はすぐに適用されます。以降のロードでも保持されます。

1. **Add a name** をクリックし、**種類** を **カテゴリー**、**P&L line**、**メトリック**、**列** から選択します。
2. **コード** を入力します。カテゴリーなら `segment_1` ～ `segment_10`、損益計算書の行ならその行のキー、メトリックならメトリックの名前、列なら `table.column` です。
3. **名前** を入力します。1 行で 60 文字までです。
4. **Save names** をクリックします。

保存すると、リスト全体が置き換えられます。名前が空の行は、その名前を削除し、**選択項目を削除** はチェックを入れた行を削除します。同じコードに 2 回名前を付けることは拒否されます。ビジネス名は、アシスタントがご自身の言葉を使えるように分析パスの説明にも書き込まれ、その説明には長さの制限があります。名前によって長すぎる場合は、何も保存されず、その旨が通知されます。

## 数値を説明する

**Explain this number** は、損益計算書の 1 つの数値が何で構成されているかを示します。**準備状況** グリッドで、エンティティと月の行に **Explain this number** があり、そのエンティティのその月の営業利益率が開きます。ウィンドウは、数値を、上部の合計に積み上がる層に分解します。

| 層 | 保持する内容 |
|---|---|
| **From the general ledger** | 元帳がその明細に転記したもの。 |
| **Allocated in** | [配賦ルール](#配賦ルール)によって、このエンティティに配分されたコスト。 |
| **Allocated out** | このエンティティが他に配分したコスト。 |
| **Eliminated in the group** | グループの結果で消去された会社間取引。 |

各層には、それが何であるかを説明する文と、最大のソース伝票が、ソースシステム、伝票、勘定科目とともに表示されます。行がある層だけが表示されます。ウィンドウはご自身の行アクセスに従い、表示できる数値だけを説明できます。裏付けのない数値には **Nothing to explain** と表示されます。

## 配賦ルール

配賦は、間接費などの共通コストを、部門、製品、顧客に配分します。モデルには 2 つのステージがあります。**Stage 1: overhead to departments** と **Stage 2: departments to products and customers** です。**Actions > Allocations...** を開くと、それぞれの方法を確認または変更できます。変更しない場合は、ウィザードが存在しなかったときと同じように動作します。閲覧者はルールを開けますが、保存はできません。

ウィザードは、ステージごとに 4 つの質問をします。

| ステップ | 質問 | 選択肢 |
|---|---|---|
| **Pool** | どのコストを配分しますか。 | 勘定科目の種類。ステージ 1 では、コストを保持している部門または **All departments**。 |
| **Driver** | 何を基準に配分しますか。 | 配賦ドライバーとしてロードした **Statistic**（人数、平方フィートなど）、**Net sales amount**、**Sales quantity**、**Spread evenly**。**Same period** または **Same period last year** のドライバーを使用します。 |
| **Target** | どこに配分されますか。 | ステージ 1: 部門。ステージ 2: 製品、顧客、またはその両方。 |
| **Method** | ドライバーが負の場合はどうしますか。 | **Ignore negative values** または **Stop and tell me**。 |

ステップの下で、`2026-09` のように年と月で書いた月の **Preview for** を使うと、保存していないルールも含め、ルールが何を行うかが表示されます。`Pool 120,000 · Allocated 120,000 · Unallocated 0`。未配賦とは、引き受けるドライバーがなかったコストです。プレビューはご自身の行アクセスに従います。

**保存** をクリックします。ルールは次の **ロード** で、または **Apply changes** をクリックしたときに有効になります。配賦ステップを手動で編集した場合、その編集は上書きされずに保持され、保存時にそのことが通知されます。ロードの実行中は保存できません。

## ボードパック

ボードパックは、結果をドキュメントアカウントのフォルダーに書き出し、すぐに送信できる状態にします。**Actions > Board pack...** を開き、**ドキュメントアカウント** と `/board-packs` のような **フォルダー** を選択して、**保存** をクリックします。以降は **ロード** のたびにパックが作成されるため、フォルダー内のファイルは直近のロードと同じ最新の状態になります。実行のたびに次が書き出されます。

- Excel ワークブック `Board pack.xlsx`。エンティティ別の損益計算書、マージンブリッジ、上位と下位の顧客が含まれます。
- 損益計算書ダッシュボードの PDF。

**Run now** をクリックすると、パックがすぐに作成され、完了するとそのファイルがフォルダーに表示されます。ダイアログには、前回の実行とその結果、および次回の実行が表示されます。**Apply changes** ではパックは作成されません。毎晩作成するには、夜間の更新を設定します（[最新の状態を保つ](#最新の状態を保つ)を参照）。それまでは、ダイアログに **Not scheduled yet** と表示されます。設定できるのは、プロジェクトを変更できるユーザーだけです。

完全には作成できないパックがあっても、ロードが失敗することはありません。

- ワークスペースでレポートがオフになっている場合、パックは Excel ワークブックのみになり、実行時に **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.** と表示されます。
- 他のユーザーが作成したダッシュボードが、Data Foundation が損益計算書ダッシュボードに必要とするアドレスをすでに使用している場合、そのダッシュボードはそのまま残され、PDF は作成されません。メッセージにはそのアドレスが示されます。他のダッシュボードに別のアドレスを付けてから、もう一度 **ロード** を実行してください。
- パックのいずれかのステップが失敗した場合、**ステータス** リストに、ステップと理由を示すアンバーの **Board pack** 行が表示されます。ロード自体は成功しています。

## 復元ポイント

復元ポイントは、**ロード** または **Apply changes** の開始時（誰が開始した場合も、スケジュールされたロードも含みます）と、マッピングやソースを変更する前に作成されます。モデルのテーブル、ディメンション、次のロードが基にする設定（ソース、ファイル、配賦ルール）が含まれます。ロード時に取得された直近 7 件のポイントと、変更前に取得された直近 5 件のポイントが保持されるため、変更によってロード時のポイントが押し出されることはありません。それより古いポイントは削除されます。

元に戻すには、**Actions > Restore...** を開きます。各ポイントには、作成日時と、その下に復元で戻るテーブルの数（例: **Puts back 12 tables.**）、および警告が表示されます。ポイントを選択して **復元** をクリックします。**復元** は、ポイントが存在する場合に利用できます。復元すると、まず現在のプロジェクトが独自のポイントとして記録されるため、再度戻ることができます。その後、テーブル、ディメンション、それらの設定が以前の状態に戻り、次のロードはそれを基に構築されます。すでに持っていたソースに復元しても、それらは変更されたものとはマークされません。ビュー、保存できないディメンション、保存されたコピーのないテーブルは警告に名前が示され、残りは復元されます。削除されたポイントへの復元は拒否され、ロードの実行中は復元できません。

## プロジェクトを複製する

**Actions > Clone...** は、指定した名前でプロジェクトをコピーします。コピーには、テンプレート、モデルへの編集、メトリック、分析パスが保持され、サンプルデータがロードされます。ソースは接続されないため、ロードする前にコピー内で接続してください。コピーの作成中も作業を続けられ、準備ができたら **プロジェクトを開く** でコピーに移動できます。

## マイテンプレートとして保存する

プロジェクトのセットアップを保存して、次のクライアントやエンティティで再利用できます。**Actions > Save as my template...** を開き、ドキュメントアカウントを選択して、ファイルに名前を付けます。名前が `.zip` で終わっていない場合は、自動的に追加されます。既存のファイルへの上書き保存は拒否されるため、別の名前を選択してください。

ファイルには、プロジェクトの構造、モデルへの編集、メトリックと分析パス、エンティティと勘定科目のビジネス名、そしてテンプレートの設定テーブルの行が含まれます。たとえば、[Cost to Serve](/ja/guides/projects/cost-to-serve/) のアクティビティマップや、[Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/) のポリシー範囲などです。接続、ファイル、夜間のスケジュール、実行、復元ポイント、ボードパック、アクセス権を持つユーザーは含まれません。

使用するには、プロジェクトを作成し、**開始元** で **From a template file...** を選択して、ドキュメントアカウントとパスを指定します。新しいプロジェクトはご自身だけが利用でき、すべてのソースは接続待ちの状態です。テンプレートの後のリリースは、編集したステップを避けて、その変更をマージします。パスにファイルがない場合は、何も作成されず、その旨が通知されます。ドキュメントアカウントを読み取れるユーザーなら誰でも、そのファイルからインストールできます。別のワークスペースで使用するには、ファイルをダウンロードして、そこにアップロードしてください。

## Ask で未解決の質問を解決する

ロードの後も、プロジェクトが次の 3 つの回答を待っている場合があります。勘定科目表でタイプが付いていない勘定科目、複数のソースが使用しているコード、ファイル内でどれにも一致しなかった列です。アシスタントに解決を依頼します。MCP 経由の AI エージェントから、**Resolve Data Foundation residue** プロンプトを使用します。待機中の内容を読み取り、項目ごとに理由付きで 1 つの回答を提案します。

アシスタントは何も書き込みません。ご自身で回答する場所に、その回答を適用します。勘定科目とコードは **Codes waiting for your answer** で、ファイルの列はファイルのマッピングで適用します。エンティティが提案されることはありません。

## プロジェクトを引き継ぐ

**セットアップ** チェックリストには、**階層を確認** の後に 4 つの締めくくり項目があります。

- **Set up the nightly refresh** は、**夜間に更新** をオンにすると完了します。
- **チームと共有** は、プロジェクトをセットアップしたユーザー以外の誰かがメンバーになると完了します。
- **Download the evidence pack** は、最後に成功したロードの後にパックをダウンロードすると完了します。
- **Hand the project over to its owner** は、セットアップしたユーザー以外のアーキテクトが存在し、合計が一致すると完了します。完了していない間は、チェックリストに次のことが表示されます。クライアントのオーナーをこのプロジェクトのアーキテクトにしてから、ご自身をメンバーから削除します。

チェックリストには、プロジェクトをセットアップしたユーザーが表示されます（**Set up by**）。

## テンプレートでモデルを拡張する

テンプレートは、レポートとモデルを Common Finance Model の上に構築するため、どの ERP が供給していても同じように動作します。**Enterprise Profitability** などのテンプレートからプロジェクトを開始すると、次が作成されます。

- [Common Finance Model のテーブル](#common-finance-model-のテーブル)。空の状態、またはサンプルデータが入った状態です。
- それらのテーブルから構築された **エンティティ**、**勘定科目**、**部門**、**顧客**、**製品**、**セグメント 1**、**セグメント 2** の各ディメンション。[階層](#階層)を参照してください。
- **ロード** ワークフローと、ERP とファイルを読み取り、整合させ、準備状況をチェックし、テンプレートのモデルを構築するために実行するワークフロー。
- テンプレート独自のレポートとモデル。**Enterprise Profitability** は、収益、COGS、売上総利益、直接費と間接費の営業費用、貢献利益、営業利益率を持つ損益計算書テーブルと、前年比および予算比のマージンブリッジを追加します。
- 結果について質問するためのメトリックと分析パス。

**開始元** では 3 つのテンプレートを利用でき、いずれも同じモデルを基盤としています。

| テンプレート | 追加されるもの |
|---|---|
| **Enterprise Profitability** | 損益計算書とマージンブリッジ。 |
| **Cost to Serve** | 各顧客へのサービス提供コストと、それを差し引いた後のマージン。[Cost to Serve](/ja/guides/projects/cost-to-serve/) を参照してください。 |
| **Operational Transfer Pricing** | 各エンティティの利益水準とポリシー範囲の比較、および真の調整。[Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/) を参照してください。 |

**From a template file...** は、保存したプロジェクトから開始します。[マイテンプレートとして保存する](#マイテンプレートとして保存する)を参照してください。

ご自身の ERP を接続する前に試すには、プロジェクトを作成するときに **サンプルデータで開始** にチェックを入れます。プロジェクトは最初のロードをすぐに実行するため、**Foundation** タブには、米ドルに換算されたユーロのエンティティを含む完全なサンプルが表示されます。ご自身の ERP を接続するか、ご自身のファイルを追加すると、サンプルは削除され、ご自身のデータに置き換わります。削除が中断された場合は、次の **ロード** で完了します。`sample` という名前のご自身のフォルダーは削除されません。ステータスページには、サンプルがそのフォルダーを保持しているため、その中の他のテーブルは読み取られないことが記載され、別の名前のフォルダーに移動するよう案内されます。

## Foundation タブ

**Foundation** タブは、データを接続、ロード、チェックする場所です。上から順に、次のセクションがあります。

| セクション | 表示内容 |
|---|---|
| **前回のロード** | 前回のロードが成功したか、失敗したか、まだ実行中か。**ロード**、**Apply changes**、**更新**、**夜間に更新** の各ボタンがあります。 |
| **What to do next** | 対応が必要なこと（重要な順）。それぞれに **確認** または **Choose which source counts from when** ボタンがあります。 |
| **ソース** | 順番に並んだ各ソース。**高度**、**Remove this source**、**グループ**、**Rename extra categories** があります。 |
| **セットアップ** | セットアップチェックリスト: **データを接続**、**データをロード**、**合計が一致することを確認**、**階層を確認**、**Set up the nightly refresh**、**チームと共有**、**Download the evidence pack**、**Hand the project over to its owner**。現在の項目は太字で表示されます。 |
| **Business names** | カテゴリー、損益計算書の行、メトリック、列に対してビジネスで使っている名前。[ビジネス名](#ビジネス名)を参照してください。 |
| **ファイル** | 追加した各ファイル、そのデータセット（**総勘定元帳**、**為替レート** など）、およびそのマッピングが **✓ 確認済み** か **○ 確認待ち** か。 |
| **ロード済みデータ** | エンティティごとの、最初と最後にロードされた期間と、準備ができている期間の数。 |
| **期間** | 各エンティティの会計期間と、それぞれが **✓ クローズ済み** か **○ 未締め** か。 |
| **準備状況** | 準備状況グリッド: エンティティ、期間、チェックごとに 1 行、そのステータスと **対応**。 |
| 接続 | ERP を接続し、エンティティとロードする履歴の月数を選択するか、別のソースを追加します。 |
| **ファイル**（追加） | CSV、TSV、TXT、Excel、Parquet ファイルを追加し、列のマッピングを確定します。 |
| **ロード** | ロードを開始します。**Apply changes** は、ERP から取得せずにロードを実行します。 |

ロードの実行中、タブは自動的に更新され、1 回の読み取りが失敗しても読み取りを続けます。ステータスを読み取れない場合は、**Foundation のステータスを読み取れませんでした。** と **再試行** が表示され、**再試行** はステータスを新たに読み取ります。タブはメッセージを表示する前に自動的に 1 回再試行し、サーバーが応答するとメッセージは消えます。

ステータスページには、次のことも記載されます。

- `/sources/` の下のフォルダーのうち、必要な列がないテーブルを持つものは、ソースとして追加されません。除外された各テーブルと、不足している列が注記に示されます。列を追加してから、**ロード** または **Apply changes** を押してください。
- ロードは成功したものの、比較する元帳明細が取り込まれなかった場合、アンバーの **Model P&L ties to GL** 行に、何も一致しなかったことが表示されます。何かが一致するまで、セットアップチェックリストの **合計が一致することを確認** は完了にならず保留のままです。元帳明細のあるソースを追加してから、**ロード** を押してください。

セットアップチェックリストは、進捗を追跡します。

- **データを接続** と **データをロード** は、ソースが接続されてロードが成功すると、自動的にチェックされます。
- **合計が一致することを確認** は、一致チェックに合格すると自動的にチェックされます。
- **階層を確認**: **ディメンションを開く** をクリックしてエンティティ、勘定科目、部門の階層を確認し、**確認しました** にチェックを入れます。この項目はご自身で確認します。
- **Set up the nightly refresh**、**チームと共有**、**Download the evidence pack**、**Hand the project over to its owner** がリストを締めくくります。[プロジェクトを引き継ぐ](#プロジェクトを引き継ぐ)と[プロジェクトアクセスの管理](/ja/guides/projects/managing-projects/#プロジェクトのアクセスの管理)を参照してください。

**アクション** メニューには、**Allocations...**、**Board pack...**、**Clone...**、**Restore...**、**Save as my template...** があります。[配賦ルール](#配賦ルール)、[ボードパック](#ボードパック)、[プロジェクトを複製する](#プロジェクトを複製する)、[復元ポイント](#復元ポイント)、[マイテンプレートとして保存する](#マイテンプレートとして保存する)を参照してください。

## Common Finance Model のテーブル

Data Foundation は、ERP かファイルかを問わずすべてのソースを同じ 15 個のテーブルに整合させるため、それらに基づいて構築されたレポート、メトリック、モデルは、ソースが何であっても同じように動作します。各行には、ソースシステムと読み取り日時も記録されます。**データセット** 列は、ファイルを追加するときに選択する名前です。

| データセット | テーブル | 保持する内容 |
|---|---|---|
| エンティティ | `cfm_entity` | 親、現地通貨とグループ通貨、国を持つ法人。 |
| エンティティ対応表 | `cfm_entity_map` | ソースのエンティティコードと、それぞれが属するエンティティ。[エンティティ対応表](#エンティティ対応表)を参照してください。 |
| 為替レート | `cfm_fx_rate` | 通貨ペアごとの月次の平均、期末、履歴レート。[為替レート](#為替レート)を参照してください。 |
| 会計カレンダー | `cfm_fiscal_calendar` | エンティティの会計期間ごとに 1 行。開始日と終了日、および締め済みかどうかを持ちます。 |
| 勘定科目表 | `cfm_account` | 親、タイプ（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、財務諸表、通常残高、レートタイプを持つ勘定科目。 |
| 部門 | `cfm_department` | 親とプロフィットセンターを持つ部門とコストセンター。 |
| 製品 | `cfm_product` | 親、ファミリー、グループ、数量単位、標準コストを持つ製品マスター。 |
| 顧客 | `cfm_customer` | 親、グループ、リージョン、国を持つ顧客マスター。顧客名はマスクされません。 |
| セグメント値 | `cfm_segment` | 名前と親を持つセグメント値。[階層](#階層)を参照してください。 |
| 総勘定元帳 | `cfm_gl_journal` | 取引通貨、現地通貨、報告通貨での仕訳明細。 |
| 試算表 | `cfm_trial_balance` | エンティティ、勘定科目、部門ごとの期間の借方、貸方、純額を、現地通貨と報告通貨で。 |
| 売上明細 | `cfm_sales_line` | 数量、総額、値引き、純額、COGS の金額を持つ請求済みの売上明細。 |
| 在庫残高 | `cfm_inventory_balance` | 製品と倉庫ごとの期末在庫。 |
| 予算 | `cfm_budget` | シナリオ、バージョン、勘定科目、部門ごとの予算とフォーキャスト。 |
| 配賦ドライバー | `cfm_stat_driver` | 人数、平方フィート、数量などの統計ドライバー。 |

期間は `YYYY-MM` の形式で書かれ、取引は転記期間で配置されます。予算は任意です。予算のない ERP でも、他のすべてがロードされます。

試算表ファイルには、借方と貸方の列、純額の列、またはその両方を含めることができます。借方と貸方だけの場合、純額は借方から貸方を引いたものになり、空の側はゼロとして扱われます。純額だけの場合、正の純額は借方に、負の純額は貸方に正の金額として変換されます。部門の列は任意です。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| **接続をテスト** で、ERP が認証情報を拒否したと表示される | 接続の認証情報と、連携用ユーザーが ERP にサインインできることを確認してください。 |
| **接続をテスト** で、データセットに **権限が不足しています** と表示される | 表示された権限を追加するよう、ERP 管理者に依頼してください。お使いの ERP の[接続ガイド](/ja/guides/connections/)に、接続に必要なものが記載されています。 |
| ERP のエラーメッセージが、ERP 自身のものより短い | PlaidCloud は、プロバイダーのエラーを表示する前に、認証情報、トークン、キーを取り除くため、一部の詳細が省略されます。**接続をテスト** を実行して、どのデータセットが影響を受けているかを確認してください。 |
| ある期間で **ロード済みデータ** が問題になる | その期間の ERP の読み取りが失敗しました。**ロード** をもう一度実行してください。ロード済みの期間はスキップされます。 |
| **勘定科目表にない勘定科目** が問題になる | ERP またはファイルの勘定科目表に、不足している勘定科目を追加し、**ロード** をもう一度実行してください。 |
| **通貨換算** が問題になる | エンティティの通貨に、その期間の報告通貨へのレートがないか、単一の報告通貨が見つかりませんでした。**為替レート** ファイルにレートを追加するか、接続が ERP の為替レートを読み取れることを確認するか、プロジェクト変数 `reporting_currency` を設定してください。その後、**ロード** をもう一度実行してください。 |
| **通貨換算** が要対応になる | 貸借対照表、在庫、予算の行に、その期間の期末レート、履歴レート、計画レートがありません。損益計算書は影響を受けません。予算月の計画レートを含め、レートを追加して、**ロード** をもう一度実行してください。 |
| **Codes waiting for your answer** が要対応になる | **確認** をクリックして各コードに回答し、**Apply changes** をクリックしてください。 |
| **Which source covers which months** が要対応になる | **Choose which source counts from when** をクリックしてソースを選択し、**Apply changes** をクリックしてください。 |
| **Intercompany balances** が赤またはアンバーになる | **Intercompany pairs** のペアを確認してください。不足している側を計上するか、明細に取引先を追加するか、不足しているレートを追加してください。 |
| **Group views are off** | アーキテクトに、**グループ** の **Everyone on the project may see the group results** にチェックを入れるよう依頼してください。 |
| **未マッピングのエンティティ** が問題になる | エンティティをエンティティマスターに追加するか、**エンティティ対応表** ファイルでそのコードを既存のエンティティにマッピングして、**ロード** をもう一度実行してください。 |
