**Data Foundation**は、PlaidCloudプロジェクトのための財務データ基盤です。その**Common Finance Model**は、複数のERPシステムと、それぞれの複数のインスタンスのERPデータを、1つのモデルにまとめます。勘定科目表、エンティティ、報告通貨がそれぞれ1つに統一されます。このモデルを基にしたレポート、メトリック、AIアシスタントは、どのERPのデータであっても同じ数値を参照します。

ERPはPlaidCloudの接続を通じて接続されるため、総勘定元帳、試算表、マスターデータ、予算は、エクスポートの必要なく、ソースから直接取り込まれます。ファイルでは、為替レート、配賦ドライバー、ERP外で管理している予算など、システムが保持していないデータを追加でき、ファイルがカバーするERPの行を置き換えることもできます。**ロード**は、すべてのソースをモデルに統合し、報告通貨に換算し、合計が一致することをチェックします。これらはすべて、プロジェクトの**Foundation**タブで行います。ソース間で同じコードが異なる意味で使われている場合は、同じ意味かどうかを回答します。管理連結は、会社間取引を消去したグループの損益計算書を構築します。**企業収益性**などのテンプレートは、この上にレポートとモデルを構築します。

## ERPの接続

ERPは、PlaidCloudの接続を通じてData Foundationに接続されます。Data Foundationは、総勘定元帳、試算表、マスターデータ、為替レート、予算をその接続から直接読み取り、読み取りのみを行います。既存の接続を選ぶことも、タブ上で新しく作成することもできます。各ERPのアクセス設定については、[接続ガイド](/ja/guides/connections/)を参照してください。

<Steps>

1. Analyzeで**プロジェクト**を開き、**新規プロジェクト**をクリックします。名前を入力し、**開始元**で**空のプロジェクト**ではなく、**企業収益性(テンプレート)** などのテンプレートを選択します。**作成**をクリックします。

   プロジェクトは**Foundation**タブで開きます。共有するまで、プロジェクトは自分だけが利用でき、自分が唯一のアーキテクトです。

2. **Foundation**タブで、ERPの既存の接続を選ぶか、**新しい接続を作成**を選択します。既存の各接続には、その接続を使用しているワークフローが一覧表示されます。どのワークフローでも使用されていない場合は、**どのワークフローでもまだ使用されていません**と表示されます。

3. 新しい接続の場合は、**接続名**を入力し、**環境**を選択して、ERP接続が求める認証情報を入力します。

   認証情報がまだありませんか。フォームには、ERP管理者宛てのアクセスリクエストが用意されています。**リクエストをコピー**または**リクエストをメールで送信**をクリックして送信し、返ってきた値を入力します。

4. **接続をテスト**をクリックします。PlaidCloudがサインインして各データセットの読み取りを試み、それぞれを**読み取り可能**、**権限が不足しています**、**エラー**のいずれかで一覧表示します。不足がある場合は、ERP管理者に追加を依頼する権限が示されます。

5. **履歴の月数**を設定します。ロードする過去の月数を、1から120の範囲で指定します。デフォルトは24です。

6. 既存の接続の場合は、ロードするエンティティにチェックを入れます。すべてオフのままにすると、すべてのエンティティがロードされます。非アクティブなエンティティと消去用エンティティは、表示を選択するまで非表示です。その後、**接続**をクリックします。

7. 新しい接続の場合は、**接続**をクリックして作成します。次に、ロードするエンティティにチェックを入れ、もう一度**接続**をクリックして保存します。保存するまでは、すべてのエンティティがロードされます。

8. 別のERPシステムまたは別のインスタンスを取り込むには、これらの手順を繰り返し、**接続**をクリックする前に**Add this as another source instead of replacing the current one**にチェックを入れます。チェックを入れない場合、新しい接続が現在のソースを置き換えます。

</Steps>

接続が完了すると、カードに、プロジェクトがロードする接続、環境、エンティティ、履歴の月数が表示されます。

各ロードでは、変更された部分のみを読み取ります。未締め期間と直近の締め済み期間は再度読み取られ、すでにロード済みの締め済み期間は保持されます。**履歴の月数**を増やすと、追加された月のみが読み取られます。為替レート、エンティティ対応表、報告通貨を変更すると、影響を受ける月が再度読み取られます。

## ソース

プロジェクトがロードする元のERPシステムとインスタンスは、それぞれソースです。**Foundation**タブの**ソース**リストには、ソースごとに1行ずつ順番に、名前、最後にロードされた日時、提供された行数、読み取る報告ブックが表示されます。たとえば、`1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`のように表示されます。まだロードされていないソースには**not loaded yet**と表示されます。確認済みのファイルもソースです。

ソースの**高度**を開くと、そのソースの使われ方を変更できます。

| 設定 | 内容 |
|---|---|
| **名前** | レポート、マッピングの質問、メッセージがソースに対して使用するラベルです。 |
| **Place in the order** | ソースの優先順位です。2つのソースが同じ会社の同じ月をカバーしている場合、順序が上のソースが優先されます。 |
| **Reporting books, separated by commas** | 読み取る会計ブックです。複数のブックを保持するシステム向けの設定です。**All reporting books**を選ぶと、すべてのブックを読み取ります。 |
| **会社**、**開始 (2026-01)**、**終了 (2026-12)** | このソースが各会社に対して提供する月です。月を空のままにすると、制限なしになります。月は、`2026-03`のように、年と月で記述します。 |

変更内容を保持するには、**保存**をクリックします。ソースを削除するには、**Remove this source**をクリックし、**削除**を確認します。そのソースからロードされたものはすべて削除されますが、後で再度接続できます。

ソースを変更しても、ERPは再度読み取られません。**Apply changes**をクリックするまで、**前回のロード**カードには**Changes not applied yet**と表示されます。この操作は、すでに取得済みのデータからロードを実行します。新しい順序、マッピング、名前、ファイルでソースを再度統合し、モデルを再構築します。ERPから最新のデータも取得したい場合は、**ロード**をクリックします。

## ERP以外のデータのファイルを追加する

ファイルは、為替レート、配賦ドライバー、[エンティティ対応表](#エンティティ対応表)、ERP外で管理している予算など、システムが保持していないデータでERP接続を補います。各ファイルは、[Common Finance Modelのテーブル](#common-finance-modelのテーブル)に一覧されているデータセットのいずれかに属します。

<Steps>

1. **ファイル**で、ファイルを保存する**ドキュメントアカウント**を選択します。

2. **CSV または Excel ファイルをここにドロップ**にCSVまたはExcelファイルをドロップするか、**ファイルを選択**をクリックします。ファイルは、ドキュメントアカウントの`/foundation/`フォルダーにアップロードされます。

   すでにドキュメントアカウントにあるファイルの場合は、その**ファイルパス**（たとえば`/foundation/budget.csv`）を入力し、**ファイルを追加**をクリックします。

   毎月新しいファイルを読み取るには、名前が一致するフォルダー内のすべてのファイルを追加します。フォルダーと、**File names that**の条件（含む、で始まる、で終わる、完全に一致する、パターンに一致する）を入力し、**Add files**をクリックします。その内側のフォルダーにあるファイルは読み取られません。

3. PlaidCloudがファイルを読み取り、マッピングを提案します。

   - **検出された区切り文字、小数点の区切り文字、日付。** 区切り文字（カンマ、セミコロン、タブ、パイプ）、小数点の区切り文字、日付形式が自動的に検出されます。
   - **データセット**: ファイルが属するCommon Finance Modelのテーブルで、ファイル名と列見出しから照合されます。一致が明確でない場合は、リストから選択します。
   - **小数点の区切り文字**: **ピリオド (1,234.56)** または**カンマ (1.234,56)**。
   - **日付形式**: ファイルに日付がある場合に表示されます。検出された形式が誤っている場合は変更します: `YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY`、`MM/DD/YYYY`。
   - **ファイル内の列**、**タイプ**、**例**、**対応先**のグリッド。列を別のフィールドに送る場合、または**ロードしない**にする場合は、**対応先**を変更します。

4. ファイルが提起する質問に回答します。たとえば、**Which company is this file for?**、**Which currency are the amounts in?**、**Are these amounts year-to-date or for the month?**、**Are the amounts shown in thousands or millions?**、**Are revenues shown as negative numbers?** などです。各質問は、ファイルに答えが含まれていない場合にのみ表示されます。

5. 各列の対応先を確認し、**マッピングを確定**をクリックします。

</Steps>

次のオプションは、該当する場合にファイルに表示されます。

| オプション | 用途 |
|---|---|
| **Which source do these rows apply to?** | コードマップのファイルを1つのソースに限定します。**Every source**を選ぶと、すべてのソースに適用されます。 |
| **Where does this file come from?** | ファイルが**This project's own codes**を保持しているか、`SAP Germany export`のように名前を付けた**Another system**からのものかを指定します。他のシステムからのファイルは、ERPソースと同様に、共有コードがチェックされます。 |
| **Split … into … parts at each …** (**高度**の下) | `100-200-300`のように複数の値を保持する1つの列を分割し、各部分をそれぞれのフィールドに送ります。 |
| **Which currency do you report in?** | プロジェクトに報告通貨がまだない場合に、報告通貨を設定します。`USD`のように、3文字で記述します。 |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 連結システムの結果をロードして、グループの損益計算書を[照合](#連結システムと照合する)できるようにします。 |

ファイルをプロジェクトから削除するには、**ファイル**の下でそのファイルの横にある**削除**をクリックするか、マッピングの**Remove this file**をクリックして、確認します。そのファイルの数値は、次に**Apply changes**をクリックしたときにレポートから除かれます。

PlaidCloudがデータセット、小数点の区切り文字、日付の順序を自動で判断できない場合（たとえば、日付が日/月とも月/日とも読めるファイル）は、確定する前に選択を求められます。同じデータセットに2つ目のファイルを追加すると、1つ目のファイルが置き換えられます。後から追加したファイルの列がデータセットと一致しない場合、ロードはそのファイルと列の名前を示し、ファイルまたはその列名を修正するか、ステップの**Schema Mismatch**を`union`に設定するよう案内します。

受け付けるファイルは、CSV、TSV、TXTのテキストファイル、Excelの`.xlsx`ファイル（最初のシートが読み取られます）、Parquetファイルです。

<Aside type="note">
ファイルが存在しない場合や空の場合でも、ロードが停止することはありません。ファイルを追加すると、まだマッピングするものがないというメッセージが表示され、ロードはパスを示す警告付きで完了し、そのデータセットは空のままになります。ファイルが用意できたら、もう一度追加してください。
</Aside>

## データをロードする

**ロード**カードまたは**前回のロード**カードで**ロード**をクリックします。ロードでは、接続済みのERPと確認済みのファイルを読み取り、Common Finance Modelに統合して、報告通貨に換算し、準備状況のチェックを実行し、テンプレートのモデルを再構築します。

- プロジェクトでは、一度に1つのロードしか実行されません。2つ目の**ロード**または**Apply changes**は、ロードがすでに実行中であることを知らせ、ロードの実行中はソースを変更できません。
- 他のワークフローが同じERP接続を使用している場合、最初のロードでそれらが一覧表示され、確認を求められます。ロードはERPから読み取るため、それらのワークフローが遅くなる可能性があるためです。続行するには、**このままロード**をクリックします。
- PlaidCloudのアップグレード後は、アーキテクトが**ロード**をクリックすると、プロジェクトの生成済みワークフローも更新され、必要な作業用テーブルが作成されます。それまでは**前回のロード**カードに**Changes not applied yet**と表示され、マネージャーが**ロード**をクリックすると、アーキテクトの**ロード**で更新される旨の警告が表示されます。
- 失敗したロードは赤で表示され、以前の結果の陰に隠れることはありません。連結が失敗した場合は、以前のグループ結果を表示する代わりに、停止したステップの名前がステータスに表示されます。以前のロードの行には、ロードが成功するまで**以前のロードの結果です。もう一度ロードしてください。** と表示されます。
- 1つのエンティティと期間の読み取りに失敗しても、残りはロードされます。**ロード**をもう一度実行すると、失敗した部分のみが取得されます。

### 除外された行

ソースが重複する場合、ロードは各数値を1件だけ保持し、他の行は二重に計上せずに除外します。除外された行は、そのソース、エンティティ、理由とともに記録され、ロードは件数を示す警告付きで完了します。たとえば、`120 rows of NetSuite EU also provided by a source ranked ahead`のように表示されます。理由は次のとおりです。

| 理由 | 意味 |
|---|---|
| 別の会計ブックにある | その行は、ソースが読み取る設定になっていない報告ブックに属しています。 |
| ソースが提供する期間の範囲外 | その行は、会社に設定された**開始**月と**終了**月の範囲外にあります。 |
| 上位のソースからも提供されている | 順序が上のソースが、同じ会社と月をカバーしています。 |
| ソースの以前のファイルにもある | 同じソースの以前のファイルが、すでにその月をカバーしています。 |
| ファイルで置き換えられた | ファイルが、そのエンティティと月のERPの行を置き換えます。 |
| 別のソースも使用しているコードを持つ | このコードには、お客様の回答が必要です。[ソース間でコードをマッピングする](#ソース間でコードをマッピングする)を参照してください。 |
| 2つのコードにマッピングされたコードを持つ | コードマップが、このコードに2つの回答を与えています。 |

統計勘定は、元帳ではなく配賦ドライバーに移動され、問題ではなく移動済みとして表示されます。

### ERPデータとファイルを併用する

ファイルは、カバーする範囲のみを置き換え、ERPのその他の行は残ります。

- **マスターファイル**（勘定科目、部門、顧客、製品、セグメント値）は、同じコードのERPの行を置き換えます。
- **トランザクションファイル**は、同じエンティティと月のERPの行を置き換えます。総勘定元帳と試算表のファイルは、さらに元帳でも照合され、予算ファイルはシナリオで、統計ドライバーファイルはシナリオとドライバーで照合されます。

ファイルが後からある月をカバーしなくなった場合は、次のロードで、その月のERPのデータが戻ります。

## エンティティ対応表

各ソースは、独自のコードでエンティティを指定します。**エンティティ対応表**は、それらのコードをエンティティマスターのエンティティに対応付けるため、すべてのソースの明細が同じエンティティに集約されます。

使用するには、CSVまたはExcelファイルを追加し、**エンティティ対応表**データセットを選択します。

| 列 | 内容 |
|---|---|
| `source_entity` | 会社コードなど、ソースが保持するコードです。 |
| `entity` | エンティティマスターでの名前で示した、そのコードが属するエンティティです。 |

- 対応表にないコードは、そのまま使用されます。
- 複数のコードを1つのエンティティにマッピングできます。それらの明細は結合され、すべてのコードで締められた時点で、その月は締め済みとみなされます。
- 対応表のコードはすべてのソースに適用されるため、各ソースのエンティティコードは、ソース間で一意である必要があります。
- **エンティティ**ファイルの行は、同じエンティティコードを持つERPのエンティティを置き換えます。

**未マッピングのエンティティ**チェックは、エンティティがエンティティマスターになく、対応表でもエンティティにマッピングされていない明細にフラグを付けます。エンティティマスターがロードされるまでは、**– 対象外**と表示されます。

## ソース間でコードをマッピングする

2つのソースが、同じコードを異なるものに対して使用したり、同じものに対して異なるコードを使用したりすることがあります。コードが複数のソースに現れる場合、Data Foundationは、そのコードがどこでも同じ意味かどうかを回答するまで、その行を除外します。これにより、各金額は一度だけ計上されます。**Codes waiting for your answer**チェックには最初の10件が一覧表示され、残りは「ほかK件」と表示されます。また、**Foundation**タブの**What to do next**カードには**確認**ボタンがあります。

**確認**を選ぶと、**Codes waiting for your answer**が開きます。コードは、**アカウントタイプ**、**会社**、**勘定科目**、**部門**、**プロフィットセンター**、**顧客**、**製品**、各追加カテゴリに分類されます。各コードについて、各ソースがそれを何と呼んでいるかと、提案が表示されます。

- **Looks like the same thing**: ソースがコードに同じ名前を付けている場合。
- **Looks like different things**: 名前が異なる場合。
- **We can't tell. Please answer.**: 判断材料がない場合。

コードは1つずつ**Yes, the same**または**No, different**で回答できます。また、**Accept all**（すべての提案を採用）、**All the same**、**All different**で、グループ全体にまとめて回答することもできます。勘定科目については、勘定科目表の親グループ全体にまとめて回答することもできます。ソースにアカウントタイプがない場合は、勘定科目のグループに対して**Use this type**を選択します: **収益**、**売上原価**、**営業費用**、**営業外損益**、**資産**、**負債**、**資本**。

マッピングはソースとディメンションごとに保持されるため、あるソースの部門に対する回答が、別のソースの勘定科目を変更することはありません。回答は入力するたびに保存され、**Saved. Press Apply changes to use your answers.** と表示されます。回答を使用するには、**Apply changes**をクリックします。

マッピングをファイルで提供することもできます。**Code map**データセットのファイルを追加し、**Which source do these rows apply to?** を選択して1つのソースに限定します。

## どのソースをいつから採用するかを選択する

2つのソースが同じ月を提供している場合、**Which source covers which months**チェックが選択を求めます。**What to do next**カードの**Choose which source counts from when**をクリックすると**Which source counts from when**が開き、重複が会社ごとに一覧表示されます。採用するソースを選択し、**That month is**に採用開始月（たとえば`2026-04`）を入力して、**Apply changes**をクリックします。もう一方のソースは、それより前の月を保持します。

同じダイアログは、2つのソースが通貨に対して異なる為替レートを提供している場合にも警告します。その場合、順序が上のソースのレートが使用されます。

## 通貨換算

各ロードでは、総勘定元帳、試算表、売上、在庫、予算の金額を、現地通貨から1つの報告通貨に換算します。レポートとモデルは換算後の金額を読み取るため、異なる通貨のエンティティが、どのシステムのものであっても、正しく合計されます。

### 報告通貨

報告通貨を選択するには、プロジェクト変数`reporting_currency`に`USD`などの通貨コードを設定します。[プロジェクト変数の管理](/ja/guides/projects/managing-projects/#プロジェクト変数の管理)を参照してください。テンプレートは、これを空の状態で作成します。空の間、各ロードでは、次のうち、通貨をちょうど1つ示す最初のものが使用されます。

1. エンティティのグループ通貨。
2. 最上位のエンティティ（親を持たないもの）の現地通貨。
3. ファイルの現地通貨。

どれも通貨をちょうど1つ示さない場合は、`reporting_currency`を設定するまで、**通貨換算**に問題が表示されます。

すでに報告通貨になっている金額はそのままなので、すべてのデータが1つの通貨であるプロジェクトにはレートは不要です。

売上、在庫、予算のファイルも通貨を保持できます。`Currency`または`Local Currency`という名前の列をマッピングすると自動的に認識され、ファイルの現地金額が報告通貨に換算されます。ファイルにすでにあるグループ金額または報告金額は、そのまま保持されます。製品の標準原価は換算されません。

### 為替レート

レートは、通貨1単位を月の報告通貨に換算します。換算後の金額は、現地金額にレートを掛けたものです。

- **ERPから**: 各ロードで、ERPが保持している為替レートを読み取ります。
- **ファイルから**: CSVまたはExcelファイルを追加し、**為替レート**データセットを選択します。ファイル内のレートは、同じ通貨と月のERPのレートを置き換えます。ERPが報告通貨へのレートを公開していない通貨で報告する場合や、予算月に計画レートを追加する場合に、ファイルを使用します。

| 列 | 内容 |
|---|---|
| `from_currency` | 換算元の通貨です。例: `EUR`。 |
| `to_currency` | 報告通貨です。例: `USD`。 |
| `period` | 月です。`YYYY-MM`形式。 |
| `average_rate` | その月の平均レートです。 |
| `closing_rate` | 月末のレートです。 |
| `historical_rate` | 資本、および取得時レートに設定された勘定科目に使用する取得時レートです。 |

報告通貨へのレートのみが使用されます。逆方向、つまり報告通貨から別の通貨へのレートで提示されたものは、反転されません。

### 適用されるレート

各行は、その行自身の通貨から換算されます。そのため、エンティティとは異なる通貨の明細は、その明細の通貨から換算されます。行に当てはまる最初の規則が適用されます。

| 行 | レート |
|---|---|
| 統計勘定および転記なしの勘定科目 | 換算されません。 |
| すでに報告通貨になっている | 換算されません。 |
| レートタイプを持つ勘定科目 | そのレート（平均、期末、取得時）。取得時レートがない場合、取得時は期末にフォールバックします。ERPからの場合、レートタイプは勘定科目自身のレートタイプです。勘定科目表ファイルでは、レートタイプ列を`fx_rate_type`にマッピングし、`average`、`closing`、`historical`のいずれかを指定します。 |
| 売上明細 | 期間の平均レート。 |
| 在庫残高 | 期間の期末レート。 |
| 予算行 | 総勘定元帳と同様に勘定科目ごと: 損益計算書の勘定科目には平均レート、貸借対照表の勘定科目には期末レート。 |
| 損益計算書の勘定科目 | 期間の平均レート。 |
| 資本勘定 | 取得時レート。取得時レートがない場合は期末レート。 |
| その他の貸借対照表の勘定科目 | 期間の期末レート。 |

換算後の金額は丸められないため、合計がずれることはありません。

<Aside type="note">
試算表は各期間の増減を保持しているため、貸借対照表の金額は、各月の増減をその月の期末レートで換算したものです。期末のレートで再換算された貸借対照表ではなく、累積換算調整勘定や会社間取引の消去もありません。換算後の金額は、損益計算書に使用してください。
</Aside>

## 階層

各ロードでは、すべてのソースのマスターデータからディメンションを再構築します。最初は7つのディメンションがあり、最大10個の追加カテゴリを持てます。

| ディメンション | 構築元 |
|---|---|
| **エンティティ** | エンティティとその親 |
| **勘定科目** | 勘定科目表と親勘定科目 |
| **部門** | 部門とその親 |
| **顧客** | 顧客とその親顧客 |
| **製品** | 製品とその親製品 |
| **セグメント1** | `segment_1`のセグメント値 |
| **セグメント2** | `segment_2`のセグメント値 |
| **セグメント3**から**セグメント10** | ソースが保持している場合の、`segment_3`から`segment_10`のセグメント値 |

- 親を持たないレコード、または自分自身を親として指定しているレコードは、最上位のメンバーとしてロードされます。
- 各ロードで階層が再構築されるため、親の変更は、ディメンションではなく、ERPまたはファイルで行ってください。
- 1つの階層の問題は、そのディメンションにのみ影響します。ロードとテンプレートのモデルは、引き続き完了します。
- 各追加カテゴリは、保持する内容に合わせて、たとえば**クラス**や**リージョン**のように名前を変更できます。**Rename extra categories**の下に、レポートで使用する名前を入力し、**Save names**をクリックします。名前には、文字、数字、スペース、ドット、ダッシュ、アンダースコアを使用でき、60文字までです。
- 各ソースは、自身の追加カテゴリが、どのカテゴリ名の下に入るかを指定します。ソースの**高度**を開き、それぞれの名前を選択するか、**Leave out**を選択して、**保存**をクリックします。`Class`と`Business area`のように、カテゴリを異なる名前で呼ぶソースは、1つのスロットを共有します。

セグメント階層をファイルで提供するには、**セグメント値**データセットを選択します。

| 列 | 内容 |
|---|---|
| `segment` | 値が属するセグメントです。`segment_1`から`segment_10`。 |
| `segment_value` | 総勘定元帳、売上、予算の明細が保持している値です。 |
| `segment_value_name` | その名前です。 |
| `parent_segment_value` | 同じセグメント内の親です。 |

## 準備状況のチェック

各ロードの後、**準備状況**グリッドに、すべてのエンティティと期間のすべてのチェックが、次のいずれかのステータスで一覧表示されます。

| ステータス | 意味 |
|---|---|
| **● 準備完了** | チェックに合格しました。 |
| **▲ 要確認** | 確認する価値はありますが、数値は使用できます。 |
| **■ 問題** | 結果を信頼する前に修正してください。 |
| **– 対象外** | このチェックに対するデータがまだありません。 |

チェックは次のとおりです。

| チェック | 確認内容 |
|---|---|
| **ロード済みデータ** | すべての会計期間に総勘定元帳の明細があり、すべてのERPの読み取りが成功していること。明細のない締め済み期間は問題で、明細のない未締め期間は要確認です。 |
| **試算表と総勘定元帳の一致** | 試算表が、エンティティ、期間、勘定科目ごとに総勘定元帳と等しいこと。ある勘定科目について試算表と総勘定元帳の両方に部門がある場合は、部門ごとにも一致を確認します。 |
| **売上と総勘定元帳の一致** | 売上明細が、各期間の総勘定元帳の収益勘定と売上原価勘定と等しいこと。 |
| **不明な製品/顧客** | すべての売上明細が、製品マスターと顧客マスターに存在する製品と顧客を指定していること。 |
| **勘定科目表にない勘定科目** | すべての総勘定元帳の明細が、勘定科目表にある勘定科目を指定していること。不明な勘定科目を持つ明細は、損益計算書から除外されます。取引はあるがタイプのない勘定科目も問題となり、勘定科目表が収益勘定科目にタイプを付けていても売上原価の勘定科目にはタイプを付けていないソースは、確認が必要になります。 |
| **通貨換算** | すべての総勘定元帳、試算表、売上、在庫、予算の行に、報告通貨での金額があること。損益計算書は換算後の金額を読み取るため、レートのない損益計算書または売上の行は問題です。レートのない貸借対照表、在庫、予算の行は要確認です。まだレートのない予算月は黄色で表示されるため、予算月の計画レートをロードしてください。[通貨換算](#通貨換算)を参照してください。 |
| **未マッピングのエンティティ** | すべての総勘定元帳、試算表、売上の明細が、直接またはエンティティ対応表を通じて、エンティティマスターにあるエンティティを指定していること。エンティティマスターがロードされるまでは対象外です。[エンティティ対応表](#エンティティ対応表)を参照してください。 |

複数のソースがあるロードでは、次のチェックが追加されます。

| チェック | 確認内容 |
|---|---|
| **Reporting book** | 複数の会計ブックをエンティティに対して保持するソースには、レポート用ブックが選択されていること。選択するまでは、最初のブックのみが対象になります。 |
| **Codes waiting for your answer** | 複数のソースで使用されているすべてのコードに回答済みであること。[ソース間でコードをマッピングする](#ソース間でコードをマッピングする)を参照してください。 |
| **Extra categories from your sources** | ソースが保持するすべての追加カテゴリに名前が付けられているか、除外されていること。 |
| **Which source covers which months** | どのソースを採用するかを選択しない限り、2つのソースが会社の同じ月を提供していないこと。 |
| **Account types and hierarchy** | ディメンションが指定するすべての親が存在し、自分自身の親や祖先になっているメンバーがないこと。親がない場合、その子は階層の最上位に表示され、ループがあるとその階層はロードされません。合計は影響を受けません。 |
| **会計カレンダー** | 各エンティティの会計期間が暦月であり、1か月分の明細をすべて1つの会計期間に割り当てられること。エンティティの期間が暦月でない場合(4-4-5、13期間)、または1か月分の明細が複数の会計期間に該当し得る場合や、会計カレンダーにその月がない場合は、確認が必要です。 |

準備ができていない各行には、**対応**列に、勘定科目表のロード、為替レートのロード、ある期間に対する**ロード**の再実行など、行うべきことが示されます。

グリッドには、対応が必要な場合にのみ表示される2つのセットアップチェックも表示されます。

| チェック | 表示される条件 |
|---|---|
| **間接費の配賦** | プロジェクト変数`overhead_department`と`overhead_driver`の一方のみが設定されているか、`overhead_driver`に一致する配賦ドライバーがないため、配賦が何も行われない場合。両方を設定するか、両方をクリアして間接費の配賦をオフにします。 |
| **予算比較** | 予算行はロードされているが、プロジェクト変数`budget_version`で指定されたバージョンに1つもなく、予算比較が空になる場合。 |

## 管理連結

各ロードでは、管理連結が構築されます。これは、グループ内のすべてのエンティティの損益計算書を、報告通貨で、会社間取引を消去してグループ化したものです。管理報告用です。連結システムは引き続き法定グループの正式な記録であり、後述のとおりそれと照合してください。

<Aside type="note">
管理連結は損益計算書のみを対象とします。法定連結や法的連結ではなく、連結貸借対照表、換算調整、のれん、少数株主持分はありません。
</Aside>

### グループを選択する

**ソース**の下で**グループ**を開くと、グループ内の会社が表示されます。チェックを外した会社は、単独でレポートに残りますが、グループの合計からは除かれます。**Save group**をクリックします。変更は、次の**ロード**または**Apply changes**で適用されます。新しい会社は、チェックを外すまでグループに含まれます。

グループの会計年度は、プロジェクト変数`group_fy_start_month`で設定した月に始まります。変更しない限り、`1`です。

### 作成されるもの

| テーブル | 内容 |
|---|---|
| **Group P&L** | エンティティ、期間、明細（収益、売上原価、営業費用、営業外、会社間差異）ごとに1行、報告通貨で表します。収益とコストは本来の符号を持ちます。 |
| **Group P&L year to date** | 同じ内容を、グループで最後に完全にロードされた期間までの年初来で表します。 |
| **Intercompany pairs** | エンティティ、グループ、期間のペアごとに1行、各側の金額と残差を表します。 |
| **Intercompany lines** | グループの数値またはペアの基になる元帳明細で、取引先を含みます。 |
| **照合** | グループの損益計算書の年初来を、連結システムと比較したものです。 |

これらのテーブルには、3つのエンティティ名が表示されます。

| エンティティ | 意味 |
|---|---|
| **Eliminations** | 会社間取引の消去です。合計はゼロになるため、グループの数値ではそのまま含め、消去前のエンティティの合計を見る場合はフィルターで除外します。 |
| **Group total** | 照合における、連結システムの合計です。 |
| **Unmapped** | 期間のない明細、およびこのプロジェクトにない連結システムの勘定科目やエンティティです。 |

メトリック**Consolidated income**、**Consolidated result**、**IC difference**と、各テーブルの分析パスにより、グループに関する質問に答えられます。

### 会社間取引の消去

会社間取引の明細は、取引先で照合されます。明細にある取引先が使用され、明細にない場合は、その顧客の取引先が使用されます。ペアの両側が消去され、両側が一致しなかった金額は、会社間差異の明細に計上されます。各ペアには理由が付きます。

| 理由 | 意味 |
|---|---|
| **一致** | 両側が同じ金額を計上した。 |
| **片側のみ計上** | 一方のエンティティが取引を計上し、その取引先は計上しなかった。 |
| **消去されず** | ペアの明細にレートがないため、どちらの側も消去されない。 |

ペアは年初来で判断されます。**Intercompany balances**行は、ペアの差異がプロジェクト変数`group_amber`（デフォルトは`1`）を超えると黄色に、`group_red`（デフォルトは`1000`）を超えると赤になります。取引先のない明細や、取引先がエンティティではない明細は消去されず、その行で件数として数えられます。取引先を保持するソースが、保持しないソースと並ぶと、黄色で表示されます。

ソース自身の消去用エンティティはグループの損益計算書に含まれず、**連結**行にその旨が表示されます。

### 連結システムと照合する

連結システムが報告する結果をファイルとして追加し、マッピングを確定するときに**These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** にチェックを入れます。**Which version of the numbers is this?** には、システムの名前で回答します。すると**照合**テーブルに、エンティティと明細ごとの年初来の**自社**、**報告値**、**差異**が表示されます。差異は通常、**Eliminations**、**Group total**、**Unmapped**の各行、またはシステムが使用する為替レートで説明できます。**Reconciliation to the source**行には、`group_amber`を超えるすべての明細が一覧表示されます。

### 閲覧できるユーザー

グループの結果は、プロジェクトの行アクセスに従います。行アクセスによってグループの結果が表示されない場合、ステータスは琥珀色で表示されます。一部のエンティティのみを閲覧できるユーザーには、それらのエンティティの消去前の合計が表示されます。**Eliminations**行や会社間取引のテーブルを閲覧するには、すべてのエンティティへのアクセスが必要です。

プロジェクトが、部門のようにグループのテーブルが保持していない列で、閲覧できる行を制限している場合、グループの結果はすべてのユーザーに対してオフのままで、**連結**には**Group views are off**と表示されます。その場合、アーキテクトだけが**グループ**の下で**Everyone on the project may see the group results**にチェックを入れることができます。変更は、次の**ロード**または**Apply changes**で適用されます。

## 最新の状態を保つ

ERP接続からのロードが問題なく成功すると、**前回のロード**カードに**夜間に更新**が表示されます。これをクリックすると、毎晩お使いのタイムゾーンの2:00に**ロード**が実行されます。カードには**Nightly refresh: Every night at 2:00**と、設定したユーザーが表示されます。

夜間のロードは、設定したユーザーとして実行されます。そのユーザーがERP接続を使用できなくなった場合は、グリッドに夜間のロードがスキップされることが示されるため、再度設定してください。サンプルデータのみのプロジェクトは、スケジュールできません。

夜間のロードでファイルが存在しない場合や空の場合は、エラーではなく、パスを示す警告付きで完了し、モデルの残りの部分は引き続きロードされます。

## テンプレートでモデルを拡張する

テンプレートは、Common Finance Model上にレポートとモデルを構築するため、どのERPがデータを供給しても同じように動作します。**企業収益性**などのテンプレートからプロジェクトを開始すると、次のものが作成されます。

- [Common Finance Modelのテーブル](#common-finance-modelのテーブル)（空の状態、またはサンプルデータが入った状態）。
- それらのテーブルから構築された**エンティティ**、**勘定科目**、**部門**、**顧客**、**製品**、**セグメント1**、**セグメント2**のディメンション。[階層](#階層)を参照してください。
- **ロード**ワークフローと、それが実行するワークフロー。ERPとファイルの読み取り、統合、準備状況のチェック、テンプレートのモデルの構築を行います。
- テンプレート独自のレポートとモデル。**企業収益性**は、収益、売上原価、粗利益率、直接および間接の営業費用、貢献利益、営業利益率を含む損益計算書テーブルに加えて、前年比と予算に対するマージンブリッジを追加します。
- 結果について質問するためのメトリックと分析パス。

独自のERPを接続する前に試すには、プロジェクトの作成時に**サンプルデータで開始**にチェックを入れます。プロジェクトはすぐに最初のロードを実行するため、**Foundation**タブに、ユーロのエンティティを米ドルに換算した例を含む、完全な例が表示されます。独自のERPを接続するか、独自のファイルを追加すると、サンプルの行はクリアされ、お客様のデータに置き換わります。

## Foundationタブ

**Foundation**タブでは、データの接続、ロード、チェックを行います。上から順に、次のセクションがあります。

| セクション | 表示される内容 |
|---|---|
| **前回のロード** | 前回のロードが成功したか、失敗したか、まだ実行中かと、**ロード**、**Apply changes**、**更新**、**夜間に更新**ボタン。 |
| **What to do next** | 対応が必要な事項（重要なものから順）と、それぞれの**確認**または**Choose which source counts from when**ボタン。 |
| **ソース** | 各ソースが順番に表示され、**高度**、**Remove this source**、**グループ**、**Rename extra categories**があります。 |
| **セットアップ** | セットアップのチェックリスト: **データを接続**、**データをロード**、**合計が一致することを確認**、**階層を確認**、**チームと共有**。現在の項目は太字で表示されます。 |
| **ファイル** | 追加した各ファイルと、**総勘定元帳**や**為替レート**などのデータセット、そのマッピングが **✓ 確認済み**か **○ 確認待ち**か。 |
| **ロード済みデータ** | エンティティごとに、ロードされた最初と最後の期間と、準備ができている期間の数。 |
| **期間** | 各エンティティの会計期間と、それぞれが **✓ クローズ済み**か **○ 未締め**か。 |
| **準備状況** | 準備状況のグリッド: エンティティ、期間、チェックごとに1行、そのステータスと**対応**。 |
| 接続 | ERPを接続し、エンティティとロードする履歴の月数を選択するか、別のソースを追加します。 |
| **ファイル**（追加） | CSV、TSV、TXT、Excel、Parquetのファイルを追加し、列のマッピングを確定します。 |
| **ロード** | ロードを開始します。**Apply changes**は、ERPから取得せずにロードを実行します。 |

ロードの実行中は、タブが自動的に更新されます。

セットアップのチェックリストで、進捗を確認できます。

- **データを接続**と**データをロード**は、ソースが接続され、ロードが成功すると、自動的にチェックされます。
- **合計が一致することを確認**は、一致を確認するチェックに合格すると、自動的にチェックされます。
- **階層を確認**: **ディメンションを開く**をクリックして、エンティティ、勘定科目、部門の階層を確認し、**確認しました**にチェックを入れます。これはご自身で確認してください。
- **チームと共有**: プロジェクトの準備ができたら共有します。[プロジェクトアクセスの管理](/ja/guides/projects/managing-projects/#プロジェクトアクセスの管理)を参照してください。

## Common Finance Modelのテーブル

Data Foundationは、ERPかファイルかを問わず、すべてのソースを同じ15個のテーブルに統合するため、それらを基に構築されたレポート、メトリック、モデルは、ソースが何であっても同じように動作します。各行には、そのソースシステムと読み取られた日時も記録されます。**データセット**列は、ファイルを追加するときに選択する名前です。

| データセット | テーブル | 内容 |
|---|---|---|
| エンティティ | `cfm_entity` | 親、現地通貨とグループ通貨、国を持つ法人。 |
| エンティティ対応表 | `cfm_entity_map` | ソースのエンティティコードと、それぞれが属するエンティティ。[エンティティ対応表](#エンティティ対応表)を参照してください。 |
| 為替レート | `cfm_fx_rate` | 通貨ペアごとの月次の平均レート、期末レート、取得時レート。[為替レート](#為替レート)を参照してください。 |
| 会計カレンダー | `cfm_fiscal_calendar` | エンティティの会計期間ごとに1行。開始日と終了日、締め済みかどうかを含みます。 |
| 勘定科目表 | `cfm_account` | 親、タイプ（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、財務諸表、通常残高、レートタイプを持つ勘定科目。 |
| 部門 | `cfm_department` | 親とプロフィットセンターを持つ部門とコストセンター。 |
| 製品 | `cfm_product` | 親、ファミリー、グループ、単位、標準原価を持つ製品マスター。 |
| 顧客 | `cfm_customer` | 親、グループ、リージョン、国を持つ顧客マスター。顧客名はマスクされません。 |
| セグメント値 | `cfm_segment` | 名前と親を持つセグメント値。[階層](#階層)を参照してください。 |
| 総勘定元帳 | `cfm_gl_journal` | 取引通貨、現地通貨、報告通貨での仕訳明細。 |
| 試算表 | `cfm_trial_balance` | エンティティ、勘定科目、部門ごとの期間の借方、貸方、純額を、現地通貨と報告通貨で表したもの。 |
| 売上明細 | `cfm_sales_line` | 数量、総額、値引き、純額、売上原価の金額を持つ請求済みの売上明細。 |
| 在庫残高 | `cfm_inventory_balance` | 製品と倉庫ごとの期末在庫。 |
| 予算 | `cfm_budget` | シナリオ、バージョン、勘定科目、部門ごとの予算と予測。 |
| 配賦ドライバー | `cfm_stat_driver` | 従業員数、平方フィート、数量などの統計ドライバー。 |

期間は`YYYY-MM`形式で記述され、取引は転記期間で配置されます。予算は任意です。予算のないERPでも、それ以外のすべてがロードされます。

試算表ファイルには、借方列と貸方列、純額列、またはその両方を含められます。借方と貸方のみの場合、純額は借方から貸方を引いたもので、空の側はゼロとして扱われます。純額のみの場合、正の純額は借方、負の純額は貸方になり、正の金額で表されます。部門列は任意です。

## トラブルシューティング

| 症状 | 対処方法 |
|---|---|
| **接続をテスト**で、ERPが認証情報を拒否したと表示される | 接続の認証情報と、連携用ユーザーがERPにサインインできることを確認します。 |
| **接続をテスト**で、データセットに**権限が不足しています**と表示される | ERP管理者に、表示された権限の追加を依頼します。お使いのERPの[接続ガイド](/ja/guides/connections/)に、接続に必要なものが記載されています。 |
| ERPのエラーメッセージが、ERP自身のメッセージより短い | PlaidCloudは、プロバイダーのエラーを表示する前に認証情報、トークン、キーを削除するため、一部の詳細は省かれます。**接続をテスト**を実行して、どのデータセットが影響を受けているかを確認します。 |
| ある期間で**ロード済みデータ**が問題になっている | その期間のERPの読み取りが失敗しました。**ロード**をもう一度実行します。ロード済みの期間はスキップされます。 |
| **勘定科目表にない勘定科目**が問題になっている | ERPまたはファイルの勘定科目表に、不足している勘定科目を追加して、**ロード**をもう一度実行します。 |
| **通貨換算**が問題になっている | エンティティの通貨に、その期間の報告通貨へのレートがないか、単一の報告通貨が見つかりませんでした。**為替レート**ファイルにレートを追加するか、接続がERPの為替レートを読み取れることを確認するか、プロジェクト変数`reporting_currency`を設定します。その後、**ロード**をもう一度実行します。 |
| **通貨換算**が要確認になっている | 貸借対照表、在庫、予算の行に、その期間の期末レート、取得時レート、計画レートがありません。損益計算書には影響しません。予算月の計画レートを含めてレートを追加し、**ロード**をもう一度実行します。 |
| **Codes waiting for your answer**が要確認になっている | **確認**をクリックして各コードに回答し、**Apply changes**をクリックします。 |
| **Which source covers which months**が要確認になっている | **Choose which source counts from when**をクリックしてソースを選択し、**Apply changes**をクリックします。 |
| **Intercompany balances**が赤または黄色になっている | **Intercompany pairs**でペアを確認します。不足している側を計上するか、明細に取引先を追加するか、不足しているレートを追加します。 |
| **Group views are off** | アーキテクトに、**グループ**の下で**Everyone on the project may see the group results**にチェックを入れるよう依頼します。 |
| **未マッピングのエンティティ**が問題になっている | エンティティマスターにエンティティを追加するか、**エンティティ対応表**ファイルでそのコードを既存のエンティティにマッピングして、**ロード**をもう一度実行します。 |
