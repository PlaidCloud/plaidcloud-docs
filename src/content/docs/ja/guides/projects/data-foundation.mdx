**Data Foundation**は、PlaidCloudプロジェクトの財務データ基盤です。その**Common Finance Model**は、複数のERPシステム（およびそれぞれの複数のインスタンス）のERPデータを、1つの勘定科目表、1組のエンティティ、1つの報告通貨を持つ単一のモデルにまとめます。このモデルをベースに構築されたレポート、メトリック、AIアシスタントは、どのERP由来のデータであっても、すべて同じ数値を参照します。

ERPはPlaidCloud接続を通じて接続されるため、総勘定元帳、試算表、マスターデータ、予算は、エクスポート不要でソースから直接取り込まれます。ファイルは、為替レート、配賦ドライバー、ERP外で管理している予算など、システムが保持していないデータを追加するもので、対象範囲のERP行を置き換えることもできます。**ロード**は、すべてのソースをモデルに整合させ、報告通貨に換算し、突合できていることをチェックします。これらはすべてプロジェクトの**Foundation**タブから行います。ソース間で同じコードが異なる意味で使われている場合は、それらが同じ意味かどうかを指定します。管理連結では、会社間取引を消去したグループ損益計算書が構築されます。**企業収益性**などのテンプレートは、その上にレポートとモデルを構築します。

## ERPを接続する

ERPは、PlaidCloud接続を通じてData Foundationに接続されます。Data Foundationは、総勘定元帳、試算表、マスターデータ、為替レート、予算をERPから直接読み取り、読み取りのみを行います。既存の接続を選択することも、タブ上で新しく作成することもできます。各ERPのアクセス設定については、[接続ガイド](/ja/guides/connections/)を参照してください。

<Steps>

1. Analyzeで**プロジェクト**を開き、**新規プロジェクト**をクリックします。名前を入力し、**開始元**で、**空のプロジェクト**ではなく**企業収益性(テンプレート)** などのテンプレートを選択します。**作成**をクリックします。

   プロジェクトは**Foundation**タブで開きます。共有するまで、プロジェクトは自分専用で、自分だけがアーキテクトです。

2. **Foundation**タブで、ERP用の既存の接続を選択するか、**新しい接続を作成**を選択します。既存の各接続には、それを使用しているワークフローが一覧表示されるか、**どのワークフローでもまだ使用されていません**と表示されます。

3. 新しい接続の場合は、**接続名**を入力し、**環境**を選択して、ERP接続が要求する認証情報を入力します。

   認証情報がまだない場合は、フォームにERP管理者向けの定型のアクセスリクエストが表示されます。**リクエストをコピー**または**リクエストをメールで送信**をクリックして送信し、返ってきた値を入力します。

4. **接続をテスト**をクリックします。PlaidCloudはサインインして各データセットの読み取りを試み、それぞれを**読み取り可能**、**権限が不足しています**、または**エラー**として一覧表示します。不足がある場合は、ERP管理者に追加を依頼する権限が示されます。

5. **履歴の月数**を設定します。ロードする過去の月数で、1から120までです。デフォルトは24です。

6. 既存の接続の場合は、ロードするエンティティにチェックを入れます。すべてのチェックを外したままにすると、すべてのエンティティがロードされます。非アクティブなエンティティと消去エンティティは、表示を選択するまで非表示です。その後、**接続**をクリックします。

7. 新しい接続の場合は、**接続**をクリックして作成します。次に、ロードするエンティティにチェックを入れ、もう一度**接続**をクリックして保存します。そうするまでは、すべてのエンティティがロードされます。

8. 別のERPシステムや別のインスタンスを追加するには、これらの手順を繰り返し、**接続**をクリックする前に**Add this as another source instead of replacing the current one**にチェックを入れます。チェックを入れないと、新しい接続が現在のソースを置き換えます。

</Steps>

接続が完了すると、カードに、プロジェクトがロードする接続、環境、エンティティ、履歴の月数が表示されます。

各ロードでは、変更された内容のみが読み取られます。未締め期間と最後の締め済み期間は再読み取りされ、ロード済みの締め済み期間は保持されます。**履歴の月数**を増やすと、追加された月のみが読み取られます。為替レート、エンティティ対応表、報告通貨を変更すると、影響を受ける月が再読み取りされます。

## ソース

プロジェクトがロードする各ERPシステムとインスタンスが、1つのソースです。**Foundation**タブの**ソース**リストには、ソースごとに1行が順番に表示され、名前、最後にロードされた日時、提供された行数、読み取る報告用帳簿が示されます。たとえば、`1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`のようになります。まだロードされていないソースには、**not loaded yet**と表示されます。確定したファイルもソースです。

ソースの**高度**を開くと、ソースの使われ方を変更できます。

| 設定 | 内容 |
|---|---|
| **名前** | レポート、マッピングの質問、メッセージでソースを示すラベル。 |
| **Place in the order** | ソースの順位。同じ会社の同じ月を2つのソースがカバーしている場合は、順位が上のソースが優先されます。 |
| **Reporting books, separated by commas** | 読み取る会計帳簿。複数の帳簿を持つシステム向けです。**All reporting books**は、すべての帳簿を読み取ります。 |
| **会社**、**開始 (2026-01)**、**終了 (2026-12)** | 会社ごとに、このソースが提供する月。月を空にすると制限なしになります。月は年と月の形式で記述します（例：`2026-03`）。 |

変更を保持するには、**保存**をクリックします。ソースを削除するには、**Remove this source**をクリックして、**削除**を確定します。そのソースからロードされたものはすべて削除されますが、後で再接続できます。

ソースを変更しても、ERPは再読み取りされません。**前回のロード**カードには、**Apply changes**をクリックするまで**Changes not applied yet**と表示されます。**Apply changes**は、すでに取得済みのデータからロードを実行します。新しい順序、マッピング、名前、ファイルでソースを再度整合させ、モデルを再構築します。ERPから最新のデータも取得したい場合は、**ロード**をクリックします。

## ERP以外のデータ用にファイルを追加する

ファイルは、為替レート、配賦ドライバー、[エンティティ対応表](#エンティティ対応表)、ERP外で管理している予算など、システムが保持していないデータでERP接続を補完します。各ファイルは、[Common Finance Modelのテーブル](#common-finance-modelのテーブル)に一覧されているデータセットのいずれかに属します。

<Steps>

1. **ファイル**で、ファイルを保存する**ドキュメントアカウント**を選択します。

2. **CSV または Excel ファイルをここにドロップ**にCSVまたはExcelファイルをドロップするか、**ファイルを選択**をクリックします。ファイルは、ドキュメントアカウントの`/foundation/`フォルダーにアップロードされます。

   すでにドキュメントアカウントにあるファイルの場合は、その**ファイルパス**（例：`/foundation/budget.csv`）を入力し、**ファイルを追加**をクリックします。

   毎月新しいファイルを読み取るには、名前が一致するフォルダー内のすべてのファイルを追加します。フォルダーと、**File names that**の条件（含む、で始まる、で終わる、完全一致、パターン一致）を入力し、**Add files**をクリックします。その中のフォルダーにあるファイルは読み取られません。

3. PlaidCloudがファイルを読み取り、マッピングを提案します。

   - **Detected delimiter, decimal separator and dates.** 区切り文字（カンマ、セミコロン、タブ、パイプ）、小数点の区切り文字、日付形式が自動的に検出されます。
   - **データセット**：ファイルが属するCommon Finance Modelのテーブル。ファイル名と列見出しから照合されます。照合が明確でない場合は、リストから選択します。
   - **小数点の区切り文字**：**ピリオド (1,234.56)** または**カンマ (1.234,56)**。
   - **日付形式**：ファイルに日付がある場合に表示されます。検出された形式が誤っている場合は変更します：`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY`、または`MM/DD/YYYY`。
   - **ファイル内の列**、**タイプ**、**例**、**対応先**のグリッド。**対応先**を変更すると、列を別のフィールドに割り当てるか、**ロードしない**に設定できます。

4. ファイルから生じる質問に回答します。たとえば、**Which company is this file for?**、**Which currency are the amounts in?**、**Are these amounts year-to-date or for the month?**、**Are the amounts shown in thousands or millions?**、**Are revenues shown as negative numbers?** などです。各質問は、ファイルに記載がない場合にのみ表示されます。

5. 各列の割り当て先を確認してから、**マッピングを確定**をクリックします。

</Steps>

次のオプションは、該当する場合にファイルに表示されます。

| オプション | 用途 |
|---|---|
| **Which source do these rows apply to?** | コードマップファイルを1つのソースに限定します。**Every source**は、すべてのソースに適用します。 |
| **Where does this file come from?** | ファイルが**This project's own codes**を保持するのか、**Another system**から来たのかを指定します。後者では、システム名（例：`SAP Germany export`）を入力します。別のシステムからのファイルは、ERPソースと同様に、共有コードがチェックされます。 |
| **Split … into … parts at each …**（**高度**の下） | `100-200-300`のように複数の値を保持する1つの列を分割し、各部分を独自のフィールドに割り当てます。 |
| **Which currency do you report in?** | プロジェクトにまだ報告通貨がない場合に、報告通貨を設定します。3文字で記述します（例：`USD`）。 |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 連結システムの結果をロードし、グループ損益計算書を[照合](#連結システムと照合する)できるようにします。 |

プロジェクトからファイルを削除するには、**ファイル**でファイルの横にある**削除**、またはそのマッピングで**Remove this file**をクリックして、確定します。そのファイルの数値は、次に**Apply changes**をクリックしたときにレポートから消えます。

PlaidCloudがデータセット、小数点の区切り文字、日付の順序を自動で判断できない場合（たとえば、日付が日/月とも月/日とも読めるファイル）、確定する前に選択を求められます。同じデータセットに2つ目のファイルを追加すると、最初のファイルが置き換えられます。後から追加したファイルの列がデータセットと一致しない場合、ロードでファイル名と列名が示され、ファイルまたはその列名を修正するか、ステップの**Schema Mismatch**を`union`に設定するよう案内されます。

使用できるファイルは、CSV、TSV、TXTのテキストファイル、Excelの`.xlsx`ファイル（最初のシートから読み取り）、Parquetファイルです。

<Aside type="note">
存在しないファイルや空のファイルが原因でロードが停止することはありません。追加するとマッピングするものがまだないと表示され、ロードはパスを示す警告付きで完了し、そのデータセットは空のままになります。ファイルが用意できたら、もう一度追加してください。
</Aside>

## データをロードする

**ロード**カードまたは**前回のロード**カードで**ロード**をクリックします。ロードは、接続済みのERPと確定済みのファイルを読み取り、Common Finance Modelに整合させ、報告通貨に換算し、準備状況チェックを実行して、テンプレートのモデルを再構築します。

- プロジェクトで同時に実行できるロードは1つだけです。2回目の**ロード**や**Apply changes**では、ロードがすでに実行中であると表示され、実行中はソースを変更できません。
- 他のワークフローが同じERP接続を使用している場合、最初のロードでそれらが一覧表示され、確認を求められます。ロードはERPから読み取るため、それらのワークフローが遅くなる可能性があるためです。続行するには**このままロード**をクリックします。
- PlaidCloudのアップグレード後は、アーキテクトの**ロード**で、プロジェクトの生成されたワークフローも更新され、必要な作業用テーブルが作成されます。それまでは、ステータスページに「ワークフローは以前のリリースで生成されました。アーキテクトのロードで更新されます。」というオレンジ色の項目が表示され、マネージャーの**ロード**では、更新できるのはアーキテクトだけであるという警告が表示されます。
- 失敗したロードは赤で表示され、以前の結果の陰に隠れることはありません。連結が失敗した場合、ステータスには、古いグループ結果を表示する代わりに、停止したステップが示されます。以前のロードの行には、ロードが成功するまで**以前のロードの結果です。もう一度ロードしてください。** と表示されます。
- 1つのエンティティと期間の読み取りに失敗しても、残りはロードされます。もう一度**ロード**を実行すると、失敗した分だけが取得されます。

### 保留された行

ソースが重複している場合、ロードは各数値の1つのコピーを保持し、二重に計上しないように、それ以外を保留します。保留された行は、ソース、エンティティ、理由とともに記録され、ロードは件数を示す警告付きで完了します（例：`120 rows of NetSuite EU also provided by a source ranked ahead`）。理由は次のとおりです。

| 理由 | 意味 |
|---|---|
| In another accounting book | 行が、ソースが読み取るように設定されていない報告用帳簿に属しています。 |
| Outside the periods the source provides | 行が、会社に設定された**開始**月と**終了**月の範囲外です。 |
| Also provided by a source ranked ahead | 順位が上のソースが、同じ会社と月をカバーしています。 |
| Also in an earlier file of the source | 同じソースの以前のファイルが、すでにその月をカバーしています。 |
| Replaced by a file | ファイルが、そのエンティティと月のERP行を置き換えています。 |
| Carrying a code another source also uses | コードについて回答が必要です。[ソース間でコードをマッピングする](#ソース間でコードをマッピングする)を参照してください。 |
| Carrying a code mapped to two codes | コードマップがコードに2つの回答を与えています。 |

統計勘定は、元帳ではなく配賦ドライバーに移動され、問題ではなく移動済みとして表示されます。

### ERPデータとファイルの併用

ファイルは、カバーする範囲のみを置き換え、ERPのその他の行はそのまま残ります。

- **マスターファイル**（勘定科目、部門、顧客、製品、セグメント値）は、同じコードのERP行を置き換えます。
- **トランザクションファイル**は、同じエンティティと月のERP行を置き換えます。総勘定元帳と試算表のファイルは元帳でも、予算ファイルはシナリオでも、統計ドライバーファイルはシナリオとドライバーでも照合されます。

ファイルが後でその月をカバーしなくなった場合、その月のERPのデータは次回のロードで戻ります。

## エンティティ対応表

各ソースは、独自のコードでエンティティを呼びます。**エンティティ対応表**は、それらのコードをエンティティマスターのエンティティにマッピングし、すべてのソースの明細が同じエンティティに取り込まれるようにします。

使用するには、CSVまたはExcelファイルを追加し、**エンティティ対応表**データセットを選択します。

| 列 | 内容 |
|---|---|
| `source_entity` | ソースが保持するままのコード（会社コードなど）。 |
| `entity` | 属するエンティティ。エンティティマスターでの名前。 |

- 対応表にないコードは、そのまま使用されます。
- 複数のコードを1つのエンティティにマッピングできます。それらの明細は統合され、すべてのコードで締められた月が締め済みとして扱われます。
- 対応表のコードはすべてのソースに適用されるため、各ソースのエンティティコードはソース間で一意である必要があります。
- **エンティティ**ファイルの行は、同じエンティティコードを持つERPのエンティティを置き換えます。

**未マッピングのエンティティ**チェックは、エンティティがエンティティマスターになく、対応表でもマッピングされていない明細にフラグを付けます。エンティティマスターがロードされるまでは、**– 対象外**と表示されます。

## ソース間でコードをマッピングする

2つのソースが同じコードを異なる意味で使うことも、同じ意味に異なるコードを使うこともあります。コードが複数のソースに現れる場合、Data Foundationは、それがどこでも同じ意味かどうかを指定するまでその行を保留し、各金額が1回だけ計上されるようにします。**Codes waiting for your answer**チェックにそれらが一覧表示されます（最初の10件と「ほかK件」）。**Foundation**タブの**対応**カードには、**確認**ボタンがあります。

**確認**をクリックすると、**Codes waiting for your answer**が開きます。コードは、**Account types**、**Companies**、**Accounts**、**Departments**、**Profit centers**、**Customers**、**Products**、および各追加カテゴリの種類別にグループ化されます。各コードについて、各ソースがそれをどう呼んでいるかと、提案が表示されます。

- **Looks like the same thing**：ソースがコードに同じ名前を付けている場合。
- **Looks like different things**：名前が異なる場合。
- **We can't tell. Please answer.**：判断材料がない場合。

コードは1つずつ**Yes, the same**または**No, different**で回答するか、グループ全体を**Accept all**（すべての提案を採用）、**All the same**、**All different**で一括して回答できます。勘定科目では、勘定科目表の親グループ全体を一度に回答することもできます。ソースに勘定科目タイプがない場合は、勘定科目のグループに対して**Use this type**を選択します：**収益**、**売上原価**、**営業費用**、**営業外損益**、**資産**、**負債**、**資本**。

マッピングはソースとディメンションごとに保持されるため、あるソースの部門への回答が、別のソースの勘定科目に影響することはありません。回答は入力するたびに保存され、**Saved. Press Apply changes to use your answers.** と表示されます。回答を反映するには、**Apply changes**をクリックします。

マッピングをファイルで提供することもできます。**Code map**データセットでファイルを追加し、**Which source do these rows apply to?** を選択して、1つのソースに限定します。

## どのソースをいつから採用するかを選択する

2つのソースが同じ月を提供している場合、**Which source covers which months**チェックで選択を求められます。**対応**カードの**Choose which source counts from when**をクリックすると、**Which source counts from when**が開き、重複が会社ごとに一覧表示されます。採用するソースを選択し、**That month is**に採用開始月（例：`2026-04`）を入力して、**Apply changes**をクリックします。もう一方のソースは、それ以前の月を保持します。

同じダイアログには、2つのソースが通貨に対して異なる為替レートを提供している場合に警告も表示されます。その場合は、順位が上のソースのレートが使用されます。

## 通貨換算

各ロードでは、総勘定元帳、試算表、売上、在庫、予算の金額が、現地通貨から1つの報告通貨に換算されます。レポートとモデルは換算後の金額を参照するため、どのシステム由来であっても、異なる通貨のエンティティが正しく合計されます。

### 報告通貨

報告通貨を選択するには、プロジェクト変数`reporting_currency`に`USD`などの通貨コードを設定します。[プロジェクト変数の管理](/ja/guides/projects/managing-projects/#プロジェクト変数の管理)を参照してください。テンプレートは、この変数を空の状態で作成します。空の間、各ロードでは、次のうち、ちょうど1つの通貨を示す最初のものが使用されます。

1. エンティティのグループ通貨。
2. 親を持たない最上位エンティティの現地通貨。
3. ファイルの現地通貨。

どれもちょうど1つの通貨を示さない場合、`reporting_currency`を設定するまで、**通貨換算**に問題が表示されます。

すでに報告通貨になっている金額はそのままになるため、すべてのデータが1つの通貨であるプロジェクトにはレートは不要です。

売上、在庫、予算のファイルも通貨を持てます。`Currency`または`Local Currency`という名前の列をマッピングすると自動的に認識され、ファイルの現地金額が報告通貨に換算されます。ファイルにすでにあるグループ金額または報告金額は、そのまま保持されます。製品の標準原価は換算されません。

### 為替レート

レートは、ある月について、通貨1単位を報告通貨に換算します。換算後の金額は、現地金額にレートを掛けたものです。

- **ERPから**：各ロードで、ERPが保持している為替レートが読み取られます。
- **ファイルから**：CSVまたはExcelファイルを追加し、**為替レート**データセットを選択します。ファイルのレートは、同じ通貨と月のERPのレートを置き換えます。ERPが報告通貨へのレートを公開していない通貨で報告する場合や、予算月の計画レートを追加する場合に、ファイルを使用します。

| 列 | 内容 |
|---|---|
| `from_currency` | 換算元の通貨（例：`EUR`）。 |
| `to_currency` | 報告通貨（例：`USD`）。 |
| `period` | 月（`YYYY-MM`形式）。 |
| `average_rate` | その月の平均レート。 |
| `closing_rate` | 月末のレート。 |
| `historical_rate` | 履歴レート。資本、および履歴レートに設定された勘定科目用。 |

報告通貨へのレートのみが使用されます。報告通貨から別の通貨への逆方向で表記されたレートは、反転されません。

### 適用されるレート

各行は、その行自体の通貨から換算されるため、エンティティと異なる通貨の明細は、その明細の通貨から換算されます。行に当てはまる最初のルールが適用されます。

| 行 | レート |
|---|---|
| 統計勘定および非転記勘定 | 換算されません。 |
| すでに報告通貨になっている | 換算されません。 |
| レートタイプのある勘定科目 | そのレート：平均、期末、または履歴。履歴レートがない場合、履歴は期末にフォールバックします。ERPの場合、レートタイプは勘定科目自体のレートタイプです。勘定科目表ファイルでは、レートタイプの列を`fx_rate_type`にマッピングし、`average`、`closing`、`historical`のいずれかを指定します。 |
| 売上明細 | その期間の平均レート。 |
| 在庫残高 | その期間の期末レート。 |
| 予算行 | 総勘定元帳と同様に勘定科目別：損益計算書の勘定科目には平均レート、貸借対照表の勘定科目には期末レート。 |
| 損益計算書の勘定科目 | その期間の平均レート。 |
| 資本勘定 | 履歴レート。履歴レートがない場合は期末レート。 |
| その他の貸借対照表の勘定科目 | その期間の期末レート。 |

換算後の金額は丸められないため、合計がずれません。

<Aside type="note">
試算表は各期間の変動額を保持しているため、貸借対照表の金額は、各月の変動額をその月の期末レートで換算したものです。期末レートで再換算した貸借対照表ではなく、累積換算調整や会社間取引の消去もありません。換算後の金額は、損益計算書に使用してください。
</Aside>

## 階層

各ロードでは、すべてのソースのマスターデータからディメンションが再構築されます。最初は7つのディメンションがあり、最大10の追加カテゴリを持てます。

| ディメンション | 構築元 |
|---|---|
| **エンティティ** | エンティティとその親 |
| **勘定科目** | 勘定科目表と親勘定科目 |
| **部門** | 部門とその親 |
| **顧客** | 顧客とその親顧客 |
| **製品** | 製品とその親製品 |
| **セグメント1** | `segment_1`のセグメント値 |
| **セグメント2** | `segment_2`のセグメント値 |
| **セグメント3**から**セグメント10** | ソースが保持している場合の、`segment_3`から`segment_10`のセグメント値 |

- 親がないレコード、または自分自身を親として指定しているレコードは、最上位メンバーとしてロードされます。
- 各ロードで階層が再構築されるため、親の変更は、ディメンションではなく、ERPまたはファイルで行ってください。
- 1つの階層の問題は、そのディメンションにのみ影響します。ロードとテンプレートのモデルは引き続き完了します。
- 各追加カテゴリを、その内容に合わせて、たとえば**クラス**や**リージョン**に名前変更できます。**Rename extra categories**で、レポートで使用する名前を入力し、**Save names**をクリックします。名前には、文字、数字、スペース、ドット、ダッシュ、アンダースコアを使用でき、60文字までです。
- 各ソースは、自身の各追加カテゴリが、どのカテゴリ名に対応するかを指定します。ソースの**高度**を開いて、各カテゴリの名前を選択するか、**Leave out**を選択し、**保存**をクリックします。`Class`と`Business area`のように、カテゴリを異なる名前で呼ぶソースは、1つのスロットを共有します。

セグメント階層をファイルで提供するには、**セグメント値**データセットを選択します。

| 列 | 内容 |
|---|---|
| `segment` | 値が属するセグメント：`segment_1`から`segment_10`。 |
| `segment_value` | 総勘定元帳、売上、予算の明細が保持している値。 |
| `segment_value_name` | その名前。 |
| `parent_segment_value` | 同じセグメント内の親。 |

## 準備状況チェック

各ロードの後、**準備状況**グリッドに、すべてのエンティティと期間のすべてのチェックが、次のいずれかのステータスとともに一覧表示されます。

| ステータス | 意味 |
|---|---|
| **● 準備完了** | チェックに合格しました。 |
| **▲ 要確認** | 確認する価値はありますが、数値は使用できます。 |
| **■ 問題** | 結果を信頼する前に修正してください。 |
| **– 対象外** | このチェックに対するデータがまだありません。 |

チェックは次のとおりです。

| チェック | 確認内容 |
|---|---|
| **ロード済みデータ** | すべての会計期間に総勘定元帳の明細があり、すべてのERPの読み取りが成功していること。明細のない締め済み期間は問題で、明細のない未締め期間は要確認です。 |
| **試算表と総勘定元帳の一致** | 試算表が、エンティティ、期間、勘定科目ごとに総勘定元帳と等しいこと。試算表と総勘定元帳の両方が勘定科目の部門を保持している場合は、部門ごとにも一致を確認します。 |
| **売上と総勘定元帳の一致** | 売上明細が、期間ごとに総勘定元帳の収益およびCOGSの勘定科目と等しいこと。 |
| **不明な製品/顧客** | すべての売上明細が、製品マスターと顧客マスターに存在する製品と顧客を指定していること。 |
| **勘定科目表にない勘定科目** | すべての総勘定元帳の明細が、勘定科目表にある勘定科目を指定していること。不明な勘定科目の明細は、損益計算書から除外されます。転記があるのに勘定科目タイプがない勘定科目も問題です。また、収益の勘定科目にタイプがあっても売上原価の勘定科目がないソースの勘定科目表は、要確認です。 |
| **通貨換算** | すべての総勘定元帳、試算表、売上、在庫、予算の行に、報告通貨の金額があること。損益計算書または売上の行にレートがない場合は、損益計算書が換算後の金額を読み取るため、問題です。貸借対照表、在庫、予算の行にレートがない場合は、要確認です。レートがまだない予算月はオレンジ色で表示されるため、予算月の計画レートをロードしてください。[通貨換算](#通貨換算)を参照してください。 |
| **未マッピングのエンティティ** | すべての総勘定元帳、試算表、売上の明細が、直接またはエンティティ対応表を通じて、エンティティマスターにあるエンティティを指定していること。エンティティマスターがロードされるまでは対象外です。[エンティティ対応表](#エンティティ対応表)を参照してください。 |

複数のソースがあるロードでは、次のチェックが追加されます。

| チェック | 確認内容 |
|---|---|
| **Reporting book** | エンティティに対して複数の会計帳簿を保持しているソースで、報告用帳簿が選択されていること。選択するまでは、最初の帳簿のみが対象になります。 |
| **Codes waiting for your answer** | 複数のソースで使用されているすべてのコードに回答済みであること。[ソース間でコードをマッピングする](#ソース間でコードをマッピングする)を参照してください。 |
| **Extra categories from your sources** | ソースが保持するすべての追加カテゴリに名前が付けられているか、除外されていること。 |
| **Which source covers which months** | どのソースが採用されるかを選択していない限り、2つのソースが会社の同じ月を提供していないこと。 |
| **Account types and hierarchy** | ディメンションが指定するすべての親が存在し、自分自身の親や祖先になっているメンバーがないこと。親が欠落していると、その子は階層の最上位に置かれ、ループがあるとその階層はロードされません。合計には影響しません。 |
| **会計カレンダー** | 各エンティティの会計期間が暦月であり、各月の行をいずれか1つの会計期間に割り当てられること。エンティティの期間が暦月でない場合（4-4-5、13期間）や、月の行が複数の会計期間に属する可能性がある場合、または会計カレンダーにその月がない場合は、要確認です。 |

準備完了ではない各行には、**対応**列に、勘定科目表のロード、為替レートのロード、期間に対する**ロード**の再実行など、行うべきことが示されます。

グリッドには、2つのセットアップチェックも表示されます。これらは、要確認の場合にのみ表示されます。

| チェック | 表示される場合 |
|---|---|
| **間接費の配賦** | プロジェクト変数`overhead_department`と`overhead_driver`の一方しか設定されていない、または`overhead_driver`に一致する配賦ドライバーがなく、配賦が何も行われない場合。両方を設定するか、両方をクリアして間接費の配賦をオフにします。 |
| **予算比較** | 予算行がロードされているが、プロジェクト変数`budget_version`で指定されたバージョンのものがなく、予算比較が空になる場合。 |

## 管理連結

各ロードでは、管理連結が構築されます。これは、グループ内のすべてのエンティティのグループ損益計算書を、報告通貨で、会社間取引を消去した状態で示すものです。管理レポート用です。法定グループの記録は連結システムが引き続き保持します。以下の手順で、それと照合してください。

<Aside type="note">
管理連結は、損益計算書のみを対象とします。法定または法務上の連結ではなく、連結貸借対照表、換算調整、のれん、少数株主持分はありません。
</Aside>

### グループを選択する

**ソース**の下で**グループ**を開くと、グループ内の会社を確認できます。チェックを外した会社は、単独でレポートには残りますが、グループ合計からは除外されます。**Save group**をクリックします。変更は、次回の**ロード**または**Apply changes**で適用されます。新しい会社は、チェックを外すまでグループに含まれます。

グループの会計年度は、プロジェクト変数`group_fy_start_month`で設定された月に始まります。変更しない限り`1`です。

### 得られるもの

| テーブル | 内容 |
|---|---|
| **Group P&L** | エンティティ、期間、行（収益、売上原価、営業費用、営業外、会社間差異）ごとに1行。報告通貨で表されます。収益とコストは自然な符号を持ちます。 |
| **Group P&L year to date** | 同じ内容を、グループの最後に完全にロードされた期間までの年初来で表したもの。 |
| **Intercompany pairs** | エンティティのペア、グループ、期間ごとに1行。各側の金額と残差を含みます。 |
| **Intercompany lines** | グループの数値またはペアの元になっている、取引先付きの元帳明細。 |
| **照合** | グループP&Lの年初来と、連結システムの比較。 |

これらのテーブルには、3つのエンティティ名が表示されます。

| エンティティ | 意味 |
|---|---|
| **Eliminations** | 会社間取引の消去。合計がゼロになるため、グループの数値には含めたままにし、消去前のエンティティの合計にはフィルターで除外します。 |
| **Group total** | 照合における、連結システムの合計。 |
| **Unmapped** | 期間のない明細、およびこのプロジェクトにない連結システムの勘定科目やエンティティ。 |

メトリック**Consolidated income**、**Consolidated result**、**IC difference**と、各テーブルの分析パスで、グループに関する質問に答えられます。

### 会社間取引の消去

会社間取引の明細は、取引先で照合されます。明細にある取引先が使用され、明細にない場合は、その顧客の取引先が使用されます。ペアの両側が消去され、両側が一致しない金額は、会社間差異の行に計上されます。各ペアには理由が付きます。

| 理由 | 意味 |
|---|---|
| **一致** | 両側が同じ金額を計上した。 |
| **Only one side booked** | 一方のエンティティが取引を計上し、取引先が計上していない。 |
| **Not eliminated** | ペアの明細に為替レートがないため、どちらの側も消去されない。 |

ペアは年初来で判定されます。**Intercompany balances**行は、ペアの差異がプロジェクト変数`group_amber`（デフォルトは`1`）を超えるとオレンジ色に、`group_red`（デフォルトは`1000`）を超えると赤に変わります。取引先がない明細、またはエンティティではない取引先を持つ明細は消去されず、この行でカウントされます。取引先を保持するソースと保持しないソースが混在していると、オレンジ色で表示されます。

ソース自身の消去エンティティはグループP&Lから除外され、**連結**行にその旨が示されます。

### 連結システムと照合する

連結システムが報告する結果をファイルとして追加し、マッピングを確定するときに**These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** にチェックを入れます。**Which version of the numbers is this?** には、システムの名前を回答します。**照合**テーブルには、エンティティと行ごとに、年初来の**ours**、**reported**、**差異**が表示されます。差異は、多くの場合、**Eliminations**、**Group total**、**Unmapped**の行、またはシステムが使用する為替レートで説明できます。**Reconciliation to the source**行には、`group_amber`を超えるすべての行が一覧表示されます。

### 閲覧できるユーザー

グループの結果は、プロジェクトの行アクセスに従います。行アクセスによってグループの結果が表示されない場合、ステータスはオレンジ色で表示されます。一部のエンティティのみを閲覧できるユーザーには、それらのエンティティの消去前の合計が表示されます。**Eliminations**行と会社間取引のテーブルには、すべてのエンティティへのアクセスが必要です。

プロジェクトが、部門のように、グループのテーブルが保持していない列によって行の閲覧権限を制限している場合、グループの結果はすべてのユーザーに対して非表示のままとなり、**連結**には**Group views are off**と表示されます。その場合、アーキテクトのみが**グループ**の下で**Everyone on the project may see the group results**にチェックを入れられます。変更は、次回の**ロード**または**Apply changes**で適用されます。

## 最新の状態に保つ

ERP接続からのロードが問題なく成功すると、**前回のロード**カードに**夜間に更新**が表示されます。これをクリックすると、タイムゾーンの毎晩2:00に**ロード**が実行されます。その後、カードには**Nightly refresh: Every night at 2:00**と、設定したユーザーが表示されます。

夜間ロードは、設定したユーザーとして実行されます。そのユーザーがERP接続を使用できなくなった場合、グリッドに夜間ロードがスキップされることが示されるため、設定し直してください。サンプルデータのみのプロジェクトはスケジュールできません。

夜間ロードで存在しないファイルや空のファイルがある場合、エラーではなく、パスを示す警告付きで完了し、モデルの残りは引き続きロードされます。

## ビジネス名

**Foundation**タブの**Business names**では、モデル内のコードに、自社で使用している名前を付けられます。レポート、メトリック、アシスタントにはこれらの名前が表示され、保存した名前はすぐに適用されます。以降のロードでも保持されます。

1. **Add a name**をクリックし、**種類**を選択します：**カテゴリー**、**損益計算書の行**、**メトリック**、**列**。
2. **コード**を入力します：カテゴリーの場合は`segment_1`から`segment_10`、損益計算書の行の場合はその行のキー、メトリックの場合はメトリックの名前、列の場合は`table.column`。
3. **名前**を、1行で最大60文字で入力します。
4. **Save names**をクリックします。

保存すると、リスト全体が置き換えられます。名前が空の行は、その名前を削除し、**選択項目を削除**は、チェックを入れた行を削除します。同じコードに2回名前を付けることは拒否されます。ビジネス名は、アシスタントが自社の用語を使えるように、分析パスの説明にも書き込まれます。この説明には長さの制限があり、名前によって長くなりすぎる場合は、何も保存されず、その旨が通知されます。

## 数値を説明する

**Explain this number**は、損益計算書の1つの数値の内訳を示します。**準備状況**グリッドで、エンティティと月の行に**Explain this number**があり、これをクリックすると、その月のエンティティの営業マージンが開きます。ウィンドウでは、数値が、最上部の合計になる階層に分解されます。

| レイヤー | 内容 |
|---|---|
| **From the general ledger** | 元帳がその行に転記した内容。 |
| **Allocated in** | [配賦ルール](#配賦ルール)によってこのエンティティに配分されたコスト。 |
| **Allocated out** | このエンティティが他に配分したコスト。 |
| **Eliminated in the group** | グループの結果で消去された会社間取引。 |

各レイヤーには、それが何であるかを説明する文と、最大のソースドキュメントがソースシステム、ドキュメント、勘定科目とともに表示されます。行があるレイヤーのみが表示されます。ウィンドウは行アクセスに従うため、閲覧できる数値のみを説明できます。裏付けのない数値には、**Nothing to explain**と表示されます。

## 配賦ルール

配賦は、間接費などの共有コストを、部門、製品、顧客に配分します。モデルには2つのステージがあります：**Stage 1: overhead to departments**と**Stage 2: departments to products and customers**。**アクション > Allocations...** を開くと、それぞれの方法を確認または変更できます。変更しない場合は、ウィザードが登場する前と同じように動作します。閲覧者はルールを開けますが、保存はできません。

各ステージで、ウィザードは4つの質問をします。

| ステップ | 質問 | 選択肢 |
|---|---|---|
| **プール** | どのコストを配分しますか？ | 勘定科目の種類。ステージ1では、そのコストを保持する部門または**All departments**。 |
| **ドライバー** | 何を基準に配分しますか？ | 配賦ドライバーとしてロードした**Statistic**（人数や面積など）、**Net sales amount**、**Sales quantity**、または**Spread evenly**。**Same period**または**Same period last year**のドライバーを使用します。 |
| **ターゲット** | どこに配分されますか？ | ステージ1：部門。ステージ2：製品、顧客、またはその両方。 |
| **メソッド** | ドライバーが負の場合はどうしますか？ | **Ignore negative values**または**Stop and tell me**。 |

ステップの下にある**Preview for**に月（年と月で記述、例：`2026-09`）を入力すると、保存していないものも含めて、ルールがどのように動作するかが表示されます：`Pool 120,000 · Allocated 120,000 · Unallocated 0`。未配賦の分は、それを受け取るドライバーがなかったコストです。プレビューは行アクセスに従います。

**保存**をクリックします。ルールは、次回の**ロード**、または**Apply changes**をクリックしたときに有効になります。配賦ステップを手動で編集していた場合は、その編集は上書きされずに保持され、保存時にそのステップ名が示されます。ロードの実行中は保存できません。

## ボードパック

ボードパックは、結果をスケジュールに従ってドキュメントアカウント内のフォルダーに書き込み、すぐに送付できる状態にします。**アクション > Board pack...** を開き、**ドキュメントアカウント**と、`/board-packs`などの**フォルダー**を選択して、**保存**をクリックします。実行のたびに、次のものが書き込まれます。

- Excelワークブック`Board pack.xlsx`。エンティティ別の損益計算書、マージンブリッジ、上位と下位の顧客を含みます。
- 損益計算書ダッシュボードのPDF。

プロジェクトにまだダッシュボードがない場合、ワークブックのみが書き込まれ、実行時にその理由が通知されます。**Run now**をクリックすると、すぐにパックを作成でき、完了するとファイルがフォルダーに表示されます。カードには、最後の実行とその結果、および次回の実行が表示されます。夜間更新が設定されると、パックはそれとともに実行されます。設定できるのは、プロジェクトを変更できるユーザーのみです。

## リストアポイント

リストアポイントは、各ロードの前、およびマッピングやソースを変更する前に作成されます。これには、モデルのテーブル、ディメンション、次のロードが構築の基になる設定（ソース、ファイル、配賦ルール）が含まれます。最近のポイントは保持され、古いものは順次削除されます。編集によって、ロード前に取得されたポイントが押し出されることはありません。

元に戻すには、**アクション > Restore...** を開き、ポイントを選択して、**復元**をクリックします。**復元**は、ポイントが存在する場合に表示されます。復元すると、テーブル、ディメンション、それらの設定が元の状態に戻り、次のロードはそれらから構築されます。保存されたコピーがないテーブルや、履歴を保持できないエンジンは、警告で名前が示され、残りは復元されます。すでに削除されたリストアポイントは拒否され、ロードの実行中は復元できません。

## プロジェクトを複製する

**アクション > Clone...** は、指定した名前でプロジェクトをコピーします。コピーには、テンプレート、モデルへの編集、メトリックと分析パスが保持され、サンプルデータがロードされます。ソースは接続されていないため、ロードする前にコピー内で接続してください。コピーの作成中も作業を続けることができ、準備ができたら**プロジェクトを開く**でそこに移動できます。

## マイテンプレートとして保存

プロジェクトのセットアップを保存して、次のクライアントやエンティティで再利用できます。**アクション > Save as my template...** を開き、ドキュメントアカウントを選択して、ファイルに名前を付けます。名前が`.zip`で終わっていない場合は、自動的に追加されます。既存のファイルへの上書き保存は拒否されるため、別の名前を選択してください。

ファイルには、プロジェクトの構造、モデルへの編集、メトリックと分析パス、エンティティと勘定科目のビジネス名、およびテンプレートの構成テーブルの行（[コスト・トゥ・サーブ](/ja/guides/projects/cost-to-serve/)のアクティビティマップや、[オペレーショナル移転価格](/ja/guides/projects/operational-transfer-pricing/)のポリシー範囲など）が含まれます。接続、ファイル、夜間スケジュール、実行、リストアポイント、ボードパック、アクセス権を持つユーザーは含まれません。

使用するには、プロジェクトを作成し、**開始元**で**From a template file...** を選択して、ドキュメントアカウントとパスを指定します。新しいプロジェクトは自分専用で、すべてのソースが接続待ちの状態になります。後のテンプレートのリリースでは、編集したステップを避けて変更がマージされます。パスにファイルがない場合は、何も作成されず、その旨が通知されます。ドキュメントアカウントを読み取れるユーザーなら、誰でもそのファイルからインストールできます。別のワークスペースで使用するには、ファイルをダウンロードして、そこにアップロードします。

## Askで未解決の質問を解決する

ロードの後でも、プロジェクトが次の3つの回答を待っている場合があります：チャートでタイプが指定されていない勘定科目、複数のソースが使用するコード、ファイル内でどれにも一致しなかった列。アシスタントにこれらの解決を依頼できます。MCP経由のAIアシスタントから、**Resolve Data Foundation residue**プロンプトを使用します。待機中の項目を読み取り、各項目に対して、理由とともに1つの回答を提案します。

アシスタントは何も書き込みません。回答は、自分で回答する場所に適用します：勘定科目とコードは**Codes waiting for your answer**で、ファイルの列はファイルのマッピングで行います。エンティティを提案することはありません。

## プロジェクトを引き渡す

**セットアップ**チェックリストには、**階層を確認**の後に4つの最終項目があります。

- **Set up the nightly refresh**は、**夜間に更新**がオンになると完了します。
- **チームと共有**は、プロジェクトを設定した人以外のメンバーがいると完了します。
- **Download the evidence pack**は、最後に成功したロードの後にパックをダウンロードすると完了します。
- **Hand the project over to its owner**は、プロジェクトを設定した人以外のアーキテクトが存在し、合計が一致すると完了します。完了していない間は、チェックリストに行うべきことが示されます：クライアントのオーナーをこのプロジェクトのアーキテクトにしてから、自分自身をメンバーから削除します。

チェックリストには、プロジェクトを設定した人が示されます（**Set up by**）。

## テンプレートでモデルを拡張する

テンプレートは、Common Finance Modelの上にレポートとモデルを構築するため、どのERPがデータを供給していても、同じように動作します。**企業収益性**などのテンプレートからプロジェクトを開始すると、次のものが作成されます。

- [Common Finance Modelのテーブル](#common-finance-modelのテーブル)。空の状態、またはサンプルデータが入った状態。
- それらのテーブルから構築される、**エンティティ**、**勘定科目**、**部門**、**顧客**、**製品**、**セグメント1**、**セグメント2**のディメンション。[階層](#階層)を参照してください。
- **ロード**ワークフローと、ERPとファイルを読み取り、整合させ、準備状況をチェックし、テンプレートのモデルを構築するためにそれが実行するワークフロー。
- テンプレート独自のレポートとモデル。**企業収益性**は、収益、COGS、売上総利益、直接および間接の営業費用、貢献利益、営業マージンを含む損益計算書テーブルと、前年比および予算比のマージンブリッジを追加します。
- 結果について質問するためのメトリックと分析パス。

**開始元**には3つのテンプレートがあり、いずれも同じモデルをベースにしています。

| テンプレート | 追加されるもの |
|---|---|
| **企業収益性** | 損益計算書とマージンブリッジ。 |
| **コスト・トゥ・サーブ** | 各顧客への対応コストと、それを差し引いたマージン。[コスト・トゥ・サーブ](/ja/guides/projects/cost-to-serve/)を参照してください。 |
| **オペレーショナル移転価格** | 各エンティティの利益水準とポリシー範囲の比較、およびtrue-up。[オペレーショナル移転価格](/ja/guides/projects/operational-transfer-pricing/)を参照してください。 |

**From a template file...** は、保存したプロジェクトから開始します。[マイテンプレートとして保存](#マイテンプレートとして保存)を参照してください。

自分のERPを接続する前に試すには、プロジェクトの作成時に**サンプルデータで開始**にチェックを入れます。プロジェクトはすぐに最初のロードを実行するため、**Foundation**タブには、米ドルに換算されたユーロのエンティティを含む完全な例が表示されます。自分のERPを接続するか、自分のファイルを追加すると、サンプルの行は消去され、自分のデータに置き換わります。

## Foundationタブ

**Foundation**タブは、データを接続し、ロードし、チェックする場所です。上から順に、次のセクションがあります。

| セクション | 表示内容 |
|---|---|
| **前回のロード** | 前回のロードが成功したか、失敗したか、実行中か。**ロード**、**Apply changes**、**更新**、**夜間に更新**ボタンがあります。 |
| **対応** | 対応が必要な項目が重要なものから順に表示され、それぞれに**確認**または**Choose which source counts from when**ボタンがあります。 |
| **ソース** | 順番に並んだ各ソースと、**高度**、**Remove this source**、**グループ**、**Rename extra categories**。 |
| **セットアップ** | セットアップチェックリスト：**データを接続**、**データをロード**、**合計が一致することを確認**、**階層を確認**、**Set up the nightly refresh**、**チームと共有**、**Download the evidence pack**、**Hand the project over to its owner**。現在の項目は太字です。 |
| **Business names** | カテゴリ、損益計算書の行、メトリック、列に対して自社で使用している名前。[ビジネス名](#ビジネス名)を参照してください。 |
| **ファイル** | 追加した各ファイル、そのデータセット（**総勘定元帳**や**為替レート**など）、およびマッピングが **✓ 確認済み**か **○ 確認待ち**か。 |
| **ロード済みデータ** | エンティティごとに、ロードされた最初と最後の期間と、準備ができている期間の数。 |
| **期間** | 各エンティティの会計期間と、それぞれが **✓ クローズ済み**か **○ 未締め**か。 |
| **準備状況** | 準備状況グリッド：エンティティ、期間、チェックごとに1行で、そのステータスと**対応**。 |
| 接続 | ERPを接続し、エンティティとロードする履歴の月数を選択するか、別のソースを追加します。 |
| **ファイル**（追加） | CSV、TSV、TXT、Excel、Parquetファイルを追加し、列のマッピングを確定します。 |
| **ロード** | ロードを開始します。**Apply changes**は、ERPから取得せずにロードを実行します。 |

ロードの実行中は、タブが自動的に更新されます。

セットアップチェックリストは、進捗を追跡します。

- **データを接続**と**データをロード**は、ソースが接続され、ロードが成功すると自動的にチェックされます。
- **合計が一致することを確認**は、突合チェックに合格すると自動的にチェックされます。
- **階層を確認**：**ディメンションを開く**をクリックして、エンティティ、勘定科目、部門の階層を確認し、**確認しました**にチェックを入れます。この項目には**これはご自身で確認してください**と表示され、自分で確認します。
- **Set up the nightly refresh**、**チームと共有**、**Download the evidence pack**、**Hand the project over to its owner**で、リストが完了します。[プロジェクトを引き渡す](#プロジェクトを引き渡す)と[プロジェクトアクセスの管理](/ja/guides/projects/managing-projects/#プロジェクトのアクセスの管理)を参照してください。

**アクション**メニューには、**Allocations...**、**Board pack...**、**Clone...**、**Restore...**、**Save as my template...** があります。[配賦ルール](#配賦ルール)、[ボードパック](#ボードパック)、[プロジェクトを複製する](#プロジェクトを複製する)、[リストアポイント](#リストアポイント)、[マイテンプレートとして保存](#マイテンプレートとして保存)を参照してください。

## Common Finance Modelのテーブル

Data Foundationは、ERPでもファイルでも、すべてのソースを同じ15個のテーブルに整合させるため、それらをベースに構築されたレポート、メトリック、モデルは、ソースが何であっても同じように動作します。各行には、ソースシステムと読み取られた日時も記録されます。**データセット**列は、ファイルを追加するときに選択する名前です。

| データセット | テーブル | 内容 |
|---|---|---|
| エンティティ | `cfm_entity` | 親、現地通貨とグループ通貨、国を持つ法人エンティティ。 |
| エンティティ対応表 | `cfm_entity_map` | ソースのエンティティコードと、それぞれが属するエンティティ。[エンティティ対応表](#エンティティ対応表)を参照してください。 |
| 為替レート | `cfm_fx_rate` | 通貨ペアごとの月次の平均レート、期末レート、履歴レート。[為替レート](#為替レート)を参照してください。 |
| 会計カレンダー | `cfm_fiscal_calendar` | エンティティの会計期間ごとに1行。開始日と終了日、および締め済みかどうかを含みます。 |
| 勘定科目表 | `cfm_account` | 親、タイプ（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、財務諸表、通常残高、レートタイプを持つ勘定科目。 |
| 部門 | `cfm_department` | 親とプロフィットセンターを持つ部門とコストセンター。 |
| 製品 | `cfm_product` | 親、ファミリー、グループ、単位、標準原価を持つ製品マスター。 |
| 顧客 | `cfm_customer` | 親、グループ、リージョン、国を持つ顧客マスター。顧客名はマスクされません。 |
| セグメント値 | `cfm_segment` | 名前と親を持つセグメント値。[階層](#階層)を参照してください。 |
| 総勘定元帳 | `cfm_gl_journal` | トランザクション通貨、現地通貨、報告通貨での仕訳明細。 |
| 試算表 | `cfm_trial_balance` | エンティティ、勘定科目、部門ごとの、現地通貨と報告通貨での期間の借方、貸方、純額。 |
| 売上明細 | `cfm_sales_line` | 数量、総額、割引、純額、COGS金額を持つ請求済みの売上明細。 |
| 在庫残高 | `cfm_inventory_balance` | 製品と倉庫ごとの期末在庫。 |
| 予算 | `cfm_budget` | シナリオ、バージョン、勘定科目、部門ごとの予算と予測。 |
| 配賦ドライバー | `cfm_stat_driver` | 人数、面積、数量などの統計ドライバー。 |

期間は`YYYY-MM`で記述され、トランザクションは転記期間で配置されます。予算は任意です。予算のないERPでも、ほかのすべてはロードされます。

試算表ファイルには、借方列と貸方列、純額列、またはその両方を含められます。借方と貸方のみの場合、純額は借方から貸方を引いたものになり、空白の側はゼロとして扱われます。純額のみの場合、正の純額は借方に、負の純額は貸方に、正の金額として変換されます。部門列は任意です。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| **接続をテスト**で、ERPが認証情報を拒否したと表示される | 接続の認証情報と、統合ユーザーがERPにサインインできることを確認します。 |
| **接続をテスト**で、データセットに**権限が不足しています**と表示される | 示されている権限を追加するよう、ERP管理者に依頼します。接続に必要なものは、ERPの[接続ガイド](/ja/guides/connections/)に記載されています。 |
| ERPのエラーメッセージが、ERP自体のメッセージより短い | PlaidCloudは、プロバイダーのエラーを表示する前に認証情報、トークン、キーを削除するため、一部の詳細は省略されます。**接続をテスト**を実行して、どのデータセットが影響を受けているかを確認します。 |
| ある期間で**ロード済みデータ**が問題になっている | その期間のERP読み取りが失敗しました。もう一度**ロード**を実行します。ロード済みの期間はスキップされます。 |
| **勘定科目表にない勘定科目**が問題になっている | ERPまたはファイルの勘定科目表に、不足している勘定科目を追加して、もう一度**ロード**を実行します。 |
| **通貨換算**が問題になっている | エンティティの通貨に、その期間の報告通貨へのレートがないか、単一の報告通貨が見つかりませんでした。**為替レート**ファイルにレートを追加するか、接続がERPの為替レートを読み取れることを確認するか、プロジェクト変数`reporting_currency`を設定します。その後、もう一度**ロード**を実行します。 |
| **通貨換算**が要確認になっている | 貸借対照表、在庫、予算の行に、その期間の期末レート、履歴レート、計画レートがありません。損益計算書には影響しません。予算月の計画レートを含めてレートを追加し、もう一度**ロード**を実行します。 |
| **Codes waiting for your answer**が要確認になっている | **確認**をクリックし、各コードに回答して、**Apply changes**をクリックします。 |
| **Which source covers which months**が要確認になっている | **Choose which source counts from when**をクリックし、ソースを選択して、**Apply changes**をクリックします。 |
| **Intercompany balances**が赤またはオレンジ色になっている | **Intercompany pairs**でペアを確認します。不足している側を計上するか、明細に取引先を追加するか、不足しているレートを追加します。 |
| **Group views are off** | アーキテクトに、**グループ**の下で**Everyone on the project may see the group results**にチェックを入れるよう依頼します。 |
| **未マッピングのエンティティ**が問題になっている | エンティティをエンティティマスターに追加するか、**エンティティ対応表**ファイルで既存のエンティティにそのコードをマッピングして、もう一度**ロード**を実行します。 |
