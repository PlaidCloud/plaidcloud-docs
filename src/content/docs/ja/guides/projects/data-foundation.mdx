**Data Foundation** は、PlaidCloudプロジェクトのための財務データ基盤です。その **Common Finance Model** は、複数のERPシステムと各システムの複数のインスタンスのERPデータを、1つの勘定科目表、1つのエンティティ体系、1つの報告通貨を持つ単一のモデルにまとめます。このモデルを基盤とするレポート、メトリック、AIアシスタントは、どのERPのデータであっても同じ数値を参照します。

ERPはPlaidCloudの接続を通じて接続されるため、総勘定元帳、試算表、マスターデータ、予算はエクスポートなしでソースから直接取り込まれます。ファイルは、為替レート、配賦ドライバー、ERPの外部で管理している予算など、システムが保持していないデータを補い、対象範囲のERPの行を置き換えることもできます。**ロード** は、すべてのソースをモデルに適合させ、報告通貨に換算し、合計が一致することを確認します。これらはすべてプロジェクトの **Foundation** タブから行います。ソース間で同じコードが異なる意味で使われている場合は、同じ意味かどうかを回答すると、管理連結によって会社間取引を消去したグループの損益計算書が作成されます。**Enterprise Profitability** などのテンプレートは、このモデルの上にレポートとモデルを構築します。

## ERPを接続する

ERPは、PlaidCloudの接続を通じてData Foundationに接続されます。Data Foundationは、総勘定元帳、試算表、マスターデータ、為替レート、予算をその接続から直接読み取り、読み取りのみを行います。既存の接続を選ぶことも、タブ上で新しく作成することもできます。各システムには、アクセスを許可する管理者向けのページがあり、[モデルにデータを供給できるシステム](/ja/guides/projects/data-foundation-getting-started/#モデルに取り込めるシステム)に一覧があります。また、[Data Foundationカバレッジマトリックス](/ja/reference/data-foundation-coverage-matrix/)では、各システムが直接供給するデータセットを確認できます。

<Steps>

1. Analyzeで **プロジェクト** を開き、**新規プロジェクト** をクリックします。名前を入力し、**開始元** で **空のプロジェクト** ではなく、**企業収益性(テンプレート)** などのテンプレートを選択します。**作成** をクリックします。

   プロジェクトは **Foundation** タブで開きます。共有するまでは、あなたのみがアクセスでき、あなたがそのプロジェクトの唯一のアーキテクトです。

2. **Foundation** タブで、ERPの既存の接続を選択するか、**新しい接続を作成** を選択します。既存の各接続には、その接続をすでに使用しているワークフローが一覧表示されます。使用されていない場合は **どのワークフローでもまだ使用されていません** と表示されます。

3. 新しい接続の場合は、**接続名** を入力し、**環境** を選択して、ERP接続が求める認証情報を入力します。

   認証情報をまだお持ちでない場合は、フォームにERP管理者向けのアクセスリクエストが用意されています。**リクエストをコピー** または **リクエストをメールで送信** をクリックして送信し、返信された値を入力します。

4. **接続をテスト** をクリックします。PlaidCloudがサインインして各データセットの読み取りを試み、それぞれを **読み取り可能**、**権限が不足しています**、または **エラー** として一覧表示します。不足がある場合は、ERP管理者に追加を依頼する権限の名前が表示されます。

5. **履歴の月数** を設定します。これは、何か月前までさかのぼってロードするかを指定するもので、1～120の範囲で指定します。デフォルトは24です。

6. 既存の接続の場合は、ロードするエンティティにチェックを付けます。すべてのチェックを外したままにすると、すべてのエンティティがロードされます。非アクティブなエンティティと消去用エンティティは、表示を選択するまで非表示です。その後、**接続** をクリックします。

7. 新しい接続の場合は、**接続** をクリックして作成します。その後、ロードするエンティティにチェックを付け、もう一度 **接続** をクリックして保存します。保存するまでは、すべてのエンティティがロードされます。

8. 別のERPシステムや別のインスタンスを取り込むには、これらの手順を繰り返し、**接続** をクリックする前に **Add this as another source instead of replacing the current one** にチェックを付けます。チェックを付けない場合、新しい接続が現在のソースを置き換えます。

</Steps>

接続が完了すると、カードにプロジェクトがロードする接続、環境、エンティティ、履歴の月数が表示されます。

各ロードでは変更された部分のみを読み取ります。未締めの期間と最後に締められた期間は再度読み取られ、すでにロード済みの締め済み期間は保持されます。**履歴の月数** を増やすと、追加された月のみが読み取られます。為替レート、エンティティ対応表、報告通貨を変更した場合は、影響を受ける月が再度読み取られます。

## ソース

プロジェクトがロード元とするERPシステムとインスタンスは、それぞれがソースです。**Foundation** タブの **ソース** リストには、ソースごとに1行ずつ順番に、名前、前回のロード日時、供給した行数、読み取る報告帳簿が表示されます。例：`1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`。まだロードされていないソースには **not loaded yet** と表示されます。確定したファイルもソースです。

ソースの **高度** を開くと、そのソースの使い方を変更できます。

| 設定 | 内容 |
|---|---|
| **名前** | レポート、マッピングの質問、メッセージがソースを指すときに使うラベルです。 |
| **Place in the order** | ソースの順位です。2つのソースが同じ会社の同じ月を対象とする場合、順位が上のソースが優先されます。 |
| **Reporting books, separated by commas** | 読み取る会計帳簿です。複数の帳簿を保持するシステムで使用します。**All reporting books** はすべての帳簿を読み取ります。 |
| **会社**、**開始 (2026-01)**、**終了 (2026-12)** | このソースが会社ごとに提供する月です。月を空欄にすると制限なしになります。月は、`2026-03` のように年と月で記述します。 |

**保存** をクリックして変更を保持します。ソースを削除するには、**Remove this source** をクリックし、**削除** を確認します。そのソースからロードされたものはすべて削除されますが、後で再度接続できます。

ソースを変更しても、ERPは再度読み取られません。**前回のロード** カードには、**Apply changes** をクリックするまで **Changes not applied yet** と表示されます。**Apply changes** は、すでに取得済みのデータからロードを実行します。新しい順序、マッピング、名前、ファイルでソースを再度適合させ、モデルを再構築します。ERPから最新のデータも取得したい場合は、**ロード** をクリックします。

## ERP外のデータのファイルを追加する

ファイルは、為替レート、配賦ドライバー、[エンティティ対応表](#エンティティ対応表)、ERPの外部で管理している予算など、システムが保持していないデータでERP接続を補います。各ファイルは、[Common Finance Modelのテーブル](#common-finance-modelのテーブル)に記載されたデータセットのいずれかに属します。

<Steps>

1. **ファイル** で、ファイルを保存する **ドキュメントアカウント** を選択します。

2. CSVまたはExcelファイルを **CSV または Excel ファイルをここにドロップ** にドロップするか、**ファイルを選択** をクリックします。ファイルは、ドキュメントアカウントの `/foundation/` フォルダーにアップロードされます。

   すでにドキュメントアカウントにあるファイルの場合は、`/foundation/budget.csv` のように **ファイルパス** を入力し、**ファイルを追加** をクリックします。

   毎月新しいファイルを読み取るには、名前が一致するフォルダー内のすべてのファイルを追加します。フォルダーと、**File names that** の条件（含む、で始まる、で終わる、完全に一致する、パターンに一致する）を入力し、**Add files** をクリックします。その中のフォルダーにあるファイルは読み取られません。

3. PlaidCloudがファイルを読み取り、マッピングを提案します。

   - **区切り文字、小数点の区切り文字、日付の検出。** 区切り文字（カンマ、セミコロン、タブ、パイプ）、小数点の区切り文字、日付形式は自動的に検出されます。
   - **データセット**：ファイルが属するCommon Finance Modelのテーブルです。ファイル名と列見出しから照合されます。照合が明確でない場合は、リストから選択します。
   - **小数点の区切り文字**：**ピリオド (1,234.56)** または **カンマ (1.234,56)** です。
   - **日付形式**：ファイルに日付がある場合に表示されます。検出された形式が誤っている場合は、`YYYY-MM-DD`、`DD.MM.YYYY`、`DD/MM/YYYY`、`MM/DD/YYYY` のいずれかに変更します。
   - **ファイル内の列**、**タイプ**、**例**、**対応先** のグリッドです。**対応先** を変更すると、列を別のフィールドに送ったり、**ロードしない** にしたりできます。

4. ファイルから生じる質問に回答します。たとえば、**Which company is this file for?**、**Which currency are the amounts in?**、**Are these amounts year-to-date or for the month?**、**Are the amounts shown in thousands or millions?**、**Are revenues shown as negative numbers?** などです。各質問は、ファイルにその情報がない場合にのみ表示されます。

5. 各列の送り先を確認し、**マッピングを確定** をクリックします。

</Steps>

次のオプションは、該当する場合にファイルに表示されます。

| オプション | 用途 |
|---|---|
| **Which source do these rows apply to?** | コードマップファイルを1つのソースに限定します。**Every source** はすべてのソースに適用します。 |
| **Where does this file come from?** | ファイルが **This project's own codes** を保持しているか、**Another system** から来ているかを指定します。システム名は `SAP Germany export` のように入力します。別のシステムのファイルは、ERPソースと同様に共有コードがチェックされます。 |
| **Split … into … parts at each …**（**高度** 内） | `100-200-300` のように複数の値を保持する1つの列を分割し、各部分をそれぞれのフィールドに送ります。 |
| **Which currency do you report in?** | プロジェクトにまだ報告通貨がない場合に設定します。`USD` のように3文字で記述します。 |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | 連結システムの結果をロードし、グループの損益計算書を[照合](#連結システムと照合する)できるようにします。 |

ファイルをプロジェクトから削除するには、**ファイル** の下でその横にある **削除** をクリックするか、マッピング上の **Remove this file** をクリックして確認します。そのファイルの数値は、次に **Apply changes** をクリックしたときにレポートから除外されます。

PlaidCloudがデータセット、小数点の区切り文字、日付の順序を自動的に判断できない場合（たとえば、日付が日/月とも月/日とも読めるファイルなど）は、確定する前に選択するよう求められます。同じデータセットに2つ目のファイルを追加すると、最初のファイルが置き換えられます。後のファイルの列がデータセットと一致しない場合、ロードはファイルと列を示し、ファイルまたは列名を修正するか、ステップの **Schema Mismatch** を `union` に設定するよう案内します。

受け付けるファイルは、CSV、TSV、TXTのテキストファイル、Excelの `.xlsx` ファイル（最初のシートを読み取ります）、およびParquetファイルです。

<Aside type="note">
ファイルが存在しない場合や空の場合でも、ロードが停止することはありません。追加時にはまだマッピングするものがないと表示され、ロードはパスを示す警告とともに完了し、そのデータセットは空のままになります。ファイルが用意できたら、再度追加してください。
</Aside>

## データをロードする

**ロード** カードまたは **前回のロード** カードの **ロード** をクリックします。ロードは、接続されたERPと確定したファイルを読み取り、Common Finance Modelに適合させ、報告通貨に換算し、準備状況のチェックを実行して、テンプレートのモデルを再構築します。

- プロジェクトで同時に実行できるロードは1つだけです。2つ目の **ロード** または **Apply changes** を実行すると、すでにロードが実行中であると表示され、実行中はソースを変更できません。
- 他のワークフローが同じERP接続を使用している場合、ロードはERPから読み取るためそれらのワークフローが遅くなる可能性があることから、最初のロードではそれらを一覧表示して確認を求めます。続行するには **このままロード** をクリックします。
- PlaidCloudのアップグレード後は、アーキテクトの **ロード** がプロジェクトの生成済みワークフローも更新し、必要な作業用テーブルを作成します。それまでは、ステータスページに「The workflows were generated by an earlier release. An Architect's Load updates them.」という黄色の項目が表示され、マネージャーの **ロード** では、更新できるのはアーキテクトだけであるという警告が表示されます。
- 失敗したロードは赤で表示され、以前の結果の陰に隠れることはありません。連結が失敗した場合、ステータスには以前のグループ結果ではなく、停止したステップが示されます。以前のロードの行には、ロードが成功するまで **以前のロードの結果です。もう一度ロードしてください。** と表示されます。
- 1つのエンティティと期間の読み取りが失敗しても、残りはロードされます。**ロード** を再度実行すると、失敗した部分のみが取得されます。

### 保留された行

ソースが重複する場合、ロードは各数値のコピーを1つだけ保持し、残りは二重にカウントせずに保留します。保留された行は、ソース、エンティティ、理由とともに記録され、ロードは件数を示す警告とともに完了します。例：`120 rows of NetSuite EU also provided by a source ranked ahead`。理由は次のとおりです。

| 理由 | 意味 |
|---|---|
| 別の会計帳簿にある | 行が、ソースの読み取り対象に設定されていない報告帳簿に属しています。 |
| ソースが提供する期間の外 | 行が、会社に設定された **開始** と **終了** の月の範囲外です。 |
| 上位のソースも提供している | 順位が上のソースが同じ会社と月を対象としています。 |
| ソースの以前のファイルにもある | 同じソースの以前のファイルがすでにその月を対象としています。 |
| ファイルで置き換えられた | ファイルが、そのエンティティと月のERPの行を置き換えています。 |
| 他のソースも使用しているコードを持つ | このコードにはあなたの回答が必要です。[ソース間でコードをマッピングする](#ソース間でコードをマッピングする)を参照してください。 |
| 2つのコードにマッピングされたコードを持つ | コードマップがそのコードに2つの回答を与えています。 |

統計勘定は元帳ではなく配賦ドライバーに移動し、問題ではなく移動済みとして表示されます。

### ERPデータとファイルの併用

ファイルは対象範囲のみを置き換え、ERPのその他の行は残ります。

- **マスターファイル**（勘定科目、部門、顧客、製品、セグメント値）は、同じコードを持つERPの行を置き換えます。
- **トランザクションファイル** は、同じエンティティと月のERPの行を置き換えます。総勘定元帳ファイルと試算表ファイルは帳簿でも照合され、予算ファイルはシナリオで、統計ドライバーファイルはシナリオとドライバーで照合されます。

ファイルが後でその月を対象としなくなった場合、その月のERPのデータは次のロードで復活します。

## エンティティ対応表

各ソースは、独自のコードでエンティティを指します。**エンティティ対応表** は、それらのコードをエンティティマスターのエンティティにマッピングし、すべてのソースの明細が同じエンティティに集約されるようにします。

使用するには、CSVまたはExcelファイルを追加し、**エンティティ対応表** データセットを選択します。

| 列 | 内容 |
|---|---|
| `source_entity` | 会社コードなど、ソースが保持しているコードです。 |
| `entity` | エンティティマスターで名付けられている、そのコードが属するエンティティです。 |

- 対応表にないコードは、そのまま使用されます。
- 複数のコードを1つのエンティティにマッピングできます。それらの明細は結合され、月はそのすべてで締められた時点で締め済みとして扱われます。
- 対応表のコードはすべてのソースに適用されるため、各ソースのエンティティコードはソース間で一意である必要があります。
- **エンティティ** ファイルの行は、同じエンティティコードを持つERPのエンティティを置き換えます。

**未マッピングのエンティティ** チェックは、エンティティがエンティティマスターになく、対応表でもマッピングされていない明細をすべてフラグ付けします。エンティティマスターがロードされるまでは、**– 対象外** と表示されます。

## ソース間でコードをマッピングする

2つのソースが同じコードを異なるものに使用したり、同じものに異なるコードを使用したりすることがあります。コードが複数のソースに現れる場合、Data Foundationは、それがどこでも同じ意味かどうかをあなたが回答するまで、その行を保留します。これにより、各金額が1回だけカウントされます。**Codes waiting for your answer** チェックは、最初の10件とその後の「and K more」を一覧表示し、**Foundation** タブの **What to do next** カードには **確認** ボタンがあります。

**確認** をクリックすると、**Codes waiting for your answer** が開きます。コードは種類別にグループ化されます：**Account types**、**Companies**、**Accounts**、**Departments**、**Profit centers**、**Customers**、**Products**、および各追加カテゴリーです。各コードについて、各ソースがそれを何と呼んでいるかと提案が表示されます。

- **Looks like the same thing**：ソースがそのコードに同じ名前を付けている場合。
- **Looks like different things**：名前が異なる場合。
- **We can't tell. Please answer.**：判断材料がない場合。

コードごとに **Yes, the same** または **No, different** で回答するか、**Accept all**（すべての提案を採用）、**All the same**、**All different** でグループ全体に一度に回答します。勘定科目の場合は、勘定科目表の親グループ全体に一度に回答することもできます。ソースに勘定科目タイプがない場合は、勘定科目のグループに対して **Use this type** を選択します：**Revenue**、**Cost of goods sold**、**Operating expenses**、**Non-operating income and expenses**、**Assets**、**Liabilities**、または **Equity**。

マッピングはソースとディメンションごとに保持されるため、あるソースの部門への回答が別のソースの勘定科目を変更することはありません。回答は入力するたびに保存され、**Saved. Press Apply changes to use your answers.** と表示されます。回答を使用するには、**Apply changes** をクリックします。

マッピングをファイルで提供することもできます。**Code map** データセットのファイルを追加し、**Which source do these rows apply to?** を選択して1つのソースに限定します。

## どのソースをいつから採用するかを選択する

2つのソースが同じ月を提供している場合、**Which source covers which months** チェックが選択を求めます。**What to do next** カードで **Choose which source counts from when** をクリックすると **Which source counts from when** が開き、重複が会社ごとに一覧表示されます。採用するソースを選択し、**That month is** に採用を開始する月（例：`2026-04`）を入力して、**Apply changes** をクリックします。もう一方のソースは、それ以前の月を保持します。

同じダイアログでは、2つのソースが通貨に対して異なる為替レートを提供している場合にも警告が表示されます。この場合、順位が上のソースのレートが使用されます。

## 通貨換算

各ロードは、総勘定元帳、試算表、売上、在庫、予算の金額を、現地通貨から1つの報告通貨に換算します。レポートとモデルは換算後の金額を参照するため、異なる通貨のエンティティも、どのシステムのものであっても正しく合計されます。

### 報告通貨

報告通貨を選択するには、プロジェクト変数 `reporting_currency` を `USD` などの通貨コードに設定します。[プロジェクト変数の管理](/ja/guides/projects/managing-projects/#プロジェクト変数の管理)を参照してください。テンプレートはこの変数を空で作成します。空の間は、各ロードで次のうち、通貨が1つだけに特定される最初のものが使用されます。

1. エンティティのグループ通貨。
2. 親を持たない最上位エンティティの現地通貨。
3. ファイルの現地通貨。

どれも通貨を1つに特定できない場合は、`reporting_currency` を設定するまで **通貨換算** が問題として表示されます。

すでに報告通貨になっている金額はそのままなので、データがすべて1つの通貨であるプロジェクトにはレートは不要です。

売上、在庫、予算のファイルも通貨を保持できます。`Currency` または `Local Currency` という名前の列をマッピングすると自動的に認識され、ファイルの現地金額が報告通貨に換算されます。ファイルにすでにあるグループ金額または報告金額は、そのまま保持されます。製品の標準原価は換算されません。

### 為替レート

レートは、通貨1単位をある月の報告通貨に換算するものです。換算後の金額は、現地金額にレートを掛けたものです。

- **ERPから**：各ロードで、ERPが保持している為替レートを読み取ります。
- **ファイルから**：CSVまたはExcelファイルを追加し、**為替レート** データセットを選択します。ファイルのレートは、同じ通貨と月のERPのレートを置き換えます。ERPがレートを公開していない通貨で報告する場合や、予算月の計画レートを追加する場合にファイルを使用します。

| 列 | 内容 |
|---|---|
| `from_currency` | 換算元の通貨です。例：`EUR`。 |
| `to_currency` | 報告通貨です。例：`USD`。 |
| `period` | 月です。`YYYY-MM` の形式です。 |
| `average_rate` | その月の平均レートです。 |
| `closing_rate` | 月末のレートです。 |
| `historical_rate` | 資本、および履歴レートに設定された勘定科目に使用する履歴レートです。 |

報告通貨へのレートのみが使用されます。報告通貨から別の通貨へという逆向きで提示されたレートは、逆数に変換されません。

### 適用されるレート

各行はその行自身の通貨から換算されるため、エンティティと異なる通貨の明細は、その明細の通貨から換算されます。行に当てはまる最初のルールが適用されます。

| 行 | レート |
|---|---|
| 統計勘定および非転記勘定 | 換算されません。 |
| すでに報告通貨になっている | 換算されません。 |
| レートタイプを持つ勘定科目 | そのレート：平均、期末、または履歴。履歴レートがない場合、履歴は期末にフォールバックします。ERPからの場合、レートタイプは勘定科目自身のレートタイプです。勘定科目表ファイルでは、レートタイプの列を `fx_rate_type` にマッピングし、`average`、`closing`、`historical` のいずれかを指定します。 |
| 売上明細 | 期間の平均レート。 |
| 在庫残高 | 期間の期末レート。 |
| 予算の行 | 総勘定元帳と同様に勘定科目別：損益計算書の勘定科目には平均レート、貸借対照表の勘定科目には期末レート。 |
| 損益計算書の勘定科目 | 期間の平均レート。 |
| 資本の勘定科目 | 履歴レート。履歴レートがない場合は期末レート。 |
| その他の貸借対照表の勘定科目 | 期間の期末レート。 |

換算後の金額は丸められないため、合計がずれることはありません。

<Aside type="note">
試算表は各期間の変動額を保持しているため、貸借対照表の金額は、各月の変動額をその月の期末レートで換算したものになります。期末レートで再換算された貸借対照表ではなく、累積換算調整額や会社間取引の消去もありません。換算後の金額は損益計算書にご利用ください。
</Aside>

## 階層

各ロードは、すべてのソースのマスターデータからディメンションを再構築します。最初は7つのディメンションがあり、追加カテゴリーを最大10個まで追加できます。

| ディメンション | 構築元 |
|---|---|
| **エンティティ** | エンティティとその親 |
| **勘定科目** | 勘定科目表と親勘定科目 |
| **部門** | 部門とその親 |
| **顧客** | 顧客とその親顧客 |
| **製品** | 製品とその親製品 |
| **Segment 1** | `segment_1` のセグメント値 |
| **Segment 2** | `segment_2` のセグメント値 |
| **Segment 3** ～ **Segment 10** | ソースが保持している場合の `segment_3` ～ `segment_10` のセグメント値 |

- 親を持たないレコード、または自分自身を親とするレコードは、最上位のメンバーとしてロードされます。
- 各ロードで階層が再構築されるため、親の変更はディメンションではなく、ERPまたはファイルで行ってください。
- 1つの階層の問題は、そのディメンションにのみ影響します。ロードとテンプレートのモデルは引き続き完了します。
- 各追加カテゴリーの名前は、保持する内容に合わせて、たとえば **クラス** や **リージョン** に変更できます。**Rename extra categories** で、レポートで使用する名前を入力し、**Save names** をクリックします。名前には、文字、数字、スペース、ドット、ダッシュ、アンダースコアを60文字まで使用できます。
- 各ソースは、そのソース独自の各追加カテゴリーが、あなたのどのカテゴリー名に属するかを指定します。ソースの **高度** を開いて各名前を選択するか **Leave out** を選択し、**保存** をクリックします。`Class` と `Business area` のように異なる名前でカテゴリーを呼ぶソースは、1つのスロットを共有します。

セグメント階層をファイルで提供するには、**セグメント値** データセットを選択します。

| 列 | 内容 |
|---|---|
| `segment` | 値が属するセグメント：`segment_1` ～ `segment_10`。 |
| `segment_value` | 総勘定元帳、売上、予算の明細が保持している値。 |
| `segment_value_name` | その名前。 |
| `parent_segment_value` | 同じセグメント内の親。 |

## 準備状況のチェック

各ロードの後、**準備状況** グリッドには、すべてのエンティティと期間のすべてのチェックが、次のいずれかのステータスとともに一覧表示されます。

| ステータス | 意味 |
|---|---|
| **● 準備完了** | チェックに合格しました。 |
| **▲ 要確認** | 確認する価値はありますが、数値は使用できます。 |
| **■ 問題** | 結果に依存する前に修正してください。 |
| **– 対象外** | このチェックの対象となるデータがまだありません。 |

チェックは次のとおりです。

| チェック | 確認内容 |
|---|---|
| **ロード済みデータ** | すべての会計期間に総勘定元帳の明細があり、すべてのERPの読み取りが成功しています。明細のない締め済み期間は問題となり、明細のない未締め期間は要対応となります。 |
| **試算表と総勘定元帳の一致** | 試算表が、エンティティ、期間、勘定科目ごとに総勘定元帳と等しくなっています。勘定科目について試算表と総勘定元帳の両方に部門がある場合は、部門ごとにも一致を確認します。 |
| **売上と総勘定元帳の一致** | 売上明細が、期間ごとに総勘定元帳の収益およびCOGSの勘定科目と等しくなっています。 |
| **不明な製品/顧客** | すべての売上明細が、製品マスターと顧客マスターに存在する製品と顧客を指定しています。 |
| **勘定科目表にない勘定科目** | すべての総勘定元帳の明細が、勘定科目表にある勘定科目を指定しています。勘定科目が不明な明細は損益計算書から除外されます。転記があるのに勘定科目タイプがない勘定科目も問題となり、収益の勘定科目にタイプがあるのに売上原価の勘定科目がないソースは要対応となります。 |
| **通貨換算** | すべての総勘定元帳、試算表、売上、在庫、予算の行に報告通貨の金額があります。損益計算書は換算後の金額を参照するため、レートのない損益計算書または売上の行は問題となります。レートのない貸借対照表、在庫、予算の行は要対応となります。レートがまだない予算の月は黄色で表示されるため、予算月の計画レートをロードしてください。[通貨換算](#通貨換算)を参照してください。 |
| **未マッピングのエンティティ** | すべての総勘定元帳、試算表、売上の明細が、エンティティマスター内のエンティティを、直接またはエンティティ対応表を通じて指定しています。エンティティマスターがロードされるまでは対象外です。[エンティティ対応表](#エンティティ対応表)を参照してください。 |

複数のソースがあるロードでは、次のチェックが追加されます。

| チェック | 確認内容 |
|---|---|
| **Reporting book** | エンティティに複数の会計帳簿を持つソースで、報告帳簿が選択されています。選択するまでは、最初の帳簿のみが対象になります。 |
| **Codes waiting for your answer** | 複数のソースで使用されているすべてのコードに回答済みです。[ソース間でコードをマッピングする](#ソース間でコードをマッピングする)を参照してください。 |
| **Extra categories from your sources** | ソースが保持するすべての追加カテゴリーに名前が付けられているか、除外されています。 |
| **Which source covers which months** | どのソースを採用するかを選択していない限り、2つのソースが会社の同じ月を提供していません。 |
| **Account types and hierarchy** | ディメンションが指定するすべての親が存在し、自分自身の親または祖先となるメンバーがいません。親が見つからない場合、その子は階層の最上位に置かれ、ループがある場合はその階層のロードが停止します。合計には影響しません。 |
| **会計カレンダー** | 各エンティティの会計期間が暦月であり、行のすべての月を1つの会計期間に割り当てられます。エンティティの期間が暦月でない場合（4-4-5、13期間）、または月の行が複数の会計期間に該当する可能性がある場合や、会計カレンダーにその月がない場合は要対応となります。 |

準備が完了していない各行には、**対応** 列に対処方法が示されます。たとえば、勘定科目表のロード、為替レートのロード、期間に対する **ロード** の再実行などです。

グリッドには2つのセットアップチェックも表示されますが、これらは対応が必要な場合にのみ表示されます。

| チェック | 表示されるタイミング |
|---|---|
| **間接費の配賦** | プロジェクト変数 `overhead_department` と `overhead_driver` の一方のみが設定されている場合、または `overhead_driver` に一致する配賦ドライバーがなく、配賦が何も行われない場合です。両方を設定するか、両方をクリアして間接費の配賦をオフにします。 |
| **予算比較** | 予算の行がロードされているが、プロジェクト変数 `budget_version` が指定するバージョンにそれが1つもなく、予算比較が空になる場合です。 |

## 管理連結

各ロードは、管理連結を構築します。これは、グループ内のすべてのエンティティのグループ損益計算書を、報告通貨で、会社間取引を消去して作成するものです。管理報告用です。法定グループの正式な記録は引き続き連結システムです。以下の手順でそれと照合してください。

<Aside type="note">
管理連結の対象は損益計算書のみです。法定連結や法的連結ではなく、連結貸借対照表、換算調整額、のれん、非支配株主持分はありません。
</Aside>

### グループを選択する

**ソース** の下で **グループ** を開くと、グループ内の会社が表示されます。チェックを外した会社は、単独ではレポートに残りますが、グループ合計からは除外されます。**Save group** をクリックします。変更は次の **ロード** または **Apply changes** で反映されます。新しい会社は、チェックを外すまでグループに含まれます。

グループの会計年度は、プロジェクト変数 `group_fy_start_month` で設定された月に始まります。変更しない限り `1` です。

### 取得できるもの

| テーブル | 内容 |
|---|---|
| **Group P&L** | エンティティ、期間、ラインごとに1行（収益、売上原価、営業費用、営業外、会社間差異）。報告通貨です。収益とコストは本来の符号を持ちます。 |
| **Group P&L year to date** | 同じ内容を、グループの最後に完全にロードされた期間までの年初来で示したものです。 |
| **Intercompany pairs** | エンティティ、グループ、期間のペアごとに1行で、各側の金額と残差を示します。 |
| **Intercompany lines** | グループの数値またはペアの根拠となる元帳の明細で、取引相手が含まれます。 |
| **Reconciliation** | 連結システムに対するグループ損益計算書の年初来の照合結果です。 |

これらのテーブルには、3つのエンティティ名が表示されます。

| エンティティ | 意味 |
|---|---|
| **Eliminations** | 会社間取引の消去です。合計はゼロになるため、グループの数値ではそのまま残し、消去前のエンティティの合計ではフィルターで除外します。 |
| **Group total** | 照合における連結システムの合計です。 |
| **Unmapped** | 期間のない明細と、このプロジェクトにない連結システムの勘定科目またはエンティティです。 |

メトリック **Consolidated income**、**Consolidated result**、**IC difference**、および各テーブルの分析パスが、グループに関する質問に答えます。

### 会社間取引の消去

会社間取引の明細は、取引相手によって照合されます。明細にある取引相手が使用され、明細に取引相手がない場合は、その顧客の取引相手が使用されます。ペアの両側が消去され、両側が一致しない金額は会社間差異の明細に計上されます。各ペアには理由が付きます。

| 理由 | 意味 |
|---|---|
| **Matched** | 両側が同じ金額を計上しています。 |
| **Only one side booked** | 一方のエンティティが取引を計上し、相手は計上していません。 |
| **Not eliminated** | ペアの明細に為替レートがないため、どちら側も消去されません。 |

ペアは年初来で判定されます。ペアの差異がプロジェクト変数 `group_amber`（デフォルトは `1`）を超えると **Intercompany balances** 行が黄色に、`group_red`（デフォルトは `1000`）を超えると赤になります。取引相手のない明細や、取引相手がエンティティでない明細は消去されず、その行でカウントされます。取引相手を保持するソースと保持しないソースが混在すると、黄色で表示されます。

ソース自身の消去用エンティティはグループ損益計算書から除外され、**連結** 行にその旨が表示されます。

### 連結システムと照合する

連結システムが報告する結果をファイルとして追加し、マッピングを確定するときに **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** にチェックを付けます。**Which version of the numbers is this?** には、システム名を回答します。**Reconciliation** テーブルには、エンティティとラインごとの年初来の **ours**、**reported**、**差異** が表示されます。差異は、通常 **Eliminations**、**Group total**、**Unmapped** の行、またはシステムが使用する為替レートで説明できます。**Reconciliation to the source** 行には、`group_amber` を超えるすべての明細が一覧表示されます。

### 閲覧できるユーザー

グループの結果はプロジェクトの行アクセスに従います。行アクセスによってグループの結果が制限される場合、ステータスは黄色で表示されます。一部のエンティティしか閲覧できないユーザーには、それらのエンティティの消去前の合計が表示されます。**Eliminations** の行と会社間取引のテーブルには、すべてのエンティティへのアクセスが必要です。

プロジェクトが、グループテーブルにない列（部門など）で行の閲覧を制限している場合、グループの結果は全員に対してオフになり、**連結** には **Group views are off** と表示されます。その場合、アーキテクトのみが **グループ** の下の **Everyone on the project may see the group results** にチェックを付けることができます。変更は次の **ロード** または **Apply changes** で反映されます。

## 最新の状態を保つ

ERP接続からのロードが問題なく成功すると、**前回のロード** カードに **夜間に更新** が表示されます。これをクリックすると、タイムゾーンの毎晩2:00に **ロード** が実行されます。その後、カードには **Nightly refresh: Every night at 2:00** と設定したユーザーが表示されます。

夜間ロードは、設定したユーザーとして実行されます。そのユーザーがERP接続を使用できなくなった場合、グリッドに夜間ロードがスキップされることが表示されます。その場合は、設定し直してください。サンプルデータのみのプロジェクトは、スケジュールできません。

夜間ロードでファイルが存在しない、または空の場合は、エラーではなく、パスを示す警告とともに完了し、モデルの残りは引き続きロードされます。

## ビジネス名

**Foundation** タブの **Business names** は、モデル内のコードに、ビジネスで使用している名前を付けます。レポート、メトリック、アシスタントはこれらの名前を表示し、保存した名前は即座に適用されます。以降のロードでもそのまま保持されます。

1. **Add a name** をクリックし、**種類** を選択します：**カテゴリー**、**P&L line**、**メトリック**、または **列**。
2. **コード** を入力します。カテゴリーの場合は `segment_1` ～ `segment_10`、P&Lラインの場合はそのラインのキー、メトリックの場合はメトリックの名前、列の場合は `table.column` です。
3. **名前** を入力します。1行で60文字までです。
4. **Save names** をクリックします。

保存すると、リスト全体が置き換えられます。名前が空の行はその名前を削除し、**選択項目を削除** はチェックを付けた行を削除します。同じコードに2回名前を付けることはできません。ビジネス名は、アシスタントがあなたの言葉を使えるように、分析パスの説明にも書き込まれ、その説明には長さの制限があります。名前によって長くなりすぎる場合は、何も保存されず、その旨が通知されます。

## 数値を説明する

**Explain this number** は、損益計算書の1つの数値の内訳を示します。**準備状況** グリッドで、エンティティと月の行に **Explain this number** があり、その月のエンティティの営業利益率が開きます。ウィンドウは、数値を、一番上の合計になるレイヤーに分割します。

| レイヤー | 内容 |
|---|---|
| **From the general ledger** | 元帳がそのラインに転記した内容。 |
| **Allocated in** | [配賦ルール](#配賦ルール)によってこのエンティティに配分されたコスト。 |
| **Allocated out** | このエンティティが他に配分したコスト。 |
| **Eliminated in the group** | グループの結果で消去された会社間取引。 |

各レイヤーには、それが何であるかを説明する文と、最大のソースドキュメントがソースシステム、ドキュメント、勘定科目とともに表示されます。行があるレイヤーのみが表示されます。ウィンドウは行アクセスに従うため、閲覧できる数値のみを説明できます。裏付けとなるものがない数値には **Nothing to explain** と表示されます。

## 配賦ルール

配賦は、間接費などの共通コストを、部門、製品、顧客に配分します。モデルには2つの段階があります：**Stage 1: overhead to departments** と **Stage 2: departments to products and customers** です。**アクション > 配賦...** を開くと、それぞれの方法を確認または変更できます。変更しない場合、ウィザードが登場する前と同じように動作します。閲覧者はルールを開くことはできますが、保存できません。

各段階で、ウィザードは4つの質問をします。

| ステップ | 質問 | 選択肢 |
|---|---|---|
| **Pool** | どのコストを配分しますか？ | 勘定科目の種類。段階1では、そのコストを保持する部門または **All departments**。 |
| **ドライバー** | 何を基準に配分しますか？ | 配賦ドライバーとしてロードした **Statistic**（人数や面積など）、**Net sales amount**、**Sales quantity**、または **Spread evenly**。**Same period** または **Same period last year** のドライバーを使用します。 |
| **ターゲット** | どこに配分されますか？ | 段階1：部門。段階2：製品、顧客、またはその両方。 |
| **メソッド** | ドライバーが負の場合はどうなりますか？ | **Ignore negative values** または **Stop and tell me**。 |

ステップの下にある **Preview for** に、`2026-09` のように年月で月を指定すると、保存していないものを含め、ルールが何を行うかが `Pool 120,000 · Allocated 120,000 · Unallocated 0` のように表示されます。未配賦のものは、受け取るドライバーがなかったコストです。プレビューは行アクセスに従います。

**保存** をクリックします。ルールは次の **ロード** で、または **Apply changes** をクリックしたときに有効になります。配賦ステップを手動で編集した場合、その編集は上書きされずに保持され、保存時にそのステップが示されます。ロードの実行中は保存できません。

## 取締役会資料

取締役会資料は、結果を、スケジュールに従ってドキュメントアカウントのフォルダーに書き込み、送付できる状態にします。**アクション > Board pack...** を開き、**ドキュメントアカウント** と `/board-packs` のような **フォルダー** を選択して、**保存** をクリックします。実行のたびに次のものが書き込まれます。

- Excelブック `Board pack.xlsx`。エンティティ別の損益計算書、マージンブリッジ、上位および下位の顧客が含まれます。
- 損益計算書ダッシュボードのPDF。

プロジェクトにまだダッシュボードがない場合は、ブックのみが書き込まれ、実行時にその理由が示されます。**Run now** をクリックすると、すぐに資料を作成できます。完了すると、そのファイルがフォルダーに表示されます。カードには、前回の実行とその結果、次回の実行が表示されます。資料はプロジェクトの **Board pack** ワークフローによって作成されますが、夜間の更新ではこのワークフローは実行されません。スケジュールに従って作成するには、[イベントスケジューラー](/ja/administration/scheduled-events/event-scheduler/)でそのワークフローをスケジュールします。たとえば、夜間の更新が完了した後の時刻に設定します。設定できるのは、プロジェクトを変更できるユーザーのみです。

## 復元ポイント

復元ポイントは、**ロード** または **Apply changes** が開始されるたびに、開始したユーザーを問わず（スケジュールされたロードを含みます）、またマッピングやソースを変更する前に作成されます。これには、モデルのテーブル、ディメンション、次回のロードが構築の元とする設定（ソース、ファイル、配賦ルール）が含まれます。ロード時に作成された直近の7つのポイントと、変更前に作成された直近の5つのポイントが保持されるため、変更によってロード時のポイントが押し出されることはありません。それより古いポイントは削除されます。

元に戻すには、**アクション > 復元...** を開き、ポイントを選択して **復元** をクリックします。**復元** は、ポイントが存在するようになると利用できます。復元時には、まず現在のプロジェクトの状態が独自のポイントとして記録されるため、再度元に戻せます。その後、テーブル、ディメンション、それらの設定が以前の状態に戻り、次のロードはそれらから構築されます。保存されたコピーがないテーブルや、履歴を保持できないエンジンは警告で示され、残りは復元されます。削除済みの復元ポイントは拒否され、ロードの実行中は復元できません。

## プロジェクトを複製する

**アクション > 複製...** は、指定した名前でプロジェクトをコピーします。コピーには、テンプレート、モデルへの編集、メトリックと分析パスが保持され、サンプルデータがロードされます。ソースは接続されていないため、ロードする前にコピー内で接続してください。コピーの作成中も作業を続けられ、準備ができたら **プロジェクトを開く** でコピーに移動できます。

## マイテンプレートとして保存する

プロジェクトの設定を保存して、次のクライアントやエンティティで再利用できます。**アクション > Save as my template...** を開き、ドキュメントアカウントを選択して、ファイルに名前を付けます。名前が `.zip` で終わっていない場合は追加されます。既存のファイルへの上書き保存は拒否されるため、別の名前を選択してください。

ファイルには、プロジェクトの構造、モデルへの編集、メトリックと分析パス、エンティティと勘定科目のビジネス名、およびテンプレートの設定テーブルの行が含まれます。たとえば、[Cost to Serve](/ja/guides/projects/cost-to-serve/)のアクティビティマップや、[Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/)のポリシー範囲などです。接続、ファイル、夜間スケジュール、実行、復元ポイント、取締役会資料、アクセス権を持つユーザーは含まれません。

使用するには、プロジェクトを作成し、**開始元** で **From a template file...** を選択して、ドキュメントアカウントとパスを指定します。新しいプロジェクトはあなただけが利用でき、すべてのソースが接続待ちの状態になります。テンプレートの後のリリースは、編集したステップを避けて変更をマージします。パスにファイルがない場合は、何も作成されず、その旨が通知されます。ドキュメントアカウントを読み取れるユーザーは、誰でもそのファイルからインストールできます。別のワークスペースで使用するには、ファイルをダウンロードして、そこにアップロードしてください。

## Askで未解決の質問を解決する

ロードの後でも、プロジェクトには次の3つについて回答待ちが残っている場合があります。勘定科目表でタイプが指定されていない勘定科目、複数のソースが使用しているコード、ファイル内でどれにも一致しなかった列です。アシスタントに解決を依頼してください。MCP経由のAIアシスタントから、**Resolve Data Foundation residue** プロンプトを使用します。回答待ちの項目を読み取り、各項目について理由とともに1つの回答を提案します。

アシスタントは何も書き込みません。提案された回答は、ご自身で回答する場所に適用します。勘定科目とコードは **Codes waiting for your answer** で、ファイルの列はファイルのマッピングで行います。エンティティを提案することはありません。

## プロジェクトを引き継ぐ

**セットアップ** チェックリストには、**階層を確認** の後に4つの最終項目があります。

- **Set up the nightly refresh**：**夜間に更新** をオンにすると完了します。
- **チームと共有**：プロジェクトをセットアップしたユーザー以外のメンバーが1人でもいると完了します。
- **Download the evidence pack**：最後に成功したロードの後にパックをダウンロードすると完了します。
- **Hand the project over to its owner**：セットアップしたユーザー以外のアーキテクトが存在し、合計が一致すると完了します。完了していない間は、チェックリストに対処方法が示されます：クライアントの担当者をこのプロジェクトのアーキテクトにし、その後、自分自身をメンバーから削除します。

チェックリストには、プロジェクトをセットアップしたユーザーが **Set up by** として表示されます。

## テンプレートでモデルを活用する

テンプレートは、Common Finance Modelの上にレポートとモデルを構築するため、どのERPが供給しても同じように機能します。**Enterprise Profitability** などのテンプレートからプロジェクトを開始すると、次のものが作成されます。

- [Common Finance Modelのテーブル](#common-finance-modelのテーブル)。空の状態、またはサンプルデータが入った状態です。
- それらのテーブルから構築された **エンティティ**、**勘定科目**、**部門**、**顧客**、**製品**、**Segment 1**、**Segment 2** のディメンション。[階層](#階層)を参照してください。
- **ロード** ワークフローと、ERPとファイルを読み取り、適合させ、準備状況をチェックし、テンプレートのモデルを構築するためにそのワークフローが実行するワークフロー。
- テンプレート独自のレポートとモデル。**Enterprise Profitability** は、収益、COGS、売上総利益、直接および間接の営業費用、貢献利益、営業利益率を含む損益計算書のテーブルと、前年比および予算比のマージンブリッジを追加します。
- 結果について質問するためのメトリックと分析パス。

**開始元** では3つのテンプレートを利用でき、それぞれが同じモデルの上に構築されます。

| テンプレート | 追加されるもの |
|---|---|
| **Enterprise Profitability** | 損益計算書とマージンブリッジ。 |
| **Cost to Serve** | 各顧客へのサービス提供コストと、それを差し引いた後のマージン。[Cost to Serve](/ja/guides/projects/cost-to-serve/)を参照してください。 |
| **Operational Transfer Pricing** | ポリシー範囲に対する各エンティティの利益水準と、真実化調整。[Operational Transfer Pricing](/ja/guides/projects/operational-transfer-pricing/)を参照してください。 |

**From a template file...** は、保存したプロジェクトから開始します。[マイテンプレートとして保存する](#マイテンプレートとして保存する)を参照してください。

ご自身のERPを接続する前に試してみるには、プロジェクトの作成時に **サンプルデータで開始** にチェックを付けます。プロジェクトは最初の「ロード」をすぐに実行するため、**Foundation** タブには、ユーロのエンティティが米ドルに換算される例を含む完全なサンプルが表示されます。ご自身のERPを接続するか、独自のファイルを追加すると、サンプルの行はクリアされ、お客様のデータに置き換わります。

## Foundationタブ

**Foundation** タブは、データの接続、ロード、チェックを行う場所です。上から順に、次のセクションがあります。

| セクション | 表示内容 |
|---|---|
| **前回のロード** | 前回のロードが成功したか、失敗したか、まだ実行中か。**ロード**、**Apply changes**、**更新**、**夜間に更新** の各ボタンがあります。 |
| **What to do next** | 対応が必要なものを重要度順に表示します。それぞれに **確認** または **Choose which source counts from when** ボタンがあります。 |
| **ソース** | 各ソースが順番に表示されます。**高度**、**Remove this source**、**グループ**、**Rename extra categories** があります。 |
| **セットアップ** | セットアップチェックリスト：**データを接続**、**データをロード**、**合計が一致することを確認**、**階層を確認**、**Set up the nightly refresh**、**チームと共有**、**Download the evidence pack**、**Hand the project over to its owner**。現在の項目は太字です。 |
| **Business names** | カテゴリー、P&Lライン、メトリック、列についてビジネスで使用している名前。[ビジネス名](#ビジネス名)を参照してください。 |
| **ファイル** | 追加した各ファイル、そのデータセット（**総勘定元帳** や **為替レート** など）、およびそのマッピングが **✓ 確認済み** か **○ 確認待ち** か。 |
| **ロード済みデータ** | エンティティごとに、ロードされた最初と最後の期間、および準備ができている期間の数。 |
| **期間** | 各エンティティの会計期間と、それぞれが **✓ クローズ済み** か **○ 未締め** か。 |
| **準備状況** | 準備状況グリッド：エンティティ、期間、チェックごとに1行で、そのステータスと **対応**。 |
| 接続 | ERPを接続し、エンティティとロードする履歴の月数を選択するか、別のソースを追加します。 |
| **ファイル**（追加） | CSV、TSV、TXT、Excel、Parquetファイルを追加し、列のマッピングを確定します。 |
| **ロード** | ロードを開始します。**Apply changes** は、ERPから取得せずにロードを実行します。 |

ロードの実行中は、タブが自動的に更新されます。

セットアップチェックリストで進捗を確認できます。

- **データを接続** と **データをロード** は、ソースが接続され、ロードが成功すると自動的にチェックが付きます。
- **合計が一致することを確認** は、一致チェックに合格するとチェックが付きます。
- **階層を確認**：**ディメンションを開く** をクリックしてエンティティ、勘定科目、部門の階層を確認し、**確認しました** にチェックを付けます。これはご自身で確認してください。
- **Set up the nightly refresh**、**チームと共有**、**Download the evidence pack**、**Hand the project over to its owner** でリストが完了します。[プロジェクトを引き継ぐ](#プロジェクトを引き継ぐ)と[プロジェクトアクセスの管理](/ja/guides/projects/managing-projects/#プロジェクトのアクセスの管理)を参照してください。

**アクション** メニューには、**配賦...**、**Board pack...**、**複製...**、**復元...**、**Save as my template...** があります。[配賦ルール](#配賦ルール)、[取締役会資料](#取締役会資料)、[プロジェクトを複製する](#プロジェクトを複製する)、[復元ポイント](#復元ポイント)、[マイテンプレートとして保存する](#マイテンプレートとして保存する)を参照してください。

## Common Finance Modelのテーブル

Data Foundationは、ERPかファイルかを問わず、すべてのソースを同じ15のテーブルに適合させるため、それらの上に構築されたレポート、メトリック、モデルは、どのソースでも同じように機能します。各行には、ソースシステムと読み取られた日時も記録されます。**データセット** 列は、ファイルを追加するときに選択する名前です。

| データセット | テーブル | 内容 |
|---|---|---|
| エンティティ | `cfm_entity` | 親、現地通貨とグループ通貨、国を持つ法人。 |
| エンティティ対応表 | `cfm_entity_map` | ソースのエンティティコードと、それぞれが属するエンティティ。[エンティティ対応表](#エンティティ対応表)を参照してください。 |
| 為替レート | `cfm_fx_rate` | 通貨ペアごとの月次の平均レート、期末レート、履歴レート。[為替レート](#為替レート)を参照してください。 |
| 会計カレンダー | `cfm_fiscal_calendar` | エンティティの会計期間ごとに1行で、開始日と終了日、および締め済みかどうか。 |
| 勘定科目表 | `cfm_account` | 親、タイプ（`Revenue`、`COGS`、`Opex`、`NonOperating`、`Asset`、`Liability`、`Equity`）、財務諸表、正常残高、レートタイプを持つ勘定科目。 |
| 部門 | `cfm_department` | 親とプロフィットセンターを持つ部門とコストセンター。 |
| 製品 | `cfm_product` | 親、ファミリー、グループ、単位、標準原価を持つ製品マスター。 |
| 顧客 | `cfm_customer` | 親、グループ、リージョン、国を持つ顧客マスター。顧客名はマスクされません。 |
| セグメント値 | `cfm_segment` | 名前と親を持つセグメント値。[階層](#階層)を参照してください。 |
| 総勘定元帳 | `cfm_gl_journal` | 取引通貨、現地通貨、報告通貨の仕訳明細。 |
| 試算表 | `cfm_trial_balance` | エンティティ、勘定科目、部門ごとの期間の借方、貸方、純額。現地通貨と報告通貨です。 |
| 売上明細 | `cfm_sales_line` | 数量、総額、値引き、純額、COGSの金額を持つ請求済み売上明細。 |
| 在庫残高 | `cfm_inventory_balance` | 製品と倉庫ごとの期末在庫。 |
| 予算 | `cfm_budget` | シナリオ、バージョン、勘定科目、部門ごとの予算と予測。 |
| 配賦ドライバー | `cfm_stat_driver` | 人数、面積、数量などの統計ドライバー。 |

期間は `YYYY-MM` の形式で記述し、取引は転記期間によって割り当てられます。予算は任意です。予算のないERPでも、それ以外のすべてがロードされます。

試算表ファイルには、借方と貸方の列、純額の列、またはその両方を含められます。借方と貸方のみの場合、純額は借方から貸方を引いたもので、空欄の側はゼロとして扱われます。純額のみの場合、正の純額は借方に、負の純額は貸方になり、正の金額として扱われます。部門の列は任意です。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| **接続をテスト** で、ERPが認証情報を拒否したと表示される | 接続の認証情報と、連携用ユーザーがERPにサインインできることを確認してください。 |
| **接続をテスト** で、データセットに **権限が不足しています** と表示される | 表示された権限を追加するようERP管理者に依頼してください。ERPの[接続ガイド](/ja/guides/connections/)に、接続に必要なものが記載されています。 |
| ERPのエラーメッセージが、ERP自身のものより短い | PlaidCloudは、プロバイダーのエラーを表示する前に認証情報、トークン、キーを削除するため、一部の詳細が省略されます。**接続をテスト** を実行して、どのデータセットが影響を受けているかを確認してください。 |
| 期間の **ロード済みデータ** が問題になっている | その期間のERP読み取りが失敗しました。**ロード** を再度実行してください。ロード済みの期間はスキップされます。 |
| **勘定科目表にない勘定科目** が問題になっている | ERPまたはファイルの勘定科目表に、不足している勘定科目を追加し、**ロード** を再度実行してください。 |
| **通貨換算** が問題になっている | エンティティの通貨に、その期間の報告通貨へのレートがないか、単一の報告通貨が見つかりませんでした。**為替レート** ファイルにレートを追加するか、接続がERPの為替レートを読み取れることを確認するか、プロジェクト変数 `reporting_currency` を設定してください。その後、**ロード** を再度実行してください。 |
| **通貨換算** が要対応になっている | 貸借対照表、在庫、予算の行に、その期間の期末レート、履歴レート、計画レートがありません。損益計算書には影響しません。予算月の計画レートを含むレートを追加し、**ロード** を再度実行してください。 |
| **Codes waiting for your answer** が要対応になっている | **確認** をクリックし、各コードに回答して、**Apply changes** をクリックしてください。 |
| **Which source covers which months** が要対応になっている | **Choose which source counts from when** をクリックし、ソースを選択して、**Apply changes** をクリックしてください。 |
| **Intercompany balances** が赤または黄色になっている | **Intercompany pairs** のペアを確認してください。不足している側を計上するか、明細に取引相手を追加するか、不足しているレートを追加してください。 |
| **Group views are off** | **グループ** の下の **Everyone on the project may see the group results** にチェックを付けるよう、アーキテクトに依頼してください。 |
| **未マッピングのエンティティ** が問題になっている | エンティティをエンティティマスターに追加するか、**エンティティ対応表** ファイルでそのコードを既存のエンティティにマッピングして、**ロード** を再度実行してください。 |
