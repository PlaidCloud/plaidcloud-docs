PlaidCloud では、ラベルを含めてテーブルを整理して管理できます。テーブルはプロジェクト内のすべてのワークフローで利用でき、多くのツールとオプションがあります。


テーブルに加えて、PlaidCloud にはテーブルデータに基づくビューもあります。ビューを使用すると、元のテーブルが変更されたときにすぐに更新が反映され、データストレージの容量も節約できます。



オプションは次のとおりです。


* 同じテーブルを階層内の複数のパスに存在させることができます（代替階層）
* テーブルにタグを付けることで、PlaidCloud のプロセスでの検索や組み込みが容易になります
* テーブルをバージョン管理できます
* テーブルを公開して、ダッシュボードのビジュアライゼーションで利用できるようにできます

PlaidCloud は、一連のフォルダーをたどるときのようなパスベースの仕組みでテーブルを整理するため、より柔軟で論理的にテーブルを整理できます。この仕組みでは、階層内でテーブルを移動したり、階層内の異なる場所から 1 つのテーブルへの複数の参照（代替階層）を作成したりできます。この方法でテーブルを管理できるため、運用、レポート、統制の必要に応じた構造にできます。



## テーブルを検索する


階層の左下にあるフィルターボックスを使用して、テーブル名とラベルを検索します。一致したものは上の階層に表示されます。


### ワークフロー別

**テーブル**タブの末尾にある**ワークフロー別**フォルダーは、テーブルを読み取るまたは書き込むワークフローごとにグループ化します。ワークフローを開くと、そのテーブルが表示されます。このフォルダーは同じテーブルを別の見方で表示しているだけなので、ここから何かを移動またはコピーすることはできません。


### 列別

**テーブル**タブの列検索ボックスに列名を入力して Enter キーを押すか、横の虫眼鏡を選択すると、その名前の列を持つテーブルだけが表示されます。検索で読み取るのは列名であり、データではないため、高速です。**含む**を選択すると、列名全体ではなく一部に一致させることができます。ボックスを空にすると、すべてのテーブルが再び表示されます。長い検索は複数のページに分けて返される場合があり、ステータス行には、検索がまだ続いているか、結果が不完全な可能性があることが表示されます。

**列ツリー**を選択すると、専用のウィンドウから検索できます。その列を持つ各テーブルを開くと、2 つのリストが表示されます。

* **参照元** — その列を供給するテーブル
* **参照先** — その列がさらに供給するテーブル

MCP 経由で接続された AI アシスタントは、`table_find(column=...)` で同じテーブルを検索でき、名前の全体または一部に一致させます。


### 値を検索

どのテーブルにある値が保持されているかを調べるには、**テーブル**タブの**アクション**メニューから**データ内の値を検索… (低速)**を選択します。特定のテーブルだけを検索する場合は、そのテーブルを右クリックして選択します。値を入力し、値の一部に一致させるには**含む**を選択して、**検索**を選択します。その値を保持する各テーブルが、値が現れる列と一致する値の一部とともに一覧表示されます。テーブルをダブルクリックするか、Enter キーを押すと、テーブルエクスプローラーで開きます。列を選択すると、一致する行に絞り込まれた状態でテーブルが開きます。列検索ボックスにテキストが入力されている場合は、検索する値に自動的に入力されます。

検索する前に、次の点を確認してください。

* 検索では、検索対象のすべてのテーブルのすべての行を読み取るため、非常に時間がかかり、多くのウェアハウスリソースを使用する場合があります。ウィンドウに警告が表示され、検索が完了するまで検索ボタンは無効のままです。
* 表示されるのは、すでに開くことができる行だけです。行レベルセキュリティはすべての検索に適用されます。
* 検索した値は、ウェアハウスのクエリ履歴に記録されます。
* 検索の対象は、テーブルのテキスト列です。まだビルドされていないテーブルはスキップされ、警告に名前が示されます。
* 結果はページに分けて返されます。ステータス行に検索が途中で停止したと表示された場合は、**さらに検索**を選択すると、まだ検索していないテーブルの検索を続行できます。

MCP 経由で接続された AI アシスタントは、`table_value_search` を使用します。値を保持するテーブルと列は返しますが、値そのものは返しません。プロジェクトで AI アシスタントに値の検索を依頼すると、Weave は一致したテーブルと列の名前を言語モデルプロバイダーに送信します。



## CSVファイルをインポート

**CSV ファイルをこのプロジェクトの新しいテーブルに変換するには:**

1. コンピューターからファイルをプロジェクトの**テーブル**リストにドラッグするか、ツールバーで**新規** > **CSVファイルからテーブルを作成**を選択して、ボックスにファイルをドロップするか、**CSVファイルを選択**をクリックします。
2. PlaidCloud はファイルを**個人用の一時ドライブ**にアップロードします（ない場合は、ワークスペースの**一時ドライブ**にアップロードします）。そして、リストの最上位に、ファイル名に基づいた名前の新しいテーブルとしてインポートします。たとえば、`Sales Data.csv` は `sales_data` になります。プロジェクトにすでに同じ名前のテーブルがある場合は、新しいテーブルに `sales_data_2` のように番号が付きます。
3. リストが更新されて新しいテーブルが選択され、**データの概要**がそのテーブルで開きます。パネルに表示される内容については、[独自の CSV から始める](/ja/get-started/quickstart/#自分の-csv-から始める)を参照してください。

受け付けるのは、`.csv` で終わるファイルだけです。テーブルを作成する権限とドキュメントストレージに書き込む権限が必要です。ロックされているプロジェクトは、ロックが解除されるまで CSV を受け付けません。インポートが失敗した場合は、その理由がウィンドウに表示され、プロジェクトは変更されません。PlaidCloud は、インポートが完了すると、成功したかどうかにかかわらず、アップロードされたファイルを一時ドライブから削除します。削除できなかった場合は、1 日後に一時ドライブが削除します。

## 名前を変更する


**テーブルの名前を変更するには:**


1. テーブルを右クリックします
2. 名前の変更オプションを選択します
3. 新しい名前を入力して保存します
4. テーブルの名前が変更されますが、元の一意の識別子は保持されます。

## クリア


**テーブルをクリアするには:**


1. 階層でテーブルを選択します
2. 上部のツールバーにあるクリアボタンをクリックします。

*注記: 1 つのテーブルまたは複数のテーブルをクリアできます*



## 削除


**テーブルを削除するには:**


1. 階層でテーブルを選択します
2. 上部のツールバーにある削除ボタンをクリックします
3. 削除操作では、テーブルがワークフローのステップまたはビューで使用されているかどうかが確認されます。使用されている場合は、削除する前にそれらの関連付けを解除するよう求められます。

*注記: テーブルを強制的に削除することもできます。強制削除すると参照が壊れたままになるため、使用は最小限にしてください。*


### 最後の読み取り

削除ウィンドウには、テーブルが最後に読み取られた時刻が、たとえば**3 日前に最後に読み取り**（ユーザーまたはステップ名付き）のように表示されるため、誰も使用していないテーブルと、まだ使用中のテーブルを区別できます。PlaidCloud はこの情報をウェアハウス自身のクエリ履歴から取得し、PlaidCloud 自身のハウスキーピングによる読み取りは除外します。

| ウェアハウス | 必要なもの |
| --- | --- |
| Snowflake | 読み取りは Access History から取得されます。Snowflake は最大で約 3 時間遅れて記録します。接続のロールには `SNOWFLAKE.GOVERNANCE_VIEWER` データベースロールが必要です（`SNOWFLAKE` データベースに対する `IMPORTED PRIVILEGES` でも動作します）。Snowflake の Standard エディションには Access History がありません。 |
| Databricks | 読み取りはリネージテーブルから取得されます。Databricks はこれも遅れて記録するため、最近の読み取りはまだ表示されないことがあります。接続の ID には、`system` に対する `USE CATALOG`、`system.access` に対する `USE SCHEMA`、`system.access.table_lineage` に対する `SELECT` が必要です。 |
| PlaidCloud Lakehouse | 読み取り履歴はまだ利用できません。ウィンドウには**読み取り履歴が不完全です**と表示されます。 |

ウェアハウスを接続すると、[接続チェック](/ja/guides/connections/external-lakehouse/#3-確認して使用する)が、不足しているこれらの権限を、実行するステートメントとともに推奨します。これらは推奨であり必須ではありません。なくてもウェアハウスには接続でき、ウィンドウには**読み取り履歴が不完全です**と表示されます。

PlaidCloud が履歴全体を読み取れない場合、その行には**読み取り履歴が不完全です**と表示され、代わりに「読み取りなし」と報告されることはありません。ウェアハウスに直接 SQL でアクセスできるユーザーは、自分の読み取りの分類方法を変更するセッションタグを設定できます。

MCP 経由で接続された AI アシスタントは、`table_describe(include=['last_read'])` で同じ回答を取得できます。



## テーブルの列を表示する


テーブルを選択すると、詳細パネルが開きます。**列**セクションには、各列が**タイプ**と**説明**とともに一覧表示されます。説明は**列のプロパティ**から取得されます。行にポインターを合わせると、長い説明を全文で読めます。

データの期限切れやどのステップもビルドしていないことが原因で、現在ウェアハウスにないテーブルには、一覧表示できる列がありません。セクションにその旨と、テーブルが持つ列の数が表示されます。列を一覧表示するには、そのテーブルに書き込むステップを実行してください。


## テーブルの使用場所を確認する


テーブルを選択すると詳細パネルが開き、そのテーブルを扱うワークフローのステップが一覧表示されます。


* **テーブルの作成元** — テーブルに書き込むステップ
* **テーブルの出力先** — テーブルから読み取るステップ
* **このテーブルを参照する可能性あり** — 解決できない変数を通じてテーブルに到達するステップ。このセクションは、そのようなステップがある場合にのみ表示されます。


ステップは、テーブルを直接指定する場合もあれば、`/Periods/{period}/Sales` のように変数を含むパスを通じて到達する場合もあります。その変数に現在の値がある場合、ステップは最初の 2 つのリストに、横に情報アイコンが付いた状態で表示されます。行にポインターを合わせると、ステップが保存しているとおりのパスが表示されます。


これらの行は、確度の低い回答として扱ってください。これらが示すのは、今から実行を開始した場合に扱われる内容であり、そのテーブルを過去に扱ったすべてではありません。変数を変更すると、別のテーブルが読み取られます。


解決できない変数もあります。変数がまったく設定されていない場合や、実行で使用される値が保存されている内容に由来しない場合です。Workflow Loop ステップは反復処理中にデータから変数を取得し、Set Variable ステップは実行中に変数を割り当て、マクロは呼び出すステップから変数が渡され、センサーによって開始された実行はそのセンサー自身の詳細を持ちます。いずれの場合も、実行の間に保存されている内容は前回の実行の名残であり、信頼できる値ではありません。そのため PlaidCloud は、誤ったテーブルになりかねない解決をせずに、**このテーブルを参照する可能性あり**の下に、解決できなかった変数とともにステップ名を一覧表示します。開いて確認してください。


ロールで表示できないステップも一覧に表示されるため、テーブルが使用中であることはわかりますが、名前やワークフローは表示されず、開くこともできません。そのステップも、テーブルを削除するときには数えられます。表示できるステップは、ロールによって非表示になっているワークフローを除いて一覧表示されます。アーキテクトには、何も非表示になりません。


*注記: **テーブル**リストからテーブルを削除する場合、変数の有無にかかわらず、パスを通じてテーブルに到達するステップは、変数を解決できない場合でも、そのテーブルを使用しているものとして数えられます。削除ウィンドウにそのステップが一覧表示され、強制した場合にのみ削除が実行されます。*

## データを表示する（テーブルエクスプローラー）


テーブルのデータは、データエクスプローラーで表示します。データエクスプローラーには、データのグリッド表示と、列ごとの値と統計の概要が用意されています。ポイントアンドクリックによるフィルター処理と、一般的なファイル形式へのエクスポートも利用できます。フィルターの選択内容は、ワークフローで使用できる Extract ステップとして保存することもできます。



## レポート用にテーブルを公開する


ダッシュボードのビジュアライゼーションは、意図的に、公開されたテーブルに限定されています。テーブルを公開するときに、データを区別しやすい一意の名前を付けることができます。これは、テーブルを生成したワークフローの一部では分かりにくい名前になっているが、ダッシュボードを作成するユーザーにはより明確な名前が必要な場合に便利です。


公開されたテーブルにはパスが関連付けられません。ダッシュボード領域で使用するテーブルのリストとして表示されます。



## ロール別にテーブルの表示を設定する


各ロールによるテーブルの表示は、エクスプローラーまたはマネージャーのチェックボックスをクリックして制御できます。複数のテーブルを更新する必要がある場合は、階層でテーブルを選択し、上部のツールバーの**アクション**メニューから目的の表示ロールを選択します。



## テーブルの内容を説明するメモ


テーブルにメモを追加すると、データを理解しやすくなります。



## テーブルの形状、サイズ、最終更新日時を確認する


各テーブルの行数、列数、データサイズは、テーブル階層に表示されます。非常に大きなテーブル（数百万行以上）の場合、行数は推定値になることがあり、その場合はおおよその行数であることを示すインジケーターが表示されます。

## テーブルから Panelアプリを作成する


テーブルまたはビューを選択し、**新規**メニューまたは右クリックメニューから **Panel アプリを作成**を選択します。プロジェクトとテーブルがあらかじめ選択された状態で、**新しい Studio アプリ**ダイアログが開きます。アプリにはテーブルの名前が付けられます。必要に応じて変更し、**作成**を選択すると、Panel Studio でアプリが開き、Weave が最初のページを作成する準備ができた状態になります。このコマンドは、1 つのテーブルまたはビューを選択していて、プロジェクトに対する編集アクセスがあり、プロジェクトが読み取り専用でない場合に使用できます。[Panelアプリの作成](/ja/guides/panel-apps/creating/#テーブルから開始する)を参照してください。


## テーブルが保存する量を確認する


**テーブル**リストには、各テーブルのサイズの横に、**現在のデータ**、**履歴**、**タイムトラベル日数**、**注記**の列が表示されます。**タイムトラベル日数**はテーブル自体の設定で、**1** はプロジェクトのデフォルトを使用していることを意味します。リストの下のステータスバーには、プロジェクトの合計が表示されます。保存量と、そのうち現在のデータと履歴がそれぞれどれだけかが示されます。**推定**と表示されたサイズは、PlaidCloud が測定するまで、テーブルの形状から推定された値です。

ツールバーの**ストレージ**を選択すると、容量を解放するための提案とタイムトラベルの設定を含む、プロジェクトの**ストレージ**ウィンドウが開きます。[ストレージの管理](/ja/guides/projects/managing-storage/#プロジェクトのストレージウィンドウ)を参照してください。


## テーブルからデータエディターを作成する


テーブルを選択し、**新規**メニューまたは右クリックメニューから**テーブルからデータエディターを作成**を選択すると、テーブルを設定済みのデータエディターに 1 ステップで変換できます。PlaidCloud はテーブルの列を調べ、エディターの入力コントロールをあらかじめ構築します。詳細については、[テーブルからデータエディターを作成する](/ja/guides/projects/managing-data-editors/#テーブルからデータエディターを作成する)を参照してください。
