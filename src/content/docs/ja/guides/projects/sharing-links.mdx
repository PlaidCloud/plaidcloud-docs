PlaidCloud は、開いているものに合わせてアドレスバーを同期します。ワークフロー、テーブル、ディメンション、またはダッシュボード、ドキュメント、IDの画面を開くと、URL がそれへの**ディープリンク**になります。その URL をコピーしてメッセージやチケットに貼り付ければ、それを開いた人は同じ画面に移動します。

## リンクのコピー

1. 共有したい画面（プロジェクト、ワークフロー、テーブル、ディメンション、データエディター、またはその他のアプリの画面）を開きます。
2. ブラウザーのアドレスバーから URL 全体をコピーします。
3. 送信します。

独立した「共有」ボタンはありません。アドレスバーそのものがリンクです。ブラウザーのブックマーク機能もこれらの URL で使用できるため、よく戻る画面は、他の Web ページと同様にブックマークできます。

<Aside type="note">
リンクが伝えるのは*場所*だけで、それを表示する権限は含まれません。リンクを開く人には、引き続きプロジェクトへのアクセス権が必要です。アクセス権のない人にはオブジェクトが表示されません。

ワークスペースにそのアプリが含まれていない、またはアクセス権が付与されていないなどの理由で、持っていないアプリへのリンクを開いた場合は、何も起こらないように見えるのではなく、リンクが利用できなかったという注記とともにホームに移動します。
</Aside>

## リンクできるもの

### Analyze

| 画面 | リンクの末尾 |
|---|---|
| プロジェクト | `#p~<project>` |
| ワークフロー（ステップグリッド） | `#p~<project>~w~<workflow>` |
| ワークフロー（ビジュアルワークフローデザイナーのキャンバス） | `#p~<project>~c~<workflow>` |
| ワークフロー内のステップ | `…~w~<workflow>~s~<step>` または `…~c~<workflow>~s~<step>` |
| 単独のステップ | `#p~<project>~s~<step>` |
| テーブルエクスプローラー | `#p~<project>~t~<table>` |
| ディメンション階層 | `#p~<project>~d~<dimension>` |
| データエディター | `#p~<project>~e~<editor>` |
| ホーム | `#home` |

リンクのプロジェクト部分は、プロジェクトにカスタムの**スキーマ**がある場合はそのスキーマになるため、リンクは16進数の文字列ではなく `#p~acme_budget~w~…` のように読めます。デフォルトのスキーマのままのプロジェクトでは、代わりにプロジェクト自体の識別子が使用されます。どちらの形式も同じプロジェクトを開くため、スキーマを設定した後も古いリンクは引き続き機能します。

### ダッシュボード、ドキュメント、ID

他のアプリの画面は直接名前が付けられているため、そのリンクは画面そのものを表します。

| アプリ | 画面 | リンク |
|---|---|---|
| ダッシュボード | ダッシュボード | `#dashboard.dashboards` |
| ダッシュボード | アプリ | `#dashboard.panel_apps` |
| ダッシュボード | ノートブック | `#dashboard.jupyterlite_deployments` |
| ドキュメント | 管理 | `#document.accounts` |
| ドキュメント | 自分のアカウント | `#document.your_accounts` |
| ドキュメント | 1つのアカウントのファイルの参照 | `#document.browser~…` |
| ID | メンバー | `#identity.members` |
| ID | ディレクトリ | `#identity.member_directory` |
| ID | 配布リスト | `#identity.distro.lists` |
| ID | セキュリティグループ | `#identity.security_groups` |
| ID | グループ監査 | `#identity.security_group_audit` |
| ID | すべてのスコープ | `#identity.scopes` |
| ID | セッション | `#identity.sessions` |
| ID | APIクライアント | `#identity.api_client_list` |
| ID | セキュリティログ | `#identity.security_log` |

一部の画面は、設定をリンクに記憶します。メンバーとメンバーディレクトリの一覧は、それぞれ**すべて**、**アクティブのみ**、**非アクティブのみ**のどれを表示していたかを保持し、アカウントの参照ではどのアカウントかを保持します。これらは、ブラウザーでは画面名の後ろにエンコードされた接尾辞として表示されます。URL 全体をコピーして貼り付けると、表示していた画面が開きます。その画面がすでに開いている場合に開くと、2つ目のウィンドウを重ねるのではなく、そのウィンドウが前面に表示されます。

<Aside type="note">
これらのリンクが指すのは画面であり、画面内のレコードではありません。メンバーへのリンクはメンバーの一覧を開きます。1人のメンバーのフォームは開きません。
</Aside>

## 誰かがリンクを開いたときの動作

- **所有しているプロジェクトも開きます**。ワークフロー、テーブル、ステップ、ディメンション、データエディターへのリンクは、そのプロジェクトも画面下部のタブとして開くため、受信者は単独のウィンドウが浮いている状態ではなく、周囲のコンテキストとともに表示されます。
- **ステップのリンクはステップを選択します**。ワークフロー内のステップへのリンクは、ワークフローを開いてそのステップを強調表示します。ビジュアルワークフローデザイナーのキャンバスでは、ステップのノードが選択されます。
- **ディメンションは、プロジェクトのロックが解除されている場合は編集可能な状態で開き**、ロックされている場合は読み取り専用で開きます。これは、プロジェクトから開く場合と同じルールです。
- **更新しても同じ場所にとどまります**。ページを再読み込みすると、最初に戻るのではなく、リンクが指すものが再び開きます。

## 画面間の移動

URL は、表示しているものに追従します。

- 画面を開くとアドレスバーが更新され、ブラウザーの**戻る**ボタンで前の画面に戻れます。
- **どのような経路でも同じです**。アクティビティストリーム、ホームのカード、**ワークフローにドリルダウン**アクション、「使用箇所」の一覧、またはログからワークフローを開いた場合でも、プロジェクトのワークフロー一覧から開いた場合と同様にリンクが更新されます。すでに開いている画面を開き直した場合も同様です。
- 画面下部にあるウィンドウのタブを選択すると、そのウィンドウのリンクがアドレスバーに戻るため、開いている画面を切り替えても URL は正確に保たれます。
- リンク可能なものが何も開いていないアプリに切り替えると、離れたばかりのアプリを指したままにするのではなく、リンクが**クリア**されます。
- ウィンドウを閉じると、URL は開いた元の場所に戻ります。ワークフローのキャンバスから開いたテーブルを閉じると、URL はそのキャンバスに戻り、プロジェクトから開いたテーブルを閉じると、プロジェクトに戻ります。
- プロジェクトの最後のウィンドウを閉じると、リンクがクリアされます。

## この変更前に保存されたリンク

古い `#te?p=…&t=…` 形式のリンクも引き続き機能します。それを開くと同じ場所に移動し、アドレスバーが現在の形式に自動的に書き換えられるため、そこから再度コピーすると、より新しく読みやすいリンクが得られます。
