**ストレージ**ウィンドウには、ワークスペースの保存量、プランに対するコスト、どのプロジェクトとテーブルが容量を使用しているかが表示されます。各プロジェクトには**ストレージ**タブもあり、各テーブルが履歴を保持する期間を設定できます。

## ストレージウィンドウを開く

**プロジェクト**画面のストレージバーには、ワークスペースの保存量が表示されます。**ストレージの詳細…** をクリックすると**ストレージ**ウィンドウが開きます。**更新**をクリックすると再読み込みされます。

## メーターの見方

**今月のストレージ**には、3 つの帯を持つメーターが表示されます。

| 帯 | 意味 |
|---|---|
| **含まれる** | プランに含まれるストレージです。 |
| **予約** | 組織があらかじめ予約しているストレージです。 |
| **オンデマンド** | 含まれる分と予約分を超えたストレージです。 |

メーターの下には、次のカードが表示されます。

- **現在の保存量** — ワークスペースが現在保存している量です。
- **予測平均** — 今月ここまでの平均で、最新の日の値が月末まで続くものとして計算します。請求にはこの値が使われ、**現在の保存量**は使われません。一時的に保存量が大幅に増えた日が請求額を決めることはありません。
- **含まれる**、**予約でカバー**、**オンデマンド** — 予測平均が各帯にどのように分配されるかを示します。

**過去90日間**には、ワークスペースの日次ストレージがグラフで表示されます。

ワークスペース管理者には、オンデマンド帯のコストなどの推定金額も表示され、ストレージを追加で予約すると節約できる場合は提案も表示されます。そのほかのメンバーにはサイズのみが表示されます。金額は推定値であり、請求書ではありません。

### データを削除するとどうなりますか？

ワークスペース管理者は、**データを削除するとどうなりますか？** に量を入力すると、今月の平均がどれだけ下がり、おおよそいくら節約できるかを確認できます。クリーンアップは毎晩実行されるため、この推定は数日後に容量が解放されるものとして計算されます。

## プロジェクト別のストレージ

ストレージウィンドウの**プロジェクト**一覧では、各プロジェクトのサイズが次のように分けて表示されます。

- **現在（GB）** — 現在テーブルにあるデータです。
- **履歴 (GB)** — タイムトラベルと復元のために保持されている以前のバージョンです。
- **合計 (GB)** — 上記 2 つの合計です。
- **30-day (%)** — 過去 30 日間にプロジェクトのストレージがどれだけ変化したかを示します。

請求対象のストレージの一部はどのプロジェクトにも属さないため、**請求されるオーバーヘッド**と表示された独立した行に表示されます。

- **バックアップ**
- **ファイルとドキュメント**
- **コンテナイメージ**
- **ワークフローの作業領域とコピー**
- **メタデータ、クリーンアップ、未測定**

**その他のプロジェクト**には、開くことができないプロジェクトの合計が表示されます。

**プロジェクト**画面の**サイズ**列には各プロジェクトのストレージが表示され、フォルダーにはその中のプロジェクトの合計が表示されます。

## プロジェクトのストレージタブ

プロジェクトを開き、その**ストレージ**タブをクリックします。プロジェクトの保存量が現在のデータと履歴に分けて表示され、テーブルの一覧が表示されます。

| 列 | 意味 |
|---|---|
| **テーブル** | テーブルの名前です。 |
| **現在のデータ** | テーブルが現在保持しているデータです。 |
| **履歴** | 復元できるように保持されている以前のバージョンです。 |
| **行数** | テーブルの行数です。 |
| **最終更新** | テーブルに最後に書き込まれた日時です。 |
| **タイムトラベル** | **3日**や**継承 (1日)** などのテーブルの設定と、復元できる最も古い時点です。 |
| **注記** | **推定**、**未計測**、**クリーンアップ中**のいずれかです。 |

一覧の下の**Suggestions**では、最も簡単に節約できる方法が示されます。90 日以上変更されていないテーブル、ごみ箱に入っているプロジェクトのテーブル、履歴がデータより大きいテーブルなどです。それぞれにボタンがあります。**テーブルを開く**、**削除…**、**タイムトラベル…** です。

## 履歴とタイムトラベル

テーブルへの書き込みのたびに、テーブルの以前のバージョンが保持されます。その古いデータが**履歴**です。**タイムトラベル**は、テーブルが履歴を保持する期間であり、どこまで遡って表示や[テーブルの復元](/ja/guides/data/table-snapshots/)ができるかを決めます。

新しいプロジェクトでは、デフォルトで 1 日分の履歴が保持されます。この設定は 2 つのレベルで制御できます。

- **プロジェクトのデフォルト。** プロジェクトの設定にある**デフォルトのタイムトラベル保持期間（日数）** は、1 から 90 までの数値です。独自の設定を持たないすべてのテーブルに適用されます。
- **テーブル。** テーブルの設定にある**タイムトラベル**は、**継承**（プロジェクトのデフォルトを使用）か、2、3、5、7、14、30、60、90 日のいずれかです。

テーブル独自の設定は、プロジェクトのデフォルトより長い場合にのみ有効になります。つまり、テーブルはプロジェクトのデフォルトを延ばすことはできますが、短くすることはできません。1 つのテーブルの履歴を少なくするには、プロジェクトのデフォルトを下げてください。

変更は次回の夜間クリーンアップで反映されます。設定を上げると、それ以降の履歴が保持されます。すでに期限切れになった履歴は元に戻せません。設定を上げると、テーブルの設定ウィンドウにもその旨が表示されます。

<Aside type="caution">プロジェクトまたはテーブルが保持する履歴を以前より短くすると、次回の夜間クリーンアップで新しい設定より古い履歴が削除されます。削除された履歴は復元できません。より長く保持するには、そのクリーンアップが実行される前に設定を上げてください。</Aside>

テーブルの復元可能な範囲は、保持される日数であり、設定ウィンドウには復元できる最も古い時点が表示されます。特定の時点への復元は、その最も古い復元可能な時点まで遡って行えます。

タイムトラベル期間が終了した後も、削除されたデータは PlaidCloud サポートがさらに 7 日間復旧できます。このデータはストレージの使用量には含まれません。

## ストレージの削減

- **不要なデータを削除するか、ごみ箱に移動します。** **Suggestions** の**削除…** を使うか、使わなくなったテーブルやプロジェクトを削除します。
- **プロジェクトのデフォルトのタイムトラベルを下げます。** **継承**に設定されたテーブルが保持する履歴が少なくなります。
- **テーブル独自のタイムトラベルを短くします。** 以前に延ばしたテーブルが対象です。
- 各プロジェクトの**ストレージ**タブで**Suggestions** を確認します。

容量は、夜間クリーンアップが実行されるにつれて、数日かけて徐々に解放されます。

## 推定サイズと取得できない合計

- **推定**は、PlaidCloud がまだそのテーブルまたはプロジェクトを測定していないことを意味します。夜間の測定が実行されるまで、サイズはテーブルの形状から推定されます。
- **Snowflake と Databricks のプロジェクト**は、データを自分のアカウントに保持します。推定サイズが表示され、PlaidCloud のストレージには算入されません。
- **ワークスペースの合計を取得できません**は、ワークスペースの合計を今は読み取れなかったことを意味します。プロジェクトのサイズは推定値として表示されます。**更新**をクリックして再試行してください。
- **You don't have access to storage usage** と表示された場合は、ワークスペース管理者にプロジェクトへの読み取りアクセスを依頼してください。
