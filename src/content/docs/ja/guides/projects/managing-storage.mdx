**ストレージ**ウィンドウでは、ワークスペースが保存しているデータ量、プランに対するコスト、そしてどのプロジェクトやテーブルが容量を使用しているかを確認できます。各プロジェクトにも**ストレージ**タブがあり、各テーブルが履歴を保持する期間を設定できます。

## ストレージウィンドウを開く

**プロジェクト**画面のストレージバーには、ワークスペースの保存量が表示されます。**ストレージの詳細…** ボタンをクリックすると**ストレージ**ウィンドウが開きます。**更新**をクリックすると再読み込みされます。

## メーターの見方

**今月のストレージ**には、3つの帯で構成されるメーターが表示されます。

| 帯 | 意味 |
|---|---|
| **含まれる** | プランに含まれるストレージです。 |
| **予約** | 組織があらかじめ予約したストレージです。 |
| **オンデマンド** | 含まれる分と予約分を超えるストレージです。 |

メーターの下には、次のカードが表示されます。

- **現在の保存量** — ワークスペースが現在保存しているデータ量です。
- **予測平均** — 当月のこれまでの平均で、最新の日の値が月末まで続くものとして計算します。請求に使われるのは**現在の保存量**ではなく、この値です。一時的に保存量が大きく増えた日があっても、請求額が決まるわけではありません。
- **含まれる**、**予約でカバー**、**オンデマンド** — 予測平均が各帯にどのように配分されるかを示します。

**過去90日間**には、ワークスペースの日別ストレージがグラフで表示されます。

ワークスペース管理者には、オンデマンド分のコストなどの推定金額も表示されます。ストレージを追加で予約すると節約できる場合は、その提案も表示されます。その他のメンバーにはサイズのみが表示されます。金額は推定値であり、請求書ではありません。

### データを削除するとどうなりますか？

ワークスペース管理者は、**データを削除するとどうなりますか？** フィールドに容量を入力すると、今月の平均がどれだけ下がり、おおよそいくら節約できるかを確認できます。クリーンアップは毎晩実行されるため、この推定では、容量が数日後に解放されるものとして計算します。

## プロジェクト別のストレージ

ストレージウィンドウの**プロジェクト**リストでは、各プロジェクトのサイズが次のように分けて表示されます。

- **現在（GB）** — 現在テーブルにあるデータです。
- **履歴 (GB)** — タイムトラベルと復元のために保持されている過去のバージョンです。
- **合計 (GB)** — 上記2つの合計です。
- **30日間 (%)** — 過去30日間にプロジェクトのストレージがどれだけ変化したかを示します。

請求対象のストレージの一部はどのプロジェクトにも属さないため、**請求されるオーバーヘッド**と表示された別の行に表示されます。

- **バックアップ**
- **ファイルとドキュメント**
- **コンテナイメージ**
- **ワークフローの作業領域とコピー**
- **クリーンアップ待ちの削除済みテーブル** — 削除したテーブルのうち、解放されるまで保持されているストレージです。クリーンアップが完了するまで合計に含まれ、完了すると除外されます。
- **メタデータ、クリーンアップ、未測定**

**その他のプロジェクト**は、開くことができないプロジェクトの合計です。

**プロジェクト**画面の**サイズ**列には各プロジェクトのストレージが表示され、フォルダーにはその中のプロジェクトの合計が表示されます。

## プロジェクトのストレージタブ

プロジェクトを開いて**ストレージ**タブをクリックします。プロジェクトの保存量が現在のデータと履歴に分けて表示され、テーブルの一覧も表示されます。

| 列 | 意味 |
|---|---|
| **テーブル** | テーブルの名前です。 |
| **現在のデータ** | テーブルが現在保持しているデータです。 |
| **履歴** | 復元できるように保持されている過去のバージョンです。 |
| **行数** | テーブルの行数です。 |
| **最終更新** | テーブルが最後に書き込まれた日時です。 |
| **タイムトラベル** | **3日間**や**継承 (1日)** などのテーブルの設定と、復元できる最も古い時点です。 |
| **注記** | **推定**、**未計測**、**クリーンアップ中**のいずれかです。 |

一覧の下にある**提案**では、最も簡単に容量を節約できる対象が示されます。90日以上変更されていないテーブル、ごみ箱にあるプロジェクトのテーブル、履歴がデータより大きいテーブルなどです。各提案にはボタンがあり、**テーブルを開く**、**削除…**、**タイムトラベル…** のいずれかです。

## 履歴とタイムトラベル

テーブルへの書き込みのたびに、テーブルの以前のバージョンが保持されます。この古いデータが**履歴**です。**タイムトラベル**はその履歴を保持する期間のことで、テーブルをどこまで過去にさかのぼって表示または[復元](/ja/guides/data/table-snapshots/)できるかを決めます。

新しいプロジェクトでは、デフォルトで1日分の履歴が保持されます。設定は2つのレベルで管理できます。

- **プロジェクトのデフォルト。** プロジェクトの設定にある**デフォルトのタイムトラベル保持期間（日数）** は、1～90の数値です。独自の設定を持たないすべてのテーブルに適用されます。
- **テーブル。** テーブルの設定にある**タイムトラベル**は、**継承**（プロジェクトのデフォルトを使用）か、2、3、5、7、14、30、60、90日のいずれかです。

テーブル独自の設定が有効になるのは、プロジェクトのデフォルトより長い場合だけです。そのため、テーブルはプロジェクトのデフォルトを延長できますが、短縮することはできません。1つのテーブルの履歴を短くしたい場合は、プロジェクトのデフォルトを短くしてください。

変更は、次回の夜間クリーンアップで反映されます。設定を長くすると、その時点以降の履歴が保持されます。すでに期限切れになった履歴を復活させることはできません。設定を長くするときは、テーブルの設定ウィンドウにもその旨が表示されます。

<Aside type="caution">プロジェクトまたはテーブルの履歴保持期間を以前より短くすると、次回の夜間クリーンアップで、新しい設定より古い履歴が削除されます。削除された履歴は復元できません。より長く保持したい場合は、そのクリーンアップが実行される前に設定を長くしてください。</Aside>

テーブルの復元可能な範囲は保持する日数で決まり、テーブルの設定ウィンドウには復元できる最も古い時点が表示されます。特定の時点への復元は、その最も古い復元可能な時点までさかのぼって行えます。

タイムトラベル期間が終了した後も、削除されたデータは、さらに7日間、PlaidCloudサポートが復旧できます。このデータはストレージの使用量には含まれません。

## ストレージを削減する

- **不要なデータを削除またはごみ箱に移動する。** 提案の**削除…** ボタンを使用するか、使用しなくなったテーブルやプロジェクトを削除します。
- **プロジェクトのデフォルトのタイムトラベルを短くする。** **継承**に設定されているテーブルが保持する履歴が短くなります。
- **テーブル独自のタイムトラベルを短くする。** 以前に延長したテーブルが対象です。
- **提案を確認する。** 各プロジェクトの**ストレージ**タブで確認できます。

容量は、夜間クリーンアップが実行されるにつれて、今後数日かけて徐々に解放されます。

## サイズの測定方法

プロジェクトとテーブルのサイズは、履歴を含め、実際に保存されているデータ量を反映しています。毎晩、テーブルのタイムトラベル設定より古い履歴がクリーンアップされるため、長い履歴を保持していたプロジェクトでは、使用量が一度にではなく、その後数日かけて減少します。

## 推定サイズと取得できない合計

- **推定**は、PlaidCloudがそのテーブルまたはプロジェクトをまだ測定していないことを意味します。夜間の測定が実行されるまで、サイズはテーブルの形状から推定されます。
- **SnowflakeおよびDatabricksのプロジェクト**は、データをお客様自身のアカウントに保持します。サイズは推定値で表示され、PlaidCloudのストレージにはカウントされません。
- **ワークスペースの合計を取得できません**は、ワークスペースの合計を今回は読み取れなかったことを意味します。プロジェクトのサイズは推定値として表示されます。**更新**をクリックして再試行してください。
- **You don't have access to storage usage**と表示された場合は、ワークスペース管理者にプロジェクトの読み取りアクセスを依頼してください。
