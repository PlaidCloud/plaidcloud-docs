## 検索

プロジェクトの検索は、階層の左下にあるフィルターボックスで行います。検索フィルターはプロジェクト名とラベルを検索して一致するものを探し、結果を上の階層に表示します。


## 新しいプロジェクトの作成

新しいプロジェクトを作成するには、次の手順に従います。

1. Analyzeを開きます
2. 上部のメニューバーから「プロジェクト」を選択します
3. 「新規プロジェクト」ボタンをクリックします
4. 「Access Control」セクションを含むフォームの情報を入力します
5. 「Create」をクリックします

これで、プロジェクトのアクセス権限の更新、オーナーの追加、ワークフローの作成を行う準備が整いました。

<Aside>デフォルトでは、プロジェクトは現在のワークスペースのすべてのメンバーがアクセスできます</Aside>


## デフォルトのドキュメントアカウントの設定

プロジェクトホームの**接続環境**の横で、プロジェクトの**デフォルトのドキュメントアカウント**を選択します。解除するには**なし**を選択します。

プロジェクト内では、すべてのファイルセレクターの先頭に**Project Default**が表示され、プロジェクトに現在設定されているアカウントの代わりになります。プロジェクトを離れたとき、プロジェクトにデフォルトが設定されていないとき、そのアカウントが削除されたとき、またはそのアカウントへのアクセス権がないときは、リストから消えます。

新しいファイルステップでは、プロジェクトにデフォルトがある場合、Project Defaultがあらかじめ選択されます。既存のステップが書き換えられることはありません。ドキュメントアカウントは、接続環境とは異なり、ステップごとに選ぶものであるため、各ステップは、ユーザー自身が変更するまで保存時のアカウントのままです。

Project Defaultのままのステップは、実行時にプロジェクトのデフォルトであるアカウントに解決されます。そのため、実行の途中でデフォルトを変更しても、影響を受けるのはまだ開始していないノードだけです。これは接続環境を変更した場合と同じです。ステップがProject Defaultで実行され、プロジェクトにデフォルトが設定されていない場合、実行は別のアカウントにフォールバックせず、プロジェクトの名前を示して失敗します。


## バージョン履歴

プロジェクト内のすべてのオブジェクト（ステップ、UDF、ワークフロー、ディメンション、保存したレイアウト、ドキュメントエディターやデータエディター、プロジェクト自体の設定）は、バージョン履歴のバックアップの対象です。バックアップは個々の保存のたびには取得されません。オブジェクトが30秒間追加で保存されなかった時点で、その確定した状態のバックアップが1回取得されます。短い間隔で何度も保存するなど、編集が連続した場合は、保存ごとのバージョンではなく、最終結果を含む1つのバージョンが作成されます。バックアップの待機によって保存が遅くなることはありません。カウントダウンもバックアップ自体もバックグラウンドで実行されます。今すぐバージョンが必要な場合は、**Back up now**を使用すると、現在の状態を即座に取得し、完了するまで待機します。これはUI、API、`*_versions` MCPアクションの `backup` で利用できます。バージョン履歴は、Freeを含むすべてのプランで利用できます。

過去のバージョンはポイントインタイムリカバリーに対応しており、オブジェクトを以前のバージョンに復元できます。ロックされたプロジェクト内での復元は、そこでの他の変更と同様に拒否されます。

バージョンはその場で復元されます。プロジェクト、ディメンション、ユーザー定義関数、ステップ、ワークフロー、データエディターのバージョンを復元すると、その同じ項目が置き換えられ、別の項目をターゲットとして指定すると拒否されます。たとえば、「A project version is restored in place. Leave the target out, or set it to this project.」と表示されます。復元は項目に対する変更であるため、編集する場合と同じロールが必要です。[行を制限する](/ja/administration/access/managing-security-groups-and-assignments/#行を制限するプロジェクトを変更できるユーザー)プロジェクトでは、プロジェクトや、制限された列が参照するディメンションを復元するには、プロジェクトのアーキテクトが必要です。古いテーブルデータを別のテーブルとして戻すには、[テーブルスナップショット](/ja/guides/data/table-snapshots/)を新しいテーブルに復元します。

この自動追跡に加えて、プロジェクトとその要素ではバージョン管理も利用できます。バージョンを簡単に作成できるだけでなく、あるバージョンから別のバージョンへ変更をマージすることもできます。これにより、スナップショットを簡単に記録したり、開発用のバージョンを作成し、必要なときにその変更を開発以外のバージョンにマージしたりできます。バージョン管理、比較、マージの実践については、[コラボレーション: バージョン、比較、共有](/ja/get-started/tutorials/collaborate-versions-and-sharing/)を参照してください。

テーブルデータには独自の履歴があります。Lakehouseが書き込みのたびに取得するスナップショットで、[テーブルスナップショット](/ja/guides/data/table-snapshots/)で説明しています。

### AIアシスタントまたはMCPによる復元と保持

AIアシスタントまたはMCPでは、`dimension_versions` が `version_id` を指定してディメンションのバージョンを復元、保持、解放し、`restore_project` はプロジェクト内のすべてのディメンションを最後のバックアップまでロールバックします。また、すべての `*_versions` の一覧（ステップ、UDF、ワークフロー、ディメンション、プロジェクト）には、各バージョンの `version_id` と、保持されているかどうかが表示されます。いずれかの `*_versions` ツールまたはREST APIによる `restore` は、項目をその場で復元します。ターゲットは指定しないか、項目自身を指定します。`project_upsert` はロックされたプロジェクトのロックを解除でき、`if_match` に対応しているため、最後に読み取った後に加えられた変更を上書きせず、失敗します。


## プロジェクトアクセスの管理

### アクセスの種類

プロジェクトのセキュリティは、3種類のアクセスに簡素化されています。

* すべてのワークスペースメンバー
* 特定のメンバーのみ
* 特定のセキュリティグループのみ

プロジェクトのセキュリティは、次の手順で簡単に設定できます。

1. Analyzeを開きます
2. 「プロジェクト」を選択します
3. 制限したいプロジェクトの編集アイコンをクリックします
4. 「Access Control」で、必要な制限を選択します
5. 「Update」をクリックします

プロジェクトへのアクセスを変更できるのは、プロジェクトのアーキテクトまたはテナント管理者のみです。変更できる内容は、アクセスの種類、プロジェクトのメンバーとセキュリティグループ、データ共有です。それ以外のユーザーには、これらのパネルが読み取り専用で表示され、「Only project Architects can change access.」というメモが表示されます。


## すべてのワークスペースメンバー

「すべてのワークスペースメンバー」アクセスは、ワークスペースのすべてのメンバーにアクセスを許可する最も簡単なオプションで、メンバーの追加の割り当ては不要です。


## 特定のメンバーのみ

「特定のメンバーのみ」のアクセス設定では、各メンバーをプロジェクトに割り当てる必要があります。メンバーをプロジェクトに割り当てるには、次の手順に従います。

1. Analyzeを開きます
2. 上部のメニューバーから「プロジェクト」を選択します
3. メンバーアイコンをクリックします
4. 「Access」列で、メンバー名の横のチェックボックスを選択して、メンバーにアクセスを許可します
5. 「Update」をクリックします

メンバー数が多いクラウドでは、この方法は想定以上の手間がかかることがよくあります。そのような場合にセキュリティグループが役立ちます。

<Aside>メンバーを追加するには、ワークスペースのメンバーである必要があります。</Aside>


## 特定のセキュリティグループのみ

「特定のセキュリティグループのみ」オプションでは、特定のセキュリティグループにアカウントへのアクセス権限を割り当てられます。アクセス制限がセキュリティグループとの関連付けに基づくため、大規模なグループのアカウントアクセスの管理がはるかに簡単になります。これは、シングルサインオンによる自動グループ関連付けと組み合わせると特に便利です。シングルサインオンでメンバーのグループ割り当てを設定すると、これらのグループによってプロジェクトへのアクセスも暗黙的に有効化・無効化できます。

割り当てられたグループを編集するには、次の手順に従います。

1. Analyzeを開きます
2. 上部のメニューバーから「プロジェクト」を選択します
3. セキュリティグループアイコンをクリックします
4. 「Access」列で、セキュリティグループ名の横のチェックボックスを選択して、セキュリティグループにアクセスを許可します
5. 「Update」をクリックします


## プロジェクト間のデータ共有

データ共有を使用すると、あるプロジェクトから別のプロジェクトのテーブルにアクセスできます。たとえば、[Import Project Table](/ja/reference/workflow-steps/import/import-project-table/)ステップと[Export Project Table](/ja/reference/workflow-steps/export/export-project-table/)ステップで、プロジェクト間のデータを移動できます。共有は、データが共有されるプロジェクトが、他の1つのプロジェクトに対して付与します。

1. データを共有したいプロジェクトを開き、その[プロジェクトホーム](/ja/guides/projects/project-home/)に移動します。
2. **Access & sharing**を開きます。**データ共有**の下で、**新規データ共有**をクリックします。
3. **プロジェクトを選択**で、このプロジェクトのデータを使用できるプロジェクトを選択します。
4. **許可される操作**で、**読み取り**、**書き込み**、またはその両方にチェックを入れ、**データ共有を追加**をクリックします。

**データ共有を削除**は、共有を削除します。プロジェクトのデータ共有を追加または削除できるのは、プロジェクトのアーキテクトまたはテナント管理者のみです。

共有はプロジェクトに対して付与されるため、そのプロジェクトのメンバーとワークフローのみを対象とします。

- 共有経由の**読み取り**には、共有が付与されたプロジェクトでのロールが必要です。そこでロールを持たないユーザーは、共有から何も取得できません。
- 共有経由の**書き込み**（共有元のプロジェクトでのテーブル、フォルダー、ディメンションの作成）には、**書き込み**共有と、自分のプロジェクトでのマネージャーまたはアーキテクトのロール（そこで同じ変更を行えるロール）が必要です。それ以外のユーザーには、「Writing to this project through a data share needs a write share from it to your project, and the Manager or Architect role in your project.」と表示されます。

ワークフローはそれぞれのプロジェクト自身のIDで実行されるため、Import Project TableステップとExport Project Tableステップは、誰が実行を開始しても共有を通じて動作します。


## 異なる閲覧ロールの設定

プロジェクトでは、中間ステップを完了するために複数の変換やテーブルが必要になる一方、最終的な結果は少数のテーブルだけになることがよくあります。メンバーは、プロジェクトのすべての要素を閲覧する必要があるとは限らず、最終成果物だけで足りる場合もあります。PlaidCloudでは、異なる閲覧ロールを設定して、各メンバーの表示内容を簡単に整理し、制御できます。

組み込みの閲覧ロールは3つあります。**アーキテクト**、**マネージャー**、**エクスプローラー**です。

**アーキテクト**ロールは最もシンプルで、プロジェクト、ワークフロー、テーブル、変数、データエディター、階層、ユーザー定義関数の完全な可視性と制御を提供します。

**マネージャー**ロールと**エクスプローラー**ロールには特定のアクセス権限はありませんが、カスタム定義できます。つまり、各グループに表示する項目を選択できます。

<Aside>**マネージャー**と**エクスプローラー**はセキュリティグループではありません。職務や情報の可視性を分離するための便利な手段にすぎません。</Aside>

プロジェクト内のすべてを閲覧する必要がある場合は、全員を**アーキテクト**にできます。そうでない場合は、メンバーを**マネージャー**や**エクスプローラー**のプロジェクトメンバーに指定して、可視性を制御できます。

別のロールを設定するには、次の手順に従います。

1. Analyzeを開きます
2. 「プロジェクト」を選択します
3. メンバーアイコンをクリックします
4. ロールを変更したいメンバーを選択します
5. 「Role」列で現在のロールをダブルクリックします
6. 目的のロールを選択します
7. 「Update」をクリックします


## プロジェクト変数の管理

プロジェクトやワークフローを実行するときは、繰り返し行うタスクのために変数を設定しておくと、煩雑さを減らし、時間を節約できます。これらの変数は通常の代数の変数と同じように動作し、変数が表すものと、その後に続く演算を設定できます。PlaidCloudでは、これらの変数をプロジェクトレベルで設定すると、そのプロジェクト内のすべてのワークフローに影響し、ワークフローレベルで設定すると、そのワークフローだけに影響します。

プロジェクトレベルの変数を設定するには、次の手順に従います。

1. Analyzeを開きます
2. 「プロジェクト」を選択します
3. Manage Project Variablesアイコンをクリックします

変数テーブルでは、変数を表示し、現在の値を表示・編集できます。「New Project Variable」ボタンをクリックして、変数を新規に追加したり、既存の変数を削除したりすることもできます。


## プロジェクトのコピー

**プロジェクトをコピー**は、プロジェクトの全体、または選択した一部を、新しいプロジェクトまたは既存のプロジェクトにコピーします。

プロジェクトをコピーするには、次の手順に従います。

1. Analyzeを開きます
2. 「プロジェクト」を選択します
3. コピーしたいプロジェクトを選択します
4. **アクション**ボタンをクリックし、**プロジェクトをコピー**を選択します
5. ターゲットを選択し、コピーする内容とデータを選んで、**プロジェクトをコピー**をクリックします
6. **コピー前の確認**の概要を確認し、**コピーを開始**をクリックします

### コピーする内容の選択

選択ツリーには、プロジェクトが保持するオブジェクトが、ワークフロー、ステップ、テーブル、ディメンション、データエディター、ユーザー定義関数の種類別に表示されます。プロジェクト全体をコピーするには、すべてにチェックを入れたままにします。一部だけをコピーするには、必要な部分だけにチェックを入れます。

それらの部分が何に依存しているかを調べる必要はありません。チェックを入れたものには、その依存関係も一緒にコピーされます。ステップが読み書きするテーブル、ステップが読み込むまたは配賦の対象とするディメンション、ステップが呼び出すユーザー定義関数、ステップが呼び出すサブワークフローやマクロが対象です。ワークフローのセンサーはワークフローとともにコピーされます。

**コピーされたセンサーは無効の状態で作成されます。** コピー先のプロジェクトで各センサーをオンにするまで、コピーでは何も起動しません。重複する項目を上書きするインポートでは、コピー先のワークフローにすでにセンサーがある場合、2つ目のセンサーは追加されません。

### 新しいプロジェクトへのコピー

新しいプロジェクトに名前とIDを付けます。IDはスキーマ名になり、後から変更できません。

**スケジュールは一時停止の状態で作成されます。** プロジェクト全体を新しいプロジェクトにコピーすると、各ワークフローのスケジュール済みイベントは一時停止の状態でコピーされるため、コピーが自動的に実行を開始することはありません。コピーが完了すると、元のプロジェクトでアクティブだったイベントを一覧にしたメッセージが表示されます。コピーでイベントを実行するには、**ツール** > **イベントスケジューラー**でイベントを選択し、**選択を有効化**をクリックします。[イベントの一時停止](/ja/administration/scheduled-events/event-scheduler/#イベントの一時停止)を参照してください。

### 既存のプロジェクトへのコピー

プロジェクトリストからターゲットを選択します。コピーは、そのプロジェクトを置き換えるのではなく、追加されます。

**ターゲットを変更できる必要があります。** ロールを持たないプロジェクトへのコピーや、変更を防ぐためにロックされているプロジェクトへのコピーは拒否されます。この確認は、何かを読み取ったり書き込んだりする前に行われるため、拒否されたコピーがターゲットに影響することはありません。また、プロジェクト自身へのコピーはできません。

**行を制限するプロジェクトのコピーには、プロジェクトのアーキテクトが必要です。** コピーは[行アクセス](/ja/administration/access/managing-security-groups-and-assignments/#行アクセスの管理)の制限がない新しいプロジェクトであり、コピー時にその旨が通知されます。「This copy is not row-restricted.」と表示されます。コピーを共有する前に、コピーに**行アクセス**を設定してください。行を制限する既存のプロジェクトへのコピーも同様に、そのプロジェクトのアーキテクトまたはテナント管理者が必要です。

**ターゲットは独自の設定を維持します。** 名前、ID、データ接続環境、ストレージのデフォルト、ドキュメントアカウント、アクセスの種類、アクセスリスト、行アクセスの付与は、すべてそのままです。取り込まれるのは、選択した内容のみです。

**Project Default**に設定されたステップは、アカウントではなくその設定自体が引き継がれます。コピー後は、コピー元で設定されていたデフォルトではなく、ターゲットプロジェクトのデフォルトに解決されます。

取り込む項目がターゲットにすでにある項目と同じ場合は、どうするかを選択します。

- **重複する項目を受信データで上書き** — 取り込まれたバージョンが、ターゲットのものを置き換えます。
- **重複する項目の新しいコピーを作成** — ターゲットは既存のものを維持し、取り込まれた項目は、名前の末尾に ` copy` を付けて追加されます。その名前も使用されている場合は、連番が付きます。

プロジェクト変数とワークフロー変数は、*新しいコピーを作成*の例外です。変数は名前で識別されるため、何からも参照されない名前に変更しない限り、2つ目のコピーを追加する方法がありません。コピーにも含まれる変数がターゲットですでに定義されている場合は、ターゲット自身の値が維持され、コピー時にスキップした変数が通知されます。*上書き*では、変数も他の項目と同様に置き換えられます。

この照合は名前ではなくIDによるものです。元のプロジェクトから来た項目は同じ項目として認識されますが、たまたま同じ名前を持つだけの2つの項目は別の項目として扱われ、どちらも残ります。

### コピーするデータ量の選択

**Data to copy**の下の2つの設定で、選択内容とともにコピーされるデータが決まります。

**テーブルデータ**は、各テーブルの何行をコピーするかを設定します。

| 選択肢 | コピーされる内容 |
| --- | --- |
| **No table data** | テーブル、ステップ、選択内容のその他の部分。行はコピーされません。これがデフォルトです。 |
| **完全** | 同じLakehouse内およびLakehouse間で、すべてのテーブルのすべての行。 |
| **サンプル** | 入力した**テーブルあたりの行数**まで。新しいプロジェクトのみが対象です。数値は1から1,000,000です。 |

サンプリングされたテーブルは、その行数まで、または行数がそれより少ない場合はすべての行を保持します。**完全**または**サンプル**のコピーでは、複数のテーブルが同時にコピーされるため、テーブル数の多いプロジェクトでも短時間で完了します。

**Copy dimension members**は、**テーブルデータ**でどの選択肢を選んでも、選択内容に含まれるすべてのディメンションのメンバーをコピーします。デフォルトでオンになっているため、テーブルデータなしのコピーでも、ディメンションにメンバーが入った状態で作成され、短時間で完了します。ディメンションをメンバーなしでコピーするには、チェックを外します。

REST API（`POST /rest/v1/analyze/project/copy`）または `project_copy` MCPツールでは、`data_mode` を `structure`、`full`、`sample` のいずれかに、`dimension_members` を `true` または `false` に設定します。`dimension_members` を省略した場合、メンバーはテーブルの行がコピーされるときにのみコピーされます。`project_copy` は、コピーされなかったERP書き込み承認など、コピーの警告も返します。

### コピーの確認

何かをコピーする前に、**コピー前の確認**にコピーの概要が表示されます。コピー元のプロジェクト、コピー先、**テーブルデータ**の選択、**Dimension members**を含めるかどうか、テーブルとビューの数、サイズ、推定時間、コピー元とコピー先のLakehouse、**ご注意**の下の警告が含まれます。**コピーを開始**をクリックして開始するか、**キャンセル**をクリックして戻り、選択を変更します。

### コピーを閲覧できるユーザー

データ（テーブルの行、ディメンションメンバー、またはその両方）を含めて作成したコピーは、作成した本人のみのプライベートなものになります。準備ができたら、新しいプロジェクトから共有してください。行レベルセキュリティを持つプロジェクトのコピーも、同じ理由でプライベートのままです。

既存のプロジェクトにデータをコピーするには、そのプロジェクトへの書き込みアクセスが必要です。

### コピーでのERP書き込み承認

自分専用のプライベートな新しいコピーには、コピー元プロジェクトの[ERP書き込み承認](/ja/guides/workflows/run-a-workflow/#プロジェクトに転記を承認する)が引き継がれるため、コピーを再度承認しなくても転記ワークフローをテストできます。対象は、テーブルデータ（**完全**または**サンプル**）、ディメンションメンバー、またはその両方を含めて作成した、新しいプロジェクトへのコピーです。承認は、次の場合にコピーされます。

- コピー元プロジェクトのアーキテクトまたはワークスペース管理者である。
- エージェントやサービスアカウントを通じてではなく、自分自身でコピーを作成する。

各承認は、現時点で自分自身が付与できる場合にのみコピーされます。つまり、その接続と環境が引き続き存在し、接続への書き込みアクセスがある場合です。コピーされた承認は、自分によるものとして記録されます。

**コピーはシミュレートの状態で作成されます。** コピー元プロジェクトの**ERP転記モード**が本番の場合、コピーの設定はシミュレートになり、ワークフローは転記する内容をERPに接続せずに作成・確認します。コピー元がシミュレートまたはオフに設定されている場合は、その設定が維持されます。コピーから実際に転記する準備ができたら、コピーのホームページの**ERP転記**にある**ERP転記モード**を本番に設定します。[転記モードの選択](/ja/guides/workflows/run-a-workflow/#転記モードの選択)を参照してください。スケジュールとセンサーは、前述のとおり一時停止および無効の状態で作成されるため、オンにするまでコピーでは何も実行されません。

既存のプロジェクトへのコピー、またはテーブルデータもディメンションメンバーもないコピーは、コピー元の承認がない状態で開始されます。転記する前に、ホームページの**ERP転記** > **ERP書き込み承認**で承認してください。

**コピー結果**には、たとえば「2 ERP write authorizations copied; ERP posting is in Simulate」のように何が行われたかと、コピーされなかった件数が表示されます。

### コピー結果

コピーが完了すると、**コピー結果**ウィンドウに、コピーされたテーブルとディメンションメンバーの概要が表示され、各テーブルとディメンションが名前と結果（**コピー済み**、**変更付きでコピー済み**、**サンプリング済み**、**スキップ済み**、**失敗**）とともに一覧表示されます。スキップまたは失敗したものについては、その理由も表示されます。**Retry failed items**をクリックすると、失敗したテーブルとディメンションを再度コピーします。コピー内のそれらの現在の内容は置き換えられます。コピーが完了または失敗すると、メッセージとメールで通知されます。結果は、メッセージから、または後から**プロジェクト**タブでコピーを選択し、**アクション**メニューから**インポートまたはコピーの結果を表示**を選択して、再度開けます。

結果は、誰かが破棄するまでコピーに残ります。コピーが完了したら、**結果を破棄**をクリックすると、プロジェクトを開けるすべてのユーザーから結果が削除されます。プロジェクト内の内容は変わりませんが、失敗した項目をウィンドウから再試行することはできなくなります。破棄するには、プロジェクトへの編集アクセスが必要で、プロジェクトがロックされていてはいけません。

### 参照の更新

プロジェクトのワークフローステップは、そのプロジェクト内のテーブルやその他のオブジェクトを参照します。**参照を更新**は、それらの参照を元のプロジェクトではなくコピーを指すように書き換えます。ほとんどの場合これが望ましい動作であるため、デフォルトでオンになっています。オフにすると、コピーされたステップは、コピー元のプロジェクトを指したままになります。

<Aside>コピーはバックグラウンドで実行されます。進行状況ダイアログには、コピーが各段階を進む様子が表示されます。**バックグラウンドで実行**をクリックするとダイアログを閉じて作業を続けられ、プロジェクトリストは自動的に更新され、コピーが完了すると通知されます。</Aside>

## プロジェクトレポートの表示

プロジェクトやワークフローが動的な場合、詳細なドキュメントを維持するのは困難です。この問題の解決を支援するため、PlaidCloudでは、ワークフロー、ワークフローステップ、ユーザー定義変換、変数、テーブルの詳細なドキュメントを提供するプロジェクトレベルのレポートを生成できます。このレポートはオンデマンドで生成され、プロジェクトの現在の状態を反映します。

レポートをダウンロードするには、次の手順に従います。

1. Analyzeを開きます
2. 「プロジェクト」を選択します
3. レポートアイコンをクリックします
