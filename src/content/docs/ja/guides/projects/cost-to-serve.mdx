**コスト・トゥ・サーブ**テンプレートは、各顧客への対応にかかるコストと、それを差し引いた後に残るマージンを示します。[Common Finance Model](/ja/guides/projects/data-foundation/)をベースにしているため、プロジェクトにデータを供給するどのERPでも動作し、**企業収益性**が構築するものをすべて含みます。

## 仕組み

1. 営業費用が、エンティティ、期間、計上先の部門ごとにプールされます。
2. 各プールには、その部門に対して**アクティビティマップ**で指定されたアクティビティとドライバーが適用されます。
3. 各顧客のドライバーは、プロジェクトの請求済み販売明細から取得されます。
4. 各プールは、エンティティと期間の範囲内で、ドライバーに基づいて顧客に配分されます。

そのエンティティと期間でドライバーの値が正でないプールは、顧客なしでそのまま通過するため、配分の合計は常にプールと一致します。

## アクティビティマップ

アクティビティマップは、テーブル`cts_activity_map`です。自由に編集でき、モデルがこのテーブルに書き込むことはありません。各行で、部門に**アクティビティ**と**ドライバー**を割り当てます。

| 列 | 内容 |
|---|---|
| `department` | 部門コード。一覧にないすべての部門には`*`を指定します。 |
| `activity` | アクティビティの名前（例：倉庫業務）。 |
| `driver` | その部門のコストを何で配分するか（以下を参照）。 |

| ドライバー | 配分の基準 |
|---|---|
| `orders` | 各顧客の注文数（重複を除いた請求書の数）。 |
| `lines` | 請求書の明細行。 |
| `quantity` | 取り扱った数量。返品も取り扱いに含まれるため、その数量分が計上されます。 |
| `revenue` | 純収益（クレジットメモを相殺後）。 |

サンプルデータには、部門`SALES`、`SERVICE`、`OPS`と、その他すべてを対象とする`*`行が含まれています。これらを自社の部門とアクティビティに変更してから、**Foundation**タブで**Apply changes**をクリックします。

## 得られるもの

| 出力 | 内容 |
|---|---|
| `cts_by_customer` | エンティティ、期間、顧客、アクティビティ別の、顧客対応コスト、顧客の収益、売上原価、売上総利益、顧客対応コスト控除後の純マージン、注文数。 |
| `cts_per_order` | 注文あたりの顧客対応コスト。 |
| `cts_tie_out` | エンティティと期間別の、元帳の営業費用と顧客に配分されたコストの比較。欠落や二重計上がなければ、差異は0です。 |

アシスタントとダッシュボード向けのメトリック：エンティティ、顧客、アクティビティ別の**Cost to Serve**、**Net margin after CTS**、**Orders**、**CTS per order**。アクティビティが`Unmapped`のコスト、または顧客がないコストは、どのアクティビティやドライバーにも割り当てられなかった営業費用です。

## プロジェクトの開始

<Steps>

1. Analyzeで**プロジェクト**を開き、**新規プロジェクト**をクリックします。

2. **開始元**で**Cost to Serve (template)** を選択します。先に作業例を確認するには、**サンプルデータで開始**にチェックを入れます。

3. ERPを接続して、**ロード**を実行します。[Data Foundationを始める](/ja/guides/projects/data-foundation-getting-started/)を参照してください。

4. 自社の部門に合わせてアクティビティマップを編集し、**Apply changes**をクリックします。

</Steps>

**Actions > Save as my template...** を使用すると、アクティビティマップをプロジェクトとともに保存できます。[マイテンプレートとして保存](/ja/guides/projects/data-foundation/#マイテンプレートとして保存する)を参照してください。
