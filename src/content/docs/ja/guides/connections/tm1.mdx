PlaidCloudをIBM **TM1 / Planning Analytics** サーバーに接続すると、ワークフローで保存済みビューやMDXクエリからキューブデータを読み取ったり、ディメンション階層をPlaidCloudのディメンションとして読み込んだりできます。この接続は、デフォルトではTM1自身のREST APIに **クラウドから直接** 到達します。自社ネットワーク内からしか到達できないTM1サーバーには、代わりにオンプレミスの[PlaidLinkエージェント](/ja/reference/cli/plaidlink/)が到達します。詳しくは、下記の[ファイアウォールの内側のTM1を読み取る](#ファイアウォールの内側のtm1を読み取る)を参照してください。このガイドでは、接続、クラウド直接のクエリの実行、1つのピリオドずつ取得するための増分抽出パターン、そしてオンプレミスの経路について説明します。

<Aside type="note">
このコネクタは読み取り専用です。TM1への書き戻しやTIプロセスの実行はできません。
</Aside>

## 前提条件

TM1管理者から、次のものが必要です。

- **TM1 REST APIホスト**。たとえば `https://tm1-prod.example.com:8010` やPAaaSのURLです。
- ワークフローがクエリするデータベース、キューブ、ビューに対する読み取りアクセスを持つ **TM1アカウント**（ユーザー名とパスワード）。
- そのアカウントの認証が **Native**（TM1のユーザー/パスワード）か **CAM**（Cognos Access Manager SSO）か。CAMの場合は **名前空間** も必要です。
- ユーザーが読み取る **データベース（インスタンス）名**。

## 接続を作成する

<Steps>

1. **Tools > Connections** を開き、`New Connection` をクリックします。

2. メニューから **IBM Planning Analytics (TM1)** を選択します。

3. 各フィールドに入力します。

   | フィールド | 値 |
   |---|---|
   | 名前 | わかりやすい名前（例: `TM1 Prod`）。 |
   | ホスト | TM1 REST APIホスト（例: `https://tm1-prod.example.com:8010`）。 |
   | デフォルトのデータベース | 任意。ステップのデータベースフィールドにあらかじめ入力するTM1データベース。 |
   | 認証モード | `Native` または `CAM`。 |
   | ユーザー名 | TM1アカウントのユーザー名。 |
   | パスワード | TM1アカウントのパスワード。 |
   | CAM名前空間 | 認証モードがCAMの場合にのみ必要。 |
   | SSL証明書を検証 | デフォルトではオン。テストサーバー上の既知の自己署名証明書の場合にのみオフにします。 |
   | タイムアウト（秒） | デフォルトは30。 |

4. `Test Connection` をクリックします。テストが成功すると、サーバーの製品バージョンが報告されます。

5. `Create` をクリックします。

</Steps>

## クエリを実行する

<Steps>

1. ワークフローに **TM1: キューブのクエリ** ステップを追加します（ステップメニューの **IBM TM1 / Planning Analytics** の下にあります）。

2. **ソースとターゲット** で、**TM1接続**、**環境**、**データベース**、**キューブ**、**ターゲットテーブル** を設定します。キューブの選択肢は、接続したデータベースから、選択後にリアルタイムで検出されます。検出で返されない場合は、名前を手入力してください。

3. **スライス** で **ソースモード** を選択します。

   - **ビュー別** — 保存済みのTM1ビューを選択します。ビューの選択肢は、キューブを選択するとリアルタイムで検出されます。
   - **MDX別** — キューブに対するMDXクエリを記述します。

4. 必要に応じて、**POV（ポイントオブビュー）** で、ビューまたはMDXがすでに固定している範囲を超えて、ディメンションメンバーを固定します。ポイントオブビューを適用できるのは `By MDX` の場合だけです。

5. **プレビュー** をクリックすると、保存する前に現在のスライスを実行し、最初の数行とセル数を確認できます。

</Steps>

## ピリオド別の増分抽出

TM1は変更を追跡しないため、変更日時以降を取得する呼び出しはありません。代わりに、実行のたびに **ピリオド**（またはバージョン）でスライスします。ポイントオブビューの `Period` を、リテラルのメンバー名ではなく `{period}` ワークフロー変数に固定してください。ポイントオブビューのメンバー値は、MDXフィールドと同様に、実行時にワークフロー自身の変数から置換されます。これにより、各実行は、キューブ全体を再読み取りするのではなく、与えられたピリオドを取得します。ステップを[スケジュールされたワークフロー](/ja/administration/scheduled-events/)に配置し、実行のたびに進む変数を使用すると、1ピリオドずつ履歴を蓄積できます。

## オプション

- **ゼロ/空のセルを除外** — デフォルトではオフです。ゼロ値のセルを取得した **後で** 除外するため、帯域幅は節約できず、転記された `0` が実データである計画用キューブでは、それを破棄してしまいます。代わりに、クエリ自体でゼロを除外することをお勧めします。MDXでは `NON EMPTY` を、または保存済みビュー自身の除外設定を使用します。
- **行数の上限** — デフォルトは250,000です。行数の上限を設定しない場合は「無制限」ではなく、この上限が適用されます。有効な上限を超えるセルを返すクエリは、黙って切り捨てられるのではなく拒否されます。クエリを絞り込むか、正当な理由で大規模な抽出が必要な場合は、行数の上限を明示的に引き上げてください。

## ディメンション階層を読み込む

[TM1: ディメンションの読み取り](/ja/reference/workflow-steps/ibm-planning-analytics/tm1-dimension-read/)ステップは、1つのTM1階層の要素、親子の関係、属性を読み取り、同じ接続を使ってクラウドから直接、PlaidCloudのディメンションに読み込みます。これはTM1: キューブのクエリとは別のステップです。キューブのセルではなく、ディメンションの構造を読み取ります。1つの階層内で2つの連結の下にあるTM1要素や、単純な `+`/`-`/`~` の符号で表現できない連結の重みは、誤って読み込まれるのではなく、拒否または警告されます。両方の制限については、ステップのリファレンスを参照してください。

## ファイアウォールの内側のTM1を読み取る

TM1サーバーに、PlaidCloudが直接到達できるネットワーク経路がない場合（パブリックエンドポイントも、許可リストに登録されたIPも、VPNもない場合）は、代わりにインストール済みの **PlaidLinkエージェント** を通じて読み取ります。[TM1: キューブのクエリ（エージェント）](/ja/reference/workflow-steps/ibm-planning-analytics/tm1-query-remote/)ステップは、上記で説明したものと同じビュー/MDX/ポイントオブビューのクエリを実行しますが、それをエージェントにディスパッチし、エージェントが自社ネットワーク内でTM1に到達します。

次のものが必要です。

<Steps>

1. TM1サーバーにネットワークアクセスできる、**インストール済みのPlaidLinkエージェント**。[PlaidLinkのインストール](/ja/reference/cli/plaidlink/install/)を参照してください。

2. **TM1に対応したエージェントビルド。** PlaidCloudはディスパッチする前にエージェントが通知する機能を確認します。そのため、TM1サポートの提供前にインストールされた既存のエージェントは、手動で再ビルドして再インストールする必要があります。PlaidLinkは自動更新されません。[PlaidLinkのアップグレード](/ja/reference/cli/plaidlink/upgrade/)を参照してください。

3. **そのエージェントと共有されたTM1接続。** 接続の `Actions > Agents` の一覧から共有します。これは、すでに設定されているメンバーまたはグループのアクセスに加えて必要です。[セキュリティモデル](/ja/guides/connections/create-connection/#セキュリティモデル)を参照してください。

</Steps>

**TM1: キューブのクエリ（エージェント）** ステップを追加し、エージェントを選択して、TM1: キューブのクエリと同じ接続、データベース、キューブ、スライスのフィールドに入力します。このステップにはリアルタイムの検出もプレビューもありません。エージェントに到達できるのは実行中だけで、フォームを開いている間は到達できないためです。そのため、キューブ、ビュー、MDXは手入力し、ステップの実行時に検証されます。
