**システム**とは、1つの環境にある1つのERP接続のことです。**伝票を転記** ステップ、ファイルからの転記、その他あらゆる転記方法（[ERPシステムに伝票を転記する](/ja/guides/connections/post-documents/)を参照）は、各ドキュメントをシステムに送信し、ドキュメントの作成、チェック、送信の方法はそのシステムが決定します。閲覧できるすべてのERP接続は、それぞれ自動的にシステムとして表示されます。5つのSAP接続があれば5つのシステムとなり、クラウドとオンプレミスが並んで表示されます。また、同じ接続でもサンドボックスと本番の[環境](/ja/guides/connections/create-connection/#環境)ではそれぞれ別のシステムとなり、それぞれに独自の設定があります。

システムの設定は環境ごとに1回行います。その環境のすべてのプロジェクトで、どのエンティティをどこに転記するかの一覧と各システムの設定が共有されます。プロジェクトごとの設定は、本番稼働のみです。

## システムを開く

[転記レジスター](/ja/guides/connections/posting-register/)を開き、レールの **設定** の下にある **システム** を選択します。ヘッダーには次の項目があります。

- 環境ピッカー：システムを一覧表示する環境を選択します。
- プロジェクトピッカー：最初は **プロジェクトなし** になっています。プロジェクトを選択すると、各システムがそのプロジェクトで本番かどうかを確認し、本番稼働できます。
- **アクション**：**このプロジェクトで本番稼働…** （プロジェクトアーキテクトに表示）、**別の環境にコピー…** （ワークスペース管理者に表示）、**どの事業体がどこへ記帳するかを提案…** 、**変更履歴** があります。

ページには、**システム · *環境*** と **どのエンティティがどこに転記されるか** の2つのカードが表示されます。環境にERP接続がない場合は、**転記先のシステムがありません** と表示されます。接続でERPシステムへの接続を追加すると、ここに表示されます。

## システムの一覧

各システムは1行で表示され、名前、ERPの種類、一連のピルが含まれます。

| ピル | 内容 |
|---|---|
| **クラウド** | クラウドシステムです。 |
| **オンプレミス · エージェントはオンライン** | エージェントが過去5分以内に通信したオンプレミスシステムです。 |
| **オンプレミス · *時刻* からエージェントはオフライン** / **オンプレミス · エージェント未接続** | エージェントがオンラインでないか、この環境を担当するエージェントがありません。 |
| **転記可能** | システムに転記できます。 |
| **未確認** | エージェントがオンラインでないオンプレミスシステムです。 |
| **本番** / **シミュレート** | プロジェクトを選択した場合にのみ表示されます。このシステムがそのプロジェクトで実際に転記を行うかどうかを示します。 |
| **廃止** | システムは新しい転記を受け付けません。本番またはシミュレートの代わりに表示されます。 |

行には、2つのボタンが表示されることもあります。

- **再接続** — オンプレミスシステムのエージェントがオンラインでない場合に表示されます。接続が開き、再度サインインできます。
- **本番稼働 ›** — プロジェクトを選択している場合に、プロジェクトアーキテクトに表示されます。廃止されておらず、転記可能で、まだシミュレートのシステムが対象です。[本番稼働](#本番稼働)を参照してください。

### 行を開くと表示される内容

行の左にあるトグルで行を開きます。3つの項目とリンクの行が表示されます。

**残りの作業** は、システムが転記できるようになるまでに必要な作業のチェックリストで、各項目に担当者が示されます。完了した項目にはチェックが付き、完了済みと表示されます。

| 項目 | 担当者 | 完了の条件 |
|---|---|---|
| サービスアカウントとその権限 | **IT** | 現時点では常に完了しており、設定は不要です。 |
| エージェントのインストールとオンライン化（オンプレミスのみ） | **IT** | エージェントがオンラインである。 |
| このシステムに転記するエンティティ | **ワークスペース管理者** | [どのエンティティがどこに転記されるか](#どのエンティティがどこに転記されるか)の行にこのシステムが指定されている。 |
| 本番稼働 | **プロジェクトアーキテクト** | 選択したプロジェクトでシステムが本番になっている。 |

**できること** は「仕訳、顧客請求書を受け付けます · 仕訳を取り消せます · 呼び出し内で応答」のような1行で、システムが受け付けるドキュメントの種類、取り消せる種類、応答が **呼び出し内で応答** か **後で応答** かを示します。各システムの完全な一覧は、後述の[各システムでできること](#各システムでできること)にあります。

**リストのコピー** は、システムの勘定科目、会社、期間のコピーがどれだけ古いかを、**今すぐ更新** と **コピーを表示** とともに示します。[システムのリストのコピー](#システムのリストのコピー)を参照してください。

その下のリンクは **IT向け**、**設定…**、**廃止にする**（または **廃止から戻す**）、**履歴** です。**履歴** は、そのシステムだけの[変更履歴](#変更履歴)を開きます。

## 設定項目

すべての設定には初期値があり、ほとんどのプロジェクトでは変更する必要がありません。

| 設定 | 場所 | 変更できるユーザー | 初期値 |
|---|---|---|---|
| どのエンティティがどこに転記されるか | 環境ごとに1回、[システム](#どのエンティティがどこに転記されるか) | ワークスペース管理者 | 行なし。行がない場合は、**システム** に一覧表示されている廃止されていないシステムが1つだけのとき、そのシステムがすべてのエンティティを受け付けます。 |
| 廃止 | システムの行 | ワークスペース管理者 | 廃止なし |
| シミュレートまたは本番 | システムごと、プロジェクトごとの[本番稼働](#本番稼働) | プロジェクトのアーキテクト | シミュレート |
| **毎回必要な値** | システムの[設定](#システム設定) | ワークスペース管理者 | なし |
| **コード対応**（エンティティの対応を含む） | システムの[設定](#システム設定) | ワークスペース管理者 | なし |
| **お客様独自の関数**（SAPオンプレミス） | システムの[設定](#システム設定) | ワークスペース管理者 | なし、または変換されたステップが持ち込む関数 |
| 保留ルール | システムごとの[保留ルール](#保留ルール) | レジスター管理者（`erp.register.admin`） | 保留されるものはなし |
| **担当者の確認待ちにする** | ステップの **詳細 ▸** の下 | ステップの作成者 | 保留されるものはなし |
| **通知先** | ステップの **詳細 ▸** の下 | ステップの作成者 | **実行を開始した人** |
| **丸め勘定と上限** | ステップの **詳細 ▸** の下 | ステップの作成者 | 丸めなし |
| **転記済み伝票が変更されて戻ってきたとき** | ステップの **詳細 ▸** の下 | ステップの作成者 | **確認する(初期値)。2 つの選択肢とともに「要対応」に入ります。** |

4つのステップ設定は、[ERPシステムに伝票を転記する](/ja/guides/connections/post-documents/)でステップとともに説明しています。ステップ自身の保留については[後述](#ステップ自身の保留)します。

## システム設定

開いた行で **設定…** を選択します。ダイアログ **設定: *システム*** を編集できるのはワークスペース管理者のみで、それ以外のユーザーには **ワークスペース管理者のみが変更できます。** と表示されます。**保存** はシステムの設定全体を置き換え、各変更は[変更履歴](#変更履歴)に記録されます。

**毎回必要な値** は、このシステムに送信されるすべてのドキュメントに追加される値で、**値** と **設定値** のペアで指定します。システムは必要な値を名前で読み取り、同じ意味を持つドキュメント自身の列がある場合は、システムの値よりそちらが優先されます。

| システム | 値 | 用途 |
|---|---|---|
| Sage Intacct | `gl_journal_id` | ドキュメントに `journal_type` がない場合に、仕訳エントリを転記する仕訳帳。 |
| Sage 100 | `bank_code` | ドキュメントに `bank_code` がない場合に、支払の引き落とし元となる銀行口座。 |

**コード対応** は、ここでのコードがシステム内の別のコードであることを示すもので、**ディメンション**、**当社のコード**、**システム側のコード** で指定します。システム内の会社のコードが異なるエンティティにはディメンション `entity` を、勘定科目には `account` を使用します。[チェック](#リストに対するチェック)は、この対応を通じて、対応がない場合は書かれているとおりに、システムのリストからコードを検索します。また、エンティティの対応があると、そのエンティティについて、一覧がこのシステムを[提案](#推奨される行)できるようになります。

**お客様独自の関数** は、SAPオンプレミスの場合にのみ表示されます。**ドキュメントの種類** ごとに関数を指定します。設定で指定するのは関数名のみです。各関数のフィールド対応（どのSAPフィールドにどの列を割り当てるか）はシステムにそのまま保持され、変換されたSAP転記ステップが持ち込んだ関数は、そのステップが持っていたフィールド対応を保持します。[SAPオンプレミス](#sapオンプレミス)を参照してください。

## どのエンティティがどこに転記されるか

2番目のカードは、どのエンティティをどのシステムに、いつから転記するかの一覧です。環境ごとに1回設定し、その環境のすべてのプロジェクトで共有されます。各行は、エンティティ、**→**、システム、任意の **開始日(YYYY-MM-DD)** で構成されます。

1. **行を追加** を選択し、エンティティを入力して **システムを選択** からシステムを選択します。廃止されていないシステムのみが表示されます。
2. **開始日(YYYY-MM-DD)** を空白にすると「最初から」になります。エンティティがそのシステムへの転記を開始する日付を指定することもできます。年の途中でエンティティを別のシステムに移すには、最初の行を残し、移行日（たとえば `2026-07-01`）から新しいシステムを指定する2行目を追加します。
3. **保存** を選択します。この形式でない日付は **日付は2026-07-01の形式で入力してください。** というメッセージで拒否されます。

一覧を編集するにはワークスペース管理者である必要があり、それ以外のユーザーは読み取り専用で表示されます。すでに保存されたエンティティの名前は変更できません。行の末尾の×で削除し、別の行を追加してください。ドキュメントで使われているものの、まだどの行にも指定されていないエンティティは、システム未選択の状態で一覧表示されます。1つもない場合、カードには **エンティティはまだありません。転記するテーブルに含まれているエンティティが対象です。行を追加して指定してください。** と表示されます。

### ドキュメントが転記先のシステムを見つける方法

ドキュメントは、そのプロジェクトの環境にあるシステムを通じて転記されます。

- 転記先のシステムは、**開始日** がドキュメントの転記日（転記日がない場合は今日）以前であるエンティティの最新の行のシステムです。
- 環境の一覧に行がまったくなく、**システム** に一覧表示されている廃止されていないシステムが1つだけの場合は、そのシステムがすべてのドキュメントを受け付けます。
- その日付でエンティティをカバーする行がないドキュメントは転記されず、エンティティに対するシステムがない旨が表示されます。
- 行が廃止されたシステムを指しているドキュメントは転記されず、システムが廃止されている旨が表示されます。

### 推奨される行

まだどの行にも指定されていないエンティティについて、環境内で廃止されていないシステムのうち、`entity` の[コード対応](#システム設定)または自身の会社リストのコピーでそのエンティティを指定しているシステムがちょうど1つの場合、一覧はそのシステムを提案します。その行には **推奨** と表示され、**承認する** を選択するまで読み取り専用のままです。保存されるのは承認した行のみです。

**アクション** の **どの事業体がどこへ記帳するかを提案…** は、Data FoundationからのWeaveの提案です。プロジェクトを選択すると、プロジェクトのData Foundationが読み込んだ各エンティティに、読み込み元の接続を入力します。モデルによる計算は行われず、何も保存されません。行が入力され、その件数がメッセージで表示されるので、各行を確認して **保存** を選択します。何も読み込まれていない場合は **まだ提案はありません。** と表示されます。

### ここでは変更できない行

- システムが廃止されている行は、**廃止** と表示された読み取り専用になります。一覧を保存しても、その行は保持されます。
- 閲覧できないシステムを指す行は、**この一覧にありません** と表示された読み取り専用になります。一覧を保存するとその行は削除されるため、**保存** を選択すると、まず **振り分けを保存** で確認を求められます。

## 本番稼働

誰かが意図的に本番稼働するまで、実際の転記は行われません。本番稼働はシステムごと、プロジェクトごとに行います。1つのプロジェクトで、一部のシステムは本番で、ほかはシミュレートのままという状態も可能です。新規、コピー、またはトライアルのプロジェクトは、誰かがそのプロジェクトで本番稼働するまで、すべてのシステムでシミュレートから始まります。

1. ヘッダーのプロジェクトピッカーでプロジェクトを選択します。
2. システムの行で **本番稼働 ›** を選択するか、**アクション** の **このプロジェクトで本番稼働…** を選択して、転記可能でまだ本番になっていないすべてのシステムを対象にします。プロジェクトを選択していない場合は **本番稼働するプロジェクトを選択してください。** と表示されます。
3. **本番稼働** ダイアログは、まず何も変更せずに変更内容を確認して表示します。
   - **これらは本番になります**：実際に転記を行うようになるシステム。
   - **プロジェクトの転記モードが本番に変わり、本番のすべてのシステムが実際に転記します。** — プロジェクト自体がまだ本番モードでない場合に表示されます。
   - **すでに本番**：すでに本番のシステム。
   - ***システム* を本番にできません**：理由付きで表示されます。システムが廃止されている、プロジェクトがロックされている、その接続への書き込みアクセス権がない、または転記できるシステムではない、のいずれかです。
4. **本番稼働** を選択します。1つ以上のシステムが本番になる場合にのみ有効になります。

本番稼働すると、その環境にあるそれらのシステムに対するプロジェクトの認可が書き込まれ、プロジェクトの転記モードが本番でなかった場合は本番に設定されます。本番稼働した各システムは[変更履歴](#変更履歴)に記録されます。本番稼働は、別の環境やプロジェクトにコピーされることはありません。

本番稼働には、ロックされていないプロジェクトのアーキテクトで、各接続への自身の書き込みアクセス権が必要です。REST API（`POST /erp/go-live`）とMCPツール `erp_go_live` を通じても同じチェックが適用され、MCPツールは委任されたAIトークンも拒否します。本番稼働するのは人であり、人に代わるエージェントではありません。どちらも、`dry_run` を false に設定しない限り、変更内容を報告するだけです。

## システムを廃止する

開いた行で **廃止にする** を選択し、**廃止** で確定すると、システムは元に戻されるまで転記先として提示されなくなります。一覧のその行は保持され、そのシステムに振り分けられたドキュメントは転記されません。**廃止から戻す** で元に戻せます。どちらもワークスペース管理者が必要で、[変更履歴](#変更履歴)に記録されます。

## IT向け

**IT向け** は **IT向け: *システム*** を開き、許可や監査ができるように、このシステムで製品が行う操作を示します。

- **サインイン先** — 接続がサインインに使用するアカウント。
- **バッチサイズ** — システムの設定で指定されているバッチサイズ、または **未設定**。
- **エージェント** と **エージェントのバージョン** — オンプレミスシステムの場合。
- **当社での呼称** — 製品が名前で呼び出す各関数またはサービスと、最後に使用された日時。SAPオンプレミスの場合は、[設定](#システム設定)で指定した関数です。転記またはテストが行われる前は、**まだありません。このシステムへ転記またはテストすると一覧表示されます。** と表示されます。

サインインの有効期限が切れている場合は、ダイアログにその旨が表示され、**再接続** が提示されます。

## 別の環境にコピーする

サンドボックスを一度設定したら、再入力せずに本番にコピーします。**アクション** の **別の環境にコピー…** を選択します（ワークスペース管理者のみ）。

1. **コピー先** で環境を選択します。
2. この環境のすべてのシステムが一覧表示され、同じ接続が他の環境でもシステムになっている場合はチェックが付きます。そうでないものは ***システム*（この環境にありません）** と表示され、チェックを付けられません。
3. **コピー** を選択して確定します。

チェックを付けた各システムについて、コピーによって他の環境のそのシステムの設定、コード対応、SAP関数がこの内容に置き換えられ、そのシステムを指定する一覧の行のうち他の環境にないもの（同じ日付からの同じエンティティ）が追加されます。すでにある行はそのままです。結果には、コピーされた一覧の行数とシステムの設定数が表示されます。本番稼働はコピーされません。他の環境のすべてのプロジェクトは、誰かがそこで本番稼働するまでシミュレートのままです。

## システムのリストのコピー

チェックでは、ドキュメントをシステム自身の **勘定科目**、**会社**、**期間** と比較します。PlaidCloudは、それぞれのコピーをシステムから読み取って保持しています。

- **本番のシステムでの本番の実行を開始するたび**に、システムから読み取ります。読み取り全体にかかる時間は最大60秒です。ドキュメントを停止できるのは、その実行の読み取りのみです。
- 開いた行の **今すぐ更新** を選択したとき。更新は転記と同様にERPシステムに接続するため、ワークスペース管理者であり、かつその接続への自身の書き込みアクセス権が必要です。読み取った勘定科目、会社、期間の数と、読み取りにかかった時間が報告されます。更新されたコピーは表示用であり、チェックには使われません。

各リストの経過時間は行に表示されます（たとえば「勘定科目は3時間前に読み取り」「期間は一部のみ、2日前に読み取り」「会社はまだ読み取られていません」など）。読み取れなかった場合は、その旨と理由が表示されます。途中で打ち切られたコピーや空で返されたコピーが、以前のコピーを置き換えることはありません。

**コピーを表示** は **リストのコピー** を開き、**勘定科目**、**会社**、**期間** のリストを1つずつ、**コード**、**名前**、**ブロック済み**、**システム上のステータス**、**開始**、**終了** とともに表示します。最初の5,000行まで表示されます。税コード、顧客、仕入先はコピーされず、システムに任されます。

シミュレートの実行ではシステムから何も読み取らないため、シミュレートではこれらのチェックは実行されず、本番稼働したときにシステムが判断します。

## リストに対するチェック

本番のシステムでの本番の実行を開始する際、各ドキュメントは、その実行が読み取ったリストに対してチェックされます。リストを読み取れなかった、一部のみだった、空で返された、または時間内に完了しなかったチェックは、未確認として扱われます。合格にも停止にもならず、システムが判断します。各ドキュメントでどのチェックが実行されたかは、実行ページに表示されます。

- **Period open**（期間が未締めであること）。 ドキュメントの期間は、期間コードで特定されるか、そうでない場合は転記日が含まれる期間で特定されます。その期間をすべてシステム上で転記締めされている場合にのみ停止されます。月と重なる調整期間があれば、その日付は未締めのままです。システムがPlaidCloudの知らない文言で報告したステータスの期間は、チェックされません。
- **エンティティが会社であること。** 会社のリストを読み取った場合、ドキュメントのエンティティは、その `entity` コード対応がある場合はそれを通じて、ない場合は書かれているとおりに、システムの会社のいずれかである必要があります。
- **勘定科目が存在すること。** 勘定科目のリストを読み取った場合、すべての明細の勘定科目は、その `account` コード対応がある場合はそれを通じて、ない場合は書かれているとおりに、システムに存在し、転記ブロックされていない必要があります。数値コードは先頭のゼロにかかわらず一致するため、`6100` で `0000006100` が見つかります。

停止されたドキュメントは、「明細3: 勘定科目6100は*システム*にありません」のような理由とともに未転記になります。各ERPシステムが提供するリストは、下の表にあります。

## 保留ルール

ルールで指定しない限り、何も保留されません。ルールによって保留されたドキュメントは、人が[承認](/ja/guides/connections/posting-register/)するまで承認が必要な状態で待機します。チェックに合格したほかのドキュメントは、承認なしで送信されます。レールの **設定** の下にある **保留ルール** を選択します。

一覧には **名前**、**適用対象**、**保留する条件**、**承認者**、**実行者** があります。ルールがない場合は **保留されるものはありません** と表示されます。`erp.register.view` を持つユーザーはルールを閲覧できます。追加、編集、削除にはレジスター管理者（`erp.register.admin`）が必要で、ツールバーに **新しいルール**、**編集**、**削除** が表示されます。ルールを削除すると、新たな保留は行われなくなります。すでに待機しているドキュメントは、誰かが判断するまで待機したままです。すべての変更は[変更履歴](#変更履歴)に記録されます。

### ルールの条件

**新しいルール** は **新しい保留ルール** を開きます。

1. ルールに**名前**を付けます。たとえば「25万を超える仕訳」です。
2. **適用対象** でシステムを選択します。閲覧できるすべての環境のシステムが表示されます。
3. **保留する条件** で、ドキュメントを保留する条件にチェックを付けます。チェックを付けたすべてが成立する必要があります。何もチェックしない場合は、何も保留されません。
   - **金額が次を超える** 数値を **エンティティ自身の通貨で** 指定します。ドキュメントの大きさは、借方と正のローカル金額の合計、またはテーブルにローカル金額がない場合は取引金額です。
   - **ファイルから転記された**。
   - **これは** **取消**、**クレジット**、**訂正** のいずれか — 3つのうち任意のものにチェックを付けます。
   - **異常としてフラグ付けされている** — [異常としてフラグ付け](#異常としてフラグ付け)を参照してください。
   - **常時(例: 決算期間中)** — システム上のすべてのドキュメントを保留します。ほかの条件は無効になります。
4. **承認者** で承認者を選択します。**登録の承認者**、または **指定した担当者** です。担当者にチェックを付け、必要に応じて、承認対象のエンティティをカンマで区切って指定します（空白はすべてのエンティティ）。
5. **保存** を選択します。ルールに名前、システム、1つ以上の条件、数値の金額が指定され、指定した担当者の場合は1人以上が指定されると有効になります。

保留されたドキュメントは、同じセットのほかのすべてのドキュメントも保留するため、セットは1つとして承認され、転記されます。

### 承認できるユーザー

承認者には `erp.register.approve` と、ドキュメントの接続に対する自身の付与が必要です。ルールで担当者が指定されている場合は、その人だけが承認でき、エンティティが指定されている場合は、そのエンティティについてのみ承認できます。自分が送信したドキュメントは誰も承認できません。実行を開始した人も、**これらを転記** で送信した人も同様です。

ドキュメントがシミュレートで送信されたときに行われた承認は、本番での送信には適用されません。同じドキュメントを後で本番で送信するときは、改めて保留され、新たな判断が必要です。

ワークスペースで転記の職務分掌が必要な場合、その対象となる取消、クレジット、訂正は、ルールがなくても、2人目の担当者のために保留されます。

### ステップ自身の保留

**伝票を転記** ステップは、**詳細 ▸** → **担当者の確認待ちにする** で、システムより多くを保留できます。その条件は **金額が次の値を超える**、**ファイルから転記された**、**取消、貸方、または訂正伝票です**、**異常としてフラグ付けされている**、**常に** で、同じように組み合わせます。何もチェックしない場合、追加の保留は行われません。ステップの保留はシステムのルールに追加されるだけで、システムのルールが保留したものを解除することはできません。そのドキュメントは、レジスターの承認者が承認します。指定した承認者は、システムのルールで設定します。

REST API（`PUT /erp/steps/{step_id}/holds`）またはMCPツール `erp_hold_upsert` でステップの保留を変更するには、`analyze.step.write` と、ロックされていないプロジェクトのアーキテクトまたはマネージャーのロールが必要です。

### 異常としてフラグ付け

ドキュメントは、そのエンティティがそれ以前に転記したものと比べて、次のいずれかに該当する場合に異常としてフラグ付けされます。

- 金額が、同じ参照の直前の転記と比べて10倍を超えて大きいか小さい。
- そのエンティティが直近500件のドキュメントで使用していない勘定科目、顧客、仕入先、または取引先を使用している。
- 転記日が期間外である。

各フラグには、理由を説明する文が記録されます。たとえば「転記日2026-08-02は期間2026-07の範囲外です。」のようになります。フラグはエンティティの以前のドキュメントから計算されます。AIモデルは呼び出されません。以前のドキュメントがないエンティティは、フラグ付けされません。

## 各システムでできること

以下のどのシステムも、シミュレートで実行できます。シミュレートでは、各ドキュメントを作成してチェックし、何も送信しません。システムが受け付けない種類のドキュメントは未転記になり、別の種類には変換されません。

| システム | 場所 | 受け付けるもの | 取消可能なもの | 応答 | チェック用のリスト |
|---|---|---|---|---|---|
| NetSuite | クラウド | 仕訳、顧客請求書 | 仕訳 | 呼び出し内 | 勘定科目、子会社、転記期間 |
| Sage Intacct | クラウド | 仕訳、顧客請求書 | 仕訳 | 呼び出し内 | 勘定科目、エンティティ、報告期間 |
| QuickBooks | クラウド | 仕訳、顧客請求書、仕入先請求書、クレジットメモ | 仕訳、顧客請求書 | 呼び出し内 | 勘定科目、会社、帳簿の締め日までに締められた月 |
| Xero | クラウド | 仕訳、顧客請求書、仕入先請求書、クレジットメモ | 仕訳、顧客請求書 | 呼び出し内 | 勘定科目、組織、ロック日までに締められた月 |
| Acumatica | クラウド | 仕訳、顧客請求書、仕入先請求書、支払、クレジットメモ | 仕訳 | 後で | 勘定科目、ブランチ、会計期間 |
| Business Central | クラウド | 仕訳 | 仕訳 | 呼び出し内 | 会社、勘定科目、会計期間 |
| Dynamics 365 F&O | クラウド | 仕訳 | 仕訳 | 後で | 主勘定、法人、会計期間 |
| Oracle Fusion | クラウド | 仕訳 | 仕訳 | 後で | 元帳、勘定科目組み合わせ、会計期間 |
| S/4HANA Cloud | クラウド | 仕訳 | 仕訳 | 後で | 会社コード、G/L勘定科目 — 期間はないため、Period openはチェックされません |
| Workday | クラウド | 仕訳 | 仕訳 | 後で | 会社、元帳勘定科目、会計期間 |
| SAP（オンプレミス） | オンプレミス | 仕訳、顧客請求書、仕入先請求書（お客様の関数を通じて） | — | 後で、エージェントのレポートから | 読み取りなし。システムが判断 |
| Sage 100 | オンプレミス | 仕訳、支払 | — | 後で、エージェントから | 読み取りなし。本番の実行ではエージェントが期間と未決済の請求書をチェック |

応答が **呼び出し内** とは、ドキュメントの送信時に応答が返ることを意味します。応答が **後で** とは、送信後に応答が届くことを意味し、届くまでドキュメントは待機中になります。応答が確定しないドキュメントは未確認になり、[転記レジスター](/ja/guides/connections/posting-register/)で決着させます。

### SAPオンプレミス

SAPオンプレミスは、エージェントを通じて、ドキュメントの種類ごとにお客様独自の関数を呼び出して転記します。この関数は[**お客様独自の関数**](#システム設定)で設定します。種類に関数がないドキュメント、または関数のフィールド対応にドキュメントの参照用のフィールドがないドキュメントは、未転記になります。既存のSAP転記ステップを変換すると、そのドキュメントの種類についてシステムにまだ関数がない場合に、そのステップの関数とフィールド対応がシステムに引き継がれます。[ERPシステムに伝票を転記する](/ja/guides/connections/post-documents/)を参照してください。

- **シミュレート** は同じリクエストを作成し、エージェントの手前で停止します。SAPには何も届きません。
- **本番** は、システムの環境を担当するエージェントにドキュメントを渡します。エージェントはSAPの応答を、プロジェクトのデフォルトのドキュメントアカウント（`/erp_posting/sap` の下）にレポートとして書き込み、各ドキュメントはそのレポートが読み取られるまで待機中のままです。デフォルトのドキュメントアカウントがないプロジェクトは、SAPに本番で転記できず、ドキュメントはその理由で未転記になります。
- **エージェントがオフラインの場合**、何も送信されません。ドキュメントは、エージェントがオフラインだったという理由で未転記になり、エージェントが復旧した後に再試行できます。エージェントが約18秒以内にドキュメントを受け取らない場合も、ドキュメントは未送信のまま戻され、同じように未転記になります。
- SAPのレポートで判断されていないドキュメントは、未確認になります。転記レジスターで決着させます。

### Sage 100

Sage 100はオンプレミスで、ネットワークAPIはありません。ドキュメントは、SageのBusiness Object Interfaceを実行するエージェントを通じて届きます。

- **接続ごとに1つの会社。** 接続でSageの会社とその通貨を指定します。別の会社のドキュメント、または別の通貨の明細があるドキュメントは送信されません。
- **仕訳** はGL仕訳エントリとして転記されます。仕訳の参照はSageでの摘要になるため、最大30文字です。
- **支払** は、Sage外で行われた支払のAP手動小切手として転記されます。1つの支払に1つの仕入先、参照が小切手番号（最大7文字）、`bank_code`（ドキュメントから、またはシステムの[毎回必要な値](#システム設定)から）、そして各明細が支払う請求書を正の金額で指定する必要があります。
- **本番の実行では**、エージェントが最初にSageに問い合わせます。Sageで締められた期間の日付の仕訳は停止され、Sageで未決済として保持されていない請求書に対する支払も停止されます。
- **送信後**、ドキュメントは、Sageの転記済みテーブルに表示されて初めて転記済みになります。Sageのバッチに入力されたものの、まだ更新されていないドキュメントは待機中のままです。バックグラウンドのスイープが、最大で1時間に1回、エージェントに再度問い合わせ、7日後もまだ待機中のものは未確認になります。

## 変更履歴

システムへのすべての変更は、実施者と日時とともに記録されます。**システム設定**、**廃止**、**SAP関数**、**コード対応**、**どのエンティティがどこに転記されるか**、**保留ルール**、**本番稼働**、**リストのコピー**（システムのリストの読み取りごと）です。レールの **設定** の下、または **アクション** メニューの **変更履歴** を選択するか、システムの行の **履歴** を選択すると、そのシステムだけの履歴が表示されます。一覧には **日時**、**実行者**、**対象**、**システム**、**対象**、**開始**、**終了** があります。

付与されているシステムへの変更を確認できます。本番稼働は、アクセスできるプロジェクトの分のみ、ステップの保留も、アクセスできるプロジェクトの分のみです。

## 誰が何をできるか

以下のルールはすべてサーバーでチェックされ、行に別の記載がない限り、アプリ、REST API、MCPツールで同じです。

| 操作 | 必要なもの |
|---|---|
| システム、システムの設定、一覧、リストのコピーを表示する | `analyze.connection.read`。閲覧できる接続のみ |
| 設定の変更、システムの廃止、一覧の保存、別の環境へのコピー | ワークスペース管理者 |
| システムのリストを更新する | システムページではワークスペース管理者。REST APIとMCPツール `erp_system_lists` では `analyze.connection.read`。いずれの場合も、その接続への自身の書き込みアクセス権 |
| 本番稼働する | ロックされていないプロジェクトのアーキテクトで、各接続への自身の書き込みアクセス権があること。人であり、委任されたAIトークンは不可 |
| 保留ルールを読み取る | `erp.register.view` |
| システムの保留ルールを追加、変更、削除する | レジスター管理者（`erp.register.admin`） |
| ステップ自身の保留を変更する | `analyze.step.write`、およびロックされていないプロジェクトのアーキテクトまたはマネージャーのロール |
| 保留されたドキュメントを承認する | `erp.register.approve` と、ドキュメントの接続に対する自身の付与。ルールで担当者が指定されている場合はその担当者。自分の送信は不可 |
