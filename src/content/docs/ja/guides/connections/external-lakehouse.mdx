プロジェクトのテーブルは、通常は組み込みの PlaidCloud Lakehouse に保存されます。ワークスペース管理者は、PlaidCloud スタッフの支援なしで、PlaidCloud 内から**自分の Snowflake または Databricks ウェアハウス**を接続することもできます。接続後、ワークフローはプロジェクトのテーブルをお客様のウェアハウスで直接読み書きします。データはお客様のアカウント内に残り、お客様のガバナンスと課金の下で管理されます。PlaidCloud は、その上で変換、ワークフロー、ダッシュボードを実行します。

## ウェアハウスを接続する

ウェアハウスの接続、変更、削除ができるのは、ワークスペース管理者のみです。

1. ユーザーメニューを開き、**ウェアハウスの管理**を選択して、**ウェアハウスを追加**を選択します。ホームのチェックリストにある**ウェアハウスを使用する**の行で**接続**を選択するか、Snowflake または Databricks の接続ダイアログで**これを自分のウェアハウスとして使用する**を選択することもできます。
2. **Snowflake** または **Databricks** を選択します。
3. 次のいずれかの方法で接続します。**Sign in with Snowflake** または **Sign in with Databricks**（最も簡単な方法です。[Snowflake または Databricks でサインインする](#snowflake-または-databricks-でサインインする)を参照）を使用するか、セットアップスクリプトを実行して、生成された資格情報を貼り付けます（以下を参照）。

### 1. 最初にセットアップスクリプトを実行する

<Aside type="caution">接続する前にセットアップスクリプトを実行してください。実行しないと、接続チェックは失敗します。</Aside>

ダイアログは、選択した名前からセットアップスクリプトを作成し、入力に合わせて更新します。**スクリプトをコピー**でコピーし、ご自身のアカウントで実行します。このスクリプトが既存のウェアハウスを変更することはありません。

| | Snowflake | Databricks |
|---|---|---|
| 実行ロール | `ACCOUNTADMIN` | ワークスペースとメタストアの管理者 |
| 作成されるもの | 60 秒のアイドル後にサスペンドされるウェアハウス（月間クレジット上限を設定し、90 パーセントで通知、100 パーセントでサスペンド）、データベース、ロール、サービスユーザー | サービスプリンシパル、アイドル時に停止する SQL ウェアハウス、カタログ（すでに存在する場合は作成されません） |
| 変更できる名前 | ウェアハウス、サイズ、月間クレジット上限、データベース、ロール、サービスユーザー | サービスプリンシパル名、SQL ウェアハウス名、サイズ、アイドル状態から停止するまでの分数、カタログ |
| デフォルト | `PLAIDCLOUD_WH`（`XSMALL`、月 100 クレジット）、`PLAIDCLOUD`、`PLAIDCLOUD_ROLE`、`PLAIDCLOUD_SVC` | `plaidcloud`、`PlaidCloud`（`2X-Small`、アイドル 10 分）、カタログ `plaidcloud` |
| 認証 | キーペア（生成方法はスクリプトに表示されます） | サービスプリンシパルの OAuth シークレット |

このスクリプトでは、次の設定も行われます。

- **ネットワークアクセス。** スクリプトには、PlaidCloud の接続元アドレスが一覧表示されます。コントロールプレーンのアドレス `130.211.116.97/32` と、別のアドレスである場合はお客様のワークスペース自身のアドレスです。Snowflake のスクリプトは、サービスユーザーに対してこれらのアドレスのみを許可するネットワークポリシーを作成します。Databricks では、ワークスペースですでに IP アクセスリストが適用されている場合、スクリプトにこれらのアドレスを許可するステートメントが含まれます。お客様のアカウントを保護しているネットワークポリシーや IP アクセスリストにも、これらのアドレスを追加してください。
- **ポリシーの引き継ぎ。** Snowflake では、ロールに行アクセス、マスキング、プロジェクション、集計、結合の各ポリシーとタグを適用する権限が付与されるため、PlaidCloud がテーブルを書き換えてもポリシーは維持されます。Databricks では、使用している行フィルターまたは列マスクの関数に対して、サービスプリンシパルに `EXECUTE` を付与してください。
- **実行コスト。** Snowflake のロールには `SNOWFLAKE.GOVERNANCE_VIEWER` データベースロールが付与されます。これにより、PlaidCloud は各実行に帰属したクレジットを読み取れるほか、[最終読み取り](/ja/guides/projects/managing-tables-and-views/#最終読み取り)にも対応できます。Databricks には、`system` カタログにあるクエリ履歴とウェアハウスサイズへの読み取りアクセスが付与されます。
- **最終読み取り。** Databricks では、テーブルの最終読み取り情報に必要な `system.access` への `USE SCHEMA` と `system.access.table_lineage` への `SELECT` も、スクリプトによって付与されます。[実行ごとのウェアハウスコスト](#実行ごとのウェアハウスコスト)を参照してください。

### 2. 接続する

| フィールド | エンジン | 入力する内容 |
|---|---|---|
| 名前 | 両方 | PlaidCloud がウェアハウスを呼ぶときの名前です。ご自身で入力するまでは、アドレスに合わせて変わります（例: `Snowflake — myorg-myaccount`）。 |
| アカウント URL | Snowflake | アカウントのホスト（例: `myorg-myaccount.snowflakecomputing.com`）。 |
| 秘密鍵 | Snowflake | サービスユーザーの秘密鍵（PEM）。キーペアに有効期限はありません。 |
| ワークスペース URL | Databricks | ワークスペースのホスト（例: `adb-1234567890123456.7.azuredatabricks.net`）。 |
| SQL ウェアハウスの HTTP パス | Databricks | 例: `/sql/1.0/warehouses/abc123def456`。 |
| アプリケーション ID | Databricks | サービスプリンシパルのアプリケーション（クライアント）ID。 |
| OAuth シークレット | Databricks | サービスプリンシパルの OAuth シークレット。PlaidCloud が自動的に更新します。 |

**高度**で、代わりに Snowflake のプログラムによるアクセストークンや Databricks の個人用アクセストークンを使用できます。トークンには有効期限があり、その日以降は新しいトークンを追加するまで PlaidCloud はお客様のウェアハウスにアクセスできなくなります。期限の 14 日前から期限後まで、日付を知らせるバナーが表示され、**ローテーション**を選択できます。これにより、そのウェアハウスで[ウェアハウスを管理する](#ウェアハウスを管理する)が開き、新しいトークンの入力を求められます。キーペアまたは OAuth シークレットを使用すれば、有効期限の問題を避けられます。

アドレスには、アカウントのパブリック URL（末尾が `.snowflakecomputing.com`、`.cloud.databricks.com`、`.azuredatabricks.net`、または `.gcp.databricks.com`）を指定する必要があります。プライベートエンドポイントやカスタムエンドポイントはここではサポートされていません。ウェアハウスにプライベートで接続するには、アタッチ後に[直接接続をリクエスト](#直接接続)してください。

### 3. 確認して使用する

- **接続をテスト**は、アドレス、サインイン、PlaidCloud に必要なすべての権限をテストします。何も保存されません。
- **自分のウェアハウスとして使用**は、同じチェックを実行し、ウェアハウスをアタッチします。**ウェアハウスを追加**以外から開いた場合は、ウェアハウスをデフォルトにも設定し、ワークスペースが切り替わるまで待機します。通常は数分かかりますが、ウィンドウを閉じても問題ありません。切り替え後は、ワークスペース内の新規プロジェクトがお客様のウェアハウスを使用し、ウィンドウには**サンプルを実行**も表示されます（[サンプルを実行する](#サンプルを実行する)を参照）。**ウェアハウスを追加**から開いた場合は、デフォルトは変更されません。新規プロジェクトでこのウェアハウスを使用するには、[ウェアハウスを管理する](#ウェアハウスを管理する)で**デフォルトに設定**を選択します。

チェックに失敗すると、問題と対処方法が分かりやすい言葉で表示されます。不足している必要な権限は、そのまま実行できる `GRANT` ステートメントとして一覧表示され、それぞれに**コピー**ボタンと、実行したらチェックを入れる**完了**ボックスがあるほか、**すべてコピー**ボタンと**セットアップスクリプトを表示**が用意されています。**サポート向けにコピー**は、PlaidCloud サポート向けに、ウェアハウス自体のエラーテキストをコピーします。

チェックでは、**推奨 — 「最終読み取り」を有効にします**の下に、付与を推奨する権限が別途一覧表示され、それぞれに**コピー**があります。これらの権限があると、テーブルの[最終読み取り](/ja/guides/projects/managing-tables-and-views/#最終読み取り)情報がウェアハウスの履歴を読み取れるようになります。これらがなくてもウェアハウスは使用できます。その場合、接続は問題なく行われ、最終読み取りには **Read history incomplete** と表示されます。

- **Snowflake:** `GRANT DATABASE ROLE SNOWFLAKE.GOVERNANCE_VIEWER TO ROLE <role>;`（`SNOWFLAKE` データベースの `IMPORTED PRIVILEGES` でも動作します）。最終読み取りにはアクセス履歴が必要ですが、Snowflake Standard エディションにはありません。
- **Databricks:** サービスプリンシパルに対する、`system` の `USE CATALOG`、`system.access` の `USE SCHEMA`、`system.access.table_lineage` の `SELECT`。

| 表示される内容 | 対処方法 |
|---|---|
| サービスユーザーがオブジェクトを使用できない | そのロールに、対象オブジェクトに対する権限を付与します。セットアップスクリプトにはすべての付与が含まれています。 |
| ウェアハウスがサスペンドされている、または存在しない | ウェアハウス名と、ウェアハウスが自動的に起動できることを確認します（Snowflake では `AUTO_RESUME`、Databricks では実行中の SQL ウェアハウス）。 |
| ウェアハウスがクレジットのクォータを使い切った | リソースモニターのクォータまたは予算を引き上げるか、リセットされるまで待ちます。 |
| ネットワークポリシーが PlaidCloud をブロックしている | セットアップスクリプトが一覧表示するアドレスを、スクリプトと同様にポリシーで許可します。 |
| トークンまたはキーの有効期限が切れた、または無効になった | 新しいトークンを作成するか、キーペアに切り替えます。 |
| Unity Catalog がサービスプリンシパルのアクセスを拒否した | カタログに対する `USE CATALOG`、`CREATE SCHEMA`、`USE SCHEMA` を付与します。 |
| PlaidCloud がサインインできなかった | ユーザーまたはサービスプリンシパルと、そのキー、トークン、シークレットを確認します。 |
| PlaidCloud がウェアハウスに到達できなかった | URL を確認し、ネットワークポリシーや IP アクセスリストで PlaidCloud のアドレスを許可します。 |
| プライベートエンドポイントやカスタムエンドポイントはサポートされていない | アカウントのパブリック URL を使用します。 |

## Snowflake または Databricks でサインインする

キー、シークレット、トークンを貼り付ける代わりに、管理者はサインインしてウェアハウスをアタッチできます。これにより、各ユーザーが自分の Snowflake または Databricks の ID でサインインするため、ダッシュボードとクエリは、お客様のウェアハウスでそれぞれのユーザー自身の権限で実行されます。

### 管理者が最初に行う設定

ご自身のアカウントで、アカウント管理者が PlaidCloud をサインインアプリケーションとして一度だけ登録します。接続ダイアログ（**自分のウェアハウスを使用する**、または**ウェアハウスの管理**から開いた場合は**ウェアハウスを追加**）には、PlaidCloud のリダイレクト URL を含め、使用する正確なテキストが表示されます。

- **Snowflake。** ダイアログに表示される `CREATE SECURITY INTEGRATION` ステートメントを実行し、`SELECT SYSTEM$SHOW_OAUTH_CLIENT_SECRETS` ステートメントの結果から `OAUTH_CLIENT_ID` をコピーします。
- **Databricks。** アカウントコンソールの **Settings > App connections** で、`PlaidCloud` という名前のアプリを追加します。ダイアログに表示されるリダイレクト URL と、すべての API へのアクセスを設定し、**Generate a client secret** はオフのままにして、そのクライアント ID をコピーします。

### ウェアハウスをアタッチする

1. **Quickest: sign in with Snowflake**（または Databricks）で、**アカウント URL**（または**ワークスペース URL**）と**クライアントID**を入力します。
2. Snowflake では、**データベース**と **PlaidCloud 用のデータ ロール**を入力します。**ウェアハウス**は省略可能で、デフォルトではお客様のものが使用されます。Databricks では、**SQL ウェアハウスの HTTP パス**を入力します。**カタログ**は省略可能で、デフォルトではお客様のものが使用されます。
3. **Sign in with Snowflake** または **Sign in with Databricks** を選択し、ベンダーのアカウントにサインインして承認します。

PlaidCloud に戻ると、ウェアハウスがもう一度チェックされます。チェックに成功すると、新しいウェアハウスが選択された状態で**お使いのウェアハウス**が開きます。不足しているものがある場合は、ウィンドウが開いたままになり、修正が必要な項目と、コピーできる不足している付与が一覧表示されます。

PlaidCloud は、お客様のアカウント内に、このウェアハウス専用の独自のサービス ID を作成します。ワークフロー、スケジュール、その他、操作する人がいない処理は、この ID として実行されます。

- **Snowflake。** PlaidCloud は、指定したデータロールのみを持つキーペア付きの新しいサービスユーザーを作成します。ロールは単純なデータロールである必要があります。次のようなロールは、PlaidCloud が拒否します。サインインに使用したロールそのもの、`ACCOUNTADMIN`、`SECURITYADMIN`、`USERADMIN`、`SYSADMIN`、`ORGADMIN` のいずれかであるか、これらを継承しているロール、`CREATE USER`、`CREATE ROLE`、`MANAGE GRANTS`、`CREATE INTEGRATION`、`CREATE NETWORK POLICY` を持つロール、ユーザーを所有しているロールです。ロールには、セットアップスクリプトの `APPLY ROW ACCESS POLICY`、`APPLY MASKING POLICY`、`APPLY PROJECTION POLICY`、`APPLY AGGREGATION POLICY`、`APPLY JOIN POLICY`、`APPLY TAG` の付与を含めることができます。これらは、再構築したテーブルがポリシーを維持するために必要です。PlaidCloud は、既存の Snowflake ユーザーの再利用も拒否します。サインインに使用するロールには、ユーザーを作成し、データロールを付与する権限が必要です。
- **Databricks。** PlaidCloud は、SQL ウェアハウスへのアクセスと、カタログのデータ権限のみを持つ新しいサービスプリンシパルを作成します。PlaidCloud がサービスプリンシパルを作成できるように、ワークスペース管理者としてサインインしてください。

サービス ID に必要な権限が不足している場合でも、ウェアハウスはサインインしたユーザー向けにアタッチされ、不足している権限を示す警告が表示されます。管理者が再度サインインするまで、ワークフローの実行は同じ理由で拒否されます。

### 全員がサインインする

ワークスペースにサインインで接続したウェアハウスがある場合、すべてのメンバーのユーザーメニューに**ウェアハウスにサインイン**が表示されます。これを選択し、**Sign in with Snowflake** または **Sign in with Databricks** を選択します。PlaidCloud はサインイン状態を維持します。サインインせずに開いたダッシュボードや、サインインの有効期限が切れた後に開いたダッシュボードには、*Sign in with Snowflake to view this dashboard: in PlaidCloud, open your user menu and choose Sign in to your warehouse.*（または *Databricks*）と表示されます。このメニュー項目から再度サインインしてください。

このようなウェアハウス上のダッシュボードは、閲覧者自身のウェアハウス上の権限で実行されます。サインインしていない閲覧者には、*Sign in with Snowflake to view this dashboard: in PlaidCloud, open your user menu and choose Sign in to your warehouse.* と表示されます。

## Databricks の要件

- **公開 URL のワークスペース。** アドレスの規則については、[接続](#2-接続する)を参照してください。
- **Unity Catalog** と、PlaidCloud がスキーマを作成できるカタログ。マネージドストレージのないカタログは `CREATE SCHEMA` を拒否し、権限を付与しても解決しません。レガシーの `hive_metastore` カタログにはボリュームがないため、そこではプロジェクトへのファイルのインポートが失敗し、Databricks 接続へのプッシュは行ごとに実行されます。
- **SQL ウェアハウス。** **サーバーレス** SQL ウェアハウスをお勧めします。停止中のクラシック SQL ウェアハウスは起動に数分かかり、停止後の最初の接続確認やクエリはその起動を待つことになりますが、サーバーレス SQL ウェアハウスははるかに早く使用可能になります。
- **ワークスペースとメタストアの管理者**が、セットアップスクリプトの実行に必要です。アプリ接続の追加にはアカウント管理者が、サインインにはワークスペース管理者が必要です。

PlaidCloud は、お客様のウェアハウスとそのダッシュボードについては User-Agent `PlaidCloud_Lakehouse` で、ワークフローで使用される Databricks 接続については `PlaidCloud_Connector` で、Databricks に対して自身を識別させます。テナント名、組織名、ユーザー名が含まれることはありません。

## Databricks のサインイン方法

PlaidCloud が Databricks にアクセスする方法は 3 つあります。ウェアハウスを追加するときに、いずれかを選択します。

| 方法 | 使用する場合 | 更新 |
|---|---|---|
| Databricks でサインイン（OAuth U2M） | 各ユーザーのダッシュボードとクエリを、そのユーザー自身の Databricks 権限で実行したい場合 | PlaidCloud がサインインを最新の状態に保ちます |
| サービスプリンシパルの OAuth シークレット（OAuth M2M） | ワークフローとダッシュボードを 1 つのサービスプリンシパルとして実行したい場合 | PlaidCloud は、古いアクセストークンの有効期限が切れる前に新しいトークンを発行します |
| パーソナルアクセストークン | どちらの OAuth 方式も使用できない場合 | トークンはその日付に期限切れとなるため、新しいトークンを追加します |

### Databricks でサインインする

PlaidCloud は、OAuth 認可コードフローと PKCE を使用してサインインします。

1. アカウント管理者として、**Account console > Settings > App connections** を開き、`PlaidCloud` という名前のアプリを追加します。接続ダイアログに表示されるリダイレクト URL と、すべての API へのアクセスを設定し、**Generate a client secret** はオフのままにします。すべての API へのアクセスが必要です。PlaidCloud は管理者のサインインを使用してサービスプリンシパルを作成し、その後サインインするユーザーには `sql` スコープのみが付与されます。
2. アプリのクライアント ID をコピーします。
3. PlaidCloud で、ユーザーメニューを開き、**ウェアハウスの管理**を選択して、**ウェアハウスを追加**を選択し、**Databricks** を選択します。
4. **最速: Databricks でサインイン** で、**ワークスペース URL**、**クライアントID**、**SQL ウェアハウスの HTTP パス**を入力します。**カタログ**は省略可能です。
5. **Databricks でサインイン**を選択し、Databricks ワークスペース管理者としてサインインして承認します。PlaidCloud は、ワークフロー用に独自のサービスプリンシパルを作成します。[ウェアハウスをアタッチする](#ウェアハウスをアタッチする)を参照してください。

### サービスプリンシパルの OAuth シークレット

1. PlaidCloud で**ウェアハウスの管理**を開き、**ウェアハウスを追加**を選択して、**Databricks** を選択します。
2. ワークスペースとメタストアの管理者として、ダイアログのセットアップスクリプトを実行します（[最初にセットアップスクリプトを実行する](#1-最初にセットアップスクリプトを実行する)を参照）。サービスプリンシパル、SQL ウェアハウス、カタログが作成されます。または、自分でサービスプリンシパルを作成し、Databricks でそのサービスプリンシパル用の OAuth シークレットを生成して、[Databricks の最小権限](#databricks-の最小権限)に示す権限を付与します。
3. **2. 接続する**で、**ワークスペース URL**、**SQL ウェアハウスの HTTP パス**、**アプリケーション ID**（サービスプリンシパルのアプリケーション ID）、**OAuth シークレット**を入力します。
4. **接続をテスト**を選択し、続いて**自分のウェアハウスとして使用**を選択します。

PlaidCloud は、トークンを発行する際に `all-apis` スコープを要求します。

### パーソナルアクセストークン

1. Databricks で、[Databricks の最小権限](#databricks-の最小権限)に示す権限を持つユーザーまたはサービスプリンシパル用に、パーソナルアクセストークンを作成します。
2. PlaidCloud で**ウェアハウスの管理**を開き、**ウェアハウスを追加**を選択して、**Databricks** を選択します。
3. **2. 接続する**で、**ワークスペース URL** と **SQL ウェアハウスの HTTP パス**を入力します。
4. **詳細設定: 代わりにパーソナルアクセストークンを使用する**を選択し、トークンを**トークン**に貼り付けます。**アプリケーション ID** と **OAuth シークレット**は不要です。
5. **接続をテスト**を選択し、続いて**自分のウェアハウスとして使用**を選択します。

トークンはその日付に期限切れとなり、新しいトークンを追加するまで PlaidCloud はお客様のウェアハウスにアクセスできなくなります。更新バナーについては、[接続](#2-接続する)を参照してください。

## Databricks の最小権限

これらの権限を、サービスプリンシパル（パーソナルアクセストークンの場合はユーザー）に付与します。**接続をテスト**は、ウェアハウスをアタッチするための権限を確認し、不足している権限をそのまま実行できる `GRANT` ステートメントとして一覧表示します。ボリュームの権限が不足している場合は、インポートまたはプッシュの実行時にのみ表示されます。

| 目的 | 付与する権限 |
|---|---|
| ウェアハウスをアタッチする | カタログに対する `USE CATALOG`、`CREATE SCHEMA`、`USE SCHEMA`、および SQL ウェアハウスに対する `CAN_USE` |
| テーブルのクエリと書き込み | プロジェクトのスキーマに対する `USE SCHEMA`、`SELECT`、`MODIFY`、`CREATE TABLE`、および SQL ウェアハウスに対する `CAN_USE` |
| ファイルとドキュメントのインポート（プロジェクトのスキーマ内の `plaid_import` ボリューム） | スキーマに対する `CREATE VOLUME`、または管理者が作成した `plaid_import` ボリュームに対する `READ VOLUME` と `WRITE VOLUME` |
| ワークフローから Databricks 接続へのテーブルのプッシュ（対象スキーマ内の `plaid_export` ボリューム） | 対象に対する `USE CATALOG` と `USE SCHEMA`、対象テーブルに対する `MODIFY`（ステップがテーブルを作成する場合は、スキーマに対する `CREATE TABLE` も）、およびスキーマに対する `CREATE VOLUME`、または管理者が作成した `plaid_export` ボリュームに対する `READ VOLUME` と `WRITE VOLUME` |

プッシュでは、各バッチを Parquet ファイルとしてボリュームにステージングし、ANSI モードをオンにして `COPY INTO` でロードします。そのため、列に収まらない値は `NULL` になるのではなく、ステップが失敗します。ボリュームの権限がない場合、プッシュは行ごとの `INSERT` ステートメントにフォールバックします。これははるかに低速で、ステップは警告を表示し、追加すべき権限を示します。`hive_metastore` カタログでは、プッシュは常に行ごとに実行され、警告は表示されません。

## Databricks に関する留意点

- **ファイルとドキュメントのインポートにはサービスプリンシパルが必要です。** サービスプリンシパルなしでサインインによりアタッチされたウェアハウス（SQL のみのアタッチ）では、インポートは停止し、ワークスペース管理者が Databricks に再度サインインしてサービスプリンシパルを追加する必要があることが表示されます。
- **ダッシュボードは、アップグレード後に一度だけ再登録されます。** Databricks のダッシュボード接続は、それぞれ PlaidCloud の User-Agent で一度だけ再登録されます。お客様が行う操作はありません。
- **ウェアハウスを削除しても、Databricks でのサインインを取り消すことはできません。** PlaidCloud が保持している、ユーザーのサインイントークンを取り消す方法は、Databricks のドキュメントにありません。PlaidCloud はそのコピーを削除し、それぞれが唯一のものである場合はサービスプリンシパルのシークレットとパーソナルアクセストークンも削除しますが、サインイントークン自体は Databricks で有効なままです。PlaidCloud が作成したサービスプリンシパルは削除されないため、Databricks で削除してください。サインインを終了するには、**Account console > Settings > App connections** で `PlaidCloud` アプリ接続を削除してください。

## ウェアハウスを管理する

ワークスペース管理者は、ユーザーメニューを開いて**ウェアハウスの管理**を選択します。**お使いのウェアハウス**ウィンドウには、各ウェアハウスの**名前**、**エンジン**、**ステータス**、**デフォルト**、**プロジェクト**が一覧表示されます。ワークスペースに Snowflake または Databricks のウェアハウスがない間は、一覧の上のカードに**PlaidCloud のウェアハウスを使用しています - ご自身のウェアハウスを持ち込めます**と表示されます。

ツールバーの**ウェアハウスを追加**は、接続時と同じフローを、**ウェアハウスを追加**というタイトルで開きます。お客様のウェアハウスが追加され、新規プロジェクトのデフォルトは変わりません。

それ以外の操作は、ウェアハウスを選択し、その行の先頭にある ⋯、右クリックメニュー、または**アクション**から選びます。各項目は、該当する場合にのみ表示されます。

| アクション | 動作 |
|---|---|
| **詳細** | [ウェアハウスの詳細](#ウェアハウスの詳細)を開きます。 |
| **デフォルトに設定** | ワークスペースがこのウェアハウスに切り替わると（通常は数分かかります）、新規プロジェクトがこのウェアハウスを使用します。すでに作成済みのプロジェクトは、作成時のウェアハウスのままです。**アクティブ**なウェアハウスのみデフォルトにできます。 |
| **名前の変更…** | ウェアハウスの名前を変更します。 |
| **サインインを更新…** | サインインでアタッチしたウェアハウスの場合: Snowflake または Databricks に再度サインインします。 |
| **認証情報をローテーション…** | キーペア、トークン、OAuth シークレットの場合: 新しいものを貼り付けます。PlaidCloud はまずお客様のウェアハウスに対して確認し、確認に成功した場合にのみ現在のものを置き換えます。 |
| **無効にする…** | ウェアハウスを一時停止します。確認画面には、そのウェアハウスを使用しているプロジェクトの数が表示されます。それらのプロジェクトは、再び有効にするまで一時停止され、データは保持されます。デフォルトのウェアハウスは無効にできません。 |
| **有効にする** | 無効にしたウェアハウスを再び有効にします。 |
| **削除** | ウェアハウスを切断します。ウェアハウスがデフォルトではなく、使用しているプロジェクトがない場合にのみ機能します。そうでない場合は、その理由が表示されます。 |

**ステータス**は、各ウェアハウスの状況を示します。

| ステータス | 意味 |
|---|---|
| **プロビジョニング** | PlaidCloud がウェアハウスをまだ設定中です。 |
| **切り替え中…** | 変更は保存され、ワークスペースに向かっています。 |
| **アクティブ** | 使用できます。 |
| **無効** | このウェアハウスを使用するプロジェクトは、再び有効にするまで一時停止されます。 |
| **注意** | 前回のチェックに失敗したか、個人用アクセストークンの有効期限が 14 日以内に切れます。理由は[ウェアハウスの詳細](#ウェアハウスの詳細)に表示されます。 |

<Aside type="note">新しいウェアハウス、新しいデフォルト、新しい名前、ウェアハウスの無効化などの変更がワークスペースに届くまで、数分かかります。各ワークスペースは他のワークスペースから分離されて実行され、構成の変更を自動的に取り込みます。そのため、変更が届くまでは、ウェアハウスに**切り替え中…** ステータスが表示され、新しいウェアハウスはプロジェクトでまだ使用できません。一覧は最大 10 分間、数秒ごとに再確認し、その後は**まだ反映されていません。後でもう一度更新してください。** メッセージを表示します。1 時間経っても変更が届かない場合は、PlaidCloud サポートにお問い合わせください。</Aside>

ウェアハウスを削除すると、PlaidCloud はお客様のアカウント内のその資格情報を取り消し、保持していたそのコピーを削除します。Snowflake では、すべてのサインインとサービス ID が含まれます。Databricks では、サービスプリンシパルのシークレットは含まれますが、ユーザーのサインインは含まれません（[Databricks に関する留意点](#databricks-に関する留意点)を参照）。データはお客様のウェアハウスに残ります。資格情報を取り消せない場合は、お客様のアカウントで自分で取り消すよう PlaidCloud が案内します。

### サンプルを実行する

サインインでアタッチした後などに、特定のウェアハウスで**お使いのウェアハウス**が開き、そのウェアハウスがデフォルトで**アクティブ**の場合、次のメッセージが表示されます。**ウェアハウスの準備ができました。サンプルを実行して動作を確認してください。** ここで**サンプルを実行**を選択すると、まず**サンプルデータを削除しますか?** ダイアログが表示されます。これは、以前のウェアハウスで実行されたシード済みのサンプルプロジェクトを完全に削除しますが、お客様自身のプロジェクトとデータには影響しません。その後、新しいサンプルを読み込み、お客様のウェアハウスで実行します。進行状況はワークフローで確認できます。お客様自身が変更を加えたサンプルプロジェクトは置き換えられず、何も実行されません。

## ウェアハウスの詳細

ウェアハウスで**詳細**を選択すると、**ウェアハウスの詳細**が開きます。

| 行 | 表示内容 |
|---|---|
| **ステータス** | ウェアハウスのステータスです。**アクティブ**でない場合は、**理由**がその内容を説明します。たとえば、失敗したチェックで見つかった問題とその対処方法や、トークンの有効期限の日付です。 |
| **エンジン** | Snowflake または Databricks。 |
| **ホスト** | ウェアハウスのアドレス（一部がマスクされます）。 |
| **勘定科目** | お客様の Snowflake または Databricks のアカウント（PlaidCloud が把握している場合）。 |
| **認証** | **キーペア**、**個人用アクセストークン**、**サービスプリンシパル**、**ベンダーでサインイン済み**。 |
| **トークンの有効期限** | 個人用アクセストークンの場合: 有効期限の日付と、**認証情報をローテーション…** ボタン。 |
| **前回のチェック** | ウェアハウスが最後にチェックされた日時と、チェックの結果が**OK**か**失敗**か。 |
| **プロジェクト** | このウェアハウスを使用しているプロジェクトの数。 |
| **接続** | ワークスペースがウェアハウスに到達する方法。[直接接続](#直接接続)を参照してください。 |

**今すぐ確認**は、PlaidCloud が保持している認証情報を使って Snowflake または Databricks のウェアハウスをもう一度チェックし、結果を**前回のチェック**として記録します。問題がなければ次のように表示されます。**PlaidCloud に必要なものはすべて揃っています。** 問題がある場合は、その内容と対処方法が表示されます。付与が不足している場合は、ウェアハウスで実行するステートメントとして一覧表示され、[確認して使用する](#3-確認して使用する)と同様に、それぞれに**コピー**と**完了**が付きます。それらを実行してから、もう一度**今すぐ確認**を選択します。

変更が反映中の間や直接接続の設定中は、ウィンドウを開いてから、または接続をリクエストしてから最大 10 分間、ウィンドウが自動的に最新の状態に保たれます。その後は、**お使いのウェアハウス**を更新（F5）して、もう一度**詳細**を選択してください。

## 直接接続

[ウェアハウスの詳細](#ウェアハウスの詳細)の**接続**行は、ワークスペースがウェアハウスにどのように到達するかを示します。PlaidCloud は、ウェアハウスが動作している場所をそのアドレスから読み取ります。Snowflake のアカウントロケーターのアドレス（例: `xy12345.us-east-2.aws.snowflakecomputing.com`）はクラウドとリージョンを示し、Databricks のアドレスはクラウドのみを示し、Snowflake の組織アカウントのアドレスはどちらも示しません。

| 接続 | 意味 |
|---|---|
| **同じクラウドとリージョン** | ウェアハウスは、ワークスペースと同じクラウドおよびリージョンで動作しています。 |
| **公共のインターネット** | ウェアハウスは別のクラウドまたはリージョンで動作しています。クエリは公共のインターネットを経由するため、応答時間とエグレス料金が発生します。 |
| **プライベート - 直接リンク** | ワークスペースは、AWS PrivateLink、Azure Private Link、Google Private Service Connect などのプライベートリンクを介してウェアハウスに到達し、クエリは公共のインターネットを経由しません。 |
| **検出されません** | PlaidCloud は、ウェアハウスが動作している場所を判断できませんでした。 |

直接接続は、ワークスペースとウェアハウスの間の公共の経路をプライベートな経路に置き換えます。ワークスペースと同じクラウドおよびリージョンにあるウェアハウス向けです。

### 直接接続をリクエストする

**直接接続をリクエスト**は、ワークスペースのプランにプライベート接続が含まれ、ウェアハウスが有効な Snowflake または Databricks のウェアハウスで、未処理のリクエストがない場合に、**ウェアハウスの詳細**に表示されます。リクエストできるのはワークスペース管理者のみです。選択すると、**接続**行がリクエストの状況に従って変わります。

| 接続 | 意味 |
|---|---|
| **リクエスト済み** | PlaidCloud がリクエストを受け取り、設定を開始します。 |
| **設定中** | PlaidCloud がプライベート接続を設定しています。 |
| **ウェアハウス管理者の対応待ち** | 接続を完了するには、ウェアハウスのアカウントでいくつかの手順が必要です。 |
| **プライベート - 直接リンク** | 接続はチェック済みで、使用されています。 |
| **要対応** | プライベート接続が機能していません。手順を確認するか、PlaidCloud にお問い合わせください。 |

直接接続がチェックに合格するまで、ワークスペースはこれまでと同じ方法でウェアハウスに到達し続けます。PlaidCloud がチェックしている間、この行には**接続を確認しています…** ステータスが表示されます。PlaidCloud がウェアハウスを公共の経路に戻した場合、この行にはウェアハウスへの到達方法が再び表示され、**直接接続をリクエスト**が再び利用可能になります。

### ウェアハウスアカウントでの手順

接続の設定中、または対応が必要な間は、**接続**行の横にある**手順を表示**から、ウェアハウス管理者向けの手順が番号付きで開きます。実行する正確なテキストと、テキストがある手順には**コピー**が表示されます。PlaidCloud の対応を待つ手順には、PlaidCloud が入力するまでその旨が表示されます。実行し終えたら、PlaidCloud の担当者にお知らせください。

| エンジン | 手順で求められる内容 |
|---|---|
| Snowflake | Business Critical エディション以上。`ACCOUNTADMIN` として実行する、PlaidCloud のプライベートエンドポイントを承認するステートメント。PlaidCloud が切り替える前に行う、セットアップスクリプトが作成したネットワークポリシーの変更: プライベートエンドポイント用のネットワークルールを追加し、PlaidCloud の公開アドレスを専用のルールに移します。ネットワークルールを持つポリシーは、IP リストを読まなくなるためです。これらのステートメントは再実行しても安全です。 |
| Databricks | プライベート接続に必要なティアのワークスペース（AWS では Enterprise、Google Cloud では Premium、Azure では Premium かつ VNet インジェクション済み）。アカウントコンソールでワークスペースに PlaidCloud のエンドポイントを登録するか、Azure ではワークスペースの Networking タブで PlaidCloud の保留中のプライベートエンドポイント接続を承認します。PlaidCloud のアドレスに対するパブリックアクセスはオンのままにして、プライベートアクセス設定で PlaidCloud をプライベートに許可します。 |

<Aside type="note">PlaidCloud のコントロールプレーンは、サインイン、設定、切断のために、引き続きパブリックアドレスでウェアハウスに到達します。手順に従い、セットアップスクリプトのアドレスに対するパブリックアクセスはオンのままにしてください。</Aside>

## 実行ごとのウェアハウスコスト

自分のウェアハウスでは、変換された Alteryx ワークフローの実行履歴に**ウェアハウスコスト**列が表示され、[移行を検証する](/ja/guides/workflows/validate-converted-alteryx-workflows/#移行を検証する)ウィンドウには、前回の実行のコストと次回の実行の見積もりが表示されます。コストの単位は、Snowflake ではクレジット、Databricks では DBU です。

| ラベル | 意味 |
|---|---|
| *attributed* | Snowflake がこれらのクレジットを実行のクエリに課金したものです。`GOVERNANCE_VIEWER` の付与を通じて読み取ります。帰属情報は、Snowflake のレポート遅延の後に表示されます。 |
| *estimated* | クエリの実行時間とウェアハウスのサイズから計算され、先頭に ≈ を付けて表示されます。Databricks では常にこの表示になります。Snowflake では、帰属情報が届く前や、付与がない場合にこの表示になります。 |

コストには、PlaidCloud のエンジンが実行したステップが含まれます。一部のみ算出された実行には *partial* と表示され、コストがまだ報告されていない実行にはその旨が表示されます。

## ポリシーと説明が引き継がれる

PlaidCloud で設定したスキーマ、テーブル、列の説明は、お客様のウェアハウス独自のカタログにコメントとして書き込まれます。Snowflake の行アクセス、マスキング、プロジェクション、集計、結合の各ポリシーと、Databricks の行フィルターおよび列マスクは、PlaidCloud がテーブルを置き換え、再作成、またはクローンしても、そのまま維持されます。ポリシーを引き継げない場合、PlaidCloud はテーブルを元の状態のままにし、メッセージにポリシーと理由が示されます。

## プロジェクトを自分のウェアハウスにバインドする

ワークスペースにウェアハウスが接続されると、**新規プロジェクト**ダイアログ（**Analyze > Projects > 新規プロジェクト**）にレイクハウスピッカーが表示されます。**テナントのデフォルト**を選択するか、特定のウェアハウスを選択します。**テナントのデフォルト**は、いずれかのウェアハウスがデフォルトになっていない限り組み込みの PlaidCloud Lakehouse です。ウェアハウスがデフォルトの場合は、新規プロジェクトが自動的にそこに作成されます。デフォルトを設定するには、[ウェアハウスを管理する](#ウェアハウスを管理する)で**デフォルトに設定**を選択するか、**ウェアハウスを追加**から開いていないダイアログで**自分のウェアハウスとして使用**を選択します。この設定の影響を受けるのは、その後に作成されるプロジェクトのみです。既存のプロジェクトは、作成時のバックエンドのままです。以降は次のようになります。

- プロジェクトのワークフローが作成、ロード、変換するすべてのテーブルが、お客様のレイクハウスで作成され、書き込まれます。
- ステップ、ビュー、ダッシュボードでの読み取りは、お客様のウェアハウスに対するクエリとして実行されます。
- PlaidCloud Lakehouse には何もコピーされません。データはお客様のアカウント内に残ります。

ワークフローは、組み込みのレイクハウスの場合とまったく同じように構築できます。インポート、変換、結合、公開の各ステップは、すべて同じように動作します。バックエンドはプロジェクトの作成時に設定され、プロジェクト全体に適用されます。

## レイクハウスにバインドされたプロジェクトへのファイルのインポート

レイクハウスにバインドされたプロジェクトに CSV、Parquet、XML、Access のファイルをインポートすると、外部クラウドバケット経由でファイルをステージングする代わりに、ウェアハウス独自の**ネイティブな並列バルクロードパス**でロードされます。Snowflake では内部ステージと `COPY INTO`、Databricks ではマネージドボリュームと `COPY INTO` を使用します（[Databricks の最小権限](#databricks-の最小権限)を参照）。追加のクラウド IAM を構成する必要はなく、ウェアハウスがどのクラウドで動作していても同じように機能します。

## クエリとテーブルの結果のエクスポート

レイクハウスにバインドされたプロジェクトからクエリまたはテーブルの結果をエクスポートすると、すべての行を PlaidCloud 経由で戻すのではなく、クラウドストレージに直接配信されます。

- **Snowflake** — エクスポートは Snowflake のサーバーサイドアンロード（ステージへの `COPY INTO`）として実行されるため、ウェアハウスが結果をストレージに直接書き込みます。大きなエクスポートは、自動的に複数のファイルに分割されます（以前は、Snowflake の単一ファイル上限を超えるエクスポートは失敗していました）。
- **Databricks** — エクスポートは Databricks のサーバーサイドアンロード（Unity Catalog のマネージドボリュームへの `INSERT OVERWRITE DIRECTORY`）として実行されるため、ウェアハウス自身が結果の書き込みとエンコードを行い、PlaidCloud は完成したファイルをストレージに中継するだけです。大きなエクスポートは自動的に複数のファイルにまたがって出力され、CSV は gzip 圧縮で配信することもできます。

## レイクハウスデータに対するダッシュボード

ダッシュボードは、両方のエンジンで動作します。

- **Databricks** — ダッシュボードは、サービスプリンシパルの OAuth 資格情報（または個人用アクセストークン）を使用して、Databricks ドライバー経由で接続します。[サインイン](#snowflake-または-databricks-でサインインする)でアタッチしたウェアハウスでは、各閲覧者のダッシュボードが閲覧者自身の Databricks ID で実行されます。
- **Snowflake** — ダッシュボードは、ウェアハウスのサービスユーザーとキーペアを使用して接続します。[サインイン](#snowflake-または-databricks-でサインインする)でアタッチしたウェアハウスでは、代わりに各閲覧者のダッシュボードが閲覧者自身の Snowflake ID で実行されます。プロジェクトのダッシュボードは、プロジェクトの作成時または公開時にセットアップされます。

## PlaidCloud にウェアハウスを登録してもらう

ウェアハウスを自分で接続する必要はありません。接続するエンジンに応じて、以下の詳細を PlaidCloud の担当者にお伝えください。管理者が代わりに登録します。

### Snowflake

| フィールド | 提供する内容 |
|---|---|
| ホスト名 | Snowflake アカウントのホスト。 |
| スーパーユーザー | PlaidCloud が認証に使用する Snowflake ユーザー。 |
| データベース | PlaidCloud がプロジェクトのスキーマを作成して管理するデータベース。 |
| ウェアハウス | PlaidCloud がクエリを実行するコンピューティングウェアハウス。 |
| ロール | PlaidCloud が使用する Snowflake ロール。 |
| 秘密鍵 | キーペア認証用の、**暗号化されていない生の** PEM 秘密鍵。base64 エンコードしたコピーではなく、鍵のテキストそのものを貼り付けてください。パスフレーズで保護された鍵はまだサポートされていません。 |

秘密鍵を渡す前に、キーペアを生成し、公開鍵を Snowflake のスーパーユーザーに割り当ててください。ロールには、対象データベースでテーブルを作成、読み取り、書き込みできる権限が必要です。

### Databricks

| フィールド | 提供する内容 |
|---|---|
| ホスト名 | Databricks ワークスペースの URL。 |
| HTTP パス | PlaidCloud がクエリを実行する SQL ウェアハウスの HTTP パス。 |
| Unity Catalog | PlaidCloud がプロジェクトのスキーマを作成して管理する Unity Catalog のカタログ。 |
| 個人用アクセストークン | 認証用の Databricks PAT。 |

トークンの ID には、そのカタログでテーブルを作成、読み取り、書き込みできる権限が必要です。

どちらの登録でもスキーマは求められません。各プロジェクトには、プロジェクトがレイクハウスにバインドされる際に、その DSN から自動的に導出された独自のスキーマが割り当てられます。

登録フォームには**接続をテスト**ボタンがあり、入力した詳細で実際に接続を開き、成功または失敗の理由を報告します。何も保存されないため、レイクハウスを登録する前に資格情報を確認できます。Snowflake のテストには、暗号化されていない生の PEM 秘密鍵が必要です（パスフレーズで保護された鍵は未サポートと報告されます）。Databricks のテストでは PAT を使用します。

登録したウェアハウスは、保存した直後には使用できません。ご自身で追加するウェアハウスと同じ理由で、**お使いのウェアハウス**に数分間**切り替え中…** と表示されます（[ウェアハウスを管理する](#ウェアハウスを管理する)を参照）。

<Aside type="note">Iceberg/Lakekeeper カタログ接続は別途登録するもので、省略可能です。Snowflake または Databricks のウェアハウスを使用するために必須ではありません。</Aside>
