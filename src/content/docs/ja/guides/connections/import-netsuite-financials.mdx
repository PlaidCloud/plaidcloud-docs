定型の NetSuite インポートステップを使うと、SuiteQL を書かなくても、よく使う NetSuite の財務データと参照データをプロジェクトのテーブルに取り込めます。ほとんどの取得は、3 つのステップでカバーできます。試算表の取得には**残高のインポート**、その元になる転記レベルの明細には **GL明細のインポート**、これらが参照する勘定科目、子会社、ディメンションには**マスターデータのインポート**を使用します。各ステップは共通の読み取りレイヤーで実行され、OAuth トークンの更新、大きな結果のページング、一時的なエラーの再試行が行われるため、全期間または全子会社の取得でも結果が漏れなく返されます。

<Aside type="tip">
定型ステップでカバーされない個別の取得には、[REST リクエストステップ](/ja/guides/workflows/rest-request-step/)で独自の SuiteQL を記述します。[NetSuite SuiteQL クエリの例](/ja/guides/connections/netsuite-financial-queries/)を参照してください。一般的な取得には、以下の定型ステップのほうが簡単です。
</Aside>

## 前提条件

- 読み取るレコードの表示アクセス権を持つ、動作する [NetSuite 接続](/ja/guides/connections/netsuite/)。
- ステップを追加するワークフロー。

## 試算表を取得する

<Steps>

1. ワークフローに **NetSuite: 残高のインポート**ステップを追加します。

2. **NetSuite接続**に接続を、**ターゲットテーブル**に残高を取り込むプロジェクトのテーブルを設定します。ステップは、実行のたびにこのテーブル全体を上書きします。

3. **開始日**と**終了日**に、取得する期間を `YYYY-MM-DD` 形式で設定します。どちらの日付も範囲に含まれます。どちらかを空白にすると、範囲のその端は無制限になります。

4. 取得を 1 つの子会社に限定するには、**Subsidiary** にその NetSuite 内部 ID を設定します。すべての子会社を対象にするには空白のままにします。（名前しかない場合は、[内部 ID を解決する](#マスターデータで内部-id-を解決する)を参照してください。）

5. マルチブック会計のアカウントでは、**Accounting Book** を空白のままにすると**プライマリブックのみ**が取得されます。これは標準的な試算表の正しいデフォルトです。ブックをまたいだ合計を意図的に取得する場合のみ `all` を設定するか、特定のブックの内部 ID を設定します。

6. 勘定科目表全体や範囲内のすべての期間が不要な場合は、**勘定科目番号**（完全一致する GL 勘定科目）または **Posting Period**（NetSuite の期間内部 ID）でさらに絞り込みます。

7. ステップを実行し（[ワークフロー内の単一ステップの実行](/ja/guides/workflows/running-one-step-in-a-workflow/)を参照）、ターゲットテーブルを確認します。

</Steps>

<Aside type="caution">
**マルチブックのアカウントは、デフォルトでプライマリブックを使用します。** この動作が導入される前は、マルチブック会計のアカウントでフィルターなしで取得すると、すべてのブックが合算され、残高が知らないうちに N 倍に計上されていました。**Accounting Book** を空白のままにすると、標準的な試算表が想定するとおり、プライマリブックのみが取得されるようになりました。以前のブック横断の合計に依存していた場合は、**Accounting Book** に明示的に `all` を設定してください。
</Aside>

## GL 明細を取得する

**NetSuite: GL明細のインポート**ステップは、接続、ターゲットテーブル、日付範囲、子会社、会計ブック、勘定科目番号、会計期間と、同じ方法で設定しますが、期間残高ではなく取引明細の詳細を返します。照合、ドリルダウン、または残高の元になった転記から詳細な損益計算書を再構築する場合に使用します。

<Aside type="note">
日付範囲は、必要なスライスに限定してください。実行のたびにターゲットテーブル全体が置き換えられるため、スケジュールされた GL の取得では毎回全結果が再抽出されます。ローリングの日付ウィンドウを使用すると、全履歴を再読み取りせずに、定期的な取得を高速に保てます。
</Aside>

<Aside type="note">
NetSuite は、1 回の SuiteQL クエリを約 100,000 行に制限しています。**開始日**と**終了日**の両方を指定すると、PlaidCloud が広い範囲の取得を、この上限を超えない小さな日付チャンクに自動的に分割するため、何もしなくても 1 年分の GL の取得が漏れなく返されます。上限を超える規模の取得で両方を空白にした場合は、結果が知らないうちに切り捨てられるのではなく、日付範囲を追加するよう求めるメッセージとともに失敗します。
</Aside>

## マスターデータで内部 ID を解決する

NetSuite の子会社、勘定科目、ディメンションの各フィールドは、名前ではなく内部 ID です。**NetSuite: マスターデータのインポート**で対応するリストを取得し、残高または明細と結合して、読みやすい名前を追加します。

<Steps>

1. **NetSuite: マスターデータのインポート**ステップを追加し、**NetSuite接続**と**ターゲットテーブル**を設定します。

2. **レコードタイプ**に、取得するリストを設定します。**勘定科目**、**子会社**、**部門**、**クラス**、**場所**、**仕入先**、または**顧客**です。

3. アクティブなレコードのみを取得するには **Include Inactive** をオフのままにし、非アクティブなレコードも含めるにはオンにします。

4. ステップを実行し、そのテーブルを残高または GL 明細と内部 ID で結合して、すべての行に名前を付与します。

</Steps>

## 取得をスケジュールする

継続的なフィードにするには、[ワークフローをスケジュール](/ja/get-started/tutorials/schedule-a-workflow/)します。各ステップはターゲットテーブル全体を置き換えるため、スケジュールされた実行では、範囲を指定した期間の NetSuite の最新の状態が常に反映されます。
