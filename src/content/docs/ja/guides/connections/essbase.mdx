PlaidCloudをOracle **Essbase**（21c以降、またはOracle Analytics Cloud）に接続すると、ワークフローから、キューブに対してライブMDXクエリを実行したり、ディメンションアウトラインをPlaidCloudのディメンションとして読み込んだりできます。この接続は、EssbaseのREST API自体に**クラウド直接**で接続します。これらのステップにはオンプレミスのエージェント経路はありません。このガイドでは、接続、クエリの実行、行数の上限とラベル付けを制御するオプション、ディメンション階層の読み込みについて説明します。

<Aside type="note">
このコネクタは読み取り専用です。Essbaseへの書き戻しはありません。
</Aside>

## 前提条件

Essbase管理者から、次のものを入手してください。

- **Essbaseサーバーのオリジン**（例: `https://your-host:9001`）。末尾の`/essbase/...`パスは含めません。
- **サービスアカウント**（ユーザー名とパスワード）。ワークフローがクエリするアプリケーションとキューブへの読み取りアクセスが必要です。

## 接続を作成する

<Steps>

1. **Tools > Connections**を開き、`New Connection`をクリックします。

2. メニューから**Oracle Essbase**を選択します。

3. フィールドを入力します。

   | フィールド | 値 |
   |---|---|
   | 名前 | わかりやすい名前（例: `Essbase Prod`）。 |
   | ベースURL | Essbaseサーバーのオリジン（例: `https://your-host:9001`）。 |
   | デフォルトアプリケーション | 任意。ステップのフォームで、このアプリケーションを事前選択します。 |
   | ユーザー名 | サービスアカウントのユーザー名。 |
   | パスワード | サービスアカウントのパスワード。 |
   | SSLを検証 | デフォルトでオンです。自己署名の証明書など、検証できない証明書を使うホストの場合にのみオフにしてください。 |

4. `Test Connection`をクリックします。テストが成功すると、Essbaseサーバーに到達し、サービスアカウントから見えるアプリケーションを一覧表示して、見つかった数を報告します。クエリを作成する前に、ベースURLと認証情報の両方を確認できます。

5. `Create`をクリックします。

</Steps>

## クエリを実行する

<Steps>

1. ワークフローに**Essbase: キューブのクエリ**ステップを追加します（ステップメニューの**Oracle Essbase**の下にあります）。

2. **構成**で、**接続**、**アプリケーション**、**Cube (Database)**、**ターゲットテーブル**を設定します。

3. **MDX**を作成します。

   - **ガイド付きメンバー選択** — キューブのディメンションとメンバーを参照して、列と行に配置するものを選択します。ステップがMDXを組み立てます。
   - **生のMDX** — 計算メンバーやセット演算子など、ガイド付き選択でカバーされないものについては、MDXの`SELECT`を直接記述または貼り付けます。

4. ステップを実行します。返されたグリッドがターゲットテーブルとして取り込まれ、列はグリッド自体から導出されます。事前にスキーマを宣言する必要はありません。

</Steps>

## オプション

- **メンバーラベルは決定論的です。** メンバーの列ラベルは、接続に構成されたエイリアステーブルから取得され、実行のたびに一貫して適用されます。Essbase自体のセッションごとのデフォルトではないため、クエリの実行時に誰がログインしていたかによってラベルのテキストが変わることはありません。
- **行数の上限のデフォルトは250,000で、引き上げることができます。** 行数の上限が未設定の場合、「無制限」ではなく250,000行の上限が適用されます。有効な上限を超える行数を返すクエリは、制限なしに実行されたり、グリッドが黙って切り捨てられたりするのではなく、行数と上限を示して拒否されます。クエリを絞り込むか、行数の上限を明示的に引き上げて、正当な大規模抽出を通してください。
- **ゼロ抑制はオプトインで、データが失われます。** ゼロ値のセルの抑制は、意図的にオンにするフィルターであり、破壊的なものです。データがまったくないセルを表すEssbase自体の`#Missing`マーカーとは異なり、実際に転記された`0`を保持するセルが破棄されます。プランニングキューブでは、転記されたゼロは誰かが入力したものとして意味があるため、ゼロを抑制すると、データがないという事実だけでなく、実際のデータが失われる可能性があります。結果からゼロを除外したい場合を除き、オフのままにしてください。

## ディメンション階層を読み込む

[Essbase: ディメンションの読み取り](/ja/reference/workflow-steps/essbase/essbase-dimension-read/)ステップは、Essbaseの1つのディメンションのアウトラインを読み取り、PlaidCloudのディメンションのメイン階層に読み込みます。同じ接続を使ったクラウド直接接続です。これはEssbase: キューブのクエリとは別のステップで、キューブのセルではなくアウトライン構造を読み取ります。

このステップは、表現できないものを誤って読み込むのではなく、名前を挙げて拒否します。共有メンバー、ラベルのみのメンバー、Dynamic Calcメンバー、属性ディメンション、`+`/`-`以外の集計演算子（Essbaseの`*`、`/`、`%`にはPlaidCloudに相当するものがありません）、およびアウトラインメンバーの合計が5,000を超えるアウトラインです。完全なリストと各拒否の意味については、[ステップリファレンス](/ja/reference/workflow-steps/essbase/essbase-dimension-read/#このステップで表現できないこと)を参照してください。
