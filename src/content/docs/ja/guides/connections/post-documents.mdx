**伝票を転記** ステップは、1つのテーブル内のドキュメントをERPシステムに転記します。このステップではシステムを指定しません。各ドキュメントは、そのエンティティの転記先のシステムに送られるため、1つのステップで複数のシステムや、同じERPの複数のインスタンスに同時に転記できます。ステップ、ファイル、REST API、MCPツールなど、あらゆる転記方法は同じチェックを経由し、独自の[実行ページ](#実行ページ)を持つ実行として記録されます。

このページでは、ステップとそのテーブルおよび設定、シミュレートと本番、実行ページ、再実行、ファイルや配賦からの転記、SAP転記ステップの変換について説明します。システム自体の設定（どのエンティティをどこに転記するか、本番稼働、保留ルール、各ERPが対応する内容）については、[ERPシステム](/ja/guides/connections/erp-systems/)を参照してください。転記後の確認、承認、取消、決着については、[転記レジスター](/ja/guides/connections/posting-register/)を参照してください。

## 開始する前に

- 転記先のERPは、それぞれPlaidCloudが転記できる接続であり、転記するエンティティとともにシステムとして設定されています。[ERPシステム](/ja/guides/connections/erp-systems/)を参照してください。
- 実際に転記するには、実行が本番で、各ドキュメントのシステムがそのプロジェクトで本番である必要があります。それまでは、すべてチェックされて **転記予定** と表示され、何も送信されません。[シミュレートと本番](#シミュレートと本番)を参照してください。

## ドキュメントが転記される流れ

エンティティと `doc_number` が同じ行は、1つのドキュメントです。実行が開始されると、ドキュメントは固定されます。**これらを転記**、再試行、承認など、実行の後続の操作では、まさにそれらのドキュメントが送信されます。その後、各ドキュメントは同じ段階を順に進み、停止を示す最初の段階で、その理由とともに停止します。

1. バランスとセット：仕訳は、使用する各通貨でバランスしている必要があり、セットは全体としてバランスしている必要があります。[セット](#セット)と、[ステップの設定](#ステップの設定)にある丸めの設定を参照してください。
2. 振り分け：ドキュメントのエンティティによって、[ERPシステム](/ja/guides/connections/erp-systems/)で設定したとおりにシステムが決まります。エンティティにシステムがないドキュメントは、未転記になります。
3. チェック：[5つのチェック](#5つのチェック)が、PlaidCloudがそのシステムについて把握している内容に対して実行されます。
4. 保留：システムの保留ルールまたはステップ自身の保留により、[転記レジスター](/ja/guides/connections/posting-register/)で人が承認するまで、ドキュメントは **承認が必要** のままになります。
5. 送信：ドキュメントはシステム独自の形式に変換されて送信されます。実行またはそのシステムがシミュレートの場合は、**転記予定** として記録されます。

各状態の意味と、それぞれの対処方法については、[転記レジスター](/ja/guides/connections/posting-register/)を参照してください。

## ステップを追加する

ワークフローに **伝票を転記** ステップを追加します。ステップメニューの **外部システム**、およびステップパレットの **外部システム** フォルダーにあります。フォームには3つのセクションがあり、その後にステップの設定用の **詳細 ▸** リンクがあります。

1. **1 · テーブル** — ドキュメントの **テーブル** を選択します。1行が1明細です。最初のドキュメントが作成されると、このセクションには、テーブルから読み取った明細数とドキュメント数が表示されます。
2. **2 · 列の対応付け** — テーブルの各列についてステップが認識した内容です。名前が転記フィールドである列は **名前で一致** になり、名前が既知の別名である列は **別名で一致** になります。ステップが認識できない列にはリストが表示されます。**この列は何ですか?** から、その列が保持するフィールドを選択すると、**これを選択しました** と表示されます。ステップとともに保存されるのは、選択した列のみです。2つの列が同じフィールドを取ることはなく、最初の列がそのフィールドを保持します。
3. **3 · 最初の伝票(システムが受け取る形式)** — テーブルの最初のドキュメントを、振り分けてシステムの形式に変換し、明細とともに表示します。テーブルにない列にシステムが固定値を指定している場合は、その固定値も表示されます（[システム設定](/ja/guides/connections/erp-systems/#システム設定)を参照）。まだ作成できない場合は、未転記の理由と同じ文言で理由が表示されます。

ステップには **テーブル** が必要です。保留金額にチェックを付ける場合、金額は数値である必要があります。丸め明細を追加する場合は、勘定科目が必要です。

## テーブル

テーブルはData Foundationの列名を使用します。Data Foundationの形式の仕訳は対応付けなしで転記され、請求済みの販売明細のテーブルは `account` と `document_type` を追加すると転記されます。1行が1明細で、`entity` と `doc_number` が同じ行は1つのドキュメントです。

| 列 | 保持する内容 |
|---|---|
| `doc_number` | ドキュメントの参照。必須です。この列がないテーブルでは、ステップが停止します。`~` を含めることはできません。PlaidCloudはバージョンの採番に ~ を使用します。 |
| `entity` | ドキュメントが属するエンティティ。システムを決定します。 |
| `posting_date`, `document_date`, `period`, `fiscal_year`, `fiscal_period`, `period_type`, `ledger`, `journal_type` | ドキュメントの日付と期間。 |
| `account` | 明細の勘定科目。 |
| `amount_txn` と `currency_txn` | 明細の金額とその通貨。現地通貨のみのテーブルでは、代わりに `amount_local` と `currency_local` を使用でき、金額の代わりに `debit` と `credit` も使用できます。 |
| `description`, `line_number`, `quantity`, `unit` | 明細のテキスト、順序、数量。 |
| `department`, `profit_center`, `product`, `customer`, `supplier`, `project`, `site`, `trading_partner`, `segment_1` から `segment_10` | 明細のディメンション。 |
| `tax_code`, `tax_amount_local`, `withholding_code`, `withholding_amount_local` | 税と源泉徴収。 |
| `due_date`, `payment_terms`, `supplier_invoice_number`, `purchase_order_number`, `invoice_no` | 請求書の詳細。 |
| `document_type` | `journal`（空白の場合）、`customer_invoice`、`supplier_invoice`、`credit_memo`、`debit_memo`、または `payment`。各システムが受け付けるものについては、[ERPシステム](/ja/guides/connections/erp-systems/)を参照してください。 |
| `set` | セット名。同じセット名を共有するドキュメントは、まとめて転記されるか、まったく転記されません。[セット](#セット)を参照してください。 |

次の別名も、大文字と小文字を区別せずに対応付けられます。`doc_number` には `invoice_number`、`reference`、`journal id`、`posting_date` には `invoice_date`、`amount_local` には `net_amount_local`、`description` には `memo`、`department` には `cost center`、`supplier` には `vendor` です。これらのいずれでもない列（たとえば独自のディメンション）は、ドキュメントとその明細に保持され、それを対応付けるシステム形式で使用されます。

一部の列は転記専用で、まだ利用できません。`action` が `post` 以外の行、または `reverse_on` を設定している行は、未転記になります。実行ページには「これはまだ利用できません。」と表示され、結果テーブルとRESTの応答には「only posting is available yet」または「a date to reverse on is not available yet」というメッセージが含まれます。転記を取消、クレジット、または訂正するには、[転記レジスター](/ja/guides/connections/posting-register/)を使用してください。

ドキュメントは、月ではなく、種類、エンティティ、参照で識別されるため、別の月に移動したドキュメントも同じドキュメントのままです。

### セット

`set` の値を共有するドキュメントは、まとめて転記されるか、まったく転記されません。

- セットは、丸めの上限を許容範囲として、全体でバランスしている必要があります。バランスしていない場合、すべてのメンバーが差額とともに未転記になります。
- いずれかのメンバーがチェックで停止された場合、セットの残りも未転記になり、「セット…の別のドキュメントが転記されませんでした」と表示されます。いずれかのメンバーが承認待ちで保留された場合、セット全体が **承認が必要** のまま待機します。
- いずれかのメンバーのシステムが本番でない場合、セット全体が **転記予定** になるため、一部も実際には送信されません。

## ステップの設定

**詳細 ▸** を開くと、ステップの4つの設定が表示されます。それぞれに初期値があり、ほとんどのステップでは変更する必要がありません。

| 設定 | 初期値 | 内容 |
|---|---|---|
| **担当者の確認待ちにする** | 保留されるものはなし | チェックを付けた条件を満たすドキュメントを、承認待ちとして保留します。 |
| **通知先** | **実行を開始した人** | 要対応のドキュメントがある状態で実行が終了したときに、通知を受け取る人。 |
| **丸め勘定と上限** | 丸めなし | 不均衡の額が上限以下のドキュメントに、丸め明細を追加します。 |
| **転記済み伝票が変更されて戻ってきたとき** | 確認する | 転記後に変更されたドキュメントを、後の実行でどう扱うか。 |

### 担当者の確認待ちにする

ドキュメントを人が承認するまで保留する条件にチェックを付けます。

- **金額が次の値を超える** — 金額。ドキュメント自身の通貨での、ドキュメントの金額と比較されます。
- **異常としてフラグ付けされている**
- **常に**

複数にチェックを付けた場合、ドキュメントが保留されるのはそれらがすべて当てはまるときだけです。何もチェックしない場合、ステップ自身は保留を追加しません。システムの保留ルールや、取消、クレジット、訂正に必要な2人目の担当者による保留は、引き続き適用されます。ステップの保留は、システムにすでにある保留ルールに追加されるだけです。保留されたドキュメントは、セットの残りも保留します。ドキュメントを保留させた送信を行った人と、その実行を開始した人は、そのドキュメントを承認できません。承認と承認者については、[転記レジスター](/ja/guides/connections/posting-register/)と[ERPシステム](/ja/guides/connections/erp-systems/)を参照してください。

### 通知先

初期値は **実行を開始した人** です。**ユーザーのリスト…** を選択すると、代わりに通知するメンバーを指定できます。要対応のドキュメントがある状態で実行が終了したときに、通知されます。

### 丸め勘定と上限

**不均衡な伝票に丸め明細を追加する** にチェックを付け、**勘定科目** と **上限** を指定します。1つの通貨での不均衡が上限以下の仕訳には、その勘定科目への明細が「丸め」という摘要で追加され、合格します。差額がそれより大きい場合や、複数の通貨にわたって差額がある場合は、差額とともに不均衡として停止されます。上限は、セット全体の許容範囲でもあります。この設定のチェックを外すと、丸めは行われません。

### 転記済み伝票が変更されて戻ってきたとき

| 選択肢 | 後の実行が、変更されたドキュメントをどう扱うか |
|---|---|
| **確認する(初期値)。2 つの選択肢とともに「要対応」に入ります。** | 変更されたドキュメントは「転記後にソースが変更されました。」というメッセージとともに未転記になり、[実行ページ](#変更されたドキュメント)で人が **このバージョンで修正** または **転記済みのものを維持** を選択するまで待機します。 |
| **訂正する。取り消して新しいバージョンを転記します。毎期間再実行するステップ向けです。** | 本番の実行では、転記済みのものが取り消され、変更されたドキュメントが次のバージョンとして送信されます。 |

## シミュレートと本番

ドキュメントがシステムに送信されるのは、次の両方が当てはまる場合のみです。

- 実行が本番である：ワークフローの実行には転記モードがあり、プロジェクト自身のモードによって上限が設けられます。詳細は[転記モードを選択する](/ja/guides/workflows/run-a-workflow/#転記モードの選択)を参照してください。シミュレートの実行は何も送信せず、オフの実行はステップをスキップします。
- ドキュメントのシステムが、そのプロジェクトで本番である：これは、システムの接続と環境に対するプロジェクトの書き込み認可があり、プロジェクトのモードが本番になっていることを意味します。[プロジェクトに転記を許可する](/ja/guides/workflows/run-a-workflow/#プロジェクトに転記を承認する)と、[ERPシステム](/ja/guides/connections/erp-systems/)での本番稼働を参照してください。

そうでない場合、ドキュメントはチェックされて **転記予定** として記録され、何も送信されません。シミュレートはシステムに一切接続しません。シミュレートの実行では、システムに問い合わせる必要があるチェックも行われません。ステップには、独自のドライラン設定はありません。唯一の例外は、転記のテストに設定されていたSAP転記ステップから変換されたステップです。これは毎回シミュレートで実行され続け、そのドキュメントは実行ページの **これらを転記** からのみ転記されます。

シミュレートの実行は、転記される内容を正確に確認する方法です。問題なさそうであれば、その[実行ページ](#これらを転記)の **これらを転記** で、固定された同じドキュメントを送信します。

## 5つのチェック

何かが送信される前に、すべてのドキュメントが5つのチェックを通ります。実行ページには、それぞれが合格、不合格、または未確認として表示されます。

| チェック | ドキュメントが停止される条件 |
|---|---|
| Balanced（バランス） | 借方と貸方が一致せず、丸めの上限を超えている。 |
| Period open（期間が未締め） | 転記日がシステム上で締められた期間にある。 |
| Accounts exist（勘定科目が存在する） | システムにない勘定科目、対応のないコード、システムが必要とする値が空、未決済ではない請求書、別の会社、またはシステムが記帳しない通貨。 |
| Not posted before（以前に転記されていない） | すでに別のシステムに転記された、またはすでにこのシステムで使用されている参照。 |
| Sets agree（セットが一致する） | メンバーが欠けている、またはドキュメントの合計が一致しないセット。 |

**Period open** と **Accounts exist** は、本番のシステムへの本番の実行が開始されるときに、PlaidCloudがシステムから読み取るリストを使用します。シミュレートの実行や、リストの読み取りが一部のみ、空、または遅延した場合、これらは未確認として扱われます。[ERPシステム](/ja/guides/connections/erp-systems/)で **今すぐ更新** によって保持されるリストのコピーは表示用であり、チェックには使われません。本番のシステムへの本番の実行では、その形式にシステム独自のチェックがある場合は、それも行われます。シミュレートの実行では行われません。

ドキュメントに対して実行されなかったチェックは、未確認として扱われ、合格として扱われることはありません。実行ページには、5つのチェック名がすべての言語で英語で表示されます。

## ステップが実行されるとき

- ステップは、システムが応答するまで最大10分間待機します。それでも応答がないドキュメントは、記録上では保留のまま次に進み、応答が届くと実行ページが更新されます。
- 実行ログには「n/m件を転記 · k件が要対応」という1行が出力されます。要対応のドキュメントがある場合、ステップは「m件中k件のドキュメントが要対応です」という警告で終了し、**通知先** の担当者に通知されます。ワークフローの残りは続行されます。
- 存在しないテーブル、列がないテーブル、行がないテーブルは警告となり、何も転記されません。`doc_number` の列がないテーブルでは、ステップがエラーで停止します。
- ステップの構成に結果テーブルが指定されている場合、ステップはドキュメントごとに1行をそこに書き込みます。`doc_number`、`action`、`state`、`source_system`（転記先のシステム）、`source_doc`（システムが付与した番号）、`message` です。

## 実行ページ

すべての実行にページがあります。ステップの実行、ファイルの実行、RESTまたはMCPで開始した実行、再試行、取消などです。[転記レジスター](/ja/guides/connections/posting-register/)の **実行回数** から **開く** で開きます。ページには、閲覧できるドキュメントのみが表示されます。閲覧できるものがない場合は、「この実行には、閲覧できるドキュメントがありません。」と表示されます。

ページの上部には、実行の状況が表示されます。

- シミュレート：「この実行はシミュレートです。どのシステムにも何も送信されていません。**これらを転記** で、固定された同じドキュメントが送信されます。」
- 本番で実行中：転記のために押すものはありません。システムが応答するにつれてページが更新され、まだ送信されていないドキュメントの数が表示されます。何かが実行中または待機中の間は、実行内容を自動的に再読み込みします。
- 本番で完了：「本番。すべてのシステムが応答しました。」
- 停止：「この実行は停止されました。送信されていないものは未転記になります。」

ドキュメントの上にある **サマリー** は、開閉でき、最後の状態が維持されます。実行にドキュメントがある場合は、最初は閉じています。内容は次のとおりです。

- ステップの実行では、最初に比較が表示されます。たとえば「変更なし121件、変更19件、新規2件」です。[再実行](#再実行)を参照してください。
- 実行のドキュメント、セット、システム、金額、および各状態の件数。
- [5つのチェック](#5つのチェック)。それぞれにチェックマーク、×印、または何も到達しなかった場合はダッシュが付きます。不合格のチェックには、合格しなかった件数が表示されます。
- **システム別**：システムごとに1行で、各状態の件数と金額、および **合計** を表示します。モードが実行と異なるシステムには、シミュレートまたは本番と表示されます。各件数をクリックすると、該当するドキュメントが開きます。
- ドキュメントの合計の横に、テーブル自身の合計：「一致しています。テーブルの行は漏れていません。」または「一致しません。テーブルの行が漏れたか、二重に集計されました。」一部のエンティティしか閲覧できない場合、合計は閲覧できるものの合計です。
- 各システムの期間と勘定科目のコピーがどれだけ古いか、またはまだコピーがないこと。

その下の **ドキュメント** リストには、担当者の対応が必要なものが先頭に表示されます。各行には、参照（`JE-1001~2` のようなバージョン付き）、エンティティ、システム、セット、金額、状態、**理由と次の対応** があります。**グループ化** は、ドキュメントを **エンティティ**、**タイプ**、**セット**、**システム** でグループ化します。1つのドキュメントを選択すると、その理由と次のステップが全文で表示され、該当する場合は **変更点**、**却下への対処方法**、**異常** も表示されます。各行は、**転記を開く** で[転記レジスター](/ja/guides/connections/posting-register/)にその転記を開き、**そのセットを表示** でそのセットを表示し、再試行が有効な場合は **再試行** を提示します。

### これらを転記

**転記予定** のドキュメントがある実行には、その件数とともに **これらを転記** が表示され、その横に「これらを転記は、表示されているドキュメントをそのまま送信します。」と表示されます。これらのドキュメントを、現時点の状態で改めてチェックしたうえで送信します。プロジェクトが本番を許可している必要があり、シミュレートの実行以降に参照が転記されていてはならず、システム独自のチェックが再度実行されます。まだシミュレートのシステム上のドキュメントは **転記予定** のままです。実行は本番になり、ページには、送信された件数と、改めてチェックされて転記されなかった件数が表示されます。

- 一部のシステムがまだ本番でない場合、ボタンは **本番稼働して転記** と表示されるか、本番にするシステムの名前が表示されます。先にそれらをそのプロジェクトで本番にし、本番にできないものが1つでもあれば、何も送信されません。システムを本番にできるユーザーにのみ表示されます。それ以外のユーザーは、システムの現状のまま転記します。[ERPシステム](/ja/guides/connections/erp-systems/)を参照してください。
- 保留ルールが保留したドキュメントは、この送信のために再度保留されます。**これらを転記** を押した人と、実行を開始した人は、そのドキュメントを承認できません。
- 閲覧できるドキュメントのみが送信されます。保存されたコピーの有効期限が切れているドキュメントは未転記になります。実行ページには「これはまだ利用できません。」と表示され、RESTの応答にはメッセージ「保存されたドキュメントの有効期限が切れています。もう一度実行してください。」が含まれます。

### システムで確認

転記されたドキュメントがある実行には **システムで確認** が表示されます。すべてが1つのシステムにある場合は、そのシステム名に続けて **でチェックイン** が表示されます（*システム名* **でチェックイン**）。実行で転記されたドキュメントがそれぞれのシステムにあるかどうかを各システムに問い合わせ、その回答を記録します。[転記レジスター](/ja/guides/connections/posting-register/)では、システムにあったドキュメントは **システムドキュメント** の横に **帳簿上** と表示され、見つからないか内容が異なるものは **要対応** に入ります。問い合わせの対象は、付与されている接続のドキュメントのうち、アクセスできるプロジェクトのものだけで、`analyze.workflow.write` が必要です。

### 実行を停止する

実行中で、まだ送信されていないドキュメントがある本番の実行には、**実行を停止** が表示されます。まだ送信されていないドキュメントは未転記になり、実行ページには「送信前に実行が停止されました。」と表示されます。すでに送信されたドキュメントはそのままで、ページには、停止された件数とすでに送信されていた件数が表示されます。本番の実行が送信の途中にあり、ドキュメントが1件も記録されていない間は、まだ停止できません。

### 再試行

行の **再試行**、またはセットの **残りを再試行** は、転記されなかったドキュメントを、固定されたまま、プロジェクトの転記モードで新しい実行として再度送信します。すでに転記されたドキュメントは再送信されません。再試行は、原因がドキュメントの外にあったドキュメントに対して提示されます。承認者が却下した、実行が停止された、エージェントがオフラインだった、システムが拒否した、期限までに見つからなかった、送信されなかった、またはエンティティにシステムがなかった場合です。チェックで停止されたドキュメントは、ソースを修正してからステップを再実行する必要があります。

### 担当者の対応が必要なセット

**担当者の対応が必要なセット** には、一部のみ転記されたセット、またはメンバーが合格しなかったために何も送信されなかったセットが表示されます。**セットを表示** は、ドキュメントをそのセットに絞り込みます。一部のみ転記されたセットでは、**残りを再試行** が転記されなかったものを再試行し、**転記済みを取り消す** は、何がどのシステムで取り消されるかを表示してから、セットの一部が転記され残りが転記されなかったことを理由に取り消します。2人目の担当者が必要な取消は **承認が必要** のまま待機し、ページには **取り消しの実行を開く** で取消自身の実行へのリンクが表示されます。

### 変更されたドキュメント

ステップが確認するに設定されていて、実行が転記後に変更されたドキュメントを見つけた場合、ページには、選択を待っている件数が表示されます。

- **すべて訂正**、または選択したドキュメントの **このバージョンで修正** は、転記済みのものを取り消し、変更されたものをその参照の新しいバージョンとして転記します。
- **すべて保持**、または選択したドキュメントの **転記済みのものを維持** は、転記済みのバージョンを維持し、変更されたものを破棄します。

どちらも、最初に確認を求められます。

## 実行

転記レジスターの **実行回数** には、転記ステップまたは転記ファイルのすべての実行が、新しい順に、**モード**、開始した人、結果とともに一覧表示されます。**開く** で、その実行ページが開きます。

一覧の上には、先月の概要が表示されます。システムごとに1行で、たとえば何件中何件が転記されたか、金額、システム自身の帳簿にある件数、要対応の転記の件数です。その前の月にシステムへ転記したステップで、その月はまだ実行されていないものは、その下に名前が表示されます。行の **開く** は、その月のそのシステムの転記を開き、月が完了していない場合は、**「要対応」を開く** で残りの項目に移動します。概要には、ステップの本番の実行が集計されます。

## 再実行

参照は1回だけ転記されます。実行に、すでに記録にあるドキュメントがある場合は、次のとおりです。

- 変更されていないものは、そのままにされます。
- 変更されたものは、ステップの[転記済み伝票が変更されて戻ってきたとき](#転記済み伝票が変更されて戻ってきたとき)の設定（確認する、または訂正する）に従います。訂正では、`JE-1001~2` のように参照の次のバージョンが転記され、システムでもそのバージョンが認識されます。
- 以前のバージョンにまだシステムからの応答がないものは、未転記になります。「この参照の以前のバージョンには、システムからまだ応答がありません。応答があってから、もう一度実行してください。」

キーにエンティティが含まれるシステムでは、別のエンティティの同じ参照は別のドキュメントです。それ以外のシステムでは拒否されます。「この参照はすでにこのシステムで使用されています。」

ステップが以前に転記し、今回は生成しなかったドキュメントは、そのままにされます。本番の実行が終了すると、そのページに、たとえば「以前に転記された3件のドキュメントは、今回は生成されませんでした。そのままにされます。」のように一覧表示され、それぞれの参照とシステムが示されます。一覧には、この実行のドキュメントの期間にステップが本番で転記したもののうち、まだ **転記済み** で、全額がクレジットされておらず、閲覧できるものが含まれます。実行が保持されなくなったドキュメントは一覧に表示されません。その場合は[転記レジスター](/ja/guides/connections/posting-register/)から取り消してください。

**これらを取り消す**（**これら 3 件を取り消す** のように件数付き）は、確認後、それらを新しい実行として取り消します。2人目の担当者の承認が必要な取り消しは **承認が必要** のまま待機し、**取り消しの実行を開く** で新しい実行が開きます。このボタンは、ロックされていないプロジェクトのアーキテクトまたはマネージャーに表示され、いま取り消せるもの、つまり付与されているシステム上の、プロジェクトが本番で転記できるドキュメントのみが件数に含まれます。1回の操作で扱える200件を超える場合は、一覧は200件で止まり、ボタンは表示されません。REST APIでは、実行を指定した `POST /rest/v1/analyze/erp/reverse/these` が同じ処理を行うか、指定したもののみを取り消します。実行中の実行、またはシミュレートされた実行は拒否されます。

配賦を転記するステップなど、毎期間再実行するステップでは、**転記済み伝票が変更されて戻ってきたとき** を一度、訂正するに設定します。

## ファイルから転記する

スプレッドシートにある少数の仕訳であれば、ワークフローを使わずにファイルを転記できます。

[転記レジスター](/ja/guides/connections/posting-register/)で、スコープを1つのプロジェクトに絞り込み、**転記** ツールバーの **アクション** メニューで **ファイルから転記…** メニュー項目を選択します。`erp.register.operate` を持つメンバーに表示されます。スコープに単一のプロジェクトがない場合は、「先にスコープでプロジェクトを1つ選択してください。」と表示されます。**ファイルから転記** ペインには3つのカードがあります。

1. **1 · システムと伝票の種類を選択** — **環境**、**システム**、そのシステムが受け付ける **ドキュメント** の種類です。**スターターファイルをダウンロード** は、そのシステムとドキュメントに適した列見出しと例の行を、Excelファイルとしてダウンロードします。
2. **2 · ファイルをアップロード** — **スプレッドシートをここにドロップ** にスプレッドシート（`.xlsx` または `.csv`）をドロップします。一緒にドロップしたほかのファイルは、サポートファイルとして実行とともに保持されますが、まだシステムには送信されません。実行の準備ができると、実行ページが開きます。
3. **過去のファイル実行** — プロジェクトの過去のファイル実行で、それぞれに **再転記** があります。

REST APIまたはMCPツールでは次のようにします。

1. `GET /erp/file-post/starter` に `connection_id`、`document_type`、`format`（`xlsx` または `csv`）を指定すると、そのシステムのその種類のドキュメントに適した列見出しと例の行がダウンロードされます。システムが受け付けない種類のドキュメントは拒否されます。
2. `POST /erp/file-post` は、スプレッドシート（`.xlsx` または `.csv`）を `file` として、`project_id` とともに受け取ります。`attachments` として送信された追加のファイルは、サポートファイルとして実行とともに保持されますが、まだシステムには送信されません。MCPツール `erp_file_post` は、代わりにPlaidCloudドキュメントのファイルを、その `account_id` と `path` で受け取ります。
3. 実行はシミュレートで開き、何も送信されません。その[実行ページ](#実行ページ)で確認し、**これらを転記** で転記します。

- 各ドキュメントは、ほかの実行と同様に、そのエンティティの転記先のシステムに送られます。
- `doc_number` 列のないファイルは何も準備せず、**このファイルを 1 件の仕訳として扱いますか?** と尋ねます。**はい、1 件の仕訳** を選択すると、ファイル全体が1つの仕訳として、ファイル名を参照として転記されます。**いいえ** を選択すると、`doc_number` 列を追加してもう一度ファイルを選択するよう求められます。REST APIでは `ask: one_journal` と応答します。`one_journal` を true にして再度送信すると1つの仕訳になり、false にすると、各行がそれぞれ独自の仕訳として、ファイル名に基づいて採番されて転記されます。
- `doc_number` 列があるファイルでは、それがない行は警告とともに除外されます。転記用の列でない見出しは無視され、警告にその名前が示されます。
- 空のファイル、または行のないファイルは、何も準備せず、その旨が表示されます。転記がオフのプロジェクトも同様です。

### 再転記

再転記は、ファイルの実行のドキュメントを、新しい転記日と新しい参照で再度転記します。毎月繰り返される仕訳向けです。

アプリでは、ロックされていないプロジェクトのアーキテクトまたはマネージャーに対し、実行のドキュメントが保持されている間、ファイルの実行のページに **再転記** が表示されます。**ファイルから転記** の **過去のファイル実行** にも同じものがあります。**転記日** を選択してから、次のいずれかを選択します。

- **再転記** は、各参照にサフィックスを付けて、繰り返しが転記済みとして拒否されないようにし、新しい実行をシミュレートで開きます。
- **毎月繰り返す** は、代わりにスケジュールに載せます。転記日と同じ日（最大で28日）の、UTC 06:00 に、繰り返しのたびにその実行日付で転記されます。このファイルのドキュメントが本番で転記されている場合は、プロジェクトが許す範囲で本番で転記されます。

REST APIでは、`POST /erp/file-post/{run_id}/again` で再転記でき、MCPツール `erp_file_post_again` でも再転記できます。

- `posting_date` は、ISO形式の日付、または `today`、`first_of_month`、`last_of_month`、`first_of_next_month`、`last_of_prev_month` のいずれか、あるいは各ドキュメント自身の転記日からの `+1m` や `-7d` のようなシフトです。
- `references` を `suffix` に設定すると、各参照に新しい月のサフィックス（`JE-1001-202612` など）が付き、繰り返しが転記済みとして拒否されません。RESTでは、代わりに各参照を新しい参照に対応付けることもできます。MCPツールは常にサフィックスを追加します。
- ドキュメント日は転記日とともに移動し、支払期日は同じ日数だけ移動し、期間の列は削除されるため、システムは新しい日付から期間を決定します。
- 新しい実行は、`live` で本番を指定しない限りシミュレートで開き、プロジェクトの転記モードを超えることはありません。閲覧できるエンティティのドキュメントのみが再転記されます。

`POST /erp/file-post/{run_id}/schedule` は、再転記を、`cron` とその `timezone`、実行のたびに算出される `posting_date`、`suffix` に設定した `references` を指定して、スケジュールに載せます。あなた自身として実行され、閲覧できるエンティティのみを転記します。本番で転記するのは、このファイルのドキュメントがすでに誰かによって本番で転記されている場合のみで、プロジェクトの転記モードを超えることはありません。スケジュールにはMCPツールはありません。

実行のドキュメントは、シミュレートの場合は30日間、応答があった後は90日間保持されます。それ以降は、再転記で準備するものがなく、その旨が表示されます。

### 転記済みとして記録

PlaidCloudを使い始める前にシステムで転記されたドキュメントについては、`POST /erp/record-posted` が、システムに接続せずにそれらを転記済みとして記録するため、後でそれらを含む実行が、再度転記することを拒否します。スプレッドシートを `file` として、システムの `connection_id` と `environment_id` とともに送信します。列 `reference` と `system_document` が必要で、任意で `entity`、`posting_date`、`document_type`（省略した場合は仕訳）を指定できます。アプリでは、`erp.register.operate` を持つメンバーに、**ファイルから転記** に **この製品の利用前に転記済みですか? 転記済みとして記録** が表示されます。これを選択すると **転記済みとして記録** が開き、**環境** と **システム** を選択し、スプレッドシートをドロップして、**転記済みとして記録** を選択します。MCPツールはありません。

- PlaidCloudがすでに転記済みとして保持しているドキュメント、まだ応答を待っているドキュメント、または別のシステムドキュメントとして保持している参照は、理由とともに、記録されなかったものとして一覧表示されます。
- ファイル内の未確認のドキュメントが転記済みとして決着されるのは、転記レジスター承認者ロールを持つユーザーによる場合のみです。それ以外のユーザーには、記録されなかったものとして返されます。

## 配賦から転記する

**配賦: ディメンションで分割** ステップは、ステップの構成の `post_documents` 設定により、その結果を、伝票を転記ステップが転記するドキュメントのテーブルとして書き込むこともできます。この設定では、書き込むドキュメントの `table` と、結果の `rule`、`account`、`source_account`、`amount`、`posting_date` の列（すべて必須）、および任意で `entity` と `currency_txn` を指定します。`set` は、ドキュメントに固定のセット名を付けます。

- 各ルールは月ごとに1つのドキュメントとなり、ルールと月で参照されます（たとえば `RENT-202611`）。結果の各行は、その勘定科目への明細と、ソースの勘定科目への相殺明細となるため、すべてのドキュメントがバランスします。
- ルールのない行や、金額がゼロの行は、明細を作成しません。金額が数値でない行は除外され、警告にその行が示されます。転記するものがない場合、ステップは警告を出し、ドキュメントのテーブルを空にします。
- 同じ月に配賦を再実行すると同じ参照になるため、転記ステップの[転記済み伝票が変更されて戻ってきたとき](#転記済み伝票が変更されて戻ってきたとき)を、訂正するに設定してください。

## SAP転記ステップを変換する

既存のSAP転記ステップは、伝票を転記ステップに変換できます。自動的に変換されるものはありません。キャンバスでステップを右クリックして **ドキュメント転記に変換…** を選択するか、ステップのフォームの **ドキュメント転記に変換…** を使用します。PlaidCloudは最初に、変換される内容を表示します。ドキュメントのフィールドに対応付けられた列、システムに振り分けられたエンティティ、これまでどおり転記を続けるかシミュレートで開始するか、および警告です。**変換** で確定します。古い設定は、ステップのバージョンに残ります。

- 変換できるのは、SAP転記ステップのみです。関数またはヘッダー列が設定されていないステップ、またはドキュメントキーが会社コードと1つのドキュメント番号でないステップは変換されず、PlaidCloudがその理由を表示します。
- ステップのフィルターにあるエンティティは、その接続へのルートとして提案されます。フィルターにエンティティがない場合は、転記する前に、[ERPシステム](/ja/guides/connections/erp-systems/)で振り分けを設定してください。
- 変換されたステップにテーブルを設定するまでは、古いステップのヘッダー、明細、VAT、源泉徴収のテーブルを自身で読み取ります。
- 変換されたステップは、古いステップが転記した内容の記録を引き継ぐため、古いステップがすでに転記した期間は再度転記されません。
- 転記のテストに設定されていたステップは、シミュレートで実行され続けます。[シミュレートと本番](#シミュレートと本番)を参照してください。

## RESTとMCP

同じ転記は、`/rest/v1/analyze/erp` のREST APIと、MCPツールからも利用できます。

| 操作 | REST | MCP |
|---|---|---|
| テーブルの最初のドキュメントを、システムが受け取る形式で確認する | `POST /erp/post/preview` | `erp_post_preview` |
| テーブルまたはドキュメントのリストを転記する | `POST /erp/post` | `erp_post_documents` |
| 実行と実行ページを読み取る | `GET /erp/runs`, `GET /erp/runs/{run_id}` | `erp_run_find`, `erp_run_describe` |
| これらを転記する、または実行を停止する | `POST /erp/runs/{run_id}/post`, `POST /erp/runs/{run_id}/stop` | `erp_run_post`, `erp_run_stop` |
| 変更されたドキュメントの確認に回答する | `POST /erp/ask` | `erp_ask_answer` |
| ドキュメントを再試行する | `POST /erp/retry` | `erp_retry` |
| スターターファイルをダウンロードする | `GET /erp/file-post/starter` | — |
| ファイルから転記する、および再転記する | `POST /erp/file-post`, `POST /erp/file-post/{run_id}/again` | `erp_file_post`, `erp_file_post_again` |
| スケジュールで再転記する | `POST /erp/file-post/{run_id}/schedule` | — |
| 転記済みとして記録する | `POST /erp/record-posted` | — |
| SAP転記ステップを変換する | `POST /erp/convert` | `erp_convert_step` |

- RESTまたはMCPからの転記は、本番を指定しない限りシミュレートで実行され、プロジェクトの転記モードを超えることはありません。
- RESTでのテーブルの転記は、最大100,000行を読み取ります。それより長いテーブルは全体が拒否されるため、代わりにステップで転記してください。
- `erp_file_post` はPlaidCloudドキュメントのファイルを受け取ります。ファイルがない場合は警告となり、何も準備されません。
- 変換と再試行は、別途指定しない限りドライランです。
- あなたの代わりに動作するAIアシスタントは、本番の転記、**これらを転記**、訂正、実際の再試行、実際の変換、再転記を拒否されます。これらは人が行います。

## 誰が何をできるか

| 操作 | 必要なもの |
|---|---|
| ステップを作成し、その最初のドキュメントをプレビューする | `analyze.step.write` |
| RESTまたはMCPで転記する | `analyze.workflow.write`、およびロックされていないプロジェクトのアーキテクトまたはマネージャー |
| スターターファイルをダウンロードする | `analyze.connection.read` |
| ファイルからの転記を開始する | `analyze.workflow.write`、およびロックされていないプロジェクトのアーキテクトまたはマネージャー |
| 実行ページを開く | `analyze.project.read`。閲覧できるエンティティのドキュメントが表示されます |
| 転記レジスターで **実行回数** を表示する | `erp.register.view` |
| **これらを転記**、**実行を停止**、訂正または維持、再転記とそのスケジュール、実行が生成しなかったものの取消 | `analyze.workflow.write`、およびロックされていないプロジェクトのアーキテクトまたはマネージャー |
| 転記中にシステムを本番にする | ロックされていないプロジェクトのアーキテクトで、接続への自身の書き込みアクセス権があること |
| **再試行** | `analyze.workflow.write`、およびロックされていないプロジェクトのアーキテクトまたはマネージャーで、ドキュメントの接続への自身の書き込みアクセス権があること |
| **転記済みを取り消す** | `erp.register.view` と `erp.register.operate` |
| 転記済みとして記録する | `erp.register.view` と `erp.register.operate`、および接続への自身の書き込みアクセス権。未確認のドキュメントの決着には `erp.register.approve` も必要 |
| SAP転記ステップを変換する | `analyze.step.write` と、プロジェクトへの書き込みアクセス権 |

SAP、Oracle E-Business Suite、Sage 100 向けの PlaidLink エージェントに転記を送信する場合（テスト転記や Sage 100 の照会を含みます）、エクスプローラーとして所属しているプロジェクトやロックされているプロジェクトを指定すると、接続に対するアクセス権の有無にかかわらず拒否されます。

すべての経路で同じルールが適用されます。UI、REST API、MCPツールは、同じチェックを呼び出します。
