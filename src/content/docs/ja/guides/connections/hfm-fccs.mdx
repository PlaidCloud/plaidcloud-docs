PlaidCloudをOracle **FCCS**（Financial Consolidation and Close、Oracle EPM Cloudの一部）に接続すると、財務担当ユーザーがHFMチームに依頼せず、自分でデータスライスを取得できます。ステップのフォームで **ポイントオブビュー（POV）** を作成して実行するだけで、結果が自動的にテーブルとして取り込まれます。ライブクエリのように感じられますが、内部ではFCCSのデータエクスポートジョブに対する非同期のリクエスト、ポーリング、取得という流れで動作しています。このガイドでは、接続、POVの作成、実行、キャッシュ、行レベルセキュリティによる結果の制御、スケジュールによる定期ロードへの変換を説明します。

<Aside type="note">
**エンティティ** の選択は範囲を限定してください。範囲を限定しない抽出は、エクスポートジョブの実行中にFCCSアプリケーションを長時間ロックする可能性があります。ポイントオブビューは、実際に必要なエンティティに必ず限定してください。
</Aside>

## 前提条件

Oracle EPM Cloudで次のものが必要です。

- **EPM Cloudのポッド／サービスURL**。たとえば `https://planning-test-yourdomain.epm.us2.oraclecloud.com` です。
- **IDドメイン**（クラシックポッドの場合）。PlaidCloudは `identitydomain.username` の形式でログインを組み立てます。
- 専用の **サービスアカウント**（ユーザー名とパスワード）。FCCSアプリケーションと、セルフサービスユーザーが取得するポイントオブビューのスライスに対する読み取りアクセス権が必要です。
- ユーザーが読み取る **アプリケーション名**。

<Aside type="note">
この接続は、クラシックEPM Cloudポッドに対して **HTTP基本認証** で認証します。OAuthベアラートークンを必要とするOCI／Gen 2ポッドは、このコネクターの対象外です。
</Aside>

## 接続を作成する

<Steps>

1. **Tools > Connections** を開き、`New Connection` をクリックします。

2. メニューから **REST - HFM/FCCS** を選択します。

3. 各フィールドに入力します。

   | フィールド | 値 |
   |---|---|
   | 名前 | わかりやすい名前（例：`FCCS Prod`）。 |
   | EPM Cloud URL | ポッド／サービスのURL（例：`https://planning-test-yourdomain.epm.us2.oraclecloud.com`）。 |
   | IDドメイン | EPM CloudのIDドメイン。ユーザー名にすでにドメインが含まれている場合にのみ、空白にしてください。 |
   | ユーザー名 | サービスアカウントのユーザー名。 |
   | パスワード | サービスアカウントのパスワード。 |
   | デフォルトアプリケーション | 任意。ステップのPOVピッカーにあらかじめ入力するFCCSアプリケーション。 |

4. `Test Connection` をクリックします。テストが成功すると、PlaidCloudが設定済みの認証情報でHFM/FCCSサーバーに到達できることが確認できます。

5. `Create` をクリックします。

</Steps>

PlaidCloudは `identitydomain.username` としてログインします（IDドメインが空白の場合、またはユーザー名にすでにドットが含まれている場合は、ユーザー名をそのまま使用します）。

## ポイントオブビューを作成する

<Steps>

1. ワークフローに **HFM/FCCS: データの読み取り（アドホック）** ステップを追加します（ステップメニューの **Oracle EPM (HFM/FCCS)** にあります）。

2. **ソースとターゲット** で、**HFM/FCCS接続**、**環境**、**アプリケーション**、**ターゲットテーブル** を設定します。

3. **POV（ポイントオブビュー）** で、FCCSのディメンションからスライスを作成します。**シナリオ、年度、期間、エンティティ、勘定科目、Custom1〜Custom4、ICP、ビュー、値**。

   - **シナリオ、年度、期間は必須です。**
   - **エンティティは範囲を限定したスライスにする必要があります。** フォームは、空の選択、「all」、または500メンバーを超える選択を拒否します。エクスポートでアプリケーションがロックされないよう、範囲を限定してください。
   - 他のディメンションを未設定のままにすると、その軸にはフィルターが適用されません。

</Steps>

<Aside type="note">
サポートされているFCCSポッドでは、接続とアプリケーションを選択すると、ライブのメタデータ検出からメンバーリストが **自動入力** されます。ピッカーには実在するメンバーが表示され、接続またはアプリケーションが変更されるたびに再検出されます。メタデータエンドポイントを公開していない古いポッドでは、ピッカーは **手動入力** に切り替わり、メンバー名を手で入力します。保存したPOVは、どちらの場合でも正しく復元されます。
</Aside>

## 実行する

<Steps>

1. ステップを実行します（[ワークフロー内で1つのステップを実行する](/ja/guides/workflows/running-one-step-in-a-workflow/)を参照してください）。

2. FCCSでエクスポートジョブが実行されている間、進行状況のステータス（「HFMジョブをポーリング中…」）が表示されます。

3. 完了すると、結果のテーブルが自動的に取り込まれます。テーブルは返されたグリッドの列から作成されるため、スキーマを事前に定義する必要はありません。

</Steps>

## キャッシュ

**同じPOVを再度** リクエストすると、PlaidCloudはFCCSへのエクスポートを再送信する代わりに、**すでに取り込まれたテーブル** を即座に提供します。実行は、アプリケーション、ターゲットテーブル、ポイントオブビュー、および **as-of** タグ（デフォルトは `latest`）をキーとして識別されます。すでに取り込まれたスライスに解決される再実行では、テーブルが書き換えられずそのまま残されたことが報告されます。同じPOVを新たに抽出し直したい場合は、as-ofタグを変更してください。

## 行レベルセキュリティで制御する

取り込まれたテーブルのエンティティ軸は、正確に **`Entity`** という名前の列に正規化されるため、テーブルは **行レベルセキュリティに対応した状態** になります。管理者は[行アクセス](/ja/administration/access/managing-security-groups-and-assignments/)でこれを制御し、セルフサービスユーザーに権限のあるエンティティだけを表示できます。

<Aside type="caution">
これは **自動ではなく、管理者の管理下で制御されます**。抽出は接続のサービスアカウントで実行されるため、PlaidCloudはステップ自身がセキュリティを宣言することを許可しません。管理者（アーキテクト）が設定する必要があります。
</Aside>

管理者は、標準の行アクセスのワークフローに従います。

<Steps>

1. 取り込まれたテーブルをレポート用に **公開** します。

2. `Entity` 列をガバナンス属性として **宣言** します（デフォルトは拒否）。

3. 最初のガバナンス対象の書き込みを **承認** します。

4. **照合** して、権限付与を有効にします。

</Steps>

管理者がこれを行うまで、テーブルはフィルタリングされません。[セキュリティグループと割り当ての管理](/ja/administration/access/managing-security-groups-and-assignments/)を参照してください。

## 定期ロードをスケジュールする

アドホックなスライスを毎晩の更新に昇格させるには、ステップで **バインドしたターゲット** を有効にします。

<Steps>

1. ステップの **バインドしたターゲット** グループで、**バインドしたターゲット（スケジュールによる定期ロード）** をオンにします。

2. 必要に応じて **キー列** を設定します。これはマージキーを構成する、カンマ区切りの列です（例：`Entity, Account`）。**空のままにする** と、取り込まれたグリッドにあるPOVディメンション列がマージキーとして使用されます。

3. ステップを[スケジュールされたワークフロー](/ja/administration/scheduled-events/)に配置します。

</Steps>

バインドしたターゲットをオンにすると、ターゲットは **永続的な** テーブルになります。実行のたびに、上書きではなくキーセットのアップサートで **マージ** され、後のグリッドに新しい列が加わった場合はスキーマが **追加的に拡張** されます（新しい列は警告を発生させますが、失敗にはなりません）。そのため、スケジュールされた実行はデータを消去せず蓄積します。これは破壊的な再ロードではなく、定期ロードです。
