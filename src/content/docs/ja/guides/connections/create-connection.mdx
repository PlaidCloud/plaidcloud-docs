**接続**は、PlaidCloud が外部システム（データベース、データレイク、ERP、REST API、クラウドサービス、Git プロバイダー）にアクセスできるようにする、保存済みの構成です。ワークフローのステップは接続を名前で参照するため、エンドポイントの詳細と認証情報は 1 か所にまとまり、それを必要とするすべてのステップとプロジェクトで再利用されます。

接続は **Tools > Connections** から管理します。

## 接続の作成

1. **Tools > Connections** を開きます
2. ツールバーの `New Connection` をクリックし、メニューから接続先のシステムを選択します
3. 接続フォームに入力します（タブとフィールドは種類によって異なります。後述の[接続フォーム](#接続フォーム)を参照してください）
4. `Create` をクリックして保存します

新しい接続が一覧に表示され、所有者はあなたになります。

<Aside type="note">接続の種類と、それぞれに必要なフィールドの一覧は、[コネクターリファレンス](/ja/reference/connectors/)にまとめられています。専用のコネクターがないサービスには、[汎用 REST 接続](/ja/reference/connectors/rest/generic-rest/)を使用します。</Aside>

## 接続フォーム

ほとんどの接続では、複数のタブを持つフォームが開きます。タブの内容は種類によって異なりますが、一般的には次のものが表示されます。

- **接続構成**（REST の場合は**接続の詳細**）— 接続の `Name`、任意の `Memo`、ホスト/ポート/データベース（REST の場合はホスト/認証タイプ）、`Usage` トグル（`Active`）、`Security Model`。データベース接続では、認証情報は **認証情報** グループにあります。REST 接続では、専用の **認証** タブにあります。
- **SSL構成** — `Use SSL`、SSL モード、および暗号化接続用の任意のクライアント証明書/ルート証明書。
- **SSH構成** — `Use SSH`、および SSH 踏み台ホストを経由して接続をトンネリングするための踏み台ホスト、ポート、ユーザー、キー。

パスワード、トークン、その他の認証情報フィールドは書き込み専用です。保存済みの接続を開き直すと空欄で表示され、空欄のまま保存すると、保存済みのシークレットが維持されます。値を再入力するのは、変更したい場合のみです。これは、REST 接続の API キー、OAuth クライアントシークレット、OAuth リフレッシュトークンにも当てはまります。複数行の認証情報（NetSuite の秘密証明書、Anaplan の証明書と秘密キー、Postman の API キー、Slack や Teams の受信 Webhook URL）も同様に書き込み専用で、入力または貼り付けの際にマスクされます。スペースのみで構成された置き換え値は、保存済みの認証情報を上書きせずに拒否されます。保存済みの値を維持するには、フィールドをクリアしてください。SQL 接続または Git 接続の SSL クライアントキーと SSH 秘密キーも書き込み専用ですが、入力中は表示されたままです。それ以外のフィールドは、エディターでも API 経由でも、接続が表示されるあらゆる場所で保存済みの実際の値が表示されます。名前から機密に見えるフィールド（データベースの読み取り専用フラグ、アカウント識別子、スキーマ、ホスト名）も同様です。マスクまたは非表示になるのは、実際の認証情報のみです。

REST API と MCP では、認証情報フィールドはエディターと同じルールに従います。空文字列を送信すると PlaidCloud は保存済みの値を維持し、`null` を送信するとクリアされます。認証情報以外のフィールドは、これまでどおり空欄を送信するとクリアされます。

必須フィールドは保存時に検証されます。不足がある場合、フォームは最初の無効なフィールドがあるタブに切り替わり、そのフィールドを示します。

## セキュリティモデル

接続の `Security Model` は、ワークスペース内で誰がその接続を使用できるかを制御します。

| オプション | 接続を使用できるユーザー |
|---|---|
| プライベート（所有者のみ） | 所有者のみ。 |
| 特定のメンバーのみ | 所有者と、明示的に指定したメンバーの一覧。 |
| 特定のセキュリティグループのみ | 所有者と、指定したセキュリティグループのメンバー。 |
| すべてのワークスペースメンバー | ワークスペース内の全員。 |

`Specific Members Only` または `Specific Security Groups Only` を選択した場合は、一覧の `Actions` メニューからアクセスを付与します。`Specific Members Only` の場合は `Members`、`Specific Security Groups Only` の場合は `Groups`、さらに `Agents` と `Owners` を選ぶと、それぞれフィルター付きのチェックリストが開き、アクセスを許可する対象にチェックを入れます（[ピッカーを使った割り当て](/ja/administration/access/managing-security-groups-and-assignments/#ピッカーを使った割り当て)を参照してください）。ここでアクセスを変更できるのは、接続の所有者またはワークスペース管理者のみです。接続を編集できるそれ以外のユーザーは、接続を開いて、すでに割り当てられているユーザーの読み取り専用の一覧からアクセス権を持つユーザーを確認できます。ワークスペース管理者は、所有者が退職した場合などに引き継ぐため、自分が所有していない接続のアクセスを変更できます。

## 接続の認証情報を確認できるユーザー

接続を使用できるユーザーは、接続を開いて設定を確認したり、Git 接続のリポジトリ、ブランチ、ファイルを参照したりできます。接続のパスワード、トークン、キーは、接続またはワークフローを編集できるメンバーにのみ返されます。REST API と MCP では、それ以外のユーザーにはマスクされた状態で返されます。

保存されているものとは異なるサーバー URL で Git 接続を参照する場合は、そのサーバー用のトークンを入力してください。

## 環境

接続には、**環境**ごとに異なる構成を保持できます（たとえば、1 つの接続名のもとで開発用ホストと本番用ホストを持たせる場合）。ツールバーの環境セレクターで、表示および編集する環境の構成を選択します。

- `New Environment` — 接続環境を追加します
- `Edit Environment` — 選択した環境の名前を変更します
- `Delete Environment` — 選択した環境を削除します。プロジェクトで使用されておらず、どのステップでも[固定環境](/ja/guides/projects/managing-projects/#ステップを1つの環境に固定する)として指定されておらず、どのエージェントも使用していない場合に限ります。それ以外の場合は、まだ何が使用しているかがメッセージに表示されます。デフォルトの環境は削除できません。

一覧の `Available` 列には、選択した接続が選択中の環境用に構成されているかどうかが表示されます。

<Aside type="note">構成を保存すると、その環境の保存済みの構成にマージされるため、空欄の書き込み専用シークレットが空の値で上書きされることはありません。</Aside>

環境は PlaidLink エージェントと共有されるため、プロジェクトの環境を切り替えると、プロジェクトが読み取る接続だけでなく、リモートステップを実行するエージェントも切り替わります。[エージェント環境](/ja/reference/cli/plaidlink/agents/#エージェントの環境)を参照してください。

## 接続の編集

1. 一覧で接続を選択します
2. ツールバーの `Edit` をクリックします（または行を右クリックします）
3. フィールドを変更し、`Update` をクリックします

## 接続のテスト

テストの方法は種類によって異なります。

- **データベース接続**（Databricks、Snowflake、PostgreSQL、Redshift）は、エディターに **接続をテスト** ボタンがあります。入力した認証情報で接続を開き、成功（到達したサーバーのバージョン付き）または失敗の理由を報告します。エディターは閉じないため、その場で修正して再試行できます。
- SSH を使用するデータベース接続では、`SSH Config` タブで SSH トンネルのテストも利用できます。
- [汎用 REST 接続](/ja/reference/connectors/rest/generic-rest/)には、保存済みの接続を通じてアドホックなリクエストを送信する `Testing` タブがあります。

テストの前に接続を保存してください。テストは保存済みの構成に対して実行されます。

<Aside type="note">**接続をテスト** は、エディターが対応した時点で、その接続の種類に表示されます。現在は、上記のデータベースの種類に加え、[TM1](/ja/guides/connections/tm1/)、[Oracle Essbase](/ja/guides/connections/essbase/)、[HFM/FCCS](/ja/guides/connections/hfm-fccs/)、Salesforce、Anaplan が対象です。NetSuite などその他の REST 接続にはまだありません。それらは、ワークフローのステップから小さなリクエストを送信して動作を確認してください（NetSuite については、[NetSuite への接続](/ja/guides/connections/netsuite/#接続をスモークテストする)を参照してください）。</Aside>

## 接続できないアドレス

接続の接続先に、ループバック、リンクローカル、クラウドメタデータのアドレスは指定できません。PlaidCloud は、接続をテストするとき、およびステップが接続を使用するときに、ホスト名が解決されるアドレスを確認します。条件を満たさないアドレスの場合は、ホスト名と解決されたアドレスを示すエラーで失敗します。プライベートネットワーク上のアドレスは影響を受けません。

## 複製、削除、使用状況の追跡

- **複製** — 接続の構成を複製し、新しい接続のベースとして使用します。[接続の複製](/ja/guides/connections/clone-connection/)を参照してください。
- **削除** — ツールバーから、選択した接続を削除します（確認を求められます）。
- **使用箇所…** — 接続を参照しているワークフローのステップを一覧表示します。編集や削除の前に影響を確認できます。

<Aside type="caution">`Edit`、`Clone`、`Delete` は、自分が所有する接続でのみ使用できます。選択した行でこれらの操作がグレー表示になっている場合は、所有者ではありません。所有者に変更を依頼するか、`Owners` から自分を追加してもらってください。</Aside>

REST API、JSON-RPC、AI アシスタント、MCP を使う場合も同様です。接続の設定を変更するには、その接続の所有者であるか、所有者のいない接続ではワークスペース管理者である必要があります。接続の有効化、無効化、ロック、ロック解除には、所有者またはワークスペース管理者が必要です。複数の接続を指定したリクエストは、そのすべてを変更できる場合にのみ適用されます。
