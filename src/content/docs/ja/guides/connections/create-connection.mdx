**接続** とは、PlaidCloudが外部システム（データベース、データレイク、ERP、REST API、クラウドサービス、Gitプロバイダー）にアクセスするための保存済みの構成です。ワークフローのステップは接続を名前で参照するため、エンドポイントの詳細や認証情報は1か所に保管され、必要なすべてのステップとプロジェクトで再利用されます。

接続は **Tools > Connections** から管理します。

## 接続を作成する

1. **Tools > Connections** を開きます
2. ツールバーの `New Connection` をクリックし、メニューから接続先のシステムを選択します
3. 接続フォームに入力します（タブとフィールドは種類によって異なります。下記の[接続フォーム](#接続フォーム)を参照してください）
4. `Create` をクリックして保存します

新しい接続は、あなたを所有者として一覧に表示されます。

<Aside type="note">接続の種類と、それぞれに必要なフィールドは、[コネクターのリファレンス](/ja/reference/connectors/)に記載されています。専用のコネクターがないサービスには、[汎用REST接続](/ja/reference/connectors/rest/generic-rest/)を使用してください。</Aside>

## 接続フォーム

ほとんどの接続では、複数のタブを持つフォームが開きます。タブの構成は種類によって異なりますが、一般的には次のようなものが表示されます。

- **接続構成**（RESTの場合は **接続の詳細**）— 接続の `Name`、任意の `Memo`、ホスト／ポート／データベース（RESTの場合はホスト／認証タイプ）、`Usage` トグル（`Active`）、そして `Security Model` です。データベース接続では、認証情報は **認証情報** グループにあります。REST接続では、専用の **認証** タブに表示されます。
- **SSL構成** — `Use SSL` に加え、暗号化接続用のSSLモードと、任意のクライアント証明書／ルート証明書を設定します。
- **SSH構成** — `Use SSH` に加え、SSHジャンプホスト経由で接続をトンネリングするための踏み台ホスト、ポート、ユーザー、キーを設定します。

パスワード、トークン、その他の認証情報フィールドは書き込み専用です。保存済みの接続を開き直すと空白で表示され、保存時に空白のままにすると、保存されているシークレットが保持されます。値を変更したい場合にのみ、入力し直してください。これはREST接続のAPIキー、OAuthクライアントシークレット、OAuthリフレッシュトークンにも当てはまります。複数行の認証情報（NetSuiteの秘密証明書、Anaplanの証明書と秘密鍵、PostmanのAPIキー、SlackやTeamsの受信Webhook URL）も同様に書き込み専用で、入力または貼り付けの際にマスクされます。スペースのみで構成された置換値は、保存済みの認証情報を上書きせず、拒否されます。保存済みの値を保持するには、フィールドを空にしてください。SQL接続またはGit接続のSSLクライアントキーとSSH秘密鍵も書き込み専用ですが、入力中は表示されたままです。それ以外のフィールドは、接続が表示されるすべての場所（エディターおよびAPI経由）で、保存されている実際の値が表示されます。名前からは機密に見えるフィールド（データベースの読み取り専用フラグ、アカウント識別子、スキーマ、ホスト名）も同様です。マスクまたは非表示になるのは、実際の認証情報のみです。

REST APIおよびMCPでも、認証情報フィールドはエディターと同じルールに従います。空文字列を送信するとPlaidCloudは保存済みの値を保持し、`null` を送信すると消去します。認証情報以外のフィールドは、空白を送信すればいずれも消去されます。

必須フィールドは保存時に検証されます。不足がある場合、フォームは最初の無効なフィールドがあるタブに切り替わり、そのフィールドを示します。

## セキュリティモデル

接続の `Security Model` は、ワークスペース内で誰がその接続を使用できるかを制御します。

| オプション | 接続を使用できる人 |
|---|---|
| 非公開（所有者のみ） | 所有者のみ。 |
| 特定のメンバーのみ | 所有者と、明示的に指定したメンバーの一覧。 |
| 特定のセキュリティグループのみ | 所有者と、指定したセキュリティグループのメンバー。 |
| すべてのワークスペースメンバー | ワークスペース内の全員。 |

`Specific Members Only` または `Specific Security Groups Only` を選択した場合は、一覧の `Actions` メニューからアクセスを付与します。`Specific Members Only` では `Members`、`Specific Security Groups Only` では `Groups` を使用し、さらに `Agents` と `Owners` もあります。それぞれがデュアルリストのピッカーを開き、アクセスの追加と削除を行えます。ここでアクセスを変更できるのは、接続の所有者またはワークスペース管理者のみです。接続を編集できるそれ以外のユーザーは、接続を開いて誰がアクセスできるかを確認できますが、変更はできません。ワークスペース管理者は、所有者が退職した場合などに接続を引き継げるよう、自身が所有していない接続のアクセスを変更できます。

## 環境

接続には、**環境** ごとに異なる構成を持たせることができます（たとえば、1つの接続名の下に開発用ホストと本番用ホストを持たせる場合）。ツールバーの環境セレクターで、表示および編集する環境の構成を選択します。

- `New Environment` — 接続の環境を追加します
- `Edit Environment` — 選択した環境の名前を変更します
- `Delete Environment` — 選択した環境を削除します

一覧の `Available` 列は、選択した接続が、選択中の環境に対して構成されているかどうかを示します。

<Aside type="note">構成を保存すると、その環境に保存されている構成にマージされるため、空白の書き込み専用シークレットが空の値で上書きされることはありません。</Aside>

環境はPlaidLinkエージェントと共有されます。そのため、プロジェクトの環境を切り替えると、リモートステップを実行するエージェントだけでなく、読み取る接続も切り替わります。[エージェント環境](/ja/reference/cli/plaidlink/agents/#エージェントの環境)を参照してください。

## 接続を編集する

1. 一覧で接続を選択します
2. ツールバーの `Edit` をクリックします（または行を右クリックします）
3. フィールドを変更し、`Update` をクリックします

## 接続をテストする

テストの方法は種類によって異なります。

- **データベース接続**（Databricks、Snowflake、PostgreSQL、Redshift）には、エディターに **接続をテスト** ボタンがあります。入力した認証情報で接続を開き、成功した場合は（到達したサーバーのバージョンとともに）成功を、失敗した場合はその理由を報告します。エディターは閉じないため、その場で修正して再試行できます。
- SSH付きのデータベース接続では、`SSH Config` タブにSSHトンネルのテストも用意されています。
- [汎用REST接続](/ja/reference/connectors/rest/generic-rest/)には、保存済みの接続を通じてアドホックなリクエストを送信する `Testing` タブがあります。

テストの前に接続を保存してください。テストは保存済みの構成に対して実行されます。

<Aside type="note">**接続をテスト** は、エディターがこの機能を提供している接続の種類に表示されます。現時点では、上記のデータベースの種類に加え、[TM1](/ja/guides/connections/tm1/)、[Oracle Essbase](/ja/guides/connections/essbase/)、[HFM/FCCS](/ja/guides/connections/hfm-fccs/)、Salesforce、Anaplanが対象です。NetSuiteなどその他のREST接続にはまだありません。それらについては、ワークフローのステップから小さなリクエストを送信してスモークテストを行ってください（NetSuiteについては、[NetSuiteに接続する](/ja/guides/connections/netsuite/#接続をスモークテストする)を参照してください）。</Aside>

## 複製、削除、使用状況の追跡

- **複製** — 接続の構成を複製して、新しい接続のベースにします。[接続を複製する](/ja/guides/connections/clone-connection/)を参照してください。
- **削除** — ツールバーから選択した接続を削除します（確認が求められます）。
- **使用箇所…** — その接続を参照しているワークフローのステップを一覧表示します。編集や削除の前に影響を確認できます。

<Aside type="caution">`Edit`、`Clone`、`Delete` は、自分が所有する接続でのみ使用できます。選択した行でこれらのアクションがグレーアウトしている場合、あなたは所有者ではありません。所有者に変更を依頼するか、`Owners` から自分を追加するよう依頼してください。</Aside>
