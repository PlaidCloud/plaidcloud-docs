[Data Foundation](/ja/guides/projects/data-foundation/)は、接続したすべてのERPシステムとインスタンスのデータを1つのCommon Finance Modelに集約します。Microsoft Dynamics 365 Business Centralは、Data Foundationが直接読み取るERPの1つです。この接続では、クライアント資格情報を使用するMicrosoft Entra IDアプリケーション、読み取り専用の権限セット、およびWebサービスとして公開したいくつかのページオブジェクトを使用します。このページは、これらを設定するBusiness Central管理者と、管理者に設定を依頼するPlaidCloudユーザーを対象としています。

PlaidCloudはデータの読み取りのみを行います。クライアントシークレットをメールで送信することは決してありません。

## アクセスリクエストの送信

**ホーム**の**Data Foundation**にあるプロジェクトの**システム**ページで、**システムを追加**の**システム**でお使いのシステムを選択し、**まだアクセス権がありませんか?** ボタンをクリックします。システムはアクセス待ちになり、プロジェクトのシステムを対象とする1件のリクエストが表示されます。**リクエストをコピー**をクリックして自分のメッセージに貼り付けるか、**リクエストをメールで送信**をクリックしてメールプログラムで開きます。件名は「PlaidCloud へのアクセス」です。

## Business Central管理者が設定する内容

<Steps>

1. **Microsoft Entra IDでアプリを登録します。** **App registrations > New registration**でクライアントシークレットを追加し、ディレクトリ（テナント）ID、アプリケーション（クライアント）ID、シークレットを控えておきます。

2. **Business Centralにアプリを追加します。** **Microsoft Entra Applications**を開いてアプリケーションを追加し、状態を**有効**に設定して、レポート対象のすべての会社に対して権限セット**D365 READ**のみを付与します。このアプリは以下のすべてのページを読み取ります。**D365 BASIC**など、書き込みが可能な権限セットは付与しないでください。

3. **ページオブジェクトをWebサービスとして公開します。** **Search > Web Services > New**で、次のページオブジェクトを、表のとおりの**サービス名**で、**Published**にチェックを入れて公開します。標準APIにはこれらのフィールドが含まれていません。

   | ページ | サービス名 | 備考 |
   |---|---|---|
   | 20 総勘定元帳エントリ | `GLEntries` | |
   | 16 勘定科目表 | `GLAccounts` | |
   | 100 会計期間 | `AccountingPeriods` | |
   | 537 ディメンション値 | `DimensionValues` | |
   | 240 ビジネスユニット | `BusinessUnits` | |
   | 605 IC取引先一覧 | `ICPartners` | |
   | 5802 値エントリ | `ValueEntries` | 売上原価と在庫残高。任意 |
   | 120 総勘定元帳予算エントリ | `GLBudgetEntries` | 予算。任意 |
   | 統計元帳エントリ | `StatisticalLedgerEntries` | 統計ドライバー。任意 |
   | 118 総勘定元帳設定 | `GeneralLedgerSetup` | ショートカットディメンション3～8。任意 |
   | 479 ディメンションセットエントリ | `DimensionSetEntries` | ショートカットディメンション3～8。任意 |
   | 573 詳細顧客元帳エントリ | `DetailedCustLedgEntries` | 未決済項目と支払。任意 |
   | 574 詳細仕入先元帳エントリ | `DetailedVendorLedgEntries` | 未決済項目と支払。任意 |
   | 371 銀行口座一覧 | `BankAccounts` | 銀行残高。任意 |
   | 277 銀行口座転記グループ | `BankAccountPostingGroups` | 銀行残高。任意 |
   | 在庫転記設定（ページを検索してください） | `InventoryPostingSetup` | 品目の購入明細の勘定科目。任意 |

4. **PlaidCloudユーザーに3つの選択内容を伝えます。** 監査修正の転記に使用するソースコード（PlaidCloudは`ADJUSTMENT`を想定しています）、部門にあたるディメンション（PlaidCloudはグローバルディメンション1の`DEPARTMENT`を想定しています）、プロフィットセンターにあたるディメンション（PlaidCloudはグローバルディメンション2の`PROFITCENTER`を想定しています）です。サイトはBusiness Centralのロケーションにあたります。

</Steps>

## 返送する情報

| 管理者が送る情報 | PlaidCloudでの入力先 |
|---|---|
| ディレクトリ（テナント）ID | **Azure ADテナントID** |
| アプリケーション（クライアント）ID | **クライアントID** |
| クライアントシークレット | **クライアントシークレット**（メールではなく、接続エディターで入力） |
| 環境名（例: `production`） | **環境** |
| 1つの会社のID | **会社ID**：接続には1つ必要です。Data Foundationは**会社**で選択した会社を読み取ります |
| 部門にあたるディメンションの名前 | システム設定**Department dimension** |
| プロフィットセンターにあたるディメンションの名前 | システム設定**Profit centre dimension** |
| 監査修正の転記に使用するソースコード | システム設定**Audit adjustment source code** |
| PlaidCloudが読み取ってよい会社 | **オプション**の**会社**：会社にチェックを入れます。どれにもチェックを入れない場合は、すべての会社が対象になります |

連結会社にあたる会社は、システム設定**Consolidation companies**に指定します。これにより、連結会社のエントリが会社の活動として集計されなくなります。為替レートは1つの会社から取得します。システム設定**Exchange rate company**でその会社を指定してください。指定しない場合、PlaidCloudは最初の会社を使用します。

## アクセスの確認

PlaidCloudに戻り、システムを追加したら、**システム**ページのそのシステムの行で**接続をテスト**をクリックします。各データセットは、**読み取り可能**、**権限が不足しています**、**エラー**のいずれかで表示されます。

| データセット | 必要なもの |
|---|---|
| エンティティ、勘定科目表、顧客、製品、為替レート、試算表 | APIアクセス（権限セットD365 READ） |
| 会計カレンダー | `AccountingPeriods`Webサービス |
| 部門 | `DimensionValues`Webサービス |
| 総勘定元帳 | `GLEntries`Webサービス |
| その他のすべてのデータセット | 任意。テストの対象外 |

データセットが不足している場合は、追加する権限またはWebサービスがテスト結果に表示されます。管理者に追加を依頼してから、もう一度テストしてください。

任意のデータセットは、サイト、プロフィットセンター、仕入先、月末残高、銀行残高、在庫残高、売上明細、仕入先請求書明細、未決済項目、支払、予算、配賦ドライバーです。いずれかを使用しない環境でも、それ以外のデータはすべて読み込まれます。次回のロード後、**CFM-Accounting - Close and assurance**ダッシュボードの準備状況チェックに、Business Centralが拒否したページが表示されます。月末残高は各月末時点の試算表で、銀行残高は、銀行口座の転記先となる勘定科目のその残高です。ある月の月末残高、銀行残高、在庫、売上明細、仕入先請求書明細、未決済項目、支払の作成元となる読み取りをBusiness Centralが拒否した場合、その月は既存の行を保持し、次回のロードで再度読み取られます。
