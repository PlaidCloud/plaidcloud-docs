**転記レジスター**には、閲覧を許可されたすべてのプロジェクトとシステムにわたって、ERPシステムに転記されたすべてのドキュメントが一覧表示されます。最初に開くのは **要対応** で、担当者が対応する必要のあるドキュメントが表示されます。そこから任意の転記を開き、その状態になっている理由を確認して、対応できます。

ドキュメントは、**伝票を転記** ステップ、各ERP独自の転記ステップ（**Intacct: 仕訳の転記** など）、転記ファイル、および後述の取消、貸方、訂正の操作からレジスターに届きます。実行の開始、チェック、送信の方法については、[ERPシステムに伝票を転記する](/ja/guides/connections/post-documents/)を参照してください。システムの設定方法については、[ERPシステム](/ja/guides/connections/erp-systems/)を参照してください。

## レジスターを開く

**転記レジスター** アプリを開きます。[誰が何を見られるか](#誰が何を見られるか)で説明している `erp.register.*` 権限のいずれかを持つメンバーに表示されます。常に **要対応** が最初に開きます。

左のレールには、3つのグループがあります。

| グループ | ページ |
|---|---|
| **転記** | **要対応**、**転記**、**実行回数** |
| **自分の対応待ち** | **承認**、**委任**、**自分のウォッチ** |
| **設定** | **システム**、**保留ルール**、**変更履歴**、**エクスポートとアラート**、**保持期間** |

**要対応** と **承認** には、レールに件数が表示されます。**保持期間** は、`erp.register.admin` を持っていない場合は非表示です。**実行回数** は転記の実行の一覧を開き、**システム** と **保留ルール** については、[ERPシステムに伝票を転記する](/ja/guides/connections/post-documents/)と[ERPシステム](/ja/guides/connections/erp-systems/)で説明しています。

PlaidCloudの他の場所からもレジスターを開けます。

- **ホーム** には、対応が必要なものがある間、**要対応** と **承認待ち** の件数とともに **転記レジスター** カードが表示されます。これを選択すると **要対応** が開きます。
- コマンドパレットには、**要対応** と **承認** が件数とともに表示されます。台帳IDを入力し、**転記を検索** に続けてIDを選択すると、その転記が開きます。

### ライブ更新

レジスターは自動的に最新の状態を保ちます。システム上で転記が変更されると、レールの件数が再読み込みされ、開いている一覧には、行を動かす代わりに **読み込み後に転記が変更されました** と **更新** ボタンが表示され、開いている転記はその場で再読み込みされます。

## 誰が何を見られるか

### 権限

レジスターを開いて操作するための権限は4つあります。1つを持っていても、別の権限が付与されるわけではありませんが、`erp.register.operate`、`erp.register.approve`、`erp.register.admin` が必要な操作には、`erp.register.view` も必要です。すべての操作は、画面の表示にかかわらず、必要な権限をサーバー側でチェックします。

| 権限 | 許可される内容 |
|---|---|
| `erp.register.view` | レジスターを開く。**要対応**、**転記**、転記の詳細を読む。**転記** で質問する。コメントと承認記録を読む。 |
| `erp.register.operate` | **取消…**、**貸方票…**、**訂正…**、**記帳ファイルとしてダウンロード…**。**保存済みレポートから確定**。**転記されたかどうかを報告** と **解決…**（どちらも `erp.register.approve` が追加で必要）。コメント、承認記録、ウォッチ。**承認** を開く、自分のリクエストを取り下げる、承認権限があれば他の人のリクエストを決定する。委任の表示と取り消し。ダウンロード、スケジュール、証跡エクスポート。 |
| `erp.register.approve` | 取消の承認。**保留中のドキュメント** の読み取りと決定。自分の承認の委任。**未確認** の転記が通ったかどうかの報告。 |
| `erp.register.admin` | 監査人プロファイルでのエクスポートと証跡エクスポート。他のメンバーのスケジュールの管理。**保持期間** の設定。[保留ルール](/ja/guides/connections/erp-systems/)の変更。 |

4つの組み込みセキュリティグループが、これらをまとめています。**転記レジスター閲覧者**（view）、**転記レジスターオペレーター**（operateを追加）、**転記レジスター承認者**（approveを追加）、**転記レジスター管理者**（4つすべて）です。

一部の操作には、レジスターの権限ではなくプロジェクトの権限が必要です。**再試行** と **システムで確認** には `analyze.workflow.write` が必要で、**再試行** には、転記のプロジェクトでのアーキテクトまたはマネージャーのロールも必要です。**変更履歴** には `analyze.connection.read` が必要です。

REST APIまたはMCPツールからレジスターを使う場合も、同じ権限と閲覧のルールが適用されます。各ルートとツールは、画面と同じチェックを実行します。

### 閲覧できる転記

レジスターの権限があればレジスターは開きますが、それだけでは転記は1件も表示されません。転記が表示されるのは、次のすべてに該当する場合のみです。

- **そのシステムの接続に対する個人の付与がある。** 接続を所有しているか、接続に名前が指定されているか、接続に指定されたセキュリティグループに属している必要があります。接続の[セキュリティモデル](/ja/guides/connections/create-connection/#セキュリティモデル)を参照してください。**すべてのワークスペースメンバー** と共有された接続は対象外で、サービスアカウントの付与も対象外です。
- **プロジェクトに属している場合は、そのプロジェクトを開ける。**
- **プロジェクトがそのエンティティの閲覧を許可している。** プロジェクトが `entity` の行アクセスによってメンバーを特定のエンティティに制限している場合、そのエンティティの転記のみが表示されます。プロジェクトアーキテクトは制限されません。

アクセス権はリクエストのたびに再読み込みされるため、付与を取り消すと、次にページを読み込んだときに有効になります。接続の付与がないメンバーには、空の一覧ではなく **表示するシステムがありません** と表示されます。

## 7つの状態

すべてのドキュメントは、転記した手段にかかわらず、7つの状態のいずれかで表示されます。すべてのピル、チップ、フィルターに同じ言葉が使われます。

| 状態 | 意味 |
|---|---|
| **転記予定** | チェック済み。システム、または実行がシミュレートのため、何も送信されていません。 |
| **承認が必要** | ルールにより、担当者の承認が必要なため保留されています。 |
| **待機中** | 承認済みで、送信される直前または送信済みです。システムはまだ応答していません。 |
| **転記済み** | ERPがこの転記を受け付けました。 |
| **未転記** | チェックで停止された、またはシステムが拒否しました。理由に原因が示されます。 |
| **未確認** | 応答がなく、システムに問い合わせることもできません。転記されたかどうかを報告してください。 |
| **取消済み** | 後の転記によって、この転記が取り消されました。 |

## 表示対象を選択する

**要対応** と **転記** は1つのスコープを共有しているため、一方で設定したフィルターは、もう一方にも有効です。ページヘッダーの下のバーに、それが表示されます。絞り込んだ項目は、削除できるチップとして表示され、デフォルトのままの項目は、**すべてのシステム** のように言葉で示されます。

**範囲を変更** を選択して編集します。

- **転記済み** — **今月**、**前月**、**過去7日間**、**過去30日間**、または **カスタム**。**カスタム** では **開始** と **終了** の日付を指定します。デフォルトは過去30日間です。
- **システム** と **プロジェクト** — 閲覧できるものから選択します。
- **エンティティ** — **詳細設定 ▾** の下にあります。

**リセット** で、スコープがデフォルトに戻ります。バーの下の **状態** チップの行で、一覧を1つの状態に絞り込めます。

ブラウザーのアドレスにスコープが含まれているため、ブックマークしたり、同僚に送ったりできます。開いた人には、その人自身のアクセス権で許可されたものだけが表示されます。

## 要対応

**要対応** には、担当者が対応する必要のあるすべてのドキュメントが、承認、**未確認**、**未転記**、確認が必要な転記済みドキュメントの順に一覧表示されます。行を選択すると開きます。ページ名の下の行には、要対応の件数と、そのうち承認待ちの件数が、たとえば「12件が要対応 · 3件が承認待ち」のように表示されます。

各行には、**参照**、**エンティティ**、**システム**、**金額**、**通貨**、**状態**、**理由**、**次の対応**、**モード** が表示されます。**プロジェクト** と **タイプ** は非表示の列で、表示できます。**理由** は最初の理由を平易な言葉で示し、ほかにもある場合は「（ほか2件）」と表示されます。**次の対応** は、それに対して何をするかを示します。

**モード** には **本番** または **シミュレーション** と表示されます。シミュレートされたドキュメントにも担当者の対応が必要です。チェックに失敗した場合は、転記する前に修正する必要があります。そのため、リンクでどちらかのモードを指定しない限り、このページには両方が表示されます。

ここでの **状態** チップは、**承認が必要**、**未転記**、**未確認**、**転記済み** です。何も該当しない場合、ページには **問題なし** と表示されます。「担当者の対応が必要なものはありません。すべてのドキュメントが転記済み、待機中、または転記予定です。」スコープを絞り込んでいる場合は、**範囲をリセット** が表示されます。

### ドキュメントが要対応になる理由

**未転記** のドキュメントには、停止した理由が示されます。何かが送信される前のチェックによる理由は、ソースまたはシステムで修正してから、再度実行します（[ERPシステムに伝票を転記する](/ja/guides/connections/post-documents/)を参照）。ほとんどの場合、**次の対応** には **修正して再実行** と表示されます。エンティティにシステムがないドキュメントでは **再試行** と表示され、システムを追加すると、ドキュメントが再び振り分けられます。`~` を含む、または長すぎる参照では、**次の対応** は空白です。

| 表示される理由 | 対処方法 |
|---|---|
| エンティティに転記するシステムが設定されていない | **システム** で、そのエンティティのシステムを選択します。 |
| そのシステムは廃止されている | 別のシステムに転記します。 |
| システム上で期間が締められている | 期間を開くか、次の期間に転記します。 |
| 勘定科目がシステムに存在しない | システムで作成するか、コードを別の勘定科目に対応付けます。 |
| コードがシステムに対応付けられていない | **システム** で対応付けます。 |
| この支払が支払う請求書が未決済ではない | システムで請求書を確認します。 |
| そのシステムが転記する会社とは別の会社のものである | その会社のシステムに振り分けます。 |
| 明細が、システムが記帳しない通貨である | システムの通貨で転記するか、別のシステムに転記します。 |
| システムが必要とする値が空である | ソースで入力します。 |
| 借方と貸方が一致しない | ソースを修正して、再度実行します。 |
| セットの一部が欠けている、またはセットのドキュメントが一致しない | セットは、すべてのドキュメントがそろっていて一致している場合にのみ転記されます。 |
| 参照がすでに別のシステムに転記されている、またはこのシステムですでに使用されている | 修正してから、再度実行します。 |
| 参照に `~` が含まれている、またはシステムに対して長すぎる | ソースで参照を変更します。PlaidCloudはバージョンの採番に `~` を使用します。 |
| このシステムは、この種類のドキュメントにまだ対応していない | 修正してから、再度実行します。 |
| この参照の以前のバージョンに、システムからまだ応答がない | 応答があってから、再度実行します。 |

そのほかの理由は、チェックに合格した後に起きたことを示しており、**次の対応** には[**再試行**](#再試行)が表示されます。承認者が却下した、送信前に実行が停止された、システムのエージェントがオフラインだった、システムに届く前に何かが失敗したため送信されなかった、システムが拒否した、または期限の時点でPlaidCloudが確認したがシステムにはなかった、などです。

残りは、**未転記** ではなくても対応が必要です。

| 理由 | 状態 | 次の対応 |
|---|---|---|
| 承認が必要で、それを保留しているルールが示される | **承認が必要** | **承認** — [承認](#承認)を参照してください。 |
| システムが時間内に応答せず、ドキュメントが転記されたかどうかを問い合わせることもできない | **未確認** | **転記されたかどうかを報告** — [未確認の転記](#未確認の転記)を参照してください。 |
| 転記後にソースが変更された | **転記済み** | **このバージョンで修正** または **転記済みのものを維持**。実行ページで回答します。 |
| セットの一部のみが転記された | **転記済み** | **修正して再実行** |
| 転記済みだが、システム自身の記録にない、または記録が異なる | **転記済み** | **システムで確認** |
| 転記後にシステムで変更された | **転記済み** | **システムで確認** |
| PlaidCloudを通さずにシステムに入力された | **転記済み** | **システムで確認** |

PlaidCloudを通さずにシステムに直接入力されたエントリは、プロジェクト、システム、エンティティ、月ごとに1行にまとめられます。たとえば「2026年10月 の 4 件の仕訳は PlaidCloud 以外で作成されました」のようになります。これらの行は、一覧を絞り込むフィルターがない場合にのみ表示され、上部の件数には含まれません。**転記済み** の日付はフィルターとして数えられ、範囲は直近30日から始まるため、これらの行は、**範囲を変更** で **転記済み** の **カスタム** を選択し、**開始** と **終了** を空のままにすると表示されます。

## 転記

**転記** には、閲覧できるすべてのドキュメントが、1ドキュメントにつき1行で一覧表示されます。**参照**、**タイプ**、**エンティティ**、**システム**、**プロジェクト**、**金額**、**通貨**、**状態**、**システムドキュメント**、**転記日**、**開始者**、**承認済み**、**モード** です。**システムドキュメント** は、システムが付与した番号で、続けて、システム自身の記録でチェックが見つけた場合は **帳簿上** と表示されます。**承認済み** には **自動** または **担当者による操作** と表示されます。ページ名の下の行には、転記の件数と通貨別の合計が表示されます。通貨が合算されることはありません。

ヘッダーには次の項目があります。

- 検索ボックスでは、入力するたびに、参照、システムドキュメント、金額が検索されます。
- **質問** は、同じ検索ボックスに入力した自分の言葉による質問を受け付けます。たとえば「10月に転記したものは？」です。状態、エンティティ、モード、月を理解し、閲覧が許可された範囲を絞り込むことしかできません。一覧には、最初の25件の一致と、何が理解されたかを示す文が表示されます。
- **本番**、**シミュレーション**、**すべて** で、表示する転記を選択します。デフォルトは **本番** です。

**状態** チップは、7つの状態すべてを網羅しています。長い一覧は1,000行で通知とともに止まり、**さらに読み込む** で次の1,000行が読み込まれます。

1つ以上の行にチェックを付けて、ツールバーの **アクション** メニューから **取消…**、**貸方票…**、**訂正…**、または **記帳ファイルとしてダウンロード…** を、それらすべてに対して一度に実行できます。これらには `erp.register.operate` が必要で、[取消、貸方、訂正](#取消貸方訂正)で説明するとおりに動作します。PlaidCloudを通さずにシステムに入力された行は、ここでは操作できません。

## 転記ドロワー

行の虫眼鏡アイコン、または **要対応** で行を選択して、転記を開きます。転記は、一覧の横の右側にドロワーとして開きます。

ドロワーの上部には、状態のピル、続いて各理由が平易な言葉で、その下にシステム自身のメッセージが表示され、さらに転記の事実が表示されます。**参照**、**タイプ**、**金額**、**システムドキュメント**、**システム**、**環境**、**エンティティ**、**転記日**、**プロジェクト**、**ワークフロー**、**ステップ**、**開始者**、**承認済み**、**モード** です。承認待ちの取消には、「この取消には、2人目の担当者の承認が必要です。開始した人は承認できません。」とも表示されます。

残りの内容は、5つのタブにあります。

| タブ | 表示内容 |
|---|---|
| **明細** | 各明細の **勘定科目**、**説明**、**借方**、**貸方**、**ディメンション**。 |
| **履歴** | ドキュメントに起きたこと、いつ、誰によるか。 |
| **バージョン** | `INV-100` や `INV-100~2` のような、参照のすべてのバージョンと、その状態、および現在表示しているバージョン。 |
| **リンク** | 由来と関連するもの。**ソースの行**、**ステップのバージョン**、**ステップの最終変更者**、**取消対象**、**取消元**、**貸方**、および **添付ファイル**。 |
| **承認** | 転記のレビュー記録とコメント。[承認記録とコメント](#承認記録とコメント)を参照してください。 |

ドロワーの **アクション** メニューには、**リンクをコピー** があり、閲覧を許可されている人なら誰でもこの転記を開けるリンクをコピーします。該当する場合は、**システムで開く**（QuickBooks Onlineの転記で、直接開けるもの）、**接続をウォッチ**（転記に接続がある場合）、**実行をウォッチ**（実行がある場合）も表示されます。`erp.register.operate` を持つメンバーには、ここに **貸方票…**、**訂正…**、**記帳ファイルとしてダウンロード…**、**システムで確認** も表示され、メニューの横のボタンとして **転記されたかどうかを報告** と **取消…** が表示されます。`erp.register.operate` がない場合、フッターには「取消には転記レジスターオペレーターのロールが必要です。」と表示されます。**再試行** は、該当するユーザーに対してメニューの横に表示されます。[再試行](#再試行)を参照してください。

各操作は、転記の状態が許可する場合にのみ提示され、グレーアウトされた項目には、ポインターを合わせるとその理由が表示されます。

### 再試行

**再試行** は、**次の対応** がそれを提示し、ドキュメントに台帳エントリがあり、`analyze.workflow.write` を持っている場合に表示されます。最初に、何が送信されるかをチェックします。再試行できるものがない場合は、その理由を示します。そうでない場合は、システムに「保存されたドキュメントを再度送信します」と確認し、**再試行** を選択すると、保存されたコピーが、プロジェクトの転記上限のもとで、新しい実行として再度送信されます。

ドキュメントが再試行されるのは、システムが記帳していないことが確実な場合のみ、つまり **未転記** または未送信の場合です。さらに、そのプロジェクトのアーキテクトまたはマネージャーのロールと、その接続に対する自身の付与が必要です。

### 取消、貸方、訂正

**転記済み** のドキュメントのみ、取消、貸方処理、訂正ができます。

- **取消…** は、システム内の転記を取り消します。
- **貸方票…** は、転記済みの請求書に対して貸方票を発行します。顧客請求書と仕入先請求書にのみ適用されます。1件の転記に貸方処理をする場合は、**金額** を空白のままにすると請求書全体が対象になり、金額を入力すると一部が対象になります。
- **訂正…** は、現在のバージョンを取り消し、PlaidCloudが、まだ転記されていない新しいバージョンのドキュメントを保持している場合は、それを次のバージョン（`REF~2`）として送信します。ソースが転記後に変更された転記にも提示されます。

それぞれ、最初に何が可能かをチェックするダイアログが開きます。いくつの転記が、どのシステムで、どのように（「システム自身の取消」「貸方票」「反対仕訳」）処理されるか、そして処理できないものとその理由です。セットの一部として転記されたドキュメントを取り消すと、セットの残りも一緒に取り消されます。**理由** を入力し、必要に応じて **日付**（初期値は今日）を変更して確定します。ボタンには、**取消 3** のように、転記の件数が表示されます。

その後、操作はほかの転記と同じように実行されます。新しい実行として記録され、チェックされ、ルールで保留された場合は承認され、送信され、確認され、実行ページが開きます。1回の操作で扱える転記は最大200件です。

取消、貸方、訂正は本番への書き込みであるため、プロジェクトがシミュレートに上限設定されている場合、プロジェクトがそのシステムへの転記を認可されていない場合、またはその接続に対する個人の付与がない場合、転記は拒否されます。システムによっては、その画面から転記を取り消す方法がなく、Sage 100 もその1つです。その場合はダイアログにその旨が表示され、[各システムでできること](/ja/guides/connections/erp-systems/#各システムでできること)の **取消可能なもの** 列で確認できます。

### 職務分掌

ワークスペースで職務分掌がオンになっている場合、しきい値以上の取消には、2人目の担当者の承認が必要です。職務分掌とそのしきい値は、PlaidCloudがワークスペースに対して設定します。レジスターには、その設定はありません。

- ドキュメントは実行で **承認が必要** と表示され、その転記の接続に対する付与を持つすべての承認者に、承認リクエストが送られます。宛先を指定する必要はありません。接続の付与が振り分けになります。
- 承認者は、`erp.register.approve` または、それを持つ人からの有効な委任と、接続に対する自身の付与を持っている必要があります。取消をリクエストした人は、委任を通じてであっても、承認できません。
- 承認は、まさにその取消、つまり転記、その理由、日付を対象とします。承認され、5分間の保留時間が過ぎたら、同じ理由と日付で同じ操作をもう一度実行すると、処理されます。
- 同じ接続での、過去24時間の送信者の取消は、合計してしきい値に対してカウントされるため、大きな取消を小さく分割してしきい値を回避することはできません。
- 接続で承認する資格のあるメンバーが2人未満の場合、承認が必要な取消は拒否されます。

### 記帳ファイルとしてダウンロード

**記帳ファイルとしてダウンロード…** は、**アクション**（**取消**、**貸方**、**訂正**）と **形式**（**Excel** または **CSV**）を尋ね、その操作用の記入済みの記帳ファイルを保存します。金額や明細を編集してから、REST APIまたはMCPツールを使ってファイルから転記します。[ERPシステムに伝票を転記する](/ja/guides/connections/post-documents/)を参照してください。

### システムで確認

**システムで確認** は、転記をそのシステムで今すぐ検索し、シミュレートは行いません。**システムで見つかりました。** または **システムで見つかりません。** と表示されるか、システムに問い合わせられなかった理由が表示され、転記の **帳簿上** のステータスが更新されます。`analyze.workflow.write` が必要です。

### 承認記録とコメント

**承認** タブでは、**レビュー済みにする**、**クリア済みにする**、または **フォローアップが必要** と、任意の **注記** で、転記のレビューを記録します。現在の承認記録とそれ以前のすべてが表示されます。

その下の **コメント** には、転記に関するプレーンテキストのメモが入ります。コメントを入力し、メンションするメンバーIDを列挙して、**コメントを投稿** を選択します。メンションされたメンバーに通知されるのは、通知の送信時にその転記を閲覧できる場合のみです。

コメントと承認記録は、追加には `erp.register.operate`、読み取りには `erp.register.view` が必要です。まだ台帳エントリがないドキュメントには、「このドキュメントには、まだコメントと承認記録は使用できません。」と表示されます。

### ウォッチ

ドロワーの **アクション** メニューの **接続をウォッチ** と **実行をウォッチ** を選択すると、以降、転記の接続または実行でのアクティビティが通知されます。オンにすると、**接続をウォッチ中** と **実行をウォッチ中** と表示されます。通知が届くのは、その通知の対象の転記を引き続き閲覧できる間のみです。ウォッチには `erp.register.operate` が必要です。

## 未確認の転記

システムが時間内に応答せず、ドキュメントが転記されたかどうかを問い合わせられない場合、転記は **未確認** になります。担当者が、システムで見つけたものをもとに確定します。

### 転記されたかどうかを報告

転記を開き、**転記されたかどうかを報告** を選択します。システムでドキュメントを探して、次のいずれかを選択します。

- **転記されました** を選択し、システムでの **ドキュメント** 番号を入力します。転記はその番号とともに **転記済み** になります。
- **転記されませんでした** を選択します。転記は **未転記** になり、再試行できます。

見たものを説明する **注記** は必須です。誤った回答は、ドキュメントの二重転記や、システムに届いていないドキュメントの記録につながる可能性があるため、`erp.register.operate`、`erp.register.approve`、およびその接続に対する自身の付与が必要です。`erp.register.approve` がない場合、ボタンはグレーアウトされ、その旨が表示されます。システム自身の応答が先に届いた場合は、その応答が優先されます。

### 台帳エントリの解決

コマンドパレットの **転記を検索** で台帳IDから開いた転記は、**要確認** または **却下** の場合（シミュレートされただけのものを除く）、**解決…** が表示されます。システムが保持している内容を確認してから、次のいずれかを選択します。

- **ERP に存在する**。転記は **転記済み** になります。システムにドキュメントを問い合わせられる場合、PlaidCloud はそこからドキュメントIDを取得し、システムにそのドキュメントがない場合、転記されていないまま保持している場合、または入力したIDと異なるIDで保持している場合は、拒否します。システムに問い合わせられない場合や、応答が得られない場合は、表示されるボックスにシステムでのドキュメントIDを入力します。
- **ERP に存在しない**。転記が **要確認** の場合にのみ表示されます。転記は **却下** になり、再試行できます。システムでそのドキュメントが転記済み、またはその他の有効な状態として表示される場合、応答が得られない場合、または送信するジョブがまだ実行中の場合は、拒否されます。システムにドキュメントを問い合わせられない場合、**再試行** はチェックせずにもう一度送信します。

**理由** は必須です。解決するには、`erp.register.operate`、`erp.register.approve`、およびその接続に対する自身の付与が必要です。**再試行** は、**却下** の転記のシステムがすでにそれを保持していると判明した場合（そこで無効化または削除された場合を除く）、再送信せず、代わりに **解決…** を使うよう案内します。

### 保存済みレポートから確定

SAPの転記は、実行のレポートを残します。**要対応** では、何かが **未確認** で、`erp.register.operate` を持っている間、ツールバーに **保存済みレポートから確定** が表示されます。チェックした行のレポート、チェックした行がない場合はスコープ内のすべてのシステムのレポートを読み取り、いくつのドキュメントが **転記済み** に確定されるかを表示し、確定できないものとその理由を一覧表示します。適用するには、**3件のドキュメントを確定** のように件数を示すボタンを選択します。

レポートからの確定では、ドキュメントを **転記済み** に移すだけで、却下としてマークされるものはありません。レポートがない、それを送信した実行より古い、または転記されたことが示されていないドキュメントは、**未確認** のままです。

## 承認

**承認** は、自分の判断を待っているものを決定する場所です。ヘッダーのチップで、次を切り替えます。

- **自分の承認待ち** — 自分が決定できる取消の承認リクエスト。
- **自分が送信** — 自分が行ったリクエスト。
- **保留中のドキュメント** — 2人目の担当者を待っている取消、貸方、訂正で、`erp.register.approve` を持っている場合にのみ表示されます。

ヘッダーの **委任** リンクは、[委任](#委任)を開きます。

### 取消リクエスト

各リクエストには、エントリ、その金額とエンティティ、依頼者とその経過時間、取り消す期間、依頼者の理由が表示されます。**承認** または **却下** を選択し、決定とともに記録される理由を入力して確定します。複数をまとめて承認するには、それらにチェックを付け、ヘッダーの **選択を承認 (3)** ボタンを選択します。ボタンにはチェックを付けた行数が表示されます。

- 承認後、メッセージには8秒間 **元に戻す** が表示され、5分間の保留の間は、行に **承認を取り消す** が表示されます。保留時間が過ぎると、取消がすでにシステムに入っている可能性があります。
- **自分が送信** では、**取り下げ** で、まだ待機中または承認済みのリクエストを取り下げられます。
- 4時間待機したリクエストには **エスカレーション済み**、24時間後には **2回エスカレーション済み** と表示されます。決定されないまま7日経つと期限切れになり、改めてリクエストする必要があります。

承認権限がない場合、ページにはリクエストの一覧の代わりに **取消を承認する権限がありません** と表示されます。

### 保留中のドキュメント

**保留中のドキュメント** には、2人目の担当者を待っている取消、貸方、訂正が最初に、続いて、古い順に、[保留ルール](/ja/guides/connections/erp-systems/)が保留しているドキュメントが一覧表示されます。実行ごとにグループ化されます。異常な大きさとしてフラグ付けされたドキュメントには **異常** と表示されます。

**承認** を選択してドキュメントを送信するか、実行のカードにある、**3件のドキュメントをすべて承認** のようにドキュメントの数を示すボタンを選択すると、表示されているすべてのドキュメントが、送信先のシステムを示す確認の後に承認されます。**却下** は理由を尋ね、ドキュメントを **未転記** にします。承認されたドキュメントは、実行のモードと、プロジェクトの現在の上限および認可のもとで送信されます。

自分が開始した、または送信した実行のドキュメントや、自分が行った転記に対する操作のドキュメントは決定できません。ほかの人が承認する必要があります。セットは全体として承認されるため、自分が決定できないドキュメントが含まれるセットは、決定できる人に任されます。

## 委任

**委任** では、承認者が、不在のときなど、一定期間、自分の承認権限を別のメンバーに渡すことができ、自分に渡された権限も表示されます。**自分が委任** と **自分に委任** の2つのカードが一覧表示されます。

**承認を委任** を選択し、**メンバー** を選び、**日** 数（デフォルトは7日、最大30日）を設定し、監査証跡に記録される **理由** を入力します。**取り消し** で委任を早期に終了できます。どちらの側からでも取り消せます。

- 委任には `erp.register.approve` が必要です。委任の表示と取り消しには `erp.register.operate` のみが必要です。委任される相手は、通常、承認者の権限を持っていないためです。だからこそ、その人に委任します。その人は `erp.register.operate` を持っている必要があります。
- 自分自身、自分に委任した人、サービスアカウントには委任できず、委任された人がその権限を他の人に渡すことはできません。
- 委任された人は、自分に委任した人が行ったリクエストを承認できません。委任された人が承認する間、**承認** のヘッダーには、誰の権限を使用しているかが表示され、各決定は、その承認者の権限で行われたものとして記録されます。

## 自分のウォッチ

**自分のウォッチ** には、ウォッチしている接続と実行が一覧表示されます。**接続をウォッチ** を選択して、閲覧できる接続の1つを追加し、**ウォッチを停止** で削除します。メッセージの **元に戻す** で、再度ウォッチします。

## エクスポートとアラート

**エクスポートとアラート** は、レジスターがファイルまたは通知としてPlaidCloudの外に出る場所です。ここでのすべてに `erp.register.operate` が必要です。ない場合、ページには、レジスターは読み取れるがエクスポートはできないと説明されます。

<Aside type="caution">
ダウンロードしたファイルは、PlaidCloudの外に出ます。権限、ロール、マスキングは、ファイルが作成されるたびに（スケジュールされた送信ごとを含む）チェックされますが、配信後には何もチェックされません。自由記述のフィールドは、すべてのエクスポートから除外されます。
</Aside>

### ファイルに含まれる内容

すべてのファイルは、作成される時点の自分自身のアクセス権から、2つのプロファイルのいずれかで作成されます。

- **スタンダード** — 金額、通貨、各ドキュメントを転記したメンバーは含まれません。
- **監査人** — 金額、通貨、各ドキュメントを転記したメンバーが含まれます。このプロファイルには `erp.register.admin` が必要です。

エクスポートで使用されるプロファイルは、ページに表示されます。

### 今すぐダウンロード

ツールバー（または **アクション** メニュー）から、次を実行できます。

- **CSVをダウンロード** と **JSONをダウンロード** は、レジスターをエクスポートします。エクスポートスケジュールを選択している場合、ファイルはそのスケジュールのフィルターを使用します。
- **証跡エクスポート…** は、1つの期間の証跡を作成します。[証跡エクスポート](#証跡エクスポート)を参照してください。

### スケジュールとアラート

**新しいスケジュール** を選択して、次を入力します。

- **名前** と **種類**：**エクスポートファイル** または **アラート**。
- エクスポートファイルの場合は **形式**（CSVまたはJSON）、アラートの場合は **送信条件**：**本番の転記が失敗したとき**、**承認が滞留しているとき**、**取消仕訳が転記されたとき**。
- **頻度**：**オンデマンド**、**毎日**、**毎週**、**毎月**。
- **受信者**：PlaidCloudのメンバー。メールアドレスは指定できません。
- 必要に応じて、絞り込みのための **接続** と **エンティティ**。

毎日実行されるジョブが、前回の送信から間隔が経過した **毎日**、**毎週**、**毎月** のスケジュールをすべて送信します。**オンデマンド** のスケジュールは、**今すぐ送信** を選択したときにのみ送信されます。**スケジュールを削除** は、スケジュールを完全に停止します。

各受信者は、送信の時点でその人自身のアクセス権で許可されたものを受け取るため、1つのスケジュールの2人の受信者が、異なるファイルを受け取ることもあります。エクスポートのロールを持たなくなった受信者、接続の付与がない受信者、メールアドレスがない受信者、無効になっている受信者はスキップされ、**今すぐ送信** には、誰が、なぜスキップされたかが表示されます。スケジュールを送信または削除できるのは、そのスケジュールの所有者、または `erp.register.admin` を持つメンバーのみです。

### 証跡エクスポート

**証跡エクスポート…** は、1つの期間を5つの部分で保存します。何が転記されたか、帳簿に何があるか、誰が承認したか、ルールとロジックで何が変わったか、誰が何をできたかです。**期間**（たとえば `2026-10`）を入力し、必要に応じて **エンティティ** の下で1つ以上のエンティティを指定し（空白はすべて）、**Excel** または **JSON** を選択して、**ダウンロード** を選択します。

ファイルには、期間内の日付で、閲覧できる本番の転記が含まれます。スタンダードプロファイルでは、金額とすべての担当者（開始した人、リクエストした人、決定した人、変更した人、承認者の理由、ルールの変更前後、アクセスのセクション）が除外されるため、完全な記録を含むのは、監査人プロファイルです。

## 変更履歴

**変更履歴** には、システムの設定、システムの廃止、SAP関数、コード対応、どのエンティティがどこに転記されるか、保留ルール、本番稼働、リストのコピーに対するすべての変更が、**日時**、**実行者**、**対象**、**システム**、**対象**、**開始**、**終了** とともに一覧表示されます。最大2,000件の変更が表示されます。残りを見るには、1つのシステムに絞り込みます。`analyze.connection.read` が必要です。

## 保持期間

**設定** の下の **保持期間** では、レジスターが3種類の履歴を保持する期間を設定します。**取得（サイドカーのリクエスト／レスポンス）**、**シミュレーションストア**、**監査証跡を書き込む** です。それぞれ、最大3,650日までの日数、または **無制限** を指定します。**保存** を選択すると適用されます。カードには、ポリシーを最後に設定した人と日時が表示されます。誰かが設定するまでは、すべての期限が無制限です。

`erp.register.admin` を持つメンバーのみが、レールに **保持期間** を表示でき、変更できます。毎日のスイープでポリシーが適用されます。

<Aside type="note">
保持期間は、何が転記されたかの記録、つまりドキュメントの二重転記を防ぐものには影響しません。取得の期限を過ぎると、転記の取得されたリクエストとレスポンスはクリアされますが、転記、その状態、詳細は残ります。シミュレーションの期限を過ぎると、シミュレートされた転記は削除されます。
</Aside>
