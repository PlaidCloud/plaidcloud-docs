PlaidCloud を **Anaplan** に接続すると、ワークフローで、Anaplan の大容量読み取りリクエスト経路を通じて保存済みビューを読み取ったり、既存のエクスポートアクションを実行したり、1 つ以上の Anaplan リストを PlaidCloud ディメンションに読み取ったりできます。この接続は Anaplan 独自の Integration API に**クラウド直接**で接続します。これらのステップにはオンプレミスエージェントを経由する経路はありません。このガイドでは、接続、認証、3 つの読み取りステップそれぞれの簡単な紹介、およびスケジュール上の考慮事項を説明します。

<Aside type="note">
このコネクターは読み取り専用です。Anaplan にデータが書き戻されることは一切なく、書き戻しステップも部分適用モードもありません。
</Aside>

## 前提条件

Anaplan のワークスペース管理者から、次のものを入手してください。

- Anaplan の**ユーザー名とパスワード**、または Anaplan のワークスペース管理者が Anaplan ユーザーに登録した **CA 証明書とその秘密鍵**のいずれか。ワークフローで読み取るワークスペースとモデルへの読み取りアクセス権が必要です。以下の[認証](#認証)を参照してください。
- 読み取り元モデルの**ワークスペース ID** と**モデル ID**。Anaplan 自身のモデル設定で確認できます。接続の作成後は、接続からライブで検出することもできます。
- **Anaplan: ビューの読み取り**の場合: 必要な行、列、フィルターのスライスを正確に反映して作成した**保存済みビュー**。以下の [Anaplan: ビューの読み取り](#anaplan-ビューの読み取り)を参照してください。
- **Anaplan: エクスポートの読み取り**の場合: モデルに**すでに存在するエクスポートアクション**。
- **Anaplan: リストの読み取り**の場合: 読み取る階層を構成する Anaplan の**リスト**。

## 認証

接続には**認証モード**があり、**基本**（デフォルト）または **Certificate** を選択します。既存の接続は、変更なしで基本モードのまま動作します。

- **基本**は、Anaplan のユーザー名とパスワードでサインインします。
- **Certificate** は、CA が発行した証明書とその秘密鍵（どちらも PEM テキストとして貼り付け）でサインインします。秘密鍵は **RSA で、暗号化されていない**ものでなければなりません。証明書は、Anaplan のワークスペース管理者があなたの Anaplan ユーザーに登録したもので、お使いのテナントで Anaplan が信頼する CA が発行したものである必要があります。PlaidCloud は鍵でランダムなチャレンジに署名し、Anaplan 自身の証明書認証フローに従って Anaplan トークンと交換します。証明書と鍵を貼り付けたあとに必要な操作はなく、トークンの更新も基本モードと同様に動作します。どちらのフィールドも貼り付けた内容をマスクし、両方のシークレットは基本モードのパスワードと同様に暗号化して保存されます。モードを切り替えても、もう一方のモードの認証情報が送信されることはありません。既存の接続を基本から Certificate に切り替える場合、証明書と鍵は引き継がれないため、あらためて貼り付ける必要があります。

Anaplan の多要素認証は、メールとパスワードでサインインするユーザーに適用されます。Certificate 認証は、自動化されたスケジュール接続向けの、パスワードを使わない選択肢です。

Certificate モードでは、貼り付けた鍵または証明書を読み取れない場合、鍵が暗号化されている場合や RSA でない場合、鍵が証明書と一致しない場合に、Anaplan に接続する前にエラーとなります。Anaplan 自身が証明書を拒否した場合は、エラーに有効期限切れかどうかが示されます。よくある原因は、Anaplan ユーザーに登録されていない証明書、またはテナントで信頼されていない CA です。

## 接続を作成する

<Steps>

1. **Tools > Connections** を開き、`New Connection` をクリックします。

2. メニューから **Anaplan** を選択します。

3. 各フィールドを入力します。

   | フィールド | 値 |
   |---|---|
   | 名前 | わかりやすい名前（例: `Anaplan Prod`）。 |
   | APIホスト | 省略可。空白のままにすると、Anaplan 標準の `https://api.anaplan.com` が使われます。 |
   | 認証ホスト | 省略可。空白のままにすると、Anaplan 標準の `https://auth.anaplan.com` が使われます。 |
   | 認証モード | **基本**（デフォルト）または **Certificate**。上記の[認証](#認証)を参照してください。 |
   | ユーザー名 | Anaplan アカウントのユーザー名。基本モードのみ。 |
   | パスワード | Anaplan アカウントのパスワード。基本モードのみ。 |
   | CA証明書 | Anaplan に登録された X.509 証明書の PEM テキスト。Certificate モードのみ。 |
   | 秘密鍵 | 証明書の RSA 秘密鍵の PEM テキスト（暗号化されていないもの）。Certificate モードのみ。 |
   | デフォルトのワークスペースID | 省略可。読み取りステップの「ワークスペース」フィールドにあらかじめ入力しておく便利機能です。 |
   | デフォルトのモデルID | 省略可。読み取りステップの「モデル」フィールドにあらかじめ入力しておく便利機能です。 |
   | タイムアウト（秒） | デフォルトは 30 です。 |

4. `Test Connection` をクリックします。テストに成功すると、認証情報から解決された Anaplan アカウントのメールアドレスが表示されます。

5. `Create` をクリックします。

</Steps>

## Anaplan: ビューの読み取り

**Anaplan: ビューの読み取り**ステップを追加すると、Anaplan の大容量読み取りリクエスト経路を通じて保存済みビューを読み取れます。**ビューは Anaplan で保存されたとおりに読み取られます。このステップには行、列、ページを選択する機能はありません。** 別のスライスを読み取るには、Anaplan で別の保存済みビューを作成してください。Anaplan では、ブール型の明細項目と保存済みビューを組み合わせてフィルターするのが一般的な方法です。データ列が Anaplan で宣言された型のまま取り込まれるのは、ビューで**明細項目が列軸にある**場合だけです。明細項目が行にある場合（一般的な損益計算書のレイアウト）や、ビューに明細項目がない場合は、すべての列がテキストとして取り込まれ、ステップがその旨を通知します。フィルターに一致する行がないビューは、警告付きで空のテーブルとして取り込まれます。数値の値のうち、曖昧さなく読み取れないもの（多くの場合、通常の小数とも欧州式の表記とも解釈できるもの）は、同じ列内の別の値でどちらの読み方が正しいか判断できない限り、推測せずに拒否されます。解析できた値は、丸め誤差なしの完全な精度で取り込まれます。フィールドと動作の詳細なリファレンスについては、[Anaplan: ビューの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-view/)を参照してください。

## Anaplan: エクスポートの読み取り

**Anaplan: エクスポートの読み取り**ステップを追加すると、Anaplan に**すでに存在する**エクスポートアクションを実行し、生成されたファイルを取り込めます。API ではエクスポートアクションを作成できません。先に Anaplan で作成または編集してください。また、このステップで出力内容を絞り込むこともできません。Anaplan でエクスポート対象として設定されている内容がそのまま取り込まれます。**すべての列がテキストとして取り込まれます。** 数値は US 形式でリクエストされます。それでも桁区切りが付いた状態で返される列は、変更されずテキストとして取り込まれ、実行が失敗する代わりに名前付きの警告が出力されます。エクスポートが失敗した場合、キャンセルされた場合、データが生成されなかった場合、ステップのポーリング予算を使い切ってもまだ実行中の場合、エクスポートに関連付けられないファイルが生成された場合、または Anaplan 自身が報告する件数と行数が一致しない場合、ステップはテーブルを取り込まずに停止します。詳細なリファレンスについては、[Anaplan: エクスポートの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-export/)を参照してください。

## Anaplan: リストの読み取り

**Anaplan: リストの読み取り**ステップを追加すると、1 つ以上の Anaplan リストを PlaidCloud ディメンションに読み取れます。**1 つのステップで複合階層全体を読み取ります。** 階層をいくつものステップに分割せず、階層にまたがるすべてのリストを、ルートから順に指定してください（例: Region、Country、Store の順）。ステージングテーブルは実行のたびに置き換えられるため、1 つのステージングテーブルを複数のステップに指定すると、それぞれが前のステップの行を消去してしまいます。Anaplan のリスト階層にはエッジごとの重みや符号がないため、すべてのエッジは単純な `+` でロールアップされます。Anaplan のリストのアクセス制御とサブセットのメンバーシップはインポートされません。これらはディメンションデータではなくメタデータだからです。ノード ID の重複、解決できない親参照、競合する親参照、インポートされるメタデータと衝突するプロパティ名がある場合は、何も取り込まれる前に拒否されます。詳細なリファレンスについては、[Anaplan: リストの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-list/)を参照してください。

## Data Foundation のソースとしての Anaplan

[Data Foundation](/ja/guides/projects/data-foundation/) は、Anaplan が保持する計画（予算、予測、連結モデルの結果）を Common Finance Model に読み込めます。取り込むのは計画のみで、元帳は取り込まず、読み取り専用です。

Data Foundation は、モデルの保存されたままのエクスポートアクションを 1 つ実行します。そのため、先に Anaplan 管理者がそのエクスポートを作成する必要があります。**Foundation** タブが、管理者向けの依頼文を作成します。エクスポートは、エンティティ、期間、勘定科目、部門ごとに 1 行となるフラットなグリッドで、列見出しは次のとおりでなければなりません。

| 列 | 内容 |
|---|---|
| `Entity` | エンティティコード。 |
| `Period` | 月（`YYYY-MM` 形式）。 |
| `Account` | 勘定科目コード。 |
| `Department` | 部門コード。計画に部門がない場合は空白。 |
| `Currency` | 金額の通貨。 |
| `Amount` | 桁区切りのない数値。計画が保持される符号のまま（収益は正）。 |

次に、ほかのソースと同様に、**Foundation** タブでこの接続をソースとして追加します（[ERP を接続する](/ja/guides/projects/data-foundation/#erpを接続する)を参照）。新しい接続では、**ユーザー名**、**パスワード**、**ワークスペース ID**、**モデル ID** の入力が求められます。Anaplan にはチェックできるエンティティの一覧がないため、フォームでエンティティの入力を求められます。エクスポートのうち保持するエンティティを**名前**に入力するか、すべてのエンティティを保持する場合は空白のままにします。続いて、次の名前で表示される**システム設定**を入力します。

| 設定 | 意味 |
|---|---|
| `export` | 実行するエクスポートアクションの ID。 |
| `scenario` | `Budget`（デフォルト）、`Forecast`、または `Consolidated`。後者は、グループの損益計算書の照合先となる連結モデルの結果用です。 |
| `version` | すべての行に付与されるラベル。デフォルトは `Anaplan` です。 |

金額は自然な符号のまま、そのまま読み取られます。桁区切りでグループ化されたまま返される列は、[Anaplan: エクスポートの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-export/)と同様に、推測されずフラグが付けられます。

## スケジュール上の考慮事項

Anaplan のリクエストレート予算は**テナント全体で共有**されます。PlaidCloud だけでなく、組織がその Anaplan テナントに対して実行しているすべての連携で共有され、PlaidCloud は同時実行間でスケジュールを調整しません。複数の Anaplan ステップが同じ cron の分に重なると、どれかが完了する前に予算を使い果たす可能性があります。Anaplan のワークフローのスケジュールはすべて同時に実行せず、**時間をずらして設定してください**。
