PlaidCloudを**Anaplan**に接続すると、ワークフローから、Anaplanの大量データ読み取りリクエスト経路で保存済みビューを読み取ったり、既存のエクスポートアクションを実行したり、1つ以上のAnaplanリストをPlaidCloudのディメンションに読み取ったりできます。この接続は、AnaplanのIntegration API自体に**クラウド直接**で接続します。これらのステップにはオンプレミスのエージェント経路はありません。このガイドでは、接続、認証、3つの読み取りステップそれぞれの概要、スケジュール上の注意点について説明します。

<Aside type="note">
このコネクタは読み取り専用です。Anaplanには何も書き戻されません。書き戻しステップも、部分適用モードもありません。
</Aside>

## 前提条件

AnaplanのWorkspace Administratorから、次のものを入手してください。

- Anaplanの**ユーザー名とパスワード**、または、Workspace AdministratorがAnaplanユーザーに登録した**CA証明書とその秘密鍵**のいずれか。ワークフローが読み取るワークスペースとモデルへの読み取りアクセスが必要です。下記の[認証](#認証)を参照してください。
- 読み取り対象のモデルの**ワークスペースID**と**モデルID**。Anaplan自体のモデル設定で確認できます。どちらも、接続の作成後に、接続からライブで検出することもできます。
- **Anaplan: ビューの読み取り**の場合 — 必要な行、列、フィルターのスライスで正確に作成された**保存済みビュー**。下記の[Anaplan: ビューの読み取り](#anaplan-ビューの読み取り)を参照してください。
- **Anaplan: エクスポートの読み取り**の場合 — モデル内に**すでに存在するエクスポートアクション**。
- **Anaplan: リストの読み取り**の場合 — 読み取りたい階層を構成するAnaplanの**リスト**。

## 認証

接続には**認証モード**があり、**基本**（デフォルト）または**証明書**を選択できます。既存の接続は、基本のままそのまま動作します。

- **基本**では、Anaplanのユーザー名とパスワードでサインインします。
- **証明書**では、CAが発行した証明書とその秘密鍵（どちらもPEMテキストとして貼り付け）でサインインします。秘密鍵は**RSAで暗号化されていないもの**である必要があり、証明書は、AnaplanのWorkspace AdministratorがAnaplanユーザーに登録したもので、お客様のテナントに対してAnaplanが信頼するCAが発行したものでなければなりません。PlaidCloudは、鍵でランダムなチャレンジに署名し、Anaplan自身の証明書認証フローに従って、それをAnaplanトークンと交換します。証明書と鍵を貼り付けた後に行うことは他にありません。トークンの更新は基本モードと同じように動作します。どちらのフィールドも貼り付けた内容がマスクされ、どちらのシークレットも基本のパスワードと同様に暗号化されて保存されます。モードを切り替えても、もう一方のモードの認証情報が送信されることはありません。既存の接続を基本から証明書に切り替える場合、証明書と鍵は引き継がれないため、貼り付ける必要があります。

Anaplanの多要素認証は、メールアドレスとパスワードでサインインするユーザーに適用されます。証明書認証は、自動化されたスケジュール接続のためのパスワードを使わない選択肢です。

証明書モードでは、貼り付けた鍵または証明書を読み取れない場合、鍵が暗号化されているかRSAでない場合、あるいは鍵が証明書と一致しない場合、Anaplanに接続する前に拒否されます。Anaplan自体が証明書を拒否した場合、エラーに期限切れかどうかが示されます。よくある原因は、証明書がAnaplanユーザーに登録されていない、またはCAがテナントで信頼されていないことです。

## 接続を作成する

<Steps>

1. **Tools > Connections**を開き、`New Connection`をクリックします。

2. メニューから**Anaplan**を選択します。

3. フィールドを入力します。

   | フィールド | 値 |
   |---|---|
   | 名前 | わかりやすい名前（例: `Anaplan Prod`）。 |
   | APIホスト | 任意。Anaplan標準の`https://api.anaplan.com`を使用する場合は空白のままにします。 |
   | 認証ホスト | 任意。Anaplan標準の`https://auth.anaplan.com`を使用する場合は空白のままにします。 |
   | 認証モード | **基本**（デフォルト）または**証明書**。上記の[認証](#認証)を参照してください。 |
   | ユーザー名 | Anaplanアカウントのユーザー名。基本モードのみ。 |
   | パスワード | Anaplanアカウントのパスワード。基本モードのみ。 |
   | CA証明書 | Anaplanに登録されたX.509証明書のPEMテキスト。証明書モードのみ。 |
   | 秘密鍵 | 証明書のRSA秘密鍵のPEMテキスト（暗号化なし）。証明書モードのみ。 |
   | デフォルトのワークスペースID | 任意。読み取りステップのワークスペースフィールドへの入力を省略するための事前入力。 |
   | デフォルトのモデルID | 任意。読み取りステップのモデルフィールドへの入力を省略するための事前入力。 |
   | タイムアウト（秒） | デフォルトは30です。 |

4. `Test Connection`をクリックします。テストが成功すると、認証情報が対応するAnaplanアカウントのメールアドレスが表示されます。

5. `Create`をクリックします。

</Steps>

## Anaplan: ビューの読み取り

**Anaplan: ビューの読み取り**ステップを追加すると、Anaplanの大量データ読み取りリクエスト経路で保存済みビューを読み取れます。**ビューは、Anaplanで保存されたとおりに読み取られます。このステップには、行、列、ページの選択はありません。** 別のスライスを読み取るには、Anaplanで別の保存済みビューを作成してください。Anaplanでは、ブールのラインアイテムと保存済みビューを組み合わせてフィルターするのが一般的です。データ列がAnaplanで宣言されたタイプのまま取り込まれるのは、ビューで**ラインアイテムが列の軸にある**場合のみです。ラインアイテムが行にある場合（一般的な損益計算書のレイアウト）や、ビューにない場合は、すべての列がテキストとして取り込まれ、ステップがその旨を通知します。フィルターに一致するものがないビューは、警告とともに空のテーブルとして取り込まれます。ステップが曖昧さなく読み取れないNumberの値（多くの場合、通常の小数とも欧州式の表記ともとれる値）は、同じ列の別の値でどちらの読み方が正しいかが決まる場合を除き、推測せずに拒否されます。解析できる値は、丸め誤差なしの完全な精度で取り込まれます。フィールドと動作の詳細は、[Anaplan: ビューの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-view/)を参照してください。

## Anaplan: エクスポートの読み取り

**Anaplan: エクスポートの読み取り**ステップを追加すると、Anaplanの**既存の**エクスポートアクションを実行し、生成されたファイルを取り込めます。APIではエクスポートアクションを作成できないため、先にAnaplanで作成または編集してください。また、このステップで出力内容を絞り込むこともできません。Anaplanでエクスポートするよう設定されている内容が、そのまま取り込まれます。**すべての列がテキストとして取り込まれます。** 数値は米国形式でリクエストされます。それでも桁区切りが付いたまま返ってきた列は、そのままテキストとして取り込まれ、実行が失敗するのではなく、名前付きの警告が表示されます。ステップは、エクスポートが失敗した場合、キャンセルされた場合、データが生成されなかった場合、ステップのポーリング予算を使い切っても実行中の場合、あるいは、エクスポートと結び付けられないファイルが生成された場合や行数がAnaplan自身の報告と一致しないファイルが生成された場合に、テーブルを取り込まずに停止します。詳細は、[Anaplan: エクスポートの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-export/)を参照してください。

## Anaplan: リストの読み取り

**Anaplan: リストの読み取り**ステップを追加すると、1つ以上のAnaplanリストをPlaidCloudのディメンションに読み取れます。**1つのステップで複合階層全体を読み取ります。** 階層をいくつものステップに分割せず、階層にまたがるすべてのリストを、ルートから順に（たとえば、Region、Country、Storeの順に）指定してください。ステージングテーブルは実行のたびに置き換えられるため、1つのステージングテーブルを指す複数のステップがあると、それぞれが前のステップの行を消去してしまいます。Anaplanのリスト階層にはエッジごとの重みや符号がないため、すべてのエッジは単純な`+`でロールアップされます。Anaplanのリストのアクセス制御とサブセットのメンバーシップはインポートされません。これらはディメンションデータではなくメタデータだからです。重複したノードID、解決できない親参照、競合する親参照、およびインポートされたメタデータと衝突するプロパティ名は、何かが取り込まれる前に拒否されます。詳細は、[Anaplan: リストの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-list/)を参照してください。

## スケジュールに関する注意点

Anaplanのリクエストレートの予算は**テナント全体で共有**されます。PlaidCloudだけでなく、そのAnaplanテナントに対して組織が実行するすべての連携が対象であり、PlaidCloudは同時に実行される処理間でスケジュールを調整しません。同じcronの分に複数のAnaplanステップが重なると、どれかが完了する前にこの予算を使い切ることがあります。すべてを一度に実行するのではなく、**Anaplanワークフローのスケジュールをずらして**ください。
