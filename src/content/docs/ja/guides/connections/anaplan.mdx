PlaidCloudを**Anaplan**に接続すると、ワークフローで、Anaplanの大容量読み取りリクエスト経路を使った保存済みビューの読み取り、既存のエクスポートアクションの実行、1つ以上のAnaplanリストのPlaidCloudディメンションへの読み取りを行えます。この接続は、AnaplanのIntegration APIに**クラウドダイレクト**で到達します。これらのステップにはオンプレミスのエージェント経由の経路はありません。このガイドでは、接続、認証、3つの読み取りステップの概要、およびスケジュール上の考慮事項を説明します。

<Aside type="note">
このコネクターは読み取り専用です。Anaplanにデータが書き戻されることはありません。書き戻しステップも、部分適用モードもありません。
</Aside>

## 前提条件

Anaplanのワークスペース管理者から、次の情報を入手してください。

- Anaplanの**ユーザー名とパスワード**、または、ワークスペース管理者がAnaplanユーザーに登録した**CA証明書とその秘密鍵**のいずれか。ワークフローが読み取るワークスペースとモデルへの読み取りアクセス権が必要です。以下の[認証](#認証)を参照してください。
- 読み取り対象モデルの**ワークスペースID**と**モデルID**。Anaplan自体のモデル設定で確認できます。どちらも、接続の作成後に接続からライブで検出することもできます。
- **Anaplan: ビューの読み取り**の場合は、必要な行、列、フィルターのスライスで正確に作成した**保存済みビュー**。以下の[Anaplan: ビューの読み取り](#anaplan-ビューの読み取り)を参照してください。
- **Anaplan: エクスポートの読み取り**の場合は、モデル内に**すでに存在するエクスポートアクション**。
- **Anaplan: リストの読み取り**の場合は、読み取りたい階層を構成するAnaplanの**リスト**。

## 認証

接続には**認証モード**があり、**基本**（デフォルト）または**証明書**を選択します。既存の接続は、変更なしで引き続き基本モードとして動作します。

- **基本**は、Anaplanのユーザー名とパスワードでサインインします。
- **証明書**は、CAが発行した証明書とその秘密鍵でサインインします。どちらもPEMテキストとして貼り付けます。秘密鍵は**RSAで、暗号化されていない**ものでなければなりません。証明書は、Anaplanワークスペース管理者がAnaplanユーザーに登録したものであり、かつテナントについてAnaplanが信頼するCAが発行したものでなければなりません。PlaidCloudは、Anaplan自体の証明書認証フローに従い、ランダムなチャレンジを鍵で署名し、Anaplanトークンと交換します。証明書と鍵を貼り付けた後に行う操作はほかにありません。トークンの更新も基本モードと同じように機能します。どちらのフィールドも貼り付けた内容がマスクされ、どちらのシークレットも基本モードのパスワードと同様に暗号化して保存されます。また、モードを切り替えても、もう一方のモードの認証情報は送信されません。既存の接続を基本から証明書に切り替える場合、証明書と鍵は引き継がれないため、貼り付け直す必要があります。

Anaplanの多要素認証は、メールアドレスとパスワードでサインインするユーザーに適用されます。証明書認証は、自動化されたスケジュール接続向けの、パスワードを使わない方法です。

証明書モードでは、貼り付けた鍵または証明書を読み取れない場合、鍵が暗号化されている場合やRSAでない場合、または鍵が証明書と一致しない場合、Anaplanに接続する前に拒否されます。Anaplan自体が証明書を拒否した場合、エラーに有効期限切れかどうかが示されます。よくある原因は、証明書がAnaplanユーザーに登録されていないこと、またはテナントでCAが信頼されていないことです。

## 接続の作成

<Steps>

1. **Tools > Connections**を開き、`New Connection`をクリックします。

2. メニューから**Anaplan**を選択します。

3. 次のフィールドを入力します。

   | フィールド | 値 |
   |---|---|
   | 名前 | わかりやすい名前（例：`Anaplan Prod`）。 |
   | APIホスト | 省略可。空白にすると、Anaplan標準の`https://api.anaplan.com`が使用されます。 |
   | 認証ホスト | 省略可。空白にすると、Anaplan標準の`https://auth.anaplan.com`が使用されます。 |
   | 認証モード | **基本**（デフォルト）または**証明書**。上記の[認証](#認証)を参照してください。 |
   | ユーザー名 | Anaplanアカウントのユーザー名。基本モードのみ。 |
   | パスワード | Anaplanアカウントのパスワード。基本モードのみ。 |
   | CA証明書 | Anaplanに登録されているX.509証明書のPEMテキスト。証明書モードのみ。 |
   | 秘密鍵 | 証明書のRSA秘密鍵のPEMテキスト（暗号化されていないもの）。証明書モードのみ。 |
   | デフォルトのワークスペースID | 省略可。読み取りステップのワークスペースフィールドに事前入力するための便宜的な値。 |
   | デフォルトのモデルID | 省略可。読み取りステップのモデルフィールドに事前入力するための便宜的な値。 |
   | タイムアウト（秒） | デフォルトは30です。 |

4. `Test Connection`をクリックします。テストに成功すると、認証情報が解決されるAnaplanアカウントのメールアドレスが報告されます。

5. `Create`をクリックします。

</Steps>

## Anaplan: ビューの読み取り

**Anaplan: ビューの読み取り**ステップを追加すると、Anaplanの大容量読み取りリクエスト経路を使って保存済みビューを読み取れます。**ビューは、Anaplanで保存されたとおりに読み取られます。このステップには、行、列、ページの選択機能はありません。** 別のスライスを読み取るには、Anaplanで別の保存済みビューを作成してください。Anaplanでフィルターをかける通常の方法は、ブール型のラインアイテムと保存済みビューの組み合わせです。データ列が宣言されたAnaplanの型で取り込まれるのは、ビューで**ラインアイテムが列軸にある**場合のみです。ラインアイテムが行にある場合（通常の損益計算書レイアウト）やビューにない場合、すべての列がテキストとして取り込まれ、ステップがその旨を通知します。フィルターに一致するものがないビューは、警告とともに空のテーブルとして取り込まれます。数値の値のうち、ステップが曖昧さなく読み取れないもの（多くは、通常の小数とも欧州式表記とも解釈できる値）は、同じ列の別の値でどちらの解釈が正しいかが決まる場合を除き、推測されずに拒否されます。正しく解析できた値は、丸め誤差なしの完全な精度で取り込まれます。フィールドと動作の詳細なリファレンスについては、[Anaplan: ビューの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-view/)を参照してください。

## Anaplan: エクスポートの読み取り

**Anaplan: エクスポートの読み取り**ステップを追加すると、**既存の**Anaplanエクスポートアクションを実行し、生成されたファイルを取り込めます。APIではエクスポートアクションを作成できないため、先にAnaplanで作成または編集してください。また、このステップで出力内容を絞り込むことはできません。Anaplanでエクスポートするように構成されている内容がそのまま取り込まれます。**すべての列がテキストとして取り込まれます。** 数値は米国式の書式で要求されます。それでも桁区切りのある状態で返された列は、変更されずにテキストとして取り込まれ、実行は失敗せずに、名前付きの警告が出力されます。エクスポートが失敗した場合、キャンセルされた場合、データが生成されなかった場合、ステップのポーリング予算を使い切っても実行中の場合、エクスポートに紐付けられないファイルが生成された場合、またはAnaplan自身が報告する行数と行数が一致しないファイルが生成された場合、ステップはテーブルを取り込まずに停止します。詳細なリファレンスについては、[Anaplan: エクスポートの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-export/)を参照してください。

## Anaplan: リストの読み取り

**Anaplan: リストの読み取り**ステップを追加すると、1つ以上のAnaplanリストをPlaidCloudディメンションに読み取れます。**1つのステップで複合階層全体を読み取れます。** 複数のステップに分割せず、階層が含むすべてのリストをルートから順に指定してください（例：地域、国、店舗）。ステージングテーブルは実行のたびに置き換えられるため、1つのステージングテーブルを指す複数のステップがあると、それぞれが前のステップの行を消去してしまいます。Anaplanのリスト階層にはエッジごとの重みや符号がないため、すべてのエッジは単純な`+`で集計されます。Anaplanのリストアクセス制御とサブセットのメンバーシップは、ディメンションのデータではなくメタデータであるため、インポートされません。重複するノードID、解決できない親参照、競合する親参照、インポートされるメタデータと衝突するプロパティ名は、いずれも何かが取り込まれる前に拒否されます。詳細なリファレンスについては、[Anaplan: リストの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-list/)を参照してください。

## Data FoundationのソースとしてのAnaplan

[Data Foundation](/ja/guides/projects/data-foundation/)は、Anaplanが保持する計画（予算、予測、連結モデルの結果）をCommon Finance Modelに読み込めます。取り込むのは計画のみで、元帳は取り込まず、読み取り専用です。

Data Foundationは、モデルの保存されたままのエクスポートアクションを1つ実行します。そのため、Anaplan管理者が先にそのエクスポートを作成します。**Foundation**タブに、管理者への依頼内容が記載されます。エクスポートは、エンティティ、期間、勘定科目、部門ごとに1行のフラットなグリッドで、次の列見出しを正確に使用する必要があります。

| 列 | 内容 |
|---|---|
| `Entity` | エンティティコード。 |
| `Period` | 月（`YYYY-MM`形式）。 |
| `Account` | 勘定科目コード。 |
| `Department` | 部門コード。計画に部門がない場合は空白。 |
| `Currency` | 金額の通貨。 |
| `Amount` | 桁区切りのない数値。計画が保持されている符号のまま（収益は正）。 |

次に、ほかのソースと同様に、**Foundation**タブで接続をソースとして追加し（[ERPを接続する](/ja/guides/projects/data-foundation/#erpを接続する)を参照）、次を選択します。

| 設定 | 内容 |
|---|---|
| エクスポート | 実行するエクスポートアクションのID。 |
| シナリオ | **予算**（デフォルト）、**予測**、または**連結**。連結は、グループの損益計算書の照合先となる連結モデルの結果用です。 |
| バージョン | すべての行に付けられるラベル。デフォルトは`Anaplan`です。 |
| エンティティ | エクスポートから保持するエンティティ。Anaplanでは選択用のリストが提供されないため、直接入力します。空白にするとすべてのエンティティが保持されます。 |

金額は、自然な符号のまま、そのまま読み取られます。桁区切りでグループ化されたまま返された列は、推測されずにフラグが付けられます。これは[Anaplan: エクスポートの読み取り](/ja/reference/workflow-steps/anaplan/anaplan-read-export/)と同じです。

## スケジュール上の考慮事項

Anaplanのリクエストレートの予算は**テナント全体で共有**されます。PlaidCloudだけでなく、そのAnaplanテナントに対して組織が実行するすべての統合にまたがります。また、PlaidCloudは同時実行間でスケジュールを調整しません。複数のAnaplanステップが同じcronの分に重なると、いずれかが完了する前にこの予算を使い切ってしまうことがあります。すべてを同時に実行せず、**Anaplanワークフローのスケジュールをずらして**ください。
