**PlaidCloud Git 接続**は、ワークフローまたはサーバー Panel アプリのビルドを、ワークスペース専用のマネージド Git サーバー上のリポジトリに向けます。この Git サーバーは `git.<your-workspace>.plaid.cloud` でお客様のために用意されており、通常の PlaidCloud ログインですでにサインインしているため、接続フォームは外部の Git プロバイダーのものよりはるかにシンプルです。入力するサーバー URL はなく、管理するユーザー名、トークン、SSH キーもありません。

<Aside type="note">PlaidCloud Git 接続では、サーバー URL や資格情報を入力する必要はありません。ワークスペースの Git サーバーと、そこへのアクセスは、PlaidCloud のサインイン（SSO を含む）から自動的に処理されるため、発行、保管、ローテーションするトークンはありません。</Aside>

## 使用する場面

読み取りたいリポジトリが外部ホストではなく、ワークスペースの組み込み Git サービスである [PlaidCloud Git](/ja/guides/git/) にある場合は、必ず PlaidCloud Git 接続を使用してください。最も一般的な使い方は、マネージドリポジトリから**サーバー Panel アプリ**または **Dash アプリ**のビルドを自動化することです。ブランチへのプッシュでアプリが再ビルドおよび再デプロイされ、外部の GitHub アカウントや個人用アクセストークンは必要ありません。

GitHub、GitLab、Bitbucket、Forgejo、Gitea など、外部サービスにホストされているリポジトリには、代わりに[外部 Git 接続](/ja/reference/connectors/git/)を使用してください。外部 Git 接続には、**サーバーURL**、ユーザー/トークンまたは SSO 認証、**SSL** タブと **SSH** タブを含むフルフォームがあります。

## PlaidCloud Git 接続を作成する

1. **Tools > Connections** を開きます。
2. `New Connection` をクリックし、メニューから **PlaidCloud Git** を選択します。
3. 簡略化されたフォームに入力します。
   - **アカウント名** — 接続の表示名
   - **メモ** — 接続の用途に関する任意のメモ
   - **リポジトリ** — `Refresh` をクリックして、ワークスペースが到達できるリポジトリを一覧表示し、1 つ選択します（たとえば `udfs` や `apps` リポジトリ）。パスを入力するのではなく、一覧から選択します。
   - **デフォルトブランチ** — 選択したリポジトリのブランチ一覧から、デフォルトで読み取るブランチを選択します
   - **開始パス** — 必要に応じてリポジトリを参照してフォルダーを選択すると、すべてのファイル検索がそのサブフォルダーに限定されます。未設定のままにすると、リポジトリ全体が対象になります
4. **使用方法**を設定します。接続を有効にするには `Active`、接続で書き込みを一切行わない場合は `Read Only` です
5. **セキュリティモデル**を設定します。ワークスペース内で接続を使用できるユーザーを指定します
6. `Create` をクリックして保存します

フォームはこれですべてです。外部の Git プロバイダーとは異なり、サーバー URL も認証タブも SSL や SSH の設定もありません。これらはすべて自動的に処理されます。

<Aside type="note">リポジトリ、デフォルトブランチ、開始パスは、ライブの一覧から選択します。まずリポジトリを選び、次にそのブランチを選び、続いてフォルダーを参照して選択するため、入力ミスの心配がありません。各一覧は接続自身のアクセス権を使用して読み取られるため、PlaidCloud Git 接続では、資格情報を入力しなくてもすぐに表示されます。</Aside>

## セキュリティモデル

`Security Model` は、ワークスペース内で接続を使用できるユーザーを制御します。

| オプション | 接続を使用できるユーザー |
|---|---|
| 非公開（所有者のみ） | 所有者のみ。 |
| 特定のメンバーのみ | 所有者と、明示的に指定したメンバーの一覧。 |
| 特定のセキュリティグループのみ | 所有者と、指定したセキュリティグループのメンバー。 |
| すべてのワークスペースメンバー | ワークスペース内の全員。 |

`Specific Members Only` または `Specific Security Groups Only` の場合は、保存後に一覧の `Actions` メニューからアクセスを付与します。共通の接続の仕組みについては、[接続の作成と管理](/ja/guides/connections/create-connection/#セキュリティモデル)を参照してください。

## マネージド Git から Panel アプリと Dash アプリのビルドを自動化する

[サーバー Panel アプリ](/ja/guides/panel-apps/creating/)または [Dash アプリ](/ja/guides/dash-apps/)は、Git ブランチからビルドされ、そのブランチへのプッシュのたびに自動的に再ビルドされます。これを PlaidCloud Git 接続に向けると、ループ全体がワークスペース内で完結します。外部ホストも、有効に保つべき個人用アクセストークンも必要ありません。

1. ワークスペースの PlaidCloud Git サーバー上のリポジトリに、アプリをプッシュします。エントリポイントの `.py` ファイル（Panel では `.servable()` を呼び出し、Dash では `server = app.server` を公開します）と、リポジトリのルートまたはエントリポイントの隣に任意の `requirements.txt` を置きます。リポジトリの構成については、[Panel アプリの作成](/ja/guides/panel-apps/creating/#アプリのリポジトリを準備する)または [PlaidCloud Git から Dash アプリをデプロイする](/ja/guides/dash-apps/deploy-from-git/)を参照してください。
2. 上記の手順に従って、**リポジトリ**がそのリポジトリである PlaidCloud Git 接続を作成します。
3. **マイPanelアプリ**で **新しいサーバーアプリ**または**新しいDashアプリ**をクリックし、**Git接続と公開ウォッチャー**で次のように設定します。
   - **Git接続** — 作成したばかりの PlaidCloud Git 接続を選択します
   - **ブランチ** — ビルド元のブランチ。このブランチへのプッシュで、アプリが再ビルドおよび再デプロイされます
   - **エントリポイント** — アプリが提供する `.py` ファイル
4. 公開ダイアログを完了し、**公開**をクリックします。

以降は、マネージド Git サーバー上のそのブランチへのプッシュのたびにアプリが再ビルドされます。PlaidCloud の外に出ることのない、エンドツーエンドの自動ビルドです。
