このチュートリアルでは、生のコストデータから動作する配賦モデルを作成するまでを、約30分で進めます。

## 必要なもの

- 少なくとも2つのテーブルを含むプロジェクト:
  - **配賦する値** — 分配したいコスト（または収益や数量）。ソース単位ごとに1行、金額を持つ列が1つ。
  - **ドライバーデータ** — 分配の基準。人員数、床面積、取引件数、収益など、配賦の*基準*にしたいもの。
- ソースとターゲットを結び付けるディメンション（コストセンター、部門、製品など、モデルに合った分類）。

これらがまだすべてそろっていない場合は、入力データの読み込み方法を[テーブルとビュー](/ja/guides/data/)および[ディメンション](/ja/guides/dimensions/)のガイドで説明しています。

## 手順

1. 配賦する値とドライバーのテーブルがある**プロジェクトを開きます**。
2. **新しいワークフローを作成します。** 配賦は常にワークフロー内で実行されます。ワークフローの外でテーブルを直接操作することはできません。
3. **配賦ステップを追加します。** ワークフロー内で、**Allocation** カテゴリからステップを追加します。ドライバーに基づく単純な分配では、**Allocation Rules** から始めるのが一般的です。
4. **ソースを設定します。** ステップが値のテーブルを参照するように指定し、配賦する金額が入っている列を選択します。
5. **ドライバーを設定します。** ステップがドライバーのテーブルを参照するように指定し、ドライバーの値が入っている列を選択します。
6. **ディメンションをマッピングします。** 各テーブルで、ディメンションメンバーを表す列を指定します。配賦ステップはこれらを使って、ソース行とドライバー行を照合します。
7. **ステップを実行します。** 出力は、分配された金額ごとに1行を持つ新しいテーブルです。
8. **結果を確認します。** 合計が想定どおりであることを確認します。配賦された金額の合計は、ソースの金額の合計と（丸め許容差の範囲内で）一致するはずです。

## よくある次のステップ

- **再帰的な分配** — ターゲット自体がさらなる配賦のドライバーを含む場合は、[再帰的な配賦](/ja/guides/allocations/setup/recursive-allocations/)を参照してください。
- **配賦用の行のタグ付け** — どの行をどのターゲットに配賦するかを制御するには、[ルールベースのタグ付け](/ja/guides/allocations/getting-started/rule-based-tagging/)を参照してください。
- **想定外の結果の調査** — 合計が一致しない場合や特定の行がおかしい場合は、[配賦のトラブルシューティング](/ja/guides/allocations/results/troubleshooting-allocations/)を参照してください。
