## Descrição


Exporta uma tabela de dados do Analyze para o PlaidCloud Document como um ficheiro JSON. Existem várias opções (apresentadas abaixo) para a orientação dos dados.



Para mais informações sobre ficheiros JSON, consulte o sítio Web oficial do JSON aqui: http://json.org/.


<Aside>Os ficheiros JSON *não* mantêm a ordem das colunas. A ordem das colunas na tabela de dados de origem não se reflete necessariamente na ordem das colunas do ficheiro exportado.</Aside>

### Orientação do JSON


Considere o seguinte conjunto de dados:




| ID |  Nome  | Género | Estado |
|----|--------|--------|-------|
| 1  | Jack   |   M    |   MO  |
| 2  | Jill   |   F    |   MO  |
| 3  | George |   M    |   VA  |
| 4  | Abe    |   M    |   KY  |

Os ficheiros JSON podem ser exportados num de quatro formatos de dados:


* Records: os dados são guardados em dicionários Python, com cada linha guardada no formato \{Coluna -> Valor, …}. Por exemplo: **[\{“ID”:1,”Name”:”Jack”,”Gender”:”M”,”State”:”MO”},\{“ID”:2,”Name”:”Jill”,”Gender”:”F”,”State”:”MO”},\{“ID”:3,”Name”:”George”,”Gender”:”M”,”State”:”VA”},\{“ID”:4,”Name”:”Abe”,”Gender”:”M”,”State”:”KY”}]**
* Index: os dados são guardados em dicionários Python aninhados, com cada linha guardada no formato \{Índice -> \{Coluna -> Valor, …},…}. Por exemplo: **\{“0”:\{“ID”:1,”Name”:”Jack”,”Gender”:”M”,”State”:”MO”},”1”:\{“ID”:2,”Name”:”Jill”,”Gender”:”F”,”State”:”MO”},”2”:\{“ID”:3,”Name”:”George”,”Gender”:”M”,”State”:”VA”},”3”:\{“ID”:4,”Name”:”Abe”,”Gender”:”M”,”State”:”KY”}}**
* Split: os dados são guardados num único dicionário Python, com os valores guardados em listas. Por exemplo: **\{“columns”:[“ID”,”Name”,”Gender”,”State”],”index”:[0,1,2,3],”data”:[[1,”Jack”,”M”,”MO”],[2,”Jill”,”F”,”MO”],[3,”George”,”M”,”VA”],[4,”Abe”,”M”,”KY”]]}**
* Values: os dados são guardados em várias listas Python. Por exemplo: **[[1,”Jack”,”M”,”MO”],[2,”Jill”,”F”,”MO”],[3,”George”,”M”,”VA”],[4,”Abe”,”M”,”KY”]]**


### Tratamento de datas


Especifique o **Formato de data** através do menu pendente. Escolha entre os seguintes formatos:


* **Epoch (Unix Timestamp – Seconds since 1/1/1970)**
* **ISO 8601 Format (YYYY-MM-DD HH:MM:SS with timeproject offset)**

Especifique a **Unidade de data** através do menu pendente. Escolha entre os seguintes formatos, listados por ordem crescente de precisão:


* **Segundos (s)**
* **Milissegundos (ms)**
* **Microssegundos (us)**
* **Nanossegundos (ns)**

### Forçar ASCII


Selecione esta caixa de seleção para garantir que todas as cadeias de caracteres são codificadas em formato ASCII correto. Esta opção está ativada por predefinição.



### Tipo de ficheiro de saída


Todos os ficheiros exportados são não comprimidos, mas estão disponíveis as seguintes opções de compressão:


* Zip
* GZip
* BZip2


### Definições adicionais

* **Um ficheiro que já existe** (`if_exists`), em **Se o ficheiro existir** — **Sobrescrevê-lo** (`overwrite`, predefinição) substitui um ficheiro que já exista; **Fazer a etapa falhar sem escrever nada** (`fail`) interrompe o passo, sem escrever nada, quando já existe um ficheiro que seria escrito.
* **Ordenar linhas por** (`sort_columns`), em **Ordem das linhas** — ordena as linhas escritas por estas colunas de origem, começando pela primeira chave, cada uma com uma definição de **Coluna**, **Ascendente** e **Nulos**. Não é necessário que uma coluna-chave seja escrita. **Nulos** assume por predefinição primeiro em ordem ascendente e último em ordem descendente. Não é utilizado com **Resumir** nem com **Distinto**.
