## Descrição


Copia dados de uma tabela do projeto atual para uma tabela de um projeto diferente. Útil quando os projetos partilham dados de referência, quando um projeto de consolidação obtém dados de vários projetos operacionais, ou quando pretende entregar resultados processados ao projeto de outra equipa.

O esquema tem de ser compatível entre a origem e o destino. O projeto de destino tem de conceder a este projeto uma partilha de dados de **Escrita**.


## Gestão de partilha de dados

![Gestão de partilha de dados](/images/import_external_project_table_1.png)

Antes de poder exportar uma tabela para outro projeto, esse projeto tem de permitir que este escreva nele. Abra o separador **Início** do projeto de **destino** e, em **Gestão de partilha de dados**, clique em **Nova partilha de dados**, selecione este projeto, assinale **Escrita** em **Operações permitidas** e clique em **Adicionar partilha de dados**. Consulte [Partilhar dados entre projetos](/pt-pt/guides/projects/managing-projects/#partilhar-dados-entre-projetos).

O passo é executado com a identidade do próprio projeto, pelo que uma execução funciona através da partilha, independentemente de quem a inicia.

## Exportar tabela de projeto externa

![Exportar tabela de projeto externa](/images/export_external_project_table.png)

### Ler de
Selecione a **Tabela de origem** no menu pendente.

<Aside type="note" title="Tabela de origem vazia">
Se a tabela de origem não tiver linhas quando o passo é executado, a exportação termina com um aviso de que a origem estava vazia, em vez de um sucesso silencioso — para que seja fácil detetar um destino inesperadamente vazio. Na maioria dos casos, isto significa que o fluxo de trabalho ainda não tinha criado essa tabela; certifique-se de que a origem está preenchida (e, nas execuções agendadas, de que está ordenada para ser executada primeiro) antes da exportação.
</Aside>

### Escrever em

#### Projeto de destino
Selecione o **Projeto de destino** no menu pendente.

#### Tabela de destino estática

Para definir a tabela de destino, selecione uma tabela existente como tabela de destino através do menu pendente **Tabela de destino** ou clique no sinal verde **"+"** para criar uma nova tabela como destino. 

##### Criação de tabelas
Ao criar uma nova tabela, tem a opção de a criar como **Vista** ou como **Tabela**. 
###### Vistas:
As vistas são úteis porque o tempo necessário para executar um passo é significativamente inferior ao de quando se utiliza uma tabela. A desvantagem das vistas é que não são úteis para exploração de dados no modo Detalhes da tabela.

###### Tabelas:
Ao utilizar uma tabela como destino, um passo demora mais tempo a ser executado, mas a exploração de dados no modo Detalhes é muito mais rápida do que com uma vista.

<Aside>Utilize tabelas nos passos fundamentais dos seus fluxos de trabalho em que seja necessária a validação de dados ou a capacidade de realizar análises ad hoc. Em todos os outros passos, utilize vistas para reduzir o tempo total de cálculo do fluxo de trabalho. É possível mudar uma tabela para vista e vice-versa, pelo que pode sempre atualizar o tipo de destino da tabela mais tarde.</Aside>

#### Tabela de destino dinâmica

A opção Dinâmico permite especificar uma tabela através de texto, incluindo variáveis.  Isto é útil ao utilizar
fluxos de trabalho orientados por variáveis, em que as referências a tabelas e vistas são relativas às variáveis especificadas.

Um exemplo que utiliza a variável `current_month` para apontar dinamicamente para a tabela de destino:

```text
legal_entity/inputs/{current_month}/ledger_values
```

<Aside>Se a tabela não existir, será criada dinamicamente quando o processo de importação for executado</Aside>

#### Acrescentar aos dados existentes

Para acrescentar os dados da tabela de origem à tabela de destino, marque a caixa ***Acrescentar aos dados existentes***.
