## Descrição

Importe ficheiros de texto JSON a partir do PlaidCloud Document.

Para mais detalhes sobre ficheiros JSON, consulte o sítio Web oficial do JSON aqui: http://json.org/.

Os ficheiros JSON *não* mantêm a ordem das colunas. A ordem das colunas no ficheiro de origem não reflete necessariamente a ordem das colunas na tabela de dados importada.

As importações de JSON são transmitidas através de armazenamento temporário, em vez de carregarem o documento inteiro em memória, pelo que ficheiros muito grandes são importados sem esgotar a memória. As colunas que só aparecem tarde num documento grande são incluídas na tabela importada. Os objetos e matrizes aninhados são importados como texto JSON compacto padrão, para que os passos seguintes os possam analisar com qualquer ferramenta JSON.

## Itens de configuração específicos

### Orientação dos dados JSON

Considere o seguinte conjunto de dados:

| ID | Name | Gender | State |
| 1 | Jack | M | MO |
| 2 | Jill | F | MO |
| 3 | George | M | VA |
| 4 | Abe | M | KY |

Os ficheiros JSON podem ser importados a partir de um de três formatos de dados:

* Records: Os dados são armazenados em conjuntos de dicionários Python, com cada linha armazenada no formato \{Column -> Value, …}. Por exemplo:


```json
[{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" }]
```

* Index: Os dados são armazenados em conjuntos de dicionários Python aninhados, com cada linha armazenada no formato \{Index -> \{Column -> Value, …},…}. Por exemplo:


```json
{ "0": { "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }, "1": { "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }, "2": { "ID": 3, "Name": "George", "Gender": "M", "State": "VA" }, "3": { "ID": 4, "Name": "Abe", "Gender": "M", "State": "KY" } }
```

* Split: Os dados são armazenados num único conjunto de dicionário Python, com os valores guardados em listas. Por exemplo:


```json
{ "columns": ["ID", "Name", "Gender", "State"], "index": [0, 1, 2, 3], "data": [ [1, "Jack", "M", "MO"], [2, "Jill", "F", "MO"], [3, "George", "M", "VA"], [4, "Abe", "M", "KY"] ] }
```

Para além dos formatos acima, é aceite JSON delimitado por novas linhas (NDJSON): um objeto JSON autónomo por linha, sem matriz envolvente. Por exemplo:

```json
{ "ID": 1, "Name": "Jack", "Gender": "M", "State": "MO" }
{ "ID": 2, "Name": "Jill", "Gender": "F", "State": "MO" }
```


### Documento completo

Para manter intacto o JSON de cada ficheiro, selecione **Importar cada ficheiro como uma linha com todo o documento JSON** (`whole_document`) em **Mais opções de JSON**. Cada ficheiro é então importado como uma linha que contém todo o seu documento JSON, com os números mantidos tal como foram escritos.

### Datas e carimbos de data/hora

Um campo é importado como datas ou carimbos de data/hora quando todos os seus valores têm o mesmo formato, de entre os seguintes:

| Formato | Datas | Carimbos de data/hora |
| --- | --- | --- |
| ISO 8601 | `2026-01-23` | `2026-01-23T23:14:00` |
| Mês primeiro | `01-23-2026` ou `01-23-26` | `01-23-2026 11:14:00 PM`, com hora de 12 horas |
| Dia primeiro | `23-01-2026` ou `23-01-26` | `23-01-2026 23:14:00`, com hora de 24 horas |
| Ano de dois dígitos primeiro | `99-01-23` | `99-01-23 23:14:00`, com hora de 24 horas |

Todos os valores de um campo são lidos da mesma forma, seja qual for a ordem das linhas. Um campo com qualquer outro formato, como `01/23/2026` ou `01-23-2026 23:14:00`, é importado como texto. O mesmo acontece com um campo cujos valores misturam formatos, embora algumas misturas de anos de dois e de quatro dígitos, como `01-23-2026` e `01-24-26`, interrompam a importação, com um erro que indica o campo.

#### Quando um valor se enquadra em mais do que um formato

`01-03-2026` tanto pode ser 3 de janeiro como 1 de março, e `23-01-26` tanto pode ser 23 de janeiro de 2026 como, lido com o ano primeiro, 26 de janeiro de 2023. Quando todos os valores de um campo se enquadram em mais do que um dos formatos acima, o **Formato de data** do passo decide, pela sua ordem de dia, mês e ano:

* Uma opção que começa por Mês Dia lê o mês primeiro: `01-03-2026` como 3 de janeiro.
* Uma opção que começa por Dia Mês ou Abreviado lê o dia primeiro: `01-03-2026` como 1 de março, e `23-01-26` como 23 de janeiro de 2026.
* Com qualquer outro Formato de data, a importação é interrompida com um erro que indica o campo e as opções que o resolveriam.

Estas opções também leem um carimbo de data/hora com a outra hora quando o dia e o mês de todos os valores são 12 ou menos: uma opção Mês Dia lê `01-03-2026 23:14:00` como 3 de janeiro, e uma opção Dia Mês ou Abreviado lê `01-03-2026 11:14:00 PM` como 1 de março. Qualquer outro Formato de data lê-os como a tabela indica, dia primeiro com hora de 24 horas e mês primeiro com hora de 12 horas.

Nenhuma opção de Formato de data lê o ano de dois dígitos primeiro, pelo que um campo como `26-01-23` só é importado com o ano primeiro quando os seus valores não podem ser lidos de outra forma, como em `99-01-23`. Escrita com um ano de quatro dígitos, como `2026-01-23`, essa data é importada como ISO 8601.

Um ficheiro que também contém um carimbo de data/hora dentro de um objeto ou de uma matriz aninhados é a exceção: nenhuma das verificações acima se aplica e um valor que se enquadre em mais do que um formato pode ser lido de forma diferente de uma linha para a seguinte.
