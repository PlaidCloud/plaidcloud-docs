## Descrição

Lê um ficheiro de base de dados Microsoft Access a partir de uma conta de documentos e importa as respetivas tabelas — uma tabela de projeto por cada tabela do Access, com o nome precedido de um prefixo à sua escolha.

Como um ficheiro Access contém muitas tabelas, este passo importa o ficheiro como um todo, em vez de mapear as colunas de uma única tabela.

## Itens de configuração específicos

### Origem

O ficheiro de base de dados Access numa conta de documentos. O seletor de ficheiros também permite a correspondência por pesquisa em vez de um caminho exato, com uma opção recursiva e uma regra para conciliar diferenças de esquema entre os ficheiros encontrados.

### Destino

**Prefixo da tabela** — acrescentado ao início do nome de cada tabela importada, para que as tabelas de um ficheiro fiquem agrupadas e não colidam com as de outra importação.

### Ignorar se não houver alterações

Ativado por predefinição. Uma execução do fluxo de trabalho ignora totalmente a importação — incluindo a transferência — quando o ficheiro de origem não foi alterado desde a última execução e as tabelas de destino ainda contêm as linhas que carregou. Uma tabela que tenha sido esvaziada é importada novamente.

## Quando o ficheiro não pode ser lido

O passo falha, indicando o ficheiro e a tabela que não conseguiu ler, em vez de terminar e deixar uma tabela vazia. Isto acontece quando o ficheiro não lista nenhuma tabela que o PlaidCloud consiga ler, quando uma tabela é indicada mas as suas colunas não podem ser descritas, ou quando a leitura das linhas de uma tabela falha — a causa habitual é um ficheiro escrito por uma versão do Access mais recente do que a que o leitor compreende. Converta ou volte a exportar o ficheiro a partir do Access e execute a importação novamente.

Um ficheiro cujas tabelas estão todas genuinamente vazias é importado com êxito e comunica um aviso de que não foram carregados registos.
