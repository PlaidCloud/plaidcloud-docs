## Descrição

Importa ficheiros de texto delimitado do PlaidCloud Document. Inclui, entre outros, os seguintes tipos de delimitador:
* vírgula (, )
* barra vertical (|)
* ponto e vírgula (; )
* tabulação
* espaço ( )
* arroba (@)
* til (~)
* dois pontos (:)

### Inspecionar ficheiro de origem selecionado

Ao premir o botão *Deduzir definições a partir do ficheiro de origem*, o PlaidCloud abre o ficheiro e inspeciona-o para tentar determinar o formato dos dados.  Verifique sempre
as definições deduzidas para se certificar de que parecem corretas.

<Aside>Se for selecionado um diretório de ficheiros para importação ou se for utilizada a pesquisa, o primeiro ficheiro encontrado será utilizado para a dedução</Aside>

Um passo cujo ficheiro não produz colunas não pode ser guardado: a gravação é interrompida com **Nenhuma coluna detetada**. Quando o PlaidCloud não conseguiu ler o ficheiro, a mensagem indica o motivo, por exemplo uma extensão pouco habitual num ficheiro delimitado ou um caminho de ficheiro que utiliza uma variável de fluxo de trabalho que não está definida. Caso contrário, verifique se o delimitador e os carateres de aspas e de escape correspondem ao ficheiro, se este é um ficheiro de texto delimitado e se não está vazio.

### Formato dos dados

#### Delimitador
Como referido acima, **Inspect Source File** tenta determinar o delimitador no ficheiro de origem. Se pretender outro delimitador, utilize esta
secção para o especificar. Os utilizadores podem escolher numa lista de delimitadores padrão. Um passo sem delimitador definido utiliza uma vírgula.
* vírgula (, )
* barra vertical (|)
* ponto e vírgula (; )
* tabulação
* espaço ( )
* arroba (@)
* til (~)
* dois pontos (:)

#### Tipo de cabeçalho

Como os CSV podem ou não conter cabeçalhos, o PlaidCloud oferece uma forma de utilizar os cabeçalhos, ignorá-los ou utilizar a ordem das colunas para determinar o alinhamento das colunas.
* **Sem cabeçalho**: o ficheiro CSV não contém cabeçalho.  Utilize a lista de origem no *Data Mapper* para determinar o alinhamento das colunas
* **Tem cabeçalho - usar cabeçalho e substituir lista de campos**: o ficheiro CSV tem um cabeçalho.  Utilize os nomes de cabeçalho especificados e ignore a lista de origem no *Data Mapper*.
* **Tem cabeçalho - ignorar cabeçalho e usar a lista de campos**: o ficheiro CSV tem um cabeçalho, mas este deve ser ignorado.  Utilize os nomes de cabeçalho especificados pela lista de origem no *Data Mapper*.

O **Tipo de cabeçalho** é guardado em `header_treatment` como `use` ou `skip` para as duas opções de cabeçalho. O passo Importar Excel aceita também `dynamic`.

#### Formato de data

Esta definição é útil se as datas contidas no ficheiro CSV não forem facilmente reconhecíveis como datas e horas.  O processo de importação tenta converter as datas, mas ter um pouco mais de informação
pode ajudar no processo de importação.

Um valor que o armazém não consiga ler com o formato indicado é guardado como vazio, em vez de interromper a importação, pelo que um formato que não corresponda ao ficheiro
produz uma coluna de datas vazias e uma importação que, ainda assim, indica êxito. Depois de alterar esta definição, verifique a coluna importada antes de confiar no resultado.

<Aside type="caution" title="Colunas de hora no Lakehouse v2">
Uma coluna cujo tipo de dados é **Hora** é importada como vazia no Lakehouse v2, seja qual for o formato de data que indicar. A função do armazém utilizada para a analisar não consegue
produzir um valor de hora do dia isolado. Importe a coluna como **Carimbo de data/hora** e leia a hora a partir dele, ou importe-a como **Texto**. As colunas **Data** e **Carimbo de data/hora**
não são afetadas.
</Aside>

### Caracteres especiais

As entradas de caracteres especiais controlam a forma como o PlaidCloud trata a presença de determinados caracteres e o que significam no contexto do processamento do CSV
 * **Carácter de aspas**: o carácter utilizado para indicar um conjunto de texto delimitado que deve ser processado como um único campo. Quando não está definido, é uma aspa dupla (`"`).
 * **Carácter de escape**: o carácter utilizado para indicar que o carácter seguinte deve ser processado tal como está e não interpretado como carácter especial.  É útil quando um campo pode conter o delimitador. Quando não está definido, é uma barra invertida (`\`).
 * **Carácter nulo**: como os CSV não têm tipos de dados, este carácter permite indicar que o valor deve ser NULL em vez de uma cadeia vazia ou 0.
 * **Campos vazios**: um campo vazio é carregado como NULL em todos os lakehouses, tanto em colunas de texto como numéricas, pelo que um número em branco é NULL e não 0. Uma célula que contenha apenas espaços é carregada tal como está.
 * **Negativos à direita**: alguns sistemas de origem geram números negativos com o símbolo negativo no fim, em vez de o colocarem como prefixo.  Esta definição processa-os como números negativos.

### Seleção de linhas

Para ficheiros de entrada com registos estranhos, defina **Ignorar linhas** com o número de linhas a ignorar antes de processar os dados.  É útil se os ficheiros contiverem blocos de cabeçalho que têm de ser ignorados antes de chegar aos dados tabulares.

As linhas ignoradas incluem as linhas em branco. Com um **Tipo de cabeçalho** **Tem cabeçalho - usar cabeçalho e substituir lista de campos**, o cabeçalho é lido a partir da primeira linha depois das linhas ignoradas, pelo que os dados são mapeados para as colunas de destino pelo nome do cabeçalho. Um ficheiro que contenha apenas as linhas ignoradas e um cabeçalho, sem linhas de dados, não importa nada e o passo conclui na mesma.

#### Exemplo: exportação de lista do SAP

Uma exportação de lista do SAP, como KE24, KSB1 ou FAGLL03, começa com um bloco de seleção, muitas vezes com linhas em branco, antes do cabeçalho das colunas:

```text
Line Item Journal Entries
Company Code: 1000
Posting Date: 2026-09-01 to 2026-09-30

Company Code|Document Number|Posting Date|Amount
1000|100004512|2026-09-03|1,500.00
```

O cabeçalho está na linha 5, pelo que existem quatro linhas antes dele. Defina **Ignorar linhas** como `4` e **Tipo de cabeçalho** como **Tem cabeçalho - usar cabeçalho e substituir lista de campos**. A importação lê `Company Code`, `Document Number`, `Posting Date` e `Amount` como nomes das colunas, e a primeira linha de dados é a linha a seguir ao cabeçalho.

Selecione **Keep Quoted Empty Fields ("") As Empty String** para carregar um campo vazio entre aspas como uma cadeia vazia em vez de NULL.

### Definições adicionais

**Mais opções de CSV** contém estes campos:

* **Codificação** (`encoding`) — o codec de Python com que o ficheiro é lido, em vez de ser detetado. Os bytes que não descodificam são lidos como U+FFFD.
* **Delimitadores** (`delimiters`) — uma matriz JSON com todos os textos que separam colunas, em vez de um único delimitador. Cada um pode ter vários carateres. Selecione **Vários delimitadores seguidos contam como um** (`combine_delimiters`) para contar vários delimitadores seguidos como um.
* **Delimitador de linha** (`row_delimiter`) — o texto que termina uma linha quando se encontra fora de aspas; uma quebra de linha noutro local passa então a fazer parte do valor. Se ficar em branco, qualquer quebra de linha termina uma linha.
* **Prefixo de linha de comentário** (`comment`) — as linhas que começam com este texto não são importadas. **Comentários** (`comments`) lista comentários como pares **Começa por** e **Termina com** que são removidos onde quer que se encontrem fora de aspas; sem **Termina com**, um comentário prolonga-se até ao fim da linha.
* **Continuação de linha** (`line_continuation`) — este texto antes de uma quebra de linha junta a linha à seguinte.
* **Aspa de fecho** (`quote_end`) — a aspa que termina um valor entre aspas, quando difere do **Carácter de aspas**. Selecione **Um valor entre aspas mantém as aspas** (`keep_quotes`) para manter os carateres de aspas de um valor entre aspas.
* **Importar uma linha vazia como uma linha de valores vazios** (`keep_blank_lines`) — uma linha vazia é importada como uma linha de valores vazios em vez de ser omitida.
