## Descrição

O passo **Espacial: exportação de ficheiro** escreve uma tabela num ficheiro espacial numa conta de documentos, com um elemento por linha: a geometria a partir de uma coluna WKT e as restantes colunas como atributos do elemento. Utilize-o em conjunto com [Spatial File Import](/pt-pt/reference/workflow-steps/spatial/spatial-file-import/).

O formulário do passo tem uma secção **Origem e ficheiro** para a tabela de origem, as respetivas colunas, o ficheiro de saída e o que acontece quando o ficheiro já existe, e uma secção **Geometria** para a coluna de geometria e o sistema de coordenadas. Os [fluxos de trabalho KNIME migrados](/pt-pt/guides/workflows/migrate-knime-workflows/) utilizam este passo para os respetivos escritores de ficheiros geoespaciais.

## Configuração

- **Tabela de origem** (`source`) — a tabela a exportar. **Colunas de origem** (`source_columns`) lista as colunas escritas.
- **Ficheiro de saída** (`output_file`) — a conta de documentos e o caminho do ficheiro. A extensão determina o formato: `.shp` (shapefile ESRI), `.geojson` ou `.json` (GeoJSON), `.gpkg` (GeoPackage), `.kml`, `.gml`, ou `.tab` e `.mif` (MapInfo). Um formato composto por vários ficheiros, como um shapefile, é escrito com os ficheiros complementares ao lado.
- **Coluna de geometria** (`geometry_column`) — a coluna que contém a geometria de cada elemento em WKT. O valor predefinido é `SpatialObj`.
- **Sistema de coordenadas** (`crs`) — o sistema de referência de coordenadas em que as geometrias estão, como `EPSG:4326`, escrito com o ficheiro.
- **Um ficheiro que já existe** (`if_exists`) — **Sobrescrevê-lo** (`overwrite`, predefinido) substitui um ficheiro que já lá esteja; **Fazer a etapa falhar sem escrever nada** (`fail`) interrompe o passo antes de ser escrito o que quer que seja.
