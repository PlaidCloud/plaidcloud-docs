## Descrição

Lê uma ou mais listas do Anaplan através da sua [ligação Anaplan](/pt-pt/guides/connections/anaplan/) e carrega-as numa dimensão do PlaidCloud. **Um passo lê uma hierarquia composta inteira** — indique todas as listas que ela abrange, começando pela raiz (por exemplo Região, depois País, depois Loja) — em vez de a dividir por vários passos: a tabela de preparação é substituída por completo em cada execução, pelo que vários passos apontados para a mesma tabela de preparação apagariam, cada um, as linhas do anterior.

Este passo aparece no menu de passos em **Anaplan**, com a etiqueta **Leitura de lista**.

O passo chega ao Anaplan **diretamente na nuvem** através da sua API de integração — não existe caminho por agente local.

<Aside type="tip">
Este conector é só de leitura e autentica-se com credenciais Basic (nome de utilizador e palavra-passe) ou de certificado CA — veja [Autenticação](/pt-pt/guides/connections/anaplan/#autenticação). O orçamento de pedidos do Anaplan é partilhado por todo o inquilino, pelo que deve desfasar o agendamento deste passo relativamente aos seus outros fluxos de trabalho Anaplan — veja [Considerações sobre o agendamento](/pt-pt/guides/connections/anaplan/#considerações-sobre-agendamento).
</Aside>

## Configuração

### Origem Anaplan

| Campo | Obrigatório | Notas |
|---|---|---|
| Ligação Anaplan | Sim | A [ligação Anaplan](/pt-pt/guides/connections/anaplan/) através da qual ler. |
| Ambiente | Sim | O ambiente da ligação. |
| Modelo | Não | Substitui o ID do modelo guardado na ligação. Descoberto em tempo real a partir da ligação, ou escrito à mão. |
| Listas | Sim | Todas as listas do Anaplan que a hierarquia abrange, como uma lista ordenada. Adicione listas descobertas a partir do modelo escolhido, ou escreva um ID à mão, e depois reordene com Mover para cima / Mover para baixo. Listá-las começando pela raiz lê-se bem, mas a ordem não altera o que é carregado — todas as listas são lidas antes de qualquer elemento superior ser resolvido. |
| Tabela de preparação | Sim | As linhas em bruto de elemento superior/elemento inferior/consolidação/nome e de propriedades são carregadas aqui antes de a dimensão do PlaidCloud ser construída a partir delas. |

### Dimensão PlaidCloud de destino

| Campo | Obrigatório | Notas |
|---|---|---|
| Especificar dimensão dinamicamente | Uma das duas | Nome da dimensão de destino, que pode conter tokens `{variable}` resolvidos em tempo de execução. Selecionado por predefinição. |
| Utilizar dimensão específica | Uma das duas | Escolha, em vez disso, uma dimensão do PlaidCloud já existente. |

**Pré-visualização** no separador **Origem** mostra as colunas e os tipos de dados que esta leitura de lista produziria, sem executar o passo. Não está disponível num projeto bloqueado.

## O que este passo não consegue representar

| Limitação | O que significa |
|---|---|
| Cada aresta agrega-se com um simples `+` | As hierarquias de listas do Anaplan não têm peso nem sinal por aresta — não há nada para ler, pelo que nada se perde na tradução, mas também nada mais pode ser representado. Se um modelo exprime exclusões ou agregações negativas através de um item de linha ou de uma propriedade, essa lógica não é transportada para a dimensão e tem de ser reconstruída a jusante. |
| As sinalizações de controlo de acesso e a pertença a subconjuntos não são importadas | As sinalizações de leitura/escrita de Selective Access e a pertença de cada item a subconjuntos da lista são metadados do Anaplan, não dados da dimensão — importar cada subconjunto como a sua própria coluna entraria, de outro modo, em colisão com propriedades reais num espaço de nomes partilhado em crescimento. Uma propriedade genuína da lista cujo nome colida com qualquer uma delas é recusada em vez de ser carregada em silêncio sob o nome da outra. |
| Os subconjuntos de itens de linha não são legíveis como dimensões | O Anaplan expõe-nos apenas através de um endpoint genérico de itens de dimensão, não como uma lista que este passo possa ler. |
| Uma lista com mais de 1 000 000 de registos não pode ser lida por este caminho | O endpoint de itens de onde este passo lê recusa liminarmente acima desse limite documentado em vez de devolver um resultado parcial, e não oferece forma de paginar para o contornar — pelo que o passo recusa e indica o limite em vez de carregar uma dimensão parcial. Entretanto, divida a lista no Anaplan ou leia um subconjunto dela. |
| Um nó fica sob exatamente um elemento superior | Um item cujo nome do elemento superior e ID do elemento superior discordam, cujo elemento superior está numa lista que este passo não lê, ou cujo elemento superior nomeado não existe de todo, é recusado pelo nome em vez de ser silenciosamente reatribuído à raiz da dimensão. |
| O item de nível superior de uma lista não é importado | O item de nível superior do Anaplan é um nó de agregação que fica acima de todos os itens da lista em vez de ser um item da própria lista, pelo que nunca é devolvido pelos itens que este passo lê. A dimensão acaba com um nível a menos do que a lista do Anaplan, e as próprias raízes da lista tornam-se as raízes da dimensão. O passo avisa quando uma lista lida declara um. |
| Os IDs dos nós têm de ser únicos em todas as listas lidas em conjunto | O ID de um nó é o código Anaplan do item, ou o seu nome quando não tem nenhum — e um código Anaplan só é garantidamente único dentro de uma lista. Duas listas que reutilizem os mesmos códigos curtos são recusadas pelo nome em vez de serem silenciosamente fundidas num só nó. |
| Não são suportadas hierarquias alternativas | Cada lista é carregada na hierarquia principal da dimensão. |
| Só de leitura | Nada é alguma vez escrito de volta no Anaplan. |
