## Descrição

Lê uma ou mais listas do Anaplan através da sua [ligação Anaplan](/pt-pt/guides/connections/anaplan/) e carrega-as numa dimensão PlaidCloud. **Um único passo lê uma hierarquia composta inteira** — indique todas as listas que ela abrange, começando pela raiz (por exemplo, Região, depois País, depois Loja) — em vez de a dividir por vários passos: a tabela de preparação é substituída por completo em cada execução, pelo que vários passos apontados para a mesma tabela de preparação apagariam, cada um, as linhas do anterior.

Este passo aparece no menu de passos em **Anaplan**, com a designação **Leitura de lista**.

O passo acede ao Anaplan **diretamente na nuvem** através da respetiva API de integração — não existe um caminho através de agente local.

<Aside type="tip">
Este conector é só de leitura e autentica-se com credenciais Basic (nome de utilizador e palavra-passe) ou com Certificado CA — consulte [Autenticação](/pt-pt/guides/connections/anaplan/#autenticação). O orçamento de pedidos do Anaplan é partilhado por todo o tenant, pelo que deve escalonar o agendamento deste passo em relação aos seus outros fluxos de trabalho Anaplan — consulte [Considerações sobre o agendamento](/pt-pt/guides/connections/anaplan/#considerações-de-agendamento).
</Aside>

## Configuração

### Origem Anaplan

| Campo | Obrigatório | Notas |
|---|---|---|
| Ligação Anaplan | Sim | A [ligação Anaplan](/pt-pt/guides/connections/anaplan/) através da qual se faz a leitura. |
| Ambiente | Sim | O ambiente da ligação. |
| Modelo | Não | Substitui o ID do modelo guardado na ligação. Detetado em direto a partir da ligação ou introduzido manualmente. |
| Listas | Sim | Todas as listas do Anaplan que a hierarquia abrange, como lista ordenada. Adicione listas detetadas a partir do modelo escolhido ou introduza um ID manualmente e, em seguida, reordene com Mover para cima / Mover para baixo. Indicá-las começando pela raiz é mais legível, mas a ordem não altera o que é carregado — todas as listas são lidas antes de qualquer elemento superior ser resolvido. |
| Tabela de preparação | Sim | As linhas de elemento superior/subordinado/consolidação/nome e de propriedades são colocadas aqui antes de a dimensão PlaidCloud ser construída a partir delas. |

### Dimensão PlaidCloud de destino

| Campo | Obrigatório | Notas |
|---|---|---|
| Especificar dimensão dinamicamente | Uma das duas | Nome da dimensão de destino, que pode conter tokens `{variable}` resolvidos no momento da execução. Selecionada por predefinição. |
| Utilizar dimensão específica | Uma das duas | Escolha, em alternativa, uma dimensão PlaidCloud já existente. |

## O que este passo não consegue representar

| Limitação | O que significa |
|---|---|
| Cada aresta é consolidada com um simples `+` | As hierarquias de listas do Anaplan não têm peso nem sinal por aresta — não há nada para ler, pelo que nada se perde na tradução, mas também não é possível representar mais nada. Se um modelo exprimir exclusões ou consolidações negativas através de um item de linha ou de uma propriedade, essa lógica não é transportada para a dimensão e tem de ser reconstruída a jusante. |
| As sinalizações de controlo de acesso e a pertença a subconjuntos não são importadas | As sinalizações de leitura/escrita do Acesso seletivo e a pertença de cada item a subconjuntos da lista são metadados do Anaplan, não dados de dimensão — importar cada subconjunto como uma coluna própria colidiria, de outro modo, com propriedades reais num espaço de nomes partilhado em crescimento. Uma propriedade genuína da lista cujo nome colida com qualquer uma delas é recusada, em vez de ser carregada silenciosamente sob o nome da outra. |
| Os subconjuntos de itens de linha não podem ser lidos como dimensões | O Anaplan expõe-nos apenas através de um ponto de acesso genérico de itens de dimensão, e não como uma lista que este passo possa ler. |
| Uma lista com mais de 1 000 000 de registos não pode ser lida por este caminho | O ponto de acesso de itens que este passo lê recusa o pedido por completo acima desse limite documentado, em vez de devolver um resultado parcial, e não oferece forma de paginar para o contornar — pelo que o passo recusa e indica o limite, em vez de carregar uma dimensão parcial. Entretanto, divida a lista no Anaplan ou leia um subconjunto da mesma. |
| Um nó tem exatamente um elemento superior | Um item cujo nome e ID do elemento superior não coincidam, cujo elemento superior esteja numa lista que este passo não lê, ou cujo elemento superior indicado não exista de todo, é recusado por nome, em vez de ser silenciosamente reatribuído à raiz da dimensão. |
| O item de nível superior de uma lista não é importado | O item de nível superior do Anaplan é um nó de consolidação que fica acima de todos os itens da lista, e não um item da própria lista, pelo que nunca é devolvido pelos itens que este passo lê. A dimensão fica com um nível a menos do que a lista do Anaplan e as raízes da própria lista passam a ser as raízes da dimensão. O passo emite um aviso quando uma lista lida declara um item destes. |
| Os IDs dos nós têm de ser únicos em todas as listas lidas em conjunto | O ID de um nó é o código Anaplan do item ou, se não tiver código, o seu nome — e um código Anaplan só tem unicidade garantida dentro de uma lista. Duas listas que reutilizem os mesmos códigos curtos são recusadas por nome, em vez de serem silenciosamente fundidas num único nó. |
| As hierarquias alternativas não são suportadas | Todas as listas são carregadas na hierarquia principal da dimensão. |
| Só de leitura | Nunca se escreve nada de volta no Anaplan. |
