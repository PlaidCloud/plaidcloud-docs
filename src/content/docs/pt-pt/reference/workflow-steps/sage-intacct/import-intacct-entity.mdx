## Descrição

Importa um objeto do Sage Intacct para uma tabela do projeto através da sua [ligação Sage Intacct](/pt-pt/guides/connections/sage-intacct/), utilizando as operações `readByQuery`/`readMore` do XML Gateway do Intacct para percorrer automaticamente todo o conjunto de resultados. Escolha a ligação, o objeto e os filtros pretendidos; o passo obtém os registos correspondentes e grava-os, sem paginação manual para gerir.

Este é um passo genérico predefinido — um tipo de passo abrange sete objetos, desde o detalhe de transações e saldos do razão geral (`GLDETAIL`, `GLACCOUNTBALANCE`, `GLENTRY`) até aos mestres de dimensões (`LOCATION`, `DEPARTMENT`, `CLASS`) e aos documentos de encomenda (`SODOCUMENT`).

<Aside type="note">
Este passo é diferente de [Import Sage Intacct Query](/pt-pt/reference/workflow-steps/sage-intacct/import-intacct-query/), que se aplica a **qualquer** objeto do Intacct com um seletor de campos de uso geral. O passo `Import Intacct Entity` é o passo de catálogo nativo especificamente para estes sete objetos, com uma lista de filtros permitidos por objeto e paginação `readMore` automática para conjuntos de resultados grandes (o detalhe do razão geral, em particular, pode ultrapassar largamente uma única página da API do Intacct).
</Aside>

## Configuração

| Campo | Obrigatório | Notas |
|---|---|---|
| Ligação Sage | Sim | A ligação Sage Intacct através da qual os dados são lidos. |
| Tabela de destino | Sim | A tabela do projeto onde os resultados são gravados. É totalmente substituída em cada execução. |
| Objeto | Sim | O objeto do Intacct a importar. Um de `GLDETAIL`, `GLACCOUNTBALANCE`, `GLENTRY`, `LOCATION`, `DEPARTMENT`, `CLASS`, `SODOCUMENT`. |
| Filtros | Não | Uma matriz de cláusulas `{field, operator, value}`. Os operadores incluem `eq`, `ne`, `gt`, `ge`, `lt`, `le`. Um intervalo exprime-se com duas cláusulas sobre o mesmo campo — uma `ge` e outra `le`. Cada objeto limita os filtros à sua própria lista de campos e operadores permitidos; uma combinação de campo ou operador não suportada é rejeitada, não ignorada silenciosamente. |

### Objetos e filtros de intervalo habituais

| Objeto | O que importa | Filtros de intervalo comuns |
|---|---|---|
| `GLDETAIL` | Detalhe de linhas de transação do razão geral | data de lançamento (`ge`/`le`), montante (`ge`/`le`) |
| `GLACCOUNTBALANCE` | Saldos de contas por período | data de fim do período (`ge`/`le`) |
| `GLENTRY` | Linhas de lançamentos de diário registados | data de lançamento (`ge`/`le`) |
| `LOCATION` | Mestre da dimensão de localização | — (apenas filtros de igualdade) |
| `DEPARTMENT` | Mestre da dimensão de departamento | — (apenas filtros de igualdade) |
| `CLASS` | Mestre da dimensão de classe | — (apenas filtros de igualdade) |
| `SODOCUMENT` | Documentos de encomendas de venda | data do documento (`ge`/`le`) |

## Como funciona a paginação

O XML Gateway do Intacct devolve os resultados uma página de cada vez. Este passo emite a chamada inicial `readByQuery` e depois segue com chamadas `readMore` utilizando o ID do conjunto de resultados devolvido pelo Intacct, até todas as páginas terem sido lidas — pelo que uma extração de `GLDETAIL` com dezenas de milhares de linhas termina numa só execução do passo, sem necessidade de ajustar o tamanho da página.

<Aside type="caution">
Uma extração muito ampla e sem filtros sobre `GLDETAIL` ou `GLENTRY` pode ainda demorar muito a ser percorrida na totalidade. Delimite uma extração grande com um intervalo de datas de lançamento em vez de contar apenas com a paginação para a tornar rápida.
</Aside>
