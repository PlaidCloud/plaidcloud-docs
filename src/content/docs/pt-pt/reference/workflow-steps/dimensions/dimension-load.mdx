## Descrição

Carrega ou atualiza uma dimensão a partir de dados de uma tabela PlaidCloud. Trata tanto as cargas iniciais (criar a hierarquia de raiz) como as atualizações incrementais (adicionar membros, alterar elementos superiores, atualizar propriedades sem reconstruir de raiz).

Suporta dois formatos de dados de origem: **Elemento superior-subordinado** (uma linha por aresta da árvore) e **Níveis** (uma coluna por nível da hierarquia, um caminho completo por linha). Valores, aliases e propriedades podem ser carregados juntamente com os dados estruturais.


## Seleção de dimensão
### Especificar dimensão dinamicamente
Para especificar uma dimensão dinamicamente, inclua variáveis de **projeto** e/ou **locais** no nome.


As variáveis são úteis quando as dimensões são atualizadas periodicamente e se pretende manter a vista histórica.

Um exemplo que usa a variável `current_month` para carregar dinamicamente a dimensão:

```text
dimension_name_{current_month}
```
### Utilizar dimensão específica

Para usar uma dimensão específica, selecione a **dimensão** no menu pendente.


### Carregar para hierarquia alternativa

Para carregar uma hierarquia alternativa, selecione primeiro a dimensão, de forma dinâmica ou específica, assinale a caixa Carregar para hierarquia alternativa e introduza o nome da hierarquia alternativa a carregar.

<Aside>É frequentemente útil ter vistas / consolidações alternativas da dimensão principal. Por exemplo, os centros de custo têm normalmente uma consolidação contabilística, mas pode ser desejável uma vista alternativa baseada na estrutura organizacional.</Aside>

Um membro que não esteja na hierarquia principal só pode estar numa hierarquia alternativa. Uma carga que o colocasse também numa segunda hierarquia alternativa falha e indica o membro e a hierarquia alternativa que já o contém. Para usar uma folha em várias hierarquias alternativas, adicione-a primeiro à hierarquia principal. Um elemento superior precisa do seu próprio nome em cada hierarquia alternativa, porque uma hierarquia alternativa não pode adicionar membros sob um membro da hierarquia principal.

## Tabela de origem

### Dinâmica
Para especificar a tabela de origem dinamicamente, assinale a **caixa Dinâmica** e introduza o nome da tabela, incluindo variáveis de **projeto** e/ou **locais** no nome.

### Estática

Para usar uma **tabela de origem** específica, selecione a tabela no menu pendente.

## Propriedades da dimensão e disposição da tabela

### Tipo de consolidação predefinido

Existem três opções de tipo de consolidação:
* **"+"**: agrega valores na dimensão.
* **"-"**: subtrai valores na dimensão.
* **"~"**: não é feita qualquer agregação na dimensão.

<Aside>Na tabela de dados de origem pode incluir **Tipo de consolidação** como coluna, para que possam ser usados vários tipos de consolidação numa dimensão. A coluna **Tipo de consolidação** é depois usada na secção **Mapeamento de colunas** abaixo.</Aside>

### Formato das colunas da tabela
Existem duas opções de formato para a **Tabela de origem** ao carregar uma dimensão.
#### Elemento superior-subordinado
Numa tabela de elemento superior-subordinado existem duas colunas que representam a estrutura da dimensão, **Parent** e **Child**.

**EXEMPLO DE ELEMENTO SUPERIOR-SUBORDINADO**

| PARENT    | CHILD    | Consolidation Type |
|-----------|----------|--------------------|
|Parent All | Parent 1 |        ~           |
|Parent All | Parent 2 | ~                  |
| Parent 1  | Child 1  | +                  |
| Parent 2  | Child 2  | +                  |
| Child 1   | Child 3  | +                  |
| Child 1   | Child 4  | +                  |
| Child 2   | Child 5  | +                  |

<Aside>No formato de tabela de elemento superior-subordinado, também pode incluir uma coluna **Tipo de consolidação** na tabela. O **Tipo de consolidação** fica associado ao subordinado.</Aside>

Uma linha com elemento superior vazio carrega o respetivo subordinado como membro de nível superior, diretamente sob a raiz. Uma linha com subordinado vazio é ignorada.

#### Níveis achatados
Numa tabela de níveis achatados existe um número ilimitado de colunas, cada uma representando um nível da dimensão.

**EXEMPLO DE NÍVEIS ACHATADOS**

|Level 1   |Level 2 |Level 3|Level 4|
|----------|--------|-------|-------|
|Parent All|Parent 1|Child 1|Child 3|
|Parent All|Parent 1|Child 1|Child 4|
|Parent All|Parent 2|Child 2|Child 5|

## Mapeamento de colunas

Utilizar o botão de menu **Inspecionar origem** preenche a **Coluna de origem** no Data Mapper.
Depois de preenchida a **Coluna de origem**, use o menu pendente **Tipo** para mapear as **Colunas de origem** para o tipo de coluna adequado.
