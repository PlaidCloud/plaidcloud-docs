## Descrição



Divide o valor de uma linha de origem em partes e encaminha cada parte para um destino diferente, com proporções determinadas por dados de driver. Mais simples do que [Allocation Rules](/pt-pt/reference/workflow-steps/allocation/allocation-rules/) — utilize-o quando só precisa de distribuir valores sem uma dimensão de atribuição.

Padrão comum: pegar num montante total, dividi-lo por vários destinatários com base em percentagens ou ponderações numa tabela de indutores e produzir uma linha de saída por destinatário.

## Definições da tabela de dados  

A **Tabela de valores a alocar**, a **Tabela de dados de driver** e a **Tabela de resultados da alocação** podem ser selecionadas de forma dinâmica ou estática.

### Seleção dinâmica de tabelas
A opção de tabela dinâmica permite especificar uma tabela através de texto e variáveis.  Isto é útil em fluxos de trabalho orientados por variáveis, em que as referências a tabelas ou vistas são relativas às variáveis especificadas.

Um exemplo que utiliza a variável `current_month` para apontar dinamicamente para uma tabela:

```text
legal_entity/inputs/{current_month}/ledger_values
```

### Seleção estática de tabelas
Quando pretende uma tabela específica como origem, deixe a caixa *Dynamic* desmarcada e selecione a tabela de origem no menu pendente.


O Explorador de tabelas está sempre disponível em qualquer seleção de tabela.  Clique no botão do Explorador de tabelas à direita da seleção de tabela e será aberta uma janela do Explorador de tabelas.

<Aside>A **Tabela de resultados da alocação** tem de ser uma tabela e não uma vista.</Aside>

### Tabela de valores a alocar

Esta é a tabela que contém os valores a alocar. Normalmente, são valores de custo ou de receita.  


### Tabela de dados de driver

A tabela de dados de driver contém os valores que o passo de alocação utilizará para alocar custos. 


Exemplos:

- Para uma cadeia de abastecimento atribuir custos a clientes, pode utilizar dados de entregas com o número de entregas ou o peso das entregas como indutor.
- Para um centro de apoio de TI atribuir os seus custos aos departamentos que apoia, os dados do indutor podem ser o número de pedidos por centro de custo. 

#### Driver Data Sign Rule
Os dados de driver podem conter valores positivos e negativos. A **Driver Data Sign Rule** permite-lhe decidir como os sinais em conflito serão tratados.
- **Error on conficting signs** - O passo de alocação produz um erro e pára se forem encontrados sinais em conflito.
- **Proceed with warning on conflicting signs** - O passo de alocação utiliza valores de indutor negativos e positivos, mas apresenta um aviso.
- **Use only positive driver values** - O passo de alocação utiliza apenas valores de indutor positivos e ignora os negativos.
- **Use only negative driver values** - O passo de alocação utiliza apenas valores de indutor negativos e ignora os positivos.
- **Use absolute values of driver data** - O passo de alocação utiliza os valores absolutos dos dados de driver.


### Tabela de resultados da alocação



#### Acrescentar resultados à tabela de destino
Se esta caixa estiver marcada, os resultados da alocação são acrescentados à tabela de resultados da alocação. 
Se esta caixa não estiver marcada, a tabela de resultados da alocação é substituída sempre que o passo de alocação é executado.

#### Colunas separadas para os resultados alocados

Se esta caixa estiver marcada, a tabela de resultados mostra o montante de cada registo alocado, bem como o montante realmente alocado a cada registo de indutor.
