## Descrição


Use-o para executar uma junção externa em 2 tabelas de dados, combinando-as numa única tabela de dados com base nas chaves de junção especificadas. O controlo **Tipo de junção** seleciona que linhas sem correspondência manter — uma junção **à esquerda**, **à direita** ou **externa completa**. A predefinida é uma junção à esquerda (todas as linhas da Tabela A, com as colunas da Tabela B preenchidas onde as chaves correspondem).


Para mais detalhes sobre a metodologia da junção externa, veja aqui: [Wikipedia SQL Join](http://en.wikipedia.org/wiki/Join_%28SQL%29)

## Colunas indicadas em tempo de execução

Selecione **Transportar também colunas indicadas em tempo de execução** para passar, sem alterações, todas as colunas de origem que o passo não lista, tal como a tabela as tem quando o passo é executado. Use-o quando um passo anterior cria colunas cujos nomes dependem dos dados, como uma pivotagem, de modo que não as pode listar ao construir o passo. Deixe-o desativado para escrever apenas as colunas que lista.

### Tipo de junção

Escolha como as linhas sem correspondência são mantidas:

- **Junção à esquerda** — mantém todas as linhas da Tabela A; as colunas da Tabela B só são preenchidas onde as chaves de junção correspondem. É a predefinida.
- **Junção à direita** — mantém todas as linhas da Tabela B; as colunas da Tabela A só são preenchidas onde as chaves de junção correspondem.
- **Junção externa completa** — mantém todas as linhas de ambas as tabelas, tenham ou não correspondência do outro lado.

## Exemplos


### Juntar fabricantes de automóveis com modelos


Neste exemplo, considere as seguintes tabelas de dados de origem. A primeira é uma lista de fabricantes de automóveis.




| Mfg_ID | Manufacturer |
|--------|--------------|
|    1   | Aston Martin |
|    2   | Porsche      |
|    3   | Lamborghini  |
|    4   | Ferrari      |
|    5   | Koenigsegg   |


A seguinte é uma lista de modelos de automóveis com um ID de fabricante. Repare que há vários modelos sem fabricante.




| ModelName          | Mfg_ID |
|--------------------|--------|
| Aventador          |    3   |
| Countach           |    3   |
| DBS                |    1   |
| Enzo               |    4   |
| One-77             |    1   |
| Optimus Prime      |        |
| Batmobile          |        |
| Agera              |    5   |
| Lightning McQueen  |        |

Para obter uma lista de modelos por fabricante, faz sentido juntar por *Mfg_ID*. Ao tirar partido dos conceitos de junção externa, a saída também poderá mostrar os itens que não têm nenhuma correspondência.



Primeiro, especifique os parâmetros de **Table 1 Data Selection**. A tabela de dados de origem é selecionada e todas as colunas são listadas.



Depois, especifique os parâmetros de **Table 2 Data Selection.** Mais uma vez, a tabela de dados de origem é selecionada e todas as colunas são listadas.



Por fim, as condições de junção são definidas no separador **Saída**. Com o botão **Deduzir**, o Analyze identifica corretamente a coluna *Mfg_ID* a usar como **Join Key**. Como este exemplo mantém as linhas sem correspondência de ambas as tabelas, defina o **Tipo de junção** como **Junção externa completa**. Por último, as 


**Colunas de saída de destino** são especificadas automaticamente com o botão **Propagar**. Isto inclui efetivamente todas as colunas de todas as tabelas, com quaisquer colunas de junção, obviamente, incluídas apenas uma vez. Repare que as colunas estão ordenadas alfabeticamente, primeiro por *Manufacturer* e depois por *ModelName*.



Como esperado, a saída final inclui todas as linhas de ambas as tabelas, quer tenham correspondência em ambas as tabelas ou não. Assim, desta vez *Porsche* aparece de facto, apesar de não ter modelos. Além disso, *Batmobile*, *Lightning McQueen* e *Optimus Prime* estão incluídos nos resultados, embora nenhum deles tenha fabricante. Afinal, quem consegue dizer "não" a estes?
