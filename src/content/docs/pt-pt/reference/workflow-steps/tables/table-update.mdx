## Descrição

Atualiza as linhas que correspondem ao filtro e escreve o resultado numa tabela de destino. Todas as
linhas de origem chegam ao destino — as que correspondem ao filtro com os novos valores e
todas as outras exatamente como estavam. O número de linhas do destino é sempre igual ao
número de linhas da origem.

O filtro escolhe as linhas que são *alteradas*, não as linhas que são devolvidas. É isso que
distingue este passo do passo [Table Extract](/pt-pt/reference/workflow-steps/tables/table-extract/),
em que o filtro remove as linhas que não correspondem.

<Aside type="note" title="Este passo já não altera a tabela de origem">
Anteriormente, atualizava a tabela de origem no local. Agora deixa a origem intacta e
escreve num destino separado, de modo que os dados originais continuam disponíveis para comparação e
o passo é executado em todos os armazéns de dados — incluindo os que não permitem alterar uma tabela
no local. Os passos guardados antes desta alteração precisam de uma tabela de destino selecionada para
poderem ser executados, e qualquer passo que lesse a origem à espera de ver as linhas atualizadas
tem de passar a apontar para o novo destino.
</Aside>

## Parâmetros de atualização

<SnippetCommonTableSourceAndTarget />

O destino tem de ser uma tabela diferente da origem — este passo lê todas as linhas de origem
e escreve-as, pelo que apontá-lo de volta para a própria origem acrescentaria o resultado aos
dados que acabou de ler.

<Aside type="note" title="A origem tem de ser uma tabela, não uma vista">
As vistas podem ser escolhidas como **destino** (e são uma boa escolha aqui — uma vista não armazena
dados e é reavaliada em relação à origem de cada vez que é lida), mas não como
**origem**: este passo obtém a lista de colunas do destino a partir do esquema da própria
tabela de origem, que uma vista não tem.
</Aside>

As colunas do destino espelham sempre as da origem, pelo que nunca as escolhe. As colunas que não
atualizar passam inalteradas, incluindo qualquer coluna adicionada à origem
depois de este passo ter sido aberto pela última vez.

## Colunas a atualizar

No separador **Seleção de dados da tabela**, adicione uma linha para cada coluna que pretende alterar e
defina exatamente um dos seguintes:

- **Constante** — um valor fixo.
- **Expressão** — um cálculo, que pode referenciar outras colunas da mesma linha.
- **Definir como nulo** — limpa a coluna.

As colunas que não listar ficam como estão.

Uma **Coluna de atualização** que as colunas de origem à esquerda não listam é apresentada a vermelho, junto a um sinal de aviso ⚠, mesmo numa linha com uma **Constante**, uma **Expressão** ou **Definir como nulo**, porque o passo atualiza essa coluna pelo seu nome exato. Guardar com uma linha assim abre uma caixa de diálogo **Colunas obsoletas encontradas** que oferece **Remover todas e guardar**, **Guardar mesmo assim** ou **Cancelar**.

Ao guardar, também se verifica cada **Coluna de atualização** em relação à tabela de origem tal como está agora, pelo seu nome exato, independentemente do que as colunas de origem listam. Uma coluna de atualização que a tabela não tem é indicada na caixa de diálogo **Colunas de origem em falta**, porque o passo falharia nela quando fosse executado. A própria lista de colunas de origem não é verificada em relação à tabela: este passo lê a tabela tal como está, não a lista.

<Aside type="caution" title="As expressões leem os valores originais da linha">
Uma expressão vê a linha tal como estava *antes* da atualização, pelo que duas colunas podem
trocar valores em segurança num único passo.
</Aside>

## Filtros de dados para atualização

No separador **Filtros de dados para atualização**, introduza a condição que identifica as linhas a
alterar. Deixe-o vazio para atualizar todas as linhas.

Uma linha cuja condição não possa ser avaliada — mais frequentemente porque uma coluna que a condição testa
é nula — é tratada como não correspondente e passa inalterada. Isto corresponde à forma como uma
base de dados avalia a mesma condição.
