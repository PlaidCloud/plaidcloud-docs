## Descrição


Use-o para combinar várias tabelas de dados com a mesma estrutura de colunas numa única tabela de dados. Por exemplo, os dados de séries temporais são um candidato ideal para esta transformação. O resultado são todos os registos das tabelas combinadas.

<Aside>**Union All** não remove duplicados. Se pretender remover registos duplicados, use antes **Union Distinct**.</Aside>

## Origens


A secção **Origens** funciona como uma coleção de todas as tabelas de dados a acrescentar em conjunto. Normalmente, todas as tabelas de dados terão a mesma estrutura de colunas (ou semelhante). Existem dois botões disponíveis para adicionar uma tabela de dados à lista:


* **Inserir linha**
* **Acrescentar linha**

Além disso, clicar com o botão direito do rato na janela **Selecionar origem a editar** apresentará as mesmas opções. Clicar com o botão direito do rato numa tabela já adicionada apresentará também a opção **Eliminar**.


Para executar a transformação corretamente, tem de existir uma entrada na secção **Origens** por cada tabela de dados de origem a acrescentar em conjunto. Estas entradas são listadas pela ordem em que serão acrescentadas. Para ajustar a ordem, clicar com o botão direito do rato numa tabela apresentará as seguintes opções:


* **Mover para baixo** (se aplicável)
* **Mover para o fim** (se aplicável)
* **Mover para cima** (se aplicável)
* **Mover para o início** (se aplicável)

Por predefinição, cada origem tem o nome *New Frame*, mas recomenda-se ao modelador que dê nomes descritivos, clicando duas vezes no nome e mudando-o em conformidade.


<Aside>É importante recordar que o texto apresentado **não** está relacionado com o nome da tabela de dados de origem. Recomendamos que o modelador atribua um nome descritivo, muitas vezes igual ao da tabela de dados de origem, mas tenha em mente que não existe qualquer ligação entre os nomes.</Aside>


## Tabela de destino


Por predefinição, a **Tabela de destino** fica em branco. Antes de atribuir um nome, tenha em conta que as tabelas de dados têm de seguir as convenções de nomenclatura do Linux. Por isso, recomendamos que os nomes sejam compostos apenas por carateres alfanuméricos. O Analyze remove automaticamente do nome quaisquer carateres inválidos. Além disso, limita o comprimento a 256 carateres, por isso seja conciso!

## Correspondência de colunas

**Corresponder colunas por** em **Tabela de destino** escolhe como as origens se alinham:

* **Nome** (predefinição) — as colunas de cada origem são correspondidas às da primeira origem pelo nome.
* **Posição** — as origens são empilhadas por ordem, como faz o `union` do Spark. O resultado assume os nomes das colunas da primeira origem, e todas as origens precisam do mesmo número de colunas. O mapeamento de colunas de cada origem não é usado, pelo que o respetivo separador **Colunas** fica desativado.

Com **Posição**, cada coluna assume um tipo que todas as origens comportam: dois tipos numéricos tornam-se o mais largo, uma data e um carimbo de data/hora tornam-se um carimbo de data/hora, e as outras misturas tornam-se texto. Uma coluna booleana ou binária misturada com outro tipo não tem tipo comum e faz o passo falhar, tal como origens com números de colunas diferentes.

Se todas as tabelas de origem estiverem em falta, o passo termina com um aviso em vez de falhar, em qualquer dos modos.

## O que é verificado ao guardar

Cada origem tem de produzir as mesmas colunas que a primeira origem: os mesmos nomes de colunas e, quando ambas declaram um, o mesmo tipo. A tabela de destino é construída a partir das colunas da primeira origem. Uma origem pode listar as suas colunas numa ordem diferente, porque são correspondidas pelo nome. Guardar um passo cujas origens difiram é recusado, nomeando cada diferença: *A origem 'east' tem de produzir as mesmas colunas que 'west': falta region; não está em 'west': area.*

Guardar também preenche, a partir dessa tabela, o mapeamento de cada origem que tenha uma tabela de origem mas não tenha colunas de origem ou de destino, tal como **Preencher ambas as tabelas de mapeamento** faria.
