## Descrição


Utilize-o para combinar várias tabelas de dados com a mesma estrutura de colunas numa única tabela de dados. Por exemplo, os dados de séries temporais são um candidato ideal para esta transformação. O resultado é sempre o conjunto distinto de registos depois de combinar os dados.

<Aside>**Union Distinct** remove duplicados. Se pretende manter todos os registos, utilize antes **Union All**.</Aside>

## Origens


A secção **Origens** funciona como uma coleção de todas as tabelas de dados a acrescentar em conjunto. Normalmente, todas as tabelas de dados têm a mesma estrutura de colunas (ou uma semelhante). Existem dois botões para adicionar uma tabela de dados à lista:


* **Inserir linha**
* **Acrescentar linha**

Além disso, clicar com o botão direito do rato na janela **Selecionar origem a editar** apresenta as mesmas opções. Clicar com o botão direito do rato numa tabela já adicionada apresenta também a opção **Eliminar**.


Para executar corretamente a transformação, tem de existir uma entrada na secção **Origens** por cada tabela de dados de origem a acrescentar. Estas entradas são listadas pela ordem em que serão acrescentadas. Para ajustar a ordem, clicar com o botão direito do rato numa tabela apresenta as seguintes opções:


* **Mover para baixo** (se aplicável)
* **Mover para o fim** (se aplicável)
* **Mover para cima** (se aplicável)
* **Mover para o início** (se aplicável)

Por predefinição, cada origem chama-se *New Frame*, mas recomenda-se ao modelador que indique nomes descritivos, fazendo duplo clique no nome e mudando-o em conformidade.


<Aside>É importante lembrar que o texto apresentado **não** está relacionado com o nome da tabela de dados de origem. Recomendamos que o modelador indique um nome descritivo, muitas vezes igual ao da tabela de dados de origem, mas tenha em conta que não existe qualquer ligação entre os nomes.</Aside>


## Tabela de destino


Por predefinição, a **Tabela de destino** fica em branco. Antes de lhe atribuir um nome, tenha em conta que as tabelas de dados têm de seguir as convenções de nomenclatura do Linux. Por isso, recomendamos que os nomes sejam compostos apenas por carateres alfanuméricos. O Analyze remove automaticamente quaisquer carateres inválidos do nome. Além disso, limita o comprimento a 256 carateres, por isso seja conciso!

## O que é verificado ao guardar

Cada origem tem de produzir as mesmas colunas que a primeira origem: os mesmos nomes de colunas e, quando ambas declaram um, o mesmo tipo. A tabela de destino é criada a partir das colunas da primeira origem. Uma origem pode listar as suas colunas por outra ordem, porque são correspondidas pelo nome. Guardar um passo cujas origens difiram é recusado, com indicação de cada diferença: *Source 'east' must produce the same columns as 'west': missing region; not in 'west': area.*

Ao guardar, também se preenche, a partir da respetiva tabela, o mapeamento de cada origem que tenha uma tabela de origem mas não tenha colunas de origem ou de destino, tal como **Preencher ambas as tabelas de mapeamento** faria.
