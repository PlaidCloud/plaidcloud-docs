## Descrição

O passo **Tabela: KNIME Rule Engine** aplica uma lista de regras do KNIME Rule Engine guardadas numa tabela, lida quando o passo é executado. A primeira regra que corresponde a uma linha decide o respetivo resultado. Os [fluxos de trabalho do KNIME migrados](/pt-pt/guides/workflows/migrate-knime-workflows/) utilizam este passo para os nós Rule Engine (Dictionary), Rule Engine Variable (Dictionary), Rule-based Row Filter (Dictionary) e Rule-based Row Splitter (Dictionary), incluindo conjuntos de regras PMML, quando as regras provêm de uma tabela que só é conhecida quando o fluxo de trabalho é executado.

O passo converte as regras que lê da mesma forma que o conversor. Uma regra que não consiga transportar, como uma que utilize sintaxe exclusiva de Java ou uma variável de fluxo, faz o passo falhar em vez de escrever uma coluna errada.

O formulário do passo tem uma secção **Tabelas** onde **Usar as regras para** escolhe o tipo de regra e se escolhem as tabelas de origem, de saída e de regras, uma secção **Saída**, uma secção **Pontuação por conjunto de regras** para conjuntos de regras PMML e uma secção **Colunas**.

## Configuração

- `source` e `target_frame` — a tabela a ler e a tabela a escrever. `source_columns` e `target_columns` são as colunas lidas e escritas; a coluna de destino indicada por `output_column` recebe o resultado das regras.
- `rules_source` — a tabela cujas linhas são as regras. `rules_column` contém cada regra, `outcome_column` o respetivo resultado e `rules_order_column`, quando definido, ordena as regras.
- `rule_kind` — `engine` (predefinição) escreve o resultado das regras em `output_column`, com o tipo indicado por `output_dtype`. `filter` e `splitter` escrevem as linhas que as regras mantêm: `include` (predefinição true) decide se um resultado de regra TRUE mantém ou descarta a linha, e `port` é `1` para as linhas mantidas ou `2` para as restantes. `variable` escreve a tabela de uma linha com o valor que as regras calculam, sem tabela de origem.
- `outcome_cell` — o tipo de célula do KNIME da coluna de resultado, que decide como um resultado é escrito numa regra. `knime_types` indica o tipo de célula do KNIME das colunas de entrada de data e hora com fuso, duração e período.
- `dollar_references` — os resultados na forma `$column$` indicam colunas e não texto. `disallow_long` (predefinição true) corresponde à definição do KNIME com o mesmo nome.
- Conjuntos de regras PMML — `default_rule` é uma regra que dispara sempre, acrescentada no fim. `weight_column` e `default_weight` (predefinição 1.0) definem o peso de cada regra para a seleção ponderada, em que a regra mais pesada é tentada primeiro. `confidence_column`, `confidence_cell`, `confidence_output` e `default_confidence_rule` escrevem a confiança do resultado de cada regra.
