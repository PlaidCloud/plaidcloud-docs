## Descrição

Importa uma entidade do Dynamics 365 Finance & Operations através da sua [ligação D365 F&O](/pt-pt/guides/connections/dynamics-365-fo/) para uma tabela de projeto. Escolha a ligação, o tipo de entidade, o modo de sincronização e quaisquer filtros; o passo obtém os registos correspondentes e escreve-os, sem necessidade de criar uma consulta OData.

Este é um passo genérico pré-definido — um único tipo de passo abrange seis entidades, desde dados mestre/de referência (contas principais, moedas, clientes, fornecedores, produtos lançados) a registos transacionais (cabeçalhos de diário do razão), quer numa chamada OData direta quer numa extração em massa DMF assíncrona.

## Configuração

| Campo | Obrigatório | Notas |
|---|---|---|
| Ligação D365 F&O | Sim | A ligação D365 F&O através da qual ler. |
| Tabela de destino | Sim | A tabela de projeto para onde os resultados são escritos. É totalmente sobrescrita em cada execução. |
| Tipo de entidade | Sim | A entidade a obter. Por predefinição `main_accounts`. Uma de `main_accounts`, `currencies`, `customers`, `vendors`, `released_products`, `ledger_journal_headers`. |
| Modo de sincronização | Sim | Por predefinição `odata`. `odata` chama diretamente o ponto de acesso OData padrão da entidade. `dmf` submete uma tarefa de exportação assíncrona da Data Management Framework e transfere o resultado quando termina — para obtenções demasiado grandes ou lentas com a paginação OData simples. |
| Filtros | Não | Filtros de intervalo e de igualdade traduzidos para o `$filter` OData do pedido. Cada entidade restringe os filtros aos campos que o D365 F&O consegue de facto avaliar no servidor — um campo não suportado é rejeitado, não descartado em silêncio. |

### Entidades e campos filtráveis

| Tipo de entidade | O que obtém | Campos filtráveis |
|---|---|---|
| `main_accounts` | Plano de contas | intervalo de contas, dimensão |
| `currencies` | Dados mestre de moedas | — |
| `customers` | Dados mestre de clientes | intervalo de contas |
| `vendors` | Dados mestre de fornecedores | intervalo de contas |
| `released_products` | Dados mestre de produtos lançados | — |
| `ledger_journal_headers` | Cabeçalhos de diário, lançados e não lançados | intervalo de datas, intervalo de contas, dimensão |

<Aside type="note">
Os filtros de **intervalo** de datas, contas e dimensões (limites do tipo `ge`/`le`) são a principal forma de delimitar uma obtenção de `ledger_journal_headers` — uma obtenção sem limites do histórico de transações pode ser muito grande. Defina pelo menos um limite numa entidade grande antes de executar sobre dados de produção.
</Aside>

<Aside type="caution">
O modo `dmf` (em massa) aguarda uma tarefa de exportação assíncrona e é substancialmente mais lento do que o modo `odata` para a mesma entidade e o mesmo conjunto de filtros. Reserve-o para extrações demasiado grandes para uma obtenção OData direta.
</Aside>
