## Descrição

Executa uma operação de paridade Alteryx com versão como tarefa gerida. É o veículo de uso geral para as [conversões do Alteryx](/pt-pt/guides/workflows/migrate-alteryx-workflows/) cujo trabalho exige bibliotecas Python — Shapely, scikit-learn, NLTK, Tesseract, reportlab — em vez de SQL de bases de dados.

A maioria das operações convertidas tem agora o seu próprio tipo de passo de primeira classe, mais fácil de ler e de editar. Este passo mantém-se para as operações que não o têm, e é o que esses tipos de passo lançam por baixo.

<Aside type="note" title="Normalmente não é criado manualmente">
  A conversão gera este passo onde é necessário. Só o adicionaria manualmente
  para executar uma operação de paridade que não tem um tipo de passo próprio — por exemplo,
  [Spatial Info](/pt-pt/reference/workflow-steps/spatial/spatial-info/).
</Aside>

## Configuração

### Executor

- **Operação** — a operação de paridade a executar.
- **Versão do contrato** — o contrato do executor ao abrigo do qual a operação é executada. A predefinição é `v1`.

### Entradas e saídas

- **Origem** / **Tabela de destino** — as tabelas principais de entrada e de saída.
- **Tabelas de entrada** / **Tabelas de saída** — tabelas adicionais para operações que recebem ou produzem mais do que uma.
- **Artefactos de entrada** / **Artefactos de saída** — entradas e saídas que não são tabelas, como imagens geradas.

### Recursos

Desativado por predefinição, caso em que a tarefa recebe os recursos normais. Ative a gestão avançada de recursos para definir explicitamente a **CPU** e a **memória** — vale a pena quando uma operação trata geometria invulgarmente grande ou treina modelos e a atribuição predefinida não é suficiente.
