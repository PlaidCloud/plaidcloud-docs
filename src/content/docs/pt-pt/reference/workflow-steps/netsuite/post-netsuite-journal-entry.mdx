## Descrição

Lança lançamentos de diário no NetSuite através da sua [ligação ao NetSuite](/pt-pt/guides/connections/netsuite/). O passo recebe duas tabelas de origem — uma tabela de cabeçalhos com uma linha por lançamento de diário e uma tabela de linhas com uma ou mais linhas de débito/crédito por lançamento —, agrupa as linhas por lançamento de diário e lança cada lançamento no NetSuite. O **Modo apenas de teste** constrói e verifica cada lançamento sem fazer qualquer chamada ao NetSuite, e uma tabela de resultados opcional regista o resultado de cada lançamento.

<Aside type="caution">
Execute cada lote primeiro em **Modo apenas de teste**, reveja a tabela de resultados e reconcilie alguns lançamentos diretamente no NetSuite antes de confiar neste passo para lançar lançamentos reais sem supervisão.
</Aside>

## Configuração

### Ligação

- **Ligação NetSuite**: a ligação NetSuite através da qual lançar, filtrada para ligações do tipo NetSuite.
- **Ambiente**: o ambiente da ligação.

As ligações NetSuite são geridas em **Ferramentas > Ligações**; consulte [Ligar ao NetSuite](/pt-pt/guides/connections/netsuite/).

### Dados

- **Tabela de cabeçalhos de lançamentos de diário**: uma linha por lançamento de diário.
- **Tabela de linhas de lançamentos de diário**: uma ou mais linhas de débito/crédito por lançamento de diário, associadas à respetiva linha de cabeçalho pelo ID do diário.
- **Modo apenas de teste**: assinalado por predefinição. Valida cada lançamento de diário segundo as verificações abaixo, mas não faz qualquer chamada ao NetSuite; nada é lançado. Desassinale-o para lançar a sério. Uma configuração do passo que omita totalmente este campo — por exemplo, uma criada através da API REST, do MCP ou de uma importação de pacote de fluxo de trabalho — também assume por predefinição o Modo apenas de teste, em vez de um lançamento real.
- **Continuar a lançar os restantes lançamentos se um falhar**: assinalado por predefinição. Quando um lançamento falha numa verificação ou no próprio lançamento, o PlaidCloud regista um erro para esse lançamento e avança para o resto do lote em vez de o interromper.
- **Submeter de forma assíncrona**: desativado por predefinição. Submete cada lançamento com o cabeçalho assíncrono `Prefer: respond-async` do NetSuite, em vez do caminho síncrono de criar e depois reler. O NetSuite coloca a tarefa em fila e o PlaidCloud regista o lançamento como `pending`, com uma referência de submissão, em vez de esperar que seja resolvido. Esta é uma escolha por ligação: utilize a mesma definição em todas as execuções contra uma dada ligação, não uma mistura. **Atualmente nada resolve automaticamente um lançamento pendente; o que o resolve é voltar a executar este passo**, que procura o lançamento e regista o seu resultado já final. Se ativar esta opção, planeie voltar a executar o passo (ou verificar diretamente no NetSuite) em vez de tratar uma linha `pending` como concluída.
- **Tabela de resultados do lançamento**: opcional. Se estiver definida, o PlaidCloud escreve-a (ou substitui-a) com uma linha por lançamento de diário; consulte [Colunas da tabela de resultados](#colunas-da-tabela-de-resultados).

### Mapa de cabeçalho / Filtros de cabeçalho

Associe as colunas da tabela de cabeçalhos aos campos do lançamento de diário abaixo e, opcionalmente, filtre os cabeçalhos a lançar, utilizando os [separadores normais de mapeamento de dados e de filtros](/pt-pt/reference/workflow-steps/common/advanced-data-mapper-usage/).

| Campo | Obrigatório | Notas |
|---|---|---|
| ID do diário | Sim | Associa uma linha de cabeçalho às respetivas linhas. Uma linha por ID de diário único. |
| Subsidiária | Sim | ID interno da subsidiária do NetSuite. |
| Data de lançamento | Sim | A data de transação do lançamento. |
| Moeda | Não | ID interno da moeda do NetSuite. |
| Memorando | Não | Memorando ao nível do lançamento. |
| ID externo | Não | Substitui o ID externo determinístico que o PlaidCloud gera para o lançamento; consulte [Relançamento e lançamentos duplicados](#relançamento-e-lançamentos-duplicados). |

### Mapa de linhas / Filtros de linhas

Associe as colunas da tabela de linhas e, opcionalmente, filtre as linhas a lançar.

| Campo | Obrigatório | Notas |
|---|---|---|
| ID do diário | Sim | Corresponde ao ID do diário de uma linha de cabeçalho. |
| Conta | Sim | ID interno da conta do razão geral do NetSuite. |
| Débito | Sim | O montante a débito; 0 para uma linha apenas de crédito. |
| Crédito | Sim | O montante a crédito; 0 para uma linha apenas de débito. |
| Memorando | Não | Memorando ao nível da linha. |
| Departamento | Não | ID interno do departamento do NetSuite. |
| Classe | Não | ID interno da classe do NetSuite. |
| Localização | Não | ID interno da localização do NetSuite. |
| Entidade | Não | ID interno da entidade (cliente ou fornecedor) do NetSuite. |

## Como funciona o lançamento

O PlaidCloud agrupa a tabela de linhas por ID do diário e constrói um lançamento de diário do NetSuite por cada linha de cabeçalho. Antes de lançar cada lançamento — ou, no Modo apenas de teste, antes de o registar como validado —, o PlaidCloud verifica que:

- o lançamento tem pelo menos uma linha
- os débitos e os créditos estão equilibrados ao cêntimo
- todas as linhas têm uma Conta
- a linha de cabeçalho tem uma Subsidiária
- a Data de lançamento é uma data válida

Qualquer verificação que falhe regista uma linha de erro para esse lançamento e, a menos que **Continuar a lançar os restantes lançamentos** esteja desativado, avança para o lançamento seguinte do lote.

### Relançamento e lançamentos duplicados

Cada lançamento é feito com um ID externo determinístico, construído a partir do projeto, da ligação, do ID do diário, da Data de lançamento e dos montantes das linhas. Relançar um lançamento cujas linhas não mudaram reutiliza esse mesmo ID externo, e o tratamento de IDs externos do próprio NetSuite impede-o de criar um lançamento de diário duplicado. Se alterar qualquer linha de um lançamento — um montante diferente, uma linha adicionada ou removida —, o PlaidCloud calcula um novo ID externo para ele, que o NetSuite aceita como um novo lançamento e não como uma atualização do anterior. Defina um valor na coluna ID externo da tabela de cabeçalhos para controlar o ID por si.

<Aside type="caution">
O relançamento apenas evita duplicados num lançamento que o NetSuite considere idêntico a um que já tem. Editar as linhas de um lançamento e voltar a executar o passo não atualiza o lançamento original no NetSuite: cria um segundo lançamento. Corrija um lançamento já lançado diretamente no NetSuite, em vez de voltar a executar este passo com dados alterados.
</Aside>

### Colunas da tabela de resultados

| Coluna | Descrição |
|---|---|
| journal_id | O ID do diário da tabela de cabeçalhos. |
| external_id | O ID externo utilizado nesta tentativa de lançamento. |
| internal_id | O ID interno do NetSuite para o lançamento de diário criado, ou a referência de submissão assíncrona enquanto `pending`. Em branco no Modo apenas de teste e em caso de erro. |
| status | `validated` (Modo apenas de teste), `posted`, `pending` (a submissão assíncrona aceitou o lançamento, mas o NetSuite ainda não o confirmou) ou `error`. |
| message | Detalhe do erro em `error`; uma nota em `pending` a indicar que voltar a executar o passo o resolve. Em branco em `posted`/`validated`. |
