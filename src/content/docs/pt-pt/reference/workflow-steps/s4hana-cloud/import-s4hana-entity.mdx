## Descrição

Importa uma entidade do SAP S/4HANA Cloud para uma tabela do projeto através da sua [ligação S/4HANA Cloud](/pt-pt/guides/connections/s4hana-cloud/). Escolha a ligação, o tipo de entidade e os filtros pretendidos; o passo obtém os registos correspondentes e grava-os, sem necessidade de criar uma consulta OData.

Este é um passo genérico predefinido — um tipo de passo abrange duas entidades: um cubo agregado `trial_balance` para relatórios de fim de período e `journal_entry_items`, ao nível do item de linha, para transações registadas em detalhe.

## Configuração

| Campo | Obrigatório | Notas |
|---|---|---|
| Ligação S/4HANA | Sim | A ligação S/4HANA Cloud através da qual os dados são lidos. |
| Tabela de destino | Sim | A tabela do projeto onde os resultados são gravados. É totalmente substituída em cada execução. |
| Tipo de entidade | Sim | A entidade a importar. Por predefinição, `trial_balance`. Uma de `trial_balance`, `journal_entry_items`. |
| Filtros | Não | Filtros de intervalo e de igualdade convertidos no `$filter` OData do pedido. Cada entidade limita os filtros aos campos que o S/4HANA consegue realmente avaliar no servidor — um campo não suportado é rejeitado, não ignorado silenciosamente. |

### Entidades e campos filtráveis

| Tipo de entidade | O que importa | Serviço OData | Campos filtráveis |
|---|---|---|---|
| `trial_balance` | Saldos agregados de contas do razão geral no fim do período | `API_OPLACCTGDOCITEMCUBE_SRV` | `CompanyCode`, `GLAccount`, `CostCenter`, `ProfitCenter`, `FiscalYear` (intervalo), `FiscalPeriod` (intervalo), `Ledger` |
| `journal_entry_items` | Itens de linha de lançamentos registados | `API_JOURNALENTRYITEMBASIC_SRV` | `CompanyCode`, `GLAccount`, `CostCenter`, `ProfitCenter`, `PostingDate` (intervalo), `FiscalYear` (intervalo), `FiscalPeriod` (intervalo), `Ledger` |

<Aside type="note">
`PostingDate`, `FiscalYear` e `FiscalPeriod` aceitam filtros de **intervalo** (limites do tipo `ge`/`le`) — a principal forma de delimitar uma extração de `journal_entry_items`, uma vez que uma extração sem limites do detalhe ao nível do item de linha pode ser muito grande. Defina pelo menos um limite numa entidade grande antes de executar com dados de produção.
</Aside>

<Aside type="caution">
`CostCenter` e `ProfitCenter` só são filtráveis quando o seu Communication Scenario os expõe. Uma dimensão que não faça parte desse cenário é rejeitada como filtro não suportado, em vez de ser ignorada silenciosamente.
</Aside>
