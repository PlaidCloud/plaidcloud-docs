## Descrição

Um **fluxo de trabalho avançado** é executado numa área de desenho visual — o **Estruturador visual de fluxos de trabalho** — onde os passos são nós de um grafo dirigido (um DAG). As linhas entre os nós mostram como os dados fluem, e o tempo de execução executa-os por ordem de dependência, e não de cima para baixo. Os ramos que não dependem uns dos outros são executados em paralelo automaticamente.

O fluxo de trabalho avançado é um dos **tipos de fluxo de trabalho** do PlaidCloud; os outros são Standard. As funcionalidades deste guia — a área de desenho visual, os **pontos de interrupção**, os **contentores**, **Executar a partir daqui**, **Simular** e o **Inspetor** acoplado — são exclusivas do tipo avançado. A área de desenho também suporta **colaboração em tempo real**: várias pessoas podem abrir o mesmo fluxo de trabalho avançado e editá-lo em conjunto, vendo a presença e as alterações umas das outras em direto.

## Standard versus avançado

Cada fluxo de trabalho tem um **tipo**, escolhido quando o cria:

| Tipo | Os passos estão organizados em… | …e são executados |
|------|------------------------|--------------|
| **Standard Serial** | a lista de passos | de cima para baixo, um de cada vez |
| **Standard Parallel** | a lista de passos | a partir da lista, em paralelo sempre que as dependências o permitam |
| **Avançado (tela DAG)** | um grafo visual de nós e ligações | por ordem de dependência — os ramos independentes são executados em paralelo automaticamente |

O tipo Standard e o avançado são executados em **motores diferentes**: um fluxo de trabalho Standard é executado a partir da respetiva **lista de passos**, enquanto um fluxo de trabalho avançado é executado a partir do **grafo** que desenha, seguindo as ligações explícitas de produtor/consumidor entre passos. É por isso que o Estruturador visual de fluxos de trabalho só abre para fluxos de trabalho avançados — as setas desenhadas num fluxo de trabalho Standard não alterariam a forma como é executado.

<Aside type="note">Um tipo de fluxo de trabalho designado **Macro** está previsto no plano de desenvolvimento — um fluxo de trabalho reutilizável e invocável, com entradas e saídas declaradas — e aparece no seletor de tipo como "Macro (em breve)".</Aside>

## Escolher o tipo de fluxo de trabalho

Pode definir o tipo ao criar um fluxo de trabalho, ou converter um fluxo de trabalho Standard existente:

- **Na criação** — o seletor de tipo de fluxo de trabalho oferece **Standard Serial**, **Standard Parallel**, **Avançado (tela DAG)** e **Macro (em breve)**. Os novos fluxos de trabalho têm como predefinição **Standard Serial**.
- **Converter um fluxo de trabalho existente** — selecione um fluxo de trabalho Standard na lista **Fluxos de trabalho** e escolha **Converter para avançado…**, depois confirme. Os seus passos, a respetiva configuração e as suas dependências são preservados — só muda a forma como o fluxo de trabalho é apresentado e executado.

Alterar o tipo de um fluxo de trabalho de Standard para avançado através da API REST ou de um assistente de IA mantém a ordem dos passos da mesma forma que **Converter para avançado…**. Alterar um fluxo de trabalho avançado de volta para Standard é recusado.

<Aside>Não existe nenhuma ação "Converter para Standard" na aplicação, pelo que deve encarar a mudança para avançado como um passo sem retorno. O tipo avançado aplica-se por fluxo de trabalho: uma área de trabalho pode misturar livremente fluxos de trabalho Standard e avançados, e converter um não afeta os outros.</Aside>

## A área de desenho

Cada passo é um nó, e as ligações entre nós definem a ordem pela qual os passos são executados. O Estruturador dispõe os passos automaticamente, e pode reorganizá-los livremente.

### Quem está aqui

Quando mais de uma pessoa tem o mesmo fluxo de trabalho avançado aberto, surge na barra de ferramentas da área de desenho uma fila de avatares que mostra quem mais o está a ver ou a editar — a mesma ideia de presença em direto de um documento partilhado. Cada pessoa é apresentada pelo seu **gravatar** (ou pelas suas iniciais, se não tiver um), e ao passar o cursor sobre um avatar é mostrado o respetivo nome. Uma pessoa aparece **uma só vez**, independentemente de quantos separadores do navegador tenha com o fluxo de trabalho aberto, e quando há mais observadores do que os que cabem, os restantes são agrupados num marcador **+N**.

### Mosaicos de passos

Cada mosaico resume o respetivo passo de relance, de cima para baixo:

- **Cabeçalho** — o ícone e o nome do tipo de passo, mais um ícone de estado que mostra o resultado da última execução do passo.
- **Entradas** — um ícone por cada tabela, dimensão ou ficheiro que o passo lê. Clique no ícone de uma tabela para a pré-visualizar na [gaveta de pré-visualização de dados](/pt-pt/guides/workflows/preview-step-data/), no ícone de uma dimensão para abrir a dimensão, ou no ícone de um ficheiro para o transferir. Um passo com muitas entradas ou saídas agrupa as restantes num marcador **+N**.
- **Nome do passo** — centrado no corpo do mosaico.
- **Saídas** — ícones das saídas do passo, com o mesmo comportamento ao clicar. Quando a tabela de saída existe, esta linha mostra também as respetivas **contagens de linhas e colunas** (por exemplo, `12,345 rows · 8 cols`) — as mesmas Linhas e Colunas apresentadas nas tabelas de Entradas/Saídas do passo — para que possa acompanhar os volumes de dados ao longo do fluxo de trabalho sem abrir cada tabela. Até lá (ou quando o passo produz um ficheiro ou uma dimensão), a linha mostra uma simples etiqueta **Saídas**. Passe o cursor sobre qualquer ícone de tabela para ver o nome e as contagens.
- **Rodapé** — as durações da última execução e a média do passo, com realce quando a execução mais recente foi invulgarmente lenta em comparação com o seu histórico.

### Navegar

- **Ampliar** / **Reduzir**, **Repor zoom para 100%** e **Ajustar todos os nós à vista** enquadram o fluxo de trabalho em qualquer tamanho.
- **Ferramenta de deslocação** — quando ativa, arrastar desloca a área de desenho em vez de selecionar. Arrastar com o botão do meio e Espaço+arrastar deslocam independentemente do interruptor.
- **Ajustar à grelha** arredonda as posições dos nós a uma grelha fixa quando os larga, para um alinhamento arrumado.

### Minimapa

Para fluxos de trabalho grandes que não cabem no ecrã, ative o **Minimapa** para acoplar um painel de visão geral no canto inferior direito. Mostra em miniatura os passos e as ligações de todo o fluxo de trabalho, com um retângulo a marcar a parte da área de desenho que está a ver.

- O retângulo da janela de visualização move-se em direto à medida que desloca e amplia, para que saiba sempre onde está no diagrama maior.
- **Clique ou arraste** em qualquer ponto do painel para saltar para essa parte do fluxo de trabalho.
- Enquanto um fluxo de trabalho é executado, cada passo no minimapa é **codificado por cores segundo o seu estado de execução** (em execução, concluído, erro, etc.), pelo que o painel serve também como visão geral do estado de saúde.

<Aside type="tip">O facto de o minimapa estar aberto é recordado entre sessões, pelo que pode deixá-lo ativo nos fluxos de trabalho em que o considere útil.</Aside>

### Disposição

- **Disposição** abre um menu de ações de disposição. Cada ação é um único passo em **Anular** (Cmd/Ctrl+Z) e aplica-se sem confirmação; uma notificação indica *Disposição atualizada — prima Anular para reverter*. Uma ação que não alteraria nada não faz nada. Veja [Dispor a área de desenho](#dispor-a-área-de-desenho).
- **Anular** e **Refazer** recuam e avançam pelas alterações de disposição (Cmd/Ctrl+Z e Cmd/Ctrl+Shift+Z), e **Histórico** abre o painel de alterações.

#### Dispor a área de desenho

| Ação | O que faz | Requer |
|---|---|---|
| **Arrumar tudo** | Dispõe todos os passos da esquerda para a direita. | Sempre disponível |
| **Arrumar seleção** | Dispõe apenas os itens selecionados, mantendo o canto superior esquerdo onde está. Os outros passos só descem se passarem a sobrepor-se. | 2+ itens |
| **Remover sobreposições** | Empurra os itens sobrepostos para baixo até nenhum se sobrepor. Nunca os reordena. | 2+ itens na área de desenho |
| **Alinhar à esquerda / ao centro / à direita / ao topo / ao meio / à base** | Alinha os itens selecionados pela margem ou pelo centro que escolher. | 2+ itens |
| **Distribuir horizontalmente / verticalmente** | Mantém o primeiro e o último itens onde estão e espaça uniformemente os restantes entre eles. | 3+ itens |
| **Ajustar tudo à grelha** | Coloca todos os itens na grelha da área de desenho e separa os que passarem a colidir. | Sempre disponível |

- **Arrumar tudo mantém a sua disposição.** Os passos continuam a fluir da esquerda para a direita, mas dentro de cada coluna mantêm a ordem de cima para baixo que já tinha, e a disposição permanece onde estava na área de desenho em vez de saltar para a origem.
- **Os grupos mantêm-se juntos.** Um [contentor](#contentores) é disposto como um único bloco. Um contentor recolhido move-se como um único mosaico, e os passos ocultos no seu interior acompanham-no.
- **As notas e os destaques acompanham os respetivos passos.** Tudo o que estiver sobre um passo move-se quando o passo se move.
- **Os grupos contam como um item.** Em Alinhar, Distribuir e Arrumar seleção, um contentor ou contentor recolhido é um item, e os passos no seu interior movem-se com ele.
- **Ajustar tudo à grelha** é independente do interruptor **Ajustar à grelha** em [Navegar](#navegar), que só afeta o local onde um passo fica quando o larga.
- **As ações indisponíveis aparecem esbatidas.** Os itens de menu que não se aplicam à seleção atual aparecem a cinzento.
- **Os fluxos de trabalho bloqueados** impedem todas as ações de Disposição. Desbloqueie primeiro o fluxo de trabalho.

### Anotar

As anotações são apenas visuais — documentam o diagrama e nunca afetam a execução.

- **Adicionar nota** — largue uma nota autocolante em qualquer ponto da área de desenho e depois **Editar texto…** para escrever nela (ou **Eliminar nota** para a remover).
- **Adicionar destaque** — desenhe uma caixa translúcida à volta de um grupo de passos relacionados e dê-lhe uma etiqueta com **Editar etiqueta…** (ou **Eliminar destaque** para o remover).
- **Cor** — codifique um passo por cores (ou reponha-o em **Predefinição**) para agrupar visualmente o trabalho.

### Bloquear

Um fluxo de trabalho pode ser **bloqueado** para evitar edições acidentais. Clique no interruptor de bloqueio para alternar entre *Edição do fluxo de trabalho — clique para bloquear* e *O fluxo de trabalho está bloqueado — clique para desbloquear para edição*. Enquanto estiver bloqueada, a área de desenho é só de leitura até a desbloquear.

### Recolher e redimensionar os painéis da paleta e do Inspetor

A paleta de passos, à esquerda, e o Inspetor, à direita, podem ser recolhidos para fora do caminho quando quiser a janela inteira para o diagrama.

- **Recolher um painel** — clique na seta no título da paleta ou no cabeçalho do Inspetor. O painel reduz-se a uma barra estreita com o título a descer pelo lado. A barra do Inspetor recolhido mostra o **nome do passo que selecionou**, para que uma área de desenho em largura total não perca o rasto do que estava a inspecionar; passe o cursor sobre ela para ver o nome completo se estiver cortado.
- **Voltar a abri-lo** — clique em qualquer ponto da barra, não apenas na seta.
- **Teclado** — prima `[` para recolher ou expandir a paleta e `]` para recolher ou expandir o Inspetor. Ambas são ignoradas enquanto escreve num campo, pelo que nunca interrompem a caixa de filtro nem uma mudança de nome em linha.
- **Duplo clique num divisor** — fazer duplo clique no divisor junto a um painel recolhe-o ou expande-o, tal como a seta.
- **Redimensionar** — arraste qualquer dos divisores. Ambos os painéis têm uma largura mínima; abaixo dela, os cartões de Entradas e Saídas do Inspetor deslocam-se lateralmente em vez de cortar os nomes e as contagens de linhas.

<Aside type="note">As larguras dos painéis e os estados recolhidos são recordados **por navegador e partilhados entre fluxos de trabalho** — não são guardados por fluxo de trabalho. Cada painel é recordado separadamente, pelo que redimensionar o Inspetor numa área de desenho não perturba uma paleta que tenha recolhido noutra. A alteração mais recente a um determinado painel é a definição que a próxima área de desenho que abrir irá usar, e as janelas de área de desenho que já tem abertas mantêm a disposição atual até as fechar e voltar a abrir.</Aside>

### Exportar o diagrama

O botão de exportação da barra de ferramentas guarda uma imagem da área de desenho para documentação, revisão ou partilha. Ao clicar nele, exporta um PDF; o respetivo menu pendente oferece **Exportar como PDF** e **Exportar como PNG**.

<Aside type="note">Os diagramas PNG e PDF exportados são sempre desenhados no esquema de cores claro, qualquer que seja o tema em que trabalhe. Um diagrama escuro é adequado no ecrã e inadequado em papel, pelo que a exportação fica fixada nas cores claras e lê-se bem quando impressa ou colada num documento.</Aside>

### Tema escuro

A área de desenho segue o tema do PlaidCloud que escolheu. No tema **Escuro**, o fundo da área de desenho, os mosaicos dos passos, os conectores, as notas, os destaques, os contentores, o minimapa e também a paleta de passos, o Inspetor e a gaveta de pré-visualização de dados ao lado são todos desenhados para um fundo escuro, com cores de estado de execução e texto de etiquetas escolhidos para se manterem legíveis sobre ele. Mudar de tema recarrega a interface, e a área de desenho assume as novas cores quando é reaberta.

## Adicionar, ligar e editar passos

Clique num tipo de passo na **[paleta](#a-paleta-de-passos)** para o largar na área de desenho, ou arraste-o para onde pretender. Para ligar passos, arraste de um passo para outro para desenhar um **conector** — é isto que indica ao tempo de execução que a saída de um passo alimenta o seguinte.

<Aside type="caution">O fluxo de trabalho tem de continuar a ser um DAG: um conector que criasse um ciclo é rejeitado ("that connector would create a cycle"). Clique com o botão direito num conector para **Remover conector** ou saltar para **Editar passo de origem…** / **Editar passo de destino…** em qualquer das extremidades.</Aside>

Um passo que lê uma tabela deve ser executado depois do passo que a escreve. **Sincronizar dependências** na barra de ferramentas encontra passos que podem ser executados demasiado cedo e sugere os conectores a adicionar. Veja [Sincronizar dependências](/pt-pt/guides/workflows/sync-dependencies/).

Clique com o botão direito em qualquer passo para:

- **Editar configuração do passo…** — o formulário de definições do passo.
- **Editar detalhes do passo…** — nome, memorando, tratamento de erros, nova tentativa e condições.
- **Converter tipo de passo…** — altere o passo para um tipo de operação diferente.
- **Duplicar passo…** — copie este passo. O formulário do passo abre no respetivo separador **Geral**, preenchido a partir deste passo, para que possa mudar o nome da cópia e escolher para onde vai; a cópia mantém a configuração deste passo.
- **Ativar passo** / **Desativar passo** — um passo desativado é ignorado no momento da execução.
- **Ver entradas do passo** / **Ver saídas do passo** — abre os dados do passo no Inspetor.
- **Pré-visualizar dados de saída** — abre a saída do passo na [gaveta de pré-visualização de dados](/pt-pt/guides/workflows/preview-step-data/) acoplada. Ao passar o cursor sobre um passo, surge também um glifo de navegação que faz o mesmo.
- **Cor** — aplique ou limpe a cor de um passo.
- **Eliminar passo…** — remove-o da estrutura do fluxo de trabalho. Os passos a jusante que dependiam da sua saída terão de ser reconfigurados.

## Simultaneidade de subfluxos de trabalho

Quando um passo invoca outro fluxo de trabalho — um passo [Executar fluxo de trabalho](/pt-pt/reference/workflow-steps/workflow-control/run-workflow/), Executar fluxo de trabalho condicional ou [Executar fluxo de trabalho em ciclo](/pt-pt/reference/workflow-steps/workflow-control/workflow-loop/) que aponte para um fluxo de trabalho que **não** seja uma Macro — só uma invocação desse subfluxo de trabalho pode ser executada de cada vez. Um subfluxo de trabalho que não seja Macro partilha um único estado de execução, pelo que duas invocações em simultâneo colidiriam.

Isto é relevante na área de desenho avançada porque os passos sem ordem relativa entre si são executados em paralelo. Se dois desses passos invocarem o mesmo subfluxo de trabalho que não seja Macro, entram em disputa.

O estruturador verifica isto quando guarda a área de desenho e mostra uma notificação de aviso intitulada **Aviso do fluxo de trabalho** que indica os passos em causa e o subfluxo de trabalho partilhado — por exemplo:

> Steps 'Build', 'Refresh' all invoke non-macro sub-workflow 'Load Dims' but are not ordered relative to each other; they may run concurrently and collide (a non-macro sub-workflow can't run twice at once). Order the steps so they don't overlap, or make 'Load Dims' a macro (macros run with per-invocation isolation).

Para o resolver:

- **Ordene os passos** de modo a que não se sobreponham — desenhe um conector para que um seja executado depois do outro.
- **Transforme o subfluxo de trabalho numa Macro** — cada invocação de uma Macro é executada no seu próprio esquema temporário isolado, pelo que a mesma Macro pode ser invocada em simultâneo em segurança. Veja [Criar uma macro](/pt-pt/guides/workflows/create-a-macro/) e a referência de [Macro Run](/pt-pt/reference/workflow-steps/workflow-control/run-macro/).

<Aside type="note">O aviso é informativo, não um bloqueio — a gravação é concluída com sucesso. É recalculado quando altera os conectores (ou ativa ou desativa um contentor), pelo que resolver o conflito e guardar novamente o elimina.</Aside>

## A paleta de passos

A **Paleta de passos**, à esquerda da área de desenho, contém todos os tipos de passo que pode adicionar, organizados em dez pastas: **Importar**; **Exportação e arquivo**; **Tabelas**; **Dimensões**; **Alocações**; **IA, ML e texto**; **Espacial**; **Documentos e relatórios**; **Fluxo de trabalho e variáveis**; e **Sistemas externos**. As pastas começam fechadas. Clique numa para a abrir; algumas contêm subpastas, como **Sage** em Importar e **Notificações** em Fluxo de trabalho e variáveis. A paleta recorda quais as pastas que deixou abertas.

### Sombreado das pastas e guias de indentação

A paleta mostra onde se encontra na hierarquia sem que tenha de a memorizar:

- **As pastas são sombreadas consoante a profundidade**, para que uma pasta de nível superior, uma subpasta e os passos no seu interior se distingam de relance. O sombreado é apenas uma indicação secundária — o ícone da pasta e a legenda a negrito já assinalam uma pasta.
- Cada pasta aberta desenha uma **guia de indentação vertical** à esquerda de tudo o que contém, e **clicar numa guia fecha a pasta a que pertence**. É a forma rápida de sair de uma pasta aberta longa cujo título já saiu do ecrã por deslocação. Ao passar o cursor sobre uma guia, é mostrado *Recolher esta pasta*.
- As pastas abrem-se e fecham-se com a mesma **caixa +/−** usada nos ecrãs de dimensões, para que o gesto seja igual em todo o produto.
- O título da pasta que está a ler **permanece fixo no topo da lista** enquanto se desloca, para que os passos sob o cursor nunca fiquem anónimos. Dentro de uma subpasta, ficam fixos o seu título e o da pasta superior.
- **Abrir ou fechar uma pasta mantém a posição de deslocação** em vez de o devolver ao topo da lista.
- **Expandir todas as pastas** e **Recolher todas as pastas** são os dois botões pequenos no título da paleta, junto à seta que recolhe a própria paleta.

Existem duas formas de adicionar um passo:

1. **Clicar nele.** A linha pisca para confirmar a adição, e o passo aparece perto do canto superior esquerdo da área de desenho visível, já selecionado, para que o Inspetor mostre os seus detalhes. Arraste-o para onde pretender. Clicou no errado? Prima **Delete** e confirme — continua selecionado, pelo que não há nada a procurar.
2. **Arrastá-lo** da paleta para a área de desenho, e fica onde o largar.

Mais duas coisas que vale a pena saber:

- **Filtrar…** pesquisa todo o catálogo pelo nome do passo, estejam as pastas abertas ou fechadas. Cada correspondência é listada sob o título da pasta de onde provém, para que veja a que pasta um passo pertence sem abrir nada. Quando nada corresponde, a paleta indica **Nenhum passo corresponde**.
- A **estrela** junto a um passo fixa-o em **Favoritos**, uma secção que fica acima das pastas e nunca é arquivada dentro de uma. Clique com o botão direito num passo para os mesmos **Adicionar aos favoritos** / **Remover dos favoritos**, mais **Adicionar à tela**.

### Navegação por teclado e leitores de ecrã

A paleta pode ser utilizada inteiramente pelo teclado e é **navegável com um leitor de ecrã**: é exposta como uma árvore, e cada linha indica se é uma pasta, se essa pasta está aberta e a que profundidade se encontra. Com um filtro escrito, os resultados são expostos como a lista simples de correspondências que são.

O Tab passa do campo **Filtrar…** para a lista — uma paragem para a lista inteira, não uma por passo — e um novo Tab sai para a área de desenho. Dentro da lista:

| Tecla | O que faz |
|-----|--------------|
| Baixo / Cima | Passa para a linha seguinte ou anterior |
| Direita | Abre a pasta em que está — ou, num passo, desce |
| Esquerda | Fecha a pasta em que está — ou, num passo, sobe para a pasta que o contém |
| Enter ou Espaço | Adiciona o passo em que está à área de desenho, ou abre e fecha a pasta |
| Esc | Regressa ao campo **Filtrar…** |

<Aside type="note">Os nomes dos passos podem ser mais longos do que a largura da paleta. Arraste o divisor entre a paleta e a área de desenho para a alargar, ou recolha totalmente a paleta — veja [Recolher e redimensionar os painéis da paleta e do Inspetor](#recolher-e-redimensionar-os-painéis-da-paleta-e-do-inspetor) para saber como a largura é recordada. Ao passar o cursor sobre um passo, é também mostrado o que faz, ou o seu nome completo se não tiver descrição.</Aside>

## Controlos de execução

A área de desenho executa o fluxo de trabalho completo ou qualquer parte dele. Como a execução segue o grafo, "a partir daqui" e "selecionados" respeitam as dependências e não a posição na lista.

| Ação | O que executa |
|--------|--------------|
| **Executar fluxo de trabalho** | O fluxo de trabalho completo, a partir dos passos iniciais. |
| **Executar este passo** | Apenas o passo selecionado. |
| **Executar a partir daqui** | O passo selecionado e todos os passos a jusante que normalmente seriam executados depois dele. |
| **Executar selecionados** | Apenas os passos selecionados — disparam em paralelo e o tempo de execução sequencia-os pelas suas dependências. |
| **Executar secção** | Os passos selecionados mais todos os passos que o grafo coloca entre o mais antigo e o mais recente da sua seleção, topologicamente. |

Enquanto um fluxo de trabalho está em execução, pode **Pausar** (os passos em curso terminam; os novos passos aguardam até **Retomar**), **Retomar** um fluxo de trabalho pausado ou parado a partir do ponto em que ficou, ou **Parar** (os passos em curso terminam; os passos em fila são cancelados). Retomar volta a executar o nó que falhou e tudo o que ainda aguarda por ele, deixando os nós concluídos intactos — veja [Pausar, parar e retomar](/pt-pt/guides/workflows/run-a-workflow/#pausar-parar-e-retomar).

## Simular

**Simular** percorre o grafo do fluxo de trabalho sem executar as transformações reais. Os passos são pintados como seriam durante uma execução real, para que possa visualizar a ordem e os ramos antes de se comprometer com o cálculo. Nada é executado e nenhum dado é alterado.

<Aside type="tip">Simular é a forma mais rápida de verificar um fluxo de trabalho grande ou com muitos ramos — confirme que a ordem e as dependências são as esperadas e, depois, faça uma execução real.</Aside>

## Pontos de interrupção

Um **ponto de interrupção** pausa uma execução quando esta chega a um passo, para que possa inspecionar a saída a montante antes de o resto do fluxo de trabalho continuar.

1. Clique com o botão direito num passo e escolha **Definir ponto de interrupção** (ou **Limpar ponto de interrupção** para o remover).
2. Execute o fluxo de trabalho. Quando a execução chega a um passo com um ponto de interrupção, a execução faz uma pausa nesse ponto; tudo o que está a jusante aguarda.
3. Inspecione as entradas e saídas do passo no Inspetor e depois **Retomar** para continuar.

Os pontos de interrupção são guardados com o fluxo de trabalho, pelo que um ponto de interrupção que definir persiste entre sessões até o limpar.

## Contentores

Um **contentor** agrupa passos relacionados numa caixa com etiqueta que pode recolher ou desativar como uma unidade — útil para organizar fluxos de trabalho grandes ou para ligar e desligar um subprocesso inteiro.

- **Agrupar num contentor** — selecione os passos, agrupe-os e dê um nome ao contentor.
- **Recolher contentor** / **Expandir contentor** — dobre o contentor num único mosaico para desobstruir a área de desenho, ou volte a abri-lo.
- **Desativar contentor** / **Ativar contentor** — desativar um contentor ignora todos os seus passos membros numa só ação. Ativá-lo repõe-nos.
- **Mudar o nome do contentor…** — altere a sua etiqueta.
- **Desagrupar contentor** — remove o contentor; os seus passos membros permanecem na área de desenho.
- **Adicionar ou remover passos** — mantenha premido **Cmd** num Mac ou **Ctrl** no Windows e arraste um passo para um contentor. O contentor é realçado como destino de largada, e o passo junta-se-lhe quando o solta. Cmd/Ctrl+arrastar um passo para fora do seu contentor, para uma zona vazia da área de desenho, remove-o. Largar sobre um contentor recolhido adiciona o passo a esse contentor.

Um passo pertence no máximo a um contentor, pelo que largá-lo sobre um contentor diferente move-o. Arrastar vários passos selecionados move-os todos. Se selecionar um contentor inteiro e fizer Cmd/Ctrl+arrastar de um dos seus passos, só esse passo se move. Um contentor simples que fique sem passos é removido. Um arrastamento simples só move o passo na área de desenho, Cmd/Ctrl+clique continua a alternar a seleção e largar fora da área de desenho não altera nada. Pode anular e refazer as alterações de pertença como qualquer outra alteração de disposição; os fluxos de trabalho bloqueados não podem ser alterados.

<Aside>Desativar um contentor é a forma mais rápida de ignorar um ramo inteiro de trabalho — por exemplo, um bloco de passos de exportação que pretende deixar de fora de uma execução de teste — sem desativar cada passo individualmente.</Aside>

### Contentores de execução

Um contentor simples é um agrupamento visual — arruma a área de desenho mas não altera a forma como os passos são executados. Transforme um contentor num **contentor de execução** e ele passa também a ser uma unidade de *execução*: o grupo inteiro é executado como um subfluxo de trabalho selado, comportando-se como um único nó no grafo principal.

**Ativá-lo** — clique com o botão direito no contentor e ative **Execução**. O contentor é redesenhado com uma margem distinta, um distintivo **Execução** no cabeçalho e uma porta de entrada e uma porta de saída, para que possa distinguir de relance um contentor de execução de um grupo normal. Passe o cursor sobre as portas para ver as descrições **Porta de entrada** e **Porta de saída**.

**Como é executado — um sub-DAG selado.** Quando um contentor é marcado para execução, a sua fronteira fica selada nos dois sentidos:

- **Nada no interior começa até as entradas do contentor terem chegado.** Cada passo membro aguarda o que alimenta o grupo, mesmo um membro que não tenha qualquer passo a montante próprio.
- **Nada a jusante do contentor começa até todos os membros terem terminado.** A saída do grupo só é libertada quando o último membro termina, pelo que o fluxo de trabalho principal trata o contentor inteiro como um único nó.

Os ramos independentes *dentro* do contentor continuam a ser executados em paralelo, exatamente como na área de desenho aberta — o selo rege apenas a fronteira do grupo, não a ordem do trabalho no seu interior.

**Ligue um passo a montante à porta de entrada.** Arraste um conector de um passo a montante para o contentor e largue-o na porta de **entrada**. Essa única ligação alimenta o grupo inteiro — cada membro que precisa da entrada recebe-a quando as entradas do contentor chegam.

**Ligue a porta de saída a um passo a jusante.** Arraste um conector da **Porta de saída** do contentor, na margem direita, para o passo a jusante que consome a saída do grupo. O passo a jusante começa quando todos os membros tiverem terminado, e o conector é desenhado a partir da margem do contentor.

Também pode desenhar um conector de um **passo membro** para o passo a jusante, como liga quaisquer dois passos. O tempo de execução encaminha essa ligação para fora pela porta de saída do contentor por si, pelo que ambas as formas dão o mesmo resultado.

**Comportamento em caso de falha.** Um membro que falha segue o mesmo tratamento de erros que qualquer outro passo:

- Com a predefinição **parar em caso de erro**, a falha de um membro interrompe a execução, e tudo o que está para lá do contentor fica retido.
- Com **[continuar em caso de erro](/pt-pt/guides/workflows/continue-on-error/)**, o membro que falhou é tratado como concluído; a saída do contentor continua a ser libertada quando os ramos restantes terminam, e o trabalho a jusante prossegue.

**Desativar um contentor de execução.** Desativar um contentor de execução ignora-o como uma unidade — os seus membros não são executados e, como um contentor ignorado não produz **nenhuma saída**, tudo o que está a jusante do contentor é também ignorado em vez de ser executado sem entrada. Isto é diferente de desativar um contentor simples (sem execução), que ignora apenas os passos membros; os passos a jusante que não dependem desses membros continuam a ser executados. Reative o contentor para repor o grupo inteiro.

**Adicionar e remover passos.** Altera os passos de um contentor de execução da mesma forma, com Cmd/Ctrl+arrastar. O PlaidCloud recusa a movimentação, mostra uma mensagem e devolve o passo ao local onde estava, quando:

- o passo está ligado à porta de entrada ou de saída do próprio contentor,
- a movimentação criaria um ciclo através da fronteira do contentor, ou
- removeria o último passo do contentor. Utilize **Desagrupar contentor**.

### Executar e monitorizar contentores de execução

Um contentor de execução é também algo que executa e acompanha como unidade. Pode iniciar apenas o respetivo trabalho, seguir um estado consolidado enquanto é executado e saltar diretamente para uma falha no seu interior — tanto na área de desenho como no Monitor de execução.

**Executar grupo / Executar grupo + a jusante.** Clique com o botão direito num contentor de execução para o executar sem tocar no resto do fluxo de trabalho:

- **Executar grupo** executa os passos membros do contentor.
- **Executar grupo + a jusante** executa os membros *e* tudo o que está a jusante do contentor.

Nenhuma das ações volta a executar os passos a montante que alimentam o contentor — executam o grupo tal como está, usando a entrada já existente. Ambas usam o mesmo mecanismo de **Executar selecionados** que os passos individuais, pelo que os membros disparam em paralelo e o tempo de execução sequencia-os pelas suas dependências.

**Estado em direto do grupo.** Enquanto um fluxo de trabalho é executado, o contentor mostra um estado consolidado dos seus membros: um ponto de estado, uma contagem **N de M concluídos** e uma margem colorida. O estado reflete os membros no seu conjunto — **erro** se algum membro falhou, **em execução** enquanto algum membro estiver em execução, **concluído** quando todos os membros terminaram, **ignorado** quando o grupo foi ignorado, e assim por diante. Um contentor recolhido mostra o mesmo agregado no seu único mosaico, pelo que dobrar um grupo não oculta o andamento do seu trabalho.

**Saltar para a falha.** Quando um grupo tem um membro com falha, clique no respetivo estado para selecionar e centrar esse membro na área de desenho — sem ter de procurar no grupo o que interrompeu a execução.

**Repetir a partir da falha.** Clique com o botão direito num contentor de execução com falha e escolha **Repetir a partir da falha** para voltar a executar apenas o membro (ou membros) com falha e o que estiver a jusante deles *dentro* do grupo; os membros que já foram bem-sucedidos são ignorados. Esta é a diferença para **Executar grupo**, que volta a executar todos os membros independentemente do resultado. Repetir a partir da falha é o caminho mais rápido de volta ao verde depois de corrigir o que fez tropeçar um membro.

**Tempo da última execução.** O cabeçalho do contentor mostra a soma das durações da última execução dos seus membros, para que possa ler o custo do grupo inteiro de relance em vez de somar os membros.

**Descrições das portas.** Passe o cursor sobre a **Porta de entrada** ou a **Porta de saída** de um contentor de execução para ver, listadas na descrição, as tabelas que atravessam essa fronteira — as entradas que o grupo recebe ou as saídas que entrega a jusante.

<Aside type="note">A tabela de passos do Monitor de execução mostra agora o contentor de cada passo e o estado consolidado desse contentor, em conformidade com o que a área de desenho mostra. Um membro com falha lê-se da mesma forma nos dois locais, pelo que pode trabalhar a partir da vista que tiver aberta.</Aside>

### Iterar um contentor

Um contentor de execução pode executar o seu sub-DAG selado **uma vez por iteração** de um conjunto de valores — pelo que um grupo que carrega e transforma os dados de uma região pode processar todas as regiões por sua vez, sem que copie os passos uma vez por região. Clique com o botão direito num contentor de execução e escolha **Definições do contentor…**, depois o separador **Iterar sobre**, e marque **Iterar este contentor de execução** para ativar a iteração (as definições só aparecem em contentores de execução, porque a iteração comanda um grupo que é executado como unidade). A iteração é opcional — deixe a caixa desmarcada e o contentor é executado uma vez, pelo que um contentor pode ter [condições](#condições-do-contentor) por si só, sem quaisquer definições de iteração.

**Configurar o ciclo.** O separador **Iterar sobre** da caixa de diálogo **Definições do contentor…** usa o mesmo modelo de iteração que o [passo Executar fluxo de trabalho em ciclo](/pt-pt/reference/workflow-steps/workflow-control/workflow-loop/), em subpáginas com separadores. Escolha como o conjunto de iteração é construído:

- **Especificar valores de variáveis sobre os quais iterar** — defina os valores por si no separador **Iteração manual de valores**. Adicione uma ou mais **variáveis de ciclo** e, para cada uma, indique uma lista explícita de valores ou um **intervalo**:

  | Tipo de intervalo | Itera uma vez por… |
  |------------|--------------------|
  | **Inteiro** | número a partir de um **início**, **fim** e **passo** |
  | **Alfa maiúsculas** / **Alfa minúsculas** | letra de um intervalo (`A`–`Z` ou `a`–`z`) |

  Um intervalo pode ter uma lista de **valores excluídos** a ignorar. Quando define mais do que uma variável, o contentor é executado uma vez por **combinação** dos respetivos valores (o produto cartesiano).

- **Usar combinação de valores únicos na tabela** — escolha uma **tabela de origem** no separador Iterar sobre e, depois, no separador **Mapeamento de dados para variáveis**, mapeie uma ou mais das suas colunas para nomes de variáveis de ciclo. O contentor é executado uma vez por **combinação única** dos valores dessas colunas. Utilize o separador **Filtros de dados da tabela** para restringir as linhas consideradas.

Os passos no interior do contentor referenciam cada variável de ciclo como qualquer variável do fluxo de trabalho — `{region}` — pelo que o SQL, as expressões, os nomes de tabelas e os caminhos de ficheiros de um membro podem variar consoante a iteração. Opcionalmente, ative **Combinar a saída de todas as iterações** para acumular os resultados de cada passagem em vez de manter apenas o último — veja a nota abaixo sobre o ponto em que isto se encontra.

**Como é executado.** As iterações são executadas **em série**, uma após a outra — os membros partilham as variáveis de ciclo, pelo que duas passagens em simultâneo leriam os valores uma da outra. Cada iteração associa as variáveis de ciclo ao valor seguinte (ou combinação) e depois executa o grupo inteiro como [uma execução normal de contentor de execução](#executar-e-monitorizar-contentores-de-execução); a iteração seguinte só começa quando a anterior termina. Um contentor está limitado a **1.000 iterações**.

**O que lê o trabalho a jusante.** Como cada passagem substitui as tabelas de saída do grupo, um passo a jusante do contentor lê a saída da **última iteração**. Se precisar das linhas de todas as iterações, ative **Combinar a saída de todas as iterações** para que as passagens se acumulem em vez de substituírem.

Por exemplo, para construir uma extração filtrada por região, adicione uma variável de ciclo `region` com uma lista de valores `East, West` e dê a um passo membro um filtro que leia a variável:

```sql
SELECT *
  FROM sales
 WHERE region = '{region}'
```

O contentor é executado duas vezes — `region = 'East'`, depois `region = 'West'` — executando o grupo selado inteiro de cada vez.

<Aside type="note">**Combinar a saída de todas as iterações** é uma capacidade posterior. Até estar disponível, conte com que os passos a jusante vejam apenas as tabelas da iteração final e escreva cada passagem numa tabela com o nome da variável de ciclo (por exemplo, uma tabela de saída com chave em `{region}`) quando precisar de manter os resultados de todas as iterações.</Aside>

### Condições do contentor

Um contentor de execução pode também ter **condições** que determinam se o contentor inteiro é executado — as mesmas verificações de variáveis, tabelas, documentos e hora que as condições de um passo usam, pelo que as duas funcionam da mesma forma. Clique com o botão direito no contentor, escolha **Definições do contentor…** e abra o separador **Condições** — o primeiro separador, onde ficam as condições de um passo: é a [mesma interface de Condições que um passo usa](/pt-pt/guides/workflows/step-conditions/), sem alterações. As condições não precisam de iteração, pelo que um contentor pode tê-las por si só, com **Iterar este contentor de execução** desativado.

**Avaliadas uma vez, na entrada.** As condições de um contentor são verificadas uma única vez, quando o contentor é alcançado no grafo — não uma vez por membro e, num contentor com iteração, não uma vez por iteração. Se as condições forem satisfeitas, todos os passos membros são executados normalmente. Se falharem, nenhum membro é executado; o contentor não produz saída, pelo que tudo o que está a jusante é também ignorado, tal como num contentor desativado.

**Apenas ignorar — não existe "ir para".** A condição falhada de um passo pode enviar a execução para um passo com nome em vez de apenas seguir em frente; a de um contentor não pode. O seletor "ir para o passo" que um passo oferece fica oculto num contentor, pelo que uma condição falhada num contentor significa sempre *ignorar o contentor e tudo o que está a jusante dele* — não há um ponto de aterragem alternativo para escolher.

**Como se combina:**

- **Desativar prevalece.** Um contentor que tenha desativado é ignorado independentemente das suas condições — desativar é um salto mais forte e incondicional que nem sequer as avalia.
- **A iteração é condicionada, não repetida em ciclo.** Um contentor que itera e tem condições verifica as condições uma vez, antes da primeira iteração, para decidir se o ciclo é sequer executado. Uma condição falhada ignora todas as iterações, não apenas a primeira; uma condição satisfeita não é reverificada de passagem em passagem.
- **Retomar mantém a decisão.** Retomar uma execução que ignorou um contentor desta forma não reavalia a condição — o contentor permanece ignorado, como qualquer outra decisão concluída antes da pausa.
- **Uma condição com erro faz falhar a execução.** Um erro ao avaliar uma condição — uma verificação mal configurada, por exemplo — faz falhar a execução com esse erro. Não é tratado como uma condição falhada, pelo que não ignora silenciosamente o contentor.

<Aside type="note">As condições de contentor usam os mesmos tipos de condição que as condições de passos — veja [Execução condicional de passos](/pt-pt/guides/workflows/step-conditions/) para as verificações de variáveis, tabelas, documentos e hora e como funcionam as comparações.</Aside>

## O Inspetor

O **Inspetor de passos** acoplado mostra tudo sobre o passo que seleciona:

- **Entradas** e **Saídas** — os dados que entram e saem do passo. O ícone de olho num cartão de entrada ou saída abre a [gaveta de pré-visualização de dados](/pt-pt/guides/workflows/preview-step-data/) para uma vista rápida das primeiras linhas dessa tabela.
- **Estatísticas de execução** — o resultado da **Última execução** do passo, a **Duração da última**, a contagem de execuções e resumos de tempos, incluindo as durações **Média** e **p95**, mais o **Erro da última execução** ou o **Aviso da última execução** quando existe.
- **Editar configuração do passo…** e **Editar detalhes do passo…** — salte diretamente para os formulários do passo e mude o nome do passo em linha clicando no respetivo nome.
- **Reverter configuração do passo (Flashback)** — restaure a configuração do passo para uma versão guardada anterior.
- **Ver histórico de execuções** — abra o histórico completo de execuções deste passo.

Selecione um único passo para o inspecionar; selecione vários e o Inspetor remete-o para as ações em massa na barra de ferramentas da área de desenho.

O Inspetor é **redimensionável** — arraste o divisor entre ele e a área de desenho — e **recolhível**: a seta junto ao nome do passo (ou a tecla `]`) dobra-o numa barra estreita que continua a mostrar o nome do passo selecionado ao longo do lado, para que possa devolver a largura à área de desenho sem perder o rasto do que tinha selecionado. Clique em qualquer ponto da barra para o abrir novamente. Veja [Recolher e redimensionar os painéis da paleta e do Inspetor](#recolher-e-redimensionar-os-painéis-da-paleta-e-do-inspetor).

## Histórico de execuções

Escolha **Ver o histórico de execuções deste fluxo de trabalho** para ver as execuções anteriores com estatísticas de resumo. A área de desenho também pinta um mapa de calor a partir dos registos de execução recentes, para que os passos que falham ou são lentos com frequência se destaquem de relance.

## Ver registos

Clique em **Ver registos** na barra de ferramentas para saltar diretamente para a vista de **Registo** do projeto, já filtrada para este fluxo de trabalho — o registo de execução completo a que de outra forma chegaria a partir da área do Projeto. Veja [Ver o registo do fluxo de trabalho](/pt-pt/guides/workflows/viewing-workflow-log/).

## Quando a área de desenho não consegue abrir um fluxo de trabalho

A área de desenho abre um fluxo de trabalho mesmo quando parte da sua disposição guardada não pode ser lida.

- **Um contentor sem posição ou tamanho guardados** — por exemplo, um criado através da API ou do MCP — abre, desenhado à volta dos seus passos membros.
- **Outro item de disposição que não pode ser lido** — o fluxo de trabalho abre na mesma, e uma notificação **Disposição parcialmente ilegível** lista o que foi reposto ou ocultado: até três itens, depois *…e mais N*. Uma anotação oculta é removida da próxima vez que guardar a disposição.
- **Um fluxo de trabalho que não pode ser carregado** — uma mensagem **Não foi possível carregar o fluxo de trabalho** indica o motivo, em vez de uma área de desenho em branco. Feche a área de desenho e abra novamente o fluxo de trabalho.
- **Um fluxo de trabalho Standard** — a área de desenho mostra **Tela visual indisponível — Este fluxo de trabalho não é avançado. Utilize 'Converter para avançado...' para ativar a tela visual.** Escolha **Converter para avançado...** no fluxo de trabalho para a ativar. Veja [Standard versus avançado](#standard-versus-avançado).
