Utilize esta lista de verificação antes de importar fluxos de trabalho do Alteryx para o PlaidCloud. Um pacote completo ajuda o PlaidCloud a criar fluxos de trabalho avançados, fluxos de trabalho de macros, dependências baseadas em Documentos e entradas de execução controladas com um mínimo de acompanhamento posterior.

<Aside type="note">
  Em portefólios grandes, execute esta lista de verificação uma vez para o portefólio e novamente para cada família de fluxos de trabalho de prioridade elevada.
</Aside>

## Reunir os ficheiros de fluxos de trabalho

Reúna todos os ficheiros de fluxos de trabalho que pertencem à migração:

1. Fluxos de trabalho standard: `.yxmd`.
2. Aplicações analíticas: `.yxwz`.
3. Macros: `.yxmc`.
4. Macros aninhadas ou partilhadas referenciadas por outros fluxos de trabalho.
5. Versões de fluxos de trabalho que ainda são utilizadas em produção.

Mantenha juntos os fluxos de trabalho e as macros relacionados quando se invocam mutuamente. O PlaidCloud utiliza essas relações para gerar fluxos de trabalho de macros e ligar as portas de entrada e saída das macros.

## Reunir as dependências de dados

Empacote os ficheiros que os fluxos de trabalho leem, escrevem ou inspecionam:

- Ficheiros CSV, TSV, de largura fixa, JSON, XML, Excel, Access, YXDB e de extração de bases de dados.
- Pastas utilizadas pelas ferramentas Directory ou Dynamic Input.
- Ficheiros de saída esperados para validação.
- Recursos de relatórios, como imagens, PDF, modelos e camadas de mapas.
- Tabelas de consulta e tabelas de regras utilizadas em junções, fórmulas, substituições e correspondências.

Se um fluxo de trabalho referenciar um caminho local do ambiente de trabalho, inclua esse ficheiro ou pasta no pacote de importação e escolha o caminho de Documentos onde o PlaidCloud o deve guardar.

## Reunir os ficheiros auxiliares espaciais

Os formatos de ficheiros espaciais exigem frequentemente que vários ficheiros permaneçam juntos. Inclua todos os ficheiros auxiliares na mesma pasta:

- Grupos de shapefiles, como `.shp`, `.shx`, `.dbf` e `.prj`.
- Grupos do MapInfo, como `.tab`, `.map`, `.id` e `.dat`.
- KML, GeoJSON e outros ficheiros espaciais autónomos.
- Ficheiros de projeção ou de sistemas de referência de coordenadas utilizados pelo fluxo de trabalho.

A falta de ficheiros auxiliares é uma causa frequente de diferenças na validação espacial.

## Registar as entradas de execução

Para aplicações analíticas, registe os valores que os utilizadores fornecem normalmente:

1. Entradas de texto, numéricas, de data, de ficheiro e de pasta.
2. Seleções de listas pendentes, botões de opção, caixas de verificação, listas e árvores.
3. Predefinições utilizadas em execuções agendadas ou repetíveis.
4. Valores que acionam condições, avisos ou erros.

O PlaidCloud converte estas entradas em variáveis de fluxo de trabalho controladas.

## Escolher o local de destino

Antes da importação, decida:

1. O projeto de destino no PlaidCloud.
2. A conta de documentos de destino.
3. A pasta de Documentos de destino para os ficheiros importados.
4. A convenção de nomes para os fluxos de trabalho e macros convertidos.
5. Se a primeira importação é uma importação de preparação ou de produção.

Em migrações de portefólios, utilize uma pasta de migração dedicada em Documentos, para que as dependências sejam fáceis de auditar.

## Escolher as evidências de validação

Para cada fluxo de trabalho, escolha o nível de validação:

- A validação estrutural confirma que o fluxo de trabalho é convertido num DAG executável do PlaidCloud.
- A validação de paridade de saída compara o esquema, a contagem de linhas e os valores das linhas com saídas fiáveis do Alteryx.
- A validação de artefactos revê relatórios, PDF, imagens, gráficos, mapas ou saídas de modelos.

Guarde as saídas esperadas com o pacote de migração sempre que a paridade de saída for necessária.

## Lista de verificação de prontidão para a importação

Antes de importar, confirme que:

- Os ficheiros de fluxos de trabalho, aplicações e macros estão presentes.
- As macros referenciadas estão presentes.
- Os ficheiros e pastas de entrada estão presentes.
- Os ficheiros auxiliares espaciais estão agrupados.
- As saídas esperadas estão disponíveis quando a validação de paridade faz parte do plano de migração.
- Os valores de entrada de execução são conhecidos para as aplicações analíticas.
- O projeto de destino e o caminho de Documentos estão selecionados.
- As credenciais ou ligações externas de que o fluxo de trabalho necessita estão disponíveis no PlaidCloud.
