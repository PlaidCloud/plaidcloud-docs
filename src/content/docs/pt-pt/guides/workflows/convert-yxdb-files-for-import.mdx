O Alteryx escreve ficheiros `.yxdb` em dois formatos. O formato clássico (escrito pelo motor original) é bem conhecido e o PlaidCloud importa-o diretamente. O motor AMP escreve uma variante mais recente — o cabeçalho do ficheiro indica `Alteryx e2 Database file` — cuja especificação é proprietária e não está publicada, pelo que nenhuma ferramenta fora do Alteryx a consegue ler, incluindo o PlaidCloud.

Durante uma migração, ainda tem o Alteryx Designer licenciado, e o Designer lê ambos os formatos. Utilize-o uma vez, antes de o desativar, para reescrever os ficheiros em formato AMP numa forma portátil.

<Aside type="note">
  Os ficheiros `.yxdb` clássicos são importados diretamente para o PlaidCloud — sem necessidade de conversão. Se uma importação falhar com um erro de ficheiro ilegível num `.yxdb`, a causa mais provável é um ficheiro em formato AMP.
</Aside>

## Identificar Ficheiros em Formato AMP

- O fluxo de trabalho que produziu o ficheiro foi executado com o motor AMP ativado.
- O PlaidCloud indica que o ficheiro é ilegível durante a importação, enquanto outros ficheiros `.yxdb` do mesmo pacote são importados sem problemas.
- Os primeiros bytes do ficheiro indicam `Alteryx e2 Database file` em vez de `Alteryx Database File` (visível em qualquer editor de texto ou hexadecimal).

## Opção A: Guardar de Novo os Ficheiros Individualmente no Designer

Para um pequeno número de ficheiros, guarde de novo cada um a partir do Designer:

1. No Alteryx Designer, adicione uma ferramenta **Input Data** e selecione o ficheiro `.yxdb`.
2. Ligue uma ferramenta **Output Data** e escolha um novo caminho `.yxdb`.
3. Nas opções da ferramenta Output Data, ative a opção para guardar o ficheiro **compatível com o Designer 18.1 e anteriores**. Isto força o formato clássico.
4. Execute o fluxo de trabalho e, em seguida, importe o novo ficheiro para o PlaidCloud.

Escrever para CSV em vez de `.yxdb` no passo 2 também funciona e dispensa a opção de compatibilidade.

## Opção B: Converter uma Pasta em Lote com o Fluxo de Trabalho Transferível

Para muitos ficheiros, transfira o fluxo de trabalho pré-construído e execute-o no Designer:

<a href="/downloads/convert_yxdb_folder.yxmd" download>Transferir convert_yxdb_folder.yxmd</a>

Encadeia uma ferramenta **Directory**, uma ferramenta **Dynamic Input** e uma ferramenta **Output Data**, de modo que todos os ficheiros `.yxdb` de uma pasta — clássicos ou AMP — sejam reescritos como um ficheiro CSV com o nome `converted_<original name>.csv`. O CSV é portátil e o PlaidCloud importa-o sem perdas.

1. Abra `convert_yxdb_folder.yxmd` no Alteryx Designer.
2. Na ferramenta **Directory**, defina a pasta que contém os seus ficheiros `.yxdb`.
3. Na ferramenta **Dynamic Input**, aponte o Input Data Source Template para qualquer ficheiro `.yxdb` dessa pasta.
4. Na ferramenta **Output Data**, defina a pasta de saída.
5. Execute o fluxo de trabalho e, em seguida, carregue os CSV para o Document e importe-os.

<Aside type="caution">
  A ferramenta Dynamic Input exige que todos os ficheiros de um lote partilhem a disposição de campos do ficheiro de modelo. Os ficheiros com uma disposição diferente são ignorados com um aviso — o painel de resultados do Designer indica cada ficheiro ignorado. Agrupe os ficheiros diferentes na sua própria pasta, com o seu próprio modelo, e execute de novo, ou guarde de novo individualmente os restantes através da Opção A.
</Aside>

Os ficheiros convertidos para CSV perdem a tipificação específica de `.yxdb` (tudo chega como texto e é tipificado de novo na importação), pelo que deve verificar por amostragem os tipos de coluna das tabelas importadas — especialmente datas e decimais de elevada precisão.
