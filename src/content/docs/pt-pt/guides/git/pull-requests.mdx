## Criar um ramo

Trabalhe num novo ramo para que as suas alterações fiquem separadas do ramo predefinido até estarem prontas.

**Na interface:**

1. Abra o seu repositório e selecione o seletor de ramos junto ao canto superior esquerdo (mostra o nome do ramo atual).
2. Escreva o nome de um novo ramo na caixa de pesquisa e selecione **Create Branch**.

**Localmente:**

1. Crie e mude para o ramo: `git checkout -b feature-x`
2. Faça as suas alterações e depois prepare-as e faça commit: `git add .` e depois `git commit -m "Describe what changed"`
3. Envie o ramo para o PlaidCloud Git: `git push -u origin feature-x`

## Abrir um pull request

1. Abra o seu repositório, selecione o separador **Pull Requests** e depois **New Pull Request**.
2. Defina o ramo a **comparar** como o seu ramo de funcionalidade e o ramo **base** como o destino (normalmente `main` ou `master`).
3. Escreva um título claro e uma descrição que explique o que mudou e porquê.
4. Para ligar issues relacionadas, adicione uma palavra-chave de fecho na descrição — por exemplo, `Closes #12` — para que a issue seja fechada automaticamente quando o pull request for integrado.
5. Atribua revisores, se necessário, e selecione **Create Pull Request**.

## Rever alterações

Os revisores trabalham sobre o pull request sem integrar nada:

1. Abra o pull request e selecione **Files Changed** para ler as diferenças.
2. Selecione qualquer linha nas diferenças para deixar um comentário em linha sobre essa alteração específica.
3. Quando terminar, submeta um veredicto global: **Aprovar** para dar o seu aval ou **Request Changes** para pedir primeiro revisões.
4. O autor envia mais commits para o mesmo ramo para responder ao feedback — o pull request é atualizado automaticamente, sem necessidade de abrir um novo.
5. Os revisores marcam os fios de comentários individuais como resolvidos assim que cada preocupação é tratada.

<Aside>Um administrador do repositório pode ativar a proteção de ramos no ramo predefinido para exigir um número mínimo de aprovações antes de um pull request poder ser integrado.</Aside>

## Integrar

Assim que o pull request for aprovado:

1. Escolha um método de integração no menu pendente junto ao botão **Merge**:
   - **Create a merge commit** — preserva todo o histórico do ramo com um commit de integração.
   - **Squash and merge** — combina todos os commits do ramo num único commit no ramo de destino.
   - **Rebase and merge** — reaplica os commits do ramo sobre o ramo de destino sem um commit de integração.
2. Selecione **Merge** para concluir.
3. Opcionalmente, selecione **Delete Branch** para limpar o ramo de funcionalidade quando já não for necessário.
