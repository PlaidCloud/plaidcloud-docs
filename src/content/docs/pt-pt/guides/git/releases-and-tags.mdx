Uma etiqueta marca um commit como significativo — normalmente uma versão como `v1.2.0`. Um lançamento assenta numa etiqueta, acrescentando notas legíveis e anexos de ficheiros opcionais, para que os utilizadores possam navegar e transferir versões específicas a partir da interface web.

## Criar uma etiqueta

Pode criar uma etiqueta a partir da interface ou do seu clone local.

**A partir da interface:**

1. Abra o seu repositório e selecione **Releases** e depois **Tags**.
2. Selecione **Create Tag**.
3. Introduza o nome da etiqueta (por exemplo, `v1.2.0`), escolha o ramo ou commit de destino e selecione **Create Tag**.

**A partir da linha de comandos:**

```bash
git tag v1.2.0
git push origin v1.2.0
```

Para etiquetar um commit anterior específico, indique o respetivo ID de commit em vez de depender de `HEAD`:

```bash
git tag v1.2.0 abc1234
git push origin v1.2.0
```

## Publicar um lançamento

1. Abra o seu repositório e selecione **Releases**.
2. Selecione **New Release**.
3. No campo **Tag Name**, escolha uma etiqueta existente ou escreva um novo nome para criar uma no topo atual do ramo predefinido.
4. Introduza um **Release Title** e escreva as notas do lançamento no corpo em Markdown — registos de alterações, instruções de atualização e problemas conhecidos pertencem todos aqui.
5. Selecione **This is a pre-release** se a versão não estiver pronta para utilização geral ou **Guardar rascunho** para a concluir mais tarde sem publicar.
6. Selecione **Publish Release** quando estiver pronta.

<Aside>Os lançamentos em rascunho só são visíveis para os membros do repositório com acesso de escrita. Um pré-lançamento é visível para todos os que têm acesso, mas é excluído da designação "Latest" na descrição geral do repositório.</Aside>

## Anexar ficheiros

Os ficheiros carregados surgem na página do lançamento como ligações de transferência com nome, juntamente com o arquivo de código-fonte gerado automaticamente.

1. No formulário de novo lançamento ou de edição de lançamento, aceda à secção **Attach Files**.
2. Arraste ficheiros para a área de carregamento ou selecione-a para navegar — binários compilados, arquivos comprimidos, somas de verificação e assinaturas são escolhas comuns.
3. Repita para cada ficheiro e depois publique ou atualize o lançamento.

Mantenha cada ficheiro com um tamanho razoável para que as transferências continuem rápidas para a sua equipa.

<Aside type="tip">Para pacotes instaláveis — módulos npm, imagens de contentor, wheels do PyPI e semelhantes — o [registo de pacotes](/pt-pt/guides/git/packages/) é mais adequado do que os anexos de lançamento. Compreende a resolução de versões, os metadados de dependências e as ferramentas de cliente (`npm`, `pip`, `docker pull`) de formas que uma simples transferência de ficheiro não consegue.</Aside>

## Ver e transferir lançamentos

1. Selecione **Releases** para ver a lista completa, do mais recente para o mais antigo.
2. O último lançamento que não é pré-lançamento aparece destacado com um selo **Latest**.
3. Cada entrada mostra o nome da etiqueta, o título do lançamento, as notas e ligações para:
   - **Source code** — arquivos `zip` e `tar.gz` gerados automaticamente do commit etiquetado.
   - **Assets** — quaisquer ficheiros que anexou ao publicar o lançamento.
4. Selecione a ligação de um ficheiro para o transferir diretamente ou copie o URL para o partilhar.

Para comparar dois lançamentos, abra os nomes das respetivas etiquetas como um URL de comparação:

```bash
https://git.example.plaidcloud.com/you/my-repo/compare/v1.1.0...v1.2.0
```
