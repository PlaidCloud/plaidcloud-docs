## Descrição


Os painéis de controlo suportam uma grande variedade de casos de utilização, desde relatórios estáticos até análises dinâmicas. Suportam necessidades de relato complexas e oferecem, ao mesmo tempo, uma interface intuitiva de apontar e clicar. Pode haver ocasiões em que encontra dificuldades. Um membro da equipa de suporte do PlaidCloud está sempre disponível para o ajudar, mas também compilámos algumas sugestões abaixo, caso se depare com um problema semelhante.



## **Perguntas e respostas comuns sobre o painel de controlo**



### Navegador preferido


Devido à colocação frequente em cache, o Google Chrome é normalmente o melhor navegador para usar com o painel de controlo. Se estiver a usar outro navegador e se deparar com um problema, sugerimos que comece por limpar a cache e os cookies para ver se isso o resolve. Se não, sugerimos que mude para o Google Chrome e verifique se o problema volta a ocorrer.



### Atraso de sincronização


* *Problema:* Depois de anular a publicação e voltar a publicar tabelas na área Dashboards, os dados não parecem estar a sincronizar corretamente.
* *Soluções:* Republicar uma tabela limpa os resultados em cache de todos os gráficos que a leem, pelo que um painel de controlo aberto depois da execução do fluxo de trabalho mostra os novos dados sem uma atualização manual. Se não mostrar, verifique se a execução terminou e se republicou a tabela esperada. Consulte [Cache de painéis de controlo](/pt-pt/guides/dashboards/dashboard-caching/).

### Erro de sincronização de tabelas


* *Problema:* Depois de recriar uma tabela com o mesmo nome publicado que uma tabela anterior, a tabela não sincroniza, mesmo depois de clicar em atualizar no painel de controlo, publicar, anular a publicação e republicar a tabela.
* *Soluções:* Republique a tabela com um nome diferente. O modelo de dados do painel de controlo não permite tabelas duplicadas, nem tabelas com o mesmo nome publicado e o mesmo ID de projeto.

### Aviso de cache


* *Problema:* Surgiu um aviso no canto superior direito a dizer “Loaded data cached **3 hours ago**. Click to force-refresh.”
* *Soluções:* Clique no aviso para forçar a atualização da cache. Também pode clicar no menu pendente junto a “Edit dashboard” e selecionar aí “Force refresh dashboard”. Qualquer uma destas opções atualiza dentro do sistema e é preferível a atualizar o próprio navegador. O tempo durante o qual um resultado é mantido é configurável — consulte [Cache de painéis de controlo](/pt-pt/guides/dashboards/dashboard-caching/).

### Aviso de permissão


* *Problema:* O meu painel de controlo publicado apresenta o mesmo erro em cada secção onde deveriam ser preenchidos dados: “This endpoint requires the datasource… permission”
* *Soluções:* Verifique se as origens de dados não são antigas. Muito provavelmente, os gráficos estão a obter dados de material desatualizado. Se isto acontecer, atualize os gráficos com novas origens de dados.
* *Problema:* Estou a receber o mesmo aviso de permissão acima, mas o meu colega consegue ver os dados do gráfico.
* *Soluções:* Se o problema é que uma pessoa consegue ver os dados nos gráficos e outra não, pode ser necessário que a segunda pessoa receba permissão de alguém dentro da categoria autorizada. Para o fazer:


	1. Aceda a Charts
	2. Selecione o segundo ícone pequeno de um lápis e papel junto ao gráfico ao qual pretende conceder acesso
	3. Clique em Edit Table
	4. Clique em Detail
	5. Clique em Owners, adicione o nome da pessoa à qual pretende conceder acesso e guarde.

<Aside>Como boa prática, sempre que criar e guardar um novo gráfico, adicione nessa altura todas as pessoas aplicáveis à secção Owners. Caso contrário, terá de voltar atrás para editar e adicionar proprietários sempre que alguém novo precisar de acesso.</Aside>


### Guardar filtros modificados no painel de controlo


* *Problema:* Modifiquei filtros no meu modelo de rascunho e pretendo guardá-los no meu painel de controlo. Os filtros não estão na lista. No meu modelo de rascunho, um aviso indicava “There is no chart definition associated with this component, could it have been deleted? Delete this container and save to remove this message.”
* *Soluções:* Aceda a “Edit Chart”. A partir daí, certifique-se de que a secção “Dashboards” tem o painel de controlo correto preenchido. Se estiver em branco, adicione o nome do painel de controlo correto.

### Formatar números: quebras


* *Problema:* A formatação dos meus números está quebrada e desordenada.
* *Soluções:* O motivo mais provável para esta quebra é o uso de nulos numa coluna numérica. Com um filtro, elimine todas as colunas numéricas nulas. Tente executá-lo novamente. Se isso não funcionar, reveja o material disponibilizado aqui: http://bl.ocks.org/zanarmstrong/05c1e95bf7aa16c4768e ou aqui: https://github.com/apache-superset/superset-ui/issues. Por fim, sinta-se sempre à vontade para contactar um membro da equipa de suporte do PlaidCloud. Este problema é conhecido e está a ser desenvolvida uma solução mais permanente.

### Formatar números


Para arredondar números ao inteiro mais próximo:


1. *Não use:* ,.0f
2. *Use antes:* ,d ou $,d para dólares

### Importar um painel de controlo existente


* *Problema:* Estou a importar um painel de controlo existente e recebo um erro na minha exportação.
* *Soluções:* Primeiro, verifique o ficheiro. Os painéis de controlo e os conjuntos de dados são importados a partir do ficheiro ZIP que **Exportar** produz. Um ficheiro de exportação JSON ou YAML mais antigo é recusado, pelo que deve exportar novamente o painel de controlo e importar o novo ficheiro ZIP.
* Em seguida, verifique se o painel de controlo tem um “Slug”. Para isso, abra Edit Dashboard, e a segunda secção intitula-se Slug. Se essa secção estiver vazia ou indicar “null”, então este não é o problema. Caso contrário, o slug tem de ser único: altere-o para algo que nenhum outro painel de controlo use, exporte novamente e importe o novo ficheiro.
