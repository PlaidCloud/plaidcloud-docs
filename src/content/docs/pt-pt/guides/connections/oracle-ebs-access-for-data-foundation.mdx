O [Data Foundation](/pt-pt/guides/projects/data-foundation/) reúne os dados de todos os sistemas ERP e instâncias que ligar num único Common Finance Model, e o Oracle E-Business Suite é um dos ERP que lê diretamente. O PlaidCloud chega ao EBS através de um agente [PlaidLink](/pt-pt/reference/cli/plaidlink/) instalado dentro da sua rede, nunca diretamente. Esta página destina-se ao administrador do EBS que faz essa configuração e ao utilizador do PlaidCloud que lha pede.

O PlaidCloud só lê dados. Ninguém envia uma palavra-passe por email.

## Enviar o pedido de acesso

Na página **Sistemas** do projeto, em **Data Foundation** no **Início**, escolha o seu sistema em **Sistema**, em **Adicionar um sistema**, e clique em **Ainda não tem acesso?**. O sistema fica a aguardar acesso e é apresentado um único pedido que abrange os sistemas do projeto. Clique em **Copiar pedido** para o colar na sua própria mensagem ou em **Enviar pedido por email** para o abrir no seu programa de correio com o assunto "Acesso ao PlaidCloud."

## O que o administrador do EBS configura

<Steps>

1. **Instalar o PlaidLink** num servidor que consiga chegar à base de dados do EBS e registá-lo no PlaidCloud.

2. **Criar um utilizador de base de dados só de leitura** para o PlaidLink, nunca o APPS nem qualquer outro utilizador de esquema que possa alterar dados. Atribua-lhe estas concessões, cada uma com um sinónimo com o mesmo nome para o objeto APPS, SELECT salvo indicação em contrário na tabela:

   | Área | Objetos |
   |---|---|
   | Sessão (obrigatório) | EXECUTE sobre `FND_GLOBAL` e `MO_GLOBAL`; `FND_RESPONSIBILITY_VL`; e `FND_USER`, ou uma vista dele com esse nome que contenha apenas `USER_ID`, `USER_NAME`, `EMPLOYEE_ID` e `DESCRIPTION`. Sem eles, todas as leituras falham |
   | Razão geral | `GL_LEDGERS`, `GL_LEDGER_NORM_SEG_VALS`, `GL_CODE_COMBINATIONS`, `GL_PERIODS`, `GL_PERIOD_STATUSES`, `GL_JE_HEADERS`, `GL_JE_LINES`, `GL_BALANCES`, `GL_DAILY_RATES`. `GL_BALANCES` tem de conter todos os períodos, e não apenas o mais recente: é o saldo de fim de mês com que o razão é comparado |
   | Flexfields | `FND_ID_FLEX_SEGMENTS`, `FND_SEGMENT_ATTRIBUTE_VALUES`, `FND_FLEX_VALUES_VL`, `FND_FLEX_VALUE_NORM_HIERARCHY` |
   | Vendas (opcional) | `RA_CUSTOMER_TRX_ALL`, `RA_CUSTOMER_TRX_LINES_ALL`, `RA_CUST_TRX_TYPES_ALL`, `RA_CUST_TRX_LINE_GL_DIST_ALL`, `HZ_CUST_ACCOUNTS`, `HZ_PARTIES`, `MTL_PARAMETERS`, `MTL_SYSTEM_ITEMS_B` |
   | Aprovador do lançamento (opcional) | `GL_JE_BATCHES` |
   | País da entidade (opcional) | `XLE_REGISTRATIONS`, `HZ_LOCATIONS` |
   | Contas a receber, contas a pagar, saldos bancários e faturas de fornecedores (opcional) | `AR_PAYMENT_SCHEDULES_ALL`, `AR_CASH_RECEIPTS_ALL`, `AR_RECEIVABLE_APPLICATIONS_ALL`, `AR_ADJUSTMENTS_ALL`, `AR_RECEIPT_METHODS`, `RA_TERMS_TL`, `CE_BANK_ACCOUNTS`, `AP_INVOICES_ALL`, `AP_INVOICE_LINES_ALL`, `AP_INVOICE_DISTRIBUTIONS_ALL`, `AP_PAYMENT_SCHEDULES_ALL`, `AP_INVOICE_PAYMENTS_ALL`, `AP_CHECKS_ALL`, `AP_SUPPLIERS`, `AP_SUPPLIER_SITES_ALL`, `AP_TERMS_TL`, `PO_HEADERS_ALL`, `PO_LINES_ALL`, `MTL_ITEM_CATEGORIES`, `MTL_CATEGORIES_B` |
   | Compras, existências, orçamentos, custos-padrão e ativos fixos (opcional) | `PO_LINE_LOCATIONS_ALL`, `PO_DISTRIBUTIONS_ALL`, `RCV_TRANSACTIONS`, `ORG_ORGANIZATION_DEFINITIONS`, `MTL_MATERIAL_TRANSACTIONS`, `MTL_SECONDARY_INVENTORIES`, `CST_STANDARD_COSTS`, `GL_BUDGETS`, `GL_BUDGET_VERSIONS`, `FA_ADDITIONS_B`, `FA_ADDITIONS_TL`, `FA_CATEGORIES_B`, `FA_BOOK_CONTROLS`, `FA_BOOKS`, `FA_CATEGORY_BOOKS`, `FA_DISTRIBUTION_HISTORY`, `FA_DEPRN_PERIODS`, `FA_DEPRN_SUMMARY`, `FA_RETIREMENTS`, `FA_TRANSACTION_HEADERS` |

   As existências são lidas a partir das transações de material, pelo que o respetivo histórico exige que estas sejam mantidas. Os orçamentos são os saldos orçamentais em `GL_BALANCES`.

3. **Indicar um utilizador da aplicação** (`FND_USER`) e uma responsabilidade de consulta, que só permita ver, que consiga ver todos os razões e todos os valores de segmento de balanceamento que pretende reportar.

4. **Descrever o plano de contas.** Indique quais os segmentos que são o segmento de balanceamento, a conta natural, o centro de custo e o segmento intercompanhia (os respetivos qualificadores de segmento). O PlaidCloud classifica uma conta de gastos como custo das mercadorias vendidas quando ela, ou um valor superior da hierarquia, é descrita como custo das mercadorias vendidas, custo das vendas ou custo da receita. Classifica uma conta como não operacional quando uma delas menciona rendimentos ou gastos de juros, rendimentos ou custos financeiros, câmbio, gasto com imposto sobre o rendimento, ou outros rendimentos e gastos. Diga ao PlaidCloud se os seus valores superiores usarem outras palavras para estes conceitos.

5. **Indicar os segmentos de site e de centro de lucro**, se mantiver sites ou centros de lucro num segmento do plano de contas (`SEGMENT1` a `SEGMENT30`). O EBS não tem qualificador para nenhum deles. O PlaidCloud lê os valores do conjunto de valores de cada segmento como as listas de sites e de centros de lucro.

6. **Confirmar os tipos de taxa.** Cada razão principal indica os respetivos tipos de taxa de média do período e de fim de período, nas opções de conversão do razão. O PlaidCloud converte com as taxas diárias desses dois tipos.

</Steps>

<Aside type="caution">
A responsabilidade errada devolve as linhas de outro razão sem qualquer erro. Confirme-a com o responsável pelo seu razão geral.
</Aside>

## O que enviar de volta

| O administrador envia | Introduzido no PlaidCloud como |
|---|---|
| O anfitrião da base de dados | **Anfitrião ou endereço IP** |
| A porta da base de dados | **Porta** (1521, a menos que a altere) |
| O nome do serviço | **Nome do serviço** |
| O utilizador de base de dados só de leitura | **Utilizador da base de dados (esquema APPS)** |
| A respetiva palavra-passe, através do formulário de ligação seguro | **Palavra-passe**, que a sua equipa introduz por si própria |
| O `FND_USER` | **Utilizador da aplicação (FND_USER.USER_NAME)** |
| A chave da responsabilidade | **Chave de responsabilidade (FND_RESPONSIBILITY.RESPONSIBILITY_KEY)** |
| Os valores de segmento de balanceamento que o PlaidCloud pode ler | Em **Opções**, **Empresas**, que o EBS não consegue listar: introduza os valores, separados por vírgulas, ou deixe vazio para carregar todas as entidades de cada razão principal |

O agente PlaidLink que chega à instância é indicado na definição de sistema **PlaidLink agent**. Os segmentos de site e de centro de lucro ficam nas definições de sistema **Site segment** e **Profit centre segment**.

<Aside type="caution">
Nunca envie a palavra-passe por email. **Palavra-passe** é um segredo: é guardado na ligação e nunca mais é apresentado.
</Aside>

## Verificar o acesso

De volta ao PlaidCloud, depois de o sistema ser adicionado, clique em **Testar ligação** na respetiva linha da página **Sistemas**. Como o EBS é alcançado através do agente PlaidLink, o teste verifica se a ligação indica tudo aquilo com que o agente inicia sessão. As próprias tabelas são lidas no primeiro carregamento, e uma tabela que o agente não possa ler é indicada nessa altura. Cada conjunto de dados lê:

| Conjunto de dados | Objetos que lê |
|---|---|
| Entidades | `GL_LEDGERS`, `GL_LEDGER_NORM_SEG_VALS` |
| Calendário fiscal | `GL_PERIODS`, `GL_PERIOD_STATUSES` |
| Plano de contas | `GL_CODE_COMBINATIONS`, as tabelas de flexfields |
| Departamentos | `GL_CODE_COMBINATIONS`, as tabelas de flexfields |
| Taxas de câmbio | `GL_DAILY_RATES` |
| Razão geral | `GL_JE_HEADERS`, `GL_JE_LINES` |
| Balancete | `GL_BALANCES` |
| Clientes | `HZ_CUST_ACCOUNTS`, `HZ_PARTIES` (opcional) |
| Produtos | `MTL_PARAMETERS`, `MTL_SYSTEM_ITEMS_B` (opcional) |
| Linhas de vendas | As tabelas `RA_CUSTOMER_TRX` (opcional) |
| Saldo de fim de mês | `GL_BALANCES`, todos os períodos (opcional) |
| Saldos bancários | `CE_BANK_ACCOUNTS`, com o saldo de fim de mês da conta de caixa de cada banco (opcional) |
| Sites, Centros de lucro | Os valores do segmento que indicar para cada um (opcional) |
| Fornecedores | `AP_SUPPLIERS`, `AP_SUPPLIER_SITES_ALL`, `AP_TERMS_TL` (opcional) |
| Itens em aberto, Pagamentos | As tabelas de contas a receber, de contas a pagar e bancárias (opcional) |
| Linhas de faturas de fornecedores | `AP_INVOICE_LINES_ALL`, com os documentos de contas a pagar (opcional) |
| Encomendas de compra | As tabelas `PO_`, `RCV_TRANSACTIONS` e as linhas de faturas (opcional) |
| Saldos de inventário | `MTL_MATERIAL_TRANSACTIONS`, `MTL_SECONDARY_INVENTORIES` (opcional) |
| Custos-padrão | `CST_STANDARD_COSTS` (opcional) |
| Orçamento | Saldos orçamentais de `GL_BALANCES`, `GL_BUDGETS`, `GL_BUDGET_VERSIONS` (opcional) |
| Ativos fixos, Movimentos de ativos | As tabelas `FA_` (opcional) |

Quando um carregamento indicar uma tabela que o agente não pode ler, peça ao administrador que conceda SELECT sobre ela e carregue novamente. Uma tabela opcional que não conceda gera um aviso que a indica, e tudo o resto é carregado. Os itens em aberto, os pagamentos, as faturas de fornecedores, as encomendas de compra, os custos-padrão, o inventário, os orçamentos, os ativos e os saldos de fim de mês e bancários mantêm as linhas que já tinham até ser possível ler a tabela.
