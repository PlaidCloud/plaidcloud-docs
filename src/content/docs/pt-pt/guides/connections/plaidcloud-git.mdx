Uma **ligação PlaidCloud Git** aponta um fluxo de trabalho, ou a compilação de uma aplicação Panel de servidor, para um repositório no servidor Git gerido da sua área de trabalho. Como esse servidor Git é alojado por si em `git.<your-workspace>.plaid.cloud` e a sessão já está iniciada através do início de sessão normal do PlaidCloud, o formulário da ligação é muito mais simples do que o de um fornecedor Git externo: não há URL do servidor a introduzir nem nome de utilizador, token ou chave SSH a gerir.

<Aside type="note">Nunca introduz um URL do servidor nem credenciais numa ligação PlaidCloud Git. O servidor Git da sua área de trabalho e o seu acesso a ele são tratados automaticamente a partir do início de sessão no PlaidCloud (incluindo SSO), pelo que não há tokens a criar, guardar ou rodar.</Aside>

## Quando utilizar

Recorra a uma ligação PlaidCloud Git sempre que o repositório que pretende ler esteja no [PlaidCloud Git](/pt-pt/guides/git/), o serviço Git integrado da sua área de trabalho, e não num anfitrião externo. A utilização mais comum é automatizar as compilações de **aplicações Panel de servidor** ou **aplicações Dash** a partir de um repositório gerido, para que um push para um ramo recompile e volte a implementar a aplicação sem uma conta GitHub externa nem um token de acesso pessoal pelo meio.

Para um repositório alojado num serviço externo (GitHub, GitLab, Bitbucket, Forgejo ou Gitea), utilize antes uma [ligação Git externa](/pt-pt/reference/connectors/git/). Essas mantêm o formulário completo, com um **URL do servidor**, autenticação por utilizador/token ou SSO e os separadores **SSL** e **SSH**.

## Criar uma ligação PlaidCloud Git

1. Abra **Tools > Connections**
2. Clique em `New Connection` e escolha **PlaidCloud Git** no menu
3. Preencha o formulário simplificado:
   - **Nome da conta** — um nome de apresentação para a ligação
   - **Memorando** — uma nota opcional sobre a finalidade da ligação
   - **Repositório** — clique em `Refresh` para listar os repositórios que a sua área de trabalho consegue alcançar e escolha um (por exemplo, o repositório `udfs` ou `apps`). Escolhe a partir da lista, em vez de escrever o caminho.
   - **Ramo predefinido** — escolha o ramo a ler por predefinição, a partir da lista de ramos do repositório selecionado
   - **Caminho inicial** — opcionalmente, navegue pelo repositório e escolha uma pasta para limitar todas as pesquisas de ficheiros a uma subpasta; deixe-o por definir para utilizar todo o repositório
4. Defina a **Utilização** — `Active` para ativar a ligação e `Read Only` se a ligação nunca deva escrever
5. Defina o **Modelo de segurança** — quem, na área de trabalho, pode utilizar a ligação
6. Clique em `Create` para guardar

É todo o formulário. Ao contrário de um fornecedor Git externo, não há URL do servidor, separador de autenticação nem configuração SSL ou SSH: tudo isso é tratado por si.

<Aside type="note">O repositório, o ramo predefinido e o caminho inicial são escolhidos a partir de listas em direto (escolha primeiro um repositório, depois o respetivo ramo e, por fim, navegue até uma pasta), pelo que não há nada que possa escrever mal. Cada lista é lida com o acesso da própria ligação, por isso, numa ligação PlaidCloud Git, é preenchida de imediato, sem credenciais a introduzir.</Aside>

## Modelo de segurança

O `Security Model` controla quem, na área de trabalho, pode utilizar a ligação:

| Opção | Quem pode utilizar a ligação |
|---|---|
| Privada (apenas proprietários) | Apenas os proprietários. |
| Apenas membros específicos | Os proprietários e uma lista explícita de membros. |
| Apenas grupos de segurança específicos | Os proprietários e os membros de grupos de segurança indicados. |
| Todos os membros da área de trabalho | Todos os utilizadores da área de trabalho. |

Para `Specific Members Only` ou `Specific Security Groups Only`, conceda o acesso a partir do menu `Actions` da lista, depois de guardar. Consulte [Criar e gerir uma ligação](/pt-pt/guides/connections/create-connection/#modelo-de-segurança) para os mecanismos de ligação partilhados.

## Quem pode ver os repositórios

Todos os repositórios que o PlaidCloud cria para si podem ser lidos por todos os membros com sessão iniciada na sua área de trabalho. Isto inclui os repositórios por trás das suas aplicações Panel e Dash e os repositórios integrados `apps` e `udfs`. Quem não tiver sessão iniciada não os pode ler.

Por esse motivo, os membros podem abrir e voltar a publicar aplicações, e escolher um repositório para uma ligação PlaidCloud Git, sem qualquer configuração por repositório.

### Avançado: repositórios privados

Um administrador do Git pode tornar um repositório privado na interface do Git. Um repositório privado deixa de estar visível para todos os membros, pelo que:

- Não aparece na lista **Repositório** das ligações PlaidCloud Git.
- O código de UDF baseado em Git não pode ser lido a partir dele, pelo que uma UDF baseada em Git guardada num repositório privado não é executada.
- Os membros não podem publicar uma aplicação a partir dele.

Para utilizar um repositório privado como origem, crie antes uma [ligação Git externa](/pt-pt/reference/connectors/git/) com o seu próprio token de acesso.

## Automatizar as compilações de aplicações Panel e Dash a partir do Git gerido

Uma [aplicação Panel de servidor](/pt-pt/guides/panel-apps/creating/) ou uma [aplicação Dash](/pt-pt/guides/dash-apps/) é compilada a partir de um ramo Git e é recompilada automaticamente a cada push para esse ramo. Apontá-la para uma ligação PlaidCloud Git mantém todo o ciclo dentro da sua área de trabalho: sem anfitrião externo e sem um token de acesso pessoal para manter ativo.

1. Faça push da sua aplicação para um repositório no servidor PlaidCloud Git da sua área de trabalho: um ficheiro `.py` de ponto de entrada (o de Panel chama `.servable()`; o de Dash expõe `server = app.server`) e um `requirements.txt` opcional na raiz do repositório ou junto ao ponto de entrada. Consulte [Criar uma aplicação Panel](/pt-pt/guides/panel-apps/creating/#preparar-o-repositório-da-aplicação) ou [Implementar uma aplicação Dash a partir do PlaidCloud Git](/pt-pt/guides/dash-apps/deploy-from-git/) para a estrutura do repositório.
2. Crie uma ligação PlaidCloud Git cujo **Repositório** seja esse repositório, seguindo os passos acima.
3. Em **As minhas aplicações Panel**, clique em **Nova aplicação de servidor** ou **Nova aplicação Dash** e, em **Ligação Git e monitor de publicação**:
   - **Ligação Git** — escolha a ligação PlaidCloud Git que acabou de criar
   - **Ramo** — o ramo a partir do qual compilar; os pushes para ele recompilam e voltam a implementar a aplicação
   - **Ponto de entrada** — o ficheiro `.py` que a aplicação deve servir
4. Conclua a caixa de diálogo de publicação e clique em **Publicar**.

A partir daí, cada push para esse ramo no seu servidor Git gerido recompila a aplicação, numa compilação automatizada de ponta a ponta que nunca sai do PlaidCloud.
