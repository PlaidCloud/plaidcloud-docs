O [Data Foundation](/pt-pt/guides/projects/data-foundation/) reúne os dados de todos os sistemas ERP e instâncias que ligar num único Common Finance Model, e o SAP S/4HANA Cloud é um dos ERP que lê diretamente. A ligação lê os serviços OData disponibilizados do inquilino com credenciais de cliente OAuth 2.0; não intervém nenhum agente. Esta página destina-se ao administrador do S/4HANA Cloud que faz essa configuração e ao utilizador do PlaidCloud que lha pede.

O PlaidCloud só lê dados. Ninguém envia uma palavra-passe ou um segredo do cliente por email.

## Enviar o pedido de acesso

No separador **Base** do projeto, escolha **Criar uma nova ligação** em **Ligação SAP S/4HANA Cloud**. O formulário mostra o pedido completo. Clique em **Copiar pedido** para o colar na sua própria mensagem, ou em **Enviar pedido por email** para o abrir no seu programa de correio com o assunto "Read-only SAP S/4HANA Cloud access for PlaidCloud (OAuth 2.0 client credentials)."

## O que o administrador do S/4HANA Cloud configura

<Steps>

1. **Criar um utilizador de comunicação** para o PlaidCloud, na aplicação **Maintain Communication Users**. O seu método de autenticação é OAuth 2.0 ou nome de utilizador e palavra-passe, conforme o seu cenário o exija.

2. **Criar um sistema de comunicação** para o PlaidCloud, na aplicação **Communication Systems**, com esse utilizador para comunicação de entrada e credenciais de cliente OAuth 2.0.

3. **Criar um acordo de comunicação** para cada cenário abaixo, na aplicação **Communication Arrangements**, todos para o sistema do passo 2. Em conjunto, expõem os serviços OData que o PlaidCloud lê:

   | Cenário | Serviço |
   |---|---|
   | Company Code | `API_COMPANYCODE_SRV` |
   | G/L Account in Chart of Accounts | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
   | Cost Center | `API_COSTCENTER_SRV` |
   | Business Partner and Customer | `API_BUSINESS_PARTNER` |
   | Product | `API_PRODUCT_SRV` |
   | Fiscal Year Variant Periods | `API_FISCALYEARPERIODFORVARIANT_SRV` |
   | Exchange Rates | `API_EXCHANGERATE_SRV` |
   | Journal Entry Item | `API_JOURNALENTRYITEMBASIC_SRV` (o diário e o saldo transitado) |
   | Billing Document | `API_BILLING_DOCUMENT_SRV` (opcional: acrescenta vendas faturadas, documentos e itens) |

   Dê ao utilizador de comunicação acesso a todos os códigos de empresa sobre os quais reporta.

</Steps>

## O que enviar de volta

| O administrador envia | Introduzido no PlaidCloud como |
|---|---|
| O anfitrião da API do inquilino, por exemplo `my300000-api.s4hana.cloud.sap` | **Anfitrião** |
| O ID do cliente | **ID do cliente** |
| O segredo do cliente, através do formulário de ligação seguro | **Segredo do cliente**, que a sua equipa cola por si própria |
| O URL do token, apenas se o seu cenário usar um servidor de autorização XSUAA em vez do próprio do inquilino (`/sap/bc/sec/oauth2/token`) | **Token URL (optional)** |
| O âmbito, apenas com um servidor de autorização XSUAA | **Scope (optional)** |
| Se o **Carry Forward Balances** foi executado para cada ano fiscal que carrega | Nada a introduzir. Os saldos de abertura são lidos a partir dele. |

<Aside type="caution">
Nunca envie o segredo do cliente por email. **Segredo do cliente** é um segredo: é guardado na ligação e nunca mais é apresentado.
</Aside>

## Verificar o acesso

De volta ao PlaidCloud, introduza os valores e clique em **Testar ligação**. Cada conjunto de dados aparece como **Legível**, **Permissão em falta** ou **Erro**:

| Conjunto de dados | Serviço de que necessita |
|---|---|
| Entidades | `API_COMPANYCODE_SRV` |
| Plano de contas | `API_GLACCOUNTINCHARTOFACCOUNTS_SRV` |
| Departamentos | `API_COSTCENTER_SRV` |
| Clientes | `API_BUSINESS_PARTNER` |
| Produtos | `API_PRODUCT_SRV` |
| Taxas de câmbio | `API_EXCHANGERATE_SRV` |
| Calendário fiscal | `API_FISCALYEARPERIODFORVARIANT_SRV` |
| Razão geral | `API_JOURNALENTRYITEMBASIC_SRV` |
| Balancete | `API_JOURNALENTRYITEMBASIC_SRV` |
| Linhas de vendas | `API_BILLING_DOCUMENT_SRV` (opcional) |

Quando um conjunto de dados mostra **Permissão em falta**, peça ao administrador que adicione o acordo de comunicação do respetivo serviço e teste novamente. As linhas de vendas, o orçamento e os saldos de inventário são opcionais: um inquilino que não contenha algum deles carrega na mesma tudo o resto.
