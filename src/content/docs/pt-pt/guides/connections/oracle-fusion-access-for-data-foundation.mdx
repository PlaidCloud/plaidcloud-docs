O [Data Foundation](/pt-pt/guides/projects/data-foundation/) reúne os dados de todos os sistemas ERP e instâncias que ligar num único Common Finance Model, e o Oracle Fusion Cloud ERP é um dos ERP que lê diretamente. A ligação Oracle Fusion utiliza credenciais de cliente OAuth 2.0, um utilizador de integração só de leitura e um pequeno conjunto de relatórios BI Publisher. Esta página destina-se ao administrador do Oracle Fusion que faz essa configuração e ao utilizador do PlaidCloud que lha pede.

O PlaidCloud só lê dados. Ninguém envia uma palavra-passe ou um segredo do cliente por email.

## Enviar o pedido de acesso

No separador **Base** do projeto, escolha **Criar uma nova ligação** em **Ligação Oracle Fusion**. O formulário mostra o pedido completo. Clique em **Copiar pedido** para o colar na sua própria mensagem, ou em **Enviar pedido por email** para o abrir no seu programa de correio com o assunto "Read-only Oracle Fusion Cloud ERP access for PlaidCloud (OAuth 2.0 client credentials)."

## O que o administrador do Oracle Fusion configura

<Steps>

1. **Criar um utilizador de integração** e atribuir-lhe uma função de trabalho que possa ver, para cada razão sobre o qual reporta:

   - Razão geral: razões, calendários contabilísticos e estados de período, lotes de diário, diários e saldos de contas (por exemplo, "General Accountant" com acesso de dados a esses razões)
   - Taxas de conversão de moeda (taxas diárias)
   - Etiquetas de segmentos de key flexfields, conjuntos de valores e respetiva hierarquia de contas (árvores)
   - Contas a receber: faturas e respetivas distribuições, e contas de clientes
   - Artigos de inventário
   - Acesso de execução aos relatórios BI Publisher do passo 3 e ao ERP Integration Service (tarefas ESS)

2. **Registar uma aplicação confidencial** no domínio de identidade (IAM) com a concessão de credenciais de cliente e o âmbito da REST API do Fusion Applications. Copie o respetivo ID do cliente e o segredo.

3. **Implementar nove relatórios BI Publisher** em `/Custom/PlaidCloud/DataFoundation`. Cada um é executado como uma tarefa ESS, com o nome do relatório como definição da tarefa, e devolve um CSV com as colunas indicadas no pedido:

   | Relatório | O que devolve |
   |---|---|
   | `PlaidCloudKeyFlexLabels` | Uma linha por segmento de cada plano de contas do razão geral: a sua posição, a sua etiqueta e o seu conjunto de valores |
   | `PlaidCloudSegmentValues` | Todos os valores desses conjuntos de valores, com o tipo de conta natural e a hierarquia de valores |
   | `PlaidCloudCalendar` | Os períodos contabilísticos de cada razão, com os tipos de taxa de média do período e de fim de período do razão |
   | `PlaidCloudCodeCombinations` | As combinações de código e os respetivos segmentos |
   | `PlaidCloudBalances` | Os saldos de abertura de cada razão |
   | `PlaidCloudJournalLines` | As linhas de diário, lidas por razão, período e valor de segmento de balanceamento de cada vez |
   | `PlaidCloudCustomers` | As contas de clientes e os nomes das respetivas partes |
   | `PlaidCloudItems` | Os artigos da organização de inventário principal |
   | `PlaidCloudSalesLines` | Uma linha por linha de fatura de Contas a receber |

   As colunas exatas de cada relatório constam do texto do pedido no separador **Base**. Indique os nomes dos relatórios exatamente como apresentados.

</Steps>

## O que enviar de volta

| O administrador envia | Introduzido no PlaidCloud como |
|---|---|
| O anfitrião do URL do seu Fusion Applications, sem `https://` | **Anfitrião do pod** |
| O URL do token do domínio de identidade | **Token URL** |
| O âmbito da aplicação da REST API | **Âmbito** |
| O ID do cliente do passo 2 | **ID do cliente** |
| O segredo do cliente do passo 2 | **Segredo do cliente** |
| Os valores de segmento de balanceamento que o PlaidCloud pode ler | Em **Balancing segment values**, que o Fusion não consegue listar: introduza um valor em **Nome**, ou deixe em branco para carregar todos |

A lista final do pedido solicita estes valores em conjunto. Partilhe o segredo do cliente através do seu gestor de palavras-passe, não por email. A equipa do utilizador do PlaidCloud cola-o no PlaidCloud por si própria.

## Verificar o acesso

De volta ao PlaidCloud, introduza os valores e clique em **Testar ligação**. Cada conjunto de dados aparece como **Legível**, **Permissão em falta** ou **Erro**:

| Conjunto de dados | Lido a partir de |
|---|---|
| Entidades, Calendário fiscal, Plano de contas, Departamentos | Os razões, mais os relatórios de etiquetas de key flexfields, valores de segmento e calendário |
| Taxas de câmbio | Taxas de conversão diárias |
| Razão geral | Lotes de diário e o relatório de linhas de diário |
| Balancete | Os relatórios de saldos e de combinações de código |
| Clientes, Produtos, Linhas de vendas | Os relatórios de clientes, artigos e linhas de vendas (opcional) |

Quando falta um conjunto de dados, o teste indica que permissão deve ser adicionada. Peça ao administrador que a adicione à função de trabalho e teste novamente. Os clientes, os produtos e as linhas de vendas são opcionais: um pod do Fusion que não os contenha carrega na mesma tudo o resto.
