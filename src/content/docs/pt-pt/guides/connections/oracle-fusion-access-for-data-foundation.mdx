O [Data Foundation](/pt-pt/guides/projects/data-foundation/) reúne os dados de todos os sistemas ERP e instâncias que ligar num único Common Finance Model, e o Oracle Fusion Cloud ERP é um dos ERP que lê diretamente. A ligação Oracle Fusion utiliza credenciais de cliente OAuth 2.0, um utilizador de integração só de leitura e um pequeno conjunto de relatórios BI Publisher. Esta página destina-se ao administrador do Oracle Fusion que faz essa configuração e ao utilizador do PlaidCloud que lha pede.

O PlaidCloud só lê dados. Ninguém envia uma palavra-passe ou um segredo do cliente por email.

## Enviar o pedido de acesso

Na página **Sistemas** do projeto, em **Data Foundation** no **Início**, escolha o seu sistema em **Sistema**, em **Adicionar um sistema**, e clique em **Ainda não tem acesso?**. O sistema fica a aguardar acesso e é apresentado um único pedido que abrange os sistemas do projeto. Clique em **Copiar pedido** para o colar na sua própria mensagem ou em **Enviar pedido por email** para o abrir no seu programa de correio com o assunto "Acesso ao PlaidCloud."

## O que o administrador do Oracle Fusion configura

<Steps>

1. **Criar um utilizador de integração** e atribuir-lhe uma função de trabalho personalizada que só possa ver, para cada razão sobre o qual reporta. Não utilize uma função que possa introduzir, lançar ou aprovar o que quer que seja, como General Accountant. A função precisa de:

   - Razão geral: razões, calendários contabilísticos e estados de período, lotes de diário, diários e saldos de contas (privilégios de consulta, com acesso de dados a esses razões)
   - Taxas de conversão de moeda (taxas diárias)
   - Etiquetas de segmentos de key flexfields, conjuntos de valores e respetiva hierarquia de contas (árvores)
   - Contas a receber e Contas a pagar: faturas, recebimentos, pagamentos e respetivas distribuições, e contas de clientes e fornecedores
   - Contas bancárias do Cash Management
   - Artigos de inventário e quantidades disponíveis
   - Para cada relatório opcional que implementar, o acesso só de visualização correspondente: Purchasing (View Purchase Order, `PO_VIEW_PURCHASE_ORDER_PRIV`, e consulta de receções, com acesso de dados às unidades de negócio de aprovisionamento), Fixed Assets (consulta de ativos, com acesso de dados aos livros de ativos corporativos e fiscais), Cost Management (Review Item Costs, com acesso de dados às organizações de custos) e Budgets (consulta de saldos orçamentais do razão geral)
   - Acesso de execução aos relatórios BI Publisher do passo 3 e ao ERP Integration Service (tarefas ESS)

2. **Registar uma aplicação confidencial** no domínio de identidade (IAM) com a concessão de credenciais de cliente e o âmbito da REST API do Fusion Applications. Copie o respetivo ID do cliente e o segredo.

3. **Implementar os relatórios BI Publisher** em `/Custom/PlaidCloud/DataFoundation`. Cada um é executado como uma tarefa ESS, com o nome do relatório como definição da tarefa, e devolve um CSV com as colunas indicadas no pedido. Os seis primeiros são obrigatórios: o razão é construído a partir deles. Os restantes são opcionais: sem um deles, os dados que contém ficam vazios e nada mais é afetado.

   | Relatório | O que devolve |
   |---|---|
   | `PlaidCloudKeyFlexLabels` | Uma linha por segmento de cada plano de contas do razão geral: a sua posição, a sua etiqueta e o seu conjunto de valores |
   | `PlaidCloudSegmentValues` | Todos os valores desses conjuntos de valores, com o tipo de conta natural e a hierarquia de valores |
   | `PlaidCloudCalendar` | Os períodos contabilísticos de cada razão, com os tipos de taxa de média do período e de fim de período do razão |
   | `PlaidCloudCodeCombinations` | As combinações de código e os respetivos segmentos |
   | `PlaidCloudBalances` | Os saldos de cada razão em todos os períodos, incluindo os períodos de ajuste: os saldos de abertura e o saldo de fim de mês com que o razão é comparado |
   | `PlaidCloudJournalLines` | As linhas de diário, lidas por razão, período e valor de segmento de balanceamento de cada vez, com quem introduziu e aprovou cada diário, quando, e o diário que estorna |
   | `PlaidCloudCustomers` | As contas de clientes e os nomes das respetivas partes (opcional) |
   | `PlaidCloudItems` | Os artigos da organização de inventário principal (opcional) |
   | `PlaidCloudSalesLines` | Uma linha por linha de fatura de Contas a receber (opcional) |
   | `PlaidCloudSites` | Os valores do segmento `GL_SITE` (opcional) |
   | `PlaidCloudSuppliers` | Os fornecedores (opcional) |
   | `PlaidCloudArDocuments`, `PlaidCloudReceipts` | As transações de Contas a receber e o que lhes foi aplicado, para itens em aberto e pagamentos (opcional) |
   | `PlaidCloudApInvoices`, `PlaidCloudApPayments` | As faturas de Contas a pagar e o que lhes foi aplicado, para itens em aberto e pagamentos (opcional) |
   | `PlaidCloudApInvoiceLines` | Uma linha por linha de fatura de Contas a pagar (opcional) |
   | `PlaidCloudBankBalances` | O saldo próprio de cada conta bancária no fim de cada mês (opcional) |
   | `PlaidCloudInventory` | A quantidade disponível e o valor de cada artigo e subinventário no fim de cada mês (opcional) |
   | `PlaidCloudBudget` | O orçamento aprovado por mês (opcional) |
   | `PlaidCloudPurchaseOrders`, `PlaidCloudPurchaseOrderEvents` | As linhas de encomendas de compra e as respetivas receções e faturas correspondentes (opcional) |
   | `PlaidCloudAssets`, `PlaidCloudAssetMovements` | O registo de ativos do livro corporativo e os movimentos de cada ativo nos livros corporativo e fiscal (opcional) |
   | `PlaidCloudStandardCosts` | O custo-padrão de cada artigo por mês (opcional) |

   As colunas exatas de cada relatório constam do texto do pedido de acesso. Indique os nomes dos relatórios exatamente como apresentados. Se implementou `PlaidCloudBalances` ou `PlaidCloudApInvoices` para uma versão anterior, alargue-os conforme descrito no pedido: `PlaidCloudBalances` tem agora de devolver todos os períodos com a respetiva atividade.

</Steps>

## O que enviar de volta

| O administrador envia | Introduzido no PlaidCloud como |
|---|---|
| O anfitrião do URL do seu Fusion Applications, sem `https://` | **Anfitrião do pod** |
| O URL do token do domínio de identidade | **URL do token do domínio de identidade** |
| O âmbito da aplicação da REST API | **Âmbito** |
| O ID do cliente do passo 2 | **ID do cliente** |
| O segredo do cliente do passo 2 | **Segredo do cliente** |
| Os valores de segmento de balanceamento que o PlaidCloud pode ler | Em **Opções**, **Empresas**, que o Fusion não consegue listar: introduza os valores, separados por vírgulas, ou deixe vazio para carregar todos |

A lista final do pedido solicita estes valores em conjunto. Partilhe o segredo do cliente através do seu gestor de palavras-passe, não por email. A equipa do utilizador do PlaidCloud cola-o no PlaidCloud por si própria.

## Verificar o acesso

De volta ao PlaidCloud, depois de o sistema ser adicionado, clique em **Testar ligação** na respetiva linha da página **Sistemas**. O teste lê um objeto para cada conjunto de dados obrigatório e apresenta cada conjunto de dados como **Legível**, **Permissão em falta** ou **Erro**. Os próprios relatórios são executados no primeiro carregamento, e os opcionais não fazem parte do teste: um que esteja em falta, ou que o utilizador não possa executar, é indicado no carregamento seguinte.

| Conjunto de dados | O teste lê |
|---|---|
| Entidades, Calendário fiscal, Plano de contas, Departamentos, Balancete | Os razões |
| Taxas de câmbio | Taxas de conversão diárias |
| Razão geral | Lotes de diário |

Quando falta um conjunto de dados, o teste indica que permissão deve ser adicionada. Peça ao administrador que a adicione à função de trabalho e teste novamente. Um pod do Fusion sem um relatório opcional carrega na mesma tudo o resto: os clientes, os produtos, os sites e os fornecedores são carregados vazios, e qualquer outro conjunto de dados mantém o que um carregamento anterior trouxe até ser possível ler novamente o relatório.

O Oracle Fusion não tem nenhuma lista de centros de lucro que o Data Foundation leia. O centro de lucro de uma linha de diário é o segmento de gestão do respetivo plano de contas.
