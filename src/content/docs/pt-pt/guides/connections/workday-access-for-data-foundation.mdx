O [Data Foundation](/pt-pt/guides/projects/data-foundation/) reúne os dados de todos os sistemas ERP e instâncias que ligar num único Common Finance Model. O Workday é um dos sistemas que lê diretamente. O Workday não tem serviço Web para linhas de diário nem para saldos, pelo que esta página se destina ao administrador do Workday que constrói os relatórios que o PlaidCloud lê e ao utilizador do PlaidCloud que lho pede.

O PlaidCloud só lê dados. Ninguém envia uma palavra-passe por email.

## Enviar o pedido de acesso

No separador **Base** do projeto, escolha **Criar uma nova ligação** e selecione **Workday**. O formulário mostra a especificação dos relatórios. Clique em **Copiar pedido** para a colar na sua própria mensagem, ou em **Enviar pedido por email** para a abrir no seu programa de correio.

## O que o administrador do Workday configura

<Steps>

1. **Construir dez relatórios personalizados (RaaS)**, quatro dos quais opcionais, e partilhá-los com o utilizador do sistema de integração. Utilize exatamente os nomes das colunas: o Data Foundation faz o mapeamento por nome, pelo que uma coluna com outro nome não pode ser lida. Todas as colunas de código são o Reference ID do objeto, não um descritor como "C100 Acme US". O formato de saída de todos os relatórios é JSON.

2. **Conceder os serviços Web do Financial_Management** `Get_Workday_Companies` e `Get_Currency_Conversion_Rates` ao mesmo utilizador.

3. **Enviar os URL dos relatórios** e os detalhes do utilizador do sistema de integração.

</Steps>

| Relatório | Obrigatório | Conteúdo |
|---|---|---|
| Linhas de diário | Sim | Uma linha por linha de diário lançada. Parâmetros: Company (a empresa da linha, como Reference ID) e Period (o Reference ID do período fiscal). Inclui as worktags Region, Fund, Program e Project, o afiliado intercompanhia, montantes na moeda da transação e do razão, e o livro |
| Saldos iniciais | Sim | Uma linha por empresa, período fiscal e conta do razão: o saldo no início do período. Só são carregadas as contas de Ativo, Passivo e Capital próprio |
| Contas do razão | Sim | Conta, nome, tipo, indicador de intercompanhia, categoria opcional e conta superior |
| Centros de custo | Sim | Centro de custo, nome e superior |
| Períodos fiscais | Sim | Uma linha por empresa e período fiscal, incluindo os períodos de ajustamento, com início, fim e estado |
| Efetivos | Opcional | Trabalhadores ativos no fim de cada período, por centro de custo, com FTE |
| Valores de worktags | Opcional | Uma linha por valor de Region, Fund, Program e Project, com o superior |
| Clientes | Opcional | Cliente, nome, superior, categoria, região e país |
| Artigos de venda | Opcional | Artigo, nome, superior, grupo e unidade de medida |
| Linhas de faturas de venda | Opcional | Uma linha por linha de fatura de cliente, com quantidade, montantes brutos, de desconto, líquidos e de custo |

A lista completa de colunas de cada relatório consta da especificação no separador Base. Aplicam-se algumas regras ao que os relatórios devolvem:

- Só são carregadas as linhas de diário Posted, e apenas o razão Actuals. Os razões Commitment e Obligation não são carregados.
- Um Book_Code em branco é o livro principal. Uma linha em branco conta em todos os livros da sua empresa e período, e uma linha com um Book_Code pertence apenas a esse livro.
- A empresa da linha prevalece sobre a do diário.
- Ledger_Account_Type_ID é Revenue, COGS, Opex, NonOperating, Asset, Liability ou Equity. O Workday tem um único tipo Expense, que é carregado como Opex. Para separar o custo das mercadorias vendidas ou os gastos não operacionais, imprima um campo calculado que devolva COGS ou NonOperating. Uma conta sem tipo não é carregada na demonstração de resultados.
- As faturas Draft, In Progress, Canceled e Denied não são carregadas.
- Os orçamentos são carregados a partir de ficheiros. O Adaptive Planning não está ligado.

## O que enviar de volta

| O administrador envia | Introduzido no PlaidCloud como |
|---|---|
| O anfitrião do Workday | **Anfitrião Workday** |
| O nome do inquilino | **Inquilino** |
| O nome do utilizador do sistema de integração | **Utilizador do sistema de integração** |
| O URL de cada relatório obrigatório | **Journal Lines report URL**, **Beginning Balances report URL**, **Ledger Accounts report URL**, **Cost Centers report URL**, **Fiscal Periods report URL** |
| O URL de cada relatório opcional que construiu | **Headcount report URL (optional)**, **Worktag Values report URL (optional)**, **Customers report URL (optional)**, **Sales Items report URL (optional)**, **Sales Invoice Lines report URL (optional)** |
| Os Reference IDs das empresas que o PlaidCloud pode ler | Escolhidas em **Companies**. Deixe em branco para carregar todas as empresas |

O utilizador do PlaidCloud cola por si próprio a **Palavra-passe** do utilizador do sistema de integração; é um segredo e nunca é enviada por email.

Em **System settings**, **Retained earnings account** indica a conta de Capital próprio (Equity) em que a demonstração de resultados de abertura é agregada, quando os nomes das contas ainda não o dizem. É opcional.

<Aside type="note">
O tipo Expense único do Workday é carregado como Opex, e a verificação de prontidão do Data Foundation assinala-o. Se for necessário distinguir as suas contas de custo das mercadorias vendidas ou não operacionais, utilize o campo calculado descrito acima.
</Aside>

## Verificar o acesso

De volta ao PlaidCloud, clique em **Testar ligação**. Cada conjunto de dados aparece como **Legível**, **Permissão em falta** ou **Erro**:

| Conjunto de dados | Provém de |
|---|---|
| Entidades | `Get_Workday_Companies` |
| Plano de contas | O relatório Contas do razão |
| Departamentos | O relatório Centros de custo |
| Calendário fiscal | O relatório Períodos fiscais |
| Taxas de câmbio | `Get_Currency_Conversion_Rates` |
| Balancete | O relatório Saldos iniciais |
| Razão geral | O relatório Linhas de diário |
| Indutores de alocação (opcional) | O relatório Efetivos |
| Valores de segmento (opcional) | O relatório Valores de worktags |
| Clientes (opcional) | O relatório Clientes |
| Produtos (opcional) | O relatório Artigos de venda |
| Linhas de vendas (opcional) | O relatório Linhas de faturas de venda |

Quando um conjunto de dados mostra **Permissão em falta**, o teste indica o relatório ou o serviço Web. Peça ao administrador que o partilhe com o utilizador do sistema de integração e teste novamente. Um inquilino sem os relatórios opcionais carrega na mesma tudo o resto.
