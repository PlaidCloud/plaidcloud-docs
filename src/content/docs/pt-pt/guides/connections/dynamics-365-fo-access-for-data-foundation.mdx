O [Data Foundation](/pt-pt/guides/projects/data-foundation/) reúne os dados de todos os sistemas ERP e instâncias que ligar num único Common Finance Model, e o Dynamics 365 Finance and Operations é um dos ERP que lê diretamente. A ligação utiliza uma aplicação Microsoft Entra ID com um segredo do cliente para os dados mestre e o ponto final SQL do seu Fabric (Synapse) Link para o diário geral, os razões auxiliares e os saldos bancários. Esta página destina-se ao administrador do Dynamics 365 que faz essa configuração e ao utilizador do PlaidCloud que lha pede.

O PlaidCloud só lê dados. Ninguém envia um segredo do cliente nem uma palavra-passe SQL por email.

## Enviar o pedido de acesso

Na página **Sistemas** do projeto, em **Data Foundation** no **Início**, escolha o seu sistema em **Sistema**, em **Adicionar um sistema**, e clique em **Ainda não tem acesso?**. O sistema fica a aguardar acesso e é apresentado um único pedido que abrange os sistemas do projeto. Clique em **Copiar pedido** para o colar na sua própria mensagem ou em **Enviar pedido por email** para o abrir no seu programa de correio com o assunto "Acesso ao PlaidCloud."

## O que o administrador do Dynamics 365 configura

<Steps>

1. **Registar uma aplicação no Microsoft Entra ID** para o PlaidCloud, com um segredo do cliente. Tome nota do respetivo ID da aplicação (cliente), do ID do diretório (inquilino) e do segredo.

2. **Associar a aplicação a um utilizador.** No Dynamics 365, em **System administration > Setup > Microsoft Entra ID applications**, adicione o ID do cliente e associe-o a um utilizador com uma função que possa ver, para cada entidade legal que pretende carregar:

   - Razão geral: entidades legais, calendários fiscais, contas principais, valores de dimensões financeiras, taxas de câmbio
   - Contas a receber: clientes e linhas de faturas de clientes
   - Contas a pagar: fornecedores (opcional)
   - Gestão de informação de produtos: produtos libertados
   - Gestão de inventário: existências disponíveis e transações de inventário (opcional)
   - Orçamentação: lançamentos do registo de orçamento (opcional)

3. **Configurar o Fabric Link para o diário geral.** As linhas do diário geral são lidas a partir do ponto final SQL do seu Fabric (Synapse) Link, não do serviço OData. Confirme que o Fabric Link está ativo para estas tabelas e crie nesse ponto final um início de sessão SQL só de leitura para o PlaidCloud:

   - `generaljournalaccountentry`
   - `generaljournalentry`
   - `fiscalcalendarperiod`
   - `dimensionattributelevelvalue`, com uma linha por cada valor de dimensão de cada combinação de dimensões financeiras e o nome da respetiva dimensão
   - para itens em aberto e pagamentos (opcional): `custtrans`, `vendtrans`, `custsettlement`, `vendsettlement`
   - para linhas de faturas de fornecedores (opcional): `vendinvoicetrans`, `vendinvoicejour`
   - para saldos bancários (opcional): `bankaccounttrans`, `bankaccounttable`

   Os sites e os centros de lucro são os valores das dimensões financeiras `Site` e `BusinessUnit`.

</Steps>

## O que enviar de volta

| O administrador envia | Introduzido no PlaidCloud como |
|---|---|
| O URL do ambiente, `https://<name>.operations.dynamics.com` | **URL do ambiente** |
| O ID do diretório (inquilino) | **ID do inquilino Azure AD** |
| O ID da aplicação (cliente) | **ID do cliente** |
| O `dataAreaId` de uma entidade legal | **Entidade legal / Empresa (dataAreaId)**: a ligação precisa de uma, e o Data Foundation lê as entidades legais escolhidas em **Empresas** |
| O ponto final SQL, a base de dados e o início de sessão do Fabric Link | Uma ligação SQL separada no PlaidCloud, cujo ID de ligação é indicado na definição de sistema **Fabric Link SQL connection (its connection ID)** |
| As categorias de conta principal das suas contas de custo das vendas (o PlaidCloud assume `COGS`) | A definição de sistema **Cost of goods sold main account categories** |
| As categorias de conta principal das contas que não são operacionais: juros, imposto sobre o rendimento, ganhos e perdas cambiais, outros rendimentos | A definição de sistema **Non-operating main account categories** |
| A dimensão financeira que nomeia o parceiro intercompanhia de uma linha (o PlaidCloud assume `IntercompanyPartner`) | A definição de sistema **Intercompany partner dimension** |
| As entidades legais que o PlaidCloud pode ler | Em **Opções**, **Empresas**: assinale-as, ou nenhuma para todas |

O segredo do cliente e a palavra-passe do início de sessão SQL nunca são enviados por email. A equipa do utilizador do PlaidCloud cola o **Segredo do cliente** no PlaidCloud por si própria, e a ligação SQL guarda o início de sessão SQL. As entidades legais que são entidades de consolidação ficam na definição de sistema **Consolidation legal entities**, para que os seus lançamentos não sejam contados como atividade de uma empresa.

## Verificar o acesso

De volta ao PlaidCloud, depois de o sistema ser adicionado, clique em **Testar ligação** na respetiva linha da página **Sistemas**. Cada conjunto de dados aparece como **Legível**, **Permissão em falta** ou **Erro**:

| Conjunto de dados | Permissão de que necessita |
|---|---|
| Entidades | Razão geral: Ver entidades legais |
| Calendário fiscal | Razão geral: Ver calendários fiscais |
| Plano de contas | Razão geral: Ver contas principais |
| Departamentos | Razão geral: Ver valores de dimensões financeiras |
| Clientes | Contas a receber: Ver clientes |
| Produtos | Gestão de informação de produtos: Ver produtos libertados |
| Taxas de câmbio | Razão geral: Ver taxas de câmbio |
| Balancete, Razão geral | Ver o razão geral (o diário, através do Fabric Link) |
| Todos os outros conjuntos de dados | Opcional, não fazem parte do teste |

Quando falta um conjunto de dados, o teste indica a permissão a adicionar. Peça ao administrador que a adicione à função e teste novamente.

Os conjuntos de dados opcionais são os sites, os centros de lucro, os fornecedores, as linhas de vendas, os saldos de inventário, os orçamentos, os saldos bancários, as linhas de faturas de fornecedores, os itens em aberto e os pagamentos. Um ambiente que não contenha um deles carrega na mesma tudo o resto. Os saldos bancários, as linhas de faturas de fornecedores, os itens em aberto ou os pagamentos de um mês que não possam ser lidos a partir do Fabric Link mantêm as linhas que já tinham e são lidos novamente no carregamento seguinte.

O Dynamics 365 não tem nenhum objeto de saldos que a ligação possa ler, pelo que não é carregado nenhum saldo de fim de mês: o razão é comparado com o seu próprio balancete.
