O [Data Foundation](/pt-pt/guides/projects/data-foundation/) reúne os dados de todos os sistemas e instâncias ERP que ligar num único Common Finance Model, e o Microsoft Dynamics 365 Business Central é um dos ERP que lê diretamente. A ligação utiliza uma aplicação Microsoft Entra ID com credenciais de cliente, um conjunto de permissões só de leitura e alguns objetos de página publicados como serviços Web. Esta página destina-se ao administrador do Business Central que efetua essa configuração e ao utilizador do PlaidCloud que lha pede.

O PlaidCloud apenas lê dados. Ninguém envia um segredo do cliente por email.

## Enviar o pedido de acesso

Na página **Sistemas** do projeto, em **Data Foundation** no **Início**, escolha o seu sistema em **Sistema**, em **Adicionar um sistema**, e clique em **Ainda não tem acesso?**. O sistema fica a aguardar acesso e é apresentado um único pedido que abrange os sistemas do projeto. Clique em **Copiar pedido** para o colar na sua própria mensagem ou em **Enviar pedido por email** para o abrir no seu programa de correio com o assunto "Acesso ao PlaidCloud."

## O que o administrador do Business Central configura

<Steps>

1. **Registe uma aplicação no Microsoft Entra ID.** Em **App registrations > New registration**, adicione um segredo do cliente e anote o ID do diretório (inquilino), o ID da aplicação (cliente) e o segredo.

2. **Adicione a aplicação no Business Central.** Abra **Microsoft Entra Applications**, adicione a aplicação, defina o seu estado como **Ativado** e atribua-lhe apenas o conjunto de permissões **D365 READ**, para todas as empresas sobre as quais elabora relatórios. Este lê todas as páginas abaixo. Não lhe atribua **D365 BASIC** nem qualquer outro conjunto de permissões que permita escrever.

3. **Publique objetos de página como serviços Web.** Em **Search > Web Services > New**, publique estes objetos de página com exatamente estes nomes de serviço e com **Published** assinalado. A API padrão não inclui os respetivos campos:

   | Página | Nome do serviço | Notas |
   |---|---|---|
   | 20 G/L Entries | `GLEntries` | |
   | 16 Chart of Accounts | `GLAccounts` | |
   | 100 Accounting Periods | `AccountingPeriods` | |
   | 537 Dimension Values | `DimensionValues` | |
   | 240 Business Units | `BusinessUnits` | |
   | 605 IC Partner List | `ICPartners` | |
   | 5802 Value Entries | `ValueEntries` | Custo das vendas e saldos de inventário; opcional |
   | 120 G/L Budget Entries | `GLBudgetEntries` | Orçamentos; opcional |
   | Statistical Ledger Entries | `StatisticalLedgerEntries` | Indutores estatísticos; opcional |
   | 118 General Ledger Setup | `GeneralLedgerSetup` | Dimensões de atalho 3 a 8; opcional |
   | 479 Dimension Set Entries | `DimensionSetEntries` | Dimensões de atalho 3 a 8; opcional |
   | 573 Detailed Cust. Ledg. Entries | `DetailedCustLedgEntries` | Itens em aberto e pagamentos; opcional |
   | 574 Detailed Vendor Ledg. Entries | `DetailedVendorLedgEntries` | Itens em aberto e pagamentos; opcional |
   | 371 Bank Account List | `BankAccounts` | Saldos bancários; opcional |
   | 277 Bank Account Posting Groups | `BankAccountPostingGroups` | Saldos bancários; opcional |
   | Inventory Posting Setup (pesquise a respetiva página) | `InventoryPostingSetup` | A conta das linhas de compra de um artigo; opcional |

4. **Indique ao utilizador do PlaidCloud três opções:** o código de origem sob o qual são lançados os seus ajustes de auditoria (o PlaidCloud assume `ADJUSTMENT`), qual a dimensão que corresponde ao seu departamento (o PlaidCloud assume a Global Dimension 1, com o nome `DEPARTMENT`) e qual corresponde ao seu centro de lucro (o PlaidCloud assume a Global Dimension 2, com o nome `PROFITCENTER`). Um site é uma localização do Business Central.

</Steps>

## O que enviar de volta

| O administrador envia | Introduzido no PlaidCloud como |
|---|---|
| O ID do diretório (inquilino) | **ID do inquilino Azure AD** |
| O ID da aplicação (cliente) | **ID do cliente** |
| O segredo do cliente | **Segredo do cliente**, introduzido no editor de ligações, não por email |
| O nome do ambiente, por exemplo `production` | **Ambiente** |
| O ID de uma empresa | **ID da empresa**: a ligação precisa de um, e o Data Foundation lê as empresas escolhidas em **Empresas** |
| O nome da dimensão que corresponde ao seu departamento | A definição de sistema **Department dimension** |
| O nome da dimensão que corresponde ao seu centro de lucro | A definição de sistema **Profit centre dimension** |
| O código de origem sob o qual são lançados os seus ajustes de auditoria | A definição de sistema **Audit adjustment source code** |
| As empresas que o PlaidCloud pode ler | Em **Opções**, **Empresas**: assinale-as, ou nenhuma para todas as empresas |

As empresas que são empresas de consolidação são indicadas na definição de sistema **Consolidation companies**, para que os seus lançamentos não sejam contabilizados como atividade de uma empresa. As taxas de câmbio provêm de uma única empresa: indique-a na definição de sistema **Exchange rate company** ou o PlaidCloud utiliza a primeira empresa.

## Verificar o acesso

De volta ao PlaidCloud, depois de o sistema ser adicionado, clique em **Testar ligação** na respetiva linha da página **Sistemas**. Cada conjunto de dados é apresentado como **Legível**, **Permissão em falta** ou **Erro**:

| Conjunto de dados | O que requer |
|---|---|
| Entidades, Plano de contas, Clientes, Produtos, Taxas de câmbio, Balancete | Acesso à API (conjunto de permissões D365 READ) |
| Calendário fiscal | O serviço Web `AccountingPeriods` |
| Departamentos | O serviço Web `DimensionValues` |
| Razão geral | O serviço Web `GLEntries` |
| Todos os outros conjuntos de dados | Opcional, não fazem parte do teste |

Quando falta um conjunto de dados, o teste indica qual a permissão ou o serviço Web a adicionar. Peça ao administrador que o adicione e teste novamente.

Os conjuntos de dados opcionais são os sites, os centros de lucro, os fornecedores, o saldo de fim de mês, os saldos bancários, os saldos de inventário, as linhas de vendas, as linhas de faturas de fornecedores, os itens em aberto, os pagamentos, os orçamentos e os indutores de alocação. Um ambiente que não utilize um deles continua a carregar tudo o resto e, após o carregamento seguinte, as verificações de prontidão, no painel de controlo **CFM-Accounting - Close and assurance**, indicam qualquer página que o Business Central recuse. O saldo de fim de mês é o balancete no fim de cada mês; os saldos bancários são esse saldo para as contas onde as suas contas bancárias lançam. Quando o Business Central recusa uma leitura a partir da qual são construídos o saldo de fim de mês, os saldos bancários, o inventário, as linhas de vendas, as linhas de faturas de fornecedores, os itens em aberto ou os pagamentos de um mês, esse mês mantém as linhas que já tinha e é lido novamente no carregamento seguinte.
