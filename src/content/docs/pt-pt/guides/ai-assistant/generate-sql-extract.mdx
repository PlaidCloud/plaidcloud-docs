## Descrição

O passo **Extrair SQL** de um fluxo de trabalho executa um `SELECT` só de leitura sobre os dados
do seu projeto e escreve o resultado numa nova tabela. Escrever essa consulta à mão exige
conhecer as tabelas de origem, as respetivas colunas e o SQL para lhes dar forma.

O editor de passos pode escrever a consulta por si. Descreva o resultado que pretende em
linguagem corrente e o AI Assistant produz o `SELECT` — e se não lhe indicar
de que tabelas ler, examina as tabelas do projeto e escolhe ele próprio as
relevantes. O SQL gerado e as colunas detetadas são apresentados para
revisão e permanecem totalmente editáveis antes de guardar o passo.

<Aside type="note">
Isto usa o mesmo modelo integrado que o AI Assistant usa — **não há nada a
configurar**. Não precisa de configurar um agente de IA nem uma ligação a um LLM por área de trabalho
para isto.
</Aside>

## Abrir o passo

Na vista **Passos** de um fluxo de trabalho, clique em **Criar passo** e escolha uma das opções:

- **Tabelas → Extrair SQL**, ou
- **AI → SQL Extract (AI Assisted)**

Ambas abrem o mesmo editor de passos Extrair SQL, que inclui agora um painel **Generate SQL
with AI** no topo da página Parâmetros de extração SQL.

## Gerar a consulta

1. **(Opcional) Escolha as tabelas de origem.** Na lista **Tabelas de origem**, selecione uma
   ou mais tabelas de que a consulta deve ler. Deixe a lista vazia para que o
   Assistant examine o projeto e escolha por si as tabelas relevantes.
2. **Descreva o que pretende.** Na caixa **Descrever**, escreva o resultado em linguagem
   corrente — por exemplo, *"classificar cada conta do razão num conjunto de atividade
   com base no intervalo do respetivo número de conta"*.
3. **Clique em Gerar SQL.** O Assistant escreve um único `SELECT` só de leitura,
   valida-o executando-o e preenche:
   - o editor **Consulta SQL Select** com a instrução gerada, e
   - a página de mapeamento **Seleção de dados da tabela** com as colunas detetadas.

   Se deixou a lista de origem vazia, as tabelas que o Assistant escolheu são
   selecionadas de volta na lista para que veja o que usou e possa ajustar.

## Rever e guardar

O SQL gerado é um ponto de partida, não uma caixa negra:

- **Edite-o livremente.** O editor de SQL é totalmente editável — refine a consulta, adicione uma
  junção ou altere a lista de colunas antes de guardar. (Para unir várias tabelas, pode
  selecionar várias tabelas de origem ou simplesmente editar a consulta gerada.)
- **Escolha uma tabela de destino.** Escolha ou dê um nome à **Tabela de destino** onde o passo escreve
  o resultado.
- **Guarde o passo.** É guardado como um passo Extrair SQL normal e é executado como parte
  do fluxo de trabalho como qualquer outro.

<Aside type="tip">
Se o Assistant devolver uma consulta que não executa, o editor continua a mostrar o SQL
juntamente com o erro, para que a possa corrigir — ou ajustar a sua descrição e
gerar de novo.
</Aside>

## Notas e limites

- O Assistant só escreve instruções `SELECT` **só de leitura**; nunca produz
  `INSERT`, `UPDATE`, `DELETE` nem outro SQL que altere dados.
- A geração **não cria nem executa** o passo — apenas elabora um rascunho da consulta e
  pré-visualiza as colunas. O passo é criado quando o guarda e é executado quando o
  fluxo de trabalho é executado.
- A consulta gerada lê-se com os **nomes de apresentação** das suas tabelas — cada tabela é
  associada uma só vez no topo da consulta com o seu nome (pelo que as colunas, junções e
  filtros se leem com nomes simples e não com ids internos `analyzetable_…`).
  Os identificadores reais são repostos automaticamente quando guarda, pelo que a consulta
  é executada sem alterações. Uma tabela cujo nome não é único mantém o seu identificador.
