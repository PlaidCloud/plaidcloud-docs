Sempre que uma tabela é escrita, o lakehouse do PlaidCloud mantém um **instantâneo** da tabela nesse momento — uma cópia consistente dos dados num determinado ponto no tempo. Os instantâneos permitem ver o que uma tabela continha anteriormente, recuperar de uma carga incorreta e auditar a forma como uma tabela mudou ao longo do tempo. O período a que pode recuar é definido pela definição de viagem no tempo da tabela: 1 dia por predefinição e até 90 dias para a predefinição do projeto ou para uma tabela que a alargue. Consulte [Gerir o armazenamento](/pt-pt/guides/projects/managing-storage/).

O painel Instantâneos permite consultar esse histórico, abrir qualquer instantâneo só de leitura no Explorador de tabelas e reverter ou restaurar a tabela para um instantâneo anterior.

## Abrir o painel Instantâneos

Na lista **Tabelas** do projeto, clique no botão de instantâneo/flashback na linha de uma tabela. O painel **Instantâneos** é aberto e apresenta os instantâneos da tabela, do mais recente para o mais antigo:

- **Quando** — a data e a hora a que o instantâneo foi criado.
- **Linhas** — o número de linhas da tabela nesse instantâneo.
- **Δ Linhas** — a variação do número de linhas em comparação com o instantâneo anterior, para ver o que cada escrita acrescentou ou removeu.
- **Tamanho** — o tamanho de armazenamento comprimido do instantâneo.
- **Etiqueta** — um nome, para instantâneos a que atribuiu nome ou que fixou.
- **Retido** — um marcador de fixação para instantâneos que estão retidos (mantidos para além do período de retenção normal).

## Ver os dados num instantâneo

Existem duas formas de ver os dados de uma tabela num momento anterior. Ambas abrem o Explorador de tabelas numa **vista histórica só de leitura**, com uma faixa a indicar o instantâneo que está a ver e um botão **Voltar aos dados atuais**.

1. **No painel Instantâneos** — selecione um instantâneo e clique em **Ver no instantâneo**.
2. **No Explorador de tabelas** — utilize a lista pendente **As of** na barra de ferramentas. Apresenta os instantâneos recentes da tabela; escolha um para mudar a vista ou escolha **Atual (dados em direto)** para voltar aos dados em direto.

<Aside>A vista histórica é só de leitura — é uma janela para o passado, não uma cópia editável. Utilize **Reverter** ou **Restaurar** (abaixo) se pretender repor dados antigos numa tabela.</Aside>

## Reverter ou restaurar um instantâneo

Selecione um instantâneo e clique em **Reverter / Restaurar**. A caixa de diálogo oferece duas opções:

- **Revert this table in place** (predefinição) — substitui os dados atuais da tabela pelos do instantâneo. Como esta ação é destrutiva, tem de escrever o nome da tabela para confirmar. Antes de os dados serem substituídos, o PlaidCloud captura automaticamente um **instantâneo de segurança anterior à reversão** do estado atual (nos motores de armazenamento que suportam fixação), para que possa sempre voltar ao ponto em que estava. Num lakehouse Databend, se as colunas da tabela tiverem mudado desde o instantâneo, a reversão no local é recusada, com indicação das colunas que mudaram — restaure para uma nova tabela.
- **Restaurar o instantâneo para uma nova tabela** — deixa a tabela original intacta e cria no projeto uma nova tabela (à qual atribui um nome e uma pasta), preenchida a partir do instantâneo, com as mesmas colunas da origem. Através do assistente de IA ou do MCP, uma restauração sem nome indicado recebe um nome baseado na tabela de origem, por exemplo `Sales (restored 3f2a9c1d)`.

<Aside type="caution">Reverter no local substitui os dados atuais da tabela. A confirmação escrita e o instantâneo de segurança automático anterior à reversão existem para o proteger — leia a caixa de diálogo antes de confirmar. A reversão é bloqueada enquanto o projeto estiver bloqueado.</Aside>

<Aside>Através da API REST ou do MCP, restaure um instantâneo no local omitindo a tabela de destino ou indicando a própria tabela. Uma restauração no local nesses casos tem a mesma proteção que a reversão da caixa de diálogo: um instantâneo de segurança anterior à reversão, quando o motor de armazenamento o suporta, e um registo de auditoria. Para que seja recusada se a tabela tiver sido escrita desde que listou os respetivos instantâneos, indique o instantâneo mais recente que viu em `expected_current_snapshot_id`.</Aside>

<Aside>Se uma restauração para uma nova tabela falhar — por exemplo, porque o instantâneo já expirou — nenhuma tabela nova é adicionada ao projeto.</Aside>

## Atribuir nomes, fixar e retenção

Os instantâneos expiram de acordo com a definição de viagem no tempo da tabela (1 dia por predefinição, até 90 dias) na limpeza noturna. A reversão ou restauro funciona até ao ponto restaurável mais antigo apresentado para a tabela. Para manter um instantâneo durante mais tempo:

- **Criar instantâneo** cria, a pedido, um instantâneo retido dos dados atuais — útil antes de uma recarga arriscada (por exemplo, "antes da recarga do T2").
- **Reter** fixa o instantâneo selecionado; **Libertar** remove a retenção e devolve-o ao ciclo de vida normal.

<Aside type="caution">Uma retenção mantém mais do que um único instantâneo — mantém o instantâneo retido *e* todos os instantâneos escritos depois dele, pelo que o armazenamento continua a crescer até libertar a retenção. Substituir uma tabela por completo (um upsert ou uma substituição SCD-2) inicia um histórico de instantâneos totalmente novo, e qualquer retenção no histórico antigo perde-se com ele.</Aside>

Restaurar todas as tabelas de um projeto de uma só vez, através da API REST, restaura cada tabela para o respetivo instantâneo retido mais recente e deixa como estão as tabelas sem retenção. Um instantâneo de segurança anterior à reversão não conta como retenção, embora o painel Instantâneos o possa marcar como retido, a não ser que também retenha esse instantâneo, por exemplo com **Reter**. Os nomes de instantâneos que começam por `pre-revert_` estão reservados para instantâneos de segurança. Se alguma tabela não puder ser restaurada, as restantes são, ainda assim, restauradas, e o pedido falha indicando cada tabela que não foi restaurada e o motivo.

<Aside>A atribuição de nome a um instantâneo a pedido está disponível em tabelas Lakehouse (StarRocks). A retenção e a libertação de um instantâneo funcionam agora também em tabelas com suporte Databend; aí, os instantâneos continuam a ser mantidos durante o período de retenção mesmo sem retenção.</Aside>

## Auditoria

As reversões no local, quer a partir da caixa de diálogo, da API REST ou de um assistente de IA, são registadas no registo de auditoria do lakehouse, incluindo quem efetuou a reversão, quando, o instantâneo para o qual foi revertida e o instantâneo de segurança que foi mantido — pelo que as alterações às tabelas feitas através desta funcionalidade são rastreáveis.
