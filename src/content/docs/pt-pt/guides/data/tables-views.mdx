Os dados e a informação tabulares no PlaidCloud são armazenados em armazéns de dados Greenplum. Isto proporciona uma enorme escalabilidade e desempenho, recorrendo a tecnologia madura e bem conhecida para minimizar o risco de perda ou corrupção de dados.

Além disso, a utilização de um armazém de dados que opera com uma sintaxe comum permite que ferramentas de terceiros se liguem e explorem os dados diretamente. Na prática, isto torna o ecossistema de dados do PlaidCloud aberto e explorável, garantindo ao mesmo tempo segurança e controlos de acesso de topo.

## Tabelas

As tabelas guardam os dados tabulares físicos em todo o PlaidCloud. Cada tabela pode conter muitos terabytes de dados, se necessário. Os dados são armazenados em vários servidores físicos e espelhados automaticamente para garantir a integridade dos dados e a elevada disponibilidade.

As tabelas são constituídas por colunas de vários tipos de dados. Utilizar um tipo de dados adequado pode ajudar ao desempenho e, sobretudo, ao tamanho de armazenamento dos dados. O PlaidCloud consegue comprimir melhor os dados se estes usarem o tipo de dados mais adequado. Normalmente, o PlaidCloud deduz o tipo, mas também é possível alterar os tipos de dados através dos mapeadores de colunas nos passos do fluxo de trabalho.

Pode encontrar tabelas pelo fluxo de trabalho que as utiliza, por um nome de coluna ou por um valor que contenham, e ver quando uma tabela foi lida pela última vez. Consulte [Gerir tabelas e vistas](/pt-pt/guides/projects/managing-tables-and-views/#localizar-tabelas).

## Vistas

As vistas funcionam como tabelas, mas não guardam dados físicos. São representações lógicas de tabelas, obtidas através de uma consulta. A utilização de vistas pode poupar armazenamento.

No entanto, a utilização de vistas tem algumas limitações. Tenha em atenção o seguinte:

 * Desempenho com empilhamento de vistas — o empilhamento de vistas (uma vista de uma vista de uma vista…, etc.) pode afetar o desempenho em tabelas muito grandes ou em cálculos complexos. Pode ser necessário criar tabelas intermédias para melhorar o desempenho.
 * Desempenho em painéis de controlo — embora seja perfeitamente aceitável publicar uma vista para utilização num painel de controlo, para tabelas muito grandes pode preferir publicar uma tabela em vez de uma vista, para uma experiência de utilizador ideal.
 * Dados dinâmicos — os dados de uma vista mudam quando mudam os dados da tabela subjacente a que faz referência. Isto pode ser uma vantagem (tudo é atualizado automaticamente) ou um transtorno inesperado, se o objetivo fosse um conjunto de dados estático.

<Aside>A utilização de vistas pode ajudar a acelerar os fluxos de trabalho, uma vez que não é necessário movimentar dados no momento da execução do fluxo de trabalho.</Aside>

<Aside>Como as vistas não contêm dados, repare que não podem ser usadas como destino de importações. Nesse caso, tem de ser usada uma tabela.</Aside>
