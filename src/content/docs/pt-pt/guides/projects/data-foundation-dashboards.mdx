Cada projeto Data Foundation inclui dezassete painéis de controlo, um conjunto de indicadores e um caminho de análise para cada assunto. Todos leem as mesmas vistas de relatório, que cada **Carregar** preenche a partir do [Common Finance Model](/pt-pt/guides/projects/data-foundation/), pelo que um painel de controlo, um indicador e uma resposta do Weave nunca divergem. Isto aplica-se a um projeto criado a partir de qualquer modelo do Data Foundation, como [Cost to Serve](/pt-pt/guides/projects/cost-to-serve/) ou [Operational Transfer Pricing](/pt-pt/guides/projects/operational-transfer-pricing/). Para verificar se os números que lhes estão subjacentes são fiáveis, consulte [Data Foundation: os números são fiáveis?](/pt-pt/guides/projects/data-foundation-proof/).

## A página Relatórios

**Relatórios**, em **Data Foundation** no início do projeto, lista os painéis de controlo por perfil: **Contabilidade**, **Executivo**, **Finanças**, **Marketing**, **Operações** e **Vendas**. Clique no nome de um painel de controlo para o abrir num novo separador do navegador. Abre no Superset habitual, e nenhum filtro é transportado a partir do projeto. Como a página indica, vê-os se tiver acesso ao projeto.

Um painel de controlo ainda sem dados é listado pelo nome, esbatido, sob uma linha como "3 reports have no data yet", com aquilo que o preencheria: "Fills when a system with pipeline data finishes its load." ou, no caso de um painel de controlo que não lê nenhum assunto em particular, "Fills when your systems finish their first load."

O cartão **Pacote do conselho**, na parte inferior, tem **Abrir o pacote para a administração** assim que o painel de controlo do pacote estiver construído, e **Definições do pacote para a administração**, disponível com acesso de edição ao projeto, que abre as definições descritas em [Pacote para o conselho](/pt-pt/guides/projects/data-foundation/#pacote-para-o-conselho).

## Quando os painéis de controlo são construídos

A instalação do Data Foundation cria as vistas de relatório, e a respetiva mensagem indica quantas vistas de relatório e painéis de controlo instalou e o que fazer a seguir. Os próprios painéis de controlo são construídos no fim de cada **Carregar** e **Aplicar alterações**, pelo respetivo passo **Make the dashboards**, a partir do que essa execução escreveu. Um projeto instalado com os dados de exemplo mostra o exemplo assim que o seu primeiro carregamento termina.

Cada execução posterior reconstrói os painéis de controlo no mesmo local, pelo que as respetivas ligações se mantêm e os dados que chegam mais tarde são preenchidos. O Data Foundation reconstrói um painel de controlo a cada Carregar, incluindo as edições, pelo que deve copiar um painel de controlo no Superset para manter as suas próprias alterações. A linha de contexto no topo de cada painel de controlo diz o mesmo.

A falta de dados nunca é um erro:

- Um gráfico ou mosaico sem dados é omitido e a respetiva linha fecha-se. Um mosaico sem dados pode ceder o seu lugar a outro, como **Owed by customers** em vez de **Net debt** quando nenhuma conta está marcada como empréstimos.
- Um separador em que nenhum gráfico tem dados é omitido. Um painel de controlo cuja **Overview** não tem nada para mostrar não é construído, e **Relatórios** lista-o como ainda sem dados.
- A execução termina com um aviso que indica o painel de controlo e o separador omitido, como "CFM-Sales - Pipeline: the Deals closing tab is left out, as its charts have no data yet."
- Se a geração de relatórios estiver desativada para a sua área de trabalho, não é criado nenhum painel de controlo, e o aviso indica-o.
- Se um painel de controlo criado por outra pessoa já tiver o endereço de que um painel de controlo do Data Foundation precisa, esse painel de controlo é deixado como está, e o aviso indica o endereço. Atribua outro endereço ao outro painel de controlo no Superset.

## Quem os vê

Um painel de controlo assume o [público-alvo predefinido para novos painéis de controlo](/pt-pt/guides/dashboards/control-who-can-see-a-dashboard/#público-alvo-predefinido-para-novos-painéis-de-controlo) do projeto quando é construído pela primeira vez. As reconstruções posteriores mantêm o público-alvo que tiver nessa altura.

Os painéis de controlo são construídos a partir de todas as linhas do projeto, e nunca a partir das linhas que uma pessoa consegue ver. Cada pessoa que abre um painel de controlo vê apenas as linhas que o seu [acesso a linhas](/pt-pt/administration/access/managing-security-groups-and-assignments/#gerir-o-acesso-a-linhas) permite. Quando alguém cujo acesso a linhas restringe o que vê inicia uma reconstrução, os painéis de controlo ficam como o último Carregar os construiu, e a mensagem indica que o próximo Carregar os reconstrói.

## Os dezassete painéis de controlo

Todos os painéis de controlo têm o título **CFM-*persona* - *report***. Abrem em **Overview** e terminam em **Detail**, que lista as linhas subjacentes aos valores. Os separadores intermédios respondem às perguntas abaixo.

| Painel de controlo | Separadores entre Overview e Detail | Para |
|---|---|---|
| **CFM-Accounting - Assets** | **Roll-forward**, **Bought and sold** | Contabilidade |
| **CFM-Accounting - Close and assurance** | **What needs fixing**, **Is the month closed**. Consulte [Data Foundation: os números são fiáveis?](/pt-pt/guides/projects/data-foundation-proof/) | Contabilidade |
| **CFM-Accounting - Intercompany** | **Which pairs do not agree**, **What has no partner** | Contabilidade |
| **CFM-Accounting - Journals** | **What was posted by hand**, **Journals to check** | Contabilidade |
| **CFM-Accounting - Receivables and payables** | **Who owes us**, **Who we pay** | Contabilidade |
| **CFM-Executive - Summary** | **Where the cash is**, **Sales and what is coming** | Executivo |
| **CFM-Finance - Operating expense** | **Which costs**, **Which departments**, **Which entities** | Finanças |
| **CFM-Finance - Performance against plan** | **What caused the gap**, **Who is over budget**, **Where the year lands** | Finanças |
| **CFM-Finance - Statements** | **What we own and owe**, **Where the cash went**, **Each unit's share**. O PDF do pacote para o conselho imprime este painel de controlo. | Finanças |
| **CFM-Finance - Working capital and cash** | **Where the cash is**, **What is tied up** | Finanças |
| **CFM-Marketing - Marketing** | **Where the money went**, **What it brought back** | Marketing |
| **CFM-Operations - Inventory** | **Where it sits**, **What is old and written off** | Operações |
| **CFM-Operations - Purchasing** | **Who we buy from**, **What we pay**, **What is still to arrive** | Operações |
| **CFM-Operations - Sites and people** | **Where cost went over**, **Staffing against plan**, **What we made** | Operações |
| **CFM-Sales - Orders and contracts** | **What we booked**, **What ships late**, **Renewals and retention** | Vendas |
| **CFM-Sales - Pipeline** | **What changed**, **Deals closing**, **How reps are doing**. Para as taxas que os respetivos montantes utilizam, consulte [Que taxa se aplica](/pt-pt/guides/projects/data-foundation/#que-taxa-se-aplica). | Vendas |
| **CFM-Sales - Sales** | **Why margin moved**, **Who buys from us**, **How reps are doing** | Vendas |

Os mosaicos de **Overview** de **CFM-Executive - Summary** são **Revenue, year to date**, **Gross margin %, year to date**, **EBITDA, year to date** e **Cash at month end**.

## Ler um painel de controlo

**A linha de contexto.** Cada separador abre com uma linha que indica o que os valores abrangem. Consulte [Nos painéis de controlo](/pt-pt/guides/projects/data-foundation-proof/#nos-painéis-de-controlo). Em **Overview**, acrescenta **Right-click any chart to break it down or see its rows**. Sem orçamento, indica **No budget loaded; comparing with last year**, e os títulos dos gráficos comparam com o ano anterior em vez do orçamento.

**Filtros.** **Período** está sempre presente. **Região**, **País**, **Division** e **Entidade** são acrescentados quando o projeto tem dois ou mais deles, e cada um lista apenas os valores dentro dos escolhidos antes dele. **Profit centre** é acrescentado quando os dados contêm dois ou mais. Seguem-se os filtros próprios do painel de controlo. Os filtros que não cabem na barra estão em **More filters**. **Período** abre no último mês fechado para todas as entidades. **CFM-Accounting - Close and assurance**, **CFM-Accounting - Intercompany** e **CFM-Sales - Pipeline** abrem no mês corrente: o primeiro mês ainda não fechado. Sem nenhum mês fechado, **Período** abre no mês mais recente.

**Mosaicos.** Um mosaico mostra o valor, a respetiva variação e a sua tendência nos doze meses até ao mês escolhido, com duas comparações: face ao orçamento e face ao ano anterior ou, quando o valor não tem orçamento, face ao mês anterior e face ao ano anterior. Um valor sem um mês próprio mostra o seu valor sem a tendência. Um mosaico que outro separador explica termina com **Why ›**, que abre esse separador. Todas as variações são apresentadas de modo que um valor positivo seja favorável, seja qual for o sentido da medida, e a seta e a cor do mosaico acompanham-no. A variação de uma margem é expressa em pontos.

**Ver também.** Todos os separadores, exceto **Overview**, terminam com uma linha **See also** que liga aos painéis de controlo relacionados.

**Unidades.** Os títulos dos gráficos indicam a unidade. A definição de projeto **Unidade de apresentação** é **Automático**, **Unidades inteiras**, **Milhares** ou **Milhões**. **Automático** utiliza unidades inteiras para uma única empresa com menos de 10 milhões de receita no seu maior ano fiscal; caso contrário, milhares, ou milhões a partir de mil milhões de receita. Os montantes por unidade, como um preço médio, nunca são escalados. Uma definição alterada é refletida quando os painéis de controlo voltam a ser construídos.

**As palavras do seu sistema.** Um projeto com um único sistema QuickBooks Online utiliza as palavras dele: **Classe** em vez de **Profit centre**, **Localização** em vez de site e **Categoria** em vez de família de produtos.

## Cópias de um projeto

Um projeto criado com [Clonar](/pt-pt/guides/projects/data-foundation/#clonar-um-projeto) não tem painéis de controlo próprios. Partilha o conjunto do original, e esses painéis de controlo continuam a ler o original. A respetiva página **Relatórios** indica **Este projeto é uma cópia**, com **Abrir o projeto de reporte** e duas opções:

- **Tornar este o projeto de reporte** aponta os painéis de controlo do conjunto para este projeto, pelo que os respetivos gráficos, ligações, favoritos e agendamentos continuam. Cada painel de controlo assume o público-alvo predefinido deste projeto, a menos que um proprietário tenha escolhido o seu público-alvo ou que alguém seja coproprietário dele. Precisa de acesso de edição a este projeto e àquele que os painéis de controlo liam antes. Um gráfico cujos dados faltam neste projeto não mostra nada aqui, e a mensagem indica o painel de controlo e os separadores. Num projeto que nunca foi carregado, a mensagem é "This project has no reporting database yet. Run Load first."
- **Atribuir à cópia os seus próprios painéis de controlo** pede-lhe que confirme: "This copy gets its own set of dashboards, as a separate business would. Use this only when the copy has become one." Clique em **Atribuir painéis de controlo** para prosseguir.

Ambas exigem acesso de edição ao projeto, e ambas reconstroem os painéis de controlo de imediato.

## Indicadores

Cada projeto recebe os indicadores que os seus painéis de controlo mostram. Cada um é uma [definição de indicador](/pt-pt/integrations/ai-coding-agents/metric-definitions/) com que o Weave responde, definida uma única vez para ambos, pelo que o Weave e os painéis de controlo concordam. Um indicador tem o nome do seu título, como **Receita** ou **Fundo de maneio** ou, quando dois partilham um título, o título e o respetivo assunto, como *título* - *assunto*. Quando dois do mesmo assunto partilham um título, é *título* (*nome do indicador*).

Os indicadores são criados quando o Data Foundation é instalado e no fim de cada **Carregar**, pelo respetivo passo **Make the metrics**. Um indicador é criado assim que a vista de relatório que lê estiver construída. Um indicador com esse nome que o projeto já tenha é deixado como está, pelo que as suas edições se mantêm. Um indicador que não possa ser criado é indicado nos avisos da execução, com o motivo; os painéis de controlo continuam a mostrá-lo.

## Caminhos de análise

A instalação do Data Foundation cria um [caminho de análise](/pt-pt/integrations/ai-coding-agents/analysis-paths/) por assunto, com o nome do projeto: *nome do projeto* - *assunto*. Os assuntos são **Finance**, **Journals**, **Trial balance**, **Drivers**, **Sales**, **Pipeline**, **Orders**, **Contracts**, **Purchasing**, **Receivables and payables**, **Intercompany**, **Inventory**, **Assets**, **Cash** e **Close and assurance**. Quando outro caminho de análise já utiliza o nome do projeto, os caminhos recebem o nome com um número, como `Northwind (2) - Finance`.

Cada caminho lê a vista de relatório do assunto e descreve todas as vistas de relatório do assunto, para que o Weave saiba o que cada uma contém. Os seus [nomes de negócio](/pt-pt/guides/projects/data-foundation/#nomes-de-negócio) são escritos na descrição do caminho de análise próprio do projeto. Um caminho com o mesmo nome que pertença a outro projeto é deixado como está, com um aviso.

## Vistas de relatório

As vistas de relatório são tabelas e vistas com o nome `cfm_rv_...` no topo do projeto, como `cfm_rv_finance_month` e `cfm_rv_sales_window`. O fluxo de trabalho **Relatórios** do projeto preenche-as a cada **Carregar**, depois de **Consolidate**. Todos os painéis de controlo, indicadores e caminhos de análise as leem, e pode consultá-las como qualquer outra tabela do projeto. Uma vista cujos dados ainda não existam é criada vazia e é preenchida assim que os seus dados chegam.
