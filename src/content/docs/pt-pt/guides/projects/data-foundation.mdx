O **Data Foundation** é a base de dados financeiros dos seus projetos PlaidCloud. O seu **Common Finance Model** reúne dados de ERP provenientes de vários sistemas ERP, e de várias instâncias de cada um, num único modelo: um plano de contas, um conjunto de entidades e uma moeda de relato. Os relatórios, os indicadores e os assistentes de IA criados sobre o modelo leem todos os mesmos números, independentemente do ERP de onde provêm.

O ERP liga-se através da respetiva ligação PlaidCloud, pelo que o razão geral, o balancete, os dados mestre e os orçamentos chegam diretamente da origem, sem nada para exportar. Os ficheiros acrescentam os dados que um sistema não contém, como taxas de câmbio, indutores de alocação ou um orçamento mantido fora do ERP, e podem substituir as linhas do ERP que cobrem. **Carregar** conforma todas as origens no modelo, converte-as para a moeda de relato e verifica se os totais coincidem, tudo a partir do separador **Base** do projeto. Os modelos, como o **Enterprise Profitability**, constroem os seus relatórios e modelos sobre esta base.

## Ligar o ERP

O ERP liga-se ao Data Foundation através da respetiva ligação PlaidCloud. O Data Foundation lê diretamente dela o razão geral, o balancete, os dados mestre, as taxas de câmbio e os orçamentos, e limita-se sempre a ler. É possível escolher uma ligação existente ou criar uma no separador; os [guias de ligações](/pt-pt/guides/connections/) abordam a configuração de acesso de cada ERP.

<Steps>

1. No Analyze, abra **Projetos** e clique em **Novo projeto**. Introduza um nome e, em **Começar a partir de**, escolha um modelo, como **Enterprise Profitability (modelo)**, em vez de **Projeto em branco**. Clique em **Criar**.

   O projeto abre no respetivo separador **Base**. É privado e o utilizador é o seu único Arquiteto, até o partilhar.

2. No separador **Base**, escolha uma ligação existente para o ERP ou escolha **Criar uma nova ligação**. Cada ligação existente lista os fluxos de trabalho que já a utilizam ou indica **Ainda não é utilizado por nenhum fluxo de trabalho**.

3. Para uma nova ligação, introduza um **Nome da ligação**, escolha o **Ambiente** e preencha as credenciais que a ligação ao ERP solicita.

   Ainda não tem as credenciais? O formulário mostra um pedido de acesso pronto a enviar ao administrador do ERP. Clique em **Copiar pedido** ou **Enviar pedido por email**, envie-o e introduza os valores que lhe devolverem.

4. Clique em **Testar ligação**. O PlaidCloud inicia sessão e tenta ler cada conjunto de dados, listando depois cada um como **Legível**, **Permissão em falta** ou **Erro**. Quando algo falta, indica as permissões que devem ser pedidas ao administrador do ERP.

5. Defina **Meses de histórico**: quantos meses para trás carregar, de 1 a 120. O valor predefinido é 24.

6. Para uma ligação existente, assinale as entidades a carregar ou deixe-as todas por assinalar para carregar todas as entidades. As entidades inativas e de eliminação ficam ocultas até se optar por as mostrar. Em seguida, clique em **Ligar**.

7. Para uma nova ligação, clique em **Ligar** para a criar. Depois, assinale as entidades a carregar e clique novamente em **Ligar** para as guardar. Até o fazer, todas as entidades são carregadas.

</Steps>

Depois de ligado, o cartão indica que ligação, ambiente, entidades e meses de histórico o projeto carrega.

Cada carregamento lê apenas o que mudou: os períodos abertos e o último período fechado são lidos novamente, e os períodos fechados já carregados são mantidos. Ao aumentar os **Meses de histórico**, só são lidos os meses acrescentados. Uma taxa de câmbio, um mapeamento de entidades ou uma moeda de relato alterados fazem ler novamente os meses que afetam.

## Adicionar ficheiros para dados fora do ERP

Os ficheiros complementam a ligação ao ERP com dados que um sistema não contém, como taxas de câmbio, indutores de alocação, um [Mapeamento de entidades](#mapeamento-de-entidades) ou um orçamento mantido fora do ERP. Cada ficheiro pertence a um dos conjuntos de dados listados em [Tabelas do Common Finance Model](#tabelas-do-common-finance-model).

<Steps>

1. Em **Ficheiros**, escolha a **Conta de documentos** onde guardar o ficheiro.

2. Largue um ficheiro CSV ou Excel em **Largue aqui um ficheiro CSV ou Excel** ou clique em **Escolha um ficheiro**. O ficheiro é carregado para a pasta `/foundation/` da conta de documentos.

   Para um ficheiro que já se encontra na conta de documentos, introduza o respetivo **Caminho do ficheiro**, por exemplo `/foundation/budget.csv`, e clique em **Adicionar ficheiro**.

3. O PlaidCloud lê o ficheiro e propõe uma correspondência:

   - **Delimitador, separador decimal e datas detetados.** O delimitador (vírgula, ponto e vírgula, tabulação ou barra vertical), o separador decimal e o formato de data são detetados automaticamente.
   - **Conjunto de dados**: a tabela do Common Finance Model a que o ficheiro pertence, identificada a partir do nome do ficheiro e dos cabeçalhos das colunas. Quando a correspondência não é clara, escolha-a na lista.
   - **Separador decimal**: **Ponto (1,234.56)** ou **Vírgula (1.234,56)**.
   - **Formato de data**: apresentado quando o ficheiro tem datas. Altere-o se o formato detetado estiver errado: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Uma grelha com **Coluna no ficheiro**, **Tipo**, **Exemplos** e **Destino**. Altere **Destino** para enviar uma coluna para outro campo ou para **Não carregar**.

4. Verifique o destino de cada coluna e clique em **Confirmar correspondência**.

</Steps>

Quando o PlaidCloud não consegue decidir sozinho o conjunto de dados, o separador decimal ou a ordem das datas, por exemplo num ficheiro cujas datas possam ser lidas como dia/mês ou mês/dia, pede que se escolha antes de confirmar. Adicionar um segundo ficheiro para o mesmo conjunto de dados substitui o primeiro.

Os ficheiros aceites são ficheiros de texto CSV, TSV e TXT, ficheiros Excel `.xlsx` (lidos a partir da primeira folha) e ficheiros Parquet.

<Aside type="note">
Um ficheiro em falta ou vazio nunca impede um carregamento. Ao adicioná-lo, é indicado que ainda não há nada para mapear, e o carregamento termina com um aviso que nomeia o caminho, deixando esse conjunto de dados vazio. Adicione novamente o ficheiro quando existir.
</Aside>

## Carregar os dados

Clique em **Carregar** no cartão **Carregar** ou no cartão **Último carregamento**. O carregamento lê o ERP ligado e os ficheiros confirmados, conforma-os no Common Finance Model, converte-os para a moeda de relato, executa as verificações de prontidão e reconstrói os modelos do modelo.

- Só é executado um carregamento de cada vez por projeto. Um segundo **Carregar** indica que já existe um carregamento em execução.
- Se outros fluxos de trabalho utilizarem a mesma ligação ao ERP, o primeiro carregamento lista-os e pede confirmação, porque um carregamento lê do ERP e pode abrandar esses fluxos de trabalho. Clique em **Carregar mesmo assim** para avançar.
- Um carregamento falhado é apresentado a vermelho e nunca fica escondido atrás de resultados anteriores. As linhas de um carregamento anterior mostram **De um carregamento anterior. Carregue novamente.** até um carregamento ter êxito.
- Se a leitura de uma entidade e período falhar, as restantes são carregadas na mesma. Execute **Carregar** novamente para obter apenas o que falhou.

### Dados do ERP e ficheiros em conjunto

Um ficheiro substitui apenas o que cobre, e as restantes linhas do ERP mantêm-se.

- Os **ficheiros mestre** (contas, departamentos, clientes, produtos e Valores de segmento) substituem as linhas do ERP com o mesmo código.
- Os **ficheiros de transações** substituem as linhas do ERP da mesma entidade e do mesmo mês. Os ficheiros de razão geral e de balancete também correspondem por livro, os ficheiros de orçamento por cenário e os ficheiros de indutores estatísticos por cenário e indutor.

Se um ficheiro deixar de cobrir um mês, os dados do ERP desse mês regressam no carregamento seguinte.

## Mapeamento de entidades

Cada origem designa as suas entidades com códigos próprios. O **Mapeamento de entidades** associa esses códigos às entidades do mestre de entidades, para que as linhas de todas as origens fiquem na mesma entidade.

Para o utilizar, adicione um ficheiro CSV ou Excel e escolha o conjunto de dados **Mapeamento de entidades**:

| Coluna | Contém |
|---|---|
| `source_entity` | O código tal como a origem o transporta, por exemplo um código de empresa. |
| `entity` | A entidade a que pertence, tal como o mestre de entidades a designa. |

- Um código que não consta do mapeamento é utilizado tal como está.
- Vários códigos podem corresponder a uma única entidade. As respetivas linhas são combinadas, e um mês conta como fechado quando está fechado para todos eles.
- Os códigos do mapeamento aplicam-se a todas as origens, pelo que os códigos de entidade de cada origem têm de ser únicos entre origens.
- Uma linha de ficheiro de **Entidades** substitui a entidade do ERP com o mesmo código de entidade.

A verificação **Entidades não mapeadas** assinala qualquer linha cuja entidade não esteja no mestre de entidades nem seja associada a uma pelo mapeamento. Até um mestre de entidades ser carregado, mostra **– Não aplicável**.

## Conversão de moedas

Cada carregamento converte os montantes do razão geral, do balancete, das vendas, do inventário e do orçamento da respetiva moeda local para uma única moeda de relato. Os relatórios e os modelos leem os montantes convertidos, pelo que as entidades em moedas diferentes, de qualquer sistema, totalizam corretamente.

### A moeda de relato

Para escolher a moeda de relato, defina a variável de projeto `reporting_currency` com um código de moeda, como `USD`. Consulte [Gerir variáveis do projeto](/pt-pt/guides/projects/managing-projects/#gerir-variáveis-do-projeto). O modelo cria-a em branco. Enquanto estiver em branco, cada carregamento utiliza a primeira das seguintes opções que designe exatamente uma moeda:

1. A moeda do grupo das entidades.
2. A moeda local das entidades de topo, as que não têm entidade superior.
3. A moeda local dos ficheiros.

Se nenhuma designar exatamente uma moeda, **Conversão de moedas** mostra um problema até se definir `reporting_currency`.

Os montantes que já estão na moeda de relato mantêm-se como estão, pelo que um projeto cujos dados estão todos numa só moeda não precisa de taxas.

Os ficheiros de vendas, de inventário e de orçamento também podem incluir uma moeda. Mapeie uma coluna com o nome `Currency` ou `Local Currency` e esta é detetada automaticamente, e os montantes locais do ficheiro são convertidos para a moeda de relato. Um montante de grupo ou de relato que já conste do ficheiro é mantido tal como está. O custo padrão do produto não é convertido.

### Taxas de câmbio

Uma taxa converte uma unidade de uma moeda para a moeda de relato num determinado mês: o montante convertido é o montante local multiplicado pela taxa.

- **A partir do ERP**, cada carregamento lê as taxas de câmbio que o ERP contém.
- **A partir de um ficheiro**, adicione um ficheiro CSV ou Excel e escolha o conjunto de dados **Taxas de câmbio**. Uma taxa no ficheiro substitui a taxa do ERP para as mesmas moedas e o mesmo mês. Utilize um ficheiro para reportar numa moeda para a qual os ERP não publicam taxas ou para acrescentar taxas previstas para os meses de orçamento.

| Coluna | Contém |
|---|---|
| `from_currency` | A moeda de origem da conversão, por exemplo `EUR`. |
| `to_currency` | A moeda de relato, por exemplo `USD`. |
| `period` | O mês, no formato `YYYY-MM`. |
| `average_rate` | A taxa média do mês. |
| `closing_rate` | A taxa no fim do mês. |
| `historical_rate` | A taxa histórica, para o capital próprio e para as contas definidas com a taxa histórica. |

Só são utilizadas taxas para a moeda de relato. Uma taxa cotada no sentido inverso, da moeda de relato para outra moeda, não é invertida.

### Que taxa se aplica

Cada linha é convertida a partir da sua própria moeda, pelo que uma linha numa moeda diferente da da sua entidade é convertida a partir da moeda em que se encontra. Aplica-se a primeira regra que se ajustar à linha:

| Linha | Taxa |
|---|---|
| Contas estatísticas e sem lançamento | Não convertidas. |
| Já na moeda de relato | Não convertida. |
| Conta com tipo de taxa | Essa taxa: média, de fecho ou histórica. A histórica recorre à de fecho quando não existe taxa histórica. A partir de um ERP, o tipo de taxa é o tipo de taxa da própria conta. Num ficheiro de plano de contas, mapeie uma coluna de tipo de taxa para `fx_rate_type` com `average`, `closing` ou `historical`. |
| Linha de vendas | A taxa média do período. |
| Saldo de inventário | A taxa de fecho do período. |
| Linha de orçamento | Por conta, tal como o razão geral: a taxa média para as contas de demonstração de resultados e a taxa de fecho para as contas de balanço. |
| Conta de demonstração de resultados | A taxa média do período. |
| Conta de capital próprio | A taxa histórica ou a taxa de fecho quando não existe taxa histórica. |
| Qualquer outra conta de balanço | A taxa de fecho do período. |

Os montantes convertidos não são arredondados, pelo que os totais não divergem.

<Aside type="note">
O balancete contém os movimentos de cada período, pelo que os montantes de balanço são os movimentos de cada mês convertidos à taxa de fecho desse mês. Não são um balanço reconvertido à taxa do fim do período, e não existe ajustamento cumulativo de conversão nem eliminação intragrupo. Utilize os montantes convertidos para a demonstração de resultados.
</Aside>

## Hierarquias

Cada carregamento reconstrói sete dimensões a partir dos dados mestre de todas as origens:

| Dimensão | Construída a partir de |
|---|---|
| **Entidade** | Entidades e respetivas entidades superiores |
| **Conta** | Plano de contas e contas superiores |
| **Departamento** | Departamentos e respetivos departamentos superiores |
| **Cliente** | Clientes e respetivos clientes superiores |
| **Produto** | Produtos e respetivos produtos superiores |
| **Segmento 1** | Valores de segmento para `segment_1` |
| **Segmento 2** | Valores de segmento para `segment_2` |

- Um registo sem elemento superior, ou que se designe a si próprio como elemento superior, é carregado como membro de topo.
- Como cada carregamento reconstrói as hierarquias, altere um elemento superior no ERP ou no ficheiro, e não na dimensão.
- Um problema numa hierarquia afeta apenas essa dimensão. O carregamento e os modelos do modelo concluem-se na mesma.
- É possível mudar o nome de **Segmento 1** e **Segmento 2** para o que contêm, por exemplo **Classe** e **Localização**.

Para fornecer hierarquias de segmento a partir de um ficheiro, escolha o conjunto de dados **Valores de segmento**:

| Coluna | Contém |
|---|---|
| `segment` | O segmento a que o valor pertence: `segment_1` a `segment_5`. **Segmento 1** e **Segmento 2** têm dimensões. |
| `segment_value` | O valor, tal como as linhas do razão geral, das vendas e do orçamento o transportam. |
| `segment_value_name` | O respetivo nome. |
| `parent_segment_value` | O respetivo elemento superior dentro do mesmo segmento. |

## Verificações de prontidão

Após cada carregamento, a grelha **Prontidão** lista todas as verificações de todas as entidades e períodos, com um dos seguintes estados:

| Estado | Significado |
|---|---|
| **● Pronto** | A verificação foi aprovada. |
| **▲ Requer atenção** | Vale a pena analisar, mas os números são utilizáveis. |
| **■ Problema** | Corrija antes de confiar nos resultados. |
| **– Não aplicável** | Ainda não existem dados para esta verificação. |

As verificações são:

| Verificação | O que confirma |
|---|---|
| **Dados carregados** | Todos os períodos fiscais têm linhas de razão geral e todas as leituras do ERP tiveram êxito. Um período fechado sem linhas é um problema; um período aberto sem linhas requer atenção. |
| **O balancete coincide com o razão geral** | O balancete é igual ao razão geral para cada entidade, período e conta. Quando o balancete e o razão geral incluem departamentos para uma conta, também coincidem por departamento. |
| **Vendas coincidem com o razão geral** | As linhas de vendas são iguais às contas de receita e de custo das mercadorias vendidas (COGS) do razão geral em cada período. |
| **Produtos/clientes desconhecidos** | Todas as linhas de vendas indicam um produto e um cliente que existem nos mestres de produtos e de clientes. |
| **Contas em falta no plano de contas** | Todas as linhas do razão geral indicam uma conta do plano de contas. As linhas com uma conta desconhecida ficam fora da demonstração de resultados. |
| **Conversão de moedas** | Todas as linhas do razão geral, do balancete, das vendas, do inventário e do orçamento têm um montante na moeda de relato. Uma linha de demonstração de resultados ou de vendas sem taxa é um problema, porque a demonstração de resultados lê montantes convertidos. Uma linha de balanço, de inventário ou de orçamento sem taxa requer atenção. Um mês de orçamento ainda sem taxa surge a âmbar, pelo que convém carregar taxas previstas para os meses de orçamento. Consulte [Conversão de moedas](#conversão-de-moedas). |
| **Entidades não mapeadas** | Todas as linhas do razão geral, do balancete e das vendas indicam uma entidade do mestre de entidades, diretamente ou através do mapeamento de entidades. Não aplicável até um mestre de entidades ser carregado. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |

Cada linha que não está pronta indica o que fazer na coluna **O que fazer**, como carregar o plano de contas, carregar taxas de câmbio ou executar **Carregar** novamente para um período.

A grelha também mostra duas verificações de configuração, que só aparecem quando requerem atenção:

| Verificação | Quando aparece |
|---|---|
| **Imputação de custos indiretos** | Apenas uma das variáveis de projeto `overhead_department` e `overhead_driver` está definida, ou nenhum indutor de alocação corresponde a `overhead_driver`, pelo que a alocação não faria nada. Defina ambas ou limpe ambas para desativar a imputação de custos indiretos. |
| **Comparação com o orçamento** | Existem linhas de orçamento carregadas, mas nenhuma está na versão indicada pela variável de projeto `budget_version`, pelo que a comparação com o orçamento ficaria vazia. |

## Manter atualizado

Depois de um carregamento a partir da ligação ao ERP ter êxito sem problemas, **Atualizar todas as noites** aparece no cartão **Último carregamento**. Clique nele para executar **Carregar** todas as noites às 2:00 no fuso horário do utilizador. O cartão passa então a mostrar **Nightly refresh: Every night at 2:00** e quem o configurou.

O carregamento noturno é executado como a pessoa que o configurou. Se essa pessoa deixar de poder utilizar a ligação ao ERP, a grelha indica que o carregamento noturno é ignorado; configure-o novamente. Um projeto que só tem dados de exemplo não pode ser agendado.

Um ficheiro em falta ou vazio num carregamento noturno termina com um aviso que nomeia o caminho, e não com um erro, e o resto do modelo é carregado na mesma.

## Construir sobre o modelo com um modelo

Um modelo constrói os seus relatórios e modelos sobre o Common Finance Model, pelo que funcionam da mesma forma, independentemente dos ERP que o alimentam. Quando se inicia um projeto a partir de um modelo, como o **Enterprise Profitability**, este cria:

- As [tabelas do Common Finance Model](#tabelas-do-common-finance-model), vazias ou preenchidas com dados de exemplo.
- As dimensões **Entidade**, **Conta**, **Departamento**, **Cliente**, **Produto**, **Segmento 1** e **Segmento 2**, construídas a partir dessas tabelas. Consulte [Hierarquias](#hierarquias).
- O fluxo de trabalho **Carregar** e os fluxos de trabalho que este executa para ler o ERP e os ficheiros, conformá-los, verificar a prontidão e construir os modelos do modelo.
- Os relatórios e modelos próprios do modelo. O **Enterprise Profitability** acrescenta uma tabela de demonstração de resultados com receita, COGS, margem bruta, despesas operacionais diretas e indiretas, contribuição e margem operacional, além de pontes de margem de ano para ano e face ao orçamento.
- Indicadores e um caminho de análise para fazer perguntas sobre os resultados.

Para explorar antes de ligar o seu próprio ERP, assinale **Começar com dados de exemplo** ao criar o projeto. O projeto executa de imediato um primeiro Carregar, pelo que o separador **Base** mostra um exemplo completo, incluindo uma entidade em euros convertida para dólares dos EUA. Quando liga o seu próprio ERP ou adiciona os seus próprios ficheiros, as linhas de exemplo são limpas e os seus dados ocupam o lugar delas.

## O separador Base

O separador **Base** é o local onde se ligam, carregam e verificam os dados. Tem as seguintes secções, de cima para baixo:

| Secção | O que mostra |
|---|---|
| **Último carregamento** | Se o último carregamento teve êxito, falhou ou ainda está em execução, com os botões **Carregar**, **Atualizar** e **Atualizar todas as noites**. |
| **Configuração** | A lista de verificação da configuração: **Ligar os seus dados**, **Carregue os seus dados**, **Verificar se os totais coincidem**, **Reveja as suas hierarquias** e **Partilhar com a sua equipa**. O item atual está a negrito. |
| **Ficheiros** | Cada ficheiro adicionado, o respetivo conjunto de dados, como **Razão geral** ou **Taxas de câmbio**, e se a correspondência está **✓ Confirmado** ou **○ A aguardar confirmação**. |
| **Dados carregados** | Para cada entidade, o primeiro e o último período carregados e quantos períodos estão prontos. |
| **Períodos** | Os períodos fiscais de cada entidade e se cada um está **✓ Fechado** ou **○ Aberto**. |
| **Prontidão** | A grelha de prontidão: uma linha por entidade, período e verificação, com o respetivo estado e **O que fazer**. |
| Ligação | Ligar o ERP, escolher as entidades e quantos meses de histórico carregar. |
| **Ficheiros** (adicionar) | Adicionar um ficheiro CSV, TSV, TXT, Excel ou Parquet e confirmar como as colunas são mapeadas. |
| **Carregar** | Iniciar um carregamento. |

Enquanto um carregamento decorre, o separador atualiza-se automaticamente.

A lista de verificação da configuração acompanha o progresso:

- **Ligar os seus dados** e **Carregue os seus dados** ficam assinalados automaticamente quando uma origem é associada e um carregamento tem êxito.
- **Verificar se os totais coincidem** fica assinalado automaticamente quando as verificações de coincidência são aprovadas.
- **Reveja as suas hierarquias**: clique em **Abrir dimensões** para rever as hierarquias de Entidade, Conta e Departamento e, em seguida, assinale **Já os revi**. Confirma este item por si.
- **Partilhar com a sua equipa**: partilhe o projeto quando estiver pronto. Consulte [Gerir o acesso ao projeto](/pt-pt/guides/projects/managing-projects/#gerir-o-acesso-ao-projeto).

## Tabelas do Common Finance Model

O Data Foundation conforma todas as origens, ERP ou ficheiro, nas mesmas quinze tabelas, pelo que os relatórios, os indicadores e os modelos construídos sobre elas funcionam da mesma forma, qualquer que seja a origem. Cada linha regista também o sistema de origem e quando foi lida. A coluna **Conjunto de dados** é o nome que se escolhe ao adicionar um ficheiro.

| Conjunto de dados | Tabela | Contém |
|---|---|---|
| Entidades | `cfm_entity` | Entidades legais com entidade superior, moeda local e de grupo, e país. |
| Mapeamento de entidades | `cfm_entity_map` | Códigos de entidade da origem e a entidade a que cada um pertence. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |
| Taxas de câmbio | `cfm_fx_rate` | Taxas mensais média, de fecho e histórica por par de moedas. Consulte [Taxas de câmbio](#taxas-de-câmbio). |
| Calendário fiscal | `cfm_fiscal_calendar` | Uma linha por período fiscal de cada entidade, com datas de início e de fim e se está fechado. |
| Plano de contas | `cfm_account` | Contas com conta superior, tipo (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), demonstração financeira, saldo normal e tipo de taxa. |
| Departamentos | `cfm_department` | Departamentos e centros de custo com departamento superior e centro de lucro. |
| Produtos | `cfm_product` | Mestre de produtos com produto superior, família, grupo, unidade de medida e custo padrão. |
| Clientes | `cfm_customer` | Mestre de clientes com cliente superior, grupo, região e país. Os nomes dos clientes não são ocultados. |
| Valores de segmento | `cfm_segment` | Valores de segmento com nome e elemento superior. Consulte [Hierarquias](#hierarquias). |
| Razão geral | `cfm_gl_journal` | Linhas de diário na moeda da transação, local e de relato. |
| Balancete | `cfm_trial_balance` | Débitos, créditos e líquido do período por entidade, conta e departamento, na moeda local e de relato. |
| Linhas de vendas | `cfm_sales_line` | Linhas de vendas faturadas com quantidade e montantes bruto, de desconto, líquido e de COGS. |
| Saldos de inventário | `cfm_inventory_balance` | Inventário de fim de período por produto e armazém. |
| Orçamento | `cfm_budget` | Orçamento e previsão por cenário, versão, conta e departamento. |
| Indutores de alocação | `cfm_stat_driver` | Indutores estatísticos como número de colaboradores, metros quadrados ou unidades. |

Os períodos escrevem-se `YYYY-MM`, e as transações são colocadas pelo período de lançamento. O orçamento é opcional: um ERP sem orçamentos carrega na mesma tudo o resto.

Um ficheiro de balancete pode incluir colunas de débito e crédito, uma coluna de líquido, ou ambas. Com apenas débito e crédito, o líquido é o débito menos o crédito, e um lado em branco conta como zero. Com apenas um líquido, um líquido positivo passa a ser o débito e um líquido negativo passa a ser o crédito, como montante positivo. Uma coluna de departamento é opcional.

## Resolução de problemas

| Sintoma | O que fazer |
|---|---|
| **Testar ligação** indica que o ERP recusou as credenciais | Verifique as credenciais da ligação e se o utilizador da integração consegue iniciar sessão no ERP. |
| **Testar ligação** mostra **Permissão em falta** para um conjunto de dados | Peça ao administrador do ERP que adicione as permissões indicadas. O [guia de ligações](/pt-pt/guides/connections/) do ERP lista o que a ligação necessita. |
| Uma mensagem de erro do ERP é mais curta do que a do próprio ERP | O PlaidCloud remove credenciais, tokens e chaves dos erros dos fornecedores antes de os mostrar, pelo que algum detalhe é omitido. Execute **Testar ligação** para ver que conjunto de dados é afetado. |
| **Dados carregados** é um problema num período | Falhou uma leitura do ERP para esse período. Execute **Carregar** novamente; os períodos já carregados são ignorados. |
| **Contas em falta no plano de contas** é um problema | Adicione as contas em falta ao plano de contas no ERP ou no ficheiro e execute **Carregar** novamente. |
| **Conversão de moedas** é um problema | A moeda de uma entidade não tem taxa para a moeda de relato nesse período, ou não foi encontrada uma única moeda de relato. Adicione as taxas a um ficheiro **Taxas de câmbio**, verifique se a ligação consegue ler as taxas de câmbio do ERP ou defina a variável de projeto `reporting_currency`. Depois execute **Carregar** novamente. |
| **Conversão de moedas** requer atenção | As linhas de balanço, de inventário ou de orçamento não têm taxa de fecho, histórica ou prevista para o período. A demonstração de resultados não é afetada. Adicione as taxas, incluindo as previstas para os meses de orçamento, e execute **Carregar** novamente. |
| **Entidades não mapeadas** é um problema | Adicione a entidade ao mestre de entidades ou associe o respetivo código a uma entidade existente no ficheiro **Mapeamento de entidades** e execute **Carregar** novamente. |
