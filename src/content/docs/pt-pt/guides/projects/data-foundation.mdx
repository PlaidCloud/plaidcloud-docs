O **Data Foundation** é a base de dados financeiros dos seus projetos PlaidCloud. O seu **Common Finance Model** reúne num único modelo os dados de vários sistemas ERP, e de várias instâncias de cada um: um plano de contas, um conjunto de entidades e uma moeda de relato. Os relatórios, os indicadores e os assistentes de IA criados sobre o modelo leem todos os mesmos números, seja qual for o ERP de origem.

O ERP liga-se através da respetiva ligação PlaidCloud, pelo que o razão geral, o balancete, os dados mestre e os orçamentos chegam diretamente da origem, sem necessidade de exportar nada. Os ficheiros acrescentam os dados que um sistema não contém, como taxas de câmbio, indutores de alocação ou um orçamento mantido fora do ERP, e podem substituir as linhas do ERP que abrangem. A ação **Carregar** harmoniza todas as origens no modelo, converte-as para a moeda de relato e verifica se os totais coincidem, tudo a partir do separador **Base** do projeto. Quando as origens usam o mesmo código para coisas diferentes, indica se significam o mesmo, e uma consolidação de gestão cria a demonstração de resultados do grupo com as operações intragrupo eliminadas. Os modelos, como o **Enterprise Profitability**, criam os seus relatórios e modelos de cálculo sobre esta base.

## Ligar o ERP

O ERP liga-se ao Data Foundation através da respetiva ligação PlaidCloud. O Data Foundation lê diretamente da ligação o razão geral, o balancete, os dados mestre, as taxas de câmbio e os orçamentos, e limita-se sempre a ler. Pode escolher uma ligação existente ou criar uma no separador. Cada sistema tem uma página dirigida ao administrador que concede o acesso, indicada em [Que sistemas podem alimentar o modelo](/pt-pt/guides/projects/data-foundation-getting-started/#que-sistemas-podem-alimentar-o-modelo), e a [Matriz de cobertura do Data Foundation](/pt-pt/reference/data-foundation-coverage-matrix/) mostra os conjuntos de dados que cada sistema fornece diretamente.

<Steps>

1. No Analyze, abra **Projetos** e clique em **Novo projeto**. Introduza um nome e, em **Começar a partir de**, escolha um modelo, como **Enterprise Profitability (modelo)**, em vez de **Projeto em branco**. Clique em **Criar**.

   O projeto abre no respetivo separador **Base**. É privado e o utilizador é o seu único Arquiteto até o partilhar.

2. No separador **Base**, escolha uma ligação existente para o ERP ou selecione **Criar uma nova ligação**. Cada ligação existente apresenta os fluxos de trabalho que já a utilizam ou indica **Ainda não é utilizado por nenhum fluxo de trabalho**.

3. Para uma nova ligação, introduza um **Nome da ligação**, escolha o **Ambiente** e preencha as credenciais que a ligação ao ERP solicita.

   Ainda não tem as credenciais? O formulário apresenta um pedido de acesso já preparado para o administrador do ERP. Clique em **Copiar pedido** ou **Enviar pedido por email**, envie-o e introduza os valores que receber.

4. Clique em **Testar ligação**. O PlaidCloud inicia sessão e tenta ler cada conjunto de dados, indicando depois cada um como **Legível**, **Permissão em falta** ou **Erro**. Quando falta alguma coisa, indica as permissões que deve pedir ao administrador do ERP para acrescentar.

5. Defina **Meses de histórico**: quantos meses anteriores carregar, de 1 a 120. O valor predefinido é 24.

6. Numa ligação existente, assinale as entidades a carregar ou deixe-as todas por assinalar para carregar todas as entidades. As entidades inativas e de eliminação ficam ocultas até escolher mostrá-las. Depois clique em **Ligar**.

7. Numa nova ligação, clique em **Ligar** para a criar. Depois assinale as entidades a carregar e clique novamente em **Ligar** para as guardar. Até o fazer, são carregadas todas as entidades.

8. Para trazer outro sistema ERP ou outra instância, repita estes passos e assinale **Add this as another source instead of replacing the current one** antes de clicar em **Ligar**. Sem esta opção, a nova ligação substitui a origem atual.

</Steps>

Depois de ligado, o cartão indica a ligação, o ambiente, as entidades e os meses de histórico que o projeto carrega.

Cada carregamento lê apenas o que mudou: os períodos abertos e o último período fechado são lidos novamente, e os períodos fechados já carregados são mantidos. Aumentar **Meses de histórico** lê apenas os meses acrescentados. Uma alteração a uma taxa de câmbio, ao mapeamento de entidades ou à moeda de relato volta a ler os meses que afeta.

## Origens

Cada sistema ERP e cada instância a partir dos quais o projeto carrega dados é uma origem. A lista **Origens** do separador **Base** mostra uma linha por origem, por ordem, com o respetivo nome, a data do último carregamento, o número de linhas fornecidas e os livros de relato que lê, por exemplo `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Uma origem que ainda não foi carregada indica **not loaded yet**. Os ficheiros que confirmar também são origens.

Abra **Avançado** numa origem para alterar a forma como é utilizada:

| Definição | O que faz |
|---|---|
| **Nome** | A etiqueta que os relatórios, as perguntas de correspondência e as mensagens usam para a origem. |
| **Place in the order** | A posição da origem. Quando duas origens abrangem o mesmo mês da mesma empresa, prevalece a que está mais acima na ordem. |
| **Reporting books, separated by commas** | Os livros contabilísticos a ler, num sistema que mantém mais do que um. **All reporting books** lê todos os livros. |
| **Empresa**, **De (2026-01)** e **Para (2026-12)** | Os meses que esta origem fornece para cada empresa. Deixe um mês vazio para não impor limite. Escreva os meses como ano e mês, por exemplo `2026-03`. |

Clique em **Guardar** para manter as alterações. Para eliminar uma origem, clique em **Remove this source** e confirme com **Remover**. Tudo o que foi carregado a partir dela é eliminado, e pode ligá-la novamente mais tarde.

Alterar as origens não volta a ler o ERP. O cartão **Último carregamento** indica **Changes not applied yet** até clicar em **Apply changes**, que executa um carregamento a partir dos dados já obtidos: harmoniza novamente as origens com a nova ordem, os novos mapeamentos, nomes e ficheiros, e reconstrói o modelo. Clique em **Carregar** quando também pretender dados atualizados dos ERP.

## Adicionar ficheiros para dados fora do ERP

Os ficheiros complementam a ligação ao ERP com dados que um sistema não contém, como taxas de câmbio, indutores de alocação, um [Mapeamento de entidades](#mapeamento-de-entidades) ou um orçamento mantido fora do ERP. Cada ficheiro pertence a um dos conjuntos de dados indicados em [Tabelas do Common Finance Model](#tabelas-do-common-finance-model).

<Steps>

1. Em **Ficheiros**, escolha a **Conta de documentos** onde guardar o ficheiro.

2. Largue um ficheiro CSV ou Excel em **Largue aqui um ficheiro CSV ou Excel** ou clique em **Escolha um ficheiro**. O ficheiro é carregado para a pasta `/foundation/` da conta de documentos.

   Para um ficheiro que já se encontra na conta de documentos, introduza o respetivo **Caminho do ficheiro**, por exemplo `/foundation/budget.csv`, e clique em **Adicionar ficheiro**.

   Para ler um ficheiro novo todos os meses, adicione todos os ficheiros de uma pasta cujo nome corresponda: introduza a pasta e, em **File names that**, escolha se os nomes contêm, começam por, terminam em, coincidem exatamente com ou correspondem a um padrão, e clique em **Add files**. Os ficheiros em pastas dentro dessa pasta não são lidos.

3. O PlaidCloud lê o ficheiro e propõe uma correspondência:

   - **Detected delimiter, decimal separator and dates.** O delimitador (vírgula, ponto e vírgula, tabulação ou barra vertical), o separador decimal e o formato de data são detetados automaticamente.
   - **Conjunto de dados**: a tabela do Common Finance Model a que o ficheiro pertence, identificada a partir do nome do ficheiro e dos cabeçalhos das colunas. Quando a correspondência não é clara, escolha-a na lista.
   - **Separador decimal**: **Ponto (1,234.56)** ou **Vírgula (1.234,56)**.
   - **Formato de data**: apresentado quando o ficheiro tem datas. Altere-o se o formato detetado estiver errado: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Uma grelha com **Coluna no ficheiro**, **Tipo**, **Exemplos** e **Destino**. Altere **Destino** para enviar uma coluna para outro campo ou para **Não carregar**.

4. Responda às perguntas que o ficheiro suscita, como **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** ou **Are revenues shown as negative numbers?** Cada pergunta só é feita quando o ficheiro ainda não a responde.

5. Verifique o destino de cada coluna e clique em **Confirmar correspondência**.

</Steps>

Estas opções aparecem num ficheiro quando se aplicam:

| Opção | Utilize para |
|---|---|
| **Which source do these rows apply to?** | Limitar um ficheiro de mapa de códigos a uma origem. **Every source** aplica-o a todas. |
| **Where does this file come from?** | Indicar se o ficheiro contém **This project's own codes** ou provém de **Another system**, que indica, por exemplo `SAP Germany export`. Um ficheiro de outro sistema é verificado quanto a códigos partilhados como uma origem ERP. |
| **Split … into … parts at each …** (em **Avançado**) | Dividir uma coluna que contém vários valores, como `100-200-300`, e enviar cada parte para o seu próprio campo. |
| **Which currency do you report in?** | Definir a moeda de relato quando o projeto ainda não tem uma. Escreva-a com três letras, por exemplo `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Carregar os resultados do sistema de consolidação para que a demonstração de resultados do grupo possa ser [reconciliada](#reconciliar-com-o-sistema-de-consolidação). |

Para retirar um ficheiro do projeto, clique em **Remover** junto a ele em **Ficheiros**, ou em **Remove this file** na respetiva correspondência, e confirme. Os valores do ficheiro deixam de constar dos relatórios na próxima vez que clicar em **Apply changes**.

Quando o PlaidCloud não consegue decidir sozinho o conjunto de dados, o separador decimal ou a ordem das datas, por exemplo num ficheiro cujas datas podem ler-se como dia/mês ou mês/dia, pede-lhe que escolha antes de confirmar. Adicionar um segundo ficheiro para o mesmo conjunto de dados substitui o primeiro. Se as colunas de um ficheiro posterior não corresponderem ao conjunto de dados, o carregamento indica o ficheiro e as colunas e pede para corrigir o ficheiro ou os nomes das colunas, ou para definir **Schema Mismatch** do passo como `union`.

Os ficheiros aceites são ficheiros de texto CSV, TSV e TXT, ficheiros Excel `.xlsx` (lidos a partir da primeira folha) e ficheiros Parquet.

<Aside type="note">
Um ficheiro em falta ou vazio nunca interrompe um carregamento. Ao adicioná-lo, é indicado que ainda não há nada para mapear, e um carregamento termina com um aviso que indica o caminho, deixando esse conjunto de dados vazio. Volte a adicionar o ficheiro quando existir.
</Aside>

## Carregar os dados

Clique em **Carregar** no cartão **Carregar** ou no cartão **Último carregamento**. O carregamento lê o ERP ligado e os ficheiros confirmados, harmoniza-os no Common Finance Model, converte-os para a moeda de relato, executa as verificações de prontidão e reconstrói os modelos de cálculo do modelo de projeto.

- Só pode estar a decorrer um carregamento de cada vez por projeto. Um segundo **Carregar** ou **Apply changes** indica que já existe um carregamento em curso, e não é possível alterar as origens enquanto um decorre.
- Se outros fluxos de trabalho usarem a mesma ligação ao ERP, o primeiro carregamento lista-os e pede confirmação, porque um carregamento lê do ERP e pode tornar esses fluxos de trabalho mais lentos. Clique em **Carregar mesmo assim** para avançar.
- Depois de o PlaidCloud ser atualizado, o **Carregar** de um Arquiteto também atualiza os fluxos de trabalho gerados do projeto, criando as tabelas de trabalho de que precisam. Até lá, a página de estado apresenta um item cor de laranja, "The workflows were generated by an earlier release. An Architect's Load updates them.", e o **Carregar** de um Gestor avisa que só um Arquiteto os pode atualizar.
- Um carregamento falhado aparece a vermelho e nunca fica oculto por resultados anteriores. Se a consolidação falhar, o estado indica o passo em que parou em vez de mostrar resultados antigos do grupo. As linhas de um carregamento anterior mostram **De um carregamento anterior. Carregue novamente.** até um carregamento ter êxito.
- Se uma entidade e período não for lida, o resto é carregado na mesma. Execute **Carregar** novamente para obter apenas o que falhou.

### Linhas retidas

Quando as origens se sobrepõem, um carregamento mantém uma cópia de cada valor e retém as outras em vez de as contar duas vezes. As linhas retidas são registadas com a origem, a entidade e o motivo, e o carregamento termina com um aviso que indica as contagens, por exemplo `120 rows of NetSuite EU also provided by a source ranked ahead`. Os motivos são:

| Motivo | Significado |
|---|---|
| Noutro livro contabilístico | A linha pertence a um livro de relato que a origem não está configurada para ler. |
| Fora dos períodos que a origem fornece | A linha está fora dos meses **De** e **Para** definidos para a empresa. |
| Também fornecida por uma origem com prioridade | Uma origem mais acima na ordem abrange a mesma empresa e o mesmo mês. |
| Também num ficheiro anterior da origem | Um ficheiro anterior da mesma origem já abrange o mês. |
| Substituída por um ficheiro | Um ficheiro substitui as linhas do ERP dessa entidade e desse mês. |
| Com um código que outra origem também utiliza | O código precisa da sua resposta. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| Com um código mapeado para dois códigos | O mapa de códigos dá duas respostas ao código. |

As contas estatísticas passam para os indutores de alocação em vez do razão, e aparecem como movidas, não como um problema.

### Dados do ERP e ficheiros em conjunto

Um ficheiro substitui apenas o que abrange, e as restantes linhas do ERP mantêm-se.

- Os **ficheiros mestre** (contas, departamentos, clientes, produtos e Valores de segmento) substituem as linhas do ERP com o mesmo código.
- Os **ficheiros de transações** substituem as linhas do ERP da mesma entidade e do mesmo mês. Os ficheiros de razão geral e de balancete também correspondem por livro razão, os ficheiros de orçamento por cenário e os ficheiros de indutores estatísticos por cenário e indutor.

Se um ficheiro deixar de abranger um mês, os dados do ERP desse mês regressam no carregamento seguinte.

## Mapeamento de entidades

Cada origem designa as suas entidades com códigos próprios. O **Mapeamento de entidades** faz corresponder esses códigos às entidades do mestre de entidades, para que as linhas de todas as origens fiquem na mesma entidade.

Para o utilizar, adicione um ficheiro CSV ou Excel e escolha o conjunto de dados **Mapeamento de entidades**:

| Coluna | Contém |
|---|---|
| `source_entity` | O código tal como a origem o apresenta, como um código de empresa. |
| `entity` | A entidade a que pertence, tal como o mestre de entidades a designa. |

- Um código que não consta do mapeamento é utilizado tal como está.
- Vários códigos podem corresponder a uma só entidade. As suas linhas são combinadas, e um mês conta como fechado quando está fechado para todos eles.
- Os códigos do mapeamento aplicam-se a todas as origens, pelo que os códigos de entidade de cada origem têm de ser únicos entre origens.
- Uma linha de um ficheiro **Entidades** substitui a entidade do ERP com o mesmo código de entidade.

A verificação **Entidades não mapeadas** assinala qualquer linha cuja entidade não conste do mestre de entidades nem esteja associada a uma pelo mapeamento de entidades. Enquanto não for carregado um mestre de entidades, apresenta **– Não aplicável**.

## Mapear códigos entre origens

Duas origens podem usar o mesmo código para coisas diferentes, ou códigos diferentes para a mesma coisa. Quando um código aparece em mais do que uma origem, o Data Foundation retém as respetivas linhas até indicar se significa o mesmo em todas, para que cada montante seja contado uma só vez. A verificação **Codes waiting for your answer** lista-os, os primeiros 10 e depois "e mais K", e o cartão **What to do next** do separador **Base** tem um botão **Rever**.

**Rever** abre **Codes waiting for your answer**. Agrupa os códigos pelo que são: **Account types**, **Companies**, **Accounts**, **Departments**, **Profit centers**, **Customers**, **Products** e cada categoria adicional. Para cada código, mostra como cada origem o designa e uma sugestão:

- **Looks like the same thing** quando as origens atribuem o mesmo nome ao código.
- **Looks like different things** quando os nomes diferem.
- **We can't tell. Please answer.** quando não há nada em que basear a decisão.

Responda a um código de cada vez com **Yes, the same** ou **No, different**, ou responda a um grupo inteiro de uma só vez com **Accept all** (aceitar todas as sugestões), **All the same** ou **All different**. Nas contas, também pode responder a um grupo-pai inteiro do plano de contas de uma só vez. Quando uma origem não tem tipos de conta, escolha **Use this type** para um grupo de contas: **Receita**, **Cost of goods sold**, **Operating expenses**, **Non-operating income and expenses**, **Assets**, **Liabilities** ou **Equity**.

Os mapeamentos são mantidos por origem e dimensão, pelo que uma resposta para os departamentos de uma origem nunca altera as contas de outra. As respostas são guardadas à medida que avança, com **Saved. Press Apply changes to use your answers.** Clique em **Apply changes** para as utilizar.

Também pode fornecer os mapeamentos num ficheiro. Adicione um ficheiro com o conjunto de dados **Code map** e escolha **Which source do these rows apply to?** para o limitar a uma origem.

## Escolher que origem conta a partir de que mês

Quando duas origens fornecem os mesmos meses, a verificação **Which source covers which months** pede-lhe que escolha. Clique em **Choose which source counts from when** no cartão **What to do next** para abrir **Which source counts from when**, que lista cada sobreposição por empresa. Escolha a origem que conta, introduza o mês a partir do qual conta em **That month is**, por exemplo `2026-04`, e clique em **Apply changes**. A outra origem mantém os meses anteriores.

A mesma caixa de diálogo avisa quando duas origens indicam taxas de câmbio diferentes para uma moeda; são utilizadas as taxas da origem mais acima na ordem.

## Conversão de moedas

Cada carregamento converte os montantes do razão geral, do balancete, das vendas, do inventário e do orçamento da respetiva moeda local para uma única moeda de relato. Os relatórios e os modelos de cálculo leem os montantes convertidos, pelo que as entidades com moedas diferentes, de qualquer sistema, somam corretamente.

### A moeda de relato

Para escolher a moeda de relato, defina a variável de projeto `reporting_currency` com um código de moeda como `USD`. Consulte [Gerir variáveis do projeto](/pt-pt/guides/projects/managing-projects/#gerir-variáveis-do-projeto). O modelo cria-a em branco. Enquanto estiver em branco, cada carregamento usa a primeira das seguintes que indique exatamente uma moeda:

1. A moeda do grupo das entidades.
2. A moeda local das entidades de topo, as que não têm entidade-mãe.
3. A moeda local dos ficheiros.

Se nenhuma indicar exatamente uma moeda, **Conversão de moedas** mostra um problema até definir `reporting_currency`.

Os montantes que já estão na moeda de relato mantêm-se como estão, pelo que um projeto cujos dados estão todos numa só moeda não precisa de taxas.

Os ficheiros de vendas, inventário e orçamento também podem incluir uma moeda. Mapeie uma coluna com o nome `Currency` ou `Local Currency` e esta é detetada automaticamente, e os montantes locais do ficheiro são convertidos para a moeda de relato. Um montante do grupo ou de relato que já conste do ficheiro é mantido como está. O custo padrão do produto não é convertido.

### Taxas de câmbio

Uma taxa converte uma unidade de uma moeda na moeda de relato para um mês: o montante convertido é o montante local multiplicado pela taxa.

- **A partir do ERP**, cada carregamento lê as taxas de câmbio que o ERP contém.
- **A partir de um ficheiro**, adicione um ficheiro CSV ou Excel e escolha o conjunto de dados **Taxas de câmbio**. Uma taxa do ficheiro substitui a taxa do ERP para as mesmas moedas e o mesmo mês. Utilize um ficheiro para relatar numa moeda para a qual os ERP não publicam taxas, ou para acrescentar taxas planeadas para os meses de orçamento.

| Coluna | Contém |
|---|---|
| `from_currency` | A moeda de origem da conversão, por exemplo `EUR`. |
| `to_currency` | A moeda de relato, por exemplo `USD`. |
| `period` | O mês, como `YYYY-MM`. |
| `average_rate` | A taxa média do mês. |
| `closing_rate` | A taxa no fim do mês. |
| `historical_rate` | A taxa histórica, para o capital próprio e para as contas definidas com a taxa histórica. |

Só são utilizadas as taxas para a moeda de relato. Uma taxa cotada no sentido inverso, da moeda de relato para outra moeda, não é invertida.

### Que taxa se aplica

Cada linha é convertida a partir da sua própria moeda, pelo que uma linha numa moeda diferente da da sua entidade é convertida a partir da moeda em que está. Aplica-se a primeira regra que corresponder à linha:

| Linha | Taxa |
|---|---|
| Contas estatísticas e contas sem lançamentos | Não convertida. |
| Já na moeda de relato | Não convertida. |
| Conta com um tipo de taxa | Essa taxa: média, de fecho ou histórica. A histórica recorre à de fecho quando não existe taxa histórica. Num ERP, o tipo de taxa é o tipo de taxa da própria conta. Num ficheiro de plano de contas, mapeie uma coluna de tipo de taxa para `fx_rate_type` com `average`, `closing` ou `historical`. |
| Linha de vendas | A taxa média do período. |
| Saldo de inventário | A taxa de fecho do período. |
| Linha de orçamento | Por conta, como no razão geral: a taxa média para as contas da demonstração de resultados e a taxa de fecho para as contas do balanço. |
| Conta da demonstração de resultados | A taxa média do período. |
| Conta de capital próprio | A taxa histórica, ou a taxa de fecho quando não existe taxa histórica. |
| Qualquer outra conta do balanço | A taxa de fecho do período. |

Os montantes convertidos não são arredondados, pelo que os totais não se desviam.

<Aside type="note">
O balancete contém os movimentos de cada período, pelo que os montantes do balanço são os movimentos de cada mês convertidos à taxa de fecho desse mês. Não são um balanço reconvertido à taxa do fim do período, e não existe ajustamento de conversão acumulado nem eliminação intragrupo. Utilize os montantes convertidos para a demonstração de resultados.
</Aside>

## Hierarquias

Cada carregamento reconstrói as dimensões a partir dos dados mestre de todas as origens. Existem inicialmente sete dimensões e até dez categorias adicionais:

| Dimensão | Construída a partir de |
|---|---|
| **Entidade** | Entidades e respetivas entidades-mãe |
| **Conta** | Plano de contas e contas-mãe |
| **Departamento** | Departamentos e respetivos departamentos-mãe |
| **Cliente** | Clientes e respetivos clientes-mãe |
| **Produto** | Produtos e respetivos produtos-mãe |
| **Segmento 1** | Valores de segmento para `segment_1` |
| **Segmento 2** | Valores de segmento para `segment_2` |
| **Segmento 3** a **Segmento 10** | Valores de segmento para `segment_3` a `segment_10`, quando as origens os incluem |

- Um registo sem registo-mãe, ou que se indica a si próprio como registo-mãe, é carregado como membro de topo.
- Como cada carregamento reconstrói as hierarquias, altere um registo-mãe no ERP ou no ficheiro, não na dimensão.
- Um problema numa hierarquia afeta apenas essa dimensão. O carregamento e os modelos de cálculo do modelo de projeto continuam a ser concluídos.
- Pode mudar o nome de cada categoria adicional para o que contém, por exemplo **Classe** ou **Região**. Em **Rename extra categories**, introduza os nomes que os relatórios utilizam e clique em **Save names**. Os nomes usam letras, números, espaços, pontos, hífenes e carateres de sublinhado, até 60 carateres.
- Cada origem indica sob que nome das suas categorias cada uma das suas categorias adicionais se enquadra. Abra **Avançado** na origem, escolha o nome para cada uma, ou escolha **Leave out**, e clique em **Guardar**. As origens que designam uma categoria com nomes diferentes, como `Class` e `Business area`, passam então a partilhar uma posição.

Para fornecer hierarquias de segmentos a partir de um ficheiro, escolha o conjunto de dados **Valores de segmento**:

| Coluna | Contém |
|---|---|
| `segment` | O segmento a que o valor pertence: `segment_1` a `segment_10`. |
| `segment_value` | O valor, tal como as linhas do razão geral, das vendas e do orçamento o apresentam. |
| `segment_value_name` | O respetivo nome. |
| `parent_segment_value` | O respetivo valor-mãe dentro do mesmo segmento. |

## Verificações de prontidão

Após cada carregamento, a grelha **Prontidão** lista todas as verificações de todas as entidades e períodos, com um dos seguintes estados:

| Estado | Significado |
|---|---|
| **● Pronto** | A verificação foi aprovada. |
| **▲ Requer atenção** | Merece uma análise, mas os números são utilizáveis. |
| **■ Problema** | Corrija antes de confiar nos resultados. |
| **– Não aplicável** | Ainda não existem dados para esta verificação. |

As verificações são:

| Verificação | O que confirma |
|---|---|
| **Dados carregados** | Todos os períodos fiscais têm linhas do razão geral e todas as leituras do ERP foram bem-sucedidas. Um período fechado sem linhas é um problema; um período aberto sem linhas requer atenção. |
| **O balancete coincide com o razão geral** | O balancete é igual ao razão geral para cada entidade, período e conta. Quando o balancete e o razão geral incluem departamentos para uma conta, também verifica cada departamento. |
| **Vendas coincidem com o razão geral** | As linhas de vendas são iguais às contas de receita e de COGS do razão geral para cada período. |
| **Produtos/clientes desconhecidos** | Todas as linhas de vendas indicam um produto e um cliente que existem nos mestres de produtos e de clientes. |
| **Contas em falta no plano de contas** | Todas as linhas do razão geral indicam uma conta do plano de contas. As linhas com uma conta desconhecida ficam fora da demonstração de resultados. Uma conta com lançamentos mas sem tipo de conta também é um problema, e uma origem cujo plano de contas tem contas de receita mas nenhuma conta de custo das mercadorias vendidas requer atenção. |
| **Conversão de moedas** | Todas as linhas do razão geral, balancete, vendas, inventário e orçamento têm um montante na moeda de relato. Uma linha da demonstração de resultados ou de vendas sem taxa é um problema, porque a demonstração de resultados lê montantes convertidos. Uma linha do balanço, do inventário ou do orçamento sem taxa requer atenção. Um mês de orçamento ainda sem taxa aparece a âmbar, pelo que deve carregar taxas planeadas para os meses de orçamento. Consulte [Conversão de moedas](#conversão-de-moedas). |
| **Entidades não mapeadas** | Todas as linhas do razão geral, balancete e vendas indicam uma entidade do mestre de entidades, diretamente ou através do mapeamento de entidades. Não aplicável até ser carregado um mestre de entidades. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |

Os carregamentos com mais do que uma origem acrescentam estas verificações:

| Verificação | O que confirma |
|---|---|
| **Reporting book** | Uma origem que contém vários livros contabilísticos para uma entidade teve o livro de relato escolhido. Até escolher, só conta o primeiro livro. |
| **Codes waiting for your answer** | Todos os códigos usados por mais do que uma origem foram respondidos. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| **Extra categories from your sources** | Todas as categorias adicionais que uma origem contém têm um nome ou foram excluídas. |
| **Which source covers which months** | Duas origens não fornecem os mesmos meses de uma empresa, a não ser que tenha escolhido qual conta. |
| **Account types and hierarchy** | Todos os registos-mãe que uma dimensão indica existem, e nenhum membro é o seu próprio registo-mãe ou ascendente. Um registo-mãe em falta coloca os seus filhos no topo da hierarquia, e um ciclo impede o carregamento dessa hierarquia. Os totais não são afetados. |
| **Calendário fiscal** | Os períodos fiscais de cada entidade são meses civis, e todos os meses de linhas podem ser colocados num período fiscal. Requer atenção quando os períodos de uma entidade não são meses civis (4-4-5, 13 períodos), ou quando as linhas de um mês podem estar em mais do que um período fiscal ou o calendário fiscal não inclui o mês. |

Cada linha que não está pronta indica o que fazer na coluna **O que fazer**, como carregar o plano de contas, carregar taxas de câmbio ou executar **Carregar** novamente para um período.

A grelha também mostra duas verificações de configuração, que só aparecem quando requerem atenção:

| Verificação | Quando aparece |
|---|---|
| **Imputação de custos indiretos** | Apenas uma das variáveis de projeto `overhead_department` e `overhead_driver` está definida, ou nenhum indutor de alocação corresponde a `overhead_driver`, pelo que a alocação não faria nada. Defina ambas, ou limpe ambas para desativar a imputação de custos indiretos. |
| **Comparação com o orçamento** | Estão carregadas linhas de orçamento, mas nenhuma pertence à versão que a variável de projeto `budget_version` indica, pelo que a comparação com o orçamento ficaria vazia. |

## Consolidação de gestão

Cada carregamento cria uma consolidação de gestão: a demonstração de resultados do grupo de todas as entidades do grupo, na moeda de relato, com as operações intragrupo eliminadas. Destina-se ao relato de gestão. O sistema de consolidação continua a ser o registo do grupo estatutário; reconcilie com ele conforme indicado abaixo.

<Aside type="note">
A consolidação de gestão abrange apenas a demonstração de resultados. Não é uma consolidação estatutária ou legal, e não tem balanço consolidado, ajustamento de conversão, goodwill nem interesses minoritários.
</Aside>

### Escolher o grupo

Em **Origens**, abra **Grupo** para ver as empresas do grupo. Uma empresa que desassinalar continua nos relatórios por si só, mas fica de fora do total do grupo. Clique em **Save group**. A alteração aplica-se no próximo **Carregar** ou **Apply changes**. Uma nova empresa pertence ao grupo até a desassinalar.

O ano fiscal do grupo começa no mês definido pela variável de projeto `group_fy_start_month`, que é `1` se não a alterar.

### O que obtém

| Tabela | Contém |
|---|---|
| **Group P&L** | Uma linha por entidade, período e rubrica (receita, custo das mercadorias vendidas, gastos operacionais, não operacional, diferença intragrupo), na moeda de relato. A receita e os custos mantêm o seu sinal natural. |
| **Group P&L year to date** | O mesmo, acumulado no ano, até ao último período do grupo totalmente carregado. |
| **Intercompany pairs** | Uma linha por par de entidades, grupo e período, com o montante de cada lado e o resíduo. |
| **Intercompany lines** | As linhas do razão por trás de um valor do grupo ou de um par, com o parceiro comercial. |
| **Reconciliação** | A demonstração de resultados do grupo acumulada no ano face ao sistema de consolidação. |

Aparecem três nomes de entidade nestas tabelas:

| Entidade | Significado |
|---|---|
| **Eliminations** | As eliminações intragrupo. Totalizam zero, pelo que deve mantê-las para os valores do grupo e filtrá-las para obter a soma das entidades antes da eliminação. |
| **Group total** | O total do sistema de consolidação, na reconciliação. |
| **Unmapped** | Linhas sem período, e contas ou entidades do sistema de consolidação que este projeto não tem. |

Os indicadores **Consolidated income**, **Consolidated result** e **IC difference**, e um caminho de análise para cada tabela, respondem a perguntas sobre o grupo.

### Eliminações intragrupo

As linhas intragrupo são emparelhadas por parceiro comercial. É utilizado o parceiro da linha; quando a linha não tem nenhum, é utilizado o parceiro do respetivo cliente. Os dois lados de um par são eliminados, e o montante pelo qual os dois lados não coincidem é registado numa linha de diferença intragrupo. Cada par recebe um motivo:

| Motivo | Significado |
|---|---|
| **Matched** | Os dois lados registaram o mesmo montante. |
| **Only one side booked** | Uma entidade registou a transação e o parceiro não. |
| **Not eliminated** | Uma linha do par não tem taxa de câmbio, pelo que nenhum dos lados é eliminado. |

Um par é avaliado no acumulado do ano. A linha **Intercompany balances** fica a âmbar quando a diferença de um par excede a variável de projeto `group_amber` (predefinição `1`) e a vermelho acima de `group_red` (predefinição `1000`). As linhas sem parceiro, ou com um parceiro que não é uma entidade, não são eliminadas e são contadas nessa linha. Uma origem que contém parceiros ao lado de outra que não os contém fica a âmbar.

As entidades de eliminação próprias de uma origem ficam fora da demonstração de resultados do grupo, e a linha **Consolidação** indica-o.

### Reconciliar com o sistema de consolidação

Adicione como ficheiro os resultados que o sistema de consolidação comunica e assinale **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** quando confirmar a respetiva correspondência. Responda a **Which version of the numbers is this?** com o nome do sistema. A tabela **Reconciliação** mostra então **ours**, **reported** e **diferença** para cada entidade e rubrica, acumulado no ano. Uma diferença é normalmente explicada nas linhas **Eliminations**, **Group total** e **Unmapped**, ou pelas taxas de câmbio que o sistema utiliza. A linha **Reconciliation to the source** lista todas as rubricas acima de `group_amber`.

### Quem pode ver

Os resultados do grupo seguem o acesso a linhas do projeto. Quando o acesso a linhas impede os resultados do grupo, o estado aparece a âmbar. Quem vê apenas algumas entidades vê as somas dessas entidades antes da eliminação. As linhas **Eliminations** e as tabelas intragrupo exigem acesso a todas as entidades.

Se o projeto limitar quem vê que linhas através de uma coluna que as tabelas do grupo não incluem, como o departamento, os resultados do grupo ficam desativados para todos e **Consolidação** indica **Group views are off**. Só um Arquiteto pode então assinalar **Everyone on the project may see the group results** em **Grupo**. A alteração aplica-se no próximo **Carregar** ou **Apply changes**.

## Manter atualizado

Depois de um carregamento a partir da ligação ao ERP ter êxito sem problemas, aparece **Atualizar todas as noites** no cartão **Último carregamento**. Clique nessa opção para executar **Carregar** todas as noites às 2:00 no seu fuso horário. O cartão passa a mostrar **Nightly refresh: Every night at 2:00** e quem a configurou.

O carregamento noturno é executado como a pessoa que o configurou. Se essa pessoa deixar de poder utilizar a ligação ao ERP, a grelha indica que o carregamento noturno é ignorado; configure-o novamente. Um projeto que só tem dados de exemplo não pode ser agendado.

Um ficheiro em falta ou vazio num carregamento noturno termina com um aviso que indica o caminho, não com um erro, e o resto do modelo é carregado na mesma.

## Nomes de negócio

Os **Business names** do separador **Base** dão aos códigos do modelo os nomes que o negócio utiliza. Os relatórios, os indicadores e o assistente mostram estes nomes, e um nome guardado aplica-se de imediato. Os carregamentos seguintes mantêm-no.

1. Clique em **Add a name** e escolha o **Tipo**: **Categoria**, **P&L line**, **Metric** ou **Coluna**.
2. Introduza o **Código**: `segment_1` a `segment_10` para uma categoria, a chave da rubrica para uma rubrica da demonstração de resultados, o nome do indicador, ou `table.column` para uma coluna.
3. Introduza o **Nome**, com um máximo de 60 carateres numa só linha.
4. Clique em **Save names**.

Guardar substitui a lista inteira. Uma linha com o nome vazio remove esse nome, e **Remover selecionados** remove as linhas que assinalar. Atribuir o mesmo código duas vezes é recusado. Os nomes de negócio também são escritos na descrição do caminho de análise para que o assistente use as suas palavras, e essa descrição tem um limite de tamanho: se um nome a tornar demasiado longa, nada é guardado e é informado disso.

## Explicar um número

**Explain this number** mostra o que compõe um valor da demonstração de resultados. Na grelha **Prontidão**, uma linha de uma entidade e mês tem **Explain this number**, que abre a margem operacional da entidade nesse mês. A janela divide o número em camadas cuja soma é o total no topo:

| Camada | O que contém |
|---|---|
| **From the general ledger** | O que o razão lançou na rubrica. |
| **Allocated in** | Custo distribuído por esta entidade pelas suas [regras de alocação](#regras-de-alocação). |
| **Allocated out** | Custo que esta entidade distribuiu por outras. |
| **Eliminated in the group** | Operações intragrupo eliminadas no resultado do grupo. |

Cada camada tem uma frase que diz o que é e os seus maiores documentos de origem, com o respetivo sistema de origem, documento e conta. Só são mostradas as camadas que têm linhas. A janela segue o seu acesso a linhas: só pode explicar os valores que consegue ver. Um número sem nada por trás indica **Nothing to explain**.

## Regras de alocação

As alocações distribuem custos partilhados, como os custos indiretos, por departamentos, produtos e clientes. O modelo tem duas fases: **Stage 1: overhead to departments** e **Stage 2: departments to products and customers**. Abra **Ações > Alocações...** para ver ou alterar a forma como cada uma é feita. Sem alterações, funcionam como funcionavam antes de existir o assistente. Um leitor pode abrir as regras, mas não as guardar.

Para cada fase, o assistente faz quatro perguntas:

| Passo | Pergunta | Opções |
|---|---|---|
| **Pool** | Que custos pretende distribuir? | O tipo de conta e, na fase 1, o departamento que contém o custo, ou **All departments**. |
| **Indutor** | Segundo que critério pretende distribuí-los? | **Statistic** que carregou como indutores de alocação, como número de colaboradores ou metros quadrados, **Net sales amount**, **Sales quantity** ou **Spread evenly**. Utilize o indutor de **Same period** ou **Same period last year**. |
| **Destino** | Onde ficam? | Fase 1: departamentos. Fase 2: produtos, clientes ou ambos. |
| **Método** | O que acontece quando um indutor é negativo? | **Ignore negative values** ou **Stop and tell me**. |

Por baixo dos passos, **Preview for** um mês, escrito como ano e mês, como `2026-09`, mostra o que as regras, incluindo as que ainda não guardou, fariam: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Tudo o que não está alocado é custo que não teve indutor para o absorver. A pré-visualização segue o seu acesso a linhas.

Clique em **Guardar**. As regras entram em vigor no próximo **Carregar**, ou quando clicar em **Apply changes**. Se tiver editado manualmente um passo de alocação, a sua edição é mantida, não substituída, e a gravação indica-o. Não pode guardar enquanto um carregamento estiver em curso.

## Pacote para o conselho de administração

Um pacote para o conselho de administração escreve os resultados numa pasta de uma conta de documentos, de forma agendada, pronto a enviar. Abra **Ações > Board pack...**, escolha uma **Conta de documentos** e uma **Pasta**, como `/board-packs`, e clique em **Guardar**. Cada execução escreve:

- Um livro Excel, `Board pack.xlsx`, com a demonstração de resultados por entidade, uma ponte de margem e os melhores e piores clientes.
- Um PDF do painel de controlo da demonstração de resultados.

Se o projeto ainda não tiver um painel de controlo, o livro é escrito sozinho e a execução indica o motivo. Clique em **Run now** para criar um pacote de imediato; os respetivos ficheiros aparecem na pasta quando termina. O cartão mostra a última execução e o seu resultado, e a próxima execução. O pacote é criado pelo fluxo de trabalho **Board pack** do projeto, que a atualização noturna não executa: para o criar de forma agendada, agende esse fluxo de trabalho com o [agendador de eventos](/pt-pt/administration/scheduled-events/event-scheduler/), por exemplo para uma hora posterior ao fim da atualização noturna. Só quem pode alterar o projeto o configura.

## Pontos de restauro

Um ponto de restauro é criado quando cada **Carregar** ou **Apply changes** começa, seja quem for que o inicia, incluindo um carregamento agendado, e antes de cada alteração a mapeamentos ou origens. Contém as tabelas do modelo, as dimensões e as definições a partir das quais o carregamento seguinte constrói: as origens, os ficheiros e as regras de alocação. São mantidos os últimos sete pontos criados para carregamentos e os últimos cinco criados antes de alterações, pelo que as alterações nunca eliminam os pontos criados para carregamentos. Os pontos mais antigos vão sendo descartados.

Para voltar atrás, abra **Ações > Restaurar...**, escolha um ponto e clique em **Restaurar**. **Restaurar** é apresentado assim que existe um ponto. Restaurar começa por registar o projeto tal como está agora como um ponto próprio, para que possa voltar atrás novamente. Depois repõe as tabelas, as dimensões e essas definições como estavam, e o carregamento seguinte constrói a partir delas. Uma tabela sem cópia guardada, ou um motor que não consegue guardar histórico, é indicado num aviso e o resto é restaurado. Um ponto de restauro que já foi descartado é recusado, e não pode restaurar enquanto um carregamento estiver em curso.

## Clonar um projeto

**Ações > Clonar...** copia o projeto com o nome que indicar. A cópia mantém o modelo de projeto, as suas edições ao modelo de cálculo, e os seus indicadores e caminhos de análise, e carrega os dados de exemplo. As origens não ficam ligadas, pelo que deve ligá-las na cópia antes de carregar. Pode continuar a trabalhar enquanto a cópia é feita, e **Abrir projeto** leva-o até ela quando estiver pronta.

## Guardar como o meu modelo

Guarde a configuração de um projeto para a reutilizar no cliente ou na entidade seguinte. Abra **Ações > Save as my template...**, escolha a conta de documentos e dê um nome ao ficheiro. Se o omitir, é acrescentado um nome que termina em `.zip`. Guardar por cima de um ficheiro existente é recusado, pelo que deve escolher outro nome.

O ficheiro contém a estrutura do projeto, as suas edições ao modelo de cálculo, os indicadores e caminhos de análise, os nomes de negócio das entidades e das contas, e as linhas das tabelas de configuração do modelo, como o mapa de atividades do [Cost to Serve](/pt-pt/guides/projects/cost-to-serve/) ou os intervalos de política do [Operational Transfer Pricing](/pt-pt/guides/projects/operational-transfer-pricing/). Não inclui ligações, ficheiros, o agendamento noturno, execuções, pontos de restauro, o pacote para o conselho de administração nem quem tem acesso.

Para o utilizar, crie um projeto, escolha **From a template file...** em **Começar a partir de** e indique a conta de documentos e o caminho. O novo projeto é privado, com todas as origens a aguardar ligação. Uma versão posterior do modelo integra as suas alterações em torno dos passos que editou. Se não existir nenhum ficheiro no caminho, nada é criado e é informado disso. Qualquer pessoa que consiga ler a conta de documentos pode instalar a partir do ficheiro. Para o utilizar noutra área de trabalho, transfira o ficheiro e carregue-o aí.

## Resolver perguntas em aberto com o Ask

Após um carregamento, um projeto ainda pode estar à espera de ser informado de três coisas: contas às quais o plano de contas não atribui tipo, códigos usados por mais do que uma origem e colunas dos ficheiros que não corresponderam a nada. Peça ao assistente que as resolva: a partir de um assistente de IA através de MCP, utilize o prompt **Resolve Data Foundation residue**. Lê o que está pendente e propõe uma resposta para cada item, com um motivo.

O assistente não escreve nada. Aplica as respostas dele onde teria respondido pessoalmente: contas e códigos em **Codes waiting for your answer**, e colunas de ficheiros na correspondência do ficheiro. Nunca propõe uma entidade.

## Entregar o projeto

A lista de verificação de **Configuração** tem quatro itens finais depois de **Reveja as suas hierarquias**:

- **Set up the nightly refresh** fica concluído assim que **Atualizar todas as noites** estiver ativo.
- **Partilhar com a sua equipa** fica concluído assim que alguém além de quem configurou o projeto for membro.
- **Download the evidence pack** fica concluído quando transfere o pacote após o último carregamento bem-sucedido.
- **Hand the project over to its owner** fica concluído assim que existir um Arquiteto diferente de quem configurou o projeto e os totais coincidirem. Enquanto não estiver concluído, a lista de verificação indica o que fazer: tornar o proprietário do cliente Arquiteto deste projeto e, depois, remover-se a si próprio dos respetivos membros.

A lista de verificação indica quem configurou o projeto (**Set up by**).

## Criar sobre o modelo com um modelo de projeto

Um modelo cria os seus relatórios e modelos de cálculo sobre o Common Finance Model, pelo que funcionam da mesma forma, sejam quais forem os ERP que o alimentam. Quando inicia um projeto a partir de um modelo, como o **Enterprise Profitability**, este cria:

- As [tabelas do Common Finance Model](#tabelas-do-common-finance-model), vazias ou preenchidas com dados de exemplo.
- As dimensões **Entidade**, **Conta**, **Departamento**, **Cliente**, **Produto**, **Segmento 1** e **Segmento 2**, construídas a partir dessas tabelas. Consulte [Hierarquias](#hierarquias).
- O fluxo de trabalho **Carregar** e os fluxos de trabalho que este executa para ler o ERP e os ficheiros, harmonizá-los, verificar a prontidão e criar os modelos de cálculo do modelo.
- Os relatórios e modelos de cálculo próprios do modelo. O **Enterprise Profitability** acrescenta uma tabela de demonstração de resultados com receita, COGS, margem bruta, gastos operacionais diretos e indiretos, contribuição e margem operacional, além de pontes de margem ano a ano e face ao orçamento.
- Indicadores e um caminho de análise para colocar perguntas sobre os resultados.

Estão disponíveis três modelos em **Começar a partir de**, todos assentes no mesmo modelo de dados:

| Modelo | Acrescenta |
|---|---|
| **Enterprise Profitability** | A demonstração de resultados e as pontes de margem. |
| **Cost to Serve** | O custo de servir cada cliente e a margem depois dele. Consulte [Cost to Serve](/pt-pt/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | O nível de lucro de cada entidade face ao intervalo da política, e o ajustamento. Consulte [Operational Transfer Pricing](/pt-pt/guides/projects/operational-transfer-pricing/). |

**From a template file...** começa a partir de um projeto que guardou. Consulte [Guardar como o meu modelo](#guardar-como-o-meu-modelo).

Para explorar antes de ligar o seu próprio ERP, assinale **Começar com dados de exemplo** quando criar o projeto. O projeto executa de imediato um primeiro Carregar, pelo que o separador **Base** mostra um exemplo completo, incluindo uma entidade em euros convertida para dólares americanos. Quando ligar o seu próprio ERP ou adicionar os seus próprios ficheiros, as linhas de exemplo são limpas e os seus dados tomam o lugar delas.

## O separador Base

O separador **Base** é onde liga, carrega e verifica os dados. Tem estas secções, de cima para baixo:

| Secção | O que mostra |
|---|---|
| **Último carregamento** | Se o último carregamento teve êxito, falhou ou ainda decorre, com os botões **Carregar**, **Apply changes**, **Atualizar** e **Atualizar todas as noites**. |
| **What to do next** | O que requer atenção, por ordem de importância, cada um com um botão **Rever** ou **Choose which source counts from when**. |
| **Origens** | Cada origem por ordem, com **Avançado**, **Remove this source**, **Grupo** e **Rename extra categories**. |
| **Configuração** | A lista de verificação de configuração: **Ligar os seus dados**, **Carregue os seus dados**, **Verificar se os totais coincidem**, **Reveja as suas hierarquias**, **Set up the nightly refresh**, **Partilhar com a sua equipa**, **Download the evidence pack** e **Hand the project over to its owner**. O item atual está a negrito. |
| **Business names** | Os nomes que o negócio utiliza para categorias, rubricas da demonstração de resultados, indicadores e colunas. Consulte [Nomes de negócio](#nomes-de-negócio). |
| **Ficheiros** | Cada ficheiro que adicionou, o respetivo conjunto de dados, como **Razão geral** ou **Taxas de câmbio**, e se a correspondência está **✓ Confirmado** ou **○ A aguardar confirmação**. |
| **Dados carregados** | Para cada entidade, o primeiro e o último período carregados e quantos períodos estão prontos. |
| **Períodos** | Os períodos fiscais de cada entidade e se cada um está **✓ Fechado** ou **○ Aberto**. |
| **Prontidão** | A grelha de prontidão: uma linha por entidade, período e verificação, com o respetivo estado e **O que fazer**. |
| Ligação | Ligue o ERP, escolha as entidades e quantos meses de histórico carregar, ou adicione outra origem. |
| **Ficheiros** (adicionar) | Adicione um ficheiro CSV, TSV, TXT, Excel ou Parquet e confirme como as colunas são mapeadas. |
| **Carregar** | Inicie um carregamento. **Apply changes** executa um sem obter dados dos ERP. |

Enquanto um carregamento decorre, o separador atualiza-se automaticamente.

A lista de verificação de configuração acompanha o seu progresso:

- **Ligar os seus dados** e **Carregue os seus dados** ficam assinalados automaticamente assim que uma origem é associada e um carregamento tem êxito.
- **Verificar se os totais coincidem** fica assinalado automaticamente quando as verificações de coincidência são aprovadas.
- **Reveja as suas hierarquias**: clique em **Abrir dimensões** para rever as hierarquias de Entidade, Conta e Departamento e depois assinale **Já os revi**. Este item é confirmado por si.
- **Set up the nightly refresh**, **Partilhar com a sua equipa**, **Download the evidence pack** e **Hand the project over to its owner** fecham a lista. Consulte [Entregar o projeto](#entregar-o-projeto) e [Gerir o acesso ao projeto](/pt-pt/guides/projects/managing-projects/#gerir-o-acesso-ao-projeto).

O menu **Ações** contém **Alocações...**, **Board pack...**, **Clonar...**, **Restaurar...** e **Save as my template...**. Consulte [Regras de alocação](#regras-de-alocação), [Pacote para o conselho de administração](#pacote-para-o-conselho-de-administração), [Clonar um projeto](#clonar-um-projeto), [Pontos de restauro](#pontos-de-restauro) e [Guardar como o meu modelo](#guardar-como-o-meu-modelo).

## Tabelas do Common Finance Model

O Data Foundation harmoniza todas as origens, ERP ou ficheiro, nas mesmas quinze tabelas, pelo que os relatórios, indicadores e modelos de cálculo criados sobre elas funcionam da mesma forma, seja qual for a origem. Cada linha também regista o sistema de origem e quando foi lida. A coluna **Conjunto de dados** é o nome que escolhe ao adicionar um ficheiro.

| Conjunto de dados | Tabela | Contém |
|---|---|---|
| Entidades | `cfm_entity` | Entidades legais com entidade-mãe, moeda local e do grupo, e país. |
| Mapeamento de entidades | `cfm_entity_map` | Códigos de entidade da origem e a entidade a que cada um pertence. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |
| Taxas de câmbio | `cfm_fx_rate` | Taxas mensais média, de fecho e histórica por par de moedas. Consulte [Taxas de câmbio](#taxas-de-câmbio). |
| Calendário fiscal | `cfm_fiscal_calendar` | Uma linha por período fiscal de cada entidade, com datas de início e fim e se está fechado. |
| Plano de contas | `cfm_account` | Contas com conta-mãe, tipo (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), demonstração financeira, saldo normal e tipo de taxa. |
| Departamentos | `cfm_department` | Departamentos e centros de custo com departamento-mãe e centro de lucro. |
| Produtos | `cfm_product` | Mestre de produtos com produto-mãe, família, grupo, unidade de medida e custo padrão. |
| Clientes | `cfm_customer` | Mestre de clientes com cliente-mãe, grupo, região e país. Os nomes dos clientes não são mascarados. |
| Valores de segmento | `cfm_segment` | Valores de segmento com nome e valor-mãe. Consulte [Hierarquias](#hierarquias). |
| Razão geral | `cfm_gl_journal` | Linhas de diário na moeda da transação, local e de relato. |
| Balancete | `cfm_trial_balance` | Débitos, créditos e líquido do período por entidade, conta e departamento, em moeda local e de relato. |
| Linhas de vendas | `cfm_sales_line` | Linhas de vendas faturadas com quantidade, montantes bruto, desconto, líquido e COGS. |
| Saldos de inventário | `cfm_inventory_balance` | Inventário no fim do período por produto e armazém. |
| Orçamento | `cfm_budget` | Orçamento e previsão por cenário, versão, conta e departamento. |
| Indutores de alocação | `cfm_stat_driver` | Indutores estatísticos como número de colaboradores, metros quadrados ou unidades. |

Os períodos escrevem-se `YYYY-MM`, e as transações são colocadas pelo período de lançamento. O orçamento é opcional: um ERP sem orçamentos carrega na mesma tudo o resto.

Um ficheiro de balancete pode conter colunas de débito e crédito, uma coluna de líquido, ou ambas. Só com débito e crédito, o líquido é débito menos crédito, e um lado em branco conta como zero. Só com um líquido, um líquido positivo passa a débito e um líquido negativo passa a crédito, como montante positivo. Uma coluna de departamento é opcional.

## Resolução de problemas

| Sintoma | O que fazer |
|---|---|
| **Testar ligação** indica que o ERP recusou as credenciais | Verifique as credenciais da ligação e se o utilizador de integração consegue iniciar sessão no ERP. |
| **Testar ligação** mostra **Permissão em falta** para um conjunto de dados | Peça ao administrador do ERP que acrescente as permissões que são indicadas. O [guia de ligações](/pt-pt/guides/connections/) do seu ERP lista o que a ligação precisa. |
| Uma mensagem de erro do ERP é mais curta do que a do próprio ERP | O PlaidCloud remove credenciais, tokens e chaves dos erros dos fornecedores antes de os mostrar, pelo que alguns detalhes ficam de fora. Execute **Testar ligação** para ver que conjunto de dados é afetado. |
| **Dados carregados** é um problema num período | Falhou uma leitura do ERP desse período. Execute **Carregar** novamente; os períodos que foram carregados são ignorados. |
| **Contas em falta no plano de contas** é um problema | Acrescente as contas em falta ao plano de contas no ERP ou no ficheiro e execute **Carregar** novamente. |
| **Conversão de moedas** é um problema | A moeda de uma entidade não tem taxa para a moeda de relato nesse período, ou não foi encontrada uma única moeda de relato. Acrescente as taxas a um ficheiro **Taxas de câmbio**, verifique se a ligação consegue ler as taxas de câmbio do ERP, ou defina a variável de projeto `reporting_currency`. Depois execute **Carregar** novamente. |
| **Conversão de moedas** requer atenção | As linhas do balanço, do inventário ou do orçamento não têm taxa de fecho, histórica ou planeada para o período. A demonstração de resultados não é afetada. Acrescente as taxas, incluindo as taxas planeadas para os meses de orçamento, e execute **Carregar** novamente. |
| **Codes waiting for your answer** requer atenção | Clique em **Rever**, responda a cada código e clique em **Apply changes**. |
| **Which source covers which months** requer atenção | Clique em **Choose which source counts from when**, escolha a origem e clique em **Apply changes**. |
| **Intercompany balances** está a vermelho ou âmbar | Verifique os pares em **Intercompany pairs**. Registe o lado em falta, acrescente o parceiro comercial às linhas ou acrescente a taxa em falta. |
| **Group views are off** | Peça a um Arquiteto que assinale **Everyone on the project may see the group results** em **Grupo**. |
| **Entidades não mapeadas** é um problema | Acrescente a entidade ao mestre de entidades, ou mapeie o respetivo código para uma entidade existente no ficheiro **Mapeamento de entidades**, e execute **Carregar** novamente. |
