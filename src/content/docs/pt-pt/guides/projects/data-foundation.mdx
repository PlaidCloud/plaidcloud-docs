O **Data Foundation** é a base de dados financeiros dos seus projetos PlaidCloud. O respetivo **Common Finance Model** reúne os dados de vários sistemas ERP, e de várias instâncias de cada um, num único modelo: um plano de contas, um conjunto de entidades e uma moeda de relato. Os relatórios, os indicadores e os assistentes de IA criados sobre o modelo leem todos os mesmos números, qualquer que seja o ERP de origem.

O seu ERP liga-se através da respetiva ligação do PlaidCloud, pelo que o razão geral, o balancete, os dados mestre e os orçamentos chegam diretamente da origem, sem nada para exportar. Os ficheiros acrescentam dados que um sistema não contém, como taxas de câmbio, indutores de alocação ou um orçamento mantido fora do ERP, e podem substituir as linhas do ERP que abrangem. A ação **Carregar** harmoniza todas as origens no modelo, converte-as para a moeda de relato e verifica se os totais coincidem, tudo a partir do separador **Base** do projeto. Quando as origens usam o mesmo código para coisas diferentes, indica se têm o mesmo significado, e uma consolidação de gestão cria a demonstração de resultados do grupo com as operações intragrupo eliminadas. Os modelos, como o **Enterprise Profitability**, criam os seus relatórios e modelos sobre esta base.

## Ligar o ERP

O seu ERP liga-se ao Data Foundation através da respetiva ligação do PlaidCloud. O Data Foundation lê diretamente dela o razão geral, o balancete, os dados mestre, as taxas de câmbio e os orçamentos, e só efetua leituras. Pode escolher uma ligação existente ou criar uma no separador. Cada sistema tem uma página para o administrador que concede o acesso, indicada em [Que sistemas podem alimentar o modelo](/pt-pt/guides/projects/data-foundation-getting-started/#que-sistemas-podem-alimentar-o-modelo), e a [matriz de cobertura do Data Foundation](/pt-pt/reference/data-foundation-coverage-matrix/) mostra que conjuntos de dados cada sistema fornece diretamente.

<Steps>

1. No Analyze, abra **Projetos** e clique em **Novo projeto**. Introduza um nome e, em **Começar a partir de**, escolha um modelo, como **Enterprise Profitability (modelo)**, em vez de **Projeto em branco**. Clique em **Criar**.

   O projeto abre no respetivo separador **Base**. É privado e o utilizador é o seu único Arquiteto, até o partilhar.

2. No separador **Base**, escolha uma ligação existente para o seu ERP ou selecione **Criar uma nova ligação**. Cada ligação existente apresenta os fluxos de trabalho que já a utilizam ou indica **Ainda não é utilizado por nenhum fluxo de trabalho**.

3. Para uma nova ligação, introduza um **Nome da ligação**, escolha o **Ambiente** e preencha as credenciais que a ligação ao ERP pede.

   Ainda não tem as credenciais? O formulário mostra um pedido de acesso já preparado para o administrador do ERP. Clique em **Copiar pedido** ou **Enviar pedido por email**, envie-o e introduza os valores que lhe devolverem.

4. Clique em **Testar ligação**. O PlaidCloud inicia sessão e tenta ler cada conjunto de dados, e depois apresenta cada um como **Legível**, **Permissão em falta** ou **Erro**. Quando falta alguma coisa, indica as permissões que deve pedir ao administrador do ERP que acrescente.

5. Defina **Meses de histórico**: quantos meses para trás carregar, de 1 a 120. O valor predefinido é 24.

6. Para uma ligação existente, assinale as entidades a carregar ou deixe-as todas por assinalar para carregar todas as entidades. As entidades inativas e de eliminação permanecem ocultas até optar por as mostrar. Em seguida, clique em **Ligar**.

7. Para uma nova ligação, clique em **Ligar** para a criar. Depois, assinale as entidades a carregar e clique de novo em **Ligar** para as guardar. Até o fazer, são carregadas todas as entidades.

8. Para incluir outro sistema ERP ou outra instância, repita estes passos e assinale **Add this as another source instead of replacing the current one** antes de clicar em **Ligar**. Sem esta opção, a nova ligação substitui a origem atual.

</Steps>

Depois de ligado, o cartão indica que ligação, ambiente, entidades e meses de histórico o projeto carrega.

Cada carregamento lê apenas o que mudou: os períodos abertos e o último período fechado são lidos de novo, e os períodos fechados já carregados são mantidos. Aumentar os **Meses de histórico** lê apenas os meses acrescentados. Uma taxa de câmbio, um mapeamento de entidades ou uma moeda de relato alterados fazem ler de novo os meses que afetam.

## Origens

Cada sistema ERP e cada instância a partir dos quais o projeto carrega dados é uma origem. A lista **Origens** do separador **Base** mostra uma linha por origem, por ordem, com o respetivo nome, a data do último carregamento e o número de linhas fornecidas, e os livros de relato que lê, por exemplo `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Uma origem que ainda não foi carregada indica **not loaded yet**. Os ficheiros que confirma também são origens.

Abra **Avançado** numa origem para alterar a forma como é utilizada:

| Definição | O que faz |
|---|---|
| **Nome** | A etiqueta que os relatórios, as perguntas de mapeamento e as mensagens utilizam para a origem. |
| **Posição na ordem** | A posição da origem na classificação. Quando duas origens abrangem o mesmo mês da mesma empresa, prevalece a que está mais acima na ordem. |
| **Livros de relato, separados por vírgulas** | Os livros contabilísticos a ler, no caso de um sistema que mantém mais do que um. **Todos os livros de relato** lê todos os livros. |
| **Empresa**, **De (2026-01)** e **Para (2026-12)** | Os meses que esta origem fornece para cada empresa. Deixe um mês vazio para não haver limite. Escreva os meses como o ano e o mês, por exemplo `2026-03`. |

Clique em **Guardar** para manter as alterações. Para remover uma origem, clique em **Remove this source** e confirme com **Remover**. Tudo o que foi carregado a partir dela é eliminado, e pode voltar a ligá-la mais tarde.

Alterar origens não volta a ler o ERP. O cartão **Último carregamento** indica **Changes not applied yet** até clicar em **Apply changes**, que executa um carregamento a partir dos dados já obtidos: harmoniza de novo as origens com a nova ordem, os novos mapeamentos, nomes e ficheiros, e reconstrói o modelo. Clique em **Carregar** quando também pretender dados atualizados dos ERP.

## Adicionar ficheiros para dados fora do ERP

Os ficheiros complementam a ligação ao ERP com dados que um sistema não contém, como taxas de câmbio, indutores de alocação, um [mapeamento de entidades](#mapeamento-de-entidades) ou um orçamento mantido fora do ERP. Cada ficheiro pertence a um dos conjuntos de dados indicados em [Tabelas do Common Finance Model](#tabelas-do-common-finance-model).

<Steps>

1. Em **Ficheiros**, escolha a **Conta de documentos** onde guardar o ficheiro.

2. Largue um ficheiro CSV ou Excel em **Largue aqui um ficheiro CSV ou Excel** ou clique em **Escolha um ficheiro**. O ficheiro é carregado para a pasta `/foundation/` da conta de documentos.

   Para um ficheiro que já se encontra na conta de documentos, introduza o respetivo **Caminho do ficheiro**, por exemplo `/foundation/budget.csv`, e clique em **Adicionar ficheiro**.

   Para ler um novo ficheiro todos os meses, adicione todos os ficheiros de uma pasta cujo nome corresponda: introduza a pasta e o que **File names that** contain, start with, end with, match exactly or match as a pattern, e clique em **Add files**. Os ficheiros em pastas dentro dela não são lidos.

3. O PlaidCloud lê o ficheiro e propõe um mapeamento:

   - **Detected delimiter, decimal separator and dates.** O delimitador (vírgula, ponto e vírgula, tabulação ou barra vertical), o separador decimal e o formato de data são detetados automaticamente.
   - **Conjunto de dados**: a tabela do Common Finance Model a que o ficheiro pertence, determinada a partir do nome do ficheiro e dos cabeçalhos das colunas. Quando a correspondência não é clara, escolha-a na lista.
   - **Separador decimal**: **Ponto (1,234.56)** ou **Vírgula (1.234,56)**.
   - **Formato de data**: apresentado quando o ficheiro tem datas. Altere-o se o formato detetado estiver errado: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Uma grelha com **Coluna no ficheiro**, **Tipo**, **Exemplos** e **Destino**. Altere **Destino** para enviar uma coluna para um campo diferente ou para **Não carregar**.

4. Responda às perguntas que o ficheiro suscita, como **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** ou **Are revenues shown as negative numbers?** Cada uma só é colocada quando o ficheiro ainda não o indica.

5. Verifique para onde vai cada coluna e clique em **Confirmar correspondência**. Enquanto trabalha, a nota por baixo do botão explica porque está à espera. Num projeto que ainda tem os dados de exemplo, o primeiro ficheiro que confirmar também remove os dados de exemplo, o que pode demorar alguns minutos.

</Steps>

Estas opções surgem num ficheiro quando se aplicam:

| Opção | Utilize para |
|---|---|
| **Which source do these rows apply to?** | Limitar um ficheiro de mapa de códigos a uma origem. **Every source** aplica-o a todas. |
| **Where does this file come from?** | Indicar se o ficheiro contém **This project's own codes** ou provém de **Another system**, que nomeia, por exemplo `SAP Germany export`. Um ficheiro de outro sistema é verificado quanto a códigos partilhados como uma origem ERP. |
| **Split … into … parts at each …** (em **Avançado**) | Dividir uma coluna que contém vários valores, como `100-200-300`, e enviar cada parte para o seu próprio campo. |
| **Which currency do you report in?** | Definir a moeda de relato quando o projeto ainda não tem uma. Escreva-a com três letras, por exemplo `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Carregar os resultados do seu sistema de consolidação para que a demonstração de resultados do grupo possa ser [reconciliada](#reconciliar-com-o-sistema-de-consolidação). |

Para retirar um ficheiro do projeto, clique em **Remover** junto ao ficheiro em **Ficheiros**, ou em **Remove this file** no respetivo mapeamento, e confirme. Os valores do ficheiro saem dos relatórios na próxima vez que clicar em **Apply changes**.

Quando o PlaidCloud não consegue decidir sozinho o conjunto de dados, o separador decimal ou a ordem das datas, por exemplo num ficheiro cujas datas podem ser lidas como dia/mês ou mês/dia, pede-lhe que escolha antes de confirmar. Adicionar um segundo ficheiro para o mesmo conjunto de dados substitui o primeiro. Se as colunas de um ficheiro posterior não corresponderem ao conjunto de dados, o carregamento indica o ficheiro e as colunas e pede-lhe que corrija o ficheiro ou os nomes das colunas, ou que defina o **Schema Mismatch** do passo como `union`.

Os ficheiros aceites são ficheiros de texto CSV, TSV e TXT, ficheiros Excel `.xlsx` (lidos a partir da primeira folha) e ficheiros Parquet.

<Aside type="note">
Um ficheiro em falta ou vazio nunca impede um carregamento. Ao adicioná-lo, é indicado que ainda não há nada para mapear, e um carregamento termina com um aviso que indica o caminho, deixando esse conjunto de dados vazio. Adicione o ficheiro de novo quando existir.
</Aside>

## Carregar os seus dados

Clique em **Carregar** no cartão **Carregar** ou no cartão **Último carregamento**. O carregamento lê o ERP ligado e os ficheiros confirmados, harmoniza-os no Common Finance Model, converte-os para a moeda de relato, executa as verificações de prontidão e reconstrói os modelos do modelo de projeto.

- Só é executado um carregamento de cada vez por projeto. Um segundo **Carregar** ou **Apply changes** indica que já existe um carregamento em execução, e não é possível alterar origens enquanto um decorre.
- Se outros fluxos de trabalho utilizarem a mesma ligação ao ERP, o primeiro carregamento lista-os e pede confirmação, porque um carregamento lê do ERP e pode abrandar esses fluxos de trabalho. Clique em **Carregar mesmo assim** para prosseguir.
- Depois de o PlaidCloud ser atualizado, o **Carregar** de um Arquiteto também atualiza os fluxos de trabalho gerados do projeto, criando as tabelas de trabalho de que necessitem. Até lá, a página de estado lista um item âmbar, "Os fluxos de trabalho foram gerados por uma versão anterior. O Carregar de um Arquiteto atualiza-os.", e o **Carregar** de um Gestor avisa que só um Arquiteto os pode atualizar.
- Aplicar uma atualização mantém as suas próprias edições aos passos gerados. Se alterou um passo e a atualização também o alterou, a sua edição é mantida e a página de estado regista o conflito pelo nome do passo. Um passo que editou e que a atualização já não gera é mantido mas desativado; elimine-o ou volte a ativá-lo se ainda precisar dele. Um passo que a atualização substitui é indicado pelo nome, e o anterior permanece nas versões do passo.
- Se uma atualização parou a meio, ou ainda está em execução, a página de estado indica-o, e os respetivos passos podem ser executados fora de ordem até terminar. Prima **Carregar** de novo como Arquiteto para a concluir. Se parar outra vez, contacte o suporte.
- Um carregamento falhado aparece a vermelho e nunca se esconde atrás de resultados anteriores. Se a consolidação falhar, o estado indica o passo em que parou em vez de mostrar resultados antigos do grupo. As linhas de um carregamento anterior mostram **De um carregamento anterior. Carregue novamente.** até um carregamento ter êxito.
- Se uma entidade e um período não puderem ser lidos, o resto continua a ser carregado. Execute **Carregar** de novo para obter apenas o que falhou.

### Linhas retidas

Quando as origens se sobrepõem, um carregamento mantém uma cópia de cada valor e retém as restantes em vez de as contar duas vezes. As linhas retidas são registadas com a respetiva origem, entidade e motivo, e o carregamento termina com um aviso que indica as contagens, por exemplo `120 rows of NetSuite EU also provided by a source ranked ahead`. Os motivos são:

| Motivo | Significado |
|---|---|
| Num outro livro contabilístico | A linha pertence a um livro de relato que a origem não está definida para ler. |
| Fora dos períodos que a origem fornece | A linha está fora dos meses **De** e **Para** definidos para a empresa. |
| Também fornecida por uma origem melhor classificada | Uma origem mais acima na ordem abrange a mesma empresa e o mesmo mês. |
| Também num ficheiro anterior da origem | Um ficheiro anterior da mesma origem já abrange o mês. |
| Substituída por um ficheiro | Um ficheiro substitui as linhas do ERP dessa entidade e desse mês. |
| Com um código que outra origem também utiliza | O código requer a sua resposta. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| Com um código mapeado para dois códigos | O mapa de códigos dá duas respostas ao código. |

As contas estatísticas passam para os indutores de alocação em vez do razão, e aparecem como movidas, não como um problema.

### Dados do ERP e ficheiros em conjunto

Um ficheiro substitui apenas o que abrange, e as restantes linhas do ERP mantêm-se.

- Os **ficheiros mestre** (contas, departamentos, clientes, produtos e valores de segmento) substituem as linhas do ERP com o mesmo código.
- Os **ficheiros de transações** substituem as linhas do ERP da mesma entidade e do mesmo mês. Os ficheiros de razão geral e de balancete também correspondem por razão, os ficheiros de orçamento por cenário e os ficheiros de indutores estatísticos por cenário e indutor.

Se um ficheiro deixar mais tarde de abranger um mês, os dados do ERP para esse mês regressam no carregamento seguinte.

## Mapeamento de entidades

Cada origem designa as suas entidades com os seus próprios códigos. O **Mapeamento de entidades** faz corresponder esses códigos às entidades do seu mestre de entidades, para que as linhas de todas as origens fiquem na mesma entidade.

Para o utilizar, adicione um ficheiro CSV ou Excel e escolha o conjunto de dados **Mapeamento de entidades**:

| Coluna | Contém |
|---|---|
| `source_entity` | O código tal como a origem o transporta, como um código de empresa. |
| `entity` | A entidade a que pertence, como o mestre de entidades a designa. |

- Um código que não está no mapeamento é utilizado tal como está.
- Vários códigos podem corresponder a uma entidade. As respetivas linhas são combinadas, e um mês conta como fechado quando está fechado para todos.
- Os códigos do mapeamento aplicam-se a todas as origens, pelo que os códigos de entidade de cada origem têm de ser únicos entre origens.
- Uma linha de um ficheiro de **Entidades** substitui a entidade do ERP com o mesmo código de entidade.

A verificação **Entidades não mapeadas** assinala qualquer linha cuja entidade não está no mestre de entidades nem é associada a uma pelo mapeamento. Enquanto não for carregado um mestre de entidades, mostra **– Não aplicável**.

## Mapear códigos entre origens

Duas origens podem usar o mesmo código para coisas diferentes, ou códigos diferentes para a mesma coisa. Quando um código aparece em mais do que uma origem, o Data Foundation retém as respetivas linhas até indicar se significa o mesmo em todo o lado, para que cada valor seja contado uma só vez. A verificação **Codes waiting for your answer** lista-os, os primeiros 10 e depois "e mais K", e o cartão **What to do next** do separador **Base** tem um botão **Rever**.

**Rever** abre **Codes waiting for your answer**. Agrupa os códigos pelo que são: **Account types**, **Companies**, **Accounts**, **Departments**, **Profit centers**, **Customers**, **Products** e cada categoria adicional. Para cada código, mostra como cada origem o designa e uma sugestão:

- **Looks like the same thing** quando as origens atribuem ao código o mesmo nome.
- **Looks like different things** quando os nomes diferem.
- **We can't tell. Please answer.** quando não há nada em que basear a decisão.

Responda a um código de cada vez com **Yes, the same** ou **No, different**, ou responda a um grupo inteiro de uma só vez com **Accept all** (aceitar todas as sugestões), **All the same** ou **All different**. Para as contas, também pode responder de uma só vez a um grupo-pai inteiro do plano de contas. Quando uma origem não tem tipos de conta, escolha **Use this type** para um grupo de contas: **Receita**, **Cost of goods sold**, **Operating expenses**, **Non-operating income and expenses**, **Assets**, **Liabilities** ou **Equity**.

Os mapeamentos são mantidos por origem e dimensão, pelo que uma resposta para os departamentos de uma origem nunca altera as contas de outra. As respostas são guardadas à medida que avança, com **Saved. Press Apply changes to use your answers.** Clique em **Apply changes** para as utilizar.

Também pode fornecer os mapeamentos num ficheiro. Adicione um ficheiro com o conjunto de dados **Code map** e escolha **Which source do these rows apply to?** para o limitar a uma origem.

## Escolher que origem conta a partir de quando

Quando duas origens fornecem os mesmos meses, a verificação **Which source covers which months** pede-lhe que escolha. Clique em **Choose which source counts from when** no cartão **What to do next** para abrir **Which source counts from when**, que lista cada sobreposição por empresa. Escolha a origem que conta, introduza em **That month is** o mês a partir do qual conta, por exemplo `2026-04`, e clique em **Apply changes**. A outra origem mantém os meses anteriores.

A mesma caixa de diálogo avisa quando duas origens indicam taxas de câmbio diferentes para uma moeda; são utilizadas as taxas da origem mais acima na ordem.

## Conversão de moedas

Cada carregamento converte os valores do razão geral, do balancete, das vendas, do inventário e do orçamento da respetiva moeda local para uma moeda de relato. Os relatórios e os modelos leem os valores convertidos, pelo que as entidades em moedas diferentes, de qualquer sistema, totalizam corretamente.

### A moeda de relato

Para escolher a moeda de relato, defina a variável de projeto `reporting_currency` com um código de moeda como `USD`. Consulte [Gerir variáveis de projeto](/pt-pt/guides/projects/managing-projects/#gerir-variáveis-do-projeto). O modelo cria-a em branco. Enquanto estiver em branco, cada carregamento utiliza a primeira das seguintes que indique exatamente uma moeda:

1. A moeda do grupo das entidades.
2. A moeda local das entidades de nível superior, as que não têm entidade-mãe.
3. A moeda local dos ficheiros.

Se nenhuma indicar exatamente uma moeda, **Conversão de moedas** apresenta um problema até definir `reporting_currency`.

Os valores que já estão na moeda de relato mantêm-se como estão, pelo que um projeto cujos dados estejam todos numa só moeda não precisa de taxas.

Os ficheiros de vendas, inventário e orçamento também podem incluir uma moeda. Mapeie uma coluna com o nome `Currency` ou `Local Currency` e esta é detetada automaticamente, e os valores locais do ficheiro são convertidos para a moeda de relato. Um valor de grupo ou de relato que já esteja no ficheiro é mantido como está. O custo padrão do produto não é convertido.

### Taxas de câmbio

Uma taxa converte uma unidade de uma moeda na moeda de relato para um mês: o valor convertido é o valor local multiplicado pela taxa.

- **A partir do ERP**, cada carregamento lê as taxas de câmbio que o ERP contém.
- **A partir de um ficheiro**, adicione um ficheiro CSV ou Excel e escolha o conjunto de dados **Taxas de câmbio**. Uma taxa no ficheiro substitui a taxa do ERP para as mesmas moedas e o mesmo mês. Utilize um ficheiro para relatar numa moeda para a qual os seus ERP não publicam taxas, ou para acrescentar taxas planeadas para os meses de orçamento.

| Coluna | Contém |
|---|---|
| `from_currency` | A moeda de origem da conversão, por exemplo `EUR`. |
| `to_currency` | A moeda de relato, por exemplo `USD`. |
| `period` | O mês, como `YYYY-MM`. |
| `average_rate` | A taxa média do mês. |
| `closing_rate` | A taxa no fim do mês. |
| `historical_rate` | A taxa histórica, para o capital próprio e para as contas definidas com a taxa histórica. |

Só são utilizadas as taxas para a moeda de relato. Uma taxa cotada no sentido inverso, da moeda de relato para outra moeda, não é invertida.

### Que taxa se aplica

Cada linha é convertida a partir da sua própria moeda, pelo que uma linha numa moeda diferente da sua entidade é convertida a partir da moeda em que está. Aplica-se a primeira regra que se ajusta à linha:

| Linha | Taxa |
|---|---|
| Contas estatísticas e sem lançamentos | Não convertida. |
| Já na moeda de relato | Não convertida. |
| Conta com tipo de taxa | Essa taxa: média, de fecho ou histórica. A histórica recorre à de fecho quando não existe taxa histórica. A partir de um ERP, o tipo de taxa é o tipo de taxa da própria conta. Num ficheiro de plano de contas, mapeie uma coluna de tipo de taxa para `fx_rate_type` com `average`, `closing` ou `historical`. |
| Linha de vendas | A taxa média do período. |
| Saldo de inventário | A taxa de fecho do período. |
| Linha de orçamento | Por conta, como no razão geral: a taxa média para as contas da demonstração de resultados e a taxa de fecho para as contas do balanço. |
| Conta da demonstração de resultados | A taxa média do período. |
| Conta de capital próprio | A taxa histórica, ou a taxa de fecho quando não existe taxa histórica. |
| Qualquer outra conta do balanço | A taxa de fecho do período. |

Os valores convertidos não são arredondados, pelo que os totais não se desviam.

<Aside type="note">
O balancete contém os movimentos de cada período, pelo que os valores do balanço são os movimentos de cada mês convertidos à taxa de fecho desse mês. Não são um balanço reconvertido à taxa do fim do período, e não existe ajustamento cumulativo de conversão nem eliminação intragrupo. Utilize os valores convertidos para a demonstração de resultados.
</Aside>

## Hierarquias

Cada carregamento reconstrói as dimensões a partir dos dados mestre de todas as origens. Existem sete dimensões à partida e até dez categorias adicionais:

| Dimensão | Construída a partir de |
|---|---|
| **Entidade** | Entidades e respetivas entidades-mãe |
| **Conta** | Plano de contas e contas-mãe |
| **Departamento** | Departamentos e respetivos departamentos-pai |
| **Cliente** | Clientes e respetivos clientes-pai |
| **Produto** | Produtos e respetivos produtos-pai |
| **Segmento 1** | Valores de segmento de `segment_1` |
| **Segmento 2** | Valores de segmento de `segment_2` |
| **Segmento 3** a **Segmento 10** | Valores de segmento de `segment_3` a `segment_10`, quando as origens os contêm |

- Um registo sem pai, ou que se indique a si próprio como pai, é carregado como membro de nível superior.
- Como cada carregamento reconstrói as hierarquias, altere um pai no ERP ou no ficheiro, não na dimensão.
- Um problema numa hierarquia afeta apenas essa dimensão. O carregamento e os modelos do modelo de projeto continuam a ser concluídos.
- Pode mudar o nome de cada categoria adicional para o que contém, por exemplo **Classe** ou **Região**. Em **Rename extra categories**, introduza os nomes que os relatórios utilizam e clique em **Save names**. Os nomes usam letras, números, espaços, pontos, hífenes e carateres de sublinhado, até 60 carateres.
- Cada origem indica sob que nome das suas categorias cada uma das suas categorias adicionais fica. Abra **Avançado** na origem, escolha o nome para cada uma, ou escolha **Leave out**, e clique em **Guardar**. As origens que designam uma categoria por nomes diferentes, como `Class` e `Business area`, partilham então um único espaço.

Para fornecer hierarquias de segmento a partir de um ficheiro, escolha o conjunto de dados **Valores de segmento**:

| Coluna | Contém |
|---|---|
| `segment` | A que segmento pertence o valor: `segment_1` a `segment_10`. |
| `segment_value` | O valor, tal como as linhas do razão geral, das vendas e do orçamento o transportam. |
| `segment_value_name` | O seu nome. |
| `parent_segment_value` | O seu pai dentro do mesmo segmento. |

## Verificações de prontidão

Após cada carregamento, a grelha **Prontidão** lista todas as verificações para cada entidade e período, com um dos seguintes estados:

| Estado | Significado |
|---|---|
| **● Pronto** | A verificação foi aprovada. |
| **▲ Requer atenção** | Merece uma análise, mas os números são utilizáveis. |
| **■ Problema** | Corrija antes de confiar nos resultados. |
| **– Não aplicável** | Ainda não existem dados para esta verificação. |

As verificações são:

| Verificação | O que confirma |
|---|---|
| **Dados carregados** | Cada período fiscal tem linhas de razão geral, e todas as leituras do ERP tiveram êxito. Um período fechado sem linhas é um problema; um período aberto sem linhas requer atenção. |
| **O balancete coincide com o razão geral** | O balancete é igual ao razão geral para cada entidade, período e conta. Quando o balancete e o razão geral têm departamentos para uma conta, também verifica cada departamento. |
| **Vendas coincidem com o razão geral** | As linhas de vendas são iguais às contas de receita e de custo das mercadorias vendidas do razão geral em cada período. |
| **Produtos/clientes desconhecidos** | Cada linha de vendas indica um produto e um cliente que existem nos mestres de produtos e de clientes. |
| **Contas em falta no plano de contas** | Cada linha do razão geral indica uma conta do plano de contas. As linhas com uma conta desconhecida ficam fora da demonstração de resultados. Uma conta com lançamentos mas sem tipo de conta também é um problema, e uma origem cujo plano atribui o tipo Receita a contas mas não tem conta de custo das mercadorias vendidas requer atenção. |
| **Conversão de moedas** | Cada linha do razão geral, do balancete, das vendas, do inventário e do orçamento tem um valor na moeda de relato. Uma linha da demonstração de resultados ou de vendas sem taxa é um problema, porque a demonstração de resultados lê valores convertidos. Uma linha de balanço, inventário ou orçamento sem taxa requer atenção. Um mês de orçamento ainda sem taxa aparece a âmbar, pelo que deve carregar taxas planeadas para os meses de orçamento. Consulte [Conversão de moedas](#conversão-de-moedas). |
| **Entidades não mapeadas** | Cada linha do razão geral, do balancete e de vendas indica uma entidade do mestre de entidades, diretamente ou através do mapeamento de entidades. Não aplicável até ser carregado um mestre de entidades. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |

Os carregamentos com mais do que uma origem acrescentam estas verificações:

| Verificação | O que confirma |
|---|---|
| **Reporting book** | Uma origem que contém vários livros contabilísticos para uma entidade teve o livro de relato escolhido. Até escolher, só conta o primeiro livro. |
| **Codes waiting for your answer** | Todos os códigos usados por mais do que uma origem foram respondidos. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| **Extra categories from your sources** | Cada categoria adicional que uma origem contém tem um nome ou foi deixada de fora. |
| **Which source covers which months** | Nenhuma origem fornece os mesmos meses de uma empresa que outra, a menos que tenha escolhido qual conta. |
| **Account types and hierarchy** | Todos os pais que uma dimensão indica existem, e nenhum membro é pai ou ascendente de si próprio. Um pai em falta coloca os filhos no topo da hierarquia, e um ciclo impede o carregamento dessa hierarquia. Os totais não são afetados. |
| **Calendário fiscal** | Os períodos fiscais de cada entidade são meses de calendário, e cada mês de linhas pode ser colocado num período fiscal. Requer atenção quando os períodos de uma entidade não são meses de calendário (4-4-5, 13 períodos), ou quando as linhas de um mês podem estar em mais do que um período fiscal ou o calendário fiscal não tem o mês. |

Cada linha que não está pronta indica o que fazer na coluna **O que fazer**, como carregar o plano de contas, carregar taxas de câmbio ou executar **Carregar** de novo para um período.

A grelha também mostra duas verificações de configuração, que só aparecem quando requerem atenção:

| Verificação | Quando aparece |
|---|---|
| **Imputação de custos indiretos** | Só uma das variáveis de projeto `overhead_department` e `overhead_driver` está definida, ou nenhum indutor de alocação corresponde a `overhead_driver`, pelo que a alocação não faria nada. Defina ambas, ou limpe ambas para desativar a imputação de custos indiretos. |
| **Comparação com o orçamento** | Estão carregadas linhas de orçamento, mas nenhuma está na versão que a variável de projeto `budget_version` indica, pelo que a comparação com o orçamento estaria vazia. |

## Consolidação de gestão

Cada carregamento cria uma consolidação de gestão: a demonstração de resultados do grupo de todas as entidades do grupo, na moeda de relato, com as operações intragrupo eliminadas. Destina-se ao relato de gestão. O seu sistema de consolidação continua a ser o registo do grupo estatutário; reconcilie com ele conforme abaixo.

<Aside type="note">
A consolidação de gestão abrange apenas a demonstração de resultados. Não é uma consolidação estatutária ou legal, e não tem balanço consolidado, ajustamento de conversão, goodwill nem interesses minoritários.
</Aside>

### Escolher o grupo

Em **Origens**, abra **Grupo** para ver as empresas do grupo. Uma empresa que desassinalar permanece nos seus relatórios isoladamente, mas fica fora do total do grupo. Clique em **Save group**. A alteração aplica-se no **Carregar** ou **Apply changes** seguinte. Uma nova empresa fica no grupo até a desassinalar.

O exercício fiscal do grupo começa no mês definido pela variável de projeto `group_fy_start_month`, que é `1`, a menos que a altere.

### O que obtém

| Tabela | Contém |
|---|---|
| **Group P&L** | Uma linha por entidade, período e rubrica (receita, custo das mercadorias vendidas, despesas operacionais, não operacionais, diferença intragrupo), na moeda de relato. A receita e os custos mantêm o seu sinal natural. |
| **Group P&L year to date** | O mesmo, acumulado no ano, até ao último período do grupo totalmente carregado. |
| **Intercompany pairs** | Uma linha por par de entidades, grupo e período, com o valor de cada lado e o residual. |
| **Intercompany lines** | As linhas do razão por trás de um valor do grupo ou de um par, com o parceiro comercial. |
| **Reconciliação** | A demonstração de resultados do grupo acumulada no ano face ao seu sistema de consolidação. |

Aparecem três nomes de entidade nestas tabelas:

| Entidade | Significado |
|---|---|
| **Eliminations** | As eliminações intragrupo. Somam zero, pelo que as deve manter para os valores do grupo e filtrá-las para obter a soma das entidades antes da eliminação. |
| **Group total** | O total do sistema de consolidação, na reconciliação. |
| **Unmapped** | Linhas sem período, e contas ou entidades do seu sistema de consolidação que este projeto não tem. |

Os indicadores **Consolidated income**, **Consolidated result** e **IC difference**, e um caminho de análise para cada tabela, respondem a perguntas sobre o grupo.

### Eliminações intragrupo

As linhas intragrupo são emparelhadas por parceiro comercial. É utilizado o parceiro indicado na linha; quando a linha não tem nenhum, é utilizado o parceiro do respetivo cliente. Ambos os lados de um par são eliminados, e o valor pelo qual os dois lados não coincidem é lançado numa linha de diferença intragrupo. Cada par recebe um motivo:

| Motivo | Significado |
|---|---|
| **Correspondente** | Ambos os lados lançaram o mesmo valor. |
| **Apenas um lado lançado** | Uma entidade lançou a transação e o parceiro não. |
| **Não eliminado** | Uma linha do par não tem taxa de câmbio, pelo que nenhum dos lados é eliminado. |

Um par é avaliado pelo respetivo acumulado no ano. A linha **Intercompany balances** fica âmbar quando a diferença de um par excede a variável de projeto `group_amber` (predefinição `1`) e vermelha acima de `group_red` (predefinição `1000`). As linhas sem parceiro, ou com um parceiro que não é uma entidade, não são eliminadas e são contadas nessa linha. Uma origem que tem parceiros ao lado de uma que não os tem aparece a âmbar.

As entidades de eliminação próprias de uma origem ficam fora da demonstração de resultados do grupo, e a linha **Consolidação** indica-o.

### Reconciliar com o sistema de consolidação

Adicione como ficheiro os resultados que o seu sistema de consolidação comunica e assinale **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** quando confirmar o respetivo mapeamento. Responda a **Which version of the numbers is this?** com o nome do sistema. A tabela **Reconciliação** mostra então **ours**, **reported** e **diferença** para cada entidade e rubrica, acumulado no ano. Uma diferença é normalmente explicada nas linhas **Eliminations**, **Group total** e **Unmapped**, ou pelas taxas de câmbio que o sistema utiliza. A linha **Reconciliation to the source** lista todas as rubricas acima de `group_amber`.

### Quem pode ver

Os resultados do grupo seguem o acesso a linhas do projeto. Quando o acesso a linhas impede os resultados do grupo, o estado aparece a âmbar. Uma pessoa que vê apenas algumas entidades vê as somas dessas entidades antes da eliminação. As linhas **Eliminations** e as tabelas intragrupo requerem acesso a todas as entidades.

Se o projeto limitar quem vê que linhas por uma coluna que as tabelas do grupo não contêm, como o departamento, os resultados do grupo ficam desativados para todos e **Consolidação** indica **Group views are off**. Só um Arquiteto pode então assinalar **Everyone on the project may see the group results** em **Grupo**. A alteração aplica-se no **Carregar** ou **Apply changes** seguinte.

## Manter atualizado

Depois de um carregamento a partir da ligação ao ERP ter êxito sem problemas, **Atualizar todas as noites** aparece no cartão **Último carregamento**. Clique nele para executar **Carregar** todas as noites às 2:00 no seu fuso horário. O cartão passa então a mostrar **Nightly refresh: Every night at 2:00** e quem o configurou.

O carregamento noturno é executado como a pessoa que o configurou. Se essa pessoa já não puder utilizar a ligação ao ERP, a grelha indica que o carregamento noturno é ignorado; configure-o de novo. Um projeto que tenha apenas dados de exemplo não pode ser agendado.

Um ficheiro em falta ou vazio num carregamento noturno termina com um aviso que indica o caminho, não com um erro, e o resto do modelo continua a ser carregado.

## Business names

Os **Business names** no separador **Base** dão aos códigos do modelo os nomes que o seu negócio utiliza. Os relatórios, os indicadores e o assistente mostram estes nomes, e um nome que guarde aplica-se de imediato. Os carregamentos seguintes mantêm-no.

1. Clique em **Add a name** e escolha o **Tipo**: **Categoria**, **Linha da demonstração de resultados**, **Indicador** ou **Coluna**.
2. Introduza o **Código**: `segment_1` a `segment_10` para uma categoria, a chave da rubrica para uma linha da demonstração de resultados, o nome do indicador, ou `table.column` para uma coluna.
3. Introduza o **Nome**, com um máximo de 60 carateres numa só linha.
4. Clique em **Save names**.

Guardar substitui a lista completa. Uma linha com um nome vazio remove esse nome, e **Remover selecionados** remove as linhas que assinalar. Atribuir o nome ao mesmo código duas vezes é recusado. Os nomes de negócio também são escritos na descrição do caminho de análise para que o assistente use as suas palavras, e essa descrição tem um limite de comprimento: se um nome a tornar demasiado longa, nada é guardado e é avisado.

## Explicar um número

**Explain this number** mostra o que compõe um valor da demonstração de resultados. Na grelha **Prontidão**, uma linha para uma entidade e um mês tem **Explain this number**, que abre a margem operacional da entidade nesse mês. A janela divide o número em camadas que somam o total no topo:

| Camada | O que contém |
|---|---|
| **From the general ledger** | O que o razão lançou na rubrica. |
| **Allocated in** | Custo distribuído para esta entidade pelas suas [regras de alocação](#regras-de-alocação). |
| **Allocated out** | Custo que esta entidade distribuiu para outras. |
| **Eliminated in the group** | Operações intragrupo que foram eliminadas no resultado do grupo. |

Cada camada tem uma frase que diz o que é e os seus maiores documentos de origem, com o respetivo sistema de origem, documento e conta. Só são mostradas as camadas que têm linhas. A janela respeita o seu acesso a linhas: só explica os valores que pode ver. Um número sem nada por trás indica **Nothing to explain**.

## Regras de alocação

As alocações distribuem custos partilhados, como os custos indiretos, por departamentos, produtos e clientes. O modelo tem duas fases: **Stage 1: overhead to departments** e **Stage 2: departments to products and customers**. Abra **Ações > Alocações...** para ver ou alterar a forma como cada uma é feita. Sem alterações, funcionam como antes de o assistente existir. Um leitor pode abrir as regras mas não as pode guardar.

Para cada fase, o assistente faz quatro perguntas:

| Passo | Pergunta | Opções |
|---|---|---|
| **Conjunto de custos** | Que custos pretende distribuir? | O tipo de conta e, na fase 1, o departamento que contém o custo, ou **All departments**. |
| **Indutor** | Por que critério os pretende distribuir? | **Statistic** que carregou como indutores de alocação, como o número de colaboradores ou os pés quadrados, **Net sales amount**, **Sales quantity** ou **Spread evenly**. Utilize o indutor de **Same period** ou **Same period last year**. |
| **Destino** | Onde ficam? | Fase 1: departamentos. Fase 2: produtos, clientes ou ambos. |
| **Método** | O que acontece quando um indutor é negativo? | **Ignore negative values** ou **Stop and tell me**. |

Por baixo dos passos, **Preview for** um mês, escrito como ano e mês, por exemplo `2026-09`, mostra o que as regras, incluindo as que ainda não guardou, fariam: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Tudo o que não está alocado é custo que não teve indutor que o absorvesse. A pré-visualização respeita o seu acesso a linhas.

Clique em **Guardar**. As regras entram em vigor no **Carregar** seguinte, ou quando clicar em **Apply changes**. Se editou um passo de alocação manualmente, a sua edição é mantida, não é substituída, e a gravação indica-o. Não é possível guardar enquanto um carregamento está em execução.

## Board pack

Um pacote para o conselho grava os seus resultados numa pasta de uma conta de documentos, pronto a enviar. Abra **Ações > Board pack...**, escolha uma **Conta de documentos** e uma **Pasta**, como `/board-packs`, e clique em **Guardar**. Cada **Carregar** cria então o pacote, pelo que os ficheiros na pasta estão tão atualizados quanto o último carregamento. Cada execução grava:

- Um livro Excel, `Board pack.xlsx`, com a demonstração de resultados por entidade, uma ponte de margem e os melhores e piores clientes.
- Um PDF do painel de controlo da demonstração de resultados.

Clique em **Run now** para criar um pacote de imediato; os respetivos ficheiros aparecem na pasta quando terminar. A caixa de diálogo mostra a última execução e o seu resultado, e a execução seguinte. **Apply changes** não cria um pacote. Para criar um todas as noites, configure a atualização noturna (consulte [Manter atualizado](#manter-atualizado)); até lá, a caixa de diálogo indica **Not scheduled yet**. Só quem pode alterar o projeto o configura.

Um pacote que não pode ser criado na totalidade nunca faz falhar o carregamento:

- Se os relatórios estiverem desativados para a sua área de trabalho, o pacote é apenas o livro Excel, e a execução indica **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- Se um painel de controlo criado por outra pessoa já tiver o endereço de que o Data Foundation precisa para o painel de controlo da demonstração de resultados, esse painel de controlo é deixado como está e o PDF não é criado. A mensagem indica o endereço; atribua outro endereço ao outro painel de controlo e execute **Carregar** de novo.
- Se algum passo do pacote falhar, a lista **Estado** mostra uma linha **Board pack** a âmbar que indica o passo e o motivo. O próprio carregamento teve êxito.

## Pontos de restauro

Um ponto de restauro é criado quando cada **Carregar** ou **Apply changes** começa, seja quem for que o inicie, incluindo um carregamento agendado, e antes de cada alteração a mapeamentos ou origens. Contém as tabelas do modelo, as dimensões e as definições a partir das quais o carregamento seguinte constrói: as origens, os ficheiros e as regras de alocação. São mantidos os últimos sete pontos criados para carregamentos e os últimos cinco criados antes de alterações, pelo que as alterações nunca expulsam os pontos criados para carregamentos. Os pontos mais antigos são descartados.

Para voltar atrás, abra **Ações > Restaurar...**. Cada ponto mostra quando foi criado e, por baixo, quantas tabelas a sua restauração repõe, por exemplo **Puts back 12 tables.**, juntamente com eventuais avisos. Escolha um ponto e clique em **Restaurar**. **Restaurar** é oferecido assim que existir um ponto. Restaurar começa por registar o projeto tal como está agora como um ponto próprio, para que possa voltar atrás de novo. Depois repõe as tabelas, as dimensões e essas definições como estavam, e o carregamento seguinte constrói a partir delas. Restaurar para as origens que já tinha não as marca como alteradas. Uma vista, uma dimensão que não pode ser guardada ou uma tabela sem cópia guardada são indicadas num aviso, e o resto é restaurado. Um ponto de restauro que já foi descartado é recusado, e não é possível restaurar enquanto um carregamento está em execução.

## Clonar um projeto

**Ações > Clonar...** copia o projeto com um nome que indicar. A cópia mantém o modelo, as suas edições ao modelo, e os seus indicadores e caminhos de análise, e carrega os dados de exemplo. As suas origens não ficam ligadas, pelo que deve ligá-las na cópia antes de carregar. Pode continuar a trabalhar enquanto a cópia é criada, e **Abrir projeto** leva-o até ela quando estiver pronta.

## Guardar como o meu modelo

Guarde a configuração de um projeto para a reutilizar com o cliente ou a entidade seguintes. Abra **Ações > Save as my template...**, escolha a conta de documentos e dê um nome ao ficheiro. Se não o indicar, é acrescentado um nome terminado em `.zip`. Guardar por cima de um ficheiro existente é recusado, pelo que deve escolher outro nome.

O ficheiro contém a estrutura do projeto, as suas edições ao modelo, os indicadores e os caminhos de análise, os nomes de negócio das entidades e das contas, e as linhas das tabelas de configuração do modelo, como o mapa de atividades do [Cost to Serve](/pt-pt/guides/projects/cost-to-serve/) ou as margens de política do [Operational Transfer Pricing](/pt-pt/guides/projects/operational-transfer-pricing/). Deixa de fora as ligações, os ficheiros, o agendamento noturno, as execuções, os pontos de restauro, o pacote para o conselho e quem tem acesso.

Para o utilizar, crie um projeto, escolha **From a template file...** em **Começar a partir de** e indique a conta de documentos e o caminho. O novo projeto é privado e todas as origens ficam à espera de ser ligadas. Uma versão posterior do modelo funde as suas alterações em torno dos passos que editou. Se não existir nenhum ficheiro no caminho, nada é criado e é avisado. Qualquer pessoa que possa ler a conta de documentos pode instalar a partir do ficheiro. Para o utilizar noutra área de trabalho, transfira o ficheiro e carregue-o lá.

## Resolver questões em aberto com o Ask

Após um carregamento, um projeto ainda pode estar à espera de que lhe indiquem três coisas: contas a que o plano não atribui tipo, códigos que mais do que uma origem utiliza e colunas dos ficheiros que não corresponderam a nada. Peça ao assistente que as resolva: a partir de um assistente de IA através do MCP, utilize o prompt **Resolve Data Foundation residue**. Lê o que está pendente e propõe uma resposta para cada item, com um motivo.

O assistente não escreve nada. Aplica as respostas dele onde teria respondido por si: as contas e os códigos em **Codes waiting for your answer**, e as colunas dos ficheiros no mapeamento do ficheiro. Nunca propõe uma entidade.

## Entregar o projeto

A lista de verificação de **Configuração** tem quatro itens finais depois de **Reveja as suas hierarquias**:

- **Set up the nightly refresh** fica concluído quando **Atualizar todas as noites** está ativo.
- **Partilhar com a sua equipa** fica concluído quando alguém além da pessoa que configurou o projeto é membro.
- **Download the evidence pack** fica concluído quando transfere o pacote depois do último carregamento bem-sucedido.
- **Hand the project over to its owner** fica concluído quando existe um Arquiteto diferente da pessoa que o configurou e os totais coincidem. Enquanto não estiver concluído, a lista de verificação indica o que fazer: tornar o proprietário do cliente Arquiteto deste projeto e, em seguida, removê-lo a si próprio dos membros.

A lista de verificação indica quem configurou o projeto (**Set up by**).

## Criar sobre o modelo com um modelo

Um modelo cria os seus relatórios e modelos sobre o Common Finance Model, pelo que funcionam da mesma forma, quaisquer que sejam os ERP que o alimentam. Quando inicia um projeto a partir de um modelo, como o **Enterprise Profitability**, este cria:

- As [tabelas do Common Finance Model](#tabelas-do-common-finance-model), vazias ou preenchidas com dados de exemplo.
- As dimensões **Entidade**, **Conta**, **Departamento**, **Cliente**, **Produto**, **Segmento 1** e **Segmento 2** criadas a partir dessas tabelas. Consulte [Hierarquias](#hierarquias).
- O fluxo de trabalho **Carregar** e os fluxos de trabalho que executa para ler o ERP e os ficheiros, harmonizá-los, verificar a prontidão e criar os modelos do modelo de projeto.
- Os relatórios e modelos próprios do modelo. O **Enterprise Profitability** acrescenta uma tabela de demonstração de resultados com receita, custo das mercadorias vendidas, margem bruta, despesas operacionais diretas e indiretas, contribuição e margem operacional, além de pontes de margem ano a ano e face ao orçamento.
- Indicadores e um caminho de análise para colocar perguntas sobre os resultados.

Estão disponíveis três modelos em **Começar a partir de**, cada um assente no mesmo modelo de dados:

| Modelo | Acrescenta |
|---|---|
| **Enterprise Profitability** | A demonstração de resultados e as pontes de margem. |
| **Cost to Serve** | O custo de servir cada cliente, e a margem depois dele. Consulte [Cost to Serve](/pt-pt/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | O nível de lucro de cada entidade face à sua margem de política, e o ajustamento final. Consulte [Operational Transfer Pricing](/pt-pt/guides/projects/operational-transfer-pricing/). |

**From a template file...** parte de um projeto que guardou. Consulte [Guardar como o meu modelo](#guardar-como-o-meu-modelo).

Para explorar antes de ligar o seu próprio ERP, assinale **Começar com dados de exemplo** ao criar o projeto. O projeto executa de imediato um primeiro Carregar, pelo que o separador **Base** mostra um exemplo completo, incluindo uma entidade em euros convertida para dólares norte-americanos. Quando liga o seu próprio ERP ou adiciona os seus próprios ficheiros, os dados de exemplo são removidos e os seus dados ocupam o lugar. Se a remoção for interrompida, o **Carregar** seguinte conclui-a. Uma pasta sua com o nome `sample` nunca é removida: a página de estado regista que os dados de exemplo ocupam essa pasta, pelo que as outras tabelas nela não são lidas, e pede-lhe que as mova para uma pasta com outro nome.

## O separador Base

O separador **Base** é onde liga, carrega e verifica os seus dados. Tem estas secções, de cima para baixo:

| Secção | O que mostra |
|---|---|
| **Último carregamento** | Se o último carregamento teve êxito, falhou ou ainda está em execução, com os botões **Carregar**, **Apply changes**, **Atualizar** e **Atualizar todas as noites**. |
| **What to do next** | O que requer a sua atenção, por ordem de importância, cada item com um botão **Rever** ou **Choose which source counts from when**. |
| **Origens** | Cada origem por ordem, com **Avançado**, **Remove this source**, **Grupo** e **Rename extra categories**. |
| **Configuração** | A lista de verificação de configuração: **Ligar os seus dados**, **Carregue os seus dados**, **Verificar se os totais coincidem**, **Reveja as suas hierarquias**, **Set up the nightly refresh**, **Partilhar com a sua equipa**, **Download the evidence pack** e **Hand the project over to its owner**. O item atual aparece a negrito. |
| **Business names** | Os nomes que o seu negócio utiliza para categorias, rubricas da demonstração de resultados, indicadores e colunas. Consulte [Business names](#business-names). |
| **Ficheiros** | Cada ficheiro que adicionou, o respetivo conjunto de dados, como **Razão geral** ou **Taxas de câmbio**, e se o mapeamento está **✓ Confirmado** ou **○ A aguardar confirmação**. |
| **Dados carregados** | Para cada entidade, o primeiro e o último período carregados e quantos períodos estão prontos. |
| **Períodos** | Os períodos fiscais de cada entidade e se cada um está **✓ Fechado** ou **○ Aberto**. |
| **Prontidão** | A grelha de prontidão: uma linha por entidade, período e verificação, com o respetivo estado e **O que fazer**. |
| Ligação | Ligue o ERP, escolha as entidades e quantos meses de histórico carregar, ou adicione outra origem. |
| **Ficheiros** (adicionar) | Adicione um ficheiro CSV, TSV, TXT, Excel ou Parquet e confirme como as colunas são mapeadas. |
| **Carregar** | Inicie um carregamento. **Apply changes** executa um sem obter dados dos ERP. |

Enquanto um carregamento decorre, o separador atualiza-se sozinho e continua a ler mesmo que uma leitura falhe. Se o estado não puder ser lido, aparece **Não foi possível ler o estado do Foundation.** com **Tentar novamente**, que o lê de novo; o separador também tenta uma vez sozinho antes de mostrar a mensagem, e a mensagem desaparece quando o servidor responde.

A página de estado também regista:

- Uma pasta em `/sources/` cujas tabelas não têm as colunas de que precisam não é adicionada como origem. Uma nota indica cada tabela que ficou de fora e a coluna que lhe falta. Acrescente a coluna e prima depois **Carregar** ou **Apply changes**.
- Se um carregamento teve êxito mas não trouxe linhas de razão para comparar, uma linha âmbar **Model P&L ties to GL** indica que nada coincidiu. **Verificar se os totais coincidem** permanece pendente na lista de verificação de configuração, não concluído, até algo coincidir. Adicione uma origem com linhas de razão e prima depois **Carregar**.

A lista de verificação de configuração acompanha o seu progresso:

- **Ligar os seus dados** e **Carregue os seus dados** ficam assinalados sozinhos quando uma origem está associada e um carregamento tem êxito.
- **Verificar se os totais coincidem** fica assinalado sozinho quando as verificações de conciliação são aprovadas.
- **Reveja as suas hierarquias**: clique em **Abrir dimensões** para rever as hierarquias de Entidade, Conta e Departamento e assinale depois **Já os revi**. Confirma este item por si.
- **Set up the nightly refresh**, **Partilhar com a sua equipa**, **Download the evidence pack** e **Hand the project over to its owner** fecham a lista. Consulte [Entregar o projeto](#entregar-o-projeto) e [Gerir o acesso ao projeto](/pt-pt/guides/projects/managing-projects/#gerir-o-acesso-ao-projeto).

O menu **Ações** contém **Alocações...**, **Board pack...**, **Clonar...**, **Restaurar...** e **Save as my template...**. Consulte [Regras de alocação](#regras-de-alocação), [Board pack](#board-pack), [Clonar um projeto](#clonar-um-projeto), [Pontos de restauro](#pontos-de-restauro) e [Guardar como o meu modelo](#guardar-como-o-meu-modelo).

## Tabelas do Common Finance Model

O Data Foundation harmoniza todas as origens, ERP ou ficheiro, nas mesmas quinze tabelas, pelo que os relatórios, indicadores e modelos criados sobre elas funcionam da mesma forma, seja qual for a origem. Cada linha regista também o respetivo sistema de origem e quando foi lida. A coluna **Conjunto de dados** é o nome que escolhe ao adicionar um ficheiro.

| Conjunto de dados | Tabela | Contém |
|---|---|---|
| Entidades | `cfm_entity` | Entidades jurídicas com entidade-mãe, moeda local e de grupo, e país. |
| Mapeamento de entidades | `cfm_entity_map` | Códigos de entidade da origem e a entidade a que cada um pertence. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |
| Taxas de câmbio | `cfm_fx_rate` | Taxas mensais média, de fecho e histórica por par de moedas. Consulte [Taxas de câmbio](#taxas-de-câmbio). |
| Calendário fiscal | `cfm_fiscal_calendar` | Uma linha por período fiscal de entidade, com datas de início e de fim e se está fechado. |
| Plano de contas | `cfm_account` | Contas com conta-mãe, tipo (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), demonstração, saldo normal e tipo de taxa. |
| Departamentos | `cfm_department` | Departamentos e centros de custo com departamento-pai e centro de lucro. |
| Produtos | `cfm_product` | Mestre de produtos com produto-pai, família, grupo, unidade de medida e custo padrão. |
| Clientes | `cfm_customer` | Mestre de clientes com cliente-pai, grupo, região e país. Os nomes dos clientes não são ocultados. |
| Valores de segmento | `cfm_segment` | Valores de segmento com nome e pai. Consulte [Hierarquias](#hierarquias). |
| Razão geral | `cfm_gl_journal` | Linhas de diário em moeda de transação, local e de relato. |
| Balancete | `cfm_trial_balance` | Débitos, créditos e líquido do período por entidade, conta e departamento, em moeda local e de relato. |
| Linhas de vendas | `cfm_sales_line` | Linhas de vendas faturadas com quantidade e valores brutos, de desconto, líquidos e de custo das mercadorias vendidas. |
| Saldos de inventário | `cfm_inventory_balance` | Inventário no fim do período por produto e armazém. |
| Orçamento | `cfm_budget` | Orçamento e previsão por cenário, versão, conta e departamento. |
| Indutores de alocação | `cfm_stat_driver` | Indutores estatísticos como o número de colaboradores, pés quadrados ou unidades. |

Os períodos escrevem-se `YYYY-MM`, e as transações são colocadas pelo período de lançamento. O orçamento é opcional: um ERP sem orçamentos carrega na mesma tudo o resto.

Um ficheiro de balancete pode conter colunas de débito e crédito, uma coluna de líquido, ou ambas. Com apenas débito e crédito, o líquido é o débito menos o crédito, e um lado em branco conta como zero. Com apenas um líquido, um líquido positivo torna-se o débito e um líquido negativo torna-se o crédito, como valor positivo. Uma coluna de departamento é opcional.

## Resolução de problemas

| Sintoma | O que fazer |
|---|---|
| **Testar ligação** indica que o ERP recusou as credenciais | Verifique as credenciais da ligação e se o utilizador de integração consegue iniciar sessão no ERP. |
| **Testar ligação** mostra **Permissão em falta** para um conjunto de dados | Peça ao administrador do ERP que acrescente as permissões indicadas. O [guia de ligações](/pt-pt/guides/connections/) do seu ERP lista o que a ligação necessita. |
| Uma mensagem de erro do ERP é mais curta do que a do próprio ERP | O PlaidCloud remove credenciais, tokens e chaves dos erros do fornecedor antes de os mostrar, pelo que alguns pormenores ficam de fora. Execute **Testar ligação** para ver que conjunto de dados é afetado. |
| **Dados carregados** é um problema num período | Falhou uma leitura do ERP para esse período. Execute **Carregar** de novo; os períodos que foram carregados são ignorados. |
| **Contas em falta no plano de contas** é um problema | Acrescente as contas em falta ao plano de contas no ERP ou no ficheiro e execute **Carregar** de novo. |
| **Conversão de moedas** é um problema | A moeda de uma entidade não tem taxa para a moeda de relato nesse período, ou não foi encontrada uma única moeda de relato. Acrescente as taxas a um ficheiro de **Taxas de câmbio**, verifique se a ligação consegue ler as taxas de câmbio do ERP ou defina a variável de projeto `reporting_currency`. Depois execute **Carregar** de novo. |
| **Conversão de moedas** requer atenção | As linhas de balanço, inventário ou orçamento não têm taxa de fecho, histórica ou planeada para o período. A demonstração de resultados não é afetada. Acrescente as taxas, incluindo as taxas planeadas para os meses de orçamento, e execute **Carregar** de novo. |
| **Codes waiting for your answer** requer atenção | Clique em **Rever**, responda a cada código e clique em **Apply changes**. |
| **Which source covers which months** requer atenção | Clique em **Choose which source counts from when**, escolha a origem e clique em **Apply changes**. |
| **Intercompany balances** está vermelho ou âmbar | Verifique os pares em **Intercompany pairs**. Lance o lado em falta, acrescente o parceiro comercial às linhas ou acrescente a taxa em falta. |
| **Group views are off** | Peça a um Arquiteto que assinale **Everyone on the project may see the group results** em **Grupo**. |
| **Entidades não mapeadas** é um problema | Acrescente a entidade ao mestre de entidades, ou associe o respetivo código a uma entidade existente no ficheiro de **Mapeamento de entidades**, e execute **Carregar** de novo. |
