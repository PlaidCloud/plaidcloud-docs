O **Data Foundation** é a base de dados financeiros dos seus projetos PlaidCloud. O seu **Common Finance Model** reúne dados de vários sistemas ERP, e de várias instâncias de cada um, num único modelo: um plano de contas, um conjunto de entidades e uma moeda de relato. Os relatórios, indicadores e assistentes de IA criados sobre o modelo leem todos os mesmos números, seja qual for o ERP de origem.

O ERP liga-se através da respetiva ligação PlaidCloud, pelo que o razão geral, o balancete, os dados mestre e os orçamentos chegam diretamente da origem, sem nada para exportar. Os ficheiros acrescentam dados que um sistema não contém, como taxas de câmbio, indutores de alocação ou um orçamento mantido fora do ERP, e podem substituir as linhas do ERP que abrangem. **Carregar** uniformiza todas as origens no modelo, converte-as para a moeda de relato e verifica se coincidem, tudo a partir do grupo **Data Foundation** da barra **Início** do projeto. Quando adiciona um segundo sistema, responde a uma pergunta por assunto, por exemplo se utiliza os mesmos códigos de conta que um sistema já ligado, e uma consolidação de gestão constrói a demonstração de resultados do grupo com as operações intragrupo eliminadas. Pode adicionar o Data Foundation a qualquer projeto, e as soluções, como **Enterprise Profitability**, constroem os respetivos relatórios e modelos de cálculo sobre ele.

## Obter o Data Foundation

Pode iniciar um projeto com o Data Foundation ou adicioná-lo a um projeto que já tenha.

- **Um projeto novo.** No Analyze, abra **Projetos** e clique em **Novo projeto**. **Começar a partir de** lista **Em branco**, **Data Foundation**, **Enterprise Profitability**, **Cost to Serve**, **Operational Transfer Pricing** e **A partir de um ficheiro de modelo**, com uma linha por baixo da lista que indica o que a escolha proporciona. O **Data Foundation** é o modelo por si só, com os respetivos relatórios. Cada uma das três soluções inclui o Data Foundation e acrescenta os seus próprios modelos de cálculo. Para ver um exemplo completo antes de ligar o que quer que seja, assinale **Começar com dados de exemplo**. Clique em **Criar**. O projeto é privado e o utilizador é o seu único Arquiteto até o partilhar.
- **O seu primeiro início de sessão.** Se puder criar projetos, a mensagem de boas-vindas do seu primeiro início de sessão propõe **Ligue o seu sistema financeiro**. Esta opção cria um projeto Data Foundation, atribui-lhe um nome e abre-o enquanto é construído.
- **Um projeto que já tem.** Abra a página **Início** do projeto. Sob o título **Data Foundation** da barra, a linha **Data Foundation** explica o que é, e um Arquiteto do projeto vê **Adicionar Data Foundation**. A construção decorre em segundo plano e a página indica **A adicionar o Data Foundation. Isto demora alguns minutos.** Os seus próprios fluxos de trabalho, tabelas e restante trabalho ficam como estão. Se o projeto já tiver uma tabela no local onde o modelo guarda uma das suas, nada é instalado e a mensagem indica o nome da tabela.

**Início** é o primeiro separador de cada projeto. Quando um projeto tem o Data Foundation, o grupo **Data Foundation** da respetiva barra contém estas linhas, cada uma com a sua própria hiperligação:

| Linha | Quando aparece |
|---|---|
| **Resumo** | Sempre. Um projeto com Data Foundation e ainda sem nenhum sistema abre nesta linha. |
| **Sistemas** | Quando o projeto tem dois ou mais sistemas, quando um sistema aguarda acesso ou quando o passo seguinte em **Resumo** é adicionar, ligar ou manter um sistema atualizado. |
| **Perguntas** | Enquanto uma pergunta aguarda a sua resposta, com o respetivo número num indicador. |
| **Relatórios** | Sempre. |
| **Alocações** | Num projeto criado com uma solução. |

## Ligar o ERP

O sistema financeiro liga-se ao Data Foundation através da respetiva ligação PlaidCloud. O Data Foundation lê diretamente dela o razão geral, o balancete, os dados mestre, as taxas de câmbio, os orçamentos e, quando o sistema os contém, os razões auxiliares, os saldos de fim de mês e os saldos bancários, e limita-se sempre a ler. As credenciais só são introduzidas no editor de ligações padrão. Cada sistema tem uma página destinada ao administrador que concede o acesso, listada em [Que sistemas podem alimentar o modelo](/pt-pt/guides/projects/data-foundation-getting-started/#que-sistemas-podem-alimentar-o-modelo), e a [Matriz de cobertura do Data Foundation](/pt-pt/reference/data-foundation-coverage-matrix/) mostra que conjuntos de dados cada sistema fornece diretamente.

<Steps>

1. Em **Resumo**, clique em **Adicione o seu sistema financeiro**. Abre-se a página **Sistemas**.

2. Em **Adicionar um sistema**, escolha o seu sistema em **Sistema**. O que se segue depende da forma como o sistema inicia sessão:

   - **QuickBooks Online e Xero** iniciam sessão através da aprovação do acesso na janela do próprio sistema. Clique em **Connect to** e no nome do sistema. A PlaidCloud cria a ligação para o ambiente do projeto e abre a janela de aprovação. Depois de aprovar, o sistema é adicionado e começa a carregar. Se o browser bloquear a janela, permita janelas pop-up para o site e tente novamente.
   - **Um sistema em que inicia sessão com credenciais** lista em **Ligação** as ligações desse tipo que pode utilizar, com a primeira selecionada, e **Nova ligação**. Escolha uma e clique em **Adicionar sistema**. **Nova ligação** abre o editor de ligações padrão com o ambiente do projeto preenchido, e o sistema é adicionado quando guarda a ligação.
   - **SAP S/4HANA, SAP ECC, Oracle E-Business Suite e Sage 100** são acedidos através de um agente PlaidLink na sua rede. Configure primeiro o agente e, em seguida, escolha a respetiva ligação, tal como para qualquer sistema que inicia sessão com credenciais.

3. Para alterar o que é carregado antes de adicionar o sistema, abra **Opções**. **Empresas** lista as empresas do sistema: assinale as que pretende carregar ou nenhuma para as carregar todas. Um sistema que não lista as suas empresas pede-lhe que as introduza. **Meses de histórico** indica quantos meses para trás carregar, de 1 a 120. Alguns sistemas têm também **Definições do sistema**, e um sistema com uma definição indispensável abre **Opções** e pede-a. Sem **Opções**, são carregadas todas as empresas ativas e 24 meses de histórico.

4. Um sistema adicionado com a respetiva ligação começa a carregar de imediato. Se outros fluxos de trabalho utilizarem a mesma ligação, a PlaidCloud pergunta primeiro **Carregar a partir de uma ligação partilhada?** e indica-os, porque o carregamento lê a partir da ligação e pode tornar esses fluxos de trabalho mais lentos. Clique em **Carregar mesmo assim** para continuar.

</Steps>

Ainda não tem acesso? Escolha o sistema e clique antes em **Ainda não tem acesso?**. O sistema é adicionado como **A aguardar acesso**, e é apresentado um único pedido que abrange todos os sistemas em espera, pronto a enviar com **Copiar pedido** ou **Enviar pedido por email**. Quando o acesso chegar, adicione o sistema com a respetiva ligação em **Adicionar um sistema**. No caso do QuickBooks Online e do Xero, clique em **Ligar** na linha do sistema.

Para incluir outro sistema ou outra instância, adicione-o da mesma forma. Adicionar um sistema deixa sempre os outros como estão, pelo que vários sistemas e instâncias alimentam o mesmo modelo consolidado. Quando adiciona um segundo sistema, o Data Foundation faz uma pergunta por assunto em vez de uma por código. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens).

Cada carregamento lê apenas o que mudou: os períodos abertos e o último período fechado são lidos novamente, e os períodos fechados já carregados são mantidos. Aumentar **Meses de histórico** lê apenas os meses acrescentados. Uma alteração numa taxa de câmbio, no mapeamento de entidades ou na moeda de relato volta a ler os meses afetados.

## Sistemas

Cada sistema e instância a partir do qual o projeto carrega é uma origem, e os ficheiros que confirma também são origens. A linha **Sistemas** da barra, e com ela a página, os respetivos botões e o cartão **Ficheiros**, aparece quando o projeto tem dois ou mais sistemas, quando um sistema aguarda acesso ou quando o passo seguinte em **Resumo** é adicionar, ligar ou manter um sistema atualizado. Com um só sistema carregado e atualizado, **Resumo** mostra-o antes em **Your system**. A página **Sistemas** lista todos os sistemas, com **Sistema**, **Estado** e **Último carregamento**. **Estado** é **A aguardar acesso**, **Ligado**, **A carregar**, **Carregado** ou **Falhou**. **Último carregamento** indica quando o sistema foi carregado pela última vez, ou **Ainda não carregado**, e, quando o projeto é atualizado segundo um agendamento, quando está prevista a próxima atualização ou desde quando está em atraso. Por baixo de um sistema que falhou, a respetiva linha indica o motivo.

Cada linha tem o botão adequado à situação do sistema:

| Botão | Quando aparece |
|---|---|
| **Carregar** | O sistema está ligado ou carregado. Lê apenas esse sistema e, em seguida, reconstrói o modelo a partir dos dados de todos os sistemas. Um sistema que falhou apresenta-o ao lado da respetiva correção. |
| **Abrir ligação** | O carregamento do sistema falhou. Abra a respetiva ligação para ver o motivo e corrigi-lo. |
| **Voltar a ligar** | O início de sessão no QuickBooks Online ou no Xero expirou. |
| **Ligar** | O QuickBooks Online ou o Xero aguarda acesso. |
| **Pedir acesso** | Um sistema que inicia sessão com credenciais aguarda acesso. Mostra novamente o pedido a enviar. |

Ao lado, **Testar ligação** inicia sessão e tenta ler cada conjunto de dados; depois lista cada um como **Legível**, **Permissão em falta** ou **Erro** e indica as permissões que deve pedir ao administrador do sistema para adicionar. **Remover** retira um sistema do projeto depois de confirmar **Remover este sistema?**. Tudo o que foi carregado a partir dele é eliminado, e é possível voltar a ligá-lo mais tarde.

Clique em **Editar** num sistema para alterar a forma como é utilizado e, em seguida, clique em **Guardar**:

| Definição | O que faz |
|---|---|
| **Nome** | O rótulo que os relatórios, as perguntas e as mensagens utilizam para o sistema. |
| **Livros de relato, separados por vírgulas** | Os livros contabilísticos a ler, no caso de um sistema que mantém mais do que um. **Todos os livros de relato** lê todos os livros. |
| **Meses que esta fonte fornece** | Para cada **Empresa**, os meses de **De (2026-01)** a **Até (2026-12)** que o sistema fornece. Deixe um mês vazio para não haver limite. Escreva os meses como ano e mês, por exemplo `2026-03`. |
| **Categorias adicionais nesta fonte** | Para cada categoria adicional que o sistema contém, o respetivo **Nome** e onde é **Apresentado em**, ou **Deixar de fora**. |
| **Empresas** e **Meses de histórico** | Que empresas o sistema carrega e quantos meses para trás. |

Acrescentar empresas, ou não assinalar nenhuma, guarda de imediato. Deixar uma empresa de fora pede primeiro que confirme **Carregar menos empresas?**, porque guardar limpa de imediato tudo o que foi carregado a partir desse sistema, e o próximo **Carregar** volta a obter as empresas assinaladas.

Quando dois sistemas fornecem o mesmo mês para a mesma empresa, conta o que está listado mais acima até escolher qual conta a partir de quando. Consulte [Escolher que origem conta a partir de quando](#escolher-que-origem-conta-a-partir-de-quando).

Alterar as origens não volta a ler o ERP. A barra acima de todas as páginas indica **Alterou as suas origens. Prima Aplicar alterações para as usar.** até clicar em **Aplicar alterações**, que executa um carregamento a partir dos dados já obtidos: volta a uniformizar as origens com as novas correspondências, nomes e ficheiros, e reconstrói o modelo. Clique em **Carregar** quando também pretender dados atualizados dos seus sistemas.

## Adicionar ficheiros com dados exteriores ao ERP

Os ficheiros complementam a ligação ERP com dados que um sistema não contém, como taxas de câmbio, indutores de alocação, um [Mapa de códigos](#mapeamento-de-entidades) de códigos de entidade ou um orçamento mantido fora do ERP. Cada ficheiro pertence a um dos conjuntos de dados listados em [Tabelas do Common Finance Model](#tabelas-do-common-finance-model).

<Steps>

1. No cartão **Ficheiros**, por baixo dos sistemas em **Sistemas**, escolha a **Conta de documentos** onde guardar o ficheiro.

2. Largue um ficheiro CSV ou Excel em **Largue aqui um ficheiro CSV ou Excel** ou clique em **Escolha um ficheiro**. O ficheiro é carregado para a pasta `/foundation/` da conta de documentos.

   Para um ficheiro que já esteja na conta de documentos, abra **Mais formas de adicionar ficheiros** e, em **Adicionar um ficheiro que já está na conta de documentos**, introduza o respetivo caminho, por exemplo `/foundation/budget.csv`, e clique em **Adicionar ficheiro**.

   Para ler um ficheiro novo todos os meses, utilize **Adicionar todos os ficheiros correspondentes de uma pasta**: introduza a pasta, escolha a condição que os nomes dos ficheiros devem cumprir face ao que introduzir, **contém**, **começa com**, **termina com**, **é exatamente** ou **corresponde a (\* representa qualquer coisa)**, e clique em **Adicionar ficheiros**. Os ficheiros em pastas dentro dela não são lidos.

3. A PlaidCloud lê o ficheiro e propõe uma correspondência:

   - **Delimitador, separador decimal e datas detetados.** O delimitador (vírgula, ponto e vírgula, tabulação ou barra vertical), o separador decimal e o formato de data são detetados automaticamente.
   - **Conjunto de dados**: a tabela do Common Finance Model a que o ficheiro pertence, identificada a partir do nome do ficheiro e dos cabeçalhos das colunas. Quando a correspondência não é clara, escolha-a na lista.
   - **Separador decimal**: **Ponto (1,234.56)** ou **Vírgula (1.234,56)**.
   - **Formato de data**: apresentado quando o ficheiro tem datas. Altere-o se o formato detetado estiver errado: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Uma grelha com **Coluna no ficheiro**, **Tipo**, **Exemplos** e **Destino**. Altere **Destino** para enviar uma coluna para um campo diferente, ou para **Não carregar**.

4. Responda às perguntas que o ficheiro suscita, como **Para que empresa é este ficheiro?**, **Em que moeda estão os montantes?**, **Estes montantes são acumulados do ano ou do mês?**, **Os montantes estão em milhares ou em milhões?**, **As receitas são apresentadas como números negativos?** ou, para um ficheiro de contratos, **Cada linha é um período de contrato?** (consulte [Registos de contratos](#registos-de-contratos)). Cada pergunta só é feita quando o ficheiro ainda não dá a resposta, exceto **Cada linha é um período de contrato?**, que todos os ficheiros propostos como contratos fazem.

5. Verifique para onde vai cada coluna e clique em **Confirmar correspondência**. Enquanto trabalha, a nota sob o botão indica o motivo da espera. Num projeto que ainda tenha os dados de exemplo, o primeiro ficheiro que confirmar remove também os dados de exemplo, o que pode demorar alguns minutos.

</Steps>

Estas opções aparecem num ficheiro quando se aplicam:

| Opção | Utilize-a para |
|---|---|
| **Which source do these rows apply to?** | Limitar um ficheiro de mapeamento de códigos a uma origem. **Every source** aplica-o a todas. |
| **Where does this file come from?** | Indicar se o ficheiro contém **This project's own codes** ou provém de **Another system**, cujo nome indica, por exemplo `SAP Germany export`. Um ficheiro de outro sistema é verificado quanto a códigos partilhados, tal como uma origem ERP. |
| **Split … into … parts at each …** (em **Avançado**) | Dividir uma coluna que contém vários valores, como `100-200-300`, e enviar cada parte para o seu próprio campo. |
| **Which currency do you report in?** | Definir a moeda de relato quando o projeto ainda não tem uma. Escreva-a com três letras, por exemplo `USD`. |
| **São resultados consolidados ou a sua demonstração de resultados reportada (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Carregar os resultados do sistema de consolidação para que a demonstração de resultados do grupo possa ser [reconciliada](#reconciliar-com-o-sistema-de-consolidação). |

Para retirar um ficheiro do projeto, clique em **Remover** junto dele em **Ficheiros**, ou em **Remove this file** na respetiva correspondência, e confirme. Os seus valores saem dos relatórios da próxima vez que clicar em **Apply changes**.

Quando a PlaidCloud não consegue decidir sozinha o conjunto de dados, o separador decimal ou a ordem das datas, por exemplo num ficheiro cujas datas podem ser lidas como dia/mês ou mês/dia, pede-lhe que escolha antes de confirmar. Adicionar um segundo ficheiro para o mesmo conjunto de dados substitui o primeiro. Se as colunas de um ficheiro posterior não corresponderem ao conjunto de dados, o carregamento indica o ficheiro e as colunas e pede que corrija o ficheiro ou os nomes das colunas, ou que defina o **Schema Mismatch** do passo como `union`.

Os ficheiros aceites são ficheiros de texto CSV, TSV e TXT, ficheiros Excel `.xlsx` (lidos a partir da primeira folha) e ficheiros Parquet.

<Aside type="note">
Um ficheiro em falta ou vazio nunca interrompe um carregamento. Ao adicioná-lo, é indicado que ainda não há nada para mapear, e o carregamento termina com um aviso que indica o caminho. O conjunto de dados mantém as linhas que o ficheiro lhe deu da última vez, se as houver. Volte a adicionar o ficheiro quando ele existir.
</Aside>

### Registos de contratos

Um ficheiro de contratos pode ser um registo de períodos de contrato ou os contratos num fim de mês, por isso confirmar um pergunta **Cada linha é um período de contrato?**. A resposta proposta é **Sim, cada linha é um período de contrato** quando o ficheiro tem uma data de início e nenhuma coluna de fim de mês. Um ficheiro que confirmou antes mantém a sua resposta quando volta a ser adicionado.

- **Sim, cada linha é um período de contrato**: cada linha é um período de um contrato, com a sua data de início, a sua data de fim e o seu valor anual. Cada carregamento copia cada linha para cada fim de mês que abrange, da data de início à data de fim, ou sem limite enquanto a data de fim estiver em branco, até ao mês do carregamento, ou ao último mês do calendário da entidade, se for anterior. Um contrato assinado que começa mais tarde conta a partir do seu início. Cada cópia é `Active`, exceto a cópia do mês do carregamento, que mantém o estado da própria linha. Uma linha sem número de linha é numerada dentro do seu contrato.
- **Não, o ficheiro contém os contratos no fim de um mês**: o ficheiro é a cópia dos contratos de um fim de mês, como qualquer outro ficheiro de contratos.

Uma linha sem data de início, uma linha cujo estado diz que terminou mas que não tem data de fim, e uma linha que termina antes do último dia do seu primeiro mês não são períodos de contrato, pelo que ficam retidas. Consulte [Linhas retidas](#linhas-retidas). Os códigos de cliente e de produto de um registo são adicionados aos clientes e aos produtos, com o código como nome, a menos que outra origem dê um nome ao mesmo código. Os seus códigos de entidade só são adicionados quando nenhuma outra origem dá nome a entidades.

## Carregar os dados

Um carregamento lê os sistemas ligados e os ficheiros confirmados, uniformiza-os no Common Finance Model, converte-os para a moeda de relato, executa as verificações de prontidão e reconstrói os modelos de cálculo. Um sistema adicionado com a respetiva ligação inicia sozinho o seu primeiro carregamento. Antes de qualquer carregamento, **Carregar** é também o passo seguinte em **Resumo**. Depois disso, **Carregar** na linha de um sistema em **Sistemas** lê apenas esse sistema e, em seguida, uniformiza, reconstrói e consolida a partir dos dados de todos os sistemas, pelo que adicionar um sistema nunca volta a ler os outros. Enquanto decorre, **Resumo** indica o que está a ser carregado.

- Só é executado um carregamento de cada vez por projeto. Um segundo **Carregar** ou **Apply changes** indica que já está um carregamento em curso, e não é possível alterar as origens enquanto decorre.
- Se outros fluxos de trabalho utilizarem a mesma ligação, o primeiro carregamento lista-os e pede confirmação, porque um carregamento lê a partir do sistema e pode tornar esses fluxos de trabalho mais lentos. Clique em **Carregar mesmo assim** para avançar.
- Depois de a PlaidCloud ser atualizada, um **Carregar** ou **Aplicar alterações** feito por um Arquiteto atualiza também os fluxos de trabalho gerados do projeto, criando as tabelas de trabalho de que necessitem. Quando está disponível uma versão mais recente do modelo, a barra acima de todas as páginas do Data Foundation indica **Update available** e que um **Carregar** ou **Aplicar alterações** feito por um Arquiteto a instala. Um **Carregar** feito por um Gestor avisa que só um Arquiteto os pode atualizar.
- Aplicar uma atualização mantém as suas próprias edições aos passos gerados. Se alterou um passo e a atualização também o alterou, a sua edição é mantida. Um passo editado que a atualização deixou de gerar é mantido, mas desativado; elimine-o ou volte a ativá-lo se ainda precisar dele. Um passo que a atualização substitui é indicado pelo nome, e o anterior fica nas versões do passo.
- Se uma atualização parou a meio, os respetivos passos podem ser executados fora de ordem até terminar. Prima novamente **Carregar** como Arquiteto para a concluir. Se voltar a parar, contacte o suporte.
- Um sistema cujo carregamento falha mostra **Falhou** em **Sistemas**, com o motivo e a respetiva correção. Quando o último carregamento terminou com um aviso, **Resumo** indica **The last Load ended with a warning:** seguido do aviso.
- Se a leitura de uma entidade e período falhar, o resto é carregado na mesma. Execute novamente **Carregar** para obter apenas o que falhou.
- Se um conjunto de dados de uma origem falhar na leitura, o resto da origem é carregado na mesma, esse conjunto de dados mantém as linhas que tinha, e o sistema mostra **Falhou** em **Sistemas** até um carregamento o ler.

### Linhas retidas

Quando as origens se sobrepõem, um carregamento conta cada valor uma única vez. As linhas que não conta são mantidas ou retidas.

As linhas mantidas ficam no projeto, assinaladas como não contabilizadas, pelo que nada do que um sistema contém se perde e nada é contado duas vezes. Uma linha é mantida quando:

- pertence a outro livro contabilístico, como um livro local ou fiscal, que a origem não está definida para ler;
- fica fora dos meses **De** e **Para** definidos para a respetiva empresa;
- diz respeito a uma empresa e a um mês que outra origem conta, por exemplo o sistema de onde uma entidade saiu;
- foi substituída por um ficheiro para essa entidade e mês.

As linhas retidas são registadas com a origem, a entidade e o motivo, e o carregamento termina com um aviso que indica as contagens, por exemplo `120 rows of NetSuite EU carrying a code another source also uses`. Os motivos são:

| Motivo | Significado |
|---|---|
| Também num ficheiro anterior da origem | Um ficheiro anterior da mesma origem já abrange o mês. |
| Um saldo de abertura posterior | O saldo de abertura mais antigo da entidade e a atividade desde então já contam. |
| Com um código que outra origem também utiliza | O código precisa da sua resposta. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| Com um código mapeado para dois códigos | O mapeamento de códigos dá duas respostas para o código. |
| Com um código que o seu próprio mestre não tem | A lista própria de contas, produtos ou clientes do sistema não tem o código. |
| Totais de relatório ou linhas em branco | As linhas de total ou em branco de um ficheiro. |
| Sem data de início, terminada sem data de fim, ou a terminar antes do último dia do seu primeiro mês, pelo que não é um período de contrato | Uma linha de um registo de contratos que não é um período de contrato. Consulte [Registos de contratos](#registos-de-contratos). |

As contas estatísticas passam para os indutores de alocação em vez do razão e aparecem como movidas, não como um problema.

### Dados do ERP e ficheiros em conjunto

Um ficheiro substitui apenas o que abrange, e as restantes linhas do ERP mantêm-se.

- **Ficheiros mestre** (contas, departamentos, clientes, produtos e valores de segmento) substituem as linhas do ERP com o mesmo código.
- **Ficheiros de transações** substituem as linhas do ERP da mesma entidade e mês. Os ficheiros de razão geral e de balancete também fazem a correspondência por razão, os ficheiros de orçamento por cenário e os ficheiros de indutores estatísticos por cenário e indutor.

Se mais tarde um ficheiro deixar de abranger um mês, os dados do ERP para esse mês voltam no carregamento seguinte.

## Mapeamento de entidades

Cada origem designa as suas entidades com os seus próprios códigos. Um ficheiro **Mapa de códigos** associa esses códigos às entidades do mestre de entidades, para que as linhas de todas as origens fiquem na mesma entidade.

Para o utilizar, adicione um ficheiro CSV ou Excel e escolha o conjunto de dados **Mapa de códigos**:

| Coluna | Contém |
|---|---|
| `source_code` | O código tal como a origem o tem, como um código de empresa. Uma coluna com o nome `source_entity` também lhe é associada. |
| `code` | A entidade a que pertence, tal como o mestre de entidades a designa. Uma coluna com o nome `entity` também lhe é associada. |

Cada linha mapeia um código de entidade, salvo se o ficheiro tiver uma coluna `dimension` que indique o contrário. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens).

- Um código que não esteja no mapa de códigos é utilizado tal como está.
- Vários códigos podem ser mapeados para uma entidade. As respetivas linhas são combinadas, e um mês conta como fechado quando estiver fechado para todos eles.
- As linhas do ficheiro aplicam-se a todas as origens, salvo se escolher uma em **A que fonte se aplicam estas linhas?**, pelo que deve limitar o ficheiro a uma origem quando duas origens utilizam o mesmo código para entidades diferentes.
- Uma linha de um ficheiro **Entidades** substitui a entidade do ERP com o mesmo código de entidade.

A verificação **Every entity known** assinala qualquer linha cuja entidade não esteja no mestre de entidades nem esteja mapeada para uma pelo mapa de códigos. Não é aplicável até ser carregado um mestre de entidades.

## Mapear códigos entre origens

Dois sistemas podem utilizar o mesmo código para coisas diferentes, ou códigos diferentes para a mesma coisa. Quando adiciona um sistema cujos códigos se sobrepõem aos de um sistema já ligado, o Data Foundation faz uma pergunta por assunto em vez de uma por código, por exemplo **Does SAP ECC use the same account codes as NetSuite?** Faz esta pergunta para as contas, os departamentos, os centros de lucro, os locais, os produtos, os clientes e cada categoria adicional.

Cada pergunta aguarda na página **Perguntas** com a resposta sugerida pelo Weave e os respetivos elementos de suporte, como quantos dos códigos partilhados têm o mesmo nome, e indica quantas linhas ficam retidas até responder. Responda **Same codes as** o outro sistema ou **Different codes from** esse sistema.

- Até responder, as linhas com os códigos partilhados ficam retidas, para que cada montante seja contado uma só vez.
- Depois de responder que um sistema utiliza os mesmos códigos, um código que mais tarde lhe seja novo é considerado do outro sistema, sem nova pergunta.
- As correspondências são mantidas por sistema e dimensão, pelo que uma resposta para os departamentos de um sistema nunca altera as contas de outro sistema.
- Uma resposta aplica-se no próximo **Carregar** ou **Aplicar alterações**, e **Histórico** em **Resumo** regista quem a deu, quando e o valor anterior.

Também pode fornecer as correspondências num ficheiro. Adicione um ficheiro com o conjunto de dados **Mapa de códigos** e escolha **Which source do these rows apply to?** para o limitar a uma origem.

## Escolher que origem conta a partir de quando

Quando uma entidade passa de um sistema para outro, ambos os sistemas a contêm. **Perguntas** pergunta **From which month does** o novo sistema **count for** a entidade, e sugere o mês seguinte ao último mês do razão do sistema anterior. O sistema anterior mantém os meses anteriores.

O cartão **Cobertura de fontes** em **Resumo** lista quaisquer outros meses que duas origens forneçam em simultâneo. Em **Problemas**, para duas origens que se sobrepõem numa empresa, introduza o mês em **Esse mês é**, por exemplo `2026-04`, escolha a origem em **Qual a origem que conta a partir desse mês?**, clique em **Guardar escolha** e depois clique em **Aplicar alterações** na barra acima da página. Até escolher, só a primeira das duas é contabilizada, e a outra origem mantém os meses anteriores ao que introduzir. **Requer atenção** explica as sobreposições que são contabilizadas conforme descrito, como duas origens que dão taxas de câmbio diferentes para uma empresa, e indica de quem são as taxas utilizadas.

## Conversão de moedas

Cada carregamento converte os montantes do razão geral, do balancete, das vendas, do inventário, do orçamento e dos razões auxiliares da respetiva moeda local para uma única moeda de relato. Os relatórios e os modelos de cálculo leem os montantes convertidos, pelo que as entidades em moedas diferentes, de qualquer sistema, somam corretamente.

### A moeda de relato

Para escolher a moeda de relato, defina a variável de projeto `reporting_currency` com um código de moeda como `USD`. Consulte [Gerir variáveis de projeto](/pt-pt/guides/projects/managing-projects/#gerir-variáveis-do-projeto). Pode, em alternativa, abrir **Ações ▾ > Definições do projeto…** em **Resumo** e introduzir o código em **Moeda de reporte**. O modelo cria-a em branco. Enquanto estiver em branco, cada carregamento utiliza a primeira destas opções que indique exatamente uma moeda:

1. A moeda de grupo das entidades.
2. A moeda local das entidades de nível superior, as que não têm entidade-mãe.
3. A moeda local dos ficheiros.

Se nenhuma delas indicar exatamente uma moeda, defina `reporting_currency` manualmente.

Os montantes já na moeda de relato ficam como estão, pelo que um projeto cujos dados estejam todos numa só moeda não precisa de taxas.

Os ficheiros de vendas, inventário e orçamento também podem ter uma moeda. Mapeie uma coluna com o nome `Currency` ou `Local Currency` e ela é detetada automaticamente, e os montantes locais do ficheiro são convertidos para a moeda de relato. Um montante de grupo ou de relato que já esteja no ficheiro é mantido tal como está. O custo padrão do mestre de produtos já está na moeda do grupo e não é convertido.

### Taxas de câmbio

Uma taxa converte uma unidade de uma moeda na moeda de relato para um mês: o montante convertido é o montante local multiplicado pela taxa.

- **A partir do ERP**, cada carregamento lê as taxas de câmbio que o ERP contém.
- **A partir de um ficheiro**, adicione um ficheiro CSV ou Excel e escolha o conjunto de dados **Taxas de câmbio**. Uma taxa no ficheiro substitui a taxa do ERP para as mesmas moedas e mês. Utilize um ficheiro para relatar numa moeda para a qual os ERP não publicam taxas, ou para adicionar taxas planeadas para os meses do orçamento.

| Coluna | Contém |
|---|---|
| `from_currency` | A moeda de origem da conversão, por exemplo `EUR`. |
| `to_currency` | A moeda de relato, por exemplo `USD`. |
| `period` | O mês, no formato `YYYY-MM`. |
| `average_rate` | A taxa média do mês. |
| `closing_rate` | A taxa no final do mês. |
| `historical_rate` | A taxa histórica, para o capital próprio e para as contas definidas com a taxa histórica. |

Quando uma moeda não tem taxa para a moeda de relato, é invertida a taxa no sentido contrário, da moeda de relato para essa moeda, mantendo 12 casas decimais. Na falta desta, a taxa dessa moeda para outra moeda é multiplicada pela taxa dessa outra moeda para a moeda de relato.

### Que taxa se aplica

Cada linha é convertida a partir da sua própria moeda, pelo que uma linha numa moeda diferente da da sua entidade é convertida a partir da moeda em que está. Aplica-se a primeira regra que corresponda à linha:

| Linha | Taxa |
|---|---|
| Contas estatísticas e contas sem lançamentos | Não convertidas. |
| Já na moeda de relato | Não convertida. |
| Conta com um tipo de taxa | Essa taxa: média, de fecho ou histórica. A histórica recorre à de fecho quando não existe taxa histórica. Num ERP, o tipo de taxa é o próprio tipo de taxa da conta. Num ficheiro de plano de contas, mapeie uma coluna de tipo de taxa para `fx_rate_type` com `average`, `closing` ou `historical`. |
| Linha de vendas | A taxa média do período. |
| Saldo de inventário | A taxa de fecho do período. |
| Fatura de fornecedor, nota de encomenda, pagamento, encomenda de venda, movimento de ativo, movimento de receita diferida, movimento de inventário ou custo padrão | A taxa média do período. |
| Conta a receber ou a pagar em aberto, montante em aberto de uma encomenda de venda, valor de um contrato ou saldo bancário | A taxa de fecho do final do mês a que se refere. |
| Linha de orçamento | Por conta, tal como no razão geral: a taxa média para as contas de resultados e a taxa de fecho para as contas de balanço. |
| Conta de resultados | A taxa média do período. |
| Conta de capital próprio | A taxa histórica, ou a taxa de fecho quando não existe taxa histórica. |
| Qualquer outra conta de balanço | A taxa de fecho do período. |

Os montantes convertidos não são arredondados, pelo que os totais não se desviam.

As vistas do pipeline `cfm_rv_pipeline_month`, `cfm_rv_won_booked` e `cfm_rv_campaign_window` convertem os montantes ganhos, perdidos e criados das oportunidades à taxa média do mês em que o negócio foi fechado ou criado. O pipeline em aberto de um mês é convertido à taxa de fecho desse mês ou, enquanto a taxa do próprio mês ainda não estiver carregada, à taxa de fecho mais recente carregada para a moeda.

<Aside type="note">
O montante ganho, perdido ou criado de um negócio em moeda estrangeira fica de fora quando a respetiva moeda não tem taxa média para esse mês, em vez de ser apresentado a outra taxa. O negócio continua a ser contabilizado. O montante de um negócio ganho em moeda estrangeira fica de fora de `cfm_rv_pipeline_month`, `cfm_rv_won_booked` e `cfm_rv_campaign_window` até ser carregada a taxa média do respetivo mês, pelo que os negócios ganhos em moeda estrangeira do mês corrente ficam em falta nos montantes ganhos até lá. Adicione a taxa a um ficheiro **Taxas de câmbio** ou verifique se a ligação consegue ler as taxas de câmbio do ERP e, depois, execute novamente **Carregar**.
</Aside>

<Aside type="note">
O razão geral e o balancete contêm os movimentos de cada período, pelo que os respetivos montantes de balanço são os movimentos de cada mês convertidos à taxa desse mês. O balanço consolidado, por sua vez, converte os saldos à taxa de fecho do mês apresentado, com a diferença numa linha de diferenças de conversão no capital próprio. Consulte [Consolidação de gestão](#consolidação-de-gestão).
</Aside>

## Hierarquias

Cada carregamento reconstrói as dimensões a partir dos dados mestre de todas as origens. Existem sete dimensões de início e até dez categorias adicionais:

| Dimensão | Construída a partir de |
|---|---|
| **Entidade** | Entidades e respetivas entidades-mãe |
| **Conta** | Plano de contas e contas-mãe |
| **Departamento** | Departamentos e respetivos departamentos-mãe |
| **Cliente** | Clientes e respetivos clientes-mãe |
| **Produto** | Produtos e respetivos produtos-mãe |
| **Segmento 1** | Valores de segmento para `segment_1` |
| **Segmento 2** | Valores de segmento para `segment_2` |
| **Segmento 3** a **Segmento 10** | Valores de segmento para `segment_3` a `segment_10`, quando as origens os têm |

- Um registo sem elemento-pai, ou que se indica a si próprio como elemento-pai, é carregado como membro de nível superior.
- Como cada carregamento reconstrói as hierarquias, altere um elemento-pai no ERP ou no ficheiro, e não na dimensão.
- Um problema numa hierarquia afeta apenas essa dimensão. O carregamento e os modelos de cálculo do modelo concluem-se na mesma.
- Pode dar a cada categoria adicional o nome do que contém, por exemplo **Classe** ou **Região**. Abra **Ações ▾ > Definições do projeto…** em **Resumo**, introduza os nomes que os relatórios utilizam em **Nomes**, em **Definições do projeto**, e clique em **Guardar**. Os nomes utilizam letras, números, espaços, pontos, hífenes e carateres de sublinhado, até 60 carateres.
- Cada origem indica em qual dos seus nomes de categoria fica cada uma das suas próprias categorias adicionais. Em **Sistemas**, clique em **Editar** na origem, escolha o nome para cada uma em **Categorias adicionais nesta fonte**, ou escolha **Deixar de fora**, e clique em **Guardar**. As origens que designam uma categoria com nomes diferentes, como `Class` e `Business area`, passam então a partilhar uma posição.

Para fornecer hierarquias de segmentos a partir de um ficheiro, escolha o conjunto de dados **Valores de segmento**:

| Coluna | Contém |
|---|---|
| `segment` | O segmento a que o valor pertence: `segment_1` a `segment_10`. |
| `segment_value` | O valor, tal como as linhas do razão geral, de vendas e de orçamento o têm. |
| `segment_value_name` | O respetivo nome. |
| `parent_segment_value` | O respetivo elemento-pai dentro do mesmo segmento. |

## Verificações de prontidão

Estas verificações são o detalhe por baixo das cinco garantias em **Resumo**; consulte [Pode confiar nos números?](/pt-pt/guides/projects/data-foundation-proof/).

Cada **Carregar** e **Aplicar alterações** executa-as para cada entidade e período, e cada verificação conta para uma das cinco garantias. Uma verificação que falha fica a vermelho. Um alerta fica a âmbar: algo a analisar que não compromete a exatidão dos valores. No painel de controlo **CFM-Accounting - Close and assurance**, o separador **What needs fixing** mostra **Every check, by system, month chosen**, com o número de itens a vermelho que cada verificação tem para cada sistema, em que zero significa que não há nada a corrigir. A tabela de itens a corrigir, do maior para o menor, para o mês escolhido, indica cada item a vermelho e o que fazer, como carregar o plano de contas, carregar taxas de câmbio ou executar **Carregar** novamente. Consulte [Painéis de controlo, indicadores e caminhos de análise](/pt-pt/guides/projects/data-foundation-dashboards/).

As principais verificações são:

| Verificação | Incluída em | O que confirma |
|---|---|---|
| **Every month loaded** | **Nada se perdeu pelo caminho** | Todos os períodos fiscais têm linhas do razão geral e todas as leituras do ERP tiveram êxito. Um período fechado sem linhas falha; um período aberto sem linhas é um alerta. |
| **Trial balance equals the ledger** | **Equilibrado com cada sistema** | O balancete é igual ao razão geral para cada entidade, período e conta. Quando tanto o balancete como o razão geral têm departamentos para uma conta, verifica também a coincidência por departamento. |
| **Sales equal the ledger** | **Nada se perdeu pelo caminho** | As linhas de vendas são iguais às contas de receita e de custo das mercadorias vendidas do razão geral em cada período. |
| **Every product and customer of a sale known** | **Nada se perdeu pelo caminho** | Todas as linhas de vendas indicam um produto e um cliente que existem nos mestres de produtos e de clientes. |
| **Every account known** e **Every account typed** | **Nada se perdeu pelo caminho** | Todas as linhas do razão geral indicam uma conta do plano de contas. As linhas com uma conta desconhecida ficam fora da demonstração de resultados. Uma conta com lançamentos mas sem tipo de conta também falha, e uma origem cujo plano classifica contas de Receita mas nenhuma conta de custo das mercadorias vendidas é um alerta. |
| **Every amount has a rate** | **O grupo fecha** | Todas as linhas do razão geral, do balancete, de vendas, de inventário e de orçamento têm um montante na moeda de relato. Uma linha de resultados ou de vendas sem taxa falha, porque a demonstração de resultados lê montantes convertidos. Uma linha de balanço, de inventário ou de orçamento sem taxa é um alerta, pelo que deve carregar taxas planeadas para os meses do orçamento. Consulte [Conversão de moedas](#conversão-de-moedas). |
| **Every entity known** | **Nada se perdeu pelo caminho** | Todas as linhas do razão geral, do balancete e de vendas indicam uma entidade do mestre de entidades, diretamente ou mapeada para uma num ficheiro **Mapa de códigos**. Não aplicável até ser carregado um mestre de entidades. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |

Estas verificações só surgem quando requerem atenção, todas em **Nada se perdeu pelo caminho**:

| Verificação | O que confirma |
|---|---|
| **Reporting book chosen** | Uma origem que tem vários livros contabilísticos para uma entidade teve o seu livro de relato escolhido. Até escolher, só conta o primeiro livro. |
| **Codes mapped** | Todos os códigos utilizados por mais do que uma origem foram respondidos. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| **One source for each key** | Não há duas origens a fornecer os mesmos meses de uma empresa, a menos que tenha escolhido qual conta. |
| **Hierarchies complete** | Todos os elementos-pai que uma dimensão indica existem, e nenhum membro é o seu próprio elemento-pai ou antecessor. Um elemento-pai em falta coloca os seus filhos no topo da hierarquia, e um ciclo impede o carregamento dessa hierarquia. Os totais não são afetados. |
| **Months placed in the fiscal calendar** | Os períodos fiscais de cada entidade são meses de calendário, e cada mês de linhas pode ser colocado num período fiscal. É um alerta quando os períodos de uma entidade não são meses de calendário (4-4-5, 13 períodos), ou quando as linhas de um mês podem pertencer a mais do que um período fiscal ou o calendário fiscal não tem o mês. |

Duas verificações de configuração só surgem quando requerem atenção. Uma surge quando só está definida uma das variáveis de projeto `overhead_department` e `overhead_driver`, ou nenhum indutor de alocação corresponde a `overhead_driver`, pelo que a alocação de custos indiretos não faria nada: defina ambas ou limpe ambas para desativar a alocação de custos indiretos. A outra surge quando há linhas de orçamento carregadas, mas nenhuma está na **Versão do orçamento** das definições do projeto (a variável de projeto `budget_version`), pelo que a comparação com o orçamento ficaria vazia.

## Consolidação de gestão

Cada carregamento constrói uma consolidação de gestão: a demonstração de resultados, o balanço e a demonstração dos fluxos de caixa de todas as entidades do grupo, na moeda de relato, com as operações intragrupo eliminadas. Destina-se ao relato de gestão. O sistema de consolidação continua a ser o registo oficial do grupo para efeitos legais; reconcilie com ele conforme descrito abaixo.

Onde quer que apareçam valores consolidados, estes têm a etiqueta **Management consolidation**: ao lado da primeira linha de **Resumo**, na linha de contexto no topo de cada painel de controlo e na coluna **Basis** do pacote para o conselho, cuja coluna **Basis note** indica "Entidades combinadas, operações intragrupo eliminadas, convertidas para a moeda de relato. Não é uma consolidação legal." Um projeto com uma só entidade não mostra etiqueta.

<Aside type="note">
A consolidação de gestão não é uma consolidação legal ou estatutária. Não elimina os investimentos contra o capital próprio, e não tem goodwill nem interesses minoritários.
</Aside>

### Escolher o grupo

Em **Resumo**, o cartão **O grupo** mostra a moeda de relato. Clique em **Alterar**, ou abra **Ações ▾ > Definições do projeto…** em **Resumo**, para abrir **Definições do projeto**, onde **Acesso por grupo e linha** lista as **Empresas do grupo**. Uma empresa que desmarque continua nos relatórios por si só, mas fica fora do total do grupo. Clique em **Guardar**. A alteração aplica-se no **Carregar** ou **Aplicar alterações** seguinte. Uma empresa nova fica no grupo até a desmarcar.

O ano fiscal do grupo começa no mês definido pela variável de projeto `group_fy_start_month`. Enquanto estiver em branco, o que acontece salvo se a definir, o ano fiscal do grupo começa no mês em que começa o ano fiscal da entidade de topo, a única entidade sem elemento-pai, ou em janeiro quando a entidade de topo não tem calendário fiscal. Quando mais do que uma entidade não tem elemento-pai, ou a entidade de topo é um nó da hierarquia sem calendário fiscal próprio, começa em janeiro e a consolidação aparece a âmbar até definir o mês.

### O que obtém

| Tabela | Contém |
|---|---|
| **Demonstração de resultados do grupo** | Uma linha por entidade, período e rubrica (receita, custo das mercadorias vendidas, gastos operacionais, não operacional, diferença intragrupo), na moeda de relato. As receitas e os custos têm o seu sinal natural. |
| **Demonstração de resultados do grupo acumulada no ano** | O mesmo, acumulado no ano, até ao último período totalmente carregado do grupo. |
| `group_statements` | A demonstração de resultados, o balanço e a demonstração dos fluxos de caixa tal como apresentados, linha a linha, com todos os subtotais e totais, para cada entidade, as eliminações e o grupo, na moeda de relato. Os rendimentos, os ativos e as entradas de caixa são positivos. Cada linha tem o montante do mês e o acumulado do ano fiscal do grupo até esse mês; uma linha de balanço tem o saldo do mês. |
| `group_result` | As mesmas três demonstrações por entidade, linha, conta e mês, em todos os livros de relato, na moeda de relato e, no caso de uma entidade noutra moeda, na sua própria moeda. Os montantes são positivos a débito, tal como no razão geral. |
| **Pares intragrupo** | Uma linha por par de entidades, grupo e período, com o montante de cada lado e o residual. |
| **Linhas intragrupo** | As linhas do razão por detrás de um valor do grupo ou de um par, com o parceiro comercial. |
| **Reconciliação** | A demonstração de resultados do grupo acumulada no ano face ao sistema de consolidação. |

Nestas tabelas aparecem três nomes de entidade:

| Entidade | Significado |
|---|---|
| **Eliminações** | As eliminações intragrupo. O seu saldo é zero, pelo que devem ser mantidas para os valores do grupo e filtradas para obter a soma das entidades antes da eliminação. |
| **Total do grupo** | O total do sistema de consolidação, na reconciliação. |
| **Não mapeado** | Linhas sem período, e contas ou entidades do sistema de consolidação que este projeto não tem. |

Os indicadores **Consolidated income**, **Consolidated result** e **IC difference** leem **Group P&L**. Estes indicadores e um caminho de análise para cada uma das tabelas **Group P&L**, intragrupo e de reconciliação respondem a perguntas sobre o grupo. O painel de controlo **CFM-Finance - Statements** e o pacote para o conselho mostram as três demonstrações.

#### As três demonstrações

- **Demonstração de resultados**: cada mês à taxa média desse mês.
- **Balanço**: o saldo de cada conta é o seu saldo de abertura mais a atividade até ao mês. Os saldos estão à taxa de fecho do mês apresentado, e o capital próprio à taxa histórica, ou ao tipo de taxa próprio da conta quando o tiver. Uma conta de capital próprio sem taxa histórica fica à taxa de fecho. A demonstração de resultados dos anos fiscais anteriores está nos resultados transitados, e a deste ano nos resultados do exercício, cada uma às taxas médias dos respetivos meses.
- A diferença de conversão é uma linha no capital próprio para cada entidade, calculada como o capital próprio e os resultados à taxa de fecho menos os valores convertidos. É o que faz um balanço convertido ficar equilibrado, e nunca um valor de acerto. Quando uma entidade noutra moeda não tem taxa de fecho para um mês, o respetivo balanço não é convertido nesse mês e não fica equilibrado, e a consolidação aparece a âmbar com o nome da entidade e do mês. Carregue a taxa e, em seguida, execute **Aplicar alterações**.
- **Fluxos de caixa**: calculados a partir do movimento de cada conta de balanço no mês, segundo a respetiva função de conta, à taxa média do mês. Uma linha de efeito das taxas de câmbio contém a parte da variação de caixa, às taxas de fecho, que resulta da variação das taxas. Uma conta de balanço sem função fica na linha de outras variações.
- As **Funções das contas** respondidas em **Perguntas** colocam as contas nas suas linhas. **Comissões** é uma linha de gastos operacionais própria. **Notas convertíveis e SAFEs** é uma linha de passivo, e a sua variação está em financiamento nos fluxos de caixa; uma conta de capital próprio com essa função permanece no capital próprio. A uma conta de gastos com o nome de uma comissão é sugerido **Comissões**, a uma conta de passivo ou de capital próprio com o nome de uma nota convertível, de um SAFE ou de um simple agreement **Notas convertíveis e SAFEs**, e a uma conta com o nome de um empréstimo de sócio, de um empréstimo do proprietário ou de um empréstimo de alguém **Empréstimos obtidos**, mesmo quando o nome também diz a pagar. A uma conta de gastos com o nome de um prestador de serviços é sugerido **Pessoal**.

O balanço termina com uma linha de controlo, ativos menos passivos e capital próprio, e a demonstração dos fluxos de caixa com a variação de caixa menos o movimento das contas de caixa. Ambas são zero quando a demonstração está correta. Consulte [Pode confiar nos números?](/pt-pt/guides/projects/data-foundation-proof/) para conhecer as garantias que as comprovam.

### Eliminações intragrupo

As linhas intragrupo são emparelhadas por parceiro comercial. É utilizado o parceiro indicado na linha; quando uma linha não tem nenhum, é utilizado o parceiro do respetivo cliente. Ambos os lados de um par são eliminados, e o montante em que os dois lados não coincidem é registado numa linha de diferença intragrupo. Cada par recebe um motivo:

| Motivo | Significado |
|---|---|
| **Correspondente** | Ambos os lados registaram o mesmo montante. |
| **Só um dos lados registou** | Uma entidade registou a transação e o seu parceiro não. |
| **Não eliminado** | Uma linha do par não tem taxa de câmbio, pelo que nenhum dos lados é eliminado. |

Um par é avaliado pelo seu acumulado do ano. A verificação intragrupo fica a âmbar quando a diferença de um par excede a variável de projeto `group_amber` (predefinição `1`) e a vermelho acima de `group_red` (predefinição `1000`), que é a **Tolerância intragrupo** em **Definições do projeto** (não é apresentada enquanto o grupo tiver apenas uma empresa). As linhas sem parceiro, ou com um parceiro que não é uma entidade, não são eliminadas e são contabilizadas nessa verificação. Uma origem que tem parceiros ao lado de outra que não tem aparece a âmbar.

As entidades de eliminação próprias de uma origem ficam fora da demonstração de resultados do grupo, e a verificação de consolidação indica-o.

Nas três demonstrações, as contas a receber e a pagar intragrupo são eliminadas por par, tal como os rendimentos e os custos intragrupo. A diferença entre os dois lados de um par fica na linha de diferenças intragrupo da demonstração de resultados ou do balanço, pelo que o balanço do grupo continua equilibrado, e o respetivo movimento fica na linha de variação dos saldos intragrupo da demonstração dos fluxos de caixa. Cada linha de eliminação tem as duas entidades e o país, a região e a divisão que partilham, pelo que uma divisão, um país ou uma região elimina apenas os pares cujas duas entidades estão ambas dentro dela, e o grupo elimina todos os pares.

### Reconciliar com o sistema de consolidação

Adicione como ficheiro os resultados que o sistema de consolidação reporta e assinale **São resultados consolidados ou a sua demonstração de resultados reportada (OneStream, Anaplan, SAP Group Reporting, FCCS)** ao confirmar a respetiva correspondência. Responda a **Que versão dos números é esta?** com o nome do sistema. A tabela **Reconciliação** mostra então **nosso**, **reportado** e **diferença** para cada entidade e rubrica, acumulados no ano. Uma diferença explica-se normalmente nas linhas **Eliminações**, **Total do grupo** e **Não mapeado**, ou pelas taxas de câmbio que o sistema utiliza. A verificação de reconciliação lista todas as rubricas acima de `group_amber`.

### Quem pode ver

Os resultados do grupo seguem o acesso às linhas do projeto. Quando o acesso às linhas impede os resultados do grupo, a verificação de consolidação aparece a âmbar. Uma pessoa que só vê algumas entidades vê as somas dessas entidades antes da eliminação, e **Resumo** informa-a: "Estes números abrangem apenas as entidades a que tem acesso, não a empresa inteira." As linhas **Eliminações** e as tabelas intragrupo exigem acesso a todas as entidades.

**Restringir linhas por entidade**, em **Acesso por grupo e linha**, limita um grupo com permissões de entidade às linhas dessas entidades, em todas as tabelas com uma coluna de entidade. Só um Arquiteto o vê. Assinalar ou desmarcar **Restringir** aplica-se de imediato, e é recusado enquanto o acesso às linhas estiver desativado para a área de trabalho. Desmarcá-lo enquanto houver grupos com permissões de entidade pergunta primeiro **Remover as permissões de entidade?**; clique em **Desativar** para continuar.

Se o projeto limitar quem vê que linhas através de uma coluna que as tabelas do grupo não têm, como o departamento, os resultados do grupo ficam desativados para todos e a verificação de consolidação indica **Group views are off**. Nesse caso, só um Arquiteto pode assinalar **Todas as pessoas do projeto podem ver os resultados do grupo** em **Acesso por grupo e linha** e clicar em **Guardar**; os restantes não veem a caixa. A alteração aplica-se no **Carregar** ou **Aplicar alterações** seguinte.

## Manter os dados atualizados

Depois de concluído um carregamento e sem nenhuma pergunta pendente que retenha linhas, o passo seguinte em **Resumo** é **Manter atualizado** até que **Atualizar**, em **Definições do projeto**, seja **Diário**, **Semanal** ou **Mensal**. Há duas formas de agendar o **Carregar**:

- **Ações ▾ > Atualizar todas as noites**, em **Resumo**, executa **Carregar** todas as noites às 02:00 UTC.
- Abra **Ações ▾ > Definições do projeto…** em **Resumo**. Em **Atualizar**, escolha **Diário**, **Semanal** ou **Mensal** e defina **Hora de atualização (UTC)**, escrita em horas e minutos, como `02:00`. Para **Semanal**, **Dia de atualização** vai de 1 (segunda-feira) a 7 (domingo); para **Mensal**, é o dia do mês. Clique em **Guardar**. **A pedido** remove o agendamento.

Só é possível configurar um agendamento depois de um carregamento com uma origem ter terminado sem verificações a vermelho, pelo que um projeto que só tenha dados de exemplo não pode ser agendado. Se só vê algumas das entidades do projeto, é um Arquiteto que o configura. Quando não é possível configurar um agendamento, é apresentado o motivo. Enquanto **Atualizar** for **Diário**, **Semanal** ou **Mensal**, a página **Sistemas** mostra quando está prevista a próxima atualização de cada sistema; consulte [A atualidade dos dados de cada sistema](/pt-pt/guides/projects/data-foundation-proof/#a-atualidade-dos-dados-de-cada-sistema). **Atualizar todas as noites** deixa **Atualizar** como está, pelo que não é apresentada nenhuma próxima atualização e **Manter atualizado** continua a ser o passo seguinte.

O carregamento agendado é executado como a pessoa que o configurou. Se essa pessoa deixar de poder utilizar a ligação de um sistema, o carregamento é ignorado com um aviso que indica o nome dessa pessoa e a ligação; volte a configurar o agendamento.

Um ficheiro em falta ou vazio num carregamento agendado termina com um aviso que indica o caminho, e não com um erro, e o resto do modelo é carregado na mesma.

## Nomes de negócio

Os **Nomes de negócio** dão aos códigos do modelo os nomes que a sua empresa utiliza. Os relatórios, os indicadores e o Ask mostram estes nomes, e um nome guardado aplica-se de imediato. Os carregamentos posteriores mantêm-no. Abra **Ações ▾ > Definições do projeto…** em **Resumo**; **Nomes de negócio** está no cartão **Nomes** de **Definições do projeto**.

1. Clique em **Adicionar um nome** e escolha o **Tipo**: **Categoria**, **Linha da demonstração de resultados**, **Métrica**, **Coluna**, **Entidade** ou **Conta**.
2. Introduza o **Código**: `segment_1` a `segment_10` para uma categoria, a chave da linha para uma linha da demonstração de resultados, o nome do indicador, `table.column` para uma coluna, ou o código de uma entidade ou conta.
3. Introduza o **Nome**, com no máximo 60 carateres numa só linha.
4. Clique em **Guardar**. A caixa de diálogo fecha-se quando tudo o que contém estiver guardado; um nome recusado é indicado por baixo da grelha, e a caixa de diálogo permanece aberta.

Guardar substitui a lista inteira. Uma linha com um nome vazio remove esse nome, e **Remover selecionados** remove as linhas assinaladas. Dar nome ao mesmo código duas vezes é recusado. Os nomes de negócio são também escritos na descrição do caminho de análise para que o assistente utilize as suas palavras, e essa descrição tem um limite de comprimento: se um nome a tornar demasiado longa, nada é guardado e é informado disso.

## Classes de receita e funções das equipas

As classes de receita são os tipos de receita que a sua empresa vende, como SaaS ou BPO, e a função de uma equipa indica para que serve o custo da equipa. O painel de controlo [CFM-Executive - Growth and efficiency](/pt-pt/guides/projects/data-foundation-dashboards/#crescimento-e-eficiência) lê ambas.

**Classes de receita** em **Definições do projeto** lista as classes, cada uma com um nome e um tipo: **Subscrição**, **Suporte e manutenção**, **Serviço gerido**, **Implementação**, **Consultoria e serviços profissionais** ou **Outro**. Os três primeiros tipos são recorrentes. Um projeto começa com uma classe de cada tipo, com o nome do tipo. Abra **Ações ▾ > Definições do projeto…** em **Resumo**. Clique em **Adicionar** para uma nova classe, mude o nome de uma classe ou o seu tipo, ou clique em **Remover**, e depois em **Guardar**.

- Cada classe precisa de um nome, com no máximo 60 carateres, e duas classes não podem ter o mesmo nome. Um nome não pode conter uma aspa simples, uma barra invertida nem chavetas, e "Shared", "Not yet classed" e "Intercompany removed" estão reservados para os relatórios.
- Mudar o nome de uma classe ou o seu tipo mantém todas as respostas dadas com ela. Os painéis de controlo mostram a alteração após o próximo **Carregar** ou **Aplicar alterações**.
- Remover uma classe volta a perguntar por cada conta e produto respondidos com ela.

**Perguntas** pergunta pela classe e pela função em **Classes de receita das contas**, **Classes de receita dos produtos** e **Funções das equipas**:

- **Qual é a classe de receita da conta …?** para cada conta de receita e de custo da receita em que o razão lança e que não tem classe, uma pergunta por conta, nunca uma para uma conta-mãe e as suas contas em conjunto. Uma conta de custo da receita também pode ser **Partilhado por todas as classes**: o seu custo é repartido pelas classes segundo a quota de receita de cada classe nos 12 meses até cada mês.
- **Qual é a classe de receita do produto …?** para cada produto de um contrato que não tem classe. A classe de um produto divide a receita recorrente por classe; cada linha de contrato conta na receita recorrente anual, seja qual for a sua classe.
- **Qual é a função do departamento … de …?** para cada departamento em que o razão lança, ou **Qual é a função do centro de lucro … de …?** para cada centro de lucro quando o seu sistema não tem departamentos, como uma Classe do QuickBooks Online. A resposta é **Custo da receita**, **Vendas e marketing**, **Investigação e desenvolvimento** ou **Gerais e administrativos**, e as equipas de cada sistema são perguntadas em separado.

A sugestão vem do nome: a uma conta ou produto com o nome de subscrições, SaaS ou manutenção, por exemplo, é sugerida uma classe desse tipo; uma palavra depois de "non-" não conta, pelo que "Non-recurring" não sugere nenhuma classe recorrente. A uma conta de receita cujo nome não a coloca em nenhuma classe é sugerida uma classe do tipo **Outro**, ou outra classe que não seja recorrente, e a uma conta de custo da receita **Partilhado por todas as classes**. A um produto só é feita uma sugestão quando o nome o coloca numa classe. A uma equipa é sugerida uma função a partir do nome, como **Vendas e marketing** para uma equipa de vendas ou de marketing, e, caso contrário, **Gerais e administrativos**.

Estas perguntas não retêm nada: não põem o projeto a âmbar e nunca são o passo seguinte em **Resumo**. Até uma conta ser respondida, a sua receita é "Not yet classed" e não conta como recorrente; um produto ainda não respondido conta na mesma na receita recorrente anual, como "Not yet classed". O painel de controlo indica o que ainda não foi respondido por baixo dos valores que afeta.

## Explicar um número

**Explicar este número** mostra o que compõe um valor. Depois de um mês carregado, **Resumo** apresenta o resultado líquido do ano até ao último mês completo, com **Explicar este número** ao lado. Esta opção abre **Explain: Net income**, com o valor do ano até esse mês no topo e, em seguida, o que o compõe, cada lista do maior para o menor:

| Lista | O que contém |
|---|---|
| **Linhas** | As linhas da demonstração que somam o valor. |
| **Entidades** | A parte de cada entidade. Num grupo, as eliminações são uma delas. |
| **Contas** | A parte de cada conta. |

Cada lista mostra os dez maiores e o resto como um único item, como **Other accounts (12)**, pelo que cada lista soma o valor. Um nome que seja uma hiperligação abre a sua própria explicação, apenas para essa linha, entidade ou conta. **Maiores documentos** lista os dez maiores documentos do razão por trás do valor, com **Sistema**, **Entidade**, **Documento**, **Lançado**, **Conta**, **Descrição** e **Montante**, e **Exportar todos os documentos** transfere-os todos. **Perguntar ao Weave porque se alterou** pergunta ao Weave porque é que o valor mudou no ano até esse mês e que entidades, contas e documentos o fizeram mudar.

A janela segue o seu acesso às linhas: só pode explicar os valores que consegue ver. Uma tabela que ainda não exista é um aviso, não um erro. Um número sem nada por detrás indica **Nada a explicar**.

## Regras de alocação

As alocações distribuem custos partilhados, como os custos indiretos, por departamentos, produtos e clientes. O modelo tem duas fases: **Etapa 1: gastos gerais para departamentos** e **Etapa 2: departamentos para produtos e clientes**. Num projeto criado com uma solução, clique em **Alocações** no grupo **Data Foundation** da barra **Início**. Abre-se **Regras de imputação**, onde pode ver ou alterar a forma como cada uma é feita. Sem alterações, funcionam como funcionavam antes de o assistente existir. Um leitor pode abrir as regras, mas não guardá-las.

Para cada fase, o assistente faz quatro perguntas:

| Passo | Pergunta | Opções |
|---|---|---|
| **Conjunto** | Que custos pretende distribuir? | O tipo de conta e, na fase 1, o departamento que contém o custo, ou **All departments**. |
| **Indutor** | Com base em que pretende distribuí-los? | **Statistic** que carregou como indutores de alocação, como o número de colaboradores ou a área em pés quadrados, **Net sales amount**, **Sales quantity** ou **Spread evenly**. Utilize o indutor de **Same period** ou **Same period last year**. |
| **Destino** | Onde ficam? | Fase 1: departamentos. Fase 2: produtos, clientes ou ambos. |
| **Método** | O que acontece quando um indutor é negativo? | **Ignore negative values** ou **Stop and tell me**. |

Sob os passos, **Preview for** um mês, escrito como ano e mês, por exemplo `2026-09`, mostra o que as regras fariam, incluindo as que ainda não guardou: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Qualquer valor não alocado é custo que não teve um indutor para o receber. A pré-visualização segue o seu acesso às linhas.

Um nome de departamento ou de estatística não pode conter uma aspa simples (`'`), uma barra invertida nem uma quebra de linha, porque o nome é escrito nos filtros dos passos de alocação. **Guardar** e uma pré-visualização da fase 1 recusam um nome assim e indicam-no.

Clique em **Guardar**. As regras produzem efeito no **Carregar** seguinte, ou quando clicar em **Apply changes**. Se editou manualmente um passo de alocação, a sua edição é mantida, não substituída, e a gravação indica-o pelo nome. Não é possível guardar enquanto um carregamento está em curso.

## Pacote para o conselho

Um pacote para o conselho escreve os resultados numa pasta de uma conta de documentos, prontos a enviar. Na página **Relatórios**, clique em **Definições do pacote para a administração** no cartão **Pacote do conselho**, escolha uma **Conta de documentos** e uma **Pasta**, como `/board-packs`, e clique em **Guardar**. A partir daí, cada **Carregar** gera o pacote, pelo que os ficheiros na pasta estão tão atualizados como o último carregamento. Cada execução escreve:

- Um livro do Excel, `Board pack.xlsx`, com uma folha **Profit and loss**, uma folha **Balance sheet** e uma folha **Cash flow**: cada mês e linha por entidade, com as eliminações e o total do grupo. Um projeto com uma só entidade não tem eliminações nem linhas de grupo.
- Um PDF do painel de controlo **CFM-Finance - Statements**.

Depois de esse painel de controlo estar construído, **Abrir o pacote para a administração**, no mesmo cartão, abre-o.

Clique em **Executar agora** para gerar um pacote de imediato; os ficheiros aparecem na pasta quando terminar. A caixa de diálogo mostra a última execução e o respetivo resultado, bem como a próxima execução. **Aplicar alterações** não gera um pacote. Para gerar um segundo um agendamento, agende o **Carregar** (consulte [Manter os dados atualizados](#manter-os-dados-atualizados)); até lá, a caixa de diálogo indica **Ainda não está agendado. Cada carregamento cria o pacote do conselho: configure a atualização noturna para o criar todas as noites.** Só quem pode alterar o projeto o configura.

Um pacote que não pode ser gerado na totalidade nunca faz falhar o carregamento:

- Se o relato estiver desativado na área de trabalho, o pacote é apenas o livro do Excel, e a execução indica **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- Se um painel de controlo criado por outra pessoa já tiver o endereço de que o Data Foundation precisa para o painel de controlo das demonstrações, esse painel de controlo fica como está e o PDF não é gerado. A mensagem indica o endereço; dê outro endereço ao outro painel de controlo no Superset e execute novamente **Carregar**.
- Se algum passo do pacote falhar, a última execução na caixa de diálogo indica **falhou**. O carregamento em si teve êxito.

## Pontos de restauro

É criado um ponto de restauro no início de cada **Carregar** ou **Apply changes**, seja quem for que o inicie, incluindo um carregamento agendado, e antes de cada alteração às correspondências ou às origens. Contém as tabelas do modelo, as dimensões e as definições a partir das quais o carregamento seguinte é construído: as origens, os ficheiros e as regras de alocação. São mantidos os últimos sete pontos criados para carregamentos e os últimos cinco criados antes de alterações, pelo que as alterações nunca eliminam os pontos criados para carregamentos. Os pontos mais antigos são descartados.

Para voltar atrás, abra **Ações ▾ > Restaurar…** em **Resumo**. Cada ponto mostra quando foi criado e, por baixo, quantas tabelas o restauro repõe, por exemplo **Puts back 12 tables.**, e, numa nota, o que deixa como está. Escolha um ponto e clique em **Restaurar**. **Restaurar** fica disponível assim que existir um ponto. O restauro começa por registar o projeto no estado atual como um ponto próprio, para que possa voltar atrás novamente. Depois, repõe as tabelas, as dimensões e essas definições tal como estavam, e o carregamento seguinte é construído a partir delas. Restaurar para as origens que já tinha não as marca como alteradas. Restaurar para um ponto criado antes de uma origem de conector ou de ficheiro ser adicionada remove as tabelas carregadas dessa origem, e um aviso indica a origem. Se anular o restauro, o Carregar volta a obter as tabelas de uma origem de conector e, para uma origem de ficheiro, confirma o ficheiro novamente. Se não for possível remover as tabelas de uma origem, um aviso indica que ficam na pasta da origem até as eliminar manualmente, e o resto é restaurado. Uma vista, uma dimensão que não pode ser guardada ou uma tabela sem cópia guardada é indicada num aviso, e o resto é restaurado. Um ponto de restauro que já foi descartado é recusado, e não é possível restaurar enquanto um carregamento está em curso.

## Clonar um projeto

**Ações ▾ > Clonar…** em **Resumo** copia o projeto com um nome que indicar. A cópia mantém o modelo, as suas edições ao modelo de dados e os seus indicadores e caminhos de análise, e carrega os dados de exemplo. As respetivas origens não ficam ligadas, pelo que deve ligá-las na cópia antes de carregar. Pode continuar a trabalhar enquanto a cópia é criada, e **Abrir projeto** leva-o até ela quando estiver pronta.

## Guardar como o meu modelo

Guarde a configuração de um projeto para a reutilizar no próximo cliente ou entidade. Abra **Ações ▾ > Guardar como o meu modelo…** em **Resumo**, escolha a conta de documentos e dê um nome ao ficheiro. Se omitir a terminação `.zip`, ela é acrescentada. Guardar por cima de um ficheiro existente é recusado, pelo que deve escolher outro nome.

O ficheiro contém a estrutura do projeto, as suas edições ao modelo de dados, os indicadores e os caminhos de análise, os nomes de negócio das entidades e contas, e as linhas das tabelas de configuração do modelo, como o mapa de atividades do [Cost to Serve](/pt-pt/guides/projects/cost-to-serve/) ou os intervalos de política do [Operational Transfer Pricing](/pt-pt/guides/projects/operational-transfer-pricing/). Deixa de fora as ligações, os ficheiros, o agendamento noturno, as execuções, os pontos de restauro, o pacote para o conselho e quem tem acesso.

Para o utilizar, crie um projeto, escolha **A partir de um ficheiro de modelo** em **Começar a partir de** e selecione a conta de documentos e o caminho. O novo projeto é privado, com todas as origens a aguardar ligação. Uma versão posterior do modelo junta as suas alterações em torno dos passos que editou. Se não existir nenhum ficheiro no caminho, nada é criado e é informado disso. Qualquer pessoa que possa ler a conta de documentos pode instalar a partir do ficheiro. Para o utilizar noutra área de trabalho, transfira o ficheiro e carregue-o lá.

## Resolver questões em aberto com o Ask

Após um carregamento, um projeto pode ainda estar à espera de três respostas: contas que o plano deixa sem tipo, códigos que mais do que uma origem utiliza e colunas dos ficheiros que não corresponderam a nada. Peça ao assistente para as resolver: a partir de um assistente de IA através de MCP, utilize o prompt **Resolve Data Foundation residue**. Este lê o que está pendente e propõe uma resposta para cada item, com um motivo.

O assistente não escreve nada. O chat do Weave AI também pode indicar o que um projeto está a aguardar (consulte [Chat do Weave AI](/pt-pt/guides/ai-assistant/weave-tab/#data-foundation)), e um agente de IA ligado por MCP pode ler as perguntas e responder-lhes diretamente (consulte [Data Foundation com um agente de IA ligado por MCP](/pt-pt/integrations/ai-coding-agents/data-foundation/)). As respostas são aplicadas por si no mesmo sítio onde teria respondido: as contas e os códigos na página **Perguntas** e as colunas dos ficheiros na correspondência do ficheiro. Nunca propõe uma entidade. Uma pergunta em **Perguntas** já pode trazer a sugestão do próprio Weave; consulte [As páginas do Data Foundation](#as-páginas-do-data-foundation).

## Entregar o projeto

Quando o projeto é configurado para outra pessoa, como um cliente, termine com estes passos:

- **Mantenha-o atualizado.** Agende o **Carregar**. Consulte [Manter os dados atualizados](#manter-os-dados-atualizados).
- **Partilhe-o.** Dê acesso à equipa na página **Acesso e partilha** do projeto. Consulte [Gerir o acesso ao projeto](/pt-pt/guides/projects/managing-projects/#gerir-o-acesso-ao-projeto).
- **Guarde um registo.** **Ações ▾ > Transferir o pacote de evidências**, em **Resumo**, transfere um livro do Excel com as folhas **Estado**, **Origens**, **Cobertura**, **Mapeamentos**, **Consolidação**, **Reconciliação** e **Último carregamento**: o que foi carregado e de onde, como os códigos foram mapeados, que o grupo coincide e como correu o último carregamento. Segue o acesso às linhas de quem o transfere, e qualquer pessoa com uma função no projeto o pode transferir.
- **Entregue-o.** Torne o proprietário Arquiteto do projeto e, em seguida, remova-se dos respetivos membros. Algumas escolhas cabem apenas a um Arquiteto, como permitir que todos vejam os resultados do grupo ou adicionar o Data Foundation a um projeto.

## Construir sobre o modelo com um modelo de projeto

Um modelo de projeto constrói os seus relatórios e modelos de cálculo sobre o Common Finance Model, pelo que funcionam da mesma forma sejam quais forem os ERP que o alimentam. Quando inicia um projeto a partir de um modelo, como **Enterprise Profitability**, este cria:

- As [tabelas do Common Finance Model](#tabelas-do-common-finance-model), vazias ou preenchidas com dados de exemplo.
- As dimensões **Entidade**, **Conta**, **Departamento**, **Cliente**, **Produto**, **Segmento 1** e **Segmento 2**, construídas a partir dessas tabelas. Consulte [Hierarquias](#hierarquias).
- O fluxo de trabalho **Carregar** e os fluxos de trabalho que este executa para ler o ERP e os ficheiros, uniformizá-los, verificar a prontidão e construir os modelos de cálculo do modelo.
- Os relatórios e modelos de cálculo próprios do modelo. **Enterprise Profitability** acrescenta uma tabela de demonstração de resultados com receita, custo das mercadorias vendidas, margem bruta, gastos operacionais diretos e indiretos, contribuição e margem operacional, além de pontes de margens face ao ano anterior e face ao orçamento.
- Indicadores e um caminho de análise para fazer perguntas sobre os resultados.

Em **Começar a partir de**, o **Data Foundation** é o modelo por si só, com os respetivos relatórios. Cada uma das três soluções inclui o Data Foundation, acrescenta os seus próprios modelos de cálculo e mostra **Alocações** na barra:

| Solução | Acrescenta |
|---|---|
| **Enterprise Profitability** | A demonstração de resultados e as pontes de margens. |
| **Cost to Serve** | O custo de servir cada cliente e a margem depois desse custo. Consulte [Cost to Serve](/pt-pt/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | O nível de lucro de cada entidade face ao intervalo da sua política, e o acerto. Consulte [Operational Transfer Pricing](/pt-pt/guides/projects/operational-transfer-pricing/). |

**A partir de um ficheiro de modelo** começa a partir de um projeto que guardou. Consulte [Guardar como o meu modelo](#guardar-como-o-meu-modelo).

Para explorar antes de ligar o seu próprio ERP, assinale **Começar com dados de exemplo** ao criar o projeto. O projeto executa de imediato um primeiro carregamento, pelo que **Resumo** mostra um exemplo completo, incluindo uma entidade em euros convertida para dólares americanos. Quando liga o seu próprio ERP ou adiciona os seus próprios ficheiros, os dados de exemplo são removidos e os seus dados tomam o seu lugar. Se a remoção for interrompida, o **Carregar** seguinte conclui-a. Uma pasta sua com o nome `sample` nunca é removida, mas, enquanto os dados de exemplo ocuparem essa pasta, as outras tabelas nela contidas não são lidas, pelo que deve movê-las para uma pasta com outro nome.

## As páginas do Data Foundation

O grupo **Data Foundation** da barra **Início** do projeto é onde liga, carrega e verifica os seus dados. As linhas apresentadas estão descritas em [Obter o Data Foundation](#obter-o-data-foundation).

| Página | O que mostra |
|---|---|
| **Resumo** | O ponto de situação do Data Foundation, se pode confiar nos números e o que fazer a seguir. Consulte abaixo. |
| **Sistemas** | Todos os sistemas a partir dos quais reporta, a respetiva situação e quando foram carregados pela última vez, **Adicionar um sistema** e o cartão **Ficheiros**. Consulte [Ligar o ERP](#ligar-o-erp), [Sistemas](#sistemas) e [Adicionar ficheiros com dados exteriores ao ERP](#adicionar-ficheiros-com-dados-exteriores-ao-erp). |
| **Perguntas** | Tudo o que aguarda a sua resposta. Consulte abaixo. |
| **Relatórios** | Os painéis de controlo por perfil, cada um aberto num novo separador, e o cartão **Pacote do conselho**. Consulte [Painéis de controlo, indicadores e caminhos de análise](/pt-pt/guides/projects/data-foundation-dashboards/) e [Pacote para o conselho](#pacote-para-o-conselho). |
| **Alocações** | Num projeto criado com uma solução, abre **Regras de imputação**. Consulte [Regras de alocação](#regras-de-alocação). |

**Resumo** lê-se de cima para baixo:

- O ponto de situação do projeto numa linha, com o passo seguinte como um botão, como **Adicione o seu sistema financeiro**, **Carregar**, **Responder a 1 pergunta**, **Manter atualizado** ou **Abrir os relatórios**, e a linha do resultado líquido com **Explicar este número**. Consulte [Explicar um número](#explicar-um-número).
- Num projeto com mais do que uma entidade, **O grupo**: o grau de completude do grupo, a respetiva moeda de relato e o mês em que começa o seu ano financeiro, com **Alterar** para abrir **Definições do projeto**.
- **Pode confiar nos números?**, as cinco garantias; com um só sistema, **Your system**; quando existir, **O que mudou**; e **Fechar um mês**. Consulte [Data Foundation: pode confiar nos números?](/pt-pt/guides/projects/data-foundation-proof/).
- **Perguntar ao Weave**, perguntas para começar.
- **Histórico**: cada resposta, correspondência, fecho e reexpressão, com quem a fez, quando e o valor anterior. Clique em **Mostrar histórico** para o listar, em **Mostrar mais** para ver entradas mais antigas e em **Exportar** para o transferir como livro do Excel.
- **Cobertura de fontes**, onde escolhe que origem conta quando duas fornecem os mesmos meses. Consulte [Escolher que origem conta a partir de quando](#escolher-que-origem-conta-a-partir-de-quando).

Se o acesso às linhas só lhe mostrar algumas entidades, **Resumo** indica **Estes números abrangem apenas as entidades a que tem acesso, não a empresa inteira.**

**Ações ▾**, no topo de **Resumo**, contém **Definições do projeto…**, **Hierarquias…**, **Atualizar todas as noites**, **Transferir o pacote de evidências**, **Clonar…**, **Restaurar…** e **Guardar como o meu modelo…**. Consulte [Hierarquias](#hierarquias), [Manter os dados atualizados](#manter-os-dados-atualizados), [Entregar o projeto](#entregar-o-projeto), [Clonar um projeto](#clonar-um-projeto), [Pontos de restauro](#pontos-de-restauro) e [Guardar como o meu modelo](#guardar-como-o-meu-modelo). A caixa de diálogo **Definições do projeto** também abre com **Alterar** no cartão **O grupo** enquanto o grupo tiver mais do que uma empresa. Só quem pode alterar o projeto pode utilizar as opções que o alteram.

**Perguntas** lista tudo o que aguarda a sua resposta, agrupado por assunto, com o número de perguntas de cada assunto. Quando adiciona um sistema, responde a uma pergunta por assunto, como se utiliza os mesmos códigos que um sistema já ligado, e não a uma por código. Uma pergunta que retém linhas dos valores indica quantas e o respetivo montante. **Weave suggests:** apresenta a resposta do Weave e os respetivos elementos de suporte: clique em **Usar esta resposta** ou escolha outra na lista e clique em **Responder**. **Aceitar todas as sugeridas** responde a todas as perguntas que têm uma sugestão. Uma resposta aplica-se no próximo **Carregar** ou **Aplicar alterações**. A linha **Perguntas** só aparece enquanto houver uma pergunta pendente.

Uma pergunta sobre uma classe de receita ou sobre a função de uma equipa não retém nada. Consulte [Classes de receita e funções das equipas](#classes-de-receita-e-funções-das-equipas).

Quando altera as origens, uma barra acima de todas as páginas indica **Alterou as suas origens. Prima Aplicar alterações para as usar.** Tem **Mostrar o que mudou** e **Aplicar alterações**, e é o único local onde se aplica uma alteração. O resultado de um **Carregar** ou **Aplicar alterações** aparece acima da página que estiver aberta, pelo que o vê em todas as páginas.

Enquanto decorre um carregamento, as páginas atualizam-se automaticamente e continuam a ler mesmo que uma leitura falhe. Se não for possível ler o estado, aparece **Não foi possível ler o estado do Foundation.** com **Tentar novamente**, que volta a ler o estado; as páginas também tentam novamente uma vez por si só antes de mostrar a mensagem, e a mensagem desaparece quando o servidor responde.

## Tabelas do Common Finance Model

O Data Foundation uniformiza todas as origens, ERP ou ficheiro, nas mesmas tabelas, pelo que os relatórios, indicadores e modelos de cálculo criados sobre elas funcionam da mesma forma seja qual for a origem. Cada linha regista também o respetivo sistema de origem e quando foi lida. A coluna **Conjunto de dados** é o nome que escolhe ao adicionar um ficheiro.

| Conjunto de dados | Tabela | Contém |
|---|---|---|
| Entidades | `cfm_entity` | Entidades jurídicas com entidade-mãe, moeda local e de grupo, país, região e divisão. |
| Mapa de códigos | `cfm_code_map` | A correspondência entre um código tal como uma origem o tem, como um código de entidade, conta ou departamento, e o código canónico. Consulte [Mapeamento de entidades](#mapeamento-de-entidades) e [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| Taxas de câmbio | `cfm_fx_rate` | Taxas mensais médias, de fecho e históricas por par de moedas. Consulte [Taxas de câmbio](#taxas-de-câmbio). |
| Calendário fiscal | `cfm_fiscal_calendar` | Uma linha por período fiscal de cada entidade, com datas de início e de fim e se está fechado. |
| Plano de contas | `cfm_account` | Contas com conta-mãe, tipo (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), demonstração, saldo normal, tipo de taxa, função de conta e classe de receita. A função, como caixa, conta a receber, conta a pagar ou resultados transitados, coloca a conta na respetiva linha da demonstração e dos fluxos de caixa. |
| Departamentos | `cfm_department` | Departamentos e centros de custo com departamento-mãe, centro de lucro e função. |
| Centros de lucro | `cfm_profit_center` | Centros de lucro com centro de lucro-pai e função. |
| Produtos | `cfm_product` | Mestre de produtos com produto-mãe, família, grupo, unidade de medida, custo padrão e classe de receita. |
| Clientes | `cfm_customer` | Mestre de clientes com cliente-mãe, grupo, região e país. Os nomes dos clientes não são ocultados. |
| Valores de segmento | `cfm_segment` | Valores de segmento com nome e elemento-pai. Consulte [Hierarquias](#hierarquias). |
| Razão geral | `cfm_gl_journal` | Linhas de diário na moeda da transação, local e de relato. |
| Balancete | `cfm_trial_balance` | Débitos, créditos e saldo líquido do período por entidade, conta e departamento, em moeda local e de relato. |
| Linhas de vendas | `cfm_sales_line` | Linhas de vendas faturadas com quantidade e montantes bruto, de desconto, líquido e de custo das mercadorias vendidas. |
| Pipeline | `cfm_opportunity` | Pipeline de vendas: uma linha por linha de oportunidade, em qualquer fase, uma cópia por fim de mês. |
| Saldos de inventário | `cfm_inventory_balance` | Inventário no final do período por produto e armazém. |
| Orçamento | `cfm_budget` | Orçamento e previsão por cenário, versão, conta e departamento. |
| CO-PA por valorização | `cfm_copa` | Análise de rentabilidade do SAP (CO-PA) por entidade, período, conta, produto e cliente, um conjunto de linhas por valorização (legal, de grupo ou de centro de lucro), nunca somadas. A receita é positiva e os custos negativos. Dos modelos, só o [Operational Transfer Pricing](/pt-pt/guides/projects/operational-transfer-pricing/#margem-co-pa) a lê. |
| Indutores de alocação | `cfm_stat_driver` | Indutores estatísticos, como o número de colaboradores, a área em pés quadrados ou as unidades. |

O modelo contém também os razões auxiliares e os respetivos mestres, preenchidos pelos sistemas que os têm:

| Tabela | Contém |
|---|---|
| `cfm_site` | Locais: fábrica, localização de armazém ou escritório, cada um numa entidade. |
| `cfm_supplier` | Mestre de fornecedores. |
| `cfm_sales_rep` | Mestre de comerciais. |
| `cfm_project` | Mestre de projetos. Uma campanha de marketing é um projeto. |
| `cfm_standard_cost` | Custo padrão por unidade, por produto, entidade de custeio e período. |
| `cfm_system_balance` | O saldo final próprio de cada sistema por conta em cada fim de mês, lido a partir do respetivo relatório de saldos e nunca das linhas de diário. |
| `cfm_supplier_invoice_line` | Linhas de faturas de fornecedores. |
| `cfm_purchase_order_line` | Linhas de notas de encomenda, uma cópia por fim de mês. |
| `cfm_open_item` | Contas a receber e a pagar em aberto, uma cópia por fim de mês. |
| `cfm_payment` | Pagamentos recebidos e efetuados. |
| `cfm_order_line` | Linhas de encomendas de venda, uma cópia por fim de mês. |
| `cfm_asset` | Registo de ativos fixos. |
| `cfm_asset_movement` | Movimentos de ativos por livro e período: aquisição, depreciação, alienação e transferência. |
| `cfm_contract` | Contratos e subscrições, uma cópia por fim de mês. Um [registo de contratos](#registos-de-contratos) é copiado para cada fim de mês que cada período abrange. |
| `cfm_deferred_revenue_movement` | Movimentos de receita diferida por contrato e período. |
| `cfm_bank_balance` | Contas bancárias e os respetivos saldos contabilísticos de fim de mês. |
| `cfm_inventory_movement` | Movimentos de inventário: entradas, saídas, produção, transferências, ajustamentos e abates. |

Uma tabela mantida com uma cópia por fim de mês substitui a cópia do mês aberto em cada carregamento. As tabelas de documentos têm uma coluna `counts`: `1` para uma linha que conta, proveniente do sistema que conta para a respetiva entidade e mês e do livro que o projeto reporta, e `0` para uma linha mantida de outro sistema ou livro. Os relatórios e os indicadores só leem as linhas que contam.

Um projeto Foundation vem com [elementos do projeto](/pt-pt/guides/projects/data-model/) para as colunas que estas tabelas partilham: `entity`, `account`, `department`, `profit_center`, `product`, `customer`, `period`, `site`, `supplier`, `sales_rep` e `project`. Cada um tem uma descrição e, quando aplicável, um tipo e uma dimensão, pelo que todas as tabelas que têm uma destas colunas mostram o mesmo significado. O Data Foundation adiciona os que o projeto não tenha e deixa tal como está um que tenha editado. Isto aplica-se a todos os ERP e origens de ficheiros.

Os períodos são escritos como `YYYY-MM`, e as transações são colocadas por período de lançamento. O orçamento é opcional: um ERP sem orçamentos carrega na mesma tudo o resto.

Um ficheiro de balancete pode ter colunas de débito e crédito, uma coluna de saldo líquido, ou ambas. Só com débito e crédito, o saldo líquido é o débito menos o crédito, e um lado em branco conta como zero. Só com o saldo líquido, um saldo positivo passa a ser o débito e um saldo negativo passa a ser o crédito, como montante positivo. Uma coluna de departamento é opcional.

## Resolução de problemas

| Sintoma | O que fazer |
|---|---|
| **Testar ligação** indica que o ERP recusou as credenciais | Verifique as credenciais da ligação e se o utilizador de integração consegue iniciar sessão no ERP. |
| **Testar ligação** mostra **Permissão em falta** para um conjunto de dados | Peça ao administrador do ERP que adicione as permissões indicadas. O [guia de ligações](/pt-pt/guides/connections/) do seu ERP lista o que a ligação necessita. |
| Uma mensagem de erro do ERP é mais curta do que a do próprio ERP | A PlaidCloud remove credenciais, tokens e chaves dos erros do fornecedor antes de os mostrar, pelo que algum detalhe fica de fora. Execute **Testar ligação** para ver que conjunto de dados é afetado. |
| **Every month loaded** falha num período | Uma leitura do ERP para esse período falhou. Execute novamente **Carregar**; os períodos que foram carregados são ignorados. |
| **Every account known** falha | Adicione as contas em falta ao plano de contas no ERP ou no ficheiro e execute novamente **Carregar**. |
| **Every amount has a rate** falha | A moeda de uma entidade não tem taxa para a moeda de relato nesse período, ou não foi encontrada uma moeda de relato única. Adicione as taxas a um ficheiro **Taxas de câmbio**, verifique se a ligação consegue ler as taxas de câmbio do ERP ou defina a variável de projeto `reporting_currency`. Depois, execute novamente **Carregar**. |
| **Every amount has a rate** é um alerta | Linhas de balanço, de inventário ou de orçamento não têm taxa de fecho, histórica ou planeada para o período. A demonstração de resultados não é afetada. Adicione as taxas, incluindo as taxas planeadas para os meses do orçamento, e execute novamente **Carregar**. |
| **Codes mapped** falha | Abra **Perguntas** e responda a cada pergunta. As respostas aplicam-se no próximo **Carregar** ou **Aplicar alterações**. |
| **One source for each key** falha | Em **Cobertura de fontes**, em **Resumo**, escolha o mês e a origem, clique em **Guardar escolha** e clique em **Aplicar alterações**. |
| A verificação intragrupo está a vermelho ou âmbar | Verifique os pares em **Pares intragrupo**. Registe o lado em falta, adicione o parceiro comercial às linhas ou adicione a taxa em falta. |
| **Group views are off** | Peça a um Arquiteto que assinale **Todas as pessoas do projeto podem ver os resultados do grupo** em **Acesso por grupo e linha**, em **Definições do projeto**. |
| Um carregamento agendado foi ignorado | A pessoa que configurou o agendamento já não pode utilizar a ligação de um sistema. Volte a configurar o agendamento. Consulte [Manter os dados atualizados](#manter-os-dados-atualizados). |
| **Every entity known** falha | Adicione a entidade ao mestre de entidades, ou mapeie o respetivo código para uma entidade existente num ficheiro **Mapa de códigos**, e execute novamente **Carregar**. |
