O **Data Foundation** é a base de dados financeiros dos seus projetos PlaidCloud. O seu **Common Finance Model** reúne dados de vários sistemas ERP, e de várias instâncias de cada um, num único modelo: um plano de contas, um conjunto de entidades e uma moeda de relato. Os relatórios, indicadores e assistentes de IA criados sobre o modelo leem todos os mesmos números, seja qual for o ERP de origem.

O ERP liga-se através da respetiva ligação PlaidCloud, pelo que o razão geral, o balancete, os dados mestre e os orçamentos chegam diretamente da origem, sem nada para exportar. Os ficheiros acrescentam dados que um sistema não contém, como taxas de câmbio, indutores de alocação ou um orçamento mantido fora do ERP, e podem substituir as linhas do ERP que abrangem. **Carregar** uniformiza todas as origens no modelo, converte-as para a moeda de relato e verifica se coincidem, tudo a partir do separador **Base** do projeto. Quando as origens utilizam o mesmo código para coisas diferentes, indica se significam o mesmo, e uma consolidação de gestão constrói a demonstração de resultados do grupo com as operações intragrupo eliminadas. Os modelos, como **Enterprise Profitability**, constroem os respetivos relatórios e modelos de cálculo sobre ele.

## Ligar o ERP

O ERP liga-se ao Data Foundation através da respetiva ligação PlaidCloud. O Data Foundation lê diretamente dela o razão geral, o balancete, os dados mestre, as taxas de câmbio e os orçamentos, e limita-se sempre a ler. Pode escolher uma ligação existente ou criar uma no separador. Cada sistema tem uma página destinada ao administrador que concede o acesso, listada em [Que sistemas podem alimentar o modelo](/pt-pt/guides/projects/data-foundation-getting-started/#que-sistemas-podem-alimentar-o-modelo), e a [Matriz de cobertura do Data Foundation](/pt-pt/reference/data-foundation-coverage-matrix/) mostra que conjuntos de dados cada sistema fornece diretamente.

<Steps>

1. No Analyze, abra **Projetos** e clique em **Novo projeto**. Introduza um nome e, em **Começar a partir de**, escolha um modelo, como **Enterprise Profitability (modelo)**, em vez de **Projeto em branco**. Clique em **Criar**.

   O projeto abre no separador **Base**. É privado e o utilizador é o seu único Arquiteto até o partilhar.

2. No separador **Base**, escolha uma ligação existente para o ERP ou escolha **Criar uma nova ligação**. Cada ligação existente lista os fluxos de trabalho que já a utilizam ou indica **Ainda não é utilizado por nenhum fluxo de trabalho**.

3. Para uma ligação nova, introduza um **Nome da ligação**, escolha o **Ambiente** e preencha as credenciais que a ligação ERP pede.

   Ainda não tem as credenciais? O formulário mostra um pedido de acesso pronto a enviar ao administrador do ERP. Clique em **Copiar pedido** ou **Enviar pedido por email**, envie-o e introduza os valores que lhe forem devolvidos.

4. Clique em **Testar ligação**. A PlaidCloud inicia sessão e tenta ler cada conjunto de dados; depois lista cada um como **Legível**, **Permissão em falta** ou **Erro**. Quando falta algo, indica as permissões que deve pedir ao administrador do ERP para adicionar.

5. Defina **Meses de histórico**: quantos meses para trás carregar, de 1 a 120. O valor predefinido é 24.

6. Para uma ligação existente, assinale as entidades a carregar ou deixe-as todas por assinalar para carregar todas as entidades. As entidades inativas e de eliminação ficam ocultas até optar por mostrá-las. Depois, clique em **Ligar**.

7. Para uma ligação nova, clique em **Ligar** para a criar. Depois, assinale as entidades a carregar e clique novamente em **Ligar** para as guardar. Até o fazer, são carregadas todas as entidades.

8. Para trazer outro sistema ERP ou outra instância, repita estes passos e assinale **Add this as another source instead of replacing the current one** antes de clicar em **Ligar**. Sem essa opção, a nova ligação substitui a origem atual.

</Steps>

Depois de ligado, o cartão indica que ligação, ambiente, entidades e meses de histórico o projeto carrega.

Cada carregamento lê apenas o que mudou: os períodos abertos e o último período fechado são lidos novamente, e os períodos fechados já carregados são mantidos. Aumentar **Meses de histórico** lê apenas os meses acrescentados. Uma alteração numa taxa de câmbio, no mapeamento de entidades ou na moeda de relato volta a ler os meses afetados.

## Origens

Cada sistema e instância ERP a partir do qual o projeto carrega é uma origem. A lista **Origens** no separador **Base** mostra uma linha para cada uma, por ordem, com o nome, quando foi carregada pela última vez e quantas linhas forneceu, e os livros de relato que lê, por exemplo `1. NetSuite US: last loaded 2026-10-28 02:00, 41,260 rows; all reporting books`. Uma origem que ainda não foi carregada indica **not loaded yet**. Os ficheiros que confirma também são origens.

Abra **Avançado** numa origem para alterar a forma como é utilizada:

| Definição | O que faz |
|---|---|
| **Nome** | O rótulo que os relatórios, as perguntas de correspondência e as mensagens utilizam para a origem. |
| **Posição na ordem** | A posição da origem na ordem. Quando duas origens abrangem o mesmo mês da mesma empresa, prevalece a que está mais acima na ordem. |
| **Livros de relato, separados por vírgulas** | Os livros contabilísticos a ler, no caso de um sistema que mantém mais do que um. **Todos os livros de relato** lê todos os livros. |
| **Empresa**, **De (2026-01)** e **Para (2026-12)** | Os meses que esta origem fornece para cada empresa. Deixe um mês vazio para não haver limite. Escreva os meses como ano e mês, por exemplo `2026-03`. |

Clique em **Guardar** para manter as alterações. Para retirar uma origem, clique em **Remove this source** e confirme **Remover**. Tudo o que foi carregado a partir dela é eliminado, e é possível voltar a ligá-la mais tarde.

Alterar as origens não volta a ler o ERP. O cartão **Último carregamento** indica **Changes not applied yet** até clicar em **Apply changes**, que executa um carregamento a partir dos dados já obtidos: volta a uniformizar as origens com a nova ordem, correspondências, nomes e ficheiros, e reconstrói o modelo. Clique em **Carregar** quando também pretender dados atualizados dos ERP.

## Adicionar ficheiros com dados exteriores ao ERP

Os ficheiros complementam a ligação ERP com dados que um sistema não contém, como taxas de câmbio, indutores de alocação, um [Mapeamento de entidades](#mapeamento-de-entidades) ou um orçamento mantido fora do ERP. Cada ficheiro pertence a um dos conjuntos de dados listados em [Tabelas do Common Finance Model](#tabelas-do-common-finance-model).

<Steps>

1. Em **Ficheiros**, escolha a **Conta de documentos** onde guardar o ficheiro.

2. Largue um ficheiro CSV ou Excel em **Largue aqui um ficheiro CSV ou Excel** ou clique em **Escolha um ficheiro**. O ficheiro é carregado para a pasta `/foundation/` da conta de documentos.

   Para um ficheiro que já esteja na conta de documentos, introduza o respetivo **Caminho do ficheiro**, por exemplo `/foundation/budget.csv`, e clique em **Adicionar ficheiro**.

   Para ler um ficheiro novo todos os meses, adicione todos os ficheiros de uma pasta cujo nome corresponda: introduza a pasta e o que os **File names that** contêm, aquilo por que começam ou terminam, a que correspondem exatamente ou a que correspondem como padrão, e clique em **Add files**. Os ficheiros em pastas dentro dela não são lidos.

3. A PlaidCloud lê o ficheiro e propõe uma correspondência:

   - **Delimitador, separador decimal e datas detetados.** O delimitador (vírgula, ponto e vírgula, tabulação ou barra vertical), o separador decimal e o formato de data são detetados automaticamente.
   - **Conjunto de dados**: a tabela do Common Finance Model a que o ficheiro pertence, identificada a partir do nome do ficheiro e dos cabeçalhos das colunas. Quando a correspondência não é clara, escolha-a na lista.
   - **Separador decimal**: **Ponto (1,234.56)** ou **Vírgula (1.234,56)**.
   - **Formato de data**: apresentado quando o ficheiro tem datas. Altere-o se o formato detetado estiver errado: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY` ou `MM/DD/YYYY`.
   - Uma grelha com **Coluna no ficheiro**, **Tipo**, **Exemplos** e **Destino**. Altere **Destino** para enviar uma coluna para um campo diferente, ou para **Não carregar**.

4. Responda às perguntas que o ficheiro suscita, como **Which company is this file for?**, **Which currency are the amounts in?**, **Are these amounts year-to-date or for the month?**, **Are the amounts shown in thousands or millions?** ou **Are revenues shown as negative numbers?** Cada pergunta só é feita quando o ficheiro ainda não dá a resposta.

5. Verifique para onde vai cada coluna e clique em **Confirmar correspondência**. Enquanto trabalha, a nota sob o botão indica o motivo da espera. Num projeto que ainda tenha os dados de exemplo, o primeiro ficheiro que confirmar remove também os dados de exemplo, o que pode demorar alguns minutos.

</Steps>

Estas opções aparecem num ficheiro quando se aplicam:

| Opção | Utilize-a para |
|---|---|
| **Which source do these rows apply to?** | Limitar um ficheiro de mapeamento de códigos a uma origem. **Every source** aplica-o a todas. |
| **Where does this file come from?** | Indicar se o ficheiro contém **This project's own codes** ou provém de **Another system**, cujo nome indica, por exemplo `SAP Germany export`. Um ficheiro de outro sistema é verificado quanto a códigos partilhados, tal como uma origem ERP. |
| **Split … into … parts at each …** (em **Avançado**) | Dividir uma coluna que contém vários valores, como `100-200-300`, e enviar cada parte para o seu próprio campo. |
| **Which currency do you report in?** | Definir a moeda de relato quando o projeto ainda não tem uma. Escreva-a com três letras, por exemplo `USD`. |
| **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** | Carregar os resultados do sistema de consolidação para que a demonstração de resultados do grupo possa ser [reconciliada](#reconciliar-com-o-sistema-de-consolidação). |

Para retirar um ficheiro do projeto, clique em **Remover** junto dele em **Ficheiros**, ou em **Remove this file** na respetiva correspondência, e confirme. Os seus valores saem dos relatórios da próxima vez que clicar em **Apply changes**.

Quando a PlaidCloud não consegue decidir sozinha o conjunto de dados, o separador decimal ou a ordem das datas, por exemplo num ficheiro cujas datas podem ser lidas como dia/mês ou mês/dia, pede-lhe que escolha antes de confirmar. Adicionar um segundo ficheiro para o mesmo conjunto de dados substitui o primeiro. Se as colunas de um ficheiro posterior não corresponderem ao conjunto de dados, o carregamento indica o ficheiro e as colunas e pede que corrija o ficheiro ou os nomes das colunas, ou que defina o **Schema Mismatch** do passo como `union`.

Os ficheiros aceites são ficheiros de texto CSV, TSV e TXT, ficheiros Excel `.xlsx` (lidos a partir da primeira folha) e ficheiros Parquet.

<Aside type="note">
Um ficheiro em falta ou vazio nunca interrompe um carregamento. Ao adicioná-lo, é indicado que ainda não há nada para mapear, e o carregamento termina com um aviso que indica o caminho, deixando esse conjunto de dados vazio. Volte a adicionar o ficheiro quando ele existir.
</Aside>

## Carregar os dados

Clique em **Carregar** no cartão **Carregar** ou no cartão **Último carregamento**. O carregamento lê o ERP ligado e os ficheiros confirmados, uniformiza-os no Common Finance Model, converte-os para a moeda de relato, executa as verificações de prontidão e reconstrói os modelos de cálculo do modelo.

- Só é executado um carregamento de cada vez por projeto. Um segundo **Carregar** ou **Apply changes** indica que já está um carregamento em curso, e não é possível alterar as origens enquanto decorre.
- Se outros fluxos de trabalho utilizarem a mesma ligação ERP, o primeiro carregamento lista-os e pede confirmação, porque um carregamento lê a partir do ERP e pode tornar esses fluxos de trabalho mais lentos. Clique em **Carregar mesmo assim** para avançar.
- Depois de a PlaidCloud ser atualizada, um **Carregar** feito por um Arquiteto atualiza também os fluxos de trabalho gerados do projeto, criando as tabelas de trabalho de que necessitem. Até lá, a página de estado mostra um item âmbar, "Os fluxos de trabalho foram gerados por uma versão anterior. Um carregamento feito por um Arquiteto atualiza-os.", e um **Carregar** feito por um Gestor avisa que só um Arquiteto os pode atualizar.
- Aplicar uma atualização mantém as suas próprias edições aos passos gerados. Se alterou um passo e a atualização também o alterou, a sua edição é mantida e a página de estado assinala o conflito pelo nome do passo. Um passo editado que a atualização deixou de gerar é mantido, mas desativado; elimine-o ou volte a ativá-lo se ainda precisar dele. Um passo que a atualização substitui é indicado pelo nome, e o anterior fica nas versões do passo.
- Se uma atualização parou a meio, ou ainda está em curso, a página de estado indica-o, e os respetivos passos podem ser executados fora de ordem até terminar. Prima novamente **Carregar** como Arquiteto para a concluir. Se voltar a parar, contacte o suporte.
- Um carregamento falhado aparece a vermelho e nunca fica escondido atrás de resultados anteriores. Se a consolidação falhar, o estado indica o passo em que parou em vez de mostrar resultados de grupo antigos. As linhas de um carregamento anterior mostram **De um carregamento anterior. Carregue novamente.** até um carregamento ter êxito.
- Se a leitura de uma entidade e período falhar, o resto é carregado na mesma. Execute novamente **Carregar** para obter apenas o que falhou.

### Linhas retidas

Quando as origens se sobrepõem, um carregamento mantém uma cópia de cada valor e retém as restantes em vez de as contar duas vezes. As linhas retidas são registadas com a origem, a entidade e o motivo, e o carregamento termina com um aviso que indica as contagens, por exemplo `120 rows of NetSuite EU also provided by a source ranked ahead`. Os motivos são:

| Motivo | Significado |
|---|---|
| Noutro livro contabilístico | A linha pertence a um livro de relato que a origem não está definida para ler. |
| Fora dos períodos que a origem fornece | A linha fica fora dos meses **De** e **Para** definidos para a empresa. |
| Também fornecida por uma origem mais acima na ordem | Uma origem mais acima na ordem abrange a mesma empresa e o mesmo mês. |
| Também num ficheiro anterior da origem | Um ficheiro anterior da mesma origem já abrange o mês. |
| Substituída por um ficheiro | Um ficheiro substitui as linhas do ERP para essa entidade e mês. |
| Com um código que outra origem também utiliza | O código precisa da sua resposta. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| Com um código mapeado para dois códigos | O mapeamento de códigos dá duas respostas para o código. |

As contas estatísticas passam para os indutores de alocação em vez do razão e aparecem como movidas, não como um problema.

### Dados do ERP e ficheiros em conjunto

Um ficheiro substitui apenas o que abrange, e as restantes linhas do ERP mantêm-se.

- **Ficheiros mestre** (contas, departamentos, clientes, produtos e valores de segmento) substituem as linhas do ERP com o mesmo código.
- **Ficheiros de transações** substituem as linhas do ERP da mesma entidade e mês. Os ficheiros de razão geral e de balancete também fazem a correspondência por razão, os ficheiros de orçamento por cenário e os ficheiros de indutores estatísticos por cenário e indutor.

Se mais tarde um ficheiro deixar de abranger um mês, os dados do ERP para esse mês voltam no carregamento seguinte.

## Mapeamento de entidades

Cada origem designa as suas entidades com os seus próprios códigos. O **Mapeamento de entidades** associa esses códigos às entidades do mestre de entidades, para que as linhas de todas as origens fiquem na mesma entidade.

Para o utilizar, adicione um ficheiro CSV ou Excel e escolha o conjunto de dados **Mapeamento de entidades**:

| Coluna | Contém |
|---|---|
| `source_entity` | O código tal como a origem o tem, como um código de empresa. |
| `entity` | A entidade a que pertence, tal como o mestre de entidades a designa. |

- Um código que não esteja no mapeamento é utilizado tal como está.
- Vários códigos podem ser mapeados para uma entidade. As respetivas linhas são combinadas, e um mês conta como fechado quando estiver fechado para todos eles.
- Os códigos do mapeamento aplicam-se a todas as origens, pelo que os códigos de entidade de cada origem têm de ser únicos entre origens.
- Uma linha de um ficheiro **Entidades** substitui a entidade do ERP com o mesmo código de entidade.

A verificação **Entidades não mapeadas** assinala qualquer linha cuja entidade não esteja no mestre de entidades nem esteja mapeada para uma pelo mapeamento. Até ser carregado um mestre de entidades, mostra **– Não aplicável**.

## Mapear códigos entre origens

Duas origens podem utilizar o mesmo código para coisas diferentes, ou códigos diferentes para a mesma coisa. Quando um código aparece em mais do que uma origem, o Data Foundation retém as respetivas linhas até indicar se significa o mesmo em todo o lado, para que cada montante seja contado uma só vez. A verificação **Códigos a aguardar resposta** lista-os, os primeiros 10 e depois "e mais K", e o cartão **What to do next** no separador **Base** tem um botão **Rever**.

**Rever** abre **Códigos a aguardar resposta**. Agrupa os códigos pelo que são: **Tipos de conta**, **Empresas**, **Contas**, **Departamentos**, **Centros de lucro**, **Clientes**, **Produtos** e cada categoria adicional. Para cada código, mostra como cada origem o designa e uma sugestão:

- **Parece ser a mesma coisa** quando as origens dão ao código o mesmo nome.
- **Parecem ser coisas diferentes** quando os nomes diferem.
- **Não é possível determinar. Responda.** quando não há nada em que se basear.

Responda a um código de cada vez com **Yes, the same** ou **No, different**, ou responda a um grupo inteiro de uma só vez com **Accept all** (aceitar todas as sugestões), **All the same** ou **All different**. No caso das contas, também é possível responder de uma só vez a um grupo-pai inteiro do plano. Quando uma origem não tem tipos de conta, escolha **Use this type** para um grupo de contas: **Receita**, **Custo das mercadorias vendidas**, **Gastos operacionais**, **Rendimentos e gastos não operacionais**, **Ativos**, **Passivos** ou **Capital próprio**.

As correspondências são mantidas por origem e dimensão, pelo que uma resposta para os departamentos de uma origem nunca altera as contas de outra origem. As respostas são guardadas à medida que avança, com **Saved. Press Apply changes to use your answers.** Clique em **Apply changes** para as utilizar.

Também pode fornecer as correspondências num ficheiro. Adicione um ficheiro com o conjunto de dados **Mapa de códigos** e escolha **Which source do these rows apply to?** para o limitar a uma origem.

## Escolher que origem conta a partir de quando

Quando duas origens fornecem os mesmos meses, a verificação **Que origem abrange que meses** pede-lhe que escolha. Clique em **Choose which source counts from when** no cartão **What to do next** para abrir **Which source counts from when**, que lista cada sobreposição por empresa. Escolha a origem que conta, introduza o mês a partir do qual conta em **That month is**, por exemplo `2026-04`, e clique em **Apply changes**. A outra origem mantém os meses anteriores.

A mesma caixa de diálogo avisa quando duas origens dão taxas de câmbio diferentes para uma moeda; são utilizadas as taxas da origem mais acima na ordem.

## Conversão de moedas

Cada carregamento converte os montantes do razão geral, do balancete, das vendas, do inventário e do orçamento da respetiva moeda local para uma única moeda de relato. Os relatórios e os modelos de cálculo leem os montantes convertidos, pelo que as entidades em moedas diferentes, de qualquer sistema, somam corretamente.

### A moeda de relato

Para escolher a moeda de relato, defina a variável de projeto `reporting_currency` com um código de moeda como `USD`. Consulte [Gerir variáveis de projeto](/pt-pt/guides/projects/managing-projects/#gerir-variáveis-do-projeto). O modelo cria-a em branco. Enquanto estiver em branco, cada carregamento utiliza a primeira destas opções que indique exatamente uma moeda:

1. A moeda de grupo das entidades.
2. A moeda local das entidades de nível superior, as que não têm entidade-mãe.
3. A moeda local dos ficheiros.

Se nenhuma delas indicar exatamente uma moeda, **Conversão de moedas** mostra um problema até definir `reporting_currency`.

Os montantes já na moeda de relato ficam como estão, pelo que um projeto cujos dados estejam todos numa só moeda não precisa de taxas.

Os ficheiros de vendas, inventário e orçamento também podem ter uma moeda. Mapeie uma coluna com o nome `Currency` ou `Local Currency` e ela é detetada automaticamente, e os montantes locais do ficheiro são convertidos para a moeda de relato. Um montante de grupo ou de relato que já esteja no ficheiro é mantido tal como está. O custo padrão dos produtos não é convertido.

### Taxas de câmbio

Uma taxa converte uma unidade de uma moeda na moeda de relato para um mês: o montante convertido é o montante local multiplicado pela taxa.

- **A partir do ERP**, cada carregamento lê as taxas de câmbio que o ERP contém.
- **A partir de um ficheiro**, adicione um ficheiro CSV ou Excel e escolha o conjunto de dados **Taxas de câmbio**. Uma taxa no ficheiro substitui a taxa do ERP para as mesmas moedas e mês. Utilize um ficheiro para relatar numa moeda para a qual os ERP não publicam taxas, ou para adicionar taxas planeadas para os meses do orçamento.

| Coluna | Contém |
|---|---|
| `from_currency` | A moeda de origem da conversão, por exemplo `EUR`. |
| `to_currency` | A moeda de relato, por exemplo `USD`. |
| `period` | O mês, no formato `YYYY-MM`. |
| `average_rate` | A taxa média do mês. |
| `closing_rate` | A taxa no final do mês. |
| `historical_rate` | A taxa histórica, para o capital próprio e para as contas definidas com a taxa histórica. |

Quando uma moeda não tem taxa para a moeda de relato, é invertida a taxa no sentido contrário, da moeda de relato para essa moeda, mantendo 12 casas decimais. Na falta desta, a taxa dessa moeda para outra moeda é multiplicada pela taxa dessa outra moeda para a moeda de relato.

### Que taxa se aplica

Cada linha é convertida a partir da sua própria moeda, pelo que uma linha numa moeda diferente da da sua entidade é convertida a partir da moeda em que está. Aplica-se a primeira regra que corresponda à linha:

| Linha | Taxa |
|---|---|
| Contas estatísticas e contas sem lançamentos | Não convertidas. |
| Já na moeda de relato | Não convertida. |
| Conta com um tipo de taxa | Essa taxa: média, de fecho ou histórica. A histórica recorre à de fecho quando não existe taxa histórica. Num ERP, o tipo de taxa é o próprio tipo de taxa da conta. Num ficheiro de plano de contas, mapeie uma coluna de tipo de taxa para `fx_rate_type` com `average`, `closing` ou `historical`. |
| Linha de vendas | A taxa média do período. |
| Saldo de inventário | A taxa de fecho do período. |
| Linha de orçamento | Por conta, tal como no razão geral: a taxa média para as contas de resultados e a taxa de fecho para as contas de balanço. |
| Conta de resultados | A taxa média do período. |
| Conta de capital próprio | A taxa histórica, ou a taxa de fecho quando não existe taxa histórica. |
| Qualquer outra conta de balanço | A taxa de fecho do período. |

Os montantes convertidos não são arredondados, pelo que os totais não se desviam.

<Aside type="note">
O balancete contém os movimentos de cada período, pelo que os montantes de balanço são os movimentos de cada mês convertidos à taxa de fecho desse mês. Não constituem um balanço reconvertido à taxa de final do período, e não há ajustamento cumulativo de conversão nem eliminação intragrupo. Utilize os montantes convertidos para a demonstração de resultados.
</Aside>

## Hierarquias

Cada carregamento reconstrói as dimensões a partir dos dados mestre de todas as origens. Existem sete dimensões de início e até dez categorias adicionais:

| Dimensão | Construída a partir de |
|---|---|
| **Entidade** | Entidades e respetivas entidades-mãe |
| **Conta** | Plano de contas e contas-mãe |
| **Departamento** | Departamentos e respetivos departamentos-mãe |
| **Cliente** | Clientes e respetivos clientes-mãe |
| **Produto** | Produtos e respetivos produtos-mãe |
| **Segmento 1** | Valores de segmento para `segment_1` |
| **Segmento 2** | Valores de segmento para `segment_2` |
| **Segmento 3** a **Segmento 10** | Valores de segmento para `segment_3` a `segment_10`, quando as origens os têm |

- Um registo sem elemento-pai, ou que se indica a si próprio como elemento-pai, é carregado como membro de nível superior.
- Como cada carregamento reconstrói as hierarquias, altere um elemento-pai no ERP ou no ficheiro, e não na dimensão.
- Um problema numa hierarquia afeta apenas essa dimensão. O carregamento e os modelos de cálculo do modelo concluem-se na mesma.
- Pode dar a cada categoria adicional o nome do que contém, por exemplo **Classe** ou **Região**. Em **Rename extra categories**, introduza os nomes que os relatórios utilizam e clique em **Save names**. Os nomes utilizam letras, números, espaços, pontos, hífenes e carateres de sublinhado, até 60 carateres.
- Cada origem indica em qual dos seus nomes de categoria fica cada uma das suas próprias categorias adicionais. Abra **Avançado** na origem, escolha o nome para cada uma, ou escolha **Leave out**, e clique em **Guardar**. As origens que designam uma categoria com nomes diferentes, como `Class` e `Business area`, passam então a partilhar uma posição.

Para fornecer hierarquias de segmentos a partir de um ficheiro, escolha o conjunto de dados **Valores de segmento**:

| Coluna | Contém |
|---|---|
| `segment` | O segmento a que o valor pertence: `segment_1` a `segment_10`. |
| `segment_value` | O valor, tal como as linhas do razão geral, de vendas e de orçamento o têm. |
| `segment_value_name` | O respetivo nome. |
| `parent_segment_value` | O respetivo elemento-pai dentro do mesmo segmento. |

## Verificações de prontidão

Após cada carregamento, a grelha **Prontidão** lista todas as verificações para cada entidade e período, com um destes estados:

| Estado | Significado |
|---|---|
| **● Pronto** | A verificação foi aprovada. |
| **▲ Requer atenção** | Merece uma análise, mas os números são utilizáveis. |
| **■ Problema** | Corrija isto antes de confiar nos resultados. |
| **– Não aplicável** | Ainda não há dados para esta verificação. |

As verificações são:

| Verificação | O que confirma |
|---|---|
| **Dados carregados** | Todos os períodos fiscais têm linhas do razão geral e todas as leituras do ERP tiveram êxito. Um período fechado sem linhas é um problema; um período aberto sem linhas requer atenção. |
| **O balancete coincide com o razão geral** | O balancete é igual ao razão geral para cada entidade, período e conta. Quando tanto o balancete como o razão geral têm departamentos para uma conta, verifica também a coincidência por departamento. |
| **Vendas coincidem com o razão geral** | As linhas de vendas são iguais às contas de receita e de custo das mercadorias vendidas do razão geral em cada período. |
| **Produtos/clientes desconhecidos** | Todas as linhas de vendas indicam um produto e um cliente que existem nos mestres de produtos e de clientes. |
| **Contas em falta no plano de contas** | Todas as linhas do razão geral indicam uma conta do plano de contas. As linhas com uma conta desconhecida ficam fora da demonstração de resultados. Uma conta com lançamentos mas sem tipo de conta também é um problema, e uma origem cujo plano classifica contas de Receita mas nenhuma conta de custo das mercadorias vendidas requer atenção. |
| **Conversão de moedas** | Todas as linhas do razão geral, do balancete, de vendas, de inventário e de orçamento têm um montante na moeda de relato. Uma linha de resultados ou de vendas sem taxa é um problema, porque a demonstração de resultados lê montantes convertidos. Uma linha de balanço, de inventário ou de orçamento sem taxa requer atenção. Um mês de orçamento ainda sem taxa aparece a âmbar, pelo que deve carregar taxas planeadas para os meses do orçamento. Consulte [Conversão de moedas](#conversão-de-moedas). |
| **Entidades não mapeadas** | Todas as linhas do razão geral, do balancete e de vendas indicam uma entidade do mestre de entidades, diretamente ou através do mapeamento de entidades. Não aplicável até ser carregado um mestre de entidades. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |

Os carregamentos com mais do que uma origem acrescentam estas verificações:

| Verificação | O que confirma |
|---|---|
| **Livro de relato** | Uma origem que tem vários livros contabilísticos para uma entidade teve o seu livro de relato escolhido. Até escolher, só conta o primeiro livro. |
| **Códigos a aguardar resposta** | Todos os códigos utilizados por mais do que uma origem foram respondidos. Consulte [Mapear códigos entre origens](#mapear-códigos-entre-origens). |
| **Categorias adicionais das origens** | Todas as categorias adicionais que uma origem tem têm um nome ou foram deixadas de fora. |
| **Que origem abrange que meses** | Não há duas origens a fornecer os mesmos meses de uma empresa, a menos que tenha escolhido qual conta. |
| **Tipos de conta e hierarquia** | Todos os elementos-pai que uma dimensão indica existem, e nenhum membro é o seu próprio elemento-pai ou antecessor. Um elemento-pai em falta coloca os seus filhos no topo da hierarquia, e um ciclo impede o carregamento dessa hierarquia. Os totais não são afetados. |
| **Calendário fiscal** | Os períodos fiscais de cada entidade são meses de calendário, e cada mês de linhas pode ser colocado num período fiscal. Requer atenção quando os períodos de uma entidade não são meses de calendário (4-4-5, 13 períodos), ou quando as linhas de um mês podem pertencer a mais do que um período fiscal ou o calendário fiscal não tem o mês. |

Cada linha que não está pronta indica o que fazer na coluna **O que fazer**, como carregar o plano de contas, carregar taxas de câmbio ou executar novamente **Carregar** para um período.

A grelha mostra também duas verificações de configuração, que só aparecem quando requerem atenção:

| Verificação | Quando aparece |
|---|---|
| **Imputação de custos indiretos** | Só está definida uma das variáveis de projeto `overhead_department` e `overhead_driver`, ou nenhum indutor de alocação corresponde a `overhead_driver`, pelo que a alocação não faria nada. Defina ambas ou limpe ambas para desativar a imputação de custos indiretos. |
| **Comparação com o orçamento** | Há linhas de orçamento carregadas, mas nenhuma está na versão indicada pela variável de projeto `budget_version`, pelo que a comparação com o orçamento ficaria vazia. |

## Consolidação de gestão

Cada carregamento constrói uma consolidação de gestão: a demonstração de resultados do grupo de todas as entidades do grupo, na moeda de relato, com as operações intragrupo eliminadas. Destina-se ao relato de gestão. O sistema de consolidação continua a ser o registo oficial do grupo para efeitos legais; reconcilie com ele conforme descrito abaixo.

<Aside type="note">
A consolidação de gestão abrange apenas a demonstração de resultados. Não é uma consolidação legal ou estatutária, e não tem balanço consolidado, ajustamento de conversão, goodwill nem interesses minoritários.
</Aside>

### Escolher o grupo

Em **Origens**, abra **Grupo** para ver as empresas do grupo. Uma empresa que desmarque continua nos relatórios por si só, mas fica fora do total do grupo. Clique em **Save group**. A alteração aplica-se no **Carregar** ou **Apply changes** seguinte. Uma empresa nova fica no grupo até a desmarcar.

O ano fiscal do grupo começa no mês definido pela variável de projeto `group_fy_start_month`, que é `1`, a menos que a altere.

### O que obtém

| Tabela | Contém |
|---|---|
| **Demonstração de resultados do grupo** | Uma linha por entidade, período e rubrica (receita, custo das mercadorias vendidas, gastos operacionais, não operacional, diferença intragrupo), na moeda de relato. As receitas e os custos têm o seu sinal natural. |
| **Demonstração de resultados do grupo acumulada no ano** | O mesmo, acumulado no ano, até ao último período totalmente carregado do grupo. |
| **Pares intragrupo** | Uma linha por par de entidades, grupo e período, com o montante de cada lado e o residual. |
| **Linhas intragrupo** | As linhas do razão por detrás de um valor do grupo ou de um par, com o parceiro comercial. |
| **Reconciliação** | A demonstração de resultados do grupo acumulada no ano face ao sistema de consolidação. |

Nestas tabelas aparecem três nomes de entidade:

| Entidade | Significado |
|---|---|
| **Eliminações** | As eliminações intragrupo. O seu saldo é zero, pelo que devem ser mantidas para os valores do grupo e filtradas para obter a soma das entidades antes da eliminação. |
| **Total do grupo** | O total do sistema de consolidação, na reconciliação. |
| **Não mapeado** | Linhas sem período, e contas ou entidades do sistema de consolidação que este projeto não tem. |

Os indicadores **Consolidated income**, **Consolidated result** e **IC difference**, e um caminho de análise para cada tabela, respondem a perguntas sobre o grupo.

### Eliminações intragrupo

As linhas intragrupo são emparelhadas por parceiro comercial. É utilizado o parceiro indicado na linha; quando uma linha não tem nenhum, é utilizado o parceiro do respetivo cliente. Ambos os lados de um par são eliminados, e o montante em que os dois lados não coincidem é registado numa linha de diferença intragrupo. Cada par recebe um motivo:

| Motivo | Significado |
|---|---|
| **Correspondente** | Ambos os lados registaram o mesmo montante. |
| **Só um dos lados registou** | Uma entidade registou a transação e o seu parceiro não. |
| **Não eliminado** | Uma linha do par não tem taxa de câmbio, pelo que nenhum dos lados é eliminado. |

Um par é avaliado pelo seu acumulado do ano. A linha **Saldos intragrupo** fica a âmbar quando a diferença de um par excede a variável de projeto `group_amber` (predefinição `1`) e a vermelho acima de `group_red` (predefinição `1000`). As linhas sem parceiro, ou com um parceiro que não é uma entidade, não são eliminadas e são contabilizadas nessa linha. Uma origem que tem parceiros ao lado de outra que não tem aparece a âmbar.

As entidades de eliminação próprias de uma origem ficam fora da demonstração de resultados do grupo, e a linha **Consolidação** indica-o.

### Reconciliar com o sistema de consolidação

Adicione como ficheiro os resultados que o sistema de consolidação reporta e assinale **These are consolidated results (OneStream, Anaplan, SAP Group Reporting, FCCS)** ao confirmar a respetiva correspondência. Responda a **Which version of the numbers is this?** com o nome do sistema. A tabela **Reconciliação** mostra então **nosso**, **reportado** e **diferença** para cada entidade e rubrica, acumulados no ano. Uma diferença explica-se normalmente nas linhas **Eliminações**, **Total do grupo** e **Não mapeado**, ou pelas taxas de câmbio que o sistema utiliza. A linha **Reconciliação com a origem** lista todas as rubricas acima de `group_amber`.

### Quem pode ver

Os resultados do grupo seguem o acesso às linhas do projeto. Quando o acesso às linhas impede os resultados do grupo, o estado aparece a âmbar. Uma pessoa que só vê algumas entidades vê as somas dessas entidades antes da eliminação. As linhas **Eliminações** e as tabelas intragrupo exigem acesso a todas as entidades.

Se o projeto limitar quem vê que linhas através de uma coluna que as tabelas do grupo não têm, como o departamento, os resultados do grupo ficam desativados para todos e **Consolidação** indica **Group views are off**. Nesse caso, só um Arquiteto pode assinalar **Everyone on the project may see the group results** em **Grupo**. A alteração aplica-se no **Carregar** ou **Apply changes** seguinte.

## Manter os dados atualizados

Depois de um carregamento a partir da ligação ERP ter êxito sem problemas, aparece **Atualizar todas as noites** no cartão **Último carregamento**. Clique nele para executar **Carregar** todas as noites às 2:00 no seu fuso horário. O cartão mostra então **Nightly refresh: Every night at 2:00** e quem o configurou.

O carregamento noturno é executado como a pessoa que o configurou. Se essa pessoa deixar de poder utilizar a ligação ERP, a grelha indica que o carregamento noturno é ignorado; volte a configurá-lo. Um projeto que só tenha dados de exemplo não pode ser agendado.

Um ficheiro em falta ou vazio num carregamento noturno termina com um aviso que indica o caminho, e não com um erro, e o resto do modelo é carregado na mesma.

## Nomes de negócio

Os **Nomes de negócio** no separador **Base** dão aos códigos do modelo os nomes que a sua empresa utiliza. Os relatórios, os indicadores e o assistente mostram estes nomes, e um nome guardado aplica-se de imediato. Os carregamentos posteriores mantêm-no.

1. Clique em **Add a name** e escolha o **Tipo**: **Categoria**, **Rubrica da demonstração de resultados**, **Indicador** ou **Coluna**.
2. Introduza o **Código**: `segment_1` a `segment_10` para uma categoria, a chave da rubrica para uma rubrica da demonstração de resultados, o nome do indicador, ou `table.column` para uma coluna.
3. Introduza o **Nome**, com no máximo 60 carateres numa só linha.
4. Clique em **Save names**.

Guardar substitui a lista inteira. Uma linha com um nome vazio remove esse nome, e **Remover selecionados** remove as linhas assinaladas. Dar nome ao mesmo código duas vezes é recusado. Os nomes de negócio são também escritos na descrição do caminho de análise para que o assistente utilize as suas palavras, e essa descrição tem um limite de comprimento: se um nome a tornar demasiado longa, nada é guardado e é informado disso.

## Explicar um número

**Explain this number** mostra o que compõe um valor da demonstração de resultados. Na grelha **Prontidão**, uma linha de uma entidade e mês tem **Explain this number**, que abre a margem operacional da entidade nesse mês. A janela divide o número em camadas que somam o total apresentado no topo:

| Camada | O que contém |
|---|---|
| **Do razão geral** | O que o razão lançou na rubrica. |
| **Alocado de entrada** | Custo distribuído a esta entidade pelas suas [regras de alocação](#regras-de-alocação). |
| **Alocado de saída** | Custo que esta entidade distribuiu a outras. |
| **Eliminado no grupo** | Operações intragrupo eliminadas no resultado do grupo. |

Cada camada tem uma frase que indica o que é e os seus maiores documentos de origem, com o sistema de origem, o documento e a conta. Só são mostradas as camadas que têm linhas. A janela segue o seu acesso às linhas: só pode explicar os valores que consegue ver. Um número sem nada por detrás indica **Nothing to explain**.

## Regras de alocação

As alocações distribuem custos partilhados, como os custos indiretos, por departamentos, produtos e clientes. O modelo tem duas fases: **Stage 1: overhead to departments** e **Stage 2: departments to products and customers**. Abra **Ações > Alocações...** para ver ou alterar a forma como cada uma é feita. Sem alterações, funcionam como funcionavam antes de o assistente existir. Um leitor pode abrir as regras, mas não guardá-las.

Para cada fase, o assistente faz quatro perguntas:

| Passo | Pergunta | Opções |
|---|---|---|
| **Conjunto** | Que custos pretende distribuir? | O tipo de conta e, na fase 1, o departamento que contém o custo, ou **All departments**. |
| **Indutor** | Com base em que pretende distribuí-los? | **Statistic** que carregou como indutores de alocação, como o número de colaboradores ou a área em pés quadrados, **Net sales amount**, **Sales quantity** ou **Spread evenly**. Utilize o indutor de **Same period** ou **Same period last year**. |
| **Destino** | Onde ficam? | Fase 1: departamentos. Fase 2: produtos, clientes ou ambos. |
| **Método** | O que acontece quando um indutor é negativo? | **Ignore negative values** ou **Stop and tell me**. |

Sob os passos, **Preview for** um mês, escrito como ano e mês, por exemplo `2026-09`, mostra o que as regras fariam, incluindo as que ainda não guardou: `Pool 120,000 · Allocated 120,000 · Unallocated 0`. Qualquer valor não alocado é custo que não teve um indutor para o receber. A pré-visualização segue o seu acesso às linhas.

Clique em **Guardar**. As regras produzem efeito no **Carregar** seguinte, ou quando clicar em **Apply changes**. Se editou manualmente um passo de alocação, a sua edição é mantida, não substituída, e a gravação indica-o pelo nome. Não é possível guardar enquanto um carregamento está em curso.

## Pacote para o conselho

Um pacote para o conselho escreve os resultados numa pasta de uma conta de documentos, prontos a enviar. Abra **Ações > Pacote para o conselho...**, escolha uma **Conta de documentos** e uma **Pasta**, como `/board-packs`, e clique em **Guardar**. A partir daí, cada **Carregar** gera o pacote, pelo que os ficheiros na pasta estão tão atualizados como o último carregamento. Cada execução escreve:

- Um livro do Excel, `Board pack.xlsx`, com a demonstração de resultados por entidade, uma ponte de margens e os clientes com melhores e piores resultados.
- Um PDF do painel de controlo da demonstração de resultados.

Clique em **Run now** para gerar um pacote de imediato; os ficheiros aparecem na pasta quando terminar. A caixa de diálogo mostra a última execução e o respetivo resultado, bem como a próxima execução. **Apply changes** não gera um pacote. Para gerar um todas as noites, configure a atualização noturna (consulte [Manter os dados atualizados](#manter-os-dados-atualizados)); até lá, a caixa de diálogo indica **Not scheduled yet**. Só quem pode alterar o projeto o configura.

Um pacote que não pode ser gerado na totalidade nunca faz falhar o carregamento:

- Se o relato estiver desativado na área de trabalho, o pacote é apenas o livro do Excel, e a execução indica **Reporting is turned off for this workspace, so the board pack has the Excel workbook only.**
- Se um painel de controlo criado por outra pessoa já tiver o endereço de que o Data Foundation precisa para o painel de controlo da demonstração de resultados, esse painel de controlo fica como está e o PDF não é gerado. A mensagem indica o endereço; dê outro endereço ao outro painel de controlo e execute novamente **Carregar**.
- Se algum passo do pacote falhar, a lista **Estado** mostra uma linha âmbar **Pacote para o conselho** com o passo e o motivo. O carregamento em si teve êxito.

## Pontos de restauro

É criado um ponto de restauro no início de cada **Carregar** ou **Apply changes**, seja quem for que o inicie, incluindo um carregamento agendado, e antes de cada alteração às correspondências ou às origens. Contém as tabelas do modelo, as dimensões e as definições a partir das quais o carregamento seguinte é construído: as origens, os ficheiros e as regras de alocação. São mantidos os últimos sete pontos criados para carregamentos e os últimos cinco criados antes de alterações, pelo que as alterações nunca eliminam os pontos criados para carregamentos. Os pontos mais antigos são descartados.

Para voltar atrás, abra **Ações > Restaurar...**. Cada ponto mostra quando foi criado e, por baixo, quantas tabelas o restauro repõe, por exemplo **Puts back 12 tables.**, juntamente com eventuais avisos. Escolha um ponto e clique em **Restaurar**. **Restaurar** fica disponível assim que existir um ponto. O restauro começa por registar o projeto no estado atual como um ponto próprio, para que possa voltar atrás novamente. Depois, repõe as tabelas, as dimensões e essas definições tal como estavam, e o carregamento seguinte é construído a partir delas. Restaurar para as origens que já tinha não as marca como alteradas. Uma vista, uma dimensão que não pode ser guardada ou uma tabela sem cópia guardada é indicada num aviso, e o resto é restaurado. Um ponto de restauro que já foi descartado é recusado, e não é possível restaurar enquanto um carregamento está em curso.

## Clonar um projeto

**Ações > Clonar...** copia o projeto com um nome que indicar. A cópia mantém o modelo, as suas edições ao modelo de dados e os seus indicadores e caminhos de análise, e carrega os dados de exemplo. As respetivas origens não ficam ligadas, pelo que deve ligá-las na cópia antes de carregar. Pode continuar a trabalhar enquanto a cópia é criada, e **Abrir projeto** leva-o até ela quando estiver pronta.

## Guardar como o meu modelo

Guarde a configuração de um projeto para a reutilizar no próximo cliente ou entidade. Abra **Ações > Guardar como o meu modelo...**, escolha a conta de documentos e dê um nome ao ficheiro. Se omitir a terminação `.zip`, ela é acrescentada. Guardar por cima de um ficheiro existente é recusado, pelo que deve escolher outro nome.

O ficheiro contém a estrutura do projeto, as suas edições ao modelo de dados, os indicadores e os caminhos de análise, os nomes de negócio das entidades e contas, e as linhas das tabelas de configuração do modelo, como o mapa de atividades do [Cost to Serve](/pt-pt/guides/projects/cost-to-serve/) ou os intervalos de política do [Operational Transfer Pricing](/pt-pt/guides/projects/operational-transfer-pricing/). Deixa de fora as ligações, os ficheiros, o agendamento noturno, as execuções, os pontos de restauro, o pacote para o conselho e quem tem acesso.

Para o utilizar, crie um projeto, escolha **From a template file...** em **Começar a partir de** e selecione a conta de documentos e o caminho. O novo projeto é privado, com todas as origens a aguardar ligação. Uma versão posterior do modelo junta as suas alterações em torno dos passos que editou. Se não existir nenhum ficheiro no caminho, nada é criado e é informado disso. Qualquer pessoa que possa ler a conta de documentos pode instalar a partir do ficheiro. Para o utilizar noutra área de trabalho, transfira o ficheiro e carregue-o lá.

## Resolver questões em aberto com o Ask

Após um carregamento, um projeto pode ainda estar à espera de três respostas: contas que o plano deixa sem tipo, códigos que mais do que uma origem utiliza e colunas dos ficheiros que não corresponderam a nada. Peça ao assistente para as resolver: a partir de um assistente de IA através de MCP, utilize o prompt **Resolve Data Foundation residue**. Este lê o que está pendente e propõe uma resposta para cada item, com um motivo.

O assistente não escreve nada. As respostas são aplicadas por si no mesmo sítio onde teria respondido: as contas e os códigos em **Códigos a aguardar resposta** e as colunas dos ficheiros na correspondência do ficheiro. Nunca propõe uma entidade.

## Entregar o projeto

A lista de verificação **Configuração** tem quatro itens finais após **Reveja as suas hierarquias**:

- **Configurar a atualização noturna** fica concluído quando **Atualizar todas as noites** estiver ativo.
- **Partilhar com a sua equipa** fica concluído quando alguém além da pessoa que configurou o projeto for membro.
- **Transferir o pacote de evidências** fica concluído quando transferir o pacote após o último carregamento com êxito.
- **Entregar o projeto ao respetivo proprietário** fica concluído quando existir um Arquiteto que não seja a pessoa que o configurou e os totais coincidirem. Enquanto não estiver concluído, a lista de verificação indica o que fazer: tornar o proprietário do lado do cliente Arquiteto deste projeto e, em seguida, remover-se dos membros.

A lista de verificação indica quem configurou o projeto (**Set up by**).

## Construir sobre o modelo com um modelo de projeto

Um modelo de projeto constrói os seus relatórios e modelos de cálculo sobre o Common Finance Model, pelo que funcionam da mesma forma sejam quais forem os ERP que o alimentam. Quando inicia um projeto a partir de um modelo, como **Enterprise Profitability**, este cria:

- As [tabelas do Common Finance Model](#tabelas-do-common-finance-model), vazias ou preenchidas com dados de exemplo.
- As dimensões **Entidade**, **Conta**, **Departamento**, **Cliente**, **Produto**, **Segmento 1** e **Segmento 2**, construídas a partir dessas tabelas. Consulte [Hierarquias](#hierarquias).
- O fluxo de trabalho **Carregar** e os fluxos de trabalho que este executa para ler o ERP e os ficheiros, uniformizá-los, verificar a prontidão e construir os modelos de cálculo do modelo.
- Os relatórios e modelos de cálculo próprios do modelo. **Enterprise Profitability** acrescenta uma tabela de demonstração de resultados com receita, custo das mercadorias vendidas, margem bruta, gastos operacionais diretos e indiretos, contribuição e margem operacional, além de pontes de margens face ao ano anterior e face ao orçamento.
- Indicadores e um caminho de análise para fazer perguntas sobre os resultados.

Estão disponíveis três modelos em **Começar a partir de**, todos construídos sobre o mesmo modelo de dados:

| Modelo | Acrescenta |
|---|---|
| **Enterprise Profitability** | A demonstração de resultados e as pontes de margens. |
| **Cost to Serve** | O custo de servir cada cliente e a margem depois desse custo. Consulte [Cost to Serve](/pt-pt/guides/projects/cost-to-serve/). |
| **Operational Transfer Pricing** | O nível de lucro de cada entidade face ao intervalo da sua política, e o acerto. Consulte [Operational Transfer Pricing](/pt-pt/guides/projects/operational-transfer-pricing/). |

**From a template file...** começa a partir de um projeto que guardou. Consulte [Guardar como o meu modelo](#guardar-como-o-meu-modelo).

Para explorar antes de ligar o seu próprio ERP, assinale **Começar com dados de exemplo** ao criar o projeto. O projeto executa de imediato um primeiro carregamento, pelo que o separador **Base** mostra um exemplo completo, incluindo uma entidade em euros convertida para dólares americanos. Quando liga o seu próprio ERP ou adiciona os seus próprios ficheiros, os dados de exemplo são removidos e os seus dados tomam o seu lugar. Se a remoção for interrompida, o **Carregar** seguinte conclui-a. Uma pasta sua com o nome `sample` nunca é removida: a página de estado assinala que os dados de exemplo ocupam essa pasta, pelo que as outras tabelas nela contidas não são lidas, e pede-lhe que as mova para uma pasta com outro nome.

## O separador Base

O separador **Base** é onde liga, carrega e verifica os seus dados. Uma barra à esquerda lista quatro páginas:

| Página | O que mostra |
|---|---|
| **Estado** | O estado do projeto: **Último carregamento** com os botões **Carregar**, **Apply changes**, **Atualizar** e **Atualizar todas as noites**, **What to do next**, a lista de verificação **Configuração**, **Dados carregados**, **Períodos**, **Prontidão** e o menu **Ações**. |
| **Respostas necessárias** | As perguntas que aguardam resposta, como os códigos que mais do que uma origem utiliza, onde indica se significam o mesmo. |
| **Cobertura das origens** | Onde as origens se sobrepõem ou deixam lacunas para uma empresa e mês, e que origem conta a partir de quando. |
| **Origens** | Cada origem por ordem, com **Avançado**, **Remove this source**, **Grupo** e **Rename extra categories**, e **Ligar**, onde liga um ERP, escolhe as entidades e quantos meses de histórico carregar, ou adiciona um ficheiro. |

Os indicadores na barra contam o que requer atenção: as questões em aberto em **Respostas necessárias**, os problemas de cobertura em **Cobertura das origens** e as origens em **Origens**. **Estado** não mostra indicador. O resultado de um **Carregar** ou **Apply changes** e a faixa de estado aparecem acima da página que estiver aberta, pelo que os vê em todas as páginas. Os botões em **Estado** que apontam para uma pergunta ou um problema de cobertura, como **Rever**, levam-no a essa página. Fechar **Respostas necessárias** ou **Cobertura das origens** leva-o de volta a **Estado**.

A lista de verificação **Configuração** é: **Ligar os seus dados**, **Carregue os seus dados**, **Verificar se os totais coincidem**, **Reveja as suas hierarquias**, **Configurar a atualização noturna**, **Partilhar com a sua equipa**, **Transferir o pacote de evidências** e **Entregar o projeto ao respetivo proprietário**. O item atual está a negrito. Os nomes de negócio, os ficheiros que adicionou e o respetivo estado de correspondência (**✓ Confirmado** ou **○ A aguardar confirmação**), e a grelha de prontidão com uma linha por entidade, período e verificação e o respetivo **O que fazer**, estão nas mesmas páginas. Consulte [Nomes de negócio](#nomes-de-negócio).

Enquanto decorre um carregamento, o separador atualiza-se automaticamente e continua a ler mesmo que uma leitura falhe. Se não for possível ler o estado, aparece **Não foi possível ler o estado do Foundation.** com **Tentar novamente**, que volta a ler o estado; o separador também tenta novamente uma vez por si só antes de mostrar a mensagem, e a mensagem desaparece quando o servidor responde.

A página **Estado** assinala também:

- Uma pasta em `/sources/` cujas tabelas não têm as colunas de que necessitam não é adicionada como origem. Uma nota indica cada tabela que ficou de fora e a coluna em falta. Adicione a coluna e prima **Carregar** ou **Apply changes**.
- Se um carregamento teve êxito mas não trouxe linhas do razão para comparar, uma linha âmbar **A demonstração de resultados do modelo coincide com o razão geral** indica que nada foi conciliado. **Verificar se os totais coincidem** fica pendente na lista de verificação de configuração, e não concluído, até algo ter sido conciliado. Adicione uma origem com linhas do razão e prima **Carregar**.

A lista de verificação de configuração acompanha o seu progresso:

- **Ligar os seus dados** e **Carregue os seus dados** ficam assinalados automaticamente quando é associada uma origem e um carregamento tem êxito.
- **Verificar se os totais coincidem** fica assinalado automaticamente quando as verificações de coincidência são aprovadas.
- **Reveja as suas hierarquias**: clique em **Abrir dimensões** para rever as hierarquias de entidades, contas e departamentos e, em seguida, assinale **Já os revi**. Este item é confirmado por si.
- **Configurar a atualização noturna**, **Partilhar com a sua equipa**, **Transferir o pacote de evidências** e **Entregar o projeto ao respetivo proprietário** encerram a lista. Consulte [Entregar o projeto](#entregar-o-projeto) e [Gerir o acesso ao projeto](/pt-pt/guides/projects/managing-projects/#gerir-o-acesso-ao-projeto).

O menu **Ações** contém **Alocações...**, **Pacote para o conselho...**, **Clonar...**, **Restaurar...** e **Guardar como o meu modelo...**. Consulte [Regras de alocação](#regras-de-alocação), [Pacote para o conselho](#pacote-para-o-conselho), [Clonar um projeto](#clonar-um-projeto), [Pontos de restauro](#pontos-de-restauro) e [Guardar como o meu modelo](#guardar-como-o-meu-modelo).

## Tabelas do Common Finance Model

O Data Foundation uniformiza todas as origens, ERP ou ficheiro, nas mesmas quinze tabelas, pelo que os relatórios, indicadores e modelos de cálculo criados sobre elas funcionam da mesma forma seja qual for a origem. Cada linha regista também o respetivo sistema de origem e quando foi lida. A coluna **Conjunto de dados** é o nome que escolhe ao adicionar um ficheiro.

| Conjunto de dados | Tabela | Contém |
|---|---|---|
| Entidades | `cfm_entity` | Entidades jurídicas com entidade-mãe, moeda local e de grupo, e país. |
| Mapeamento de entidades | `cfm_entity_map` | Códigos de entidade das origens e a entidade a que cada um pertence. Consulte [Mapeamento de entidades](#mapeamento-de-entidades). |
| Taxas de câmbio | `cfm_fx_rate` | Taxas mensais médias, de fecho e históricas por par de moedas. Consulte [Taxas de câmbio](#taxas-de-câmbio). |
| Calendário fiscal | `cfm_fiscal_calendar` | Uma linha por período fiscal de cada entidade, com datas de início e de fim e se está fechado. |
| Plano de contas | `cfm_account` | Contas com conta-mãe, tipo (`Revenue`, `COGS`, `Opex`, `NonOperating`, `Asset`, `Liability`, `Equity`), demonstração, saldo normal e tipo de taxa. |
| Departamentos | `cfm_department` | Departamentos e centros de custo com departamento-mãe e centro de lucro. |
| Produtos | `cfm_product` | Mestre de produtos com produto-mãe, família, grupo, unidade de medida e custo padrão. |
| Clientes | `cfm_customer` | Mestre de clientes com cliente-mãe, grupo, região e país. Os nomes dos clientes não são ocultados. |
| Valores de segmento | `cfm_segment` | Valores de segmento com nome e elemento-pai. Consulte [Hierarquias](#hierarquias). |
| Razão geral | `cfm_gl_journal` | Linhas de diário na moeda da transação, local e de relato. |
| Balancete | `cfm_trial_balance` | Débitos, créditos e saldo líquido do período por entidade, conta e departamento, em moeda local e de relato. |
| Linhas de vendas | `cfm_sales_line` | Linhas de vendas faturadas com quantidade e montantes bruto, de desconto, líquido e de custo das mercadorias vendidas. |
| Saldos de inventário | `cfm_inventory_balance` | Inventário no final do período por produto e armazém. |
| Orçamento | `cfm_budget` | Orçamento e previsão por cenário, versão, conta e departamento. |
| Indutores de alocação | `cfm_stat_driver` | Indutores estatísticos, como o número de colaboradores, a área em pés quadrados ou as unidades. |

Os períodos são escritos como `YYYY-MM`, e as transações são colocadas por período de lançamento. O orçamento é opcional: um ERP sem orçamentos carrega na mesma tudo o resto.

Um ficheiro de balancete pode ter colunas de débito e crédito, uma coluna de saldo líquido, ou ambas. Só com débito e crédito, o saldo líquido é o débito menos o crédito, e um lado em branco conta como zero. Só com o saldo líquido, um saldo positivo passa a ser o débito e um saldo negativo passa a ser o crédito, como montante positivo. Uma coluna de departamento é opcional.

## Resolução de problemas

| Sintoma | O que fazer |
|---|---|
| **Testar ligação** indica que o ERP recusou as credenciais | Verifique as credenciais da ligação e se o utilizador de integração consegue iniciar sessão no ERP. |
| **Testar ligação** mostra **Permissão em falta** para um conjunto de dados | Peça ao administrador do ERP que adicione as permissões indicadas. O [guia de ligações](/pt-pt/guides/connections/) do seu ERP lista o que a ligação necessita. |
| Uma mensagem de erro do ERP é mais curta do que a do próprio ERP | A PlaidCloud remove credenciais, tokens e chaves dos erros do fornecedor antes de os mostrar, pelo que algum detalhe fica de fora. Execute **Testar ligação** para ver que conjunto de dados é afetado. |
| **Dados carregados** é um problema num período | Uma leitura do ERP para esse período falhou. Execute novamente **Carregar**; os períodos que foram carregados são ignorados. |
| **Contas em falta no plano de contas** é um problema | Adicione as contas em falta ao plano de contas no ERP ou no ficheiro e execute novamente **Carregar**. |
| **Conversão de moedas** é um problema | A moeda de uma entidade não tem taxa para a moeda de relato nesse período, ou não foi encontrada uma moeda de relato única. Adicione as taxas a um ficheiro **Taxas de câmbio**, verifique se a ligação consegue ler as taxas de câmbio do ERP ou defina a variável de projeto `reporting_currency`. Depois, execute novamente **Carregar**. |
| **Conversão de moedas** requer atenção | Linhas de balanço, de inventário ou de orçamento não têm taxa de fecho, histórica ou planeada para o período. A demonstração de resultados não é afetada. Adicione as taxas, incluindo as taxas planeadas para os meses do orçamento, e execute novamente **Carregar**. |
| **Códigos a aguardar resposta** requer atenção | Clique em **Rever**, responda a cada código e clique em **Apply changes**. |
| **Que origem abrange que meses** requer atenção | Clique em **Choose which source counts from when**, escolha a origem e clique em **Apply changes**. |
| **Saldos intragrupo** está a vermelho ou âmbar | Verifique os pares em **Pares intragrupo**. Registe o lado em falta, adicione o parceiro comercial às linhas ou adicione a taxa em falta. |
| **Group views are off** | Peça a um Arquiteto que assinale **Everyone on the project may see the group results** em **Grupo**. |
| **Entidades não mapeadas** é um problema | Adicione a entidade ao mestre de entidades, ou mapeie o respetivo código para uma entidade existente no ficheiro **Mapeamento de entidades**, e execute novamente **Carregar**. |
