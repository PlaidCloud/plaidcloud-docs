## Pesquisar

A pesquisa de projetos faz-se com a caixa de filtro, no canto inferior esquerdo da hierarquia. O filtro de pesquisa procura correspondências nos nomes e nas etiquetas dos projetos e mostra os resultados na hierarquia acima.


## Criar novos projetos

Para criar um novo projeto:

1. Abra o Analyze
2. Selecione “Projetos” na barra de menus superior
3. Clique no botão “Novo projeto”
4. Preencha as informações do formulário, incluindo a secção “Access Control”
5. Clique em “Create”

O projeto fica então pronto para atualizar as permissões de acesso, adicionar proprietários e criar fluxos de trabalho.

<Aside>Por predefinição, o projeto fica acessível a todos os membros da área de trabalho atual</Aside>


## Definir uma conta de documentos predefinida

Na página inicial do projeto, junto a **Ambiente da ligação**, escolha uma **Conta de documentos predefinida** para o projeto, ou **Nenhum** para a limpar.

Dentro do projeto, todos os seletores de ficheiros apresentam **Project Default** em primeiro lugar, em representação da conta que o projeto tem atualmente definida. Deixa de aparecer na lista quando sai do projeto, quando o projeto não tem predefinição definida, quando essa conta foi eliminada ou quando deixa de ter acesso à mesma.

Um novo passo de ficheiro preseleciona a predefinição do projeto quando o projeto tem uma. Os passos existentes nunca são reescritos: cada um mantém a conta com que foi guardado até que a altere, uma vez que a conta de documentos é uma escolha por passo, ao contrário do ambiente da ligação.

Um passo deixado na predefinição do projeto resolve para a conta que for a predefinição do projeto no momento da execução; por isso, alterar a predefinição a meio de uma execução afeta apenas os nós que ainda não começaram, tal como acontece com a alteração do ambiente da ligação. Se um passo for executado com a predefinição do projeto e o projeto não tiver nenhuma predefinição definida, a execução falha e indica o projeto, em vez de recorrer a outra conta.


## Histórico de versões

Todos os objetos de um projeto — um passo, uma UDF, um fluxo de trabalho, uma dimensão, uma disposição guardada, um documento ou editor de dados e as próprias definições do projeto — estão abrangidos por cópias de segurança do histórico de versões. Não é feita uma cópia de segurança a cada gravação individual; em vez disso, quando um objeto passa 30 segundos sem nova gravação, é feita uma cópia de segurança do seu estado estabilizado. Uma sequência de edições — várias gravações em rápida sucessão — produz uma única versão com o resultado final, e não uma versão por gravação. A gravação nunca fica mais lenta por esperar por uma cópia de segurança: a contagem decrescente e a própria cópia de segurança são executadas em segundo plano. Se precisar de uma versão de imediato, utilize **Back up now** para capturar o estado atual de imediato e aguardar a sua conclusão — disponível na IU, na API e como ação `backup` das ferramentas MCP `*_versions`. O histórico de versões está disponível em todos os planos, incluindo o Free.

As versões anteriores permitem a recuperação num ponto no tempo: restaurar um objeto para uma versão anterior. A restauração é recusada num projeto bloqueado, tal como qualquer outra alteração aí.

Uma versão é restaurada no próprio local. Restaurar uma versão de um projeto, dimensão, função definida pelo utilizador, passo, fluxo de trabalho ou editor de dados substitui esse mesmo item, e indicar um item diferente como destino é recusado — por exemplo, “A project version is restored in place. Leave the target out, or set it to this project.” Restaurar é uma alteração ao item, pelo que exige a mesma função necessária para o editar; num projeto que [restringe linhas](/pt-pt/administration/access/managing-security-groups-and-assignments/#quem-pode-alterar-um-projeto-que-restringe-linhas), restaurar o projeto ou uma dimensão lida por uma coluna restringida exige um Arquiteto do projeto. Para recuperar dados antigos de uma tabela como uma tabela separada, restaure um [instantâneo da tabela](/pt-pt/guides/data/table-snapshots/) para uma nova tabela.

Para além deste registo automático, os projetos e os seus elementos permitem também a criação de versões. Criar uma versão é fácil e também é possível fundir alterações de uma versão noutra. Isto proporciona uma forma simples de manter o registo de instantâneos ou de criar uma versão para desenvolvimento e, depois, fundir essas alterações na versão que não é de desenvolvimento quando pretender. Consulte [Collaborate: Versions, Compare, and Share](/pt-pt/get-started/tutorials/collaborate-versions-and-sharing/) para ver a criação de versões, a comparação e a fusão na prática.

Os dados das tabelas têm o seu próprio histórico — instantâneos tirados pelo Lakehouse em cada gravação — descrito em [Instantâneos de tabelas](/pt-pt/guides/data/table-snapshots/).

### Restaurar e reter através do assistente de IA ou do MCP

Através do assistente de IA ou do MCP, `dimension_versions` restaura, retém e liberta uma versão de dimensão pelo seu `version_id`, e `restore_project` repõe todas as dimensões do projeto na sua última cópia de segurança, e cada listagem `*_versions` (passos, UDFs, fluxos de trabalho, dimensões, projetos) mostra o `version_id` de cada versão e se está retida. Um `restore` através de qualquer ferramenta `*_versions`, ou da API REST, restaura o item no próprio local: deixe o destino de fora ou defina-o como o próprio item. O `project_upsert` pode desbloquear um projeto bloqueado e respeita `if_match`, falhando em vez de substituir uma alteração feita desde a última vez que leu o projeto.


## Gerir o acesso ao projeto

### Tipos de acesso

A segurança dos projetos foi simplificada em três tipos de acesso:

* Todos os membros da área de trabalho
* Apenas membros específicos
* Apenas grupos de segurança específicos

Definir a segurança do projeto é fácil:

1. Abra o Analyze
2. Selecione “Projetos”
3. Clique no ícone de edição do projeto que pretende restringir
4. Escolha a restrição pretendida em “Access Control”
5. Clique em “Update”

Apenas um Arquiteto do projeto ou um administrador do tenant pode alterar quem tem acesso a um projeto — o seu tipo de acesso, os membros e os grupos de segurança que nele constam e as suas partilhas de dados. Qualquer outra pessoa vê esses painéis só de leitura, com a nota “Only project Architects can change access.”


## Todos os membros da área de trabalho

O acesso “Todos os membros da área de trabalho” é a opção mais simples, uma vez que dá acesso a todos os membros da área de trabalho e não exige qualquer atribuição adicional de membros.


## Apenas membros específicos

A definição de acesso “Apenas membros específicos” exige a atribuição de cada membro ao projeto. Para atribuir membros a um projeto:

1. Abra o Analyze
2. Selecione “Projetos” na barra de menus superior
3. Clique no ícone de membros
4. Conceda acesso aos membros ao selecionar a caixa de verificação junto ao respetivo nome na coluna “Access”
5. Clique em “Update”

Em clouds com um grande número de membros, esta abordagem pode exigir mais esforço do que o desejável, e é aí que os grupos de segurança se tornam úteis.

<Aside>Para adicionar membros, tem de ser membro da área de trabalho.</Aside>


## Apenas grupos de segurança específicos

A opção “Apenas grupos de segurança específicos” permite atribuir a grupos de segurança específicos a permissão de acesso à conta. Como as restrições de acesso dependem da associação a um ou mais grupos de segurança, a administração do acesso à conta para grupos maiores é muito mais simples. Isto é particularmente útil quando combinado com a associação automática a grupos através do início de sessão único. Ao utilizar o início de sessão único para definir as atribuições de grupos dos membros, esses grupos podem também ativar e desativar implicitamente o acesso a projetos.

Para editar os grupos atribuídos:

1. Abra o Analyze
2. Selecione “Projetos” na barra de menus superior
3. Clique no ícone de grupos de segurança
4. Conceda acesso aos grupos de segurança ao selecionar a caixa de verificação junto ao respetivo nome na coluna “Access”
5. Clique em “Update”


## Partilhar dados entre projetos

Uma partilha de dados permite que um projeto aceda às tabelas de outro projeto — por exemplo, para que os passos [Import Project Table](/pt-pt/reference/workflow-steps/import/import-project-table/) e [Export Project Table](/pt-pt/reference/workflow-steps/export/export-project-table/) possam mover dados entre eles. Uma partilha é concedida pelo projeto cujos dados são partilhados, a um outro projeto:

1. Abra o projeto cujos dados pretende partilhar e aceda ao respetivo separador **Início**.
2. Em **Gestão de partilha de dados**, clique em **Nova partilha de dados**.
3. Em **Selecionar projeto**, escolha o projeto que pode utilizar os dados deste projeto.
4. Em **Operações permitidas**, assinale **Leitura**, **Escrita** ou ambas e clique em **Adicionar partilha de dados**.

**Eliminar partilha de dados** remove uma partilha. Apenas um Arquiteto do projeto ou um administrador do tenant pode adicionar ou eliminar as partilhas de dados de um projeto.

Uma partilha é concedida a um projeto, pelo que fala apenas em nome dos membros e dos fluxos de trabalho desse projeto:

- **Ler** através de uma partilha exige uma função no projeto a que foi concedida. Quem não tiver nenhuma função aí não obtém nada da partilha.
- **Escrever** através de uma partilha — criar uma tabela, uma pasta ou uma dimensão no projeto que partilha — exige uma partilha de **Escrita** e a função de Gestor ou Arquiteto no seu próprio projeto, a função que poderia fazer a mesma alteração aí. Qualquer outra pessoa recebe a indicação “Writing to this project through a data share needs a write share from it to your project, and the Manager or Architect role in your project.”

Os fluxos de trabalho são executados com a identidade própria do respetivo projeto, pelo que os passos Import Project Table e Export Project Table funcionam através de uma partilha, independentemente de quem inicia a execução.


## Definir diferentes funções de visualização

Muitas vezes, um projeto pode exigir várias transformações e tabelas para concluir passos intermédios, enquanto o resultado final pode acabar por consistir apenas em algumas tabelas. Os membros nem sempre precisam de ver todos os elementos do projeto, por vezes apenas o produto final. O PlaidCloud permite definir diferentes funções de visualização para simplificar e controlar facilmente a visibilidade de cada membro.

Existem três funções de visualização incorporadas: **Arquiteto, Gestor** e **Explorador**

A função **Arquiteto** é a mais simples, pois permite visibilidade e controlo totais sobre projetos, fluxos de trabalho, tabelas, variáveis, editores de dados, hierarquias e funções definidas pelo utilizador.

As funções **Gestor** e **Explorador** não têm privilégios de acesso específicos, mas podem ser definidas à medida. Por outras palavras, pode escolher que itens são visíveis para cada grupo.

<Aside>**Gestor*** *e **Explorador** não são grupos de segurança; apenas proporcionam uma forma prática de segregar funções e a visibilidade da informação.</Aside>

Pode tornar todos **Arquiteto** se considerar necessária a visibilidade de tudo no projeto; caso contrário, pode designar membros como membros do projeto **Gestor** e/ou **Explorador** e controlar a visibilidade dessa forma.

Para definir a função:

1. Abra o Analyze
2. Selecione “Projetos”
3. Clique no ícone de membros
4. Selecione o membro cuja função pretende alterar
5. Faça duplo clique na função atual do membro na coluna “Role”
6. Selecione a função pretendida
7. Clique em “Update”


## Gerir variáveis do projeto

Ao executar um projeto ou fluxo de trabalho, pode ser útil definir variáveis para tarefas recorrentes, de modo a reduzir a confusão e poupar tempo. Estas variáveis funcionam como uma variável algébrica normal, permitindo definir o que a variável representa e que operação deve seguir-se-lhe. O PlaidCloud permite definir estas variáveis ao nível do projeto, o que afeta todos os fluxos de trabalho desse projeto, ou ao nível do fluxo de trabalho, o que afeta apenas esse fluxo de trabalho específico.

Para definir uma variável ao nível do projeto:

1. Abra o Analyze
2. Selecione “Projetos”
3. Clique no ícone Manage Project Variables

Na tabela de variáveis, pode ver as variáveis e ver/editar os valores atuais. Pode também adicionar novas variáveis ou eliminar as existentes ao clicar no botão “New Project Variable”.


## Copiar um projeto

**Copiar projeto** copia um projeto — na íntegra ou apenas as partes que escolher — para um projeto totalmente novo ou para um projeto que já exista.

Para copiar um projeto:

1. Abra o Analyze
2. Selecione "Projetos"
3. Selecione o projeto que pretende copiar
4. Clique no botão **Ações** e escolha **Copiar projeto**
5. Escolha o destino, selecione o que levar e a quantidade de dados, e clique em **Copiar projeto**
6. Verifique o resumo **Rever antes de copiar** e clique em **Iniciar cópia**

### Escolher o que copiar

A árvore de seleção lista o que o projeto contém, por tipo — fluxos de trabalho, passos, tabelas, dimensões, editores de dados, funções definidas pelo utilizador. Deixe tudo assinalado para copiar o projeto inteiro ou assinale apenas as partes pretendidas.

Não precisa de determinar de que dependem essas partes. Tudo o que assinalar traz consigo as suas dependências: as tabelas que um passo lê e escreve, as dimensões que carrega ou em relação às quais aloca, as funções definidas pelo utilizador que chama e qualquer subfluxo de trabalho ou macro que invoca. Os sensores de um fluxo de trabalho acompanham o fluxo de trabalho.

**Os sensores copiados chegam desativados.** Nada é acionado na cópia até ativar cada sensor no projeto de destino. Uma importação que substitui itens duplicados não adiciona um segundo sensor quando o fluxo de trabalho de destino já o tem.

### Copiar para um novo projeto

Dê ao novo projeto um nome e um ID. O ID passa a ser o nome do seu esquema e não pode ser alterado posteriormente.

**Os agendamentos chegam em pausa.** Quando copia um projeto inteiro para um novo, os eventos agendados de cada fluxo de trabalho chegam em pausa, para que a cópia não comece a executá-los por si própria. Quando a cópia termina, uma mensagem lista os eventos que estavam ativos no original. Para executar um na cópia, selecione-o em **Ferramentas** > **Agendador de eventos** e clique em **Ativar selecionados** — consulte [Colocar um evento em pausa](/pt-pt/administration/scheduled-events/event-scheduler/#pausar-um-evento).

### Copiar para um projeto existente

Escolha o destino na lista de projetos. A cópia acrescenta ao projeto em vez de o substituir.

**Tem de poder alterar o destino.** Uma cópia para um projeto em que não tem qualquer função é recusada, tal como uma cópia para um projeto que foi bloqueado para impedir alterações — verificado antes de ser lido ou escrito o que quer que seja, pelo que uma cópia recusada deixa o destino intacto. Um projeto também não pode ser copiado para si próprio.

**Copiar um projeto que restringe linhas exige um Arquiteto do projeto.** A cópia é um novo projeto sem restrição de [acesso a linhas](/pt-pt/administration/access/managing-security-groups-and-assignments/#gerir-o-acesso-a-linhas), e a cópia informa-o disso: “This copy is not row-restricted.” Configure o Acesso a linhas na cópia antes de a partilhar. Copiar para um projeto existente que restringe linhas exige igualmente um dos seus Arquitetos ou um administrador do tenant.

**O destino mantém as suas próprias definições.** O seu nome, ID, ambiente de ligação de dados, predefinições de armazenamento, conta de documentos, tipo de acesso, listas de acesso e concessões de acesso a linhas são todos deixados como estão. Apenas o conteúdo que selecionou é trazido.

Um passo definido como **Project Default** leva essa definição consigo, e não uma conta — depois de copiado, resolve para a predefinição que o projeto de destino tem, e não para a que tinha na origem.

Quando um item recebido é o mesmo item que já existe no destino, escolhe o que acontece:

- **Substituir itens duplicados pelos dados recebidos** — a versão recebida substitui a que está no destino.
- **Criar nova cópia dos itens duplicados** — o destino mantém o que tem e o item recebido é adicionado ao lado, com ` copy` acrescentado ao nome, e um contador se esse nome também já existir.

As variáveis de projeto e de fluxo de trabalho são a exceção a *Criar nova cópia*: uma variável é identificada pelo seu nome, pelo que não há forma de adicionar uma segunda cópia sem a renomear para algo a que nada faz referência. Quando o destino já define uma variável que a cópia também transporta, o valor do próprio destino é mantido e a cópia indica as variáveis que deixou intactas. *Substituir* trata as variáveis como tudo o resto e substitui-as.

Esta correspondência é feita por identidade, não por nome — um item que veio originalmente do mesmo projeto é reconhecido como o mesmo item, ao passo que dois itens que apenas partilham o mesmo nome são tratados como itens diferentes e ambos estarão presentes depois.

### Escolher a quantidade de dados a copiar

| Modo | O que é copiado |
| --- | --- |
| **Apenas estrutura** | Tabelas, passos e o resto da seleção, sem linhas. |
| **Dados completos** | As linhas de todas as tabelas, no mesmo lakehouse e entre lakehouses. |
| **Amostra** | Até ao número de linhas que introduzir de cada tabela, apenas para um projeto novo. O número pode ir de 1 a 1.000.000. |

Uma tabela de amostra contém até esse número de linhas, ou todas as suas linhas quando tem menos.

### Rever a cópia

Antes de copiar o que quer que seja, **Rever antes de copiar** resume a cópia: o projeto de origem, o destino, o modo de dados, o número de tabelas e vistas, o tamanho, uma estimativa de tempo, o lakehouse de origem e de destino e quaisquer avisos em **Tenha em atenção**. Clique em **Iniciar cópia** para começar ou em **Cancelar** para voltar atrás e alterar a seleção.

### Quem pode ver a cópia

Uma cópia feita com dados é privada para a pessoa que a fez. Partilhe-a a partir do novo projeto quando estiver pronto. Uma cópia de um projeto com segurança ao nível da linha permanece privada pelo mesmo motivo.

Copiar dados para um projeto existente exige acesso de escrita a esse projeto.

### Resultados da cópia

Quando a cópia termina, uma janela **Resultados da cópia** lista o resultado de cada tabela por nome, com o motivo de qualquer tabela que tenha falhado. Clique em **Tentar novamente as tabelas com falha** para copiar novamente apenas essas tabelas; o conteúdo de uma tabela repetida é substituído. É notificado, por mensagem e por correio eletrónico, quando uma cópia termina ou falha, e pode reabrir os resultados a partir da mensagem, ou mais tarde, ao selecionar a cópia no separador **Projetos** e escolher **Ver resultado da importação ou cópia** no menu **Ações**.

Os resultados permanecem na cópia até que alguém os dispense. Depois de a cópia ter terminado, clique em **Dispensar resultado** para os remover para todos os que podem abrir o projeto. Nada no projeto muda, mas as suas tabelas com falha deixam de poder ser repetidas a partir da janela. Dispensar exige acesso de edição ao projeto, e o projeto não pode estar bloqueado.

### Atualizar referências

Os passos de fluxo de trabalho de um projeto referem tabelas e outros objetos dentro desse projeto. **Atualizar referências** reescreve essas referências para que apontem para a cópia e não para o original — o que é quase sempre o pretendido e é o motivo pelo qual está ativado por predefinição. Desativá-lo deixa os passos copiados a apontar para o projeto de onde vieram.

<Aside>A cópia é executada em segundo plano. Uma caixa de diálogo de progresso mostra a cópia a avançar pelas suas fases; pode clicar em **Executar em segundo plano** para a dispensar e continuar a trabalhar — a lista de projetos é atualizada automaticamente e é notificado quando a cópia termina.</Aside>

## Ver o relatório do projeto

Quando um projeto ou fluxo de trabalho é dinâmico, manter documentação detalhada torna-se um desafio. Para ajudar a resolver este problema, o PlaidCloud permite gerar um relatório ao nível do projeto que fornece documentação detalhada dos fluxos de trabalho, passos de fluxo de trabalho, transformações definidas pelo utilizador, variáveis e tabelas. Este relatório é gerado a pedido e reflete o estado atual do projeto.

Para transferir o relatório:

1. Abra o Analyze
2. Selecione “Projetos”
3. Clique no ícone de relatório
