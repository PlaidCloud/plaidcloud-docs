*~25 minutos · um histórico de versões, uma comparação, uma ligação partilhada*

Quando várias pessoas trabalham no mesmo projeto, as perguntas que importam no primeiro dia são sempre as mesmas: *O que mudou? Consigo recuperar um estado anterior? Como passo uma alteração de um projeto para outro? Como envio um colega diretamente para aquilo que estou a ver?* O PlaidCloud responde às quatro de origem — o trabalho é **versionado, comparável e partilhável**, e este tutorial acompanha cada uma delas.

A mensagem a reter: nada se perde. Todas as alterações são registadas, quaisquer dois projetos podem ser comparados e todos os ecrãs têm uma ligação.

## O Que Vai Fazer

1. Consultar o histórico automático de alterações de um projeto e ler o respetivo registo.
2. Comparar dois projetos e compreender o que faz uma fusão.
3. Organizar o trabalho com etiquetas para o voltar a encontrar.
4. Copiar uma ligação direta que leva um colega a um local exato.

## Pré-requisitos

- Uma área de trabalho PlaidCloud e um projeto que possa abrir.
- Um segundo projeto — uma cópia ou um equivalente de QA/Produção — se quiser experimentar a comparação com conteúdo real. Um [projeto copiado](/pt-pt/guides/projects/managing-projects/#copiar-um-projeto) funciona bem.

## Parte 1: O Trabalho É Versionado

Tudo o que constrói num projeto é registado por si — não precisa de ativar esta funcionalidade.

> **Nada se perde.** Todas as alterações a um projeto — fluxos de trabalho, editores de dados, hierarquias, estruturas de tabelas e funções definidas pelo utilizador — são registadas e permitem a **recuperação do estado num ponto no tempo**. Isto significa que uma alteração acidental pode ser recuperada e qualquer ponto anterior pode ser copiado para comparação.

Além desse registo automático, os projetos e os seus elementos suportam **versionamento**: criar uma versão é fácil e pode **fundir alterações de uma versão noutra**. É uma forma simples de manter instantâneos, ou de desenvolver numa versão e fundir essas alterações na versão de não desenvolvimento quando estiver pronto.

### Ler o Registo do Projeto

O Registo do projeto consolida todos os registos individuais de fluxos de trabalho numa vista abrangente da atividade do projeto — membros atribuídos, fluxos de trabalho executados e mais.

1. Abra **Analyze**.
2. Selecione **Projetos**.
3. Abra o separador **Registo** (o registo do projeto).

Para restringir um registo muito movimentado, use o controlo de filtro junto às mensagens do registo e escolha os critérios de filtragem. Para ler uma entrada na íntegra, clique nela com o botão direito do rato e consulte a caixa **Mensagem de registo**.

> **Limpar o registo elimina também os sub-registos.** O botão **Limpar registo** remove o Registo do projeto *e* o sub-registo de cada fluxo de trabalho que lhe está associado. Limpe-o apenas quando pretender mesmo eliminar esse histórico.

## Parte 2: Comparar Dois Projetos

A comparação permite ver exatamente o que difere entre dois projetos e, nas partes que podem ser copiadas em segurança, fundir alterações selecionadas de um para o outro. Adequa-se a duas situações do dia a dia: **promover alterações entre ambientes** (um projeto de QA para o seu equivalente de Produção) e **rever face a uma cópia anterior** (um clone mês a mês, para ver o que mudou).

Mantém o controlo em todo o processo — nada é escrito até selecionar itens específicos e aplicá-los, e pode validar primeiro com uma execução de teste.

### Abrir uma Comparação

1. Abra **Analyze** e selecione **Projetos**.
2. Clique com o botão direito do rato no projeto de que pretende partir (ou use o respetivo menu de ações) e escolha **Comparar com...**.
3. O projeto de que partiu fica preenchido como **Origem**. Escolha o **Destino** na lista pendente.
4. Clique em **Comparar**.

Ambos os projetos têm de estar na mesma área de trabalho. Use **Trocar** para inverter a Origem e o Destino antes de comparar — a direção importa, porque uma fusão copia *da* Origem *para* o Destino.

### Ler a Comparação

O lado esquerdo agrupa todas as diferenças na respetiva categoria — **Fluxos de trabalho** (com **Passos** aninhados), **Variáveis**, **Dimensões**, **Editores**, **UDFs**, **Vistas** e **Tabelas**. Cada item tem um selo com o seu estado:

| Selo | Significado |
|---|---|
| **Adicionado** | Na Origem mas não no Destino — seria criado no Destino |
| **Modificado** | Em ambos, mas a configuração difere |
| **Eliminado** | No Destino mas não na Origem |
| **Inalterado** | Idêntico dos dois lados (oculto por predefinição) |

Selecione um item alterado para ver à direita uma tabela **Campo / Origem / Destino**, com a **Diferença de configuração** completa por baixo. Filtre por nome ou caminho, ou alterne as caixas de seleção de estado, para focar uma lista longa.

### Compreender o Que a Fusão Faz

Nem todas as diferenças podem ser copiadas em segurança, por isso a comparação identifica cada item:

- **Fluxos de trabalho, Passos e Variáveis** podem ser fundidos.
- **Dimensões, Editores, UDFs, Vistas e Tabelas** são **só de leitura** — reveja-os aqui, mas copie-os com as respetivas ferramentas dedicadas.

Para fundir, selecione os itens fundíveis, clique em **Execução de teste** para validar sem escrever, depois em **Aplicar** e confirme. Os itens fundidos mantêm a sua identidade no Destino, pelo que pode comparar novamente mais tarde e fundir mais alterações sem criar duplicados.

> **Uma fusão altera o Destino.** Reveja as diferenças, execute um teste e confirme que a Origem e o Destino estão no sentido certo antes de aplicar. Se outra pessoa editou o Destino depois de ter carregado a comparação, a fusão pára em vez de substituir o trabalho dessa pessoa — atualize e volte a aplicar.

Para promover Dev → QA → Produção entre projetos copiados uns dos outros, consulte [Voltar a sincronizar a partir do projeto de que copiou](/pt-pt/guides/projects/compare-and-merge-projects/#voltar-a-sincronizar-a-partir-do-projeto-de-que-copiou), que emparelha os itens pela sua linhagem de cópia em vez de pelo nome.

## Parte 3: Organizar com Etiquetas

As **Etiquetas** são marcadores livres que associa a objetos — o próprio projeto, os respetivos fluxos de trabalho, passos, tabelas, dimensões, editores de dados e UDFs. Use-as para agrupar itens relacionados segundo o que for importante para si (uma fase do trabalho, um sistema de origem, um responsável, uma versão) e voltar a encontrá-los depressa.

Todos os objetos etiquetáveis têm uma caixa **Etiquetas** no respetivo painel de detalhes:

1. Clique em qualquer ponto da caixa **Etiquetas** para colocar o cursor.
2. Escreva o texto da etiqueta.
3. Prima **Enter** (ou escreva uma vírgula) para a adicionar.

Remova uma etiqueta com o **×** no respetivo marcador ou prima **Backspace** com o campo de entrada vazio para eliminar a última.

> **As etiquetas são guardadas em minúsculas.** O PlaidCloud converte cada etiqueta para minúsculas automaticamente e recusa duplicados no mesmo objeto. Mantenha o seu conjunto consistente e passa a ser uma forma leve de segmentar um projeto grande.

Para encontrar itens etiquetados, escreva a etiqueta na caixa de filtro de uma lista do projeto — a pesquisa corresponde ao texto das etiquetas e ao nome do item.

## Parte 4: Partilhar uma Ligação Direta

O PlaidCloud mantém a barra de endereço em sintonia com o que tem aberto. Abra um fluxo de trabalho, uma tabela ou uma dimensão e o URL passa a ser uma **ligação direta** para esse objeto. Não existe um botão de partilha separado — a barra de endereço *é* a ligação.

1. Abra o objeto que pretende partilhar.
2. Copie o URL completo da barra de endereço do navegador.
3. Envie-o — quem o abrir chega ao mesmo ecrã.

As ligações começam pelo projeto: primeiro o projeto, depois o objeto dentro dele, separados por `~`.

| Ecrã | A ligação termina com |
|---|---|
| Projeto | `#p~<project>` |
| Fluxo de trabalho (grelha de Passos) | `#p~<project>~w~<workflow>` |
| Fluxo de trabalho (área de desenho do Estruturador visual de fluxos de trabalho) | `#p~<project>~c~<workflow>` |
| Um passo dentro de um fluxo de trabalho | `…~w~<workflow>~s~<step>` |
| Explorador de tabelas | `#p~<project>~t~<table>` |
| Hierarquia da dimensão | `#p~<project>~d~<dimension>` |
| Editor de dados | `#p~<project>~e~<editor>` |

Abrir uma ligação restaura o **contexto superior**, não apenas a janela em causa: uma ligação para um fluxo de trabalho volta a abrir também o respetivo projeto, pelo que o destinatário chega com o projeto envolvente na barra de separadores. Uma ligação para um passo seleciona até o passo por si.

> **Uma ligação transporta a *localização*, não a permissão.** Quem a abrir continua a precisar de acesso ao projeto. Quem não tiver acesso não verá o objeto — por isso partilhar uma ligação é seguro. Controle quem pode ver o quê em [Controlar o acesso a dados](/pt-pt/get-started/tutorials/control-data-access/).

As ligações antigas no estilo `#te?p=…&t=…` continuam a funcionar e reescrevem-se discretamente para a forma atual, mais legível, na primeira navegação.

**Nada se perde — e agora pode demonstrá-lo.** Leu o histórico de um projeto, comparou dois projetos e fundiu-os em segurança num único sentido, organizou o trabalho com etiquetas para o voltar a encontrar e entregou a um colega uma ligação direta que o leva exatamente onde está.
