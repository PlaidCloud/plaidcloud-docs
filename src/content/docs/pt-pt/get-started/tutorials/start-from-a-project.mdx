*~15 minutos · copiar ou importar um projeto e depois torná-lo seu*

A vitória mais rápida no primeiro dia do PlaidCloud não é construir do zero — é começar a partir de algo que já funciona. Escolha um projeto que já importa dados, os transforma e produz um resultado, obtenha a sua própria cópia e altere as partes que são suas.

Não há uma galeria de modelos para explorar. Em vez disso, tem duas formas concretas de começar a partir de um projeto funcional:

- **Copiar um projeto** que já existe na sua área de trabalho para um projeto novo, só seu — [Copiar um projeto](/pt-pt/guides/projects/managing-projects/#copiar-um-projeto).
- **Executar um pacote portátil** — um projeto que alguém exportou como um pacote autónomo em [formato portátil](/pt-pt/guides/projects/export-to-portable-format/), que é executado por si só fora do PlaidCloud.

Qual escolher depende do seu destino.

| Pretende… | Utilize | Resultado |
|---|---|---|
| Construir sobre um projeto dentro do PlaidCloud e continuar a iterar | **Copiar projeto** | Um projeto novo que é seu, pronto para editar e executar |
| Executar a lógica de um projeto offline, ou entregá-lo a alguém sem início de sessão no PlaidCloud | **Exportar para formato portátil** | Um pacote autónomo de Python + DuckDB |

## Pré-requisitos

- Uma área de trabalho PlaidCloud ([comece uma avaliação gratuita](https://app.plaidcloud.com) se ainda não tiver uma).
- Para o **Caminho A**: um projeto existente que consiga ver no separador **Projetos** — um seu, um exemplo partilhado ou qualquer um a que um colega lhe tenha dado acesso.
- Para o **Caminho B**: um `.zip` em formato portátil que alguém tenha exportado, ou um projeto seu para exportar.

> **Não tem a certeza do que é um projeto?** Um projeto é a unidade de trabalho no PlaidCloud — tem os seus próprios dados, fluxos de trabalho, dimensões e histórico, e não partilha estado com nenhum outro projeto. Leia primeiro [Projetos](/pt-pt/guides/projects/) se isto for novo para si.

## Caminho A: Copiar um projeto existente

Copiar cria um duplicado completo e editável — de tudo, ou apenas das partes que escolher — num projeto novo que é inteiramente seu.

1. Abra **Analisar** e selecione o separador **Projetos**.
2. Selecione o projeto a partir do qual pretende começar.
3. Clique no botão **Ações** e escolha **Copiar projeto**.
4. Escolha **um projeto novo** como destino. Atribua-lhe um nome e um **ID**.
5. Deixe a árvore de seleção totalmente assinalada para trazer o projeto inteiro e depois clique em **Copiar projeto**.

> **O ID é permanente.** O ID que atribui ao projeto novo torna-se o nome do seu esquema e não pode ser alterado mais tarde. Escolha algo com que se sinta bem a viver — o nome pode ser alterado a qualquer momento, o ID não.

A cópia é executada em segundo plano; é notificado quando termina. Consulte [Copiar um projeto](/pt-pt/guides/projects/managing-projects/#copiar-um-projeto) para ver a caixa de diálogo completa.

### Traga apenas as partes que quer

Não tem de copiar tudo. A árvore de seleção lista o que o projeto contém por tipo — fluxos de trabalho, passos, tabelas, dimensões, editores de dados, funções definidas pelo utilizador — e pode assinalar apenas as partes que quer. Tudo o que assinalar traz consigo as suas dependências automaticamente: as tabelas que um passo lê e escreve, as dimensões em relação às quais carrega, as funções que chama e qualquer subfluxo de trabalho que invoque. Nunca tem de descobrir essas dependências por si.

> **Mantenha as referências a apontar para a sua cópia.** Deixe **Atualizar referências** ativado (a predefinição). Reescreve os passos copiados para que apontem para as tabelas e objetos do seu projeto novo em vez de voltarem ao original — quase sempre o que pretende. Desative-o apenas se quiser deliberadamente que a cópia continue a ler os objetos do projeto de origem.

## Caminho B: Começar a partir de um pacote portátil

Um pacote portátil é um projeto empacotado como um programa Python autónomo que é executado em [DuckDB](https://duckdb.org) sem qualquer ligação ao PlaidCloud. É a forma de começar a partir de um projeto funcional quando quer que seja executado *fora da plataforma* — no seu portátil, numa tarefa de CI ou nas mãos de alguém sem início de sessão no PlaidCloud.

Se um colega já lhe entregou um pacote, avance para [Executá-lo](#executá-lo). Para criar um por si:

1. Abra **Analisar** e selecione o separador **Projetos**.
2. Selecione um único projeto.
3. Abra o menu **Ações** e escolha **Exportar para formato portátil**.
4. Defina a **Conta de documentos** e o **Caminho da pasta** para onde o pacote é escrito, deixe **Include data** marcado para que seja executado sem qualquer origem externa e clique em **Exportar**.

O resultado é um `.zip` que contém um script Python por fluxo de trabalho, os instantâneos de dados em Parquet, um `requirements.txt` com os pacotes Python de que os scripts precisam e um `README.md`, um `COVERAGE.md` e um `RUN_ORDER.md`. Consulte [Exportar para formato portátil](/pt-pt/guides/projects/export-to-portable-format/) para saber o que é cada ficheiro.

> **Um pacote portátil é um instantâneo unidirecional, não uma reimportação.** É executado *fora* do PlaidCloud e não sincroniza de volta — as alterações que fizer ao pacote não regressam ao projeto, e voltar a exportar após edições produz um pacote novo. Para continuar a trabalhar dentro do PlaidCloud, utilize antes o **Caminho A**. Para continuar a iterar no PlaidCloud *e* distribuir uma cópia executável, faça ambos.

> **A fidelidade é feita com o melhor esforço.** Os passos de transformação SQL são reproduzidos exatamente. Os passos proprietários e com efeitos secundários — alocações, carregamentos de dimensões, notificações, passos de documentos e relatórios, scripts — são exportados como marcadores que não voltam a ser executados; em vez disso, o seu último resultado materializado é incluído como instantâneo. A fidelidade de cada passo fica registada em `COVERAGE.md`. Para resultados totalmente recalculados, execute o projeto no PlaidCloud.

### Executá-lo

Descomprima o pacote, crie um ambiente Python e execute cada script de fluxo de trabalho pela ordem que `RUN_ORDER.md` indica:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python pipeline_<workflow>.py
```

Cada script cria as suas tabelas numa base de dados DuckDB local. Os passos SQL são recalculados em direto; os passos substituídos por marcadores deixam o respetivo resultado em instantâneo no lugar.

## Torne-o seu

Seja como for que tenha começado, a cópia é agora sua para alterar — é aqui que a vitória do primeiro dia compensa. Alguns primeiros movimentos:

| Faça isto | Onde |
|---|---|
| Aponte as importações para *os seus* dados em vez dos do exemplo | Os passos de importação de cada fluxo de trabalho — consulte [Carregar, transformar e publicar dados](/pt-pt/get-started/tutorials/load-and-transform-data/) |
| Mude o nome do projeto ou ajuste quem o pode abrir | [Gerir projetos](/pt-pt/guides/projects/managing-projects/) → Controlo de acesso |
| Defina variáveis de projeto para valores que se repetem entre fluxos de trabalho | [Gerir variáveis de projeto](/pt-pt/guides/projects/managing-projects/#gerir-variáveis-do-projeto) |
| Confirme que tudo continua a ser executado de ponta a ponta | Clique em **Executar** em cada fluxo de trabalho e acompanhe o registo |

Como todas as alterações são registadas, pode experimentar à vontade — o [controlo automático de alterações](/pt-pt/guides/projects/managing-projects/#histórico-de-versões) permite-lhe recuperar qualquer estado anterior se uma edição correr mal.
