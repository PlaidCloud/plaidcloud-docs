*~20 minutos · um passo com falha, um diagnóstico de IA, uma correção aplicada*

Executa um fluxo de trabalho, um passo fica vermelho e o texto do erro, por si só, não lhe diz o que alterar. Este tutorial percorre esse momento exato: abre o **AI Assistant** integrado do PlaidCloud, deixa-o diagnosticar o passo com falha com base nos seus dados em direto, aprova a correção que ele propõe e volta a executar para confirmar. Depois utiliza o mesmo assistente para escrever um passo Extrair SQL a partir de uma descrição em linguagem corrente.

Este é o AI Assistant integrado no produto que o ajuda a criar e a corrigir fluxos de trabalho. **Não** é o mesmo que ligar um agente de programação com IA externo (Claude Code, Cursor, MCP) ao seu inquilino — esse caminho complementar encontra-se em [Ligar um agente de programação com IA](/pt-pt/get-started/tutorials/mcp-with-ai-agent/).

## O que vai fazer

| Fase | O que vai utilizar |
|---|---|
| Ver o passo falhar e ler o erro | O separador **Registo** do projeto |
| Diagnosticar e corrigir o passo com falha | O assistente de correção, no separador **AI Assistant** da entrada do registo |
| Confirmar a correção | Responder que sim quando o assistente se oferecer para voltar a executar o passo |
| Adicionar uma nova consulta sem escrever SQL | **Generate SQL with AI** num passo Extrair SQL |

## Pré-requisitos

- Uma área de trabalho do PlaidCloud ([inicie uma avaliação gratuita](https://app.plaidcloud.com) se não tiver uma) e um projeto que possa editar.
- Um fluxo de trabalho com pelo menos um passo — idealmente um que falhe, ou que consiga fazer falhar (um nome de coluna escrito incorretamente numa transformação basta para reproduzir o cenário).

> **O assistente corrige com as suas permissões.** Só pode alterar um passo que você próprio já poderia editar, e cada alteração que faz é reversível ao voltar a executá-lo ou ao editar o passo diretamente. Consulte [Corrigir erros de fluxos de trabalho com IA](/pt-pt/guides/ai-assistant/fixing-workflow-errors/).

## Passo 1: executar o fluxo de trabalho e encontrar o erro

Quando um passo falha, surge um indicador de erro tanto no fluxo de trabalho como no passo que falhou, e a falha é escrita no registo do fluxo de trabalho.

1. Abra o seu projeto e execute o fluxo de trabalho (ou o único passo que está a testar).
2. Mude para o separador **Registo** do projeto. O registo lista os eventos à medida que os passos são executados — incluindo avisos e erros.
3. Na lista do registo, selecione a entrada do passo que falhou. A mensagem completa — incluindo qualquer traceback — abre no painel à direita, no separador **Mensagem de registo**.

> **Não tem um fluxo de trabalho com problemas à mão? Crie um em 30 segundos.** Em qualquer passo de transformação, edite a expressão de uma coluna para referenciar uma coluna que não existe — por exemplo, altere `net_amount` para `net_amnt` — e guarde. Execute o passo e este falha com um erro no registo a dizer que a coluna `net_amnt` não existe. É uma configuração incorreta genuína que o assistente de correção foi concebido para detetar, pelo que é uma forma limpa de seguir este tutorial do princípio ao fim.

Para saber mais sobre como os erros surgem e as opções para os tratar, consulte [Gerir erros de passos](/pt-pt/guides/workflows/managing-step-errors/) e [Consultar o registo do fluxo de trabalho](/pt-pt/guides/workflows/viewing-workflow-log/).

## Passo 2: abrir o assistente de correção

O assistente de correção fica mesmo ao lado do erro em bruto, já direcionado para o passo que falhou.

1. Com a entrada de registo com falha selecionada, encontre o painel à direita que mostra **Mensagem de registo**.
2. Mude esse painel para o separador **AI Assistant**.

A conversa do **AI Assistant** abre já direcionada para o fluxo de trabalho e o passo de onde provém a entrada de registo selecionada, pelo que não tem de lhe indicar que passo falhou. Pode ler o erro em bruto em **Mensagem de registo** e conversar com o assistente em **AI Assistant**, lado a lado.

Para a maioria dos erros, começa a diagnosticar de imediato. Para alguns erros comuns, como uma expressão que refere uma coluna que não existe, a primeira resposta é, em vez disso, uma breve explicação que o PlaidCloud já tem para esse tipo de erro: o que costuma causá-lo, que palavras da mensagem de erro observar e como corrigi-lo. Essa explicação não analisa o seu passo. Responda — por exemplo, *"Verifique este passo e corrija-o"* — e o assistente continua a partir daí. Consulte [Erros comuns](/pt-pt/guides/ai-assistant/fixing-workflow-errors/#erros-comuns).

## Passo 3: deixá-lo diagnosticar e propor uma correção

O assistente trabalha por uma ordem fixa e nada é guardado até que o autorize:

1. **Diagnostica** — lê a configuração do passo com falha e as tabelas e colunas que ele utiliza, verificando as suas conclusões com os seus dados em vez de adivinhar apenas a partir do texto do erro.
2. **Propõe** — se encontrar uma configuração incorreta genuína, mostra a configuração corrigida do passo e explica claramente o que alterou e porquê. Nesta fase nada é escrito.
3. **Aprova** — aguarda o seu consentimento explícito. Uma resposta ambígua não é considerada aprovação.
4. **Aplica** — depois de aprovar, escreve a configuração corrigida no passo, através do mesmo caminho que o editor de passos utiliza.
5. **Oferece uma nova execução** — pergunta se pretende voltar a executar o passo agora. Responda que sim e ele executa o passo e diz-lhe se a correção funcionou.

Leia a alteração proposta antes de a aprovar. O assistente repara a configuração do único passo de onde veio o erro — por exemplo, um nome de coluna ou de função escrito incorretamente, uma expressão inválida, um tipo de dados ou conversão errados, ou SQL malformado — e altera o mínimo que corrige o erro.

> **É honesto sobre o que não consegue corrigir.** A sua única alavanca é a configuração desse passo. Não cria, elimina nem reordena passos, não edita outro passo nem altera os seus dados. Muitas falhas não são de todo problemas de configuração — dados de origem em falta ou malformados, um passo a montante que falhou primeiro, um erro transitório ou de infraestrutura, um problema de permissões ou lógica defeituosa dentro de uma transformação ou UDF. Nesses casos, explica o que encontrou e indica-lhe onde está a correção real, em vez de forçar uma edição para parecer uma solução.

## Passo 4: aprovar e voltar a executar

1. Quando a configuração proposta lhe parecer correta, confirme a alteração explicitamente. O assistente aplica-a ao passo.
2. Quando o assistente perguntar se deve voltar a executar o passo, responda que sim. Executa o passo e diz-lhe se teve êxito ou se falhou novamente. Também pode voltar a executar o passo, ou o fluxo de trabalho, por si.

Se o assistente lhe disse que a causa está fora da configuração do passo — dados incorretos, uma falha a montante, um problema de permissões —, essa é a resposta. Corrija-a onde ela realmente está, em vez de pedir ao assistente que edite o passo na mesma.

> **Os avisos são muitas vezes benignos.** Se a entrada do registo for um aviso e não uma falha grave, o assistente dirá muitas vezes que não é necessária qualquer alteração, em vez de inventar uma edição. É um resultado válido, não um beco sem saída.

## Passo 5: gerar um passo Extrair SQL com IA

Agora utilize o mesmo assistente de base para acrescentar trabalho novo, e não apenas para reparar. O passo **Extrair SQL** executa um `SELECT` só de leitura e escreve o resultado numa nova tabela — e o editor do passo pode escrever essa consulta por si.

1. Na vista **Passos** do fluxo de trabalho, clique em **Criar passo** e escolha **Tabelas → Extrair SQL** ou **AI → SQL Extract (AI Assisted)**. Ambos abrem o mesmo editor, que inclui um painel **Generate SQL with AI** no topo da página Parâmetros de extração SQL.
2. **(Opcional) Escolha as tabelas de origem.** Na lista **Tabelas de origem**, selecione uma ou mais tabelas de onde a consulta deve ler. Deixe-a vazia para que o Assistant examine o projeto e escolha ele próprio as tabelas relevantes.
3. **Descreva o que pretende.** Na caixa **Descrever**, escreva o resultado pretendido em linguagem corrente — por exemplo, *"classificar cada conta do razão num conjunto de atividade com base no intervalo do número da conta"*.
4. **Clique em Gerar SQL.** O Assistant escreve um único `SELECT` só de leitura, valida-o executando-o e preenche o editor **Consulta SQL Select** e a página de mapeamento **Seleção de dados da tabela** com as colunas detetadas. Se deixou a lista de origem vazia, as tabelas que escolheu ficam selecionadas na lista para que veja o que utilizou.

> **Não há nada a configurar.** Isto utiliza o mesmo modelo integrado que o AI Assistant utiliza — não precisa de configurar um agente de IA nem uma ligação LLM por área de trabalho para isso.

## Passo 6: rever e guardar o passo

O SQL gerado é um ponto de partida, não uma caixa negra.

1. **Edite-o livremente.** O editor de SQL é totalmente editável — refine a consulta, adicione uma junção ou altere a lista de colunas antes de guardar.
2. **Escolha uma tabela de destino.** Escolha ou dê um nome à **Tabela de destino** onde o passo escreve o resultado.
3. **Guarde o passo.** É guardado como um passo Extrair SQL vulgar e é executado como parte do fluxo de trabalho, como qualquer outro.

O Assistant escreve apenas instruções `SELECT` só de leitura — nunca `INSERT`, `UPDATE`, `DELETE` ou outro SQL que altere dados. A geração apenas cria rascunhos e pré-visualizações; o passo é criado quando o guarda e é executado quando o fluxo de trabalho é executado. Se uma consulta gerada não for executada, o editor mostra o SQL juntamente com o erro, para que a possa corrigir — ou ajustar a sua descrição e gerar novamente. Todos os pormenores em [Gerar passos de extração SQL com IA](/pt-pt/guides/ai-assistant/generate-sql-extract/).

**Esta é a ajuda do assistente.** Diagnosticou um passo com falha com base em dados em direto, aprovou e aplicou a correção da IA, confirmou-a com uma nova execução e gerou um passo Extrair SQL funcional a partir de uma frase em linguagem corrente — o mesmo assistente a reparar o que está avariado e a construir o que é novo.
