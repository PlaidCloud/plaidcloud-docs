*~30 minutos · uma verificação de prontidão, uma importação, uma execução validada*

Migre um fluxo de trabalho Alteryx para o PlaidCloud de ponta a ponta: verifique se está pronto, importe-o e converta-o, veja o que foi convertido sem problemas e o que requer atenção, e execute-o. Esta é uma primeira migração pensada para criar confiança — não uma visita exaustiva. Escolha um fluxo de trabalho que conheça bem e, idealmente, para o qual tenha uma saída correta conhecida, para poder confirmar que a execução convertida está certa.

O importador do PlaidCloud preserva o grafo do fluxo de trabalho, carrega os ficheiros referenciados para Documentos, gera fluxos de trabalho de macros e mapeia cada ferramenta Alteryx para um passo de fluxo de trabalho nativo ou para um executor gerido. A maior parte de um fluxo de trabalho converte-se com pouco esforço manual — e a parte franca deste tutorial é o resto: algumas ferramentas requerem atenção, e o PlaidCloud indica exatamente quais, para que possa ir diretamente a elas.

## Pré-requisitos

- Uma área de trabalho PlaidCloud e um projeto para onde importar. Utilize um projeto de migração dedicado para que as dependências sejam fáceis de auditar.
- Um ficheiro de fluxo de trabalho Alteryx — `.yxmd` (fluxo de trabalho), `.yxwz` (aplicação analítica) ou `.yxmc` (macro).
- Os ficheiros que esse fluxo de trabalho lê em tempo de execução, guardados juntamente com ele.
- Uma conta de documentos e uma pasta onde o PlaidCloud possa guardar os ficheiros importados.

## Passo 1: Verificar a prontidão

Uma importação limpa começa com um pacote completo. Reúna tudo o que o fluxo de trabalho utiliza antes de abrir o importador:

1. O próprio ficheiro do fluxo de trabalho, mais as macros que chama — incluindo macros aninhadas — como ficheiros `.yxmc`.
2. Ficheiros de dados de entrada: CSV, TSV, Excel, Access, YXDB, XML, JSON e extrações de bases de dados.
3. Ficheiros auxiliares espaciais guardados na mesma pasta — grupos de shapefile (`.shp`, `.shx`, `.dbf`, `.prj`), grupos MapInfo (`.tab`, `.map`, `.id`, `.dat`) e quaisquer ficheiros de projeção. A falta de ficheiros auxiliares é uma causa frequente de diferenças espaciais.
4. Os recursos de relatório que o fluxo de trabalho referencia: imagens, PDF, modelos e camadas de mapa.
5. Para uma aplicação analítica, os valores que os utilizadores normalmente introduzem — texto, números, datas, seleções de ficheiros e pastas, e seleções em listas pendentes ou caixas de verificação. Estes tornam-se variáveis do fluxo de trabalho que definirá antes de uma execução.

Depois, decida duas coisas: a pasta de Documentos que guardará os ficheiros carregados e se vai validar este fluxo de trabalho de forma estrutural (converte-se e executa-se?) ou com saídas corretas conhecidas (produz os mesmos resultados?).

> **Leve a saída correta conhecida.** Se tiver um resultado fiável da execução no Alteryx, guarde-o com o pacote. É o que transforma "executou" em "está correto" no Passo 4.

A [lista de verificação de prontidão para a migração do Alteryx](/pt-pt/guides/workflows/alteryx-migration-readiness-checklist/) é a versão completa deste passo, para quando passar de um fluxo de trabalho para um portefólio.

## Passo 2: Importar e converter

1. Abra o projeto de destino no PlaidCloud.
2. Abra **Ferramentas → Importar fluxo de trabalho Alteryx**.
3. Escolha o projeto de destino e selecione o ficheiro `.yxmd`, `.yxwz` ou `.yxmc`.
4. Opcionalmente, defina prefixos para os nomes do fluxo de trabalho, dos passos e das tabelas. Os nomes das tabelas já têm como prefixo o nome do próprio fluxo de trabalho, pelo que um único fluxo de trabalho não precisa de um prefixo próprio.
5. Escolha a conta de documentos e a pasta para os ficheiros importados.
6. Adicione quaisquer ficheiros ou pastas referenciados de que o fluxo de trabalho precise em tempo de execução.
7. Inicie a importação.

Quando a importação termina, a janela substitui o formulário por um **relatório de conversão**: quantos passos foram mapeados com confiança elevada, quantos requerem revisão e — quando existem — uma tabela que identifica cada passo de confiança inferior, a sua operação, a sua confiança e notas. Este relatório é o cerne da migração. Cada passo assinalado também tem a mesma nota no memorando do passo na área de desenho, para que possa ir diretamente a ele.

O PlaidCloud guarda as dependências importadas na pasta de Documentos que escolheu e aponta os passos convertidos para esses caminhos, de modo que o fluxo de trabalho é executado de forma repetível sem um sistema de ficheiros de ambiente de trabalho.

> **Os comentários e os contentores acompanham a conversão.** As caixas de comentário chegam como notas e caixas de destaque, e os Tool Containers tornam-se grupos — explicam o fluxo de trabalho exatamente como no Alteryx e não acrescentam trabalho em tempo de execução. A barreira de um **Control Container** também é preservada: os seus passos são importados já configurados para serem executados apenas quando os dados controlados têm linhas.

## Passo 3: Rever o que foi convertido e o que requer atenção

Abra o fluxo de trabalho avançado gerado e percorra o relatório de conversão de cima para baixo. A maioria dos passos converte-se com confiança elevada e não requer nada da sua parte. Os assinalados são onde uma primeira migração ganha credibilidade — leia cada nota e decida.

Esta é a forma franca de uma conversão parcial e o que significa cada caso:

| O que vê | O que significa | O que fazer |
|---|---|---|
| Passo de confiança elevada | Mapeado sem problemas para um passo nativo ou para um executor | Nada — verifique por amostragem, se quiser |
| Passo assinalado para revisão | Convertido, mas com uma ressalva que vale a pena confirmar | Leia a nota; verifique o resultado face ao esperado |
| Passo marcado como não convertido | O importador recusou em vez de adivinhar mal | Corrija a causa no Alteryx e volte a importar, ou crie o passo manualmente |
| Uma referência a uma tabela que ainda não existe | Um conjunto de dados Calgary ou criado externamente que o fluxo de trabalho não gerou | Carregue a tabela indicada antes de executar |

Alguns avisos que é provável encontrar numa primeira migração:

- **Amostragem aleatória** (Create Samples, Random % Sample) mantém exatamente os tamanhos e as proporções, mas o PlaidCloud seleciona os seus próprios registos — valide-os pelas contagens e proporções, não por quais as linhas escolhidas.
- **Os modelos XGBoost** são convertidos num classificador de gradient boosting do scikit-learn; espere equivalência estatística, não valores idênticos, e consulte as notas do passo.
- **Um passo não convertido falha de propósito** quando o fluxo de trabalho chega a ele, de modo que uma conversão com uma barreira por resolver ou uma tabela em falta não pode ser executada como se nada estivesse errado. Esta franqueza é deliberada — é o importador a recusar-se a apresentar um número errado como certo.

> **Uma execução bem-sucedida não é automaticamente uma execução correta.** O relatório indica onde olhar; a validação no passo seguinte diz se deve confiar nos números. Não a ignore num fluxo de trabalho cuja saída outras pessoas utilizam.

Para o catálogo completo de como cada família de ferramentas é convertida, consulte a [matriz de conversão do Alteryx](/pt-pt/reference/alteryx-conversion-matrix/).

## Passo 4: Definir variáveis, executar e validar

1. Na área de desenho do fluxo de trabalho convertido, reveja os passos e os ramos gerados.
2. Defina quaisquer **variáveis do fluxo de trabalho** — são as perguntas da aplicação convertidas e os parâmetros de execução. Aponte as variáveis de ficheiros e pastas para os caminhos de Documentos do Passo 2 e faça corresponder os valores aos que utilizou na execução no Alteryx.
3. Clique em **Executar** no fluxo de trabalho (não num único passo) e acompanhe o registo à medida que cada passo é executado por ordem.
4. Reveja o histórico de execuções, as saídas dos passos e quaisquer notas de prontidão.

Depois, valide ao nível que escolheu no Passo 1:

- **Estrutural** — o fluxo de trabalho abriu, o grafo tem os ramos e as macros esperados, as entradas foram carregadas, as variáveis apareceram e a execução terminou. Suficiente para prontidão e inventário.
- **Paridade de saída** — compare o esquema, o número de linhas e os valores das linhas com a saída do Alteryx em que confia. A ordem das linhas é ignorada, a menos que o fluxo de trabalho ordene explicitamente. Verifique também o tratamento de nulos, a precisão numérica, as datas e a geometria, quando aplicável.

Se uma comparação diferir, analise as causas por ordem: ficheiros de entrada em falta ou diferentes, valores de variáveis diferentes, instantâneos de origem diferentes, depois diferenças de nulos/datas/arredondamento/ordenação e, por fim, referência espacial ou formato de geometria. Corrija a causa, execute novamente e compare outra vez. O [guia de validação](/pt-pt/guides/workflows/validate-converted-alteryx-workflows/) tem a lista de verificação completa.

> **Voltar a importar é seguro.** Corrigir um pacote e importá-lo novamente cria o seu próprio conjunto de tabelas em vez de substituir a primeira importação — elimine o fluxo de trabalho anterior e as respetivas tabelas quando estiver satisfeito com o novo.

## Migrou um fluxo de trabalho

Levou um fluxo de trabalho Alteryx desde uma verificação de prontidão até uma execução validada no PlaidCloud e — igualmente importante — já sabe ler o relatório de conversão para distinguir o que foi convertido sem problemas do que requer uma análise. Esse é todo o ciclo. Repita-o por fluxo de trabalho e, para um portefólio maior, migre em lotes para um projeto dedicado.
