*~15 minutos · iniciar sessão, orientar-se, executar o primeiro exemplo*

Esta é a sessão que todos os outros tutoriais pressupõem que já fez. Vai iniciar sessão, aprender onde ficam os projetos, os fluxos de trabalho, os dados e os painéis de controlo, e depois abrir um fluxo de trabalho pronto a usar, executá-lo e ver um resultado do outro lado. Ainda sem construir nada de raiz — isso é o [Início rápido](/pt-pt/get-started/quickstart/), que esta página complementa. Pense nisto como o mapa antes da viagem.

> **Vai precisar de uma área de trabalho.** Se não tiver uma, [inicie uma avaliação gratuita](https://app.plaidcloud.com) — é aprovisionada uma área de trabalho em poucos minutos. Tudo o que se segue acontece dentro dela.

## Como o PlaidCloud está organizado

Três palavras explicam quase tudo o que vai ver. A sua conta vive numa **organização** (a fronteira de faturação e identidade). Dentro dela existem uma ou mais **áreas de trabalho** — ambientes isolados onde o trabalho acontece de facto. Dentro de uma área de trabalho estão os **projetos**, e cada projeto possui as suas próprias tabelas, fluxos de trabalho, dimensões e histórico. Os projetos não partilham estado entre si.

O modelo de dados completo — ligações, vistas, dimensões, alocações — está descrito em [Conceitos](/pt-pt/get-started/concepts/). Não precisa de tudo hoje; as três palavras acima chegam para se orientar.

## Passo 1: iniciar sessão e conhecer o Iniciador

Abra o URL da sua área de trabalho (algo como `https://acme.plaid.cloud`) e inicie sessão — o seu URL exato consta do e-mail de boas-vindas ou de avaliação e também da página da sua organização. A primeira coisa a que chega é o **Iniciador** — uma única página de mosaicos que reúne aquilo com que mais trabalha, para que retome de onde ficou. A partir daqui, **Analyze** é a área da aplicação onde estão os seus projetos, fluxos de trabalho, tabelas e painéis de controlo; vai passar a maior parte desta sessão lá dentro.

O Iniciador está organizado em três faixas, de cima para baixo. Uma faixa só aparece quando tem algo para mostrar:

| Faixa | O que contém |
|---|---|
| **Requer atenção** | Fluxos de trabalho cuja execução mais recente falhou — os problemas surgem assim que chega |
| **Pinned** | Tudo o que marcou como favorito, pela ordem em que o fixou |
| **Recentes** | Projetos, painéis de controlo e aplicações Panel que abriu ou editou recentemente |

Numa área de trabalho nova, estas faixas estão quase vazias — é o esperado. À medida que trabalha, vão-se preenchendo. Os pormenores completos estão no [guia do Iniciador](/pt-pt/guides/launcher/).

> **Dois atalhos que vale a pena aprender já.** Prima **Ctrl/Cmd-K** em qualquer ecrã para abrir a paleta de comandos: lista o que abriu por último e as ações que pode executar e, à medida que escreve, pesquisa também projetos, fluxos de trabalho, tabelas, painéis de controlo e aplicações Panel. Clique na **estrela** de qualquer cartão para o fixar na faixa **Pinned**, para que nunca saia do alcance.

## Passo 2: orientar-se — onde ficam as coisas

Tudo no PlaidCloud vive dentro de um projeto, e um projeto apresenta o seu conteúdo em separadores. Vai voltar a estes constantemente:

| Onde | O que encontra |
|---|---|
| **Projetos** | Todos os projetos da área de trabalho; abra um para trabalhar dentro dele |
| **Fluxos de trabalho** | Os pipelines que importam, transformam e publicam dados |
| **Tabelas** | Os dados estruturados — linhas e colunas — que os fluxos de trabalho leem e escrevem |
| **Painéis de controlo** | Vistas interativas publicadas, construídas a partir de tabelas |
| **AI Assistant** | Uma conversa no âmbito do projeto para fazer perguntas sobre os seus dados e fluxos de trabalho |

O modelo mental a reter: um **fluxo de trabalho** é uma sequência de **passos**, cada passo lê de uma ou mais **tabelas** de origem e escreve numa tabela de destino — deixando os originais intactos. Um **painel de controlo** lê as tabelas que um fluxo de trabalho publica. É este o ciclo que vai ver vezes sem conta.

## Passo 3: abrir um exemplo pronto a usar

Em vez de construir já alguma coisa, abra algo que já funciona e veja-o a trabalhar.

1. A partir do **Iniciador** ou de **Analyze → Projetos**, abra um projeto. Se a sua área de trabalho de avaliação veio com um projeto de exemplo, abra esse — se o separador **Projetos** estiver vazio, nenhum foi disponibilizado, pelo que deve percorrer uma vez o [Início rápido](/pt-pt/get-started/quickstart/) para criar um pequeno projeto e fluxo de trabalho e depois voltar aqui. O resto desta página funciona da mesma forma em ambos os casos.
2. Mude para o separador **Fluxos de trabalho** dentro do projeto.
3. Faça duplo clique num fluxo de trabalho para abrir o **Workflow Explorer**. Vai ver os passos dispostos por ordem — importações à esquerda, transformações e publicações a fluir para a direita.
4. Clique num único passo para ver como está configurado: a tabela de origem, a tabela de destino e as opções. Não precisa de alterar nada — está a ler, não a editar.

> **Ler antes de executar é um bom hábito.** Percorrer os passos de um fluxo de trabalho antes de o executar diz-lhe que tabelas vai tocar e o que vai produzir — para que o resultado não seja uma surpresa.

## Passo 4: executá-lo e ver um resultado

Agora faça-o fazer alguma coisa.

1. No Workflow Explorer, clique em **Executar** no fluxo de trabalho inteiro (não apenas num passo).
2. Acompanhe o **registo** à medida que cada passo é executado por ordem. Cada linha indica que passo foi executado e se teve êxito.
3. Quando a execução terminar, mude para o separador **Tabelas**. A tabela de saída do fluxo de trabalho está lá — clique nela e deverá ver linhas a preencher a grelha: as linhas e colunas reais que o fluxo de trabalho acabou de produzir. As linhas nessa tabela são o sinal visível de êxito.

Essa tabela é o seu resultado: dados reais que um fluxo de trabalho acabou de criar a partir das suas origens. Se o fluxo de trabalho terminou com um passo de publicação, essa saída fica agora acessível aos [Painéis de controlo](/pt-pt/guides/dashboards/) e a outros consumidores.

> **Se um passo ficar vermelho, não há problema por agora.** Uma execução falhada também aparece na faixa **Requer atenção** do Iniciador. Quando estiver pronto para corrigir uma, o tutorial [Corrigir um fluxo de trabalho com o assistente de IA](/pt-pt/get-started/tutorials/fix-a-workflow-with-ai/) acompanha o diagnóstico e a reparação de uma falha — não tem de a resolver nesta sessão.

## Passo 5: fazer uma pergunta (opcional)

Cada projeto tem um **AI Assistant** integrado — uma conversa no âmbito dos dados e dos fluxos de trabalho desse projeto. Abra-o e faça uma pergunta simples, como *que tabelas existem neste projeto?* ou *o que produziu o último fluxo de trabalho?* É a forma mais rápida de se orientar num projeto desconhecido, e as conversas persistem por projeto, pelo que pode retomar um tópico mais tarde.

## Já tem o mapa

Em quinze minutos fez o que todos os tutoriais seguintes dão por adquirido: iniciou sessão, orientou-se no Iniciador e nos separadores de um projeto e executou um fluxo de trabalho do início até ao resultado final. A partir daqui, cada tutorial assenta exatamente neste ciclo — ligar dados, moldá-los, modelá-los, mostrá-los.

## Para onde ir a seguir

- **A versão de referência disto** — o [Início rápido](/pt-pt/get-started/quickstart/) constrói um pequeno fluxo de trabalho de raiz, passo a passo, como uma consulta a que pode voltar.
- **O vocabulário** — [Conceitos](/pt-pt/get-started/concepts/) define todos os termos que conheceu hoje e alguns que ainda não.
- **A sua primeira construção a sério** — [Do CSV à resposta](/pt-pt/get-started/tutorials/csv-to-answer/) leva um único ficheiro até uma resposta, e [Carregar, transformar e publicar dados](/pt-pt/get-started/tutorials/load-and-transform-data/) é o pipeline completo de ponta a ponta.
- **O caminho completo** — [Tutoriais](/pt-pt/get-started/tutorials/) lista os cenários pela ordem em que os dados se movem pela plataforma.
