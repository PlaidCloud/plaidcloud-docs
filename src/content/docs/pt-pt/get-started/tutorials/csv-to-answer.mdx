*~10 minutos · o seu CSV, uma tabela carregada, um primeiro resultado*

Esta é a versão rápida. Traz um CSV e, no fim, terá-o importado, carregado numa tabela, executado uma única transformação e lido um resultado real a partir dos seus próprios dados.

É o complemento de alta velocidade de [Carregar, transformar e publicar dados](/pt-pt/get-started/tutorials/load-and-transform-data/) — esse demora cerca de uma hora e constrói um pipeline completo de vários passos, com junções e uma publicação. Comece aqui pelo resultado imediato; vá para lá quando quiser aprofundar.

## Pré-requisitos

- Uma área de trabalho do PlaidCloud ([inicie uma avaliação gratuita](https://app.plaidcloud.com) se não tiver uma).
- Um projeto onde trabalhar — crie um a partir do separador **Projetos** se ainda não tiver nenhum.
- Um ficheiro CSV seu. Serve qualquer ficheiro com uma linha de cabeçalho e uma coluna numérica — vendas, despesas, uma lista de encomendas.

## Passo 1: criar um fluxo de trabalho

Um fluxo de trabalho é o pipeline que importa e transforma os seus dados.

1. Abra o seu projeto e mude para o separador **Fluxos de trabalho**.
2. Clique em **Novo fluxo de trabalho** na barra de ferramentas.
3. Dê-lhe um nome como "CSV Quick Start" e deixe o **Tipo de fluxo de trabalho** no valor predefinido, **Standard Serial**.
4. Clique em **Criar** e, depois, faça duplo clique no novo fluxo de trabalho para abrir o [Workflow Explorer](/pt-pt/guides/workflows/workflow-explorer/).

## Passo 2: importar o seu CSV

1. Adicione um novo passo e escolha um passo **Import → CSV** (ou o passo de importação que corresponda ao formato do seu ficheiro).
2. Na configuração do passo:
   - **Ficheiro de origem** — aponte para o seu CSV: carregue-o ou escolha-o a partir de uma conta de documentos ligada.
   - **Tabela de destino** — dê-lhe o nome `my_data`.
   - **Delimitador, carácter de aspas, linha de cabeçalho** — ajuste apenas se o seu ficheiro não for standard; os valores predefinidos tratam um ficheiro típico separado por vírgulas com uma linha de cabeçalho.
3. Execute o passo.

O seu CSV fica agora carregado como uma [tabela](/pt-pt/guides/data/tables-views/) no projeto. Uma tabela contém os dados físicos de linhas e colunas; é daí que tudo o que se segue lê.

> **A origem nunca é tocada.** Cada passo lê de uma origem e escreve num destino, deixando o original intacto. A importação do seu CSV escreveu `my_data`; a transformação do passo seguinte lê essa tabela e escreve num local novo.

## Passo 3: verificar a tabela carregada

Mude para o separador **Tabelas** e entre em `my_data`. Confirme o número de colunas, algumas linhas de exemplo e se os tipos de dados parecem corretos — uma coluna numérica deve ser lida como número e não como texto. Se algum tipo estiver errado, pode corrigi-lo com os mapeadores de colunas no passo de importação e executá-lo novamente.

## Passo 4: executar uma transformação

Agora transforme a tabela em bruto numa resposta. Este exemplo filtra as linhas relevantes e mantém apenas as colunas que lhe interessam — ajuste os pormenores ao seu ficheiro.

1. Adicione um passo **Tables → Table Lookup** (ou qualquer transformação de tabela que permita filtrar e selecionar colunas).
2. Configure:
   - **Tabela de origem** — `my_data`
   - **Tabela de destino** — `my_result`
   - **Condições de filtro** — uma condição que reduza as linhas, por exemplo `amount > 0`
   - **Colunas a manter** — o subconjunto que pretende ler, mais qualquer coluna calculada como `revenue = quantity * price`
3. Execute o passo.

Para o conjunto completo de funções que pode utilizar numa coluna calculada — operações com cadeias de caracteres, cálculos com datas, lógica condicional —, consulte a [referência de expressões](/pt-pt/reference/expressions/).

> **O que deve ver.** Depois de o passo ser executado, `my_result` tem menos linhas do que `my_data` — o filtro reduziu-as — e a sua coluna calculada (como `revenue`) está presente e preenchida em todas as linhas restantes. Se o número de linhas não diminuiu ou a coluna calculada está vazia, volte a verificar a condição de filtro e a expressão antes de continuar.

## Passo 5: ler o resultado

Abra o separador **Tabelas** e entre em `my_result`. Menos linhas do que `my_data`, apenas as colunas que manteve e a coluna calculada preenchida — essa é a sua primeira resposta, diretamente a partir dos seus próprios dados.

Também pode executar os dois passos de uma só vez: de volta ao fluxo de trabalho, clique em **Executar** (ou em **Run All** no menu **Ações**) para executar tudo por ordem. Cada passo mostra um ícone de estado à medida que avança — **Completed** significa que terminou sem problemas. Consulte [Executar um fluxo de trabalho](/pt-pt/guides/workflows/run-a-workflow/) para saber o que significa cada estado e como retomar uma execução interrompida.

> **Deparou-se com um erro?** Os dois culpados habituais são um tipo de dados que foi importado como texto quando precisava de um número e uma condição de filtro que faz referência a um nome de coluna que não existe na tabela. Verifique a tabela do Passo 3 e volte a executar. [Gerir erros de passos](/pt-pt/guides/workflows/managing-step-errors/) cobre o resto.
