## Organização, área de trabalho, membro

A conta começa ao nível da **organização** — o limite de faturação e de identidade. Dentro de uma organização existem uma ou mais **áreas de trabalho**, que são ambientes isolados onde o trabalho efetivo decorre. Os **membros** são utilizadores que pertencem a uma organização e a quem é concedido acesso a áreas de trabalho específicas, com funções específicas.

- A maioria das equipas começa com uma área de trabalho por ambiente (desenvolvimento, teste, produção) ou uma por unidade de negócio.
- Os grupos de segurança dentro de uma área de trabalho controlam o que cada membro pode fazer.

Mais informações: [Gestão de acessos](/pt-pt/administration/access/)

## Projeto

Um **projeto** é a unidade de trabalho dentro de uma área de trabalho. Cada projeto possui os seus próprios dados, fluxos de trabalho, dimensões e histórico de auditoria. Os projetos não partilham estado entre si — são isolados.

Utilize projetos para separar entre si análises, processos de negócio ou produtos de dados distintos.

Mais informações: [Projetos](/pt-pt/guides/projects/)

## Ligação

Uma **ligação** é uma configuração guardada que permite ao PlaidCloud aceder a um sistema externo — uma base de dados, uma conta de armazenamento na nuvem, um ERP, uma API REST. As ligações são reutilizadas pelos passos dos fluxos de trabalho, para que as credenciais não sejam duplicadas entre passos.

Mais informações: [Ligações (tarefas)](/pt-pt/guides/connections/) · [Conectores (referência)](/pt-pt/reference/connectors/)

## Tabela e vista

Uma **tabela** são dados estruturados dentro de um projeto — linhas e colunas, como uma tabela SQL. As tabelas provêm de importações, transformações ou origens externas. As **vistas** são resultados de consultas guardados, assentes sobre tabelas.

Mais informações: [Tabelas e vistas](/pt-pt/guides/data/)

## Fluxo de trabalho e passo

Um **fluxo de trabalho** é um pipeline que opera sobre tabelas. Cada fluxo de trabalho é uma sequência de **passos**: importar um CSV, juntar duas tabelas, filtrar linhas, exportar para JSON, enviar uma notificação. Os passos podem ser executados sequencialmente, em paralelo, de forma condicional ou em ciclos.

Os passos dividem-se em categorias:

- **Importar** — trazer dados (CSV, Excel, SQL, Parquet, JSON, etc.)
- **Tabelas** — transformar tabelas (juntar, filtrar, desagregar, pivotar, anexar, upsert)
- **Exportar** — enviar dados para fora
- **Documento** — tratar PDFs, imagens e ficheiros arbitrários
- **Notificações** — enviar mensagens por correio eletrónico, Slack, Teams, SMS, webhook
- **Alocação** — executar modelos de alocação de custos
- **Dimensão** — criar e modificar hierarquias
- **SAP / SAP-PCM** — chamar operações específicas do SAP
- **Controlo do fluxo de trabalho** — variáveis, ciclos, subfluxos de trabalho

Mais informações: [Fluxos de trabalho (tarefas)](/pt-pt/guides/workflows/) · [Passos de fluxo de trabalho (referência)](/pt-pt/reference/workflow-steps/)

## Dimensão

Uma **dimensão** é uma hierarquia — tipicamente utilizada para segmentar ou agregar dados. Centros de custo, produtos, geografia, tempo. As dimensões podem ser criadas a partir de tabelas, carregadas de origens externas ou modificadas de forma incremental.

As alocações utilizam dimensões para decidir *o que alocar a quê*.

Mais informações: [Dimensões](/pt-pt/guides/dimensions/)

## Alocação

Uma **alocação** distribui valores de um conjunto de linhas para outro com base em dados de indutores e regras. Pense em preços de transferência, custeio baseado em atividades, reimputação de custos de TI, rentabilidade — sempre que existe um conjunto de custos que tem de ser distribuído por consumidores.

As alocações combinam tabelas (valores, indutores, resultados), dimensões (as regras) e passos de fluxo de trabalho (para executar o modelo).

Mais informações: [Alocações](/pt-pt/guides/allocations/)

## Painel de controlo

Um **painel de controlo** é uma vista interativa e publicada dos dados de um projeto. Crie-o a partir de tabelas e vistas publicadas.

Mais informações: [Painéis de controlo](/pt-pt/guides/dashboards/)

## Assistente de IA

Uma conversa com âmbito de projeto para fazer perguntas sobre os dados e os fluxos de trabalho. As conversas são persistentes e isoladas por projeto.

Mais informações: [Assistente de IA](/pt-pt/guides/ai-assistant/)

## Como se articulam

Um fluxo completo típico:

1. **Configurar uma ligação** ao sistema de origem.
2. Dentro de um **projeto**, criar um **fluxo de trabalho** que:
   - **Importa** dados através da ligação (cria tabelas)
   - **Transforma** com passos de tabela
   - **Junta** com **dimensões** para dar contexto
   - **Aloca**, se estiver a distribuir custos
   - **Publica** o resultado
3. Um **painel de controlo** lê as tabelas publicadas.
4. Os **membros da área de trabalho** consultam o painel de controlo ou os resultados através do assistente de IA.
