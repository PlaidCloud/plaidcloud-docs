## O que vai criar

Um pequeno fluxo de trabalho que:

1. Importa um CSV para uma tabela do projeto
2. Filtra e transforma os dados com alguns passos
3. Publica o resultado para que outras ferramentas o possam consumir

<Aside>
Este guia é propositadamente simples — é uma visita às várias peças, não uma análise aprofundada. Depois de o concluir, a página [Conceitos](/pt-pt/get-started/concepts/) explica *porque* é que as coisas estão organizadas desta forma, e a secção [Guias](/pt-pt/guides/) aborda cada tarefa em pormenor.
</Aside>

## Comece com o projeto de exemplo

Para ver um resultado final antes de construir um, existe um atalho. Numa área de trabalho nova, surge um botão **Carregar exemplo**. Se a área de trabalho oferecer mais do que um exemplo guiado, é primeiro necessário escolher qual carregar a partir de uma lista curta:

- **Análise de vendas a retalho** — retalho e vendas
- **Desempenho de campanhas por canal** — marketing
- **Relatório do estado do inventário** — cadeia de abastecimento e operações
- **Orçamento vs real por departamento** — finanças

Cada um é um pequeno conjunto de dados realista, criado inteiramente com os passos de transformação low-code do PlaidCloud — sem SQL escrito à mão —, pelo que depois é possível abrir o fluxo de trabalho concluído e ver exatamente como funciona. Escolha um (ou, se só existir um exemplo disponível, o PlaidCloud carrega-o diretamente) e o PlaidCloud cria o projeto e executa o respetivo fluxo de trabalho, mostrando cada fase à medida que avança — **Importing** de um ficheiro, **Cleaning**, ramificação em alguns resumos paralelos e, por fim, a combinação numa única tabela de resultados — antes de abrir o resultado. Quando a execução termina, o PlaidCloud também publica a tabela de resultados para relatórios e cria automaticamente um painel de controlo a partir dela: um resumo de indicadores-chave, uma tendência ao longo do tempo, uma decomposição pela categoria principal do exemplo e — nos exemplos de retalho e de inventário — uma decomposição por estado dos EUA. A primeira execução demora cerca de um minuto, enquanto o armazém de dados aquece; todas as seguintes são quase instantâneas, e o ecrã avisa-o disso, para que a espera não seja uma surpresa. Obtém-se um primeiro resultado real e um painel de controlo concluído em poucos minutos sem construir nada, e todas as peças criadas podem ser abertas, alteradas e executadas de novo. Se o carregamento ou a execução do exemplo encontrar um problema, o PlaidCloud informa e propõe tentar novamente.

O projeto de exemplo, o respetivo fluxo de trabalho e cada painel de controlo que cria são partilhados com toda a área de trabalho no momento em que são criados — um colega com acesso de leitura vê o mesmo exemplo concluído, sem necessidade de qualquer passo de partilha adicional.

Cada ecrã vazio também orienta para o passo seguinte, em vez de deixar uma grelha em branco. **Projetos**, **Fluxos de trabalho**, **Tabelas**, **Ligações** e **Painéis de controlo** apresentam, cada um, uma breve explicação e uma ação principal — **Novo projeto**, **Novo fluxo de trabalho**, **Importar pacote de tabelas**, entre outras —, pelo que existe sempre um caminho evidente a seguir. Uma ligação **Precisa de ajuda?** nestes ecrãs e no painel de boas-vindas conduz diretamente ao suporte em caso de dificuldade. Quem for adicionado a uma área de trabalho como leitor encontra nestes ecrãs uma explicação do que está a ver, sem ações que não pode executar. E se um leitor chegar a uma área de trabalho que ainda não tem conteúdo visível, é recebido com uma breve introdução, uma visita guiada à aplicação e acesso rápido à ajuda — para que haja sempre um passo seguinte.

Esta primeira execução guiada surge em todas as áreas de trabalho novas, em todos os planos. Quem já conhece bem a aplicação pode escolher **Dispensar** no painel de boas-vindas — uma confirmação rápida lembra que a orientação continua disponível — e o painel deixa de ser apresentado. Para o voltar a apresentar em qualquer altura, abra o menu do utilizador no canto superior direito e escolha **Reiniciar integração**.

## Comece com o seu próprio CSV

Para começar com dados próprios em vez de um exemplo, escolha **Traga os seus próprios dados**. Está ao lado de **Carregar exemplo** num ecrã **Projetos** vazio, e a página inicial também o oferece. É necessária permissão para criar projetos e tabelas e para escrever no armazenamento de documentos para o ver. Depois de existirem projetos, **Novo** > **Projeto a partir de ficheiro CSV** no ecrã **Projetos** abre a mesma janela e, para adicionar um CSV a um projeto existente, consulte [Importar um ficheiro CSV](/pt-pt/guides/projects/managing-tables-and-views/#importar-um-ficheiro-csv).

Largue um ficheiro CSV na caixa, ou escolha **Escolher um ficheiro CSV** para selecionar um; só são aceites ficheiros terminados em `.csv`. O PlaidCloud carrega o ficheiro para a **Personal Temp Drive** ou, se não existir, para a **Temp Drive** da área de trabalho, cria um projeto com o nome do ficheiro, importa-o para uma tabela com o nome do ficheiro — `Sales Data.csv` torna-se o projeto **Sales Data** com a tabela `sales_data` — e abre a lista **Tabelas** do novo projeto. Em seguida, abre-se um painel **Passo seguinte sugerido** e, depois de o PlaidCloud ter feito uma primeira análise da tabela, este passa a **Os seus dados num relance**, mostrando quantas linhas a tabela tem e, para as suas seis primeiras colunas, o tipo de cada coluna, a percentagem de valores vazios e quantos valores distintos contém.

Por baixo encontra-se um gráfico de barras inicial. As barras correspondem aos valores de uma coluna com uma lista curta de valores repetidos, como uma região, e cada barra totaliza ou calcula a média de uma coluna numérica para esse valor, ou conta as respetivas linhas. Quando há mais do que um gráfico razoável a desenhar, a IA do PlaidCloud escolhe um e dá-lhe um título; vê apenas os nomes, os tipos e as contagens das colunas, nunca um valor do ficheiro. Se nenhuma coluna tiver uma lista curta de valores repetidos, o painel indica que não existe gráfico inicial.

Quando os relatórios estão ativados e existe permissão para publicar tabelas, o PlaidCloud também publica a tabela para relatórios e cria um painel de controlo inicial a partir do gráfico, e **Abrir painel de controlo** abre-o num novo separador. Os gráficos do painel de controlo têm o nome das colunas que mostram, como "Receita total por região"; o título da IA aparece apenas no gráfico do painel. Como qualquer novo painel de controlo, começa por ficar visível para todos os membros do projeto; consulte [Controlar quem pode ver um painel de controlo](/pt-pt/guides/dashboards/control-who-can-see-a-dashboard/) para alterar isso.

O painel também oferece **Limpar estes dados** ou **Resumir estes dados**, cada um a abrir um passo pronto a rever, ou **Agora não** para ignorar.

Se a importação falhar, o PlaidCloud remove o projeto que acabou de criar e indica o que correu mal. O PlaidCloud elimina o ficheiro carregado da unidade temporária assim que a importação termina, quer tenha ou não tido êxito; se isso não acontecer, a unidade temporária elimina-o ao fim de um dia. Se a área de trabalho não tiver unidade temporária, a janela indica que não há onde guardar o ficheiro, e um administrador da área de trabalho tem de contactar o suporte.

## Acompanhe o seu progresso na página inicial

Depois de entrar numa área de trabalho, a página inicial mostra um cartão **Primeiros passos** que acompanha a configuração passo a passo, com um indicador de progresso ("N de M") incorporado. O que é apresentado depende da função: os administradores veem cinco passos — experimentar o exemplo, ligar os dados, criar o primeiro fluxo de trabalho, publicar um painel de controlo e convidar a equipa; os construtores veem três — experimentar o exemplo, criar o primeiro fluxo de trabalho e publicar um painel de controlo; os leitores não veem o cartão.

O cartão destaca sempre, como ação principal, o que ainda não foi feito, e cada um dos restantes passos pendentes é uma linha clicável que conduz diretamente ao local certo. Um passo concluído fica assinalado de forma permanente — nunca deixa de estar assinalado — e os passos concluídos recolhem-se para que o cartão se mantenha centrado no que falta.

<Aside>
"Publicar um painel de controlo" só conta um painel de controlo que tenha publicado pessoalmente — se um colega publicar um, a sua caixa não fica assinalada.
</Aside>

Para deixar de ver o cartão, escolha **Ocultar** e ele recolhe-se num pequeno botão "Primeiros passos · N/M" na barra de ferramentas; clique nesse botão em qualquer altura para voltar a apresentar o cartão completo. **Reiniciar integração**, no menu do utilizador, também o repõe. Para desativar totalmente a integração, utilize **Dispensar a integração?**; fica desativada até escolher **Reiniciar integração**.

Quando todos os passos estão concluídos, o cartão retira-se: desaparece da página inicial e surge uma única celebração "Está tudo pronto" — uma vez por área de trabalho, independentemente do número de dispositivos ou navegadores utilizados.

O progresso, o estado oculto ou visível do cartão, as visitas guiadas, as sugestões e tudo o que foi dispensado na página inicial acompanham a conta e não o navegador. Ao iniciar sessão a partir de um novo dispositivo, de outro navegador ou de uma janela anónima, retoma-se exatamente de onde ficou, em vez de recomeçar.

O resto deste guia constrói manualmente o mesmo tipo de fluxo de trabalho, para que seja possível ver cada peça em funcionamento.

## 1. Abrir um projeto

Depois de iniciar sessão, entra na área de trabalho. Abra o separador **Projetos** e crie um novo projeto — dê-lhe um nome descritivo, como "Início rápido". Um projeto é o local onde os dados, os fluxos de trabalho e as dimensões vivem em conjunto.

Consulte [Gerir projetos](/pt-pt/guides/projects/managing-projects/) para saber mais sobre o ciclo de vida do projeto.

## 2. Importar um CSV

Dentro do projeto, abra o separador **Fluxos de trabalho** e crie um novo fluxo de trabalho. Adicione um passo **Importar → CSV**. Carregue um pequeno CSV a partir do computador local ou aponte para um CSV num armazenamento de documentos ligado.

Execute esse passo. O CSV fica como uma tabela no projeto. Abra o separador **Tabelas** para a ver.

Referência: [Passo Importar CSV](/pt-pt/reference/workflow-steps/import/import-csv/) · Guia: [Onde estão os fluxos de trabalho?](/pt-pt/guides/workflows/where-are-workflows/)

## 3. Adicionar um passo de transformação

De volta ao fluxo de trabalho, adicione um passo **Tabelas → Table Lookup** (ou qualquer um dos passos de tabela). Configure a origem e o destino, escolha as colunas a manter e aplique um filtro simples.

Ao executar o passo, o resultado é uma nova tabela que pode ser pré-visualizada.

Referência: [Passos de fluxo de trabalho](/pt-pt/reference/workflow-steps/)

## 4. Publicar o resultado

Adicione um passo **Publicar** final (em **Dados → Publicar**) para que a tabela fique disponível para painéis de controlo, ferramentas de BI ou consumidores externos.

Guia: [Publicar dados](/pt-pt/guides/data/publish/)

## 5. Executar todo o fluxo de trabalho

Clique em **Executar** no fluxo de trabalho. Acompanhe o registo à medida que cada passo é executado. Se ocorrer algum erro, o guia [Gerir erros de passos](/pt-pt/guides/workflows/managing-step-errors/) aborda a depuração.
